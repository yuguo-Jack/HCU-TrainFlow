# lite：发现优先的知识维护

这是存储、检索和维护流程重构，不是一次全量上游资料更新。六项 Skill 和原 CLI 入口保持，HCU 仓知识继续交给独立 HCU-Knowledge；本仓使用其固定 lite 提交及现有绑定，不复制私有原件。

## 保留什么

重要的作者解释、固定源码引用、选定官方文档、实际引用 PR 的原件，以及自包含站点/最终模型证据继续保留。来源的职责、版本、父 gitlink 和实际消费者需要可核对；新来源无需凑九维报告、机制数量或逐 PR 总结。

普通 PR 用 `wiki-search-pr` 或现有 `wiki-search` 的联搜找到 URL，直接打开原页即可。`wiki-pr` 默认只读正文和固定 head/base；需要时再加 `--discussions` 或 `--files`。形成实现结论时查看对应代码/测试，不把标题或合入状态当作已部署能力。GitLab 仍经 HCU-Knowledge 的现有路由查询，不虚构本仓未实现的平台接口。

`capture_policy.changes: discover` 每次观察一页近期 PR，默认 10 项，私有轻量候选最多 1000 项。它不调用正文、评论、review 或 diff 全采，不扫描全部历史，不把旧 pending 清零。旧讨论不可搜索不再构成全量本地镜像的理由；更早的问题由平台联搜按需发现。

分支固定提交未变时跳过完整树、文档及正文刷新；变化时检查已登记的固定路径，按实际影响复核作者知识。重要变化才整理深入案例。原有源码未读范围和历史不可用项仍是有日期的边界，不为完成结构重构改称已验证。

## 原件与历史

普通 PR 的旧 JSON 和生成 Markdown 已与现有 Git blob 比较后从当前树退役。固定基线为 `0f2e883b101fc1cebf627d9203b03068827a6a5a`，保留的 main / v0.7.4 使这些对象仍可追溯；没有再复制一套 ZIP 镜像。当前实际引用的 53 组 PR 页面及原件直接存在。

`wiki-read` 可按旧 PR ID 或历史相对路径恢复查阅副本，raw JSON 同时验证 SHA-256。恢复只读已有 Git 对象，不自动刷新来源。浅克隆没有旧对象时，返回明确的固定提交 fetch / 原页查阅说明；普通当前知识检索和所需引用原件不依赖下载全部历史。旧 Git 历史不会因为新建 lite 分支自动缩小。

新索引把文档版本和 FTS 共享在一个数据库中，generation 仅保存成员关系。同输入不复制整库；当前小语料校验内容哈希，只有变化页重新解析和索引，避免 Windows 保留时间戳的复制漏检。新快照按版本保存压缩的精确原页，旧 generation 读取不会错用当前修改后的原件。老格式索引仍可读取；若其精确原始字节未曾保存，正文仍可读，但明确标注原件不可用。查阅副本中的用户批注不被覆盖。

## 本轮验收

- 净退役 54,666 份普通 PR 当前副本，4,318,805,195 字节；53 组实际引用证据保留。作者/导航基线 110 页中，108 页字节不变，只有覆盖与 PR 导航两页修改维护范围。
- `knowledge/` 从 4,404,607,656 字节降至约 68 MB；此数不包含 `.git` 历史、旧任务 Store 和本轮诊断记录，不代表整个工作区减少 98%。
- 当前索引 1458 页，数据库 28,856,320 字节；旧正式索引 648,314,880 字节。首次构建约 3.69 秒，无变化检查约 0.59 秒，未变化页重新解析 0；这些是本机本轮测量，不是跨机器性能保证。
- 沿用先前 20 组真实问题，当前与无历史冷副本各 20/20 命中并读取同 SHA 正文；另核对 10 个退役历史原件和旧正式 generation 的精确读取。当前知识校验、组织覆盖、文档与 Skill 路由检查通过；完整本地 CPU 回归 1389 通过、4 平台跳过。

软件/存储/未知范围变更跑 Windows/Ubuntu × Python 3.10/3.12；纯资料变更执行相应知识、文档、Skill 和相关回归，汇总检查始终运行。现有安装先核验来源、版本和打包配置，匹配时不重装；Skill 按内容哈希只同步变化项。不新增依赖或训练运行时。

本轮只提交并推送 origin 的 lite，不改 main 或旧标签，不自动打新标签。实际发布以对应提交、CI 和发布回执为准；没有训练、GPU 或新增硬件资格验证。
