# 工作空间与写入边界

默认只在**当前任务的工作空间及其已核实的远端、容器映射目录**内创建、修改、移动和删除文件。读取必要的外部代码、文档、系统状态与日志不受这条写入规则限制。该约定适用于主控、阶段 Skill、算子 Skill、成员 Agent 和远端脚本，独立执行环境检查、分析、诊断或交付时同样适用。

这是一条减少误操作和环境污染的执行规则。`cwd`、命令卡及 TaskSpec 权限不是文件系统沙箱，不能自动约束训练框架、编译器或任意子进程的全部写入；需要强隔离时使用经过验证的只读挂载、操作系统权限或容器策略。

## 1. 先确定映射，沿用同一份记录

首次接手或映射改变时，在已有任务 `DETAILS.md` / 环境记录中补充下表。已有可靠记录直接复用，不为每条命令新增审批或报告。仅交付任务可记在现有工作计划中，无需建立训练状态机。

| 范围 | 记录内容 | 默认用途 |
| --- | --- | --- |
| 本地任务根 | 解析后的绝对路径、任务归属 | 开发 checkout、任务 Store、配置、传输包、报告与缓存 |
| 远端任务根 | 节点/站点、绝对路径、是否共享存储 | 固定源码快照、构建、训练输出和守护状态 |
| 容器/Pod 映射 | 宿主路径 → 容器路径、读写属性、容器/Pod 身份 | 把进程实际看到的路径对应到宿主；相同字符串不代表相同目录 |
| 外部只读输入 | 数据集、权重、参考仓、工具安装和原始日志路径 | 查阅和读取；有写副作用的加载器须单独处理 |
| 必要额外写入 | 精确路径、目的、操作范围、授权依据、回退或保留方式 | 已获准的独立开发仓、Wiki/Skill 安装、指定交付输出等 |

本地与远端优先使用同名任务子目录；实际根由现场决定，不写死某个站点路径。`TRAINFLOW_PROJECT` 是工作流安装/文档位置，`TRAINFLOW_WORKSPACE` 是当前任务私有存储，两者不能混用。Store 可以在任务根的子目录中；不要把 Store 的对象目录、源码 checkout 和整个共享盘视为同一清理范围。

SSH 跳转节点一般只转发连接；需要落盘的包、日志或 known-hosts 文件也明确放在该节点的任务目录。裸机/Conda 核对实际解释器和输出；Docker 核对 bind mount；Slurm 核对分配节点上的工作目录；K8s 核对 PVC/subPath、Pod UID 和容器路径。共享目录按实际存储身份管理一次，不能在各节点重复清理。

复用用户已有 checkout 时，先确认修改它属于本次授权并记录为额外写入路径；不为了目录整齐移动工程或覆盖未提交改动。Git worktree 会写其关联仓的 Git 元数据，创建/提交前也要知道这一范围。

## 2. 把隐式输出也放进任务目录

第一次使用工具、变更启动脚本/镜像/依赖后，核对命令、配置和环境变量的实际写入位置；相同已验证配方可复用。重点包括：

- **源码与构建**：独立开发 checkout、构建目录、扩展 `.so`、Triton/Inductor 缓存。参考仓、知识库源码缓存和固定快照不作为开发目录。上游必须原地构建时，在任务内建立可写构建副本，记录它与固定源码的关系及实际加载产物。
- **训练与调试**：checkpoint、数据预处理/索引、TensorBoard、profiler trace、Probe、TraceLens 分析/回放输出、core dump 与临时通信文件。共享数据和权重优先只读挂载；加载器若在输入旁生成索引，改用受支持的私有缓存或任务副本。
- **下载与临时文件**：按当前工具支持配置 `TMPDIR`（Windows `TMP`/`TEMP`）、`XDG_CACHE_HOME`、`PIP_CACHE_DIR`、`HF_HOME`、`TORCH_EXTENSIONS_DIR`、`TRITON_CACHE_DIR`、`TORCHINDUCTOR_CACHE_DIR` 等到任务内的独立子目录。先查源码/帮助/实际环境确认，不能假定所有工具支持或遵守这些变量。不要为迁移缓存整体改写 `HOME`，以免改变凭据、SSH 或已有配置的定位。
- **观察与恢复**：远端 watcher/sentinel 的状态、PID、日志、恢复脚本和新 attempt 输出使用同一已登记映射。只重启作业不意味着可更改站点服务、驱动配置或其他任务目录。

容器只将任务根作为必要的可写 bind mount，外部输入尽可能 `ro`，避免把共享盘父目录或整个宿主根暴露为可写。硬件设备、Docker/调度器运行时和系统日志会由既有服务产生站点管理的写入；本约定不宣称能消除这些系统行为，也不允许 Agent 顺手修改这些服务的数据目录。重编底层库优先任务内构建、独立安装前缀或任务专用容器，记录加载路径与回退；不直接覆盖其他作业共用的库。

已有缓存可只读复用。配置改动后做一次小范围路径检查，确认生成物实际落点，再启动大写入；不在每轮实验中扫描整机。

## 3. 写入、同步与清理前的实际检查

1. **确认目标真实位置。** 展开配置变量，在目标机器/容器中核对绝对路径、现有父目录和挂载。检查 symlink、Windows junction/reparse point；不能只用字符串前缀判断，也不能先 `resolve` 再把跳到外部的结果当成原授权。根目录、共享父目录、空变量或意外 `..` 不是有效的任务目标。
2. **确认操作范围。** 默认增量复制或新快照，不覆盖运行中源码。同步先核对源/目标和方向；`rsync --delete`、镜像同步、`robocopy /MIR`、递归 chmod/chown 等必须列清影响范围并预览；只有专属目标、确有必要且已有授权时才执行。不能把“写入授权”等同于“清空目录授权”。
3. **约束并行成员。** 把映射记录和允许修改的子路径交给成员，`allowed_paths` 与实际 checkout 对齐；共享构建/输出要隔离或串行。成员不能自行扩大到父目录。挂载或路径归属改变时更新记录，再继续受影响动作。
4. **保留清理原有保护。** 按 [工作区维护](workspace-maintenance.md) 的低频时机、登记、pin、退役、dry-run 和回执执行。位于工作空间内不代表可随意删除；基线、有效 checkpoint、用户源码、原始证据仍受保护。禁止用全局 `docker system prune`、清空共享缓存、整机找大文件后删除等方式替代任务清理。

源码传输器会拒绝含 `..`、符号链接或 Windows reparse point 的目标路径及父路径，并拒绝已占用的目标/暂存路径。确实通过链接挂载工作区时，先核对真实目标及授权，传入实际路径。此预检防止意外重定向；不抵御检查后被其他进程替换父目录的竞态，任务目录仍需专属写权限和协调。详情见 [源码传输](source-transfer.md)。

## 4. 必要例外与知识维护

任务内能合理完成的操作留在任务内。确需外部写入时，先说明并记录**具体路径、必要性、会改什么、影响谁、如何回退**，核对用户已有授权和现场约定。已有明确授权则继续，不重复询问；没有授权或存在未确定的共享影响时，只暂停依赖该写入的动作，向用户说明缺口，其他独立工作继续。取得 root 或容器写权限不等于取得任意目录的任务授权。

| 场景 | 处理方式 |
| --- | --- |
| 现场依赖缺失 | 先使用已有兼容环境或任务内可行的安装方式；必须改共享 Conda/DTK、系统包、驱动、服务或全局 `core_pattern` 时核实明确授权及维护窗口。不能暗改别人正在使用的环境 |
| 工作流本机安装/升级 | 用户要求安装维护时，选定 TrainFlow checkout、实际 Skill 目录和 Python 安装位置属于维护范围；按 [安装同步](integrations.md) 校验后替换，仅处理工具管理的副本，不扫整个 Skills/Python 目录 |
| 普通 Wiki 查询 | 私有索引、线上 PR、代码与下载缓存留在选定任务 Store/参考目录；不因查阅修改工程 `knowledge/` 或 HCU 大知识库 |
| Wiki 与 Skill 更新、里程碑经验提炼 | 在该维护范围内使用已绑定 TrainFlow 工程的 `knowledge/`、相关 Skill/docs/维护记录及必要安装同步路径；收录仍须满足知识筛选规范。该权限不扩展到上游训练仓或 HCU 大知识库 |
| 交付用户补丁、导出/提 PR | 使用已确认的开发 checkout/目标输出；保留未提交改动，核对 Git 归属与差异，沿用 [交付规范](change-delivery.md)。参考缓存不转为开发仓 |

发现意外越界写入时，先停止同类写入并记录实际路径、进程和影响。不要未经核实直接删除“恢复原状”，它可能与既有文件混在一起；保留证据，修正输出配置或取得必要授权后继续。
