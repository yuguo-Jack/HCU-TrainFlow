# 能力与验证边界

当前发布版本见 [README](../README.md) 与[变更记录](../CHANGELOG.md)。本地测试覆盖协议和工具逻辑，部分能力已有真实 HCU 环境中的有界验证；换环境、引擎或规模后仍需按对应条件验收。下表区分已经执行的范围和待验证部分；经筛选的通用站点知识另在 Wiki 保存，完整任务日志仍留私有工作区。整体方法见[工程介绍](project-overview.md)，阶段衔接见[工作流全景图](workflow-map.md)。

完整安装包括 HCU 知识库的检索和更新能力，但普通适配、分析、查询及本项目维护不会隐式更新 HCU-Knowledge。`--workflow-only` 仅供开发者刷新六个工作流 Skill，不是完整安装；安装步骤见 [快速开始](quickstart.md)。

安装保留项目 checkout，Skill 自带 references 随安装复制，项目脚本/文档由显式项目路径、`TRAINFLOW_PROJECT` 或安装时写入的 `workspace.json.project_root` 定位。wheel 包含维护模块，单独安装 wheel 不会附带全部 scripts/docs/Wiki；远端辅助脚本须按同一修订显式部署。维护与观察换代的使用和边界见 [工作区维护](workspace-maintenance.md)。

工作空间约束见[统一写入边界](workspace-boundaries.md)：六个 Skill 共用映射、输出/缓存和必要例外规则；源码传输另有目标链接预检，维护脚本保留受限删除检查。CLI 不为任意命令提供文件系统沙箱，部署仍须核对实际挂载、权限与工具输出。

## TraceLens 已验证范围

当前主线另完成了 gfx936/DTK 26.10 的 TraceLens 有界资格验证：训练 Graph 前后向映射、实际输入 EventReplay、实测参考 Roofline、原生 Agent 指标及推理复核、hipprof JSON/pftrace 同源对照、XProf/XCompute counter 与 SQTT。另以真实 trace 验证了受管 split/merge/compare 和原生源码定位、索引，合并不自动校时，自比较不代表提速。命令、计时/数据边界和未覆盖项见 [TraceLens HCU 分析](tracelens-analysis.md)；没有因此扩大完整模型 loss、多架构或生产长稳的验证声明。

## 模型精度诊断的覆盖

三个阶段共用[精度诊断方法](practices/model-accuracy-diagnosis.md)：NV 对照、HCU 自查、HCU Probe 采集和匹配、跨 rank 首差、SFT/RL 与恢复后偏差。已核对固定 Probe 源码及官方方法，登记调用入口和验收边界；目前没有保留完整 HCU/NV 模型对照或 Probe 现场实验的验收证据，不要求预先实测全部后端。现有质量门槛继续核对冻结初态、配方、样本和实际候选；Probe 不会由 CLI 自动安装/执行，也不自动判模型通过。

## 官方 Wiki 的统一阅读粒度

官方资料按 `knowledge/projects/<project>/knowledgebase/{upstream,local}` 统一组织，原文/PR 与整理后的机制解释分开；HCU 仓库知识通过 HCU-Knowledge 联查，本仓仅维护工作流接口和有复用价值的经验。

所有登记来源共用[九项内容标准](wiki-authoring-standard.md)：定位、目录、安装、运行测试、数值/状态契约、调用链、性能显存、诊断恢复、版本与 PR。各仓入口和具体机制见[覆盖导航](../knowledge/COVERAGE.md)，跨引擎优化见[参考选择](optimization-reference-map.md)。Megatron、TorchTitan、DeepSpeed、SFT/RL、推理后端与第三方参考均有同等阅读维度；页数可以不同，不能用大量原文或 PR 数量代替专题讲解。

源码目录、教程和 PR 增量分别采集；作者页说明选定机制、证据及边界，正文复核后才应用来源更新。组织检查仅确认阅读入口完整，不证明每个结论正确或通过 HCU 实测。发布线、开发分支和未合入 PR 分开追踪；Wiki 内容更新本身不增加训练、性能或故障注入的硬件验证范围。

## 后续验收重点

1. 在每个目标环境重新确认资源、权限、启动方式和预期；冻结真实源码、依赖、模型、数据与基线身份，保留早期发现记录。
2. 根据端到端证据推进系统/通信/算子候选，验证局部正确性和收益，并在稳定阶段验 loss。
3. 在非平凡并行域采集至少两个适当 rank 的 profile，核对切分、显存、通信与负载均衡；不能把单卡结果外推到多机。
4. 按任务允许的代理模型范围验证，再恢复目标结构、扩 DP 域及规模，接入现有容错。
5. 分别验收主控中断接续、真实告警送达、Agent 唤醒、训练恢复和监控自身失效；通知、分析和恢复是不同证据。
6. 有效修改集中整合到指定活跃 HCU 出口，重新验证整合版本；同步文档、Skill 和私有经验后再评估发布条件。

工程发布不表示所有站点、所有引擎和规划中的全部机制已经生产验证；当前证据范围以上表及专项验证说明为准。

后续 Wiki 深度扩展还包括官方 release/roadmap 与特性 PR 的持续策展、更多 AI 编译调用链，以及各 SFT/RL 引擎的实际模型与底层实现专题。当前可先按问题使用已保留的官方文档、源码导航和线上 PR，并由 Agent 沿官方仓库/文档入口查未收录的教程、Releases、roadmap issue/discussion/project，再追实际模型配置与底层实现；无需等全部写成深度专题才能查证。此路径不表示所有内容已本地收录或离线可搜，网络、权限、页面读取和版本差异仍须如实反馈。详见 [官方内容按需查证](wiki.md#未收录的官方内容按需查证)。TE/cuDNN 的具体收录范围见[覆盖导航](../knowledge/COVERAGE.md)，不代表所有 backend、版本和训练组合均已逐项验证。

知识维护时机见 [任务中的维护时机](knowledge-architecture.md#任务中的维护时机)：`knowledge_followup` 是由 Agent 处理的非阻塞提示，不是后台采集服务；私有报告自动归档不等于共享 Wiki 已更新。

## 当前主线诊断方法补强

规模长稳 Skill 已补充六类故障分流及 HCU 知识库、在线 PR、源码查证路径；环境适配和优化增加失败交接。新指南来自文档/源码核对与离线场景复核，不增加真实故障复现的覆盖声明。通信契约失配、VMFault/core、真实泄漏、数值偏差、存储失败、节点替换与不同部署恢复仍需在授权现场逐项验证。安装迁移/文档校验不能代替这些硬件验证。

## 方法与实测的验证分工

性能证据刷新、三表分析、HCU 计数器判读、组合/停滞处置，以及跨阶段重放、假设排除、二分和节点交叉诊断，来自参考源码、HCU 知识与离线回归核对。上限模型、阶段门槛、中断重入及消息交接另有程序回归。这些检查本身不增加实际 HCU 性能或故障注入结论；TraceLens 实测资格单列在上文，不将工具资格扩展成完整训练验收。
