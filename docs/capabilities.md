# 0.4.0.dev1 开发状态与后续验证

本版本是开发里程碑，不是正式发布。本地测试覆盖协议和工具逻辑，部分能力已有真实 HCU 环境中的有界验证；换环境、引擎或规模后仍需按对应条件验收。下表区分已经执行的范围和待验证部分；经筛选的通用站点知识另在 Wiki 保存，完整任务日志仍留私有工作区。

安装保留项目 checkout，Skill 自带 references 随安装复制，项目脚本/文档由显式项目路径、`TRAINFLOW_PROJECT` 或安装时写入的 `workspace.json.project_root` 定位。wheel 包含维护模块，单独安装 wheel 不会附带全部 scripts/docs/Wiki；远端辅助脚本须按同一修订显式部署。维护与观察换代的使用和边界见 [工作区维护](workspace-maintenance.md)。

## 后续验收重点

1. 在每个目标环境重新确认资源、权限、启动方式和预期；冻结真实源码、依赖、模型、数据与基线身份，保留早期发现记录。
2. 根据端到端证据推进系统/通信/算子候选，验证局部正确性和收益，并在稳定阶段验 loss。
3. 在非平凡并行域采集至少两个适当 rank 的 profile，核对切分、显存、通信与负载均衡；不能把单卡结果外推到多机。
4. 按任务允许的代理模型范围验证，再恢复目标结构、扩 DP 域及规模，接入现有容错。
5. 分别验收主控中断接续、真实告警送达、Agent 唤醒、训练恢复和监控自身失效；通知、分析和恢复是不同证据。
6. 有效修改集中整合到指定活跃 HCU 出口，重新验证整合版本；同步文档、Skill 和私有经验后再评估发布条件。

本版的“完成”指本表已实现工具和可复现本地验证完成，不表示所有站点、所有引擎和规划中的全部机制已经生产验证。

后续 Wiki 深度扩展还包括官方 release/roadmap 与特性 PR 的持续策展、更多 AI 编译调用链，以及各 SFT/RL 引擎的实际模型与底层实现专题。TE/cuDNN 已覆盖本次列出的实现和教程，仍不代表所有 backend、版本和训练组合均已逐项验证。
