# 优化异常、证据不足与诊断交接

沿现有热点排序和迭代流程执行。本页补充“实验出问题或结果不可信时怎么办”，不新增阶段或强制每轮长训。统一故障方法见项目 `skills/hcu-train-scale-and-stability/references/diagnosis.md`，依赖/启动问题见环境检查与模型适配 Skill 的 `references/troubleshooting.md`。

## 判断哪些情况先暂停性能结论

| 异常 | 先做什么 | 回到优化的条件 |
|---|---|---|
| profile 缺 rank/步标记/shape 或全为零 | 查真实采集入口、过滤窗口、日志完整性、解析版本、原始事件；确认未采到与确实未执行 | 补足影响本结论的证据或缩小声明范围，缺项仍在报告中，不把解析成功当全覆盖 |
| 跑得更快但候选未被调用 | 核对 dispatcher/backend、fallback、cache 与二进制身份 | 证明当前候选真正生效，再比较同条件性能 |
| 微单测变快、模型更慢 | 查暴露关键路径、并发计算/通信争用、launch、临时 buffer 和额外同步 | 分清局部收益与整步净收益；回退负收益组合或调整调度，再验证 |
| 波动大、偶尔最快 | 查共享负载、预热/JIT、输入分布、频率、CPU/存储/通信、计时同步 | 固定可比条件并重复配对；不足以分辨收益时报告不确定，不挑最快一轮 |
| 输出/梯度/更新错误、NaN | 固定失败样本与同初态，检查真实 dispatch、融合边界/cast/累积/别名/生命周期 | 局部回归通过后才恢复候选集成；稳定阶段完成 loss 对照 |
| OOM/增长、卡住/core、重启后偏离 | 保存同一候选 context/attempt 的证据，转对应故障分支；保留原基线 | 修复/缓解范围、代价及回归明确，不能以速度或重启成功掩盖错误 |
| 去掉 profiler/hook 后现象改变 | 检查采集引入的同步、分配、stream/时序与扰动 | 回到正常执行形态复验；诊断运行不参加性能收益统计 |

## 局部正确性失败的排查顺序

1. 先排除 reference 和 candidate 使用了不同数据、随机状态、布局/stride、shape、精度、训练模式、累积或参数组。检查 reference 本身与目标模型契约是否一致。
2. 找首次分歧而不是末端最大的误差：算子输入 → 中间输出 → 梯度 → 归约/缩放 → 更新。按需查 HCU hcuprobe/TE dump、知识库同类问题和官方 PR；核对采集覆盖和异步快照是否保存了当时数据。
3. 对 fused kernel 检查 cast 舍入点、累积精度、mask/边界、in-place/alias、反向保存量、跨流读写依赖；数值近似只有在已约定契约内才可接受。未知项交回原算子 Skill 补基线/定位，不自动放宽容差。
4. 对照匹配源版本和源码测试，必要时保存最小输入重放并审查最新修复；读取完整 PR 与实际合入代码。模型层故障不应直接变成重写某个 kernel 的任务。
5. 修复后局部多 shape/前后向/更新回归，保留原失败用例；集成稳定后按 `docs/training-state-validation.md` 做阶段 loss。没有 NV 环境不代表无需正确性参考，也不要求因此停止全部调查。

## 上限与停止依据同样需要排障

条件模型预测不合理或效率大于100%，先检查 FLOPs/有效字节量、单位、实际 dtype/指令路径、稀疏/重算/缓存、计时范围和硬件峰值依据；不能把“超过上限”写成优化成绩。单测异常偏低不能直接下调可达上限来掩盖环境问题。

模型内外差距尚未解释、合理上限仍未知或候选有明显空间但缺工具时，给出优先级、下一检查和需要的专家/环境。经过有界分析与试验无新证据就升级；analyze 模式只提供分析与建议，不启动实验。正常优化候选继续由 baseline/HIP/Triton Skill 按各自流程执行，性能瓶颈时应使用实际分析工具。

跨阶段交接沿用同一问题 ID、context/attempt、证据和 owner。故障诊断返回最小复现、定位范围和验证条件；优化负责人负责修复实施及收益/数值验收。除非问题确实有独立范围，不为一次异常再机械派多个 Agent。
