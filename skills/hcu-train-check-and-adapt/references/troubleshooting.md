# 环境检查与模型适配：失败分流和交接

用于环境验收、首次启动和建立正确性基线时的异常。先沿当前启动链找首次失败，保持用户 patch 和实际执行基线；不是每次失败都重新安装整套软件或换模型配置。

## 1. 按发生位置缩小问题

| 阶段/症状 | 首轮证据 | 区分方法与后续动作 |
|---|---|---|
| 连不上、容器/Pod/作业未起 | SSH/调度/容器退出和事件、目标身份、资源授权、挂载与工作目录 | 区分连接、镜像/权限、资源不足和应用失败。启动结果 unknown 时先核实原作业，不再提交一个相同任务 |
| import/加载扩展失败 | 完整首次 traceback、Python/package 路径、wheel/编译器/DTK 版本、依赖锁 | 查 extension 与实际动态库是否匹配；同名库或已安装包不等于加载了它。undefined symbol 追调用者、导出符号和 ABI，no kernel image 追编译目标 gfx 与实际分派 |
| 编译/JIT 失败 | 第一处编译错误、完整命令、CMake/build 配置、目标架构、缓存来源 | 固定最小编译单元，核对头/库/编译器与 HCU 分支；独立新构建目录验证，不清整个共享缓存。编译成功还需实际加载和 dispatch 证据 |
| 分布式初始化/首步卡住 | 全 rank 启动/退出、rendezvous、设备映射、数据游标 | 转规模长稳 Skill 的诊断指南，区分成员缺失、参数/顺序不一致与通信实现；不只看 rank0 日志 |
| 单节点正常、多节点失败 | 每个节点的激活链、镜像/依赖/挂载、HCU 环境变量、主机与容器网络视图 | 逐 rank 对照非敏感有效配置、库身份与数据 manifest；共享路径不保证同内容。检查真实 NIC/拓扑与独立通信契约 |
| 首次初始化/前后向/保存 OOM | 最紧 rank 的峰值、失败 phase、实际模型/优化器、并行布局与临时 buffer | 回容量和切分规划，区分主机/容器 OOM 与显存 OOM；不据单次失败随意缩 dim、换算法或宣称硬件故障 |
| 跑通但 loss 不合理/实现 fallback | 实际模型构造参数、数据/tokenizer、mask/labels、loss 归一、optimizer/参数组、dispatch | 对照支持该模型的官方分支/PR 与 HCU 配方，建立同初态小样本前后向/更新对照；默认只缩层，模型语义不明保持缺口 |

`--help`/import、调试器和检查脚本也可能初始化设备或触发负载。先读入口/当前帮助判断副作用，在已分配资源内操作。没有权限或工具缺失记为 incomplete，不把跳过检查写成 pass。

## 2. 依赖问题必须追到真正加载的制品

先保留当前可复现状态，再核对启动 cwd、解释器、包元数据与模块文件、扩展构建产物和进程已加载库。动态库运行时可能 dlopen，不以静态依赖清单代替进程实际映射；离线目标未运行时明确只能证明链接关系。按 `$hcu-knowledge-search` 查对应 HCU PyTorch、Galaxy、DCC、TE/Flash-Train/Primus Turbo 或通信库，再沿源码调用链定位。

需要重编时用独立开发 checkout 和任务安装前缀，记录源 SHA、工具链、编译目标、依赖、产物哈希和激活方式；验证所有相关 rank 都加载新制品。不要直接覆盖共享 DTK 或别人的环境，也不以另一节点的版本输出替代全组核对。缺符号/权限时先给明确问题与所需项，不能用 AMD/NV 源码冒充 HCU 实现。

**按缺失能力逐级修复，而非一遇错就升级整个栈。** 先确认已支持的模型/算子只是配置或注册未接通，还是接口/语义确实不支持；依次考虑匹配现场的参数调整、最小源码修复、兼容上游补丁、独立依赖构建。每解决一层重新读首个失败，不累积无关开关。变更层级须符合已授权范围；只查环境不自动改模型。每个临时替代保留原因、影响和撤销条件，不能用更换优化器、mask 或辅助模块让测试表面跑通。

graph/compile 首次执行问题单独检查前向与 backward worker 的库 handle/workspace、捕获的分配/释放、静态输入存储和异步通信支持。一次前向 warmup 不证明 backward 初始化已完成；compile 成功不代表稳定特化命中。保持同一输入、参数和梯度语义，对照 eager/graph/compile 的最小路径，记录调试开关和实际 fallback；恢复正常模式后重验。可查大库 `pytorch-memory-stream-graph-lifecycle` 及所用 TE/编译器源码。

## 3. 基线失败时的最小递进

在不改变问题所需条件的前提下，从导入/构造 → 固定小输入前向 → backward → 真实 optimizer 更新 → 对应并行组 → 短窗口保存恢复逐步定位；已经有证据通过的阶段直接复用，不能为形式全重跑。每步记录目标调用是否实际执行、有效样本、输出/梯度/状态检查和未覆盖范围。使用随机 token 或缩层代理验证链路时明确其用途，不能据此验收目标训练质量。

数值与运行异常统一读项目 `skills/hcu-train-scale-and-stability/references/diagnosis.md`，按其知识/PR/源码查证方法推进；`environment` 仍只交环境检查结果，不强制进入上述模型递进。未知配方、无参考预期、安装 ABI 不明和尚未定位的异常都有明确下一步和 owner，不为了让流程变绿取消检查。

需要定位回归、间歇卡住或疑似坏节点时，共用该指南 §1.1–1.2 的失败重放、假设排除、版本二分和节点交叉方法。不得把适配时规避的问题悄悄交给优化阶段，也不得把减少 rank/layer 后不再触发的问题标为已解决。

## 4. 交接给优化和长稳阶段

交付除了能启动的命令，还包括：环境 pass/fail/incomplete 矩阵及预期依据、实际生效配置/依赖、资源/数据与模型语义、最紧 rank 容量/余量、初态与短跑/保存恢复结果、历史异常与缓解/未解项。临时关闭融合/compile/overlap 才能跑通时标明功能或性能代价及恢复条件，优化阶段能追到原证据，不能把诊断设置悄悄当最终配方。

没有现场验证的部署方式、gfx、模型与工具接口保持待验证；只做文档/源码检查不证明全环境健康。方法更新与证据来源见规模长稳 Skill 的 `references/evidence-sources.md`。
