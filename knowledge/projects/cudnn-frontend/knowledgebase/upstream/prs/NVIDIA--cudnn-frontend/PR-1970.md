# sdpa: unroll native FP8 KV conversion by eight chunks

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1970) · state: closed · merged: True

## Original PR description

The native half-Q/FP8-KV converter spends work on loop and swizzle indexing for every 256-element chunk. Unroll eight chunks per iteration so the compiler can amortize that work while retaining the same lane-owned stores, packed conversions and synchronization.

Validation (the qualified converter and mixed-KV runtime are unchanged after merging the landed parent):
- 94 mixed-KV and physical-origin functional cases pass, including all FP8 encodings, standalone and graph calls, empty sequences, rebinding and retained CUDA Graph replay.
- 46 memcheck and 46 synccheck cases pass with zero errors. Functional and performance runs used one local SM100; the final sanitizer run used a second available SM100.
- Ten native variants cross-compile with CuTeDSL 4.7 to verified SM103 cubins. The final helper/config/kernel executable code matches that compiled source; parent combine changes have a separate 14-variant minimum-DSL compile check. No SM103 execution claim.
- The earlier five-workload, 80-arm study compares unroll 1/4/8 and a preconverted-half attribution control. The candidate's same-plan geometric latency ratio versus unroll1 is 0.854; one nearly flat dense cell retains a +0.158% reverse-order result.
- A separate six-workload, 54-arm physically padded ragged study gives a 0.871 geometric latency ratio; all 18 same-plan pairs improve in both orders. Full FP64 O/Stats, exact gap canaries and changed-length/origin/table replay pass. These are local SM100 warm CUDA Graph measurements against the parent converter, not serving results.
- Minimum-DSL SM103 ragged SASS has additional static local-memory instructions (2 stores/2 loads to 5/5). That limitation is retained; the measured SM100 result does not establish SM103 performance.
- Scoped pre-commit passes. No heuristics changes.
