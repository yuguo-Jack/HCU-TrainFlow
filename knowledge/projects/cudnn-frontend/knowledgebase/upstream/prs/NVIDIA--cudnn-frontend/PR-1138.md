# frost(sdpa): SM89 (Ada / L20) d64 dense forward row

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1138) · state: open · merged: False

## Original PR description

## Change

Add the opt-in `sdpa_fwd_prefill_sm89` d64 dense FP16/BF16 forward row for Ada (compute capability 8.9), using the existing SM80-family template with an architecture-specific gate and a plan-time shared-memory check. The SM80 row remains gated to compute capability 8.0.

The review follow-up fixes auxiliary staged-copy caching: input gathers and output copies include target compute capability in both their in-memory and persistent template keys, and compile in the operand device context. Forward, backward, and packed-copy callers pass their actual device; the packed outer memo also includes the device ordinal. This prevents an Ada-first staged d32 compile from being reused as an A100 copy kernel, or the reverse.

The mixed-family regression covers native d64 and staged d32 in both A-B-A device orders. It shares the core SDPA artifact, allows one auxiliary-copy compile per family, forbids JIT on return to the first family, and checks O/LSE against FP64 references and across devices. Remove the duplicated SM89 configuration header and correct the widening explanation.

## Supported row

Dense `bshd`/`dense_flex`, d64 FP16/BF16, unmasked, top-left causal, and qualified left sliding-window cases. Right-band widening is not yet qualified for this row; the kernel supports it, so the earlier accepted-and-ignored explanation was incorrect. The capability remains narrow pending a separate qualification. GQA/MQA, other head sizes, packed input, bottom-right causal, padding, sinks, bias, decode, FP8/MXFP8, and other architecture rows remain outside this row's advertised support.

## Validation

- Four private host-cache controls reproduce the old wrong-target reuse and verify the new architecture separation, explicit device context and restoration, and A-B-A reuse for both copy factories. The CUDA compiler and context are test doubles in these controls.
- Targeted Black, Black-Jupyter, SPDX, Python syntax, and diff checks passed.
- The new mixed SM80/SM89 GPU cases have not been compiled or run on this host. Native collection fails because the CUDA cuDNN Python extension is unavailable.
- Earlier L20 qualification and timing results belong to the prior GPU-tested revision; this cache follow-up has no new GPU validation or performance claim.

## Merge order

As requested, #1141 must land first, then this branch needs to be rebased on develop so the PR contains only the SM89 row and its required cache follow-up. #1141 is currently open, so that dependency cleanup is still pending.
