# Gate unified SDPA compute type on cuDNN 9.29

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1786) · state: closed · merged: True

## Original PR description

Unified forward SDPA compute type now follows the usual cuDNN version gates: `CUDNN_VERSION >= 92900` for the enum reference and the existing runtime backend-version check for dynamic loading. This removes the development-header feature macro added in #1746.

**Merge ordering:** keep this PR in draft until backend MR !4785 is merged and a daily cuDNN 9.29.0.x build containing `CUDNN_ATTR_OPERATION_SDPA_FWD_COMP_TYPE` is available. Earlier 9.29.0 development headers without that enum are intentionally not supported by this follow-up.

## Affected area

C++ frontend unified forward SDPA descriptor construction, shared by the existing Python graph API, and attention documentation.

## Summary

- Replace `#if (CUDNN_VERSION >= 92900) && defined(CUDNN_HAS_SDPA_FWD_COMP_TYPE)` with the version check alone.
- Retain `NV_CUDNN_FE_DYNAMIC_CHECK_CUDNN_BACKEND_VERSION(92900, ...)` before setting a non-default compute type when dynamically loading the backend.
- Update the older-header error to name cuDNN 9.29.0 and update the documentation to state the supported version contract.

## Why

Backend review requested the same version-only convention used by the other unified SDPA attributes. Maintaining a separate capability macro in the backend and frontend is unnecessary once a daily 9.29.0 build with the attribute is available.

## Related issues

- Follow-up to merged #1746.
- Companion [cuDNN backend MR !4785](https://gitlab-master.nvidia.com/cudnn/cudnn/-/merge_requests/4785) removes `CUDNN_HAS_SDPA_FWD_COMP_TYPE` from the public backend header.

## API and compatibility impact

No new public API or accumulation mode is added. Default/explicit FLOAT continues to avoid the new attribute entirely. An explicit or inherited HALF request uses the existing backend attribute on 9.29+; older headers or dynamically loaded older libraries reject it. The companion backend still rejects HALF at descriptor finalization because FP16 accumulation is not implemented.

Released headers older than 9.29 remain compilable. Early 9.29 development headers without the new enum may fail compilation after this PR; that compatibility is intentionally outside the supported contract. Static-link builds retain the existing direct backend-call behavior.
