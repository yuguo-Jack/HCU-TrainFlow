# perf(sdpa): join D64 CGA1 softmax row maxima

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2059) · state: closed · merged: True

## Original PR description

SM100 BF16 D64 causal prefill currently reduces each 64-column score chunk separately before publishing alpha. Build one maximum tree across the 128-column row for the existing dense, unsplit CGA1 geometry. The change applies to both masked and interior tiles and both packing modes; loads, sums, synchronization and workspace stay unchanged.

On the same local 68-SM SM100, warm CUDA-graph replay for the consumed 8K GPT-OSS sink workload improves packed latency from 284.1 us to 272.7 us (about 4%). This is about 3.3% faster than the former best native unpacked plan (281.9 us), leaving about 1.8% to the retained backend control (267.9 us). Existing 2K CGA1 controls improve about 1.8% packed and 0.7–0.9% unpacked. CGA2 keeps its prior tree because its measured effects were small and mixed. These are kernel timings, not serving E2E results.

Validation:
- All 24 existing D64 causal-softmax tests pass, including forced online rescale, tails, bottom-right masks, sinks, fresh bindings and changed-input retained replay.
- Three existing GPT-OSS workloads, both packing modes and CTA widths, reversed process orders and separately compiled unchanged controls: 84 plan/order correctness checks pass. The final scoped source also passes a 14-cell replay/rebinding comparison and reproduces the 8K gain.
- Specializing the new condition off reproduces the parent module AST; specializing it on matches the measured prototype. Scoped pre-commit checks pass.

No eligibility, public knob, heuristics or placement changes. Tested with CuTeDSL 4.8.0, CUDA 13.4 compiler and cuDNN 9.28 dev.
