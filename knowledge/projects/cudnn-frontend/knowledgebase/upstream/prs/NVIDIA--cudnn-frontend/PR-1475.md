## Summary

**Release 1.31: please cherry-pick into `1.31.0-rc`.** The change is test-only and applies unchanged there.

`test_ref_cache.py::test_the_recipe_files_are_the_test_trees_frames_never_the_harness` (#1457) asserts that some frame path on the stack contains `site-packages`. The CI images are Debian-based and install pytest under `/usr/local/lib/python3.12/dist-packages`. The assertion therefore fails deterministically on every `python:{dev,rel}:{sm80,sm90,sm100}` lane and on `deploy:test_bdist_wheels_ga_cudnn_3.12:{sm80,sm90}`. Examples: nightly 72349147, jobs 475494726, 475494678, 475494679.

`ref_cache._library_roots()` itself already covers `dist-packages` through `site.getsitepackages()`. Only the test spelled the path.

**Fix.** The test now locates the harness by module: the directories of `_pytest`, `pluggy` and `torch`, plus the standard library. It no longer matches a path spelling. Both assertions keep their meaning:
- pytest frames are on the stack;
- none of them is a recipe file.

## Testing

- `sdpa/test_ref_cache.py` in a venv (`site-packages`): 17 passed.
- No `dist-packages` interpreter with pytest and torch is available locally, so this PR's CI python lanes are the `dist-packages` check.
