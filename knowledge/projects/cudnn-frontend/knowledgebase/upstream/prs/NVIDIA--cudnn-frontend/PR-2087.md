## Affected area

CI or test infrastructure: BSA FP8 dispatch contract.

## Summary

Pin `k_quant_block_size=16` in both SM120 quantizer and launch expectations. Keep exact keyword equality, the SM90 V layout, sparse metadata, argument identity and dispatch-order checks.

## Why

#2004 added the K-scaling recipe argument with a default of 16. The existing dispatch test still expected the earlier keyword sets, so its SM120 case failed before reaching the launch check. Scheduled develop pipeline 77874593, job 518907002, shows this failure at source `5d9990b8e72a5dab3b5fc9f6a0a91531fbcdc456`; it remains on develop `73b1c185a19218213a7e5b9f9d11a1fe13cc412b`.

## Related issues

Follow-up to #2004. Auto-FE todo 0009.

## API and compatibility impact

None. Test expectations and their docstring only.

## Testing

Rebuilt native bindings from the isolated worktree and verified the package, native binding and BSA API import paths. On SM100, from `test/python`:

```
python -m pytest -o addopts= -n 0 -rA --tb=short block_sparse_attention/cutedsl/test_BSA_attention_fp8.py::test_bsa_fp8_blk128_dispatch_preserves_v_layout_and_metadata
```

- Before: 1 failed (SM120 dispatch case), 1 passed (SM90 case).
- After: 2 passed.
- Changed-file pre-commit and `git diff --check` passed.

This test models the two dispatch architectures and replaces quantization/kernel launch with argument checks. It does not measure kernel numerics or performance. Targeted `python/misc` CI will run the affected CuTe DSL suite.
