## Affected area

FE OSS kernels or CuTeDSL; benchmarks and performance documentation.

## Summary

This follows the memory-bounded deterministic DSA backward implementation from #1770 and improves its clustered dKV relay path without changing the public API.

- streamline the GPU-scope release/acquire ownership chain and remove redundant GPU-wide fences and relay rendezvous
- retain the portable 8K crossover to four-CTA relays and the existing 32 GiB memory-first fallback to sixteen-CTA relays
- combine relay planes directly in fixed order in the conversion kernel, removing the separate FP32 prefold launch
- add production-width TopK=2048, cluster-4/8/16, repeatability, and CUDA Graph coverage
- document latency, workspace, Nsys, and NCU results

## Why

The merged relay implementation bounds deterministic dKV scratch for large contexts, but its hot path still paid for two GPU-wide fences, redundant CTA rendezvous, and a separate prefold pass. An explicit cluster-4 profiling experiment showed that its 32 main-kernel waves dominated Q=4K latency. The automatic policy keeps the conservative cluster-8 selection below Q=8K because the earlier cluster-4 crossover did not generalize across SM100 devices.

The optimized ownership chain remains explicit:

1. producer reducer threads complete their relaxed FP32 atomics
2. a participating CTA barrier orders those atomics before the slot-lane GPU-scope release
3. the next rank observes that release with a control-dependent GPU-scope acquire load
4. its participating CTA barrier carries the acquired visibility to all reducer threads before subsequent dKV atomics

Rank zero has no predecessor and the final rank has no successor. Kernel completion covers the final tile. The protocol orders only ranks whose sparse TopK rows overlap. Duplicate indices within one query's active TopK prefix remain outside the deterministic contract, as in the existing bounded-wave path.

## Performance

Measured on the SM100 test environment with PyTorch 2.14.1+cu130, CuTe DSL 4.8.1, cuDNN 9.24, BF16 H64, TopK=2048, synthetic forward statistics, five warmups, and 40 allocation-free calls.

The automatic policy uses cluster-8 below Q=8K, cluster-4 for longer queries, and the eight-plane cluster-16 fallback when the preferred layout would exceed the 32 GiB relay budget.

In an explicit Q=4K cluster-4 experiment, Nsys attributes the local gain primarily to the 32 main-kernel waves (22.941 -> 9.696 ms). This is implementation evidence rather than the portable automatic policy. The optimized trace has no prefold kernel; fixed-order conversion takes 1.452 ms and workspace clearing takes 0.658 ms.

NCU reports 96 registers/thread, 231.42 KiB dynamic shared memory, one CTA/SM residency, 26.33% achieved occupancy, 57.37% DRAM throughput, and 35.07% compute throughput for the cluster-4 main kernel. A 144-CTA experiment regressed 12.017 -> 14.932 ms and increased scratch from 4.533 -> 5.096 GiB, so the 128-CTA wave is intentional.
