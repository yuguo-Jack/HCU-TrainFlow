## Affected area

FE OSS kernels / CuTeDSL: packed split-KV SDPA combine.

## Summary

Packed split-KV attention uses the generic reduction loop even when its prepared plan already knows the split count. Pass that existing plan-time information to the combine and reuse its existing small-group prefetch reducer for aligned FP32 partials with up to eight splits.

Compile only the reducer group required by the plan. Standalone runtime-split callers, larger split counts and unsupported dtype/alignment/width combinations retain the generic path.

## Why

The small-group reducer can issue partial loads together before consuming them. Reusing it removes dependent-load serialization in the packed combine without adding a kernel launch or preparing metadata during execution. Selecting the group at plan time avoids compiling several unused reducer variants.

This is a kernel-path optimization, not a change to split selection or a claim about serving throughput. The specialized body adds compilation work at plan build; warm execution does not compile or select another kernel.

## Related issues

Follow-up to the existing prepared ragged/paged split-KV execution path. No issue is closed by this PR.

## API and compatibility impact

No public API, tuning knob, capability, dependency floor, workspace size or native-binder change. Split count was already part of the attention plan; this adds no runtime-data cache key. Live packed totals, pointers and strides stay runtime inputs. Partial Stats remain natural-log; requested final Stats conversion and folding an attention sink once are preserved. Unsplit plans are unchanged.

- Independent full-attention comparisons check O/LSE against FP64 and poison workspace/outputs before replay. Cases include changing lengths, zero live totals, retained captures, independent K/V layouts/tables, Stats NH/HN and ln/log2/none, strided outputs, sinks and inactive partials.

No timing threshold or heuristic winner/order golden is added. Target-hardware performance measurements are kept separate from these functional checks.

Review follow-up (`cf3823164`): mask partial O by its computed weight, so finite-LSE underflow or a dominating sink cannot contaminate the result through `0 * NaN`.
