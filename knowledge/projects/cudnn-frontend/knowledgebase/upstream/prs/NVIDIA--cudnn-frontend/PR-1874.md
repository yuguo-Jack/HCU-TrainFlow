# feat(sdpa): support paged FP8 attention sinks

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1874) · state: closed · merged: True

## Original PR description

Per-tensor FP8 attention with paged K/V and a per-head sink is declined even though the SM100 D64/D128 kernel already has the paged loader and the sink epilogue. Admit that composition in graph support checking and the standalone API, and update the support matrix.

The added tests cover packed and unpacked GQA, MHA, independently laid-out K/V pools, both FP8 input formats, output formats and optional Stats, causal/window masks, empty KV and trimmed Q. A retained CUDA graph is replayed after rebinding storage and changing sinks, lengths and page-table contents; outputs are poisoned before replay. D128 replay covers both CTA widths.

## Affected area

FE OSS kernels or CuTeDSL — SDPA capability admission and regression tests.

## API and compatibility impact

Existing graph and standalone signatures are unchanged. SM100-line per-tensor FP8 D64/D128 paged plans now accept attention sinks. The existing FP8 split-plus-sink restriction remains, as it does for dense KV; paged THD queries and block-scaled outputs retain their existing restrictions.

## Testing

Coverage lives in `test/python/sdpa/frost/test_sdpa_fwd_paged_sm100.py`, including `test_paged_graph_fp8_sink` and `test_paged_graph_fp8_sink_rebind_replay`. Run the per-tensor FP8 subset with:

```sh
cd test/python
pytest -q -o addopts= -m L0 sdpa/frost/test_sdpa_fwd_paged_sm100.py -k 'fp8 and not mxfp8'
```

Pre-commit passes for all four changed files. The regression first demonstrates the missing plan on the parent implementation; candidate checks compare O, Stats and Amax_O against the existing FP64 reference and check exact-zero dead rows.
