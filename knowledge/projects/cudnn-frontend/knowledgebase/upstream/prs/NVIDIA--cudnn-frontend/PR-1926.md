# sdpa: enable deterministic native D192/D256 half backward

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1926) · state: closed · merged: True

## Original PR description

The native D192x128/D256 half backward engine rejected `use_deterministic_algorithm=True` even though its output tiles and gradient reductions already have fixed ownership and order. This enables the request for dense and packed THD inputs on SM100/SM103, using the same kernel and workspace chain.

## Affected area

FE OSS SDPA backward APIs, eligibility and tests.

## Summary

- Admit deterministic FP16/BF16 requests for native D192x128 and D256, dense and THD.
- Keep other adapters behind their existing deterministic capability gate.
- Check raw gradient bits across repeated execution, changed bindings and retained CUDA Graph replay, including workspace chunks, physical origins and empty sequences.

## Why

A deterministic request should reach the existing fixed-order native implementation across both supported layouts. This adds no gradient algorithm, workspace or kernel launch.

## Related issues

Native packed D192x128 is now on develop through merged #1925. The deterministic change is commit `509abd139139ee2c320f061ceb6e8c3f890a1099`; merge commit `0afa3809be9f291e0897ed61d8ea55947531b7b8` incorporates that landing and resolves the shared test-helper conflict. The full source tree is identical to the tested `509abd139` tree; scoped and commit hooks pass.

## API and compatibility impact

The existing opt-in `sdpa_bwd_sm100_d256` engine accepts the additional request. Public signatures and default placement are unchanged. Other capability restrictions remain.
