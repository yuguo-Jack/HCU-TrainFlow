## Summary

TE/JAX asked for a JAX API for the Rubin-specialized grouped GEMM + SwiGLU + MXFP8 quant fusion (#1275). Following the unified API convention, new JAX ops go through the unified `*_jax_sm100` entry point, not new `cudnn.jax` names. The existing `cudnn.jax` ops are kept as aliases.

| | JAX | Torch |
|---|---|---|
| Unified GLU forward | `grouped_gemm_glu_jax_sm100(..., b_tensor=, sfa_tensor=, sfb_tensor=, norm_const_tensor=)` (canonical MXFP8 mode, new) | `grouped_gemm_glu_wrapper_sm100` (now also dispatches canonical MXFP8 JAX inputs) |
| SwiGLU forward | `cudnn.jax.grouped_gemm_swiglu`, kept as an alias of the unified MXFP8 path with `act_func="swiglu"`, `generate_c=True` | unchanged |
| dSwiGLU backward | `cudnn.jax.grouped_gemm_dswiglu`, kept | unchanged |

1. **Unified GLU JAX entry.** `grouped_gemm_glu_jax_sm100` gains keyword-only `b_tensor`, `sfa_tensor`, `sfb_tensor`, `norm_const_tensor`, `discrete_col_sfd`, and the GeGLU scalars. That selects the canonical MXFP8 mode:
   - A `(m, k)` and B `(experts, n, k)`;
   - `act_func` `"swiglu"` or `"geglu"`, with the activation scalars as compile-time constants;
   - returns a `TupleDict` with the eager wrapper's keys (C only with `generate_c`).

   The existing BF16 discrete mode (`b_ptrs`, `n`) is unchanged, including its positional order and `(d, c)` return.
2. **Wrapper dispatch.** `grouped_gemm_glu_wrapper_sm100` sends JAX inputs with dense `b_tensor` and `sfa_tensor` to it. The check runs before the hot-loop memo, since JAX tracers can't enter the memo key, and costs Torch calls about 90 ns. The BF16 JAX path and the existing JAX error paths are unchanged.
3. **Rubin kernel selection.** On SM107 the canonical mode builds `moe_blockscaled_grouped_gemm_glu_rubin.BlockScaledMoEGroupedGemmGluKernel`, validated with its own `can_implement`. Neither kernel uses a workspace for dense weights, so one adapter serves both.
4. **`discrete_col_sfd`.** Expert-packed column scales are now accepted by the canonical GLU/SwiGLU/dSwiGLU JAX paths and wrappers, which previously rejected them.
5. **No output zero-fills.** Outputs the kernels write are no longer zero-filled; only backward `dprob` is initialized, for atomic accumulation. This follows #631.

This is based on @jberchtold-nvidia's prototype (`jberchtold/rubin-gmm-fusion`), rebuilt on `develop` after #1233. The prototype added a Rubin-only `cudnn.jax.grouped_gemm_glu` that always returned a 3-D C. Here the unified entry serves both architectures, returns 2-D outputs, and requires `generate_c=True` to return C, as the Torch wrapper does. dSwiGLU has no Rubin-specific kernel, so its JAX path only gains changes 4 and 5.

## Why

- The unified GLU wrapper is the API TE's grouped MLP calls. JAX needs the same entry, on both SM100 and Rubin, under the `_jax_sm100` convention.
- TE uses expert-packed column scales on the Torch side; JAX could not request them.
- XLA zero-filled C, D, D_col and both SF buffers before every call. The Torch wrapper never paid that cost.

## Related issues

Closes #1275.

## API and compatibility impact

- No new exports; the API index is unchanged. `grouped_gemm_glu_jax_sm100` gains keyword-only parameters. `b_ptrs`, `n` and `prob_tensor` become optional in the signature, but BF16 mode still requires `b_ptrs` and `prob_tensor`.
- New optional `discrete_col_sfd=False` on `cudnn.jax.grouped_gemm_swiglu` and `grouped_gemm_dswiglu`.
- No deprecations: renaming or retiring existing names is left to the API pruning plan (#1461).
- `grouped_gemm_glu_wrapper_sm100` with canonical MXFP8 JAX inputs now runs instead of raising. It requires `sf_vec_size=32` and an FP8 `d_dtype`. Bias, discrete weights, SiTU-GLU, dynamic scheduling, `b_major="n"`, `sf_fp8_dtype_override` and caller streams raise `ValueError`.
- JAX output rows at or past `padded_offsets[-1]` (data and scale factors) are now **unspecified** instead of zero, matching the Torch path. Backward `dprob` padding stays zero.
- Performance, `jax.jit` wall time on SM100:
  - Shape: 8 experts; M 49152 allocated, 24576 active; K 7168; forward N 4096, backward N 2048.
  - Method: median of 3 interleaved rounds of 50 calls, in one process. Develop's zero-fills were restored by swapping in the old `grouped_call`.

| | develop (zero-filled) | this PR |
|---|---:|---:|
| SwiGLU forward | 794 µs | 627 µs |
| dSwiGLU backward | 622 µs | 422 µs |

Repeated samples varied by 100 µs or more, so treat these figures as approximate.

  - Seen red: JAX with `discrete_col_sfd=False` mismatches the packed Torch reference in both directions.
