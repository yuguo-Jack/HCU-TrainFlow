## Affected area

Build, packaging, installation, and documentation.

## Summary

Bring over the existing Windows ARM64 packaging fixes: skip unavailable CuTe DSL/TVM runtime wheels, select Ninja >= 1.13 on Windows ARM64, declare Python 3.15 support, and pass CMake's build configuration as separate arguments. Remove stale setup comments.

Replace the norm README's private package-index command with its actual requirement: a DSL build >= 4.7.0 that exports `cutlass.primitives`, plus an import check.

## Why

The packaging files differed between the GitHub and GitLab trees. The norm installation instructions also caused the guardword scan to fail.

## Related issues

None.

## API and compatibility impact

No API changes. Other platforms retain their existing dependencies and Ninja pin. Windows builds now honor Debug or Release. The norm requirement is unchanged; a version number alone does not guarantee the required module is available.

**Gate Flex Attention before importing its CuTe DSL modules on Windows ARM64.**

The new markers remove both runtime packages, but `cudnn.flex_attention` eagerly imports `dispatch.py`, which imports `cutlass`, and `compile_cache.py`, which imports `tvm_ffi`. Therefore, `import cudnn.flex_attention` fails on Windows ARM64 before any operation runs. Add the same pre-import DSL availability gate used by `cudnn.norm`, or explicitly remove this feature from the supported Windows ARM64 surface.
