## Summary

The paged generation suites excluded ragged query/output layouts. The FP8 harness also redeclared sequence-length tensor UIDs and attached packed K/V offsets to dense page pools when combining these layouts.

Build and bind sequence lengths once, pack only Q/O/Stats for paged KV, and retain packed K/V behavior for unpaged ragged input. Enable ragged draws in the f16 and FP8 paged suites and independently draw paging for model generation. The existing FP8 THD head-dimension limit remains 128.

Deterministic regressions exercise mixed query/KV lengths through both shared harnesses, with f16/bf16 and E4M3/E5M2 inputs, regular/cumulative lengths, padded controls, and independent O/Stats references. Metadata regressions cover both length representations and ragged offset multipliers, alongside unpaged packed-KV controls. Unsupported backends retain the existing harness decline/skip behavior.

Related to #966.

Validation on RTX 6000D (SM120), PyTorch 2.13.0+cu130, driver 595.91.07, cuDNN 9.27.0.42, CuTe DSL 4.8.0:
- New regression against unchanged baseline: **11 failed, 10 passed, 2 skipped**. Failures identify duplicate length UIDs, conflicting regular/cumulative lengths, illegal K/V pool offsets, and missing suite/model draws.
- Updated regression: **17 passed, 6 skipped**. This includes six native-backend f16/bf16 numerical cases comparing O/Stats across regular ragged, cumulative ragged, and padded layouts. The six FP8 numerical cases decline on SM120; they are not counted as numerical validation.
- Selected generated paged suites and llama31 model controls: **11 passed, 10 skipped** (8 native graphs, 3 existing SM120 FROST graphs). Skips are unsupported FP8 graphs; one selected random FP8 shape has a head dimension outside the multiple-of-16 requirement. Six compiler optimization warnings are from the unchanged SM120 kernel.
- Directory collection finds all 23 new cases: **13310/13902 tests collected (592 deselected)**.
- Changed-file pre-commit hooks and `git diff --check` pass.

Independent SM100 qualification of `0cc92dbcac91` subsequently passed all 23 new cases with FROST enabled and again with it disabled, including all six FP8 O/Stats numerical cases. See [review 5731511703](https://github.com/NVIDIA/cudnn-frontend/pull/2183#pullrequestreview-5731511703). The maintainer-requested SDPA misc pipeline also passed on that head; SM100 passed all 23 new cases, while SM80/SM90 each passed 17 and skipped six ([CI result](https://github.com/NVIDIA/cudnn-frontend/pull/2183#issuecomment-6567844020)). These are focused checks, not exhaustive randomized or multi-architecture qualification.

CodeQL follow-up explicitly initializes the three optional packed-KV locals (`max_t_kv`, K/V ragged offsets) to `None` before conditional allocation. Valid dataflow already follows `kv_packed(cfg) => cfg.is_ragged`; packed allocations overwrite these defaults before guarded reads, and paged/dense layouts leave the metadata absent. No allocation, graph binding, reference, tolerance or assertion was changed.

After this cleanup, the same deterministic and selected generated/model controls on the supplied SM120 server pass: **28 passed, 16 skipped, 64 deselected**. This does not add SM120 FP8-paged qualification. Changed-file Black, Black-Jupyter, SPDX and diff checks pass. The cleanup was independently reviewed.
