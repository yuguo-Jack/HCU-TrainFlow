# SDPA: validate Python-only workspace devices before prepared launch

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1846) · state: closed · merged: True

## Original PR description

Prepared SDPA could accept a workspace wrapper on the wrong CUDA device when the wrapper exposed `.device` but did not implement `__dlpack_device__`. The graph normalizer accepts this Python producer, but the workspace guard only consulted DLPack, allowing an invalid pointer to reach execution.

Check the observable Python device in that fallback. Ordinary DLPack producers keep their existing device check, and bare integer addresses retain their caller-managed placement contract. This is independent of the in-progress ordered-binding optimization.

The regression covers mapping and ordered graph execution, valid-input recovery, CPU and foreign-CUDA declarations, malformed/partial declarations (including strings and explicit `None`), and the absent-device caller contract. Invalid-device controls record a would-be launch so testing the unfixed code cannot poison a CUDA context. The agent guide records this validation technique.

Validation:

- Both new regression cases fail safely on the original guard; the focused GPU suite passes **83 tests, zero skips** with the fix.
- A separate two-device check rejects four foreign workspaces before writes and passes ten subsequent eager/capture O/LSE checks against FP64 references.
- Full native build and scoped formatting/license checks pass.

**Owner closeout complete; ready for normal merge.** The independent review is approved. The source change preserves the ordinary DLPack workspace path, and the controlled same-process comparison below finds no consistent common-path cost. This is sufficient for this scoped correctness fix. The original interprocess outliers remain documented and unassigned; this is not a blanket performance-equivalence or serving claim. No kernel or heuristic changes are included.


Follow-up on `13c1645df`: the malformed-device review finding is fixed, with the same **83 tests / zero skips** and two-device qualification passing. A separate, fixed same-process experiment compares the exact old/new functions using the same graph, pointers and native module, with CPU/scheduling counters. All four FROST host aggregates differ by less than 0.6%, and none of their 32 paired blocks exceeds the original 2% diagnostic threshold. The two flagged pairs in this new experiment occur in unchanged backend controls, which do not call the modified function. All samples and flags remain included. This finds no consistent common-path cost on the tested graphs; the original interprocess outliers remain unassigned, and no serving or unconditional equivalence claim is made. Current-head independent review is now approved. Actual terminal logs and JUnit agree for all five scoped CI lanes (SM80/100/103/107/120): 73,390 passed, 41,271 skipped and 29 existing expected failures, with no failures or errors. Skips and expected failures are not counted as passes. Current-head approval, public checks and review threads were rechecked before normal merge.
