## Affected area

FE OSS kernels or CuTeDSL

## Summary

`Nvfp4AttentionQatBackward` lists cc 10.3 among its supported parts, but `_frost_support_reason` declined every part except cc 10.0. With `backend="auto"` a B300 therefore always fell back to Triton, and `backend="frost"` raised. The FROST kernels compile for the device's own target, so the backend now accepts cc 10.0 and 10.3 (`_FROST_CAPABILITIES`). The other FROST requirements are unchanged: B=1, noncausal, equal sequence lengths divisible by 256, and CuTe DSL >= 4.7.0.

Test changes:

- `test_nvfp4_attention_qat_frost.py` and the FROST-executing cases of `test_nvfp4_attention_qat_dispatch.py` run on both parts.
- The metadata-only probe `test_auto_architecture_selection_metadata_only` checked that a patched cc 10.3 falls back to Triton. It now covers the SM120 parts only.
- The docs' FROST section says SM100/SM103.

The Triton route's 64x64 tile choice (`optimized_sm100`) is still cc 10.0 only; this PR does not change it.

## Why

On a B300 the FROST backward was never selected although it runs there.

## Related issues

None found.

## API and compatibility impact

None on cc 10.0. On cc 10.3, `backend="auto"` now selects FROST for the declarations FROST serves, and `backend="frost"` succeeds instead of raising.

## Testing

B300 (cc 10.3), develop `64ed3dfe` with its own extension, torch 2.14.1+cu130, cuDNN 9.27.0, CuTe DSL 4.8.1, Triton 3.8.0, run from `test/python`:

The PR has one case fewer because the cc 10.3 parametrization of the metadata-only fallback probe was removed. Not run on cc 10.0, where the check admits the part exactly as before.

B300 performance for this change, since it makes `backend="auto"` select FROST on cc 10.3.

`benchmark/nvfp4_attention_qat/benchmark_backends.py` on this head: B1, D128, BF16, noncausal, equal lengths, `head_chunk=0`. Environment: torch 2.14.1+cu130, Triton 3.8.0, CuTe DSL 4.8.1. Each arm is the median of ten CUDA-graph samples (three backwards each), ABBA order:

| Heads | Sequence | Triton ms | FROST ms | Speedup |
|---|---|---|---|---|
| 3 | 8192 | 1.9226 | 0.4894 | 3.93x |
| 3 | 32768 | 26.5224 | 5.4850 | 4.84x |
| 12 | 8192 | 6.7414 | 1.4532 | 4.64x |
| 12 | 32768 | 102.0361 | 19.1865 | 5.32x |

- Auto resolved to FROST in every case.
- dV was bitwise equal to Triton. dQ / dK relative L2 was 0.0032, as in the SM100 README.
- Workspace is identical for both arms.

The Triton arm here is the 32x32 launch that cc 10.3 gets today. #2106 gives cc 10.3 the cc 10.0 64x64 launch, which is about 2x faster there. Against that launch, FROST is 2.01x, 2.43x, 2.38x and 2.60x faster on the same four cases.
