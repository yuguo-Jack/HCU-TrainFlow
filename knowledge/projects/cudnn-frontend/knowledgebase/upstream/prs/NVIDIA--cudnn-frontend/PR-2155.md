# Fix independent physical origins in native D192 THD attention

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2155) · state: closed · merged: True

## Original PR description

Nonpaged half D192/V128 THD plans currently accept independent ragged offsets but can read compact logical prefixes instead of each tensor's physical origin. Bind Q/K/V/O/Stats origins in the native two-CTA paths and the existing shared single-CTA path, while keeping logical lengths and scheduling metadata separate from storage addressing.

The existing device setup builds sequence-local TMA maps for gapped storage and retains one map per load port for compact two-CTA inputs. Stats stores honor their declared packing, initially dead clusters exit before acquiring uninitialized maps, and Q loads reuse the acquire at each descriptor lifetime boundary. This uses the existing binder and one setup launch, without staging tensors or changing the caller API.

Depends on #2153. The inherited D192 scheduler implementation is reviewed there. This PR also adds the full-capacity persistent-tail regression requested in that review. Scope is unsplit, nonpaged BF16/FP16 D192/V128. Split-origin support remains separate.

Validation:

- 12 native independent-origin cases pass on each of SM100 and SM107, covering both half dtypes, token/head Stats, CGA1/CGA2, Natural/LPT, mixed offset integer widths and multipliers, changed storage/strides/lengths, retained capture, keyless rows and empty replay.
- Existing compact/LPT controls: 8 passed on SM107; 6 passed and 2 architecture-specific skips on SM100.
- On each architecture, memcheck, racecheck and synccheck each pass two focused native cases with zero reported errors.
- 28 host contract checks pass. Collection through the selected architecture CI entries confirms 12 new cases per architecture; the shared helper is not independently collected.
- Two additional SM107 persistent-tail cases pass for FP16/BF16: live work exceeds the actual bound launch, followed by changed-length/keyless and empty replay.
- The unchanged baseline fails the preparation detector because origin specifications are absent. Scoped pre-commit hooks and diff checks pass.
