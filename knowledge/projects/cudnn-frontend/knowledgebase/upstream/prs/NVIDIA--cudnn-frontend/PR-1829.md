## Affected area

FE OSS kernels or CuTeDSL (SDPA forward heuristics / placement)

## Summary

Two default-order fixes for dense SDPA forward:

1. **Rubin per-tensor FP8 dense d128** (`_sm107_fp8_dense_d128`, `_sm107_fp8_d128_chunk_leads`):
   - PackGQA now goes first at every S_q.
   - The chunk arm extends to s_q ≤ 4096 for packed GQA.
   - MHA leads only within one wave of 2-SM clusters (b·h_q ≤ SMs/2), and only causal with s_q ≤ 512.
2. **d512 sliding window** (`_d512_swa`): the SM100 / SM107 half rows, SM100 / SM107 per-tensor FP8 rows and SM90 half row lead dense causal windows at exact d512, for s_q ≥ 128 and S_kv ≥ 1024 with no sink or right band. This is DeepSeek-V4's SWA-128 MQA core.

## Why

**FP8 d128.** #1790 capped the Rubin FP8 d128 chunk arm at s_q ≤ 512 and called the loss above it a "512-row cluster wave cliff". A candidate audit (every legal plan timed) shows the cliff is the heuristic, not the kernel:
- Past one 512-row Q tile the unpacked plan pads every head's last tile: q576–768 runs 1.28–1.87x the backend's time.
- PackGQA runs at 0.85–0.96 of the backend at every S_q.
- The same audit found that #1790 led MHA at ≥ 128 units, where the 512-row tile carries ≤ 128 live rows per unit and loses 1.24–1.77x.

Hold-out 4 used 102 random cases, with the rule frozen and the code deployed before measuring, and every legal plan timed:
- 99 cases scored: 31 led at 0.10–0.91, with no lead-loss.
- Mean regret fell from 34.4% to 29.7%.
- 2 cases exceeded the audit's 600 s per-case budget and 1 had no FROST plan.

**d512 SWA.** The nightly attention_training dashboard showed FROST at 0.25–0.61 of the backend on the DSv4 SWA-128 core on every GPU, while every row trailed because of the window. A re-measurement used ab.py (CUDA-graph replay, warm and cold L2, cuDNN 9.27.0.42) over 36 graphs per dtype: MQA 64/1 and 128/1, 16/1, and GQA 32/4; top-left squares S = 1k / 4k / 16k at window 128 / 512 / 4096; bottom-right chunks q128 / q2048 over a 32k cache. FROST/backend time:

| GPU | bf16 | per-tensor FP8 |
|---|---|---|
| B200 | 0.24–0.57 | 0.32–0.90 |
| H100 | 0.18–0.75 | (the SM90 row serves no FP8) |
| Rubin | 0.33–0.97 | 0.40–0.73 |

FP8 agrees with the backend within rel-RMS 0.04 (E4M3 O); bf16 within 0.003.

SM120 is not measured locally, so its SWA rule is unchanged (window squares still trail).

## Related issues

Revises #1790's chunk rule. Related: #1788 (Rubin backend bottom-right short-Q has no KV split, so the FE default already routes FROST there).

## API and compatibility impact

None. This changes Python default ordering only. Capabilities and EngineSpecs are unchanged (exempt from SDPA Rule S2).
