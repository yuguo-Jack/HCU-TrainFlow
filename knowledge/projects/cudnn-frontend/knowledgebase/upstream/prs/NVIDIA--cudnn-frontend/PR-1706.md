## Affected area

FE OSS kernels or CuTeDSL

## Summary

- Remove the runtime PyTorch fallback from the SM100 DSA MXFP8 scale packers.
- Require contiguous one-byte CUDA inputs, a supported GPU, and the CuTe DSL runtime required by the existing CUDA packer.
- Require caller-owned output storage for THD packing so the supported path remains allocation-free, asynchronous, and CUDA Graph capturable after warm-up.
- Move the PyTorch layout implementation into a test-only byte-exact oracle and use it for DSA numerical fixtures.

## Why

The single-launch CUDA packer added in #1564 is the supported runtime implementation. Keeping a second PyTorch packing path duplicated the layout contract, hid unsupported environments behind a slower non-capturable fallback, and exposed unsupported E8M0 indexed-write behavior. The test-only oracle preserves independent layout validation without carrying that fallback in production.

## Related issues

Related to #1564.

## API and compatibility impact

This changes private DSA MXFP8 packing helpers:

- CPU, non-byte, strided, unsupported-GPU, and unsupported-CuTe-DSL inputs now fail explicitly instead of falling back to PyTorch.
- Runtime packing requires `nvidia-cutlass-dsl >= 4.7.0` and a compatible architecture target; the package-wide dependency floor remains unchanged.
- THD Q/K packing requires caller-provided `out` storage. BSHD/MKL helpers retain their allocation convenience and optional caller-owned outputs.
- The existing CUDA kernel implementation and packed layout are unchanged.
