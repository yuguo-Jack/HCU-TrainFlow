## Affected area

FE OSS kernels / CuTeDSL SDPA backward (the d128 f16/bf16 family of `sdpa_bwd_sm100_d128`), one FE node header, Python engine
integration, tests, docs.

## Summary

Four changes to the d128 backward family. (1) The `cta_group::2` pair body gets a DENSE twin: a dense compact-BSHD BF16 GQA/MQA
declaration is served by the pair under the default per-S rule exactly like the packed one -- the same five launches over the same workspace,
the main kernel byte-identical (the setup kernel synthesizes the packed metadata from the dense extents). (2) cc 10.7 (Rubin) is admitted in the
existing row for every body it dispatches, the compile target following the device as for cc 10.3 (no kernel is copied into another arch
directory; the sm_107a renderings hash kernel-by-kernel to the sm_100a records); the pair heuristic's per-S threshold becomes part-keyed and
is re-measured on Rubin (8192 holds); a pinned deterministic override that cannot finalize on cc 10.7 becomes a decline, so the FROST
recompute row serves deterministic d128 backward there. (3) Rubin's extra TMEM and SMEM are wired in as typed, part-keyed maps of the pair body -- `tmem_map = "dq_576"` (the independent dQ image
at columns 512-575 of the 576-column carve, two barrier rows fewer) and `smem_map = "rubin_b2"` (a two-stage dS / exchange staging ring with
`dq_read_done`, sQ1 x2, sDO1 x2 in the 327 KiB carveout) -- both measured on a Rubin class node and both kept OFF by default: the TMEM map is
neutral, the SMEM ring loses (numbers below), so the shipping maps stay the SM100 ones on every part. (4) The six d128 kernels of
`kernels/sm100` and their helper and per-route host modules are consolidated into `bprop_d128_f16.py` (13 kernels in nine sections,
each old module's header kept as its section docstring) and `prepared_d128_host.py` (one `compile_host_<route>` per route, every cache key and
exported symbol unchanged); 13 modules removed, no shims; pure code motion: 54 of 54 PTX renderings (sm_100a and sm_107a, 206 per-kernel
md5s) byte-identical before and after, every committed record reproduced. This supersedes the
earlier draft of this PR, which copied one body into `kernels/sm107` under a new engine id.

## Why

The pair body (the fastest d128 backward on Blackwell at S >= 8K) served only packed THD declarations; dense GQA fell back to the one-CTA
body. Rubin had no d128 backward row; its tcgen05 feature set is the SM100 line's, so the SM100 bodies run there unchanged. The one-CTA body
and the pair body each beat the alternatives on Rubin where a backend plan exists at all (below). One kernel module replaces five kernel
files and four helper files that had grown by accretion.

## Related issues

## API and compatibility impact

Append-only. `cta_pair` now admits dense compact-BSHD declarations (no new field; the selector's predicate is named `layout`); new typed
op-level field `tmem_map` on the pair body (`None` = the part's default, `s_tail` on every part; `dq_576` selectable by name on cc 10.7:
the independent dQ TMEM image at columns 512-575 of the 576-column carve, two barrier rows fewer, measured neutral, kept as the base of the
staging arm) and `smem_map` = "sm100" | "rubin_b2" | the diagnostic "sm100_oversized" (cc 10.7 only, off by default). `CTA_PAIR_MIN_SEQ` is a mapping per admitted cc (8192 on cc 10.0 / 10.3 / 10.7). Capabilities
row `sdpa_bwd_sm100_d128`: `sm_hi` 106 -> 107. SUPPORT_MATRIX_TRACKER.md and docs/operations/attention/sdpa_bwd_sm100_d128.md updated in the
same commits (Rule S2). Placement (the SDPA guide's placement rule): the THD d128 lead box applies on cc 10.7 as on cc 10.0 (the cuDNN backend offers no d128 THD
backward plan on cc 10.7 with 9.24 or 9.27, so the FROST row is the only candidate there); dense d128 trails on every part (parity measured
against the backend's engine on Rubin: +1.6 % at 16K, inside noise at 8K) until a placement study measures the dense pair twin. Declined by
name, unchanged: deterministic on the grouped / packed routes, FP16 grouped, windows on the pair, `dkv_accum = fp32_reduce` on the dense
pair twin, `16w_fa4` with `dq_576` / `rubin_b2`. The header change: `override_heuristics_query()` no longer pins backend engine 17 for deterministic
backward on `sm_version > 103` (it returns the "no override" value with the reason the (256, 512] band already uses); cc 10.0 / 10.3 keep
their engine-5 pin (verified). The fp8 backward node's identical branch is listed as an open item.
