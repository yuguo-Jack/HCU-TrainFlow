## Affected area

FE OSS kernels or CuTeDSL

## Summary

`bprop_d128_accum_grouped_f16.py:187` now passes `skv` to `dense._softmax_loop`, which is the argument list the dense caller at `bprop_d128_accum_f16.py:695` uses.

## Why

#1791 added an `skv` parameter to the dense kernel's `_softmax_loop` but did not update the grouped dense kernel's call. The arguments after `sq` shift left by one, so every grouped-GQA d128 backward build fails with `_softmax_loop() missing 1 required positional argument: 'dtype'`. The nightly attention_training run (backend 9.29.0.11, frontend 9c9db1e) records ten llama3.1 bf16 backward cases per clock leg on GB200 and GB300 that turned from valid to build failure.

The grouped dense kernel already takes `skv` as a parameter (line 154). Its `nk = skv // M` covers aligned lengths only, so the tail-key masking that `skv` drives in the dense loop is a no-op here.

## Related issues

Regression from #1791.
