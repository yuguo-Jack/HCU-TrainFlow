## Affected area

Packaging (Python wheel)

## Summary

**Release 1.31: please cherry-pick into `1.31.0-rc`.** The change applies unchanged there.

`kda_hopper_cuda` is the KDA engine ranked first on SM90. At run time it reads and NVRTC-compiles `python/cudnn/linear_attention/hopper/cuda_kernels/kda_{fused,bwd}_sm90.cu` (`hopper/cuda_host.py`, `hopper/cuda_bwd_host.py`). No `[tool.setuptools.package-data]` glob lists those files, and package discovery only collects `.py`. So the 1.30.0 wheel and the 1.31.0 candidate ship without them, and the engine raises `FileNotFoundError` from an installed wheel. The CAKE kernels next to them were already listed.

**Fix.** Add `"cudnn.linear_attention.hopper" = ["cuda_kernels/*.cu"]`.

**Tripwire.** The new `test/python/core/test_package_data.py` asserts that every non-Python, non-Markdown file under `python/cudnn` is matched by a package-data glob. It fails on the base with exactly these two files.

## Testing

| Check | Base (`1.31.0-rc`) | This PR |
|---|---|---|
| `setup.py build_py` output contains `hopper/cuda_kernels/*.cu` | no | yes (both files) |
| `cuda_host._library(0)` on H100, from the `build_py` tree (installed layout) | `FileNotFoundError: .../hopper/cuda_kernels/kda_fused_sm90.cu` | loads |
| `core/test_package_data.py` | fails, listing the two `.cu` files | passes |

Why CI did not catch this: under the repo's pytest setup, `cudnn` resolves to the installed tree but `cudnn.linear_attention.hopper.cuda_host` resolves to the source tree. So `test_bdist_wheels` reads the kernels from the checkout. I verified this by printing `cudnn.__file__` and `cuda_host.__file__` inside pytest. The direct probe above runs outside pytest.
