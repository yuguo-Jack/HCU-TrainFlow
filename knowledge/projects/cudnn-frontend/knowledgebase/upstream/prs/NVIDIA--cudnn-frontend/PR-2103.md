## Affected area

FE OSS kernels or CuTeDSL

## Summary

The experimental JAX block sparse attention (`cudnn.jax.block_sparse_attention`, `cudnn.ops.block_sparse_attention_{forward,backward}_jax`) ran only on compute capability 10.0. The torch BSA path already serves the same blk128 kernels on cc 10.3.

Admitting cc 10.3 at the device check alone is not enough. `forward_call` and `backward_call` compiled with `compile_options="--gpu-arch=sm_100a"`, and that cubin does not load on cc 10.3: the first run on a B300 with only the check widened failed in both parity cases with `Failed to load cutlass_call function: CuteDSLRT_Error_CudaError`. This PR:

- `jax_api.py`: `is_sm100` accepts compute capability 10.0 or 10.3. `configuration()` keeps the matched device and stores its arch-specific target in `Config.gpu_arch`: `sm_100a` on cc 10.0, `sm_103a` on cc 10.3. Both calls compile with `--gpu-arch={c.gpu_arch}`. `Config` is the `lru_cache` key of both calls, so the two targets never share a compiled call.
- `test/python/block_sparse_attention/jax/conftest.py`, `test_bsa_jax.py`, `cutedsl/test_BSA_jax_parity.py`: accept both parts. The torch-free isolation script checks that device 0 is the default device, not that it is cc 10.0.
- `docs/operations/sparse_attention/bsa.md`: the JAX section's device row says SM100 or SM103.

`test/python/core/jax/conftest.py`, which gates the other JAX suites to cc 10.0, is unchanged.

## Why

On a B300 the JAX API raised "requires ... an SM100 (compute capability 10.0) GPU" although its kernels serve that part through the torch API.

## Related issues

None found.

## API and compatibility impact

None on cc 10.0, which still compiles for `sm_100a`. On cc 10.3 the JAX calls now run instead of raising `ValueError`.

## Testing

B300 (cc 10.3), develop `64ed3dfe` with its own extension, torch 2.14.1+cu130, CuTe DSL 4.8.1, JAX 0.12.0.1 (`jax[cuda13]`), `XLA_PYTHON_CLIENT_PREALLOCATE=false`, run from `test/python`:

| Command | develop | check widened only | this PR |
|---|---|---|---|
| `python -m pytest block_sparse_attention/jax/test_bsa_jax.py block_sparse_attention/cutedsl/test_BSA_jax_parity.py` | 1 passed, 35 skipped | 2 failed (the parity cases, cubin load), 2 passed, 32 skipped (the JAX conftest still required cc 10.0) | 35 passed, 1 skipped |

The case skipped with this PR needs a process with more than one visible GPU. Not run on cc 10.0.
