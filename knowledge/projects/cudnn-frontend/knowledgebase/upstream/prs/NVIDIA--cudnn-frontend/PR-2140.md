## Affected area

FE OSS kernels or CuTeDSL (SDPA forward default plan order on cc 10.7)

## Summary

`_pack_gqa_points`' one-wave rule for unsplit native D64 (#2118) now applies only to graphs with an attention sink. Graphs without a sink go back to the generic order: the packed set leads, with the split the wave model picks.

## Why

The rule was measured with sinks. With a sink this row cannot split KV, so while the unpacked launch fits one wave, unpacked runs no slower than packed. The condition did not require the sink. Since #2123 gave native D64 packing a split, a graph without a sink packs and splits far faster than the unpacked, unsplit plan the rule put first.

The rule was re-measured on current develop (cuDNN 9.29.0.18) on every lattice cell where it changes develop's first plan, plus the matching cells of the earlier off-lattice holdout:
- **Without a sink**, the rule's plan was the slower one on nearly every cell.
- **With a sink**, it was neutral on the lattice and ahead on off-tile holdout caches.

So it stays for sinks only. The measurements are in the private study record.

## Related issues

Follow-up to #2118; interacts with #2123 / #2127.

## API and compatibility impact

Default plan order only, on cc 10.7 dense half D64 graphs without a sink and without a window whose unpacked launch fits one wave.

## Testing

- `test_rubin_native_d64_packs_past_one_unpacked_wave` now runs with and without a sink. The two no-sink one-wave cases fail on develop and pass here; they also assert that the leading packed plan splits.
