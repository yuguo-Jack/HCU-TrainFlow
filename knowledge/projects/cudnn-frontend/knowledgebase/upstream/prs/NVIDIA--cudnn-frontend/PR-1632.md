# sdpa (frost): host L0 regression test for the native backward binder's list geometry across every arch fixture (complements #1631)

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1632) · state: closed · merged: True

## Original PR description

## What this PR is now

#1631 (merged) fixed the production side of #1633: the native backward binder converts its standalone geometry through nanobind's explicit `tuple(handle)` again (`py::tuple(declared)` / `py::tuple(py::handle(runtime_geometry[i]))` in `python/pygraph/sdpa_bwd_binding.cpp`), so the **list** of `(shape, strides)` pairs the standalone backward adapters build no longer dies in `RuntimeError: std::bad_cast` before the geometry check runs. This PR carried the same two-line change; rebased onto develop, that change is gone and **only the regression test remains**. Complements #1631; closes #1633 (the defect is fixed there, the coverage lands here).

## What remains: one host-only L0 test

`test/python/sdpa/frost/test_sdpa_native_bwd_binding.py::test_backward_native_binder_converts_sequence_geometry`, parametrized over every arch fixture of the file (`sm80`, `sm100`, `sm107`, `sm107_thd`, `sm120`) and entered through the Python `prepared.bind` of the standalone form (`native_binding=True`), i.e. the entry the adapters use:

- a list geometry and list `(shape, strides)` entries bind to the same frame as the tuple form,
- a changed layout is still refused with the plan's `runtime geometry` `ValueError`, a short list with the `geometry count` `ValueError`,
- a non-sequence (`geometry=7`) raises Python's own `TypeError`, not a C++ cast error.

#1631's `test_standalone_geometry_accepts_lists` pins the `sm100` / `sm107` fixtures through `_SdpaBwdBinder.bind` directly; this test adds the other three fixtures (the SM80, THD and SM120 forms), the Python entry point, the count refusal and the non-sequence contract. The two overlap on purpose, and neither dispatches a kernel.
