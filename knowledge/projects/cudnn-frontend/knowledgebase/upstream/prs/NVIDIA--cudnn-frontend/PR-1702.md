# Optimize causal THD forward attention for context parallel workloads

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1702) · state: open · merged: False

## Original PR description

Causal THD forward attention currently leaves all softmax exponent work on MUFU, including interior tiles with no causal-mask work. On SM100, use the existing mixed-exp2 implementation for 32 of each 128 columns on eligible BF16 D128-flavor interior tiles. Masked and diagonal tiles retain the existing MUFU path. This reduces complete context-parallel attention latency in the measured workload.

The extension is limited to nonpaged, unsplit causal THD without a sliding window, under the existing architecture gate. Dense causal, FP16 causal THD, D64, paged and split-KV behavior remain unchanged. There is no new API, knob, capability, allocation or kernel launch.

**Stacked on #1696** (`aae7a712`). That work-lookup commit is unchanged; this PR adds the interior-softmax optimization and its tests. The cumulative diff will shrink when the parent lands.

### Complete context-parallel measurements

B32 / S16384 / Hq32 / Hkv8 / D128, BF16 causal THD, 524,288 tokens, CP4/A2A. Each node uses four 148-SM B200 GPUs at default 1000 W with NV18 links. cuDNN 9.27.0.42, CUDA 13.2, CuTeDSL 4.8 cu13 and FA4 4.0.0b35.dev1+gbb25ba3. Warm eager timing includes forward, backward, helpers and communication through native TE C++, using the slowest rank. The candidate changes only the forward interior softmax; TE binaries, backward and communication are fixed.

| Independent node | Baseline FROST | Interior-exp2 FROST | FA4 | Paired candidate / baseline |
| --- | ---: | ---: | ---: | ---: |
| A | 74.617 ms | 73.342 ms | 70.940 ms | -1.72% |
| B | 74.517 ms | 73.367 ms | 70.716 ms | -1.46% |

Each node has four balanced orders, 16 fresh four-rank process sets, 256 complete output/gradient checks and 48 telemetry/stability windows. Each process set uses three blocks of five warmups and 50 timed iterations. Candidate latency is lower in 4/4 paired orders on each node; the incremental saving is 1.46–1.72%. The optimized path still takes 3.34–3.78% longer than FA4. Percentages are medians of within-order paired ratios; nodes are not pooled.

These performance measurements retain their frozen experimental-package attribution. The public patch keeps the measured nonpaged kernel body, normalizes its static gate to bool and explicitly excludes paged inference. Exact public-package GPU qualification is reported below; complete-CP performance of the published package has not been remeasured, and no original benchmark-grid win rate is claimed.

### Validation

- Exact candidate on B200: **22 numerical / changed-input replay cases** and **one explicit unsupported-cga1 rejection case**, with zero skips. Independent CPU FP64 checks cover O and Stats, both causal alignments, MHA/GQA, token/head-major packed Stats, scaled inputs, zero-length replay and untouched output capacity.
- Six numerical cases additionally cover served D128-flavor widths `(72,72)`, `(120,120)`, `(96,80)`, `(80,96)`, `(128,64)` and `(64,128)`. These use the public unpacked-GQA contract and separate V/O element offsets; no capability is expanded.
- **memcheck, racecheck and synccheck** each pass both an exact-D128 packed case and a 96/80 unpacked case, with zero reported errors or hazards.
- **49 host gate checks** and **14 CPU template lowerings** cover architecture, dtype, cluster, head-flavor and paged controls. Other-architecture compilation is not GPU execution, and raw-template compilation is not public-graph admission.
- Default L0 collection selects one case; the rest are L1. Changed-file pre-commit checks pass. The existing native binding is reused with 108 C++/header inputs verified unchanged; this is a Python kernel/test change.
