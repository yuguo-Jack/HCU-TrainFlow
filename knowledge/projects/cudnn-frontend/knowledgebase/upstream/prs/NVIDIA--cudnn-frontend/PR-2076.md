# Reduce SM100 D64 final-output load and store overhead

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2076) · state: closed · merged: True

## Original PR description

## Summary

Dense BF16 D64 CTA1 attention uses the same 16-column fragment for final output as for online O rescaling. That limit avoids register spills in the rescale loop, but makes final normalization issue extra TMEM loads and shared-memory stores. Keep rescaling at 16 columns and use 32 columns for final output for unsplit non-THD plans, including paged KV with dense Q. The timings below cover nonpaged inputs.

## Why

On three existing GPT-OSS-shaped SM100 DEV cases, packed CUDA-event graph replay improves **0.53–1.02%**. Unpacked changes range from **0.14% faster to 0.21% slower**. For the 8K case, the fastest native plan moves from about **272.6–272.7 us to 271.1–271.2 us**, versus the retained strongest backend control at **267.9 us**. Measurements used a 68-SM SM100 GPU, BF16 D64, Torch CUDA 13.0, DSL compiler CUDA 13.4, cuDNN 9.28, and CuTe DSL 4.8, with alternating timing order and reversed process order. These are kernel-replay measurements, not serving throughput.

## Affected area

FE OSS kernels / CuTeDSL — SM100 SDPA forward.

## Related issues

No issue is closed by this performance follow-up.

## API and compatibility impact

The patch changes no public capabilities, workspace contract, or heuristics. The condition also applies to paged KV with dense Q; the review bot exercised that route and its empty-KV replay explicitly. CTA2, FP16, split-KV, THD, and other head widths retain their previous fragment size.


## Testing

- 24 existing D64 tests pass, including both CTA widths and packing modes, causal and bottom-right masks, sinks, tails, forced online rescaling, pointer rebinding, and changed-input CUDA Graph replay.
- 420 complete FP64 O/Stats observations pass across native and backend controls. All 360 native observations are bitwise identical to their matching unchanged controls; these are observation counts, not unique shapes.
- Explicit BF16 cross-compilation confirms wider final loads while retaining the 16-column rescale stores. The FP16 exclusion control produces the unchanged cubin. The formatted production module is AST-identical to the measured candidate.
- Changed-file format and license checks pass.

Qualification harness commands were `python functional.py`, `python probe.py forward`, and `python probe.py reverse`. The functional harness injects the candidate template and invokes `pytest.main(['-q', '-x', '-m', 'L0', '-p', 'no:cacheprovider', 'sdpa/frost/test_sdpa_frost_d64_causal_softmax.py'])`; import/source hashes and compiled-route receipts were checked. Formatting used `pre-commit run --files python/cudnn/sdpa/fwd/kernels/sm100/prefill_d128_f16.py`.
