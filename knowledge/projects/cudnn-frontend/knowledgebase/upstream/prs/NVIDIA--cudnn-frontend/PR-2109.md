## Affected area

FE OSS kernels or CuTeDSL

## Summary

`cudnn.triangle_multiplicative_update` serves cc 10.3 with the sm100 body of the LayerNorm-prologue dual GEMM (`ln_prologue.ARCHS_BY_CC[(10, 3)] = "sm100"`). That body pins `frost_compile_options = "--enable-tvm-ffi --gpu-arch sm_100a"`, and an `sm_100a` cubin does not load on cc 10.3. On a B300, every K1 / K3 launch failed with `DSLRuntimeError: ... TVM FFI function is not initialized. Was this function compiled for a different ...`.

Changes:

- `gemm/frost/ln_prologue/__init__.py`:
  - `TARGETS_BY_CC` (`sm_100a` / `sm_103a` / `sm_107a`) and `target_for_cc(cc)`, which gives the same typed decline as `body_arch_for_cc` off a served part.
  - `build_ln_dual_gemm(params, arch, target=None)`: `None` keeps the body's home target (`HOME_TARGETS`) and the loader key every caller has had. Any other target loads its own template module (`load_template(..., extra_key=("gpu_arch", target))`), so the two parts never share a module, its `compile()` cache or a compiled artifact. That module then compiles for the target. A target the body cannot serve raises `ValueError`.
- `triangle_multiplicative_update`: the API passes `target_for_cc(cc)` to `build_trimul_proj` / `build_trimul_tail`, and its per-device plan cache (`_substrate_plan_on`) keys on the target as well.
- Tests:
  - The three suites that build the substrate directly pass the device's target through a `_target()` helper next to `_arch()`.
  - `test_each_served_part_compiles_the_body_for_its_own_target` patches the loader and pins the module key and compile options per target.
  - The SASS probes keep compiling the home body's `sm_100a` text, which is what they inspect.

## Why

The triangle multiplicative update advertises SM103 (`docs/operations/matmul/triangle_multiplicative_update.md`) but could not launch there.

## Related issues

None found.

## API and compatibility impact

None on cc 10.0 or cc 10.7: same target, same module key, same compiled artifacts. On cc 10.3 the API now runs. `build_ln_dual_gemm` / `build_trimul_proj` / `build_trimul_tail` gain an optional trailing `target`.
