# test(core): bar the FROST SDPA forward engines in the native SDPA lowering test

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2233) · state: open · merged: False

## Original PR description

## Problem

`test/python/core/graph/test_native_backend_lowering.py::test_native_sdpa_fwd_lowers_to_backend` builds a causal f16 SDPA graph and asserts that it ran on the cuDNN backend plan (`_assert_ran_on_backend`). The FROST SDPA forward prefill engines are default candidates: `sdpa_fwd_prefill_sm80`, `_sm90`, `_sm100`, `_sm107` and `_sm120` carry no `opt_in` in `engines/manifest.py`. Where the heuristics rank one of them first, it claims the graph and the test fails:

```
assert FrostSdpaFwdEngine(name='sdpa_fwd_prefill_sm120', engine_id=20505) is None
```

| GPU | develop |
|---|---|
| RTX 5060 Ti (cc 12.0) | fails |
| B300 (cc 10.3) | fails |
| A100 (cc 8.0) | passes (the backend ranks first) |
| GH200 (cc 9.0) | passes (the backend ranks first) |

## Change

#2115 made the same change for the norm tests in this file (`_bar_frost_norm`). This PR does the same for SDPA:
- `_bar_frost_sdpa_fwd(g)` bars the `frost_sdpa_fwd` family by name;
- the test builds through it.

The test keeps covering the generic lowering to the backend, which is what it is for. FROST SDPA keeps its own suites under `test/python/sdpa/frost`. The benchmarks already bar FROST SDPA the same way on their backend legs (`benchmark_single_sdpa.py`, `benchmark_single_attention.py`).

## Testing

`test/python/core/graph/test_native_backend_lowering.py`, develop `a0f7b9f4`, cuDNN 9.27:
