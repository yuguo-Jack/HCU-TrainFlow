# sdpa: widen 32-bit offset math for >2^31-element operands; add >4 GiB span tests

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2060) · state: closed · merged: True

## Original PR description

## Summary
SDPA kernels that form element/byte offsets in 32 bits silently read or write the wrong rows once an operand's reachable span crosses 2^31 elements / 4 GiB (e.g. a gapped dO with a large batch stride; the backend side is the cause of pytorch/pytorch#202035 and is fixed separately in the cuDNN backend). This PR audits the OSS kernels for the same class of bug, fixes the real hits, and adds regression tests.

## Fixes
- **SM120 bwd compact path**: `dq_accum`, dQ store and dK/dV workspace addressing now widen `batch` with `wide_index(...)` before the multiply (`sm120/bprop_chain_f16.py`, `sm120/bprop_f16.py`). Verified by lowering to sm_120a PTX: at 2^31 elements the original has `mul.wide.s32` address math in `convert_dq` and the main kernel; after the fix `convert_dq` has none and the main kernel has 2 (small stats/semaphore indices).
- **QAT Triton bwd** (`bwd/qat/_kernels.py`, `_nvfp4.py`): `batch_head` is cast to `tl.int64` before multiplying by strides. On H100 the preprocess kernel hit an illegal address at BH=1024, S=65536, D=64 before and is correct after.
- **Declines instead of wrong answers**: flex varlen rejects q/k/v/output spans > 2^31-1 elements; BSA Sage-FP8 rejects a Q batch stride >= 2^31 (Int32 TMA stride).
- Audited, no change needed: SM120/SM80 fwd (strides are already Int64 in the prepared hosts / explicit `cutlass.Int64`), SM100 frost bwd chain, QSA, DSA bwd, BSA non-exact KV.

## Tests
- `test/python/sdpa/graph/test_sdpa_large_span_strides.py` (L1): fwd + bwd with each operand (q, k, v, o, dO, dq, dk, dv) as a gapped view whose second batch/head starts exactly 4 GiB in; per-batch and per-head rel-L2 vs an fp64 reference. Skips if free GPU memory is insufficient. On a backend without the fix it fails for O/dO (batch and head) and dQ (head gap); it should pass once the backend fix ships.
- `test/python/sdpa/test_sdpa_large_span_host_only.py` (L0): SM120 bwd lowering (MHA, GQA), QAT PTX check, flex and BSA declines. 5 of 6 fail on the pre-fix tree, all 6 pass with it.

## Not verified
- No SM120/SM100 hardware run (SM120 bwd, BSA Sage guard, nvfp4 QAT checked by lowering / host checks only); only the QAT preprocess kernel and the new L1 test were run on H100.
- The L1 test was run against an unpatched backend, where it fails as described above.
- BSA/flex/DSA `seqlen_info` Int32 offsets are guarded (flex) rather than widened.
- The SM120 d512 fwd variants were not lowered.
