## Summary

Closes #1415 with documentation instead of a kernel change.

- `Amax_S` was documented as "the absolute maximum of S tensor". In this section $S = \text{softmax}(P)$, so the value is the maximum of the softmax probabilities, at most 1. With no `sink_token` and at least one unmasked key per row, every row sums to 1 and the value is also at least $1/S_{kv}$.
- Without dropout, `scale_s = 448.f` (an amax of 1) therefore never saturates S; with dropout probability p, `448(1-p)` is a conservative choice because the graph scales kept entries by $1/(1-p)$ before `scale_s`. Computing `Amax_S` buys little. #602 removed it from the FROST kernels because nothing consumed it and it cost every FP8 execute a zero-fill plus per-row atomics.
- The docs now say three things:
  - the output is optional; leave it virtual if you do not consume it;
  - FROST declines graphs that declare it, so they run only if a backend engine supports them (otherwise no supported plan, e.g. the #1415 decode cases);
  - on SM100 the backend currently under-reports it at short `s_q` (#1613).
- #1415 proposed producing `Amax_S` in the FROST FP8 kernels. A cheaper alternative, writing the bound 1.0, was also considered. Both were dropped: the backend reports the actual maximum, which can be far below 1, so 1.0 would not match it.

## Testing

Documentation only; no code changes. The backend behaviour described was measured on cuDNN 9.27.0.42 (frontend 1.32.0) with e4m3 Q/K/V:

| Case | Result |
|---|---|
| H100 | `Amax_S` matches `max(softmax(QK^T * attn_scale))` (0.242931 vs 0.243272), independent of `scale_s` |
| H100, small logits, s_kv 4096 | 3.25e-4 |
| Causal | 1 on H100 and B200 |
| B200, short `s_q` | ~0.78x of the true maximum, filed as #1613 |
