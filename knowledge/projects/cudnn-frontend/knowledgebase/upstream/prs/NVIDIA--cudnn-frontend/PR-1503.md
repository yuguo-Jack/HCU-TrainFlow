# SDPA: consider additional split waves for short paged queries on SM107

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1503) · state: closed · merged: True

## Original PR description

Paged D128 prefill on SM107 currently leaves split selection at one when no partitioned grid fits its first-wave budget. For small batches with short queries and long KV prefixes, allow the existing split kernels to be considered across up to three waves.

Preserve every existing first-wave choice. Only when none is available, B1–4 with declared Q64–128 and KV8K–32K reuses the existing physical packed/unpacked grid scorer. Q128 is one unpacked query tile; packing may produce more tiles, which the scorer accounts for. Existing BF16, D128, HND, page-size, mask, head-count and native-binder gates remain in place. Blackwell selection is unchanged.

This changes plan-time selection only. It adds no kernel, public knob, execute-time preparation or device-to-host length read. Changing the selected provider is not a promise of identical host submission cost. No timing or preferred-split golden test is added.

Based on develop `e15aac24b`. Its shape-override gate is unchanged: bounded paged callers need #1469, and #1476 separately refines the declared packed-query capacity used by the SM107 policy. Those changes were also tested as an integration stack and are not included in this diff. Disabling shape overrides in the fixed-graph checks does not disable FlashInfer's declaration buckets; selection always uses declared capacities.

Validation with cuDNN 9.27 and CuTe DSL 4.8:

- Existing geometry, heuristics and prepared-binding suites: **1,035 passed** on this develop-based change; **1,072 passed** on the dependency stack (2 deselected in each).
- Existing paged D128 BF16 capture suite: **44 passed**, including packed NH/HN Stats and changed sequence lengths.
- Public FlashInfer wrapper entry points: independent FP64 O/LSE checks and poisoned-output replay after modifying V across fixed and bounded declarations, uniform/mixed lengths and MHA/GQA cases. The local integration fixture adds only SM107 to FI's architecture admission; it neither forces a FE engine nor changes the wrapper contract, and is not a public FI admission change.
- **12 workspace lifecycle cases**, NH/HN Stats: 128 → 1 → 8 → 128 MiB, workspace-constrained reselection, reuse of the original graph, replay of all retained captures, and a tripwire against preparing another plan during warm run/capture.
- File-scoped formatting/hooks passed. Performance evidence remains internal; no full-model serving claim is made here.
