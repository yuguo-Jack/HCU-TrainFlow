# sdpa: enable native SM107 FP8 D192 PackGQA

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1934) · state: closed · merged: True

## Original PR description

Native SM107 D192x128 FP8 kernels already contain whole-group GQA packing, but the graph capability row rejects it and the adapter separately rejects packed split-KV. Admit exact D192x128 packing and make the graph row and packed-split adapter guard read one shared PackGQA shape set. Existing native body, split partials and final sink normalization stay in place.

D64/D128 behavior is preserved. D256/D512 packing, non-native head padding, THD and paged restrictions remain independently gated. Heuristic and placement source files are unchanged; expanding legal plans can affect candidate generation and selection, which remains with the heuristics owner.

Enable the existing D192 GQA2/4/8, grouped-LPT and E5M2 sink tests on SM107. Add exact-shape multi-batch tests across both FP8 inputs, BF16/FP8 output and all schedulers, including sink/split composition, rebound buffers and retained capture replay. Exercise the existing sink/split suite with D192 packing and pin the independent padded-head decline.

Target qualification on SM107 passes 58 new/updated feature tests and six existing controls; three targeted Compute Sanitizer memcheck cases report zero errors. Default FROST collection includes the suite. The original graph rejection and the separate adapter rejection were reproduced before the fix. A bounded six-case, 108-plan packed/unpacked replay study also passes O/Stats/Amax before and after capture replay; performance details remain internal.

Depends on #1931 for native FP8 sink/split composition. This PR adds the D192 packing domain and its coverage on top of that change.
