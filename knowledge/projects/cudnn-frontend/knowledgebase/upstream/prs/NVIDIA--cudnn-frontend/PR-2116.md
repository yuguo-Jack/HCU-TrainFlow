## Summary

- `python -m benchmark.heuristics_regret <run> --baseline <earlier run>` adds a run-to-run section. It compares each case's `cudnn_auto` time with the same case in the earlier run, matched on the configuration columns both runs record. Cases slower than `--regress` (default 1.2x) are split into two tables: the default plan changed (a dispatch change), or the plan stayed the same (a kernel, backend or measurement change). Cases whose default stopped running are listed separately. With `--fail`, a slower new default plan or a lost default exits 1.
- A results file with two rows of one leg for one case (the linear-attention CSVs) is skipped with a warning instead of aborting the report. A whole nightly run directory can now be passed.
- Inference result rows gain `attn_mask` (`top_left` / `bottom_right` / `no_mask`, the training suite's vocabulary) and `has_sink`. The alignment comes from one helper, `config_types.attn_mask`, which `benchmark_single_attention` also uses to build the graph, so the column cannot drift from the graph.

## Why

- **The regression report.** The nightly records the default-dispatch time on every case (#1848), but nothing compares it across runs, so a default plan that changes and slows down between two nightlies is only found by reading the raw results. The report lists such cases first, under "new default plan", apart from same-plan drift. The dispatch fix for the change that prompted this is a separate PR.
- **The columns.** The inference CSV did not say how a causal case was aligned or whether it carried a sink, so offline replays of the default dispatch had to reconstruct both from the config files. The suite builds `s_q == s_kv` context graphs top-left and chunks bottom-right. Placement keyed those as different classes, which is how a generated placement entry missed square prefills (fixed separately). That is invisible in the data today.

## Related issues

Follows #1848.

## API and compatibility impact

None outside `benchmark/`. CSV rows gain two trailing columns. `--baseline` pairs a case with rows whose column set contains, or is contained in, its own (so a run that added a column still pairs with its predecessor) and drops a case with more than one counterpart; training and inference CSVs never pair with each other.

## Testing

- `pytest benchmark/attention_inference/tests/`: 16 passed. New tests cover the baseline split (new plan / same plan / lost default, with a column the baseline predates), mixed training + inference directories where only one schema gained a column, skipping a duplicate-leg file, and the `attn_mask` vocabulary. Each fails on develop or on this PR's first head.
- `benchmark_single_attention.py --backend cudnn --phase context --causal` run as a script on an H100: builds and times as before.
- `python -m benchmark.heuristics_regret <run> --baseline <earlier run>` on two nightly result directories (the run pair described above).
