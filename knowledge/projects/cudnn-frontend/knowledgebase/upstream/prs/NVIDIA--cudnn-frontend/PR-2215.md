# test(causal_conv1d): skip an NWH case the backend declines for shared memory

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2215) · state: open · merged: False

## Original PR description

## Problem

`test_causal_conv1d_nwh_autograd[fp64-k4-silu]` and `[fp64-k4-identity]` fail on devices with about 99 KB of shared memory per block. cuDNN 9.27 declines the FP64 NWH forward there with status 3010 (`CUDNN_STATUS_NOT_SUPPORTED_SHARED_MEMORY_INSUFFICIENT`), which the binding raises as `RuntimeError: cudnnCausalConv1dNwhForward failed with status 3010`. The other dtypes in the same test run normally.

| device | develop 97b7bc31 |
|---|---|
| RTX 5060 Ti (cc 12.0) | 2 failed, 37 passed |
| L40S (cc 8.9) | 2 failed, 37 passed |

## Change

`test_causal_conv1d_nwh_autograd` skips when the NWH call fails with status 3010 and quotes the backend's message in the skip reason. Any other error still fails the test. Nothing outside this test changes.

## Tests

On an RTX 5060 Ti (cc 12.0) with cuDNN 9.27, `test/python/causal_conv1d/torch/test_causal_conv1d.py` gives 37 passed, 2 skipped with this change (develop: 2 failed, 37 passed). The skip reason reads `cuDNN reports insufficient shared memory for this NWH case on this device: cudnnCausalConv1dNwhForward failed with status 3010`. `pre-commit` passes.
