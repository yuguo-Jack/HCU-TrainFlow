# 767: Ship the SDPA repro tool as `python -m cudnn.repro`

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/767) · state: open · merged: False

## Original PR description

Moves `tools/cudnn_repro` into the `cudnn` package so the SDPA reproducer is
available as `python -m cudnn.repro` (and the `cudnn-repro` console script)
without a second `pip install`.

## Why

The tool is pure stdlib with zero dependencies, yet shipped as its own
distribution requiring `pip install -e tools/cudnn_repro`. It now sits next to
`collect_env.py`, the other `python -m cudnn.<tool>` utility. The root
`packages.find` glob (`cudnn*`) picks the subpackage up, so no packaging change
was needed beyond deleting the old `pyproject.toml` and moving the console
script entry to the root `[project.scripts]`.

## What changed

- `tools/cudnn_repro/cudnn_repro/` → `python/cudnn/repro/` (pure move, all
  imports were already relative)
- `tools/cudnn_repro/tests/` → `test/python/repro/`
- New optional `output` positional:

  ```bash
  python -m cudnn.repro sdpa.log            # stdout, as before
  python -m cudnn.repro sdpa.log repro.sh   # write to a file instead
  python -m cudnn.repro --all sdpa.log out  # all commands, blank-line separated
  ```

- Tests now run in CI for the first time — under `tools/` they were not wired
  into any pipeline. Marked `L0` for the pure-Python unit tests, `L1` for the
  closed-loop ones that spawn real GPU SDPA runs and replay them.

## Caveat

`python -m cudnn.repro` imports the parent `cudnn` package, which loads
`_compiled_module`. Triaging a log now needs the wheel installed; before, the
tool ran on any bare Python.

## Testing

- `pytest test/python/repro/` — 45 passed
- `pytest test/python --collect-only` — 53978 collected, no regressions
- All three CLI modes (stdout / output file / `--all` + output file) and the
  `cudnn-repro` console script verified by hand
- L1 closed-loop: `test_sdpa_random_fwd_L0[test1]` passes.
  `test_sdpa_random_bwd_L0[test1]` fails on a payload mismatch — **pre-existing**,
  reproduced on unmodified `develop` via a worktree, not introduced here.
