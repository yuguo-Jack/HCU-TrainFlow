# frost: report no CuTe DSL target below SM80 instead of a KeyError

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2221) · state: open · merged: False

## Original PR description

## Problem

The CuTe DSL's `Arch` enum starts at `sm_80`. On a Turing part (cc 7.5: T4, RTX 20xx), compiling any DSL kernel dies inside the DSL:

```
.../cutlass/base_dsl/enums.py:110: KeyError: 'sm_75'
```

`cudnn.frost.buffers.cutedsl_arch_requirement_error(device_cc)` is the target half of `cudnn.frost.cutedsl_runtime_available`, and the gate callers consult before compiling. It only checked cc 10.7, so on cc 7.5 it reported no problem.

As a result, callers that already have a torch fallback for "the DSL cannot target this GPU" took the DSL path anyway and crashed instead of falling back:
- `cudnn.sdpa.packed_lse`
- `cudnn.sdpa.varlen_metadata`

## Change

`cutedsl_arch_requirement_error` now refuses a part below cc 8.0 by name, without importing the DSL. This has two effects:
- `cutedsl_runtime_available(cc)` now reads False on cc < 8.0. This is the correct answer, but it is a behavior change for consumers of the probe, such as FlashInfer.
- The two fallbacks above now take their torch path.

Nothing changes on cc 8.0 and newer. The cc 10.7 check is unchanged.

Other edits:
- `test_flashinfer_consumed_surface.py`: the arch-aware probe test now covers cc 7.5. A new host-only test checks cc 7.5 / 7.0 / 6.1: the message names the part, the DSL is never asked, the probe reads False, and cc 8.0 still passes.
- The rule is also stated in `python/cudnn/AGENTS.md` and `docs/utilities/python_graph_and_execution_backends.md`.

## Testing

RTX 2060 (sm_75), cuDNN 9.27, CuTe DSL 4.8.1, develop e77fe6d4:

| | failed | passed | skipped |
|---|---|---|---|
| `test_packed_lse`, `test_varlen_metadata`, `test_flashinfer_consumed_surface`, base | 26 | 41 | 16 |
| same files, this PR | 0 | 41 | 45 |

No change on cc 8.0 and newer. A100 (sm_80) runs the same three files plus `triangle_attention/cutedsl/test_api.py` and `test/python/QSA`: base 115 passed / 281 skipped, this PR 118 passed / 281 skipped. The 3 extra passes are the new cc 7.5 / 7.0 / 6.1 cases.

`black 26.3.1 --line-length 160 --fast` is clean.

## Out of scope

Some direct-compile suites call `cute.compile` without consulting this gate:
- the `gated_attention_block` kernel tests;
- the FROST GEMM per-K tests.

They still fail on cc 7.5 with the same `KeyError`.

The triangle-attention prefix-length tests do consult the gate. They now fail with a typed `NotImplementedError` naming the missing target instead of a `KeyError`, with the same failure count.

Adding skips to those suites is separate work.
