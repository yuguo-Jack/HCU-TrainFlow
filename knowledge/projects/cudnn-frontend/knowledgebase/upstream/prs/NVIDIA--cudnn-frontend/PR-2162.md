## Affected area

CI or test infrastructure: FP8 and MXFP8 SDPA backward harnesses.

## Summary

The backward harnesses currently use the QKV dtype for dO, so the E4M3-QKV/E5M2-dO training mix cannot be expressed. Append optional `ExecConfig.dO_type` (`None` follows QKV), serialize it in repros, and use it for dO storage, graph declarations, and per-tensor descale or both MXFP8 scale-factor orientations.

Draw E5M2/E4M3 dO at 2:1 in the generic and model backward suites and the three legacy backward sweeps. Keep their existing QKV domains. Regenerate the coverage table and add 57 host contract/reference cases covering repro compatibility, graph declarations, draw domains, and actual host quantization/binding preparation intercepted before kernel execution.

## Why

Cover mixed-format backward inputs with the backend's independent intermediate formats: per-tensor P follows QKV, while dS follows dO. Append optional `torch_ds_type` to the backward reference and use dO's format for dQ/dK rounding attribution; dV keeps QKV/P attribution. Omission preserves existing reference callers. The MXFP8 reference policy, existing scale pairs, numerical tolerances and support-check skip behavior are retained. This corrects the P2 identified in [native review](https://github.com/NVIDIA/cudnn-frontend/pull/2162#pullrequestreview-5728574565).

## Related issues

Related to #955. Claimed in https://github.com/NVIDIA/cudnn-frontend/issues/955#issuecomment-6558586567.

## API and compatibility impact

No library API or kernel changes. Test-only fields/arguments, including `torch_ds_type`, are appended with defaults. Old repro dictionaries and omitted dO format retain the QKV format. Sweeps with the new random axis generate new configs; a printed repro records the chosen dtype.

The script below was saved as `/tmp/cudnn-issue-955/run_host_tests.py`. It is deliberately outside the package and does not change the repository test environment.

```python
"""Run host-only harness contracts on macOS with a cuDNN enum/import shim.

No backend, CUDA graph, or GPU numerical validation is performed.
"""
import enum
import sys
import types
from pathlib import Path

root = Path(sys.argv[1]).resolve()
sys.path.insert(0, str(root / 'test/python'))
shim = types.ModuleType('cudnn')
for name, members in {
    'data_type': 'NOT_SET HALF BFLOAT16 FLOAT DOUBLE INT8 INT32 INT64 BOOLEAN FP8_E4M3 FP8_E5M2 FP8_E8M0 FP4_E2M1',
    'diagonal_alignment': 'TOP_LEFT BOTTOM_RIGHT',
    'attention_implementation': 'AUTO COMPOSITE UNIFIED',
    'heur_mode': 'A B FALLBACK',
    'tensor_reordering': 'NONE F8_128x4',
    'knob_type': 'TILE_CGA_M PACK_GQA SPLIT_KV',
}.items():
    cls = enum.Enum(name, members, module='cudnn')
    setattr(shim, name, cls)
shim.pygraph = None
shim.set_stream = None
shim.backend_version_string = None
shim.cudnnGraphNotSupportedError = type('cudnnGraphNotSupportedError', (Exception,), {})
sys.modules['cudnn'] = shim
if '--coverage' in sys.argv:
    from sdpa.graph.suites.gen_coverage import main
    main()
    raise SystemExit(0)
import pytest
raise SystemExit(pytest.main(['-q', '--noconftest', '-c', '/dev/null', '-o', 'markers=L0: smoke', str(root / 'test/python/sdpa/test_fp8_do_dtype.py'), *sys.argv[2:]]))
```

```sh

Plan-probe errors remain recorded as unavailable instead of discarding tensor evidence. Atomic writes prevent a partial bundle from suppressing a later capture; save, cleanup and stderr failures preserve the original pytest failure.
