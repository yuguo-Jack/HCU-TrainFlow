# Add documented FE-OSS modules to the API index

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1528) · state: closed · merged: True

## Original PR description

Twelve modules documented under `docs/fe-oss-apis` were missing from `api_index_modules.txt`. Their top-level `cudnn.*` re-exports are lazy imports outside `cudnn.__all__`, so none of their APIs were tracked. This lists them and regenerates the baseline (+504 names):

| Module | Names |
| --- | --- |
| `cudnn.gemm.cutedsl.dense.{amax, dsrelu, srelu, swiglu}` | 7 each |
| `cudnn.gemm.cutedsl.dense.proj_rope_mxfp8` | 12 |
| `cudnn.conv.cutedsl` | 33 |
| `cudnn.moe_ep` | 307 |
| `cudnn.gated_attention_block` | 82 |
| `cudnn.rope` | 19 |
| `cudnn.engram` | 14 |
| `cudnn.gemm.mhc_projection_bwd` | 7 |
| `cudnn.sdpa.fwd.torch_op` | 2 |

`sdpa/fwd/torch_op.py` had no `__all__`. It now exports `sdpa`, the function behind the documented `cudnn.sdpa_torch`.

Not included: internals that FlashInfer imports directly (`cudnn.datatypes`, `cudnn.frost.buffers`, `cudnn.gemm.frost.*`). Indexing them would make them public, so that is left to the API pruning plan.

Testing: the baseline was generated with `api_index.py --write` against a package built from this branch's Python. The compiled module came from a current-`develop` build, because the shared backend build lacks the new GNN headers. That module has no optional `gnn_agg_*` symbols, so the 9 `gnn_agg_*` names already in the baseline were kept as-is. Every other existing name reproduced exactly. With that module, `test_api_index.py` passes 8 of 9; the one failure is those 9 names. All 12 modules import cleanly with `CUDA_VISIBLE_DEVICES=''`; the venv has no `nvshmem4py`, and `moe_ep` imports it lazily.
