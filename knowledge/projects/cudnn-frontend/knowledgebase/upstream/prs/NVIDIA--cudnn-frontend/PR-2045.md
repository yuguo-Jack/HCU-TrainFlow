## Affected area

Python API or bindings

## Summary

Register one package-level interpreter-exit cleanup for the module-level forward, backward, and summary graph caches owned by the GDN, GDN2, GDP, KDA, and Mamba2 operation wrappers.

No public API or kernel behavior changes. No nanobind-specific test is added; this is lifecycle cleanup for the Python-owned caches.

## Why

A development build can report nanobind reference-leak diagnostics at interpreter shutdown even though execution succeeds and exits with status 0. The module-level caches can retain cached pygraphs, including bound `DeclaredLayout`, `WorkspaceCarve`, and `_OrderedBindingSchema` objects, until after nanobind begins tearing down its registered types.

Clearing all Linear Attention graph caches through one `atexit` callback gives those Python-owned objects a deterministic lifetime and releases them before extension teardown. cuDNN Frontend already uses `atexit` for process-lifetime backend handles; this applies the same ownership principle to graph caches.

## Related issues

None.

## API and compatibility impact

None. Cache contents remain process-lifetime during normal execution and are cleared only while the interpreter is exiting.

## Testing

- `pre-commit run --files python/cudnn/linear_attention/ops/__init__.py`: passed.
- `python3 -m py_compile python/cudnn/linear_attention/ops/__init__.py`: passed.
- Isolated execution of the current `ops/__init__.py`: passed; exactly one exit callback cleared all 15 forward, backward, and summary caches across the five operation modules.
- Before the fix, a real KDA forward subprocess on an SM100 GPU with CUDA 13 emitted three leaked-instance diagnostics (`DeclaredLayout`, `WorkspaceCarve`, and `_OrderedBindingSchema`) at process exit.
- With the final centralized cleanup, the same real KDA forward completed and the subprocess exited without any `nanobind: leaked` diagnostic.
- Actual module caches: all 15 caches cleared successfully and a second cleanup call was idempotent.
- `CUDA_VISIBLE_DEVICES=0 python3 -m pytest -q linear_attention/frost/test_kda_execution.py`: 54 passed in 232.34 seconds on SM100, CUDA 13, cuDNN 9.24, and CuTe DSL 4.8.1.
