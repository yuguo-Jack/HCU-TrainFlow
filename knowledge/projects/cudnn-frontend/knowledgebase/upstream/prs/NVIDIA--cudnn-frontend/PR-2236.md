# dsa: decline cc 12.x in the IndexerForward and SparseAttentionBackward gates, and skip the tests there

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2236) · state: closed · merged: True

## Original PR description

Follow-up to #2170, which made the indexer backward and score recompute gates decline cc 12.x.

## Problem

RTX 5060 Ti (cc 12.0), develop `a0f7b9f4`, `-m L0 test/python/deepseek_sparse_attention`: 147 failed.

| failure | count | cause |
|---|---|---|
| `TypeError: 'bool' object is not callable` (`sparse_attention_backward/_interface_sm100.py:704`) | 22 | `SparseAttentionBackward.check_support()` declines only `major < 9`. On cc 12.x it passes, then `compile()` stores the SM90 placeholder `_compiled_kernel = True`, then `execute()` dispatches to the SM100 launch, which calls it. |
| `Unsupported GPU compute capability (12, 0) for DSA CuTe kernels. Add it to ..._ARCH_MAP` | 81+ | `IndexerForward.check_support()` declines only `major < 10`, so the failure surfaces at compile time with a message that asks the user to edit the package. |
| the gates' own `RuntimeError` (score recompute, dense indexer backward) | ~40 | The APIs decline correctly, but the tests' skips use bare thresholds (`capability[0] < 9`, `major * 10 + minor < 100`, ...), so cc 12.x reaches the gate. |

## Change

API:
- `SparseAttentionBackward.check_support()` now accepts SM90 and the SM100-family capabilities in `_SM100_FAMILY_ARCH_FLAGS`, the only targets with a backward kernel. This is the same shape as `DenseIndexerBackward`'s gate. cc 11.x is declined too: `_sm100_gpu_arch_flag()` has no entry for it, so it never compiled there.
- `IndexerForward.check_support()` now uses `has_tcgen05`, like the score recompute gate.

Tests:
- The SM90 / SM100 skips in `test/python/deepseek_sparse_attention` go through `has_tcgen05`: 26 sites in 8 files, plus `dsa_utils.py`'s `min_compute_capability >= 100` floor.
  - `< 10` and `< 100` become `not has_tcgen05(major)`.
  - `< 9` and `< 90` become `major != 9 and not has_tcgen05(major)`.
- `indexer_top_k` is left alone, because `IndexerTopK` serves cc 12.x.
- On cc 8.x, 9.x and 10.x every changed condition gives the same answer as before.

## Testing

RTX 5060 Ti (cc 12.0), cuDNN 9.27, CuTe DSL 4.8.1, `-m L0 test/python/deepseek_sparse_attention`:
- develop: 147 failed, 353 passed.
- this PR: 0 failed, 344 passed, 517 skipped.

`black 26.3.1 --line-length 160 --fast` is clean.

I could not run this on an SM90 or SM100 part right now. The API change keeps the same accepted set there: SM90 plus (10, 0), (10, 3) and (10, 7).

## Not in this PR

The mxfp8 wrapper paths (`test_DSA_indexer_forward_wrapper_mxfp8_matches_dequant_reference`, `test_DSA_dense_score_recompute_wrapper_mxfp8_matches_dequant_reference`) reach `compile_options()` without going through the class gate, so on cc 12.x they still raise the `_ARCH_MAP` message. The tests now skip there.
