## Affected area

SDPA FROST forward, THD (packed) native binder

## Summary

Fixes #1482.

A single-request (`b == 1`) THD graph can declare head-major Stats `(1, H_q, S_q, 1)` over a `[H_q, t_q]` buffer, with `S_q` below the packed-Q capacity `t_q`. Such a graph passed `check_support` and `build_plans`. Then the first `execute` raised `ValueError: cudnn.sdpa: head-major lse_tensor logical shape must cover bounded packed Q`, and at that point the plan walk has no fallback (Rule 2).

The native THD binder (`python/pygraph/sdpa_thd_binding.cpp`) checked the declaration's logical rows against the packed-Q capacity. The kernel writes at most `b * S_q` live rows (`seq_len_q <= S_q`). So the logical bound is now `min(capacity, b * S_q)`; this is option 2 in the issue. The storage checks are unchanged: the observed span must still hold `H_q * head_stride`.

- The Python binding oracle (`test/python/sdpa/frost/sdpa_binding_reference.py`) applies the same bound.
- The cc 10.7 detector `test_sdpa_paged_thd_sink_head_major_batch_one_cc107_L0` changes from strict xfail to a must-serve cell.
  - It has an SM100 twin, `test_sdpa_thd_head_major_batch_one_frost_L0[paged|nonpaged x sink|no_sink]`.
  - `_p2_cfg` gains a trailing `paged=True` kwarg so the twin can build the nonpaged case.
- The cc 10.7 P2 sweep keeps `b == 1` head-major draws head-major; it no longer rewrites them to token-major.
- `SUPPORT_MATRIX_TRACKER.md`: the Gaps row is removed, and the P2 validation paragraph is updated.
