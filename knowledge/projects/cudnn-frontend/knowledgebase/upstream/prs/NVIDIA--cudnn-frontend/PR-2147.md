# Add native SM107 half D256 dense prefill splitting

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2147) · state: closed · merged: True

## Original PR description

Native SM107 FP16/BF16 D256 dense prefill now supports explicit split-KV on its existing two-CTA unpacked path, including supported aligned head envelopes. Each partition writes FP32 O partials and natural-log partial Stats into caller workspace; the existing combine applies the sink once and produces final O/Stats. Empty partitions retain the reduction identity, and the unsplit path keeps its existing epilogue.

Graph and standalone admission share the same native-path predicate. Partial-workspace sizing and native binding now agree with the kernel's FP32 stores. There is no heuristic-policy or caller-API change.

Validation: 58 focused checks pass on the target architecture (42 native GPU cases and 16 host checks), including existing D128 and quantized-family controls. Five memchecks, two racechecks, and two syncchecks pass with zero errors or hazards. The related host suite passes 421 checks; 23 GPU cases skip on that host. The new admission tests reject on the unchanged parent, and the partial-workspace regression detects the initial half/FP32 mismatch. Scoped hooks pass.

Coverage includes FP16/BF16, causal and bottom-right tails, sliding windows, sinks, empty partitions, persistent scheduling, O-only/natural/log2 Stats, logical head envelopes, native binding, fresh pointers, and retained CUDA-graph replay. All 41 new cases are also collected through the existing SM107 CI entrypoint. This change adds a legal kernel option; it makes no default-selection or performance claim.
