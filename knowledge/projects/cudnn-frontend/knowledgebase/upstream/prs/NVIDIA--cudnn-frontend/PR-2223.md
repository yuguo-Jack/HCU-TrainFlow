# gemm(frost sm100): bind a dimensioned packed-FP4 output tap at half the logical N

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2223) · state: open · merged: False

## Original PR description

## Problem

`_tap_fake_shape` in `python/cudnn/gemm/frost/sm100/epilogue_codegen.py` binds an **undimensioned** FP4 output as `(sym_m, sym_n // 2, l)`, because E2M1 packs two values per byte. Its **dimensioned** branch binds `sym_n` instead.

An FP4 tap whose tensor carries `[1, S, N]` is therefore declared `N` bytes wide, as a block-scaled quant output is. The compiled host then refuses the real `N // 2`-byte row at its shape check, before launch.

This only affects the STG drain, because the TMA drain does not bind through that tap. For example, NVFP4 gather with F8_128x4 row scales at N=288 on a 256-column tile stops at the packed-output shape check, while N=256, which uses TMA, works.

## Change

Bind `(sym_n // 2)` in the dimensioned branch too, for FP4 data taps. Reduction and quant-scale taps are not packed and are excluded.

This was split out of #2198 at review.

## Testing

New `test_moe_gather_nvfp4_reordered_row_scales_sm100[tma_drain|stg_drain]` covers NVFP4 gather with F8_128x4 row scales at N=256 (TMA drain) and N=288 (partial 32-column STG drain). It checks the real scale values and the dequantized output. It does not check the scale padding slots; that is #2198's job.

B300 (SM103), cuDNN 9.27, CuTe DSL 4.8:

| | `tma_drain` | `stg_drain` |
|---|---|---|
| develop + new test | pass | **fail** (packed-output shape check before launch) |
| this PR | pass | pass |

FP4 / quant subset of `test_moe_grouped_matmul_fwd.py` + `test_matmul.py` with this change: 81 passed, 16 skipped. The only 2 failures are the two `test_sm100_quant_scale_k_padding_is_zeroed` cases, which need #2198's padding fix and are unrelated to this change.

`black 26.3.1 --line-length 160 --fast` is clean.
