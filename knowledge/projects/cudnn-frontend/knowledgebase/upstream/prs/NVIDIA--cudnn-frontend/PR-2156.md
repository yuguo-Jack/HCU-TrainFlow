# norm: keep the atomic-free GroupNorm backward on whole warps

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2156) · state: closed · merged: True

## Original PR description

## Problem

The atomic-free GroupNorm / InstanceNorm backward (`groupnorm_fast_sm100`) rounds its CTA width up to a multiple of the channels per group. When CPG does not divide 256, the result is not a whole number of warps. For example, 640 or 1280 channels in 32 groups give CPG 20 or 40, and the CTA becomes 260 or 280 threads.

`_block_sum2` assumes whole warps. It shuffles with a full mask and reduces `bt // 32` warp slots. With a partial last warp:

- that warp's contribution is dropped from the row sums;
- its lane 0 writes `red[nwarps]`, which is the first warp's slot for the second accumulator.

As a result, dx is wrong and changes between identical calls. dgamma and dbeta are unaffected, because they are reduced per channel outside the block sum. The CGA route already declines a width that is not a multiple of 32 (`if bt % 32: return None`); the fast route had no such check.

On a B300, develop gives these dx errors against an fp64 autograd reference:

| shape (32 groups) | dtype | develop max abs err | this branch |
|---|---|---:|---:|
| 16x1280x16x16 | fp32 | 7.2e-02 | 6.4e-06 |
| 2x1280x8x8 | fp32 | 1.5e-01 | 4.1e-06 |
| 16x1280x16x16 | bf16 | 7.4e-02 | 3.1e-02 |
| 2x1280x8x8 | bf16 | 9.3e-02 | 3.1e-02 |
| 4x640x32x32 | bf16 | 3.4e-02 | 3.1e-02 |
| 32x256x16x16 (CPG 8, control) | bf16 | 3.1e-02 | 3.1e-02 |

The bf16 floor of about 3.1e-02 is the same as on the CPG 8 control shape. On develop, 20 repeated calls at the CPG 20 / 40 shapes do not give a bitwise-equal dx; on this branch they do.

## Change

- New `block_threads(spec, elem_bytes)` picks the width as before (sized to the row, at most 256 before rounding), then rounds it up to a multiple of lcm(CPG, 32).
- When lcm(CPG, 32) exceeds 1024 (for example CPG 33), it returns `None`. `eligible()` then declines and the dispatcher falls through to the next route.
- `backward()` uses the same helper.
- Widths that were already whole warps are unchanged. Every CPG from 1 to 1024 was checked over several spans: no width that was a multiple of 32 and of CPG moves, so those shapes run the same kernel as before.

## Tests

New file `test/python/norm/cutedsl/test_norm_gn_fast_bwd_full_warps.py` (L0):

- Host only: the width is a multiple of 32 and of CPG for CPG in 1, 2, 3, 5, 8, 10, 20, 40, 64, 96 and 160, over four spans. CPG 33 declines.
- GPU: five shape / dtype cells that take the fast route (asserted with a spy). Each checks that 8 identical calls give a bitwise-equal dx, and compares dx / dgamma / dbeta against fp64 autograd.

On develop, all five GPU cells fail with "dx changed between identical calls". With this change, all 50 tests pass. The full `test/python/norm` with this change gives 1379 passed and 1 skipped. Its one failure came from an earlier parametrization of the new test, which picked a cell that takes another route; that is fixed in this head.
