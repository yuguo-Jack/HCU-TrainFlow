# test(sdpa): the packed-sink combine cells call the packed host entry with its current fourteen arguments

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2074) · state: closed · merged: True

## Original PR description

## What

`test_sdpa_fwd_dsl_sm107.py::test_packed_sink_combine_counts_virtual_key_once[{none,ln,log2}-{float16,bfloat16}]` calls the compiled sink packed split-combine entry (`compile_ptr(packed=True, has_sink=True)` through `positional_entry`) directly.  The six cells now pass the entry's current fourteen positional operands: the eleven they always passed, then the two `None` physical-origin operands (`cu_q_ptr`, `origin_ptrs` -- compact partials carry no physical origins) and `n_batch`, the one batch the packed entry serves, the way the prepared split host (`_thd_split_host.py`) and the sibling direct-entry tests (`test_sdpa_split_combine_sm100.py`, `test_sdpa_split_combine_many_splits.py`) already do.  The assertion is unchanged: the virtual sink key is counted once, the dead partials are never read, the padding stays untouched.  No kernel or host entry changes; no other cell of the module is touched.

## Since when

#1866 appended the paged-THD physical-origin operands to `_host_ptr_packed` (`cu_q_ptr`, `origin_ptrs`, `n_batch`; `origin_specs` is a Constexpr), so the compiled positional frame grew from eleven to fourteen slots -- `(..., total_q_ptr, stream, sinks_ptr, cu_q_ptr: None, origin_ptrs: None, n_batch: int32)`.  The sibling direct-entry tests were updated in that PR; these six cells, which run only on cc 10.7 (`pytest.skip` elsewhere), were not, and each has failed there since with

```
TypeError: Expects 14 parameters when calling: `_host_ptr_packed(o_partial_ptr: DataPointer, ..., stream: Stream, sinks_ptr: DataPointer, cu_q_ptr: None, origin_ptrs: None, n_batch: int32)`
```

(the same six failures are listed as pre-existing in #2070's test summary).
