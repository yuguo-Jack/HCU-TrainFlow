## Summary

On a GPU outside the FROST linear-attention rows (SM100 / SM103 / SM107), 28 `linear_attention` L0 tests fail with `cudnnGraphNotSupportedError: no engine — python or backend — proposed a plan`. The suite's convention for a declined configuration is a skip ("<engine> declined: ..."); on the same GPU, 5154 sibling cases already skip with a "declined" reason. The 28 failures bypass it:

- **`build_and_pin`** is documented as "declines waive the test", but it only caught the pinned plan's `check_support`. A graph that no engine plans at all raised from `create_execution_plans`. That path is now waived too, where no FROST engine can run (below). This covers `test_forward_state_alias_after_graph_warmup` (6 cases).
- **Direct op calls that now go through the same waiver:**
  - the `mamba2_summary` / `mamba2_summary_bwd` helpers (`test_mamba2_summary_matches_prefill`, 4 cases);
  - the op calls in `test_mamba2_summary_graph_mixed_state_dtypes` (2 cases);
  - the summary op in `test_steep_summary_matches_reference` (4 cases);
  - the warm-up launches of `test_steep_cuda_graph_gate_transitions` (12 cases).

The waiver is `waive_engine_less(what)`. It skips a `cudnnGraphNotSupportedError` only when `frost_la_unavailable()` reports that no FROST linear-attention engine can run in this process: outside SM100 / SM103 / SM107, or without a supported `nvidia-cutlass-dsl` (the device and DSL half of `frost_la_gate`). Elsewhere it re-raises, so a device the rows serve takes exactly the same path as before, and a planning, heuristic or malformed-graph failure there still fails the test. No product code changes.

## Why

These tests fail on any non-SM100-family GPU instead of skipping. Found while running the suite on an L40S.
