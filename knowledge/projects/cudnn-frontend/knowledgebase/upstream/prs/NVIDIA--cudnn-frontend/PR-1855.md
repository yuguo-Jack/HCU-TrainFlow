# sdpa fwd (frost): propose PackGQA / split on the flavor the leg lands on (Rubin d64 decode)

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1855) · state: closed · merged: True

## Original PR description

## What

`_pack_gqa_eligible` and `_split_points` decide whether to *propose* a packed or split plan by reading the knob-less `_selected_d_shape(caps, facts)`. Since #1607 the Rubin half row has dense-only 32/64-wide native tiles, so for a D64 (or D32) graph that knob-less read returns the native small tile, which has no PackGQA or split. Every packed and split proposal was dropped.

`mismatch()` disagrees: a packed or split *request* walks past the dense-only tile onto the d128 shared bodies (`_beyond_dense_leg`) and is admitted. Explicit `PACK_GQA=1` therefore builds and runs correctly, but the default proposal list never contains it.

The proposal now asks the same question `mismatch()` asks, using the prospective packed/split knobs:
- `_pack_gqa_eligible` passes `SdpaFwdKnobs(pack_gqa=True, split_kv, cga)` to `_selected_d_shape` and to `rubin_dense_d128_shared_leg`.
- `_split_points` passes the split leg's knobs.

## Effect

The change only applies to rows with `dense_only_d_shapes` whose pack/split d-shape lists are set, which today means Rubin d32/d64 dense graphs. The SM100 row's lists are `None`, so its behavior is unchanged.

CPU proposal check, Rubin, B128 H64/8 D64 KV131072, Q 1/4, full and SWA128, with and without sink:

| source | lead plan |
|---|---|
| parent of #1607 (2bcdd1bb4) | packed (split 4 without sink) |
| develop before this PR | unpacked native d64 only |
| this PR | packed (split 4 without sink), same as the parent in all 8 cases |

Long d64/d32 prefill still leads with the native tile; the packed d128 plan is added only as a runner-up.

This is the gpt-oss sink-decode regression in the Rubin nightly. The kernel owner bisected it to #1607 and measured explicit packed back at the parent's time on those shapes. The no-sink split proposals are checked on CPU only; I did not time them on GPU.

## Tests

- New `test_rubin_d64_decode_proposes_the_packed_leg` (8 cases). It fails on develop (8/8) and passes with this change. It also asserts that every proposal passes `mismatch()`.
- `test_heuristic_geometry.py`, `test_sdpa_bias_nchunk_sm107.py`, `test_sdpa_bias_sm107.py` and `test_flashinfer_consumed_surface.py`: 941 passed, 82 skipped.
