# Enable native D128 N64 tiles for paged THD attention

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2163) · state: closed · merged: True

## Original PR description

Paged THD D128 plans reject an explicit `TILE_N=64`, although their native SM107 prefill body already implements the two-score-slot pipeline. Admit this option for unsplit FP16/BF16 plans with one or two CTAs, using the existing shared graph/standalone predicate. The default remains N128; dense-paged and paged split plans retain their existing domain.

The SM107 CI entry collects 12 admission/record checks and 8 graph boundary cases covering page sizes 8–256, independent K/V layouts, physical Q/O/Stats origins, packing, Natural/LPT, windows/sinks, empty/keyless requests, stride/pointer rebinding and retained CUDA Graph replay. The N64 cases use a full-row CPU FP64 reference with unchanged tolerances and canaries. This is a knob-domain extension; no capabilities row, heuristic or placement change.

Validation: 45 focused host checks passed. Restoring the parent predicate makes all four N64 admission cases fail at the intended gate. The actual SM107 CI entry passes all 20 checks (12 admission/record + 8 native lifecycle cells). Two representative cases each pass unfiltered memcheck, synccheck and racecheck, with zero reported sanitizer errors or hazards. The final source snapshot matches this PR head; scoped hooks pass.

An earlier run with the GPU FP64 reference passed the entry and memcheck, but its racecheck reached a 650-second timeout without a result. That incomplete run is retained. Moving only reference computation to CPU preserves all rows, tolerances and canaries and allows the unfiltered racecheck to finish. Configured CI and bot review remain separate from these author checks.
