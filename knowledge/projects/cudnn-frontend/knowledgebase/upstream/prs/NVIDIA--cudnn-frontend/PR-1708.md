## Affected area

FROST linear-attention forward compilation and the shared compiled-artifact wrapper serializer.

## Summary

GDN/GDP warmup forward and GDN2/KDA uncut/chain forward currently cache compiled launchers only in process-local dictionaries. Route these five compiler entrypoints through `compile_cached`, retaining their existing static specialization keys and in-process dictionaries so fresh processes can reuse exported artifacts.

These launchers pass configuration dataclasses as `cutlass.Constexpr`. The serializer currently rejects all dataclass compile arguments, even when the DSL removes them from the runtime signature. Allow those configurations only when the executor's own argument rectification proves that no dataclass survives at runtime. Runtime dataclasses and executors that cannot establish that contract continue to bypass export. The serialized runtime calling convention stays unchanged.

## Why

An in-process cache cannot amortize compilation across worker or service restarts. Reusing the common artifact cache supplies its existing source/dependency/device invalidation and atomic publication. This patch covers the five specified forward compiler entrypoints; it does not add persistent caching to every linear-attention helper or backward kernel.

## Related issues

None.

## API and compatibility impact

No public API or kernel-math changes. Existing cache directory and disable controls apply. Compile keys contain static specialization data; runtime pointers and packed sequence contents are not persisted. Artifact eligibility remains conservative on older DSL executors.
