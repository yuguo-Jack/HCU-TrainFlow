# sdpa(bwd): keep runtime padding out of the SM120 backward's GEMM operands

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2206) · state: open · merged: False

## Original PR description

## Problem

#2135 made runtime padding unread data for the SM80 forward bodies, and #2178 did the same for the SM120 forward. The SM120 backward (`sdpa_bwd_sm120`, `bprop_f16`) TMA-loads whole K/V and Q/dO tiles. On a dense padded graph, the rows past `seq_len_kv` / `seq_len_q` lie inside the declared S_kv / S_q, so TMA loads them exactly as they are stored. P is masked to 0 on those rows, but the GEMMs still multiply it against them:

- **K/V padding → dQ:** dP = dO·Vᵀ over a NaN V row is NaN, so dS = P·(dP − δ) = 0·NaN = NaN, and dQ += dS·K also multiplies 0 against the NaN K row.
- **Q/dO/O padding → dK (and dV):** dK += dSᵀ·Q and dV += Pᵀ·dO run over the padded q rows. δ = rowsum(dO·O) and the Stats LSE of a padded row are also unread data.

Tested on an RTX 5060 Ti (cc 12.0) at develop c24ef372, with the K/V padding and the Q/dO/O padding each filled with NaN on its own:
- NaN only in the K/V padding: 12 of 16 cases return NaN in valid dQ rows.
- NaN only in the Q/dO/O padding: 16 of 16 cases return NaN in valid dK rows.

## Change

- `_common.py`: new `zero_tile_rows` helper. It zeroes rows `[row_lo, rows)` of one chunked/swizzled tile through `tile_ptr`. The swizzle stays within a row, so whole rows are cleared. As in the forward's `sanitize_v_tail`, each warp redundantly clears the full overhang and then syncs itself.
- `bprop_f16.py` (all changes apply only when runtime lengths are present):
  - With `seq_len_kv`, after the K/V TMA waits: zero the sK/sV rows past `seq_len_kv[b]`. This runs once per CTA and only on a partial tile, before V moves to registers.
  - With `seq_len_q`: zero the sQ/sdO rows past `seq_len_q[b]`. Only the first, highest q block can hold such rows. A `fence.proxy.async` follows, because TMA later refills those buffers.
  - With `seq_len_q`: `trim_q_rows` (padded rows' LSE := +inf, so P = 0) now applies whenever `seq_len_q` is present; before, it applied only with a sink. A padded row's δ is set to 0.
  - Graphs without runtime lengths compile to the same kernel. The det-2-kernel path already declines padding.
- New `test/python/sdpa/frost/test_sdpa_bwd_sm120_padding_nan.py`, an SM120 port of the SM80 test in #2200. It fills the Q/dO/O/Stats padding past `seq_len_q` and the K/V padding past `seq_len_kv` with NaN, then checks the valid rows of dQ, dK and dV against a reference computed on clean data. It covers D64/128/192/256, fp16/bf16, causal and non-causal, with s_q = s_kv and s_q < s_kv.

## Tests

On an RTX 5060 Ti (cc 12.0), develop c24ef372, CuTe DSL 4.8.1, cuDNN 9.27:
- New test: 16 failed on develop (12 NaN in valid dQ, 4 in valid dK), 16 passed with this change.
- `-m "L0 or L1"` over `test_sdpa_bwd_dsl_sm120`, `test_sdpa_bwd_native_layout_contract`, `test_sdpa_native_bwd_binding`, `test_sdpa_bwd_dot_strides` and `test_sdpa_bwd_heuristics`: 1171 passed, 8 skipped, 4 failed on both develop and this change. The four failures are the same `test_backward_dot_other_arch_lowering[*-sm_107a]` cases, which this toolchain cannot lower.
- Padded backward timing (b=4, h=16, s=2048, bf16, `seq_len_q` = `seq_len_kv` = [2011, 1029, 2047, 1536], 5×20 iterations, median):

  | case | develop | this change |
  |---|---|---|
  | D128 | 5.84 / 5.89 ms | 5.82 / 5.83 ms |
  | D128 causal | 3.41 / 3.41 ms | 3.44 / 3.44 ms |
  | D64 | 2.91 / 2.92 ms | 2.94 / 2.95 ms |

  The two values are two interleaved runs. All differences are within 1%.
- `pre-commit` on the touched files passes.

No cc 12.1 device was run.
