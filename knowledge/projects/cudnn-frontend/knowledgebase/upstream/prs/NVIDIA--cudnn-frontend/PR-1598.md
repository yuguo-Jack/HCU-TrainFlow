# test: relax BSA large-logits LSE tolerance

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1598) · state: closed · merged: False

## Original PR description

The SM90 blk64 mixed-warp large-logits case produces LSE values around 5.7e8. The kernel output and torch reference can differ by about 1.3e-4 relatively from fp16/bf16 QK reduction while the centered softmax output remains correct.

Use a small relative tolerance for the large even-row LSE comparison instead of an absolute-only 1e3 bound. Keep the output check and ordinary-row LSE tolerance unchanged.

Validated on H100 10.176.200.163 with the CI-style cutlass-4.8 sm90 repro for test_bsa_attention_forward_sm90_blk64_large_logits_mixed_warp.

### Before Fix

The target test failed on the even-row LSE check:

```
AssertionError: Tensor-likes are not close!

Mismatched elements: 32 / 32 (100.0%)
Greatest absolute difference: 74624.0 at index (0, 0, 0) (up to 1000.0 allowed)
Greatest relative difference: 0.00013179502275306731 at index (0, 0, 0) (up to 0 allowed)
```

The output tensor comparison had already passed; only the large-LSE absolute-only tolerance was too strict.

### After Fix

After changing the even-row LSE comparison from absolute-only tolerance to a small relative tolerance:

```
torch.testing.assert_close(
    result["lse_tensor"][..., 0::2],
    lse_ref[..., 0::2],
    atol=1e3,
    rtol=2e-4,
)
```
the target test passed:

```
======================= 2 passed, 122 warnings in 10.26s =======================
pytest-gpu: wall time 17.042s
```
### Rationale

For this large-logits case, even-row LSE values are approximately `5.7e8`. The observed absolute difference (`74624`) corresponds to only about `1.3e-4` relative error, which is expected from the large fp16/bf16 QK reduction while preserving finite, centered softmax output. The fix keeps the existing output check and ordinary-row LSE tolerance unchanged, and only scales the even-row LSE tolerance with the tensor magnitude.
