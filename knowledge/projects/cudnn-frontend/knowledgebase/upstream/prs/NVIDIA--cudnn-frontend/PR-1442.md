## Affected area

## Summary

`sdpa_fwd_prefill_sm80` returns NaN for a causal graph whenever `attn_scale > ln 2` (about 0.693), for example `attn_scale = 1.0` with a pre-scaled Q. This PR fixes it in both SM80 forward kernels (`prefill_f16.py`, `prefill_d256_f16.py`).

**Mechanism.**
1. The kernels fill masked scores with `-FLT_MAX`, take the row max over the raw scores, and multiply it by `scale * log2(e)`.
2. Above `attn_scale = ln 2` that factor exceeds 1. A row that is fully masked within a KV tile therefore overflows to `-inf`.
3. The running max also starts at `-inf`, and `-inf - -inf` is NaN in both the rescale factor and P.
4. Causal graphs hit this on their first KV tile, the one nearest the diagonal, which the kernel processes first.

Unmasked graphs were not affected. A sink does not protect a row: these kernels add the sink after the KV loop. (Corrected after review: an earlier version said it did.)

**Fix.** Clamp the scaled iteration max to `-FLT_MAX`. The clamp is compiled only into kernels with a mask and runs only on the KV iterations that apply it (the existing runtime `needs_mask`), so interior iterations and unmasked kernels are unchanged.

For `attn_scale <= ln 2` the clamp is a no-op. For larger scales, a fully masked tile row now:
- gets P = 0 for its masked cells,
- has its rescale factor zero the (empty) accumulator,
- is overwritten by the first tile that holds a real score.

The LSE and `inv_l` guards for fully masked rows are unchanged.

The shared reference `_check` in `test_sdpa_prepared_sm80.py` now takes the scale from the case. The staged-copy suite, which reuses it, names its 1/sqrt(d) scale explicitly.
