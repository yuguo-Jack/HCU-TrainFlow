## Summary

This PR adds `libcudnn_frontend_aot_sm120.so`: attention forward for compute capability 12.0 (RTX 50xx, RTX PRO Blackwell) with every kernel compiled ahead of time, behind a header-only C++ API. A plan is built once per shape class (head dim, dtypes, mask, sink, GQA ratio). `execute()` takes run-time `b / s_q / s_kv / h_q / h_kv`, byte strides and pointers, and only launches.

- **Two backends, one API.** The plan's KV dtype picks the backend:
  - f16/bf16 KV runs the FROST SM120 prefill templates, exported ahead of time with run-time extents and strides. Decode-shaped calls run them split-KV and PackGQA, including split-KV with sinks (#1731) and PackGQA with `tile_q % G != 0` (#1740, G = 6).
  - q8_0/q4_0 KV runs hand-written flash-decode kernels over the ggml block cache (`aot/sm120/src/decode_q8_q4.cu`).
- **Kernel selection.** `build.py` runs FROST's own SM120 heuristic (`heuristics.recommend`) offline over a shape grid and emits a static selection table per shape class. A caller can also pin any prebuilt knob set, and the C ABI lists them.
- **Uncovered combinations** return `NOT_SUPPORTED` with a message; nothing falls back silently.
- **The CuTeDSL runtime is not linked.** The exported objects import ten thin wrappers from `libcute_dsl_runtime.so` (42 MB). `aot/sm120/src/runtime_shim.cpp` provides them, each matching the CuTeDSL 4.8.0 runtime's wrapper as read from its disassembly. `ldd` of the library shows only libstdc++, libm, libgcc_s and libc, with cudart linked statically.
- **Files:**

**Default matrix:**
- f16 and bf16;
- d 64 / 128 / 256 × {no mask, causal}, plus d64 causal with sinks and d64 causal + 128-token window with sinks (gpt-oss);
- PackGQA G ∈ {2, 4, 6, 8};
- splits {1, 2, 4, 8, 16, 32}.

That is **444 prefill + 4 combine kernels, 47.5 MiB**. On a GPU-less 96-core host the heuristic pass took 15 s and the export 25 s, plus compile and link.

## Why

llama.cpp/ggml (C++, no Python) wants cuDNN attention kernels on sm_120a. An integration through the cuDNN graph API paid about 30 ms per new shape to build the graph. This library never compiles at run time: plan build only loads modules, and `execute()` costs about 1.5 µs of host time for one launch and about 3 µs for two.

Design choices, and where they differ from what one might expect:
- **No template changes.** An earlier prototype added `dynamic=` / `kernel_name=` / `export_options=` hooks to the templates' `compile()`. On current develop the SM120 templates already compile through a prepared pointer host that binds batch, sequence lengths and strides at run time, so those hooks are not needed. `aot_host.py` adds a host that also takes the head counts at run time, and it reuses the kernel object the template's own `compile()` builds. The cross-check below confirms that the AOT kernels are bit-identical to the Python FROST engine for the same knobs.
- **The build is driven by Python, with an opt-in CMake option.** Export needs CuTeDSL in-process. CMake wraps `build.py` and builds the test and benchmark.
- **The C++ header stands alone.** It depends only on `cuda_runtime.h` and uses the C status codes rather than FE's `error_t`, so a consumer can vendor the two headers without cuDNN headers.
- **Extents are passed as `Int32` leaves.** A Python-int tuple is traced as a compile-time constant and silently dropped from the exported C ABI. The wrapper prototype still declares it, but the values are baked in.
- **No LSE output in ABI v1.** llama.cpp does not consume one; the append-only structs leave room to add it.

## Related issues

Related to #1731 (split-KV with an attention sink on SM120) and #1740 (PackGQA with `tile_q % G != 0` on SM120); both are included in the matrix.

## API and compatibility impact

- **New and experimental:** the headers `cudnn_frontend/experimental/sm120_aot_attention{,_abi}.h`, a new opt-in CMake target, and a new Python module that nothing imports by default. There are no changes to existing APIs, templates, heuristics or default builds.
- **Build:** `nvidia-cutlass-dsl >= 4.8` (verified on 4.8.0), a CUDA 13 toolkit (verified 13.2) and g++; no GPU.
- **Run:** compute capability 12.0 only (SASS for `sm_120a`, no PTX), and a driver that supports the CUDA 13.2 runtime (verified on 615.71.09). Linux only.

## Testing

All GPU results below are from one **RTX PRO 6000 Blackwell Workstation Edition** (188 SMs, driver 615.71.09, CUDA 13.2), on the library built from this branch's head (`75edfecd5`).

- **`test_sdpa_sm120 --lib <so>`: 1815 passed, 0 failed.**
  - Prefill through the selection table: 784 cases. These are 16 classes × G ∈ {1, 2, 3, 4, 6, 8, 12} × 7 shapes:
    - decode s_q = 1, speculative s_q = 7, s_q > s_kv, and non-tile-multiple lengths;
    - the compact BSHD layout, and a llama.cpp-like layout (BHSD Q, KV cache with spare capacity, padded O head stride; the padding is checked for clobbering).
  - Every prebuilt knob set pinned: 888 cases (444 sets × 2 shapes).
  - Errors are measured against an fp32 reference. The worst max |O − ref| is 4.9e-4 for f16 (tolerance 6e-3) and 4.1e-3 for bf16 (tolerance 3e-2).
  - Quantized decode: 124 cases (84 directed + 40 random) against a double-precision reference, with tolerance 1e-2 × max(1, |O|).
  - CUDA-graph capture + 3 replays bit-identical: 4 cases (FROST unsplit, FROST split + combine, q8_0, q4_0).
  - Two concurrent streams × 50 iterations, bit-identical to single-stream runs: 1 case.
  - Rejections (unsupported class or knob set, misalignment, G mismatch, workspace too small, n_q > 8): 14 cases.
- **`test_sdpa_sm120 --compare-lib <cute-dsl build>`: 144 / 144 bit-identical.** This compares the shipped library (in-tree runtime shim) with the same objects linked against `libcute_dsl_runtime.so` (`build.py --runtime cute-dsl`). It covers 16 classes × G {1, 6, 8} × 3 shapes, including the split-KV and PackGQA kernels.
- **`crosscheck_frost.py`: 15 / 15 bit-identical** (max |diff| = 0) against `SdpaFwdDslSm120`, the in-process Python engine, using the knob set the AOT table chose for each case. The cases cover:
  - d 64 / 128 / 256, f16 and bf16;
  - split-KV and PackGQA with G = 2, 4, 6 and 8;
  - split-KV with sinks;
  - sinks with a 128-token window;
  - the KV-cache layout.
- **`bench_sdpa_sm120`:** host time per `execute()` is the median over 11 batches of 100 calls (single process).
