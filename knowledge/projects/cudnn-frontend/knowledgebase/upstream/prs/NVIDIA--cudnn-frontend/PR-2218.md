## Summary

- Add application-defined reduction graphs with typed identities and reducer callbacks.
- Expose custom-reduction helpers and reduction modifiers in C++ and Python.
- Add argmax, argmin and sampling examples, supported HLO-derived argmax regressions, plan round trips, and input-validation coverage.

## Reviewer overview

Start with [How custom reductions work](https://github.com/NVIDIA/cudnn-frontend/pull/2218/files?short_path=7f98261#diff-7f982619e548086ecf52f241ff5265416e8462452769907876050e5e114311be) for the concepts, data flow and an argmax example. This Markdown guide is an added file in this PR (`docs/operations/custom_reduction/overview.md`) and will merge with the feature. It is also listed under **Custom Reduction → How custom reductions work** in the documentation navigation.

A reduction can carry several streams as one state: argmax carries a `(value, index)` pair and combines both according to an explicit tie/NaN rule. The reducer callback builds a symbolic scalar graph during operation-graph construction. cuDNN then executes the resulting reduction through the normal execution-plan path.

## Python sample

The [custom-reduction argmax notebook](https://github.com/NVIDIA/cudnn-frontend/pull/2218/files?short_path=c589cca#diff-c589cca39a45fcd93504a838db2b5e44d6324c9eb1a6bff1c4f3426897d5dc79) is included in this PR at `samples/python/71_custom_reduction_argmax.ipynb`, following the repository's numbered Python tutorial convention and listed in `samples/README.md`.

It walks through greedy decoding, argmax/argmin NaN rules, speculative-decoding verification, masked argmax, and Gumbel-max sampling, with PyTorch reference checks. All seven code cells passed in the local cuDNN 9.29 / SM100 qualification run.
