## Affected area

FE OSS kernels or CuTeDSL

## Summary

Fixes two develop regressions that #1907 introduced. Both fail on every GitLab `python:*` lane and on `python/*/frost:cutlass-rel:sm100`, for example in pipeline 76928986.

1. **Kernel name prefix.** `sparse_lean_d256_f16._kernel` gains the `set_name_prefix("cudnn", remove_cutlass_symbol=True)` its sibling kernel has. This fixes `core/frost/test_frost_kernel_name_prefix.py`.
2. **Import boundary.** Declaring a gated attention block, plain or with the in-block indexer decode, imported `cudnn.sdpa.fwd.heuristics` to read the `tile_form` vocabulary and the lean-tile rules. `heuristics` imports `cudnn.frost.tile_dsl`, so three `core/test_import_boundaries.py` cases failed:
   - `test_gated_block_declaration_and_execute_preflight_do_not_import_cache_kernel`
   - `test_indexer_decode_declaration_under_fuse_prepare_does_not_import_the_prepare_kernel`
   - `test_indexer_decode_declaration_declines_old_dsl_at_check_support_not_at_construction`

   The fix moves the vocabulary, the two kernel-template names, the lean-tile placement/decline/fill rules and the lean split arithmetic (`lean_sparse_n_sub` / `lean_sparse_split` and their constants) **verbatim** into a new DSL-free module, `cudnn.sdpa.fwd.sparse_tile_rules`.
   - `heuristics` and `config_sm107` re-export every moved name unchanged.
   - The block and the sparse adapter now import the rules module on the declaration and `check_support` paths.
   - Five monkeypatches that set those constants on `heuristics` now target the owning module. Patching `heuristics` would no longer reach the moved functions.

## Why

The import-boundary tests keep declaration DSL-free (python/cudnn/AGENTS.md Rule 7: an old DSL must be a typed version error at `check_support`, never an import failure at construction). The rules are pure host arithmetic, so a DSL-free home is the natural place for them.

## Related issues

Follow-up to #1907. Bisected: the import-boundary test passes at its parent `955ed583b` and fails at `7301fad21` and every later develop commit.

## API and compatibility impact

None. Every moved name is still importable from `heuristics` and `config_sm107`. Rules, values and docstrings are unchanged.
