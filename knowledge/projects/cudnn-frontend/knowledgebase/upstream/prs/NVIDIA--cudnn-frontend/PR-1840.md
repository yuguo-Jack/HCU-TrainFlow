# test(sdpa): expose child stacks on artifact timeouts

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1840) · state: closed · merged: True

## Original PR description

Cold prepared-backward artifact tests currently report a 300-second subprocess timeout without showing the child's captured output. The visible traceback therefore cannot distinguish time spent importing or compiling from blocked execution or reference checks.

Use a shared test runner that arms a child-side `faulthandler` stack dump at 270 seconds and includes both captured streams in a timeout failure. Both prepared-backward artifact suites use it. The 300-second deadline, child GPU programs, numerical checks, cache-hit assertions and capture/replay checks remain unchanged. Test guidance records how to verify this diagnostic path.

Validation:
- Deliberately blocked CPU child: the original runner hides the child stack; the new runner reports the stack and both stdout/stderr markers.
- Normal child retains argv, environment, working directory and JSON output; nonzero child exit remains a failure for the existing callers.
- Both existing GPU child program strings are byte-for-byte unchanged.
- Changed-file pre-commit checks and `git diff --check` pass.

This is a diagnostic change, not a resolution or waiver of the outstanding GPU-CI timeouts. No new GPU qualification is claimed for this patch.
