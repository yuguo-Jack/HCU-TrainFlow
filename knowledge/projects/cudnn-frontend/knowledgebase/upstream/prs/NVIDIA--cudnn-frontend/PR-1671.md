## Affected area

CI or test infrastructure

## Summary

`test_sdpa_bwd_dsl_sm120.py::test_sdpa_bwd_dsl_sm120_strided_io_rejects_unaligned` builds an SDPA backward whose Q has a head stride of 68 fp16 elements (136 bytes). It used to assert two things: the SM120 FROST engine declines the graph, and the backend builds it instead.

#1572 (fixing #1571) made the frontend refuse a stride that is not a multiple of the declared 16-byte alignment for the native engines too. Those engines return wrong output or fault on such strides. So no plan builds any more.

The test now expects `cudnnGraphNotSupportedError` and checks that the message contains both declines. The FROST half ("never a copy") is unchanged, and the docstring now matches the behavior.

## Why

Both sm120 frost lanes of develop schedule 74082381 (FE 149f1150d) fail with the same error: job 489328359 (cutlass-rel) and job 489575569 (cutlass-4.8).

```
cudnnGraphNotSupportedError: no plan in the list could be built:
  [0] sdpa_bwd_sm120[TILE_M=64, TILE_N=128]: sdpa_bwd_sm120: q declares strides the kernel cannot address natively (...); got stride (34816, 68, 272, 1)
  the backend declined: Q: stride 68 of dimension 1 is 136 bytes, not a multiple of the tensor's 16-byte alignment
```

The previous schedule, 73793365, did not include #1572, and both lanes passed there (487012489, 487012496). The CI of #1572 did not run the sm120 frost lanes.

Related to #1571 and #1572.
