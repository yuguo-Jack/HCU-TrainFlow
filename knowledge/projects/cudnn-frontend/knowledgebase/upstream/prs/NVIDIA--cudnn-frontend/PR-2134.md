# [SDPA] Serve single-query SM80 graphs through native forward bodies

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2134) · state: closed · merged: True

## Original PR description

SM80 FROST forward currently rejects every graph with a declared query length of one, even though its native forward bodies predicate query rows. Admit these graphs through the existing dense, THD and paged implementations, with the support matrix updated to describe the prefill-body implementation.

The regression coverage checks FP16/BF16 across all four native envelopes and aligned logical widths, independent physical offsets and page pools, empty Q/KV sequences, masks, sink/bias, optional Stats, nonpositive scales, changed bindings and retained CUDA Graph replay. Execute guards check allocation, compilation and synchronization; output canaries protect storage gaps.

Validation: the parent fails the new graph test because no SM80 FROST plan is offered. A100 qualification: 128 tests passed. Compute Sanitizer: 16 dense/THD/paged single-query cases passed with zero errors. Scoped pre-commit passed.

Builds on #2133; land it first. This adds functional coverage and makes no performance claim for the existing prefill body against a specialized decode kernel.
