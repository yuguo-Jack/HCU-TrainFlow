## Affected area

FE OSS kernels or CuTeDSL

## Summary

Add native `qhead_per_kv_head=96`, `head_dim=576` support to DeepSeek sparse-attention target recompute on SM90 and the SM100 architecture family.

- SM90 uses two H48 head tiles, restricted to the sparse-attention target path. Existing sparse-indexer and dense score-recompute dispatch remains unchanged.
- SM100-family dispatch uses `(M, N, K) = (96, 128, 192)`.
- Add L0 reference tests with and without `topk_length`, including empty and partial rows.
- Add L1 production-boundary tests for logical top-k 2048, 2049, 2050, and 2051.

## Why

H96 callers currently pad Q/LSE to H128 before target recompute. This performs 33.3% more head work and adds caller-side padding traffic and launch overhead.

The native layouts remove that work without introducing a public API change or tensor-layout conversion.

The tile configurations were selected through compile/run validation and profiling:

- On SM90, H48 × 2 consistently outperformed the padded H128 kernel. An H64 × 2 masked alternative showed no stable performance gain and would add masking complexity.
- On the SM100 architecture family, the N64 attention epilogue cannot represent H96 because it would require an unsupported TMEM repetition. N128 covers all 96 heads using the existing fixed repetition.
- K192 keeps the SM100 kernel within the shared-memory budget while retaining two KV pipeline stages. It was 1.81x faster than K64 at top-k 2048 and 1.88x faster at top-k 2051 on SM103.

## Related issues

None.

## API and compatibility impact

- No public API or signature changes.
- Extends sparse-attention target recompute to accept native H96/D576 on SM90 and the SM100 architecture family.
- SM90 sparse-indexer and dense score-recompute behavior remains unchanged.
- Native H96 agrees with the padded-H128 implementation to a maximum absolute error of `3.50e-10` and a maximum relative L2 error of `1.33e-7` across the production performance cases.
