## Summary

This PR adds an experimental, default-off `CUDNN_FRONTEND_PYTHON_FREE_THREADED` build option and protects two shared native caches previously relying on the GIL.

- Pass `FREE_THREADED` to nanobind and select its matching runtime target.
- Serialize CUDA primary-context cache initialization to avoid duplicate retains.
- Publish DLPack type-cache entries with release/acquire ordering. Cache hits do not acquire a mutex; insertion remains locked and rechecks for concurrent or reentrant publication.

## Why

<!-- What problem does this solve, and why is this approach appropriate? -->
I noticed there are python free threading wheels in the current releases, so I added this cmake option.

nanobind's lock will do nothing when not in free threading mode, so there's no performance loss with adding `nanobind::ft_mutex`, see https://github.com/wjakob/nanobind/blob/v3.0.1/include/nanobind/nb_misc.h#L75-L106

## API and compatibility impact

<!-- Note public API, supported GPU/cuDNN/CUDA/Python versions, performance, or backward-compatibility changes. Write "None" if not applicable. -->

This is an initial opt-in for native-backend use with independent graphs and handles. Shared graph/handle access still requires caller synchronization.
Frontend logging must remain disabled during concurrent calls.

Python-side graph_cache and context-fallback synchronization, and qualification of FROST/third-party runtimes, are deferred. Stable ABI requirements are unchanged.
