# test(gemm/cutedsl): skip the tcgen05 GEMM tests on cc 12.x through has_tcgen05

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2234) · state: open · merged: False

## Original PR description

Follow-up to #2166.

## Problem

#2166 made the CuTe DSL GEMM APIs decline cc 12.x in `check_support()` with a `RuntimeError`:

```
RuntimeError: GemmSwiglu requires SM100+ compute capability with tcgen05 (not cc 12.x), but found SM120 on the current device
```

The tests' own SM100 skips still compare the capability with a bare threshold: `capability[0] < 10`, `major * 10 + minor < 100` or `compute_capability < 100`. A cc 12.x device passes those. The tests only catch `ValueError` / `NotImplementedError` around `check_support()`, so the gate's `RuntimeError` fails them instead of skipping them.

RTX 5060 Ti (cc 12.0), develop `a0f7b9f4`, `-m L0 test/python/gemm`: 2480 failed in `gemm/cutedsl`, all with that `RuntimeError`. The largest groups are `test_gemm_swiglu` (570), `test_grouped_gemm_dglu` (454), `test_grouped_gemm_glu` (435) and `test_gemm_amax` (207).

## Change

- All 32 test-level gates in `test/python/gemm/cutedsl` (22 files) now go through `cudnn.tensor_adapter.has_tcgen05`, as the API gates already do.
  - The import is local, because most of these files deliberately do not import `cudnn` at module level.
  - The skip messages are unchanged.
- Five `compute_capability` locals that only fed the old comparison are removed.
- On cc 10.x and 11.x, `has_tcgen05` gives the same answer as the old threshold, so nothing changes on those parts.
- `test_gemm_cutedsl_arch_gate.py` gets a companion to its API-side check, `test_no_cutedsl_gemm_test_skip_admits_cc12_by_threshold`: no test in the directory may skip SM100 on a bare threshold. Its pattern matches all 32 sites on develop and none after this change.

## Testing

RTX 5060 Ti (cc 12.0), cuDNN 9.27, CuTe DSL 4.8.1, `-m L0 test/python/gemm/cutedsl`:
- develop: 2480 failed.
- this PR: 0 failed, 112 passed, 4459 skipped.
- `test_gemm_cutedsl_arch_gate.py`: 8 passed.

`black 26.3.1 --line-length 160 --fast` is clean. `ruff --select F401,F811,F841` reports the same 32 findings as develop; none are new.

I could not run this on a tcgen05 GPU at the moment. The change only replaces each gate's condition with one that gives the same answer for cc 10.x / 11.x.
