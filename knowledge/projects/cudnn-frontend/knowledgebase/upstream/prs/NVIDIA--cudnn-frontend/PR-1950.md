## Affected area

FE OSS kernels or CuTeDSL

## Summary

On Rubin (cc 10.7), take a paged bf16 d128 GQA prefill chunk that FlashInfer's `auto` declares at its Q128 bound. It declares as many packed Q tiles as unpacked ones. Both split choosers broke that equal-work tie toward the **unpacked** grid:
- `paged_thd_split_choice`'s main arm (at one Q tile this is a first-wave tie);
- the one-tile fallback `_d128_thd_split_wave_choice`.

This PR breaks the tie toward the **packed** grid at the same split. In the fallback this comes from a new `prefer_pack` argument that only the Rubin call sets, so SM100's wave choice is unchanged. No split count changes.

## Why

A bounded declaration can only overstate the live tokens. Packed tiles shrink with the live tokens, while unpacked tiles keep one tile per head, so at a declared tie the packed grid does no more work and shares each K/V tile across the group.

- **Diagnosis:** on the exact bounded graphs FlashInfer declares, with actual inputs, packing at the current split was faster on every diagnosed case. It was not in the recommended list before this change.
- **Holdout:** a separately frozen 24-case holdout (six head pairs × B 1–4, live Q 64–128, KV 2k–32k) compared the parent and head defaults through FlashInfer's `auto` in both process orders, with full O / LSE, rebinding and replay checks.
  - All 24 routes changed (PACK_GQA 0 → 1, every other knob preserved).
  - 22 improved in both orders.
  - **Two B = 1 cases with live Q near the bound regressed by about 1%.** This is accepted as an explicit tradeoff, the maintainer's decision: the predeclared "no both-order regression" criterion is replaced by "aggregate gain, per-case regression ≤ ~1.5%".
  - Performance details remain internal.
