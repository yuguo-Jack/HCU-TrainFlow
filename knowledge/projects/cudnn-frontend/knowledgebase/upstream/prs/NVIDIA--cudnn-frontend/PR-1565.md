## Affected area

C++ header `include/cudnn_frontend_shim.h`: the CUDA runtime/driver symbol lookup used under `NV_CUDNN_FRONTEND_USE_DYNAMIC_LOADING`. The Python package and TransformerEngine build with this define.

## Summary

Fixes #1486.

**Root cause.**
- `get_cuda_symbol()` keeps its library handles in a function-local `static std::unordered_map`.
- Every `NV_FE_CALL_TO_CUDA` call looks a handle up in that map. The map is first constructed on the first CUDA call made through the shim, so at exit it is destroyed before any static constructed earlier.
- Since #1195, destroying an execution plan that was recorded into a CUDA graph calls `cudaUserObjectRelease` (`CudaGraphRetainedResource::State::~State`), which goes through `get_cuda_symbol()`.
- TransformerEngine caches its graphs in a function-local `static GraphCache` (`transformer_engine/common/fused_attn/graph_cache.h`). That cache is constructed on its first use, before the graphs it holds make their first CUDA call through the shim. So it is constructed before the shim's map and destroyed after it.
- At exit, the cache's plans therefore look up a handle in an already-destroyed map. This is a heap-use-after-free and shows up as the SIGSEGV after pytest's summary.

**Fix.** The handle map and its mutex are intentionally leaked. This is the same pattern `cuda_graph_retention.h` already uses for its deferred-release queue, so CUDA calls from other statics' destructors stay valid during teardown.

## Testing

I used a standalone repro, built with `-DNV_CUDNN_FRONTEND_USE_DYNAMIC_LOADING` against CUDA 13.2 and run on B200:
- a function-local static owns a `CudaGraphRetainedResource`;
- the program creates a graph, retains the resource on it, and returns from `main`.

This is the same shape as TE's cache. Source:

<details><summary>repro.cpp</summary>

```cpp
#include <dlfcn.h>
#include <cstdio>
#include <memory>
#include <cudnn_frontend.h>

void *cudnn_frontend::cudnn_dlhandle = nullptr;

struct Cache {
    cudnn_frontend::detail::CudaGraphRetainedResource resource;
};

static Cache &
cache() {
    static Cache instance;  // constructed before the shim's first CUDA call
    return instance;
}

int
main() {
    cache();
    cudaGraph_t graph = nullptr;
    if (cudnn_frontend::detail::cuda_graph_create(&graph, 0) != cudaSuccess) {
        return 2;
    }
    cache().resource.retain_on_graph(graph, [] { return std::make_shared<int>(1); });
    return 0;  // the graph is left alive, as a framework's captured graph would be at exit
}
```
