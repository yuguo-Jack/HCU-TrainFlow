## Affected area

FE OSS kernels or CuTeDSL

## Summary

SM90 dense score recomputation runs two consumer warp groups and a producer down separate control-flow branches. Their named barriers currently lower to aligned `bar.sync` / `bar.arrive` despite the warp-role split; synccheck reports divergent threads and terminates the instrumented launch. Racecheck also reports shared-memory hazards between the initial weights fill and producer writes, between reduction reads and slot reuse, and between a consumer's weight/LSE read and the next head tile's producer writes.

Use non-aligned CTA sync and arrive operations while retaining the existing barrier IDs, participant counts and ping-pong schedule. Initialize weights before the initial CTA barrier, protect each consumer's reduction reads before the slots are reused, and add a cross-group handoff when more than one head tile reuses weights/LSE. Add numerical and sanitizer regressions for both score types and both producer modes.

## Related work

Related to #2252, which addresses the separately launched SM90 sparse score kernel. #2244 addresses an independent SM100-family dense score publication path.

## API and compatibility impact

No public API changes. The change targets SM90. The CUDA 12 CuTe DSL compiler runs used the CUDA 13 PyTorch/cuDNN runtime; they are not end-to-end CUDA 12 deployment tests.

## Testing

- GH200 (SM90), develop `f88a1ef2`, cuDNN 9.27.0.42, PyTorch 2.14.0+cu130, DSL 4.8.1/cu13: two selected sanitizer regressions fail on the base (synccheck attention and racecheck indexer); with this change `test_DSA_dense_score_sync_sm90.py`: **12 passed**, covering attention/indexer, unified/split producer, normal execution, synccheck and racecheck.
- With this change, the two original single-shape repros each passed normal execution, memcheck, synccheck and racecheck. The prior multi-head candidate still triggered two racecheck failures; the final cross-group weight/LSE handoff removes those failures in the 12-test run.
- Existing SM90 dense attention and indexer boundary tests: **20 passed, 39 deselected**, including multi-head and THD-wrapper cases.
- Cold-compile BF16 reference checks: four cases each with DSL 4.8.0/cu12, 4.8.0/cu13 and 4.8.1/cu12: **12 passed**. DSL 4.8.1/cu13 is covered by the regression and existing tests. The loaded DSL compiler versions were CUDA 12.9 and 13.4 respectively.
- CUDA Graph replays for both score paths and both producer modes matched references after changing Q and weights/LSE.
- PTX inspection shows the role-scoped named sync/arrive instructions use `barrier.sync` / `barrier.arrive`; the unconditional initial CTA barrier remains `bar.sync`.
- Changed-file pre-commit hooks and `git diff --check` passed.

The tested shapes do not constitute full SM90 performance qualification. For one warmed CUDA Graph replay shape, attention medians were 8.86/8.90 us (base) and 8.74/8.80 us (fix); indexer medians were 6.94/7.07 us (base) and 7.05/6.94 us (fix). These short measurements are not a general performance claim.
