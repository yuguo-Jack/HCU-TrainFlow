# gemm(frost sm100): decline int32-compute epilogue ops without an int32 emitter

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2199) · state: open · merged: False

## Original PR description

## Problem

#2022 (G4.4) added an INT32-compute gate to the SM120 tree. The SM100 tree has none, so an epilogue op that computes in INT32 but goes through Float32-only CuTe DSL math fails inside `cute.compile` instead of declining. None of these errors is a decline type, so the default `build_plans()` walk stops at FROST instead of reaching another engine.

On a B300 (cc 10.3), develop d760fefe: a bf16 GEMM, then one pointwise op with `compute_data_type=INT32` and an int32 output, through the SM100 JIT.

| Op | develop |
|---|---|
| `cmp_lt`, `cmp_eq`, `logical_and`, `logical_not`, `floor`, `ceil`, `relu_backward` | `TypeError: floor is only supported for floating-point types` |
| `exp`, `sqrt` | `TypeError` (`exp2` / `sqrt` ... floating-point types) |
| `mod`, `pow` | `DSLRuntimeError`: the compiler could not build valid IR |
| `sigmoid` | the process dies with a segmentation fault |
| `add` with an `fp8_e4m3` / `fp8_e5m2` output, or an `fp8_e4m3` aux | `CompilerDiagnosticError`: NVVM backend compilation failed |
| `add`, `mul`, `div` | build and compute exactly |

## Change

- `sm100/compiler.py`: the SM120 tree's `_check_int32_compute`, run in `probe_chain` (so `FrostGemmEngine.check_support` and the planner see it) and in `jit_from_cudnn_graph`, next to `dtype_arch_reject`.
  - It declines an INT32-compute op outside the shared emitter's INT32 set, and an INT32-compute op that reads or writes fp8.
- One difference from the SM120 list: `div` stays served. On SM120 it returns the fp32 quotient's bit pattern (#2022). On SM100 it returns the truncated integer quotient, and the new `test_sm100_int32_div_is_exact` pins that.
- Tests in `test_epilogue_int32_compute.py`. They use a bf16 GEMM, because cc 10.3 has no int8 MMA:
  - the declines through the engine and the SM100 JIT;
  - the accepted ops, `div` included;
  - an exact INT32 `div`;
  - the fp8 edges.

## Tests

On a B300 (cc 10.3), develop d760fefe:
- `test_epilogue_int32_compute.py`: 15 failed on develop (the new declines did not raise), 31 passed, 41 skipped with this change.
- The table above, op by op, one process per case.
- `pre-commit` on the touched files passes.
