## Affected area

FE OSS kernels / CuTeDSL: SM90 block-sparse attention backward, 64-token blocks.

## Summary

This fix was motivated by intermittent NaN gradients observed in real distributed training with block-sparse attention enabled on Hopper (SM90) GPUs.

Wait at the first `PReady` barrier of each nonempty backward subtask before WG1 can reuse shared V as FP32 dV scratch. Keep the existing arrive-only behavior for subsequent iterations. Add eight regression cases covering normal execution and a test-only scheduling delay with legal, finite inputs.

## Training background and motivation

NaN gradient norms were observed during actual training in both 128-GPU and 1,536-GPU jobs, so the symptom was not limited to the largest configuration. This prompted an investigation of the SM90 BSA backward path.

In an instrumented 128-GPU training run, with no injected scheduling delay or synchronization fix, WG2 loaded a V value of approximately `-2.46e36` into its registers while the corresponding global-memory V value was `-2.359375`. The archived V tensor confirmed the latter value. The same backward call produced NaNs in dQ and dK, with the affected dK block matching the KV block where the read mismatch was detected. The archived Q/K/V/O/LSE/dO tensors were finite. These observations motivated checking whether the shared V storage could be overwritten before WG2 finished reading it.

These training observations came from a downstream integration and provide the motivation for this PR. Instrumentation can perturb scheduling even without an injected delay. The public-repository regression below independently exercises the synchronization defect on the stated upstream revision: under the same test-only scheduling delay and identical inputs, the original kernel fails and the fixed kernel passes. Those regression results are operator-level evidence, not an end-to-end training comparison.

## Why

WG1 computes P and dV. WG2 first copies V from shared memory into registers, then uses V to compute dP and subsequently dQ/dK. The dV epilogue reuses the shared V storage as FP32 scratch.

Previously, WG1 only signaled `PReady` and continued. This did not guarantee that WG2 had completed its initial V load before WG1 reached the dV epilogue. A backward subtask with a single incoming query block can reach the epilogue without the later-iteration wait that otherwise constrains execution. WG2 can therefore read overwritten storage as BF16 V, producing incorrect or nonfinite gradients even with legal, finite, aligned inputs.

WG2 already participates in the same `PReady` barrier after its initial V load. Making WG1 wait there on `pds_iter == 0` establishes the required ordering. This is the first iteration of each `(batch, head, KV block, query bucket)` subtask, not a single synchronization for the entire kernel. With the current `V_in_regs=True` implementation, later iterations reuse the register copy of V, so their notification behavior is unchanged. The fix preserves the existing barrier ID and the 256 participating compute threads.
