## Summary

Add opt-in FROST engine **20609** for d128 SDPA backward through the existing cuDNN Frontend graph API. Dense MHA supports BF16/FP16, unmasked and top-left causal attention. Exact SM100 also supports packed THD MHA and BF16 dense/THD GQA/MQA.

The main kernel computes all five attention products, using FP32 atomic dQ scratch and a final cast. Grouped attention stores BF16 per-query-head dK/dV partials and reduces them in FP32. Complete execution takes three to five launches including helpers. Dense MHA retains a one-launch, zero-workspace recompute fallback. Operand placement follows cuDNN's pipeline; no FlashAttention kernel code was copied.

Includes prepared/native bindings, declaration and workspace validation, critical numerical/replay/eligibility tests, and [API documentation](https://github.com/RomanAnders90/cudnn-frontend/blob/frost/codex-b200-bwd-d128/docs/fe-oss-apis/attention/sdpa_bwd_sm100_d128.md). All four accumulation routes use portable 512-column TMEM allocation/deallocation, which compiles with public CuTeDSL 4.8's default CUDA 12 flavor. Grouped dense declarations reject Stats/Delta spans exceeding the signed Int32 index range.

## Compatibility and validation

Existing engine IDs and public signatures are preserved. Packed/grouped paths require cc 10.0, CuTeDSL >=4.8 and positive FP32-representable scale. Packed MHA supports BF16/FP16; grouped paths support BF16 only. Grouped FP16, deterministic execution, bottom-right/sliding-window masks, bias, sinks, dropout, dense per-batch padding and dense grouped tails decline explicitly. dQ accumulation is nondeterministic; BF16 dK/dV partials introduce intermediate rounding. Caller-owned workspace is initialized on every execution.

Current host validation: **711 passed, zero failures or skips; 78 GPU cases explicitly deselected**. This includes graph and standalone acceptance/rejection around the grouped dense Stats/Delta Int32 boundary. The d128-specific modules now collect 212 cases, reduced from 466 before consolidation; all 302 pre-existing native architecture cases remain.

Public CuTeDSL 4.8 CUDA 12 compilation: the original dense route reproduces the unsupported `.exclusive` error; all four corrected accumulation routes and the unchanged recompute control compile. Accumulation mains have zero spills and retain packed FP32 arithmetic. THD setup helpers have existing compiler-dependent spills, so this is not a claim that every helper is spill-free.

Fresh GB200 execution with public CuTeDSL 4.8 / CUDA 12: **39 passed, zero failures or skips** (9 dense, 13 THD MHA, 17 grouped). This covers all four accumulation routes and the unchanged recompute control, including capture/rebinding, persistent reuse, empty sequences, opposing partials, and allocation/launch checks. Actual compiler imports and returned kernel images were verified; every worker exited and was reaped successfully.

Retained tests cover dense/THD MHA and GQA/MQA numerics, tails and empty sequences, independent origins and gaps, capture/rebinding, no execution-time allocation or host metadata reads, native argument/storage contracts, and unsafe geometry/dtype/compiler declines. Numerical tolerances are unchanged. Scoped pre-commit and whitespace checks pass. Reports, charts, generated data and plotting code are excluded from the source change.
