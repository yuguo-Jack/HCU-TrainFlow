## Affected area

FE OSS kernels or CuTeDSL

## Summary

`sdpa_bwd_sm100_d256` (the d256 / D192x128 half backward) leaves opt-in. `sdpa/bwd/heuristics._leads` ranks it **ahead of the backend** for d256 on cc 10.0, and **behind** it in every other case:
- mask-free ragged THD past S_q 4096, where the declared total is below b · S_q;
- D192x128;
- other parts;
- deterministic, bias, dropout, window and sink graphs.

The SUPPORT_MATRIX_TRACKER and the sm107 backward doc drop the opt-in wording (Rule S2).

## Why

All numbers come from a full-power B200 (1000 W, 148 SMs) against cuDNN 9.28.0.38, run through the training harness's backward pass in bf16 at 32k tokens per case. The legs were backend, FROST and default dispatch, with the opt-in flag unset for the default leg.

- **Training grid, frozen before timing, 108 cases:** d256 GQA 16/2, 32/4 and MHA 16/16; D192x128 MHA 16 / 32 / 128 heads; S 1k / 4k / 16k; causal and mask-free; BSHD, full-length THD and half-to-full ragged THD.
  - d256: FROST ran at 0.73–0.98 of the backend's time. The exception is mask-free ragged THD at S ≥ 4096, at 0.95–1.10.
  - D192x128: FROST ran at 1.08–1.91 everywhere, so it stays behind.
  - Regret (default ÷ faster leg, geo / max): 1.079 / 1.373 before, 1.001 / 1.053 with the rule.
- **Holdout, 40 seeded random cases, frozen with the training grid and run once at the frozen head `6b13e5d69`.** It adds 64/8, 32/2 and 64-head D192x128 shapes, S 512–12k and 0.75 fill.
  - Every default route matches the rule.
  - All 15 changed routes are faster than the parent default: geo 0.835, worst 0.976.
  - Regret is 1.069 / 1.290 for the parent and 1.001 / 1.074 for the head. The two cells above 1.05 are a same-plan re-measurement (default vs FROST leg, same `sdpa_bwd_sm100_d256` plan) and one mask-free ragged THD case the rule deliberately leaves on the backend.

Raggedness is read from the declared `max_total_seq_len_q`. A caller that declares capacity rather than the live total puts that corner on FROST, which measured 1.07–1.10× the backend's time.

## Related issues

Follows #1896 (`sdpa_bwd_sm100_d128` default). D192x128 backward stays behind the backend; that kernel gap is reported to the kernel owner.

## API and compatibility impact

None to the API. On cc 10.0 the default backward plan order changes for the graphs above. On every other part, and for the trailing cases, FROST's d256 plan is now offered after the backend's instead of not at all.

## Testing

- New `test_sm100_d256_leads_the_backend_only_inside_its_measured_box` checks the slot is not opt-in, LEAD for d256 dense / full THD / short ragged / causal ragged, TRAIL for mask-free ragged past 4096, D192x128, cc 10.3 and each unmeasured feature, and opt-in still putting FROST first. RED on develop, GREEN here.
