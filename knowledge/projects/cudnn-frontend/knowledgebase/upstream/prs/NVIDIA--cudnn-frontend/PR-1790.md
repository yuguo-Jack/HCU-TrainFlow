## Affected area

FE OSS kernels or CuTeDSL (FROST SDPA forward default placement; no kernel change).

## Summary

`_place_sm107_fp8` (#1684) gains a d128 arm. On exact cc 10.7, a dense per-tensor E4M3 d128 chunk (s_q < S_kv) puts FROST ahead of the backend when the GQA group is a power of two (so the Q tile packs it) and one of the following holds:

- **bottom-right causal**, s_q <= 512, and either S_kv >= 8192, or S_kv >= 4096 and S_kv >= 64 s_q;
- **mask-free**, s_q <= 128, and S_kv on the KV tile (`_synth_kv_padding` false).

Everything else at d128 keeps the backend first: squares, top-left causal chunks, unpackable groups, and the features #1684 already excludes. d192 is unchanged (backend first).

## Why

**The backend loses badly on these shapes.** On Rubin, the backend's bottom-right causal FP8 plan does not split KV at short s_q (#1788): q16 kv128k runs 737 us at both 8/1 and 64/8 heads. FROST runs the same graphs in 29 us and 101 us. That shape is decode-verify and chunked prefill, so this is the default path for those workloads.

**Placement A/B.** Same method as #1684 (`ab.py`: same graph on both arms with Amax_S virtual, CUDA-graph replay, two rounds with the arm order swapped, warm and cold L2; cc 10.7, 216 SMs, cuDNN 9.27.0.42). Lead-loss means FROST leads while slower than the backend by > 3 % warm or cold.

| set | cases | led | regret, develop -> PR | led graphs, FROST / backend | lead-losses |
|---|---|---|---|---|---|
| fit grid (s_q 16-2048, S_kv 1k-128k, 8/1, 64/8, 32/4 b4, 8/1 b8; causal-BR and mask-free) | 184 | 104 | 137.5 % -> 7.8 % | 0.04-0.97 | 0 |
| hold-out 1 (random, unaligned lengths) | 60 | 13 | 95.7 % -> 27.0 % | 0.09-0.55 | 0 |
| hold-out 2 (random, more head configs) | 100 | 29 | 82.0 % -> 23.9 % | 0.15-1.01 | 0 |
| **hold-out 3 (fresh, measured after freezing; groups 1-16 incl. 3/5/6/12)** | 100 | 30 | 78.4 % -> 23.4 % | 0.15-0.97 | 0 |

Each of the first two hold-outs changed the rule once:

- **Hold-out 1: mask-free graphs.** A mask-free graph off the KV tile cannot split and ran 2-5x slower, so mask-free now leads only on the tile.
- **Hold-out 1: s_q above 512.** Above 512, FROST's 512-row cluster doubles its wave count before the backend's does. b8 8/1 q576-768 kv13k ran 1.76x, the same at split 1/2/3/4 and with or without Stats, and recovered to 0.93 at q >= 896. Hence s_q <= 512.
- **Hold-out 1: short caches.** The KV/Q-ratio clause got a 4096 floor (b2 40/8 q29 kv3246: 1.05x).
- **Hold-out 2: GQA groups 5 and 6.** These do not divide the Q tile, run unpacked, and lost 1.3-1.75x at b > 1. Hence power-of-two groups only.

Hold-out 3 was generated and measured after the rule was frozen.

The s_q > 512 wave cliff is a FROST kernel/heuristic gap (the cluster size, not placement), as is the d192 loss at b·h_q >= 128 (1.25-1.82x). Both are left out of the lead set rather than worked around.
