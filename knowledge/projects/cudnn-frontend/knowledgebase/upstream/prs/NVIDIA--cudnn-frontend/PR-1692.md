## Affected area

FE OSS kernels or CuTeDSL

## Summary

Fix two non-finite cases in the CSA compressor's ratio=128 forward (`csa/compressor/compressor_sm100_r128.py`), whose
window softmax is computed in chunks and merged:

- A chunk with a NaN or +inf score was dropped by the merge, so the output was finite where the eager softmax gives NaN.
  The merge now skips only empty chunks (`den == 0`).
- A -inf position (for example a masked APE row) seen before any finite position computed `exp(-inf - -inf)` = NaN, so
  the output was NaN or wrong where the eager softmax gives that position weight 0. The running max now starts at the
  lowest finite fp32 instead of -inf.

On finite inputs the output is bitwise unchanged and the kernel time is unchanged. Adds a test over every forward
schedule bucket.

## Why

Each CTA splits a row's window into `tchunks` chunks; a chunk keeps a running `(m, den, acc)` and the CTA merges the
chunk partials in a fixed order. `docs/fe-oss-apis/csa.md` (Numerics, ratio=128, item 3) states that the kernels
reproduce the fp32 eager reference's non-finite propagation.

**NaN chunk dropped.** The merge skipped a partial with `if d2 > 0`, to ignore the empty previous-block half of a
segment's first block. A chunk that saw a NaN score, or a +inf score (`exp(inf - inf)`), has `den = NaN`, which also fails
`> 0`. The NaN was lost unless it was in the first chunk. Repro: one NaN or +inf score at block 1, own-half position 100,
column 0; compare `out[1, 0]` with the fp32 eager softmax:

| coff, d, blocks | develop, NaN score | develop, +inf score | this PR | eager |
|---|---|---|---|---|
| 1, 128, 64 | 0.4688 | 0.4688 | NaN | NaN |
| 2, 128, 64 | -0.3105 | -0.3105 | NaN | NaN |
| 1, 512, 64 | 0.0618 | 0.0618 | NaN | NaN |
| 1, 128, 300 | 0.1318 | 0.1318 | NaN | NaN |
| 2, 512, 2000 | 0.0425 | 0.0425 | NaN | NaN |

The merge now tests `d2 != 0`: an empty chunk has `den == 0` exactly and is still skipped, and a NaN partial is merged.

**-inf before the first finite position.** The running max started at -inf. In the online loop a -inf position does not
update the max (`s > m` is false), so it computes `exp(s - m) = exp(-inf - -inf) = NaN`; in the two-phase loop a chunk
whose positions are all -inf has max -inf and the same NaN. With APE row 0 set to -inf (the first position of every
window masked), against the fp32 eager reference, which is finite everywhere:

| coff, d, blocks | develop: NaN outputs | develop: max abs error on the finite ones | this PR: NaN outputs / max abs error |
|---|---|---|---|
| 1, 128, 64 | 8192 / 8192 | - | 0 / 0.0039 |
| 2, 128, 64 | 8064 / 8192 | 0.776 | 0 / 0.0032 |
| 1, 512, 300 | 153600 / 153600 | - | 0 / 0.0077 |
| 1, 128, 2000 (two-phase) | 0 | 0.0053 | 0 / 0.0053 |

The two-phase bucket is not affected here because its first chunk's max is finite. A chunk after the first whose
positions are all -inf had `den = NaN` and was dropped by `d2 > 0`, which happened to give the eager result; with the
merge fix alone it would make the output NaN, so both changes are needed (see Testing). The running max now starts at the lowest finite fp32: a -inf
position seen before any finite one contributes `exp(-inf) = 0`, a chunk of only -inf positions ends with `den == 0` and
is skipped by the merge, and an all -inf window gives `0 / 0` = NaN, as the eager softmax does. On finite inputs the
first finite position rescales the empty `(0, 0)` partial by `exp(lowest - s) = 0`, exactly as `exp(-inf - s)` did, so
the outputs are bitwise the same. A per-element `m == -inf ? 0 : m` guard in the exp argument fixes the same cases, but it
measured up to 12% slower in the online-loop buckets (c2 d128 1024 blocks: 41.9 -> 47.0 us), so this PR uses the initial
value instead.

The other CSA kernels apply the same rule correctly already: the ratio=128 backward and the ratio 2 / 4 kernels take the
max over the whole window before the exp and sum every partial without a skip, which matches the eager softmax for a
NaN, a +inf, a -inf at any position and an all -inf window.
