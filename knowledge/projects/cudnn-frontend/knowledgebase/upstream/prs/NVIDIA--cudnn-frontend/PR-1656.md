# benchmark/dsa: indexer + core sparse attention suite across phases, KV dtypes and paged layouts

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1656) · state: open · merged: False

## Original PR description

## Summary

Extends `benchmark/dsa` from a bf16, square-prefill, core-attention-only sweep into a config-driven suite that covers the lightning **indexer** as well as the sparse **core attention**, across:

- **phases**: `context` (prefill), `generation` (decode rows, batch × per-request kv_len × q_tokens incl. MTP), `bprop`
- **KV / index-key storage dtypes**: `bfloat16`, `mxfp8`, `nvfp4`
- **paged** variant (pool + block table; the kernels take flat ids, so paging is an id-mapping / locality change, not an API change)
- **models**: DeepSeek-V4.1-Flash (both indexer modes: `dense` and `hierarchical` = 16K-candidate consumer), GLM-5.3 / GLM-5.3-Flash, and a new opt-in Qwen3.8 QSA preset

Every (model, component, phase, dtype, paged) cell that no cuDNN FE kernel serves today is recorded as an explicit **skipped row with a reason**, decided by one pure function (`benchmark/dsa/support.py::decide_support`) in the runner before any subprocess is spawned. The nightly contract is preserved: the first 25 CSV columns, the 7-field `RESULT` line, the exit-3 skip convention and `<config>.webp` are unchanged, and `deepseek_v4` still expands to exactly the same 20 cases and labels.

## What runs today (verified on a cc 10.0 B200 and on a cc 10.7 board)

| component / phase | bf16 flat | bf16 paged | mxfp8 | nvfp4 |
|---|---|---|---|---|
| core context / generation / bprop | yes | yes | skip (no MXFP8 KV core kernel) | skip (no NVFP4 consumer) |
| indexer context / generation (dense) | yes | skip (dense keys only) | yes (Q and K e4m3 + UE8M0/32) | skip |
| indexer hierarchical (consumer) | yes (`SparseIndexerScoreRecompute` + `IndexerTopK`) | skip | skip (bf16-only) | skip |
| indexer bprop | yes | skip | skip | skip |
| Qwen3.8 QSA (all cells) | skip: no servable QSA kernel in this suite | | | |

Servable rows are identical on cc 10.0 and cc 10.7 (both map to the same kernel bodies): deepseek_v4 20/20 (legacy, unchanged), deepseek_v41 80/324, glm53 118/384, qwen38_qsa 0/168 (coverage rows, opt-in; not in `run_all.sh`'s default list). Full sweeps of the committed code: B200 612 rows → 120 success / 492 skipped / **0 failed**; cc 10.7 board all four configs, 896 rows → 218 / 678 / **0 failed**.

## Measurement notes

- Core TFLOPS are counted on the ids actually gathered (`sum(topk_length)`). Context and bprop rows keep full id lists over the whole KV range (the legacy meaning and the kernel's indexer-prefix contract); only generation rows use causal lists. Full lists cost the 32k core bprop ~18 % vs. causal lists at equal FLOPs (27.9 vs 23.6 ms on B200, reproduced on a re-run — the bwd scatter loses locality), so the table below supersedes the first-draft numbers.
- Generation rows run the prefill kernel as flat rows (one CTA per query row, no split-KV) and report `gather_gbps` on footer-inclusive bytes; this is labelled in `backend_detail`.
- Hierarchical rows time the consumer step (candidate-restricted scoring + top-k 512); the source layer's block top-k is not a cuDNN kernel and is not timed.
- mxfp8 indexer rows quantize Q and K (the kernel contract); bytes/token columns report the production storage formats (288/324/528/594/1024/1152 B records, 68/132/256 B index keys).
- `<config>_extended.webp` (one panel per component × phase) encodes a variant structurally — colour = KV dtype (second tone for a config's second model), lighter tint = paged, dotted hatch = hierarchical indexer, dashed edge = deterministic bwd — so styles never cycle, and its legend lists only variants with a served bar plus one hatched "skipped / failed" entry (second commit; the legacy `<config>.webp` is untouched).

## Tests

- `python -m unittest discover -s benchmark/dsa/tests -v` — CPU-only contract tests (legacy pin, enumeration, skip matrix on cc 9.0/10.0/10.3/10.7, bytes/FLOP constants, id generators, RESULT parsing, CSV schema, charts).
