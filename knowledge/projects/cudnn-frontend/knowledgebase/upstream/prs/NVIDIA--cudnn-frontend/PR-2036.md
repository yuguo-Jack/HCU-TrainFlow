## Summary

The grouped persistent scheduler of the four SM120 MoE templates now converts its warp ballot to `Uint32` before the bit reverse and bit find that pick the winning lane:

```python
winning_lane = cutlass.Int32(31) - cute.arch.bfind(cute.arch.brev(cutlass.Uint32(thread_succeed))).to(cutlass.Int32)
```

`cute.arch.bfind` then emits `bfind.u32` instead of `bfind.s32`. For each of the four kernels (bf16 and NVFP4, both orientations), the PTX differs from develop in this one instruction only.

Two tests (four cases) are added. `gemm_test_utils.py` gains `keep_kernel_ptx` / `kernel_ptx`, which compile a plan with `--keep-ptx` (persistent compiled cache off; PTX files and generated sources under the test's tmp dir) and read the PTX back, and `brev_bfind_types`, which lists the type of every `bfind` that reads a `brev.b32` result in the same PTX function.

## Why

The scheduler warp finds the group that holds a claimed tile with a ballot over 32 consecutive groups. The groups' prefix ends never decrease, so the ballot is a suffix mask and the winner is its lowest set lane, computed as `31 - bfind(brev(ballot))`. The ballot is an `Int32` (`nvvm.vote_sync(..., BALLOT)`), `brev` keeps the type, and `cute.arch.bfind` emits `bfind.s32` for an `Int32` operand. `bfind.s32` returns the position of the highest bit that differs from the sign bit. When every lane succeeds (lane 0 wins: ballot `0xFFFFFFFF`, `brev` gives -1) it returns `0xFFFFFFFF`, and `winning_lane` is `31 - (-1) = 32`.

Lane 0 wins on most launches: the CTA that claims tile 0 takes this path whenever group 0 has rows, and so does a claim that falls in the first group of a later 32-group window. Any other claim that finds its group is won by a higher lane; bit 0 of the ballot is then clear, `brev(ballot)` is non-negative, and `bfind.s32` already returned the right lane. The six `shfl.sync.idx` reads of the winner's state (group, begin, end, start, tile count, and the next scan base or SF start) still read lane 0, because `shfl.sync` uses only the low 5 bits of the lane operand. Outputs are therefore correct today, but `winning_lane` is outside `[0, 31]`, the range the CuTe DSL documents for a `shfl_sync` source lane. Any other use of the value (a compare, an index, a different clamp) would be wrong.

Reproducer on an RTX PRO 6000 (SM120): a CuTe DSL kernel in which warp `w` votes the suffix ballot `lane >= w`, then evaluates the template's expression next to the unsigned one and reads `lane_idx` back through `shfl.sync.idx`:

```
lowest winning lane  0: template winning_lane= 32 shfl src= 0 | unsigned winning_lane= 0 shfl src= 0
lowest winning lane  1: template winning_lane=  1 shfl src= 1 | unsigned winning_lane= 1 shfl src= 1
lowest winning lane 31: template winning_lane= 31 shfl src=31 | unsigned winning_lane=31 shfl src=31
```

In the templates themselves, for example the bf16 MoE grouped matmul with 34 groups (S = 421, N = K = 128, `CONFIG_sm120_128x128x128_16x16x32_cluster1x1_warps4x2`), the kernel PTX on develop has `bfind.s32 %r812, %r813;` followed by `sub.s32 ..., 31, %r812;`. The swap-AB template and both NVFP4 block-scale templates have the same instruction. Expected is `bfind.u32`.

`bfind.u32` of `brev(ballot)` is the position of the highest set bit, that is `31 - (lowest set lane)`, so the expression returns the lowest set lane for every non-zero ballot (0 for an all-lanes ballot). `32 - popc(ballot)` would also give the right lane, but only while the ballot is a suffix mask; the unsigned bit find does not depend on that. With a decreasing `first_token_offset` (invalid input) the ballot need not be a suffix mask. When lane 0 succeeds in such a ballot, the signed form picked the lowest failing lane (ballot `0x5`: lane 1), while the unsigned form picks the lowest succeeding lane (lane 0), which is the group the scan is looking for. When lane 0 fails, the two forms agree.

The linear-attention Frost code already writes this search on an unsigned word: `python/cudnn/linear_attention/frost/common/gdn2_state_grad.py:73-75` converts its ballot word to `Uint32` before `brev` / `bfind`.

Found in an audit of the SM120 Frost kernel templates (finding B36).
