# Overlap dS stores in fused D192 THD backward

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1976) · state: closed · merged: True

## Original PR description

The fused D192 THD backward kernel drained each dS TMA store before loading the next Qdk operand, despite having a two-slot transfer ring. Keep one store in flight and return each slot's reuse credit only after both its TMA store and dK MMA readers finish. Drain the final slot at every work-item boundary, preserving ring phases across work items.

This changes only the fused THD path with at least two transfer slots. Workspace size, launch count, accumulation order, graph eligibility and public APIs are unchanged.

Validation on the candidate kernel:

- 12 existing B200 tests and 12 native SM107 tests pass without skips, covering FP16/BF16, compact and physical-origin THD, ordinary/deterministic execution, FP64 gradient references, changed lengths, poisoned outputs, rebinding and retained CUDA Graph replay.
- Two native cases each pass memcheck, synccheck and racecheck with zero errors, hazards or warnings.
- Scoped pre-commit passes. The rebased source tree matches the native-qualified source files, and the B200-qualified kernel is byte-identical.

B200 performance evidence is limited to warm CUDA Graph replay of BF16, H16, D192/V128, half-to-full THD, on a production 148-SM B200 at its 1000-W power limit, driver 615.71.09, Torch 2.14.1+cu130, CuTe DSL 4.8 and cuDNN 9.28. Baseline and candidate use identical buffers and workspace; both build orders include an unchanged-source control and independent gradient/replay checks.

|---|---|---:|---:|---:|---:|

These medians use 64 warmup graph replays and 36 samples balanced across all six execution orders of baseline/candidate/control. The short case remains variable. An earlier four-case causal/mask-free sweep had larger control movement (up to 3.08%) and retained a +0.38% long-causal regression in one build order. This is a small overlap improvement; the long mask-free backend performance and workspace gaps remain open. No serving-throughput claim.
