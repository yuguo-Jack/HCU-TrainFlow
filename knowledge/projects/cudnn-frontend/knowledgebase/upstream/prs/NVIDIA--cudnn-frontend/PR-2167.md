# Admit explicit native SM80 attention tiles in graph plans

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2167) · state: closed · merged: True

## Original PR description

SM80 graph plans currently reject explicit `TILE_M`, `TILE_N` and `TILE_CGA_M` even when the native standalone adapter supports the requested geometry. Admit the bounded native tile domains through the public graph plan API, sharing flavor selection with the adapter. This makes configurations such as D192/V128 M64/N64 selectable by graph callers.

Keep implicit A/FALLBACK proposals unchanged. D256 N128 stays outside graph admission because its double buffers exceed A100 shared memory; wide heads retain their fixed M32/N16 tile and SM80 permits only CGA1. Existing feature/layout/scheduler gates remain in effect.

Validation:
- A100: 149 focused tests pass, including 22 native graph cases covering public knob roundtrip, selected geometry, full output/LSE reference, changed bindings and CUDA Graph replay, plus existing standalone geometry tests.
- 82 metadata-only checks pass without initializing CUDA; four explicit requests fail on the parent and pass with this patch.
- 72 A/FALLBACK proposal lists exactly match the parent.
- Scoped pre-commit hooks pass. The configured SM80 FROST CI entry collects the new test file.

This changes only explicit knob admission and shared metadata selection; kernel arithmetic and default heuristics are unchanged. Per SDPA Rule S2, the knob-domain-only change does not require a support-matrix update.
