## Affected area

FE OSS kernels or CuTeDSL

## Summary

Compile out redundant head-bound predicates from the SM100 DSA D576 two-CTA backward kernel when the head tile is fully populated by H128. H96 continues to use the existing runtime head checks for its partial tile.

## Why

The D576 two-CTA backward kernel was generalized from H128 to deterministic H96 in #1734. The H96 tail checks remained as runtime predicates in generated H128 code even though all 128 heads are active.

On the packed Top-K 2048 training workload, these predicates regressed H128 nondeterministic backward by 1.13%–1.18%. Nsight isolated the regression to the main two-CTA kernel: launch geometry, 96 registers per thread, shared-memory use, and occupancy were unchanged, while executed instructions increased by 2.38%–3.15%. The zero-init and dKV conversion kernels were unchanged.

This change guards each hot-path bounds check with the compile-time full-tile condition:

```python
cutlass.const_expr(self.num_heads == self.H_TILE_CLUSTER) or head < Int32(self.num_heads)
```

CuTeDSL therefore removes the predicate from generated H128 code while preserving the H96 tail checks.

## Related issues

Related to #1734.

## API and compatibility impact

There are no public API, dispatch, supported-shape, numerical-operation, or workspace-sizing changes.

The change applies to the shared H128/H96 D576 two-CTA kernel. H128 deterministic and nondeterministic paths compile out the redundant predicates. H96 deterministic retains its runtime head guards. H96 nondeterministic dispatches to the separate `h96_h64_h32` kernel. H32, H64, H128 D512, and generic paths use other kernels.

Measured on one NVIDIA L20D (SM103, 148 SM), CUDA 13.0, PyTorch 2.12.1, cuDNN 9.20, and cuDNN Frontend 1.32.0. Inputs were BF16 with Dqk=576, Dv=512, Top-K=2048, and packed KV segments `[27726, 17644, 12603, 7563]`. Each result combines two interleaved runs per revision, with 10 warmups followed by 8 blocks of 20 iterations per run.
