# sdpa: add UnifiedSDPABackwardNode and route backward through the SDPA support surface

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/895) · state: open · merged: False

## Original PR description

## Scope and plan

This is the single frontend PR for the non-FP8 part of the unified SDPA backward work (internal plan doc "Unified SDPA Backward Parity Plan", nvbugs 5102117). The backend side lands as a few cuDNN MRs: first cleanup plus SM80/SM90 support with heuristics reachability (MR !4388), then feature parity with the composite path (masks, bias, dropout, padding, ragged, deterministic), then FP8. This PR stays in draft while the first two land and the UNIFIED surface in `sdpa_support_surface.h` is widened here as each backend feature becomes available (masks, bias/score_mod, dropout, padding/ragged, deterministic, Stats strides, mixed head dims). When it leaves draft it enables everything the backend supports at that point; FP8/MXFP8 backward (including merging the FP8 backward attributes into `SDPA_backward_attributes`) is the only other planned frontend PR.

## Summary

Frontend counterpart of the unified SDPA backward work (nvbugs 5102117), paired with cuDNN backend MR !4388.

Mirrors the forward-side design for SDPA backward:

- `SDPABackwardNodeBase<Derived>` is the shared base; `CompositeSDPABackwardNode` keeps the existing graph lowering and the new `UnifiedSDPABackwardNode` emits a single `CUDNN_BACKEND_OPERATION_SDPA_BWD_DESCRIPTOR`.
- All implementation-independent backward validation moves out of the composite node into `SDPA_backward_attributes::validate_sdpa_backward_support_surface` in `sdpa_support_surface.h`, alongside the forward surface. Per-implementation capability lives in `verify_sdpa_backward_support_surface_for_implementation`.
- `SDPA_backward_attributes::set_implementation(AUTO | COMPOSITE | UNIFIED)`, serialized in the graph JSON. AUTO tries UNIFIED first and falls back to COMPOSITE.
- UNIFIED backward surface (cuDNN >= 9.27): dense FP16/BF16 Q/K/V/O/dO/Stats + attn_scale -> dQ/dK/dV, arbitrary Q/K/V/O/dQ/dK/dV strides, GQA/MQA. No masks, bias, dropout, padding, ragged offsets or deterministic mode yet. Arbitrary Stats strides are accepted too (the backend MR fixed the engine's dot(dO,O) descriptor; fuzzed Stats layouts pass on all three arches). Mixed head dims (including d_qk=192/d_v=128) go through the unified path; the backend MR fixes the engine's d_v sizing for them.
- Python: `sdpa_backward(..., implementation=...)`, new `test_sdpa_random_bwd_unified_L0` (fuzzed Q/K/V/O/Stats layouts, GQA, d 8..128, s up to 2048); `fp16.py` forwards the configured implementation and waives UNIFIED training on cuDNN < 9.27.
- `docs/operations/Attention.md` documents the option.

The FP8 backward attributes are intentionally not merged into `SDPA_backward_attributes` yet; that is deferred to the FP8 frontend PR, once the backend FP8 unified backward MR exists.

## Testing

Against the MR !4388 backend build (cuDNN 9.27.0 dev):

- `test_sdpa_random_bwd_unified_L0`: 128/128 pass on A100, H100 and SM100.
- The same cases with `--implementation AUTO` and `--implementation COMPOSITE` pass on H100 (composite paths exercise the moved validation).
- Rebased onto develop 902c1a778 (2026-09-10); with that base the unified sweep is again 128/128 on all three GPUs, and the first four `test_sdpa_random_bwd_L0` seeds (269 cases, AUTO) pass on H100, including the d_qk=192/d_v=128 GQA case, which now runs through the unified engine on H100 and SM100 with the fixed backend.

## Second widening: padding, ragged layouts, offset multipliers, cumulative lengths (MR !4476)

Two more commits, paired with cuDNN backend MR !4476 (cuDNN 9.28 dev; the version floor is still to be finalized):

- On SM100-class devices the UNIFIED backward surface now admits `padding_mask` with `SEQ_LEN_Q`/`SEQ_LEN_KV`, ragged (THD) offsets on every tensor, `max_total_seq_len_*` and ragged offset multipliers. Other architectures keep rejecting them until the backend engines catch up.
- `SDPA_backward_attributes` gains `CU_SEQ_LEN_Q` / `CU_SEQ_LEN_KV` (`set_cu_seq_len_q/kv`), mirroring the forward: b + 1 entries per side, mutually exclusive with the per-batch form, either form per side. The unified node lowers them to the new `CUDNN_ATTR_OPERATION_SDPA_BWD_CU_SEQ_LEN_{Q,KV}DESC`; the composite implementation rejects them explicitly; the padding-mask validation accepts either form.
- Python: `sdpa_backward(..., cu_seq_len_q=..., cu_seq_len_kv=...)`. Test library: the backward graph carries the ragged offset multiplier on Q/K/V/O as well as the gradients (the tables are shared), and passes `cu_seq_len_*` when configured; `test_sdpa_random_bwd_unified_L0` now draws ragged, ragged_mult, cu_ragged, cu_ragged_mult, padded, cu_padded and full layouts.

Testing against the MR !4476 backend build on SM100: `test_sdpa_random_bwd_unified_L0` 128/128 (42 cumulative-length cases, 13 of them with multipliers); `test_sdpa_random_bwd_L0` + `test_sdpa_random_bwd_ragged_L0` with UNIFIED 534 passed; composite sweeps unchanged on SM100 (840), H100 (763) and A100 (138); on H100 the unified sweeps waive the new layouts as designed (355 passed / 285 skipped).

## Third widening: SM8x/SM9x layouts, sink, masks and score modifiers, dropout, deterministic (MR !4476, commits 6-10)

Two more commits, paired with the later commits of cuDNN backend MR !4476 (cuDNN 9.28 dev line; version floors still to be finalized):

- **Layouts / sink / masks** (`c8d32e961`): the UNIFIED backward surface admits padding, ragged (THD) layouts, offset multipliers and cumulative lengths on SM8x and SM9x as well as SM10x; `SINK_TOKEN` / `DSINK_TOKEN`; `Bias` (without `dBias`, which has no unified backend counterpart yet); alibi, diagonal-band masks (causal, bottom-right, sliding window) and a forward `score_mod` (replayed on the recomputed scores; `score_mod_bprop` still routes to the composite node). `UnifiedSDPABackwardNode` lowers alibi like the unified forward (slopes in the FE workspace). The SM8X/SM12X "ragged Stats not supported" rule is scoped to the composite path.
- **Dropout and the deterministic algorithm** (`05067cace`): `Seed` / `Offset` admitted and forwarded as `CUDNN_ATTR_OPERATION_SDPA_BWD_DROPOUT_*`; `use_deterministic_algorithm` served on SM9x (kv-ordered dQ workspace reduction) and SM10x (dK/dV kernel + dQ kernel) by pinning the unified backward engine with its `STAGES` knob in `override_heuristics_query()`. Not available on SM8x/SM12x, nor on SM10x with a bias or with `d > 128` (no 2-CTA split kernels yet) — those graphs stay on the composite path under AUTO.
- **Tests:** `test_sdpa_random_bwd_unified_L0` draws sink, alibi, bias, band masks, bottom-right alignment, dropout and the deterministic algorithm. With dropout the forward runs on AUTO (the unified forward does not generate Stats with dropout) and `cfg.bwd_implementation` pins only the backward; sink and dropout are kept apart (that combination mismatches the reference on the composite engine too). `sdpa/fp16.py`: the `dBias` checks key on whether the graph has a `dBias` tensor; forward graphs that no AUTO implementation supports are waived. New: `test_sdpa_custom_features.py::test_sdpa_dropout_bwd_unified`, `test_flexible_sdpa_bprop.py::test_sdpa_bprop_with_causal_score_mod_vs_reference` (composite vs unified, torch reference).

Testing against the MR !4476 backend build: unified backward L0 on A100 58 / L40S 58 / H100 87 / SM100 73 passed (the rest waived as unsupported on the arch), unified dropout tests pass on all four, deterministic reruns are bitwise identical on H100 and SM100.

## Follow-ups (commits 8-10)

- `2642401e9` test: the unified backward L0 draws the sink token together with dropout (the pair was drawn by no sweep and hid a scaled dSink and a mis-weighted SM100 forward sink, both fixed in MR !4476), and `test_sdpa_dropout_with_sink_token` covers it directly (AUTO and pinned unified backward, s = 92 exercises the SM100 short-sequence engine choice).
- `056873c8c` allow a bias with the deterministic algorithm on SM10x (the split kernels address the bias correctly now).
- `6da57fcf1` d = 256 on SM10x runs on the unified backward as the three-kernel (2-CTA) plan, pinned whether or not determinism was requested, like the composite node forces determinism for d = 256 on Blackwell.

- `c56129e48` SDPA backward validation: ragged offsets require a padding mask, mirroring the forward rule. The backward engines' dQ downcast and full-head reductions take their ragged paths only when the per-sequence lengths are present; no current caller hits this (every THD caller passes the lengths).

## Fourth widening: dBias and the deterministic algorithm on every architecture

Two more commits, paired with the next backend changes (cuDNN 9.28 dev line). They supersede the notes above that dBias has no unified counterpart and that the deterministic algorithm is not available on SM8x/SM12x.

- **dBias** (`6777be83f`): the unified node passes a `dBias` output to the new `CUDNN_ATTR_OPERATION_SDPA_BWD_DBIAS_DESC`, and the support surface accepts it together with `Bias`. The backend serves it on its SM80/SM90 engines (the SM80 one on Blackwell-class devices) through a dS workspace and post-kernel dQ / dBias reductions, as the composite path does; ragged layouts and cumulative sequence lengths with dBias stay on the composite path.
- **Deterministic algorithm** (`80734a142`): SM8x / SM12x pin the SM80 engine with `STAGES = 2` (the dS workspace, no dQ atomics). On SM9x, `STAGES = 2` is now the default too, like the composite node's dP-workspace path; the kv-ordered dQ reduction (`STAGES = 4`) is used for ragged layouts and when `CUDNN_FRONTEND_ATTN_DP_WORKSPACE_LIMIT` caps the workspace below its requirement, the same opt-in as the composite node. The ordered reduction serializes per (batch, head) and was up to ~5x slower than the composite path on H100 for long causal sequences.
- **Tests:** `test_sdpa_random_bwd_unified_L0` requests `dBias` for half of its bias draws; new `test_sdpa_dbias_bwd_unified` (fp16 / bf16, no mask / causal, square and non-square sequences) against the reference dBias.

Testing against the matching backend build on A100, L40S, H100 and SM100: unified dQ / dK / dV / dBias are bitwise identical to the composite path for dBias graphs; deterministic reruns are bitwise identical on all four GPUs and match the composite deterministic output; unified backward L0 passed A100 58 / L40S 58 / H100 80 / SM100 68 with no failures (the deterministic draws now run on all four instead of being waived); dropout, dBias, flexible-backward and unified-forward tests 157/157 (189/189 on SM100).
