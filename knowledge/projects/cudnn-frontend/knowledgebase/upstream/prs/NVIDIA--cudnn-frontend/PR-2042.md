## Affected area
- FE OSS kernels or CuTeDSL

## Summary

- Extend the native SM100/SM103 H96 DSA backward path to static Top-K widths 2049–2051, in both ordinary and deterministic modes.
- Add aligned, zero-filled 16-byte index staging for Top-K widths that are not multiples of four.
- Preserve the existing compact path and shared-memory layout for aligned Top-K widths.
- Add dispatch, numerical-gradient, and deterministic bitwise-repeatability coverage for Top-K 2048–2051.

## Why

With `kpool=4` DSA, selecting 2048 tokens can produce an effective Top-K width of 2048–2051 after including the current pooling-block tail.

The existing H96 dispatch only admitted selected aligned widths, so 2049–2051 fell back to the H64+H32 path.

Simply extending the dispatch whitelist is unsafe: these widths can produce unaligned row addresses and a partial final index vector for the existing 16-byte `cp.async` loader. This change aligns the source address down, stages one additional zero-filled vector when needed, and applies a logical prefix offset when consuming the indices.


## Related issues

None.

## API and compatibility impact

- No public API or signature changes.
- Native coverage is expanded only for contiguous BF16 H96, D576/V512 backward on supported SM100/SM103 devices.
- Top-K 2048 and other aligned shapes retain the existing staging specialization.
- Unsupported devices, layouts, data types, and head dimensions retain their existing fallback behavior.
- The unaligned specialization adds 32 bytes of shared memory; aligned shapes are unchanged.
