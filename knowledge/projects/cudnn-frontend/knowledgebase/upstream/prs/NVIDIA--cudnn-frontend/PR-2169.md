# nsa: decline cc 12.x in the top-k reduction and compression attention gates

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2169) · state: closed · merged: True

## Original PR description

## Problem

`NSA.TopKReduction` and `NSA.CompressionAttention` build tcgen05 kernels, but `check_support()` gated on `compute_capability < 100`. A cc 12.x part (RTX / workstation Blackwell) reports a major above 10 and passes that gate, so the plan is admitted and the kernel then cannot build. This is the same defect #2166 fixed for the CuTe DSL GEMM APIs.

Evidence on a B300:

- **The gate admits cc 12.0.** With the capability reported as `(12, 0)` to `check_support()` only, both plans return True on develop, and their kernels then build and run natively.
- **The kernels cannot build for cc 12.x.** I kept their PTX (`CUTE_DSL_KEEP=ptx`) and assembled it with ptxas (CUDA 13.3, `.version` lowered from 9.4 to 9.3 for that ptxas). It assembles for `sm_103a`. For `sm_120a`, ptxas rejects it with `Feature '.32x32b' not supported on .target 'sm_120a'` and `Feature '.collector::a::discard' not supported on .target 'sm_120a'`, for both kernels.

## Change

Both gates call `has_tcgen05(major)` (from #2166) in place of the bare threshold. Their messages say "with tcgen05 (not cc 12.x)", and the exception type is unchanged. cc 10.x and 11.x are admitted exactly as before.

## Tests

New L0 file `test/python/native_sparse_attention/cutedsl/test_NSA_arch_gate.py`. For each plan, it builds the plan the way the existing compile/execute tests do, reports cc 12.0 to `check_support()`, and expects the gate's `RuntimeError`.

On a B300:

- **Develop:** both cases fail.
- **With this change:** the whole `test/python/native_sparse_attention` at `-m "L0 or L1"` gives 33 passed, 2 skipped, 0 failed.
