# Fix stream ownership and ordering in GPU regression tests

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1807) · state: closed · merged: True

## Original PR description

Two existing GPU tests can fail under valid stream state: the retention test tries to capture the session handle's default stream, and the QSA multi-device test launches on a side stream before its output sentinel fills are ordered. These appeared in the broad CI run for #1806, whose graph-dispatch changes are not on either failing path.

Give the retention test its own non-default capture stream and restore the handle afterward. Order both QSA output initializations before their side-stream consumers. This only changes tests and their guide; numerical tolerances, kernels and public behavior are unchanged.

Validation on native H100 with a second visible L40S:
- Both the original baseline and #1806 reproduce the same three failures when the handle is deliberately left on the default stream and producer-stream output fills are delayed. The implicit-stream QSA control passes.
- The repaired tests pass all four cases under that same controlled ordering, and all four pass without the diagnostic instrumentation.
- The complete capture-lifetime file plus the two QSA multi-device cases: **10 passed**.
- Scoped formatting and license hooks passed. The private delay probe is diagnostic only; no timing assertion or extra heuristic test is added.
