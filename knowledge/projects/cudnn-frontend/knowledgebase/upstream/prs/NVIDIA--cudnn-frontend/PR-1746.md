# Honor compute_data_type when lowering unified SDPA

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1746) · state: closed · merged: True

## Original PR description

Unified SDPA currently accepts the frontend's compute-type setting without forwarding it to the backend descriptor. An explicit or inherited `HALF` request can therefore be silently lost. This change preserves the historical `FLOAT` behavior and forwards non-default requests when the backend attribute is available; otherwise it fails explicitly.

## Affected area

C++ frontend graph construction and unified forward SDPA backend lowering, shared by the existing Python graph API; attention documentation.

## Summary

- Use the existing `SDPA_attributes::set_compute_data_type()` / Python `compute_data_type` setting when constructing the unified forward SDPA descriptor.
- Preserve operation-level override and graph-level inheritance. If both are unset, use `FLOAT`.
- Reject accumulation types other than `FLOAT` and `HALF`.
- For a non-default request, set `CUDNN_ATTR_OPERATION_SDPA_FWD_COMP_TYPE`, guarded by the header version, `CUDNN_HAS_SDPA_FWD_COMP_TYPE`, and a runtime backend-version check.
- Document the API, compatibility behavior, and current implementation limit in `docs/operations/Attention.md`.

## Why

Q/K/V/O storage dtype does not identify the requested accumulation precision. A graph with FP16 or BF16 tensors may still require FP32 accumulation. The existing frontend compute-type setting needs to retain its meaning through unified descriptor construction, including when the requested precision is unsupported.

For example, a graph-level `HALF` request now reaches the new backend attribute or produces an error. An explicit operation-level `FLOAT` override continues to work with older headers and libraries.

## API and compatibility impact

No new public setter, Python parameter, or binding is introduced. Both C++ and Python use the existing compute-type API.

| Request | Behavior |
| --- | --- |
| Graph and operation compute types unset | Use the historical FP32 default |
| Inherited or explicit `FLOAT` | Preserve compatibility; do not require the new backend attribute |
| Inherited or explicit `HALF` | Forward the attribute when supported; otherwise return an error |
| Explicit `FLOAT` over graph-level `HALF` | Honor the operation override |
| `BFLOAT16` compute type or another unsupported type | Reject explicitly |

**Backend dependency and current limit:** this uses the companion development-backend definition of `CUDNN_ATTR_OPERATION_SDPA_FWD_COMP_TYPE` and its `CUDNN_HAS_SDPA_FWD_COMP_TYPE` capability macro. The implementation checks `CUDNN_VERSION >= 92900` at compile time and backend version 92900 at runtime, and additionally requires the capability macro because version alone does not establish that the development headers contain the enum. No numeric attribute value is invented. The release/version gate should be confirmed when the backend API is assigned to a release.

The matching development backend currently rejects `HALF` at descriptor finalization because an FP16-accumulator kernel is not implemented. This PR establishes the precision contract and explicit rejection; it does not enable reduced-precision accumulation or claim a performance improvement. Existing executable kernels retain FP32 accumulation, softmax reductions, and statistics. Composite and backward SDPA are unchanged.

Expected: the four unset/FLOAT cases succeed, the two HALF cases fail explicitly, and BFLOAT16 compute is rejected. The exact HALF error depends on whether rejection happens at the frontend header gate, backend attribute assignment, or backend descriptor finalization.

```cpp
#include <cudnn_frontend.h>
#include <iostream>
#include <stdexcept>
#include <string>

namespace fe = cudnn_frontend;

int main() {
    cudnnHandle_t handle = nullptr;
    if (cudnnCreate(&handle) != CUDNN_STATUS_SUCCESS) return 2;
    struct Case { const char* name; fe::DataType_t graph_type, op_type; bool success; };
    using D = fe::DataType_t;
    const Case cases[] = {
        {"both unset", D::NOT_SET, D::NOT_SET, true},
        {"inherited FLOAT", D::FLOAT, D::NOT_SET, true},
        {"explicit FLOAT", D::FLOAT, D::FLOAT, true},
        {"explicit HALF", D::FLOAT, D::HALF, false},
        {"inherited HALF", D::HALF, D::NOT_SET, false},
        {"FLOAT overrides HALF", D::HALF, D::FLOAT, true},
        {"invalid BFLOAT16", D::FLOAT, D::BFLOAT16, false},
    };
    for (auto const& c : cases) {
        fe::graph::Graph graph;
        graph.set_io_data_type(D::HALF).set_intermediate_data_type(D::FLOAT).set_compute_data_type(c.graph_type);
        auto q = graph.tensor(fe::graph::Tensor_attributes().set_name("Q").set_dim({1,8,128,64}).set_stride({65536,64,512,1}));
        auto k = graph.tensor(fe::graph::Tensor_attributes().set_name("K").set_dim({1,2,256,64}).set_stride({32768,64,128,1}));
        auto v = graph.tensor(fe::graph::Tensor_attributes().set_name("V").set_dim({1,2,256,64}).set_stride({32768,64,128,1}));
        auto options = fe::graph::SDPA_attributes().set_name("precision")
            .set_generate_stats(false).set_attn_scale(0.125f)
            .set_implementation(fe::AttentionImplementation_t::UNIFIED).set_compute_data_type(c.op_type);
        auto [o, stats] = graph.sdpa(q, k, v, options);
        o->set_output(true).set_dim({1,8,128,64}).set_stride({65536,64,512,1});
        auto status = graph.validate();
        if (!status.is_good()) {
            std::cerr << "VALIDATE FAILED " << c.name << ": " << status.get_message() << '\n';
            cudnnDestroy(handle);
            return 3;
        }
        status = graph.build_operation_graph(handle);
        std::cout << c.name << ": " << (status.is_good() ? "accepted" : "rejected") << " " << status.get_message() << '\n';
        if (status.is_good() != c.success) { cudnnDestroy(handle); return 4; }
    }
    cudnnDestroy(handle);
    std::cout << "PASS: frontend precision inheritance, override, default and rejection\n";
}
```
