## Affected area

FE OSS kernels or CuTeDSL (FROST SDPA forward heuristics and placement).

## Summary

Follow-up to #1468.

- **Packing.** On nonpaged SM100/SM103, `_prefer_thd_pack_gqa` now also packs GQA2, so the first plan for causal d128 half THD is packed. #1468 did the same for GQA16.
- **Placement.** GQA2 joins the unsplit packed lead with one extra gate: declared `S_kv >= 4096`. All of #1468's gates still apply.

## Why

Setup: B300 SXM6 (148 SMs), cuDNN 9.27.0.42, CuTeDSL 4.8.0, with FlashInfer-style declarations as in #1468. The GQA2 set has 72 cases: a 32-case grid (H 8-64, B 1-32, Q 128-2048, KV 1k-8k) and a 40-case random hold-out.

- **Packed against unpacked, both unsplit:** packed matched or beat unpacked on every case. It helped most at large batch, for example 1.58 -> 0.94, 1.78 -> 0.96 and 2.17 -> 1.26 of the backend.
- **Packed against the backend:**
  - At KV >= 4096, 0.53-0.97, with no loss.
  - On a 1-2k cache, large batches lost: B32 Q1024 KV1024 1.19x, B32 Q64 KV2048 1.26x, B27 Q228 KV1k 1.14x. Hence the KV gate.
- **Final code on the device:** I re-ran 206 THD cases (the GQA2 sets plus #1468's grid, hold-out and small-launch sets), timing the backend against the default pick. There were 75 unsplit leads and no lead slower than the backend by more than 3% (warm, cold or eager). The only case above 3% is an existing GQA1 split from #1452 at parity (`v05`, 1.01 / 1.03 / 1.04).
- **B200:** the earlier #1468 GQA2 data agrees. Its slowest packed case at KV >= 4096 was 1.01 (`u13`).

Not changed: GQA2 at KV < 4096 keeps the backend first, even though some of those cases win at 0.7-0.94.

## API and compatibility impact

The default `PACK_GQA` changes for nonpaged SM100/SM103 GQA2 causal d128 half THD graphs, and their placement changes at KV >= 4096. Explicit knob records behave as before.

## Testing

- Heuristics / placement / split-KV / analyzer host tests: 1633 passed, 2 skipped.
- #1468's invariant test (a lead always has a legal packed first plan) now covers GQA2.
