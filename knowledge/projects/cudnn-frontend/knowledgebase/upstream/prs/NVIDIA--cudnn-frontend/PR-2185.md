## Affected area

FE OSS kernels or CuTeDSL

## Summary

Add a separate native Hopper D64 FP16/BF16 forward body for exact dense D_QK=D_V=64. QK and PV each use four `m64n64k16` WGMMA steps, with one producer warpgroup and one compute warpgroup (256 threads), one shared P tile and a full 64-column output fragment. This avoids the D512 instruction geometry for D64.

Reuse the existing Hopper TMA/map builder, sign-aware online softmax and prepared pointer host. Select the new template through the existing SM90 engine identity, keep D64 backend-first, and preserve the D512 envelope and placement. Retain the existing D512 path for standalone declarations outside the native D64 subset. Add admission, code-generation, prepared ABI and Hopper-only numerical/rebinding/capture regressions.

## Why

The existing SM90 graph row serves the large D512 envelope. A native small-head implementation needs its own instruction geometry, shared storage and barrier arrivals before its domain can be admitted.

Related to #378.

## API and compatibility impact

No public signature or SM80 architecture gate changes. The bounded addition supports dense exact-D64 FP16/BF16 MHA and unpacked GQA, optional natural/base-two Stats, noncausal/top-left/bottom-right causal masks, and the existing single-CTA schedulers. Literal zero and negative scales retain the sign-aware softmax path.

THD, device lengths/padding, sinks, window/right bands, PackGQA, paging, split-KV and quantized types remain outside the native D64 body and graph scope. Standalone declarations already supported by the D512 envelope retain that path; the native feature predicate selects a template rather than rejecting them. The existing refusal of unpadded bottom-right S_q>S_kv is preserved and mirrored in the new D64 graph admission/template compiler. Smaller or unequal heads gain no D64 envelope coverage.

**Real Hopper execution is still required for qualification.** The supplied server has only RTX 6000D (cc12.0); the production SM90 guard remains intact. No Hopper numerical correctness, sanitizer, runtime capture/rebinding or performance qualification is claimed.

## Testing

Source-bound Python 3.12, Torch 2.13.0+cu130, cuDNN frontend 1.33.0/backend 9.27, CuTe DSL 4.8.0 (CUDA 13.4 compiler), actual RTX 6000D cc12.0.

From `test/python`:

```sh
python -m pytest -q -s sdpa/frost/test_sdpa_native_d64_sm90.py
```

**49 passed, 61 skipped** within the final selected regression run. The passes comprise 35 host admission/placement/export/route checks and 14 real `sm_90a` cross-compilations: 12 D64 profiles across both dtypes, mask anchors, optional/base-two Stats, schedulers and zero/negative scales, plus two D512 controls. Fourteen route checks model the declaration target only and trap the template loader before any JIT or launch: dense D64 selects its native body, while sinks, window/right bands, paired lengths, THD and PackGQA retain D512. Before the compatibility fix these checks produced 12 failures and two passing dense controls; all 14 now pass. Each compiled artifact passes the real prepared `_positional_order()` check, including the TVM-FFI entry and compiled wrapper ABI. The missing `_host` export and unsupported BR geometry checks were observed failing before their corrections.

PTX/cubins and disassembly were inspected: D64 uses no `m64n256` instructions, each committed MMA group has four k16 steps, and the retained disassemblies contain no local spill loads/stores. These are code-generation checks.

All 61 skips in the new module require actual Hopper execution and are not counted as qualification. They include eight standalone D512-envelope regressions for the reported sink/window/length/PackGQA declarations, with independent FP64 O/Stats references, fresh storage and changed-value capture replay. Changed-file formatting/syntax/SPDX and `git diff --check` pass. No tolerance was relaxed.

Selected new and existing SM90 routing, native-frame, heuristic and placement controls:

```sh
python -m pytest -q -s -n 0 sdpa/frost/test_sdpa_native_d64_sm90.py sdpa/frost/test_sdpa_native_sm90_binding.py sdpa/frost/test_sdpa_fwd_dsl_sm90.py sdpa/frost/test_sdpa_fwd_heuristics.py sdpa/frost/test_sdpa_fwd_placement.py -k sm90
```

**145 passed, 212 skipped, 489 deselected** on actual cc12.0. The compatibility change affects host selection only; no kernel, graph admission, architecture gate, ranking or tolerance changed. The documented Hopper qualification hold remains.

Remaining qualification: execute the new Hopper detectors and existing D512 controls on H100/H200, run native memory/synchronization checks, and measure performance before considering any ranking promotion.
