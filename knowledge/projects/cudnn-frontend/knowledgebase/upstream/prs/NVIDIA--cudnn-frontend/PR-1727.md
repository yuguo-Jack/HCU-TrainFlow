# ops: move the KDA and BSA ops to cudnn.ops; remove the cudnn.jax/cudnn.torch names

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1727) · state: closed · merged: True

## Original PR description

Moves the KDA and BSA ops to `cudnn.ops`, following the naming convention in `docs/fe-oss-apis/api_conventions.md` (#1655), and removes the unused `cudnn.jax` / `cudnn.torch` names they replace.

| Removed | Use instead |
| --- | --- |
| `cudnn.jax.kimi_delta_attention_fwd` | `cudnn.ops.kimi_delta_attention_forward_jax` |
| `cudnn.jax.kimi_delta_attention_bwd` | `cudnn.ops.kimi_delta_attention_backward_jax` |
| `cudnn.jax.block_sparse_attention_forward` | `cudnn.ops.block_sparse_attention_forward_jax` |
| `cudnn.jax.block_sparse_attention_backward` | `cudnn.ops.block_sparse_attention_backward_jax` |
| `cudnn.torch.block_sparse_attention_forward` | `cudnn.ops.block_sparse_attention_forward` |
| `cudnn.torch.block_sparse_attention_backward` | `cudnn.ops.block_sparse_attention_backward` |
| `cudnn.torch.block_sparse_attention_fp8_forward` | `cudnn.ops.block_sparse_attention_fp8_forward` |

Each new name is the same function object as the removed one. The removed names shipped in 1.30.0 and 1.31.0 (#1111), and no caller was found: TransformerEngine, FlashInfer, Megatron-LM and JAX (heads of 2026-10-12/13) do not reference them, and GitHub code search finds no other user. This follows #1597. The PyTorch BSA names under `cudnn` and `cudnn.BSA` are unchanged.

Not moved:
- `cudnn.jax.kimi_delta_attention` and `cudnn.jax.block_sparse_attention` (the differentiable `custom_vjp` entries), and the differentiable PyTorch `kimi_delta_attention`. They have no direction, so their naming is still open.
- The JAX interop utilities (`call`, `TensorSpec`, `gemm_operand_spec`, `sf_atom_spec`, `row_major_desc`, `zeros_init`, `neg_inf_init`) and the `cudnn.torch` SDPA provider (`calls`, `install`, `served_plan_names`). These are not ops.

Changes:
- `cudnn.ops`: the seven names are added to `_LAZY_EXPORTS`. `import cudnn.ops` still imports neither PyTorch nor JAX, and a missing framework gives the standard optional-dependency error.
- `cudnn.jax` / `cudnn.torch`: the seven old names are dropped from `__all__` and `__getattr__`.
- Tests and benchmarks: the BSA and KDA JAX tests, the PyTorch BSA tests (`test/python/block_sparse_attention/cutedsl`) and the `benchmark/bsa` scripts call the `cudnn.ops` names. The torch-free (`test_import_isolation`) and JAX-free (`test_torch_runtime_without_jax`) subprocess tests and `test_explicit_entries_moved_to_cudnn_ops` check the new names resolve and the old ones are gone.
- Docs: `bsa.md` and `kda_jax.md` use the new names.
- API index: seven names removed, seven added.

Testing on an SM100 GPU with CUDA JAX 0.11.2, all markers:
- `test/python/block_sparse_attention` (PyTorch and JAX), `test/python/linear_attention/jax`, `test/python/core/jax`, `test/python/core/test_import_boundaries.py`, `test/python/core/cutedsl/test_cutedsl_version_gate.py`, `test/python/api_index`, and the `cudnn.ops` unit tests for causal_conv1d and NVFP4 conversion: 351 passed, 258 skipped. 255 skips are SM90- or SM120-only BSA cases, which run in CI; 2 need two visible GPUs; 1 needs `CUDNN_API_INDEX_PACKAGE_ROOT`. The `benchmark/bsa` scripts were byte-compiled only.
- After rebasing onto `develop` at e30e7c318 (#1663): `test/python/api_index`, `test/python/block_sparse_attention/jax`, `test_BSA_jax_parity.py`, `test_kda_jax.py` and `test/python/core/test_import_boundaries.py`: 121 passed, 3 skipped (two need two visible GPUs; one needs `CUDNN_API_INDEX_PACKAGE_ROOT`).
- The API index scanner matches the edited baseline, apart from the environment artifact below.
- pre-commit passes.

Environment note: `develop`'s C++ does not build against the shared backend build on this machine, so the package under test was this branch's Python with a compiled module from an earlier build. That module lacks the optional `gnn_agg_*` symbols (9 names in the index scan). This PR changes no C++.
