## Summary

Enable deterministic indexer backward for compact H32 tensors on the default
SM100 backend. The existing CuTeDSL kernel already combines the two required
properties: it pads H32 to its internal M64 tile with predicated compact
stores, and its deterministic mode assigns fixed query-row stripes to
CTA-private dK planes. This change exposes that supported intersection in the
Python capability gate, documents it, and adds focused correctness and
performance coverage.

The `sm100_v2` deterministic backend remains H64-only.

## Why

The production r=4 DSA indexer uses H32. Before this change,
`IndexerBackward(..., deterministic=True)` rejected H32 before launch even
though the default kernel's compact-H32 path and fixed-owner deterministic dK
path are compatible. Callers therefore had no native deterministic path for
this shape.

The new test exercises 194 query rows, which is more than twice the 96
producer planes and forces plane reuse across waves. It covers local and
global top-k indices, FP32 and BF16 dK, TopK512 and TopK2048, eight bitwise
repeat launches, an independent numerical reference, poisoned output and
workspace storage, and canary tails after compact dQ/dW tensors.

## Related issues

None.

## API and compatibility impact

There is no signature change. On SM100/SM103, the default indexer-backward
backend expands its deterministic envelope from H64/D128 to H32-or-H64/D128.
The `sm100_v2` deterministic envelope remains H64/D128. Existing ordinary and
H64 deterministic behavior is unchanged.

The deterministic implementation retains the existing 96 dense FP32 dK
planes, so its caller-owned workspace is
`96 * B * S_k * D * sizeof(float)`, aligned by the existing helper. A single
GB200 measurement of the compact-H32 path with B=1, D128, TopK512, global
indices, five warmups, 20 CUDA-event samples, reused outputs/workspace, and a
256 MiB L2 flush measured:

| Global context / CP | Local Q / compressed K | Ordinary | Deterministic | Ratio | Ordinary run max allocation | Deterministic run max allocation | Workspace |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 256K / 64 | 4,096 / 65,536 | 272.42 us | 1,423.98 us | 5.23x | 0.65 GiB | 3.65 GiB | 3.00 GiB |
| 256K / 32 | 8,192 / 65,536 | 510.51 us | 1,984.56 us | 3.89x | 0.97 GiB | 3.97 GiB | 3.00 GiB |
| 1M / 64 | 16,384 / 262,144 | 1,397.41 us | 5,656.59 us | 4.05x | 1.85 GiB | 13.85 GiB | 12.00 GiB |

The max-allocation columns are process peaks from the benchmark harness and
include its compact/H64 validation buffers and L2 flush tensor. The incremental
deterministic allocation equals the reported workspace.

The deterministic cost is dominated by clearing 96 full dK planes and
reducing them in fixed order; this PR does not change that algorithm.
