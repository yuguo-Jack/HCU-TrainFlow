## Affected area

FE OSS kernels / CuTeDSL: FROST GEMM analyzer, IR, template capabilities, prepared binding recipe and mainloop code generation, plus tests and a sample.

## Summary

Recognize A-side, B-side, or simultaneous per-K input scaling:

```text
(A [batch,M,K] * scale_a [1,1,K]) @ (B [batch,K,N] * scale_b [1,K,1])
```

Each multiply computes in FP32 and rounds to its MMA operand dtype before GEMM. Apply the multiplies in the existing SM100 mainloop operand-transform stage without materializing scaled matrices.

- Add an internal, mainloop-only `per_k` auxiliary mode. The analyzer records its reduction axis explicitly from the operand side; dimensions alone do not identify it, including when K=1. Do not reinterpret output-axis broadcasts as K.
- Keep dynamic per-K extent binding independent of emitted Python symbol names. The internal `TensorRef.symbolic_shape` uses only constants and the existing GEMM extent identities (M/N/K/batch/group), retaining the declared logical rank. The compiler separately lowers it to the existing minimum-rank-2 auxiliary ABI and renders source; fake shape and fake stride share that lowered rank. Swap-AB transforms the explicit reduction axis along with dimensions/strides.
- Recognize both multiplication input orders and preserve surrounding unary operations and repeated multiply nodes/rounding. Shared references are bound only once.
- Recover global K from logical, unswizzled SMEM vector coordinates; load the correct scale for each lane. Bound scale loads by K and reuse transformed-padding zeroing.
- Use the GEMM's `sym_k` for both scale orientations, with symbolic fake strides rather than baking the original unit-axis strides. Dynamic M/N/K can be rebound without recompiling this kernel.
- Keep IR validation structural (references and broadcast dimensions). Implementation restrictions live in the mainloop template's capability hook, with specific rejection reasons.
- Prepare immutable `PerKScaleRule` records in the existing aux binding recipe. Validate shape/K extent, unit K stride and dtype inside the existing aux-validation pass, before any launch or output/workspace writes. No separate scale loop or fixed-M/N/K checks.
- Support swap-AB by migrating the operations and transposing the scale views, while validating bindings in original caller coordinates. No per-K ban in the generic IR transform.
- Add graph/IR/capability/render/binding tests, numerical generated-transform tests runnable on Hopper, full Blackwell GEMM numerical/capture tests, and a comparison sample with `--side a|b|ab`.

### Cleanup and test consolidation

- Cache recursive pointwise dimension inference for one operand walk; reject non-scale candidates before traversing their producers.
- Rely on the shared TMA alignment gate instead of duplicating it in per-K capability checks.
- Include the scale name in prepared binding errors; update stale scalar-only/A-only comments and diagnostics.
- Consolidate shared graph, buffer and plan helpers and merge binding rejection/recovery with dynamic rebinding coverage. Reduce the new test module from 426 to 375 lines and from 179 to 47 collected cases (including one merged symbolic-shape contract test).
- Replace the 118-case full-GEMM Cartesian matrix with 10 representative cases. Each checks random numerics, changed-scale CUDA-graph replay, exact K-index output and dynamic M/N/K rebinding; preserve all 12 operand/scale-dtype/orientation generated-fragment cases.

## Why

Existing mainloop binary fusion accepts only scalar graph-input auxiliary tensors. Per-K input scaling extends operand-transform fusion to a practical non-scalar broadcast and can avoid separate multiply launches plus the write/read of M-by-K and/or K-by-N intermediates. This draft does **not** claim a measured speedup.

The follow-up refactors the initial A-only, fixed-shape prototype: restrictions are no longer mixed into IR validation, and execution consumes prepared binding rules instead of re-reading IR policy.

### Refactor scope

The shape changes are supporting plumbing for dynamic per-K scaling, not a general symbolic-shape or graph-compiler redesign. There is no expression algebra, new public shape API, or separately stored symbolic shape. Existing broadcast metadata remains authoritative; the internal extent view is derived from it and the explicit per-K operand axis. Logical-rank/ABI-rank separation and the extent refactor remain in dedicated commits, separate from kernel feature implementation, so they can be reviewed independently.

## API and compatibility impact

No new public operation, parameter, engine or execution API. The graph uses ordinary `mul` and `matmul`; lowering stays internal to FROST. The new optional `Aux.mainloop_scale` and internal `TensorRef.reduction_axis` fields are appended with defaults. Per-K references require an explicit reduction axis; existing epilogue/scalar construction is unchanged.

Implemented template scope:

- A, B, or both; scaled operands are K-major BF16 or FP16, without operand-load casts.
- Contiguous BF16/FP16/FP32 per-K scales, shared across the declared batch.
- FP32 multiplication, rounded to the corresponding MMA operand dtype.
- Dynamic M/N/K, swap-AB, and surrounding unary/scalar operations.
- K obeys the existing TMA alignment (divisible by 8 for these 16-bit operands).
- Scaled A needs M>1; scaled B needs N>1 for unambiguous graph-input scale identification.
- The unscaled operand is governed by the existing MMA dtype/layout capabilities, not a new BF16-only condition.

MoE, block-scale and parallel multi-GEMM remain outside the existing mainloop template routes. Backend and other FROST routes retain their own eligibility rules. Public import-time lazy boundaries are unchanged.
