## Affected area

FE OSS kernels or CuTeDSL (FROST SDPA forward heuristics and default placement; no kernel change)

## Summary

1. **Dense d128 CGA width by wave count** (`heuristics.py`). This covers the SM100 f16 row and the cc 10.7 shared dense d128 leg, d64 envelope included. Past one decode tile, the single-CTA decode tile (`TILE_CGA_M=1`) now leads when two conditions hold:
   - its waves are at most 1.6x the cga2 cluster's waves (`ceil(units*ceil(rows/128)/SMs) <= 1.6 * ceil(units*ceil(rows/512)/(SMs/2))`);
   - the cache is below 16k tokens.

   The other width is always listed as a runner, so autotune can reach both. Before this change, cga1 was proposed only at `S_q * G <= 128`.
2. **Rubin dense d64/d128 placement re-fit** (`placement.py`). The #1510 fit predates the #1484 decode tile.
   - Decode-shaped `2 <= s_q <= 16` now leads at every unit count; the old `units <= 8` bound is removed.
   - `s_q == 1` keeps the backend.
3. **New lead rule on SM100 and Rubin.** A causal dense d64/d128 prefill whose decode-tile launch fits one wave now leads, with or without a sink (`_d128_one_decode_tile_wave`). The #1518 graph is in this class.

No `Capabilities` or knob-domain change (Rule S2 exempt). The tracker row describing the decode tile's proposal rule is updated.

## Why

#1518: on Rubin, the first FROST plan for B1, Hq=Hkv=32, S=512, D128, sink, bottom-right causal was the cga2 body. A faster cga1 plan existed but was never proposed, and placement kept the backend first. This repo's numbers (cc 10.7, 216 SMs, cuDNN 9.27, CUDA-graph replay, warm / cold L2):

| | develop | this PR |
|---|---|---|
| default plan | backend, 14.6 / 16.4 us | FROST cga1, **10.8 / 11.6 us** |
| first FROST plan | cga2 LPT, 13.1 / 16.1 us | cga1, 10.8 / 11.6 us |
| best legal FROST plan | 10.2 us (not proposed) | 10.2 us (listed) |

To find out whether other graphs miss good candidates, a **candidate-coverage audit** timed every legal FROST knob combination per graph and compared it with the proposed list. The table reports two ratios: the first proposed plan over the best legal plan (mean), and the number of graphs whose best legal plan was not proposed at all.

| audit set | first / best: develop -> PR | best not proposed: develop -> PR |
|---|---|---|
| cc 10.7, 73 graphs (d128 MHA/GQA +-sink, prefill/chunk/decode; d192/256/512) | 1.133 -> 1.032 | 31 -> 4 |
| cc 10.7 hold-out, 36 graphs (no mask, top-left causal, SWA, off-grid heads/lengths) | 1.230 -> 1.033 | 21 -> 1 |
| B200, same 73 graphs | 1.097 -> 1.029 | 18 -> 0 |
| B300, same 73 graphs | 1.076 -> 1.025 | 14 -> 0 |

Every timed arm was checked against an FP32 reference on sampled rows; there were no numerics flags.

**Placement**, FROST-first vs backend-first A/B on d64/d128 cases. Each run was a dev / new / dev sandwich; dev and dev2 agree within +-1.4 % at p5-p95. Regret is the slowdown against the faster provider. A lead-loss is FROST leading while slower than the backend by more than 3 % warm or cold.

| board, set | regret: develop -> PR | lead-losses |
|---|---|---|
| cc 10.7, 386 cases (decode s_q 1-16, chunks to 128k KV, squares, 48-case random hold-out) | 179.5 % -> 1.8 % | 0 |
| B200, 242 cases (same set) | 1.9 % -> 1.0 % | 0 |
| B200, 144-case hold-out (s_q 2/8/16 both masks, 48 random prefill) | 4.7 % -> 3.3 % | 1, pre-existing (see below) |
| B300, 242 cases (same set as B200) | 3.0 % -> 2.0 % | 0 |

- The B300 A/B and 7 of its 73 audit graphs (the ones that hung on develop, #1532) ran with #1541's one-line kernel change applied, on all arms alike.
- The one-wave rule's qualifying cases across all of these sets (146: 79 A/B, 67 audit) ran 0.03-0.88 of the backend, warm and cold.
- The single B200 hold-out lead-loss is d128 B4 8/1 q448 kv20000 top-left causal, at 1.26x. develop's chunked rule already leads it with the same FROST plan, so it is unchanged by this PR.

**Long-KV guard.** Without it, the wave rule put chunks at 32k-128k KV onto the decode tile and ran 0.86-0.97 (9 of 21 changed plans on B200, 9 of 47 on cc 10.7). With the guard, all 68 changed first plans run at 0.98x or faster. On B300 the guarded rule changed 9 first plans: geomean 1.28x, worst 0.98x.
