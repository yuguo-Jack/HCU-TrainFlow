# Cache immutable SDPA function metadata across plans

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1844) · state: closed · merged: True

## Original PR description

Building another SDPA plan for an already-loaded adapter and kernel repeats Python signature inspection. Cache the immutable parameter names and template host argument order by function identity, with bounded caches shared across plans. A replaced function gets its own entry, and each plan still receives its own mutable argument-order list.

Keep the compiled-wrapper ABI check per plan. The caches do not retain adapter instances or compiled launchables, and execution still validates and binds the current tensors, workspace and stream. Public APIs, eligibility, heuristics, native bindings and kernels are unchanged.

Validation on B200 with cuDNN 9.27 and public CuTeDSL 4.8.0:

- All 123 selected existing prepared-execution tests pass on both baseline and candidate, including O/LSE, pointer/workspace rebinding, shape overrides, FP8 scales and CUDA Graph capture/replay.
- Six new cases in two existing test files fail on the baseline and pass with this change. They cover reuse across plans, replacement entry points, all prepared host variants, independent slot lists and compiled-wrapper ABI rejection.
- The warmed graph-construction probe performs one signature inspection for the current compiled-wrapper check instead of six. Neither execute path performs signature inspection.
- Scoped formatting/license hooks pass. No timing threshold or heuristic-order golden was added.
