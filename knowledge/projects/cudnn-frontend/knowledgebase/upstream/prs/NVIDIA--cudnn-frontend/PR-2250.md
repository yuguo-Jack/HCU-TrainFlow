# test(bsa): organize the BSA tests by API path and drop non-interacting parameter crossings

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2250) · state: open · merged: False

## Original PR description

## Summary

The BSA tests in `test/python/block_sparse_attention/cutedsl` had grown into 15 files split along unrelated axes (operation, architecture, kernel history), with tests duplicated per architecture, six hand-written references and several per-file helper copies. This PR reorganizes them by API path, with the GPU architecture and the sparse block size as parameters, and removes parameter crossings that do not interact.

### Layout (15 files -> 8)

| File | Contents |
|---|---|
| `test_BSA_forward.py` | BF16/FP16 forward numerics |
| `test_BSA_backward.py` | backward numerics |
| `test_BSA_backward_metadata.py` | K-to-Q CSR and paired-KV refinement kernels |
| `test_BSA_kpage.py` | KPage, blk64 and blk128 |
| `test_BSA_fp8_forward.py` | Sage FP8 forward numerics, grouped by kernel |
| `test_BSA_fp8_quantize.py` | Sage FP8 quantizer recipes |
| `test_BSA_api.py` | host-side contracts: argument checks, DSL gates, dispatch, split/bucket policies |
| `test_BSA_jax_parity.py` | unchanged |

Tests without an architecture prefix run on every GPU the path supports; `test_sm<arch>_blk<size>_*` tests cover one kernel and skip elsewhere.

### Commits

1. **Reorganize** — move/rename into the layout above and merge tests that only differed by architecture or block size: the generic forward/backward tests run at blk64 and blk128 on every architecture (replacing the SM120 native blk128 and SM100 blk64 copies), the SM90 and SM100 large-logit regressions share one table, the KPage blk64 tests join the blk128 ones, and the three FP8 rejection tests become one table that patches the architecture and runs on any GPU. Shared helpers replace per-file copies: one masked attention reference (empty rows, GQA, backward, FP64), one FP8 online-softmax reference for the SM90 and SM120 kernels, the SM90 blk128 case/check helpers, `no_host_sync()` and `cuda_graph()`. A directory `conftest.py` runs the references with FP32 matmuls and restores the RNG state after each test (five tests set `allow_tf32 = False` without restoring it, which leaked into later tests under `TORCH_ALLOW_TF32_CUBLAS_OVERRIDE=1`). The SM90 blk64 shared-V regression drops the variant that copied the kernel source and injected a delay; its plain cases stay.
2. **L0/L1** — four long sweeps keep boundary/diagonal cells in L0, the rest run at L1.
3–5. **Non-interacting crossings (SM90, SM100, SM120)** — where a parameter feeds a path independent of the others (e.g. the BHSD/BSHD layout vs. the scheduler, the backward Q bucket vs. KV boundaries, the 16-bit type vs. list length), it alternates instead of being crossed; one SM100 FP8 test that was a strict subset of another is merged into it. Each commit message lists the tests and the reasoning.

Old -> new test names are recorded in the commit messages; no production code changes (the only non-test edits are the SM120 benchmark docstring, which absorbs the usage notes that lived in the old forward test, and the JAX README file names).
