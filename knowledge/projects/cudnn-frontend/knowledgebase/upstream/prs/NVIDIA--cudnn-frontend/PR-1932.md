## Affected area

- FE OSS kernels or CuTeDSL

## Summary

- Apply the metadata optimization to both atomic and deterministic
  specializations of the generic ratio-2/4 backward kernel.
  Forward and the separately dispatched ratio-128 kernel are unchanged.
- Locate the segment owning a CTA's first compressed row with an upper-bound
  search over `cu_seqlens_comp`.
- Carry that segment cursor forward across the CTA's remaining consecutive rows,
  including repeated prefixes from empty or shorter-than-ratio sequences.
  The fragmented benchmark places an empty segment inside the pack so a later
  valid compressed row crosses the repeated prefix.
- Preserve the existing floating-point expressions and deterministic dAPE
  partial/reduction trees.
- Add a `--packed-metadata` benchmark mode that pairs plain and highly fragmented
  256K/1M THD inputs.

## Why

The generic backward kernel previously scanned all packed sequences for every
compressed row and every participating head-dimension thread. Its metadata work
therefore grew as `O(compressed_rows * sequences)` and dominated long, highly
fragmented packs. The compressed prefixes are monotonic and each CTA owns eight
consecutive rows, so a single logarithmic lookup plus forward-only cursor updates
provides the same mapping with substantially less work.

## Related issues

None.

## API and compatibility impact

No public API, support envelope, workspace size, compile-cache key, launch shape,
or stream behavior changes. The kernel performs no new allocation or host/device
synchronization. Floating-point expressions, CTA-local accumulation order, and
deterministic dAPE reduction trees remain unchanged. With deterministic mode
enabled, dKV, dScore, and dAPE were bitwise identical to the unchanged-source
control in every measured case. The atomic path retains its existing
non-deterministic dAPE accumulation; no bitwise guarantee is added for that mode.

## Performance

NVIDIA SM103, PyTorch 2.12.1+cu130, cuDNN Frontend 1.32.0 environment and
public CuTeDSL 4.8.1. Each variant was compiled in an isolated source package and
process. Both sources were measured with reversed atomic/deterministic plan
construction order.

The repository's existing `--long-context` production shapes use unequal packed
sequences representing the documented CP32/64 workloads. The table reports the
full deterministic operation (producer plus fixed-order dAPE reduction), with the
two construction-order controls shown separately.

| Existing production shape | Unchanged develop controls | This PR controls | Time reduction |
| --- | ---: | ---: | ---: |
| 256K packed, CP32/64 | 117.44 / 116.53 us | 105.01 / 104.98 us | 10.3% |
| 1M packed, CP64 | 381.38 / 380.96 us | 328.46 / 328.74 us | 13.8% |

The same runs also measured the non-deterministic (atomic) path. The following
table averages the measurement medians across the two plan construction orders.
Operation time includes the required dAPE buffer clear and backward execution;
allocation and JIT compilation are excluded.

| Atomic backward, ratio=4, coff=1, D128 | Unchanged develop | This PR | Time reduction |
| --- | ---: | ---: | ---: |
| 256K packed | 117.26 us | 116.14 us | 0.96% |
| 1M packed | 372.97 us | 371.83 us | 0.30% |

These small differences do not establish a robust speedup for atomic backward.
For these seven-sequence production shapes, substantial measured gains are in
deterministic backward. The more fragmented cases below improve both modes.
This PR optimizes
shared metadata lookup without changing either mode's dAPE reduction strategy.
These are compressor-backward microbenchmarks, not end-to-end training results.

The metadata-stress benchmark was rerun after moving the empty segment inside
the fragmented pack (`[31, 0, 777, ...]`, with compressed prefixes
`[0, 7, 7, 201, ...]`). It covers 256K/1M plain and fragmented THD inputs using
ratio=4, coff=1, D128. Both sources use this same revised benchmark. As above,
times are full-operation medians averaged across two plan construction orders,
with 30 warmup iterations and 100 measurements per run. These results replace
the earlier trailing-empty-segment metadata-stress measurements.

| Input | Mode | Unchanged develop | This PR | Time reduction |
| --- | --- | ---: | ---: | ---: |
| 256K plain | Deterministic | 109.48 us | 104.47 us | 4.6% |
| 256K packed, 55 sequences | Deterministic | 196.30 us | 108.10 us | 44.9% |
| 1M plain | Deterministic | 353.83 us | 325.30 us | 8.1% |
| 1M packed, 221 sequences | Deterministic | 1817.74 us | 345.72 us | 81.0% |
| 256K plain | Atomic | 117.01 us | 116.81 us | 0.17% |
| 256K packed, 55 sequences | Atomic | 178.71 us | 117.99 us | 34.0% |
| 1M plain | Atomic | 372.66 us | 372.42 us | 0.06% |
| 1M packed, 221 sequences | Atomic | 1757.77 us | 374.14 us | 78.7% |

The small atomic-path differences for plain inputs are not evidence of a stable
speedup. The fragmented cases demonstrate that atomic backward also benefits
when repeated segment scans account for more of its execution time.

Deterministic workspace is unchanged: 16.5/66 MiB for the 256K/1M production
shapes, and approximately 16.498/65.988 MiB for the revised fragmented benchmark.
With deterministic mode enabled, full dKV/dScore/dAPE SHA-256 hashes matched
between independently compiled baseline and candidate processes for both revised
fragmented shapes; all outputs were finite and bitwise stable on repeat
execution. Earlier validation also established baseline/candidate hash equality
for both production shapes and the plain metadata-stress cases. The revised
benchmark's deterministic dAPE maximum absolute errors against its FP64 reference
are unchanged between baseline and candidate: `2.48e-5` at 256K and `8.28e-5` at 1M.
