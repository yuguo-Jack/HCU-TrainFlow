# Accept canonical layouts in grouped dGLU, dgrad quant, and wgrad

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1422) · state: open · merged: False

## Original PR description

## Summary

Extends the canonical layouts from #1233 to the grouped GEMM backward paths that Transformer Engine's fused MLP calls: dGLU, dgrad (the quant wrapper), and wgrad.

- **dGLU** (SM100 and Rubin) accepts contiguous A `(m, k)`, C `(m, 2n)`, prob and dprob `(m,)`, dense B `(l, n, k)`, and packed scale buffers of any rank. With 2-D A it returns 2-D D_row/D_col and physical SFD buffers. The deterministic dprob path accepts a 1-D dprob.
- **N-major canonical B:** dGLU and quant accept the column-wise `(l, k, n)` weight buffer with `b_major="n"`, as used for dgrad. The kernels receive the major through `b_major_mode`, because strides cannot distinguish a contiguous `(l, k, n)` from `(l, n, k)`. Without this, an `(l, k, n)` buffer was silently read as `(l, n, k)`.
- **wgrad** accepts flat 1-D scale buffers. The kernel rebuilds the 2-D view from the token count, so a new token count still reuses the compiled kernel.
- The dGLU and wgrad wrappers advertise `supports_canonical_layouts`. Legacy layouts are unchanged.

## Measurements

These numbers come from TE's fused MXFP8 grouped MLP (4096 tokens, 8 experts, hidden size 2048, intermediate size 512) with the companion TE change using these layouts:
- Forward + backward host p50 drops from 1419 µs to 1329 µs (−6%), measured on SM100 with a pinned CPU over three interleaved rounds.
- The forward output and all gradients are bitwise identical.

## Testing

All on SM100.
- **New `test_grouped_gemm_backward_canonical.py`:** compares canonical against legacy bitwise. It covers dGLU with K- and N-major B and physical or flat scales (cold and warm calls), deterministic dprob, short scale-buffer rejection, quant with N-major B, and wgrad with flat scales and a changed token count.
- **Existing suites** (dGLU, dGLU workspace, wgrad, wgrad tensormap, quant, quant canonical, GLU canonical, canonical layouts, prepared, wrapper memo, scheduler counter, and JAX dGLU/wgrad/quant): 905 passed, 669 skipped.
  - That run found 6 BF16/JAX wgrad failures, caused by this change's cache key for absent scale tensors. They are fixed, and the wgrad suites now pass (71 passed).
- **TE `tests/pytorch/test_grouped_mlp.py`** with the TE change: 553 passed, 4461 skipped. The 1 failure is pre-existing and also fails on TE `main`.

## Not covered

- Rubin is not hardware-tested.
- NVFP4 canonical backward is not tested; TE uses these layouts only for MXFP8.

**[P1 · high risk] Validate flat wgrad scale capacity and contiguity on every call** ([source](https://github.com/NVIDIA/cudnn-frontend/blob/fe28b38f375b7be4f2740581baff2a3c912e7b90/python/cudnn/gemm/cutedsl/grouped/wgrad/api.py#L416))

The new rank-1 signature makes the entire scale extent dynamic, while check_sf_shape only runs when constructing a new op. kernel_facing_wgrad_sf then derives a contiguous 2-D layout from the operand token count, ignoring the actual flat buffer's extent and stride. Two consequences: (1) after a valid warm-up, a genuinely 16-byte SFA or SFB allocation reaches the compiled call even when 7,680 / 12,800 bytes are required; the same call is rejected cold. The generated layout can therefore read beyond that allocation. (2) even cold, a correctly sized stride-2 flat tensor is accepted and interpreted as contiguous bytes, silently producing incorrect gradients. Please validate the required packed element count and dense contiguous layout before reuse/launch, including the direct API path. Keep the dynamic compile key so valid token-count changes still reuse the kernel; this should be a metadata check, not another specialization. Add warm-invalid/valid-recovery and strided-flat regression cases. This is high risk because the first case permits invalid memory reads and the second produced silent numerical corruption.

Evidence: On the exact head, local SM100 / CuTe DSL 4.7, using the new test's wgrad_inputs([256, 384]): all three warm cases (short SFA, short SFB, both short) reached the real op's compiled-call boundary with genuine 16-byte allocations; I intercepted there, so no out-of-bounds kernel was executed. All three were rejected cold, and a subsequent valid warm call matched bitwise. To check the generated FFI as well, I then ran all three short-declared-view cases while retaining full valid backing allocations: FFI accepted them and native execution matched the complete-buffer output, demonstrating that no later extent guard rescues this path. For the stride check, safe 2*N allocations had even bytes matching the original logical scales and differing odd bytes: SFA-only, SFB-only, and both stride-2 cases were accepted cold and had max absolute wgrad errors 78, 80, and 116 versus contiguous inputs. Attribution: Newly enabled by this PR's rank-1 wgrad scale support and dynamic flat-scale cache signature; not a claim that all existing rank-2 validation behavior was introduced here.
