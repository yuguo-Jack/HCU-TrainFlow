# norm(graph): stop re-deriving the plan's bindings on every execute

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2142) · state: closed · merged: True

## Original PR description

## Problem

Every execute of a FROST norm graph plan repeats work that only depends on the plan:

- `resolve_variant_pack` rebuilds its uid / name / object tables on every call. That means querying each bound tensor's name and UID from C++ (21 `get_name` and 21 `get_uid` calls per LayerNorm forward execute) and recounting duplicates, although a lowered plan's bindings never change. `SdpaBinding.index()` already caches the same tables for attention.
- `on_stream()` enters `torch.cuda.stream()` even when the requested execution stream is already torch's current stream. That is the usual case: the handle's stream set to torch's current stream.

## Change

- `NormBinding.index()` builds `(by_obj, by_uid, by_name)` once, on the first execute, when the graph is already built, and `resolve_variant_pack` reuses it. The resolution rules are unchanged: object, then unique UID, then unique name, and a name or UID shared by two bound tensors identifies neither.
- `on_stream()` returns a `nullcontext` when the requested handle equals torch's current raw stream, read with the existing `_torch_stream._raw_current_stream`. A request for the legacy default stream (handle 0) from a side stream still switches.

## Measurements (B300, cc 10.3)

LayerNorm / RMSNorm forward graphs, bf16, with the FROST plan selected. Develop and this branch ran in separate processes, alternating, three times; the table gives medians. Warm enqueue of `g.execute`, and per-execute GPU time of a captured CUDA graph of 20 executes:

| norm | rows x C | develop enqueue µs | this branch enqueue µs | develop replay µs | this branch replay µs |
|---|---|---:|---:|---:|---:|
| LayerNorm | 1024 x 1024 | 230 | 197 | 3.19 | 3.20 |
| LayerNorm | 4096 x 4096 | 235 | 201 | 10.83 | 10.83 |
| LayerNorm | 16384 x 4096 | 232 | 200 | 44.20 | 44.23 |
| LayerNorm | 2048 x 8192 | 232 | 201 | 11.69 | 11.76 |
| RMSNorm | 1024 x 1024 | 223 | 193 | 2.96 | 2.94 |
| RMSNorm | 4096 x 4096 | 225 | 192 | 7.75 | 7.79 |
| RMSNorm | 16384 x 4096 | 225 | 195 | 45.06 | 45.09 |
| RMSNorm | 2048 x 8192 | 225 | 196 | 8.80 | 8.78 |

Enqueue drops 13-15%. Replay is unchanged (0.993-1.006), and in every case the replay output equals the eager output. The backward graph engines share both paths; I did not time them separately.

## Tests

- New `test/python/norm/graph/test_norm_graph_binding_cost.py`:
  - the tables are built once and resolve the same keys on a later call, with ambiguous names left unresolved;
  - the current stream is not entered again, while a side stream and an explicit default-stream request still switch.
- On B300, `test/python/norm` gave 1329 passed, 1 skipped. The new file ran in a second run, together with `test_frost_norm_stream_ordering` and `test_frost_norm_graph_roundtrip`: 8 passed.
