# fix(bsa): lazily import torch for cached device capability

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1097) · state: open · merged: False

## Original PR description

## Summary

Fix `NameError: name 'torch' is not defined` when the PyTorch bucketed K-to-Q CSR builder calls `_device_capability()`. Import `torch` inside the cached helper so the builder works while preserving the module's lazy Torch dependency.

## Why

`build_bucketed_k2q_csr_cutedsl()` imports Torch in its own local scope. That import is not visible to the module-level `_device_capability()` helper after the module-level Torch import was removed.

## Affected area

FE OSS kernels / BSA backward metadata preparation.

## API and compatibility impact

No API or dependency changes. The device-capability cache remains intact, and importing this shared kernel module does not add an eager Torch import.

## Related issues

Related to #1091, which includes a module-level Torch import alongside a broader performance change. This PR isolates the fix and retains lazy importing.

## Testing

- Reproduced the `NameError` by calling `_device_capability(0)` on unmodified `develop`; the same call passes after this change. Repeated calls hit the existing cache.
- GB200 / CuTe DSL 4.8.0.dev0: fixed-count and variable-count CSR builders match a host reference on both cold and warm calls (4 cases). The module has no global `torch` binding after these calls.
- `pre-commit run --files python/cudnn/block_sparse_attention/csrc/bwd/bucketed_k2q_csr.py` — passed.
- `git diff --check` — passed.
