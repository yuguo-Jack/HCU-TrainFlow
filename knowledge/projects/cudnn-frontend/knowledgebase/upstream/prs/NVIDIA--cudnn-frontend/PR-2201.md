# perf(dsa): faster SM100 indexer backward dK reduce and sm_scale fold; tighten the indexer-backward contract

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2201) · state: closed · merged: True

## Original PR description

## Summary

Performance work and cleanup for the DSA sparse indexer backward (`IndexerBackward` / `indexer_backward_wrapper`).

### Performance (SM100 family)
- **BF16 `d_index_k`**: dK accumulates in a column-permuted fp32 scratch (p128 reduce with an xor-4 exchange), and the trailing cast un-permutes it. End to end this is 1.19–1.27x on B200 and B300 compared with the natural-layout reduce. The scratch is carved from the caller's workspace, which is required for BF16 outputs.
- **`sm_scale` folded into the dS weights**, so the dK drain and the dQ epilogue no longer multiply by it. This gives 1.08–1.22x with an fp32 `d_index_k` and 1.00–1.04x with BF16 over a 60-config sweep. It is bit-identical at `sm_scale=1`.
- **Compact H32**: the padded heads 32..63 skip the TMEM readback and the dS math, and GEMM2 runs only the K-blocks that hold real heads.

### API / contract
- **Breaking:** the experimental `sm100_v2` backend is removed, together with the `backend` parameter, the kernel, its benchmark (`benchmark_dsa_indexer_h32_native.py`), docs and tests. After the changes above, the default kernel is at least as fast on all measured shapes.
- **Breaking:** `IndexerBackward.__init__`'s `deterministic` and `deterministic_dk_planes` parameters are now keyword-only.
- `check_support` now admits only what the kernels compile and were validated on:
  - Architectures: SM90, plus SM100, SM103 and SM107 (`INDEXER_BACKWARD_SM100_CAPABILITIES`).
  - Head count: SM90 H == 64; SM100 family H ∈ {32, 64}. The previous limit admitted H96, H128 and H256, which either fail to compile or exceed SMEM.
  - D == 128, block_I == 128, topk > 0 and a multiple of block_I, and `sm_scale` finite and positive.
  - Dense indexer backward: H == 64. On SM90, D and block_I must be 128; on the SM100 family, D and block_I ∈ {64, 128}.
- DSL gates follow Rule 7: `cutedsl_requirement_error`, plus `cutedsl_arch_requirement_error` on SM107. With the gate in place, the cp.async K-load fallback for pre-Gather4 DSLs was unreachable and is deleted.
- `compile()` now builds every kernel eagerly from fake CuTe tensors (new helper `utils.tensor_conversion.fake_cute_tensor`), so `execute` never compiles and the R11 `compile_allocates_nothing` check exercises the real build. The redundant `has_tcgen05` guards in the factories are removed; admission lives only in `check_support`.

### Docs / benchmark / tests
- `docs/operations/sparse_attention/dsa.md` documents the new envelope and drops the v2 section.
- `benchmark_dsa_indexer_h32.py`: adds `--d-index-k-dtype`, preallocates the workspace, and checks that medians are finite.
- `test_DSA_indexer_backward.py` is consolidated into table-driven tests (18 functions, 117 cases): a `check_support` envelope table, a malformed-tensor table, and deterministic, Rule 8 and kernel-level reference checks. The GEMM-only reference test now also runs on SM90 (20 natural-layout cases), covering invalid, out-of-range and duplicate IDs and local and global IDs.
