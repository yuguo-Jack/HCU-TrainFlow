# test(kda_sm90): don't require the optional cuTile engine on Hopper

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2228) · state: open · merged: False

## Original PR description

## Problem

`cuda.tile` is the optional `[cutile]` extra. On a Hopper without it, two L0 tests in `test/python/linear_attention/hopper/test_kda_sm90_cuda.py` fail instead of running what they can:

| test | failure without cuTile |
|---|---|
| `test_plan_name_still_overrides` | `cudnnGraphNotSupportedError: no kda_cutile plan for this graph (offered: ['kda_hopper_cuda', 'kda_hopper'])` |
| `test_declined_graph_falls_through` | `cudnnGraphNotSupportedError: no engine — python or backend — proposed a plan for this graph (… kda_cutile: KdaCuTileEngine requires the cuda.tile runtime: No module named 'cuda.tile'; … kda_hopper_cuda: KdaHopperCudaEngine: head dims must be 128, got K=64 V=64)` |

`test_la.py` already waives these cases for the `cutile` backend through `waive_unsupported`. This file does not.

## Change

- `test_plan_name_still_overrides` pins `plan_name="kda_cutile"`, so it now skips when `cuda.tile` is not installed, with a reason.
- `test_declined_graph_falls_through` relies on cuTile to serve the head-dim-64 graph that the sm90 engines decline. Without cuTile nothing on Hopper serves it, so the test now asserts that the call declines with `kda_hopper_cuda`'s own head-dim reason. That still pins the point of the test: the 128-only engine never receives the graph. Coverage is kept rather than skipped.
- With cuTile installed, both tests run exactly as before.

## Testing

GH200 (sm_90), cuDNN 9.24, CUDA 13.2, `-m L0 test/python/linear_attention/hopper/test_kda_sm90_cuda.py`:
- develop without cuTile: 2 failed, 16 passed.
- this PR without cuTile: 17 passed, 1 skipped (`test_plan_name_still_overrides`).
- this PR with `cuda-tile` 1.7.0 installed: unchanged from develop. Both tests take the cuTile path. In this environment they still fail inside cuTile's own compile, see below.

`black 26.3.1 --line-length 160 --fast` is clean.

## Not in this PR

With `cuda-tile` 1.7.0 installed on this GH200, the cuTile path does not compile for sm_90:
- CUDA 13.2's `tileiras` has no `sm_90` target: `Cannot find option named 'sm_90'`. Its `--gpu-name` list is sm_80/86/87/88/89/100/103/110/120.
- `tileiras` 13.4.92 (`nvidia-cuda-tileiras`) lists `sm_90`, but compiling `chunk_local_cumsum_vector_kernel` still returns code 5.

That is a toolchain question rather than a frontend one, so I've left the engine alone. I'm mentioning it in case CI's SM90 job gets its `tileiras` from somewhere else.
