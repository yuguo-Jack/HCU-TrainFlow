## Affected area

Python graph API/validation, FE OSS GEMM graph lowering and native variant-pack views, tests and sample.

## Summary

Draft: lower zero-copy logical reshape nodes on operands of a single plain FROST GEMM. Project ordered reshape/last-two-axis transpose views through elementwise chains, so a graph such as `[B,H,S,K] -> leaky_relu -> reshape([B,H*S,K]) -> GEMM` can use the existing mainloop fusion without materializing activated storage.

- Add Python-native reshape shape/mode validation and dtype inheritance, without coupling frontend validation to backend reshape descriptor creation. Unspecified reshape targets keep classic default/scalar inference; VIEW_ONLY validation does not impose LOGICAL dtype/count constraints.
- Compute logical reshape strides using contiguous address chunks. Unit axes, legal axis merges/splits and padding that stays outside a merged chunk are handled uniformly across ranks; copying across a stride gap is refused.
- Preserve operation order for reshape/transpose compositions instead of commuting noncommuting structural operations. Pointwise compute/output dtypes, rounding and scalar operand order remain intact.
- Use one operand normalization pass, producer map and shape/dtype cache for ordered reshape/transpose projection. The pure geometry layer supports arbitrary permutations; GEMM's last-two-axis capability gate stays in graph lowering. No separate reshape pre-pass.
- Represent transformations with immutable `ViewStep` / `OperandView` records. Preserve each intermediate step's legality, including all equivalent shared-input paths when runtime strides change. Virtual pointwise nodes inherit the projected input layout, including padding.
- Retain runtime view ownership in GemmRecipe. Reuse prepared geometry when source shape/stride match, re-prove changed strides, and include rank-N batch folding in the same final native view. Each transformed operand creates at most one metadata view; identity compositions retain the original operand list. Tensor views preserve storage offset and ownership. No per-step Python/native calls on warm matching-layout launches.
- Add checked native OperandBuffer.metadata_view: original pointer/dtype/device/observed storage are retained; positive geometry, element count, original/observed span and signed-64-bit element/byte addressing are validated. `metadata_view` and `flatten_batch` share checked geometry and view construction; the common explicit-stride path avoids copying the source stride vector. Framework tensor execution uses one proved `as_strided`, never a potentially copying reshape. No new C++ includes.
- Add a public graph-API correctness sample and focused geometry, projection, storage, rejection, native transport and SM100 capture tests. No repository Markdown changes.

## Why

FROST already absorbs operand transposes and affine batch ranks, but `_node_to_recorded_op()` has no reshape lowering. An explicit legal reshape therefore interrupts otherwise supported pointwise-to-GEMM fusion. This builds on the ownership and zero-copy contracts from #2073 without changing kernel arithmetic or scheduling.

## Related issues

Related to merged #2073; no linked open issue.

## API and compatibility impact

This is an initial, bounded draft, not a general graph reshape compiler:

- Explicit positive target dimensions, equal element counts and equal source/output dtype are required for fused reshapes. LOGICAL and VIEW_ONLY are served only when their declared layouts match the same logical zero-copy address map. Arbitrary VIEW_ONLY reinterpretations remain outside this engine's support.
- BF16/FP16/FP32 source storage is considered, subject to the existing architecture, dtype, TMA/layout and pointwise gates. Packed/quantized reshape, reductions, MoE and multi-GEMM families are not generalized.
- Reshaped source shapes are fixed by preparation; fresh storage can be rebound. Dynamic dimensions on unreshaped operands retain the existing binding contract. No dynamic factorization is guessed from a new element count.
- Unary and equal-shaped/scalar pointwise paths can be projected. Non-scalar partial broadcasting and operand gen_index are declined rather than changing their coordinates.
- Equivalent shared views are deduplicated while retaining every view path for changed-stride revalidation. A shared input requiring incompatible views, or an observable branch requiring its original incompatible coordinates, is declined. Materialized intermediate views and epilogue/unrelated structural views are not silently absorbed.
- The existing rank-N batch folding restrictions remain in effect after operand projection. A reshape requiring a data copy is not selected as a FROST view.
- Direct DeviceView compositions are supported only when the final layout is contiguous; final strided layouts require a tensor or native variant pack. The public graph route uses native graph-coordinate packs.

New fields/methods are append-only. No generated MMA/mainloop arithmetic or barrier code changes; no GPU speedup claim.
