# frost(gated block): indexer EXTEND-step kernels -- chunk compress, rounding attribute, kbar gather, canonical list (kernels only)

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2056) · state: closed · merged: True

## Original PR description

## Summary

The in-block indexer of the gated attention block (`QsaSpec(index_source="indexer")`) serves a prefill chunk behind a cached prefix in a later change (the EXTEND step: the block stage, its typed declines, the tracker rows and the documentation). This PR lands the **kernels** that step is built from, each with its kernel-level contract and tests, and changes **nothing in the served matrix** -- the new arms are unreachable from the block until the block stage lands, which is why no `Capabilities` / `SUPPORT_MATRIX_TRACKER.md` row moves here (Rule S2's rows land with the block-stage PR).

* **`kernels/qsa_compress.py` -- the ring read-only CHUNK form.** `compile_qsa_compress_step(ring_write=False)` is the step form at T rows with the ring write folded out: a T-row launch would alias every ring slot (the hazard the step form's `cap >= S_q + pool - 1` rule excludes), so the chunk's tail enters the ring by the cache-write launch over the ring's circular slots instead, in stream order. The host rule on that form is the kernel's true bound `cap >= pool - 1` (`min_ring_rows(..., ring_write=False)`); `ring_slots=True` is refused with it; the key is extended off the default only. A chunk-written row is bitwise the from-scratch prefill compress of the same four raw keys (pinned on every residue of the chunk start, chunks of 1 .. 2048 rows, pages 16 / 32 / 64, caps 3 / 4 / 8, the chunks shorter than the group remainder included).
* **The `rounding` attribute, `INDEX_COMPRESS_ROUNDINGS = ("single", "hf")`** (DSL-free in `cache_write_contract.py`; `QsaPrepareIndexArms.rounding` appended), the rounding points of the indexer's two compress chains at all four kernel sites -- the prefill form at pool 4 and at pool 1 (the indexer query), the chunk / decode step form, the fused prepare launch's query and compress arms. `"single"` (default) is today's chain: fp32 through the mean, the norm and the RoPE, one rounding at the store (under the e4m3 cache the e4m3 cast of that bf16 row). `"hf"` is the HF dtype flow -- the pooled key rounded to the io dtype before its norm, the normed row rounded before its rotation, the rotation's three operations each rounded (`tile_dsl.pointwise.round_pair_io` / `rope_rotate_half_io`: one shared helper for the four sites) -- the same rounding points as an HF-style cache row, not its bits: the fp32 reduction orders differ, so the tests gate it as a statistic (99.997 .. 100.000 % of the elements bitwise the HF-rounding oracle at S 5 .. 4096, bf16 and f16, pool 4 and pool 1; the `"single"` arm agrees with that oracle on 67 .. 84 %). Under either value every FROST writer stays bitwise the others. A per-recipe compile key off the default only: today's artifacts keep their keys.
* **`kernels/qsa_kbar_gather.py` (new).** The paged compressed-key cache through the main block table into the contiguous `[B, n_blocks_max, 128]` operand of the compact-logits scorer -- a 16-byte-granule bit copy (bf16 or e4m3, one kernel body); zero rows for an unassigned page and for the rows a dead or short sequence's chunk can read -- plus the extend step's device metadata from `kv_lens`: the per-row visible counts, the per-sequence report (served / dead / shorter than the chunk / past the table's reach) and the per-piece first position **clamped** at `pool x n_blocks_max + pool - 1 - rows`, the memory guard that keeps the scorer's compact writes inside a loose, plan-constant per-piece slab whatever `kv_lens` holds; the host refuses a chunk longer than the table's reach. No SMEM, no mbarrier, no shuffle.
* **`kernels/qsa_canonical_list.py` (new).** The canonical row order of a selected block list in one launch: one warp per row, the 512 slots sorted descending by an in-register bitonic network over `shfl.sync.bfly`, `-1` past the position rule's count (a dead row all `-1` whatever the scorer wrote), the per-row list length; in place legal; `top_k` a runtime multiple of 4 in [4, 512], one artifact for every `top_k` and row count. No SMEM, no mbarrier.

Both new kernels carry no arch pin (any CuTe DSL device from sm_80), gate the DSL floor at `compile_*` (Rule 7) and key the persistent compiled-plan cache on every `Constexpr`. The barrier table and the SMEM table of every kernel touched here are **empty** -- stated in each module docstring together with the per-lane stride of every global access; no async proxy exists, so there is no `fence_proxy` site.
