## Affected area

CI or test infrastructure.

## Summary

Add 60 deterministic convolution cases covering forward, data-gradient, and weight-gradient operations, including ReLU and residual-add fusions. Preserve the existing 16 fixed cases and the convolution fuzzer's default behavior.

- Cover FP16 and FP32 forward/data-gradient/weight-gradient cases, plus BF16 weight-gradient residual cases, with FP32 computation across nine configurations.
- Represent fused convolution edge dtypes explicitly, and validate WGRAD residual precision with eight small FP16/BF16 controls using both low-precision and FP32 edges.
- Exercise both virtual and materialized weight-gradient intermediates, checking every exposed output independently.
- Use exact comparisons for the 16 BF16 residual cases: their integer inputs accumulate exactly in FP32, and the reference includes final BF16 rounding.
- Add 40 reference/argument checks covering rounding, residual addition, bias ordering, activation, default behavior, and invalid fusion requests. A separate GPU regression checks the default materialized-edge dtype.
- Keep case seeds independent of table positions and include the shape in every residual case ID.
- Mark the 60-case expansion L1; keep the small precision and helper regressions L0. CI configuration is unchanged.

- `test/python/conv/graph/test_conv_fixed.py` defines the fixed parameter matrix, executes the cases, and checks final and materialized intermediate outputs.
- `test/python/conv/graph/test_conv_fuzzer.py` provides the shared graph and reference helpers. Optional intermediate settings preserve existing defaults; gradient-output ReLU means a pointwise ReLU after convolution/residual addition, not a ReLU derivative.

## Why

Add reproducible coverage for convolution fusions that should run consistently rather than depend on random selection. Reuse the existing graph and reference helpers, check materialized outputs independently, and use cancellation controls that fail when intermediate precision is changed. ReLU alone and integer-only inputs do not establish rounding sensitivity.

## Related issues

None.

## API and compatibility impact

No public API, binding, or production-library changes. The original 16 fixed cases and generated fuzzer defaults are preserved. Shared helpers reject backward bias epilogues, missing required bias, and intermediate requests for plain convolution before graph setup. Omitting the intermediate dtype keeps FP32 fused edges.

FP32 cases rely on planning-time support checks rather than an unnecessary Ampere minimum. Existing dtype-specific capability gates remain. The eight rounding-sensitive GPU controls qualify WGRAD residual paths, not a universal consumer-precision rule for every convolution engine.

Capability and planning-time support rejections remain skips. Execution failures, non-finite outputs, and numerical mismatches remain failures. This does not expand the library's supported GPU or software configurations.
