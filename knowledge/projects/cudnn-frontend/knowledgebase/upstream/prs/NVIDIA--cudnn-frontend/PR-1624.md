## Affected area

## Summary

Fix NSA selection attention (THD, `is_causal=False`, the default) attending to keys past the end of the
query's sequence when a selected block is the sequence's partial last block. Keys at or past the sequence
end are now masked, next to the existing causal mask. Adds an L0 regression test.

## Why

`HopperSelectAttentionFwd` loads every selected block as one `block_size`-row K/V tile that starts at
`block * block_size` in the sequence (the per-sequence K/V views are widened to `seq_len` rounded up to
`block_size`). When the sequence length is not a multiple of `block_size`, its last block is partial,
and the rest of that tile holds the next sequence's K/V rows, or TMA zero fill past the end of K/V for
the last sequence. The only token-level mask was the causal one (`causal_within_selected_blocks`), so in
non-causal mode those keys entered the softmax. O, M and L of every query that selects a partial last
block then include another sequence's keys (or score-0 keys). The repo's reference
(`run_ref_nsa_selection_attention`) clamps every block to the sequence, and the docs state no length
constraint. Causal mode was not affected: keys past the sequence end are also in the future of every query.

Repro (B200; run from the repository root):

```python
import sys

import torch

sys.path.insert(0, "test/python/native_sparse_attention/cutedsl")
from nsa_reference import run_ref_nsa_selection_attention
from cudnn import NSA

torch.manual_seed(0)
bs, topk, h_q, h_kv, d = 64, 16, 4, 1, 128
for lens in ([1024, 1024], [1000, 1024], [1024, 1000], [100, 64], [70, 130, 64]):
    T = sum(lens)
    q = torch.randn(T, h_q, d, device="cuda", dtype=torch.float16)
    k = torch.randn(T, h_kv, d, device="cuda", dtype=torch.float16)
    v = torch.randn(T, h_kv, d, device="cuda", dtype=torch.float16)
    # Every query selects the last min(topk, num_blocks) blocks of its own sequence.
    idx = torch.zeros(T, h_kv, topk, dtype=torch.int32)
    cnt = torch.zeros(T, h_kv, dtype=torch.int32)
    start = 0
    for s in lens:
        nb = (s + bs - 1) // bs
        sel = torch.arange(max(nb - topk, 0), nb, dtype=torch.int32)
        idx[start : start + s, :, : len(sel)] = sel
        cnt[start : start + s] = len(sel)
        start += s
    idx, cnt = idx.cuda(), cnt.cuda()
    cu = torch.tensor([0] + torch.tensor(lens).cumsum(0).tolist(), dtype=torch.int32, device="cuda")

    O, L, M = NSA.selection_attention_wrapper(q, k, v, idx, cnt, cu, cu, block_size=bs)
    zeros = lambda *shape: torch.zeros(*shape, device="cuda")
    O_ref, L_ref, M_ref = run_ref_nsa_selection_attention(q, k, v, zeros(T, h_q, d), zeros(T, h_q, 1), zeros(T, h_q, 1), lens, idx, cnt, bs, d**-0.5)

    start, err = 0, []
    for s in lens:
        err.append(f"{(O[start : start + s].float() - O_ref[start : start + s]).abs().max().item():.1e}")
        start += s
    print(lens, "max |O - ref| per sequence:", err)
```

The fix masks keys at positions `>= key_end`, where `key_end` is the sequence length, or `t + 1` with
causal masking. The causal mask already covered every position past the sequence end, so the causal path
compiles to the same code as before. The coordinate tensor and `current_block` are now built in both
modes. A selected block that starts at or past the end of its sequence is now fully masked, like a
future-only block under causal masking, so the existing `-inf - -inf` guard applies in both modes;
without it such a block makes the row NaN when it is processed first (the `[64-True]` case of the new
test).

## API and compatibility impact

No API change.

- Causal mode: unchanged. The generated SASS is identical (checked for bf16 block 64 GQA 16, fp16 block 32
  GQA 4 and bf16 block 128 GQA 16), and O, M
  and L are bitwise identical to develop on 24 ragged causal configurations (fp16 / bf16, block 16 / 32 /
  64 / 128, (H_q, H_kv) = (1, 1) / (4, 1) / (32, 2)).
- Non-causal mode: results change only for queries that select a block extending past the end of their
  sequence. When every sequence length is a multiple of `block_size`, O, M and L are bitwise identical to
  develop.
- Performance (non-causal): the token-level mask now runs on every selected tile, as it already did in
  causal mode. Kernel time on B200, CUDA events, 20 warm-up + 200 timed launches per round, median of 9
  rounds, develop and this PR compiled and timed alternately in one process on the same buffers, plus an
  independently compiled copy of the unchanged kernel as a control; the last column repeats the
  measurement on a second B200 (100 timed launches per round):

  | shape (block 64, top-16, D 128) | develop | this PR | control | second B200: this PR (control) |
  |---|---|---|---|---|
  | T 4096 = [2000, 2096], H_q 32 / H_kv 8, bf16 | 1439 us | +0.3% | +0.3% | +1.3% (-0.1%) |

  Over six runs on the first B200 the GQA-16 delta was +3.7% to +5.8%; in causal mode all three shapes stayed within the
  control's spread. Skipping the per-element mask with a warp-uniform branch on tiles that end before
  `key_end` measured the same on this compiler, so this keeps the per-element form the causal path
  already uses.

Not changed here: a key row past the end of the sequence still enters P·V with P = 0, so a NaN or Inf in
the next sequence's V rows inside the partial tile still reaches this sequence's O (0 × NaN). Finite
values no longer leak. K rows are safe, because their scores are overwritten with -inf.
