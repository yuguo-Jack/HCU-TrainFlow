## Affected area

FE OSS kernels or CuTeDSL

## Summary

`compress_topk_cand_buffer_size` sizes the paged BSHD candidate buffer for the single launch that paged K runs.

- `paged=True` (appended, default `False`): full `bs * per_batch_floats` buffer, `microbatch_rows > 0` rejected with the launch's error.
- Same shape as the existing LSE and block-scaled single-launch branches.
- Before: the default `microbatch_rows=-1` sized an auto-microbatch window at `seqlen_q >= 32768`, so a paged launch raised `cand_buffer too small`.
- Docs name both paged sizing calls (BSHD and THD).

## Why

Follow-up to #1823: its last open review comment, [Align paged candidate-buffer sizing with the single-launch path](https://github.com/NVIDIA/cudnn-frontend/pull/1823#pullrequestreview-5638436322).

## Related issues

Related to #1823.

## API and compatibility impact

- `compress_topk_cand_buffer_size`: optional `paged` appended, dense callers unchanged.

## Testing

- `test_DSA_indexer_forward_paged_declines`: at `bs=2, seqlen_q=32768, seqlen_k=8192, ratio=4` the paged size equals the `microbatch_rows=0` size and exceeds the dense default.
- Same case: `paged=True` with an explicit microbatch raises.
- Paged indexer and compressed top-k suites pass.
