# shim: gate causal_conv1d_forward/backward on the runtime backend version

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2214) · state: open · merged: False

## Original PR description

## Problem

`detail::causal_conv1d_forward` / `causal_conv1d_backward` (cuDNN 9.22 API) were guarded only by `#if CUDNN_VERSION >= 92200`. A frontend built against newer cuDNN headers but running on an older backend (dynamic loading) looks up `cudnnCausalConv1dForward` / `cudnnCausalConv1dBackward`, which do not exist there, and throws `RuntimeError: Unable to find symbol ...`.

Every later causal conv1d wrapper already checks the runtime version and returns `CUDNN_STATUS_NOT_SUPPORTED` when the backend is too old: NWH and B2B (9.24), FFT and long-FFT (9.26).

`test_causal_conv1d_rejects_unsupported_kernel_size` shows it. For `kernel_size = 1` the binding's precheck lets the call through to the shim (it only rejects sizes above the maximum). The 9.22 pair then raises the symbol error instead of the expected `ValueError`, while the NWH/B2B cases get `NOT_SUPPORTED` and the `ValueError`.

## Change

- `cudnn_frontend_shim.h`: `causal_conv1d_forward` and `causal_conv1d_backward` return `CUDNN_STATUS_NOT_SUPPORTED` when `get_backend_version() < 92200`. Inside the `#if CUDNN_VERSION >= 92200` block the compiled version is already at least 9.22, so only the backend version needs checking.
- `get_backend_version()` is defined further down the header, so it is forward-declared before the pair.
- The Python bindings then behave as they do for the other wrappers: the kernel-size `ValueError` for an out-of-range size, otherwise `cudnnCausalConv1dForward failed with status 9`.

## Tests

`test/python/causal_conv1d/torch/test_causal_conv1d.py`, frontend module built from develop 97b7bc31 with cuDNN 9.27 headers:

| GPU, backend | develop | this change |
|---|---|---|
| L40S (cc 8.9), cuDNN 9.21.1 | 2 failed, 15 passed, 22 skipped (`Unable to find symbol cudnnCausalConv1dForward` / `...Backward`) | 17 passed, 22 skipped |
| L40S, cuDNN 9.27.0 | 37 passed, 2 failed | 37 passed, 2 failed (the same two cases) |
| V100 (cc 7.0), cuDNN 9.10.2 | the same two `rejects_unsupported_kernel_size` cases fail with `Unable to find symbol` | not run |

The two failures on 9.27 are unrelated to this change. They are `test_causal_conv1d_nwh_autograd[fp64-k4-*]`, where `cudnnCausalConv1dNwhForward` returns status 3010 (`CUDNN_STATUS_NOT_SUPPORTED_SHARED_MEMORY_INSUFFICIENT`) on this GPU.

`pre-commit` (clang-format) on the header passes.
