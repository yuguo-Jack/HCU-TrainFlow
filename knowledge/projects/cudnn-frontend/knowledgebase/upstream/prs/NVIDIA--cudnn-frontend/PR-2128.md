# perf(sdpa): shrink SM80 short-query D128 CTAs

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2128) · state: closed · merged: True

## Original PR description

SM80 dense D128 queries with at most 64 declared query rows currently use a 128-row CTA with eight warps. This change uses 64 rows and four warps when TILE_M is unset, keeping sixteen rows per warp and avoiding work on the unused half of the CTA. Explicit 128-row requests and the defaults for longer queries, other head widths and THD remain unchanged.

Standalone TILE_M=64 requests in the D128 envelope now select four warps, including masked and packed THD execution. The existing kernel body, memory addressing, arithmetic, workspace contract and graph eligibility are unchanged. The graph row does not gain a tile-knob domain; placement and candidate ranking are unchanged.

Validation:

- 14 host boundary checks pass; the parent fails six of these checks.
- 174 native A100 checks pass, including 20 new FP16/BF16 cases and 154 existing prepared-path checks. They cover causal/BR/SWA masks, Stats log bases, sinks/bias/padding, nonpositive and large scales, declared strides, fresh bindings and CUDA Graph replay.
- Four scoped Compute Sanitizer memcheck cases pass with zero errors. FP64 reference matmuls run on CPU for this check because the installed cuBLAS emits internal-symbol lookup diagnostics under sanitizer; all CUDA API and memory checks remain enabled.
- Scoped formatting and SPDX hooks pass.
