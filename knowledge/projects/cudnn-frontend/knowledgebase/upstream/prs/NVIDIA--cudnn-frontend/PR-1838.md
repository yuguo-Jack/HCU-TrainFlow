# fix(sdpa): admit paged D128 partial PackGQA on SM107

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1838) · state: closed · merged: True

## Original PR description

Paged D128 FP16/BF16 GQA groups such as 6 or 12 were rejected on SM107 before compilation, even though the shared two-CTA kernel already supports partial head groups. This also breaks the existing paged THD work-lookup replay test on current develop.

Use one predicate in graph and standalone admission to accept exact D128/V128 paged THD partial packing with CGA2 and no split. The kernel continues to pack `gcd(GQA, 128)` heads. Other CTA/split/head-dimension domains keep their existing limits, and automatic candidate ordering is unchanged. The support matrix records this scope.

Validation of the production change on head `8fd10c4cc3dc`: 1,563 metadata/geometry/admission tests and 28 native SM107 paged replay cases passed, with no skips or failures. The 28 cases comprise the four existing paged-lookup cases plus 24 expanded partial-group cases. Exact develop `5169b2691674` reproduced the original `12/2 does not pack at tile_m=128` failure before execution. Metadata tests cover graph/standalone agreement and typed declines; GPU cases cover FP16/BF16, GQA6/12/24, NHD/HND pools, NATURAL/LPT, token/head-major Stats, FP64 references, changed lengths and page tables, dead rows and all-empty retained CUDA Graph replay. The native extension was rebuilt from the current develop source before qualification.

Changed-file pre-commit and diff checks passed. Source and native binary identities were verified before and after each arm. This change does not modify kernel code, execution bindings or heuristic ordering. Public CI remains pending; the coordinated CI minimum-version fix is tracked separately. No new performance or sanitizer claim.

Review follow-up `09b03e88fb7d` adds assertions that every observed module uses the requested `PACK_GQA` mode and the expected `gcd(GQA, 128)` group. All 28 paged replay cases passed again on that exact head with no skips or failures; the production implementation is unchanged. The 1,563 contract cases and baseline RED above are the earlier run, not a second execution.

**Assert the packing mode of the loaded kernel in the paged replay helper.**

`_build_graph` records every loaded kernel module and asserts only `_BOUNDED_THD_DECODE` and, for paged runs, `CFG.PAGED_KV`. Nothing asserts `CFG.PACK_GQA`. The replay assertions check O/Stats values and dead-row NaNs, which an unpacked kernel can also satisfy. A regression that drops the requested packing would therefore pass these cases. Add a check that the recorded modules run the requested packing mode:

```diff
     assert loaded and all(m._BOUNDED_THD_DECODE == (q.dtype == torch.bfloat16) for m in loaded)
+    assert all(int(m.CFG.PACK_GQA) == pack for m in loaded), "The executed kernel must use the requested packing mode"
```

Optionally, also check `CFG.PACK_G` against `math.gcd(hq // hkv, 128)` for packed partial groups. This needs `import math` in the test module.
