## Summary

- Add canonical BF16 torch layouts to grouped GEMM, GLU, dGLU, and wgrad:
  - A/C/D: (m, x)
  - probability tensors: (m,)
  - dense weights: (experts, n, k)
- Normalize canonical operands inside the compiled kernel without execute-time copies or conversions.
- Preserve legacy kernel-facing layouts and existing JAX behavior.
- Avoid device-to-host reads when fresh offset and pointer tensors are supplied to warm executions.
- Expose supports_bf16_canonical_layouts for integration feature detection.
- Treat default-stream sentinel handles as a no-op when torch is already on its default stream.


## Why

Transformer Engine uses natural row-major BF16 operands and may provide freshly allocated offset and pointer-table tensors on each invocation.

Previously, callers had to construct kernel-specific views, and identity-based validation caches could miss for fresh metadata tensors, causing blocking device-to-host reads during execution. This added host overhead and prevented CUDA Graph capture.

The new path compiles canonical operand ranks directly and converts them to kernel-facing layouts during tracing. Runtime validation is based on operand metadata, keeping warm execution asynchronous and allocation-free.
