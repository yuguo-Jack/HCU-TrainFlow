# sdpa(bwd): exclude runtime KV padding from the SM80 backward's K/V loads

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2200) · state: open · merged: False

## Original PR description

## Problem

#2135 made runtime padding unread data for the SM80 forward bodies. The SM80 backward (`sdpa_bwd_sm80`, `bprop_f16`) still loads K/V rows past a dense batch's `seq_len_kv`. `GATE_KV` covers only a static partial tile and THD, and on a dense padded graph `kv_bound` is the declared S_kv. The Q side is already bounded by `seq_len_q`.

P is masked to 0 on those rows, but:
- dP = dO·Vᵀ over a NaN pad row is NaN;
- dS = P·(dP − δ) is 0·NaN = NaN;
- dQ += dSᵀ·K then carries it into every valid dQ row.

The kernel's own comment says the zero-fill exists to keep exactly that term clean ("no NaN leak into valid dQ"); it just isn't applied to runtime lengths.

On an A100 (cc 8.0), develop d760fefe, with NaN in the Q/dO/O padding past `seq_len_q` and in the K/V padding past `seq_len_kv`: 12 of the new test's 16 cases return NaN in valid dQ rows. The 4 that pass are causal with s_q < s_kv, where the mask never reaches the padded KV rows.

## Change

- `bprop_f16.py`: for dense graphs with `seq_len_kv`, the K and V loads now zero-fill rows at and past `min(seq_len_kv, S_kv)`, the same way they already do past a partial tile.
  - P masking, the stores and the THD path are unchanged.
  - Zero-filled pad rows also give 0 instead of NaN in the dK/dV rows that the padding covers.
- The D64 fast path (`bprop_d64_f16`) serves only plain dense graphs, never padded ones, so it needs no change.
- New `test/python/sdpa/frost/test_sdpa_bwd_sm80_padding_nan.py`.
  - Fills the Q/dO/O padding past `seq_len_q` and the K/V padding past `seq_len_kv` with NaN.
  - Checks the valid rows of dQ, dK and dV against a reference computed on clean data.
  - Covers D64/128/192/256, fp16/bf16, causal and non-causal, with s_q = s_kv and s_q < s_kv.

## Tests

On an A100 (cc 8.0), develop d760fefe:
- New test: 12 failed on develop (NaN in valid dQ), 16 passed with this change.
- With this change, the SM80 backward suites pass: 341 passed, 68 skipped. The suites are `test_sdpa_bwd_native_artifacts_sm80`, `_native_execution_sm80`, `_native_strides_sm80`, `_prepared_sm80`, `_prepared_thd_sm80`, `_staged_sm80`, `_thd_sm80`, `_thd_sm80_offsets` and `test_sdpa_sm80_padding_nan`.
- `pre-commit` on the touched files passes.
