# perf(sdpa): extend SM80 short-query tiling for D128 and D192

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2130) · state: closed · merged: True

## Original PR description

Short dense D128 queries with 65–128 rows and D192/V128 queries with up to 64 rows still use 128-row, eight-warp CTAs. Extend the 64-row, four-warp lowering to these cases; the D192 tile also reduces the shared-memory footprint. Explicit TILE_M requests keep their requested size, and explicit 64-row D192-envelope tiles use the matching four-warps configuration, including standalone THD.

Builds on #2128; land that dependency first. This changes kernel lowering and focused tests. Same-device paired replay shows an aggregate improvement, retaining a small MHA regression; the measured tradeoff is intentional.

Validation:
- Host regression: parent has 9 failures and 16 passes; candidate has 25 passes.
- 192 native A100 tests pass, covering FP16/BF16, query boundaries, masks, strided buffers, fresh bindings, CUDA Graph replay, explicit THD tiles and existing prepared-execution contracts.
- Eight scoped Compute Sanitizer memcheck cases pass with zero errors.
- Ten existing development cases, both orders: 40 committed-source default-versus-baseline replay observations pass full FP64 O/Stats and canary checks. Longer-query controls retain their existing behavior.
- Scoped pre-commit passes.
