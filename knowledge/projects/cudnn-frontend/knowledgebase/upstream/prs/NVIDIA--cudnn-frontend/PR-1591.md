# test(gated_attention_block): the SDPA stage's bf16 bound form holds on the residual after the fp8 flips' exact rank-1 terms (the dense GQA dV d-row of the 212-SM dataset)

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1591) · state: closed · merged: True

## Original PR description

## Summary

The fp8 gated attention block's two backward suites (dense `test_fp8_stage_localised_bounds`, packed `_assert_sdpa_stage_per_sequence`) hold the SDPA stage's bf16 `dQ / dK / dV` to the bf16 block's per-cell bound (`2^-7 max|ref| + 2^-6 |ref|`, `cos >= 0.999`) through `_assert_grad_close`. A per-cell bound is not a bound of the e4m3 flip class: the kernel and the reference quantize `P * 2^8` and `dS * scale_dp` to e4m3 independently from fp32 values a few 1e-6 apart, and where the two straddle a rounding midpoint one WHOLE d-row of the output moves by the exact rank-1 term `(c_alt - c_ref) x descale x operand row` -- a magnitude set by the e4m3 spacing and by `|dO|` / `|Q|` / `|K|`, not by `max|ref|`. This PR gives that pin the e4m3 flip-structured shape both suites already use for `dW_o` and `dW_qkvg`: one shared helper, `_assert_sdpa_stage_flip_structured`, at both call sites. A cell with no d-row outside the bound takes `_assert_grad_close` itself (same code path, same print, same return); a d-row outside must be PROVEN one flip from the reference's own intermediates by the fp8 SDPA row's own proof (`sdpa.fp8.flip_evidence`, the engine behind `assert_close_fp8_grad`, run with the bf16 bound as its tolerance), the flipped rows stay within the row recipe's budget `max(1, 1e-5 x rows x keys)`, and the fp64 residual after the exact rank-1 term is inside the UNCHANGED bound on every cell; anything else fails with the previous message plus the attribution. Nothing is widened.

Fixes #1575. Follows up the two comments on #1505 (the dataset detector they asked for ran; its result is below).

## The failure

`test/python/gated_attention_block/cutedsl/test_block_thd_backward_fp8.py::test_thd_fp8_gradients_match_the_per_sequence_modelled_oracle[dense-gqa_8_2]` on the `python/*/cutedsl:cutlass-4.8:sm107` nightly job: the only red of that job (1 failed, 6145 passed), deterministic across the two nightly schedules since #1505 merged, identical numbers both days:

```
AssertionError: dV seq 1 [300:428] vs the row's reference (the bf16 bound form): max|diff|=0.003906 max|ref|=0.334 worst cell 1.357 of the bound (rtol=0.015625, atol=0.0078125*max|ref|) cos=1.000000 torch.bfloat16
```

Characterisation (the module's own `_report_stage_difference` print and the captured cell): 1 of 256 d-rows of the 128-token sequence's dV is outside the bound (key 117 of kv head 0; 2 of its 256 cells), rel RMS 8.19e-4, `cos 1.000000`; the same sequence's dQ / dK have 0 d-rows outside (worst 0.000 / 0.144 of the bound); dV is bitwise the reference on the other three cells of the matrix. The fp8 row recipe (`assert_close_fp8_grad`, atol 0.08 / rtol 0.2 + the flip budget) passed the cell with 0 elements outside its atol, so its flip proof never ran; only the stricter bf16 bound form fired.

## The detector (AGENTS.md, "A numerics failure on ONE CI lane") -- a dataset, not a kernel and not the packed path

- **Captured** on a 212-SM Rubin part (cc 10.7, cuDNN 9.27 backend, develop at the base of this PR): the official run of the function there is 1 failed / 3 passed with the identical message; everything the cell consumes and produces was saved (the pre-quantization bf16 draws, the e4m3 slots, lse, delta, scalars, the per-sequence references and their full `p_scaled / ds_scaled / valid` intermediates).
- **Replayed** on a 204-SM Rubin part with the captured inputs substituted for the generator's draws: 63 of 63 kernel outputs are BITWISE the 212-SM run (inputs, dy, the forward record, every backward workspace slot including dq / dk / dv, delta, every gradient, `scale_dp`, 28 scalars), and the bf16 bound form fails with the same statistics (the same d-row, 1.357, 0.003906 / 0.334, 2 cells). The 204-SM part's own dataset passes both forms on all 9 (sequence, output) cells, dV of that sequence bitwise the reference. torch's device Philox lays its draws out by SM count, so one `manual_seed` is a different dataset per SM count: the 212-SM dataset carries the flip, the 204-SM dataset (measured here) and the 216-SM one (reported on #1505) do not.
- **Dense vs packed A/B** on the 212-SM part: the dense per-tensor fp8 block at B = 1, S = 128 over the sequence's exact bytes (delayed grad scaling at the packed run's read-back scales, the packed `scale_dp` 512) has a bitwise forward record (out, slab, o, lse, rstd, q8 / k8 / v8 / o8) and bitwise every backward intermediate (dy8, do, do8, og8, q8, k8, v8, delta, dq, dk, dv, dqkvg, dqkvg8) against the packed rows, and its dV fails the bf16 bound form with the identical 1.357 -- the packed chain is not involved.
- **Attribution**, from the captured reference intermediates (independently of the helper): the red d-row's own reduction has 512 candidate positions (q heads 0..3 of kv head 0 x 128 queries), all valid (dense), 26 within 1/32 of a code spacing of an e4m3 midpoint, and exactly ONE satisfies every condition: `P[b 0, q head 3, i 33, j 117] x 256 = 8.5`, the midpoint of the adjacent codes +8 / +9 -- the reference rounds it to +8 (round-to-nearest-even), the kernel to +9; the exact term `+1 x 1/256 x dO[0, 33, 3, :]` reproduces the row to 0.117 of the bound, fits as 0.992 flips, 0 cells outside after it. `max|diff| = 0.003906 = 2^-8` is that one code step (spacing 1 in `[8, 16)`) x `1/256` x `|dO| = 1`: two bf16 ulps at `|ref| 0.33`, on a cell with `|ref| ~ 0.017` whose bound is `2^-7 x 0.334 + 2^-6 x 0.017 = 0.00288`, hence 1.357. One more candidate satisfies the tolerance condition alone (q head 1, i 1: a half-code step, residual 0.975 of the bound) and fits as 0.23 flips: the fit band `1 +- 1/2` rejects it -- the band is load-bearing on this cell, not decorative.

## The form (one helper, both suites)

`_assert_sdpa_stage_flip_structured(got, ref, what, *, kind, keys, operand, flip_unit, intermediates, fp8_dtype=e4m3, out_dtype=bf16) -> worst` in `test_block_backward_fp8.py`, imported by the packed module; both call sites keep their byte-identical `what` strings (the message prefix above stays greppable). In assertion order, with the bound `_ATOL_FRAC max|ref| + _RTOL |ref|` unchanged throughout:

0. finite; **no d-row outside the bound -> `return _assert_grad_close(got, ref64, what)`** -- the identical path, so a cell inside the bound passes exactly as before and the form adds nothing below it;
1. the old statistics line is printed, `cos >= _COS_MIN`;
2. the d-rows outside stay within the row recipe's budget `_row_budget(rows, keys) = max(1, 1e-5 x rows x keys)` (the module's one formula; the floor, 1, at this cell's 256 d-rows x 128 keys) -- a systematic shift is many rows, each "one flip", and is named here before any reference re-run;
3. every d-row outside is PROVEN one flip by `sdpa.fp8.flip_evidence` run with THIS bound as its ordinary tolerance: a VALID position of the row's own reduction (same batch, a q head of the kv head's GQA group, unmasked), the reference's scaled intermediate within 1/32 of a code spacing of the midpoint of two ADJACENT e4m3 codes, the exact term reproducing the row within the bound on every cell and within bf16's own rounding (atol + half a bf16 code spacing from each side), the least-squares flip count within `1 +- 1/2`; a row that is not one flip fails with `_explain_unfit_row`'s diagnosis printed;
4. the proven flips' exact rank-1 terms `u x flip_unit x gain x operand[operand_row]` are removed in fp64 and the residual is inside the unchanged bound on EVERY cell -- the proof's tolerance condition restated in the suite's arithmetic and message, the magnitude cap a defect fails.

`sdpa/fp8.py` gains the public, additive `flip_evidence(actual, expected, bad_rows, atol, rtol, *, tag, kind, operand, flip_unit, fp8_dtype, intermediates, out_dtype=None)` (wraps the existing `_flip_evidence`; never asserts; refuses a `kind` outside `_FLIP_KINDS`, a packed `[T, h, d]` output and a bad-row mask of the wrong length as `ValueError`) and `describe_flip`, the per-fit line `assert_close_fp8_grad` printed, factored out byte-identically (the recipe now prints through it; its behaviour is unchanged and the 44 pre-existing self-tests pass as before).

Keyed on cells OUTSIDE the bound, the form widens nothing and catches nothing new below it; above it, it is stricter than the per-cell bound (a row explained by a flip still has to hold the bound on every cell after the term; a row not explained fails as before).

## Nothing widened

`_ATOL_FRAC`, `_RTOL`, `_COS_MIN`, `_FP8_GRAD_TOL`, `_MIDPOINT_WINDOW`, `_ONE_FLIP_BAND`, `_ROW_BUDGET_FLOOR` and `_row_budget` are untouched; the diff changes no numeric constant (every removed line with a digit is a docstring, a comment, the two replaced call lines, the moved print or an import). Inside the bound the path is `_assert_grad_close` verbatim; outside it, a row without a proven flip fails with the previous message. A kernel defect that is exactly one adjacent e4m3 code at a midpoint position is indistinguishable from the class by construction and IS the class (the statement `assert_close_fp8_grad` already makes for fp8 outputs); a second flipped row within one 128-token sequence fails the budget and is worth a look, not a widening.

Not changed here: the packed module's `assert_close_fp8_grad` call passes no `kind=`, so if ITS cap ever failed on a packed sequence the recipe would raise `ValueError` (the tag is not a flip kind) instead of running its proof -- unreachable today (that cap, 4 x 0.08, sits at `max|ref|` on these cells) and outside this fix; one keyword in a follow-up.
