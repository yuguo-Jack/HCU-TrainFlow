## Affected area

FE OSS kernels (linear attention, SM90 CUDA KDA)

## Summary

**Release 1.31: please cherry-pick into `1.31.0-rc`.** The change applies unchanged there.

#1454 made `x * rsqrt(sum(x*x) + 1e-6)` the qk L2-norm contract for every LA engine. The SM90 CUDA forward kernel (`kda_fused_sm90.cu`) kept F.normalize's `1 / max(||x||, 1e-12)`. A KDA graph with `use_qk_l2norm_in_kernel` and small-norm q/k rows therefore gives different results on `kda_hopper_cuda` (default on H100) than on FROST (B200). This breaks the one-contract rule (`python/cudnn/AGENTS.md` Rule 8). `test_la.py::test_fwd_qk_l2norm_small_rows[hopper_cuda-kda]` fails on every sm90 CI lane, including nightly 72349147 (`o rms ratio 1.101 >= 0.02`).

**Fix.** The kernel now uses `rsqrtf(sum_sq + 1e-6f)`. A zero-filled out-of-range row still normalizes to zero. The CUDA backward declines `use_qk_l2norm` (`cuda_engine.py`), so it needs no change. The NVRTC cubin cache is keyed by source content, so no stale cubin survives.

**Out of scope, noted:** the vendored, opt-in CAKE forward (`flashkda_training_c16.cu:1130`) still uses `rsqrt(max(sum_sq, 1e-12))`, while its backward uses `+ 1e-6`. That is upstream code pinned by `SHA256SUMS`, and `kda_cake` declines unless opted in.
