# feat(norm): prototype typed pointwise epilogue fusion

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2225) · state: open · merged: False

## Original PR description

## Summary

Prototype a typed pointwise epilogue for the existing LayerNorm/RMSNorm row kernel, using existing graph nodes rather than introducing a dedicated fused-operation API:

```python
h, rstd = graph.rmsnorm(...)
z = graph.mul(gate, h)
y = graph.add(residual, z)
```

The prepared lowering also handles add/mul DAG branches that share the norm result, arbitrary-rank right-aligned broadcasts, and independently typed pointwise outputs. The norm result and intermediate pointwise results stay in registers; the entire example captures as one kernel rather than three.

**This is intentionally a draft prototype, not a ready-to-land public graph feature.** It consumes public graph node declarations through the internal `cudnn.norm.epilogue.prepare(graph)` entry, but is **not registered in engine discovery**. Consequently the ordinary `graph.execute()` lifecycle does not yet select this fusion.

## Implementation

- Build a topologically ordered SSA pointwise program and broadcast address layouts from graph declarations.
- Keep graph/host preparation in `norm/epilogue.py` and device emission in `norm/epilogue_codegen.py`.
- Extend the existing row kernel with optional compile-time epilogue arguments; the default norm path remains unchanged. Do not duplicate reduction, staging, or normalization code.
- Cast the norm result to its declared output dtype before evaluating the DAG, then preserve compute/output dtype semantics at every pointwise node. Explicit `add.rn.f32`/`mul.rn.f32` prevents cross-node FMA contraction: a plain FP32 cast was insufficient in the initial experiment.
- Compile from fake tensors at prepare time. Execution validates current storage, binds zero-copy dense views, and launches without tensor conversions, device allocations, device-to-host reads, or additional kernels.
- Preserve observable mean/rstd outputs and reject output/input overlap. Deduplicate identical tensor roles for UID/name binding when X is also a residual input.

## Current support boundary

- Ordinary forward LayerNorm/RMSNorm; fixed positive dense row-major declarations.
- FP16/BF16/FP32 inputs, norm output matching X, FP32 computation, typed add/mul outputs and dense broadcast auxiliaries.
- One bound final pointwise output; intermediate norm/pointwise results must be virtual. Saved statistics may be outputs but cannot be consumed by this epilogue yet.
- Declared target gate: SM90/SM100/SM103. **Native validation below is SM90 only**, not Blackwell qualification.
- No adaptive/zero-centered affine fusion, generic dynamic shape rebinding, non-dense layouts, unary pointwise operations, or public engine-discovery integration yet. Unsupported declarations decline before compilation.
- No documentation or standalone sample changes in this prototype.

## Validation

Native NVIDIA H20 (SM90), cuDNN backend 9.19, PyTorch 2.11.0+cu128, CuTe DSL 4.8.1:

```bash
cd test/python
python -m pytest \
  norm/graph/test_frost_norm_pointwise_epilogue.py \
  norm/cutedsl/test_frost_norm_stability.py \
  norm/graph/test_frost_norm_engine_e2e.py \
  -n 0 -x -q
```

- **22 passed, 1 deselected** under the repository's default L0 selection; 20 are new prototype tests.
- New tests cover ranks 2/3/4; FP16/BF16/FP32; vector/scalar stores and widths 128/133/64/129; mixed intermediate/final dtypes; branches; broadcasts; shared-input name binding; invalid layout/op/broadcast/observability/binding and alias rejection.
- Bitwise equality with the same norm kernel followed by independently rounded pointwise operations, plus an independent FP32 norm reference with tolerance.
- Explicit nondefault stream, changed-input graph replay, NaN-poisoned output, same-input repeatability, and test-owned graph reset in `finally`.
- CUDA Driver graph inspection asserts exactly one captured kernel. Execute guards forbid allocation/conversion/recompilation and check blocking CUDA synchronization.
- Compute Sanitizer **memcheck and synccheck: 20 passed each, 0 errors**. These runs use `PYTORCH_ALLOC_CONF=expandable_segments:False` (and the legacy alias) to avoid a local `cuMemCreate` permission failure in Torch's expandable allocator; the kernel implementation is unchanged.
- Scoped pre-commit and `git diff --check` pass.

## Exploratory performance (not an acceptance criterion)

Local, uncommitted measurement harness; shared H20 hardware, BF16 RMSNorm followed by FP32 row gate multiplication and BF16 residual addition. The baseline uses the same norm row configuration and preallocated pointwise outputs (three kernels), not allocating eager expressions. Seven samples, alternating order, median GPU CUDA-graph replay time; CPU enqueue is measured separately with compilation/synchronization outside the timed region. Changed-input replay is checked bitwise after timing. Driver graph inspection confirms one fused node versus three separate nodes.

| X shape | Separate GPU replay | Fused GPU replay |
| --- | ---: | ---: |
| (1, 1, 4096) | 11.16 us | 5.96 us |
| (1, 32, 4096) | 11.28 us | 5.94 us |
| (4, 128, 4096) | 26.88 us | 12.84 us |
| (4, 128, 8192) | 50.79 us | 18.73 us |

These fixed-configuration spot checks are indicative, not an isolated application benchmark or a comparison against all available tuned implementations. Python binding overhead is not tuned.
