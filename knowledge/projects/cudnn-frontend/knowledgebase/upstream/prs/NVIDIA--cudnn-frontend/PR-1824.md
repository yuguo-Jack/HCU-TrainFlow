# perf(sdpa): coalesce D128 THD split partial output stores

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1824) · state: closed · merged: True

## Original PR description

D128 THD split-KV attention writes an FP32 partial output for each split before combining the results. The current store mapping scatters adjacent rows across memory sectors. This change pairs neighboring lanes: each writes 16 bytes of the same row, together covering a 32-byte sector. Four register shuffles per eight values supply the partner lane's half.

The helper applies to aligned, D-contiguous D128 THD partial buffers in the shared SM100/SM107 single-CTA kernel. Normalization remains per row, and exchanged row/head/liveness metadata preserves partially populated tiles and packed query heads. Other layouts retain the existing store path. There is no additional shared-memory scratch, barrier, launch, public knob, or host preparation/execution work.

Validation on develop 35150c04 plus this one-file change, with cuDNN 9.27:

- B200: existing focused suite: 188 passed on baseline and 188 passed on candidate.
- SM107: the same 188-case suite passed on both sources; 32 additional existing sink/capture cases passed on the candidate.
- Numerical and lifetime probes cover FP64-reference O and requested LSE, pointer rebinding, retained CUDA Graph replay, dynamic lengths, packed/unpacked heads, and tail/empty rows.
- SM107 candidate: two focused cases passed full-process memcheck; two passed FE-kernel-filtered racecheck with zero reported hazards/errors. The racecheck statement is limited to the selected FE kernels.
- Performance was checked with distinct source-verified baseline/candidate graphs, shared input/output addresses, and repeated interleaved measurements in forward/reverse geometry order. Measurements are retained privately; this PR does not claim a serving speedup.
- Scoped formatting/license hooks and `git diff --check` passed. Existing tests are reused; no heuristic-selection or timing golden is added.
