## Affected area

Tests (`test/python/tiers`).

## Summary

#1702 re-parametrized `test_d128_f16_folds_the_split_out_of_the_band_builds` with cga, dtype and cc axes. The `[causal]` id listed in `tiers/smoke_cc100.txt` and `tiers/smoke_cc107.txt` therefore no longer collects. As a result, `test_tiers.py::test_every_listed_cell_collects[smoke_cc100.txt / smoke_cc107.txt]` fails in every `python_tests` pipeline (seen on #1848 and #1849, which change neither the test nor the tiers).

This PR points both smoke tiers, and their `*_code_paths.tsv` maps, at the equivalent new cell `[causal-cga2-bf16-cc100_on]`: dense causal, cga2, bf16, cc 10.0 gate on. That is what the old single cell exercised.

#1702's own CI ran the `frost` target only, which does not include `test_tiers.py`. That is why this slipped through.
