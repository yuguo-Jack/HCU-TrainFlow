## Problem

A captured `torch.cuda.CUDAGraph` that a test leaves in a reference cycle is destroyed whenever Python's cycle collector next runs. That can happen inside a *later* test's capture, and destroying an executable graph mid-capture invalidates that capture: `operation failed due to a previous error during capture`. The failure lands on an innocent test and depends on order and timing.

- `test/AGENTS.md` ("CUDA Graph test lifetimes") already requires test-owned graphs to be reset. Nothing enforces it.
- Mechanism, reproduced standalone with torch 2.13:
  - leak a captured graph in a cycle, `gc.collect()` inside another capture → that capture fails;
  - `reset()` the leaked graph first → the capture succeeds.

To measure the scope, a pytest probe wraps `CUDAGraph.__init__`/`capture_end`/`reset`. After each test, it classifies every graph the test created as freed, cyclic or held. It also records whether the graph was "armed": captured and never reset, the only state whose destruction hurts.

A full sdpa/frost run with the detector below found one more armed leak, in `test_sdpa_prepared_thd.py::test_thd_output_row_stride_above_int32_reaches_device_descriptors`. Whether a graph lands in a cycle can depend on test order: the paged test leaks in suite order but not alone.

## Change

- **`test/python/conftest.py`:**
  - Wraps `torch.cuda.CUDAGraph` `__init__`/`capture_end`/`reset` to track graphs per test.
  - After teardown, if a graph the test created is still alive and armed, runs `gc.collect()` between tests, where destruction is harmless.
  - Fails the test in teardown if the collector freed an armed graph.
  - Tests that reset their graphs, or drop them by refcount, pay nothing.
- **Leaks fixed with `try/finally graph.reset()`:**
  - `sdpa/frost/test_sdpa_fwd_paged_sm100.py::test_paged_adapter_cuda_graph_replay_no_host_sync`
  - `sdpa/frost/test_sdpa_prepared_thd.py::test_thd_output_row_stride_above_int32_reaches_device_descriptors`

  - `gemm/cutedsl/test_grouped_gemm_dglu_bf16_training.py`
- **`test/AGENTS.md`:** the CUDA Graph lifetime rule now names the detector.

On CodeRabbit's outside-diff Minor ("Preserve capture state after early graph collection", `conftest.py:235-241`): not changing this.

- **What the detector protects.** The hazard is a captured graph destroyed *inside a later test's capture*. Collecting between tests at teardown removes that hazard whether or not this test's own report fires.
- **Collection during the owning test is self-reporting or harmless.** If the cycle collector frees a captured graph while its own test is running, then either:
  - the free happens outside any capture, which is harmless; or
  - it happens inside that same test's later capture, which fails that test visibly.
- **The suggested callback adds false positives.** A weakref finalizer cannot tell a cycle-collector free from an ordinary refcount free: for example, a graph captured inside a helper and dropped when the helper returns. With the callback, those would be reported as leaks. Telling the two apart would need `gc.callbacks` bookkeeping, which is more machinery than this miss is worth.
