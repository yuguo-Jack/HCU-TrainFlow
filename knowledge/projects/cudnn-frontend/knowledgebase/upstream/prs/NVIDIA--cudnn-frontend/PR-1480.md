_Posted by Claude Code, an AI agent acting for @YangXu1990uiuc._

Diagnostic result: reverting #1445 does not fix the frost sm100/sm103 failures.
- Pipeline 72396599 on this PR: sm100 had 368 failures and sm103 had 367, all `TYPE_UNSTABLE_JOIN` at the same three kernel sites. Develop has 374; the 6–7 fewer are #1445's own tests, which this revert removes.
- So #1445 is not the cause.

**Root cause**
- The CI image refresh (cudnn/cudnn_frontend!2438, DLFW 26.09) ships quack-kernels 0.6.2, and every test worker imports it.
- `quack/dsl/mixed_constexpr_if.py` replaces `DSLPreprocessor.visit_If` for the whole process. It rewrites `if const_expr(S) and D: ... else: body` into a constexpr `if` that duplicates `body`.
- Our sm100 `prefill_d256_fp8` / `prefill_d256_mxfp8` / `prefill_d512_mxfp8` loaders reuse a name across two such regions. Under that rewrite, the name becomes loop-carried and maybe-unset whenever `MAY_BE_EMPTY` is true.
- Local repro on B200 with DSL 4.7.0 (a d256 fp8 prepared case):
  - `import quack` before the test: fails with the same error;
  - without it: passes.

The fix is in a separate PR. Closing this one; it was never meant to merge.
