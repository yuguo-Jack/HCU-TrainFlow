# test(gated_attention_block): the raw indexer key pool cell runs the landed sparse block end to end instead of expecting the sparse core's decline

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1657) · state: closed · merged: True

## Original PR description

## Symptom

`test/python/gated_attention_block/cutedsl/test_block_serving_extend.py::test_raw_indexer_key_pool_at_flash_next` (L1, Rubin) fails on `develop` with `Failed: DID NOT RAISE NotImplementedError`: it still wraps the band geometry's `check_support()` in `pytest.raises(NotImplementedError, match="sparse attention core")`.  No pipeline saw it: the sm107 CI job runs `-m L0`.

## Cause

#1639 landed the sparse attention core as stage (4) of a `QsaSpec` block, so a block declared with the indexer band and `paged_kv_page_size` accepts at `check_support()` -- the decline the cell expected no longer exists.

## What the cell checks now

Every existing bitwise check is kept, through the block's own stage objects (the only way to read the slab between the projection and norm + RoPE): the raw indexer key's pool bitwise `index_k_raw_view` at every slot, the K / V pools bitwise the post-RoPE bands, the pre-norm raw key untouched by norm + RoPE, the moved-byte count.  The block now `check_support()`s (asserted) and compiles, so the workspace comes from `get_workspace_size()` (the `_align_up` import had no other user).  Then the WHOLE block runs on the same inputs with the full caller list (`block_ids` = every complete block of the row's own sequence, below the identity bound; `block_lens` the count) on fresh NaN pools: its three pools bitwise the stage walk's, its slab's raw key (`index_k_raw(workspace)`) bitwise the walk's, `out` finite, and `out` / the gated O within the suite's bars of the fp32 QSA oracle (`cos(out) > 0.999`, `max|d O_gated| <= 2e-2` -- the dense block suites' budget; nothing widened).  Test-only; no library change.
