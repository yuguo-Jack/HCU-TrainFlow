## Affected area

FE OSS kernels or CuTeDSL (Python SDPA lowering).

## Summary

Dense, unpadded exact-D128 SM120 per-tensor FP8 graphs can now request split-KV with an attention sink. Lowering compiles sink-free half partials, and the existing final combine adds the sink exactly once while preserving Scale_O, Stats and Amax_O.

## Why

The earlier SM120 refusal prevented this composition even though the prepared binder and half-partial final combine already supported it. Reusing that path keeps quantization, scaling and sink ownership in the existing final combine.

## Related issues

Related to #381.

## API and compatibility impact

No public signature, kernel ABI, workspace layout, placement or automatic-selection change. Eligibility uses logical QK/V dimensions, so smaller heads covered by the D128 tile remain outside this addition. MXFP8, other heads, THD, padding, paging, block-scaled output and gated splits retain their restrictions. Direct FP8 template specializations that fold a sink per partial still decline. SM121 shares the family admission; native qualification was performed on cc12.0 only.

## Testing

NVIDIA RTX 6000D, native cc12.0 (GPU4), Python 3.12, Torch 2.13.0+cu130, cuDNN 9.27 and CuTe DSL 4.8.0 (CUDA 13.4 compiler). Both RED and GREEN imported the isolated source checkout.

- Baseline RED: two bounded-domain assertions and the first requested numerical graph failed at the existing sink/split refusal.
- `python -m pytest -q -s sdpa/frost/test_sdpa_fp8_sink_split_sm120.py`: 25 passed. Strict FROST route, E4M3/E5M2 inputs, four scalar output dtypes, Scale_O/Stats/Amax, physical output padding, empty chunks, changed input/storage and retained capture replay, standalone packed keyless rows against a float64 oracle, default scales and optional outputs.
- Existing controls: `python -m pytest -q -s -m 'L0 or L1' sdpa/frost/test_sdpa_fwd_split_kv_sm120.py sdpa/frost/test_sdpa_native_fp8_arch_binding.py -k '(sm120 or half_partial_contract) and not graph_rebinding_and_changed_scale_replay and not physical_wide_operand and not standalone_omitted_scales_replay'`: 176 passed, 121 deselected.
- CI collection with `-k frost`: 25 tests collected.
- Two targeted memory-access checks: 2 passed, `ERROR SUMMARY:0 errors`, using `--report-api-errors no --error-exitcode 99`. Default API reporting emits 40 `cuGetProcAddress_v2` binding/driver version-probe diagnostics; an independent existing sink-free native control emits the exact same 40 diagnostics. Both default logs are retained. This qualifies only the selected memory accesses, not general CUDA API behavior.
- `pre-commit run --files <changed files>`: passed.

No tolerance was loosened. The default-reporting sanitizer runs exit 99 from the version probes; they are not claimed as clean sanitizer results. No racecheck, performance improvement or cc12.1 execution is claimed.
