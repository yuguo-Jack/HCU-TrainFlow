## Summary

Test-only changes under `test/python/moe_ep/`:

- `test_moe_ep_multinode.py`
  - Add `forward-ep8-world8`, the whole-world EP8 inference-forward case that was missing next to ep4/ep6/ep12/ep16.
  - After every case, shut the MegaMoE runtime down and barrier on the EP group. Destroy the process group only for subgroups, never for `WORLD`.
- `test_moe_ep_backward.py`
  - In the two EP2 training-graph overflow tests (`test_training_graph_error_mode_overflow_asserts_on_all_ep2_ranks`, `test_training_graph_drop_mode_overflow_completes_forward_and_backward`), prepend `test/python` to the probe subprocess's `PYTHONPATH`. Any existing value is kept.

## Why

- **Runtime teardown.** The runtime manager stays alive after `op.close()` and stays bound to the EP group's membership. The test used to shut it down only after subgroup cases. Previously the `WORLD` cases always ran last, so this never mattered. With `forward-ep8-world8` running before `forward-ep6-world8`, the runtime was still bound to the 8-PE `WORLD` group. The ep6 case was then refused with `already bound to a different EP subgroup`, its teardown no longer matched the idle ranks' barrier, and the run hung until the 10-minute NCCL timeout.
- **Probe `PYTHONPATH`.** `probe_moe_ep_training_graph.py` runs under `torch.distributed.run` in a fresh interpreter. Its `sys.path` starts at the probe's own directory (`test/python/moe_ep/`), so `from moe_ep.moe_ep_test_support import ...` only worked if the caller had exported `PYTHONPATH=test/python`. Without that, both tests fail with `No module named 'moe_ep'`. Setting the path in the test makes it independent of how the suite is launched.
