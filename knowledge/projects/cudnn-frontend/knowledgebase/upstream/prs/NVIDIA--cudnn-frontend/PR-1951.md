# frost(sdpa sparse sm107): the lean decode tile's placement bound counts the CTAs per chunk (B x H_kv), not B x H_kv x S_q -- the shared-list block at B 1 x S_q 2..4 takes the lean body under "auto"

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1951) · state: closed · merged: True

## Original PR description

## Summary

The lean block-sparse decode tile's PLACEMENT bound counts the lean grid's own unit: the CTAs per chunk, `B x H_kv`, not `B x H_kv x S_q`.  The lean
body (`sparse_lean_d256_f16`, #1907) is one CTA of `128 x N_MT` threads per (sequence, KV head, chunk of k sub-tiles); the step's `S_q` rows ride INSIDE the CTA as
`N_MT = ceil(S_q x G / 16)` m16 tiles of four warps each (128 threads at `S_q` 1 / G 12, 512 at `S_q` 4 / G 16), so the grid is `B x H_kv x split` and `S_q` sizes the CTA, not the grid.  The merged rule
`sparse_decode_lean_tile_selected` counted `B x H_kv x S_q <= LEAN_SPARSE_MAX_UNITS` (= 4) and so kept B 1 x `S_q` 3..4 (6 / 8 "units", but 2 CTAs
per chunk) on the tcgen05 core under `"auto"` -- the cells the end-to-end gate measured WINNING on the lean body, and the follow-up #1907 named.
With this change `"auto"` on cc 10.7 takes the lean tile at B 1 and B 2 (two KV heads) at every served step width `S_q` 1..4 and keeps the tcgen05
core from B 4 up; the constant stays 4, its name stays `LEAN_SPARSE_MAX_UNITS` (the tests, the docs and the tracker read it).  No kernel change; no
perf claim beyond the merged gate's table; every other rule (the list form, the k pin, the split, the admissibility declines) untouched.

## Why: the gate's own rows prove the unit

The end-to-end gate of #1907 (one exclusive GPU of the 212-SM cc 10.7 class at the clock lock, CUDA-graph replay, one process per cell with every
arm, A/B/A x 3 x 100, every oracle before timing; its table is in that PR) read, per decode step, the lean body against the tcgen05 core in the
same block.  Re-keyed by CTAs per chunk the `S_q` 1 and the `S_q` 4 cells land on the SAME side at the same level, which a `B x H_kv x S_q` count
cannot express:

| CTAs per chunk (`B x H_kv`) | cells | lean vs tcgen05 core, per step (POSITIVE = lean faster) | under `"auto"` before -> after |
|---|---|---|---|
| 2 (B 1) | `S_q` 1 at 8K / 32K / 128K | +6.8 % / +5.7 % / +4.8 % | lean -> lean |
| 2 (B 1) | `S_q` 4, the shared-list block, at 8K / 32K / 128K | **+6.4 % / +6.6 % / +6.8 %** (2.2-2.4 us) | **tcgen05 (8 "units") -> lean** |
| 4 (B 2) | `S_q` 1 at 8K / 32K | +1.8 % / +1.3 % | lean -> lean |
| 8 (B 4) | `S_q` 1 at 2K / 8K / 32K / 128K | -2.6 % / -3.5 % / -2.0 % / -2.2 % | tcgen05 -> tcgen05 |
| 8 (B 4) | `S_q` 4, the shared-list block, at 8K / 32K / 128K | **-9.7 % / -8.8 % / -9.2 %** | tcgen05 -> tcgen05 |
| 16 (B 8) / 32 (B 16) | `S_q` 1 | -17.2 % / -16.3 %; -44.1 % / -43.6 % | tcgen05 -> tcgen05 |
| 64 (B 32) | `S_q` 1; `S_q` 4 | -60.8 .. -51.3 %; -36.5 .. -35.7 % | tcgen05 -> tcgen05 |

The B 1 x `S_q` 2..4 shared-list cells (one gathered list per sequence) move onto the default route; B 2 x `S_q` 2..4 (4 CTAs per chunk, the level
that holds at `S_q` 1) move with them -- unmeasured at `S_q` 2..4, stated, the explicit `sparse_tile_form="tcgen05"` keeps the core there.  Nothing
else moves: the per-row indexer block never takes the lean tile past one row (the list-form decline, independent of the bound), and a pinned
`decode_split_kv` that is not a lean split keeps the core as before.

## The change

* `python/cudnn/sdpa/fwd/sparse_tile_rules.py` (the rules' home since #1923): `sparse_decode_lean_tile_selected` returns
  `B x H_kv <= LEAN_SPARSE_MAX_UNITS` (the `s_q` parameter stays in the signature -- every caller passes it -- and is deliberately unread: the
  served rows are `sparse_lean_tile_decline`'s business); the constant's docstring states the unit and re-keys the gate's table by CTAs per chunk;
  the AUTO pin's docstring records the refit's two readings.  `sparse_tile_form_auto` and `DecodeEnvelope.sparse_tile(...)` read the same rule, so
  they follow.
* The adapter's TWO BODIES paragraph (`sparse_gqa_sm107.py`), the block's `sparse_tile_form` knob comment and the envelope's field comment
  (`gated_attention_block/api.py`), the docs knob row and two-bodies paragraph (`docs/fe-oss-apis/gated_attention_block.md`), and the tracker's
  lean paragraph (`SUPPORT_MATRIX_TRACKER.md`: the PLACEMENT sentence -- which still said `= 32 units` -- and the measured-table line, now by CTAs
  per chunk) spell the new unit.  No `Capabilities` field and no `EngineSpec` changes: a knob-domain change (the AUTO default's domain), the
  tracker updated anyway as #1907 did.
* Docstring correction (text only; no sizing change), from a review of the vendored copy downstream: the two block docstrings in
  `python/cudnn/gated_attention_block/api.py` that named the sparse THD arm's int32 metadata `THD_WORK_META_WORDS(B)` now name
  `THD_META_WORDS(B)` (= 4 B + 4 words, 16-byte rounded) -- the layout the sm107 sparse adapter sizes the buffer with
  (`sparse_gqa_sm107._thd_meta_bytes`); `THD_WORK_META_WORDS` (5 B + 5) is the dense THD path's layout.
