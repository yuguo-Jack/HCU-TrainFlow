# feat(sdpa): support deterministic dense D128 backward

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1875) · state: closed · merged: True

## Original PR description

Dense D128 MHA backward graphs requesting `use_deterministic_algorithm=True` are rejected even though the existing recompute kernel gives each gradient tile a single CTA owner and a fixed reduction order. Select that native, zero-workspace implementation for deterministic requests through the ordinary graph and standalone APIs.

The accumulation implementation uses unordered FP32 dQ reductions. Grouped and THD deterministic requests remain declined; their existing accumulation paths do not satisfy the deterministic contract. The support matrix and API documentation now distinguish these cases.

## Affected area

FE OSS kernels or CuTeDSL — SDPA backward implementation selection and regression coverage.

## API and compatibility impact

The existing deterministic op attribute now selects the fixed-order recompute implementation for dense MHA, BF16/FP16, unmasked or top-left causal, within the D128 engine's existing architecture/layout/shape envelope. Public signatures are unchanged. Query the plan's workspace size as usual; this implementation requires zero bytes.

Existing tests retain the unrequested implementation-selection and zero-workspace contracts. Pre-commit passes for all five changed files.
