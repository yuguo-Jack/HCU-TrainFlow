## Affected area

FE OSS kernels / CuTeDSL: SM100/SM103 BF16 block sparse attention.

## Summary

Long fixed-count KV rows previously stayed unsplit whenever the Q grid had at least 512 tiles. Auto selection now permits four splits for 450–899 active KV blocks and eight splits for 900 or more, including large-Q workloads. Large-Q variable-count rows and shorter fixed-count rows retain one split; short-Q selection and workspace-budget fallback remain in place.

The blk64 forward and combine paths write directly into the requested BHSD/BSHD output layout, eliminating output transpose copies and avoiding forced BHSD copies of contiguous BSHD inputs. The SM100 blk64 backward kernel derives O, dO, and dQ views from each tensor's own layout rather than reusing Q's layout. Documentation and the existing auto-selection test are updated.

## Why

Long fixed-count rows can benefit from split-KV even when there are enough independent Q tiles to fill the GPU. Variable-row index capacity can substantially overestimate real work, so large-Q variable-count workloads remain conservative. Native layout handling removes copies that would otherwise add overhead to these paths.

## Related issues

None.

## API and compatibility impact

No public signature or dependency changes. BF16 auto split selection changes for long fixed-count rows. Explicit splits, workspace-budget fallback, contiguous output contracts, and the separate Sage FP8 policy are preserved. The new private combine argument is appended with a default.
