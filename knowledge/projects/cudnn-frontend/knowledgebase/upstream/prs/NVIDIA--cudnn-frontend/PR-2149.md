# sdpa fwd heuristics (sm107): lead unpacked causal THD prefill with LPT on d64 and few-wave d128

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2149) · state: closed · merged: True

## Original PR description

## What

On the SM107 (Rubin) half row, the THD scheduler led NATURAL unless the graph packed its GQA group. Unpacked causal THD prefill (MHA, MQA, and ragged GQA, which does not pack) balances its causal triangle better under LPT while the grid is a few waves. This PR leads LPT for that case:

- **d64**, the 1-CTA flavor: at any size.
- **d128**: up to 10 waves (`_SM107_THD_LPT_MAX_WAVES`).
- **d256**: measured mixed, so it keeps NATURAL.
- **Windowed, sink, and non-causal graphs:** unchanged.

The wave count is the formula the dense Rubin no-GQA rule already uses, now one helper (`_sm107_cluster_waves`). FlashInfer's override (envelope) declarations count as many waves, so only d64 changes there. The other policy stays listed for autotune.

## Evidence (FlashInfer's own cudnn path, single-tenant Rubin)

- **Train:** 311 cells, ragged and paged, d 64/128/256, MHA / MQA / unpacked GQA, b 1-16, S_q 128-8192. Gap-fill cells sit at 10-17 waves, between the lattice's 9.5 and 19. Each cell times FROST's first plan and its scheduler twin; outputs are bit-identical.
- **Holdout 1** (48 cells, frozen before timing) showed d256 losing at 5-7 waves. The rule was narrowed to d64 / d128, which consumed it.
- **Holdout 2** (36 fresh cells, frozen before timing): 30 decisions change, and no cell is slower than 5 %.
- Unit test `test_sm107_unpacked_causal_thd_scheduler`; host suites pass (1818).
