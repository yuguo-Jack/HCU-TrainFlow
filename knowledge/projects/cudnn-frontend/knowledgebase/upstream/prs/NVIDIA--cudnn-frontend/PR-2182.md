## Affected area

CI or test infrastructure

## Summary

Print the selected native plan name when the shared SDPA harness records its routing. Previously only Python-engine routes printed an engine/knob identity, so a native MXFP8 backward failure could report its forward engine without identifying the backward plan that ran.

Read the selected unified plan index after build and use `get_plan_name_at_index`; preserve existing routing counters and the FROST `LAST_PLAN` / `LAST_ARMS` contract. Cover non-first plan selection and the existing Python-engine logging, plus a real built backend graph with FROST GEMM explicitly excluded.

## Related issues

Related to #2122. This supplies the missing backward-plan diagnostic for further reproduction. The intermittent SM100 NaN failure remains unverified on the available SM120 hardware.

## API and compatibility impact

Test logging only; no execution, numerical, tolerance or engine-admission changes.

## Testing

RTX 6000D (cc12.0), Python3.12.3, cuDNN9.27.0.42, Torch2.13.0+cu130, CuTeDSL4.8.0, source-bound frontend1.33.0:

- Before the change, the selected-native-plan regression failed for both index0 and index2; the Python-engine control passed.
- `python -m pytest sdpa/test_routing_diagnostics.py -m L0 -q`: 4 passed.
- Same command with `CUDNN_FRONTEND_ENABLE_FROST_ENGINES=1`: 4 passed.
- Scoped pre-commit hooks and `git diff --check`: passed.
- Independent review found no remaining issues after excluding FROST GEMM from the real native control.
