# norm(groupnorm): launch the CGA GroupNorm / InstanceNorm routes through tvm-ffi

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2146) · state: closed · merged: True

## Original PR description

## Problem

The CGA GroupNorm / InstanceNorm routes still wrap every operand with `dyn()` (`from_dlpack(...).mark_layout_dynamic()`) on each call. This is the same per-call export that #2141 removed from the warp LayerNorm / RMSNorm forward. On a B300, a warm `norm_fprop` / `norm_bprop` GroupNorm call spends about 80-160 µs / 250-280 µs on the host for these routes. In eager use that is longer than the kernels themselves at diffusion-UNet shapes.

## Change

- `groupnorm_cga_sm100` forward and backward now compile once with `--enable-tvm-ffi`. The fake operands are flat, with dynamic lengths, built with #2141's `fake_rows()`. Each call passes the torch tensors directly through `ffi()`, which detaches them when they are on an autograd tape.
- The compile keys are unchanged.
- The fast backward route (short rows) stays on `dyn()`. Its tvm-ffi build gave a dx that differed from develop at 16x1280x16x16. That route's dx is not reproducible on develop itself at CPG 20 / 40 (a partial-warp block reduction, fixed separately in #2156), so the comparison says nothing about the ffi build. It is not part of this change.
- The NHWC, plain and BatchNorm routes are not touched.

## Measurements (B300, cc 10.3)

`cudnn.norm` torch API, bf16, 32 groups, NCHW. Develop and this branch ran in separate processes, alternating, twice. Warm enqueue per call, for shapes from 1x128x512x512 to 16x1280x16x16 (the forward set also includes 2x320x96x96; the backward set adds 32x256x16x16):

- **Forward**, CGA route (5 shapes): 81-83 µs and 156-160 µs on develop in the two reps; 44-47 µs on this branch.
- **Backward**, CGA route (1x128x512x512, 8x512x64x64, 4x256x128x128): 253-280 µs on develop; 93-115 µs on this branch.

The host was shared, which is why the develop numbers moved between reps.

## Correctness

- **Forward:** y, mean and rstd are bitwise identical to develop in all 30 compared tensors.
- **Backward, CGA cells** (1x128x512x512, 8x512x64x64, 4x256x128x128): dx, dgamma and dbeta are bitwise identical to develop. The one backward shape whose dgamma / dbeta differed (by at most 2.6e-6 relative), 2x320x96x96, does not take the CGA route: it falls through to the row-wise kernel with per-element atomics, and two runs of develop alone also differ there.
- **Tests:** the full `test/python/norm` on B300 (develop plus this change) gives 1333 passed, 1 skipped. That suite runs every GroupNorm / InstanceNorm graph and CuTe DSL test.
