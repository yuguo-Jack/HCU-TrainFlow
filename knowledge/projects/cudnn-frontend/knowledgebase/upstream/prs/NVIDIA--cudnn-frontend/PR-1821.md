# fix(sdpa bwd): decline a too-old CuTe DSL before importing a kernel module -- THD_BWD_META_WORDS from the DSL-free constants, not tile_dsl.thd at module scope

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1821) · state: closed · merged: True

## Original PR description

## What

The SM80 SDPA backward wrapper (`sdpa_bwd_wrapper_sm80`) declines a too-old CuTe DSL by version again, **before** its module imports anything DSL-bound (python/cudnn/AGENTS.md **Rule 7**). The pure-Python word count `THD_BWD_META_WORDS` moves to the DSL-free `tile_dsl/constants.py`; `tile_dsl/thd.py` re-exports it, and `sdpa/bwd/api_dsl.py` imports it from `constants` instead of from `thd` at module scope. One regression test per wrapper models a DSL without `cutlass.experimental` on any installed DSL.

## Why

`sdpa/bwd/api_dsl.py` is the wrapper's entry -- an independent caller-facing path with no engine `check_support` in front of it -- so the module itself has to import without the DSL for the wrapper to reach its typed decline. #1796 added

```
python/cudnn/sdpa/bwd/api_dsl.py:23   from cudnn.frost.tile_dsl.thd import THD_BWD_META_WORDS
python/cudnn/frost/tile_dsl/thd.py:32  from cutlass.experimental import primitives as nvvm
```

at module scope (the SM100 THD workspace sizing in `scratch_workspace_bytes()`), and `cutlass.experimental` is a package the public `nvidia-cutlass-dsl` **4.6.2** wheel -- the one `pyproject.toml`'s downstream floor admits and the released-DSL CI jobs install -- does not ship. The import error pre-empts the version decline:

```
test_sdpa_sm80_cutedsl_gate.py::test_bwd_wrapper_declines_by_version
E   ModuleNotFoundError: No module named 'cutlass.experimental'
```

That is the one failure on each of the sm80 / sm90 / sm100 released-DSL jobs of #1813's last pipeline (sm80 1 failed / 788 passed / 2062 skipped; sm90 1 failed / 1267 passed / 1577 skipped / 6 xfailed; sm100 1 failed / 1877 passed / 973 skipped). The same jobs passed on that PR's first pipeline, which ran before #1796 merged (2026-10-23); the failure is deterministic on any tree that contains #1796 under a DSL without `cutlass.experimental`, so it is a develop regression, not #1813's and not test-order dependent. On a 4.7.0+ host the package exists and nothing shows.

## The change

* `python/cudnn/frost/tile_dsl/constants.py` (no imports; already imported at module scope by the wrapper module): `THD_BWD_META_WORDS = lambda b: 6 * b + 6`, with the backward metadata layout it closes spelled out (`= THD_BWD_WORK_PREFIX_OFF(b) + (b + 1)`).
* `python/cudnn/frost/tile_dsl/thd.py`: imports it from `constants` and keeps re-exporting it -- `__all__` unchanged, so the sm107 d256 kernels, `kernels/thd_helpers.py`, `prepared_sm100.py` and the SM100 THD tests keep `from cudnn.frost.tile_dsl.thd import THD_BWD_META_WORDS`; the lambda is one object through every import form (checked). `THD_BWD_MAPS_OFF` / `TENSOR_MAP_ALIGN` stay in `thd`: no host module needs them at import time, and moving them would split the tensor-map extension across two files.
* `python/cudnn/sdpa/bwd/api_dsl.py`: one import line from `constants`, with a two-line comment saying why `thd` must not be imported at module scope here.
* `python/cudnn/sdpa/fwd/api_dsl.py` was checked and is already clean (its `thd` imports are all inside methods); the new forward cell pins it.

No `Capabilities` / `EngineSpec` change, so no `SUPPORT_MATRIX_TRACKER.md` update (python/cudnn/sdpa/AGENTS.md Rule S2 scope).

## Test -- RED, then green

`test/python/sdpa/cutedsl/test_sdpa_sm80_cutedsl_gate.py` (module-level `pytestmark = L0`) gains

* a fixture `no_experimental_primitives`: `cutlass.experimental` and `cutlass.experimental.primitives` set to `None` in `sys.modules` (an import of either then raises `ModuleNotFoundError`, as on the 4.6.2 wheel), and `cudnn.sdpa.fwd.api_dsl`, `cudnn.sdpa.bwd.api_dsl`, `cudnn.frost.tile_dsl.thd` dropped from `sys.modules` so the test's import re-executes their module scope -- a copy cached by an earlier test cannot hide the chain. Teardown restores the cached module objects and the attributes a re-import rebinds on the parent packages (read through `vars(pkg)`, so a lazy package `__getattr__` does not import the child), so later tests keep the one module object everything else imported.
* `test_bwd_wrapper_declines_before_the_dsl_import` and `test_fwd_wrapper_declines_before_the_dsl_import`: the existing decline (`NotImplementedError` matching `found 4\.6\.2`) under that fixture.
