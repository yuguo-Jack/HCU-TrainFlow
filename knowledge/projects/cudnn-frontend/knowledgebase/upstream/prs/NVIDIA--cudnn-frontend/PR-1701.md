## Affected area

C++ frontend API or graph construction

## Summary

Run the callback on a copy, map the returned plans to their original
indices, and apply the existing `reorder_plans()` helper before selecting
index 0. Failed or invalid callback results leave the original ordering
and selection unchanged.

This extends the synchronized-reordering approach from #1340 to the
legacy callback tuner, preserving its callback signature. The native
`Graph::autotune` path is unchanged.

## Why

`Execution_plan_list::autotune` lets its callback reorder or prune
`execution_plans` without updating the corresponding engine configs,
notes, or filter flags. After tuning, metadata queries can describe
a different plan from the one executed.
