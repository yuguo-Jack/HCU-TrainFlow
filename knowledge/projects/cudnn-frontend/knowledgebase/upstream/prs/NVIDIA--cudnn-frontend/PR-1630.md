# Fix TMEM release state in SM100 MXFP8 backward kernels

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1630) · state: open · merged: False

## Original PR description

## Summary

Use `tmem.free(tmem_ptr, num_columns=self.tmem_alloc_cols)` in the SM100 D256 MXFP8 dQ and dK/dV kernels instead of overwriting the allocator's private column counter.

When the allocator carries that counter as a DSL value, assigning a Python integer inside the release warp branch changes its carried structure and compilation fails with `CONTAINER_STRUCTURE_CHANGED`. The explicit-count API preserves the allocator state and releases the same number of columns. No public signature or synchronization changes.

## Testing

- Reduced two-CTA SM100 compile test, with allocation and release in separate runtime warp branches: the original assignment reproduces the 3-to-2 structure error; explicit-count release passes and emits matching 512-column allocation/deallocation.
- Changed-file pre-commit hooks passed (Black, notebook formatting and SPDX).
- Python syntax checks and `git diff --check` passed.
