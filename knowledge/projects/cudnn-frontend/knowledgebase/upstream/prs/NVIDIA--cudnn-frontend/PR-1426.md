## Problem

When a graph omits `attn_scale`, cuDNN and FROST compute different functions:

- **Backend:** inserts no scale multiply, so the scale is 1.0. `docs/operations/Attention.md` documents this: "Set to 1.0 by default".
- **FROST:** `graph_analyzer` passed the missing value to the adapters as `facts.scale = None`, and every adapter turns `None` into 1/sqrt(d).

This breaks Rule 8 (one graph contract). On SM100 the FROST prefill engine is the first-ranked plan, so with FROST enabled, a graph without a scale silently changed its result.

Measured on B200 (cuDNN 9.26, bf16, B=1, H=2, S=256, no mask). Each plan was run on the same graph and compared against references at scale 1.0 and scale 1/sqrt(d):

| d | plan | max \|O − ref(1.0)\| | max \|O − ref(1/√d)\| | max \|Stats − ref(1.0)\| |
|---|---|---|---|---|
| 128 | `sdpa_fwd_prefill_sm100` | 3.96 | 0.0015 | 48.5 |
| 128 | backend eng10 / eng8 | 0.014 / 0.009 | 3.95 | 0.0001 / 0.0 |
| 256 | `sdpa_fwd_prefill_sm100` | 4.05 | 0.0021 | 63.0 |
| 512 | `sdpa_fwd_prefill_sm100` | 4.23 | 0.0028 | 99.8 |

Backward, given a forward record computed at scale 1.0:

| d | plan | max \|dQ − ref\| | max \|dQ ref\| |
|---|---|---|---|
| 256 | `sdpa_bwd_sm100_d256` | 65.4 | 65.4 |
| 256 | backend eng5 | 0.19 | 65.4 |
| 512 | `sdpa_bwd_sm100` (the only plan offered) | 107.0 | 107.0 |

The five `test_default_attn_scale` cases encoded the FROST meaning: they omitted the scale and checked against a 1/sqrt(d) oracle.

## Change

- **`graph_analyzer.py`:** an omitted static `attn_scale` becomes `facts.scale = 1.0`. A tensor scale stays `None`, as before. The adapters' own `scale_softmax=None → 1/sqrt(d)` default is unchanged, because it is their direct-API contract.
- **Tests:** the omitted-scale cases in the SM100 d256/d512/MXFP8 backward suites and the SM107 d256/d512 backward suites now use a 1.0 oracle. The suites with unit-normal inputs pre-scale Q by 1/sqrt(d), so the logits stay in their usual range.
- **New tests:**
  - `test_omitted_attn_scale_is_no_scaling` in the analyzer suite: GPU-free, with explicit and zero controls.
  - `test_dsl_sm100_omitted_attn_scale_is_no_scaling`: forward O and Stats at d128/d512.
- **`python/cudnn/sdpa/AGENTS.md`:** one bullet recording the convention and naming the tests that detect a regression.

Out of scope: an *explicit* `attn_scale=0.0` is still replaced by 1/sqrt(d) in some adapters (SM100/SM120/SM80 forward, SM120/SM80 backward). That is a separate issue.
