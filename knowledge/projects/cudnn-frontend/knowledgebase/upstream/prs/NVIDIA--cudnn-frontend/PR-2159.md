# causal_conv1d: give the native route row-major strides at a size-1 dim

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2159) · state: closed · merged: True

## Original PR description

## Problem

`cudnn.ops.causal_conv1d` sends a call to the native width-four route when the `[B, T, D]` transpose of `x` is contiguous (`_can_route_causal_conv1d_bulk`). `Tensor.is_contiguous()` ignores the stride of a size-1 dimension. So when `T == 1` or `D == 1`, a plain row-major `[B, D, T]` input is admitted, but its transpose does not have row-major strides:

- `x[2, 264, 1]` (row-major) transposes to `[2, 1, 264]` with strides `(264, 1, 1)`; the row-major strides are `(264, 264, 1)`.
- `x[2, 1, 17]` transposes to `[2, 17, 1]` with strides `(17, 1, 17)`; the row-major strides are `(17, 1, 1)`.

The bulk backend compares strides exactly, so these calls fail with `ValueError: X tensor stride mismatch ... X must be [B, T, D] contiguous` instead of running. This covers a single-token call with or without state, a packed call whose total is one token, and any `D == 1` call. The same data passed through the channel-last allocation works.

## Change

- `row_major_view()` in `causal_conv1d_bulk_sm100/autograd.py` returns a contiguous tensor with canonical strides via `reshape(-1).view(shape)`: same storage, no copy, and a no-op when the strides are already canonical.
- `_run_causal_conv1d_bulk_backend` applies it to `x_btd` and to the full-width initial state before calling the backend.
- The autograd backward applies it to `dy` and `d_final_state` after `.contiguous()`, which returns such a tensor unchanged.

## Tests

New L1 test `test_row_major_input_with_a_size_one_dim_takes_the_native_route` in `test_causal_conv1d_semantic_api_sm100.py`, three cases: dense `T == 1`, dense `D == 1`, and packed with one token. Each runs a stateful call with bias forward and backward twice: once with the row-major input, once with the same values in the channel-last allocation.

- It asserts the native route is taken.
- Output, final state, dx and d(initial state) must match bitwise. dweight / dbias are compared with a tolerance, because they use FP32 atomics outside deterministic mode.

On a B300:

- **Develop:** all three cases fail with the stride mismatch.
- **With this change:** the file passes 8 / 8.
- **`test/python/causal_conv1d` with `-m "L0 or L1"`:** develop gives 31 failed / 250 passed and this change gives 28 failed / 253 passed. The 28 failures are the same set on both. They all come from the `torch/` tests calling the generic FFT backend (`cudnnFFTCausalConv1dForward failed with status 3000`) with the cuDNN 9.27 backend on that machine, and are unrelated to this change. The only difference is the three new cases.
- **Fuzz** of the public API (stateful, with and without bias, dense and packed, D from 1 to 4096, one to about 10k tokens), forward and all gradients against an fp64 reference: 328 channel-last cells pass on both. Of 68 row-major cells with a size-1 dim, 59 raise on develop and all 68 pass with this change.
