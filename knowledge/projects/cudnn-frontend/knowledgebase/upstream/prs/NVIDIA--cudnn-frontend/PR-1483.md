## Affected area

FE OSS kernels or CuTeDSL

## Summary
Since this morning, the `python/sdpa/frost:cutlass-rel:sm100` and `:sm103` lanes fail on develop and on every PR, with 374 failures.
- Every failure is the same DSL compile error, in the SM100 FP8 / MXFP8 loader warps:
  ```
  error[TYPE_UNSTABLE_JOIN]: `kv_row_base` has type `None` on one path and `Int32` on another.
  --> cudnn/sdpa/fwd/kernels/sm100/prefill_d256_fp8.py:1085
  ```
- The other two sites are `k_row` at `prefill_d256_mxfp8.py:1352` and `prefill_d512_mxfp8.py:1396`.
- Only the `MAY_BE_EMPTY` builds fail: a mask or split-KV.

## Why

### Root cause
- The refreshed CI test image (DLFW 26.09) ships **quack-kernels 0.6.2**, and every test worker imports it.
- `quack/dsl/mixed_constexpr_if.py` replaces `DSLPreprocessor.visit_If` for the whole process on `import quack`. It rewrites:
  ```python
  if const_expr(S) and D:            if const_expr(S):
      pass                     ->        if D: pass
  else:                                  else: body
      body                           else:
                                         body
  ```
- These loaders have two such regions per tile:
  - The first assigns `kv_row_base` (or the `k_row, ...` tuple from `_kv_tile_coords`).
  - The second contains a `cutlass.range` loop that reassigns the same names.
- Stock DSL: each region is a dynamic `if`, the names are branch-local, and the loop does not carry them.
- Under quack's rewrite: the copy of `body` in the constexpr `else` makes the names function-scoped, so the loop carries them. When `S` (`MAY_BE_EMPTY`) is true, the traced path took the inner dynamic `if`, so the carried value is `None`.

This is not limited to CI. vLLM and SGLang both pin `quack-kernels==0.6.5`, which installs the same patch, and import it. So any such process that compiles one of these FROST rows would fail the same way.


### Fix
- Rename the per-iteration names in those loops (`kv_row_loop`; `k_row_loop, k_page_loop, ...`), so the loops no longer share a name with the prologue.
- Under the stock DSL this changes nothing: the names were loop-local SSA values either way.
- `prefill_d512_mxfp8.py`'s `_SWA_REUSE_P` loop reuses the same tuple and gets the same rename.
- `python/cudnn/AGENTS.md` Rule 7 records the trap and how to detect it.
