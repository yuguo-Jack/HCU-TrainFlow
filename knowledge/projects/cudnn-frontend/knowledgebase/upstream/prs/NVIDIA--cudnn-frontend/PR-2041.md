# Remove unreachable SM80 SDPA staging paths

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2041) · state: closed · merged: True

## Original PR description

SM80 attention now rejects layouts that require staging at support checks, leaving the old staging executors unreachable. Remove those executors and their unused copy/RoPE helpers, and make forward/backward compilation use the native prepared hosts directly. Preserve the native launch ABI, diagnostics, workspace contracts and numerical kernels.

Update existing tests to verify native launches, current pointers, CUDA Graph replay, alias rejection and cached-artifact reloads. Validation: 317 host checks and 1,022 A100 tests passed; a separate 1,198-test run with the old staging entries replaced by failure tripwires also passed. Scoped formatting and license checks pass.

* **Behavior Changes**

  * Dense operands must use D-contiguous, vector-aligned, non-overlapping layouts; layouts that do not meet native requirements may be rejected.
  * Backward operations support declared operand layouts, including strided statistics, subject to native layout requirements.
  * Dense forward operations no longer require staging workspace. THD operations continue to reserve space for aligned length metadata.
