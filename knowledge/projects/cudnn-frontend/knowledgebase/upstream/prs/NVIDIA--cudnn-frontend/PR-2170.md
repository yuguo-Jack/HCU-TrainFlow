# dsa: decline cc 12.x in the indexer backward and score recompute gates

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2170) · state: closed · merged: True

## Original PR description

## Problem

On every part other than SM90, `DSA.IndexerBackward`, `DSA.DenseIndexerBackward` and the score recompute plans build their SM100 kernels (`indexer_backward_sm100`, `dense_indexer_backward_sm100`, `sparse_score_recompute_sm100` / `dense_score_recompute_sm100*`), all of which use tcgen05. Their gates were `major != 9 and major < 10`. A cc 12.x part (RTX / workstation Blackwell) passes that gate, so `check_support()` returns True and the tcgen05 kernel then cannot build for `sm_120a`. This is the same defect #2166 fixed for the CuTe DSL GEMM APIs.

## Change

- The `IndexerBackward`, `DenseIndexerBackward` and `_check_score_arch` gates use `major != 9 and not has_tcgen05(major)` (`has_tcgen05` from #2166).
- The two backward kernel factories' own `Requires SM100+` checks use the same helper.
- Messages say "with tcgen05 (not cc 12.x)", and the exception types are unchanged.
- SM90, cc 10.x and cc 11.x are admitted exactly as before.

## Tests

New L0 file `test/python/deepseek_sparse_attention/cutedsl/test_DSA_arch_gate.py`:

- **`IndexerBackward` (H = 64 compact):** with cc 12.0 reported to `check_support()`, it expects the gate's `RuntimeError`.
- **`_check_score_arch`:** for cc 8.0, 9.0, 10.0, 10.3, 11.0, 12.0 and 12.1, 8.0 and 12.x are declined and the rest are admitted.

On a B300:

- **Develop:** the three cc 12.x cases fail, and the five admit / decline controls pass.
- **With this change:** the whole `test/python/deepseek_sparse_attention` at `-m "L0 or L1"` gives 1037 passed, 57 skipped, 0 failed.
