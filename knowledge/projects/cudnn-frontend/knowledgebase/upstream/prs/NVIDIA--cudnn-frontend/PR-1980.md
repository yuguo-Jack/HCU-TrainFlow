# perf(sdpa): launch only live query warps in split combine

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1980) · state: closed · merged: True

## Original PR description

For Q1/Q2 with at most 16 KV splits, the row-per-warp combine launches four warps even though only one or two have rows. Launch 32/64 threads with an explicit 64-thread upper bound, reducing register allocation per block and improving residency. The kernel has no CTA barrier or cross-warp exchange, so its row mapping and arithmetic remain identical.

## Affected area

FE OSS kernels / SDPA split combine.

## Summary

- Size the existing short-query combine block from its runtime query-row count; retain one shape-generic prepared entry.
- Extend artifact-reuse coverage across Q1/Q2/Q3/Q5 and the many-split boundary.

## Why

Local SM100 CUDA-event replay over four paged Q1/GQA8 length cohorts and split 1/2/4/8/16 shows a 2.6% aggregate full-attention latency reduction in both construction orders; the 16 changed split plans improve 3.2–3.3%. An independently compiled unchanged-source control moves within 0.04%. Including unsplit plans, the best tested one-long and mixed-length plans improve about 4.1–4.5% and 2.1%; equal-length cases continue to prefer the unchanged unsplit path. This is local kernel/graph-replay evidence, not a serving or other-GPU performance claim.

Paired profiling confirms 32 rather than 128 threads for Q1, unchanged registers per thread, and zero local spills. O and Stats are bitwise equal to the baseline in all eight profiled plans.

None.

## API and compatibility impact

No public API, plan selection, workspace, numerical policy, supported-feature or dependency changes. Other combine forms keep their launch geometry.
