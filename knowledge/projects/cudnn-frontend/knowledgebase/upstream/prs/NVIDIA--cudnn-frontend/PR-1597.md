# Remove the cudnn.jax and cudnn.torch grouped SwiGLU aliases

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1597) · state: closed · merged: True

## Original PR description

Removes four namespace aliases:

| Removed | Use instead |
| --- | --- |
| `cudnn.jax.grouped_gemm_swiglu` | `cudnn.grouped_gemm_swiglu_wrapper_sm100`, or `cudnn.grouped_gemm_glu_jax_sm100` with `act_func="swiglu"`, `generate_c=True`, and an FP8 `d_dtype` |
| `cudnn.jax.grouped_gemm_dswiglu` | `cudnn.grouped_gemm_dswiglu_wrapper_sm100`, or `cudnn.grouped_gemm_dglu_jax_sm100` with `act_func="dswiglu"` and an FP8 `d_dtype` |
| `cudnn.torch.grouped_gemm_swiglu` | `cudnn.grouped_gemm_swiglu_wrapper_sm100` (the same function) |
| `cudnn.torch.grouped_gemm_dswiglu` | `cudnn.grouped_gemm_dswiglu_wrapper_sm100` (the same function) |

This PR first deprecated them with a `FutureWarning`; it now removes them outright. They were added in #1079 and shipped in 1.30.0 and 1.31.0, the docs mark these APIs experimental, and no caller was found: TransformerEngine, FlashInfer, Megatron-LM and JAX (heads of 2026-10-12/13) do not reference any of the four, and GitHub code search finds no other user.

Changes:
- `cudnn.jax` / `cudnn.torch`: drop the names from `__all__` and `__getattr__`.
- `grouped_gemm_swiglu_wrapper_sm100` and `grouped_gemm_dswiglu_wrapper_sm100` used the `cudnn.jax` aliases for JAX inputs. They now import the JAX implementation directly, with the same CuTe DSL version check. Their behavior is unchanged.
- Error messages and a docstring that recommended the aliases now recommend the unified functions.
- API index: the four names are removed.
- Tests: `test_grouped_gemm_canonical_jax.py` calls the JAX implementation functions and the wrappers. `test_torch_namespace_alias_without_jax` becomes `test_torch_wrapper_without_jax`.
- Docs: the alias sections are removed from the two legacy pages and the overview. Each page keeps one line on what to call instead.

Testing, on an SM100 GPU with CUDA JAX 0.11.2:
- `test/python/gemm/jax/test_grouped_gemm_canonical_jax.py`: 117 passed, 0 skipped.
- Every other test file that imports `cudnn.jax` or `cudnn.torch`, plus the legacy grouped SwiGLU/dSwiGLU suites and the import-boundary tests: 423 passed, 202 skipped, 4 failed. The 4 failures are `sdpa/torch/test_torch_provider.py::test_sdpa_dense_parity`, which fail the same way on unmodified `develop` in this environment (see below).
- The API index scanner matches the edited baseline, apart from the environment artifact below.

Environment note: `develop`'s C++ does not build against the shared backend build on this machine, so the package under test was this branch's Python with a compiled module from an earlier build. That module lacks `_native_pack_from_facts` (the 4 SDPA failures) and the optional `gnn_agg_*` symbols (9 names in the index scan). This PR changes no C++.

@coderabbitai ignore
