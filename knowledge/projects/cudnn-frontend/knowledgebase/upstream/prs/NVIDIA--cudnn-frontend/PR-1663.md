# Index the lazy top-level cudnn names

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1663) · state: open · merged: False

## Original PR description

The API index scanner reads only each listed module's `__all__`. The top-level `cudnn` package keeps the names it loads lazily (`_LAZY_OPTIONAL_IMPORTS`) out of `__all__`, so that `from cudnn import *` does not load optional dependencies. As a result 135 public names were untracked, including the spellings downstream uses: TransformerEngine imports nine `grouped_gemm_*_wrapper_sm100` / `gemm_proj_rope_mxfp8_wrapper_sm100` names with `from cudnn import ...`, and Megatron-LM and FlashInfer use `cudnn.DSA`.

Changes:
- `api_index.py`: for each listed module, also resolve every public name in its `_LAZY_OPTIONAL_IMPORTS` table that is not already in `__all__`, and record it. A name that fails to resolve fails the check like an unresolved `__all__` export, so stale lazy-table entries are caught. The name is recorded without its class members: the object it resolves to is already indexed in the module that defines it, so expanding it again would duplicate those entries.
- `api_index.txt`: +135 names, all `cudnn.<lazy name>`. Nothing else changes.
- `test_api_index.py`: a fixture test for lazy names (public recorded, `_private` skipped, no member expansion) and a failure case for an entry that does not resolve.
- README: describes the lazy-name rule.

Only `cudnn` needs this: every other indexed module with a lazy table already lists those names in `__all__`.

Testing:
- `test_api_index.py`: 10 passed, 1 skipped (the runtime baseline, which needs a built wheel).
- Regenerated the index with `api_index.py --write`. The additions are exactly the 135 public `_LAZY_OPTIONAL_IMPORTS` names that were not indexed; the other 3 (`gated_attention_block`, `gnn`, `moe_ep`) were already indexed as modules. The package under test used a compiled module from an earlier build, which lacks the 9 optional `gnn_agg_*` names, so those existing entries were kept as they are.
