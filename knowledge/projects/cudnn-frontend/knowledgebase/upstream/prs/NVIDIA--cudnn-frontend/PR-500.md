# AOT: serialize() exports Python-engine plans; deserialize() runs them with no JIT (C++ or Python)

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/500) · state: open · merged: False

## Original PR description

Rewrite of AOT against current develop. `graph.serialize()` now works when the selected plan is a Python (CuTeDSL) engine, and `deserialize()` runs it from Python or pure C++ with no Python engine, no JIT and no cuDNN handle.

## API

There is no new API. The existing serialize/deserialize pair covers Python-engine plans:

```python
blob = bytes(graph.serialize())      # selected plan is FROST SDPA: kernels + launch sequence
g = cudnn.pygraph(); g.deserialize(blob); g.execute(pack, ws)   # no cutlass import, no compile
```
```cpp
cudnn_frontend::graph::Graph g;
g.deserialize(blob);                 // no handle, no device properties
g.execute(handle_or_nullptr, uid_to_ptr, workspace);
```

Compared with the first draft, these are removed:
- `export_to_disk`, `import_from_disk`, `KernelLibrary`.
- The global registry (`register_global`, `get_global`, and related), along with its cross-DSO visibility hack.
- The mandatory `set_name()`.
- The `CUDNN_FRONTEND_ENABLE_AOT` build flag and the tvm-ffi headers at build time.
- The demo engines.

Users store blobs however they already store backend plans.

## How a plan is exported

Engines implement one method, `CompiledPlan.launches()`. It returns exactly what `execute()` issues, and both are built on one binding function, so they cannot drift. Export calls `launches()` twice over the declared operands, placed at distinct placeholder addresses. It then classifies each argument:
- **Constant.** Equal in both calls.
- **Address.** Moved with exactly one operand or the workspace; stored as that buffer plus an offset.
- **Refused.** Anything else, named in the error.

No kernel runs during export. Nothing is allocated, and no DSL internals are monkeypatched; the first draft ran kernels and patched `tvm_ffi_provider`. Each kernel's exported object is linked into a small shared object.

The C++ loader is `include/cudnn_frontend/experimental/aot_engine.h`:
- It mirrors the tvm-ffi C ABI, so the header-only build gains no dependency.
- It resolves `libtvm_ffi.so` and `libcute_dsl_runtime.so` by SONAME. Python preloads both from the wheels.
- It loads modules from memfd, never from a shared `/tmp` path, and each distinct module once per process.
- It checks compute capability and SM count before any kernel initializes.

## Initial coverage

| Plan | AOT |
|---|---|
| FROST SDPA fwd, SM100/SM107 f16/bf16, prepared launch: dense, decode, split-KV, THD (packed / padded Stats), paged KV | yes |
| cuDNN backend plans | unchanged |
| FROST SDPA fwd tensor-ABI rows (fp8/mxfp8, SM120, SM80), SDPA bwd, FROST GEMM/conv, linear attention | `serialize()` raises with the reason |

A deserialized plan is the plan for the declared shapes, like a backend plan, so execute-time overrides are refused. The kernels are shape-generic, so graphs of different shapes share one module. Linux only.

## Fixed along the way

- **Wrong plan serialized.** On develop, `serialize()` with a FROST plan selected silently wrote whichever backend plan had last been built. It now exports the selected plan or raises. The test was red on develop.
- **CuTeDSL init deadlock.** In nvidia-cutlass-dsl 4.7, concurrent *first* calls of an exported kernel deadlock in the runtime's init spinlock. The AOT engine serializes first calls. The C++ 8-thread test hung 3 of 3 times without the lock and passes with it. This should be reported upstream.
- **Python `deserialize()`** now accepts `bytes` as read from a file, not only the list that `serialize()` returns.

## Measured (B200)

Host submit cost per execute. SDPA decode, 41×100 bursts, median:

| path | µs |
|---|---|
| Python, JIT'd FROST plan | 35.98 |
| Python, same plan deserialized (C++ AOT engine) | 9.57 |
| C++, deserialized, positional `execute` | 4.38 |

The refactor's cost on the Python engine's own `execute()` is within noise: 13.83 µs before and 13.82 µs after, host-only.

## Verified

- `test/python/sdpa/frost/test_sdpa_aot.py`: 18 tests.
  - Bitwise round trip for six shapes: dense, decode, split-KV, THD, THD padded Stats, paged decode.
  - Re-serialization.
  - Module sharing across shapes.
  - Wrong-SM refusal, override and null-workspace refusal, and CUDA-graph population refusal.
  - Rule 8: no allocation or sync across three executes.
  - First execute under `torch.cuda.graph` capture.
  - A fresh process that imports no cutlass and no kernel package.
  - A pure C++ consumer (`samples/aot/run_plan.cpp`, built with the repo's `-Werror` set).
  - The C++ concurrent first-call test.
- Regression, after rebasing onto develop `411ad321a`: 1476 passed, 109 skipped, 0 failed across the AOT, serialization, kernel-cache, prepared SDPA (THD, geometry, FP8, FP8 split), decode, dispatch, variant-pack, compiled-cache and GEMM execute suites.
- A partial `sdpa/frost` L0 sweep reached 33% with no failures. It was stopped before completion and ran on an intermediate revision.
- Headers compile under GCC C++17 with the repo's warning set, with and without `CUDNN_FRONTEND_SKIP_JSON_LIB`. Not built on MSVC or clang.
