# Fix GroupNorm cache reuse for strided operands

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2256) · state: open · merged: False

## Original PR description

## Problem

GroupNorm/InstanceNorm rowwise forward and the atomic-free backward reuse a compiled CuTe function across calls. `dyn()` specializes a unit stride but represents a non-unit stride dynamically. The cache keys do not encode that difference for the affine and statistics vectors.

For example, running a GroupNorm with contiguous scale and bias, then calling it with a stride-2 scale or bias of the same shape, can return incorrect values. Reversing the order also fails; a reused incompatible signature can cause an illegal memory access.

## Change

Include each affected vector's unit-stride classification in the corresponding cache key. Non-unit strides retain their dynamic signature, so different non-unit strides can still reuse one compiled function. The change does not copy operands or allocate scratch in the execution path.

## Validation

- B300 (SM103): 16 new cases passed, including scale and bias independently in both call orders, backward scale and mean/rstd views, stride-2/stride-3 reuse, and changed-input CUDA Graph replay. The original implementation failed all eight isolated affine/scale order cases and the isolated mean and rstd cases.
- The same 16 cases passed on GH200 (SM90); the three changed files were verified identical to those tested on B300.
- B300: 55 existing norm L0 cases passed, with one deselected.
- B300: all 16 new cases passed with CuTe DSL 4.8.0/cu12, 4.8.0/cu13, 4.8.1/cu12, and 4.8.1/cu13.
- Black 26.3.1 with the repository's `--line-length 160 --fast` options and `git diff --check` passed.
