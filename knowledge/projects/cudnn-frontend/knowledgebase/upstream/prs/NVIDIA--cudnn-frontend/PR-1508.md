## Affected area

FE OSS SDPA plan-time selection.

## Summary

Use the declared packed-query capacity and existing PackGQA candidates when choosing native nonpaged D128 splits on SM107. These two parts of the shared selector previously applied only to Blackwell, so Rubin estimated the padded B×Q grid even when the caller provided a tighter total-query bound.

The implementation changes two conditions in the existing selector. Rubin retains its one-wave budget, Q64–1024 prefix domain, minimum KV work per partition, and existing candidate score. The test enumerates small-batch token distributions independently to check the physical launch budget and candidate validity, without fixing a winning split or pack setting.

## Why

The native split path already supports packed GQA and bounded token totals. Candidate construction and provider placement share this selector; counting its actual packed/unpacked geometry lets both use the graph's existing capacity contract consistently.

## Related issues

Related to #1439. The paged changes in #1469, #1476 and #1503 are outside this diff; this branch is directly based on develop `d0c3db0aa`.

## API and compatibility impact

Plan-time selection only, using existing FP16/BF16 D128 kernels and public knobs. No capability expansion or execute-path change. MLA, paged selection and other architectures retain their existing policy.

FI needs to supply a meaningful total-query capacity to expose the tighter bound; the private FI integration prototype used for that part of validation is separate from this FE change.
