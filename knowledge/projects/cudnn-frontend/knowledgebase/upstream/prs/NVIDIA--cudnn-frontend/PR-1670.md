# frost(sdpa_bwd_sm80): release the deterministic dQ relay with a plain release store

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1670) · state: closed · merged: True

## Original PR description

## Summary

Follow-up to #1626. Each handoff in the SM80 deterministic dQ relay ran a CTA barrier, then a GPU-scope `fence.acq_rel`, then an `atom.exch.release`. The barrier already orders every thread's dQ `atomicAdd`s before thread 0, and a GPU-scope release is cumulative over them. So the extra fence only drained the adds a second time, on every Q iteration.

This PR drops the fence and publishes the turn with `st.release.gpu`. The SM120 backward relay already does the same (`_bwd_relay_release`).

## Performance

A100, B2 H64/8, d128, bf16, backward pass only (`benchmark_single_sdpa.py`, two runs per point, run-to-run spread under 0.1 ms).

| Mask | S | Deterministic before | Deterministic after | Non-deterministic |
|---|---|---|---|---|
| none | 4096 | 37.1 ms | **34.4 ms** | 29.6 ms |
| none | 8192 | 143.5 ms | **132.4 ms** | 114.4 ms |
| causal | 4096 | 19.4 ms | **18.3 ms** | 15.8 ms |
| causal | 8192 | 73.8 ms | **69.3 ms** | 59.6 ms |

The non-deterministic path is unchanged: everything here sits under `const_expr(deterministic)`.

## What else was measured (not in this PR)

- **Where the unmasked deterministic cost goes.** At S=4096, waiting for a turn accounts for about 2.4 ms and the release for about 4.9 ms. Most of the release cost was the fence.
- **Rotating each KV tile's Q-loop start does not work.** Deadlock freedom needs every wait to target a CTA with a lower blockIdx. That pins each slot's order to descending KV, so a rotated start makes every tile wait on its predecessor's last step.
- **Two variants that did not help.** Deferring the release until after the next iteration's first GEMM made unmasked slower (36.3 ms). Polling the semaphore with `ld.acquire` instead of `atom.add(0)` made no difference.
