## Affected area

FE OSS kernels / CuTeDSL: SM90 DSA indexer forward.

## Summary

The load warp writes the shared W tile using all 32 lanes, but the Q TMA completion only orders the issuing lane. Consumers can read other lanes' W stores without a handoff. The FP8 path has the same problem for K scale stores and uses one elected lane to release an entire warp's scale reads before the stage is reused.

Add an unaligned named barrier for W publication with the load warp and the actual consumer warpgroups (160 BF16 or 288 FP8 threads). For FP8, count each scale-loading lane in the KV full mbarrier and have each consumer lane release the empty stage after its reads. The existing Q/K TMA and MMA schedule, output contract and supported dtypes remain unchanged.

## Validation

On GH200 SM90, cuDNN 9.27.0.42, PyTorch 2.14.0+cu130, CuTeDSL 4.8.1/cu13 and Compute Sanitizer 2026.1.1:

- New regression: 10 passed, covering BF16, FP8 packed THD, FP8 H32/H64 with more than two KV tiles, racecheck and synccheck. The four racecheck cases fail on develop with shared-memory hazards while their underlying numerical tests pass.
- Existing indexer boundary selection: 14 passed, 9 architecture-dependent skips, 56 deselected.
- Cold-compiled BF16 and FP8 H32/H64 reference cases: 3 passed in each of CuTeDSL 4.8.0/cu12, 4.8.0/cu13 and 4.8.1/cu12; the CUDA 13 framework/backend and driver were retained. The compiler flavors report CUDA 12.9 and 13.4.
- CUDA Graph capture/replay matched eager output and LSE after changing the weights, for BF16 and FP8. One short ABBA measurement, including graph replay overhead, had BF16 medians 10.61/10.71 us before and 10.56/10.58 us after; FP8 8.21/8.18 us before and 8.21/8.21 us after. This does not establish general performance.
- Changed-file pre-commit hooks and `git diff --check` passed.

This is separate from #2252 and #2253, which address the sparse and dense score recomputation kernels rather than indexer forward.
