# test(bsa): restore allow_tf32 by hand; pytest 9.2's monkeypatch deletes it at teardown

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2211) · state: closed · merged: True

## Original PR description

## Problem

pytest 9.2 changed `MonkeyPatch.setattr`: when no data descriptor is in the way, it records the old value from the target's instance `__dict__` (its comment cites pytest#10644).
- `torch.backends.cuda.matmul` is a `cuBLASModule` that serves `allow_tf32` through `__getattr__` / `__setattr__`, so the attribute is never in its `__dict__`.
- The recorded old value is therefore NOTSET, and teardown calls `delattr`, which raises `AttributeError: 'cuBLASModule' object has no attribute 'allow_tf32'`.

Three BSA call sites patch it this way. Their tests pass, but each one also reports an ERROR at teardown. `test_bsa_attention_forward_sm90_blk64_large_logits_mixed_warp` patches before its SM90 skip, so it errors on every GPU. pytest 9.1.1 does not have this problem, and the repo does not pin pytest.

Minimal repro (torch 2.14.0, pytest 9.2.0, no GPU work):

```python
def test_mp(monkeypatch):
    monkeypatch.setattr(torch.backends.cuda.matmul, "allow_tf32", False)
# 1 passed, 1 error (teardown AttributeError); passes cleanly on pytest 9.1.1
```

## Change

In `test_BSA_attention_forward.py` and `test_BSA_sm90_backward_sync.py`, the call sites (two tests and the `sm90_bsa` fixture) now use `_disable_tf32_matmul(request)`. The helper saves the flag, sets it to `False`, and restores it with `request.addfinalizer`. Nothing else in the tests changes.
