# test(gemm): point the Rubin dispatch tests at the GLU / dGLU blockscaled APIs and select them at L0

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2176) · state: closed · merged: True

## Original PR description

## Problem

Four of the Rubin dispatch tests in `test/python/gemm/cutedsl/test_rubin_kernel_dispatch.py` carry no `L*` marker. CI selects with `-m L0`, so they never run: `test_rubin_kernel_module_is_present`, `test_is_sm107_device_gating`, `test_get_rubin_kernel_lazy_import` and `test_kernel_selection_uses_rubin_on_sm107`. The four other tests in the file are already `L0`.

Two of them have gone stale for GLU and dGLU. #459 moved `_get_rubin_kernel` and the blockscaled kernel selection from `grouped/{glu,dglu}/api.py` into `grouped/{glu,dglu}/_blockscaled_api.py`. The test parameters still import the old modules, so all four GLU / dGLU cases fail when run:

```
E   AttributeError: module 'cudnn.gemm.cutedsl.grouped.glu.api' has no attribute '_get_rubin_kernel'
E   AttributeError: module 'cudnn.gemm.cutedsl.grouped.dglu.api' has no attribute '_get_rubin_kernel'
```

The Rubin selection itself is still in place (`self._kernel = _get_rubin_kernel() if self._is_rubin_kernel else ...` in both `_blockscaled_api.py` files). Only the test paths are stale.

## Change

- Point the GLU and dGLU parameters at `cudnn.gemm.cutedsl.grouped.{glu,dglu}._blockscaled_api`. The family name the file-presence test derives from the path is unchanged.
- Mark the four tests `L0`, as the rest of the file is. They are host-only: a file check, mocked capabilities and a lazy import.

## Tests

On a B300:
- Develop, without a marker filter: the four GLU / dGLU cases fail as above; the other 12 pass.
- With this change, `-m L0` on the file selects 27 cases (11 before), and all 27 pass.
