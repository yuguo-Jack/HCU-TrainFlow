## Affected area

FE OSS kernels or CuTeDSL (SM120 SDPA forward).

## Summary

Enable FP16/BF16 exact-D128 forward attention with dense queries over paged KV on SM120. Independent K/V block tables and HND/NHD pool layouts bind through the shared prepared validator. The attention CTA copies selected pages directly into the existing swizzled MMA tiles with 16-byte `cp.async`; no gather/repack launch is added.

## Why

The SM120 half engine currently declines paged KV. Reuse its native compute and scheduler while lowering page addressing inside the producer. Dead rows skip table/pool reads and zero-fill shared memory. Each producer lane commits/drains its copies and publishes an async-tracked `.noinc` arrival to the count-32 barrier. Consumers retain their acquire parity waits.

Paged loads already zero-fill the V tail, so the paged leg excludes the legacy redundant compute-warp tail stores that race PV reads. The explicit local copy drain is retained: removing it failed the targeted racecheck. The guide records this ordering contract and the optional-GridConstant descriptor ABI requirement.

## Related issues

Related to #381.

## API and compatibility impact

Scope is dense Q, exact D_QK=D_V=128, FP16/BF16, unsplit M64/M128 prefill. Existing masks, sinks, schedulers and PackGQA compose. K/V pools retain equal page capacities; their tables and layouts are independent. Page size must be divisible by8 and divide128 or be a multiple of128. THD, quantized pools, decode tiles, other heads, split-KV, bias and score side outputs retain declines.

Standalone table operands and template fields are appended with defaults. Unpaged TMA descriptors retain optional `GridConstant` annotations; unpaged compute/publication is unchanged. No graph API, heuristic, workspace format or tolerance change. Execution adds no allocation, host read, layout conversion or runtime JIT. No performance claim; native qualification is cc12.0 only.
