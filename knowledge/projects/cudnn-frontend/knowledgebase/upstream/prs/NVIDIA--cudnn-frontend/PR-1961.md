# frost(sdpa sparse sm107): the PDL default on the block-sparse decode chain flips ON for cc 10.7 -- the caller-list block launches under programmatic dependent launch by default, bitwise the plain chain and never slower over B 1 / 4 / 32

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1961) · state: closed · merged: True

## Original PR description

## Summary

The PDL default of the block-sparse decode chain flips ON for cc 10.7: `SPARSE_DECODE_PDL_DEFAULT_CCS = ((10, 7),)` (it was empty).  A
caller-list `QsaSpec` block declared with `use_pdl=None` (the default) over bf16 / f16 pools on a cc 10.7 part now launches its chain -- the
norm + RoPE pass, the separate cache write, the separate sigmoid gate, the block-sparse core and its split combine -- under programmatic
dependent launch, exactly what `use_pdl=True` has done since the switch landed: the same kernels, `out` / the gated O / the LSE / the pools
bitwise the plain chain, eagerly and under CUDA-graph capture.

What stays: the explicit knob pins either way (`use_pdl=False` is the plain chain on cc 10.7, `use_pdl=True` is served on every part); every
other part reads False until measured there; the routes that decline the switch keep declining with the same typed reason (the in-block
indexer's decode step -- `QsaSpec(index_source="indexer")` --, `thd=True` on a `QsaSpec` geometry, e4m3 pools, the quantized pipelines), and
AUTO never resolves True where the explicit True is refused.  `DecodeEnvelope.pdl_default` reads the new tuple: True for the served
caller-list form on cc 10.7, False under the indexer and on every other part; the per-step reading is
`decode.pdl_default and decode.route(s_q, batch).pdl_capable` on the dense form and `decode.pdl_default` itself under `sparse_core` (the
sparse core carries the sites at every served step width; the dense route table does not apply there -- the comments / docs that stated
the dense formula for both forms are corrected, from a review comment on this PR).  No kernel change.  No `Capabilities` field or `EngineSpec` changes (a
knob-domain change); the docs' knob row and block-sparse PDL paragraph, the tracker's sentence that stated the old default, the constant's
docstring and every comment / docstring that said "empty until measured" now spell the new default.

## Why: measured on every served route, bitwise, no cell slower

The switched block was measured against the plain one in one process on one exclusive cc 10.7 GPU of the 212-SM class at the locked SM clock
(2376 MHz): CUDA-graph replay medians of A/B/A x 3 rounds x 100 iterations with the slots shuffled per iteration, every arm in the same
process over its own pool holding the same oracle-written prefix bytes, the served block built twice per process as its own control twin (the
pair's magnitude, floored at 1 %, is the cell's band), every numerics oracle before timing (the PDL arm must be bitwise the plain arm), the SM
clock sampled during the timed rounds and the power-cap counters read before and after every process (no event).  Speed-ups are POSITIVE
`baseline / new - 1`; SOL % = the step's own HBM bytes under the whole-layer byte model against that GPU's measured HBM copy bandwidth, the HBM
term.  Under `"auto"` the body is the lean tile at B 1 (batch x KV heads <= 4 CTAs per chunk) and the tcgen05 core at B 4 and B 32, so both
bodies are covered on the route that serves them.

the default may flip for a bitwise, performance-only launch attribute: a cell LOSES if PDL is slower than the plain block beyond that
process's control band; the default flips only if no measured cell loses, every PDL arm is bitwise its plain arm, every oracle passes and
the clock reads clean, with every served route covered.  Result: 13 of 13 cells pass, no cell slower, every PDL arm bitwise, every control
pair within its band -- so the default follows the measurement.  (The earlier per-step bar of >= 1.0 us and >= 5 % that kept the switch
explicit was written for a new kernel body; a launch attribute that changes no bit and loses nowhere is held to "never slower" instead.)
