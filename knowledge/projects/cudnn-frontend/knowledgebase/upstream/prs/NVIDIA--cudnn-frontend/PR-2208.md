# gemm(frost sm100): decline split-K on fp32 sums over all of M and N (G8.1)

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2208) · state: open · merged: False

## Original PR description

## Problem

This is the SM100 port of #2019 (G8.1). The split-K reducer adds an fp32 sum over all of M and N (`[1,1,1]` or `[B,1,1]`) with one same-address atomic per output vector, so its rounding drifts with the number of vectors.

The SM100 tree has no rule for this. `_auto_split_k` splits such chains on its own, and explicit configs or replayed `SPLIT_K_SLC` records compile them.

On B300 (cc 10.3), develop d760fefe, I replayed the listed FROST record with `SPLIT_K_SLC` 1/2/4 on bf16 A = 1, B = 0.125 -> relu -> fp32 AVG over all of M and N, where every element is exactly K/8:

| shape | S=1 | S=2 | S=4 |
|---|---|---|---|
| 3000x3000x1024 | 128.595 | 124.379 (2.8% low) | 124.379 |
| 8192x7168x1024 | 126.662 | 117.051 (8.6% low) | 117.051 |
| 384x384x8192 | 1023.89 | 1023.78 | 1023.78 |

The exact answers are 128, 128 and 1024. ADD and NORM1 came back exact on this data only because every partial sum is an exactly representable power-of-two multiple; on general data they drift the same way.

The unsplit AVG drift on SM100 (4.65e-3 and 1.05e-2 above, against about 1.5e-5 on SM120 per #2019) is a separate issue that this PR doesn't address.

## Change

- `sm100/compiler.py`: add `_splitk_reduction_drifts`, the same rule as SM120. `_splitk_reject_reason`, the gate shared by the automatic pick, explicit configs and knob replay, now declines with that reason.
  - Modes that are exact under atomics (amax, max, min, int32 sums) keep split-K.
  - Per-row and per-column sums keep split-K.
- Tests:
  - `test_gemm_knobs.py`: the host-only gate test now runs for both families (`test_split_k_gate_declines_tile_invariant_fp32_sums[sm100|sm120]`) and needs no GPU.
  - `test_matmul.py`: `test_splitk_declines_tile_invariant_fp32_sum` now runs on any Blackwell GEMM GPU instead of SM120 only.

## Tests

With the change: 14 passed and 1 skipped (the SM120-only knob replay test).
- `-k "splitk or split_k or reduction"` over `test_matmul` and `test_gemm_knobs`: 95 passed, 12 skipped.
