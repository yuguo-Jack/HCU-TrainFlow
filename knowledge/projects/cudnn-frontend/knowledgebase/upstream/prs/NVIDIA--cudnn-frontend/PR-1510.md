## Affected area

FE OSS kernels or CuTeDSL (FROST SDPA forward placement, SM107 (Rubin) half row only).

## Summary

`_place_sm107_f16` led the backend only for a selected native THD split or the qualified packed paged prefill. Every dense graph therefore ran on the backend, including decode-shaped and d512 shapes where the backend is 2-10x slower on Rubin.

For dense graphs on cc 10.7 (no THD, paging, window or sink), this PR adds the measured shards:
- **`2 <= s_q <= 16`**:
  - d192/d256/d512 lead.
  - d64/d128 lead at one KV unit, or at up to 8 KV units with at least 8k KV.
- **Prefill**:
  - d512 and its envelope lead.
  - Chunks of at most 128 Q tiles from a 4k cache lead. These are the SM100 chunk bounds (`CHUNKED_MAX_Q_TILES`, `CHUNKED_MIN_KV_TOKENS`).
- **Unchanged**: squares, wider chunks and `s_q == 1` keep the backend first.

## Why

Setup: gr100 board (cc 10.7, 216 SMs), public cuDNN 9.27.0.42, CuTeDSL 4.8.0. I timed the backend's pick against the first FROST plan with CUDA-graph replay, warm and with an L2 flush, as the median of 11.

There were 620 dense BF16 cases: decode (`s_q` 1 and 4), chunked prefill, squares, the d512 envelope (d320-d448), and a random hold-out.

| Shard | FROST / backend |
|---|---|
| `s_q` 2-16, d192 / d256 / d512 | 0.04-0.75 / 0.08-0.42 / 0.19-0.33 |
| `s_q` 2-16, d64/d128, <= 8 KV units with >= 8k KV, or 1 unit | 0.07-0.63 |
| `s_q` 2-16, d64/d128, 64+ units | 0.91-1.62 (TRAIL) |
| prefill d512 + envelope | 0.08-0.67 |
| chunk, <= 128 Q tiles, >= 4k KV (d64-d256) | 0.04-1.00 |
| squares d64-d256, wider chunks | 0.42-1.98, mixed (TRAIL) |
| `s_q == 1` (d64/d128/d256/d512) | 1.6-25 (TRAIL) |

| Placement | Leads | Mean regret | Leads slower than 1.03x |
|---|---|---|---|
| develop | 0 | 116% | 0 |
| this PR | 224 | 3.2% | 0 |

Measurement caveats:
- On this board the first-measured arm (FROST) can read 40-85% slow on an otherwise identical plan. That biases every ratio above against FROST, so a lead this rule takes is, if anything, understated.
- Another user's jobs shared the GPU for part of the session. Those phases (THD sets, the tail of the d512 envelope sweep, one chunk pass) were discarded, and every number above is from minutes with no other process on the GPU.
- The split-KV cost constants were not refit for Rubin. The fit tool showed that the floor and minimum-tiles constants do not change Rubin's picks, and the board's noise is too high for 10-30% split comparisons.

Not changed: `s_q == 1` d192, which wins 0.37-0.84 only at 128 KV units and needs a wider sweep. Also unchanged are THD, paged, windowed and sink graphs, and the FP8/MXFP8 Rubin rows.

## API and compatibility impact

Only the default plan order for SM107 f16/bf16 dense graphs changes. Explicit knob records and the opt-in flag behave as before.

## Testing

- Heuristics / placement / split-KV / analyzer host tests: 1571 passed, 2 skipped.
- No new unit test pins these bounds (test/AGENTS.md); the measurements above are the evidence.
