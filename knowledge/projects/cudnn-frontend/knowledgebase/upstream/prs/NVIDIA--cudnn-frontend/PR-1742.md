## Summary

Adds `precision="nvfp4"` to the SM100 DSA indexer through a standalone kernel, `indexer_score_unified_sm100_nvfp4.py`, alongside the unchanged MXFP8 kernel.

- **Paths:** every SM100 path that takes `precision="mxfp8"`. These are indexer forward (dense scores), indexer forward + compressed top-k (logits, LSE, fused softmax) and dense score recompute (scores + LSE), in both BSHD and THD.
- **Inputs:** Q/K are packed E2M1 (`torch.float4_e2m1fn_x2`, last dim `head_dim // 2`) with non-negative E4M3 scales per 16 elements. The scales are packed with the existing DSA scale packers. Fold the per-tensor global scales into `sm_scale`.
- **Kernel:** `kind::mxf4nvf4.block16` MMAs (K=64) with a leaner epilogue. The epilogue sets up per-row state once, overlaps the head-weight copy with the first TMEM load, and runs the head reduction unconditionally with a masked store and LSE update. ReLU is exact and accumulation is FP32. `utils/sm100/gemm.py` gains `gemm_ptx_partial_nvfp4`.
- **Format table:** `score_recompute/_block_scaled.py` maps each precision to its dtypes, scale vector size and kernel class.
- **Host checks:** supported head groups are listed in `indexer_forward/_support.py`, and the dense and top-k wrappers refuse other groups before launch. NVFP4 follows the shared trailing-query rule. With zero keys, dense returns empty scores and top-k returns all `-1` indices with `-inf` logits.

```python
scores = cudnn.DSA.indexer_forward_wrapper(
    q_fp4, k_fp4, w, ratio=4, precision="nvfp4",
    q_scale=q_scale_packed, k_scale=k_scale_packed,
    sm_scale=sm_scale * g_q * g_k,          # NVFP4 global scales folded in
    q_causal_offsets=offsets,
)["scores"]
```

## Why

With this change, NVFP4-quantized indexer Q/K can be scored directly. On the measured R100 cases, NVFP4 runs 10-21% faster than the MXFP8 kernel (time ratios 0.794-0.896). The speedup comes from the leaner epilogue, which relieves the epilogue-bound ReLU-weighted head reduction.

## API and compatibility impact

- `precision="nvfp4"` works on the existing indexer forward, compressed top-k and score recompute wrappers.
- `compress_topk_cand_buffer_size` gains an appended `precision=` parameter. Block-scaled launches do not microbatch, so the auto default sizes the full single-launch buffer and an explicit `microbatch_rows > 0` raises.
- `sf_vec_size` now defaults to `None`, which selects the format's vector size: 32 for MXFP8 (as before) and 16 for NVFP4.
- The compressed top-k compile keys no longer include `sm_scale`, for every precision. Changing `sm_scale` (for example, NVFP4 per-step global scales) therefore no longer recompiles. The dense paths already left it out.
- NVFP4 support:
  - SM100 family only (CC 10.0 / 10.3 / 10.7); there is no SM90 path.
  - `qhead_per_kv_head` in {32, 64} with `H_kv = 1`.
  - `D = 128` only.
- The MXFP8 kernel and bf16 behaviour are unchanged.

## Performance

**Setup:** R100 with SM clock locked at 1500 MHz and memory at 3186 MHz, 3 alternating process pairs, between-run CV <= 0.3%.

The table shows NVFP4 time relative to develop's MXFP8 kernel, on the same cases and process pairs (lower is better):

| Case | 64 heads | 32 heads |
|---|---|---|
| P4K / P16K / P64K / P128K | 0.890 / 0.852 / 0.846 / 0.843 | - / 0.818 / 0.794 / - |
| C8K@32K / C8K@128K / C8K@256K | 0.858 / 0.861 / 0.861 | - / 0.800 / 0.799 |
| B8x4K / Bmix31K / B4xC2K@32K | 0.875 / 0.889 / 0.896 | 0.849 / 0.830 / - |

- **Clocks:** under the lock, the sustained SM clock was 1.40-1.41 GHz for NVFP4 and 1.43-1.44 GHz for MXFP8.
- **Commit:** measured on develop `f9525318d`. The forward-kernel changes up to base `d8b0a7ed5` add the 4/8/16-head paths and leave the 32- and 64-head code measured here unchanged.
- **Bottleneck:** at 8192 x 64K, tensor-pipe utilization is 24.9% (64 heads) and 23.3% (32 heads) of the FP4 MMA peak (Nsight Compute, ~2.04 GHz). The epilogue head reduction is the limit, not the MMA.
