# docs: Python API naming conventions for new APIs

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1461) · state: closed · merged: True

## Original PR description

Adds `docs/fe-oss-apis/api_conventions.md`, naming rules for **new** public op APIs (names added to `test/python/api_index/api_index.txt`). The graph API is out of scope. Existing names are unchanged; renames belong to the API pruning plan.

Pattern: `cudnn.<op_name>_<forward|backward>` for PyTorch, `cudnn.<op_name>_jax_<forward|backward>` for JAX, and `cudnn.<op_name>_standalone_<forward|backward>` for framework-free APIs that take raw device pointers and a stream. Each is a function exported from the top-level `cudnn` package.

Rules:
1. Functions only. Exported op classes such as `GroupedGemmSwigluSm100` are legacy.
2. No `wrapper` in names.
3. Spell out `forward` / `backward`; every op has a direction.
4. No architecture or implementation tokens (`sm100`, `dsl`, `frost`, ...); dispatch happens inside the function.
5. No op namespaces (`cudnn.torch`, `cudnn.jax`, `cudnn.gemm`); a JAX variant is marked by `_jax` in the name.

The doc is linked from the FE-OSS overview and Fern nav. The contributor guides (`AGENTS.md`, `python/cudnn/AGENTS.md`, `python/cudnn/README.md`, and the cutedsl integration skill) now describe new op APIs as public functions: what to validate, compile-once reuse, outputs, and stream handling.

**[P2] Do not require an unregistered TupleDict as a JAX function result** ([source](https://github.com/NVIDIA/cudnn-frontend/blob/e8a95bf20e511b99da0802e07f0b847fe3980e4e/python/cudnn/AGENTS.md#L686))

This rule now explicitly requires `<op>_jax_<direction>` functions to return TupleDict. The current TupleDict is an unregistered dict subclass, so returning it directly from a jax.jit-wrapped function raises TypeError rather than returning the op outputs. I reproduced this on CPU using the exact class definition from this head: `jax.jit(lambda x: TupleDict(output=x + 1))(1)` is rejected as an invalid JAX output type, while the plain-dict control passes. Please scope TupleDict guidance to the applicable tensor convenience APIs and require JAX-compatible pytrees for JAX results, or explicitly require a correctly registered return container. Apply the same qualification to the integration recipe. This is a documentation-contract correction; this PR itself does not change runtime exports.

Evidence: Source inspection found no TupleDict pytree registration. Exact-class CPU probe with JAX 0.11.2 reproduced the output-type rejection; a built-in dict control returned the expected value. Attribution: The changed public function contract explicitly extends the previous wrapper return convention to JAX APIs.
