## Affected area

## Summary

`TestIdentityBound::test_adversarial_plant_makes_the_dropped_block_matter` plants a dominant key at token 2049 (`h_2049 = 30 * h_2051`, Q weights copied from K, no QK norm) and requires it to add more than 8 nats to row 2051's LSE. The planted score is about `30 * |W_k h_2051|^2 * scale`, and `|W_k h_2051|^2` is a random draw. With the 30x factor the margin falls below 8 nats on about 5% of datasets. The local B200 draws one of them at seed 6 (6.47 nats). This PR raises the factor to 60.

## Why

Seeds 0-499 on each GPU, run with the unmodified oracle (`evidence/qsa-plant-margin-b200/sweep.py`). Each GPU gets a different dataset per seed because torch's Philox layout follows the SM count.

| GPU | x30: failing datasets | x30: min / median margin | x60: failing | x60: min / median margin | max cos(O_list, O_dense) |
|---|---|---|---|---|---|
| L40S | 22/500 | 3.73 / 13.17 | 0/500 | 15.03 / 33.96 | 0.408 |
| B200 | 27/500 (incl. seed 6) | 3.49 / 13.29 | 0/500 | 14.54 / 34.22 | 0.423 |
| H100 | 32/500 | 4.36 / 12.85 | 0/500 | 16.32 / 33.33 | 0.423 |
| A100 | 32/500 | 4.71 / 13.08 | 0/500 | 17.03 / 33.80 | 0.417 |

The other assertions do not depend on the factor. `_differing_rows == [2051]` held for all 4000 runs, and the cosine bound (`< 0.5`) gives the same values at both factors because the planted key already dominates O at 30x.

## Related issues

Related to #1639, which added the test, and #1674, which reported this B200 failure under Testing.
