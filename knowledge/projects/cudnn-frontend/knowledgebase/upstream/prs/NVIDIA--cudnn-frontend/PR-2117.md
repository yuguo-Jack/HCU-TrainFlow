## Summary

Comment only: no code changes.

The comment on `_EXP2_FMA_SPLIT_CC` (`fwd/api_dsl.py`) keeps the exp2 MUFU / FMA split off on cc 10.3 "until a GB300 A/B says otherwise". Two of the seven `_EXP2_FMA_SPLIT_KERNELS` entries already had B300 numbers: `fp8 (192,128)` and `mxfp8 (192,128)` both lose there. The other five had been measured on B200 only. This PR records a B300 A/B of those five. None wins, so `_EXP2_FMA_SPLIT_CC` stays `{(10, 0)}`.

## Method

- B300 SXM6 (1100 W), cuDNN 9.28.0.38, develop `f510fe8f`.
- Two source trees: A is develop; B is the same tree with `_EXP2_FMA_SPLIT_CC = frozenset({(10, 0), (10, 3)})`.
- FROST forward pinned: `benchmark/attention_training/benchmark_single_sdpa.py --sdpa_backend cudnn_oss --profile_pass fwd`, 50 iterations after 10 warmup.
- A/B/A/B in separate processes with separate caches. Before each run, a check printed the tree's `_EXP2_FMA_SPLIT_CC`, confirming which arm it was.
- The cases are the B200 cases the comment cites.

| entry | case | split on / off, dense | split on / off, causal |
|---|---|---|---|
| `mxfp8 (128,128)` | B=1 H=24/8 S=16K | 1.268, 1.267 | 1.154, 1.152 |
| `fp8 (128,128)` | B=1 H=64/8 S=8K | 1.051, 1.051 | 1.124, 1.119 |
| `f16 (192,128)` | B=1 H=128/128 S=8K | 1.022, 1.019 | 0.998, 1.001 |
| `f16 (128,128)` | B=1 H=64/8 S=8K | 1.049, 1.052 | 1.000, 1.000 |
| `f16 (64,64)` | B=1 H=32/32 S=8K | — | 1.050, 1.050 |

Each cell gives both A/B pairs. The causal `f16 (128,128)` row is identical by construction: the kernel's dense-band gate keeps causal builds all-MUFU.

Not measured: the d64 decode tile's set (`_EXP2_FMA_SPLIT_DECODE_KERNELS`) on cc 10.3.

## Why

The comment asked for this measurement. It answers the question for the five entries, so a later reader does not repeat the A/B or widen the gate.
