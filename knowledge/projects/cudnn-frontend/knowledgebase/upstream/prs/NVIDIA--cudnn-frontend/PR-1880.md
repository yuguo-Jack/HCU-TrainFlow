## Summary

Every SM120 Frost template now creates its A and B data TMA descriptors with `l2_promotion=l2_128b` (the 512-byte scale-factor atoms are left alone), and `Sm120KernelTemplate.multi_gemm_smem_bytes` sizes the packed e2m1 side of a mixed MXFP4 x MXFP8 pair at its real 64-byte SMEM row, as `multi_gemm_ab_stages` and the kernel's ring layout already did. One commit, 9769e15b.

## Why

The templates called `cutlass.experimental.cuda.tensor_map.create_tensor_map_tiled` without an `l2_promotion`, so the descriptors carried the DSL default (none) instead of CUTLASS's 128-byte promotion. A box whose K row is 64 bytes then issues one DRAM request per row. That is exactly the packed e2m1 side of a mixed MXFP4 x MXFP8 pair (a 128-element fp8 K tile holds 128 e2m1 values in 64 B) and any 64-byte K tile.

Measured on an RTX PRO 6000 Blackwell Server Edition (SM120, 188 SMs), CUDA 13.4, cutlass-dsl 4.7.1, torch 2.14.0+cu130, driver 615.71.09, through FlashInfer's unified MoE benchmark (CUPTI, CUDA graph, cold L2, per-backend autotune):

- The MXFP8 x MXFP4 MoE kernels were TMA bound at 0.85 TB/s while the NVFP4 and MXFP8 kernels of the same tile (128-byte rows) streamed at 1.19 TB/s. Removing the mainloop's MMAs, fragment loads and scale loads left the time unchanged, as did 2 to 4 ring stages and a padded one-byte-per-value e2m1 form (see the sibling PR for that experiment). A standalone TMA streaming test of the same boxes reproduces 0.85 vs 1.19 TB/s with promotion none vs `l2_128b`, and shows no difference for 128-byte rows.
- Kernel level, 12-expert 7168x3072 MoE at 16 tokens: FC1 342.8 -> 253.4 us, FC2 129.4 -> 98.1 us; the CuTe-DSL SM12x mixed-input kernels take 251.4 / 97.8 us. Whole MoE call kernel time 473 -> 365 us (SM12x 353 us).
- 40-case matrix (8 shapes x T = 1/16/128/1024/4096, same session A/B): Frost MXFP8 x MXFP4 time becomes 0.883x of before (geomean; T=1 0.86x, T=16 0.81x, T=128 0.84x, T=1024 0.91x, T=4096 0.99x, the last being compute bound). Against the fastest other FlashInfer backend (CUTLASS / cuTile / SM12x) Frost moves from 0.863x to 0.966x; with FlashInfer's stage budgeting following the corrected footprint it reaches 0.997x of SM12x (17 of 35 cases not slower).
- BF16 tiles with a 64-byte K tile load the same way and should gain similarly (not measured separately).

FlashInfer's frozen SM120 MXFP8 x MXFP4 catalog (`flashinfer/fused_moe/backends/cudnn_frost/artifacts/mxfp8_mxfp4`) was re-exported from this commit: all 754 kernel ids are unchanged, only the rendered sources change (the `l2_promotion` lines).

Related PRs from the same investigation: #1881 (scheduler-counter knob, stacked on this PR) and #1882 (the padded e2m1 experiment this fix supersedes).
