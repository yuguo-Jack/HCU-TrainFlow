# Prioritize KV length in unsplit paged prefill scheduling

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1805) · state: closed · merged: True

## Original PR description

Bottom-right paged attention can have short queries with much longer KV prefixes. Ranking those requests by query length can leave expensive KV traversals until late in the persistent work queue.

Use the existing setup kernel's KV-length ranking for the two-CTA paged, bottom-right, non-window prefill path. The shared template serves Blackwell D64/D128 and Rubin paged D128. Query tiles keep their existing LPT order within a request; full prefill keeps its request order because Q and KV lengths agree.

The setup helper now honors its explicit ranking argument directly. Decode and D256 callers retain their former split-only condition at the call site. Engine placement, supported configurations and host preparation remain unchanged. This adds no public knob or kernel launch.

Validation:

- Existing prepared-THD lifecycle tests: B200 **172 passed / 12 skipped**; SM107 **80 passed / 104 skipped**. Skips are unsupported architecture/family combinations.
- Baseline/head numerical checks on seven mixed/full-prefill controls and 16 additional geometries, with and without Stats: full O/LSE references, changed pointers and retained CUDA Graph replay. Paired outputs are bitwise equal.
- Focused SM100 Compute Sanitizer checks with CUDA 13.2 tooling/bindings: baseline and head each pass three cases under memcheck and racecheck, with zero errors or hazards. API-error reporting remains enabled.
- Scoped formatting and license hooks pass. No heuristic-order or timing golden tests are added.

This changes an offered kernel's work order; it does not establish an end-to-end serving improvement or change default engine selection. #1796 changes work-prefix decoding in the same helper area; its adjacent call-argument edit can compose with this change by retaining the split-only ranking predicate while removing the retired work-prefix argument.
