# [SDPA] Build THD descriptors directly from cumulative prefixes

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1850) · state: closed · merged: True

## Original PR description

Small THD batches with cumulative lengths currently publish prefixes to global metadata and wait at a CTA barrier before building descriptors. Build the descriptors directly from the existing cumulative inputs while a separate warp computes metadata, removing that dependency for the opted-in B1–32 path.

The descriptor helper normalizes a sliced cumulative prefix through an appended optional `compact_origin` argument. Independent caller-port origins remain absolute. Larger batches, mixed length formats, insufficient block widths and callers that do not opt in retain their existing paths. Metadata layout, descriptor publication, public graph APIs, workspace requirements and default plan ordering are unchanged.

Validation:
- Native SM107 with public CuTe DSL 4.8.0: **172 passed, zero failures/errors/skips** using the normal repository conftest. This covers 52 descriptor/metadata cases and 60 cases each for native CGA1 and CGA2, including FP64 O/Stats, packed/unpacked execution, three Stats layouts, both log bases, fresh bindings, changed device lengths and poisoned retained captures.
- The 52 descriptor cases also pass on SM100. Deliberately removing cumulative-origin normalization makes the new detector fail; the unchanged candidate passes. Controls include nonzero cumulative origins, empty requests, B33, mixed formats, clipping, rank policy and block width.
- Matched-source component and complete-attention comparisons completed with numerical and retained-replay checks. Performance evidence remains internal; no public timing or serving claim is made.
- Scoped pre-commit formatting and SPDX checks pass. The branch is based on the landed native stack and is whole-tree identical to the tested candidate.
