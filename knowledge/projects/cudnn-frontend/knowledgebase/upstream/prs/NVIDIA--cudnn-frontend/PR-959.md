## Affected area

Python SDPA autograd/provider integration and FROST packed-THD backward.

## Summary

- Preserve packed forward Stats through the public SDPA autograd bridge when a native packed backward path is available; retain the dense compatibility path where it is required.
- Propagate exact packed buffer capacities through graph construction and cache keys, including shared rounded-workspace buckets with different actual totals.
- Mask inactive rows and reduction capacity before they can introduce NaNs into valid gradients; do not apply dense per-batch indexing to packed storage.
- Add public-op and registered PyTorch varlen-provider route/gradient regressions, plus trailing-capacity, GQA, and graph-level coverage.
- Adapt stage-3 GEMM compilation to the current explicit-device interface.

## Why

The graph-level SM100 d512 THD+GQA engine already exists, but the public autograd bridge re-padded packed Stats and made that route unreachable. A declared packed capacity can also exceed the last active prefix-sum entry; inactive capacity must not enter reductions.

## API and compatibility impact

Public call signatures are preserved. Existing engine capability rows are unchanged: this repairs integration and storage semantics, not a new head-dimension or architecture support claim. SM120 packed implementation changes require target-hardware CI in addition to the local SM100 checks below.

**What carried over** (8 files vs develop):

- **`fwd/torch_op.py`:** the packed-Stats backward route (`_thd_bwd_prefers_packed_stats`, the `RAGGED_STATS` offset, exact `T_q`/`T_kv` and `stats_is_packed` in the graph/cache key), adapted to develop's positional bindings.

- **`kernels/sm100/bprop_d512_f16.py`:** keeps the `batch_idx < n_batch` guard around the Stats/delta loads. Idle units in the occupancy-sized grid otherwise read one row past the exact packed buffer.
- **`sdpa/packed_lse.py`:** the trailing-capacity fix now lives in the torch fallback `_torch_repad`, as a gather. Rows at or past `cu[-1]` are never indexed. Develop's prepared repad kernel was already safe.
- **Tests:** in `test_sdpa_bwd_thd_sm100.py`, `sdpa/torch/test_torch_ops.py` and `test_sdpa_fwd_dsl_sm100.py`.

**Made redundant by develop**, so dropped:

- **SM100 THD backward:** now a single prepared pointer host (`prepared_sm100.compile_plan` / `execute_standalone`) that compiles all stages at plan time and keys exact packed geometry. That replaces:
  - the PR's `lru_cache` stage helpers;
  - the plan-time `mm_lo`/`mm_hi` compile;
  - the delta bucket;
  - the length dtype/device checks.
- **`assume_compact_*` flags:** in the old sm120 chain file, which develop moved to `bprop_chain_common.py`; they are no longer needed.

**Not carried over:** zero-total packed sides (`c07ac8832` and the zero-total part of `893caca6b`). Develop's prepared `bind` and the C++ `_SdpaBwdBinder` reject the null pointer that a zero-token tensor has. Lowering `thd_min_total` to 0 would admit graphs that then fail on a workspace-size mismatch. `engines.py`, `frost/tile_dsl/thd.py`, `SUPPORT_MATRIX_TRACKER.md` and `test_sdpa_bwd_thd_sm80.py` therefore stay at develop: zero-total sides decline, as they do today. Supporting them on the prepared host needs a native-binder change and is a separate follow-up.
