# test: wait for allocated GPUs before releasing Torch cache

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1909) · state: closed · merged: True

## Original PR description

With expandable segments enabled, test cleanup can release cached memory on a GPU whose default stream is still running. The Torch allocator in the CI image synchronizes stream 0 on the current device before unmapping another device’s segment. A later scalar-init launch then reports `cudaErrorIllegalAddress`.

Synchronize each device with reserved Torch memory before emptying the cache. Keep devices without allocations untouched. Add a two-GPU regression that checks completion before release, so the old-code failure does not poison the CUDA context.

Validation on GB200 with the CI source and container (Torch 2.14.0a0+b2c75dd062.nv26.09, CuTe DSL 4.8.1):

- Minimal reproducer: old cleanup triggers the same scalar-init illegal address; guarded cleanup passes.
- New regression fails on the old helper and passes with the fix. All 19 tests in `test_conftest_parallel.py` pass.
- Full CuTe DSL CI selection, 16 workers across four GPUs, with a 120-second per-test watchdog: **4,257 passed, 1,892 skipped** in each of two runs (246 s and 242 s).
- Pre-commit hooks and `git diff --check` pass.

The original run also had a QSA stream-test timeout. It did not recur in either fixed full-suite run, including the QSA park and DSA nondefault-stream cases. Its link to the allocator race is not independently established.
