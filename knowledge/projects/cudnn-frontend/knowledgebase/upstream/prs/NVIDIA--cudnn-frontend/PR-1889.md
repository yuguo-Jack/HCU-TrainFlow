## Affected area

FE OSS kernels or CuTeDSL

## Summary

- The norm kernels imported `cutlass.primitives`. The public `nvidia-cutlass-dsl` wheels (4.8.1 checked) export the primitive layer only as `cutlass.experimental.primitives`, the name the FROST SDPA kernels already import; builds that also export `cutlass.primitives` alias it to the same module (as the norm README already said). So on a public wheel every norm engine declined with "does not export cutlass.primitives", and FROST norm was reachable only with an internal DSL build.
- The 18 norm kernel modules and `frost.buffers.cutedsl_primitives_error` now use `cutlass.experimental.primitives`; README, docstrings and notes follow.
- `test_frost_norm_lazy_import`: the decline case now blocks both names. A new L0 case blocks only `cutlass.primitives` (the public-wheel layout) and requires `cudnn.norm` to resolve and two kernel modules to import. Both probes block through `sys.meta_path`, so the kernels' own `import` statements are covered, not only `importlib.import_module` (the old probe patched only the latter, so it could not see the kernel imports).

## Why

Raised in #1817 as an environment caveat: with a public wheel, `cudnn.norm` cannot be used at all. #1817's norm part (new SM90/B300 rows) is #1888.

## Related issues

Related to #1817.

## API and compatibility impact

No API change. Environments with a public DSL wheel can now use FROST norm; environments whose build exports both names import the same module as before.

| `python -m pytest -m "L0 or L1" norm` | | 5278 passed, 50 skipped, **4 failed** |

On develop with the public wheel, every FROST norm kernel file in `norm/cutedsl` skips with "FROST norm tests lowers through the CuTe DSL primitive layer (cutlass.primitives), which the installed nvidia-cutlass-dsl (4.8.1) does not export", and `test_resolving_the_api_does_load_it` fails with the same `ImportError`. With this PR those files run; the skips left are the SM100-only RMSNorm RHT-amax cases, and the one failure in this PR's column is `test_frost_norm_layout`, the first of the four below.

The four failures in the full run are the four that develop also fails on GH200 when `cutlass.primitives` is aliased by hand (4 failed / 5277 passed / 50 skipped there; this PR adds one test): the BatchNorm cooperative-launch retry, and three graph tests that need a norm row serving cc 9.0. #1888 fixes those. The two PRs are independent, except that both edit the same lines of `python/cudnn/norm/README.md`; whichever lands second needs a small rebase there.

Below SM90 the native kernel tests skip: a directory `conftest.py` in `test/python/norm/cutedsl` gates them, since the kernels use mbarrier transaction counts, bulk async copies and clusters. Before it, those tests ran and failed to compile once the public name made them importable on an older GPU. One test is exempt: `test_forward_refuses_mismatched_parameters` raises before any kernel is built, so it carries the `norm_rejects_before_launch` marker (registered in `pytest.ini`) and runs on every GPU. On L40S (cc 8.9), public DSL 4.8.1, `-m "L0 or L1" norm/cutedsl norm/graph/test_frost_norm_lazy_import.py`: develop 8 passed / 35 skipped / 1 failed; this PR at `5b751b0b`, before that exemption, 10 passed / 40 skipped.
