# frost(gemm): write quant scales for partial runtime vectors

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2251) · state: open · merged: False

## Original PR description

## Problem

A reused FROST GEMM plan can stop writing valid quantization scales when runtime N ends inside an epilogue vector. For a mixed row/column F8_128x4 graph compiled at M=256, N=384 and reused at N=352, the existing full-vector predicate leaves 256 valid row-scale bytes unwritten on B300. A separate column-scale predicate drops another 256 valid bytes after the row predicate is corrected.

## Change

- Predicate scalar row-scale writes on the end of the corresponding quantization block.
- Predicate SM100 and SM120 column-scale writes on the column owned by each lane.
- Cover one reused plan across four N values, row and mixed row/column outputs, poisoned scale storage, allocation guards, and changed-input CUDA Graph replay.

This fixes valid scale writes. Padding-byte initialization is the separate subject of #2198; its padding predicates will need to remain consistent with these per-block and per-column bounds.

## Validation

- B300 (SM103), cuDNN 9.27.0.42, PyTorch 2.14.1+cu130, CuTe DSL 4.8.1. The new mixed row/column regression fails on base `f88a1ef2`: 256/2816 row-scale bytes mismatch at N=352.
- With this change, `test_matmul.py -k "reused_quant_plan_writes_partial_scale_rows or dense_mixed_block_quants"`: 3 passed, 2 skipped (SM120-only), including poisoned scale outputs, guard bytes and changed-input capture/replay.
- `test_moe_grouped_matmul_fwd.py -k test_moe_swap_ab_quant`: 8 passed.
- Changed-file Black check, Python syntax compilation and `git diff --check` passed.

Native SM120 execution and performance measurements have not been run.

Requested labels: `cat-bugfix`, `area:gemm`, `area:frost`, `orig-external`. The contributor account cannot apply upstream labels; the milestone is maintained by the project.
