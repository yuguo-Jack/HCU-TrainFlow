# sdpa: release SM107 service-warpgroup registers collectively

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2069) · state: closed · merged: True

## Original PR description

The MMA, load, store and scheduler warps in SM107 half prefill previously released registers at four separate instruction sites. PTX requires all four warps in a warpgroup to execute the same `setmaxnreg` instruction. Move their release to one common site before role dispatch, preserving the register budgets, arithmetic, synchronization and launch geometry.

This fixes the shared D32/D64/D128 body, including packed and unpacked paths and both two- and three-softmax-warpgroup configurations. The regression check runs through the selected SM107 CI entry and detects the old five-release-site rendering versus the corrected two sites (correction and service warpgroups). Five existing cubin-record families are refreshed after same-toolchain parent/candidate compilation; their comparisons and other SASS assertions remain intact.

Validation:
- The new detector fails on the parent at the release-site assertion and passes all seven candidate configurations.
- All 24 existing three-softmax-warpgroup tests pass.
- All 29 historical cubin hashes reproduce under public CuTeDSL 4.8.0 / CUDA 13.4; all 29 candidate PTX/cubin pairs retain the register budgets and existing spill bounds.
- Four existing mixed-length paged cases, in both execution orders, preserve complete O/Stats hashes through initialization, pointer rebinding, fresh/retained graph replay and changed-input replay. The harness retains the same pre-existing one-element O reference-bound failures in all arms and preserves its nonzero exit status; tolerances are unchanged.
- The selected CI entry collects all seven new cases; those seven plus the existing score-output SASS test pass (eight passed, zero skipped). Memcheck reports zero errors; attention-scoped racecheck reports zero errors and zero warnings.

The instruction contract is documented in [PTX setmaxnreg](https://docs.nvidia.com/cuda/parallel-thread-execution/#miscellaneous-instructions-setmaxnreg).
