# the DSA unified indexer scorer serves the small head groups 4 / 8 / 16 per KV head (bf16 + MXFP8) and a trailing query

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1654) · state: closed · merged: True

## Original PR description

## What

The SM100 unified compressed-key indexer scorer (`cudnn.deepseek_sparse_attention.indexer_forward`, the THD and BSHD forms with the fused radix top-k) packed 32 or 64 query heads per KV head on its 128-row MMA tile. This PR packs **4 / 8 / 16 heads per KV head** (32 / 16 / 8 tokens per tile) in both the **bf16** and the **MXFP8** arm, and lets a query token **trail its compressed keys by up to `ratio - 1` tokens** (the block-compressed form's last incomplete block) by applying the ratio-causal limit per token instead of refusing the geometry.

A block-sparse attention indexer with a 4-head x 128 MQA group per token (Qwen-style sparse attention) needs exactly this scorer at 4 heads; it is the kernel half of that indexer. The frontend-only indexer row that consumes it follows in its own PR.

## How

- **bf16**: the unified score kernel's per-token epilogue generalized to the small groups (the per-token ratio-causal limit, the compact and dense stores, the optional online LSE); the `W_ILP` unroll derived from the group (a fixed 8 unrolled zero pairs at 4 / 8 heads -- silently zero scores, now impossible by construction); `_support.py` names the ONE head-group table both arms and the wrapper read.
- **MXFP8**: a new epilogue for the dense small groups -- each epilogue warpgroup owns one 64-column half of the accumulator and loads only its half (the half-tile `Ld32x32b x16` load the 32-head LSE schedule already used); the scale plumbing (Q scale packing per 128 packed rows, the THD scale prefix at `128 // gcd(128, group)` tokens, the TMA / TMEM scale-factor path) was group-agnostic and is unchanged; the 32 / 64-head epilogues are untouched; `max_q_tokens_per_tile` 4 -> 32.
- **The zero-key edge of the trailing query** (found in review): a query shorter than one compressed block has no compressed key yet (S_q 3 at ratio 4 with S_k 0); the dense path returns the empty (B, S_q, 0) scores before any compile or launch (the out-view check keeps the dtype / device / shape contract and skips the row-stride rule for an empty key extent), the compressed top-k wrapper returns its padded result (-1 indices, -inf logits) as before, and one token more is refused by name.
- **Declines** stay typed: a head group outside `(4, 8, 16, 32, 64)` in either precision is refused by name before any launch; the support table is one shared contract (`test_indexer_forward_support_tables_are_the_shared_contract`).
- No new barrier, no new SMEM buffer: the small-group epilogues read the same TMEM accumulator slots through the existing load schedule; the mainloop and the scale pipeline are as before.

## Tests

`test/python/deepseek_sparse_attention/cutedsl/test_DSA_indexer_forward.py` and `test_DSA_indexer_forward_compressed.py` (L0): the small groups in bf16 (BSHD and THD tails, a query tail past the last complete block, 4 heads at top-512 over 7 / 513 / 8192 blocks); in MXFP8 with **random per-32 scales** against the fp64 dequantized reference (the small-group scale packing itself, not only unit scales), the MXFP8 online LSE at 4 and 64 heads, the unit-scale MXFP8 arm equal to the plain e4m3 scorer up to fp32 ties; the decline rows; the shared support table. Run at this head: the two modules 110 passed / 4 skipped (the skips are the SM90-only cells; the zero-key boundary cell is the 110th) on an SM 10.0 part (152 SMs) and on an SM 10.7 part; on a host without a Blackwell-family GPU the device cells skip and the declines run (2 passed / 112 skipped). The API index is unchanged (no public member added). Docs: `docs/fe-oss-apis/dsa.md`.
