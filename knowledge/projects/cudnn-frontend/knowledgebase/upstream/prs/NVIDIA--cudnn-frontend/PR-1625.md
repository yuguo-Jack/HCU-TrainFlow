## Summary

Fixes `test_sm80_thd_compile_key_plan_time_only` in `test/python/sdpa/cutedsl/test_sdpa_fwd_sm80.py`, which fails on `develop`:

- It counted cache hits on `compile_thd_host`, but #1434 put `prepared_sm80_thd.build_launch` (its own `lru_cache`) in front of it. A re-call now hits the launch cache and never reaches `compile_thd_host`, so the expected hit never happens. The test now counts the host compile's misses and the launch cache's hits.
- Its third call used the same token total as the first (256), so it never exercised "same batch count, different totals". It now uses a different total.

The behavior under test still holds: no recompile per token total. The test is `L1`, so the default `L0` CI selection does not run it, which is why this went unnoticed.

## Why

Keeps the continuous-batching regression guard for the SM80 THD forward meaningful.

## Related issues

Related to #1434.

None (test only).
