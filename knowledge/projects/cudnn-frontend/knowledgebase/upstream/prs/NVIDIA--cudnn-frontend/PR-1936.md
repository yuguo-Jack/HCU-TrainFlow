# Reuse workspace device observation in ordered THD execution

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1936) · state: closed · merged: True

## Original PR description

The native ordered THD path already reads the current workspace pointer and extent from its DLTensor, then queries the producer again in Python to check its device. Carry the device from the same native observation into that placement check, removing the duplicate producer query on each execution.

The shared reader retains no workspace facts across calls. The Python API and returned tuple stay unchanged, including completion for unsupported producers. Pointer, capacity and device checks still run before launch. Backend and dense callers keep the existing reader contract; kernels and selection policy are unchanged.

Validation:
- Fresh Release builds with warnings as errors; scoped pre-commit hooks pass.
- Exact parent and head each pass 731 metadata tests, with 31 GPU-dependent cases skipped in that CPU-only run. The workspace regression also checks real Torch CPU storage after accepted CUDA metadata without launching an invalid pointer.
- Separate GPU integration through public FlashInfer plan/run: 12 parent/head comparison cells across two native THD cases and a backend control, in both orders. Full O/LSE references, fresh bindings and retained CUDA Graph replay pass; routes match.

This is a focused host execution change, not a serving performance claim.
