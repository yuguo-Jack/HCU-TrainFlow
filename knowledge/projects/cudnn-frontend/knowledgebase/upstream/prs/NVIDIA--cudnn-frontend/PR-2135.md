# [SDPA] Exclude runtime padding from SM80 native loads

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2135) · state: closed · merged: True

## Original PR description

SM80 forward attention can produce NaN outputs when Q/K/V padding contains NaNs, even though runtime sequence lengths exclude those rows. Score masking cannot remove a NaN V value because multiplying it by a zero softmax weight still produces NaN.

Predicate native Q and K/V loads by the runtime logical length as well as physical capacity. The change applies to both existing SM80 forward bodies and leaves packed-THD addressing intact.

Validation: the new graph regression fails on develop with NaNs in every valid D64 output; an independent unchanged-parent D256 control reproduces the same issue. A100 qualification: 32 regression cases passed. Compute Sanitizer: 8 padding cases plus 24 existing zero/negative-scale controls passed with 0 errors. Tests cover FP16/BF16, all four native families, aligned and tail dimensions, empty sequences, causal/sink/bias composition, fresh bindings, changed-length CUDA Graph replay, and output/Stats canaries. Scoped pre-commit passed.
