## Summary

Fixes #1604. This carries the post-merge P1 on #1534 ([CI follow-up](https://github.com/NVIDIA/cudnn-frontend/pull/1534#issuecomment-6134280207)).

#1534 added a head/tail "phantom" KV step: when a sub-tile's first (or last) KV tile has no live key, the softmax warp group runs `_softmax_phantom_step` and moves `seg_lo` up (or `seg_hi` down). The three loops after it still used the original `bounds.unmasked_lo` / `bounds.unmasked_hi`. With a narrow top-left band both unmasked bounds equal the original `bounds.left`, so the third loop re-runs the KV step the phantom already consumed. The softmax and MMA barrier counts then diverge, and the kernel spins forever.

The fix clamps both unmasked bounds into the peeled `[seg_lo, seg_hi)` and uses them in all three loops. The clamp is the same one `_bounds_for_tile_split` uses, and it keeps `seg_lo <= unmasked_lo <= unmasked_hi <= seg_hi`. When nothing is peeled, the bounds are unchanged.

CI evidence: the 2026-10-13 develop schedule failed `test_sdpa_mxfp8_fwd_L0[test34]` on the SM100 cutlass-rel, SM100 cutlass-4.8 and SM103 cutlass-rel frost lanes. The failure is the conftest watchdog firing at the `torch.cuda.synchronize()` after `graph_fwd.execute`. test34 is B=4, H=4, d=128, s_q=157, s_kv=545, `left_bound=1`, `right_bound=29`, TOP_LEFT, block-scaled O, routed to `frost:sdpa_fwd_prefill_sm100_mxfp8 → prefill_d128_mxfp8`.
