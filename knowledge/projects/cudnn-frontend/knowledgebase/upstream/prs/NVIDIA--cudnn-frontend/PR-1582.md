## Affected area

Python API or bindings (`tools/cudnn_repro` dev tool; also touches its packaging metadata in `pyproject.toml`)

## Summary

- `tools/cudnn_repro/cudnn_repro/log_parser.py`: import `Optional` and change `-> Tuple[str, dict] | None` (`_parse_context_entry`) and `-> Tuple[int, List[int]] | None` (`_parse_tensor_dump`) to `Optional[...]` forms.
- `tools/cudnn_repro/pyproject.toml`: `requires-python` `>=3.8` -> `>=3.9`.

## Why

`Tuple[...] | None` is evaluated at definition time and raises `TypeError: unsupported operand type(s) for |: '_GenericAlias' and 'NoneType'` on Python before 3.10. As a result `import cudnn_repro.log_parser` and the `cudnn-repro` CLI crash on 3.9, even though CONTRIBUTING.md says Python >= 3.9 and the package declared >=3.8. Python 3.8 cannot work either, because other modules use builtin generics such as `list[...]` at definition time, so the declared minimum is raised to match reality.

## Related issues

None

## API and compatibility impact

Raises the declared minimum Python of the `cudnn-repro` dev tool from 3.8 to 3.9 (3.8 never worked). No behavior change on 3.10+.

## Testing

Before the change, on Python 3.9.25, from `tools/cudnn_repro`:

```
$ python -c "import cudnn_repro.log_parser"
TypeError: unsupported operand type(s) for |: '_GenericAlias' and 'NoneType'
```

After the change, on both Python 3.9.25 and 3.13, every module in `cudnn_repro/` imports without error, and:

```
$ pip install pytest looseversion && python -m pytest -q tests
43 passed, 30 skipped
```

`pre-commit run --files tools/cudnn_repro/cudnn_repro/log_parser.py tools/cudnn_repro/pyproject.toml`: black, black-jupyter and SPDX license header passed (clang-format: no files to check).
