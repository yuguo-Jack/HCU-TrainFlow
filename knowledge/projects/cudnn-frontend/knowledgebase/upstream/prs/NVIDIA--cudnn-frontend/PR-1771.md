# fix(dsa): use valid partial-CTA barriers

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1771) · state: closed · merged: True

## Original PR description

## Summary

- replace partial-CTA `NamedBarrier.arrive_and_wait()` calls with the structured `nvvm.barrier_cta_sync(..., aligned=False)` operation
- use the CuTe DSL unaligned nonblocking arrival for the reduce-warp-to-TMEM-deallocation handoff
- preserve every existing barrier ID, participant count, and pipeline ordering edge

The SM100 DSA backward kernel partitions one CTA into load, MMA, compute, and reduce warp roles. `NamedBarrier.arrive_and_wait()` carried an aligned-CTA promise even at role-specific call sites, so Compute Sanitizer reported divergent-barrier failures. The new helper represents the actual contract in NVVM IR without inline PTX: only the named subset participates, and the structured operation still provides the barrier memory-ordering edge.

## Synccheck before / after

The before runs reported `Barrier error detected. Divergent thread(s) in block`. The D576 path is intentionally excluded: reviewer validation exposed a separate, pre-existing mbarrier missing-wait issue that is outside this focused partial-CTA fix.

Please add the acquire before issuing dKV4, or redesign its notification so the unused empty-barrier phases are not advanced. This is a separate existing issue, not a request to undo the partial-CTA fix.
