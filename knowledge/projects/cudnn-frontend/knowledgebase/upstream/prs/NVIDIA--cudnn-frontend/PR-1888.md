## Affected area

FE OSS kernels or CuTeDSL

## Summary

- **SM90 rows (opt-in).** `norm_fprop_sm90` / `norm_bprop_sm90` on appended manifest slot 1 of each family. The norm kernels use cp.async.bulk, clusters, mapa and mbarriers, all Hopper; the rows stay behind `CUDNN_FRONTEND_ENABLE_FROST_ENGINES` until they lead the backend everywhere (benchmark below).
- **TMEM tier gated.** The one SM100-only instruction family on these paths is the BatchNorm NHWC training forward's TMEM cache tier (tcgen05). `utils.has_tmem()` gates it; without TMEM, `_knobs_for` picks the large-M smem tier and `_tmem_cap` returns 0. On develop the direct API on SM90 fails to compile these shapes ("unsupported operation").
- **Cooperative-launch fallback.** The BatchNorm kernels fall back from occupancy 2 to 1 on a too-large cooperative launch, but matched only the driver spelling `TOO_LARGE` while the DSL raises `cudaErrorCooperativeLaunchTooLarge`. `utils.coop_launch_too_large` accepts both, in the four BatchNorm launchers. This also fixes an existing BatchNorm layout test that fails on B300 on develop.
- **B300 on the SM100 rows.** `Capabilities.arch` (one exact cc) becomes the set `Capabilities.archs`; the SM100 rows serve `{(10, 0), (10, 3)}`. The kernels emit nothing SM100-only that SM103 lacks.
- **Tests.** `test_frost_norm_layout`: two L0 BatchNorm NHWC cases that reach the cache tiers (mid M 16x256x56x56, wide C 8x1024x7x7). `test_frost_norm_engines`: each row accepts only its own ccs, and the SM90 rows are offered only under opt-in, on slot 1. `test_frost_norm_engine_e2e`: runs the row serving the current device, skips where none does. `test_frost_norm_graph_roundtrip` and `test_frost_norm_no_alloc` skip on a device that no norm row on offer serves (`norm_test_utils.frost_norm_rows_offered_here()`, opt-in rows counted only under the variable); where one does, a planning failure fails them. README updated.

## Why

Proposed in #1817: the norm engines compared the device cc exactly against `(10, 0)`, so GH200/H100 and B300 got no FROST norm plan through the graph API.

## Related issues

Fixes the norm part of #1817.

## API and compatibility impact

No public API change. New engine rows: opt-in on SM90; on cc 10.3 the SM100 rows now produce plans (previously declined). `Capabilities.arch` is renamed to `archs` inside the norm engine modules (internal dataclass, only read by `mismatch`).

**Environment caveat (raised in #1817):** `cudnn.norm` imports `cutlass.primitives`, which the public `nvidia-cutlass-dsl` 4.8.1 wheel ships only as `cutlass.experimental.primitives`. All runs below alias `cutlass.primitives` to the experimental module in the test environment; this PR does not change the import (#1889 switches it to the public name).

## Testing

GH200 (sm_90), develop `4cd4e613` plus this branch (rebased onto `fa065f1e` after the runs; the commits in between do not touch the files this PR changes), CuTe DSL 4.8.1, cuDNN 9.27.0, torch 2.14.1+cu130, CUDA 13.2, `CUDNN_FRONTEND_ENABLE_FROST_ENGINES=1`, run from `test/python`:

| Command | develop | this PR |
|---|---|---|
| `python -m pytest -m "L0 or L1" norm` | 5277 passed, 50 skipped, **4 failed** | 5290 passed, 41 skipped |

Develop's four failures on GH200 are the BatchNorm cooperative-launch retry (`test_frost_norm_layout`) and three graph tests that need a norm row serving cc 9.0 (`test_frost_norm_engine_e2e`, `test_frost_norm_graph_roundtrip`, `test_frost_norm_no_alloc`); all four pass on this branch, and no test goes from pass to fail.

B300 (cc 10.3), measured on develop `f2aa360e` plus this branch (no norm file changed between `f2aa360e` and `fa065f1e`): `norm` at L0+L1 5328 passed / 3 skipped; develop 4 failed (three graph tests whose SM100 row refuses (10, 3), and the BatchNorm layout test that hits the cooperative-launch retry).

`benchmark/norms/benchmark_cudnn_vs_frost.py` over its 15 config shapes, FROST vs the cuDNN backend, geomean (forward / backward):

| GPU | bf16 | fp16 |
|---|---|---|
| GH200 | 1.01x / 1.02x (per shape 0.92–1.15x) | 1.06x / 1.09x |
| B300 | 1.00x / 1.06x | 1.00x / 1.06x |

Hence opt-in on SM90. No SM100 (cc 10.0) GPU run here.
