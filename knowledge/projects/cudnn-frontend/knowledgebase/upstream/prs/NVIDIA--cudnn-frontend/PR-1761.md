## Affected area

FE OSS kernels or CuTeDSL (DSA indexer forward; Python wrappers only, no kernel change).

## Summary

Adds a keyword-only `clean_logits: bool = True` to the dense indexer forward entry points:

- `DSA.indexer_forward_wrapper(..., *, clean_logits=True)`
- `DSA.IndexerForward(..., *, clean_logits=True)`
- `indexer_forward._interface.indexer_fwd` (BF16 and MXFP8) and its strict `_indexer_fwd_bound` entry
- `indexer_forward._interface_sm90.indexer_fwd`

`True` keeps today's behaviour byte for byte. `False` skips the `out.fill_(-inf)` that runs before every dense score launch. `docs/fe-oss-apis/dsa.md` (Indexer Forward section) and the docstrings state the contract below.

The same docs bullet also said that a caller `out` which is not a padded-stride view raises `ValueError` and that "nothing is staged or copied back". `indexer_forward_wrapper` actually stages such an `out` and copies the result back, as its docstring says and `test_DSA_indexer_forward.py` checks. The bullet now describes what the wrapper does, because the new rejection below depends on it.

## Why

The dense wrappers write the whole `(T_q, S_k)` FP32 score tensor twice per call: once with `-inf`, then from the score kernel. Since the SM100 path moved to the unified score kernel (#370), that kernel writes exactly each row's ratio-causal prefix and never writes `-inf`, so the fill exists only so that masked positions read `-inf`. Passing `out=` (#470) does not avoid it.

Many consumers never read those positions. The common pattern is dense scores followed by `indexer_top_k` with `next_n=1` and per-row lengths equal to the causal limit. Long-context training and prefill in inference stacks both use it. For these consumers the fill only costs write bandwidth:

- **Isolated primitive, one GB300 (SM103)**, AWS-CMH job 4595144. The shapes are GLM-5.2 1M-token packed THD with CP64 slot shapes. The stack is FE 1.31.0 + CuTe DSL 4.6.2. The fill's cost depends only on the buffer size, not on the FE version. Numbers are CUDA-graph replay, p50 per call, one GPU per shape:

  | CP rank (slot) | `-inf` fill | scorer call incl. fill | scorer + `indexer_top_k` | same without the fill |
  |---|---:|---:|---:|---:|
  | 0 (64 GiB score buffer) | 8.79 ms | 61.11 ms | 82.56 ms | 73.77 ms (-10.6%) |
  | 21 | 7.36 ms | 59.22 ms | 80.89 ms | 73.54 ms (-9.1%) |
  | 42 | 5.92 ms | 57.27 ms | 76.74 ms | 70.81 ms (-7.7%) |
  | 63 | 4.49 ms | 55.36 ms | 73.75 ms | 69.26 ms (-6.1%) |
  | 128K context | 0.284 ms | 2.218 ms | 2.836 ms | 2.551 ms (-10.0%) |

  The torch profiler shows the fill as the torch fill kernel at about 7.8 TB/s. Skipping it does not change peak memory, because the score buffer is still allocated.
- **In training**, OCI-AGA job 1175415: GLM-5.2, 1M context, 256 GB300, TP1/PP4/EP64/CP64, Nsight Systems step 7. The fill takes 8.77 ms per call on CP rank 0. With 96 scorer calls per step on the bottleneck pipeline stage, that is about 0.84 s per step (about 1.9% of a 44.1 s step), and 0.98 s on the first stage (112 calls). At 128K context it is about 53 ms per step. These per-step figures multiply the measured per-call fill by the call count; they are not an end-to-end A/B.
- **Precedent.** DeepGEMM's `fp8_mqa_logits` exposes the same choice as `clean_logits`. SGLang's DSA indexer passes `clean_logits=False` to it on CUDA and lets the top-k mask by per-row range. sgl-project/sglang#28757 did the same on the HIP path, where the fill was about 11% of prefill GPU time (GLM-5.1, 16x8192, MI350X). vLLM avoids the dense fill by switching to compressed logits plus per-row top-k. This PR keeps the dense API and lets callers that read only the causal prefix skip the fill.

With `clean_logits=False`, `IndexerForward.execute()` launches only the score kernel. For callers that don't need the `-inf` mask, this removes a hidden `fill_` launch (`python/cudnn/AGENTS.md` Rule 2).

## Contract

With `clean_logits=False`, for local query row `q_local` of batch / THD segment `b`, the kernel writes only the columns

```
k_local < clamp((q_causal_offsets[b] + q_local + 1) // ratio, 0, seqlen_k_b)
```

(`q_causal_offsets` defaults to 0, as it does for the mask itself). Every other element of the output is **unspecified**: stale or uninitialized memory, possibly NaN. That covers:

- columns at or past that limit,
- THD columns past a segment's own `seqlen_k_b`, up to `max_seqlen_k`,
- THD rows not covered by `cu_seqlens_q`.

Use it only when every consumer reads each row's causal prefix and nothing else. An example is `indexer_top_k_wrapper(scores, seq_lens, top_k, next_n=1)` with per-row `seq_lens` no larger than the limit above.

I re-checked this contract against develop `2f5e93c0`. Every dense store in the SM100 unified kernels writes under `q_token_idx < seqlen_q && pos < col_limit && pos < seqlen_k`, with `col_limit` as above:

- BF16 `IndexerScoreUnifiedSm100._epilogue_indexer_dense`, all head groups;
- MXFP8 `_epilogue_indexer_dense_single_q` (64), `_epilogue_indexer_dense_qh32_pair` (32) and `_epilogue_indexer_dense_group` (4/8/16).

`_dense_compute_n_blocks` visits every K block below the last row's limit, and all of these stores are plain stores. On SM90, every valid position is likewise written by a plain store; the existing reference tests already require that with the fill on. Whether SM90 also writes positions outside the prefix is left unspecified. No dense path reads the prefilled value.

Rejected with `ValueError`:

- A caller `out` that the convenience entry would stage through a padded buffer and copy back, because the kernel cannot bind its layout. A whole-buffer copy-back costs as much as the skipped fill, and copying back only each row's prefix would need a ragged per-row copy. Rejecting it keeps the flag's meaning honest. The padded-stride view (`buf[..., :S_k]` of a `ceil4(S_k)` allocation) and `IndexerForward` bind directly and are unaffected. SM90 binds a contiguous `out` directly, so nothing is rejected there.
- `clean_logits=False` on the compressed-logits path (`is_compressed_logits=True`), which has no dense output. `indexer_forward_top_k_wrapper` does not take the flag.

The flag is not part of any compile key (Rule 4), so one compiled kernel serves both settings. SM90 LSE is unaffected.

## Related issues

None filed. History: the fill arrived with the v1.24.0 DSA sync. #297 added an SM90 kernel-internal `clean_logits` that was never wired to the API and was removed by #370.

Draft #1742 (NVFP4 indexer) touches the same files: it folds the MXFP8 branch of `_indexer_fwd_bound` into a shared block-scaled branch. The guarded fill sits in that branch, so whichever PR lands second needs only a small rebase, and NVFP4 inherits the flag.

## API and compatibility impact

The new parameter is keyword-only, appended at the end of each signature, and its default preserves current behaviour byte for byte. This PR changes no kernel, compile key, dtype or architecture support. `indexer_forward_top_k_wrapper` is unchanged, and so are the public names in `test/python/api_index/api_index.txt`.

A known consumer is Megatron-LM's DSA cuDNN path, which probes `indexer_forward_wrapper` for a parameter named `clean_logits`. It passes `False` only for the packed-THD scorer whose only reader is per-row top-k.

## Testing

New file `test/python/deepseek_sparse_attention/cutedsl/test_DSA_indexer_forward_clean_logits.py` (24 tests, all `L0`). Every test NaN-poisons its output buffers, so any read outside the causal prefix shows up:

- `..._is_keyword_only`: `clean_logits` is keyword-only with default `True` on all four entry points, and absent from `indexer_forward_top_k_wrapper`.
- `..._thd_top_k[h_q 4/16/32/64, ratio 1/4, top_k 64/2048]`: THD with per-segment causal offsets, ragged K tails (segments of 1..2600 keys, `max_seqlen_k` 2600) and three rows not covered by `cu_seqlens_q`. The head groups cover each SM100 tile packing (8/8/4/2 query tokens per tile). Requires:
  - the documented limit to equal the reference mask;
  - the `clean_logits=False` prefix to match the float64 reference, and the `clean_logits=True` run bit for bit;
  - `clean_logits=True` to still write `-inf` over every masked position despite the poison;
  - some masked position to stay NaN, so the fill really is skipped;
  - `indexer_top_k` with per-row lengths equal to the limit to return identical indices and values (ordered by index first, since slot order is unspecified) and to match the top-k reference.
- `..._bshd_default_unchanged[ratio 1/4]`: BSHD without offsets. The default (no kwarg) equals `clean_logits=True` bit for bit and passes the full reference check, including the `-inf` pattern. The compile cache holds one entry after both settings. Same prefix and top-k checks as above.
- `..._thd_mxfp8[qh64/qh32/qh8]` (SM100): the same checks for MXFP8 THD against the dequantized reference, one head group per MXFP8 dense epilogue (single token, token pair, small group).
- `..._rejects_staged_out_and_compressed_path` (SM100): a contiguous caller `out` with `S_k=67` raises before any launch (the buffer is still all NaN). The default still stages and copies back correctly. `clean_logits=False` without `out` returns the prefix. The compressed path rejects the flag.
- `..._padded_view_bound_directly` (SM100): a padded-stride `out=` view and the `IndexerForward` plan with `S_k=1001`. The prefix is bitwise equal to the clean run, the pad columns are never written, and top-k is identical.
