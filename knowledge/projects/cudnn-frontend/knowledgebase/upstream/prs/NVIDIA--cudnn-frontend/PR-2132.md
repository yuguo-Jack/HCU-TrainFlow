# perf(sdpa): reduce SM80 D256 short-query tile storage

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2132) · state: closed · merged: True

## Original PR description

Short dense D256 queries use the same 128-row, 8-warp tile as long prefill, with 128 KiB of shared memory. Use 64 rows, 32 keys and 4 warps for exact D256 dense queries of at most 128 rows, reducing shared memory to 64 KiB. Explicit tile requests remain intact. The existing D256 kernel body serves the new geometry; no staging buffer or extra launch is added.

Admit 32-key tiles only for the physical D256 family and make explicit 64-row tiles use four warps in that family. Other families retain their key-tile domains. Graph capability and candidate-policy files are unchanged. The tested short-query set has a clear aggregate benefit with a small MHA tradeoff; long-query defaults retain their existing geometry.

Depends on #2130 (which builds on #2128); land those first.

Validation: host geometry/admission checks pass (45 tests; parent fails 11). Focused qualification passed 265 checks (45 host and 220 native SM80), covering FP16/BF16, masks, noncontiguous inputs/outputs, Stats strides, rebinding, retained capture/replay, explicit tile controls and the existing prepared contract suite. Twelve scoped memcheck cases pass with zero errors. Scoped pre-commit hooks pass. The separate ten-case, four-geometry, both-order experiment passed 80 full-reference O/Stats, replay and canary observations.

The committed-source automatic route also passes 40 paired replay observations across the same ten cases, with unchanged long-query controls.
