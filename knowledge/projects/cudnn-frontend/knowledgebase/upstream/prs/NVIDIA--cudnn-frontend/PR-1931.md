# sdpa: support native SM107 FP8 sinks with split-KV

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1931) · state: closed · merged: True

## Original PR description

Dense per-tensor FP8 graphs on SM107 currently reject attention sinks with split-KV, although their native D64/D128/D192x128 kernels already produce the required FP32 partials. Admit that combination through the shared sink-combine path: each native main kernel remains sink-free, and the final combine includes the sink once while preserving output scaling, Stats, and Amax.

The change keeps existing head-envelope, PackGQA, scheduler, CGA, paged, and THD restrictions. Native D256/D512 split and MXFP8 sink/split support remain separate. Heuristic and placement source files are unchanged.

Parents #1929 and #1930 are merged. This PR now contains only the native SM107 follow-up. The SM107-only commit consists of the common admission predicate, matching diagnostics, the support tracker, and a target-architecture test file.

Validation on target hardware: the previous admission reproduces RED; 32 new full-output/rebind/retained-CUDA-Graph tests and 75 existing native architecture controls pass. Two targeted memcheck cases pass with zero errors, and default FROST collection includes the new suite. The tests assert native SM107 source routing and cover both FP8 inputs, BF16/FP8 output, empty split chunks, explicit and omitted scales, and independent D256/D512 declines.

Eight same-feature cases / 180 explicit plans pass full O/Stats/Amax checks before and after warmed CUDA Graph replay. Target performance evidence stays internal. Scoped formatting hooks and diff checks pass.

Parent #1929 is now merged into this branch. The complete source tree is identical to the qualified pre-merge tree; this update changes ancestry only.

Parent #1930 is also merged into this branch. Its complete source tree remains identical to the target-qualified tree; the current diff is limited to the five SM107 follow-up files.
