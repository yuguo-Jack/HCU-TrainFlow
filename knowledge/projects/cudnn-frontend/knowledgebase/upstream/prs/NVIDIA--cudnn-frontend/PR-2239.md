# test(qsa_score_paged): skip the selector cells past the SM120 deterministic top-k column cap

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2239) · state: open · merged: False

## Original PR description

## Problem

The paged selector in `qsa_select_decode_paged_forward` runs the deterministic FP32 `IndexerTopK`. On SM120, `IndexerTopK` serves at most `_SM120_DETERMINISTIC_MAX_NUM_COLS[torch.float32]` columns, which is 16,384, and its `check_support()` declines wider rows:

```
RuntimeError: deterministic IndexerTopK on SM120 supports at most 16384 columns for torch.float32, got 32768
```

The `n_blocks_max=32768` cells in `test/python/gated_attention_block/cutedsl/test_qsa_score_paged.py` hit that decline, so on an RTX 5060 Ti (cc 12.0) they fail instead of skipping:
- `test_paged_selection_matches_the_fp64_topk_set_up_to_ties`: 12 cells
- `test_paged_selection_on_the_e4m3_pair_is_the_selection_on_the_same_values_upcast`: 3 cells

## Change

Both tests skip those cells on SM120. The skip reads the cap from `indexer_top_k.api` and uses the API's own `(12, 0)` condition, so it follows any change to the cap. No other cell is affected.

## Testing

RTX 5060 Ti (cc 12.0), develop `a0f7b9f4`, cuDNN 9.27, `-m L0 test/python/gated_attention_block/cutedsl/test_qsa_score_paged.py`:
- develop: 15 failed, 224 passed.
- this PR: 0 failed, 224 passed, 17 skipped.

I compared the outcomes test by test: every cell that passes on develop still passes.

`black 26.3.1 --line-length 160 --fast` is clean.
