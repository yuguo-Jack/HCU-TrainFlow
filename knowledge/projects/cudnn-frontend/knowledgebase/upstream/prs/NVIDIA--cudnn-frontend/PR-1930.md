# sdpa: admit per-tensor FP8 D512 graph split plans

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1930) · state: closed · merged: True

## Original PR description

Depends on #1929; the follow-up itself adds the existing D512 flavor to the per-tensor FP8 graph split domain. Standalone already supports this split kernel, while an otherwise identical graph plan was rejected by `split_d_shapes`.

Dense D512 and its existing 16-aligned head envelope now use the same FP32 partials and final combine through the graph API, with O scaling, Stats and Amax, including sink composition from #1929. Scheduler, CGA, scalar-tail, paged and packed-Q constraints stay in place. No kernel body, heuristics or placement change. The support tracker and the previous packed-domain decline detector are updated.

Validation on SM100, 148 SM / 600 W, cuDNN9.27.0.42, CuTeDSL4.8.0:

- RED before admission; 33 graph/domain cases pass after. Covers exact D512 and D384x320 envelope, both FP8 inputs, all four output dtypes, packed/unpacked GQA, empty split chunks, padded output storage, sinks, rebind and changed-input capture replay.
- Targeted envelope/FP8-output/sink memcheck: zero errors. All 32 new cases are collected by the normal FROST folder and CI filters.
- Four same-feature B2 H4/KH2 KV8192 cases, Q1/Q17 with/without sink: 72 explicit plans check full O/Stats/Amax before/after timed replay. New split plans take 35.2%–48.8% of the best measured unsplit latency, improving in both candidate orders. Includes all three legal schedulers in correctness checks. These are warmed local CUDA-graph measurements, not default-selection or serving claims.

Incorporated parent review fix21ef93447 in4d7a38d59: serial combine masks zero-weight partial payloads. Parent307 regressions pass. This PR's unchanged four-cell/72-plan performance probe was also rerun after the update, with full O/Stats/Amax checks before/after replay; all four cells still improve in both candidate orders.

Parent #1929 is now merged into this branch. The complete source tree is identical to the qualified pre-merge tree; this update changes ancestry only.

This capability expansion can change automatic first-plan selection even though heuristic and placement source files are unchanged. Review reproduced a slower first plan for B2, Hq/Hkv4/2, Q257, KV8192, D512, E4M3 inputs/BF16 output without a sink. The explicit split capability remains useful for the measured short-Q region; the first-candidate regression is handed to the heuristics owner for policy qualification. See the nonblocking P2 in https://github.com/NVIDIA/cudnn-frontend/pull/1930#pullrequestreview-5666421562.
