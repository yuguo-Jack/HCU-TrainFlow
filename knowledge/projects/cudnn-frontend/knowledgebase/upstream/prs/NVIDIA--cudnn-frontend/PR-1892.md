## Affected area

FE OSS kernels or CuTeDSL

## Summary

- `kda_bwd_sm90.cu` hard-coded `KSCALE = 1/sqrt(128)` in `k_prep` and `k_bwd`, so `KdaHopperCudaEngine` declined every backward graph with a non-default scale while its forward kernel already took the scale as an argument.
- `k_prep` and `k_bwd` take `float scale` (a kernel argument, not a `-D` define, so one NVRTC build serves every scale); `cuda_bwd_host.launch` passes it; `KdaHopperCudaBwdPlan` reads it from the node like the forward plan does (default `1/sqrt(128)`). The engine's backward scale decline is removed.

## Why

#1818: on Hopper, KDA training graphs with a non-default query scale had no backward engine.

## Related issues

Fixes the backward-scale part of #1818.

## API and compatibility impact

No API change. The default scale gives the same kernel arithmetic as before; non-default scales are now served on SM90.
