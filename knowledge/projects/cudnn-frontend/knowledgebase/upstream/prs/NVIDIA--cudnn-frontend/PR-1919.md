## Summary

Fixes a regression introduced by c5e02afd where adding thd_excluded_d_shapes to Capabilities changed the append-order contract pinned by SDPA FROST tests.

The new field was appended after pack_gqa_requires_divisible, which shifted Capabilities[-6:] and broke:

test/python/sdpa/frost/test_sdpa_bias_sm107.py::test_template_params_and_capabilities_are_appended

This patch moves thd_excluded_d_shapes to immediately after dense_only_d_shapes, before the resident-bias / kv-mask append-order pins, preserving the existing Capabilities[-6:] contract.

## Root Cause

test_template_params_and_capabilities_are_appended intentionally pins the tail ordering of Capabilities:

bias_d_shapes
bias_io_dtype_only
kv_mask
kv_mask_dtypes
tile_ns_by_d_shape
pack_gqa_requires_divisible

c5e02afd added thd_excluded_d_shapes after pack_gqa_requires_divisible, so the dataclass tail became:

bias_io_dtype_only
kv_mask
kv_mask_dtypes
tile_ns_by_d_shape
pack_gqa_requires_divisible
thd_excluded_d_shapes

That violated the append-order pin even though the new capability itself is valid.

## Fix

Move thd_excluded_d_shapes earlier in the dataclass:

dense_only_d_shapes
thd_excluded_d_shapes
bias_d_shapes
bias_io_dtype_only
kv_mask
kv_mask_dtypes
tile_ns_by_d_shape
pack_gqa_requires_divisible

This keeps the new native dense-Q-only capability while preserving the resident-bias / kv-mask tail ordering contract.
