## Affected area

FE OSS kernels or CuTeDSL (SM120 MXFP8 SDPA lowering).

## Summary

Dense, unpadded exact-D128 SM120 MXFP8 graphs can request split-KV with an attention sink. The main specialization produces sink-free half partials; the existing prepared combine adds the sink once and preserves O, Stats and Amax_O.

## Why

The MXFP8 adapter already has the prepared scale-factor binding and half-partial combine, but rejects sink splits. Share one bounded eligibility predicate between graph and standalone checks and disable the sink only on the partial producer.

## Related issues

Related to #381. This is separate from #2184, which covers per-tensor FP8.

## API and compatibility impact

No public signature, kernel ABI, workspace layout, placement or heuristic change. Other MXFP8 heads, THD, padding, paging, block-scaled output and epilogue gates retain their declines. Direct template calls that fold sinks per partial remain refused. Graph MXFP8 Stats remain natural-log; the standalone adapter also retains final base-2 Stats. Native qualification is cc12.0 only; cc12.1 shares the gate but was not tested.

## Testing

NVIDIA RTX 6000D (native cc12.0), Python3.12, Torch2.13.0+cu130, cuDNN9.27.0.42 and CuTeDSL4.8.0/CUDA13.4 compiler. A fresh extension was built from the upstream baseline; all test processes import this source checkout.

Native baseline RED: both new eligibility assertions and the first strict FROST graph failed at the old sink/split refusal. Feature suite: **23 passed**. Tests cover E4M3/E5M2 inputs, four scalar output dtypes, split2/9 with empty chunks, per-block SF and sink storage/content changes, retained capture/rebinding, physical output padding, optional Stats/Amax, and standalone keyless rows with natural/base-two final Stats against FP64 references. No tolerance changes.
