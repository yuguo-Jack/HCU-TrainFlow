# sdpa(fp8): decline padding mask + left band bound on Hopper (#1009)

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1069) · state: closed · merged: False

## Original PR description

## Summary

Fixes #1009 (`deploy:test_bdist_wheels_ga_cudnn_3.12:sm90` hanging on `test_bprop_fp8_thd[test52]`).

- **Root cause (backend, SM90 only):** the Hopper FP8 SDPA *forward* kernel never finishes when a whole Q tile has no valid keys. Two ways to get there in the fuzz suites:
  - `test52`: THD fp8 e4m3, b=2, GQA 3:1, d=64, s=6447, `seq_len_q=[5380, 5176]`, `seq_len_kv=[5175, 1307]`, TL band `left=1224 / right=2078` -- rows past `kv_len + left_bound` of batch 1 see no keys.
  - `test359` (found by running the whole suite on H100 with the first fix): **no window**, b=3, MHA d=128, `seq_len_q=[270, 6898, 1785]`, `seq_len_kv=[2022, 0, 540]` -- a zero-length KV batch.

  The hang is in the fwd `execute` + `synchronize` (fp8.py:596), not the bwd graph -- Hopper already declines fp8 ragged bwd. Reproduced with cuDNN 9.25.0.21 and 9.27.0.28; the identical configs pass in FP16 and on SM100.
- **Frontend gate:** `validate_sdpa_support_surface` now declines `SM90 && padding_mask && left_bound` for FP8 forward with `GRAPH_NOT_SUPPORTED`. Blackwell and FP16 are untouched.
- **Harness skip:** `test/python/sdpa/fp8.py` skips SM90 fp8 padded draws in which some batch has `seq_len_q > 0` and (`seq_len_kv == 0` or a TL left bound ending past its keys). `seq_len_kv == 0` is runtime data the frontend cannot see, so this cannot be a graph-level rule; the message names the issue.
- Adds `test/python/test_sdpa_fp8_hopper_padding_window_rejected.py` (validation-only, pins `pygraph(sm_version=90)` so it runs on any GPU; positive controls for no-left-bound / no-padding / SM100) and documents both limitations in `docs/operations/Attention.md`.

## Evidence (H100 NVL, FE develop `2a0343f07`, cuDNN 9.25.0.21 via LD_PRELOAD; fwd-only variants)

| variant | result |
|---|---|
| test52 as drawn | **hang** (>8 min; also hangs on cuDNN 9.27.0.28) |
| test52, no window (`left=right=None`) | pass 2.7 s |
| test52, dense (no ragged/padding), same band | pass 2.2 s |
| test52, equal per-batch lens `kv=[5175, 5176]` | pass 2.0 s |
| test52, `kv=[5175, 3200]` / `3000` (>= 1 full dead Q tile) | **hang** (3/3) |
| test52, `kv=[5175, 3900]` (52 dead rows, no full tile) / `4000` (none) | pass (one 4000 run took 47 s, then 2.3 s -> racy) |
| test52, left-only causal window (`right=0`) | **hang** |
| test52, right-only window (`left=None`) | pass 2.9 s |
| test52 in fp16 | pass 2.1 s |
| test359 as drawn (`kv=[2022, 0, 540]`) | **hang** (>25 min in the suite run, >150 s standalone) |
| test359 with `kv=[2022, 64, 540]` | pass 1.5 s |
| test359 in fp16 | pass 2.4 s |

With this PR, `test52` and `test359` skip on the H100 in 0.2 s (`SM90 FP8 forward hangs on query rows with no valid keys (...; GitHub #1009)`).

## Trade-off

The graph-level gate is broader than the trigger: it also declines Hopper FP8 padded/THD + sliding-window graphs whose batches all satisfy `seq_len_q == seq_len_kv` (self-attention), which run fine. FE cannot see per-batch lengths at plan time. Once the SM90 kernel is fixed in the backend, bound this rule by backend version and drop the harness skip.

- vedaanta · comment · 2026-09-15T17:29:48Z · [source](https://github.com/NVIDIA/cudnn-frontend/pull/1069#issuecomment-5684929853)

Backend root cause + fix: cuDNN MR !4489 (`vagarwalla/sm90-fp8-fprop-dead-q-tile` -> dev).
