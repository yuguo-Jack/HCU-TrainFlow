# sdpa fwd placement: SM100 per-tensor FP8 decode-shaped GQA leads with FROST (MTP / gpt-oss sink)

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1876) · state: closed · merged: True

## Original PR description

## What

On SM100, `_place_sm100_fp8` put the backend ahead of FROST for every `2 <= s_q <= 16` graph (MTP / spec-decode verify widths) and for every graph with an attention sink. The reason given was "not measured". With #1867 the nightly now runs these serving-form fp8 cases, and they showed large default-dispatch misranks.

This PR measures that region and lets FROST lead where it wins:
- **`2 <= s_q <= 16`** at d128 and d256, and at d64 with a sink (gpt-oss, with or without SWA128).
- **d64 with a sink, any `s_q <= 16`:** from 32 KV units (`b * h_kv >= 32`), or for a single SWA query row (`s_q == 1` with a window) at any batch.
- Dense and paged GQA, non-THD, **E4M3 O** (the measured output), caches of at least 1k.

Everything outside that region keeps the previous behavior: d128 `s_q == 1`, THD, MHA, d64 without a sink, windows off the d64 sink graph, block-scaled O, other O dtypes, and caches below 1k.

## Measurements (B200, cuDNN 9.28.0.38; the nightly runs 9.28.0.40)

**Training grid**: 540 cases, each on the backend and FROST legs. It covers d64 sink with and without SWA128, d128 and d256; q 1/2/4/8/16; kv 4k/64k; b 1/32/128; dense and paged.

| family, layout, q | FROST / backend (geomean, range) | FROST wins |
|---|---|---|
| d128 dense, q 2–16 | 0.10 (0.03–0.31) | 72/72 |
| d128 paged, q 2–16 | 0.12 (0.04–0.37) | 72/72 |
| d256 dense, q 2–16 | 0.05 (0.01–0.25) | 48/48 |
| d64 sink, q 2–16 | 0.33 (0.12–1.01) | 44/48 (the rest b=1 parity) |
| d64 sink SWA128, q 2–16 | 0.36 (0.13–1.06) | 44/48 (the rest b=1 parity) |
| d64 sink SWA128, q 1 | 0.22 (0.06–0.70) | 12/12 |
| d64 sink full cache, q 1 | 0.41 (0.15–1.23) | 8/12 (losses: b=1 × 8 KV heads, 1.20–1.23) |
| d128 dense / paged, q 1 | 1.48 / 1.88 | 1/12 each → keeps the backend |

- On the d128/d256 `s_q == 1` cells the backend failed to build (NVRTC) in 24 of 48 cases. The default dispatch already falls through to FROST there.
- FROST declines fp8 paged d256 today, so leading on it changes nothing.
- **Paged d64 sink** (served since #1874; measured after rebasing, 120 cases): d64 sink full cache 0.32 geo for `s_q 2-16` (48/48 wins); d64 sink SWA128 0.26 for `s_q = 1` (12/12) and 0.42 for `s_q 2-16`. All 16 losses are b = 1. A full-cache single row loses 1.20-1.22, and paged SWA `s_q >= 2` loses 1.09-1.49. Those are the cases the 32-KV-unit bound returns to the backend.

**Hold-out**: 60 random cases, written and hashed before the rule existed (sha256 `3b1bd615…`). They cover random heads within the d64-sink, d128 and d256 families; q 1–16; kv log-uniform over 1k–128k; b 1–256; dense or paged, with mixed cache lengths when paged. Each case ran the backend, FROST, and the default dispatch with this change, and is scored as default time over the faster of the other two:

| | geomean regret | above 1.05 | worst |
|---|---|---|---|
| develop (backend leads) | 2.67 | 34 / 60 | 65× |
| first revision (measured `cudnn_auto`) | 0.995 | 0 / 60 | 1.02 |
| first revision, rebased on #1874 (measured `cudnn_auto`) | 0.997 | 0 / 60 | 1.03 |
| final rule (from the same measured legs) | 1.001 | 0 / 60 | 1.02 |

The final rule's row is computed offline: each hold-out case takes the leg the rule selects, using the backend and FROST times measured on the rebased tree. Develop on the rebased tree scores geomean 2.87, with 37 cases above 1.05.
