## Summary

`test/python/tiers/` has SMOKE lists for cc 10.7 and cc 10.0 only, so on a B300 (cc 10.3) `-m smoke` selects nothing and `conftest.py` prints the `[tiers] no SMOKE list for this GPU` line.

- `smoke_cc103.txt` lists the 252 cells of `smoke_cc100.txt` that run on cc 10.3. These are the same engine rows, with their sm100 bodies compiled for `sm_103a`. The header names the 24 cc 10.0 cells left out and why:
  - 9 cc 10.7 / SM120 kernels and bindings, which skip on cc 10.3 as they do on cc 10.0;
  - 5 native dense, prefill, sink and split binding cells, gated to SM100;
  - 9 gated attention block cells whose dense and FP8-projection forms are admitted on (10, 0) only;
  - 1 FP8 backward graph of `test_mhas_v2` at D = 144, which no engine serves on cc 10.3 with cuDNN 9.27.
- `smoke_cc103_code_paths.tsv` copies the cc 10.0 rows for the listed ids.
- `tiers/README.md` names the list and its count.

No test file changes. `test_tiers.py` picks up the new list on its own.

## Why

A B300 run gets the same one-cell-per-code-path tier as B200 and Rubin.

## Related issues

#2105 admits the gated block's dense forms and its FP8-projection mode on (10, 3). Once it lands, the 9 gated-block cells can join this list in a follow-up; their files pass on a B300 with #2105's change.

## API and compatibility impact

None. Test tiers only; CI keeps `-m L0`.

## Testing

B300 (cc 10.3), develop `64ed3dfe` with its own extension, torch 2.14.1+cu130, cuDNN 9.27.0, CuTe DSL 4.8.1, `CUDNN_FRONTEND_ENABLE_FROST_ENGINES=1`, from `test/python`:

| Command | Result |
|---|---|
| develop, the cc 10.0 list applied on cc 10.3: `CUDNN_TEST_TIER_ARCH=cc100 python -m pytest -o addopts= -m smoke sdpa/frost gated_attention_block/cutedsl sdpa/graph/test_mhas_v2.py` | 252 passed, 25 skipped |
| this PR, the list picked from the device: `python -m pytest --collect-only -o addopts= -m smoke sdpa/frost gated_attention_block/cutedsl sdpa/graph/test_mhas_v2.py` | 252 collected |
| this PR: `python -m pytest test_tiers.py` | 14 passed |

The listed ids are exactly the 252 that passed in the first row.
