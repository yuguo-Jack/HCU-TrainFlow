# Fix channels-last norm cache reuse for strided operands

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2257) · state: open · merged: False

## Original PR description

## Problem

The channels-last GroupNorm and InstanceNorm forward and backward kernels cache a CuTe function without accounting for the layout specialization of the affine and statistics vectors. `dyn()` specializes unit strides but keeps non-unit strides dynamic.

Calling the same shape first with contiguous scale/bias and then with stride-2 views can produce incorrect output; reversing the order can also produce an illegal memory access. Backward has the same issue for scale, mean, and inverse standard deviation.

## Change

Include the unit-stride classification of each affected vector in the four channels-last kernel cache keys. Different non-unit strides still share the dynamic signature. No operand copy or execution-time allocation is added.

This covers the channels-last kernels independently of the rowwise kernels in #2256.

## Validation

- B300 (SM103) and GH200 (SM90): all 32 new cases passed against PyTorch after rebasing onto the current develop head, including individual scale/bias and mean/rstd stride changes in both call orders, non-unit stride reuse, and changed-input CUDA Graph replay using caller-provided workspace.
- Before the fix, GroupNorm and InstanceNorm forward/backward probes failed on B300 for both call orders; GH200 independently reproduced four individual affine/statistics cases.
- B300: all 32 cases also passed with CuTe DSL 4.8.0/cu12, 4.8.0/cu13, 4.8.1/cu12, and 4.8.1/cu13. The first 4.8.1/cu12 attempt yielded when another process entered the GPU; a fresh run on a different admitted GPU passed.
- Existing channels-last layout/fallback/backward L0 selection: 3 passed, 1 deselected on each GPU.
- Black 26.3.1 using the repository's `--line-length 160 --fast` options and `git diff --check` passed.
