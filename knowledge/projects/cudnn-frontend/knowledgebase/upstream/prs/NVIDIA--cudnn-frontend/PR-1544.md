# sdpa(fwd sm107): keep a fully-masked leading KV tile out of the running max on the nine d128 / d192x128 / d512 prefill kernels

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1544) · state: closed · merged: True

## Original PR description

## The defect

Nine Rubin (cc 10.7) prefill kernels -- `sm107/prefill_d128_{f16,fp8,mxfp8}.py`, `prefill_d192_d128_{f16,fp8,mxfp8}.py`, `prefill_d512_{f16,fp8,mxfp8}.py` -- mask scores with the finite sentinel (-3.4028235e38) and started their online-softmax running max at it.  A row whose FIRST KV tile is fully masked while a LATER tile holds its keys (a sliding-window band or a bottom-right diagonal clearing a whole 128-key tile) took that sentinel as its running max:

- on the f16 / bf16 kernels' scaled chain and on the per-tensor FP8 kernels under unit descales, `sentinel * scale_log2` overflows to -inf at `attn_scale * log2 e > 1` and the exp2 shift reads `-inf - (-inf) = NaN` -- NaN P into BMM2, NaN O (and a NaN denominator) on every such row; the d512 half kernel's correction hand-off cells carried a strict xfail for exactly this geometry (3064 NaN rows, `LSE = log(1e-30)`);
- on the MXFP8 kernels (which clamp the scaled tile max to the sentinel), under the pre-folded scale, and under the quantizer's per-tensor descales, the shift read 0 and the dead tile published P = 1 per masked column -- mass that only `alpha = 0` at the next live tile wiped, a multiply by zero of the tile's `P . V`.

The whole-row `_kv_empty` / `_row_empty` / `row_dead` selects never applied: these rows have keys.  The d256 trio took the same fix in #1488.  Not affected: the d512 2x2 twin and the SM100 f16 / bf16 bodies (d128, d192x128, d256, d512), the SM100 d256 per-tensor FP8 body and the SM100 d256 / d512 MXFP8 bodies, which mask with true -inf and shift through `row_max_for_exp2`.  Still carrying the finite-sentinel inlined chain, out of this PR's scope (a follow-up PR with the same one-call replacement): the SM100 d128 / d192x128 MXFP8 bodies (`sm100/prefill_d128_mxfp8.py`, `sm100/prefill_d192_d128_mxfp8.py` -- they clamp the scaled tile max to the sentinel, so only the P = 1 form) and the SM100 d128 / d192x128 per-tensor FP8 bodies (`sm100/prefill_d128_fp8.py`, `sm100/prefill_d192_d128_fp8.py` -- unclamped, both forms).  The widened MXFP8 leading-tile cell runs on those SM100 bodies too and is green there only because its all-ones draw makes the P = 1 form invisible; the follow-up carries a cell whose values expose it.

## The fix

Each kernel's running-max step (one site per kernel; the three d512 role-split bodies also shift by the returned value at their 2 / 1 / 5 shift sites) becomes the one shared call

```python
total_max, alpha, new_total_max = running_max_step_finite_sentinel(
    <raw tile max>, current_max, total_max, NEG_INF, RESCALE_THRESHOLD, masked=CFG.MASK_FLAGS != MASK_NONE
)
```

`_common_blackwell.running_max_step_finite_sentinel` (landed with #1488): a tile that is fully masked before the row's first live key is `tile_dead` and is SELECTED out of the running state -- `total_max` stays at the sentinel (so `is_first` starts the online softmax at the first live tile), `alpha = exp2(sentinel - sentinel) = 1` exactly (the accumulator and the row-sum are still their zero-trip state) and the exp2 shift is 0, so every column of the tile lands at `exp2(sentinel * scale) = +0` on every arm (f32, f16x2, the fused shift + convert).  Dead tiles after a live one were already exact; a row with no live key at all still ends at `(sentinel, 0)` for the epilogue's geometry select.  The MXFP8 kernels keep their clamp (the select keys on the RAW tile max).

**No barrier change, no SMEM / TMEM change:** no mbarrier added, no init count or arrive site touched, no config field; the diff is the softmax step, its comments and the import.  The predicate folds out of the `MASK_NONE` build: the dense cubin of 8 of the 9 kernels is **byte-identical** (sm_107a trace-compile md5 before and after, per kernel in the commit messages); the d512 half kernel's dense cubin differs only by ptxas's uniform-register assignment in the MMA warp's descriptor arithmetic (40 of 5393 SASS lines, UR renames and reordered `UIADD3.64` / `UTCHMMA` operands, zero opcode-histogram change, no softmax instruction).  The masked builds gain one compare and a few selects per lane per KV tile.

Rule S2: no `Capabilities` / `EngineSpec` change -- the support-matrix tracker is untouched.
