## Summary

#1608 made dense, unsplit d256 MXFP8 SDPA legs run the 2-CTA pair (`cta_mma == 2`) on cc 10.7 (`config_sm100.d256_mxfp8_pair_leg`; O bitwise identical to one CTA). The gated attention block's MXFP8 path uses that SDPA, but `test_mxfp8_block_second_execute_agrees_bitwise_and_runs_natural_cga1` still asserted `cta_mma == 1`:

```
FAILED test/python/gated_attention_block/cutedsl/test_block_mxfp8.py::test_mxfp8_block_second_execute_agrees_bitwise_and_runs_natural_cga1 - assert (0 == 0 and 2 == 1)
```

The SDPA pick is correct; only the expectation is stale. This PR:
- pins `cta_mma == 2` for this dense leg;
- renames the test to `..._runs_natural_pair`;
- updates the three block docstrings that still said cga1.

The failing assertion was the test's first check, so the second-execute bitwise comparison never ran on SM107. CI on this PR runs it.

## Testing

The two other failures on that lane (`test_block_serving_extend.py::test_write_through_matches_the_slab_and_the_oracle_on_every_layout_and_page[{dense,packed}-bf16-hnd-16]`) are not touched here. Each has a single element of K that differs by 0.03125 from the oracle, while the pool still matches the slab bitwise. That is reported on #1606.
