# frost(sdpa): declare the fused epilogue gate's slab-column layout at batch 1 x one token again (canonicalize first)

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2070) · state: closed · merged: True

## Original PR description

## What

`config_sm107.epilogue_gate_layout_declarable` -- the standalone adapter's half of the fused epilogue gate's layout rule -- now answers with the native dense layout contract, `config_sm100.dense_bind_strides(...) is not None`: the singleton axes canonicalized first, then BSHD-compact or an aligned covering B/H/S permutation.  That is the same call the graph half (`graph_analyzer.gate_layout_ok`) and the binder (`prepared._dense_role_layout`) already make, so the three cannot drift again.  One line of logic; the rest of the diff is the docstring, the tests and one sentence in the support matrix tracker.

## Root cause

#2038 ("Bind dense attention forward layouts without staging copies") rewrote `config_sm100.bshd_zero_copy_stride` to canonicalize the singleton axes and to return `None` when the canonical layout is compact, and moved the graph half of the gate rule to `dense_bind_strides`.  The adapter half kept its old two-call form, `bshd_compact(shape, RAW strides) or bshd_zero_copy_stride(...) is not None`.  A gate sliced out of a fused projection slab at batch 1 x one query token keeps the slab's token pitch on both singleton axes -- BHSD strides `(13312, 256, 13312, 1)` for 24 heads, `(17408, 256, 17408, 1)` for 32 -- so the raw compactness test failed, the canonicalizing helper returned `None` *because* the layout is compact once canonicalized, and the engine row admitted a graph that `SdpaFwdDslSm100.check_support` then refused with `GATE layout is not TMA-expressible ... got BHSD strides (13312, 256, 13312, 1)`.

On cc 10.7 every gated-attention-block DECODE declaration at batch 1 x one token with the gate fused into the split combine failed this way at `develop` (since 76b49a6b0; green at 835f459ab): `test_block_serving_decode.py::test_decode_split_ladder_recombines_on_the_decode_grid[b1-sq1-split4 | split8 | split16]`, `::test_the_write_through_in_the_norm_rope_launch_drops_the_cache_write_launch_seven_to_six`, `test_block_serving_pdl.py::test_detector_the_combine_reads_the_partials_only_after_its_dependent_wait`, `::test_detector_turns_red_when_the_combine_launches_with_the_attribute_but_does_not_wait`, and #2068's new `test_fp8_proj_bf16_attention_launch_census_is_the_bf16_chain_plus_the_quantize_launch` (the same geometry).  cc 10.0 is unaffected (the gate is its own launch there).

No layout #2038 declines is re-admitted: an unaligned or overlapping head pitch and a strided head dim stay refused on both halves (the kept `test_gate_check_support_declines_typed` ValueError and the new decline cells).  No `Capabilities` field changes; the support matrix tracker gains one sentence under "Native dense forward layout contract".
