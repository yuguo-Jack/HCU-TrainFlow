# frost(sdpa): the fused store's rounding vocabulary lives in the DSL-free rules module (restores the declaration import boundary)

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2071) · state: closed · merged: True

## Original PR description

## What

The fused gated e4m3 store's rounding vocabulary (`COMBINE_OUT_ROUNDING_SINGLE` / `COMBINE_OUT_ROUNDING_STAGED` / `COMBINE_OUT_ROUNDINGS`, added by #2066) moves from `python/cudnn/sdpa/fwd/heuristics.py` to the DSL-free `python/cudnn/sdpa/fwd/sparse_tile_rules.py`, where the sparse decode's `tile_form` vocabulary already lives for the same reason.  `heuristics.py` re-exports the three names unchanged through its existing re-export block, so `heuristics.COMBINE_OUT_ROUNDINGS` keeps working for every caller (the suites and the support-matrix prose included).  The sparse adapter (`sparse_gqa_sm107.py`) imports them beside `SPARSE_LEAN_TILE_EXPLICIT_CCS` -- no module-level `heuristics` import, as before #2066; the kernel module (`sm100/split_combine.py`) keeps its pre-existing `DECODE_COMBINE_MAX_LEAN_BLOCKS` import and takes the three names from their home.  The same three string constants: no behaviour changes, no kernel change.

## Why

Two cells of `test/python/core/test_import_boundaries.py` have been red on `develop` since #2066 merged:

- `test_indexer_decode_declaration_under_fuse_prepare_does_not_import_the_prepare_kernel` -- `assert "cudnn.frost.tile_dsl" not in modules`
- `test_indexer_decode_declaration_declines_old_dsl_at_check_support_not_at_construction`

#2066 imported the vocabulary at module level from `heuristics.py`, which imports `cudnn.frost.tile_dsl.constants` at module level.  Constructing a gated-block indexer DECODE declaration imports the sparse adapter, so the declaration's construction now pulled in the `cudnn.frost.tile_dsl` package before the stage's `check_support` gated the DSL floor -- the lazy-import boundary of `python/cudnn/AGENTS.md` (Rule 7: a declaration constructs on any DSL and declines by name at `check_support`; the kernel module is imported only after the gate).  The outside-diff review note on #2066 ("move the rounding vocabulary to the DSL-free module") was right in effect: the import did reach the declaration path.

## Tests

- **Import boundary** (the regression): the two cells above RED on `develop` -> GREEN with this change (fresh interpreters per probe); `core/test_import_boundaries.py` whole: 33 passed.
- **Gate module host tier**: `sdpa/frost/test_split_combine_gate_e4m3.py` gains a one-line pin in the existing `compile_ptr` cell that the heuristics re-export IS the rules module's object; host tier 15 passed / 67 skipped (an A100 host; the cc 10.x rows skip).
- **cc 10.7 part (functional, 204-SM class)**: `test_split_combine_gate_e4m3.py` whole: 82 passed (0 failed, 0 skipped); `test_sdpa_fwd_sparse_lean_sm107.py` whole (the adapter's lean route and the host rows that read the vocabulary): 135 passed (0 failed); `core/test_import_boundaries.py` whole: 33 passed.  The moved constants change no byte of behaviour: the same counts the #2066 validation recorded on the same part class (82 / 135).
- `black -l 160`, `py_compile` clean; the `SUPPORT_MATRIX_TRACKER.md` is untouched (no `Capabilities` field or `EngineSpec` changes -- Rule S2 exempt; its `heuristics.COMBINE_OUT_ROUNDINGS` reference stays valid through the re-export).
