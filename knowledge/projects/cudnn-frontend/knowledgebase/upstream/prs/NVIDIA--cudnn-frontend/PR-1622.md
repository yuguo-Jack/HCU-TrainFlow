One runtime-contract gap remains: consuming a stride that the existing packed-blob validator does not constrain introduces silent wrong results for a previously accepted binding. **[P1 · blocks approval] Validate the expert-plane layout before trusting the runtime SF stride** ([source](https://github.com/NVIDIA/cudnn-frontend/blob/207839bdbc7a9631b833176e8fdfead956ba8a32/python/cudnn/gemm/frost/sm100/kernel_templates/sm100_moe_grouped_block_scale_matmul_fwd.py#L2078))

The old SF contract consumes a packed F8_128x4 byte blob, and `_sf_blob_reject` still checks only its dense span and total capacity. It does not establish that the runtime expert-labelled axis describes separate packed expert planes. For E=3, N=K=256, NVFP4, take the existing correct 12,288-byte SFB payload and rewrap the same bytes as `sfb.reshape(-1).view(16, 3, 256).transpose(0, 1)`. This is still a dense rank-3 blob with shape (3,16,256), passes validation, and worked before this PR. Its batch stride is 256 bytes, however, so the new descriptor reads expert 1 at byte 256 instead of 4096 and silently corrupts outputs. I reproduced this through public `graph.execute()` and the direct compiled API, with both SWAP_AB orientations. Please either preserve/normalize the legacy packed-blob interpretation where applicable, or explicitly validate the new per-expert plane contract before using this stride (including plane size, alignment and accessible extent). Apply the same contract to the swap-AB and SM120 changes. Add the padded-positive and incompatible-layout cases as regressions. This blocks approval because an accepted public binding now returns wrong results without an error.

Evidence: SM100 A/B at identical input bytes: baseline 411012aa5 passes all four direct/public x normal/swap-AB cases; 207839bdb fails all four with 24,240/44,288 mismatched output elements (54.7%), max absolute difference 1584. The extra allocation used by the probe bounds all descriptor reads within probe-owned storage. In contrast, supported outermost-expert storage with 512/1536 extra bytes per expert passes the intended fix. Attribution: introduced by this PR: runtime stride becomes semantically significant without updating the packed-blob admission contract

Validation: Source-pinned SM100: 38 existing relevant tests passed, 2 architecture-specific tests skipped; this includes swap-AB coverage and SM120 render smoke checks. Six focused NVFP4/MXFP4/MXFP8 x normal/swap-AB cases passed: same compiled plan rebound across +512-byte, +1536-byte and compact expert storage, exact output equality, and CUDA Graph replay with explicit capture-stream binding. The intended padded-storage reproducer fails on the old templates in both NVFP4 orientations (54.8% of output elements differ) and passes on this head. The reported packed-blob compatibility probe passes on the baseline and fails on this head in all four direct/public API x normal/swap-AB cases.

Limitations: No native SM120 execution was available; render checks do not establish native correctness there. Deferring automatic CI while the reproduced silent-correctness issue remains unresolved.

I am withholding approval for the high-risk P1 findings above and leaving a COMMENT. Please address them before merging.
