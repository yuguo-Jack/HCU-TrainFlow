## Affected area

CI or test infrastructure; FROST kernel naming.

## Summary

- Gate nine norm test modules with the existing DSL capability check before kernel imports, per Python Rule 7.
- Update the QK norm/RoPE cache-key assertion for `use_pdl` and cover both values.
- Place grouped backward kernel naming calls next to their definitions and use the standard `cudnn` prefix.
- Pin the native-d64 SM107 SDPA plan and expect `prefill_d128_f16`.
- Select the existing FP64 oracle option for dense and packed serving-pool tests.

## Why

OSS/FROST tests fail during norm collection on DSL builds without the required APIs, and several assertions lag the implementation. The serving-pool reference also crosses a BF16 rounding boundary during FP32 projection: on the saved failing inputs, its normalized value is `-2.28125`, while the kernel and FP64 oracle both give `-2.3125`.

## Related issues

OSS and FROST CI failures; no linked GitHub issue.

## API and compatibility impact

No public API changes. Norm tests skip unsupported DSL builds. The pool oracle retains intermediate dtype casts and all comparison tolerances.
