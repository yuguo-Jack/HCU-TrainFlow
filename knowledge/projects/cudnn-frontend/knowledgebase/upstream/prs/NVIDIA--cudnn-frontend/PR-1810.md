# Fix final P1 ownership and masked probability rounding in D192 FP8 attention

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1810) · state: closed · merged: True

## Original PR description

The SM100 D192/V128 FP8 kernel can overwrite the preceding P1 probability tile before its PV MMA consumes it. Ordinary iterations wait for a real S0 lookahead completion, which also orders that consumption. The final iteration substitutes a softmax-thread notification and loses the MMA dependency. Under sufficient scheduling skew, this can also lap the second P-chunk readiness phase and prevent forward progress.

For multiple KV tiles, release the final P1 slot from the correction warpgroup after its existing wait for the preceding PV1 completion. Empty and single-KV tiles retain their original notification. Arrival counts and phase tracking remain unchanged; this repair adds no barrier or runtime API. Six correctness cases delay the previous P1 consumer, covering one/two/four KV tiles, dense/causal masks, O/LSE/amax, and equivalent negative/positive scales. The test-only delay compiles out of normal builds.

Those tests also exposed an independent, pre-existing masked E4M3 arithmetic error. Degree-2 exp2 emulation can move an unnormalized probability across an FP8 midpoint, producing a large output error for rows with few valid keys. Extend the existing masked native-exp2 path from E5M2 to E4M3. A fixed-input two-key regression places P=0.78075 below the 0.78125 midpoint, independently of CUDA RNG layout. The unmasked instruction mix is unchanged; masked paths use native exp2, so the change has an instruction-cost tradeoff. No tolerance is relaxed.

Validation:
- The updated kernel passes 36 focused D192 tests on SM100. Existing ownership qualification also covered 99 prepared/native/staged/split lifecycle cases, pointer/scale rebinding and CUDA Graph replay.
- The fixed-input regression fails on all four matched SM100 GPUs with the old arithmetic (max O error 0.14051 against 0.04), and passes on all four with the fix. The diagnostic retains the baseline failures rather than reporting its overall pipeline green.
- The original failed CI input is bitwise identical across old/new/skewed ownership schedules. With the arithmetic fix, its maximum O error falls from 0.05892 to 0.00223; O/LSE/amax pass the existing checks.
- The unfixed ownership path stalls under the same injected scheduling skew; the repaired path completes. Tests contain no timing thresholds or heuristic rankings. Scoped pre-commit hooks pass.

Fresh official CI is required for c186f9704. The previous head passed SM103/SM107/SM120 qualification but had the now-addressed SM100 numerical failure. The separate timeout reported on #1806 remains under investigation; this PR does not claim to attribute that original event.
