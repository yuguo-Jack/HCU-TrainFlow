## Summary

FlashInfer's cuDNN backend (`flashinfer/cudnn/{prefill,decode,utils}.py`) reads a handful of frontend facts before it routes work to this package: the native SDPA binder's `supports_*` flags (`cudnn._pybind_module._SdpaThdBinder.supports_stats_stride_override` / `.supports_nonpaged_packed_split`), `graph.selected_engine` and its `.name` against the FROST engine names, `graph.backend_plan_entries()`, the CuTe DSL gate in `cudnn.frost.buffers` (`cutedsl_state` / `cutedsl_too_old` / `CUTEDSL_MIN_VERSION`) and `cudnn.datatypes._torch_to_cudnn_data_type`. A private name consumed outside this package is still a caller boundary (`python/cudnn/AGENTS.md` Rule 9), so this PR keeps every one of them as spelled and gives each a public twin:

| what the caller asks | kept as spelled | public spelling (new) |
|---|---|---|
| does the native SDPA binder honor a packed-split / stride contract? | `_SdpaThdBinder.supports_<cap>` (static `True` properties) | `cudnn.sdpa_capabilities() -> frozenset[str]`: every `supports_<cap>` flag of the build, as `<cap>`; append-only; empty on a build without the binder |
| can the FROST engines run on this install, for this GPU? | `cudnn.frost.buffers.cutedsl_state()` / `cutedsl_too_old()` / `CUTEDSL_MIN_VERSION` (the version half) | `cudnn.frost.cutedsl_runtime_available(device_cc=None) -> bool`: the engines' own gate as a probe -- the version half from package metadata, plus, given a `(major, minor)` cc, the target half (`cutedsl_arch_requirement_error`) |
| the cuDNN dtype of a torch dtype | `cudnn.datatypes._torch_to_cudnn_data_type` | `cudnn.datatypes.torch_to_cudnn_data_type` (the private name is an alias of it) |
| which engine serves the selected plan; is the backend still reachable? | `graph.selected_engine`, `graph.backend_plan_entries()` | unchanged; documented as public API, with the engine names `sdpa_fwd_prefill_sm100` / `_sm107` / `_sm120` as stable identifiers (manifest names and slots are append-only) |
| the caller hints | `cudnn.pygraph(is_override_shape_enabled=, is_cuda_graph_replay_expected=)`, `cudnn.graph(**graph_kwargs)` | unchanged; documented on the class |

Also: a "Consumed by FlashInfer" section in `docs/utilities/python_graph_and_execution_backends.md`; the API index gains the module `cudnn.frost` and the rows `cudnn.frost.cutedsl_runtime_available` / `cudnn.sdpa_capabilities`; Rule 9 in `python/cudnn/AGENTS.md` names the pin test.

## Why

**The runtime probe is arch-aware on purpose.** The DSL floor every FROST row declines under is 4.7.0 everywhere, but the cc 10.7 rows additionally need a DSL whose `Arch` knows `sm_107a` -- the public 4.8.0 wheel is the first -- and that gate lives in `cutedsl_arch_requirement_error`, not in the version check. A device-blind probe (the formula a caller can spell today from `cutedsl_state` / `cutedsl_too_old`) therefore reads True on a cc 10.7 part with a 4.7.x DSL while every FROST row declines, and a performance-driven routing decision made on it would send the graph to the backend engine. `cutedsl_runtime_available(device_cc=cc)` closes that blind spot: `device_cc=None` keeps the version-only answer, a cc applies the target half; a cc that is not a pair of integers is a `TypeError` (a `10.5` must not read as cc 10). The DSL is imported only for a cc 10.7 part.

**The names are pinned where a rename would be noticed.** `test/python/sdpa/frost/test_flashinfer_consumed_surface.py` (host-only, L0, no DSL needed) asserts each spelling above still resolves with its signature -- the binder flags as static `True` properties on the class, `sdpa_capabilities()` as their public spelling (every member with a `supports_` twin), `selected_engine` a property and `backend_plan_entries(self)` a query, the two `pygraph` hints with their parameter kinds and defaults plus `**kwargs` on `cudnn.graph` (the probe FlashInfer runs for the replay hint), the three engine names at their manifest slots, the DSL gate names and `CUTEDSL_MIN_VERSION == (4, 7, 0)`, the dtype mapping as one function object behind both spellings, a fresh-interpreter probe that `import cudnn` + the public probes pull neither torch nor the DSL, and the docs section naming every public spelling. The arch-aware cells pin the DSL state exactly where the engines read it: absent / 4.6.2 -> False everywhere; 4.7.1 and 4.7.0rc1 without `sm_107a` -> True blind and on cc 8.0 / 10.0, **False on cc 10.7**; 4.8.0 with `sm_107a` -> True on cc 10.7; an internal build without the target -> True blind, False on cc 10.7; a list spells the same part; the DSL is asked only for a cc 10.7 part. A rename of any consumed name now fails this repository's CI instead of silently degrading a downstream integration to its fallback path.
