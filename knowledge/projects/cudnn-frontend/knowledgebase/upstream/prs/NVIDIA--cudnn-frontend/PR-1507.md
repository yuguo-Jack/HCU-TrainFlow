## Affected area

FE OSS kernels or CuTeDSL

## Summary

Fix out-of-range indices from the varlen DSA indexer top-k kernel when a row is shorter than its
misalignment prologue: `prologue_elems` is clamped to the row length. Adds an L0 regression test.

## Why

`IndexerTopKKernelVarlen` splits each row into a scalar prologue up to the next 32-byte-aligned
address, a vectorized body and a tail. `prologue_elems` comes from the row address alone and is not
bounded by `length`. When a row starts misaligned (bf16 with `num_cols % 16 != 0`, fp32 with
`num_cols % 8 != 0`) and its `seq_len` is smaller than the prologue, the prologue reads columns past
`seq_len` and can select them, so the kernel returns indices >= seq_len (`remaining` also goes
negative). Downstream sparse attention then gathers KV entries outside the row's valid range.

Repro (B200):

```python
x = torch.randn(2, 17, device="cuda").bfloat16()
x[1, 3:] = 100.0
seq_lens = torch.tensor([17, 3], dtype=torch.int32, device="cuda")
r = DSA.indexer_top_k_wrapper(x, seq_lens, top_k=1, next_n=1, return_val=True, tie_break=1)
r["indices"][1, 0]  # 3 -- outside seq_len=3
```

Conditions: misaligned row start, `seq_len` < prologue elements, and `top_k < seq_len`. Clamping keeps
the existing split for every row at least as long as its prologue; a shorter row becomes all prologue
(empty body and tail), which is the correct scalar path. Same family as #410 (OOB lanes in varlen
indexer top-k).
