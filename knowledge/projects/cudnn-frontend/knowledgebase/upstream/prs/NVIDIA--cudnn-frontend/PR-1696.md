# Optimize THD work lookup for context-parallel attention

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1696) · state: open · merged: False

## Original PR description

**Merge hold: keep this PR unmerged for investigation of the reproduced small-batch device cost.** The many-sequence improvement does not cancel this regression.

Packed context-parallel attention can spend substantial time locating each THD work item: the forward kernel scans every sequence and repeats head/tile division at every visit. This change stops at the owning sequence and computes those coordinates once. When the first and last entries of the existing longest-first GPU remap have the same rounded tile count, it locates the owning sequence directly. This also supports unequal sequence lengths within one tile bucket.

The optimization reads current device metadata on every execution, preserving ragged layouts, empty sequences, scheduler order and attention arithmetic. Initial admission is limited to SM100-family D128 BF16, top-left causal THD, 128×128 tiles, two CTAs and SPLIT_KV=1. The same opt-in also reaches paged THD through the shared D128 body, including eligible SM107 paged plans. Work ownership is determined by packed Q tiles; Q and KV lengths need not match. Other helper consumers retain their existing decoder. No public API, engine capability or heuristic changes are introduced.

Validation on a production B200 (148 SMs), cuDNN 9.27, CuTeDSL 4.8 with the CUDA 13 compiler flavor, and a freshly built FE native binding:

- 75 tests passed, zero failures or skips: 36 new cases and 39 existing THD cases.
- New cases cover three MHA/GQA head configurations, packing on/off, all three schedulers, both packed-LSE layouts, changing lengths/remap/input values on one CUDA Graph, all-empty work followed by live work, untouched output tails, and independent CPU FP64 O/LSE references.
- One representative case is collected by default L0; the complete new matrix is selected with `-m 'L0 or L1'`.
- Repository format and SPDX hooks passed.
- Compute Sanitizer 13.2 memcheck: the representative L0 graph-replay case passed with zero errors using explicit CUDA API error reporting and memory instrumentation enabled. Default extended reporting initially counted a Torch random-input code-recompilation warning; that first run is not treated as a zero-error pass.

Follow-up paged coverage: all 42 tests in this file passed on B200 (36 existing plus 6 new paged combinations), with zero skips. The new BF16 top-left causal cases cover NHD/HND pools, GQA ratio 6 with partial PackGQA, unequal Q/KV lengths, separate changing K/V page tables, all three schedulers, both packed-LSE layouts, empty-to-live replay, tail canaries, and an independent CPU FP64 O/LSE reference. They assert both the paged route and the bounded decoder. The two default-L0 paged cases also passed Compute Sanitizer memcheck with zero errors, explicit CUDA API error reporting, and memory instrumentation enabled. This follow-up changes tests and scope comments only; it does not change runtime admission or attention arithmetic. The controlled B200 experiment below reproduces a small-batch device-latency increase. Correctness passes do not clear that performance hold.

Run the new coverage from `test/python`:


## Small-batch regression follow-up

A separate controlled experiment on one production B200 (148 SMs, default 1000 W, exclusive allocation) compares the retained original decoder with the bounded decoder inside current-head source. Both arms use BF16 top-left causal packed THD, Hq/Hkv=8/2, D128, 128x128 tiles, two CTAs, PackGQA, LPT and no split. The timed public FE graph includes forward, packed FP32 LSE and metadata helpers.

| Batch x sequence | Original decoder, eager GPU interval | Bounded decoder, eager GPU interval | Median paired change |
| --- | ---: | ---: | ---: |
| 1 x 2048 | 34.192 us | 34.616 us | **+1.25%** |
| 64 x 512 | 140.759 us | 69.780 us | -50.42% |

Each shape uses four fresh processes with reversed construction orders. Every process builds two independent original-decoder and two independent bounded-decoder CUDA functions, with both FE cache layers disabled. All arms share input/output/workspace addresses within that process. Eight balanced timing rounds per process retain A/A controls as well as A/B comparisons. All 864 complete CPU-FP64 O/LSE validation stages pass, including poisoned replay and changed input values.

The single-sequence eager interval increases in all four processes (1.216-1.253%); its independent-compilation A/A envelope is 0.147%. Graph replay also increases, with a +3.55% paired median and a wider 3.48% A/A envelope, so the stable eager result is the primary hold evidence. The many-sequence replay change is -49.62%. Host submission has no established repeatable regression, but remains inconclusive under the predeclared criterion rather than being certified unchanged. Workspace size is equal; shared-buffer process memory is stable.

Only the eight expected worker processes appear in GPU telemetry. All sampled measurement-window clocks are 1965 MHz without clock-event flags; clocks were unlocked and 1 Hz sampling cannot resolve every timing phase. This is a local decoder experiment, not a full-base integration comparison, an isolated-main-kernel attribution, a TE CP result or an FA4 comparison. Keep the PR open for human analysis of the small-batch cost.

These are local forward-plus-LSE measurements. This PR does not claim full context-parallel end-to-end improvement; TE forward integration, backward and communication measurements remain separate work.

### Follow-up regression result: hold retained

A private follow-up candidate on the current integration stack preserves the original B=1 decoder and applies the bounded lookup only to multi-batch inputs. It is **not published in this PR head**. The complete prospective study on an exclusive production B200 (148 SMs, default 1000 W; cuDNN 9.27, CUDA 13.2 and CuTeDSL 4.8 CUDA 13 flavor) uses BF16 causal THD, Hq8/Hkv2/D128, four fresh processes per shape, and independent AA/BB controls.

All **1,152 full O/LSE checks pass**, with no observed allocation growth during timing. B=1 passes all four bounded host/eager/replay metrics. The follow-up nevertheless has **small-batch device regressions**:

| Shape | Full-chain eager wall baseline / candidate | Paired change |
|---|---:|---:|
| B1/S2048 | 33.734 / 33.727 us | -0.003% |
| B2/S512 | 15.851 / 16.413 us | +3.492% |
| B5/S513 | 18.356 / 18.643 us | +1.534% |
| B64/S512 | 140.462 / 70.508 us | -49.800% |

The B2/B5 eager regressions have sufficiently precise AA/BB controls. Across all shapes and host submission, eager stream, eager wall and complete graph replay, **5 metrics pass, 5 remain inconclusive, and 6 trigger regression holds**. B64's observed gain does not clear the remaining control-precision gates or offset regressions elsewhere. These are FE component measurements, not TE/CP end-to-end results or benchmark-grid wins.

The private candidate is not promoted and the prepared full-CP comparison is not admitted. The completed experiment and all original holds are retained. A narrower lookup policy must receive independent correctness, sanitizer, excluded-shape and prospective host/device performance checks before reconsidering promotion. This PR remains on hold; no runtime source was changed by this update.
