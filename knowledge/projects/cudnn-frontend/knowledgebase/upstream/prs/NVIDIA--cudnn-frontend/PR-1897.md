## Affected area

## Summary

JAX is an optional dependency group (pyproject `jax`). Without it, collecting `gemm/` or the whole suite fails:

```
ERROR gemm/jax/test_gemm_amax_jax.py - ModuleNotFoundError: No module named 'jax.numpy'
... (one per gemm/jax module)
!!!!!!!!!!!!!!!!!!! Interrupted: 17 errors during collection !!!!!!!!!!!!!!!!!!!
```

The cause is the test directory itself. `test/python/gemm/jax` has no `__init__.py`. pytest's prepend import mode puts `test/python/gemm` on `sys.path` as soon as it collects a `gemm/test_*.py` file. From then on `import jax` resolves to that directory as a namespace package, so `pytest.importorskip("jax")` passes and the module fails at `import jax.numpy`. Collecting `gemm/jax` on its own skips correctly, because nothing has put `gemm/` on the path yet.

The root `conftest.py` now records JAX as absent (`sys.modules["jax"] = None`) when `importlib.util.find_spec("jax")` finds nothing, or only a namespace directory. It does this at conftest import, before any test path is added. As a result, every `importorskip("jax")` skips: both at module level in `gemm/jax` and inside the two `gemm/cutedsl/test_grouped_gemm_dglu_workspace.py` tests. The XLA target gate's `import jax` also sees no JAX. An installed JAX is a regular package with an origin and is left alone.

## Why

Without the fix, an environment set up with the torch group only cannot run `pytest -m L0` over the tree: the session stops at collection.
