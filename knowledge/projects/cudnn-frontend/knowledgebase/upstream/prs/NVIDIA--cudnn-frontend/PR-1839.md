# test(sdpa): refresh SM107 backward PTX records after shared protocol changes

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1839) · state: closed · merged: True

## Original PR description

The public CuTe DSL 4.8.0 CI lanes fail three SM107 D512 backward rendering checks because their committed hashes still describe the October 9 source. The dense CLC scheduler changed in #1547, and #1796 replaced the shared THD decoder and updated the probe metadata geometry.

Refresh those three records for the current implementation and document how to check helper/probe changes when maintaining PTX records. Compiler-version gating, hash comparisons and SASS assertions remain in place.

Validation with an isolated, complete public CuTe DSL 4.8.0 Python 3.12 package set:

- Historical source/probes generated all three old records twice in separate processes; current source/probes generated all three CI-observed hashes twice.
- Restoring only the historical kernel, scheduler, backward decoder and probe geometry in the current tree recovered all three old hashes. Raw PTX differences were inspected.
- On exact fix head `a00362e07db9`, the committed-record check, three hash comparisons and both existing SM107 D512 SASS checks passed: **6 passed, no skips or failures**.
- Changed-file hooks and `git diff --check` passed.

This updates test data and test-maintenance guidance only. The validation above is compiler coverage; it does not clear the separate staged-artifact timeout or SM103 D192 spill failures in the broader CI run.
