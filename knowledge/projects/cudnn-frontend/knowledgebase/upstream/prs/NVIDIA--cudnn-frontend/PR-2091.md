## Summary

**What.** The block-sparse (index-list) d256 core on cc 10.7 now serves its THD (packed sequences) and PAGED (page pools) arms **together on the bottom-right diagonal** -- the composition `thd=True` + `paged_kv=True` + `bottom_right=True`, the new `SparseCapabilities.thd_paged_kv` claim. Through the gated attention block this is the **packed block-sparse EXTEND form with caller lists**: a `thd=True` declaration with `kv_source="paged"` on a bottom-right `QsaSpec(index_source="caller")` geometry is **ONE execute for a mixed serving step** -- decode rows beside prefill chunks of any length, every sequence behind its cached prefix, in any sequence order -- with the caller's per-row lists, the sparse core unsplit, the LSE served and the gate in the core's epilogue. Functional claim only; no performance number in this PR.

**The composition.** No kernel body changes. The three `const_expr` arms exist and are validated alone; they compose because they touch disjoint facts of a work item: the THD fold changes who decodes the item (the unit id -> head, packed token, the sequence found over `cu_seqlens`), the PAGED fold changes the gather row coordinate only (the page from the block table's row of the sequence the THD decode found; the dense arm's packed row offset is unread), the BOTTOM_RIGHT fold changes the row's position and dead predicate (`pos = tok + (kv_len_b - q_len_b)` from the per-sequence KV length the setup launch stores). The barrier bundle, the SMEM / TMEM maps and every arrive count are the dense arm's; the barrier table of the composed rendering was rebuilt from the source (18 rows, every init count equal to the sum of its issuing lanes, the exit drains in count and order, the dead-CTA exit above every init) and needed no change. The kernel-file diff is docstring-only (the docstring-stripped AST equals `develop`'s): the THD x PAGED paragraph with the composed degenerate matrix and the barrier ledger under this rendering. A host trace-compile of the composed rendering (sm_107a, decoded with `cuobjdump` / `nvdisasm`; nothing dispatched) reads 96 registers / 8 bytes of stack / one STL-LDL pair at G 4 ungated -- identical to the existing THD rendering's -- 93 / 0 gated and 96 / 0 at G 12: the composition adds no spill and selects no fallback.

**The contract** (the docs paragraph "The packed block-sparse EXTEND form" and `ExtendEnvelope.requires`):

- Declaration: `thd=True`, `num_sequences=B_max`, `max_seq_len`, `cu_seqlens` as the stack hands the Q lengths (either form), `kv_source="paged"`, `paged_kv_page_size=P` (16 / 32 / 64 / 128), the pools and a CONTIGUOUS `[B_max, max_pages]` int32 `sample_block_table` -- one row per sequence of the packing, never Q's batch extent of 1 --, bf16 / f16 activations, `save_for_backward=False`, `return_lse` served (`[1, H_q, T]` fp32, head-major packed), `fuse_gate` served (the core's epilogue), `decode_split_kv=None` (the packed form's claim-counter scheduler has no split axis), `sparse_tile_form` `"auto"` / `"tcgen05"`, `use_pdl` None / False.
- `token_capacity`: optional. `None` is the tight contract (the lengths sum to `T`); an int equal to the samples' `T` is the BOUNDED form, the recommended serving contract -- a step hands lengths summing to `T_live <= T`, the CAPACITY launch runs every stage over the `T` rows with the pad rows' slot `-1` writing nothing and their `out` rows exactly 0 on a once-zeroed workspace; `execute(num_tokens_live=)` where every dense projection resolves a JIT tile.
- Execute: `seq_lens` (`[B_max]` lengths or `[B_max + 1]` prefix sums -- the Q side), `kv_lens` (`[B_max]`: each sequence's LOGICAL KV length INCLUDING this step's tokens; `0` = a dead entry whose rows, if any, are `out = 0` / `LSE = -inf`; a sequence shorter than its chunk leaves its negative-position rows dead), `block_table` exactly the declared table, the pools, `slot_mapping`, `block_ids` `[T, top_k]` with sequence-relative ids (`block_lens` optional). Row `j` of sequence `b` sits at position `kv_lens[b] - q_len_b + j` and sees its own listed blocks plus the open tail. Device-value contract (reported, never raised): `kv_lens[b]` in `{0}` or `[q_len_b, max_pages x P]`. Any sequence order.
- Capture: a CUDA-graph capture takes the block after ONE eager warm-up on the capture stream; the replay serves new lengths / tables / lists / slots / pools through the captured tensors.
- Typed declines, each raised with exactly the text of its `extend.declines` row: `thd_paged_select_form`, `thd_paged_split`, `thd_paged_lean`, `thd_paged_shared_list`, `thd_paged_pdl`, `thd_paged_fuse_prepare`, `thd_paged_e4m3_pool`, `thd_paged_indexer` (the in-block indexer on the packed form is a follow-up: hand the selection in under caller lists, or run the dense extend step per chunk-length group). The serving table's `sparse` row stays reachable through a sparse-adapter record without the composition claim.
- The envelope: `extend.sparse_core`, `extend.index_sources == ("caller",)`, `extend.index_list_forms == ("per_row",)`, `extend.sparse_tiles == ("sparse_d256_f16",)`, `extend.writes_lse`, `extend.pdl_stages == ()` -- the appended tail of `ExtendEnvelope` (a dense geometry reads the defaults) -- and `forms == ("extend", "decode")` on a bottom-right `QsaSpec` geometry.

**Parity class vs the two-run form.** The step computes the same function as a dense `[B_dec, S_q]` decode block plus one dense `[1, T]` paged `QsaSpec` block per chunk over the same pools: per row BITWISE where that control runs the sparse core unsplit (`decode_split_kv == 1`, read back from the control) and its slab GEMM takes the same projection route (both past the small-M bound of 128 rows); within the sparse modules' bounds otherwise (`cos(out) > 0.999`, the gated O inside the bf16 / f16 OUTPUT bound, the LSE within `atol 2e-2`) -- the class is asserted from the control's resolution, never discovered from a measurement.

**The adapter (`sparse_gqa_sm107.py`).** `SparseCapabilities.thd_paged_kv` (appended last, the conjunction of the three arms); `check_support` admits the composition with `seq_kv_lens` as the `[n_seq]` logical lengths (a prefix-form KV length, the top-left composition, the split, the shared list, PDL and the lean tile decline by name), and resolves the SEQUENCE count before the paged checks, so a THD declaration's block table is checked against the number of sequences and the metadata sized by it (before this the paged checks read Q's batch extent of 1: a `[1, max_pages]` table would have passed with every sequence reading row 0). `config_sm107.py`: the two pair predicates admit exactly the triple; THD x PAGED on the top-left diagonal and BOTTOM_RIGHT under THD on the dense packed form stay refused with their texts.

**The block (`api.py`).** The serving table's `sparse` row is record-driven; the packed sparse stage binds two length descriptors and the table at `num_sequences` rows; the declaration resolves the tcgen05 body at split 1; the `thd_paged_*` rows are one spelling for the constructor and the envelope (`_qsa_thd_paged_decline_texts`); `ExtendEnvelope` gains the append-only tail `sparse_core` / `index_sources` / `index_list_forms` / `sparse_tiles`; `_SPARSE_EXTEND_REQUIRES` spells the form.

**The EXTEND verdict folds the packed form's geometry declines (fixed in `404b8d95f`, the review's finding).** For a `QsaSpec` geometry the envelope's `extend.served` was decided by the serving table's rows alone, so a geometry whose packed declaration the constructor refuses by the geometry itself -- `thd_paged_shared_list` (`index_list_form="shared"`) or `thd_paged_indexer` (`index_source="indexer"`) -- read `served=True` with `"extend"` in `forms`. The two rows are now ONE predicate for the constructor and the envelope (`_qsa_thd_paged_geometry_decline`, the shared list first as the constructor orders them), met after the record's THD row and before the table as the constructor meets it: `extend.served` / `reason` / `forms` / `sparse_tiles` are the declaration's verdict for every `QsaSpec` geometry on every part reading (on cc 10.0 the part row speaks first, unchanged); every decline text kept, the geometry's DECODE record untouched, a dense geometry as before. The new host cell `test_packed_sparse_extend_verdict_equals_the_declaration_per_geometry` (bf16 / f16) declares seven geometries (caller lists with and without the fifth band, the shared list, the indexer, both) and asserts the verdict EQUALS the declaration's outcome: served iff it constructs, else `extend.reason` == the `NotImplementedError` raised == the `thd_paged_*` row.

## Why

A serving step with decode rows AND prefill chunks under caller lists was TWO plans per layer (the decode step and the extend step, back to back on one stream) and, for ragged chunks, several extend executes grouped by chunk length -- the interim contract the docs stated. With the composition a serving stack issues ONE execute per layer for the whole packing: per layer the packed chain is the dense chain's five launches plus the THD setup launch, where the two-run form is two blocks' chains (plus a split combine where the decode block splits); the launch census is pinned by kernel name. The served matrix therefore moves here, in one commit: the `SparseCapabilities` claim, the config predicates, the block's serving table, the docs paragraph, the tracker rows.
