## Affected area

FE OSS kernels / CuTeDSL: the SM100-family BF16 DSA indexer and dense score-recompute shared mainloop.

## Summary

Add a two-stage `PipelineAsync` for `sPerHead`. All 32 load-warp lanes publish W/LSE after their stores; all 128 epilogue lanes wait before reading and release the slot after consumption. The producer acquires before reusing a slot and drains at exit.

Add six public-wrapper regression cases covering BF16/FP32 weights, partial tiles, persistent reuse, wholly empty causal tiles, a nondefault stream, repeated calls and changed weights. The 64-head causal case exercises a tile with no K blocks, rather than only empty rows within a nonempty tile.

## Why

Rotating shared storage with `tile_count % 2` does not publish ordinary W/LSE stores to the other warps or prevent reuse before all readers finish. Q/K tensor-core completion does not establish that handoff for every load lane. Numerical checks can pass with this race; racecheck is the regression detector.

## Related issues

FP32 weights and dtype-aware compile keys are already supported by #1311. This PR adds only the publication fix.

## API and compatibility impact

No public API, supported dtype, numerical formula or dependency-floor change. `PipelineAsync` is available at the declared CuTeDSL 4.8.0 floor. The separate MXFP8/MXFP4 mainloops are outside this qualification. These are kernel/API correctness results; no performance claim is made.

## Reproduction

Use Linux with an SM100-family GPU, a CUDA 13 toolkit and compatible driver, cuDNN 9 headers/libraries, and a C++17 compiler. Put `nvcc` and `compute-sanitizer` on `PATH`. Set `CUDNN_PATH` and `CUDAToolkit_ROOT` if needed, as in [Building from Source](https://github.com/NVIDIA/cudnn-frontend#building-from-source).

With `uv` installed:


Run both sections from the repository root. The editable install picks up the kernel change without reinstalling. Read both pytest's summary and the sanitizer summary; zero hazards alone is not a numerical pass.
