## Affected area

FE OSS kernels / SDPA forward selection.

## Summary

Allow bounded paged D128 graphs to use the existing split selector. `paged_thd_split_domain` already requires a valid positive packed-Q capacity for shape overrides, but `paged_thd_split_choice` then rejected every override-enabled graph. Removing that redundant exclusion lets an eligible bounded declaration use the same policy as its fixed equivalent.

Extend the existing declared-geometry test to paged SM100/SM107, with and without Stats. It compares fixed and bounded declarations without pinning a split count, engine winner, or timing. Unbounded overrides must still decline.

## Why

FlashInfer needs reusable bounded graphs as lengths change. Otherwise, enabling shape reuse makes a previously eligible split disappear and places the backend first, even though the prepared split path supports the declared bounds.

B200 (148 SMs, 1000 W), cuDNN 9.27.0.42, CuTeDSL 4.8, Torch 2.12/CUDA 13.2, FE develop `c57af9650` versus this selector change. Same private FI paged-bucketing prototype in both arms; ordinary public wrapper, BF16 D128, HND pools, page16, bottom-right causal, output-only, Hq/Hkv=16/4, four independent layer buffers. Medians across two reversed measurement orders:

| Declared Q / KV | GPU replay before / after, us per layer | Eager plan + four layers through completion, us |
|---|---:|---:|
| 128 / 8192 | 173.22 / 23.28 | 878.40 / 327.70 |
| 512 / 16384 | 202.59 / 80.93 | 999.62 / 515.35 |

The paired FE comparison covered eight geometries, with FP64 output checks and changed-input replay checks in every run. These are attention component measurements. The FI auto policy and serving adoption need separate qualification. Host enqueue can increase when the selected route changes: the first row measures 27.80 to 36.54 us per layer; GPU and complete-chain gains should not be described as host submission gains.

## Related issues

Related to #1439 and the paged selection in #1451 / #1463. This does not solve coarse caller capacity declarations. #1468 addresses nonpaged unsplit placement separately.

## API and compatibility impact

No public API, kernel, native ABI, or capability-row change. Existing BF16 D128 paged eligibility, device/layout bounds, workspace checks, cost model, and explicit candidates remain in place. Only already-supported bounded declarations become eligible for the same automatic choice as fixed declarations.
