# Fix terminal dQ barrier reuse in FROST attention backward

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1698) · state: open · merged: False

## Original PR description

## Problem and change

Persistent D128 FROST backward can reuse a completed dQ source-credit barrier phase without a successful wait. The store warp bootstraps four credits for each CLC work item, while the terminal dV/dK epilogue observes only slices 1 and 3. Slices 0 and 2 can therefore advance unobserved after the final dQ tile or a work item with no Q iterations. Ordinary numerical tests can pass despite this protocol violation.

Observe all four terminal dQ credit phases before publishing dV/dK. Apply the same repair to dense and THD accumulation loops; grouped-query kernels reuse those loops. Preserve the existing per-tile waits, TMA source-consumption waits and arithmetic.

Add eight regression cases covering MHA/GQA, causal/noncausal, FP16/BF16, both packed Stats layouts, persistent and zero-trip work, changed THD lengths/origins, poisoned storage and graph replay. Document the phase-observation requirement and synccheck detector in the SDPA agent guide. No capability row or public API changes.

## Performance hold

**Keep this PR unmerged pending performance investigation.** Reviewer measurements on two SM100 engineering devices found a repeatable dense-case cost for the added terminal waits: about +1.8% and +3.2% for FP16 causal MHA, B=3/H=6/Q=768/KV=1152/D=128. The ragged GQA control was approximately flat, and the separate host-enqueue checks did not establish repeatable added overhead. These are local complete-chain measurements with unlocked clocks, not production-B200 or context-parallel results.

The repair addresses a demonstrated synchronization violation. Passing correctness tests and review approval do not waive the performance hold; retain the required phase observations while investigating the cost. Broader host, device and full-CP non-regression qualification is still pending.
