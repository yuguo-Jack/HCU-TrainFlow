# sdpa fwd: launch geometry for native D576x512 (planning raised KeyError: 576 on SM100)

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1913) · state: closed · merged: True

## Original PR description

## What

#1902 added the native D576x512 shape to `sdpa_fwd_prefill_sm100`. The launch-geometry tables `config_sm100.cga_ctas` and `cga_tile_m`, however, map only d 32–512. The split-KV wave model calls `cga_ctas(_selected_d_shape(...)[0], cga)` while proposing plans, so it raises:

```
heuristics.propose -> recommend -> _knob_sets -> _split_points -> _split_launch -> cga_ctas
KeyError: 576
```

`propose()` runs inside `create_execution_plans` on every lane, including the native-backend one. As a result, **any SM100 D576x512 graph (Kimi K3 absorbed-MLA decode) currently fails planning**, whichever engine the caller wants.

The fix adds the D576 geometry. D576 runs the 2x2 datapath with one CTA pair (`make_cfg_d512_2x2(cga_m=2)`), which gives 2 physical CTAs and 128 Q rows per cluster. D512 is unchanged at (4, 256).

## Verification

**Before the fix** (develop 8cc48fe8e), the inference harness on SM100 with Kimi K3 decode shapes failed with `KeyError: 576` on the `cudnn`, `cudnn_oss` and `cudnn_auto` legs alike.

**After the fix**, every leg plans and runs (SM100, cuDNN 9.28.0.38, ms):

| shape | cudnn | cudnn_oss | cudnn_auto |
|---|---:|---:|---:|
| 96/1 d576/512, q1, b64, kv 8k, dense | 6.59 | 1.15 | 6.60 (backend) |
| same, paged | 7.27 | 1.21 | 7.26 (backend) |
| q4 MTP, b64, kv 8k, paged | 256.73 | 1.42 | 1.43 (FROST) |
| q1, b1, kv 128k, paged | 1.88 | 0.43 | 1.88 (backend) |

The `s_q == 1` rows show that placement keeps the backend where FROST is 4–6× faster. That placement change will be a separate PR backed by a frozen-holdout study; this PR is only the crash fix.

## Tests

- New `test_native_d576_has_launch_geometry_for_the_split_model`. It raises `KeyError: 576` on develop and passes with this change.
- FROST SDPA heuristics, placement and geometry suites, plus `test_sdpa_fwd_d576_sm100.py` and `test_sdpa_fwd_d512_2x2_sm100.py`: 1698 passed. The one failure is `test_kernel_source_arrive_sites_match_the_ledger`, which also fails on develop and which #1911 fixes.
