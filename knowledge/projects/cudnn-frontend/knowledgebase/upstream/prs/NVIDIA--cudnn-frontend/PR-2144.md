# Support scalar KV tails in native half split attention

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2144) · state: closed · merged: True

## Original PR description

Explicit split-KV plans currently reject mask-free dense attention with a non-tile-aligned KV extent outside a narrow head-dimension domain. The existing half kernels already mask the scalar KV tail and emit empty-split identities. Admit their D64, D128, D192/V128, D256 and D512 flavors, including supported logical head-dimension envelopes, consistently in graph and standalone support checks.

This changes candidate eligibility, with no kernel-body, default-selection or execute-path changes. Existing split restrictions remain in force, including the SM107 dense D256 decode-tile requirement. FP8/MXFP8 domains are preserved. The support matrix documents the expanded half domain.

Validation:
- SM100 and SM107 each pass 79 targeted cases and 4 Compute Sanitizer memcheck cases (zero errors). Coverage includes FP16/BF16, nine exact/logical width pairs, split4/O+Stats and split16/O-only, fresh bindings, scalar KV overrides across tile boundaries, poisoned backing tails and changed-V CUDA Graph replay. Existing D128 half/FP8 cases remain controls.
- 433 related host tests pass, 23 skip and 38 are deselected. The 27 new admission checks give 26 failures and one existing pass on the unchanged parent, then all pass with this change.
- Scoped hooks and diff checks pass. A separate broader analyzer/heuristics run reached its 600-second limit and is not counted as passing.

Native coverage is collected directly through the existing architecture CI entries: `TestNativeScalarTailSplit` in `test_sdpa_fp8_sm107.py` and `test_sdpa_fwd_dsl_sm100.py`. Each entry collects 27 admission and 36 native replay cases; architecture guards avoid running both entries on one device. The shared helper has no `test_` prefix, so directory sweeps do not duplicate it.
