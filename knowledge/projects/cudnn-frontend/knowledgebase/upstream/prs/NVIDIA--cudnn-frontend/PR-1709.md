# Prioritize long-KV requests in split prefix attention

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1709) · state: closed · merged: True

## Original PR description

For bottom-right prefix attention, a request with few query tokens can still have a long KV traversal. Ranking split requests only by Q length can leave expensive partitions until late in a persistent launch.

This changes the existing setup remap to rank by descending KV length for the shared D64/D128/D256 forward split hosts, with stable original-index ties. The path is restricted to bottom-right attention without a sliding window. Other callers keep Q-length ranking. Split counts, task coverage, main kernels, synchronization, workspace layouts and host execution are unchanged; this adds no public tuning knob or setup launch.

The existing metadata test now covers both sort keys, anti-correlated lengths, stable ties, zero-length batches, cumulative offsets, and warp boundaries. It does not pin an attention heuristic or timing result. Reverting the test probe to Q ordering reproduces the expected remap mismatch; the final metadata matrix passes 136 cases on SM100. The device implementation also passed the existing 144-case SM100 and 64-case SM107 dynamic/capture matrices, focused mask controls, and standalone memcheck/racecheck probes.

Ready for review. Target B200 performance qualification and the uniform-batch regression check remain prerequisites for merging. Local experiments show a benefit for skewed split candidates, but this does not fix automatic split selection. A uniform-batch timing difference remains under investigation because the local test device changes clocks under load. No universal no-regression or serving-speedup claim is made.
