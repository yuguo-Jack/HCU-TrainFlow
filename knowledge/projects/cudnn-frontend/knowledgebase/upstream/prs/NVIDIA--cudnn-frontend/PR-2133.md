# [SDPA] Support native SM80 paged KV and independent THD origins

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2133) · state: closed · merged: True

## Original PR description

SM80 FROST forward attention currently cannot serve paged KV through the graph API, and its packed path derives every physical sequence origin from length prefixes. This adds native paged loads and independent physical Q/K/V/O/Stats origins, so page pools and storage gaps bind directly without staging copies.

- Supports FP16/BF16 dense and THD queries across the four SM80 tile families and their eight-aligned logical head-width envelopes. K/V may have independent pool capacities, HND/NHD strides and page-table pitches. Loads predicate logical rows and columns before accessing page tables.
- Separates live lengths from per-port INT32/INT64 offsets, strides and element multipliers. Preserves the existing packed-wrapper ABI; graph O without offsets uses its declared batch pitch. Runtime rebinding and CUDA Graph replay reuse compiled artifacts, with metadata validation before writes.
- Extends the native dense binder and graph capability/support tracker together. Other architecture rows retain their existing pool-count contract. Graph decode and explicitly padded THD Stats retain their existing limitations.

Validation on A100: 567 focused GPU/native-ABI tests passed (4 skipped); 165 host admission/geometry/Stats checks and 82 targeted paged/append-only capability checks passed. Compute Sanitizer: 26 independent-origin/paged-graph cases passed with zero errors. Matching native extension build and scoped pre-commit passed. Tests cover full FP64 O/Stats references, changed page tables/offsets/lengths, fresh bindings, empty sequences, NaN slack, output canaries, and execute-time allocation/compilation/synchronization guards.

Builds on #2132; land that dependency first. No heuristics or placement policy changes, and no performance claim.
