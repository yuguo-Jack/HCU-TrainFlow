# perf(sdpa): pack short-query combine warps across heads

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1982) · state: closed · merged: True

## Original PR description

Q1/Q2 lean split-combine currently launches separate blocks for each head. Group up to four independent head warps per block, reducing the short-query block count while keeping each row's reduction and stores unchanged. Guard the final head group explicitly; larger-query and many-split forms keep their existing launches and selector inputs.

The new B3/H5/Q2 regression exercises partial head groups across the 16/17-split boundary and larger split counts.

On a local 68-SM SM100 device, warm full-attention CUDA Graph replay across eight paged BF16 D128 cohorts and splits 1/2/4/8/16 improves aggregate latency by 0.44% and 0.47% in reversed construction orders. Independent unchanged-source controls move +0.028% and -0.027%. For B4/H16:2/Q1 with all KV lengths 8192, the best tested plan improves 26.192→25.548 us and 26.208→25.520 us (2.46–2.63%). Other improved best-tested split plans gain about 0.2–2.0%; unsplit winners remain within control variation. Standalone small-batch combine cases can regress about 0.13–0.18 us. These are local explicit-plan measurements; default dispatch, production B200, other architectures' runtime performance and serving are outside this result.

Validation:

- 233 repository tests in both split-combine modules, including shape reuse, output strides, sinks, dead splits and FP8.
- 1,200 full-attention FP64 O/Stats lifecycle checks with common input/output/workspace addresses, changed lengths, poisoned capture replay and pointer rebinding; 576 standalone combine lifecycle checks.
- Six cases under each of Compute Sanitizer memcheck and synccheck, zero errors.
- 24 offline compilation controls across sm100a/sm103a/sm107a/sm120a, covering half partials, sink/Q lengths, gate/PDL, ragged Int64 and FP8 amax/scale.
- Scoped pre-commit checks.
