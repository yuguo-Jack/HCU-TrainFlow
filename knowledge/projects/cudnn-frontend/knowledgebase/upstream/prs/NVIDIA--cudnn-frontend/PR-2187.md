# sdpa(fwd): zero the runtime KV padding tail of V in the SM90 D512 prefill

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2187) · state: closed · merged: True

## Original PR description

## Problem

On SM90, a dense SDPA forward graph with `use_padding_mask` and runtime `seq_len_kv` returns NaN in valid output rows when the K/V storage past a batch's `seq_len_kv` holds NaN bit patterns. Those rows are runtime padding. `sdpa_fwd_prefill_sm90` is the only FROST forward plan on Hopper (head dims in (256, 512]), and it leaks at D512, D320 and D272, fp16 and bf16. Backend `eng8` stays clean on the same graphs.

The pad rows lie inside the declared S_kv, so TMA loads them as they are. The score mask zeroes P there, but P @ V multiplies P = 0 by the padded V row, and `0 * NaN = NaN` reaches every valid row. #2135 made runtime padding unread data for the SM80 bodies, and the SM120 bodies already zero this tail (`thd_helpers.sanitize_v_tail`; see also #2178).

## Change

- `prefill_d512_f16.py`: on the first visited KV tile of a graph with dense KV lengths, each compute warpgroup zeroes the rows of its own V half at and past `kv_len`. WG1 owns half 0 and WG2 half 1.
  - The zeroing runs after the V FULL wait and before that warpgroup's PV WGMMA.
  - Each warpgroup then fences the async proxy and syncs on its own named barrier, new ids 4 and 5, so WGMMA reads the zeros.
  - Only the first visited tile can hold pad rows: the reverse walk starts at the tile that holds `kv_len - 1`.
  - THD graphs are unchanged: their clipped per-sequence maps already make the tail TMA-OOB zeros.
- `_common_hopper.py`: new `zero_v_tail_rows`. SW128 permutes 16-byte chunks only within a 128-byte row, so whole rows are cleared without the swizzle math. The 128 lanes split the 2048 16-byte stores of a half.
- New `test/python/sdpa/frost/test_sdpa_sm90_padding_nan.py`, modelled on `test_sdpa_sm80_padding_nan.py`.
  - Fills the Q/K/V padding with NaN and checks O and Stats against an fp64 reference.
  - Replays a captured CUDA graph with changed lengths, then repeats with fresh bindings.
  - Covers D512, D320, D272 and D512x384, fp16/bf16, causal and non-causal.

## Tests

On a GH200 (cc 9.0), cuDNN 9.27:
- Before the fix, I ran a probe over every ranked plan with NaN only in V's padding. Both `sdpa_fwd_prefill_sm90` configurations leaked at every head dim; `eng8` did not.
- New test on develop (cad0be0a): 32 failed. With this change: 32 passed.
- `test_sdpa_fwd_dsl_sm90.py`, `-m "L0 or L1"`, on the patched tree: 117 passed.
- `pre-commit` on the touched files passes.
