## Affected area

CI or test infrastructure

## Summary

`gated_attention_block_qsa_reference` computes its projection as one fp32 GEMM over all 1408 columns of `w_qkvg`: 768 dense columns plus the 640-column INDEX band. `test_the_index_band_is_split_off_and_exposed` compares that output against the dense oracle, which runs the same GEMM at N = 768, with a 1e-5 bound documented as "bitwise in practice".

On some GPUs cuBLAS reduces the shared columns in a different order at the two N. This PR makes the QSA oracle run the dense columns and the band as two GEMMs. Each output element is still one fp32 dot product rounded once, so the oracle's math is unchanged; only the reduction order becomes independent of the band. A stale comment in the test is updated in place.

## Why

Fixed inputs (`seed=15`, `h` [1, 64, 256]), fp32 with TF32 off. The table counts how many of the 768 shared columns differ between the N = 1408 and N = 768 GEMMs:

| GPU | fp32 values differing (of 49152) | after bf16 rounding | test before |
|---|---|---|---|
| L40S | 30617 | 6 | **fails**: `out: max rel diff 6.868e-04 > 1e-05` |
| A100 | 28130 | 7 | passes |
| H100 | 0 | 0 | passes |
| B200 | 0 | 0 | passes |

A100 also has differing values but stays under the 1e-5 bound. CI runs this test on sm80/90/100/107 but has no sm89 cutedsl lane, so the L40S failure only shows up locally.

## Related issues

Related to #1639, which added the oracle and the test.

## API and compatibility impact

None. Test oracle only.

## Testing

- **The failing test on all four GPUs**, after this change: `pytest gated_attention_block/cutedsl/test_gated_block_qsa_reference.py -k test_the_index_band_is_split_off_and_exposed` passes on L40S, A100, H100 and B200. The band now matches the indexer's `k_raw` bitwise: 8192/8192, max diff 0.
- **The full set of QSA test files that import this oracle** (`test_gated_block_qsa_reference`, `_vs_transformers`, `test_block_qsa*`):
  - L40S: 132 passed, 105 skipped.
  - B200: 131 passed, 1 failed, 105 skipped. The failure is `TestIdentityBound::test_adversarial_plant_makes_the_dropped_block_matter` (`6.47 > 8.0` nats). It fails identically with the unmodified develop oracle on this host and passes on CI sm100, so this PR does not cause it.
- **Not run locally:** the sm107-only kernel tests.
- **Probe:** `evidence/qsa-index-band-l40s/probe.py` in the workspace.
