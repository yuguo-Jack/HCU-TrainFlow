# fix(gemm): use SM110-safe warp amax throughout CuTeDSL kernels

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1745) · state: closed · merged: True

## Original PR description

## Summary

Fixes #1686's unsupported FP32 warp reduction on SM110. Jetson AGX Thor supports the block-scaled `tcgen05` MMA, but `redux.sync.max.f32` and `redux.sync.max.abs.NaN.f32` fail in ptxas. The grouped wrappers admit SM110 and therefore reach that compile error.

Move the existing grouped SwiGLU shuffle fallback into a shared helper and route the remaining 39 direct FP32 max reductions through it, across grouped, dense and discrete GEMM families. SM110 uses five butterfly shuffles with NaN propagation; other targets retain the previous redux instruction. The Hadamard-quant helper preserves absolute-max semantics, and the grouped helper retains its existing exports.

A separate test-only change reuses the existing grouped dSReLU midpoint-aware comparison for FP8 row- and column-quantized output. One Thor offset test disagreed at 1/131072 elements: the FP32 reference was exactly -46 (rounded to -48), while the kernel returned -44. CPU FP64 recomputation from captured inputs produced -45.999989206195096. Both cuBLAS versions reproduced the original failure. The same element has the corresponding column-quantized midpoint disagreement (-24 versus -22), so both output comparisons retain their unrounded reference. The check retains the original `atol=0.1` and `rtol=0.01`, using the existing unrounded-reference midpoint rule for this narrow-dtype boundary; ordinary mismatches still fail.

## Native Thor validation

Jetson AGX Thor, CC 11.0, CUDA toolkit 13.2, PyTorch 2.13.0+cu130, cuDNN 9.27.0.42, CuTeDSL 4.8.1. The installed Frontend resolves to the tested source checkout; changed files were matched by SHA256. Native tests use explicit cuDNN loading to avoid the older system copy.

- `test_sm110_amax_reduction.py` plus `test_rubin_kernel_dispatch.py`: **29 passed**. Eight device cases check all 32 lanes for finite values, all-negative values, NaNs and infinities, with and without absolute value.
- A frozen representative sweep selected the first parameter of every test function in 13 affected GEMM files: **201 passed / 22 skipped / 1 failed**, 224 total. The single failure is the FP8 midpoint comparison above. Architecture/configuration skips remain listed separately.
- After preserving both row and column pre-quantization references: the full quant file plus the existing adversarial midpoint test passed **194 / 390 cases, with 196 architecture/configuration skips and zero failures**, in 244.39 seconds. The intermediate row-only repair exposed the same pixel in the column output; its failed full sweep was also retained (193 passed / 196 skipped / 1 failed).
- The original issue's Transformer Engine XML contained 117 tests failing with `redux.f32`. Re-running those exact node IDs with the repaired Frontend: **117 passed**, in 300.52 seconds. This includes fused MLP forward/backward, prequantized inputs/gradients, FP16, main-grad overwrite and CUDA graph cases.

The TE check uses the existing `2.22.0.dev0+9d9bd9e5` Thor build (which already carries local Thor build/quantization patches, not a pristine upstream checkout) and an isolated package copy with the same three test-only SM110 admission changes described in the issue. It does not enable Thor by default in upstream TE. CUDA 13.2 cuBLAS was explicitly selected because the older wheel cuBLAS lacks a symbol required by that existing TE build. A library-selection collection error and a malformed standalone node ID were corrected before the 117-case execution; both failed collection logs were retained.

## Regression coverage and review follow-up

The all-lane numerical test now runs on SM100/SM103/SM107 as well as SM110, exercising the unchanged native redux path on those CI targets instead of skipping them. Direct kernel imports skip on CuTeDSL versions below the repository floor, and SM107 skips if the installed DSL lacks its target.

At `527a23f066b1df3d4d21239468b19416943f4c83`, the Thor helper/dispatch/midpoint run passed 30 tests. The maintainer independently [reported native SM100 validation](https://github.com/NVIDIA/cudnn-frontend/pull/1745#issuecomment-6311247525) with CuTeDSL 4.8.0 and quack 0.6.2 imported first: **223 passed, 196 skipped, 16 deselected, zero failures**. This includes all eight device reduction cases, architecture dispatch, grouped quantization L0 and the adversarial midpoint detector. That result is bound to the stated head and does not qualify every affected GEMM family or performance.

Review fixes at `2fd85628b369c18072db654e3b2b7beb77ac1627` remove an overlapping newline alternative in the source-routing regex. The original regex exceeded a two-second subprocess deadline on a long multiline non-match; the fixed expression handles both matching and non-matching inputs, now covered by two regressions. The grouped helper's original `_target_needs_shuffle_amax()` remains a forwarding function, avoiding unused private aliases while preserving its callable behavior. The six-architecture predicate test checks both entry points. Kernel arithmetic and FP8 comparison policy are unchanged.

The latest source-pinned native Thor run passed **32 tests / 0 skipped / 0 failed** in 5.77 seconds. All 20 changed files matched SHA256 before execution; collected logs and inputs were verified afterward. Local Black, Black-Jupyter, SPDX and `git diff --check` passed.

The upstream integration run for `527a23f` reports three failing SM100/SM107 jobs. Its internal logs are not accessible from the contributor environment, so the failure node IDs/logs have been requested for triage; this PR does not claim that the full integration matrix is green. Native SM103/SM107 validation and review of the latest head remain pending.

## Controls and limits

Earlier cross-compilation controls assemble both helpers for sm_110a/sm_100a/sm_103a; the raw FP32 redux control is rejected for sm_110a and assembles for sm_100a/sm_103a. Cross-compilation is not counted as device execution. Native SM100/SM103 performance and full parameter sweeps remain unmeasured here; the non-SM110 instruction path is unchanged.

`pre-commit run --files` passed Black, Black-Jupyter and SPDX checks. No public API signatures, capability matrix rows or production numerical tolerances changed.
