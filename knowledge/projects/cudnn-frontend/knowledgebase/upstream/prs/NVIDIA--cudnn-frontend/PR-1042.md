# sdpa(paged): harden the paged KV decline paths and bound the page walk (#964 review)

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1042) · state: closed · merged: False

## Original PR description

## What

Follow-ups from the CodeRabbit review of #964, which merged before they were applied. All five findings are still open on develop; none were addressed pre-merge. Each is reachable from a caller-supplied value that plan-time validation let through.

## `engines.mismatch()`

**`page_size <= 0` crashed instead of declining.** It reached `128 % p` and raised `ZeroDivisionError`; a negative value passed the divisibility checks and reached `config_sm100._validate_params`, which raises. Now takes the same lower bound as `_validate_params`.

**The mixed-head-dim rejection asked the wrong question.** It keyed on head-dim inequalities, which is not the same as which flavor the lowering picks. Now keyed on `_pick_flavor`:

| dims | flavor | wired? | old rule | review's suggestion | this PR |
|---|---|---|---|---|---|
| (128, 192) | (256, 256) | yes | **rejected** | ok | ok |
| (192, 128) | (192, 128) | no | rejected | rejected | rejected |
| (256, 128) | (256, 256) | yes | ok | **rejected** | ok |

Worth flagging: the review suggested `d_qk > 128 and d_v <= 128`, which fixes `(128, 192)` but breaks `(256, 128)`. Only `(192, 128)` actually lands on the unwired d192x128, so the flavor is the thing to test.

## `_common_blackwell._resolve_seqlen_kv()`

Clamp the per-batch KV length to `[0, scalar_seqlen_kv]`, as `_resolve_seqlen_q` already does for Q — the KV twin lacking it was the asymmetry.

Load-bearing under `PAGED_KV`, where the scalar is the block table's capacity (`max_pages * PAGE_SIZE`): a device length above it put `n_pages_b` past the end of the table row, so the page walk read a block-table entry outside the batch's row and handed TMA an arbitrary page id. Clamping at the shared resolver covers every caller, including the per-tile loop update.

## `api_dsl.SdpaFwdDslSm100`

- **Block-table stride declarations must have two entries.** The execute-time comparison zips `got`/`want`/`shape`, and `zip` truncates — a one-element declaration silently skipped the page-axis check and still entered the compile key.
- **Reject paged operands from another CUDA device.** The launch device comes from `q_tensor` and the fake descriptors carry no device, so a pool or block table on a second GPU reached the binder as a foreign-device pointer.

## `graph_analyzer.SdpaBinding._build_index()`

Dedupe bound tensors by identity. One block table serving both K and V is the ordinary case; counting it twice marked its name and uid ambiguous, so `resolve_variant_pack` ignored variant-pack entries keyed by either.

## `SUPPORT_MATRIX_TRACKER.md`

The gaps row said paged KV was d128-forward only and listed THD as unsupported, contradicting footnote p and the d256 column.

## Validation

SM100, cuDNN 9.26.0.33, `CUDNN_FRONTEND_ENABLE_FROST_ENGINES=1`:

- paged + graph-analyzer + split-kv suites: **247 passed**
- `test_mhas_v2 -k fwd`: 200 passed / 4 failed — those 4 (`fwd_unified_block_mask_L0` test11/12/20/23) reproduce **identically with these changes reverted**, so they predate this work.
