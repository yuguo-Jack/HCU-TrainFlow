# bench(attention): reuse workspace and add GH200 and H100 measurements

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1744) · state: closed · merged: True

## Original PR description

## Problem and change

The native attention benchmark allocates its fixed-plan workspace before the loop, then allocates another workspace on each iteration while the old allocation is still live. A BF16 deterministic backward at B=2/H=64/S=16384 needs about 65 GiB, but the transient second copy makes it OOM on both H100 80GB and GH200.

Reuse the already allocated workspace when rebinding the iteration's tensors. Graph plans and workspace requirements are fixed. A subprocess regression test enforces a single-workspace allocation budget across two iterations for forward and backward; the old runner fails this control and the repaired runner passes.

Also add canonical attention-training CSVs, charts, environment notes and complete pass/skip/fail disposition ledgers for GH200 and H100. The attention dimensions follow the existing Llama configuration; these are microbenchmarks, not full-model measurements.

## Validation

- H100: original 60-case native sweep = 56 measured / 4 OOM; repaired same sweep = **58 measured / 2 OOM**. Both 16k BF16 deterministic backward masks now fit. The remaining two 32k cases request approximately 258 GiB and remain OOM; original negative outputs were retained.
- GH200: original 210-case sweep = 66 measured / 60 skipped / 84 failed. The repaired 16k BF16 deterministic-backward rechecks passed for both masks, giving **68 measured rows across 212 case executions** while retaining the original disposition ledger.
- The benchmark test file passed **8/8** on GH200, including both new allocation-budget tests, in 17.51 seconds.
- Black, Black-Jupyter and SPDX checks passed with `pre-commit run --files`; no C++ files changed.

## Measurement boundaries

Base frontend and benchmark: `ddf1dd36007633710c468f7fef1acb3897d7f6f4`. Native runs use PyTorch 2.14.1+cu130, cuDNN 9.27.0.42 and CuTeDSL 4.8.1. FA4 has a separate dependency stack documented in the GH200 README; its backward fails in FA4's `get_smem_store_C` call, and only its ten forward measurements are included. FROST D128 BF16/FP8 is declined on Hopper; MXFP8 has no available engine for the tested SM90 configurations.

The configuration has ten iterations with zero explicit warmup; the runner reports the final-five median. `skip_ref=True`, so CSV `max_diff=0` is a placeholder, not a correctness result. H100 causal/noncausal shards ran concurrently on two GPUs in one host and may share platform clock/power effects. The SOL denominator uses sampled SM clocks. The READMEs and `run-outcomes.json` preserve these limits and the differing original/recheck runtime bindings.

## API and compatibility impact

No public API or numerical-tolerance changes. Failed/skipped cases are excluded from timing charts and retained in the outcome ledgers.

## Reproduction

The canonical configuration is `python -m benchmark.attention_training.runner --config llama`; filter to the documented backend/dtype combinations when reproducing either directory. H100 used two independent mask shards; GH200's repaired recheck selected BF16, backward, deterministic, sequence length 16384 and both masks. The changed-file SHA and per-case ledgers are in each result directory.

From `test/python`, the regression command was:
```sh
CUDNN_FRONTEND_CUDART_LIB_NAME=libcudart.so.13 \
python -m pytest -n1 -rA sdpa/graph/test_sdpa_benchmark_single_sdpa.py
```
