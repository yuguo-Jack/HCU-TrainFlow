## Affected area

C++ frontend API or graph construction (plus the Python binding defaults)

## Summary

- **`layernorm`: `scale` and `bias` are now optional** in C++ (`nullptr`) and Python (`None`, now the default).
  - Scale without bias (`nn.LayerNorm(bias=False)`) works for any shape. The training `mean`/`inv_variance` dims are unchanged: `input`'s dims, with 1 wherever `scale` is not 1.
  - Bias without scale is refused at `validate()` with `INVALID_VALUE`. The backend rejects it (`hasBiasDesc() && !hasScaleDesc()`, `CUDNN_STATUS_BAD_PARAM`), and the FE error now says to pass a scale of ones.
  - With neither, the same rule as RMSNorm without a scale (#1542) applies: `input` may have at most one non-unit dimension after the first, or, in training, the caller sets the stats dims. Otherwise the node refuses, because the backend's inference default (normalize H only for `{B,S,H}`) and the inferred training stats `{B,1,1}` (normalize S×H) disagree.
- **`adalayernorm`: `bias` is now optional.** Its Python binding has always defaulted `bias` to `None`. `scale` stays required.
- `Graph::layernorm` / `Graph::adalayernorm` keep `nullptr` out of the inputs map, as `Graph::rmsnorm` does since #1542.
- `docs/operations/Normalizations.md` documents the contract.

## Why

On develop, both cases crash in `validate()`: `infer_properties_node` dereferences the null bias.

| Case on develop | Result |
|---|---|
| `layernorm(x, scale, nullptr)` | core dump (`evidence: run927_base.log`, the first no-bias case) |
| `adalayernorm(x, scale, nullptr)`, i.e. the Python default | core dump |
| either one on this branch | validates and runs |

`nn.LayerNorm(bias=False)` is the common case this unblocks.

## Related issues

Part of #188, following #1542 (RMSNorm). The norm backwards still require a scale, so #188 stays open for those.

## API and compatibility impact

- **Additive.** `scale` and `bias` gain `None` defaults in the `layernorm` binding; the positional order is unchanged.
- **No change for graphs that pass both.** The only new refusals are for graphs that previously crashed or were rejected by the backend.
- **Backend qualification** (probe matrix over {scale+bias, scale only, bias only, neither} × {`{N,H,1,1}`, `{B,S,H}`} × {inference, training}, with Y checked against a CPU reference):
  - A100, H100 and B200 with cuDNN 9.27;
  - H100 with 9.12, 9.14, 9.18, 9.20 and 9.24.
  - All served cases match the reference; bias-only is the only backend rejection. Older backends were not qualified.
