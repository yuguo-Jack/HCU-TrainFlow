## Affected area

FE OSS kernels or CuTeDSL

## Summary

- Add a native SM90 fused WGMMA sparse-prefill forward path for H16-H128 and Dqk 512/576.
- Provide symbolic bounded-cache compilation and preallocated CUDA Graph-safe execution with zero global workspace.
- Preserve the SM100 path and document architecture, layout, aliasing, empty-row, stream, and lifecycle contracts.

## Why

SM90 had no frontend-native DSA forward path. This port follows the FlashMLA Hopper sparse-prefill schedule so the compute and memory pipeline stays close to the established C++ implementation, while adapting the host contract to cuDNN Frontend plan reuse, strict pre-launch validation, bounded specialization, and CUDA Graph capture.

## Related issues

None.

## API and compatibility impact

The existing public sparse-attention forward API now admits SM90 for FP16/BF16, H in {16, 32, 64, 96, 128}, and Dqk in {512, 576}. SM90 requires `nvidia-cutlass-dsl[cu13] >= 4.8.0`. Prepared execution requires preallocated, disjoint, contiguous, correctly aligned outputs. Existing SM100 behavior is unchanged.

When `topk_length` is shorter than a configured `indexer_topk`, `lse_indexer` retains the source kernel's `+inf` sentinel; the full output, max-logit, and LSE results remain valid.

## Testing

- H200 focused suite: 40 passed; covers H {16,32,64,96,128} x Dqk {512,576} x {BF16,FP16}, optional inputs, invalid indices, empty rows, tile tails, short indexer prefixes, strided wrapper inputs, prepared validation, and CUDA Graph replay.
- 1,000,000 deterministic graph replays completed with zero bit mismatches.
- `compute-sanitizer` synccheck, memcheck (`--report-api-errors no`), and initcheck each report 0 errors on Dqk 576 K129 tail and Dqk 512 K640 short-indexer-prefix shapes.
- Pre-commit, compileall, diff checks, fence audit, compatibility/boundary audit, and CUDA Graph lifecycle audit pass.

## Credits

The SM90 kernel schedule and pipeline are adapted primarily from [FlashMLA's MIT-licensed Hopper sparse-prefill implementation](https://github.com/deepseek-ai/FlashMLA/tree/4f38f29ef6793c228363e4af5be66d44e81167ba/csrc/kernels/sm90/prefill/sparse). The cuDNN Frontend port extends that foundation with H16/H32/H64/H96/H128 coverage, arbitrary logical K tails and boundary handling, bounded symbolic compilation, and an allocation-free prepared-execution contract for CUDA Graph capture and replay.

The public API accepts softmax_scale=0, but invalid slots were already replaced with -inf before this FMA. Multiplying those slots by zero produces NaN probabilities, which enter the sum and PV accumulation; multiplying the result by the epilogue's zero reciprocal cannot remove NaNs. For example, H=16, Dqk=512, K=1, finite Q=0, KV=1 and indices=[[0]] should return O=1 with max_logits=LSE=0, but the padded slots take this invalid arithmetic path. Negative scales also turn masked -inf into +inf, and reducing raw logits before a negative scale selects the wrong maximum. Scale valid logits first, then mask and reduce the scaled logits; keep invalid probabilities exactly zero. Add zero/negative-scale tail cases against the reference. This blocks approval because accepted finite inputs can silently produce incorrect attention outputs.
