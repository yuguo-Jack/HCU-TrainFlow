## Summary

The DSA hardware-validation cases skipped on every part but cc 10.0, although the code they cover serves cc 10.3:

- `dsa_utils._require_exact_sm100` (13 cases in `test_DSA_sparse_attention_backward.py`, 2 in `test_DSA_sparse_score_recompute.py`) required exactly `(10, 0)`. The sparse attention backward maps cc 10.3 to `sm_103a` (`_SM100_FAMILY_ARCH_FLAGS`, `_BLACKWELL_CAPABILITIES`, the q-cluster gate), and the SM100 score recompute serves `compute_capability >= 10`.
- `test_DSA_indexer_backward.py` kept its own `_require_exact_sm100` (22 cases), whose docstring said SM103 end-to-end execution was "intentionally not required by this suite yet". It also required SM100 on the second device of the two-device case. The public gate accepts both parts (`INDEXER_BACKWARD_SM100_CAPABILITIES = ((10, 0), (10, 3))`).

Both helpers become `_require_sm100_family`, which accepts `(10, 0)` and `(10, 3)`. The two-device case accepts either part on the second device. No product code changes.

## Why

These cases never ran on a B300; this PR runs them there.
