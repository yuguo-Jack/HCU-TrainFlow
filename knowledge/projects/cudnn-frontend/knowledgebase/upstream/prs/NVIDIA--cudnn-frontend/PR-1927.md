## Affected area

FE OSS kernels or CuTeDSL

## Summary

1. **Placement.** `_sm107_paged_gqa_prefill` (cc 10.7, paged bf16 d128, page 16, head-major K, b 1–4, bottom-right causal) now also places FROST first for GQA 4 / 8 / 16 **long-prefix chunks**, where 1024 < s_q ≤ 4096 and 6144 ≤ S_kv ≤ 32768. Previously the chunk box ended at s_q ≤ 1024, so these chunks kept the backend first. MHA, group 2, windows, sinks and every other condition are unchanged.
2. **License header.** `sdpa/fwd/sparse_tile_rules.py` (added in #1923) takes the Apache-2.0 header. Its lines are NVIDIA-written and none appears in LICENSING.md's MIT list. That PR copied a neighbour's MIT header by mistake.

## Why

The range is exactly that of a training grid frozen before any timing: 32/8, 32/4, 64/4; b 1 / 4; s_q 1.5k–4k; S_kv 6k–32k. It was measured through FlashInfer's paged prefill wrapper with full O / LSE, pointer-rebinding and CUDA-graph replay checks in both process orders. The rule was written from that grid alone and then frozen at `b372ad334`. A separately frozen 40-case holdout with random geometries, including scope controls outside the box, then qualified it with no refit. Performance outcomes remain internal. This PR's placement source differs from the frozen head only in the module docstring (AST-checked).

## Related issues

Extends the Rubin paged GQA chunk placement from #1828.

## API and compatibility impact

None to the API. The default plan order changes on cc 10.7 for the graphs above. FROST and the backend are both still offered, and `deselect_engines` / opt-in behave as before.
