## Problem

Since #1233 (merged 2026-10-05 21:33 UTC), the `python/*/cutedsl:cutlass-4.8:sm107` lane fails 7 grouped GEMM cases on every PR pipeline that includes it, regardless of what the PR touches:

```
test_grouped_gemm_glu_canonical.py::test_glu_canonical_matches_legacy[situglu-*]   (4)
    NotImplementedError: Rubin grouped GEMM GLU does not support situglu
test_grouped_gemm_quant_canonical.py::test_quant_memo_uses_current_data_and_routing
    NotImplementedError: Rubin grouped GEMM quant does not support row_scale fusion
test_grouped_gemm_swiglu.py::test_grouped_gemm_swiglu_wrapper_dedicated_configs[fp4_tile_n128_{1,2}cta]
    ValueError: MMA tiler N must be in (256,), got 128
```

Examples: #956 pipeline 71764764 (job 470776983) and #1003 pipeline 71788822 (job 470990238). Neither PR touches grouped GEMM.

All three messages are intentional declines. The Rubin kernels have rejected situglu since #645 and row_scale fusion since #447, and the Rubin GLU kernel tiles N=256 only (`_blockscaled_api.py`, `supported_tile_n`). The tests #1233 added run these configurations on every SM10x device.

## Change

Test-only. On Rubin (`cudnn.api_base.get_device_type() == "rubin"`) each case asserts the typed decline instead of skipping it, so the decline stays covered on SM107:

- **GLU canonical, situglu:** asserts `NotImplementedError` "does not support situglu".
- **Quant memo:** asserts the row_scale decline, then runs the memo and routing check with bias only.
- **SwiGLU dedicated configs, tile N=128:** asserts the `MMA tiler N` `ValueError`.

SM100 behaviour is unchanged.

## Evidence

- **SM100, real hardware:** `test_grouped_gemm_glu_canonical.py`, `test_grouped_gemm_quant_canonical.py` and `test_grouped_gemm_swiglu.py::test_grouped_gemm_swiglu_wrapper_dedicated_configs`: 70 passed. B200, cuDNN 9.26.
- **Rubin decline path on SM100, with `is_sm107_device` patched to return True:**
  - develop: the four situglu cases fail with the CI error (RED).
  - this branch: they pass (GREEN).
- **tile N=128 cases:** cannot be simulated this way, because the local DSL cannot import the Rubin kernel module. The asserted message is the one the SM107 lane raises (quoted above). GREEN on real SM107 needs the cutedsl CI lane; it has been triggered.
