# perf(bsa): SM90 paired-KV backward, SM90 KPage for blk64/blk128, and shared BSA test gates

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2202) · state: closed · merged: True

## Original PR description

## Summary

Ports the SM100 BSA blk64/blk128 work that applies to Hopper, routes SM90 by SM90 measurements, adds the KPage path on SM90 for blk64 and blk128 metadata, and consolidates the BSA test gates.

**SM90 blk64 backward**
- Paired-KV backward: matched KV64 neighbors run in one CTA (one KV64 block per compute warpgroup) and share one sweep of Q/dO, LSE/dPsum and the dQ reduction. The gate is shared with SM100.
- Single-group direct dK/dV (counterpart of SM100 #1091): when every query block falls in one bucket, dK/dV are stored with TMA in the output dtype, without the FP32 workspace.
- Fixed-count lists also take the paired backward on SM90.

**SM90 blk64 forward**
- Automatic split-KV policy for SM90 (counterpart of SM100 #1603): split only once a head's K/V clearly exceeds L2.
- Fix: a nonpositive or NaN `softmax_scale` gave NaN or wrong outputs in the forward (split and unsplit) and in the regular backward. The scores are now scaled before masking, as on SM100.
- Fix: cross-warpgroup named barriers in the regular backward used the aligned `bar.sync` at different call sites (reported by synccheck). They now use the unaligned helpers.

**SM90 blk128 backward**
- CSR offsets are built with one warp per row (`parallel_offsets=True`), as on SM90 blk64 and SM100/SM103 blk128.

**KPage on SM90**
- blk64 forward: one CTA owns query blocks `2p` and `2p + 1`. It walks the union of their KV lists as 16-row pages gathered into 128-row tiles, so K/V of shared blocks are loaded once. The pair-walk metadata is built by CuTe DSL kernels.
- blk128 forward and backward: the layout rewrites the blk128 metadata as 64-row halves with a CuTe DSL kernel. KV halves without valid rows leave every list, and all-padding Q halves get an empty list. The forward runs the blk64 KPage kernel above (one pair of halves = one 128-row query block). The backward runs the SM90 blk64 backward with `LSE = +inf` on padding query rows. Padding rows of `o`/`lse`/`dq`/`dk`/`dv` are written as zero, the same contract as SM100/SM103.
- SM90 contract: MHA only, `seqlen_q`/`seqlen_k` multiples of 64, no `bwd_kv_groups`. These limits are checked in the API and raise `NotImplementedError`. The docs (`bsa.md`) and `benchmark/bsa/README.md` are updated.

**Tests**
- `bsa_utils` now provides `require_arch`, `require_cutedsl`, `import_bsa`, `import_kpage_bsa`, `valid_rows` and `random_metadata`. They replace five copies of `_import_bsa`, six per-file gate helpers and about 40 inline capability/skip blocks.
- `attention_backward_reference` handles GQA.
- `test_BSA_kpage.py` runs on SM90 as well. Its calls pass `sparse_block_size=128` explicitly, and `test_kpage_seqlen_not_multiple_of_128` gains a `(960, 704)` case that both architectures run.
- No test is renamed or removed by the cleanup commit. Before and after it, every collected case kept its outcome on B200 and H100.
