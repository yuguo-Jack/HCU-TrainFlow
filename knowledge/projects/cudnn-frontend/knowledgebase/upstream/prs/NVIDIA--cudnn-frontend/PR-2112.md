## Affected area

CI or test infrastructure

## Summary

The native SDPA binding suites (`test_sdpa_native_{dense,prefill,sink,split,arch,ragged_decode}_binding.py`) run their GPU cases through the graph and standalone helpers of `test_sdpa_native_dense_binding.py`. Those helpers take a `cc` argument, default `(10, 0)`, and skip unless the device is exactly that part. So every SM100 case skipped on cc 10.3, although SM103 serves the same sm100 bodies compiled for `sm_103a`.

`_parts(cc)` maps the `(10, 0)` default to the SM100 family, `(10, 0)` and `(10, 3)`. Every other `cc` stays exact: the cc 10.3 and cc 10.7 cases that `test_sdpa_native_arch_binding.py` names keep their part. The skip message names the admitted parts. No product code changes.

## Why

These cases never ran on a B300; this PR runs them there.

## Related issues

#2108 widens the one exact-SM100 standalone split case in `test_sdpa_native_split_binding.py`. This PR does not touch that file, so the two do not overlap.

## API and compatibility impact

None. Test only.

## Testing

B300 (cc 10.3), develop `64ed3dfe` with its own extension, torch 2.14.1+cu130, cuDNN 9.27.0, CuTe DSL 4.8.1, `CUDNN_FRONTEND_ENABLE_FROST_ENGINES=1`. From `test/python/sdpa/frost`: `python -m pytest -m "L0 or L1" test_sdpa_native_dense_binding.py test_sdpa_native_prefill_binding.py test_sdpa_native_sink_binding.py test_sdpa_native_split_binding.py test_sdpa_native_arch_binding.py test_sdpa_native_ragged_decode_binding.py`:

| | passed | skipped |
|---|---|---|
| develop | 878 | 225 |
| this PR | 1044 | 59 |

The 59 skips left are 57 cc 10.7 cases and the split case #2108 covers. Not run on cc 10.0, where `_parts` admits the part exactly as before.
