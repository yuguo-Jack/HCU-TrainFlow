# norm(bprop): spread the plain backward's dgamma / dbeta atomics over slots

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2139) · state: closed · merged: True

## Original PR description

## Problem

LayerNorm / RMSNorm backward rows whose width has no whole-warp vector mapping take the plain one-CTA-per-row `_ln_bwd_kernel`: in bf16 / fp16 that is every width that is not a multiple of 64 (48, 96, 200, 720, 1000, 2000, 3000, ...). Its dgamma / dbeta are per-element fp32 atomics straight into the `[C]` outputs, so all R rows serialize on the same C addresses. On a B300 the backward at C = 96 takes 0.55 ms at 65k rows and 1.09 ms at 131k rows, where the native backend takes about 0.15 ms.

## Change

- `_ln_bwd_kernel` takes an `nslots` constexpr (default 0: unchanged). With `nslots > 0`, row r adds into slot `r % nslots` of a `[nslots, C]` fp32 partial buffer. The existing `_ln_bwd_finalize_kernel` then sums the slots into dgamma / dbeta (`_ln_bwd_slots_host`).
- The plain route of `backward()` uses it from 1024 rows. `nslots` is `min(1024, R // 16, 2^21 // C)` rounded down to a power of two: it is part of the compile key, so it takes at most five values (64 ... 1024) instead of changing with every row count. The partials are carved from the workspace, and `scratch_bytes` reports them.
- dgamma / dbeta stay atomic reductions, so they are no more bitwise repeatable run to run than before. Only the summation order changes; dx is unaffected.
- Below 1024 rows the direct atomics stay. The pipelined, tiled and CGA routes and the extended-affine backward are unchanged. The forward is untouched.

## Measurements (B300, cc 10.3)

Both legs run `benchmark/norms/_norm_bench_worker.py --backend cudnn` with the default plan (the FROST engine), each in its own process: develop, then this branch, with the order alternating per cell. The ratio is this branch's backward time over develop's.

- **Training grid** (bf16, LayerNorm / RMSNorm, rows 1024-131072 x C 96 / 160 / 1000 / 2000 / 5000): 0.100-0.902. The forward, which this change does not touch, measured 0.984-1.018.
- **Row floor.** A first version without a floor failed its frozen holdout at 201 rows (1.187: the extra launch). A small-row grid (rows 64-1024, C 96 / 720 / 2000, bf16 / fp16) gave:
  - 1.07-1.34 up to 256 rows;
  - 0.77-1.11 at 512 rows;
  - 0.53-0.91 at 1024 rows.

  Hence the 1024-row floor.
- **Frozen holdout.** The rule was fixed before the draw, with the criterion "every cell <= 1.03x develop". The draw was 16 cells: off-grid widths 48-6000, rows log-uniform from 1024 to 200k, bf16 and fp16. Range 0.097-0.752:

**Power-of-two slot counts (6890c11f).** The first head used `R // 16` directly. That compiled a new artifact for each row count between 1024 and 16k rows. The fix rounds the count down to a power of two. I re-measured the same 16 holdout cells afterwards, so this is not a fresh holdout. The ratios were 0.096-0.750, against 0.097-0.752 before.

The same holdout also covered an extension of the slots to the extended-affine backward (zero-centered gamma / adaptive), which reuses this kernel. Three of its 16 cells exceeded 1.03: 1.14-1.40, at 2.5k-5.6k rows per address with C 1536-4096. That extension is not part of this PR.

The kernel path is architecture-independent, so cc 10.0 takes the same change. I measured only on cc 10.3.
