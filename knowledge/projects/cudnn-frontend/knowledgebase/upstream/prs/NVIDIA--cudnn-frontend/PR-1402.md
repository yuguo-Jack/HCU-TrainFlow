## Problem

`test_grouped_gemm_dsrelu.py::test_grouped_gemm_dsrelu_deterministic_at_scale` (L1, seed 53) fails on B200 on develop `20a3c87b5`. The failure is deterministic and is the same on the Rule 8 merge base `54a716b`:

```
Mismatched elements: 1 / 16777216 (0.0%)
Greatest absolute difference: 8.0 at index (811, 474, 0) (up to 0.1 allowed)
```

The output is e4m3 (`d_row_tensor`). A probe of the reference quantizer at that element gives:

| quantity | value |
|---|---|
| pre-quantization value | `168.75` |
| block amax | `637.79` |
| `norm_const` | `0.01` (fp32 `0.0099999998`) |
| scale factor | `2^-6` |
| code-domain value | `107.99999758` |
| fp32 rounds it to | `108.0`, the midpoint between e4m3 codes 104 and 112 |

The reference (`cute.testing.convert`) rounds the tie to even and gets 112. The kernel accumulates the GEMM in a different order and gets 104. Neither is a defect: the input sits on the rounding boundary, so the last fp32 bit decides.

## Change

Test-only.

- `compute_reference_row_quant` takes `return_unrounded=False`. When set, it also returns the scaled values before rounding to `d_dtype`. Existing callers are unchanged.
- The `d_row` and `d_col` checks use a new `assert_close_quantized`. An element outside atol/rtol is accepted only if its unrounded reference value is the midpoint of the kernel's and the reference's codes (relative 1e-5). Every other element is compared at the original tolerances.
- `test_assert_close_quantized_accepts_only_midpoint_ties`: a CPU self-test. A tie passes. A one-ulp difference away from the midpoint fails. A missing unrounded tensor keeps strict behaviour.

## Evidence

- Probe log: code-domain value `107.99999758`, fractional position 0.4999997 of an 8-wide ulp.
- `test_grouped_gemm_dsrelu.py`, L0+L1, B200, cuDNN 9.26:
  - develop: `deterministic_at_scale` fails (above).
  - this branch: 123 passed, 80 skipped.
