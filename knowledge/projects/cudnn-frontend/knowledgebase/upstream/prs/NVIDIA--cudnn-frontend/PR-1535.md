## Affected area

FE OSS kernels or CuTeDSL (Python/JAX entry points)

## Summary

Follow-up to #1399, which added canonical MXFP8 JAX to the unified GLU forward. This PR repeats it for the two MoE backward ops, so `{MXFP8} x {glu, dglu, wgrad}` all run from JAX on SM100 and Rubin through the unified `*_jax_sm100` entries:

| | JAX entry (canonical MXFP8 mode) | Shared wrapper | Kernel (SM100 / Rubin) |
|---|---|---|---|
| GLU fwd (#1399) | `grouped_gemm_glu_jax_sm100(..., b_tensor=, sfa_tensor=, ...)` | `grouped_gemm_glu_wrapper_sm100` | GluBias / Glu Rubin |
| dGLU bwd | `grouped_gemm_dglu_jax_sm100(..., b_tensor=, sfa_tensor=, ...)` | `grouped_gemm_dglu_wrapper_sm100` | DgluDbias / Dglu Rubin |
| wgrad | `grouped_gemm_wgrad_jax_sm100(a, b, offsets, sfa_tensor=, sfb_tensor=)` | `grouped_gemm_wgrad_wrapper_sm100` | Wgrad / Wgrad Rubin |

1. **dGLU** (commit by @jberchtold-nvidia, from his TE integration branch): `grouped_gemm_dglu_jax_sm100` gains keyword-only `b_tensor`, `sfa_tensor`, `sfb_tensor`, `norm_const_tensor`, `discrete_col_sfd` and the GeGLU scalars, mirroring the GLU entry. `dswiglu`/`dgeglu`; only `dprob` is zero-initialized. The shared wrapper dispatches canonical JAX inputs to it before the memo. My follow-up folds it into `dglu/jax_api.py` next to the BF16 path, as in `glu/jax_api.py`, and replaces its dprob-only reference test with byte parity against Torch.
2. **wgrad**: `grouped_gemm_wgrad_jax_sm100` gains keyword-only `sfa_tensor`/`sfb_tensor`, which select canonical MXFP8:
   - A `(m, tokens)` and B `(tokens, n)` row-major, the same contract as the BF16 JAX path. The kernel takes N-major MXFP8 B (verified bit-exact against the independent reference on SM100 and Rubin), so no transposed copy is needed.
   - SF buffers are the Torch per-expert packed bytes at any dense rank; offsets are cumulative token ends in multiples of 128.
   - Output is a dense XLA `(experts, m, n)` `wgrad_tensor` in a `TupleDict`; it is not zero-filled (the kernel zero-writes experts with no tokens). The descriptor workspace is an uninitialized output.
   - `grouped_gemm_wgrad_wrapper_sm100` dispatches JAX inputs with `sfa_tensor` to it before the memo.
3. `grouped_call`'s `backward` flag is renamed `zero_dprob`, since wgrad is a backward op that zeroes nothing.

## Why

TE's JAX MoE (`jberchtold/rubin-gmm-fusion`) already calls `grouped_gemm_glu_wrapper_sm100` / `grouped_gemm_dglu_wrapper_sm100` with JAX arrays. wgrad completes the MXFP8 MoE backward set. BF16 and NVFP4 variants, and the remaining grouped ops (dSReLU, SReLU, quant, glu_hadamard), are follow-ups.

## Related issues

Follow-up to #1275 / #1399.

## API and compatibility impact

- No new exports; the API index is unchanged. Both JAX entries gain keyword-only parameters. `grouped_gemm_dglu_jax_sm100`'s `b_ptrs`, `n`, `prob_tensor` and `grouped_gemm_wgrad_jax_sm100`'s `wgrad_ptrs` become optional in the signature; BF16 mode still requires them.
- `grouped_gemm_dglu_wrapper_sm100` and `grouped_gemm_wgrad_wrapper_sm100` with canonical MXFP8 JAX inputs now run instead of raising. They require `sf_vec_size=32`. Unsupported options raise `ValueError` naming the option (dGLU: dbias, deterministic, dynamic scheduling, dSiTU-GLU, rounding to input dtype; wgrad: discrete output, caller `wgrad_tensor`, `accumulate_on_output`, `TensorRagged`, global scales, FP4, `sf_fp8_dtype_override`).
- `GroupedGemmWgradSm100` (class API) stays torch-only for block-scaled inputs; its error now points to the wrapper/entry.
- No deprecations.
