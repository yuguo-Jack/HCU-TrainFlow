## Summary

The NVFP4 QAT backward's Triton route uses 64x64 tiles, 8 warps and 2 / 3 stages only for noncausal graphs on cc 10.0 (`optimized_sm100`). Every other supported part, cc 10.3 included, uses 32x32 tiles, 4 warps and 3 / 3 stages. On a B300 the 64x64 launch is about 2x faster, with bitwise-identical gradients, so this PR applies it to cc 10.3 as well. Causal graphs and the SM120 parts keep the 32x32 launch.

Changes:

- `sdpa/bwd/qat/api.py`: `capability in ((10, 0), (10, 3))` instead of `== (10, 0)`.
- The docs sentence about the launch.
- A metadata-only test pinning the launch tuple on modeled cc 10.0 / 10.3 / 10.3 causal / 12.0.

This is independent of #2102, which admits cc 10.3 to the FROST backend. With #2102, `auto` selects FROST on cc 10.3 for the declarations FROST serves, and Triton remains the route for the rest (B > 1, causal, lengths not divisible by 256) and for `backend="triton"`.

## Why

The tile choice was tuned on cc 10.0 only. cc 10.3 runs the same Triton kernels and gains the same way.

## Related issues

None found.

## API and compatibility impact

None. Same outputs (bitwise on the measured cases), same workspace; only the Triton launch configuration on cc 10.3 changes.

## Testing

B300 (cc 10.3), develop `64ed3dfe`, torch 2.14.1+cu130, Triton 3.8.0. Both launch configurations were run on the same inputs (B1, D128, BF16, noncausal, `backend="triton"`), using `benchmark_backends.py`'s inputs and timing: three backwards per CUDA graph, five ABBA / BAAB rounds, median.

| Heads | Sequence | 32x32 ms (develop) | 64x64 ms (this PR) | Speedup | dQ / dK / dV |
|---|---|---|---|---|---|
| 3 | 8192 | 1.9382 | 0.9818 | 1.97x | bitwise equal |
| 3 | 32768 | 26.4785 | 13.3132 | 1.99x | bitwise equal |
| 12 | 8192 | 6.7415 | 3.4610 | 1.95x | bitwise equal |
| 12 | 32768 | 102.0098 | 49.8046 | 2.05x | bitwise equal |

`python -m pytest sdpa/cutedsl/test_nvfp4_attention_qat_backward.py sdpa/cutedsl/test_nvfp4_attention_qat_dispatch.py` on this branch (B300): 18 passed, 11 skipped. The skipped cases are the FROST ones, which decline cc 10.3 on develop (#2102 admits it), so the Triton backward cases ran the 64x64 launch on cc 10.3. The new `test_triton_launch_config_per_part` pins the launch tuple for modeled cc 10.0, 10.3, 10.3 causal and 12.0.

Not run on cc 10.0, where the launch is unchanged.
