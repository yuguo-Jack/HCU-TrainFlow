# Keep indexed graph execution independent of shared plan selection

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1806) · state: closed · merged: True

## Original PR description

Overlapping `execute_plan_at_index()` calls on a prebuilt graph can execute the wrong Python plan. The implementation temporarily changed the graph's selected index before binding and restored it afterward; another caller could overwrite that index in between. The final restored selection could also be wrong.

Keep the requested index local through the common execution path. Indexed backend execution also uses the same prepared ordered-binding path as ordinary execution. Public signatures, plan creation, kernel selection and kernel code are unchanged. This fixes execution of prebuilt plans; it does not make concurrent planning or shared caller-owned handles safe.

Validation:

- Added a deterministic CPU regression using two coordinated callers and the existing fake-engine dispatch fixture. The baseline executes both wrong plans; the change executes each requested plan and preserves the graph's selection.
- CPU dispatch suite: **75 passed**.
- Existing SM100 binding, workspace and normalization suites: **77 passed / 1 skipped**, covering both backend and FROST, fresh buffers, overrides, changed workspace/streams and CUDA Graph replay.
- Measured warm CPU submission and GPU replay for both providers, mapping/ordered bindings and default/indexed execution with an ABBA control. This is component validation, not a serving throughput claim.
- Scoped formatting and license hooks pass. The regression has no heuristic-order or timing golden.
