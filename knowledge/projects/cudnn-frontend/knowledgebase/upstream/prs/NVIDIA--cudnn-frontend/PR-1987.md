## Affected area

FE OSS kernels or CuTeDSL

## Summary

`FrostSdpaBwdEngine`, `FrostNormFwdEngine` and `FrostNormBwdEngine` JIT-compile in `build_plans()`, but they inherited `BaseEngine`'s empty `behavior_notes`. So `deselect_behavior_notes([RUNTIME_COMPILATION])` kept their plans. All three now declare `RUNTIME_COMPILATION`, the same as every other python engine (SDPA forward, GEMM, conv, linear attention).

## Why

Review on #1962 found this. #1962 made more SDPA backward rows default-offered, so a caller who excludes runtime compilation could still get a backward plan that JIT-compiles.

## Related issues

Follow-up to #1962. The other #1962 review finding (SM80 staging copies) is tracked separately in #1986.

## API and compatibility impact

`get_behavior_notes_for_plan_at_index` now reports `RUNTIME_COMPILATION` for these plans, and the note filters treat them like every other python plan. Nothing changes for callers who don't filter on notes.

## Testing

- New `test_every_manifest_engine_declares_runtime_compilation` (`test/python/core/test_dispatch.py`) instantiates every engine of every manifest family, opt-in ones included. It fails on develop, listing every SDPA backward row, and passes with this change.
- `pytest -m "" core sdpa/frost/test_sdpa_bwd_heuristics.py norm`: 6196 passed, 6 failed. The 6 failures fail identically on develop on this host: two `test_knob_vocabulary` cases, `test_kernel_cache`, the two native norm-lowering tests, and one norm thread-safety case.
