## Affected area

FE OSS kernels or CuTeDSL

## Summary

Three fixes in the fused RMSNorm + RHT + amax kernel (`python/cudnn/rmsnorm_rht_amax/`):

1. The per-row reduction slots in shared memory were reused by the next row with nothing ordering the previous row's
   reads first. They are now double-buffered by row parity, with no added barrier.
2. Row offsets were 32-bit, so `M * N > 2^31` faulted with an illegal address. Rows are now addressed through a 64-bit
   element offset.
3. `check_support` admitted an `N` whose row tile does not fit in shared memory, and the launch then failed. It now
   declines such an `N`.

Adds an L0 test for the shared-memory bound and an L1 test for rows past element 2^31.

## Why

**1. Reduction slots (wrong output).** Each row of a CTA's `rows_per_cta` rows does:

```python
if lane_id == 0:
    reduction_buffer[0, warp_id] = warp_sum      # write this row's partial
cute.arch.barrier()
if lane_id < cfg.warps_per_row:
    block_val = reduction_buffer[0, lane_id]     # every warp reads every slot
```

Nothing orders a warp's reads of row r before another warp's write of row r + 1: a warp that finishes its reads can run
the next row and overwrite its slot while a slower warp is still reading row r. The slow warp then normalizes row r with
part of row r + 1's sum of squares. compute-sanitizer racecheck reports it without any timing change (M=64, N=8192,
rows_per_cta=8, num_threads=512): develop 7 hazards, this PR 0. With a legal delay injected on warp 1 right after the
barrier (20 x `nanosleep 100000`), M=1184, N=8192, rows_per_cta=8, num_threads=512, rows alternating x1 / x64 in
magnitude, 3 runs: develop 3108 wrong rows and 444 wrong CTA amax values (max error 15.2); this PR 0 and 0. Without a
delay neither tree produced a wrong row.

The slots are now `(2, warps_per_row)` and row r uses slot `r % 2` (`row_idx` is a compile-time loop index). Row r + 2
reuses row r's slots; every warp has read them before it arrives at row r + 1's barrier, and no warp writes row r + 2's
partial before that barrier completes. This adds `warps_per_row * 4` bytes of shared memory and no barrier.

**2. 32-bit row offset (illegal address).** Rows were addressed with `cute.local_tile(m_x, (1, n), (row, 0))` over a
tensor whose row count is a 32-bit symbol, so `row * n` was computed in 32 bits. At N=32768 and M=65544 the rows from
65536 on fault (`CUDA_ERROR_ILLEGAL_ADDRESS`). A helper now forms `Int64(row) * n` (with the 16-byte alignment the 128-bit
copies need asserted) and builds the `(1, n)` row view from it; `check_support` already requires X and O to be compact
row-major. With the fix, M=65544 x N=32768 and M=131072 x N=16384 match the reference on every row.

**3. Shared memory not checked.** The CTA holds one bf16 row tile, so the shared memory request grows with N. N=131072
requested 262,528 bytes against B200's 232,448-byte per-block opt-in limit, and the launch failed. `check_support` now
compares the kernel's request (`RMSNormRHTAmaxKernel.smem_bytes_for`, which the kernel also uses) with
`shared_memory_per_block_optin` of the tensors' device and raises `ValueError` above it. N=65536 and N=98304 still pass.
