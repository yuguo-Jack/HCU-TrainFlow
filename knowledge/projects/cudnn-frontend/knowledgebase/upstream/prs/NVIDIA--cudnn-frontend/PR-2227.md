# feat(frost-gemm): fuse row gather into matmul operand loading

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2227) · state: open · merged: False

## Original PR description

## Summary

Add a Python graph `gather` node and lower the supported `gather -> matmul` pattern directly into the existing SM100 grouped gather operand loader. No selected-row tensor is materialized.

```python
# cache: [T, K], indices: [B, H, S], weight: [B, H, K, N]
selected = graph.gather(cache, indices, axis=0)
y = graph.matmul(selected, weight).set_output(True)
# y: [B, H, S, N]
```

The graph operation replaces the chosen input axis with `indices.shape`, preserves the input dtype, and defines **negative and out-of-range indices as zero-filled rows**, not negative-index wrapping. It is Python-only; there is no cuDNN backend gather lowering in this change.

### Implementation

- Keep logical gather semantics separate from zero-copy ABI/storage views.
- Reuse the existing MoE gather loader and grouped scheduler, with compile-time uniform group boundaries `[g*S, (g+1)*S)`. No offset tensor or offset-generation pass is required for this route.
- Share checked `OperandView.apply` between dense recipes and this grouped binding path. Runtime binding validates fixed shapes, dtype/device, writable layout and output/input aliasing; no tensor conversion or materializing reshape is performed.
- Compile the unused offset operand as `None`, retaining the original explicit-offset path for ordinary MoE gather.

### Initial supported lowering

- One direct gather of an unbatched rank-2 `[T,K]` source along axis `0`/`-2`, consumed as matmul **A**; the gather output must be virtual.
- Contiguous INT32 indices `[... ,S]`, allowing arbitrary positive batch-prefix rank; fixed geometry fitting Int32.
- Matching FP16/BF16 source and weight. Weight batch prefix either matches the index prefix or broadcasts wholly via singleton dimensions. Existing graph matmul equal-rank rules remain unchanged.
- Existing supported non-swapped SM100 grouped-gather configurations; ordinary layout/toolchain/resource gates still apply.

B-side gather, other gather axes, batched source caches, partial batch broadcasting, surrounding pointwise/view chains and dynamic geometry are deliberately declined rather than materialized. This is **not** a complete DSA attention implementation and makes no GPU speedup claim. Existing scheduler/workspace initialization is still part of the plan; avoiding gather materialization does not imply a single launch or zero workspace.


**858 passed, 587 skipped.** Includes host lowering/contract tests and actual Torch/native-slot ABI projection checks. The FP16/BF16 Hopper helper probes execute the existing indirect row-index helper and loader range guard, checking duplicate/invalid indices and changed-input CUDA graph replay. They do **not** qualify the full SM100 GEMM pipeline.

Separately cross-compiled four complete rendered gather kernels (FP16/BF16, uniform boundaries and the retained explicit-offset specialization) on H20 with an explicit `sm_100a` compile target; all produced PTX with `.target sm_100a`. These were **not executed**.

The new full SM100/SM103 GEMM tests cover direct compiled-plan and public graph execution, batch/weight broadcast, K tails and changed-input/same-input capture replay, but are skipped locally because no Blackwell device is available. Please run the GEMM/FROST Blackwell CI before considering this draft ready.
