# gemm(cutedsl): decline cc 12.x in the tcgen05 GEMM architecture gates

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/2166) · state: closed · merged: True

## Original PR description

## Problem

The CuTe DSL GEMM APIs under `python/cudnn/gemm/cutedsl` (dense amax / swiglu / proj-rope, discrete-grouped swiglu, and the grouped glu / dglu / srelu / dsrelu / dswiglu / quant / unfused / wgrad / glu-hadamard families, plus the four grouped JAX entry points) all gate on `compute_capability < 100`, or `major < 10` in the JAX ones. Their kernels are SM100-family tcgen05 kernels, but a cc 12.x part (RTX / workstation Blackwell) reports a major above 10. So on cc 12.x `check_support()` returns True and the failure only shows up when the kernel is built.

Evidence on a B300 (no cc 12.x part needed):

- **The gate admits cc 12.0.** With `GemmAmaxSm100`'s capability query patched to return `(12, 0)`, `check_support()` returns True.
- **The kernel cannot build for cc 12.x.** I compiled the same `GemmAmaxSm100` case natively with `CUTE_DSL_KEEP=ptx` and assembled the kept PTX with ptxas (CUDA 13.3; `.version` lowered from 9.4 to 9.3 for that ptxas):
  - `-arch=sm_100a` and `-arch=sm_103a` assemble.
  - `-arch=sm_120a` fails: `Instruction 'tcgen05.mma' not supported on .target 'sm_120a'`, together with `tcgen05.cp`, `tcgen05.commit`, `.cta_group::1` and `.block32`.
  - `-arch=sm_121a` fails the same way.

## Change

- New `cudnn.tensor_adapter.has_tcgen05(major)`, next to `get_compute_capability`: `major >= 10 and major != 12`.
- All 24 gates in `gemm/cutedsl` call it in place of the bare threshold, and their messages say "with tcgen05 (not cc 12.x)". The exception types are unchanged.
- cc 10.x, including 10.7, and 11.x are admitted exactly as before. Nothing here changes behaviour on a supported part.

cc 11.0 is left alone. For what it is worth, the same `GemmAmaxSm100` PTX also fails `-arch=sm_110a`, but on `redux.f32` rather than tcgen05, so whether 11.0 should be admitted is a per-kernel question I have not looked into.

## Tests

New L0 file `test/python/gemm/cutedsl/test_gemm_cutedsl_arch_gate.py`:

- the `has_tcgen05` truth table for majors 8 to 12;
- a source check that no file under `gemm/cutedsl` still gates on a bare `< 100` / `major < 10` threshold, and that at least 24 files call `has_tcgen05(major)`;
- with the capability patched to `(12, 0)`, `GemmAmaxSm100.check_support()` raises the gate's `RuntimeError`.

On a B300, all 7 cases fail on develop (`DID NOT RAISE RuntimeError` for the last one) and pass with this change.

With this change, the full `test/python/gemm/cutedsl` at `-m "L0 or L1"` on the B300 gives 2735 passed, 1844 skipped, 0 failed.
