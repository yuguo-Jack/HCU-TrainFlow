# test: allow shared reduction tails in FP8 fold checks

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1871) · state: closed · merged: True

## Original PR description

The fold pair dispatch is uniform within a CTA, so its operand paths can share the amax reduction, barrier, and atomic instruction site. Allow shared or separate static sites while retaining the vectorized-load, no-spill, and nonzero reduction checks.

Add a direct regression with distinct A/B partials, scales, output tensors, and amax destinations. Compare both quantized outputs and pre-quantization maxima against an independent reference, including a changed-input rerun.

**Check barrier dominance for each reduction tail.**

One shared barrier is correct when both reduction arms converge before the barrier and that barrier dominates both lane-0 reduction reads. The current global `BAR` count also accepts separate tails where one arm has no barrier. The runtime test may pass when scheduling orders the stores before the read, so it does not deterministically detect this lowering regression.

Extend the SASS check to analyze control flow per reduction tail. Require a dominating CTA barrier for each separate tail, while allowing one barrier for a converged shared tail. This is a test-coverage improvement; the current lowering is not shown to be incorrect. The check requires more than a count-based assertion, but it would protect a synchronization-sensitive kernel path.
