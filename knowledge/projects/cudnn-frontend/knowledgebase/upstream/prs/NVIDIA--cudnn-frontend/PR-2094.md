## Affected area

## Summary

New generated placement entries for four SM100 (cc 10.0) bf16 classes that the latest Blackwell nightly showed default dispatch losing. Each class has an on-tile and an off-tile entry.

| Class | Rule | Nightly default today (geomean / max regret) |
|---|---|---|
| paged d512 decode, one KV head (DSv4-style MLA) | FROST past a cost threshold | 3.83 / 13.1 |
| paged d512 context (THD Q, bottom-right causal) | FROST once the KV per request is ≥ 512 (off the tile: past a cost threshold) | 2.62 / 3.06 |
| paged d256 context | same as d512 context | 1.69 / 2.02 |
| dense D576×512 decode | FROST past a cost threshold; off the tile, past ~313 query rows | 2.44 / 6.54 |

Two generator features join `cost` and `tiles`. Each is used only because a class's data was monotone in it and in neither existing scalar:
- **`rows` = log2(b · h_q · s_q).** Dense D576 decode off the 128-key tile cannot split KV, and the unsplit tile runs every head of a request. FROST loses up to 256 query rows (1.13–16×) and wins from 384 (0.41–0.90), for any b / h_q split.
- **`kv` = log2(S_kv per request).** In short-KV paged prefill the kernel's fixed cost dominates. FROST loses at KV 128 (1.0–1.7×) even for q = 16, and wins 3–6× at KV 4096.

The class key gains one group value, `gqa_unpacked`: a decode-shaped (s_q ≤ 4) GQA graph the forward row cannot pack, decided by the row's own `heuristics._pack_gqa_group`. Paged d512 decode at G = 12/24/48/96 does not pack (the group does not divide the 128-row tile); each query head re-reads K/V, and FROST ran 5–21× slower there while packed groups won 2–6×. Partial packers stay in the packed class: D576 packs 32 of 96, and d256's decode tile packs the whole group. Every existing entry regenerates unchanged under the new key and features.

## Why

Default dispatch on these shapes picked the backend, leaving 1.7–3.8× on the table across 108 gb200 nightly cases.

### Method

The per-family grids, holdouts and scripts are on internal scratch; the sizes are below.
- **Train grids** were frozen (sha256) before timing and are wider than the nightly shapes: h_q 8–128, b 1–128, S_kv 16–128k, page 16/32/64, KV fill 0.25–1, q 1 and 16–8192.
- **Gap and extreme cells:**
  - 70 off-tile cells, so every class has a measured off-tile twin.
  - 18 cells at 384–768 query rows, so the `rows` threshold is not a midpoint across a gap.
  - 96 short-prefill cells. An `always` fitted on 512+ prefills also claimed q = KV = 16, where FROST is 2× slower.
- **Holdouts** were frozen before fitting, drawn off the training lattice (head counts 12–96, odd batches, off-tile lengths), and scored once at the frozen head.
- **The first d512 decode holdout failed:** the unpacked GQA regime above. After the key change, a fresh holdout (holdout6) was frozen before the change and scored once.
- **Parts and backend:** cuDNN 9.29.0.17, the nightly's build. The main grids are on a full-power B200. The d512 decode grid, the off-tile, gap and short-KV cells, and the d512 decode holdouts are on a cc 10.0 B100 (850 W). The d512 decode threshold fitted on B100 scores regret 1.002 on the B200 grid.

### Results

Regret = chosen ÷ faster provider. The parent is develop, which routes all of these to the backend. A changed route is a case the table now sends to FROST.

|---|---|---|---|---|---|
| paged d512 decode (holdout6) | 40 | 1.786 / 8.93 | 1.000 / 1.000 | 18 | 0 |
| paged d512 context | 32 | 2.647 / 6.74 | 1.111 / 6.74 | 28 | 0 |

The context residuals are short-KV cases the conservative `kv ≥ 512` threshold leaves on the backend. FROST wins some of them at KV 256, but leading there would make a few cases 8–11% slower than the parent.
