# docs: op APIs live in cudnn.ops

[Upstream PR](https://github.com/NVIDIA/cudnn-frontend/pull/1655) · state: open · merged: False

## Original PR description

Updates the naming convention per the 2026-10-13 frontend v1 sync-up (Yang's proposal, agreed with Anerudhan): op functions move from the top-level `cudnn` package to `cudnn.ops`.

```
cudnn.ops.<op_name>_<direction>               # PyTorch
cudnn.ops.<op_name>_<direction>_jax           # JAX
cudnn.ops.<op_name>_<direction>_standalone    # no framework
```

- `docs/fe-oss-apis/api_conventions.md`: new pattern; ops are imperative (forward and backward are separate calls); rule 5 now says ops live in `cudnn.ops`, not the top-level package, `cudnn.torch`, `cudnn.jax`, or an op package. The examples use `cudnn.ops.…`. The grouped GEMM examples use unified GLU instead of the legacy SwiGLU, and one row shows today's `cudnn.ops.causal_conv1d` becoming `cudnn.ops.causal_conv1d_forward`.
- `AGENTS.md`, `python/cudnn/AGENTS.md`, and the cutedsl integration skill: new ops are exported through `_LAZY_EXPORTS` in `python/cudnn/ops/__init__.py` instead of `_LAZY_OPTIONAL_IMPORTS` in `python/cudnn/__init__.py`. `cudnn.ops` is in the API index module list, so new ops are tracked by the index automatically.

`cudnn.ops` already exports nine names (the causal_conv1d family and NVFP4 quantize/dequantize). New names end in `_forward`/`_backward`, so they do not collide with them; the existing ones are aliased and deprecated through the PIC sign-off process like every other existing API.

Docs only.
