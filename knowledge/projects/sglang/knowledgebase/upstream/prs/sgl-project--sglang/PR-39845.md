# [Feat] hicache: opt-in exclusive L2->L3 tiering, dedup cache-mode L3 writes through the existence cache

[Upstream PR](https://github.com/sgl-project/sglang/pull/39845) · state: open · merged: False

## Original PR description

## Motivation

With `--hicache-storage-backend` in cache mode, storage (L3) is written at L2 admission: every page that enters the host pool is also written to storage. L3 therefore always holds a superset of L2 and adds no reusable capacity. A prefix that is evicted from host is only in L3 if its write happened to complete, and a prefix that is still in host is fetched from host anyway. On a Mooncake store shared by several prefill workers this showed up as a store that turns over constantly (every L2 admission is a put) while the hit rate does not move.

This PR adds an opt-in mode where L3 is written from the coldest host pages ahead of their eviction instead. The two tiers then hold different pages and L3 becomes an overflow layer for L2. Measured on Qwen3.5-397B-A17B-NVFP4, GB300, 3P:2D PD-disaggregated, AgentX closed-loop trace at concurrency 1000: 142.2K total TPS/GPU without a store, 152.2K with the store in this mode (+7%); host hit rate held at 93.1%. At concurrency 850, where the host pool alone already covers the working set, the extra write traffic costs about 1.5%, which is why the mode is opt-in.

The second commit fixes write-side dedup in cache mode. A recompute after L2 eviction re-creates a node with `backuped=False`, so the node flag alone re-writes content that L3 already holds. `write_backup_storage` now skips spans the `StorageExistenceCache` covers, and beliefs are recorded on the storage ack from the full hash chain (not the `completed_tokens`-truncated one) so ranks cannot diverge in the write/skip decision. The cost of that choice is that a failed write still records the pages as stored until a prefetch miss invalidates the belief; `test_hicache_l3_failed_write_still_records_belief` pins this behavior down.

## Modifications

Commit 1, `SGLANG_HICACHE_L3_WRITE_ON_HOST_EVICT` (default off):

- `unified_cache/components/full.py`: the host-eviction heap walk is one generator (`_host_eviction_walk`) shared by `drive_host_eviction` and the new read-only `peek_host_eviction_candidates(num_tokens)`, which returns host leaves in eviction order until `num_tokens` are covered. `_is_host_leaf` gains `ignore_children` so the simulation reuses the same predicate. The Rust adapter raises `NotImplementedError`; the mode requires the Python tree core.
- `unified_radix_cache.py`: when the mode is on, the L2-admission storage write is skipped and `_write_behind_host_tail` runs on the `check_hicache_events` path (every 4th call, rank-replicated inputs only). It keeps `SGLANG_HICACHE_L3_EVICT_WRITE_RESERVE_FRACTION` (default 0.05) of the host pool either free, in flight, or already in storage. Candidates the existence cache already covers count as covered until host eviction consumes them, so a steady state with a fully tiered tail does not re-walk the heap; `reset()` clears both the in-flight map and that clean-tail count. Counters: `wb_walks`, `wb_issued_tokens`, `wb_clean_tokens`, `wb_unbacked_tokens` via `prefetch_outcome_stats_snapshot`.
- Enabling the mode with `--hicache-host-memory-mode buffer_only` or the Rust tree core raises `ValueError` at init.
- `write_backup_storage` returns the operation id.

Commit 2, existence-cache dedup in cache mode:

- `write_backup_storage` skips spans covered by `storage_existence_cache`.
- The prefetch-cut belief invalidation runs in both host memory modes (was buffer_only-only).
- Beliefs are added on the storage ack from `operation.hash_value` unconditionally.
- New unit test `test_hicache_l3_failed_write_still_records_belief`.

[by Claude Code] **Severity: perf | Confidence: Medium**

**Issue**

Cache mode never records beliefs for pages fetched from L3. `_handle_prefetch_result` inserts them with `insert_host` but does not call `storage_existence_cache.add`. When one of these nodes later reaches the LRU tail, this check misses and `write_backup_storage` writes the same pages back to L3. Buffer mode already records beliefs for fetched pages in `stage_completed_prefetch` ("the fetch itself is the evidence").

**Example**

A request hits a prefix in L3, the prefetch loads it into host, and that host copy later goes cold. With `SGLANG_HICACHE_L3_WRITE_ON_HOST_EVICT=1`, the write-behind walk re-puts every one of those pages. That is the write churn this mode is meant to remove.

**Fix**

After a successful `insert_host` in `_handle_prefetch_result`, call `self.storage_existence_cache.add(PoolName.KV, hash_value[: completed_tokens // self.page_size])`. `completed_tokens` is already the same on every rank at that point.
