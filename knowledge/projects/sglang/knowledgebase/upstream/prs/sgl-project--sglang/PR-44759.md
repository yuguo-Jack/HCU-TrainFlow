# [Perf] pythonic: Resume streaming bracket matching instead of rescanning the buffer

[Upstream PR](https://github.com/sgl-project/sglang/pull/44759) · state: open · merged: False

## Original PR description

## Motivation

`PythonicDetector.parse_streaming_increment` calls `_find_matching_bracket` on every chunk, and it walks the whole buffered call in a Python loop each time. Streaming one long call, such as a `write_file` with a 16 KB file, is quadratic: about 420 ms of CPU per call on top of the final parse.

## Modifications

`_find_matching_bracket` stores the text it scanned without finding the closing bracket, plus the bracket depth at its end. On the next chunk it resumes after that text if the buffer still starts with it. Otherwise it rescans from the start, for example when stripping a special token changed the buffer. Matching rules are unchanged.

Two tests: streaming a nested call in 1, 2 and 3 character chunks, and the case where stripping rewrites the buffered prefix.

## Accuracy Tests

No model output changes. A differential test against the previous detector compared `normal_text`, calls and the buffer after every chunk over 70,000 random streams (about 430,000 chunks): nested brackets, brackets, quotes and escapes in strings, multiple calls, truncated input, special tokens and random chunk sizes. All matched. Pythonic tests in `test_function_call_parser.py` pass; the 15 DeepSeek V3.2/V4 failures in that file locally are the same on main (missing triton on CPU).

## Speed Tests and Profiling

CPU only, Llama 3 tokenizer, one `write_file` call streamed one token per chunk, 7 alternating fresh processes per side, median:

| Content | Before | After | Speedup |
|---|---|---|---|
| 2 KB | 13.1 ms | 5.6 ms | 2.3x |
| 4 KB | 46.6 ms | 11.9 ms | 3.9x |
| 8 KB | 159.1 ms | 25.6 ms | 6.2x |
| 16 KB | 668.7 ms | 273.9 ms | 2.4x |

At 16 KB most of the remaining time is the `tool_call_regex` search in `detect_and_parse` on the last chunk, which #18397 and #32107 cover. #44505 and #38869 change the same function to skip brackets inside strings; whichever lands second needs a small rebase, and the cache would then also carry the string state.
