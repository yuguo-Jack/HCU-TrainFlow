# [Perf] kv-cache: Reduce gather padding for shared prefixes

[Upstream PR](https://github.com/sgl-project/sglang/pull/45157) · state: open · merged: False

## Original PR description

## Motivation

Fixes #45155. Shared prefix pages are deduplicated, but the per-rank gather block still sums each request's prefix bound, so padding is copied and communicated at every layer.

## Modifications

Cap the existing bound with `ceil(Kmax / N) + U - Kmax`, where `U` is the unique prefix-page count and `Kmax` the longest prefix. The remaining unique pages are conservatively allowed to belong to one rank. This reuses existing metadata without another host synchronization or collective. Add shared/nested-prefix, skewed-owner and multi-GPU regression coverage.

## Accuracy Tests

- `test_page_interleave_shard.py`: 78 passed, 415 subtests passed; four-GPU case skipped on the two-GPU host.
- 24,600 greedy first-token outputs match baseline; 820 sampled output/top-10 logprob checks match exactly across page sizes 4/16/32/64/128.
- Ruff lint/format, isort and `git diff --check` pass.

## Speed Tests and Profiling

Qwen3-32B BF16, 2×H100, TP2/CP2, FA3, YaRN 4×, eight requests sharing a cached prefix and adding 128 input tokens each. Base: `7c99ace127`. Per page size: ABBA server runs, 15 warmup + 30 timed batches per case/run. Metric: median batch maximum of server `e2e_latency`.

| Page size | 32K latency reduction | 64K | 120K |
| --- | ---: | ---: | ---: |
| 4 | 15.2% | 21.9% | 27.7% |
| 16 | 15.8% | 22.2% | 27.8% |
| 32 | 15.7% | 22.1% | 27.7% |
| 64 | 16.0% | 22.8% | 28.0% |
| 128 | 19.4% | 27.9% | 31.9% |

At page 64, 120K improves from 1,020 to 734 ms. Single-request/unshared-prefix control medians change by at most 1.3%; isolated tail spikes remain.

These are synthetic cached-prefix prefill measurements with real weights/NCCL, fake P/D transfer and an identical benchmark-only cache-insertion hook on both variants. They do not measure decode or full P/D performance.
