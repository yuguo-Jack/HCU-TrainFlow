## Motivation

On gfx950, GLM-5.2 decode and MTP verify with 48 rows or fewer go through the four-kernel fused DSA indexer (#38583). Two of its kernels can do less work:

- **Logits.** With MTP, each request contributes 6 verify rows. All 6 read the same KV pages, but `logits_hist_m` loads every page once per row.
- **Top-k.** `topk_transform` runs 64 blocks per row. Fewer blocks per row lets the grid stay co-resident for its persistent-rank form.

The whole fused-indexer call (4 kernels) gets 1.20x to 1.36x faster, depending on the context mix. End to end at 120k context, median ITL improves 1.8%. Logits are bit-identical and the selected top-k sets are unchanged.

## Modifications

**`paged_mqa_logits.cuh`** now ships three logits kernels. `PagedMqaLogitsKernel::run` takes a new `variant` argument that picks one.

| variant | kernel | used for |
|---|---|---|
| 0 | `logits_hist_m` (unchanged from main) | per-row; 25+ rows that are not 6-row MTP groups |
| 1 | `logits_hist_s` (new, per-row) | 24 rows or fewer |
| 2 | `logits_hist_grp<16, 12, 6>` (new) | 30 to 48 rows that come 6 per request |

- `logits_hist_s` is tuned for short batches:
  - page ids are preloaded one per lane;
  - each page is addressed through a buffer resource;
  - the fine-histogram flush starts at the lowest bin that node 4 can read;
  - when the grid needs more than one round of resident blocks, the longest rows are dispatched first.
- `logits_hist_grp` loads each K page shared by a request's 6 consecutive rows once per group, then scores it for every row of the group.
  - The page loads are shared only after the kernel checks on the device that the siblings' page ids really match. A group whose page ids differ takes the general path, so the result is exact for any input.
  - The per-page math is `logits_hist_m`'s, so the logits are bit-identical.

**`topk_transform.cuh`**: `prank_fit_g` shrinks G to the largest value at or below the requested one that lets the persistent-rank form run, but no lower than 32. G only repartitions an exact selection, so the top-k set does not change. `TOPK_G` goes from 64 to 48.

**Host side.**
- `loader.logits_launch(rows, table_pages, rows_per_request)` returns `(blocks_per_row, variant)`.
- `_gfx950_fused_decode` passes `rows_per_request` as rows divided by batch size on TARGET_VERIFY, and 1 otherwise.
- Shapes are host constants, so every choice is CUDA-graph safe.
- Decode without MTP, other MTP draft counts, and rows that are not a multiple of 6 keep `logits_hist_m` at 25 rows and above.

**Tests** (`test/registered/amd/test_dsa_gfx950_fused_indexer.py`):
- the three variants give bit-identical logits and the same node-4 selection:
  - on 5- and 8-request verify batches from 4k to 300k tokens, with mixed lengths;
  - on grouped rows whose page tables differ;
- the `logits_launch` selection boundaries.

## Accuracy Tests

The logits are bit-identical to main's and the selection is unchanged, as covered by the unit tests above. Beyond those:
- **Whole call against main.** Main's four kernels and this PR's were run on the same inputs, for every case in the tables below plus graph-wide page tables. Every row's top-2048 slot set and every byte of the K written that step are identical.

## Speed Tests and Profiling

**Whole fused-indexer call, kernel level.** Measured on MI355X:
- inputs: 6 rows per request; each request's rows have lengths L+1..L+6; page table 16386 pages wide;
- one CUDA graph runs the call over 4 KV pools, and each sample is that replay divided by 4;
- medians in us.

| rows (requests) | contexts | main | this PR | speedup |
|---|---|---|---|---|
| 12 (2) | lognormal, median 180k, max 600k | 52.0 | 44.2 | 1.18x |
| 24 (4) | same | 88.0 | 72.5 | 1.21x |
| 36 (6) | same | 132.5 | 90.6 | 1.46x |
| 48 (8) | same | 167.4 | 114.3 | 1.46x |
| 12 / 24 / 30 / 36 / 42 / 48 | all 120k | 44.3 / 68.5 / 76.7 / 95.1 / 103.7 / 114.2 | 39.6 / 68.9 / 74.5 / 73.9 / 79.9 / 82.9 | 1.12 / 0.99 / 1.03 / 1.29 / 1.30 / 1.38x |

Weighted over a decode rank's batch distribution, the lognormal mix goes from 104.6 to 77.2 us (1.36x). Equal weights at 120k go from 83.3 to 69.7 us (1.20x).

**Logits kernel alone, and why three variants.** 6 rows per request, 120k tokens, us:

| rows | `logits_hist_m` | `logits_hist_s` | `logits_hist_grp` |
|---|---|---|---|
| 12 | 26.3 | **21.5** | 43.6 |
| 24 | 47.2 | **39.8** | 55.2 |
| 30 | 55.2 | 58.6 | **51.0** |
| 36 | 65.8 | 80.9 | **53.5** |
| 48 | 79.1 | 129.5 | **61.2** |

At 400k tokens and 24 rows, the grouped kernel wins (79.9 us against 120.4 for `logits_hist_m`). Below 30 rows the host still picks `logits_hist_s`, because shapes must be fixed at capture time and only short contexts make the grouped kernel lose.

**End to end.**
- Setup: GLM-5.2-MXFP4, TP8, MTP (EAGLE, 5 steps, 6 draft tokens), simulated acceptance 3.61, `--max-running-requests 8`.
- Benchmark: `bench_serving`, random 120k input / 1k output, concurrency 8, 16 prompts per run, 2 runs per server.
- Main and this PR alternate on one node, each in a fresh server.

| | median ITL ms |
|---|---|
| main (4 servers, 8 runs) | 5.06 - 5.10 |
| this PR (2 servers, 4 runs) | 4.96 - 5.00 |

**In-server kernels.** A torch-profiler capture of eager decode at 48 rows came from an earlier revision. In it, `topk_transform` runs 21 us against main's 32 us.

## How to reproduce

Hardware: MI355X (gfx950), ROCm 7.2. Image: `lmsysorg/sglang-rocm:v0.5.22-rocm720-mi35x-20261018`, whose four `dsa_gfx950/*.cuh` files and `hip_gfx950/loader.py` are byte-identical to main's. For the PR arm, this branch's files are copied over.

```bash
python3 test/registered/amd/test_dsa_gfx950_fused_indexer.py -v      # one gfx950 GPU
SGLANG_OPT_USE_TOPK_V2=true SGLANG_SIMULATE_ACC_LEN=3.61 SGLANG_SIMULATE_ACC_METHOD=match-expected \
SGLANG_SIMULATE_ACC_TOKEN_MODE=real-draft-token python3 -m sglang.launch_server --model-path amd/GLM-5.2-MXFP4 \
  --trust-remote-code --kv-cache-dtype fp8_e4m3 --dsa-prefill-backend triton --dsa-decode-backend triton \
  --mem-fraction-static 0.85 --speculative-algorithm EAGLE --speculative-num-steps 5 --speculative-eagle-topk 1 \
  --speculative-num-draft-tokens 6 --tensor-parallel-size 8 --max-running-requests 8 --cuda-graph-max-bs-decode 8
python3 -m sglang.bench_serving --backend sglang --dataset-name random --random-input-len 120000 \
  --random-output-len 1000 --random-range-ratio 1.0 --num-prompts 16 --max-concurrency 8 --seed 1
```

The kernel changes were found with an automated kernel-optimization search. This PR ports them onto main, restricts each kernel to the shapes where it measured faster, and adds the selection and tests.
