## Motivation

On ROCm 10.1 with torch 2.12+, torch.profiler collects no GPU events.
### root cause
PyTorch 2.12 switched kineto to rocprofiler-sdk, which tracks its registered client in an environment variable; PyTorch 2.11 used roctracer and never reads that variable.
The sglang parent process initializes HIP, which sets `ROCPROFILER_REGISTER_LIBRARY` in its environment, and every child process inherits that value.
The child process then believes a profiler is already registered, so it never registers its own, and `torch.profiler` reports
no GPU activity at all, no kernels, no HIP API calls, and no error.

## Modifications

gated by ```_is_hip (torch_built_with_hip())```, AMD specific.

## Speed Tests and Profiling

Both paths were tested on gfx1250, ROCm 10.1 / torch 2.12.

**Diffusion** — FLUX.2-dev 1024x1024, 6 steps:

```bash
SGLANG_DIFFUSION_PLATFORM_OVERRIDE=rocm ENABLE_CK=0 \
SGLANG_DIFFUSION_TORCH_PROFILER_DIR=$OUT \
sglang generate \
  --model-path $FLUX2_PATH \
  --prompt "A cinematic shot of a cute cat wearing a tiny astronaut helmet." \
  --num-gpus 1 --tp-size 1 --width 1024 --height 1024 \
  --num-inference-steps 6 --profile --num-profiled-timesteps 3
```

| trace category | before | after |
| --- | ---: | ---: |
| `kernel` | 0 | 5,331 |
| `cuda_runtime` | 0 | 9,533 |
| `ac2g` | 0 | 14,864 |
| `cpu_op` | 23,848 | 23,848 |

**LLM serving** — gpt-oss-120b-w-mxfp4-a-fp8, TP 1:

```bash
TRITON_HIP_USE_EXPERT_SCHEDULING=0 ENABLE_CK=0 \
SGLANG_TORCH_PROFILER_DIR=$OUT \
python3 -m sglang.launch_server \
  --model-path amd/gpt-oss-120b-w-mxfp4-a-fp8 \
  --tp 1 \
  --trust-remote-code \
  --max-running-requests 512 \
  --mem-fraction-static 0.9 \
  --attention-backend triton \
  --disable-radix-cache \
  --disable-cuda-graph \
  --port 8000

# with requests in flight, so there are forward steps to profile
python3 -m sglang.profiler --url http://127.0.0.1:8000 \
  --gpu --no-cpu --num-steps 5 --output-dir $OUT
```

@HaiShaw  thanks for review, addressed comments as follows:

**1. the `_is_hip` gate**

`is_hip()` can't be used here. it lives in `srt/utils/common.py`, which does `import torch` at module scope, so importing it means importing torch. `import torch` is exactly when the inherited value gets read, so popping after that is a no-op. 
`environ._default_hip()` has the same problem, it resolves lazily after torch is in.

so i kept `_is_hip` gate but without importing torch via `torch_built_with_hip()` 

**2. moving them out of `environ.py`**

moved both to `python/sglang/srt/debug_utils/rocprofiler_register.py`


**3. env name**

renamed to `SGLANG_ROCM_KEEP_INHERITED_ROCPROFILER_REGISTER`.
