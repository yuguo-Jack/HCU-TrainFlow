# [Fix] openai: enable xgrammar reasoning when thinking mode is active

[Upstream PR](https://github.com/sgl-project/sglang/pull/46000) · state: open · merged: False

## Original PR description

## Motivation

Fixes #36675.

`_process_messages` computed `xgrammar_reasoning = thinking_mode and (self.reasoning_parser is None)`, but `_get_reasoning_from_request()` returns `False` whenever no reasoning parser is configured. The two conjuncts are mutually exclusive, so `xgrammar_reasoning` was always `False`.

With no `--reasoning-parser`, a chat template that turns thinking on (for example Qwen3 `enable_thinking` default-on), a tool-call parser, and `tool_choice="required"`, the builtin xgrammar structural tag omitted the reasoning prefix and forced the model straight into a tool call while it was mid-thought — the opposite of what the adjacent comment says is intended.

When a reasoning parser *is* configured, `ReasonerGrammarBackend` still owns the reasoning prefix, so xgrammar tags must continue to describe only the post-reasoning tool-call suffix. That path is unchanged.

Assumption: "template thinking on" is read from `template_manager.reasoning_config` alone (toggle / special_case). Without that config there is no reliable toggle signal, so xgrammar reasoning stays off. Scheduler-side `require_reasoning` still requires a parser and stays `False` in the parserless case.

## Modifications

- `serving_chat.py`: extract the template-toggle evaluation into `_template_enables_reasoning()`, and gate `xgrammar_reasoning` on `reasoning_parser is None and _template_enables_reasoning(request)`. `_get_reasoning_from_request` / `require_reasoning` are unchanged for the no-parser early return and for parser-configured behavior.
- `test_serving_chat.py`: add `test_parserless_template_thinking_reaches_xgrammar_tag` (default-on / explicit on / explicit off). Existing `test_xgrammar_tag_omits_reasoning_when_parser_owns_it` still asserts `thinking_mode=False` when a parser owns the prefix.
