# Skip abandoned requests after encoder dispatch lock admission

[Upstream PR](https://github.com/sgl-project/sglang/pull/42075) · state: closed · merged: False

## Original PR description

## Motivation

An image/audio request can time out or be cancelled while its batch waits for `encode_dispatch_lock`, held by a health probe or direct encode. The scheduler checked request futures before waiting for that lock, then still broadcast and encoded the abandoned request after acquiring it. Timeout cleanup may have already run before any encoder state existed.

## Modifications

Recheck pending futures under the acquired dispatch lock, before constructing the TP broadcast and rank-0 batch. Skip an empty group and preserve the ordering of surviving requests and their results.

## Accuracy Tests

- Five new CPU cases fail on the original code and pass with this change: all abandoned, mixed live/abandoned entries in each position, and a real submit timeout followed by a successful live request. The complete scheduler test module passes all 19 cases.
- A separate actual-source probe exercises `EncoderScheduler` and `MMEncoder` acquisition, staging and release methods. Before the fix, an expired request is broadcast, encoded and left staged after its caller exits; afterward only the following live request reaches those stages. Model/preprocessing and transport boundaries are doubled with CPU tensors, and GPU-facing eager imports are excluded. This does not validate CUDA or distributed transport.
- Matching pre-commit checks pass. Independent agent review found no actionable issue.

## Speed Tests and Profiling

The regression verifies that abandoned requests cause no encode or TP broadcast calls after lock admission. No serving-throughput or GPU speed benchmark was performed.
