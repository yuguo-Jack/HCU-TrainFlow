# [Fix] MLA chunked-prefix MHA: convert base-2 LSE before natural-log merge_state

[Upstream PR](https://github.com/sgl-project/sglang/pull/46313) · state: open · merged: False

## Original PR description

## Motivation

`DeepseekV2AttentionMLA._chunked_prefix_attn_mha` (`models/deepseek_common/attention_forward_methods/forward_mha.py`) folds prefix-chunk attention into the extend-part attention using `merge_state` / `merge_state_v2`. Those functions expect **natural-log** LSE.

The LSE inputs come from two kernels:
- `flashinfer.prefill.trtllm_ragged_attention_deepseek(..., return_lse=True)` (trtllm_mla backend)
- `BatchPrefillWithRaggedKVCacheWrapper.forward_return_lse` (flashinfer MLA backend)

Both return **base-2** LSE, which is FlashInfer's convention. FlashInfer 0.7.x documents base 2 as the default and adds `lse_base="ln"` to `run()`. The merge therefore weights the partial outputs by `exp(ΔLSE)` instead of `2^ΔLSE`.

When it triggers:
- **trtllm_mla**, the default for DeepSeek-family models on SM100: every prefill that extends a radix-cache prefix (`handle_attention_trtllm_mla` → `MHA_CHUNKED_KV`). That covers multi-turn, agentic and RL-rollout traffic.
- **flashinfer:** prefix ≥ `SGLANG_CHUNKED_PREFIX_CACHE_THRESHOLD` and total tokens above the one-shot MHA capacity (128K).
- FA3/FA4 return natural-log LSE and are unaffected. FA4 was checked on B200.

## Modifications

- Add `lse_base2_to_natural()` to `layers/attention/merge_state.py`. It multiplies the returned LSE by ln 2 and passes non-tuple outputs (no LSE requested) through unchanged.
- Apply it exactly once, at the two MLA backend return sites:
  - `TRTLLMMLABackend` ragged prefill
  - `FlashInferMhaChunkKVRunner.forward`

## Accuracy Tests

**Kernel level.** SGLang's exact merge pattern, 16 heads, qk/v head dims 192/128, against an FP64 single-pass reference:

| kernel | prefix | max err before | max err after | bf16 rounding floor |
|---|---|---|---|---|
| flashinfer ragged | 4K | 4.5e-2 | 6.8e-4 | 4.2e-4 |
| trtllm ragged | 4K | 3.3e-2 | 5.7e-4 | 2.8e-4 |

**End to end.** DeepSeek-V2-Lite-Chat, TP1, B200. For each case, 512 suffix tokens are scored twice:
- **cold:** prefix+suffix with the radix cache flushed, a single pass with no merge;
- **warm:** prefix cached first, then prefix+suffix, which takes the chunked merge path.

Cells are mean |Δlogprob| between cold and warm / fraction of tokens with |exp(Δ)−1| > 0.2:

| backend / version | prefix | before | after | triton backend (reference) |
|---|---|---|---|---|
| trtllm_mla / 0.5.9, real text | 16K | 0.078 / 14.7% | 0.027 / 3.7% | 0.027 / 3.5% |
| trtllm_mla / 0.5.9, random tokens | 32K | 0.192 / 34.1% | 0.047 / 5.1% | 0.055 / 7.8% |
| flashinfer / 0.5.22, real text | 144K | 0.090 / 11.7% | 0.027 / 4.7% | 0.025 / 3.9% |

Cold scoring is bitwise deterministic and unaffected by the change. After the fix, the remaining cold/warm difference matches the ordinary kernel-to-kernel gap: cold trtllm vs cold triton is 0.064.

**New test:** `test/srt/test_mla_chunked_prefix_lse.py`.
- It pins the raw kernels' base-2 convention, so a future FlashInfer default change can't cause a silent double conversion.
- It checks the chunked merge against an FP64 reference for both kernels.
- With the fix the FlashInfer cases pass. Without it, 2 of the 3 FlashInfer cases fail; the convention-pinning case passes either way, as intended.
- The trtllm cases need SM100 and FlashInfer's trtllm-gen cubins. They ran on 0.5.9 + flashinfer-cubin 0.6.3, where they passed with the fix and failed without it.
