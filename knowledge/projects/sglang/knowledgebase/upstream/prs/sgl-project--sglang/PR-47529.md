# [Fix] RL: Fix crash when returning routed experts under DCP or KV sharding

[Upstream PR](https://github.com/sgl-project/sglang/pull/47529) · state: open · merged: False

## Original PR description

## Why?

With `--enable-return-routed-experts`, sglang saves each token's routed experts in a CPU buffer, one row per KV slot. The buffer is sized for one GPU's KV pool.

With DCP (decode context parallel) or KV sharding (`--enable-kv-cache-sharding`), KV slot numbers cover every GPU's pool. Slots past the first GPU's pool have no row, so the server crashes.

```text
Example: DCP 4, each GPU's KV pool holds 64 tokens

KV slots        0 ──────────────────────────────── 271   (4 GPUs' pools)
buffer before   0 ──── 67                                (1 GPU's pool)
                         └─ slot 68 → IndexError → server crashes
buffer after    0 ──────────────────────────────── 271
```

We hit this on Kimi-K3 with DCP16 during RL, about 20 minutes into the run.

## What?

- Make the buffer cover every KV slot the allocator can hand out:
  - no DCP, no KV sharding: unchanged
  - DCP: every DCP rank's pool
  - KV sharding: every shard's pool
- Only one function changes: `RunnerIds.capture_token_capacity`. The indexer top-k buffer uses it too, so it gets the same fix.
- The int16 buffer option that used to be in this PR is now #47833.

## Verification?

A new unit test fills the KV pool and checks that the buffer has exactly one row per slot:

```text
case            largest slot   rows before   rows after
no DCP               67             68            68
DCP 4               271             68 ✗         272
KV sharding 4       271             68 ✗         272     (observed, CPU)
```

## Test?
