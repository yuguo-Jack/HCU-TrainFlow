# [Perf] [AMD] GLM5: Fuse DSA indexer Hadamard and FP8 quant

[Upstream PR](https://github.com/sgl-project/sglang/pull/30715) · state: open · merged: False

## Original PR description

## Motivation

The DSA indexer issues many tiny per-layer kernels (qk-rmsnorm, rope+cache, fp8 quant, Hadamard, top-k). On gfx950 these run serially, so per-kernel launch overhead and the intermediate HBM round-trips dominate the indexer's wall-time. This fuses the query-side Hadamard + fp8 quant to cut a launch and a full bf16 round-trip.

Prefill kernel profile (GLM-5.2-MXFP4, MI355X TP4, EXTEND, conc4 8192/1024), query Hadamard + quant:

| | kernels | ms |
|---|---|---|
| fusion off | `fast_hadamard_transform` (query) + `act_quant_kernel` | ~12.0 |
| fusion on | `_hadamard_quant_kernel` | 4.4 |

## Modifications

Fuse the indexer query's **Hadamard transform + block FP8 quant** into a single Triton kernel (`fused_hadamard_act_quant`), replacing the two-pass `act_quant(rotate_activation(q))` which writes a bf16 tensor to HBM then reads it back. The fused kernel keeps the post-Hadamard row in registers and quantizes in place, removing one bf16 HBM round-trip of the query per layer.

On the decode path the same kernel also folds `_apply_q_scale_and_softmax_scale` (`weights * q_scale * softmax_scale`): the kernel already emits `q_scale` and the head-gate `weights` are row-aligned before the quant, so the per-(token,head) rescale is an extra output instead of a separate elementwise launch.

- Opt-in, shape-guarded: `SGLANG_DSA_FUSE_HADAMARD_QUANT=1`, gfx950, `head_dim == block_size == 128`; default off, two-pass path unchanged. Query-only.
- Hadamard = matmul vs the ±1 Sylvester matrix (fp32 accum) ×`1/sqrt(N)`, equivalent to `fast_hadamard_transform(x, scale=N**-0.5)`. Quant matches `act_quant` (group=128 absmax, e4m3fn + fp32 scale).
