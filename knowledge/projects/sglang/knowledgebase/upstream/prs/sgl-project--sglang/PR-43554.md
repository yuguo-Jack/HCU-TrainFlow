# [Docs] Let the Qwen3 B300 recipe use the default attention backend

[Upstream PR](https://github.com/sgl-project/sglang/pull/43554) · state: closed · merged: True

## Original PR description

## Motivation

The Qwen3 cookbook command generator forces FlashInfer for B300. This overrides the existing Blackwell MHA backend selection and slows the Qwen3-8B BF16 workload tested on GB300.

## Modifications

Remove the explicit `--attention-backend flashinfer` from the B300 command. Let runtime compatibility checks select the backend. On the tested GB300/Qwen3-8B configuration, argument resolution selects `trtllm_mha` with page size 64. The all-reduce option is retained.

## Accuracy Tests

Full held-out GSM8K, 1,314 cases plus five separate few-shot examples, non-thinking mode, temperature 0, top_p 1, seed 42, max_tokens 2048, concurrency 64. Exact case IDs and prompt hashes match. FlashInfer: 1197/1314; TRT MHA: 1201/1314. Both runs have zero request errors and no truncated responses. The candidate loses 8 previously correct answers and gains 12; this task-level check does not establish numerical equivalence.

## Speed Tests and Profiling

SGLang `e35f60b9bcb51045fd0602d8ed12cff8021c040f`, Qwen3-8B revision `b968826d9c46dd6066d109eabc6255188de91218`, one GB300, TP1, BF16, no speculative decoding or mixed chunking. Matched random ShareGPT-derived prompts with nominal 8192 input / 1024 output tokens, seed 42 and request_rate=inf. Per-request prompt hashes and actual input lengths match at every concurrency; all timed requests complete with 1024 output tokens. Warmup and cache flush precede timing; profiling is separate.

| Concurrency | FlashInfer output tok/s | TRT MHA output tok/s | Change |
|---:|---:|---:|---:|
| 4 | 794.99 | 896.50 | 12.8% |
| 8 | 1292.54 | 1458.84 | 12.9% |
| 16 | 1870.02 | 2120.51 | 13.4% |
| 32 | 2438.07 | 2679.98 | 9.9% |
| 64 | 2808.55 | 3079.07 | 9.6% |
| 128 | 2960.55 | 3388.23 | 14.4% |

Separate C128 captures verify the switch from generic page-1 FlashInfer decode to native page-64 GenMHA decode. Attention kernel time over eight decode steps drops from approximately 198.5 ms to 170.2 ms (288 launches in each capture).

The full curve used one GPU, but part of it overlapped an independent experiment on another GPU in the same host. An earlier C128 pair measured 2959.48 vs 3398.09 output tok/s. A subsequent GPU0 confirmation with no other task GPU work on the host measured 795.30 vs 897.50 output tok/s at C4 (+12.85%) and 2962.09 vs 3398.69 at C128 (+14.74%). Exact per-request prompt records and input/output token counts match. C128 median TTFT improved from 6.451 s to 5.813 s and median TPOT from 36.924 ms to 32.022 ms.

The independent full GSM8K repeat scored 1198/1314 vs 1199/1314, with zero errors and all responses ending naturally; the candidate lost 8 cases and gained 9. This confirms the observed task-level behavior, not numerical equivalence. The benchmark does not establish gains for every Qwen3 variant supported by the command generator.

This recipe change addresses the backend throughput gap. It does not resolve the high-concurrency TTFT scheduling gap: in the full curve at C128, TRT MHA measured 5.891 s median TTFT versus 1.006 s for the matched vLLM baseline.
