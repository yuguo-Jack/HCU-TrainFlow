# [CI] tests: Rendezvous the tile-sharding gloo test through a file store

[Upstream PR](https://github.com/sgl-project/sglang/pull/47551) · state: closed · merged: True

## Original PR description

## Motivation

`TestShardedDecode::test_three_ranks_agree_with_the_serial_decode` in `python/sglang/multimodal_gen/test/unit/test_diffusion_decoder_tile_sharding.py` is flaky on shared CI runners (tracked as **T7** in #42752):

```
DistNetworkError: The server socket has failed to listen on any local network address. port: <N>, ... EADDRINUSE
```

The test picked its rendezvous port with `_free_port()`: bind to port 0, read the port, close the socket. Rank 0's `TCPStore` only listens on it later, after `mp.spawn` starts the workers. A concurrent job on the same host can take the port in that window.

## Modifications

- Rendezvous through `init_method="file://<tmpdir>/store"` (a `FileStore` in a `tempfile.TemporaryDirectory`) instead of `MASTER_ADDR`/`MASTER_PORT`, so the test reserves no TCP port at all. Gloo's own pair connections still bind ephemeral ports atomically, so nothing races.
- Drop the now-unused `_free_port()` and the `os`/`socket` imports.

Test-only change; no product code touched. The same `file://` rendezvous is already used in `python/sglang/multimodal_gen/tools/quantize_pi05_modelopt_fp8.py`.

## Test plan

- **Deterministic repro of the race** (torch 2.15 CPU, gloo, 3 ranks): probe a port as `_free_port()` does, have another socket take it, then rendezvous.
  - Old pattern (`MASTER_PORT=<probed>`): `DistNetworkError: The server socket has failed to listen on any local network address. port: 61544, useIpv6: false, code: -48, name: EADDRINUSE`, the same signature as CI.
  - New pattern (`file://` store), same squatted port still held: passes.
- Pre-commit (isort, ruff, ruff format, codespell) clean.
- The full test file has not been run locally yet: it imports triton, which has no macOS wheel. Relying on CI (`multimodal-gen` unit tests) for the end-to-end run.
