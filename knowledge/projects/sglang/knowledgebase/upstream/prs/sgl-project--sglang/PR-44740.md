# [Perf] NIXL: prepared dlists for hybrid-model state transfer

[Upstream PR](https://github.com/sgl-project/sglang/pull/44740) · state: closed · merged: True

## Original PR description

## Motivation

Hybrid-model state (Mamba/GDN, SWA, DSA indexer, QSA, MiniMax, MXFP8 block scales) was
sent with a fresh `initialize_xfer` per request, rebuilding and re-validating every
descriptor. With `NIXL_UCX_SGL_ENABLE=1` the data path is one SGL put per transfer, so
this host-side descriptor work is what remains on the transfer worker.

## Modifications
- At peer registration, build one strided source/destination dlist pair per decode peer
  covering all whole-slot state components; per request, one `make_prepped_xfer` with
  int32 selectors instead of one `initialize_xfer` per component.
- Decode advertises its state pool lengths (new registration frame 23) so prefill can
  size the destination dlist. An older decode without the frame stays on the generic path.
- Components the fast path cannot address (TP-sliced layouts, PP/CP/DCP, unpaired
  entries) stay generic per component. A stride mismatch is recorded at registration and
  fails every transfer to that peer with the reason, instead of addressing the decode
  with the prefill stride or killing the bootstrap thread.
- State completion is one standalone `{room}_state_{rank}` notification sent after every
  handle of the chunk settles (NIXL UCX flushes the endpoint before DONE). This replaces
  per-component attached notifs, which let decode treat the first component's arrival
  as state complete.

## Accuracy Tests

Not applicable: the same bytes move through prepared descriptors. Byte-for-byte
equivalence of the prepared and generic paths was checked with a memcpy fake agent
across Mamba, SWA on MHA, DSA with elided layers, QSA with layer ids, MLA peers with
mismatched TP, a decode with an extra DSA entry, and multi-component requests.
