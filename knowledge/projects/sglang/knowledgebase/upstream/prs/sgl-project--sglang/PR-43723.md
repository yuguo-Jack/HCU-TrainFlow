# [PD][NIXL] Fix staging buffer startup by accepting slot_layer_ids

[Upstream PR](https://github.com/sgl-project/sglang/pull/43723) · state: closed · merged: True

## Original PR description

## Motivation

Enabling `SGLANG_DISAGG_STAGING_BUFFER=1` with the nixl transfer backend fails at scheduler init:

```
File "sglang/srt/disaggregation/prefill.py", line 365, in _init_kv_manager
    kv_manager.set_kv_buffer_tensors(
TypeError: NixlKVManager.set_kv_buffer_tensors() got an unexpected keyword argument 'slot_layer_ids'
```

5f216fc33f (#35758) added `slot_layer_ids` to both call sites (`prefill.py` and `decode.py`) and to `MooncakeKVManager.set_kv_buffer_tensors`, but left `NixlKVManager.set_kv_buffer_tensors` with the three argument signature from #22536. Both call sites pass the keyword unconditionally, so the NIXL staging path cannot start.

## Changes

Accept and store `slot_layer_ids` in `NixlKVManager.set_kv_buffer_tensors`, matching `MooncakeKVManager`. NIXL calls its own `send_kvcache_staged` rather than the shared `PrefillStagingStrategy.transfer`, and that path does no pipeline parallel layer pairing, so storing the value is sufficient.

## Validation

Two node PD, 8x H100 80GB per node, DeepSeek R1 Distill Qwen 32B, prefill TP 2 feeding decode TP 4, NIXL over UCX. On main both roles raise the TypeError during init and the server exits. With this change both roles come up and serve requests through the staging path.

No unit test is added because the coverage gap is in fixture configuration rather than in this file. `server_fixtures/disaggregation_fixture.py` pins the transfer backend to mooncake under CI, so `TestDisaggregationStagingDecodeLargerTP` only ever exercises mooncake, and `test_nixl_backend_basic.py` sets `SGLANG_DISAGG_STAGING_BUFFER` to `false`. Can push that separately.
