# [Perf] dsa: Cache k-pool logits budgets per forward

[Upstream PR](https://github.com/sgl-project/sglang/pull/42164) · state: closed · merged: False

## Original PR description

## Motivation

The pooled DSA indexer reads the MQA logits budget at each sparse-attention layer of a large prefill. Each read calls `torch.cuda.mem_get_info`.

Cache that reading per live forward batch and device. Each child in a two-batch overlap keeps its own entry, so switching between them can reuse the budget.

## Modifications

Keep weak references to live forward batches and prune expired entries during lookup. A new batch, including a new breakable-graph replay batch, reads free memory again. The existing small-matrix and graph-capture paths are unchanged; this applies to the pooled indexer.

## Accuracy Tests

CPU planner and stream-scheduling regressions and scoped formatting pass on the updated branch, including alternating live batches with different memory budgets. The overlap regression failed before the fix.

A local RTX 5070 Ti check on this head passed chunk coverage and budget bounds using real free-memory queries, with reuse across alternating live batches and pruning after a batch expires. It does not allocate MQA logits or run overlapped model execution.

GPU overlap, long-context allocator behavior and full-model accuracy remain unverified. A budget read at the first layer can still overestimate memory available later in that forward.

Run the unit suites with `python -m pytest` and scoped formatting with `pre-commit run --files <changed-files>`.

## Speed Tests and Profiling

On this head, an isolated budget lookup benchmark on an RTX 5070 Ti measured median cache hits at 0.12 us, compared with 5.4 us for a direct free-memory budget read. This measures helper calls only; no kernel or serving speedup is established. The focused regression verifies reuse of each live batch's budget reading.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Retain budget entries for both TBO children**

When `--enable-two-batch-overlap` is used with a k-pool DSA prefill whose child logits exceed the budget-check threshold, this single per-device slot is overwritten on every child switch. `execute_overlapped_operations` runs child A then child B for each stage (`python/sglang/srt/batch_overlap/operations.py:63-65`), while the DeepSeek prefill strategy yields within every layer (`python/sglang/srt/batch_overlap/operations_strategy.py:113-125`), and each child has its own `ForwardBatch`; consequently A's entry is replaced by B before A reaches the next sparse layer, and vice versa. This path therefore still calls `mem_get_info` once per sparse layer per child, so the cache needs to retain both live `(device, batch)` entries.
