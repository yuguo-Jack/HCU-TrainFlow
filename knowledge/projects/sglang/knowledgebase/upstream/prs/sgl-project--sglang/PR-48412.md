# [Feat] pp: Relay routed experts through pipeline-parallel stages

[Upstream PR](https://github.com/sgl-project/sglang/pull/48412) · state: open · merged: False

## Original PR description

## Motivation

`--enable-return-routed-experts` captures each MoE layer's top-k expert ids per token so an RL trainer can replay the rollout's routing. With `--pp-size > 1`, each stage captures only its own layers, and only the first stage keeps a host cache and answers requests. Responses therefore carry the first stage's layers and zeros for every later stage: on `Qwen3-30B-A3B` with `--pp-size 2`, layers 24 to 47 come back all zero, 49.6% of all ids. A trainer that replays those ids trains against the wrong experts for half the model.

## Modifications

Each forward's routed-expert rows, `[tokens, num_layers, topk]` int32, travel with the microbatch:

- Under PP every stage rank keeps a device cache (#47553 dropped it on ranks that send no outputs) and returns the forward's rows instead of writing the host cache. Each stage merges its own layer columns into the rows it received and sends them on with the hidden states. The TP worker pops them before the forward, so the model and its CUDA graphs never see the key.
- The last stage adds the full rows to the output message it already sends back. The first stage writes them into its host cache at the KV slots it recorded at launch and drops the key before forwarding the output on.
- Middle prefill chunks keep their output message while capture is on, or their tokens would silently return zeros. Capture is refused with `SGLANG_ENABLE_PP_SPEC`, whose spec branch does not carry the rows.

Cost: `num_layers * topk * 4` bytes per token on each PP hop while the flag is on. Nothing changes without PP or without the flag.

## Not in scope

- `--enable-return-indexer-topk` has the same per-stage gap under PP and still returns zeros for later stages.
- Speculative decoding under PP outside the gated `SGLANG_ENABLE_PP_SPEC` flow: the rows are dropped on the spec path, so the result is the same zeros as before.
- #30712: capture with attention DP and non-DeepEP MoE crashes on prefill CUDA graphs, with or without PP. The attention-DP test class passes `--cuda-graph-backend-prefill=disabled` until that is fixed.

## Accuracy Tests

`test/registered/rl/test_return_routed_experts_pp.py` (4x H100, `extra-b`): two servers with identical flags except `--pp-size 2` on one, every routed-expert id compared between them across `/generate`, `/v1/chat/completions` and `/v1/completions`. `Qwen3-30B-A3B-FP8`, 100 ShareGPT prompts, deterministic inference, chunked prefill at 256 tokens.

| Reference server | Mismatched ids (generate / chat / completions) | Layers that come back all zero |
|---|---|---|
| main, `--pp-size 2` | 49.6% | 24 to 47 |
| this PR, `--pp-size 2` | 0 of 9,517,440 / 8,747,904 / 8,442,240 | none |
| this PR, `--tp 2 --attn-dp-size 2 --pp-size 2` | 0 of 9,517,440 / 8,746,368 / 8,442,240 | none |

CPU unit tests:

- `test/registered/unit/state_capturer/test_routed_experts_scattered_a2a.py`: under PP every stage rank returns its rows and the first rank's host cache stays untouched until the rows come back.
- `test/registered/unit/managers/test_pp_output_exchange_order.py`: middle prefill chunks keep their output message while capturing.
