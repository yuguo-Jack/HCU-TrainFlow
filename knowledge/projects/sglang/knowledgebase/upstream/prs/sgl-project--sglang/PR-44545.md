# [Fix] r3: Keep routed experts across retract when opted in

[Upstream PR](https://github.com/sgl-project/sglang/pull/44545) · state: open · merged: False

## Original PR description

## Motivation

With rollout routing replay (R3) and `pause_generation_mode=retract`, a weight update retracts running requests. `reset_for_retract` drops their KV cache and `routed_experts`, and the resumed request re-prefills `origin_input_ids + output_ids` under the new weights. The routed-experts capturer stores rows per KV slot, so the re-prefill overwrites the routing of already-generated tokens, while their logprobs still come from the original decode under the old weights and the old routing. The trainer then replays routing that did not produce those logprobs.

On GLM-5.3-Flash fully-async RL this was the difference between a trainer-vs-rollout logprob abs diff of about 0.05 and about 0.018 at the same staleness. The same gap showed up on MI355X and on MI300X.

#43966 fixes the same bug unconditionally, with a broader history helper and tests. This PR is the opt-in version that those RL runs used. It stays off unless `SGLANG_R3_KEEP_ROUTING_ON_RETRACT=1`.

## Modifications

When the flag is set:

- `release_req` snapshots the request's captured routing rows before its KV cache is released, and merges them with rows kept by earlier retracts. Requests that do not ask for routed experts are skipped. `input_embeds` retraction discards `output_ids` and restarts generation, so that path drops any kept rows instead of restoring them onto a new sequence.
- After the final routed experts are collected, the kept rows overwrite the re-prefilled rows for the tokens they cover. Every 64 restored requests the server logs the fraction of `(token, MoE layer)` expert sets the re-prefill changed, as `[r3-keep-routing] restored ...`.

## Accuracy Tests

GLM-5.3-Flash fully-async RL:

| | `train_rollout_logprob_abs_diff` |
|---|---|
| Retract without this flag | about 0.05 |
| `SGLANG_R3_KEEP_ROUTING_ON_RETRACT=1` | about 0.018 |

On MI300X with the flag, the gap over 4 steps was 0.022–0.029, in the same range as the previous build's R3 runs (0.017–0.037).

## Speed Tests and Profiling

The snapshot is one host gather of the request's captured rows at retraction, and one overwrite at response assembly. Rollout step time on the MI300X R3 run stayed in the same 114–157 s range as the run without R3.
