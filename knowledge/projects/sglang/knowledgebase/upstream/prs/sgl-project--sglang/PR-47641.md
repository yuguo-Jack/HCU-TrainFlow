# [Perf] [NVIDIA] moe: One-warp-per-token CUDA MoE router for sigmoid, sqrtsoftplus and softmax routing

## What

A JIT CUDA MoE router, `moe_route_warp`: one warp per token, each lane holds E/32 experts as order-preserving u32 keys, sorts them once (compile-time Batcher network in the new `sgl_kernel/algorithm.cuh`), and every top-k round reduces only the 32 lane heads (`redux` max, then min lane for the lowest-id tie-break). The launcher picks 1 warp per CTA while all tokens fit in one wave and 4 warps per CTA beyond that.

Covered (static config, 128..512 experts, multiple of 32): sigmoid / sqrtsoftplus with correction bias (grouped `noaux_tc` or ungrouped) and softmax, fp32 / bf16 logits, fused shared-expert slots, renorm epsilon, `num_token_non_padded`, packed FlashInfer ids. `moe_fused_gate` and `biased_grouped_topk_gpu` dispatch to it whenever the config is covered; everything else (fewer than 128 experts, Kimi-K3's 896, softcap, fp16 logits) keeps the Triton router.

Also:
- DeepSeek-V4.1 VL per-token bias (`input_ids` / `bias_alt`) as a compile-time mode; the token id is loaded before the PDL wait.
- MuseSpark routing moves to the same kernel (compile-time mode); `muse_spark/routing.cuh` is removed.
- Removed kernels whose paths now go through `moe_fused_gate`: the JIT `topk_softmax` (unused on CUDA), the LoRA `kimi_k2_moe_fused_gate` and `topk_softmax_pack` (and the two LoRA env flags of the former).
- NaN logits rank last (as DeepGEMM's mega-gate).

Yes — the router is independent of the expert weight format. It only reads the gate logits (fp32 / bf16) and the correction bias and writes top-k ids / weights (optionally the FlashInfer packed ids), so it serves MXFP4 / MXFP8 / NVFP4 / FP8 / BF16 MoE models alike, whenever the MoE runner asks SGLang for the top-k (e.g. DeepSeek-V4 with fp4 experts on the `flashinfer_mxfp4` runner, or any Triton / DeepEP / DeepGEMM path). Runners that do the routing inside their own kernel (e.g. `flashinfer_trtllm` with routing bypass) don't call it, regardless of the quantization.
