# [Fix] mem_cache: Reject underflowing component size deltas in the Python tree core

[Upstream PR](https://github.com/sgl-project/sglang/pull/44370) · state: open · merged: False

## Original PR description

## Motivation

#43722 added `adjust_component_size` to both tree cores, but the two disagree when a delta would drive a ledger below zero:

- Rust (`unified_tree_core.rs:adjust_component_size`) uses checked arithmetic and returns `InvalidComponentSizeDelta` (a `ValueError` in Python), leaving both ledgers untouched. Its own test `component_size_adjustment_errors_preserve_both_ledgers` pins that contract.
- Python adds the delta unconditionally, so the same call silently records a negative evictable or protected size.

No production component calls the API yet, so nothing is wrong today. But Rust is the default core, so a component written and tested against one core would behave differently on the other the day it starts calling `adjust_component_size`.

## Modifications

- `UnifiedTreeCore.adjust_component_size` (Python) raises `ValueError` before touching the ledger when `current + delta < 0`, with the same fields as the Rust error.
- The interface docstring states the contract.

Python ints cannot overflow, so only the underflow half of the Rust check applies.

## Tests

- New `test_underflowing_adjustment_raises_and_preserves_ledgers`, parametrized over both backends and over an evictable and a protected node. It checks that `-5` and `-(1 << 63)` raise and leave both ledgers unchanged, and that an exact `-4` still lands at zero.
- Negative control: with the old Python core, both `python` cases fail (`DID NOT RAISE ValueError`) and both `rust` cases pass.
- `test_rust_tree_core_integration.py`: 469 passed. `test_unified_radix_cache_unittest.py` and `test_rust_unified_radix_cache_unittest.py`: 2916 each, OK. The Rust extension was built from this tree.
