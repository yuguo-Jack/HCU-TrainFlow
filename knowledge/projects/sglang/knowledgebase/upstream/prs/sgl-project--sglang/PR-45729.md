## Motivation

Issue: #42170. Currently, for a colocate worker, we can turn on --enable-prefill-cp for prefill and --enable-cp-decode-attn-tp for decode. In this way, prefill batch computes in a CP manner (split token) and decode batch computes in a TP manner (split weight). However, decode TP computes full batch is not friendly for high concurrency. Therefore, this PR provides a prefill CP decode DP option for a colocate worker.

## Modifications
This colocate decode DP modification is within model forward and doesn't affect the scheduler.
1. Each rank selects different query rows and pads the local batch at runtime for the subsequent projection, indexer, attention computation.
2. Each rank computes compressor using full batch and write the full KVcache into kv pool. 
3. After attention, Allgather is performed to collect the attn results of each rank and subsequent mhc/moe will not be affected.
4. For Dspark draft forward, the attention remains TP even if --cp-decode-attn-mode dp is set.

## Speed Tests and Profiling
We did test on 4*H20-3e and tested the cases of cache hit 93% and cache hit 70%. Input is 64K and output length is 500 tokens. The baseline we compare is pure TP4 and Prefill CP4 + Decode TP4. The result is as below. As we can see, CP+Decode DP has **4% ~23%** performance improvements across all concurrency and both cache hit rate. The percentage improvement shown in the table is calculated compared with CP + Decode TP.
