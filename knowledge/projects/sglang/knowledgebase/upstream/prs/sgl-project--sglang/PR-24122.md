# [FIX] nvtx: skip NVTX hooks during torch.compile tracing to fix piecewise CUDA graph warmup (#23872)

[Upstream PR](https://github.com/sgl-project/sglang/pull/24122) · state: open · merged: False

## Motivation

`enable_layerwise_nvtx_marker=True` registers forward pre/post hooks that call:

```python
nvtx.range_push("{}".format(marker_dict))
```

When piecewise CUDA graph warmup runs `torch.compile`, Dynamo traces into these hooks and fails because it has no `as_proxy()` implementation for `StringFormatVariable` over a `ConstDictVariable`.

This causes the scheduler subprocess to crash and makes the feature completely unusable on the default compiled code path.

Fixes #23872

---

## Modifications

Added:

```python
if torch.compiler.is_compiling():
    return
```

at the top of both `module_fwd_pre_hook` and `module_fwd_hook` in:

```text
python/sglang/srt/utils/nvtx_pytorch_hooks.py
```

`torch.compiler.is_compiling()` is natively understood by Dynamo. During tracing it resolves to `True`, so both hooks are treated as early-return no-ops and the compiled region is captured without errors.

At actual inference runtime the guard returns `False`, so the NVTX calls execute normally and per-layer profiling markers continue to work as intended.

No behavior change when `enable_layerwise_nvtx_marker=False` since the hooks are never registered.
