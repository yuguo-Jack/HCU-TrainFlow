# [Fix] Harmony parser: keep the response when a block opens on an unknown channel

[Upstream PR](https://github.com/sgl-project/sglang/pull/43396) · state: open · merged: False

## Original PR description

## Motivation

gpt-oss models sometimes open a response on a channel name outside the Harmony set (observed with `openai/gpt-oss-safeguard-20b`: `verdict`, `partial`, `backward`, `raw`, `ori`, `simulate`) before a valid `analysis` or `final` block. `CanonicalStrategy._parse_block` returns `None` for such a header, `parse()` then treats the block as incomplete and holds the entire remaining text, and the valid `final` block that follows is never emitted. The chat completions response then has `content: ""` and no `reasoning_content`, with `finish_reason: stop` and `completion_tokens` counting hundreds of generated tokens.

In a production classifier that reads a one-character final answer this hit about 5% of calls on ordinary prompts (523 of 9,994 under one system prompt). Re-issuing the same requests through `/generate` with special tokens kept showed a valid `final` 0/1 in 45 of 45 samples, 12 of which opened on an invented channel name.

## Modifications

`python/sglang/srt/parser/harmony_parser.py`: when `_extract_channel_type` does not recognise the channel, parse the block instead of returning `None`. Its content is emitted as `reasoning`, or as `normal` when the block ends with `<|return|>`; a block with no terminator is still held as incomplete. `analysis`, `commentary` and `final` handling is unchanged.

`test/registered/unit/parser/test_harmony_parser.py`: the existing unknown-channel case now expects a reasoning event rather than a held block; new cases cover an unknown-first response keeping its later final, an unknown block closed by `<|return|>`, a truncated unknown block staying held, and streaming parity at token boundaries.

## Accuracy Tests

Not applicable: no change to model forward code or sampling. The parser unit tests pass (`test_harmony_parser.py`), and the new or changed cases fail against the previous code.

## Speed Tests and Profiling

Not applicable: the change only adds a branch for a channel header that was previously rejected.
