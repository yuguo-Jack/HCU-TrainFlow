# [Perf] [AMD] aiter: Speed up asm fp8 MLA prefill for 12-head and mixed-prefix batches

[Upstream PR](https://github.com/sgl-project/sglang/pull/47035) · state: open · merged: False

## Original PR description

## Motivation

- Kimi-K3 at TP8 runs 12 MLA heads per rank. On gfx950 the AITER asm fp8 MLA prefill paid three avoidable costs on that shape:
  - padding 12 heads to 16 copied K and V twice per layer (head repeat);
  - SGLang still padded when AITER ships a native 12-head reduce (`nh12_hd128`, ROCm/aiter#7087);
  - a prefix chunk with any keyless request moved the whole chunk to the bf16 varlen attention.
- These costs land on prefill (TTFT) for every layer and every prefix chunk.

## Modifications

- Zero-pad missing heads with one copy and a zero tail instead of repeating heads.
- Run 12 heads unpadded when the installed AITER has the `nh12_hd128` reduce instance (probed from AITER's `reduce_instances` sources, since `mla_reduce_v1` aborts on a missing shape).
- Keep prefix chunks with keyless requests on the asm fp8 PS prefill: PS metadata covers only the requests with keys, and keyless rows return zero output and LSE `-inf`, which `merge_state` weights by zero.
- Pack prefix-chunk K/V straight to fp8 in one pass (`pack_prefix_chunk_kv` -> `mla_kv_pack_quantize_fp8`).
- `pack_prefix_chunk_kv` is hidden when the asm fp8 prefill is off, so those runs keep the model dtype for the prefix latent and the existing K concat.

| Condition | Prefill path |
|---|---|
| gfx95, MLA, asm fp8 prefill on, AITER has `nh12_hd128` | 12 heads, no padding |
| Same, AITER without `nh12_hd128` | zero-padded to 16 heads |
| Prefix chunk with keyless requests | asm fp8 PS over the requests with keys (was bf16 varlen) |
| asm fp8 prefill off, decode, CUDA, gfx942 | unchanged |
