# [AMD] Opt-in AITER GDN chunked prefill (opt_vk stages and fused FlyDSL)

[Upstream PR](https://github.com/sgl-project/sglang/pull/44103) · state: open · merged: False

## Original PR description

**Title:** [AMD] Opt-in AITER GDN chunked prefill (opt_vk stages and fused FlyDSL)

## Motivation

On ROCm, GDN (Gated DeltaNet) chunked prefill runs the Triton FLA chunk path:
five kernels (cumsum + KKT, solve_tril / recompute w,u, the hidden-state
recurrence, the output kernel), with per-chunk states round-tripping through
HBM. AITER has faster implementations for gfx950. This PR wires them in behind
an opt-in flag, so Qwen3.8-Flash-Next (and other GDN models) can use them on
MI355X without changing default behaviour.

## Modifications

New opt-in env vars (`python/sglang/srt/environ.py`, AMD/AITER section, default off):

| Env var | Values | Meaning |
|---|---|---|
| `SGLANG_AITER_GDN_PREFILL` | `0` (default) / `1` | With `SGLANG_USE_AITER=1`, route `TritonGDNKernel.extend` on HIP through AITER |
| `SGLANG_AITER_GDN_PREFILL_H` | `triton` (default), `hip`, `flydsl`, `fused` | Which AITER implementation to use |

- **`triton` / `hip` / `flydsl`**: AITER's opt_vk stages (FlyDSL prepare, the chosen
  hidden-state kernel, the VK output kernel). They are called stage by stage
  because the public `chunk_gated_delta_rule_opt_vk` drops the per-chunk states
  `h` that radix state tracking reads (it also fails on the strided q/k views
  the GDN backend passes). These APIs are already in AITER main.
- **`fused`**: a single FlyDSL kernel for the whole chunk loop. The state stays on
  chip, and q/k l2norm runs in-kernel. It also writes the fp32 chunk-boundary
  track snapshot itself, so `TritonGDNKernel.supports_track_state_snapshot` is
  True in this mode. **Requires ROCm/aiter#<AITER_PR>**
  (`aiter.ops.flydsl.gdn_fused_prefill`).

Files:
- `layers/attention/linear/kernels/gdn_aiter_prefill.py` (new): `AiterGDNPrefill`
  wraps both paths. It builds prefill metadata from host-side
  `extend_seq_lens_cpu`, so there is no device-to-host read, and caches it
  across all GDN layers of a forward.
- `layers/attention/linear/kernels/gdn_triton.py`: lazy, cached
  `_aiter_gdn_prefill()` selection.
  - `extend()` is split into `extend()` / `_extend()`, so track state is filled
    from `h` (device-side index math, no sync) for any path that returns `h`.
  - The new `__init__` sets `supports_track_state_snapshot` for the fused mode.
- `layers/attention/linear/gdn_backend.py`: pass
  `seq_lens_cpu=forward_batch.extend_seq_lens_cpu` to the extend kernel.

Fallbacks: if AITER lacks the requested kernel (ImportError), the module logs
once and keeps Triton. Per batch, it also falls back to the existing Triton path
when the fused kernel declines the operands, `seq_lens_cpu` is missing or
mismatched, `ssm_states` is non-contiguous, or `inplace_update=False`. Nothing
changes when the flag is off, or on CUDA/NPU/CPU/XPU.

## Accuracy Tests

MI355X, Qwen3.8-Flash-Next MXFP4, TP1 + NEXTN (MTP), GSM8K (1319 questions, chat
template, thinking off):

| Prefill path | GSM8K |
|---|---|
| Triton (baseline) | 96.1% |
| `SGLANG_AITER_GDN_PREFILL_H=triton` (opt_vk) | 96.6% |
| `SGLANG_AITER_GDN_PREFILL_H=fused` | 96.7% |

Kernel-level check against an fp32 recurrence (one GDN layer, H=48, Hg=16, K=V=128):

| Path | o rel_l2 vs fp32 | final state rel_l2 vs fp32 |
|---|---|---|
| Triton (sglang) | 4.11e-3 | 3.54e-3 |
| opt_vk, `H=triton` | 4.11e-3 | 3.54e-3 |
| opt_vk, `H=hip` / `H=flydsl` | 4.91e-3 | 6.32e-3 |
| fused | 3.31e-3 | 2.87e-3 |

Tracked chunk-boundary state vs fp32 truth: Triton `h` 3.53e-3, fused snapshot
2.36e-3. Varlen batches (`[5000, 64, 1, 11000, 333, 63, 65]`) and `-1`
padding rows (which write slot 0 only) were checked as well.

## Speed Tests and Profiling

One GDN layer (H=48, Hg=16, K=V=128), MI355X:

| Tokens | Triton (sglang) | opt_vk `triton` | opt_vk `hip` | opt_vk `flydsl` | fused |
|---|---|---|---|---|---|
| 1 x 16384 | 1.724 ms | 1.246 ms | 1.290 ms | 1.254 ms | **0.783 ms** |
| 1 x 32768 | 3.366 ms | 2.517 ms | 2.572 ms | 2.520 ms | **1.540 ms** |
| varlen (7 seqs, 16.5K) | 1.598 ms | 1.221 ms | 1.133 ms | 1.134 ms | **0.775 ms** |

End to end, Qwen3.8-Flash-Next MXFP4 TP1 + NEXTN, ISL/OSL 32K at concurrency 4:
mean TTFT went from 2642 ms (Triton) to 2469 ms (fused). Throughput and p90
interactivity stayed within run-to-run noise, because this workload is
decode-bound.

Usage:
```bash
export SGLANG_USE_AITER=1
export SGLANG_AITER_GDN_PREFILL=1
export SGLANG_AITER_GDN_PREFILL_H=fused   # needs [ROCm/aiter](https://github.com/ROCm/aiter/pull/6496); otherwise triton
```
