# [Fix] scheduler: Align deterministic SSM prefill chunks

[Upstream PR](https://github.com/sgl-project/sglang/pull/45545) · state: open · merged: False

## Original PR description

## Motivation

Fixes #45481. Concurrent arrivals can split Qwen3.5's remaining 128-token prefill into 105+23 tokens, changing GDN's recurrent-state updates despite deterministic inference being enabled.

## Modifications

Align deterministic SSM prefill chunks to the state-cache chunk size while preserving the attention backend's alignment. Apply this to continuing chunks and the `ignore_eos` admission path as well. Update one existing test double for the added argument; no new test cases.

## Accuracy Tests

Reproduced the reported token divergence with Qwen3.5-35B-A3B on 2× H100 (TP1/PP2 + NEXTN). After the fix, all 294 requests across the original and forced repros produced identical 64-token outputs per input. Existing related tests: 56 passed, 56 subtests passed. Formatting and lint checks passed.

## Speed Tests and Profiling

No throughput benchmark; this fixes deterministic chunk scheduling.

- MarinaMackay · comment · 2026-10-26T06:29:59Z · [source](https://github.com/sgl-project/sglang/pull/45545#issuecomment-6409748966)

@SouthWest7 FYI, I opened #46525 for #46446, and the two PRs are complementary rather than overlapping. #46525 only changes the GDN backend: under deterministic inference it runs the decode tail of a mixed batch through the decode kernel. The issue's two-request repro needs that, and this PR does not touch it. This PR's chunk alignment covers the concurrency differences that remain with mixed chunk off.

I applied this PR on top of #46525 on 1x H200 (main `d7f832d30a`, Qwen3.5-9B, Triton, deterministic). Client concurrency 1 vs 8, 32 prompts, number of differing outputs:

| | mixed off, radix off | mixed on, radix off | mixed on, radix on |
|---|---|---|---|
| #46525 only | 3/32 | 2/32 | 6/32 |
| #46525 + this PR | 0/32 | 0/32 | 1/32 |

Also, this PR now conflicts with `8252e3af63` (#41701) in `schedule_policy.py`, which wraps both cut sites in `floor_chunked_tokens`. For the runs above I kept this PR's side of both hunks, which is equivalent without DCP.
