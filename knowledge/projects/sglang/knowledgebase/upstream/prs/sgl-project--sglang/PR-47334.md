# [Fix] grpc: Set TCP_NODELAY on accepted runtime.v1 gRPC connections

[Upstream PR](https://github.com/sgl-project/sglang/pull/47334) · state: open · merged: False

## Original PR description

## Motivation

The `runtime.v1` gRPC server (`rust/sglang-grpc`) hands a plain `TcpListener` to tonic through
`serve_with_incoming_shutdown`. tonic applies its `tcp_nodelay` setting only to listeners it binds itself, so the
sockets this server accepts keep Nagle's algorithm enabled. Streamed responses are one small frame per token, all
flowing server → client with almost nothing coming back, which is exactly the pattern where Nagle plus the client's
delayed ACK stalls the sender: each frame waits for the previous one to be acknowledged, and the acknowledgement is
held back by the peer for up to 40 ms.

Measured with the Dynamo SGLang sidecar as the gRPC client (same host, loopback, Qwen3-0.6B, nightly `c10e0e17`,
three rounds), compared with the same deployment through the Rust server's `api.v1` listener and with the in-process
`sgl.Engine` path:

| | TTFT p50 at concurrency 1 | ITL p99 at concurrency 64 | inter-token gaps > 2× median, c=64 | gaps in the 36–44 ms band (of ≈162 k) |
|---|---|---|---|---|
| runtime.v1 gRPC server, as is | **46.6 ms** | **40.1 ms** | **10.7 %** | 5704 |
| same, `TCP_NODELAY` forced on accepted sockets (`LD_PRELOAD` shim, nothing else changed) | 21.2 ms | 25.4 ms | 0.97 % | 492 |
| Rust server (`api.v1`, already sets `TCP_NODELAY` in `utils/sock.rs`) | 22.0 ms | 22.9 ms | 0.84 % | 240 |
| in-process `sgl.Engine` | 21.7 ms | 25.5 ms | 0.99 % | — |

Throughput and the ITL median are unchanged by the option; only the first-token delay and the 40 ms tail go away.
The Rust server's listeners (`rust/sglang-server/src/utils/sock.rs`) and the Python HTTP server already run with
`TCP_NODELAY`; this brings the `runtime.v1` listener in line.

## Modifications

- `rust/sglang-grpc/src/server.rs`: wrap the listener in `tonic::transport::server::TcpIncoming` with
  `with_nodelay(Some(true))` (new `grpc_incoming` helper) instead of a bare `TcpListenerStream`, so every accepted
  connection gets `TCP_NODELAY`. No other behavior changes; `serve_with_incoming_shutdown` and the shutdown path are
  the same.
- `rust/sglang-grpc/src/server/tests.rs`: unit test that a connection accepted through `grpc_incoming` reports
  `nodelay() == true`.

Not applicable (transport-only change, no effect on model outputs).
