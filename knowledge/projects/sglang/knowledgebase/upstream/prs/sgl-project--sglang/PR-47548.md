# [Perf] RL: Gather DeepEP routed-expert ids once per forward

[Upstream PR](https://github.com/sgl-project/sglang/pull/47548) · state: closed · merged: False

## Original PR description

Stacked on #47547, which is stacked on #47523. Only the last commit is new here.

## Why?

With DeepEP and DP attention, each attention-TP rank holds a slice of the tokens. So capture all-gathered every MoE layer's ids inside the forward: one small collective per layer, on every rank, between top-k and dispatch.

```text
Before (one forward, attn-TP 2, L MoE layers)       After
layer 1: top-k → all-gather → device buffer         layer 1: top-k → local buffer
layer 2: top-k → all-gather → device buffer         layer 2: top-k → local buffer
  ...                                                  ...
layer L: top-k → all-gather → device buffer         layer L: top-k → local buffer
                                                    forward end: 1 gather → output rank
= L collectives on every rank                       = 1 collective
```

## What?

- With DeepEP and DP attention (attn-TP > 1), each rank writes its own tokens' ids to a local buffer. `on_forward_end` gathers every layer to attn-TP rank 0, the output rank, in one call. Ranks hold equal, rank-ordered shares, so the rows land in the same order the per-layer all-gather produced.
- Rows per rank: eager forwards use what `capture()` saw. Graph replay uses the local DP buffer length the runner set, and eager forwards warn if the two disagree.
- Groups outside pp0 / attn-cp0 send nothing. Without DP attention, the per-layer all-gather is unchanged.

## Verification?

- Unit test with two simulated attention-TP ranks: the one gather rebuilds exactly the rows the per-layer all-gather wrote. **Observed** passing.
- H200, DeepSeek-V2-Lite-Chat, TP4 × DP2 with DP attention and DeepEP low-latency mode: bitwise routing versus `main`, plus decode timing. **Pending**.
