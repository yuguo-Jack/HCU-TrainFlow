# [Fix] Require control-plane auth on mesh HA management routes (fixes #45006)

[Upstream PR](https://github.com/sgl-project/sglang/pull/45017) · state: open · merged: False

## Original PR description

## Summary

Mesh HA management routes (`/ha/*`) in `sgl-model-gateway` were protected only by the data-plane `auth_middleware` (Bearer == `--api-key`), which performs no role check. In a deployment with `--enable-mesh`, a data-plane API key, and control-plane RBAC (`--control-plane-api-keys`), any holder of the data-plane key could read cluster state/topology, write config entries that gossip to every peer, change the global rate limit, and trigger a graceful mesh leave — while the genuine control-plane Admin credential was rejected with 401 on the same routes.

This change wraps `mesh_routes` with the same `apply_control_plane_auth` already used for `admin_routes`/`worker_routes`: when control-plane RBAC is configured, only Admins can reach `/ha/*`; when it is not configured, the wiring falls back to the data-plane API key check, so behavior is unchanged.

Thank you @yyymk for the thorough report and the public disclosure — the reproduction steps and the control experiment made the intended fix direction clear.

Fixes #45006.

## Root cause

In `sgl-model-gateway/src/server.rs::build_app`, `admin_routes` and `worker_routes` go through `apply_control_plane_auth` (control-plane middleware when `--control-plane-api-keys`/JWT is configured, otherwise the data-plane fallback), but `mesh_routes` was attached only to `middleware::auth_middleware`, which checks the Bearer token against `--api-key` and does no role check.

## Change

```diff
-    // HA management routes
+    // HA management routes (control-plane authorization: Admin only when
+    // control-plane RBAC is configured, otherwise plain data-plane API key).
     let mesh_routes = Router::new()
         .route("/ha/status", get(get_cluster_status))
         ...
-        .route("/ha/shutdown", post(trigger_graceful_shutdown))
-        .route_layer(axum::middleware::from_fn_with_state(
-            auth_config.clone(),
-            middleware::auth_middleware,
-        ));
+        .route("/ha/shutdown", post(trigger_graceful_shutdown));
+    let mesh_routes = apply_control_plane_auth(mesh_routes);
```

## Reproduction

Verified on current main (commit `4ec19ca`), built with Rust 1.90.0. Two mesh routers plus one mock worker, all on 127.0.0.1, following the issue's topology:

```bash
# mock worker on 127.0.0.1:39990 (see issue for mock_worker.py)
sgl-model-gateway \
  --host 127.0.0.1 --port 33800 --policy round_robin \
  --worker-urls http://127.0.0.1:39990 \
  --worker-startup-timeout-secs 5 --disable-health-check --log-level info \
  --api-key user-secret \
  --control-plane-api-keys admin1:Admin:admin:admin-secret \
  --control-plane-api-keys user1:User:user:user-secret \
  --enable-mesh --mesh-server-name R1 \
  --mesh-host 127.0.0.1 --mesh-port 39530 --mesh-peer-urls 127.0.0.1:39531
# second router identical with --port 33801, --mesh-server-name R2, mesh :39531 -> peer 127.0.0.1:39530
```

Note: on current main, `/ha/config` values must be hex-encoded (hence `deadbeef`/`cafebabe` below); the 0.3.2 behavior in the issue accepted arbitrary strings.

## Regression checks

- **Mesh peering intact** (gossip runs over the smg-mesh TCP protocol on the mesh port, never through the `/ha/*` HTTP routes; no in-repo HTTP caller of `/ha/*` exists). With the fix, both nodes see the full cluster:
  ```
  $ curl -s http://127.0.0.1:33800/ha/status -H 'Authorization: Bearer admin-secret'
  {"node_name":"R1","node_count":2,"nodes":[{"name":"R1","address":"127.0.0.1:39530",...},
   {"name":"R2","address":"127.0.0.1:39531",...}],"stores":{"membership_count":2,...}}
  $ curl -s http://127.0.0.1:33800/ha/health -H 'Authorization: Bearer admin-secret'
  {"status":"healthy","node_name":"R1","cluster_size":2,"stores_healthy":true}
  ```
- **Public health probes untouched** (`/liveness`, `/readiness`, `/health`, `/health_generate` are in `public_routes`): `GET /liveness` and `GET /health` return 200 with no credentials, before and after.
- **Inference path untouched**: `POST /v1/completions` with the data-plane key returns 200, before and after. (`/ha/health` is a mesh-topology management view, not the liveness probe.)
- **No control-plane RBAC configured**: `apply_control_plane_auth` falls back to the plain data-plane `auth_middleware`, so deployments without `--control-plane-api-keys`/JWT see no behavior change.
