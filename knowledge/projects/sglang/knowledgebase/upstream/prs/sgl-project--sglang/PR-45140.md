# [DSA] Fix kpool fused top-k overflow when coarse bin exceeds smem

[Upstream PR](https://github.com/sgl-project/sglang/pull/45140) · state: closed · merged: False

## Original PR description

## Summary
- Backport the kpool fused top-k overflow fix from #39273 onto `release/v0.5.21`.
- When the coarse threshold bin has more than `SMEM_INPUT_SIZE` (4096) candidates, rescan with unique 64-bit `(score, index)` keys instead of clipping into shared memory and returning the wrong top-k set.
- Normal (non-overflow) rows keep the existing fast path with no extra work.
- Add CUDA/ROCm coverage for overfull-bin membership and CUDA-graph replay.

## Context
`main` / `release/v0.5.22` already contain this fix via #39273. GLM-5.3-Flash long-context / clustered logits can hit the overflow path; without it, fused kpool select can silently pick the wrong groups.
