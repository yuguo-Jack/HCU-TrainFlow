# [Fix] hicache: Move NIXL pages that are not whole O_DIRECT blocks

[Upstream PR](https://github.com/sgl-project/sglang/pull/46540) · state: open · merged: False

## Original PR description

## Motivation

Refs #45563.

With a NIXL file plugin and O_DIRECT on (the default), every transfer's address and length must be whole 4 KiB blocks. DSA models' host pages are not: GLM-5.x has 3,316,736 B KV pages and 667,392 B indexer pages. Such a pool fails `is_stride_page_aligned(4096)` and falls back to copy mode. Copy mode's staging slots are exactly one page long, so the kernel refuses (EINVAL) every transfer and NIXL leaves empty files behind. The L3 then either never produces a usable hit or, with older NIXL, restores all-zero KV.

## Modifications

**Copy mode (any layout, any pool).** Under O_DIRECT, each staging slot is padded to whole 4 KiB blocks. A write copies the page into the start of its slot and NIXL writes the whole slot; a read fills the slot and copies only the page's bytes back. This is the same approach as #42491 for hybrid pools, applied to both the v1 (KV) and the v2 (hybrid) staging buffers.

**Zero-copy for `page_first_direct`.** When NIXL will open files with O_DIRECT, `MLATokenToKVPoolHost` and `DSAIndexerPoolHost` place their pages at a 4 KiB-multiple stride, so `HiCacheNixl` keeps zero-copy instead of falling back to copy mode:

- **Allocation (`alloc_padded_pages`):** one allocation of `page_num × stride`, exposed as the usual `(page_num, ...)` tensor through a strided view. The view keeps the allocation's CUDA host-registration ranges, so `destroy()` still unregisters them.
- **Who decides:** `get_storage_page_align(layout, allocator_type)` asks the backend. For NIXL, `NixlBackendConfig.needs_page_alignment()` makes the same decision `HiCacheNixl` uses: `use_direct_io` in `extra_config` first, then the env var, and never for OBJ plugins.
- **Page size the pool reports:** the pool still reports each page's own bytes (`get_page_buffer_meta`), and `HostKVCache.storage_page_align` records the padding. `HiCacheNixl` rounds each zero-copy transfer up into its page's padding and registers the padded span (`_span_bytes`). Other storage backends see the same page sizes as before.
- **GPU ↔ host copies:** unchanged. The `page_first_direct` kernels address host pages through the tensor's strides, so they skip the padding.
- **Everything else:** with padding off, pools allocate and behave exactly as before.

**Cost:** under 4 KiB of padding per page, in host memory and on disk (GLM-5.x: +1,024 B per KV page, +256 B per indexer page). Zero-copy saves one host copy per page and lifts the 128-page batch cap.

**Not covered:** `page_first`, `page_unified`, other host pool classes, and a NIXL backend attached at runtime are not padded; they use the padded staging slots.

**Related:**
- #42491 pads only the hybrid pools' slots.
- #35231 pads the slot stride but not the length.
- #46131 (empty or short files read as misses) is complementary.

## Accuracy Tests

**New unit tests**, all of which fail without this change:

| test | checks |
| --- | --- |
| `TestHostPagePadding` (`test_mem_pool_host.py`) | the padding decision, `alloc_padded_pages`, and that padded pools report and keep their pages |
| `TestNixlDirectIOPages`, `...OnDisk` (`test_hicache_nixl_storage.py`) | KV (v1) and indexer (v2) pages that are not whole blocks round-trip under O_DIRECT, through padded slots (128 pages) and zero-copy (160 pages). The first uses a stand-in that refuses unaligned transfers, so it runs on any filesystem; the second uses real O_DIRECT files |
| `test_direct_kernels_follow_padded_host_pages` (`test_dsa_pool_host_unit.py`, GPU) | GPU → padded host pools → GPU through the `page_first_direct` kernels, with every layer compared |

These three files run in `lmsysorg/sglang:nightly-dev-20261026-8252e3af` on one H200, with the O_DIRECT directory on XFS with 4096-byte sectors:
- **With this PR:** 65 passed, 1 skipped (MinIO).
- **Without it:** 19 failed, all of them new.

**GLM-5.x page shapes.** On the same filesystem, 8 pages went GPU → host → NIXL files → host → GPU, built from the real MLA (79 layers) and DSA indexer host pools. Every page was intact in every layer.

## Speed Tests and Profiling

**Setup.** One H200, `nvcnvn/DeepSeek-V3.2-4L` (DeepSeek-V3.2 cut to 4 layers + MTP), TP 1, FP8 KV, EAGLE, `page_first_direct` with the `direct` io backend, NIXL POSIX on ext4, O_DIRECT on. The host pool is small enough that returning rounds come from the L3.

**Load.** `bench_multiturn.py` with 32 clients and 4 rounds of 4,096 tokens. Then 16 prompts of 8,192 tokens are sent cold, evicted, and sent again.
