# [Kernel] Add fused activation + FP8 quantization JIT kernel for Triton MoE path

[Upstream PR](https://github.com/sgl-project/sglang/pull/31712) · state: closed · merged: False

## Original PR description

## Motivation

 The Triton MoE runner path (`_fused_moe_kernel_sequence`) currently performs activation (SiLU/GELU/gelu_tanh + Mul) and FP8 blockwise quantization as separate operations, requiring an intermediate bf16 buffer write and read between them.

  This PR adds a general-purpose fused CUDA JIT kernel that combines activation + multiply + FP8 per-token-group quantization in a single pass, eliminating the memory round-trip.

  **Applicable to all FP8 blockwise MoE models** on the Triton runner path, including:
  - Both SiLU and GELU activation types
  - Both EP (Expert Parallelism) and non-EP deployments
  - Any model using block_k=128 FP8 quantization 

  Note: The DeepGemm runner has its own fused path (`silu_and_mul_contig_post_quant`). This optimization targets the Triton runner, which is used in different deployment scenarios.



## Modifications
  - **New JIT CUDA kernel**:
  `python/sglang/jit_kernel/csrc/elementwise/fused_act_and_mul_quant.cuh`
    - Supports both SiLU  GELU and gelu_tanh activation functions
    - FP8 (e4m3fn) per-token-group quantization fused in the same kernel
    - Optional expert_ids filtering for EP mode
  - **Python wrapper**: Extended `python/sglang/jit_kernel/activation.py` with
  `run_activation_quant()`
  - **Integration in Triton MoE runner**:
    - `fused_moe.py`: Call fused kernel when conditions met, output FP8 tensor + scales directly
    - `fused_moe_triton_kernels.py`: Skip redundant quantization when input is already FP8
  - **Env gate**: `SGLANG_OPT_FUSED_ACT_QUANT` (default: enabled)
  - **Tests**: `test/registered/jit/test_fused_act_and_mul_quant.py`
  - **Benchmarks**: `test/registered/jit/benchmark/bench_fused_act_and_mul_quant.py`
  ### Gating conditions

  The fused kernel activates when ALL conditions hold:
  1. `SGLANG_OPT_FUSED_ACT_QUANT=1` (default)
  2. CUDA platform
  3. FP8 W8A8 quantization enabled
  4. Block-wise quantization with `block_shape[1] == 128`

**Warp-Synchronous Undefined Behavior / Potential Hang:**
At lines 89 and 92, threads can exit early from the kernel if `token_id >= num_tokens` or if the expert is filtered out (`expert_ids == -1`). However, at line 123, the active threads perform a warp-synchronous reduction using `__shfl_xor_sync` with a full mask of `0xffffffff`:
```cpp
local_max = fmaxf(local_max, __shfl_xor_sync(0xffffffff, local_max, mask));
```
In CUDA (especially on Volta and newer architectures with independent thread scheduling), calling `__shfl_xor_sync` with a mask that includes threads that have already exited or are inactive results in **undefined behavior** and can cause the GPU to hang or produce incorrect/garbage results.

**Recommendation:**
Instead of exiting early, use an `active` boolean flag to guard the memory loads and stores. For inactive or filtered threads, set `local_max = 0.0f` (which acts as the neutral element for the absolute maximum reduction) so that all threads in the warp remain active and safely participate in the `__shfl_xor_sync` reduction with the `0xffffffff` mask.

```
  const uint32_t tid = blockIdx.x * blockDim.x + threadIdx.x;
  const uint32_t token_id = tid / num_vecs;
  const uint32_t lane_id = threadIdx.x % 32;

  bool active = (token_id < num_tokens);
  if constexpr (kFilterExpert) {
    if (active && params.expert_ids[token_id / params.expert_step] == -1) {
      active = false;
    }
  }

  PDLWaitPrimary<kUsePDL>();

  float vals[kVecSize] = {0.0f};
  float local_max = 0.0f;

  if (active) {
    const uint32_t vec_offset = tid % num_vecs;
    const uint32_t gate_offset = token_id * (num_vecs * 2) + vec_offset;
    const vec_t gate_vec = load_as<vec_t>(params.input, gate_offset);
    const vec_t up_vec = load_as<vec_t>(params.input, gate_offset + num_vecs);

#pragma unroll
    for (uint32_t i = 0; i < kVecSize; ++i) {
      const float act_f32 = apply_activation_f32<kAct>(cast<fp32_t>(gate_vec[i])) * cast<fp32_t>(up_vec[i]);
      vals[i] = cast<fp32_t>(cast<T>(act_f32));
      local_max = fmaxf(local_max, fabsf(vals[i]));
    }
  }

  // Half-warp reduce (16 threads = one quant group)
  // Safe to use 0xffffffff mask because no threads exited early
#pragma unroll
  for (uint32_t mask = kThreadsPerGroup / 2; mask > 0; mask >>= 1) {
    local_max = fmaxf(local_max, __shfl_xor_sync(0xffffffff, local_max, mask));
  }

  // Scale computation
  float scale;
  if constexpr (kScaleUE8M0) {
    const float raw = fmaxf(local_max, kEps) / kFP8E4M3Max;
    const uint32_t bits = __float_as_uint(raw);
    const int32_t exp = static_cast<int32_t>((bits >> 23) & 0xFF) + ((bits & 0x7FFFFF) != 0);
    scale = __uint_as_float(static_cast<uint32_t>(exp) << 23);
  } else {
    scale = local_max / kFP8E4M3Max;
  }
  const float inv_scale = 1.0f / (scale + kEps);

  if (active) {
    const uint32_t vec_offset = tid % num_vecs;
    const uint32_t icol = vec_offset * kVecSize;
    fp8_t* const out_row = static_cast<fp8_t*>(params.output_q) + token_id * hidden_dim;
    float* const scale_row = static_cast<float*>(params.output_scale) + token_id * num_groups;

    // Quantize and vectorized store FP8 (8 bytes = 1x STG.64)
    {
      const float4 f4_0 = make_float4(
          vals[0] * inv_scale, vals[1] * inv_scale,
          vals[2] * inv_scale, vals[3] * inv_scale);
      const float4 f4_1 = make_float4(
          vals[4] * inv_scale, vals[5] * inv_scale,
          vals[6] * inv_scale, vals[7] * inv_scale);
      const __nv_fp8x4_e4m3 pack0(f4_0);
      const __nv_fp8x4_e4m3 pack1(f4_1);
      uint2 packed;
      packed.x = *reinterpret_cast<const uint32_t*>(&pack0);
      packed.y = *reinterpret_cast<const uint32_t*>(&pack1);
      *reinterpret_cast<uint2*>(out_row + icol) = packed;
    }

    // Store scale (one per group; lane 0 and lane 16 each own one group)
    if (lane_id == 0 || lane_id == 16) {
      scale_row[icol / kGroupSize] = scale;
    }
  }
```

**[correctness, blocking] Non-finite inputs become fp8 NaN codes.** `__nv_fp8x4_e4m3(float4)` uses SATFINITE, which saturates ±inf/out-of-range but converts **NaN to an fp8 NaN code (0x7f)**. The absmax above uses `fmaxf` (IEEE drops the NaN operand), so `inv_scale` stays finite and NaN values sail straight into the packed codes.

Every kernel this path replaces (`silu_and_mul` + `sglang_per_token_group_quant_fp8` — AOT v1/v2, Triton, and the unified kernel after #32188) clamps first: IEEE `fminf`/`fmaxf` return the non-NaN operand, so non-finite inputs quantize to ±448. CUDA-graph capture warmup runs the model over reused, uninitialized buffers; on CI runners those contain NaN bit patterns. Exactly this omission in #30924 broke the H100 deepep CI (`NaN detected! sampler: next_token_logits`), root-caused and fixed in #32188 — and this kernel sits on the default Triton-runner path with the env flag default-on.

Fix (bit-identical for finite inputs): a single-sided `fminf(v, 448.f)` before packing is sufficient — see #32296 for the argument (min kills NaN/+inf, SATFINITE handles -inf). Also `scale = local_max / kFP8E4M3Max` (L134) can store an exact `0.0` scale for an all-zero group; the family computes `max(amax, eps) / 448` and never emits 0.0 — worth matching while here. Please also add a poison test mirroring `test_per_token_group_quant.py::test_non_finite_inputs_are_sanitized`.

**[correctness, blocking-ish] `__shfl_xor_sync(0xffffffff, ...)` with early-exited lanes is UB.** Two divergent `return`s sit above this (L89 tail, L92 expert filter). Whenever `hidden_dim % 256 == 128` (i.e. `num_vecs % 32 == 16`) a warp straddles two tokens, so half the warp can exit while the other half executes a shuffle whose mask names the exited lanes — undefined behavior per the CUDA programming guide, and `compute-sanitizer --tool synccheck` will flag it.

Note your own e2e config hits the shape: Qwen3-235B moe_inter 1536 / TP4 = 384 → `num_vecs = 48`. The minimal test shape `(1, 256)` hits it too (lanes 16–31 exit at the tail). It happens to produce correct results on sm90 because the xor-butterfly (masks 8/4/2/1) stays within each 16-lane half — that's luck, not contract, and it isn't guaranteed on future archs.

Suggested fix: keep all lanes alive through the reduce — follow the in-tree `per_token_group_quant` flat kernel pattern (warp-uniform exit + tail duplication via `min(work_id, total-1)`), or predicate the loads/stores instead of returning. Precedent for this bug class: #20661 (rmsnorm small-hidden fix).
