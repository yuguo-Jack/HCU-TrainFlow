# [Test] Record per-step scheduling traces in the scripted runtime

[Upstream PR](https://github.com/sgl-project/sglang/pull/43895) · state: open · merged: False

## Original PR description

- With `SGLANG_TEST_SCRIPTED_RUNTIME_TRACE_DIR` set, each scripted run writes a JSONL trace: a header with the trace format and the server config, a `schedule` record per planned step, a `result` record per processed result, and a `paused` record per paused iteration.
- Each schedule record also holds what the scheduler's readers saw at the top of the iteration: the idle checks behind health check, pause and flush, the in-flight request set, and the load report.
- `python -m sglang.test.scripted_runtime.scheduling_trace OLD_DIR NEW_DIR` diffs two trace dirs; rids are relabeled in first-seen order so two runs of one commit compare equal. Traces whose headers differ are reported as a config mismatch.
- `SGLANG_TEST_SCRIPTED_RUNTIME_EXTRA_ENGINE_KWARGS` runs the same scripts under another server config.
- The DP-converted batch unit test stubs the new scripted scheduler hook.

No behavior change outside the scripted test runtime.
