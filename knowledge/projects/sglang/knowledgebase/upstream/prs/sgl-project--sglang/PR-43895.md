# [Refactor] scheduler: Write every request KV length through ReqKvInfo methods

[Upstream PR](https://github.com/sgl-project/sglang/pull/43895) · state: closed · merged: True

## Original PR description

- Add named length methods to `ReqKvInfo` (`allocate_extend`, `allocate_decode`, `allocate_spec_decode`, `allocate_prealloc`, `commit_prealloc`, `commit_decode`, `commit_finished`, `truncate_committed`, `truncate`, `free_tail`, `rewind`, `protect_prefix`, `record_insert`, `clear_tree_prefix`, `shield_swa_prefill`, `reset_for_retract`); each body is exactly the statements it replaces.
- Route every writer of `cache_protected_len`, `cache_inserted_len`, `kv_committed_len` and `kv_allocated_len` under `python/sglang/srt` through them: `mem_cache`, `session`, scheduler, schedule policy, batch result processor, PD decode, dLLM and beam search (28 sites).
- `Req.reset_for_retract` resets its KV fields through `ReqKvInfo.reset_for_retract`, the same subset as before.
- Add `test/registered/unit/managers/test_req_kv_lengths.py`: an AST guard over `python/sglang/srt` that fails, outside `ReqKvInfo`, on an assignment, augmented assignment or `del` of a length field, on `setattr` / `delattr` / `__setattr__` or a `__dict__` / `vars()` key naming one, on `ReqKvInfo(...)` or `dataclasses.replace(...)` keywords setting one, and on any use of `component_evicted_seqlens` (two unreachable `req.kv is None` constructor sites are allowlisted, and the allowlist must match exactly); plus unit tests pinning each method and the fields `reset_for_retract` resets.
- Add `ReqKvInfo.copy_evicted_seqlens`; the LMCache insert copies the evicted lengths through it.
- `test_decode_bookkeeping_ownership.py` counts the watermark methods at their call sites.
- Unit fakes that passed a `SimpleNamespace` as `req.kv` to a routed writer now use a real `ReqKvInfo`.

No behavior change, except that when `Req.reset_for_retract` hits its existing `holds_kv` assertion, the tree-prefix and mamba fields are no longer reset before the error is raised.
