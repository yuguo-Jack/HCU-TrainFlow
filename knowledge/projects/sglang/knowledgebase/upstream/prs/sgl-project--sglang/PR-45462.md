## Motivation

An expert ID of `-1` represents valid padding, including without expert parallelism. Reusing Marlin projection storage can expose stale values for those routes; clearing the entire allocation adds work to valid routing. Muse also needs its gate/up and down projections to share the original workspace budget.

## Changes

- Reuse one Muse projection workspace sized for `M * topk * max(2I, H)`. Finalization predicates inactive routes before reading payloads or scores, including poisoned inactive values, and preserves the existing product-rounding boundary.
- Add opt-in `zero_inactive_output` to native Marlin. Down projections complete inactive destinations within the existing kernel, including public `no_combine` output. The default preserves caller-owned inactive rows; active GEMM math, atomics and reduction choices stay unchanged.
- Let owned alignment producers optionally publish `[padded_token_count, inactive_prefix_blocks]` in one count allocation. An explicit consumer flag selects the packed read and existing compressed sorted scheduling. Scalar/external producers keep the checked fallback; EP keeps its generic path. Empty inputs, dirty allocation tails and graph replay retain defined count semantics.
- Preserve the upstream scratch callback ABI and accept scalar or one-element packed-router counts through a storage-sharing view. Ordinary Marlin and Muse opt into the count fact only with producers that actually publish it.

Review the alignment/count contract first, then native output completion, Muse workspace/finalization and the registered regressions. LoRA projection changes belong to #45681.

- Keep paired inactive-prefix counts independent of optional expert-map capacity completion, including combined-option graph replay coverage.
