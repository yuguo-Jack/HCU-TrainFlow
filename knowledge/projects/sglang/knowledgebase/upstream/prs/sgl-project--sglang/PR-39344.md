# [Fix] function_call: Unwrap spurious arguments/input wrapper in DeepSeek DSML parser

[Upstream PR](https://github.com/sgl-project/sglang/pull/39344) · state: open · merged: False

## Original PR description

## Motivation

Fixes #38924.

`DeepSeekV32Detector` (and the `DeepSeekV4Detector` / `DeepSeekV41Detector` subclasses) pass tool-call parameters through verbatim. The model sometimes wraps the real parameters in a spurious top-level `arguments`/`input` key, so the wrapper reaches the client in `message.tool_calls[].function.arguments` and any schema-validating client rejects the call (`'command' is a required property`). Shows up more often as context grows in multi-turn agent sessions; mirrors vllm-project/vllm#41240 / #48931.

| emitted | should be |
|---|---|
| `{"arguments": {"path": "/x"}}` | `{"path": "/x"}` |
| `{"arguments": "cd /x && ls"}` (bash) | `{"command": "cd /x && ls"}` |
| `{"input": {"path": "/x"}}` | `{"path": "/x"}` |
| `<｜DSML｜parameter name="arguments" string="true">cd /x</…>` | `{"command": "cd /x"}` |

## Fix

- `_unwrap_wrapped_arguments()`: no-op unless the object is exactly one wrapper key (`arguments`/`input`) that is not itself a declared property of the tool. Unwraps a dict value directly, decodes a JSON-object string (the double-encoded `string="true"` sub-case), and remaps a bare scalar onto the tool's sole property. Ambiguous cases are left untouched rather than guessed.
- Applied once per complete invoke in both `detect_and_parse` and `parse_streaming_increment`. Since #39632 the streaming path buffers a whole invoke before emitting, so the earlier partial-prefix hold-back logic from the first revision of this PR is gone; non-wrapped calls are untouched.

## Tests

8 regression cases in `test_deepseekv4_detector.py` (dict / scalar / `input` / XML / double-encoded wrappers, two negative-branch guards against over-unwrapping, and a wrapped-plus-well-formed parallel turn), each checked non-streaming and at 1-, 4-, and whole-message chunk widths.

- `test_deepseekv4_detector.py`: 33 passed; the 6 bug-guarding cases fail on `main`, the 2 negative-branch guards pass on both.
- `test_deepseekv41_detector.py`: 10 passed.
- `ruff format` / `ruff check` (pre-commit rule set) / `isort` clean.
