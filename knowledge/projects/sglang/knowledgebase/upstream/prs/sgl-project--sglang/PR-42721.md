# [Model] Support Clef and Clef-Flash decision models on /v1/systemone

[Upstream PR](https://github.com/sgl-project/sglang/pull/42721) · state: closed · merged: True

## Original PR description

## Motivation

[Clef](https://huggingface.co/Cloudflare/clef) (Qwen3.8-27B) and [Clef-Flash](https://huggingface.co/Cloudflare/clef-flash) (Qwen3.5-9B) are the decision models we released at Cloudflare. Each is a standard Qwen3.5 checkpoint plus a small joint schema head (`joint_head_config.json`, `joint_head.safetensors`). The head reads the backbone's final hidden states over one prompt that holds the state and every question, and returns one logit per allowed option of every question. Nothing is generated, so a request with 64 questions is a single prefill.

This PR serves the published checkpoints as-is on the existing `/v1/systemone` route, following the decision-models design. System One API clients, including the TypeSafe SDKs, work unchanged with no translation layer, and the route renders the exact prompt the head was trained with. Every new path is gated on a `Qwen3_5ForConditionalGeneration` checkpoint that ships `joint_head_config.json`, so nothing changes for any other model.

Closes #42409.

## Modifications

- **Detection** (`configs/model_config.py`, `arg_groups/model_hook.py`). `ModelConfig.joint_head_config` holds the checkpoint's `joint_head_config.json`. Such a checkpoint is served as one complete prefill per request: embedding mode with no radix cache, no chunked prefill and no CUDA graphs. It also requires TP=1 and PP=1, because the head reads full LM head rows.
- **Model** (`models/qwen3_5.py`). `Qwen3_5ForConditionalGeneration` replaces its pooler with `JointSchemaPooler` and loads `joint_head.safetensors` with `strict=True`. The checkpoint index leaves that file out, so the backbone loader never sees it.
- **Head** (`layers/joint_schema_head.py`, new). Parameter names match the checkpoint. One head pass scores a whole prefill batch:
  - token-wise steps run on the flat batch;
  - attention is variable-length per request, through FlashAttention;
  - span means come from FP32 prefix sums over each request's schema region only, so a long state costs no more than its memory projection.
- **Request plumbing** (`io_struct.py`, `tokenizer_manager.py`, `scheduler.py`, `schedule_batch.py`, `forward_batch_info.py`). `EmbeddingReqInput.decision_layout` carries each prompt's question and option spans and is threaded like `token_indices_to_pool`. The tokenizer manager:
  - checks the layout against the prompt after image placeholders expand, and returns 400 on a mismatch;
  - refuses a layout for any other model;
  - on a Clef server, refuses embedding requests that have no layout. Health checks are exempt.
- **Serving** (`entrypoints/systemone/joint_schema.py`, new; `entrypoints/systemone/serving.py`).
  - The prompt is built piece by piece, following the checkpoint's reference `encode_record`, and sent as one request.
  - Per-question softmax probabilities are mapped back to request order and go through the route's existing `_answer`, so `confidence` uses the same formulas as other models on the route.
  - `x_label_mass` is omitted, because the head scores only the allowed options.
  - LoRA adapters and `chat_template_kwargs` are refused.
- **Warmup** (`entrypoints/http_server.py`). Startup warmup goes through `/v1/systemone`, because a Clef server refuses plain `/encode`.
- **Tests** (`test/registered/unit/layers/test_joint_schema_head.py`, `test/registered/unit/entrypoints/systemone/test_joint_schema.py`, both new).
  - Decision layouts round-trip, shift with expanded images, and reject layouts that do not fit the prompt.
  - The batched head matches a per-request loop over the stock torch modules (1-GPU CI; skipped on CPU).
  - The prompt is the trained one, its spans hold each question and option in head order, long states are truncated, and image placeholders precede the state.
  - Answers map head order back to the request, and a Clef server refuses `chat_template_kwargs`, LoRA, and `/v1/decisions`.

## Accuracy Tests

**Setup:** 1× H200, BF16, this PR on `main` at `1e1bdee`, with HF weights `Cloudflare/clef@2f3de3dd` and `Cloudflare/clef-flash@17f0b0ad`.

**Reference:** the checkpoint's own `joint_schema_model.py` (`load_release_model`, `encode_record`, model forward) on transformers 5.17. It runs over 12 payloads covering 3 and 64 questions, permuted options, 255 options, states up to 32k tokens, and 1 or 4 images.

| Model | Top choice vs reference | Max \|Δp\| vs reference | Prompt tokens vs reference |
|---|---|---|---|
| Clef-Flash | 100% (12/12 payloads) | 0.011 | identical, images included |
| Clef | 100% (12/12 payloads) | 0.068 | identical, images included |

The Clef gap is BF16 noise on both sides. Against an FP32 run of the reference, SGLang BF16 is as close as the BF16 reference itself, or closer. Top choices match FP32 64/64 in every case:

| Payload | Reference BF16 vs FP32, max \|Δp\| | SGLang BF16 vs FP32, max \|Δp\| |
|---|---|---|
| 64 questions | 0.036 | 0.038 |
| 64 questions, 2k-token state | 0.078 | 0.032 |
| 64 questions, permuted options | 0.035 | 0.034 |

## Speed Tests and Profiling

c=1 on 1× H200, BF16, median of 25 requests after warmup:

| Model | 3 questions (511 tokens) | 64 questions (6.5k tokens) | 3 questions × 255 options (8.8k tokens) |
|---|---|---|---|
| Clef-Flash | 38 ms | 186 ms | 247 ms |
| Clef | 67 ms | 572 ms | 755 ms |

**Under load:** 64 mixed requests at c=16 (8 payload types, text and images, 211k prompt tokens in total) take 5.4 s on Clef-Flash and 17.6 s on Clef. Their answers match c=1, with max |Δp| of 0.0032 and 0.0049 and no choice changes.

**Refusals:** `/v1/decisions`, `/encode`, `chat_template_kwargs` and LoRA requests return 400, and `/health_generate` returns 200.
