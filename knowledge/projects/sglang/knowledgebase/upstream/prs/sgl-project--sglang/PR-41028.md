# [HiCache] Fix Mooncake registration for split MLA host buffers

[Upstream PR](https://github.com/sgl-project/sglang/pull/41028) · state: open · merged: False

## Original PR description

**Summary**

Fix incomplete zero-copy memory registration for MLA host pools using the page_first_kv_split layout.

This layout allocates separate K, V, Indexer, and optional Indexer-scale buffers, but kv_buffer aliases only K. Without get_hybrid_pool_buffer(), Mooncake falls back to registering only K, while get_page_buffer_meta() also returns pointers into the other allocations. Accessing these unregistered buffers causes TRANSFER_FAIL errors and transfer timeouts with GLM-5.2 + HiCache + Mooncake on Ascend.

**Changes**

Implement MLATokenToKVPoolHost.get_hybrid_pool_buffer() to expose all non-None physical backing buffers for the split layout.
Preserve single-buffer registration for ordinary layouts.
Add regression coverage for optional Indexer/scale buffers, FP8 storage, differing KV/Indexer layer counts, ordinary layouts, and dummy pools.
Verify registration pointers and byte lengths, including coverage of every zero-copy page range.

**Testing**

All four regression test methods passed on an NPU machine, including split-buffer registration, zero-copy page-range coverage, ordinary layouts, missing optional attributes, and dummy pools.
Validated GLM-5.2 + HiCache + Mooncake in an actual NPU environment.
Confirmed that removing the fix causes five regression scenarios to fail due to K-only registration.
Passed Ruff lint and formatting, isort, Python syntax, and diff whitespace checks.
