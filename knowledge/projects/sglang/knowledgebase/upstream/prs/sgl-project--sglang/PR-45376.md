# [Fix] moe: Publish a server config in the CUTLASS runner dispatch-format and placement tests

[Upstream PR](https://github.com/sgl-project/sglang/pull/45376) · state: closed · merged: True

## Original PR description

Follow-up to [#43363](https://github.com/sgl-project/sglang/pull/43363), merged today: it broke two CPU unit tests on `main`, and this test-only PR fixes them. Sorry for the breakage.
cc @Fridge003 (merged [#43363](https://github.com/sgl-project/sglang/pull/43363); added the dispatcher test in [#44666](https://github.com/sgl-project/sglang/pull/44666)) and @Jiminator (added the placement test in [#44518](https://github.com/sgl-project/sglang/pull/44518)).
Ready to run: `/rerun-test test/registered/unit/layers/moe/test_flashinfer_dispatcher.py`. `test_moe_runner_config_placement.py` runs only in the Intel CPU suite (`stage-b-test-cpu-intel`), so `/rerun-test` on ubuntu-latest skips it.

## Summary

- **Fixes two CPU unit tests that fail on `main` since [#43363](https://github.com/sgl-project/sglang/pull/43363) merged.** Both call the FlashInfer CUTLASS MoE runner directly without publishing server args. [#43363](https://github.com/sgl-project/sglang/pull/43363) made the runner read the `disagg` config to size its tuning range, so they now raise `ValueError: config namespace 'disagg' not published`.
- **Test-only change; no runtime code changes.** Each call is wrapped in `get_context().override_server_args(model_path="dummy")`, the same pattern the neighbouring tests in these files already use.

## Motivation

Since #43363, the CUTLASS MoE runner (`python/sglang/srt/layers/moe/moe_runner/flashinfer_cutlass.py`) reads `get_disagg()` and the prefill-chunk settings on every call. That PR also updated the tests that existed at its base. Two tests were added on `main` after that base, and they call the runner without any server args published:

| Test | Added in | CI suite | Result on `main` `f8fd41c36e4` |
|---|---|---|---|
| `test/registered/unit/layers/moe/test_flashinfer_dispatcher.py::TestFlashinferRunnerDispatchFormats::test_cutlass_preserves_prefill_and_decode_combine_formats` | #44666 | `base-a-test-cpu` | error (both subtests) |
| `test/registered/unit/layers/moe/test_moe_runner_config_placement.py::test_sm120_nvfp4_dispatch_uses_live_layer_placement` | #44518 | `stage-b-test-cpu-intel` | fail |

Both fail with `ValueError: config namespace 'disagg' not published`, raised from `_cutlass_moe_tune_max_num_tokens`. A real server always publishes these configs, so serving is not affected. Only these tests are.

## Modifications

- `test_flashinfer_dispatcher.py`: add `get_context().override_server_args(model_path="dummy")` to the existing `with (...)` block around `fused_experts_flashinfer_to_flashinfer_cutlass`.
- `test_moe_runner_config_placement.py`: wrap the `_run_flashinfer_cutlass` call in the same context manager. This is the pattern `_kernel_placement` in the same file uses.

These two tests and [#43363](https://github.com/sgl-project/sglang/pull/43363)'s own `test_flashinfer_cutlass_swiglu_params.py` are the only tests under `test/` that call the CUTLASS MoE runner entry points directly.
