# [Fix] beam_search: Allow beam search with SWA hybrid caches

[Upstream PR](https://github.com/sgl-project/sglang/pull/44434) · state: open · merged: False

## Original PR description

# [beam] Allow beam search with SWA hybrid caches

## Summary

Relaxes the beam-search admission gate so requests are accepted when the
KV cache is an SWA hybrid (`supports_swa()`), while keeping the rejection
for mamba hybrids. Previously any SWA model got:

> `Beam search is not supported with SWA/mamba hybrid caches.`

## Why SWA is safe here

The unified hybrid SWA allocator mints **one virtual id space** shared by
the full-attention and sliding-window sub-pools (`UnifiedSWATokenToKVPoolAllocator`:
one `alloc` binds both sides under the same virtual id; both read paths
translate from the virtual id). Every beam fork primitive operates purely
on `req_to_token` virtual ids and never touches pool internals:

- `alias_members_prompt_kv` — copies the leader's prompt virtual-id mapping;
- `remap_kv_mapping` — shuffles virtual ids between survivor rows;
- `collect_orphan_slots` / `free` / `free_member_rows` — reclaim virtual
  ids, with the allocator's own per-side tombstone filters handling the
  sliding-window side.

So both pools follow reparenting automatically. Mamba stays rejected: its
state checkpoints do not survive row remapping. No scoring/selection logic
is touched; the length-normalized `beam_score` convention is unchanged.

## Test plan

Engine: H100, Llama4x-style 16-layer hybrid model (sliding window 2047 on
13/16 layers, full attention on 4), triton attention backend, `page_size=1`,
pytorch sampler, served from the `prod-inference-nvidia` image.

- `beam_width=10, n=3` and `beam_width=100, n=100, max_new_tokens=2` on a
  production retriever prompt: accepted (previously HTTP 400), 100
  sequences returned, best `[200008] @ -0.061` — identical to greedy
  step-1 on the same prompt to 4 decimals.
- 40-query soak (20 greedy + 20 `beam_width=10` interleaved, 20 distinct
  prompts): 20/20 step-1 agreement between greedy and beam best, engine
  healthy throughout, no allocator/leak warnings in logs.
- Distribution parity vs an independent serving stack on the same 20
  prompts: 17/20 step-1 agreement; the 3 diffs are beam-vs-greedy
  selection effects on near-ties (0.14-nat margin), not distribution
  divergence.
- Non-SWA models are unaffected: the only behavioral delta is that
  `supports_swa() and not supports_mamba()` no longer short-circuits to
  the error string.

## Notes for reviewers

- The error string changes from `"... SWA/mamba hybrid caches."` to
  `"... mamba hybrid caches."` — flagging in case anything matches on it.
- If your model pairs SWA with a stateful recurrence (mamba), it is still
  rejected via `supports_mamba()`.
