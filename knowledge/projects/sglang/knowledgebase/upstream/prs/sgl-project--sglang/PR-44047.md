# [Fix] Validate sampling bounds and preserve chat output limits

[Upstream PR](https://github.com/sgl-project/sglang/pull/44047) · state: open · merged: False

## Original PR description

## Motivation

Invalid sampling values could pass chat request parsing and reach serving. Output-limit handling also used `max_completion_tokens or max_tokens`, causing an explicit zero to fall back to the legacy limit.

Validate these inputs and use consistent output-limit precedence. For example, `max_completion_tokens=0` with `max_tokens=5` now resolves to zero.

## Modifications

| Scope | Behavior |
| --- | --- |
| `n` | Enforce `[1, MAX_N]`, where `MAX_N=128`, in Python chat/completion request models and shared sampling verification. Shared verification also rejects non-integer values. |
| `top_logprobs` / `logprobs` | Enforce `[0, 20]` for chat. Positive counts require `logprobs=true`; omitted, null, and zero counts retain their existing handling. |
| Temperature | Require a finite chat temperature in `[0, 2]`, preserving omitted and null defaults. |
| Logit bias | Share `[-100, 100]` bounds between chat parsing and engine verification. Engine verification rejects malformed types, nonfinite values, and oversized integers with `ValueError`. |
| Output limits | Validate both chat output-limit fields independently as nonnegative. Use `effective_max_tokens` for context validation and sampling conversion, preserving `max_completion_tokens` precedence even when zero. |
| Stop-token IDs | Reject IDs outside `[0, vocab_size)` during shared sampling verification. |

Changes are grouped into six commits by scope, with regression coverage in each.
