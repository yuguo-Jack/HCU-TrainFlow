# [XPU] split Intel nightly into kernel-main and kernel-wheel jobs

[Upstream PR](https://github.com/sgl-project/sglang/pull/41857) · state: closed · merged: True

## Original PR description

The Intel XPU nightly now runs two setups:

| Job | Image | sglang | sgl-kernel-xpu | Suites |
|---|---|---|---|---|
| `nightly-xpu-kernel-main-{1,2,4,8}-gpu` (renamed from `nightly-xpu-*`) | `intel/sglang-dev:latest-kernel-main` | main | main (built from source) | `nightly-xpu-kernel-main-{1,2,4,8}-gpu` (renamed from `nightly-xpu-{1,2,4,8}-gpu`) |
| `nightly-xpu-kernel-wheel-1-gpu` (new) | `intel/sglang-dev:latest` | main | prebuilt wheel from `pyproject_xpu.toml` | `stage-a-test-1-gpu-xpu` + `stage-b-test-1-gpu-xpu` (PR CI, 39 files), then `nightly-xpu-kernel-wheel-1-gpu` (9 files) |

Both images are published by `release-docker-intel-xpu-nightly.yml` (#41650).

Schedule (single `intel-bmg-nightly` runner, so jobs run one after another):

- `nightly-xpu-kernel-wheel-1-gpu`: 22:30 IST (`0 17 * * *` UTC)
- `nightly-xpu-kernel-main-*`: 01:00 IST (`30 19 * * *` UTC)

Each cron runs only its own jobs; `workflow_dispatch`, push and `workflow_call` runs still run all of them. The concurrency group includes the cron, so one scheduled run doesn't cancel the other.

## Changes

- `nightly-test-intel.yml`:
  - Rename the four existing jobs and pass `--image-tag latest-kernel-main` to `xpu_ci_start_container.sh`.
  - Add `nightly-xpu-kernel-wheel-1-gpu`. It installs the PR CI test deps and the diffusion extra's deps (read from `pyproject_xpu.toml`) under a constraints file that pins the image's torch/sglang/kernel builds, so the image itself is tested. It runs the PR CI suites with the same 180-min budget and `--enable-retry`, then runs `nightly-xpu-kernel-wheel-1-gpu --nightly`. The second step runs even if the first fails. The job timeout is 600 min because the two suites together (~5h est.) exceed the 360-min default.
  - Split the schedule into two crons (above) and key the concurrency group on the cron.
  - Add the new job to `check-all-jobs`.
- `nightly-xpu-kernel-wheel-1-gpu`'s PR CI step: pass `--timeout-per-file 600 --retry-timeout-increase 0` to the stage-a + stage-b run. The slowest passing file in recent runs took 487s; hung files (e.g. `test_xpu_basic`, `kv_canary/test_self_unit_req_to_expected_token_ids_manager`) ran the full 30 min before retrying. The same cap for `pr-test-xpu.yml`, plus fail-fast per-file overrides, is in #42048.
- Rename the `nightly-xpu-{1,2,4,8}-gpu` suites to `nightly-xpu-kernel-main-{1,2,4,8}-gpu` (test registrations, `run_suite.py`, `--suite` args, metrics artifact names). This includes `test_fused_inplace_qknorm_rope_xpu` (added on main by #40190), which goes to `kernel-main` only because it imports the new `sgl_kernel.fused_inplace_qknorm_rope` op, which the released wheel may not have.
- `xpu-ci-job-monitor.yml`: point the per-model report at the renamed `nightly-xpu-kernel-main-*-metrics` artifacts.
- `run_suite.py`: add `nightly-xpu-kernel-wheel-1-gpu` to the XPU nightly suites.
- Register these tests to `nightly-xpu-kernel-wheel-1-gpu`. They keep their `nightly-xpu-kernel-main-1-gpu` registration and existing `est_time`:
  `test_deepseek_ocr_triton`, `test_gemma_4_e2b`, `test_spec_eagle_parity`, `test_xpu_classification`, `test_xpu_embedding`, `test_xpu_rerank`, `test_xpu_reward`, `test_xpu_zimage_turbo`, `test_deepseek_ocr_2_olmbench`.

The workflow file name is unchanged, so `release-branch-cut.yml` and `ci_failures_analysis.py`, which refer to it by file name, are unaffected.

I would avoid A/B for PR #41857. They describe kernel provenance, not test stages, so the names are opaque and easy to confuse with PR CI’s stage-a and stage-b.

Other backends use descriptive names: NVIDIA includes the nightly-test-nvidia.yml, NPU distinguishes nightly-test-npu.yml, and AMD has a nightly-test-amd.yml. The XPU image publisher already calls its variants main and wheel.

I recommend `nightly-xpu-kernel-main-{1,2,4,8}-gpu` and `nightly-xpu-kernel-wheel-1-gpu`, consistently across jobs, suites, and artifacts.
