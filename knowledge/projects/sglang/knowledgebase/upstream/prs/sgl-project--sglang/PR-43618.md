# fix(metrics): report per-iteration prefill variance

[Upstream PR](https://github.com/sgl-project/sglang/pull/43618) · state: open · merged: False

## Original PR description

## Summary

Fix scheduled `var_prefill_length` to describe the current prefill iteration instead of the full original prompts. Match vLLM: accumulate `2 * prefix_length + chunk_length`, then divide the population variance by four. For prefixes `[4, 2]` and chunks `[1, 3]`, the result is `0.25`, independent of future prompt tokens.

Three executable production lines. The existing accumulator, schema, and other counters are unchanged. No new tests or assertions are added; one existing mixed-batch fixture supplies the chunk lengths required by the fix.

## Validation

**Correctness (archived GPU implementation):** **7 baseline mismatches → 0 candidate mismatches** across 56 received prefill-containing records. Emitted-metric coverage for progressed chunks with multiple prefills and mixed batches with multiple prefills remains incomplete after ten attempts because of existing zero-timer suppression; that issue is deferred.

**Performance:** **Qwen/Qwen3-0.6B**, one H100 PCIe 80 GB, BF16/TP1, exactly **8,192 input / 1,024 output tokens**, chunk size 512, overlap/mixed chunks/radix cache enabled, raw streaming completions. AIPerf 0.13.0; five paired rounds with rotated variant order. All **60 fresh-server runs** completed: **8,000 measured requests**, 3,280 excluded warmups, zero request errors, and zero FPM stream gaps.

“New” is the per-iteration variance fix; “old” is the baseline with the existing KV-counter correction and full-prompt variance. Each is compared with its own FPM-disabled baseline. Positive means worse: throughput loss or latency increase; negative means improvement. Both implementations show measurable FPM enablement cost at concurrency 1; all on/off intervals at concurrency 32 and 128 include zero. All direct new-on/old-on intervals also include zero, which does **not** establish equivalence. The concurrency-1 ITL ratio-of-ratios is **+0.082% [0.027%, 0.137%]**, one of 45 pointwise comparisons without multiplicity adjustment. All valid rounds were retained. GPU clocks were not locked and varied at higher concurrency; throughput includes fill/drain, TTFT includes queueing, and ITL p50 is the median of per-request mean decode latency.

These results compare archived baseline `9848e3fa` with candidate `d43f8851`, both derived from audited `968726f3`; they were not rerun on the PR's current upstream base. This is the Qwen3 variance campaign, separate from the earlier Qwen2.5-7B counter-fix campaign.
