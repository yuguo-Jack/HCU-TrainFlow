# [Perf] dsa: Enable the v2 packed prefill top-k on CUDA

[Upstream PR](https://github.com/sgl-project/sglang/pull/48407) · state: open · merged: False

## Original PR description

## Motivation

- On CUDA, the DSA indexer's prefill top-k for a PAGED extend uses the legacy `topk_transform_prefill_kernel`. That's the
  path GLM-5.x prefill takes with the trtllm DSA backends and an FP8 KV cache. The kernel is latency-bound per row and
  slow at long context.
- SGLang already has an exact v2 kernel for this layout: `topk_packed_kernel`, with per-row windows and page-table
  output. It is compiled only under `USE_ROCM`, although nothing in it is AMD-specific.
- On GB300 with GLM-5.2 NVFP4, the legacy kernel is 14% of prefill kernel time at a long cached-prefix turn.

## Modifications

- `topk_v2.cuh`: compile `topk_packed_kernel` and `TopKKernel::transform_packed` on every backend; this drops the two
  `#ifdef USE_ROCM` guards.
- `topk.py`: export `topk_transform_packed` unconditionally. `dsa_topk_backend.py`: the packed PAGED branch now also runs
  on CUDA. XPU has no packed op and stays on the legacy kernel, and unsupported shapes still fall back.
- `test_topk_v2.py`: the packed tests run on CUDA. Two new tests:
  - `test_topk_v2_packed_exact`: exact top-k with ties, unaligned starts, scattered page tables, rows shorter than k, and
    row chunks;
  - `test_topk_v2_packed_dsa_dispatch`: the DSA dispatch reaches the packed kernel and matches the legacy kernel.

## Accuracy Tests

- `test_topk_v2.py` on GB300: 338 passed, 26 skipped, on the Oct-28 and the Nov-4 SGLang nightly images. Every skip
  predates this change (CUDA cluster path, ROCm-only).
- Real GLM-5.2 indexer logits, 133,632 rows: the top-k matches `torch.topk` exactly; ties at the k-th score are
  interchangeable.
- GSM8K, 200 questions, real acceptance: 0.930 on main, 0.945 and 0.965 with this PR (two runs). The standard error is
  about 1.7 pp, so this is unchanged. On the Nov-4 image, GSM8K-20: 0.90 on both arms (accept length 1.94 / 1.95).

## Speed Tests and Profiling

GB300, one tray, GLM-5.2 NVFP4, DEP4 prefill server (below), `lmsysorg/sglang:nightly-cu134-20261028-86f72e5` (Oct-28
SGLang nightly image) with and without the patch. The table is uncached prefill tokens/s per GPU over two runs with the
arm order swapped.

| workload | main | this PR | Δ |
|---|---:|---:|---:|
| warm: 118k-token shared prefix + 10k new tokens, 32 concurrent, 4 reps per run | 12,342 | 13,633 | **+10.5%** (+10.9%, +10.1%) |
| cold: 32k new tokens, 16 concurrent | 14,531 | 14,817 | +2.0% |
| cold: 128k new tokens, 8 concurrent | 10,569 | 11,981 | +8% / +19% (two single runs) |
| prefill top-k kernel time, µs per uncached token (warm, profiled) | 14.3 | 4.0 | −72% |

Re-check on `lmsysorg/sglang:nightly-cu134-20261104-27aedf7` (Nov-4 SGLang nightly image, current main) with this
branch: warm 118k + 10k, 2 reps, 11,962 → 14,083 tokens/s per GPU (**+17.7%**; one run, main first). The profiled warm
run shows only `topk_packed_kernel` for the prefill top-k (main: `topk_transform_prefill_kernel`).

```bash
python3 -m sglang.launch_server --model-path nvidia/GLM-5.2-NVFP4 --trust-remote-code --quantization modelopt_fp4 \
  --kv-cache-dtype fp8_e4m3 --context-length 1048576 --mem-fraction-static 0.8 \
  --tensor-parallel-size 4 --data-parallel-size 4 --expert-parallel-size 4 --enable-dp-attention --enable-dp-lm-head \
  --load-balance-method total_tokens --chunked-prefill-size 65536 --max-prefill-tokens 16384 --max-running-requests 164 \
  --moe-runner-backend flashinfer_cutlass --fp4-gemm-backend flashinfer_cutedsl --bf16-gemm-backend cutedsl \
  --dsa-paged-mqa-logits-backend cutedsl --disable-cuda-graph \
  --speculative-algorithm EAGLE --speculative-num-steps 1 --speculative-eagle-topk 1 --speculative-num-draft-tokens 2
# Client: token-id prompts, max_tokens=1, closed loop; the shared prefix is sent once per DP rank before timing.
```
