# [Perf] [Intel] gemma4: Extend BF16 prefill GEMM to intermediate rows

[Upstream PR](https://github.com/sgl-project/sglang/pull/44936) · state: open · merged: False

## Original PR description

## Motivation

Gemma4 E2B's BF16 XPU prefill GEMM fast path is restricted to exactly 4096 rows, leaving useful intermediate shapes on the ordinary projection/activation path. This admits 256, 1024, 2048 and 4095 rows when the loaded native library explicitly reports support.

Stacked on #44925, with the existing 4096-row path preserved. Companion native PR: https://github.com/sgl-project/sgl-kernel-xpu/pull/561 (depends on sgl-kernel-xpu#559).

## Modifications

Query native capability independently for `(256, 1024, 2048, 4095, 4096)` at each projection width. Dispatch the fused GEMM only for reported row counts. Missing/false queries and older 4096-only wheels preserve the original 4096-row standalone-lookup/native paths. Unadmitted shapes use the parent model path. Existing hardware, dtype, TP, weight, backend, hook, delegated-method and gradient guards remain; add a 32-bit addressing bound.

Activation and PLE retain their existing 4096-row dispatch. Extend the existing integration fixture with admitted shapes, compile/replay, ordinary-path fallback checks, and explicit legacy-wheel capability coverage.

## Accuracy Tests

- All three existing XPU model integration files pass: activation lookup, PLE add/scale, and prefill GEMM. The GEMM fixture covers both widths, changed live operands, compile/replay, hooks/backend fallbacks, and missing/false/wide-only/4096-only capability queries.
- Companion final native binary: 59 pytest cases pass. Across 35 trained layers × 5 admitted row counts × 3 input scales, all 525 operator comparisons match Torch projection plus native activation exactly in BF16 words.
- Full serving A/B: all 216 one-token outputs match. Full 16-token text/token-ID/logprob records match exactly in 23/28 cases. Differences occur at M256 index2 (top-five logprobs) and the four M512 cases; an identical-baseline rerun independently reproduces logprob differences in these same five cases. Two M512 text/token-ID sequences differ in this A/B; none differ in that shorter baseline-repeat compatibility check, so the cause of output variation remains open. M512 retains the parent dispatch. Longer decode text matches are 124/128, 585/640 and 1198/1536 at concurrency1/8/32. Thus this evidence does not establish universal output parity. No new model accuracy score was run.

## Speed Tests and Profiling

Intel Arc Pro B70, TP1, unchanged BF16 target/assistant snapshots, same full decode graphs and NEXTN settings, prefix cache disabled in both arms. Compare parent `a3c379de38` against `a2dfdf0eb0`, using the same 89 native binaries in both arms; the parent only dispatches this GEMM at 4096 rows.
