# [Perf] diffusion-sdpa: Use a lazy lower-right causal bias when Sq != Sk

[Upstream PR](https://github.com/sgl-project/sglang/pull/47094) · state: open · merged: False

## Original PR description

## Motivation

`SDPAImpl.forward` handles causal attention with `Sq != Sk` by materializing a dense `Sq x Sk` bool mask on every call (`torch.ones(Sq, Sk).tril(Sk - Sq)`). The live caller is HunyuanImage3: its cross-attention is a `causal=True` `LocalAttention`, with q from the hidden states and k/v from `kv_states`. It reaches this path whenever the SDPA backend is selected (e.g. the SM12x default).

A dense mask has two costs on CUDA:
- **Memory:** O(Sq*Sk) allocated and read on every call.
- **Kernel choice:** SDPA cannot use the flash kernel with an explicit mask.

## Modifications

- **Eager path:** pass `torch.nn.attention.bias.causal_lower_right(Sq, Sk)` instead of the dense mask. `CausalBias` routes to flash attention, or to memory-efficient attention with a lower-right custom mask type, without materializing anything. It falls back to materializing only where neither kernel applies (e.g. CPU), which matches the current behavior.
- **Compiled path:** keep the dense mask while Dynamo is tracing. On torch 2.14, constructing `CausalBias` inside a compiled region is a graph break, and an error under `fullgraph=True`.
- **Unchanged:** `Sq == 1` (no mask), `Sq == Sk` (`is_causal=True`), and the lower-right alignment.

## Tests

Added `TestSDPACausalShorterQuery` to `test/unit/test_cuda_attention_backend.py`. It runs on CPU and asserts two things:
- `SDPAImpl` hands SDPA a `CausalBias`, not a dense tensor.
- Output equals an explicit lower-right reference, with GQA (4 q heads, 2 kv heads).

The second check also guards against a rewrite to plain `is_causal=True`, which is top-left aligned and gives different results when `Sq != Sk`.

Results:
- **Before the fix:** the new test fails; the recorded mask is a dense bool `8x32` tensor.
- **After the fix:** `test_cuda_attention_backend.py` passes (26 passed, 2 skipped). The SDPA routing and priority test files also still pass.
- **Ad hoc compile check:** `SDPAImpl.forward` with `Sq != Sk` under `torch.compile(fullgraph=True)` compiles and matches eager.

## Accuracy Tests

Lower-right causal semantics are unchanged; the unit test checks numerical equality against the previous mask.

## Speed Tests and Profiling

Microbenchmark on A100-SXM4-40GB, torch 2.14.1+cu130, bf16, 32 heads, head dim 128. `F.scaled_dot_product_attention` with the old dense mask (mask construction included) vs `causal_lower_right`:

| Sq | Sk | dense mask | lazy bias | speedup | peak MB |
|---|---|---|---|---|---|
| 256 | 1024 | 0.152 ms | 0.087 ms | 1.74x | 20.8 -> 32.1 |
| 1024 | 4096 | 1.283 ms | 0.613 ms | 2.09x | 92.0 -> 80.1 |
| 2048 | 4096 | 2.069 ms | 0.672 ms | 3.08x | 120.0 -> 96.3 |
| 4096 | 8192 | 7.081 ms | 2.272 ms | 3.12x | 288.0 -> 192.5 |
| 4096 | 16384 | 14.080 ms | 5.103 ms | 2.76x | 512.0 -> 320.5 |

Max abs diff vs the dense path is within bf16 tolerance (<= 2e-3). End-to-end HunyuanImage3 latency not measured.

Note on `Sq > Sk`: torch warns that lower-right causal can produce NaN for the leading fully-masked rows. The CPU math path returns 0 for those rows, the same as before. No current caller has `Sq > Sk`.
