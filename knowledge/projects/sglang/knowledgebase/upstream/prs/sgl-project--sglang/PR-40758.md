# [Bug][openai] Escape literal DSV4.1 image placeholder in user text

[Upstream PR](https://github.com/sgl-project/sglang/pull/40758) · state: closed · merged: False

## Original PR description

## Summary

Fixes #39274.

User/tool/reasoning text that quotes the literal `<｜deepseek_image｜>` token was hard-rejected with HTTP 400. Clients that keep the failed turn in history then wedge the conversation on every follow-up.

This PR follows the same neutralize pattern as Kimi: rewrite a user-supplied occurrence to the ASCII-pipe spelling `<|deepseek_image|>` instead of raising. Genuine `image` / `image_url` blocks still insert the real placeholder.

## Changes

- Add `IMAGE_PLACEHOLDER_ESCAPED` and escape helpers in `encoding_dsv41.py`
- Replace `_validate_no_image_sp_tokens` raise paths with escape-in-place for `content`, `reasoning_content`, text blocks, and string `tool_result` content
- Add CPU unit tests covering escape paths plus a control that real `image_url` still inserts the genuine token
