# [Doc] cookbook: Mirror SA cluster NCCL_CUMEM_ENABLE in AgentX launches, fix GPU counts

[Upstream PR](https://github.com/sgl-project/sglang/pull/44228) · state: closed · merged: True

## Original PR description

[by Claude Code]

## Motivation

The cookbook's **Agentic Long-Context Deployment** sections (#42726, #43083, #43799, #43983, #44065) on GLM-5.2, DeepSeek-V4, DeepSeek-V4.1, Qwen3.5 and Qwen3.8-Flash-Next mirror SemiAnalysis InferenceX AgentX submissions as raw launch commands, each linked to the run that measured it. A review of [InferenceX #3953](https://github.com/SemiAnalysisAI/InferenceX/pull/3953) found two places where the pages differ from what SemiAnalysis actually ran:

1. **`NCCL_CUMEM_ENABLE=1` was missing from many worker environments.** SemiAnalysis's B300, B200, GB200 and GB300 clusters export it into every worker container, and most recipes do not set it themselves. SGLang sets it to `int(enable_symm_mem)` when it is unset ([`engine.py`](https://github.com/sgl-project/sglang/blob/07c8f7294daa12087e969c89a11f773d36b9d42d/python/sglang/srt/entrypoints/engine.py#L1658-L1659) at `07c8f729`, one of the pinned images). A reader who copied a single-node command without `--enable-symm-mem` therefore ran with cuMem off, while SemiAnalysis ran with it on.
2. **The GPU count on many deployment chips was wrong.** The chip counted whole nodes, so a TP4 engine on 4 of an 8-GPU B300 node showed "8 GPUs".

This PR also pins [InferenceX #3953](https://github.com/SemiAnalysisAI/InferenceX/pull/3953) to its measured run, which now has a `/use` comment. Apart from the generated data files, the only change is one line in the AgentX component (`_agentx.jsx`): the chip now says "1 GPU" instead of "1 GPUs", because single-GPU deployments now appear. Page text, Deployment panels and Playgrounds are unchanged.

    - GB200 cluster: [run 38266927261](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/38266927261).
    - GB300 cluster: [run 38221097558](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/38221097558).
  - **Bash-launcher lanes.** On the B300 and B200 clusters these also started their servers through the same `srun --container-image` path, so they ran in the same environment.
  - **Not changed.** The H200 cluster does not set it ([run 34857875250](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/34857875250)). Lanes on three clusters with only bash-launcher runs (one B200, one B300 and the H100 cluster) have no worker fingerprint, so they are unverified and left unchanged. NIC names, log levels and timeouts from the cluster environment stay out, as before.
  - **Scope.** 22 lanes and 978 of the 2,144 command sets change, and only by this variable.
    - **Behavior changes (642 command sets in 16 lanes).** These are single-node workers without `--enable-symm-mem`, where the reader's SGLang would otherwise turn cuMem off:
      - DeepSeek-V4: B200 Dynamo agg, B200 and B300 SGLang HiCache MTP, B300 EAGLE.
      - DeepSeek-V4.1: B200, B300, GB200 and GB300 DSpark, GB300 Dynamo agg.

      - Qwen3.8-Flash-Next: B200 and GB300.
    - **Already 1 (the other 336).** SGLang sets it to 1 anyway: `--enable-symm-mem` forces it (Qwen3.5 B200/B300/GB300 lanes, GLM-5.2 B300 TP4 c32), and multi-node GB200/GB300 workers default it on (DeepSeek-V4 GB200/GB300 Dynamo agg). There the variable only makes the measured environment explicit.
- **GPU count (fix).** A deployment's chip now counts the GPUs its workers use: TP × PP per worker, times DP when DP attention is off. Before, it counted every node a worker touched. 40 deployments change, and nothing else about them:
  - Examples: GLM-5.2 B300 Dynamo agg TP4 8 → 4; Qwen3.8-Flash-Next TP1 on B200/B300 8 → 1 and on GB300 4 → 1; DeepSeek-V4.1 B300 TP2 8 → 2; Qwen3.5 B300 1P1D TP2 prefill + TP2 decode 16 → 4; GLM-5.2 B200 1P4D (DEP8 prefill + 4 × TP4 decode) 40 → 24.
  - Every new count fits the worker's node count, which the pipeline now checks.
- **GLM-5.2 NVFP4 B300 Dynamo+SGLang ([InferenceX #3953](https://github.com/SemiAnalysisAI/InferenceX/pull/3953)) pinned.** Both deployments ("Agg TP4", c1/c8/c16/c20; "Agg TP4·DPA4", c24/c32/c48) now point to [run 38356572105](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/38356572105) at `caa2199e` and show as verified, instead of "in progress" at the PR head `56b2949a`.

  - The derived HiCache tier of the DPA4 deployment now takes its flags from this measured lane instead of `glm5.2-fp4-b300-sglang-agentic-mtp`. The flags are identical.

## How the commands are produced

The pipeline and rules are the same as in #44065, with these changes:

- **Cluster environment.** The rules now list, per SemiAnalysis cluster, the environment variables it exports into workers whose absence changes SGLang's own defaults. Today that is only `NCCL_CUMEM_ENABLE`; `NCCL_NVLS_ENABLE` and `NCCL_GRAPH_MIXING_SUPPORT` are tracked but no cluster sets them.
  - Each entry cites the run and host whose worker fingerprint showed the value.
  - Every sync re-checks the table against measured worker fingerprints and fails on a mismatch or an unlisted cluster.
  - The round-trip check now also fails on any worker variable that comes from neither the launch nor this table.
- **GPU count.** The formula above.

Each lane is still rendered at the exact commit of the run that produced its dashboard data. SA-only settings are removed: the benchmark harness, cluster paths and caches, telemetry, and InferenceX's synthetic speculative acceptance (disclosed per deployment). Placeholders replace IPs, ports and NICs. Router and KV-offload variants that were not run are derived and labeled "Derived — not run".

The data files are generated. The only hand-written change is the one-line pluralization in `_agentx.jsx`.
