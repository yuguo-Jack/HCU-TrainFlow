# [Fix] hicache: Fix host-memory registration failures in Confidential Computing

[Upstream PR](https://github.com/sgl-project/sglang/pull/46836) · state: open · merged: False

## Original PR description

## Motivation

Fixes https://github.com/sgl-project/sglang/issues/46799

HiCache normally registers its host pools with CUDA. On the tested Confidential Computing (CC) host, `cudaHostRegister` returns error 801 (`cudaErrorNotSupported`), preventing the default host-pool allocation path from working. Qwen3.8-Flash-Next also needs its GDN recurrent state and QSA indexer pools to follow the same allocation policy as attention KV.

Add an opt-in pageable L2 host tier so these deployments can extend prefix caching to CPU memory.

## Modifications

- Add `SGLANG_HICACHE_PAGEABLE=1` to allocate attention KV, recurrent-state, and QSA host pools in ordinary CPU memory. Pinned allocation remains the default.
- Add staged MLA/DSA backup and load for `direct` I/O with `page_first_direct` layout. CUDA runtime copies move data between host and device; GPU kernels access only device buffers. Transfers preserve page order and packed indexer scales, and teardown releases staging buffers and MLA transfer views.
- Support DSV4 whole-page transfers and partial-token transfers for the C4 V4 layout (64 slots per 37,440-byte row) through pageable copies. Partial copies preserve neighboring values, scales, and page padding.
- Reject kernel I/O, unified memory, external cache linkers, HiSparse, and L3 storage when pageable mode is enabled. The L3 check also applies to runtime attachment.
- Fix the SM90 FlashInfer GDN fallback so CUDA graph padding uses the reserved dummy state slot instead of overwriting the last live slot. This fix is also included in [#46554](https://github.com/sgl-project/sglang/pull/46554).

Host sizing and eviction continue to use existing HiCache policies. Pageable copies may synchronize the submitting thread. MLA/DSA staging adds temporary allocations outside the host-pool budget.

## Accuracy Tests

### Standard decoding

Tests use `Qwen/Qwen3.8-Flash-Next-FP8` from ModelScope, revision `47b13b2ed4`, on an H20 host running as a TDX guest. The reference and HiCache instances each use two GPUs with TP2/EP2. Both use FlashInfer GDN prefill/decode, BF16 recurrent state, a 32,768-token context and device KV limit, chunked prefill 2,048, 16 Mamba state slots, and a static memory fraction of 0.96. The requested running-request limit is 4; the runtime caps it at 3 because each request requires five state slots. CUDA graphs and overlap scheduling are enabled. MTP and PLE embedding offload are disabled. HiCache uses `write_through`, direct I/O, `page_first_direct`, and a host/device ratio of 4.

GSM8K follows the [upstream Qwen3.8 test recipe](https://github.com/sgl-project/sglang/blob/6393e66b8649b4e6e22f2d94a933e69059192900/test/registered/e2e/disaggregation/test_qwen4_exp_pd_prefill_cp.py): `run_sgl_eval`, 200 questions, 32 client threads, thinking enabled, and a 16,384-token output limit. The evaluator uses temperature 0 and top_p 0.95. Both instances exceed that test's 94% threshold. The upstream test uses NVFP4; these paired results use the same FP8 checkpoint.

| Test | Reference without HiCache | Pageable HiCache |
| --- | --- | --- |
| GSM8K | 195/200 (97.5%) | 195/200 (97.5%) |
| Request errors / output truncations | 0 / 0 | 0 / 0 |
| Known-answer retrieval, ~2.5k-token prefix | 3/3 | 3/3 |
| Known-answer retrieval, ~20k-token prefix | 3/3 | 3/3 |

The retrieval test places an access code at 10%, 50%, or 90% of the prompt. The reference keeps the prefix in device cache; unrelated requests evict the HiCache instance’s device copy before retrieval. All cases returned the expected code. HiCache reloaded 2,496 host tokens per short-prefix request and 20,032 per long-prefix request.

Regression results: 168 passed, one Mamba kernel-I/O test skipped (unused by pageable mode), and five DSV4 L2 tests passed.

Coverage includes allocation and cleanup, configuration checks, runtime L3 attachment, storage registration/DCP behavior, and GDN padding. CUDA transfer tests check:

- MLA/DSA byte-exact backup/load through host-pool dispatch, release of backing and staging buffers, and repeated `destroy()`.
- DSV4 whole pages and C4 V4 partial-token transfers across chunk boundaries, including preservation of adjacent data and rejection of invalid device indices.
- QSA uint8/bfloat16 compressed buffers and scattered pages on a non-default stream, with byte-exact backup/load and teardown without host registration.

The branch starts from `6393e66b86`. Standard-decoding Qwen measurements use `9ee3850a87`, GLM measurements use `a4e8b21ef0`, and DeepSeek measurements use `7e5306ca76`. Regression results correspond to `4d361847c3`.

For the standard-decoding Qwen tests, run GSM8K once per endpoint, with separate output directories:

```bash
python test/manual/hicache/eval_pageable_accuracy.py \
  --url "$ENDPOINT_URL" --model "$MODEL_PATH" --output-dir "$RESULT_DIR"

python test/manual/hicache/eval_pageable_roundtrip.py \
  --url "$HICACHE_URL" --reference-url "$REFERENCE_URL" \
  --model "$MODEL_PATH" --churn-requests 16 --prompt-tokens 20000 \
  --output "$RESULT_DIR/reload.json"
```

### Speculative decoding

MTP/DSpark tests use `4d361847c3` on the H20 CC host. Each pair uses the same checkpoint and speculative configuration, with HiCache disabled in the reference.

| Model / speculative configuration | GSM8K without HiCache | Pageable HiCache | Long-prefix L2 reload |
| --- | --- | --- | --- |
| Qwen3.8-Flash-Next-FP8, TP4/EP4, NEXTN 3/1/4 | 192/200 (96.0%) | 195/200 (97.5%) | 3/3 |
| DeepSeek-V4.1-Flash-1017, TP8/EP8, DSPARK block size 5 | 194/200 (97.0%) | 195/200 (97.5%) | 3/3 |
| GLM-5.3-W4AFP8, TP8, EAGLE 5/1/6 | 1284/1319 (97.35%) | 1287/1319 (97.57%) | 3/3 |

All six runs passed the upstream accuracy thresholds with zero request errors. The DeepSeek and GLM reference runs each had one truncated response, counted incorrect; the pageable runs had none. All ~20k-token reload cases returned the expected answer with a host-cache hit. DeepSeek used eager metadata preparation after the upstream metadata graph capture failed in both configurations; target-verify and draft CUDA graphs remained active.

Use the same checkpoint, GPUs, backends, and KV capacity for both runs. Define the shared model and serving arguments in the Bash array `SERVER_ARGS`, including `--enable-cache-report` and `--max-total-tokens 32768`. Add the model’s speculative flags:

```bash
# Qwen3.8 (TP4/EP4)
--speculative-algorithm NEXTN --speculative-num-steps 3 \
  --speculative-eagle-topk 1 --speculative-num-draft-tokens 4
# DeepSeek-V4.1 (TP8/EP8)
--speculative-algorithm DSPARK --speculative-dspark-block-size 5
# GLM-5.3 (TP8)
--speculative-algorithm EAGLE --speculative-num-steps 5 \
  --speculative-eagle-topk 1 --speculative-num-draft-tokens 6
```

First launch the reference with `SGLANG_HICACHE_PAGEABLE=0 python -m sglang.launch_server "${SERVER_ARGS[@]}"`, without `--enable-hierarchical-cache`, and save its results:

```bash
# PROFILE: qwen38 | dsv41 | glm53
# MODEL_PATH: local checkpoint directory
# SERVED_MODEL: API model name; ENDPOINT_URL: running server URL
python test/manual/hicache/eval_pageable_accuracy.py \
  --profile "$PROFILE" --url "$ENDPOINT_URL" --model "$SERVED_MODEL" \
  --output-dir "$RESULT_DIR/reference-gsm8k"
python test/manual/hicache/eval_pageable_serial_roundtrip.py \
  --url "$ENDPOINT_URL" --model "$MODEL_PATH" --mode reference \
  --require-speculative --output "$RESULT_DIR/reference-reload.json"
```

Stop the reference server, then launch the pageable configuration and evaluate it using the same checkpoint path and saved reference:

```bash
SGLANG_HICACHE_PAGEABLE=1 python -m sglang.launch_server \
  "${SERVER_ARGS[@]}" \
  --enable-hierarchical-cache --enable-cache-report \
  --hicache-io-backend direct --hicache-mem-layout page_first_direct \
  --hicache-write-policy write_through --hicache-ratio 4

python test/manual/hicache/eval_pageable_accuracy.py \
  --profile "$PROFILE" --url "$ENDPOINT_URL" --model "$SERVED_MODEL" \
  --output-dir "$RESULT_DIR/pageable-gsm8k"
python test/manual/hicache/eval_pageable_serial_roundtrip.py \
  --url "$ENDPOINT_URL" --model "$MODEL_PATH" --mode pageable \
  --require-speculative --reference-result "$RESULT_DIR/reference-reload.json" \
  --output "$RESULT_DIR/pageable-reload.json"
```

The GSM8K profiles use upstream scoring and generation settings, with 200 questions and a 94% threshold for Qwen, 200/95% for DeepSeek, and 1,319/92% for GLM. The reload script uses ~20k-token prompts and 16 churn requests. The scheduler caps output length to fit the available KV capacity.

### GLM-5.3 and DeepSeek-V4.1-Flash

Additional checks use the same shared-prefix protocol on eight H20 GPUs in the CC guest, with a 32,768-token device KV limit and no MTP. The pageable configuration uses direct I/O, `page_first_direct`, `write_through`, and ratio 4. Each model has its own generated dataset; the paired runs process 290,254 input tokens for GLM and 284,905 for DeepSeek.

| Model / checkpoint | Configuration | Completed | Output tokens/s | Median TTFT (ms) | Median TPOT (ms) | Host-cache hit tokens |
| --- | --- | --- | --- | --- | --- | --- |
| GLM-5.3-W4AFP8 | Reference without HiCache | 128/128 | 142.10 | 1530.11 | 16.92 | 0 |
| GLM-5.3-W4AFP8 | Pageable HiCache | 128/128 | 169.64 | 725.30 | 16.76 | 116,160 |
| DeepSeek-V4.1-Flash-1017 | Reference without HiCache | 128/128 | 230.51 | 912.44 | 10.18 | 0 |
| DeepSeek-V4.1-Flash-1017 | Pageable HiCache | 128/128 | 246.71 | 591.02 | 10.21 | 112,640 |

GLM uses TP8, W4AFP8 weights, FP8 KV, page size 64, `flashmla_sparse_q8` prefill and `flashmla_kv` decode, context 65,536, and static memory fraction 0.8. DeepSeek uses TP8/EP8, FP8 weights with FP4 routed experts, the `dsv4` attention backend, `flashinfer_mxfp4`, FP8 KV, page size 256, context 16,384, static memory fraction 0.85, and FlashInfer autotuning disabled. Both use chunked prefill 2,048 and a running-request limit of 32. Overlap scheduling and decode CUDA graphs are enabled. GLM also uses prefill graphs; upstream's DSV4 policy disables prefill graphs due to capture-pool memory pressure. Unavailable multicast/allreduce fusion falls back in both configurations.

All 768 measured requests completed successfully with 128 output tokens each. Host-cache hits confirm L2 reuse. Each configuration was measured once on a shared host using the native SGLang API.
