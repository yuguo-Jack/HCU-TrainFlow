# [Perf] kimi-k3: Allow residual bank shards with NCCL

[Upstream PR](https://github.com/sgl-project/sglang/pull/47452) · state: closed · merged: True

## Original PR description

## Motivation

`SGLANG_K3_SP_ATTN_RES` keeps post-MoE residual streams and bank operations on each rank's token shard, then gathers the normalized attention input. Its eligibility check also requires K3's custom collective backend, preventing NCCL deployments from using an existing layout that already has ordinary ReduceScatter/AllGather fallbacks.

## Modifications

- Remove the custom-collective requirement from bank-slice eligibility. Preserve the existing opt-in switch, SP-MoE and residual-bank requirements, PP=1 restriction, consecutive-MoE guard, and speculative hidden-state capture exclusions.
- Keep fused bank/communication paths conditional on custom collective availability. At the terminal bank read, skip custom fusion preparation when no custom gather callback exists; this avoids preparing a pending residual add only to fall back to the ordinary read.
- Use the actual eligibility helper throughout the stage-planning tests, including the terminal read, and check NCCL fallback behavior without a custom communicator.
- Update the existing switch's documentation. No new flags, device-name checks, private communicators, tuning-table bypasses, or communication kernels are introduced.

This reduces the bank rows read and written; it does not shrink the physical bank allocation. The contiguous-QKV convolution optimization is independent and is not included in either measurement arm.

## Speed Tests and Profiling

Independent baseline and PR worktrees use the same common base above. Conditions: Kimi-K3, 8× B300 (B30Z/SM103), TP8/EP8, MegaMoE with default real expert routing, ISL 65,536, OSL 1, concurrency 1, chunk 65,536, BF16 recurrent state, FP8 KV, `NCCL_SYM_CTAS=16`, default CE AllGather, MegaMoE reserved SMs=2. CUDA graphs, radix caching, overlap scheduling, custom SP collectives, and AR fusion are disabled. Only the PR arm enables the existing bank shard carry switch.

Each independent restart receives 4 warmup requests and two 16-request measured blocks. Baseline and PR are measured twice in an interleaved baseline/KDA/bank sequence. No profiler or hot-path diagnostic code is attached. Throughput is total input tokens divided by total measured duration; P50/P99 are recomputed from all raw formal requests in each row.

The original explicit `fake` dispatch fails on the common base because Kimi-K3 does not provide expert placement metadata. Both arms therefore use the default real routing. These results are not combined with the earlier prototype's fake-dispatch measurements.
