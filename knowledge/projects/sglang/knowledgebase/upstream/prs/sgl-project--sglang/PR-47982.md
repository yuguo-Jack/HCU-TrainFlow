# [Feat] dflash: Shared context K/V drafts with a one-layer draft KV pool

[Upstream PR](https://github.com/sgl-project/sglang/pull/47982) · state: open · merged: False

## Original PR description

## Motivation

A DFlash draft keeps context K/V for every draft layer, so its KV pool costs `num_draft_layers` layers per token.
A shared context K/V draft computes one context K/V from the target hidden states, and every draft layer attends to it.
Its pool then holds one layer per token, and the freed memory goes to the target's KV cache.

## Modifications

- `dflash_config.shared_context_kv: true` in the draft config turns it on. Checkpoints carry `shared_context_kv.{input_norm,kv_proj,k_norm}.weight`.
- `DFlashSharedContextKV.write_context_kv` replaces the "target hidden -> per-layer context K/V" step: RMSNorm over the concatenated target features, one projection to [K | V], RMSNorm on each K head, RoPE, then one write as layer 0. It follows `DFlashMLAAttention.write_context_kv`.
- The draft KV pool has one layer (`end_layer = 1`), every draft layer's `RadixAttention` uses layer 0, and the target-side KV budget counts one draft layer.
- `DFlashAttention`, `project_target_hidden` and the per-layer write path are unchanged, so existing drafts behave as before. TP and quantized drafts are handled as for `fc`.
- New unit test: `test/registered/unit/spec/test_dflash_shared_context_kv.py`.
