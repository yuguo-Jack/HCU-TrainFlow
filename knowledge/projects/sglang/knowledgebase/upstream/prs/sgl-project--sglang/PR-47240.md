# [Fix] diffusion: Check cancellation at stage and sampling boundaries

[Upstream PR](https://github.com/sgl-project/sglang/pull/47240) · state: closed · merged: True

## Original PR description

## Motivation

Follow-up to #47055. Cancellation was coupled to progress-bar updates, which are not always sampling-step boundaries: some samplers update infrequently or once per chunk. A cancellation during encoding, decoding, or after the last sampling step could also miss the opportunity to skip later work.

## Changes

- Check at executor stage boundaries on every replica rank, outside rank-selective branches. Retain the original requests even when the final stage returns `OutputBatch`.
- Move sampling checks out of `ReportingTqdm` into `PipelineStage.check_cancelled`. Preserve the existing custom-sampler integrations and check inside SANA-WM streaming chunks. Grouped sampling checks the complete request group, not only its first request.
- Check after forward, before saving or handing finalization to a background thread. Sequential execution consumes the current output before checking, so cancellation cannot shift the remaining outputs between requests.
- Keep disabled checks lightweight. Reuse existing residency cleanup, cancellation transport, and all-members-cancelled semantics. No new options or production modules.
- Document checkpoint placement for custom pipelines and the API's cancellation limits.

Existing production files: +78/-39 lines. Tests and docs: +218/-56 lines.

## Validation

- Seven targeted test files on an isolated GPU development machine: **195 passed, 2 subtests passed**.
- Includes real two-process Gloo stage-boundary tests for replicated and rank-only stages, terminal `OutputBatch`, cleanup, low-frequency progress updates, sequential output ordering, deferred finalization, and SANA-WM inner-step cancellation. Also runs existing video lifecycle, executor, MOVA, SANA-Video2 and Kandinsky6-SR tests.
- Changed-file pre-commit checks pass.

**Native GPU validation:** Wan2.1 T2V 1.3B, 2 x H200, Ulysses 2, BF16/resident weights, FA, eager, 832x480, 17 frames, 8 steps, seed 42. Python 3.12, PyTorch 2.14.1+cu130, diffusers 0.37.0, pyzmq 27.2.0. The same warm process alternated non-cancellable/cancellable requests in A-B-B-A order, eight samples per arm, with conditioning caching, progress reporting and saving enabled in both arms and stage-profiling synchronization disabled.

| Check | Result |
| --- | --- |
| Saved-output E2E median, checks off / on | 0.8208 s / 0.8261 s (+0.64%) |
| Cancel a 50-step request after progress step 20 | Stops before decoding; no output saved |
| Pre-cancelled request | Does not enter the pipeline |
| Normal request after both cancellations | Completes successfully |
| 17 comparable completed MP4s | Byte-identical SHA-256 |

This measures the check toggle on this head, not branch-vs-main performance or all-model throughput. GPU validation uses a diagnostic SDK harness through the real scheduler, ZMQ and distributed workers, not an additional live HTTP E2E test. DELETE integration is covered by the lifecycle/IPC tests. The diagnostic SDK logs cancelled outputs as errors, and shutdown emits the existing CUDA IPC producer-lifetime warning; neither is claimed fixed here. The development environment uses `FLASHINFER_DISABLE_VERSION_CHECK=1`; CI remains the supported-environment regression gate.

## Limits

This is cooperative cancellation, not kernel preemption. Rank-only stages finish before their executor checkpoint; already-running saves/uploads are not interrupted. Disaggregated and multi-node cancellation remain outside the scope inherited from #47055. A new custom sampler must use the documented checkpoint API; arbitrary inner loops are not intercepted automatically.
