# [Doc] quantization: Add architecture page; scope contribution guide to workflow

[Upstream PR](https://github.com/sgl-project/sglang/pull/46870) · state: open · merged: False

## Original PR description

## Motivation

The quantization contribution guide names the Config / Scheme / Backend split from the [Quantization Modifications roadmap](https://github.com/sgl-project/sglang/issues/15194), but it doesn't make it enforceable:

- "The backend does not know the checkpoint format" is stated as a design goal, not a rule.
- "Layout conversion" is assigned to the backend. That wording also covers checkpoint-specific scale merging, so format conversion keeps landing in `hardware_backend/<device>/quantization/`.
- There is no place for device schemes (for example `NPUCompressedTensorsW8A8Int8`), which is the pattern NPU code actually uses.
- The suggested `<method>_kernels.py` naming suggests every backend file should be named after a checkpoint format.

Contributors and reviewers need one page that says where each change goes.

## Modifications

- New page `developer_guide/quantization_architecture.mdx`:
  - an ownership table for config, scheme, device scheme, and backend method, saying which of them know the checkpoint format
  - rules:
    - the recipe sets the backend method's input, not the checkpoint format
    - format conversion goes in the scheme, kernel-required layout in the backend
    - name backend methods by recipe
    - subclass an existing backend method before adding one
    - the same checkpoint loads the same way on every backend
  - a "where does my change go" table, plus short MoE and online-quantization sections.
- `quantization_contribution_guide.mdx` is now workflow only: steps, validation, and the PR checklist. The Design Goals and file-layout sections moved to the new page. The steps and checklist now name the layers.
- Adds the new page to `docs.json` nav and the developer guide overview.

Scope is quantization only (`layers/quantization/` and `hardware_backend/*/quantization/`). Docs only, no code changes.
