## Motivation

sgl_kernel_npu implements block verification for the chain-mode EAGLE/EAGLE3/NEXTN rejection-sampling kernel, but the `--speculative-use-block-verification` gate in sglang rejects `device=="npu"`, so NPU users cannot enable it. This PR admits NPU for the chain path while keeping every other device's behavior unchanged.

## Modifications

- `arg_groups/speculative_hook.py`: allow `device=="npu"` in the block-verification gate for the EAGLE/EAGLE3/NEXTN chain path only. and all other non-CUDA/ROCm devices are still rejected. The implicit enforcement of `--speculative-use-rejection-sampling` (which strictly requires `--speculative-eagle-topk=1`) is unchanged.
- `arg_groups/fields/spec.py`: update the flag's help text to document NPU support.
- `test/registered/unit/spec/test_block_verification_args.py`: add `test_supported_on_npu` (EAGLE/EAGLE3/NEXTN accepted on NPU) and update the negative cases — DFLASH/DSPARK on NPU now hit the algorithm gate instead of the device gate, and cpu/xpu test the new device-gate message.

## Accuracy Tests

Unit tests: `test_block_verification_args.py` 5 passed (including `test_supported_on_npu`).

End-to-end on Qwen3.6-35B-A3B NEXTN (NPU, TP2, `--speculative-num-steps 3 --speculative-eagle-topk 1 --speculative-num-draft-tokens 4 --speculative-use-block-verification`, 6 fixed prompts):

- Greedy (temperature=0): all 6 outputs **byte-identical** to the classic chain-verification baseline (no block verification), with `avg_spec_accept_length` exactly equal (3.1167). This is the expected invariant: at temperature 0 the one-hot target distribution reduces Algorithm 2 to longest-argmax-prefix acceptance, i.e. classic greedy chain verification — so any deviation (or kernel failure) would be caught.
- Sampled (temperature=0.7): all 6 outputs deviate from the greedy baseline and `avg_spec_accept_length` stays at the same magnitude (3.12), confirming the sampled block-verification path is active and healthy.
