## Motivation

<!-- Describe the purpose and goals of this pull request. -->
A packed caller that marks its trailing rows as padding gives the AITER grouped-varlen kernel a second `cu_seqlens` segment covering only padding. The kernel partitions work across segments, so the extra one costs part of every call. Attend the live prefix as a single segment and zero the tail, reusing the `trailing_padding_used_len` contract the FA and Sage backends already implement.

MiniMax-H3 packs one request into a single sequence and pads it to a multiple of 64, giving `cu_seqlens = [0, used, seq_len]`. The alignment tail is therefore a second varlen segment containing nothing but padding.

AITER's grouped-varlen kernel partitions work across segments, so that second segment costs part of every attention call. The cost tracks the segment count, not the padding rows: with the aiter kernel at 7 heads, head_dim 128, bf16, a zero-row tail and a one-row tail are within 0.1% of each other, while collapsing to a single segment is consistently faster.


## Modifications

<!-- Detail the changes made in this pull request. -->

- Added single-segment varlen handling to the AITER attention backend for packed callers whose trailing rows are padding.
- `AITerImpl` now opts into the existing `packed_trailing_padding` contract, reusing the `trailing_padding_used_len` helper already shared by the FlashAttention and Sage backends.
