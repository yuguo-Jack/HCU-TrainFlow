# [Perf] [NVIDIA] attention: Reuse the flashinfer MLA decode tactic for trtllm_mla eager decode

[Upstream PR](https://github.com/sgl-project/sglang/pull/47787) · state: open · merged: False

## Original PR description

## Motivation

`flashinfer.decode.trtllm_batch_decode_with_kv_cache_mla` rebuilds its runner objects and tuning config and calls `AutoTuner.choose_one` on every call. CUDA-graph replay skips that host code, but eager decode (`--disable-cuda-graph`, batches above `cuda_graph_max_bs`) pays it once per layer per step.

## Modifications

- New `python/sglang/srt/layers/attention/trtllm_mla_decode_cache.py` with `cached_trtllm_mla_decode`, which keeps only the `(runner_kind, tactic)` decision chosen across FlashInfer's SM10x candidate runners (`trtllm-gen` and `cute-dsl`) per shape and builds only the selected runner on every call from the caller's tensors and exact `max_seq_len`:
  - outputs are bitwise identical to the public API, both untuned and after `flashinfer.autotune(True)`;
  - no tensor is cached, so the KV pool and workspace can be freed or re-created at any time (memory saver, weight sync);
  - the key has no per-layer state, so all layers share the same entry within a FlashInfer seq-len / 128-token K-tile bucket; LRU-bounded (4096 entries), skipped while FlashInfer is autotuning or inside an active tuning context, and invalidated when profiling results or loaded config files (`load_configs`) change;
  - LSE requests, non-SM10x devices (e.g. SM120 XQA), boundary/unaligned inputs, FlashInfer builds without the runner classes (`flashinfer.mla._core`), and builds whose dispatcher caches the decision itself (`AutoTuner.selection_cache_token`) use the public API unchanged.
- `TRTLLMMLABackend._run_decode_kernel` calls it when `SGLANG_TRTLLM_MLA_CACHE_DECODE_RUNNER=1` (default off) and skip-softmax is not enabled.
- New `test/registered/attention/test_trtllm_mla_decode_cache.py` (14 unit tests).

## Accuracy Tests

Outputs are bitwise identical (`torch.equal`) to `trtllm_batch_decode_with_kv_cache_mla` on every tested shape, both untuned and after `flashinfer.autotune(True)` (including shapes where autotuning selects `CuteDslMlaDecodeRunner`), as well as non-power-of-two `max_seq_len` with eager-sized (4096-token) page tables and explicit `backend="cute-dsl"`. The unit test suite covers H in {16, 128}, B in {1..64}, ragged lengths, LSE requests, growing `max_seq_len`, multiple layers sharing entries, KV/workspace release (`weakref`), tuning-context bypass, `load_configs` / `_dirty_seq` invalidation, non-SM10x fallback, boundary/invalid input error contracts, and missing-API fallback.

## Benchmarking and Profiling

B200, BF16 KV, page size 64, 4096-token page tables, H in {16, 128}, B in {1, 8, 32, 128}, `max_seq_len` 1500, interleaved runs against the public API:

| Metric | Result |
|---|---|
| Host time per decode call | 3.6x-4.5x lower (also with `max_seq_len` growing every step) |
| Eager per-call latency | 1.7x-2.6x lower |
| CUDA-graph replay | unchanged (-2.0% to +2.8%) |
| Outputs | bitwise identical on 8/8 shapes (untuned) and 7/7 shapes (after `autotune(True)`) |

In eager decode (`--disable-cuda-graph`, or batches above `cuda_graph_max_bs`), FlashInfer rebuilds its MLA decode runners and runs `AutoTuner.choose_one` once per layer per step. This PR caches only the chosen `(runner, tactic)` per shape, no tensors, behind `SGLANG_TRTLLM_MLA_CACHE_DECODE_RUNNER` (default off). Outputs are bitwise identical to the public API, untuned and after `flashinfer.autotune(True)`; CUDA-graph replay does not change.

flashinfer-ai/flashinfer#8233 proposes the same cache inside FlashInfer. On builds that expose `AutoTuner.selection_cache_token` (added there), this helper calls the public API unchanged, so the two PRs do not conflict.
