# [Fix] Honor KDA safe-gate backend capabilities

[Upstream PR](https://github.com/sgl-project/sglang/pull/41121) · state: closed · merged: False

## Original PR description

## Motivation

KDA models with a bounded safe gate (for example, Kimi-K3 with `gate_lower_bound=-5.0`) fail when dispatched to FlashInfer decode or target verification. The dispatcher rejects every non-Triton kernel, although FlashInfer already forwards `lower_bound` to `recurrent_kda`.

## Modifications

- Declare `supports_safe_gate=True` on the linear attention kernel base; CuTe DSL retains its explicit False override.
- Select effective decode and verify kernels by safe-gate capability, matching the existing extend fallback. Keep FlashInfer selected and reroute unsupported kernels to Triton.
- Read the declared capability directly in the extend selector.

## Accuracy Tests

- Isolated execution of the dispatcher source with mocked kernels: 18 cases covering decode, verify, and extend, supported/unsupported safe gate, and bounds None, -5.0, and 0.0. Confirmed original decode/verify rejection and fixed selection, lower_bound forwarding, and absence of calls to the other backend.
- Repository pre-commit checks passed on both changed files; the branch-name guard was excluded. `git diff --check` passed.
- This checkout has no PyTorch, Triton, or GPU; full kernel and model tests were not run here. The isolated checks are not committed CI tests.
- Reporter-provided validation with this fix AND the separate prefill tuple-unpacking fix: Kimi-K3 with `--linear-attn-prefill-backend flashkda --linear-attn-decode-backend flashinfer`, 356-token health-check prefill returned HTTP 200, 120-token generation completed, and no traceback was observed. This is combined functional validation, not an accuracy benchmark or a standalone validation of this commit.

Not run. Kernel computations are unchanged; this fixes Python backend dispatch.
