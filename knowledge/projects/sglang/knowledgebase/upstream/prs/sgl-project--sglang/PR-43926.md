# [Rust] Serve /weights_checker from the Rust frontend

[Upstream PR](https://github.com/sgl-project/sglang/pull/43926) · state: closed · merged: True

## Original PR description

## Motivation

A server running the Rust frontend answers 404 on `/weights_checker`, so
nothing can ask it for its weight checksums or fingerprint: neither the RL
weight-sync checks (`test/registered/rl/test_weight_checker_e2e.py`) nor an
operator comparing two engines. The Python frontend has served this route for
a long time, and the scheduler-side handler (`weight_updater.check_weights`)
already runs on every rank regardless of frontend; only the HTTP route and its
control request were missing on the Rust side.

## Modifications

- `rust/sglang-server/src/message/io_struct.rs`: add the `CheckWeightsReqInput`
  control message (`action`, `allow_quant_error`, `skip_tensor_list`,
  `selector`) with the same positional wire layout as the Python msgspec
  struct: `[tag, rid, http_worker_ipc, action, allow_quant_error,
  skip_tensor_list, selector]`.
- `rust/sglang-server/src/api_server/core/handle.rs`: `CoreHandle::check_weights`
  sends that request through the existing control path and decodes the
  scheduler's `CheckWeightsReqOutput` (`success`, `message`, optional
  per-rank `payload`).
- `rust/sglang-server/src/api_server/http/info.rs`: route `GET|POST
  /weights_checker` with the Python contract:
  - Body fields `action` (default `checksum`), `allow_quant_error`,
    `skip_tensor_list` and `selector` (`target`, `draft` or `all`). An absent
    or `null` body uses the defaults; unknown fields are ignored.
  - JSON reply with `success` and `message`, plus `ranks` (each rank's record
    as the scheduler sent it) and `per_engine_checksum` (the SHA-256 of the
    ranks' `per_gpu_checksum`s, in rank order) when the ranks returned
    records. 200 on success, else 400.
  - A malformed body (unknown `selector`, `null` `action`, invalid JSON) is a
    400 before anything reaches the scheduler, with the Rust frontend's
    `{"error": ...}` body.
- `rust/sglang-server/Cargo.toml` / `rust/Cargo.lock`: `sha2` was already in
  the dependency tree; it becomes a direct dependency of `sglang-server` (one
  new edge in the lockfile, no new crate).

Tests added:
- `weights_checker_relays_the_scheduler_outcome`: the body's fields (and the
  defaults for an empty or `null` body) reach one `CheckWeightsReqInput`; the
  reply matches the Python JSON byte for byte, field order included, for rank
  records, an empty record list, and a failure (400, no `ranks`); malformed
  bodies are 400s that never reach the scheduler.
- `check_weights_req_msgpack_shape`: pins the seven-element wire array.

Known limitation under attention DP, shared with every other control route on
the Rust frontend: with the default control broadcast, a call to a DP listener
other than rank 0 does not get an answer; with
`--enable-dp-attention-local-control-broadcast`, the checker's `all_gather`
spans the full TP group and collides with the other groups' collectives. Call
the route on the rank-0 listener without that flag.
