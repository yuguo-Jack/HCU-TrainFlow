## Motivation

GLM-5.2 with DP attention runs the triton sparse-MLA decode with all 64 heads on each rank, an fp8 KV cache, and topk 2048. MTP adds 6 verify rows per request. At 48 to 96 rows, `triton_sparse_mla_fwd` uses a geometry that needs several rounds of CUs (BLOCK_H=16, four head blocks per row) and re-reads each row's gathered KV once per head block.

This PR adds a decode plan for that shape:
- **Speed.** The kernel is 2.4x to 3.2x faster at 48 to 96 rows.
- **Accuracy.** It is within fp8 tolerance of an fp32 reference: 37 to 38 dB SNR, against 26 to 37 dB on main.
- **End to end.** GLM-5.2 with DP attention (TP8 DP8, MTP) gets 11.8% lower median ITL.

Every other shape keeps main's path.

## Modifications

- **Decode plan** (`_decode_splitk_splits`).
  - Applies on gfx950 with an fp8 cache, a head count that is a multiple of 32, d_v 512 and tail 64.
  - Runs one head block per row (`BLOCK_H == H`), so each gathered KV row is read once.
  - Parallelism comes from KV splits, sized as `num_cu // rows`, so the grid stays within one round of CUs.
  - Applies when at least 2 splits fit, i.e. up to `num_cu / 2` rows (128 on MI355X).
- **Split-K partial loop.** Shape specialisations that only the decode plan turns on, so every existing caller keeps its compile-cache key:
  - i32 page offsets;
  - dense tiles;
  - 256-wide value groups at a two-deep pipeline;
  - in-place accumulator rescale;
  - streaming (`.cs`) KV loads;
  - P@V dots fenced out of the attention-chain layout;
  - a head-interleaved partial layout with its own reduce (`_sparse_mla_reduce_dq_kernel`);
  - write-through partial stores;
  - a compile-time tile trip count.
- **Residency-aware geometry** (`_decode_geometry`). Launches that exceed one round at BLOCK_H=16 but are not covered by the decode plan get a residency-aware `(BLOCK_H, PIPE_STAGES)`, on an fp8 cache with a multiple of 32 heads.
- **Fused-kernel async-copy scope.** The fused kernel at PIPE_STAGES=3 compiles without direct-to-LDS async copies on an fp8 cache (measured faster). bf16 keeps its current lowering.
- **DCP split-K path (#44322) is unchanged.**
  - The reduce kernel's LSE store is kept in both of its head-block branches.
  - A static assert rules out combining the compile-time trip count with a per-row `topk_length`.
- **Test.** `test_gfx950_fp8_64h_decode_plan_matches_reference` checks 48, 60 and 96 rows, with and without a -1 tail, against an fp32 reference at more than 35 dB.

## How to reproduce

Hardware: MI355X (gfx950), ROCm 7.2. Kernel tests run on main's tree. End-to-end runs use `lmsysorg/sglang-rocm:v0.5.22-rocm720-mi35x-20261018` with main's `triton_sparse_mla.py` and `triton_sparse_mla_decode.py` copied in for the main arm, and this branch's `triton_sparse_mla.py` for the PR arm. In those copies, one import line is pointed at `kvcache/cache_ops`, the pre-#45112 location of `q8kv8_topk_length_from_indices`.

```bash
python3 -m pytest -q test/registered/kernels/ops/attention/test_triton_sparse_mla_hip.py
SGLANG_OPT_USE_TOPK_V2=true SGLANG_SIMULATE_ACC_LEN=3.61 SGLANG_SIMULATE_ACC_METHOD=match-expected \
SGLANG_SIMULATE_ACC_TOKEN_MODE=real-draft-token python3 -m sglang.launch_server --model-path amd/GLM-5.2-MXFP4 \
  --trust-remote-code --kv-cache-dtype fp8_e4m3 --dsa-prefill-backend triton --dsa-decode-backend triton \
  --mem-fraction-static 0.85 --speculative-algorithm EAGLE --speculative-num-steps 5 --speculative-eagle-topk 1 \
  --speculative-num-draft-tokens 6 --tensor-parallel-size 8 --data-parallel-size 8 --enable-dp-attention \
  --max-running-requests 64 --cuda-graph-max-bs-decode 8
python3 -m sglang.bench_serving --backend sglang --dataset-name random --random-input-len 32000 \
  --random-output-len 1000 --random-range-ratio 1.0 --num-prompts 128 --max-concurrency 64 --seed 1
```

The kernel changes were found with an automated kernel-optimization search. This PR ports them onto main (including the DCP changes of #44322). It also replaces the search's fp8 split-K partials with bf16 ones: those cost about 5 dB at 72 to 96 rows for about 8% speed.
