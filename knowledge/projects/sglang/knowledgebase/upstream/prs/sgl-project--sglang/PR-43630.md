# [diffusion] Cache SANA-Video 2.0 negative prompts and compact TI2V masks

[Upstream PR](https://github.com/sgl-project/sglang/pull/43630) · state: closed · merged: False

## Original PR description

## Motivation

Repeated SANA-Video 2.0 requests with the same negative prompt rerun Gemma, and TI2V sampling builds masks and timesteps across every latent channel and spatial position even though they vary only by frame.

## Modifications

- Reuse the shared conditioning cache for negative prompts, preserving its budget, disable option, and input-based cache keys.
- Keep TI2V masks and model timesteps framewise. Expand timesteps only at the scheduler boundary, preserving its per-token interface and sampling equations.
- Cover repeated and changed negative prompts, disabled caching, and compact timestep storage in the existing tests.

## Accuracy Tests

- The regression tests failed before the change and passed afterward. Focused model, pipeline, and cache tests passed in the existing A800 environment; repository pre-commit checks passed.
- All eight eager A/B video pairs matched exactly, both as MP4 files and decoded RGB frames.
- Applying this patch to the BCG branch in #41501 captured both timestep shapes successfully; T2V and TI2V outputs matched eager exactly, with no capture failures or signature misses. This PR has no dependency on that branch.
- A CUDA sampler comparison at the default latent shape preserved every output element and the conditioned first frame. Frame-timestep storage fell from 11.23 MiB to 100 bytes; the scheduler still receives spatial per-token timesteps.

## Speed Tests and Profiling

A800 80GB, 832×480, 81 frames, 50 steps, guidance 8, seed 42, all components resident, torch.compile disabled. Means of three requests after warmup; end-to-end includes lossless video saving.

| Mode | Text encoding, main → PR | Saved-request end-to-end, main → PR |
| --- | ---: | ---: |
| T2V | 57.3 → 32.1 ms | 35.99 → 36.03 s |
| TI2V | 57.8 → 31.6 ms | 36.08 → 36.12 s |

Text encoding became faster, but this run showed no end-to-end speedup. Peak reserved memory was unchanged; peak allocated memory increased by about 1.5 MiB with negative conditioning retained on device.
