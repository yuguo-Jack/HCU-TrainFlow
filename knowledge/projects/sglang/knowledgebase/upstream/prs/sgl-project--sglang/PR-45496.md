# [Fix] data_parallel_controller: Fix active ranks update and simplify round-robin dispatch

[Upstream PR](https://github.com/sgl-project/sglang/pull/45496) · state: closed · merged: True

## Original PR description

## Motivation

This PR resolves a state desynchronization issue in `DataParallelController` and simplifies the round-robin request dispatch path:

1. **Stale Worker Cache in `update_active_ranks`:** In `DataParallelController.update_active_ranks`, the non-elastic branch (`get_exec().moe.elastic_ep_backend is None`) updated `self.status` directly via `list(ranks.status)` without masking against `self.dp_active` or calling `self._refresh_active_workers()`. As a result, `self._active_workers` and `self._active_count_cache` remained stale after rank liveness changes, and unprovisioned expansion slots (`dp_active == False`) could be marked active in `self.status` if `ranks.status` contained trailing `True` values.
2. **Redundant Iteration in `round_robin_scheduler`:** To work around stale `_active_workers` entries, `round_robin_scheduler` previously ran a defensive `while attempts < len(active)` loop re-checking `if self.status[slot]:` on each dispatch. Because `DataParallelController` runs on a single-threaded event loop and `_active_workers` represents the exact filtered intersection of provisioned (`dp_active`) and healthy (`status`) ranks, every entry in `_active_workers` is guaranteed routable once `_refresh_active_workers()` is consistently invoked.

By unifying `update_active_ranks` to always mask with `self.dp_active` and invoke `_refresh_active_workers()`, we enforce the `_active_workers` invariant across all paths and streamline `round_robin_scheduler` into a direct $O(1)$ lookup.

## Modifications

- **`python/sglang/srt/managers/data_parallel_controller.py`:**
  - Unified `update_active_ranks`: removed branching divergence between elastic and non-elastic paths, consistently intersected `ranks.status[i]` with `self.dp_active[i]`, and unconditionally invoked `self._refresh_active_workers()`.
  - Simplified `round_robin_scheduler`: removed the redundant `while attempts < len(active)` loop and inner `self.status[slot]` check in favor of direct $O(1)$ slot indexing (`active[self.round_robin_counter % len(active)]`).
- **`test/registered/unit/managers/test_data_parallel_controller.py`:**
  - Updated `_make_controller` to support `max_dp_size` and initialize `dp_active`, `status`, and `_active_count_cache`.
  - Updated `TestRoundRobinScheduler.test_skips_inactive_workers` and `TestStatusAwarenessInconsistency` docstrings to reflect `_active_workers` routing, and added `test_raises_when_no_active_workers`.
  - Added `TestUpdateActiveRanks` to verify `_active_workers` cache refresh, unprovisioned slot masking, and length-mismatch handling.
