# [Fix] session: reject unsupported input embeddings

[Upstream PR](https://github.com/sgl-project/sglang/pull/40745) · state: open · merged: False

## Original PR description

## Why

Fixes #40728. `input_embeds` sent to `/generate` with a session opened through `/open_session` reaches session history assembly with `input_ids=None` and crashes the scheduler. Session history also requires embedding positions to survive append, replacement, and recovery.

## What changed

Reject `input_embeds` combined with `session_params` during request normalization. The error directs callers to standalone embedding requests or token-based sessions. Rejection happens after request-ID normalization and before request-state creation or scheduler dispatch. Non-streaming requests receive HTTP 400; streaming requests receive an `invalid_request_error` event with code 400 and a final `[DONE]` event.

Standalone embedding requests and token-based sessions retain their existing paths. This patch establishes an explicit unsupported-input boundary. Multi-turn embedding support requires a separate session-history contract.

## Verification

The earlier integration of main `74308cf1` at `d349e137` passed 37 scenarios: 24 unsupported session-embedding combinations returned the intended error after request-ID normalization; 13 standalone embedding and token/text session controls were accepted. That main revision accepted all 37, reproducing the missing boundary. This covers single/batch inputs, parallel sampling, streaming flags, empty session dictionaries, and replacement parameters.

Historical validation reported at `af2ea88c` follows; these checks were not rerun as complete server imports in this integration.
