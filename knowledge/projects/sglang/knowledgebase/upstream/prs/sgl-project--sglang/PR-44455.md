# [Perf] [AMD] lm_head: Use aiter tgemm for the bf16 lm_head on gfx1250

[Upstream PR](https://github.com/sgl-project/sglang/pull/44455) · state: open · merged: False

## Original PR description

## Motivation

On gfx1250 the unquantized bf16 lm_head goes through `torch.matmul`, which lands on hipBLASLt and is several times slower than aiter's GEMM at decode batch sizes.

## Modifications

With `SGLANG_USE_AITER=1` on gfx1250, a 2D bf16 lm_head matmul uses `aiter.tuned_gemm.tgemm.mm`, as `unquant.py` already does for linear layers on HIP. Other dtypes, shapes and devices keep the existing path.

### Dependency on aiter

None beyond the aiter in the gfx1250 Docker image: `tgemm` and its gfx1250 GEMM path are already there.

## Setup

Kimi-K2-Thinking-MXFP4, TP8, MI455X (gfx1250), image `rocm/sgl-dev:v0.5.21-rocm10-mi45x-20261011`; aiter is the image's plus ROCm/aiter#5935, #5501, #5043 and #5402 (all in aiter 2bb549102). The Kimi-K2 cookbook targets MI300X; flags used here beyond it: `--attention-backend aiter --prefill-attention-backend aiter --decode-attention-backend triton --page-size 64 --disable-radix-cache --disable-custom-all-reduce --chunked-prefill-size 8192 --cuda-graph-max-bs-decode 128`, with `SGLANG_USE_AITER=1`, `SGLANG_ROCM_FUSED_DECODE_MLA=0` and `AITER_FORCE_A8W4=1`. Before and after differ only by this PR.

## Accuracy Tests

GSM8K with `few_shot_gsm8k` (8-shot, 1319 questions, `max_new_tokens` 512, the settings of sglang's AMD Kimi accuracy tests): before and after to be added.

The lm_head output is bit-identical to `torch.mm` at batch sizes 1, 4, 32 and 128.

## Speed Tests and Profiling

lm_head of Kimi-K2 at TP8 (vocab shard 20480 x 7168, 293 MB of weights, far larger than L2), MI455X, CUDA-graph replay:

| batch | torch.mm (ms) | tgemm.mm (ms) |
|---|---|---|
| 1 | 0.131 | 0.070 |
| 4 | 0.129 | 0.062 |
| 32 | 0.285 | 0.074 |
| 128 | 0.986 | 0.232 |

End to end, TP8 8k/1k concurrency 4: TPOT before and after to be added.
