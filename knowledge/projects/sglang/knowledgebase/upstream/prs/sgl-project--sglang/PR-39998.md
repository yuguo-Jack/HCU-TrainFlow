# [AMD] FP8 prefill for AITER: FP8-Q unified attention, and FP8 ASM FMHA for GQA ratios like 6 via KV-head repeat

[Upstream PR](https://github.com/sgl-project/sglang/pull/39998) · state: open · merged: False

## Original PR description

## Motivation

#38757 routes AITER extend/prefill through `unified_attention`. When the KV cache is FP8, it still passes Q in BF16. AITER then sees a BF16-Q / FP8-KV call, which has two effects:

- AITER does not select its tuned FP8-Q / FP8-KV prefill config (ROCm/aiter#5598).
- The gfx950 Gluon kernel is not used, because it requires Q and KV to have the same dtype (ROCm/aiter#4614).

The unified **decode** path already quantizes Q to FP8 with `scaled_fp8_quant()` and passes the matching `q_descale`. This PR makes prefill do the same.

## Modifications

In `_forward_extend_unified()`, when `kv_cache_dtype` is FP8:

- Quantize Q to FP8 with the layer's K scale (`layer.k_scale`, or the backend default), as decode does.
- Pass the same scale as `q_descale` to `unified_attention`.

With a BF16 KV cache, nothing changes.

**When this code runs:** `_forward_extend_unified()` is used when `SGLANG_USE_AITER_UNIFIED_ATTN=1` is set, and also, automatically, for models with a sliding-window KV pool. In both cases decode already uses FP8 Q, so this change gives prefill the same Q precision as decode. Routing does not change.

## Kernel selection check

MI355X, Qwen3.8-27B (24 Q heads, 4 KV heads, `head_dim=256`), FP8 KV:

| Stack | Q / KV dtype | AITER kernel config |
|---|---|---|
| Before this PR | BF16 / FP8 | generic Triton `D_GEQ_256` (`BLOCK_M=16`, tile 32) |
| This PR + ROCm/aiter#5598 | FP8 / FP8 | `D_GEQ_256.Q_GEQ_256.DT_fp8_fp8` (`BLOCK_M=128`, tile 64) |
| This PR + ROCm/aiter#4614 | FP8 / FP8 | gfx950 Gluon 2D prefill and 3D decode |


### FP8 ASM FMHA for GQA ratios the kernel lacks

The gfx950 FP8 `head_dim=256` ASM FMHA kernel accepts only GQA ratios 1/2/4/8/16. Qwen3.8-27B has 24 Q / 4 KV heads (ratio 6), so its prefill fell through to unified or CK attention.

`_forward_extend_fp8_asm_gqa_repeat()` gathers the paged FP8 KV (through a uint8 view), repeats each KV head so the ratio becomes a supported one (6 → 2, 3 → 1), quantizes Q with the K scale and calls `flash_attn_varlen_fp8_pertensor_func` (causal). The repeat factor is the odd part of the ratio, used only when the remaining power of two is a supported ratio.

- Gate: gfx950, FP8 KV cache, `head_dim == v_head_dim == 256`, plain extend (no speculative, sliding window, sinks or soft cap). Everything else keeps its current path.
- `SGLANG_ENABLE_AITER_FP8_ASM_PREFILL_GQA_REPEAT` (default on) turns it off.
- Cost: the gathered and repeated KV is a temporary of about 0.75 GB per layer at 128K context, TP1.
- On Qwen3.8-27B this path takes every prefill chunk, so the FP8-Q unified prefill above is the fallback for configurations outside the gate.

## Accuracy Tests

- New unit tests in `test_aiter_fp8_q_unified_attention.py`:
  - FP8 KV: Q is quantized with the K scale, `q_descale` is passed, `cu_seqlens_q` is correct, and the output shape and dtype are unchanged.
  - BF16 KV: Q passes through unchanged and `q_descale` is `None`.
- The full test file passes on MI355X.
- Re-validated post-rebase on AMD Instinct MI355X (ROCm 10, AITER): all 5 unit tests in `test/registered/attention/test_aiter_fp8_q_unified_attention.py` pass cleanly.
- Deterministic chat-template checks give the same answer with BF16 Q, FP8 Q, ROCm/aiter#5598, and ROCm/aiter#4614. This covers a short prompt and a 60K-token needle prompt.

- `TestAiterFP8AsmPrefillGQARepeat`: repeat factors, and 24/4 and 12/2 head layouts with prefix + extend against a float reference.

## Speed Tests and Profiling

These numbers are for **this PR together with ROCm/aiter#5598**. This PR is what lets AITER pick the FP8 config, but the speedup comes from the AITER kernel.

MI355X, TP1, Qwen3.8-27B MXFP4, FP8 KV, `--chunked-prefill-size 16384`. Same request count and token count in every run.

| Workload (input/output, concurrency) | Baseline (tok/s) | This PR + aiter#5598 (tok/s) | Change |
|---|---:|---:|---:|
| 8K/1K, c4 | 372.32 | 377.03 | +1.3% |
| 60K/600, c4 | 156.85 | 177.33 | +13.1% |
| 60K/600, c16 | 218.84 | 260.60 | +19.1% |
| 128K, c4 | 105.84 | 132.14 | +24.8% |
| 128K, c16 | 130.78 | 173.95 | +33.0% |

The baseline is the same setup without this PR or aiter#5598. With prefill-heavy requests (output length 8), median TTFT was 52% lower at 60K input and 65% lower at 128K input than the same stack with BF16 Q.


### FP8 ASM prefill with GQA repeat

MI355X, TP1, `amd/Qwen3.8-27B-Quark-AWQ-MXFP4`, FP8 KV, `sglang.bench_serving` A/B on the five long-context rows of our sweep, against the same image without this commit:

| Input length, concurrency | Throughput |
|---|---|
| 60K c4 | +7.8% |
| 60K c16 | +10.4% |
| 60K c64 | +11.1% |
| 128K c4 | +17.1% |
| 128K c16 | +20.2% |
| **Geomean** | **+13.2%** (TTFT −15.6%, TPOT −10.9%) |

Kernel time for the prefill attention drops 40–53% at TP1 and 33–49% at TP2. GSM8K 0.950; a 112K-token needle prompt gives identical greedy output.
