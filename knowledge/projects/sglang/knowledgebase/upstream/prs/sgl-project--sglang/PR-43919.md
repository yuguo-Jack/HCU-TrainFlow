# [unified memory pool] Prefer SWA reclaim quotas with a HiCache storage backend or on PD decode

[Upstream PR](https://github.com/sgl-project/sglang/pull/43919) · state: closed · merged: True

## Original PR description

## Motivation

`UnifiedSWATokenToKVPoolAllocator.reclaim_plan` computes the joint FULL/SWA eviction quotas with a fixed priority: it first finds the least SWA reclaim that fits with every evictable FULL token available, then trims FULL. That spends FULL prefix before it touches the sliding window.

Two configurations want the opposite priority:

- a HiCache storage backend is attached: the FULL prefix is the part of the tree that storage can serve again, so it is the part worth keeping resident;
- the engine is the decode side of a PD pair: the device prefix arrives by transfer rather than by local prefill.

## Modifications

- `reclaim_plan(..., prefer_swa=False)`: with `prefer_swa` the same two-pass search runs with the roles swapped, i.e. least FULL reclaim first, then least SWA reclaim.
- `evict_to_free_tokens` selects `prefer_swa` when `enable_hierarchical_cache` is set and `hicache_storage_backend` is not `None`, or when `disaggregation_mode == "decode"`. The leaves are read per call because the storage attach/detach endpoints and PD role switching change them at runtime.
- Only the quotas handed to the tree change. Victim selection, eviction cascades, locks, compaction gates and capacity checks are untouched; direct component eviction and `evict_for_alloc` keep their original order.

## Tests

`test/registered/unit/mem_cache/test_multi_ended_allocator.py`:

- `test_reclaim_plan_matches_exhaustive_page_targets` now also asserts the `prefer_swa=True` plan equals the lexicographic (FULL, SWA) minimum of the feasible set, next to the existing (SWA, FULL) check.
- `test_evict_to_free_tokens_prefers_swa_reclaim_on_storage_or_decode` pins the planner argument for four configurations: default and hierarchical-cache-only keep FULL-first; storage backend and decode role switch to SWA-first.

Both are red on main (`reclaim_plan` rejects the keyword; the argument is absent) and green here. The ten CPU unit files that build the unified SWA allocator (`test_multi_ended_allocator`, `test_prefill_memory_budget`, `test_unified_radix_allocation_eviction`, `test_swa_locked_full_recover_unified`, `test_unified_byte_accounting`, `test_unified_tri_pool`, `test_unified_capacity_memo`, `test_unified_free_no_host_sync`, `test_unified_swa_shared_virtual_ids`, `disaggregation/test_unified_memory_move_gate`) pass with the change.
