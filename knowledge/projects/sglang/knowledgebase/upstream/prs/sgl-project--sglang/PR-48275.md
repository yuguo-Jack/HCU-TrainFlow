# [Feat] hicache: debug check that load-backs restore the backed-up rows

[Upstream PR](https://github.com/sgl-project/sglang/pull/48275) · state: open · merged: False

## Original PR description


## Motivation

When HiCache output goes wrong after a host hit, the cause is hard to localize. It might be the backup, the host layout, a load into the wrong slot, a race with eviction, or a state the backup missed. Today nothing checks that the rows a load-back writes to the GPU are the rows that were backed up for those host slots.

This PR adds an opt-in debug check, `SGLANG_DEBUG_HICACHE_VERIFY=1`. Rows backed up from the GPU through the L2 transfer engine are hashed, and each later load-back of those host slots is checked against the hash, row by row, at a cost that only applies while the variable is set. Host slots filled without a device-to-host backup (by a storage backend or by PD decode host receive) cannot be checked, so the check turns itself off in those setups.

## Modifications

- `python/sglang/srt/mem_cache/hicache_verify.py` (new): `HiCacheVerifier`.
  - **Backup:** after a device-to-host backup finishes, each backed-up device row is hashed (two 64-bit polynomial hashes over the row's bytes, computed on the device). The hash is stored under the row's host slot.
  - **Load:** after a host-to-device load finishes, the loaded device rows are hashed the same way and compared with the hashes stored for their host slots. Mismatches are logged as errors with the host slots. Counts (`written`, `checked`, `mismatch`, `unverified`) are logged at most every 60 s.
  - **Rows covered:** MHA pools (all layers' K and V), MLA pools (all layers' KV), Mamba pools (conv and temporal state), and pools that wrap a `full_kv_pool`. Rows of other pools are counted as unverified, with a one-time warning naming the pool. So are host slots that have no recorded backup, such as packed draft-model layers, which are loaded but not backed up by a transfer of their own.
  - **Memory:** hashes are kept in per-(host pool, device pool) tensors indexed by host slot (16 B per slot), so their memory is bounded by the host pool size. Rows are hashed one layer at a time, in chunks of 64K words against one fixed 1 MiB coefficient table per device, so the hashing temporaries are one layer's copy of the rows plus 1 MiB per row, whatever the all-layer row size (Mamba temporal state included).
- `python/sglang/srt/mem_cache/l2_transfer.py`: `L2TransferEngine` builds the verifier when the variable is set. `submit_device_to_host` and `submit_host_to_device` wait for the transfer's finish event and pass the submitted transfers to it. The HiCache controllers, the unified radix cache and the Mamba component back up and load through these two methods. With the variable unset, the only change is one `is not None` check per submission.
- `python/sglang/srt/managers/cache_controller.py` and `python/sglang/srt/disaggregation/decode.py`: attaching a storage (L3) backend, or enabling PD decode host receive (`--disaggregation-decode-host-receive-threshold` below 1), turns the check off with one warning. Storage prefetch and the prefill peer write host slots directly, without a device-to-host backup, so a reused slot would still carry the previous occupant's hash and its load-back would be reported as a false mismatch.
- `python/sglang/srt/environ.py`: `SGLANG_DEBUG_HICACHE_VERIFY = EnvBool(False)` in the debugging section.
- `docs/docs/references/environment_variables.mdx`: a row for the new variable.
- `test/registered/unit/mem_cache/test_hicache_verify.py` (new, CPU):
  - a backup and load round trip through `L2TransferEngine` is checked;
  - a host row with one flipped bit is reported as a mismatch;
  - Mamba conv/temporal rows are covered;
  - slots without a backup and unsupported pools count as unverified;
  - a flipped byte in the last chunk of a multi-chunk row is reported;
  - turning the check off (as a storage attach does) leaves transfers working;
  - the check is off by default.
- `test_decode_retraction_backup.py`: enabling decode host receive turns the check off. `test_hicache_storage_registration_hook.py`: attaching a storage backend turns it off.
- `test_hicache_storage_registration_hook.py`, `test_hicache_dcp_host_pool.py`, `test_hicache_unified_key_scheme.py`: their controller stubs, built without `__init__`, gain the `l2_transfer_engine` attribute that `attach_storage_backend` now reads.

## Accuracy Tests

The check only reads rows after transfers finish. With the variable unset, the code path is unchanged.

Each model ran a 16-conversation x 6-turn shared-prefix workload with HiCache, then re-sent the first turn after 65 s idle. The re-send makes the device evict prefixes to the host and load them back. Greedy decoding, same server args with the check on and off.

| Model | GPU | HiCache args | Rows checked (last periodic count) | Mismatches | Cached tokens on / off |
|---|---|---|---|---|---|
| Qwen/Qwen2.5-0.5B-Instruct (MHA) | RTX PRO 6000 Blackwell | `--hicache-ratio 4 --max-total-tokens 16384` | 70,570 | 0 | 242,959 / 242,959 |
| Qwen/Qwen3.5-4B (GDN hybrid: KV + Mamba state) | H100 80GB | `--hicache-size 16 --max-total-tokens 16384 --max-mamba-cache-size 96 --mamba-radix-cache-strategy extra_buffer` | 67,075 | 0 | 218,644 / 218,644 |

Generated text with the check on agrees with the check off within the agreement of two check-off runs (Qwen3.5-4B: 74/96 on vs off, 70/96 off vs off; Qwen2.5-0.5B: 73/96 vs 77/96). Neither model is repeat-deterministic with the radix cache on. `--enable-deterministic-inference` turns the radix cache off, which HiCache does not allow.


## Speed Tests and Profiling

No speed claim. The check is off by default and adds one `is not None` test per transfer submission when off. When on, it synchronizes the transfer stream on every backup and load, so it is meant for debugging, not production serving.
