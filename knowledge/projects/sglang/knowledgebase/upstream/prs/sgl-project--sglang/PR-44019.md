# [CI] [NPU] npu-coverage: run only coverage-recommended tests on PRs (precise test selection)

[Upstream PR](https://github.com/sgl-project/sglang/pull/44019) · state: closed · merged: True

## Original PR description

<!-- Thank you for your contribution! Please follow these guidelines to enhance your pull request. If anything is unclear, submit your PR and reach out to maintainers for assistance. Join our Slack community at https://slack.sglang.io to discuss further. -->

## Motivation

Every same-repo PR currently runs all 9 NPU a3 suites (base-b 1/2/4/8/16, base-c
acc/perf 2/16) in full on scarce self-hosted Atlas 800T runners, even when the
change touches a narrow code slice. The coverage infrastructure to do better
already exists (per-test coverage collection, test_case_map, test_selector), but
it could not actually drive PR runs:

- `recommend-tests-from-coverage` was hard-disabled (`if: false`, OBS baseline
  returned 403) and its recommendations were never wired into the real test
  jobs — no per-suite bucketing, no filtering, no skip semantics.
- The baseline was incomplete: server / scheduler / detokenizer subprocesses
  were untraced (subprocess coverage had been removed pending a graceful
  teardown story), and the base-a CPU unit suite contributed no coverage, so
  recommendations systematically missed server-side code paths.
- `test_selector.py` only recognized the k8s workspace prefix, silently
  discarding test cases collected under other runner topologies, and
  parametrized pytest node ids were mangled by the filesystem-safe encoding.
- There was no coverage report to inspect what the baseline actually measures.

This PR closes the loop: NPU PR CI now runs only the coverage-recommended
subset per suite, and the baseline behind those recommendations now includes
subprocess (server-side) code, the base-a unit suite, hosted-runner
collections — and is inspectable via HTML reports.

## Modifications

**Precision test selection (PRs run only the recommended subset)**
- Re-enabled `recommend-tests-from-coverage` in `pr-test-npu.yml` (runs on
  `pull_request` in non-coverage mode). Every step carries step-level
  `continue-on-error: true`, so this advisory job always concludes `success`
  and can never cascade-kill test jobs through the fast-fail health check;
  failed steps stay visible (red ✗ + annotation).
- Added `scripts/ci/npu/precise-test/bucket_recommended_tests.py`: enumerates
  each suite's registered PR-mode tests via `list_tests.py`, intersects with
  the recommendation, and exports per-suite `should_run_<suite>` /
  `only_tests_<suite>` outputs. Empty bucket → skip the whole job (frees a3
  runners); zero-file enumeration falls back to a full run (registered-pool
  guard, no silently green suites); any failure → empty outputs → full-suite
  fallback.
- All base-b / base-c a3 jobs now `needs: recommend-tests-from-coverage`,
  skip on `should_run_* == 'false'`, and pass their bucket via the new
  `only_tests` input.
- `_npu-pr-test-stage.yml` / `_npu-single-node-test-stage.yml`: new
  `only_tests` input; a non-empty list is staged to
  `/tmp/precision_tests.txt` and forwarded as `run_suite.py --only-file-list`;
  coverage job names now include the partition.
- `test/run_suite.py`: new `--only-file-list` (with `load_only_file_list`)
  filters the suite before partitioning, so matrix shards split the filtered
  pool evenly and disjointly.

**Subprocess coverage re-enabled (server / scheduler / detokenizer measured)**
- `run_tests_with_coverage.sh`: exports `COVERAGE_PROCESS_START` and installs
  an inert-by-default `sglang_ci_subprocess_coverage.pth` next to the
  coverage package so Popen'd servers auto-start coverage; subprocess files
  inherit the per-test `COVERAGE_FILE` (parallel mode suffixes them) and land
  in the same per-test dir, so the existing combine / test_case_map logic
  attributes them with zero changes. `CACHE_ROOT` is now overridable via
  `PRECISE_TEST_CACHE_ROOT`.
- `coveragerc`: `sigterm = True` — scheduler/detokenizer have no SIGTERM
  handler of their own; the handler installed by `process_startup()` is what
  flushes their data when teardown SIGTERMs the tree.
- New `precise_test_coverage_plugin.py` pytest plugin, double-gated on
  `SGLANG_KILL_PROCESS_TREE_GRACEFUL=1` and loaded only in coverage runs:
  patches `kill_process_tree` in the pytest process only with a SIGTERM-first
  + bounded-wait (default 20 s) wrapper that defers to the original SIGKILL
  backstop, and refreshes stale bindings across `sys.modules`. No product
  code (`python/sglang`) is modified.
- `setup_coverage` encoding keeps `[` and `]` so parametrized pytest node ids
  (`test_x[case_id]`) stay reversible.

**Baseline completeness & runner generality**
- `test_selector.py`: replaced the hardcoded k8s prefix with
  `WORKSPACE_MARKER = "__sglang__sglang__"`, recognizing both k8s
  (`/__w/sglang/sglang`) and hosted (`/home/runner/work/sglang/sglang`)
  checkout roots via partition at the first anchor.
- New `base-a-test-npu-cov` job in `pr-test-npu.yml`: coverage-mode
  counterpart of the base-a CPU unit gate. Runs on `ubuntu-latest` (the suite
  mocks torch_npu / sgl_kernel_npu and needs a CPU triton; the NPU image's
  triton-ascend conflicts with those mocks), stages coverage under a local
  `PRECISE_TEST_CACHE_ROOT`, and ships it to `setup-covstub` as an artifact
  that merges 1:1 into the shared-disk run dir.
- `setup-covstub` merges that artifact and materializes the git-ignored
  `_version.py` placeholder in covstub so report generation finds all
  recorded sources.

**HTML coverage reports (visibility, non-blocking)**
- New "Generate HTML coverage report" step in `setup-covstub`: combines the
  per-test data (`--keep`) and renders two reports — the full one plus an
  NPU-only view via a dedicated rcfile
  (`source = covstub/sglang/srt/hardware_backend/npu`, full-tree denominator,
  never-imported files count as 0%). Totals are appended to the step summary.
- The step uses `continue-on-error: true` with natural `errexit` propagation:
  a failure shows as a red step but never blocks the baseline
  Archive/Publish/Cleanup pipeline. Reports live outside `outputs/`, are
  uploaded as the `coverage-html-report` artifact, and are published to the
  shared disk as fixed-name `htmlcov.tar.gz` / `htmlcov-npu.tar.gz`
  (latest-run retention, same as the baseline).
- `setup-covstub` and `pr-test-npu-finish` now also wait on
  `base-a-test-npu-cov`.
