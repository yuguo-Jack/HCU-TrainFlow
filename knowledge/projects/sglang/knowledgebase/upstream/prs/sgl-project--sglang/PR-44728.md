# [Docs] [AMD] Qwen3.8-27B cookbook: Add an MI355X MXFP4 recipe

[Upstream PR](https://github.com/sgl-project/sglang/pull/44728) · state: open · merged: False

## Original PR description

## Motivation

The Qwen3.8-27B cookbook page has no AMD recipe. AMD publishes an MXFP4 checkpoint for CDNA4, `amd/Qwen3.8-27B-Quark-AWQ-MXFP4`: the language model is MXFP4 W4A4 and the vision encoder stays bf16. It runs on a single MI355X.

## Modifications

- `qwen3.8-27b.jsx`:
  - adds `mi355x` hardware and an `MXFP4` quantization option;
  - maps the model name to the AMD checkpoint;
  - sets the ROCm docker image (`lmsysorg/sglang-rocm:v0.5.21-rocm724-mi35x-20261014`).
- New `mi355x` / `mxfp4` cell, single GPU like the other cells. Flags come from the AMD nightly performance config for this checkpoint at TP1:
  - `SGLANG_USE_AITER=1`, `--quantization quark`, `--attention-backend aiter`;
  - `--kv-cache-dtype fp8_e4m3`, `--mem-fraction-static 0.9`, `--chunked-prefill-size 16384`;
  - the qwen3 reasoning and tool-call parsers.

  The cell reports **Final Verification In Progress** until the accuracy results below are in.
- The DSPARK overlay is disabled on MI355X: it pins a FlashInfer draft attention backend, which ROCm does not ship.
- Page text: MI355X added to the supported cards. A note recommends `--mm-enable-dp-encoder` when serving at `--tp-size 2`, so that each GPU encodes whole images instead of splitting every vision layer across both GPUs.

`node docs/scripts/check_cookbook_configs.mjs` passes.

## Accuracy Tests

Pending (MI355X): GSM8K (1319 questions, `run_eval`) for the new cell, and MMMU at TP2 with `--mm-enable-dp-encoder` off/on.

## Speed Tests and Profiling

Pending (MI355X): image-serving throughput at TP2 with `--mm-enable-dp-encoder` off/on.
