# [Fix] scheduler: Never schedule a late request after an abort-mode pause with multiple tokenizer workers

[Upstream PR](https://github.com/sgl-project/sglang/pull/45809) · state: open · merged: False

## Original PR description

## Motivation

Fixes #45773.

With `--tokenizer-worker-num > 1`, `/pause_generation` with `mode="abort"` can return while another tokenizer worker still has a request in flight. That request reaches the scheduler after the pause; the scheduler is not paused in `abort` mode, so it schedules it. If the caller then releases the KV cache (`/release_memory_occupation`, the usual RL weight-update flow), the request runs against a released KV cache.

The pause only waits for the **originating** worker's `model_update_lock`:

- Each tokenizer worker has its own `is_pause` and `model_update_lock`; a request passes the pause gate, then tokenizes and is sent **inside** that worker's reader lock (which spans the request's whole lifetime).
- The router broadcasts `is_pause` to all workers but skips forwarding an `abort` pause to the scheduler, so `_engine_paused` stays `False`.
- The originator's polling (`abort_all` + own-lock check) exits without observing other workers' in-flight requests.

With one tokenizer worker this cannot happen: the single reader lock covers every in-flight request.

## Modifications

Make the scheduler the authority for abort-mode pauses, so correctness no longer depends on which worker originated the pause:

- **`multi_tokenizer_mixin.py` (router)**: forward abort-mode `PauseGenerationReqInput` to the scheduler as well (in_place/retract were already forwarded).
- **`scheduler.py`**:
  - `pause_generation` accepts `"abort"` with **deferred** semantics:
    1. Raise a `_pending_abort_pause` gate first — every request admitted from then on is aborted by a pending check in `handle_generate_request`/`handle_embedding_request` (admit through the normal path so per-request state exists, then abort with the standard machinery), instead of being scheduled.
    2. Sweep `abort_all` once, authoritatively at pause-processing time, so requests already queued/running are aborted even if the originator's polling already fired its last `abort_all` (a ZMQ ordering window).
    3. **Do not** set `_engine_paused` immediately: requests in the running batch need forward passes to finish their aborts, and freezing the loop would deadlock the pause. The engine keeps running until the drain completes.
  - `_promote_pending_abort_pause` (called from `ingest_requests`, the single point all event loops share — normal, overlap, PD prefill/decode, MLX) flips `_engine_paused` once `is_fully_idle(ignore_waiting=False)`: running batch, waiting queue and disagg queues are all empty, so nothing can be scheduled between the promotion and `continue_generation`.
  - `continue_generation` also clears a never-promoted pending gate (continue raced ahead of the drain).
- **Single-worker path unchanged**: there the reader lock spans the whole request lifetime, so the originator's poll already covers every in-flight request; the scheduler never sees an abort pause in that mode.
- `io_struct.py` docstring + RL docs updated to describe the new abort-mode contract. No caller breaks: after an abort pause the tokenizer gates are already closed for all modes, so the server already required `continue_generation` to accept work again.

After the promotion, a request that arrives even later simply queues like `in_place` (never scheduled during the pause window, runs on fresh state after `continue_generation`) — no corruption in any interleaving.

## Accuracy / Regression Tests

`test/registered/unit/managers/test_scheduler_pause_generation.py` (replaces `test_abort_mode_rejected_at_scheduler`, which pinned the old "abort not accepted" contract):

- abort pause defers: pending gate raised, engine still running, one authoritative abort_all sweep fired
- bare `PauseGenerationReqInput()` (defaults to abort) defers the same way
- promotion happens only at full idle, and not while queues are non-empty
- promotion is a no-op without a pending pause
- `continue_generation` clears a stale pending gate
- a late arrival is aborted while the gate is pending

`test/registered/unit/managers/test_multi_tokenizer_mixin.py`:

- router forwards both abort pause and continue to the scheduler and broadcasts both to every registered worker (order-independent assertion; `all_worker_ipcs` is a set)

`test/registered/unit/disaggregation/test_prefill_result_polling.py`: harness gains the new attribute (it drives the real `ingest_requests`).
