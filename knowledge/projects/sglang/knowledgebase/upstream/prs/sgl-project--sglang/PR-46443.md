# [Fix] diffusion: Fix rollout conditioning and scalar weight checksums

[Upstream PR](https://github.com/sgl-project/sglang/pull/46443) · state: closed · merged: True

## Original PR description

Fixes #46444.

## Bugs reported

### 1. Batched rollout trajectories associate samples with the wrong conditioning

**Affected code:** `runtime/post_training/rl_dataclasses.py`, `concat_rollout_trajectory_data()` and `select_output_rollout_trajectory()`.

**Trigger:** Multiple rollout outputs with different prompts or conditioning are dynamically batched. Their denoising environments contain per-sample values such as positive/negative prompt embeddings and guidance tensors.

**What goes wrong:** The merge concatenates sample-aligned latent trajectories and log-probabilities, but sets `denoising_env` to the first output's environment. The later selection step slices the trajectory tensors for a requested output, yet passes that same unsliced environment through for every output. Consequently, output 1, 2, and so on can each carry output 0's conditioning.

**Impact:** A trainer that replays the denoiser using the returned trajectory environment evaluates later samples under the wrong prompt/conditioning. Their recomputed log-probabilities no longer correspond to the conditioning used to generate those samples. The request can complete without an error, leaving the RL update silently based on mismatched data.

**Fix and regression coverage:** Merge batch-shaped tensors recursively through the environment's nested dictionaries/lists/tuples, and slice those tensors by output index when selecting one trajectory. The regression is added to the existing `test_multi_output_rollout_trajectory.py` and checks three distinct prompt embeddings and guidance values after merge and per-output selection.

### 2. Tensor checksum verification raises on zero-dimensional tensors

**Affected code:** `runtime/post_training/tensor_update_checker.py`, `compute_tensor_sha256()`.

**Trigger:** The update checker hashes a scalar parameter or buffer, such as a zero-dimensional BF16 tensor.

**What goes wrong:** After moving the tensor to CPU and making it contiguous, the function calls `tensor.view(torch.uint8)`. PyTorch rejects a zero-dimensional tensor when the view changes element size, raising `RuntimeError` instead of returning a digest.

**Impact:** Weight verification fails for valid scalar tensors, so the checker cannot verify an update manifest containing one. The failure is in checksum construction, not a mismatch between the submitted and loaded weights.

**Fix and regression coverage:** Flatten the tensor before viewing its bytes, while continuing to include its original shape and dtype in the hash. The regression was added to the existing `test_weight_utils.py` and verifies that a scalar BF16 tensor returns a repeatable SHA-256 digest.
