# [Fix] grpc: Add option to use remaining context

[Upstream PR](https://github.com/sgl-project/sglang/pull/44123) · state: open · merged: False

## Original PR description

## Summary

When a client uses SGLang’s typed Generate or TextGenerate gRPC RPC and does not provide an output-token limit, the API currently cannot distinguish between using the default limit (when max_new_tokens is absent) and having no caller-provided limit (when max_new_tokens is null). As a result, requests intended to generate up to the safe context and KV-cache limits are instead capped at the default of 128 tokens.

## Changes

- add `use_remaining_context` to the runtime gRPC sampling parameters
- forward `max_new_tokens: null` when no explicit limit is provided and the option is enabled
- preserve explicit `max_new_tokens` precedence and the existing default behavior
