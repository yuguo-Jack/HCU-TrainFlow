# [diffusion] Support BCG for LTX-2.3 / LTX-2.5

[Upstream PR](https://github.com/sgl-project/sglang/pull/42928) · state: closed · merged: False

## Original PR description

## Motivation

Breakable CUDA graphs (BCG) did not take effect for LTX-2.3 serving. Requests ran eager, and nothing in the log said so:

- The stage-1 guided passes (STG / modality, split and batched) called the DiT directly instead of going through the BCG runner.
- Warmup did not carry the request's guider params, so it captured the official-CFG signatures that serving never replays.
- The STG perturbation mask was built with a host-to-device copy, which is illegal inside a graph capture.

LTX-2.5 was not on the BCG allowlist at all.

At typical sizes LTX is host-bound: a denoising step issues 36k (LTX-2) to 76k (LTX-2.3) PyTorch ops, so the GPU waits on the CPU. BCG replays each step's DiT forward from captured graphs, which cuts host ops per step about 10x with bit-identical output.

## Modifications

- LTX-2.3 guided passes go through the BCG runner (`_ltx2_call_current_model`).
- LTX-2.3 warmup carries the request's guider params, so warmup captures the signatures serving uses.
- The STG perturbation mask is filled on device.
- LTX-2.5 is added to the BCG allowlist.
- The LTX-2 / LTX-2.3 and LTX-2.5 cookbook pages document BCG and its warmup rules:
  - Warm up at the served shape.
  - Name a warmup image for image-conditioned requests.
  - Warm up at the request's quality level.
  - Keep the DiT resident, since graphs hold its weight addresses.
- Unit test: the LTX-2.3 warmup request carries the stage-1 guider params.

CI cases are unchanged.

## Validation

H200 with the H100 setup emulated: 80,900 MiB free per GPU and `original` two-stage mode. Each run is a CI case with BCG enabled and warmup at the case's shape. Per-step times are not H100 numbers.

Eager vs BCG, 2 runs each, before merging the latest main:

| Case | Step eager -> BCG | E2E eager -> BCG | Peak reserved / allocated, BCG (MiB) | BCG output vs eager |
|---|---|---|---|---|
| ltx_2_two_stage_t2v | 150 -> 43 ms | 7.56 -> 2.87 s | 60,002 / 56,645 | byte-identical |
| ltx_2.3_two_stage_t2v_2gpus | 179 -> 76 ms | 7.02 -> 3.53 s | 61,584 / 58,281 | byte-identical |
| ltx_2_3_two_stage_ti2v_2gpus | 334 -> 93 ms | 11.79 -> 4.10 s | 63,236 / 58,319 | byte-identical |
| ltx_2.3_one_stage_ti2v | 643 -> 407 ms | 20.61 -> 13.12 s | 55,332 / 51,746 | byte-identical |
| ltx_2_3_hq_pipeline | 896 -> 600 ms | 17.52 -> 13.20 s | 70,576 / 65,738 | byte-identical |
| ltx_2_5_diffusion_decoder_2gpus | 284 -> 147 ms | 6.69 -> 5.75 s | 71,064 / 69,968 | byte-identical |

The LTX-2.5 run keeps its DiT resident.

- Graphs replay in serving: the profile of steps 3-4 shows 289 graph launches per DiT call.
- Host ops per step drop from about 41k to 2.4k (LTX-2.3 t2v) and from 36k to 3.6k (LTX-2).
- All cases pass consistency against the H100 GT, except HQ, which already fails in eager on H200. Its BCG output is byte-identical to eager.

After merging the latest main, BCG on the same setup:

| Case | Graph captures / signature misses | Median step | E2E | Consistency |
|---|---|---|---|---|
| ltx_2.3_two_stage_t2v_2gpus | 3 / 0 | 76.3 ms | 3.54 s | pass, md5 equal to eager |
| ltx_2_3_two_stage_ti2v_2gpus | 5 / 0 | 92.3 ms | 4.10 s | pass |
| ltx_2_5_diffusion_decoder_2gpus | 2 / 0 | 151.1 ms | 5.20 s | pass |

`test_cfg_parallel_warmup.py` passes (54 tests).
