# [Feat] radix-tree: Report the last visited node and a shorter FULL device match in match results

[Upstream PR](https://github.com/sgl-project/sglang/pull/45703) · state: closed · merged: True

## Original PR description

## Motivation

A match walk can step into a node and then reject it: a host-only node without HiCache, a node past the SWA window, or a node a component validator declines. `MatchResult` reports only the deepest accepted node (`best_match_node`) and the device anchor, so a cache layered on the tree core cannot tell where the walk actually stopped. A core whose FULL device values are not laid out one pool row per token also has no place to report a reusable prefix that is shorter than the node-boundary match. Both cores and the binding should report these the same way so a caller behaves identically on either backend.

## Modifications

`MatchResult` gains two optional fields, on the Python `NamedTuple`, the Rust struct and the PyO3 binding:

- `last_visited_node_id`: the deepest non-root node the walk stepped into, whether or not a validator accepted it. `None` when the walk never left the root (empty key, empty tree, a dead first child).
- `full_device_match_len`: the reusable prefix length seen by the FULL device-value scan before node-boundary or auxiliary constraints. `None` when no shorter prefix was reported. The stock cores always report `None`; the field is a slot for a core that computes one.

Rust crate (`rust/sglang-radix-tree`): `match_prefix_helper_` returns the visited node with the rest of its walk state, `match_post_processor_` and `empty_match_result` fill both fields, `MatchResultBinding` exposes them and `InspectionMatchResultInput` reads them.

Python: `UnifiedTreeCore._match_prefix_helper(key, params)` now returns the finished `MatchResult` and calls `_match_post_processor` itself, passing the visited node and the device validators, so both cores build the result in one place; `match_prefix` becomes a thin wrapper. `zero_match_result` clears both fields, and `RustUnifiedTreeCore` copies them from the binding.

Tests: the Rust match tests assert `last_visited_node_id` on full hits, partial matches, misses, dead nodes, host-only nodes with and without HiCache, the SWA tombstone case and the borrowed-validator walk. `test_rust_tree_core_integration.py` runs the match cases on both backends and covers the empty tree (page size 2, keys of length 0, 1 and 3), an exact hit, a split match checked against `collect_path_info`, a host-only node whose visited node is independent of device acceptance, `zero_match_result` clearing the fields, the stale-finalizer path preserving them, and the SWA allocator-layout case.
