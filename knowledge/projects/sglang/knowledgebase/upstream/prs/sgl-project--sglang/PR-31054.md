# [AMD] Support Quark DeepSeek-V4-MXFP4 checkpoints on the DSV4 stack, enabling shared-expert fusion and MTP

[Upstream PR](https://github.com/sgl-project/sglang/pull/31054) · state: closed · merged: True

## Original PR description

## Summary

Enables the AMD Quark DeepSeek-V4-MXFP4 checkpoints ([amd/DeepSeek-V4-Pro-MXFP4](https://huggingface.co/amd/DeepSeek-V4-Pro-MXFP4), [amd/DeepSeek-V4-Flash-MXFP4](https://huggingface.co/amd/DeepSeek-V4-Flash-MXFP4)) on ROCm, including shared-expert fusion and MTP/EAGLE speculative decoding.

These checkpoints pre-quantize **shared expert to MXFP4**, matching the same spec as the routed experts, so it can be fused into the routed MoE. The checkpoints keep MTP block shared expert in blockwise FP8.

This PR also fixes a Quark MXFP4 MoE loading bug that silently dropped around 25% of every expert's FFN channels for running the [amd/DeepSeek-V4-Pro-MXFP4](https://huggingface.co/amd/DeepSeek-V4-Pro-MXFP4) checkpoint at TP8 (GSM8K 90%, vs base deepseek-ai/DeepSeek-V4-Pro GSM8K 96%).

## Changes

- **`layers/quantization/quark/schemes/quark_w4a4_mxfp4_moe.py`**: fixes padded TP loading. When aiter pads the per-rank intermediate width (e.g. 384 -> 512), each rank's real checkpoint channels now load at the head of its buffer, so the `intermediate_pad` tail aiter skips is actually zeros, instead of useful weights. Non-Quark schemes are unaffected. 
- **`layers/quantization/quark/quark.py`**:
  - DeepSeek-V4 fuses `wq_a` + `wkv` into `wqkv_a`, which has no per-layer spec of its own; it now inherits `wq_a`'s (blockwise FP8) spec instead of falling back to the global MXFP4 spec.
  - `can_fuse_shared_expert` also checks the NextN draft block (`model.decoder`), so the draft vetoes fusion when its FP8 shared expert doesn't match its MXFP4 routed experts. It also resolves the `shared_expert` vs `shared_experts` module spelling from the config's own keys; a misspelled lookup incorrectly fell through to the global spec.
- **`models/deepseek_v4.py`**:
  - `get_hf_to_sglang_mapper` maps Quark's checkpoint-named specs (`layers.N.attn.wq_a`, `mtp.0.ffn.experts.N.w1`, ...) onto sglang module names. It returns `None` for other formats, so the mapper does not affect other quant configs.
  - `_prepare_deepseek_v4_weights` renames Quark's FP8-block scales (`*.weight_scale`, e8m0) to the native DeepSeek-V4 spelling (`*.scale`). The existing native paths (attention `weight_scale_inv`, `e_proj`/`h_proj`, `wo_a` dequant) then apply unchanged.
- **`models/deepseek_v4_nextn.py`**: the draft's mapper places `mtp.0.*` under `model.decoder.*` (with `e_proj`/`h_proj` beside it), so the draft resolves its own per-layer specs, including the FP8 shared expert that vetoes draft fusion.
- **`test/registered/unit/layers/quantization/test_quark_config.py`**: CPU tests for the draft-only fusion veto, the `wqkv_a` spec, and padded TP loading. 



**Related Upstream Work**
- For the Quark MXFP4 MoE loading bug (`intermediate_pad` causing real weights to be dropped), the native DeepSeek-V4 FP4 path (`Fp8MoEMethod`) avoids this by aligning to 128 instead of 256 (PR #31450), so base DSV4 Pro TP8 runs unpadded at 384.
- PR #40811 added an unpadded Quark option for Kimi-K3, but only behind `SGLANG_AITER_K3_OPT`, and it isn't safe to enable globally (only the FlyDSL kernels accept 128-aligned widths).

### Launch server

```bash
SGLANG_USE_ROCM700A=0 SGLANG_HACK_FLASHMLA_BACKEND=unified_kv_triton AITER_BF16_FP8_MOE_BOUND=0 \
python3 -m sglang.launch_server --trust-remote-code \
  --model-path <model-dir> --tp <tp-size> \
  --attention-backend dsv4 --page-size 256 --kv-cache-dtype fp8_e4m3 \
  --mem-fraction-static 0.85 --swa-full-tokens-ratio 0.15 --chunked-prefill-size 16384 \
  --enforce-shared-experts-fusion \
  --host 0.0.0.0 --port 30000
# + MTP: --speculative-algorithm EAGLE --speculative-num-steps 3 --speculative-eagle-topk 1 --speculative-num-draft-tokens 4
```
