# [Fix] diffusion: Fail closed after local worker loss or multi-rank OOM

[Upstream PR](https://github.com/sgl-project/sglang/pull/46025) · state: closed · merged: True

## Original PR description

## Motivation

Production fault tests for #45919 exposed an independent bug: a local GPU worker can exit while the HTTP server still advertises readiness. A multi-rank allocator OOM is worse: the failing rank resumes request dispatch while its peer remains in the previous forward, permanently desynchronizing the replica.

Both failures were reproduced on main (`4b273537dec`), independently of progress reporting.

## Changes

- Track launcher-owned worker process identities, including the WebUI HTTP child and locally launched disaggregated pools.
- Return readiness 503 after any owned worker exits, including zombie/PID-reuse cases. Keep HTTP liveness independent.
- Check owned processes once per second, terminate pending scheduler waits even without an RPC deadline, and reject new POST requests with 503. Completed job status/content remain readable.
- Treat allocator OOM during a multi-rank forward as fatal to the worker. Exit at the process boundary without potentially blocking CUDA/NCCL teardown; do not reuse the desynchronized replica.
- Preserve request-level OOM recovery for single-GPU replicas, including independent DP replicas.
- Document restart requirements and coverage limits. No extra GPU collective, per-step callback, CLI knob, or change to generated outputs.

## Validation

- Remote regression tests: the new client and multi-rank OOM cases fail before the fix (3 failed, 2 passed). Fixed related suite: **114 passed, 4 subtests passed**.
- Real 2x H200 tests, PyTorch 2.14.1+cu130 / CUDA 13.0 / Diffusers 0.37.0 / Transformers 5.19.0. Wan2.1-T2V-1.3B-Diffusers, 512x320, 17 frames, seed 42, 24 denoising steps after warmup.
- A separate GPU allocation leaves approximately 128 MiB free; an 832x480, 33-frame request triggers a real allocator OOM, not an injected exception.
- Ulysses=2: pressure on rank 0 and rank 1 tested separately. All three in-flight/queued jobs fail within **0.77 s / 0.66 s**, without an RPC deadline. TP=2 non-output-rank OOM: **0.94 s**. Readiness/new POSTs return 503; previous output remains downloadable and decodes to identical frames.
- Single GPU: three OOM/recovery cycles. DP=2: three cycles on **each** GPU. All nine recoveries preserve decoded frame hashes; normal readiness remains 200.
- SP outputs before failure match main's decoded frame hashes. No owned child processes remain after shutdown.
- Combined with #45919 on a detached validation head: real per-step progress and multi-rank OOM handling both pass. The independent fixes remain separate PRs.
- Earlier real worker-SIGKILL tests also covered the spawned HTTP bootstrap and a local encoder/denoiser/decoder pool with Mooncake transfers. Full Gradio UI was not tested.
- Pre-commit passes. No GT, tolerance, or performance baseline changes.

This is bounded failure handling, not transparent failover: restart the whole server and retry failed jobs. Arbitrary live-process hangs, remote-worker supervision, durable job recovery, and fatal CUDA-context errors remain separate concerns (#45065).
