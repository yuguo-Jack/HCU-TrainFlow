# Honor GPU stride across scheduler and encoder launchers

[Upstream PR](https://github.com/sgl-project/sglang/pull/42084) · state: closed · merged: False

## Original PR description

## Motivation

`--gpu-id-step` currently multiplies only the tensor-parallel offset in scheduler placement. With `--pp-size 2 --tp-size 2 --gpu-id-step 2`, the four local ranks select GPUs `[0, 2, 2, 4]` instead of `[0, 2, 4, 6]`. Pipeline-only layouts also ignore the requested stride between stages.

The disaggregated encoder's TP and DP placement ignore the stride entirely. Its distributed local device is also initialized from the logical rank instead of the selected GPU, so nonzero base IDs or an explicitly selected DP device can disagree with the model device.

## Modifications

Apply the stride to the combined local PP/TP rank in the scheduler launchers and weight-cache placement helper. Preserve the configured base GPU ID and the DP replica offset, which is already measured in physical GPU IDs.

Apply stride to encoder TP defaults and parent-side DP placement before device reindexing. Use the resolved encoder GPU for distributed local-device initialization while preserving logical rank and explicit `gpu_id` overrides, including a reindexed zero.

## Accuracy Tests

- Scheduler/weight-cache CPU placement regressions: 3 methods, 24 subcases pass; the original source fails 12 subcases.
- Actual encoder constructor/DP-launcher CPU regressions: 2 methods, 10 subcases pass; the pre-fix encoder code fails 7 subcases. Cover nonzero bases, default/nondefault stride, explicit device overrides, and parent placement before reindexing.
- All applicable pre-commit hooks pass.
- Tests execute actual launcher methods and the encoder constructor up to distributed initialization. Process spawn, model/config initialization and GPU/distributed boundaries are doubled; local harnesses exclude eager GPU package initialization. No CUDA/NCCL, model execution, or multi-GPU performance claim is made.
