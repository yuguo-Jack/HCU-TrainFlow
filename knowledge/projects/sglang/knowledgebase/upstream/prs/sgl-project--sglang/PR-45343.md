# [Fix] logging: Use per-process request log files to avoid rotation races

[Upstream PR](https://github.com/sgl-project/sglang/pull/45343) · state: open · merged: False

## Original PR description

## Motivation

Fixes #45342. With `--tokenizer-worker-num > 1` and `--log-requests-target <dir>`, every tokenizer worker writes `<hostname>_0.log` with its own hourly `TimedRotatingFileHandler`. Their rotations race: a colliding rename overwrites the freshly rotated file, and the workers still holding it keep writing into an unlinked inode, so their logs are silently lost. Without a collision, N-1 workers never rotate. The race window is much wider on network file systems.

## Modifications

- `python/sglang/srt/utils/log_utils.py`: file targets are now named `<hostname>_<rank>_<pid>.log` (previously `<hostname>_<rank>.log`). Each process owns and rotates its own file. The logger name uses the same stem.
- `test/registered/utils/test_log_utils.py`: `test_file_per_process` forks 3 processes that log to the same directory and asserts that there are 3 separate files, one event each. It fails on the current code (`1 != 3`).

Behavior change: file names gain a `_<pid>` suffix, and a restarted server writes new files instead of appending to the old one. Tools that read a fixed `<hostname>_<rank>.log` need to glob `<hostname>_<rank>_*.log*`. The other options were to add the suffix only for tokenizer workers, or to use a worker index instead of the pid. Both need the worker identity threaded into `create_log_targets`. The pid also covers the scheduler status logger and any future multi-process caller, so it is the simpler choice. Happy to switch if maintainers prefer another option.

## Accuracy / Speed

Not affected (logging only).

## Testing
