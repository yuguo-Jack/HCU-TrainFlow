## Motivation

A pool combining full attention, sliding-window attention and recurrent state needs the same recurrent host layout and attention-parallel metadata as the other hybrid host stacks.

## Changes

- Share recurrent host-layout selection between hybrid stack builders.
- Select direct state storage for split-KV host layouts.
- Forward attention tensor/context-parallel groups when assembling the full/window/state host stack.

## Validation

At downstream `ca400c908c`, assembler coverage passed **43 tests**. Transfer comparison across **eight configurations** showed the intended attention-group changes; unsupported state layouts failed on both sides.

Later per-tip four-chain replay had **0 divergences**, and CPU host-layout selection passed. These are combined downstream and CPU results; attention TP/CP HiCache was not validated on distributed hardware.
