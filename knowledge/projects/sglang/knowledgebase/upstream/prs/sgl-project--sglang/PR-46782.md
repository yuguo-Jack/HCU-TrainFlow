# [Perf] wan2.2-s2v: Build the per-request shapes once, as Python ints

[Upstream PR](https://github.com/sgl-project/sglang/pull/46782) · state: open · merged: False

## Original PR description

## Motivation

Follow-up to #43279, for review comments 3 and 4 there:
- **Comment 3:** the S2V DiT rebuilt its shape tensors and RoPE table on every forward.
- **Comment 4:** `e[1].item()` graph-broke every block.

**Stacked on #43279:** this branch is #43279's head plus one commit, so until #43279 merges the diff also shows #43279's commits. Only the last commit is new: `[Perf] wan2.2-s2v: Build the per-request shapes once, as Python ints`.

## Modifications

One commit, `dits/wan_s2v.py` only (+197/−172).

- **Per-request shapes:**
  - The grids, `seq_lens`, condition masks and RoPE tables depend only on the latent shapes. `_build_request_shapes` now builds them once per request.
  - They are cached in an LRU of 4 (`_REQUEST_SHAPES_CACHE_SIZE`), keyed on the video/ref shapes, the motion-frame token counts and the device. A server alternating resolutions still hits.
- **RoPE tables:**
  - `RopeTableMixin._cached_rope_table` is an `lru_cache` keyed on plain-int grids and the owning module, following `RotaryEmbedding._forward_cached_from_grid` in `mrope.py`.
  - The table is built for one head, since the rotation is the same for every head and `rope_apply` broadcasts it. At 30,976 tokens that is about 32 MB of complex128 instead of about 1.27 GB for 40 heads.
- **Motion frames:** `FramePackMotioner` keeps its frame buckets and RoPE grids as Python ints and gets its table from the same cache. The forward runs the frame packer before the shape lookup, and `inject_motion` only concatenates.
- **Comment 4:** the block split index stays a Python int (`e[1]`, no `.item()`), taken from `original_seq_len`, which is an int at its source.

**Not in this PR:**
- Comment 4's per-token-timestep rework (dropping the split and the `*2Seg` layers); that is a larger change of its own.
- 6 graph breaks remain in the DiT, from `np.linspace(...).tolist()` inside the RoPE table build. A pure-Python replacement removes them bit-exactly, but it measured speed-neutral, so it is left out.

## Accuracy Tests

Wan2.2-S2V-14B, 704x1024x81, 4 steps, seed 42, image + `talk.wav`, SP=2 Ulysses. 2x Intel Arc Pro B60, torch 2.14.0+xpu. One request per process, interleaved runs.

- **Eager, #43279 head vs this PR (2 runs each):**
  - PSNR-Y between the two trees is 36.14–36.25 dB. Each tree against itself gives 36.20 / 36.08 dB; SP=2 eager is not bit-reproducible.
  - Lip-sync scores are equal on both trees. Both are low because the wav2vec2 `last_hidden_state` fix is not on #43279's base; with it, see the next point.
- **On the full S2V stack, base vs base + this change (compiled, 2 runs each):** PSNR-Y 32.14–32.71 dB across trees, against same-tree floors of 31.86 / 32.45, with normal lip sync.
- **Equivalence on CPU, old code vs new code, same inputs:** `torch.equal` on the tokens, RoPE rows, masks, `seq_lens` and the split index, across batch 1/2 × `add_last_motion` 0/1/2 × drop on/off (12 cases), with the real `FramePackMotioner`.
- **S2V unit tests** (`test_wan_s2v_audio_encoder*.py`, `test_multiple_task_types.py`, `test_cfg_parallel_warmup.py`, `test_cache_dit_integration.py`): the same pass counts as #43279's head.

## Speed Tests and Profiling

Same setup.

| | #43279 head | this PR |
|---|---|---|
| eager e2e (2 runs each) | 187.69 / 188.97 s | 183.10 / 188.44 s |
| compiled, 1 run each (cold) | **XPU OOM at step 3/4** (190–225 s/step) | 287.33 s, 34 s/step after step 1 |
| graph breaks in the DiT (compiled) | 14 | 6 |

On the full S2V stack (2 runs each, compiled), this change's effect:
- Steady-state steps are unchanged.
- Step 1 is +2.5 s, the cost of tracing larger graphs in each new process.

So the change is speed-neutral in steady state. Its gain is that the compiled path fits in memory and has far fewer graph breaks.
