# [Feat] kernels: Add out-of-tree dispatch for gated RMSNorm

[Upstream PR](https://github.com/sgl-project/sglang/pull/38749) · state: open · merged: False

## Original PR description

## Motivation

Out-of-tree platforms need a supported way to provide a gated RMSNorm implementation without monkeypatching SGLang internals.

## Modifications

- Convert the FLA gated `RMSNorm` to `BaseFusedOp`.
- Preserve the existing Triton and CPU paths.
- Add a portable Torch reference implementation for supported gate activations and layouts.
- Add unit coverage for gating, strided gates, and invalid layouts.

The optimized Qwen GDN prefill path supplies flattened `x` with shape `[tokens * heads, dim]` and a strided `z` view with shape `[tokens, heads, dim]`. Triton consumes the token and head strides directly without materializing `z`. To keep `forward_native` semantically equivalent, it reshapes `x` to the logical gate shape, computes the result, and restores the flattened output shape. This is normally a metadata-only view and avoids copying the strided gate. Other mismatched layouts are rejected consistently with Triton.

## Accuracy Tests

The CPU tests compare the native implementation against independently computed Torch results. The existing CUDA GDN layout test now also compares the native implementation with Triton for the strided prefill gate. Full upstream CI is pending.

## Speed Tests and Profiling

No optimized kernel changes. Existing in-tree platforms retain their current implementations, and the additional shape handling runs only when the native backend receives the strided prefill layout.
