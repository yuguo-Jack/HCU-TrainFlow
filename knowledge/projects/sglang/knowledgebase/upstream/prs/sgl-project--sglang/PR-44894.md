# [Perf] Frozen-KV: avoid host synchronization when sizing the verify mask

[Upstream PR](https://github.com/sgl-project/sglang/pull/44894) · state: closed · merged: False

## Original PR description

## Motivation

Frozen-KV draft graph replay reads `seq_lens.sum().item()` on the host to size the verify mask. That synchronization blocks the CPU from dispatching subsequent work.

## Modifications

Add an opt-in `SGLANG_FROZEN_KV_NO_HOST_SUM=1` path for top-k=1 Triton CUDA graphs. Reuse the target full-mask buffer with a CPU-known request-lifetime capacity, check actual storage capacity, and preserve `seq_lens_sum=None` through graph padding. Fall back for eager execution, unsupported backends/layouts, existing CPU lengths, multimodal/embedding requests, sessions, retraction history, and pending/finished requests. The default remains off. This PR contains only four files and is independent of adaptive decoding and the CUDA verify feature.

## Accuracy Tests

- Repository pre-commit passes. All 12 registered guard/boundary/CUDA mask-reuse tests pass on the pinned performance branch and independently on upstream-base commit 6a44376b912f449929b0a10d84937d97f17a6bfe (base a126e8d640c707f855e8da31f906035883f4ff70).
- Pinned-branch OFF/ON/ON/OFF fixed batches: 259,584 output tokens and all acceptance statistics match.
- Upstream-base short-prompt b1/3/7/8/32 OFF/ON live assertions match tokens and acceptance. Retained fixed-batch artifacts include long-prompt b3/b7 padding/SWA cases and contain 26,112 matching output tokens.
- Graph-disabled b3/b7, forced retraction (11 retractions per setting), regular/streaming sessions, image input, abort/recovery, and a b7->8 near-context-limit case pass OFF/ON token comparisons.
- Nondeterministic asynchronous stress is not an exact-output oracle: pinned OFF/ON differed on 84/192 requests, while OFF/OFF differed on 82/192. A separate deterministic-attention OFF/ON stress control matches 192/192. The upstream-base raw stress also completes, but has 47/192 output differences; no exact-match claim is made for that workload.
- Pre-existing integration limitation: input_embeds crashes in target prefill on both OFF and ON with Gemma4's input_ids/input_embeds exclusivity error, before this draft helper is reached. The direct guard test passes, but a successful HTTP embedding fallback has not been validated. This pre-existing prefill failure is outside this optimization; the opt-in helper rejects embedding requests and falls back to the original path. Tracked separately in #44895.
