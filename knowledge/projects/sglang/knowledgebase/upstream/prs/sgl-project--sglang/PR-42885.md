# [Feat] lora: FP8 MoE LoRA on the Triton vendor (18/21)

[Upstream PR](https://github.com/sgl-project/sglang/pull/42885) · state: closed · merged: False

## Original PR description

Part 18 of 21 of the LoRA runtime stack (branch `lora-stack-17-triton-fp8`, base `lora-stack-16-cutedsl-bf16`). The stack is cut from the development branch of #42284.

## What this part adds

Add the block-FP8 quant info and admission (128-block weights, resident
float8 bytes) and the Triton FP8 provider; the runner admits FP8 experts.

Tests: Triton FP8 provider numerics against an FP32 reference at hidden 512
and 7168, FP8 admission (weight family and geometry).

- GB300 run r45: the tree of upstream main `c1c287a429` plus parts 01–18 imports every module this part changes and passes this part's tests together with every earlier part's unit tests: **395 passed, 20 warnings, 154 subtests passed in 30.25s** (excluding the tests that fail identically on the untouched base tree in that environment).
- `pre-commit` passed on the changed files of every part; `pre-commit run --all-files` passed on the complete stack tree.

The complete 21-part tree equals the development branch of #42284 at `e7b7179a86` (the `6588053ef2` tree with four test-only follow-ups squashed into its dense commit: the admission/snapshot trim, the restored FP8 block-shape admission pin, a second trim that keeps only the tests guarding silent failures and adds pins for four coverage gaps, and restored numerical and packing coverage; production code is unchanged) minus the benchmark tools and the Triton MoE tuning tables, which follow in separate PRs.
