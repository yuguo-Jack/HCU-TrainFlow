# [Perf] openai: Skip unused prompt decoding

[Upstream PR](https://github.com/sgl-project/sglang/pull/44110) · state: open · merged: False

## Original PR description

## Motivation

Long text-only chats on multimodal models waste API-process CPU and memory: each new turn decodes a prompt that nothing reads when the engine gets IDs.

Agent clients with long histories hit this on GLM-5.3-Flash, Qwen3.6-35B, MiniMax-M3 and Qwen3-VL-2B. Behind sgl-router, GLM-5.3-Flash and MiniMax-M3 text chats already arrive as IDs and skip this path.

On one B200 with Qwen3-VL-2B at 96.9K tokens and concurrency 16, QPS goes from 23.5-23.7 to 51.3-51.6 with `max_tokens=1` and from 15.5-15.7 to 20.6-21.0 with `max_tokens=32`. RSS growth over 160 prompts of about 116K tokens drops from 586-609 MB to 186-191 MB.

This is a test setup, not a cookbook deployment. The 2x gain appears only when the API process is the limit. Otherwise, expect about 10-20 ms saved per new turn at this size.

The chat template cache misses on each new turn and stores that text plus IDs as Python ints, which take most of each entry.

Open overlap: #30876 skips the same decode but predates this cache and conflicts with main. #46796 covers only requests with media, #27298 sends text-only requests as text, and #47028 caches encoding only (no combined run).

## Modifications

Text-only requests now decode only when sent as text (Responses, Moss-VL, tokenizers that add special tokens). The cache keeps their IDs as a compact array without text, so a resend still hits it. Media requests and engine input do not change.

A resend sent as text still decodes, about 20 ms at 112K tokens on Qwen3-VL-2B.

## Accuracy Tests

`96eb1d47bc` is the last head before I squashed this branch onto main `7b88f09239`. The squash kept the same diff, and I did not repeat these runs on it. On the squashed commit, only pre-commit and `test_serving_chat.py` ran, on CPU. Its only failures also occur on main in that environment, which lacks optional packages.

On one B200 against main `4ffc9e1b7d`, prompt IDs and temperature-0 output matched on Qwen3-VL-2B (sent as IDs) and LFM2.5-VL with cookbook backends (sent as text), for text, tools, `continue_final_message`, images, streaming, `/v1/tokenize`, Responses and Anthropic.

sgl-eval 0.1.3 gsm8k on Qwen3-VL-2B scored 0.815 on both with the same predicted answers (200 examples, temperature 0, seed 0, top_p 0.95, max_tokens 512).

The new test fails on main. `TestLlavaServer` and entrypoint unit modules found no regression.

Not checked: Moss-VL, mistral-common tokenizers on a server, a GLM-5.3-Flash server, sgl-router, real resend rates, and runtime CI (no `run-ci` label).
