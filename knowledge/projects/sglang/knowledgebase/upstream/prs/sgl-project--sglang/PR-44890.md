# [Perf] [Intel] gemma4: Use exact softcap comparison ranks for greedy verification

[Upstream PR](https://github.com/sgl-project/sglang/pull/44890) · state: open · merged: False

## Original PR description

Stacked on #44884; this PR contains only the exact comparison-rank lookup follow-up.

## Motivation

The fused greedy-verification logits reduction still computes FP32 softcap for every vocabulary element. BF16 has only 65,536 bit patterns, so build exact comparison ranks through the existing native FP32 softcap once and reduce those ranks instead. This preserves transformed equality classes, including softcap saturation, signed zero, and NaNs. Weights, BF16 logits, and the head GEMM remain unchanged.

## Modifications

- Extend the XPU reduction with an optional immutable 256 KB comparison table and unsigned-rank/first-index reductions.
- Keep the table in a nonpersistent LogitsProcessor buffer, keyed by generation device and softcap. Construct it during eager warmup; unmatched first capture or compile keeps the existing tanh reduction.
- Carry the immutable table reference with deferred logits through graph replay. Slice token rows without slicing the table. Current-request eligibility and the ordinary-logits fallback remain unchanged.

The table records exact FP32 output ordering and equality for the actual native softcap operation; it does not approximate or change model precision. Scope remains no-gather Gemma4 BF16 FrozenKV target verification, validated at TP1.

## Accuracy Tests

- Exhaustive native FP32 softcap order/equality proof across all 65,536 BF16 bit patterns for softcap None, zero, and 30; device lookup checked for every pattern.
- Six XPU kernel tests passed, including signed zero, saturation ties, first NaN/global index, chunk boundaries, public lazy dispatch, Meta shapes, and graph replay with changed inputs.
- Two real LogitsProcessor lifetime/capture tests passed, covering separate owners, cap changes, nonpersistent state, immutable captured references, and no table construction inside first capture.
- 75 CPU namespace/policy tests and 15 subtests passed. Rank-aware Meta smoke and pre-commit passed.
- Fifteen controlled same-GPU serving cases matched the parent exactly, including returned token logprobs and repetition-penalty/bias/min-new-token fallbacks.
- Official GSM8K200, temperature 0, seed 42, eight threads: parent 159/200 (79.5%), candidate 164/200 (82.0%), zero errors and two truncations each. Earlier parent serving scored 165/200; these are compatibility results, with no quality-improvement claim.
- Candidate official GSM8K200 temperature 1: 165/200 (82.5%), zero errors, two truncations. This uses the ordinary-logits fallback, not the changed greedy reduction.

Exact operator and controlled-serving parity do not establish arbitrary batch-independent model bitwise equivalence.

Each server switch warmed 128 requests at c32 with 256 output tokens. Timing uses seed 42 and 256 outputs, 64 requests at c1 and 128 at c8/c32.
