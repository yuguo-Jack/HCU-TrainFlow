# [Fix] Keep flashinfer MXFP4 permute-index cache on host

[Upstream PR](https://github.com/sgl-project/sglang/pull/39468) · state: closed · merged: False

## Original PR description

## Motivation

`get_w2_permute_indices_with_cache` stores its shuffle-index cache on the device by default. When memory saver releases the weights region, those device tensors are zeroed while the cache dict still holds them, so the next forward after resume computes garbage permutations. Keeping the permute indices on the host avoids the corruption; the indices are small and reused every forward.

Standalone fix.

## Modifications

- `python/sglang/srt/layers/quantization/mxfp4.py`: build the permute-index cache with `get_shuffle_matrix_a_idx_with_cache` / `get_shuffle_matrix_sf_a_idx_with_cache` on host tensors instead of the device-cached helper.

## Accuracy Tests

MXFP4 MoE forward path unchanged; only the cache residency of the permute indices changes (host vs device).

## Speed Tests and Profiling

No perf impact: the indices are already uploaded per use; keeping them on host removes a device allocation.
