# fix: preserve Inkling empty-content round trips

[Upstream PR](https://github.com/sgl-project/sglang/pull/33028) · state: open · merged: False

## Original PR description

## Motivation

Inkling encodes assistant output as typed content blocks. A tool-call-only
response has no `<|content_text|>` block, while an explicitly generated empty
text block is a distinct wire representation.

The non-streaming chat response path converted both cases to `content=""`.
When that response was rendered into the next turn, the model's native template
inserted an empty text block that was absent from the generated tokens, breaking
TITO round trips. The custom Inkling renderer also differed from the native
template for empty, null, and omitted content.

## Modifications

- Track whether the Inkling reasoning state machine actually parsed a text
  block, without mistaking a literal `<|content_text|>` inside tool JSON for
  framing.
- Return `content=None` for Inkling responses with no text block while
  preserving `content=""` for an explicit empty text block.
- Match the model-provided Jinja in the Inkling renderer for empty, null, and
  omitted content, and terminate every historical assistant turn.
- Add response and renderer regression coverage. The model chat template is not
  modified.

## Accuracy Tests

- SGLang unit suites: `382 passed`, plus `38 subtests passed`.
- Official Hugging Face Jinja parity: 8/8 empty, null, omitted-content, and
  tool-call cases are token-exact.
- Miles native-template Stage 2: `74/74 passed`.
- Miles fast regression suite: `321 passed`, `39 deselected`.
- `thinkingmachines/Inkling-Small-NVFP4` revision
  `b6a99534467840620d411e4cd4ad5819b2610d9c` on a 4×H200 TP4 runner:
  16/16 multi-role rollout samples completed, with the aggregate TITO mismatch
  rate and every hard mismatch category at `0.0`.

Not applicable. This changes response parsing and prompt serialization only; no
model-forward or kernel path is changed.
