# [CI] scoring: Reuse HF reference models across setwise tests

[Upstream PR](https://github.com/sgl-project/sglang/pull/46942) · state: closed · merged: False

## Original PR description

## Motivation

The setwise parity tests load the same CPU reference checkpoint for each prompt: 7 loads in the sequence-classification class and 3 in the causal-LM class per file run. Each class needs one load. This saves about 2.3 s of reference work on a B200 and lowers the peak memory of the test process. File elapsed time shows no measurable saving.

## Modifications

Each parity class loads its `float32` reference model once at the end of `setUpClass` and releases it in `tearDownClass`. Prompts, forward passes, assertions, tolerances, and Engine configurations do not change.

Deliberate limits:

- A failed reference load fails the class in setup without the per-test CI retry. With the checkpoint cached, `from_pretrained` still loaded when the Hub endpoint returned 429, 500, or 503 or refused connections.
- The helpers keep their no-op `model.cpu()` and `empty_cache()` calls, because removing them reindents about 25 lines.

These limits are deliberate. Do not add code for them without a real input that reaches the case.

## Accuracy Tests

At this head (`224e77ca33`, on main `c757c4bb7c`), the complete file passed in its CI form on one NVIDIA B200 with the real Engine and default checkpoints. For each helper and prompt, the reference output hash matched main `c108a656f1`, which loads a fresh model per prompt. A forced load failure in each class reported that error from setup and shut down the Engine. CI test workflows have not run on this draft.

## Speed Tests and Profiling

One NVIDIA B200 with warm caches ran the two `c108a656f1` columns three times each, interleaved, under a timing wrapper.

| Per file run | main `c108a656f1` | This change on `c108a656f1` | This head, one run |
| --- | --- | --- | --- |
| Reference checkpoint loads | 10 | 2 | 2 |
| Time in reference loads | 2.0 to 2.2 s | 0.6 to 0.7 s | 0.6 s |
| Time in reference loads and forward passes | 3.5 to 3.9 s | 1.4 s | 1.3 s |
| Peak RSS of the test process, without Engine workers | 6.7 to 7.8 GiB | 5.8 GiB | 5.8 GiB |
| File elapsed time | 94.4 to 103.6 s | 93.8 to 96.2 s | 95.7 s |

The same code varied by 9 s on main, which exceeds the saving. Engine startup, shutdown, and GPU idle waits took about 78 s of an 83 s suite run. CI elapsed time was not measured.
