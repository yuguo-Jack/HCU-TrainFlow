# [Perf] [NPU] multimodal: Add bounded cross-request Qwen3-VL image batching

[Upstream PR](https://github.com/sgl-project/sglang/pull/44233) · state: open · merged: False

## Original PR description

## Motivation

The NPU chunked multimodal path encodes image-cache misses per request even
when the scheduler has already selected multiple compatible image requests.
This PR adds an opt-in, bounded path for Qwen3-VL image encoding, with real
Ascend A2 correctness and performance validation.

Related to the cross-request ViT batching item in #43519, not intended to
close the whole roadmap issue.

Related work: #38368 proposes a generic encoder input-token budget. The small
partitioning helper here overlaps that infrastructure concern; the distinct
scope here is NPU enablement, conservative model/mode gating and A2 validation.
The NPU opt-in should reuse the generic budget mechanism when that lands rather
than maintaining two independent batching-budget implementations long term.

## Modifications

- Add `SGLANG_NPU_VIT_MAX_BATCH_PATCHES`, default `0` (disabled).
- Enable the existing cross-request per-image cache/deduplication/scatter path
  for a single-NPU, unquantized `Qwen3VLForConditionalGeneration` image encoder.
- Partition unique cache misses by input patches **before** spatial merging.
  Never split an image: an individually oversized image runs alone.
- Do not wait for new requests or change the scheduler's request selection.
- Keep the per-request path for video, other model classes, TP > 1, DP
  encoders, quantized models, ViT graph execution and unsupported input forms.
- Add CPU regression coverage, a self-contained NPU image/cache smoke test,
  and Ascend environment-variable documentation.

There are no shipped vision-model forward changes and no new CANN operators.
Decode graphs can still be enabled; the visual encoder remains eager.
The patch budget is not a strict total-memory limit.

## Accuracy Tests

Environment: one **Ascend A2 910B3 64GB**, Qwen3-VL-8B-Instruct BF16, TP1,
CANN 9.0.0, torch/torch-npu 2.10.0, Transformers 5.19.0, tokenizers 0.23.1.
Used `main-cann9.0.0-910b` with the checkout-required Transformers version in
an isolated dependency directory. A3/A5 have **not** been tested.

- `test_mm_chunked_embedding_unit.py`: **35 passed**. Includes budget bounds,
  oversized/empty input, cache on/off, duplicate misses, cache hits, mode
  gates and partial chunk slices in original request order.
- New NPU test: mixed sizes, multi-image order, >512-token image chunks and
  changed text prefixes with image-cache reuse. Passed standalone server
  launch/teardown, eager execution and decode-graph execution on A2.
- Decode graph logs confirm real replay, not just capture. A separate
  128-request concurrency-8 smoke run passed 128/128.
- Temporary probes confirmed actual cross-request visual calls. Batched
  versus individual BF16 features are **not bitwise identical** (cosine about
  0.99945–0.99955); no probes are included in the patch.

Real-image paired comparison: **192/192 answer strings agree exactly**, with no
newly incorrect answers and no truncated completions in either arm.

| Fixed subset | Metric | Disabled | Enabled |
|---|---|---|---|
| ChartQA test, 64 distinct images | relaxed numeric accuracy (5%) / text match | 85.94% | 85.94% |
| DocVQA validation shard 0/6, 64 distinct images | ANLS | 92.10% | 92.10% |
| VQAv2 validation shard 0/68, 64 distinct images | normalized majority-answer exact match | 67.19% | 67.19% |

Protocol: fixed seed 42 per source file, deduplicate images before selecting
64 samples, combined shuffle seed 17; longest image edge limited to 1024
without upscaling. Both arms use identical PNGs/prompts, `temperature=0`,
`seed=42`, `max_tokens=64`, concurrency 8, chunked prefill 4096, eager mode,
and separately restarted servers. Enabled budget: 8192 input patches.
This is a small paired regression check, **not** an official full-dataset
benchmark or proof of universal equivalence. VQAv2 uses majority-answer
exact match, not the official consensus score.

Temporary shape-only logs confirm 55 visual calls with 2–5 distinct images;
the maximum observed call had 7936 input patches. Excluding server warmup,
192 images required 192 encoder calls when disabled and 119 when enabled.
The logs did not copy tensors to CPU or force synchronization and are removed.

## Speed Tests and Profiling

Initial A2 measurements on main `68c18a5701` plus this patch, before rebasing
onto `6daae9c98e` for the real-image accuracy checks:

TP1 BF16, eager, patch budget 2048 vs disabled, chunk 2048, context 8192,
max-running-requests 8, mem-fraction-static 0.7. A local HTTP streaming client
sent unique mixed-height 448-wide synthetic images at concurrency 4:
8 excluded warmup requests, then 3 × 24 measured requests per arm.
No numerical probes or NPU synchronizations were injected in measured runs.

| Metric | Disabled | Enabled |
|---|---:|---:|
| TTFT p50 | 470.09 ms | 384.36 ms |
| TTFT p95 | 494.79 ms | 404.80 ms |
| Aggregate requests/s | 7.226 | 8.572 |

All 72 answers per arm matched expectations. A reverse-order fresh-server
repeat produced 384.10 ms p50. The observed ~18% TTFT reduction is specific
to this workload, not a general VLM speedup guarantee. Performance on the
real-image accuracy subset is not used as a benchmark here.
