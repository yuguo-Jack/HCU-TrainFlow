# [ROCm] Use the fused MLA absorb + RoPE + KV-write kernel for decode-sized forward modes only

[Upstream PR](https://github.com/sgl-project/sglang/pull/41533) · state: closed · merged: True

## Original PR description

## Motivation

On gfx950, `fused_fp8_bmm_rope_cat_and_cache_mla` (#38340) replaces the absorbed q BMM and the
RoPE / cat / KV-write kernel with one launch. At decode and verify sizes this is a clear win, because
neither separate kernel fills the CUs. At prefill shapes (8k tokens x 4) the two separately tuned
kernels are faster. This PR keeps the fused kernel for decode-sized forward modes and uses the
two-kernel path that main already has for EXTEND, MIXED and SPLIT_PREFILL.

## Modifications

- In `forward_absorb_rocm_prepare()` (`forward_mla_rocm.py`), the fused kernel is now also gated on
  `not forward_mode.is_extend_or_draft_extend_or_mixed()`. That is false for EXTEND, MIXED and
  SPLIT_PREFILL, so DECODE, TARGET_VERIFY and DRAFT_EXTEND_V2 keep the fused kernel. `is_extend()` is
  not used because it includes TARGET_VERIFY, which is extend-shaped but decode-sized.

No new numerical path: the prefill modes take the same two-kernel path main uses whenever the fused
kernel is not selected. CUDA graphs are captured for DECODE and TARGET_VERIFY only, so the captured
graphs still contain the fused kernel.

## Speed Tests and Profiling

MI355X TP4. Server, the same for main and +PR:

```bash
python3 -m sglang.launch_server --model amd/GLM-5.2-MXFP4 --tp 4 --trust-remote-code \
  --tool-call-parser glm47 --reasoning-parser glm45 --mem-fraction-static 0.85 \
  --kv-cache-dtype fp8_e4m3 --disable-radix-cache --chunked-prefill-size 16384 \
  --dsa-prefill-backend triton --dsa-decode-backend triton \
  --enable-aiter-allreduce-fusion --tokenizer-worker-num 8
# MTP adds:        --speculative-algorithm EAGLE --speculative-num-draft-tokens 4 \
#                  --speculative-num-steps 3 --speculative-eagle-topk 1
```

Client (greedy, the `bench_serving` default):

```bash
python3 -m sglang.bench_serving --backend sglang --dataset-name random \
  --random-input <ISL> --random-output <OSL> --random-range-ratio 0.8 \
  --max-concurrency <conc> --num-prompts <conc * 5>
```

Total tok/s/GPU is (input + output) token throughput divided by 4. The
ratio columns are oriented so that above 100% means this PR is better: throughput is +PR / main,
TTFT and TPOT are main / +PR. The numbers were measured with an earlier revision of this PR that
wrapped the same condition in a helper; the logic is identical.
