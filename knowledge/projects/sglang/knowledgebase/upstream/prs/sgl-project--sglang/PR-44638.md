# [NPU] linear ReplaySSM: ring decode via triton-ascend

[Upstream PR](https://github.com/sgl-project/sglang/pull/44638) · state: open · merged: False

## Original PR description

# [Feat] [NPU] linear-attention: Enable ReplaySSM ring decode via triton-ascend

## Motivation

`--enable-linear-replayssm` (ReplaySSM ring decode) previously worked on CUDA only: at decode time, a shared Triton ring kernel (`fused_recurrent_linear_replayssm`) replays the last `--linear-replayssm-cache-len` steps of per-token inputs to reconstruct / roll back SSM states, supporting state restore and radix-track-boundary force flush. The NPU (Ascend) GDN/KDA hybrid linear-attention backends were not wired up, so hybrid linear-attention models (Qwen3.5, Kimi-Linear, ...) could not use the feature on NPU. This PR routes the NPU decode path through the same ring kernel (compiled via triton-ascend) and fixes a pad-row state-corruption bug exposed while bringing it up.

## Modifications

**Feature enablement**
- `ascend_hybrid_linear_attn_backend.py`: add `ReplaySSMDecodeMixin` — detects when the ring is live (pool flag, cursor presence, KDA bounded-gate fallback) and hands the post-conv packed qkv straight to the ring kernel; `AscendMambaAttnBackendBase` allocates static per-bs `replayssm_write_pos_list` / `replayssm_force_flush_list`, captured by pointer and refreshed in place before each graph replay.
- `ascend_gdn_backend.py` / `ascend_kda_backend.py`: wire the decode paths through the mixin (falls back byte-identically to the legacy per-step decode whenever the ring is not usable).
- `hybrid_linear_attn_backend.py`: extract the ring-cursor snapshot+advance logic from the CUDA `_replay_metadata` inline block into `_replayssm_graph_buffers`, so CUDA and Ascend share one implementation (radix-track flush, L-1 wrap, slot dedup).

**Correctness fixes**
- Pad-row sentinel: under graph replay, padding rows' `mamba_cache_indices` changed from `0` to `pad_slot_id` (-1) — previously they read/wrote physical slot 0's conv/ring state (root cause of repetition/garbled text and the GSM8K baseline collapse).
- NPU conv decode: `cache_indices.clamp_min(0)`, since the CANN conv op has no verified skip semantics for -1.
- Kernel workarounds for triton-ascend 3.2's rejection of 3-operand boolean chains (`fused_recurrent_linear_replayssm.py`, `fused_sigmoid_gating_recurrent.py`).

**Argument validation**
- `attention_hook.py`: with the flag on for NPU, require `--linear-attn-decode-backend triton` (the ring kernel runs through triton-ascend); error out when `mamba-radix-cache-strategy` is not `no_buffer`, with a page-size hint.

Debug-only instrumentation (KDA prefill in-situ probe, shadow-cursor validator) is intentionally not included; equivalent debugging capability lives in the kernel-level UT `debug/test_npu_linear_replayssm_decode.py`.

## Accuracy Tests

| Test | Model (path) | Result |
|---|---|---|
| GSM8K | Qwen3.5-9B (GDN, L=16, TP2, concurrent bs>1) | ring 0.885 vs baseline 0.905 (std≈0.3, within noise); ring confirmed engaged |
| E2E greedy parity | Kimi-Linear-48B-A3B-Instruct (KDA, L=4, TP2, CUDA graph on) | identical trajectory prefix ≥ 2L; per-token logprob dev mean≤0.05 / max≤0.25 (bf16-drift bound); repeated request deterministic |

## Speed Tests and Profiling

GSM8K A/B (Qwen3.5-9B, TP2, identical config except the flag):

| | Baseline | Ring (L=16) |
|---|---|---|
| Output throughput | 434.6 tok/s | 360.3 tok/s (-17%) |
| Eval latency | 51.3 s | 61.1 s |

The overhead is by design: each decode step replays the last L ring records per layer (memory-read amplification and compute scale linearly with L), plus ~3.4 GB of ring buffers per rank. The cost shrinks with a smaller `--linear-replayssm-cache-len`.
