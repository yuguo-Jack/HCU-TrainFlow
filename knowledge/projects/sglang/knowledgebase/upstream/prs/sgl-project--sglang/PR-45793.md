# [Perf] dsv4: Dequantize eight V4.1 KV tokens per program in the sparse prefill gather

[Upstream PR](https://github.com/sgl-project/sglang/pull/45793) · state: open · merged: False

## Original PR description

## Motivation

The DeepSeek-V4.1 sparse prefill path gathers its paged FP8 (SWA) and FP4 (compressed) KV into a BF16 workspace with `dequantize_k_cache_paged_v41`. Both kernels launch one program per token, which leaves the gather well below memory bandwidth.

## Modifications

- The V4.1 FP8 and FP4 dequant kernels process 8 tokens per program, with a masked tail. The FP4 kernel interleaves the low and high nibbles in registers and stores each row contiguously.
- `TestV41KVDequant`'s workspace-slice case now checks that rows on both sides of `out` stay untouched.

## Accuracy Tests

Output is bit-identical to the previous kernels on all four V4.1 layouts (split and token-interleaved, fp8 and fp4), including random bytes with NaN and -0.0 payloads. `test_v41_kv_store.py` passes on GB300.
