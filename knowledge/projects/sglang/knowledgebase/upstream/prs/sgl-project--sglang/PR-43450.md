# [Feat] scheduler: Add forward observer and deferred responses for plugins

[Upstream PR](https://github.com/sgl-project/sglang/pull/43450) · state: closed · merged: True

## Original PR description

## Motivation

Out-of-tree consumers need to publish forward outputs asynchronously before returning references to clients. SpecForge uses this to write target prefill hidden states into Mooncake for draft-model training. A sampling observer cannot see all forward outputs, and synchronous auxiliary-output consumption cannot hold a response until publication finishes.

## Modifications

- `ModelRunner.forward_observer` receives the batch, forward batch and logits output immediately after target forward, before sampling can clear tensors. Its optional device output joins the existing auxiliary copy/consume path. Unsupported execution modes fail at observer installation.
- `Scheduler.defer_response(req, completion)` registers one completion for a finished, unstreamed request. A completion exposes `done()`, `result()` and `cancel()`; a `Future[None]` works directly. The scheduler owns the request, polls completion during busy/idle/paused execution, finalizes metadata on its own thread and streams once.
- Aborting a held request retires scheduler ownership and cancels its completion; unexpected completion failures return an abort response. Pending requests participate in weight-version bookkeeping. Shared publication futures must not be canceled by one sibling request.
- Held requests do not affect TP-wide idle/cache/memory decisions because only the output rank owns publication. The plugin retains captured data independently of released KV cache.
- Cover lifecycle, failure, cancellation, version tracking and unsupported paths with real Futures, including error delivery through both ZMQ and the embedded Rust frontend.

## Relationship to #43449

Rebased onto main `e732f5d41e`, which includes merged #43449's target-only auxiliary hidden-state capture. This PR adds the forward observer and scheduler-owned asynchronous response completion on top.

The compatible consumer and separate server/trainer environment support are on [SpecForge's companion branch](https://github.com/maocheng23/SpecForge/tree/codex/pr43450-completion-plugin). Its live H200 integration was validated against the earlier combined SGLang tree as described below.
