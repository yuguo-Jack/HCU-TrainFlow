# [Fix] rust-server: Honour cache_salt and require_reasoning on /generate

[Upstream PR](https://github.com/sgl-project/sglang/pull/44533) · state: closed · merged: True

## Original PR description

Stacked on #44312 (`priority` and the `x-override-*` headers on the Rust frontend): this branch is based on `oss-sync-fc133deaf0`, and the diff against it is this change alone. Once #44312 merges, this will be rebased onto `main`.

## Motivation

The Rust frontend's `/generate` schema ignores unknown top-level keys, so request fields the Python server honours are dropped silently in Rust mode. Four of them change the result:

- `cache_salt`: the prefix cache's second namespace key, beside `extra_key`. Dropping it lets requests sent under different salts share cached prefixes.
- `require_reasoning`: the scheduler applies grammar constraints only after the reasoning section. Dropping it constrains the reasoning output from the first token.
- `lora_path` and `session_params`: dropping them returns base-model or stateless output with a 200. Python returns a 400 for both on a server without LoRA or without that session.

## Modifications

- `cache_salt` and `require_reasoning` become `GenerateRequest` schema fields (proto tags 25 and 26; `api_types.py`, `sglang.api.v1.rs` and `sglang.api.v1.serde.rs` regenerated with `cargo gen-api`). `cache_salt` follows Python's `_normalize_cache_salt`, the same rules as `extra_key`: one value broadcasts, a list is per item and needs a batch of the same length, and an empty value means none (`message/request.rs`). Both reach the scheduler header, whose default slots are now filled through `cache_salt`, slot 45, so the header is 46 entries long (`message/io_struct.rs`).
- `lora_path` and `session_params` are declared as raw JSON fields (tags 27 and 28) so that a non-null value is a 400 ("… is not supported by the Rust server"). `null` still passes, so the `bench_serving` payload parses as before.
- The four fields leave the pinned list of Python-only request fields in `test_parity.py`. The rest of that list (`custom_labels`, `log_metrics`, `no_logs`, …) stays ignored; dropping those changes only logging.
