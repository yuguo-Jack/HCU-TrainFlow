# [NPU] add e2e test for some parameters on NPU

[Upstream PR](https://github.com/sgl-project/sglang/pull/41685) · state: open · merged: False

## Original PR description

## Motivation

The four multimodal serving parameters below have no end-to-end coverage in the NPU
registered parameter suite:

- `--allowed-media-domains`
- `--media-url-max-file-size-mb`
- `--mm-preprocess-cache-size-mb`
- `--trust-mm-content-hashes`

Each guards a distinct serving behavior — media URL policy enforcement at download
time, the budget and lifecycle of the content-addressed multimodal preprocess cache,
and caller-supplied content-hash verification/trust. This PR adds registered e2e
parameter tests that launch a real server per flag and assert the observable
behavior (HTTP status, error messages, startup logs, `/server_info` echo), following
the existing style of `test/registered/npu/basic_function/parameter/`.

## Modifications

Two new test files. **Test-only PR: zero production code changes.**

### `test/registered/npu/basic_function/parameter/test_npu_url_security.py`

`register_npu_ci(est_time=3600, suite="nightly-1-npu-a3", nightly=True)`

- `TestNpuAllowedMediaDomains` (`--allowed-media-domains 127.0.0.1`):
  - A URL on the whitelisted domain completes a full generate round.
  - A URL on a non-whitelisted domain (`localhost` vs `127.0.0.1`) is rejected with
    400 `Media URL domain is not allowed`.
  - `file://` media is still accepted (community behavior: local files are allowed).
- `TestNpuMediaUrlMaxFileSizeMb` (`--media-url-max-file-size-mb 1`):
  - A valid PNG under the limit is served.
  - A ~2 MiB download is rejected with 400 `... exceeds the ... byte download limit`.

### `test/registered/npu/basic_function/parameter/test_npu_mm_preprocess_cache.py`

`register_npu_ci(est_time=4500, suite="nightly-1-npu-a3", nightly=True)`

- `TestNpuMmPreprocessCacheSizeMb` (`--mm-preprocess-cache-size-mb 256`):
  - The startup log reports the cache enabled with the configured budget and caller
    content hashes *verified*.
  - `/server_info` echoes `mm_preprocess_cache_size_mb=256`; repeated identical
    requests succeed.
  - While hashes are not trusted, a correct caller hash does not bypass media
    loading: an unreadable URL still fails.
- `TestNpuMmPreprocessCacheDisabled` (`--mm-preprocess-cache-size-mb 0`):
  - No cache-enabled startup log; `/server_info` echoes `0`; inference still works.
- `TestNpuTrustMmContentHashes` (`--trust-mm-content-hashes` + cache 256):
  - The startup log reports caller content hashes *trusted*; `/server_info` echoes
    the flag.
  - Correct caller hash + live URL → 200; wrong caller hash → 400
    `content hash mismatch`.
  - A trusted hash resolves the cached artifact without downloading: the same hash
    against an unreadable URL still returns 200 (without the flag this fails, as
    covered by `TestNpuMmPreprocessCacheSizeMb` above).

### Shared test infrastructure

- A local threaded HTTP origin serves deterministic PNG bodies (seeded /
  SHA-256-pinned) so download-policy and hash checks are stable.
- Requests use Qwen2.5-VL's chat prompt format with `min_new_tokens`, and the
  success contract is `meta_info.completion_tokens >= 1` with non-empty text — i.e.
  "the request fully traversed download → decode → prefill → decode", independent
  of generation quality.
- All classes inherit `CustomTestCase` with defensive `tearDownClass`
  (`terminate_and_kill_process_tree`), dedicated ports (31410–31450), and the
  `QWEN2_5_VL_3B_INSTRUCT_WEIGHTS_PATH` constant from `test_ascend_utils`
  (env-overridable for local weight layouts; CI uses the community default).
