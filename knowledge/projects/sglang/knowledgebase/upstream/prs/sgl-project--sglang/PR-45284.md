# [Perf] [AMD] dsv4: HIP flat RoPE kernel with one cos/sin load and int64 offsets, bitwise unchanged

[Upstream PR](https://github.com/sgl-project/sglang/pull/45284) · state: open · merged: False

## Original PR description

## Motivation

On ROCm, DeepSeek-V4 / V4.1 run RoPE (forward on q, inverse on the attention output) through `apply_rotary_emb_flat_kernel`, the batched 3D path that DeepseekV4 enables on HIP. The kernel has two problems:
- For every (token, head) row it gathers cos and sin with two strided 64-element loads and builds the rotated term with `tl.where` + `tl.flip`. This costs 7-31% of its time at prefill sizes.
- Its token offsets are int32, so it writes out of bounds once n·H·512 reaches 2³¹ (e.g. 65536 tokens at 128 heads per rank).

## Modifications

All changes are inside `apply_rotary_emb_flat_kernel` (+11/−18):
- Load each row's 64 interleaved cos/sin values once and split the real and imaginary parts in registers.
- Compute with explicit `tl.fma`: round the sine product, then one fma. The compiler already produced this rounding for `x * cos + x_rot`, and `fused_q_norm_rope` uses it on HIP, so the output is bitwise equal.
- Make the token index int64.

The launch (16 rows and 1 warp per program) is unchanged.

An earlier revision of this PR replaced the kernel with a 3D tile kernel and a launch-config function (+47/−55). That revision is not faster overall (mixed at 32 and 64 heads, slower at 128 heads; table below), so this revision keeps the existing kernel.

## Speed Tests and Profiling

Setup: MI355X x1, `lmsysorg/sglang-rocm:v0.5.22-rocm10-mi35x-20261025` (ROCm 10, Triton 3.8.0) with the AgentX recipe's `TRITON_HIP_USE_ASYNC_COPY=0`, layout `[n, H, 512][..., -64:]`, inverse (forward within 4%), positions random over a 1M-row table, CUDA graph replay median, mean of two GPUs, µs. Decode sizes (1-384 tokens, H 1-128, hot): 1.98-4.26 → 1.76-3.08 µs, faster at every size. At the 45-192-row verify/draft sizes it is 2.28-2.71 → 1.96-2.07 µs.

End to end the effect is small, so there is no end-to-end A/B.
- **Prefill.** At TP2 the inverse RoPE after OPUS prefill runs on layers 0-19 of each 16K-row chunk, 20 × 27-35 µs ≈ 0.54-0.69 ms of a ~359 ms 16K-token TTFT. This PR saves about 86-103 µs per chunk (~0.03%). It saves about 58-79 µs per chunk at TP4, and 113-182 µs per rank at DP2 attention.
- **Decode.** At verify/draft sizes it saves 0.3-0.7 µs per call, so a DSpark step (about 84 calls) saves about 25 µs at TP4, 30-50 µs at TP2 and 50-55 µs at DP2 attention.

Only measured on MI355X (gfx950). The launch config is unchanged, so MI300X (gfx942) keeps the configuration it was tuned with, but it has not been re-measured.
