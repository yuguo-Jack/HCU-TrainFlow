# [Perf] dp-attention: Exchange the scheduler's MLP sync rows with gather + broadcast on gloo

[Upstream PR](https://github.com/sgl-project/sglang/pull/44622) · state: closed · merged: True

## Original PR description

## Motivation

With DP attention every scheduler step exchanges one small `MLPSyncBatchInfo` row per attention rank on the CPU gloo group (token counts, attention pairs, the CUDA-graph votes, the forward mode). gloo implements `all_gather` as a ring of `world_size - 1` serial hops, so the latency of that exchange grows linearly with the attention world. A gather onto group rank 0 followed by a broadcast is one hop plus a log-depth tree and fills the same buffer.

## Modifications

- `exchange_sync_rows` in `python/sglang/srt/managers/scheduler_components/dp_attn.py` fills the flat buffer in group-rank order exactly like `all_gather_single`. On a CPU group with more than two ranks it gathers every rank's row onto group rank 0 (directly into the row views of the output) and broadcasts the filled buffer; device tensors and two-rank groups keep `all_gather_single`, since at two ranks the ring is already the single hop.
- `MLPSyncBatchInfo.all_gather` calls it on its all-gather path; the existing `use_all_reduce` branch is unchanged.
- Tests (`test/registered/unit/managers/scheduler_components/test_dp_attn.py`): the two existing mocks of `all_gather_single` move to the new seam. `TestSyncRowExchangeGloo` spawns an 8-rank gloo world and, for sub-groups of 2, 3, 4, 5, 6 and 8 ranks over four rounds with a random per-rank sleep and busy-wait before each exchange, asserts that the exchange matches the ring all-gather bitwise on every rank and that the real `MLPSyncBatchInfo.all_gather` still produces the right `global_num_tokens`, `global_attention_pairs` and decode CUDA-graph vote. The world is capped at 8 because every rank is a spawned interpreter and the hosted CPU runner's memory bounds it; the file's `est_time` is raised accordingly.

## Accuracy Tests

Not applicable: the exchanged rows are bitwise identical to the all-gather result, which the new test checks on every rank.

## Speed Tests and Profiling

No benchmark is included. The change swaps a ring all-gather for gather + broadcast on CPU groups larger than two ranks, and the new test checks the exchanged rows are identical; two-rank groups and device tensors keep the previous path.

Local validation on this head: `python3 test/registered/unit/managers/scheduler_components/test_dp_attn.py` passes all 18 tests. `isort`, `ruff`, `ruff format`, `codespell`, `check_registered_tests.py` and `check_no_bare_pytest_main.py` at the pinned pre-commit versions report nothing.
