# [Perf] scheduler: Track num_held_rows incrementally in prefill batch admission

[Upstream PR](https://github.com/sgl-project/sglang/pull/46337) · state: open · merged: False

## Original PR description

## Motivation

In `Scheduler._get_new_batch_prefill_raw` (`python/sglang/srt/managers/scheduler.py`) and `SchedulerDllmMixin.process_dllm_incoming_reqs` (`python/sglang/srt/dllm/mixin/scheduler.py`), each iteration of the `for req in self.waiting_queue:` admission loop recomputes:

```python
num_held_rows = sum(r.kv.holds_kv for r in adder.can_run_list)
```

Because `adder.can_run_list` is strictly append-only across the prefill admission pass and `r.kv.holds_kv` does not change for already-admitted requests until `ScheduleBatch.init_new` allocates pool rows after the loop completes, rescanning `adder.can_run_list` from index `0` on every candidate request causes $\mathcal{O}(N^2)$ `r.kv.holds_kv` evaluations as `can_run_list` grows (e.g., under large `max_running_requests` / chunked-prefill / batched prompt workloads).

## Modifications

- Track `num_held_rows` and `num_held_rows_scanned` incrementally in `Scheduler._get_new_batch_prefill_raw` and `SchedulerDllmMixin.process_dllm_incoming_reqs`, scanning only newly appended entries `adder.can_run_list[num_held_rows_scanned:]` on each iteration (`O(1)` amortized per candidate, `O(N)` total across the pass).
- Add `TestHeldRowAdmission.test_incremental_held_rows_avoids_quadratic_rescan` in `test/registered/unit/managers/test_scheduler_held_row_admission.py` verifying that `r.kv.holds_kv` is read at most once per admitted request while preserving exact admission semantics.

## Benchmark

Microbenchmarking the admission loop (`100` prefill scheduling passes):
- `N = 1,024` admitted requests: `42.0 ms` $\rightarrow$ `0.26 ms` (**161.5x** speedup, `524,800` property evaluations reduced to `1,024`)
- `N = 4,096` admitted requests: `674.0 ms` $\rightarrow$ `1.00 ms` (**674.0x** speedup)
- `N = 8,192` admitted requests: `2,826.0 ms` $\rightarrow$ `2.10 ms` (**1,345.7x** speedup)
