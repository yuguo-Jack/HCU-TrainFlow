# [Fix] diffusion: Drop stale mismatch_msg from FLUX 3 video VAE gate call

[Upstream PR](https://github.com/sgl-project/sglang/pull/45778) · state: closed · merged: True

## Original PR description

## Motivation

#41894 calls `BitExactFusionGate.accept_or_fallback(..., mismatch_msg=...)`, but #44690 removed that keyword from the gate and every other caller. The first fused QKV norm+RoPE call in the FLUX 3 video VAE raises `TypeError: unexpected keyword argument 'mismatch_msg'`. This is the remaining break after #45775.

## Modifications

Drop the keyword.

## Tests

`test/registered/kernels/ops/diffusion/test_flux3_video_qknorm_rope.py` on H200: `test_natten_prepare_qkv_matches_eager_and_reuses_rope_cache` fails with the `TypeError` with #45775 alone; all 4 pass with this change.
