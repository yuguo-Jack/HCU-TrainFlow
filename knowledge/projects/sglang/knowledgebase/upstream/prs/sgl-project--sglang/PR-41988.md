# [AMD][Diffusion] Route unquantized linears through aiter tgemm on gfx1250

[Upstream PR](https://github.com/sgl-project/sglang/pull/41988) · state: closed · merged: True

## Original PR description

## Motivation
On ROCm, diffusion DiT linears call `F.linear`, which goes to hipBLASLt. On gfx1250 that is about 3x slower than aiter's tuned Triton GEMM for the large Wan2.2 projections.
## Modifications
- Add `SGLANG_USE_ROCM_AITER_TGEMM` (default off).
- When it is enabled on ROCm, `apply_unquantized_linear` sends bf16/fp16 linears to `aiter.tuned_gemm.tgemm.mm`, which picks the backend for each (M, N, K) from aiter's tuned CSVs. Calls with mixed dtypes still use `F.linear`.
Tuned configs for Wan2.2 on gfx1250 are in the companion aiter [PR#6032](https://github.com/ROCm/aiter/pull/6032).
## Accuracy Tests
The output video is bit-identical (same mp4 md5) with the flag on and off. `tgemm` matches `F.linear` exactly on all Wan2.2 GEMM shapes.
## Speed Tests and Profiling
Wan2.2-T2V-A14B, 720x1280, 33 frames, 8 steps, 1x gfx1250, median of 3 interleaved runs:
| Stage | hipBLASLt | aiter tgemm | Speedup |
| --- | --- | --- | --- |
| Text encoding | 1.01 s | 0.96 s | 1.05x |
| Denoising | 228.74 s | 64.41 s | **3.55x** |
| Decoding | 7.37 s | 7.00 s | 1.05x |
| Total | 237.39 s | 72.64 s | **3.27x** |

Scaling with `--num-frames` (single run each; 193-frame tuned run is estimated):
| Frames | Denoising (hipBLASLt → tgemm) | Decoding | Total (hipBLASLt → tgemm) | Total speedup | GEMM share of a tuned step |
| --- | --- | --- | --- | --- | --- |
| 33 | 228.7 → 64.4 s | 7.4 s | 237.4 → 72.6 s | 3.27x | 31% |
| 81 | 644.5 → 260.9 s | 16 s | 661.8 → 278.7 s | 2.37x | 15% |
| 129 | 1191.7 → 602.4 s | 24 s | 1217.4 → 629.3 s | 1.93x | 11% |
| 193 | 2094.0 → 1680.5 s | 36 s | 2131.8 → 1719.3 s | 1.24x* | 8% |

\* At 193 frames, the two FFN GEMMs exceed 2^31 elements and stay on `F.linear`. Only the 5120x5120 projections use tgemm.
Time saved per step grows with frame count (20.6 s at 33 frames to 75.3 s at 129 frames). The overall speedup still drops, because attention grows quadratically with token count and becomes the main bottleneck. Text encoding (~1 s) and decoding are unaffected. No new GEMM shapes appear between 33 and 193 frames (only M changes), so the aiter configs need no retuning.
To reproduce, add `SGLANG_USE_ROCM_AITER_TGEMM=1` to the `sglang generate` command.
These numbers were measured on the original local branch, which has the same diff as this PR. The rebased branch has only passed `py_compile`.
