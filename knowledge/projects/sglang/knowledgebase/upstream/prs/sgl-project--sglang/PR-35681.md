# [Perf] Avoid RadixKey suffix copies in cache walks

[Upstream PR](https://github.com/sgl-project/sglang/pull/35681) · state: closed · merged: False

## Original PR description

## Motivation

Deep radix-cache walks repeatedly sliced `RadixKey`, copying progressively smaller token arrays along the matched path.

## Modifications

- Reuse `RadixKey.match_at` and `child_key_at` introduced on main by #37324.
- Keep one request key and advance caller-local cursors in the remaining Radix, HiRadix, Mamba, and SWA walks.
- Leave the main-branch RadixKey API and already-optimized Unified tree unchanged.
- Add suffix-equivalence tests and a deep-tree serving benchmark.

## September 14 CPU-only update

Rebased onto `7465e42b7a`, including the current CI baseline. Removed the duplicate RadixKey API and Unified-tree changes already covered by #37324. The remaining production change touches four cache implementations.

- Four offset/sliced-suffix tests passed against the unchanged main RadixKey definition.
- 144 comparisons of the actual main/updated match-helper definitions passed across all four caches, normal/bigram keys, page sizes 1/4/16, and partial/full/missing-tail matches.
- These were dependency-isolated CPU checks with lightweight node/split fixtures, not the full cache integration suites. Ruff/isort and whitespace checks passed.
- Full cache suites, insertion/eviction integration, and serving benchmarks still need revalidation. Results below are historical and must not be attributed to the reduced September 14 diff.
