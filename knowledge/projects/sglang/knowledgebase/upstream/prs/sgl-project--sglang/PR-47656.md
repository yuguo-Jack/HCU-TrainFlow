# [Fix] [NPU] moe: Honor SwiGLU clamp for BF16 and INT8 experts

[Upstream PR](https://github.com/sgl-project/sglang/pull/47656) · state: open · merged: False

## Original PR description

## Summary

DeepSeek-V4 passes `swiglu_limit=10` to its routed experts, but the Ascend runner only applies that limit for MX and block-FP8 kernels. BF16 and W8A8 INT8 fall through to plain SwiGLU, including the DeepEP/Ascend Ops branches. With gate=20 and up=20, the BF16 result is 400 instead of 100.

Use the existing `NPUSwigluWithLimit` for the remaining weight formats when a limit is set. INT8 GMM2 already dynamically quantizes floating input when no per-token scale is supplied. Preserve the TP activation all-gather wrapper. The MX-specific branch and configurations without a limit keep their existing selection.

This covers the W8A8 DeepSeek-V4-Flash deployment documented for Ascend. The change is confined to the shared Ascend runner.

## Validation

On Ascend, using the source-extracted runner, activation, quantization and grouped-matmul methods:

- **16 compute checks passed:** BF16/INT8, cumulative/count group lists, all three transport selections with a clamp, and no-clamp controls for standard routing.
- **2 graph replays passed:** BF16 and INT8 with changed inputs.
- Five valid rows plus three NaN padding rows; valid outputs match a CPU clamp/SiLU reference followed by the same GMM2 path.
- The standard-routing baseline fails all four clamped cases and passes all four no-clamp controls.
- CPU selection checks cover 12 combinations, including unchanged MXFP4/block-FP8 selection, plus a simulated TP wrapper check.
- Applicable lint checks pass; the two hooks requiring `python3` on Windows also pass when their scripts are invoked with `python`.

These checks execute real NPU ops, with transport selection scaffolded; they do not exercise distributed communication or full-model accuracy. An initial tiny-input run hit a device exception in the unchanged old DeepEP activation kernel, so the numerical baseline above is limited to standard routing. No throughput claim.
