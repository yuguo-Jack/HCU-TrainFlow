# [Fix] [NVIDIA] modelopt-nvfp4: Keep MoE global scales in gate/up order

[Upstream PR](https://github.com/sgl-project/sglang/pull/45289) · state: closed · merged: True

## Original PR description

## Motivation

ModelOpt NVFP4 MoE global scales identify the logical gate and up projections, while some kernels require weights in physical `[up, gate]` order. This PR replaces the merged #44858 implementation with a loader fix that keeps global scales in canonical `[gate, up]` order across backends.

The contents of #44858 (`78185f4b3f565cbe0fec20d71bb5deb372428e80`) are reverted, including its helper extraction and added weekly test. The loader implementation retains the SwiGLU beta correction (`1 / g1_alphas_up`), the shared-clamp warning, and CPU tests of the actual loading and post-load paths.

## Changes

- Reorder ModelOpt NVFP4 weights and block scales in `_load_w13`, leaving per-tensor global scales in logical order.
- Use `use_flashinfer_trtllm_weight_layout` so nominal TRT-LLM with MegaMoE retains canonical weight order.
- Remove the backend-dependent `up_first` argument from GEMM1 alpha computation.
- Cover backend layouts, TP slicing, repeated loading, non-gated experts, and SwiGLU/SiTU post-load parameters in the existing CPU suite.
