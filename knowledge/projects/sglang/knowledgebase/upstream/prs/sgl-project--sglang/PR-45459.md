# [Fix] openai: Support long prompt encoding with fastokens

[Upstream PR](https://github.com/sgl-project/sglang/pull/45459) · state: open · merged: False

## Original PR description

## Motivation

Eligible long prompts fail with `--tokenizer-backend fastokens` when parallel prompt encoding builds its plan: fastokens' `PostProcessor` does not expose `num_special_tokens_to_add`. The tokenizer backend does, as does Hugging Face tokenizers. This compatibility failure is mentioned separately in #45310; this PR does not address that issue's multimodal deadlock.

## Modifications

Query the special-token count through the tokenizer backend. Add a real fastokens regression covering absent, ByteLevel and TemplateProcessing post-processors, including token ID equivalence with and without special tokens. The existing CPU test dependency already installs fastokens.

## Accuracy Tests

- Reproduced on CPU with fastokens 0.3.4, Transformers 5.19.0 and the Qwen3-32B tokenizer, loaded through `fastokens.patch_transformers()` and `AutoTokenizer`. Before: 54,050-character English and 47,550-character Chinese prompts both raise `AttributeError`, with either `add_special_tokens` setting. After: all four outputs exactly match direct encoding; short prompts and the Hugging Face backend also remain identical.
- New regression fails in all three post-processor cases before the fix. The complete `test_parallel_prompt_encode.py` suite passes after it: 20 tests and 16 subtests. On this macOS host, an isolated import harness loads the real encoder and tokenizer packages and substitutes `unittest.TestCase` only for the GPU idle/retry test wrapper; the normal Linux CI suite remains to run.
- Repository pre-commit checks passed for both changed files.

## Speed Tests and Profiling

No performance claim; this restores a failing tokenization path. No GPU inference was run.
