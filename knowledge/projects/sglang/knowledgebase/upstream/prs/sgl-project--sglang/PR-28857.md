## Summary

Fix two Gemma4 tool-parser array cases: a quoted `]` inside a nested array must stay part of the string, and a stray closing bracket in a bare value must stop parsing instead of looping forever. The change follows the merged vLLM fix in https://github.com/vllm-project/vllm/pull/41991 and keeps the no-progress guard scoped to arrays.

Regression coverage includes nested quoted brackets and a stray closing bracket. The branch is rebased onto current main.

This pull request fixes potential infinite loops and depth corruption in the Gemma 4 array parser by correctly skipping string delimiters and handling stray closing brackets. The review feedback correctly points out that the timeout mechanism relies on POSIX-specific `signal.SIGALRM` and `signal.alarm`, which will fail on non-POSIX platforms like Windows, and suggests conditionally enabling the timeout guard to improve portability.

- gemini-code-assist[bot] · comment · 2026-06-21T22:50:14Z · [source](https://github.com/sgl-project/sglang/pull/28857#discussion_r3449178862)

![medium](https://www.gstatic.com/codereviewagent/medium-priority.svg)

The `signal.SIGALRM` and `signal.alarm` functions are only available on Unix-like (POSIX) systems. Running these tests on non-POSIX platforms (such as Windows) will raise an `AttributeError`. To make the test suite more robust and portable, we should conditionally enable the timeout guard only if `SIGALRM` is supported.

```suggestion
def _time_limit(seconds: int):
    if not hasattr(signal, "SIGALRM"):
        yield
        return

    def _raise(*_):
        raise TimeoutError("gemma4 parser did not terminate")

    signal.signal(signal.SIGALRM, _raise)
    signal.alarm(seconds)
    try:
        yield
    finally:
        signal.alarm(0)
```
