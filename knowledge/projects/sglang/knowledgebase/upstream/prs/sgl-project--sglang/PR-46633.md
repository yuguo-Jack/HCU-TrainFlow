# [Perf] [NVIDIA] gdn: Make ReplaySSM verify pipeline stages configurable

[Upstream PR](https://github.com/sgl-project/sglang/pull/46633) · state: open · merged: False

## Original PR description

## Motivation

Three Triton pipeline stages reduced GDN ReplaySSM verify latency on the measured Qwen3.8 Flash-Next Rubin recipe, but they regress several GB300 shapes, especially FP32 SSM checkpoints. Preserve the existing two-stage default and make tuning opt-in.

## Modifications

- Add `SGLANG_GDN_REPLAYSSM_VERIFY_NUM_STAGES` through `environ.py`, default `2`. Read it once when the GDN attention backend is constructed, then pass the cached integer only to ReplaySSM target verify.
- Document `SGLANG_GDN_REPLAYSSM_VERIFY_NUM_STAGES=3` for the measured Rubin TP1 / BF16 SSM / NEXTN 3-step, 4-draft-token recipe in the Qwen3.8 Flash-Next cookbook.
- Leave ordinary decode, prefill, KDA, and non-ReplaySSM verify unchanged; the existing gfx95 specialization still overrides the applicable launch to one stage.
- Keep one numerical test: eight requests combine empty/mixed/full history and a padded request, comparing output and all five ring buffers bitwise between two and three stages.

## Accuracy Tests

GB300 (SM103), PyTorch 2.15.0+cu134, Triton 3.9.0, CUDA 13.4: all 90 microbenchmark cases matched bitwise in output and five ring buffers. Shapes cover Qwen3.5-397B TP4/TP8, Qwen3.8 Flash-Next TP1/TP4 and Qwen3-Next TP1, BF16/FP32 checkpoints, and 1/4/16/28/32/64/96/128/256 requests with four verify tokens per request. The original four-history numerical test and the final minimal test were also run on GPU after the change.

## Speed Tests and Profiling

GB300, one verify kernel at a time, ring length 16, four draft tokens, mixed 0–8 history. Median of 90 CUDA-event measurements with a 256 MiB L2 flush before each timed kernel; these are cold-cache kernel measurements, not end-to-end serving results.

| Model / TP | SSM dtype | Requests | 2 stages (µs) | 3 stages (µs) |
|---|---|---:|---:|---:|
| Qwen3.5-397B TP4 | FP32 | 32 | 22.528 | 26.672 |
| Qwen3.5-397B TP8 | FP32 | 64 | 22.720 | 26.656 |
| Qwen3.8 FN TP1 | FP32 | 256 | 247.824 | 304.128 |
| Qwen3.8 FN TP1 | BF16 | 64 | 50.864 | 49.968 |
| Qwen3.8 FN TP4 | BF16 | 96 | 24.576 | 25.648 |

Compiled shared memory per CTA grows from 13,312 to 24,576 bytes for BF16 checkpoints, and from 22,528 to 41,984 bytes for FP32 checkpoints. These tradeoffs vary with dtype, head shape, batch and architecture, so this PR uses an explicit opt-in instead of an automatic threshold inferred from one GPU/compiler environment.

Earlier Rubin TP1 / BF16 SSM serving measurements: verify kernel 26.40 → 23.48 µs per layer (36 layers); decode step at concurrency 64 / 8K, 18.09 → 17.97 ms. Those measurements motivated the opt-in and were not rerun on Rubin in this revision.
