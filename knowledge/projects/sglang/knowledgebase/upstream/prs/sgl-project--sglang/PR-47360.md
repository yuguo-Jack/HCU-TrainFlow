# [CI] [AMD] start-container: Let PR jobs use a cached image up to 2 days old

[Upstream PR](https://github.com/sgl-project/sglang/pull/47360) · state: closed · merged: False

## Original PR description

## Motivation

Since #47162 (merged 2026-10-29), MI300 jobs on ROCm 10 take about 3 minutes to start their container, up from about 6 seconds. It started at 19:00 UTC that day, when that day's MI300 image was published.

Why:

- #47162 changed `amd_ci_start_container.sh` to always prefer the newest image on Docker Hub.
- Each ARC runner is used for one job and then deleted. Images it pulls are not kept for the next job.
- Runners start with a copy of a per-node warm store that holds one image (`rocm10-mi30x`). The store is refreshed about 5 hours 20 minutes after a new image is published (for example, the 2026-10-29 image was published at 19:06 UTC, and the nodes refreshed at 00:26-00:29 UTC).
- So from each publish until the next refresh, every MI300 ROCm 10 job downloads the 63 GB image again through the Dragonfly mirror, taking about 3 minutes. That is about 5 hours a day, roughly 40 extra runner hours a day.

## Modifications

For `pull_request` runs only, use an image that is already on the runner if it is at most 2 days old (`PR_LOCAL_IMAGE_MAX_AGE_DAYS`, default 2). Otherwise, fall through to the current newest-first logic.

Scheduled, nightly and manual runs are unchanged and still take the newest image.

PR jobs install sglang from the PR checkout and build `sgl-kernel` from it, so an image up to 2 days old is fine for them. The image still provides AITER, Triton, torch, ROCm and the Dockerfile settings.

Checked locally with a stub `docker`:

| Run | On the runner | On Docker Hub | Picked |
|---|---|---|---|
| PR | yesterday | today | yesterday (no pull) |
| PR | 3 days old | today | today (pull) |
| schedule | yesterday | today | today (pull) |
| schedule | yesterday | yesterday only | yesterday (no pull) |

The gap it worked around is now short.
