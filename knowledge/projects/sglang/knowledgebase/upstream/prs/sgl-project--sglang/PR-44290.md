# [Fix] bench_serving: fix peak concurrency accounting in metrics

[Upstream PR](https://github.com/sgl-project/sglang/pull/44290) · state: open · merged: False

## Original PR description

Fixes #44278

### Motivation

`calculate_metrics` in `python/sglang/benchmark/serving.py` computed `Peak concurrent requests` as the max over per-second buckets: every integer-second bucket touched by a request (from start second through end second) was incremented, then the max was taken. That accounting over-counts requests that never run at the same time:

- five sequential requests inside one second reported a peak of 5 instead of 1;
- a request ending exactly when another starts reported a peak of 2 instead of 1 (double-counted boundary handoff).

So the reported "Peak concurrent requests" could exceed the benchmark's configured `--max-concurrency`, as seen in the run recorded in #14165 (`Max request concurrency: 1` but `Peak concurrent requests: 2`).

### Modifications

- In `calculate_metrics`, keep the per-second `concurrent_requests_per_second` bucket array for the `--plot-throughput` plot, but compute the scalar `max_concurrent_requests` with a sweep line over half-open `[start, end)` intervals of successful requests: end events sort before start events at the same timestamp, so touching intervals do not count as overlapping.
- Unchanged: per-second plot statistics, output-token throughput, average concurrency, and the "Peak concurrent requests" printout label — only the scalar peak is now truthful.

The Rust client's `peak_windows` (`rust/sglang-bench/src/metrics.rs`) shares the same bucket accounting; left out of scope here so the change stays CPU-verifiable, noted as a follow-up.

### Tests

- Issue's CPU-only repro (from the issue body) against the real `calculate_metrics`, with heavy deps (`torch`, `transformers`, `aiohttp`, ...) stubbed via `sys.modules`: sequential-within-one-second now reports 1 (was 5), boundary handoff reports 1 (was 2), genuinely-overlapping control still reports 5 — all pass.
- Additional edge cases verified: staggered/nested overlaps (peak 3), chained touching intervals (peak 1), failed requests excluded, overlaps spanning multiple seconds — all pass.
- `ruff check --select F401,F821,F823,UP037`, `ruff format --check`, `python3 -m py_compile`, and `git diff --check` all pass on the touched file.
- No GPU on this machine; end-to-end benchmark runs and the Rust client change were not exercised here — a maintainer CI run (`--ask-ci`) would be appreciated.
