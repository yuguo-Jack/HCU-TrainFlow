# [Feat] lora: Record a LoRA-free decode graph for the dense engine (07/21)

[Upstream PR](https://github.com/sgl-project/sglang/pull/42874) · state: closed · merged: False

## Original PR description

Part 07 of 21 of the LoRA runtime stack (branch `lora-stack-06-dense-graphs`, base `lora-stack-05-dense-runner`). The stack is cut from the development branch of #42284.

## What this part adds

When the LoRA backend skips inactive dense batches, DecodeCudaGraphRunner
records a "nolora" graph per batch size for all-base batches.
Tests: the backend flag and the decode runner's default.

Files outside the LoRA owners' paths: `srt/model_executor` (decode graph runner).

## Verification

- GB300 run r45: the tree of upstream main `c1c287a429` plus parts 01–07 imports every module this part changes and passes this part's tests together with every earlier part's unit tests: **364 passed, 20 warnings, 152 subtests passed in 28.18s** (excluding the tests that fail identically on the untouched base tree in that environment).
- A serving smoke at this prefix (Qwen3-0.6B with a synthetic rank-16 adapter, `--lora-backend triton_v2`, decode graphs on, mixed adapter/base batch) produced the same texts, token ids and log-probs as the complete stack.
- `pre-commit` passed on the changed files of every part; `pre-commit run --all-files` passed on the complete stack tree.

The complete 21-part tree equals the development branch of #42284 at `e7b7179a86` (the `6588053ef2` tree with four test-only follow-ups squashed into its dense commit: the admission/snapshot trim, the restored FP8 block-shape admission pin, a second trim that keeps only the tests guarding silent failures and adds pins for four coverage gaps, and restored numerical and packing coverage; production code is unchanged) minus the benchmark tools and the Triton MoE tuning tables, which follow in separate PRs.
