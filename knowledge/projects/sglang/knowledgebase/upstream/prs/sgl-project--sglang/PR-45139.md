# [Fix] frontend: Pass custom CA certificates to streaming requests

[Upstream PR](https://github.com/sgl-project/sglang/pull/45139) · state: open · merged: False

## Original PR description

## Motivation

When connecting to an HTTPS server signed by a custom CA, `RuntimeEndpoint(..., verify="/path/to/ca.pem")` can initialize and make non-streaming requests, but streaming generation fails with `CERTIFICATE_VERIFY_FAILED`. The streaming branch of `http_request` omits `verify` when calling `requests.post`, so the supplied CA bundle is ignored.

## Modifications

- Forward `verify` to `requests.post` for streaming requests.
- Add a CPU regression covering custom CA selection, certificate verification with the default `verify=None`, and streamed response consumption. It uses the real requests TLS configuration and mocks urllib3's network I/O boundary.
