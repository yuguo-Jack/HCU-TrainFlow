# [Doc] lora: document PEFT adapter compatibility and fused target modules

[Upstream PR](https://github.com/sgl-project/sglang/pull/45362) · state: open · merged: False

## Original PR description

## Motivation

The LoRA Serving page explains how to start a LoRA server, but it does not explain what makes a PEFT adapter compatible with SGLang's runtime layout. This leaves users without a documented path when an adapter uses a regex `target_modules` string, or when the adapter targets an unfused projection that SGLang fuses at runtime.

This PR adds an "Adapter compatibility" section to `docs/docs/advanced_features/lora.mdx`. It documents the `target_modules` list requirement, common fused-name mappings, the model-specific `supported_lora_modules` contract, when repacking is needed, and a short verification recipe. It does not change runtime behavior.

This is based on a real Qwen3.5-family 27B GDN hybrid MoE adapter exported by PEFT/ms-swift. The adapter uses a regex `target_modules` string and split `in_proj_qkv`, `in_proj_z`, `in_proj_b`, and `in_proj_a` tensors. This PR turns that compatibility contract into documentation; it does not change runtime behavior.

## Modifications

- `docs/docs/advanced_features/lora.mdx`: add an "Adapter compatibility" section after the LoRA serving arguments.
- Document that `target_modules` must be a list of suffixes. An arbitrary regex string is rejected even when `--lora-target-modules` is provided, because SGLang still validates each adapter's `adapter_config.json`.
- Document the common fused mappings (`q_proj` / `k_proj` / `v_proj` -> `qkv_proj`, `gate_proj` / `up_proj` -> `gate_up_proj`) and the GDN examples (`in_proj_q` / `in_proj_k` / `in_proj_v` / `in_proj_z` -> `in_proj_qkvz`, `in_proj_qkv` + `in_proj_z` -> `in_proj_qkvz`, `in_proj_b` + `in_proj_a` -> `in_proj_ba`), with a note that support is model- and version-specific.
- Clarify that repacking changes module names and tensor layout only, and must preserve `r`, `lora_alpha`, `lora_dropout`, and the A/B values.
- Add a verification checklist: use `--lora-strict-loading`, inspect the resolved target set, confirm the adapter appears in `/v1/models`, and compare base and adapter outputs at temperature 0.
