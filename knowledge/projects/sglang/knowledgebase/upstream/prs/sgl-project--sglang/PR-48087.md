# [Perf] imports: Keep the detokenizer off TokenizerManager and the tokenizer off schedule_batch

[Upstream PR](https://github.com/sgl-project/sglang/pull/48087) · state: closed · merged: True

## Original PR description

- `TokenizerWorker` and `get_tokenizer_worker_class` move, unchanged, from `managers/multi_tokenizer_mixin.py` to a new `managers/tokenizer_worker.py`. The detokenizer imports `MultiHttpWorkerDetokenizerMixin` from the mixin module, and the `TokenizerWorker(TokenizerManager)` subclass there made it load all of `TokenizerManager`. `engine.py`, `http_server.py` and `ServerArgs.get_tokenizer_worker_class` import the worker from the new module.
- The tokenizer side no longer loads `schedule_batch`:
  - `BaseFinishReason`, the five `FINISH_*` classes and `MultimodalInputs` move, unchanged, from `managers/schedule_batch.py` to `managers/req_types.py`. Their 143 importers in 123 files (model files, multimodal processors, the tokenizer side) import them from `req_types`, and no longer load the batch module to get them;
  - `get_request_return_hidden_states_mode` moves, unchanged, to `managers/req_types` next to `get_return_hidden_states_mode`;
  - `disaggregation/encoder/receiver.py` imports `Req` inside `create_req`, its only use;
  - `managers/utils.py` imports `Req` for annotations only.

Import time, CPU only, warm `.pyc`, median of 5:

| module | main (s) | this PR (s) | modules loaded (main -> PR) |
|---|---|---|---|
| `sglang.srt.managers.detokenizer_manager` | 8.28 | 5.57 | 7937 -> 5778 |
| `sglang.srt.managers.tokenizer_manager` | 8.99 | 8.63 | 7925 -> 7335 |
| `sglang.srt.entrypoints.engine`, `http_server`, `managers.scheduler` | 8.7-9.5 | unchanged | +1 (the new module) |

No behavior change, except that:
- `TokenizerWorker` and `get_tokenizer_worker_class` are imported from `sglang.srt.managers.tokenizer_worker` instead of `sglang.srt.managers.multi_tokenizer_mixin`;
- the moved request types report `sglang.srt.managers.req_types` as their `__module__`. `schedule_batch` still imports them, so the old import path keeps working.
