# [Feat] hicache: Deduplicate MLA layers in Kimi hybrid stacks

[Upstream PR](https://github.com/sgl-project/sglang/pull/45175) · state: open · merged: False

## Original PR description

> Part of the HiCache MLA host-dedup series (see umbrella(#45177)). This is `[6/N]`, stacked on `[5/N]`. Builds on `[3/N]` (#45141 — L2 dedup and the shared-CPU-read path) and `[2/N]` (#43798 — rank-sharded state files); the file-L3 broadcast combination also relies on `[4/N]` (#45168). The shared-CPU-read extension for Kimi is delivered in #45177.

## Motivation

Kimi K3's MLA KV is duplicated across TP ranks and can keep a single copy, but KDA/linear-attention state differs per rank and must be stored separately. The global model layer number also differs from the MLA sub-pool layer number and must be mapped correctly.

## Modifications

- Dedup only the MLA host KV; broadcast mode uses owner/dummy. KDA/Mamba state keeps real per-rank allocation and read/write.
- Map model global layers to MLA buffers; the budget includes one MLA copy plus all private state.

Shared mode for Kimi (all GPUs restore from one CPU MLA cache, KDA state still restored independently) is added in #45177; this PR keeps broadcast as the default. Shared read is limited to single-node plain-TP L2 and is not extended to file L3. The file-L3 broadcast combination depends on `[4/N]` and the rank-state-file isolation in `[2/N]`.

## Accuracy Tests

Validation scope: the five-group 80/80 result below includes `nodup → broadcast → nodup → shared → nodup`. The three groups relevant to this broadcast PR account for 48/48 full answers and 24 real L2 restores. The shared group and its following baseline account for the remaining 32/32 answers and 16 restores and are reported in #45177, together with Kimi-specific shared-read slow-reader/cancellation/reuse checks. These model figures come from earlier integrated builds, not a rerun of this rebased branch.

Component checks: **94 passed, 1 skipped, 45 sub-checks passed**. The latest full model has 24 MLA layers + 69 KDA layers; five interleaved comparison groups give **80/80 full answers** correct, with cold/restored and cross-mode text and full token IDs identical. Five groups × 8 real L2 restores each (host 2368, device 0), 40 total; recompute-after-clear passes. A dual-GPU test additionally checks different physical positions, slow rank, cancellation, and reuse.

An earlier broadcast-only switch group had 16/16 answers correct per group, 8 replays at host 1216 each; an independent file-L3 restart regression had two groups × 8 restores at 8704 storage tokens each, four rounds 32/32 answers identical. This is an L3 correctness check, not an L3 performance or cancellation test.

GSM8K first-200 single-run comparison: no-dedup 149/200, dedup 151/200, both with no error requests or truncation; 192 answers have identical text and extracted answers. This is **not** a claim that dedup improves accuracy.

## Speed Tests and Profiling

Single node, 8×NVIDIA GPU (SM103, ~267.7 GiB usable each), TP8, PyTorch 2.14.1+cu130, sglang-kernel 0.4.9, FlashInfer 0.7.0.post1. Model uses MXFP4 packed weights with BF16 KV and its original FlashInfer SiTU backend. Fixed GPU cache cap 4096 tokens, context 4096, host ratio 32, Mamba cache 32, chunked prefill 512, CUDA graph disabled. All modes use the same weights, data, and non-experimental args.

Unmodified community `benchmark/hicache/bench_multiturn.py`: 16 independent sessions, first round 2048 input tokens, sub-question length 80 (2144 actual second-round input after formatting), 16 output tokens, concurrency 1, 4 req/s, FIFO, seed 1. Prefix working set ~32,768 tokens, exceeding GPU cache and fitting in L2. Cache is cleared at each benchmark start; round 1 writes, round 2 restores. Each group warms up once and measures five formal runs, interleaving restart baselines in the order below.

| Mode | Five restore-round avg TTFT (ms) | Median (range), ms | Two-round TPOT median, ms | Two-round throughput median, req/s |
| --- | --- | ---: | ---: | ---: |
| No dedup, before baseline | 405.63 / 409.03 / 407.29 / 430.92 / 406.98 | 407.29 (405.63–430.92) | 166.632 | 0.23953 |
| Dedup broadcast | 405.34 / 423.74 / 395.81 / 414.56 / 407.08 | 407.08 (395.81–423.74) | 164.851 | 0.24370 |
| No dedup, middle baseline | 403.65 / 412.26 / 399.24 / 402.19 / 413.28 | 403.65 (399.24–413.28) | 164.156 | 0.24645 |

(The shared-read group and after-baseline are reported in #45177.) Broadcast is ~**+0.40%** vs the mean of its two adjacent no-dedup medians. Sample ranges overlap, supporting "close to baseline" for this workload; no statistically significant speedup or universal gain is claimed. All formal samples have restore-round total hit 95.5224%, identical real host restore volume per mode, and zero GPU-hit delta across eight TP ranks. Only MLA copies are deduped; KDA state is still stored per rank, so whole-machine memory savings cannot be scaled by MLA layer count.

Profile is separate from formal timing. Broadcast here covers 24 MLA layers; other model TP communication is retained. Receiving-rank NCCL time includes waiting and is not the net latency difference vs no-broadcast.

### Repro

Run on a single node with enough memory for the same full weights; first generate the public synthetic data:

```python
import json
rows = []
for i in range(64):
    prompt = (f"Document number {i}. Describe the sequence for task {i}. "
              + f"In task {i}, the river crosses the stone bridge and the team records each result. " * 120)
    rows.append({"conversations": [
        {"from": "human", "value": prompt},
        {"from": "gpt", "value": f"Record the result for task {i}."},
    ]})
with open("public-conversations-64.json", "w") as f:
    json.dump(rows, f)
```

Set `MODE` per group and launch an independent server; other args unchanged (`MODE` is `nodup` or `broadcast` here; `shared` is in #45177):

```bash
MODEL=/path/to/Kimi-K3
PORT=30000
MODE=nodup  # nodup, broadcast
DEDUP_ARGS=()
case "$MODE" in
  nodup) ;;
  broadcast)
    DEDUP_ARGS=(--enable-mla-hicache-host-dedup
                --mla-hicache-host-dedup-mode "$MODE") ;;
  *) exit 1 ;;
esac
NCCL_NVLS_ENABLE=0 python -u -m sglang.launch_server \
  --model-path "$MODEL" --tp-size 8 \
  --host 127.0.0.1 --port "$PORT" --trust-remote-code \
  --weight-loader-prefetch-checkpoints --enable-cache-report --enable-metrics \
  --mem-fraction-static 0.85 --max-total-tokens 4096 \
  --context-length 4096 --max-running-requests 4 \
  --chunked-prefill-size 512 --disable-cuda-graph \
  --max-mamba-cache-size 32 \
  --enable-hierarchical-cache --hicache-ratio 32 \
  --hicache-write-policy write_through --hicache-io-backend direct \
  --hicache-mem-layout page_first_direct --random-seed 42 \
  "${DEDUP_ARGS[@]}"
```

After the server is ready, in another terminal with the same `MODEL`/`PORT`, run the order `nodup → broadcast → nodup` here (the full `nodup → broadcast → nodup → shared → nodup` sequence spans `[6/N]` and #45177). Use a separate results dir per group and keep all five formal samples:

```bash
GROUP=nodup-before  # nodup-before, broadcast, nodup-middle
mkdir -p "results-$GROUP"
for TRIAL in warmup 1 2 3 4 5; do
  curl -fsS "http://127.0.0.1:$PORT/metrics" \
    > "results-$GROUP/metrics-$TRIAL-before.txt" || exit 1
  python benchmark/hicache/bench_multiturn.py \
    --host 127.0.0.1 --port "$PORT" --model-path "$MODEL" \
    --dataset-path public-conversations-64.json \
    --num-clients 16 --num-rounds 2 --request-length 2048 \
    --sub-question-input-length 80 --output-length 16 \
    --max-parallel 1 --request-rate 4 --distribution uniform \
    --enable-round-barrier --ready-queue-policy fifo \
    --disable-auto-run --seed 1 \
    --log-file "results-$GROUP/benchmark-$TRIAL.jsonl" \
    --tag "$GROUP-$TRIAL"
  curl -fsS "http://127.0.0.1:$PORT/metrics" \
    > "results-$GROUP/metrics-$TRIAL-after.txt" || exit 1
done
```

Compare `round.round_1.average_ttft`, excluding warmup. In the out-of-timing metric snapshots, each formal run has host-hit delta 32,832 and zero native device-hit delta across eight TP ranks; verify total hit rate and true L2 restore separately. Broadcast remains the default. This group validates L2 only.
