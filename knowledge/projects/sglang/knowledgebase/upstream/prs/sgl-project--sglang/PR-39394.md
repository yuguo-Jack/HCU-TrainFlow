- Leslie360 · comment · 2026-09-16T02:11:25Z · [source](https://github.com/sgl-project/sglang/pull/39394#issuecomment-5690967977)

**Hardware verification now closed on two independent machines — `hardware-pending` in the commit message can be dropped.**

We reproduced the exact failure mode and confirmed the fix on **two different 8×A800 (SM80) rigs** (driver 550.144.03, sglang main @ 5c2de3f, torch 2.13.0+cu130), using the real production `weight_loader` path (CPU tensors, gloo backend, 2 processes `RANK/WORLD_SIZE=2`).

**Minimal repro** (the failing combination this patch clamps):
```python
from sglang.srt.layers.linear import ColumnParallelLinear, RowParallelLinear
from sglang.srt.distributed.parallel_state import initialize_model_parallel
# TP2 engine
initialize_model_parallel(tensor_model_parallel_size=2, backend="gloo")
# layer built with explicit tp_size=1, tp_rank left to constructor fallback
gate_up = ColumnParallelLinear(64, 128, bias=False, tp_size=1, prefix="mlp.gate_up")
down = RowParallelLinear(128, 64, bias=False, tp_size=1, prefix="mlp.down")
# real weight_loader on full checkpoint weights
gate_up.weight_loader(gate_up.weight, full_gate_up)
```

**A/B (identical on both machines):**

| Tree | rank0 | rank1 | exit |
|---|---|---|---|
| unpatched main | loads OK | `RuntimeError: start (128) + length (128) exceeds dimension size (128)` at `linear.py:451 weight_loader` (`loaded_weight.narrow`) | 0/1 |
| patched | loads OK | `tp_rank` clamped to 0, full replica loaded, params identical to checkpoint | 0/0 |

CPU unit tests: `test_resolve_tp_rank.py` **4 passed** on the patched tree (both machines). Full `test/registered/unit/layers/` suite: 4 pre-existing failures (DeepEP/MoE) identical before/after the patch on both machines — not introduced by this change.

**Why it matters:** a layer built with explicit `tp_size=1` (full replica — e.g. a tp=1 draft model, or shared experts under DeepEP/a2a with `--disable-shared-experts-fusion`) inside a TP>1 engine falls back `tp_rank` to the GLOBAL rank; on rank≥1 the loader computes `start_idx = tp_rank * shard_size` and narrows past the end of the replicated weight. Clamping `tp_rank` to 0 when effective `tp_size==1` fixes it at the constructor.

No further `hardware-pending` caveats remain.
