# [Perf] [NPU] dsv4: Avoid unused packed indexer cache allocation

[Upstream PR](https://github.com/sgl-project/sglang/pull/47647) · state: open · merged: False

## Original PR description

## Motivation

The NPU V4 Indexer pool allocates the base CUDA-format packed cache as well as separate native K and scale buffers. NPU writes, PD registration and HiCache use the native buffers; the packed allocation is never updated.

With 65,536 compressed slots and four Indexer layers, removing it reduces measured pool allocations from 65.67 MiB to 32.54 MiB when the FP4 indexer option is off.

## Modifications

- Skip the unused packed allocation.
- Expose the native buffers as shared-storage byte views through `contiguous_page_row_buffers()`.
- Reject the packed-only accessor explicitly instead of returning unused storage.
- Update the comments describing the pool layout.

Native buffer shapes, dtypes and write operations are unchanged.

## Accuracy Tests

Reused the original and patched source methods in an isolated harness with generic KVCache setup scaffolded:

- 8 NPU cases passed: sizes 0/64/1024/65536, FP4 option off/on, four layers, head dimension 128, native page size 64 and global page size 256.
- Native K/scale writes and readback match exactly before and after. PD pointer/length metadata and HiCache region selection refer to the native buffers. Page-row views share storage and pass host/device round-trip checks.
- 16 CPU cases passed, additionally checking the arch35 FP8/FP32 layout. No arch35 hardware run was performed.

These are pool-level checks, not full-model accuracy or cross-host PD tests.

## Speed Tests and Profiling

Measured `torch.npu.memory_allocated()` deltas for pool construction at 65,536 slots and four layers:

| FP4 option | Before | After | Saved |
| --- | ---: | ---: | ---: |
| Off | 68,855,808 bytes | 34,115,584 bytes | 33.13 MiB |
| On | 52,013,056 bytes | 34,115,584 bytes | 17.07 MiB |

The option changes the old packed allocation, not the native NPU buffers. These savings apply to the Indexer pool, not total model memory. Throughput was not benchmarked.
