# [Fix] [AMD] hicache: Size the Mamba host share by persistent checkpoint bytes

[Upstream PR](https://github.com/sgl-project/sglang/pull/47040) · state: open · merged: False

## Original PR description

## Motivation

- HiCache mirrors only the persistent Mamba checkpoint to host: conv state and temporal (SSM) state.
- `MambaPool` published no host-specific size, so host-budget code fell back to `get_kv_size_bytes()`, which also counts device-only speculative-verify scratch and ReplaySSM rings.
- Result: the Mamba host weight was inflated (Kimi-K3: 9.68 GB vs 5.22 GB per rank), which
  - shrank the KV share of an explicit `--hicache-size` split by device pool bytes, and
  - over-estimated host bytes in HiCache auto-sizing, lowering the auto ratio.

## Modifications

- `MambaPool.host_capacity_bytes` = conv + temporal checkpoint bytes only; consumers already prefer it over `get_kv_size_bytes()`:

| Consumer | Effect |
|---|---|
| `_split_hicache_size` (explicit `--hicache-size`, no Mamba pin) | Mamba share drops to its checkpoint bytes; KV share grows |
| `hicache_auto_size._estimate_hicache_bytes` | Mamba estimate excludes scratch and rings |
| Unified memory stack | unchanged (sets its own `host_capacity_bytes`) |

- No change to the proportional split or auto-sizing logic, and no new flag; this PR is accounting-only.
- Regression test checks that the split fed by `host_capacity_bytes` ignores spec scratch.
- Related PRs:
  - #47867 (`--hicache-mamba-size-gb`): with the pin set, this PR has no effect; unset, the default split it falls back to moves toward KV.
  - #47584 does not interact with it.

## Accuracy Tests

- Only host-memory accounting changes; model forward, kernels, state contents and transfers are untouched.

| Test suite (MI355X) | Result |
|---|---:|
| Hybrid pool assembler | 45 passed, 36 subtests passed |
| HiCache auto-sizing | 3 passed, 2 subtests passed |
| Server arguments | 347 passed, 196 subtests passed |
| Pre-commit | passed |

- The server-argument suite has 4 MuseSpark subtest failures on ROCm (`modelopt_fp4` unsupported); same on `main`.

## Speed Tests and Profiling

- Capacity accounting only; no throughput or latency change expected.
- Kimi-K3 c16 startup logs, 8x MI355X, per-rank Mamba allocation:

| Component | Size | Mirrored to host? |
|---|---:|---:|
| Conv checkpoint | 0.34 GB | Yes |
| Temporal checkpoint | 4.88 GB | Yes |
| Speculative SSM scratch | 4.17 GB | No |
| Speculative conv scratch | 0.29 GB | No |

| Host sizing weight | Before | This PR | Delta |
|---|---:|---:|---:|
| Per-rank Mamba bytes | 9.68 GB | 5.22 GB | **-46.1%** |

- The old fallback was inflated by 4.46 GB (~85% over the checkpoint size); that host budget goes back to the KV tier.
