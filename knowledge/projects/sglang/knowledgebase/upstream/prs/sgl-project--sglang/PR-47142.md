# [Fix] hicache: Enable DFlash L2/L3 caching with DCP

[Upstream PR](https://github.com/sgl-project/sglang/pull/47142) · state: open · merged: False

## Original PR description

## Motivation

`DFLASH` is rejected when DCP and HiCache are enabled, even though the existing replicated draft sidecar mirrors the widened logical slot space. Removing that guard alone also leaves automatic host sizing undercounting the draft allocation, and Mooncake's object-layout handshake can assert because it inspects a physical page instead of a logical storage page.

## Modifications

- Admit DFlash alongside DSpark through the existing DCP/HiCache path, preserving the unsupported-mode guards.
- Account for DCP-widened full draft sidecars in automatic host-cache sizing; keep SWA slot accounting unchanged.
- Use the logical page span for Mooncake object-layout inspection.
- Update the Kimi-K3/HiCache documentation. No kernel or speculative verification algorithm changes.

This PR contains no test-file changes. The validation below was run locally against the same runtime code.

## Accuracy Tests

Manual validation on 8 GB300 GPUs across two four-GPU nodes, based on `5cc9c933fc8acdffb5fc847d3b4824f082cd3297`:

- Target: `moonshotai/Kimi-K3`; draft: `modal-labs/Kimi-K3-DFlash@c192d15a43407bf758b5ae0880d5c72052fef1de`, block size 2.
- BF16 target/draft KV, FP32 SSM, TP8/DCP8, overlap and decode graphs enabled. Natural acceptance, without acceptance simulation.
- Frozen inputs of 2,100/4,700/8,800 tokens, 256 generated tokens. Restored/reference acceptance ratio must be at least 0.9; decode-versus-fresh-prefill logprob maximum difference must remain below 0.5.

| Check | Result |
| --- | --- |
| DFlash L2 eviction/load-back | 3/3 passed; host reuse 2048/4608/8704, device reuse zero |
| Native Mooncake TCP L3 | 6/6 passed across fresh-engine and flush/overwrite/restore cycles |
| File L3 | 6/6 passed across the same restore cycles |
| DCP1 DFlash regression | Base and candidate each passed 3/3, with identical judged values |
| DSpark DCP8 Mooncake regression | 6/6 passed |

The DFlash restores preserved acceptance (ratio 1.0) with maximum numerical difference 0.260715. Per-rank target/draft keys, payload sizes and Mamba state objects were checked after the judged requests. A disposable negative control suppressing only draft-sidecar preservation still restored target state but reduced acceptance ratios to 0.514/0.502/0.64, so the acceptance check detects draft-state loss hidden by target verification.

Mooncake validation used the real native TCP service with external 8 GiB segments per node, engine global segment zero and no SSD offload. Focused suites passed 115 CPU cases and 1,857 CUDA cache-component cases; 301 explicit fixture-matrix cases were skipped. Local negative-control probes also provide causal failing-base/passing-candidate evidence.

An FP8 KV baseline control exceeded the fixed numerical tolerance (0.777606 versus 0.5). These results validate the BF16 KV configuration; this PR does not claim to resolve that FP8 numerical gap or validate a separate `DFlash2DraftModel` selector checkpoint.

CI-pinned Mintlify 4.2.559 `broken-links --check-anchors --check-redirects` also passes.
