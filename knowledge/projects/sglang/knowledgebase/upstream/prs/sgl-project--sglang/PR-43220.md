# [Feat] minimax-h3: expose AdaLN cache stats in perf dumps

[Upstream PR](https://github.com/sgl-project/sglang/pull/43220) · state: open · merged: False

## Original PR description

## Motivation

MiniMax-H3's online AdaLN cache already counts cache activity, but request perf dumps cannot distinguish device hits, host restores, and successful builds. Expose those counters as request deltas and cache-instance cumulative snapshots. Follow-up to https://github.com/sgl-project/sglang/pull/35623#issuecomment-6008019614.

## Modifications

- Add `MiniMaxH3AdalnCacheStats.snapshot()` and `RequestMetrics.record_cache_stats(name, request, cumulative)`. Repeated collection into one metrics object adds request deltas and replaces the cumulative snapshot; nested report data is copied.
- Collect around the real H3 denoise loop, including preparation before step zero, with a local baseline and `finally`. Warmup and failed work remain in cumulative counters; warmup, suppressed metrics, disabled caches, and prebuilt sidecars do not add a report entry. `invalidate()` retains its existing cumulative behavior.
- Carry `cache_stats` through metrics serialization, disaggregation, performance logs/records, and benchmark perf JSON. Old records default to `{}`. Preserve atomic file replacement, the output-rank writer, and grouped-request representative selection.

Counters describe the reporting rank's local cache instance, without new collectives or TP summation. Cache policy, capacity, inference math, and CLI are unchanged.

| Field | Meaning |
| --- | --- |
| `gpu_hit_plans` | Distinct timestep plans found on device |
| `host_hit_plans` | Distinct timestep plans restored from the host tier |
| `built_plans` | Successfully built distinct timestep plans |
| `host_evicted_groups` | Evicted host groups |
| `host_pressure_skips` | Host stores skipped for capacity/pressure |

Example after cold A → device-hit A → cold B → host-restored A:

```json
{
  "cache_stats": {
    "minimax_h3_adaln": {
      "request": {
        "gpu_hit_plans": 0,
        "host_hit_plans": 2,
        "built_plans": 0,
        "host_evicted_groups": 0,
        "host_pressure_skips": 0
      },
      "cumulative": {
        "gpu_hit_plans": 2,
        "host_hit_plans": 2,
        "built_plans": 4,
        "host_evicted_groups": 0,
        "host_pressure_skips": 0
      }
    }
  }
}
```

## Accuracy Tests

**CPU component tests.** These use nonzero tiny safetensors weights and independent projection oracles. They cover:
- duplicate plans, device/host hits, host capacity/eviction;
- failed checkpoint retry and slot visibility;
- warmup and invalidation;
- the real denoising-stage entry point, plus accumulation and isolation;
- real sidecar loading;
- JSON/log/disaggregation compatibility, and grouped output-rank writing.

```bash

python -m pytest -q \
  python/sglang/multimodal_gen/test/unit/test_minimax_h3_adaln_perf_stats.py \
```

### Full H3 service validation

The GPU runs used the implementation before the rebase onto current main. The rebase only moved the unit test, so the runtime code is identical.

**Setup:**
- Model: full native `MiniMaxAI/MiniMax-H3` FL2VA at revision `42ed227e`.
- Hardware: 2 × B200, TP2.
- Settings: Torch SDPA, `lossless` quality, seed 42, CPU generator, 4 s at 24 fps, 768 short edge.
- AdaLN cache: online, plan width 2, 49 device slots, 4 GB host tier per rank.

**Runs:**
- **This change:** one server lifetime serves A → A → B → A (50/50/48/50 schedule points) through the real `/v1/videos` create/poll/content endpoints.
- **Parent:** serves A in a fresh server with the same configuration.

| Request | built | device hits | host hits | Video/audio latents vs parent | Decoded RGB vs parent | Decoded PCM vs parent |
|---|---|---|---|---|---|---|
| A, cold | 49 | 0 | 0 | identical | max 127, RMSE 1.13 | identical |
| A, repeat | 0 | 49 | 0 | identical | max 129, RMSE 1.36 | max 0.0035 |
| B | 46 | 1 | 0 | — (different prompt) | — (different prompt) | — (different prompt) |
| A, after B | 0 | 3 | 46 | identical | max 123, RMSE 1.24 | max 0.0035 |

**Results:**
- **Latents:** the original video and audio latents are bit-identical to the parent for every A request, so reporting does not change generation.
- **Counters:** they follow the expected cache path. The cold run builds 49 plans, the repeat hits 49 on device, and A after B restores 46 from the host tier.
- **Decoded media:** the MP4-decoded RGB frames (and PCM, for later requests) still differ slightly between server runs, even where the latents are identical — including the cold request, whose PCM is identical. So the difference comes from the decode/encode path after the latents, not from this change. The frames are visually equivalent.

## Speed Tests and Profiling

No end-to-end performance claim. Snapshot/delta reporting reads only Python integer counters; it adds no tensor reads, CUDA synchronization or collectives. The service run above is a correctness smoke test. Its latent capture synchronizes on both revisions, so it is not a latency benchmark.

Supersedes #43214, which used a differently named branch.
