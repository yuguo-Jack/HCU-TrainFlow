# [Perf] diffusion: Wan-Animate-2 1.7x faster denoising via exact FA3 in-context attention, opt-in FP8 reference K/V

[Upstream PR](https://github.com/sgl-project/sglang/pull/47121) · state: closed · merged: True

## Original PR description

## Motivation

Wan-Animate-2's in-context self-attention is about 71% of GPU time per denoising step on H100 (torch profiler). It runs compiled flex_attention over a padded [generation | reference video] layout that is always sized for a full-length clip, so short clips also pay for the padded frames.

## Modifications

1. **Exact FA3 path for the in-context attention (Hopper).** `_in_context_attention` computes the same masked attention as FA3 calls merged by log-sum-exp with the existing `merge_state` kernel:
   - dense FA3 over the generation keys;
   - varlen FA3 per frame over the reference keys (generation frame j attends reference frame j-1);
   - for `log_scale != 0` (distilled checkpoint), generation frame 1's keys get their own call with `lse + log_scale`, which equals the score bias;
   - a short clip's missing frames are zero keys under the full-clip mask, so they are added back exactly as `out * sigmoid(lse - log(num_zero_keys))`.

   `_split_attention_is_exact` gates it. Grids that differ by a row, batch > 1 and non-Hopper GPUs keep the flex path unchanged.
2. **Opt-in FP8 reference K/V cache.** `SGLANG_DIFFUSION_WAN_ANIMATE_2_FP8_REFERENCE_KV=1` (default off) stores the per-clip reference K/V as `float8_e4m3fn` with one fp32 scale per (token, head). Each block dequantizes into its attention input. It errors on non-CUDA, below sm89, and ROCm.
3. The reference cache is stored once per clip in the padded slot layout, sized to that clip.

## Benchmark

H100 80GB, official Wan2.2 demo inputs (`examples/wan_animate/animate`), 944x528, seed 42, layerwise DiT offload and text encoder CPU offload as in CI, FP8 off unless noted. Single runs; the PR ran first on a cold compile cache. Denoise step = steady-state s/it.

| setting | main step | PR step | step speedup | end to end (main to PR) |
|---|---|---|---|---|
| base, 1 GPU, 1 short clip, 40 steps | 9.75 s | 5.52 s | **1.77x** | 441.4 to 265.5 s (1.66x) |
| base, 1 GPU, 3 clips (2 full + short), 40 steps | 11.26 s (full clip) | 8.08 s | 1.39x (full), 3.17x (short) | 1299.6 to 809.5 s (**1.61x**) |
| distilled, 1 GPU, 10 steps, guidance 1.0 | 5.62 s | 2.94 s | **1.91x** | 109.7 to 73.4 s (1.49x) |
| base, 2 GPU CFG-parallel | 5.06 s | 2.84 s | 1.78x | 263.5 to 173.1 s (1.52x) |
| base, 2 GPU Ulysses SP=2 | 5.23 s | 3.08 s | 1.70x | 255.7 to 158.6 s (1.61x) |

Peak memory (base, 1 GPU, 1 clip), reserved / allocated: main 58.5 / 32.2 GB, PR 56.6 / 30.8 GB, PR with FP8 **27.2** / 23.7 GB. FP8 costs about 1-3% per step. Multi-clip and multi-GPU peak memory is about the same as main.

The FA3 path ran in every PR run: 0 flex autotune lines on a cold cache, while main logs them.

## Accuracy

- Unit tests (`test_wan_animate_2_parallelism.py`): 47 passed on H100, 167 passed / 8 skipped (H100-only) on CPU. New tests cover:
  - split vs flex on H100: full and short clip, `log_scale` 0 and -1.3, FP8 on and off;
  - split vs dense masked attention on CPU, with a torch stand-in for FA3;
  - when the gate allows the split;
  - FP8 quantization: zero rows, outliers, saturation.
- Single attention call at the real shape, split vs flex: rel L2 3.6e-3, max abs 2.4e-4 (bf16 rounding).
- End to end, per-frame PSNR of the decoded video vs main. Main is bitwise deterministic across runs, so this measures the change:

  | setting | PSNR mean / worst frame |
  |---|---|
  | base, FP8 off | 39.0 / 36.0 dB |
  | base, FP8 on | 40.4 / 36.0 dB |
  | distilled | 40.2 / 37.8 dB |
  | 3 clips | 39.3, 36.8, 35.0 dB per clip / 30.5 dB |
  | 2 GPU CFG-parallel, SP=2 | 37.8 / 32.7 dB, 40.5 / 38.3 dB |

  FP8 adds no measurable error on top of the kernel change. The difference is bf16 rounding in a different attention kernel, compounded over steps and blocks. It grows across clips because each clip is conditioned on the previous one. Main itself moves 38-40 dB between 1 and 2 GPUs.
