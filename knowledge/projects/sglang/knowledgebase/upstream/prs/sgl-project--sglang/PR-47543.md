# [Fix] hicache: mlock pinned host buffers so page aging never scans them

[Upstream PR](https://github.com/sgl-project/sglang/pull/47543) · state: closed · merged: True

## Original PR description

## Motivation

`cudaHostRegister` keeps a host pool's pages resident for DMA, but it leaves them on the kernel's evictable LRU. Proactive reclaim (page aging) clears the accessed flag of every page it scans there, pinned or not. On GPUs that read host memory through the CPU page tables (ATS), the device's next access to an aged page takes a page fault instead of a plain read, so host-to-device copies out of a HiCache host pool can fault page by page once the pool has been aged.

Locked pages sit on the unevictable LRU and are never scanned, so making mlock part of pinning removes those faults at the source. There is no new flag: a pinned buffer is a locked buffer.

## Modifications

All in `python/sglang/srt/mem_cache/pool_host/common.py`:

- `_cuda_host_register` mlocks the buffer once all of its ranges are registered. Every buffer that `alloc_with_host_register` pins (`pin_memory=True`) is therefore locked too: the HiCache host pools on CUDA and ROCm, and the other users of that allocator.
- `_cuda_host_unregister` munlocks it once all of its ranges are unregistered, so a destroyed pool returns to ordinary memory. The locked range is kept on the tensor next to the registered ranges, under `_HOST_LOCKED_RANGE_ATTR`.
- Before locking, the `RLIMIT_MEMLOCK` soft limit is raised to the hard limit, which needs no privilege. The locked range, the time the lock took, the limits, `CAP_IPC_LOCK` and `VmLck` are logged at INFO.
- A refused lock (a memlock limit below the buffer size without `CAP_IPC_LOCK`, as in many containers) logs a warning with errno, the size, the limits, `CAP_IPC_LOCK` and `VmLck`, and says to raise the limit or grant the capability. The buffer stays registered and usable exactly as before this PR. Failing instead would turn deployments that work today into startup failures, for a lock that only keeps device reads fast and never affects correctness.
- Unchanged: `pin_memory=False` (nothing is pinned or locked), torch-pinned buffers (npu, musa, xpu) and `hipHostMalloc` pools, which the device runtime allocates.

Cost: the host pool becomes unevictable memory, which it is pinned for DMA anyway. Locking adds work during startup; the INFO log reports its duration. On ATS platforms a registered pool could previously still be swapped out; with this change pinned means resident there too, as it already does on non-ATS platforms, so host pools must fit in RAM as they already must elsewhere.
