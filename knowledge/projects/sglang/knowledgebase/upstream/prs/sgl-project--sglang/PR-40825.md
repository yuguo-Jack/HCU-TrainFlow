# [Feat] [NPU] kimi-k3: Support DCP with shared compact communication

[Upstream PR](https://github.com/sgl-project/sglang/pull/40825) · state: closed · merged: True

## Original PR description

## Motivation

Enable decode context parallelism (DCP) for Kimi-K3 on Ascend NPU, including DSPARK speculative decoding. Sharding the target model's MLA KV cache across DCP ranks reduces per-rank KV storage for a given logical context capacity.

## Implementation

- **KV layout:** distribute target MLA latent and RoPE buffers by physical page. Localize cache-write locations to the owning rank, while keeping draft KV replicated.
- **Prefill/extend:** all-gather the cached target prefix and restore token order before the existing MLA attention computation. Replicated draft workers read their complete local cache.
- **Decode/target verify:** reuse the common Q all-gather, compute attention over each rank's local KV pages, and merge partial results through compact AllToAll with BF16/FP16 outputs and FP32 LSE. Eager target verification with no real queries returns zero partial outputs and `-inf` LSE for collective participation.
- **Eager and graph execution:** derive rank-local KV lengths, block tables, and per-query visibility from page ownership. Graph replay uses the backend's prepared local CPU lengths and pads graph-only request rows with zero; the FIA CPU length mirror is required.
- **P/D transfer:** support prefill DCP=1 to decode DCP=N with Ascend page transfers. Hybrid MLA uses the common layer-ID pairing helper across PP stages and selects local target pages and global replicated draft pages directly in `AscendKVManager.send_kvcache_dcp()` using `num_draft_entries`. DSA retains its per-entry pool layout metadata; KDA state uses its existing state-transfer path. Shared pool and prefill files are unchanged.

## Validation

- 17 CPU regression tests pass with production imports in an isolated CANN 9.2 overlay. Coverage includes 20 hybrid PP/draft/buffer-width transfer combinations that reject layout-helper calls, DSA index-buffer transfer addresses, and invalid metadata/draft-count rejection.
- CPU prefix-reconstruction checks pass across 450 configurations and 2,104 rank outputs, covering DCP2/4/8, token/page interleaving, partial pages, mixed and empty prefixes, and 128K/512K contexts.
- Syntax, repository-selected Ruff rules, Ruff formatting, isort, and diff checks pass for the tested files. Two existing E402 findings remain in `npu_graph_runner.py`.

These CPU checks do not validate native NPU kernels or full-model serving. Full-model accuracy, throughput/latency, and P/D end-to-end validation for the current head remain pending. The model results below are reference measurements and have not been reproduced on this head.

## Run

Four-node DSPARK example. Replace the paths, node addresses, distributed initialization address, and network interface with the deployment values. Ascend DCP requires `ASCEND_USE_FIA=1`; this example uses `--dcp-comm-backend a2a`.

Due to differences in memory layout:
- GPU: Uses a single contiguous buffer [latent | RoPE], allowing both parts to be written in a single kernel launch.
- Current NPU implementation: Uses two separate buffers:
  - k_buffer: latent
