# [CI][Ascend] Downgrade multimodal-gen 2-npu PR test to 2-NPU runner

[Upstream PR](https://github.com/sgl-project/sglang/pull/37397) · state: closed · merged: False

## Original PR description

## Motivation

The `multimodal-gen-test-2-npu-a3` PR test job currently runs on `linux-aarch64-a3-800t-16` (16-NPU) runners, but every test case in suite `2-npu` uses at most 2 NPUs:

- All 6 parametrized cases in `test_server_2_npu.py` use `num_gpus=2` (tp_size=2, ulysses_degree=2, or ring_degree=2, with all HCCL communication done within a single node).
- The standalone case `test_glm_image_distributed.py` occupies exactly 2 NPUs (AR on gpu 0 via `--base-gpu-id 0`, denoiser on gpu 1 via `--num-gpus 1 --base-gpu-id 1`), and its skip guard only requires `device_count() >= 2`.

Keeping this job on 16-NPU runners wastes scarce `a3-800t-16` resources that are contended by heavy suites such as acc-8 / acc-16. The repo already runs `multimodal-gen-test-1-npu-a3` and `base-c-test-acc-2-npu-a3` on `linux-aarch64-a3-800t-2` runners, so the 2-NPU runner pool is available and proven.

## Modifications

- `.github/workflows/pr-test-npu.yml`: change `runs-on` of the `multimodal-gen-test-2-npu-a3` job from `linux-aarch64-a3-800t-16` to `linux-aarch64-a3-800t-2`.
- Keep the matrix partitions (`part: [0, 1]`) and all other job settings unchanged. The per-shard estimated runtime (~20 min) is well below the 60-minute step timeout, so no timeout adjustments are needed.

Note: `minimax_h3_t2va_2npu` and `mova_360p_ti2va_2npu` rely on host memory for layerwise offloading; if the 2-NPU nodes have less host RAM, those two cases are the ones to watch in the CI result.
