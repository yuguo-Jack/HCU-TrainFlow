# [Rust] Serve any `model` name on the OpenAI chat and completions routes

[Upstream PR](https://github.com/sgl-project/sglang/pull/43923) · state: closed · merged: True

## Original PR description

## Motivation

The Rust frontend's `/v1/chat/completions` and `/v1/completions` answer `400 "The model `x` does not exist"` for any `model` other than the served name. The Python handlers accept any name, serve the loaded model and echo the name back, in the response and in every stream chunk. So a client that names the model its own way (for example `"model": "my-chat-model"` against a server whose served name is a checkpoint path) works against the Python server and fails against the Rust one.

What Python does today:

- Chat and completions accept any `model` and echo it.
- The only meaningful form is `base-model:adapter`, which selects that LoRA adapter. With LoRA off, the request is a 400.
- Python checks the model name only in `/v1/models/{model}` (404) and in the Responses API (404). The Rust server already matches the first and has no Responses route, so neither changes here.

## Modifications

- `openai.rs`: a `model_error` helper decides whether a request's `model` can be served. Any name is served, except the `base-model:adapter` form: the Rust server has no LoRA, so it answers 400 with a message naming the adapter instead of silently serving the base model. The served name is always accepted, even when it contains a colon, and an empty adapter (`name:`) is no adapter, as in Python's parsing.
- `chat.rs`, `completions.rs`: replace the equality check against `served_model_name` with `model_error`.
- `test_utils.rs`: drop the two "unknown model" 400 cases, add `answering_app_state` (a core intake that answers every generation with one finished chunk, with the ChatML template so chat can render) and `openai_handlers_serve_any_model_name`, which drives both routes end to end: the served name and another name get 200 and echo the name back, `model:adapter` gets 400 naming the adapter, and the helper's edge cases (`other-model: `, `org/model:v1`, served name with a colon) are pinned directly.

Tests, from `rust/`: `cargo fmt --all -- --check`, `cargo clippy --locked -p sglang-server --all-targets -- -D warnings`, and `cargo test --locked -p sglang-server`. The new test fails on the current code (the second name gets 400) and passes with the change.
