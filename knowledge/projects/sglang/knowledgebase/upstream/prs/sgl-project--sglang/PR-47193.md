# [Perf] [AMD] attention: Switch MLA decode to Aiter on gfx1250

[Upstream PR](https://github.com/sgl-project/sglang/pull/47193) · state: open · merged: False

## Original PR description

### Motivation
On gfx1250, MLA decode runs the Triton kernel. AITER has a faster ASM decode kernel (fp8 Q, fp8 KV). This PR switches decode to it and folds its input preparation into the existing fused RoPE/KV-cache kernel, so no extra kernels are added per layer.

### Changes
- **ASM decode path** (opt-in: `SGLANG_AITER_MLA_GFX1250_ASM=1` with `--decode-attention-backend aiter`)
  - Non-persistent AITER ASM kernel; fp8 KV cache, page size 64.
  - The KV cache uses the page layout the ASM kernel reads. Prefill and prefix reads go through the pool, so other paths are unaffected.
  - CUDA-graph compatible.
- **Fusion**
  - The fused RoPE + concat + KV-cache kernel also writes the ASM page layout and emits the fp8, padded Q the kernel takes directly, removing the separate Q quantization and KV-write pass.

Default behavior (flag off) is unchanged.

### Dependencies
- Stacked on #44458 (paged Gluon MLA decode on gfx1250) and #44459 (fused RoPE/KV-cache write on gfx1250). Please review only the last two commits.
- Requires ROCm/aiter#7133 (paged-layout mode for the fused RoPE/KV-cache kernel).

### Results
Kimi-K2-Thinking MXFP4, 8× gfx1250, TP8, input/output 8192/1024, same server args apart from the decode backend:

| Concurrency | TPOT (ms) Triton → ASM | Total throughput (tok/s) Triton → ASM | TTFT |
|---|---|---|---|
| 4  | 20.56 → 15.98 (**−22%**) | 1680 → 2144 (**+28%**) | −3% |
| 8  | 27.40 → 20.27 (**−26%**) | 2528 → 3362 (**+33%**) | −3% |
| 16 | 37.28 → 27.64 (**−26%**) | 3728 → 4990 (**+34%**) | −4% |
| 32 | 57.52 → 40.36 (**−30%**) | 4838 → 6812 (**+41%**) | −7% |
| 64 | 96.64 → 64.54 (**−33%**) | 5862 → 8728 (**+49%**) | −12% |

GSM8K (1319 questions, 5-shot): Triton 0.934, ASM 0.929.

### Test
- Unit checks: the fused kernel's paged layout is byte-identical to the token-major write, the fp8 Q matches, and CUDA graph capture works.
- End-to-end benchmark and GSM8K above.
