# [Perf] dsv4: Score the V4.1 index logits in bf16 on SM100

[Upstream PR](https://github.com/sgl-project/sglang/pull/45880) · state: closed · merged: True

## Original PR description

- On SM100, the DeepSeek-V4.1 ratio-1/2 index layers now pass bf16 head weights and request bf16 logits from DeepGEMM's `fp8_fp4_mqa_logits` / `fp8_fp4_paged_mqa_logits`, so the kernels reduce in bf16. This is the configuration the reference kernels use on SM100: they take bf16 head weights only and emit bf16 logits there. The sparse candidate path already used bf16 weights and logits.
- The dtype is decided once (`index_logits_dtype()` / `index_weights_dtype()` in `index_logits.py`), resolved on first use so importing the module does not touch CUDA.
- `SGLANG_OPT_DSV41_BF16_INDEX_LOGITS` now defaults to unset: unset means bf16 on SM100 and fp32 elsewhere; setting it keeps working as an explicit override (true: bf16 logits, with bf16 head weights on SM100 only; false: the fp32 path everywhere). Recipes that set it to 1 are unaffected except that SM100 now also passes bf16 head weights.

No change on other architectures (SM90 keeps the torch indexer; SM120 keeps fp32 weights and logits), or anywhere the flag is set to false.

Verification: a dispatch check over SM100 / non-SM100 with the flag unset, true and false gives the expected head-weight and logits dtypes on both the flat and paged calls; on SM100 with no env set the branch resolves to bf16 logits and bf16 head weights at runtime; the existing V4.1 indexer unit tests pass.

- Flat prefill logits tiles are now sized as fp32 logits whatever the logits dtype (`flat_index_logits_rows_per_tile`), as its docstring intended: with bf16 logits the old formula doubled the rows per tile, so the per-row selection scratch that grows with the tile pushed the scoring peak past the fp32 path's budget. fp32 tiling is unchanged. The SM100 prefill indexer tests now score their reference in the indexer's dtypes and accept block or pick differences only where bf16 scores tie at the selection floor; they pass with bf16 (the SM100 default) and with `SGLANG_OPT_DSV41_BF16_INDEX_LOGITS=0`.
