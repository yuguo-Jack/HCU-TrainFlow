# [Feat] [NPU] weight-cache: Add NPU weight cache support

[Upstream PR](https://github.com/sgl-project/sglang/pull/41495) · state: open · merged: False

## Original PR description

## Motivation

Enable the weight cache daemon (`--weight-cache-mode`) on the NPU (Ascend)
backend. Today it is CUDA/ROCm-only: zero-copy weight sharing relies on torch's
`_share_cuda_` IPC handle export, which does not exist on Ascend, so NPU fails
loud with an opaque error. This PR unblocks NPU by moving the transport onto a
backend built on **native torch_npu multiprocessing reduction**, and fixes the
platform fingerprint so a daemon/engine pair running on different Ascend
hardware is correctly rejected as a mismatch (Ascend's reported compute
capability is always `(0, 0)` and cannot distinguish NPU devices).

## Modifications

- **`weight_cache/transport.py`** — add `NpuIpcTransportBackend` (`npu_ipc`) that
  serializes each `tensor.data` with `MultiprocessingSerializer` and reuses the
  existing length-prefixed socket framing (same protocol as `torch_ipc`). On NPU
  the underlying reduction is resolved by torch_npu's natively registered
  `reduce_tensor` / `rebuild_npu_tensor`, so the device index is self-describing
  and no `SGLANG_TP_RANK` is required. `choose_daemon_transport_backend()` /
  `get_client_transport_backend()` route to it when `is_npu()`.
- **`weight_cache/daemon.py`** — allow NPU alongside CUDA/ROCm in `load()`;
  early-return from the CUDA-only `expandable_segments` allocator guard on NPU;
  add `_reserved_memory_bytes()` so preloaded-weight accounting maps to
  `torch.npu.memory_reserved` on Ascend (vs `torch.cuda.memory_reserved`).
- **`weight_cache/protocol.py`** — add a `platform_extra` field to `CacheConfig`
  (part of the struct-equality `matches()` check) and populate it in
  `compute_env_stamp()` for NPU with `device_name`, `device_uuid` and
  `torch_npu.__version__`, covering the `(0, 0)` capability blind spot. CUDA
  keeps it empty and continues to rely on `device_capability`.
- **`weight_cache/ipc_loader.py`** — messages/comments expanded from "CUDA IPC /
  GPU" to the general "zero-copy IPC / device memory" wording; no behavior change.

The transfer is zero-copy by design — the client rebuilds tensors pointing into
the daemon's physical NPU HBM — and safe because plain inference never triggers
`monkey_patch_torch_reductions()`, so `rebuild_npu_tensor` keeps its native
behavior. Functional verification (zero-copy + no `SGLANG_TP_RANK`) is covered
separately by a dedicated NPU test in a follow-up test branch; this PR contains
only the runtime/adaptation changes.

## Accuracy Tests

No model forward / kernel code is changed. This affects only how preloaded
weight tensors are transferred (still byte-identical via zero-copy IPC) and how
the daemon↔engine environment fingerprint is validated. Inference outputs are
therefore unchanged by construction; the fingerprint change is validation-only
and turns previously-accepted hardware mismatches into a clean config mismatch.

## Speed Tests and Profiling

Loading and inference paths are zero-copy; no extra data copies are introduced.
The only added cost is a negligible `is_npu()` branch in `choose_daemon_transport_backend()`,
run once per process at startup. No throughput regression is expected.
