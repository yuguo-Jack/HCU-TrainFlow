# [Feat] lmcache: Decide external KV loads from measured costs

[Upstream PR](https://github.com/sgl-project/sglang/pull/47518) · state: open · merged: False

## Original PR description

## Motivation

Loading cached KV can cost more than recomputing it. Let deployments choose using measured costs.

## Modifications

Add optional `--lmcache-load-cost-profile`. Match the model, parallel size, chunk size, prompt length, common local prefix and actual external hit length. Skip loading only when measured recomputation saves at least the configured margin (default 5%). Unmeasured shapes keep loading.

Add `--lmcache-min-retrieve-tokens` (default 0). Keep rank decisions consistent, release skipped-load locks, and still store recomputed KV. Profiles load once at startup; both options preserve existing behavior by default. PD use requires #47507; includes #47558.

## Accuracy Tests

MI355X / ROCm 10 TP=2 SHM tests passed partial-hit rejection, recompute/store/reuse, unknown-shape loading and salt isolation with exact 8-token outputs. Integrated PD tests passed rejection followed by acceptance after both-server restart, matching 16 baseline tokens. Combined integration a1477798 passed 459 tests and 262 subtests. After merging main at 41f8cbb7cc, CPU regression with the test-only fix #47564 passed 441 tests and 214 subtests on ROCm. Without #47564, its four known Muse Spark subtests fail. Hosted CI is pending.

## Speed Tests and Profiling

At 0c10512e, Qwen3-0.6B TP=1, concurrency 1/output 8, non-lazy 64 GiB L1: 1824 calibration/validation requests passed output and hit checks. Held-out inline mean request time fell from 300.08 to 216.91 ms (27.7%); SHM stayed near 99 ms. Profiles are specific to the measured workload and require recalibration when it changes.
