# [Fix] kernels: Support OOT fused ops under torch.compile

[Upstream PR](https://github.com/sgl-project/sglang/pull/47229) · state: closed · merged: True

## Original PR description

## Motivation

Before this change, out-of-tree (OOT) platform plugins register eager fused-op implementations through
[`BaseFusedOp.register_oot_forward()`](https://github.com/sgl-project/sglang/blob/46caa54562a97e71d9b937c62875c90b39274b0d/python/sglang/kernels/fused_op.py#L375).
[`BaseFusedOp._resolve_forward_method()`](https://github.com/sgl-project/sglang/blob/46caa54562a97e71d9b937c62875c90b39274b0d/python/sglang/kernels/fused_op.py#L539)
selects the function for the active platform and binds it to the operator with
`registered.__get__(self)`. This works eagerly without adding a
`forward_<platform_key>` method to the operator class.


Out-of-tree platform plugins can register eager fused-op implementations without defining platform-specific methods on operator classes. However, model compilation currently has no equivalent registration API.

Eager dispatch also binds registered functions directly to the operator instance. When PyTorch saves compiler guards, it can look up a bound method by name. A registered function may have no matching class attribute, causing serialization to fail.

Provide an explicit OOT compile registration API and store plugin functions in a form that supports both eager execution and compiler guard serialization. Plugins can choose their compile implementation independently while keeping normal PyTorch tracing behavior.


## Modifications

- Add `BaseFusedOp.register_oot_compile_forward(op_cls, fn, platform_key)`.
  Selection uses the exact operator type and active OOT platform, before the
  existing subclass compile-selection method.
- Store registered functions without binding them to the instance.
  `_forward_oot()` and `_forward_oot_compile()`, defined on `BaseFusedOp`, call
  them with the operator instance as `self`. The active and saved forward
  methods can therefore be resolved by name during guard serialization.
- Preserve eager dispatch precedence, rebinding of registered Python methods,
  compile fallback behavior, explicit/forced backend priority, trace labels,
  and repeated enter/leave restoration.
- Trace the registered function's body as part of the enclosing model.
  Unsupported tracing operations still fail with `fullgraph=True`; normal
  graph-break behavior applies with `fullgraph=False`.
- Add test cases using a fake OOT platform and tensor operations,
  including the guard-serialization regression. Document the registration API.

A plugin can register the same function for both modes, or use separate
implementations with the same signature and behavior:

```python
BaseFusedOp.register_oot_forward(Op, eager_forward, platform_key)
BaseFusedOp.register_oot_compile_forward(Op, compile_forward, platform_key)
```
