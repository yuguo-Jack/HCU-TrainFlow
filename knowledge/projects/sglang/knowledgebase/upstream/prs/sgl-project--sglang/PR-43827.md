# [Spec] Bundle DFlash draft KV with Mamba checkpoints

[Upstream PR](https://github.com/sgl-project/sglang/pull/43827) · state: open · merged: False

## Original PR description

## Motivation

On a hybrid SSM target, a cached prefix resumes from a Mamba checkpoint, and a DFLASH draft whose layers all use sliding-window attention resumes with it only if it still has its KV for the window before that checkpoint. Yet the draft keeps one KV slot per target token. On Qwen3.8-27B its pool is 8.58 GB, and most of it holds rows that no cached prefix resumes from.

This PR keeps the draft's KV as bundles instead: each Mamba checkpoint and its draft window are cached, moved between HiCache tiers and evicted together, in a pool sized from the Mamba slots, and the rest goes to the target KV cache. It is opt-in through `SGLANG_DFLASH_DRAFT_KV_BUNDLING`. On 1xH200 with Qwen3.8-27B and the `z-lab/Qwen3.8-27B-DFlash2` draft (sliding window 2048, 8 running requests, auto Mamba slots):

| | Mamba slots | draft pool | target pool |
|---|---|---|---|
| default | 68 | 450,060 tokens, 8.58 GB | 450,060 tokens |
| bundling | 68 | 139,196 tokens, 2.65 GB | 547,205 tokens (+21.6%) |

Depends on #43808, whose commit comes first here; please review the second commit. The draft pool uses the draft-as-SWA allocator from #40665, without its ratio flag.

## Modifications

- The draft's KV pool becomes the SWA side of the target allocator (`DraftSWATokenToKVPoolAllocator`), so the radix tree holds draft KV as its SWA component, and the DFLASH worker writes draft KV through the full-to-SWA mapping.
- `DraftWindowComponent` and `DraftWindowMambaComponent`, selected through `component_registry_override`, count per node the checkpoints on each tier whose window covers it. A checkpoint adds its window when a tier gains it and releases it when the tier loses it, and draft KV that no window covers is freed once unlocked. Inserts split nodes at window starts so each node lies wholly inside or outside a window.
- A device or host draft shortfall evicts Mamba checkpoints through the existing Mamba walk, so a checkpoint and its window leave together. `sglang:draft_bundle_evictions_total` counts these evictions.
- With HiCache, only a checkpoint's window gets a host copy. The host draft pool holds one window per host Mamba slot beside `--hicache-size`, and HiCache auto-sizing prices it that way.
- Mamba slots keep their size. The draft pool holds one window per Mamba slot plus the running requests' draft beyond their windows, capped at one slot per target token, and comes out of the target KV budget.
- Applies to DFLASH with `--speculative-draft-window-size`, an all-sliding-window draft and a hybrid SSM target without sliding-window layers, on CUDA. PD disaggregation, DCP, HiCache storage backends and buffer mode, LMCache, FlexKV, unified memory and custom radix backends keep the per-token pool, and the startup log names the reason.

## Accuracy Tests

`test/registered/spec/dflash/test_dflash_draft_kv_bundling.py` on 1xH200 with Qwen3.8-27B and the `z-lab/Qwen3.8-27B-DFlash2` draft, at page size 64 with HiCache write_back: GSM8K 0.975 with accept length 5.75. A prompt whose bundle was evicted from GPU reloads its window from host and matches a resident hit in text and accept length.

`test_draft_window_bundle.py`, `test_pool_configurator.py` and `test_hicache_auto_size.py`: 74 passed. The unified radix cache suite passes on both tree cores (Python 1,348, Rust 2,948), and `test/registered/unit/mem_cache` adds no failures over main.

## Speed Tests and Profiling

The compute path is unchanged. Window-start splits add radix tree nodes, which makes cache lookups and eviction walks slightly longer.
