# [Perf] [NVIDIA] fused_moe: Add H20 configs for GLM-5.3-Flash TP8/TP4

[Upstream PR](https://github.com/sgl-project/sglang/pull/45089) · state: open · merged: False

## Original PR description

## Motivation

With plain tensor parallelism (`--tp 8` or `--tp 4`, no `--ep`), GLM-5.3-Flash runs its routed experts through the Triton fused MoE. The serving lookups are:

- `E=289` for the target layers, because the shared expert is fused into the routed experts by default.
- `E=288` for the NextN/MTP draft layer, and for any run with `--disable-shared-experts-fusion`.

No config exists for these shapes on any GPU, so on H20 every MoE layer logs `Using default MoE kernel config` and runs with `BLOCK_SIZE_M=64`. #38913 added H20 configs for the EP4/EP8 shapes (`E=72`/`E=36`, `N=2048`). This PR adds the TP shapes.

## Modifications

Four Triton 3.8.0 configs (main pins torch 2.14.1, which ships Triton 3.8.0):

| File | Used by |
| --- | --- |
| `E=289,N=256,device_name=NVIDIA_H20,dtype=fp8_w8a8,block_shape=[128, 128].json` | TP8, target layers |
| `E=288,N=256,device_name=NVIDIA_H20,dtype=fp8_w8a8,block_shape=[128, 128].json` | TP8, MTP draft layer / shared-expert fusion disabled |
| `E=289,N=512,device_name=NVIDIA_H20,dtype=fp8_w8a8,block_shape=[128, 128].json` | TP4, target layers |
| `E=288,N=512,device_name=NVIDIA_H20,dtype=fp8_w8a8,block_shape=[128, 128].json` | TP4, MTP draft layer / shared-expert fusion disabled |

The files were generated with the stock `benchmark/kernels/fused_moe_triton/tuning_fused_moe_triton.py`, using the default search space (1,280 configs after the `BLOCK_SIZE_K` filter) and the default 18 batch sizes. Each batch size was tuned in its own process on one GPU.

To get `E=289`, I applied #43647's one-line `common_utils.py` change locally. That change adds `Glm5NextForConditionalGeneration` to the fused-shared-expert list; without it, the tuner writes only `E=288`. This PR leaves the tuner alone so it does not overlap #43647.

Small batches now use `BLOCK_SIZE_M=16` (M ≤ 512), M=1024 uses 32, and M ≥ 1536 mostly uses 64. The separate down-projection (`_down`, TMA) configs from `tuning_fused_moe_triton_sep.py` are not included. Serving keeps reusing the up config for the down GEMM, as it does today.

## Setup

- 8× NVIDIA H20 96 GB, image `nightly-dev-20261015-a6a8c560`. Its fused-MoE kernel, config loader and tuner files match main `58ad074`. The one difference is that main has since changed the HIP-only `SGLANG_USE_AITER` read in `fused_moe_triton_kernels.py` to go through `envs`.
- torch 2.14.1+cu130, Triton 3.8.0.
- One GPU on this node overheats under sustained load: it runs at 0.7–1.2 GHz and 87–90 °C, while the other seven stay at 1980 MHz and 40–68 °C. The 10 batch sizes first tuned on it were re-tuned on the other GPUs, and 7 of those picks changed. Kernel numbers and TP4 serving numbers below exclude that GPU. TP8 serving had to include it (in both arms), so those runs understate the gain.

## Serving

Both arms use the same image and flags. The default arm runs the image as-is. The tuned arm sets `SGLANG_MOE_CONFIG_DIR` to a directory holding only these four files; its server log shows `Using MoE kernel config from .../triton_3_8_0/E=289,...` (and `E=288,...` for the draft layer). Other settings:

- Triton MoE (auto-selected), BF16 KV cache, default DSA backends, radix cache off.
- `--reasoning-parser glm45 --tool-call-parser glm47`.
- MTP: `--speculative-algorithm EAGLE --speculative-num-steps 5 --speculative-eagle-topk 1 --speculative-num-draft-tokens 6`.
- Load: `sglang.bench_serving --dataset-name random-ids --tokenize-prompt --random-range-ratio 1.0 --request-rate inf --seed 42`, with 4× concurrency prompts (8 at concurrency 1), after one warm-up run per server start.
- Accept length is the server's running average.
