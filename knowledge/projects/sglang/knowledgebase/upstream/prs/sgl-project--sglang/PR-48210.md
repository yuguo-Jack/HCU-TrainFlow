# [Feat] [Intel] sensenova: Run SenseNova-U1.5-8B-MoT on Arc Pro B60

[Upstream PR](https://github.com/sgl-project/sglang/pull/48210) · state: open · merged: False

## Original PR description

## Motivation

SenseNova-U1.5-8B-MoT does not run on Intel Arc Pro B60 (24 GB): its BF16 weights (32.7 GiB) exceed one card and the pipeline is single-device, so loading OOMs. Separately, XPU `RMSNorm` with `cast_x_before_out_mul=True` multiplied the weight before rounding, so ~25 % of outputs differed from HF.

## Modifications

1. `[Feat]` commit 1 — run SenseNova on B60:
   - `sensenova_u1/loader.py`: when the weights exceed 75 % of one device, split the decoder layers over the next visible devices (byte-balanced; masks copied once per device). Unchanged `model.to(device)` when the model fits.
   - `layernorm.py`: XPU `RMSNorm` with `cast_x_before_out_mul` uses the native path, so outputs follow HF rounding.
   - Cookbook: Intel BMG (2 cards) recipe. Tests: split decoder bit-exact vs single device.
2. `[Perf]` commit 2 — fused RMSNorm:
   - New Triton `layernorm/rmsnorm_cast_before_mul.py`: HF rounding order, strided rows (q/k halves from `chunk`), launches on the input's device. `RMSNorm.forward_xpu` uses it for `cast_x_before_out_mul`; all other XPU paths are unchanged.
   - Tests: kernel accuracy, strided rows, cross-device race, XPU default paths still match `sgl_kernel`.
3. `[Perf]` commit 3 — overlap the two CFG branches across the split XPUs:
   - A direct XPU-to-XPU copy waits for both devices' queues and serializes them (measured: two 100 ms streams take 203 ms with one copy in between, 104 ms through pinned host memory). Split transfers now go through pinned host memory ordered by events (`move_to_device`).
   - Each forward ends on the last device (final norm and FM head live there), so the primary starts the other CFG branch while the last device finishes.
   - Removed per-step host syncs: token-kind readback in `Qwen3Model.forward`, patch-position setup in the vision embeddings (cached per grid).
4. `[Perf]` commit 4 — run the existing bit-exact Triton rotate-half RoPE on XPU (gate and device context only).
5. `[Perf]` commit 5 — sgl-kernel-xpu flash attention for unmasked attention on BMG (`set_attn_backend("sdpa")` still forces SDPA).
6. `[Perf]` commit 6 — tensor-parallel decoder (`--num-gpus N --tp-size N`): q/k/v and gate/up split by output, o/down by input with one all-reduce each. Without `--tp-size` the layer split is unchanged. Cookbook B60 recipe moves to TP=2; it needs Gen5 PCIe links (on a Gen2 link a 32 MB all-reduce takes 13 ms instead of 1.9 ms).

Commit 2 recovers the native path's cost and is within 2 % of upstream's `sgl_kernel` while keeping HF rounding. A100 80GB is unchanged: 40.0 s before / 39.8 s after all commits, pixel-identical image.

Profile (torch profiler, per denoise step on B60), commit 1 -> commit 5: RMSNorm 512 -> 51 ms, RoPE 178 -> 49 ms, attention 454 -> 322 ms; device overlap between the two B60s 0 -> 1.8-2.1 s per 4 steps. Remaining: GEMM 1516 ms/step (67.5 %), pipeline bubble (each card ~65 % busy).
