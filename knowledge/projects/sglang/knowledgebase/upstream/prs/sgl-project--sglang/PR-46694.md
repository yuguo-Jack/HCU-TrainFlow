# [Perf] [AMD] minimax: decode indexer CP for DSpark verify on the NVFP4 index cache

[Upstream PR](https://github.com/sgl-project/sglang/pull/46694) · state: open · merged: False

## Original PR description

> Part of the MiniMax-M3.1-Flash AMD series that replaces #45936 (closed with its base branch `minimax-m3.1-flash`): kernel PRs #46690 (attention), #46691 (MoE / GEMM) and #46692 (quick all-reduce), now merged; then #47862 (shared in-tree AITER tuned rows), #46693 with the M3.1 call sites stacked on it, and this PR (indexer CP), stacked on #46693: review the commits after #46693's. It follows the DeepSeek-V4.1 AMD layout (#41018-#41021, then #41308).

## Summary
- Opt-in `SGLANG_MINIMAX_M3_INDEXER_CP=1`: the decode indexer's context partitioning now covers DSpark verify on the NVFP4 index cache. DSpark enables it only under static verify, since ragged verify trims rows per request.
- Each rank scores a quarter of the index-K blocks for all four index heads in one tile; the merge picks exactly what the per-rank selector picks.
- Candidates go straight into the head owner's uncached IPC receive buffer instead of an all-gather. It engages from 12 verify requests, and its buffers are set up only for the NVFP4 index cache, the one that reads them. The base and both CP merge kernels share one block-id selection (`_select_block_ids`).
- The CP partial pass runs one wave of 256 short splits up to 96 requests and two waves of longer splits past that, tuned on MI350X at 8-128 requests and 110K context over index-K pools larger than the MALL.
- Per layer at 64 requests x 110K context: 165.7 -> 84.0 us. AgentX c64 (MI350X, 3600 s, HiCache): 86,995 -> 90,140 tok/s/GPU; on the ROCm 7.2 image with 180 GB write-back HiCache, 84,955 -> 88,962.

## Verification
- MI350X (ROCm 7.2 image, AITER `acf8fdf93`, `SGLANG_USE_AITER=1`), this branch: `test_minimax_indexer_cp` 3 (134 subtests), `test_minimax_indexer_cp_ipc` 2 (4 GPUs: exact against the native selector, and a missing peer traps instead of hanging), CPU `test_minimax_indexer_cp_gate` 2 (9 subtests). pre-commit clean.
- The IPC exchange's per-row call counters wrap at 510 (where tag and parity repeat), and the merge traps after 2^30 polls (about 2.5 minutes) with the row and tag it waited on, under the scheduler watchdog's 300 s.
