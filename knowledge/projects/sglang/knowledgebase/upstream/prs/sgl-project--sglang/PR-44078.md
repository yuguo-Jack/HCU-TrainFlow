# feat(sglang): add image number limitation to prevent OOM (#8540)

[Upstream PR](https://github.com/sgl-project/sglang/pull/44078) · state: closed · merged: False

## Original PR description

## Summary
Fix sgl-project/sglang#8540.

Adds a per-request image-count bound across the multimodal processor
pipeline.  Each 4K image costs roughly 1 GiB GPU memory with the fast
image processor, so unbounded multi-image requests can easily OOM the
serving instance.

### Changes

Three layers of validation to fail fast before any heavy image preprocessing:

1. **Rust ingress prefetch** (`config.py`): the default
   `{"image": 5}` is propagated to the Rust side so early requests can be
   rejected there too.
2. **Python TokenizerManager** (`tokenizer_manager.py`):
   `_validate_mm_limits()` now falls back to
   `BaseMultimodalProcessor.DEFAULT_IMAGE_NUM_LIMITATION = 5` instead of
   skipping validation when no limit is configured.
3. **BaseMultimodalProcessor** (`base_processor.py`): a defensive check in
   `validate_mm_data()` that honours the ServerArg override if set, or the
   class-level constant otherwise.

Operators can tune the bound or disable it:

```bash
# default: 5 images
sglang serve ...

# custom bound
sglang serve ... --limit-mm-data-per-request '{"image": 10}'

# disable all limits
sglang serve ... --limit-mm-data-per-request '{}'
```
