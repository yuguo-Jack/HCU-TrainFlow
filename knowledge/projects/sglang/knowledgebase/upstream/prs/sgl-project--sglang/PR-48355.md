# [Fix] glm47: Let the tool grammar survive templates that ignore enable_thinking

[Upstream PR](https://github.com/sgl-project/sglang/pull/48355) · state: open · merged: False

## Original PR description

## Motivation

Fixes #48336.

GLM-5.3-Flash's chat template ignores the `enable_thinking` kwarg and always ends the rendered prompt with the think-start token (depth is controlled by `reasoning_effort`). The glm47 full-assistant EBNF derived its thinking state from the raw kwarg: with `enable_thinking=False` and `accommodate_chat_template=True`, `generate_glm_grammar` emitted `thinking_block ::= ""` and excluded the think-end token everywhere else. A model already inside the template-opened thinking block could never close it, so **every** request with `tools` + `enable_thinking: false` ran to `max_tokens` with `finish_reason: "length"`, empty `content` and no tool call — even a trivial one. Without tools no grammar is built and the same request is fine; with `enable_thinking: true` or the kwarg omitted, also fine. Clients and gateways commonly send `enable_thinking: false` (the Qwen3-style convention), turning it into a guaranteed runaway generation against this model.

## Modifications

One branch of `generate_glm_grammar` (`glm4_moe_detector.py`): the glm47, `enable_thinking=False`, `accommodate_chat_template=True` case now emits

```ebnf
thinking_block ::= ( thinking_block_content "<think-end>" )?
```

instead of `thinking_block ::= ""`. This is correct for both template styles:

- **templates that honor `enable_thinking`** render no think-start; the optional block is skipped and the model still goes straight to the answer or a tool call — the grammar still allows exactly what it allowed before, minus the trap;
- **templates that ignore the kwarg** (GLM-5.3-Flash) open the thinking block themselves; the model can now close it and proceed normally.

The `thinking=True` shapes are untouched, and the glm45 branch is left unchanged (it has no runtime caller — the only call site hardcodes `chat_template_version="glm47"`).

The trade-off is that `enable_thinking=False` no longer *bans* a thinking block from the grammar; it still means "tell the template not to think", and for templates that honor it nothing changes in practice. Banning the close token, however, is what turned an ignored kwarg into a hang.

## Regression Tests

New `test/registered/unit/function_call/test_glm47_grammar_thinking.py` compiles the generated EBNF with xgrammar and asserts string acceptance:

- the regression case: `"<think-end>391"` is accepted with `enable_thinking=False` (the template already opened the block; the very first generated token may be the close token) — **fails on the pre-fix grammar**;
- `"<think-end><tool-call…>"` likewise accepted — **fails on the pre-fix grammar**;
- direct answer / direct tool call still accepted with `enable_thinking=False` (templates that honor the kwarg keep working);
- `thinking=True` still rejects an answer without a preceding think-end and accepts the closed one; the non-accommodate full-block form still accepts `<think-start>…<think-end>answer`.

Also verified with a minimal tokenizer that the fixed grammar's first-token allow-set contains the think-end token (it was absent before the fix) while the tool-call and plain-text alternatives are unchanged.
