# [Perf] attention: Skip the triton MLA K rescale when k_scale is 1.0

[Upstream PR](https://github.com/sgl-project/sglang/pull/44457) · state: open · merged: False

## Original PR description

## Motivation

For MLA, the triton backend divides K by `k_scale` before writing the KV cache, because `MLATokenToKVPool` takes no scale: a clone plus a divide on extend and an in-place divide on decode. Quark checkpoints create `k_scale` for every layer and leave it at 1.0 when there is no KV scale, so every layer divides by one.

## Modifications

When `k_scale_float == 1.0`, write K directly on both paths. A `None` `k_scale_float` keeps the divide. Non-MLA paths are unchanged.

This touches the same extend block as #42181 (out-of-place divide) without overlapping it; the two are independent.

## Setup

Kimi-K2-Thinking-MXFP4, TP8, MI455X (gfx1250), image `rocm/sgl-dev:v0.5.21-rocm10-mi45x-20261011`; aiter is the image's plus ROCm/aiter#5935, #5501, #5043 and #5402 (all in aiter 2bb549102). The Kimi-K2 cookbook targets MI300X; flags used here beyond it: `--attention-backend aiter --prefill-attention-backend aiter --decode-attention-backend triton --page-size 64 --disable-radix-cache --disable-custom-all-reduce --chunked-prefill-size 8192 --cuda-graph-max-bs-decode 128`, with `SGLANG_USE_AITER=1`, `SGLANG_ROCM_FUSED_DECODE_MLA=0` and `AITER_FORCE_A8W4=1`. Before and after differ only by this PR.

## Accuracy Tests

Numerically identical (division by 1.0). GSM8K with `few_shot_gsm8k` (8-shot, 1319 questions, `max_new_tokens` 512, the settings of sglang's AMD Kimi accuracy tests): before and after to be added.

## Speed Tests and Profiling

Decode at batch 4: the divide was 61 kernels and about 1.2 ms per step; the per-step profile before and after this PR alone is to be added. End to end, TP8 8k/1k concurrency 4: TPOT before and after to be added.
