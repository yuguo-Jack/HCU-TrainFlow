# [Feat] bench: Add `bench_engine_steps.py` for steady prefill and decode step cost

[Upstream PR](https://github.com/sgl-project/sglang/pull/46006) · state: closed · merged: False

## Original PR description

Adds `benchmark/engine_steps/bench_engine_steps.py`: the cost of one prefill or decode step at a fixed, steady batch, against a running server (`--base-url`) or an in-process engine (`--engine` plus server flags).

- **Workload**: each DP rank warms a shared `--context` prefix; every request adds a random, uncached `--new-tokens` suffix and is pinned to its rank. Prefill sends one-token requests at `--tokens-per-step` new tokens per rank per step; decode streams `--batch-per-rank` requests per rank.
- **Metric**: whole steps only. The window starts and ends at step boundaries (the scheduler's stamps under `--enable-metrics`, else arrival gaps), per GPU from the server topology.
- **Guards**: the run fails on a missed prefix or a cached suffix, a dry queue, ranks that ran unequal steps or tokens, EPLB, decode `--stream-interval` other than 1, decode steps too short to separate, or a stall past `--timeout`.
- **Cross-check**: `--server-log` compares the result with the engine's per-step log lines over the same window, on every rank, and fails beyond 0.5%.
- **Profiling**: `--profile-steps` traces a separate, continuously fed burst once every rank has warmed up, and fails if the burst would drain inside the trace.
- `--out` writes a JSON record: workload, result, cross-check, server info, package versions and GPUs.

No runtime change.

## Verification

- DeepSeek-V4.1-Flash, DP attention 4: prefill at 8K and 64K new tokens per rank per step (HTTP and in-process) and decode at 16 requests per rank agree with the engine log within 0.1%.
- `test/registered/unit/bench/test_bench_engine_steps.py` (CPU) covers step windows, log parsing, GPU normalization, guards, timeouts and profiling.
