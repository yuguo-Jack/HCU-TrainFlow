# [CI] [NPU] precise-test: skip recommend-tests-from-coverage when no NPU paths changed

[Upstream PR](https://github.com/sgl-project/sglang/pull/46055) · state: closed · merged: True

## Original PR description

### Problem

`recommend-tests-from-coverage` in `pr-test-npu.yml` only declares `needs: pr-gate` and gates on `!failure() && !cancelled() && ...`. `pr-gate` is deliberately skipped when `check-changes.outputs.changes_exist != 'true'` (the PR touches no NPU paths), and a skipped dependency is neither `failure` nor `cancelled` — so the recommend job still runs: it downloads the coverage baseline (`outputs.tar.gz` + `test_case_map.json`), extracts covstub, runs `test_selector.py` and buckets per suite, while every consumer job is skipped.

Observed in https://github.com/sgl-project/sglang/actions/runs/39955217397 (PR #45857, which only changes `python/pyproject.toml`): `check-changes` reported no NPU changes, `pr-gate` / `base-a-test-npu` / all stage jobs were skipped, yet "Recommend tests from coverage" ran to completion (~93s) and uploaded a report no job consumed.

### Fix

Gate the job with the same predicate as `pr-gate`:

- `needs: [check-changes, pr-gate]`
- add `needs.check-changes.outputs.changes_exist == 'true'` to the `if`

`changes_exist` is `main_package || multimodal_gen`, so multimodal-gen-only PRs keep getting recommendations.

### Verification

- `yaml.safe_load` parses the workflow; the folded `if` evaluates to the intended single expression.
- PR that touches only `python/pyproject.toml` (no NPU paths): recommend job now skips instead of downloading the baseline.
- PR that touches `python/sglang/multimodal_gen/**` only: recommend job still runs (unchanged behaviour).
- `coverage_mode: true` (coverage-collection-npu.yml) path unchanged: job stays skipped.
