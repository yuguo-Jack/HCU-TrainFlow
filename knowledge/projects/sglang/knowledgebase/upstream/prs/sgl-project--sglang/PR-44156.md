# [AMD] GLM-5.2: use custom AR + add-RMSNorm (non-fused) in decode/verify

[Upstream PR](https://github.com/sgl-project/sglang/pull/44156) · state: open · merged: False

## Original PR description

# [AMD] GLM-5.2: use non-fused all-reduce + RMSNorm in decode on MI355X

## What
For `GlmMoeDsaForCausalLM` on HIP (single node, no attention DP), also declare
`disable_aiter_allreduce_fusion_in_decode=True`. Decode/verify then runs custom
all-reduce followed by the fused add-RMSNorm kernel instead of the fused
aiter AR + RMSNorm kernel.

## Why
At TP4 on MI355X the fused 2-stage AR + RMSNorm is ~10% slower than custom AR +
add-RMSNorm at every decode/verify size (16..256 tokens x 6144 hidden). An MTP
verify step issues 158 of them, so AR + norm drops from 5.29 to 4.50 ms per
iteration at M=192.

## E2E
MI355X TP4, GLM-5.2-MXFP4, EAGLE MTP (3 steps, 4 draft tokens), random OSL 1024,
max running 48. Both runs use the breakable prefill graph; only the decode AR path differs.

| ISL | conc | TPOT ms | output tok/s |
|---|---|---|---|
| 1024 | 4 | 4.08 -> 4.05 (-0.7%) | 854 -> 864 (+1.2%) |
| 1024 | 64 | 13.09 -> 12.86 (-1.8%) | 3333 -> 3425 (+2.8%) |
| 8192 | 4 | 4.88 -> 4.83 (-1.0%) | 738 -> 753 (+2.1%) |
| 8192 | 64 | 24.74 -> 24.57 (-0.7%) | 1818 -> 1829 (+0.6%) |

Geomean: TPOT -1.0%, output throughput +1.6%, TTFT -0.9%. gsm8k unchanged (0.93).

## Notes
- With prefill already disabled, this leaves the aiter AR fusion unused for GLM-5.2;
  dropping the `enable_aiter_allreduce_fusion=True` declaration would be equivalent.
- CUDA and other models are untouched.
