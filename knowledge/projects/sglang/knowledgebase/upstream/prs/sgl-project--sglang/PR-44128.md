# feat: piggyback scheduler load report on streaming token output (#11186)

[Upstream PR](https://github.com/sgl-project/sglang/pull/44128) · state: closed · merged: False

## Original PR description

## Summary

Closes #11186

Implements a lightweight piggyback load reporting mechanism where scheduler load metrics are carried through streaming token messages, so the HTTP worker and its clients always see fresh load data without a separate polling round-trip.

Also keeps the watching mode: the HTTP worker caches the latest per-DP-rank load from each streaming chunk, available for external query.

## Architecture

Pure Python changes - no CUDA kernels, no Rust code.

```
Scheduler.process_batch_result
  |
  +-- publish_load_snapshot()         <- already-computed LoadSnapshot
  +-- output_streamer.set_pending_load_snapshot(snapshot)  <- NEW
  |
  v
stream_output -> _stream_output_generation
  |  consume pending snapshot -> PiggybackLoadInfo
  v
to_payload() -> BatchTokenIDOutput.piggyback_load
  |
  v
DetokenizerManager -> BatchStrOutput.piggyback_load
  |
  v
TokenizerManager._handle_batch_output
  +-- cache in _latest_piggyback_loads  (watch mode)
  +-- surface num_running_reqs / num_waiting_reqs / gen_throughput on meta_info
```

## Why cheap

- No extra O(queue) walks: reuses the snapshot already computed by publish_load_snapshot.
- Carried once per batch, not per token.
- Graceful degradation: nothing piggybacks when publish_load_snapshot throttles.
- SHM/ZMQ paths untouched; /v1/loads still uses the SHM reader.
