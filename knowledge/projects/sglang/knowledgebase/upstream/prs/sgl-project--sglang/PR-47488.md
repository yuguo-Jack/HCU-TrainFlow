# [Fix] diffusion: Fail fast on offline runtime failures

[Upstream PR](https://github.com/sgl-project/sglang/pull/47488) · state: closed · merged: True

## Original PR description

## Motivation

Offline `DiffGenerator.generate()` catches scheduler errors, logs them, and continues with later prompts. An illegal memory access or device-side assertion can therefore return `None` or partial results and leave the same failed runtime available for the next call. If a local worker exits before replying, the synchronous client can also wait indefinitely when no RPC timeout is configured.

This complements #45065 by covering the synchronous/offline client side of the failure reported in #38167.

## Modifications

- Raise and latch `DiffusionRuntimeError` for recognized device context/allocator failures and dead local workers. Stop the remaining prompts and reject subsequent requests until the generator is recreated.
- Check owned worker health while polling for a synchronous response. Send each request once and preserve the overall configured RPC deadline.
- Give fatal device errors precedence over earlier recoverable errors in control fan-out. Both synchronous and asynchronous loops stop immediately on a fatal reply, so a later replica cannot hide it with a timeout or an unbounded receive. Successful replies, ordinary errors, and OOM still reach every replica.
- Route explicit client warmup and LoRA operations through the same checked request path, preserving pinned replica routing for per-replica warmup. Close the client's resources and terminate its owned local processes on runtime failure.
- Release resources for prepared video requests that are skipped after an unrecoverable failure. Keep recoverable request errors and OOM handling compatible.
