# [Fix] llguidance: Preserve token state on decode reentry

[Upstream PR](https://github.com/sgl-project/sglang/pull/47781) · state: open · merged: False

## Original PR description

## Motivation

In disaggregated serving, `process_prebuilt` uses `grammar.current_token` to distinguish a fresh transferred request from a retracted request whose last output token has already been accepted. `GuidanceGrammar.accept_token` never updates this field, so llguidance consumes the last token again on PREBUILT reentry and can abort a valid constrained request.

A CPU reproduction uses the real llguidance byte tokenizer and regex `abc`: processing transferred token `a` twice through `process_prebuilt` aborts on the second call because the matcher expects `b`.

## Modifications

- Record `current_token` in `GuidanceGrammar.accept_token`, matching the existing xgrammar/reasoner behavior.
- Add a CPU regression that exercises the actual PREBUILT method twice with a native llguidance matcher, checks that no request abort occurs, and then accepts the remaining valid suffix. It also covers accepting a decoded `b`, appending it to `output_ids`, and reentering PREBUILT before accepting `c`. KV bookkeeping and relay/speculation dependencies are substituted; the matcher and PREBUILT logic are real.
