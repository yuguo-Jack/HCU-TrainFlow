# [Model] Add MiniCPM-V 4.7 support

[Upstream PR](https://github.com/sgl-project/sglang/pull/41993) · state: open · merged: False

## Original PR description

## Motivation

MiniCPM-V 4.7 reuses the 4.6 vision/LLM stack, so most of this PR is about the parts 4.6 cannot express. Both released variants are covered: the 1B dense model and the 35B-A3B MoE.

## Changes

### Canvas 3-D M-RoPE

When a checkpoint sets `mrope_mode = "canvas"`, visual tokens are placed on a per-image slice canvas instead of being given sequential positions. The layout is ported from the reference `mrope_minicpmv4_7.py` shipped with the checkpoints, using sglang's `max + 1 - n` rope-delta convention. Positions flow from the processor through `forward_batch.mrope_positions` into the backbone forward, covering the CUDA-graph and speculative-decode paths.

### 35B-A3B MoE

Its `text_config.model_type` is `qwen3_5_moe_text`, a distinct backbone class. Both the config lookup and the LLM construction branch on it, so the fused `experts.{gate_up_proj,down_proj}` tensors actually load. The sglang config classes win explicitly over the native transformers ones.

### Per-request `mm_processor_kwargs`

`downsample_mode` / `max_slice_nums` can be set per request. Values resolve into a request-scoped media profile, and the vision tower groups patches by their own `use_vit_merger` flag, so batching cannot apply one request's settings to another's patches. The multimodal cache identity keys on pixel content **plus** patch/canvas geometry: two requests whose pixels hash alike but whose slice grids or downsample modes differ never share embedding- or radix-cache state, and each thumbnail/slice span is padded with its own item's pad value.

### Config and dispatch

Config registration, model dispatch and the chat-template hook all key off `model_type` — the 4.7 checkpoints still carry the 4.6-era `version: 4.1`.

### Speculative decoding (DFLASH/DSPARK)

The 4.6/4.7 wrappers expose aux hidden-state capture (`set_dflash_layers_to_capture`) and delegate to the Qwen3.5 backbone, so the released DSpark draft checkpoints serve directly:

```
--speculative-algorithm DSPARK --speculative-draft-model-path <draft checkpoint>
```

### Quantized checkpoints (compressed-tensors FP8 / INT4)

The checkpoints' `quantization_config.ignore` lists name modules in HF (`model.vision_tower.…`, `model.merger.…`) or native-4.7 (`llm.model.…`, `resampler.mlp.N.mlp.0`) style, while sglang's module tree uses `vpm.` / `llm.` / `resampler.…linear_N` names. The ignore names are mapped onto sglang's namespace before scheme resolution, so the vision tower and connector stay unquantized instead of failing to load or silently quantizing the wrong layers.

## Verification

Serve + sgl-eval on 4×GB300, GSM8K full 1319 (temp 1.0 / top-p 0.95):

| Configuration | GSM8K | Stop rate | Image probes |
|---|---|---|---|
| 1B | 84.08% | 100% | 5/5 |
| 1B + DSpark | 83.70% (accept len ≈ 1.3) | 100% | 5/5 |
| 35B-A3B, tp=2 | 96.36% | 100% | 5/5 |
| 35B-A3B FP8, tp=2 | 96.97% | 100% | 5/5 |
| 35B-A3B INT4, tp=1 | 96.97% | 100% | 5/5 |
| 35B-A3B + DSpark, tp=2 | 96.97% (accept len ≈ 1.1–1.3) | 100% | — |

Image probes cover 16x default, per-request 4x override, multi-image, `max_slice_nums=1`, and cross-request isolation (alternating modes on the same image keeps token counts and answers correct). The canvas layout matches the reference port element-wise, fuzz-checked on 19,305 random layouts.

## Notes

- The checkpoints ship remote code, so `--trust-remote-code` is required. 4.7 runs the same GDN hybrid backbone as 4.6 and therefore needs the same `--mamba-radix-cache-strategy extra_buffer` registration.
- The FP8/INT4 checkpoints' bundled remote code (`video_processing_minicpmv4_7.py`) imports `BASE_VIDEO_PROCESSOR_DOCSTRING`, which transformers 5.17 removed; serving those two variants on 5.17 needs a one-line patch in the checkpoint copy (base and dense variants are unaffected).
- INT4: serve with tp=1 — the vision tower is unquantized and W4A16 group-128 divisibility otherwise constrains vision layer partitioning.
