# [Fix] hicache: Include Mamba slot side states in Mooncake storage

[Upstream PR](https://github.com/sgl-project/sglang/pull/48293) · state: open · merged: False

## Original PR description

## Motivation

Fixes https://github.com/sgl-project/sglang/issues/48145.

Qwen3.8-Flash-Next-FP8 can return valid generation results while HiCache backup to Mooncake fails with:

```text
NotImplementedError: Mamba storage zero-copy does not carry registered slot side states; use a whole-page storage backend.
```

The host pool already holds these states, but its storage metadata rejects them, and Mooncake generates object keys only for the temporal and convolution states. This prevents the complete checkpoint from being backed up and restored.

## Modifications

- Return each nonempty slot-state page's pointer and byte size from `MambaPoolHost.get_page_buffer_meta()`, preserving its dtype. Reject incomplete or noncontiguous pages.
- Add matching Mooncake component keys, keeping buffer indices stable when empty states are skipped. Side states then participate in the existing read/write and page-completeness checks, so a missing required state makes the page a cache miss.
- Add CPU regression coverage for state transfer and cache-hit completeness, including mixed dtypes, empty buffers, page sizes 1/2, conv-only pools, and invalid pages.

Existing temporal and convolution object keys are preserved. Checkpoints without the required side-state objects are not treated as complete cache hits.

## Accuracy Tests

Tested against main at [40a64e1b5b](https://github.com/sgl-project/sglang/commit/40a64e1b5ba00c73b7f8a123a903a2123b7d467c).

**CPU regression tests:** the new tests reproduce the exception on the unmodified base. With this change, all 46 tests in the Mooncake CPU test group pass:

```bash
PYTHONPATH=python python -m unittest discover \
  -s test/registered/unit/mem_cache -p 'test_mooncake*.py'
```

**Model-level check:** Qwen3.8-Flash-Next-FP8, TP4/EP4, four NVIDIA RTX PRO 5000 72GB Blackwell GPUs, Mooncake 0.3.13.post1 over eRDMA (`erdma_0`), and FlashInfer 0.7.2.

1. Send a fixed 4,224-token prompt with greedy decoding. The cold request reports zero cached tokens.
2. Keep the independent Mooncake storage process running and restart SGLang.
3. Repeat the request. It restores 4,096 tokens from Mooncake and prefills the remaining 128 tokens:

```json
{
  "cached_tokens": 4096,
  "cached_tokens_details": {
    "device": 0,
    "host": 0,
    "storage": 4096,
    "storage_backend": "MooncakeStore"
  }
}
```

The cold and restored requests produce identical output token IDs. The same write/restart/restore check also passed with the fix applied to SGLang 0.5.22 over TCP at TP8/EP8. These checks cover checkpoint restoration; a full model accuracy evaluation has not been run.
