# [Fix] lfm2-vl: Register the VL architecture in the LFM2 override

[Upstream PR](https://github.com/sgl-project/sglang/pull/33744) · state: open · merged: False

## Original PR description

## Motivation

LFM2-VL does not start on SM100 with default flags. The attention backend resolves to `trtllm_mha`, which sets `page_size=64`. The hybrid ShortConv cache needs `page_size=1`, so the scheduler dies at startup. Reproduced on main at d748bede96:

```
'attention_backend': 'trtllm_mha', 'page_size': 64
...
AssertionError: MambaComponent requires page_size=1 when mamba_extra_buffer is disabled, got 64
```

Text-only LFM2 already resolves to FlashInfer on SM100 through `python/sglang/srt/arg_groups/model_overrides/lfm2.py`. `Lfm2VlForConditionalGeneration` is not registered there.

## Modifications

1. Register `Lfm2VlForConditionalGeneration` in `_lfm2_overrides`. On SM100 with no user-set backend, the language model resolves to `attention_backend=flashinfer` with `page_size=1`. The vision tower keeps the multimodal attention default.
2. `test_lfm2_vl_is_registered` in `test/registered/unit/test_model_overrides.py` resolves the VL architecture through the registry and checks that it gets FlashInfer on SM100 and no override elsewhere. It fails on main.
