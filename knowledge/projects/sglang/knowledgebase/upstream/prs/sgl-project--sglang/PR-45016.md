# [Feat] unified_cache: Support Kimi K3 (FULL + Mamba) on the UMBP direct linker

[Upstream PR](https://github.com/sgl-project/sglang/pull/45016) · state: open · merged: False

## Original PR description

## Motivation

#41343 added Mamba support to the unified-cache direct linker for hybrid SWA + Mamba models on Mooncake. Kimi K3 (MLA + KDA) is FULL + Mamba without SWA and is served on MI355X with the UMBP (mori) backend; the linker supported neither. This PR adds both.

## Modifications

**FULL + Mamba device pool group** (`linker_pool_assembler.py`, `hybrid_pool_assembler.py`)
- `_MambaStrategy.build_direct_linker_pool_group`: the MLA KV entry plus the slot-addressed Mamba entry from #41343. Only a plain `MLATokenToKVPool` is accepted, so MHA, DSA and scaled (FP4) full-attention pools are rejected at startup, as are unified memory, int8 Mamba checkpoints, Mamba side states, `--dcp-size > 1` and draft KV.
- A pool entry can declare the shard it holds. The MLA KV declares shard 0, since it is identical on every attention TP rank; the Mamba state is per rank.

**UMBP** (`umbp_direct_linker.py`, `umbp_store.py`)
- Ranks that declare the same shard share the pool's keys, with the shard in place of the rank, so the store keeps one copy of the MLA KV.
- The store refuses every writer of a shared key but the first, so a refused shared key counts as stored when the store holds it.
- The Mamba object key of a linker entry is chosen by type instead of `getattr` defaults; the keys are unchanged.

## Tests

- `test_linker_pool_assembler.py`: the FULL + Mamba group, its shards and its rejections.
- `test_umbp_direct_linker_rank_keys.py`: the object keys of linker and HiCache pools, the shard in place of the rank, the shared-key write race.

## Accuracy Tests

New `test_unified_cache_linker_kl_kimi_linear_umbp.py` mirrors `test_unified_cache_linker_kl_inkling.py` on Kimi-Linear-48B-A3B (MLA + KDA) at TP4 with a local UMBP standalone server: turn 1 offloads, `/flush_cache` drops the device tree, turn 2 restores from UMBP alone (asserts `cached_tokens_details.host == cached_tokens`) and is replayed against recomputed logprobs. Turn 2 is scored right after the restore boundary, since further out the MLA layers mask a wrong KDA state. ROCm is not bit-exact, so the threshold is 1e-2. Registered in `nightly-amd-8-gpu-mi35x`.

Measured on MI355X, 4 samples:

| Run | avg KL |
|---|---|
| This PR, 6 runs | 1.4e-3, 1.8e-3, 9.5e-4, 8.7e-4, 1.2e-3, 1.4e-3 |
| Negative control: KDA state not restored (slot zeroed) | 4.8e-2, 6.2e-2 (fails) |

Kimi K3 at TP8 on 8x MI355X:
- Teacher-forced restore probe (logprobs over a prefix restored from UMBP after `/flush_cache`, against the device tree's run-to-run noise): passes.
- GSM8K with the few-shot harness of `test_kimi_k3_eval_mi35x.py`, run twice with `/flush_cache` in between so that the second pass resumes from UMBP: 0.956, then 0.954.

## Known limitations

- `--dcp-size > 1` and draft KV (e.g. DSPARK) are rejected on FULL + Mamba models for now.
- Mooncake with the FULL + Mamba group is untested; the shared KV key is UMBP-only.

Related: #41343, #44977. Supersedes #39511.
