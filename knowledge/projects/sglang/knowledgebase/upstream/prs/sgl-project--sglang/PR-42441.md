# [Fix] mem_cache: keep a non-linear NextN layer out of the req-pool mamba layer list

[Upstream PR](https://github.com/sgl-project/sglang/pull/42441) · state: closed · merged: False

## Original PR description

**Closed as superseded (2026-10-15).** Superseded by merged #44098 (`7f0434e4af02`). Current upstream allocates only target KDA layers; the original 34-layer-plus-NextN case now returns 34 layers without draft layer 45. This PR is no longer needed.

Reopened from #39433. GitHub closed that PR on 2 October when the fork it came from was deleted; its review history is still there.

## Motivation

`KVCacheConfigurator._get_mamba_layer_ids_for_req_pool` (from #36507) appends every id in the config's `nextn_layer_ids` to the mamba layer list whenever speculative decoding is on. That is right for a hybrid model whose NextN block is itself a linear-attention layer, but on GLM-5.3-Flash the NextN draft block is a DSA attention layer (the draft model subclasses `DeepseekV3ForCausalLMNextN`, no KDA), so the appended id never indexes mamba state. `MambaPool` and `MambaPoolHost` still size their layer axis from the list, so they carry 35 layers of conv + SSM state for 34 KDA layers.

Reproducible symptom, GLM-5.3-Flash TP4 with `--speculative-algorithm EAGLE` on 4x RTX PRO 6000 Blackwell: the boot log prints `ssm_state size 2.75GB` per rank at 161 slots; with the fix it prints `2.67GB` (34/35), and with `--enable-hierarchical-cache --hicache-size 32` the host Mamba pool goes from 10.98 GB to 10.78 GB for the same 565 checkpoint slots, freeing +26,240 tokens for the KV host tier. 2.9% of the state pool, growing with the slot count.

## Modifications

- New torch-free helper `python/sglang/srt/mem_cache/mamba_layer_ids.py::resolve_req_pool_mamba_layer_ids`: a NextN id is appended only when the config cannot classify the layer (no `is_kda_layer`, the Qwen3-Next style config keeps the unconditional append) or classifies it as linear.
- `KVCacheConfigurator._get_mamba_layer_ids_for_req_pool` calls the helper with the config's `is_kda_layer`. Spec-off and the pipeline `[start, end)` slice are unchanged.
- `test/registered/unit/mem_cache/test_mamba_layer_ids.py` (11 tests, CPU, `base-a-test-cpu`): the GLM shape drops the id, a classifier-less config keeps the append, a classifier that calls the NextN layer linear keeps it, spec-off never appends, the PP slice is unchanged, and the configurator wiring is pinned by AST.

## Accuracy Tests

Rebase validation (2026-10-04, upstream `f2385314b2b3`): the commit is patch-identical to the 2026-10-02 revision and all 11 CPU tests pass. The repo's pre-commit hooks pass on the changed files. The GPU measurements below are historical pre-rebase results; no GPU validation was rerun for this update.

No numerics change: the dropped layer slot was never read or written. Checked on GLM-5.3-Flash TP4, 4x RTX PRO 6000 Blackwell, EAGLE adaptive [3,5]: accept length 3.08 to 3.23 (n=15/15/30) vs 3.09 on the unpatched build (within noise, sd 0.72 to 0.83), decode-log accept rate 0.82 to 0.83 on both, greedy 64-token outputs on 3 prompts within the unpatched build's own non-determinism floor under adaptive MTP, chat and tool-call smoke identical, HiCache restore cells unchanged.

Not a hot path (one list computation at pool construction). The only runtime effect is the smaller state pool.
