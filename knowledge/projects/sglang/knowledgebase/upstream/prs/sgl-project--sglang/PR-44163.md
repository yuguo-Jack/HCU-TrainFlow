# [RL] Restore the flashinfer_trtllm bf16 MoE weight layout in weight-update sessions

> (PR description is generated by AI tool)

## Motivation

`update_weights_from_tensor` on a bf16 MoE served with `--moe-runner-backend flashinfer_trtllm` (the non-routed runner) fails on the first expert copy:

```
RuntimeError: The size of tensor a (64) must match the size of tensor b (256) at non-singleton dimension 2
```

`UnquantizedFusedMoEMethod.process_weights_after_loading` packs `w13_weight` / `w2_weight` into the TRT-LLM block layout (`[E, 2I, H]` -> `[E, H/128, 2I, 128]`) for both `flashinfer_trtllm` and `flashinfer_trtllm_routed`. The only thing that undid it before a hot weight copy was `maybe_restore_flashinfer_trtllm_bf16_weight_shape_for_load` in `FusedMoE._weight_loader_impl`, and that helper is gated on `get_moe_runner_backend().is_flashinfer_trtllm_routed()` (#20214). On the non-routed runner it returns early, so the checkpoint-shaped `[I, H]` shard is copied into a 4-D block slice.

#40777 added the weight-update session (`begin_weight_update` -> `restore_weights_before_loading`, `end_weight_update` -> `postprocess_weights`) as the place where in-place repacks are undone and re-applied, but `UnquantizedFusedMoEMethod` still inherits the no-op `restore_weights_before_loading`, so the session does not restore the trtllm layout on either runner; the routed runner only worked because of the per-tensor helper.

## Modifications

`python/sglang/srt/layers/quantization/unquant.py`:

- Implement `UnquantizedFusedMoEMethod.restore_weights_before_loading`: when `use_flashinfer_trtllm_moe`, reshape `w13_weight` and `w2_weight` back to their load shapes. Shape only, as with the Marlin W4A16 MoE restore: the refit rewrites every expert and `end_weight_update`'s postprocess re-applies the block layout.
- Gate `maybe_restore_flashinfer_trtllm_bf16_weight_shape_for_load` on `self.use_flashinfer_trtllm_moe` (the flag that applied the layout) instead of the routed backend, and share the shape logic with the session hook. The per-tensor path stays for loads that run outside a session (`update_weights_from_disk`, IPC).

`test/registered/unit/layers/quantization/test_unquant_trtllm_bf16_moe_reload.py` (new, mirrors `test_compressed_tensors_wna16_moe_reload.py`; `base-b`, `1-gpu-small`): builds a bf16 `FusedMoE` under each trtllm runner, postprocesses it, then

- `test_session_restores_the_load_shape_and_finalize_repacks`: `begin_weight_update` hands back `[E, 2I, H]` / `[E, H, I]`, `end_weight_update` repacks.
- `test_refit_reproduces_a_fresh_load`: a session refit to a second checkpoint equals a fresh load of that checkpoint bit-for-bit and keeps the parameter `data_ptr`s (captured CUDA graphs keep reading the same buffers).

Neither test launches the trtllm-gen kernel, so they run on any CUDA GPU.

Before the fix (A100-40GB, torch 2.14.1+cu130, flashinfer 0.7.1, main @ 684fea8af3):

