# [CI] rerun-test: Validate suites before dispatch

[Upstream PR](https://github.com/sgl-project/sglang/pull/45007) · state: open · merged: False

## Original PR description

## Motivation

In #44938, `/rerun-test -c` passed for a test registered with `stage="extra-a"` and `runner_config="4-gpu-h100"`, even though `extra-a-test-4-gpu-h100` does not exist. The handler validated the runner and ran the file directly, bypassing `run_suite.py`'s suite validation. After merge, the invalid registration broke suite collection in regular CI and required #45004.

## Modifications

Validate CUDA suite names and explicit CPU `suite=` registrations during rerun resolution, before dispatching the affected file. Read the existing `PER_COMMIT_SUITES`, `NIGHTLY_SUITES`, and `OTHER_SUITES` catalogs with AST parsing, without importing SGLang or executing the catalog file. Invalid registrations produce a comment identifying the file and suite. A file with multiple CUDA registrations is rejected if any registration fails validation.

This also covers `-c`, wildcard selection, and `/rerun-group` through their shared resolution path. Other valid files in a mixed request retain the existing independent dispatch behavior.

Add regression tests and run them through a scoped pre-commit hook so relevant handler, runner configuration, and suite catalog changes exercise this check in lint CI.
