# [Fix] ci: Add pytest entry point for Muse Spark router tests

[Upstream PR](https://github.com/sgl-project/sglang/pull/45843) · state: closed · merged: True

## Original PR description

## Motivation

The registered Muse Spark router test added in #45508 has no executable `__main__` entry point. `collect_tests()` rejects it before suite filtering, so unrelated diffusion suites also abort during test discovery (for example, [the component-accuracy job on #43673](https://github.com/sgl-project/sglang/actions/runs/39799001104/job/119894529572)).

## Modifications

Add `sys.exit(pytest.main([__file__, "-v"]))` behind the `__main__` guard so the file runs its tests and propagates pytest's exit status when executed directly. This changes one test file, with no kernel or model changes.

## Accuracy Tests

- Reproduced the original missing-entry-point `ValueError` on the unmodified file.
- After the fix, the same strict CI collector accepts all **2,472 registered test files / 3,005 registrations** on main at `cc811ff0c3`.
- Verified the entry point forwards pytest exit codes 0, 1 and 5.
- `pre-commit run --files test/registered/kernels/ops/gemm/test_muse_spark_router_gemv_cutedsl.py` passed.

GPU accuracy tests were not rerun: the change only restores the test entry point.

## Speed Tests and Profiling

Not applicable; inference and kernel code are unchanged.
