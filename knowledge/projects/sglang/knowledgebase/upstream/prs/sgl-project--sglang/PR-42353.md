# [Fix] anthropic: Preserve streamed tool arguments across formatting whitespace

[Upstream PR](https://github.com/sgl-project/sglang/pull/42353) · state: open · merged: False

## Original PR description

## Summary

Fixes #42260: formatting whitespace emitted before a tool's final argument fragment closes the Anthropic `tool_use` block early, dropping the remaining JSON. Keep that block open for whitespace-only text chunks.

```text
upstream SSE: tool starts → arguments "{" → text "\n" → arguments "}"
before:       tool starts → arguments "{" → tool stops → final "}" dropped
after:        tool starts → arguments "{" → arguments "}" → tool stops
```

The production change is one condition in the adapter. Existing CPU tests now cover empty inputs, consecutive calls, fragmented arguments, tool IDs, balanced block events, and transitions to real text/reasoning.

### Third-party validation and production reports

- **CUDA/NVFP4/DFLASH backport validation:** [@puncsky's report](https://github.com/sgl-project/sglang/pull/42353#issuecomment-6280230538) reproduces the missing closing brace on DGX Spark GB10 (aarch64), using Qwen3.8-27B-NVFP4 and DFlash2. The experiment backports only this PR's whitespace/tool-block condition from head `03b9976bccfb761039a8dffaf9bc07ed8a851c49` onto a pinned image. In the live DFLASH sample, valid streaming responses improve from **2/3 to 3/3**. Replaying the same 12 captured OpenAI source streams through both actual adapters preserves **22/24 complete decoded tool inputs before, 24/24 after**, including the original tool IDs and order. Both no-speculation streaming cohorts pass 3/3, and both non-streaming cohorts pass 6/6. The linked report contains the pinned inputs, request and validation details.
- **Production confirmation with a separate workaround:** [@hanxiao's report in #42260](https://github.com/sgl-project/sglang/issues/42260#issuecomment-6375164308) describes the same truncation on SGLang v0.5.22 with Qwen3.8-27B AWQ INT4, DFlash2 and `qwen3_coder`. Reported invalid tool inputs are **8/48** for stock Anthropic streaming and **0/48** after their parser-side whitespace workaround; their OpenAI streaming control has 0/24. These results validate their deployed workaround and corroborate the failure mechanism. They do not measure this PR's adapter patch.

These are contributor-reported results. The GB10 experiment validates the single-condition backport, rather than integration of the entire PR tree. Its replay checks decoded JSON, not identical serialization bytes. Live streams in that experiment contain no meaningful text chunks; post-tool text is covered separately by synthetic adapter replay. Neither report establishes general speculative-decoding output equivalence or performance gains.

## Merge Danger

**Door:** two-way

No schema or API change; the condition can be reverted independently.

**Blast Radius:** Anthropic

Scope is the streaming adapter. Whitespace-only text chunks while a tool block is open are treated as formatting and discarded, including a separate whitespace chunk immediately before later real text. Leading whitespace within a non-whitespace text chunk is preserved. Exact post-tool whitespace reconstruction and non-whitespace text interleaved with unfinished tool arguments would require a broader parser/adapter change.

### CUDA/NVFP4/DFLASH validation: real failure and same-stream recovery

I reproduced #42260 on a DGX Spark GB10 (aarch64), with CUDA/NVFP4/DFLASH, and verified the existing PR's one-condition fix against the exact failing source stream.

Pinned inputs:

- PR head inspected: `03b9976bccfb761039a8dffaf9bc07ed8a851c49`.
- Image: `lmsysorg/sglang@sha256:b1259f3ea3275f66237c498ea388919729018bc9f01c3d638391e06e2cf3f469`.
- Qwen3.8-27B-NVFP4 revision `482ca0f3832238542f8f5295dde86b5f22711d80`; DFlash2 revision `015e795645c74b1a0eeef3b570031fb62e769bc5`.
- Context/token pool 8192, concurrency one, static fraction .65, decode graph maximum batch one, `qwen3_coder` tool parser and `qwen3` reasoning parser. Requests disable thinking; DFLASH verifies eight draft tokens. Backend defaults are unchanged.

The experiment backports only this PR's whitespace/tool-block condition onto the pinned image, not the whole latest PR tree. Both variants have identical lossless upstream-SSE instrumentation and read-only source snapshots.

The two independent `read_file` calls request `alpha.txt`, then `beta.txt`. The first call's relevant source deltas are:

```text
arguments: "{"
arguments: "\"path\": \"alpha.txt\""
content:   "\n"
arguments: "}"
```

Base Anthropic output closes the first tool block before the newline text block and drops its final `}`. The captured OpenAI source has both complete inputs; the base Anthropic response has only one decodable call. The non-streaming control returns both complete inputs. Replaying **that same captured source** through the backport produces both complete inputs with their original tool IDs and order, with balanced blocks and correct terminal metadata.

Live matrix (three streamed plus three non-streamed requests per configuration):

| | Base | Backport |
| --- | --- | --- |
| No speculation: valid streaming responses | 3/3 | 3/3 |
| DFLASH: valid streaming responses | 2/3 | 3/3 |
| Valid non-streaming envelopes/schema | 6/6 | 6/6 |

All 12 real captured source streams were additionally replayed through both actual adapters in the pinned CPU container. Base preserves **22/24** complete decoded input objects (10/12 equivalent streams); the backport preserves **24/24** (12/12), including original IDs/order. This is decoded JSON equality, not a claim about identical JSON serialization bytes. Source validity, final OpenAI-to-Anthropic stop-reason mapping, usage and block events are independently reconciled against raw captures.

The three-file DFLASH case emits only `a.txt` in both streaming and non-streaming, for both variants. That is model noncompliance, not adapter truncation or something this patch fixes. The no-spec baseline does not reproduce the adapter defect. Live streams contain no meaningful text chunks; a separate synthetic replay through the actual adapters checks real post-tool text, and 23 CPU tests cover validators, malformed metadata, schema, chunk preservation, delayed readiness and independent guard behavior. Text comparisons require exact non-whitespace characters plus ordered verbatim preservation of each non-whitespace source chunk; reconstruction of standalone whitespace-only chunks is outside scope.

All four workers exit successfully; the one malformed response is a scientific failure in the base cohort, not a worker execution failure. Sampled whole-machine memory peaks range 52.109–60.661 GiB, with at least 61.027 GiB available; no guard fires. No throughput, general inference quality, or exact semantic-equivalence claim about speculative decoding follows from these small correctness probes.
