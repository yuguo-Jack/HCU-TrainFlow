# [CI] [NVIDIA] gb300: Remove the 4-gpu-gb300 CI suite

[Upstream PR](https://github.com/sgl-project/sglang/pull/45698) · state: open · merged: False

## Original PR description

## Motivation
The GB300 nodes are being split into 2-GPU runners, so `4-gpu-gb300` is going away. This builds on #45313 by @mmangkad, rebased on current main after #45294. It also re-homes the remaining 4-GPU work instead of disabling all of it.

## Modifications
**Suite removal** (as in #45313):
- Remove the `4-gpu-gb300` jobs from `pr-test.yml` and `nightly-test-nvidia.yml`, from `scripts/ci/runner_configs.yml`, and from the suite lists in `test/run_suite.py`.
- Keep `base-c-test-aarch64` with only the `2-gpu-gb300` row, and keep it in `pr-test-finish`.

**Re-homed tests and jobs:**

| Item | Change | Why |
|---|---|---|
| `test_disaggregation_aarch64` | Prefill and decode at TP1 on GPUs 0 and 1; registered on `2-gpu-gb300` | The only aarch64 PD test (suggested by @kpham-sgl) |
| `test_numa_utils` | Drop the `4-gpu-gb300` registration | Already runs on `4-gpu-b200` |
| `release-whl-flashmla.yml` (`sm103-aarch64`) | `4-gpu-gb300` → `2-gpu-gb300` | The tests are single-process kernel scripts. @ziyixu, please confirm. |
| `release-whl-deepgemm.yml` (`sm100-aarch64`) | Tests skipped for now | Per @Fridge003, the suite needs changes to fit on 2 GPUs |
| `test_glm52_nvfp4` (TP4 nightly) | Still disabled | Moves to an `8-gpu-b300` nightly once B300 capacity allows. The pool is down to 2 runners and had 4 jobs queued at up to 99 min. |
| `test_cuda_vmm_transport`, `test_mm_transport_{1,2}node_cuda_vmm` | Still disabled | Re-home them or drop them? Open question for review |

## Testing
- `ruff format`, `ruff check` and `isort` pass on the changed files. The one F841 in `test_numa_utils.py` is already on main.
- The changed workflow YAML files parse.
- `test_disaggregation_aarch64` on `2-gpu-gb300`: run linked in a comment.

Supersedes #45313.
