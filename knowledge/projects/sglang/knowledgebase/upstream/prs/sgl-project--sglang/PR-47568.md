# [Perf] [ROCM] diffusion: Encode the MP4 while the VAE decodes on ROCm too

[Upstream PR](https://github.com/sgl-project/sglang/pull/47568) · state: closed · merged: True

## Original PR description

## Motivation

`can_encode_while_decoding` gates streaming on `current_platform.is_cuda()`, so ROCm encodes the whole video after the decode (~0.23 s for H3 at 1280x704x124f). The post-decode path already uses the same `CudaVideoEncoder` on ROCm, and the streamed MP4 is byte-identical to the one-shot one.

## Modifications

Drop the platform gate; the unit test no longer expects ROCm to be excluded.

## Accuracy Tests

Streamed MP4 is byte-identical to the one-shot MP4; md5 equal to main on every prompt checked.

## Speed Tests and Profiling

Setup for all numbers below: 4x MI355X, MiniMax-H3 T2VA, 1280x704 (SemiAnalysis "720p"), 124 frames, 49 forwards, Ulysses 4 + aiter, single stream. Each arm is a fresh server (1 warmup + 3 timed requests), ABAB across two rounds, base = main `75a5da7f`.

720p median -0.16 s.
