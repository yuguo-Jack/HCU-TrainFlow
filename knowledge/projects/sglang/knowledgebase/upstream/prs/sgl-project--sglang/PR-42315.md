# [Fix] function_call: Preserve text before DeepSeek V3.1 streaming tool calls

[Upstream PR](https://github.com/sgl-project/sglang/pull/42315) · state: open · merged: False

## Original PR description

## Motivation

Fixes #42136. DeepSeek V3.1 streaming loses assistant text when a delta contains both text and a tool-call opening marker. For example, `Let me check the weather.\n` disappears when followed by the tool call in the same delta.

## Modifications

Extract the text before the earliest supported opening marker, return it alongside the tool-call deltas, and consume that prefix from the buffer immediately. This preserves whitespace and prevents repeated text while the parser waits for a tool name or arguments. The parsing-error fallback retains the extracted prefix too.

Add CPU-registered regression tests covering an entire call in one delta, text/marker/call boundaries, both supported opening markers, and incremental arguments. They assert both exact text emission and assembled tool name/JSON arguments.

## Test results

Before the fix, the new regressions reproduced lost text: 4 failures (including subtest failures).

No GPU/model serving benchmark: this is a parser correctness fix; no performance improvement is claimed. Split special-token handling and other existing multi-call parser behaviors are outside this change.
