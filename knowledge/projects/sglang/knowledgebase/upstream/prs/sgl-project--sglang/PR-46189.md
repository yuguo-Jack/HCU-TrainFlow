Stacked on https://github.com/sgl-project/sglang/pull/46185 (ReplaySSM for DFLASH and DSPARK). This PR's own changes are two commits: `[Feat] mamba: read packed variable-length rows in causal_conv1d_update` and `[Feat] gdn: run target verify on packed ragged tokens (ReplaySSM)`. The three `mamba` conv-tile commits on the branch are rebased copies of https://github.com/sgl-project/sglang/pull/46184 (the packed conv builds on its tile store) and drop out once https://github.com/sgl-project/sglang/pull/46184 merges.

## Problem

Compact verify (`SGLANG_RAGGED_VERIFY_MODE=compact`) packs a variable number of verify tokens per request. GDN target verify reads the packed tokens as a dense `[batch, draft tokens]` window from the conv on. So compact verify is refused on GDN models (Qwen3.5/3.6/3.8), and they always verify the full draft block. Eager compact verify on a GDN target was also reported to hit an illegal memory access (sgl-project/sglang#35413).

## Fix

With `--enable-linear-replayssm-spec` and compact verify, every GDN target verify reads its packed tokens in place. Nothing is copied into a dense window.

- `causal_conv1d_update` takes optional `query_start_loc` and `max_seqlen`. With them, x and out are packed `[num_tokens, dim]`.
  - Each sequence updates the conv state and the intermediate windows (per-token or the deduplicated tile) exactly like a dense row zero-padded to `max_seqlen`.
  - Output is written only for the sequence's own rows.
  - A sequence with no rows exits at entry, even when it has a state slot. Rows past the last sequence are never touched.
  - The dense path is unchanged.
- `GDNAttnBackend` decides once, at startup, whether target verify is packed. The decision does not depend on the batch, so a CUDA graph captured with one layout (uniform included) replays any other. A uniform layout gives the dense result bit for bit.
- The packed conv output goes to the ReplaySSM spec verify, which already reads rows by `query_start_loc`.
- GDN reports ragged-verify graph support only for this path.
  - The snapshot verify (FlashInfer MTP, Triton recurrent) stays dense.
  - The startup refusal of compact verify now names `--enable-linear-replayssm-spec`. Cap-accept stays allowed, since it verifies the dense window.
- The ReplaySSM spec check is computed once in the backend constructor; the backend computed it in two places.
- CUDA-graph safety: the ReplaySSM verify zeros packed rows past the last request (token-tier leftovers), so every output row is finite. Padding rows (mamba slot -1, or no tokens) were already zeroed or skipped.
  - Static verify outputs for real rows are unchanged.
  - Output rows of padding slots in padded dense graphs are now zero instead of left unwritten.
- The ragged ReplaySSM startup check requires a ring-writing verify backend on KDA models only. The GDN ReplaySSM verify writes the ring under every verify backend, including the SM100 default, flashinfer.

The packed conv layout and the empty-row exit follow SubSir's packed verify conv. The deduplicated tile store it extends is also SubSir's work.

On this PR alone, compact layouts come from DSPARK, which is covered by unit tests here. DFLASH produces them once https://github.com/sgl-project/sglang/pull/46190 lands; the serving numbers below were measured with that change applied.

## Effect

- A ragged verify step matches the dense step of the same real tokens bit for bit: outputs, ring records, committed state and conv state. This holds in eager mode and in CUDA-graph replay (graphs captured with a ragged or a uniform layout), for:
  - padded rows;
  - zero-length rows;
  - uncovered tier leftovers;
  - an extended last row.
- Kernel time on GB300 at Qwen3.8-27B TP1 shapes (bf16, T=8, bs 128):
  - conv: 17.4 us dense, 18.1 us packed with every row full, 17.0 us packed with mixed lengths;
  - ReplaySSM verify: 105.9 us, unchanged (105.8 us before).

### Serving

Setup:
- Qwen3.8-27B with DFLASH (DFlash2 block 8), bf16 mamba state, SPEED-Bench first turns, GB300; `--max-running-requests` 128 at TP1 and 512 at TP4.
- Measured on a tree that also contains the DFLASH compact-verify change.
- Compact uses an offline cost table profiled on an older build of the same stack, not on this tree.

Decode tok/s = per-request decode rate (output tokens after the first / time after the first token), times concurrency; c1 is the single-request decode rate.

| config | c1 | c4 | c8 | c16 | c64 | c128 |
|---|---|---|---|---|---|---|
| TP1 T=1 static | 319 | 1207 | 2168 | 3775 | 7180 | 8320 |
| TP1 T=1 compact | 320 | 1198 | 2120 | 3631 | 7198 | 9223 |
| TP1 T=0 static | 362 | 1355 | 2489 | 4188 | 8181 | 9518 |
| TP1 T=0 compact | 350 | 1306 | 2334 | 3989 | 8103 | 10527 |

TP1 T=1 c64 is the mean of 2 runs per mode and c128 the mean of 3 (static 8307-8334, compact 9047-9387); every other cell is one run.

| TP4 T=1 (cap 512) | c64 | c256 | c512 |
|---|---|---|---|
| static | 13122 | 16970 | 19478 |
| compact | 12117 | 18159 | 22381 |

A paired rerun on this PR's own final commits, before https://github.com/sgl-project/sglang/pull/46185's fused multiply-add fix and the last conv-tile commit (TP1, T=1, both servers at the same time):

| level | static | compact | change |
|---|---|---|---|
| c8 | 2259 | 2071 | -8.4% |
| c128 | 8246 | 9380 | +13.8% |

- Compact gains +11 to +15% at full load: +10.9% (T=1) and +10.6% (T=0) at TP1 c128, +13.8% in the paired rerun, +14.9% at TP4 c512. At these levels the running cap equals the concurrency; https://github.com/sgl-project/sglang/pull/46182 shows that this setup reads 7-15% higher than a larger cap, slightly more for compact, so compare them only within these tables.
- Acceptance per verify step drops at high load, because compact trims verify lengths. At TP1 T=1 c128 the accepted length is 3.18-3.22 vs 3.58-3.60; at TP4 c512 it is 3.13 vs 3.58. At c16 and below it matches static.
- Below full load, compact can be slower:
  - up to 4% at TP1 T=1 c4-c16 (even at c1 and c64);
  - 1-6% at TP1 T=0 c1-c64, most at c8;
  - 8% at TP4 c64;
  - 8% at c8 in the paired rerun.

  One known part of the gap is GDN's: ragged graphs capture min(tokens, max_bs) slots, so padding slots launch CTAs too. With 8 requests in 64 slots, that is 7.8 us of ReplaySSM verify and 2.3 us of conv per layer, about 0.5 ms per step over 48 layers.

  Follow-up: a persistent row loop in the verify and conv kernels that stops at the real row count, or fewer capture slots at low token tiers.

## Tests

- `test/registered/layers/mamba/test_causal_conv1d_update_varlen.py`: packed vs zero-padded dense, bitwise.
  - 7 layouts, including zero-length rows with and without a state slot.
  - Both window layouts, bf16 and fp32, T in {2, 4, 8, 16}.
  - CUDA-graph replay vs eager.
- `test/registered/attention/unittests/gdn/test_gdn_replayssm_direct_commit.py`:
  - ragged vs dense through `GDNAttnBackend.forward_extend` and the backend commit, for 5 layouts in bf16 and fp32;
  - ragged CUDA-graph replay vs eager, with ragged and uniform capture.
- `test/registered/unit/spec/test_gdn_replayssm_dflash_commit.py`: the startup refusal, and the hook rule for GDN/KDA × verify backend, including flashinfer.
- compute-sanitizer memcheck, initcheck and racecheck on the new tests: no memory errors, no uninitialized reads, no hazards.
- End to end on Qwen3.8-27B: compact verify serves at TP1 and TP4 with CUDA graphs, and at TP1 in eager mode, with no errors.
- Existing GDN, mamba and spec unit tests pass. Two `test_gdn_replayssm_spec_fold` cases fail on GB300 the same way on the base branch.

## Related upstream work

- **sgl-project/sglang#38897 (same feature, different design).** It also runs GDN target verify on packed ragged tokens: a packed variable-length conv, GDN ragged-graph support and ragged ReplaySSM verify, plus planner and mRoPE fixes that overlap https://github.com/sgl-project/sglang/pull/46190. How this PR differs:
  - Conv: it adds a second kernel, `causal_conv1d_update_varlen`, which writes the intermediate window per token, and keeps a dense scratch with index copies for non-CUDA and tree verify. This PR adds packed rows to the existing `causal_conv1d_update`, so packed rows also get the deduplicated tile store of https://github.com/sgl-project/sglang/pull/46184, and one kernel serves both layouts.
  - Scope: it declares ragged-graph support for every GDN verify path, including the snapshot verify, and does not change the FlashInfer GDN verify kernel, which views the tokens as `[bs, seq_len // bs]`. This PR declares it only under `--enable-linear-replayssm-spec`, where the verify reads rows by `query_start_loc`, and keeps compact refused for the snapshot verify.
  - ReplaySSM: its ReplaySSM change is in the fold-every-commit verify, whose ring current main allocates only for KDA. This PR uses the GDN circular-ring verify and zeroes token-tier leftovers so CUDA-graph replays stay finite.
  - It also changes KDA verify; this PR does not touch KDA.

  What to do: the two are alternatives, so one should land. If sgl-project/sglang#38897 lands first, what remains of this PR is restricting GDN ragged-graph support to the verify paths that read packed rows, the tail zeroing, and the tile store for its varlen kernel.
- **sgl-project/sglang#35725**: its latest head also declares GDN ragged-graph support, scatters packed conv input to a dense window and sends ragged batches to the Triton varlen verify. Same overlap as above.
- **sgl-project/sglang#42688** changes the ReplaySSM compact commit masking (see https://github.com/sgl-project/sglang/pull/46185); no overlap with this PR's own commits.
- **sgl-project/sglang#35413** reported the eager compact illegal memory access on GDN. Its startup cost-table derivation skips GDN targets because GDN does not declare ragged-graph support; with this PR that check passes under ReplaySSM.
