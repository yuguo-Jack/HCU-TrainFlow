# [KDA] Speed up the ReplaySSM fold with narrower tiles and input prefetch

[Upstream PR](https://github.com/sgl-project/sglang/pull/44024) · state: open · merged: False

## Original PR description

## Summary
Speeds up `kda_replayssm_exact_fold_kernel`, the `--enable-linear-replayssm-spec` commit that replays each request's accepted draft tokens into its fp32 KDA state.

- V tile `BV` 32 -> 8 (`KDA_FOLD_BLOCK_V`, tuned on GB300), keeping full-K rows and `num_warps=1`.
- The next accepted token's ring entries (k, v, gate, beta) are loaded while the current token is folded.

## Results
All-layer fold on GB300, K=V=128, fp32 state, bf16 k/v ring. Shapes per GPU: GLM-5.3-Flash TP4 (34 KDA layers, 16 heads) and Kimi-K3 TP8 (69 KDA layers, 12 heads). L2 flushed before every call; median of interleaved main/PR runs.

## Correctness
Folded state is bit-identical to main for both shape sets at batch 1/2/16/32/64/128 with 1/3/6/8 accepted tokens, mixed per-request accept lengths (0-8), and the `extra_buffer` track snapshot. `test_kda_replayssm_ring_fused.py` and `test_kda_replayssm_fold_batched.py` pass.
