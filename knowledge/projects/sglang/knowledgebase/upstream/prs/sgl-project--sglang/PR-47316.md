# [Feat] [AMD] runtime: Add a master switch for monokernel runtime optimizations

[Upstream PR](https://github.com/sgl-project/sglang/pull/47316) · state: open · merged: False

## Original PR description

## Motivation

#47105 put the runtime optimizations that accompany NVIDIA megakernels behind one switch. The AMD monokernels (sgl-project/sgl-amd-mono, `--enable-amd-monokernel`) need several of the same DeepSeek-V4.1 DSpark optimizations, plus ROCm-specific ones; their recipe lists each variable by hand. Without a switch, the ROCm-specific ones would change ROCm's default path.

This PR adds the AMD switch and one optimization under it. Two follow-ups add theirs under the same switch: #47317 (ROCm sampling verify) and #47318 (DSpark draft and accept launches).

## Modifications

- **`SGLANG_ENABLE_AMD_MONO_RUNTIME_OPTIMIZATION`** (default off), with #47105's semantics: unset children follow it, explicitly set children win (including `0`), and it does not enable the monokernels themselves.
- **Children that follow either master switch.** Six DeepSeek-V4.1 DSpark children that we validated with the AMD monokernels now default on with either the NVIDIA or the AMD switch:
  - `SGLANG_OPT_DSV41_DSPARK_PREPARE_INPUTS_ONCE`
  - `SGLANG_OPT_DSV41_DSPARK_MID_FOLD`
  - `SGLANG_OPT_DSV41_DSPARK_POST_FOLD`
  - `SGLANG_OPT_DSV41_DSPARK_SKIP_PREFILLED_INPUTS`
  - `SGLANG_OPT_DSV41_TARGET_VERIFY_METADATA_GLUE`
  - `SGLANG_OPT_DSV41_TARGET_METADATA_EARLY`

  The other NVIDIA children are unchanged. The sampling-accept graph, for example, is not validated on ROCm.
- **Verify graph without the folded epilogue on sampling steps** (`SGLANG_OPT_DSV41_DSPARK_NOTAIL_VERIFY_GRAPH`, AMD child). The folded greedy epilogue is captured into every target-verify graph, so a step that does not take the in-graph accept (sampling, grammar) still runs it, disarmed: ~21 kernels, ~110 us a step at TP8.
  - A model runner's optional capture-tail hooks now make each decode graph also be captured without them ("notail"), and a step replays that variant unless it wants the hooks.
  - With the child on, the DSpark worker registers its verify epilogue there.
  - With it off, the epilogue stays a plain tail hook, nothing is captured twice, and the runner's new code paths are inert.

With both switches off, every default and every code path is main's.

## Accuracy Tests

- `test/registered/unit/test_environ.py`: master scope, explicit child overrides and explicit `None`, now for both switches. Mutation-checked: a child that stops following the AMD switch fails 4 cases.
- GSM8K, 8-shot, 1319 questions, DeepSeek-V4.1-Flash TP8 with sgl-amd-mono (sgl-project/sgl-amd-mono#82), this PR and the two follow-ups, switch on: 0.917.
