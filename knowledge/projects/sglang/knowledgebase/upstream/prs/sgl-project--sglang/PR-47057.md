# [Feat] radix-cache: Bundle SWA KV windows with Mamba checkpoints

[Upstream PR](https://github.com/sgl-project/sglang/pull/47057) · state: open · merged: False

## Original PR description

## Motivation

In a unified radix tree with SWA and Mamba components, a cached prefix resumes from a Mamba checkpoint and only needs the SWA KV in the window before it. But the two components evict independently, so SWA eviction can drop a checkpoint's window and make the checkpoint unusable, while SWA KV that no checkpoint needs stays cached.

This PR adds an opt-in `CacheInitParams.swa_checkpoint_windows` policy that only keeps SWA KV in the window before each cached Mamba checkpoint, and evicts each window with its checkpoint. #47058 builds on it to size DFlash draft KV by Mamba checkpoints.

## Modifications

- Each node counts how many cached checkpoints have it in their window, on device and on host. A checkpoint adds its window when it's stored or loaded onto a tier and removes it through a new `on_peer_value_freed` hook, which the tree core calls whenever it evicts a value, so every path that frees a checkpoint also frees its window.
- `store_checkpoint` splits the node where a new checkpoint's window starts, so no node straddles a window's start.
- SWA eviction frees KV outside every window first. If that isn't enough, `evict_for_alloc` evicts Mamba checkpoints with their windows, like its existing Mamba/Full donor fallback, and a new `sglang:swa_checkpoint_evictions_total` metric counts these.
- With HiCache, only checkpoint windows get a host copy, and host eviction frees host SWA outside every window before whole host checkpoints. Under write-through, a window's host backup can stop at a node whose own backup is still in flight, so for now the nodes it missed keep their device SWA, with a TODO to back them up once that backup lands.
- Both tree cores implement this as a mode of the SWA and Mamba components, with the window logic in `components/checkpoint_window.py` and `.rs`.
- Startup fails if the policy is combined with storage backends, buffer mode, the external cache linker, the session radix cache, unified memory, or a radix cache other than `UnifiedRadixCache`.

## Accuracy Tests

`test_unified_radix_cache_checkpoint_window.py` adds 9 cases at page sizes 1 and 4 on both tree cores, covering shared windows, eviction order, write-back and write-through restores, host eviction, finished requests, and a randomized invariant check.

The unified radix cache suites pass on both tree cores on an L4 (Python 1,734, Rust 1,260), and so does the Rust crate (942).

## Speed Tests and Profiling

With the policy on, splitting nodes at window starts adds radix tree nodes.
