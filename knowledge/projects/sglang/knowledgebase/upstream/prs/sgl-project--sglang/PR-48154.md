# [Perf] [AMD] mla: Use the gfx950 aiter RoPE, RMSNorm and MLA KV-row paths on gfx1250

[Upstream PR](https://github.com/sgl-project/sglang/pull/48154) · state: open · merged: False

## Original PR description

## Motivation

On gfx1250, MLA prefill runs three small ops on different paths from gfx950: `DeepseekScalingRotaryEmbedding` runs `forward_native` (about nine torch kernels), RMSNorm uses a gfx1250-only Triton branch, and the MLA KV rows go through `index_put`. aiter's cached-positions RoPE kernel and `rmsnorm2d_fwd` build and run on gfx1250 with the current gfx1250 aiter pin; the RMSNorm row-tail fix for N % 8 != 0 is ROCm/aiter#6348, which the pin includes. This PR extends the gfx950 paths for these three ops to gfx1250.

## Modifications

- `DeepseekScalingRotaryEmbedding`: on gfx1250 with `SGLANG_USE_AITER=1`, call `aiter.rope_cached_positions_2c_fwd_inplace` in place. The module stays sglang's because ROCm MLA decode paths read `cos_sin_cache`, which aiter's rope modules do not have. The kernel reads cos/sin without strides, so it gets contiguous query-dtype copies of the module's own `cos_sin_cache`, built on first use and rebuilt when the cache or the query dtype changes. `forward_native` is kept for calls with `offsets` and when `rl_on_policy_target` forces native rope. A key passed as its own query (the `IndexerKPool` K-only path) is rotated once, since the kernel loads both inputs before storing.
- RMSNorm: drop the gfx1250 Triton branch and use aiter `rmsnorm2d_fwd` / `rmsnorm2d_fwd_with_add`, as on other ROCm targets. This applies to every model on gfx1250 with `SGLANG_USE_AITER=1`, in prefill and decode.
- MLA KV rows: use `store_mla` / `read_mla` on gfx1250, as on gfx950.
- Update the rope factory and DeepSeek utils comments that said aiter rope does not build on gfx1250.
- Add a gfx1250-only test in `test/registered/rotary/test_rope_rocm.py` that compares the aiter RoPE path with `forward_native` (neox and GPT-J styles, strided q_pe/k_pe views shaped like the MLA callers, in-place output, cache growth, dtype change, a key passed as its own query, and the `forward_native` fallbacks).

gfx950 is unchanged. On gfx1250, RoPE now runs in place with query-dtype cos/sin, the same as the aiter rope module on gfx950. MLA decode RoPE on gfx1250 also moves to this kernel, except where #44459 fuses it into the decode kernel; the measurements below were taken with #44458 and #44459 applied, so this PR should land after #44459.

Validated on gfx1250 with Kimi-K2-Thinking-MXFP4 at TP8.
