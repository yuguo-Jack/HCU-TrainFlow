# [Fix] conversation: Open the first user turn with [INST] after a Mistral system prompt

[Upstream PR](https://github.com/sgl-project/sglang/pull/46284) · state: open · merged: False

## Original PR description

## Motivation

With a system message, the built-in `mistral` and `devstral` chat templates never open the first user turn. Their `system_template` ends after `[/SYSTEM_PROMPT]\n\n`, while the `LLAMA2` renderer emits the first message without a tag, relying on the system template (or the `"[INST] "` fallback) to open it, as `llama-2`'s system template does with its leading `[INST] `. A system + user request therefore renders as

```
[SYSTEM_PROMPT]\nBe brief.\n[/SYSTEM_PROMPT]\n\nU0 [/INST]
```

with a closing `[/INST]` but no opening `[INST]`. For comparison, Mistral-Small-3.1-24B-Instruct-2503's official chat template renders the same request as `<s>[SYSTEM_PROMPT]Be brief.[/SYSTEM_PROMPT][INST]U0[/INST]`.

`devstral` hits this on every request whenever the model is in the local HF cache, because its template loads the bundled `SYSTEM_PROMPT.txt` as the default system message.

## Modifications

- Append `"[INST] "` to the `system_template` of `mistral` and `devstral`. The example above now renders as `[SYSTEM_PROMPT]\nBe brief.\n[/SYSTEM_PROMPT]\n\n[INST] U0 [/INST]`.
- Requests without a system message are unchanged (they already use the `"[INST] "` fallback), and `llama-2` is untouched.
- Adds a regression test for both templates that fails on current main and passes with this change.

## Design notes

**Why fix the template instead of the renderer?** The `LLAMA2` renderer's contract is that the prefix (system prompt or fallback) opens the first user turn; `llama-2` already follows it. Changing only the two templates that break the contract keeps every other template's output identical.

**Why keep the existing spacing and `\n\n`?** SGLang's built-in templates already differ from the official ones in whitespace (`[INST] U0 [/INST]` vs `[INST]U0[/INST]`). Matching Mistral's exact spacing would change every existing prompt for these templates, so this PR only adds the missing tag.

**Related:** #46283 fixes a different `LLAMA2`-style bug (non-alternating roles) in the same file. The two PRs touch different lines and are independent.
