## Motivation

Unified memory reclaimed through a stack of per-shape protocols (a FULL cache donor for state slots, per-shape reclaim plans, the prefix tree's per-component targets), and capacity reads used per-band views and the sizing's static per-side split. Both disagreed with what a take could actually serve: capacity reads missed room that compacting an end or moving a float opens, could report free state ids no layout could place, and a decode preallocation could pass separate state and token checks and still fail its take.

## Modifications

- One victim loop (`mem_cache/kv/alloc/chain.py`, `unified_radix_cache.py`): if the demand fits (relayout allowed), take it; if it would not fit even with every evictable entry evicted, evict nothing; otherwise evict victims in the cache's order one at a time, checking the fit after each and stopping at the first fit. Admission credits the same evictable entries (`admits`). The donor protocol and the per-shape reclaim plans are removed.
- Decode preallocation prices a request's pending state slots together with its tokens in one question (`disaggregation/decode.py`, `allocator/{base,swa,hisparse}.py`).
- Capacity reads (`chain.py`, `kv/storage.py`, `unified_memory_pool.py`, `managers/scheduler_components/pool_stats_observer.py`): a sub-pool's availability is the largest demand of that sub-pool alone a take can serve now; the token read is the largest demand the owner and every window can take together. Sub-pools share bytes, so availabilities do not add up.
- The per-shape capacity policies, pricing functions, credited reservation check and float movers are removed (`kv/alloc/interim.py`, `pricing.py`, `band.py`); a float moves only by `relocate_into`. A relief first lays the chain out with rows under unfinished network transfers held in place; only when no such layout serves the demand does it fall back and wait on the host for those transfers. Bands' neighbour-credit capacity read is removed.
- Tests: `test/registered/unit/mem_cache/test_unified_reclaim_victim_loop.py`, `test_unified_move_destinations.py`, `test_unified_state_usage.py`, plus planner-question rewrites of the pricing, tri-pool, joint-reclaim and HiCache tests; `test_unified_dynamic_gate_capacity.py` is removed with the policy it tested.

**Observable change (unified memory only):** reported available sizes and usage come from the layout planner, so they can be larger than before (room a rearrangement opens) and per-sub-pool availabilities overlap. State usage is reported as 0 when no state slot is held and other sub-pools hold the bytes.
