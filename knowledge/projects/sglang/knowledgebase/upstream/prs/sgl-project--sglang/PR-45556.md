# [Feat] disagg: Admit the DeepSeek-V4 paged KV layout in the PD decode radix cache

[Upstream PR](https://github.com/sgl-project/sglang/pull/45556) · state: open · merged: False

## Original PR description

Stacked on #46395 (write PD decode KV to the linker). Review only the top commit.

## Motivation

On CUDA, the PD decode radix cache rejects DeepSeek-V4 unless it runs the unified KV layout, so DeepSeek-V4.1 on the default paged layout cannot reuse decode-side prefixes or write its decode KV to the external store.

## Modifications

- `validate_decode_radix_cache`: admit the DeepSeek-V4 paged KV layout. Prefix-hit transfers (suffix pages plus whole request state) already go through the generic hybrid-SWA path.

## Tests

- `test_decode_radix_cache_validation.py` now admits the paged layout.
- New e2e `test_disaggregation_decode_radix_linker_dsv41.py`: the cookbook disagg recipe scaled to 1P1D (DEP2 each, DSpark, megamoe), Mooncake store, decode radix cache, and the linker on both roles. Across four turns, with both device caches flushed between turns, prefill `cached_tokens` covers the previous turn's prompt and output. It fails with the decode radix cache off (1280 < 2048).
- sgl-eval gsm8k, 200 examples, model preset, two passes: 0.965 / 0.975 on GB300, 0.97 / 0.96 on B300.

## Known limits

- The decode tree inserts at request finish, so SWA rows exist only near each node tail. When a follow-up adds fewer than 256 tokens, prefill bounded replay re-prefills past the last decode page, and the hit falls back to the prompt boundary.
- Decode-local prefix reuse with DP attention still needs prefix-aware DP routing.
