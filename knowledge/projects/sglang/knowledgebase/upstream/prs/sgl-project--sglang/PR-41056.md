## Motivation

Enable the existing `--disaggregation-enable-kv-checksum` diagnostic on Ascend NPU for prefill/decode disaggregation. Prefill and decode currently construct the checksum computer with a CUDA device and use the CUDA checksum kernel.

This PR adds an NPU implementation with the same ordered raw-byte Adler-32 semantics and fixes the early-send dependency in the shared Ascend/Mooncake transfer path.

## Modifications

- Add a Triton-Ascend Adler-32 implementation for strided transfer descriptors. Bytes are processed on the NPU; only reduced checksum data is copied to the host. Reuse `_MOD_ADLER` as a kernel constexpr.
- Construct the prefill/decode checksum computer using the KV pool's actual device and dispatch to the NPU or existing CUDA implementation.
- Validate descriptor devices, shapes, dtypes and lengths. Ordinary paged KV uses its page indices. Additional state descriptors currently share one state-index vector; on NPU, only homogeneous Mamba or SWA state types are accepted. DSA and other/heterogeneous state types are rejected until their index mappings are handled explicitly.
- Carry the existing early-send completion event from `MooncakeKVSender` into `TransferKVChunk`. The transfer worker waits on that event before staging or reading source KV memory, then clears it. Skipped sends discard the event, and failed requests bypass the wait.
- Keep early-send and overlap enabled. The new event wait runs in the transfer worker; no device-wide synchronization is added.
- Add independent zlib-oracle kernel tests, sender/worker event regressions, and Ascend PD tests with exact token lengths, cache reuse, concurrency, intentional checksum corruption and recovery.

The event fix is in the shared Mooncake path used by Ascend. CUDA/Mooncake runtime behavior was not exercised in this validation.

## Accuracy Tests

Functional validation on 2026-10-09 at head `d5ae6d84f3853c2ee9d06d1c0cc295cdb1d85347`:

- **NPU kernel/unit tests: 9/9 passed**, using Python `zlib.adler32` as an independent oracle. Coverage includes byte tails, descriptor order and duplicates, empty components, FP16/BF16/FP32 raw bytes, modular overflow, selected/unselected mutations, paged/FIA views, nested Mamba-style state descriptors, and invalid/unsupported inputs.
- **Early-send event regressions: 4/4 passed**. Verify that enqueue does not wait, the transfer worker waits before KV reads, skipped/failed sends do not wait, and final tasks retain their event.
- **Exact-token PD matrix: 81 unique requests audited**: 78 normal requests returned HTTP 200 with exact prompt/output counts and applicable cache-hit assertions; 3 deliberately corrupted-checksum requests returned HTTP 500 with the checksum-mismatch reason, each followed by a successful recovery request.
  - Cold input lengths: `1, 2, 17, 127, 128, 129, 255, 256, 257, 511, 512, 513, 1023, 1024, 1025, 4095, 4096, 4097, 8191, 8192, 8193, 10000, 16383, 16384, 16385, 24577, 32768`.
  - Cached-prefix boundaries, three rounds of KV page reuse, two groups of mixed-length four-concurrent requests, three groups of shared-1024-token-prefix four-concurrent requests, and output lengths 1/32/128.
  - Two executions were interrupted by external SIGTERM after 47 and 3 completed requests. The remaining 31 requests passed in a clean resume. Source hashes were unchanged across runs. This is combined coverage, not one uninterrupted full-suite pass.
- **Checksum-disabled smoke: 8/8 passed**, covering cold inputs through 16385 tokens and shared-prefix concurrent requests. This checks request behavior, lengths and cache hits.

Environment: Qwen3-32B, Ascend prefill TP2 + decode TP2, page size 128, chunked prefill size 8192, overlap and early-send enabled, prefill radix cache enabled and decode radix cache disabled. Container image: `swr.cn-southwest-2.myhuaweicloud.com/base_image/dockerhub/lmsysorg/sglang:cann9.1.0-a3-B072`. Set `ASCEND_MF_STORE_URL=tcp://127.0.0.1:27600` before launch; the tests use bootstrap port 27500.

## Speed Tests and Profiling

Same-service ABBA smoke comparison: **skip early-send / event wait / event wait / skip early-send**. The baseline reproduces the previous protective guard that disabled cached-prefix early-send. Both variants enable checksum and overlap; event timing probes are disabled.

Each round has 2 excluded warmups, 4 measured serial requests and 8 measured requests with 4 concurrent clients. Requests share a 1024-token cached prefix, have a unique 1025-token suffix and generate 4 tokens. All 57 recorded requests passed; 48 were measured.

| Metric | Skip early-send baseline | Event-wait implementation | Change |
| --- | ---: | ---: | ---: |
| Serial response time | 5.2419 s | 5.2491 s | +0.14% |
| Four-concurrent throughput | 0.2731 req/s | 0.3156 req/s | +15.56% |

Serial aggregate is the median of the two round medians; concurrent aggregate is measured requests divided by total group wall time. These are small samples for this cached-prefix workload, not a production-wide performance guarantee or a comparison against a checksum-disabled service.
