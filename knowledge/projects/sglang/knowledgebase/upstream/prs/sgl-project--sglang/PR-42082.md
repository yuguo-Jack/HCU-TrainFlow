# [HF3FS] Stop persistence timers on graceful shutdown

[Upstream PR](https://github.com/sgl-project/sglang/pull/42082) · state: open · merged: False

## Original PR description

## Motivation

With HF3FS metadata persistence enabled, stopping Uvicorn leaves the process waiting for its non-daemon save timer. The timer keeps scheduling its successor, while the registered `atexit` shutdown callback cannot run until those threads finish. A confirmed write after the last periodic save is consequently not flushed on graceful shutdown.

## Modifications

- Shut down persistence in `Hf3fsMetadataServer.run()`'s `finally`, including serving errors and `KeyboardInterrupt`.
- Fence shutdown and timer rearming with the existing state lock. Cancel and join the timer outside that lock before the final save, so an active periodic writer cannot race the final writer on the same temporary file.
- Make shutdown idempotent and avoid joining the current thread.
- Add CPU regressions for normal return, serving failure, interruption, a gated active save, repeated shutdown, and disabled persistence.

## Accuracy Tests

- Original source: five failing assertions across the new methods/subtests; corrected source: four test methods and three subtests pass.
- Actual loopback Uvicorn, metadata HTTP initialize/reserve/confirm, and SIGINT reproduction: before the fix, Uvicorn stopped but the process did not exit and the confirmed write was absent from persistence. After the fix, the process exits successfully and the final confirmed key/page mapping is persisted.
