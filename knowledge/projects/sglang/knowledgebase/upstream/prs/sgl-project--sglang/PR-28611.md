# [AMD] add nightly kv_canary JIT benchmark suite

## Original PR description

## Summary

Onboards the 4 `kv_canary` JIT benchmark tests (`bench_write`, `bench_verify`, `bench_plan`, `bench_scatter_req_token_ids`) to AMD CI as a **nightly-only** suite, mirroring CUDA (which registers these benches nightly-only via `nightly-kernel-1-gpu`).

- New suite `nightly-amd-kernel-1-gpu` added to `NIGHTLY_SUITES[HWBackend.AMD]` in `test/run_suite.py`.
- Dedicated 1-GPU jobs added to `nightly-test-amd.yml` (`nightly-test-1-gpu-kernel`) and `nightly-test-amd-rocm720.yml` (`nightly-test-1-gpu-kernel-rocm720`), running `run_suite.py --hw amd --suite nightly-amd-kernel-1-gpu --nightly`.
- Each bench gets `register_amd_ci(suite="nightly-amd-kernel-1-gpu", nightly=True)`. CUDA registrations are untouched.

### Decisions
- **Nightly-only (no per-PR suite)**: mirrors CUDA for these benches; keeps per-PR AMD CI cost unchanged.
- **Perf asserts**: none of the 4 benches have latency/throughput assertions (they only return `run_benchmark` timing tuples), so nothing assumes NV numbers.
- **rocm720**: wired on both the mi3xx and rocm720 nightly workflows; `bench_plan` (the riskiest kernel) runs on both.
- **Reduced-range nuance**: `scripts/ci/amd/amd_ci_exec.sh` always exports `SGLANG_IS_IN_CI`, so `get_benchmark_range` returns the CI-reduced range in every AMD CI context. This nightly suite therefore runs the same reduced workload as CUDA's `nightly-kernel-1-gpu` (which likewise runs under `SGLANG_IS_IN_CI=true`) — a nightly perf-trend signal, not a larger sweep.
- **No CUDA behavior change**: `bench_plan`'s total-tokens / pool-capacity sweeps are left exactly as on `main` (ungated), so CUDA's existing nightly coverage is unaffected.
