# [Fix] diffusion: Nomas KV budget counts freed cached memory, reject SP-indivisible segments up front

[Upstream PR](https://github.com/sgl-project/sglang/pull/47516) · state: closed · merged: True

## Original PR description

## Summary

Fixes #47515. Two small bug fixes in the Hy-Nomas pipeline.

- `_free_bytes` now adds `memory_reserved - memory_allocated` (same correction as `qwen_image21._cache_fits`), so memory the allocator holds from an earlier request counts as available. Before, the KV budget came out too low, which caused false `Nomas KV requires ...` errors offline and early eviction in realtime.
- `NomasInputValidationStage` now rejects a segment whose video tokens (`latent_frames * H/32 * W/32`) are not divisible by the Ulysses degree, at request time. Before, `local_token_range` raised deep in the DiT, after text encoding and mid-session in realtime. Realtime flush chunks (1 latent frame, never run through the DiT) are exempt.

## Tests

Two tests added to the existing `test_nomas.py` (the SP one is parametrized: 13 frames ok, 17 frames rejected, flush chunk ok). Run on Modal CPU, targeted files only.

| | B1 test | SP test |
|---|---|---|
| main | fails: `assert 10 == 40` | 17 frames fails: `DID NOT RAISE ValueError` |
| this PR | passes | passes |

- `test_nomas.py` + `test_nomas_realtime.py` on this PR: 42 passed, 11 skipped (CUDA-only).
- Removing the flush exemption makes the flush case fail, so that test guards it.

## Review

An independent review pass found the flush-chunk rejection in my first version of the SP check. Fixed and covered by the flush test case. It also noted that the validation stage running with model parallel initialized on real workers is not covered by the unit test.
