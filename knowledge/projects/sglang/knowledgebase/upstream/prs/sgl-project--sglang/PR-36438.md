# [grok2] Fix silently incomplete expert weights when tp_size < presharded checkpoint width

[Upstream PR](https://github.com/sgl-project/sglang/pull/36438) · state: open · merged: False

## Original PR description

## Motivation

`xai-org/grok-2` ships a checkpoint that is **presharded 8 ways**: the MoE expert weights are split across `pytorch_model-*-TP-000..007.safetensors`, while every other tensor lives in `*-TP-common.safetensors` as a full tensor.

`_prepare_presharded_weights` has each rank glob only its own shard:

```python
allow_patterns += [f"*-TP-{tp_rank:03d}.safetensors", "*-TP-common.safetensors"]
```

At `tp_size < 8` this reads only shard `tp_rank` of each expert group while the layers are sized for the smaller TP. **It does not raise**: `hit_names` counts tensor *names*, and every name is present in the rank's single shard, so the load reports `#missing_exclude_scales: 0` and the server starts normally on a partially-populated model. The failure is silent and shows up only as degraded quality.

Measured on 8x MI350X (gfx950), `tp_size=4`, FP8, GSM8K 5-shot / 1319 questions:

| | GSM8K |
|---|---|
| `tp_size=4`, current `main` | **0.901** |
| `tp_size=4`, this PR | **0.926** |
| `tp_size=8` (reference, unaffected by this PR) | 0.932 |

The model code itself is already TP-agnostic (attention only asserts divisibility) - the limitation is purely checkpoint file selection.

## Modification

Rank `r` at `tp_size=T` owns exactly the contiguous slice covered by checkpoint shards `[r*g, (r+1)*g)` where `g = N/T`, so its weights can be reconstructed by concatenating those `g` shards.

1. **File selection** - derive the checkpoint width from `max(shard id) + 1` and reject gaps, then have each rank select its `g` shards. `tp_size > N` would require *splitting* a shard and is rejected with an explicit error.
2. **Merge-aware weights iterator** - selecting extra files is **not sufficient on its own**: the shards expose *identical tensor names*, so the default iterator would yield duplicates and keep only one. The new iterator opens a group's shards together (via `ExitStack`) and concatenates per tensor, keeping peak memory at one merged tensor. The concat axis is taken from the tensor name (`w1`/`w3` column-parallel -> dim 0, `w2` row-parallel -> dim 1) and anything else raises rather than guessing, since a wrong axis would yield a plausibly shaped but corrupted tensor.

Both helpers fall back to the stock loader when the checkpoint is not presharded, and are installed for every `tp_size` (a presharded checkpoint has to be reassembled at `tp_size=1` too).

## Correctness validation

- **Bit-exact weight reconstruction** - the per-rank tensors produced by this patch are `torch.equal` to an independently merged checkpoint sliced for `tp_size=4`, verified across `w1`/`w2`/`w3` and all 4 ranks.
- **No-op at native TP** - with the patch applied, `tp_size=8` output is **token-identical** to stock on a fixed greedy prompt set, and `#hit_names` is unchanged (707).
- **Memory** - `tp_size=4` uses 66.10 GB/GPU vs 35.40 GB/GPU at `tp_size=8`, the expected 2x.
