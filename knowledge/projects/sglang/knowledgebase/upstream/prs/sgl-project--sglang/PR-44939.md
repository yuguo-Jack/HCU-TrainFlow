# Exchange latent-width MoE rows under DP attention (Nemotron-H, Kimi K3)

[Upstream PR](https://github.com/sgl-project/sglang/pull/44939) · state: open · merged: False

## Original PR description

## Why?

- Latent MoE models run their experts in a narrower latent space: Nemotron-3 Super 4096 → 1024, Ultra 8192 → 2048, Kimi K3 7168 → 3584.
- Under DP attention with `--moe-a2a-backend none`, each MoE layer still all-gathers and reduce-scatters **hidden-width** rows across EP, and runs the router and down projection on every gathered row on every rank.

## What?

- New `layers/moe/latent_moe_comm.py`, opt-in via `SGLANG_OPT_LATENT_MOE_COMM=1`:
  - each attention-TP rank routes and down-projects only its slice of the DP group's tokens;
  - EP all-gathers `[latent | top-k weights | top-k ids]` and reduce-scatters latent partial sums;
  - each rank up-projects its own rows; one attention-TP all-reduce adds them to the shared expert (sharded over attention TP, overlapped on the alt stream).
- Nemotron-H and Kimi K3 call it from their MoE forward, and declare the layer as an FFN on attention rows that completes its own sum, so the stage boundary skips the DP gather.
- Unsupported setups log why and keep the default path. Allowed runners: `triton`, and `flashinfer_mxfp4` (K3's SiTU experts take precomputed top-k).

## Verification?

Per-token EP traffic per MoE layer (expected):

```text
                 Before (hidden)        After (latent + top-k)
Nemotron Super   2 x 4096 cols   ->     1024 + 88 + 1024 cols   (3.8x less)
Kimi K3          2 x 7168 cols   ->     3584 + 64 + 3584 cols   (2.0x less)
```

GB300 NVL72, 2 nodes in one rack, TP8 / DP2 / EP8, `random-ids` 2000 in / 300 out, path off -> on (observed):

```text
Nemotron-3 Super BF16 (triton)       c=16   1268 -> 1465 tok/s  (+15.5%)   TPOT 11.6 -> 10.1 ms
                                     c=128  4612 -> 4829 tok/s  (+4.7%)
Kimi K3 MXFP4 (flashinfer_mxfp4)     c=16    482 ->  520 tok/s  (+7.9%)    TPOT 25.5 -> 24.6 ms
                                     c=128  1057 -> 1101 tok/s  (+4.1%)
```

- Logprobs vs a plain-TP reference (48 prompts, 6.6k tokens): mean |Δ| 0.092 (on) vs 0.091 (off) for Nemotron, 0.093 vs 0.094 for K3; batching noise is 0.087–0.093. Top-1 agreement 95–96% in every case. (observed)
- A GB300 rack shares NVLink across nodes, so the gain is below the traffic ratio; EP over InfiniBand should gain more (expected).

```bash
SGLANG_OPT_LATENT_MOE_COMM=1 python -m sglang.launch_server --model-path <latent MoE> \
  --tp 8 --dp 2 --enable-dp-attention --ep 8 --moe-a2a-backend none --moe-runner-backend triton ...
# log: "Latent-width MoE exchange enabled."
```

- Passed: `pytest test/registered/unit/layers/moe/test_latent_moe_comm.py` (8 tests, CPU). 16 simulated ranks (2 DP x 8 attention TP, EP16) against the hidden-width dataflow: same routing and outputs (fp64, 1e-10) for MAX_LEN, uneven/even SUM_LEN, an idle DP group, no shared expert, and a latent norm (K3); collective choice per padding mode; bf16 error; bit-exact payload packing.
