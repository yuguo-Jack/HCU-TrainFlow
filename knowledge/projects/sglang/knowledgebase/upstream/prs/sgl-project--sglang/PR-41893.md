# [DSV4][Spec] DSPARK verify-merged mixed step, deterministic C4 top-k ties, eager ragged indexer

[Upstream PR](https://github.com/sgl-project/sglang/pull/41893) · state: open · merged: False

## Original PR description

## Motivation

With `--enable-mixed-chunk` (#36933), running DSPARK requests are folded into prefill steps, but
there each running request only decodes its pending token: 1 token per step instead of the ~4.8 a
normal DSPARK verify step yields. Agentic traffic prefills almost constantly (long multi-turn
contexts, tool outputs), so running requests spend much of their time at 1 token/step. On
DeepSeek-V4-Flash at 7.0 req/s, ITL p99 is 126.9 ms with `main`'s mixed chunk vs 29.5 ms with this PR.

```
One prefill step. P = new request's prompt chunk; r1..r3 = requests already decoding.

main:
  forward:  [ P P P P P P P P P P P P | r1 | r2 | r3 ]        1 token each
  result:   r1..r3 advance 1 token

this PR:
  draft:    r1..r3 each get W-1 draft tokens
  forward:  [ P P P P P P P P | r1 x W | r2 x W | r3 x W ]    pending token + drafts, verified here
  result:   r1..r3 advance ~4.8 tokens each; MoE weights read once for both populations
```

The PR also fixes non-deterministic tie handling in the DSV4 C4 indexer top-k, extends
`SGLANG_FLASHINFER_AUTOTUNE_EXTEND` to speculative target workers, and adds an eager ragged indexer
path for breakable prefill graphs.

## Modifications

Six commits, meant to be reviewed commit by commit. All new behaviour is behind new env flags
(default off) except commit 1.

1. **`[DSV4] Fix top-k tie handling: deterministic and exact on overflow`** (no flag)
   - Before: ties at the k-th value were resolved in thread-arrival order, so the selected set could
     differ run to run. v1 could also select an element below the k-th value when a bin overflowed
     its 8192-entry smem buffer.
   - After: ties go to the lowest position (bitmap + prefix sum in v1, index-ascending radix select
     in v2); overflowed bins are re-scanned from the input. Equivalent to a stable sort; tie-free
     rows are unchanged.
2. **`[Spec] Extend-shaped FlashInfer MoE autotune for speculative target workers`**
   - Before: `SGLANG_FLASHINFER_AUTOTUNE_EXTEND=1` skipped speculative targets, so their prefill and
     mixed steps ran untuned MoE tactics.
   - After: targets run the EXTEND dummy, sized to the request pool. Draft workers and PD-prefill
     targets are unchanged.
3. **`[DSV4] Verify-merged mixed step for DSPARK`** (`SGLANG_DSPARK_VERIFY_MERGED_MIXED=1`)
   - **Guard** (`verify_merged_mixed_enabled`): active only with DSPARK + `--enable-mixed-chunk` and
     without DP attention, PP, TBO or decoder SWA bounded replay; otherwise it warns once and
     `main`'s path runs. Since it excludes DP attention it does not interact with
     `SGLANG_ENABLE_DP_SPEC_PREFILL_COORDINATION` (#41623); the two dispatch branches are disjoint.
   - **Scheduler:** prefill rows first, then W-token verify rows. The token budget charges W tokens
     per running row. Batches with grammars or custom logit processors are not merged. Results
     are split per population; `main`'s 1-token bookkeeping (`resolve_mixed_spec_tails`,
     `stash_bonus_tokens`, `kv_committed_len += 1`) is bypassed for merged batches.
   - **Worker:** `DSparkWorkerV2._forward_mixed` drafts for the running rows, runs one target
     forward over both populations, then accepts/commits the verify rows. Committed lengths stay on
     the GPU.
   - **DSV4 backend:** attention metadata and dispatch split per population (including the SM90
     q8kv8 path).
   - `SGLANG_ENABLE_PREFILL_WAR_READ_DONE` now also covers MIXED steps and breakable-graph replays;
     SWA store slots are hoisted to metadata init.
   - New metric: `sglang:mixed_verify_steps_total`.
4. **`[DSV4] Write mixed-step attention output in place`**: both populations write straight into
   the layer's output buffer, removing one full-width copy per layer.
5. **`[DSV4] Copy only TP-local heads of the mixed-step attention output`**
   (`SGLANG_DSV4_ATTN_OUTPUT_TP_LOCAL_COPY=1`): a Triton row copy writes only this rank's TP heads.
   Padding heads are left stale; this is safe because `MQALayer` slices `o[:, tp_slice, :]`.
6. **`[DSV4] Eager ragged indexer`** (`SGLANG_DSV4_INDEXER_EAGER_RAGGED=1`)
   - Before: under breakable prefill graphs the C4 indexer scored every padded row of the bucket.
   - After: real prefill rows of all requests share one ragged non-paged launch per layer, in an
     eager section (same pattern as `bcg_deepseek_v4_low_ratio_sources`). Logits go through the
     existing row-chunk memory budget. Verify rows stay on the paged path.

| flag | default | effect |
|---|---|---|
| `SGLANG_DSPARK_VERIFY_MERGED_MIXED` (new) | off | commits 3–4 |
| `SGLANG_DSV4_ATTN_OUTPUT_TP_LOCAL_COPY` (new) | off | commit 5 |
| `SGLANG_DSV4_INDEXER_EAGER_RAGGED` (new) | off | commit 6 |
| `SGLANG_ENABLE_PREFILL_WAR_READ_DONE` (existing) | off | now also covers MIXED + breakable replays |
| `SGLANG_FLASHINFER_AUTOTUNE_EXTEND` (existing) | off | now also tunes speculative targets |

## Accuracy Tests

DeepSeek-V4-Flash-0731, DSPARK, TP2 on 2×B200, `main` at 81f27fb3. Three arms, same model and
hardware:

- **A: `main`, base flags.** The model's standard launch command (below, without the tuning lines).
- **B: `main`, unmodified, with tuned launch flags.** A plus breakable prefill CUDA

- **C: this PR.** B plus this PR's three new env flags.

**Known caveats**
- With all flags off, behaviour differs from `main` only through commit 1 (tie order; rows with
  ties can select a different, now deterministic set) and commit 2 (only if
  `SGLANG_FLASHINFER_AUTOTUNE_EXTEND=1` is already set with a speculative algorithm).
- v2 top-k remains non-deterministic on rows with more than 2048 candidates in a single bin.
- Validated end to end only on DeepSeek-V4-Flash + DSPARK, TP2, B200.
- On DSV4.1, `autotune_prefill_kernels` returns early, so commit 2 has no effect there.
