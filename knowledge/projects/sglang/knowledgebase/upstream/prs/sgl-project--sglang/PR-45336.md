# [Fix] spec: Accept pp_proxy_tensors in FrozenKVMTP and UNO workers

[Upstream PR](https://github.com/sgl-project/sglang/pull/45336) · state: open · merged: False

## Original PR description

## Motivation

Fixes #40155.

`Scheduler.run_batch` drives all speculative decoding through `BaseSpecWorker.forward_batch_generation`, and on the non-overlap path it passes `pp_proxy_tensors` unconditionally — whatever the pp size:

- `srt/managers/scheduler.py:4752` and `:4765` — `self.model_worker.forward_batch_generation(batch, pp_proxy_tensors=pp_proxy_tensors)`

`FrozenKVMTPWorkerV2` and `UnoWorkerV2` never took the keyword, so any request routed through them dies on the first speculative step with:

```
TypeError: <Worker>.forward_batch_generation() got an unexpected keyword argument 'pp_proxy_tensors'
```

Root cause: `BaseSpecWorker` is an ABC but never declared `forward_batch_generation`, so nothing enforced the interface the scheduler calls through. Each worker evolved its own signature and two of them silently fell behind.

This is a revival of a fix that has twice gone stale: #44211 (closed unmerged) and #42165 (open, inactive since 2026-10-02). Credit for the approach — accept-and-forward on frozen, discard on uno, abstract declaration on the base — belongs to their authors. #44490 is a parallel fix for the same issue; ours additionally adds the interface test the issue requested (part 2), and the two agree on the core changes.

## Modifications

**`python/sglang/srt/speculative/frozen_kv_mtp_worker_v2.py`**

Accept `pp_proxy_tensors=None` and forward it — to the target worker on the prefill branch (mirroring `EAGLEWorkerV2._forward_prefill_batch`), and to `self.verify()` on the decode branch (the inherited `EAGLEWorkerV2.verify` already takes it).

**`python/sglang/srt/speculative/uno_worker_v2.py`**

Accept `pp_proxy_tensors=None` and drop it. UNO is startup-gated to TP=PP=1 (`speculative_hook.py` `_handle_uno`), so the scheduler never hands it real proxy tensors; accepting the keyword keeps the shared call shape valid.

**`python/sglang/srt/speculative/base_spec_worker.py`**

Declare `forward_batch_generation` as an abstract method on `BaseSpecWorker`, so a worker that falls behind the interface fails at construction instead of mid-request. All existing workers already implement it, so nothing else changes.

**`test/registered/spec/test_spec_worker_interface.py`** (new)

Signature-inspection test that walks `sglang.srt.speculative` and asserts every worker that defines `forward_batch_generation` accepts both scheduler keywords (`on_publish`, `pp_proxy_tensors`). A new worker that drops them fails CI the day it lands, not in production.

## Accuracy Tests

Not applicable — no kernel, model forward, or sampling change. Call binding only; greedy outputs are unaffected by construction.

## Speed Tests and Profiling

Not applicable — no execution-path change beyond accepting a keyword that is `None` on the affected configs (UNO: always, per the TP=PP=1 gate; frozen: forwarded to the existing target-worker parameter).

## Verification

- All 8 `forward_batch_generation` definitions in `sglang.srt.speculative` (eagle, dflash, dspark, ngram, multi_layer_eagle, frozen_kv_mtp, uno, base) accept both keywords — verified by AST signature check on the real sources.
- `BaseSpecWorker` ABC gate verified: a subclass missing the override raises `TypeError` at construction; a conforming subclass instantiates.
- Negative control: the same signature check against the pre-fix `origin/main` versions of both workers fails — the check detects exactly the bug this PR fixes.
- The registered test (`test/registered/spec/test_spec_worker_interface.py`) runs in CPU CI; it imports the full speculative package and walks it, so any worker that regresses the interface fails at collection.
