# [Fix] Keep media fetch permits until blocking I/O finishes

[Upstream PR](https://github.com/sgl-project/sglang/pull/42042) · state: open · merged: False

## Original PR description

## Motivation

Cancelling an async caller does not stop a blocking media download. The caller used to release its semaphore permit while that download was still running, so later requests could exceed the download limit. Rejecting a sibling source has the same problem.

## Changes

Move the permit into the blocking fetch closure. The download keeps its slot until it returns or unwinds. A live request can still use any remaining slot. The limit and download timeouts stay the same.

The branch now includes current main and keeps the move of the prefetch code into `rust/sglang-server/src/api_server/core/prefetch.rs`. Start with `fetch_ordered`.

## Tests

Both new regressions use real HTTP downloads with explicit start and release signals. They cover caller cancellation and a failed sibling source, check that a live request can make progress, and check that all permits return after the download finishes.

On the updated branch, restoring permit ownership to the async caller makes both regressions fail. Keeping the permit in the blocking closure makes all 10 prefetch tests pass.

Strict Clippy passes for the workspace, server library and test targets, optional multimodal features, and radix tree. Formatting and matching precommit hooks pass.

These checks ran on macOS ARM64 with Rust 1.92. No GPU inference test or complete server test suite was run for this update.

AI assistance was used for implementation and validation.
