# [Feat] unified-cache: Support out-of-tree external linkers

[Upstream PR](https://github.com/sgl-project/sglang/pull/40595) · state: open · merged: False

## Original PR description

## Motivation

Selecting a unified cache external linker currently requires adding a backend branch to SGLang. Allow a separately installed package to supply a `UnifiedCacheLinker`, selected explicitly by class name and Python module path, following the configuration pattern used by vLLM KV connectors.

## Ownership and connections

![Ownership and connections: SGLang owns scheduling, the radix tree, and GPU KV allocation; the external linker runs inside the worker and transfers KV to and from external storage.](https://raw.githubusercontent.com/maobaolong/sglang-fs-linker/a0ce57537025948483301ee5c900e134da802dec/docs/images/linker-ownership.png)

SGLang retains prefix matching, request admission, GPU slot allocation, and tree locks. The separately installed linker runs inside the same worker and implements external storage access, KV transfers, and completion reporting. The filesystem example uses CPU staging internally. This PR changes how the linker is selected and constructed; the existing runtime ownership boundary is preserved.

## Modifications

- Add explicit `--unified-cache-external-linker-backend dynamic` selection. For this backend, `--unified-cache-external-linker-config` accepts `linker`, `linker_module_path`, and optional `linker_extra_config`. Validate the schema in the frontend and import the plugin only in the cache-owning worker. New plugins require no SGLang registration or source changes.
- Require a concrete `UnifiedCacheLinker` subclass and construct it as `Linker(server_args, params, components=..., extra_config=...)`, with a private copy of its extra options.
- Configuration never overrides the backend selector. Mooncake/MORI accept backend storage options directly through the same config flag; when absent, they retain the existing `--hicache-storage-backend-extra-config` fallback. An explicit config, including `{}`, replaces that fallback. Mooncake config can be combined with MLA deduplication.
- Accept configuration while the linker is disabled, without importing or constructing a plugin. This prepares configuration for future runtime attachment; this PR does not implement runtime attach/detach.
- Document the constructor and completion contract and add generic config/factory tests with CPU CI registration.

This PR contains only the SGLang extension mechanism and its tests. The filesystem implementation, packaging, verifier, and plugin-specific tests are maintained separately in [maobaolong/sglang-fs-linker](https://github.com/maobaolong/sglang-fs-linker); no example package is included in this PR.

The independent plugin is published on [PyPI as `sglang-fs-linker==0.1.0`](https://pypi.org/project/sglang-fs-linker/0.1.0/) ([successful release workflow](https://github.com/maobaolong/sglang-fs-linker/actions/runs/35627801114)). That release was validated with the earlier SGLang revision recorded below. It predates upstream's required `finish_layer_wise_loading(counter_index)` method and cannot be instantiated on the current PR head without adapting the plugin to the new completion contract.

Selection syntax for a filesystem plugin adapted to the current `UnifiedCacheLinker` contract (the published `0.1.0` release does not yet implement that contract):

```bash
--enable-unified-cache-external-linker \
--unified-cache-external-linker-backend dynamic \
--unified-cache-external-linker-config '{
  "linker": "FileSystemLinker",
  "linker_module_path": "sglang_fs_linker.linker",
  "linker_extra_config": {
    "directory": "/tmp/sglang-fs-kv",
    "namespace": "qwen3-0.6b-example-v1"
  }
}'
```

There is no `kv_role`: the linker contract includes both load and offload. This adds an extension mechanism without expanding the tree wrapper's model support.
