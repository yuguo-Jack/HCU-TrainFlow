# [Fix] [AMD] dsv4: Use a 64-bit warp mask in the V4.1 K store shuffles

[Upstream PR](https://github.com/sgl-project/sglang/pull/46257) · state: closed · merged: False

## Original PR description

## What
Switch the `__shfl_xor_sync` masks in `deepseek_v4/main_norm_rope.cuh` from `0xffffffffu` to `warp::kFullMask`.

## Why
#45934 added `fused_k_norm_rope_flashmla_v41` (warp-per-token V4.1 K store). Its two shuffle loops pass a 32-bit mask, and ROCm's `amd_warp_sync_functions.h` statically requires a 64-bit mask, so the JIT module no longer builds on gfx950:

```
amd_warp_sync_functions.h:307:62: error: static assertion failed due to requirement 'sizeof(unsigned int) == 8': The mask must be a 64-bit integer.
main_norm_rope.cuh:513:18: note: in instantiation of function template specialization '__shfl_xor_sync<unsigned int, float>'
```

This breaks `test_v41_kv_store.py` in `stage-b-test-1-gpu-small-amd-mi35x` on main: https://github.com/sgl-project/sglang/actions/runs/39952723713/job/120410987523

## Notes for the reviewer
- `warp::kFullMask` is `uint32_t 0xffffffff` on CUDA and a 64-bit all-ones mask on ROCm, so CUDA codegen is unchanged. `fused_norm_rope_v2.cuh` already uses it for the same pattern.
- The reduction logic needs no change on wave64: `kWarpThreads` is 32 on both platforms and every XOR mask is at most 16, so lanes never exchange across the two 32-lane halves of a wave.
- The two Hadamard loops in the indexer Q kernels (lines 817 and 1034) had the same literal mask. They are not instantiated in the failing test, but I switched them too so the file is consistent.
