# [Fix] [NVIDIA] trtllm_mla: Reject prefill and skip the decode counter on SM12x

[Upstream PR](https://github.com/sgl-project/sglang/pull/28837) · state: open · merged: False

## Original PR description

## Motivation

On SM120/SM121, TRTLLM MLA fails in two ways:

1. Prefill: `--attention-backend trtllm_mla` passes server-argument validation, because the check only asks for Blackwell, and then FlashInfer fails with `Unsupported architecture` in the dense TRTLLM MLA prefill kernel. `--prefill-attention-backend trtllm_mla` is not checked at all.
2. Decode: with FlashInfer prefill and TRTLLM MLA decode, the decoder always passes `multi_ctas_kv_counter_buffer` for the trtllm-gen path. FlashInfer's `backend="auto"` picks XQA when the compute capability major is not 10 (`flashinfer/mla/_core.py:4209-4210` in 0.7.2), and XQA raises `multi_ctas_kv_counter_buffer is only supported by the trtllm-gen backend` (`_core.py:4292-4294`).

Both are still present on main `4eb606b2a`. Fixes #24633 (closed by the stale bot without a fix).

## Modifications

1. `_mla_kv_cache_dtype_checks` resolves the effective prefill and decode backends (`attention_backends_of`) and checks them separately. TRTLLM MLA prefill requires `is_sm100` (major 10), and the error suggests `--prefill-attention-backend flashinfer`. TRTLLM MLA decode still requires Blackwell (majors 10, 11 and 12). A global `--attention-backend trtllm_mla` that both phases override no longer triggers the checks.
2. `TRTLLMMLABackend` stops passing `multi_ctas_kv_counter_buffer` when `is_sm120_supported()` (major 12), where FlashInfer selects XQA. SM10x keeps the counter, and no other decode argument changes.

Scope:

1. The prefill gate also rejects SM11x, because `is_sm100` covers major 10 only. SM11x decode is unchanged and still passes the counter. I have no SM11x hardware and did not test it.
2. The KV cache dtype check now also applies when only the prefill backend is `trtllm_mla`.
3. `_mla_backend_page_constraints` still keys on `--attention-backend` and `--decode-attention-backend`; this PR does not change it.

## Accuracy Tests

N/A for model outputs: on SM10x the kernel arguments are unchanged, and on SM12x these configurations failed before.

On `0e28e731a` (main `4eb606b2a`), CPU only, Transformers 5.19.0, sglang-kernel 0.4.10 and FlashInfer 0.7.2 (main's pins):

1. `pytest test/registered/unit/server_args/test_server_args.py -q`: 308 passed. Of the 7 new `TestTrtllmMlaArchGuard` cases, 3 fail on main (combined and explicit TRTLLM MLA prefill on SM120 are accepted, and an unused global `trtllm_mla` triggers the check); the other 4 cover allowed setups and pass on both.
2. `pytest test/registered/dcp/test_trtllm_mla_family_dcp_metadata.py -q`: 4 passed, 28 skipped without a GPU. The new `test_sm12x_decode_omits_trtllm_gen_counter` is among the GPU cases.

On the earlier head `3a67bc777`, on an RTX PRO 6000 (SM120) with Transformers 5.17.0, sglang-kernel 0.4.8 and FlashInfer 0.7.0.post1:

1. Main reached the unsupported prefill kernel; the patch rejected the configuration before loading weights.
2. A two-layer dummy-weight MLA model with 128 attention heads failed mixed FlashInfer prefill and TRTLLM MLA decode on main with the counter-buffer error; the patch served a request with four generated tokens.
3. `test_trtllm_mla_family_dcp_metadata.py` passed on one GPU (32 passed, 2 subtests passed). It checks metadata and decode arguments, not multi-GPU execution.

These GPU runs were not repeated after the rebase. No model-quality, performance or SM100 hardware result is claimed.

## Code Review

This pull request updates the compatibility checks for the `trtllm_mla` attention backend in `server_args.py` by separating prefill and decode validation. It restricts the prefill backend to SM100/SM103 (datacenter Blackwell) architectures to prevent crashes on workstation/consumer Blackwell GPUs (SM120/SM121), while continuing to allow the decode backend on all Blackwell architectures. Corresponding unit tests have been added to verify this behavior. There are no review comments, and I have no feedback to provide.
