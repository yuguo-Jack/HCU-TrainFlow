## Motivation

In GLM context-parallel prefill, the existing MoE input path gathers BF16 hidden states before routing and activation quantization. This transfers full-precision activations and repeats routing and quantization across CP ranks.

This change moves routing and activation quantization before the CP AllGather, allowing ranks to communicate FP8 activations together with the scales and routing metadata. Fused packing and unpacking reduce the overhead of preparing the communication payload.

## Modifications

- Add an opt-in `SGLANG_CP_MOE_FP8_TRANSPORT=1` environment variable. The optimization is disabled by default.
- Compute routing from the original local BF16 hidden states, then perform local block-wise FP8 activation quantization.
- Fuse FP8 activations, FP32 scales, routing weights, and expert IDs into a single aligned byte payload.
- Use one CP AllGather for the packed payload and fuse unpacking into the downstream input tensors.
- Extend layer-boundary declarations to support compute-owned CP input gathering while preserving the existing output-reduction contract.
- Allow the eligible DeepGEMM path to consume prequantized inputs without quantizing them again.
- Retain the existing BF16 path for unsupported configurations.
- Add correctness tests and standalone packing/unpacking benchmarks.

The optimized path currently targets eligible GLM interleaved CP configurations with CP/TP group sharing, CP size equal to TP size, and EP=1. It does not enable general EP>1 support.

## Accuracy Tests

- Kernel correctness and CUDA Graph replay tests: **28 passed**.
- Layer-boundary regression tests: **14 passed**.
- Four-GPU preparation-chain validation passed for global token counts of **4,096, 8,192, 17,408, 32,768, and 65,536**:
  - FP8 activation bytes matched exactly.
  - FP32 quantization scales matched exactly.
  - Expert IDs and their ordering matched exactly.
  - Maximum routing-weight absolute difference: **2.68e-7**.
- Verified that the DeepGEMM prequantized-input dispatch consumes the supplied FP8 tensors rather than the BF16 placeholder.
- Targeted Ruff checks and `git diff --check` passed.

The four-GPU tests used actual GLM router weights with synthetic BF16 inputs. Full-model GSM8K and end-to-end serving regression have not yet been run for this change.

## Speed Tests and Profiling

Measured the complete MoE input-preparation chain on **4× NVIDIA H200 GPUs**, using SGLang's PyNcclCommunicator.

Compared paths:

```text
Baseline:
BF16 AllGather → global routing → global FP8 quantization

Optimized:
local routing → local FP8 quantization → fused packing
→ FP8 payload AllGather → fused unpacking → scale-layout conversion
```

Both paths produce equivalent downstream input tensors. The optimized timings include the scale-layout conversion required by the tested DeepGEMM compact-input path.

Test configuration:

- Hidden size: 4,096
- CP size: 4
- FP8 quantization group size: 128
- Top-k metadata: 8 routed experts + 1 shared expert
- Actual GLM layer-45 router weights
- CUDA Graph timing with rotating input buffers exceeding L2 capacity
- Five alternating trials, with the slowest-rank latency used for each sample

| Global tokens | Local tokens/rank | Baseline (ms) | Optimized (ms) | Speedup | Latency reduction |
| --- | --- | --- | --- | --- | --- |
| 4,096 | 1,024 | 0.1513 | 0.1060 | 1.43× | 29.9% |
| 8,192 | 2,048 | 0.2650 | 0.1711 | 1.55× | 35.5% |
| 17,408 | 4,352 | 0.5419 | 0.3241 | 1.67× | 40.2% |
| 32,768 | 8,192 | 0.9634 | 0.5675 | 1.70× | 41.1% |
| 65,536 | 16,384 | 1.8628 | 1.0937 | 1.70× | 41.3% |

The per-token communication payload decreases from **8,192 bytes to 4,304 bytes**, including scales, routing metadata, and alignment padding: a **47.5% reduction**.

These results measure the input-preparation chain only. They exclude expert dispatch, MoE GEMMs, output reduction, and full-model execution, and should not be interpreted as end-to-end model speedups.
