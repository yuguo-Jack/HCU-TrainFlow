## Original PR description

# [LMCache] Support DSA models (DeepSeek-V3.2) via LMCache multi-process backend
## Motivation
This PR enables LMCache offloading for DSA-family models (e.g. DeepSeek-V3.2) under LMCache multi-process (MP) backend.

Previously `LMCRadixCache` only supported MHA/GQA/MLA KV pools. For `DSATokenToKVPool`, the sparse attention buffer `index_k_with_scale_buffer` was missing during offloading. After warm KV restoration, stale index data caused intermittent output divergence between cold and warm-hit decoding.

This design keeps SGLang as the single source of KV pool tensor definitions, and passes LMCache only required tensor lists without monkey-patching KV pool objects. There is zero behavioral change for existing MHA/GQA/MLA models.

## Modifications
All changes are confined to `python/sglang/srt/mem_cache/storage/lmcache/lmc_radix_cache.py`:
1. Add helper `_extract_kv_pools(kvcache)`
    Classifies KV pool type once on initialization and returns `list[list[torch.Tensor]]`:
    | KV Pool Type | Return Value | Notes |
    |--------------|-------------|-------|
    | MHATokenToKVPool | `[k_buffer, v_buffer]` | Separate per-layer k/v tensors |
    | MLATokenToKVPool | `[kv_buffer]` | Fused shared kv tensor, LMCache auto-deduplicates |
    | DSATokenToKVPool | `[kv_buffer, index_k_with_scale_buffer]` | Fused kv + sparse attention index buffer |
    | Unknown pool | Throw explicit `RuntimeError` | Replace fragile chained `getattr` silent failure |
    
The extra `index_k_with_scale_buffer` ensures DSA cache correctness; it must be offloaded/restored together with main KV tensors.

2. Refactor connector initialization
    Pass pre-parsed `kv_cache_pools` to both `LMCacheMPConnector` and `LMCacheLayerwiseConnector`:
    ```python
    kv_cache_pools = _extract_kv_pools(kvcache)
    connector_kwargs = dict(
        sgl_config=model_config,
        tp_size=tp_size,
        rank=rank,
        kv_cache_pools=kv_cache_pools,
        tp_group=tp_group.device_group if tp_group is not None else None,
    )

3. Scope restriction
    The new `kv_cache_pools` parameter is passed to both MP and IP connectors, but DSA + LMCache in-process (IP) backend is untested and unsupported in this PR. Only multi-process LMCache backend is validated for DSA models.

## Dependency
Depends on paired LMCache PR to accept extra tensor group in `kv_cache_pools` and register two kernel groups under shared `engine_group_id=0`:
https://github.com/LMCache/LMCache/pull/4062

## Accuracy Validation
1. End-to-end test on DeepSeek-V3.2 + LMCache MP
    Cold and warm-hit inference outputs are fully bitwise identical across all test prompts; the original random divergence issue is eliminated.
2. Regression test for non-DSA models
    Validated DeepSeek-V2 (MLA) and standard MHA models, no changes to inference results or warm cache hit logic.

## Performance Analysis
No negative inference overhead introduced:
1. `_extract_kv_pools` runs only once during `LMCRadixCache` initialization, no per-decode cost.
2. For MHA/GQA/MLA models, no extra tensor groups are passed, so both SGLang and LMCache sides follow the exact same code paths as before
