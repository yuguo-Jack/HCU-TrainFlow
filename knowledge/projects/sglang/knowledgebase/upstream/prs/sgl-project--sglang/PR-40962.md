# [Fix] speculative: build target graphs outside draft contexts

[Upstream PR](https://github.com/sgl-project/sglang/pull/40962) · state: open · merged: False

## Original PR description

Adaptive EAGLE builds extra draft and target graph resources when it initializes adaptive step counts. Keeping the draft TP, MoE and A2A contexts active around the whole operation can make target attention backends and graph runners inherit draft settings, including a no-A2A draft paired with a DeepEP v2 target.

I've limited those contexts to draft-resource construction. Target resources are built after they exit, while the worker-state override remains active. This refresh merges main `66cac6b79ccf` and keeps its resolved draft parallel layout and platform-specific graph-runner selection, including platforms that disable graph capture.

The focused CPU regressions check context placement, exception restoration, and out-of-tree graph capture enabled/disabled. They fail against main `66cac6b79ccff` and pass with this change. This run executes the actual two production method ASTs, platform selector and registered test class with startup/configuration dependencies isolated. The affected Ruff, formatting, isort and registered-test checks pass. The normal package test entry was also attempted, but import stops at the missing `tvm_ffi` dependency; normal-package execution remains pending.

A separate historical GPU backport on `033446bb05` completed adaptive initialization and generation with compatibility backports. It does not validate this PR's current head or current main. Current-version GPU execution remains pending, and no performance improvement is claimed.

AI assistance: Codex helped with the main sync, code review, regression coverage and CPU validation.
