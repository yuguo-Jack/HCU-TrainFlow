# [Fix] speculative: Keep adaptive target graph construction outside draft contexts

[Upstream PR](https://github.com/sgl-project/sglang/pull/40962) · state: open · merged: False

## Original PR description

## Summary

Limit the draft TP, MoE runner, and MoE A2A contexts to constructing draft resources in `build_adaptive_runtime_state`. Build target attention backends and target decode graph runners after those contexts exit.

`init_cuda_graphs` currently wraps the entire adaptive controller initialization in draft contexts. The controller builds both draft and target resources. With target `deepep_v2` and draft `none`, the target graph runner therefore observes the draft A2A configuration even though the target model uses DeepEP v2.

One observed consequence on TP16 is that an additional width-1 target runner admits batch size 60 under the draft context, instead of retaining the target's attention-TP gather alignment. The initial width-6 target capture succeeds, followed by a DeepEP hybrid dispatch barrier timeout during adaptive initialization.

The change preserves `owns_attention`, the worker-state override around the whole candidate build, all adaptive candidates, and each runner's existing configuration.

## Validation

- Added CPU regressions covering the real `init_cuda_graphs` → adaptive builder call chain, asserting draft-only context scope for draft resources and target context for target resources.
- Added an exceptional draft-capture path check to verify context restoration.
- On a pinned `033446bb05` environment, the unpatched implementation fails the context regression and the backport passes both tests.
- GPU backport validation: two 8-GPU Hopper nodes, TP16/EP16, target DeepEP v2 hybrid, draft A2A none, per-rank dispatch capacity 512, adaptive widths 1/2/4/6/8. All configured adaptive states initialize; text and 1/7/25-image generation complete with the expected synthetic results. The previous additional-capture barrier timeout did not recur.
- The GPU run used the pinned deployment with its DeepEP v2 compatibility backports, not a full current-main installation. This PR does not claim end-to-end performance gains or comprehensive DeepEP v2 validation.
- Changed-file Ruff checks and `git diff --check` pass.

The production-backport findings are used to validate this narrowly scoped context bug. This PR does not add communication barriers, change NCCL versions, or alter graph batch sizes.
