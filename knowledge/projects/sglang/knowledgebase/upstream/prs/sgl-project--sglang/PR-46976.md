## Motivation

Separate composite allocators repeat token/state lifecycle and transfer-event handling for each supported pool combination.

## Changes

Build all unified pools with a ChainAllocator over their ordered sub-pools. Share allocation lifecycle, grouped frees, translation and event propagation; replace composite-type checks with capabilities while retaining the existing capacity policies.

## Validation

Historical validation at `db7885842d` / `9a7aad64a1`:
- Composite-versus-chain comparison: **612 runs / 173,472 operations, 0 divergences**.
- TP1, one H200 per server; PyTorch 2.14.1, sglang-kernel 0.4.10, FlashInfer 0.7.2:

GSM8K used 200 examples; serving used 1,024/256 input/output tokens and concurrency 64. These historical GPU results were not rerun after the latest rebase.
