## Motivation

<!-- Describe the purpose and goals of this pull request. -->

This PR fixes four issues:
1. In cosmos3, fp8 kernel will hit cuda illegal memory when sequence length is big.
2. turn on ulysses sequence parallelism support for action generation.
3. resolve history_mode from checkpoint config file for sim bimanual
4. when using sp with ulysses, and when there is only one key/value on a rank, K and V will point to the same shared buffer in memory after all-to-all operation during attention calculation. Basically K is overwritten by V.

## Modifications

<!-- Detail the changes made in this pull request. -->
1. With 2 720p control videos, the full sequence length is 85560 tokens, super's down_proj input is 25600 wide. In that case 85600x25600 > 2^31. Currently, the tensor pointer y_ptr is int32, which is insufficient. The fix is cast g_id to int64 when calculating the element position.
2. remove NotImplementedError for action generation when sp > 1. Added some code refactor for sequence sharding.
3. for sim-bimanual, history_mode defaults to auto. A resolve_history_mode method turns it into full or sliding from the checkpoint config.
4. in _usp_input_all_to_all, force tensor copy instead of implicit contiguous() call, which will point to shared buffer if tensor is already contiguous. This happens when there is just one key/value on a rank.
