# [Security] Fix multimodal SSRF local file disclosure with path allowlist and validation (#45206)

[Upstream PR](https://github.com/sgl-project/sglang/pull/45558) · state: open · merged: False

## Original PR description

## Description

Closes #45206.

### Problem
In SGLang's multimodal input loaders (`image_url`, `video_url`, `audio_url`), remote `http(s)` URLs are strictly validated by `download_remote_media` and `--allowed-media-domains`. However, `file://` URIs and bare filesystem paths bypassed this security policy entirely:
1. **SSRF Allowlist Bypass & Arbitrary Local File Disclosure**: An operator configuring `--allowed-media-domains` was still exposed to local file disclosure. Attackers sending `file:///etc/passwd` or `/home/...` could direct IO workers to read arbitrary local files into memory and forward decoded contents to the model.
2. **Denial of Service via Special Devices / Unbounded Reads**: Reading `/dev/zero`, `/dev/urandom`, named pipes, or directories would hang IO workers or trigger unbounded allocations leading to OOM crashes.
3. **Symlink Escape & Path Traversal**: Symlinks and relative paths (`../`) could escape local directory boundaries.

### Solution
This PR hardens multimodal local media ingestion across all loaders:
1. **Configurable Path Allowlist**:
   - Adds `--allowed-local-media-paths` to `Mm` config namespace.
   - When configured, only paths within the canonical real path of allowed directories/files can be accessed.
   - When `--allowed-media-domains` is configured but no `--allowed-local-media-paths` are provided, local file and `file://` access is **automatically disabled** by default, closing the SSRF allowlist bypass loophole.
2. **Path Normalization & Traversal Prevention**:
   - Uses `os.path.realpath(os.path.abspath(url2pathname(...)))` to resolve symlinks and parent directory traversals (`../`).
3. **Regular File & Size Limit Enforcement**:
   - Enforces `os.path.isfile()` to strictly block character/block devices (`/dev/zero`, `/dev/urandom`), directories, and FIFOs.
   - Restricts local media read size using `media_url_max_file_size_mb` (and streams reading with bounded size limit).
4. **Unified Enforcement**:
   - Protects `get_image_bytes`, `load_image`, `load_audio`, `_normalize_video_input`, `get_video_bytes`, `identity.py`, `mimo_v2.py`, and `moss_vl.py`.

### Test Evidence
- Extended `test/registered/unit/multimodal/test_media_url_security.py` with 7 new comprehensive test cases (17 passed in 4.29s):
  - Domain allowlist blocks local `file://` and bare paths when no local paths are allowed.
  - Whitelisted directory allows valid local files and `file://` URIs.
  - Unwhitelisted paths, `../` directory traversals, and symlink escapes outside the allowed directory are strictly rejected.
  - Special devices (`/dev/zero`, `/dev/null`) and directories are rejected.
  - Files exceeding `max_file_size_mb` are rejected.
  - Empty `allowed_local_media_paths` blocks all local media access.
  - `load_image` and `load_audio` enforce local media security boundaries.
- Regression tests passed:
  - `test/registered/unit/server_args/test_resolution_declarations.py` (14 passed)
  - `test/registered/unit/test_server_args_migration.py` (12 passed)
