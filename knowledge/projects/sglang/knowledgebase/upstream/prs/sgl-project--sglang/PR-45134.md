# [Fix] dsv41: Support the minimal and medium reasoning effort levels

[Upstream PR](https://github.com/sgl-project/sglang/pull/45134) · state: open · merged: False

## Original PR description

## Motivation

OpenAI's `reasoning_effort` accepts none, minimal, low, medium, high, xhigh and max. DeepSeek-V4.1's encoder names low (50), high (75) and max (100) on a 1-100 budget, with xhigh as an alias of high (#39929). So `minimal` and `medium` fell back to the default `high` with a server-side warning, and `minimal` got more reasoning than `low`.

## Modifications

- `parse_dsv41_reasoning_effort` maps `minimal` to 50, the same as `low` (Harmony also maps minimal to low), and `medium` to 62, between `low` and `high`.
- The same applies to `SGLANG_DSV41_REASONING_EFFORT`.
- The encoder is unchanged.
- Rust `sglang-processor` render matches.
- The cookbook, the environment variable reference and the warning text list the new levels.

## Accuracy Tests

Only `minimal` and `medium` render differently, as budget 50 and 62 instead of 75.

## Speed Tests and Profiling

Not applicable.

## Validation

- **Python:** a new test in `test_serving_chat.py` covers the parsed values, the environment default and the rendered prompt through `_process_messages`. It fails before the change and passes after.
- **Rust:**
  - The render parity fixture gains `effort_minimal`, and `effort_medium` now expects budget 62. The fixture was generated with the V4.1 tokenizer.
  - The parity test fails with the old code.
  - A unit test covers the budget mapping.
