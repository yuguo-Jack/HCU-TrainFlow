# [Fix] observability: Log scheduler stats once per attention CP group

[Upstream PR](https://github.com/sgl-project/sglang/pull/45319) · state: closed · merged: True

## Original PR description

## Motivation

With `--enable-prefill-cp`, every attention-CP rank logs the same scheduler stats as follows.

```
[2026-10-20 04:41:56 ATTN_CP1 TP1] Decode batch, #running-req: 1, #token: 58560, token usage: 0.02, accept len: 3.33, accept rate: 0.47, cuda graph: True, gen throughput (token/s): 181.02, #queue-req: 0
[2026-10-20 04:41:56 ATTN_CP2 TP2] Decode batch, #running-req: 1, #token: 58560, token usage: 0.02, accept len: 3.33, accept rate: 0.47, cuda graph: True, gen throughput (token/s): 181.02, #queue-req: 0
[2026-10-20 04:41:56 ATTN_CP3 TP3] Decode batch, #running-req: 1, #token: 58560, token usage: 0.02, accept len: 3.33, accept rate: 0.47, cuda graph: True, gen throughput (token/s): 181.02, #queue-req: 0
[2026-10-20 04:41:56 ATTN_CP7 TP7] Decode batch, #running-req: 1, #token: 58560, token usage: 0.02, accept len: 3.33, accept rate: 0.47, cuda graph: True, gen throughput (token/s): 181.02, #queue-req: 0
[2026-10-20 04:41:56 ATTN_CP4 TP4] Decode batch, #running-req: 1, #token: 58560, token usage: 0.02, accept len: 3.33, accept rate: 0.47, cuda graph: True, gen throughput (token/s): 181.02, #queue-req: 0
[2026-10-20 04:41:56 ATTN_CP5 TP5] Decode batch, #running-req: 1, #token: 58560, token usage: 0.02, accept len: 3.33, accept rate: 0.47, cuda graph: True, gen throughput (token/s): 181.02, #queue-req: 0
[2026-10-20 04:41:56 ATTN_CP6 TP6] Decode batch, #running-req: 1, #token: 58560, token usage: 0.02, accept len: 3.33, accept rate: 0.47, cuda graph: True, gen throughput (token/s): 181.02, #queue-req: 0
[2026-10-20 04:41:56 ATTN_CP0 TP0] Decode batch, #running-req: 1, #token: 58560, token usage: 0.02, accept len: 3.33, accept rate: 0.47, cuda graph: True, gen throughput (token/s): 181.02, #queue-req: 0
```

CP ranks share scheduler state, so these lines repeat the same numbers and clutter the log.

## Modifications

- Require `attn_cp_rank == 0` in addition to `attn_tp_rank == 0` for `is_stats_logging_rank` in `python/sglang/srt/observability/metrics_collector.py`. This matches the existing leader check for KV events in the same function.
- Effect: only CP rank 0 now logs stats and exports per-scheduler Prometheus metrics (unless `--enable-metrics-for-all-schedulers` is set).
- No change when CP is disabled, since `attn_cp_rank` is always 0.
