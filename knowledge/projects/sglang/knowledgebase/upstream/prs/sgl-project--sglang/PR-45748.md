# [Feat] parser: Source-certified marker matching contract (P1, stacked on #45587)

[Upstream PR](https://github.com/sgl-project/sglang/pull/45748) · state: open · merged: False

## Original PR description

Stacked on #45587; the diff includes its commit until that PR merges, after which this branch is rebased onto main and marked ready.

## Motivation

#45587 matches GLM's `</think>`, `<tool_call>` and argument tags by output token id, so tags the model spells with ordinary tokens stay text. It leaves three contracts implicit:

- When ids cannot be used (no ids, unsupported tokenizer, text that disagrees with the ids), matching silently falls back to text. A deployment cannot ask for id matching to be guaranteed.
- The parsers query a masked copy of their text (`view()`), which only defuses marker first characters. A lookup on a string other than the end of the parsed text returns that string unchanged, which is also a silent fall back to text.
- An empty id list, missing ids, and stream chunks whose ids repeat or skip are not told apart.

This PR adds the mode switch and typed lookups that later parsers can build on, still only for `glm45` and `glm47`. It is the first step of moving output parsing to source-certified markers (design discussion: #45587).

## Modifications

**`--parser-match-mode auto|strict|text`** (server argument, default `auto`).

| Condition | `text` | `auto` (default) | `strict` |
|---|---|---|---|
| Parser or tokenizer cannot match by id | text | text, reason logged once | server fails to start |
| Response has no output ids | text | text, reason logged once | error |
| Text past what the ids decode to, including any text with an empty id list | text | no markers match in that text; warning once | error by the end of output |
| Text disagrees with the ids, or ids repeat / skip / go back | text | warning, text for the rest of the output (#45587 behavior) | error |

In streaming, the text-past-ids check runs when the output ends, so text already streamed is followed by the error instead of a stop. Text at the end of output counts as covered only when the ids render it: bytes of an unfinished character the decoder still holds (shown as U+FFFD) and the text of special tokens the ids hold, in id order, or a prefix of that (trimmed stop text). Mid-output, the parser text either shows the text of every special token the ids hold, at its position, or none; each reading is matched while the text agrees with it, so a special token followed by its own text spelled with ordinary tokens leaves that text visible when special tokens are skipped. Markers resolve only where every surviving reading agrees. A special token held behind an unfinished character takes its place once later text decodes.

Errors are `500` for non-streaming Chat/Responses/Anthropic, an error event for Chat streaming, and `response.failed` for Responses streaming. The Rust server refuses `strict`. `/parse_function_call` and `/separate_reasoning` take text only and parse in `text` mode.

**Typed marker lookups** (`parser/control_token_stream.py`). `ControlTokenStream.find(kind, text, start)` and `match_at(kind, text, offset)` return a `MarkerSpan(kind, start, end)` only where a control token of that kind wrote the marker. `find`, `match_at` and `view` raise on any string other than the end of the parsed text instead of matching it as text.

- `glm45` locates `<think>`, `</think>` and `<tool_call>` with them.
- `glm47` one-shot parsing finds call, name and argument boundaries with them instead of regexes over the masked view; the streaming XML state machine keeps the view for its partial-tag handling.

**Source contract.**

- An empty id list is a source that wrote no markers; missing ids are no source.
- Stream ids go through a cursor shared by both parsers. In incremental mode a chunk must end at `meta_info.completion_tokens`; in cumulative mode the list may run ahead of `completion_tokens` (it shares storage with the request and grows between chunks) but not behind it, and a new list must repeat every id seen before. The same list object is trusted to only grow; an in-place rewrite of it is not detected. Comparing the prefix only when the list object changes keeps the check linear.
- A marker that is a special token (`special=True`) is refused: the decoder skips it, so its position is never recorded. GLM's markers are all `special=False`.
- A control `<think>` that does not begin the output stays in the reasoning, as in one-shot parsing, however the stream is chunked; splicing it out would leave a buffer the ids cannot locate markers in.

## Tests

`test_function_call_parser.py::TestGlmControlTokenIds` (real `zai-org/GLM-5.3` tokenizer). Each new case fails on #45587:

- `test_special_token_markers_are_refused`: `<|assistant|>` (`special=True`) is refused, and `strict` raises.
- `test_marker_lookups_take_only_the_end_of_the_parsed_text`: `find` returns the control `</think>` and skips the spelled one; `find`, `match_at` and `view` raise on other strings, including where no marker would match.
- `test_empty_output_ids_are_not_missing_ids`: `None` matches as text; `[]` certifies no markers; `strict` raises for both.
- `test_strict_mode_fails_where_auto_matches_as_text`: disagreeing text (one-shot and streaming, reasoning and tool call) and parsers without id support.
- `test_text_mode_ignores_output_ids`.
- `test_stream_output_ids_must_continue`: incremental repeat and gap, cumulative ids behind the token count, shrinking, or changing an earlier id raise in `strict`; cumulative ids running ahead of the token count do not.
- `test_think_start_after_text_keeps_matching_by_id`: the same result one-shot and streamed whole, cut right before `<think>`, or token by token.
- `test_strict_mode_refuses_text_past_its_output_ids`: text the ids do not render fails one-shot and streamed in every chunking (whole, each single cut, token by token; incremental and cumulative): an empty id list with text, U+FFFD or a special token's text; U+FFFD with no held bytes; a special token's text with no special id, at the end or inside; and text past the ids in the `glm47` stream.
- `test_held_bytes_and_special_tokens_source_the_end_of_text`: a held character, held bytes then a special token, a special token then held bytes, a kept special token, and trimmed stop text parse to the full `(reasoning, content)` one-shot and streamed in every chunking, with special tokens kept or skipped; each chunk's ids are observed before its text is parsed.
- `test_special_tokens_keep_matching_by_id_around_them`: a special token held behind an unfinished character with text after it, and a special token followed by its own spelled text, give the full `(reasoning, content)` with spelled and control `</think>` told apart, in `strict` and `auto`, with special tokens kept or skipped, one-shot and streamed in every chunking (incremental and cumulative ids, text whole or one character at a time).

Serving routing (synthetic byte-level tokenizer with the GLM markers added):

- `test_serving_chat.py`: Chat with `n=2`, non-streaming and both streaming modes; Anthropic `/v1/messages`, non-streaming and both streaming modes; `strict` startup refusal, `500` on non-streaming disagreement, and a `500` stream error event, with no stop chunk, for disagreeing text and for text past the ids in both streaming modes.
- `test_serving_responses_stream.py`: Responses, non-streaming and both streaming modes; `strict` text past the ids ends in `response.failed`.

Removing any of eight id hand-offs in `serving_chat.py` / `serving_responses.py` turns at least one of these tests red.

A one-off differential check over 3000 random GLM-5.3 outputs (control tokens mixed with spelled markers) found `glm47` and `glm45` one-shot results identical to #45587, with and without output ids.

CPU suites `unit/function_call`, `unit/parser`, `unit/entrypoints/openai`, `unit/entrypoints/anthropic` and `unit/server_args`: 2133 passed, 1 skipped. Three tests fail identically on #45587: `test_validation_errors_are_422_on_this_route_only` and two `test_server_args` tests.
