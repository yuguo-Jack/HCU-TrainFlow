# [Bugfix] Retain global embedding cache hits through output assembly

[Upstream PR](https://github.com/sgl-project/sglang/pull/42060) · state: closed · merged: False

## Original PR description

## Motivation

With the global multimodal embedding cache enabled, a request can validate a cached hit and then evict it while staging another item's newly encoded embedding into the same host pool. The GPU output path then raises `Cached embedding ... disappeared during assembly`; fallback staging can also invalidate a hit needed by the CPU output path.

## Modifications

Atomically retain READY cache entries before computing the fallback mask. Keep those entries pinned through staging and output assembly, and release them when the request exits that scope, including exceptions and cancellation. Deduplicate repeated hashes and release only the references acquired by this scope. Preserve the existing rank-zero cache access and collective ordering.

Add CPU regressions for allocation pressure, nested and duplicate pins, partial prefetch, eviction before retention, entry replacement, exceptional exits, and encoder orchestration.

## Accuracy Tests

- Actual encoder/controller source reproduction: before the fix, a one-page pool with one cached hit and one new item raises the missing-hit error. After the fix, the same path assembles the expected cached and newly computed values, with the retained entry's final pin count equal to zero.
- **34 CPU tests passed**: 26 controller tests and all eight encoder global-cache tests, including six staging/assembly success, exception, and cancellation subcases.
- The local harness loads the actual source definitions while excluding GPU-facing import initializers. The end-to-end orchestration reproduction uses real CPU tensors and explicit model/CUDA stream/transfer boundary doubles. Two unchanged Mooncake wrapper tests require the unavailable full import environment and were excluded. No GPU or Mooncake transport run is claimed.

## Speed Tests and Profiling

No inference performance claim. Under pool pressure, optional staging may skip a new cache entry while its already computed tensor supplies the current request's output.
