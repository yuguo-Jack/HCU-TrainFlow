# [Perf] deepseek-v4.1: Default decoder SWA bounded replay on for both PD roles on CUDA

[Upstream PR](https://github.com/sgl-project/sglang/pull/45035) · state: closed · merged: True

## Original PR description

- Decoder SWA bounded replay now defaults on for PD prefill and decode workers on CUDA, as it already does for standalone servers (`python/sglang/srt/arg_groups/deepseek_v4_hook.py`). PD on ROCm keeps the explicit `--enable-decoder-swa-bounded-replay`, since replay has not been run there under PD.
- The cookbook's sentence on the default now names the PD roles.
- Checked on GB300 with DeepSeek-V4.1-Flash: one DEP2 prefill worker (encoder SWA bounded replay on) and one DEP2 decode worker, DSpark block 5, MegaAttention, MegaMoE, Mooncake, without the replay flag. Both workers log `DeepSeek-V4.1 decoder SWA bounded replay resolved to True`; GSM8K with sgl-eval (1,319 questions, greedy, thinking off) behind a shared 8-shot prefix scores 97.12% with zero KV transfer failures. PD runs with the flag set by hand were checked in #44952.

Behavior change: CUDA PD workers that did not pass the flag now run bounded replay; `--no-enable-decoder-swa-bounded-replay` keeps full prefill.
