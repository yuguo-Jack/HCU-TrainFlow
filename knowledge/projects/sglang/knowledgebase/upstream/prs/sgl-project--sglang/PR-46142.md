# [Fix] diffusion/server: Clean up workers on startup failure

[Upstream PR](https://github.com/sgl-project/sglang/pull/46142) · state: closed · merged: True

## Original PR description

## Summary

The three diffusion launchers wait for startup pipes in rank order. If a later rank exits while an earlier rank is still initializing (for example, waiting in NCCL), startup can remain blocked. Pool and standalone-role launchers also retain parent-side pipe writers, hiding EOF. A failed later pool role can leave earlier roles running.

- Share one spawn/readiness helper across monolithic, local-pool and standalone-role launchers. Start every rank before waiting, then watch both startup pipes and all child process sentinels.
- Close parent-side pipe handles and terminate/reap started workers on startup errors, spawn failures or interrupts.
- Clean up previously started pool roles and the router when a subsequent startup step fails.
- Preserve the spawn bootstrap contract and rank/device mapping. No new flags, polling loop, runtime work or production modules; production code is 52 lines smaller.

## Validation

Tested at `3c1c895f8f94` on Linux with 2x H200, Python 3.12.15, PyTorch 2.14.1+cu130, diffusers 0.37.0 and transformers 5.19.0.

- Related shutdown, worker-bootstrap and load-inclusive timing suites: **38 passed, 13 subtests passed**.
- Real child-process tests cover out-of-order readiness, later-rank exit, explicit startup error, EOF while a child remains alive, a ready rank exiting, spawn failure and interruption. Pool tests also cover a later-role failure and router-bind failure.
- GPU fault injection reproduced blocked startup on `74c08f3dc5d` in all three launch paths. The fix reports the failed rank after cleanup in **90 ms / 81 ms / 83 ms** (monolithic / local pool / standalone role), with no live child processes on return. With an encoder already loaded, a failing denoiser is reported after cleanup in **2.29 s**.
- Real Wan2.1-T2V-1.3B generation passed for single-GPU, two-GPU, local-pool and independently launched encoder/denoiser/decoder paths: 512x320, 17 frames, 4 steps, seed 42, FA. The two-GPU decoded frames are byte-identical to the same-configuration baseline; the single-rank paths also agree with each other. No GT or thresholds changed.
- Pre-commit passed. No startup-speed claim is made from the single-sample smoke timings.

This handles observable startup failures, not arbitrary hangs in still-live workers. It does not add automatic restarts or durable job recovery. Runtime readiness monitoring remains separate in #46025.
