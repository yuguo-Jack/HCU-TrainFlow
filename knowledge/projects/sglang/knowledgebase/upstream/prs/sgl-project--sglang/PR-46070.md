# [Refactor] openai: drop unreachable request-id code in serving base

[Upstream PR](https://github.com/sgl-project/sglang/pull/46070) · state: open · merged: False

## Original PR description

## What

`_generate_request_id_base()` in `serving_base.py` returns `None` unconditionally, so the code below it could never run:

```python
return None

# TODO(chang): the rid is used in io_strcut check and often violates ...
if rid := getattr(request, "rid", None):
    return rid

return f"{self._request_id_prefix()}{uuid.uuid4().hex}"
```

The `uuid` import exists only for that unreachable line. Anything added under the `return None` inherits the same problem, which is how this survived: the deferral note reads like an explanation of live code.

## Change

- Move the TODO up as a comment on `return None` so the deferral is still documented where the implementation will go.
- Delete the unreachable tail and the now-unused `uuid` import.

No behaviour change: the method returned `None` before and returns `None` after. `_request_id_prefix` is left alone — it is called live by the OCR streaming path (`models/unlimited_ocr_v2_support/chat.py`) and several serving classes, and the removed line was not its only user.

## Scope

Single file, +4/−8, no test. The earlier revision of this PR added an `ast` test asserting that no statement follows the unconditional return; it has been dropped. That guard is closer to a linter than a test — it pins one private method's name and shape for 55 lines — and the shape it protected is now simply gone.

`black --check` and `ruff check --select F,E9` are clean on the file.
