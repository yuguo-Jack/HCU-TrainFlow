# [Perf] wan2.2-s2v: Compute RoPE in fp32 via _apply_rotary_emb, as in wanvideo.py

[Upstream PR](https://github.com/sgl-project/sglang/pull/44756) · state: open · merged: False

## Original PR description

Routes Wan2.2-S2V's RoPE through `_apply_rotary_emb` in fp32, **matching the existing Wan I2V path in `wanvideo.py`** rather than introducing a new mechanism. Device-agnostic; no XPU-specific code.

## Change
S2V built its rotary embedding inline with a different dtype policy from its sibling model. This reuses `wanvideo.py`'s helper so the two Wan DiTs apply RoPE identically.

1 file (`dits/wan_s2v.py`), +23/−15.

## Measured
2 × B60, SP=2 Ulysses, 576×768, `dit=layerwise-offload`: **−8.3 % per step (−3.3 s/step)**. The saving comes from dropping fp32 intermediate concatenations, not from lower precision — the rotary math stays in fp32, as in `wanvideo.py`.

## Review note
This changes RoPE's numerics relative to the previous S2V path (it now matches `wanvideo.py` instead). Output parity was checked by eye on the reference clip, **not** bit-exactly — if upstream wants a stricter bar, say so and I will add a numerical comparison against the pre-change path.

## Base
⚠️ **Stacked on #43279** (the S2V port), included here as the first commit. Independent of #44755, the wav2vec2 fix (audio encoder only). **The modulation-fusion PR (#43288, retitled) is stacked on top of this one** — its modulation-fusion commit builds on this one, so merge this first.

Split out of #43288.
