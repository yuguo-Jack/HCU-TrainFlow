- zhangxiaolei123456 · comment · 2026-09-05T01:55:58Z · [source](https://github.com/sgl-project/sglang/pull/36449#discussion_r3939068250)

Thanks, I follows the same direction as #24932. This PR avoid registering draft/MTP state as a second component with the same state type and relying on occurrence-based matching. Instead, we pack the draft DSv4 SWA state into the same logical SWA component:

- paged layout: target + draft state are packed under one StateType.SWA
- unified_kv layout: target + draft SWA ring state are packed under one StateType.SWA_RING

This makes the transport metadata cleaner and removes the need to distinguish “the first SWA” vs “the second SWA”.

- zhangxiaolei123456 · comment · 2026-09-05T12:38:36Z · [source](https://github.com/sgl-project/sglang/pull/36449#discussion_r3940652387)

File: `python/sglang/srt/disaggregation/mooncake/conn.py` · line None

Remove the state component type metadata completely, but that would make the registration rely only on positional component indices. That is fragile for heterogeneous state layouts.

For example, one side may register components as:

prefill: [SWA, C128_STATE]
decode:  [SWA, SWA_RING, C128_STATE]

Without sending the component types, component index 1 from prefill would be matched to index 1 on decode, incorrectly mapping C128_STATE to SWA_RING. `state_layer_ids` cannot fully solve this because it only identifies entries inside a component; it does not describe the semantic type of the component itself.

So the cleanup keeps the wire metadata, but renames it to `state_component_types` and removes the old duplicate-occurrence matching logic. This preserves safe matching for heterogeneous components while dropping the original duplicated-SWA design.
