# [multimodal] Stop packing per-image features only to split them again

[Upstream PR](https://github.com/sgl-project/sglang/pull/41014) · state: closed · merged: False

## Original PR description

**1 of 3** on multimodal feature handling (#41014, #41015, #41016). Independent of the other two.

## Motivation

Several processors build one tensor per image, `torch.cat` them into one request-wide buffer, and hand that to the scheduler — which splits it straight back apart in `get_new_expanded_mm_items` so each image can be hashed and cached on its own.

`internvl` does both halves in the same function, a few lines apart:

```python
image_tensor = torch.cat(pixel_values_list, dim=0)
...
cumulative = 0
for i, num_patches in enumerate(num_patches_list):
    items.append(MultimodalDataItem(
        feature=image_tensor[cumulative : cumulative + num_patches], ...))
    cumulative += num_patches
```

`num_patches_list[i]` is `tiles.shape[0]`, so each slice reconstructs its input tensor exactly. The concatenation is a second request-sized allocation standing alongside the parts it copies, and nothing ever reads it whole.

## Modifications

Keep the per-image list. No new type is needed — the framework already carries one end to end: `_try_simple_split` slices a list by index, `hash_feature` hashes one, `_move_feature_to_cpu` recurses into it. `nano_nemotron_vl`'s dynamic-resolution branch has always done this.

- **`internvl`** — both text paths consume `pixel_values_list` directly. A net deletion.
- **`mimo_v2`**, **`nano_nemotron_vl`** — hand the list over instead of packing it.

`nano_nemotron_vl`'s static branch also regains cache granularity it had silently lost. It packed one tiles tensor per image and handed the result to the EVS item factory, which makes a single bundled item; `_try_simple_split` requires `feature_count == num_items`, so with more than one tile per image the packed rows outnumbered the placeholders and the split declined. Nothing was corrupted — the guard declines rather than mis-slicing — but per-image caching was lost for every multi-tile request.

## Result

One extra full copy of the features, at every request size — a flat **50% of peak feature memory** — and it is gone. It scales with images × resolution.

## Tests

- New `test_per_image_feature_lists.py`: ragged lists split per image; a packed multi-tile tensor declines to split; lists hash and move to CPU.
- End-to-end A/B over single, paired, tripled, repeated and quadrupled images: answer text, prompt/completion token counts and the per-prefill cached-token sequence matched byte for byte.
- `test/registered/unit/multimodal/` green; `isort` / `ruff check` / `ruff format` clean.
