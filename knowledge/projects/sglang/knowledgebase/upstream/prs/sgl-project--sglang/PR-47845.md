# [Fix] mem_cache: report Mamba state cache when it exhausts the KV budget

[Upstream PR](https://github.com/sgl-project/sglang/pull/47845) · state: open · merged: False

## Original PR description

## Motivation

Thank you to @victrgao for the detailed report and the root-cause analysis.

Serving a hybrid linear-attention model (Qwen3.5-9B, Gated DeltaNet) with native MTP through EAGLE fails at startup with an error whose advice cannot be followed:

```
ValueError: Loaded weights leave no GPU memory for the KV cache under --mem-fraction-static=0.9. Raise --mem-fraction-static above 0.693 (minimum viable = 1 - available/pre = 0.6928). If using speculative decoding, draft weights are now counted.
```

The value in use (0.9) is already above the suggested one (0.693), and the server starts as soon as `--max-running-requests` is lowered from 64 to 15. The memory that is missing is the Mamba state cache, not the weights. In `_profile_available_bytes` (`python/sglang/srt/mem_cache/kv_cache_configurator.py`), `rest_memory` is reduced by `_handle_max_mamba_cache(rest_memory)`, and when the result is below zero the error computes the "minimum viable" fraction as `1 - available_gpu_memory / pre_model_load_memory`, a bound that only accounts for weights. Whenever the Mamba reservation is what drives `rest_memory` below zero, the message recommends a fraction lower than the one in use and never mentions `--max-running-requests`.

Fixes #47830.

## Modifications

In `_profile_available_bytes` only:

- Record the budget before `_handle_max_mamba_cache` runs.
- When the pre-Mamba budget is positive and the reservation drives it to zero or below, raise a Mamba-specific error that reports the reservation size (the total amount `_handle_max_mamba_cache` subtracts, which includes speculative-decoding scratch when applicable) and suggests lowering `--max-running-requests`, capping the state cache with `--max-mamba-cache-size`, or reducing `--speculative-num-draft-tokens`.
- The existing weights-only error is unchanged for budgets already exhausted before the Mamba reservation and for non-Mamba models, and the sizing arithmetic itself is untouched, so this change has no effect on model outputs or inference speed.

Added `test/registered/unit/mem_cache/test_kv_cache_configurator_mamba_error.py` with four cases:

- Mamba-driven exhaustion names the Mamba options (fails before the fix).
- Zero rest after the Mamba reservation names the Mamba options.
- Weights-only exhaustion keeps the `--mem-fraction-static` advice.
- Mamba present but weights already exhausted keeps the old advice.

## Reproduction

No GPU run is claimed here: this environment has no ROCm GPU, so the reproduction below is at the logic level. It loads the real `kv_cache_configurator.py` with its heavy imports (torch, sglang modules) stubbed out and exercises the real `_profile_available_bytes` with the reporter's numbers: 31.57 GB device, 9.70 GB available after weights, `--mem-fraction-static` 0.9 (3.16 GB static slack, 6.54 GB left before the Mamba reservation), and an 8.00 GB Mamba reservation for 64 running requests.

```python
"""Logic-level reproducer for sgl-project/sglang#47830.

No GPU, no torch: the real kv_cache_configurator.py is loaded with its
heavy imports stubbed out, and _profile_available_bytes is exercised with
the reporter's numbers (31.57 GB device, 17.63 GB target weights +
4.24 GB draft weights leaving 9.70 GB available, --mem-fraction-static 0.9,
Mamba reservation of 8.00 GB for 64 running requests).

Usage: python3 repro_47830.py <path-to-kv_cache_configurator.py>
"""

import ast
import importlib.util
import sys
import types
from types import SimpleNamespace
from unittest.mock import MagicMock


def load_module_with_stubs(path):
    with open(path) as f:
        tree = ast.parse(f.read())
    # Pre-register every imported dotted module name (and its prefixes)
    # as a stub so the real file can be exec'd without torch/sglang deps.
    # Stdlib modules (dataclasses, typing, gc, ...) stay real: stubbing
    # dataclasses would turn @dataclass into a MagicMock and swallow the
    # class under test.
    STUB_TOP = {"torch", "msgspec", "sglang"}
    names = set()
    for node in ast.walk(tree):
        if isinstance(node, ast.Import):
            for alias in node.names:
                names.add(alias.name)
        elif isinstance(node, ast.ImportFrom) and node.module:
            names.add(node.module)
    names = {n for n in names if n.split(".")[0] in STUB_TOP}
    for name in sorted(names):
        parts = name.split(".")
        for i in range(1, len(parts) + 1):
            prefix = ".".join(parts[:i])
            if prefix not in sys.modules:
                mod = types.ModuleType(prefix)
                mod.__path__ = []
                sys.modules[prefix] = mod
    for name in sorted(names):
        parts = name.split(".")
        parent = ".".join(parts[:-1])
        if parent and parent in sys.modules:
            setattr(sys.modules[parent], parts[-1], sys.modules[name])
    # Leaf stubs must allow arbitrary attribute access (from X import Y).
    for name in names:
        mod = sys.modules[name]
        if not isinstance(mod, MagicMock):
            mock = MagicMock(name=name)
            mock.__path__ = []
            sys.modules[name] = mock
            parts = name.split(".")
            parent = ".".join(parts[:-1])
            if parent in sys.modules:
                setattr(sys.modules[parent], parts[-1], mock)
    spec = importlib.util.spec_from_file_location("kcc_under_test", path)
    mod = importlib.util.module_from_spec(spec)
    sys.modules["kcc_under_test"] = mod
    spec.loader.exec_module(mod)
    return mod


def run_case(kcc, *, available_gb, mamba_reserve_gb, mambaish,
             mamba_absolute=None):
    cfg = kcc.KVCacheConfigurator.__new__(kcc.KVCacheConfigurator)
    cfg.device = "cpu"
    cfg.gpu_id = 0
    cfg.mambaish_config = SimpleNamespace() if mambaish else None
    cfg.post_capture_kv_active = False
    cfg.model_config = SimpleNamespace(is_multimodal=False)
    # slots=True dataclass: patch the method on the class, not the instance.
    if mamba_absolute is not None:
        kcc.KVCacheConfigurator._handle_max_mamba_cache = (
            lambda self, rest: mamba_absolute
        )
    else:
        kcc.KVCacheConfigurator._handle_max_mamba_cache = (
            lambda self, rest: rest - mamba_reserve_gb
        )
    kcc.get_available_gpu_memory = lambda *a, **k: available_gb
    kcc.get_parallel = lambda: SimpleNamespace(
        launch_world_size=1, world_group=SimpleNamespace(cpu_group=None)
    )
    kcc.get_schedule = lambda: SimpleNamespace(
        mem_fraction_static=0.9,
        prefill_max_requests=None,
        max_mamba_cache_size=None,
        max_running_requests=64,
    )
    kcc.get_disagg = lambda: SimpleNamespace(disaggregation_mode="decode")
    kcc.get_exec = MagicMock()
    kcc.get_mm = lambda: SimpleNamespace(mm_feature_transport=None)
    kcc.mm_runtime_reservation_gb = lambda **k: 0.0
    try:
        result = cfg._profile_available_bytes(31.57)
        return f"OK: {result} bytes"
    except ValueError as e:
        return f"ValueError: {e}"


def main():
    path = sys.argv[1]
    kcc = load_module_with_stubs(path)
    print("== case 1: Mamba reservation drives rest_memory below zero ==")
    print(run_case(kcc, available_gb=9.70, mamba_reserve_gb=8.00, mambaish=True))
    print("== case 2: weights alone exhaust the budget (no Mamba) ==")
    print(run_case(kcc, available_gb=2.00, mamba_reserve_gb=0.0, mambaish=False))
    print("== case 3: Mamba present but weights already exhaust budget ==")
    print(run_case(kcc, available_gb=2.00, mamba_reserve_gb=8.00, mambaish=True))
    print("== case 4: pre-Mamba rest negative (weights-only message) ==")
    print(run_case(kcc, available_gb=3.00, mamba_reserve_gb=1.00, mambaish=True))
    print("== case 5: post-Mamba rest exactly 0.0 (Mamba message) ==")
    print(run_case(kcc, available_gb=9.70, mamba_reserve_gb=0.0,
                   mambaish=True, mamba_absolute=0.0))


if __name__ == "__main__":
    main()
```

Before the fix (unpatched file), case 1 reproduces the reported misleading message, while cases 2 and 3 show the weights-only message:

```
== case 1: Mamba reservation drives rest_memory below zero ==
ValueError: Loaded weights leave no GPU memory for the KV cache under --mem-fraction-static=0.9. Raise --mem-fraction-static above 0.693 (minimum viable = 1 - available/pre = 0.6927). If using speculative decoding, draft weights are now counted.
== case 2: weights alone exhaust the budget (no Mamba) ==
ValueError: Loaded weights leave no GPU memory for the KV cache under --mem-fraction-static=0.9. Raise --mem-fraction-static above 0.937 (minimum viable = 1 - available/pre = 0.9366). If using speculative decoding, draft weights are now counted.
== case 3: Mamba present but weights already exhaust budget ==
ValueError: Loaded weights leave no GPU memory for the KV cache under --mem-fraction-static=0.9. Raise --mem-fraction-static above 0.937 (minimum viable = 1 - available/pre = 0.9366). If using speculative decoding, draft weights are now counted.
```

After the fix, case 1 names the Mamba reservation and the actionable options, and cases 2 to 4 are unchanged:

```
== case 1: Mamba reservation drives rest_memory below zero ==
ValueError: Mamba state cache leaves no GPU memory for the KV cache under --mem-fraction-static=0.9. The Mamba state cache reservation is 8.00 GB, leaving no room in the 6.54 GB available after weights and the static slack. Try: (1) reduce --max-running-requests, (2) cap the state cache with --max-mamba-cache-size, or (3) reduce --speculative-num-draft-tokens.
== case 2: weights alone exhaust the budget (no Mamba) ==
ValueError: Loaded weights leave no GPU memory for the KV cache under --mem-fraction-static=0.9. Raise --mem-fraction-static above 0.937 (minimum viable = 1 - available/pre = 0.9366). If using speculative decoding, draft weights are now counted.
== case 3: Mamba present but weights already exhaust budget ==
ValueError: Loaded weights leave no GPU memory for the KV cache under --mem-fraction-static=0.9. Raise --mem-fraction-static above 0.937 (minimum viable = 1 - available/pre = 0.9366). If using speculative decoding, draft weights are now counted.
== case 4: pre-Mamba rest negative (weights-only message) ==
ValueError: Loaded weights leave no GPU memory for the KV cache under --mem-fraction-static=0.9. Raise --mem-fraction-static above 0.905 (minimum viable = 1 - available/pre = 0.9050). If using speculative decoding, draft weights are now counted.
== case 5: post-Mamba rest exactly 0.0 (Mamba message) ==
ValueError: Mamba state cache leaves no GPU memory for the KV cache under --mem-fraction-static=0.9. The Mamba state cache reservation is 6.54 GB, leaving no room in the 6.54 GB available after weights and the static slack. Try: (1) reduce --max-running-requests, (2) cap the state cache with --max-mamba-cache-size, or (3) reduce --speculative-num-draft-tokens.
```

Note: the small difference between the issue's 0.6928 and the reproducer's 0.6927 comes from the reporter's rounded figures (9.70 GB / 31.57 GB) rather than the exact device values.
