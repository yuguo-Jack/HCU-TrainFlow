# [Spec] Fix trtllm_mha draft startup on GLM-5.3-Flash

[Upstream PR](https://github.com/sgl-project/sglang/pull/45115) · state: open · merged: False

## Original PR description

## Motivation

Since #42178, GLM-5.3-Flash runs with 256-token pages (64 * `index_kpool`). With `--speculative-draft-attention-backend trtllm_mha`, the trtllm_mha page check resets the page size to 64, and the DSA pool fails at startup:

```
AssertionError: DSA requires 64-token physical pages, got page_size=64 with index_kpool=4
```

## Modifications

- Keep a DSA model's 64 * `index_kpool`-token page when trtllm_mha is the draft backend.
- In `TRTLLMHAAttnBackend`, read a page over 128 tokens as consecutive 64-token pages. HND KV pools aren't supported for this and raise an error.

Why not read the 256-token pages directly? trtllm-gen can, but only for GQA drafts, and allowing it in the page check would affect every model on trtllm_mha. Reading 64-token pages works for any draft and only touches DSA models.

## Accuracy Tests

GLM-5.3-Flash NVFP4 on 2x B300 with a DFlash draft on trtllm_mha scores 0.927 on GSM8K, the same as a build from before #42178 that ran the draft on 64-token pages.

Unit tests cover the DSA page staying at 256 with a trtllm_mha draft (fails on main) and the backend's 64-token page choice and HND error.

## Speed Tests and Profiling

N/A. The draft kernels run on 64-token pages, as they did before #42178.
