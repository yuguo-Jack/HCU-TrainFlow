# [dLLM] Preserve literal mask text in prompts

[Upstream PR](https://github.com/sgl-project/sglang/pull/35998) · state: open · merged: False

## Original PR description

## Motivation

dLLM decoding masks are framework-owned, but supported tokenizers currently encode literal prompt text such as `<|mask|>` as the reserved model mask ID. dLLM algorithms can then mistake that prompt position for the start of the decoding block and modify prompt content.

This common-path fix unblocks #31773.

## Modifications

- Reuse the supported dLLM model parameters in the tokenizer manager to identify the reserved mask ID without loading the model configuration a second time.
- Create a private tokenizer configured to split the reserved mask token, and retokenize only mask-containing text spans so surrounding BPE context is retained.
- Apply the same normalization to text-derived generation prompts, `/tokenize`, and native gRPC `Tokenize`, while preserving unrelated added and chat-template control tokens.
- Reject caller-provided prompt `input_ids` containing the reserved mask ID instead of silently rewriting them.
- Add focused unit coverage for contextual and adjacent masks, control-token boundaries, non-special mask metadata, reusable tokenization IDs and counts, direct IDs, unsupported tokenizer behavior, and the non-dLLM path.

## Accuracy Tests

This does not change model forward or kernel code.

Verified with the official `inclusionAI/LLaDA2.2-flash` tokenizer:

- Default tokenization maps literal `<|mask|>` to `156895`.
- Contextual normalization removes the reserved mask ID, preserves the exact decoded text, and retains whitespace and adjacent-mask BPE merges.
- Neighboring `<|role_end|>` remains the original special token.

## Speed Tests and Profiling

No model execution path changes. The private tokenizer is created once at startup. Non-dLLM requests return immediately; dLLM prompt normalization scans for the reserved mask ID and only decodes and re-encodes spans that contain it.
