# [Fix][Spec] Bound draft-extend replay metadata to graph buckets

[Upstream PR](https://github.com/sgl-project/sglang/pull/36913) · state: open · merged: False

## Original PR description

## Motivation

Draft-extend CUDA graph replay pads a runtime batch to a captured graph bucket.
The manual replay views report the selected bucket as `batch_size`, but expose
maximum-capacity `req_pool_indices`, `seq_lens`, and optional
`seq_lens_cpu` tensors. They also omit `num_padding`.

Backends that derive replay metadata from tensor length or padding count can
therefore read rows outside the selected bucket. The single-layer runner and
the reachable per-step multi-layer runner have the same mismatch.

## Modifications

- Bound request indices and device/CPU sequence lengths to `[:bs]` in both
  manual draft-extend replay views.
- Pass `num_padding=bs-raw_bs` while preserving padding rows and
  `seq_lens_cpu=None`.
- Add CPU regressions for padded and exact buckets, present and absent CPU
  mirrors, and buffer capacity larger than the replay bucket.

No attention kernel, model arithmetic, cache-location layout, or Qwen-specific
code changes.

- ClaudeLiang · comment · 2026-11-03T17:50:28Z · [source](https://github.com/sgl-project/sglang/pull/36913#issuecomment-6611380134)

We hit this independently on an out-of-tree Cambricon MLU backend, so adding a data point here instead of opening a duplicate.

**Observed effect.** MLU590, TP4, MTP (NEXTN, topk=1), bs=8, draft-extend replayed from a graph:

| Draft-extend | Accept length |
|---|---|
| eager | 3.10 |
| graph replay | 2.28 |
| graph replay, backend slices its inputs to `batch_size` | 3.10 (ITL p50 −7.5 ms) |

The MLU backend took the batch size from `seq_lens.shape[0]`, so on replay it saw `max_bs` rows and refreshed the metadata for the wrong bucket. We currently work around it inside the backend; the change in this PR fixes it at the source, and with it we can drop the workaround.

**Why CUDA doesn't show it.** The in-tree backends that serve `DRAFT_EXTEND_V2` (Triton, FlashAttention, FlashInfer, DSA, …) already slice to `bs` themselves, so the full-length view is masked there. Any backend that infers the batch from tensor length hits it.

**Tests on current main.** The test file no longer runs against main because of API drift: `EAGLEDraftExtendCudaGraphRunner.execute()` now requires `select_index`, it reads `model_runner.model_config`, and `MultiLayerEagleDraftExtendCudaGraphRunner.replay()` now requires `out_cache_loc_virtual` / `iteration_ids` / `iteration_cols`. I have a version rebased on current main with the same two view changes and the same six scenarios (both runners, padded and exact bucket, CPU mirror present/absent). All six fail with the two hunks reverted and pass with them.

@ArthurOstapenko are you still planning to land this? I'm happy to post the rebased patch here for you to pick up, or, if you'd rather hand it off, open a replacement PR that credits this one.
