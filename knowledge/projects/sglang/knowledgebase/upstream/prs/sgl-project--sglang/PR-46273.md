# [Fix] session: Order a waiting streaming-session turn under dfs-weight

[Upstream PR](https://github.com/sgl-project/sglang/pull/46273) · state: open · merged: False

## Original PR description

## Motivation

With `--enable-streaming-session` and `--schedule-policy dfs-weight`, the scheduler crashes as soon as a later streaming-session turn waits in the queue.

That turn's prefix match returns its session slot's virtual node (`StreamingSession.try_match_prefix`), which has no path in the tree. `SchedulePolicy._sort_by_dfs_weight` hands every waiting request's `last_node` to `UnifiedRadixCache.dfs_weight_order`, and the tree core cannot resolve the virtual node:

- Python tree core: `KeyError: <..._VirtualNode object at ...>`
- Rust tree core: `TypeError: '_VirtualNode' object cannot be interpreted as an integer`

Both raise inside `get_new_batch_prefill`, so the whole scheduler goes down. Locking already treats the virtual node as a special case (`UnifiedRadixCache.lock`), but the dfs-weight ordering does not.

## Modifications

- `UnifiedRadixCache.dfs_weight_order` replaces a virtual node with the root handle before calling the tree core, so a session turn is ordered with the requests that match nothing in the tree. Its KV lives in the session slot, not in a subtree the sort could group it with.
- New test `TestStreamingSessionLockLifecycle.test_dfs_weight_policy_orders_a_waiting_session_turn`. It builds a real later turn whose `last_node` is the slot's virtual node, puts it in a waiting queue with a plain request, runs `SchedulePolicy("dfs-weight", ...).calc_priority`, and finishes with `sanity_check`.
