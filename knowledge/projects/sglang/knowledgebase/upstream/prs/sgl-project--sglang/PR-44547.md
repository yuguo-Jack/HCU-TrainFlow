# [Perf] [AMD] spec: Split greedy-verify argmax and prefer aiter tuned bf16 rows on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/44547) · state: closed · merged: False

## Original PR description

> Kimi-K3 on gfx950 series (all drafts): #44547 gfx950 verify argmax + tuned rows, #44548 KDA, #44549 MLA decode, #44550 MLA prefill, #44551 → #44552 → #44553 collectives, MoE decode, MoE prefill. The end-to-end numbers in each PR are for all seven together.

## Motivation

Two gfx950 decode costs outside any model's kernels: greedy EAGLE verify takes `torch.argmax` over wide vocabularies
(163,840 for Kimi-K3), which reduces each row on one workgroup, and on ROCm the verify results then go out as three
rank-0 broadcasts; and `UnquantizedLinearMethod` sends bf16 shapes that aiter's merged tuned table has measured rows
for to the Triton a16w16 path instead.

## Modifications

- Greedy verify on gfx950 with a vocabulary of at least 32K: `topk1.split_argmax` (the draft top-1 kernels' split
  argmax + a finalize kernel; first-max tie order, NaN ranks below every finite logit). The three verify outputs are
  views of one int32 buffer, so the rank-0 broadcast is a single collective (other platforms keep their allocations
  and broadcasts).
- gfx950 bf16 linears whose shape has a measured row in aiter's tuned table (`"us"` in the config) go to `tgemm.mm`
  ahead of the Triton a16w16 path.

## Accuracy Tests

**Setup for every number below:** 8x MI350X (gfx950, 1000 W), Kimi-K3 (MXFP4 MoE, bf16 attention) at TP8 with EAGLE3
(topk 1, 3 steps, 4 draft tokens), FP8 KV cache, `SGLANG_USE_AITER=1`, aiter's K3 FlyDSL kernels
(`AITER_SITUV2_A8W4=1 AITER_FLYDSL_FORCE=1 SGLANG_AITER_K3_OPT=1`), CUDA graphs for bs 1/2/4/8/16, and an aiter bf16 GEMM table with K3 rows re-tuned on this pod with HBM-resident weights
(`AITER_CONFIG_GEMM_BF16`; not part of this PR, it belongs in aiter's model configs). EAGLE3 on K3 needs the
aux-capture commit of #43599, applied locally for these runs. Microbenchmarks rotate their weights through HBM.
Per-feature numbers were measured on the integration branch of this series as each piece landed (Oct 13-14,
earlier `main`); the end-to-end numbers are from the integration of all seven PRs rebased on `main` b67785153a,
together with #43599's aux capture, #41867 and #41848.

- `test_spec_topk1.py` (new case): equal maxima in different vocab splits resolve to the lowest index and a NaN logit
  does not win, at 1 / 4 / 64 rows of a 163,840 vocabulary.
- End-to-end integration: see below.
