# [Feat] simulator: Add optional InferCast latency and KV budgets

[Upstream PR](https://github.com/sgl-project/sglang/pull/36069) · state: open · merged: False

## Original PR description

## Motivation

Allow SGLang Simulator to use InferCast for prepared model-forward latency and independent KV capacity estimation. Scheduling, prefix-cache behavior, chunk admission and simulation time remain owned by SGLang.

## Modifications

- Add an optional InferCast predictor through the existing predictor interface, preserving ordered EXTEND/MIXED shapes, DECODE histories, explicit unsupported errors and milliseconds-to-seconds conversion.
- Opt prepared-batch metadata and OFFLINE predictor-query time exclusion into the new predictor; retain existing predictor behavior.
- Add independent resource budgets through the InferCast SDK and translate logical capacity through SGLang's native pool-sizing functions.
- Keep CPU dummy initialization from importing accelerator kernels, including lazy AITER loading in the Quark helper.
- Add adapter, bootstrap, scheduler and budget tests, the opt-in real-provider HTTP suite and one eager R1 configuration. Include the resource-budget suite in CPU CI.

The five commits separate CPU bootstrap, prepared-forward hooks, latency provider, KV budgets and HTTP tests/CI. The latency provider currently supports canonical DeepSeek-R1 with matching measured inputs; the budget adapter accepts the explicitly supported ordinary decoder cache layouts. Existing Markdown/MDX files are unchanged.

## Accuracy Tests

- Six focused simulator suites: **180 passed / 11 skipped** after rebasing on `b6d3b7e163`. Four skips require local Torch and seven require explicit real-provider HTTP inputs.
- Resource-budget suite: **44 passed**, including a small-model test against the actual InferCast resource SDK. YAML parsing and `git diff --check` passed.
- Recorded `8ec7c55d1cd04af35252cac6f2c1467ee65135b2` HTTP suite with the merged SDK tree: **9 passed** (7 real-provider HTTP cases and 2 launcher configuration tests), including eager EXTEND/DECODE, chunking, prefix reuse, MIXED, BLOCKING arrivals, independent R1 KV sizing and generic Qwen replay with InferCast budgets. CPU validation uses `SGLANG_ENABLE_HEALTH_ENDPOINT_GENERATION=0` because the native generated-health endpoint polls for at least one second while this suite's probe timeout is one second; subsequent `/generate` calls exercise the simulator HTTP generation and scheduler path.

Review follow-up: loaded-model latency validation still needs complete quantization/MoE structure binding. These results use the canonical matching R1 configuration.

## Historical serving comparison (diagnostic)

Compare the **recorded CPU simulator at `8ec7c55d1cd04af35252cac6f2c1467ee65135b2`** with frozen DeepSeek-R1 serving measurements collected on **two 8 x MI355X hosts on 2026-09-19**. Target configuration: TP8/EP2/PP1, BF16 attention, FP8 weights/KV, page size 1, fixed 65,536-token capacity and 16 output tokens per request. The graph profile uses piecewise prefill and full decode capture. This is a post-hoc regression against historical GPU evidence; no new GPU measurements or refitting are involved.

Nine workloads cover cold prompts, prefix reuse, ragged B1/B2/B4/B8, chunked prefill and combined prefix/chunk behavior. Each has eager and graph profiles, with five CPU repetitions compared against five real repetitions per host: **18 simulator points / 90 runs, 36 paired comparisons / 180 historical GPU runs**. All repetitions and cases are retained, including the first repetition.

MAPE is the equally weighted mean of per-case absolute percentage errors, computed from five-repetition case means. Prefix error uses percentage points. GPU timing is client-observed; simulator timing comes from the server's logical clock, excluding predictor CPU query time.

The existing simulator retains measured CPU scheduling/result-processing overhead in that logical clock. These results therefore describe this CPU runtime and target profile, rather than isolated model-forward accuracy.

**Comparison boundary:** the recorded GPU servers use `disable_overlap_schedule=False`, while CPU simulator compatibility forces `True`. Native overlap submits the next batch before publishing the previous result; the simulated normal loop publishes immediately after its batch. The CPU native source is also SGLang `0.5.18`, while the measured GPU baseline is `0.5.17.dev36+gcb05a44f3`. This table is a historical regression diagnostic, **not a matched-scheduler accuracy validation**. The TTFT gap cannot be assigned entirely to the InferCast model or corrected by adding a fixed decode delay. Paired GPU overlap-on/off runs and separate first-use/steady measurements are required for attribution.
