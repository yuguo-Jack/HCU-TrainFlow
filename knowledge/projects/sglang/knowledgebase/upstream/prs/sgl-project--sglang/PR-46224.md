# [DRAFT][Feat] kv-events: Advertise every DP rank's publisher from node 0 for multi-node DP

[Upstream PR](https://github.com/sgl-project/sglang/pull/46224) · state: closed · merged: False

## Original PR description

## Motivation

`/server_info` and gRPC `GetServerInfo` describe the KV-event publisher as one `endpoint_host` plus an `endpoint_port_base`, and tell KV-aware routers to derive every DP rank as `tcp://<worker host>:<base + dp_rank>`. That only holds when all DP ranks run on the node that serves the API. With multi-node DP (for example `--dp-size 16 --nnodes 2`), the ranks on follower nodes publish from their own hosts, so a router holding only node 0's URL subscribes to the wrong machine for those ranks and silently sees no events from them.

The per-node `kv_event_sources` list that followers expose through their metadata-only `GetServerInfo` covers a process that runs beside each node (a per-node relay). A router with no per-node process, such as the SGLang model gateway or Dynamo's frontend dialing engines directly, cannot reach those lists; Dynamo currently refuses `nnodes > 1 && dp_size > 1` for exactly this reason.

## Modifications

Node 0 advertises every DP rank's publisher, from every node, with a host other machines can reach, as `kv_events.sources`:

```json
"kv_events": {
  "publisher": "zmq", "topic": "", "block_size": 128, "dp_size": 16,
  "endpoint_host": "*", "endpoint_port_base": 5557,
  "sources": [
    {"dp_rank": 0, "node_rank": 0, "endpoint": "tcp://10.0.0.1:5557", "replay_endpoint": "tcp://10.0.0.1:5558", "topic": "", "block_size": 128},
    {"dp_rank": 8, "node_rank": 1, "endpoint": "tcp://10.0.0.2:5565", "replay_endpoint": "tcp://10.0.0.2:5566", "topic": "", "block_size": 128}
  ]
}
```

- `ZmqEventPublisher.describe_advertised_source`: the off-box view of the bound socket. A wildcard bind advertises `advertise_host` (new `KVEventsConfig` field) or, failing that, the node's detected IP via `get_local_ip_auto`. A loopback bind is advertised only when `advertise_host` says how to reach it. Connect-style and IPC publishers are never advertised off-box. `describe_local_source` is unchanged; the two share one helper.
- `SchedulerKvEventsPublisher.advertised_kv_event_sources` tags each source with `node_rank`; `Scheduler.get_init_info` reports it next to `kv_event_sources`, under the same gRPC gate.
- `DataParallelController.exchange_advertised_kv_event_sources`: once a node's schedulers are ready, followers send their list to node 0 over a REQ/REP exchange on `dist_init_addr` at a new port offset (`KV_EVENT_SOURCES_HANDSHAKE_PORT_DELTA = 14`, beside the worker-port handshake). Node 0 acknowledges each report and returns the merged list sorted by `dp_rank`. Same 600 s timeout as the worker-port handshake; a late follower is logged and the merged list is served without its ranks rather than failing startup. Single-node deployments and elastic joiners return their local list and open no socket.
- `engine.py` merges the new key across local schedulers exactly as it merges `kv_event_sources`.
- `build_server_info` moves `advertised_kv_event_sources` out of the top-level info and into `kv_events.sources`. The descriptor docstring in `runtime_context.py` documents the key and tells routers to prefer it over base-plus-offset.

The per-node `kv_event_sources` list and the follower metadata server are untouched, so per-node relays keep working as before. The Rust-server path (`rust_server/config.py`) still builds only `kv_event_sources`; extending it needs a field on the Rust side and is left out here.

- ishandhanani · comment · 2026-10-24T03:32:33Z · [source](https://github.com/sgl-project/sglang/pull/46224#issuecomment-6379350625)

Closing. This only extends the Python server's `/server_info` and the `runtime.v1` `json_info` descriptor. Under the Rust server (`SGLANG_RUST_SERVER=1`) each DP rank has its own api.v1 listener, `GetServerInfo` is typed, and its launch-time server info cannot carry a list merged after all nodes are ready, so a node-0 merged `kv_events.sources` does not reach api.v1 clients. The off-box publisher view (reachable host, `node_rank`, `replay_endpoint`) belongs on the typed `KvEventSource` per listener instead; I will coordinate that with the api.v1 discovery work in #45859 / #45996. Also noting for the record: the `dist_init_addr + 14` handshake offset coincides with the Rust-mode scheduler input port of dp_rank 7 (`port_base + 6 + dp_rank`, `port_base = dist_init_port + 1`), so a merge of this shape would need a different port or a Rust-mode gate.
