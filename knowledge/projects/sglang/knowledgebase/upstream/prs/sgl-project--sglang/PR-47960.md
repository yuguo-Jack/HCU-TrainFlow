## What

The DeepSeek-V4 top-k v2 kernel gets a process-wide exactness mode, `SGLANG_TOPK_V2_MODE`, compiled in as `-DSGL_TOPK_MODE`:

| mode | contract | default |
|---|---|---|
| 0 fast | legal output; an overflowing threshold bin keeps an arbitrary subset | opt-in |
| 1 exact | selected values equal `torch.topk`'s; tie choice unspecified | CUDA, ROCm |
| 2 deterministic | exact, and the same selected set on every run (ties by smallest index, -0 == +0) | |

On main, only the cluster path is inexact: it truncates an overflowing threshold bin to 2048 entries in arrival order. This happens on real GLM-5 indexer scores, where layer 1 overflows on most rows. NaN input stays implementation-defined in every mode, with legal output only.

Changes, mostly in `topk_impl.cuh`:
- Cluster path (C16 / C8 small batch, C8 persistent pool):
  - 11-bit coarse bins;
  - the histogram is exchanged by `st.async` all-gather, so every rank finds the threshold and its own output bases (no rank-0 merge, fewer cluster barriers);
  - above-threshold elements are emitted directly;
  - a one-warp rank of the k-th digit replaces most of rank 0's tie stage;
  - rows whose threshold bin overflows are resolved inside the cluster (fine histogram + second pass), off the normal-row codegen path;
  - +-0 / inf / NaN bins are made consistent with the bin bounds instead of taking a slow path.
- One-block paths (Register, Streaming): `refine_ties` uses digits relative to the bin's lower edge (2 rounds instead of 3); Streaming folds overflow detection into the collect pass; score loads compile to `LDG`.
- Mode 0 compiles out every exactness fallback, including the ROCm split path; mode 2 adds index-ordered tie resolution only where an equal group straddles the k-th place.
- Blackwell plan table for the persistent pool re-tuned (the old one sent large batches of long rows to the pool where one-block Streaming is faster).
- `SGL_TYPE_CHECKING` (set only by the clangd config from `python -m sglang.kernels.jit`) defaults JIT-passed macros for IDE indexing.

## Performance

Mode 1 is the default on every platform. B300, nvcc 13.4, median % vs main (negative = faster), 108 shapes: real indexer score rows of GLM-5.2 (k 2048), DeepSeek-V4-Pro (k 1024) and V4.1-Flash (k 512), 8K-1M, bs 1-256, plus mixed batches. CUDA graph behind a producer that triggers PDL after its stores.

| path | mode 1 (default) | mode 0 | mode 2 |
|---|---|---|---|
| Register (<= 16K) | -2.7 | -1.7 | +1.4 |
| Streaming | +0.8 | +1.4 | +3.7 |
| cluster, small batch (C16) | -13.8 | -14.4 | -12.6 |
| cluster, small batch (C8) | -6.1 | -4.2 | -4.8 |
| cluster, persistent pool | -4.3 | -4.2 | -0.5 |
| mixed batches | -4.1 | -3.7 | -0.9 |
| all | -3.5 | -3.0 | -0.8 |

By context, mode 1: 8K -2.4, 16K -2.9, 32K -8.3, 64K -4.3, 128K -7.8, 256K -5.5, ~1M -8.8.

| shape | main | mode 1 (default) | mode 0 | mode 2 |
|---|---|---|---|---|
| GLM-5.2 64 x 128K (main's bin overflows) | 50.1 | 33.0 | 27.1 | 34.7 |
| GLM-5.2 64 x 256K | 40.2 | 38.0 | 37.2 | 38.5 |
| GLM-5.2 1 x 960K | 15.6 | 13.5 | 13.5 | 13.9 |
| V4.1-Flash 64 x 256K | 34.1 | 32.7 | 32.8 | 33.9 |
| V4-Pro 64 x 128K | 24.1 | 24.3 | 24.3 | 25.2 |

(us per call)

Known regressions:
- Streaming at bs >= 64, 32K-128K: mode 0 up to +2.3 % (0.1-0.4 us); mode 2 up to +6.7 %.
- Batches where every row overflows (GLM-5 layer 1) on the cluster paths: mode 1 up to +9.6 %, mode 2 up to +18 % vs main, which returns a wrong top-k on those rows.
- H200: works and is exact; mode 1 is +2.4 % overall vs main, more on batches with overflowing rows.

## Correctness

288 adversarial cases per arch: bin overflow, narrow bins, ties straddling the k-th place, all-equal, two values, signed zero, inf, NaN, at k 512 / 1024 / 2048 on every paged path.

| | main | mode 0 | mode 1 | mode 2 |
|---|---|---|---|---|
| inexact cases (B300 / H200) | 75 / 60 | 113 / 113 (allowed) | 0 / 0 | 0 / 0 |
| run-to-run different sets | 199 / 198 | allowed | allowed | 0 / 0 |

On the real score rows, main is inexact on 13 GLM shapes (all cluster paths); modes 1 and 2 on none. No illegal output in any mode.

## Tests

`test_topk_v2.py`: in-process tests run in the default mode 1; `test_topk_v2_modes` checks mode 0 (legal output) and mode 2 (exact, deterministic) in a subprocess each (one mode per process), started at module setup so their JIT builds overlap the in-process tests (cold run on B300: 89 s). 314 passed / 26 skipped on B300 in modes 0, 1, 2 and on H200.
