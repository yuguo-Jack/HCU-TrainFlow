# [Perf] Beam search: drop the per-step blocking index copy in logits

[Upstream PR](https://github.com/sgl-project/sglang/pull/44395) · state: open · merged: False

## Original PR description

@hnyls2002 @ch-wan — this is a small perf fix in the beam search logits
capture path (the code added in #31626), and it sits on the overlap
scheduler's per-step critical path, so I'd appreciate your eyes on it.

Every decode step, capture_pre_sample_logits gathered the leader rows with a
python-list index. The list is staged as an 8B pageable H2D copy; the driver
syncs the stream first, and the just-replayed decode cuda graph is on that
stream, so the host blocked in cudaStreamSynchronize for ~3.2ms per step and
could not prepare the next batch while the forward was still running.
append_beam_tail already has these indices on device — I keep them on BeamTail
and switch to index_select, which also removes the .clone().

nsys, Qwen3-0.6B, 1 request / 16 new tokens, L20, decode step interval:
  beam_width=20  : 7.9ms -> 4.9ms
  beam_width=100 : 11.4ms -> 7.5ms
Beam scores and texts are bit-identical; test/registered/unit/beam_search
is 23 passed.

Could you take a look when you have time? Happy to add a regression test or
re-measure on other GPUs if that helps.
