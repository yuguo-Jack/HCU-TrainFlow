# [Fix] lora: Reject unsupported trained bias in LoRA adapters

[Upstream PR](https://github.com/sgl-project/sglang/pull/41920) · state: open · merged: False

## Original PR description

## Summary

Adapters trained with `bias="lora_only"` or `bias="all"` pass validation, and their bias tensors enter projection normalization as LoRA matrix weights.

Reject these adapters in the shared validator before changing configuration or loading weights. The error identifies the adapter and asks for one trained with `bias="none"`. Missing bias and `bias="none"` remain supported.

Refs #41828.

## Verification

Using the real CPU adapter loaders with saved safetensors and tensor input:

| Adapter | Before | After |
| --- | --- | --- |
| `bias="all"` or `"lora_only"` | Success, with a 1D `qkv_proj.bias` among normalized matrix weights | Rejected; configuration and registry unchanged |
| `bias="none"` | Success | Success, with identical matrices |

- The new regression failed before the patch and passes afterward. It covers file, tensor, and initial adapter loading, supported defaults, and state preservation.
- Related CPU tests: 11 passed, with 8 subtests.
- Changed-file pre-commit hooks passed.
