# [Fix] lang: Prevent StreamExecutor deadlock after worker thread error

[Upstream PR](https://github.com/sgl-project/sglang/pull/47628) · state: open · merged: False

## Original PR description

## Motivation

When `StreamExecutor` runs with `use_thread=True` (the default for `@sgl.function`), `_thread_worker_func` executes queued `SglExpr` items sequentially. If `_execute(expr)` raises an exception on an earlier expression in a multi-step program, `_thread_worker_func` drains whatever items are currently in `self.queue`, signals the existing events in `self.variable_event` / `self.stream_var_event`, sets `self.error_`, and exits the worker loop.

However, two race conditions can still cause `sync()`, `text()`, `messages()`, `error()`, or `get_var()` to block indefinitely (`self.queue.join()` / `event.wait()`):

1. **Subsequent `submit(expr)` calls after worker failure**: In a multi-step `@sgl.function` where the main thread submits additional expressions after `_thread_worker_func` has already broken out of its loop on an exception, `submit(expr)` creates fresh `threading.Event` instances in `self.variable_event` / `self.stream_var_event` and puts `expr` onto `self.queue`. Because the worker thread has already exited, those queue items are never popped (`task_done()` is never called) and the newly created events are never signaled, causing `state.sync()`, `state.error()`, `state.text()`, `state.messages()`, and `state.get_var()` to hang permanently.
2. **`end()` called during worker error teardown or multiple times**: `end()` previously checked `if self.worker.is_alive(): self.queue.put(None)` without synchronizing with the worker loop exit. If `end()` runs after the worker has finished draining `self.queue` in its exception handler (while the thread is still alive before returning) or if `end()` is called more than once, an unconsumed `None` sentinel remains in `self.queue` with `unfinished_tasks > 0`, deadlocking any subsequent `sync()`.

## Modifications

- Add `self._worker_lock` and `self._worker_stopped` on `StreamExecutor` when `use_thread=True`, and initialize `stream_text_event` / `stream_var_event` before starting the worker thread.
- Synchronize `submit()`, `end()`, and `_thread_worker_func` termination under `self._worker_lock`:
  - If `submit(expr)` is called after `_worker_stopped` is set, initialize variable/stream events for `expr`, immediately signal them via `_signal_all_events()`, and skip enqueueing `expr` onto `self.queue`.
  - Ensure `end()` only enqueues the `None` sentinel once when `not self._worker_stopped`.
  - In `_thread_worker_func`, mark `_worker_stopped = True`, drain remaining queue items with matching `task_done()` calls, and signal all variable/stream events atomically under `_worker_lock`.
- Add unit tests in `test/registered/unit/lang/test_stream_executor_error.py`.
