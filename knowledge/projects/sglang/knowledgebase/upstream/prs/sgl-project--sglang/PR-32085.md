# [Fix] constrained: Bound grammar compilation workers and expose an override

[Upstream PR](https://github.com/sgl-project/sglang/pull/32085) · state: open · merged: False

## Original PR description

## Motivation

Fixes #32084. Bound the grammar-compilation executor so a burst of distinct schemas cannot create the host-sized default pool inside a CPU-limited container. Companion vLLM fix: vllm-project/vllm#49461; production RCA: vllm-project/vllm#49460.

## Modifications

- Use `max(1, min(cpu_count // 2, 8))` for `BaseGrammarBackend.executor`.
- Add `SGLANG_GRAMMAR_COMPILE_MAX_WORKERS`: positive values override the default; 0 selects automatic sizing.
- Test the cap, one-worker floor, host-count fallback, override, and actual backend executor size.
- Integrate main at `834bfe4ef0ec11ac5625fac3f94f60c041a36cb8` (2026-10-19), preserving its updated grammar request/framing interfaces.

## Speed Tests and Profiling

GPU/container-quota before-and-after serving benchmarks remain outstanding. The production measurements referenced above come from the vLLM deployment and are not SGLang performance results.

This bounds the outer pool; it does **not** detect cgroup CPU quotas or change backend-internal thread counts. Eight workers may still oversubscribe a smaller quota. The lower default reduces concurrent compilation on small and large hosts relative to bare `ThreadPoolExecutor()`, potentially increasing schema-burst compilation latency. Operators can tune `SGLANG_GRAMMAR_COMPILE_MAX_WORKERS`.
