# [Spec] Move state capture outputs with the accepted path (EAGLE topk>1, ngram)

[Upstream PR](https://github.com/sgl-project/sglang/pull/37949) · state: closed · merged: False

## Original PR description

## Motivation

With EAGLE tree drafting (`topk > 1`), accepted KV moves to the front of each request's block, but routed-expert and indexer captures remain in tree order. Consumers then read plausible capture rows for the wrong tokens. NGRAM also drops the capture handles before the scheduler can publish them. Both affect routing data used by RL replay.

## Changes

- Move pending capture rows with the accepted KV, using the same compaction as predictions and hidden states.
- Carry both capture handles through NGRAM's result.
- Defer capture publication during single-stage target verification even when overlap is disabled, so the existing result copy/finalize path runs after compaction.
- Update the pipeline-parallel KV-only caller for the required argument. This preserves that path; it does not add end-to-end pipeline-parallel capture support.

## Verification

CPU regressions exercise accepted-slot readback, the KV-only pipeline caller, and deferred publication through the real model runner/capturer boundary. The fixture selects non-front tree nodes and uses nonzero KV slots.

The GPU regression compares decode routing with a cold-prefill reference for NGRAM and EAGLE topk 4, with overlap enabled and disabled. It needs the two-GPU runner and has not been executed locally. Indexer compaction uses the same mechanism, but this GPU comparison covers routed experts.

The five CPU regressions and changed-file pre-commit checks pass. GPU execution remains a merge prerequisite.
