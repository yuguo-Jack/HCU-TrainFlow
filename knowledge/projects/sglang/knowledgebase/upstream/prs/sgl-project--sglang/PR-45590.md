## Motivation

When a request finishes before its first Mamba tracking interval, the [int8-checkpoint path](https://github.com/sgl-project/sglang/blob/6cac4dc3fe9a4bf15009f300132c3c7a1853c210/python/sglang/srt/mem_cache/unified_cache/components/mamba.py#L609-L627) reads an unwritten ping-pong state slot, then discards the zero-length checkpoint. The read is unnecessary; no output corruption was observed. Related [PR #44718](https://github.com/sgl-project/sglang/pull/44718) and [PR #39209](https://github.com/sgl-project/sglang/pull/39209) address different checkpoint cases.

## Modifications

Skip the state read when tracked length is zero.
Nonempty checkpoints are unchanged.
No user-facing documentation changes are needed.

## Accuracy Tests

- Historical Qwen3.5-0.8B-Base HTTP warmup: the unwritten-state read disappeared after the fix. [Evidence](../../new-dynamic-findings-260904.md#sg-d1-zero-length-int8-mamba-checkpoint-reads-uninitialized-state).
- On main `2e7c9d851c`, the focused checkpoint suite passed `2/2` with CPU-device and `datasets` stubs. Current-main serving replay remains pending.

## Speed Tests and Profiling

Not measured since only the finished zero-length path changes.
