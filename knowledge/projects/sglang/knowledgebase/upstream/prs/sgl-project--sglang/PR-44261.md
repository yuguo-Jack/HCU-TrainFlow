# [Fix] spectrum: bound Spectrum under FLUX.1 true CFG and cap CFG gate reuse

[Upstream PR](https://github.com/sgl-project/sglang/pull/44261) · state: open · merged: False

## Original PR description

Depends on #42423 (this branch is stacked on it; review the last four commits) and on #44260 (the FLUX CFG-weight check below reads `true_cfg_scale` through it).

## Motivation

Under FLUX.1 true CFG, Spectrum forecasts drift far from the real features from the first predicted step (relative L2 0.27-0.52 at step 5 on FLUX.1-dev), and even one final-step forecast left border artifacts in held-out images. CFG gating that freezes the cond-minus-uncond difference for most of the run also drifts with every reused step.

## Modifications

- FLUX.1 true CFG, CFG weight <= 2: Spectrum follows a bounded schedule. Real forwards for the first 40% of the steps and the last 2, and a real forward every other step in between (window 2, no growth). Other request Spectrum parameters are kept, and request-owned params are not mutated.
- FLUX.1 true CFG, CFG weight > 2: Spectrum is disabled for the request. The model returns no Spectrum context, so no forecaster is built and the request runs the uncached path. The log says which applies, once per request.
- `SpectrumParams.final_real_steps` (default 0, no CLI flag) keeps the final steps real; the FLUX policy sets it to 2.
- CFG gating may reuse the frozen delta for at most the final step on FLUX.1 and the final 5 steps on Wan (`cfg_gate_max_reused_steps`; all Wan variants inherit it). An earlier gate is moved later with a warning. Gating stays off by default.
- `spectrum.mdx`: FLUX.1 true CFG schedule with measurements, and the Wan gating cap.

## Accuracy Tests

Unit: `test_spectrum_lifecycle.py`, `test_cfg_gating.py`: 19 passed, 61 subtests (bounded schedule at CFG 1.5/2.0, disabled above 2 with no forecaster built, `final_real_steps`, Wan cap including explicit-disable and CFG-parallel cases).

FLUX.1-dev, 1024x1024, guidance 3.5, true CFG 1.5 and 2.0, 28 and 50 steps, 15 prompts x 2 seeds, compared with the same requests without Spectrum (B200). The gate was fixed before the run: median PSNR >= 27 dB per configuration, LPIPS <= 0.12 for every sample, and every image inspected.

| true CFG, steps | median PSNR, 1 GPU | max LPIPS, 1 GPU | median PSNR, 2 GPU CFG parallel | max LPIPS, 2 GPU |
| --- | --- | --- | --- | --- |
| 1.5, 28 | 29.13 dB | 0.114 | 29.13 dB | 0.098 |
| 1.5, 50 | 31.64 dB | 0.066 | 31.59 dB | 0.058 |
| 2.0, 28 | 28.24 dB | 0.114 | 28.24 dB | 0.104 |
| 2.0, 50 | 30.78 dB | 0.058 | 30.33 dB | 0.062 |

- The 9 prompts and the seed not used to choose the schedule give 29.1-31.6 dB median.
- All 240 image pairs were inspected, plus full-resolution corners of the worst three: no artifacts. Differences are composition, texture or small details, sometimes a different but plausible element (for example, a paved surface instead of asphalt).
- At true CFG 4 the Spectrum output is bit-identical to the uncached output (15/15).
- Re-checked after merging current `main` (`c82e8bd5fe`) together with #44260: 36 requests (true CFG 1.5/2.0 x 28/50 steps x 4 prompts, plus true CFG 4 on 2 prompts) are bit-identical to the acceptance outputs above.

Wan2.1-T2V-1.3B at its defaults (480x832, 81 frames, 50 steps), mean frame PSNR against no CFG gating:

| `cfg_gate_step` | guidance 3.0 | guidance 5.0 |
| --- | --- | --- |
| 0.3 (35 reused steps) | 30.1-31.2 dB | 23.4-27.2 dB |
| 0.7 (15 reused steps) | 40.2-42.1 dB | 34.2-37.3 dB |
| 0.9 (5 reused steps, the new cap) | 46.1-47.1 dB | 40.7-42.8 dB |

The error grows smoothly with the number of reused steps, so the cap bounds an approximation rather than working around a bug.

End-to-end check of the cap on the real model (same defaults, guidance 3.0, seed 42, this branch): `cfg_gate_step` 0.3 and 0.7 each log `limits CFG residual reuse to the last 5 step(s) ... effective gate 45/50`, and their frames are bit-identical to an explicit 0.9; PSNR against the ungated run is 46.05 dB.

## Speed Tests and Profiling

FLUX.1-dev, 1024x1024, one B200 with no other process on it during the run, 2 warmups + 5 measured requests per case, alternating order:

| true CFG, steps | without Spectrum | Spectrum | speedup |
| --- | --- | --- | --- |
| 1.5, 28 | 5.24 s | 3.84 s | 1.36x |
| 1.5, 50 | 9.37 s | 6.92 s | 1.35x |
| 2.0, 28 | 5.26 s | 3.86 s | 1.36x |
| 2.0, 50 | 9.38 s | 6.93 s | 1.35x |

The schedule runs about 72% of the DiT forwards.

Limitations: validated only at true CFG 1.5 and 2.0, 1024x1024, 28 and 50 steps on FLUX.1-dev; the Wan cap was measured on Wan2.1-T2V-1.3B only. The quality gate is perceptual, not bit-exact: with Spectrum on, the same seed gives a slightly different image.
