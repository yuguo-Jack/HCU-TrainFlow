## Motivation

Add HiCache storage management endpoints to the Rust server so clients can attach,
detach, clear, and inspect the configured storage backend.

## Modifications

- Define HiCache requests and responses in proto and use generated types for HTTP JSON and gRPC.
- Add PUT, DELETE, and GET `/hicache/storage-backend`, and POST `/hicache/storage-backend/clear`, with corresponding gRPC methods.
- Keep HiCache operations and configuration in a dedicated `HiCacheManager`, shared by HTTP and gRPC. Protect the configuration with `RwLock` and keep it out of `AppState` and `CoreInner`.
- Convert API requests into the existing Python scheduler messages, preserving scheduler results and updating configuration only after successful attach/detach operations.
- Return `HiCacheStorageResponse` as JSON for HTTP control operations, with HTTP 200 on success and 400 on scheduler rejection.
- Add HTTP/gRPC tests, configuration and JSON parity coverage, and a runtime test verifying shared state between HTTP and gRPC.

### Compatibility

HTTP control responses use structured JSON rather than Python's current plain-text responses.
GET retains the four configuration fields exposed by Python.

Invalid attach requests return HTTP 422. Framework-generated validation error
bodies retain the native Axum format rather than reproducing FastAPI/Pydantic errors.
