# [Test] mooncake: bind metadata server to loopback in tests

[Upstream PR](https://github.com/sgl-project/sglang/pull/48121) · state: closed · merged: True

## Original PR description

## Motivation

Mooncake 0.3.14 hardens the Python HTTP metadata server (kvcache-ai/Mooncake#4472): with no `MC_METADATA_HTTP_TOKEN`, it now refuses to bind a non-loopback address. Its default `--host` is `0.0.0.0`, and our tests launch it with only `--port`, so with 0.3.14 the server exits at startup and the test fails in `setUpClass`:

```
RuntimeError: HTTP Metadata Server refuses to bind 0.0.0.0:8822 without an authentication token ...
```

Seen in the 0.3.14rc4 validation PR #36469, `registered/disaggregation/test_disaggregation_decode_radix_linker.py` on `4-gpu-h100`: https://github.com/sgl-project/sglang/actions/runs/41606237049/job/125816818899

## Modifications

Every client in these tests already reaches the metadata server via `http://127.0.0.1:<port>/metadata`, so bind it to loopback:

- `python/sglang/test/mooncake_utils.py` (shared helper, used by the disaggregation tests)
- `test/registered/hicache/test_hicache_storage_mooncake_backend.py`
- `test/registered/hicache/test_pp_with_hicache.py`
- `python/sglang/srt/mem_cache/storage/mooncake_store/README.md`: use `--host 127.0.0.1` for the single-server example, and note `MC_METADATA_HTTP_TOKEN` for multi-server setups

`--host` already exists in 0.3.13.post1 (the currently pinned version), so this is a no-op today and unblocks the 0.3.14 bump.

## Accuracy Tests

Not applicable (test launch args + docs only).

Local check against the 0.3.14 server code (`release/v0.3.14`, `python/mooncake/http_metadata_server.py`):
- `--port 18822`: exits with rc=1, same `refuses to bind 0.0.0.0` error as CI
- `--host 127.0.0.1 --port 18822`: listens, PUT/GET on `/metadata` succeed
