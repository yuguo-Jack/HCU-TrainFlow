# [Fix] radix-cache: Separate logical and reclaimable value lengths in tree components

[Upstream PR](https://github.com/sgl-project/sglang/pull/45238) · state: closed · merged: True

## Original PR description

## Motivation

A tree node's device value has two lengths that the tree cores treated as one: the logical length of the stored index tensor, which slicing, prefix matching and `collect_path_info` spans read, and the number of allocator slots the pool gets back when the value is evicted, which the evictable/protected ledgers count. A component whose backing is released or shared under a value can occupy fewer pool rows than the logical value describes, and the ledgers then drift from what the allocator actually reclaims: prefill admission adds the evictable ledger to the allocator's free space and the eviction walk counts it toward its request, so both over-report.

## Modifications

- Python: `TreeComponent.reclaimable_tokens` becomes `reclaimable_value_len`, and every ledger site in the Full, SWA and Mamba components (insert, lock, release, materialize, evict, recount) reads it instead of `len(value)`. `value_len` stays the logical length.
- Rust: `Node` gains `device_reclaimable_value_len`, zero for roots and absent values, and the same ledger sites in the Full, SWA and Mamba components and the core use it instead of `device_value_len` or the tensor's first dimension. The SWA component's private `value_len` helper goes away.
- `adjust_component_size` rejects a delta that would drive a ledger negative with `ValueError` and leaves the counters untouched, on both cores; the interface docstring says so.
- `evict_device_next_node` reports progress when a step freed device or host backing even though no node was consumed, so an eviction walk over zero-accounted nodes keeps going instead of stopping early.

Nothing changes for components whose reclaimable length equals the logical one, which is every in-tree component today.
