# [Perf] encoding: Find the last user turn once per render in the native DeepSeek encoders

[Upstream PR](https://github.com/sgl-project/sglang/pull/45411) · state: closed · merged: False

## Original PR description

## Motivation

`render_message` in `encoding_dsv41` and `encoding_dsv32` (and `encoding_dsv4`) needs the index of the last user turn
and computes it itself with `find_last_user_index(messages)` on every call. `_encode_messages_text` /
`encode_messages` call `render_message` once per message, and the scan walks back from the end until it reaches a user
turn. In an agent loop the conversation is one user turn followed by hundreds of tool-call / tool-result turns, and in
dsv41 / dsv32 tool-result-only user turns are skipped by the scan, so it walks back over almost the whole list for every
message: the render is O(n^2) in the number of tool turns.

Rendering is synchronous in `OpenAIServingChat._process_messages`, so this time is spent on the HTTP event loop like
the tokenization in the companion PR.

Render time of `encode_messages(..., thinking_mode="thinking")` for a conversation of one user turn followed by n
tool-call / tool-result pairs (same machine, single process):

| messages | dsv41 before | dsv41 after | dsv32 before | dsv32 after | dsv4 before | dsv4 after |
|---:|---:|---:|---:|---:|---:|---:|
| 502 | 49 ms | 10 ms | 13 ms | 2 ms | 6 ms | 6 ms |
| 2,002 | 658 ms | 40 ms | 194 ms | 7 ms | 23 ms | 22 ms |
| 4,002 | 2,702 ms | 81 ms | 766 ms | 13 ms | 45 ms | 43 ms |

dsv4's scan does not skip tool-result-only user turns, so it stops early and shows no change; it gets the same
signature for consistency across the three encoders.

## Modifications

- `render_message` in `encoding_dsv4.py`, `encoding_dsv41.py` and `encoding_dsv32.py` takes an optional
  `last_user_idx`. When it is `None` (any external caller), it computes it exactly as before.
- The render loops compute `find_last_user_index(full_messages)` once on the same list they render and pass it in.
  `_drop_thinking_messages` / `drop_thinking_messages` are unchanged (one scan each).
- New `test_native_encoder_render.py`:
  - `test_prompt_matches_per_message_lookup`: for each encoder, chat / thinking mode, with and without a follow-up user
    turn, the rendered prompt equals the one rendered with the old per-message lookup.
  - `test_last_user_lookup_is_not_per_message`: rendering 300 tool turns calls `find_last_user_index` at most 4 times
    (it was 602 before this change).

## Accuracy Tests

The prompt string is unchanged by construction (same list, same function, computed once instead of per call), and
pinned by `test_prompt_matches_per_message_lookup`. Additionally checked on 383 randomized `encoding_dsv41`
conversations (tool calls, reasoning, CJK / emoji, partial special-token strings, with and without `drop_thinking`):
identical output.
