# [Doc] [AMD] docs: document APU memory model and mamba state cache on gfx1151

[Upstream PR](https://github.com/sgl-project/sglang/pull/47264) · state: open · merged: False

## Original PR description

## Motivation

The Strix Halo / gfx1151 section tells you which image to use and which flags to pass, but not how a gfx1151 deployment actually behaves. Two facts decide that, and neither is documented:

1. **There is no VRAM.** `rocm-smi` may report a small carve-out (512 MB on the machine used here), while SGLang allocates from the GTT pool — the same pool `torch.cuda.total_memory` and `mem_get_info()` report (~108 GiB on a 128 GB machine). Advice written for discrete GPUs ("keep `--mem-fraction-static` below 0.9, leave head-room for activations") does not transfer.
2. **For hybrid (GDN) models the mamba state cache caps the batch, not the KV pool.** The cache reserves 5 state slots per request, so `--max-running-requests` above that value is silently ignored:

```
max_running_requests is capped to 99 by the mamba state cache
(max_mamba_cache_size=498, 5 state slots per request)
```

`--mamba-ssm-dtype bfloat16` halves the state size and doubles the cap (99 -> 195 on the same pool, KV capacity unchanged: 875k -> 874k tokens).

## Changes

- **Remove "(or rely on the gfx115 auto-default)"** from the LLM bullet and require the backend explicitly. Without `--attention-backend`, the resolved value on gfx1151 is `aiter` (`server_args: 'attention_backend': 'aiter'`), which is CDNA/wave64-oriented and does not come up on this device. The flag and `SGLANG_USE_AITER=0` are both needed.
- **Add "Memory model on an APU"** — GTT vs carve-out, and what `--mem-fraction-static` is a fraction of.
- **Add "Hybrid (GDN) models and the mamba state cache"** — the startup cap line, the `--mamba-ssm-dtype` lever, and a state-sizing example for `Qwen3.5-4B` (24 linear layers, `32 x 128 x 128` per layer ⇒ 24 MiB/request in bf16).

## Evidence

Measured on a Ryzen AI MAX+ 395 (gfx1151, 128 GB) with `rocm/sgl-dev:v0.5.21-rocm724-gfx1151-20261008`:

| observed | value | source |
|---|---|---|
| `attention_backend` when unset | `aiter` | `server_args` echoed at startup |
| `rocm-smi --showmeminfo vram` | 512 MB | rocm-smi |
| `rocm-smi --showmeminfo gtt` | 108 GiB | rocm-smi |
| `torch.cuda.get_device_properties(0).total_memory` | 108 GB | torch |
| mamba cap, default ssm dtype | 99 | startup log |
| mamba cap, `--mamba-ssm-dtype bfloat16` | 195 | startup log |
| KV tokens, both of the above | 875k / 874k | startup log |

No performance numbers are claimed in this change; all values are startup-log or config-derived, so they can be reproduced without a benchmark.

## Testing

`docs/` change only. Verified the flag against `sglang/srt/arg_groups/fields/exec_.py` (`mamba_ssm_dtype` choices: `float32`, `bfloat16`, `float16`; default `None`, read from model config) and the cap against `sglang/srt/mem_cache/kv_cache_configurator.py`.
