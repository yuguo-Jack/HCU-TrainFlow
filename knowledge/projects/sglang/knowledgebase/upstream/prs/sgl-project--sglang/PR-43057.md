# perf(kv-cache): fuse sharded DSA indexer and raw FP8 stores

[Upstream PR](https://github.com/sgl-project/sglang/pull/43057) · state: open · merged: False

## Original PR description

CP-sharded prefill currently quantizes/stages indexer keys, selects the owner rows, and writes the local cache separately. The raw FP8 latent path similarly repeats conversion and scatter work for scratch and persistent storage. This PR adds optional-capability fast paths for those two writes while preserving the existing fallbacks.

### Changes

- Quantize BF16 DSA indexer keys once and write both the full scratch view and this rank's owner-local packed FP8 K/FP32 scale pages in one CUDA kernel.
- Convert raw FP8 latent NoPE/RoPE tensors with the existing PyTorch conversion once, then reuse a warp-local staging row for scratch and owner-local stores. Preserve each destination's reserved-row-zero behavior and use the required async-proxy fence/synchronization order before TMA.
- Gate indexer dispatch to BF16 keys, 128-element blocks, ordinary FP32 scales, int64 locations and page64 packed buffers. Gate latent dispatch to the existing large-chunk raw 512+64-byte layout, supported CUDA capability/alignment and no DCP.
- Fall back before launch for unsupported formats/layouts or unavailable JIT compilation. Kernel execution errors propagate; they are not swallowed and retried as a second write.
- Recompute scratch locations when callers reuse/mutate their location tensors. Existing non-sharded writers are unchanged.

This does not include scratch capacity reduction, MoE autotuning, grouped gathers, LiSA or decode HiSparse.

### Numerical contracts

The indexer uses the ordinary CUDA fused writer's quantization arithmetic and shares the same quantized result across both destinations. GPU tests assert byte equality to two ordinary CUDA fused stores. The comparison with the preceding Triton `act_quant` fallback follows the existing CUDA/Triton rounding contract (up to one FP8 representable step at rounding ties); it is **not** claimed to be bitwise identical to that fallback.

The raw latent kernel scatters already-converted bytes, retaining PyTorch's FP8 overflow/NaN behavior. GPU tests assert whole-buffer byte equality, including untouched rows and guard bytes.

### Validation

- 82 new CPU capability/validation/dispatch cases passed.
- Combined regression: **219 passed, 126 subtests passed, 718 GPU-dependent cases skipped** on the local Mac (712 new kernel cases plus 6 prerequisite GPU cases).
- New registered GPU cases cover CP2/CP4/CP8 and every owner, fragmented pages, partial batches, noncontiguous inputs, different row strides, target/draft offsets, skip/trash rows and CUDA Graph replay. On a supported CUDA device, JIT compilation failures fail the kernel tests rather than silently skipping them.
- CPU dispatch tests mock the CUDA launch boundary; they do not establish GPU numerical correctness. ServerArgs CPU regressions bypassed the local MPS-version preflight.
- CI script entry points accept the runner's `-f` flag. Changed-code static/format checks and `git diff --check` passed.

### Remaining qualification

No NVCC execution, real GPU kernel validation, latest-main Nsight performance measurements or full-model accuracy validation was performed in this environment. The older fork's microbenchmark gains are not claimed for this port; current main has changed the single-destination latent writer. Keep this PR in draft until GPU correctness, model accuracy and fresh performance comparisons pass.
