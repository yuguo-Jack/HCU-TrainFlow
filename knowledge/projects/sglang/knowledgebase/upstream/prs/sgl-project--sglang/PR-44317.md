# [Perf] speculative: Cache the grammar mask host token filter and skip unconstrained draft-tree walks

[Upstream PR](https://github.com/sgl-project/sglang/pull/44317) · state: open · merged: False

## Original PR description

## Motivation

With `--enable-strict-thinking` every request carries a `ReasonerGrammarObject`, and while it is in the thinking state the speculative verify path (`generate_token_bitmask` → `traverse_tree`) calls the strict-thinking token filter at every draft-tree node. On the host-side mask that filter is `set_token_filter_torch`, which re-aggregates the (constant) excluded token ids and builds small CPU tensors on every call: ~30 µs per node. At batch 54 with DSpark block size 3 that is 4–6 ms of scheduler (GIL) time per decode step; `py-spy --gil` on the TP0 scheduler showed 54% of decode GIL time in `build_grammar_vocab_mask` → `traverse_tree` + `set_token_filter_torch`, with the GPU under-utilized (SM active 0.4–0.5).

## Modifications

- `set_token_filter_torch`: cache, per (token ids, is_allowed, row length), the aggregated element indices, bitmasks and the reset-plus-apply row template; write host rows through a numpy view (4.7 µs per call, bitwise-identical output). The non-host path keeps tensor indexing with the cached arrays.
- `traverse_tree`: convert the tree tensors to Python lists once and read the parent bitmask through a numpy view.
- `BaseGrammarObject.needs_vocab_mask()` (default True) lets `generate_token_bitmask` skip requests whose grammar cannot constrain the step; `ReasonerGrammarObject` returns True only while the token filter can act (thinking state with an excluded set, or an inner grammar after thinking). `sampling_info.grammar_mask` is still cleared for skipped requests.
- Unit tests extended: `test_token_filter_ops.py` (randomized old-vs-new equivalence, reset and no-reset, allowed and excluded), `test_spec_utils_traverse_tree.py`, `test_reasoner_grammar_backend.py` (needs_vocab_mask across states).

## Accuracy Tests

Token filter output is bitwise identical to the previous implementation (randomized equivalence test in `test_token_filter_ops.py`); grammar masks are unchanged, only their cost.

## Benchmarking and Profiling

DeepSeek-V4.1-Flash, 1P1D (TP4 prefill + TP4 decode, DSpark block 3, strict thinking on), GB300, closed-loop real-trace replay on the decode worker, before → after:

| concurrency | output tok/s per chip | TPOT (ms) | tok/s per user |
|---|---|---|---|
| 16 | 18.1k → 22.7k | 5.20 → 3.96 | 192 → 253 |
| 32 | 26.7k → 34.8k | 7.23 → 4.85 | 138 → 207 |
| 64 | 34.4k → 48.7k | 11.58 → 6.01 | — → 167 |

A same-model deployment whose requests leave the thinking state early (filter never fires) measured 23.2k / 35.7k / 51.2k tok/s per chip at the same rungs, i.e. the patch closes the gap. `set_token_filter_torch`: 30 µs → 4.7 µs per call.
