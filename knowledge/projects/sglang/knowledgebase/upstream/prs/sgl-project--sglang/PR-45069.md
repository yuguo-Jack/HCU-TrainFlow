# [Fix] deepseek-v4: Count the FlashMLA schedule kernel's block scalars in its shared-memory bound

[Upstream PR](https://github.com/sgl-project/sglang/pull/45069) · state: closed · merged: False

## Original PR description

## Motivation

`_maybe_precompute_flashmla_sched_meta` skips the split-KV schedule precompute when the schedule's dynamic shared memory, `4 * (5 * b + 1 + 8 * num_sm_parts)` bytes, exceeds 48 KiB (#40429), and the C++ launcher checks the same bound. The kernel also declares ten `__shared__` ints statically (`warp_sums[8]`, `total_num_blocks_shared`, `first_idle_part_shared`), which count against the same default 48 KiB. Batches right at the edge pass both checks and the launch fails:

```
tvm.error.InternalError: Failed at .../deepseek_v4/flashmla_sched_meta.cuh:273: CUDA error: invalid argument
```

With 148 schedule parts the failing batches are b = 2219 and 2220 (49120 + 40 and 49140 + 40 bytes). Decoder SWA bounded replay runs the late layers of an extend in the decode FlashMLA layout with up to 128 rows per request, so a DEP2 prefill with 32K tokens per rank reaches these batch sizes; the server crashed after tens of minutes of an agentic workload.

## Modifications

- Move the three block scalars into the dynamic allocation (`kScratchInts` after the schedule output), so the kernel has no static shared memory and the bound is exact.
- `flashmla_sched_meta.py` exposes `sched_meta_smem_bytes(...)` and `MAX_SMEM_BYTES`; the precompute guard uses them instead of an inline formula.
- Tests: `test_largest_admitted_schedule_launches` walks the precompute down from an oversized batch and launches the first schedule it admits (on main it admits b = 2220 and the launch fails); the skip test pins the derived limit (2218 at 148 parts).

## Accuracy Tests

The schedule is unchanged: all of `test_flashmla_sched_meta.py` (bit-exact comparison against FlashMLA's own schedule and outputs) passes on GB300.

## Speed Tests and Profiling

No performance change; batches above the limit keep falling back to FlashMLA's own scheduler. Two 60-minute DeepSeek-V4.1-Flash DEP2 prefill runs at 32K tokens per rank crashed at this launch; with a guard leaving headroom for the static scalars, four further 60-minute runs of that configuration completed without errors. This change makes the bound exact instead.
