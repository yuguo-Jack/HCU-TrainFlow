# [Fix] muse: Support Responses namespace tools and defer_loading

[Upstream PR](https://github.com/sgl-project/sglang/pull/44685) · state: closed · merged: True

## Original PR description

## Motivation

For Muse Spark, `/v1/responses` drops function-tool `defer_loading` and namespace definitions before rendering the prompt. Namespace calls also need separate `namespace` and `name` fields in Responses outputs, while the model and tool-call parser use qualified names such as `browser.search`.

Original author: [sid-rp](https://github.com/sid-rp) (`sid-rp <sidrp@meta.com>`).

## Modifications

- Gate namespace expansion, nested template tools, deferral forwarding, output-name splitting, and replay-name qualification on `tool_call_parser == "muse"`. Other parsers retain their existing function/custom-tool conversion, rendered schemas, and call names.
- Preserve nested namespace definitions and namespace/member deferral flags for the chat template, while registering qualified names for tool-call parsing.
- Accept both flat and OpenAI-wrapped function members, matching the official Muse Spark chat template. Use the same member normalization for prompt construction, parser registration, and output-name mapping.
- Preserve standalone custom tools when they appear alongside namespaces, including their existing function shim, grammar description, and deferral flag.
- Split qualified names in full/streaming Responses outputs and rejoin them when replaying calls.
- Extend the existing CPU unit tests to exercise the real message-processing/Jinja path and native Muse ATEM parsing, including mixed custom tools and both namespace-member shapes. Add non-Muse regressions for Qwen, Llama, and requests without a parser, including full/streaming dotted function names and replay.
