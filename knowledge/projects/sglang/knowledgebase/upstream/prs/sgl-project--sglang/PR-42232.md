# [Perf] Skip unused FlashMLA sparse-prefill statistics in serving

[Upstream PR](https://github.com/sgl-project/sglang/pull/42232) · state: open · merged: False

## Original PR description

## Motivation

Remove post-attention statistics-conversion launches from ordinary sparse prefill. Existing callers still receive output, base-2 max logits and base-2 LSE by default; output-only serving callers can now omit unused statistics.

Depends on https://github.com/sgl-project/FlashMLA/pull/17. This pins its immutable fork commit for review; replace it with the promoted organization-owned `sgl` revision before merging.

Related: #42170. #41512 already skips these conversions for its packed **output-only** serving path. This PR instead preserves the ordinary full API and benefits its stock/fallback callers; it does not add conversion savings to the packed output-only path. The FlashMLA dependency updates will need reconciliation if both land.

## Modifications

- Pin FlashMLA `6f9da943b2454d46af89bcb0cf3e67aae4203ed6` with SHA256 `6e794350c972409c646c849366d401d075fe87c34d1fb004e37468534a32d068`. The downloaded archive was checked against all 185 tracked source files. This commit currently lives in `ajit283/FlashMLA`; the CMake URL explicitly names that fork rather than an upstream archive URL that currently returns 404. Replace it with a promoted organization-owned revision before merge.
- Add `return_log2_lse=True` to the SGL wrapper/operator: default base-2 statistics are unchanged; `False` returns output plus `None, None`, skipping statistics allocations/stores.
- Opt the ordinary DSA and DeepSeek V4 serving callers out of unused statistics. Their attention dispatch/head padding is unchanged.
- Extend independent FP32-reference tests across True/False, H64/H128, D512/D576, top-k 128/512/2048, sinks, lengths, invalid/empty rows, rising/negative logits and graph-input mutation. Top-k 2048 exercises regular H128 rather than only its small-topk specialization.
- Check legacy seven-argument operator calls and require one GPU attention kernel without conversion launches on all supported prefill paths/modes.

The dependency preserves native natural-log defaults (`return_log2_lse=None`) while offering explicit base-2 (`True`) or output-only (`False`) modes. No new attention backend, native-head dispatch, or serving configuration. Existing SGL callers keep the base-2 default; no natural-log conversion is performed by the compatibility shim.

## Speed Tests and Profiling

Historical measurements of the earlier H64-only fusion, not the new optional-statistics API. Clean `3620b63` baseline versus that dependency patch, built with matching flags and isolated symbols. Identical inputs, allocation contracts and all three outputs; median of nine interleaved CUDA-graph measurements.

**32 H64 queries, D512, 8192 cached tokens:**

| GPU | Top-k | Original us | Fused us | Speedup |
|---|---:|---:|---:|---:|
| GB200 | 128 | 8.533 | 6.374 | 1.34x |
| GB300 | 128 | 8.925 | 6.454 | 1.38x |
| GB200 | 512 | 14.620 | 12.417 | 1.18x |
| GB300 | 512 | 14.664 | 12.203 | 1.20x |
| GB200 | 2048 | 38.337 | 36.211 | 1.06x |
| GB300 | 2048 | 37.385 | 34.960 | 1.07x |

A same-binary control restoring the two multiplies returns to baseline latency (8.543/8.925 us at top-k128). Profiling confirms **3 -> 1 GPU kernels** for H64 and unchanged 3-kernel behavior for H128.

These are full-operator, primarily warm-cache microbenchmarks—not attention-compute FLOP savings or end-to-end serving speedups. The percentage benefit decreases for longer attention kernels. No B200 or Hopper runtime result is claimed.
