# [Fix] dspark/MiniMax-M3.1-Flash: Inject decode-step draft KV under the draft's TP placement

[Upstream PR](https://github.com/sgl-project/sglang/pull/46851) · state: closed · merged: True

## Original PR description

## Motivation

With attention DP, DSpark on MiniMax-M3.1-Flash (#45925) crashes at the first decode step at `--attn-dp-size 4`, and in a PD decode worker at `--attn-dp-size 2`:

```
  File ".../speculative/dspark_components/dspark_worker_v2.py", line 1296, in _forward_decode
    self._verify_executor.commit_hidden(
  ...
  File ".../models/dspark_minimax.py", line 172, in project_target_hidden
    return self.hidden_norm(self._fc_gatherer(self.fc(target_hidden)[0]))
  ...
ValueError: Mismatched mW.shape[0] on argument #1 when calling: `__call__(mX: Tensor([n0, 24576], bfloat16), mW: Tensor([24576], bfloat16), ...)`, expected to be 24576
```

Under attention DP a dense DSpark draft runs on the attention-TP group, which `DSparkWorkerV2` enters with `_draft_context()` to build the draft, capture its graphs, propose, and inject the prefill KV, but not for the decode-step `commit_hidden`. There the M3.1 draft all-gathers its column-parallel `fc` output over the whole TP group: 4 x 6144 = 24576 columns into the 6144-wide `hidden_norm` at `--tp 4 --attn-dp-size 4`, and 4 x 3072 = 12288 in a PD decode worker at `--attn-dp-size 2`.

Colocated `--attn-dp-size 2` happens to work: `MultimemAllGatherer` binds its multimem buffer to the group of its first call, the prefill inject inside the placement, which a PD decode worker never runs. At attention-TP size 1 it builds no buffer, and its NCCL fallback gathers over the current TP group.

## Modifications

Run the decode-step `commit_hidden` inside `self._draft_context()`, like the prefill inject. Without attention DP the context is a no-op.

## Accuracy Tests

MiniMax-M3.1-Flash with DSpark, 4x GB300 (PD: one tray per role), main and this PR on `lmsysorg/sglang:nightly-cu134-20261026-5ef9901`. GSM8K with sgl-eval 0.1.3 (temperature 1.0, top_p 0.95, `--max-tokens 32768`); cells are all 1,319 questions / the first 100 one at a time:

| Layout | main | This PR |
|---|---|---|
| `--tp 4 --attn-dp-size 4 --ep 4` (MegaMoE) | crash | 96.36 / 96 |
| `--tp 4 --attn-dp-size 2 --ep 4` (MegaMoE) | 96.13 / 97 | 95.45 / 96 |
| `--tp 4` (TRT-LLM routed MoE) | 95.45 / 99 | 95.91 / 98 |
| PD 1P1D (Mooncake), `--attn-dp-size 2` on both roles | decode worker crash | 95.15 / 98 |

At temperature 1.0 one standard error on 1,319 questions is about 0.5 points.

DSpark acceptance length at `--attn-dp-size 4` is in line with `--tp 4`: 4.01 / 4.23 against 4.01 / 4.28 (SPEED-Bench coding / GSM8K prompts, T 1.0). Passkey retrieval passes at 126k and 503k prompt tokens, and `--disaggregation-enable-kv-checksum` logs no mismatch on either PD role.

The existing DSpark CPU tests in `test/registered/unit/spec/` pass.
