# [Doc] [AMD] cookbook: Add the Qwen3.5 MI355X FP8 agentic recipe covering the GPU-resident and HiCache bands

[Upstream PR](https://github.com/sgl-project/sglang/pull/46757) · state: closed · merged: True

## Original PR description

## Motivation

The Qwen3.5 cookbook documents the MI355X FP8 agentic recipe only for the HiCache band: TP4, `--kv-cache-dtype fp8_e4m3` and the scheduler/tokenizer tuning are emitted only when Host DRAM (HiCache) is selected. The same recipe also serves low concurrency (1-14) entirely from GPU KV with no HiCache tier, and that configuration is not described anywhere on the page.

This adds it in the shape of DeepSeek-V4.1 cookbook section 3.6 ("Agentic Long-Context on MI355X"): one launch command, per-concurrency values, and the bands called out explicitly.

## Modifications

`docs/cookbook/autoregressive/Qwen/Qwen3.5.mdx`

- Add section 3.3.1, "Agentic Long-Context on MI355X (FP8, MTP)": one full launch command matching the recipe's flags and env vars, a per-concurrency table (1-80) of `--max-running-requests`, `--cuda-graph-max-bs-decode` and `--hicache-size`, and the HiCache flags for concurrency 16-80.
- State that concurrency 1-14 runs GPU-resident without HiCache.
- Note that `NEXTN` resolves to `EAGLE`, and that multithreaded weight loading is the default.
- Update the FP8 KV cache warning and the HiCache bullet, which tied the FP8 KV cache and tuning to HiCache only, to point at the new section.

Documentation only; the generated Playground commands are unchanged.

Documentation-only; no runtime code path is touched.
