# [Feat] mem_cache: prepare registered backends before worker graphs

[Upstream PR](https://github.com/sgl-project/sglang/pull/44856) · state: open · merged: False

## Original PR description

## Motivation

A registered radix-cache factory runs after the scheduler has initialized worker CUDA Graphs. It cannot prepare layer-transfer counters/events that must be present during initial graph capture. This adds an optional preparation callback at the existing worker boundary without moving cache construction.

Refs https://github.com/sgl-project/sglang/issues/44855.

## Modifications

- Add keyword-only `prepare_worker` to `register_radix_cache_backend`. Keep the original factory identity and store factory/callback in one registry entry; invalid or duplicate registration cannot partially overwrite it.
- Dispatch only the published selected backend before any runner in `TpModelWorker.init_cuda_graphs`, passing the same worker and original `capture_decode_cuda_graph` value. Old registrations/default selection are no-ops; unknown backends and callback errors stop before runner initialization.
- Document repeat-call idempotence and the limited boundary. `ensure_decode_cuda_graphs`, independent runner recapture, pending admission and teardown are outside this change.
