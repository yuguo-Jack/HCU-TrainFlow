# [Feat] sgl-router: Serve the OpenAI Responses API on /v1/responses

[Upstream PR](https://github.com/sgl-project/sglang/pull/42314) · state: open · merged: False

## Original PR description

## Motivation

Clients built on the OpenAI Responses API (the openai SDK's `responses.*`, Codex) cannot use sgl-router today: it only serves chat completions. This adds `POST /v1/responses` to the router.

## Modifications

A Responses request is converted to a chat request at ingress and served by the existing `chat_completions` handler, so it is routed exactly like chat (tokenization, cache-aware routing, admission, retry, PD). The reply is converted back on the outer body, streaming or not.

- **Request**: string or item `input`; messages (`developer` → `system`), reasoning, function calls and outputs; text and image parts; `instructions`, `max_output_tokens`, `reasoning.effort`, `text.format` (JSON schema), `tool_choice`. Conversion works on `serde_json::Value`, so sglang chat extensions (`top_k`, `chat_template_kwargs`, …) pass through.
- **Tools**: `function`, plus the shapes Codex sends: `namespace` groups (flattened to `<ns>__<name>`) and `custom` freeform tools (a function with one `input` string, grammar appended to the description). Replies map back to namespaced `function_call` / `custom_tool_call` items, and history items of both kinds are accepted.
- **Streaming**: the spec event sequence with a gapless `sequence_number` (`response.created` → `in_progress` → item / part / delta / done events → `completed`, `incomplete` or `failed`); usage, including `cached_tokens`, is always present. An engine abort ends the Response as `failed`.
- **Unsupported, rejected with 400**: `previous_response_id`, `conversation`, `background` and stored prompts (the router is stateless; send the full conversation), and `top_logprobs`. `reasoning.effort` is passed through to the engine unchanged.
- **Errors**: engine errors are re-wrapped into the `{"error": {...}}` envelope; an upstream reply that cannot be read or parsed is a 502 via `ApiError::UpstreamStatus`.
- `src/protocol/sse.rs` is a small generic layer that rewrites a chat SSE body into another protocol's events (`SseTransducer`, `transduce_body`). It wraps the body produced by `proxy/sse.rs`, so timeouts, abort-on-disconnect and TTFT/ITL metrics are unchanged.

Built-in tools such as `web_search` are rejected with 400.

The companion PR for Anthropic `/v1/messages` (#42316) carries a byte-identical `protocol/sse.rs`; whichever lands second only needs a one-line rebase in `protocol/mod.rs`.
