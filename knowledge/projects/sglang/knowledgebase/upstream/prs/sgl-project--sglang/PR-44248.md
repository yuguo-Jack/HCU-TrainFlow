# [PD] Bound the mooncake early-registration room lifecycle

[Upstream PR](https://github.com/sgl-project/sglang/pull/44248) · state: open · merged: False

## Original PR description

## Motivation

PD frontends can dispatch the decode leg of a request concurrently with — or ahead of — the prefill `/generate` reaching its scheduler (ai-dynamo's prefill-router has a documented race where the decode phase begins before SGLang has registered the room on the prefill side, dynamo#9388), so a room registration can arrive at the prefill `bootstrap_thread` while the room's `MooncakeKVSender` does not exist yet. Decode registers exactly once and never re-sends.

Unconditional early acceptance of such registrations is *correct* (this PR keeps it), but the other end of the lifecycle has two gaps on current main:

1. **A registration for a concluded room recreates its transfer targets.** A room that is terminal `Failed`, or whose tables were popped after a failure/success, gets its `transfer_infos[room]` re-created by a late registration. The chunks belong to a request that no longer exists, and a later request that happens to reuse the same `bootstrap_room` would inherit them (dead-end transfers; cf. the room-reuse caution already documented in `update_status`, and the duplicate-room failure family in #40125).

2. **Early registrations with no prefill leg leak.** When the /generate leg never arrives (router dropped it, request re-routed), the `request_status`/`transfer_infos` entries its registration created are never reclaimed — unbounded growth under router churn.

## What this PR does (prefill-role only)

- `MooncakeKVSender.__init__` **claims** its room before the base inserts `Bootstrapping`; `clear()`/`abort()` **tombstone** the room before the teardown pops the tables. That ordering makes a consumer snapshot that reads neither the tombstone nor a live state impossible.
- The registration handler keeps accepting early registrations, but **drops registrations for concluded rooms**: terminal `Failed`, tombstoned, or table-absent with a recorded failure (covers a conclusion whose tombstone was not written locally, e.g. a sibling-rank bootstrap timeout concluded the room first).
- A 15s **housekeeping sweep** reclaims rooms whose early registration was never claimed by a prefill request within `SGLANG_DISAGGREGATION_BOOTSTRAP_TIMEOUT + 60s` (concluding them first — tombstone + recorded root cause, like a sender would), and expires stale tombstones. Sender creation and teardown both synchronize on the lifecycle lock before touching the room tables, so a room still tracked as early is guaranteed to have no live sender.
- The lifecycle hooks no-op on a manager without the lifecycle state (decode role, or partially constructed test shells), so no existing test needs to change.

No wire-format changes; no behavior change for healthy rooms.

## Tests

New `test/registered/unit/disaggregation/test_mooncake_registration_lifecycle.py` (9 cases): early acceptance and completion before the sender exists; no demotion across sender creation (the `max()` ordering in `update_status`); partial multi-decode-rank registration; the three concluded-room drops (Failed / tombstoned / failed-then-cleared); sweep reclaim and preserve of fresh/claimed rooms. Full `test/registered/unit/disaggregation` suite on this branch: **691 passed, 18 skipped, 0 failed** (main is green here).

## Production context

Seen in a kv-router PD + mooncake deployment under closed-loop bursts: rooms whose registration races the prefill leg's intake (the wedge class), and — the flip side that motivated this PR's hardening — a bootstrap-timeout abort leaves no target to notify, so a late registration drifts in for a room that already concluded and must not be re-armed. Related upstream conversations: #40125 (duplicate bootstrap_room), #10111 (bootstrap stalls under load), #43719 (deferred-ack poisoning family).
