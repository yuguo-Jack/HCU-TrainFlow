# [Perf] [AMD] kda: Kimi-K3 verify tuning, four-step ReplaySSM commit and chunk-major prefill scan on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/44982) · state: open · merged: False

## Original PR description

> Kimi-K3 on gfx950 merge queue (all drafts; they land one at a time in this order): 1 #44978 verify argmax + tuned bf16 rows · 2 #44979 MLA prefill · 3 #44980 streaming AttnRes · 4 #44981 MoE prefill · 5 #44982 KDA · 6 #44983 MLA decode prep · 7 #44984 MLA decode epilogue · 8 #44985 LL column tail · 9 #44986 fused all-reduce read · 10 #44987 fused route sort · 11 #44988 split MoE front + bank partials · 12 #44989 MLA q-norm + q_b. Replaces #44547-#44553.

## Motivation

Kimi-K3 runs 69 KDA layers. On gfx950 the EAGLE verify kernel, the ReplaySSM commit and the chunked-prefill scan
leave measurable time on the table for the K3 TP8 shape (12 heads per rank, K = V = 128, 4-token drafts), and the
MXFP4 checkpoint never takes the fused KDA in-projection even though its attention weights are bf16.

## Modifications

All new paths are gated on `is_gfx95_supported()`; other platforms keep their current kernels.

Verify and commit (EAGLE):
- `fused_kda_conv_gating_verify`: on gfx950 the inputs of step t + 1 are loaded before step t's stores
  (`PREFETCH_NEXT`; vmcnt also counts stores, so a load issued after the stores waits for their acks), and the
  K3 TP8 shape picks its V tile by batch size. The output is bit-identical with and without the prefetch.
- `kda_backend`: the ReplaySSM ring write covers every gfx950 batch the HIP verify gate admits, and that gate now
  takes 4-token drafts. The PP-spec validity mask is only built when PP spec reads it (one launch per layer).
- `commit_kda_replayssm_after_verify(max_accept=)`: with at most 4 accepted tokens on gfx950 the fold loads every
  ring row before the first update (bit-identical to the dynamic loop).
- `kimi_k3_tiny_gemm`: a K = 128 Triton GEMM for the f_b projection at verify sizes (M <= 64) on gfx950.

Chunked prefill (K = V = 128, gfx950):
- The gated key is written chunk-major (`[chunks, H, K, 64]`, tokens contiguous) by both producers, so the state
  scan's reduction dimension loads straight into the MFMA operand; the scan's V tile follows the CU count
  (`SGLANG_ROCM_KDA_CHUNK_MAJOR_SCAN`).
- Extends of at most `SGLANG_ROCM_KDA_FUSED_OUTPUT_MAX_TOKENS` (3072) tokens run a scan that also writes the output
  (`fla/kda_chunk_scan.py`), dropping the per-chunk checkpoint and its separate output kernel.

Kimi-K3: `_may_fuse_kda_inproj` no longer requires `do_fuse_qkvbfg` (which also requires `quant_config is None`);
the existing unquantized-weight check still rejects quantized projections.

| New env var | Default |
|---|---|
| `SGLANG_ROCM_KDA_CHUNK_MAJOR_SCAN` | on |
| `SGLANG_ROCM_KDA_FUSED_OUTPUT_MAX_TOKENS` | 3072 |

## Accuracy Tests

**Setup for every number below:** 8x MI350X (gfx950, 1000 W), Kimi-K3 (MXFP4 MoE, bf16 attention) at TP8 with EAGLE3
(topk 1, 3 steps, 4 draft tokens), FP8 KV cache, `SGLANG_USE_AITER=1`, aiter's K3 FlyDSL kernels
(`AITER_SITUV2_A8W4=1 AITER_FLYDSL_FORCE=1 SGLANG_AITER_K3_OPT=1`), CUDA graphs for bs 1/2/4/8/16, and an aiter bf16 GEMM table with K3 rows re-tuned on this pod with HBM-resident weights
(`AITER_CONFIG_GEMM_BF16`; not part of this PR, it belongs in aiter's model configs). EAGLE3 on K3 needs the
aux-capture commit of #43599, applied locally for these runs. Microbenchmarks rotate their weights through HBM.
Per-feature numbers were measured on the integration branch of this series as each piece landed (Oct 13-14,
earlier `main`). All branches of the series are on `main` 4eb606b2ae (2026-10-17); the kernel tests below ran on this
branch, and the end-to-end checkpoints on that `main` plus the queue up to each slot.

- GSM8K 400 (chat, greedy): 0.985 / accept length 3.61 with the chunk-major scan; 0.9825 / 3.618 with the ReplaySSM
  ring + four-step fold; end to end: see below.
- Kernel tests on MI350X: `test_fused_kda_conv_recurrent_verify.py` (new K3 TP8 cases), `test_kda_replayssm_fold_batched.py`
  (new: four-step fold == dynamic loop, bitwise), `test_kda_chunk_major_scan.py` (new: chunk-major scan bit-exact with
  token-major; fused-output scan within rounding; tail chunks, padded rows, track snapshots),
  `test_kimi_k3_kda_inproj_fusion.py` (new: the MXFP4 checkpoint's bf16 in-projection fuses; f_b GEMM vs F.linear):
  43 passed, 1 skipped (a CUDA-only green-context case), 19 subtests passed.
- `test_glm_fp32_weights_bit_exact_on_rocm` fails on `main` in this image as well (unrelated to this change; #43991
  fixes it), so its two cases were deselected in the run above.
