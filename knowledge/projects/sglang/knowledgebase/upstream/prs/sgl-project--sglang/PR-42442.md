# [Feat] function-call: Add strict DSML validation and recovery

[Upstream PR](https://github.com/sgl-project/sglang/pull/42442) · state: open · merged: False

## Original PR description

Reopened from #39435. GitHub closed that PR on 2 October when the fork it came from was deleted; its review history is still there.

## Motivation

Current main buffers complete DeepSeek invokes and rejects malformed parameter tags through #39632. It still ignores stray prose around otherwise valid parameters, drops only the malformed invoke in a multi-call turn, and suppresses the rejected DSML text. Some deployments need the rejected text for recovery and prefer dropping the whole non-streaming turn over executing its remaining calls.

## Modifications

Add `SGLANG_ENABLE_STRICT_DSML_TOOL_CALLS`, default `false`, to the shared DeepSeek detector. With strict mode enabled, every non-blank character in an invoke body must belong to a complete parameter tag, or the body must be one valid JSON object. A malformed body returns the full non-streaming turn as content with a warning and no calls.

Streaming keeps main's complete-invoke buffering. The tool name and validated arguments are emitted together only when the invoke closes. A malformed invoke forwards the rest of its calls block as content and prevents later invokes in that block from becoming calls. Parsing resumes after the block closer. Calls emitted before the malformed member cannot be recalled.

The rebase retains upstream's configurable tag names, rejection of non-standard JSON constants, whitespace handling and default fail-closed behavior. The earlier partial-argument streaming implementation is removed because #39632 makes it unnecessary. This also satisfies the review request to keep a complete JSON object from escaping before the entire invoke passes validation.

## Validation

Rebased onto upstream `f2385314b2b3` on 2026-10-04; the commit is patch-identical to the 2026-10-02 revision. The strict DSML suite and the existing V4 and V4.1 detector suites pass on CPU: 59 tests and 1,055 subtests. Coverage includes malformed bodies, valid parameters, JSON followed by trailing text, multiple blocks, chunk widths from 1 to 1,000, cut streams, name/argument atomicity, preamble preservation and unchanged default behavior. The strict suite uses `unittest.TestCase`, like the existing parser tests, to avoid importing model runtime dependencies for pure string parsing. The repo's pre-commit hooks pass on the changed files.

Ruff 0.15.1 lint and format, isort 7.0.0, codespell and `git diff --check` pass on the changed files. No model execution or GPU validation was rerun after this rebase. Earlier served checks used DeepSeek-V4.1-Flash on four RTX PRO 6000 GPUs, but those results predate the current upstream parser and are not evidence for this head.

No speed result is claimed. Strict mode adds one check of unmatched body text and a forwarding path on parse failure; normal argument parsing and complete-invoke buffering remain upstream's implementation.
