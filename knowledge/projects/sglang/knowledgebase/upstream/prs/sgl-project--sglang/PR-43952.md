# [Fix] [AMD] diffusion: Prevent ComponentResidencyError after compile warmup

[Upstream PR](https://github.com/sgl-project/sglang/pull/43952) · state: closed · merged: True

## Original PR description

## Motivation

**What goes wrong**
On gfx1250, the first real request after torch.compile warmup raises ComponentResidencyError for transformer_2 on Wan 2.2 A14B. That request always calls disable_offload(), which sets manager.enabled to false. The user passed --dit-layerwise-offload, so the residency plan for transformer_2 is still layerwise offload, and preparing that component fails the check.

**Where it shows up**
The disable_offload() call is shared, so any device that compiles with explicit layerwise offload can hit it. gfx1250, and any machine where both DiTs still fit, keeps the weights resident. Putting them back after the compile window matches that plan, so there is no residency error. It shows up on the low-memory Wan 2.2 A14B path, including the gfx1250 multi-GPU run: visible memory is not enough for both DiTs, so layerwise offload has to stay on after compile. The cleanup path treats that the same as a temporary compile window.

**How to fix**
Call disable_offload() only when the user did not ask for layerwise offload, so a compile-only window still restores GPU residency and an explicit request stays enabled.

## Reproduction

This Wan 2.2 A14B config is the low-memory run that raised `ComponentResidencyError` for `transformer_2`. `offload_during_compile` is left at its default, `true`.

```bash
sglang generate \
  --model-path /mnt/raid/models/Wan2.2-T2V-A14B-Diffusers/ \
  --prompt "A cat and a dog baking a cake together in a kitchen." \
  --height 720 --width 1280 \
  --num-inference-steps 8 \
  --num-frames 193 \
  --seed 42 \
  --num-gpus 2 \
  --enable-cfg-parallel \
  --performance-mode auto \
  --dit-layerwise-offload true \
  --enable-torch-compile true \
  --warmup-mode server \
  --attention-backend aiter
```

## Modifications

- `DenoisingStage._explicit_dit_layerwise_offload()` is true when `dit_layerwise_offload` is set or `is_dit_layerwise_offload_selected` is true.
- `_offload_for_torch_compile_warmup` calls `disable_offload()` only when that helper is false. An explicit layerwise request stays enabled. A compile-only window still restores GPU residency.
- Unit tests cover both cases: an explicit request does not call `disable_offload()`, and a compile-only window still does.
