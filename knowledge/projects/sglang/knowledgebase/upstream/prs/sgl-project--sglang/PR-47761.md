# [Perf] dsa: Use larger FP8 KV tiles for high query parallelism

[Upstream PR](https://github.com/sgl-project/sglang/pull/47761) · state: open · merged: False

## Original PR description

Use 128-row KV tiles for eligible SM90 FP8 sparse attention workloads. Mask virtual padding in the final index tile so non-divisible top-k widths do not require an index-table copy. Preserve existing dispatch for other architectures and layouts.

## Motivation

<!-- Describe the purpose and goals of this pull request. -->

Improve TileLang FP8 sparse attention on SM90 when query parallelism is already sufficient. Larger KV tiles reduce serial loop and online-softmax update overhead, delivering **1.11×–1.13× speedups** in the measured Partial + Combine microbenchmarks.

## Modifications

<!-- Detail the changes made in this pull request. -->

- Select 128-entry KV tiles for SM90 FP8 workloads with 16 heads, a 512-dimensional latent, no RoPE tail, index width ≥2048, and query rows ≥4× the SM count. Keep existing dispatch for other architectures and layouts.
- Support non-divisible index widths with masked virtual padding and consistent ceiling-based block counts. For width 2112, block128 takes 17 iterations instead of block32's 66, without widening or copying the index tensor.
- Extend the existing TileLang DSA regression helper with one SM90 large-query case covering width 2112, a valid final logical column, and CUDA Graph replay.

## Accuracy Tests

<!-- If this pull request affects model outputs (e.g., changes to the kernel or model forward code), provide accuracy test results. -->

H200 validation of the kernel change covered **19 cases**, including neighboring query counts, index widths, invalid indices, KPool tails, fallback layouts, and CUDA Graph replay. FP8 results passed the fixed relative-L2 threshold of 0.03 against sampled FP32 references; virtual padding matched explicit padding exactly in the 13 eligible cases.

Pre-commit and 528 CPU dispatch/coverage checks pass on this branch. The added GPU regression has not yet been rerun on the rebased PR head.

## Speed Tests and Profiling

<!-- If this pull request impacts inference speed, provide benchmarking and profiling results. -->

H200 CUDA Graph microbenchmarks compare block32 and block128, both using 128 threads and one KV split. Inputs use synthetic Q/KV, sparse indices and page mappings with 16 heads, latent dimension 512, no RoPE tail, and index width 2112. Timings cover **Partial + Combine** and exclude projection, Indexer and index preparation.

| Query rows | Shared-prefix KV speedup | Independent KV speedup |
|---:|---:|---:|
| 528 | 1.128× | 1.123× |
| 768 | 1.121× | 1.119× |
| 1024 | 1.126× | 1.121× |
| 1536 | 1.125× | 1.116× |

At 1024 query rows, shared-prefix KV takes **1.095 → 0.972 ms**; independent KV takes **1.121 → 1.000 ms**. Independent KV assigns separate physical context pages to each request.
