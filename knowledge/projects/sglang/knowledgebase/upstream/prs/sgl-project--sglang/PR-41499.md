# [Test] [NPU] hicache: Add storage prefetch retry e2e test

[Upstream PR](https://github.com/sgl-project/sglang/pull/41499) · state: open · merged: False

## Original PR description

## Motivation

Add a dedicated Ascend NPU e2e test that validates the HiCache L3 storage prefetch retry parameters — `--hicache-storage-prefetch-retry-max-attempts` and its companion `--hicache-storage-prefetch-retry-poll-interval` — are consumed on the NPU backend. HiCache's tiered cache backs long prefixes out to the L3 storage backend, and storage prefetch supervises the recovery of cached prefixes with a bounded retry budget and a paced poll interval. These parameters are device-agnostic by design, but before this PR there was no CI coverage proving they actually engage on Ascend (NPU). This PR closes that gap with a self-contained e2e case so regressions in the retry-budget path on NPU are caught automatically.

## Modifications

- **`test/registered/npu/basic_function/HiCache/test_npu_hicache_storage_prefetch_retry.py`** — add a new NPU e2e test class `TestNPUHiCacheStoragePrefetchRetry` that:
  - Launches Qwen3-8B on Ascend with `--enable-hierarchical-cache`, `--hicache-storage-backend file`, `--hicache-storage-prefetch-policy wait_complete`, `--hicache-storage-prefetch-retry-max-attempts 4`, and `--hicache-storage-prefetch-retry-poll-interval 1`, forcing the long prompt onto the L3 `file` backend.
  - Sends a long (multi-page) prompt and asserts the first request has `cached_tokens == 0`.
  - Calls `/flush_cache` to drain the device cache, guaranteeing the next request must walk the storage prefetch path.
  - Re-sends the same prompt and asserts a storage prefetch hit (`cached_tokens > 500`), proving the retry parameters were exercised end-to-end without error.
  - Registers the suite via `register_npu_ci` (`est_time=400`, `suite="full-1-npu-a3"`, `nightly=True`).
  - **Also fixed within this branch**: call `/flush_cache` on the root path with a `timeout` query param, and surface the response error body in the assertion when the call fails, so failures are diagnosable rather than opaque.

## Accuracy Tests

This is a functional e2e test rather than an accuracy benchmark. The test verifies correct end-to-end behavior of the storage prefetch retry budget on NPU: it asserts the flush triggers a genuine remote (L3) access on the second request and that the retry parameters are consumed without error. The test has been run and validated on the NPU (Ascend) environment.

## Speed Tests and Profiling

No throughput impact. This PR only adds and refines a CI e2e test; it does not change any runtime kernel, collective, or serving path. It adds NPU coverage for the retry-budget configuration knob already used on other backends.
