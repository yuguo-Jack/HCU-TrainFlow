# [Refactor] unified-cache: Factor match validators and match completion into helpers

[Upstream PR](https://github.com/sgl-project/sglang/pull/45714) · state: closed · merged: True

## Original PR description

Follows #45703 (the shared match result fields and the `_match_prefix_helper(key, params)` signature it introduces); this pull request's base is that branch, and its own diff is the top commit only.

## Motivation

`UnifiedTreeCore._match_prefix_helper` builds the per-component match validators inline, and `UnifiedRadixCache._match_tree` runs the component finalizers and the linker inline after the walk's actions are applied. A tree core or cache layered on these classes (for example one registered through the tree core registry) that wants another validator, or work between the walk's actions and the finalizers, has to copy both loops.

## Modifications

- `UnifiedTreeCore._create_match_validators(params, match_device_only)` returns the validator tuple for a walk; `_match_prefix_helper` calls it for the HiCache case (host-backed nodes allowed) and the device-only case instead of building the tuples inline.
- `UnifiedRadixCache._finalize_match_result(params, result)` runs the component finalizers in component order, asserts they emitted no actions, and applies the linker; `_match_tree` calls it right after the walk's actions are applied.
- A unit test in `TestUnifiedRadixCacheActionRouting` pins the order: the walk's actions first (a split routed to FULL, then the freed KV segment), then the completion with the same `params` and `result` objects, the finalizers in component order, and the linker last.

No behaviour change for the stock cores: the same calls run in the same order.
