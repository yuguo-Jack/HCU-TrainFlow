# [Fix] [NVIDIA] inkling: Fit small-M grouped GEMM in SM120 shared memory

[Upstream PR](https://github.com/sgl-project/sglang/pull/45420) · state: open · merged: False

## Original PR description

## Motivation

Inkling doesn't start on SM120 GPUs (RTX 50 series, RTX PRO 6000 Blackwell). The server dies while capturing decode CUDA graphs:

```
File ".../sglang/kernels/ops/moe/inkling_moe.py", line 998, in grouped_gemm_triton
    _grouped_gemm_kernel[grid](
triton.runtime.errors.OutOfResources: out of resource: shared memory, Required: 110592, Hardware limit: 101376.
```

The small-M grouped GEMM config (used for decode, up to 6144 routed tokens) runs with `num_stages=4`. With 16x128x128 bf16 tiles, Triton keeps 3 stage buffers in shared memory: 3 x 36,864 B = 110,592 B. SM120 only allows 101,376 B per block.

This was already fixed for SM121 (GB10 / DGX Spark) in [#33108](https://github.com/sgl-project/sglang/pull/33108). SM121 has the same 99 KB limit, but that fix only checks `is_sm121()`, so SM120 still gets 4 stages.

This affects the NVFP4 checkpoint too, not just BF16. NVFP4 experts use FP4 kernels, but `Inkling-Small-NVFP4` leaves layer 2's experts unquantized (`model.llm.layers.2.mlp.experts` is in `exclude_modules`). Those BF16 experts go through `grouped_gemm_triton`, so the NVFP4 model crashes on SM120 as well.

## Modifications

- `inkling_moe.py`: use `num_stages=3` on SM120 as well (`is_sm120() or is_sm121()`). That needs 2 x 36,864 B = 73,728 B, which fits. Other GPUs are unchanged.
- `test_moe_preprocess.py`: also register the test on the `1-gpu-small` (RTX 5090) runner, the same way `test_convrot_int8.py` does. This test already covers the small-M config, but it only ran on H100, which is why this slipped through.

## Accuracy Tests

Only the pipeline depth changes. The math is the same, so outputs are identical (same as #33108).

Tested on an RTX 5090:

- `test_moe_preprocess.py`: 3 failed / 14 passed before the fix (`test_grouped_gemm_small_config_matches[1|16|64]`, all `OutOfResources`), 17 passed after.
- I also ran the whole `base-b-kernel-unit-test-1-gpu-small` suite with this change, and nothing else was affected.
- End to end: the real checkpoint (171 GB) doesn't fit on one card, so I shrank Inkling-Small's config to 3 layers (2 dense + 1 MoE, matching the real model's first layers, 32 experts) and launched it with `--load-format dummy --disable-prefill-cuda-graph`. Before: the server dies in `capture_decode_graph` with the error above. After: it starts and serves `/v1/chat/completions`.
