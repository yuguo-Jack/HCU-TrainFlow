## Original PR description

# Add Xing4.0-29B-A4B (Xing4_0) model support

## Summary

Adds native support for the open-weights **Xing4.0-29B-A4B** model: https://huggingface.co/XingChen-AGI/Xing4.0-29B-A4B (also available on ModelScope: https://modelscope.cn/models/XingChen-AGI/Xing4.0-29B-A4B)

- **Model**: 29B total / 4B activated MoE, 40 layers, 64 routed experts (top-4), first 2 layers dense
- **Architecture**: DeepSeek-V2 building blocks (MLA attention) with Xing4-specific extensions:
  - **mHC** (multi-head residual, `hc_mult=4`) residual streams with fused `mhc_pre` / `mhc_post` TileLang kernels registered as torch custom ops for torch.compile compatibility
  - **KTEP** CPU-offloaded experts (partial expert offloading)
  - **DSA** (DeepSeek Sparse Attention) support
  - **MTP**: DeepSeek-V3-compatible MTP head reused as the EAGLE draft model (draft weights carried in the main checkpoint)
- Reuses `DeepseekV2MoE` / `DeepseekV2MLP` / `DeepseekV2AttentionMLA` / `DeepseekV2WeightLoaderMixin` and integrates with the `layer_boundary` (`append_stages`) stack abstraction
- Includes `xing4_0` reasoning parser and tool-call parser (auto-detected via `reasoning_config`)

## Changes

- `python/sglang/srt/models/xing4_0.py`: model implementation (adapted to the `append_stages` layer-boundary refactor: boundary declarations, `reduce_results=False` MLP/MoE with boundary-managed output sums, explicit TP `sum_output` in the mHC branch)
- `python/sglang/kernels/ops/layernorm/mhc.py`: `mhc_pre` splitk kernel support for `hc_hidden_size=14336`
- `python/sglang/srt/configs/xing4_0.py`: `Xing4_0Config` registered in the config registry
- `python/sglang/srt/function_call/xing4_0_detector.py`, parser name lists: `xing4_0` tool-call parser (also wired into the static CLI choices)
- `python/sglang/srt/parser/reasoning_parser.py` + names: `xing4_0` reasoning parser
- `python/sglang/srt/arg_groups/`: auto-detection hooks (reasoning/tool-call parser defaults for the architecture)
- `test/registered/moe/test_xing4_0_model.py`: GSM8K e2e regression test (nightly, `2-gpu-large`, tp=2) with the xing4_0 reasoning/tool-call parsers enabled — so future interface refactors that break this model are caught by CI
- Docs entries in `supported-models/generative_models.mdx` and `advanced_features/tool_parser.mdx`

## Test Evidence

- Server launches successfully with `--tp-size 2 --speculative-algorithm EAGLE` (auto-selected steps=3, topk=1, draft_tokens=4), MTP draft weights loaded from the main checkpoint
- Greedy decoding produces coherent Chinese output; health check passes
- Added test collected and registered for the nightly CUDA CI

```bash
sglang serve --model-path XingChen-AGI/Xing4.0-29B-A4B \
  --trust-remote-code --tp-size 2 \
  --reasoning-parser xing4_0 --tool-call-parser xing4_0 \
  --speculative-algorithm EAGLE   # uses the checkpoint's native MTP layer

curl -s http://localhost:8000/v1/chat/completions -H "Content-Type: application/json" -d '{
  "model": "XingChen-AGI/Xing4.0-29B-A4B",
  "messages": [{"role": "user", "content": "Introduce yourself in one sentence."}]
}'
```

## Notes for Reviewers

- The GSM8K score floor in the new test is intentionally conservative (0.3) until a reference score is established; happy to tighten after a full eval run
- mHC branch bypasses the stage boundary and completes its MLP output sum explicitly via `sum_output(SumGroup.TP)`; the boundary-managed path is used everywhere else

Done. The model-local mHC plumbing is gone; everything now goes through sglang.kernels +`MHCState` , following the glm5_next wiring:

- `mHCModule` is now a thin`MHCState` adapter over the high-level`hc_pre` /`hc_post` wrappers;`DecoderLayer` wires attention/FFN boundaries through`MHCState` residual ops, and pipeline ranks use the standard`from_pp` /`to_pp` flow. The torch custom-op registrations, the hand-rolled mHC forward branch, and`input_expand` /`output_contract` are deleted (net −332 lines).
- Two Xing4_0-specific behaviors remain in the adapter, both verified necessary: (1) the checkpoint's`hc_fn` was trained with the residual mixing matrix transposed relative to the kernel convention, so`h_res` is transposed after`hc_pre` — without it the model's outputs are gibberish; (2) on Ascend,`torch.ops.npu.hc_pre` /`hc_post` are selected at the model layer, mirroring how deepseek_v4 selects its NPU mHC ops.
- One small addition to`sglang.kernels` :`hc_pre` now threads`n_splits_pre` so the 14336 splitk path (already in this PR's kernel diff) is reachable from the high-level API — the default 32 is illegal for`hc_hidden_size=14336` (14336/32=448 is not a multiple of the kernel's`hidden_block` ). Default stays 32; glm5_next / dsv4 are unaffected.
- Verified numerically identical to the previous path (`h_post` /`h_res` /`hc_post` outputs equal), and end-to-end: GSM8K 100 samples 0.87 (reference 0.84), reasoning and tool-call e2e passing.
