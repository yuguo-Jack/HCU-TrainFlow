# [Feat] xing4_0: Add model support

[Upstream PR](https://github.com/sgl-project/sglang/pull/39793) · state: open · merged: False

## Original PR description

This PR adds support for **Xing4.0-29B-A4B** (29B-parameter MoE with \~4B activated parameters), which combines MLA attention with mHC (multi-hyper-connections) residual streams.

Model weights: [<https://modelscope.cn/models/XingChen-AGI/Xing4.0-29B-A4B>](https://huggingface.co/XingChen-AGI/Xing4.0-29B-A4B)

### Key changes

- `python/sglang/srt/models/xing4_0.py`: model implementation built on the DeepSeek-V2 building blocks (MLA + MoE), with fused TileLang mHC kernels (`mhc_pre` / `mhc_post`) registered as torch custom ops for torch.compile compatibility
- `python/sglang/srt/configs/xing4_0.py`: `Xing4_0Config` registered in the config registry
- DeepSeek-V3-compatible MTP head reused as the EAGLE draft model
- `xing4_0` tool-call parser (tag-based `<tool_call>name<param_key>k</param_key><param_value>v</param_value></tool_call>` format) and reasoning parser
- `mhc_pre` splitk kernel support for `hc_hidden_size=14336`
- Docs entries for the tool-call parser and supported models

### Launch command

```bash
python -m sglang.launch_server \
  --model-path XingChen-AGI/Xing4.0-29B-A4B \
  --trust-remote-code \
  --tp-size 2 \
  --context-length 262144 \
  --reasoning-parser xing4_0 \
  --tool-call-parser xing4_0 \
  --speculative-algorithm EAGLE
```

Verified with TP=2, 262K context, and EAGLE (MTP) speculative decoding.

Thanks for the review, @gjsheu — all four points have been addressed in the latest commit.

- **L340 `_get_llama_4_scaling`**: confirmed it was never called. It was a duplicated copy of the
  helper already defined in `deepseek_common/utils.py` (that's the one `deepseek_v2.py` uses).
  Removed it. The `llama_4_scaling` argument on the layer `forward` is independent and left as-is.
- **L383 `hasattr(config, "index_topk")`**: it was a bare no-op statement — deleted.
- **L384 `config.model_type == "deepseek"`**: correct, `Xing4_0Config.model_type` is always
  `"xing4_0"`, so that operand was always `False`. Simplified to
  `use_mha = all(dim == 0 for dim in (qk_nope_head_dim, qk_rope_head_dim))`.
- **MTP plumbing (376-377, 410, 425, 454, 458, 464, 702-703, 988, 1031)**: confirmed it can be
  removed. `Xing4_0Model` only builds `num_hidden_layers` layers and never constructs a layer with
  `is_nextn=True`; the draft is dispatched to `DeepseekV3ForCausalLMNextN` via `model_config.py`,
  and the model loader calls `load_weights(weights)` without `is_nextn`. Removed all of it —
  including the second `if self.enable_mhc and not self.is_mtp_layer` in `forward`, which relied on
  the same now-dead `self.is_mtp_layer`.

Net effect is dead-code removal only; verified TP=2 / 262K / EAGLE generation still produces
correct output. Thanks!
