# [Fix] [NPU] awq: Preserve weight dtype in linear fallback

[Upstream PR](https://github.com/sgl-project/sglang/pull/47639) · state: open · merged: False

## Original PR description

## Motivation

The NPU AWQ linear fallback always casts dequantized weights to BF16, including when scales and activations are FP16. This discards FP16 precision before the linear operation. For example, with local K = group size = 128, an FP16 scale of 0.10028076171875 produces 12.8125 instead of 12.8359375 for an all-one input.

## Modifications

Cast fallback weights to `layer.scales.dtype`. The quantized matmul fast path is unchanged.

## Accuracy Tests

Ran the original and patched loader and linear methods on an NPU with torch-npu 2.10.0.post6:

- 36 cases: K/group size 64/64 and 128/128 (fallback), 256/128 (fast-path control); FP16/BF16; bias/no bias; constant and random weights, asymmetric zeros, 2D/3D inputs.
- Before: 24 passed, 12 failed. All failures were FP16 fallback cases.
- After: 36 passed. Fallback weights and outputs match the independently unpacked, dtype-preserving dense reference exactly. Fast-path controls use rtol=0.02, atol=0.125.
- The example above now returns 12.8359375.

The harness executes the class extracted from each source file. These are operator-level checks, not a full-model accuracy evaluation.
