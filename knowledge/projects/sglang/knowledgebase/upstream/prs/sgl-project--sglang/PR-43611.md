# [Fix] mamba: Make Mamba2 prefill batch invariant in deterministic mode

[Upstream PR](https://github.com/sgl-project/sglang/pull/43611) · state: open · merged: False

## Original PR description

## Motivation

Fixes #43413 for the Triton Mamba2 prefill path.

A request can land on a different physical scan chunk depending on its neighbors. Chunked prefill and prefix-cache reuse can also resume from a state produced by a different floating-point computation. The request's chunk grid and its cached checkpoints both need to stay consistent.

## Modifications

- Give each request a canonical chunk grid within one padded scan. Carry CPU boundaries through prefill metadata to avoid a device-to-host sync in each layer.
- Align truncated prefill by its absolute end position and preserve the scheduler's request-slot admission check.
- Use canonical scan states as deterministic prefill checkpoints. Round FP16/BF16 boundary states before continuing the recurrence, so a resumed scan reads the same precision as an unsplit one.
- Keep boundary-state copies separate from the varlen matrix reduction to avoid the gfx950 compiler assertion reported in review. Return final states from the scan itself, including after zero-dt padding, instead of recomputing partial tails. A single request copies its final state directly.
- Keep decode and speculative verification from promoting recurrent states to prefill checkpoints. With `no_buffer`, donate only aligned, unfinished prefill states. Restrict this policy to models that use the Mamba2 SSD scan.
- Clear the preceding sequence's contribution to positive zero before the local dot. The signed-zero case reproduced on W7900D with the original PR.
- Cover mixed batches, split states, optional scan arguments, checkpoint extraction, scheduling and cache reuse.

NGRAM tree/stream fixes and FlashInfer dependency experiments remain separate contributions.
