# [Fix] Make Mamba2 prefill batch invariant in deterministic mode

[Upstream PR](https://github.com/sgl-project/sglang/pull/43611) · state: open · merged: False

## Original PR description

## Motivation

With Granite 4.0-H-Tiny, `--enable-deterministic-inference` still allows a greedy request to produce different outputs when it is batched with prompts of different lengths (#43413). In Mamba2 prefill, the lengths of earlier requests determine where a request lands in the packed scan's chunk grid. That changes the reduction order.

## Modifications

- Align each request to a scan chunk boundary when deterministic inference has multiple prefills. The requests still use one packed scan; padding has zero effective `dt`.
- Read final SSM states at the real sequence ends and map tracked intermediate states back to the caller's original chunk grid.
- Carry CPU sequence boundaries in the prefill metadata to avoid a device-to-host sync in every Mamba layer. The existing packed path remains in use outside this case.
- Add GPU coverage for a request run alone and after different-length neighbors, including nonzero initial states and tracked states.

Fixes #43413.

## Accuracy Tests

On an RTX 4090 with `ibm-granite/granite-4.0-h-tiny`:

- The issue's prefix test gave `1/5/2/1` unique outputs in five trials on the unmodified base. On current main (`234ccba`), this change gave `1/1/1/1` in 30 trials (120/120/117/108 samples across the four prefix groups).
- On current main, ten trials with `--return-logprob` kept generated text invariant, but two of 15 samples for the 4097-character prefix had a different first-token logprob with radix cache enabled. The same eight-request layout also differs on the unmodified base. With this patch, disabling radix cache makes the two logprobs match exactly. This change does not address that cache-dependent case.
- On the earlier base, ten trials each with `--mamba-radix-cache-strategy extra_buffer` and with radix cache disabled gave `1/1/1/1`. The no-radix run also matched token IDs and logprobs exactly.
- Mamba GPU operator tests: 22 passed, including the new batch-invariance cases and existing continuous-batch chunking cases.

## Speed Tests and Profiling

In a four-request, Granite-shaped scan microbenchmark on the same GPU, the original packed scan took 0.51 ms and the aligned scan took 1.19 ms (20 measured iterations after warmup). This extra cost applies to deterministic inference with multiple prefills; the default scan path is unchanged. I did not treat the end-to-end prefix test as a throughput benchmark because it assigns prompts randomly.
