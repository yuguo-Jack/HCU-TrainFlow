# [Feat] disaggregation: Decode host receive on the unified page-envelope host pool

[Upstream PR](https://github.com/sgl-project/sglang/pull/47124) · state: closed · merged: True

## Original PR description

## Motivation

With the unified memory pool, the FULL and SWA host pools share one backing of page envelopes that relocates pages when it compacts. Decode host receive only accepted per-layer KV host buffers, so a decode node running on this host pool rejected host receive at startup. This PR adapts decode host receive to the shared page-envelope host pool.

## Modifications

- **Registration.** `HostPoolGroup.get_contiguous_buf_infos` registers a page-envelope host pool whose peer writes are gated as one region of whole page envelopes per pool (`peer_write_buf_info`), and raises when the device side is not exactly one region with matching page bytes, or when the entry carries packed draft device pools.
- **Whole pages.** The shared backing is a whole number of pages of every pool that shares it (`math.lcm` of their page bytes): rounded down when it is sized from the host memory budget, up otherwise. Transfer backends register the backing in page-size items.
- **Peer writes block host compaction.** The decode installs a peer-write gate on its host pool (`set_peer_write_gate`). The backing refuses to compact while a transfer peer may write a page it was given: a destination is published but not yet queued, a host-staged request is on the transfer queue, or a failed transfer awaits its drain.
- **The prefill writes physical pages.** The decode sends `peer_write_indices`: physical page ids resolved after the last host allocation that could move them. Other host pools keep the base hooks, which return the ids unchanged and ignore the gate.
- **The retraction reserve stays whole.** A receive is admitted only if a complete FULL and SWA retraction backup still fits the shared backing afterwards. Both pools are priced together by the backing's packed free bytes (`can_fit_many_then`), so shared free bytes are not counted twice. Admission never compacts the backing. Other host pools keep the per-pool checks.
- **Fails loud on sidecars.** Sidecar pools indexed by a shared host pool raise at startup; a peer would otherwise write sidecar rows that restoration never reads.
- **Host-staged requests do not keep the transfer pin source busy.** `disagg_transfers_in_flight` keeps device compaction from moving pages a receive may write. A request receiving into the host pool holds no device page until `allocate_host_staged`, so it no longer counts while it waits on the transfer queue. Requests receiving into device memory still count.
- **Pinned index uploads.** The unified host pool stages restore host indices through pinned memory before the non-blocking upload; from pageable memory the upload blocked the scheduler until the transfer stream had finished its earlier copies.
- **One host-layout finish event per stream.** `L2TransferEngine` keys the host-layout finish event by stream, so a restore on a caller's stream that finishes first no longer replaces the event of an engine-stream load still reading host pages.

The unit tests' fake transfer-queue entries now carry `host_staged`, since the decode predicate reads it.
