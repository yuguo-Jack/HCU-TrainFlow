# [Fix] compressed-tensors: Load layers that match no target as unquantized

[Upstream PR](https://github.com/sgl-project/sglang/pull/46336) · state: open · merged: False

## Original PR description

## Motivation

Fixes #46335.

SGLang cannot build a model from a compressed-tensors checkpoint that leaves a layer out of both `config_groups[*].targets` and `ignore`. llm-compressor writes such checkpoints for experts-only and attention-only quantization. It sets `"ignore": []` and stores every untargeted layer unquantized. SGLang raises on the first of those layers, before it loads any weight:

```
File ".../layers/quantization/compressed_tensors/utils.py", line 144, in find_matched_target
ValueError: Unable to find matching target for model.language_model.layers.0.linear_attn.in_proj_qkvz in the compressed-tensors config.
```

The checkpoint that hit this is [`bottlecapai/ThinkingCap-Qwen3.8-Flash-Next-NVFP4`](https://huggingface.co/bottlecapai/ThinkingCap-Qwen3.8-Flash-Next-NVFP4) at `df3922b2`. It is a `qwen4_exp` model whose config targets only the routed experts, with NVFP4 weight-only quantization:

```json
"config_groups": {"group_0": {"targets": ["re:.*mlp\\.experts\\.\\d+\\.(gate_proj|up_proj|down_proj)$"], "input_activations": null, "...": "..."}},
"ignore": [],
"sparsity_config": {}
```

A missing `packed_modules_mapping` is not the cause. Qwen4-Exp already maps `in_proj_qkvz` to `in_proj_qkv` and `in_proj_z`, and the config targets neither shard. Today the checkpoint only loads with `--json-model-override-args` replacing the whole `quantization_config`, with `"ignore": ["re:^(?!.*mlp\\.experts).*$"]` added.

vLLM has loaded untargeted layers as unquantized since vllm-project/vllm#41965. Its `find_matched_target` returns `None`, and the layer falls back to `UnquantizedLinearMethod`. This PR ports that change and logs the fallback once. It also keeps one check that vLLM dropped, described under Modifications.

Related work:

- #41836 and #41876 hit the same error on GLM-5.3-Flash and fix it for that model with a name mapper. Their tests expect `UnquantizedLinearMethod` for the affected projections, which is what this PR gives untargeted layers. That checkpoint is untested with this PR.
- #45898 adds `test_granitemoe_packed_modules.py`, which expects `Unable to find matching target` when the mapping is missing. With this PR that case no longer raises (see Compatibility).
- #38224 wraps `find_matched_target` in `try/except ValueError`. The wrapper becomes unnecessary.

## Modifications

```diff
 def find_matched_target(layer_name, module, targets, fused_mapping):
     match on layer name, then module class, then fused shards
-    if nothing matched: raise ValueError("Unable to find matching target ...")
+    if nothing matched: return None
+    if a fused layer matched only some shards: raise ValueError("Found different quantization schemes ...")

 def CompressedTensorsConfig.get_scheme_dict(layer, layer_name):
+    if no target matched: warning_once(...); return None
+    # get_quant_method then takes its existing unquantized paths

 def CompressedTensorsConfig.get_linear_scheme(layer, layer_name):
-    with suppress(ValueError):
-        sparsity_scheme = sparsity_scheme_map[find_matched_target(...)]
+    matched_target = find_matched_target(...)
+    if matched_target is not None:
+        sparsity_scheme = sparsity_scheme_map[matched_target]
```

- In `compressed_tensors/utils.py`, `find_matched_target` returns `Optional[str]` and no longer raises when nothing matches. `_match_fused_layer` still returns `None` when no shard matches. When only some shards match, it now raises, because one fused weight cannot hold a quantized shard next to a bf16 one. Without that check, this PR would turn today's construction error into a silent bf16 load. `should_ignore_layer` already raises the same error for inconsistent `ignore` shards. This check is the one deliberate difference from vLLM.
- In `compressed_tensors/compressed_tensors.py`, `get_scheme_dict` returns `None` for an untargeted layer and logs one `warning_once`. The message names no layer, because `warning_once` caches on its arguments and a per-layer message would print 921 lines for this checkpoint. The sparsity lookup checks for `None` instead of catching `ValueError`. This change is required, since with `sparsity_config: {}` every linear layer would otherwise reach `sparsity_scheme_map[None]` and raise `KeyError`.
- The `get_lm_head_scheme` docstring and a comment in `test_compressed_tensors_lm_head.py` justified the code with the unmatched-layer error. That error is gone, so both now point to the unquantized path.
- Five cases join `test_compressed_tensors_mixed_precision.py`, the existing file for target and `ignore` matching:
  - `test_untargeted_linear_loads_unquantized` gives the reported `in_proj_qkvz` an `UnquantizedLinearMethod`.
  - `test_untargeted_experts_load_unquantized` covers an attention-only config, where `get_moe_scheme` returns `None` for the experts.
  - `test_untargeted_layers_are_logged` checks that the fallback logs a warning.
  - `test_partly_targeted_fused_layer_raises` covers the check on partly matched fused layers.
  - `test_fused_layer_matches_when_every_shard_matches` guards the all-shards path of the rewritten `_match_fused_layer`. No other compressed-tensors unit test reaches it.

### Compatibility

- A layer that matched a target before resolves exactly as before. Only the no-match branch changed.
- Checkpoints that raised `Unable to find matching target` now load, with the untargeted layers unquantized.
- A layer that is quantized in the checkpoint but whose SGLang name matches no target, as with the missing mapping in #45898, no longer fails at construction. It gets unquantized parameters that do not match the stored tensors, and the outcome depends on the model's `load_weights`. The warning is the signal. A fused layer with only some shards targeted still raises.
- A fused layer whose shards only partly match a `sparsity_config` target now raises. The old sparsity lookup swallowed that error.
- Reverting this PR restores the old error. Nothing is persisted.

The serving smoke test ran on one NVIDIA GB10 (sm121, aarch64, 128 GB unified memory).
