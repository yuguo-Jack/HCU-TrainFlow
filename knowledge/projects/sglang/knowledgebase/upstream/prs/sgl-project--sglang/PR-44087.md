# [Bug] Fix bench_serving request-rate timing drift (#43930)

[Upstream PR](https://github.com/sgl-project/sglang/pull/44087) · state: closed · merged: False

## Original PR description

## Summary

Fixes the scheduling drift in `bench_serving`'s open-loop request generator when `--request-rate` is used.

## Root Cause

In `python/sglang/benchmark/serving.py`, the `get_request()` function's non-trace-timestamps branch used a **relative sleep** for each gap:

```python
interval = np.random.exponential(1.0 / request_rate)
await asyncio.sleep(interval)
```

Because `asyncio.sleep()` almost always wakes a little late (e.g. CPython's `EpollSelector` rounds every timeout up to a whole millisecond, plus event-loop overhead), and because each new gap started from the moment the previous sleep returned, the lateness was never recovered. After k requests the sends were about k * delta behind schedule, causing the achieved rate to fall below `--request-rate` R by roughly R / (1 + R*delta).

## Fix

Switch the non-trace scheduling branch to **absolute target arrival times** — the same strategy already used by the trace-timestamps branch in this same function. Each drawn exponential interval is accumulated from a single reference start timestamp (`time.perf_counter()`), so wake-up jitter is bounded to a single gap and does **not** compound across requests.

```python
start = time.perf_counter()
next_arrival = 0.0
for request in input_requests:
    delay = start + next_arrival - time.perf_counter()
    if delay > 0:
        await asyncio.sleep(delay)
    yield request
    if request_rate != float("inf"):
        next_arrival += np.random.exponential(1.0 / request_rate)
```

The random gaps are still drawn in the same order from the same distribution, so with a fixed `--seed` the drawn schedule is identical to before. With `--request-rate inf`, behavior is unchanged. The fix also removes the extraneous gap that the old code slept after the final request.

## Verification

Running the reproduction script from issue #43930 at 100 req/s across 1000 requests:

| Metric | Before fix | After fix |
|---|---|---|
| Lag at request 999 | ~700 ms | ~0.7 ms (bounded) |
| Achieved rate | 93.2 req/s (-6.5%) | 99.7 req/s (-0.0%) |
