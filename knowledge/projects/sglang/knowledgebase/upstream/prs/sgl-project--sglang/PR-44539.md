# [Fix] [AMD] docker: Restore the AITER sparse MLA spill patch on the 2bb549102 pin

[Upstream PR](https://github.com/sgl-project/sglang/pull/44539) · state: closed · merged: False

## Original PR description

## What

Restore the ROCm/aiter#6042 patch that #44534 removed. The patch is now applied from its squash-merge commit `57e2c6b42` on AITER main instead of the PR-branch commit `042a28918`.

## Why

#44534 dropped the cherry-pick because it assumed the `2bb549102` pin already contains ROCm/aiter#6042. It doesn't: the pin is from Oct 10 and ROCm/aiter#6042 merged on Oct 13. The old cherry-pick conflicted because ROCm/aiter#6159 rewrote `pa_decode_sparse.py` between the previous pin and this one. `042a28918` was written before that rewrite, while the squash-merge commit was made after it.

Without the patch, the gfx950 sparse MLA decode on 64-bit gathers uses the peeled kernel, which spills about 110 VGPRs below Triton 3.8. That affects the ROCm 7.2 / 7.2.4 images (Triton 3.7.0). The ROCm 10 images run Triton 3.8.0, so the patch doesn't change their behavior.

ROCm/aiter#5967 and ROCm/aiter#6007 are in the pin, so their patches stay removed.

## Test plan

- Checked out `2bb549102` in a local AITER clone and ran `git cherry-pick --no-commit 57e2c6b42`. It applies cleanly, and the result matches `pa_decode_sparse.py` at `57e2c6b42` exactly.
- `release-docker-amd-rocm720-nightly.yml` built from this change, all four flavors (gfx942/gfx950 x rocm720/rocm724): https://github.com/sgl-project/sglang/actions/runs/38803779443. The cherry-pick applied in all four builds and the images built.
