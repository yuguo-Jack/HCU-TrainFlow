# [Fix] moe: Match padded-row indices to token-count dtype

[Upstream PR](https://github.com/sgl-project/sglang/pull/48109) · state: closed · merged: True

## Original PR description

## Motivation

MoE padded-row masking constructs row indices with `torch.arange`. Without an
explicit dtype, these indices default to `int64`, while
`num_token_non_padded` may use another integer dtype such as `int32`.

Mixed-dtype tensor comparisons are not supported uniformly across execution
backends and may select an unnecessary fallback path. Constructing row indices
with the token-count tensor's dtype keeps the comparison backend-neutral while
preserving the existing masking semantics.

## Modifications

- Construct padded-row indices with `num_token_non_padded.dtype` throughout
  `python/sglang/srt/layers/moe/topk.py`.
- Preserve the existing ID masking, weight zeroing, fill values, and no-padding
  behavior.
- Add focused regression coverage for `int32` and `int64` token counts.
- Verify the actual comparison operand dtypes while still executing and
  validating the real masking operations.
- Extend non-contiguous eager-fallback coverage for both top-k IDs and weights.
