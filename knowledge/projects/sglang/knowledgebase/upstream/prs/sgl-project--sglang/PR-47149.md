# [Perf] dsv4: Fix amax8_varlen and mega MoE pre-dispatch grids for 1024-thread SMs

[Upstream PR](https://github.com/sgl-project/sglang/pull/47149) · state: closed · merged: True

## Original PR description

## Motivation

Two DeepSeek-V4.1 decode kernels lose time to grid shape on GPUs whose SMs hold 1024 resident threads (CC 10.7 / sm_107), not to memory bandwidth:

- `amax8_varlen` (two-level indexer block keys) sizes `grid.y` from the logits buffer width (`max_compressed_seq_len`), but rows only hold `compressed_seq_lens` keys. At 128K context about 85% of the 512-thread CTAs exit after reading `seq_len`; at 2 CTAs/SM that is dozens of waves of empty CTAs.
- `mega_moe_pre_dispatch` launches 640-thread CTAs for hidden 5120. Two do not fit a 1024-thread SM, so the quant CTAs plus the pad CTAs run in two waves.

## Modifications

- `block_amax.cuh`: cap `grid.y` at two waves of resident CTAs (occupancy API, cached per device) and grid-stride over key chunks.
- `mega_moe_pre_dispatch.cuh`: when two one-chunk-per-thread CTAs do not fit an SM (`cudaDevAttrMaxThreadsPerMultiProcessor`), launch half the threads with two 16B chunks each (both loads issued before the quant-group reductions) and two pad slots per thread. On 2048-thread SMs the launch is unchanged.
- Both per-device host queries are cached with `init_once`. The two-chunk launch is used only when `top_k <= num_chunks / 2`, so no previously valid `top_k` is rejected.

Both kernels produce bitwise-identical outputs (all outputs compared, including pad slots and the scale swizzle).

## Accuracy Tests

On sm_107 (CC 10.7), at this PR's head (merged with main, including #46090):

- `test/registered/kernels/ops/moe/test_mega_moe_pre_dispatch.py`: 6 passed. The new `test_hidden_5120_two_chunk_matches_one_chunk` quantizes the same rows with `top_k=6` (two chunks per thread on 1024-thread SMs) and `top_k=384` (one-chunk fallback) and requires identical FP8 bytes and scales, plus correct top-k copies and padding.
- Both kernels are bitwise identical to main's versions at the decode shapes below (all outputs, including pad slots).

Not yet run: an end-to-end GSM8K run. CI hardware (2048-thread SMs) takes only the one-chunk path.
