## Motivation
On gfx950, the V4.1 low-ratio indexer has a fused index-Q kernel (RoPE + fp4 quantize + FlyDSL pack) only for ≤ 64 tokens. Prefill and large decode-verify batches fall back to two kernels that write the query to memory as bf16 and read it back. For a 16k-token prefill chunk this takes ~1.4 ms per indexer layer (~2% of prefill time at 68k input).

<!-- Describe the purpose and goals of this pull request. -->

## Modifications
- Add `index_q_rope_pack_flydsl`: a dedicated Triton kernel (one program per token and 16 heads) that does the RoPE, the fake-quant and the FlyDSL fp4 pack in one launch for any number of tokens. Its output is bitwise identical to the two standalone kernels it replaces.
- Use it in `_indexer_inputs` for > 64 tokens. The ≤ 64-token decode path is unchanged.
- Tests: bitwise match against the standalone kernels (up to 16k tokens, 16/32/64 heads, inf/nan inputs), non-contiguous positions, and inputs around both quantization floors.
