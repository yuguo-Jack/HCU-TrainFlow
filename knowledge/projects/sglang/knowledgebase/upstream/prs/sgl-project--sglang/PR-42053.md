# [Fix] function_call: Flush buffered text at stream end in Llama-3.2 and dots detectors

[Upstream PR](https://github.com/sgl-project/sglang/pull/42053) · state: open · merged: False

## Original PR description

## Motivation

Same loss pattern as #41909 / #41914 / #41962 / #41963 / #42007:
`Llama32Detector` and `DotsToolDetector` hold text back in `self._buffer`
while waiting for the closing marker, and `BaseFormatDetector.finish()`
returns an empty result by default. When the stream ends with an incomplete
tool call still buffered, the held-back text is silently dropped:

- `Llama32Detector`: the whole python block (including preceding normal
  text) is kept in `_buffer` until the call can be resolved; at end of
  stream it is lost.
- `DotsToolDetector`: a partial `<dots_function_call>` invoke block is
  lost at end of stream.

## Changes

Add a `finish()` override to each detector that flushes `_buffer` as normal
text:

- `Llama32Detector`: flush the buffered python block.
- `DotsToolDetector`: flush the buffered partial invoke block; a pure
  trailing closing tag (`</dots_function_call>`) is syntax residue and is
  not re-emitted.

Normal streams are unaffected: `finish()` stays a no-op when `_buffer` is
empty.

## Tests

Offline unit tests (no server, no model loading) for each detector cover:
- partial tool call at stream end: `finish()` releases the buffered text;
- clean stream: `finish()` returns an empty result;
- complete-call behavior: the buffered block is flushed rather than dropped.

All pass locally (`pytest test/registered/unit/function_call/test_{llama32,dots}_detector_finish.py`), ruff clean (ignoring pre-existing E722 warnings in `llama32_detector.py`).
