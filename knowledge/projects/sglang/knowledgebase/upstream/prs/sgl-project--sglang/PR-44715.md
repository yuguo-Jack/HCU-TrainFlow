# [Fix] bailing: MoE gate dtype follows config.router_dtype

[Upstream PR](https://github.com/sgl-project/sglang/pull/44715) · state: closed · merged: True

## Original PR description

## Motivation

`BailingMoeV3` forces the MoE gate GEMM to bf16, overriding `router_dtype="fp32"` from Ling checkpoints. The bf16 gate perturbs top-k routing enough to cause output variance (reported by the Ling team on Ling-3.x checkpoints; the fp32 gate is what the checkpoint was trained/tuned against).

## Modifications

Gate dtype follows the checkpoint config: `router_dtype == "fp32"` (or absent) → fp32 gate; any other value → bf16. No behavior change for configs that don't set `router_dtype="fp32"`.

## Accuracy Tests

Routing-affecting change: greedy outputs shift back to the fp32-gate reference. Ling team validated on their internal branch and the ling-v3-open branch.

## Speed Tests and Profiling

On Hopper the fp32 gate GEMM does not use tensor cores, so decode gives back part of the bf16-gate speedup; correctness takes priority.
