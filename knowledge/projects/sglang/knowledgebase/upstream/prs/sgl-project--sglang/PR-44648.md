# [AMD] [Perf] Route tuned unquantized diffusion linears to aiter gluon GEMM on gfx1250

[Upstream PR](https://github.com/sgl-project/sglang/pull/44648) · state: closed · merged: False

## Original PR description

## Motivation

**What goes wrong**
Diffusion DiT linears go through `F.linear`, which on gfx1250 lands on hipBLASLt (~56 TFLOPS on the Wan2.2 shapes) or inductor's Triton matmul template under torch.compile (~620-690 TFLOPS). aiter's gfx1250 gluon `gemm_a16w16` reaches 777-892 TFLOPS on the same shapes once tuned, but nothing in multimodal_gen calls it.

**Where it shows up**
Only gfx1250 with `SGLANG_USE_AITER=1`. It shows up on every Wan2.2 A14B block: the q/k/v/o and cross-attn q/o projections (M=90000, N=K=5120), the FFN up (N=13824) and down (K=13824) projections are 25% of denoise time. gfx942/gfx950 and CUDA are untouched.

**How to fix**
On gfx1250, send an unquantized half-precision linear to aiter gluon `gemm_a16w16` only when aiter reports a tuned config for its (N, K); everything else keeps `F.linear`, because aiter's untuned default is ~3x slower than inductor at large M.

Depends on the aiter PR adding the tuned gfx1250 GEMM-A16W16 configs for N=5120/K=5120, N=13824/K=5120, N=5120/K=13824 (branch https://github.com/yichiche/aiter/tree/gfx1250-a16w16-wan-configs, PR to ROCm/aiter pending). Without it the gate finds no tuned shape and this change is a no-op.

## Modifications

- `runtime/platforms/aiter.py`: add `USE_AITER_GFX1250`.
- `runtime/layers/linear.py`: in `apply_unquantized_linear`, route to aiter `gemm_a16w16` (bias fused in the epilogue) when on gfx1250, dtypes are bf16/fp16 and match, and `get_gemm_config("GEMM-A16W16", ...)` reports a tuned (N, K). The tuned check is cached per (N, K) and marked `torch.compiler.assume_constant_result`, so it folds to a constant under torch.compile (verified with `fullgraph=True`); the aiter op is already a registered custom op and stays opaque to inductor.

## Accuracy Tests

Kernel: max relative error vs an fp32 reference is 0.27% for M=18000, N=13824, K=5120, identical in eager and compiled mode. Every tuned config was checked against fp32 before timing.

End to end (same seed): output video is visually equivalent to the baseline (same scene, composition and quality). PSNR vs baseline is 18.5 dB, which is the normal trajectory drift of an 8-step sampler under GEMM rounding changes; no artifacts.

## Benchmarking and Profiling

Setup: Wan2.2-T2V-A14B-Diffusers, MI450 (gfx1250, one NPS2 partition, 96 CU), 1 GPU, 1280x720, 193 frames (90000 tokens), 8 steps, seed 42, `--attention-backend aiter --enable-torch-compile true --regional-compile`, `SGLANG_TORCH_COMPILE_MODE=max-autotune-no-cudagraphs`. Timing is the "Warmed-up request processed in" line, each config run solo on the same partition with the sibling partition idle.

| Config | Warmed-up e2e (s) | vs baseline |
|---|---|---|
| Baseline (`F.linear` / inductor) | 201.86 | - |
| This PR | 189.06 | -6.3% |

Per-GEMM microbenchmark, M=90000, solo (inductor = `torch.compile(F.linear, mode="max-autotune-no-cudagraphs")`):

| Shape (N x K) | Calls/block | inductor (us) | aiter gluon tuned (us) | Speedup |
|---|---|---|---|---|
| 5120 x 5120 | 6 | 7232 | 5359 | 1.35x |
| 13824 x 5120 (FFN up) | 1 | 20167 | 14285 | 1.41x |
| 5120 x 13824 (FFN down) | 1 | 18521 | 15948 | 1.16x |

Per-block GEMM time from paired torch-profiler traces (trace_module_analyzer, sibling partition loaded in both runs): 137.9 ms -> 105.0 ms (-24%), including the tanh-GELU that is no longer fused into inductor's matmul epilogue (~0.65 ms solo, follow-up: use gluon's `activation="gelu_tanh"`).
