## Motivation

Use FlashInfer's optimized Hopper implementation for DOTS3 sliding-window MLA
decode, now merged in [flashinfer#6823](https://github.com/flashinfer-ai/flashinfer/pull/6823).
This replaces the existing composite fallback for supported inputs without
vendoring a kernel, adding a serving option, or changing other attention backends.

## Modifications

- Add a small adapter around the public FlashInfer
  `batch_decode_with_kv_cache_mla_swa` API and its workspace-size helper.
  Prepare reusable workspace and warm the module before CUDA Graph capture.
- Select the native path inside the existing DOTS SWA backend using actual
  **local SWA heads**, rather than full-attention heads. The qualified domain is:

  | Property | Native path |
  | --- | --- |
  | Hardware | SM90; at least 223,584 bytes of opt-in shared memory |
  | Data type | BF16 queries and KV cache |
  | Local batch | 1, 2, 4, 8, or 16 |
  | Query length | 1 or 4; bounded decode, not general prefill |
  | Local query / KV heads | 64 / 1 |
  | QK / value dimension | 1088 / 1024 |
  | KV cache | Contiguous Page64 latent cache; no repacking |
  | Window | 513 tokens: current position plus up to 512 preceding keys |
  | Attention context parallelism | 1 |

- Keep the existing fallback for unsupported devices, shapes or layouts, and
  older FlashInfer installations without the optional API. For example,
  attention-TP8 with local SWA Hq=8 stays on fallback. Prefill, draft-model
  routing and other decode backends are unchanged.
- Include this adapter in the existing startup FlashInfer autotune context,
  including discovery through DOTS and two-batch-overlap backend wrappers.
- Do not suppress compilation, loader/ABI or CUDA execution errors. An explicit
  missing-AOT condition with JIT disabled may retain fallback.
- Add one CPU/H100-registered test file covering native execution, Graph replay,
  autotune, selection guards, optional-API fallback and error propagation.

No dependency pin change is included. Native execution requires a FlashInfer
build containing #6823; an older installation continues to work through fallback.
No additional environment variable or decode-backend argument is required.

## Accuracy Tests

Validated the submitted SGLang head `0dcac687` (based on main `52a6f704`)
against FlashInfer main `f810e74b`, which includes #6823. Environment:
NVIDIA H100 80GB HBM3 / 132 SMs, PyTorch 2.14.1+cu130, CUDA 13.0.

| Test | Result |
| --- | --- |
| Fresh FlashInfer SM90 MLA/SWA JIT build and source-path verification | Passed |
| FlashInfer kernel and trace tests | 183 passed, no skips |
| SGLang adapter and existing DOTS backend tests | 21 passed, no skips |
| Direct invocation of the registered adapter test file | 15 passed |
| Existing upstream FlashInfer-autotune synchronization suite | 12 tests and 7 subtests passed |
| CPU-only adapter and DOTS tests | 18 passed, 3 expected GPU-only skips |
| Native adapter versus SGLang fallback, all 10 supported batch/query-length combinations | Passed |

Adapter coverage includes actual native execution, saved autotune-cache entries,
bitwise eager/Graph-replay agreement, unsupported-shape and missing-API fallback,
missing-AOT handling, and propagation of non-recoverable execution errors.

The 10-shape comparison explicitly requires native selection for local batch
1/2/4/8/16 and query length 1/4, with Hq=64, KV length=1055, Page64 and W513.
Relative L2 against the actual SGLang fallback is 0.00771–0.00874, below the
0.03 smoke-test threshold. This comparison is not a bitwise-identity claim:
the two implementations have different arithmetic paths. FlashInfer's kernel
tests independently check numerical references and masked NaN/Inf KV cases.

Reproduction, with the required dependencies and a FlashInfer build containing #6823:

  test/registered/unit/layers/attention/test_flashinfer_mla_swa.py \

These are operator/backend integration results, not model-quality qualification.
The earlier FlashInfer-path dummy-weight full-model eager test passed, but it
predates this rebase. Full-model CUDA Graph and real-weight qualification through

## Speed Tests and Profiling

Complete attention-operation latency, **including any separate split combine**.
NVIDIA H100 80GB HBM3 / 132 SMs, PyTorch 2.14.1+cu130, CUDA 13.0;
BF16, local Hq=64, QK/V dimensions=1088/1024, KV length=4127 (Page64 offset31),
W513, scale=0.0625. Warm-cache CUDA Graph timing: 12 interleaved rounds,
300 replays per round; median latency in microseconds.

The baseline is SGLang's existing
`forward_dense_kvlora_swa_torch_fallback` (Torch BMM/softmax plus Triton
gather/masking), not another FlashInfer kernel. Global batch is the
attention-DP8 deployment mapping; each operator call uses the listed local batch.

| Query length | Global / local batch | Fallback (µs) | FlashInfer (µs) | Speedup |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 8 / 1 | 19.278 | 11.548 | 1.669× |
| 1 | 16 / 2 | 20.105 | 14.410 | 1.395× |
| 1 | 32 / 4 | 23.147 | 17.233 | 1.343× |
| 1 | 64 / 8 | 25.923 | 24.959 | 1.039× |
| 1 | 128 / 16 | 38.873 | 26.982 | 1.441× |
| 4 | 8 / 1 | 21.228 | 16.923 | 1.254× |
| 4 | 16 / 2 | 22.762 | 24.394 | 0.933× |
| 4 | 32 / 4 | 27.060 | 25.506 | 1.061× |
| 4 | 64 / 8 | 36.891 | 33.380 | 1.105× |
| 4 | 128 / 16 | 62.907 | 51.569 | 1.220× |

Nine of ten shapes improve; local batch2/query length4 is about 7.2% slower.
The supported-shape guard is a correctness/support guard, not a guarantee of
winning against fallback in every shape.

These measurements were collected on 2026-10-21 using FlashInfer `139aec4d`
and the pre-rebase companion SGLang integration. They include the masked-KV
repair and required P async-proxy fences. The merged FlashInfer API, binding
and kernel sources used in the latest validation are byte-identical to that
measured version; SGLang's runtime integration patches survived rebase unchanged.
The latest SGLang rebase was revalidated for correctness, but this performance
table was **not rerun on that exact rebase**. These are operator measurements,
not full-model throughput or end-to-end speedups.
