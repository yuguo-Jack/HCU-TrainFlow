# [Fix] engram: Clamp multimodal pad ids in host-built history rows

[Upstream PR](https://github.com/sgl-project/sglang/pull/45038) · state: closed · merged: True

## Original PR description

Fixes #45010.

- #43043 widened multimodal pad ids to 62 bits, but the scheduler still packs the n - 1 tokens before each extend into the int32 engram history. A request whose prefix ends in image tokens raised `value cannot be converted to type int32 without overflow` on every scheduler rank (DeepSeek-V4.1-Flash, MMMU-Pro)
- Add `EngramHasher.history_row`, which left-pads a row and clamps ids at or above `MM_PAD_SHIFT_VALUE` to that value; the extend and PD-prebuilt branches of `NgramEmbeddingManager._prepare_engram_history` and the encoder-SWA replay builder use it
- Add a CPU test for both branches: wide pad ids fit the history and hash the same as the image token

No change to hash ids: the engram hash already reads every id at or above `MM_PAD_SHIFT_VALUE` as the image token (`engram_hash.py`), and text token ids stay below it.
