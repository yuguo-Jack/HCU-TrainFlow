# [Fix] nixl: Stop an aborted room from parking the transfer worker forever

[Upstream PR](https://github.com/sgl-project/sglang/pull/44677) · state: open · merged: False

## Original PR description

## Motivation

Fixes #44369.

In PD disaggregation with the NIXL backend, a decode-side abort marks the room `KVPoll.Failed` and registers a deferred ACK target, but does not cancel the submitted NIXL handles nor interrupt a prefill transfer worker already inside `_await_handles()`. The wait is bounded only after an `ERR` is observed: while every handle reads healthy-but-non-terminal (`PROC`), the deadline stays `None` and the worker polls forever.

Each aborted room therefore leaves one transfer worker parked, `_staging_outstanding[room] == 1`, and the deferred abort ACK unsent. Since `SGLANG_DISAGGREGATION_QUEUE_SIZE` defaults to `4`, four aborted rooms with never-settling handles can exhaust the default prefill transfer worker pool.

## Modifications

- `python/sglang/srt/disaggregation/nixl/conn.py`: `_await_handles()` now takes an optional `room` argument. While polling, if the room is already `KVPoll.Failed` and no handle has errored yet, the batch is treated as broken so the existing `NIXL_ERR_SETTLE_TIMEOUT_S` deadline bounds the wait. Both call sites in `transfer_worker()` pass `room=room`.
- The worker then exits through the existing failure path, which poisons the deferred ACK (`_deferred_ack_poisoned_rooms`) instead of sending it. This is safe: a handle that never settled does not prove the write into the decode's KV pages is over, so decode must not be told those pages are free.

- Sworol · comment · 2026-10-16T06:39:33Z · [source](https://github.com/sgl-project/sglang/pull/44677#issuecomment-6209687208)

This PR addresses the same issue as #44570, with one deliberate semantic
difference in the abort path.

Both fixes make the worker's wait room-aware so an abort cannot park a
transfer worker on a handle that never settles. The divergence is what
happens to the deferred abort ACK:

- **#44570** ends the wait immediately on room abort and fires the ACK
  (`_maybe_ack_drained_abort`) right away, while the submitted handles may
  still read `PROC`.
- **This PR** keeps the wait bounded — it arms `NIXL_ERR_SETTLE_TIMEOUT_S`
  when the room is found `Failed` while polling — and lets the worker exit
  through the existing failure path, which poisons the deferred ACK instead
  of sending it.

The ACK is the prefill rank's proof that it will no longer write into the
decode's KV pages: decode-side `is_abort_release_safe` gates the page
release on receiving ACKs from every prefill rank that could still write.
A handle still reading `PROC` does not prove the write has stopped. Sending
the ACK before every handle settles can therefore make the decode release
and reuse pages that the in-flight transfer may still touch. This PR keeps
the "ACK only after every handle settles" contract, leaves the room poisoned
so no stale ACK fires later, and lets the decode-side release timeout (30s)
be the backstop for the never-settling case — while still freeing the worker
so it returns to its queue.

Both approaches unblock the worker; this one additionally preserves the
deferred-release safety invariant.
