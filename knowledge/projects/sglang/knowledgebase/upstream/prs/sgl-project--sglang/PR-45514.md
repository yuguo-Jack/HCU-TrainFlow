Motivation

The current bundle matching implementation repeatedly filters the baseline and target DataFrames for each unique target key, introducing significant overhead as the number of tensor files and unique keys grows.

This PR optimizes bundle matching to reduce repeated DataFrame filtering while preserving matching semantics and target bundle ordering.

## Modifications

- Replace repeated `filter_rows` calls with dictionary-based grouping and lookup.
- Group tensor file metadata by identity keys in a single pass over each DataFrame.
- Preserve target bundle ordering based on the first appearance of each key.
- Handle cases where the baseline is missing target key columns by matching on the shared subset of key columns.
- Preserve the behavior of returning empty baseline bundles for unmatched target keys and excluding baseline-only keys.
- Add regression tests for missing baseline key columns, empty baseline inputs, and target bundle ordering.

## Accuracy Tests

Not applicable to model accuracy. This change only modifies comparator bundle matching logic and does not modify model computation or model outputs.

Comparator correctness was validated through unit tests and comparisons between the old and new implementations.

- Bundle matcher unit tests: 16 passed.
- Verified matching behavior, unmatched bundles, and target bundle ordering.
- Compared old and new comparator outputs on synthetic inputs and a real inference tensor dump.

## Speed Tests and Profiling

This PR targets comparator performance by replacing repeated DataFrame filtering with dictionary-based grouping and lookup.

### Real-world GLM5 inference tensor dump

Evaluated on a self-collected SGLang GLM5 inference dump containing per-module input and output tensors from a single prefill step.

- Approximately 190,672 `.pt` file pairs.
- Approximately 1.4 GB of tensor dump data per side.
- End-to-end comparator runtime decreased from **1,414 s to 567 s**, approximately **2.49× faster**.
- The previous implementation spent approximately **865 s** in bundle matching.

These results demonstrate the end-to-end performance improvement on a real tensor-comparison workload. The standalone bundle-matching runtime of the new implementation was not separately reported for this real workload.

### Synthetic microbenchmark

The old and new bundle matching implementations were benchmarked on synthetic metadata tables.

| Rows per side | Old implementation | New implementation | Speedup |
|---:|---:|---:|---:|
| 1,000 | 0.506 s | 0.0051 s | 99.8× |
| 5,000 | 2.693 s | 0.0255 s | 105.6× |
| 20,000 | 13.907 s | 0.1082 s | 128.6× |

For a synthetic workload with 1,323,567 rows per side, the new implementation completed bundle matching in 10.46 s. The old implementation was not benchmarked at this scale.

Synthetic microbenchmark results measure bundle matching in isolation and should not be interpreted as end-to-end inference speedups.
