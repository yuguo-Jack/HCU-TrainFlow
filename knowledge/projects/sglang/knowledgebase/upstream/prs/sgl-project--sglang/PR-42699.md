## Motivation

Bring the MI45x (gfx1250) image onto ROCm 10.1. It is published alongside the existing ROCm 10.0 images rather than replacing them, so nothing consuming the current `rocm10-*` tags changes.

## Modifications

**torch 2.11 → 2.12.** ROCm 10.1 publishes no torch 2.11 wheel, so the bump comes with the SDK. torchvision moves 0.26 → 0.27 and torchaudio stays on 2.11.
`srt_hip_rocm101` carries the 2.12 pin, mirroring `srt_hip_rocm724`.
**Triton comes from the SDK.** This flavor sets `BUILD_TRITON=0` and keeps `3.8.0+git669b31ac` as shipped with ROCm 10.1, instead of the source build the 10.0 flavor uses.

Triggered a test build of the ROCm 10.1 gfx1250 image from this branch:

**Run:** https://github.com/sgl-project/sglang/actions/runs/38671327370 (`job_select=publish-gfx1250-rocm101`)

Expected output, to `rocm/sgl-dev` only:

```
rocm/sgl-dev:v0.5.21-rocm101-mi45x-20261015-test
```

The `-test` suffix and the dropped `lmsysorg/sglang-rocm` mirror are both marked `TEMPORARY` in the workflow and will be removed once the image checks out.

The other two jobs were skipped, so the released ROCm 10.0 tags are untouched. For reference, what this workflow publishes once the temporary bits are gone:

| Job | GPU_ARCH | Tag |
|---|---|---|
| `publish` | `gfx942-rocm1000` | `v<version>-rocm10-mi30x-<date>` |
| `publish` | `gfx950-rocm1000` | `v<version>-rocm10-mi35x-<date>` |
| `publish-gfx1250` | `gfx1250-rocm1000` | `v<version>-rocm10-mi45x-<date>` |
| `publish-gfx1250-rocm101` | `gfx1250-rocm1010` | `v<version>-rocm101-mi45x-<date>` |

ROCm 10.0 and 10.1 are published side by side rather than one replacing the other. The 10.1 image is a separate `gfx1250-rocm1010` Dockerfile stage because `BUILD_TRITON` is an `ENV`, not an `ARG`, and the two flavors need different values: 10.0 builds Triton from source, 10.1 keeps the one the SDK ships.
