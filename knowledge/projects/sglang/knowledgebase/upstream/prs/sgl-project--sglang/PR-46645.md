# [Fix] grammar: mask every scheduler stop token until the grammar can end

[Upstream PR](https://github.com/sgl-project/sglang/pull/46645) · state: open · merged: False

## Original PR description

## Motivation

The xgrammar backend only received the model config's EOS ids, but the scheduler also finishes on `tokenizer.eos_token_id` and `additional_stop_token_ids`. The grammar treats a stop token it doesn't know about as plain text, so a constrained request could end on that token in the middle of the grammar. For example, Kimi-K3 with `tool_choice=required` ended on `[EOS]` right after its text reply, with no tool call.

## Modifications

`create_grammar_backend` merges every token the scheduler stops on (config EOS ids, `tokenizer.eos_token_id`, `additional_stop_token_ids`) once and passes that set to every grammar backend: xgrammar, llguidance, outlines and registered custom backends.

## Accuracy Tests

`test_grammar_stop_token_ids_include_every_scheduler_stop_token` and `test_custom_backend_receives_tokenizer_stop_tokens` fail on `main` and pass with this PR. The other tests in `test_base_grammar_backend.py` give the same results on `main` and with this PR.
