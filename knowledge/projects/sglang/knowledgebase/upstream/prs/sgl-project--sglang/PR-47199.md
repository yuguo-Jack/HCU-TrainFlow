# [Fix] [AMD] DSv4.1: Use 64-bit row offsets in the candidate-block kernels

[Upstream PR](https://github.com/sgl-project/sglang/pull/47199) · state: open · merged: False

## Original PR description

## Motivation

DeepSeek-V4.1-Flash PD decode with DSpark on MI355X crashes while capturing the bs=384 decode CUDA graph (2304 verify rows per DP rank):

```
Memory Fault Error [..., kernel: _candidate_block_scores_kernel]
Exception: Capture cuda graph failed: CUDA error: an illegal memory access was encountered
```

`_candidate_block_scores_kernel` and `_gather_candidate_blocks_kernel` compute `row * logits_stride` in int32. On a 1M-context server the decode logits are `[rows, 1052672]` fp32, so the offset overflows 2^31 from row 2041: every DSpark decode graph from bs=341, and eager verify steps with very long requests.

## Modifications

Use a 64-bit row offset, `row.to(tl.int64) * logits_stride`, in both kernels.

## Accuracy Tests

Only the address computation changes, so outputs are unchanged wherever the old code did not fault. An offline gfx950 compile shows the offset is now a 64-bit multiply (`s_mul_hi_i32` + `s_mul_i32`) instead of a wrapped i32 product. MI355X validation of both kernels against torch on a `[2304, 1052672]` logits tensor is pending.
