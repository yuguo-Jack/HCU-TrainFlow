# [Feat] spec: Support CUDA attention DP for DFlash and DFlash2

[Upstream PR](https://github.com/sgl-project/sglang/pull/46330) · state: closed · merged: True

## Original PR description

This PR is part of a merged stack (oldest at bottom):

* __->__ #46330 (merged)
* #46290 (merged)

## Motivation

CUDA currently rejects DFLASH with attention DP. Enable plain DFlash and selector-based DFlash2 using the draft placement resolved by #46290, including unequal local batches and idle DP replicas.

## Modifications

- Admit CUDA attention DP with explicit `--enable-dp-lm-head`, CP=1 and PP=1. Reject Domino/LiLiCorr heads and the unimplemented experimental heterogeneous prefill/verify coordination mode.
- Reconstruct the embedding actually used by the draft on that embedding's own TP group before serving. Preserve padded/added vocabulary ordering, embedding quantization methods and output dtype.
- Defer DFLASH DP target-verify attention planning and graph-buffer loading to the runner, after final batch preparation and graph eligibility decisions. Stop marking deferred metadata ready through the deprecated `skip_attn_backend_init` argument.
- Initialize empty mRoPE positions for idle batches so DP padding can materialize valid target-verify rows.
- Read target DP state before entering the narrowed draft scope. Keep the draft eager under DP, retain eligible target CUDA graphs, and warm selector kernels during startup.
- Add focused unit tests, two registered four-GPU nightly E2E cases, and launch documentation.

The skip-argument changes are confined to DFLASH callers; EAGLE/NextN metadata decisions and the shared runner are unchanged. Empty idle mRoPE initialization is a shared `ForwardBatch` change and also applies to other algorithms using mRoPE models. Non-DP/DSpark preplanning defaults and NPU-specific behavior are preserved.
