# [Doc] cookbook: Install MiniMax-M3.1-Flash from main and move GB / Hopper to nightly images

[Upstream PR](https://github.com/sgl-project/sglang/pull/48000) · state: open · merged: False

## Original PR description

## Motivation

MiniMax-M3.1-Flash NVIDIA support is in `main` ([#45925](https://github.com/sgl-project/sglang/pull/45925) and follow-ups), so the cookbook no longer needs the "install from the support PR (TBD)" step or the one-off `dev-minimax-m31-flash` image everywhere.

The latest release, v0.5.23, includes #45925. It does not include later fixes the recipes rely on, such as DSpark on Hopper (#46868), the DSpark draft KV TP placement fix (#46851) and the MSA plugin behind `--enable-nvidia-megakernel` (#46625). It also has no CUDA 13.4 image. So the page points at nightlies, not `latest`.

## Modifications

**Python install**
- Install SGLang from `main` instead of a PR checkout.
- Pin MSA to `1e7bf76f26a5f53cfc2d4d297e1ec2e40955e431`, the commit `docker/Dockerfile.cu134` pins.
- Run `git submodule update --init --recursive`, because MSA prefill compiles against its CUTLASS submodule.
- Install `integrations/sglang`, the MSA MonoKernel plugin that the Low-Latency recipe's `--monokernel-backend msa` loads. The previous pin `c8e1013` has no `integrations/` directory.
- Say that AMD support is not in `main` yet.

**Docker images** (`dockerImages` and the Docker tab)

| Hardware | Image | Why |
| --- | --- | --- |
| GB300, GB200 | `lmsysorg/sglang:nightly-cu134` | CUDA 13.4 nightly. It ships MSA and its plugin and is published for arm64 only. |
| H200 | `lmsysorg/sglang:dev` | cu130 nightly. Hopper does not use MSA or need CUDA 13.4. |
| B300, B200 | `lmsysorg/sglang:dev-minimax-m31-flash` (unchanged) | No x86_64 CUDA 13.4 nightly exists yet; #47999 adds one. |
| MI355X, MI350X | `lmsysorg/sglang:dev-minimax-m31-flash-mi35x` (unchanged) | The AMD integration ([#46693](https://github.com/sgl-project/sglang/pull/46693)) is still open. Also drops a trailing space from these two image strings. |

The AgentX snippets are dated benchmark records pinned by digest and are not touched.
