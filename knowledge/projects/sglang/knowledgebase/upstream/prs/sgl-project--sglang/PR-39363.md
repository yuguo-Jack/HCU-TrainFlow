# [Perf] dsv4: shard the MHC prenorm prewarm across co-located ranks

[Upstream PR](https://github.com/sgl-project/sglang/pull/39363) · state: open · merged: False

## Original PR description

## Summary

Distribute MHC prenorm bucket compilation across ranks sharing a TileLang cache using two passes: claim available buckets, then wait for deferred buckets and replay outside the lock. Every rank still materializes all kernels; kernel math, bucket selection, and prewarm timing are unchanged.

- Locks use TileLang's resolved `TILELANG_CACHE_DIR` and include GPU architecture in the bucket key.
- mkdir/open/flock/unlock/close failures fall back to independent prewarm, with one warning per process. Lock-contention waits are bounded to 300 seconds per bucket.
- Owner death releases the OS lock. Recovery or timeout may cause concurrent compilation; there is no single-waiter takeover guarantee.

## Validation

Three CPU tests pass: multiprocess claim/wait/release, bounded waiting, and parameterized lock failures that preserve full-bucket replay and propagate replay exceptions. Pre-commit checks pass.

Existing DeepSeek-V4-Flash-0731 results from the original patch (not rerun for this reliability update):

| Hardware | MHC prewarm before → after | Startup to first response before → after |
|---|---|---|
| B200 TP8 | 158.6s → 31.4s | 442.7s → 316.3s |
| GB300 TP4 | 286.0s → 81.3s | 725.5s → 518.8s |

Warm-cache prewarm was ~2.6s either way. Four deterministic DSPARK prompts produced identical text, acceptance lengths, and verification counts.

GPU cold/warm-cache reruns and real cross-node shared-filesystem validation remain outstanding. Read-only filesystem failures are covered by EROFS injection. The timeout cannot interrupt filesystem calls stuck inside the OS, and TileLang's own cache/compiler errors remain outside this helper.
