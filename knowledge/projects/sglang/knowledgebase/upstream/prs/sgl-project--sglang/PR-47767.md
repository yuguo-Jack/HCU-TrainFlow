# [Feat] mem_cache: Add native CUDA VMM fabric custom mem pool for MNNVL PD

[Upstream PR](https://github.com/sgl-project/sglang/pull/47767) · state: open · merged: False

## Original PR description

## Motivation

Related to #38024 and #23074.

On multi-node NVLink fabric (MNNVL, e.g. GB200/GB300 NVL72) systems running disaggregated prefill/decode with `--disaggregation-transfer-backend nixl`:
1. `maybe_init_custom_mem_pool` (`python/sglang/srt/mem_cache/utils.py`) previously required `SGLANG_MOONCAKE_CUSTOM_MEM_POOL` to be set and imported `mooncake.allocator.NVLinkAllocator` (`mooncake-transfer-engine`), while `KvVmmArena` (`kv_vmm_backing.py`) is gated off for MLA models (`overrides.py: if mla_enabled: return False`).
2. In NIXL deployments where `mooncake-transfer-engine` is not installed (or `SGLANG_MOONCAKE_CUSTOM_MEM_POOL` is unset), every KV cache pool — including both multi-layer target `MLATokenToKVPool`/`MHATokenToKVPool` instances and speculative EAGLE's separate 1-layer draft `MLATokenToKVPool` — falls back to PyTorch's default `cudaMalloc` pool (`CU_MEM_HANDLE_TYPE_NONE`), preventing `CU_MEM_HANDLE_TYPE_FABRIC` export across nodes and forcing UCX/NIXL onto host TCP.

## Modifications

- **`python/sglang/srt/mem_cache/fabric_mem_pool.py`**:
  - Add `CudaVmmFabricAllocatorStub`, a native, size-unbounded `torch.cuda.memory.CUDAPluggableAllocator` compiled with `with_cuda=False` (resolving `cuDeviceGet`, `cuMemCreate`, `cuMemRelease`, `cuMemAddressReserve`, `cuMemAddressFree`, `cuMemMap`, `cuMemUnmap`, `cuMemSetAccess`, and `cuMemGetAllocationGranularity` from `libcuda.so.1` via `dlopen`/`dlsym`, so neither `nvcc` nor CUDA toolkit headers are required at runtime).
  - Allocate physical pages with `CU_MEM_HANDLE_TYPE_FABRIC` (probing `gpuDirectRDMACapable=1` first per device and automatically falling back to `gpuDirectRDMACapable=0` when GPUDirect RDMA is unavailable) with no minimum size cutoff, so both target KV pools and smaller speculative EAGLE draft KV pools, `MambaPool`, and staging buffers are fabric-exportable.
  - Cache one `torch.cuda.MemPool` per CUDA device inside `with torch.cuda.device(cuda_dev):` (`get_cuda_vmm_fabric_mem_pool`) so multiple KV pools on the same GPU safely share one `MemPool` without rebuilding the C++ stub or hitting cross-thread device-0 `use_count` assertions.
- **`python/sglang/srt/environ.py`**: Add `SGLANG_ENABLE_NIXL_FABRIC_MEM_POOL = EnvBool(True)` to control automatic activation for NIXL on MNNVL fabric-ready GPUs.
- **`python/sglang/srt/disaggregation/mooncake/utils.py`**:
  - Add `"FABRIC"` to `SUPPORTED_MOONCAKE_CUSTOM_MEM_POOL_TYPES` (and reject `"FABRIC"` alongside `"NVLINK"`/`"BAREX"` under `MOONCAKE_PROTOCOL=efa`).
  - Fall back to the native CUDA VMM `"FABRIC"` pool on fabric-ready GPUs (`is_gpu_fabric_ready(device)`) when `SGLANG_MOONCAKE_CUSTOM_MEM_POOL=NVLINK` (or `"True"`) raises `ImportError` on `mooncake.allocator`.
- **`python/sglang/srt/mem_cache/utils.py`, `python/sglang/srt/disaggregation/common/staging_handler.py`, `python/sglang/srt/arg_groups/overrides.py`, & `python/sglang/srt/entrypoints/engine.py`**:
  - Auto-enable the native `"FABRIC"` custom memory pool in `maybe_init_custom_mem_pool` (and `staging_handler._get_custom_mem_pool`) when `SGLANG_MOONCAKE_CUSTOM_MEM_POOL` is unset, `SGLANG_ENABLE_NIXL_FABRIC_MEM_POOL` is `True`, `disaggregation_mode in ("prefill", "decode")`, `disaggregation_transfer_backend == "nixl"`, `not enable_memory_saver`, and `is_gpu_fabric_ready(device)` is `True`.
  - Skip `post_capture_kv_sizing_planned` and single-node `kv_shard_symmetric_scratch` when `nixl_fabric_custom_mem_pool_planned(cfg)` is `True` (matching existing `SGLANG_MOONCAKE_CUSTOM_MEM_POOL` behavior).
- **`test/registered/unit/mem_cache/test_fabric_mem_pool.py` & `test/registered/unit/disaggregation/test_mooncake_efa_allocator.py`**: Add unit tests covering JIT compilation & C++ `malloc`/`free` tracking across large target and small draft allocation sizes, per-device `MemPool` singleton reuse, `SGLANG_MOONCAKE_CUSTOM_MEM_POOL=FABRIC` and `NVLINK` `ImportError` fallback, NIXL auto-activation and `SGLANG_ENABLE_NIXL_FABRIC_MEM_POOL=0` opt-out, EFA validation, and `post_capture_kv_sizing_planned`.

## Accuracy Tests

Allocator-only backing change (`CU_MEM_HANDLE_TYPE_FABRIC` VMM backing for `torch.cuda.MemPool`); tensor layouts, dtypes, and kernel math are unchanged. Unit tests verified via:
- `python test/registered/unit/mem_cache/test_fabric_mem_pool.py -v` (7/7 passed)
- `python test/registered/unit/disaggregation/test_mooncake_efa_allocator.py -v` (2/2 passed)
- `python test/registered/unit/server_args/test_server_args.py -k "post_capture_kv_sizing" -v` (1/1 passed)

## Speed Tests and Profiling

Enables zero-dependency `CU_MEM_HANDLE_TYPE_FABRIC` KV cache export across MNNVL cliques for both target KV pools and speculative EAGLE draft KV pools under `--disaggregation-transfer-backend nixl`, avoiding silent fallback to host TCP when `mooncake-transfer-engine` is absent.
