# [Fix] diffusion: Offset LTX-2.3 BCG video RoPE by the SP shard start

[Upstream PR](https://github.com/sgl-project/sglang/pull/45995) · state: closed · merged: True

## Original PR description

## Motivation

The legacy LTX-2.3 one-stage path (LTX-2.3 with a non-two-stage pipeline class) passes `video_coords=None` to the model. The model forward then builds the video RoPE coords itself, shifting each SP shard to its global position (`start_frame = sp_rank * local_frames`). The shift matches `sp_video_start_frame` from `LTX2PipelineConfig.shard_latents_for_sp`.

With `--enable-breakable-cuda-graph`, the stage instead builds those coords before capture, because building them inside the forward does an unpinned host-to-device copy that capture rejects. `_prepare_ltx2_rope_coords_for_bcg` passed no `start_frame`. So under SP every rank > 0 encodes its frames as if they started at frame 0, its shard repeats rank 0's temporal positions, and the video loses its temporal order past the first shard.

This affects LTX-2.3 one-stage (the default pipeline for `Lightricks/LTX-2.3` when `--pipeline-class-name` is not given) with SP > 1 and `--enable-breakable-cuda-graph`. BCG is opt-in. SP comes from explicit flags, or from `--num-gpus 4` with default flags, which resolves to SP 4. Two-stage pipelines and LTX-2 are not affected, because their coords come from `prepare_video_rope_coords_for_sp`, which already applies the start frame. Audio is not affected because the legacy path does not shard audio. The bug was added together with LTX-2.3 BCG support in #34929. CI does not cover it: the BCG suites run Z-Image only, and `test_ltx2_bcg_coords.py` asserted the call without a start frame.

## Modifications

`ltx_2/denoising.py`: `_prepare_ltx2_rope_coords_for_bcg` takes `video_start_frame`, and `_get_ltx2_rope_coords` passes the shard start (0 when the latents are not SP-sharded). The start frame was already in the coords cache key.

`test_ltx2_bcg_coords.py`: the existing helper test now expects `start_frame=0`. A new test runs `_get_ltx2_rope_coords` on the legacy BCG path with a real `LTX2AudioVideoRotaryPosEmbed` for SP ranks 0 and 1, and compares against the coords the eager forward builds for that shard.

## Accuracy Tests

- New test: on main, rank 0 passes and rank 1 differs on every temporal coordinate (48/144 elements). It passes with this PR. Rank 0 and non-SP runs build the same coords as before.
