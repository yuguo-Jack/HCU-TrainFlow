# [Feat] diffusion: Calibrate residency probes that run a single iteration and honor pipeline step minimums

[Upstream PR](https://github.com/sgl-project/sglang/pull/37809) · state: open · merged: False

## Original PR description

## Motivation

Three calibration defects in the warmup-driven residency planner (#36703), found while tuning MiniMax-H3 on a DGX Spark but not specific to unified memory:

1. **A single-iteration probe priced the whole DiT as one-shot.** H3 denoises `steps-1` times, so the 2-step warmup runs one DiT iteration and every layer measured a use count of 1. `estimate_layerwise_layer_uses` treated any count ≤ 1 as "not per-iteration" and left it unscaled, so the planner saw a DiT read once per request: no residency utility, no page-cache credit.
2. **Explicit `--warmup-resolutions` switched off the probe floor and the stage timers.** `collect_auto_residency_metrics` required `warmup_resolutions is None`, leaving a 2-step warmup without stage breakdown; the planner then ran on byte ordering alone.
3. **The resident-only validation pass ran one step.** H3 rejects `num_inference_steps < 2` (its sigma schedules include both interval endpoints), so a correct promotion was validated with an invalid request and rolled back.

## What changes

- In a repeated stage that itself ran a single iteration, a layer count of 1 is scaled to the target iterations (the fallback path resolves the stage's measured/target iterations the same way).
- Explicit warmup resolutions keep the `AUTO_RESIDENCY_TIMING_STEPS` floor and `suppress_stage_breakdown = False`; they only choose the probe's shape.
- `PipelineConfig.minimum_inference_steps` (default 1; MiniMax-H3 sets 2) and `_short_validation_step_limit` so the short validation never goes below it.

Unit tests: `test_single_iteration_probe_counts_repeated_stage_layers_per_iteration`, `test_short_validation_respects_pipeline_minimum_steps`.

Measured on the GB10 (H3 fl2va): before, the post-warmup plan chose `changes=[none]` four runs in a row and, once the pricing was right, its `transformer(resident)` promotion was rolled back by the 1-step validation; after, the promotion is selected and kept.

Split out of #37680.

## Follow-ups in this PR (2026-09-04)

**Calibration timing is logged.** Every planner decision and every rollback now logs the probe's total, its per-stage and per-step durations and the measured→target iteration counts (`Auto residency: calibration timing (...)`). The first thing it showed: in normal runs the probe records carry **no** stage or step durations (`stages: ; steps: []`), because the perf logger only records them under `SGLANG_DIFFUSION_STAGE_LOGGING` or a `perf_dump_path`; the comment in `warmup_request_builder` claiming the stage timers stay on was wrong.

**The regression check compares the probe's own wall time.** The rollback check used to compare request durations extrapolated from the probe (median of two CPU-side step timings × the target step count, ×12.7 for a 4-step probe of a 50-step default) with a 5% tolerance. With stage logging on, a GB10 run measured a promoted-DiT probe that took the same ~225 s as the layerwise probe as "863 s → 2108 s" and rolled back to the layout it had just measured as 2.6× slower; without stage logging the check never ran (the extrapolation was 0). It now compares the two same-shape probes' total wall time with a 15% / 5 s tolerance (`probe_duration_ns` / `reference_probe_duration_ns` on the rank report). The extrapolated durations remain for the savings model.
