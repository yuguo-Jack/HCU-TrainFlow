# [CLI] Avoid loading diffusion runtime during backend auto-detection

[Upstream PR](https://github.com/sgl-project/sglang/pull/39407) · state: open · merged: False

## Original PR description

## Motivation

When `sglang serve` is launched without an explicit `--model-type`, it runs backend auto-detection before falling back to the LLM backend.

The diffusion detector calls `is_registered_diffusion_model_path()`, which previously invoked `_ensure_registry_initialized()`. That initialization scans and imports every built-in diffusion pipeline, even when the target is a regular LLM.

On Ascend, importing these diffusion pipelines can transitively import the `attentions` package and load its bundled `libcust_opapi.so`. The LLM runtime may also load CANN's `custom_transformer/libcust_opapi.so`. Both libraries export operators such as:

```text
aclnnQuantLightningIndexer
aclnnQuantLightningIndexerGetWorkspaceSize
```

Loading both implementations into the same process can cause operator registration and symbol resolution conflicts.

The issue does not occur with `--model-type llm` because explicit backend selection skips auto-detection entirely.

## Modifications

- Stop registered diffusion path detection from discovering and importing every built-in runtime pipeline.
  - Built-in model path aliases are already populated by `_register_configs()` during registry module initialization.
  - Explicitly configured `SGLANG_EXTERNAL_MODEL_PACKAGE` packages are still loaded, preserving external diffusion model auto-detection.
- Make the public exports from `sglang.multimodal_gen` lazy:
  - `DiffGenerator`
  - `PipelineConfig`
  - `SamplingParams`
- Preserve the existing public import API, including:

```python
from sglang.multimodal_gen import DiffGenerator
```

- Add regression coverage to verify:
  - Importing `sglang.multimodal_gen` does not eagerly import the diffusion generator runtime.
  - Lazy public exports still resolve correctly.
  - Registered local diffusion model paths remain detectable without invoking `_ensure_registry_initialized()`.

This change does not modify model execution, attention backend selection, or any Ascend kernel implementation.

## Accuracy Tests

Not applicable. This PR does not change model forward paths, kernels, numerical operations, or generated outputs.

## Speed Tests and Profiling

No steady-state inference performance impact is expected.

Backend auto-detection should become faster and use less startup memory because it no longer imports all built-in diffusion pipelines before launching an LLM server.

No formal performance benchmark was run.

## Expected Ascend Behavior

Before this change, starting an LLM without `--model-type llm` could load both:

```text
CANN custom_transformer/libcust_opapi.so
site-packages/attentions/.../libcust_opapi.so
```

After this change, diffusion auto-detection no longer imports the runtime pipelines that load `attentions`. LLM startup should therefore behave consistently with explicit `--model-type llm`.

- awesome-pro · comment · 2026-09-30T20:44:41Z · [source](https://github.com/sgl-project/sglang/pull/39407#issuecomment-5919412465)

This one is approved and has been `CONFLICTING` for a while, so I reproduced the rebase against current `main` (`201c4b9b2a`) to see exactly what it needs. It is one conflict, and the resolution is not obvious: a naive rebase silently drops a fix `main` has since added. Details so nobody has to redo this.

**`main` has since mitigated the same problem, but more narrowly.** `cli/utils.py` now has:

```python
def _diffusion_deps_available() -> bool:
    # Locating diffusers is cheap; importing the registry costs ~2 s and then
    # fails anyway without it. A false positive is caught by the caller.
    import importlib.util

    return importlib.util.find_spec("diffusers") is not None
```

and `_is_diffusion_model_from_registry()` short-circuits on it. That only avoids the ~2 s registry import **when `diffusers` is not installed**. When it *is* installed, `main` still imports `sglang.multimodal_gen.registry` in-process, which is the thing this PR exists to avoid: the operator registration and pipeline discovery happen in the CLI process before a backend has been chosen. So the two are complementary, not redundant, and this PR is still worth landing.

**The conflict is a clean "both added here" at `cli/utils.py:35`.** The PR replaces `_diffusion_model_from_registry`'s body outright, and `main` inserted the `_diffusion_deps_available()` guard at the top of that same body. Taking the PR side alone deletes `main`'s guard, so every CLI backend auto-detection would spawn a `sys.executable -c` subprocess (with a 60 s timeout) even when `diffusers` is not installed at all. That is a real regression, and it is invisible from the PR diff because the PR predates the guard.

The resolution that keeps both wins:

```python
def _is_diffusion_model_from_registry(model_path: str) -> bool:
    if not _diffusion_deps_available():
        return False

    is_registered = getattr(
        sys.modules.get("sglang.multimodal_gen.registry"),
        "is_registered_diffusion_model_path",
        None,
    )
    if is_registered is not None:
        return is_registered(model_path)
    # ... existing subprocess fallback unchanged ...
```

**Two things worth a re-check on the rebase, since the approval predates them.** `ping1jing2` approved on 2026-09-15, but the branch has six commits after that (through 2026-09-17), including a `Merge branch 'main'` and three commits named `refactor`. The current head is a long way from what was approved.

**And the final diff has no test.** `gh pr view --json files` reports exactly one file, `python/sglang/cli/utils.py` (+38/-4). The original commit added `test/registered/unit/cli/test_serve_backends.py` coverage, but later `refactor` commits removed it again; `main`'s 249-line copy of that file has no reference to `_is_diffusion_model_from_registry`, `_diffusion_deps_available`, or the subprocess path. So the behaviour this PR changes, spawning a subprocess on the CLI's hot path, is currently untested, and the rebase is the natural moment to pin it (for example: reuse the in-process function when the module is already imported, and do not spawn when `diffusers` is absent).

@xiedeyantu if you would rather not untangle the two merge commits, I am happy to prepare the rebase: the guard-preserving resolution above, plus the missing test, either as a push to your branch or as a fresh PR that credits this one, whichever the maintainers prefer. @ping1jing2 since your approval predates the last six commits, worth confirming the current shape is still what you approved.
