# [Perf] qsa: scale the indexer prefill scores inside the relative scoring kernel

[Upstream PR](https://github.com/sgl-project/sglang/pull/48274) · state: open · merged: False

## Original PR description


## Motivation

`tilelang_qsa_mqa_prefill_relative` (the request-relative prefill scoring of the QSA indexer used by Qwen3.8-Flash-Next) writes unscaled scores into an fp32 `[rows, longest request]` workspace and then runs `logits.div_(scale)`. That is one more full read and write of the workspace for every prefill row chunk, which is the largest buffer of the indexer prefill.

This PR stores the scores already scaled inside the kernel, so the separate pass goes away. The logits are unchanged bit for bit.

## Modifications

- `python/sglang/srt/layers/attention/qsa/mqa.py`:
  - `_tilelang_qsa_mqa_prefill_relative_kernel` takes an `InvScale` scalar and stores `score * InvScale`;
  - `tilelang_qsa_mqa_prefill_relative` passes `fp32(1 / scale)` and drops the `div_`.
  - Why it is exact: PyTorch's CUDA `div_` by a host scalar computes `x * fp32(1 / scale)` (the reciprocal is computed once in fp32), and the kernel's single multiply is the same operation, so no rounding changes. `_reciprocal_fp32` computes that reciprocal on the host in fp32.
- `test/registered/kernels/ops/attention/qsa/test_qsa_indexer.py`: `test_relative_prefill_scores_equal_absolute` also runs with `score_scale=3.0`. The relative kernel (scale folded in) must equal the absolute-layout kernel followed by `div_` bit for bit, for bf16 and fp8 keys. The comparison against the torch reference keeps its tolerance and runs at the default scale as before.

No new server argument or environment variable.

## Accuracy Tests

Outputs are unchanged bit for bit:
- `test_relative_prefill_scores_equal_absolute` passes on H100 and RTX PRO 6000 Blackwell Server Edition, including the new non-default-scale cases (bf16 and fp8).
- In the benchmark below, a hash of every written logit is identical between main and this PR on every shape and GPU.

## Speed Tests and Profiling

Time of one `tilelang_qsa_mqa_prefill_relative` call: one row chunk as `select_prefill_tokens` issues it (`_qsa_prefill_row_chunk_size`), with Qwen3.8 indexer shapes (4 heads x 128, bf16), and `width` = compressed keys of the longest request. Timing uses `sglang.kernels.jit.benchmark.marker.do_bench` with a cold L2, reporting the median. Main and this PR alternate in the same container on the same GPU (A, B three times), and the table shows the median of the three runs, in µs.

| rows (chunk) | width | requests | H100 main | H100 PR | speedup | RTX PRO 6000 main | RTX PRO 6000 PR | speedup |
|---|---|---|---|---|---|---|---|---|
| 4096 (4096) | 4096 | 1 | 113.7 | 69.5 | 1.64x | 89.6 | 69.8 | 1.28x |
| 4096 (1536) | 21504 | 1 | 236.2 | 150.0 | 1.57x | 257.6 | 199.5 | 1.29x |
| 8192 (1536) | 21504 | 4 | 251.7 | 164.7 | 1.53x | 277.4 | 220.2 | 1.26x |
| 16384 (4096) | 8192 | 4 | 251.9 | 163.6 | 1.54x | 238.1 | 163.4 | 1.46x |

The spread across the three runs is at most 1.2 % on H100 and at most 5.5 % on the RTX PRO 6000 (main's first 4096-row run, 94.5 vs 89.6). On GB200 (two runs per arm) the same shapes improve 1.07-1.11x (90.1 → 83.6, 239.2 → 219.9, 261.7 → 243.8, 229.6 → 207.5 µs).
