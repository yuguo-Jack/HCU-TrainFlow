# [Fix] scheduler: Reserve encoder-replay rows in the shortest-prefill-first chunk reservation

[Upstream PR](https://github.com/sgl-project/sglang/pull/46063) · state: open · merged: False

## Original PR description

[by Claude Code]

## Motivation

With `--schedule-policy shortest-prefill-first` (SPF), while a long prompt is prefilled over several chunks, SPF
shortens that prompt's chunk so that shorter waiting requests can run in the same step: it reserves room for each of
them, charging its uncached tokens rounded up to a page (`SchedulePolicy.shortest_prefill_chunk_limit`). With
`--enable-encoder-swa-bounded-replay` (DeepSeek-V4.1), a cache hit that starts a new sliding-window (SWA) state (it has
no request slot yet, or was retracted) also recomputes up to 128 of its cached tokens ("replay rows"), and admission
charges those rows to the chunk as well (`PrefillAdder._replay_len`). The reservation did not count them, so it came
up to 128 tokens short per hit. The last reserved hit then no longer fits; SPF cannot split it (only one request may
be mid-chunk), so it waits and the room reserved for it stays empty. The next step computes the same reservation, so
the hit keeps waiting until the long prompt's last chunk. This PR adds each reserved hit's replay rows to the
reservation, through the same helper admission uses. Nothing changes with encoder replay off, for cache misses, or
for hits that keep their slot, and a request computes exactly the same tokens as before; only the step in which it
is prefilled changes.

SPF and its chunk reservation come from #40024 (@Oasis-Git); the replay-row charge at admission from #45040 and
#45047 (@hnyls2002). #46022, another SPF fix, edits the same two files; the two merge cleanly.

- **Performance:** DeepSeek-V4.1-Flash on 4x B200, the published InferenceX AgentX TP4 EP4 c24 cell with encoder
  replay on (mid curve, MTP), 2 ABBA pairs on one node: **TTFT p90 7.14 → 2.49 s and 6.33 → 2.40 s (−65%, −62%)**;
  request throughput +7.7% / +6.7%; the share of the 8192-token prefill chunk left empty while requests wait drops
  from 31% to 5%. Cost: decode is about 3% slower per token (paired decode ms/token p90 +3.0%; ITL p90 +2.4% / +2.5%),
  because prefill steps now carry more tokens.
- **Accuracy:** GSM8K under the same AgentX load (sgl-eval, 300 questions): 98.33% → 97.67% (−2 questions, within
  sampling noise); speculative accept length 3.37-3.43 → 3.40-3.42. New unit test: 6 of its 9 cases fail on main, all
  pass with this PR.

## Modifications

**+6 / −1 runtime code (1 file), +95 / −3 tests (2 files).** No kernel changes, no new flags, no default changes.

- `shortest_prefill_chunk_limit` adds each reserved request's replay rows to its charge, through
  `PrefillAdder._replay_len`, the helper admission uses (`python/sglang/srt/managers/schedule_policy.py`). The charge
  is `ceil_page(new_tokens) + replay_rows`, matching admission, which rounds only the new tokens. The reservation uses
  the prefix match from sorting the queue (`req.num_matched_prefix_tokens`); if admission re-matches a longer
  page-aligned prefix, the replay rows grow by at most as many tokens as the new tokens shrink, so the reservation
  still covers the hit.
- `PrefillAdder._replay_len` becomes a `@staticmethod` (it does not use `self`), so the policy can call it
  (`schedule_policy.py`).
- Tests (`test/registered/unit/managers/`): a table test in `test_prefill_adder.py` (below);
  `create_shortest_prefill_adder` gains `encoder_replay` and `page_size` arguments. `TestShortestPrefillFirst.setUp`
  in `test_schedule_policy.py` installs default server args, because the reservation now reads the encoder replay flag
  (a running server always has them).

## Accuracy Tests

**GSM8K under load** (same server and configuration as the speed test, runs B2 and A2 below): 120 s into a second
900 s AgentX run on the server, `sgl-eval run gsm8k` (sgl-eval 0.1.3, 300 questions, 16 threads, temperature 1.0,
top_p 0.95, max tokens 16384, seed 0; thinking on through the server's `SGLANG_DEFAULT_THINKING=1`):

| Arm | GSM8K | Errors | AgentX load during the eval |
|---|---|---|---|
| main (5994c5597d) | 98.33% (295/300) | 0 | 1253 requests, 0 errors |
| this PR | 97.67% (293/300) | 0 | 1336 requests, 0 errors |

The 2-question difference is within one run's sampling noise at temperature 1.0 (about ±0.8 pp per arm, binomial
estimate, not measured). Both evals started and finished inside their AgentX load window.

**Unit tests** (CPU): `test_shortest_prefill_reserves_encoder_replay_rows_of_hits` runs one long prompt and two
waiting cache hits (512 and 1024 uncached tokens) through `shortest_prefill_chunk_limit` and `PrefillAdder`, and
checks the long prompt's chunk, which hits are admitted whole, and the chunk room left. Every expected value is
derived by hand from the chunk arithmetic (example: a 4096-token chunk with two resetting hits reserves 512 + 128 and
1024 + 128, so the long prompt gets 2304 and both hits fit exactly; main gives it 2560 and turns the second hit away).
The cases and the mistake each one catches:

- encoder replay off, a cache miss, a hit that keeps its slot: nothing reserved for replay (charging replay rows
  where admission charges none);
- a hit with no slot, and a retracted hit that still holds a slot, at 256-token pages: 128 rows each (the missing
  charge this PR fixes; forgetting that retraction restarts the window);
- 64-token pages: a 64-token prefix (replayed whole: a flat 128-row charge), and a re-match one page longer than the
  sort-time match (charging the re-matched prefix instead of the sort-time one);
- one-token pages and a 1792-token chunk, where only the second hit's 128 replay rows push it past the room left after
  the first, so it waits (a fit check that ignores replay rows, which would reserve the whole chunk; an off-by-one in
  the row count, which larger pages round away).

On main 6 of the 9 cases fail; with this PR `test_prefill_adder.py` and `test_schedule_policy.py` pass (66 tests,
73 subtests), also with this PR merged onto current main.

## Speed Tests and Profiling

**Where on the curve, and why AgentX.** The fix only acts when SPF and encoder replay are both on and cache hits wait
behind a long prompt that is being chunked. Multi-turn agentic traffic at mid concurrency does exactly that: most
prompt tokens are prefix-cache hits (96% theoretical hit rate on this trace set), and new sessions bring prompts far
longer than the 8192-token chunk. The B200 TP4 EP4 c24 cell is the published B200 AgentX cell that uses SPF in that
region (in each main run, requests were queued in 853 of about 1100 prefill steps). The effect depends on the request mix
(prefix hits, long prompts, multi-turn), so this is an AgentX measurement rather than a static workload.

**Setup.** 4x B200 (one node), image `lmsysorg/sglang:nightly-dev-cu13-20261024-5994c559` (SGLang 5994c5597d, this
PR's base); the PR arm replaces only `python/sglang/srt/managers/schedule_policy.py` with this PR's file. Model
`deepseek-ai/DeepSeek-V4.1-Flash` (revision 314113f8a7). Server flags: the published InferenceX AgentX B200 TP4 EP4 c24
cell, plus the two flags this path needs (`--enable-encoder-swa-bounded-replay`, and `--cuda-graph-backend-prefill
breakable`, which encoder replay requires). Speculative acceptance is real: the published cell's
`SGLANG_SIMULATE_ACC_*` variables are left unset, so the accuracy check runs on the same configuration. Client: AgentX
(agentx-harness 1.0.12), trace set `semianalysis_cc_traces_weka_062126`, 24 concurrent sessions, a 900 s measured window
after warm-up, straight to the server (no router). Order main, PR, PR, main on one node, a fresh server per run.

```bash
export SGLANG_DEFAULT_THINKING=1 SGLANG_DSV41_REASONING_EFFORT=high SGLANG_ENABLE_DSV41_ENGRAM_HOST_TABLE=1 \
  SGLANG_DSV41_ENGRAM_HOST_TABLE_LAYOUT=per_rank SGLANG_TIMEOUT_KEEP_ALIVE=900 SGLANG_CUDA_COREDUMP_BEFORE_CRASH=0 \
  SGLANG_PYSPY_DUMP_BEFORE_CRASH=0 NCCL_CUMEM_ENABLE=1 NCCL_MNNVL_ENABLE=1 NCCL_DEBUG=WARN NVSHMEM_REMOTE_TRANSPORT=none
python3 -m sglang.launch_server --model-path deepseek-ai/DeepSeek-V4.1-Flash \
  --served-model-name deepseek-ai/DeepSeek-V4.1-Flash --port 30000 --tensor-parallel-size 4 --expert-parallel-size 4 \
  --chunked-prefill-size 8192 --max-running-requests 48 --mem-fraction-static 0.76 --prefill-decode-interval 96 \
  --schedule-policy shortest-prefill-first --speculative-algorithm DSPARK --speculative-dspark-block-size 5 \
  --swa-prefix-tails 768 --cuda-graph-max-bs-decode 64 --reasoning-parser auto --tool-call-parser auto \
  --tokenizer-backend fastokens --enable-metrics --trust-remote-code --watchdog-timeout 3600 \
  --enable-encoder-swa-bounded-replay --cuda-graph-backend-prefill breakable

agentx profile --url http://127.0.0.1:30000 --model deepseek-ai/DeepSeek-V4.1-Flash \
  --tokenizer deepseek-ai/DeepSeek-V4.1-Flash --tokenizer-trust-remote-code --concurrency 24 \
  --benchmark-duration 900 --warmup-grace-period 3600 --public-dataset semianalysis_cc_traces_weka_062126 \
  --server-metrics http://127.0.0.1:30000/metrics
```
