# [Fix] mem_cache: Fix HiCache load-back rollback and pin handoff

[Upstream PR](https://github.com/sgl-project/sglang/pull/48049) · state: open · merged: False

## Original PR description

## Motivation

When HiCache restores cached data from host memory to the device, it acquires node locks and reserves slots for KV, auxiliary pools, and request state. Existing admission code handles several failure returns, but leaves gaps in exception cleanup and lock handoff:

- FULL KV slots can remain reserved if a subsequent auxiliary allocation or eviction callback raises.
- Earlier auxiliary allocations are not rolled back when a later step raises. Derived transfers can also retain indices referring to source slots that have already been returned.
- `prepare_load_back()` runs outside the cleanup scope. An assertion from an exhausted Mamba request pool, or a later component's preparation failure, can leave node locks held and earlier request-state reservations unreleased.
- On success, the initial device lock is released before tree-state commit and before the asynchronous load-back receipt acquires its replacement lock, leaving a protection gap.

These issues affect available capacity in preallocated pools, state indices, and node eviction eligibility. This PR fixes the shared HiCache load-back lifecycle independently of INT8 checkpoints or codec fusion.

## Modifications

Update two production files and add one CPU regression-test file:

- **`hybrid_cache_controller.py`**
  - Release FULL slots newly allocated by `load()` when auxiliary resolution raises, preserving ownership of caller-provided slots.
  - Cover auxiliary allocation and derived-index resolution with rollback: return reservations made by the call and restore the original host/device indices of derived transfers.
  - Retain main's `merge_source_transfers()` behavior for multiple transfers from the same source pool.
- **`unified_radix_cache.py`**
  - Move device-lock acquisition and per-component preparation into `try/finally`, recording completed preparation steps so they can be finalized on failure.
  - Centralize admission-lock release. On success, acquire the asynchronous receipt's protection before releasing the initial device lock; on failure, return the host lock.
  - Preserve multiple pending receipts for host-only checkpoints.
- **`test_hicache_load_back_rollback.py`**
  - Add 14 test methods covering fault rollback, caller-owned resources, normal rejection, and lock handoff, registered in `base-a-test-cpu`.

## Accuracy Tests

### Reproduction

Tests use normally imported production methods, real CPU slot allocators, and real Mamba prepare/finalize implementations, with fault injection at allocation, eviction, and TreeCore callback boundaries.

| Scenario | Unmodified main | With this fix |
|---|---|---|
| Auxiliary allocation raises after reserving two KV slots | Free slots fall from 8 to 6; no operation is queued | Free slots return to 8 |
| Mamba request pool is exhausted; preparation asserts | Host/device lock counts remain 1/1 | Both return to 0 |
| A later component fails after an earlier preparation | Request slot remains set; only 1 of 2 slots is free | Request field cleared; both slots free |
| Transfer-spec construction raises | Request slot is returned, but locks remain 1/1 | Reservations and locks are cleaned up |
| Normal commit-action callback | Device-lock count is 0 | Count remains 1 until asynchronous protection takes over |

On unmodified main, 10 test methods expose failures. Pytest reports `12 failed, 7 passed, 3 subtests passed`; this includes subtest failures and does not represent 12 independent bugs. With the fix, all **14 new test methods and 8 subtests pass**.

The handoff test establishes the protection gap at commit time; it is not evidence of a reproduced concurrent use-after-free.
