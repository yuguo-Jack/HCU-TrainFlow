## Motivation

Code outside the KV storage read the storage plan's lifetimes, the allocator's bands and id spaces directly (the Triton backend took window lengths and value widths from the plan; decode named host pools and tree slots through the plan and window bands; the PD setup branched on the storage's type), and a sub-pool's internal name crossed two external boundaries directly: PD peers ordered and compared window entries by it, and window usage metrics were labelled by it. Renaming a sub-pool inside the process would then change the transfer protocol and the metric series.

## Modifications

- `mem_cache/kv/storage.py`, `static_kv_storage.py`: thin storage methods answer what consumers need (`primary_window_name`, `host_pool_name`, `window_tree_component`, `entry_sub_pool`, `storage_format_tag`, `draft_hosting_sub_pools`, `holds_view`); the static storage answers the same calls (its one window, its window host pool, the window slot).
- `kv/router.py`, `kv/routed_cache.py`, `layers/attention/triton_backend.py`: a layer's route and its sub-pool carry the attention window it reads over; the Triton backend reads window lengths from its router and value widths from the views.
- `kv/plan.py`: the target's window is chosen by one rule (`primary_window`), shared by the plan and the sizing that runs before a plan exists. `available_units` is the planner's answer (the separate `device_room` read is removed), so a host load evicts only what a take cannot otherwise get.
- `kv/decl.py`, `disaggregation/utils.py`, `base/conn.py`, `decode.py`: `SubPoolExternal` declares a sub-pool's PD entry key and usage label (`wire_key`, `label`) beside its host pool and tree component names; wire entries carry their key (`WireEntry.key`), peers order and compare entries by it (`KVArgs.state_wire_keys`), and usage reports each sub-pool under its label. Static pools register no key.
- `managers/scheduler.py`: the window capacities in `/server_info` and the startup gauge are the storage's own figures (the denominators of the window usage gauges) instead of the one sizing token count every window was assigned.
- `hybrid_pool_assembler.py`, `base_prefix_cache.py`: the host-stack assembler builds its slot ids from the storage's tree slots.
- Tests: `test_unified_window_lengths.py`, `test_unified_window_wire.py`, `test_unified_window_sub_pools.py`.

**Behavior change:** `/server_info` `memory_usage.token_capacity_window` and `sglang:max_total_num_tokens_window` now report each window's own capacity from the storage. Wire keys and labels keep the names the previous PRs introduced, so PD pairing and metric names do not change here.
