# [PD] Charge decode admission the page-rounded allocation when the radix cache is disabled

[Upstream PR](https://github.com/sgl-project/sglang/pull/43173) · state: closed · merged: True

## Original PR description

## Motivation

With the decode radix cache disabled, `DecodePreallocQueue.pop_preallocated` charges admission the raw fill length of the request (`_pre_alloc_fill_len`), while `_pre_alloc` goes on to allocate `_required_alloc_tokens(fill_len, prefix_len=0)`, which rounds the fill length up to whole pages. On a paged KV pool a request can therefore pass admission with fewer free tokens than the allocation it is about to make. The radix-cache path already charges the page-rounded amount; the no-radix path should charge the same thing.

Example: `page_size=64`, `fill_len=3`. Admission charged 3 tokens; `_pre_alloc` allocated 64.

## Modifications

- `python/sglang/srt/disaggregation/decode.py`: on the no-radix admission path, compute `required_alloc_tokens` with `_required_alloc_tokens(fill_len=..., prefix_len=0)` instead of the raw fill length.
- `test/registered/unit/disaggregation/test_decode_queue_cleanup.py`: the SWA-tail reclaim case gives its mocked allocator a real `page_size`, since the no-radix path now reads it.
- `test/registered/unit/managers/test_priority_scheduling_disaggregation.py`: new regression case `test_admission_without_radix_cache_charges_the_alloc_hook` pins the no-radix admission charge to the `_required_alloc_tokens` hook and checks that the charge decides whether the request is admitted. It fails on the previous code (`_required_alloc_tokens` is never called there).

## Accuracy Tests

Not applicable: scheduler bookkeeping only, no change to model outputs.

## Speed Tests and Profiling

Not applicable: one extra page-rounding computation per admitted request on the no-radix path, the same one the radix path already performs.
