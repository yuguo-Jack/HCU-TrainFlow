# [Fix] [AMD] docker: Update Mooncake for HIP RDMA memory accounting

[Upstream PR](https://github.com/sgl-project/sglang/pull/46878) · state: open · merged: False

## Original PR description

## Motivation

AMD SGLang prefill/decode deployments can lose their remaining allocatable VRAM when Mooncake registers an existing HIP KV allocation through dma-buf. Subsequent device allocations or kernel loading can fail despite registration not allocating another KV cache.

This updates the ROCm image's Mooncake dependency to include https://github.com/kvcache-ai/Mooncake/pull/4657 (merged as `a7f04df3451c4296f6cd1ff9d37b660042393aa8`). Mooncake now probes the driver and, where needed, holds one peer-memory anchor per underlying HIP allocation while keeping data MRs on dma-buf.

**Draft: the ROCm image build and AMD/RDMA validation below are still pending.**

## Modifications

- Update `MOONCAKE_COMMIT` in `docker/rocm.Dockerfile` from `78566d459c140956fd15606e102132b1acc83eec` to the merge commit above. Keep Mooncake's default `MC_HIP_KFD_PIN_FIX=1` automatic detection.
- Add a manual regression through SGLang's `MooncakeTransferEngine` wrapper. It allocates 60% of initially free VRAM, batch-registers two sub-buffers sharing that allocation, checks free VRAM in both directions, verifies a subsequent 64 MiB allocation and kernel execution, then checks accounting as each sub-buffer is unregistered.
- Run the regression in an isolated child with RDMA selected, HIP transport disabled, and dma-buf enabled. Require a conclusive native KFD probe log so an unsupported build/kernel or a peer-memory fallback cannot produce a false pass.

The dependency target is 473 commits ahead of the previous pin. Image builds and existing PD/HiCache compatibility checks are needed in addition to the focused regression.

## Relationship to #45759 and image rollout

Related: https://github.com/sgl-project/sglang/pull/45759 restores dma-buf in AMD PD CI while reducing the KV pool. This is a companion dependency update and does not duplicate that contributor's workflow/test edits.

The current CI image still needs to be rebuilt with this dependency before the existing `MOONCAKE_DISABLE_HIP_DMABUF=1` bypass can be removed. After the rebuilt image is selected, validate #45759's dma-buf path and reassess its KV pool bound against actual available memory. Removing the accounting error does not remove genuine memory-capacity constraints.
