## Motivation

The HiCache host pool is striped exactly like the page-interleave device pool: host slots live in the same widened logical index space, host page h is owned by rank h % N, and the host free lists are owner-classed. Every backup and load-back pairs device and host pages of the same owner, so a rank's share of any transfer is exactly its own pages, copied between its own HBM and host rows by the stock kernels. No cross-rank traffic; per-rank host memory is unchanged while logical host capacity grows with the shard group.

- pool_host/page_interleave.py: classed host slots + owned_rows narrowing.
- Backup draws host slots from the node's first-page owner (rotation_base + depth, host-side); load-back draws device pages from the first host page's class (alloc_cyclic). Both are sync-free.
- The controller narrows (host, device) to local rows while host indices are still on CPU.
- The prefix gather waits on the layer's load; scratch is reserved before a load-back is queued, so every H2D is consumed by its own batch.
- The load-back device eviction loops under the min-class floor.
- HiCache storage (L3) stays rejected under sharding, at launch and at runtime attach.
