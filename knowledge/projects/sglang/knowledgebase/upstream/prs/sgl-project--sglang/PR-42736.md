# [Perf] flashinfer: Autotune kernels at prefill sizes by default

[Upstream PR](https://github.com/sgl-project/sglang/pull/42736) · state: open · merged: False

## Original PR description

## Summary

Run the prefill-sized FlashInfer autotune pass by default, for every generation target (including speculative targets) and for EAGLE / EAGLE3 / STANDALONE drafts. This replaces the per-model `autotune_prefill_kernels` / `wants_prefill_autotune` hooks on DeepSeek-V4.1 and GLM-5.3-Flash with one generic full-forward pass, so every FlashInfer-tuned op (MoE, FP4 / MXFP8 GEMMs) gets prefill-sized tactics.

- `SGLANG_FLASHINFER_AUTOTUNE_EXTEND` is deprecated; `--disable-flashinfer-autotune` still turns autotuning off.
- PD decode workers skip the pass.
- The EXTEND dummy now matches a real extend: no TARGET_VERIFY reshaping, `is_extend_in_batch` published, and CP prepared and sharded when active.

### Request-pool cap

The prefill-sized dummy defaults to one sequence per token, which some backends cannot run (a real batch never has more sequences than the request pool). Now that the pass is on by default, these backends pack it into at most the request-pool size instead: DeepSeek-V4, linear attention (`MambaAttnBackendBase`), MiniMax / Qwen / MiniCPM sparse, Dots, torch native / flex and hpc_ops.

## Results

8x B300, fresh autotune cache. Largest tuned token count per op:

| Model | Config | Tuned up to |
|---|---|---|
| DeepSeek-V4.1-Flash | TP4 EP4, DSpark | FP4 MoE 16384, MXFP8 GEMM 16384 |
| GLM-5.3-Flash FP8 | TP4, EAGLE 5/1/6 | MoE 32768 |
| GLM-5.3-Flash-NVFP4 | TP4, EAGLE 5/1/6 | FP4 MoE 32768, FP4 GEMM 32768, draft BF16 MoE 32768 |
