# [Function Call] Avoid copying already streamed GLM47 argument values

[Upstream PR](https://github.com/sgl-project/sglang/pull/43729) · state: open · merged: False

## Original PR description

## Motivation

`Glm47MoeDetector._process_xml_to_json_streaming` appends every emitted string, array, object, and boolean character to `_current_value`. Those values have already been streamed, and the closing-tag branch only uses the remaining tail. Attribute string concatenation repeatedly copies an increasingly large value that is never consumed.

## Modifications

Remove the two redundant accumulations for values emitted incrementally. Keep buffering for `auto`, `number`, and `integer`, which are parsed at the closing tag. Empty values, JSON escaping, partial closing tags, and reset behavior retain their existing paths.

This is separate from #42575: it removes argument-value copies inside the streaming state machine and does not change regex matching or argument-pair scanning.

## Accuracy Tests

**34 relevant GLM47/IQuest tests passed**, including three new regression methods. The new buffer-retention test fails on unmodified upstream for all four streamed value types and passes with this patch. Numeric and inferred values retain their complete buffers and outputs. ## Speed Tests and Profiling

Synthetic CPU measurement on AMD Ryzen Threadripper PRO 9945WX, CPython 3.12.15. One typed string argument containing repeated `a` characters, streamed in 32-character chunks. Six samples per version after one warmup, alternating version order; outputs checked identical. Baseline is upstream `e6072935bf`, compared with the same source plus this change.

| Scope | Argument characters | Before, median | After, median |
| --- | ---: | ---: | ---: |
| XML-to-JSON streaming stage | 16,384 | 12.64 ms | 10.43 ms |
| XML-to-JSON streaming stage | 65,536 | 59.36 ms | 39.69 ms |
| XML-to-JSON streaming stage | 262,144 | 404.99 ms | 161.56 ms |
| Full `parse_streaming_increment` path | 65,536 | 885.25 ms | 865.72 ms |

The large stage-local reduction is not a whole-parser or model throughput claim. The full parser still rescans the accumulated tool-call buffer and improved by only about 2% in this workload. GPU inference was not benchmarked for this CPU-only change.
