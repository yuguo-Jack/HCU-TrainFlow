# [CI] [NPU] workflow: Gate pr-test-npu-finish on pr-gate and drop nightly PR trigger

[Upstream PR](https://github.com/sgl-project/sglang/pull/47823) · state: closed · merged: True

## Original PR description

## Motivation

pr-test-npu-finish aggregated the test jobs but not pr-gate, so a run blocked at the gate (missing run-ci label, draft PR, rate limit) skipped every test job and still reported all-green. Add pr-gate to its needs, matching pr-test-finish, pr-test-musa-finish and pr-test-mlx-finish. A skipped gate (coverage mode or no relevant changes) still passes, since the finish job only fails on failure/cancelled.

Also remove the pull_request self-trigger from nightly-test-npu.yml: touching that file launched the entire nightly suite on ungated NPU runners, and no other nightly workflow has such a trigger. schedule, workflow_dispatch and workflow_call callers are unaffected.

## Test plan

- YAML parses for both workflows (pr-test-npu-finish needs = [pr-gate, check-changes, ...]; nightly triggers = [schedule, workflow_dispatch, workflow_call]).
- NPU CI will validate the finish behavior on this PR once run-ci is added.
