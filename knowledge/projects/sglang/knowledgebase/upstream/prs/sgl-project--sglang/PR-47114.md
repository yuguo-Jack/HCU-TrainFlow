# [Fix] rust_server: Record startup-time metrics in Rust mode

[Upstream PR](https://github.com/sgl-project/sglang/pull/47114) · state: closed · merged: True

## Original PR description

## Motivation

With `--enable-metrics`, the `TokenizerManager` records `sglang:startup_time_seconds` (per phase: `load_weight`, `kv_cache_allocation`, `scheduler_e2e`, `tokenizer_e2e`) and `sglang:startup_cuda_graph_time_seconds` (per capture phase) once the schedulers report their startup phases, and the engine logs the "Engine startup timings" line from the same values. Rust mode has no `TokenizerManager`, so a Rust-mode server exposed neither family on `/metrics` and never logged the timings. Everything else the frontend serves on `/metrics` comes from the scheduler processes' multiprocess files or from the frontend's own request metrics; the startup phases reach only the main process.

## Modifications

- `python/sglang/srt/entrypoints/engine.py`: in Rust mode, the main process records the startup-time metrics itself once `scheduler_init_result.wait_for_ready()` returns, through a new `_rust_server_startup_time_sink()`. The sink is a no-op without `--enable-metrics`; otherwise it builds the tokenizer collector class `resolve_collector_class(STAT_LOGGER_ROLE_TOKENIZER, ...)` picks, with `tokenizer_metric_labels()`, and returns its `emit_startup_time`. The default class is read from the `metrics_collector` module at call time, so a replacement installed after `engine` is imported (a stat logger, or a model package's own collector) still applies. The samples land in the main process's prometheus_client multiprocess file, which the Rust `/metrics` already merges.
- `Engine._set_startup_time` takes the sink callable instead of the tokenizer manager. The Python path passes `tokenizer_manager.set_startup_time` and behaves as before, including the timings log line, which Rust mode now logs too.
- `test/registered/unit/entrypoints/test_rust_server_dp_ports.py`: `test_rust_mode_main_process_reports_startup_time` replaces `metrics_collector.TokenizerMetricsCollector` after import, as a model package does, and checks that the sink builds that class with the base labels and forwards to `emit_startup_time`, and that it builds nothing without `--enable-metrics`.
