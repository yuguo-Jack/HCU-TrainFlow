# [Fix] scheduler: Record weight version events on every request list

[Upstream PR](https://github.com/sgl-project/sglang/pull/43909) · state: closed · merged: True

## Original PR description

Readers that collect live requests by hand take them from `Scheduler.request_lists()`.

- Fixes the weight version update missing requests outside the running batches: `record_weight_version_change` recorded events only on requests in batch snapshots, the waiting queue, the chunked slot, deferred responses and HiSparse staging, so a request waiting for its grammar, in a PD queue, in the dLLM queue or in a parked uOCR window got no weight-version event. It now records on every request in every list.
- Queue gauges and load read their lists from `request_lists()` by kind: the waiting, grammar and PD prefill gauges, copied in the prefill, decode and idle reports, become one `_update_queue_stats`; `get_loads` reads the PD queues by kind and drops three queue getters.

Behavior change: the fix above.

## Test plan
- `test_records_on_every_request_list`: requests in the running, waiting, chunked, grammar and PD sending lists each get the event (the grammar and PD sending ones fail before the fix).
- The unit tests under `test/registered/unit/{managers,disaggregation,lora,utils,dllm,observability}` pass locally with `SGLANG_IS_IN_CI=1`, apart from failures the base has too.
