# [Refactor] tokenizer_manager: Move the crash-dump writer into a utils module

[Upstream PR](https://github.com/sgl-project/sglang/pull/47107) · state: closed · merged: True

## Original PR description

## Motivation

`TokenizerManager.dump_requests_before_crash` built the `--crash-dump-folder` pickle inline: the `<folder>/<hostname>/crash_dump_<time>.pkl` path, the dict of `server_args`, `config_updates`, `resolved_config`, redacted `requests` and `launch_command`, and the retry without `server_args` when that fails to pickle (seen with `--trust-remote-code`). A writer that does not depend on `TokenizerManager` lets another frontend produce the same file, so the existing readers such as `scripts/playground/replay_request_dump.py` load either. This PR only moves the writer; the dump itself does not change.

## Modifications

- New `python/sglang/srt/utils/crash_dump.py` with `write_crash_dump(folder, hostname, requests, server_args, resolved_config, watermark_config)`. It builds the same dict as before, pickles it to `<folder>/<hostname>/crash_dump_<time>.pkl`, keeps the retry without `server_args` and `resolved_config` when pickling fails, and returns the path.
- `TokenizerManager.dump_requests_before_crash` still collects the finished and unfinished requests and logs the summary line; it now calls `write_crash_dump`. The now-unused `redact_watermark_command_line` import moves with the code.
- New `test/registered/unit/utils/test_crash_dump.py` (`base-a-test-cpu`) pins the dump as the `TokenizerManager` writes it: the folder and file name, the file mode, the dict keys and values, the finished and unfinished requests, and that it happens once per process.

Not in scope: any change to what the dump contains or where it is written.

## Testing

- `pre-commit run --files` on the three changed files passes (isort, ruff, ruff format, codespell, the registered-test registry checks).
- `test/registered/unit/utils/test_crash_dump.py` passes on this branch, and the same test file passes against `main` before the move (the `TokenizerManager` with the inline writer), so the test pins the existing behaviour rather than the new code.
