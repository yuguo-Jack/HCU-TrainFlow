## Performance: `--attention-backend sage_attn` on Intel XPU

**Setup:** 1x Intel Arc Pro B60 (24 GB, Xe2), driver 1.15.39122, torch 2.13.0+xpu, triton-xpu 3.7.2, sglang-kernel-xpu 0.3.0, diffusers 0.38.0, bf16. Baseline is the existing XPU flash-attention backend (`fa`).

### Kernel: one attention call vs `fa`

Median of 5 interleaved rounds, XPU event timing, batch 1, bf16.

| Shape (tokens x heads x head_dim) | `fa` | `sage_attn` | Speedup |
|---|---|---|---|
| Wan2.1 480p self-attention, 32760 x 12 x 128 | 94.26 ms | 81.29 ms | **1.16x** |
| Long sequence, 16384 x 24 x 64 | 27.14 ms | 22.82 ms | **1.19x** |
| Z-Image 1024², 4224 x 30 x 128 | 4.30 ms | 4.12 ms | 1.04x |
| 4096 x 24 x 128 | 3.21 ms | 3.26 ms | 0.98x |
| 4429 x 24 x 64 | 1.78 ms | 1.95 ms | 0.91x |
| Text cross-attention, 32760 q x 512 kv x 12 x 128 | 1.88 ms | 2.23 ms | 0.85x |

- **Where it pays off:** gains grow with sequence length.
- **Where it loses:** on short sequences and text cross-attention, the INT8 quantization prepass (about 0.5 ms per call at image sizes) costs more than the INT8 Q·Kᵀ saves.
- **Accuracy vs fp32 attention** (all test shapes, fp16 and bf16): cosine >= 0.9999, relative L2 error ~1.3e-2, LSE max abs error < 0.025.

### End to end: `sglang generate`, fa / sage / sage / fa

Run with `--warmup-mode request` and `SGLANG_DIFFUSION_SYNC_STAGE_PROFILING=1`. "Steady step" is the median of denoise steps 1..N; step 0 includes the DiT upload from the CPU offload that is enabled automatically on 24 GB.

| Model | Backend | Steady denoise step | Request total | Peak memory | Quality vs `fa` |
|---|---|---|---|---|---|
| Wan2.1-T2V-1.3B, 832x480, 81 frames, 10 steps | `fa` | 8772 / 8781 ms | 107.86 / 107.96 s | 22.26 GB | reference (two runs bit-identical) |
| | `sage_attn` | 8035 / 8033 ms (**-8.5%**) | 100.50 / 100.50 s (**-6.9%**) | 22.26 GB | PSNR 32.40 dB mean / 30.24 dB worst frame; SSIM 0.931 / 0.923 |
| | `torch_sdpa` | 10460 ms | 124.76 s | 22.26 GB | PSNR 35.73 / 34.58 dB; SSIM 0.951 / 0.947 |
| Z-Image-Turbo, 1024x1024, 9 steps | `fa` | 878.6 / 878.4 ms | 17.31 / 17.30 s | 12.38 GB | reference (bit-identical) |
| | `sage_attn` | 875.4 / 874.3 ms (-0.4%) | 17.27 / 17.27 s (-0.2%) | 12.38 GB | PSNR 20.74 dB, SSIM 0.823 |
| | `torch_sdpa` | 903.9 ms | 17.53 s | 12.38 GB | PSNR 23.58 dB, SSIM 0.880 |

- **Why the gains differ:** with `fa`, attention is 66% of a Wan denoise step (5.77 s of 8.79 s) but only 15% of a Z-Image step (133 ms of 875 ms); GEMMs (58%) and element-wise ops dominate Z-Image. The profiler window covers 7 steps, normalized per step.
- **Wan quality** passes the repo's video thresholds (SSIM 0.92 / PSNR 24 dB).
- **Z-Image quality:** the 8-step distilled model amplifies any attention rounding change; even exact `torch_sdpa` differs from `fa` by a similar amount. The global flag also puts the Qwen3 text encoder on Sage. For image models, `--component-attention-backends transformer=sage_attn` keeps the text encoder on `fa`.
- **Recipes:** Z-Image follows the cookbook's Intel BMG recipe (1 GPU, default flags). Wan2.1 is not a documented BMG recipe; it was run to measure a long, attention-heavy sequence, with 10 steps instead of the default 50 because per-step cost is unchanged.

## Performance post Driver and Triton Version upgrade(As it caused regression, had to change tile configs to chose between perf and accuracy): `--attention-backend sage_attn` on Intel XPU

**Setup:** 1x Intel Arc Pro B60 (24 GB, Xe2), driver 1.15.39122, torch 2.14.0+xpu, triton-xpu 3.8.0, sglang-kernel-xpu 0.4.0, diffusers 0.38.0, bf16, base `41eaeb0445`. Baseline is the existing XPU flash-attention backend (`fa`).

### Kernel: one attention call vs `fa`

Median of 5 interleaved rounds, XPU event timing, batch 1, bf16.

| Shape (tokens x heads x head_dim) | `fa` | `sage_attn` | Speedup |
|---|---|---|---|
| Long sequence, 16384 x 24 x 64 | 26.92 ms | 21.24 ms | **1.27x** |
| Wan2.1 480p self-attention, 32760 x 12 x 128 | 95.67 ms | 87.12 ms | **1.10x** |
| Z-Image 1024², 4224 x 30 x 128 | 4.47 ms | 4.18 ms | **1.07x** |
| 4096 x 24 x 128 | 3.42 ms | 3.37 ms | 1.01x |
| 4429 x 24 x 64 | 1.77 ms | 1.82 ms | 0.97x |
| Text cross-attention, 32760 q x 512 kv x 12 x 128 | 1.99 ms | 2.08 ms | 0.96x |
| 1024 x 24 x 64 | 0.11 ms | 0.14 ms | 0.79x |

- **Where it pays off:** gains grow with sequence length.
- **Where it loses:** on short sequences and text cross-attention, the INT8 quantization prepass and host launch cost exceed what INT8 Q·Kᵀ saves.
- **Quantization:** Q is quantized per 128 rows (64 for head_dim 64) and K per 64 rows, and each attention tile uses exactly one Q scale and one K scale. A per-row scale vector inside the loop made triton-xpu 3.8 route it through shared memory on every K/V iteration (3x slower). Same speed on triton-xpu 3.7.2.
- **Accuracy vs fp32 attention** (all test shapes, fp16 and bf16): cosine >= 0.9999, relative L2 error ~1.3e-2, LSE max abs error < 0.025.

### End to end: `sglang generate`, fa / sage / sage / fa

Run with `--warmup-mode request` and `SGLANG_DIFFUSION_SYNC_STAGE_PROFILING=1`. "Steady step" is the median of denoise steps 1..N.

| Model | Backend | Steady denoise step | Request total | Peak memory | Quality vs `fa` |
|---|---|---|---|---|---|
| Wan2.1-T2V-1.3B, 832x480, 81 frames, 10 steps | `fa` | 8845 / 8848 ms | 100.84 / 100.89 s | 7.44 GB | reference (two runs bit-identical) |
| | `sage_attn` | 8248 / 8256 ms (**-6.7%**) | 94.87 / 94.88 s (**-5.9%**) | 7.44 GB | PSNR 33.26 dB mean / 30.70 dB worst frame; SSIM 0.940 / 0.936 |
| | `torch_sdpa` | 10420 ms | 116.51 s | 7.44 GB | PSNR 33.69 / 31.02 dB; SSIM 0.943 / 0.939 |
| Z-Image-Turbo, 1024x1024, 9 steps | `fa` | 875.9 / 876.8 ms | 9.37 / 9.38 s | 12.38 GB | reference (bit-identical) |
| | `sage_attn` | 872.8 / 873.3 ms (-0.4%) | 9.34 / 9.36 s (-0.3%) | 12.38 GB | PSNR 20.66 dB, SSIM 0.824 |
| | `torch_sdpa` | 897.8 ms | 9.57 s | 12.38 GB | PSNR 23.15 dB, SSIM 0.873 |

- **Why the gains differ:** attention is about two thirds of a Wan denoise step but only about 15% of a Z-Image step. The Z-Image change is below the 1.5% end-to-end bar, so this PR claims no speedup for 1024² images.
- **Wan quality** passes the repo's video thresholds (SSIM 0.92 / PSNR 24 dB) and sits close to the exact `torch_sdpa` noise floor.
- **Z-Image quality:** the 8-step distilled model amplifies any attention rounding change; even exact `torch_sdpa` differs from `fa` by a similar amount. For image models, `--component-attention-backends transformer=sage_attn` keeps the text encoder on `fa`.
- **Wan on 24 GB XPU needs `--component-residency text_encoder=component-offload` with any backend:** the default warmup preload of its 21 GiB fp32 text encoder leaves too little memory for the Level Zero driver and the first denoise step fails with `UR_RESULT_ERROR_OUT_OF_RESOURCES`. This is unrelated to this PR; `fa` and `torch_sdpa` fail the same way.
- **Recipes:** Z-Image follows the cookbook's Intel BMG recipe (1 GPU, default flags). Wan2.1 is not a documented BMG recipe; it was run to measure a long, attention-heavy sequence, with 10 steps instead of 50 because per-step cost is unchanged.

**Update: `sage_attn` on XPU now uses Intel ARK (`auto-round-lib`) when it's available**

On XPU, `sage_attn` now runs Intel ARK's `sagev1` kernel when `auto-round-lib` is installed. It's added to the XPU `diffusion` extra, pinned to 0.16.0. SGLang's Triton kernel still runs in these cases:

- **Calls that need the LSE (ring attention).** ARK 0.16.0 returns one LSE per 16 query rows, so these calls log a one-time warning and use Triton. Upstream issue: <link>
- **Head dims other than 64 and 128.**
- **ARK missing or its XPU library failing to load.** This logs a warning and uses Triton. It usually happens because the library needs `<env>/lib` on `LD_LIBRARY_PATH`.

Setup:
- Hardware and software: Arc Pro B60 (one card), torch 2.14.0+xpu, triton-xpu 3.8.0, sglang-kernel-xpu 0.4.0, auto-round-lib 0.16.0.
- Run settings: bf16, seed 42, `--warmup-mode request`.
- Step time is the median of steps after the first.
- For the "sage_attn (Triton)" rows, ARK was hidden so that importing it fails.

**Wan2.1-T2V-1.3B, 832x480, 81 frames, 10 steps** (`--component-residency text_encoder=component-offload`)

| Backend | Request | Denoise step | vs fa (step / request) | PSNR / SSIM vs fa (mean, min frame) |
|---|---|---|---|---|
| fa | 100.86 s | 8847 ms | n/a | n/a |
| sage_attn (ARK) | 85.13 s | 7285 ms | **-17.7% / -15.6%** | 32.90 / 0.934 (min 31.32 / 0.928) |
| sage_attn (Triton) | 94.87 s | 8254 ms | -6.7% / -5.9% | 33.26 / 0.940 (min 30.70 / 0.936) |

**Z-Image-Turbo, 1024x1024**

| Backend | Request | Denoise step | vs fa (step / request) | PSNR / SSIM vs fa |
|---|---|---|---|---|
| fa | 9.38 s | 876.0 ms | n/a | n/a |
| sage_attn (ARK) | 9.17 s | 853.5 ms | **-2.6% / -2.2%** | 23.54 / 0.900 |
| sage_attn (Triton) | 9.34 s | 872.7 ms | -0.4% / -0.4% | 20.66 / 0.824 |

For reference, torch_sdpa vs fa with the same settings gives 33.69 / 0.943 on Wan and 23.15 / 0.873 on Z-Image. Peak memory is the same for all backends: 7.44 GB for Wan and 12.38 GB for Z-Image.

**Attention kernel alone** (bf16; median of interleaved runs):

| Shape (tokens x heads x head dim) | fa | Triton | ARK |
|---|---|---|---|
| Wan self-attention 32760x12x128 | 95.7 ms | 87.1 ms (1.10x) | 67.9 ms (1.41x) |
| Z-Image 4224x30x128 | 4.47 ms | 4.18 ms (1.07x) | 3.49 ms (1.28x) |
| 4096x24x128 | 3.41 ms | 3.37 ms (1.01x) | 2.74 ms (1.24x) |
| 16384x24x64 | 26.9 ms | 21.2 ms (1.27x) | 21.6 ms (1.25x) |
| 4429x24x64 | 1.77 ms | 1.82 ms (0.97x) | 1.94 ms (0.91x) |
| 1024x24x64 | 0.11 ms | 0.14 ms (0.79x) | 0.23 ms (0.48x) |
| Cross-attention 32760 q x 512 kv x 12x128 | 1.94 ms | 2.08 ms (0.96x) | 1.93 ms (1.01x) |

ARK and Triton were timed in separate processes, each against its own fa run, because importing ARK sets an IGC environment variable for the whole process. The fa timings in the two processes agreed within 0.1%, except cross-attention at about 2.5%. Speedups are against fa. ARK is slower than fa on short sequences, but neither model above hits that range.

Accuracy against an fp32 reference is the same for both kernels (relative error 1.30e-2 for ARK vs 1.32e-2 for Triton at the Z-Image shape).

**Tests**
- `test/registered/kernels/ops/diffusion/test_sage_attn_ark_parity.py` (XPU, stage-b): ARK vs Triton through the backend, 13 cases covering bf16/fp16, D64/D128, GQA, causal, cross-attention, non-default scale, and strided or sliced inputs. The tolerance is 3e-2; the cases measure 2e-4 to 1.8e-2. The test also fails if both calls run the same kernel. It skips until the XPU CI image is rebuilt with the new `diffusion` extra.
- `python/sglang/multimodal_gen/test/unit/test_xpu_attention_backend.py`: LSE calls never reach ARK, a library that fails to load falls back to Triton, and inputs are re-strided for ARK's stride check.
