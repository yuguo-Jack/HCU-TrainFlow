# [Feat] Valen: Add native decision-head serving

[Upstream PR](https://github.com/sgl-project/sglang/pull/45618) · state: open · merged: False

## Original PR description

## Motivation

Valen-2B currently requires its custom Transformers implementation for decision inference. This adds native SGLang loading and `/v1/systemone` serving for `ValenQwenForDecisionMaking` checkpoints, with all questions sharing one causal Qwen3.5 prefill and the trained FP32 Mixer head scoring their candidates.

## Modifications

- Register the Valen config and reuse the native Qwen3.5 backbone, preserving the checkpoint's compute dtype and FP32 decision-head weights. Native serving does not require `--trust-remote-code`.
- Compile Valen's trained prompt format and role spans, preserve candidate order, and pool context/instruction/candidate/decision features across batched requests.
- Support text, conversation states, and images with the checkpoint's resize limits through `/v1/systemone`, including choice, noul, and score questions.
- Enforce complete-prefill execution without prefix reuse, truncation, chunked prefill, or CUDA graphs. This implementation supports shared-state Mixer checkpoints at TP=1/PP=1; video/audio content blocks are explicitly rejected.
- Add compiler, head, config, and serving tests, an end-to-end reference comparison script, and usage documentation.

## Accuracy Tests

- Related CPU regression tests: **54 passed, 1 skipped, 128 subtests passed**.
- Prompt token IDs and role spans matched the published checkpoint implementation for text and image inputs; the FP32 head matched with identical weights/features.
- Real Valen-2B weights on one NVIDIA H200: five reference cases plus 20 mixed requests at concurrency 4. Input token counts and choice results matched. Maximum absolute probability difference from Transformers: **0.00767321**. Maximum concurrent-versus-sequential difference: **0.00742241**. The test's tolerance is 0.02.
- Both default overlap scheduling and `--disable-overlap-schedule` passed the same GPU checks.
- All applicable pre-commit hooks passed after applying the repository's isort formatting.

## Speed Tests and Profiling

One H200, PyTorch 2.14.1/CUDA 13, Transformers 5.19.0, sglang-kernel 0.4.10, FA3, BF16 backbone compute, FP32 head, and default overlap scheduling. The reference retains the checkpoint's FP32 weights and uses its configured BF16 backbone autocast. Optional Transformers `causal_conv1d` and `flash-linear-attention` kernels were not installed.

These are synthetic smoke benchmarks, with the median of three warmed runs per case. Native timings include local HTTP overhead. They are not a general model-performance claim.

| Case | Input tokens | Transformers (ms) | SGLang (ms) | Speedup |
| --- | ---: | ---: | ---: | ---: |
| Short text, three questions | 160 | 39.80 | 27.61 | 1.44× |
| Conversation, three questions | 176 | 38.57 | 27.19 | 1.42× |
| 11-level score | 83 | 35.12 | 26.56 | 1.32× |
| Long text, three questions | 1480 | 97.66 | 30.39 | 3.21× |
| Image, two questions | 312 | 58.45 | 46.82 | 1.25× |

The mixed 20-request run at concurrency 4 achieved **33.15 requests/s**. The script saves raw responses, server logs, launch arguments, per-case latency, and probability differences for inspection.
