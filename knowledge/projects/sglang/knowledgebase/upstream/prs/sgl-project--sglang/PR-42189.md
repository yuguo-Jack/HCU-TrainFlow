# [Fix] deepseek-v4.1: Restore CUDA VL expert remapping and recording

[Upstream PR](https://github.com/sgl-project/sglang/pull/42189) · state: open · merged: False

## Original PR description

## Motivation

Vision-enabled DeepSeek-V4.1 checkpoints route text-only requests through CUDA `vision_topk()` too. Outside MegaMoE, that path skips ordinary TopK finalization: expert-distribution counts stay empty and nonidentity EPLB placement does not reach the physical-expert dispatch boundary.

Fixes #42188.

## Modifications

- Keep device-side, per-token text/image correction-bias selection and finalize CUDA VL routes through ordinary TopK's capture, expert mapping, shared-slot and recorder path.
- Pass existing expert-location dispatch information through both normal and dual-stream DeepSeek MoE call sites.
- Retain fused packed output when finalization preserves its IDs and weights; use the standard unpacked result after remapping.
- Mask padding after shared-slot rewrites. Preserve the existing non-CUDA and MegaMoE behavior.

No modality-admission synchronization, public option or dependency is added.

Follow-up to my earlier review/CI request: further source inspection identified a correctness gap in the current admission-based approach.

With DP attention and gathered MoE, routing consumes global token rows, but `forward_batch.mm_inputs` remains rank-local. The current check can therefore select different routing paths across ranks for a mixed text/image batch. Host-side admission also needs additional care for prefill CUDA graph capture and replay.

I plan to revise this PR by removing the new CUDA batch-level admission check, retaining device-side per-token modality selection, and making VL routing reuse the standard TopK finalization: EPLB remapping, padding, shared-expert handling, recording, and valid packed outputs. No new collective or modality-specific recorder is planned; existing ROCm behavior will be kept unchanged in this revision.

The existing H200 results are historical validation of the original TP8/EP4/DP1 implementation, not validation of this replacement. Mixed-DP and cross-modality graph replay tests are still pending.

Please hold off merging the current revision. I am moving the PR back to Draft and updating the description to distinguish the planned replacement from the code currently on the branch. Feedback on this approach would be appreciated.
