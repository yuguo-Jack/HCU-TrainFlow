# Support Gemma 4 language-only startup

[Upstream PR](https://github.com/sgl-project/sglang/pull/32221) · state: closed · merged: False

## Original PR description

## Summary

- allow `Gemma4ForConditionalGeneration` through server validation only in `--language-only` mode
- avoid constructing Gemma 4 vision/audio towers and embedders in that mode
- keep Gemma 4 `--encoder-only` rejected because the model does not implement that mode
- preserve precomputed image/video embeddings and fail clearly if raw inputs reach unavailable local fallback

`ModelConfig` already propagates `ServerArgs.language_only` onto the HF config consumed by the model constructor. Gemma 4 language-only therefore supports text and remotely precomputed multimodal embeddings; it deliberately does not claim local multimodal fallback without towers.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Preserve local fallback when encoders are unavailable**

When `--language-only` is used and the tokenizer cannot wait for remote embeddings (for example `zmq_to_scheduler`/`mooncake` with no registered encoder URLs, or adaptive dispatch leaving a single-image request local), `_tokenize_one_request` falls back to local multimodal processing and sends raw `mm_inputs` to the scheduler. With this condition the first PP rank has only `PPMissingLayer`/`None` for the Gemma4 encoders, so `general_mm_embed_routine` can still invoke `get_image_feature`/`get_video_feature`/`get_audio_feature` on raw inputs and crash instead of serving the fallback. Either keep the local Gemma4 embedders for fallback-capable language-only workers or disable/guard that fallback for Gemma4.
