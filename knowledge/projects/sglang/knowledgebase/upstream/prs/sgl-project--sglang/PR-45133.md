# [Fix] openai: End failed chat and completion streams with an error

[Upstream PR](https://github.com/sgl-project/sglang/pull/45133) · state: open · merged: False

## Original PR description

Based on #45130; only the last commit is new.

## Motivation

After the first chunk, a chat stream caught only `ValueError`. Any other exception ended the stream with no error frame and no final `data: [DONE]`, which OpenAI clients wait for. Completions streams caught every exception but sent the exception text.

## Modifications

- Chat and completions streams catch every exception after the first chunk and end with an error frame and `[DONE]`.
- A `ValueError` keeps its message (`invalid_request_error`), as before the stream.
- Any other exception is logged and reported with a generic message (`server_error`).
- Exceptions before the first chunk still return an HTTP error.
- Transcription streams are unchanged.
- A `ValueError` raised by internal code also keeps its message, as before.

Not applicable: error handling only.

## Validation

New tests in `test_serving_chat.py` and `test_serving_completions.py` cover:
- `RuntimeError` and `ValueError` mid-stream;
- the frame without the envelope;
- an exception before the first chunk.

The two mid-stream `RuntimeError` tests fail before the change and pass after. Both suites pass on CPU.
