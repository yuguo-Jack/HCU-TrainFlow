# [KDA] Support extra_buffer mamba radix cache for Kimi Linear

[Upstream PR](https://github.com/sgl-project/sglang/pull/30243) · state: closed · merged: False

## Original PR description

## Motivation

KDA (Kimi Delta Attention) previously did **not** support the `extra_buffer` mamba radix cache strategy. Forcing it on regressed GSM8K accuracy to **~0.63**, so `KimiLinearForCausalLM` fell back to `no_buffer`, which requires `--disable-overlap-schedule` and gives up the overlap throughput win.

  **Root cause:** `extra_buffer` prefix caching needs the intermediate SSM state `h` at chunk boundaries to be tracked so radix can restore a shared prefix. This was wired for GDN / Mamba2 but not for KDA, so the tracked prefix slots held stale/zero state and every prefix-reusing request restored a garbage SSM state.

  **Key point:** KDA's `chunk_kda_fwd` *already computes* the same per-chunk-boundary `h` as GDN's chunk kernel (`chunk_gated_delta_rule_fwd_h`) — it was simply discarded. So this fix is **pure plumbing: no new or modified Triton kernel.**


## Modifications

 - **`fla/kda.py`** — `chunk_kda_fwd` / `chunk_kda` gain `output_intermediate_states`; return `(o, h)` when set, else `o` unchanged.
  - **`kernels/kda_triton.py`** — `TritonKDAKernel.extend` threads the flag and returns `(core_attn_out, h)`.
  - **`kernels/kda_cutedsl.py` / `kernels/kda_flashkda.py`** — assert-guard the flag, since the fused kernels do not expose `h` (`extra_buffer` forces the Triton prefill path anyway).
  - **`kda_backend.py`** —
    - store the **transposed** `conv_states_shape` (KDA's raw `conv[0]` is `(slots, K-1, channel)` vs GDN's `(slots, channel, K-1)`), so the shared `_init_track_conv_indices` reads `[-1] == K-1` as the window length;
    - set the track / mask indices in an `init_forward_metadata` override (mirrors GDN);
    - in `forward_extend`, snapshot the pre-conv window into the transposed `conv[0].transpose(-1, -2)` view and track the intermediate SSM state via `_track_mamba_state_extend`.
  - **`arg_groups/overrides.py`** — whitelist `KimiLinearForCausalLM` for `extra_buffer` (gated on `linear_attn_backend == "triton"`).
  - **`test/registered/unit/layers/test_kda_extra_buffer_conv_track.py`** — new CPU unit test asserting the KDA transposed-view conv snapshot is bit-identical to a native GDN `(slots, channel, K-1)` snapshot (track + restore parity).

## Accuracy Tests

**CPU unit test:** 4/4 pass.

  **E2E** on `Kimi-Linear-48B-A3B-Instruct` (TP=2, GSM8K 5-shot, 1319 questions, radix + CUDA graph on, no speculative decoding):

  | Mode | Overlap schedule | Accuracy | Latency |
  |------|------------------|----------|---------|
  | `no_buffer` (baseline) | forced **off** | 0.892 | 97.5 s |
  | `extra_buffer` (this PR) | **on** | **0.900** | **87.4 s** |

  `extra_buffer` now **matches** `no_buffer` accuracy (the 0.63 regression is gone) and runs **~10% faster** by keeping the overlap schedule enabled.
