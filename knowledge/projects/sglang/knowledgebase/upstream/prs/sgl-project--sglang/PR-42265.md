# [Kimi-K3] Piecewise prefill CUDA graphs: run MLA attention as one eager break

[Upstream PR](https://github.com/sgl-project/sglang/pull/42265) · state: open · merged: False

## Original PR description

## Motivation

Prefill CUDA graphs don't pay off for Kimi-K3 today. Under a captured prefill graph (`--cuda-graph-backend-prefill breakable`), `handle_attention_trtllm_mla` pins MLA to the absorbed path, because MHA's shapes vary with the cached KV length. On agentic turns (a few thousand new tokens over a ~100K-token cached prefix) absorbed MLA does ~3.4× the attention FLOPs of MHA, and the breakable runner also never plans DCP metadata. Even with the DCP metadata fixed, breakable prefill graphs ran 6.1% slower than eager on InferenceX AgentX.

## Modifications

Split the graph at attention, as vLLM's piecewise graphs do:

- `kimi_k3.py`: inside a prefill breakable graph, each MLA layer's `self_attn` runs as one `eager_on_graph` break on the live batch with the graph flags suspended, so it takes the same MHA path as eager. KDA cores stay breaks; norms, projections and MoE replay from the graph.
- `prefill_cuda_graph_runner.py`: plans DCP metadata at capture and on every replay, and hands the unpadded live batch to the break.

Defaults are unchanged; enable with `--cuda-graph-backend-prefill breakable --cuda-graph-bs-prefill ...`.

## Benchmark (Kimi-K3, 8×B300, TP 8 + DCP 8)

Graph buckets of 64–8,192 tokens; the eager baseline ran right after on the same node.

| | Eager | This PR |
|---|---|---|
| Prefill, 326 new tokens on a 79K cached prefix | 0.543 s | 0.272 s (−50%) |
| Prefill, 4,294 new tokens on a 79K cached prefix | 0.550 s | 0.394 s (−28%) |
| Prefill, 547 tokens, no prefix | 0.508 s | 0.246 s (−52%) |
| InferenceX AgentX throughput per GPU (concurrency 48) | 10,480 tok/s | 11,654 tok/s (+11.2%) |
| AgentX TTFT median / p90 | 1.51 / 3.32 s | 1.07 / 2.59 s (−29% / −22%) |
