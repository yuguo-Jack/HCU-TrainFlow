## Motivation

Inside the KV storage package, a few modules imported a layer above their own (memory and the plan importing the storage or the router, the storage importing `mem_cache.common`, the chain allocator borrowing the static sliding-window allocator's invariants), and consumers reached a unified pool's storage as an attribute of its allocator and branched on whether it was there. This PR makes the package import downward only and gives every consumer the pool's storage directly.

## Modifications

- Import order: `Region`, `KV_PART` and `STATE_PART` move to the declarations (`mem_cache/kv/decl.py`); window retirement (`retire_window_rows`, which now requires the window's sub-pool) and `coalesce_ranges` move from `mem_cache.common` into `mem_cache/kv/advance.py`; the chain allocator imports the allocation kernels from the kernels package and owns its window segment invariants (`kv/alloc/invariants.py`).
- Storage, not the allocator's attribute: the static storage answers the move-safety recording calls (`record_forward`, `retire_forward`, `record_host_transfer`, `record_network_transfer`) as no-ops, since static pools never move a row; the scheduler, PD transfer helpers, KV checksum and prefix-cache restore go through `kv_storage_of`, and their `storage is None` branches are removed. The chain is told at construction what it read through its storage (the plan, the request rows' memory, each window's kept tail).
- HiCache through the storage interface: `managers/cache_controller.py` and `mem_cache/hybrid_cache/hybrid_cache_controller.py` take the unified pool's `kv_storage`, record host copies on it and end load reservations once a load is submitted (`KVStorage.end_load_reservations`); the attach path finds the storage with `kv_storage_of`; `set_hicache_transfer_done_event` is removed.
- Tests: `test/registered/unit/mem_cache/kv/test_import_order.py` parses the package and fails on any upward import outside a listed set (the static pools' per-family classes); transfer bookkeeping, move-gate and HiCache tests updated.

**Known limitation:** a HiCache load takes its FULL rows from the owner band directly (`KVStorage.owner_load_alloc`), not through the chain planner, so when the band cannot serve them the load is skipped and the host hit is lost. Routing these takes through the planner is left for a follow-up.

No other behavior change.
