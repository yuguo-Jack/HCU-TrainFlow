# [Refactor] memory-pool: Bind HiCache entries to device pools by name

[Upstream PR](https://github.com/sgl-project/sglang/pull/48137) · state: open · merged: False

## Original PR description

## Motivation

Followup of #48136. Host assembly still reached into wrapper pools by attribute name to find the device pool each host entry transfers through: `c4_kv_pool`, `c4_indexer_kv_pool`, `c128_kv_pool` and `swa_kv_pool` for DeepSeek-V4, `full_kv_pool` and `swa_kv_pool` for hybrid SWA and its drafts, and `main_pool` and `index_k_pool` for MiniMax sparse. This PR lets each pool report that binding next to its infos, so assembly no longer knows the wrapper layouts.

## Modifications

- `KVCache.device_pools_by_name` maps every described pool name to the device pool its transfers and allocation bind to. Plain pools bind to themselves. `SWAKVPool`, `DeepSeekV4TokenToKVPool` and `MiniMaxSparseKVPool` bind to their sub-pools, and DeepSeek-V4 compressor states bind to none. Infos stay plain buffer facts and never hold a pool.
- `MiniMaxSparseKVPool.get_device_pool_infos` reports the sparse KV and its K-only index.
- The DeepSeek-V4, hybrid SWA, hybrid Mamba SWA, MiniMax sparse and draft SWA builders bind entries through it, and MTP draft selection reads the drafts' infos.

## Accuracy

Same KL and host probe as #48136 on all ten assembly paths including DeepSeek-V4 with MTP, MiniMax bf16 and NVFP4 and QSA. Results are identical to #48136.
