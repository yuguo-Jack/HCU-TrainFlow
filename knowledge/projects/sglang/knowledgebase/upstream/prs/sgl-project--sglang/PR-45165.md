# [Fix] speculative: Reject PP rejection sampling at startup

[Upstream PR](https://github.com/sgl-project/sglang/pull/45165) · state: open · merged: False

## Original PR description

## Motivation

Pipeline-parallel EAGLE/MTP currently rebuilds `EagleVerifyInput` from the PP relay, which does not carry the target-vocabulary draft proposal distribution. Enabling rejection sampling therefore passes startup but fails on the first sampled request when verification finds `draft_probs` missing. Block verification implicitly enables the same rejection path.

Fixes #45162.

## Modifications

- Reject PP + EAGLE-family rejection sampling during `ServerArgs` resolution, before model loading or request handling.
- Let the same guard cover block verification after its implicit rejection-sampling resolution and `NEXTN` after alias resolution.
- Preserve PP greedy verification, single-stage rejection/block verification, and the independent DSPARK PD-prefill path.
- Keep HIP auto-enable semantics intact: a simulated HIP PP configuration now fails explicitly instead of silently falling back to greedy sampling behavior.

This is a fail-fast compatibility check. It does not add rejection-sampling support to the PP relay or change sampling behavior for supported configurations.

## Accuracy Tests

Not applicable. The change rejects an unsupported configuration during argument resolution and does not modify model outputs for valid configurations.

The focused test uses a local minimal Llama config and the real `ServerArgs.resolve_once()` pipeline. Against unmodified `main`, the new cases fail because no error is raised; with this patch they pass.
