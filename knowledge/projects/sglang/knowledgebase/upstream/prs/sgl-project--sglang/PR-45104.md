# [Fix] hisparse: Copy DeepSeek-V4 eager backups token by token

[Upstream PR](https://github.com/sgl-project/sglang/pull/45104) · state: closed · merged: True

## Original PR description

## Motivation

With DeepSeek-V4 and `--enable-hisparse`, each decode step backs up the compressed C4 token that every active request produced in the previous step (`HiSparseCoordinator._eager_backup_previous_token`). That gives one scattered token per request. The tokens go through `DeepSeekV4PagedHostPool.backup_from_device_all_layer`, which chooses its whole-page path purely by count: `numel % slot_page_size == 0`. When exactly 64·k requests back up on the same step, it takes every 64th index as a page id and copies whole pages:

- 63 of the 64 tokens are never backed up, so a later swap-in reads stale host data;
- the host page of each 64th request is overwritten with an unrelated device page.

Both are silent. A batch of equal-length requests at concurrency 64, 128 or 256 hits this on every fourth decode step.

## Modifications

- `DeepSeekV4PagedHostPool.backup_tokens_from_device_all_layer`: copies individual C4 tokens with the existing `transfer_cache_dsv4_mla` path. `backup_from_device_all_layer` now calls it for its unaligned branch instead of carrying a second copy.
- The eager backup calls the token copy explicitly for DSV4, so the token count no longer selects the copy granularity. Staging and preload still copy one request's contiguous pages and keep the page path. The DSA host pool (`MLATokenToKVPoolHost`, layer_first) already copies per token and is unchanged.

## Tests

- Keep one focused regression: `TestDSV4HiSparseEagerBackup::test_page_sized_batch_uses_token_copy` in `test_hisparse_unit.py`. It invokes the real eager-backup method for 64 requests with scattered C4 locations, checks that all host/device indices reach the token-copy interface, and rejects calls to the page-copy interface. The host pool is mocked; model pools, a distributed process group, and a second reference cache are unnecessary for this dispatch regression.
- The existing token-copy kernel is unchanged. This test checks dispatch and indices, not copied bytes.
- Validation for the test simplification: Python syntax, formatting, lint, and pre-commit checks. The revised CUDA test has not been run locally.
- Previous revision `a9e454784d` reported 70 passed and 10 skipped across the related HiSparse/host-pool suites on one GPU, including a real-copy negative control. Those results predate this test simplification.
