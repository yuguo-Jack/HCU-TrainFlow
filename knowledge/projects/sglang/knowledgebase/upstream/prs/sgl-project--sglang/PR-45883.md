# [Feat] rust/grpc: Honor --grpc-response-timeout-secs in the Rust server

[Upstream PR](https://github.com/sgl-project/sglang/pull/45883) · state: open · merged: False

## Original PR description


## Motivation

The Rust server's gRPC adapter waits a fixed 300 seconds for each call's next response event and ignores `--grpc-response-timeout-secs`. This PR allows the timeout to be explicitly configured.

## Modifications

- The Rust `ServerArgs` gains `grpc_response_timeout_secs`.
- `_build_server_args` forwards the resolved server arg.
- `GrpcService` uses it in place of the 300 s constant, for `Generate`'s per-event wait and for `Detokenize`, as the Python bridge applies it to every RPC.
- A value of `0` falls back to the 300 s default with a warning, Python's argument validation already rejects non-positive values.
