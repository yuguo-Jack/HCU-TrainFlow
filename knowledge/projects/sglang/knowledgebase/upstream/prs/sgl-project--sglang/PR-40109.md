# [Bugfix] Reject unsupported GLM-5.3 prefill CP

[Upstream PR](https://github.com/sgl-project/sglang/pull/40109) · state: closed · merged: False

## Original PR description

## Motivation

GLM-5.3-Flash currently constructs the regular layer communicator, but the generic DSA context-parallel detection still allows `--enable-prefill-cp` to start. With Triton KDA, rank-local token tensors are then consumed with global sequence metadata and the worker can fail later with a CUDA illegal memory access.

Fail at model initialization instead of launching an unsupported configuration and surfacing the error asynchronously through the NCCL watchdog.

## Modifications

- Reject GLM-5.3-Flash startup when prefill context parallelism is enabled.
- Tell users to remove `--enable-prefill-cp` until model-specific CP support is implemented.
