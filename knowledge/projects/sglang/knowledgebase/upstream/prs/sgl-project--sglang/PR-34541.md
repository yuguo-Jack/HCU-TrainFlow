# fix: honor effective committed KV length in external caches

[Upstream PR](https://github.com/sgl-project/sglang/pull/34541) · state: closed · merged: False

## Motivation
Fixes #34539.

When `--strip-thinking-cache` is enabled for a request containing reasoning tokens, the common KV release path passes the prompt-only effective committed length through `kv_len_to_handle`.

The regular radix cache honors this boundary, but the LMCache and FlexKV store paths recomputed their lengths from the request's original committed state. This could make the external cache store thinking and answer KV that should have been discarded.

Because the common path releases the KV slots beyond the effective committed length after `cache_finished_req()` returns, an asynchronous external store could also read slots after they had been released or reused.

<!-- Describe the purpose and goals of this pull request. -->

## Modifications
- Cap the LMCache store length by `kv_len_to_handle`.
- Cap the FlexKV store length by `kv_len_to_handle`.
- Preserve the existing `speculative_eagle_topk > 1` length calculation and apply the effective length only as its upper bound.
- Add a CPU-only regression test covering both external-cache backends.
- Stub the optional LMCache and FlexKV dependencies so the test does not require either package or a GPU.

The effective store length is now computed as:

```python
kv_committed_len = min(kv_committed_len, kv_len_to_handle)
```
