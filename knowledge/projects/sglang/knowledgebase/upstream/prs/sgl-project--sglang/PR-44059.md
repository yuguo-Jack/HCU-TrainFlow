# [Perf] Beam search: drop the per-step blocking index copy in logits c…

[Upstream PR](https://github.com/sgl-project/sglang/pull/44059) · state: closed · merged: False

## Original PR description

…apture

capture_pre_sample_logits indexed the leader rows with a python list (logits[leader_rows]). PyTorch stages such an index as an 8B pageable H2D copy that synchronizes with the pending forward, so the host blocked in cudaStreamSynchronize for ~3.2ms on every decode step and the overlap scheduler could not run ahead of the GPU.

append_beam_tail already materializes those indices on device; keep them on BeamTail and use index_select, which also produces the clone the caller needs (the sampler rewrites next_token_logits in place).

nsys, Qwen3-0.6B, 1 request / 16 new tokens, H100, decode step interval:
  beam_width=20 : 7.9ms -> 4.9ms
  beam_width=100: 11.4ms -> 7.5ms
Beam scores and texts are unchanged.
