> Integration after kernel slices #44817, #44818, #44819, #44820, #44821, #44822. Review the last 4 commits: `6df63d7ce6`, `1a1be676eb`, `0711869f48`, `13db6c0571` (642 lines). Compare: https://github.com/yuychang/sglang/compare/up/b5f-latent-tail-adapter...up/b5-fp8-moe-front-tail


## AITER prerequisites

None. This kernel is compiled from the SGLang tree. It only imports AITER FlyDSL helpers that are already on AITER main. [ROCm/aiter#6026](https://github.com/ROCm/aiter/pull/6026) is not used: the measured recipe compiles the vendored kernel (`SGLANG_OPT_HIP_K3_FLYDSL_SOURCE=sglang`).

## Motivation

Before routing, Kimi-K3 runs three projections on the same hidden state: the router, the latent down projection and the shared expert. After the experts it runs a residual add, RMSNorm and the latent up projection. At small decode batches each is a separate small launch.

## Modifications

Kernel slices: #44817, #44818, #44819, #44820, #44821, #44822.

**`6df63d7ce6` add QuarkW4A4MXFP4.materialize_bf16_weight**
- Return a dense BF16 copy of an MXFP4 dense linear's weight without changing the layer.
- Let models build their own decode-side weight caches from Quark MXFP4 linears.

**`1a1be676eb` run the ROCm MoE front through the FP8 pre-route and latent tail kernels**
- Add forward_fused_rocm, the ROCm counterpart of the fused [latent | shared] MoE path, in kimi_k3_rocm_moe.py.
- Merge only the router and latent projections when Quark leaves the shared experts quantized.
- Build FP8 pre-route weights from Quark MXFP4 shared experts through materialize_bf16_weight.
- Run the router, latent down and shared gate-up as one FP8 launch for 1 to 4 tokens, and the shared down as another.
- Fuse the latent RMSNorm, up-projection and residual add for 1, 2 or 4 tokens.
- Run the quantized shared down-projection through its own kernel when the activated input skips the FP8 path.
- Gate it behind SGLANG_OPT_HIP_K3_MOE_PREROUTE_FP8 and SGLANG_OPT_HIP_K3_LATENT_TAIL_FP8, off by default.
- Document the switches.

**`0711869f48` drop a per-layer bias cast and the MoE output scratch on ROCm**
- Store the MoE correction bias in the gate-logit dtype at load when AITER routes, so topk stops casting it every call.
- Write the final MoE three-way add into the up-projection output on ROCm instead of a fresh [M, D] tensor.
- Neither changes the computed values.

**`13db6c0571` make the ROCm latent MoE tail token count a runtime argument and use it in speculative verify**
- Make the token count a runtime argument of the latent-tail kernel, with token tiles of 1, 2, 4 and 8, up to 256.
- Use the fused tail for decode and verify batches up to SGLANG_OPT_HIP_K3_LATENT_TAIL_MAX_TOKENS, default 4.
- Default to 4 because 32 served slower on MI355X: 8K/1K at 8-32 requests, DSpark AgentX at 4 and 48.
- Reject a ceiling outside the kernel range at load instead of clamping it.
- Test every token tile with a residual prefix and document the ceiling.

Switch: `SGLANG_OPT_HIP_K3_MOE_PREROUTE_FP8`, `SGLANG_OPT_HIP_K3_PREROUTE_PREACTIVATED_SHARED`, `SGLANG_OPT_HIP_K3_LATENT_TAIL_FP8` (ceiling `SGLANG_OPT_HIP_K3_LATENT_TAIL_MAX_TOKENS=4`). Everything is ROCm only; CUDA and other checkpoints keep the existing path.

Each FlyDSL kernel builder stays one function, because it is one kernel construction.
