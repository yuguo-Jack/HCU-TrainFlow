# [Feat] pd: Place prefill sessions by projected per-rank token load

[Upstream PR](https://github.com/sgl-project/sglang/pull/48098) · state: open · merged: False

## Original PR description

## Motivation

A long conversation can be sent to a different prefill DP rank on its next turn even when its previous prefix is still resident. In the original 300 s first-token control, all 12 timeouts changed P shard. Seventeen successful requests changed shard too. This PR makes session reuse an explicit placement policy.

## Modifications

- Add the opt-in `--load-balance-method prefill_session_tokens` for a PD prefill engine. Place new sessions using estimated prompt/output footprint, live token load and per-rank KV capacity. Planning slots are advisory and fall back to projected load when full.
- Prefer the session’s active rank on later turns, honor explicit rank overrides, and bound the reservation history by time and size. Native KV admission still owns allocation. Existing load-balancing policies keep their behavior.

## Speed Tests and Profiling

In both candidate replays all **48/48** adjacent formal-turn pairs stayed on the same P rank, versus **8/48** and **12/48** in the controls. Uncached prompt tokens per replay fell from **5.10–5.11 million** to **136,571–138,224**. P H2D volume increased to **319.64–328.35 GiB**. Against the mean of both controls, mean TTFT fell **90.7%** and aggregate output throughput rose **9.42×**. D decoding slowed as more requests decoded concurrently, with unchanged D code and settings. [Placement microbenchmark](https://github.com/INBreezefall/sglang/tree/682f1c33931c4b8c0ab11df9d0236d00ff06fcfb/benchmark/ascend_a2_pd_evidence).

GLM-5.2 W4A8C8 ran on four hosts with eight Ascend 910B4-1 NPUs each, CANN 9.1.0 and torch-npu 2.10.0.post6. P and D each used TP16 and attention DP8. Every arm used SGLang `40a64e1b5ba0` with the same A2 C8 / Mooncake compatibility fixes. Each row contains all 72 responses from the same 24 sessions × three closed-loop turns, after 24 warm-ups. Temperature was 0, output was capped at 256 tokens, and retries were disabled.

| Arm | Mean TTFT (s) | P95 TTFT (s) | Client decode (tok/s per request, valid n/72) | D decode (tok/s) | Output TPS (tok/s) |

Client decode averages valid semantic streaming spans. The PD relay can buffer output. D decode is the inverse of token-weighted server ITL, covering every post-first token interval. Output TPS counts actual output tokens over the formal wall window. The complete comparison allowed 1,200 s for the first token and 300 s between subsequent events. A separate original 300 s control completed 38 of 50 attempted requests before its stop policy withheld 22. [Protocol and anonymized per-request results](https://github.com/INBreezefall/sglang/tree/26bc7bdac9a4158319a7d3d8e3cd10218072bb05/benchmark/ascend_a2_pd_evidence/c24).
