# [Test] scheduler: Reset the published context after each prefill-adder test

[Upstream PR](https://github.com/sgl-project/sglang/pull/45766) · state: open · merged: False

## Original PR description

## What breaks

`TestPrefillAdder.setUp` publishes a process-wide scheduler config:

```python
set_global_server_args_for_scheduler(ServerArgs(model_path="dummy"))  # tp_size=1
```

It is never torn down. pytest shares one process across test files, so every later
test that scopes `get_parallel().override(...)` is cross-checked against that stale
bag by `_validate_parallel` and dies on the width equation:

```
ValueError: parallel topology is inconsistent (set by override):
tp_size == attn_tp_size * attn_dp_size * attn_cp_size
  1 != 4 * 1 * 1 (= 4)
```

Reproduced on the unmodified `lmsysorg/sglang:v0.5.22` image with two upstream files:

```bash
python -m pytest -q \
  test/registered/unit/managers/test_prefill_adder.py \
  test/registered/unit/model_executor/test_num_token_non_padded_localization.py
# 27 failed, 59 passed, 68 subtests passed
```

Every failure is a subtest of `test_num_token_non_padded_localization.py`
(`TP4`, `TP4.SP4`, `TP2.DP2.SP2`, ...). Each file passes on its own.

## Fix

Register `reset_context()` right after the publish. `addCleanup` runs LIFO, so the
per-test `override_server_args().restore()` callbacks registered later still run
first — reversing the order would resurrect the leaked bag and silently reintroduce
the bug.

```diff
-from sglang.srt.runtime_context import get_context
+from sglang.srt.runtime_context import get_context, reset_context
...
         set_global_server_args_for_scheduler(ServerArgs(model_path="dummy"))
+        self.addCleanup(reset_context)
         self.mock_tree_cache = self.create_tree_cache()
```

## Verification

Same two-file command after the patch, on the same image:

```
59 passed, 95 subtests passed
```

`reset_context()` has no production callers (`srt/` never calls it); this only
restores the isolation the test file assumed.

## Scope

Test-only. `self.addCleanup(reset_context)` is the established pattern in the tree
(`test/registered/unit/test_pre_publish_readers.py`, `unit/models/test_qwen3_vl_*`,
`unit/model_executor/model_runner_components/test_startup_weight_load.py`, ...).
A full single-process `test/registered` run still has other publishers that never
reset; this PR fixes the one that breaks the `unit/` subtree.
