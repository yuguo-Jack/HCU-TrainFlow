# [feat]support_init_random_mtp

[Upstream PR](https://github.com/sgl-project/sglang/pull/23147) · state: open · merged: False

## Original PR description

## Summary

Adds draft-model support for attaching a **randomly-initialized MTP head** to a dense Qwen3 model during RL training, so the MTP head can be trained from scratch alongside the main model and speculative decoding quality improves over time.

Paired with the miles-side changes in radixark/miles.

## Changes

- **New** `python/sglang/srt/models/qwen3_mtp.py` — `Qwen3ForCausalLMMTP` draft architecture (fc + pre_fc_norm_{embedding,hidden} + 1 Qwen3 decoder layer), modelled on `qwen3_next_mtp.py` / `qwen3_5_mtp.py`.
- **model_config.py** — remap `Qwen3ForCausalLM` → `Qwen3ForCausalLMMTP` when `is_draft_model` is true (mirrors the existing Qwen3Next / Qwen3_5 entries).
- **models/qwen3.py** — target `load_weights` skips `"mtp"` tensors so the Megatron weight-sync broadcast doesn't `KeyError` on MTP params that belong to the draft, not the target.
- **scheduler_update_weights_mixin.py** — `update_weights_from_distributed` now routes through `self.draft_worker` when one exists, matching the tensor-path behaviour. Previously only the colocated tensor path reached the MTP draft in disaggregated setups.
- **speculative/eagle_worker{,_v2}.py**, **multi_layer_eagle_worker{,_v2}.py** — add `update_weights_from_distributed` / `update_weights_from_tensor` so both target and draft/MTP runners receive broadcasts.

## Test plan

- [ ] Unit: `Qwen3ForCausalLMMTP` loads a dense Qwen3-4B HF config + injected `num_nextn_predict_layers=1` without triggering the `PP is not compatible with MTP models` assertion.
- [ ] E2E with miles `--init-random-mtp` on Qwen3-4B: training starts from `accept_rate ≈ 0.33` baseline and climbs as MTP loss drops.
