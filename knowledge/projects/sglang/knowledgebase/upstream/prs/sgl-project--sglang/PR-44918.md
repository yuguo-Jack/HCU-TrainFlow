# [Perf] DeepSeek-V4.1: capture the vision encoder in CUDA graphs per image grid

[Upstream PR](https://github.com/sgl-project/sglang/pull/44918) · state: open · merged: False

## Original PR description

## Motivation

The DeepSeek-V4.1 vision encoder (32-layer ViT + aligner) runs replicated on every TP rank and is host-bound:
hundreds of small launches per image, a host-to-device copy of the rotary tables and `cu_seqlens` per call, and
four boolean-mask writes that each sync the host while the image span is assembled. Host jitter on one rank then
becomes collective wait on the other ranks in the first LM layer after the encoder. In a TP4 trace of a
768x1024 image, rank 0 spent about 30 ms in that all-reduce, longer than the encoder itself.

## Modifications

- `DeepseekV41ViTCudaGraphRunner` (new, `multimodal/deepseek_v41_vit_cuda_graph_runner.py`) replays vision
  tower + aligner + span assembly as one graph per `(n_vit_h, n_vit_w)` grid.
  - On by default on CUDA and ROCm; off with `--disable-cuda-graph`. No new server args or env vars.
  - A grid is captured on its second sighting, so one-off sizes stay eager and pay no capture cost.
  - At most 16 grids are kept (LRU); graphs share one private memory pool.
  - A capture that fails is logged once and that grid stays eager.
  - Capture uses `capture_error_mode="thread_local"`, since other threads keep issuing CUDA calls.
  - The returned span is cloned, because spans live on in the multimodal embedding cache.
- `assemble_image_span` builds `[start] + ([features] * w + [newline]) * h + [end]` with two `cat`s instead of
  four boolean-mask writes. It produces the same layout as `image_token_types` (bit-exact, unit-tested) with no
  host sync. The eager path uses it as well.
- Rotary tables and attention metadata are cached on device per grid (`get_vision_inputs`), so neither path
  copies them per call, and the graph never records a host-to-device copy.

## Accuracy Tests

The graph replays the same kernels as the eager path, so outputs are bit-exact with eager on the tested grids.

| MMMU (TP4, MI350X) | Score |
|---|---|
| main | 0.7539 |
| this change | 0.7678 (n=1) |

The difference is within run-to-run noise of the end-to-end eval (batch composition varies between runs).

## Speed Tests and Profiling

DeepSeek-V4.1-Flash, TP4, MI350X, `bench_serve` with `sglang-oai-chat`, one random image per request, sizes
512x512 / 768x1024 / 2048x1600. Measured with a prototype of this change that has the same graph scope (tower +
aligner + span, per-grid capture). Relative to main:

| | Change vs main |
|---|---|
| Median TTFT, 5 rows (c4–c64) | 16–31% lower |
| Rank-0 all-reduce after the encoder (768x1024) | 30.5 ms → 2.9 ms |
| Encoder time alone, one GPU (1521 / 4070 / 8343 patches) | −16% / −3% / −3% |
| Capture time per grid | ≤ 230 ms |
| Graph pool per grid | ≤ 0.6 GiB |

Most of the end-to-end gain comes from removing rank-to-rank skew rather than from the encoder getting faster
on one GPU.
