# [Fix] benchmark: Skip malformed custom JSONL records

[Upstream PR](https://github.com/sgl-project/sglang/pull/47407) · state: open · merged: False

## Original PR description

## Motivation

The custom JSONL benchmark loader skips invalid JSON syntax, but assumes that every successfully decoded record is a dictionary containing a list of text turns. A file containing `null` followed by a valid conversation therefore raises `AttributeError` before it can sample the valid record. Invalid conversation containers, turns, or text values also raise during loading or tokenization.

## Modifications

- Skip records that are not dictionaries, conversation fields that are not lists with at least two turns, non-dictionary turns, and non-string prompt/completion values.
- Preserve the existing `conversations`/`conversation` and `content`/`value` aliases, filtering, token accounting, and chat-template behavior.
- Add regression coverage to the existing CPU-registered benchmark dataset test suite, using temporary JSONL files and the real local tokenizer.

## Accuracy Tests

```bash
PYTHONPATH=python python -m pytest test/registered/bench_fn/test_benchmark_datasets_api.py -q
```

48 tests and 80 subtests pass on CPU (Python 3.12.15, PyTorch 2.14.1+cpu, Transformers 5.19.0, tokenizers 0.23.2). Before the loader fix, 70 malformed-record subtests failed on main at `8fd181eaf4137b0ba52de8f3a34095f1933b3bc7`. The regression requests two rows from each invalid/valid pair, so shuffling cannot hide an invalid record behind the request limit.
