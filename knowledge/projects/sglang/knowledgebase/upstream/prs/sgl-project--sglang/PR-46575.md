# [Fix] k2_v3: Treat both Optional spellings alike when coercing arguments

[Upstream PR](https://github.com/sgl-project/sglang/pull/46575) · state: open · merged: False

## Original PR description

## Motivation

`Optional[str]` can be written in two equivalent schema spellings, and `K2V3Detector` gets a different case wrong for each:

| schema | untyped XML value `123` | explicit null (JSON `null`, or `arg_type` `null`) |
|---|---|---|
| `{"anyOf": [{"type": "string"}, {"type": "null"}]}` (Pydantic's default for `Optional[str]`) | `123` (int), expected `"123"` | `null` (correct) |
| `{"type": ["string", "null"]}` | `"123"` (correct) | `"null"` (string), expected `null` |

Causes:
- `_argument_type` returns `None` for any `anyOf`/`oneOf`, so the value falls through to best-effort `json.loads`. The `type`-list path already narrows `[X, "null"]` to `X`.
- `_coerce_value` coerces an explicit null to the schema type. For `string` this means `json.dumps(None)`, which gives `"null"`.

## Modifications

- `_argument_type`: an `anyOf`/`oneOf` with exactly one non-null branch (after resolving local `$ref`) uses that branch's type, matching the `type`-list handling. Real multi-branch unions still return `None`, so the wire `arg_type` keeps precedence. `test_xml_typed_union_uses_wire_value_type` is unchanged and still passes.
- `_coerce_value`: an explicit null (JSON `null` or `arg_type` `null`) is returned as `None` before any schema coercion.
- Added `test_optional_string_keeps_text_and_null` to `test_k2_v3_detector.py`. All three sub-cases fail on current main.
