# [Perf] diffusion: Map local array spills instead of copying them

[Upstream PR](https://github.com/sgl-project/sglang/pull/46436) · state: closed · merged: False

## Original PR description

## Motivation

Large local diffusion replies are spilled to a private `.npy` file in the request's shared-memory directory. When the client materializes the reply, `NumpyArrayFileRef.materialize` calls `np.load`, which reads the whole payload into a second host allocation before the file is unlinked. A 124-frame 1344x768 video reply carries about 1.54 GB of FP32 data through this path.

## Modifications

- `NumpyArrayFileRef.materialize` loads the spill with `mmap_mode="c"` and returns a plain `np.ndarray` view over the mapping. Pages are read when the consumer touches them instead of up front.
- The mapping outlives the unlink that follows and the request-directory cleanup. Copy-on-write keeps the returned array writable without modifying the file.
- Trade-off: a retained reply keeps its spill storage and one mapping alive until the last view is released, instead of owning an independent allocation.

## Accuracy Tests

No numerical change: the returned array holds the same bytes as before. `test_materialized_spill_is_a_writable_mapping` checks that the result is backed by a mapping, that the spill file is removed, and that writes to the result work without changing the other values.

## Speed Tests and Profiling

The end-to-end effect is small. The one-line form has not been benchmarked on a model. An earlier, larger variant of the same idea (a writable mapping with free-space and descriptor guards) was measured on H200 with a 124-frame video model (one warmup, then three 50-step requests per variant, at `49933325`):

| Stage | Before | After |
|---|---:|---:|
| Client reply materialization | ~0.59 s | ~0.0005 s |
| Client uint8 conversion (full pass over the data) | 0.34 s | 0.34 s |
| Whole request, generate call to host media | 304.746 s | 303.973 s |

The producer side (writing the spill) is unchanged.

- niehen6174 · comment · 2026-10-31T05:42:42Z · [source](https://github.com/sgl-project/sglang/pull/46436#issuecomment-6539687574)

Closing. The spill path this maps is not on the HTTP image or video path: images return encoded bytes, and videos are saved on the worker.

On the offline array path, measured on B200 together with #46439, almost all of the gain came from quantizing before the copy. Once replies are uint8, the copy this PR avoids is about a quarter of the size, worth tens of milliseconds.

There is also a cost. A retained result now keeps its pages in `/dev/shm` instead of anonymous memory until it is released. That adds up for callers that hold large results, such as RL buffers, and an in-place write duplicates the touched pages.
