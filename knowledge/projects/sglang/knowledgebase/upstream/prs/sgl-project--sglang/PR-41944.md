# [Perf] [XPU] diffusion: Avoid QKV copies in flash attention

[Upstream PR](https://github.com/sgl-project/sglang/pull/41944) · state: open · merged: False

## Original PR description

## Motivation

`XPUAttentionImpl.forward` called `.contiguous()` on q, k and v before every
flash-attention call:

```python
q_ = query.contiguous().reshape(bsz * seqlen_q, nheads_q, d)
k_ = key.contiguous().reshape(bsz * seqlen_k, nheads_k, d)
v_ = value.contiguous().reshape(bsz * seqlen_k, nheads_k, d)
```

In FLUX.2's single-stream blocks q/k/v are head-packed, row-strided *slices* of
one fused projection output (`[tokens, 13824]` = `q | k | v | mlp`), so each
`.contiguous()` materialised a fresh `[tokens, heads, 128]` tensor — 3 copies
per block, 144 per DiT forward, 8.8 ms of profiled device time.

The sgl-kernel-xpu flash-attention kernel reads rows through their stride, so
the copies are not needed.

## Modifications

`multimodal_gen/runtime/layers/attention/backends/xpu_backend.py`: new
`_as_fa_input` helper used for q, k and v. It passes the tensor through
untouched when the `[rows, heads, head_dim]` view is one the kernel can read
directly — unit last-dim stride, heads packed at `head_dim`, row stride a
multiple of 8, 16-byte-aligned base — and otherwise copies exactly as before.

This is XPU-only; no other backend is touched.

## Accuracy Tests

Kernel-level probe at the FLUX.2 shape (`[4608, 12, 128]`, token stride 13824):
output with strided q/k/v is `torch.equal` to output with contiguous inputs.
The same probe also confirms the kernel accepts a strided *output* buffer and
leaves neighbouring columns untouched (not used by this PR — see follow-up).

`test_flux2_xpu_norm_fusions.py::test_attention_reads_fused_projection_slices_in_place`
(added here): asserts `_as_fa_input` returns the input's own `data_ptr` for a
fused-projection slice, and that `XPUAttentionImpl.forward` gives a
`torch.equal` result for strided and contiguous inputs. The file is now 6 cases,
all passing on Arc Pro B70.

End to end: no bit-exact fallback warnings; images differ from the parent commit
only at oneCCL run-to-run noise level (see PR 2).

## Speed Tests and Profiling

End to end (FLUX.2-dev, 1024x1024, 8 steps, bf16, eager, warm, TP4 on 4x
Arc Pro B70), 2 runs per side:

| | denoise (8 steps) | per DiT forward |
|---|---|---|
| parent commit | 6.140 / 6.129 s | — |
| this commit | 6.077 / 6.095 s | **−6 ms (−0.8%)** |

torch.profiler: the 144 `aten::copy_` kernels per forward (8.8 ms) are gone.
Flash attention itself costs ~1.2 ms more per forward with strided reads, so the
net saving is smaller than the copies removed.
