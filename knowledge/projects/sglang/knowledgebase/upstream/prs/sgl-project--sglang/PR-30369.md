# Skip mamba middle chunks

[Upstream PR](https://github.com/sgl-project/sglang/pull/30369) · state: closed · merged: False

## Original PR description

# Motivation

In chunked-prefill mode, when a request’s prefill is split into multiple chunks, only the final chunk needs its mamba/SSM state tracked into the radix cache — the intermediate (“middle”) chunks’ mamba states will be overwritten by the final chunk anyway. However, the current code tracks mamba state for every prefill chunk, wasting memory and CPU cycles on ping-pong buffer allocations and radix cache tracking that are immediately discarded.

This PR skips mamba tracking for middle prefill chunks, reducing memory headroom requirements and avoiding unnecessary work during chunked prefill.

# Modifications

## `python/sglang/srt/managers/schedule_batch.py` — `_mamba_radix_cache_v2_req_prepare_for_extend`:
- Early-return a no-op `_MambaRadixCacheV2TrackEntry(track_mask=False, track_index=0, track_seqlen=-1)` when `req.inflight_middle_chunks > 0`, skipping all tracking/copying for middle chunks.

## `python/sglang/srt/mem_cache/common.py` — `alloc_req_slots`:
- For middle-chunk requests that have not yet allocated a ping-pong buffer (`req.mamba_ping_pong_track_buffer is None`), count only `MAMBA_STATE_PER_REQ_NO_CACHE` toward `mamba_state_needed` instead of the full factor (3× for prefix-cache mode). This avoids reserving ping-pong slots that won’t be used.

## `python/sglang/srt/mem_cache/memory_pool.py` — `HybridReqToTokenPool.alloc`:
- When `req.inflight_middle_chunks > 0` and `req.mamba_ping_pong_track_buffer is None`, skip `_alloc_ping_pong_buffer` and write `-1` into `req_index_to_mamba_ping_pong_track_buffer_mapping` for those request indices.
- When the final chunk later arrives (`inflight_middle_chunks == 0`), the ping-pong buffer is allocated normally and the mapping is updated.

## `test/registered/unit/managers/test_mamba_middle_chunk_tracking.py` — new unit tests:
- `test_middle_chunk_skips_mamba_tracking` — verifies `_mamba_radix_cache_v2_req_prepare_for_extend` returns `track_mask=False` for middle chunks.
- `test_final_chunk_still_tracks_mamba_state` — verifies final chunks still track normally.
- `test_middle_chunk_does_not_allocate_ping_pong_slots` — verifies alloc skips ping-pong allocation for middle chunks and writes `-1` to the mapping.
- `test_final_chunk_allocates_ping_pong_slots_after_middle_skip` — verifies the final chunk correctly allocates ping-pong buffers after a middle chunk skipped them.
- `test_middle_chunk_headroom_excludes_ping_pong_slots` — verifies `alloc_req_slots` uses reduced headroom for middle chunks.
- `test_final_chunk_headroom_keeps_ping_pong_slots` — verifies final chunks use full headroom.

File: `python/sglang/srt/mem_cache/common.py` · line 433

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

There are two potential `AttributeError` issues here:
1. `tree_cache` is typed as `BasePrefixCache | None` and can be `None`. Calling `tree_cache.supports_mamba()` directly will raise an `AttributeError` if it is `None`.
2. `req_to_token_pool` is typed as `ReqToTokenPool`, which does not have the `enable_mamba_extra_buffer` attribute (only `HybridReqToTokenPool` does). Accessing it directly will raise an `AttributeError` if a base `ReqToTokenPool` is passed.

We should add a `None` check for `tree_cache` and use `getattr` to safely access `enable_mamba_extra_buffer`.

```suggestion
            if (
                tree_cache is not None
                and tree_cache.supports_mamba()
                and getattr(req_to_token_pool, "enable_mamba_extra_buffer", False)
                and req.inflight_middle_chunks > 0
                and req.mamba_ping_pong_track_buffer is None
            ):
```
