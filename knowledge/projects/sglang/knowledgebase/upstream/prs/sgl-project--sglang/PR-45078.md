# [Perf] hicache hf3fs: Copy and submit per page in usrbio batch_write

[Upstream PR](https://github.com/sgl-project/sglang/pull/45078) · state: open · merged: False

## Original PR description

## Motivation

`Hf3fsUsrBioClient.batch_write` copied every page into the shm staging buffer, prepared all I/Os, and only then submitted once. So no write I/O could start until every page had been copied and prepared.

The write path also had two correctness issues:
- Results were read in prepare order, but 3FS returns completions in completion order.
- On a `wait()` timeout or error, the call returned with I/O still in flight. The next call could then overwrite a shm region or ring slot that was still in use.

## Modifications

All changes are in `hf3fs_usrbio_client.py`:
- `batch_write` now copies, prepares and submits each page in turn, so a page's I/O starts before the next page is copied. `check()` limits a batch to `entries` pages, so each page has its own ring slot and shm region.
- New `_wait_all`: maps results by `userdata` (the page index), and waits out every prepared I/O, through partial waits, `wait()` errors and past `client_timeout`, before returning.

`batch_read` is unchanged.

## Speed Tests and Profiling

**Setup:** standalone client benchmark (`bench_client.py`, not part of this PR) on a 3FS cluster. File size 2 GiB, 16 MiB pages, `numjobs=1`, `entries=8`, 3 warmup + 10 timed iterations. Baseline is this PR's parent commit. Base and PR runs were interleaved, 8 repeats each.

| | WRITE p50 (GiB/s), median of 8 | vs base |
|---|---:|---:|
| base | 2.92 | — |
| this PR | 5.33 | **1.82×** |

- This PR beat base in 8 of 8 paired repeats, by 1.39× to 2.41×.
- A single-run sweep over page size (1–16 MiB) × `entries` (2–32) found no slowdown beyond noise. 1–4 MiB pages still gained 1.2–2.1×.
- READ is unchanged.
