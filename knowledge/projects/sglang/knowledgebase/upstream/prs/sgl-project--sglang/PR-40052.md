# [Perf] [XPU] fp8: Optimize FP8 scale layouts

[Upstream PR](https://github.com/sgl-project/sglang/pull/40052) · state: open · merged: False

## Original PR description

## Motivation

Optimizes XPU FP8 linear by pre-materializing scale layouts during weight loading and enabling fused rowwise `scaled_mm` for channelwise FP8 weights when the input shape and scale layouts are supported.

FP8 linear layers using Torch scaled_mm may perform redundant scale-layout conversions during every forward pass. For block-wise FP8, the required transpose-contiguous layout can be materialized once after weight loading. For channelwise FP8, XPU supports fused rowwise scaled_mm, but the path requires per-token activation scaling and a [N, 1] weight-scale layout.

## Modifications

- Materialize scale layout during weight loading.
- Enable `use_per_token_if_dynamic` and fused rowwise scaled_mm.

## Accuracy Tests

test_xpu_fp8_linear.py

## Speed Tests and Profiling

N=K=1024:
Block-scale layout materialization reduced block FP8 scaled_mm latency by approximately 8.7% to 10.0% across M=1, 8, 128.
Fused rowwise scaled_mm reduced latency by approximately:
  26.9% at M=8
  26.7% at M=128
