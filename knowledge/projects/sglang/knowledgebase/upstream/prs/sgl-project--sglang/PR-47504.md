# [CI] [AMD] mi355x: Clean up interrupted nightly jobs and reduce runner disk usage

[Upstream PR](https://github.com/sgl-project/sglang/pull/47504) · state: closed · merged: True

## Original PR description

## What

Clean up interrupted MI355X disaggregation jobs and reduce the logs kept on the runner.

- On launcher exit or INT/TERM, remove the job's detached containers and cancel its Slurm allocation. At the next job's start, also remove containers from this runner's stale allocations.
- Lower the two-node Slurm time limit from 2.5 hours to 1 hour. Four-node jobs keep 2.5 hours.
- Before a benchmark, remove this runner's diagnostic logs older than seven days, keeping the newest Runner and Worker log. Require 5 GiB of free filesystem space and check that an 8 MiB file can be written and flushed in the diagnostic, temp, workspace and home directories.
- Archive benchmark logs without making a staging copy. Remove the local archive after a successful upload.

## Why

The [October 28 nightly job](https://github.com/sgl-project/sglang/actions/runs/40647818033/job/122814505274) failed with `Disk quota exceeded` while the runner was writing `_diag/blocks`. The [October 27 job](https://github.com/sgl-project/sglang/actions/runs/40465896895/job/122206637186) reports that the runner lost communication with GitHub.

The servers run in detached containers on Spur. If the launcher stops before cleanup, those containers can keep using GPUs and delay later jobs. This adds cleanup on exit and before the next job, while reducing disk usage and checking storage before starting servers.

Old diagnostic upload blocks and model caches are left alone. The write check detects current quota exhaustion; it does not reserve space for the whole run. SIGKILL or loss of access to the compute nodes can prevent exit cleanup, so recovery still depends on a later job. A runner that cannot start needs manual recovery.
