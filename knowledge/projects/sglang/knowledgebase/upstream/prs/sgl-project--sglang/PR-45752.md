## Motivation

`get_prefill_mqa_inputs` packed each request's complete compressed keys using a Python loop. For every request, it performed a cast, a `// ratio` operation, and an `index_select`, followed by a final `torch.cat`.

This required `3B + 1` launches per QSA layer. When metadata did not contain host-side lengths—which happens on every eager forward on `main`—it also called `sequence_lengths.tolist()`, introducing a host synchronization.

<!-- Describe the purpose and goals of this pull request. -->

## Modifications

- Replace the GPU packing loop with `gather_qsa_compressed_keys`, which gathers keys in one Triton launch over `(block tile, sequence)`.
- Copy raw bytes so the same kernel supports both BF16 and FP8 caches.
- Reuse the compressed `cu_seqlens` that `build_qsa_row_ranges` already computes for row offsets.
- Record the scheduler's `seq_lens_cpu` as `prefill_sequence_lengths_cpu` for every extend, allowing output sizing without a device read.
- Preserve the per-request gather for CPU tensors.
