# [Fix] [AMD] moe: Run compressed-tensors channel-wise FP8 experts correctly on the Triton runner with AITER

[Upstream PR](https://github.com/sgl-project/sglang/pull/46791) · state: open · merged: False

## Original PR description

## Motivation

On ROCm with AITER enabled, compressed-tensors FP8 MoE models with per-channel weight scales (for example `RedHatAI/Qwen3-30B-A3B-FP8-dynamic`) return wrong results when the experts run on the Triton MoE runner (`--moe-runner-backend triton`). GSM8K drops from 95% to 0%. Two independent bugs cause this:

1. **Preshuffled weights.** `CompressedTensorsW8A8Fp8MoE.process_weights_after_loading` preshuffles the expert weights for AITER whenever AITER is enabled, also when the experts will run on the Triton runner. The Triton runner reads them as if they were unshuffled.
2. **Wrong K for unpadded experts.** For FP8 experts without a block shape, `invoke_fused_moe_kernel` takes K as the weight's K minus `get_moe_padding_size(_use_aiter)`, assuming the weight loader padded the experts along K. With AITER enabled that is AITER's padding size (128) even when the experts were not padded, which is the case for compressed-tensors per-channel experts. So the last 128 columns of K are skipped in both projections; for Qwen3-30B-A3B that is hidden 2,048 -> 1,920 in w13 and intermediate 768 -> 640 in w2.

## Modifications

- `compressed_tensors_w8a8_fp8_moe.py`: new helper `_channel_experts_on_aiter()`, true when channel-wise experts run on AITER's fused MoE (the AITER runner explicitly, or the automatic choice with AITER enabled). The preshuffle and the automatic runner choice both use it, so the two can no longer disagree. With the automatic runner and the AITER runner nothing changes.
- `fused_moe_triton_kernels.py`: the K padding comes from the tensors (`B.shape[2] - A.shape[1]`, the experts' K minus the activations' K) instead of a module-level `get_moe_padding_size(_use_aiter)`. When the loader did pad the experts, the result is the same as before.
- New CPU test `test/registered/unit/layers/quantization/test_compressed_tensors_fp8_channel_moe_runner.py` for the runner decision (automatic, explicit Triton, explicit AITER, non-channel strategies).

## Accuracy Tests

MI350X, ROCm 7.2.4, `rocm/sgl-dev:v0.5.22-rocm724-mi35x-20261021`, `RedHatAI/Qwen3-30B-A3B-FP8-dynamic`, TP1, normal mode, `SGLANG_USE_AITER=1`, GSM8K (sgl-eval 0.1.2, temperature 0, 1,319 questions):

| MoE runner | before | + preshuffle fix | + K fix (this PR) |
| --- | --- | --- | --- |
| `--moe-runner-backend triton` | 0.00% | 84.69% | 94.92% |
| automatic (AITER) | | | 94.92% |

The new unit test passes (`4 passed`); without the change it fails (no `_channel_experts_on_aiter`).

## Speed Tests and Profiling

No change to the AITER path or to experts that the loader padded. The fixed Triton path computes over the full K, as intended.
