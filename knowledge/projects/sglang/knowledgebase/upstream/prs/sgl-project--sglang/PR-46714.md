# fix(function_call): support streaming multiple tool calls in InternlmDetector

[Upstream PR](https://github.com/sgl-project/sglang/pull/46714) · state: open · merged: False

## Original PR description

## Motivation
Fixes #46661

In `InternlmDetector.parse_streaming_increment`, after the first tool call is completed (`current_tool_id > 0`), any subsequent chunk without a full `<|action_start|> <|plugin|>` marker was unconditionally discarded via `self._buffer = ""`. When the start marker arrived across multiple chunks (e.g., `<|action_start|>` followed by ` <|plugin|>`), the detector cleared the buffer prematurely, causing all subsequent tool calls in the stream to be dropped.

## Proposed Changes
1. **Streaming Multi-Call Parsing**: Refactor `parse_streaming_increment` in `internlm_detector.py` to iteratively parse all complete tool calls in the buffer.
2. **Buffer Preservation**: Retain partial marker prefixes across chunks using `_ends_with_partial_token` and prevent premature buffer clearing.
3. **State Synchronization**: Synchronize `prev_tool_call_arr` and `streamed_args_for_tool` sequentially with `call.tool_index = self.current_tool_id = len(self.prev_tool_call_arr)` without array desynchronization or off-by-one errors.
4. **Unit Tests Added**: Added comprehensive unit tests in `test_function_call_parser.py` testing non-streaming and streaming across various chunk sizes (1, 2, 4, 7, 16, len(text)) with multiple sequential tool calls.
