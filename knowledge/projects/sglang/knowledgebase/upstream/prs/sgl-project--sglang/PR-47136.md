[Upstream PR](https://github.com/sgl-project/sglang/pull/47136) · state: closed · merged: False

## Original PR description

## Codex notes

**Reassessment:** The 128-token decoder replay window is an intentional approximation, as documented in the [cookbook](https://github.com/sgl-project/sglang/blob/e1b6d7581e4e3ff4b9491bf9c4507a135e4f6146/docs/cookbook/autoregressive/DeepSeek/DeepSeek-V4_1.mdx#L108). Numerical differences from full prefill do not establish a correctness bug. The earlier bug claim is withdrawn.

The cache regression checks rows preceding a matched prefix endpoint without applying the consumer's replay mask. Normal bounded prefill caps prefix reuse and masks attention below the replay start, so this test does not demonstrate an invalid cache read.

This patch expands the replay window and changes cache reuse policy. It is a draft pending reassessment of its purpose and performance/quality tradeoff.

-Robot

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Account for DCP-widened cache pages in the replay bound**

When decoder bounded replay is explicitly enabled with `dcp_size > 1`, this passes the logical 256-token page size even though cache construction deliberately widens the tree/allocator page to `page_size * dcp_size` (`kv_cache_builder.py:440-447`), and that combination is not rejected by the explicit-enable validation. The new bound is therefore too short for the pages that `free_out_of_window_slots` publishes: for DCP=2 and the 40-layer/source-20 configuration it computes 3052 rows instead of 3564, so a later match ending on the earlier retained 512-token page can reuse late-layer SWA rows whose transitive inputs were never replayed and return incorrect outputs. The HIP backend mirrors this call, so use the tree's widened page size or reject DCP for this feature.
