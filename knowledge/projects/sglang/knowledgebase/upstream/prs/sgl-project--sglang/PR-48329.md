# [Feat] scheduler: Support logprobs in mixed chunked prefill

[Upstream PR](https://github.com/sgl-project/sglang/pull/48329) · state: open · merged: False

## Original PR description

## Motivation

SGLang currently disables mixed chunked prefill whenever either the prefill or decode batch requests logprobs.

The existing mixed-batch metadata incorrectly counts one-token decode tails as input-logprob rows, potentially causing logprob shape mismatches and incorrect indexing.

This PR enables logprob-enabled requests to benefit from mixed prefill/decode execution.

## Modifications

- Correct mixed prefill/decode logprob metadata while preserving in-flight references.
- Reuse existing CUDA Graph and distributed execution paths, with compatibility guards for unvalidated configurations.
- Reuse existing logprob cursor handling for skipped mixed-batch requests.
- Retain Full CUDA Graph capture inputs until graph cleanup to prevent invalid tensor references.
- Add CPU/GPU regression tests and an independent same-forward FP64 logprob oracle.

No new kernels or user-facing configuration options are introduced.

## Accuracy Tests

Validated on **8×H20, BF16**, primarily with Qwen2.5-7B, plus representative Qwen3, LoRA, EAGLE3, and hybrid workloads.

- **473 scenarios**, 1,252 requests.
- **1,520 actual Mixed + Logprob forwards**, including 716 model CUDA Graph replays.
- **110,666 HTTP token positions** checked.
- Maximum same-forward FP64 oracle error: **2.08e-6** (`atol=3e-6, rtol=0`).
- **76 focused unit tests passed.**

Covered Eager/Breakable/Full CUDA Graph, representative TP/DP/PP configurations, heterogeneous logprob requests, Top-K, requested-token logprobs, chunk boundaries, caching, and request cancellation.

Unsupported or unvalidated combinations retain the existing fallback behavior. Separate cross-forward numerical differences, also observed in upstream execution paths, are outside this PR's scope.

## Speed Tests and Profiling

A small H20 regression check showed comparable ordinary-serving throughput:

- Upstream: **1,313 tokens/s**
- Patched: **1,320 tokens/s** (+0.53%)

No obvious regression was observed. This is a regression check rather than a comprehensive performance benchmark.
