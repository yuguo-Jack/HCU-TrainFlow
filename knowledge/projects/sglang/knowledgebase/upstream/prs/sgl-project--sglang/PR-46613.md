# [Perf] diffusion: Cosmos-Dreams rollout-owned prefix K/V buffer

[Upstream PR](https://github.com/sgl-project/sglang/pull/46613) · state: open · merged: False

## Original PR description

## Motivation

Every denoise step, each layer concatenated `[text | history]` and then `[prefix | chunk]`, and every commit re-allocated the whole history. That is 2 full K/V history copies per layer per step plus an O(T) copy per commit.

## Changes

- `PrefixKVHistory` (cosmos_dreams.py): per-layer `[text | history | chunk scratch]` buffers owned by the rollout. Indexing returns history views, so it works anywhere a `list[KVPair]` history is read.
- The transformer writes the chunk's K/V into the scratch rows and attends to a view, so no history copy per step. `_joint_attention` takes `chunk_in_prefix` and keeps its old signature.
- `append_kv_history` appends in place for the buffer, with the same sink + window eviction and the same window check.
- Rollout creates the buffer at the first commit. Its initial capacity is `sink + window + chunk` frames, capped at the request's latent frame count so short requests do not over-reserve. The buffer grows on demand if needed. Frustum `SelectedHistory` and plain lists still work and take a single-copy path via `_prefix_kv`.

## Tests

Added `TestCosmosDreamsPrefixBuffer` (Modal CPU): buffer contents are bitwise equal to `append_kv_history` over mixed append sizes (full, sliding, sink+window, preallocated capacity), initial-block-over-window is rejected, and `_joint_attention` with `chunk_in_prefix` is bitwise equal to the concat path. `test_cosmos_dreams.py`: 61 passed, 1 skipped on Modal CPU. The 3 `test_offloaded_vae_uses_serial_decode` subtests fail identically on main in the CPU env (55 passed, same 3 failures on main).

## Benchmark

Real checkpoint (`nvidia/Cosmos3-Nano-Sim-Bimanual`), Modal L40S, base 9f6678aa3d vs this branch. 81 frames (21 latent), 480x640, seed 1, fixed synthetic input image, no actions, full-history default profile. 1 cold warmup run discarded, then 10 warm runs per variant, alternating. Full per-run data and tests are in the comment below.

| | base | this PR |
|---|---|---|
| Rollout stage, mean (s) | 6.837 (sd 0.065) | 6.718 (sd 0.079) |
| Peak memory (MB) | 30960 | 29924 |
| Output mp4 md5 | identical across all 20 runs | identical across all 20 runs |

The rollout is 1.7% faster (95% CI 0.7% to 2.7%; Welch p = 0.0018, Mann-Whitney p = 0.0036). That is statistically significant but small at this size (short history, small chunk). Peak memory is about 1 GB lower. Caveats: noise input and null actions, one resolution and GPU, full-history profile only, runs share a container.

Earlier synthetic microbenchmark (L4, 12 layers, 16 heads / 4 KV heads, head dim 128, 512 text tokens, 256 tokens per frame, chunk of 4 frames, 4 denoise steps, framewise commits, QK norm and RoPE stubbed, plain SDPA): 1.04x to 1.08x, outputs bitwise equal, with gains growing with history length and shrinking as chunk size grows. Not a substitute for the real-checkpoint numbers above.

`cosmos3_sim_auto.py` and `nomas_kv_cache.py` are not touched.
