# feat(qwen4-exp): support GR and PLE sequence parallelism

[Upstream PR](https://github.com/sgl-project/sglang/pull/43048) · state: open · merged: False

## Original PR description

## Summary

This PR extends the existing LayerNorm sequence-parallel path to Qwen4Exp / Qwen3.8-Flash-Next.

During prefill, Gated Residual (GR/HC) and PLE activations are sharded along the token dimension across the tensor-parallel group. GDN, QSA/attention, and TP-MoE keep their existing full-token computation semantics through an output-aware fallback:

```text
all-gather token rows
  -> full-row computation
  -> TP-partial output: reduce-scatter with SUM
     complete output: local token-row shard
```
The output contract is explicit at each call site. GDN and attention return TP-partial outputs and therefore use SUM reduce-scatter. MoE selects between SUM reduce-scatter and local sharding through SGLang's existing `post_experts_output_is_complete()` semantics, preventing already-combined FlashInfer/PPLX/MegaMoE outputs from being summed twice.

The feature reuses the existing `--enable-layernorm-sp` option. It does not introduce a Qwen4Exp-specific environment variable, and the default path remains unchanged when the flag is not enabled.

## Motivation

Qwen4Exp applies Gated Residual projections to all token rows in every decoder layer. PLE adds another replicated token-row projection.

Under tensor parallelism, these operations are duplicated on every TP rank. Sharding their token dimension removes the replicated computation while preserving the existing tensor-parallel layout and reduction semantics of attention, GDN/QSA, and MoE.

## Design

The implementation:

- keeps GR and PLE activations sequence-sharded during prefill;
- gathers full token rows before GDN, QSA/attention, or MoE;
- temporarily disables the SP flag while running existing full-row computation;
- requires each full-row call site to explicitly declare whether its output is TP-partial or already complete;
- reduce-scatters TP-partial outputs with SUM, while directly selecting the local token shard from already-complete outputs;
- uses `post_experts_output_is_complete(is_tp_path=True)` to preserve the reduction semantics of each supported MoE backend and avoid double reduction;
- keeps decode on the original non-SP path;
- adds reusable token-row shard, all-gather, reduce-scatter, and replicated-compute helpers to the existing `layernorm_sp` module;
- preserves the original path when `--enable-layernorm-sp` is not specified.

Qwen4Exp LayerNorm-SP currently requires:

- tensor parallel size greater than 1;
- expert parallel size equal to tensor parallel size;
- pipeline parallel size equal to 1;
- DP attention disabled;
- speculative decoding disabled;
- attention context parallel size equal to 1.

Standalone Qwen4Exp context parallelism remains supported when LayerNorm-SP is disabled. Only the currently unsupported LayerNorm-SP × attention-CP combination is rejected. Unsupported configurations fail during argument validation.

## PLE physical-row layout

PLE operates on a physical CUDA Graph bucket, while only a prefix of the rows may contain processed tokens. Padding must happen before sequence sharding.

For example, the final chunk of a 235K-token request has:

```text
processed_tokens = 5624
physical_tokens  = 8192
TP               = 4
```

The correct physical layout is:

```text
rank0: 2048 valid
rank1: 2048 valid
rank2: 1528 valid + 520 padding
rank3: 2048 padding
```

Sharding the 5,624 processed rows before padding would insert padding between globally contiguous valid ranges and corrupt the PLE short-convolution state. This PR pads the embedding tensor to `physical_tokens` first and then selects the TP-local token shard.

## Usage

Add `--enable-layernorm-sp` to a supported Qwen4Exp launch command:

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3 \
PYTHONUNBUFFERED=1 \
PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True \
python3 -m sglang.launch_server \
  --model-path /models/Qwen3.8-Flash-Next-FP8 \
  --served-model-name qwen3.8-flash-next-fp8 \
  --tp 4 \
  --ep 4 \
  --chunked-prefill-size 8192 \
  --mem-fraction-static 0.85 \
  --linear-attn-prefill-backend flashinfer \
  --linear-attn-decode-backend flashinfer \
  --mamba-ssm-dtype bfloat16 \
  --reasoning-parser auto \
  --tool-call-parser auto \
  --enable-layernorm-sp \
  --host 0.0.0.0 \
  --port 31000
```

Without `--enable-layernorm-sp`, Qwen4Exp uses the existing non-SP path.

## Performance

The benchmark used:

- 4× NVIDIA H20;
- Qwen3.8-Flash-Next-FP8;
- TP4 / EP4;
- chunked prefill size 8192;
- FlashInfer linear-attention prefill and decode backends;
- the same server configuration for OFF and ON;
- OFF → ON → OFF → ON service restarts;
- fixed token inputs and warmup requests.

| Workload | TTFT improvement | E2E improvement | Input throughput improvement |
|---|---:|---:|---:|
| 32K input, BS1 | 17.72%–18.36% | approximately 16% | approximately 20% |
| 235K input, BS1 | 14.63%–14.71% | approximately 14% | approximately 17% |
| 32K input, BS4 | 18.74% | 18.14% | 22.14% |

Peak memory decreased by approximately 1.0 GiB per GPU.

BS1 decode TPOT remained effectively unchanged, which is expected because this optimization is enabled only for prefill/EXTEND. The BS4 TPOT improvement reflects reduced scheduling delays from concurrent long prefills rather than a decode-kernel speedup.
