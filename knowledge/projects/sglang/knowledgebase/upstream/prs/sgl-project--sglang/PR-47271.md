# [Feat] Mistral-Large-4: add model support

[Upstream PR](https://github.com/sgl-project/sglang/pull/47271) · state: open · merged: False

## Original PR description


## Summary

Adds support for **Mistral Large 4** (`mistralai/Mistral-Large-4-1T-A52B`): a 1T-param / 52B-active MoE multimodal model (Pixtral vision host) with MLA + DSA sparse attention (top-k 2048), cross-layer KV sharing (layer 35 provides KV for layers 39/43/…/71), YaRN to a native 1,048,576-token context, and a bundled **DSpark** draft head (3 drafted tokens/step, RNN head) for speculative decoding. Also supports the official NVFP4 checkpoint (`mistralai/Mistral-Large-4-1T-A52B-NVFP4`, Blackwell) and online NVFP4 conversion of the FP8 checkpoint.

## Checkpoints and install

Both checkpoints ship the Mistral-native layout (`params.json`, `tekken.json`, consolidated shards) plus transformers-format files; the FP8 repo also ships `config.json`. The loader selects the Mistral-native parser from the weight layout (params + consolidated, no HF shards), independent of `config.json` presence or Hub cache state.

```bash
docker pull lmsysorg/sglang:mistral-large-4   # multi-arch (amd64 + arm64), mistral-common 1.13.0 included
```

The release tokenizer (tekken v15, reasoning effort low/medium/high) requires `mistral-common[image] >= 1.13.0`; the day-0 image ships it. Cookbook: https://docs.sglang.io/cookbook/autoregressive/Mistral/Mistral-Large-4

## Implementation highlights

- Mistral-native config/loader path for the new architecture (MLA + indexed sparse attention, cross-layer KV source mapping, MoE 128 experts top-4 + 1 shared, Pixtral vision host); FP8 block-quant and NVFP4 (modelopt mixed precision) weight paths; bundled DSpark draft detected from the checkpoint (`mtp.dspark`, gamma 3, verify window 4).
- **DSpark speculative decoding**: draft attention backend, HiSparse residency hooks, prefill/decode-CP composition guards.
- **Prefill CUDA graphs (breakable)** for the Pixtral host, for text **and** image batches: at a matched batch composition, replayed outputs are token-identical to eager wherever deterministic, and stay inside eager's variant set at near-ties.
- **Reasoning effort protocol**: `low`/`medium`/`high` supported; omitted effort resolves to the checkpoint default (`high` on the release tokenizer) with correct reasoning/final separation in both tokenizer modes (native mistral-common and HF tokenizer + chat template); `"none"` is rejected (400) per the release tokenizer contract. Omitted and explicit `high` render token-identically.
- **Parser auto-detection** for reasoning (`[THINK]`) and tool calls from mistral-common control tokens.
- **Fail-fast composition guards** with actionable errors: incompatible raw/packed FP8 DSA backend pairs, unsupported DSA precision keys, draft window/sink overrides, KV-cache sharding with cross-layer KV sharing, PD peer-config fingerprint mismatches.
- Context parallelism: prefill CP (interleave) and decode CP; HiSparse sparse-residency serving; HiCache including index-key elision.

## Launch

```bash
# FP8, 8× B300 (TP8)
python -m sglang.launch_server --model-path mistralai/Mistral-Large-4-1T-A52B \
  --tp-size 8 --reasoning-parser auto --tool-call-parser auto --mem-fraction-static 0.85

# + DSpark (burst traffic)
  --speculative-algorithm DSPARK --max-running-requests 64

# Official NVFP4, 4× GB300 (TP4)
python -m sglang.launch_server --model-path mistralai/Mistral-Large-4-1T-A52B-NVFP4 \
  --tp-size 4 --reasoning-parser auto --tool-call-parser auto --mem-fraction-static 0.85 \
  --speculative-algorithm DSPARK
```

Context length, tokenizer and KV dtype resolve from the checkpoint; the two parser flags are required (off by default). Full recipes and the hardware matrix are in the cookbook (link above).

## Known limitations

- Pipeline parallelism is constrained by the shared-KV provider layer (layer 35 and its consumers on one stage); PCP+DCP and KV-cache sharding are rejected with fail-fast errors; PD disaggregation beyond 1P1D is not yet validated.
- Reasoning effort `"none"` is rejected by the release tokenizer; omitted effort reasons at the checkpoint default `high`.
- DSpark with PP > 1 is rejected except the PD-prefill exception; DSpark with image input has no validated gate.

## Tests

CPU-registered unit tests cover: ML4 config resolution (native/HF parser selection incl. Hub cache states), weight mapping, DSpark shapes/guards, KV sharing + pool sizing, fail-fast composition guards, checkpoint-format detection, peer-fingerprint digest (integer-keyed configs), omitted/null/kwargs reasoning-effort policy across Chat/Responses/Anthropic paths, and Pixtral prefill-graph eligibility for text and image batches.
