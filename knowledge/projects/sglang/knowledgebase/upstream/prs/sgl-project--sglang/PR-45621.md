# [Feat] decisions: Serve StartLux-Decision checkpoints on /v1/systemone

[Upstream PR](https://github.com/sgl-project/sglang/pull/45621) · state: open · merged: False

## Original PR description

## Motivation

- [startlux-models/StartLux-Decision-v1.1-27B-AutoThink](https://huggingface.co/startlux-models/StartLux-Decision-v1.1-27B-AutoThink) is a decision model on the Qwen3.5-27B backbone that keeps its own LM head: the rows of the answer letters `A` to `Z` are the readout, and `decision_config.json` declares them in the `lodestar-letter-readout-v1` format with a calibrated temperature per question type.
- SGLang cannot serve it today, and does not say so. `decision_config.json` is only read when `architectures` is `["Qwen3_5Model"]`, and that loader requires `format_version`; a StartLux checkpoint is `["Qwen3_5ForConditionalGeneration"]`, so the file is ignored and `/v1/systemone` silently falls through to the general route with SGLang's own prompt wording and a temperature of 1.0.
- Its reference server implements the System One API that `/v1/systemone` already serves, so the checkpoint can answer there with the prompt, the letters, and the per-type temperature it was trained with.

## Modifications

- `load_decision_config` dispatches on the format its `decision_config.json` declares. The lodestar one is validated and normalized to one shape (codes, letter token ids, per-type temperature, option limit, grouping), and a format the loader does not honor is refused instead of served as another one.
- `ModelConfig` reads the config for the Qwen3.5 conditional-generation architectures as well, and leaves their architecture untouched: that head is the readout, so no readout is injected. A lodestar config on a bare backbone is refused, since there is no head to read.
- `SystemOneServing` gets the family: it renders the trained prompt (fixed system line, `Evidence / Question / Options` block, thinking-off assistant prefix), checks that each answer letter is one token right after it, reads every question at its own type's temperature in as few passes as that allows, and reports the extra `None of the above` candidate as `none_probability` with the listed options renormalized. `none_check` (on by default, as the checkpoint's server does) and `allow_none` control that candidate.
- The thought loop and the grouping rounds of a long choice list need more than one read-out. The route declares `think_mode`, `gate`, `think_budget`, `mix`, `return_details` and `return_thought` and refuses them by name, and refuses a choice list over one pass, instead of silently ignoring them. Images are refused the same way.
- Three unit test files: the prompt literal, the per-type temperatures, the none split and the refusals through the handler; both `decision_config.json` formats and their rejections through `ModelConfig`.
- `examples/startlux/sglang_backend.py` runs the checkpoint's own protocol layer on a serving SGLang, so the AutoThink thought loop and its grouping rounds are available without this route generating anything.
- A cookbook page, a supported-models entry, and a command snippet.

## Accuracy Tests

**Per-question parity with the checkpoint's own implementation.** Same machine, same weights, text only, one pass, radix cache off, both reading the none candidate: this branch on two A100-SXM4-40GB cards (tensor parallel 2) against the checkpoint's own server (`startlux_decide` over its transformers engine, single GPU), 14 questions in 5 fixed cases (choice with up to 20 options, noul, score, JSON and long text states).

| | value |
| --- | --- |
| top-option agreement | 14 / 14 |
| worst absolute probability difference | 0.0065 |
| worst `none_probability` difference | 0.0082 |
| worst score difference | 0.010 |

**DecisionPivot, the benchmark the checkpoint is published on.** Run through the repository's own runner and scorer (`runner/bench_http.py`, `scoring/score.py`), the full core track — 13 tasks, 7,800 items, all 7 layers — against the same two engines:

| layer | this branch | checkpoint's own server |
| --- | ---: | ---: |
| A `answerable_facts` | 80.3 | 79.7 |
| B `perm_inherit`, `policy_case` | 59.8 | 60.9 |
| C `log_count_check` | 22.7 | 23.3 |
| D four decision tasks | 48.7 | 47.8 |
| E `clause_change`, `dep_resolve` | 50.3 | 50.7 |
| F `ledger_reconcile`, `record_rule` | 63.0 | 63.3 |
| G `filter_match` | 26.7 | 26.0 |
| **overall, 7 layers** | **50.2** | **50.2** |

Per task the accuracy differs by at most 0.010 (6 items of 600). These are absolute scores of this run configuration (one pass, none candidate on, default gate); the published one-pass rows in the repository's `tables/T4_one_pass_vs_reasoning.csv` are a different checkpoint stage and are not reproduced here.

**The AutoThink thought loop, over SGLang.** The thought loop is not in this route, but the checkpoint's own protocol layer runs it on SGLang unchanged, because it needs only two engine primitives: a read-out and a sampled continuation. `examples/startlux/sglang_backend.py` implements those two on a serving SGLang (`/v1/score` has no arbitrary-label read-out over a plain prompt, so the read-out takes the last prompt position's `top_logprobs` from `/generate`, and the thought is a `/generate` with the checkpoint's sampling) gives the whole protocol, gate and mixing included:

| question | thought | difference from the checkpoint's own server |
| --- | --- | ---: |
| choice, one pass (above the gate) | none | 0.0010 |
| noul, gate 0.9 | 109 tokens, ended by `</think>` | 0.023 |
| noul, gate 0.9 | 85 tokens, ended by `</think>` | 0.033 |

The two thinking rows differ because the thought is sampled: another run writes another thought, and the answer mixes it 0.25 / 0.75. The question that did not think agrees with the reference to 0.001, which is what the one-pass rows above already show.

Two controls, both on the same items:

- Reading the same prompt at temperature 1.0 instead of the trained per-type temperature moves a choice probability by up to 0.12, so the parity above does not hold for any prompt or temperature.
- Crossing the none setting (one side reads the candidate, the other does not) moves a choice probability by up to 0.12 as well, while the same setting on both sides agrees within 0.0095. The none path is therefore exercised, not bypassed.

Not run: images, and a choice list over one pass (both refused by the route with a message naming why).

## Speed Tests and Profiling

One request in flight, one pass per question, two A100-SXM4-40GB cards in BF16: P50 0.35 s for the ~300-token cookbook example. Each question is a prefill of the whole state with no decode, so latency follows prompt length.
