# [NPU] Fix Ascend CPU affinity using runtime device topology

[Upstream PR](https://github.com/sgl-project/sglang/pull/44042) · state: open · merged: False

## Original PR description

## Motivation

`set_gpu_proc_affinity()` assumes the physical device ID can be derived from the
locally visible index, and that host CPU locality is reachable through the same
mechanism used for GPUs. On Ascend NPU nodes neither holds:

1. Container logical device IDs do **not** necessarily equal host physical IDs,
   so a device's CPU locality cannot be inferred from `ASCEND_RT_VISIBLE_DEVICES`.
2. NPU CPU locality is only reported by `npu-smi info -t topo`.

As a result, worker processes either keep the inherited affinity (spanning every
NUMA node on the host) or bind to cores that belong to a different NPU — both
cost cross-NUMA memory traffic on every host-side step.

## What this PR does

- **`sglang/srt/hardware_backend/npu/topology.py`** (new) — `NPUTopology` resolves
  the physical device ID through the CANN runtime (`aclrtGetPhyDevIdByUserDevId`,
  falling back to the legacy `aclrtGetPhyDevIdByLogicDevId` name, which also takes
  a *user* device ID) and reads per-NPU CPU locality from `npu-smi info -t topo`.
  Also exposes the NUMA nodes a CPU set touches.
- **`sglang/srt/utils/cpu_affinity.py`** (new) — provider-agnostic CPU allocation:
  `parse_cpu_list`, `allocate_cpu_cores` (keeps SMT siblings together and handles
  non-contiguous CPU numbering), and `bind_cpu_affinity`, which partitions cores
  among the process-visible devices deterministically so independently started
  workers agree without cross-process coordination.
- **`sglang/srt/utils/common.py`** — route the NPU case in
  `set_gpu_proc_affinity()` through the new helper; GPU behavior is unchanged.
- **`test/registered/utils/test_npu_cpu_affinity.py`** (new).

Behavior notes:

- Binding always stays inside the **inherited** affinity mask.
- Discovery failures leave the affinity unchanged unless
  `SGLANG_CRASH_ON_NUMA_BIND_FAILURE` is set.
- No NUMA memory policy is applied and no additional capabilities are required.

## Testing

New unit tests cover the three layers:

- `TestCPUAllocation` — CPU range parsing and rejection of malformed input;
  non-contiguous SMT grouping and remainder distribution; a disallowed SMT
  sibling is not pulled in; insufficient physical cores is rejected.
- `TestNPUTopology` — runtime ID remapping combined with `npu-smi` topology
  parsing; the legacy CANN entry point receives the *user* index; missing mapping
  API, mapping error, missing/duplicate/malformed topology, and query timeout all
  raise rather than silently bind.
- `TestBinding` — cross-NUMA and shared-NUMA device layouts; cpuset intersection;
  no local allowed CPU keeps the inherited affinity; discovery failure does not
  bind; strict mode raises; `setaffinity` permission error is non-fatal; readback
  mismatch restores the inherited affinity; duplicate and overlapping device
  localities are refused.

```shell
python -m pytest test/registered/utils/test_npu_cpu_affinity.py
```
