# [Perf] spec_v2: Eliminate per-step seq_lens_sum D2H host syncs in Frozen-KV MTP

[Upstream PR](https://github.com/sgl-project/sglang/pull/47082) · state: open · merged: False

## Original PR description

## Motivation

In `spec_v2` overlap mode, `FutureMap.resolve_seq_lens_cpu` checks `decide_needs_cpu_seq_lens(spec_v2_attn_backends)` and leaves `batch.seq_lens_cpu = None` and `batch.seq_lens_sum = None` when all active attention backends set `needs_cpu_seq_lens = False` (such as `TritonAttnBackend`, `TRTLLMHAAttnBackend`, and `FlashAttentionBackend`).

While standard EAGLE-3 (`EagleDraftWorker` / `build_eagle_verify_input`) was migrated to this sync-free contract, `FrozenKVMTPDraftWorker` (`--speculative-algorithm NEXTN` with assistant models) still had blocking per-step `.item()` D2H synchronizations on the hot path:
1. `FrozenKVMTPDraftWorker.draft` unconditionally called `batch.seq_lens_sum = torch.sum(batch.seq_lens).item()` on every draft decode step.
2. `expand_for_topk_draft` called `forward_batch.seq_lens_sum = torch.sum(forward_batch.seq_lens).item()` when `forward_batch.seq_lens_cpu is None` (`topk > 1`), causing a second blocking D2H sync per step.
3. `FrozenKVMTPDraftWorker._init_frozen_kv_metadata` called `torch.sum(forward_batch.seq_lens).item()` when `seq_lens_cpu is None`, even when `draft_attn_backend.needs_cpu_seq_lens` is `False`.
4. `FrozenKVMTPCudaGraphRunner.execute` computed `forward_batch.seq_lens_sum + (expanded_bs - raw_expanded_bs) * self.seq_len_fill_value` without guarding for `forward_batch.seq_lens_sum is None`.
5. `FrozenKVMTPDraftWorker.draft` passed `batch.seq_lens_sum` directly to `build_tree_kernel_efficient` instead of using `target_attn_backend.verify_mask` and the sync-free `seq_lens_sum` upper bound (`0` when preallocated/`QLEN_ONLY`, `bs * target_attn_backend.max_context_len` for `FULL_MASK`) as in `build_eagle_verify_input`.

## Modifications

- **`python/sglang/srt/speculative/frozen_kv_mtp_worker_v2.py`**:
  - In `FrozenKVMTPDraftWorker.draft`, derive `batch.seq_lens_sum` from `batch.seq_lens_cpu` when present (`None` on the GPU-only path) and use `target_attn_backend.verify_mask` + sync-free upper-bound sizing when calling `build_tree_kernel_efficient`.
  - In `_init_frozen_kv_metadata`, only fall back to `torch.sum(forward_batch.seq_lens).item()` when `seq_lens_cpu is None` if `getattr(self.draft_attn_backend, "needs_cpu_seq_lens", True)` is `True`.
- **`python/sglang/srt/speculative/frozen_kv_mtp_utils.py`**:
  - In `expand_for_topk_draft`, compute `seq_lens_sum` from `seq_lens_cpu` when available, scale `forward_batch.seq_lens_sum *= topk` if pre-populated, and leave it `None` on the GPU-only path.
- **`python/sglang/srt/speculative/frozen_kv_mtp_cuda_graph_runner.py`**:
  - Guard `padded_seq_lens_sum` with `None if forward_batch.seq_lens_sum is None else ...` in `execute()`, matching `EAGLEDraftCudaGraphRunner`.
- **`test/registered/unit/spec/test_frozen_kv_mtp_hostsync.py`**:
  - Add unit tests verifying that `Tensor.item()` is never called when `seq_lens_cpu=None` and `needs_cpu_seq_lens=False`.
