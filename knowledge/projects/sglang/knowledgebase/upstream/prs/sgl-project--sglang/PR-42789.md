# [Spec] Read the DFLASH/DSPARK draft pool budget from the live attn_tp_size

[Upstream PR](https://github.com/sgl-project/sglang/pull/42789) · state: closed · merged: False

## Original PR description

## Motivation

Fixes #38202. Supersedes #38203.

Under DP attention the DFLASH/DSPARK draft KV pool is reserved at the raw `tp_size` width while the pool builders shard the draft KV heads by the attention width, which is smaller by `attn_dp_size`. The reservation under-counts the draft pool by that factor and the draft worker OOMs out of the runtime slack, exactly as reported in the issue.

The pricing line itself is already fixed on main: #42651 moved it to `get_parallel().attn_tp_size`, and #45684 split DFLASH onto `draft_attn_tp_size()` while keeping the attention-sharded width for the rest of the family. What is still missing is the guard. Nothing pinned the width the reservation sees, so the same drift can come back with the next topology refactor, and #38202 and #38203 have stayed open through all of it. This PR closes that gap.

#38203 derived the width from the configured leaves at the call site. That derivation no longer works on current main (resolution leaves the deprecated `enable_dp_attention` flag false, and the `derive_attention_widths` helper it imported is gone), and re-deriving topology at the call site duplicates logic that can drift from what the runtime actually stamps. Reading the live width stays the right shape; this PR pins it.

## Modifications

- A comment at the call site in `_resolve_dflash_draft_cell_size` names the invariant: the reservation must price the same width the pool builders shard by, and raw `tp_size` under-counts it by `attn_dp_size`.
- CPU regression test `test_draft_budget_prices_the_attention_sharded_width`: publishes a tp16/attn-dp16 topology and asserts both family paths (DFLASH through `draft_attn_tp_size()`, the rest through `get_parallel().attn_tp_size`) price the draft KV heads at the sharded width of one rank.

## Tests

The test prices through `_resolve_dflash_draft_cell_size` end to end, including the dtype resolution it wraps. Both subtests go red when the pricing is moved back to raw `tp_size` (mutation-verified). Full `test_pool_configurator.py` on current main: 65 passed + 23 subtests. `ruff check` with the repo's pre-commit selection and `ruff format` are clean on both touched files.

## Accuracy Tests

No model-output path is touched; this only documents and pins how much KV budget the draft pool reserves.

## Speed Tests and Profiling

No hot path is touched; the resolver runs once at startup.
