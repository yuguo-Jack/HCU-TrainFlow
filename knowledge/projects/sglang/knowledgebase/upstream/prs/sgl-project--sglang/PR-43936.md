# [PD] Recompute retracted DeepSeek-V4 requests on prefill instead of crashing decode

[Upstream PR](https://github.com/sgl-project/sglang/pull/43936) · state: closed · merged: True

## Original PR description

- Replace `dsv41_dspark_needs_rebootstrap` with `dsv4_needs_rebootstrap`: every DeepSeek-V4 decode server now recovers a retracted request by recomputing its prefix on the prefill. Before, only V4.1 with DSpark did; DeepSeek-V4 and V4.1 without DSpark resolved to the `cpu_tensor` backup, which `DeepSeekV4TokenToKVPool` does not implement, so the decode scheduler crashed with `NotImplementedError` on its first retraction.
- `backup_kv_cache` checks `none` first, so an explicit `--disaggregation-decode-retraction-backup none` still aborts the request. A DeepSeek-V4 request with multimodal inputs is aborted, since the recompute payload carries token ids only.
- A retraction that aborts without a host-pool backup reports 503 "Retry later" instead of "Retraction host KV pool exhausted".
- Rebootstrap skips the prefill recompute for a fake transfer, whose receiver completes on its own; before, both the fake transfer backend and a request with the fake bootstrap host raised `AttributeError` on the decode scheduler.
- `test_disaggregation_dsv4.py` forces retraction on the decode worker and checks after GSM8K that the worker stays up and retracted at least once.

Behavior change: a DeepSeek-V4 PD decode server recomputes retracted requests instead of crashing. With `none`, and for requests with images, it aborts with 503 instead; this also applies to V4.1 with DSpark, which before recomputed in both cases (dropping the images).

Fixes #33385
