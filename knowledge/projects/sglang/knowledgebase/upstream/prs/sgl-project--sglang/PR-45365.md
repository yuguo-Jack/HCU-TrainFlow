# [Fix] [AMD] gpt-oss: support EP for gfx1250 W4A8 MXFP4 MoE

[Upstream PR](https://github.com/sgl-project/sglang/pull/45365) · state: closed · merged: True

## Original PR description

## Motivation

On gfx1250, serving `amd/gpt-oss-120b-w-mxfp4-a-fp8` with `--tp 2 --ep-size 2` crashes with a GPU memory fault during decode CUDA graph capture (in `_moe_gemm_a8w4_decode`).

The gfx1250 W4A8 MoE path(gluon MoE) routes over all 128 global experts, but with EP each rank only holds its 64 local experts. 

## Modifications

- `aiter_mxfp4_w4a8_moe.py`: when an `expert_map` is given, route from the global logits with aiter's `ep_sort_routing`. Gates for non-local experts go to a sentinel bin (no GEMM blocks scheduled) and are masked out of the GEMM2 reduce via `gate_valid`. The layer's existing all-reduce sums the per-rank partial outputs.
- `quark_w4a8_mxfp4_moe.py`: build the global→local `expert_map` once after weight loading (before CUDA graph capture) when `moe_ep_size > 1`, and pass it to the forward.

Scope: all changes are behind the existing `_use_gfx1250_w4a8` gate (HIP + gfx1250), so other platforms and architectures are unaffected. On gfx1250 without EP, the original `routing()` path is unchanged.

## Accuracy Tests

gpt-oss-120b-w-mxfp4-a-fp8, `--tp 2 --ep-size 2`, and `--tp 4 --ep-size 4`  gfx1250:

| | Before | After (TP2/EP2) | After (TP4/EP4) |
|---|---|---|---|
| Server startup | GPU memory fault | OK | OK |
| GSM8K (1319 examples) | N/A | 96.21% | 95.98% |

Kernel-level check: the EP=2 output (rank 0 + rank 1 summed) matches a PyTorch dequantized reference with ~2.5e-3 relative error for batch sizes 1–256.

## Speed Tests and Profiling

This is a correctness fix; it was crashing before, so there is no prior baseline to compare against.
