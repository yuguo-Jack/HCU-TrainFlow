# [Feat] qwen3.5: Support native sequence classification

[Upstream PR](https://github.com/sgl-project/sglang/pull/47729) · state: open · merged: False

## Original PR description

## Motivation

Related to #41110 and based on @Daboolu's original implementation in #36332. Qwen3.5 classification checkpoints need native score-head loading and raw last-token scores through the pooled-output path.

This is a collaborative current-main adaptation with additional regressions. @Daboolu invited us to share the integration changes and tests in https://github.com/sgl-project/sglang/issues/41110#issuecomment-6555184597. The original PR remains open. This Draft makes the adaptation reviewable and does not presume which PR maintainers should land; the changes can be consolidated into one landing path. It does not claim the original design as independent work.

Original attribution is retained in the commit with `Co-authored-by: daisijun <sijun.dsj@gmail.com>`. A complete applicable patch and validation notes were shared at https://gist.github.com/nhq-0806/213108eda469d3bbf5003d854855a9aa.

## Modifications

- Add a dedicated dense `Qwen3_5ForSequenceClassification` module, reusing the existing backbone and `score_and_pool` implementation.
- Load the bias-free `score.weight` head and return raw last-token classification/regression scores. Avoid creating an unused vocabulary head and handle tied-embedding checkpoint loading on the AMX branch.
- Register classification, hybrid-cache and multimodal capabilities and processor routing. Preserve the default generation embedding normalization.
- Cover actual checkpoint mapping, forward dispatch, unequal request lengths, one/two-label outputs and caller-selected positions with CPU regressions.
- Add a no-download hybrid-model GPU parity test and a short checkpoint-format note in the reward-model documentation.

## Accuracy Tests

Rebased on main `3edea93cbc0d857026253df0535a4d89791032a3`; tested commit `1c434e6493d70aa74d6d911262b12193090a9fb4`.

Environment: Python3.12.8, PyTorch2.14.1+cu130, Transformers5.19.0; one NVIDIA A10080GB PCIe. The isolated environment omits torchaudio; no audio validation is claimed.

```bash
CUDA_VISIBLE_DEVICES=999 PYTHONNOUSERSITE=1 python -m pytest \
  test/registered/unit/models/test_qwen3_5_sequence_classification.py \
  test/registered/unit/models/test_qwen3_5_packed_weight_loader.py \
  test/registered/unit/models/test_qwen3_5_pipeline_parallel.py \
  test/registered/unit/layers/test_pooler_score_and_pool.py \
  test/registered/unit/configs/test_embedding_model_spec.py -q --disable-warnings
# 37 passed, 17 subtests passed in 16.18s

CUDA_VISIBLE_DEVICES=0 python -m pytest \
  test/registered/prefill_only/test_qwen35_classification_parity.py -q --disable-warnings
# 1 passed, 3 subtests passed in 30.23s
```

The GPU fixture has seeded random BF16 weights, one GDN layer and one full-attention layer, two labels and request lengths3/7/129. Batched and individual scores match the Transformers classification reference within atol=rtol=0.02. These are numerical regressions, not trained reward-model quality results. Image/video accuracy, quantization, TP/PP and multi-node execution have not been validated.

Before the implementation, the native architecture registration probe fails and classifies the architecture as generation. A negative control that bypasses the classification head fails both one/two-label numerical regression cases as expected.
