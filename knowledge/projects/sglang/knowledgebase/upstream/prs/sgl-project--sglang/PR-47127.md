# [Fix] mem_cache: Build an empty KVLayerRouter from empty layer maps

[Upstream PR](https://github.com/sgl-project/sglang/pull/47127) · state: closed · merged: True

## Original PR description

[by Claude Code]

## Motivation

A KV pool's `KVLayerRouter` maps each model layer to the sub-pool view that stores its KV. `from_layer_maps` builds
it from one entry per token-KV sub-pool (name, view, layer-to-index map), and parts other than token KV, such as a
request's recurrent state, are bound to it afterwards with `bind_part`. `from_layer_maps` now defaults `owner` (the
sub-pool whose write ids are the request's token ids) to `layer_maps[0][0]`, so an empty `layer_maps` raises
`IndexError: tuple index out of range` (`router.py`, line 180) instead of building a router with no token KV.
`test_gdn_prefill_graph.py` builds its GDN backend's router exactly that way, `from_layer_maps(pool, ())` and then
`bind_part` for the state, so it fails on main in `jit-kernel-unit-test-1-gpu-large`
([log](https://github.com/sgl-project/sglang/actions/runs/40724349833/job/122944002696), H100). This PR defaults the
owner only when there is a layer map. Routing for non-empty layer maps does not change: same owner default, same
routes. Every production caller (`HybridLinearKVPool`, `SWAKVPool`, `RoutedKVCache`) passes at least one layer map.

The two changes met on main within five minutes: #46980 made the test build its router from `()`, and #46990 then
added the owner default.

**Impact**

- **Accuracy:** none. Only `from_layer_maps` with no layer maps changes, from an `IndexError` to an empty router.
  `test_gdn_prefill_graph.py` passes with this PR and fails on main (1x B200, both as CI runs it and under pytest).
- **Performance:** none. The change is in router construction, which runs once when a pool is built.

## Modifications

**+4 / −2 runtime code (1 file; 2 of the added lines are docstring), +31 tests (1 file).** No kernel changes.

- `KVLayerRouter.from_layer_maps` (`python/sglang/srt/mem_cache/kv/router.py`): set the default owner only when
  `layer_maps` is non-empty. The docstring now says that no layer maps build a router without token KV.
- `test_kv_layer_router_parts.py`: new CPU test `test_a_router_without_token_kv_routes_its_bound_parts`. It builds a
  router from `()`, binds a state part at indices `{2: 1, 3: 0}` (not the identity, so a route that used the layer id
  would fail), and checks that the router lists no token KV sub-pools and that layer 2 reads index 1 of the bound
  view. On main it fails with the `IndexError` above.
