# [Fix] [AMD] quark: Skip no-copy loads after MXFP4 quantization

[Upstream PR](https://github.com/sgl-project/sglang/pull/45802) · state: closed · merged: True

## Original PR description

## Motivation

With expert parallelism, the online Quark MXFP4 loader can receive a nonlocal expert after finishing its local weights. The underlying loader correctly copies nothing, but the wrapper compares the accumulated BF16 element count with the now-packed parameter size and raises an assertion. This affects online-quantized MoE loading, including the Qwen3.5 MTP path on ROCm.

## Modifications

Return after a zero-copy load, following weight-name validation. Local copies retain the existing completion and quantization logic. Add CPU regressions for both packed weight parameters and invalid names.

## Accuracy Tests

CPU test file: `test/registered/unit/layers/quantization/test_quark_w4a4_mxfp4_moe.py` 5 passed. The two new no-copy cases fail without the fix; the invalid-name case rejects an incorrectly placed early return.

On an MI355X with real AITER quantization, compared base `9301ca37` with the three-line fix: six loading sequences and sixteen controls per version passed the expected base-failure/head-success checks. Packed weights and scales matched direct-quantization references and corresponding EP1/EP2 expert fixtures. Invalid names and duplicate local loads retained their expected errors.

## Speed Tests and Profiling

Not applicable: the change handles a no-copy call during weight loading; no inference-speed claim.
