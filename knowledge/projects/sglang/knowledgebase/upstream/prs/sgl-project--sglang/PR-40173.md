# [Quant] Route hybrid NVFP4 MXFP4 draft experts through the CUTLASS MoE method on SM90/SM120

[Upstream PR](https://github.com/sgl-project/sglang/pull/40173) · state: open · merged: False

## Original PR description

## Motivation

`HybridFp8NvFp4Config` (the config `loader.py` builds for `nvidia/DeepSeek-V4*-NVFP4` checkpoints: FP8 attention/dense + NVFP4 routed experts) sends the FusedMoE layers that remain MXFP4 — the bundled DSpark/MTP draft experts, excluded from the NVFP4 map — to `Mxfp4FlashinferTrtllmMoEMethod` unconditionally. That TRT-LLM MoE kernel exists only on SM100. `Fp8Config.get_quant_method` already handles the identical layers of the stock checkpoint by selecting `Mxfp4FlashinferCutlassMoEMethod` on SM90/SM120 ("SM100 uses TRT-LLM; SM90 uses W4A16 and SM120 uses MXFP8xMXFP4"), so the hybrid path is the only place the platform branch is missing.

## Modifications

One platform branch in `HybridFp8NvFp4Config.get_quant_method`, mirroring `fp8.py`: on SM90/SM120 return `Mxfp4FlashinferCutlassMoEMethod(Fp8MoEMethod(self), prefix=prefix)`; otherwise the existing TRT-LLM method. No change to the NVFP4 routed-expert method, to any non-MoE layer, or to SM100.

## Accuracy / speed

Served on 4× NVIDIA DGX Spark (GB10, SM121), TP4/EP4, `nvidia/DeepSeek-V4.1-Flash-NVFP4` @ `3431dde3`, `--moe-runner-backend flashinfer_cutlass`, DSpark block 5, `--enable-decoder-swa-bounded-replay`, on top of `e087e662` with this change bind-mounted. Without it the draft cannot load on this hardware; with it the draft loads (`Initialized DSpark draft runner ... gamma=5`) and serves:

- 112/112 structured tool/JSON requests; needle retrieval exact at 131K / 262K / 655K prompt tokens; 8 concurrent 262K prompts 8/8.
- Decode C1/C4/C8 36.9 / 80.8 / 107.4 tok/s with the draft vs 27.7 / 71.6 / 109.4 without.
- Output is deterministic across boots (two boots gave byte-identical top-20 logprobs at 1,440 panel positions); first-token distributions identical to the no-speculation boot on the same checkpoint.

Full record with raw JSON: [sparkring performance record](https://github.com/FujitsuPolycom/sparkring/blob/main/performance/records/deepseek-v41-flash/sglang-79f656a6-nvfp4-20260917.md) (§5–6). Not tested on SM90 or SM100 hardware; SM100 code path is unchanged.
