# [Perf] [AMD] dsv4: aiter sparse prefill, fp8 wo_a and mxfp8_128 GEMM

[Upstream PR](https://github.com/sgl-project/sglang/pull/48064) · state: open · merged: False

## Original PR description

Speed up DSV4 on gfx1250:

- Dispatch the unified-KV sparse prefill to aiter `pa_prefill_sparse`.
- Run the fp8 `wo_a` GEMM on gfx1250.
- Use the aiter `mxfp8_128` GEMM for block-fp8 linears.

<!-- results -->
### Accuracy
GSM8K (200 questions, greedy), DeepSeek-V4-Pro: TP4 0.965, EP4 0.975.

### Performance
Setup:
- Model: DeepSeek-V4-Pro, BF16 KV cache, DSPARK speculative decoding (block 6, 1 step)
- Parallelism: TP4 (`--tp 4`, CP prefill + CP decode attention); EP4 (`--tp 4 --dp 4 --ep 4 --enable-dp-attention`, mori a2a)
- Step time: torch profiler on rank 0, GPU time per step; decode = 8 steps at 4 running requests (VERIFY = target verify, DRAFT = DSPARK draft), prefill = one EXTEND step of an ~8k-token prompt (TP4) / 4k (EP4)
- Comparison: with vs without this PR, same image and node, all earlier PRs of the series applied

Profiler step time (without -> with):

| step | without | with | change |
|---|---|---|---|
| TP4 decode VERIFY | 25.61 ms | 17.77 ms | -30.6% |
| TP4 decode DRAFT | 2.22 ms | 1.83 ms | -17.4% |
| TP4 prefill EXTEND | 741.5 ms | 191.9 ms | -74.1% |
| EP4 decode VERIFY | 64.09 ms | 61.54 ms | -4.0% |
| EP4 prefill EXTEND | 920.1 ms | 297.6 ms | -67.7% |
