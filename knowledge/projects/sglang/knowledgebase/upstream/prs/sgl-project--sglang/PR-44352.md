# [Fix] scheduler: Cap exhausted single-pool continuations

[Upstream PR](https://github.com/sgl-project/sglang/pull/44352) · state: open · merged: False

## Original PR description

## Motivation
Cached follow-ups can exhaust a single-pool KV cache while a long prompt is still mid-chunked-prefill. The scheduler then forces a full chunk and raises `Prefill out of memory` even when less than one chunk is physically free.

Reproduced in production by SGLang-based deployments with 1.6M-token KV pools; free capacity at failure was 1,600–1,920 tokens while the forced continuation requested 8,192 tokens. Internal tracking: Coral-Bricks-AI/www#671.

## Changes
- Cap a single-pool continuation to page-aligned current capacity minus allocator page overhead.
- Defer the continuation when no usable capacity remains.
- Reserve its unfinished remainder against other requests admitted in the same pass.
- Preserve existing SWA transient-window behavior.
- Add focused budget and scheduler regressions.
