# [rust-renderer] Expand scalar bootstrap rooms across parallel choices

[Upstream PR](https://github.com/sgl-project/sglang/pull/42029) · state: closed · merged: False

## Original PR description

## Motivation

The Rust renderer repeats a scalar `bootstrap_room` across choices when an OpenAI request sets `n > 1`, even though each forwarded engine request has `sampling_params.n = 1`. For example, chat with room 100 and `n = 3` forwards rooms `[100, 100, 100]`, causing independent choices to reuse the same bootstrap room.

## Modifications

Expand scalar rooms across both prompts and choices for chat, text completions, and token-ID completions. Match Python's sample-major room numbering while retaining the renderer's prompt-major request order. Preserve explicit room lists and reject scalar overflow before engine submission.

## Accuracy Tests

- Four regression tests fail before the fix and pass afterward; all 13 focused OpenAI tests pass.
- Full `sglang-renderer` suite: 129 unit tests and 1 doctest pass with pinned Rust 1.92.
- Real standalone renderer HTTP requests against a recording mock engine: chat `n=3` now forwards `[100, 101, 102]`; two-prompt text and token requests forward `[100, 102, 104, 101, 103, 105]`. Explicit-list controls are unchanged. The engine's model output is mocked; no GPU PD run was performed.
- Strict workspace, renderer test-target, multimodal feature, and radix-tree Clippy checks pass. Formatting and touched-file pre-commit checks pass.
