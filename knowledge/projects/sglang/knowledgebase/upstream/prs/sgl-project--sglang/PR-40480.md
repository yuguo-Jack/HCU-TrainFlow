# [Fix] Make PLE logical clearing safe while KV memory is offloaded

[Upstream PR](https://github.com/sgl-project/sglang/pull/40480) · state: open · merged: False

## Original PR description

## Motivation

With memory saver enabled, releasing the KV cache on PLE models can crash with a CUDA illegal memory access.

#14209 fixed this for `MambaPool`. #19029 proposed flushing before pause and was closed as solved by #14209. #37500 later added PLE pools with the same bulk writes in `clear()`, bringing the failure back:

- `release_memory_occupation()` pauses the KV-cache tag before calling `flush_cache()`.
- The flush reaches `ShortConvPool.clear()` and `NGramPool.clear()`, which write to tensors whose backing memory has already been released.

## Modifications

Make both PLE `clear()` methods no-ops, extending #14209's lifecycle to these pools. Existing deferred initialization calls `reset_slots()` before extend: zero for short-conv, `eos_token_id` for n-gram. Cached-prefix hits inherit state through `copy_slots()`. PLE-enabled disaggregated decode already clears bookkeeping without these bulk resets.

The reserved padding slot 0 is never allocated, so per-slot resets do not cover it. Its contents are already undefined after pause/resume; initializing it needs a separate fix and validation.

Added `test/registered/unit/mem_cache/test_ple_state_pool_offload.py` with 6 CPU tests covering offload safety, allocator bookkeeping, slot initialization, cached-prefix copying, and disabled pools. All 6 pass; reverting only the source gives 3 failed / 3 passed. The full `test/registered/unit/mem_cache/` suite has no new failures on CPU. Pre-commit passed on both files.

On 8x H20 with TP8, memory saver and radix cache enabled, the unmodified tree crashes on all 8 ranks. This patch passes both cycles of generation, repeated-prefix generation, release/resume, and generation again with `ALL_STEPS_OK`. The pause-before-flush ordering stays unchanged.
