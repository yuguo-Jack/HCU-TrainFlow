# [Fix] function_call: Keep Qwen3Coder string null and invalid booleans

[Upstream PR](https://github.com/sgl-project/sglang/pull/42992) · state: closed · merged: False

## Original PR description

Fixes #42764

`Qwen3CoderDetector._convert_param_value` turned the text `null` into `None` before reading the parameter schema, so a string argument whose value is `null` was dropped. A boolean value other than `true` or `false` was rewritten as `false`.

`null` is now `None` only when the schema allows null (`type` includes `null`, an enum contains `null`, or `anyOf`/`oneOf` has a null branch). Other `null` text stays a string. An unrecognized boolean stays the raw string, matching the integer and number branches.

`TestQwen3CoderDetector`: the new case plus the existing boolean and nullable `anyOf` cases, 4 passed.
