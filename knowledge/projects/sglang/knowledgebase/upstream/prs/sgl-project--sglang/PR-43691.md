# [diffusion] fix: shard Qwen-Image adaLN modulation and text FFN under TP

[Upstream PR](https://github.com/sgl-project/sglang/pull/43691) · state: closed · merged: True

## Original PR description

## Motivation

On 2x RTX 5090 (32 GB, PCIe, no P2P), Qwen-Image under `--tp-size 2` cannot keep or swap the DiT. The rank-local TP checkpoint slice is **29.60 GiB per rank**, so TP2 only removes about 22% of the ~38 GiB DiT:

- `--dit-cpu-offload true --text-encoder-cpu-offload true` OOMs while moving the DiT onto the GPU.
- Keeping the DiT resident leaves no room for the text encoder.
- The only working option was streaming the DiT layer by layer every step: 62.2 s, or 41.7 s with 30 resident layers.


Two groups of weights are copied in full on every rank:

- `img_mod` / `txt_mod` are `ReplicatedLinear(dim, 6*dim)`, holding 6.8B of the 20B parameters.
- `txt_mlp` is replicated whenever `tp <= 2`, holding 4.5B parameters. This default was tuned on H100 with NVLink, where it gave -8% latency at tp=2.

## Modifications

Four commits (the fourth simplifies the second; the net change is what is described here):

1. **Shard the adaLN modulation projections under TP.**
   - The modulation input is one token per sample, so the output can be column-sharded and the `[B, 6*dim]` result all-gathered at negligible cost.
   - When `tp > 1` and the checkpoint is unquantized, `img_mod` / `txt_mod` become `ColumnParallelLinear(gather_output=False)`.
   - `_gather_modulation_shards` all-gathers the img and txt shards in one collective per block. It also covers `zero_cond_t`, where the two batch sizes differ.
   - The modulation cache stores the gathered tensors, so cache behavior is unchanged.
   - `tp == 1`, quantized and Nunchaku checkpoints keep `ReplicatedLinear`.
   - The rank-local TP loader already slices `ColumnParallelLinear` weights by output dim, so the loader needs no change.
2. **Shard the text FFN under TP.**
   - `txt_mlp` was replicated whenever `tp <= 2`. It now uses the same column/row-parallel layout as `img_mlp`.
   - The replication came from an H100 measurement (-8% latency at tp=2). That win is given up on H100-class devices; it was not re-measured here.
   - On the 5090 the sharded layout was also slightly faster than the replicated one (21.25 vs 21.72 s).
   - There is no new env var or config knob.
3. **Docs:** a Qwen-Image cookbook section for two 32 GB GPUs.
4. **Drop the memory gate and env override from (2).** An earlier revision of this PR replicated `txt_mlp` on devices with at least 48 GiB and added `SGLANG_QWEN_IMAGE_REPLICATE_TXT_MLP`. Both are removed, so `txt_mlp` is always sharded under TP and no knob is added.

New unit test `test_qwen_image_tp_shard.py` checks that the gathered modulation layout equals the full projection, including the `zero_cond_t` 2:1 case.

Qwen-Image-2.1 uses its own `qwen_image21.py` and is not affected.

## Accuracy Tests

Setup: 1024x1024, 50 steps, CFG off, seed 42, same prompt.

| Comparison | PSNR | max-abs |
|---|---|---|
| New TP2 vs old TP2 (layerwise) | 44.6 dB | 44 |
| New TP2 vs 1 GPU | 24.8 dB | 202 |
| Old TP2 vs 1 GPU (reference) | 24.9 dB | 203 |
| tp=1 before vs after | identical | 0 |

TP2 drifts from 1 GPU by the same amount before and after this change, and the new TP2 output looks the same as the old TP2 output side by side.


## Speed Tests and Profiling

Setup: 2x RTX 5090 32 GB (SM120, PCIe, no P2P). Client wall-clock median of 5 runs after 2 warmup runs, concurrency 1.

| Config | Before | After |
|---|---:|---:|
| Per-rank DiT slice (TP2) | 29.60 GiB | 19.06 GiB |
| TP2, `--dit-cpu-offload --text-encoder-cpu-offload` | OOM | **21.3 s** (peak ~22 GB/GPU steady) |
| TP2, DiT resident, `--text-encoder-cpu-offload` | does not fit | **19.7 s** (peak 31.75 GB) |
| TP2, `--dit-layerwise-offload` (no resident layers) | 62.2 s | **43.0 s** (peak 14.5 GB) |
| TP2, previous replicated `txt_mlp` layout, with DiT CPU offload | – | 21.7 s |
| 1 GPU, DiT layerwise (regression check) | 72.01 s | 72.00 s |

Previous best sglang TP2 result: 41.7 s (DiT layerwise, 30 resident layers).

Layerwise offload also gets faster: each streamed layer shrinks from about 0.49 to 0.32 GiB per rank.

Ulysses2 + layerwise runs the tp=1 code path, which this PR does not touch. It takes 75.0 s, slower than TP2 because Ulysses does not shard the weights and every rank streams the full DiT each step.

Not re-measured on H100. There this PR shards `txt_mlp` too, which gives up the -8% at tp=2 noted in the removed comment. The modulation sharding adds one small all-gather per block (`[B, 6*dim]`, B = batch).
