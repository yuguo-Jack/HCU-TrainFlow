# [Fix] [AMD] kvcache: Use HIP shared-memory capability attribute

[Upstream PR](https://github.com/sgl-project/sglang/pull/47110) · state: closed · merged: False

## Original PR description

<!-- PR title: [Type] scope: title, or [Type] [Hardware] scope: title. -->

## Motivation

On ROCm/HIP (reproduced on AMD Strix Halo/gfx1151), the KV-cache JIT kernel fails to compile because the shared runtime header references CUDA-only shared-memory attributes. The observed compiler errors are:

```text
use of undeclared identifier 'cudaDevAttrMaxSharedMemoryPerBlockOptin'
use of undeclared identifier 'cudaDevAttrMaxSharedMemoryPerBlock'
```

SGLang falls back, so the server may start without the optimized KV-cache JIT path.

## Modifications

- Use `hipDeviceAttributeMaxSharedMemoryPerBlock` in the ROCm path.
- Preserve the existing CUDA attribute path.
- Keep the fix limited to the shared-memory capability query used by KV-cache JIT kernels.

## Accuracy Tests

No model weights or forward math changed. A real `store_cache()` test on gfx1151 copied two K/V rows correctly, and a Qwen3.5 server smoke test with decode graph capture returned `KV_JIT_OK`.

## Speed Tests and Profiling

This is a compile/correctness fix, not a performance claim. Tested KV-cache JIT specializations for `num_threads=0, 32, 64` loaded successfully on gfx1151.

## Limitations

This PR does not change CUDA graph defaults, memory planning, AWQ/MXFP4 kernels, PLE offload, or FlashInfer/AITER. Full CUDA regression and extended ROCm correctness tests remain follow-ups.
