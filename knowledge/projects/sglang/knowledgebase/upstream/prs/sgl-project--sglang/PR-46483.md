# [Perf] [NPU] attention: Avoid CPU sequence length synchronization for Kimi K3

[Upstream PR](https://github.com/sgl-project/sglang/pull/46483) · state: open · merged: False

## Original PR description

## Motivation

Kimi K3 inference on Ascend can still depend on CPU sequence-length mirrors in both the MLA target and DSpark draft attention paths. Maintaining these mirrors and updating host-side graph inputs introduces synchronization overhead on the decode critical path.

Removing this dependency requires both target and draft attention to consume valid KV lengths directly from device memory. This PR enables that flow for supported configurations, while preserving CPU mirrors for attention paths that still require host metadata.

## Modifications

- Add opt-in CANN FlashMLA support for ordinary BF16 MLA decode and static DSpark target verification on Ascend A5 through `SGLANG_NPU_USE_FLASH_MLA=1`. Adapt query/output layouts and provide combined paged KV storage compatible with existing prefill interfaces.
- Integrate `mojo_paged_mtp_decode` from `sgl-kernel-npu` for static DSpark GQA draft attention through `ASCEND_USE_MOJO_MTP=1`, allowing the draft to consume device-resident sequence lengths.
- Make CPU sequence-length requirements capability-aware. Allow `SGLANG_NPU_ATTN_BACKEND_NEEDS_CPU_SEQ_LENS=0` for supported target/draft combinations, and propagate graph-update requirements through hybrid attention backends.
- Skip host sequence-length rebinding during graph replay when the selected backend supports device lengths. Maintain stable metadata buffers, preserve input prefix lengths, and handle inactive request slots and token padding.
- Update DSpark draft and target verification to require valid attention lengths and reject allocation-headroom fallbacks. Correct metadata construction when CPU mirrors are absent, including ordinary decode and speculative page-boundary handling.
- Declare the Ascend KDA prefill checkpoint capability and adjust a recurrent-kernel condition for Triton compatibility. Preserve the original attention and KV-cache paths on unsupported hardware.
- Add unit and regression coverage for backend gating, optional CPU mirrors, graph replay, KV-cache layouts, page boundaries, and padding, plus numerical checks of the draft attention operator using the Triton interpreter.

## Accuracy Tests

The kernel is checked against a float32 reference on Ascend 950PR. Each case
compares full attention output element-wise after applying the same tiling the
kernel uses (per-request KV gather, GQA head expansion, right-down causal mask):

| Case | bs | gamma | q/kv heads / dim | page | variant | max abs | rel error |
|---|---|---|---|---|---|---|---|
| dspark nominal | 2 | 7 | 64 / 16 / 64 | 128 | causal | 1.98e-4 | 0.308% |
| padded batch (one zero-length req) | 3 | 7 | 64 / 16 / 64 | 128 | causal | 1.94e-4 | 0.323% |
| page 16 | 2 | 7 | 64 / 16 / 64 | 16 | causal | 3.42e-4 | 0.339% |
| single request | 1 | 1 | 64 / 16 / 64 | 16 | causal | 3.73e-4 | 0.285% |
| non-causal | 2 | 7 | 64 / 16 / 64 | 128 | non-causal | 2.09e-4 | 0.364% |
| GQA group 4 | 2 | 4 | 32 / 4 / 128 | 128 | causal | 5.32e-4 | 0.348% |
| GQA group 1 | 2 | 1 | 8 / 1 / 64 | 128 | causal | 2.04e-4 | 0.301% |

All outputs finite, no NaN/Inf. Max relative error stays under 0.4%, inside
bfloat16's 8-bit mantissa budget (`2^-8 = 0.39%`).

A 12-layer chain (attention → residual → rmsnorm, identical inputs on both
paths) accumulates to 0.52% against the fp32 reference — the expected growth
once the per-layer error is already at the dtype floor.

Unit tests: `test_npu_mojo_mtp.py` and `test_npu_mojo_mtp_kernel.py` pass
(17 tests). The kernel test imports the installed `sgl_kernel_npu` package
rather than a source path.

## Speed Tests and Profiling

### Setup

| Item | Value |
|---|---|
| Hardware | Ascend 950PR × 4 (single node) |
| Model | Kimi-K3 depth-reduced 12-layer checkpoint, bfloat16 |
| Parallelism | TP4 / DP4 (`--enable-dp-attention --dp-size 4`) |
| Draft | DSpark static draft, gamma=7, block size 7 |
| Page size | 128 |
| Workload | `bench_serving`, random dataset, input 16000 / output 1000 tokens, 64 prompts, concurrency 64 (peak concurrency 64, decode batch 8 per rank) |

Two configurations are compared:

- **A (this change)**: `ASCEND_USE_MOJO_MTP=1`, `SGLANG_NPU_USE_FLASH_MLA=1`,
  `SGLANG_NPU_ATTN_BACKEND_NEEDS_CPU_SEQ_LENS=0`
- **B (baseline)**: `ASCEND_USE_MOJO_MTP=0`, `SGLANG_NPU_USE_FLASH_MLA=0`,
  `SGLANG_NPU_ATTN_BACKEND_NEEDS_CPU_SEQ_LENS=1`

Timing runs have the profiler disabled; profiling runs use
`torch_npu.profiler` (Level2 + PipeUtilization) over 20 decode steps. Both
columns in each table come from the same host, model and scheduler build.

### Throughput and latency

| Metric | A (mojo + FlashMLA + no CPU mirror) | B (baseline) | Delta |
|---|---|---|---|
| Successful requests | 64 | 64 | — |

| Output token throughput (tok/s) | **405.35** | 396.65 | **+2.2%** |
| Total token throughput (tok/s) | **6891.02** | 6743.01 | **+2.2%** |

`MemCopySync` disappearing is the direct consequence of
`SGLANG_NPU_ATTN_BACKEND_NEEDS_CPU_SEQ_LENS=0`: the draft reads device lengths,
so the per-step pinned D2H mirror has no remaining consumer.

## Reproduction

### 1. Build and install the wheel

```bash
git clone https://github.com/sgl-project/sgl-kernel-npu
cd sgl-kernel-npu

# The full build does not cover Ascend 950; build the kernels module only.
source /usr/local/Ascend/cann/set_env.sh

python3 -m pip install --force-reinstall --no-deps \
    output/sgl_kernel_npu-2026.9.0-cp312-cp312-linux_aarch64.whl
```

### 2. Launch script

`launch_k3_spec.sh [port] [tp] [flash_mla] [needs_cpu_seq_lens]`

The two switches under test are the third and fourth arguments; the values in
the tables above are `1 0` for A and `0 1` for B.

```bash
#!/bin/bash
set -e

PORT=${1:-8504}
TP=${2:-4}

unset https_proxy http_proxy HTTPS_PROXY HTTP_PROXY

source /usr/local/Ascend/cann/set_env.sh
source /usr/local/Ascend/cann-9.1.0/opp/vendors/customize/bin/set_env.bash 2>/dev/null || true
source /usr/local/Ascend/cann-9.1.0/opp/vendors/custom_transformer/bin/set_env.bash
source /usr/local/Ascend/nnal/atb/set_env.sh 2>/dev/null || true

export SGLANG_ENABLE_TP_MEMORY_INBALANCE_CHECK=0

# ---- Scheduler ----
export SGLANG_SET_CPU_AFFINITY=1
export SGLANG_ENABLE_OVERLAP_PLAN_STREAM=1
export SGLANG_NPU_USE_TRITON_PREFIX_KV_CACHE_STORE=1
export SGLANG_K3_SHARED_EXPERTS_ATTN_TP=1
export SGLANG_NPU_FINE_GRAINED_MOE_DUAL_STREAM=True

export ASCEND_USE_MOJO_MTP=${ASCEND_USE_MOJO_MTP:-1}
export ASCEND_USE_FIA=1
export SGLANG_NPU_USE_MLAPO=0
export SGLANG_NPU_ATTN_BACKEND_NEEDS_CPU_SEQ_LENS=${NEEDS_CPU_SEQ_LENS}
if [ "${USE_FLASH_MLA}" = "1" ]; then
    export SGLANG_NPU_USE_FLASH_MLA=1
    export SGLANG_USE_FIA_NZ=0
    export SGLANG_NPU_USE_FIAS_V2_BSND=0
else
    export SGLANG_NPU_USE_FLASH_MLA=0
    export SGLANG_USE_FIA_NZ=1
    export SGLANG_NPU_USE_FIAS_V2_BSND=1
fi

# ---- DSpark spec v2 ----
export SGLANG_ENABLE_SPEC_V2=1
export SGLANG_RAGGED_VERIFY_MODE=static
export SGLANG_DSPARK_FOLDED_PROPOSAL=0
export SGLANG_DSPARK_FOLDED_SAMPLING=0
export SGLANG_DSPARK_STACKED_CTX_KV=0
export SGLANG_DSPARK_EMBED_IN_GRAPH=0

export PYTHONPATH=/home/w00948925/sglang/python:$PYTHONPATH

MODEL_PATH=${MODEL_PATH:-/home/w00948925/models/reduced12_geo3k_step2_r19_bf16_hf_20260926}
DRAFT_PATH=${DRAFT_PATH:-/home/w00948925/models/RadixArk-Kimi-K3-DSpark}

LOGDIR=${LOGDIR:-/home/w00948925/k3_logs}
mkdir -p ${LOGDIR}
LOG=${LOGDIR}/spec_$(date +%m%d_%H%M%S).log

python3 -m sglang.launch_server \
    --model-loader-extra-config '{"enable_multithread_load": true}' \
    --model-path ${MODEL_PATH} \
    --tokenizer-path ${MODEL_PATH} \
    --trust-remote-code \
    --attention-backend ascend \
    --device npu \
    --dtype bfloat16 \
    --mamba-ssm-dtype bfloat16 \
    --tp-size ${TP} \
    --enable-dp-attention \
    --dp-size ${TP} \
    --enable-dp-lm-head \
    --max-mamba-cache-size 160 \
    --mem-fraction-static 0.95 \
    --chunked-prefill-size 2048 \
    --cuda-graph-bs-decode 32 \
    --max-running-requests 128 \
    --host 0.0.0.0 \
    --port ${PORT} \
    --max-total-tokens 200000 \
    --linear-attn-verify-backend triton \
    --watchdog-timeout 9000 \
    --speculative-algorithm DSPARK \
    --speculative-draft-model-path ${DRAFT_PATH} \
    --speculative-draft-model-quantization unquant \
    --speculative-dspark-block-size 7 \
    --speculative-draft-attention-backend ascend \
    --speculative-eagle-topk 1 \
    2>&1 | tee ${LOG}
```

### 3. Benchmark script

`bench_k3.sh [port] [tag]`, overridable through `MODEL_PATH`, `LOGDIR`,
`SHAREGPT`, `CONC`, `NPROMPT`, `INPUT_LEN`, `OUTPUT_LEN`.

The tables above use `CONC=64 NPROMPT=64`:

```bash
#!/bin/bash
set -e

PORT=${1:-8504}
TAG=${2:-run}

source /usr/local/Ascend/cann/set_env.sh
source /usr/local/Ascend/cann-9.1.0/opp/vendors/custom_transformer/bin/set_env.bash
export LD_LIBRARY_PATH=/usr/local/Ascend/cann-9.1.0/opp/vendors/custom_transformer/op_api/lib/:${LD_LIBRARY_PATH}

export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1

MODEL_PATH=${MODEL_PATH:-/home/w00948925/models/reduced12_geo3k_step2_r19_bf16_hf_20260926}

OUT=${LOGDIR:-/home/w00948925/k3_logs}/bench_${TAG}_$(date +%m%d_%H%M%S).log

python3 -m sglang.bench_serving \
  --backend sglang \
  --host 127.0.0.1 \
  --port ${PORT} \
  --model ${MODEL_PATH} \
  --tokenizer ${MODEL_PATH} \
  --dataset-path ${SHAREGPT:-ShareGPT_V3_unfiltered_cleaned_split.json} \
  --dataset-name random \
  --tokenize-prompt \
  --random-input-len ${INPUT_LEN:-16000} \
  --random-output-len ${OUTPUT_LEN:-1000} \
  --request-rate inf \
  --random-range-ratio 1 \
  --num-prompts ${NPROMPT:-64} \
  --max-concurrency ${CONC:-16} \
  2>&1 | tee ${OUT}

echo "RESULT_FILE=${OUT}"
```
