# [Fix] [AMD] dsa: Limit AITER decode metadata to the active batch

[Upstream PR](https://github.com/sgl-project/sglang/pull/41696) · state: closed · merged: True

## Original PR description

# [AMD] Limit AITER DSA decode metadata to the active batch

## Motivation

The AITER DSA backend preallocates `kv_indptr` for the maximum request-pool
capacity and reuses that buffer for smaller decode batches. The AITER metadata
builder consumes the logical length of the tensor it receives. Passing the
capacity-sized tensor exposes entries beyond the active batch and can construct
invalid persistent MLA work metadata.

On MI355X TP4 with an FP8 KV cache, the invalid metadata caused eager and CUDA
graph execution to fault in:

`aiter::mla_a16w8_qh16_m16x4_n16x1_coex0_mask1_ps`

## Modifications

Pass only the active `bs + 1` entries to the AITER metadata builder:

```python
kv_indptr = kv_indptr[: bs + 1]
```

The backing buffer remains preallocated and reused. This change only corrects
the logical range passed to `get_mla_metadata_v1`.

## Accuracy Tests

AITER is included in the existing registered FP8 DSA decode matrix.

On MI355X TP4 with `amd/GLM-5.2-MXFP4`, FP8 KV cache, AITER DSA prefill/decode,
and CUDA graphs through decode batch 64, the parent revision faulted in
`aiter::mla_a16w8_qh16_m16x4_n16x1_coex0_mask1_ps`. The corrected path
completed 60k-input/600-output eager execution and CUDA graph capture/replay
without the fault. Eager and graph-enabled runs produced identical output.

The serving reproduction used 60,000 input tokens, 600 output tokens,
concurrency 4, 32 prompts, and seed 15.

## Speed Tests and Profiling

This is a correctness fix. No standalone serving-speed improvement is claimed;
decode metadata reuse is submitted separately.

## Reproduction

Launch the parent or candidate revision on MI355X:

```bash
SGLANG_USE_AITER=1 python3 -m sglang.launch_server \
  --model amd/GLM-5.2-MXFP4 \
  --tp 4 \
  --trust-remote-code \
  --attention-backend dsa \
  --dsa-prefill-backend aiter \
  --dsa-decode-backend aiter \
  --dsa-topk-backend sgl-kernel \
  --kv-cache-dtype fp8_e4m3 \
  --page-size 64 \
  --cuda-graph-max-bs-decode 64 \
  --disable-radix-cache \
  --chunked-prefill-size 32768 \
  --max-prefill-tokens 32768
```

Run 60,000 input tokens and 600 output tokens at concurrency 4 with 32 prompts
and seed 15. The parent revision faults during eager execution or CUDA graph
capture/replay; the candidate completes the workload.
