# [Feat] PD: Add Mooncake host-only KV staging for decode

[Upstream PR](https://github.com/sgl-project/sglang/pull/45990) · state: open · merged: False

## Original PR description

## Motivation

In disaggregated serving, allocating decode GPU KV slots before remote transfer completes reserves device capacity for requests that are not yet ready to decode.

This PR enables Mooncake to use the native decode Host-receive path. Incoming prompt KV is received into the HiCache Host pool, and GPU allocation is deferred until restoration admission. Decode prefix caching is not required.

## Modifications

- Register native Host-pool buffers with Mooncake and publish Host destinations through the existing transfer metadata.
- Extend native buffer export to support uncompressed MLA and shared-index DSA, while retaining the existing MHA/GQA/MQA path.
- Reuse native allocation budgets, pool transfer descriptions, and HiCache loading queues to batch H2D restoration.
- Reuse native completion events and cross-rank acknowledgment before admitting restored requests.
- Preserve memory ownership during cancellation, transfer failure, and rebootstrap until outstanding local copies and remote writes are drained.

Enable Host-only staging on decode with:

```bash
--disaggregation-decode-host-receive-threshold 0
--disaggregation-decode-retraction-backup host_pool
```

The default threshold of `1` retains the existing receive behavior. Host-pool capacity is configured through the existing HiCache options.

## Accuracy Tests

Evaluated GLM-5.2-FP8 using the official SGLang evaluation scripts and scoring logic. Both modes used temperature `0`, an output limit of `8192` tokens, and concurrency `32`.

| Benchmark | Baseline | Host-only staging |
|---|---:|---:|
| GSM8K, thinking enabled | 1251 / 1319 (**94.84%**) | Run 1: 1249 / 1319 (**94.69%**); Run 2: 1254 / 1319 (**95.07%**) |
| MMLU, thinking disabled | 12593 / 14042 (**89.68%**) | 12593 / 14042 (**89.68%**) |

All evaluations completed without request errors. Dataset identities, evaluation revision, and generation settings were checked between modes.

On MMLU, 49 questions were correct only in the baseline and 49 were correct only with Host-only staging. These runs show no aggregate accuracy degradation.

GPU validation covered GLM-5.2-FP8 with MLA/DSA. Other model architectures and parallelism combinations have not been fully GPU-validated.

## Speed Tests and Profiling

Tested GLM-5.2-FP8 in a 1P1D deployment, with **TP8/EP8 on both prefill and decode**.

Workload:

- Unmodified `benchmark/hicache/bench_multiturn.py`.
- 32 concurrent conversations across 86 rounds: **2752 requests**.
- Initial input: **32768 tokens**.
- Additional input per round: **1024 tokens**.
- Fixed output: **512 tokens per request**.
- Final conversation length: **163840 tokens**.
- All rounds included, without profiling instrumentation.
- FCFS scheduling in both modes.
- Prefill radix caching and L2 enabled in both modes.
- Decode prefix caching disabled in both modes.
- MTP disabled in both modes.

| Metric | Baseline | Host-only staging | Change |
|---|---:|---:|---:|
| Average TTFT | 2.1934 s | 1.7853 s | **−18.6%** |
| P90 TTFT | 4.1427 s | 3.9820 s | −3.9% |
| P99 TTFT | 21.9316 s | 21.8619 s | −0.3% |
| Output throughput | 1329.67 tokens/s | 1313.88 tokens/s | −1.2% |
| Average TPOT (derived) | 19.6263 ms | 20.7293 ms | +5.6% |

All **2752 requests** completed without errors in both modes. Both runs reported the same prompt-token cache hit rate of **98.0630%**.

The measured benefit is an **18.6% reduction in average TTFT**, with output throughput within 1.2% of the baseline and a 5.6% increase in average TPOT.
