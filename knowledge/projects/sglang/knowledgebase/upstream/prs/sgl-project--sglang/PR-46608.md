# [Perf] [AMD] moe: Add opt-in AITER MegaMoE-TP for eager TP MoE forwards

[Upstream PR](https://github.com/sgl-project/sglang/pull/46608) · state: open · merged: False

## Original PR description

## Motivation

In an eager prefill or extend forward, a TP MoE layer of GLM-5-Next runs three steps: the AITER fused MoE for the routed experts, the shared expert's GEMMs, and the TP all-reduce. AITER's MegaMoE-TP (`aiter.ops.flydsl.mega_moe_tp`, ROCm/aiter#5937, in the pinned AITER `285579b6`) runs all three as one persistent kernel. No SGLang code calls it yet. The existing AMD MegaMoE path is expert-parallel (`--moe-a2a-backend megamoe`) and is not touched here.

This PR adds `--enable-aiter-mega-moe-tp` (default off). With it, eager extend forwards of 1 to 4096 tokens make one MegaMoE-TP call per MoE layer.

Scope:

- Models: `Glm5NextForConditionalGeneration` (e.g. `amd/GLM-5.3-Flash-Quark-MXFP4`) with MXFP4 experts on the AITER MoE runner. With the option on, any other model is refused at load. Not reached: the GLM-5 NextN draft model, the other `DeepseekV2MoE` hosts, CUDA and CPU.
- Platform: ROCm, `gfx950`, TP 2 to 8 on one node. Measured: TP 2 with `--disable-shared-experts-fusion` (shared expert appended, below). This is main's TP 2 default: on HIP, main fuses the shared expert only at TP 4 and TP 8. The fused shared-expert layout is accepted and measured at TP 2 with #46578 (below).
- With the option off, `aiter.ops.flydsl.mega_moe_tp` is not imported and the added hooks return at once.

## Modifications

- New `layers/moe/aiter_mega_moe_tp.py`: gates, shared-expert layout, kernel runner, watchdog and forward hook. It is called from `models/glm5_next.py` (`register` in the decoder layer; the forward hook hands the reduced output to `ffn_boundary.complete_now(..., already_reduced=True)`) and from `model_executor/model_runner.py` (`finalize` after weight loading, not for draft workers).
- The argument and its startup refusals in `arg_groups/` and the server-arguments doc. `SGLANG_AITER_MEGA_MOE_TP_MAX_TOKENS` (default 4096) and `SGLANG_AITER_MEGA_MOE_TP_COMM_DTYPE` (`fp8`, the default, or `bf16`) in `environ.py`.
- Tests: a CPU test of the per-forward gate, and a 2-GPU test against a PyTorch MXFP4 reference. `benchmark/kernels/aiter_mega_moe_tp/` holds the per-layer microbenchmark below.

Behaviour:

- Routing stays in SGLang (`forward_gate` and `topk`): the kernel's fused router needs `E % 64 == 0`, and E is 289 here.
- An unfused, TP-sharded shared expert is preshuffled like the routed experts and appended as slot E at load; a fused one already is the last slot. One `MegaMoeTP` runtime (`comm_mode="ar"`) serves all MoE layers, with every launch configuration prepared at load.
- Every per-forward gate reads a value that is equal on all TP ranks; each stock-path reason is logged once at INFO.
- With the option on, an unsupported setup raises a `ValueError` naming the reason, at startup (e.g. EP, PP, multi-node, attention DP, TBO, HiCache, LoRA, speculative decoding) or at load (e.g. not `gfx950`, not the `aiter` runner, experts that are not MXFP4 gated SiLU).
- The stock path is kept for CUDA graph capture (including `--cuda-graph-backend-prefill breakable`, opt-in on ROCm), for decode (the kernel was slower than stock per layer at batch 32 and 64), and for forwards above 4096 tokens.
- The kernel is persistent and collective, with a 2 s wait limit fixed in the pinned AITER: if a rank reaches a launch more than 2 s after its peer (a first-use compile, a host stall), the next eligible forward raises and the server ends. This happened three times in our GLM-5.3-Flash serving runs. ROCm/aiter#7024 makes the limit configurable, which needs a newer pin.
- Online weight updates are rejected through the existing `_derived_weight_cache_error` hook, because the kernel binds the startup weights.

## Accuracy Tests

fp8 communication is lossy: the MoE partial outputs are quantized to fp8 before the reduction. `SGLANG_AITER_MEGA_MOE_TP_COMM_DTYPE=bf16` keeps them in bf16.

- The added 2-GPU test (TP 2, fp8, small shapes): relative L2 0.047-0.050 and minimum row cosine 0.997 against an fp32 PyTorch reference with the kernel's MXFP4 activation quantization (bound 0.065); identical on both ranks.
- At the GLM-5.3-Flash layer shape (earlier version, same kernel calls), relative L2 against the same kind of reference: stock 0.02, fp8 0.038, bf16 0.003. MegaMoE-TP outputs are bitwise identical across ranks and repeated calls; the stock path's are not (stage-2 atomics).

End to end (setup below): mean probability of the gold answer letter (P(gold)) over 805 single-image multiple-choice MMMU validation items, thinking off, concurrency 1, two patched and two baseline launches per arm, paired by item:
