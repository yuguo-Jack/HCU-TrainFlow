# [Fix] dsv4: Skip DP-attention pad rows in the engram hasher and low-ratio sources

[Upstream PR](https://github.com/sgl-project/sglang/pull/40424) · state: closed · merged: True

## Original PR description

## Motivation

With DP attention and `attn_tp_size > 1`, `prepare_mlp_sync_batch` pads each DP rank's token count up to a multiple of `attn_tp_size`. The pad rows sit after the live tokens, and `extend_seq_lens` covers only the live tokens. Two DeepSeek V4.1 paths did not expect those rows and crashed the scheduler.

### Crash 1: `EngramHasher` on a padded idle batch

An idle DP rank runs an IDLE forward with pad rows to stay in lockstep. `EngramHasher.forward` fell through to `assert mode.is_extend()`:

    engram serves extend, target-verify and decode, not 4

### Crash 2: low-ratio sources on a padded eager extend

At metadata init, an eager extend already builds the low-ratio request ids and positions over the live tokens (`low_ratio_req_indices`, `low_ratio_pos_i64`). With pad rows, `positions` is longer than those rows, so `forward_low_ratio_sources` skipped them and rebuilt request ids with `token_req_indices(num_tokens=positions.shape[0])`. That `repeat_interleave` has an `output_size` larger than the sum of `extend_seq_lens`; the extra ids are uninitialized, and the compressor hit a CUDA device-side assert.

## Modifications

- `forward_low_ratio_sources`: when the prebuilt rows are shorter than `positions`, slice `x`, `q_lora`, and `positions` to those rows, then use the prebuilt request ids and positions. Indexer outputs are reset to -1 before each write, so the pad rows stay masked.
- `EngramHasher.forward`: an IDLE batch takes the same early return as an empty one, with zero hashes, and never writes engram history.

No behavior change on any path where the prebuilt rows are not shorter than `positions`: prefill CUDA graph, eager breaks inside it, the late-layer tail, decode, and target verify. An IDLE batch with tokens previously always hit the assert.

## Accuracy Tests

Model outputs on live tokens are unchanged; only pad rows and idle output, which are discarded, are affected. Selected V4.1 accuracy and unit tests are running through `/rerun-test`. No CI test runs V4.1 with DP attention and `attn_tp_size > 1`, so the crash itself is covered only by the original repro (DP attention, CUDA graph on and off): it ran to completion on the first version of this fix and has not been rerun on the current one.

## Benchmarking and Profiling

No perf impact expected: the idle path returns early, and the padded extend works on fewer rows.
