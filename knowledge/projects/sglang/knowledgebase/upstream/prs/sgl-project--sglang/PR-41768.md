# [Fix] multimodal: Keep every image, video and audio of a request when n > 1

[Upstream PR](https://github.com/sgl-project/sglang/pull/41768) · state: closed · merged: True

## Original PR description

## Motivation

A single request with more than one image, video or audio breaks when `n > 1`:

```python
GenerateReqInput(text="Compare these", image_data=["a.png", "b.png"], sampling_params={"n": 2})
# normalize_batch_and_arguments() -> ValueError: The length of image_data should be equal to the batch size.
```

The same happens on `/v1/chat/completions` with two `image_url` parts and `n=2`: a 400 error, while `n=1` works. For video and audio nothing is raised, but each sample only gets the **first** item (`obj[0].video_data == "v1"`), so the model answers about one video.

Cause: with `n > 1`, `_handle_parallel_sampling` turns a single request into a batch of one and wraps `text` / `input_ids` / `input_embeds`, but not the media fields. The batch helpers then read the request's flat media list as one entry per request. This is the same issue #7830 fixed for `input_embeds`.

## Modifications

`python/sglang/srt/managers/io_struct.py`: when the single request is converted to a batch, also wrap a non-empty flat list in `image_data`, `video_data`, `audio_data`, `mm_hashes` and `mm_content_hashes`. A list already given as one entry per request (`[["a.png", "b.png"]]`), a single non-list item and an empty list keep their current paths, so those requests and `n = 1` are unchanged.
