# [Scheduler] Skip the unread FutureMap seq_lens publish for non-speculative overlap batches

[Upstream PR](https://github.com/sgl-project/sglang/pull/47351) · state: closed · merged: False

## Original PR description

## Motivation

With the overlap scheduler, after `forward_batch_generation` returns for a non-speculative batch, the scheduler calls `self.future_map.publish(future_indices, batch.seq_lens + 1)`. That call writes `FutureMap.new_seq_lens_buf`, but only two places read that buffer:

- `FutureMap.resolve_seq_lens_cpu`, which returns early when `batch.spec_info is None`;
- `FutureMap.resolve_mixed_spec_tails`, which only runs for speculative batches.

For non-speculative batches `publish` records no event and receives no confidence tensor here. Each decode step therefore launches two kernels on the forward stream, `seq_lens + 1` and the scatter, and nothing reads the result.

## Modifications

Remove the non-speculative `publish` call and the comment line that described it. Speculative batches still publish through `on_publish` from inside the worker.

## Accuracy Tests

Overlap scheduling on an out-of-tree platform: non-speculative in eager and graph mode, speculative in graph mode. Non-speculative outputs match the golden tokens. GSM8K stays within baseline noise: 0.8832 against 0.8875 +/- 0.0107 without speculative decoding, and 0.9469 against 0.952 +/- 0.0107 with it.
