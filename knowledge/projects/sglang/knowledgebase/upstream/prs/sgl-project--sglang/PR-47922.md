# [Fix] eplb: Skip draft recording and reuse NPU TP groups

[Upstream PR](https://github.com/sgl-project/sglang/pull/47922) · state: open · merged: False

## Original PR description

## Summary

This follows the NPU EPLB support merged in #47574. It fixes draft passes entering the target model's statistics window and lets NPU EPLB use the existing TP device group when its ranks match WORLD.

Draft recording uses the existing disabled-region context, so GPU and NPU runners follow the same target/draft recording rule. TP-group reuse and the capture guard in this PR are NPU-specific.

## Draft statistics

Target and draft runners share an expert-distribution recorder. Its forward context resets counters on entry and appends a record on exit. The guard inside a draft model runs after that context has entered, so it suppresses the model's hooks but still leaves an empty draft record in the target window. For example, a 200-record window with alternating target and draft passes contains only 100 target observations.

`ModelRunner.forward` now enters `recorder.disable_this_region()` for a draft before entering `recorder.with_forward_pass`. The recorder checks its existing `_disable_all` state on entry and returns an empty result before counter reset, collection or accumulator append. Both real and no-op recorders keep their original method signatures. There is no new parameter, state field or accumulator flag. Runner identity also covers drafts executing a `TARGET_VERIFY` forward.

Target passes keep the existing lifecycle, including valid observations with zero routes. A disabled region inside a target pass still suppresses only that region: target counts before and after it remain in the record. Nested disabled passes preserve the outer counters, and exceptions restore the previous disabled state.

Some NPU capture callbacks call the model directly and bypass the runner's recording context. `capture_one` therefore opens the same disabled-region context for a draft runner, covering both warmups and capture. Its previous capture body moves unchanged to `_capture_one`. This covers the [single-graph multi-step draft path](https://github.com/sgl-project/sglang/blob/56509f096780e7b0506f8b07b3c4b1ae691d14d9/python/sglang/srt/speculative/multi_layer_eagle_draft_extend_cuda_graph_runner.py#L1091), which calls `capture_one` without entering `capture_session`. Existing model-local guards, including DSpark's, remain in place.

## TP group reuse

The default PyTorch WORLD group and SGLang's TP device group are separate communication contexts, even when their members are identical. EPLB previously used WORLD for statistics and weight transfers. This PR passes the existing TP device group to those operations when:

- Distributed initialization is complete and the TP group exists.
- Its ordered ranks are exactly `0..WORLD_SIZE-1`, and its backend matches WORLD.
- Elastic EP is disabled.

This preserves the WORLD rank numbers used by statistics roots, placement maps and migration peers. Other configurations keep `group=None`, which selects WORLD. The existing NPU migration requirement, `TP size = EP size = WORLD size`, still applies; WORLD fallback does not relax that check or add support for arbitrary subgroups or new PP/elastic topologies.

The reused group keeps its HCCL settings. There is no new EPLB group or buffer-size/expansion-mode override. First use of P2P can still allocate backend resources, so reusing a group does not imply zero allocation or a fixed memory saving. Other code that uses WORLD can still activate its resources.

With dynamic EPLB enabled, startup runs one all-reduce and all-peer P2P warmup on the selected TP group before serving and graph capture. Every rank participates, including ranks that have no transfers in the first rebalance. Each submits `2 * (WORLD_SIZE - 1)` send/receive operations; a cached group skips repeated warmup. A final NPU synchronization keeps the small buffers alive until communication finishes. Recording-only use selects the group for statistics without this P2P warmup.

## Code changes

`expert_distribution.py` skips the forward recording lifecycle when `_disable_all` is already set. Its real and no-op recorder interfaces keep their original signatures. `ModelRunner.forward` enters the existing disabled-region context for draft workers before starting that lifecycle. There is no recording decorator.

`hardware_backend/npu/eplb.py` retains TP selection, startup warmup and staging. Its recorder subclass now only selects the communication group and performs the existing warmup. The draft decorator and subclass lifecycle override are removed. The NPU graph backend uses an explicit recording context around capture.

The existing optional-group arguments still carry the selected TP group through statistics collectives and migration send/receive. The placement algorithm, accumulator implementations, weight staging and migration algorithm are unchanged. Shared GPU graph runners are unchanged.

I checked the shared recorder and the GPU call paths. My conclusion is that this is a correctness improvement to target statistics on GPU as well as NPU. It intentionally changes draft recording; it is not limited to the NPU backend.

The recorder belongs to the target model. Existing `ModelRunner` initialization already skips target expert-location/recorder initialization and EPLB-manager creation for draft workers. Draft forwards still reach the process recorder, however. Previously, a model-level `disable_this_region()` suppressed hook writes without skipping the outer forward's reset/collect/append lifecycle. A draft could therefore append an empty row to the target's rolling window. Drafts without that local guard can also contribute their own counts. Neither belongs in the target's EPLB window.

This argument makes the ownership explicit:

```python
enabled=not self.is_draft_worker
```

| Call | Recorder behavior after this change |
| --- | --- |
| Normal target forward | Original reset, hook, collect and append sequence. |
| Draft through `ModelRunner.forward()` | Skip reset, hook writes, collect and append. The model forward still executes. |
| No-op recorder (recording not configured) | Accept the argument and continue the model forward without collecting statistics. |
| An explicitly disabled scope | Skip the recorder lifecycle while the scope is disabled. |

For the normal target case, I compared the AST with the pre-refactor version: the lifecycle body after the new early-exit branch is identical. The benefit is that draft calls no longer consume entries in the target's rolling window or touch its counters through that lifecycle. This is a statistics-correctness benefit; I have not measured a GPU throughput improvement.

I used the runner's role rather than the batch mode because draft work can also use `TARGET_VERIFY`. I kept `disable_this_region()` as a local suppression mechanism: disabling part of a target forward must not discard valid counts collected before and after that region. There is no new accumulator flag or filtering rule, and genuine zero-count target records are retained. See the [recorder entry](https://github.com/AkiYangDev/sglang/blob/17b8f6192c04a45c706a1804fdd1a19a33fd8cc9/python/sglang/srt/eplb/expert_distribution.py#L256-L286) and [runner call](https://github.com/AkiYangDev/sglang/blob/17b8f6192c04a45c706a1804fdd1a19a33fd8cc9/python/sglang/srt/model_executor/model_runner.py#L1909-L1924).

I also checked capture separately from replay:

- EAGLE multi-step capture calls `eagle_worker.draft_forward()` and then `draft_runner.forward()`. The new exclusion is therefore active while those model operations are captured.
