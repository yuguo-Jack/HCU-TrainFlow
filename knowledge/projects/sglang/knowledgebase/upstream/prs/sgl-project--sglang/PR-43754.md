# [Feat] eplb: Add a rebalance limit to freeze expert placement

[Upstream PR](https://github.com/sgl-project/sglang/pull/43754) · state: open · merged: False

## Original PR description

Add `--eplb-max-rebalance-count K`: after K rebalances, EPLB freezes the expert layout and stops recording. This removes the periodic global stall for deployments that only need a few rebalances.

## Motivation

EPLB rebalances every `--eplb-rebalance-num-iterations` passes for the whole life of the server, and each rebalance stalls all EP ranks. Some deployments only need a few rebalances, but cannot use a precomputed `--init-expert-location` either: the expert load depends on that deployment's live traffic, and there is no representative offline trace. Once real traffic has been seen, the distribution is stable. Later rebalances mostly chase window noise, and each one still costs a stall.

DeepSeek-V4-Pro FP4 on MI355X, MegaMoE prefill EP8, agentic trace, conc 512, rebalance every 200 passes:

- Balancedness (mean/max GPU load) goes from 0.711 (trivial layout) to 0.973 after the 1st rebalance and 0.983 after the 2nd. With K=1 frozen for ~2 h it stays at 0.93-0.99 (median 0.967), with no drift.
- Unlimited rebalancing stalls 3.7-4.5 s each time (up to 15.5 s), every 3-4 min, for ~66 s per hour.
- With K=1 or K=3, the prefill speed-up from EPLB stays within 0.6% of unlimited, with zero stalls in steady state. End-to-end throughput differences were within noise.

## Modifications

- New server arg `--eplb-max-rebalance-count` (default 0 = no limit, must be >= 0), with a doc row.
- `rebalance()` returns whether the layout was updated, so only executed rebalances count. A skipped one (disabled, mid elastic-EP scale, above the utilization threshold) does not.
- After K rebalances the generator stops the recorder and only yields. `reset_generator()` (elastic EP) restarts the budget and the recorder.
- The frozen layout stays applied: the remap in `select_experts` is gated on `enable_eplb`, not on the recorder. All ranks freeze on the same pass, because the generator advances in lockstep.
