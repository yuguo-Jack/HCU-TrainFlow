# [Feature] multimodal: [sglang-miles] Item feature cache key sanity check

[Upstream PR](https://github.com/sgl-project/sglang/pull/48286) · state: open · merged: False

## Original PR description

## Motivation

A cache key that leaves out something the features depend on returns another item's features without any error, and nothing downstream can tell.

## Modifications

- `TokenSpaceProcessor.HIT_CHECK_RATE = 1 / 100`: one hit in a hundred is treated as a miss, loaded and processed again, and compared with the cached value field by field: the same keys, and every tensor field equal in dtype and value (`torch.equal` on the CPU). A difference raises `RuntimeError` naming the modality and the field, so a bad key fails a request instead of training on wrong features. The checked value is not written back.

## Tests

`test_mm_token_expansion.py`: a checked hit is loaded like a miss, equals the cache and is not rewritten; a cache holding other `pixel_values` raises. The test helper pins the rate to 0 so the load counts of the other cases stay deterministic.

Run on the H200 devbox: `test_mm_token_expansion.py` and `test_preprocess_cache.py`, 58 passed.

End to end (geo3k as in #48285, 15 steps, disk cache): 76 of 9955 hits were recomputed, all equal to the cache; data preprocess 0.56 s (0.51–0.53 s without the check), step time 92.7 s, logprob abs diff 0.0113, reward 0.317.

After #48285. Main port: #48288.
