# Fix autograd retention in CUDA graph capture tail hooks

[Upstream PR](https://github.com/sgl-project/sglang/pull/43854) · state: closed · merged: True

## Original PR description

## Motivation

CUDA graph capture tail hooks run after the model forward returns, outside the forward's no-grad scope. The scheduler's event-loop grad-mode guard does not cover startup graph capture either. As a result, hooks that use trainable parameters can build autograd history during warmup and capture even though the model forward itself disables gradients.

For example, `DsparkDraftSampler` computes Markov corrections and confidence scores using parameters with `requires_grad=True`, then copies the results into persistent output buffers. Without no-grad, these writes attach `CopySlices` history to the buffers and keep saved tensors from successive warmup/capture calls alive. With Qwen3-8B + DSpark and a decode capture limit of 256, disabling grad during startup capture eliminates this history and reduces ready-process GPU memory by **806 MiB**.

## Modifications

- Decorate `Scheduler.init_all_cuda_graphs` with `@torch.no_grad()`. It is the single startup entry for CUDA graph capture of the target and draft workers, so everything capture runs around the model forward (tail hooks, input preparation, draft-worker graphs) no longer records autograd history. Recapture after startup already runs inside the guarded event loops.
- Plain `torch.no_grad` rather than `DynamicGradMode`: with `SGLANG_ENABLE_TORCH_INFERENCE_MODE=1`, buffers created during capture would become inference tensors, which the `no_grad` disagg event loops cannot write in place.

## Speed Tests and Profiling

A/B configuration:

- Hardware: one NVIDIA H20, TP=1.
- Target model: `Qwen/Qwen3-8B`.
- Speculative decoding: `--speculative-algorithm DSPARK`, with draft model `deepseek-ai/dspark_qwen3_8b_block7`.
- Attention backends: `--attention-backend fa3 --speculative-draft-attention-backend fa3`.
- Ragged verify: `SGLANG_RAGGED_VERIFY_MODE=compact`.
- Capture and concurrency limits: `--cuda-graph-max-bs-decode 256 --max-running-requests 256`.
- Captured buckets: default prefill graphs enabled, with 58 token buckets up to 8192; target verify and draft decode each use 51 sparse request buckets up to 256.

Only the no-grad guard differs between the two runs.

| Measured quantity | Without no-grad | With no-grad | Reduction |
| --- | ---: | ---: | ---: |
| Server process GPU memory after startup | 91.171875 GiB | 90.384766 GiB | **806 MiB** |
| Physical GPU memory added during draft graph initialization (warmup + capture) | 2,684 MiB | 1,878 MiB | **806 MiB / 30.03%** |
| Autograd nodes retained by persistent sampler output buffers after capture | 7,501 | 0 | 7,501 |
| GPU storage kept alive for backward by those buffers (excluding model parameters; counted once per storage) | 1,648.319 MiB | 0 | 1,648.319 MiB |

The first row includes model weights and KV cache. The last row measures retained tensor storage; its reduction need not equal the physical memory reduction because the allocator can keep freed storage for reuse. No inference-speed benchmark or full accuracy evaluation was run.

### Single H200 re-check of the scheduler-level guard

| Variant | Server process GPU memory (MiB) | Draft verify graph capture (GB) | Target prefill + verify capture (GB) |
