# [Fix] [NPU] modelslim: Fix grouped W4A8 MoE loading and TP scale sharding

[Upstream PR](https://github.com/sgl-project/sglang/pull/46270) · state: open · merged: False

## Original PR description

## Motivation

**What goes wrong without this patch.** DeepSeek-R1-0528 ModelSlim W4A8 ([Modelers_Park/DeepSeek-R1-0528-w4a8](https://modelers.cn/Modelers_Park/DeepSeek-R1-0528-w4a8), `group_size=256`) loads and starts on Ascend A3, but it does not produce a usable answer:

- Setup: one A3 server, the DeepSeek-R1 Cookbook recipe, SGLang `d9ce511`.
- Request: a plain chat prompt, `What is 2+3? Give only the number.`
- Result: `content` is empty and `finish_reason` is `length` (at 1024 completion tokens). `reasoning_content` contains repetitive text, and the model never gives a final answer.

With this patch, the same setup answers `5` with `finish_reason: "stop"` and passes all 10 functional checks (plain, streaming, sequential, multi-turn and concurrent requests). The full GSM8K results are below.

**Why.** The grouped W4A8 MoE loading path has three issues:

1. `ModelSlimConfig.get_moe_scheme` instantiates every MoE scheme with `cls(self, weight_group)`. `ModelSlimW4A8Int8MoE` therefore never receives the checkpoint's `group_size` or the layer's `moe_tp_size`, so it falls back to per-channel handling (`group_size` 0) for weights that are quantized in groups of 256.
2. `NPUW4A8Int8MoEMethod._process_scale` unpacks `group_num, k, n = weight.shape` and doubles `n`, but at this point the weight is still `[E, packed_out, in]`. The doubled dimension is the input size, so the group scales are reshaped with the wrong width.
3. Group scales, offsets and scale biases are registered as per-channel parameters. The w2 per-channel loader copies the full checkpoint tensor without TP slicing, even though these buffers shrink with `moe_tp_size`. For example, at MoE TP=4, a `[N, 16]` scale bias is copied into a `[N, 4]` buffer.

The factory and scale-reshape lines are identical in `d9ce511`, `8e3e2980d` (the SGLang inside `quay.io/ascend/sglang:main-cann9.1.0-a3`) and `bb72b47`, so `main` (checked at `a99eaf9a`, 2026-10-24) and the image (digest `sha256:9e653832d34f058a0035b5009fe8efcd61358c72fec5cf7412df7a236ff544ae`) contain the same code. The empty-answer symptom was reproduced end to end on `d9ce511`; for the other revisions the affected lines were verified by source comparison.

Related Cookbook task: Ascend/sglang#1206.

## Modifications

- `modelslim.py`: for `ModelSlimW4A8Int8MoE`, pass `group_size` from the quantization description and `tp_size=layer.moe_tp_size`.
- `moe_methods.py`: take `n` from the packed output dimension (`group_num, n, _ = weight.shape`).
- `modelslim_w4a8_int8_moe.py`: mark group scales, offsets and scale biases for the existing GROUP loader, so w2 input partitions are sliced by MoE TP rank. Per-channel scales remain replicated; presharded checkpoints are loaded without another slice.
- `test_npu_modelslim_grouped_w4a8.py`: five unit tests covering group-size/TP-size passthrough, scale shape/packed values, and actual scale loading for grouped and per-channel checkpoints. Loading tests cover TP=1/4, every rank, both projections, two experts and full/presharded tensors.

The original three tests fail on `bb72b47` (two assertion failures and one error: `0 != 256`, `1 != 4`, and a scale width mismatch of 32 versus 128). The two additional loading tests expose 32 failing subcases before the TP loader correction. All five tests pass on A3 with the final change, using real PyTorch CPU tensors and the production parameter-creation and loader code.

Run the unit tests from the repository root in the Ascend environment:

```bash
PYTHONPATH=python python3 -m unittest -v \
  test.registered.npu.basic_function.quant.test_npu_modelslim_grouped_w4a8
```

## Accuracy Tests

DeepSeek-R1-0528 W4A8, Atlas 800T A3, SGLang `bb72b47` with the configuration and scale-layout fixes, full GSM8K test set (1319 questions, `sgl-eval==0.1.3`, thinking on, 16384 output tokens, temperature 0.6, top-p 0.95, seed 1, concurrency 64, context length 32768):

| Deployment | Correct | Score | finish_reason |
| --- | --- | --- | --- |
| 1×A3, PD co-located | 1257/1319 | 95.30% | 1318 stop, 1 length |
| 2×A3, PD disaggregated | 1256/1319 | 95.22% | 1319 stop |

Both runs had zero request errors and used MoE TP=1. The TP scale-sharding change is covered by the five unit tests above.
