# [AMD][Fix] Incorrect vision token counting

[Upstream PR](https://github.com/sgl-project/sglang/pull/38035) · state: open · merged: False

## Original PR description

## Motivation

`bench_serving --dataset-name image` reports a vision-token count that is wrong by two orders of magnitude for a whole class of VL models, and gives no sign that it has. 

Measured on `amd/MiniMax-M3-MXFP4` (`MiniMaxVLProcessor`, no processor-level chat
template, tokenizer template present, `image_token_id=200025` → `]<]image[>[`),
512x512 images:

| | `prompt_len` | `text_prompt_len` | `vision_prompt_len` |
| --- | --- | --- | --- |
| before | 5 | 2 | **3** |
| after, 1 image | 504 | 178 | **326** |
| after, 2 images | 830 | 178 | **652** |

**Why this matters.** Multimodal performance measurements without it are not reliable because 
`total_input_vision_tokens`, `total_input_text_tokens` and every input-tokens/s figure derived from them are off
by two orders of magnitude, so a run publishes an input-side throughput number that
is wrong by ~100x while looking entirely healthy.

That makes this a prerequisite for trusting any `--dataset-name image` result,
including the VL benchmark numbers in the MiniMax-M3 optimization series (#41662,
#41663, #41664, #41672), all measured on this dataset path with this model.
#37732 is the companion fix, stopping media placeholders leaking into randomly
sampled prompt *text* where they cause silent HTTP 400 request loss; different files
(`common.py` vs `image.py`), neither depends on the other.
