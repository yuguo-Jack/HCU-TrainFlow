# [Perf] HiSparse: elide unused shared-layer indexer key buffers

[Upstream PR](https://github.com/sgl-project/sglang/pull/48333) · state: open · merged: False

## Original PR description

## Motivation

GLM shared-indexer layers reuse another layer's top-k result and do not write their own indexer keys. HiSparse currently disables the existing shared-layer index-K elision policy, so it still allocates logical-length index-K buffers for those layers. For a 78-layer GLM layout with 21 full indexers, this allocates 57 unused buffers.

## Modifications

- Add opt-in `SGLANG_ENABLE_HISPARSE_INDEX_K_ELISION=1` (default off).
- Restrict it to CUDA `glm_moe_dsa` target workers in PD decode, with PP/attention CP/DCP all 1, no external cache linker, and a valid full/shared indexer layout beginning with a full indexer. Draft workers keep their own storage. Unsupported configurations retain the old allocation policy.
- Apply the same eligibility policy to actual index-K allocation and token-pool memory budgeting. Leave target attention KV and independent draft KV/index-K intact.
- Preserve layer-aligned zero-row placeholders and raw getter behavior, including transfer-counter advancement. Reject attempts to run indexer read/write kernels on shared layers; do not confuse non-owned CP layers with shared layers.
- Log the active indexer-layer count and allocated index-K bytes.

Enable the flag on the decode engine before launch. It is independent of the HiSparse swap-in prefetch flag. An explicit `--max-total-tokens` cap still limits the resulting logical capacity; elision does not remove that cap or change the model context length.

## Speed Tests and Profiling

This change reduces allocated index-K storage; it does not change top-k computation. For the tested GLM layout, active target index-K buffers drop from 78 to 21, reducing that component's storage by 57/78 (about 73%). This is not a 73% reduction in total GPU memory. No inference-throughput claim.
