# [Fix] embedding: Force full recompute when pooling reads inside a cached prefix

[Upstream PR](https://github.com/sgl-project/sglang/pull/46711) · state: open · merged: False

## Original PR description

## Motivation

When an embedding request reuses a cached prefix, the scheduler recomputes only the suffix of the sequence (the match is capped one short of the input, so at most the last token is guaranteed). The pooler then indexes the produced hidden states as if they covered the full sequence. With CLS or MEAN pooling, pooled classification scores, or request-level pooling positions, the rows the pooler reads were never recomputed, so the request silently returns the hidden state of the wrong tokens.

Reproduced on current main with BGE-small on CPU (no GPU needed), two identical `[10, 11, 12]` requests to `/encode`:

- first request (cold cache): `[-0.0645, -0.0517, 0.0350, ...]` — the correct CLS embedding
- second request (prefix hit, recomputes only token 12): `[-0.0542, -0.0084, 0.0228, ...]` — token 12's hidden state, wrong

Every identical request after the first returns the wrong value until the entry is evicted. LAST pooling is unaffected because the last token is always recomputed.

## Modifications

- `EmbeddingModelSpec.pooling_may_read_prefix`: true for CLS/MEAN pooling, bidirectional attention (whose cached KV is itself only valid for the original full sequence), and classification execution.
- `Req` carries the flag from `model_config.embedding_model_spec`, and `_compute_max_prefix_len` returns 0 for it — and for requests with `token_indices_to_pool` or `multi_item_delimiter_indices` — forcing a full recompute instead of a prefix match.
- LAST-pooling models (llama/qwen-style decoder embeddings) keep reusing prefixes; pinned by tests.
- New CPU unit test `test_embedding_prefix_pooling.py` for the spec property and the Req guard.

## Accuracy and Benchmark

- Same CPU BGE-small server after the fix: identical requests now return identical embeddings on cold and warm cache (all equal to the cold-cache value above).
- `pytest test/registered/unit/managers/test_embedding_prefix_pooling.py` — 8 passed; existing `test_embedding_model_spec.py` — 7 passed.

Deliberately out of scope: these models still write KV that nobody reads back (harmless; skipping the write can be a follow-up), and the unrelated #4753 warmup workaround is untouched (its "embedding errors for list of size 1" premise no longer reproduces — batch-of-1 works today).
