# [Fix] hicache: tolerate concurrent file storage directory creation

[Upstream PR](https://github.com/sgl-project/sglang/pull/44422) · state: open · merged: False

## Original PR description

## Motivation

Two file-backend creators (for example, TP rank 0 in different PP stages) can both observe a missing shared storage directory. The second `os.makedirs` then raises `FileExistsError` during initialization.

## Modifications

Use `exist_ok=True` for directory creation. Keep the existing TP/CP rank guard, path precedence and error propagation unchanged. Add a deterministic CPU regression that pauses both real existence checks before either worker creates the directory, plus existing-directory, nonzero-rank and permission-error controls.

## Tests

Linux, Python 3.12, Torch 2.11.0: 40 tests across the new directory test and the existing file-LRU/path-routing files. The unchanged baseline has 39 passes and one error wrapping the expected race assertion (`FileExistsError`); the final commit passes all 40 with no skips. Exact package/source hashes were checked before and after; no production stubs, installs, model downloads or GPU work. This is component coverage, not an engine-startup or model benchmark.

Standalone Ruff checks/format, isort and the three repository test-registration/entry-point checks passed. File-scoped pre-commit could not fully finish on Windows: its Ruff executable was blocked by application control and three hooks could not find `python3` (those Python checks passed separately). Hosted CI is still needed.
