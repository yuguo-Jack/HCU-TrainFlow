# Keep positional-readout requests out of chunked prefill

[Upstream PR](https://github.com/sgl-project/sglang/pull/41724) · state: closed · merged: False

## Original PR description

## What

Requests that carry `token_indices_to_pool` (positional-readout / setwise scoring, as used by decision-model serving) must not be split by chunked prefill. When a batch fills past `--chunked-prefill-size` (default 8192), the last admitted request is chunked; its readout positions index the whole prompt, so they point past the chunk's hidden states and crash the scheduler with a CUDA `vectorized_gather_kernel` index-out-of-bounds assert.

The rule is 5 lines in `PrefillAdder._select_prefill_admission`: such a request returns `AddReqResult.OTHER` and waits for the next batch, as long as its prompt fits one chunk. Larger prompts keep today's behavior.

## Why now

#41712 (decision-model serving) generates these requests at concurrency and hit the crash in its first 32-way e2e run. The existing setwise e2e tests all run with `chunked_prefill_size=-1`, so this path was never exercised. Landing it separately keeps the serving PR reviewable.

## Test

`test_prefill_adder.py::test_readout_request_waits_instead_of_being_chunked` fails on the pre-fix code and passes with the fix. The 32-concurrent workload that produced the crash now completes with 0 errors.
