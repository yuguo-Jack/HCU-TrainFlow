# [Perf] dsv4: Let the fused MXFP8 producers run inside the breakable prefill graph

[Upstream PR](https://github.com/sgl-project/sglang/pull/45980) · state: closed · merged: True

## Original PR description

- `fused_mxfp8_rows` decides when the fused producers write the next DeepGEMM consumer's MXFP8 input directly. Extend batches took the fused path in eager prefill, but not inside a breakable prefill graph, so graph prefill (the low-concurrency shapes) still wrote bf16 and quantized it in a separate pass before `wqkv_a`.
- The prefill graph captures with the extend flag cleared, so the check also counts the prefill graph scope (`is_in_prefill_graph_scope()`): extend batches now take the fused path inside the graph as well.
- The mHC boundary producer runs in a captured segment and its consumer reads the pair as ordinary graph tensors, so it needs no special handling there. The attention output producer is unchanged in the graph: the mega attention runs inside an eager break that writes a captured bf16 buffer.

With this, graph prefill and eager prefill run the same producers and the same `wqkv_a` GEMM, so a prefill batch computes the same values whether or not it replays a graph. Against the previous graph path, `wqkv_a` moves from FlashInfer's quantize-and-GEMM to the DeepGEMM MXFP8 GEMM that eager prefill already uses, so graph prefill outputs are not bitwise equal to before; they now match eager prefill's path.

Verification:
- Inside graph replay and in eager prefill, the fused boundary's MXFP8 pair matches a standalone per-token-group quantize of the same normalized rows: the fp8 bytes match exactly, and the scale bytes match on every group that holds data (they differ only on all-zero groups, which decode to zeros either way).
- A GPU profile of graph prefill shows the standalone quantize before `wqkv_a` gone; the remaining standalone quantize calls feed `wo_b`, whose producer stays bf16 inside the attention break.
- DeepSeek-V4.1-Flash prefill with the breakable graph captures and replays every batch with the fused producers, with no OOM at the recipe memory fraction, and GSM8K is unchanged. `test_deepseek_v4_pipeline.py` and `test_deepseek_v4_boundary.py` pass.
