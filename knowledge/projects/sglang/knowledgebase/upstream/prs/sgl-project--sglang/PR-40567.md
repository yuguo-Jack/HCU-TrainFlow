# [Feat] dspark: Enable DeepSeek-V4.1 dynamic verify on PD decode

[Upstream PR](https://github.com/sgl-project/sglang/pull/40567) · state: open · merged: False

## Original PR description

DeepSeek-V4.1 DSpark rejects dynamic verify on PD decode. This enables `compact`
and `cap-accept` on decode while keeping prefill static and preserving main's
Mooncake/NIXL, attention-DP and interleaved Prefill-CP validation.

The attention TP group broadcasts the chosen budget before selecting the layout
and graph tier. The SPS profiler accepts a separate decode control URL: generation
uses the PD router, while budget updates, observations, abort and reset reach
decode. Observations distinguish logical target rows, padded input rows and the
CUDA graph capacity actually replayed. Off-diagonal profiling rejects eager
fallback, ineffective budget pins and inconsistent execution geometry.

### Dependencies and calibration fixes

- Retains merged #42709 and reuses #42718's packed-token request mapping and
  Engram extend path, preserving the original commit authorship. There is no
  parallel mapping kernel in this PR. It also includes #42711's pinned-budget
  corrections. Both dependencies remain open; their commits can be dropped
  after they merge.
- `dspark_force_budget_frac: null` now resets the pin through HTTP/msgpack.
  Other null updates remain invalid, and invalid mixed updates are atomic.
- Real calibration found that the normal survival cutoff could leave a forced
  budget underfilled. Profiling pins now retain confidence ranking with cutoff
  zero, including zero-probability prefixes; reset restores the normal policy.
- The profiler matches the server's fractional-budget multiplication order,
  avoiding the B12/0.7 truncation mismatch (41 vs 42 draft slots).

### Validation

Final head `7b8d4f061a` is based on main `eae134d61f`. **120 focused tests and
75 subtests pass**, including real CUDA graph replay of both layout variants,
changing request layouts, short/empty rows, padding, and a real Gloo subgroup
whose leader is global rank 1. Pre-commit passes.

Full-model checks on H20 TP8/EP8 with released DeepSeek-V4.1-Flash weights:

- Compact graph/eager top-1 agrees at 78/78 monolithic positions and 149/149 PD
  positions, including a separate 30K-context probe. All compared logits are
  finite. PD graph repeats are bitwise equal at those 149 positions.
- Real Engram hashes agree across graph/eager/repeat, all 42 independent
  target-only prefixes and all 78 compact/static aligned positions. PD batches
  are aligned by request ID and token position across split/reordered layouts.
- **Full-model target-only parity is not established:** compact/target-only
  top-1 is 38/42; static/target-only is 36/42; compact/static is 73/78. Static
  graph/eager is 78/78. Monolithic compact graph/eager has weighted MAE 0.07658
  and max absolute error 4.24219; target-only MAE is 0.92134 and max error 14.75.
  A BF16 MoE diagnostic did not eliminate differences and was not full-model
  BF16. These checks establish mapping/history consistency, not losslessness.
- The full-model probes use `4e6b50e506` on main `306ccf6f57`, before the isolated
  forced-pin/profiler corrections. The final main refresh changes GLM chat
  templates, NPU attention and tests; the native token-ID H20 path is unchanged.
  All 20 PR files are byte-identical across that final rebase. Formal decode
  uses final HEAD; static prefill remains on `4e6b50e506`.

SPS was recalibrated using actual replayed graph rows: **25 fit cells, numeric
rank 12/12; fit median/max error 1.00%/3.05%**. Ten independent hold-outs pass
median/max 1.55%/12.31%; two additional graph-tier checks pass at 1.86%/2.18%.
Every captured tier has a physical measurement, with at least 10 measured steady
seconds per valid cell. Invalid underfilled/rounding attempts are retained and
excluded. Logical costs expand through graph buckets, so the table invents no
savings within a fixed replay tier. Simulated AL1 is used only for cost fitting.

### PD measurements

Two poc-beijing nodes, 8 H20 GPUs per role, TP8/EP8, attention DP1, Mooncake,
1P1D, full verify width 6, Decode max-running 16. Default folded proposal and
overlap, no simulated acceptance, forced budget or diagnostic hooks. Frozen
16 public LongBench-v2 inputs span 12,678–30,324 tokens; caches are flushed per
trial. Each fresh process has an untimed identical warmup. No request retries.

| Client concurrency | Original paired E2E TPS gains | Mean API TPOT reductions | Strict draft AL, static → compact |
|---:|---:|---:|---|
| 1; N16/output512 | +0.39%, −0.07% | +0.42%, −0.41% | 2.416 → 2.488; 2.478 → 2.496 |
| 16; N64/output1024 | +8.59%, +5.90% | +7.41%, +9.02% | 2.661 → 2.346; 2.658 → 2.360 |

A separate C64/N64/output1024 pair gives **+0.86% E2E TPS**, API TPOT
8.461 → 7.516 ms (−11.17%), and strict draft AL 2.742 → 2.422. Static/compact
have sampled continuous B16 windows of 24.8/15.8 seconds, but whole-trial full
coverage is only 56.1%/37.5%, below the 95% gate. This pair is not pooled with
ABBA. Its first attempt lost Decode GPU monitoring during compact startup;
that coverage failure is retained, and both arms were repeated with identical
settings after repairing the sampler. All 448 requests in the original ABBA
and replacement pair completed with zero failures/retractions and complete
GPU monitoring. Independent raw-record aggregation and OLS fitting verify all
37 SPS points and all 1,248 requests, including warmups and excluded trials.

Original C16 mean paired E2E gain is 7.24%; C1 is effectively unchanged. These
are complete client-workload results, **not stable B16 decode-only claims**:
none of the original trials achieves a continuous sampled 10-second full-target
window or 95% whole-trial coverage. C16 repeats the 16 inputs four times and
reuses about 72–73% of prefill tokens within each trial; this is not a cold,
unique-prompt workload. API TPOT is derived from native `decode_throughput`,
not isolated GPU kernel time. Strict draft AL excludes the bonus; AAL = AL +1.

Complete output strings differ on every original static/compact comparison. Same-mode
repeats also have 0/16 (C1) and 0/64 (C16) exact matches for both static and
compact. Baseline variability does not establish task-quality equivalence.
No answer-quality score or lossless guarantee is claimed. NIXL, attention DP
and Prefill CP have configuration-test coverage only. H20 does not activate
DSv4.1's Blackwell candidate graph variants; the two-variant CUDA regression
covers their layout/mapping geometry, not Blackwell full-model execution.
