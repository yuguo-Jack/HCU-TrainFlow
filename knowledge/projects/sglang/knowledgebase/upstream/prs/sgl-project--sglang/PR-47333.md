# [Fix] Spec: Fall back to eager when the ragged-verify tier exceeds the captured grid

[Upstream PR](https://github.com/sgl-project/sglang/pull/47333) · state: closed · merged: True

## Original PR description

## Motivation

#34038 moved the ragged-verify tier resolution into `DSparkVerifyPlanner._resolve_verify_tier`, which calls `round_up_grid` on the token floor. `schedule_layout` now calls that helper before its `ragged_layout_exceeds_captured_grid` check, so when the floor is above `capture_num_tokens[-1]`, `round_up_grid` raises `ValueError` and kills the scheduler instead of falling back to eager.

This happens in COMPACT ragged verify with confidence scheduling (not verify-all) whenever a decode batch is larger than the captured CUDA-graph grid, for example `--max-running-requests` > `--cuda-graph-max-bs-decode`. Before #34038 the exceeds check ran first and returned `None` (eager).

```
File ".../dspark_planner.py", line 432, in schedule_layout
File ".../dspark_planner.py", line 533, in _resolve_verify_tier
File ".../ragged_verify.py", line 38, in round_up_grid
ValueError: total 255 exceeds max grid tier 32; the caller must reject this batch before selecting a graph tier
```

## Modifications

- `_resolve_verify_tier` runs `ragged_layout_exceeds_captured_grid` itself and returns `exceeds_captured_grid`. When the tier exceeds the grid, it skips `round_up_grid` and returns `graph_num_tokens=None`.
- `schedule_layout` returns `None` (eager) on `tier.exceeds_captured_grid`, so the exceeds check and the rounding share one source.
- `_budget_aligned_to_graph_tier` already returns the budget unchanged when `graph_num_tokens is None`, so with `speculative_dspark_align_verify_tokens_to_graph_tier` on, oversized batches no longer raise there either.
- Added CPU unit tests in `test_dspark_scheduler.py`: tier resolution past the grid (no hint and DP tier hint), `schedule_layout` falling back to eager, and the aligned budget staying unchanged.

## Accuracy Tests

Not affected: the change only turns a crash into the eager fallback that existed before #34038.
