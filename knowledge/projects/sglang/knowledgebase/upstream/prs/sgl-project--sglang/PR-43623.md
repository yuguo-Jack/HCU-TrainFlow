# [DSpark] Apply `SGLANG_SIMULATE_ACC_LEN` inside the accept instead of switching paths

[Upstream PR](https://github.com/sgl-project/sglang/pull/43623) · state: closed · merged: True

## Original PR description

- The simulated correct length is drawn once per step before target verify and staged into the verify epilogue, which replaces the accepted length inside the folded accept; the eager accept applies the same value.
- A simulated run therefore takes the same graph and kernels as a served run, so its TPOT measures the production path.

Behavior change: `SGLANG_SIMULATE_ACC_LEN` runs no longer fall back to the eager accept, so their TPOT numbers change.

## Verification

- On the full DSpark draft stack, DeepSeek-V4.1 TP4 on GB300 with `SGLANG_SIMULATE_ACC_LEN=3.51`: all 880 requests at concurrency 1, 16 and 64 succeed and the logged accept length is 3.49-3.51.
