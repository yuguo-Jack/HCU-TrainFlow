# [Perf] entrypoints: Avoid O(N^2) request body chunk concatenation in RequestDecompressionMiddleware

[Upstream PR](https://github.com/sgl-project/sglang/pull/48027) · state: open · merged: False

## Original PR description

## Motivation

In `python/sglang/srt/entrypoints/http_request_decompression.py`, `RequestDecompressionMiddleware.__call__` reassembles incoming compressed ASGI `http.request` chunks on the asyncio event loop before dispatching `_zstd_decompress` to a worker thread:

```python
body = b""
more_body = True
while more_body:
    message = await receive()
    if message["type"] != "http.request":
        return await self.app(scope, receive, send)
    body += message.get("body", b"")
    more_body = message.get("more_body", False)
```

Because `message` is a `dict` (making `message.get("body", b"")` have refcount > 1 while stored in `message`), CPython's in-place `bytes` resize optimization cannot trigger on `body += message.get("body", b"")`. Every chunk therefore allocates a new `bytes` object and copies the entire prefix accumulated so far, resulting in **$O(K \cdot B)$ ($O(N^2)$) memory copying directly on the main asyncio event loop** when receiving large zstd-compressed requests (such as base64 multimodal image/video/audio payloads or large batch prompts split across 16 KB–64 KB HTTP chunks).

## Modifications

- Accumulate incoming `http.request` chunks into `chunks = []` and concatenate them in a single pass via `body = b"".join(chunks)` once `more_body` is `False`.
- Add unit tests in `test/registered/cpu/test_request_decompression.py` covering many small chunks, interleaved empty chunks, and verifying single-pass `b"".join` without pairwise `+=` concatenation.

### Benchmark (32 MiB zstd-compressed payload across ASGI chunks)

| ASGI Chunk Size | Before (`body += chunk`) | After (`b"".join(chunks)`) | Speedup |
|---|---|---|---|
| 64 KB (512 chunks) | 2.65 s | **0.043 s** | **61.6x faster** |
| 16 KB (2,048 chunks) | 6.73 s | **0.041 s** | **164.1x faster** |
