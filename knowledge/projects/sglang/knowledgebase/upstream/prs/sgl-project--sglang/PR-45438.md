# [Fix] disaggregation: Transfer the draft's DSA indexer cache for hybrid DSA models

[Upstream PR](https://github.com/sgl-project/sglang/pull/45438) · state: open · merged: False

## Original PR description

## Motivation

For hybrid DSA pools (`HybridLinearKVPool` with `use_dsa`, e.g. GLM-5.3-Flash: KDA + DSA layers) `setup_state_kv_args` registers `StateType.DSA` / `DSA_TAIL` from the target's `full_kv_pool` only. An EAGLE/NEXTN draft on such a model owns a single-layer DSA pool whose indexer cache is never transferred, so after a PD handoff the decode-side draft runs its top-k over an all-zero index for every prompt position. Prompts up to `index_topk` are unaffected; above it MTP acceptance drops and per-user decode speed on PD falls well below aggregated serving.

The pure-DSA branch (`DSATokenToKVPool` target, DeepSeek-V3.2 / V4 NEXTN) already ships the draft's indexer cache; the hybrid branch does not.

## Modifications

`python/sglang/srt/disaggregation/utils.py`: in the hybrid branch, after the target's DSA components, register the draft's index cache and kpool tail as `StateType.DSA` / `DSA_TAIL` components of their own, with the draft layer ids remapped above `num_hidden_layers` (`_remap_draft_layer_ids`). The target's components are untouched, so `slice_dsa_tail_dst_ptrs_for_pp` keeps its equal key/score halves per component and a peer without a draft simply registers fewer trailing components. A draft pool whose page / kpool / tail geometry differs from the target's is skipped with a warning.

New CPU unit test `test/registered/unit/disaggregation/test_hybrid_dsa_draft_disagg_state_kv_args.py`: component layout with and without a draft, draft layer ids, geometry mismatch, non-DSA draft.

## Accuracy Tests

GLM-5.3-Flash NVFP4 (`index_topk` 2048, NEXTN 5 steps), one TP1 prefill + one TP1 decode over NIXL GPUDirect on GB300, versus an aggregated worker with identical engine args (`agg`) and a second identical aggregated worker on another node (`agg2`, the node-to-node noise floor). Same prompts on all arms, greedy, 100 prompts per length, 1600 output tokens, paired difference in MTP acceptance ± standard error.

| prompt tokens | 2.0k | 2.8k | 4.1k | 8.2k |
|---|---|---|---|---|
| before: 1P1D − agg2 | −6.8% (±1.9) | −9.6% (±2.2) | −17.5% (±1.8) | −20.2% (±1.5) |
| after: 1P1D − agg2 | −2.6% (±2.5) | −2.2% (±2.9) | −4.2% (±1.4) | −0.3% (±1.5) |
| agg − agg2 (noise) | −0.1 … −1.6% | +2.6 … −1.9% | +0.1 … −2.7% | −2.5 … +0.7% |

Memory dump at the first decode-side draft step of a 7.9k-token request: the draft pool's `index_k` / `index_k_scale` had 0 of 7850 rows populated before, and match the aggregated worker after. Both peers log `state_types=[MAMBA, DSA, DSA_TAIL, DSA, DSA_TAIL]`.

## Speed Tests and Profiling

Replay of a production trace on the same 1P1D pair, per-user decode tok/s at concurrency 8 / 16 / 32 / 64: 99 / 76 / 66 / 62 → 117 / 89 / 78 / 76. TTFT unchanged.

Not exercised: PP > 1 prefill, DeepSeek-V3.2 NEXTN (pure-DSA branch, untouched).
