# [Fix] spectrum: reset Spectrum state per CFG branch

[Upstream PR](https://github.com/sgl-project/sglang/pull/42423) · state: open · merged: False

## Original PR description

Fixes #35053.

Spectrum now initializes each independent CFG branch at denoising step 0. Negative-only ranks therefore use the configured skip window and discard forecast history from previous requests.

Under CFG parallel, ranks of the remaining shared-state models also reset their local state. `SpectrumParams.get_total_forward_steps` counts one local forward per step via a new keyword-only `cfg_parallel` flag (default `False`). No current model reaches this path (FLUX now has per-branch state, and MiniMax-H3 does not support CFG parallel); it keeps any shared-state model correct once it enables CFG parallel. Serial shared-state models keep positive-branch reset ownership, and the public full-reset API remains available.

FLUX now gets per-branch Spectrum state, like Wan/Hunyuan/SD3. With serial true CFG, its cond and uncond forwards used to share one counter and one forecaster. As a result:
- the forecaster mixed cond and uncond features;
- CFG gating, which stops the uncond forward after the gate step, shifted the cond skip schedule;
- the end-of-run wrap never fired.

Embedded-guidance FLUX.1-dev runs a single branch and is unaffected. Cache algorithms, thresholds, and defaults are unchanged.

Adapted the branch-local reset from @Oxygen56's unmerged PR #35140, with production-context regression tests using real tensor forecasts. The tests cover separate CFG ranks (Wan and FLUX), both serial branch orders, completed/interrupted requests with changed feature shapes, debug statistics, shared-state models, topology-aware forward counts, and FLUX under CFG gating (cond decisions and outputs match the ungated run).

Supersedes #42157 (branch renamed to follow the repository's branch naming).

**End to end** on B200 (Wan2.1-T2V-1.3B-Diffusers, 832x480, seed 42, guidance 3.0, Torch SDPA; compile/BCG/warmup off), comparing upstream `main` with `main` + both fixes. FLUX runs use `yujiepan/FLUX.1-dev-tiny-random` (FLUX.1-dev architecture, random weights) with true CFG, so they compare behaviour, not image quality.

*Request isolation:* a different-shape request runs first, then the target is compared with a fresh instance.

| Model, topology | `main` | `main` + both fixes |

| FLUX, 1 GPU serial true CFG | same Spectrum decisions as fresh | same Spectrum decisions as fresh |
| FLUX, 2 GPU CFG parallel | negative rank fails `size of tensor a (256) must match … (400)` (stale state) → other rank hangs until timeout | same Spectrum decisions as fresh |

The tiny FLUX checkpoint is not bit-reproducible even without a cache: two fresh instances differ (max abs pixel diff 11), and so do repeated requests on one instance. This is run-to-run non-determinism, not state carried across requests, so FLUX isolation is judged by the absence of crashes and by identical per-step Spectrum decisions.

*FLUX with CFG gating:* serial true CFG, 20 steps, gate at step 6. With per-branch state the cond decisions match the ungated run step for step; with FLUX on one shared state they do not.

*Cost (Wan):* 33 frames, 30 steps, 3 prompts × 3 requests each. Spectrum skips 63% of DiT forwards in both topologies, with mean PSNR vs no cache 26.6 dB (1 GPU) and 27.2 dB (2 GPUs, CFG parallel), worst prompt 20.6 dB. Median speedup was 2.14× on 1 GPU; on 2 GPUs our shared nodes made timing noisy (median 1.33×, individual requests 2.5–5.1 s vs 4.8 s without a cache). Repeated requests on the same instance were bit-identical.

### Update (2026-10-14)

- **Merged current `main`.** Kept `force_spectrum_real` on `ForwardContext` while taking #43064's removal of the unused `attention_backend_cls`. The lifecycle test moved with the other diffusion unit tests to `python/sglang/multimodal_gen/test/unit/` and, like them, drops per-file CI registration.
- **CFG residual refresh uses real forwards.** When CFG gating refreshes its frozen cond-minus-uncond difference, both branches now run real forwards through the normal Spectrum hooks, so the difference never holds a forecast and both branch histories advance once. The forced-real scope is restored if a forward raises. On a small Wan2.1-T2V-1.3B CFG 5 regression (256x256, 17 frames, 20 steps, gate 0.3 plus Spectrum, two prompts), mean frame PSNR of the combined mode against the uncached run rose from 8.7 / 12.3 dB to 13.0 / 16.0 dB.
- **Docs.** `spectrum.mdx` explains how Spectrum combines with CFG gating, measured on Wan2.1-T2V-1.3B at its defaults: the combination is slower than Spectrum alone and no more accurate.
- The FLUX.1 true-CFG Spectrum schedule and the per-model gating caps are in the follow-up #44261.

Lifecycle and gating unit tests on the merged branch: 14 passed, 21 subtests passed.
