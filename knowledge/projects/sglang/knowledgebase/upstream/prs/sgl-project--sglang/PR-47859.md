# [Feat] moe: Add Mooncake Elastic EP scale-up support

[Upstream PR](https://github.com/sgl-project/sglang/pull/47859) · state: open · merged: False

## Original PR description

## Motivation

Use Mooncake's elastic Buffer for the Mooncake A2A backend and integrate it with SGLang's existing Elastic EP scale-up flow.

This PR accompanies [Mooncake #4853](https://github.com/kvcache-ai/Mooncake/pull/4853#event-34543201148). Mooncake provides the elastic Buffer and peer connection management APIs; this PR integrates them into SGLang.

## Modifications

- Make `--moe-a2a-backend mooncake` use `Buffer.create_elastic()` by default and exchange peer metadata through TCPStore. Buffer selection does not depend on `--elastic-ep-backend`; the latter still controls SGLang's elastic state and scale-up flow.
- Reserve buffer capacity based on the maximum EP size and connect new ranks on demand. Keep the legacy constructor available through a documented source-level switch for debugging.
- Use the current EP size for dispatch/combine. When SGLang's elastic state is enabled, copy the Buffer's local fault mask back to it.
- Reuse the existing expert rebalancing and decode CUDA Graph recapture flow.
- Clear stale TBO child batches before a rank-fault retry so they are rebuilt for the retry.
- Add a registered test with a single script entry point that starts the service and new ranks and verifies two consecutive scale-ups.

## Accuracy Tests

On qjy-002 with 4 NVIDIA H20 GPUs, ran the registered `test/registered/ep/test_mooncake_ep_elastic_scale.py` using SGLang commit `1244c847e2` and `mooncake-transfer-engine-cuda13==0.3.14`. The local model was GLM-5.1-FP8 with its first 4 layers (3 dense layers and 1 MoE layer). An external wrapper supplied the local model path, layer override, and node-specific NIC configuration; the registered test and its assertions were unchanged.

- EP2 → EP3 → EP4 scale-up succeeded.
- Output token IDs from the existing and newly added cohorts matched the pre-scale baseline. The maximum absolute logprob difference in all four comparisons was `0.000000`.
- Decode CUDA Graph replay counter checks passed for each tested cohort.
- Result: `Ran 1 test in 668.549s`, `OK`, Python exit code `0`.

A separate 2-GPU H20 communication test (SGLang `bd09ceacde`, native Mooncake `711db3ff`) exercised the default Mooncake dispatcher with `elastic_ep_backend=None`. It used `Buffer.create_elastic()`, TCPStore, and the native fast path without fallback. FP8 dispatch followed by identity-expert combine returned the original inputs with maximum absolute error `0.0` on both ranks; exit code was `0`.
