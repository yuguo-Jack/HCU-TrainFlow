# [Refactor] memory-pool: Build QSA indexer host pools from buffer info

[Upstream PR](https://github.com/sgl-project/sglang/pull/40916) · state: closed · merged: True

## Original PR description

## Motivation

Part 4 of 5 of https://github.com/sgl-project/sglang/pull/40608. QSAIndexerPoolHost read the compressed key buffers, page shape and host layout directly from QSATokenToKVPool and its anchor host pool. This PR has QSATokenToKVPool export them through get_device_pool_infos() as a dense IndexKeyBufferInfo for the INDEXER pool, indexed by KV pages. The assembler captures the target and MTP draft infos, checks that they share page coverage and compress ratio, and builds QSAIndexerPoolHost from the packed info plus the host page count and layout. The host pool no longer references the device pool.

Host budget, host layout and the transfer path are unchanged. Under a fixed hicache size the KV host budget still excludes the packed index bytes, now summed from the captured buffers.

## Accuracy

Qwen3.8-Flash-Next, tp 4, NEXTN, HiCache multi-turn KL with forced host hits against main, 3 runs per side. In every run the assembled host pools and the H2D transfer sequence are identical to main, host-served sample counts are equal (prefill 5/8, decode 8/8), and decode-hit KL is identical. Prefill-hit KL varies run to run on main as well and stays within main's range.

main:
```
prefill_kl: 0.01408 / 0.00876 / 0.00591
decode_kl:  0.00358 / 0.00358 / 0.00358
```

this PR:
```
prefill_kl: 0.00835 / 0.00375 / 0.00784
decode_kl:  0.00358 / 0.00358 / 0.00358
```
