# [MoE] Coordinate NCCL EP Graph admission for zero-token ranks

[Upstream PR](https://github.com/sgl-project/sglang/pull/38887) · state: closed · merged: False

## Original PR description

## Motivation

Ranks participating in one NCCL EP transaction must agree on Graph admission even when a rank is idle or preparing prefill. This change coordinates admission before native EP work.

## Dependency and independent review

## Modifications

- Vote on the dispatch communicator's CPU group, including IDLE and prefill participants, and preserve zero-token participation in remotely routed expert work.
- Match the fixed-capture-mode contract of the migrated runner: incompatible hidden modes cause collective eager fallback. Later compatible batches can recover Graph execution.
- Do not dynamically recapture during serving. Retain independent local Graph buckets when the existing TP constraints allow them.

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Add NCCL EP to the TP-spanning backend set**

For a normal multi-GPU launch with `tp_size > 1` and no explicit `--ep-size`, `_A2A_EP_SPANNING_BACKENDS` still omits `nccl_ep`, so the MoE EP group remains size 1 even though `NcclEpDispatcher` communicates over `get_tp_group()`. Consequently each rank allocates all experts while the NCCL group spans every TP rank, and Graph admission also gathers only over singleton MoE groups; this can produce invalid expert-layout parameters and allow ranks to diverge between Graph and eager execution. Include `nccl_ep` in the TP-spanning resolution and the corresponding DeepSeek EP initialization predicate.

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Reject unsupported non-FP8 NCCL EP models**

When a supported-shape MoE has no `Fp8Config` (for example a BF16 Qwen/DeepSeek checkpoint), this unconditional selection creates `DeepEPMoE`, but its NCCL-specific `deprecate_flag` path is enabled only for FP8 Triton. The dispatcher still returns `DeepEPLLDispatchOutput`, after which the legacy `run_moe_core` reaches `assert False, "forward_deepgemm_masked is deprecated"` on the first request. Either reject non-block-128-FP8 NCCL EP configurations during setup or provide a compatible compute adapter instead of exposing them through the public backend choice.
