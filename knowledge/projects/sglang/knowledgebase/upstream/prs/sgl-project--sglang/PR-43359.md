# fix(attention): reject float32 model dtype at FlashInfer backend init

[Upstream PR](https://github.com/sgl-project/sglang/pull/43359) · state: open · merged: False

## Original PR description

## Motivation

Fixes #43162. `--dtype float32` (and its alias `"float"`) are advertised, parser-accepted choices, but no FlashInfer attention kernel exists for fp32: the JIT module URI map (`filename_safe_dtype_map` in `flashinfer.jit.utils`) covers fp16/bf16/fp8/integer dtypes only. The engine loads the weights, enters CUDA-graph capture, and dies with a bare `KeyError: torch.float32` from `get_batch_decode_uri`, taking the whole process group down with an unactionable message.

## Modifications

`FlashInferAttnBackend.__init__` now validates the resolved model dtype before touching any runner state and raises a `ValueError` that names the supported dtypes and points at `--dtype float16/bfloat16` or `--attention-backend torch_native`. Same failure class as before, but raised at backend init instead of mid-capture, with the remediation in the message.

New CPU unit tests pin the gate, the message content, and that backend construction raises before reading any pool/config state.

## Accuracy Tests

No model output path changes; the gate only rejects a configuration that never produced output.
