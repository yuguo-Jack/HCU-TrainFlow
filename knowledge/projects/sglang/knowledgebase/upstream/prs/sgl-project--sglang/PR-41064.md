## Motivation

<!-- Describe the purpose and goals of this pull request. -->

The CPU backend has no vectorized bf16 to fp8 e4m3 activation quantizer. The W8A8 FP8 GEMM and MoE kernels need one, and Diamond Rapids adds AVX10.2 instructions that convert to fp8 in hardware.

## Modifications

<!-- Detail the changes made in this pull request. -->

- `vec.h`: `cvtfp32_fp8e4m3_avx10_2` (fp32 to fp16 to fp8 with `vcvtph2hf8`) and `quantize_row_fp8e4m3` for a dynamic per-row scale or a given scale, next to `quantize_row_int8`. The AVX-512 path uses ATen's `cvtfp32_fp8e4m3`. The AVX10.2 loop is selected through `__builtin_cpu_supports("avx10.2")`. GCC does not inline across the `target("avx10.2")` attribute, so the whole row loop carries it.
- `quant_fp8.cpp` (x86 only): `per_token_quant_fp8_cpu`, and `cpu_has_avx10_2` for the test.
- The CMake x86-only source list, and the CPU docs note that the AVX10.2 intrinsics need GCC 15.
- `test_gemm.py`: comparison against a torch reference, with fp8 subnormal outputs, a zero row, non-contiguous input, and the multiple-of-32 check.
