# [Fix] http_server: Apply SGLANG_TIMEOUT_KEEP_ALIVE to Granian HTTP/1.1 connections

[Upstream PR](https://github.com/sgl-project/sglang/pull/45760) · state: closed · merged: True

## Original PR description

## Motivation

While running high-concurrency benchmarks on SGLang, I noticed that passing `--enable-http2` makes SGLang ignore `SGLANG_TIMEOUT_KEEP_ALIVE`: it serves through Granian instead of uvicorn, and only uvicorn reads that variable.

As a result, Granian closes any idle HTTP/1.1 connection after its default 30 s. Connection-pooling clients (like `aiohttp`, which keeps idle connections for 300 s) that reuse a connection right at the 30 s mark hit immediate disconnections (`ClientOSError: Can not write request body` / `ServerDisconnectedError`). In long multi-turn benchmarks, one of these on a warm-up request can abort the whole run.

## Modifications

- When `SGLANG_TIMEOUT_KEEP_ALIVE` is set, it is passed to Granian as the HTTP/1.1 `header_read_timeout` (seconds to ms), which Granian also uses as its idle timeout ([hyper#3828](https://github.com/hyperium/hyper/pull/3828)). This covers both the single- and multi-worker Granian servers.
- Unset: no change (Granian keeps its 30 s default). Zero or negative values are rejected at startup.
- In Granian the same timeout also limits how long a client may take to send request headers.
- Adds a CPU unit test and a one-line docs update. Builds on the approach in #29560.

## Testing

- Unit test 4/4; `pre-commit` passes.
- Patched server: idle connections close after 30 s when the variable is unset, and stay open past 90 s with `SGLANG_TIMEOUT_KEEP_ALIVE=300`. Reusing pooled connections right around the 30 s mark, 1–9 of 41 requests failed before the fix and 0 of 41 after.
