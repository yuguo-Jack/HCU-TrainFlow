# [Scheduler] Align deterministic flashinfer chunks to the q-tile grid, not the split-KV tile

[Upstream PR](https://github.com/sgl-project/sglang/pull/43612) · state: open · merged: False

## Original PR description

## Summary

Alternative to #43598. Two findings behind it, both measured on 4x B300 (flashinfer 0.7.0.post1):

1. **The alignment was tied to the wrong kernel constant.** Deterministic-flashinfer chunk truncation used `SGLANG_FLASHINFER_PREFILL_SPLIT_TILE_SIZE` (4096), which is the split-KV tile. Probing `BatchPrefillWithPagedKVCacheWrapper(backend="fa2", fixed_split_size=4096)` directly, a chunked prefill reproduces the unchunked one bit for bit iff every chunk starts on the kernel's 128-row q-tile grid (`128 / gqa_group` tokens); the split tile value (4096 / 1024 / None) does not change which boundaries are exact.
2. **The Kimi-Linear test never ran that kernel.** Kimi-Linear is MLA, so `--attention-backend flashinfer` resolves to `FlashInferMLAAttnBackend`, which has no deterministic mode (no fixed split, ragged prefill for no-prefix extends, `BatchMLAPagedAttentionWrapper` for chunked ones). A Kimi-Linear TP2 sweep shows chunked vs unchunked input logprobs differ by up to 4.2 and even the unchunked server is not batch-invariant, with or without alignment.

So the backend now declares the grid instead of the scheduler matching names: `AttentionBackend.prefill_chunk_align` defaults to `None`, deterministic `FlashInferAttnBackend` sets it to its q-tile width (`PREFILL_Q_TILE_TOKENS = 128`), the hybrid wrappers forward their dense child's value, and the scheduler's `init_prefill_chunk_align` just reads it. The MLA backend leaves it `None`, so the Kimi test is unchanged and starts on main as is; the env var stays a pure kernel knob.

A new kernel test, `test_flashinfer_deterministic_chunk_invariance.py`, pins the MHA invariant in both directions: exact on the 128 grid, not exact off it.

Verified on the final revision: kernel test 2/2; `test_deterministic_chunk_align` 2/2; Qwen3-8B deterministic flashinfer with `--chunked-prefill-size 256` matches the unchunked server bit for bit on every prompt, sequential and concurrent, while `--chunked-prefill-size 100` is rejected at startup with "aligned to 128 tokens"; `TestKimiLinearDCPDisaggregation` OK with the untouched test file (292 s). The TP arm fails on B300 with `cached_tokens == 0` both before and after this change, because B300 defaults Kimi-Linear to flashinfer, which disables the radix cache under deterministic inference; CI's H100 defaults to fa3.

Not addressed here: deterministic inference for the flashinfer MLA path, and the MHA-path holes where a tiny last chunk, a chunk batched with many 1-token extends, or an off-grid radix-cache hit lands on a different fa2 tile.
