# [Perf] kimi-k3: Shard the MoE front projection and gather quantized activations

[Upstream PR](https://github.com/sgl-project/sglang/pull/45126) · state: open · merged: False

## Original PR description

## Motivation

The merged MoE front computes the full latent projection on every TP rank. Sharding this projection reduces redundant computation and weight reads.

## Modifications

- Extend the existing CuTeDSL GEMM with weight-row mapping, preserving the shared-expert and router projections while computing only the local latent shard.
- Quantize each shard before gathering it, reusing the existing routing and quantization kernels.
- Derive shard sizes and communication layouts from model dimensions and the TP group.
- Preserve FP32 projection outputs, native MoE metadata preparation, and the existing fallback paths.

## Accuracy Tests

- Generated tokens match the baseline for all 30 measured, 64 warmup, and 3 boundary requests in each mode.
- DFlash verification, accepted-draft, and proposed-draft counts match exactly.
- TP8 GPU checks cover M=1/M=8 projection, routing, quantization, and CUDA Graph replay with updated inputs.

## Speed Tests and Profiling

Kimi-K3 on 8×B300, TP8, concurrency 1, 8192 input / 1024 output tokens.
Same inputs and client, 64 warmups with 32 output tokens and 30 measured requests per mode, without profiling.
Measured commits: baseline `f7ad4345b8`; optimized [`86d5b499f7`](https://github.com/leonardHONG/sglang/commit/86d5b499f7cebfd99fe4aa8ba52f2404088cb53a).

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Gate sharding on gather-kernel availability**

When this gather-specific JIT variant cannot be loaded (for example, `SGLANG_CRASH_ON_JIT_COMPILE=1` is used without a seeded `kimi_k3_route_quant_gather` artifact, or its build fails), this unguarded `_jit_module(gather.comm.world_size, hidden)` call raises after the model has selected the sharded projection, so 1/8-token generation aborts instead of using the existing full-projection fallback. The ordinary route/quant handoff checks `available()`, but that probe only loads `_jit_module()` without the gather arguments and therefore cannot protect this distinct module; probe the gather variant before setting `sharded_front` and retain the full path when it is unavailable.
