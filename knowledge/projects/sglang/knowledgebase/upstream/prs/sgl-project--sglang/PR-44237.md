# [Fix] embedding: Do not reuse prefixes or split prefills for encoder models

[Upstream PR](https://github.com/sgl-project/sglang/pull/44237) · state: open · merged: False

## Original PR description

## Motivation

Serving an encoder embedding model or a cross-encoder with the default flags gives wrong results or crashes. Measured on main:

- **`BAAI/bge-base-en-v1.5` (`BertModel`)** returns wrong embeddings. Cosine similarity with the Hugging Face reference is 0.83 on the first request and 0.21 on every later identical request, so the result depends on what was requested before.
- **`BAAI/bge-m3` (`XLMRobertaModel`) and `cross-encoder/ms-marco-MiniLM-L6-v2` (`BertForSequenceClassification`)**: the scheduler exits on the first request. For the cross-encoder the error is `RuntimeError: The size of tensor a (23) must match the size of tensor b (24)` in `models/bert.py`; for bge-m3 it is an `AssertionError`.

These models attend bidirectionally, so each token's K/V depend on the tokens after it. `embedding_model_spec.py` already handles this for EmbeddingGemma: "Prefix reuse and split prefills would reuse K/V states whose values depend on later prompt tokens", and its spec sets `safe_disable_radix_cache` and `safe_disable_chunked_prefill`. The generic encoder spec and the classification spec leave both off, so `_handle_model_capability_adjustments` never disables them.

The radix cache then serves prefixes cached by earlier requests. The warmup request already shares `[CLS]` with every prompt; later requests reuse the whole prompt. Chunked prefill breaks these models in the same way. With `--disable-radix-cache --chunked-prefill-size 8`, bge-base returns the same wrong vector for a 9-token input.

The existing cross-encoder server test (`test_openai_server.py`) works around this by passing `--disable-radix-cache --chunked-prefill-size -1` by hand.

## Modifications

- `_native_embedding_spec` sets both flags for `ENCODER_ONLY` execution (`BertModel`, `XLMRobertaModel`, `Contriever`). Decoder-pooling models (`LlamaEmbeddingModel`, `MistralModel`) and `CLIPModel` are unchanged.
- The classification spec sets both flags for `BertForSequenceClassification` and `XLMRobertaForSequenceClassification`. The causal classifiers (Llama, Qwen2, Qwen3) keep the radix cache and chunked prefill.
- Regression test `test_encoders_disable_prefix_reuse_and_split_prefill`, next to the existing BERT capability test: the four encoder architectures get both disabled, and `Qwen3ForSequenceClassification` keeps them.

## Accuracy Tests

Setup:

- One RTX 4090, `lmsysorg/sglang:nightly-dev-20261014-684fea8a` (main at `684fea8a`), with and without this patch.
- Flags: defaults plus `--is-embedding`. The cross-encoder also needs `--attention-backend triton` on this GPU, because FlashInfer cannot run its head dim of 32. #44238 changes the default backend for such head dims.
- Embeddings were compared with `AutoModel` CLS pooling plus L2 normalization in float32, and rerank scores with `AutoModelForSequenceClassification` logits.

| Model | Main | This PR |
|---|---|---|
| `bge-base-en-v1.5`, 9 request shapes (string, list, batch, token ids, base64, duplicates, mixed lengths, unicode) | min cosine 0.21 to 0.84 | 1.00000 for all |
| `bge-m3`, same 9 request shapes | scheduler exits on the first request | 1.00000 for 8 of 9 (see note) |
| `ms-marco-MiniLM-L6-v2` `/v1/rerank`, 9 cases including 20 documents | scheduler exits on the first request | scores within 0.004 of the reference, same order |

Note on bge-m3: the mixed-length batch scores 0.9966. There the server counts 92 prompt tokens and the reference tokenizer 91, for an input ending in a space. I did not investigate this further; it is not related to caching.

## Speed Tests and Profiling

No throughput claim. These models no longer use prefix caching or chunked prefill, which matches EmbeddingGemma and what the encoder tests already pass by hand.
