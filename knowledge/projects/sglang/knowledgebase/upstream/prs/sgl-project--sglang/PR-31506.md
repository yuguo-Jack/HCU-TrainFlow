# [multimodal] Decode input_audio media containers with PyAV

[Upstream PR](https://github.com/sgl-project/sglang/pull/31506) · state: closed · merged: False

## Original PR description

## Motivation

`input_audio` payloads that arrive as media containers (AAC-in-MP4, AVI, AMR-NB, AMR-WB) are rejected by the current audio decode backends (libsndfile/torchcodec), and the resulting exceptions surface as internal server errors even though the input is a client problem. Production clients also mislabel AMR bytes as `audio/wav`, so MIME-based routing is not reliable.

## Modifications

- Route byte-sniffed MP4, AVI, AMR-NB, and AMR-WB `input_audio` containers through in-process PyAV decoding:
  - `is_audio_container()` sniffs container magic bytes from the first 16 bytes.
  - `decode_audio_container()` strictly decodes the first audio stream (resampled, mono or multi-channel), skipping undecodable packets with a warning.
  - `load_audio()` checks the header and dispatches recognized containers to PyAV before the torchcodec/soundfile paths; file paths are passed to PyAV directly instead of being read fully into memory.
- Normalize invalid containers to client `ValueError`s while preserving the lenient video-audio wrapper (`extract_audio_from_video_bytes` still returns `None` for silent/corrupt videos). `fast_load_mm_data()` re-raises `ValueError` instead of wrapping it in `RuntimeError`, so bad `input_audio` stays a client input error.
