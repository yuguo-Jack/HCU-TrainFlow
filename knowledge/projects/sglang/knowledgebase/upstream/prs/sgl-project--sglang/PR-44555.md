# [DSv4.1] Fuse request-window KV copies

[Upstream PR](https://github.com/sgl-project/sglang/pull/44555) · state: closed · merged: True

## Original PR description

[codex/claude generated]

## Motivation

Encoder bounded replay copies packed request-window KV data and scales using advanced indexing, which materializes byte-index grids and launches multiple operations per layer. This adds substantial overhead when replaying long prefills.

## Modifications

- Copy each token's data and scales in one Triton kernel, respecting physical page strides and strided location arrays.
- Call the kernel directly for the existing GPU request-window path. Its state and workspace pools allocate separate packed uint8 buffers, so per-copy device, shape, stride, and storage-alias checks are unnecessary.
- Add byte-exact tests for both KV formats, page sizes, counts, padding, strided locations, and graph replay with changed locations.

## Accuracy Tests

Local validation covers 2 GPU tests (including 48 layout/page/count subcases), 5 encoder-replay tests, and 13 compressed-pool tests. Copies are compared byte-for-byte against an independent reference. Workload records were checked for expected cache accounting and output lengths. These synthetic replay checks are not model-quality evaluations; no GSM8K/MMLU result is claimed.

The performance-tested patch is based on `f2b73d4f9b4e64415b8d775b0f811c7801f1728b`. The PR is transplanted onto `bba535ebb4d176c6bf8361619e0c29fa263642fe`; focused validation is repeated there. Pre-commit passes locally. GitHub CI has not been run.

## Speed Tests and Profiling

DeepSeek-V4.1-Flash on 4x GB300, TP4/EP1, FlashMLA, chunked prefill 16384, memory fraction 0.8, max running requests 128, prefill CUDA graphs disabled. DSPARK uses block size 5 and simulated acceptance 5.4; decoder bounded replay is disabled. Runtime: PyTorch 2.14.1+cu130, FlashInfer 0.7.1, fastokens 0.3.4.

Unchanged synthetic high-load subset: 816 scheduled arrivals over 300 seconds, client concurrency cap 64, 891,421 total output tokens in each run. Measurements below use the same base revision and workload; this is a fixed-arrival replay, not maximum-throughput or semantic-accuracy testing.

| Configuration | Median TTFT (ms) | p95 TTFT (ms) | Median E2E (ms) | p95 E2E (ms) |
| --- | ---: | ---: | ---: | ---: |
| Encoder replay, original copy | 524.70 | 2089.57 | 8692.07 | 54291.49 |
| Encoder replay, fused copy | 395.92 | 1687.73 | 3397.61 | 19216.46 |
| Encoder replay, fused copy repeat | 393.83 | 1748.74 | 3390.33 | 19603.67 |

Both candidate runs reduce median E2E latency by approximately 61% and median TTFT by approximately 25%. Low-load serial replay completed 895 requests before versus 1152/1148 after within 300 seconds.

Encoder replay disabled remains faster: median TTFT 343.42 ms, median E2E 2443.99 ms, p95 E2E 13863.49 ms, and 1280 low-load completions. This patch reduces copy overhead; it does not eliminate the remaining replay regression. Full performance runs have not been repeated on the newer PR base.
