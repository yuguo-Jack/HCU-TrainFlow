# [NPU][CI] Fail fast and speed up long-running qwen3.6 accuracy cases

[Upstream PR](https://github.com/sgl-project/sglang/pull/39813) · state: closed · merged: True

## Original PR description

## Motivation

The qwen3.6-27b gpqa accuracy cases are slow in the nightly-acc pipeline: a single evalscope run takes ~3h11m (w8a8) and ~1h47m (bf16). gpqa allows up to 3 accuracy retries by default, so a borderline failure amplifies wall time and can hit the per-file timeout. This change makes these long-running cases fail fast on the first run and speeds up the w8a8 case, without changing the accuracy baseline.

## Modifications

- python/sglang/test/ascend/e2e/test_npu_accuracy_utils.py: add a per-case max_retries class attribute (defaults to None, keeping the dataset-derived behavior via get_max_retries) and make run_accuracy honor it. Backward compatible.
- test_npu_qwen3_6_27b_1p_gpqa.py: set max_retries = 1.
- test_npu_qwen3_6_27b_w8a8_1p_in3k5_out1k5_50ms_gpqa.py: set max_retries = 1 and bump eval_batch_size 8 -> 16.
- .github/workflows/nightly-test-npu.yml: temporarily disable the nightly-poc-multi-node-mix-tests-cann910 job (if: false).

## Accuracy Tests

This change only touches test/CI configuration and does not modify model forward/kernel code, so accuracy is unaffected; the gpqa baseline (0.878) is unchanged.

## Speed Tests and Profiling

- w8a8 gpqa: eval_batch_size 8 -> 16 is expected to shorten a single evalscope run (baseline ~3h11m).
- fail-fast retry: the w8a8 gpqa case no longer triggers up to 2 extra retries on a below-threshold result, avoiding the per-file TIMEOUT observed in run 34993274105.
