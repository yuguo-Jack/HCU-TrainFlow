# docs: add thinking budget guide

[Upstream PR](https://github.com/sgl-project/sglang/pull/41601) · state: closed · merged: True

## Original PR description

## Summary

Adds a dedicated documentation page for controlling the thinking budget of reasoning models. Today this is scattered across server-argument rows and model cookbooks; there is no single page covering the three control tiers and their pitfalls.

New page `docs/advanced_features/thinking_budget`:

- **Chat-template hints** — `enable_thinking`, template-defined `thinking_budget`, `reasoning_effort`; notes these are hints with no token guarantee, and that `thinking_budget` is silently ignored when the model's chat template does not define it.
- **Hard budget with strict thinking** (recommended) — `--enable-strict-thinking` with per-request `max_thinking_tokens` on `/generate`, `custom_params: {"thinking_budget": N}` on chat completions, and the `SGLANG_MAX_THINK_TOKENS` server-wide cap. Documents that `/generate` requests must also set `require_reasoning: true` or the budget is silently ignored, and that xgrammar (the default backend) satisfies the token-filtering requirement.
- **Hard budget with a custom logit processor** — `--enable-custom-logit-processor`, the built-in per-family processors (`Qwen3` / `GLM-4.5/4.6` / `DeepSeek-R1` / `Inkling`), and how to subclass `ThinkingBudgetLogitProcessor` for models with different think token ids.
- **Verify the budget applies** — a deterministic check plus the three common silent-failure modes.

Also registers the page in `docs.json` (Advanced Features, after `separate_reasoning`), adds a cross-link from the Reasoning Parser page, and links the page from the `--enable-strict-thinking` row in `server_arguments`.

All flags, request fields, env vars, and class names were verified against the code on current `main`. `mint broken-links` and `mint validate` pass; pre-commit passes.

- yepapa-nest · comment · 2026-10-01T14:19:54Z · [source](https://github.com/sgl-project/sglang/pull/41601#issuecomment-5933383983)

Thanks for pulling this together, it's a really useful page.

One note on the chat completions section: the line "There is no `max_thinking_tokens` field on chat completions" describes exactly the gap that #36750 is meant to close. That PR adds `max_thinking_tokens` to `ChatCompletionRequest` and wires it into the same strict-thinking path that `/generate` uses. With it, the field is accepted directly instead of being dropped, and `custom_params.thinking_budget` keeps working as before.

If `custom_params` is the interface you'd rather keep, I'm happy to close #36750. If you'd like the first-class field, I can rebase it on whatever this doc ends up describing, and the doc could then mention both options. Either way, it would be good to settle on one so the doc and the API agree.
