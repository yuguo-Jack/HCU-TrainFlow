# [Fix] vl: stop treating literal <image> user text as image placeholder

[Upstream PR](https://github.com/sgl-project/sglang/pull/44149) · state: closed · merged: False

## Original PR description

## Summary

Fixes #43979

When a Qwen-VL model request carries at least one real image AND literal `<image>` text in any message (e.g., from a GitHub issue/PR page replayed as a tool result), the processor incorrectly counts the user text as an image placeholder, causing:

```
Mismatch: More 'IMAGE' tokens found than corresponding data provided.
```

This is a permanent conversation-wedging bug in agent workloads.

## Root Cause

`QwenVLImageProcessor.image_token_regex` matched both:
1. The native chat-template tokens: `<|vision_start|><|image_pad|><|vision_end|>`
2. The legacy `/generate` sentinel: `<image>`

The chat template **only** emits the native sequence, so any bare `<image>` in rendered chat prompts is user text. But the combined regex made `get_combined_regex()` (used for prompt splitting/counting) treat both as real placeholders.

## Changes

### `python/sglang/srt/multimodal/processors/qwen_vl.py`

1. **Cleaned `image_token_regex`** — removed `|<image>` alternative. The regex now only matches native chat-template tokens. This fixes the chat path: user text `<image>` is no longer counted as a placeholder.

2. **Preserved legacy `/generate` path** — added a fallback in `_normalize_prompt_for_fast_path()` that normalizes `<image>` to native tokens when the prompt contains no native tokens (i.e., raw `/generate` prompts still work).

## Testing

Verified with a standalone regex test:

| Scenario | Old regex | New regex | Result |
|---|---|---|---|
| Chat template: 1 native + 1 user `<image>` | count=2 (buggy) | count=1 (correct) | Bug fixed |
| Legacy `/generate`: 2 `<image>` only | count=2 | count=2 | Still works (fallback) |
| Chat template: 1 native, no user `<image>` | count=1 | count=1 | Unchanged |

No GPU needed — this is a pure regex fix with zero behavior change for correct inputs.
