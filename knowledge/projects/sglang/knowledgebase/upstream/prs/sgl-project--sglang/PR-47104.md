# [Fix] multimodal: Handle None data_token_pairs fallback in pad_mm_token_pairs

[Upstream PR](https://github.com/sgl-project/sglang/pull/47104) · state: open · merged: False

## Original PR description

## Motivation

`pad_mm_token_pairs` in `python/sglang/srt/managers/mm_utils.py` is typed to accept `data_token_pairs: Optional[List[Tuple[int, int]]] = None` and includes a fallback to `mm_inputs.im_start_id` / `mm_inputs.im_end_id` (or logging a warning and returning `input_ids` unchanged when no token pairs are available, e.g., when called with `token_pairs or None` from `dots3_common`). However, three bugs prevented the `None` fallback from ever working:

1. Line 267 executed `[s for s, _e in data_token_pairs]` **before** checking `if data_token_pairs is None:`, immediately raising `TypeError: 'NoneType' object is not iterable`.
2. Line 271 set `data_token_pairs = [mm_inputs.im_start_id, mm_inputs.im_end_id]` (a flat list of 2 ints rather than a list of `(start, end)` 2-tuples `[(mm_inputs.im_start_id, mm_inputs.im_end_id)]`), which both shadowed the subsequent `if data_token_pairs is None:` check when `im_start_id` was `None` and raised `TypeError: cannot unpack non-iterable int object` when `im_start_id` / `im_end_id` were set.
3. `MultiModalityDataPaddingPatternTokenPairs.__init__` similarly iterated over `data_token_pairs` without guarding for `None`.

## Modifications

- Resolve the `data_token_pairs is None` fallback first, constructing `[(mm_inputs.im_start_id, mm_inputs.im_end_id)]` only when both `mm_inputs.im_start_id` and `mm_inputs.im_end_id` are non-`None`.
- Compute `data_start_token_ids` after the `data_token_pairs is None` early return.
- Guard `data_token_pairs or []` in `MultiModalityDataPaddingPatternTokenPairs.__init__`.
- Add unit tests in `test/registered/unit/managers/test_mm_pad_token_pairs.py`.
