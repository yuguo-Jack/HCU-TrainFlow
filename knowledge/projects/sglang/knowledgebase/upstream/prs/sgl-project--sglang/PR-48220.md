# [Fix] [NVIDIA] cosmos:Multi node execution fixes

[Upstream PR](https://github.com/sgl-project/sglang/pull/48220) · state: open · merged: False

## Original PR description

# [Fix] diffusion/cosmos3: Fix multi-node CFG-parallel FSDP desyncs and auto_tune GPU probing

## Motivation

Serving a Cosmos3 checkpoint that only fits with FSDP sharded across nodes
(`--use-fsdp-inference --cfg-parallel-size 2 --ulysses-degree 4 --nnodes 2`)
hits three independent bugs:

1. **Startup fails on multi-node launches.** `auto_tune` probes `num_gpus` device
   ids on every node, but `num_gpus` is the total across nodes:
   `AssertionError: Invalid device id`.
2. **T2I returns a corrupted image, then the server hangs.** The default T2I
   `guidance_interval` turns CFG off partway through the request. During CFG-split
   steps each CFG rank caches only its own UND K/V entry, so at the first no-CFG step
   one rank misses its cache and reruns the UND layers. Under FSDP that issues
   all-gathers the other ranks never match: the collectives pair the wrong layers
   (equal shard sizes, so NCCL does not error), one node returns an image built from
   mixed-layer weights, and the other node hangs until the NCCL watchdog fires.
   Every later request then hangs as well.
3. **Transfer with control-CFG + text CFG desyncs the same way.** Three CFG branches
   on two ranks give one rank two forwards and the other one, so the ranks issue
   different numbers of FSDP all-gathers.

## Modifications

- `auto_tune.py`: probe `num_gpus // nnodes` local GPUs.
- `Cosmos3DenoisingStage._denoise_once`: track each step's CFG split mode
  (`"control"`, `"text"` or none) and call `transformer.reset_cache()` on every rank
  when it changes, so all ranks recompute the UND prefix in the same step. Costs one
  extra UND pass per mode change (one per T2I request).
- `Cosmos3DenoisingStage._predict_noise_cfg`: distribute branches in rounds of
  `cfg_world_size`; a rank with no branch in a round reruns the round's first branch
  and discards it, so every rank runs the same forwards. The padded rank was idle,
  so step latency is unchanged.
- Tests: new `TestCosmos3CfgParallelUndCache` (runs the real denoising loop as each
  of two CFG ranks against a fake UND cache and checks they miss it in the same
  steps); `test_control_cfg_parallel_distribution` now asserts equal per-rank
  forward counts. Both fail on `main` and pass with this change.

## Accuracy Tests

No change to single-GPU or non-FSDP outputs: (2) only adds a cache reset and (3)
only adds discarded forwards; neither changes the computed prediction.

End to end on 2 nodes x 4 GB300 (`--num-gpus 8 --nnodes 2 --use-fsdp-inference
--hsdp-shard-dim 8 --cfg-parallel-size 2 --ulysses-degree 4`), 1280x720, 35 steps:

| Case | Before | After |
| --- | --- | --- |
| Server start | `Invalid device id` | healthy |
| T2I (default CFG window) | noise image; the second node hangs | clean image |
| Next request (guidance 1.0) | hangs, HTTP 500 after NCCL timeout | 32.5 s |
| Transfer, edge control, guidance 3 + control guidance 1.5 (3 branches), 189 frames | hangs in the first chunk; NCCL watchdog fires on the CFG all-reduce after 600 s and the server dies | 464.6 s; both nodes finish every chunk in lockstep |
| T2V / I2V (33 frames), V2V (189 frames), transfer with guidance 1 | n/a | all OK |

## Speed Tests and Profiling

T2I pays one extra UND (text) pass per request. Transfer with 3 CFG branches on 2
ranks: the padded rank's extra forward runs while the other rank does its second
forward, so the step time stays at two forwards (4.2 s/step above).
