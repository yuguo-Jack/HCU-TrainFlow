# [Fix] [AMD] dsv41: Make Engram's input_ids optional for the AMD monokernel

[Upstream PR](https://github.com/sgl-project/sglang/pull/46612) · state: open · merged: False

## Original PR description

## Motivation

#45904 made `input_ids` a required keyword-only argument of `Engram.forward` and moved the V4.1 image-row mask into `engram_gate`. The AMD monokernel plugin that main pins and the ROCm image installs (sgl-amd-mono `05e0bb02e1`, `python/pyproject_other.toml`) still calls `engram(x, hash_ids, forward_batch)` and keeps image rows itself, as SGLang's forward did before #45904. So every DeepSeek-V4.1 server with `--monokernel-backend amd` (`--enable-amd-monokernel`) now dies at decode CUDA-graph capture:

```
  File "/sgl-workspace/sgl-amd-mono/sgl_amd_mono/deepseek_v41/spec.py", line 909, in _backbone
    residual = engram(
TypeError: Engram.forward() missing 1 required keyword-only argument: 'input_ids'
```

It reproduces on `lmsysorg/sglang-rocm:v0.5.22-rocm10-mi35x-20261025` and `lmsysorg/sglang-rocm:v0.5.22-rocm724-mi35x-20261025`. sgl-amd-mono main makes the same call, so bumping the pin does not help.

## Modifications

`Engram.forward`'s `input_ids` defaults to `None`. `engram_gate` already treats `None` as "no image mask", so a caller that leaves it out gets the pre-#45904 output and keeps the image rows itself, as the plugin does. SGLang's own caller still passes `input_ids` and is unchanged.

## Accuracy Tests

MI355X, `lmsysorg/sglang-rocm:v0.5.22-rocm10-mi35x-20261025` (SGLang main at `ca4bedfffa`, sgl-amd-mono `05e0bb02e1`); "this PR" applies this change to that SGLang. DeepSeek-V4.1-Flash TP2 + DSpark with the AgentX TP2 c16 server settings (`--mem-fraction-static 0.80 --chunked-prefill-size 16384 --prefill-decode-interval 96 --swa-prefix-tails 1024 --max-running-requests 32`, per-rank Engram host table):

| | `--monokernel-backend amd` | startup |
|---|---|---|
| main | yes | the TypeError above, in target-verify graph capture |
| this PR | yes | serves; the monokernels run the target-verify steps of batch size 1-8 (8 of 20 captured graphs), and the DSpark draft's |
| main / this PR | no | serves |

GSM8K (`sglang.test.few_shot_gsm8k`, 1319 questions):

| | `--monokernel-backend amd` | parallel 64 | parallel 8 |
|---|---|---:|---:|
| main | no | 0.904 | 0.892 |
| this PR | no | 0.904 | 0.902 |
| this PR | yes | 0.898 | 0.904 |

At parallel 8 every target-verify step has at most 8 requests, so all of them run on the monokernels. The spread is the server's run-to-run nondeterminism. Without the monokernel this PR's greedy output is token-identical to main's (smoke prompt, 32 tokens).

Decode against prefill on 8 LongBench-v2 prompts sent together (sgl-amd-mono's `test_covered_steps_match_prefill`, bound 0.03), mean KL:

| | `--monokernel-backend amd` | mean KL |
|---|---|---:|
| main | no | 0.0120 |
| this PR | no | 0.0075 |
| this PR | yes | 0.0141 |

`Engram.forward` called the way the plugin calls it, followed by the plugin's image mask, is bitwise equal to SGLang's call on the fused Triton gate (gfx950) and on the torch path, in bf16 and fp32, for 1-333 rows of which a third are image rows. On main the same call raises the TypeError. With this PR applied on the image, these unit tests pass: `test_deepseek_v41_bcg_multimodal`, `test_engram_history`, `test_dspark_engram_commit_in_graph`, `test_deepseek_v4_boundary`, `test_deepseek_v4_pipeline`, `test_deepseek_v4_shared_expert_fusion`, `test_deepseek_v4_amd_tp4`, `test_encoder_swa_replay` and `test_dspark_sampling_accept_graph`, plus sgl-amd-mono's `test_contract`, `test_deepseek_v41_spec` and `test_deepseek_v41_index_plan`.

## Speed Tests and Profiling

No speed change: SGLang's own path is unchanged, and the monokernel path is the one it ran before #45904.
