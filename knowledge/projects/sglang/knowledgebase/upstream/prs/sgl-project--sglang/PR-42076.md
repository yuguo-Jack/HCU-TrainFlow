# [NPU] Budget DSV4 KV and indexer storage by backend byte rates

[Upstream PR](https://github.com/sgl-project/sglang/pull/42076) · state: closed · merged: False

## Original PR description

## Motivation

The common DeepSeek-V4 configurator uses a 584-byte KV row and a 132-byte default indexer token when sizing NPU pools. The NPU constructors allocate different layouts: 1,024-byte BF16 KV rows before A5 or 640-byte aligned FP8 rows on A5. The indexer retains its packed compatibility buffer and additionally owns dedicated K and scale buffers, for 262/264 bytes per token.

A CPU constructor-growth regression demonstrates both shortfalls while cancelling fixed dummy-page overhead. The mismatch exists on current main and is independent of the memory-metric change in #37935.

This change corrects the per-token coefficients only. Reserved pages, state padding and A5 request-bank floors remain separate fixed-overhead concerns; this is not an exact total-budget or OOM guarantee.

## Modifications

- Use the NPU BF16 / A5 packed-row byte rate for the resolved BF16 pool path
- Include the NPU indexer's packed compatibility storage plus dedicated K/scales, with the architecture-specific scale dtype
- Add a CPU regression comparing forecast growth with the real pool constructors at two page-aligned capacities, for pre-A5/A5 and default/FP4 packed compatibility layouts
- Leave non-NPU sizing, allocations, kernels, and forward computation unchanged

The CUDA low-ratio layout and padding work in #41275 is outside this change. No post-capture VMM, host-memory, or draft-budget behavior changes.

## Tests

On Python 3.12, Torch 2.14.0+cpu and Triton 3.8.0, against the standalone main-based candidate:

- All eight new architecture/layout/buffer subcases fail on unchanged main and pass with this correction
- 92 tests and 43 subtests pass across configurator, compressed pools, unified FP8 pools, C4 lifecycle and compressor-write-padding tests
- Direct unittest execution of the new class passes
- Applicable pre-commit hooks, Python compilation and diff whitespace checks pass

The tests stub the optional torch_npu import and select NPU architecture branches while allocating CPU tensors. They inspect explicit owned buffers, without relying on #37935's accounting accessor.

A three-layer toy with a 32 MiB budget previously advertised 74,368 full-token slots for both architectures. The corrected rates select 44,800 before A5 or 64,512 on A5. Measured CPU tensor storage changes from 54,781,440 to 34,101,440 bytes before A5, and from 38,739,840 to 33,839,744 bytes on A5. The remaining 547,008 / 285,312 bytes above the budget are fixed-overhead limitations outside this coefficient fix.
