# [Test] kv_canary: Drop min_p from the canary-info e2e sampling params

[Upstream PR](https://github.com/sgl-project/sglang/pull/48301) · state: open · merged: False

## Original PR description

## Motivation

`test/registered/kv_canary/test_self_e2e_canary_info.py` has failed on main since #41916, which makes the scheduler abort any request with `min_p > 0` on a speculative-decoding server ([scheduled run job](https://github.com/sgl-project/sglang/actions/runs/41736410757/job/126266970572)).

The test's servers run EAGLE, and 2 of its 8 requests (`canary-info-2`, `canary-info-6`) used `min_p=0.05` from `CANARY_INFO_SAMPLING_PARAMS`. Both were aborted (`min_p is not supported with EAGLE speculative decoding`), and the test expects every request to finish with `length`.

## Modifications

Drop `min_p` from that entry, keeping `temperature=1.0, top_k=20`. `CANARY_INFO_SAMPLING_PARAMS` is only used by the canary-info e2e tests, all of which run EAGLE. The unit test `test_self_unit_canary_info.py` still covers `min_p` in the sampling digest.

## Notes

In the failing run, the aborted `canary-info-2` also reported a first output token whose canary info didn't match, and with `--kv-canary raise` that crashed the server (exit 137), cutting off every other stream. That is a separate question for the canary hook (should aborted requests be checked?) and is not changed here.
