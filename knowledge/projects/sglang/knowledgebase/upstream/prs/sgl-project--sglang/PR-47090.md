# [Perf] qwen-image21: Pack BF16 gate/up projections on SM120

[Upstream PR](https://github.com/sgl-project/sglang/pull/47090) · state: open · merged: False

## Original PR description

**Current-head update (2026-10-30): `188169fa0db0bb2d524d56a97184590f948cca07` passed the frozen 512 gates but failed the 1024 cleanup gate for T2I and editing. See the full revalidation and actual images below. The original report measures `efcb88a2`; it does not establish that the current head passed cleanup.**

Qwen-Image 2.1 runs separate BF16 gate and up projections in its image MLP. Packing them into one projection reduces saved-request E2E latency by **3.16% for 512² T2I and 2.63% for 512² editing** on RTX PRO 6000 Blackwell. The original 1024² cases improve by 1.08% and 0.94%; those smaller gains are retained below.

The change shares gate/up storage while preserving checkpoint parameter names and shapes, then reuses the existing packed SiLU-multiply operator. It adds no kernel or public flag. Eligibility is limited to SM120, resident unquantized TP1 projections, BF16 batch-one targets of 1024 or 4096 tokens, and `quality="high"`. Prefixes, exact/lossless requests, LoRA wrappers, incompatible storage/layouts and `torch.compile` retain separate projections. Views are derived from parameters, with the existing `_apply` lifecycle repacking after CPU/GPU transfers.
