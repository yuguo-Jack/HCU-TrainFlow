# [Fix] function_call: Flush buffered text at stream end in GLM-4.7/4-MoE and Cohere Command R4 detectors

[Upstream PR](https://github.com/sgl-project/sglang/pull/41914) · state: open · merged: False

## Original PR description

## Motivation

Same loss pattern as #41821 / #41909: `Glm47MoeDetector`, `Glm4MoeDetector`
and `CohereCommand4Detector` hold text back in `self._buffer` while waiting
for the closing tool-call marker. `BaseFormatDetector.finish()` returns an
empty result by default, so when the stream ends with an incomplete marker
still buffered, the held-back text is silently dropped:

```python
d = Glm47MoeDetector()
d.parse_streaming_increment("hello <tool_call>get_weather('par", [])
d.finish([])  # returns empty; "<tool_call>get_weather('par" is lost
```

## Changes

Add a `finish()` override to each detector that flushes `_buffer` as normal
text, matching the existing pattern in `IQuestQ1Detector.finish` and the
fixes in #41909. Normal streams are unaffected: `finish()` stays a no-op
when `_buffer` is empty.

## Tests

Offline unit tests (no server, no model loading) for each detector cover:
- partial tool call at stream end: `finish()` releases the buffered text;
- clean stream: `finish()` returns an empty result;
- fully parsed stream: no duplication at `finish()`.

All pass locally (`pytest test/registered/unit/function_call/test_{glm47_moe,glm4_moe,cohere_command4}_detector.py`), ruff clean.
