# [Fix] transcription: Keep a reference to the delayed chunk-abort task

[Upstream PR](https://github.com/sgl-project/sglang/pull/47715) · state: closed · merged: False

## Original PR description

## Motivation

`OpenAIServingTranscription._abort_chunk_requests` schedules `abort_after_dispatch_window()` with `asyncio.create_task()` and never stores the task. The [asyncio docs](https://docs.python.org/3/library/asyncio-task.html#asyncio.create_task) say to keep a reference to fire-and-forget tasks, because the event loop holds only weak references to them. Ruff flags this as `RUF006`.

This is hygiene, not a fix for an observed failure. While the task sleeps, the loop's timer handle keeps it alive. The change removes the reliance on that implementation detail. That matters here because this delayed pass is the only abort for chunk requests whose rid was assigned after the first pass, and those requests keep decoding on the scheduler until they're aborted.

#34480 fixes the same pattern in `TokenizerManager`, `TokenizerWorker` and the diffusion `mesh_api`, but not this site. This PR covers only the transcription handler, so the two don't overlap.

## Modifications

- Keep the task in a per-handler `_background_tasks` set, and remove it when the task completes.
