# [Feature] hicache: support DCP with EAGLE/MTP speculative decoding

[Upstream PR](https://github.com/sgl-project/sglang/pull/45499) · state: open · merged: False

## Original PR description

[by Claude Code]

## Motivation

AgentX-style long-context agentic workloads on GLM-5.2 / DSA models benefit from decode context parallelism (DCP) and HiCache at the same time. On 8xB200, TP8+DCP8 gives about 6x the logical KV capacity of TP8. HiCache would keep long multi-turn prefixes in host DRAM. These deployments run the checkpoint's own MTP head through EAGLE. Today the combination is rejected twice:

- `resolve_hicache_dcp_compatibility` raises `NotImplementedError` for `--dcp-size > 1` + HiCache unless the speculative algorithm is DSPARK.
- `_dsa_dcp_overrides` rejects HiCache for any DSA model under DCP.

So DCP + EAGLE/MTP has to run with GPU-resident KV only.

## Root cause

Under DCP, the target MLA KV is striped by position. The HiCache host pool keeps widened logical slots and translates them to this rank's physical rows at the transfer boundary (#33112). The draft KV, including the NextN/MTP layer, is **replicated**: every rank stores the full draft context over the widened virtual slots, untranslated.

- **EAGLE/MTP drafts are packed.** For NextN MTP, `_build_hicache_draft_plan` packs the draft pool into the target host pool as extra layers. The draft rows would then go through the per-rank translation and be sized like the per-rank shard. That is wrong for a replicated pool. DSpark (#35221) works because its draft goes through the separate *sidecar* host pool, sized over the anchor's `logical_size` with no translation.
- **DSA index-K is replicated too** (#43735). `DSAIndexerPoolHost` copied its size from the anchor's per-rank shard, so logical host indices above `size` had no host page.
- **The replicated draft indexer sidecar was mis-sized.** A replicated DSA draft's stored index-K row holds `dcp_size` kernel pages. `make_dsa_indexer_pool_decl` sized a host page from `index_page_size`, so it either failed its divisibility assert (`dcp_size=8`) or copied `1/dcp_size` of each row.

## Change

- `speculative/base_spec_worker.py`: with DCP + HiCache, back the draft up as a sidecar instead of packing it. The sidecar is the same host pool that DCP + DSpark already uses. Multi-runner (multi-layer EAGLE) and `topk > 1` raise a clear `NotImplementedError`.
- `arg_groups/hicache_hook.py`: allow `EAGLE`/`NEXTN` with `--speculative-eagle-topk 1` alongside DSPARK. Other algorithms and `topk > 1` are still rejected. The L3 storage backend, LMCache, HiSparse and non-MLA guards are unchanged.
- `arg_groups/model_overrides/deepseek_v2.py`: DSA + DCP now allows HiCache. HiSparse is still rejected.
- `mem_cache/pool_host/dsa.py`:
  - The indexer host pool spans the anchor's widened `logical_size`. This is unchanged without DCP.
  - The indexer decl sizes a page from the stored row, `page_size // index_kpool`, which is the same as before for non-replicated pools.
- `mem_cache/hicache_auto_size.py`: the draft sidecar estimate counts widened target slots under DCP. It used to undercount the draft host pool by `dcp_size`.
- `docs/advanced_features/dcp.mdx`: document the new scope.

No kernel changes.

## Related PRs

- **#44122 (@kpham-sgl)** takes the same sidecar plus logical-sized index-K approach for DSA MTP. It does not change `make_dsa_indexer_pool_decl`, so its replicated draft indexer sidecar keeps the `index_page_size`-based page size:
  - At `--dcp-size 8` (the GLM-5.2 TP8+DCP8 deployment), building the draft sidecar hits `AssertionError: index page of 8448 bytes does not split over page_size=512 tokens`.
  - At DCP2 and DCP4 it copies only `1/dcp_size` of each draft index-K row. Outputs stay correct because the target verifies, but MTP acceptance after load-back degrades.

  #44122 also drops the speculative-algorithm guard entirely. This PR keeps an explicit EAGLE/NEXTN topk-1, single-runner and DSPARK allowlist. Happy to fold the decl fix into #44122 instead if maintainers prefer.
- #45205 (ROCm) enables DSA DCP HiCache with a DCP-sharded packed MTP draft on top of #44322. #43599 handles the Kimi-K3 EAGLE3 MLA draft.

## Limitations

- Only HiCache L2 (host DRAM). L3 storage backends with DCP stay rejected, and so does TileLang FP8 KV with DCP.
- EAGLE/NEXTN needs `--speculative-eagle-topk 1` and a single draft model runner, so multi-layer EAGLE is rejected. EAGLE3/STANDALONE stay rejected with DCP + HiCache because they are untested.
- Each rank's draft sidecar holds every logical slot, because the draft KV is replicated. For GLM-5.2 that is one extra layer next to 78 sharded target layers.

**Pre-commit:** `pre-commit run --all-files` passes on this commit.

**GPU (GLM-5.2-FP8, 1x GB300 node with 4 GPUs, TP4 + DCP4).** This used SM103 GB300 rather than 8xB200; both run the same DSA DCP `trtllm` path. All runs used `--kv-cache-dtype fp8_e4m3` (DSA prefill/decode resolved to `trtllm`, DCP comm `fi_a2a`) and `--speculative-algorithm EAGLE --speculative-num-steps 3 --speculative-eagle-topk 1 --speculative-num-draft-tokens 4`, with `SGLANG_ENABLE_RANK_CONSENSUS_CHECKER=1`.

- **Capacity:** device KV is 1,276,224 physical tokens/rank, so `max_total_num_tokens=5,104,896` logical. Under the default auto-sizing, the host pools per rank were:
  - target KV: 2,552,512 physical tokens (114.68 GB)
  - DSA indexer, logical-sized: 28.30 GB
  - draft KV sidecar: 10,210,304 logical tokens (5.88 GB)
  - draft indexer: 1.35 GB

  That is 139.9 GiB, matching the auto-size estimate.
- **Load-back probe:** a 46K-token fact-list document is prefilled. Eight retrieval questions are asked on the original device KV and repeated once. Then 122 distinct 46K-token fillers (5.6M tokens) evict the document, and the eight questions are asked again. The first of those loads 45,824 prefix tokens from host (`cached_tokens_details: {"device": 0, "host": 45824}`).

| Config | GSM8K (sgl-eval 0.1.3, 200 ex., GLM-5.2 preset, thinking on, seed 0) | Retrieval acc. device-hit / after host load-back | Mean MTP accept len device-hit / after load-back | Server avg accept len |
| --- | --- | --- | --- | --- |
| No HiCache (baseline) | 97.5% | 8/8 / 8/8 (recomputed) | 3.07 / 3.18 | 2.89 |
| HiCache `write_through`, `page_first`, `kernel` | 98.5% | 7/8 / 8/8 | 3.08 / 3.03 | 2.96 |

The only retrieval miss is item 1234, which the model also misses on device-resident KV. Greedy continuations past the answer word are not run-to-run deterministic in this configuration, even without HiCache: a plain device-hit repeat matches its own earlier text in only 1-3 of 8 cases. The fair checks are therefore answers and acceptance length, and both match. A wrong latent shard or index-K page would break long-range retrieval. A corrupted draft KV would collapse the MTP acceptance length. The rank-consensus checker never fired.
