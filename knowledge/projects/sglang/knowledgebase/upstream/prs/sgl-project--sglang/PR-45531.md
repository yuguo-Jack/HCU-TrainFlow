# [Fix] [AMD] attention: Pass the layer softcap to aiter unified-attention decode

[Upstream PR](https://github.com/sgl-project/sglang/pull/45531) · state: closed · merged: True

## Original PR description

## Motivation

`AiterAttnBackend.forward_decode` calls aiter's `unified_attention` with `softcap=0`, so a model with an attention logit softcap loses it on every decode step that runs unified attention (`SGLANG_USE_AITER_UNIFIED_ATTN=1`, or the hybrid SWA pool). The extend paths already pass `layer.logit_cap`, so prefill and decode disagree. Gemma 2 has an attention softcap of 50; on Gemma 2 27B, GSM8K drops from 0.878 on triton to 0.213.

## Modifications

- Pass `softcap=layer.logit_cap` in the decode call. Layers without a softcap have `logit_cap = 0.0`, the value the call passed before.
- `test_decode_applies_the_layer_softcap` checks that the decode call passes the layer's softcap. It fails on main.

## Accuracy Tests

1x MI325X (gfx942), ROCm 7.2.2, main at `1c2f424` against this PR, TP 1, `SGLANG_USE_AITER_UNIFIED_ATTN=1 --attention-backend aiter --disable-cuda-graph --context-length 8192 --mem-fraction-static 0.85`. CUDA graphs are off because on this path at page size 1, main's graph decode reads a stale page table (#34833). With #34833 applied and graphs on, the results match (Gemma 2 27B: 0.240 → 0.878). GSM8K is `sglang.test.few_shot_gsm8k` (8-shot, 512 new tokens, 1319 questions); passkey is 5 keys at 8128 tokens.

| model | GSM8K, main → PR | passkey, main → PR | GSM8K, triton |
|---|---|---|---|
| Gemma 2 27B it | 0.213 → 0.879 | 4/5 → 5/5 | 0.878 |
| Gemma 2 9B it | 0.841 → 0.848 | 5/5 → 5/5 | 0.849 |
| Gemma 2 2B it | 0.487 → 0.487 | 5/5 → 5/5 | 0.490 |
| Gemma 3 12B it (no attention softcap) | 0.901 → 0.903 | 15/15 → 15/15 | |

## Speed Tests and Profiling

Decode with #34833 applied to both arms and CUDA graphs on, `sglang.benchmark.serving --dataset-name random-ids`, 64 prompts, 1024 in / 512 out, concurrency 8:

| model | output tok/s, before → after | median TPOT, before → after |
|---|---|---|
| Gemma 2 27B it | 110.4 → 105.1; 111.7 → 106.5 with the GPUs swapped | 70.1 → 74.0 ms; 70.3 → 73.8 ms |
| Gemma 2 9B it | 41.4 → 38.3 | 160.9 → 166.3 ms |

Applying the cap costs 3–6% of decode time, which the extend paths already pay.
