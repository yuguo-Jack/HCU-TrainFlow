# [Fix] diffusion/openai: Bound job lists and complete cursor pagination

[Upstream PR](https://github.com/sgl-project/sglang/pull/46156) · state: closed · merged: True

## Original PR description

## Summary

Bound video and mesh job-list responses and complete their cursor metadata.

Previously, omitting `limit` serialized every stored job. Responses also omitted `last_id` and `has_more`, so the OpenAI video iterator could stop after the first page.

- Default to 20 jobs, retain the maximum of 100, and validate `order`.
- Return `first_id`, `last_id`, and `has_more` from the existing shared store.
- Update the docs to use SDK pagination and retrieve individual jobs when polling.

This bounds each response, not retained jobs or generation queue size. The store still sorts its records; admission control and retention are separate concerns.

## Validation

- Remote regression suite: 75 passed across security, video lifecycle, image API, and OpenAI utilities.
- The three added cases fail before the fix. Real OpenAI SDK 2.6.1 traversal now returns all 21 jobs in exactly three requests instead of stopping after seven.
- Real Uvicorn/HTTP comparison with 50,000 stored jobs per endpoint: default video responses shrink from 19.9 MB to 8.1 KB; mesh responses from 12.9 MB to 5.2 KB. Across three default-list requests per endpoint, request latency drops from 155-529 ms to 6-7 ms, and maximum concurrent control-endpoint latency from 496 ms to 1.6 ms.
- Explicit `limit=100` returns identical job-data hashes before and after; both servers shut down cleanly.
- Pre-commit passed. No model inference or GPU performance claim is involved.

Environment: Python 3.12.15, OpenAI 2.6.1, FastAPI 0.156.4, HTTPX 0.28.1, Uvicorn 0.54.0, Pydantic 2.14.1.
