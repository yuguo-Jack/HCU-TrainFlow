# [Perf] [AMD] qwen3_5: use strided GDN prefill projection views on HIP

[Upstream PR](https://github.com/sgl-project/sglang/pull/41683) · state: open · merged: False

## Original PR description

## Motivation

`use_strided_prefill_z` is gated on `_is_cuda`, so ROCm materialises `mixed_qkv`/`z`/`b`/`a` through `fused_qkvzba_split_reshape_cat_contiguous` where CUDA takes free strided views via `qwen3_5_gdn_prefill_projection_views`.

That helper contains no kernel and nothing device-specific — it is plain slicing and `.view()`. The consumers are already stride-aware:

- the gated RMSNorm Triton kernel takes explicit `stride_z_row` / `stride_z_token` / `stride_z_head`;
- `mixed_qkv` is only read by `causal_conv1d_fn`, whose output is a fresh tensor;
- the post-conv split `fused_qkv_split_gdn_prefill` already admits `is_hip()`.

## Modifications

```diff
             use_strided_prefill_z = (
-                _is_cuda
-                and forward_batch.logical_forward_mode.is_extend_without_speculative()
-            )
+                _is_cuda or _is_hip
+            ) and forward_batch.logical_forward_mode.is_extend_without_speculative()
```

Two supporting changes, both in `test/registered/attention/test_gdn_prefill_layout.py`:

- `register_amd_ci(est_time=13, stage="stage-b", runner_config="1-gpu-large-amd")`, so the file that covers `qwen3_5_gdn_prefill_projection_views` runs on a ROCm runner.
- `@unittest.skipIf(not is_cuda(), ...)` on `test_compact_prefill_conv_matches_rectangular_output_and_cache`. That test fails on ROCm for reasons unrelated to this PR: the class skips on `torch.cuda.is_available()`, which is **True** on ROCm so the test runs, while `_init_prefill_conv_block_table` returns early on `not is_cuda()`, which is **False** on ROCm so `conv_block_table` is never built. The test then asserts it is not None. Guarding that one method with `is_cuda()` makes it track the gate it is testing; the class-level torch guard stays so everything else still runs on AMD.

## Accuracy Tests

GSM8K, full 1319-question test set, `--thinking-mode qwen-3`, temperature 0, 2 runs per arm (2638 samples each), on 8x MI355X:

| arm | score |
|---|---:|
| stock | 0.9708 |
| #41677 (decode fused proj+conv) | 0.9666 |
| #41683 (prefill strided z) | 0.9663 |
| both | 0.9723 |

No significant difference against stock (two-proportion z-test: p = 0.38 / 0.34 / 0.74). Spread across arms is 0.61 pp against a 0.48 pp binomial standard error for a single run, and the both-patches arm scores highest — inconsistent with any additive degradation.
