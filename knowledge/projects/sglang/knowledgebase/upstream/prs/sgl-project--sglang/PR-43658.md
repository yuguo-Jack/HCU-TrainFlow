# [Fix] openai: Honor Inkling reasoning-off requests

[Upstream PR](https://github.com/sgl-project/sglang/pull/43658) · state: open · merged: False

## Original PR description

## Motivation

Fixes #43145.

For Inkling, `apply_reasoning_enabled(request, False)` sets `reasoning_effort="none"`, but `_get_reasoning_from_request` falls back to the detector's always-on default. The request therefore still requires reasoning in the grammar and response parsing paths. The read-side decision should agree with the effort used to encode the messages.

## Modifications

- Add an Inkling branch to the shared reasoning decision, reusing `_parse_inkling_reasoning_effort` and the cached server default. Zero effort disables reasoning; positive effort enables it. Explicit server-level `force_reasoning` behavior is preserved.
- Extend the existing Inkling tests to check disable/read-back and a table of explicit, positive, and default efforts. Use `CustomTestCase` for the touched registered test class.

## Accuracy Tests

The branch includes upstream main 51faf523 and the CI-required base b6778515.
The combined OpenAI/Anthropic serving suites passed **225 tests with 132 subtests**
on the tested merge commit 74926c0a. The regression fails before the fix.

Validation uses Python 3.12.13, Torch 2.14.1+cu130, sglang-kernel 0.4.10,
FlashInfer 0.7.2 and Transformers 5.19.0. The request fixtures run on CPU in the
CUDA-enabled pinned runtime and import the actual source modules.
Model inference/accuracy and full upstream serving CI remain unverified;
upstream serving tests require maintainer authorization through run-ci.
