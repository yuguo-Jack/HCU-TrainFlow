# [Fix] mamba: Release consumed lazy Mamba prefix locks before donation retry

[Upstream PR](https://github.com/sgl-project/sglang/pull/43559) · state: closed · merged: True

## Original PR description

## Dependency

Depends on #43567, now merged and included in this branch. Releasing the prefix lock alone can expose stale in-place checkpoint donation under slot pressure.

## Problem and change

With lazy overlap, the next decode can consume the temporary tracking slot before the previous prefill donates its checkpoint. Donation then needs a replacement slot while the consumed prefix state is still locked, exhausting the pool and asserting.

On a failed lazy donation allocation, release this request's consumed Mamba prefix reference before eviction/retry. Preserve KV locks and other requests' references; record the release to avoid a double decrement. Keep the allocation assertion and existing capacity formulas unchanged.

The CPU regression covers full 3-slot and 4-slot per-request pools and the subsequent normal unlock. A registered GPU regression additionally uses exactly 4 Mamba slots and 1 running request: warm a 128-token prefix, then extend it to 255 tokens and generate 32 tokens with overlap and decode CUDA graphs enabled. The first decode takes the fourth slot before prefill donation, which must reclaim the consumed prefix instead of requiring a fifth slot. It reuses the existing Mamba KL test server and CI registration. Checkpoint invalidation is handled separately in #43567.

## Validation

The base run uses the unmodified base runtime, not a selectively reverted fix.

- Added GPU regression validated on GB300 with Qwen3.5-0.8B: both tests in `test_mamba_cache_kl.py` pass (49.7 seconds), including the existing checkpoint-reuse test with KL=0.
- Negative control: remove only this PR's prefix-lock release block while retaining #43567; the new test fails in prefill checkpoint donation with `AssertionError: Can not alloc mamba cache`.
- Pre-commit passed for the added test.

- This branch independently: 14 CPU tests and 12 subtests passed; pre-commit passed.
- The two PRs merge without conflicts. Their combined runtime files are identical to the previously validated combined fix (43d6c962aa).
- Combined E2E on GB300 with overlap and decode CUDA graphs: Qwen3.5-0.8B passes 24 requests with 1 running request / 4 slots and 96 with 4 / 16; Qwen3.5-4B + NEXTN passes 24 with 1 / 4. Original main asserts in these cases. Both single-request 4-slot runs exactly match their 8-slot references in output tokens and logprobs. Ordinary and NEXTN 3-slot runs also complete 24 requests each.

The earlier combined GPU results cover both fixes together. The new negative control isolates the prefix-lock release change while retaining checkpoint invalidation.
