# [Feat] step5: Support HiSparse

[Upstream PR](https://github.com/sgl-project/sglang/pull/44469) · state: open · merged: False

## Original PR description

Depends on #44467 (its commit shows here until that merges).

## What
HiSparse for Step5 full-attention layers. The Step5 kernels read whole 8-token regions, so the HiSparse item is a region rather than a token:

- `Step5HiSparseFullKVPool` stores FULL KV as region rows; attention keeps its `[slots, 1, 192]` token view.
- The DSV4 HiSparse allocator is split into a shared `CompressedHiSparseTokenToKVPoolAllocator` with DSV4 and Step5 subclasses.
- The Step5 backend remaps only the physical-region word of `packed`: prefill reads the region mapping, decode swaps misses in through the existing block swap-in kernel. No attention kernel changes.
- Supports PD decode with direct-to-host transfer. Rejects FP8 KV, PD prefill and MTP (as for other HiSparse models).
- Also fixes `HiSparseMHATokenToKVPoolHost` backup, which skipped the last layer of pools with the default inclusive `end_layer`.

Usage: `--enable-hisparse --disable-radix-cache --hisparse-config '{"top_k": 513, "device_buffer_size": 1024, "host_to_device_ratio": 4}'`. `device_buffer_size` counts regions. Host memory is device FULL KV x ratio, so cap it with `--max-total-tokens`.

## Verification
Step-5-Preview, 4x GB300 TP4, BF16 KV, Triton MoE, `device_buffer_size=520`:

| | non-PD | PD (mooncake) |
|---|---|---|
| Greedy tokens/logprobs vs no-HiSparse, prompts 0.5K-54K | identical | identical |
| 8 concurrent ~24K needle prompts | 8/8 | 8/8 |
| gsm8k (200) baseline / HiSparse | 0.945 / 0.940-0.945 | 0.945 / 0.955 |
| Negative control (skip host->device copy) | diverges past the device buffer | diverges past the device buffer |

HiSparse unit and kernel tests pass.
