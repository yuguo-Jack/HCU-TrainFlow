# [AMD] ci: register 5 framework tests to run on AMD CI

[Upstream PR](https://github.com/sgl-project/sglang/pull/25208) · state: closed · merged: True

## Original PR description

## Summary

First batch of the NV→AMD coverage gap audit. On `main`, ~200 tests are registered for CUDA via `register_cuda_ci(...)` but not for AMD. This PR adds `register_amd_ci(...)` to 5 framework-level tests that have no NVIDIA-specific kernel paths in their test body, so they run on AMD CI per-commit.

## What now runs on AMD per-commit

| AMD suite | File | est_time |
|---|---|---|
| `stage-b-test-1-gpu-small-amd` | `core/test_engine_child_pids.py` | 77s |
| `stage-b-test-1-gpu-small-amd` | `observability/test_tracing.py` | 113s |
| `stage-b-test-1-gpu-small-amd` | `prefill_only/test_pooled_hidden_states.py` (12 of 13 classes) | 100s |
| `stage-b-test-1-gpu-large-amd` | `sessions/test_session_control.py` (2 of 3 methods) | 87s |
| `stage-b-test-1-gpu-large-amd` | `sessions/test_streaming_session.py` | 691s |

The added est_time mirrors the CUDA est_time as a first estimate; the weekly `update-est-time` bot will retune from measured timings.

## Two in-file method-level skips remain

These match the existing AMD-registered precedent in the codebase (`test/registered/hicache/test_hicache_variants.py`, `test/registered/perf/test_bench_serving_1gpu_large.py`), where a single method or class is skipped via `@unittest.skipIf(is_hip(), "...")` while the rest of the file's coverage stays active on AMD:

1. `prefill_only/test_pooled_hidden_states.py::TestPooledHiddenStatesMISEngine` — `enable_mis=True` triggers `_handle_multi_item_scoring` which asserts `flashinfer` prefill/decode backend (NVIDIA-only). The other 12 tests in the file run unchanged.
2. `sessions/test_session_control.py::test_session_control_with_branching` — surfaces a deterministic 1-token greedy-output divergence between the session-branching cache-reuse path and plain generation, observed on MI300 (gfx942). Suspected ROCm numerical-precision difference; passes on CUDA. The other test methods in the class run unchanged.

## How candidates were filtered

- 197 CUDA-only files on `main` → kept only those whose body contains no hardcoded `flashinfer` / `trtllm` / `fa3` / `cutedsl` / `cutlass` / `flashmla` / `nvfp4` / `mxfp4` / `gpt-oss` / `sm_NNN` references.
- Kept only `stage-b-test-1-gpu-small` and `stage-b-test-1-gpu-large` targets so we can reuse existing AMD CI partitions without workflow changes.
- All edits pass the project's own AST registry parser (`collect_tests(..., sanity_check=True)`).

### Details

The PR is purely additive and CI-registration-only:

- Adds `register_amd_ci(est_time=…, suite=…)` calls beside the existing `register_cuda_ci` calls in 8 test files.
- Adds 3 `disabled=…` reasons (Whisper/flashinfer, gpt-oss-20b mxfp4 ×2) so unsupported tests are skipped on AMD at partition time.
- Adds 2 small AMD-only `@unittest.skipIf(is_hip(), …)` decorators (`TestPooledHiddenStatesMISEngine`, `test_session_control_with_branching`).

No production code under `python/sglang/srt/**` is modified, no kernel code is touched, and no test logic is changed for CUDA. Every failing CI job is hitting either (a) a pre-existing AMD perf/NCCL flake on a test the PR doesn't touch, (b) a HuggingFace API 429 rate-limit on the AMD disaggregation runner, or (c) a 30-min step timeout on NVIDIA driven by `test_awq.py` blowing through its `est_time` budget. The two PR-added tests that landed on a failing AMD shard (`test_session_latency.py`, `test_streaming_session_swa.py` on shard `1-gpu-large-amd, 1`) were correctly suppressed by the `disabled="…mxfp4 quantization"` reason and were never executed.

**Verdict: safe to ignore for this PR.** Suggested next step is a re-run; if the same AMD perf/NCCL/HF-429 jobs reappear they should be tracked as separate environment/flake issues, not PR regressions.
