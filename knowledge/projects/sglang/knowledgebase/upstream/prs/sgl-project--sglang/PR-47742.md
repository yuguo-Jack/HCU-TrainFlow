# [Fix] kimi-k3: Honor initial expert placement in fused routing

[Upstream PR](https://github.com/sgl-project/sglang/pull/47742) · state: closed · merged: True

## Original PR description

## Motivation

Kimi-K3 does not expose the model metadata required by `--init-expert-location`. Its merged gate / latent-projection front also wraps logical top-k IDs without the ordinary placement remap or active-batch padding mask. A configured placement must agree with both checkpoint weight loading and runtime dispatch.

## Modifications

- Expose expert-location metadata for both the text model and multimodal wrapper, allowing the existing loader to place checkpoint experts according to an initial permutation.
- Pass the current routing inputs to the existing top-k post-processing helper after the merged front. Keep the existing capture / recorder behavior, including avoiding duplicate counts when mapping and recording are fused.
- Keep fake dispatch on the ordinary routing path because it transforms logits before top-k selection.
- Reject online EPLB and redundant experts, whose weight layout is not implemented by Kimi-K3. Reuse the existing `--init-expert-location` / `--ep-dispatch-algorithm static` options; do not introduce a placement heuristic, a benchmark-specific map, or a new flag.

## Accuracy Tests

Tested against upstream `b146a8576de930cf3adc104e601feb2790cdf3f6` with this PR applied independently:

- `test_topk_routing_inputs.py` and `test_kimi_k3_expert_placement.py`: **28 passed, 73 subtests passed**. Covers target/draft isolation, changes to the active padding mask, metadata for both model entry points, and rejection of unsupported relocation modes.
- `test_moe_front.py` and `test_expert_location_weight_loading.py`: **10 passed, 42 subtests passed**. The GPU case runs the actual merged front and model method with a non-identity permutation and padded tokens; mapped IDs, routing weights and latent output match the reference exactly. It also checks that fake dispatch declines the fused routing contract.
- `test_moe_front.py` and `test_eplb_map_record.py`: **4 passed** before adding the fake-dispatch eligibility assertion. Mapping/counting kernels filter padding correctly.

GPU tests used NVIDIA B30Z (B300), PyTorch 2.14.1+cu130 and Triton 3.8.0. Full-model output validation has not been rerun on this integration; the results above are operator and unit validation.

## Speed Tests and Profiling

This change enables a valid initial placement and preserves the fused routing path where its contract is supported. No end-to-end speed claim is made for this branch. Earlier Kimi-K3 tuning motivated the change, but those results also depended on a workload-derived expert permutation and other patches; they are not attributed to this integration.
