# [Feat] jit: Add SGLANG_JIT_DISABLE_FAST_MATH to drop --use_fast_math from JIT builds

[Upstream PR](https://github.com/sgl-project/sglang/pull/46304) · state: open · merged: False

## Original PR description

## Motivation

When chasing a numerical difference between two builds or two GPUs, the first thing to rule out is fast math. For SGLang's own JIT kernels that is hard to do today:

- 28 op files under `python/sglang/kernels/ops/` pass `--use_fast_math` to the JIT build (26 of the 156 `load_jit` call sites pass it, two more build through torch's cpp_extension), and since #43236 the activation ops pass it on every CUDA arch.
- `load_jit` strips the flag only on HIP (`kernels/jit/utils/compile/loader.py`); on CUDA there is no way to turn it off short of editing each op file. The per-call `fast_math=False` exists only for the activation ops.
- The TileLang kernels already opt out through `TL_DISABLE_FAST_MATH`, and FlashInfer has `FLASHINFER_EXTRA_CUDAFLAGS`; the nvcc JIT path has nothing comparable.

This adds `SGLANG_JIT_DISABLE_FAST_MATH` (default off): when set, `load_jit` drops `--use_fast_math` / `-use_fast_math` from `extra_cuda_cflags`, exactly what the HIP branch does. Nothing changes unless it is set.

## Modifications

- `python/sglang/srt/environ.py`: `SGLANG_JIT_DISABLE_FAST_MATH = EnvBool(False)` in the JIT developer-knob group.
- `python/sglang/kernels/jit/utils/compile/loader.py`: the HIP-only list comprehension becomes `_strip_fast_math_flags()`, applied when `is_hip_runtime()` or the switch is on.
- ``test/registered/unit/kernels/test_load_jit_fast_math.py``: a CPU-only unit test (`register_cpu_ci`, `base-a-test-cpu`) for the helper and for `load_jit` composing `BuildSpec.cuda_cflags` with and without the switch, and for the HIP path staying as it was.

Why it is safe: the build key hashes the generated ninja text, so builds with and without the flag never share a cache entry; deep_select's `--ftz=false` stays valid on its own (nvcc's default); `relu2(..., fast_math=False)` keeps working, the switch only removes a flag and never adds one. Out of scope: the prebuilt sgl-kernel wheels, FlashInfer / TileLang / Triton kernels (their own knobs), and the two ops that build through torch's cpp_extension.

## Accuracy Tests

Default behaviour is unchanged (the flag is only dropped when the variable is set), so no model output changes by default. With the switch on, kernels that pass `--use_fast_math` compile with IEEE division/sqrt and without flush-to-zero, which is the point of the switch.

## Speed Tests and Profiling

No change by default. With the switch on, those kernels run at their non-fast-math speed; the switch is a debugging aid, not a serving configuration.
