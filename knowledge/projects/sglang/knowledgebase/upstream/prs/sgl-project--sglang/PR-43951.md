# [Fix] hicache: Bound staged admission retries on shared capacity rejection

[Upstream PR](https://github.com/sgl-project/sglang/pull/43951) · state: open · merged: False

## Original PR description

## Motivation

Follow-up to #36345. A staged Mamba cache hit can be rejected repeatedly by the shared prefill memory budget without advancing its bounded admission retry counter. The request then remains queued indefinitely, even when dropping the staged hit would allow cold recomputation.

On Qwen3.5-0.8B with TP=1 on one GB300, a real HTTP request with a 512-token L3 hit and a 2,200-token prompt exceeded 1,000 capacity rejections with the deferral counter still at zero and timed out after 45 seconds. The same prompt completed with a cold cache.

## Modifications

- Route staged admission deferrals through a small shared helper.
- Count shared-capacity `NO_TOKEN` rejections and load-back preallocation failures toward the existing retry bound, in addition to Mamba slot exhaustion.
- Preserve staged hits for `OTHER` batch/input-limit rejections.

Only `schedule_policy.py` changes; no test files are included.

## Accuracy Tests

- Real GPU/HTTP E2E: after the fix, the staged hit was dropped after exactly 32 `device_capacity` deferrals and the request completed with eight output tokens. Output token IDs and all eight output logprobs matched the cold-cache control exactly (maximum absolute logprob difference: 0.0).
- Positive L3-hit check: a 768-token prompt still reused 512 storage-cached tokens and completed successfully.
- Prefill admission and storage-prefetch lifecycle suites, including temporary local regression checks: **62 passed, 54 subtests passed**. The regression checks reproduced two failures before the fix and are not included in this PR.
- Pre-commit hooks passed.

## Speed Tests and Profiling

In the targeted capacity-pressure E2E, the baseline timed out after 45.03 seconds; the fixed request completed in 0.49 seconds. The cold-cache control completed in 1.04 seconds. These are individual reproduction runs, not throughput benchmarks.

Reproduction used unified memory, Mamba `no_buffer`, buffer-only HiCache with file storage and `wait_complete` prefetch, 4,096 total tokens, three Mamba cache slots, and one running request. Seed a 512-token prefix and flush it to L3, retain an unrelated 64-token request in device cache, then submit a 2,200-token prompt sharing the stored prefix.
