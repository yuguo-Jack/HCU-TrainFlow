# [Scheduler] Reclaim the idle device cache on every rank

[Upstream PR](https://github.com/sgl-project/sglang/pull/40444) · state: open · merged: False

## Original PR description

## Motivation

`SGLANG_EMPTY_CACHE_INTERVAL` is documented as *"Interval (seconds) at which to empty **the device** cache; set this if memory accumulates over a long serving period."* On a multi-rank deployment it only ever emptied rank 0's cache, so every other rank kept accumulating until the process OOMed. That is #12344 ("`SGLANG_EMPTY_CACHE_INTERVAL` with `tp=2` clears only the first video card, the second one overflows"). The issue was closed as inactive and the code is unchanged on `main`, so the bug is still present.

Root cause: the interval reclaim lived in `IdleSleeper.maybe_sleep()`, and an `IdleSleeper` can only be built on the rank that owns the tokenizer/rpc sockets — `init_idle_sleeper` gates on `pp_rank == 0 and attn_tp_rank == 0 and attn_cp_rank == 0`, because `ipc_channels.recv_from_tokenizer` / `recv_from_rpc` are the poller's input and are `None` elsewhere. The gate itself is not removable: parking needs those sockets. But the caching allocator is **per process**, so reclaiming it from that one rank leaves the other ranks' cached blocks pinned for the life of the process.

Measured on a TP4 ROCm deployment (4x MI308X) serving GLM-5.3-Flash with `--sleep-on-idle` and `SGLANG_EMPTY_CACHE_INTERVAL=600`, some hours after the last request:

| device | free VRAM |
|---|---|
| GPU 0 (rank 0, has the `IdleSleeper`) | 49,276 MiB |
| GPU 1 / 2 / 3 | 15,728 / 15,758 / 15,856 MiB |

The three non-rank-0 devices were each sitting on roughly 33 GiB of cached-but-free blocks. A single `POST /flush_cache` then released 33,826 MiB on *each* of GPU 1/2/3 (GPU 0 unchanged) — so the per-rank `empty_cache()` itself works fine; only its trigger was rank-gated.

## Modifications

- `Scheduler.on_idle()` runs on **every** rank (both `event_loop_normal` and `event_loop_overlap` call it when there is no batch) and now calls the new `Scheduler.maybe_empty_cache_on_idle()`, which applies `SGLANG_EMPTY_CACHE_INTERVAL` to the local device.
- `IdleSleeper` / `RustServerIdleSleeper` go back to being parking primitives: they keep polling / waiting, and no longer own the interval or the `empty_cache()`.
- New CPU-only unit test, `test/registered/unit/managers/test_scheduler_idle_empty_cache.py`, building a bare `Scheduler` with `idle_sleeper = None` (i.e. what every rank but the socket owner looks like).

The env var's default (`-1`) still disables the whole thing, and the reclaim stays gated on the rank actually being idle, so it never fires while a batch is in flight.

## Speed Tests and Profiling

N/A. With `SGLANG_EMPTY_CACHE_INTERVAL` unset (the default) this is a no-op: `maybe_empty_cache_on_idle()` returns before doing any work. When it is set, the number of `empty_cache()` calls per rank is unchanged from before (at most one per interval, and only while the rank is fully idle) — the only difference is *which* ranks make them.
