# [Feat] rust: Parse DeepSeek-V4/V4.1 output with deepseek-recipe

[Upstream PR](https://github.com/sgl-project/sglang/pull/46780) · state: closed · merged: True

## Original PR description

- Add `DeepSeekOutput` in `sglang-processor` (`deepseek_output.rs`): per request it computes the parse start, stop strings and parsing options as `serving_deepseek_recipe` does, and its `DeepSeekOutputParser` feeds output token ids to deepseek-recipe's `StreamProcessor`, returning reasoning, content and tool-call deltas
- `lower_chat` (sglang-server's lowered path and sgl-router) and sglang-server's typed chat handler parse DeepSeek-V4/V4.1 output with it when the reasoning and tool parsers are the DeepSeek ones; mixing a DeepSeek parser with another model's is rejected as unsupported
- Remove the Rust ports of the DeepSeek-V4 DSML tool parser and think parser, their reasoning and tool parity fixtures, and `py_rstrip`
- Regenerate the DeepSeek `openai_parity` fixtures against the Python handler, which already parses through deepseek-recipe (#45907)
- Python keeps `DeepSeekV4Detector` only for the tool-choice structural tag; its docstring says so, and its unit test now tests `DeepSeekV32Detector`, whose parse logic is still live

Behavior change: DeepSeek-V4/V4.1 responses from the Rust hosts now match the Python server's. Tool-call arguments stream in pieces, `</think>` no longer appears in content when `separate_reasoning` is off, and a continued thinking turn streams as Python streams it.
