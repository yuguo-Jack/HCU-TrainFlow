# [Feat] sgl-router: Render Kimi-K3 through sglang-processor

[Upstream PR](https://github.com/sgl-project/sglang/pull/43608) · state: closed · merged: True

## Original PR description

> [!NOTE]
> **Stack 2/3**, merge in order: #43625 (GLM-5.3) → #43608 (Kimi-K3) → #43689 (Qwen3.8). This PR is based on #43625 (`kan/sgl-router-glm53`), so its diff shows only the Kimi-K3 commit. After #43625 merges it gets rebased onto `main`.

Adds Kimi-K3 to sglang-processor and serves its chats from the router end to end: the router renders and tokenizes every text Kimi-K3 chat exactly as SGLang does, and with the cookbook's `kimi_k3` reasoning and tool parsers it also lowers them to `/generate` and parses the output itself (reasoning split, tool calls, usage). This follows #43000 (DeepSeek-V4.1).

## Modifications

- **Render:** `ChatFormatter::KimiK3` (`render/models/kimi_k3.rs`). `render_request` builds the request the way `serving_chat.py` calls the checkpoint's encoder (`_prepare_kimi_k3_messages` and the `kimi_k3` branch of `_encode_messages`), then renders it with Dynamo's `KimiK3Formatter`:
  - **Messages:** the pydantic message dump keeps only text parts, neutralizes the image placeholder, and turns developer turns into system turns. String tool arguments are parsed into objects.
  - **Tools:** dumped as `exclude_unset` does, with schema types normalized as `_validate_request` does (`varchar` becomes `string`). A system turn with tools renders only its declaration.
  - **Thinking:** kwargs win, then `reasoning`/effort, then the server's defaults; on by default.
  - **`thinking_effort`:** the kwarg, else a `low`/`high`/`max` request effort, else `max`.
  - **`tool_choice`** (`required`/`none`) and **`response_format`** (including the legacy `schema` and the kwargs `response_schema`) render as SGLang renders them.
  - **Continuation:** the `continue_final_message` prefix is returned on its own, since SGLang tokenizes it separately.

  `render_request` now returns a `RenderedPrompt`, so K3 keeps its special-token segments. `render_prompt` keeps Dynamo's K3 request semantics, which typed hosts rely on, so sglang-renderer is unchanged.
- **Left to the engine:** where the pinned formatter would render differently, `render_request` returns an error and hosts send the request to the engine:
  - media (image, video and audio parts), as for DeepSeek-V4.1 and GLM-5.3;
  - a null `thinking_effort` with thinking on;
  - whitespace-only reasoning history;
  - string tool arguments that are not a JSON object;
  - numbers serde_json prints differently from Python (`1e-06`, integers beyond 64 bits, `-0`);
  - tokenizer arguments in `chat_template_kwargs` (including `messages`, which `build_chat_segments` rejects);
  - tool declarations Dynamo rejects.

  Requests `_validate_request` rejects (a required `tool_choice` without tools, a `json_schema` format without a schema) fail to render too.
- **Router:**
  - Kimi-K3 renders through the processor. The router's own `kimi::normalize` is gone; the chunked tiktoken encode stays.
  - Every text chat forwards `input_ids` (`AllText`).
  - Kimi chats lower to `/generate` like other `AllText` models. `required`, named and strict `tool_choice`, system-turn tools, media and `logprobs` (no `tokenizer.json`) keep the engine's route.
- **Parsing (`openai/`, `think/`, `tool_call/`):**
  - `think/models/kimi_k3.rs`: `KimiK3Detector` from `parser/reasoning_parser.py` (XTML think channel, response/message unwrapping, skipped-think detection, tools passthrough). `ThinkConfig` becomes an enum so a detector that overrides the base splitting gets its own variant.
  - `tool_call/models/kimi_k3.rs`: the `kimi_k3` detector from `function_call/kimik3_detector.py`.
  - `openai/kimi_k3_tag.rs`: the `tool_choice: auto` structural tag (`get_kimik3_auto_tool_call_structural_tag`), with `strip_structural_tag_excludes`.
  - `kimi_k3_format.rs`: the XTML markers and helpers the three share (`kimik3_format.py`).
  - `lower_chat` / `ChatResponder` apply `serving_chat.py`'s K3 rules: `skip_special_tokens=False`, `<|close|>tools<|sep|>` as a stop string, thinking on unless kwargs turn it off, non-strict `json_schema` unconstrained (`renderer_handles_response_format`), `name:N` tool-call ids (`_process_tool_call_id`), and the three-token generation stub left out of reported prompt tokens. `ChatModel` carries `chat_encoding_spec`.

## Checks

- **Render:** 112 cases match SGLang's prompt text and token ids at `moonshotai/Kimi-K3@f831ab66`, using the real tiktoken vocab. 13 are known gaps that the processor leaves to the engine. `generate_parity.py` records the template text for a spec that tokenizes inside `apply_chat_template`.
- **Parsers and OpenAI layer (fixtures from SGLang's Python):**
  - `reasoning_parity/kimi_k3.json`: 96 cases (19 outputs × forced/unforced × streamed/not, plus `force_nonempty_content` for 5), chunked to split every marker.
  - `tool_parity/kimik3.json`: 46 chunked outputs (43 distinct), including token-level and single-character splits, truncation mid-marker, and typed argument values (integers beyond 64 bits, `-0`, `NaN`, `Infinity`, overflowing floats, duplicate keys, escapes, strings `json.loads` rejects, and an argument of 5,000 nested arrays). Values go through `json.dumps(json.loads(...))` exactly (`py.rs::python_json_reencode`), so integers keep their digits; the scanner neither recurses nor copies per level, so nesting costs heap, not stack, and past Python 3.12's ~10,000-container `RecursionError` the value is treated as JSON Python cannot load.
  - `openai_parity/kimi-k3.json`: 24 cases recorded from `OpenAIServingChat` (including an 8-hop `$ref` chain for the tag's schema typing, which stops past 64 levels or 10,000 steps and leaves such tools to the engine) (including tools with `regex: ""` / `ebnf: ""`, which Python treats as unset, so the tag stays); the `/generate` body (prompt ids, stop list, the auto structural tag byte for byte, including every `_schema_types` branch) and the OpenAI response (unary and streaming, usage, tool-call ids, `n=2`) match for all 22 served, and the 2 others are left to the engine.
  - Dynamo's own `kimi_k3` reasoning parser, tool parser and structural tag match these Python fixtures in 13/54, 35/51 and 1/22 cases (response wrappers left in content, a different tag grammar), so the processor ports SGLang's; the three share `kimi_k3_format.rs`, as Python's share `kimik3_format.py`.
- **End to end on 8×B300 (cookbook B300 Low-Latency recipe: TP8, `--mem-fraction-static 0.85`, `kimi_k3` parsers):** each request is sent to the engine and through the real `sgl-router` binary.
  - **Real weights (`moonshotai/Kimi-K3@f831ab66`):**
    - 48 greedy chats (math, effort levels, thinking off, JSON output, single, parallel and serial tool calls, tool results, continuation, truncation; unary and streaming): 46 of 48 are served via `/generate` and the router's `/generate` bodies match the `GenerateReqInput` `OpenAIServingChat` builds for all 46. Responses match except two whose generations diverge mid-reasoning from identical inputs, as the engine also does between its own runs; on six repeats each, the router and the engine give the same output.
    - GSM8K (1319, chat API, `reasoning_effort=low`): 0.977 through the engine and 0.977 through the router, all router requests via `/generate`.
    - `bench_serving` (`sglang-oai-chat`, random 8192 in / 1024 out, every router request via `/generate`):

      | concurrency | path | output tok/s | median TTFT (ms) | median ITL (ms) |
      |---|---|---|---|---|
      | 16 | engine | 613 | 5042 | 19.2 |
      | 16 | router | 654 | 4119 | 19.2 |
      | 64 | engine | 1071 | 12505 | 31.8 |
      | 64 | router | 1070 | 12540 | 31.9 |
  - **Dummy weights with scripted K3 outputs** (a custom logit processor forces think, response and tools channels): 59 cases identical, 55 via `/generate`; plus 159 free-form cases identical except engine-side nondeterminism and timing fields.
- The proxy tests cover both routes: a Kimi chat lowers to `/generate` with the router's ids, `skip_special_tokens=false`, `require_reasoning` and the tools stop; unsupported shapes keep the chat route.
- `cargo test` and `cargo clippy -D warnings` pass for `rust/` and `experimental/sgl-router`.
