# [Test] ngram: Add shared code-edit benchmarks for SGLang and TensorRT-LLM

[Upstream PR](https://github.com/sgl-project/sglang/pull/47388) · state: open · merged: False

## Original PR description

## Motivation

The existing NGRAM country-card benchmark reports acceptance length, but does not measure code-edit throughput against another inference engine. This PR adds a shared-input code-edit benchmark for SGLang and TensorRT-LLM, with exact prompt-token checks, request isolation, and separate generation/workflow timing.

This builds on the global Trie/SAM allocation implementation in #37879 and complements the country-card/distractor benchmark in #37877. Both related PRs are still open. The current diff against `main` includes the inherited global-tree implementation as well as the benchmark additions and Docker build fixes. Keep this PR in draft while the dependency is integrated, the branch is updated against current `main`, and baseline-output differences are investigated.

## Modifications

- Add the [TRT preparation and benchmark helper](https://github.com/aaronlinear/sglang/blob/cfbfabd4c5966034649988d36d39910b0b3a4b4a/benchmark/sa_spec/bench.py), which pins the model/dataset revisions, prepares the first 100 code-edit prompts, and runs ordinary decoding, NGram, SA with match size three, and longest-match SA.
- Add the [SGLang benchmark runner](https://github.com/aaronlinear/sglang/blob/cfbfabd4c5966034649988d36d39910b0b3a4b4a/benchmark/ngram/bench_code_edits.py), comparing ordinary decoding, legacy BFS/PROB allocation, global path probability, and global specificity-weighted path probability. Each mode/repetition starts a fresh server; requests are serial and mode order rotates between repetitions.
- Export prompt IDs through TRT's own tokenizer/dataset loader. Before SGLang starts, check the dataset hash, manifest, model/tokenizer metadata, row order, prompt text, output budget, and complete token arrays. Send the exported IDs directly to `/generate` and check the server's echoed IDs.
- Load only the current prompt's exact tokens as the external SAM corpus, flush request state, and remove/check the corpus between requests. Neither reference solutions nor TRT-generated answers become SGLang inputs. Add native-corpus API support for raw `token_chunks`, including shape, vocabulary, and token-budget validation.
- Save provenance, resolved settings, per-request output IDs, streaming timings, final speculative counters, and baseline comparisons. Report HTTP, workflow, and full-client-window throughput separately. Add an offline mismatch inspector for first divergences, affected tasks, repeatability, and pairwise mode agreement.
- Include the global-tree implementation from #37879: joint Trie/SAM proposal allocation, path-probability and specificity scoring, parent-before-child tree materialization, CLI/FFI integration, and unit/reconstruction coverage. Global allocation remains an explicit opt-in; the default is `disabled`.
- Add a prebuilt-container launcher, environment checks, an optional thin Dockerfile, CPU tests, and [reproduction/comparison documentation](https://github.com/aaronlinear/sglang/blob/cfbfabd4c5966034649988d36d39910b0b3a4b4a/benchmark/ngram/README.md). The branch also carries root Dockerfile fixes for shared build-argument defaults, qualified CUDA image names, and gateway build parallelism/file limits.

### Shared benchmark contract

| Setting | TensorRT-LLM helper | SGLang runner |
| --- | --- | --- |
| Model | Prepared Llama-3.1-8B base snapshot, BF16 | Same prepared snapshot, BF16 |
| Inputs | First 100 rows of pinned `glaiveai/code_edits_sample`, raw completion prompts | Same prepared rows and exported TRT prompt token IDs |
| Generation | Greedy, 256 output tokens, EOS ignored | Same |
| Load | TP=1, batch/concurrency=1 | TP=1, serial requests, maximum running requests=1 |
| Draft capacity | Four draft proposals | Width five: current token plus four proposals |
| Prefix KV reuse | Disabled | Disabled, with explicit flush between requests |
| Chunked prefill | Disabled | Disabled |
| Decode graph batch size | One | One |
| Warmup | Ten requests, excluded | Ten requests, excluded |

`prepare` writes `model/`, `dataset.jsonl`, and `manifest.json`. The token export invokes the same `initialize_tokenizer` and `create_dataset_from_stream` functions used by `trtllm-bench` and writes `trt-inputs.json`. SGLang verifies and consumes that export. The optional `--trt-results` argument only imports performance reports; it does not affect generation inputs.

The code enforces input agreement with the export. Establishing the identity of a historical TRT timing run still requires its preserved inputs/runtime records; the export is a preprocessing pass, not a capture from that older run. Model metadata and the weight index are hashed, while weight shards are reused from the prepared snapshot rather than independently rehashed.

The 18 benchmark CPU tests cover exact HTTP token forwarding, request isolation and cleanup, stream validation, dataset hash drift, warmup exclusion/mode rotation, report aggregation, and offline mismatch inspection. The five tokenizer-control tests cover unchanged raw-token forwarding, invalid IDs/shapes, token-budget enforcement, ambiguous input rejection, and the existing document-tokenization path. The latter ran on macOS with SGLang's in-tree platform stubs; neither suite establishes CUDA execution or model-output equivalence.

The completed SGLang H200 matrix had 100 requests per mode and three repetitions. Baseline outputs repeated exactly. The subsequent artifact inspection reported exact repeatability within each speculative mode and identical outputs between the two global modes, but both global modes differed from baseline on nine unique prompts. Legacy BFS differed on 11 prompts and legacy PROB on 12. These correspond to 27, 33, and 36 request/repetition mismatches respectively.

All measured requests passed prompt-ID and fixed-output-length checks. `--fail-on-mismatch` raised after all 15 trials completed and the summary was saved. The performance data is retained, but baseline-output equivalence is unresolved. Numerical differences across execution shapes and implementation errors have not been distinguished; neither these timings nor repeatability establish code-edit accuracy. The historical TRT speculative modes also reported `Same text=False`, without full-run mismatch counts.

## Speed Tests and Profiling

Historical runs on one H200 using the shared workload above. SGLang results were reported on 2026-10-15 at runner revision `0392849b4e9bdabb772a7fafef940b42251d5a1e`; the benchmark/reporting scripts are unchanged at this PR head. TRT results are the earlier 2026-10-10 median summary using TRT-LLM `1.3.0rc25`. No new GPU run or profiling was performed when opening this PR.

| SGLang mode | HTTP tok/s | Workflow tok/s | HTTP speedup vs own baseline | Mismatching pairs / 300 |
| --- | ---: | ---: | ---: | ---: |
| baseline | 204.54 | 199.53 | 1.000x | 0 |
| legacy_bfs | 373.84 | 287.71 | 1.828x | 33 |
| legacy_prob | 375.08 | 345.17 | 1.834x | 36 |
| path_probability | 500.45 | 462.17 | 2.448x | 27 |
| specificity_path_probability | 540.41 | 495.30 | 2.642x | 27 |

SGLang rates are medians across three trials; speedups are medians of ratios to the paired baseline. Workflow includes cache flush, prompt-corpus setup, isolation checks, generation, and cleanup. It excludes model startup and warmup.

| TRT mode | Internal output tok/s | Speedup vs own baseline | Same text as baseline |
| --- | ---: | ---: | --- |
| baseline | 197.55 | 1.000x | True |
| ngram | 522.09 | 2.643x | False |
| sa3 | 605.94 | 3.067x | False |
| sa_longest | 631.83 | 3.198x | False |

TRT rates are the helper's median summary; the repetition count was not included in the supplied summary. Its speedups are ratios of median rates. The separate detailed NGram report's 527.3613 tok/s is one trial and is not substituted for the 522.09 median above.

Within SGLang, the best global mode has 44.1% higher HTTP throughput than legacy PROB; specificity weighting adds 8.0% over plain path probability. Its reported HTTP rate is 3.5% above TRT NGram, with essentially the same baseline-relative gain (2.642x versus 2.643x). It remains 10.8% below TRT SA3 and 14.5% below TRT SA-longest. These are descriptive comparisons of the reported rates, not controlled estimates of a framework advantage.

Comparison limits:

- TRT measures an internal request window without detokenization. SGLang HTTP includes transport and detokenization but excludes prompt-SAM setup; SGLang workflow includes setup/cleanup. TRT SA initialization occurs inside generation, so neither printed boundary is identical across frameworks.
- TRT uses a whole request window; SGLang HTTP/workflow rates use summed request durations. SGLang also saves full-window rates, but they are not in the pasted table.
- Retrieval and execution differ: SGLang uses a static prompt SAM plus online Trie; TRT uses growing request-local NGram/SA history. Match limits and tree/chain work differ despite equal draft capacity. The recorded TRT smoke forced overlap off for NGram while SA kept it on; SGLang's default matrix requires overlap on.
- Warmup selection and memory-allocation settings differ. TRT's `max_num_tokens=8192` is a runtime token budget, whereas SGLang's `context_length=8192` is a sequence limit.
- Raw GPU artifacts are not included in this PR. Exact historical provenance, output-equivalence diagnosis, and statistical variability still need the saved run artifacts. These results describe this serial fixed-length workload.

See the [README](https://github.com/aaronlinear/sglang/blob/cfbfabd4c5966034649988d36d39910b0b3a4b4a/benchmark/ngram/README.md) for token export, the strict 10-request smoke, the 100-request/three-repetition matrix, mismatch inspection, and separate scheduler controls.
