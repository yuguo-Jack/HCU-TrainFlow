# [Test] hicache: Run the unified transfer-lifecycle cases on a fake device for events and streams

[Upstream PR](https://github.com/sgl-project/sglang/pull/46801) · state: open · merged: False

## Original PR description

## Motivation

`test_unified_hicache_transfer_lifecycle.py` is a CPU-CI test, but on a machine with a visible CUDA device four of its `_UnifiedHiCacheCase` cases fail (also noted in #43932 as failing identically on its base):

- `TestSwaLoadBackReservation::test_reservation_retries_once_after_device_eviction`
- `TestLoadBackAdmission::test_host_match_stays_pinned_while_reclaim_evicts_host_leaves`
- `TestLoadBackAdmission::test_shared_budget_reclaims_for_the_load_and_pending_demand`
- `TestWritePolicySwitch::test_incompatible_host_tree_is_rejected_without_side_effects`

Two mismatches in the fixture cause this:

1. **Events and streams.** The fixture swaps only `torch.cuda.current_stream` for a recording `_Stream`. But `cache_controller.py` and `l2_transfer.py` each cache `device_module = get_device_module()` at import time. With CUDA visible, that is `torch.cuda`, so the controller creates real `torch.cuda.Event`s. Calling `record()` with no argument resolves the patched `current_stream()` and gets a `_Stream`, which fails with `RuntimeError: expected stream to be a torch.Stream or torch.cuda.Stream object`. Without CUDA, `torch.cpu.Event` hides this, and its events are always complete.
2. **Host registration.** `_cuda_host_register` is patched only around `init_hicache`, but cleanup (`release_host_resources`) runs the real `_cuda_host_unregister` on CPU buffers that were never registered. With CUDA visible this returns rc=713 (`cudaErrorHostMemoryNotRegistered`), and the warning path then raises a `TypeError` in teardown, so each failing case also gets a teardown error.

## Modifications

Test-only, one file:

- A `_Device` stand-in (`Event`, `Stream`, `current_stream`, `stream`) replaces `device_module` in both `cache_controller` and `l2_transfer`. It is installed before `init_hicache` and stays in place until after `release_host_resources`. The events have state: an event finishes when it is recorded, unless the device is inside `hold()`. Events recorded under `hold()` stay pending until `complete_pending()`, and `synchronize()` completes the event it is called on. So the fake keeps a real in-flight window instead of reporting every event as done.
- `_cuda_host_register` and `unified._cuda_host_unregister` are now patched for the same lifetime, so registration and unregistration match.
- The real allocator, controller, copies, queues, locks and accounting are unchanged. The `_recorded_stream` stand-in for the allocator's `torch.cuda.current_stream()` waits is also unchanged.
- New case `TestWriteThroughAck::test_rows_stay_pinned_while_the_backup_is_in_flight`: while the D2H finish event is pending, `writing_check()` keeps the ack queued and the node's device lock held. Both are released only after the event completes. Before this change, every event in this file was complete, so nothing here covered that window.

Related: the teardown `TypeError` comes from `cudaGetErrorString` being passed an `int` rc in `pool_host/common.py`. That production bug is addressed separately by #43795. This PR only stops the test from reaching that path.

## Validation

1x H20 (driver 595), torch 2.14.0+cu130, sglang-kernel 0.4.9, Python TreeCore (Rust extensions not built), on `main` at `e4d4a9a7`. These versions are one patch below the pins (torch 2.14.1, sglang-kernel 0.4.10). The test calls no kernels, and the failure depends only on `torch.cuda.Event.record` rejecting a non-CUDA stream:

| Run | Base (`e4d4a9a7`) | This PR |
| --- | --- | --- |
| CUDA visible | 4 failed, 4 passed, 4 teardown errors | 9 passed |
| `CUDA_VISIBLE_DEVICES=""` | 8 passed | 9 passed |

The four base failures are `RuntimeError: expected stream to be a torch.Stream or torch.cuda.Stream object`. The four teardown errors are the `cudaGetErrorString` `TypeError` after `cudaHostUnregister` returns 713. An earlier run on an RTX 3070 (driver 535, torch 2.14.1+cu126, base `0cf683ea`) gave the same table.

- Mutation check: removing the `finish_event.query()` gate in `_count_ready_acks` fails only the new case (`0 != 1`).
- Patches restored after a failing `init_hicache`: a local plugin forces the host-memory budget check to fail inside `init_hicache`, after the fixture has installed its patches. A follow-up test in the same process (CUDA visible) then checks that `device_module is torch.cuda` in both modules, that the register/unregister functions are the originals, and that a real `torch.cuda.Event().record()` works. It passes.
- Same process with `test_hicache_staged_write_back_dispatch.py`, `test_storage_prefetch_lifecycle.py` and `test_unified_hicache_regressions.py` (CUDA visible): 61 passed, 1 skipped. The skip is an existing case in `test_hicache_staged_write_back_dispatch.py`.
- `pre-commit run --files <file>`: all hooks pass.
