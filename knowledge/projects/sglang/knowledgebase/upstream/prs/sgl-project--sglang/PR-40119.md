# Expose flush_cache timeout through the Python Engine API

[Upstream PR](https://github.com/sgl-project/sglang/pull/40119) · state: closed · merged: False

## Original PR description

## Motivation

`Engine.flush_cache(timeout_s=2.5)` raises `TypeError` before reaching the manager, although `TokenizerManager.flush_cache` and the HTTP endpoint already support the scheduler's optional wait timeout. Expose the same option through the embedded Python API.

**Draft for initial API review.** Lint CI and the direct Mac CPU regression tests pass. Upstream Linux CPU tests remain pending: the current test workflows stop at the Draft gate, before executing tests.

## Modifications

- Accept `timeout_s: Optional[float] = None` and forward it unchanged to the manager.
- Preserve default calls, return values, failure messages, and exceptions.
- Add registered CPU regression coverage and document the existing immediate/deferred behavior. No new retry logic, scheduler idle checks, or DP result aggregation changes.

The backend contract is from #21413 and #21490; #39562 addresses DP result aggregation separately.

## Validation

- [Lint CI passed on this head](https://github.com/sgl-project/sglang/actions/runs/35317737404), including repository-wide pre-commit, all four Rust hooks, and documentation checks.
- **Direct registered test: 4 methods pass** on macOS arm64, Python 3.12.14 / PyTorch 2.13.0, using the alternate-platform `pyproject_other.toml` and `srt_mps` dependencies. Optional Rust extensions were disabled at installation (`SGLANG_BUILD_RUST_EXTS=none`).
- In the same environment, replacing only `engine.py` with the upstream base produces five error cases rooted in the unsupported `timeout_s` argument; the default-call control still passes. Restoring the exact PR source passes all four methods again.
- This runs the unchanged test file through normal package imports, using the repository's own Mac compatibility layer and `maybe_stub_sgl_kernel()` helper. No external AST extraction or module-replacement harness is used for these results. No Engine/model is constructed.

Invocation from the checkout with the Mac dependencies installed:

```bash
SGLANG_USE_CPU_ENGINE=1 CUDA_VISIBLE_DEVICES=0 HF_HUB_OFFLINE=1 \
  PYTHONPATH=python python -B \
  test/registered/unit/entrypoints/test_engine_flush_cache.py -v
```

The Mac platform compatibility layer needs a normal host environment where Metal availability can be queried. The initial restricted-sandbox attempt could not see Metal and failed importing Triton; an empty `CUDA_VISIBLE_DEVICES` also failed in the shared test utilities. The successful CPU run uses the environment above. These tests cover the synchronous API wrapper, not real backend wait timing or GPU behavior.
