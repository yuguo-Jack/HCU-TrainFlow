# [Fix] deepgemm: adapt mhc calls to the {1,m,n} output contract (#43743)

[Upstream PR](https://github.com/sgl-project/sglang/pull/44734) · state: open · merged: False

## Original PR description

Fixes #43743

## What does this PR do?

`mhc_fused_post_pre`'s large-batch path still used the **old DeepGemm contract**: it allocated a `{n_splits, m, n}` output and passed `num_splits` explicitly to `tf32_hc_prenorm_gemm`. The current contract (and the pin `sgl-deep-gemm` exposes via its C++ assertion) only accepts `{1, m, n}` when `num_splits` is given — split-K is now reduced internally — so CUDA-graph capture crashes on the assertion.

The only form valid under **both** the old pinned wheel and the new contract is: 2D `{m, n}` output, no `num_splits` argument (the form `deepseek_v4.py` already uses for its plain GEMM). This PR rewrites all four remaining old-contract call sites to that form:

- `mhc.py::mhc_fused_post_pre` (the issue's crash): 2D output, then `unsqueeze(0)` to `{1, m, n}` with `n_splits=1` for the downstream big-fuse kernel — same shape the fallback branch already feeds it; also removes the now-useless large `{n_splits, m, n}` pre-allocation.
- `mhc.py::mhc_pre` (same old contract, reachable via the default-on path and `prewarm_mhc_pre`)
- `mhc.py::hc_mix_stats_sinkhorn_deepgemm` (2 GEMMs + reduce with `NUM_SLICES=1`, offsets proven elementwise-equivalent to the previous 3D layout)
- `deepseek_v4.py::_flashinfer_hc_pre` (behind `SGLANG_OPT_USE_FLASHINFER_MHC`; removes the dead squeeze branch)

## Verification (GPU e2e not runnable here — stated plainly; mock/CPU level)

- Mocked `deep_gemm` implementing **both** contracts, injected into the real (AST-extracted) old and new function sources: old code crashes the new-contract assertion with exactly the issue's shape error; new code passes both contracts, and downstream kernels receive `{1,m,n}` with `n_splits=1`. Small-batch FMA (`{4,m,n}` TileLang partials) and fallback paths verified unchanged. 17/17 checks.
- The pinned `sgl-deep-gemm==0.2.2` wheel was unpacked: its embedded assertion text proves `num_splits>1` requires `{n_splits,m,n}` there, i.e. the no-`num_splits` 2D form is the only dual-compatible choice.
- Local wheel execution-level verification is not possible on this machine (the wheel aborts inside its C++ entry for any input on sm120, before any kernel of ours), stated explicitly.

## Notes

- Dead code left behind on purpose (`_flashinfer_mhc_pre_num_splits` etc.) — cleanup can follow once maintainers confirm the contract migration.
- Old-contract callers lose the explicit caller-side split-K, which the issue reporter measured as no-benefit on this fused path anyway.
