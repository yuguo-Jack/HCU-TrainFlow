# [Perf] diffusion/preprocess: Extend exact GPU input processing across pipelines

[Upstream PR](https://github.com/sgl-project/sglang/pull/45733) · state: closed · merged: True

## Original PR description

## Summary

Extend the exact RGB preprocessing introduced in #45398 beyond Cosmos3, using one shared resize/crop/normalize entry point rather than per-model kernels.

This PR includes the original commit from @xupinjie with its authorship preserved because #45398 is still open. It should land after that PR; merging main afterwards will remove the overlapping diff.

- Cover FLUX.2/Klein reference images, Qwen-Image-Edit 2509/2511 VAE inputs, Wan TI2V, Cosmos3 I2V/V2V, and RGB conversion in the shared image-VAE stage.
- Upload compact uint8 pixels, fuse Lanczos/crop/FP32 normalization, and fast-path identity resize. Preserve Pillow rounding, each model's crop geometry, and encoder input strides.
- Bound video decoding for first-frame and control-video consumers instead of decoding the full clip and slicing afterwards.
- Retain CPU processing for unsupported platforms/modes and small workloads; reuse `SGLANG_FORCE_CPU_IMAGE_PREPROCESSING=1` as an override. Include output area when deciding whether an upscale is too small for GPU processing.
- Document temporary VRAM, first-use compilation, and the distinction between input-chain and full-request speedups.

The extension beyond #45398 adds about 146 production lines and removes 30, with no additional production files.

## Accuracy And Tests

- Registered CUDA entry points: all 5 kernel tests and all 3 runtime preprocessing tests pass.
- Existing input-validation/Cosmos3 suite: **158 passed, 55 subtests passed**.
- Exact external Diffusers FLUX.2 and Qwen VAE processor comparisons, including odd/portrait/4K shapes; compare both values (`rtol=atol=0`) and strides.
- Real Wan TI2V geometry and real MP4 first/last/prefix decoding match the CPU reference exactly. Non-RGB floating-point VAE inputs retain their original normalization policy.
- Native E2E: all **12 paired output files** (warmup plus three distinct requests for each of three models) match baseline SHA-256, including saved PNG/MP4 files. No GT or consistency threshold changes.
- Pre-commit and diff whitespace checks pass.

Cosmos3 is covered by preprocessing tests, not a full checkpoint E2E run. No general cross-hardware bitwise-equivalence claim is made.

## Performance

Hardware/software: **1 NVIDIA H200, 143771 MiB reported total VRAM**, Intel Xeon Platinum 8558P host; PyTorch 2.14.1+cu130, CUDA 13.0, Triton 3.8.0, Diffusers 0.37.0, Transformers 5.19.0, Pillow 11.3.0, PyAV 16.1.0.

### Complete Native Requests

Baseline: `5f62e23d3051d09fa711f825b20abead20c3a717`; candidate: `17c917344bd639a90abae9c2644c12de96853396`. Both sides use the native SGLang pipeline, one GPU, batch 1, four steps, seed 42, `quality=exact`, manual/resident placement, no torch.compile or CUDA Graph. Input: distinct 1920x1080 PNGs/prompts to avoid conditioning-cache hits. One warmup and three measured requests per process; report medians, excluding loading but **including file decoding, preprocessing, transfer, learned encoding, denoising, decoding, output encoding/saving, and API return**.

| Model / Output | Baseline | GPU input path | Observed latency reduction |
| --- | ---: | ---: | ---: |
| FLUX.2-klein-4B / 512x512 | 494.3 ms | 454.6 ms | 8.0% |
| Wan2.2-TI2V-5B / 17x704x1248 | 2240.9 ms | 2210.4 ms | 1.4% |
| Qwen-Image-Edit-2511 / 512x512 | 1530.7 ms | 1498.9 ms | 2.1% |

These are bounded low-step samples, not a statistical guarantee or a universal model speedup. Longer denoising workloads amortize input processing further.

Peak allocated VRAM (same requests): FLUX 16893.02 -> 16904.59 MiB; Wan 48772.43 -> 48772.53 MiB; Qwen 57158.03 -> 57170.23 MiB. This is **not zero-extra-VRAM**: temporary pixels and coefficient buffers live on GPU. Peak reserved VRAM was unchanged for Wan/Qwen and increased by 12 MiB for FLUX.

### Input Chain In Isolation

Synthetic RGB JPEGs, quality 92, warm filesystem cache, resize to 1024x1024, three warmups plus ten measured samples. Includes JPEG file decode, resize/crop/normalize, H2D, and CUDA synchronization; excludes learned encoder/denoiser work. CPU override vs GPU path in the same checkout; outputs match exactly.

| Source | CPU input chain | GPU input chain |
| --- | ---: | ---: |
| 1024x1024 | 22.94 ms | 12.55 ms |
| 1920x1080 | 60.97 ms | 25.22 ms |
| 3840x2160 | 204.44 ms | 112.20 ms |

Image/video codec decoding and tokenization remain on CPU where they were previously. Output codecs are unchanged: this does not silently substitute NVENC for libx264 or claim that all CPU work has moved to GPU.
