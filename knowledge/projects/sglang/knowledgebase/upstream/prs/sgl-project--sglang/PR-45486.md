# [Fix] [AMD] MoE: Preserve CT FP8 Triton layout and reduction dimensions

[Upstream PR](https://github.com/sgl-project/sglang/pull/45486) · state: closed · merged: True

## Original PR description

## Motivation

With `SGLANG_USE_AITER=1` and an explicit Triton MoE runner, compressed-tensors CHANNEL FP8 layers receive AITER-shuffled weights and lose 128 reduction elements in the non-block FP8 kernel (1024 → 896 in the regression). Both cause incorrect outputs.

## Modifications

- Shuffle CT CHANNEL FP8 weights only for an actual AITER runner.
- Match the non-block FP8 kernel's padding calculation to its existing caller when AITER is enabled.
- Add an AMD CI-registered runtime quantization test under `test/registered/unit/layers/quantization/`, covering checkpoint loading, postprocessing, and numerical Triton/AITER MoE comparisons with 1- and 33-token inputs.

Related: [#41636](https://github.com/sgl-project/sglang/pull/41636) addresses the shuffle mechanism in `Fp8MoEMethod` block-FP8; this PR fixes the separate compressed-tensors CHANNEL path and the non-block kernel dimension calculation.

### Real-checkpoint validation

`RedHatAI/Qwen3-30B-A3B-FP8-dynamic`, revision `10a439027a4fd228adc03a7bffb1aac10a179938`, was evaluated on the same MI355X image and base/head sources. All four arms observed actual CT CHANNEL execution in all 48 layers and verified the loaded source hashes. TP1, eager execution, AITER enabled, padding disabled; 200 GSM8K test examples, five demonstrations from the train split, greedy decoding, maximum 512 generated tokens.

| Configuration | Correct / 200 |
| --- | --- |
| Base, AITER runner | 180 |
| Base, AITER runner repeat | 179 |
| Base, explicit Triton runner | 0 |
| Patched, explicit Triton runner | 181 |

All 800 predictions were independently rescored and prompt/dataset hashes verified. Every base Triton output hit the 512-token cap. This is a configuration-specific sanity check, not full-dataset accuracy or statistical equivalence; default AITER is the known-good reference.

## Speed Tests and Profiling

A separate fixed-output probe (four prompts, 64 tokens each, three timed repeats after warmup) measured median output rates of 103.88 tok/s for base Triton and 104.75 tok/s for patched Triton; AITER reference runs measured 99.71 and 103.64 tok/s. This bounded probe is not a production throughput or speedup claim.
