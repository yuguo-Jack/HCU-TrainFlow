# [Fix] [AMD] scripts: Run and correctly test Dockerfile-only PRs (CI filter + AITER rebuild)

[Upstream PR](https://github.com/sgl-project/sglang/pull/47395) · state: closed · merged: True

## Original PR description

## Motivation

A PR that only bumps the AITER pin in `docker/rocm.Dockerfile` currently gets no real AMD test coverage, for two reasons:

1. **The tests don't run.** `docker/rocm.Dockerfile` starts the AMD workflow, but it isn't in any of the `check-changes` filter groups. Every test job is skipped and the run still shows green.
2. **Tests that do run use the old AITER.** CI runs on a prebuilt image, which is usually a day or two old. The install script is supposed to rebuild AITER when the image's version doesn't match the Dockerfile pin, but that check never fires. For example, in run 38779037426 (2026-10-15) the pin was `2bb549102`, the image had `e7d2453f2`, and the rebuild was still skipped.

## Modifications

- `.github/workflows/pr-test-amd.yml`: add `docker/rocm.Dockerfile` to all four filter groups, so a Dockerfile change runs the tests.
- `scripts/ci/amd/amd_ci_install_dependency.sh` (gfx942/gfx950 only; gfx1250 is unchanged):
  - Read the AITER commit from the image's version string (the part after `+g`) and compare it with the Dockerfile pin. If they match, keep the image's AITER. If not, rebuild AITER and log why.
  - The rebuild repeats the Dockerfile's AITER steps, including the three patches the Dockerfile applies. All three are still needed at the current pin.
  - Kernels are not compiled ahead of time. Doing that takes about 2 hours per GPU type, which is longer than the job timeouts. Instead, each kernel compiles the first time a test uses it.

## Testing

I ran the real script sections on an MI355 machine:
- On an image whose AITER matches the pin, the rebuild is skipped.
- On an image with an older AITER (`2bb549102` vs. pin `285579b62`), AITER is rebuilt in 94s and the installed version matches the pin. After that, an AITER op test passes; its first run, including kernel compilation, took 60s.
- The last commit only reorganizes the script: on gfx942/gfx950 it runs the same commands as the tested version, in a slightly different order, and gfx1250 runs the same commands as on `main`. I checked this by printing the commands each version runs, not on a GPU.
