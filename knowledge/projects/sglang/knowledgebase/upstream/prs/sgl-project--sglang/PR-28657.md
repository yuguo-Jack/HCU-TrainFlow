# fix(openai): avoid IndexError and keep the assistant header when continue_final_message empties messages

[Upstream PR](https://github.com/sgl-project/sglang/pull/28657) · state: open · merged: False

## Original PR description

## Problem

In the DeepSeek encoding branch of `_process_messages` (`chat_encoding_spec` in `dsv4`/`dsv32`), `continue_final_message=True` with a single trailing assistant message makes `_handle_last_assistant_message` strip that message and leave an empty list. Two things then go wrong:

1. `messages[0]["role"]` in the empty-system-prompt insertion raises `IndexError: list index out of range`.
2. Even with the indexing guarded, nothing is left to render the assistant generation header, so appending `assistant_prefix` at the token level would continue bare text rather than an assistant turn.

`_validate_request` only rejects an originally-empty `messages`, so the list empties after validation and is not caught.

## Fix

- Guard the system-prompt insertion with `not messages or messages[0]["role"] != "system"`.
- Remember the emptied list right after the strip (the inserted empty system message would mask it), and when it was emptied, encode the spec's assistant generation header explicitly before appending the prefix: `ASSISTANT_SP_TOKEN` plus the thinking start/end token for dsv4/dsv41, `<｜Assistant｜>` for dsv32, mirroring what each encoder emits on a normal generation.

## Test

Added `test_dsv_encoders_handle_continue_final_message_only_assistant` to `test/registered/unit/entrypoints/openai/test_serving_chat.py` (CPU unit test), covering dsv4 and dsv32: no IndexError, and the rendered prompt contains the assistant generation header.

When `continue_final_message=True` and the request contains only a single trailing assistant message, the assistant message is stripped, leaving an empty list (or only the system message). In this case, the custom DeepSeek encoders (`dsv4` and `dsv32`) will not append the assistant start token (`<｜Assistant｜>`) because there are no user or developer messages in the remaining list. This results in a malformed prompt missing the assistant role marker.

To fix this, we should check if the remaining messages contain any user, developer, or tool messages. If they do not, we must prepend the assistant start token to `assistant_prefix` before it is encoded and appended.

```suggestion
            # If the remaining messages do not contain any user, developer, or tool messages,
            # the encoder won't append the assistant start token. We must prepend it to assistant_prefix.
            if assistant_prefix and not any(m.get("role") in ("user", "developer", "tool") for m in messages):
                assistant_start = "<｜Assistant｜>" + (
                    "<think>" if thinking_mode == ThinkingMode.THINKING else "</think>"
                )
                assistant_prefix = assistant_start + assistant_prefix

            # messages can be empty here when continue_final_message strips a lone
            # trailing assistant message, so guard before indexing messages[0].
            if not messages or messages[0]["role"] != "system":
                # insert an empty system prompt to help render tool system prompt
                messages.insert(0, {"role": "system", "content": ""})
```
