# [CI] tests: Let test_hicache_storage size its host cache to the runner

[Upstream PR](https://github.com/sgl-project/sglang/pull/44729) · state: closed · merged: True

## Original PR description

## Motivation

`base-b-test-1-gpu-small (7)` fails on PRs whenever it lands on a smaller 5090 runner: `test/registered/hicache/test_hicache_storage.py` launches its server with `--hicache-size 100`, a fixed 100 GB pinned host pool, and on runners with roughly 51-81 GB of host memory the server is OOM-killed at launch:

```
CI_OFFLINE: Offline launch failed (Server process exited with code -9), retrying with online mode...
Exception: Server process exited with code -9. Check server logs for errors.
✗ FAILED: .../test/registered/hicache/test_hicache_storage.py returned exit code 5
```

The same shard passes when it draws a larger runner, so affected PRs only get through by rerunning until they do. It hit four unrelated PRs on 2026-10-16 (#44583, #44533, #44613, #44614).

## Modifications

On CUDA the test no longer passes `--hicache-size`. With neither `--hicache-size` nor `--hicache-ratio` set, the server uses the default host/device ratio and `--hicache-host-memory-fraction` (0.8 by default) reduces it until the host pools fit the machine's available memory, including the cgroup limit. The test still exercises the hierarchical cache with the `file` storage backend and the same MMLU threshold. ROCm keeps its explicit `--hicache-size 200`.

## Test plan

- `black`, `isort`, `ruff check --select=F401,F821,F823,UP037` clean on the changed file.
- Not run locally: the test's model (`meta-llama/Llama-3.1-8B-Instruct`) is gated on the available machine, and its environment predates main's kernel requirements. This PR's own `base-b-test-1-gpu-small (7)` runs the test on the affected 5090 runners and is the validation.
