# [Fix] hicache: Reject v1-only storage backends at attach time on multi-pool cache stacks

[Upstream PR](https://github.com/sgl-project/sglang/pull/46016) · state: open · merged: False

## Original PR description

## Motivation

The multi-pool v2 storage API (`batch_exists_v2`/`batch_get_v2`/`batch_set_v2`) was added in #20457, and backends are expected to override all three methods to serve multi-pool cache stacks. Three backends never got that update: aibrix, simm, and eic. The base class defaults just raise `NotImplementedError`.

So this combination is selectable today:

- hybrid model (Mamba/SWA/DSA, anything that creates sidecar pools) + one of those backends
- the server starts fine, accepts requests
- the first storage transfer hits `batch_exists_v2` and dies with a bare `NotImplementedError`, no hint about which config knob is wrong

The lookup path calls it as soon as `pool_transfers` is non-empty, so this is not a corner case. It will always crash once the storage layer sees traffic.

This change makes the failure happen at attach time instead, with an error that names the backend and the sidecar pools and says what to do about it.

## Modifications

- `HiCacheStorage.supports_pool_transfers()`: classmethod that checks whether the backend overrides the three v2 methods. No hardcoded backend list, a backend advertises support by overriding, same as the rest of the API.
- `HybridCacheController.attach_storage_backend()` now validates sidecar pool support after `super()` attaches. If the host pool group has non-anchor pools and the backend lacks the v2 methods, it raises `ValueError` naming the backend and pools, and rolls the attach back through `detach_storage_backend()` so nothing stays half-wired. This covers both the startup attach and the runtime admin attach path.
- `register_host_pool_entry()` runs the same check for sidecars registered after attach (decode retraction backup pools, draft sidecars). The entry is rejected before it lands in the pool group.
- Anchor-only stacks are not affected. Plain MHA/MLA models on a v1-only backend never issue v2 transfers, so existing setups keep working.

## Accuracy Tests

No model output changes. This converts a late crash into an early one, control path only.

New unit tests in `test/registered/unit/mem_cache/test_hicache_sidecar_backend_gate.py` (CPU, no GPU needed):

- probe reports no support for the base class and for a partial override (overriding one of the three methods must not count as support)
- v1 backend + sidecar pools raises at attach, message contains the missing API names and the pool names
- v2 backend + sidecar pools attaches fine
- v1 backend + anchor-only stack attaches fine (no behavior change for existing setups)
- gate failure rolls the attach back (`enable_storage` back to False, `storage_backend` cleared)
- late sidecar registration on a v1 backend is rejected before mutating the pool group
- aibrix/simm/eic are checked from source via AST, since their vendor SDKs are optional dependencies and cannot be imported in CI

I could not run an end-to-end GPU test with a real hybrid model plus aibrix/simm/eic, those need vendor SDKs (`aibrix_kvcache`, Scitix simm lib, AWS EIC infra). The gate logic itself is covered by the mock tests above.

## Speed Tests and Profiling

One method-identity comparison per attach. Nothing added to the serving path.
