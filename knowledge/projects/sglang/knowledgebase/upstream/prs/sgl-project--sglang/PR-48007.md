## Motivation

Unified memory compacts and relocates pages while forwards and host copies may still touch them. Several orderings were incomplete: lazy compaction checked write races against the most recent forward only; the recurrent-state band had no write set although state kernels update slots in place; forwards were recorded only on the overlap path, while pipeline parallelism schedules a stage's next microbatch while earlier ones still run. A move could therefore copy a slot a running forward was still writing. On the scheduling side, an urgent relief made the host wait for the running forward, and HiCache window copies pinned every band while any copy was queued, which kept compaction off under write-through.

## Modifications

- Every launched forward (overlap and PP paths) is recorded with its token write ids and the state slots it writes (working, tracking, copy-on-write) until its event fires; a forward whose write ids are produced inside it (a PP stage's verify) holds non-urgent moves until it ends; an overlap speculative batch records its writes as unknown (`managers/scheduler.py`, `scheduler_pp_mixin.py`, `mem_cache/kv/storage.py`, `kv/alloc/band.py`).
- Relief waits on the GPU only: free lists are read to the host before the first wait and kept in step on the host; page lists go device-ward through pinned memory; move and reuse decisions follow retirement (when the scheduler processes a forward's result), so every TP rank decides alike (`kv/alloc/band.py`, `chain.py`, `signals.py`).
- A copy waits only the newest unfinished forward whose recorded writes meet its sources; bytes a move vacates outside the band are fenced with that forward's event, and any later write into them waits it on the GPU.
- The window tail of a preallocated extend is a slice of host-known length instead of `torch.unique` and a boolean filter (no scheduler-stream sync).
- HiCache window copies name their rows by owner token ids and translate them at submission (`managers/cache_controller.py`, `mem_cache/l2_transfer.py`, `unified_radix_cache.py`, `disaggregation/decode_kvcache_offload_manager.py`); the band-wide pin goes. Pages that must not move (a load's reserved rows until submission) are fixed individually; the band still compacts and moves around them.
- Page moves are ordered after the host copies that touch them.
- Tests: `test/registered/unit/mem_cache/test_unified_scheduling_no_host_sync.py` (extend, decode, window tail, retirement and state slots under sync-debug mode), `test_unified_transfer_ordering.py`, `test_unified_float_relocation_ordering.py`, plus updates to the move-gate, HiCache lifecycle and tri-pool tests.

No change without `--enable-unified-memory`.
