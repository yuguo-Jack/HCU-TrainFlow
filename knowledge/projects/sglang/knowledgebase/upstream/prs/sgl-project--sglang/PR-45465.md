## Motivation

With `--enable-encoder-swa-bounded-replay` on HIP, the radix tree still kept an SWA component because the DSpark draft read its SWA through the target's paged mapping, each cached-prefix prefill ran a separate replay forward, and decode / target-verify copied the SWA window ring <-> workspace on every layer. Together these cost hits and decode time.

## Modifications

Three commits, reviewable one by one:

- Draft SWA ring on HIP: `uses_draft_swa_ring()` is true on HIP too (except unified_kv triton) and the pool keeps `swa_valid_from` for it; the HIP radix backend writes the draft block's SWA rows into the ring and skips the full-to-SWA translation.
- Folded replay: HIP folds each hit's replay rows into its extend (`SGLANG_HIP_FOLD_ENCODER_SWA_REPLAY`, default on); extend and late-layer tail rows are floored at the request's replay start via `encoder_swa_row_floor`, MLP-sync padding rows get floor 0.
- In-place decode window: decode / verify rows address the per-request ring directly (`slot * capacity + pos % capacity`), so `buffer()` returns the ring and `commit()` updates the tags once per forward; prefill / extend / replay keep the workspace. `SGLANG_HIP_REQUEST_WINDOW_DIRECT` (default on) switches back.
- Unit tests: folded-replay floor, and the in-place window bit-exact against the workspace path (decode / verify / floor).

## Accuracy Tests

GSM8K 5-shot, 1319 questions, 2x MI355X TP2, DeepSeek-V4.1-Flash + DSpark + encoder replay: main 0.889 -> 0.906.

## Speed Tests and Profiling

AgentX trace replay c64 PDI 8, same setup: TTT/GPU 157,543 -> 174,697 (+10.9%), TPOT p50 13.95 -> 11.84 ms, P90 interactivity 57.3 -> 65.5.
Decode bs16 / bs64 ctx 32k: window kernels -44 to -49 ms of GPU time per 40 steps.
