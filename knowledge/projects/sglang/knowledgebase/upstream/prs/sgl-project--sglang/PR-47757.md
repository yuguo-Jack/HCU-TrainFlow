# [Fix] disagg: Isolate malformed NIXL prefill bootstrap metadata

[Upstream PR](https://github.com/sgl-project/sglang/pull/47757) · state: open · merged: False

## Original PR description

## Problem and proposed behavior

The NIXL prefill bootstrap loop currently lets metadata decoding errors escape the receive loop. A malformed registration or transfer message can therefore terminate the bootstrap thread; transfer parsing can also fail after an empty room entry has already been created.

This is an initial draft for a narrow part of the control-loop fault isolation work tracked in #34510, following the earlier work in #35281.

## Included in this draft

- Parse GUARD registration/transfer metadata completely before registering a peer or publishing transfer metadata to a room.
- Reject missing guards, incomplete mandatory frames, and decoding errors (`ValueError` / `struct.error`), log without frame contents, and continue receiving messages.
- Keep socket, engine, peer-registration application, and room-state errors outside the recoverable parsing boundary. Preserve the existing ABORT and staging handlers.
- Keep the wire format and existing `from_zmq` interfaces unchanged, including optional trailing fields.

## Coordination and scope

#47032 and #45194 contain related Mooncake work. This draft only changes the NIXL **prefill** bootstrap metadata receive path.

#46745 adds optional Rust codecs at the existing NIXL `from_zmq` interfaces. This draft calls those interfaces rather than adding another codec or changing their wire format. There is still adjacent work to coordinate; this PR does not assume that other contributors have excluded NIXL isolation from their plans. I can rebase, narrow, or close this draft if the work converges with another implementation.

This is not full control-loop isolation or complete protocol semantic validation. Decode-side loops, staging-message isolation, room recovery/timeouts, peer policy, and transfer execution are outside this initial patch.

## Validation and next steps

Completed: Python AST parsing, `git diff --check`, and static review of mandatory frame counts, ABORT routing, state publication order, and the exception boundary.

**No CPU functional tests or GPU/PD end-to-end validation have been run for this draft.** Before marking ready, the intended checks are malformed-message followed by valid-message loop survival, no peer/room mutation on rejected metadata, unchanged valid registration/transfer behavior, propagation of application failures, and NIXL PD smoke coverage. The optional Rust-codec path should also be checked once coordinated with #46745.
