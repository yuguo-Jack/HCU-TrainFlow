# [Fix] Preserve deterministic DSpark target-verify parity

[Upstream PR](https://github.com/sgl-project/sglang/pull/35541) · state: closed · merged: False

## Original PR description

## Motivation

Addresses #35150.

With deterministic inference, ordinary Qwen3.8 decode and linear DSpark `TARGET_VERIFY` differed in two numerically relevant places:

- decode rounds the GDN beta value through the activation dtype, while target verify kept it in FP32;
- decode uses `decode_attention_fwd`, while target verify used `extend_attention_fwd_unified`.

Either difference can perturb the persistent GDN state over repeated reject/commit rounds. A routing-only negative control still diverged from the clean packed-decode Base output at token 13 with all 95 drafts rejected, so attention routing alone is insufficient.

## Modifications

- Round target-verify beta through its source activation dtype before accumulating in FP32.
- Represent an unmasked linear verify block as independent decode streams with KV lengths `prefix_len + 1, ..., prefix_len + verify_len`.
- Route only the deterministic CUDA DSpark target-worker path through the existing Triton decode kernel, in eager execution and CUDA Graph replay.
- Preserve the existing path for non-deterministic inference, draft workers, masked/tree or ragged verification, MLA, DCP, sliding-window attention, unified memory, encoder-decoder models, and non-CUDA platforms.

## Validation Status

Validation uses one NVIDIA GeForce RTX 5090 with CUDA 13.0, `RadixArk/Qwen3.8-27B-NVFP4` and `RadixArk/Qwen3.8-27B-DSpark`, TP=1, Triton attention, deterministic inference, FP32 SSM state, gamma=1, and the exact 96-token reproduction from #35150.

- Clean production Base packed-decode oracle: 96 tokens, SHA256 `3ca7a432820875b0dc7c1f2d2e644664e8b864947592a0e876d00400848b6e72`.
- Routing-only negative control: 0/95 drafts accepted and first divergence from the clean Base output at token 13.
- The combined beta and attention changes match a sequential/unpacked decode diagnostic, but fail against the clean production packed-decode Base oracle: 0/95 drafts accepted, first divergence at output token 6 (`Base=279`, `DSpark=781`), DSpark SHA256 `5fc99930b4c8f106a1267003582448c2f9bfe1f17c4db52839924cfc8e830fa1`.
- This PR remains Draft while the remaining packed GDN decode difference is localized; the current commit does not yet fix #35150.
- Focused GQA probe: target-verify attention is bitwise equal to sequential decode (`unequal=0`, `max_abs=0`); eager and CUDA Graph `kv_indptr`, KV indices, and split metadata are identical.
- `py_compile`, Black 26.1.0, Ruff, and `git diff --check` pass.

## Speed Tests and Profiling

No speed claim. The new path is selected only for explicit deterministic inference, where decode parity is the goal. Default non-deterministic serving is unchanged.

## Related Work

- The beta-rounding hunk is also present in #34734 by @qq1060; credit to that PR for identifying this alignment. That broader feature PR adds ragged and checkpoint support but does not route deterministic verification through decode and explicitly leaves greedy equivalence unresolved. If #34734 lands first, the duplicate one-line hunk can be dropped during rebase.
- #34597 uses the same decode-kernel routing principle for DeepSeek-V4 MTP.
- #34821 changes target-verify causal convolution; it does not align Triton full attention.
- #33291 adds an opt-in Decode-Verify-Rollback algorithm; this fix preserves the existing DSpark path.
