# [Perf] dsv4: Drop local references that keep residual-stream tensors alive through the prefill step

[Upstream PR](https://github.com/sgl-project/sglang/pull/45900) · state: closed · merged: True

## Original PR description

- In `DeepseekV4Model`, three local names kept a full residual-stream tensor alive longer than needed during a prefill step:
  - `before_engram` in the Engram block held the pre-Engram residual until the next Engram layer; the image-row `torch.where` now reads `state.residual`, which is the same tensor at that point.
  - `aux` in the DSpark capture block kept the captured residual after its mean was appended; it is now deleted.
  - `_forward_impl` kept a reference to the layer input while `_forward_layers_hc_pre_from_prev` ran; it now hands the tensor over without a caller-frame reference, so the layer loop can free it once the first residual replaces it.
- At large prefill batches each of these is a multi-GiB tensor; holding them raises the in-step peak and, after partial steps, forces an allocator retry that can fail with fragmentation at high `--mem-fraction-static`.

No behavior change: the same values are computed; only tensor lifetimes are shorter.

Verification: the in-step memory peak of DeepSeek-V4.1-Flash DEP4 prefill at large batches drops and consecutive full-size steps no longer need an allocator retry; throughput is unchanged; GSM8K is unchanged.
