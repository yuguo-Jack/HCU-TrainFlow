# [HiCache] Support file-backed L3 offloading for DeepSeek V4 with CP

[Upstream PR](https://github.com/sgl-project/sglang/pull/37808) · state: open · merged: False

## Motivation

Enable file L3 caching for DeepSeek V4 with context parallelism. Replicated CP caches currently use per-rank file keys that can disagree with writer selection, causing L3 misses on non-writer ranks.

## Modifications

- Use a shared `_cpfull_{size}` namespace with one canonical writer for replicated DSV4 CP caches.
- Unify backup writer and file LRU/quota ownership.
- Limit the change to DSV4 + file storage + CP > 1 + PP1; preserve other configurations.
- Add CPU regression coverage and extend the existing DSpark file-L3 replay test with CP v2.

## Accuracy Tests

Validated with `DeepSeek-V4-Flash-0731-FP8` in a two-node P/D deployment:

- Prefill: 8 × H20, PP1 × TP8 × Attention CP8 v2, `interleave`
- Decode: 8 × H20, TP8 × DP8, DSpark
- P/D transfer: Mooncake RDMA
- HiCache: `write_through`, `direct`, `page_first_direct`, 256-token pages, file L3 with `wait_complete`

The tests followed the SGLang registered HiCache replay workflow:

- L2: cold request → evict it from L1 with 28 × 131,072-token requests → replay
- L3: cold request → wait for storage backup → flush L1/L2 → replay
- Input/output: 32,768/64 tokens, `temperature=0`

| Path | Replay cache source | Hit rate | Cold | Replay |
|---|---|---:|---:|---:|
| Host L2 | `device=0, host=32,512, storage=0` | 99.22% | 1,457.33 ms | 702.71 ms |
| File L3 | `device=0, host=0, storage=32,512` | 99.22% | 1,482.40 ms | 744.28 ms |

Additional validation:

- All **17/17 strict checks passed**.
- L2 H2D counter increased by 262,144 tokens (`32,768 × 8 CP ranks`).
- File L3 stored one shared copy: CP0 backed up 32,768 tokens.
- CP0–CP7 each prefetched 32,512 tokens during L3 replay.
- Cold and replay outputs matched exactly for all 64 output tokens on both paths.
- DSpark acceptance remained stable:
  - L2 accept length: `2.370 → 2.370`
  - L3 accept length: `2.286 → 2.370`

GPQA Diamond was also evaluated with temperature `1.0`, reasoning effort `max`, and a 128,000-token output limit:

Score: 178/198 (89.90%)
