# [sgl-router] Separate LoRA block IDs from prompt lookup keys

[Upstream PR](https://github.com/sgl-project/sglang/pull/42818) · state: open · merged: False

## Original PR description

Worker KV-event block IDs may include a worker-local LoRA UUID and cannot be reproduced from an incoming prompt. This separates those external IDs from canonical lookup keys, so base requests and different adapters do not receive each other's prefix credit.

Stacked on #42817. Both existing event modes can supply LoRA events; the router uses tokens, the public adapter name, and cache salt to compute lookup keys.

## Changes

- Translate LoRA stores through a shared `sgl-kv-indexer::lora` implementation. Keep mappings scoped to each worker/DP rank, retain parent digests for continuation events, and count independent external owners of each lookup key on each storage tier.
- Make store replay idempotent. Removing one external block revokes only tiers that lost their last owner, so separate adapter loads and GPU/host copies do not evict each other's prefix credit. Clear local mappings on worker clear/reset/teardown; clear bridge mappings on `AllBlocksCleared`.
- Apply the same translation in the local event index and remote indexer bridge. Existing base-model stores and removals keep their published-key path, including the existing medium and unknown-tier handling.
- Preserve replay, bootstrap sequence gates, snapshot watermarks, and rank filtering. Buffered LoRA stores retain the tokens needed for translation. Peer snapshots retain the external-ID map for subsequent removals and continuations.
- Negotiate LoRA snapshots with `include_lora=true`. New consumers receive version 2 when mappings are present; legacy consumers receive a base-only version-1 view at the same watermark. Mixed-version deployments can continue bootstrapping base caches. Base-only snapshots remain version 1.
- Thread request namespaces through local/remote prefix scoring, pending prefixes, DP-rank selection, and reorg routing. Resolve `base:adapter` to the base model's workers while preserving the adapter in the forwarded body.

## Validation

- Entire Rust router/indexer workspace: 1,531 tests passed, including the existing event replay, concurrency, tiers, bootstrap, proxy, and remote indexer suites.
- Added coverage for opaque IDs, separate load ownership, duplicate stores, tier transitions, delayed parents, salt/bigram atoms, snapshot round trips and removal after restore, bootstrap token retention, and actual HTTP mixed-version snapshot negotiation.
- The LoRA proxy test feeds opaque worker IDs through event ingestion and verifies adapter/base worker selection.
- All 10 engine-derived lookup parity cases passed; regenerated fixtures are unchanged.
- Clippy with warnings denied, rustfmt, Black/isort, and diff whitespace checks passed.

Serving E2E and CUDA HiCache transitions remain unverified on this revision: the GPU devbox was evicted for low ephemeral storage. The remote indexer retains its existing soft-state/reconnect limitations. Reloading different weights under the same public adapter name still requires versioned names to avoid stale lookup credit.
