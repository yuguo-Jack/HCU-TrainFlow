# [Do not merge - need to clean] GLM-5.3-Flash (glm5_next) LoRA serving + glm53next port rebased

[Upstream PR](https://github.com/sgl-project/sglang/pull/37753) · state: open · merged: False

## Original PR description

## Summary

LoRA serving for **GLM-5.3-Flash** (`glm5_next`) on `sglang-miles`, on top of the `sglang-miles-glm53next` port rebased onto current `sglang-miles`.

- **Port**: the 11 commits of `sglang-miles-glm53next` (GLM-5.3-Flash model / config / kpool memory pools / DSA kpool indexer / mHC communicators / indexer-topk capture, from sgl-project/sglang#36507) rebased onto `sglang-miles` (`c16b821`) with no conflicts, so the model now runs with the streamed LoRA weight updates used by current miles.
- **LoRA for `glm5_next`** (`python/sglang/srt/models/glm5_next.py`):
  - `Glm5NextForConditionalGeneration.supported_lora_modules` and a per-layer `get_hidden_dim`. GLM-5.3 mixes KDA linear attention (34 layers) and DSA sparse MLA (11 layers), so `o_proj` has different input widths per layer type, `qkv_proj` exists only on KDA layers, the MLP is dense for the first 3 layers and MoE (shared + routed experts) afterwards; the config-driven default assumed one attention shape per model.
  - `Glm5NextLinearAttention` keeps the unfused `qkv_proj` / gate layout when LoRA serving is enabled: the fused `MergedColumnParallelRepeatedLinear` / `ColumnParallelBatchedLinear` have no LoRA wrapper. (The FP8 checkpoint already runs unfused.)
- **New LoRA target modules** (`python/sglang/srt/lora/utils.py`, `python/sglang/srt/utils/common.py`): the KDA gate projections `b_proj`, `f_a_proj`, `f_b_proj`, `g_a_proj`, `g_b_proj` (`KDA_GATE_LORA_NAMES`) are registered as known targets, in the replicated / attention-TP tables, with a config-driven default geometry from `linear_attn_config`, and accepted by `--lora-target-modules`.
- Unit test: `test/registered/unit/lora/test_glm5_next_lora_hidden_dim_unit.py` (CPU): per-layer geometry for KDA vs DSA vs dense/MoE layers, and the KDA-gate registration.

### What LoRA newly covers vs. before on this model

| Module | Before | Now |
|---|---|---|
| KDA `q/k/v_proj` (`qkv_proj`), `o_proj` | wrong geometry (global attention shape) or unwrappable (fused layout) | per-layer geometry, unfused layout under LoRA |
| KDA `b_proj`, `f_a_proj`, `f_b_proj`, `g_a_proj`, `g_b_proj` | not known / not selectable | supported |
| DSA `fused_qkv_a_proj_with_mqa`, `q_b_proj`, `kv_b_proj`, `o_proj` | supported via the generic MLA path | unchanged; `o_proj` now sized per layer |
| dense MLP / shared expert / routed experts | supported | unchanged |
| KDA `conv1d`, `A_log`, `dt_bias`, `o_norm`; kpool `index_kpool_compress_*`; mHC params | not linears | not adapted |
| DSA indexer `wq_b`/`wk`/`weights_proj` | supported with `SGLANG_DISABLE_DSA_INDEXER_FUSION=1` | unchanged (excluded by the miles recipe: no gradient on the fused training path) |

## Validation (H200)

4-layer public slice `CharyZeng/GLM-5.3-Flash-4layer` (bf16, TP2, `--lora-backend triton --moe-runner-backend triton --disable-shared-experts-fusion`), synthetic rank-16 adapters, server with LoRA vs the same server serving a merged-weights checkpoint (identical kernel config); mean |Δ logprob| over 211 prompt tokens:

| Adapter group | LoRA vs merged reference | no adapter vs adapter (control) |
|---|---|---|
| KDA q/k/v/o + gates | 0.064 | 0.318 |
| DSA MLA q_a/kv_a/q_b/kv_b/o | 0.056 | 0.464 |
| dense + shared MLP | 0.046 | 0.388 |
| routed experts (virtual-experts path) | 0.011 | 0.187 |

A zero-`lora_B` adapter reproduces the base logprobs bit-exactly. The residuals are at the slice's kernel-variant noise floor (the same slice differs by 0.013 mean between `--moe-runner-backend` choices and by 0.036 between fused/unfused KDA).

Full FP8 `zai-org/GLM-5.3-Flash` (TP8, EP8, LoRA enabled, zero-B and random adapters loaded), gsm8k 5-shot, 200 questions: base **92.0 %**, zero-B adapter **93.0 %**, random adapter **93.5 %**; zero-B vs base logprobs identical.

Cross-framework (Megatron-Bridge glm5_next with the same adapter, radixark/Megatron-Bridge PR): 4-layer slice TP2+SP base 0.070 / LoRA 0.061 mean |Δ logprob|; in the miles RL loop with routing replay, full model 3×8 H200: `train/train_rollout_logprob_abs_diff` 0.0121, KL 7.2e-4, reward 0.92 on gsm8k.
