# [Test] [NPU] speculative_inference: Add NEXTN rejection sampling e2e test

[Upstream PR](https://github.com/sgl-project/sglang/pull/41503) · state: open · merged: False

## Original PR description

## Motivation

Add a dedicated Ascend NPU e2e test that validates speculative decoding with classic rejection sampling — `--speculative-use-rejection-sampling` — is consumed on the NPU backend with the NEXTN algorithm. NEXTN shares the target's full vocabulary (unlike Qwen EAGLE3's reduced hot vocab), so it is the compatible path for classic rejection sampling. Before this PR there was no CI coverage proving that rejection sampling actually engages on Ascend (NPU). This PR closes that gap with a self-contained GSM8K e2e case so regressions in the rejection-sampling path on NPU are caught automatically.

## Modifications

- **`test/registered/npu/basic_function/speculative_inference/test_npu_eagle_rejection_sampling.py`** — add a new NPU e2e test class `TestNpuNextnRejectionSampling` that:
  - Launches Qwen3.5-9B on Ascend with `--attention-backend ascend`, `--disable-radix-cache`, `--speculative-algorithm NEXTN`, `--speculative-num-steps 3`, `--speculative-eagle-topk 1`, `--speculative-num-draft-tokens 4`, `--speculative-use-rejection-sampling`, `--tp-size 1`, `--mem-fraction-static 0.7`, `--disable-cuda-graph`, `--dtype bfloat16`, and `--mamba-ssm-dtype bfloat16`.
  - Sets `SGLANG_ENABLE_OVERLAP_PLAN_STREAM=1` to exercise the overlap plan stream on the hybrid linear-attention (GDN) model.
  - Runs GSM8K via the Ascend mixin and asserts both the accuracy target (`accuracy=0.81`) and a positive speculative acceptance length, proving the rejection-sampling path is exercised end-to-end without error.
  - Registers the suite via `register_npu_ci` (`est_time=400`, `suite="base-b-test-1-npu-a3"`, plus `nightly="nightly-1-npu-a3"`).
  - **Also fixed within this branch**: set `--mamba-ssm-dtype bfloat16`. The mamba intermediate-state mover on Ascend (`move_cache_dynamic_last_kernel_h_block`) defaults the SSM state to `float32`; on a single card that overflows the NPU unified buffer during Triton `/biShengIR` compilation (`ub overflow, requires 2097152 bits while 1572864 bits available`). Lowering the SSM state dtype to `bfloat16` halves the kernel's UB footprint so the kernel compiles on Ascend.

## Accuracy Tests

This test validates end-to-end behavior of NEXTN rejection sampling on NPU via GSM8K. It asserts the GSM8K accuracy target (`0.81`, `num_questions=1319`) is met and a positive speculative acceptance length is observed, confirming the `--speculative-use-rejection-sampling` path is consumed without error. The test has been run and validated on the NPU (Ascend) environment.

## Speed Tests and Profiling

No throughput regression is expected from this PR as-is. This PR only adds a CI e2e test and fixes the SSM state dtype that prevented the Ascend mamba mover kernel from compiling; it does not change any runtime kernel, collective, or serving path. Speed/throughput coverage for NEXTN on NPU is tracked separately by existing NPU performance tests (`qwen3_6_35b_a3b`, etc.).
