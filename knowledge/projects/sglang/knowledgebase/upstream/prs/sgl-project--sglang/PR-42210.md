# [WIP][sglang-miles] Add GPU delta decode and in-place weight updates

[Upstream PR](https://github.com/sgl-project/sglang/pull/42210) · state: open · merged: False

## Original PR description

## Motivation

@humansand

Apply canonical Miles updates directly to live SGLang weights, and load HF-base delta publications on fresh or restarted engines. Paired [Miles #3894](https://github.com/radixark/miles/pull/3894); [tracker #3734](https://github.com/radixark/miles/issues/3734).

## Modifications

- **Lifecycle/API:** four Miles-facing routes: `/get_gpu_delta_info`, `/update_weights_from_gpu_delta`, `/get_gpu_delta_status` and `/clear_gpu_delta_state`. One update carries the negotiated participants, session ID and publication descriptor. Tokenizer initialization and worker-count admission run once at the public request boundary. SGLang prepares while serving, then owns pause/fence/apply, all-rank acknowledgement and resume. APPLIED IPC carries identity/provenance/state/pause boundaries and the applied/target-version verdict; full metrics remain in RESUMED and status. Internal preparation failure is released; an uncertain XOR after apply dispatch is never replayed.
- **Recovery/deployment:** rolling and fresh-engine HF-base updates share the explicit descriptor contract; there is no manifest-only loader. Resources remain cached by default (`release_state=False`). `release_state=True` performs the existing all-rank close/shared-cache-release sequence after successful resume in the same request, preserving phase receipts on success; explicit clear remains available. Cleanup does not change weights, committed version or pause and is excluded from activation phase timings.
- **Pause/cache controls:** update accepts `flush_cache=True` and `abort_all_requests=False`, preserves a caller-owned pause, and records the model label before opening generation admission. A retained or failed pause is not reported as a completed resume interval.
- **Preparation:** validate manifest/byte contracts, read/hash into shared tmpfs and decode/copy into private rank HOST_NUMA arenas while serving. `GPU_DELTA_HOST_CACHE_DIR` remains a deployment control and must name host-shared tmpfs (default `/dev/shm/sglang-gpu-delta-<uid>`). Build byte descriptors and prepare three fixed access-family kernels before PREPARED; dimensions/activity do not specialize code. Packed, word-affine and byte-affine layouts use generic addressing.
- **Fixed pipeline:** one hardware-DE stream, one Triton apply stream and exactly two decoded output slots. Decode-ready and apply-finished events order each slot's reuse; sticky status guards subsequent mutation. Output storage allocates after the pause/fence, while prepared descriptors and retained capacity avoid rebuilding the plan. The streams drain before release on error/cancellation. This is a fixed design, with no pipeline-depth selector, encoded-HBM ring, software decompression fallback or runtime autotuning. [Layout](https://github.com/sgl-project/sglang/blob/23ae75c70a97c29cb5fcf919bb8c4d3c7c5057c2/python/sglang/srt/weight_sync/gpu_delta/layout.py), [codec](https://github.com/sgl-project/sglang/blob/23ae75c70a97c29cb5fcf919bb8c4d3c7c5057c2/python/sglang/srt/weight_sync/gpu_delta/codec.py).
- **Device ownership:** only hardware-DE-facing tensors use feature-owned `cuMemAlloc`; aliases retain the allocation owner and producer/consumer streams drain before free. CUDA context restoration and uncertain-free diagnostics remain explicit. Model parameters are updated in place, with no concurrent unrelated updater.
- **Integrity:** publications carry codec/frame geometry, plan/stream/version bindings, matrix XOR or raw overwrite and omitted zero masks. Each update controls payload SHA verification with `validate_payload_hash=True` by default; `False` skips payload passes only. This request field is SGLang's sole hash-policy input. Manifest/file/native checks remain. Ordinary updates are consecutive; a fresh engine can accept HF base0→current.
- **Tracing:** [`SGLANG_ENABLE_NVTX_OPERATIONS=1`](https://github.com/sgl-project/sglang/blob/23ae75c70a97c29cb5fcf919bb8c4d3c7c5057c2/python/sglang/srt/weight_sync/gpu_delta/profiling.py) enables preparation, scheduler, worker and enqueue ranges. Disabled decorators return the callable unchanged; no added device sync. The benchmark owns capture; pause ranges close only on successful unpause.
- **Upstream interfaces:** tokenizer controls use the total replica × attention-DP rank count. DeepSeek canonical aliases and shared-expert mapping are resolved at admission. MXFP4 updates the shuffled inference scale images; retained loader-only checkpoint scales are outside the exclusive GPU-delta consumer path. TRTLLM/MegaMoE identity checks track the current layer-owned calibration buffers.
- **Versions:** each rollout/eval pool owns a consecutive transport sequence. The actor's model version is a separate label attached to generated samples; resume records it before generation admission. Repeated, jumped or rewound model labels do not change transport sequencing. Checkpoint reuse binds both rollout ID and model version.
- **W&B metrics:** [`perf/gpu_delta/*`](https://github.com/radixark/miles/blob/ca1a0df808747a729f2c8100a89b6cf49f5a5908/miles/backends/training_utils/weight_update/protocols/gpu_delta/metrics.py) reports completed updates, including a final update without a later train call; eval adds `eval/`. Rank timings use min/p50/max only with complete coverage. Shared encoded caches count once per engine/host; private DE arenas count per rank. Initial sync is logged without inventing a rollout step. Reporting errors cannot retry an applied update. No extra collective, polling or device synchronization is added for reporting. Engine prepare/apply/resume/activation metrics now use server tokenizer monotonic spans, excluding optional clear; outer coordinator activation remains the Miles await. Rank preparation and scheduler-pause clocks are unchanged.

| Publication | Inner GPU compression / hardware decode | Outer compression | Receiver preparation |
|---|---|---|---|
| `snappy-zstd` | Snappy | GPU Zstd, 1 MiB chunks | CPU Zstd into private rank DE arena |
| `lz4-zstd` | LZ4 | GPU Zstd, 1 MiB chunks | CPU Zstd into private rank DE arena |
| `lz4` | LZ4 | None | Copy compact inner arena into private rank DE arena |

### Admitted FlashInfer layouts

[Admission-time layout helpers](https://github.com/sgl-project/sglang/blob/23ae75c70a97c29cb5fcf919bb8c4d3c7c5057c2/python/sglang/srt/weight_sync/gpu_delta/flashinfer.py) factor existing packed buffers into segmented affine byte views. Segments preserve canonical order and exclude padding; aliases receive one XOR, independent consumer images each receive it. Updates perform no weight/mask permutation or requantization.

| Native format | TRTLLM / routed | CuTe DSL | MegaMoE |
|---|---|---|---|
| BF16 | Yes | — | — |
| FP8, 128×128 blocks, UE8M0 scales | Yes | — | — |
| MXFP8 | Yes | — | Yes |
| MXFP4 with MXFP8 activation | Yes | — | Yes |
| NVFP4 | W4A4 | W4A4 / W4A16 | W4A4 |

Only these combinations are admitted. This is native byte-layout support, not new inference kernels or full-serving qualification of every combination. Block128 UE8M0 accepts exact compact U8 scales and expands them losslessly into the consumer’s FP32 API image; arbitrary FP32 scales and load-time quantization/conversion fallbacks are rejected. CuTe wrappers/derived buffers must already exist. Routed experts require fixed topology and expert TP=1; EPLB, redundant experts and elastic joiners are unsupported. Full-serving evidence here remains **GLM-5.2 NVFP4 W4A16**.
