# [Fix] cuda_graph: Recapture target prefill graphs after disk weight updates

[Upstream PR](https://github.com/sgl-project/sglang/pull/46431) · state: open · merged: False

## Original PR description

## Motivation

`update_weights_from_disk(recapture_cuda_graph=True)` only recaptures decode graphs. When loading replaces parameter storage, target prefill graphs still replay the old addresses: they can serve stale weights or access freed memory even though the update succeeds.

## Modifications

Route weight updates through a callback that cleans up and recaptures an existing target prefill graph before recapturing decode, matching startup order. Use a fresh shared pool so prefill-only recapture does not revive a drained pool and hit `CachingHostAllocator`'s `use_count > 0` assertion. Keep the existing speculative draft placement guard; spec-worker-owned draft graph recapture is outside this change. The broader backend cleanup work in #44296 is separate.

## Accuracy Tests

Reproduced on H100, PyTorch 2.14.1+cu130, baseline `a99c7d050f`, using Qwen3-0.6B and real HTTP generation/weight-update requests. This is a **controlled parameter-storage reallocation repro**, not a claim that the ordinary Qwen loader reallocates weights:

- Created checkpoint B by negating checkpoint A's MLP down-projection weights. A probe wrapper clones parameter storage before reload and retains the previous storage, making stale reads deterministic.
- Before the fix, with breakable prefill graphs and decode graphs disabled, all 6 prompts retained A's first token and logprob after updating to B. None matched a fresh eager B server. A second update released the original storage and hit an illegal memory access in prefill.
- After the fix, tested two consecutive updates with decode graphs disabled and with full decode graphs enabled: all 24 post-update requests matched the fresh eager B server's complete 8-token outputs and token logprobs exactly (maximum difference 0), with no failed requests. Server logs confirm prefill graph replay.
- Existing draft recapture tests: 3 passed. Ruff lint/format and `git diff --check` passed. No new test files.

GPT-OSS-20B/Marlin was also attempted, but its native reload fails earlier with `default_weight_loader() got an unexpected keyword argument 'weight_name'`; that is not counted as a repro of this issue.

<summary>Controlled reproduction setup</summary>

Create B from a local Qwen3-0.6B checkpoint, retaining its config/tokenizer files:

```python
from safetensors.torch import load_file, save_file

weights = load_file(f"{checkpoint_a}/model.safetensors")
for name in weights:
    if name.endswith("mlp.down_proj.weight"):
        weights[name] = -weights[name]
save_file(weights, f"{checkpoint_b}/model.safetensors")
```

Install this probe in a Python launcher before starting the server (also at module scope so spawned workers install it):

```python
from sglang.srt.models.qwen3 import Qwen3ForCausalLM

original_load = Qwen3ForCausalLM.load_weights

def load(self, weights):
    if getattr(self, "_probe_loaded", False):
        self._probe_old_weights = [p.data for p in self.parameters()]
        for p in self.parameters():
            p.data = p.data.clone()
    result = original_load(self, weights)
    self._probe_loaded = True
    return result

Qwen3ForCausalLM.load_weights = load
```

Launch A with TP1, `--attention-backend triton --context-length 1024 --max-total-tokens 4096 --chunked-prefill-size 128 --cuda-graph-bs-prefill 4 8 16 32 64 128 --cuda-graph-backend-prefill breakable --cuda-graph-backend-decode disabled --disable-overlap-schedule`. For the decode-enabled run, replace the disabled flag with `--cuda-graph-bs-decode 1 2`.

Generate `The capital of France is` with temperature 0, `max_new_tokens=8`, `ignore_eos=true`, and `return_logprob=true`. POST `/update_weights_from_disk` with `model_path=checkpoint_b`, `load_format="auto"`, and `recapture_cuda_graph=true`, then generate again after flushing the cache. Before the fix the first token/logprob remains `12095 / -0.4147300720214844`; the corrected result and fresh eager B reference are `5015 / -3.8977460861206055`. Repeat the update to exercise graph cleanup and recapture again.
