# [Fix] scheduler: Preserve async readback grad mode and failures

[Upstream PR](https://github.com/sgl-project/sglang/pull/45058) · state: closed · merged: False

## Original PR description

## Motivation

Async readback callbacks run on a new thread, which starts with gradients enabled instead of the scheduler's no-grad/inference-mode policy. A callback raising `SystemExit` also currently signals successful completion before killing the worker, leaving later copies unresolved.

## Modifications

Apply `DynamicGradMode` around each copy and record `BaseException` failures through the existing `HostCopyDone` error path, so consumers reject invalid results and subsequent copies can finish. Add two regression cases to the existing worker GPU fixture.

## Accuracy Tests

- Both new cases fail against main at `0dc6de2e74e999464b5e63a9a059db2e4e0518a3` before the runtime fix.
- `python -m pytest test/registered/unit/managers/test_async_d2h_copy_worker.py -q`: **10 passed, 6 subtests passed** on a CUDA GPU.
- Same file with `SGLANG_ENABLE_TORCH_INFERENCE_MODE=true`: **10 passed, 6 subtests passed**.
- These cover exact readback values, producer-stream ordering, scheduler routing, error propagation, continued processing after failure, and both grad policies.
- No model-serving accuracy evaluation was run.

## Speed Tests and Profiling

No serving benchmark was run; this fixes worker context and error handling. The existing GPU readback tests passed under both grad policies.
