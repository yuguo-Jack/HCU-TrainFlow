# [Perf] moe: Run the Marlin GPT-OSS SwiGLU through the fused Triton kernel

[Upstream PR](https://github.com/sgl-project/sglang/pull/46134) · state: closed · merged: True

## Original PR description

## Summary
The Marlin MoE GPT-OSS-style activation, `gate * sigmoid(alpha * gate) * (up + 1)` with gate clamped above and up clamped both ways, now runs through the fused Triton `swiglu_oai_split` (fp32 math), writing into the existing intermediate buffer, instead of the bf16 elementwise torch version.

## Changes to existing code
- `fused_marlin_moe`: same formula and clamps; results change only by rounding, now closer to an fp32 reference. This affects every model on the Marlin path with `gemm1_alpha` set (GPT-OSS, MiniMax-M3.1 on Hopper).
- `swiglu_oai_split` takes an optional `out` buffer.

## Verification
- test_activation: `test_swiglu_oai_split_is_the_marlin_gpt_oss_activation` checks the formula, that the error against fp32 is no larger than the bf16 version's, and the in-place write.
- test_marlin_moe: `test_fused_marlin_moe_gpt_oss_activation` runs `fused_marlin_moe` with `gemm1_alpha` and `clamp_limit` against a torch MoE reference using the same formula (fp16 and bf16, m = 1 and 123).
- TODO: GPT-OSS accuracy on the Marlin path.

Cut byte-for-byte from #45925 (MiniMax-M3.1-Flash support) at 10e655aa98.
