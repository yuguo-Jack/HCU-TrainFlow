## Motivation

Add a NIXL object backend backed by DOCA MEMOS, enabling HiCache to offload host KV pages to NVMe memory via the DOCA MEMOS plugin. Zero-copy requires hugetlb-backed host buffers and page-first layouts; otherwise the path falls back to aligned bounce buffers.

## Modifications

- **`storage/nixl/hicache_nixl.py`**: Add DOCA_MEMOS support — hugetlb-backed buffer checks via `tensor_mem_backend()`, per-component zero-copy registration for split mappings (asymmetric K/V, mamba temporal/conv), 4 KiB-padded bounce slots, asymmetric flat-page get/set helpers, and chunked v2 transfers over `STORAGE_BATCH_SIZE`. Unify key formatting through `_format_key()` (sha256-truncated for DOCA_MEMOS, file path for FILE, raw key otherwise).
- **`storage/nixl/nixl_utils.py`**: Register `DOCA_MEMOS` in `OBJ_PLUGINS`; enforce `SGLANG_HUGEPAGE_MODE=required` + `SGLANG_HUGEPAGE_SIZE=2MB` at backend selection; default `query_mem_mode=actual` for existence checks; scope the bucket requirement to `OBJ` only.
- **`storage/mmap/mmap_allocator.py`**: Track per-tensor memory backend (`MEM_BACKEND_MMAP`/`HUGEPAGE`) via `tensor_mem_backend()`; expose `HUGEPAGE_BYTES_2MB`/`HUGEPAGE_BYTES_1GB`.
- **`pool_host/{base,mamba,mha}.py`**: Fix `is_stride_page_aligned()` strides to include `page_size` (mamba) and add alignment checks for `MHATokenToKOnlyPoolHost`; `AsymmetricMHATokenToKVPoolHost.get_hybrid_pool_buffer()` returns `[k_buffer, v_buffer]`.
- **`storage/nixl/nixl.config.toml.sample`**: Document DOCA_MEMOS plugin section and hugepage/layout requirements.
- **Tests**: Add `TestDocaMemosNixl` (registration, conv-only mamba round-trip, asymmetric K/V round-trip, initparams, hugepage-policy enforcement), a large-pool chunking test, and `test_alloc_mmap_tracks_mem_backend`.

Loading `libc` via `ctypes.CDLL` on every call is inefficient as it performs a `dlopen` each time. It is better to cache the library object at the module level. Additionally, explicitly setting `argtypes` and `restype` for both `mmap` and `munmap` ensures type safety and avoids potential issues with pointer truncation or incorrect argument passing on different architectures.

![medium](https://www.gstatic.com/codereviewagent/medium-priority.svg)

The `release` method should be robust against exceptions in `cuda_unregister`. If `cuda_unregister` raises an exception (for example, if the CUDA runtime is already partially torn down during interpreter shutdown), the `munmap` call will be skipped, leading to a memory leak. Wrapping the unregistration in a `try...except` block ensures that the mapping is always released.

```suggestion
    def release(self) -> None:
        """Unregister from CUDA and unmap."""
        try:
            self.cuda_unregister()
        except Exception:
            logger.debug("Failed to unregister hugepage buffer from CUDA during release", exc_info=True)
        self.munmap()
```
