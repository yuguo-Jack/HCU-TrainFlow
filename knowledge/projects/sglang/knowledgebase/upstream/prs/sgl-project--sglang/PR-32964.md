# [AMD] Add gfx1201 fallbacks for failing MoE kernels

[Upstream PR](https://github.com/sgl-project/sglang/pull/32964) · state: open · merged: False

## Original PR description

## Motivation

Several `sgl_kernel` operations reproducibly segfault on AMD gfx1201
(Radeon AI PRO R9700) during Qwen3.5 MoE inference.

The affected paths are:

- `SiluAndMul.forward_cuda`
- `topk_softmax`
- `moe_align_block_size`
- direct `silu_and_mul` use in the Triton fused-MoE runner

## Modifications

Added narrowly scoped HIP + gfx1201 fallbacks for the affected operations.

The fallbacks preserve existing behavior while avoiding the failing native
`sgl_kernel` paths on gfx1201.

CUDA behavior and ROCm behavior on non-gfx1201 architectures are unchanged.

## Accuracy Tests

Validated the gfx1201 fallbacks against the existing PyTorch/Triton behavior.

For `topk_softmax`, representative Qwen3.5 MoE shapes with 256 experts and
top-8 routing were checked against `torch.softmax` plus `torch.topk`.

The fallback preserves:

- FP32 softmax
- optional softcapping
- optional correction bias
- renormalization
- descending routing probabilities
- lower expert ID on ties

End-to-end validation:

- 4× AMD Radeon AI PRO R9700
- gfx1201
- ROCm 7.2.2
- PyTorch 2.9.1
- SGLang v0.5.16
- Qwen3.5-122B-A10B-AWQ-4bit
- tensor parallel size 4
- FP8 KV cache
- 262144 context length
- concurrent requests

TP4 inference completes successfully with the patch.

A separate RCCL LL-protocol hang requires `NCCL_PROTO=Simple` and is not
addressed by this PR.

## Speed Tests and Profiling

Observed end-to-end results on 4× Radeon AI PRO R9700:

- Single-stream decode: approximately 6.1 output tokens/second
- Concurrent aggregate output: approximately 33 output tokens/second
- Peak concurrent output: approximately 60 output tokens/second
- Prefill: approximately 2580 input tokens/second

These results are provided as functional validation on gfx1201 rather than as
a performance comparison against the native kernels, since the native kernels
segfault on this architecture.

- vivienfanghuagood · comment · 2026-10-29T12:17:04Z · [source](https://github.com/sgl-project/sglang/pull/32964#issuecomment-6496429065)

I checked whether these fallbacks are still needed once #43679 lands. #43679 fixes the host/device `WARP_SIZE` mismatch in the AOT kernels, which looks like the root cause of the gfx1201 crashes listed here.

On gfx1201 (Radeon AI PRO R9700) with current `main` + #43679, without this PR, the AOT kernel unit tests for the three native ops you fall back from all pass:

- `test_activation.py` (incl. `silu_and_mul`): 945 passed
- `test_moe_topk_softmax.py`: 744 passed (on `main` with only the allowlist widened, this file aborts the process)
- `test_moe_align.py`: 144 passed, 72 skipped

End to end, with #47254 for the default attention backend, OLMoE-1B-7B (MoE, Triton fused-MoE runner) serves with default flags and decode CUDA graphs. gsm8k (sgl-eval, 50 questions) scored 62–66% across runs.

I haven't run Qwen3.5-122B-A10B-AWQ at TP4. So if anything in this PR's path still fails on top of #43679, it would be good to know which op. Otherwise #43679 may make this PR unnecessary.
