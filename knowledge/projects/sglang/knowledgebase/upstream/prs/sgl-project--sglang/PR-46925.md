# [Perf] dsv41: Reorder the Engram all-to-all output with a Triton kernel

[Upstream PR](https://github.com/sgl-project/sglang/pull/46925) · state: closed · merged: True

## Original PR description

- Add `engram_rows_to_token_major` (`sglang.kernels.ops.embeddings`), a Triton copy that reorders the Engram all-to-all output from [source rank, token, columns] to [token, columns]. It replaces `transpose(0, 1).reshape(...)`, whose strided copy ran at about 1.9 TB/s.
- The Engram `all_to_all` lookup uses it; the output is bitwise the same.
- Docs: the `auto` measurements are updated; GB300 at DP 2 is no longer an exception.
- Test: checked once on GB300 against transpose + reshape at DP 2, 4, 8 and 0-4,096 tokens per rank (bitwise equal); the kernel is also covered end to end by the DP Engram lookup.

No behavior change; only the reorder after the all-to-all is faster.

## Measurements

Reorder at 32K tokens per rank: GB300 441 -> 128 us, B300 452 -> 124 us, H200 483 -> 197 us.

The `EngramEmbedding` DP lookup per layer on GB300, host `per_rank` table, 32K tokens per rank, outputs bitwise equal to `all_reduce`:

| DP | `all_reduce` (us) | `reduce_scatter` (us) | `auto` before (us) | `auto` after (us) |
|---:|---:|---:|---:|---:|
| 2 | 3,490 | 2,590 | 2,843 | 2,426 |
| 4 | 5,872 | 3,657 | 2,765 | 2,436 |

Over the 144 microbenchmark shapes of #46917 (GB300, B300, H200; DP 2-8; 512 to 65,536 tokens per rank, uniform or skewed), `all_to_all` is now the fastest choice in 134 (was 121), including all 96 from 8,192 tokens per rank up; in the other 10, all at 2,048 tokens per rank or fewer, another choice is ahead by at most 85 us.
