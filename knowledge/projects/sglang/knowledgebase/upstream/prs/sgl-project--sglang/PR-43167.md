# [DSv4.1] Size the late-layer tail request indices on the host

[Upstream PR](https://github.com/sgl-project/sglang/pull/43167) · state: closed · merged: False

## Original PR description

## Motivation

```bash
python3 -m pytest test/registered/attention/unittests/dsv4/test_deepseek_v4.py -k TestLateLayerTailRequestIndices
```

With `--enable-decoder-swa-bounded-replay`, every extend forward runs `_build_late_layer_tail_metadata`, which calls `torch.repeat_interleave(req_pool_indices, tail_lens)` with device repeat counts and no `output_size`. PyTorch then copies the total to the host to size the output: one device synchronization per extend forward, although the tail lengths are already on the host (`tail_lens_cpu`).

## Modifications

Adds `_repeat_per_request(values, counts, counts_cpu)`, which passes `output_size=sum(counts_cpu)`, and uses it for the tail request indices.

## Accuracy Tests

The output is the same by construction. `TestLateLayerTailRequestIndices` (new) runs the helper under `torch.cuda.set_sync_debug_mode("error")` and checks its values. `test_deepseek_v4.py`: 26 passed (45 subtests) on GB300.

## Speed Tests and Profiling

Not benchmarked; it removes one host synchronization per extend forward on the decoder-SWA bounded replay path.
