## Motivation

First code PR of RFC #43949 (part 2 of 4): the monokernel plugin, which runs most of a decoder layer, including its TP all-reduce, as one or two persistent launches. No model is registered here, so `--enable-monokernel` refuses to start; the DeepSeek-V4.1 spec comes in the next PR.

## Modifications

- `--enable-monokernel` (default off) and the hook calls SGLang makes: `handle_monokernel` in the config pipeline (refuses with every reason at once), `load_tensor` / `loaded`, `attach` in `precompile_kernels_after_loading`, `route` once a forward and `kernel` at each span start (7 srt files, +45 lines).
- `kernels/ops/mono`: `MonoSpec` (devices, features, requirements, spans, numerics, disable reasons), routing by step width with plans compared across ranks, check mode (`SGLANG_TEST_MONO_CHECK`).
- `common_hip`: shared device runtime (mailboxes, peer memory, plans) and in-kernel fail-stop: every wait has a deadline; on timeout the launch flags its peers and stops with a GPU fault. `SGLANG_TEST_MONO_FAULT_INJECT=rank:site[:after]` injects a stalled wait.

## Accuracy Tests

No model output changes: no spec is registered and the switch is off by default. CPU unit tests under `test/registered/mono` (40 pass).

## Speed Tests and Profiling

No change with the switch off.
