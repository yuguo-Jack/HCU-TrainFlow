# [Test] [Ascend] npu: Add GLM-5.2 2P2D gpqa cases and unify evalscope retry loop

[Upstream PR](https://github.com/sgl-project/sglang/pull/47611) · state: closed · merged: True

## Original PR description

## Motivation

Port the two new GLM-5.2-w8a8 4-node 2P2D accuracy test cases from Ascend/sglang#1296 into the community repo, and clean up the duplicated evalscope retry logic shared by the NPU accuracy test bases.

## Modifications

- Add `test/registered/npu/accuracy/glm5_2/test_npu_glm_5_2_w8a8_2p2d_32p_dcp_gpqa.py` (decode side: tp32/dp8/dcp4) and `test/registered/npu/accuracy/glm5_2/test_npu_glm_5_2_w8a8_2p2d_32p_pcp_gpqa.py` (prefill side: attn-cp8). Both extend `TestNpuAccuracyMultiNodePdSepTestCaseBase` with `max_retries = 1` and are registered with `disabled="accuracy testcase"` for now.
- Refactor the ~100%-duplicated evalscope retry loop previously copy-pasted in all three NPU accuracy base classes (`test_npu_accuracy_utils.py`) into one shared `run_evalscope_with_retry` helper (net -41 lines).
- PdMix/PdSep base classes now honor the per-case `max_retries` class attribute (previously only the single-node base consumed it, so the override in PdSep subclasses like kimi_k3 gpqa was dead code).
- Add structured `[retry-budget]` logging that records the retry budget source and the actual attempts consumed per case, easing nightly triage.

## Accuracy Tests

Validated on the nightly NPU multi-node POC pipeline (run https://github.com/sgl-project/sglang/actions/runs/41107271816):

- `pcp_gpqa` case passed: accuracy **0.909** vs baseline 0.912, finished after 1/1 attempt (`[retry-budget] ... finished after 1/1 attempt(s), best accuracy=0.909`).
- `dcp_gpqa` case cannot start on current main: upstream hard-rejects the DSA + DCP + PD-disaggregation combination (`ValueError: DSA DCP does not support PD disaggregation.` in `deepseek_v2.py`). Both cases are registered `disabled`, so they do not run in suites until enabled.
