# [Feat] bench: support --tokenize-prompt for generated-shared-prefix

[Upstream PR](https://github.com/sgl-project/sglang/pull/40900) · state: closed · merged: True

## Original PR description

## Summary

- Support the existing `--tokenize-prompt` option for the `generated-shared-prefix` dataset, sending raw random token IDs so the server skips tokenization before prefill and shared prefixes remain exact at the token level.
- Require `--backend sglang` and single-turn requests (`--gsp-num-turns=1`, the default); reject multi-turn token-ID prompts before benchmark setup.
- Keep token-ID cache entries separate from text-mode entries, preserve exact token-length statistics, and share token generation through `gen_prompt_ids()`.
- Add regression tests for token-ID lengths/statistics and multi-turn rejection.

This ports the change from HYGON-AI/sglang-das#315.

## Benchmarking note

When measuring the speedup, send requests to `/generate` or `/v1/completions` rather than a chat endpoint. Chat template processing and other chat-specific overhead can obscure the tokenization speedup. For this benchmark's `--tokenize-prompt` mode, use `--backend sglang`, which sends requests to `/generate`.

## Validation

Four focused isolation checks passed: exact token-ID lengths/statistics, multi-turn rejection, shared-prefix/cache behavior, and text helper compatibility. Syntax compilation and `git diff --check` also passed. The full CPU integration suite was not run locally because its dependencies are unavailable; CI still needs to confirm it.

Thanks for the PR — sending raw ids for GSP is useful (it also makes the shared prefix exact at the token level, which the decode→re-encode text path doesn't guarantee). A few issues before merge:

**main already has this switch.** `--tokenize-prompt` (`serving.py`, "Use integer ids instead of string for inputs") is the existing global flag for this; `random-ids` honors it via `return_text=not tokenize_prompt`, and `async_request_sglang_generate` already sends `input_ids` for non-str prompts. GSP currently just asserts it off (`generated_shared_prefix.py:59`). Suggest dropping `--gsp-input-ids` and instead removing that assert + wiring `input_ids=args.tokenize_prompt` — that also inherits the existing `backend == "sglang"` guard and avoids two flags for the same thing.

**Must-fix**
1. `--gsp-num-turns > 1` + ids silently produces wrong traffic (inline below).
2. No backend guard: chat backends receive `list[int]` as `messages` (inline below).

**Nits**
- Stats are suppressed in ids mode, but `prompt_len = len(ids)` is exact there — totals/averages can still be printed (use `len()` instead of `tokenizer.encode`).
- No test: `test/registered/bench_fn/test_benchmark_datasets_api.py` already covers `random-ids` + `tokenize_prompt=True`; a GSP counterpart asserting `list[int]` prompts, `prompt_len == len(prompt)`, and rejection of multi-turn would cover this.

**must-fix**: with `--gsp-num-turns > 1`, each prompt becomes `List[List[int]]`.
