# feat(bench): add --gsp-input-ids to skip server tokenization

[Upstream PR](https://github.com/sgl-project/sglang/pull/40900) · state: open · merged: False

## Original PR description

## Summary

- add `--gsp-input-ids` for the generated-shared-prefix dataset
- send raw random token IDs directly so the server skips tokenization before prefill
- keep input-ID cache entries separate from text-mode cache entries

This ports the change from HYGON-AI/sglang-das#315.

## Benchmarking note

When measuring the speedup, 用 `/generate` 或 `/v1/completions` 发；不要用 chat 接口，否则 chat template 等额外开销会让结果看起来“没快多少”。

### reviews

- whybeyoung · COMMENTED · 2026-10-13T01:07:06Z · [source](https://github.com/sgl-project/sglang/pull/40900#pullrequestreview-5497682315)

Thanks for the PR — sending raw ids for GSP is useful (it also makes the shared prefix exact at the token level, which the decode→re-encode text path doesn't guarantee). A few issues before merge:

**main already has this switch.** `--tokenize-prompt` (`serving.py`, "Use integer ids instead of string for inputs") is the existing global flag for this; `random-ids` honors it via `return_text=not tokenize_prompt`, and `async_request_sglang_generate` already sends `input_ids` for non-str prompts. GSP currently just asserts it off (`generated_shared_prefix.py:59`). Suggest dropping `--gsp-input-ids` and instead removing that assert + wiring `input_ids=args.tokenize_prompt` — that also inherits the existing `backend == "sglang"` guard and avoids two flags for the same thing.

**Must-fix**
1. `--gsp-num-turns > 1` + ids silently produces wrong traffic (inline below).
2. No backend guard: chat backends receive `list[int]` as `messages` (inline below).

**Nits**
- Stats are suppressed in ids mode, but `prompt_len = len(ids)` is exact there — totals/averages can still be printed (use `len()` instead of `tokenizer.encode`).
- No test: `test/registered/bench_fn/test_benchmark_datasets_api.py` already covers `random-ids` + `tokenize_prompt=True`; a GSP counterpart asserting `list[int]` prompts, `prompt_len == len(prompt)`, and rejection of multi-turn would cover this.

- whybeyoung · comment · 2026-10-13T01:07:06Z · [source](https://github.com/sgl-project/sglang/pull/40900#discussion_r4253745126)

File: `python/sglang/benchmark/datasets/generated_shared_prefix.py` · line 308

**must-fix**: with `--gsp-num-turns > 1`, each prompt becomes `List[List[int]]`. In `benchmark()`, `_normalize_round_messages(list[int])` returns `None`, so `is_multi_turn` is False and the multi-turn wrapper is skipped. The whole list-of-lists is then sent as `input_ids` to `/generate`, which the server treats as a *batch*: turn 1 = system+q1, turns 2..N = bare questions with no history. Results are wrong with no error. Please reject `num_turns > 1` together with ids mode at arg validation.

**must-fix**: no backend restriction.
