# [Fix] Honor tool_choice.disable_parallel_tool_use on /v1/messages

[Upstream PR](https://github.com/sgl-project/sglang/pull/43112) · state: open · merged: False

## Original PR description

## Motivation

Anthropic clients send `tool_choice.disable_parallel_tool_use: true` to allow at most one tool call in a turn. The `/v1/messages` endpoint dropped this field, so parallel tool calls stayed on. A reviewer noted the missing field when the endpoint was added in #18630, and it was not followed up.

## Modifications

- Add the optional `disable_parallel_tool_use` field to `AnthropicToolChoice`.
- When it is true, the converter sets `parallel_tool_calls=False` on the chat completion request. The chat path already applies that setting to the tool call constraints.
- New unit test `test_tool_choice_disable_parallel_tool_use_is_forwarded`. Its `disable_parallel_tool_use=True` case fails on main and passes with this change. The whole `test/registered/unit/entrypoints/anthropic` folder passes: 64 passed.

## Accuracy Tests

Not affected. The change only converts the request.

## Speed Tests and Profiling

Not affected.
