# [Fix] Preserve BF16 NaNs in per-token FP8 quantization

[Upstream PR](https://github.com/sgl-project/sglang/pull/42689) · state: open · merged: False

## Original PR description

## Motivation

BF16 NaNs currently become finite FP8 values during per-token group quantization. For example, the UE8M0 path converts a NaN lane to `+448`, hiding invalid activations from downstream NaN checks. Preserve those NaNs so callers can detect the original numerical failure.

This intentionally changes the BF16 FP8 sanitization behavior introduced in #32188 and optimized in #32296. FP16 retains its existing behavior because its scaling multiplier can overflow for finite inputs.

## Modifications

- Use NaN-preserving clipping for BF16 with UE8M0 scales.
- Use the saturating FP8 conversion directly for BF16 with FP32 scales. It preserves NaNs while still saturating infinite and out-of-range scaled values.
- Keep FP16, FP32-input, and INT8-output behavior unchanged.
- Add plain/fused and flat/masked regression cases, including fully NaN groups, masked padding, and CUDA graph capture/replay. Retain the existing non-finite sanitization cases for FP16.

## Accuracy Tests

- Python syntax, Ruff checks/formatting, Clang-format 20.1.7, and `git diff --check` pass.
- Full CUDA regression suite: **123 passed, 0 skipped** on GB300 with CUDA 13.2. Command: `SGLANG_JIT_KERNEL_RUN_FULL_TESTS=1 pytest -q test/registered/kernels/ops/quantization/test_per_token_group_quant.py`. This includes finite-input regressions, BF16 NaN preservation, FP16 sanitization, and capture/replay with finite and NaN-containing inputs.
- Graph tests cover the quantizer itself. Full-model graph warmup with async assertions enabled remains a separate validation requirement because warmup may read uninitialized buffers.

## Speed Tests

No benchmark completed on this upstream revision. The change adds no host synchronization or separate GPU kernel.
