# [Fix] Kimi-K3: Refresh --dcp-replicate-q-proj weights on weight update

[Upstream PR](https://github.com/sgl-project/sglang/pull/47530) · state: open · merged: False

## Original PR description

Stacked on #47527. Only the last commit is new here; I will rebase onto `main` once #47527 is merged.

## Why?

- With `--dcp-replicate-q-proj` (Kimi-K3's default under DCP), the model runner all-gathers `q_b_proj` and `w_kc` into full-head buffers once, after the first load (`ModelRunner._prepare_replicated_q_proj`). The DCP MLA decode projects Q from those buffers.
- A weight update rewrites `q_b_proj` and `w_kc` but never the buffers. So an engine that starts on dummy weights and gets its real weights by update, as RL engines do, decodes with random Q.
- Kimi-K3 W4A16 TP16+DCP16 RL measured ESS 0.06 and KL 0.65 against the trainer, versus ESS 0.99 and KL 0.003 for TP16 without DCP.

## What?

- `post_load_weights` re-gathers the replicated buffers in place for each MLA layer whose attention weights the call loaded. In place matters because captured CUDA graphs hold these buffers.
- With no weight names (P2P/RDMA updates call only `post_load_weights`), every MLA layer is refreshed on every rank, so the DCP all-gathers line up.
- The block-FP8 replica `q_b_proj_qrep` is rebuilt the same way as at startup and copied into the existing module.
- `model_runner.py` is unchanged. The refresh reuses its `_gather_block_fp8_linear` through a lazy import; reviewers may prefer moving that helper to a shared module.

## Verification?

```text
Kimi-K3 TP16 + DCP16, engine started from dummy weights, RL weight sync

Before: q_b_proj / w_kc updated, full-head Q buffers still dummy → ESS 0.06, KL 0.65   (observed, internal fork)
After:  full-head Q buffers re-gathered on update                   → ESS 0.99, KL 0.003 (observed, internal fork)
```
