# [Anthropic] Attach mid-turn inline system messages in place to preserve prefix cache (#42272)

[Upstream PR](https://github.com/sgl-project/sglang/pull/42533) · state: open · merged: False

## Original PR description

Fixes #42272

### Problem
When serving chat templates that enforce system-at-beginning (e.g. Qwen's `System message must be at the beginning.` guard), `AnthropicServing._convert_to_chat_completion_request` previously folded every mid-conversation `role: "system"` message into the leading system block (`self._merge_inline_system`).

Clients such as Claude Code 2.1.x send an inline system message after every turn (environment updates, then `<total_tokens>...</total_tokens>` reminders). Hoisting these turns into the leading system block rewrote the prompt prefix at the very beginning of the prompt on every turn:
- RadixAttention prefix caching missed 100% of conversational history.
- In multi-turn agent sessions (e.g. 75K–109K context), every turn re-prefilled the entire context from scratch (TTFT ~8.3s).

### Solution
1. **In-place inline system attachment on merge path**: On the merge path (`self._merge_inline_system`), stop hoisting mid-conversation system messages into the leading system block; only the top-level `anthropic_request.system` field is placed there.
2. **`_attach_inline_system`**:
   - Attaches mid-conversation system messages in place wrapped in `<system>`n{text}`n</system>`.
   - Appended to the preceding `user` or `tool` message if present (string content gets appended; list content gets a text part appended).
   - Emitted as a `user` message if no preceding `user`/`tool` message exists (preserving valid alternation for strict templates).
3. **Prefix cache stability**: Earlier conversational turns render identically across requests. Multi-turn benchmarks demonstrate cache hit rates rising from 32% to 96% and mean TTFT dropping from 8.3s to 0.5s.
4. **Test coverage**:
   - Updated expectations in existing unit tests (`test_in_messages_system_merged_when_template_requires_first`, `test_in_messages_system_merged_with_top_level_when_merge`, `test_constructed_message_objects_merged_on_merge_path`).
   - Added new unit tests in `test/registered/unit/entrypoints/anthropic/test_serving.py`:
     - `test_in_messages_leading_inline_system_emitted_as_user`
     - `test_in_messages_system_attached_to_preceding_tool_result`
     - `test_in_messages_system_attached_to_multipart_user_content`
     - `test_in_messages_system_prefix_cache_multi_turn_invariant`

- rishabhsinha17 · comment · 2026-10-09T23:03:55Z · [source](https://github.com/sgl-project/sglang/pull/42533#issuecomment-6090751089)

Checked this at the rendered-token level, since the radix cache matches tokens after the chat template runs rather than converted messages.

I drove `_convert_to_chat_completion_request` from main (f6c848c) and from this branch (e680ca4) with a conversation shaped like the one in #42272: a top-level system block, then per turn a user message, an inline system env block, a `tool_use`, a `tool_result`, an inline `<total_tokens>` reminder and an assistant reply, 10 requests in all. I forced the merge path (`supports_inline_system = False`) and rendered every request with the Qwen/Qwen3-0.6B chat template.

On main, the share of each prompt that the next request repeats falls from 95% at the first request to 47% by the ninth. The fork never moves past the system text because each new inline system message changes the leading block, so new prefill per request grows with the conversation (149 to 701 tokens in this short run). On this branch every request repeats the previous prompt in full and new prefill per request equals the appended turn (55 to 138 tokens), 914 tokens over the 9 follow-up requests against 3,689 on main.

One gap the unit tests leave open is that they compare converted messages, while a template can still render an earlier turn differently once a later one exists. A test that renders turn k and turn k+1 through a real template and asserts token-prefix equality would catch that class of regression. Happy to share the script if useful.

Here is the script. It takes a checkout path and a model on the command line and drives `_convert_to_chat_completion_request` from that tree. The same file measures main and this branch, at e680ca4 when I ran it.

<details>
<summary>probe.py</summary>

```python
"""Render a Claude-Code-style /v1/messages conversation through SGLang's Anthropic converter
(main vs PR #42533) and Qwen3's chat template, and measure turn-to-turn token prefix reuse.

Usage: python probe.py <variant_dir> <model>
"""
import json
import sys
from types import SimpleNamespace

variant, model = sys.argv[1], sys.argv[2]
sys.path.insert(0, f"{variant}/python")
from sglang.srt.entrypoints.anthropic.protocol import AnthropicMessagesRequest  # noqa: E402
from sglang.srt.entrypoints.anthropic.serving import AnthropicServing  # noqa: E402
from transformers import AutoTokenizer  # noqa: E402


class FakeChat:
    native_reasoning_history = False
    supports_inline_system = False  # the merge path: templates with a system-first guard

    def __init__(self):
        self.tokenizer_manager = SimpleNamespace(tokenizer=SimpleNamespace(chat_template=None))

    def supports_native_reasoning_history(self):
        return False

    def apply_reasoning_enabled(self, chat_request, enabled):
        pass

    def wrap_reasoning_history(self, text):
        return f"<think>\n{text}\n</think>"


SYSTEM = "You are a coding agent. Follow repository conventions and run tests before finishing. " * 20
ENV = "<env>cwd: /repo\nplatform: linux\ndate: 2026-10-09</env>"
TASKS = ["Find why test_cache fails.", "Fix it without changing the API.", "Run the full test suite.",
         "Add a regression test.", "Write a changelog line."]


def build_requests():
    """Requests in the order an agent sends them; each one resends the full history."""
    msgs, reqs, budget = [], [], 200000
    for i, task in enumerate(TASKS):
        msgs.append({"role": "user", "content": task})
        msgs.append({"role": "system", "content": ENV})
        reqs.append(list(msgs))  # model decides to call a tool
        msgs.append({"role": "assistant", "content": [{"type": "tool_use", "id": f"call_{i}", "name": "read_file",
                                                       "input": {"path": f"src/mod_{i}.py"}}]})
        msgs.append({"role": "user", "content": [{"type": "tool_result", "tool_use_id": f"call_{i}",
                                                  "content": f"def f_{i}():\n    return {i}\n" * 8}]})
        budget -= 1500
        msgs.append({"role": "system", "content": f"<total_tokens>{budget} tokens left</total_tokens>"})
        reqs.append(list(msgs))  # model answers after the tool result
        msgs.append({"role": "assistant", "content": f"Done with step {i + 1}."})
    return reqs


def to_dicts(chat_request):
    out = []
    for m in chat_request.messages:
        d = m.model_dump(exclude_none=True) if hasattr(m, "model_dump") else dict(m)
        c = d.get("content")
        if isinstance(c, list):  # SGLang flattens text parts before applying a string-content template
            d["content"] = "\n".join(p.get("text", "") for p in c if isinstance(p, dict))
        if d.get("tool_calls"):
            for tc in d["tool_calls"]:
                fn = tc.get("function", {})
                if isinstance(fn.get("arguments"), str):
                    try:
                        fn["arguments"] = json.loads(fn["arguments"])
                    except json.JSONDecodeError:
                        pass
        out.append(d)
    return out


def lcp(a, b):
    n = 0
    for x, y in zip(a, b):
        if x != y:
            break
        n += 1
    return n


tok = AutoTokenizer.from_pretrained(model)
serving = AnthropicServing(FakeChat())
renders = []
for msgs in build_requests():
    req = AnthropicMessagesRequest.model_validate(
        {"model": "m", "max_tokens": 64, "system": SYSTEM, "messages": msgs, "stream": False})
    chat = serving._convert_to_chat_completion_request(req)
    ids = tok.apply_chat_template(to_dicts(chat), tokenize=True, add_generation_prompt=True)
    if not isinstance(ids, list):
        ids = ids["input_ids"]
    renders.append(list(ids))

rows = []
for k in range(len(renders) - 1):
    kept = lcp(renders[k], renders[k + 1])
    rows.append({"request": k + 1, "prompt_tokens": len(renders[k]), "kept": kept,
                 "kept_share": round(kept / len(renders[k]), 3),
                 "new_prefill_next": len(renders[k + 1]) - kept})
print(json.dumps({"variant": variant.rsplit("/", 1)[-1], "rows": rows,
                  "mean_kept_share": round(sum(r["kept_share"] for r in rows) / len(rows), 3),
                  "total_prefill_after_first": sum(r["new_prefill_next"] for r in rows)}))
```

</details>

Run it once per tree, `python probe.py /path/to/sglang-main Qwen/Qwen3-0.6B` and again with this branch's checkout. Each row is one request, with the tokens the next request keeps as a prefix and the new prefill it adds. `FakeChat` forces the merge path, which is the case #42272 describes.

For the unit test, the last loop is the part worth keeping. Render turn k and turn k+1 through a real template, assert the k+1 ids start with the k ids, and run it with a system-first template such as Qwen3's. The converted-message checks still belong in the suite. This one catches a template that renders an earlier turn differently once a later one exists.
