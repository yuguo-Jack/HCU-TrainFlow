# [Feat] lora: CuTeDSL FP8 grouped GEMMs and providers (19/21)

[Upstream PR](https://github.com/sgl-project/sglang/pull/42886) · state: closed · merged: False

## Original PR description

Part 19 of 21 of the LoRA runtime stack (branch `lora-stack-18-cutedsl-fp8`, base `lora-stack-17-triton-fp8`). The stack is cut from the development branch of #42284.

## What this part adds

Add the SM90 and SM100 FP8 grouped GEMM kernels, the FP8 prepare entry points
and their inventory entries, and the CuTeDSL FP8 providers with 128x128 block
scales for both row domains. CuTeDSL becomes the FP8 default vendor.

Tests: CuTeDSL FP8 numerics, scale-epilogue tile rejection, the SM90
heuristic, masked-capacity graph replay, prepared-input reuse, FP8 vendor
selection.

## Verification

- GB300 run r45: the tree of upstream main `c1c287a429` plus parts 01–19 imports every module this part changes and passes this part's tests together with every earlier part's unit tests: **424 passed, 740 warnings, 154 subtests passed in 56.82s** (excluding the tests that fail identically on the untouched base tree in that environment).
- `pre-commit` passed on the changed files of every part; `pre-commit run --all-files` passed on the complete stack tree.

The complete 21-part tree equals the development branch of #42284 at `e7b7179a86` (the `6588053ef2` tree with four test-only follow-ups squashed into its dense commit: the admission/snapshot trim, the restored FP8 block-shape admission pin, a second trim that keeps only the tests guarding silent failures and adds pins for four coverage gaps, and restored numerical and packing coverage; production code is unchanged) minus the benchmark tools and the Triton MoE tuning tables, which follow in separate PRs.
