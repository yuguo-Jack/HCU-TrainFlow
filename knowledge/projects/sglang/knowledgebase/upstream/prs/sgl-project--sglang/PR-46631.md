# [Perf] [NVIDIA] qsa: Share compressed-key reads across the four verify rows of a request

[Upstream PR](https://github.com/sgl-project/sglang/pull/46631) · state: open · merged: False

## Original PR description

## Motivation

#43463 bounds the decode indexer's work by the context length, but at the batch sizes we serve (112–256 verify rows) it launches 16 CTAs per row, so each CTA walks 1/16 of a long context serially. With MTP, the four verify rows of a request also read the same compressed keys four times. At long contexts the scorer becomes slower than before #43463.

## Modifications

- For target verification with four draft rows (page size 16, head dim 128, BF16 or FP8 index cache, 64–380 rows divisible by 4) on SM107 (Rubin), score the four rows of a request together: 32 CTAs per request group, each reading a key tile once for the four query rows.
- Pass the actual indexer head count separately from the MMA zero padding; keep the per-row skip for rows with ≤512 compressed blocks.
- All other shapes and architectures keep the #43463 path unchanged. The choice depends only on the row count, so it is CUDA-graph safe.
- No new CI test; the bitwise comparisons and graph replay checks below were run as standalone validation.

## Accuracy Tests

Scorer logits are bitwise identical to the existing kernel over a sweep of 1–384 rows × 2K–256K context, and over 256 captured real length/padding mixes in BF16 and FP8. Top-k selection follows from the same logits.
