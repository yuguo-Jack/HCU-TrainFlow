# [Perf] dsv-v4.1: Score only candidate positions in indexer consumers

[Upstream PR](https://github.com/sgl-project/sglang/pull/46003) · state: open · merged: False

## Original PR description

## Motivation

The Torch prefill indexer consumer currently computes scores over all visible K positions before gathering scores from previously published candidate blocks.

Since the consumer selects its final top-k exclusively from those blocks, scoring positions outside the candidate set adds unnecessary computation and intermediate tensor traffic.

This PR computes scores directly over the published candidates, reducing the score width from the full visible K length to the candidate width.

## Modifications

- Add a Triton kernel that loads K positions through candidate block IDs and computes BF16 per-head scores directly over those positions.
- Preserve the existing ReLU, head weighting, and head reduction operations.
- Apply causal and invalid-candidate masking to the compact scores.
- Select top-k from the compact scores and map the selected columns back to request-local positions and KV pool slots.
- Calculate the score chunk size using the candidate width.
- Enable the optimized path for CUDA BF16 inputs with head dimension 128 and up to 64 heads, when the candidate width is at most half the visible K length. Retain the existing path otherwise.

Candidate publication and candidate counts remain unchanged. This change targets prefill consumers; Decode is unchanged.

## Accuracy Tests

Local validation on NVIDIA H200:

- Passed 21 candidate-score and top-k checks covering empty inputs, short sequences, tile boundaries, and long sequences.
- Passed 30 shape/seed combinations using the model's FP4 fake-quantization path, with exact score and top-k agreement against the reference.
- Passed 8 prefill integration cases covering compression ratios 1/2, full and consumer paths, CP request-row reconstruction, and requests with zero query rows. Selected indices and KV-slot writes matched the reference.
