# [Doc] cookbook: Default Qwen3.8-Flash-Next datacenter recipes to FP8 KV cache and QSA indexer

[Upstream PR](https://github.com/sgl-project/sglang/pull/45245) · state: closed · merged: True

## Original PR description

## Motivation

The Qwen3.8-Flash-Next datacenter recipes run with a BF16 KV cache and a BF16 QSA indexer: none of the checkpoints declare an FP8 KV cache, so `--kv-cache-dtype auto` resolves to BF16, and `--qsa-indexer-dtype` defaults to BF16. This PR makes FP8 the default for both on H200 / B200 / B300 / GB300.

## Modifications

- Add `--kv-cache-dtype fp8_e4m3` and `--qsa-indexer-dtype fp8_e4m3` to every H200 / B200 / B300 / GB300 cell (BF16, FP8, NVFP4 RDXA and NVFP4 NVDA). The GB300 NVFP4 (NVDA) low-latency cell drops its `--kv-cache-dtype bfloat16` / `--speculative-draft-kv-cache-dtype bfloat16` pins.
- `--qsa-indexer-dtype` landed in #39614 and first shipped in v0.5.22; the `qwen38flashnext` image (and the pinned v0.5.21 image) predates it. The CUDA datacenter images move to `lmsysorg/sglang:v0.5.22` (GB300: `v0.5.22-cu130`), and the install note now asks for v0.5.22 or later.
- RTX PRO 6000 (SM120), DGX Spark (SM121) and AMD cells are unchanged: the FP8 indexer is gated to CUDA SM90/SM100 at startup.
- The GB300 NVDA low-latency warning notes that the qualified InferenceX launch ran v0.5.21 with BF16 KV / indexer. The Agentic Long-Context section is left as measured.

## Validation

Config loads under Node; every datacenter cell carries both FP8 flags with no BF16 KV pin, and no other cell carries `--qsa-indexer-dtype`. No GPU run, so accuracy rows in the benchmarks panel still reflect the BF16 KV / indexer runs.
