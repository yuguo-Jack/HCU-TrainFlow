# [Fix] glm47: Handle unserializable tool arguments

[Upstream PR](https://github.com/sgl-project/sglang/pull/44111) · state: open · merged: False

## Original PR description

## Motivation

GLM47 falls back to Python literal parsing when a tool argument is not valid JSON. Values such as sets then fail when the serving path serializes arguments to JSON, which can drop a non-streamed call or interrupt stream finalization.

## Modifications

Check literal-evaluation results with `json.dumps` before returning them. If parsing or JSON serialization raises `TypeError`, keep the original argument text. The separate GLM45 parser is unchanged; this follows the existing Poolside parser pattern.

## Accuracy Tests

Focused CPU regressions and scoped formatting pass on the updated branch. Earlier checks through the serving code covered nested Python-only values and stream finalization. Array and object argument text is still streamed verbatim, so malformed model output can produce invalid JSON chunks. A live model/server run remains unverified.

Run the unit suites with `python -m pytest` and formatting with `pre-commit run --files <changed-files>`.

## Speed Tests and Profiling

Not applicable. The serialization check runs only after JSON parsing fails.
