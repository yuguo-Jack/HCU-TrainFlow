# [Feat] diffusion: Per-task prompt enhancer config and the FLUX.3 Klein upsampler protocol

[Upstream PR](https://github.com/sgl-project/sglang/pull/44662) · state: closed · merged: True

## Original PR description

## Motivation

FLUX.3 Image Klein ships a prompt upsampler, [`black-forest-labs/flux-3-image-klein-pup`](https://huggingface.co/black-forest-labs/flux-3-image-klein-pup) (Qwen3.5-9B). The model card says the image model is meant to run on its long captions, not on a short prompt. `--prompt-enhancer-config` could not drive it as trained:
- every task got the same system prompt and a `{"task", "prompt"}` JSON envelope;
- images always came after the text;
- one sampling config applied to all tasks.

The upsampler has its own t2i / i2i system prompts, an i2i scaffold with the references first, a reference resize, and per-task presence penalty.

## Modifications

`prompt_enhancement.py` only. The upsampler runs as an external srt server, as the enhancer always has.

- **`tasks`**: per-task `system_prompt`, `user_template` (`"{prompt}"` is substituted), `images_first` and `generation_kwargs`.
  - Unset fields fall back to the top level.
  - A task with no entry keeps today's behavior exactly.
- **`protocol: "flux3-klein-pup"`** (+ `protocol_source`, a local dir or HF repo, default the pup repo) follows BFL's reference code (`src/flux3/pup.py`). It reads `system_prompts.json` and sets:
  - **t2i**: the `t2i` prompt, raw prompt as the user message, presence penalty 1.5;
  - **i2i**: the `i2i` prompt, the reference scaffold with images first, presence penalty 0;
  - **references**: RGB over white, LANCZOS-resized to the reference budget (1 MP / 724² / 512² for 1 / 2 / 3+ refs, 32-px grid), JPEG q92;
  - **sampling**: temperature 0, top_p 0.95, top_k 20, min_p 0, max_tokens 3584, `enable_thinking: false`.

  Explicit config fields override the protocol.
- **Cookbook (FLUX.3 §7)**: config, serve command and curl example. The layout (`*_bbox`) prompts are not wired yet.

## Validation

H200, sglang `main` + this branch. The upsampler ran as srt from the image's sglang.

- **Unit tests**: `test_prompt_enhancement.py` 57 passed. New cases:
  - per-task template, image order and sampling merge;
  - the protocol payload (system prompts, sampling, scaffold; a 2000×1000 RGBA reference arrives as a 1440×704 JPEG with white where it was transparent);
  - explicit tasks overriding the protocol;
  - invalid task configs rejected.
- **End to end** (FLUX.3 Klein Base, 1 GPU, `"enhance_prompt": true`):
  - **t2i**: 9.38 s per request, of which about 2 s is upsampling.
  - **i2i** with one reference: 16.30 s.
  - The server log shows the upsampled prompts (2160 and 1438 characters) reaching the pipeline.
- **Reproducibility**: greedy decoding alone does not give a stable caption, because it varies with srt's prefix-cache state. With `--enable-deterministic-inference --disable-radix-cache` on the upsampler, reruns return the identical caption (md5 `b0e44fd9c061`). The cookbook says so.

Not tested: video tasks (unchanged path), multi-reference i2i end to end (resize covered by unit test).
