# [Fix] session: Prefill a retracted one-token first turn as a new request

[Upstream PR](https://github.com/sgl-project/sglang/pull/46276) · state: open · merged: False

## Original PR description

## Motivation

With `--enable-streaming-session`, the scheduler crashes with `AssertionError: a reused row must carry allocated KV` (in `ReqToTokenPool.alloc`, from `alloc_for_extend`) when a session's first turn has a one-token prompt and is retracted after its prefill, before it decodes anything.

How it happens:

1. The first turn's row allocation hands its record to the session slot (`StreamingSession.take`).
2. `retract_decode` releases the turn through `try_cache_finished_req`. The slot keeps the record with `kv_committed_len = 1`.
3. When the turn is scheduled again, the prefill match key drops the last prompt token, so for a one-token prompt the key is empty. `try_match_prefix` still lends the record, rewinds it to `min(1, 0) = 0` with `_free_tail`, and returns a 0-token match.
4. The request now owns a req_to_token row with no KV. `ReqToTokenPool.alloc` asserts on exactly that and takes the scheduler down.

## Modifications

- `try_match_prefix`: when the record has nothing to reuse (`min(kv_committed_len, len(key)) == 0`), release the slot and return `None` before lending it, so the turn prefills as a new request. The NPU branch just above already does the same for a match below one aligned page. Later turns always carry the session's history in the key, so this only applies to the first turn.
- New test `test_retracted_one_token_first_turn_is_prefilled_as_a_new_request` in `test_streaming_session_unit.py`. It fails on `main` because the request comes back holding the row without KV.
