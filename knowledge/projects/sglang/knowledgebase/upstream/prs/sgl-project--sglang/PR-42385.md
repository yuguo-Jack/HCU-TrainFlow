## Original PR description

## Motivation
Part of the Cake-kernel forwarding layer requested in the tracker sgl-project/sglang#42176 (namespace per RFC #29630):
every public FlashInfer Cake entry point gets a lazy adapter under `python/sglang/kernels/cake_kernels/`, a
`KernelSpec(backend=FLASHINFER)` in `sglang.kernels.ops.<group>`, and a registered test. Precedent: #42004 (SM103
softmax). FlashInfer baseline: `e4f94f94848372b5019eb1d8b4e075a7393f7e1a` (main, 2026-10-03; see `cake_kernels/README.md` § Versioning).
The sglang dependency pin is **unchanged**; when the installed FlashInfer lacks a module the adapter's
`supports_<op>()` returns `False` (via `importlib.util.find_spec`) and the registered test skips with the reason.

> **Stacked on #42381.** This branch contains that PR's commit(s) so it is importable on its own; review only the top commit(s) — the diff shrinks to this PR's files once the base PR merges.

Adapter rules (checked by `test/registered/unit/kernels/test_kernels_namespace.py`, which ships in 42381):
importing the adapters or `sglang.kernels.ops` loads no FlashInfer / CUDA / JIT; `supports_<op>()` mirrors the
FlashInfer admission (SM, dtype, layout, shape, module presence) and never raises; forwarders import FlashInfer
lazily. Each registered test checks (a) the registry resolves the explicit FlashInfer backend, (b) the admission
predicate, (c) the facade result is **bitwise** identical to calling FlashInfer directly, and (d) a reference check
at the dtype's tolerance (BF16 1e-2, FP8 0.1, FP4 1.0 — never loosened).
