# [Perf] [SM90] dsv4.1: Add fused FP8 prefill indexer scoring

[Upstream PR](https://github.com/sgl-project/sglang/pull/45539) · state: open · merged: False

## Original PR description

## Motivation

DeepSeek-V4.1's Torch prefill indexer on Hopper computes QK scores in BF16. This PR converts Q/K to E4M3 and uses **native FP8 Tensor Core matrix multiplication** to accelerate scoring in full, candidate-publishing, and candidate-consuming index layers.

All Q/K values observed in the conversion audit were exactly representable in E4M3, allowing these inputs to use FP8 computation without input-conversion error. The implementation also fuses ReLU, head weighting, and reduction to reduce intermediate memory traffic.

On 8×H20-3e, the complete fused FP8 path reduces mean TTFT by **19.21% at 67,715 input tokens** and **29.62% at 127,703 input tokens**, compared with the original Torch BF16 path.

## Modifications

- **Native FP8 scoring:** use E4M3 Q/K with Triton `tl.dot` for FP8 matrix multiplication, rather than converting FP8 operands back to BF16 for the dot product. Keep head weights in BF16, preserve BF16 rounding points after the dot product, weighting, and reduction, and output FP32 scores.
- **Direct FP8 K preparation:** gather request-visible FP4 cache entries and decode directly into a request-shared E4M3 K buffer, avoiding an intermediate BF16 K write. Convert query rows to E4M3.
- **Fused postprocessing:** apply ReLU, head weighting, head reduction, and causal masking inside the same kernel, avoiding a full per-head score tensor in HBM.
- **Adjusted chunk budget:** size FP8 query chunks for reduced scores and selection scratch; preserve the existing BF16 budget.
- **One opt-in switch:** `SGLANG_DSV41_FP8_PREFILL_INDEXER=1` enables the path across prefill index layers on supported SM90 inputs (32 indexer heads, head dimension 128). It defaults to OFF and preserves the original path and explicit Torch oracle override.
- Add kernel and dispatch regression tests. Candidate selection, index writeback, and decode behavior remain unchanged.

## Accuracy Tests

**Model evaluation:** the same source with FP8 OFF/ON, single-node 8×H20-3e, TP8/EP8, chunk size 8192, bounded replay enabled, no speculative decoding. Temperature 0, top_p 1, sampling seed 1, max_new_tokens 4096; identical frozen input IDs in both arms.

| Dataset | FP8 OFF | FP8 ON |
|---|---:|---:|
| GSM8K, fixed 200-question subset, 0-shot | 184/200 (92.0%) | 182/200 (91.0%) |
| GSM8K length-truncated responses | 8 | 7 |
| GSM8K parsing failures | 3 | 3 |
| LongBench-v2, 9-question long-context smoke | 4/9 | 4/9 |
| LongBench-v2 length-truncated responses | 3 | 2 |
| Request/runner errors | 0 | 0 |

GSM8K used concurrency 8; LongBench-v2 used concurrency 1 with actual input lengths from 18,426 to 123,398 tokens. The GSM8K difference is **−1.0 percentage point**. Repeating the 16 initially discordant GSM8K questions in reverse arm order left 3 consistently A-only and 1 consistently B-only outcomes. These subset results do not establish statistical non-inferiority; LongBench-v2 is a smoke test.

**Q/K conversion audit:** separate instrumentation checked every executed prefill indexer Q/K element across all eight ranks and layers 2/8/14/20/24/28/32/36. All observed conversions were bitwise lossless, with no nonfinite values, overrange values, or nonzero-to-zero conversions; maximum observed absolute value was 128.

## Speed Tests and Profiling

Single-node **8×H20-3e**, **TP8/EP8**, chunk size **8192**, bounded replay enabled, no speculative decoding, prefill graph disabled, decode graph enabled, and the automatic bounded decoder-tail graph retained. BS=1, OSL=1, radix cache disabled, with a cache flush before each request. Both arms use the same source and configuration except for the FP8 switch.
