# [Feat] kimi-k3: bound rank-local vision encoding batches

[Upstream PR](https://github.com/sgl-project/sglang/pull/46103) · state: open · merged: False

## Original PR description

K3 defers image preprocessing to the owning vision-DP rank, but that rank still materializes and encodes its whole shard at once. Large requests can retain a normalized pixel buffer and encoder workspace together.

Add an opt-in `SGLANG_K3_VISION_MAX_FRAMES_PER_BATCH` limit. Each owner preprocesses and encodes complete temporal items in bounded groups, then uses the existing embedding gather and order reconstruction. `0` keeps the current one-batch path; final embeddings and language-model KV still grow with the request. This builds on main's deferred preprocessing, rather than adding a new video input format or duplicating #35325.

Validate the frame budget against the complete shared grid list before owner assignment or encoding. Otherwise an oversized item can make its owner raise while an empty peer enters the single-image broadcast. The regression covers both ranks; valid requests retain the existing batching and order.

## Validation

The earlier CPU mRoPE helper and synthetic K3 routing checks validate temporal grouping, owner-only callbacks, underfilled/empty ranks and ordering on `8fa0c9d0`. They use a synthetic tower and are not real CUDA preprocessing or tower-numerics evidence.

At `4978d435`, the follow-up executes the actual K3 `get_image_feature` method, DP helper and new registered regression bodies on CPU. The old source rejects on the owner but reaches broadcast on the empty peer; the patch makes both reject before any collective. The unchanged helper regression suite also passes. Torch 2.14.1 is real CPU; runtime configuration, collective groups and media-item objects are fixtures, with startup imports isolated. This does not execute real collectives or the full SGLang package.

At `0176d36`, a new registered CPU test runs two real Gloo ranks: both reject an invalid budget, then the same ranks finish a single-item broadcast and an uneven all-gather. Locally, unchanged K3 method/helper bodies were loaded from source with fixture configuration and media objects (macOS, CPU Torch 2.14.1). It fails on pre-guard `8fa0c9d0` with a 10-second Gloo receive timeout and passes on the fix. The upstream test uses normal K3 imports; that full-package path remains unverified locally because `datasets` is missing. This adds CPU collective liveness/recovery evidence, not CUDA/NCCL or full-service validation.

At `f384bc57`, a source-isolated run on **2× A100 PCIe 40GB** used the unchanged K3 method and six DP helper bodies with real CUDA tensors and NCCL (PyTorch 2.5.1+cu124, NCCL 2.21.5). Single-image broadcast with an empty peer and unequal padded all-gather passed exact shape/value checks on both ranks, for parent `8fa0c9d0` and the current head. Oversized/zero-budget cases rejected on both fixed ranks before collective/tower/materialization; the parent's empty-rank collective attempts were intercepted before NCCL, then both variants completed healthy cases in the same initialized group. The tower, media and group adapters are fixtures. [GPU run and scope](https://github.com/sgl-project/sglang/pull/46103#issuecomment-6519517985).

A separate normal-package run at `f384bc57` constructs the real encoder-only K3 wrapper, vision tower and projector with a tiny configuration and deterministic random weights (1,952 parameters), using two real SGLang WORLD/model-parallel Gloo ranks. The current complete source archive was checked against all 11,229 Git blobs. Unlimited and frame-bounded outputs match exactly for an empty-peer broadcast and an uneven gather with temporal pooling/spatial interpolation; both ranks reject invalid temporal budgets and complete healthy requests afterward. This uses CPU Torch 2.14.1 on macOS, native RoPE/SDPA, already prepared tensor items and explicit test topology. The unused message-queue broadcaster is disabled via its normal option, and upstream's macOS compatibility layer remains active. It does not qualify CUDA tower numerics, pretrained weights, media preprocessing, CUDA IPC or the production launcher.

Scoped Ruff, formatting, isort and diff checks pass. The cookbook documents the limit. Current-head docs-site validation, normal-package CUDA preprocessing/tower numerics, peak memory and end-to-end serving remain unverified. No performance claim.
