# [Perf] [AMD] kda: Use a HIP chunked-prefill kernel for KDA on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/45710) · state: closed · merged: True

## Original PR description

## Motivation

Kimi-K3 has 69 KDA (Kimi Delta Attention) layers. On MI350X / MI355X (gfx950), KDA prefill runs the multi-kernel Triton `chunk_kda` pipeline. This PR adds a HIP chunked-prefill kernel for gfx950 and tries it first inside `TritonKDAKernel.extend`, so the default prefill backend gets faster on gfx950 without a new flag. Other GPUs, and inputs the kernel does not cover, keep `chunk_kda`.

**Note: This kernel is generated by [KDAgent](https://nvlabs.github.io/kda/blog/2026-09-27-kda-for-kda/) in AMD ecosystems.  Cost around 5k dollars in humanize2 flow to get this.**

## Modifications

The kernel follows the `sglang.kernels` layout of RFC #29630: it was produced with the Kernel Design Agents workflow, so the implementation lives in `kernels/kda_kernels`, it is registered with `KernelBackend.KDA`, and runtime code reaches it only through the `sglang.kernels.ops` facade.

- `kernels/kda_kernels/csrc/attention/kda_prefill_gfx950.cu` and its loader `kernels/kda_kernels/kda_prefill_gfx950.py`, JIT-compiled on first use with `load_extension_with_recovery`. The kernel needs the bf16 16x16x32 MFMA and up to 157 KiB of LDS, so it is gfx950-only.
  - `kda_intra_kernel` runs over (64-token chunk, head). It computes the gate `-5 * sigmoid(exp(A_log) * (g + dt_bias))` and its chunk cumsum, the beta sigmoid, the q/k L2 norms, and the chunk's UT transform and intra-chunk attention, and stores them as one workspace block per chunk.
  - A recurrence kernel walks each sequence's chunks and writes the outputs, the final states (in place, like `chunk_kda`) and the optional `track_state` snapshot. `kda_recur_path` picks one of six layouts from the batch shape, the longest sequence and the CU count: a pipelined single kernel for balanced batches with about one (sequence, head) pair per CU, sequence groups joined by an fp32 scan for one long sequence, warp-specialized value-split kernels for few pairs or a dominant long sequence, and one workgroup per pair otherwise.
- `kernels/kda_kernels/README.md`: provenance entry.
- `kernels/ops/attention/__init__.py`: registers `attention.kda_prefill_gfx950` (`KernelBackend.KDA`, HIP).
- `kernels/ops/attention/linear/kda_gfx950_prefill.py` (facade): `extend()` calls the kernel through `get_kernel` and returns `None` for anything it does not cover: other GPUs, `SGLANG_ROCM_KDA_HIP_PREFILL=0`, spec-decode extends, prefill CUDA graph chunk tables, a gate lower bound other than -5, non-raw beta, per-chunk states `h` requested without a track buffer, non-bf16 inputs, head dim other than 128, and a non-contiguous state pool. It passes `max(extend_seq_lens_cpu)` to the kernel, so choosing the layout needs no GPU sync.
- `srt/layers/attention/linear/kernels/kda_triton.py`: on ROCm, `TritonKDAKernel.extend` calls the facade first and keeps `chunk_kda` when it returns `None`. This guarded call is the only runtime change; CUDA builds never import the facade.
- `test/registered/kernels/ops/attention/test_kda_gfx950_prefill.py` (MI35x suite): the Triton extend routes to the HIP kernel; uncovered inputs fall back; eight layouts covering all six recurrence paths, the chunk-aligned track extend and five track-snapshot cases match `chunk_kda`; untouched state slots stay bit-identical.

## Accuracy Tests

MI355X, `lmsysorg/sglang-rocm:v0.5.22-rocm10-mi35x-20261020`.

- Against `chunk_kda` over 210 shapes (1-128 sequences of 64-64K tokens, 12 and 24 heads, with and without `track_state`): output, final-state and track-snapshot relative L2 difference at most 0.59% (both kernels round to bf16). Unselected state slots stay bit-identical.
- Pass: the new test, `unit/kernels/test_kernels_namespace.py` (includes the KDA directory/backend pairing check), `attention/unittests/kda/test_triton.py`, `attention/test_kda_kernels.py`, `kernels/ops/attention/test_fused_kda_conv_recurrent_verify.py`, `kernels/ops/attention/kda_flydsl/test_kimi_k3_kda_decode.py` and `amd/test_kimi_k3_kda_inproj_fusion.py`.
- Kimi-K3 TP8 GSM8K (8-shot, 1319 questions): 0.960 with both HIP kernels off, 0.961 with this PR and the companion fused-decode PR on.

python3 -m sglang.launch_server --model-path moonshotai/Kimi-K3 --tp-size 8 \
  --attention-backend triton --dtype bfloat16 --mem-fraction-static 0.85 \
  --cuda-graph-max-bs-decode 64 --max-running-requests 64 \
  --reasoning-parser kimi_k3 --tool-call-parser kimi_k3 --trust-remote-code
python3 -m sglang.bench_serving --backend sglang --dataset-name random-ids \
  --random-input-len 1024 --random-output-len 512 --random-range-ratio 1 \
