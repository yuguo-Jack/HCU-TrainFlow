# Fix DeepSeekV3 streaming: emit arguments when name and fence arrive in same delta

[Upstream PR](https://github.com/sgl-project/sglang/pull/42464) · state: open · merged: False

## Original PR description

## Motivation

With `--tool-call-parser deepseekv3`, a streamed tool call loses its arguments when the closing ` ``` ` fence and end tokens arrive in the same streaming event as the tool name match. This is the common case with MTP speculative decoding or `--stream-interval > 1`, where short arguments complete in one delta.

The client receives `"arguments": "{}"` instead of the actual arguments, making the tool call unusable.

## Root cause

`parse_streaming_increment` processed the tool name (lines 135-148) and arguments (lines 149-196) in mutually exclusive `if`/`else` branches. When the regex matched a complete call on the first pass, the `if not self.current_tool_name_sent` branch emitted the name and returned without entering the `else` branch that processes arguments.

## Fix

Remove the `else` gate so argument processing runs unconditionally after the name is sent. When `self._last_arguments` is empty (just sent the name), the full `func_args_raw` is emitted as the argument diff, which is correct.

## Verification

CPU-only, no model weights needed:

```python
from sglang.srt.entrypoints.openai.protocol import Function, Tool
from sglang.srt.function_call.deepseekv3_detector import DeepSeekV3Detector

tools = [Tool(type="function", function=Function(name="get_weather",
         parameters={"type": "object", "properties": {"city": {"type": "string"}}}))]

chunks = [
    "<｜tool▁calls▁begin｜><｜tool▁call▁begin｜>function<｜tool▁sep｜>get_weather\n",
    '```json\n{"city": "Paris"}\n',
    "```<｜tool▁call▁end｜><｜tool▁calls▁end｜>",
]

detector = DeepSeekV3Detector()
streamed = [c for chunk in chunks for c in detector.parse_streaming_increment(chunk, tools).calls]
print("streaming       :", [(c.name, c.parameters) for c in streamed])
# Before: [('get_weather', '')]
# After:  [('get_weather', ''), (None, '{"city": "Paris"}')]
```

Also tested:
- Everything in one chunk (single delta)
- Fine-grained streaming (normal per-token chunks)
- Multi-tool calls (two consecutive tool calls)

All produce arguments matching `detect_and_parse`.
