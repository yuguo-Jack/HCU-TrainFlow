# [Perf] http: Serialize /v1/embeddings responses with model_json_response

[Upstream PR](https://github.com/sgl-project/sglang/pull/46166) · state: closed · merged: True

## Original PR description

## Motivation

`/v1/embeddings` returns the `EmbeddingResponse` Pydantic model to FastAPI. Without a
`response_model`, FastAPI runs `jsonable_encoder` over it, a recursive pure-Python walk that copies
every float of every embedding, before `ORJSONResponse` serializes the copy. The cost grows with the
number of floats in the response, so it shows most on requests that carry many embeddings. The chat and completions routes already avoid this with `model_json_response`, which serializes the
model once with pydantic-core.

## Modifications

- `python/sglang/srt/entrypoints/http_server.py`: `/v1/embeddings` returns
  `model_json_response(...)`, as `/v1/chat/completions` and `/v1/completions` do. Error responses
  pass through unchanged.
- `test/registered/unit/entrypoints/test_embedding_responses.py` (new, CPU): the route returns JSON
  bytes equal to `EmbeddingResponse.model_dump_json(by_alias=True)`.

## Accuracy Tests

Ran `Qwen/Qwen3-Embedding-0.6B` model on one RTX A6000. 32 synthetic texts (8 to 8,430 tokens), sent one per request, as batches in several orders, and concurrently. Each embedding is compared with the FP32 SentenceTransformer reference and the min cosine similarity was ~0.99986 (with and without this change)
