# [NPU][Bugfix] use CANN libdevice for DSpark Markov sampling

[Upstream PR](https://github.com/sgl-project/sglang/pull/43849) · state: closed · merged: True

## Original PR description

## Motivation

DeepSeek V4 Flash with DSpark fails during NPU draft graph capture in [[this CI job](https://github.com/sgl-project/sglang/actions/runs/38233348303/job/114772999125)](<https://github.com/sgl-project/sglang/actions/runs/38233348303/job/114772999125>).

`MarkovSampleStep` calls `-libdevice.log1p(-uniform)`, but the Ascend backend does not map the generic Triton `libdevice` stub to its CANN implementation. The call returns `None`, causing compilation to fail with:

```
AST unary operator '__neg__' is not (currently) implemented on type NoneType
```

The sampling kernel was introduced in \#43621 and integrated into draft graph capture in \#43668.

## Modifications

- Import `triton.language.extra.cann.libdevice` on NPU in `markov_sample.py`.
- Retain the existing generic `libdevice` import on other platforms.

- Host validation with mocked platform/Triton imports and real CPU PyTorch passed: library selection, greedy special values, deterministic sampling, and noise-offset advancement.
