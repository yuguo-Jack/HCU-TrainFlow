# [Perf] [AMD] deepseek-v4: Skip top-k refinement for proven positive-zero ties

[Upstream PR](https://github.com/sgl-project/sglang/pull/44927) · state: closed · merged: True

## Original PR description

## Motivation

DeepSeek-V4 top-k can collect more than 2048 bitwise positive-zero scores in its threshold bucket. The overflow refinement added in #37941 then rescans the input even though all candidates are equal. This case occurs in score tensors captured from an InferenceX AgentX serving run on MI355X.

## Modifications

Prove that every threshold-bucket candidate is bitwise +0, including candidates beyond the staging buffer, and skip refinement only when that proof succeeds. Negative zero, subnormals, and nonzero candidates retain exact refinement.

The shortcut covers register, streaming, and split paths and is gated by `USE_ROCM`; non-ROCm builds retain the original refinement path. Existing shared-memory storage and the split limit are preserved.

## Accuracy Tests

- The eight added graph-replay cases pass on MI355X for both baseline `3b34d9f8` and patch commit `e04efd0a`, with fresh JIT caches. They cover K=1024/2048, all three dispatch paths, and transitions between +0 ties, late tiny positives, subnormals, and negative zero.
- On the serving-image stack, the patch also passes 224 adversarial cases per variant and 96 existing strict prefill tests. Captured-score checks verify exact selected values and valid, unique indices.

**GSM8K with the top-k patch: 1246/1319 (94.47%).**

DeepSeek-V4-Pro-0813 with FP4 experts, TP8 on eight MI355X GPUs, using SGLang `34c4ba14` / AITER `2bb54910` with this PR's top-k headers. The evaluation ran directly through Slurm.

All 1319 test questions were evaluated with eight examples from the training split, temperature 0, seed 42, a 512-token generation limit, and request concurrency 32. Graphs and speculation were disabled. Zero request errors, invalid answers, or truncations.

## Speed Tests and Profiling

**Serving benchmark: [InferenceX](https://github.com/SemiAnalysisAI/InferenceX) AgentX agentic-coding workload**, using DeepSeek-V4 FP4 on 16 MI355X GPUs: one 8-GPU prefill node and one 8-GPU decode node. Concurrency means the AgentX client's `--concurrency` setting (replay lanes).

The controlled A/B uses the same node pair, Python TreeCore, and `lmsysorg/sglang-rocm:v0.5.22-rocm724-mi35x-20261016` base image; the candidate changes only the two top-k headers. At concurrency **192**, with a **1200-second measurement** and **one extra warmup request per lane**:

| Metric (higher is better) | Original | Patched | Change |
| --- | ---: | ---: | ---: |
| P90 interactivity (tokens/s; 1/P90 ITL) | 75.52613 | 81.74591 | +8.24% |
| Total tokens/s/GPU | 40418.21406 | 41878.94256 | +3.61% |

The patched run completed 6740 profiling requests with zero errors. Additional full-length InferenceX AgentX runs at concurrency **192, 256, 384, and 512** used **3600 seconds and ten extra warmup requests per lane**; all completed with zero profiling request errors. Raw results and collected metrics were reconciled.

For operator timing on baseline/patched main, five of six captured input tensors improve by **28.1%–44.5%**, while one is effectively unchanged, using an original → patched → original-repeat sequence on one MI355X. Separate large-batch synthetic controls on the serving-image stack measured **0.59%–5.92% latency overhead** on non-overflow/nonzero cases, so the benefit depends on the input distribution.
