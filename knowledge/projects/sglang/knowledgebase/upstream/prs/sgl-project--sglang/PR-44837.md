# [Perf] deepseek_v4: fuse block-FP8 shared experts into MegaMoE for any 32-aligned block size

[Upstream PR](https://github.com/sgl-project/sglang/pull/44837) · state: closed · merged: True

## Original PR description

## Motivation

Profiling DeepSeek-V4.1-Flash DEP2 prefill on GB300 (MegaAttention, MegaMoE, Mega-mHC, decoder bounded replay, eager prefill, 16K tokens per rank per step) shows the MegaMoE kernel instantiated with `kNumSharedExperts=0`, and the shared expert running as a standalone MLP instead: per layer two dense MXFP8 GEMMs, two activation quantizes, a `silu_mul_clamp` and an `add_`.

On one 16K-token cold prefill chunk per rank (rank 0, torch profiler):

| | Per step |
|---|---:|
| Dense MXFP8 GEMM launches, of which shared-expert | 210, 80 |
| Shared-expert GEMM time | about 18 ms |
| Shared-expert quantize, silu and add launches | 80 + 40 + 40 |
| Total kernel launches | 1,812 |

The eager prefill step is dispatch-bound (median inter-kernel gap 41 µs, about 65 µs of idle per launch), so the ~200 removed launches matter as much as the kernel time.

## Why the fusion was off

`should_fuse_mega_moe_shared_experts` required `shared_experts_weight_block_size == [128, 128]`. DeepSeek-V4.1-Flash's checkpoint quantizes the shared experts as block-FP8 `[32, 32]` with `scale_fmt: ue8m0`, so the gate silently fell back even though `SGLANG_OPT_DEEPGEMM_MEGA_MOE_FUSE_SHARED_EXPERTS` defaults on.

## Modifications

- `mega_moe_shared_block_size_supported`: accept any `(block_m, block_k)` with `block_k % 32 == 0`.
- `_transform_mega_moe_shared_sf`: expand the checkpoint block scale to the kernel's per-row 1x32 UE8M0 layout (each row of a block repeats the block's scale; each 32-wide K slice inside a K block repeats it), using the grouped `transform_sf_into_required_layout` API with a singleton group for the per-row recipe, the same way the routed experts are transformed. The existing `[128, 128]` recipe path and the DeepGEMM-packed int32 path are unchanged.
- Numerics: with `ue8m0` checkpoint scales the expansion is exact; for non-power-of-two scales the UE8M0 cast is the rounding the routed experts already take (`disable_ue8m0_cast=False`), same as before for 128x128.

## Measured

GB300, DEP2 (TP2 + DP attention, EP2), DeepSeek-V4.1-Flash, MegaMoE, Mega-mHC, decoder bounded replay, eager prefill, 16K-token prefill budget per rank, rank 0. Same build with the fusion on (job 3467) and off through `SGLANG_OPT_DEEPGEMM_MEGA_MOE_FUSE_SHARED_EXPERTS=0` (job 3468). The trace shows the engagement: the MegaMoE kernel is instantiated with `kNumSharedExperts=1` (`sm100_fp8_fp4_mega_moe_impl<17280u, 5120u, 2304u, 384u, 1u, ...>`, `0u` with the fusion off) and the per-layer shared-expert quantize, GEMM, silu and add launches are gone.

| One 16K-token cold chunk per rank | fusion off | fusion on |
|---|---:|---:|
| Step time, unprofiled, median of 3 (ms) | 241 | 235 |
| 128K-token prompt in eight 16K chunks, unprofiled (ms) | 1,925 | 1,842 |
| Profiled step annotation (ms) | 267 | 240 |
| Kernel launches per step | 1,847 | 1,607 |
| Dense MXFP8 GEMM launches per step | 212 | 132 |
| MoE section per layer (mHC kernel to the next layer's mHC kernel), sum over 21 layers (ms) | 107.0 | 100.8 |

Every layer's MoE section is shorter, by 0.17 to 0.44 ms. The MegaMoE kernel itself grows by 0.35 to 0.45 ms per layer since it now carries the shared expert; the six removed launches were worth 0.6 to 0.7 ms of kernel time plus their dispatch gaps.

Before: fusion off, layer 6, 4.53 ms and 13 kernels between the two mHC kernels.

After: fusion on, same layer, 4.24 ms and 9 kernels.

![fusion on, layer 6 MoE section](https://raw.githubusercontent.com/kpham-sgl/sglang/assets-prefill-h2h-2026-10-16/prefill-h2h-2026-10-16/pr44837-after-fusion-on-job3467-moe-section.jpg)
