# [HiCache] Add radixshmem storage backend

[Upstream PR](https://github.com/sgl-project/sglang/pull/40704) · state: open · merged: False

## Original PR description

RadixShmemStorage is a HiCacheStorage L3 backend over a node-local radix-server. sglang keeps its host staging pool; pages are copied to and from radixshmem's SlotStore, and keys are the chained page hashes salted per pool and per rank (TP rank only for rank-sharded pools). The backend hands the server its slot geometry on the first storage call, once every host pool is registered: block_size is the KV page size and the slot holds the largest pool page. ALL_PAGES pools are stored as radix paths (prefix query, run pull); TRAILING_PAGES pools as one-block paths per page; pools without bytes (DeepSeek-V4's logical KV anchor) are never stored.

Registered as builtin backend "radixshmem" on the zero-copy v1/v2 path. Unit tests run against an in-memory fake. Verified on DeepSeek-V4-Flash TP4 with --hicache-host-memory-mode buffer_only: a flushed 10k-token prompt is served from storage (cached_tokens_details.storage == 9984).
