# [Perf] kda-replayssm: Reuse the verify-fused commit step indices

[Upstream PR](https://github.com/sgl-project/sglang/pull/44396) · state: open · merged: False

## Original PR description

## Motivation

With `--enable-linear-replayssm-spec` on a KDA model, `commit_mamba_states_after_verify` takes the KDA ReplaySSM branch on every verify. That branch recomputed `last_correct_step_indices` and `mamba_steps_to_track` with about 17 eager kernel launches per step, although the verify commit already fuses both into `prepared_step_indices` (`prepare_verify_commit_outputs`) and the GDN ReplaySSM branches use them. On GLM-5.3-Flash MTP 5/1/6 the host is already the bottleneck with this flag, so the extra launches delay every verify.

## Modifications

- The KDA ReplaySSM branch takes `prepared_step_indices` when given and otherwise calls `_verify_commit_step_indices`, like the two GDN ReplaySSM branches. Both compute the same values as the removed eager code.
- The idle / empty-batch early return and the choice between prepared and recomputed indices now run once, before the branch dispatch, instead of in each of the four branches.
