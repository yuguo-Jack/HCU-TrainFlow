# [Fix] function_call: Keep GLM string arguments as raw text

[Upstream PR](https://github.com/sgl-project/sglang/pull/42995) · state: closed · merged: False

## Original PR description

Fixes #42765
Fixes #42778

GLM chat templates write a string argument raw. Non-streaming parsing still ran that text through `json.loads`, so a string whose text is valid JSON was rewritten.

`Glm47MoeDetector` turned `"hello"` into `hello`. `Glm4MoeDetector` did the same, and also turned `true` into `True`, `null` into `None`, and `1e2` into `100.0`. Streaming already kept the raw text, so the two paths disagreed. `Ling3Detector` inherits the GLM-4 parser.

A string parameter whose text is valid JSON now stays that text. A string that is not valid JSON still follows the existing fallback, including the invalid-escape case that strips one layer of quotes.

`TestGlm4MoeDetector` and `TestGlm47MoeDetector`: 28 passed.
