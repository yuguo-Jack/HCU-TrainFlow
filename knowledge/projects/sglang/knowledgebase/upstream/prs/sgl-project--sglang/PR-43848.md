# [Fix] ngram: Preserve genuine token 0 leaves in corpus merges

[Upstream PR](https://github.com/sgl-project/sglang/pull/43848) · state: open · merged: False

## Original PR description

## Motivation

After padding is disconnected, a genuine token-0 leaf is still discarded when
online and external NGRAM results are merged. Corpora proposing 0 and 40 should
preserve both connected candidates.

## Changes and predecessor

This PR retains the two original commits from samridh10exe's #43742 unchanged,
then adds the focused three-file +29/-4 fix. Padding is identified by a
disconnected parent, and the Python debug helper omits disconnected rows.
Registered CPU regressions cover both corpus sources and BFS/PROB traversal.

The predecessor remains unmerged, but its implementation is already included in
this branch. Review the incremental delta at
https://github.com/mercury125/sglang/compare/1f2c9017543297a291c88efd9182fa664ea2fb70...581f7e2a787cbce8baedc4345a50c13c4599548a.
The branch can be reviewed as a stack; rebase after the predecessor merges.
