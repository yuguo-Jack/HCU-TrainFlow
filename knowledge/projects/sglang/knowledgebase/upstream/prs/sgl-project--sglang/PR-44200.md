# [Feat] watermark: Add DSPARK speculative decoding support

[Upstream PR](https://github.com/sgl-project/sglang/pull/44200) · state: open · merged: False

## Original PR description

> Note: the first commit on this branch is the EAGLE verify-append hotfix from #44199 (watermarked EAGLE/EAGLE3 output is undetectable on main without it). This branch will be rebased to a single commit once #44199 lands.

DSPARK verifies a linear draft chain. Each verify row's context is the committed watermark tail followed by the earlier draft tokens, so the existing speculative selector applies with a lower-triangular chain mask. The DSPARK worker forces those rows before acceptance. After acceptance it records the accepted rows' contexts and appends the committed tokens to the ring.

**Design: verify-side forcing.**
- A forced row's target distribution is one-hot, so DSPARK's rejection-sampling accept — with or without block verification — emits exactly the watermarked token.
- Detection therefore follows the unchanged contract: no DSPARK-specific detector logic, single and dual key alike.
- Draft-side keyed sampling would raise acceptance, but it needs the selector inside DSPARK's folded draft graph and a cropped-vocabulary hash contract. It is left as follow-up given the measured cost below.

**Evidence** (DeepSeek-V4.1-Flash, 8×H200, TP8/EP8, DSPARK block size 5):
- Detection: 40 essays × 512 tokens, temperature 1.0, top-p 0.95. DSPARK median request z is 2.73 (16/40 at p < 1e-3) against 3.06 (18/40) without speculation on the same prompts; wrong key z 0.91. OFF: median z 0.21, 0/40.
- GSM8K-100 (temperature 1.0, top-p 0.95): 99% with 100% stop rate, both watermarked and not, 0 truncated, 0 errors.
- Throughput: bench_serving random 1024/512, c8, 100 prompts, temperature 0.8, top-p 0.95, top-k 20, six reps over two launches: TPOT +3.73%, output throughput −2.25%, accept length −3.27%.

**Also fixes** an EAGLE/NEXTN regression (#44199): the fused verify-commit path (#41175) skipped the watermark ring append, so watermarked EAGLE3 output on main is undetectable. On Qwen3-8B with EAGLE3 3/1/4, 0/40 requests reach p < 1e-3 before the fix and 40/40 after; tree 5/8/32 is also 40/40.

**Tests:**
- CUDA watermark selector/state suites, plus a DSPARK chain case. The case checks that rejection-sampling accept, with and without block verification, emits the forced tokens, and that the committed ring and context history equal those of non-speculative decode (22 passed total).
- Endpoint e2e `test_watermark.py` (5 passed).

Not covered: DSPARK with DP attention or PD disaggregation (PD stays rejected by validation). DFLASH stays rejected; its chain can reuse `force_speculative_chain` in a later PR.
