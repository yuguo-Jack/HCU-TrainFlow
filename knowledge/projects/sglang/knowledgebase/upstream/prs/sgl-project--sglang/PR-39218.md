## Motivation

The Rust `/v1/chat/completions` handler currently serializes every already-typed request message into a recursive `serde_json::Value` tree, scans the tree for unsupported media keys, and then discards it. Text-only requests therefore allocate, copy, and JSON-escape the full prompt a second time before template rendering and tokenization.

## Modifications

- Inspect the typed Dynamo message and content-part enums directly instead of building an intermediate JSON tree.
- Preserve the existing behavior for user and tool image, video, audio URL, and input-audio parts.
- Keep assistant audio references and media-like words inside ordinary text accepted, matching the existing key-based scan.
- Match all relevant enums exhaustively so a future dependency variant addition fails compilation instead of silently bypassing validation.

## Accuracy Tests

- Exact decision parity across the paired performance portfolio: **54/54 pairs** matched.
- Focused typed-versus-Value fixtures cover every currently reachable message and media content-part variant.
- The dependency's currently unsupported `file` content variant still fails request deserialization before handler validation.
- `cargo test --locked -p sglang-server --lib`: **266 passed, 0 failed**.

## Speed Tests and Profiling

The measured region repeatedly invokes each arm's exact production media predicate over pre-built typed messages; fixture construction and request deserialization are outside timing.
