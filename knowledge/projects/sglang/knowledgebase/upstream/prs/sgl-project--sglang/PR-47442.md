## Motivation

With the DiT offloaded to CPU, Cosmos3 can return a different image or video than with the DiT resident, for the same request and seed.

`Cosmos3OmniTransformer.post_load_weights` builds the RoPE inv_freq table on the DiT's device, and only when the table is on meta; otherwise it keeps the one the constructor built on CPU. With `--dit-cpu-offload` or `--dit-layerwise-offload` the DiT is still on CPU at that point, so the table is computed on CPU. CPU and CUDA `pow` function round 5 of Edge's 64 entries one ulp apart (also similar for Nano and Super). The resident path and original NVIDIA's cosmos code (https://github.com/NVIDIA/cosmos-framework) compute it on CUDA.

Nobody noticed this problem because the offloaded output still looks fine, just a different render of the same scene, and the difference only happens at larger token positions. The Cosmos 3 GPU tests also run resident only.

I found this while optimizing Cosmos 3 on DGX Spark (SGLang enables CPU offloading by default when serving Cosmos 3). Since Spark has unified memory, so I ran the experiments below on a 4090, which has separate VRAM and system RAM like most machines.

## Modifications

Always compute `inv_freq` on `get_local_torch_device()`, then move it to the DiT's device. It stays float32 and non-persistent. On the normal meta-to-GPU load the values are the same as before.

- JackZeng0208 · comment · 2026-11-03T09:01:14Z · [source](https://github.com/sgl-project/sglang/pull/47442#issuecomment-6599491304)

@rwang5203 mentioned to me that the previous code adds 58 ms to the Edge DiT load with `--dit-cpu-offload`. With offload, `post_load_weights` was the first caller of the CUDA `pow` and reciprocal kernels, so it paid their lazy module load (~14 ms and ~4-7 ms). main never loads them. Building the table on CPU avoids that but changes the output again.

The new commit (https://github.com/sgl-project/sglang/pull/47442/changes/b3775d740bfeca64f2690898df40b08da09a0b55) use `torch.logspace` on CUDA when `head_dim` is a power of two (128 for all Cosmos 3 models). CUDA `logspace` calls the same `pow`, and with a power-of-two `head_dim` the exponents are exact in FP32, so the table is bit exact. `logspace` shares its kernel module with `arange`, which the forward loads anyway. The reciprocal runs on the DiT's device, and CPU and CUDA round it the same. Other cases keep the original code.

`post_load_weights` on a 4090, Cosmos 3 Edge:

| | main | previous (without the new commit) | now |
|-|-|-|-|
| resident | 32.8 ms | 32.7 ms | 9.4 ms |
| `--dit-cpu-offload` | 5.0 ms | 30.7 ms | 6.7 ms |
| `--dit-layerwise-offload` | 2.6 ms | 29.6 ms | 4.4 ms |

Over 20 paired fresh starts per mode, DiT load matches main (offload -0.5 ms, 95% CI [-8.5, +7.7]; layerwise median +1.4 ms). The ~1 ms left is the `arange` module load that main does in its warmup request, just moved earlier. Outputs are bit exact to main branch in all three modes, and request latency is unchanged.
