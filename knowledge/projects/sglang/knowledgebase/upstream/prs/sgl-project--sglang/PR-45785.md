# [Fix] scheduler: Publish KV metrics when idle

[Upstream PR](https://github.com/sgl-project/sglang/pull/45785) · state: closed · merged: True

## Original PR description

## Motivation

When the scheduler becomes idle, it refreshes its local and Prometheus statistics without publishing `KvMetrics`. Consumers such as Dynamo can retain the last busy-batch KV usage and continue rejecting requests after the engine is idle.

## Modifications

- Publish refreshed KV metrics from `_maybe_log_idle_metrics()`, preserving the existing metrics gate and idle reporting interval.
- Add regression coverage for idle updates in regular, prefill, and decode modes, including nonzero remaining KV usage, rate limiting, and disabled metrics.

## Accuracy Tests

- All 54 related CPU unit tests pass. The added regression tests fail without the fix.
- Real-GPU Qwen3-0.6B 1P1D validation with a 60% KV threshold: the baseline completes the first request, then rejects three requests while actual prefill KV usage is 0% and reported usage remains 79%. With the fix, all four requests complete and idle KV metrics return to 0%.
- Three additional busy/idle cycles confirm that genuine busy-worker rejection still works and admission recovers after idle. Every successful request generates 256 tokens.

**[major] New idle KV test uses stale PD queue fixtures and fails** (AI review, round 1)

`test_idle_publishes_refreshed_kv_metrics` loops over every `DisaggregationMode`, but its scheduler fixture does not match current `main`:

- **PREFILL:** #43902 renamed `disagg_prefill_inflight_queue` to `disagg_prefill_transfer_queue`. `_maybe_log_idle_metrics` now reads the new name, so this subtest raises `AttributeError: 'types.SimpleNamespace' object has no attribute 'disagg_prefill_transfer_queue'`. That is the error in `base-a-test-cpu (4)`.
- **DECODE:** `_update_decode_queue_stats` (added in #45970) calls `disagg_decode_prealloc_queue.pre_allocated_token_counts()` and reads `pool_stats.full_capacity` / `is_hybrid_swa`. The prealloc stub here has only `queue`. The per-subtest `get_pool_stats` lambda (around lines 1070-1076) returns an object without `full_capacity`. So DECODE will also fail once PREFILL passes.

Fix: rename the prefill queue attribute and stub `pre_allocated_token_counts`. Also add `full_capacity=1, is_hybrid_swa=False` to the `SimpleNamespace` returned by the per-subtest `get_pool_stats`.

```suggestion
        self.scheduler.disagg_prefill_bootstrap_queue = types.SimpleNamespace(queue=[])
        self.scheduler.disagg_prefill_transfer_queue = []
        self.scheduler.disagg_decode_prealloc_queue = types.SimpleNamespace(
            queue=[], pre_allocated_token_counts=lambda: (0, 0)
        )
        self.scheduler.disagg_decode_transfer_queue = types.SimpleNamespace(
            queue=[], num_pending_deferred_releases=lambda: 0
        )
```
