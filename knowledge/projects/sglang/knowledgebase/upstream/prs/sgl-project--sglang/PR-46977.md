## Motivation

Capacity decisions are spread across allocator policies and scheduler state-slot bookkeeping, making it difficult to keep admission consistent with allocation.

## Changes

Price capacity from host-side band snapshots, invalidate cached snapshots when allocator state changes, and use a shared allocation path. Consolidate prefill budgeting and state-slot reservations without changing the existing chain-specific admission rules.

Run the full seeded and corner-state pricing matrix in extra-a while retaining fast capacity and layout regressions in base.

## Validation

Pre-rebase cleanup validation: the complete pricing property file passed **3 tests on 1×H200** (PyTorch 2.14.1, CUDA 13). This validates the unchanged test bodies; the registration now selects extra-a. Kernel-library versions were not recorded for this run. No tests were rerun after the rebase.

Historical validation through `655d6c5605`:
- Four-chain replay: **0 divergences**; admission: **4,608 decisions, 0 differences**, also under sync-debug.
- Pricing properties: **3 tests / 942 subtests passed**; planted pricing/memo defects were detected.
- TP1 H200 A/B (PyTorch 2.14.1, FlashInfer 0.7.2): gpt-oss-120b and Qwen3.8-27B both scored **97.0% before/after** on GSM8K-200; throughput changed **+0.9% / +0.2%**.

Separate CPU review matched **320,000 pricing queries** and **270,000 budget observations**. GPU benchmarks were not rerun on this rebased head.
