# [Sampling] Reject logit_bias / repetition_penalty values that overflow the sampler

[Upstream PR](https://github.com/sgl-project/sglang/pull/41734) · state: closed · merged: False

## Original PR description

## Motivation

`SamplingParams.verify()` checks `logit_bias` keys but not values. The scheduler writes each value into a float32 tensor while building the batch, so a value beyond float32 range (e.g. `1e39`) raises inside the scheduler loop and takes the server down with every request on it. NaN / Inf / non-numeric values also pass. A bias that fits in float32 can still overflow once the sampler divides logits by the temperature (e.g. `3.4e38` at temperature 0.5), producing NaN probabilities that make `torch.multinomial` raise in the scheduler (device-side assert on GPU). A tiny `repetition_penalty` such as `1e-45` does the same.

## Modifications

- `verify()` rejects `logit_bias` values unless they are finite numbers with `|value| <= 1e30`, and `repetition_penalty` outside `[1e-6, 2]`. These requests now get a 400 before reaching the scheduler. Large negative biases used to ban tokens (e.g. `-1e9`) stay valid.
- Tests in `test/registered/unit/sampling/test_sampling_params.py`.

Relationship to open PRs: #31866 validates `logit_bias` against the OpenAI `[-100, 100]` range, which rejects values that are accepted and handled correctly today, and does not bound `repetition_penalty`.
