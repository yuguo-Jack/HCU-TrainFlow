# [Fix] dflash: Apply the muP logit multiplier in DFlash2 and Domino draft heads

[Upstream PR](https://github.com/sgl-project/sglang/pull/47311) · state: open · merged: False

## Original PR description

## Motivation

muP targets such as Inkling declare `logits_mup_width_multiplier` (m = 24 for Inkling) and serve logits as `(h / m) @ W.T` (`models/inkling.py`). Draft trainers fold the same `1/m` into the borrowed target head, so drafts learn against `(h / m) @ W.T`.

DSpark already serves this way: `dspark_worker_v2` reads m from the target `hf_text_config`, and `compute_base_logits` divides the draft hidden by m. The DFlash v2 worker did not do this for two draft families:

- **DFlash2 selector.** `compute_candidates` projected the unscaled hidden through the target `lm_head`. The top-k candidate ids are unchanged, because top-k is invariant to a positive scale. The unary logits passed to the selector, however, were m× larger than in training, so the unary/pairwise balance and the sampling temperature no longer matched the trained selector.
- **Domino.** `domino_greedy_rollout` adds base logits (`z @ W.T`) and learned correction logits. With an m× larger base term, the correction is mostly drowned out. In a CPU reproduction with m = 24, 19–36 of 45 greedy proposals changed.

DFlash v1 uses argmax only, so a positive scale does not change it. Targets without the field are not affected.

## Modifications

- **`DFlashWorkerV2.__init__`** sets `draft_model.logits_mup_width_multiplier` from the target `hf_text_config`, following the same contract as DSpark. This happens before `init_cuda_graphs`, so graph capture and replay both see the value.
- **`DFlash2DraftModel.compute_candidates`** divides the hidden by m before `candidate_topk`.
- **`domino_greedy_rollout`** gains a `logits_mup_width_multiplier` kwarg and divides only the base-logit input. The correction path keeps the unscaled draft hidden, which matches how the draft was trained. Both the CUDA-graph `_DominoDraftSampler` and the eager call site pass the value.
- **Tests:**
  - `test_dflash_logits.py`: a new test checks that the selector's candidates and unary logits equal `topk((h / m) @ W.T)` for m ∈ {None, 24}.
  - `test_dflash_domino.py` (CUDA): a new test checks that dividing the hidden by m = 32 is bitwise equal to folding `W / 32` into the head, for pool sizes 0 and 5. The sampler replay test now also runs with the multiplier set.

Open question for reviewers: LiLiCorr also applies log_softmax to target-head logits. I left it unchanged because I could not confirm whether its training folds m.

Companion training-side PR (SpecForge teacher/head logit transforms): sgl-project/SpecForge#1050

## Accuracy Tests

- `test/registered/unit/spec/test_dflash_logits.py`: 22 passed on CPU. The new muP test fails if the fix is reverted.
- The equivalence asserted by the new Domino test (divided hidden equals folded head, bitwise, for m = 32) was reproduced on CPU. The CUDA test file itself has not been run yet.
- Not yet measured: end-to-end acceptance length for DFlash2 and Domino on an Inkling target. That needs a GPU run.

## Speed Tests and Profiling

The change adds one elementwise division of the `[N, H]` draft hidden, and only for muP targets. Nothing changes for other targets.
