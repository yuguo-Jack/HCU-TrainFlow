# [Feat] hicache: Support DeepSeek V4 multi-pool host dedup

[Upstream PR](https://github.com/sgl-project/sglang/pull/45173) · state: open · merged: False

## Original PR description

> Part of the HiCache MLA host-dedup series (see umbrella #45177). This is `[5/N]`. Depends on `[4/N]` (#45168 — `file` L3 for broadcast-mode dedup), which stacks on `[3/N]` (#45141 — L2 dedup **and** the shared-CPU-read path), `[2/N]` (#43798), and `[1/N]` (#43795). The shared-CPU-read extension for V4 is delivered in #45177.

## Motivation

V4 spreads KV, indexer, RoPE, and compressed state across multiple pools with different page sizes and layer mappings. Plain MLA dedup is not enough to restore all content, and allocating per pool separately would double-charge the same host budget.

## Modifications

- Build owner/dummy mirrors for duplicated SWA, C4/C128 KV, indexer, RoPE, FP4 data/scale, and compressed state; independent draft is really allocated, packed draft is rejected.
- Restore by each pool's physical position and the global layer mapping, preserving unselected regions of partial C4 pages; unsupported formats error explicitly.
- Charge the host budget by cumulative physical bytes across all pools; dummies carry no payload, and independent state is counted separately.

Shared-CPU-read mode for V4 (`--mla-hicache-host-dedup-mode shared`) is added in #45177; this PR keeps broadcast as the default and only path. V4 and V4.1 are validated with their own weights; the broadcast-only layer-wise flag is not enabled here.

## Accuracy Tests

Validation scope: the component totals and model results below come from earlier integrated builds. V4/V4.1 shared-read coverage, including model-specific slow-reader, cancellation and reuse checks, belongs to #45177; this PR adds broadcast-mode model support. These historical results are separate from regression checks on the rebased branch.

Component checks: **108 passed, 1 skipped, 94 sub-checks passed**, covering multi-pool, partial pages, mapping, budget, and failure cleanup. In the latest TP8 no-dedup / broadcast groups, each model passes **16 full known answers** and **8 real L2 restores** per group; text, full token IDs, and stop states are identical. A dual-GPU test additionally covers slow layer, slow reader, cancellation, and reuse.

## Speed Tests and Profiling

For the broadcast configuration covered here, V4 TTFT is about 3.7% higher than the mean of its two no-dedup baselines; V4.1 is about 0.47% lower in these samples. The independent-repeat row without a broadcast measurement belongs to the shared-read comparison in #45177. Neither result establishes a universal speedup.

Within each model: same 8×H20-3e node, TP8, PyTorch 2.14.1+cu130, kernel 0.4.9, FlashInfer 0.7.0.post1. L1/context = 4096, host ratio = 32, chunked prefill = 512, max running = 4, graph disabled. V4.1 uses EP8, `--moe-a2a-backend none --fp8-gemm-backend triton` across all groups.

Community `bench_multiturn.py`, 16 sessions of 2048 tokens, sub-question length 80, output 16, concurrency 1, 4 req/s, seed 1; each group warms up, formal samples take the median restore-round average TTFT (ms).

| Model / batch | No dedup (before) | Broadcast | No dedup (after) |
| --- | ---: | ---: | ---: |
| V4 Flash, first round ×5 | 282.74 | 293.69 | 283.51 |
| V4 Flash, independent repeat 2/5/3 | 290.43 | — | 286.16 |

### Repro

Each mode launches an independent server; stop the previous group cleanly before running the next. V4 Flash uses its own weights; V4.1 Flash uses its own weights plus the EP8/backend args in every mode. `MODE` is `nodup` or `broadcast` here (`shared` is in #45177):

```bash
export OMP_NUM_THREADS=4
export NCCL_NVLS_ENABLE=0
export SGLANG_JIT_DEEPGEMM_PRECOMPILE=0

MODEL=/path/to/DeepSeek-V4-Flash-0731
PORT=30000
MODE=nodup
MODEL_ARGS=()
## For V4.1 Flash, use these settings in every mode:
## MODEL=/path/to/DeepSeek-V4.1-Flash
## MODEL_ARGS=(--ep-size 8 --moe-a2a-backend none --fp8-gemm-backend triton)

DEDUP_ARGS=()
case "$MODE" in
  nodup) ;;
  broadcast)
    DEDUP_ARGS=(--enable-mla-hicache-host-dedup
                --mla-hicache-host-dedup-mode "$MODE") ;;
  *) echo "MODE must be nodup or broadcast" >&2; exit 1 ;;
esac

python -u -m sglang.launch_server \
  --model-path "$MODEL" --tp-size 8 "${MODEL_ARGS[@]}" \
  --host 127.0.0.1 --port "$PORT" --trust-remote-code \
  --weight-loader-prefetch-checkpoints --enable-cache-report --enable-metrics \
  --mem-fraction-static 0.85 --max-total-tokens 4096 \
  --context-length 4096 --max-running-requests 4 \
  --chunked-prefill-size 512 --disable-cuda-graph \
  --enable-hierarchical-cache --hicache-ratio 32 \
  --hicache-write-policy write_through --hicache-io-backend direct \
  --hicache-mem-layout page_first_direct --random-seed 42 \
  --swa-full-tokens-ratio 1.0 "${DEDUP_ARGS[@]}"
```

Generate the 64-session dataset once (reused by all modes; the benchmark selects 16 by seed 1):

```bash
python - <<'PYDATA'
import json

conversations = []
for index in range(64):
    prompt = (
        f"Document number {index}. Describe the sequence for task {index}. "
        + f"In task {index}, the river crosses the stone bridge and the team records each result. "
        * 120
    )
    conversations.append({
        "conversations": [
            {"from": "human", "value": prompt},
            {"from": "gpt", "value": f"Record the result for task {index}."},
        ]
    })
with open("public-conversations-64.json", "w", encoding="utf-8") as file:
    file.write(json.dumps(conversations, ensure_ascii=False) + "\n")
PYDATA
```

Run in a second terminal. `TRIAL=0` is warmup and is excluded from the median. Use a fresh results dir per group:

```bash
MODEL=/path/to/DeepSeek-V4-Flash-0731
PORT=30000
RUN=nodup-before  # Other runs: broadcast, nodup-after.
REPEATS=5         # V4.1 uses 3, with runs nodup, broadcast.
mkdir "results-$RUN"

for ((TRIAL=0; TRIAL<=REPEATS; TRIAL++)); do
  curl --fail --silent "http://127.0.0.1:$PORT/metrics" \
    > "results-$RUN/metrics-$TRIAL-before.prom"
  python benchmark/hicache/bench_multiturn.py \
    --host 127.0.0.1 --port "$PORT" --model-path "$MODEL" \
    --dataset-path public-conversations-64.json \
    --num-clients 16 --num-rounds 2 --request-length 2048 \
    --sub-question-input-length 80 --output-length 16 \
    --max-parallel 1 --request-rate 4 --distribution uniform \
    --enable-round-barrier --ready-queue-policy fifo \
    --disable-auto-run --seed 1 \
    --log-file "results-$RUN/benchmark-$TRIAL.jsonl" \
    --tag "$RUN-$TRIAL"
  curl --fail --silent "http://127.0.0.1:$PORT/metrics" \
    > "results-$RUN/metrics-$TRIAL-after.prom"
done
```

Compare `round.round_1.average_ttft` for formal samples. The before/after `/metrics` reads are outside benchmark timing; use the `sglang:cached_tokens_total{cache_source="host"}` delta to verify restore volume, and check each TP series' `sglang:prefill_effective_tokens_total{mode="device_hit"}` separately — do not simply sum TP metrics (double counting).
