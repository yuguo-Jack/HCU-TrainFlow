# [Perf] [AMD] diffusion: Add opt-in MXFP8 attention on gfx1250 via aiter fmha_fwd_mxfp8_asm

[Upstream PR](https://github.com/sgl-project/sglang/pull/44649) · state: open · merged: False

## Original PR description

## Motivation

**What goes wrong**
Self-attention dominates Wan2.2 A14B denoise time on gfx1250 (MI450): at 90000 tokens one BF16 FMHA call takes 224 ms. `SGLANG_DIFFUSION_AITER_FP8_ATTN=1` does not help there. It per-tensor-quantizes q/k/v for a gfx950-only FP8 kernel, which gfx1250 does not ship, so it falls back to BF16 and only adds overhead.

**Where it shows up**
gfx1250 with `SGLANG_USE_AITER=1`, `--attention-backend aiter` and `SGLANG_DIFFUSION_AITER_FP8_ATTN=1`, for non-causal MHA with head_dim 128 (Wan2.2 self- and cross-attention). With the flag off, which is the default, nothing changes on any device, and other GPUs never reach the new path.

**How to fix**
When the opt-in flag is set on gfx1250, quantize q/k/v to MXFP8 with one fused Triton pass each, then call aiter's `fmha_fwd_mxfp8_asm`. k/v are zero-padded to the kernel's multiple of 128, and the softmax denominator is corrected exactly from the returned LSE. The call is kept out of torch.compile, because Inductor cannot functionalize the ASM op.

## Modifications

- New `runtime/layers/attention/backends/aiter_mxfp8.py`:
  - `_qk_quant_kernel` / `_v_quant_kernel` (Triton): bf16 bshd -> e4m3 in bhsd memory, with e8m0 scales per 32 elements (along head_dim for q/k, along seq for v), written directly in the ASM kernel's tiled scale layout. The layout mirrors aiter `op_tests/test_fmha_fwd_mxfp8_asm.py`.
  - `mxfp8_attention`: pads k/v to a multiple of 128 with zeros. Each zero key adds exactly exp(0) = 1 to the denominator and nothing to the numerator, so the output is rescaled in place by `1 / (1 - num_pad * exp(-lse))`. It is decorated with `@torch.compiler.disable`; without it, a compiled DiT block fails with `InductorError: auto_functionalized_v2 was not removed`.
  - `can_use_mxfp8_attention`: bf16, head_dim 128, MHA, non-causal, unit last-dim stride.
- `backends/aiter.py`: take the MXFP8 path first when `SGLANG_DIFFUSION_AITER_FP8_ATTN=1`, gfx1250, dropout 0 and the shape is eligible; otherwise unchanged.
- `platforms/aiter.py`: add `USE_AITER_GFX1250` (the same line as #44671, so whichever lands first, the other rebases cleanly).
- New `test/registered/unit/multimodal_gen/test_aiter_mxfp8_attention.py` (gfx1250 only; skipped elsewhere):
  - `test_matches_fp32_reference_with_and_without_kv_padding`: cosine > 0.995 against fp32 SDPA, for 1000 keys (padded to 1024, exercises the LSE correction) and 512 keys (no padding).
  - `test_runs_inside_an_inductor_compiled_function`: a `torch.compile`d function that calls `mxfp8_attention` matches eager exactly. It fails with the Inductor error above when the decorator is removed.

## Accuracy Tests

Kernel level, random bf16 inputs vs the BF16 FMHA:

| Sq x Sk x H | k/v padded | cosine vs BF16 | max abs diff |
|---|---|---|---|
| 1000 x 1000 x 4 | yes (+24) | 0.99863 | 0.027 |
| 4000 x 512 x 8 | no | 0.99863 | 0.055 |
| 90000 x 90000 x 40 | yes (+112) | 0.99849 | 0.0045 |

The padded cases match the unpadded case, so the LSE correction is exact.

End to end (Wan2.2-T2V-A14B, same seed, settings below): the video is clean and coherent in every run (no black or noisy frames), but the composition visibly shifts vs BF16 (PSNR 15.3 dB vs the BF16 run): the cat's pose and coat color change. Three MXFP8 runs produced identical videos. This is why the path stays opt-in under the existing FP8 flag.

Unit tests on MI450 (gfx1250): `test_aiter_mxfp8_attention.py` 2/2 pass; with `@torch.compiler.disable` removed, the compile test fails with `auto_functionalized_v2 was not removed`.

## Benchmarking and Profiling

Setup: Wan2.2-T2V-A14B-Diffusers, MI450 (gfx1250), 1280x720, 193 frames (90000 tokens), 8 steps, seed 42, 2 GPUs with `--enable-cfg-parallel`, `--attention-backend aiter`, `--enable-torch-compile false`, `SGLANG_USE_ROCM_AITER_TGEMM=1`. Timing is the "Pixel data generated successfully" line. Runs were sequential with nothing else on those GPUs. Both columns use aiter with ROCm/aiter#6629, which is needed for a correct TGEMM output at this size.

| Config | Runs (s) | Mean (s) | vs baseline |
|---|---|---|---|
| Baseline (flag off) | 168.72, 168.09 | 168.4 | - |
| This PR, `SGLANG_DIFFUSION_AITER_FP8_ATTN=1` | 123.61, 122.38, 121.71 | 122.6 | -27.2% (1.37x) |

With torch.compile on (1 GPU, `--regional-compile`, `SGLANG_TORCH_COMPILE_MODE=max-autotune-no-cudagraphs`), the flag measured 217.7 s -> 127.6 s (-41%). Those runs also carried the #44648 GEMM routing, which on its own measured within noise.

Attention kernel at S=90000, H=40, D=128 (quantization and pad correction included): 224.1 ms BF16 FMHA -> 95.8 ms MXFP8 (2.34x).
