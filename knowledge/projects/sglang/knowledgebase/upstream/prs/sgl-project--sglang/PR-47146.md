# [Fix] dsv4: Capture the replay tail thread-locally while serving

[Upstream PR](https://github.com/sgl-project/sglang/pull/47146) · state: closed · merged: True

## Original PR description

- `RowBucketGraphRunner` captures the decoder SWA replay tail the first time a bucket is used, while serving. That capture used the default `global` capture mode, so a CUDA call from any other thread during it fails with `CUDA_ERROR_STREAM_CAPTURE_UNSUPPORTED`. With the external linker on, its load and offload threads call `event.synchronize()` at any time, and the server crashed at the first replay-tail capture. Bounded replay is on by default for DeepSeek-V4.1 on CUDA, so DeepSeek-V4.1 with the linker is exposed whenever linker traffic overlaps those first captures.
- The capture now uses `thread_local` mode, as the other captures taken while serving already do (metadata glue graph, DSpark sampling, EAGLE post-verify). The capture runs on its own stream, which no other thread uses.

Tested on one GB300 node with DeepSeek-V4.1-Flash TP2, DSpark, `--enable-decoder-swa-bounded-replay` and the Mooncake linker: the server crashed at the first replay-tail capture without the change, and every launch with it served linker loads without errors.
