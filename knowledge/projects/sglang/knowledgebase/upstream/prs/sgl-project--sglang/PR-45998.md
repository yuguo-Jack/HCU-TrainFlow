# [Fix] dumper: evaluate filters with a safe AST evaluator (no eval RCE)

[Upstream PR](https://github.com/sgl-project/sglang/pull/45998) · state: open · merged: False

## Original PR description

## Motivation

Fixes #44188.

`/dumper/configure` accepts a `filter` string that was evaluated with `eval()` while exposing `re.search` / `re.match`. Those function objects keep `__globals__`, so a client that can reach the dumper control route can import modules and run arbitrary Python in the scheduler process when `DUMPER_SERVER_PORT=reuse`.

## Changes

- Replace `eval()` with a restricted AST walker that only allows constants, names, comparisons, boolean/arithmetic ops, lists/tuples, subscripting, and calls to an allowlisted set of helpers (`search`, `match`, `len`, `abs`, `min`, `max`, `sum`, `any`, `all`).
- Block attribute access in filter expressions entirely, and wrap the regex helpers so attribute access cannot reach `__globals__` even if that restriction is relaxed later.
- Keep `SyntaxError` behavior for invalid expressions so existing syntax-error tests stay green.
- Add regression tests for the known escape payloads from #44188, and update the undefined-helper test to expect the stricter `ValueError`.

Legitimate filters used in tests and docs (`layer_id == 0`, `'keep' in name`, `search(r'attn|mlp', name)`, etc.) continue to work.
