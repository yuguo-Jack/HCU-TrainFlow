# [Perf] dsv41: Build the MegaGate row masks once per forward

[Upstream PR](https://github.com/sgl-project/sglang/pull/46071) · state: closed · merged: True

## Original PR description

## Motivation
With MegaGate on (`SGLANG_OPT_DEEPGEMM_MEGA_GATE=1`), `run_mega_gate` rebuilds the valid-row mask (`arange < num_token_non_padded`) and the image-token mask (`input_ids == image_token_id`) in every MoE layer, though both depend only on the batch. In DeepSeek-V4.1-Flash decode this is three small kernels per gate call, serialized ahead of the gate on the MoE stream, in every layer of every step.

## Modifications
- `mega_gate.py`: `mega_gate_forward_scope(forward_batch)` installs a per-forward dict on `forward_batch`; `_gate_row_masks` builds the two masks on the first MoE layer and returns them to the rest (keyed by row count and the identity of the inputs). Under CUDA graphs the capture records one build.
- `mega_moe.py`: pass `forward_batch` to `run_mega_gate`.
- `deepseek_v4.py`, `deepseek_v4_dspark.py`: wrap `forward` in the scope.

No behavior change when MegaGate is off.

## Accuracy Tests
GSM8K (`sglang.test.run_eval`, 5-shot, 1,314 examples, temperature 0, thinking off), DeepSeek-V4.1-Flash, DP attention + EP 8, MegaGate + `SGLANG_DSV4_KV_LAYOUT=v41_new`: same score before and after.

## Speed Tests and Profiling
Decode, DeepSeek-V4.1-Flash, DP attention + EP 8 on GB300, MegaGate + `v41_new`, 8 to 256 running requests per rank: 0.25-0.35 ms less per step at every batch size (1.1-2.3%), from the server's `Decode batch` lines. In a GPU trace, the arange / int compare / int64 compare launches ahead of the gate go from one set per MoE layer to one per forward.
