# [sgl-router] Policy reorg 4/N: affinity store, session-aware and sticky policies

[Upstream PR](https://github.com/sgl-project/sglang/pull/40086) · state: closed · merged: False

## Original PR description

Stacked on the 3/N core PR. Still built beside the current path; nothing calls it yet.

## Modifications

- `policies/state/affinity_store.rs`: scoped session / routing-key bindings with idle expiry. `bound()` returns a binding only while its engine is in the supplied set; `bind()` lets a concurrent binding that is still in-set win, so racing first touches converge on one engine.
- `policy_reorg/session_aware.rs`: admitted in-set binding wins (`session_primary`); a rejected binding is kept and the request falls back (`session_admission_fallback`); a new session binds to a power-of-two choice among admitted engines (`assigned`); keyless requests fall back without binding (`no_session`). `HitRequired` never falls back or binds.
- `policy_reorg/sticky.rs`: same shape keyed by routing key with the configured fallback policy (built with `AllowAll`; the sticky policy applies admission once) and the existing `StickyOutcome` metrics.
- `PickRequest` gains `affinity_enabled` (for global-preserve) and `affinity_key()`; `build_policy` takes `PolicyDependencies { metrics, affinity }`.

Dropped per the design: primary/backup pairs, `stable_pair`, and the soft-mode pressure escape. Config rejection for those lands with the removal PR.
