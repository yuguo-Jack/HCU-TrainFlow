# [Feature] Support GLM-5.3-Flash PD disaggregation with MTP

[Upstream PR](https://github.com/sgl-project/sglang/pull/45105) · state: closed · merged: False

## Original PR description

## Motivation

Closes https://github.com/flytiger-eco/sglang-for-sail/issues/95

Enable GLM-5.3-Flash prefill/decode disaggregation with MTP enabled on both endpoints, including deployments where P uses CP8TP8 and D uses TP8EP8.

The hybrid state-transfer path needs to include draft-side sparse-attention state and distinguish CP-sharded KDA state from CP-replicated auxiliary state. PPU eager draft execution also needs to rebuild metadata on the correct attention backend when batch padding changes the planned shape.

## Modifications

- Register draft DSA index-K and compression-tail buffers alongside the target buffers for hybrid DSA models.
- Assign draft index-K buffers to the draft layer-ID band and preserve layer-aware pairing in Mooncake and NIXL transfers.
- Propagate an explicit `state_shard_on_attn_cp` flag from the cache configuration to the transport layer.
- Route CP-sharded KDA state to the matching decode TP ranks in Mooncake, while retaining the existing handling of replicated auxiliary state and the default attention-TP layout.
- Allow PPU DSA multi-step eager draft metadata to be replanned after shape-changing padding.
- Use the active draft-step attention backend for that replan in `EagerRunner`, keeping metadata consistent with the backend used by the forward.
- Add regressions for draft-state registration, compression tails, target/draft layer pairing, CP-to-TP state routing, and padded PPU eager draft execution.

## Accuracy Tests

Manual correctness smoke tests were performed on PPU with Mooncake before the release-branch rebase:

| Prefill | Decode | MTP on both endpoints | Startup and chat completion |
| --- | --- | --- | --- |
| TP8 | TP8EP8 | Disabled | Passed |
| CP8TP8 | TP8EP8 | Disabled | Passed |
| TP8 | TP8EP8 | Enabled | Passed |
| CP8TP8 | TP8EP8 | Enabled | Passed |

Additional checks covered the P-to-D boundary:

- Eight prompts were tested for each MTP topology.
- The root token, draft seed, hidden state, and DSA seed matched between P and the corresponding D ranks.
- D accepted the first draft token supplied by P in all 16 requests.
- Mean acceptance length at D's first verification was 4.00 for TP-to-TP and 4.25 for CP-to-TP, including the bonus token.
- A 10,049-token chunked prompt returned the expected checksum in both MTP topologies.

These are targeted correctness smoke tests. Native distributed validation covers PPU/Mooncake; the NIXL layer-pairing change has unit-test coverage.

The rebased commit preserves the original patch according to `git range-diff`. Validation on the rebased target branch remains pending.

## Speed Tests and Profiling

Reference measurements of the pre-rebase implementation used two nodes with eight PPUs each, FP8 weights, BF16 KV cache, and EAGLE with 5 steps, topk 1, and 6 draft tokens.

Workload: input 4096, output 1500, concurrency 16, 80 requests.

| Prefill | Decode | Successful requests | Output throughput (token/s) | Mean TPOT (ms) | D-server average acceptance length |
| --- | --- | ---: | ---: | ---: | ---: |
| TP8 | TP8EP8 | 80/80 | 1965.46 | 6.78 | 5.9235 |
| CP8TP8 | TP8EP8 | 80/80 | 2049.46 | 6.79 | 5.8935 |

A matched before/after speed comparison and profiling validation on the rebased target branch are pending.
