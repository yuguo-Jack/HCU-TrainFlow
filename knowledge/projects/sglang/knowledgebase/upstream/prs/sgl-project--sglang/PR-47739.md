# [Fix] speculative: Validate adaptive policy options before startup

[Upstream PR](https://github.com/sgl-project/sglang/pull/47739) · state: open · merged: False

## Original PR description

## Motivation

An adaptive EMA config with `update_interval: 0` passes startup validation, loads the model, captures CUDA graphs, and then crashes the scheduler with `ZeroDivisionError` when verify feedback reaches the first update tick (`(batch_count - warmup_batches) % update_interval` in `adaptive_spec_params.py`). With the default warmup that is the 11th feedback batch — the crash arrives only after full startup. Non-finite EMA options (`ema_alpha` NaN/inf, hysteresis, `ceiling_coeff`) are worse in a way: the policy is left with a NaN acceptance estimate and silently never adjusts. The only validation today covers `candidate_steps`, and it accepts bools (`isinstance(True, int)` is True).

## Modifications

One commit, `python/sglang/srt/speculative/adaptive_spec_params.py`:

- Validate that the config and each slot entry are JSON objects.
- Validate the effective slot — global defaults merged with per-BS overrides — so an invalid option is caught whether it was set globally or per slot: `update_interval >= 1`, `warmup_batches >= 0`, `ema_alpha` finite and in `[0, 1]`, `up_hysteresis`/`down_hysteresis` finite, `ceiling_coeff` non-negative.
- Use `type(x) is int` / `type(x) in (int, float)` so bools are rejected where numbers are required.
- Validation happens in `_load_adaptive_config`, which runs during argument resolution — invalid policies now fail before any worker or CUDA graph is built.

## Accuracy Tests

Existing harness (`test/registered/unit/spec/test_adaptive_spec_params.py`, pure CPU, drives the real `AdaptiveSpeculativeParams` and `resolve_candidate_steps_from_config`):

- With this branch: 33 tests + 79 subtests pass — the existing suite unchanged plus the new validation tests (every invalid shape: non-object configs/slots, boolean `candidate_steps`, all invalid option values x global-vs-slot placement).
- Against unpatched main with the same test file: all 79 new subtests fail — every invalid option (including `update_interval: 0` and `ema_alpha: NaN`) is currently accepted.
- A positive test pins the effective-slot semantics: a global `update_interval: 0` overridden per-BS to `1` routes with the slot's values.

## Speed Tests and Profiling

No inference-speed impact: validation runs once at startup on the config dict; the decode hot path is untouched.
