# [FlashInfer] Persist autotune results in the autotune_v2 managed store

[Upstream PR](https://github.com/sgl-project/sglang/pull/42108) · state: closed · merged: False

## Original PR description

## Motivation

FlashInfer autotune persistence never pays off for ops that profile under a non-default measurement policy. The trtllm-gen FP4 MoE (`flashinfer::trtllm_fp4_block_scale_moe`) profiles with cold L2, and the v1 JSON files written by `save_configs` record no per-entry policy. So while tuning, `AutoTuner.search_cache` skips every file entry for that op, and every boot re-profiles it from scratch, even when the file holds the exact keys. On a B300 Kimi-K3 deployment that is about 4 minutes of startup per pod, with a fully seeded, matching cache on disk.

FlashInfer's `autotune_v2` managed store is the fix path. flashinfer-ai/flashinfer#5495 records each entry's profiling policy in that store, so a cold-L2 winner is reused on the next boot. The v1 file path stays gated by design. This PR moves sglang onto `autotune_v2` so it picks that up.

## Modifications

`python/sglang/srt/model_executor/runner/flashinfer_autotune.py`
- **One store per rank, attached once per process** (`attach_flashinfer_autotune_store`).
  - `autotune_v2` attaches its store for the whole process, and the last attach wins. Serving then reads tuned winners from that store's partition.
  - So the target, extend, draft and PCIe-IPC tuning passes all have to tune into a single store that is attached before the first of them runs.
  - Root: `$SGLANG_CACHE_DIR/flashinfer/autotune/managed/<key>/rank_tp{}_pp{}_dp{}`. FlashInfer adds its own environment namespace below it (library versions, GPU).
- **Cross-rank agreement gate rebuilt over the store** (`_agree_on_autotune_store`). Same contract as before: a store hit skips a profile, so ranks that would hit differently desync the per-profile timing all-reduce.
  - Each rank all-gathers a digest of its entries plus its FlashInfer environment. The environment picks which namespace a rank reads, so equal stores alone do not mean equal hits.
  - If the digests diverge, every rank wipes its own store, then votes again on whether the wipe worked. If any rank still has entries, every rank tunes in memory only, so the group never splits.
  - The gate runs before the store is attached, because attaching loads the store into memory.
  - Every branch is decided on gathered values, so all ranks take the same one.
- **TP groups: exclusive `flock` on each rank's store, held for the process lifetime.**
  - FlashInfer reads keys missing from its attach-time snapshot from disk on first lookup. Without the lock, a second server on the same host publishing into the same root mid-tuning could split a TP group on a hit.
  - A single rank (TP=1) takes no lock and skips the gate. It has no group to split, and FlashInfer publishes each entry atomically, so co-located TP=1 servers of one model share one store.
  - If any rank can't lock its store, every rank tunes in memory only. The failing rank logs why (held by another process, root not creatable, or `flock` unsupported).
- `SGLANG_FLASHINFER_AUTOTUNE_CACHE=0` now tunes into a fresh timestamped store instead of a timestamped JSON file (docs updated).
- The manual `load_configs` / `save_configs` dance around `autotune(True)` is gone. v2 never touches `_file_configs`, so the draft worker can no longer drop the target's loaded tactics.

`python/sglang/srt/model_executor/runner/base_runner.py`
- `warmup()` attaches the store **before** `_pre_initialize_pcie_ipc_workspace()`.
- PCIe-IPC tunes through `AutoTuner.choose_one` in its `prepare()`. Winners tuned before the attach land in the plain in-memory cache, which serving stops reading once a store is attached.

## Dependency

The startup win needs a FlashInfer release that contains flashinfer-ai/flashinfer#5495 (open and approved as of this PR). On the pinned `flashinfer_python==0.7.0.post1` this change is behavior-neutral for cold-L2 ops: they re-tune every boot, exactly as today. Default-policy ops reuse store entries just as they reused v1 file entries.

## Accuracy Tests

Not applicable. This changes where tuned tactics are persisted and when they are reused, not tactic selection.
