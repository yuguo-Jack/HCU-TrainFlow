# [Fix] function_call: Release buffered user text at stream end in InternLM, MiniCPM-5 and Hunyuan detectors

[Upstream PR](https://github.com/sgl-project/sglang/pull/41962) · state: open · merged: False

## Original PR description

## Motivation

Same loss pattern as #41909 / #41914: `InternlmDetector`, `MiniCPM5Detector`
and `HunyuanDetector` hold text back in `self._buffer` while waiting for the
closing tool-call marker. `BaseFormatDetector.finish()` returns an empty
result by default, so when the stream ends with an incomplete marker still
buffered, the held-back text is silently dropped:

```python
d = InternlmDetector()
d.parse_streaming_increment("...<|action_end|>done <|action_start|> <|plugin|>par", [])
d.finish([])  # returns empty; "done " never reaches the client
```

## Changes

Add a `finish()` override to each detector that releases only user-visible
text: prose in front of an opening marker (already streamed in the normal
case) or trailing text outside a tool-call block. A buffer that reaches the
opening marker is a truncated protocol block - the closing marker can no
longer arrive - so the block itself is dropped rather than flushed, and
markers can never leak into `normal_text`. Same rule as the Spark2.5 /
Kimi-K3 / DeepSeek-V3.2 detectors. Normal streams are unaffected:
`finish()` stays a no-op when `_buffer` is empty.

## Tests

Offline unit tests (no server, no model loading) for each detector cover:
- truncated call at stream end: the protocol block is dropped, prose before
  it has already been delivered by the streaming path;
- text before a truncated opening marker, text after a completed call, and
  truncated marker prefixes are released as normal text;
- clean stream: `finish()` returns an empty result;
- fully parsed stream: no duplication at `finish()`.

All pass locally (`pytest test/registered/unit/function_call/test_{internlm,minicpm5_detector_finish,hunyuan_detector_finish}`), ruff clean.
