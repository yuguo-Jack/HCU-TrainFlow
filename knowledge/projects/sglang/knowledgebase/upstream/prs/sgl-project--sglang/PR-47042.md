# [Perf] [AMD] aiter: Bucket decode paged-attention partitions by sequence length

[Upstream PR](https://github.com/sgl-project/sglang/pull/47042) · state: closed · merged: True

## Original PR description

## Motivation

aiter decode on the non-MLA path calls `paged_attention_ragged` with `max_num_partitions = ceil(context_len / 256)`: 512 for Llama-3.1-8B, 160 for Qwen3-8B. The main kernel's grid is `(num_seqs, max_num_partitions, num_kv_heads)` and the value is baked into every decode CUDA graph. Blocks past a sequence's length exit early, but launching and scheduling them still costs time, and at high batch the cost is no longer hidden behind real work. In the microbench below, at batch 64 / 1536 tokens P=512 costs 19.8 µs more per call than P=16 (0.63 ms per 32-layer step); at batch 256 it costs 274 µs more (+93%).

## Modifications

- `graph_variants.py`: new `SeqLenBucketGraphVariants` picks the first bucket whose limit covers `max(seq_lens_cpu)`, else the fallback. It reads only the host copy; a missing, empty or device tensor selects the fallback.
- `base_attn_backend.py`, `decode_cuda_graph_runner.py`: `AttentionBackend.get_decode_graph_variants` returns None by default; the decode runner asks the backend after the DSA / DSV4.1 factories and reuses the existing variant capture and replay code.
- `aiter_backend.py`: buckets `p16` (up to 4096 tokens) and `p128` (up to 32768), each kept only when 4x its partition count is at most `max_num_partitions`, plus `pmax` for any length. Llama gets p16 / p128 / p512, Qwen3 gets p16 / p160, models with fewer than 128 partitions get no buckets. Only plain decode with one token per request on the `paged_attention_ragged` path gets variants. Eager decode uses the same table when `spec_info` is None and `seq_lens_cpu` is present, so aiter never JIT-builds a new reduce kernel while serving. Spec decode, graphs captured without a variant, and the sync-free path without `seq_lens_cpu` keep `max_num_partitions`; an unknown capture label raises. The chosen count goes into the new `ForwardMetadata.decode_num_partitions`. Every choice keeps `partitions * 256 >= max seq_len`, since fewer partitions drop KV silently. The workspace stays sized for `max_num_partitions`.
- `environ.py`, `environment_variables.mdx`: `SGLANG_AITER_DECODE_PARTITION_BUCKETS` (default true); false disables bucketing.
- Tests: new `test_aiter_decode_partition_buckets.py` (AMD CI); `test_aiter_fp8_kv_scales_paths.py` and `test_aiter_fp8_q_unified_attention.py` add `decode_num_partitions` to the `ForwardMetadata` they build.
