# [Fix] compressed-tensors: Serve NVFP4 W4A4 linears via FP4 Marlin when --fp4-gemm-backend marlin is set on SM100

[Upstream PR](https://github.com/sgl-project/sglang/pull/44213) · state: closed · merged: True

## Original PR description

## Motivation

Fixes #43988.

With a compressed-tensors NVFP4 W4A4 checkpoint on SM100, `--fp4-gemm-backend marlin` crashes during CUDA-graph capture:

```
flashinfer.utils.BackendSupportedError: mm_fp4 does not support backend 'marlin' with capability 100
```

`_get_scheme_from_parts` returns the native `CompressedTensorsW4A4Fp4` linear whenever the capability check passes. That scheme hands the backend name straight to FlashInfer `mm_fp4`, which has no `marlin` backend. FP4 Marlin is weight-only, and #40022 already added the weight-only path (`CompressedTensorsW4A16Fp4(has_input_global_scale=True)`) for W4A4 checkpoints, but it is only taken when the capability check fails.

## Modifications

- `compressed_tensors.py`: when `--fp4-gemm-backend marlin` is set, W4A4 NVFP4 dense linears take the existing weight-only Marlin path on SM100 too, the same way ModelOpt NVFP4 honors the flag. Without the flag, SM100 still uses the native W4A4 scheme.
- The warning now names the reason for each case. For an explicit marlin request it also says that NVFP4 MoE layers follow `--moe-runner-backend` and stay W4A4.
- `test_compressed_tensors_fp4_schemes.py`: a CPU regression test for SM100 + `marlin`. It asserts that the linear gets the weight-only scheme, the MoE keeps `CompressedTensorsW4A4Nvfp4MoE`, and the warning says both. It fails on `main` and passes with this change.

## Accuracy Tests

1x NVIDIA B200 (compute capability 10.0), image `lmsysorg/sglang:dev-cu13`, `python -m sglang.launch_server --model-path <model> --tp 1 [--fp4-gemm-backend marlin]`, then `python -m sglang.test.few_shot_gsm8k --num-questions 200`.

| Model | Code | `--fp4-gemm-backend` | Result | GSM8K |
|---|---|---|---|---|
| RedHatAI/Qwen3-8B-NVFP4 | main | marlin | crashes (`BackendSupportedError`, below) | n/a |
| RedHatAI/Qwen3-8B-NVFP4 | this PR | marlin | serves, dense linears via FP4 Marlin | 0.935 |
| RedHatAI/Qwen3-8B-NVFP4 | this PR | auto (native W4A4) | serves, unchanged path | 0.905 |
| RedHatAI/Qwen3-30B-A3B-NVFP4 | this PR | marlin | serves, dense via Marlin, MoE stays W4A4 | 0.910 |

The weight-only Marlin result is in line with the native W4A4 path. 200 questions is too small to read anything into the 0.03 difference.

Note: both main and this PR were run on the image's checkout (`684fea8`). For the "this PR" rows, this commit was applied on top as a patch, because the image could not fetch from GitHub. It applies cleanly and touches only `compressed_tensors.py`, so the only difference between the before and after rows is this change.
