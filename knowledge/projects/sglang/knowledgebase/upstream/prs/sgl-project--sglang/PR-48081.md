# [Fix] disaggregation: fix HiSparse staged-spec crash under DP-attention padding

[Upstream PR](https://github.com/sgl-project/sglang/pull/48081) · state: open · merged: False

## Original PR description

## Bug

A hisparse + speculative decode engine under PD disaggregation crashes on the first multiturn traffic that goes through HiSparse staging: staged requests are released with the relay seeded by bonus tokens only, so the first draft decode after staging runs the eager path. Under uneven DP-attention batch sizes the eagerly-planned metadata then reads a page table with fewer rows than the padded topk batch and the scheduler asserts (`page_table_1.shape[0] == topk_indices.shape[0]`).

## When it happens

Mooncake PD with a hisparse + EAGLE decode engine and staging active. The pre-existing draft-state seeding (`build_disagg_draft_input`) only stashes the relay payload under overlap schedule — but PP>1 prefill forces overlap off, so exactly the topologies that stage the most (big models, e.g. GLM-5.3 FP8 at TP8 → PP2, 88.5 GB/GPU) never seed the relay. The crash then lands on the first multiturn benchmark whose sessions exceed the device tier.

## Fix

Two small pieces:

- `Scheduler._build_hisparse_decode_batch` (the staging release): with spec on, build the transferred draft state via `build_disagg_draft_input` and stash it in the relay explicitly (the helper only stashes under overlap; standalone, where the helper returns `None`, falls back to the bonus-only payload).
- `dsa_backend`: when the eager draft batch was DP-padded after this backend's metadata was planned, rebuild `page_table_1` from `req_to_token` for the padded batch (new `rebuild_padded_draft_page_table` helper). Dummy padded rows are inert — their topk is all -1.

## Verification

- Unit tests (`test/registered/unit/disaggregation/test_hisparse_staged_spec_crash.py`): the spec release seeds the full draft state (topk_p / topk_index / hidden_states / dsa_topk_indices asserted on the stashed relay payload); non-spec and standalone releases stay bonus-only; the padded rebuild maps real rows correctly and keeps its width when the planned table is wider.

- E2E (equivalent logic, deployed as an inline patch on v0.5.22- and v0.5.23-based trees; GLM-5.3 FP8 on 4x H100, prefill TP8xPP2+CP8, decode TP16+DP16 + EAGLE 3/1/4, hisparse): without the patch the first multiturn benchmark (35k x 7 turns, ~17 in flight) crashes the decode with the page-table/topk assert; with it, the full suite passes — multiturn, 8k/2k throughput, 70k shared-prefix, and 128k-context needle retrieval 5/5, zero crashes.
