# [CI] [AMD] miles: Pass CI and the SGLang source path to nightly suites

[Upstream PR](https://github.com/sgl-project/sglang/pull/48067) · state: closed · merged: True

## Original PR description

## Problem

- Miles runs its between-file process cleanup only when `CI=true`, but the AMD Miles nightly workflows do not pass `CI` into the container's suite command, so the cleanup never runs.
- `tests/e2e/long/test_qwen3_0.6B_verifiers.py` checks the Verifiers SDK in a child virtual environment. The AMD Miles nightlies give that process no SGLang source path, so it cannot import the editable SGLang install, and the test has failed every night since Oct 25 on MI35x ([Nov 2 run](https://github.com/sgl-project/sglang/actions/runs/41542027483/job/125608323462)). It fails the same way on MI30x ([Nov 3 run](https://github.com/sgl-project/sglang/actions/runs/41542033993/job/125806019821)). CUDA CI already puts the SGLang sources on `PYTHONPATH`.

## Change

- Pass `CI=true` through the existing exec helper in both AMD Miles nightly workflows.
- Add `/sgl-workspace/sglang/python` to `PYTHONPATH` in both AMD Miles nightly workflows (MI35x and MI30x).

## Validation

- On `rocm/sgl-dev:miles-rocm10-mi35x-20261102`, the original two-GPU Verifiers E2E passed with only the `PYTHONPATH` change: all three SDK cases, plus the original 12-sample rollout, group-reward, finite-logprob and one-step training checks. The CI suite reported 1/1 passed.
- With a recorder in place of Docker, the exec helper forwards `CI=true` for every matrix entry with this change and not without it. Miles' cleanup predicate turns on for isolated runs and stays off with an external Ray cluster.

Co-author-with: @JessicaJiang-123
