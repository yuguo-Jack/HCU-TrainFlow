# [Perf] RL: Keep routed-expert rows only for MoE layers

[Upstream PR](https://github.com/sgl-project/sglang/pull/47536) · state: open · merged: False

## Original PR description

## Why?

- Routed-experts capture (`--enable-return-routed-experts`, used for RL routing replay) keeps a device row and a host row per model layer (`num_hidden_layers`), but hybrid models route in only some layers.
- Nemotron 3 Ultra routes in 48 of 108 layers, so 60 of every 108 rows stay zero forever. With TP8 on two GB300 nodes and an 11.4M-token KV pool, that is 101 GiB pinned per rank, 56 GiB of it never written.
- The response pads those zero rows too: a 131k-token Ultra request sends 1188 MiB of routing (before base64), and the trainer drops the zero layers right after decoding.

## What?

- Add `NemotronHConfig.moe_layer_ids`, and `get_routed_experts_layer_ids` in `configs/model_config.py`: Nemotron-H's MoE layers, every layer for other models. The capturer and `TokenizerManager` both use it.
- Device and host caches keep one row per routed layer. `capture()` maps a layer id to its row and raises for a layer that is not routed, instead of writing a wrong row.
- **Response change, Nemotron-H only:** `meta_info["routed_experts"]` now has logical shape `[tokens, num_moe_layers, top_k]`, MoE layers in layer order. Other models are unchanged (`num_hidden_layers` rows).
- `meta_info["routed_experts_num_layers"]` reports the layer count so clients can reshape without knowing the model. The docs say which layers are returned.
- `--enable-return-routed-experts` on a model with no routed layer fails at startup with a clear error.

## Verification?

```text
Nemotron 3 Ultra (108 layers, 48 MoE, top-22), TP8, 11.4M-token KV pool

                          Before                         After
host cache per rank       108 rows/token → 101 GiB       48 rows/token → 45 GiB      (observed, internal fork)
131k-token response       [131072, 108, 22] = 1188 MiB   [131072, 48, 22] = 528 MiB  (expected)
meta_info                 routed_experts                 routed_experts + routed_experts_num_layers = 48

Qwen3 / DeepSeek / Kimi   [tokens, num_hidden_layers, top_k], unchanged; routed_experts_num_layers = num_hidden_layers
```

- Trainer side: radixark/miles#4602 reads `routed_experts_num_layers` (and falls back to every layer for older servers) and maps each Megatron MoE layer to its column.

## Test?

- `test/registered/unit/state_capturer/test_routed_experts_scattered_a2a.py::TestRoutedLayerHostStorage::test_returns_routed_layers_in_layer_order`: Nemotron-H rows come back in MoE-layer order and match an all-layer capturer's MoE columns. **Observed** passing on f378d67 ([/rerun-test](https://github.com/sgl-project/sglang/actions/runs/41389330550)).
- `test/registered/rl/test_return_routed_experts.py`: now also checks `meta_info["routed_experts_num_layers"]` on Qwen3-30B-A3B. **Observed** passing on f378d67, 8 tests on 4×H100 ([/rerun-test](https://github.com/sgl-project/sglang/actions/runs/41389342793)).
- `pre-commit run` on the changed files: **observed** passing.
- Full lint and pr-test fail only on breakages already on `main` (duplicate `tree_cache=` in `test_decode_queue_cleanup.py`, `test_scheduler_pause_generation`, `test_quark_config`).
- GPU end-to-end with Nemotron-H and routing replay through miles: **pending**.
