# [Fix] rust-server: Derive advertised host towards dist_init_addr and reject loopback on multi-node

[Upstream PR](https://github.com/sgl-project/sglang/pull/47534) · state: open · merged: False

## Original PR description

closes #47509

### why
in multi-node deployments with rust server (`SGLANG_RUST_SERVER=1`), `gather_server_endpoints()` resolved wildcard listener binds (`0.0.0.0`, `::`) via `get_local_ip_auto(fallback="127.0.0.1")`. on multi-homed or isolated cluster nodes without default routes, this can either pick an unroutable interface or fall back to loopback (`127.0.0.1`). when it fell back to loopback, it only logged a warning and published `127.0.0.1:<port>` anyway. other ranks then relayed control requests (`/flush_cache`, `/start_profile`, etc.) to `127.0.0.1`, which routed to their own local listener at the same offset rather than the target rank.

also, `_rendezvous_is_loopback` failed to recognize schemes in `dist_init_addr` like `tcp://127.0.0.1:5000` because `NetworkAddress.parse` did not strip scheme prefixes.

### what changed
1. added `get_local_ip_towards()` in `network.py` that probes a connected udp socket towards target host/port (`getsockname`, no network traffic sent).
2. in `gather_server_endpoints()`, when wildcard host is bound:
   - honors explicit `SGLANG_HOST_IP` / `HOST_IP` if set.
   - derives source ip on the interface routing towards `dist_init_addr` when set.
   - falls back to `get_local_ip_auto(fallback="127.0.0.1")`.
3. rejects loopback listener on multi-node (`nnodes > 1`) with `ValueError` when rendezvous is not loopback, preventing silent misrouting across nodes.
4. updated `NetworkAddress.parse()` to strip scheme prefixes (`tcp://`, `http://`), enabling `_rendezvous_is_loopback` to correctly parse `dist_init_addr`.
5. added unit tests covering towards probing, scheme parsing, fallback, env override, and multi-node loopback rejection.
