# fix: preserve GLM4 string ids emitted as bare scalars

[Upstream PR](https://github.com/sgl-project/sglang/pull/28114) · state: open · merged: False

## Original PR description

## Summary

- keep the raw text for string-typed GLM4 tool arguments emitted as bare scalars (123, true, null): the JSON-coerced int/bool/None hit the caller's `str()` fallback and came out as Python spellings ("True", "None") instead of the model's exact text
- the glm47 twin needs no change; its caller already falls back to the raw arg_value when the parsed value is not a string

Fixes #42133.

Reworked onto current main. The June version guarded the ast.literal_eval fallback; main has since grown strategy 2.5 (raw text for string-typed non-JSON) via #30644, which covers the underscore-grouped case, but strategies 1 and 2 still coerce an unquoted scalar for a string-typed param: json.loads("123") returns int 123 straight into a string argument. The guard now sits at both JSON-success exits: string-typed and not a string means keep the raw text. Verified locally with the extracted parser (upstream returns int 123 / bool True on the witnesses, this branch returns the raw text); the registered parser suite covers the new cases in CI since it needs the full env.
