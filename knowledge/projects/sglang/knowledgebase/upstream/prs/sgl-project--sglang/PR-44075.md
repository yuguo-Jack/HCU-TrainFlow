# [Fix] sgl-router: Resend on a closed pooled connection; add --disable-circuit-breaker

[Upstream PR](https://github.com/sgl-project/sglang/pull/44075) · state: closed · merged: True

## Original PR description

## Motivation

With one prefill and one decode worker, sgl-router fails a few requests per hour:

- SGLang closes idle keep-alive connections after 5 s, while sgl-router reuses them for up to 90 s. A request sent as the engine closes one fails before any response; with one worker per role, neither hyper nor `--retry-max-attempts` resends it, so the client gets a 502.
- Three such resets open the worker's circuit breaker, which then rejects that role's requests (502/503) while the worker is serving. It cannot be turned off, although `--cb-threshold` is documented as enabling it.

## Modifications

- Idle pooled connections expire after 3 s, and an HTTP/1.1 send that fails with a reset, broken pipe or EOF before any response is resent once to the same worker. The engine never read it, so it cannot run twice; only a failed resend reaches the breaker.
- The breaker stays on by default: under `--worker-urls` it is the only thing that takes a dead worker out of routing. New `--disable-circuit-breaker` turns it off, and `--cb-cool-down-secs` no longer requires `--cb-threshold`.
- A worker without a breaker config gets `CircuitBreaker::disabled()`, which ignores failures and reports closed; tests that rely on a breaker now configure one.
- `hyper` becomes a direct dependency (`Cargo.lock` unchanged); docs are in `REFERENCE.md`.

## Testing

- New `proxy::tests::closed_connection_is_retried_once`, against a raw HTTP/1.1 worker: a reset or EOF on the first connection is resent and returns 200 (502 without this change); a worker that closes every connection returns 502 after exactly two; one that never answers returns 504 after one.
- New `workers::registry::tests::breaker_without_config_never_opens`: a worker added without a breaker config stays routable after 10 failures (fails without this change).
- New `config::cli` tests: the breaker is on by default, and `--disable-circuit-breaker` turns it off and rejects the tuning flags.
- Passing: `cargo +nightly fmt --all -- --check`, `cargo check`, `cargo clippy -- -D warnings`, `cargo test --release --workspace -- --skip parity_matrix`.

## Benchmark (MI355X)

Same setup as #44072: DeepSeek-V4-Pro, 1 prefill + 1 decode engine with 8 DP-attention ranks each, AgentX trace replay with AIPerf, 1 h per concurrency, sgl-router built at 1e86143bf0, no `--cb-threshold`.

In the concurrency-256 run, three sends to the only prefill worker failed with `Connection reset by peer` within 0.2 ms (the keep-alive race fixed here). That opened the worker's default breaker, and the router rejected three more requests before an in-flight request to the worker succeeded and closed it:

| status | router error | cause |
|---|---|---|
| 502 | `worker circuit breaker open` | breaker |
| 503 | `breaker_open` | breaker |
| 503 | `no_prefill_workers_available` | breaker: no routable prefill worker |

- These three were 30% of the run's 10 failed requests; the other seven were the resets themselves.
- At this concurrency an in-flight success closed the breaker within milliseconds. With few requests in flight nothing closes it early, so every request for that role would get 503 for up to the 30 s cool-down (not measured).
- The reruns used `--cb-threshold 1000000` (equivalent to `--disable-circuit-breaker`) with `SGLANG_TIMEOUT_KEEP_ALIVE=300` on the engines, which removes the race from the engine side, and had no errors in 8 runs (c192–c512, two decode policies); before, every run hit the race (2–11 failed requests per hour, or an aborted warmup). The `sgl-model-gateway` arms of the same benchmark run with `--disable-circuit-breaker`.

Thanks for the rebase. One blocker came in from main after this push.

**Semantic conflict with #42674.** #42674 (native gRPC ChatComplete) merged at 05:11Z, after this PR's CI ran at 02:22Z, so CI didn't catch it. Its test `grpc_chat::stream_outcomes_reach_the_breaker_by_status` registers workers with no breaker config and expects three 500s to open the default breaker:

https://github.com/sgl-project/sglang/blob/main/experimental/sgl-router/tests/proxy/grpc_chat.rs#L241

With this PR that breaker never opens. Locally, on `81f3141a22a` merged with current main, the test fails 3/3; on main it passes 3/3. So merging as-is would turn main red.

The fix is the same change you made to the other tests:

```diff
-        registry.add_with_cb(spec, None, profile).unwrap();
+        registry
+            .add_with_cb(spec, Some(Default::default()), profile)
+            .unwrap();
```

With it, all 7 `grpc_chat` tests pass (3/3 runs), and fmt is clean. The rest of the suite on the merged tree is green, apart from the `bucket_routing` flake that main has too.

Two non-blocking notes on the default change itself:

1. Without `--cb-threshold`, nothing else sheds a dead worker on a static `--worker-urls` fleet: there is no active health check, and `--retry-max-attempts` defaults to 1. In a quick test (1 dead worker of 3, round_robin, no retries, 60 requests), this PR gives 20 client errors vs 3 with the old default. A line in the README or release notes telling static fleets to set `--cb-threshold 3` (or `--retry-max-attempts 3`) would help.
2. This makes sgl-router default to breaker-off, while sgl-model-gateway defaults to on. It matches the documented intent here, but it would be good for a maintainer to explicitly sign off on it.

### inline_comments

- ShangmingCai · comment · 2026-10-17T13:02:52Z · [source](https://github.com/sgl-project/sglang/pull/44075#discussion_r4302744802)

File: `experimental/sgl-router/src/workers/worker.rs` · line 282

I don't think we should turn the breaker off by default. It's the only thing in sgl-router that takes a dead worker out of routing: there is no active health check, and under `--worker-urls` nothing re-registers. With this change a dead worker just keeps getting its share of traffic forever.

If someone really needs the breaker off, can we add an explicit opt-out like the gateway's `--disable-circuit-breaker` and keep the default on?


- ShangmingCai · comment · 2026-10-17T13:02:52Z · [source](https://github.com/sgl-project/sglang/pull/44075#discussion_r4302744804)

File: `experimental/sgl-router/README.md` · line None

`--retry-max-attempts 3` only covers a worker that refuses connections. For a hung worker the retry only happens after `--request-timeout-secs` (300s by default), so requests stop failing but still sit there for 5 min first. In my test with retries on, about 1/3 of requests still waited the full timeout. So I don't think retries can replace the breaker here.
