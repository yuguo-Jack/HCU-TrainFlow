# [Perf] trtllm_mha: Split full-attention decode KV across CTAs at large batch (opt-in)

[Upstream PR](https://github.com/sgl-project/sglang/pull/46082) · state: closed · merged: True

## Original PR description

## Motivation

TRTLLM-GEN decode gives each (request, KV head) `max(1, SMs // (batch * kv_heads))` CTAs. Once `batch * kv_heads` exceeds half the SMs, every request-head streams its whole KV on a single CTA. In long-context batches the longest request then sets the time of every full-attention layer.

This PR splits the KV of full-attention layers across a fixed number of CTAs at large batch, in fixed-q-len decode and verify. Sliding-window layers, ragged verify and the XQA path (SM90/SM120) are unchanged.

FlashInfer has no per-call split count yet. The split is applied by scoping the SM count that `trtllm_batch_decode_with_kv_cache` reads for that one call. The number of split CTAs is capped by the workspace and the multi-CTA counter buffer.

Related: #37208 regroups mixed-length decode batches; this PR instead splits each request's KV on full-attention layers. The two compose; not yet measured together.

## How to enable

```bash
SGLANG_TRTLLM_MHA_FULL_ATTN_KV_SPLITS=8          # default 0 (off)
SGLANG_TRTLLM_MHA_FULL_ATTN_KV_SPLITS_MIN_BS=12  # default 12
```

Requires `--attention-backend trtllm_mha` on SM100.

## Performance

Muse-Spark-Open NVFP4, 4x GB300, TP4/EP4, FP8 KV cache, DFLASH with 8 draft tokens, HiCache (write-back), at most 32 running requests. Multi-turn long-context requests at concurrency 48. Each row toggles only the decode split on the same build.

| Baseline | Concurrency | Throughput per GPU (tok/s), baseline | Throughput per GPU (tok/s), this PR | Per-user decode speed, P90 (tok/s/user), baseline | Per-user decode speed, P90 (tok/s/user), this PR |
|---|---|---|---|---|---|
| No KV split (default) | 48 | 46,373 | 64,231 (+38.5%) | 41.87 | 72.05 (+72.1%) |
| Existing all-layer seq-len split, `SGLANG_TRTLLM_MHA_DECODE_SEQ_LEN_SPLITS=4` | 48 | 57,728 | 64,231 (+11.3%) | 58.91 | 72.05 (+22.3%) |

## Tests

`test/registered/unit/layers/attention/test_trtllm_mha_paged_kv.py`, 4 new CPU cases:
- the split engages only on full-attention layers, at batch >= MIN_BS, where FlashInfer would split less;
- a fixed-q-len verify launches inside the scope, sized by requests (query rows // `q_len_per_req`);
- the split CTAs stay within the workspace and counter capacity;
- the scoped SM count is restored after an error.

Accuracy, GSM8K strict match with the split: 0.9765. The split changes the attention reduction order, at rounding level only.

[by Claude Code] **Severity: perf | Confidence: Medium**

**Issue**

The split works only because FlashInfer 0.7.2's `trtllm_batch_decode_with_kv_cache` calls the module-level name `flashinfer.decode.get_device_sm_count` on every call. If a FlashInfer bump caches the SM count, reads it through another name, or moves it into C++, this patch silently stops working and the speedup is lost. The new tests replace `flashinfer` with a `SimpleNamespace`, so they cannot catch that.

**Fix**

Add a GPU case to `test/registered/attention/unittests/dense/test_trtllm_mha.py`. It should run a full-attention decode at batch >= MIN_BS with the split on, compare the output with the unsplit run, and check that the scoped SM count was read. Also add a `TODO` that links a FlashInfer issue for a per-call split argument.
