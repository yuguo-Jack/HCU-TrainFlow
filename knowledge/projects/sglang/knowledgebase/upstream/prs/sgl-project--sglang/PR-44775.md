# [Feat] profiler: Add the forward pass id to detailed step span labels

[Upstream PR](https://github.com/sgl-project/sglang/pull/44775) · state: closed · merged: True

## Original PR description

## Motivation

With detailed step annotations enabled, consecutive forward steps can produce identical `step[...]` span labels: two decode or target-verify steps with the same batch size and the same prefix-sum terms (`g_sq`, `g_sqsq`, ...) cannot be told apart in a trace. A tool that wants to pair a step span with per-forward data recorded elsewhere, such as the expert-distribution recorder, which is keyed by the model runner's `forward_pass_id`, currently has to match by shape and order, which breaks exactly when shapes repeat.

## Modifications

- `build_step_span_name` (`python/sglang/srt/utils/profile_utils.py`) gains a keyword-only `forward_id: int | None = None`. When detailed annotations are enabled and `forward_id` is given, the label ends with `forward_id=<n>`, placed after the aggregate suffix (or directly after the base label when the CPU mirrors are missing). With detailed annotations disabled the label is unchanged, so the default trace output does not change.
- `ModelRunner.forward` passes `forward_id=self.forward_pass_id`, which is the same counter the expert-distribution recorder uses for that forward. The other caller (the multi-layer draft-extend replay span) keeps the default.
- `test_detailed_annotations.py` adds one case: the same shape under two forward ids yields two distinct labels for both the target (`VERIFY`) and draft (`DRAFT`) stage, the disabled path still emits the base label, and a batch without CPU mirrors emits `step[VERIFY bs=2 forward_id=42]`.

## Accuracy Tests

Not applicable: no change to model outputs; only the profiler span label changes, and only when detailed annotations are enabled.

## Speed Tests and Profiling

Not applicable: one extra keyword argument per forward and one f-string append when detailed annotations are enabled.
