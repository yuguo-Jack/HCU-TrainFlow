# [Feat] wan-animate-2: Support the distilled variant

[Upstream PR](https://github.com/sgl-project/sglang/pull/44085) · state: open · merged: False

## Original PR description

## Motivation

Add native support for [Wan-Animate-2 Distilled](https://huggingface.co/Wan-AI/Wan2.2-Animate-2-14B-Distilled-Diffusers) (`Wan-AI/Wan2.2-Animate-2-14B-Distilled-Diffusers`), the distilled variant of the 14B character-animation model of the Wan2.2 family. Like the base checkpoint it takes a **reference image** and a **reference video** and produces a clip of the reference subject performing the reference video's motion; the distilled checkpoint does it in 10 steps at `guidance_scale` 1.0 instead of 40 steps with CFG 3.0.

Builds on #42941. The distilled checkpoint is served by the same native `WanAnimate2Pipeline`, selected automatically from the checkpoint directory, as configuration on top of the base support: `log_scale = -1.3` in the attention score modifier, 10 steps at `guidance_scale` 1.0, no CFG parallelism, DPM-Solver++ as the [official](https://github.com/Wan-Video/Wan-Animate-2) command-line implementation samples it.

## Modifications

### New
- `Wan_Animate_2_14B_Distilled_Config` (`configs/pipeline_configs/wan.py`): the DiT config with `log_scale` -1.3, the official distillation yaml value (a `log_scale` key in the checkpoint's `transformer/config.json` still wins), and `supports_cfg_parallel=False`. `Wan_Animate_2_14B_Distilled_SamplingParam` (`configs/sample/wan.py`): 10 steps, `guidance_scale` 1.0, everything else inherited from the base sampling params.
- `WanAnimate2SchedulerLoader`: the distilled checkpoint is sampled with DPM-Solver++ 2M on the Wan sigma grid, like the base checkpoint, because that is what the model authors' command-line implementation runs for both checkpoints (their distilled yaml's `flow_solver: euler` key is read by no code). The `FlowMatchEulerDiscreteScheduler` named in the distilled repo's `scheduler/scheduler_config.json` is read only by the Diffusers pipeline, which also omits the distilled `log_scale` bias. The loader builds DPM-Solver++ for the distilled config without reading that file and loads the checkpoint's `scheduler/` for the base config; it sets `component_names = []` so it stays pipeline-local, like `WanAnimate2TransformerLoader`; the existing loader-registry test covers both. On the same seed DPM-Solver++ lands 1.8 dB closer to the authors' command-line output than Euler on the shipped grid (33.2 against 31.4 dB, at the same cost): the choice matches the authors' executable implementation; it is not a quality ranking. `--scheduler-class-override` is ignored for the distilled checkpoint and one warning says so (the base checkpoint still honours it).
- Registry detectors: both repos share the `model_index.json` `_class_name`; the variant is named only by the `_class_name` of `modular_model_index.json`. The distilled detector matches `WanAnimate2DistilledModularPipeline` or a Wan-Animate-2 path whose directory name carries a `distill` token (a token in a parent directory does not count), the base detector the rest, the distilled one registered first because a directory with `model_index.json` matches both through the shared class. `--model-id Wan2.2-Animate-2-14B-Distilled-Diffusers` pins the variant explicitly.
- Cookbook page `docs/cookbook/diffusion/Wan/Wan-Animate-2.mdx`: variant table, defaults note, distilled presets, request examples, the GB200 distilled benchmark section and troubleshooting entries. The command picker config `docs/src/snippets/configs/Wan/wan-animate-2.jsx` gains a **Checkpoint weights** option in the shape of the Qwen-Image 2.1 Turbo one (#43391): per-checkpoint defaults and Request command, CFG parallelism disabled, **Auto** topology resolving to Ulysses and **Auto** text encoder to CPU offload for the distilled checkpoint, the nine measured GB200 layouts as verified recipes, covered by `docs/scripts/tests/wan-animate-2-config.test.mjs`. The model catalog lists both ids.
- Unit tests in `test/unit/test_wan_animate_2_config.py` (the two configs, the loader, the CFG-parallel rejection, the `guidance_scale` rejection) and routing in `test_registry.py`; the unit tests run offline on CPU. One GPU CI case, `wan2_2_animate_2_14b_distilled_ref2v` (1 GPU, H100): the base case's inputs at the distilled recipe, at the default video consistency thresholds, with a perf scenario.

### Shared code touched
- `registry.py`: the modular-index probe, a pure addition. For a local directory that ships `modular_model_index.json`, the detectors are also probed with that file's `_class_name`; unit test in `test_registry.py`. Nothing else outside the Wan-Animate-2 files changes.

### Supported features
- Everything the base pipeline supports in #42941 except CFG parallelism: server warmup, Ulysses, TP and TP x Ulysses, text-encoder CPU offload, DiT layerwise offload (never changes a layout's output, about 2 s in the table below), per-request audio, the bf16 DiT with fp32 encoders and VAE.
- Server warmup (`--warmup-mode server`, the `sglang serve` default): three synthetic one-clip startup requests with a built-in reference image and a generated silent reference video: the bounded warmup shape, a residency probe at the largest supported budget, 720x1280, that decides whether the DiT stays resident, and the bounded shape again. A request whose frame geometry differs from the warmup shapes pays a one-time flex-attention autotune on its first occurrence (about 16 s on 1 GPU, 12 to 13 s on 2, 9 s on 4); with `--warmup-mode off` or `request` the first real request pays it instead.
- Multi-GPU: at `guidance_scale` 1.0 the CFG-parallel auto-enable rule does not fire, so `--num-gpus N` resolves to Ulysses (`--ulysses-degree N`); `--tp-size N` and `--tp-size 2 --ulysses-degree 2` work as on the base checkpoint.

### Notes on model-specific parameters
- The base model's parameters are unchanged (`clip_len`, `fps`, `prompt_ref`, `size` as a pixel-area budget, `video_path` / `video_url`, `seconds` and `num_frames` ignored); the distilled checkpoint changes only the defaults: `num_inference_steps` 10 and `guidance_scale` 1.0.
- `guidance_scale` other than 1.0 is rejected at request admission (see **Rejected at startup or request admission**): the distilled checkpoint samples at 1.0 only.
- `log_scale` is not a request parameter: it comes from the config class (-1.3) or from the checkpoint's `transformer/config.json` when that file carries the key.

### Rejected at startup or request admission
- CFG parallelism for the distilled config, with `Wan_Animate_2_14B_Distilled_Config does not support CFG parallelism`: there is one branch per step, nothing to split.
- `guidance_scale` other than 1.0 for the distilled checkpoint, at request admission by the per-request validation hook (`ValueError`, HTTP 400 on `/v1/videos`): `guidance_scale=<value> is not supported by the distilled Wan-Animate-2 checkpoint: it samples at guidance_scale 1.0 only (the distilled recipe has no unconditional branch); omit the field or set it to 1.0.`
- Everything the base pipeline rejects in #42941 (`--ring-degree` above 1, `--use-fsdp-inference`, degrees that do not divide the 40 heads, an explicit `--attention-backend`, MXFP8 attention, `enable_teacache` / `enable_spectrum`, `use_img_emb=false`, any `--disagg-role`).

### Deviations from the native-support contract
The per-request contract is kept as-is from the base model implementation. The one deviation this PR adds: the distilled checkpoint's scheduler is built in code by `WanAnimate2SchedulerLoader` instead of being read from the checkpoint's `scheduler/`, because the shipped config names a sampler the official reference implementation does not use (see the DPM-Solver++ rationale above).

## Speed Tests and Profiling

Tested on 1, 2 and 4 GPUs of a 4x GB200 node (189 GB per GPU).

Workload: the base PR's workload at the distilled defaults: 10 steps, `guidance_scale` 1.0, fps 30, 237 frames = 7 clips of 37, 640x800 budget on a 16:9 reference image (960x528 frame), seed 123, `sglang serve --text-encoder-cpu-offload --warmup-mode server`, two identical `/v1/videos` requests per server. E2E is the steady state (the second request); peak is the `nvidia-smi` maximum over ranks during the request, in the cookbook's unit (GiB column, `nvidia-smi` MiB / 1000, as the base table reports it). This is the cookbook's distilled GB200 benchmark.

| Config | GPUs | Flags (plus `--text-encoder-cpu-offload`) | E2E (s) | Peak per GPU (GiB) |
| --- | ---: | --- | ---: | ---: |
| 1 GPU, DiT resident | 1 | none | 150.2 | 69.5 |
| 1 GPU, layerwise DiT offload | 1 | `--dit-layerwise-offload --layerwise-offload-components transformer` | 150.0 | 39.7 |
| 2 GPU, Ulysses2 (framework default) | 2 | `--ulysses-degree 2` | 87.0 | 60.1 |
| 2 GPU, Ulysses2, layerwise DiT offload | 2 | `--ulysses-degree 2 --dit-layerwise-offload --layerwise-offload-components transformer` | 86.3 | 31.4 |
| 2 GPU, TP2 | 2 | `--tp-size 2` | 97.1 | 40.0 |
| 4 GPU, Ulysses4 (framework default) | 4 | `--ulysses-degree 4` | 55.8 | 51.0 |
| 4 GPU, Ulysses4, layerwise DiT offload | 4 | `--ulysses-degree 4 --dit-layerwise-offload --layerwise-offload-components transformer` | 58.0 | 21.5 |
| 4 GPU, TP2 x Ulysses2 | 4 | `--tp-size 2 --ulysses-degree 2` | 59.3 | 35.3 |
| 4 GPU, TP4 | 4 | `--tp-size 4` | 64.1 | 30.4 |

Speedups:
- Ulysses is the fastest layout, 1.73x over 1 GPU on 2 GPUs (87.0 s vs 150.2 s) and 2.69x on 4 (55.8 s); the tensor-parallel layouts are slower (97.1, 59.3 and 64.1 s).
- Layerwise DiT offload costs about 2 s and leaves the output identical while cutting the request-phase peak from 69.5 to 39.7 GiB on 1 GPU, 60.1 to 31.4 GiB on 2 and 51.0 to 21.5 GiB on 4.
- The gain over the base checkpoint is structural (4x fewer steps, one branch per step). Every row's first request is 9 to 17 s slower than the steady state: the one-time flex-attention autotune fires because the request's frame geometry differs from the warmup shapes, plus other one-time costs. Whole-run peaks, which include the server warmup's synthetic requests (one at the largest supported budget, 720x1280, to decide whether the DiT stays resident), are higher: 95.5 / 64.8 / 72.3 / 41.9 / 47.3 / 57.4 / 27.3 / 38.9 / 37.8 GiB in row order.
- `--enable-torch-compile` on 1 GPU brings no gain: 156.8 s steady state against 150.2 s eager, 1168 s for the first compiled request, 85.9 GiB peak, output 37.5 dB PSNR from eager and identical across requests.


### Recommended parallelism config

It is recommended to use `--text-encoder-cpu-offload`. CFG parallelism is rejected for this checkpoint, so every layout below is Ulysses, TP or their combination.

**1 GPU**
- About 96 GiB or more: defaults (DiT resident): 150.2 s, 69.5 GiB during the request, 95.5 GiB over the whole run including the server warmup's 720x1280 residency probe.
- 80 to 96 GB: add `--dit-layerwise-offload --layerwise-offload-components transformer` (150.0 s, 39.7 GiB during the request, 64.8 GiB over the whole run, identical output).

**2 GPUs**
- `--ulysses-degree 2` (what `--num-gpus 2` resolves to): 87.0 s, 60.1 GiB per GPU during the request (72.3 GiB whole run).
- 80 GB per GPU: the same with `--dit-layerwise-offload --layerwise-offload-components transformer` (86.3 s, 31.4 GiB during the request, 41.9 GiB whole run, same output), or `--tp-size 2` (97.1 s, 40.0 GiB, 47.3 GiB whole run).

**4 GPUs**
- `--ulysses-degree 4` (what `--num-gpus 4` resolves to): 2.69x over 1 GPU (55.8 s), 51.0 GiB per GPU during the request (57.4 GiB whole run).
- 80 GB per GPU: the same with `--dit-layerwise-offload --layerwise-offload-components transformer` (58.0 s, 21.5 GiB during the request, 27.3 GiB whole run), or `--tp-size 2 --ulysses-degree 2` (59.3 s, 35.3 GiB, 38.9 GiB whole run; measured once), or `--tp-size 4` (64.1 s, 30.4 GiB, 37.8 GiB whole run).

## Known limitations and follow-ups
- At `guidance_scale` 1.0 the negative prompt is still encoded: the default is a conditioning-cache hit after the warmup, and a custom negative prompt costs one UMT5 forward per distinct value. Skipping it is a follow-up.
- CI: ci-data has no ground-truth frames for the distilled case.

## Resolved known limitations
- The 720x1280 budget (the official distilled demo default) fails on both checkpoints when the reference image and the reference video have different aspect ratios: each is resized to the requested area at its own ratio and the in-context layout is sized from the image grid only. With the benchmark inputs the image gives 1280x704 = 80x44 = 3520 tokens per frame, the video 1264x720 = 79x45 = 3555, and the reference-video copy overflows (`The expanded size of the tensor (3520) must match the existing size (3555)`). A separate PR sizes the in-context attention slot from the larger of the two grids; until it merges, use 640x800 or crop the reference video to the image's aspect ratio. Everything above runs at 640x800 / `clip_len` 37. Fix in https://github.com/sgl-project/sglang/pull/44090
