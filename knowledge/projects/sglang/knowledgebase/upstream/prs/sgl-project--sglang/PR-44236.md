# [Fix] metrics: Populate pending_prealloc_token_usage and add pre_allocated_token_usage

[Upstream PR](https://github.com/sgl-project/sglang/pull/44236) · state: open · merged: False

## Original PR description

## Motivation

`sglang:pending_prealloc_token_usage` has reported `0` on every scrape since it was added. `SchedulerStats` declares the field with a `0.0` default and `log_stats` reads it, but nothing ever assigns it. The metric came from #11625, an automated `scripts/copy_from_oss.py` sync that only touched `collector.py`, and the producer-side change never followed. `gemini-code-assist` flagged this on that PR, but the comment was not addressed before merge, and `git log -S pending_prealloc_token_usage` shows no other commit.

Its name and description ("pending preallocated tokens (not preallocated yet)") describe decode-side admission backlog: tokens of requests still waiting for KV space. The decode side currently exposes no token-level signal for this. `num_decode_prealloc_queue_reqs` only counts requests.

## Modifications

- Fill `pending_prealloc_token_usage` in `_update_decode_queue_stats()`, the single place where the other decode queue stats are set, and which every reporting path reaches. The value is the tokens that requests in the prealloc queue and the retracted queue still need to allocate (`_pre_alloc_fill_len`), divided by `max_total_num_tokens`. A value above 1 is expected when decode cannot keep up.
- Add `sglang:pre_allocated_token_usage`: tokens already preallocated for in-flight KV transfers (transfer queue, excluding host-staged requests), divided by `max_total_num_tokens`. The decode log line already prints this value as `pre-allocated usage`. The log line now reads the stat, so its output is unchanged.

The two gauges look at prealloc pressure from different sides. The first shows demand that cannot get KV space yet. The second shows KV space that is reserved but still waiting for the transfer, i.e. slow prefill or transfer. The second one is a separate addition. If reviewers prefer, I can drop it or move it into its own PR.
