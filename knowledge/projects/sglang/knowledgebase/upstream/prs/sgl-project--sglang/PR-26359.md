## Code Review

This pull request introduces support for the Qwen3 MoE true on-policy contract, adding new configurations, schemas, and runtime policies for deterministic MoE routing, dispatch, and combine operations. It also refactors several helper functions in `config.py` to accept an optional `server_args` parameter. However, inserting `server_args` as a positional argument in `should_use_tp_invariant_row_linear` and `should_use_tp_invariant_tree_all_reduce` breaks backward compatibility for existing callers. It is highly recommended to make `server_args` a keyword-only argument in both functions to prevent silent logic bugs.

Changing the positional order of parameters by inserting `server_args` as the second argument is a breaking change. Any existing callers of `should_use_tp_invariant_row_linear(k_size, row_linear_enable_inv)` will now have their second argument silently bound to `server_args` instead of `row_linear_enable_inv`, leading to incorrect behavior or runtime errors.

To maintain backward compatibility, please keep `row_linear_enable_inv` as the second positional argument and make `server_args` a keyword-only argument.

```python
def should_use_tp_invariant_row_linear(
    k_size: int,
    row_linear_enable_inv: Optional[bool] = None,
    *,
    server_args: Optional[Any] = None,
) -> bool:
```
