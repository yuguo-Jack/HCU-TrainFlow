## Motivation

RFC #43949 part 3 of 4: DeepSeek-V4.1-Flash decode on monokernels (gfx950, TP2 / TP4). Depends on #44406 (framework); please review the last commit.

## Modifications

- All 40 decoder layers run whole as two launches, K1 (`layer_in -> core_in`) and K2 (`core_in -> layer_out`), for decode and DSpark verify steps of up to 48 rows; larger steps take the normal path.
- Indexer layers run SGLang's compressor and top-k between K1 and K2, with K2i scoring the indexer logits (`SGLANG_TEST_MONO_DSV41_K2A=0` keeps SGLang's logits for A/B).
- `mono.skip_metadata`: the HIP backend skips the aiter decode schedule for ratios K2i scores (one filter in `deepseek_v4_backend_hip_radix.py`).

## Accuracy Tests

DeepSeek-V4.1-Flash TP4 `--enable-monokernel`: GSM8K 1319 0.905, NIAH (32k / 64k / 120k) 60/60.

## Speed Tests and Profiling

AgentX, TTT/GPU and P90 interactivity vs upstream CI run 37423021942 (no monokernel): TP4 c1 / c4 / c8 +23% / +16% / +6% and +52% / +55% / +42%; TP2 c1 / c4 / c8 +22% / +11% / +4% and +48% / +42% / +23%.
Skipping the unused schedule: c1 TPOT -1% (8k) / -3% (128k).
