# [Feat] diffusion: add Hy-Nomas offline and realtime support

[Upstream PR](https://github.com/sgl-project/sglang/pull/46124) · state: closed · merged: True

## Original PR description

## Motivation

Add [HY-Nomas](https://huggingface.co/tencent/Hy-Nomas) (Tencent Hunyuan, Apache-2.0) to SGLang Diffusion. HY-Nomas is a video world model that generates one event at a time. Each event is a structured JSON caption with a frame count and optional camera poses, and it attends to the KV cache of earlier events. This PR serves it both as offline video jobs and as a realtime WebSocket session that accepts events one by one.

### Demo

https://github.com/user-attachments/assets/e8310c2f-0ead-4a61-81e8-51a7136ff18a

## Modifications

**Model**
- Native segment-autoregressive DiT with an explicit per-segment KV cache, camera conditioning and action-aware attention masks (`runtime/models/dits/nomas.py`, with helpers in `nomas_layers.py` and `nomas_kv_cache.py`). The MLPs, adaLN modulation and caption projection reuse the shared SGLang layers.
- Native PixelUMM pixel decoder with windowed decoding and stable-prefix streaming (`runtime/models/vaes/nomas.py`).
- Qwen2.5-VL-7B text encoder through the existing encoder path.

**Pipeline and serving**
- `NomasPipeline` with event planning, request validation, text encoding and a segment denoising loop (`pipelines_core/stages/model_specific_stages/nomas/`).
- The HTTP `/v1/videos` API accepts Nomas fields (`segments`, `prompt_format`, `norm_extrinsics`, `continuation_prompts`) through model-owned request hooks. Noise is always drawn on the CPU, as the model requires.
- A realtime adapter on `/v1/realtime_video/generate` keeps the session KV cache, noise bank and decoder state across events. The cache grows geometrically and evicts the oldest events FIFO once it reaches its budget. One session at a time.
- Ulysses SP and TP for the DiT, plus DiT layerwise offload. Ring, CFG and data parallelism are rejected.
- `tencent/Hy-Nomas` loads through the existing HF overlay mechanism (`runtime/utils/model_overlay.py`) and is registered so `sglang serve` routes it to diffusion. No conversion step is needed.

**Performance**
- Segment attention on Hopper: dense FlashAttention-3 over the visible prefix `[history | video | head text]`, plus one small pass per action over its own text, merged by log-sum-exp. Other GPUs use a FlexAttention block mask.
- Bit-exact fused kernels (`emulate_precision_casts`, reductions left in ATen): modulation + cast, QK RMSNorm + RoPE in the DiT; RMSNorm, QK-norm + MRoPE and SwiGLU in PixelUMM.
- PixelUMM windows are decoded in parallel across the decode-parallel group instead of redundantly on every rank.

**Docs**
- New cookbook page `docs/cookbook/diffusion/HY-Nomas/HY-Nomas.mdx` with a command builder, placed next to the other world models.

**Tests**
- `unit/test_nomas.py`: DiT session, cache, masks, FA3 vs. masked reference, bitwise checks of the fused kernels, pipeline stages and HTTP request contracts.
- `unit/test_nomas_realtime.py`: cache growth and eviction, RNG order, streaming decode and the realtime adapter.
- `unit/test_nomas_parallel.py`: TP=2 and SP=2 match single-rank outputs; window-parallel decode equals a serial decode. Registered in the 2-GPU lane.
- `single_test_file/test_nomas_offline.py`: one real-weight 1-GPU case. It calls `DiffGenerator` with two 120-frame events at 352×640, 8 steps and seed 42, then compares frames 0/120/239 with the shared consistency checks.

Not included: the Nomas-PE prompt enhancer (a separate LLM service), image-to-video, multi-session serving, and FP8/INT8/LoRA variants.

## Accuracy Tests

On 2×H200 at 20c79a3de9, with the official weights and the CI request (two 120-frame events, 352×640, 8 steps, seed 42):

| Check | Result |
| --- | --- |
| Nomas unit tests (3 files, both GPUs visible) | all passed, none skipped |
| Offline `DiffGenerator` vs. FA3 goldens | passed; frames 0/120/239 pixel-identical, also when generated and checked on different GPUs |
| `sglang serve`, 1 GPU, realtime WebSocket | 240 frames; two sessions with the same seed are identical |
| `sglang serve --sp-degree 2` | HTTP and WebSocket output pixel-identical to 1 GPU |
| `sglang serve --dit-layerwise-offload true` | HTTP output pixel-identical to 1 GPU |
| `sglang serve --tp-size 2` | runs, but differs from 1 GPU (uint8 MAE 5.8). **Known gap**; the cookbook recommends SP. |

The FA3 path changes output relative to FlexAttention by floating-point accumulation order only. The model amplifies such differences across its 8-step distilled sampler and later events: changing FlexAttention's block size from 128×64 to 128×128, with identical mask semantics, moves the CI video by the same amount (mean absolute difference about 8 in the first event, 26 in the second; CLIP similarity 0.97–0.99). All later optimizations are bitwise exact. The regression goldens are generated on the FA3 path that Hopper CI runners use.

**Upstream H100 CI:** At `b5bcdae3bb4165ca4989ce6929b1cc9a2310474e`, [the 1-GPU partition 2 job](https://github.com/sgl-project/sglang/actions/runs/40156395428/job/121058748138) ran `test_nomas_offline_two_events` with the pinned remote goldens: **1 passed in 150.76 s**, CLIP 1.0, SSIM 1.0, PSNR inf, mean absolute difference 0. The full test duration includes model loading and comparison; generation reported 46.07 s and peak reserved memory 25058 MiB. The Base workflow passed; this does not claim that the remaining platform checks are green.

Full-model numerical parity with Tencent's reference implementation is not claimed.

## Speed Tests and Profiling

**End to end**, official weights, `sglang serve`, 704×1280, two 120-frame events (240 frames, 10 s of video), one warm-up request excluded. Before: 3411888bbd (FlexAttention); after: 20c79a3de9.

| | 1 GPU before | 1 GPU after | SP=2 before | SP=2 after |
| --- | ---: | ---: | ---: | ---: |
| HTTP `/v1/videos`, submit to MP4 | 50.15 s | **34.11 s** | 36.11 s | **20.07 s** |
| Denoising stage | 32.9 s | 19.3 s | 18.9 s | 11.3 s |
| Decoding stage | 15.8 s | 12.9 s | 15.8 s | 6.8 s |
| Realtime session, total | 55.3 s | **38.3 s** | 40.3 s | **23.6 s** |
| Realtime session, first frames | 22.3 s | 15.7 s | 16.7 s | 10.0 s |

**DiT**, one 120-frame segment (8 Euler steps plus the cache forward), one H200, random BF16 weights at full size:

| Segment (history) | FlexAttention | FA3 | FA3 + fused elementwise |
| --- | ---: | ---: | ---: |
| 1 (0) | 13.54 s | 10.44 s | 8.61 s |
| 3 (2) | 29.73 s | 19.51 s | 17.49 s |
| 5 (4) | 45.82 s | 28.55 s | 26.35 s |
| 5 segments | 148.6 s | 97.5 s | 87.5 s |

FA3 is about 2× FlexAttention on the attention kernel (620–650 TFLOP/s). Profiles show the GPU 99.9% busy, so launch overhead is not a factor.

**Segment attention kernels**, one layer at 704×1280 on one H200: 27,000 queries (current video plus valid text), 16 heads × 128, BF16, two actions, history of 0–5 events. Every candidate is checked against the FlexAttention mask semantics.

| Kernel | 0 events | 1 | 3 | 5 | Max abs diff |
| --- | ---: | ---: | ---: | ---: | ---: |
| FlexAttention (block mask, previous default) | 19.8 ms | 37.9 ms | 75.2 ms | 113.0 ms | reference |
| FlexAttention, `BLOCK_M/N = 128` | 17.0 ms | 32.2 ms | 65.8 ms | 85.7 ms | ≤2.4e-4 |
| MagiAttention FFA, upstream Hy-Nomas ranges | 9.7 ms | 19.0 ms | 38.0 ms | 56.3 ms | ≤2.4e-4 |
| MagiAttention FFA, merged prefix range | 9.5 ms | 19.4 ms | 36.9 ms | 55.5 ms | ≤2.4e-4 |
| **FA3 (sgl-kernel) + log-sum-exp merge, this PR** | 10.2 ms | 18.9 ms | 36.7 ms | 54.6 ms | ≤4.9e-4 |

MagiAttention v1.1.1 is the version upstream Hy-Nomas pins; it was built from source for this comparison (C++20 for the PyTorch 2.14 headers, communication extension skipped). MagiAttention and the FA3 path are within 1–5% of each other (620–650 TFLOP/s), about 2× FlexAttention. FA3 is used because it ships with sgl-kernel and adds no dependency; MagiAttention expresses arbitrary range masks in one call and remains an option if segments ever carry many actions.

**PixelUMM decode**, 60 latents to 240 frames: 15.85 s → 13.40 s on one GPU, and 7.31 s with two-rank window parallelism (previously every rank decoded the whole clip).

No performance gate is added.
