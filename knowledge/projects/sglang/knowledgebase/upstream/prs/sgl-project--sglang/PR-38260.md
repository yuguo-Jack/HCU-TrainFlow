# Add get_available_cpu_memory()

[Upstream PR](https://github.com/sgl-project/sglang/pull/38260) · state: closed · merged: False

## Original PR description

## Motivation

On CPU, sglang auto-computes mem_fraction_static from total host memory and does not honor container cgroup memory limits. This makes a single server reserve a huge KV-cache pool regardless of the actual model size, and makes it impossible to run multiple sglang containers on one host safely.

## Modifications

Added a `get_available_cpu_memory` function which tries to retrieve the cgroup memory limit from `/sys/fs/cgroup/memory.max`. Existing CPU mem acquisition approach ` psutil.virtual_memory().total` is used as a fallback.
