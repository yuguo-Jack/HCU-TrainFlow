# [Perf] kimi-k3: Rank-local expert ids for the EP routed MoE

[Upstream PR](https://github.com/sgl-project/sglang/pull/45544) · state: open · merged: False

## Original PR description

## Motivation

- With expert parallelism each rank runs only its own experts (112 of Kimi-K3's 896 at EP8).
- FlashInfer picks its routing kernel from the total expert count.
- At 896 experts, decode steps of 5-16 tokens run the multi-block cluster routing kernel.
- That costs 11-12.6 us per MoE layer, about 1 ms per decode step.

## Modifications

- The fused route+quant kernel writes rank-local ids: own experts `0..count-1`, any other expert `count + top-k slot`.
- The runner passes `num_experts = round_up(count + top_k, 4)` (128 at EP8) and offset 0.
  FlashInfer then uses its single-block routing kernel up to 16 tokens.
- The same (token, expert, weight) entries reach the expert GEMMs in the same order, so outputs do not change.
- Startup tuning also tunes the rank-local key (2-3 min more on a first start without an autotune cache).
- Applies only with EP > 1 on the fused decode path (MXFP4 trtllm-gen MoE, up to 64 tokens per step).
  EP = 1, prefill and other models are unchanged.
