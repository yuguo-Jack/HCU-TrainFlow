# fix: audio model fallback bugs in voxtral/midashenglm processors and mrope scheduling

[Upstream PR](https://github.com/sgl-project/sglang/pull/44473) · state: open · merged: False

## Original PR description

## Summary

Found while routing more ASR models through `/v1/audio/transcriptions` (follow-up to #44452).

Both `voxtral.py` and `midashenglm.py` assumed `input_text` passed to `process_mm_data_async` is always a `str`. On `/v1/audio/transcriptions`, empty text becomes an empty **list** (not an empty string) once a multimodal processor is attached (`tokenizer_manager.py`'s `_tokenize_one_request` sets `input_ids = []` for empty-text multimodal requests, and that empty list is what reaches the processor as `input_text`). This crashed both processors outright:
- `midashenglm.py`: `AUDIO_TOKEN_REGEX.search(input_text)` raised `TypeError: expected string or bytes-like object, got 'list'`
- `voxtral.py`: `prompt.rfind("[INST]")` raised `AttributeError: 'list' object has no attribute 'rfind'`

Fixed both to normalize list `input_text` to a string first, the same pattern already used in `qwen_audio.py`'s `_build_transcription_prompt`.

Voxtral needed two more fixes once that crash was gone:
1. Its Mistral tokenizer ignores `return_dict` and always returns a `BatchEncoding` from `apply_chat_template`, which the processor assumed was always a plain token-id list (`TypeError: unsupported operand type(s) for +: 'dict' and 'list'`). Now unwraps `BatchEncoding`/tensor/nested-list results to a plain `list[int]`.
2. An empty prompt rendered as a content-less `[INST][/INST]` turn with no transcription instruction, so the model free-associated an unrelated response instead of transcribing (e.g. asked to transcribe "I am from the cutter lying off the coast", it returned "The cutter is a small island located off the coast of the mainland"). Now defaults to an explicit `"Transcribe this audio."` instruction when no text is supplied.

Separately: `ForwardBatch._compute_mrope_positions_extend`/`_compute_mrope_positions_decode` assumed any request with a multimodal item already has `mrope_positions`/`mrope_position_delta` populated once `model_config.model_is_mrope` is true. Those fields are only set from vision grid info during image/video processing. An audio-only model whose text backbone happens to declare `rope_scaling.mrope_section` -- inherited from a vision-capable sibling architecture it doesn't itself use, e.g. MiDashengLM -- crashes with a `None`-subscript / `None.item()` `TypeError` on every single request, since no vision processor ever runs to populate those fields. Both call sites now fall back to the existing text-only position path when `mrope_positions`/`mrope_position_delta` aren't set, instead of assuming they always are.

MiDashengLM needed one more fix after the above two: a template-based default prompt (mirroring `qwen_audio.py`'s `_TRANSCRIPTION_CONVERSATION` pattern) so empty-text requests get a real instruction via `apply_chat_template` instead of the bare `<audio>` span. Even with that, generation degenerated into a repeated `"!"` token from the very first output token -- traced to `MiDashengLMModel.__init__` never setting `tie_word_embeddings` on `text_config`, so it inherited `Qwen2_5OmniTextConfig`'s default of `True`. `Qwen2ForCausalLM` then discarded the checkpoint's real `lm_head.weight` (verified numerically distinct from `embed_tokens.weight`) and reused the tied embeddings as the output head, producing degenerate output regardless of prompt or audio content. Now forces `tie_word_embeddings=False` so the real checkpoint weights load.

## Test plan

Validated on Intel XPU via `lmms_eval`'s `openslr_librispeech_other` task served through `/v1/audio/transcriptions`:

- **Voxtral-Mini-3B-2507**: WER 100 → 2.86 (reference 1.86 is on the easier test-clean split; test-other is harder). Confirms both the list-normalization and default-prompt fixes.
- **MiDashengLM-7B**: WER 100 → 4.76 (reference 6.2, model's own HF card). Confirms the input-list fix, mrope fix, default-prompt fix, and the lm_head tying fix together restore working transcription.
