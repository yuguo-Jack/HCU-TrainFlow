# [Fix] disaggregation: Agree on deferred decode KV releases across attention TP ranks

[Upstream PR](https://github.com/sgl-project/sglang/pull/44371) · state: closed · merged: False

## Original PR description

## Motivation

On PD decode with attention TP > 1, each rank decides **by itself** when to free the pages of a failed transfer it is holding for deferred release (#35049). Those decisions feed admission, so ranks can end up with different free capacity, admit different requests, and then mismatch on the next collective (`poll_and_all_reduce` over lists of different lengths).

There are two rank-local decisions:

1. **When to release.** `resolve_deferred_releases` MIN-reduces only the host-destination branch. The device branch releases on the local drain ack or the local deadline. Ranks wait on different prefill peers, so their acks land on different steps. #43719 made this common: when a Mooncake send fails on only some prefill ranks, the poisoned rooms never ack. Decode ranks paired with those peers then hold for the full timeout (30 s by default), while the other ranks release on the next step.
2. **Whether to hold at all.** In `pop_transferred`, a rank whose receiver never finished bootstrapping (`bootstrap_infos is None`) cannot notify prefill and releases at once. A peer rank that did notify holds the same request.

## Modifications

- `DecodeTransferQueue._all_ranks_agree(flags, op)` reduces per-entry decisions over the attention-TP gloo group that the transfer polls already use. It issues no collective at TP 1 or when the list is empty.
- `pop_transferred` collects the hold decision for every failed entry and MAX-reduces it, so if any rank holds, all ranks hold. The failed set and its order are already identical across ranks, because the polls are reduced.
- `resolve_deferred_releases` builds one ready flag per held entry and MIN-reduces it, so an entry is released on the step where every rank is ready.
  - Device entry: ready when drained or past its deadline.
  - Host entry: ready only when drained, unchanged.
  - This replaces the host-only reduction.
- `_defer_release` counts `bootstrap_infos or ()`. A rank that holds only because a peer did needs no ack, so it is ready immediately.

Cost: one gloo all-reduce of a short int tensor per scheduler step, only while failed transfers are being decided or held.

## Tests

- New `TestDeferredReleaseRankAgreement` runs three scenarios on a real two-process gloo group, with no mocked collective:
  - the drain ack lands on one rank first;
  - the deadline passes on one rank first;
  - one rank cannot notify.

  In each, both ranks must free the request on the same step.
- Negative control: on main all three fail.
  - drain: rank 0 releases one step early, `[1, 1]` vs `[0, 1]`.
  - deadline: rank 0 releases early.
  - notify: rank 1 releases at once, `[1, 0, 0, 0]`.
- The single-rank tests in `test_deferred_decode_kv_release.py` and `test_decode_queue_cleanup.py` now run under a one-rank gloo group instead of a `MagicMock` group. Both files pass: 45 and 14 tests.
