# [CI] [AMD] pr-test: Move large-model and perf tests from AMD PR CI to nightly

[Upstream PR](https://github.com/sgl-project/sglang/pull/46085) · state: closed · merged: True

## Original PR description

## What

Moves the large-model and perf tests in AMD's stage-c (and two in stage-b) out of PR CI:

| Test | PR CI time | New home |
|---|---|---|
| `test_kimi_k2_instruct` | 23 min | `nightly-amd-8-gpu`, run by a new `nightly-8-gpu` job (MI30x) |
| `test_moriep_small`: low-latency, MTP-only, TBO + low-latency, MTP + TBO + low-latency, EPLB | ~25 min | new `test_moriep_small_extra.py`, also `nightly-amd-8-gpu` |
| `test_deepseek_v32_basic` | 19 min | `nightly-amd-accuracy-8-gpu-deepseek-v32` |
| `test_qwen35_fp8_ar_fusion_mi35x` (perf) | 13 min | `nightly-amd-8-gpu-mi35x` |
| `test_qwen3_coder_next_8gpu` | 5 min | `nightly-amd-8-gpu-mi35x` |
| `stage-c-dsv4-pro-fp4-amd-mi35x` job | 13 min | removed; `nightly-8-gpu-mi35x-deepseek-v4-pro` runs the same file |
| `test_llada2_mini_amd`, `test_vlm_serving_aiter` | 16 + 8 min | `extra-a-test-1-gpu-large-amd` |

`stage-c-test-large-8-gpu-amd` drops from 4 to 2 shards, and `stage-c-test-large-8-gpu-amd-mi35x` from 3 to 1.

## Why

CUDA's PR CI keeps roughly one small model per GPU config in base-c, and its large-model tests run nightly. On AMD, stage-c runs Kimi-K2, DeepSeek-V3.2, Qwen3.5 perf and a 9-server MoRI EP sweep on every PR: about 100 min of 8-GPU MI30x time and 40 min of 8-GPU MI35x time per run. Times are measured from the `elapsed=` lines in recent PR job logs.

## Notes for the reviewer

- The MoRI EP split follows `ep/test_deepep_small.py` / `test_deepep_small_extra.py`. PR CI keeps pure DP, normal, TBO + normal, and MTP + TBO + normal. The extra file imports the shared args from `test_moriep_small`, as other sibling tests in `test/registered` do.
- The `nightly-amd-accuracy-8-gpu-kimi-k2` suite is declared but no nightly job runs it, so Kimi-K2 gets a new `nightly-8-gpu` job rather than relying on it. That job uses the existing `nightly-amd-8-gpu` suite name, which had no files.
- Headroom on the nightly steps that take more files:
  - The DeepSeek-V3.2 accuracy step currently runs 15–35 min against its 120-min timeout.
  - The MI35x GPT-OSS accuracy step runs ~20 min against 180.
- DeepSeek-V4-Flash stays in PR CI, matching CUDA's base-c.

Related: #46084 (CUDA-extra tests to the AMD extra tier), #46086 (parallel shards).
