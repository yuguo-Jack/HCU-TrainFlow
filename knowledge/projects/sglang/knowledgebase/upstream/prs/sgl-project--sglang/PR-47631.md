# [Fix] profiler: keep trace files inside output_dir

[Upstream PR](https://github.com/sgl-project/sglang/pull/47631) · state: open · merged: False

## Original PR description

## Motivation

Fixes #44189

`/start_profile` takes `profile_prefix` and `profile_id` from the caller and joins them into the trace filename as is. a prefix like `../escaped` writes the trace one level above `output_dir`; an absolute prefix like `/tmp/elsewhere/x` makes `os.path.join` drop `output_dir` entirely. `profile_id` has the same problem.

(#44201 tried this but was closed along with everything else from that account.)

## Modifications

- add `sanitize_profile_filename_component` in `profile_utils.py`; it replaces `/`, `\`, `os.sep`, `os.altsep` and NUL with `_` and leaves everything else alone, so normal ids and prefixes keep their exact names
- call it on `profile_id` and `profile_prefix` at the top of `ProfilerManager.configure`, so both the v1 path and the `SGLANG_PROFILE_V2` path get clean values (this also covers the memory snapshot and merged trace names that reuse them)
- call it on `profile_prefix` in the encoder profiler too

with no separators left, the joined name is always a single filename under `output_dir`.
