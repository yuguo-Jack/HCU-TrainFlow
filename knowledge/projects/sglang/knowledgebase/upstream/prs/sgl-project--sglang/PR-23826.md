# [Bugfix] Reject non-positive prefill request limits

[Upstream PR](https://github.com/sgl-project/sglang/pull/23826) · state: closed · merged: False

## Original PR description

## Motivation

Starting an engine with `prefill_max_requests=0` completes model setup, then the first `generate()` call blocks. Current `main` still accepts the value and passes it to the scheduler, where the first request fails the admission check because `0 >= 0`.

Fail during argument resolution, before model startup. Fixes https://github.com/sgl-project/sglang/issues/23788.

## Modifications

Reject non-positive `prefill_max_requests` values in the model-independent `ServerArgs` validation path. The parameterized CPU test covers `0` and `-1`. Valid positive values and the default `None` keep their existing behavior.

When `check_server_args()` is called, it will likely raise a `TypeError` at line 6657 when attempting to check `":" not in self.served_model_name`. 

To ensure these tests are robust and don't fail due to this pre-existing issue in `check_server_args`, consider explicitly setting `served_model_name="dummy"` in the test cases. This applies to lines 179, 186, and 192 as well.

```suggestion
        server_args = ServerArgs(model_path="dummy", prefill_max_requests=None, served_model_name="dummy")
```
