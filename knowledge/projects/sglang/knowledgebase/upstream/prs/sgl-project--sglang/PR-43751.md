# [Fix] Make tokenizer request-state initialization atomic

[Upstream PR](https://github.com/sgl-project/sglang/pull/43751) · state: closed · merged: False

## Original PR description

## Motivation

If a batch contains fresh request IDs followed by an ID already in flight, `_init_req_state` can raise after publishing the earlier states. Initialization runs before the handler's failure-cleanup block, so those undelivered states remain in `rid_to_state` and prevent later reuse of their IDs.

Preserve the existing request map when ID validation, state construction, or timing/trace initialization fails.

## Modifications

- Validate the complete ID set against live requests and other IDs in the batch before constructing states.
- Initialize states and their timing/trace metadata privately, then publish them together after every item succeeds.
- Extend the existing CPU cleanup suite with parameterized collision, construction-failure, generation/embedding, trace-metadata, and adapter-ownership regressions.

Related to #41911, which addresses the same live-ID collision. @C1ves is credited as a co-author of the commit. This change also covers failures during state construction and timing/trace setup; it guarantees request-map atomicity rather than rollback of telemetry already emitted.
