# [diffusion] Encode LTX video/audio through the shared bounded MP4 path

[Upstream PR](https://github.com/sgl-project/sglang/pull/43656) · state: closed · merged: True

## Original PR description

## Summary

Reuse the existing bounded CUDA MP4 encoder for native LTX video/audio output. Offer explicit whole-clip hand-off for ordinary VAEs without automatically enrolling them. No new server flag or model-name whitelist.

- LTX emits only finalized, blended/cropped frame prefixes when temporal tiling is already enabled; untiled decode hands over the finished clip once.
- Ordinary video decoders need no callback implementation for explicit `DecodingStage.decode(..., on_frames=...)` use. Their default remains main's GPU-direct saving path: cross-model E2E did not establish a meaningful gain from moving whole-clip encoding into the decode stage. Existing incremental Wan/H3 paths remain intact.
- Preserve BF16 normalization order, audio muxing, component declarations, rank-consistent execution, and normal saving on encoder failure.
- Bound frame conversion intermediates as well as the encoder queue. Raw frames, batching, compilation, interpolation/upscaling, custom postprocessing and custom decode stages retain their original paths.
- Document the shared hand-off contract. No tiling defaults, GT files, or consistency thresholds change.

## Matched E2E measurements

Native Lightricks/LTX-2, H200, BF16, 8 steps, CFG 3, seed 42, 24 fps, generated audio, x264 fast/CRF25. Timer includes the complete generate request through fully written MP4, excludes loading. Baseline is main's original decoding stage and temporal decode implementation, tested in the same process. Six requests per configuration; discard the first sample per mode, average two warmed samples per mode.

| Hardware / workload | Temporal tiling | Main | This PR | Latency reduction |
|---|---|---:|---:|---:|
| 1 H200, 768x512x49 | off | 3.247 s | 2.966 s | 8.6% |
| 1 H200, 768x512x49 | on | 3.330 s | 2.968 s | 10.9% |
| 1 H200, 1024x576x121 | off | 11.201 s | 10.112 s | 9.7% |
| 1 H200, 1024x576x121 | on | 11.536 s | 10.173 s | 11.8% |
| 2 H200, Ulysses 2, 768x512x49 | off | 2.592 s | 2.277 s | 12.1% |
| 2 H200, Ulysses 2, 768x512x49 | on | 2.815 s | 2.396 s | 14.9% |

All six MP4s within each matched configuration have identical SHA256, including audio. Tiled runs explicitly use tile32/stride24; this is not enabled by the PR and is not a claim of equivalence to untiled decode. Large-workload runtime allocated peak stayed within 3 MiB (68.82 GiB untiled / 66.35 GiB tiled); reserved peak was unchanged at 72.97 GiB. These are runtime peaks, not loading measurements.

Environment: torch 2.14.1+cu130, diffusers 0.37.0, transformers 5.19.0. Baseline 3458c94fad9f; E2E feature 812a1f8ef3cc. Latest main merged afterward.

## Cross-model default-policy check

Additional native H200 E2E A/B at 8 steps, fixed prompt/seed, BF16 and resident weights, no compile. Each model/shape runs ten interleaved requests; discard the first sample per mode. Hunyuan short-workload repeat uses twenty requests. Table reports warmed median, including fully saved MP4 (not just the decode-stage timer). Baseline ad8b1e1f851a versus the initially broad default at 5bdf76e8dde3.

| Model | Workload | Main | Broad hand-off | Observation |
|---|---|---:|---:|---|
| HunyuanVideo | 256x256x17, repeat | 0.872 s | 0.870 s | no meaningful gain |
| HunyuanVideo | 832x480x81 | 36.605 s | 36.556 s | 0.13% difference |
| Wan2.1 T2V 1.3B | 256x256x17 | 0.518 s | 0.518 s | unchanged |
| Wan2.1 T2V 1.3B | 832x480x81 | 8.126 s | 8.119 s | 0.09% difference |

The first Hunyuan short run showed a 2.45% mean slowdown (1.54% median); the twenty-request repeat did not reproduce a stable regression (0.45% mean improvement). This is not evidence for a reliable whole-clip speedup. Ordinary VAEs already use GPU-direct saving in main, unlike LTX's NumPy materialization path. Therefore this PR no longer automatically enables whole-clip hand-off for ordinary VAEs. The explicit callback API remains available, and avoids repeating normalization for whole-clip decode.

All MP4s within each matched model/workload have identical SHA256. An additional ten-request Hunyuan E2E on final head eae532cd51b8 asserts that both modes use the original saving path: 0.8717 vs 0.8723 s mean (+0.07%), identical MP4s. Seventy additional complete requests in total. Each model's A/B stays on the same dedicated GPU; separate model runs use the two GPUs of the same host, so sub-percent timing differences are not claimed as gains. This does not establish universal no-regression across hardware or workloads.

## Additional requested families

Final head eae532cd51b8 versus main ad8b1e1f851a, native SGLang pipelines, H200, resident weights, eager, default conditioning cache, seed 42. Alternate A/B ten times per shape and discard the first request per mode; report warmed median of the full request through saved PNG/MP4. No Diffusers backend fallback. Image families run on one H200; H3 uses two H200 with Ulysses 2.

| Checkpoint | Workload | Steps | Main | This PR |
|---|---|---:|---:|---:|
| Qwen/Qwen-Image | 512x512 | 8 | 1.0396 s | 1.0361 s |
| Qwen/Qwen-Image | 1024x1024 | 8 | 1.9692 s | 1.9699 s |
| black-forest-labs/FLUX.2-klein-4B | 512x512 | 4 | 0.1254 s | 0.1263 s |
| black-forest-labs/FLUX.2-klein-4B | 1024x1024 | 4 | 0.4380 s | 0.4370 s |
| ideogram-ai/ideogram-4-fp8 | 512x512 | default preset, 20 | 1.4774 s | 1.4783 s |
| ideogram-ai/ideogram-4-fp8 | 1024x1024 | default preset, 20 | 5.9451 s | 5.9544 s |
| nvidia/Cosmos3-Nano | 832x480x9 | 4 | 0.4300 s | 0.4303 s |
| nvidia/Cosmos3-Nano | 832x480x33 | 4 | 1.3846 s | 1.3850 s |
| MiniMaxAI/MiniMax-H3, FL2VA | target 768x768, 4 s | 4 | 5.3283 s | 5.3311 s |

These differences are sub-percent noise, not speedup claims. Qwen/FLUX remain on image saving; Ideogram/Cosmos keep their specialized decode stages. H3 already uses incremental MP4 encoding in main, so the comparison exercises the shared encoder's bounded frame postprocessing rather than newly enabling streaming.

All image/Cosmos files within each shape are byte-identical. H3's nine requests after the first cold baseline request have the same complete MP4 SHA256, including audio. The first baseline request has identical decoded video pixels but different audio from warmed requests. An independent fresh process running only the original baseline for three requests reproduces the exact cold/warm hashes, so this is not introduced by the encoder change; its underlying cold-start audio cause remains outside this PR. Do not claim universal cold/warm reproducibility. H3 resolves the requested 4-second target to an actual 107-frame MP4 at 24 fps (video 4.4583 s, audio 4.45 s), identically in both modes.

Warmed allocated/reserved peaks observed at the decoder boundary are identical for Qwen, FLUX and Ideogram. H3's maximum allocated observation differs by less than 1 MiB (94.9818 vs 94.9825 GiB), reserved unchanged at 97.3457 GiB. These are not isolated loading peaks or proof for other workload sizes. Ninety additional saved A/B E2E requests across the five families plus three baseline-only cold-start checks, with no GT/threshold changes. Environment: Python 3.12.15, torch 2.14.1+cu130, diffusers 0.37.0, transformers 5.19.0.

## Validation / boundaries

- Final merged head eae532cd51b8: 35 tests and 27 subtests passed on H200; all changed files pass pre-commit. Ordinary decoders without callback capability must not automatically stream.
- Exact LTX decoded-tensor comparison against the independent original two-loop implementation, temporal on/off, slicing/batching, callback stability and cropping.
- GPU FP32/BF16 MP4 byte equality, audio/no-audio, normal fallback and rank/order checks.
- Ordinary Hunyuan GPU decode and whole-clip MP4 hand-off regression; shared spatial-parallel decode tests.
- Actual speedup measurements above cover LTX-2 only. Cross-family regression checks cover the listed representative checkpoints, not every variant. H100/5090 and concurrent workloads remain unvalidated. Custom image/audio/mesh and specialized decode stages are intentionally not blindly enrolled.
