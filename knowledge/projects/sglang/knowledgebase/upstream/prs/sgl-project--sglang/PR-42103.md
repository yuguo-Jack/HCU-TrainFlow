# [Feat] weights: Add native ModelExpress weight transfer backend support

[Upstream PR](https://github.com/sgl-project/sglang/pull/42103) · state: open · merged: False

## Original PR description

## Motivation

Add native ModelExpress weight-transfer backend support through `POST /update_weights_from_modelexpress`. Trainers can request a published weight version while SGLang delegates staging and installation to MX. This integration targets `main` and can be used by different training frameworks.

## Modifications

```text
version request → native weight-update lock → scheduler checks (PP, draft model)
                → TP workers: cache checks + MX stage → TP staging agreement
                → restore packed layers → MX apply → release
                → TP install agreement → record version → flush caches
```

- Use the native weight-update synchronization helper, including when generation is already paused.
- Delegate receiver configuration to MX's public `get_modelexpress_generator()`. `WeightUpdater` creates the optional client on the first refit, reuses it, and closes it at scheduler shutdown.
- Install only after every TP rank has staged the version. If any rank fails to stage, release the staged handles and fail without touching the weights. Combine every rank's install result before reporting success.
- Before installing, restore layers that a kernel repacked in place (compressed-tensors W4A16 MoE on Marlin, BF16 MoE on `flashinfer_trtllm`), as `begin_weight_update` does. Skip the restore when MX already serves the staged version, since MX does not reload it.
- Record the version as soon as the install succeeds, then flush the requested caches, as the other update paths do. A refused flush still fails the call.
- Reject pipeline parallelism, speculative draft models, and incompatible weight-cache modes before mutation, with a failed response (HTTP 400).
- Like the other update paths, record `weight_load_duration_seconds` under the `modelexpress` source, and clear the multimodal preprocess cache after a successful refit that flushes caches.
- Document installation from ModelExpress `main`, the upcoming v0.8.0 release, receiver configuration, and endpoint usage.

The validated workflow uses S3 deltas and full checkpoints, with transfer and reconstruction handled by MX. Companion implementation and trainer integration: [ModelExpress #826](https://github.com/ai-dynamo/modelexpress/pull/826) and [Miles #3886](https://github.com/radixark/miles/pull/3886).

**[High] A rejected request kills the server instead of returning HTTP 400.** When a derived weight cache is active (mHC splits, HPC bf16xfp32 GEMM, or a model-owned `_derived_weight_cache_error`), this raises `RuntimeError`. Nothing catches it between the scheduler's request dispatch and `run_scheduler_process`, which logs it and sends SIGQUIT to the parent, so the whole server goes down. `update_weights_from_disk` returns `(False, error)` for the same condition. Suggest `return False, error` here. `_assert_weight_cache_inactive` on line 102 has the same effect (shared with the other update paths), and `test_model_updater_honors_native_weight_cache_restrictions` currently asserts the raise.

**[High] A staging failure on one rank leaves the TP group serving mixed weights.** Each rank runs `stage_weight` and then `apply_weight` on its own, and ranks only agree after installation (line 131). If one rank's staging fails (S3 error, timeout, local disk) while the others succeed, those ranks install version N and the failed rank stays on N-1. The call reports failure, but there is no rollback (the disk path reloads the original weights), so the TP group is left with mixed weights. Suggest all-gathering the staging result before `apply_weight`, and releasing the staged handle on every rank if any rank failed.

**[Medium] The install path skips `restore_weights_before_loading`.** `apply_weight` reaches ModelExpress's `_SglangInstaller._install_checkpoint`, which calls `loader.load_weights_and_postprocess` directly.
