# [Perf] dsv41: Add an opt-in current Mega prefill kernel

[Upstream PR](https://github.com/sgl-project/sglang/pull/46402) · state: open · merged: False

## Original PR description

## Motivation

Adds a default-off opt-in to use the current FlashMLA Mega prefill kernel for DSv4.1 gathered BF16 workspaces. With `SGLANG_OPT_DSV41_CURRENT_MEGA_PREFILL=1`, eligible prefill calls use the current implementation; the existing default and paged decode dispatch are preserved.

## Modifications

The selector is explicit because the performance effect depends on the workload. It does not introduce an automatic token threshold.

## Speed Tests and Profiling

Dependencies: PyTorch 2.14.1 (CUDA 13.0 runtime), sglang-kernel 0.4.10, sgl-flash-mla 1.0.0 and sgl-deep-gemm 0.2.3.post2.

Final candidate: `1755b7c479b98ee3b8c134728f61acacb516aac0`; baseline: `773cb938fe9484a8f7e7e46fb1b1fe96412c59ed`.

Measurements use `benchmark/engine_steps/bench_engine_steps.py` from #46006 at `543a2804d5c8f3167c8fd8bb5c3a3ef862c3774f`. The setup uses NVIDIA GB300 and DeepSeek-V4.1-Flash, TP2/EP2 with attention DP2, MegaMoE, BF16 index logits, bounded encoder/decoder replay, eager prefill with tail graphs, context 131072 and 4096 new tokens. Timing uses DSPARK block size 5, simulated acceptance 3.51 (`match-expected`, `real-draft-token`), real expert routing, and `SGLANG_DP_USE_GATHERV=0`. Each arm drains 4096 requests per rank, with 5 warmup steps and seed 733427905. Pipeline depth is 8 for the 32K budget and 32 for the 4K budget. Each group's order was fixed before running.

| Requested prefill token budget per rank | ABBA paired throughput change | BAAB paired throughput change |
|---|---:|---:|
| 32768 | +0.2900%, +0.2949% | +0.3642%, +0.2882% |
| 4096 | +0.0537%, +0.9243% | -1.4576%, +0.7525% |

All 16 opt-in raw arms replay exactly through the official scorer. Cross-arm workload, server settings, versions, environment and GPU configuration checks pass. The 32K improvement repeats in both orders. The 4K results have mixed signs and baseline variation, so they do not establish a stable 4K benefit. These are fixed-batch prefill engine-step measurements, not application E2E results.

## Accuracy Tests

Actual-model boundary checks pass at both token budgets with the switch off and on: 80 sampled main-path records per arm have matching outputs/scales, unchanged inputs, and the expected dispatch. Eight CPU routing checks and pre-commit checks pass.

Native GSM8K on the same 200 inputs scores 196/200 for baseline and 195/200 for the candidate, both above the existing 0.95 threshold, with actual draft acceptance. All outputs are nonempty and terminate normally. One answer changes from correct to wrong; only 87 generation strings are identical. This is a threshold pass, not evidence of unchanged accuracy or generation equivalence. Native latency/throughput is excluded from the performance comparison.

## Default-off control

The additional default-off 4K ABBA control produced -1.5682% and +1.4015% paired throughput changes. Both variants select the legacy kernel. This mixed control does not establish a default-path regression or a default-path non-regression guarantee. No stable 4K speedup is claimed.
