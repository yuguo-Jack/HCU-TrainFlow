# [Fix] [AMD] dsv4: transfer unified C4 state by request-local rows

[Upstream PR](https://github.com/sgl-project/sglang/pull/47938) · state: open · merged: False

## Original PR description

## Motivation

DeepSeek-V4 unified-KV PD can silently copy the wrong C4 compression state on ROCm. The unified compressor writes C4 attention/indexer state in request-local rings, but PD currently bundles those buffers into the SWA component and indexes them through `full_to_swa`.

The unified allocator does not populate that paged mapping. In a CPU reproduction with sequence length 13, prefill request slot 2 and decode slot 5, transfer returns success after copying the page-zero state while leaving the decode request's live state untouched. Equal ring sizes do not prevent the failure.

## Modifications

- Register unified C4 attention/indexer buffers separately, with one physical state row per item. Keep non-unified state registration unchanged.
- Build both endpoint payloads with the existing logical-overlap helper and each peer's own request slot and ring size.
- Add a shared C4 state type using the existing Ascend wire value; dispatch it through Mooncake, NIXL and MORI, preserve strict index-length checks, and reject mismatched MORI row widths.
- Slice both attention and indexer pointer groups for PP metadata. Keep an empty C4 slot when a stage has no C4 layers, and skip payload computation for empty components on both endpoints.
- Add regression tests for registration, request-slot/ring mappings, non-unified controls, PP slicing, draft component ordering, and empty/live endpoint payloads.

Both peers must use the new unified C4 state layout. This is independent of the A3 fix in #47934 and does not include the NPU PP registration fix.

## Accuracy Tests

Tested against main `e33cd0c3a10474c7a0f6efeb69ce2cf4b7a55021`:

- Five focused unified-C4 tests and two complete empty/live endpoint tests pass in the CPU AST harness.
- 160 production Mooncake sender / bounds-checked CPU byte-transfer cases pass: 8/16/32-row rings, equal and different request slots, short histories, and 128/256 boundaries. Both state groups and untouched destination rows are checked.
- Actual NIXL dispatch and MORI state-transfer planning methods pass with SDK submission boundaries mocked. Negative cases reject unequal index counts and unequal MORI row widths.
- Eleven CPU fixture tests pass after importing the real production modules in an Ascend environment (torch 2.10.0+cpu / torch_npu 2.10.0.post6, CANN 9.1): the two endpoint tests, all six unified-C4/mixed-layout tests, and three target/draft registration controls. This is not ROCm device validation.
- Ruff 0.15.1 formatting and selected lint checks, isort 7 and `git diff --check` pass.

No ROCm device, backend transport or full-model quality regression was run. PP helper tests do not extend support to configurations rejected by existing startup gates. The original A3 hardware results are not used as evidence for this fix.

## Speed Tests and Profiling

No performance claim; this corrects which state rows are transferred.
