# [Perf] lora: Eliminate redundant dict key copies and slot rescans in LoRA eviction and batch prep

[Upstream PR](https://github.com/sgl-project/sglang/pull/46403) · state: open · merged: False

## Original PR description

## Motivation

In multi-LoRA serving (`python/sglang/srt/lora/eviction_policy.py` and `python/sglang/srt/lora/mem_pool.py`), `LoRAMemoryPool.prepare_lora_batch` runs before every forward batch to mark active adapters as used and allocate buffer slots for missing adapters:

1. **`LRUEvictionPolicy.select_victim` and `FIFOEvictionPolicy.select_victim`** materialized a full `list(self.access_order.keys())` / `list(self.insertion_order.keys())` copy on every eviction even though neither dictionary is mutated during iteration.
2. **`LRUEvictionPolicy.mark_used`** called `self.access_order.pop(uid, None)` followed by re-insertion on every batch access instead of `OrderedDict.move_to_end(uid)`, and eagerly formatted f-strings for `logger.debug` even when `DEBUG` logging is disabled.
3. **`LoRAMemoryPool.prepare_lora_batch`** rescanned `range(self.max_loras_per_batch)` from index `0` and rebuilt the `candidates` and `non_none_candidates` sets from scratch for *every* missing adapter in the batch ($O(K \cdot M)$ for $K$ missing adapters and pool capacity $M$).

## Modifications

- **`python/sglang/srt/lora/eviction_policy.py`**:
  - Iterate directly over `self.access_order` / `self.insertion_order` in `select_victim` without allocating a temporary `list` of keys.
  - Use `self.access_order.move_to_end(uid)` in `LRUEvictionPolicy.mark_used` and lazy `%s` formatting in `logger.debug(...)` calls.
- **`python/sglang/srt/lora/mem_pool.py`**:
  - Return early in `prepare_lora_batch` when all requested adapters are already resident in `self.uid_to_buffer_id`.
  - Collect `empty_slots`, `non_none_candidates`, and `has_none_candidate` in a single $O(M)$ pass when misses occur, and consume empty slots / evicted victims incrementally in $O(1)$ per missing adapter while preserving deterministic slot order and base-model (`None`) last-resort fallback.
- **`test/registered/unit/lora/test_eviction_policy.py`**:
  - Added `test_prepare_lora_batch_multi_eviction_and_base_fallback` verifying multi-adapter eviction ordering, pinned-adapter preservation, base-model (`None`) fallback, and `ValueError` when all slots are pinned.
