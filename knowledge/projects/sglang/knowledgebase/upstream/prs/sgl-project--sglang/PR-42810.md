# [kernel] SwiGLU-OAI MXFP8 producer; move swizzled MXFP8 producers to ops/quantization

[Upstream PR](https://github.com/sgl-project/sglang/pull/42810) · state: closed · merged: True

## Original PR description

## Motivation

Models with a clamped SwiGLU-OAI MLP (e.g. MiniMax-M3's dense and shared experts) that feed an MXFP8 down projection currently run the activation and `flashinfer.mxfp8_quantize` as two separate kernels. The existing diffusion `_silu_mul_mxfp8_kernel` already writes FlashInfer's 128x4 swizzled E8M0 scales, so this PR adds a SwiGLU-OAI branch to it.

## Modifications

- `_silu_mul_mxfp8_kernel` takes `ALPHA` / `LIMIT` as constexpr. `ALPHA=None` keeps the SiLU path unchanged. Otherwise it computes `clamp(gate, max=limit) * sigmoid(alpha * gate) * (clamp(up, ±limit) + 1)` in the op order Inductor emits for `swiglu_no_interleaved_with_alpha_and_limit`, rounding to bf16 once.
- New `swiglu_oai_mxfp8(hidden, alpha, limit)`, registered as `quantization.swiglu_oai_mxfp8`.
- Move `mxfp8_swizzled_triton.py` from `kernels/ops/diffusion/quantization/` to `kernels/ops/quantization/`, since the quantizer and SwiGLU producers are not diffusion-specific. The diffusion facade still re-exports `mxfp8_quantize_swizzled`, `silu_mul_mxfp8`, `indexed_scale_shift_mxfp8_` and the `can_use_*` predicates by their full module path, so diffusion callers don't change. The test moves to `test/registered/kernels/ops/quantization/`.
- The kernel now writes the scale padding itself (padded rows and columns get 0), so the `torch.zeros` memset on the scale buffer goes away. Batches of up to 1024 rows use 4-row tiles.

## Accuracy

Payload and swizzled scales, padding included, are byte-identical to the unfused `swiglu_no_interleaved_with_alpha_and_limit` + `flashinfer.mxfp8_quantize` chain: 0 of 63.4M bytes differ over 1–5800 rows and input scales from 1e-2 to 100.

## Tests

`test/registered/kernels/ops/quantization/test_mxfp8_swizzled.py` adds:
- SwiGLU-OAI vs the eager chain, with rows {1, 7, 128, 333}, n {768, 1056} and scale {1e-3, 1, 30}. The input is a strided view, and the allocator is dirtied first so a missing padding write would show up.
- A CUDA graph replay test.

On B300 (SM103) with this branch: 30 passed in `test_mxfp8_swizzled.py`, plus `multimodal_gen/test/unit/test_mxfp8_online_gemm.py` (33 passed, 1 skipped across both files). All four registry specs pointing at the moved module resolve.

## Benchmark

Width 768, CUDA graphs: 1.3–1.5 µs for 1–256 rows (unfused: 2.2–3.1 µs) and 6.3 µs at 5800 rows (unfused: 8.9 µs).
