# [HiCache] Preserve L2/L3 hit attribution across scheduling retries

## Motivation

Fix prefill cache-hit attribution so L2/L3 hits retain their source after promotion to GPU. Apply the same attribution to request responses and prefill metrics.

This fixes:
- **Scheduling retries after H2D:** preserve L2/L3 attribution when a request loads KV onto GPU but is deferred by admission checks and rematches the prefix in a later round.
- **Concurrent L3 prefetch deduplication:** retain the full completed L3 fetch span, including tokens already inserted by another request.
- **Buffer-only shared-prefix coverage:** preserve L3 attribution when another request partially or fully populates the GPU prefix while prefetch is staged.
- **Partial eviction or failed load-back:** clip attribution to the cached prefix actually used and count overlapping H2D loads only once.

Reuse existing L3 span tracking in UnifiedCache, add it to HiRadixCache, and keep prefetch lifecycle accounting consistent with admission-time attribution.

### Validation

**End-to-end: Qwen3-8B + Mooncake RDMA**

| Scenario | Before | After |
|---|---|---|
| Four requests sharing an 8,192-token prefix, cache mode | L1: 24,576; L3: 8,192 | L1: 0; L3: 32,768 |
| A shorter request loads the shared prefix before a longer request, in both cache and buffer-only modes | Long request: L1: 4,096; L3: 4,096 | Long request: L1: 0; L3: 8,192 |
| Subsequent warm request hitting existing GPU KV | L1: 8,192; L3: 0 | Unchanged |

Prometheus per-tier counter deltas matched the response breakdowns. Generated tokens were identical before and after the change.

**Deterministic regression coverage**

- H2D completes, admission returns `OTHER`, and the request is retried: preserve L2 and mixed L2/L3 attribution.
- Repeated, overlapping, or disjoint H2D spans: avoid double counting.
- A shorter admitted prefix: clip attribution to the prefix actually reused.
- HiRadix and Unified cache prefetch completion with partial or full insertion deduplication: preserve the completed L3 span.
- Buffer-only staging partially or fully covered by another request: retain fulfilled L3 attribution.
- Buffer-only tail drops due to insufficient capacity, load failure, overlap, or auxiliary-window constraints: retain only the already-covered L3 portion.
- Namespace mismatches, dropped host insertions, and prefixes shortened before the storage span: do not credit invalid L3 hits.
- Existing GPU hits remain L1.
