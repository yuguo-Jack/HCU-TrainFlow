## Original PR description

## Motivation

Move the XPU image to the oneAPI 2026.1.3 patch release, matching sgl-project/sgl-kernel-xpu#537, and pick up the sglang-kernel-xpu 0.5.0 wheel.

## Modifications

- `docker/xpu.Dockerfile`: `intel/deep-learning-essentials:2026.1.2-devel-ubuntu24.04` → `2026.1.3-devel-ubuntu24.04`
- `python/pyproject_xpu.toml`: `sglang-kernel-xpu` wheel `v0.4.0+xpu/sglang_kernel_xpu-0.4.0` → `v0.5.0+xpu/sglang_kernel_xpu-0.5.0` (`cp310-abi3-manylinux_2_38_x86_64`)

PyTorch version is unchanged.

## Notes

- The tag `2026.1.3-devel-ubuntu24.04` is published on Docker Hub (2026-08-31).
- The 0.5.0 wheel is published on [sgl-project/whl v0.5.0+xpu](https://github.com/sgl-project/whl/releases/tag/v0.5.0%2Bxpu).
- PR XPU CI (`pr-test-xpu.yml`) pulls the prebuilt nightly image via `scripts/ci/xpu/xpu_ci_start_container.sh` and does not build `docker/xpu.Dockerfile`. The new base image is first built by `release-docker-intel-xpu-nightly.yml` after merge. To validate before merge:

```bash
docker build -t sglang:xpu -f docker/xpu.Dockerfile .
```

This bump also fixes wrong output with XPU decode graphs at TP > 1, which looks like the root cause of #45034.
