# perf(mla): use native SATFINITE FP8 conversion in MLA KV/Q preparation

[Upstream PR](https://github.com/sgl-project/sglang/pull/42659) · state: closed · merged: True

## Original PR description

## Motivation

The FP8 MLA KV/Q preparation kernel (`set_mla_kv_concat_q`) converts BF16 → FP8 E4M3 with `__NV_NOSAT`. With CUDA 13.4 this lowers to a software (FP64-mediated) conversion; `__NV_SATFINITE` lowers to the native packed `F2FP.SATFINITE.E4M3` instruction and removes most of the kernel's latency.

## Modifications

Change only the conversion mode and its comment.

Semantic change: finite overflow and ±inf now clamp to ±448 instead of becoming NaN; NaN stays NaN. TMA stores, DCP indexing, PDL sync and the launch heuristic are unchanged.

## Accuracy Tests

- Q-output reference checks passed for 1, 8, 32, 64, 128, 512 and 1024 rows.
- Conversion helper checked over all 65,536 BF16 encodings (PDL on/off): non-NaN outputs match the clamped reference bitwise, and NaN stays NaN.
- GSM8K (full 1319, FP8 KV, TP8, with speculative decoding): NOSAT 95.00% vs SATFINITE 94.84% (-0.15 pt, within noise; 28 paired regressions and 26 improvements).

## Speed Tests and Profiling

Kernel microbenchmark (H=12, DCP=1), CUDA-graph warm medians and cold medians after a 512 MiB L2 flush. Measured on SM107 (Vera Rubin); the conversion change itself is not architecture-specific.

| Rows | Warm, SATFINITE vs NOSAT | Cold, SATFINITE vs NOSAT |
|---:|---:|---:|
| 1 | -67.2% | -61.0% |
| 8 | -59.7% | -58.1% |
| 32 | -58.0% | -62.9% |
| 64 | -59.6% | -63.4% |
| 128 | -59.1% | -63.7% |
| 512 | -66.9% | -63.2% |
| 1024 | -67.5% | -59.1% |

NCU confirms native `F2FP.SATFINITE.E4M3`: executed warp instructions drop by 87%.
