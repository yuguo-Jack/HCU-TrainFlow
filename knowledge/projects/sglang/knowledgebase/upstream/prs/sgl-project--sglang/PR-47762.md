# [Fix] diffusion: make VMoBA backend loadable and respect softmax_scale

[Upstream PR](https://github.com/sgl-project/sglang/pull/47762) · state: open · merged: False

## Original PR description

## Problem

`--attention-backend vmoba_attn` could never resolve. `runtime/layers/attention/backends/vmoba.py` and `_VMOBAAttentionBackendResolver.resolve` imported `kernel.attn.vmoba_attn.vmoba`, a path left over from the FastVideo port that does not exist in sglang, so it always raised ImportError.

`softmax_scale` was also dropped: `VMOBAAttentionImpl.__init__` ignored it and `MixedAttention.forward` hardcoded `q.shape[-1] ** -0.5`.

## Changes

- Import from `sglang.multimodal_gen.csrc.attn.vmoba_attn.vmoba` in both places. It is a namespace package, so packaging picks it up. `grep -rn "kernel\.attn" python/` is now empty.
- `moba_attn_varlen` takes `softmax_scale: float | None = None` (None means `head_dim ** -0.5`). It is passed to the self-chunk-only shortcut and to `MixedAttention.apply` as the last arg, stored as `ctx.softmax_scale`, and used in both forward and both backward flash-attn calls. The backend now stores and passes it.
- `generate_data` self-test tensors are now leaf tensors.

Current Wan models use the default scale, so the `softmax_scale` change fixes a latent bug and does not change their output.

## Testing

- CPU (Modal): `test_vmoba_selection.py`, 17 passed, including the new `test_softmax_scale_is_respected`.
- GPU (Modal L40S, torch 2.6, flash-attn 2.7.4.post1): `test_vmoba_selection_gpu.py` 2 passed; `test_vmoba_attn.py` 96 passed, 48 skipped (the test's own chunk-size skip).
- pre-commit on the changed files: clean.
- **Not done: no end-to-end generation.** I could not build a working environment for it. The repo pins torch 2.14, flash-attn has no prebuilt wheel for that torch, and `sgl_kernel` does not load on torch 2.8, which does have one. Importing the backend from an installed package works.

## Follow-ups (not in this PR)

- The VMOBA branch in `DenoisingStage` builds `moba_params` but never calls `attn_metadata_builder.build(**moba_params)` or assigns `attn_metadata`, so generation will still fail there. The kwargs can come from `--attention-backend-config` with a `moba_config` key; FastVideo's `wan_1.3B_77_480_832.json` has the right keys. Needs an end-to-end check by someone with a working flash-attn setup.
- Perf PR for flash-attn `max_seqlen` sizing.
- Issue for `first_full_step` / `first_full_layer` handling in the backend.
