# [Doc] serving: show optional shared admission for background workers

[Upstream PR](https://github.com/sgl-project/sglang/pull/46199) · state: open · merged: False

## Original PR description

Add a runnable OpenAI client and complete configuration for deployments that intentionally put a single-inflight HTTP admission queue in front of SGLang. The example uses [Adaptive Inference v0.2.0](https://github.com/midhatn/adaptive-inference/releases/tag/v0.2.0), preserves the caller's model, generation settings, tools, images and SGLang `extra_body`, and selects background work through a separate client URL.

The documentation explains the tradeoff with native batching and points users who need concurrent scheduling to SGLang's existing scheduler. It also describes pending cancellation, active-response draining, timeout quarantine, and unsupported Responses/native management endpoints. This changes documentation only; no SGLang runtime or dependency is changed.

Validation: six local tests execute the actual documentation snippets through the released gateway and the OpenAI SDK against a deterministic HTTP fixture. They cover both classes, JSON/SSE responses, nested backend paths, preserved request fields, foreign-control rejection, and no automatic retry on 503. These are client/gateway contract tests; no SGLang model inference or throughput comparison was run. Mintlify build validation and broken-link checks passed.

AI assistance was used to prepare this documentation and its local contract tests. 

The standalone [revision/validation receipt](https://github.com/midhatn/adaptive-inference/blob/d6f4e201ba28602189872746922e527c58ed0cbd/integrations/openai-admission/evidence.json) and [executable contract tests](https://github.com/midhatn/adaptive-inference/blob/d6f4e201ba28602189872746922e527c58ed0cbd/integrations/openai-admission/test_recipes.py) preserve this recipe independently of the upstream proposal.
