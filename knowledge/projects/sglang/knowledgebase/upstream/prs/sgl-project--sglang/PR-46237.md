# [Perf] diffusion: Split LTX tiled VAE decode across the decode-parallel ranks

[Upstream PR](https://github.com/sgl-project/sglang/pull/46237) · state: closed · merged: True

## Original PR description

## Motivation

On a multi-GPU LTX server every decode-parallel rank runs the VAE decode, so that the spatial-parallel convolutions can exchange halo rows. `_decode_spatial` only takes that height split when each rank's rows fit in one tile. Otherwise it falls back to `tiled_decode` with the split disabled, and every rank then decodes every tile of the whole frame. On two GPUs both ranks do the same work, and the second GPU adds nothing.

Tiling is on by default (`vae_tiling`), with 512 x 512 tiles, so the fallback is taken whenever one rank's share of the frame is larger than one tile. LTX-2.5's two-stage recipe decodes 1920x1088 (a 34 x 60 latent, 15 tiles): each of two ranks would get 17 x 60 latent rows against a 16 x 16 tile, and both decoded all 15 tiles. LTX-2 and LTX-2.3 hit the same fallback at 1024x1536.

## Modifications

- `models/vaes/ltx_2_vae.py`: `tiled_decode` decodes tiles `r, r + W, ...` on decode-parallel rank `r` of `W`. `_gather_tiles` pads each rank's tiles to the largest tile, all-gathers them over the decode-parallel group in one call, and puts them back in tile order before the blend. Each tile is decoded on its own, so the gathered set is the set a single rank decodes. The split applies when spatial-parallel decode is installed (every decode-parallel rank then runs the decode) and there are at least as many tiles as ranks. Otherwise the decode is unchanged.

Tests:
- `test_vae_spatial_parallel_decode.py`, `test_ltx_tile_shards_gather_back_in_tile_order`: 3 x 5 tiles with a partial last row and column, round-robin over two ranks. The gather returns every tile in order, with its own shape and values.
- `test_ltx_vae_parallel_decode.py` (two ranks over gloo): the `tiled_shard` case now runs the split and still matches the single-rank tiled decode.

## Accuracy Tests

4xB300, LTX-2.5 two-stage (`Lightricks/LTX-2.5-Diffusers`, 1920x1088, 121 frames), `--num-gpus 2 --ulysses-degree 2`, same prompts and seeds. The output MP4s are byte-identical to main for all four requests (md5 `47eb2a29...`, `cfa61144...`, `8f0094d4...`, `3cbba017...`).

## Speed Tests and Profiling

Same setup, synchronized stage timers (`SGLANG_DIFFUSION_SYNC_STAGE_PROFILING=1`):

| | main | this PR |
|---|---|---|
| `LTX2AVDecodingStage` | 2.88 s | 2.10-2.13 s |
| request (client, 3 requests after warmup) | 7.07-8.05 s | 6.31-6.37 s |

Per rank, the decode stage's GPU kernel time went from 1732 ms to 933 ms (torch.profiler, rank 0).
