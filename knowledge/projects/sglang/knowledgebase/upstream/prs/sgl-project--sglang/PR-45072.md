# [Feature] Add GLM-5.3-Flash NVFP4 KV cache on SM90 with FA3

[Upstream PR](https://github.com/sgl-project/sglang/pull/45072) · state: open · merged: False

## Original PR description

## Motivation

GLM-5.3-Flash (`Glm5NextForConditionalGeneration`) has 11 DSA layers with a
512-dimensional latent, no RoPE cache, and a pooled indexer (`index_kpool=4`).
The standard GLM SM90 NVFP4 implementation assumes a 64-dimensional RoPE tail
and a fixed 2048-token decode table. This draft adds a functional compact-cache
path for Flash, while retaining the existing KDA states and FP8 indexer.

## Modifications

- Add 288-byte no-RoPE rows: 256 bytes of E2M1 values plus 32 E4M3 block-16
  scales. Preserve the standard 416-byte layout and per-layer FP32 outer scale.
- Extend codec validation, Triton/reference writers and gather/dequantization,
  pool sizing, hybrid-layer mapping, and global-scale forwarding.
- Select FA3 for Flash prefill/decode on SM90. Dequantize selected rows to BF16
  and preserve the pooled history budget plus up to three tail tokens.
- Limit temporary KV materialization to 64 query sequences per FA3 call
  (about 128 MiB for 2051 selected rows per query), rebasing cumulative lengths
  and preserving query order. The persistent cache remains packed.
- Follow current main's 256-token logical pages / 64-entry pooled index pages.
- Keep unsupported combinations fail-fast: non-SM90, non-BF16 activations,
  incompatible backends/layouts, speculative decoding, PP/CP/DCP, PD,
  HiSparse, HiCache/LMCache, unified memory, and TBO.

This draft includes the prerequisite standard GLM SM90 NVFP4 port from
#31269, authored by [Njuapp](https://github.com/Njuapp) (reference head
`5c3ab6d987bf2d5a78598277e79d5167fc191b53`), as a separate first commit.
That reference PR is unmerged. The Flash changes extend its codec and serving
integration; they do **not** add a fused 512-dimension/288-byte decode kernel.
SM90 computes attention with BF16 operands after dequantization.

Example launch configuration, not executed in this draft (choose TP for your deployment):

```bash
python -m sglang.launch_server \
  --model-path zai-org/GLM-5.3-Flash \
  --tp-size 8 --dtype bfloat16 --kv-cache-dtype nvfp4 \
  --dsa-prefill-backend fa3 --dsa-decode-backend fa3 \
  --page-size 256
```

## Accuracy Tests

No GPU tests, native build, model inference, checkpoint-quality evaluation, or
benchmarks were run for this draft. The new Torch/Triton regression cases are
added but unexecuted. Runtime validation is pending; this is intentionally a draft.

Completed checks:

- 40 host-only configuration/layout assertions using pinned official
  GLM-5.2, GLM-5.3, GLM-5.3-BF16 and GLM-5.3-Flash config snapshots; no Torch
  or serving code was loaded for those checks.
- Python AST parsing, isort, repository-configured Ruff rules/formatting,
  clang-format, and `git diff --check`.

Added coverage includes no-RoPE encoding parity, invalid/padded indices,
layout mismatches, hybrid global-to-local layer/scale mapping, unchanged
indexer/tail dtypes, pooled tail preservation in extend/decode, compact pool
accounting, chunked FA3 metadata rebasing/query order, and CUDA Graph codec replay.
Historical validation of the standard port on an older serving baseline is
not claimed as validation of this rebased implementation or Flash.

## Speed Tests and Profiling

Not run. The FA3 path is a functional implementation with temporary BF16
materialization and extra launches; no latency or throughput improvement is
claimed. A native SM90 no-RoPE fused decode kernel and full-model quality
acceptance remain follow-up work.
