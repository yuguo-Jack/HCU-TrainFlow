# [Fix] Unblock CUDA graph startup for hybrid parallelism

[Upstream PR](https://github.com/sgl-project/sglang/pull/43211) · state: closed · merged: True

## Original PR description

## Motivation

`test_hybrid_dp_ep_tp_mtp.py::Test03` times out during server startup in the weekly H200 suite. With TP=8, `--moe-dense-tp-size 1`, and FlashInfer all-reduce fusion, prefill CUDA graph capture stalls at the 28-token shape. The capture batch bypasses eager padding, leaving different token-shard widths across ranks. The same failure appears in the [October 4 weekly run](https://github.com/sgl-project/sglang/actions/runs/37166616108/job/111330769101) and the August 16 run, on different H200 runners.

Running the rest of the file also exposed a startup OOM in Test12 (V3, attention DP8, DeepEP). DeepGEMM's warmup memory estimate excludes FP8 scale buffers: it estimates 8.375 GiB for a masked GEMM executor whose buffers actually need about 8.485 GiB. With 8.459 GiB available, decode graph initialization fails while allocating the output buffer. Test17 exposes a second omission: DeepGEMM also needs a 112 MiB temporary TMA-aligned LHS scale copy on Hopper. Its executor buffers fit into the 8.498 GiB available, but scale conversion runs out of memory.

## Modifications

- Round prefill capture buckets up using the existing CUDA graph parallelism alignment helper, then sort and deduplicate them. Capture buffers and replay padding use the same aligned buckets. A custom maximum such as 28 tokens rounds up to 32 rather than losing its coverage.
- Include FP32 token and block scale buffers and architecture-specific scale-conversion workspace in all FP8 DeepGEMM warmup memory estimates. Hopper needs a temporary TMA-aligned LHS copy; Blackwell needs packed UE8M0 scales, RHS broadcasting, and any grouped packing fallback buffers. MUSA does not receive the Hopper workspace allowance. The existing budget check can then choose a smaller warmup range before allocating the buffers.
- Add regression coverage for TP8, attention DP, configurations that do not require gathered token buffers, capture/replay at an unaligned custom ceiling, and memory estimates against the actual buffers constructed by every warmup executor and the strided storage needed for scale conversion. The memory test uses meta tensors and includes non-aligned scale dimensions and the V3 OOM shape across Hopper, Blackwell, and MUSA. Remove the redundant warmup-memory comment.

Keep the weekly file's models, launch flags, and accuracy thresholds.

## Accuracy Tests

- **All 60 configurations passed across batches before the architecture-specific review follow-up**, retaining the weekly file's models, launch flags, 64-example / 32-thread MMLU evaluation, and `score > 0.48` threshold. Scores range from **0.546875 to 0.921875**, with request error rate **0** in every configuration.
- Test00–Test09 passed after capture-bucket alignment. They use the BF16 Lite model and are unaffected by the FP8 memory-budget changes. With the Hopper scale-workspace fix, Test10–Test16 passed together (**7 tests**) and Test17–Test59 passed together (**43 tests**).
- Before fixing alignment, Test03 reproducibly stalled at the 28-token capture shape. After alignment it scored **0.625**. Before the budget fixes, Test12 failed while allocating executor buffers and Test17 failed while converting scales, each in both startup attempts. Both now pass without changing launch flags or reducing test coverage.
- Prefill helper suite: **22 tests passed**. The expanded memory regression passes **36 cases**: six executor variants, two shapes, and three architecture settings. It measures meta-tensor storage and live scale-conversion allocations, including the grouped packing fallback. The review follow-up fails 12 Blackwell/MUSA cases on the preceding implementation and passes afterward.
- Real Blackwell scale-conversion probes pass for all three FP8 executors with both direct packing and the grouped fallback, allowing for CUDA allocator rounding. The review follow-up preserves Hopper budgets exactly in **24 comparisons**; the 60-configuration GPU suite was not rerun after this follow-up.
- Applicable pre-commit checks passed.

## Speed Tests and Profiling

Prefill graph capture for the original failing configuration completed in approximately 17 seconds after alignment. No throughput benchmark was run.
