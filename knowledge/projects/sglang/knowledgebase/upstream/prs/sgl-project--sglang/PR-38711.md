# [Fix] observability: Correct speculative FPM timing and decode lengths

[Upstream PR](https://github.com/sgl-project/sglang/pull/38711) · state: open · merged: False

## Original PR description

## Summary

Fix speculative-decoding FPM timing ownership and decode-length statistics. Each result retains its own timing span and immutable count/sum/variance instead of combining overlapped iterations or reading a missing/stale CPU length mirror. Attention-DP ranks with no local requests retain their timed dummy-forward records. Idle heartbeats now follow scheduler state, so a long forward cannot look idle merely because the publisher queue is quiet.

## Implementation

DeviceTimer exposes generic interval observers. FPM timing, schemas and publication live in `forward_pass_metrics.py`; all corresponding test cases and fixtures live in `test_forward_pass_metrics.py`, with one CPU CI registration. The DeviceTimer dependency is imported only for type checking. FPM groups existing intervals by run_batch result, preserves the same-stream check, and carries timing through rank-local PP metadata, including PREBUILT recursion, skipped output communication and the speculative-output relay. PP metadata retains both the upstream forward-time microbatch/KV snapshot and rank-local FPM timing. At _resolve_spec_v2_tokens entry, after existing result-copy synchronization and before settlement, supported EAGLE/EAGLE3/DSPARK paths freeze req.seqlen - 1 statistics on the result. Queued statistics remain a per-rank scheduler-queue snapshot and stay immutable during deferred publication.

Remove unused start/end-event fields and the unreachable monotonic fallback, inline the extra timing context manager with exception-safe sealing, remove duplicate emission-time polling, and skip per-interval elapsed-time calculations when there are no reporters. Algorithm selection is a module-level constant; shared test fixtures replace duplicate fake intervals. Full PP round-trip and skip-output regression coverage remains.

## Overhead

Production adds no CUDA events, GPU kernels, D2H transfers or explicit synchronization. FPM-off keeps the original forward method and skips decode-statistics reduction. FPM-on performs CPU bookkeeping, stream checks, statistics reduction and asynchronous publication. wall_time is the first-start/last-end span of existing instrumented intervals on one stream, including segment gaps; work outside those boundaries is excluded. The FPM v1 wire schema is unchanged. These structural checks do not quantify CPU overhead; the earlier AgentX comparisons remain in the performance-evidence comment.

### Interpretation and limitations

- Total throughput changed **-0.77% (B200)** and **-0.65% (B300)**; output throughput changed **-0.33%** and **-0.49%**. Latency changes vary by percentile. One historical comparison and one ordered pair do not establish zero overhead or a statistical overhead bound; closed-loop runs complete slightly different request sets.
- Both experiments' measured exports report `submission_valid=true` and zero request errors/output-length mismatches. B300 had **3/4 profiling cancellations** at the drain deadline. Its off warmup exported **353 successes plus one empty-content response error**, although the phase progress log counted 354 completed with zero errors; on warmup exported 354 successes and omitted the error-count metric.
- B300 needed a guarded forkserver cleanup during each dataset setup, before measurement. No engine/client source or serving setting was changed. Optional persistent mmap-cache writes failed, while the complete runtime mmap and replay succeeded.
- FPM-on Prometheus exports reported counter-reset warnings whose cause remains unresolved. Affected Prometheus delta/rate statistics are not used in these tables; native FPM counters showed no resets. Observable counter continuity does not rule out drops before sequence assignment.
