# [Perf] Kimi-K3: Enable the fused KDA decode at 6 and 3 heads per rank

[Upstream PR](https://github.com/sgl-project/sglang/pull/47526) · state: closed · merged: True

## Original PR description

## Why?

- `KimiK3DeltaAttention._prepare_fused_decode` accepts only 12 local KDA heads (TP8).
- The fused KDA decode kernel supports 12, 6 and 3 heads (TP8, TP16, TP32), and its kernel test covers all three.
- So at TP16 or TP32 every KDA layer logs "K3 fused KDA decode disabled". Decode then runs three kernels (`causal_conv1d_update`, the delta-rule recurrence, gated RMSNorm) instead of one fused kernel.

## What?

- Check the local head count against the kernel's supported set, now public as `kda_fused_decode.SUPPORTED_HEADS`, instead of a hard-coded 12. The `A_log` and `dt_bias` shape checks use the same count.
- The "disabled" log names the local head count and the supported set.
- The ROCm path is unchanged.

## Verification?

```text
Kimi-K3 at TP16 → 6 local KDA heads

Before: _prepare_fused_decode → A_log.numel() = 6 != 12 → "K3 fused KDA decode disabled"
        → decode: 3 kernels per KDA layer
After:  6 in SUPPORTED_HEADS → _kda_fused_decode_ready = True
        → decode: 1 fused kernel per KDA layer                       (expected)
```

- Reproduce: launch Kimi-K3 with `--tp 16` and search the server log for `fused KDA decode disabled`.

## Test?

- `test/registered/kernels/ops/attention/test_kda_fused_decode.py` already covers the kernel at 12, 6 and 3 heads: **pending CI**.
- `pre-commit run` on the changed files: **observed** passing.
- Kimi-K3 at TP16 on GPUs: **pending**.
