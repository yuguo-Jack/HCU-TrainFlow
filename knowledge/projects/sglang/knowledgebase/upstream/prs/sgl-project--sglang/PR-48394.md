# [Perf] diffusion: Fuse Anima gated residuals during BCG capture

[Upstream PR](https://github.com/sgl-project/sglang/pull/48394) · state: open · merged: False

## Original PR description

## Motivation

Anima executes three gated residual additions per transformer block. In native BCG, each `residual + gate * update` currently captures separate multiply and add kernels. Reusing the existing exact residual kernel at these sites removes 8,400 launches per 50-step CFG request and lowers saved-request E2E by **4.53–4.88%** on B300 in repeated main/before-cleanup/final comparisons.

This improves existing BCG support. Final SGLang remains **4.14–4.65% slower than native vLLM-Omni** on the admitted long-prompt workload; the short-prompt cross-framework quality check fails. Both limitations are retained below.

- Main baseline: `a16830deb5ea5b1e8c9874ad646f3ba95542191c`.
- Before cleanup: `947ae324f519d8c7b0dd0287e641d23850afb81e`.
- Final tested PR head: `535fde6f76ad954d6448847d495e8d4c51e236a8`.
- Original `circlestone-labs/Anima` revision: `f973fc41ec7545364ac9776c2440285f43ff2a30`.
- Components `circlestone-labs/Anima-Base-v1.0-Diffusers` revision: `073c3a9db359c31ad0e8aa268d15775473c2176c`.

## Modifications

- Reuse `residual_gate_add` in one small Anima helper only inside the native BCG context and outside `torch.compile`. All three residual sites call it; eager and compiled execution retain the original expression.
- Extend the existing transformer/Cosmos comparison to exercise the real fused helper in FP32/BF16 × batch1/batch2, including eager calls before and after the BCG context. No duplicate model implementation or new test suite.
- Document the BCG scope and eager constraint in the kernel README. No new kernel, flag, precision policy, shape cache or padding rule.

An initial unconditional fusion was rejected: all four paired eager comparisons regressed 3.21–4.50%, despite GPU kernel savings. The final BCG restriction removes that dispatch cost from replay. The original experiment, failures and CPU diagnosis remain in the archive.

### Native vLLM-Omni control — admitted long workload remains slower

Omni commit `817d4c17feb702289a2d2b2cbacfd594c262b7a7`, Torch2.13.0+cu130 / Diffusers0.40.0, same physical GPU, weights, BF16, inputs and resource budget. SGLang's native conversion preserves all 685 original BF16 tensors byte-for-byte; Omni loads the original checkpoint and identical components. Default `enforce_eager=False`, native attention and **28 actual regional compiled blocks remain enabled**.

An independent 18-engine protocol uses `M M O O F F`, then `M O F F O M` twice. Each engine has one short priming request, short warmup, long quality warmup, long settling warmup, then four formal long requests.
