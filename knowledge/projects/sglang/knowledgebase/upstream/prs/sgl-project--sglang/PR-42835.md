# [Test] rust: Add manual API v1 frontend E2E coverage

[Upstream PR](https://github.com/sgl-project/sglang/pull/42835) · state: open · merged: False

## Original PR description

## Scope

This PR adds one manual real-model E2E test for the Rust HTTP and `sglang.api.v1` gRPC frontends.

Note: The test logically depends on the API v1 implementation in #42118, so this PR must merge after that PR.

## Manual frontend E2E

`test/manual/test_rust_frontend_e2e.py` starts a real Rust frontend plus scheduler/model process and generates its Python client stubs from the checked-out `sglang.api.v1` protobuf definitions.

The generation matrix contains 12 cases:

- Native text and token-ID generation over HTTP and API v1 gRPC, each streaming and unary: 8 cases.
- OpenAI completions and chat over HTTP, each streaming and unary: 4 cases. API v1 does not expose OpenAI chat/completions as gRPC RPCs.

For native generation, the suite compares HTTP and gRPC output, finish reason, usage, cached-token metadata, streaming behavior, and unary response shape.

The suite also covers:

- HTTP health endpoints and typed gRPC `HealthCheck`, `GetModelInfo`, `GetServerInfo`, `ListModels`, and `Detokenize`.
- Invalid HTTP and gRPC requests followed by a successful liveness request.
- Concurrent HTTP/gRPC clients with distinct forced outputs to detect cross-delivery.
- Scheduler-confirmed cancellation for native HTTP, native gRPC, and a two-choice OpenAI HTTP request.
- Active-stream shutdown, child-process and listener cleanup, restart on the same ports, post-restart inference, and idle shutdown/restart.

Run from a source checkout with one GPU, a built Rust server extension, and `grpcio-tools` installed:

```bash
python3 test/manual/test_rust_frontend_e2e.py -v
```

The suite remains manual and is not registered in CI.
