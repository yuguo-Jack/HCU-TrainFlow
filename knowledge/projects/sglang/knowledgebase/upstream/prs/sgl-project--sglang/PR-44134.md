# [sglang-miles] Qwen VL: pass client `input_ids` to `legacy_load_mm_data` so #26555 keeps them

[Upstream PR](https://github.com/sgl-project/sglang/pull/44134) · state: open · merged: False

## Original PR description

**Problem.** On miles' SGLang branch, a Qwen VL request with images ignores the client's token IDs. The server turns them back into text and tokenizes that text again, which can split words differently. So the engine samples from a prompt that differs from the one the trainer scores. On Qwen3.8-27B-VL training runs, 60 to 85 percent of screenshot requests from turn 2 on differed by 1 to 2 IDs. This is the problem reported in [miles#1700](https://github.com/radixark/miles/issues/1700) ("no longer a true TITO path").

Example 1. One split word: the engine re-tokenizes the client's IDs.

```text
sent:  [279, 46587, 62, 327, 1979]   " the mart_" + "adoption" + " model", plus 1 image
now:   ran [279, 46587, 9731, 1979]  62 + 327 merged into 9731, 1 ID short
       the trainer scores 5 IDs; the engine sampled after 4
fixed: ran [279, 46587, 62, 327, 1979], ID for ID
```

**Where in the code** (all on `sglang-miles`).

- The Qwen processor calls the legacy loader without the client's IDs: [`qwen_vl.py:1014-1020`](https://github.com/sgl-project/sglang/blob/6b5f3dfc5a395d6fd56d105c34c8e3542846ca4c/python/sglang/srt/multimodal/processors/qwen_vl.py#L1014-L1020). The call came in [sglang#18781](https://github.com/sgl-project/sglang/pull/18781) ("tmp fix for vlm training: use legacy_load_mm_data for qwen-vl").
- Without them, the exact-token block of [sglang#26555](https://github.com/sgl-project/sglang/pull/26555) is skipped without a warning: [`base_processor.py:1860-1866`](https://github.com/sgl-project/sglang/blob/6b5f3dfc5a395d6fd56d105c34c8e3542846ca4c/python/sglang/srt/multimodal/processors/base_processor.py#L1860-L1866).

**Change.** Pass the client's IDs to the legacy loader (Diff 1). The legacy loader stays, so whatever #18781 fixed still holds. Clients must send one image placeholder per image, as #26555 requires; miles' generate path does that after [miles#4051](https://github.com/radixark/miles/pull/4051). A client that sends N placeholders per image gets the existing fallback warning. The same PR cherry-picks [sglang#44133](https://github.com/sgl-project/sglang/pull/44133) onto `sglang-miles`.

Diff 1. [`qwen_vl.py`](https://github.com/sgl-project/sglang/blob/6b5f3dfc5a395d6fd56d105c34c8e3542846ca4c/python/sglang/srt/multimodal/processors/qwen_vl.py#L1014-L1020) on `sglang-miles`.

```diff
         base_output = await self.legacy_load_mm_data(
             prompt=input_text,
             image_data=image_data,
             video_data=request_obj.video_data,
             audio_data=request_obj.audio_data,
             multimodal_tokens=self.mm_tokens,
+            input_ids=input_text if isinstance(input_text, list) else None,
         )
```

**Model scope.** Qwen VL only. The bug lives only in sglang-miles' Qwen processor.

**Tests.** 2 new tests in `test/registered/vlm/test_qwen_vl_input_ids_e2e.py`, modeled on [`test_token_id_retokenize_e2e.py`](https://github.com/sgl-project/sglang/blob/7dc2930585782c09630d617a510bec08c1724845/test/registered/vlm/test_token_id_retokenize_e2e.py). All pass on Qwen3.8-27B-VL. The model defaults to Qwen2.5-VL-3B-Instruct; `SGLANG_TEST_QWEN_VL_MODEL` points it at another Qwen VL checkpoint. The tests of [sglang#44133](https://github.com/sgl-project/sglang/pull/44133) come with the cherry-pick.

```bash
pytest test/registered/vlm/test_qwen_vl_input_ids_e2e.py
```

- "D" + "escribe" (re-encodes to one token) + " the picture: " + one placeholder + one 64x64 image through `/generate` runs as `len(input_ids) - 1 + N` prompt tokens; the IDs read back with `logprob_start_len 0` equal the sent IDs at every text position, and the image positions are N contiguous positions (the read-back reports the image item's pad value there, not the placeholder ID).
- The same text without the image keeps `len(input_ids)` prompt tokens.

**Results on a real model.** Qwen3.8-27B-VL with this one-line change applied to the engine:

Table 1. Prompt IDs the engine ran, read back with `logprob_start_len 0`.

| Request | Ran as sent? |
|---|---|
| text only | yes |
| split words, no image | yes |
| split words, one placeholder, one image | yes |
| a folded-image placeholder (`" <image collapsed>"`) | yes |
| control: N placeholders per image | no: fell back and merged the split word |

8 agent episodes (1,136 requests) ran ID for ID with 0 fallback warnings. One training run had 0 prompt-length mismatches; without the change most screenshot requests mismatched.

**Question for @yueming-yuan.** What did #18781 fix? If the newer loader now works for Qwen VL training, removing the legacy call is the cleaner change. We kept it because the other path is untested on our side.
