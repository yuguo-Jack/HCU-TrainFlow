# [Refactor] deepseek-v4: Use explicit stage boundaries and row transport

[Upstream PR](https://github.com/sgl-project/sglang/pull/43607) · state: closed · merged: True

## Original PR description

This PR was part of the following stack (oldest at bottom; all merged):

* __->__ #43607
* #43606
* #43605
* #43604

## Motivation

DeepSeek V4/V4.1 CUDA execution manages mHC reads, residual updates, deferred sums and MoE operand movement in model-specific forward paths. Explicit boundary declarations let the same producer completion reach ordinary consumers, PP transfers, graph exits and draft-model exits while preserving the original residual rows.

## Modifications

Use a frozen `msgspec.Struct` for layer invocation metadata and explicitly declare the terminal mHC reader stateless.

Route CUDA attention and MoE outputs through mHC read/update adapters and compute-row transport. Keep DeepSeek-specific gather, return, shared-expert finalization and TBO events/buffers in `models/deepseek_common/moe_transport.py`. The generic `layer_boundary/row_transport.py` defines the source/compute/returned-row contract and completion lifecycle; V4 is currently its only model-family user.

Select explicit CUDA/non-CUDA decoder subclasses. Non-CUDA tuple/HcState and fused execution are grouped in `deepseek_v4_platform_stage.py`, retaining their existing numerical protocols. Include NextN, DSpark, PP receiving stages, late-layer DP and breakable-graph tail handling. Preserve `update_context` through both `StageBoundary.finish` and `StageBoundary.exit` into the row-transport update binder; bind it once for deferred and immediately applied updates.

| Operation | CUDA location |
|---|---|
| Attention output all-reduce | `TransportExit.finish` / `complete_owed`, or consumer read completion fusion |
| DP operand gather | `MoeRowTransport.__init__`, bound during stage prepare |
| MoE all-reduce / shared-expert finalization | `MoeFinalize.complete` |
| DP scatter / reduce-scatter / variable reduce-scatter | `MoeRowTransport.return_output` |
| mHC post | Consumer read completion, `TransportExit._write`, or `FinalRead` |
| TBO issue / wait | Model transport helpers and V4 op strategy |

| Main method / entry | CUDA implementation | Non-CUDA implementation |
|---|---|---|
| Decoder `forward` / `forward_hc_pre_from_prev` | `DeepseekV4CudaDecoderLayer.forward` + `HcRead` / `HcUpdate` | `NonCudaDecoderMixin.forward` / `forward_hc_pre_from_prev` |
| `_run_moe_ffn_dp_sync` | `MoeTransport` / `MoeRowTransport` / `MoeFinalize` | `NonCudaDecoderMixin._run_moe_ffn_dp_sync` using shared transport |
| TBO mHC prepare / post operations | CUDA decoder ops + boundary adapters | Same ops on `NonCudaDecoderMixin` |
| TBO gather / combine operations | Shared DeepSeek transport helpers | Platform ops using shared transport helpers |
| DSpark stage forward / FFN | CUDA DSpark stage + boundary completion | `NonCudaDSparkMixin` |
| AMD fused model loop | Not used | Platform fused-boundary functions called by AMD model helpers |

## Accuracy Tests

- Before this restack: affected CPU suite 470 passed, 21 skipped, 7,363 subtests; H200 Hopper/cache/dual-stream GPU tests 18 passed, 32 deselected, 2 subtests.
- GB300 comparisons against fixed main `72730d6360` matched for V4 TP2 decode graph, V4.1 TP4/DP4 late-layer shared experts, V4.1 DSpark serial decode graph and V4 NextN serial decode graph.
- A fresh main/final TP4/EP4/DP2 BF16 DeepGEMM comparison matched with eight actual TBO executions on each side. DP-padded child rows were even. Without DP and with attention gather disabled, the scheduler did not prepare TBO children, so this is not evidence of an uneven-row TBO execution.
- All GPU results above used reduced synthetic models with dummy weights and real kernels/collectives. They predate this restack. Model-specific adapter files are unchanged. The latest revision corrects shared reader callback binding and row-transport update-context forwarding, with CPU regressions; the older GPU runs do not validate these new API fixes. Current CPU and hooks results are recorded below.

## Limits and Follow-up

- DSpark attention completion uses the attention-TP group when `1 < attn_tp < tp`; main may use the full TP group. Reachability and complete numerical validation of that non-default configuration remain open, so universal numerical equivalence is not claimed.
- Model, DSpark and NextN still select different platform call signatures/state at some call sites. Non-import `_is_cuda` lines remain 31 / 7 / 2 respectively. A unified single-layer calling contract and platform naming cleanup remain follow-up work; this PR does not claim the CUDA path's overall complexity is reduced.
- CUDA transport scope still covers return/update, while the non-CUDA synchronous scope ends after compute. Static sum guards, bound-update TBO splitting and per-call next-boundary construction also remain open.
- Non-CUDA hardware, full-weight accuracy, PD + CP4 and formal performance acceptance are unverified. CPU orchestration coverage does not substitute for AMD/NPU/XPU hardware validation.

## Speed Tests and Profiling

No speedup or formal no-regression claim. Existing synthetic-model timing samples and host profiles are diagnostic only.

## Current Stack Validation

All three updated adapter commits passed pre-commit independently; the two K3 commits are unchanged. The final stack CPU suite passed **481 tests and 7,409 subtests**, with **21 hardware-specific skips**. Independent common-layer and Inkling boundary suites passed **372 tests / 7,315 subtests** and **386 tests / 7,329 subtests**, respectively.

Four new regressions fail on the prior implementation and pass with the fixes. They cover terminal export releasing state retained by an old output handle (including a failing final norm), terminal reader binding for written/pending/fused output with two contexts, rejection and cleanup when binding changes read capabilities, and rejection of bindable update results on both immediate and deferred exit paths. Existing tests cover the converted containers, short-convolution positions and stateless V4 terminal reads.

The earlier callback-selection, transformed-reader and row-transport context regressions remain covered. No GPU tests or formal performance benchmarks were rerun for these fixes; prior GPU evidence retains its stated limitations.
