# [Fix] Keep profiler state consistent across start/stop requests

[Upstream PR](https://github.com/sgl-project/sglang/pull/40182) · state: closed · merged: False

## Original PR description

## Motivation

Profiler state can outlive the request that should reject, replace, or stop it:

- An immediate start ignores `_init_profile()`'s active-session rejection and overwrites the existing profiler handle.
- Replacing a pending `start_step=3` request with an immediate start retains the old trigger; step 3 starts another profiler and overwrites the new session's handle.
- An explicit stop during stage-based capture succeeds, but the next stage starts profiling again because the stage trigger remains armed.

## Modifications

Respect initialization failures, assign the deferred-start counter on every accepted initialization, and disarm stage/stop targets after a successful explicit stop. Internal automatic stops retain the stage configuration, so normal prefill-to-decode transitions still work.

Consolidate the registered CPU coverage into one lifecycle test file with a shared fixture. Include a combined sequence that stops a stage session, replaces a deferred request, rejects another active start, and then stops without rearming.

## Scope

Stopping while inactive still returns failure, including when a capture is pending; this does not add a cancellation API. Backend rollback, stop exception handling, V2 semantics, and speculative stage classification are unchanged.

#39506 handles memory snapshots; #39733 aggregates worker replies. #35115 changes trace export and explicit-stop replies asynchronously, so its eventual integration must coordinate when triggers are disarmed; that combination is not validated here.
