# [Perf] [NVIDIA] deepseek-v4.1: Align BF16 prefill indexer score width

[Upstream PR](https://github.com/sgl-project/sglang/pull/45794) · state: closed · merged: True

## Original PR description

## Motivation

The DeepSeek V4.1 Torch prefill indexer computes BF16 scores over request-local compressed keys. On H200, unaligned visible lengths such as 28,799 and 57,343 are significantly slower than nearby 64-aligned lengths.

Padding the score width to a multiple of 64 improves GEMM alignment while preserving the logical scoring range.

## Modifications

- Restore request-row mapping from per-request local token counts when `req_rows` is `None` under CP.
- For BF16 device tensors with a visible length of at least 1,024, pad the dequantized index-key tensor to a multiple of 64 once per request and reuse it across query chunks.
- Calculate query chunk sizes using the padded width to respect the existing score-tensor memory budget.
- Slice scores back to the logical visible length before causal masking and top-k selection, so padded positions cannot enter selection.

## Accuracy Tests

Local validation on DeepSeek V4.1 Flash:

- 20 CP request-row mapping cases passed.
- 12 score-shape and boundary cases using model-style FP4 inputs passed with exact agreement on valid columns.
- 8 Prefill integration cases passed with exact raw-index and KV-slot writeback agreement.
- 8 synthetic arithmetic/retrieval probes at approximately 32K and 64K context lengths matched the reference outputs.

GSM8K, 1,319 examples per run:

| Configuration | Accuracy | Request error rate |
| --- | ---: | ---: |
| Fresh baseline, run 1 | 96.74% | 0% |
| Fresh baseline, run 2 | 96.36% | 0% |
| Optimized | 96.74% | 0% |

The baseline A/A runs show run-to-run variation. These results do not establish bitwise equivalence of complete generated outputs or replace representative long-context quality evaluation.

## Speed Tests and Profiling

### Setup

- Model: DeepSeek V4.1 Flash.
- Hardware: 8 × NVIDIA H200.
- Prefill: TP4 / CP4 / EP4.
- Decode: TP4 / DP4 / EP4.
- Prefill BCG: disabled.
- Decode and router processes held fixed across comparisons.

Both baseline and optimized runs include the same CP request-row mapping fix. The measured differences therefore isolate the score-width alignment change.

### End-to-end benchmark

Primary workload: all input 65,536, cache hit rate 50%,70%,90%, output 512 tokens.
Results are means of three runs with 512 requests each and 10 warmup requests per run.
