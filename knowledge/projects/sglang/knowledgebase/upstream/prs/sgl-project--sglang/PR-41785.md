# Fix tokenize responses to report the server context limit

[Upstream PR](https://github.com/sgl-project/sglang/pull/41785) · state: closed · merged: False

## Original PR description

## Motivation

With `--context-length 1024`, `/tokenize` and `/v1/tokenize` can report the tokenizer's 131072-token limit, even though the server only accepts 1024. This gives clients the wrong limit. Fixes #41748.

## Modifications

Return the server's context length in both tokenize endpoints. Add a regression test for text, batched text, and chat messages.

## Accuracy Tests

- Local MLX `TestTokenizeDetokenize`: 6 passed with a 1024-token server limit.
- CPU checks with smaller, larger, and unlimited tokenizer limits: 6 passed; token IDs unchanged.
- `pre-commit run --all-files` passed with Rust-only hooks skipped (no Rust changes). CUDA/AMD tests are pending CI.
