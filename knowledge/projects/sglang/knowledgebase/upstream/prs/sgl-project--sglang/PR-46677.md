## Motivation
DeepSeek-V4.1's checkpoint stores `wo_a` as fp8 with 32x32 block scales (`weight_block_size: [32, 32]`, `scale_fmt: ue8m0`). On ROCm, sglang's fp8 `wo_a` path only took DeepSeek-V4's 128x128 blocks, so V4.1's `wo_a` is dequantized to bf16 at load and runs as a bf16 batched GEMM (split-K partial + reduce on decode), reading twice the weight bytes of the fp8 checkpoint.

aiter now supports this fp8 shape: `batched_gemm_a8w8_mxscale_bpreshuffle` runs 32x32 block scales on gfx950 and ships tuned configs for V4.1's `wo_a` shapes (ROCm/aiter#5896).

This PR switches V4.1's `wo_a` to that kernel: the fp8 weight is kept as is, re-laid out at load, and the activation is quantized per 32 to match.

## Modifications
DeepSeek-V4.1's `wo_a` is fp8 with 32x32 blocks. To wire it up, the weight is shuffled into the (16, 16) layout at load time, leaving the fp8 values and e8m0 scales unchanged; in forward, the activation is quantized per 32 and the GEMM runs on aiter's `batched_gemm_a8w8_mxscale_bpreshuffle`. The scale shape decides which GEMM is used, so DeepSeek-V4's 128x128 path is unaffected.
