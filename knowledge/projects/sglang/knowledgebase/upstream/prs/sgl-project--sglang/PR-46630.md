# [Perf][DSA]: Cut MTP decode overhead with live-length-bounded replay metadata and a greedy-draft argmax exchange

[Upstream PR](https://github.com/sgl-project/sglang/pull/46630) · state: open · merged: False

## Original PR description

## Motivation

With MTP on DSA models (GLM-5.x, DeepSeek-V3.2), every decode step pays costs that scale with `--context-length` and the vocab rather than with the live work:
- The replay metadata kernels launch one program per 128 columns of the context-wide page table: 8193 per row at the default 1M context.
- The MTP draft-decode replay precomputes into a full-width scratch table, then copies it into every step backend.
- Each greedy draft step all-gathers `rows x vocab` logits only to take an argmax.

## Modifications

- **[DSA] Bound the replay metadata kernels by the live KV length.**
  - Adds bounded variants of the decode, target-verify and draft-extend replay metadata kernels (`kernels/ops/attention/dsa_metadata_bounded.py`).
  - Each request gets at most `min(budget / rows, 256)` programs, which stride over its live column blocks.
  - The grid depends only on (rows, width, budget), so it stays CUDA-graph safe.
  - Outputs are bit-identical to the unbounded kernels.
  - Used on CUDA with kpool 1 and without KPool metadata fusion.
- **[DSA] Write the MTP draft-decode replay metadata in one bounded launch.**
  - `DeepseekSparseAttnMultiStepBackend` writes each step backend's graph metadata straight from `req_to_token`, in one bounded launch for up to 4 steps. This replaces the precompute + full-width copies.
  - Draft steps seeded with the draft-extend top-k no longer run their DeepGEMM schedule refresh, which they never used.
  - Enabled per captured bs, only when the step backends' tables match.
- **[Spec] Greedy EAGLE drafts: exchange vocab-shard argmax partials instead of gathering logits.**
  - For topk=1 drafts, each TP rank reduces its LM-head shard to per-split argmax candidates, 4 exact fp32 lanes each.
  - The TP sum all-reduce exchanges the candidates. A one-warp finalize then picks the token with the same tie and NaN rules as the gathered path.
  - Tokens, `topk_p` and positions are bit-identical, inside the draft-decode and draft-extend CUDA graphs.
  - Draft `LogitsProcessor`s opt in through `enable_draft_argmax_exchange()`.
  - The gather is kept for non-vocab-parallel heads, softcapping, DP attention, and when the all-reduce would run on NCCL.

**Flags (kill switches, both default on):**
- `SGLANG_DSA_BOUNDED_REPLAY_METADATA=0` turns off the first two commits.
- `SGLANG_SPEC_DRAFT_ARGMAX_EXCHANGE=0` turns off the third.

**Related:**
- #44358 shares one metadata buffer set across MTP draft steps; if it lands, the second commit reduces to a single-destination bounded write.
- #37106 and #41172 take other approaches to the greedy-draft argmax.
- #46211: its `_fused_draft_extend_tail_eligible` reads `next_token_logits`, which is `None` when the exchange is engaged, so it should decline when `next_token_argmax_partials` is set.
