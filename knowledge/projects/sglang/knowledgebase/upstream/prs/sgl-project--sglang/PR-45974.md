# [CI] unit-test: Run the fused FP8 writer HIP test in the CPU suite

[Upstream PR](https://github.com/sgl-project/sglang/pull/45974) · state: closed · merged: False

## Original PR description

## Problem

`test/registered/unit/layers/attention/test_fp8_fused_writer_hip.py` registers itself for a suite that does not exist:

```python
register_amd_ci(est_time=2, suite="stage-a-test-cpu-amd")
```

`stage-a-test-cpu-amd` appears nowhere else in the tree. It is not in `PER_COMMIT_SUITES[HWBackend.AMD]`, not in `NIGHTLY_SUITES`, and no workflow passes it to `test/run_suite.py`. Since `filter_tests()` selects by exact suite name, no gating job has ever collected this file; the only place it is executed today is the non-gating daily coverage run, which walks `test/registered/unit/` with pytest.

The existing guard does not catch this: `validate_all_suites()` skips `HWBackend.AMD` and `HWBackend.NPU` (`_SUITE_CHECKED_BACKENDS`), because those backends also carry suites that are defined only inside their nightly workflows. So the misregistration stays silent.

## Fix

Register the file to `base-a-test-cpu`, which is what every other test in `test/registered/unit/layers/attention/` uses. The test needs no GPU - it only exercises the wrapper's validation paths and CPU tensor helpers, and returns before the `aiter` import:

- `test_geometry_gate` - pure geometry predicate
- `test_available_rejects_mi300` - patches `is_gfx95_supported`
- `test_prepare_aiter_rope_caches_squeezes_cpu_tables` - CPU tensors
- `test_refuses_non_fp32_layernorm` / `test_refuses_wrong_geometry` - raise before `from aiter.ops.cache import ...`

## Verification

```
$ pytest test/registered/unit/layers/attention/test_fp8_fused_writer_hip.py -q
5 passed
```

## Related, not fixed here

Seven unit tests under `test/registered/unit/npu/` register to `stage-a-unit-test-npu`, which is also never dispatched - the NPU Stage-A job runs `--suite base-a-test-npu`. I left them out of this change because two of them no longer match the implementation and would turn the NPU gate red if wired up as-is:

- `test_npu_mla_preprocess.py::TestIsFiaNz::test_fia_nz_without_mlapo_raises` expects an `AssertionError`, but `is_fia_nz()` now documents and implements independence from MLAPO.
- `test_npu_mxfp8_linear.py::TestNPUW8A8BlockFP8Linear::test_rejects_non_ue8m0_scale_format` expects a `ValueError` for `scale_fmt`, which `process_npu_arch35_mxfp8_linear_weights` does not raise - it treats every non-`ue8m0` value as the e4m3 path.

Happy to follow up on those once the intended behavior is settled.
