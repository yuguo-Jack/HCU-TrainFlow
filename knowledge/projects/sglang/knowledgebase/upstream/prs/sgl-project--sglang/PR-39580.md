## Motivation

<!-- Describe the purpose and goals of this pull request. -->
I met data corruption on 4\*A100 `Qwen3-30B-A3B`, and 8\*L20 `Qwen3-235B-A22B-Thinking-2507-FP8` when enabling EPLB:

```
python3 -m sglang.launch_server \
  --model-path /data/Qwen3-235B-A22B-Thinking-2507-FP8 \
  --host 0.0.0.0 \
  --port 30000 \
  --tp-size 8 \
  --ep-size 8 \
  --disable-custom-all-reduce \
  --enable-eplb \
  --ep-num-redundant-experts 8 \
  --eplb-rebalance-num-iterations 100 \
  --expert-distribution-recorder-mode stat \
  --log-level info \
  2>&1 | tee eplb-qwen3-235b.log


python3 -m sglang.launch_server \
  --model-path /mnt/disk4/abc/Qwen3-30B-A3B \
  --host 0.0.0.0 \
  --port 30000 \
  --tp-size 4 \
  --ep-size 4 \
  --disable-custom-all-reduce \
  --enable-eplb \
  --ep-num-redundant-experts 4 \
  --eplb-rebalance-num-iterations 100 \
  --expert-distribution-recorder-mode stat \
  --expert-balancedness-report-mode server_log \
  --log-level info \
  2>&1 | tee eplb.log
```

When the prompt's `max_tokens` exceeds the `--eplb-rebalance-num-iterations`, the answer turns to be corrupted at the tail of the output after the rebalance.
