# [AMD] [Kimi-K3] Fix bf16 SSM decode under HIP graphs

[Upstream PR](https://github.com/sgl-project/sglang/pull/41570) · state: open · merged: False

## Original PR description

## Motivation

`--mamba-ssm-dtype bfloat16` on Kimi-K3 writes bad KDA outputs into the MoE when HIP graphs are on. `--disable-cuda-graph` hides it: the eager path does not pad `query_start_loc` the same way.

Default path. Kimi-K3 always sets `lower_bound`. The old gate took packed T=1 only when `lower_bound` was unset, so decode used the varlen kernel. Graph replay pads `query_start_loc` to a plateau such as `[0, 1, 2, 2, 2]`. Those T=0 rows were left uninitialized.

Fused path (`SGLANG_K3_KDA_FUSED_BACKEND=aiter`). Graph capture loaded a bf16 SSM pool as f32. The recurrence is fp32; the pool load and store were the wrong width.

## Modifications

Default path:

- Packed T=1 implements `lower_bound`. `TritonKDAKernel` sets `supports_packed_decode_safe_gate`, so Kimi-K3 stays on packed decode. Packed writes zeros for padded slots.
- The varlen kernel writes zeros for T=0 rows. Pad rows share one `bos`, so each later pad row is also zeroed at its own index. A real earlier token is not touched.
- Compile both SSM dtypes before HIP graph capture.

Fused path:

- Recurrence stays fp32.
- A bf16 pool is loaded and stored as bf16x8, so each gfx950 buffer copy stays 16 bytes. The K tile follows the pool dtype: 8 values for bf16, 4 for fp32.
- Compile both SSM dtypes and the batch-2 kernel before capture.

Tests:

- Packed bf16 graph replay with `lower_bound` and padded slots, bit-exact with eager.
- Varlen graph padding: every T=0 row is zero, and a real row is not.
- Fused graph replay keeps the existing fp32 batch-2 case and adds bf16 at batch 1 and batch 2. One bf16 batch-1 run also checks the output against the reference.

## Accuracy Tests

Full model, gfx950, HIP graphs on. Scores are concurrency 4 / 64.

| --- | --- | --- |
| GSM8K | 0.51 / 0.88 | ~0.965 / ~0.965 |
| NIAH | 0.0 / 0.0 | 0.91 / 0.86 |

## Speed Tests and Profiling

The fp32 decode path is unchanged. A bf16 SSM pool is half the state bytes. On MI355X TP8 Kimi-K3 this is about 1% decode.
