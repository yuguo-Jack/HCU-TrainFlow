# [diffusion] quantization: packed Q/K/V projection for convrot_int8's comfy_kitchen backend

[Upstream PR](https://github.com/sgl-project/sglang/pull/44208) · state: open · merged: False

## Original PR description

<h2 id="motivation" data-pm-slice="1 3 []">Motivation</h2><p>Qwen-Image 2.1's <code>QwenImage21Attention</code> projects Q/K/V from one activation with three separate <code>[C, C]</code> linears. <code>convrot_int8</code> has two kernel backends:</p><ul data-spread="false"><li data-label="•" data-list-type="bullet" data-spread="false"><p>the JIT / <code>customkernel</code> backend (CC 9.0 / 10.0 / 12.0 / 12.1), which #38040 already gives a <em>fused</em> single rotation + activation quantisation for q/k/v sharing one input;</p></li><li data-label="•" data-list-type="bullet" data-spread="false"><p>the <code>comfy_kitchen</code> backend, which serves the GPUs the JIT ops do not build for (CC 8.x Ampere/Ada, CC 10.3) and has <strong>no</strong> equivalent: every attention block pays two redundant ConvRot activation quantisations and issues three narrow GEMMs.</p></li></ul><p>On a GPU with no FP8/NVFP4 tensor cores -- A100 (CC 8.0), RTX 30/40-series -- the <code>comfy_kitchen</code> backend is not a fallback, it is the <em>only</em> INT8 path, so this gap is real there.</p><h2 id="modifications">Modifications</h2><ol data-spread="false"><li data-label="1." data-list-type="ordered" data-spread="false"><p><code>layers/quantization/convrot_int8_comfy_kitchen.py</code>: the fused kernel <code>apply</code> ran inline moves to a module-level <code>int8_linear(x, weight, weight_scale, group_size, bias=None, split_out_features=None)</code>, and <code>apply</code> becomes a thin adapter. This is a <strong>pure refactor</strong>: the op, its argument order and its numerics are unchanged, and there is now a single place for the row-split cap. <code>split_out_features</code> lets a packed caller judge the row-split heuristic on the per-projection width instead of the packed width.</p></li><li data-label="2." data-list-type="ordered" data-spread="false"><p><code>models/dits/qwen_image21.py</code>: teach the existing bf16 packing to also cover <code>convrot_int8</code>. The three int8 <code>[C, C]</code> weights and the matching <code>[C, 1]</code> fp32 row scales are re-homed onto one <code>[3C, C]</code> / <code>[3C, 1]</code> storage each, and <code>_project_qkv_packed_convrot_int8</code> projects all three through a single <code>int8_linear</code> call. A new <code>BitExactFusionGate</code> verifies the first call against the module forwards and falls back on any mismatch, so the packed path can only ever be used when it is bit-exact.</p></li><li data-label="3." data-list-type="ordered" data-spread="false"><p><code>test/unit/test_qwen_image21.py</code>: four new unit tests -- storage sharing keeps values and shares one storage; the packing predicate requires the <code>convrot_int8</code> method; the consecutive-slice view rejects gaps and separate storages; the packed <code>int8_linear</code> call is bit-exact against the separate per-projection calls at production shapes.</p></li></ol><h2 id="accuracy-tests">Accuracy Tests</h2><p>Packed call is bit-exact against the separate calls (<code>max_abs = 0.0</code>); <code>cat(quantize(W_i))</code> equals <code>quantize(cat(W_i))</code> exactly. End-to-end on A100 GPU 0 (1024x1024, 40 steps, CFG 1, seed 42), the output PNG md5 is <strong>identical</strong> to the frozen INT8 baseline: <code>05288a62012b1353230d53c3297cb67c</code>. The whole flow is inside the existing bit-exact gate, so an unexpected mismatch disables the fusion rather than changing the output.</p><h2 id="speed-tests-and-profiling">Speed Tests and Profiling</h2><p>A100 GPU 0 (CC 8.0, <code>comfy_kitchen</code> backend), Qwen-Image 2.1, 1024x1024 @ 40 steps, CFG 1:</p>
arm | denoise | per step | output md5
-- | -- | -- | --
convrot_int8, unpacked QKV | 9.059 s | -- | 05288a62...
convrot_int8, packed QKV (this PR) | 8.796 s | 0.220 s | 05288a62...

<p>Kernel level (M=4114, C=4096, group_size=256): 1.263 ms -&gt; 1.005 ms per attention block (-0.257 ms/block, -8.2 ms/step); the whole saving is the removed ConvRot work.</p><p>Scope: on JIT-capable GPUs (H100/H200/Blackwell) the equivalent fusion already exists via the <code>customkernel</code> backend, so this PR is a backend-parity change with no effect there.</p><h2 id="checklist">Checklist</h2><ul data-spread="false"><li data-item-type="task" data-label="•" data-list-type="bullet" data-spread="false" data-checked="true"><p>Format your code according to the pre-commit guide.</p></li><li data-item-type="task" data-label="•" data-list-type="bullet" data-spread="false" data-checked="true"><p>Add unit tests.</p></li><li data-item-type="task" data-label="•" data-list-type="bullet" data-spread="false" data-checked="true"><p>Update documentation / docstrings as needed.</p></li><li data-item-type="task" data-label="•" data-list-type="bullet" data-spread="false" data-checked="true"><p>Provide accuracy and speed benchmark results.</p></li></ul>
