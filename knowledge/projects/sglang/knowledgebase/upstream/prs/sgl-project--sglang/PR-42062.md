# [Bugfix] Preserve multimodal cache entries when an item cannot fit

[Upstream PR](https://github.com/sgl-project/sglang/pull/42062) · state: closed · merged: False

## Original PR description

## Motivation

`MultiModalStaticCache.set` evicts existing entries before discovering that a new embedding exceeds the entire byte budget. The new entry is rejected, but all previous cache hits are lost. This can happen with an oversized image/video request under `SGLANG_VLM_CACHE_SIZE_MB`.

## Modifications

Reject an oversized entry before eviction. Keep the existing duplicate-key behavior and size calculation, so an admissible slice backed by a larger storage can still be cloned into the cache. Add byte-budget, LRU, duplicate-key, view, and zero-capacity regressions.

## Accuracy Tests

- Four CPU test methods pass; the original code fails four subcases covering retained entries/LRU and exact/zero-capacity caches.
- Actual direct-encoder/cache source reproduction: requests for a small item, an oversized item, then the same small item invoke the encoder three times before and twice after, with identical outputs.
- Local validation loads the unchanged source definitions while excluding GPU-facing package initializers; the model boundary returns real CPU tensors. No GPU/model inference run is claimed.
- Touched-file pre-commit hooks pass, including CPU test registration.

## Speed Tests and Profiling

The reproduction checks avoided encoder calls, not GPU throughput or latency.
