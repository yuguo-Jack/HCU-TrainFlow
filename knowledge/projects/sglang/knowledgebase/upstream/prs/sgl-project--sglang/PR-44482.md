# [Feat] radix-cache: Add --system-prompt fixed-prefix optimization for hybrid Mamba models

[Upstream PR](https://github.com/sgl-project/sglang/pull/44482) · state: open · merged: False

## Original PR description

## Motivation

This optimization targets **offline bulk processing** (batch annotation /
enrichment over a document library): a large batch of requests is fired at
a static model, **every request is fully independent** — single-turn, no
conversation history is ever reused — and **all requests carry the
identical fixed system prompt**, often thousands of tokens.

In this scenario the system prompt is the *only* content shared across
requests, which breaks the assumptions the radix cache normally relies on:

- **Full-attention models**: the shared system-prefix KV is reused, but
  every request's unique suffix is *also* inserted into the radix tree on
  finish. Since no request is ever seen twice, those suffix entries are
  pure waste — they occupy KV pages and evict useful entries until the
  batch ends.
- **Hybrid Mamba / linear-attention (SSM) models** are worse: every request
  holds a running state slot plus ping-pong tracking slots for radix
  donation, so `max_running_requests` is capped to
  `max_mamba_cache_size // 3` (ratio 3). Each finished request also donates
  its per-request suffix state into the tree, evicting the shared
  system-prefix state it just helped create.

When the deployment has a fixed system prompt, all requests can share one
chunk-aligned boundary state instead:

- warm requests hold **1 running slot** (no ping-pong, no suffix
  tracking/donation) → the mamba ratio drops from 3 to **1**, i.e. **3x
  more concurrent requests** on the same state pool;
- the per-request suffix KV and mamba state are **freed, not cached** →
  the radix tree stays tiny (exactly one shared system-prefix node), and
  suffix state never evicts the shared boundary state.

## Modifications

New flag `--system-prompt <text-or-file-path>` (inert when unset — every
patched site checks the boundary first, default behavior is
byte-identical). The system text is injected as the first chat message for
requests that carry no system role, so batch clients can omit it from
every request and save the per-request payload.

Three layers:

**Tokenizer layer** (`srt/system_prompt/`, new package):
- `SystemPrefix` renders the system block once and caches its token ids;
  each request becomes `cached_prefix_ids + ids(rest)`. A one-time
  token-identity probe verifies `prefix + ids(rest) == ids(full)` with three
  strategies (explicit bare-system render → measured length-difference →
  auto-strip for templates that inject a default system block, e.g.
  Qwen2.5-VL). On any mismatch, prefix caching silently disables itself and
  the caller falls back to a single full render — output stays
  byte-identical.
- The injected system text is padded with single-token fillers so the
  prefix length is a multiple of `mamba_cache_chunk_size()` (linear-attention
  state only checkpoints at chunk boundaries).

**Scheduler layer**:
- Warm/cold is a runtime property: the first request (empty tree) and
  post-eviction requests are cold and keep the full ping-pong + tracking
  path to (re-)capture the shared boundary state; everything after is warm
  (`is_system_prefix_warm`) and skips ping-pong allocation, suffix
  tracking, and donation.
- `Req.__init__` seeds `mamba_branching_seqlen` from the boundary;
  `init_next_round_input` re-derives it after prefix match so the seed
  survives the empty-tree first pass (otherwise the finish-time donate
  would poison the shared boundary node).
- Admission (`_mamba_gap_budget_for_req`), slot counting
  (`ensure_mamba_capacity`), alloc, lazy prealloc, and decode track masks
  all charge/filter warm requests consistently (warm = 1 slot, cold =
  `1 + mamba_initial_tracking_slots`).
- Warm requests get a sentinel ping-pong buffer pointing at reserved slot 0
  (never handed out by the allocator, filtered on free) so index consumers
  stay in bounds without a real allocation.

**Cache layer**:
- The radix tree key is truncated at the page-aligned boundary
  (`_system_kv_cap`); suffix pages are still freed → no pool leak, and the
  tree retains exactly one shared system-prefix node.
- Mamba donate length is capped at the boundary → suffix donates hit
  `mamba_exist` and are freed, never stored.
- `kv_cache_configurator`: with `--system-prompt` the mamba ratio is forced
  to 1, with a 2-slot reserve for the shared boundary state + evict/COW
  headroom.

## Accuracy Tests

- 29 CPU unit tests in `test/registered/unit/test_system_prompt.py` covering
  prompt resolution, chunk alignment, all three token-identity probe
  strategies, the warm/cold predicate, donate capping, boundary
  seeding/reseeding, and the radix key cap.
- The token-identity probe is itself the output-correctness guard: any
  template that cannot be split byte-identically disables the optimization
  and falls back to the full render, so generated tokens are unchanged by
  construction.

single-turn requests, identical fixed system prompt on every request),

## Update: production-verified fix chain added

The new commits (49e54ff289..93356ed393) are a chain of fixes for issues found when this feature ran in a production deployment (internally, on the v0.5.17-based release). They are backported onto this branch with adaptations to current main (the internal branch predates the `ReqKvInfo` migration and the removal of the `MAMBA_STATE_PER_REQ_*` constants). Summary, in causal order:

**1. Unaligned boundary crash (49e54ff289)** — the original padding-up alignment altered the token stream and a boundary that fails the identity probe at request time left the mamba pool sized for the warm steady state while every request stayed cold (over-admission crash). Now:
- The shared prefix is truncated **down** to the chunk grid instead of padded up — the full token stream stays byte-identical to the native render (the removed tail is re-prefilled per request, giving up only its cache reuse).
- A startup probe (`probe_system_prefix_or_disable`) runs **before any subprocess forks**: on probe failure the flag is cleared so pool sizing and runtime behavior stay consistent (feature-off everywhere).
- A slot-count admission budget is added for the static (non-shared) hybrid mamba pool.

**2. Phantom evictable credit (80e25e3750)** — the static-pool budget counted `mamba_evictable_size()`, but the match-time COW can only draw from the hard free list (its evict-retry can be blocked by locks on the shared boundary node). Now hard free slots only.

**3. Waiting-queue throttle (6a6f6ffacc + e29f58503d)** — the match-time mamba COW allocates the request's running slot *before* `add_one_req` can reject it, so a deep waiting queue drained the hard free list and died on free=0. The scheduler now stops pulling new requests once the remaining slot budget can't cover a worst-case cold request (`_mamba_match_headroom`).

**4. Audit logs (a08d87f9e0 + 092a49ec50)** — periodic `[MambaAudit]` lines reconcile the physical pool state against logical holders; made slot leaks and the crash root cause observable.

**5. Budget blind to match-time COW (1bf88bde57)** — the slot budget keyed on `mamba_pool_idx is None`, but the match COW sets that field *before* the budget runs, so every queued request was charged zero while its COW drained the free list. Fixed by sampling `fresh_cow` pre-match. Also: the warm sentinel ping-pong buffer is guarded against decode post-processing (it would otherwise free reserved slot 0 into the allocator), the token-concat fast path only engages when the leading system message content equals the fixed prompt (a client-supplied different system must not be silently replaced), and a per-request render failure now falls back to the full render instead of raising.

Unit tests grew from 29 to 44 cases covering the truncate-down invariants, the startup probe gate, the static-pool budget, the match headroom, and the fresh_cow accounting.
