## Original PR description

Ten validated serving optimizations for GLM-5.3-Flash, from a 4xGB300 benchmark campaign against vLLM (fixed workload: 80 random-token requests, chat 1000/1000 and summarization 8000/1000 at concurrency 1/16/80, natural NEXTN 5-1-6, TP4/EP1, FP8 KV).

- JustinTong0323 · comment · 2026-10-13T02:17:34Z · [source](https://github.com/sgl-project/sglang/pull/39422#issuecomment-6136758579)

Closing: the remaining value of this PR no longer justifies keeping it open.

**Measured outcome (2026-10-12, GLM-5.3-Flash, 4x B300, trtllm MoE, sim acc 3.00):** after updating the branch onto current main and fixing two gate bugs that prevented the glue from ever engaging (Glm5Next's text_config carries no `architectures`, so `is_deepseek_dsa` always rejected it; `real_page_size` was renamed to `physical_page_size` upstream), the DSA draft-metadata glue graph measures:

- adaptive 5/1/6, c16: +0.2%
- fixed 5/1/6, c16: ~0% (2347 vs ~2346 tok/s)
- fixed 5/1/6, c64: +0.2% (3996 vs 3989 tok/s)

The glue graph is confirmed to initialize and engage correctly (debug-instrumented serve), so this is 'engaged but not valuable', not 'not working'.

**Why the value is gone:** the host-side metadata overhead this PR targeted has largely been absorbed by work that landed since: #38845 (KPool metadata fusion), #41175 (NEXTN verify+draft input-prep fusion), #41987 (per-step CPU seq_lens sync removal). At c16-c64 the engine is GPU-bound (~85-90% stream occupancy), so the remaining host-side savings are off the critical path. The original +9.97% was measured on the pre-#38845 tree at C80 CPU saturation.

**Salvageable if ever revisited:** the SM103 split-mhc_post TileLang path (33-512 tokens, hc=4, hidden 4096) was kept through the update but never perf-measured; parity tests exist in the branch (0872719ded + 18e5f1f198 on xinyuan/glm53flash-sota-perf).

Thanks for the reviews along the way.
