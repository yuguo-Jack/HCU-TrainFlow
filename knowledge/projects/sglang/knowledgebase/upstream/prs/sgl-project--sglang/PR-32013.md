# :bug: [llm][npu][quant] Fix ModelSlim MXFP4 packed weight loading

[Upstream PR](https://github.com/sgl-project/sglang/pull/32013) · state: closed · merged: True

## Original PR description

# Summary

Fixes offline ModelSlim `W4A4_MXFP4` checkpoint loading on Ascend NPU.

Current ModelSlim exports FP4 weights as packed `uint8` tensors with shape `[out, in//2]`, while SGLang still registered the legacy `float8_e4m3fn [out, in]` checkpoint layout. This caused a shape mismatch when loading newly exported checkpoints.

# Root Cause

ModelSlim now applies `pack_fp4_to_uint8` when exporting `W4A4_MXFP4` weights. The existing SGLang implementation still expected the older one-FP4-per-byte representation and called `npu_dtype_cast` after loading, which would also repack an already-packed weight.

# Changes

- Register `W4A4_MXFP4` weights as packed `uint8 [out, in//2]`.
- Transpose the already-packed weight directly during post-load processing.
- Remove the redundant `npu_dtype_cast` repacking step.

# Validation

- Manually validated with a current ModelSlim `W4A4_MXFP4` packed checkpoint on Ascend NPU.
- Python compilation check passed.
- Black and isort checks passed.
