# [Feat] [Intel] xpu: Use SYCL kernels for mxfp4 indexer on XPU

[Upstream PR](https://github.com/sgl-project/sglang/pull/45780) · state: open · merged: False

## Original PR description

## Motivation
Enable XPU execution of the DeepSeek V4/4.1 FP4 indexer by integrating the corresponding SYCL operators from sgl-kernel-xpu.
The SYCL implementations are added in the `sgl-kernel-xpu` PR (https://github.com/sgl-project/sgl-kernel-xpu/pull/572) and exposed as
`torch.ops.sgl_kernel.fused_q_indexer_rope_hadamard_fp4_quant`, `torch.ops.sgl_kernel.fp4_paged_mqa_logits`, `torch.ops.sgl_kernel.index_q_rope_pack_weights`, `torch.ops.sgl_kernel.index_k_norm_rope_pack_store`.

## Modifications
Enable FP4 indexer configuration on XPU

Allow --enable-deepseek-v4-fp4-indexer on XPU devices.
Update platform validation and the associated error message.
Integrate DeepSeek V4 FP4 query preparation and scoring

Dispatch fused query RoPE, Hadamard transform, and FP4 quantization to sgl_kernel.fused_q_indexer_rope_hadamard_fp4_quant.
Convert the complex RoPE cache to the real-valued layout expected by the SYCL operator.
Reinterpret per-group scale bytes as packed int32 scales to preserve the caller-facing layout.
Dispatch paged FP4 MQA logits to sgl_kernel.fp4_paged_mqa_logits on XPU instead of DeepGEMM.
Integrate DeepSeek V4.1 Q/K preparation

Use sgl_kernel.index_q_rope_pack_weights for query RoPE, FP4 packing, and head-weight preparation.
Use sgl_kernel.index_k_norm_rope_pack_store for fused key RMSNorm, RoPE, FP4 packing, and paged-cache storage in the applicable decode/target-verify and extend paths.
Preserve existing platform paths

Select XPU operators through platform-specific dispatch.
Keep CUDA and ROCm implementations unchanged.
