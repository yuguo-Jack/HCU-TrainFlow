# [LoRA] Honor use_rslora from PEFT adapter config

[Upstream PR](https://github.com/sgl-project/sglang/pull/41774) · state: open · merged: False

## Original PR description

## Motivation

SGLang ignores `use_rslora` in a PEFT adapter config. PEFT scales an rsLoRA adapter by `lora_alpha / sqrt(r)` ([Kalajdzievski 2023](https://arxiv.org/abs/2312.03732)), but `LoRAAdapter` always uses `lora_alpha / r`.

The adapter loads without error, and its update is `sqrt(r)` times too weak: 4x at r=16, 8x at r=64.

```
use_rslora=True:  PEFT scaling=16.0,  SGLang scaling=2.0   # wrong
use_rslora=False: PEFT scaling=2.0,   SGLang scaling=2.0   # correct
```

Reported in #40835 with a full reproduction script.

## Modifications

**`python/sglang/srt/lora/lora_config.py`**
- Parse `use_rslora` from the PEFT adapter config (defaults to `False`).

**`python/sglang/srt/lora/lora.py`**
- When `use_rslora` is `True`, compute `scaling = lora_alpha / sqrt(r)` instead of `lora_alpha / r`.

**`test/registered/lora/test_rslora_scaling.py`** (new, 64 lines)
- Parametrized unit tests across three (r, alpha) pairs verifying:
  - Standard LoRA scaling matches `alpha / r`
  - rsLoRA scaling matches `alpha / sqrt(r)`
  - rsLoRA scaling is strictly larger than standard for any r > 1
- Separate test confirming `use_rslora` defaults to `False` when absent from the config dict.
