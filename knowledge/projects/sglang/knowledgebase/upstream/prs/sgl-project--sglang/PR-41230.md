# [Fix] [Apple] mlx: reject output logprobs without sampling

[Upstream PR](https://github.com/sgl-project/sglang/pull/41230) · state: open · merged: False

## Original PR description

## Summary

On the MLX backend, `return_logprob=True` without `--mlx-enable-sampling` produced empty logprob arrays. `/v1/score` then returned an opaque 500 after the score result processor found no output logprobs.

The scheduler now rejects this unsupported request before admission with `Output logprobs on the MLX backend require --mlx-enable-sampling.` Non-MLX requests and MLX requests with sampling enabled keep their existing paths. The Apple Metal guide lists the flag beside the other MLX serving parameters and describes its logprob requirement.

## Validation

- Integrated main `74308cf1` at `27daff53`. Source-isolated execution of the complete production request handler rechecked all eight combinations of MLX, sampling, and output-logprob flags on both main and candidate. Only MLX output-logprob requests with sampling disabled take the new abort path; the request retains the expected error and logprob state.
- At prior integrated head `03dd0754`, repository pre-commit checks passed for AST validation, import ordering, Ruff, formatting, codespell, CI registry validation, and related hooks.
- `git diff --check` passed.
- [Verified on Apple M2 by @luke-edward](https://github.com/sgl-project/sglang/pull/41230#issuecomment-5862325827) at `34c4378` on Apple M2 16 GB, macOS 15.7, Python 3.12.13, PyTorch 2.13.0, MLX 0.32.2, and `Qwen/Qwen2.5-0.5B-Instruct` bf16. With sampling disabled, logprob requests to `/generate` and `/v1/score` return 400 with the flag requirement; ordinary generation returns 200. With sampling enabled, both endpoints return populated logprob and score results.

Fixes #41211.
The earlier integration used the source-loaded handler and admission fixtures; full scheduler imports and model-backed endpoints were covered by the historical runs above.
