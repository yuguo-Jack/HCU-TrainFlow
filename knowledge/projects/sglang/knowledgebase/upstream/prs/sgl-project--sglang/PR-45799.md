# [Feat] model: Add MiniCPM-OCR 1.0 support

[Upstream PR](https://github.com/sgl-project/sglang/pull/45799) · state: open · merged: False

## Original PR description

## Motivation

MiniCPM-OCR 1.0 is the MiniCPM-V 4.6 stack with a different `model_type`, so
this only registers it: `MiniCPMOcrForConditionalGeneration` subclasses the 4.6
model unchanged, plus its own config and image-geometry alignment.

## Modifications

- `configs/minicpm_ocr_1_0.py`: `MiniCPMOCR1_0Config` /
  `MiniCPMOCR1_0VisionConfig` subclass the 4.6 configs and pin `model_type` to
  the checkpoint's values. Registered in `configs/__init__.py` and
  `_CONFIG_REGISTRY`.
- `models/minicpmv.py`: `MiniCPMOcrForConditionalGeneration` for
  `model_type: minicpm_ocr`, routed to the 4.6 version.
- `multimodal/processors/minicpmv4_6.py`: new `align_merge_factor` on
  `MiniCPMV4_6ImageProcessor` (default 4, so 4.6 is unaffected). OCR's image
  processor applies a single 2x2 merge in `"4x"`, so it uses 2.
- `parser/conversation.py`: skip the legacy conv template for `minicpm_ocr`, so
  the checkpoint's own `chat_template.jinja` is used.
- `model_loader/loader.py`: also set `shared_experts_config` on the inner
  `minicpmv` module. `MiniCPMV` forwards attributes via `__getattr__` and
  `DefaultModelLoader` returns `model.eval()`, which resolves to the inner
  module, so the attribute set on the wrapper is lost. Not OCR-specific — 4.6
  and 4.7 hit the same `AttributeError` at warmup.
