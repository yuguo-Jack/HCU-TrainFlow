# [Feat] lora: MoE LoRA runner and serving integration (15/21)

[Upstream PR](https://github.com/sgl-project/sglang/pull/42882) · state: closed · merged: False

## Original PR description

Part 15 of 21 of the LoRA runtime stack (branch `lora-stack-14-moe-runner`, base `lora-stack-13-moe-providers`). The stack is cut from the development branch of #42284.

## What this part adds

Add MoeLoraRunner, which binds plans and providers once per layer and runs the
LoRA stages inside FusedMoE.run_moe_core, and wire it in: FusedMoEWithLoRA
takes the lora_* path, LoRAManager rejects target sets that leave MoE layers
without a runner, the memory pool refuses shared-expert weights without a
destination, and server args admit lora_cutedsl, lora_triton and lora_marlin
(triton_v2 only; standard dispatch; trivial expert placement; draft models
default to the ordinary runner). The runner admits BF16 experts; quantized
layers are rejected with a clear error until their vendors land.

Tests: runner attach and binding, the runtime contract, shared-outer
numerics, stage dispatch, the prefill-graph contract and e2e prefill graphs,
server-arg guards, model overrides. The runner-level numeric oracles run the
CuTeDSL vendor and land with it.
