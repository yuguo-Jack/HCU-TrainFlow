# [Fix] disaggregation: Pair ordinary MHA KV by layer ID across uneven prefill PP stages

[Upstream PR](https://github.com/sgl-project/sglang/pull/28229) · state: open · merged: False

## Original PR description

## Motivation

Fixes #27740 (closed by the stale bot; the bug is still on main).

With PD disaggregation, prefill can run pipeline parallel while decode runs PP=1. Plain MHA pools publish no layer IDs, so Mooncake (equal and heterogeneous TP), Mori and NIXL's heterogeneous-TP path place a prefill stage's K/V entries in decode's list by position (`get_mha_kv_ptrs_with_pp` or Mori's copy of it), treating `dst_num_total_layers % num_kv_layers != 0` as appended draft KV. An uneven split (7+8 of 15) takes that branch without any draft, so V lands in the wrong decode slots, and with a draft model the last stage also overwrites draft K. NIXL's equal-TP path rejects these transfers instead, because they need layer IDs.

## Modifications

`build_kv_layer_ids` now describes ordinary MHA registrations (`MHATokenToKVPool` itself, NHD layout, no KV quantization, two entries per layer) from the pool decode registers, so both peers use the layer-ID pairing hybrid pools already go through (`build_transfer_entry_pairs`), with the existing draft ID band and no new registration field. NIXL's heterogeneous-TP descriptors now pair the same way as Mooncake's `send_kvcache_slice`, and Mori's MHA pairing gets the `pp_size == 1` positional fallback the other paths apply.

With PP prefill, prefill and decode workers must be upgraded together: one-sided layer IDs are rejected (`Layer metadata must be provided by both PD peers or neither`), and on Mooncake and NIXL that stops a transfer worker or the prefill bootstrap thread rather than one request. `pd_disaggregation.mdx` describes this per backend. With PP=1 prefill, mixed versions keep positional pairing on all three backends. Quantized and special-layout MHA pools publish no layer IDs and keep the positional path, so they are not fixed here.

Related: #33497 by @zmtttt found the draft K overwrite on the last stage, and #33457 by @yhyang201 covers the hybrid-linear side.

## Accuracy Tests

On `604bcb8f3` (main `bce7b27aa`), `pytest -q test/registered/unit/disaggregation` gives 698 passed, 14 skipped, 358 subtests passed. Of the 10 new or renamed test methods, 7 fail on main and 3 guards (quantized pool, special layouts, unknown pool) pass on both; the Mori version-skew and NIXL heterogeneous-TP cases also fail with their source change reverted. isort, ruff, ruff-format and codespell pass on the changed files.

Rebased onto main `4eb606b2a` as `cbf865cd6`; the only change to the diff is one docstring sentence removed from `build_kv_layer_ids` (the upgrade guidance stays in `pd_disaggregation.mdx`), and main has not touched `srt/disaggregation` or `memory_pool.py` since `bce7b27aa`. On `cbf865cd6`, `pytest -q test/registered/unit/disaggregation` gives 698 passed, 14 skipped.

Real Mooncake TCP copies between two processes on one RTX PRO 6000, through the production equal-TP planner with IDs from the real pool builder (fixture managers, logical stage partitions, main `4fc86f73c`; these files are unchanged since): main corrupts every uneven case (11,520 or 21,504 target elements, plus 768 or 1,536 draft elements with a draft) and only the 8+8 control matches; the patch matches all six cases. Mori and NIXL are covered by the CPU tests only, and full PP serving across GPUs was not run.

## Speed Tests and Profiling

No end-to-end claim. Ordinary MHA transfers now pay the ID pairing: 7 to 34 us per call for 28 to 128 layers in a CPU microbenchmark (median of 7 x 10,000 calls), against under 1 us for `get_mha_kv_ptrs_with_pp`.

- lalaopt · comment · 2026-08-27T08:58:11Z · [source](https://github.com/sgl-project/sglang/pull/28229#issuecomment-5436736133)

We independently hit the hybrid-model (GDN + full-attention) prefill-PP KV indexing bug on v0.5.18 + Mooncake, and can confirm the layer-id pairing approach in this PR fixes it on real hardware.

**Setup**: Qwen3.6-27B (48 layers, `full_attention_interval=4`), PD disaggregation over Mooncake (rdma), equal TP — P: tp1 **pp2**, D: tp1 pp1, on A100.

**Symptom on stock v0.5.18**: stage 0 transfers fine, stage 1 fails with `Prefill transfer kvcache error, layers_current_pp_stage is out of range: layers_current_pp_stage=6, len(dst_k_ptrs)=0`. This is the even-split sibling of the uneven-split mis-detection in #27740: `get_mha_kv_ptrs_with_pp` slices the decode-side dense KV list with `prefill_start_layer`, which counts the GDN layers too (stage 1: `start_layer=24` against a 12-entry K list → empty slice).

**What we verified**: we applied the same gate-promotion semantics as this PR's `_send_kvcache_generic` change (route the MHA layout to `build_transfer_entry_pairs` when both peers advertise `kv_layer_ids` — v0.5.18 already exchanges them in the registration frames) onto v0.5.18 and re-ran the failing scenario:
- The stage-1 transfer failure is gone; requests complete through both pipeline stages (3/3).
- Greedy outputs (temperature 0, 5 prompts × 64 tokens) match a pp1 baseline exactly on 4/5 prompts; the remaining one differs by a single near-tie token flip ("globally renowned" vs "renowned worldwide") that re-converges to an identical suffix — consistent with pp microbatching numerics, not mis-paired KV.

Hope this helps move the review along — happy to share more details from our runs if useful.
