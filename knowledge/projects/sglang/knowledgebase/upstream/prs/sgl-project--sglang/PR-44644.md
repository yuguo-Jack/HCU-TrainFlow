# [Perf] kernels: Enter a JIT kernel's device guard only when the device differs

[Upstream PR](https://github.com/sgl-project/sglang/pull/44644) · state: closed · merged: True

## Original PR description

## Motivation

JIT kernel wrappers that launch through tvm-ffi enter `torch.cuda.device(t.device)` around the launch. Entering and leaving it costs about 1.6 µs per call on an x86 host, even when `t` is already on the current device, which is always the case in a one-device-per-process server. The qknorm complex RoPE wrappers used by Qwen-Image-2.1 run it on every attention layer.

## Modifications

- `sglang.kernels.jit.utils.device_guard(t)` returns a shared `nullcontext` when `t.get_device()` is the current device, and `torch.cuda.device(t.device)` otherwise.
- `qknorm_complex_rope_cuda` and `qknorm_complex_rope_pack_` use it.

Behaviour on another device is unchanged. Other wrappers can adopt the helper one line at a time.

## Accuracy Tests

On 2xH200:
- `test/registered/unit/kernels/test_device_guard.py`: 2 passed. With the tensor on the current device, `torch.cuda.device` is never constructed (it is monkeypatched to raise). With a tensor on `cuda:1`, the device is entered and restored.
- `test_complex_rope.py`: 38 passed.
- `test_qwen_image21_cuda.py`: 25 passed.
- `test_model_fast_paths.py`: 114 passed.

## Speed Tests and Profiling

Base `c15edf314d`, H200 (Xeon 8558P).

| | µs per call |
|---|---|
| `torch.cuda.device(t.device)` enter and exit | 1.64 |
| `device_guard(t)`, current device | 0.49 |

End to end the change is too small to resolve on H200. In Qwen-Image-2.1 TP2 512², with both paths in one server and chosen per request, it measured +0.27% (faster in 5/16) against an in-process A/A of 0.00%: the wrapper runs about 2,400 times per request. The saving is per call. Grace hosts pay roughly twice the x86 Python cost.
