# [Cleanup] Remove unused NUM_SMS parameter from _compute_pid

[Upstream PR](https://github.com/sgl-project/sglang/pull/32399) · state: closed · merged: False

## Original PR description

  ## Motivation
  `_compute_pid` in `python/sglang/srt/batch_invariant_ops/batch_invariant_ops.py` accepts a `NUM_SMS` argument but never uses it — the tile → `(pid_m, pid_n)` mapping depends only on `tile_id`, `num_pid_in_group`, `num_pid_m`, and `GROUP_SIZE_M`.

  Dropping the unused parameter makes it explicit that per-tile assignment is  independent of the SM count, which is one of the properties the batch-invariant kernels rely on (the caller's persistent grid loop uses `NUM_SMS` as its stride, but the mapping itself does not).

  ## Modifications
  - Remove `NUM_SMS` from the `_compute_pid` signature and from its two call sites (`matmul_kernel_persistent`, the persistent bmm kernel).
  - No behavior change: the helper is inlined by Triton and the removed argument was dead. Verified on H100 that outputs are bit-identical before/after.
