# [Perf] [AMD] dsv4: Route the DSV4 GEMMs through AITER

[Upstream PR](https://github.com/sgl-project/sglang/pull/48068) · state: open · merged: False

## Original PR description

On gfx1250:
- decode/prefill bf16 `wo_a` use the AITER bf16 GEMM
- fp32 compressor projections and the generic bf16/fp32 GEMM go through AITER `tgemm`
- the shared-expert `down_proj` and both `wq_b` GEMMs take their input quantized once for the `mxfp8_128` GEMM

Depends on sgl-project/sglang#48064.

<!-- results -->
### Accuracy
GSM8K (200 questions, greedy), DeepSeek-V4-Pro: TP4 0.960.

### Performance
Setup:
- Model: DeepSeek-V4-Pro, BF16 KV cache, DSPARK speculative decoding (block 6, 1 step)
- Parallelism: TP4 (`--tp 4`, CP prefill + CP decode attention)
- Step time: torch profiler on rank 0, GPU time per step; decode = 8 steps at 4 running requests (VERIFY = target verify, DRAFT = DSPARK draft), prefill = one EXTEND step of an ~8k-token prompt (TP4) / 4k (EP4)
- Comparison: with vs without this PR, same image and node, all earlier PRs of the series applied

Profiler step time (without -> with):

| step | without | with | change |
|---|---|---|---|
| decode VERIFY | 17.77 ms | 16.97 ms | -4.5% |
| decode DRAFT | 1.83 ms | 1.86 ms | +1.4% |
| prefill EXTEND | 191.9 ms | 191.1 ms | -0.4% |
