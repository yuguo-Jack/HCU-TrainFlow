# [disaggregation] Mooncake: report KV transfer latency metric and set KVPoll.Transferring

[Upstream PR](https://github.com/sgl-project/sglang/pull/32147) · state: closed · merged: False

## Original PR description

## Motivation

The mooncake disaggregation backend inherits `transfer_total_bytes` accounting from `CommonKVSender` but never fills `KVTransferMetric.transfer_latency_s`. The consumer (`ReqTimeStats`) then falls back to `completion_time - prefill_transfer_queue_entry_time`, which only covers the last chunk of a chunked prefill, so `sglang:kv_transfer_latency_ms` is under-reported and `kv_transfer_speed_gb_s` over-reported. The NIXL backend already measures this precisely.

Separately, the mooncake backend never reports `KVPoll.Transferring`: the prefill room status goes straight from `WaitingForInput` to `Success`, leaving the standing `# todo: set Transferring correctly in backend` unaddressed.

## Modifications

- `MooncakeKVSender` records `time.perf_counter()` on the first non-empty `send()` and fills `transfer_latency_s` on the first `poll()` that observes `KVPoll.Success` (failed transfers keep it `None`). `alloc_latency_s` is intentionally left `None`, matching NIXL — the mooncake sender path has no backend-visible allocation-wait phase, and the consumer already derives `alloc_ms` from scheduler timestamps.
- `MooncakeKVManager.transfer_worker` marks the room `KVPoll.Transferring` when it dequeues a chunk, mirroring the NIXL transfer_worker.
- `AscendKVSender`/`AscendKVManager` inherit both changes.

## Accuracy Tests

Observability / state-machine change only; no model outputs affected. New CPU unit tests (mocked manager, no TransferEngine or GPU required) cover: latency spans all chunks of a chunked prefill, start time is set once and only for non-empty chunks, failed transfers report no latency, latency + bytes combine into a correct speed, and `transfer_worker` emits `Transferring` before `Success`. All pass.
