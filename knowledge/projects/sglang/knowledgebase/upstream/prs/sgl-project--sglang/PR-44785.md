# [Fix] srt: Apply --gc-threshold in every server process and freeze every tokenizer worker

[Upstream PR](https://github.com/sgl-project/sglang/pull/44785) · state: closed · merged: True

## Original PR description

## Motivation

`--gc-threshold` is applied with `gc.set_threshold` in the launching process only. The scheduler and detokenizer subprocesses keep Python's default thresholds, so a deployment that raised the gen2 threshold to stop periodic full collections still sees them in the scheduler, where they cost the most.

The post-warmup `/freeze_gc` request freezes the scheduler and detokenizer, but with `--tokenizer-worker-num` greater than one it is served by whichever tokenizer worker receives it, so only that worker's interpreter is frozen. The other workers keep scanning their long-lived heap on every collection.

Defaults are unchanged: with no `--gc-threshold` nothing new is set, and the single-tokenizer path still freezes exactly where it did.

## Modifications

- `freeze_gc` (`python/sglang/srt/utils/common.py`) takes an optional `gc_threshold` and applies it with `gc.set_threshold` before `gc.freeze()`; `None` leaves the thresholds alone.
- `FreezeGCReq` carries `gc_threshold: Optional[List[int]] = None`. `TokenizerManager.freeze_gc` reads the configured threshold off the device args, sends it with the request, and passes it to its own local freeze; the scheduler and detokenizer handlers pass `recv_req.gc_threshold` through.
- `_wait_and_warmup` (`python/sglang/srt/entrypoints/http_server.py`) gains `post_warmup_callback`, run after warmup and before the routed `/freeze_gc` request. In multi-tokenizer mode each worker's warmup thread gets a callback that freezes that worker's interpreter with the configured threshold, so every worker freezes locally and the routed request still covers the scheduler and detokenizer.

## Accuracy Tests

Not applicable: no change to model execution or outputs. Only garbage-collector thresholds and freeze points move, and only in the processes that were previously skipped.

## Speed Tests and Profiling

Not applicable as a benchmark: the change removes recurring gen2 collections from the scheduler and the extra tokenizer workers when a threshold is configured, and is a no-op otherwise.

Unit tests on this head (CPU, `pytest`): `test/registered/unit/utils/test_common.py` and `test/registered/unit/managers/test_multi_tokenizer_mixin.py`, 37 passed. New cases: `freeze_gc` preserves the thresholds without a configuration and applies a configured one; each tokenizer worker freezes locally with the configured threshold after warmup and before the routed request.
