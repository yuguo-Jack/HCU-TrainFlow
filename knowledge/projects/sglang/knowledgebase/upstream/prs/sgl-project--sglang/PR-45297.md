# [Doc] [AMD] cookbook: Fix DeepSeek-V4 PD image and c1 capacity

[Upstream PR](https://github.com/sgl-project/sglang/pull/45297) · state: closed · merged: True

## Original PR description

## Motivation

The MI355X DeepSeek-V4-Pro-0813 PD cookbook still documents c1 with two request slots and decode graph sizes 1–2. Its Docker commands also select an older image despite enabling mxscale GEMM and power-of-two routing settings.

This completes the cookbook follow-up to #44454 identified in [InferenceX #4186](https://github.com/SemiAnalysisAI/InferenceX/pull/4186#issuecomment-6279021019). Source configuration: [recipe at `6ad6674d9de2`](https://github.com/SemiAnalysisAI/InferenceX/blob/6ad6674d9de25c0abfc3ed511a580c147cfd47df/inferencex-e2e/benchmarks/multi_node/srt-slurm-recipes/dsv4/sglang/mi355x-fp4/agentx/disagg-umbp-dspark.yaml).

## Modifications

- Document eight request slots on both c1 workers and decode graph sizes 1–8, while keeping client concurrency at one. Explain the exception to the strategy presets' `2 × concurrency` sizing rule.
- Select `lmsysorg/sglang-rocm:v0.5.22-rocm720-mi35x-20261019` for both Pro and Pro Official FP4 PD prefill, decode and router Docker commands, and update the matching example. Both variants share one image; single-node images remain unchanged.
- Remove submission/PR-following descriptions from the PD documentation and config comments; keep provenance in this PR description.

This touches §3.7 and its deployment guidance/config resolver. #45268 addresses the separate single-node §3.6 recipe.
