# [Speculative] DSpark serving: per-step host-overhead cuts, hybrid draft-pool KV injection, strip-layout conv intermediates, NIXL PD geometry guards

[Upstream PR](https://github.com/sgl-project/sglang/pull/39154) · state: closed · merged: False

## Original PR description

## Motivation

Thirteen self-contained changes from serving block-speculative (DSpark / DFlash-family) drafts at high concurrency, each measured on a GB300 microbench in its own commit message. They fall into four groups: per-decode-step host overhead on the DSpark verify and decode paths, hybrid (full + SWA) draft-pool KV injection, an opt-in strip layout for the speculative conv intermediates, and NIXL prefill-to-decode transfer guards for non-uniform KV registration geometry. Nothing changes default behavior for non-speculative serving; the strip layout is opt-in per state shape.

## Modifications

One commit per row (bottom to top of the branch); the test column is the registered unit test each commit adds or extends.

| Commit | What it does | Test |
| --- | --- | --- |
| DSpark verify: reuse the pre-planned attention metadata on the graph path | marks the pre-planned verify batch ready so `load_batch` is not re-run inside `execute`; four fewer launches per step | existing DSpark verify tests |
| DSpark decode: persistent plan-length staging with a change-gated H2D, device-staged mamba track positions | one pinned staging buffer per step, copied only when the plan lengths change | `test/srt/test_dflash_decode_plan_staging.py` |
| DSpark decode: route the per-step logprob extraction through one overridable seam | one translation point for the decode logprob extraction | `test/srt/test_dspark_decode_logprob_seam.py` |
| Scheduler: skip time_stats in Rust-server mode; extend decode logprob lists once per step | no per-token `time_stats` pickling or list appends on the result path | `test/srt/test_decode_logprob_bulk_extend.py`, `test_output_streamer_customized_info.py` |
| RadixCache: build the finished request's token history with one copy | one array concat instead of two per finished request | `test/srt/test_history_prefix.py` |
| Scheduler: settle a denied prefill pass before the candidate's prefix match | the denied-pass verdict is taken before the radix walk; sizing refreshes the fill ids first and keeps one SWA window of lock margin | `test/registered/unit/managers/test_prefill_adder.py` |
| DSpark draft: persistent `global_num_token_non_padded` scalar for the per-step draft ForwardBatch | a fill kernel replaces a per-step pinned H2D copy | covered by the plan-staging test |
| Scheduler: resolve ScheduleBatch field names once per class for the forward snapshots | class-level cache instead of `dataclasses.fields` walks per step | `test/srt/test_scheduler_field_names.py` |
| Mamba: track indices, one gather per batch instead of a row gather plus a column gather | one gather kernel | `test/srt/test_mamba_track_indices.py` |
| Scheduler: decode result loop skips the per-token finish scan for requests that cannot finish this step | finish candidates are pre-filtered per step | `test/srt/test_spec_finish_candidates.py` |
| DSpark KV injection: address hybrid (full + SWA) draft pools through `KVWriteLoc` | injected context KV for a hybrid draft pool goes through the pool with the SWA loc for window layers | `test/.../spec/test_dspark_kv_inject_hybrid_pool.py`, `test_swa_pool_prefix_valid_routing.py` |
| Mamba: strip layout for the speculative conv intermediates (opt-in per state shape) | one conv-input row per draft token instead of a (K-1)-wide window snapshot; the commit rebuilds the window bitwise (`fused_conv_strip_commit`) | strip commit parity tests |
| Disaggregation: NIXL falls back on ragged KV region slot counts, entry-aligned V-half strides, registration summary | the prepped fast path indexes descriptors as `layer * num_slots + page` with region 0's count while the list holds each region's real count; ragged local registration now falls back to the address-based path (or refuses on the two prepped-only paths), the MHA V half is strided with its own item length, and each side logs its registration geometry | `test/registered/unit/disaggregation/test_pd_transfer_geometry_guards.py` |

The NIXL drift was reproduced on an unmodified tree by driving `_prepare_payload_xfer` and the prepped `send_kvcache` with a recording agent: with region slot counts `[64, 64, 128, 128]`, region 3 page 5 is indexed as `3 * 64 + 5 = 197`, which is region 2 slot 69. A ragged registration needs an appended draft pool whose size differs from the target's (a target-only post-capture resize); uniform registrations are unaffected.

## Benchmarking and Profiling

Per-commit GB300 microbench numbers (ms or us per decode round, kernel counts) are in each commit message. The host-side commits together cut scheduler host-busy time per decode round from 43.6 ms to 36.3 ms at 384 concurrent requests on a gd36-class hybrid model with a DSpark draft (TP4/EP4), with round time unchanged because the GPU is saturated there; at 8 and 32 concurrent requests the deltas are within noise. Accept lengths are identical before and after.
