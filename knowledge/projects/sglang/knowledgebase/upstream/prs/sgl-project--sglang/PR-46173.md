# [Perf] diffusion: Run Cosmos3's multi-GPU VAE decode on the lossless fast path

[Upstream PR](https://github.com/sgl-project/sglang/pull/46173) · state: closed · merged: True

## Original PR description

Branch: mick/cosmos3-vae-decode-fast-path, stacked on #46149 (mick/wan-vae-parallel-decode-fast-path 93ccc5dc4f), commit 638c1f882f

Merge note: this PR and #46172 both edit the decode call in `Cosmos3DecodingStage.forward`; whichever lands second needs a trivial rebase.

## Motivation

Cosmos3 decodes with the Wan 2.2 VAE (`AutoencoderKLWan`, bf16). With more than one GPU, the decode is spatial-parallel over 4 ranks. Two things kept that decode off the CUDA fast path that Wan pipelines use:

1. `vae_loader._should_use_channels_last_3d` gave Cosmos3 channels_last_3d Conv3d weights only at `num_gpus == 1`. With NCDHW weights, cuDNN wraps every conv in `nchwToNhwc` / `nhwcToNchw` conversions (about 200 ms per 189-frame decode on rank 0, profiled). The fused RMSNorm+SiLU kernel only takes channels_last input. The spatial-parallel decoder exchanges halos in either layout (#46149 made Wan multi-GPU channels_last for the same reason).
2. `Cosmos3DecodingStage` never enters `use_vae_fast_path`. The fast path is installed on the VAE at load (since #46149, also on the spatial-parallel decoder), but its gate stays off, so the unfused bf16 `F.normalize -> * scale * gamma + bias -> SiLU` chains run instead.

## Modifications

- `loader/component_loaders/vae_loader.py`: Cosmos3 converts the VAE's Conv3d weights to channels_last_3d at any GPU count. Single-GPU Cosmos3 already did.
- `stages/model_specific_stages/cosmos3.py`: the VAE decode runs under `use_vae_fast_path(vae, quality_allows(quality, "lossless"))`, the same gate the generic `DecodingStage` uses. `quality="exact"` requests keep the reference ops.
- Tests:
  - `test_vae_loader.py`: the channels_last policy now covers multi-GPU Cosmos3.
  - `test_cosmos3.py::TestCosmos3DecodeFastPath`: the gate is on for `lossless` and `high` and off for `exact`.

This touches the same lines in `Cosmos3DecodingStage.forward` as "Encode Cosmos3 video while it decodes". Whichever lands second needs a trivial rebase that keeps both context managers.

## Accuracy Tests

The decode stays in bf16, the official precision. The fused kernel normalizes in fp32 and rounds once, where the reference rounds every bf16 op. The channels_last conv picks different cuDNN algorithms, and the channel reduction runs in a different order. Both changes are float re-association; the precision is not lowered.

Cosmos3-Nano T2V 720p 189 frames on 4xB300. All builds decode the same latents, and the videos are saved with x264 at crf 0 (lossless), two requests each:

| compared | PSNR | mean abs diff | max abs diff | SSIM |
|---|---|---|---|---|
| without vs with this PR | 54.34 / 54.36 dB | 0.154 / 0.152 | 20 / 17 | 0.99998 |
| without vs channels_last only (`quality=exact`) | 56.88 / 56.91 dB | 0.086 / 0.084 | 8 / 13 | 0.99999 |
| fp32 VAE vs without this PR (bf16 reference ops) | 52.09 / 52.13 dB | 0.259 / 0.255 | 14 / 18 | 0.99996 |
| fp32 VAE vs with this PR | 52.16 / 52.21 dB | 0.255 / 0.250 | 24 / 23 | 0.99996 |

Mean abs diff and max abs diff are on the 0-255 scale.

Against an fp32 decode of the same latents, this PR is as close as the bf16 reference ops, and slightly closer by PSNR and mean error. The difference between the two bf16 decodes is smaller than either one's distance to fp32. `quality="exact"` keeps the reference ops.

## Speed Tests and Profiling

Cosmos3-Nano T2V 720p 189 frames, 4xB300 (CFG 2 x Ulysses 2, 4-rank spatial-parallel decode), synchronized stage timers, two requests per build. All builds include "Gather spatial-parallel decode heights on the host" and "Encode Cosmos3 video while it decodes":
