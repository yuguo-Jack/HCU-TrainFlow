# [Fix] moe: Keep FP8 TRT-LLM in-kernel routing for padding-only TopK bounds

[Upstream PR](https://github.com/sgl-project/sglang/pull/47502) · state: open · merged: False

## Original PR description

[by Claude Code]

## Motivation

Fixes #47501.

#45917 made `fused_experts_none_to_flashinfer_trtllm_fp8` turn a lazy (`BYPASSED`) TopK output into explicit `topk_ids`/`topk_weights` whenever it carries `num_token_non_padded`. That bound does not mean the batch has padded rows. `enable_num_token_non_padded()` attaches it to every forward whenever `moe_ep_size > 1`, in eager prefill and in every decode CUDA graph, padded or not. With `--ep > 1`, every block-FP8 MoE layer therefore left FlashInfer's fused in-kernel router and paid two extra launches per decode step:

| Per decode step, bs=1, TP rank 0 (`Qwen/Qwen3.8-Flash-Next-FP8`, 48 MoE layers, GB200) | parent of #45917 | #45917 | #45917 + this PR |
| --- | ---: | ---: | ---: |
| GPU kernels | 1562.7 | 1658.7 | 1562.7 |
| `_router_triton_kernel` (materialized softmax top-10 over 512 experts) | 0 | 48 x ~6.5 us | 0 |
| `mask_topk_ids_padded_region` | 0 | 48 x ~1.4 us | 0 |

Only the expert-placement remap (`expert_location_dispatch_info`) needs materialized routes: the in-kernel router cannot apply a logical-to-physical expert map, and before #45917 that case raised. A padding bound alone does not need them:

- With the standard dispatcher, padded rows never leave the rank.
- FlashInfer sizes its workspace from `num_tokens * top_k`.
- The caller drops padded-row outputs.

The same FP8 runner already routes padded rows in-kernel at EP=1, where the bound is `None`, and so do the FP4, BF16, and MXFP4 TRT-LLM runners. Masking does not pay for itself on padded batches either: con3 (decode bs 3, padded to the bs-4 graph) is faster without it (below).

## Modifications

- `BypassedTopKOutput.needs_select_experts` (`topk.py`): true when routing straight from logits would skip work that `select_experts` does:
  - the expert-placement remap;
  - routed-expert capture (`--enable-return-routed-experts`, unless the TopK opted out, as drafts do);
  - expert-distribution recording (`expert_distribution_recorder_mode` set);
  - routing simulation (`SGLANG_SIMULATE_UNIFORM_EXPERTS` / `SGLANG_SIMULATE_ROUND_ROBIN_EXPERTS`).
  This is the same set that `mimo_v2` already uses to gate its bypassed TopK.
- `fused_experts_none_to_flashinfer_trtllm_fp8`: materialize a bypassed TopK only when `needs_select_experts`. A padding bound alone keeps the in-kernel router. The predicate does not depend on the bound, so the unbounded (EP=1) FP8 path now also runs these hooks.
- `FusedMoE.forward` under tc-piecewise CUDA graphs uses the same predicate to keep such outputs off the opaque logits-only op. That op rebuilds a partial `TopKConfig`, which `select_experts` must not run from.
- The rest of #45917 is unchanged:
  - remap support on the bypassed path
  - materialized/routed inputs and FP16 score promotion
  - deferred finalize on materialized routes
  - CUTLASS/W4A8 route producers
- The `layer.py` tc-piecewise check still forwards bounded lazy outputs through `forward_impl`, because consumers that do materialize (the CUTLASS runner, the FlashInfer A2A dispatcher) still need the bound there.
- Tests:
  - `test_fp8_padding_bound_still_runs_select_experts_hooks` (CPU): a padding bound with no placement remap, run with capture, recording, and simulation each enabled in turn. The runner must reach the routed kernel, and the hook must see the real-row IDs.
  - `test_piecewise_lazy_routing_with_capture_keeps_the_full_config` (CPU): an unbounded lazy output with capture enabled under tc-piecewise must go through `forward_impl`, not the opaque op.
  - Both fail on the previous head of this PR (4 failures) and pass now.
  - `test_topk_routing_inputs.py` (CPU): a bounded `BYPASSED` output without a placement remap must reach the logits (in-kernel) kernel, and padded-row outputs are left to the caller. With a placement remap it must still reach the routed kernel with padded IDs `-1` and zeroed rows. The deferred-finalize ABI check follows the same split. On the unfixed runner these assertions fail (25 subtests); with this PR they pass.
  - `test_flashinfer_fp8_routed.py` (Blackwell GPU): bounded routes are materialized in the test before reaching the runner. It still covers valid/partial/inactive/recovery CUDA-graph replay, poisoned padded rows, and deferred finalize on the materialized path.
