# [HiSparse] Fix inflated full token usage for DeepSeek V4

[Upstream PR](https://github.com/sgl-project/sglang/pull/30909) · state: open · merged: False

## Original PR description

## Motivation

When HiSparse is enabled for DeepSeek V4, an empty KV cache can report a high
`full token usage` immediately after startup.

For example, with the following pool sizes:

- Full logical capacity: 5,445,376 tokens
- C4 device capacity: 272,268 compressed tokens
- Compression ratio: 4

The previous implementation calculated available full-token capacity as:

```python
min(logical_available, device_available * compress_ratio)
```
This limited the reported capacity to 1,089,072 tokens and caused an empty
logical pool to appear approximately 80% occupied.
