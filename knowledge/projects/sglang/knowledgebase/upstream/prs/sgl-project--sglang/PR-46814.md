# [Feat] [Ascend] attention: Use sgl-kernel-npu quantized sparse attention for DSpArk

[Upstream PR](https://github.com/sgl-project/sglang/pull/46814) · state: open · merged: False

## Original PR description

## Motivation

On Ascend 950, the DSpArk draft C1 path reads quantized shared-KV cache but currently calls the generic sparse-attention operator. Route that path through the dedicated `sgl-kernel-npu` quantized operator and its host metadata scheduler. This change depends on [sgl-kernel-npu PR #876](https://github.com/sgl-project/sgl-kernel-npu/pull/876).

## Modifications

- Add `is_dspark` to `_sparse_attn_ops()` and select `torch.ops.npu.kv_quant_sparse_attn_sharedkv_metadata_host` and `torch.ops.npu.kv_quant_sparse_attn_sharedkv` only for Ascend 950 DSpArk draft C1. Other attention paths retain their existing operators.
- Pass contiguous CPU `int32` query/KV length mirrors to host metadata while keeping NPU length tensors for the attention call.
- Check wheel import and operator registration in `extra_ops_loader.py` from DSpArk worker initialization, matching the structure of randgun/sglang#33. Validate query, packed KV, sinks, and metadata before dispatch, and make non-contiguous queries contiguous.

This ports the integration from [randgun/sglang#33](https://github.com/randgun/sglang/pull/33) onto the current upstream `main` without the other changes from the `br_dsv4_950` branch.
