# [Feat] [NVIDIA] megakernels: Expose hybrid runtime and DSpark verification views

[Upstream PR](https://github.com/sgl-project/sglang/pull/45406) · state: closed · merged: True

## Original PR description

## Motivation

Hybrid MLA/KDA megakernel plugins need typed access to SGLang-owned cache and step state after model resources are prepared and before CUDA graph capture. This includes ordinary decode and fixed-width Kimi K3 DSpark target verification. The companion implementation is [sgl-nvidia-mega #25](https://github.com/sgl-project/sgl-nvidia-mega/pull/25).

## Modifications

- [`9b00e04f`](https://github.com/leejnau/sglang/commit/9b00e04f555a2ed9b583d2e3baf3e302cfd0ba21): explicit post-resource preparation, typed per-step views, graph-static ownership checks, and existing non-hybrid behavior, rebased onto the current NVIDIA kernel-plugin layout and API v2.
- [`ca36ffa8`](https://github.com/leejnau/sglang/commit/ca36ffa89a687505b7d0705d0b02945a2b425aed): request-local KDA verification state, MLA query-width metadata, auxiliary hidden-state buffers, and capture-lifetime checks. SGLang retains ownership of acceptance, recurrent-state commit, and stock draft-model execution.
- [`27687018`](https://github.com/leejnau/sglang/commit/27687018a1e33252bc42cdcd0c337116c8f6c91f): preserve architecture-specific EagleBinding dispatch/capture behavior, with a real-binding regression.
- [`5f31ea56`](https://github.com/leejnau/sglang/commit/5f31ea5649618cf0d81fbb359411e403a2ebdf0f): avoid per-view legacy accessor closures while retaining lazy access and typed-only hybrid views.
- [`3e41ef87`](https://github.com/leejnau/sglang/commit/3e41ef8764018321d612d15f69da8a9f4c35796a): align runtime test fixtures with the API-v2 installed-object and optional-entry contracts.

The foundation and DSpark commits formerly proposed in [#46479](https://github.com/sgl-project/sglang/pull/46479) remain separate reviewable commits. No kernel arithmetic or default execution path is changed. The focused DSpark configuration is GB300, TP8, five draft proposals plus one anchor (q6), and DCP off. Uniform q4–q8 metadata support retains fail-closed layout and ownership checks. The original full-model evidence uses an 8,192-token context; bounded long-context qualification is described separately in the companion plugin PR.

The [isolated Kimi plugin compatibility commit](https://github.com/leejnau/sgl-nvidia-mega/commit/32262d4f5b4eecc725a5b89584f33bbcf3c85273) in the companion PR supports ordinary decode independently of DSpark. It prefers the new interfaces and falls back only when the new namespace is absent.

## Accuracy Tests

Current rebased pair: SGLang `3e41ef8764018321d612d15f69da8a9f4c35796a` and plugin `90e1b1b48a79d556dbddc093a3358b1d9b7912e2`. Server/GPU dependencies unavailable on the host were isolated with test stubs; this is not a full native-framework import or GPU requalification. Focused repository lint, import ordering and formatting checks pass. The GPU measurements below remain attributed to their original revisions.

The native old/new-layout matrix passed on GB300 for ordinary-decode and DSpark bindings: all 34 isolated test-file runs completed without failures or skips. Checks covered actual module/type/registration/preparation identities and audited installed wheel payloads, identical across layouts within each pair. The ordinary-decode pair is SGLang `d8543baa` / plugin `32262d4`; the native-tested DSpark pair is `0e9e2aa` / `e64e4d0`. The subsequent `d3d6d8c` changes only one test import's formatting, with identical AST and no production changes. This is focused compatibility validation, not a new full-model accuracy run.

Historical full-model measurements apply specifically to **SGLang `02406d4ef05680cbf3d77287354d887b039141d9` + sgl-nvidia-mega `194d693d15a51f74a727889531fd6d9cd01bf355`**, not the rebased pair. [by Claude Code] **Severity: functional | Confidence: Medium**

**Issue**

`KdaStateView` exposes only `conv` and `temporal`. With `--enable-linear-replayssm`, `mamba2_layer_cache()` also returns the `replayssm_d/k/g` ring, and KDA decode writes the ring and flushes `temporal` only every `--linear-replayssm-cache-len` steps. `_prepare_hybrid` does not check for this, so the plugin gets an incomplete recurrent state. The Kimi K3 spec in sgl-nvidia-mega#17 does not refuse this flag either.

**Example**

A batch size outside the plugin widths runs stock ReplaySSM decode. The next covered step reads a `temporal` that lags the ring, and the next stock step replays the ring on top of a state the megakernel already advanced. Outputs drift silently.

**Fix**

In `_prepare_hybrid`, raise when `state.replayssm_d is not None`, or add the ring to the view.
