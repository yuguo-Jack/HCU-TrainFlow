# [Perf] diffusion: fix 5 quantization-layer overheads (NVFP4 scale conversion, BnB, Nunchaku)

[Upstream PR](https://github.com/sgl-project/sglang/pull/46303) · state: open · merged: False

## Original PR description

Fixes #46302.

Five independent, minimal fixes to real overheads in the diffusion (`multimodal_gen`) quantization layer. Each is its own commit. Tests are folded into the closest existing test file for each change (no new test files), reusing existing fixtures/imports wherever one already fit, plus a GPU benchmark for the NVFP4 scale conversion fix.

## Commits

1. **NVFP4 scale TMA conversion: avoid GPU->CPU->GPU round trip.** `ModelOptFp4LinearMethod.process_weights_after_loading` built the padded TMA scale buffer with a device-less `torch.zeros(...)`, forcing scales off and back onto the GPU on every load. Calls the existing on-device `_linear_nvfp4_scales_to_tma` helper instead.
2. **Dynamic NVFP4: cache `weight_scale_2.max()` at load.** It's fixed after loading; stop reducing the tensor on every forward.
3. **Comfy full-precision NVFP4: unswizzle scales once at load**, not on every forward. Scoped under its own attribute (`_weight_scale_linear`) since the sibling dynamic-activation-quant method still needs `weight_scale` swizzled.
4. **BnB 4-bit: skip the output-buffer copy for a single unfused shard.** Calls `matmul_4bit` directly in the common (non-fused) case.
5. **Nunchaku: lazily read only the needed scale tensors** via `safetensors.safe_open` instead of deserializing the entire checkpoint (including the bulk int4 weights) with `load_file`.

## Benchmark (Modal T4, torch 2.14.1+cu130, transformers 5.19.0, sglang-kernel 0.4.10+cu130, CUDA 13.0)

**Fix 1 - NVFP4 scale TMA conversion** (scales shape 3072x256, 200 iters):

| | ms/call |
|---|---|
| old (CPU round trip) | 1.3967 |
| new (on-device) | 0.0535 |

~26x faster, output bit-identical to the old path.

Fixes 2-5 are load-time/metadata-sized operations (one-time per module load or per checkpoint patch), not per-forward hot-path ops, so there's no meaningful ms/call story for them beyond the unit tests.

## Tests

No new test files. Each fix's test(s) landed in the closest existing file, reusing its imports/fixtures:

- Fixes 1 & 2 (`modelopt_quant.py`): `test_modelopt_fp4_backend.py` - new `TestModeloptFp4ScaleProcessing` class, two tests (TMA layout correctness against an independent hand-derived reference, and that `apply()` uses the cached `weight_scale_2_max` instead of recomputing it).
- Fix 3 (`comfy_nvfp4.py`): `test_text_encoder_loader.py` - one new test next to the existing `test_comfy_nvfp4_dynamic_matmul`, reusing its already-imported `ComfyFullPrecisionNvfp4LinearMethod`/`ComfyNvfp4Config`. The existing `test_nvfp4_awq_portable_linear_and_rowwise_embedding` now runs `process_weights_after_loading` before `apply`, like the real loader does.
- Fix 4 (`bitsandbytes.py`): `test_ideogram4.py` - one new test next to its existing `test_bitsandbytes_tp_quant_state_uses_local_output_shard`, in the same `TestIdeogram4` class.
- Fix 5 (`nunchaku_config.py`): `test_transformer_quant.py` - one new test next to the existing `test_resolve_transformer_quant_load_spec_keeps_nunchaku_hook`, reusing its `tempfile`/`save_file` pattern.

## Dropped

An earlier revision also moved the ModelOpt W8A16 scale multiply from the weight to the output. CI showed it was less accurate (the bf16 GEMM output gets rounded twice), and for diffusion shapes, where tokens far outnumber channels, it adds elementwise work instead of saving it. Reverted.

## Deferred (filed in #46302, not in this PR)

- Dropping the TP all-reduce in dynamic NVFP4's input-scale computation - plausibly correctness-preserving but needs TP>1 validation, and the win (one scalar all-reduce) is likely too small to justify the risk without it.
- Generalizing the FP8 dequant-once cache (`weight_only_fp8.py`) to GGUF/Quanto/BnB/Comfy/W8A16 - real direction, but those formats dequantize structurally differently; a genuine refactor, not a minimal diff.
