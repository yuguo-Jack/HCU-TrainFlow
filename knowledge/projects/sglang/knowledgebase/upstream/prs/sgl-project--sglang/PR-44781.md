# [Fix] multimodal: expand single-channel GPU JPEG tensors to RGB on load

[Upstream PR](https://github.com/sgl-project/sglang/pull/44781) · state: open · merged: False

## Original PR description

## Motivation

Fixes #44748.

Grayscale JPEGs decoded on GPU via `torchvision.io.decode_jpeg` (default unchanged mode) come back as `[1, H, W]`. `BaseMultimodalProcessor._load_single_item` returned those tensors unchanged, so Qwen-VL (and similar) processors that normalize with three RGB channel means fail:

```
RuntimeError: output with shape [1, 1, H, W] doesn't match the broadcast shape [1, 3, H, W]
```

Related: #35101 forces `ImageReadMode.RGB` at the decode call site. This PR is defense in depth at the load boundary so any 1-channel tensor is expanded before processing, including when the decode path is unchanged.

## Modifications

- Add `ensure_rgb_image_tensor` and use it from `smart_to_rgb` for tensors.
- Route GPU-decoded tensors through `smart_to_rgb` in `_load_single_item` instead of returning them raw.
- Add unit tests that mock `load_image` returning 1-channel / HW / RGB tensors.

## Accuracy Tests

- New unit tests in `test_base_processor_image_decode.py` (`TestLoadSingleItemGrayscaleGpuTensor`).
- Helper smoke-checked for CHW `[1,H,W]` → `[3,H,W]`, HW → `[3,H,W]`, and RGB passthrough.
