# [Fix] moe: Preserve expert recording with TRT-LLM routing

[Upstream PR](https://github.com/sgl-project/sglang/pull/48142) · state: open · merged: False

## Original PR description

PR Title:[Fix] moe: Preserve expert recording with TRT-LLM routing
## Motivation

Fixes #47932.

When FlashInfer TRT-LLM is used with expert distribution recording enabled, SGLang can still select `BYPASSED` routing. Since expert selection happens inside the TRT-LLM kernel, the normal `select_experts` path is skipped, along with the expert distribution recorder hook.

As a result, the server can process requests normally while reporting zero expert counts. This makes the recorded statistics unreliable when monitoring expert usage.

## Modifications

This PR makes a small change to `TopK.bind_runner_backend`:

- Use `TopKOutputFormat.STANDARD` for FlashInfer TRT-LLM when expert distribution recording is enabled, allowing the recorder to observe expert selection.
- Keep the existing `BYPASSED` routing when recording is disabled.
- Leave the FlashInfer MXFP4 routing behavior unchanged.
- Add a CPU regression test covering all four recording modes (`stat`, `stat_approx`, `per_pass`, and `per_token`), as well as the default behavior with recording disabled.

The aim is to make expert distribution recording work correctly without changing the normal inference path.

## Accuracy Tests

Added a registered CPU regression test to check routing format selection across all four recording modes and when recording is disabled.

The test has not yet been executed in a full SGLang development environment. End-to-end inference accuracy validation is also pending.

## Speed Tests and Profiling

No performance benchmarks have been run yet.

Normal inference with recording disabled retains the existing routing path, so no performance change is intended for that configuration.

When recording is enabled, standard routing may introduce additional overhead compared to the in-kernel bypass. This has not yet been measured.
