# fix(diffusion): make warmup preload components and headroom configurable

[Upstream PR](https://github.com/sgl-project/sglang/pull/43674) · state: open · merged: False

## Original PR description

## Motivation

Fixes #41126.

Warmup preferred preloads are hard-coded. `preferred_ready_after_request` is set on the pipeline's `ComponentUse` hints, and the fit check always reserves 1 GiB (`_WARMUP_PRELOAD_MARGIN_BYTES`). A user cannot turn those preloads off, limit them to named components, or change the headroom. The weight-only check still does not estimate activations or attention workspace; this change only makes the existing policy configurable.

## Modifications

- `--warmup-preload-components` (`auto` | `none` | comma-separated list). `auto` keeps today's hints. `none` skips preferred warmup preloads and does not unload components with `keep_ready_after_warmup`. A list accepts exact module keys or the existing groups `dit`, `text_encoder`, `image_encoder`, `vae`, and `all`. A group includes numbered suffixes. An exact key matches only that module. Names the pipeline did not mark preferred are not preloaded. An unmatched selector warns once.
- `--warmup-preload-margin-gib` (float, default `1.0`). `0` is allowed. Negative, NaN, and infinite values are rejected. `round(1.0 * 1024**3)` equals the old constant.
- The filter runs only when `batch_is_warmup`, and only after an explicit `--component-residency` mode has won. The single offloaded DiT rule is unchanged.
- The margin is stored on `ResidencyState.warmup_preload_margin_bytes` and read by both free-memory comparisons in `ComponentOffloadStrategy.finish_request`. `SnapshotOffloadStrategy` inherits that. Layerwise offload does not use the margin; the component filter still clears `preferred` before the strategy call.
- A missing policy on a test fake means `auto`. A missing margin means 1 GiB.
