## Motivation

DeepEP V2 sizes per-expert masked GEMM buffers using the configured maximum dispatch capacity across all source ranks, even for small CUDA Graph batches. These buffers are retained by captured graphs and can cause out-of-memory failures during capture.

## Modifications

- Bound masked GEMM buffers by the current source-token upper bound, accounting for worst-case routing, uneven TP shards, Graph padding, and GEMM alignment.
- Apply the tighter bound when EP spans the full TP group with attention DP/CP disabled; retain the existing capacity for other topologies.
- Keep communication buffers unchanged, with no additional collectives, device-to-host synchronization, or model-specific conditions.
- Add focused capacity and topology-fallback coverage to the existing CPU lifecycle tests.

## Accuracy Tests

- All **11 CPU lifecycle tests** passed. Four-rank GPU checks cover worst-case routing, uneven shards, and CUDA Graph replay.
- GLM-5.3-Flash, **4 × H200, TP4/EP4**, ordinary prefill/decode: GSM8K, **1,314 examples × 2 runs: 96.0%, 95.9%**. Model validation includes #46225 and #46424 for independent KDA/GDN padding and DSA output-layout fixes; neither is a code dependency of this allocation change.

## Speed Tests and Profiling

Capture comparison with an **8,192-token prefill chunk**, default model context length and attention TP gather, `mem_fraction_static=0.85`, and a decode Graph limit of 64:

| Metric | Baseline | This PR |
|---|---|---|
| Decode CUDA Graph capture | OOM while capturing bs56, after bs64 completed | All 10 capture sizes completed |
| Complete Graph memory per GPU | Unavailable: capture failed | **2.90–2.91 GiB** |
| Available memory per GPU after capture | Unavailable | **17.28 GiB** |

The baseline failed when allocating a **4.50 GiB** masked GEMM workspace with approximately **3.11 GiB** free. This PR completed capture at the same settings. Memory values above use framework capture logs; no complete baseline Graph-memory total or percentage reduction is reported because its capture failed.

Reproduction command (model path and serving address replaced):

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3 \
EP_DISABLE_GIN=1 \
SGLANG_DEEPEP_V2_NUM_MAX_DISPATCH_TOKENS_PER_RANK=2048 \
python -m sglang.launch_server \
  --model-path /path/to/GLM-5.3-Flash \
  --served-model-name llm \
  --trust-remote-code \
  --tp-size 4 \
  --ep-size 4 \
  --moe-runner-backend deep_gemm \
  --moe-a2a-backend deepep_v2 \
  --kv-cache-dtype fp8_e4m3 \
  --mamba-ssm-dtype bfloat16 \
  --dsa-prefill-backend tilelang \
  --dsa-decode-backend tilelang \
  --mem-fraction-static 0.85 \
  --max-mamba-cache-size 320 \
  --max-running-requests 64 \
  --cuda-graph-max-bs-decode 64 \
  --cuda-graph-bs-decode 1 2 4 8 16 20 24 32 40 48 56 64 \
  --chunked-prefill-size 8192 \
  --reasoning-parser glm45 \
  --tokenizer-worker-num 4 \
  --host 127.0.0.1 \
  --port 8000 \
  --random-seed 42
```

The per-rank dispatch capacity is 2,048 for this TP4/chunk8192 configuration. `EP_DISABLE_GIN=1` selects the non-GIN communication path used for validation. After TP alignment, the actual captured sizes are `[4, 8, 16, 20, 24, 32, 40, 48, 56, 64]`. The command uses default context length and attention TP gather and does not override `max_prefill_tokens`.
