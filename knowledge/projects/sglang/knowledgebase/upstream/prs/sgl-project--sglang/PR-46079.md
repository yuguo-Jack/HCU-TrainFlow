# [Fix] model_loader: Hash np_cache weight file names instead of using tensor names

[Upstream PR](https://github.com/sgl-project/sglang/pull/46079) · state: open · merged: False

## Original PR description

## Motivation

`np_cache_weights_iterator` (`--load-format npcache`) used each tensor's name as the file name of its `.npy` cache entry:

```python
state = torch.load(bin_file, map_location="cpu", weights_only=True)
for name, param in state.items():
    param_path = os.path.join(np_folder, name)
    with open(param_path, "wb") as f:
        np.save(f, param.cpu().detach().numpy())
```

`name` is read out of the checkpoint, so it is not a safe path component. That has two consequences:

1. **It decides where the file goes.** A name holding `..` or a leading `/` puts the write outside `<model>/np/`. The names are then persisted to `weight_names.json` and joined again on the read path, so later starts read back from the same places even without re-reading the checkpoint.

2. **It rejects legitimate names.** A checkpoint whose tensors are named with `/` separators raises `FileNotFoundError`, because `np/` has no matching subdirectory — so such checkpoints cannot be loaded with this format at all.

The on-disk name never needed to be the tensor name: `weight_names.json` already carries the mapping, which is what makes this fixable without changing what the iterator yields.

## Modifications

- `_np_cache_file_name()` derives the cache file name from sha256 of the tensor name, so the name is opaque and collision-resistant.
- `weight_names.json` becomes `{"version": ..., "weights": [[name, file_name], ...]}`. `_load_np_cache_index()` treats absent / unreadable / other-version as "rebuild". The version field is load-bearing: an index written by the previous layout maps weights to checkpoint-chosen paths, so it is discarded rather than read under the new rules.
- The read path rejects an index entry whose file name is not a plain basename, so a leftover or hand-edited index cannot redirect the read either.

Callers are unaffected: the iterator still yields `(tensor_name, tensor)` pairs, with the same names in the same order.

Added four cases to `test/registered/unit/model_loader/test_weight_utils.py` (CPU, no model weights): a traversing name stays inside the cache dir, a `/`-separated name round-trips, an old-layout index is rebuilt rather than trusted, and a current-version index naming a path is rejected. The first two fail on the pre-fix code — the first overwrites a file outside the cache directory, the second raises `FileNotFoundError`.

## Accuracy Tests

No accuracy impact. This changes only the on-disk file names of np_cache entries, never a tensor value; the iterator yields the same names and the same tensors. `test_separator_in_tensor_name_round_trips` pins the value round-trip.

## Speed Tests and Profiling

No measurable impact expected. The added work is one sha256 over each tensor's *name* (not its data) while the cache is built, and one basename comparison per weight on the cached read path; the number of files read on a cache hit is unchanged.

One-time cost: the first load after this change rebuilds the np cache for a given model, because the old index is discarded. Subsequent loads are as before.
