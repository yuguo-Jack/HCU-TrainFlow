# [Test] HiCache: Don't require a storage hit in the random-failure test

## Motivation

`TestHiCacheStorageRandomFailure` (added in #43539) starts the server with `SGLANG_TEST_HICACHE_BACKEND_RANDOM_FAILURE=0.05`. With that setting, the HiCache storage failure injector fails each storage call with probability 0.05, drawn independently on each TP rank. If a failure lands on a prefetch on either rank, the ranks agree on a miss and the request runs with no tokens from storage. The class's own test, `test_random_failures_degrade_to_cache_misses`, checks exactly that: every request still completes and the server stays healthy.

The class also inherits `test_basic_backup_and_prefetch` from `HiCacheStorageBaseMixin`. That test requires more than 700 of the 768 prompt tokens to come back from storage, so it fails whenever an injected failure hits the prefetch. Its single retry draws again at the same rate. It failed this way in `base-b-test-2-gpu-large` on an unrelated PR, with `cached_tokens=0` on both tries ([job](https://github.com/sgl-project/sglang/actions/runs/40473220711/job/122115023492)), and passed on main's scheduled run.

This PR stops the random-failure class from running the inherited strict-hit test. `TestHiCacheStoragePageFirstDirectIO` and `TestHiCacheStorageRandomDelay` still run it; injected delays never turn a hit into a miss.

- **Accuracy:** no runtime code changes.
- **CI:** removes an intermittent `base-b-test-2-gpu-large` failure (`AssertionError: 0 not greater than 700 : Expected significant cached tokens for remote hit`).
