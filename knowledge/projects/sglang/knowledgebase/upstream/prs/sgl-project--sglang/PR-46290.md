# [Refactor] spec: Resolve draft parallel placement from model declarations

[Upstream PR](https://github.com/sgl-project/sglang/pull/46290) · state: closed · merged: True

## Motivation

Draft placement under DP attention is currently inferred from speculative algorithm names and worker flags, even though the choice belongs to the draft model implementation. Target-side draft KV sizing also resolves its attention width separately.

Resolve placement from a model declaration and share the resulting layout across execution and memory setup. Existing defaults are preserved: with TP8 / attention DP2, a single-group dense draft still runs as two TP4 replicas, each consuming its own request rows.

## Modifications

- Add immutable `DraftParallelSpec` and `DraftParallelLayout`. Models declare either ordinary execution within one TP group or participation in the target's attention/FFN layout. The resolver uses the same registered model class as the loader, including replacements.
- Declare the existing behavior on Llama EAGLE3, Kimi K2.5 EAGLE3, DFLASH and DeepSeek V4 DSpark. Keep an explicit legacy adapter for undeclared model implementations.
- Resolve the concrete group, attention TP width and CP suppression once in target scope. Reuse that layout for draft construction, attention backends, graph setup, forwards and DP phase coordination. Preserve DFLASH's CP-only policy, the other workers' existing gates, scope restoration and nesting protection.
- Keep DSpark's local logits synchronization separate from its whole-model placement; retain the existing unsupported-layout rejection.
- Pass the same resolved layout to target KV setup. Move DFLASH-family bytes-per-token calculation to KV configuration so reservation and fused placement use the execution width. Direct runner callers without a draft worker retain a named compatibility path.

This does not add a placement planner or CLI option, widen supported layouts, or change model arithmetic, collective ordering or embedding/head sharing timing.
