# [Fix] openai: Reject developer messages silently omitted by chat templates

[Upstream PR](https://github.com/sgl-project/sglang/pull/40103) · state: open · merged: False

## Original PR description

## Motivation

Fixes #40082. A chat template can silently omit `developer` messages while `/v1/chat/completions` accepts the request. With the Qwen3-0.6B tokenizer, the resulting prompt contains the user question but loses the developer instruction.

Return a 400 response before generation when the selected Jinja template does not render a developer message. Preserve the role, contents, and ordering for templates that support it; do not implicitly promote developer instructions to system instructions.

## Modifications

- Before encoding an uncached Jinja prompt containing developer messages, render a separate probe with a distinct sentinel at each developer message's actual conversation position. Reject a missing sentinel with the offending message index.
- Use the same tools, template options, and string/content-parts representation as the request. The probe is never tokenized or sent to generation, and does not mutate request data.
- Requests without developer messages keep one render. Supported developer requests add one probe render on a cache miss; existing cache hits avoid both renders. Native custom encoders are unchanged.
- Cover silently ignored roles, content parts, multiple developer messages, original-prompt preservation, cache reuse, and the serving handler's 400 response before generation.

I checked existing work: #40077 addresses inline instruction ordering in Responses/Kimi Messages, not unsupported developer roles in this generic Chat Completions path. No direct fix for #40082 was found at submission.
