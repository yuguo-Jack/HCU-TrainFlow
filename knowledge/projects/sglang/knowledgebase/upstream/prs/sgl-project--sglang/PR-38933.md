# feat(moe): integrate FlashInfer BF16 MegaMoE for DeepSeek-V3

[Upstream PR](https://github.com/sgl-project/sglang/pull/38933) · state: closed · merged: False

## Original PR description

## Motivation

Integrate FlashInfer's capacity-bounded SM100 BF16 rank-major MegaMoE backend into SGLang's DeepSeek-V3 expert-parallel path. The integration targets the low-latency TP8/EP8 deployment coordinate implemented by https://github.com/flashinfer-ai/flashinfer/pull/4810 and fails closed for unsupported model or parallelism settings. Each rank passes its actual active slice of 1–128 tokens, and all eight ranks must use the same active-row count for a launch.

This PR corresponds to the validated SGLang integration head
`3fa9c343c4724a93b494d569a780a726c238dff6`, which includes upstream main
`afe90a8bc908002219993794404c7c95dd3ced1d`, and FlashInfer head
`466998f16191cda80fb531f0268ccd536b3def16`. Its resolved tree is
`7de16a817c506acf967b42f24e8c9bbecb1b9209`.

Dependency: this integration requires the FlashInfer API in
[FlashInfer PR #4810](https://github.com/flashinfer-ai/flashinfer/pull/4810),
which is not yet merged. Tests below use that exact dependency commit, not a
released FlashInfer wheel. Enable the adapter with
`--moe-a2a-backend flashinfer_megamoe --moe-runner-backend auto` in the
supported unquantized BF16 TP8/EP8 configuration.

## Modifications

- Add `flashinfer_megamoe` as an explicit MoE A2A backend and validate its fixed TP8/EP8, BF16, static-expert-placement contract during server-argument resolution.
- Convert loaded canonical BF16 expert weights into the FlashInfer layer, transfer weight ownership after preprocessing, and use FlashInfer's session-owned 128-row capacity buffers without SGLang-side staging or padding.
- Route the fused dispatch, expert compute, and combine path through FlashInfer while retaining SGLang's shared-expert computation.
- Split eager prefills into rank-synchronous chunks of at most 128 tokens and pass each actual 1–128-row slice directly to FlashInfer; no synthetic padding rows are dispatched.
- Support admitted CUDA graph buckets without allocator work during capture while preserving the same active-row count across ranks.
- Add focused server-argument, active-slice, weight-build, warmup, chunking, capture-state, and graph-contract tests.
