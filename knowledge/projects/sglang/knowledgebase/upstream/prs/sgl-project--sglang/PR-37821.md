# [Feat] diffusion: Add API key authentication to HTTP server

[Upstream PR](https://github.com/sgl-project/sglang/pull/37821) · state: open · merged: False

## Original PR description

## Summary

Fixes #47067

Add API key authentication to Diffusion HTTP and WebSocket endpoints using the existing SRT middleware and endpoint permission levels. This supersedes the closed PR #23244.

Management endpoints use `ADMIN_OPTIONAL`, matching SRT:
- No keys: normal and management endpoints remain open.
- API key only: both require the API key.
- Admin key only: normal endpoints remain open; management endpoints require the admin key.
- Both keys: normal endpoints require the API key; management endpoints require the admin key.

## Changes

- Add `--api-key` and `--admin-api-key` to Diffusion server arguments, excluding the keys from the server argument representation.
- Apply shared authentication to HTTP requests and WebSocket handshakes, and mark LoRA, weight management, and memory release/resume endpoints with `ADMIN_OPTIONAL`.
- Reject unauthorized WebSocket connections before acceptance using ASGI close code 1008 (HTTP 403 on the wire). This covers realtime video, Action, and OpenPI routes. The shared middleware also applies the same policy to SRT WebSocket routes.
- Resolve authentication metadata across supported FastAPI router layouts and keep `/liveness` public. Preserve upstream health/readiness/metrics and CORS preflight exemptions.
- Register CORS outside authentication so cross-origin clients can read authentication error responses.
- Add parser, HTTP authentication, and WebSocket handshake regression tests.
- Include the WebSocket dependency in the cross-platform Diffusion extra and restrict a NVIDIA-specific attention test to NVIDIA CUDA.
