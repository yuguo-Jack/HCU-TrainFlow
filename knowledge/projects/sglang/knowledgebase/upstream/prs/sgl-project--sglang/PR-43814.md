# [Fix] [NPU] disaggregation: Fix host-pool backup for decode retraction

[Upstream PR](https://github.com/sgl-project/sglang/pull/43814) · state: open · merged: False

## Original PR description

## Motivation

Enable the existing `--disaggregation-decode-retraction-backup host_pool` option and automatically selected host-pool backup on Ascend NPU decode servers.

When a decode server uses host-pool backup without enabling hierarchical caching or decode KV offload, it still needs Ascend HiCache IO and memory-layout settings. These settings were only applied to hierarchical caching and KV offload. In addition, `page_first_direct` host buffers used the wrong dimension when building per-layer views, which could cause incorrect KV transfers or out-of-bounds indexing when the host pool has fewer pages than model layers.

## Modifications

- **`python/sglang/srt/hardware_backend/npu/utils.py`**: Apply the Ascend HiCache configuration when the server role is `decode` and the retraction backend is explicitly `host_pool` or unset for automatic selection. This selects `kernel_ascend` IO and the existing NPU layout selection; MHA uses `page_first_direct`.
- **`python/sglang/srt/mem_cache/pool_host/mha.py`**: Build per-layer views for `page_first_direct` by transposing the page and layer dimensions, as already done for `page_first`.
- **`test/registered/unit/npu/test_decode_retraction_backup.py`**: Add eight registered NPU tests covering configuration selection, FIA and non-FIA buffers, exact KV restoration into newly allocated device pages, partial pages, exhausted host capacity, and the `none` backend.

## Accuracy Tests

- All **8 NPU unit tests passed** in `sglang-wt-a3`, including actual NPU KV backup/restore with both `cpu_tensor` and `host_pool`.
- `git diff --check` and Python syntax checks passed.

Integration validation before the rebase used actual **Llama-3.2-1B-Instruct** weights with BF16, MHA, TP=1, Ascend transport, and eager prefill/decode. Each scenario used four concurrent requests generating 64 tokens:

| Scenario | Result |
| --- | --- |
| Baseline | All four requests completed without retraction. |
| `cpu_tensor` | All four requests completed after eight retractions; generated token IDs matched the baseline exactly. |
| `host_pool` | All four requests completed after eight retractions; generated token IDs matched the baseline exactly. |
| Automatic selection | Resolved to `host_pool`; all four requests completed after eight retractions and matched the baseline exactly. |
| `none` | Retracted requests returned HTTP 503; the remaining request completed. |
| Exhausted host pool | The request that could not be backed up returned HTTP 500; the other three completed. |

All six decode instances remained healthy after their requests. These PD integration scenarios have not been rerun after the rebase.

Shared CPU cache regression tests before the rebase: **32 passed, 1 skipped**, with the optional NPU-only Mamba copy kernel disabled for CPU fixtures. This fixture adjustment was not used for the NPU unit tests or PD integration runs. Ruff and isort also passed before the rebase.
