## Motivation

The NPU precision-test (coverage-based test selection) pipeline consumes a prebuilt
baseline: `test_case_map.json` (test case → covered lines) plus `outputs.tar.gz`
(the `covstub` source tree). Both files were expected in OBS, but they had to be
uploaded **manually** after each `Coverage Collection (NPU)` run. A forgotten
upload meant `recommend-tests-from-coverage` silently fell back to a stale
baseline, and the mis-selection was invisible until a regression slipped through.

The baseline also had no quality floor: a run whose coverage collapsed (missing
subprocess data, skipped suites, partial job failures) would happily overwrite a
good baseline, degrading every subsequent PR's test selection with no signal.

At the same time, the new automated upload must not become a single point of
failure — the shared-disk baseline is still the primary artifact, and readers of
that disk must not lose it just because an external bucket was unreachable.

## Modifications

Workflow-only changes in `.github/workflows/pr-test-npu.yml`; product code and
test behavior are untouched. Everything below runs only in
`coverage_mode: true` (the `setup-covstub` job), i.e. never on a normal PR run.

- **Single source of truth for the NPU-only coverage number.** The
  `Generate HTML coverage report` step now computes the NPU-only total once,
  writes it to `${RUN_DIR}/npu_coverage.txt`, and the run-page summary reuses
  that same value. The number shown to reviewers and the number gated on can
  no longer diverge; the file is written unconditionally because
  `GITHUB_STEP_SUMMARY` may be unset on the k8s runner pool.

- **New `Upload baseline to OBS` step.** Replaces the manual push:
  - Skips (warning only) when `test_case_map.json` / `outputs.tar.gz` are
    missing, so an empty run can never overwrite a good baseline.
  - Fails closed if `npu_coverage.txt` is absent (e.g. the report step died
    before writing it).
  - Enforces an `MIN_NPU_COVERAGE=40` floor on NPU-only line coverage; below
    it the upload is rejected instead of poisoning the baseline.
  - Skips (warning only) when `OBS_ACCESS_KEY_PRECISION` /
    `OBS_SECRET_ACCESS_KEY_PRECISION` are not configured.
  - Bootstraps `obsutil` on demand, uploads with `-acl=public-read`, then
    verifies each object with an anonymous HTTPS `HEAD` == 200 — a stale
    private ACL would otherwise only surface as a confusing failure in the
    next run's download step.

- **`Publish outputs and map to shared disk` is now `if: ${{ !cancelled() }}`.**
  A failed OBS upload no longer skips the primary shared-disk publish.

- **`Clean up per-run directory` keeps default `success()` and also sweeps
  residue.** Any earlier failure (including the OBS upload) still preserves
  `RUN_DIR` for manual recovery; on success it additionally deletes
  `*-attempt-*` directories older than 8h, at `-maxdepth 1` so the shared
  `coverage/` dir and concurrently running jobs are never touched.
