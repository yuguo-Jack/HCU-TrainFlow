# [VLM][EPD] Honor caller mm_hashes under zmq_to_scheduler and mooncake

[Upstream PR](https://github.com/sgl-project/sglang/pull/43887) · state: open · merged: False

## Original PR description

## Motivation

An external KV-aware router can send `mm_hashes`, one hash per image. SGLang then derives the image pad token ids from that hash, so the prefix-cache keys and the token ids in KV events follow the router's hash. With encoder disaggregation on `zmq_to_scheduler` (what `auto` picks for most models) or `mooncake`, SGLang drops these hashes. On these backends the scheduler builds `mm_inputs` after the embeddings arrive, but `TokenizedGenerateReqInput` has no `mm_hashes`, so the scheduler pads with the hash of the received embedding. A router that matches KV events against its own hash then never matches a block that holds image tokens. `zmq_to_tokenizer` is not affected, because TokenizerManager builds `mm_inputs` there. This PR carries `mm_hashes` to the scheduler and applies them with the same helper that TokenizerManager uses.

## Modifications

- TokenizerManager sends `mm_hashes` to the scheduler in a new optional field of `TokenizedGenerateReqInput`.
- The caller-hash loop moves, unchanged, into a shared helper, `apply_caller_mm_hashes`. The encoder receiver calls it when it builds `mm_inputs`, which covers the ZMQ, gRPC and mooncake paths.
- `mm_hashes` that is not a list of strings now gets a 400. Main ignored it with a warning. With the new typed field, it would fail the scheduler's decode. This includes a list that mixes `null` with valid hashes, such as `[null, "<hex>"]`. Main applied the valid entries of that list.

This PR and #41375 edit the same TokenizerManager block. Whichever PR lands second moves the #41375 rebuild of `padded_input_ids` into `apply_caller_mm_hashes`.

## Accuracy Tests

`Qwen/Qwen3-VL-2B-Instruct`, one GPU, KV events on, encoder and language servers on `zmq_to_scheduler` (the only backend run live). The request sends `mm_hashes: ["00c0ffee12345678"]`, so the expected pad is `1_000_000 + hash % 2**30 = 306419896`.

| Build | Image pad in KV events | Output |
|---|---|---|
| main `450837e770` | 862609084 (embedding hash) | 1041 prompt tokens |
| this PR | 306419896 (caller hash) | 1041 prompt tokens, same text as main |

Unit tests: three new tests. The scheduler-built pad value test and the shape rejection test fail on main and pass here. The forwarding test fails if `_create_tokenized_object` stops copying `mm_hashes`. The rest of the 9 related unit files pass on both (278 passed, 2 skipped).
