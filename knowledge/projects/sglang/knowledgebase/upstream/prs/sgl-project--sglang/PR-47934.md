# [Fix] [NPU] dsv4: transfer A3 C4 state using peer-local rows

[Upstream PR](https://github.com/sgl-project/sglang/pull/47934) · state: open · merged: False

## Original PR description

## Motivation

DeepSeek-V4-Flash PD on A3 fails when prefill runs without speculation and decode enables DSpark. The target C4 compressor uses an 8-row ring on P and a 16-row ring on D. A3 currently bundles each entire attention/indexer ring into the SWA state component, so the peers publish different item strides:

- Attention state: 65,536 vs 131,072 bytes (8,192 bytes per row).
- Indexer state: 16,384 vs 32,768 bytes (2,048 bytes per row).

The shared manager correctly rejects this layout mismatch, and generation returns HTTP 500 with the Ascend transfer backend. This PR addresses that original failure only.

## Modifications

The diff is limited to **three production files and one regression-test file**. C4 payload construction stays in the existing hook; no request-pool API is added.

- Keep A3 SWA registration limited to SWA KV pages; register C4 attention/indexer state as individual rows through the existing Ascend C4 component.
- Derive the last eight logical history positions independently on each peer, using its request token table, full-to-SWA mapping and local ring size. This follows the A3 explicit compressor table, including history spanning noncontiguous SWA pages.
- Keep the existing A5 request-bank mapping and the shared stride/index-length guards.
- Add regression coverage for short histories, ring/page boundaries, different physical page mappings, row-sized registration, and agreement with the actual compressor history table.

Both P and D must use the updated A3 state layout. There is no mixed-version wire compatibility. Separate PP empty-component and ROCm unified-state issues are outside this PR.
