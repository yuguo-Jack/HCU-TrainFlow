# [Fix] HiSparse: use receiver draft layout for PP KV transfer

[Upstream PR](https://github.com/sgl-project/sglang/pull/48332) · state: open · merged: False

## Original PR description

## Motivation

With pipeline-parallel prefill and HiSparse speculative decode, prefill and decode do not necessarily expose the same target/draft KV layout. An early prefill stage has no draft, and a HiCache prefill tail can pack draft KV into the target pool. In both cases the local `num_draft_entries` can be zero while decode exposes a host-backed target prefix and a device-backed draft suffix.

`MooncakeKVManager.send_kvcache()` currently derives the receiver's host/device boundary from this local count. This raises `HiSparse spec PD transfer requires an appended device-only draft KV buffer` for the layouts above, or can classify the wrong destination buffers when the counts differ.

## Modifications

- Append decode's draft-entry count to Mooncake's receiver registration message. Preserve the existing frame positions and accept older messages without the appended field.
- Carry that count through the transfer worker and use it to identify the receiver's device-only draft suffix. Keep the existing local-count fallback for older peers and existing validation of the count.
- Keep the DSV4 compressed layout path unchanged.
- Add exact destination-address tests for PP stages with absent/packed local draft KV, and registration serialization/legacy-message regressions.
