# [Fix] Support Qwen prefill CP with whole-expert EP and optimize NIXL KV transfers

[Upstream PR](https://github.com/sgl-project/sglang/pull/47920) · state: open · merged: False

## Original PR description

Allow EP == TP with Qwen CP/TP group sharing and pack NIXL KV head slices into bounded per-worker GPU buffers before coalesced direct-to-KV writes. Preserve scratch ownership across asynchronous transfers and quarantine uncertain completions.

Add registered CPU/CUDA regressions and a two-rank collective smoke check. Validated with 60 focused tests, pre-commit hooks, and live PD generation and benchmark checks.

## Motivation

Qwen prefill CP currently rejects EP > 1, preventing whole-expert partitioning needed to avoid FP8 block-alignment failures when expert intermediate dimensions are split across TP ranks.
With CP enabled, prefill and decode can also have different attention-TP layouts. The existing NIXL head-slice path generates many small per-token transfers, causing severe latency under concurrent cached-prefix workloads.

## Modifications

- Allow EP == TP alongside EP == 1 for Qwen CP/TP group sharing, reusing existing CP gather, expert reduction, and CP take-back operations.
- Add GPU packing of destination KV head slices before coalesced direct-to-KV transfers.
- Bound scratch memory to 64 MiB per transfer worker, wait for completion before reuse, and quarantine buffers after uncertain failures.
- Preserve bootstrap rank pairing and existing fallback paths without requiring decode-side staging.
- Add registered CPU/CUDA regression tests and a two-rank collective validation script.
Validation: 60 focused tests and all applicable pre-commit checks passed. In a controlled concurrency-10 benchmark, mean TTFT decreased from 53.89 s to approximately 1.46 s, with prefill BCG disabled in both runs.
