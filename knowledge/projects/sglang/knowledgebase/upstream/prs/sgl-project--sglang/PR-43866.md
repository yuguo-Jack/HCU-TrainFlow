# [Multimodal] Return 400 for images Pillow refuses as decompression bombs

[Upstream PR](https://github.com/sgl-project/sglang/pull/43866) · state: open · merged: False

## Original PR description

## Motivation

An image above twice `Image.MAX_IMAGE_PIXELS` (178,956,970 pixels) makes `Image.open` raise `DecompressionBombError`, before any decode. That class subclasses `Exception`, not `OSError`, so neither `except (OSError, SyntaxError)` in `_load_image` nor `CLIENT_MEDIA_EXCEPTIONS` catches it. `_load_single_item` then reports the image the client sent as a server fault, a 500, where `test_base_processor_bad_input.py` says client media that cannot be decoded raises `ValueError`.

```
$ PYTHONPATH=python python bomb.py   # main 279f1fa, Pillow 12.3.0
PNG 27385 bytes, 225,000,000 pixels, Pillow limit 89478485
RuntimeError <- DecompressionBombError: 0...: Image size (225000000 pixels) exceeds limit of 178956970 pixels, could be decompression bomb DOS attack.
```

Refs #43707: once #43713 restores the Pillow limit for NanoNemotron, those requests reach this path too.

## Modifications

- `utils/common.py`: add `Image.DecompressionBombError` to `CLIENT_MEDIA_EXCEPTIONS`. Every user of the tuple (`llava.py`, the encoder preprocessor, `systemone/serving.py`) gets the same 400.
- `test_base_processor_bad_input.py`: a 15000 x 15000 1-bit PNG, about 27 KB, must raise `ValueError` caused by `DecompressionBombError`. The class also joins `test_tuple_covers_the_documented_families`.
