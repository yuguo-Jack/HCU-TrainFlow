## Motivation

The DeepGEMM contiguous MoE path currently executes clamped SwiGLU activation, per-token group FP8 quantization, and scale-layout conversion as separate operations.
This introduces additional kernel launches and materializes an intermediate BF16 activation tensor. Fuse these operations to reduce memory traffic and launch overhead while preserving the existing numerical behavior.
The optimization is independent of context parallelism.

## Modifications

- Extend the existing contiguous activation–quantization CUDA kernel to support BF16 intermediate rounding and TMA-aligned FP32 scale output.

- Add shape-dependent rows-per-CTA selection.

- Integrate the fused kernel into the eligible DeepGEMM contiguous MoE path.

- Keep the existing implementation as the fallback for unsupported configurations.

- Add an opt-in environment variable, disabled by default:
```bash
export SGLANG_DEEPGEMM_FUSE_ACTIVATION_QUANT=1

sglang serve \
  --model-path /path/to/model \
  --moe-runner-backend deep_gemm
```
-Add registered correctness tests and an operator microbenchmark.

## Accuracy Tests

Validated on NVIDIA H200:
- 72 correctness tests passed, covering multiple token counts and hidden dimensions, scale layouts, CTA configurations, tail handling, zero/NaN inputs, empty inputs, and CUDA Graph replay.
- Verified exact FP8 output and FP32 scale agreement against the existing separate-operation implementation.
- Tested the real DeepGEMM contiguous execution path, including both grouped GEMMs, with hidden dimensions of 512 and 3072. Outputs were bitwise identical with fusion enabled and disabled.
These are operator-level and runner-level checks; no model-level accuracy claim is made.

## Speed Tests and Profiling

Measured on NVIDIA H200 using CUDA Graph timing with rotating input/output buffers to avoid hot-L2-only measurements. Results are the median of five alternating trials per implementation.
The baseline includes activation, FP8 quantization, and scale-layout conversion. The fused implementation performs these operations in one kernel.
| Tokens | Baseline (µs) | Fused (µs) | Speedup |
|---:|---:|---:|---:|
| 8192 | 20.62 | 6.62 | 3.11× |
| 32768 | 61.46 | 21.86 | 2.81× |
| 65536 | 117.20 | 41.97 | 2.79× |
