# [Perf] Route BF16 mixed-batch decode tails through decode attention

[Upstream PR](https://github.com/sgl-project/sglang/pull/43238) · state: closed · merged: True

## Original PR description

## Motivation

In ordinary BF16 mixed prefill/decode batches, one-token decode tails run through context attention. In the measured Qwen3-VL workload, enabling mixed chunking therefore reduces concurrency-128 throughput from approximately 3765 to 3201 output tokens/s.

## Modifications

Identify the trailing one-token requests in eligible extend batches. Run context attention for the prefill prefix and the existing fixed-query-length decode kernel for the tail, preserving request order, page-table slices and shared output-buffer reuse. Restrict the split to BF16 causal decoder attention without speculative metadata; retain the existing paths for other batches. No new kernel or launch flag is added.

This change is based directly on upstream main `2e64740442` and has no dependency on the other optimization PRs. Repository pre-commit checks pass on this branch. GPU results below are prior measurements of the extracted implementation, not fresh validation of this new main-based branch. No serving tests were restarted.

## Accuracy Tests

Prior standalone validation: 18 mixed-attention cases covering heterogeneous lengths and output-buffer aliasing; maximum absolute difference 0.001953125. This routing change uses a different attention execution path and is not a bitwise-equivalence claim. Main has since changed surrounding KV metadata code; fresh integration validation on this branch remains outstanding.

## Speed Tests and Profiling

Prior one-B300 Qwen3-VL-4B BF16 measurements, nominal 8192-input/1024-output text requests:

| Measurement | Original mixed routing | Split decode tails |
| --- | ---: | ---: |
| C128 output tokens/s | 3201.14 | 3777.27 |
| Representative attention batch: 8192 prefill tokens + 128 decode rows | ~3.79 ms | ~1.00 ms |

The serving change is +18.0% for this measured mixed-chunk configuration. Both arms already contained the same GEMM tuning; this is not a clean-main full-stack comparison. Single sweeps used different GPUs and do not establish a general speedup or repeatability bound.
