# [Feat] [NPU] layernorm-sp: Support sequence parallel on NPU

[Upstream PR](https://github.com/sgl-project/sglang/pull/41496) · state: open · merged: False

## Original PR description

## Motivation

Enable `--enable-layernorm-sp` (Megatron-style LayerNorm sequence parallelism) on the NPU (Ascend) backend. On CUDA the SP fast-path fuses the matmul with the collective using torch's `symm_mem` operators; Ascend has no equivalent, so on NPU the flag previously ran through a slower un-fused reduce-scatter/all-gather (or failed to engage the intended fast path at all). This PR wires an NPU fast-path on top of the CANN **MC2** (Matmul + Collective-Communication) fused kernels — `npu_mm_reduce_scatter_base` / `npu_all_gather_base_mm` — and makes the fused-eligibility decision device-aware, so `--enable-layernorm-sp` on Ascend matches the CUDA fused behavior.
It also removes an NPU startup crash in TP2 caused by the TP memory-balance heuristic, which assumes CUDA idle-capacity semantics that `torch.npu.mem_get_info()` does not model.

## Modifications

- **`layers/layernorm_sp.py`** — probe the CANN MC2 fused ops once at import on NPU (`_HAS_NPU_MC2_FUSED`); route `column_parallel_g_matmul` / `row_parallel_gbar_matmul` through `npu_all_gather_base_mm` / `npu_mm_reduce_scatter_base` using the TP group's HCCL `hcom` handle (`_npu_hccl_comm_name()`), with the existing plain reduce-scatter/all-gather retained as a safe fallback. Make `sp_fused_matmul_eligible()` device-aware: NPU additionally requires the MC2 kernels and 2-D weights, while CUDA keeps using `symm_mem`. The bookkeeping in `initialize_layernorm_sp()` is unchanged in behavior, but now emits an explicit `LayerNorm sequence parallelism (SP) ENABLED` log so activation is observable.
- **`arg_groups/layernorm_sp_hook.py`** — emit a startup warning on NPU that SP semantics are validated only by the NPU e2e test before relying on the flag in production on Ascend.
- **`distributed/bootstrap.py`** — skip `_check_tp_memory_balance` when `device == "npu"` so TP2 model init no longer hard-crashes on Ascend; `pre_model_load_memory` used for KV sizing is unaffected.
No op names, signature, or checkpoint layout change; the fallback keeps the non-NPU behavior byte-for-byte.

## Accuracy Tests

The NPU fast-path is exercised by a dedicated e2e GSM8K test located in a follow-up test branch (`feat/npu-layernorm-sp-tests`), running Qwen3-8B with tp=2, bf16 and `--enable-layernorm-sp`. It asserts both a GSM8K accuracy threshold (≥ 0.85) and that the SP-enabled log marker appears in server startup logs, proving the feature truly engaged rather than silently no-op'ing. The fused and un-fused paths are mathematically equivalent within floating-point reordering noise, so no numerics change is expected.
## Speed Tests and Profiling
On NPU the MC2 fused ops replace separate matmul + reduce-scatter/all-gather with single fused kernels, matching the CUDA fused path and avoiding extra collective round-trips. The fallback path only triggers if the CANN kernels are unavailable. No throughput regression is expected; no extra data copies are introduced.
