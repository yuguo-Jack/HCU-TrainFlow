# [Intel GPU] Dequantize dense block-fp8 weights to bf16 at load

[Upstream PR](https://github.com/sgl-project/sglang/pull/40616) · state: closed · merged: False

## Original PR description

## Motivation

On XPU a block-fp8 dense linear falls back to the block scaled kernel. In a
DeepSeek V4 Flash profile on Arc Pro B70 at TP8 that kernel was 81.5% of GPU
time across 944 calls per step, and it lost to oneDNN in bf16 even though it
reads half the bytes.

Folding the single scale per 128x128 block into the weight once at load turns
the runtime op into a plain mm, which oneDNN serves directly. The cost is
memory: 0.734 GB per card for that model, on the dense layers only. Expert
weights stay compressed.

## Modifications

`SGLANG_OPT_XPU_FP8_TO_BF16_GEMM` is a new `EnvBool(False)` under a new Intel
XPU section in `environ.py`. It is off by default, so no platform changes
behaviour unless it is set.

`_xpu_dequant_block_fp8` folds the per-[block_n, block_k] scale into the weight
and returns the layer's original dtype; a ue8m0 packed scale is inverted first.

`Fp8LinearMethod.process_weights_after_loading_block_quant` converts the weight
when the gate is on and the weight is `float8_e4m3fn`, drops
`weight_scale_inv`, and records `xpu_dense_bf16` on the method so a second call
is a no-op. `apply` then takes `F.linear`, and raises if it is handed
pre-quantized activations, which the dense bf16 path cannot consume.

A layer that declares `keep_plain_weight_layout` is skipped. That flag marks a
weight the model reads itself and runs its own GEMM on (DeepSeek V4 `wo_a` under
`SGLANG_OPT_FP8_WO_A_GEMM`), which needs both the fp8 weight and its scale.
`create_fp8_weight_` now initialises the flag to `False` so the new gate reads a
field that is always present; the two pre-existing read sites are left alone.

MoE weights are untouched.

## Accuracy Tests

`test/registered/unit/layers/quantization/test_xpu_dense_fp8_dequant.py`,
registered in `base-a-test-cpu`. It checks the fold against an independent
per-element reference for an aligned shape, a ragged one (200 x 300 against a
128 x 128 block, where the expanded scale has to be truncated) and a non-square
block, plus a negative control that the scale is actually applied. The fold is
plain torch, so the test needs no accelerator.

## Benchmarking and Profiling

The GPU time share quoted above is from an XPU profile of DeepSeek V4 Flash on
Arc Pro B70 at TP8. This PR adds no benchmark of its own: the flag is off by
default and the change is a load-time weight transform.
