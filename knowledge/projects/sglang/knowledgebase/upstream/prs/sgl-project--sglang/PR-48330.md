# [Benchmark] Add random video dataset support

[Upstream PR](https://github.com/sgl-project/sglang/pull/48330) · state: open · merged: False

## Original PR description

## Summary

SGLang's benchmark client (`python/sglang/benchmark/`) has an `image` dataset
(`--dataset-name image`) for synthetic image-based load testing, but no video
equivalent, despite the serving stack already supporting video end-to-end:
`GenerateReqInput` already has a `video_data` field, and the chat-completions
protocol already defines `video_url` content
(`python/sglang/srt/entrypoints/openai/protocol.py`).

This PR adds a `video` dataset type, following the same architectural pattern
as the existing `image`/`audio` datasets:

- A new `VideoDataset` dataclass in `python/sglang/benchmark/datasets/video.py`
  that generates synthetic random-content videos (random pixel frames, encoded
  via OpenCV `cv2.VideoWriter` to mp4/configurable container format, as a
  base64 data-URI).
- Vision tokens are counted locally via the target model's real HF processor,
  so client-side token accounting matches what the server will actually see.
- Wired into `serving.py`'s request-building and CLI argument parsing: new
  flags `--video-count`, `--video-resolution`, `--video-frames`,
  `--random-video-count`, `--video-format`; extended `--dataset-name` choices.

## Testing

Built a test image from a current SGLang-main-tracking nightly ROCm image
(`lmsysorg/sglang-rocm:v0.5.23-rocm724-mi35x-20261103`), served
`Qwen/Qwen2.5-VL-7B-Instruct` on a single MI355X GPU via a `gpuq`-gated job,
and ran:

```
python3 -m sglang.benchmark.serving --backend sglang-oai-chat \
    --dataset-name video --num-prompts 4 --video-count 1 \
    --video-resolution 720p --video-frames 4 ...
```

end-to-end against the real running server. Result: 4/4 successful requests,
full benchmark summary produced (throughput, TTFT, TPOT, ITL).

Note: decoding the generated video server-side requires the `decord` (or
`torchcodec`) package in the serving environment. This is an existing
server-side requirement already documented elsewhere in SGLang's model
cookbooks (e.g. the Ling-3.0-flash-VL page: "Video input needs `decord` or
`torchcodec`"), not something this PR's benchmark client needs to add as a
dependency, since decoding happens inside the target model's own multimodal
processor, not the client.
