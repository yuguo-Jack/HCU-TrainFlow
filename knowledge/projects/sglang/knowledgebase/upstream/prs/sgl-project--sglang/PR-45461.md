# [CI] vlm: Harden fixture cleanup after setup and shutdown failures

[Upstream PR](https://github.com/sgl-project/sglang/pull/45461) · state: closed · merged: True

## Original PR description

## Motivation

VLM input-format tests load vision towers and projectors into the parent test process. Shutting down the engine leaves those modules alive across test classes. On affected runners, NVML reports a PID that the container's GPU-idle check cannot match, so this retained memory causes the next class to fail with `GPU(s) still not idle`.

Cleanup must also run when engine shutdown raises or visual initialization fails partway through loading a model. A live initialization traceback can otherwise retain the parent model even after class attributes are cleared.

## Changes

- Release class-owned vision modules in `finally`, collect cycles, and call the existing backend-aware `empty_gpu_cache()` helper.
- Clear failed visual-initialization frame locals, including chained exceptions, before existing setup-error teardown runs. Preserve exception objects, messages, and traceback locations.
- Avoid temporary teardown-loop references keeping the final module alive through cache cleanup.

The GPU-idle memory threshold and PID matching are unchanged. Shared PID-namespace handling remains separate work.

## Validation

Tested the original PR head `8e34fba684` and the updated fixture on one H200 devbox with Python 3.12.15, PyTorch 2.14.1+cu130, Transformers 5.19.0, and NVIDIA open kernel driver 595.71.05.

- Public-model inference: all 10 InternVL2-2B, Kimi-VL-A3B-Instruct, and Qwen2.5-VL-3B-Instruct tests passed on both versions with `SGLANG_IS_IN_CI=true`.
- Real 3 GiB CUDA allocation probes: the original fixture retained the allocation after injected shutdown and initialization failures; the updated fixture returned allocated and reserved memory to zero in both failure cases and normal teardown. Original errors remained observable.
- Local validation before removing the standalone test: 2 CPU test methods covering 11 subcases passed with GPUs hidden. No new test file is included in the PR.
- Applicable pre-commit checks passed.

Gemma was excluded because this devbox lacks authorized access to the gated model. The H200 environment reports matching local and NVML PIDs, so it does not reproduce the proprietary-driver PID mismatch. ROCm and XPU hardware were not tested.

The initial PR author separately reported testing on an affected H100 runner with NVIDIA driver `570.211.01` and the proprietary kernel module, running this file directly with `SGLANG_IS_IN_CI=true`. After releasing the vision modules, the run passed 16 tests with 3 skips; that result was not rerun here.

- Kangyan-Zhou · comment · 2026-10-22T23:19:22Z · [source](https://github.com/sgl-project/sglang/pull/45461#discussion_r4354539757)

File: `test/registered/vlm/test_vlm_input_format.py` · line None

**Should fix:** `cls.engine.shutdown()` has no `try/finally` around it. If it raises, the release below never runs. `Engine.shutdown` wraps `kill_process_tree(..., wait_timeout=60)` in a `try/finally` with no `except`, so a timeout or a failure stopping a gRPC or weight-cache daemon propagates out. The vision modules then stay on the GPU, and the next class fails the idle check with "GPU(s) still not idle" instead of showing the real teardown error.

Wrap the shutdown in `try:` and move the module release into `finally:`.

- Kangyan-Zhou · comment · 2026-10-22T23:19:22Z · [source](https://github.com/sgl-project/sglang/pull/45461#discussion_r4354539765)

File: `test/registered/vlm/test_vlm_input_format.py` · line None

**Should fix:** this release frees nothing when `setUpClass` fails partway through `_init_visual`. `CustomTestCase.safe_setUpClass` (`python/sglang/test/test_utils.py`) calls `tearDownClass()` from inside its `except` block, while the exception is still live. The traceback's `_init_visual` frame still holds the `model` local, and that parent model keeps every submodule already moved to the GPU alive. Setting the class attributes to `None` doesn't drop them, and `empty_cache()` runs before the frame is released. After that nothing calls it again, so the next class fails the idle check: the same cascade this PR is fixing.

Two concrete cases:
- Gemma: `vision_tower.to(cuda)` succeeds, then `multi_modal_projector.to(cuda)` OOMs.
- InternVL: `vision_model` and `mlp1` reach the GPU, then a transformers bump drops a config field read at lines 538-549.

One way to fix it in this file is to clear the failed frames' locals before re-raising, wherever `_init_visual` is called. That is the base `setUpClass` plus the InternVL and MiniCPM overrides:
```python
try:
    cls._init_visual()
except BaseException as e:
    traceback.clear_frames(e.__traceback__)
    raise
```

**Should fix:** `empty_gpu_cache()` in `sglang.test.test_utils` already does this. It calls `torch.accelerator.empty_cache()` and falls back to CUDA/XPU.

The hand-rolled branch also doesn't match how devices are picked. The InternVL and MiniCPM `setUpClass` overrides choose `cuda` via `torch.cuda.is_available()`, which is True on ROCm. `_is_cuda` is sglang's `is_cuda()`, which requires `torch.version.cuda` and is False on ROCm, so the cache is never emptied there.
```suggestion
        empty_gpu_cache()
```
(plus `from sglang.test.test_utils import CustomTestCase, empty_gpu_cache`)
