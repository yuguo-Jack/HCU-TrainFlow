# [Spec] Declare kv_indptr/kv_indices on EagleVerifyInput for DP-attention idle verify

[Upstream PR](https://github.com/sgl-project/sglang/pull/43289) · state: open · merged: False

## Original PR description

## Motivation

Point fix for #43287 (kept open for the structural question). With EAGLE + DP attention + triton and an eager idle verify, the idle rank crashes with `AttributeError: 'EagleVerifyInput' object has no attribute 'kv_indptr'`. Root cause, repro and trigger conditions are in the issue.

**Draft on purpose:** this is the second time the same failure has shown up in a `SpecInput` subclass (see #28221). The issue asks maintainers whether they prefer a structural fix, such as declaring the fields on `SpecInput`, gating the backend reads, or decoupling the idle path from `spec_info`. I'll rework this PR into whichever direction is chosen.

## Modifications

Declare `kv_indptr` / `kv_indices` as `None` on `EagleVerifyInput`, matching `EagleDraftInput`. Verify inputs never populate them. The `None` value makes the backend's existing "rebuild plain metadata from `seq_lens`" fallback reachable for the idle verify batch.

Both fields are needed: some paths read both (e.g. `triton_backend.py:740-741`), so declaring only one just moves the crash to the next line.

## Accuracy Tests

No output change: no change for non-idle verify (`TARGET_VERIFY` takes a different branch and never reads these fields) or for the CUDA-graph idle path.

## Speed Tests and Profiling

N/A (declaration only, no hot-path change).

### Repro / functional test

4× GB300, Qwen3-30B-A3B + EAGLE3 draft, TP2/DP2, `--enable-dp-attention --attention-backend triton`, 6 sequential single requests. Tested on a downstream fork that shares this code path with `main`, not on `main` itself:

| | before | after |
|---|---|---|
| `--disable-cuda-graph` | crash on warmup request | 6/6 OK |
| CUDA graph on | 6/6 OK | 6/6 OK |

No CI test added yet; the issue proposes one (idle verify per backend × algorithm under DP attention, eager), pending the direction discussion.
