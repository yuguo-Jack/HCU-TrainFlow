# [Feat] [NVIDIA] runtime: Add a master switch for megakernel runtime optimizations

[Upstream PR](https://github.com/sgl-project/sglang/pull/47105) · state: closed · merged: True

## Original PR description

## Motivation

Enable the runtime optimizations accompanying NVIDIA megakernels with one opt-in switch across model paths, instead of carrying a long list of per-optimization environment variables in launch recipes.

## Modifications

- Add `SGLANG_ENABLE_NV_MEGA_RUNTIME_OPTIMIZATION=0` (default). The `SGLANG_ENABLE_` name follows the env-var conventions.
- Reuse `EnvField`'s generic lazy callable-default mechanism: each included `EnvBool` has `SGLANG_ENABLE_NV_MEGA_RUNTIME_OPTIMIZATION.get` as its default. Resolution stays in `environ.py`; call sites and existing capability checks are unchanged.
- **Explicit child values take precedence**, including `0`/`false` with the master on and `1` with the master off. **Unset children follow the master**. The **master defaults off**, preserving current defaults. `.set(None)` retains the existing explicit-None behavior. This switch does not enable the megakernel backend itself.
- Upcoming megakernel follow-up PRs will use this switch instead of adding their own master switch.

### Mapping to the existing model recipes

- **DSv4.1 / DSpark ([#45450](https://github.com/sgl-project/sglang/pull/45450)):** the runtime recipe contains the 16 included DSv4.1 switches plus `SGLANG_OPT_DSV41_DSPARK_SIM_DRAW_AHEAD`. The latter remains explicit when simulated acceptance is used. The master additionally enables the Qwen3.5 group; most of that group is inactive on this path, but the shared scheduler synchronization and replay input-staging paths below can apply.
- **Qwen3.5 / EAGLE MTP ([#45474](https://github.com/sgl-project/sglang/pull/45474)):** the runtime group contains the 11 included Qwen3.5 switches. The master additionally enables the DSv4.1 group; most of that group is inactive on this path, but the shared graph-fill and captured-metadata replay paths below can apply.
- Settings outside these groups remain explicit in the recipes, including `SGLANG_OPT_DSV41_MEGA_MHC_PREFILL`, `SGLANG_ENABLE_METADATA_GLUE_GRAPH` and `SGLANG_EAGER_INPUT_NO_COPY`, where used. Simulation, placement, backend and numeric tuning settings are not replaced by the master.

For the **dedicated DSpark target-verify glue/early path**, the generic `SGLANG_ENABLE_METADATA_GLUE_GRAPH` is not a prerequisite: with the master on and all three child/generic settings unset, both DSv4.1 child switches resolve to true and the eligible runner creates its own metadata glue graph. Explicitly enabling generic metadata glue instead creates `_metadata_glue` first, bypassing `_target_metadata_glue` selection and its early-metadata path. Keep generic-glue recipe settings specific to the path they were measured with.

These four shared switches extend beyond the model-specific recipe in which they were measured:

| Model receiving an additional optimization | Switch | Why it is intended to preserve outputs |
| --- | --- | --- |
| DSv4.1 / DSpark | `SGLANG_Q35MF_EDGE_SHM_SYNC` | Single-host TP4 scheduler TP syncs exchange the same values through a shared-memory table. Its multi-host companion switches apply only to eligible group/topology configurations. |
| DSv4.1 / DSpark | `SGLANG_Q35MF_MKH_N3B` | The generic decode/verify replay `_restage_skip` path checks tensor identity, `_version` and stream before skipping duplicate input copies; unchanged Mamba tracking indices are reused only where that state exists. |
| Qwen3.5 / EAGLE MTP | `SGLANG_OPT_CUDA_GRAPH_FILL_FAST_PATH` | Without padding, `reset_padding` is already a no-op; the dense integer copy fast path writes the same fields. |
| Qwen3.5 / EAGLE MTP | `SGLANG_OPT_SKIP_GLUED_REPLAY_VIEW` | Applies when metadata glue is enabled, including the `SGLANG_ENABLE_METADATA_GLUE_GRAPH=1` setting used for #45474's measurements. For an already captured key, `MetadataGlueGraph.run` does not read `fb_view`; calling `replay()` reinstalls and replays the same metadata. |

**GPU A/B on both models (below) measured these paths on the receiving model:** no measurable effect on throughput, prefill latency or accuracy. Explicit child `0` remains available to disable each path.

The remaining model/backend-specific switches are inactive on the other cited recipe: DSpark paths check the DSpark algorithm and their worker/backend/static-graph conditions; EAGLE post-verify and GDN capture have their own worker/backend gates; chain-tree construction applies only to TRT-LLM MHA; the vectorized small-field copy is consumed by EAGLE post-verify graphs; and the Qwen3.5 recipe uses NVFP4 rather than the MXFP4 path. Deferred context-KV retains its cache, disaggregation and attention-DP eligibility checks. EAGLE graphs require CUDA, topk-1 and no attention-DP, with eager fallback for unsupported batches; GDN capture checks the target worker, Triton kernel, layouts and buckets. No additional model-name restrictions are introduced.

### Broader backend applicability

`SGLANG_OPT_MXFP4_DEFERRED_FINALIZED_SHAPE` affects **any model using deferred-finalize MXFP4 trtllm-gen MoE**, including the `deepseek_v2` / DeepSeek-V3, `deepseek_v4`, `minimax_m3`, `mimo_v2` and `kimi_k3` model paths. It changes the FlashInfer tactic-cache key for 33–96 rows and more than 384 rows by supplying the finalized output shape. This setting was tuned only on DSv4.1; its performance on those other model paths has not been validated here.
