# [Fix] cache: don't stamp a Mamba checkpoint on a shorter insert key

[Upstream PR](https://github.com/sgl-project/sglang/pull/39209) · state: open · merged: False

## Original PR description

## Motivation

Fixes #38815. In a joint Full/SWA/Mamba cache, `cache_finished_req` (and the unfinished twin) truncates the insert key to the smallest component boundary (`effective_cache_len = min(...)` across component prepare hooks). An SWA branch at 96 leaves the insert leaf at 96, while `MambaComponent.prepare_for_caching_req` has already attached the Mamba state tracked at 192 to the insert params. Both commit implementations then stamped state192 onto key96, and the reporter's H200 repro shows the consequence: a warm-cache request hitting 96 resumes from the wrong state, with diverged logprobs in all three input groups.

## Changes

The Mamba value now carries the seqlen it was produced at through `InsertParams` — Python side, the Rust binding, and the Rust in-flight `InsertWalkState` — and both commit sites skip the stamp when the inserted key's token length doesn't match it (atom length plus the bigram overlap for EAGLE keys):

- `python/sglang/srt/mem_cache/unified_cache/components/mamba_component.py`: `commit_insert_component_data` returns early on misalignment; `cleanup_after_caching_req` treats a skipped value as not-inserted on both the finished and unfinished paths (int8 slot freed, ping-pong slot not kept).
- `rust/sglang-radix-tree/src/components/mamba.rs`: same guard in the Rust component, so the Rust TreeCore deployment the reporter reproduced on is covered.
- `python/sglang/srt/mem_cache/rust_tree_core/adapter.py` and `rust/sglang-radix-tree/src/python_bindings.rs`: `mamba_value_seqlen` threaded through the binding (defaulted `None`, so non-tracked inserts keep legacy behavior).

A truncated finish therefore simply doesn't checkpoint that state instead of caching a wrong one. This is strictly safer: the resume falls back to recomputation on the existing no-checkpoint path instead of resuming from a later state.

## Test plan

- New Rust unit test `misaligned_mamba_value_is_not_stamped` in `src/tests/components/mamba.rs`: key96 + seqlen192 leaves zero Mamba values in the tree; the same leaf then accepts the value once seqlen matches its position.
- New Python unit test `test/registered/unit/mem_cache/test_mamba_value_alignment.py` (registered `base-a-test-cpu`): misaligned not stamped, aligned stamped, untracked value keeps legacy behavior.
- Verified locally on this Mac: full Rust suite `cargo test -p sglang-radix-tree` **847 passed / 0 failed** (torch 2.11 build venv, CPU); Python component tests 3/3; existing Python Mamba suites `test_mamba_path_state_cap` + `test_mamba_donated_alloc_ratio` 16 passed with no regressions.
- Not run locally (no GPU): the KL-level suites (`test_unified_radix_cache_kl_mamba`, `_kl_swa`, `_kl_hybrid_bitexact`) — those exercise this path on real models and are the right CI coverage for it.
