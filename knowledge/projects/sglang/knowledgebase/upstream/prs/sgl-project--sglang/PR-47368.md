# [Fix] model-loader: Preserve KV cache scale tensors

[Upstream PR](https://github.com/sgl-project/sglang/pull/47368) · state: open · merged: False

## Original PR description

## Motivation

`load_kv_cache_scales` currently replaces `k_scale` and `v_scale` with Python floats. This raises a `TypeError` when the attributes are registered `Parameter`s, and leaves non-parameter paths with values that tensor-consuming attention backends cannot expand. It also leaves the host-side `k_scale_float` and `v_scale_float` mirrors stale.

Fixes #47357.

## Modifications

- Add a shared helper that updates existing tensor/`Parameter` storage in place, creates scalar `float32` tensors when storage is absent, and synchronizes the host float mirrors.
- Use the helper in all eight model loaders that had the same direct-float assignment pattern: Apertus, Arcee, GLM4, Llama, MiMo-V2, OPT, Qwen2, and Solar.
- Add CPU regression coverage for registered-parameter and absent-scale paths.

The existing per-loader HIP/FNUZ scaling adjustment remains unchanged.

## Accuracy Tests

This changes scale representation, not the numeric scale value or model math.

- The issue's checkpoint-free CPU reproduction failed before the patch with the registered-parameter `TypeError` and the missing-tensor `AttributeError`.
- A source-level CPU regression harness against the patched loader passed both paths: existing `Parameter` identity was preserved, missing scales became expandable tensors, and both host mirrors were updated to `0.25`.
- `python -m py_compile` passed for all changed Python files.
- The repository's three registered-test validation scripts passed when invoked directly with Python. The full registered unit test was not run locally because the available Windows environment cannot import SGLang's Unix-only `resource` dependency; it is registered for the upstream CPU CI suite.

## Speed Tests and Profiling

Not applicable. The helper runs only while loading external KV-cache scales, before inference and CUDA graph capture.
