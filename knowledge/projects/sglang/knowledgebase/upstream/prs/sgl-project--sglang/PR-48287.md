# [Feature] multimodal: Share the token-space item feature cache on disk

[Upstream PR](https://github.com/sgl-project/sglang/pull/48287) · state: open · merged: False

## Original PR description

## Motivation

- #47903 caches each media item's features per process, so an RL trainer rank still loads and preprocesses every item the rollout engines already processed. In the geo3k token-space recipe the trainer's media rebuild is most of `perf/data_preprocess_time`, and for video it is seconds per step.
- The cache was switched on by `--token-space-preprocess-cache-trust-url`, which conflated "the URLs name immutable media" with "cache at all".

## Modifications

- `DiskPreprocessCache(directory)`: a map from cache keys to files under one directory, shared by every process that sees it. A value is written to a temporary file and renamed into place with `os.replace`, so a reader sees all of it or none; a key whose file exists is not rewritten. Nothing is evicted: the directory lives as long as the job, like its checkpoints. Values are unpickled on read (`weights_only=False`, processor outputs carry video metadata objects), so only trusted processes may write the directory; the flag help says so.
- Cache keys drop the device index and keep the device type (video: plus whether the loader decodes on the GPU), so a trainer rank on cuda:3 hits what an engine computed on cuda:1. They also carry the transformers and sglang versions; within one job these never change a hit or a miss, they only keep a directory written by one environment from being read by another.
- Under `keep_mm_features_on_device` (cuda_ipc / cuda_vmm transport) a hit loads on the CPU while misses stay on the GPU; hits are moved to their modality's device before `torch.cat`.
- Cache `get` and `__setitem__` run in the default thread pool: a disk backend reads whole files, and the event loop and the media IO pool must not wait for it.
- New `--enable-token-space-preprocess-cache` switches the cache on: in memory within `--mm-preprocess-cache-size-mb`, or on disk with the new `--token-space-preprocess-cache-dir`. It requires `--enable-token-space-processor` and `--token-space-preprocess-cache-trust-url`; the in-memory form requires a positive size; the directory requires the switch. `--mm-preprocess-cache-size-mb` goes back to meaning only the memory LRU.
- Qwen3-VL on Hopper keeps cuda_ipc when the cache is on disk: only a memory budget costs the transport.

Not in this PR: concurrent misses on one key each compute and write it (the file is written once, by whoever renames first). Measured 2.7 writes per key on video items; single-flight is a follow-up.

## Tests

`test_preprocess_cache.py`: another process reads what one wrote; a written key is not rewritten. `test_mm_token_expansion.py`: the served core caches only with the switch, in memory or on disk; a hit joins the misses on their device. `test_model_overrides.py`: a disk cache beside a memory budget keeps cuda_ipc.

Run on the H200 devbox (CPU tests), each file in its own process: `test_mm_token_expansion.py`, `test_preprocess_cache.py`, `test_model_overrides.py` pass. The two failures listed in #47903 are unchanged.

End to end with radixark/miles (trainer side: radixark/miles#4651), Qwen3-VL-2B-Instruct geo3k, 4 GPUs colocated, TP 1, 15 steps, means over steps 1+:

| arm | data preprocess (s) | step time (s) | train/rollout logprob abs diff | reward |
|---|---|---|---|---|
| no cache (2 runs) | 0.83 / 0.86 | 93.1 / 94.3 | 0.0113 / 0.0113 | 0.311 / 0.306 |
| disk cache (3 runs) | 0.51 / 0.52 / 0.53 | 94.4 / 94.5 / 94.4 | 0.0113 / 0.0113 / 0.0114 | 0.314 / 0.314 / 0.312 |

Every trainer lookup hit (4 ranks x 1920, no misses, no writes); the engines wrote every item once per concurrent miss. A synthetic-video variant of the same recipe: data preprocess 2.31 s → 1.01 s, logprob abs diff 0.0105 vs 0.0107, step time 91.2 s → 98.3 s from the engines writing 19 MB items 2.7 times each (the write amplification above).

## Stack

After #47901. The main port of #48285; the patch is byte-identical to it. The unit tests and the end-to-end runs above were done on the sglang-miles stack, not re-run here.
