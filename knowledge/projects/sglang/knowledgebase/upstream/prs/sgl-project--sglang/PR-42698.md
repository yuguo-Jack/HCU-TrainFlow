# [Cake] kimi_k3_fp8_projection: per-weight cached launcher in the MLA projection route

[Upstream PR](https://github.com/sgl-project/sglang/pull/42698) · state: closed · merged: False

## Original PR description

## Motivation

The Cake `kimi_k3_fp8_projection` route in the Kimi-K3 MLA projection path resolved its plan, validated the prepared weight and allocated a workspace on every call; at bs-1 1024-token prefill the host side cost 87-117 us per projection call on GB300. FlashInfer's `kimi_k3_fp8_projection_launcher` (per-weight cached launcher, see the linked FlashInfer PR) keeps the per-(M, stride, address class) plan and the per-M workspace, so a call only binds the activation and output.

## Modifications

- Use one cached launcher per prepared projection weight in the Cake MLA projection route; graph capture pins the captured workspaces.
- Draft until the FlashInfer release carrying the launcher is pinned.
