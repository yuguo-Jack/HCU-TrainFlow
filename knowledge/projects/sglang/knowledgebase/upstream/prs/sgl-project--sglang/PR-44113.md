# [Core] Add subclass hooks for the generation request class and optimistic prefill eligibility

[Upstream PR](https://github.com/sgl-project/sglang/pull/44113) · state: closed · merged: True

## Original PR description

## Motivation

A downstream fork that keeps per-request state on a `Req` subclass, or carries one extra field on the tokenized wire type, currently has to copy `handle_generate_request`, `Session.create_req` and `_create_tokenized_object` wholesale just to change the class they construct. The same goes for a fork that wants its own rule for when a disaggregated prefill may run before its decode receiver is bound: the eligibility test is inlined in `pop_bootstrapped`, next to the pause check and the metadata-buffer admission that every subclass must keep.

This routes the existing construction sites through one override point per class, in the spirit of the `init_*` override points the large classes already expose. Default behaviour is unchanged.

## Modifications

- `Scheduler._create_generation_req(recv_req, *args, **kwargs)` builds the `Req` on the plain, session and unknown-session paths of `handle_generate_request`. `Session.create_req` takes a `req_factory` (default `Req`) so the session path reaches the same hook.
- `TokenizerManager.tokenized_generate_req_type` and `batch_tokenized_generate_req_type` are class attributes naming the wire types that single and batched dispatch construct.
- `PrefillBootstrapQueue.can_prefill_before_bootstrap(req)` holds the per-request eligibility test for prefilling while the sender is still bootstrapping. The `is_retracted` pause check and `ensure_metadata_buffer` stay in the shared queue loop, so a permissive subclass cannot resume a retracted request or skip metadata admission.

## Checklist

- Unit tests (CPU, `base-a-test-cpu`):
  - `test/registered/unit/managers/test_request_class_override_points.py` (new): a `Scheduler` subclass overriding `_create_generation_req` receives its `Req` subclass on all three request paths; a `TokenizerManager` subclass's wire types reach single and batched dispatch.
  - `test/registered/unit/managers/test_priority_scheduling_disaggregation.py`: a `PrefillBootstrapQueue` subclass whose eligibility hook always answers yes admits a bootstrapping request that the default rule would hold, and still never admits a retracted one.
  - All three cases fail on current `main` and pass with this change.
- Existing CPU unit tests around the touched code pass: `test_priority_scheduling_disaggregation`, `test_scheduler_sampling_mask_validation`, `test_multimodal_abort_cleanup`, `test_gemma4_uniform_lifecycle`, `test_session_token_share_unit`, `test_prefill_result_polling`, `test_admission_abort_not_enqueued`, `test_disagg_idle_step_counters`, `test_scheduler_hicache_events`.
