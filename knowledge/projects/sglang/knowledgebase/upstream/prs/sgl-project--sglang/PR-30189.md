# [LoRA] Fix crash loading GDN in_proj_qkv/in_proj_z adapters for Qwen3.5

[Upstream PR](https://github.com/sgl-project/sglang/pull/30189) · state: closed · merged: False

## Original PR description

## Motivation

Fixes #30168. Serving Qwen3.5/3.6 GDN (GatedDeltaNet) models with `--enable-lora`
crashes at startup: ```NotImplementedError: get_hidden_dim not implemented for in_proj_qkv```

HuggingFace/PEFT exposes the GDN input projection as two linears (`in_proj_qkv`
and `in_proj_z`). SGLang fuses both into `in_proj_qkvz`. The LoRA path had no
mapping for the split names, so they reached `LoRAMemoryPool.init_buffers` raw
and crashed the server before serving any request.

## Modifications
- **`srt/lora/utils.py`**: Add `in_proj_qkv/q/k/v/z → in_proj_qkvz` entries to
  `params_mapping` in `get_normalized_target_modules`. 

- **`srt/lora/lora.py`**: Extend `_normalize_in_proj_qkvz` to handle the 2-way
  HF/PEFT split. 
  - `lora_A`: the shared qkv weight is tiled into q/k/v slots, z
  gets its own slot → `[4r, hidden]`. 
  - `lora_B`: concat along the output dim → `[fused_out_dim, r]`.

- **`test/registered/unit/lora/test_lora_utils.py`**: 7 CPU-only unit tests for
  name normalization

- **`test/registered/unit/lora/test_lora.py`**: 7 CPU-only unit tests for weight
  stacking
