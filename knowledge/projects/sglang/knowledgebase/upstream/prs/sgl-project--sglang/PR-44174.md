# [Refactor] trtllm: TRTLLMHAAttnBackend inherits directly from AttentionBackend

[Upstream PR](https://github.com/sgl-project/sglang/pull/44174) · state: closed · merged: False

## Original PR description

## Background

TRTLLMHAAttnBackend was inheriting from FlashInferAttnBackend but reusing almost none of the parent's attention-specific behavior.

## Problem

The parent `__init__` was allocating resources that TRTLLM never uses:
- `prefill_wrapper_ragged`, `prefill_wrappers_paged`, `prefill_wrappers_verify`, `decode_wrappers`
- `indices_updater_prefill`, `indices_updater_decode`
- A shared `workspace_buffer` that TRTLLM immediately replaces with its own zero-init buffer
- FlashInfer-specific configuration (DLLM, deterministic, tensor cores, etc.)

TRTLLM overrides every attention dispatch method and uses completely different kernels. The inheritance was creating dead allocations for every TRTLLM backend instance.

## Modifications

1. **`TRTLLMHAAttnBackend`**: Changed base class from `FlashInferAttnBackend` to `AttentionBackend`. Inlined the small bits of plumbing TRTLLM actually needs:
   - pool references (`req_to_token_pool`, `token_to_kv_pool`, `kv_index_translator`)
   - `kv_cache_quant_method` resolution
   - `_resolve_swa_kv_pool()` static method (extracted from FlashInfer parent)
   - `kv_indptr` / `kv_last_page_len` buffer allocation

2. **`FlashInferMultiStepDraftBackend`**: Updated `attn_backends` type hint from `List[FlashInferAttnBackend]` to `List[AttentionBackend]` since the list now contains both FlashInfer and TRTLLM backend instances.

## Testing

- Syntax validation passes for both modified files
- All external references verified (isinstance checks, imports, registry) are safe
- No runtime dependencies on FlashInfer parent class remain
