# [Feat] serving: add configurable max_payload_size for HTTP request bodies

[Upstream PR](https://github.com/sgl-project/sglang/pull/44161) · state: closed · merged: False

## Original PR description

## Summary

Fixes #6622. Adds a new `--max-payload-size` CLI flag (default **10 MB**) that controls the maximum size of incoming HTTP request bodies across all supported ASGI backends (Uvicorn and Granian).

### The problem

When sending large JSON payloads (e.g. ~10 MB with base64-encoded images) to the SGLang HTTP server, requests were rejected with a size-limit error. The root cause was Granian HTTP/1.1 defaulting `HTTP1Settings.max_buffer_size` to ~408 KB, while Uvicorn exposes `h11_max_incomplete_event_size` without SGLang wiring it up.

### What changed

**New config field** in `Serving` namespace (`python/sglang/srt/arg_groups/fields/serving.py`):
```python
max_payload_size: int = 10 * 1024 * 1024
```
Accessible via CLI: `--max-payload-size` or env var `SGLANG_MAX_PAYLOAD_SIZE`.

**Applied to every ASGI server launch path** in `python/sglang/srt/entrypoints/http_server.py`:

| Backend | Parameter | Default before |
|---------|-----------|----------------|
| Granian HTTP/1.1 | `HTTP1Settings(max_buffer_size=...)` | 417,792 B (~408 KB) |
| Granian HTTP/2 | `HTTP2Settings(initial_stream_window_size=...)` | 1,048,576 B (1 MB) |
| Uvicorn (all modes) | `h11_max_incomplete_event_size=...` | h11 internal default |

All 4 launch paths (single-tokenizer Granian, multi-tokenizer Granian, SSL-refresh Uvicorn, default Uvicorn) now forward the value.
