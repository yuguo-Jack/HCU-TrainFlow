# [Perf] mem_cache: Prefetch Mooncake linker lookups off the scheduler thread

[Upstream PR](https://github.com/sgl-project/sglang/pull/45740) · state: closed · merged: False

## Original PR description

## Motivation

With the Mooncake external linker, `match_prefix` runs the store's existence check for a request's uncached tail synchronously on the scheduler thread.

## Modifications

- After each prefill round, the scheduler prefetches the existence checks for the first few waiting requests on a linker thread.
- `MooncakeDirectLinker` caches the answers for 5 s (below Mooncake's lease); `lookup` reuses fresh entries and only queries missing keys. Errors are not cached. Backends that do not prefetch are unaffected.

## Accuracy Tests

No numerics change. Unit tests cover key parity with `match`, TTL/error refetch, and `reset` draining in-flight prefetches.

## Speed Tests and Profiling

DeepSeek-V4.1-Flash DEP2, DSPARK, Mooncake external linker, one GB300 node. Engine fresh-token throughput per prefill rank over the 900 s measurement window, mean of all runs:

| Setting | Runs (without / with) | Without (tok/s/rank) | With (tok/s/rank) | Change |
|---|---|---:|---:|---:|
| PD prefill | 8 / 9 | 77,037 | 77,403 | +0.5% |

Within run-to-run noise on one node, where the prefill GPUs stay busy. The lookup runs on the scheduler thread, so the change targets deployments where that thread is the bottleneck (many prefill workers); that setting is not measured yet.
