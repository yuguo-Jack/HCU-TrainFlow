# [Perf] score: Binary-search anchor positions in _anchor_counts_per_item

[Upstream PR](https://github.com/sgl-project/sglang/pull/46697) · state: open · merged: False

## Original PR description

## Motivation

In `TokenizerManagerScoreMixin._anchor_counts_per_item` (`python/sglang/srt/managers/tokenizer_manager_score_mixin.py`), counting how many anchor token positions strictly fall inside each item boundary `(lo, hi)` previously scanned the entire `anchor_positions` list per item:

```python
sum(1 for p in anchor_positions if lo < p < hi)
```

Because `anchor_positions` is produced by `_find_subsequence_positions` scanning left-to-right (`range(0, n - m + 1)`), it is guaranteed to be strictly sorted in ascending order. Replacing the per-item $O(A)$ generator scan with `bisect_left(anchor_positions, hi) - bisect_right(anchor_positions, lo)` reduces multi-item anchor counting from $O(I \cdot A)$ to $O(I \log A)$ while preserving identical strict-interior `(lo < p < hi)` semantics.

## Modifications

- Import `bisect_left` and `bisect_right` from `bisect` in `python/sglang/srt/managers/tokenizer_manager_score_mixin.py`.
- Replace the per-item linear generator scan in `_anchor_counts_per_item` with `bisect_left(anchor_positions, hi) - bisect_right(anchor_positions, lo)`.
- Add `test_anchor_counts_per_item_many_items_and_boundary_anchors` in `test/registered/unit/managers/test_setwise_score_mixin.py` verifying strict-interior boundary exclusions (`lo` and `hi` excluded) across multi-item scoring inputs.
