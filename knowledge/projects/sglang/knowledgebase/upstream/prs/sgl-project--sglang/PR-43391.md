# [Diffusion] Support Qwen-Image 2.1 Turbo and checkpoint sampling grids

[Upstream PR](https://github.com/sgl-project/sglang/pull/43391) · state: closed · merged: True

## Original PR description

## Motivation

[Qwen-Image 2.1 Turbo](https://huggingface.co/Qwen/Qwen-Image-2.1-Turbo) needs the checkpoint's preset eight-step sigma grid. Loading its weights with the existing Qwen-Image 2.1 pipeline otherwise generates a uniform schedule from `num_inference_steps`, which does not reproduce Turbo sampling. This follows [Diffusers #14950](https://github.com/huggingface/diffusers/pull/14950).

## Modifications

- Load `sample_sigmas` from `model_index.json` into the existing Qwen-Image 2.1 pipeline config. Explicit request sigmas take precedence; checkpoints without a preset retain their existing schedule. Keep scheduler settings checkpoint-driven.
- Set the effective request step count from the selected sigma grid before encoding/denoising. Reuse all existing model components and stages; no new pipeline or dependency version is required.
- Register the Turbo model ID and update the model catalog and README.
- Extend the existing Qwen-Image 2.1 cookbook page and command picker with a Turbo checkpoint option, automatic eight-step sampling, minimal CLI/API commands, and verification scoped to the selected checkpoint. Keep the original checkpoint's performance figures explicitly separate from Turbo.

## Accuracy Tests

On H200 development GPUs, using public checkpoint revision `d65dbc9a7e8f6b5479e33dee6030eaab2a906509`, native precision and eager execution:

- All 83 Qwen-Image 2.1 unit tests passed, including model-index → pipeline config → request validation → native scheduler coverage, preset/request override precedence, and legacy dynamic-shift behavior.
- Single-GPU HTTP generation, editing, transparent generation/editing, multi-image editing, and two outputs passed with FlashAttention. Generation, editing, and transparent generation also passed with Torch SDPA. TP×2 generation and editing passed.
- Every tested request executed eight denoising steps. Supplying `num_inference_steps=2` produced the same PNG as omitting it, confirming that the preset controls the schedule.
- The minimal cookbook offline `sglang generate` command produced an RGBA PNG in eight steps.
- Compared against Diffusers at the #14950 merge commit `da1d3829cf08d4f329b526d89e17cc035c049d8d`, with matched CPU generators, seeds, 1024×1024 dimensions, BF16 weights, SDPA and editing input. The eight timesteps match exactly; output comparisons are below (pixel equality is not claimed).

| Workload | RGB SSIM | RGB PSNR | Alpha SSIM |
| --- | ---: | ---: | ---: |
| Generation | 0.99135 | 37.56 dB | 0.99898 |
| Edit | 0.99605 | 48.69 dB | 0.99990 |
| Transparent generation | 0.99722 | 46.12 dB | 0.99821 |

Runtime: PyTorch 2.14.1+cu130 and Transformers 5.19.0. SGLang uses Diffusers 0.37.0; the reference uses the pinned upstream source above. Turbo consumer-GPU, quantization, graph replay and dynamic-batching combinations remain unverified in the picker.

## Speed Tests and Profiling

The development runs verified the eight-step schedule and functional paths. No controlled throughput or latency benchmark is claimed, and no Turbo performance table is added to the cookbook.
