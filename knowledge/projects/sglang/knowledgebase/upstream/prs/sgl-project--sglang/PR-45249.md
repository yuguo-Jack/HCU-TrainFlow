# [gRPC] Add lifecycle-aware standard health checks

[Upstream PR](https://github.com/sgl-project/sglang/pull/45249) · state: open · merged: False

## Original PR description

## Motivation

Kubernetes and Dynamo need the standard `grpc.health.v1.Health` protocol on SGLang's Python-runtime native gRPC frontend. Readiness must also distinguish a healthy paused engine from one that can currently accept inference work.

This PR incorporates and supersedes #40129 by @tmonty12, preserving its `tonic-health` integration and event-driven engine-state publication while adding the lifecycle-aware health contract.

## Changes

- Register the standard `grpc.health.v1.Health` service on the existing inference gRPC listener.
- Expose two named entries: `inference` and `liveness`.
- Map `inference = healthy && !is_pause` and `liveness = healthy`.
- Seed both statuses before the listener accepts requests.
- Reuse `EngineStatePublisher`; health requests do not poll Python or run synthetic inference.
- Publish only visible status changes to connected `Watch` clients.
- Publish terminal `NOT_SERVING` for both entries before closing watch streams and the listener.
- Preserve the custom `HealthCheck` and `WatchEngineState` RPCs.

| `healthy` | `is_pause` | `inference` | `liveness` |
| --- | --- | --- | --- |
| `true` | `false` | `SERVING` | `SERVING` |
| `true` | `true` | `NOT_SERVING` | `SERVING` |
| `false` | `false` | `NOT_SERVING` | `NOT_SERVING` |
| `false` | `true` | `NOT_SERVING` | `NOT_SERVING` |

The separate Rust `sglang.api.v1` frontend is intentionally out of scope.
