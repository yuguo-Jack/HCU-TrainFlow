# [Feat] rust-server: multimodal (image) preprocessing through sglang-processor

[Upstream PR](https://github.com/sgl-project/sglang/pull/46291) · state: open · merged: False

## Original PR description

Move the Rust server's (`SGLANG_RUST_SERVER=1`) image preprocessing to `sglang-processor`, over Dynamo's `dynamo-multimodal`, and accept images in `/v1/chat/completions`. The bar is bit-identical to SGLang's Python CPU path at every stage and end to end. The new `processor-mm-parity` skill describes how that is checked.

**Stack:** this PR (Qwen2.5-VL, Qwen3.5) → https://github.com/sgl-project/sglang/pull/46562 (DeepSeek-V4.1) → https://github.com/sgl-project/sglang/pull/46563 (GLM-5.3-Flash).

## Modifications

1. **`sglang-processor`: new `mm` module.** `MmProcessor::from_spec` builds Dynamo's family processor from the spec Python resolves. `process(input_ids, images)` runs hash, decode, `process_item`, layout and positions on the calling thread. `tests/mm_parity.rs` checks it against fixtures recorded from Python (Qwen2.5-VL-3B, Qwen3.5-0.8B; 17 images across formats and size boundaries, both backends, multi-image, overrides).
2. **rust-server: use it.** The built-in MM worker calls `MmProcessor` on the resolved media bytes. `MmSpec` builds Dynamo's `ProcessorSpec`, and Python still resolves the spec. `sglang-mm` is untouched; it is removed in a follow-up.
3. **rust-server: images in chat.** `extract_images` collects image sources in Python's order (`process_content_for_template_format`). Video, audio, file parts, and any media sent to a text-only model, are still refused, and so is an image part without a URL (Python fails on it too).
4. **Pins `pillow<13`.** Pillow 13 changed PIL-backend bicubic output (5 of 16 cases), so Python's own output depended on the installed version.

### Findings

- `sglang-mm` did not match Python on JPEG, because its decoder is not libjpeg-turbo. Dynamo's decoder matches.
- Python's CUDA defaults (nvJPEG, GPU resize) differ from its own CPU path. Rust matches the CPU path.

### Known gaps (upstream, `ai-dynamo/frontend-crates`)

- 16-bit images: PIL clips them, Dynamo rejects them (`known_gap` in the fixtures).
- Dynamo's typed chat request refuses images in system/assistant turns and bare-base64 `image_url`.
- Text-only content-part lists render as on `main`: Dynamo joins them with `\n`, while Python keeps them as lists for multimodal templates and joins tool results with spaces. Fixed separately; turns with images already reach the template as lists, as in Python.

## Accuracy Tests

Qwen2.5-VL-3B on B300 unless noted.

- **Stage level** (`cargo test -p sglang-processor --test mm_parity`): bit-identical to Python's CPU path under Pillow 12.3, except the 16-bit `known_gap`.
- **Python vs Rust server** (`--image-processor-backend pil`, fresh servers, greedy): `/generate` 9/9 image cases, and `/v1/chat/completions` 4/4 image chats, have identical prompt ids, output ids and logprobs. Video chat → 400. Run at `1fb60b866d` (rebased onto `main` `911693e3f8`, which includes #45449). The later commits remove the text-part normalization, which leaves turns with images unchanged (see the next item), and refuse image parts without a URL.
- **Chat rendering vs Python** (`process_content_for_template_format` + `apply_chat_template`): image chats (system turn; an image followed by two text parts; text followed by two images) are byte-identical on the shipped Qwen2.5-VL-3B, Qwen3-VL-2B and Qwen3.5-0.8B templates at `4b9ed744dc`.
- **MMMU**, 100 samples, Qwen3.5-0.8B, default flags (`test_rust_native_mm_mmmu.py` harness; sgl-eval has no plain MMMU): Rust 0.36 / 0.36 / 0.34, Python 0.33 / 0.37 / 0.33. CI gate 0.30. (Earlier revision, same image pipeline. Default flags differ in inputs: Python resizes on the GPU.)
- **MMMU on identical inputs at this head:** Python **0.3402**, Rust **0.3402**. Same harness and 100 samples, Qwen3.5-0.8B, `--image-processor-backend pil` on both (Python on Pillow 12.3; MMMU images arrive as PNG, so no nvJPEG), fresh servers, greedy, one request at a time.
- **Existing tests:** `test_rust_native_mm_e2e.py` 4/4 and `test/registered/unit/multimodal/rust/` pass at `1fb60b866d` (Pillow 12.3). At `4b9ed744dc`, `sglang-server` unit tests 386/386 and `sglang-processor` tests (all features) pass, and clippy `-D warnings` and rustfmt are clean. `test_rust_native_mm_mmmu.py` passed on the earlier revision.
