# [Feat] diffusion: support MiniMax-H3 disaggregated serving

[Upstream PR](https://github.com/sgl-project/sglang/pull/40957) · state: open · merged: False

## Original PR description

## Motivation

MiniMax-H3 currently rejects every disaggregated serving role. This PR enables H3 to use the existing DiffusionServer, encoder, denoiser, and decoder infrastructure, including multiple independent denoiser instances. Full-weight inference covers T2VA, first-frame-conditioned FL2VA, and Ref2VA, including 768p generation and a denoiser using two-GPU Ulysses SP or TP. Transport coverage includes single-host Mooncake TCP/RDMA and cross-host TCP.

## Modifications

- Enable H3 disaggregation and construct model-dependent stages through role-specific factories. Load both VAEs on the encoder for conditioning, the DiT on the denoiser, and both VAEs on the decoder.
- Preserve H3 request state across transfers: serialize data-only `msgspec.Struct` execution plans, restore the typed resolved plan without recomputing media geometry, and reconstruct the pipeline's sampling-parameter subclass while retaining subclass defaults and explicit `None` values.
- Preserve CPU placement for tensor leaves in request extras. Restore them on the receive transfer stream so device-to-host copies cannot race asynchronous buffer loading, covering both prefetched and direct receive paths.
- Add an optional `compute_dtype` to `USPAttention` and set it explicitly for H3 VAE attention. This makes backend selection independent of whether the DiT was loaded in the same process, while preserving explicit backend selection and the video VAE's FP32 SDPA path.
- Add regression coverage for role admission/module loading, request wire round trips, CPU/GPU tensor restoration, CUDA stream ordering, and VAE attention backend selection.

The implementation reuses the existing transport. Encoder-to-denoiser and denoiser-to-decoder tensors use Mooncake; control messages and final decoder results continue through the existing ZMQ path.

## Speed Tests and Profiling

Functional concurrency was verified with per-request CUDA events and overlapping denoising intervals on GPUs 1 and 2. These runs include completion synchronization and diagnostic tensor capture; they are not throughput benchmarks. No end-to-end speedup claim is made. CPU tensor restoration currently adds device-to-host copies to preserve correctness.
