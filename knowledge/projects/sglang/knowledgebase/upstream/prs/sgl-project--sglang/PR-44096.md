# [Test] [AMD] diffusion: Run the IPC all-to-all transport tests only on CUDA

[Upstream PR](https://github.com/sgl-project/sglang/pull/44096) · state: closed · merged: True

## Original PR description

## What

Skips the two unit tests in `test_ipc_a2a_lifecycle.py` that exercise the CUDA-only IPC all-to-all transport when the platform isn't CUDA.

## Why

`ipc_a2a_ready()` never sets up this transport off CUDA, but these tests call into `IpcA2AState` directly and patch attributes that only exist on CUDA setups:

- `test_ipc_requires_nvlink_before_mapping_peer_memory` patches `current_platform.is_full_nvlink`. `RocmPlatform` doesn't define it, so the test fails with `AttributeError` on every ROCm lane, e.g. https://github.com/sgl-project/sglang/actions/runs/38249882022/job/114813200452
- `test_ipc_buffers_are_allocated_outside_expandable_segments` patches `torch._C._accelerator_getAllocatorSettings`, which the torch builds in the ROCm 7.2.0 / 7.2.4 images don't have, e.g. https://github.com/sgl-project/sglang/actions/runs/38285937257/job/114934302715

`torch.cuda.is_available()` is also True under ROCm, so the gate checks `current_platform.is_cuda()`, as `test_component_residency.py` does for its CUDA-only cases. Nothing changes on CUDA.

The other failing multimodal unit test in the first job, `test_compiled_all_reduce_is_one_graph`, is fixed separately in #43770.

## Test plan

- `ruff`/`isort` clean. The change only adds skip markers.
- ROCm 10 (MI300): in [multimodal-gen-test-1-gpu-amd (rocm10, 1)](https://github.com/sgl-project/sglang/actions/runs/38429275685/job/115407927155), the four `test_ipc_requires_nvlink_before_mapping_peer_memory` cases and both `test_ipc_buffers_are_allocated_outside_expandable_segments` cases are skipped, and the rest of `test_ipc_a2a_lifecycle.py` passes. That job's only failure is `test_compiled_all_reduce_is_one_graph`, which #43770 fixes. Not run on the ROCm 7.2.0 / 7.2.4 lanes, which PR CI doesn't cover.
