# [Fix] hicache: Require admin API key for POST /storage-backend/clear

[Upstream PR](https://github.com/sgl-project/sglang/pull/44898) · state: open · merged: False

## Original PR description

## Motivation

Fixes #44191.

`POST /hicache/storage-backend/clear` performs a destructive operation
(deleting every regular file in the persistent HiCache backend directory)
but was only guarded by `@auth_level(AuthLevel.ADMIN_OPTIONAL)` with no
explicit admin-key check. On a deployment configured with only `--api-key`
(no `--admin-api-key`), any ordinary inference client could erase the
persistent hierarchical cache storage with a single unauthenticated-feeling
request (the issue's reproducer gets HTTP 200 with a plain user API key).

The sibling endpoints for the same backend already treat this as
administrator-only: `PUT /hicache/storage-backend` (attach) and
`DELETE /hicache/storage-backend` (detach) both refuse when the server was
started without `--admin-api-key`. Notably, the `--admin-api-key` help text
(`python/sglang/srt/arg_groups/fields/serving.py`) already lists
`/hicache/storage-backend/clear` as an example of a sensitive management
endpoint — the code just didn't enforce it.

## Modifications

- `python/sglang/srt/entrypoints/http_server.py` — `clear_hicache_storage_backend`
  now returns the shared "requires admin API key" error response when the
  server was started without `--admin-api-key`, mirroring the attach/detach
  endpoints (same call, per the codebase's FIXME convention of simulating
  ADMIN_FORCE until the auth wiring is refactored).
- `test/registered/unit/entrypoints/test_http_server_auth_levels.py` — new
  `TestHiCacheClearAdminGuard` (CPU): with no admin key configured the
  endpoint returns 400 and never calls `clear_hicache_storage`; with an
  admin key configured it delegates and returns 200.
- `test/registered/disaggregation/test_disaggregation_decode_radix_cache.py`
  — `TestDisaggregationDecodeRadixHiCacheFileBackend` now launches with
  `--admin-api-key` and sends the bearer header on the `/clear` and
  `/flush_cache` calls (both are admin-gated once a key is configured).

## Tests

- New CPU unit tests added; they run in CI (`register_cpu_ci`, same file).
- Local verification here (no GPU / no full deps on this machine, so the
  import-time unit test could not be executed locally): an AST harness
  extracted the real `clear_hicache_storage_backend` function from
  `http_server.py` and executed it against stub collaborators —
  admin key unset → 400 + storage NOT cleared; admin key set → 200 +
  storage cleared. PASS.
- End-to-end HTTP verification against a live server (the issue's
  curl reproducer) was not possible on this machine; CI maintainers' run
  is requested.
- Audit: `ruff check --select F401,F821,F823,UP037`, `ruff format --check`,
  `python3 -m py_compile`, and `git diff --check` all pass on the touched
  files; no added line over 88 cols.
