# [Fix] [NVIDIA] modelopt-nvfp4: Read w13 global scales in the TRT-LLM [up, gate] order

[Upstream PR](https://github.com/sgl-project/sglang/pull/44858) · state: open · merged: False

## Original PR description

## Motivation

On the FlashInfer TRT-LLM MoE backend, ModelOpt NVFP4 experts whose gate (w1) and up (w3) global scales (`weight_scale_2`) differ are dequantized with the two scales swapped. Under this layout the loader stores w13 rows, and their per-tensor scales, as `[up, gate]`, but `_compute_gemm1_alphas` (#27588) reads column 0 as gate.

Standard ModelOpt exports tie gate/up scales (NVIDIA/Model-Optimizer#1033), so most checkpoints are unaffected. Before Model-Optimizer 0.45 (NVIDIA/Model-Optimizer#1560), experts never reached during calibration could stay untied, e.g. 6 of 3,840 in `nvidia/Gemma-4-26B-A4B-NVFP4`. It was reported on an in-house checkpoint with untied scales. Online NVFP4 (`nvfp4_online.py`) quantizes gate/up together with one shared scale, so it is unaffected.

## Modifications

- `_compute_gemm1_alphas` takes `up_first` and reads the columns in w13 row order; `process_weights_after_loading` passes `up_first=self.use_flashinfer_trtllm_weight_layout`. Other backends are unchanged.
- The TRT-LLM SwiGLU params move into `_compute_trtllm_gated_act_params`. Beta is added to the raw up half, so it now uses `g1_alphas_up`. The kernel applies one clamp limit to both raw halves, which can't be exact for both when their scales differ; it stays in gate-half units and logs a warning.
- Unit tests: the beta/clamp units and the SiTU branch of the moved helper.
- E2E (weekly, 4x B200): serve [`mmangkad/Qwen3-30B-A3B-NVFP4-untied-gate-up`](https://huggingface.co/mmangkad/Qwen3-30B-A3B-NVFP4-untied-gate-up) on `flashinfer_trtllm` and require GSM8K >= 0.90 (sgl-eval). Locally: 0.960 with this PR, 0.305 on the base commit.

## Accuracy Tests

`mmangkad/Qwen3-30B-A3B-NVFP4-untied-gate-up` is `nvidia/Qwen3-30B-A3B-NVFP4` with `up_proj.weight_scale_2 *= 4` and `up_proj.weight_scale /= 4` in every expert: gate/up differ, dequantized weights are bit-identical.

sgl-eval 0.1.3 GSM8K, 200 examples, `--moe-runner-backend flashinfer_trtllm`, TP1, 1x B300 (Qwen3 cookbook recipe, but with an NVFP4 checkpoint and a forced MoE backend):

| Checkpoint | Thinking, before | Thinking, after | Non-thinking, before | Non-thinking, after |
|---|---|---|---|---|
| Original (tied) | 98.0% | 97.5% | 95.0% | 95.0% |
| Untied | **51.0%** | **97.0%** | **29.0%** | **95.0%** |

Thinking: temperature 0.6, top_p 0.95, max_tokens 32768. Non-thinking: temperature 0.7, top_p 0.8, max_tokens 2048.

Kernel checks for the SwiGLU params: one expert with gate/up scale ratio 0.30, run through `prepare_static_weights_for_trtllm_fp4_moe` and `trtllm_fp4_block_scale_moe` against a dequantized reference (alpha 1.702). Relative error; FP4 noise floor 0.09.

Beta: `1/up_alpha` gives 0.089, `1/gate_alpha` gives 0.508.

Clamp, real limit L, kernel given P. Each row is a hypothesis for the real thresholds the kernel applies:

| Real thresholds | P = L/gate_alpha | P = L/up_alpha |
|---|---|---|
| gate <= P * gate_alpha, abs(up) <= P * up_alpha (both raw) | **0.072** | **0.133** |
| both at P * up_alpha | 0.608 | 0.742 |
| gate only, up unclamped | 0.611 | 0.873 |
| both at P * gate_alpha | 1.989 | 2.155 |

The kernel clamps both raw halves at P, so with untied scales no single P gives both halves the real limit L.
