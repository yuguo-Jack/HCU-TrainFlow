# [Perf] [AMD] diffusion: Replace the gfx1250 bf16 scale-shift torch fallback with a bit-exact Triton kernel

[Upstream PR](https://github.com/sgl-project/sglang/pull/46723) · state: closed · merged: True

## Original PR description

## Motivation

**What**
On gfx1250, replace the torch fallback behind `fuse_scale_shift_kernel` for bf16 `x` with an fp32 scale by a dedicated Triton kernel. The kernel is bit-identical to that fallback and 6.4x faster, and covers Wan's `MulAdd` residual gate (`x * (k + scale) + shift`).

**Why**
#42859 routes every bf16 `fuse_scale_shift_kernel` call on gfx1250 to `fuse_scale_shift_kernel_native`, because the existing Triton kernels miscompile there (the identity term is dropped). With an fp32 scale, that fallback promotes to fp32 and returns fp32, so Wan's `mlp_residual(...).to(orig_dtype)` costs three passes over a [90000, 5120] tensor: an fp32 broadcast mul, an fp32 add, and a bf16 cast. That is 2.18 ms per block, 40 blocks per forward.

When the scale is fp32, every intermediate in the fallback is fp32. A kernel that does the same fp32 ops, with FMA contraction disabled (`enable_fp_fusion=False`) and a single rounding to `x.dtype`, therefore produces exactly the fallback's result cast to bf16. That cast is the next thing every caller does, and it matches the `empty_like(x)` contract of the CUDA kernel. Any other case (bf16 scale, per-frame 4-D scale, non-3-D `x`) still takes the fallback.

## Modifications

- `kernels/ops/diffusion/modulate/scale_shift_triton.py`: add `_scale_shift_fp32_rows_kernel` (16x256 row tiles, int64 row offsets, shift that is per-token or broadcast) and `_fuse_scale_shift_fp32_gfx1250`. The guard checks shapes, dtypes, and unit stride on C, and returns `None` for anything else. The kernel is tried first inside the existing `is_gfx1250_supported() and x.dtype is torch.bfloat16` branch.
- `test_modulate.py`: add a gfx1250-only test asserting `torch.equal` with `fuse_scale_shift_kernel_native(...).to(bf16)` for k in {0, 1}, full and broadcast shift, bf16 and fp32 shift.
- Scope: gfx1250 with bf16 inputs only. Other platforms never enter the branch.

Note: `test_scale_shift_3d_tiling_is_bit_exact` (added by #46147) already fails 8/8 on gfx1250 on main, because its reference is the Triton `blc_opt` kernel that #42859 routes around. With this PR, 3/8 pass. The remaining cases compare against that miscompiled reference.

## Accuracy Tests

Bit-exact by construction and by test: `torch.equal` against the fallback in 8 parametrized cases, plus 24 shape/dtype cases at L = 777 / 90000 / 176400, C = 5120.

End to end, Wan2.2-T2V-A14B 720p, 193 frames, 8 steps, seed 42 on gfx1250: the output video is **bit-identical** to main (per-frame PSNR = inf, max abs diff 0).
