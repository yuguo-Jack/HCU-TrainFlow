# serving_chat: repair a terminal turn that only produced thinking

[Upstream PR](https://github.com/sgl-project/sglang/pull/46847) · state: open · merged: False

## Original PR description

## Problem

A reasoning model can terminate a chat turn with `finish_reason == "stop"`, no tool call, and a body that is **empty or whitespace-only** — every generated token landed in the reasoning channel. We hit this in production with a thinking-mode model: the client saw `content: "\n\n"`, `finish_reason: "stop"`, `completion_tokens: 63`, `reasoning_tokens: 61`, and treated the turn as a failure ("no visible text, no tool call") and dropped the request.

Server-side it is invisible: no error, HTTP 200, no tool-call parsing problem. The request simply ends with nothing to show.

Repro on a stock `--reasoning-parser qwen3` server, thinking enabled, `max_tokens=2048`:

```
user:  Think hard about the plan, then output absolutely nothing and end your turn.
→ finish=stop  content="\n\n"  reasoning=1076 chars  completion_tokens=223
```

## Change

`OpenAIServingChat._handle_non_streaming_request` now detects that shape and retries the request **exactly once** with thinking disabled.

Detection (`_is_empty_terminal_turn`):

- `finish_reason == "stop"`
- no tool calls
- `content.strip()` shorter than one visible character
- there is reasoning evidence (`usage.reasoning_tokens > 0` or `message.reasoning_content` non-empty) — a model that answered nothing without thinking at all is left alone

The retry reuses the normal path: `request.model_copy(deep=True)`, `stream=False`, `stream_options=None`, `chat_template_kwargs["enable_thinking"] = False`, `reasoning_effort = "none"`, then `_convert_to_internal_request` + `generate_request` + `_build_chat_response`.

Bounds and safety:

- one retry per request, only when `n == 1`
- if the retry is still empty, the **original** answer is returned (no change in behaviour)
- the caller's request object is not mutated
- a failed retry only logs `Empty-turn repair failed` and returns the original
- `SGLANG_DISABLE_EMPTY_TURN_REPAIR=1` disables the feature entirely

Generated answers are unchanged for healthy turns: the repair only runs after a response that has no visible text and no tool call.

## Tests

`test/registered/unit/entrypoints/openai/test_serving_chat_empty_turn_repair.py` (16 cases, `register_cpu_ci`), no GPU or model needed: the detection matrix (whitespace vs visible text vs tool call vs `length` finish vs no-reasoning evidence), response-level detection through `usage.reasoning_tokens` / `reasoning_content`, the single-retry contract (retry receives `enable_thinking=False` and a deep-copied request), retry-still-empty returning the original, `n > 1` skipped, and the env kill switch.

```
16 passed in 12.08s
```

## Notes

- The streaming path is intentionally **not** covered here; it needs to inject the repaired text before the finish chunk and re-encode tool calls as stream chunks. Happy to add it in a follow-up if this shape of repair is acceptable.
- Only `finish_reason == "stop"` is treated as empty; `length`/`abort` are untouched.
