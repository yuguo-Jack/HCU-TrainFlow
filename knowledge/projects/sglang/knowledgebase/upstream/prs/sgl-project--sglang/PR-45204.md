# [Fix] model-loader: Make --weight-loader-drop-cache-after-load effective for mmap loads

[Upstream PR](https://github.com/sgl-project/sglang/pull/45204) · state: open · merged: False

## Original PR description

## Motivation

`--weight-loader-drop-cache-after-load` is meant to release each checkpoint shard from the page cache once its weights have been copied out. With the default mmap path it mostly does nothing.

`safetensors_weights_iterator` and `buffered_multi_thread_safetensors_weights_iterator` call `posix_fadvise(POSIX_FADV_DONTNEED)` right after a shard's last `yield`. At that point the caller still holds the last tensor, and every pt tensor from `safe_open` is a view of one whole-file mmap. DONTNEED skips pages that are still mapped, so only unmapped readahead is dropped and the consumed shard stays cached. Models that keep a tensor for a later fused copy hold a shard mapped for many shards, and the advice for that shard is never repeated.

On a unified-memory aarch64 GPU system with 122 GiB, loading a ~180 GiB NVFP4 checkpoint with TP4, 40-55% of each consumed shard stayed in the page cache with the flag on, and free memory fell to a few GiB mid-load.

## Modifications

Only `python/sglang/srt/model_loader/weight_utils.py` (+34/-2):

- New `_drop_unmapped_file_caches(pending, force=False)`. Each finished shard is appended to `pending`. At every shard boundary, a pending shard whose realpath no longer appears in `/proc/self/maps` gets the existing `_drop_file_cache_after_load`. Shards that are still mapped stay pending and are retried at the next boundary.
- At the end of the iterator, all remaining shards are advised (`force=True`), as the current code does.
- Both mmap iterators are covered. Tensors, their order and the default (flag off) are unchanged. No new flag.
- Matching is by realpath, not `(dev, inode)`, because on btrfs the device number in `/proc/self/maps` differs from `stat`. Maps are read as bytes and compared with `os.fsencode(realpath)`, so non-UTF-8 file names cannot break loading.
- Any failure to read or parse the maps is caught, logged at debug level, and falls back to advising all pending shards right away (the current behavior). It never raises into loading.

Limitation: a shard still mapped at the final sweep is advised once and not retried, so it stays cached. For a streaming consumer that is only the last shard.

Related work: #40594 releases the cache once after loading and postprocessing; that does not lower the peak during the load, so the two are complementary. vllm-project/vllm#62110 uses a one-shot weakref on the last tensor yielded from each shard; this change also covers shards whose earlier tensors are still referenced.

## Accuracy Tests

No numerical change: the iterators yield the same tensors in the same order. The new unit test checks that every copied parameter equals the checkpoint tensor.

## Speed Tests and Profiling

The extra cost is one read of `/proc/self/maps` per shard boundary, about 0.8 ms with ~530 mappings on an x86_64 CPU host. That is negligible next to loading a multi-GiB shard. Nothing changes when the flag is off.

## Tests

New CPU-only test `test/registered/unit/model_loader/test_drop_cache_after_load.py` (registered in `base-a-test-cpu`):

- Builds a 4-shard fake checkpoint (4 MiB total), evicts it, and runs both mmap iterators with `drop_cache_after_load=True`. The consumer copies every tensor into a preallocated param and keeps one tensor of shard 0 until shard 2 starts. Page-cache residency is read with `mincore(2)` through ctypes. It asserts that shards are kept while mapped, dropped at the boundary after they are released, and that all copied weights are identical. Skips if the filesystem cannot drop the page cache (for example tmpfs).
- A mapped file named `b"\xff.bin"` stays pending while mapped and is advised after unmap.
- If the maps check fails, all pending shards are advised.

Result: patched, 3 passed (both iterators). On current main the residency test fails for both iterators with consumed shards still 100% resident (`[1.0, 1.0] != [0.0, 0.0]`). The existing `test_prefetch_checkpoints.py` still passes (21 tests).
