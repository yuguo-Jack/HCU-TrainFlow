# [Feat] RL: Publish runner weights over MoRI-IO for peer weight writes

[Upstream PR](https://github.com/sgl-project/sglang/pull/47890) · state: open · merged: False

## Original PR description

## Motivation

miles is adding a MoRI-IO transport for its P2P weight updates (radixark/miles#4607): on AMD GPUs, the trainer
writes new weights into the rollout engines' GPU memory over MoRI-IO RDMA. For that, each engine runner has to publish
a MoRI engine and its registered weight memory. This PR adds that step, next to the existing Mooncake and NIXL seeds.

## Change

New flag `--remote-instance-weight-loader-start-seed-via-mori`, the MoRI-IO counterpart of `...-via-nixl`.

- **Engine**: each runner creates a MoRI `IOEngine` with the RDMA backend. Notifications are off by default, because
  peers only write and nothing would pop the inbound status.
- **Registration**: the runner registers the allocator blocks that hold its weights. These are the same merged blocks
  `_collect_weight_blocks` gives Mooncake and NIXL.
- **Publishing**: through the engine info bootstrap server, as
  ```
  {"transport": "mori", "engine_desc": "<base64 EngineDesc>",
   "memory_blocks": [[address, size, "<base64 MemoryDesc>"], ...],
   "weights_info_dict": {...}}
  ```
- **Refused at startup**:
  - with another seed transport;
  - with a remote-instance load over `transfer_engine` or `modelexpress`, whose loader registers and publishes the
    weights itself;
  - without the `mori` package;
  - with `--enable-memory-saver`, which releases the registered weights.
- **Refused at registration**: expandable-segment memory, which MoRI cannot register and aborts on.
- **Server args**: the flag enables the bootstrap server and parallelism-config registration. Its field is appended
  after the other sglang-miles fields in `POSITIONAL_FIELD_ORDER`.

## Testing

- **Unit tests**: transport selection, the published format, the startup refusals, block registration and the
  expandable-segment refusal. `test_remote_instance_weight_roles.py`, `test_remote_instance_loader.py` and
  `TestServerArgsPositionalOrder` pass, as does pre-commit.
- **End to end with miles** on MI355X (`ionic` RoCE), SGLang's ROCm image with MoRI v1.2.4:
  - models: Qwen2.5-0.5B and Qwen3-30B-A3B;
  - layouts: one node (4 train + 4 rollout GPUs) and two nodes (8 → 8);
  - `--check-weight-update-equal` and per-write checksums pass.

  These runs applied this change to the image's SGLang commit, with the field-order line adapted to that commit's
  layout.
