# [Fix] session: Fix session replacement without a request ID

[Upstream PR](https://github.com/sgl-project/sglang/pull/41483) · state: open · merged: False

## Original PR description

## Motivation

A session turn with `replace: true` and no request ID crashes the scheduler when the session already contains requests. `SessionReqNode.clear()` removes entries from the dictionary that `Session.create_req()` is iterating, so the client loses its connection.

## Modifications

Clear a snapshot of the root request nodes. Each root clears its descendants recursively, so every branch is removed once. The regression tests cover two roots with a child under one of them, then check that a replacement succeeds and an old request ID is rejected.

## Tests

- The new CPU unit test fails on `main` with `RuntimeError: dictionary changed size during iteration` and passes with this change. The existing session token-sharing unit tests pass.
- On an Apple M4 with PyTorch 2.13.0, MLX 0.32.2, and `mlx-community/Qwen3-0.6B-4bit`, the real `/generate` flow disconnects and terminates the scheduler before the fix. After the fix, replacement returns HTTP 200, the old request ID returns HTTP 400, and `/health` returns HTTP 200. Both runs used [#41314's MLX startup fix](https://github.com/sgl-project/sglang/pull/41314).
- Changed-file pre-commit checks pass.

Fixes #41470.
