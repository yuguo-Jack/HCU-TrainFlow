# [Perf] [NPU] dsv4: Reuse verify sequence lengths

[Upstream PR](https://github.com/sgl-project/sglang/pull/47713) · state: open · merged: False

## Original PR description

During compressed target-verify graph replay, `_build_dsv4_graph_replay_ctx` already copies the final sequence lengths to the device as `compress_seq_lens`. `_refresh_graph_seq_metadata` then copies the same CPU lengths again.

Reuse that device tensor when `active_target_verify` is true, removing one redundant H2D conversion per nonempty metadata update. Keep the existing conversion for other verify cases, where `compress_seq_lens` may contain live lengths.

Validation: 432 CPU cases and 432 real Ascend NPU cases passed using the actual before/after methods and an independent length oracle. Coverage includes EAGLE/DSpark/explicit live lengths, C4/C128, decode/draft controls, idle replay, padding and empty batches. All 36 nonempty active-verify cases remove one conversion call on each device. NPU results were copied back and checked against the oracle; both runs used identical source hashes. Device environment: torch 2.10.0+cpu, torch_npu 2.10.0.post6.

Formatting and lint checks passed; the two hooks requiring `python3` were run directly with Python on Windows. Test files are kept outside this PR. These are metadata fixture tests, not captured-graph replay or full-model tests. Conversion counts are instrumented calls, not profiler measurements. No timing improvement is claimed.
