# [Feat] pd: Extract MooncakeTransport behind a common Transport interface

[Upstream PR](https://github.com/sgl-project/sglang/pull/46460) · state: open · merged: False

## Original PR description

## Motivation

Extract Mooncake engine operations from the PD connection manager into the common `Transport` interface defined in #46455, completing Step 2 of #34510 while preserving the protocol and wire format.

## Modifications

- Add `MooncakeTransport` for Mooncake and Ascend. Transfer plans use buffer keys and uint64 byte offsets.
- Centralize batched registration, shared-region deduplication, zero-length filtering, and deregistration of KV, state, auxiliary, staging, and DCP pack buffers.
- Reuse contiguous page groups and separate DCP target packing, draft slicing, and draft packing into named helpers.
- Update transfer tests to exercise the real manager and transport over a fake engine, including mixed live and zero-length DSA tail buffers, the MiniMax index-K transfer, and the sharded DSA transfer.
- Two commits: the `Transport` interface, then the Mooncake extraction.

Mooncake writes block until `batch_transfer_sync` returns. A failed transfer may still be in flight; callers must stop local and peer access before releasing memory. The shared engine remains running after transport teardown.

## Accuracy Tests
