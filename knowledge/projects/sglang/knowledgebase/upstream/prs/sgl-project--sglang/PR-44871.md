# [Fix] request_logger: truncate list elements in --log-requests output

[Upstream PR](https://github.com/sgl-project/sglang/pull/44871) · state: open · merged: False

## Original PR description

## Motivation

The `max_length` truncation behind `--log-requests` bounds the number of list items but not the size of each item, so a request with large strings (for example base64 `image_data`) can produce a multi-MB log record:

- JSON format: the elided branch of `_transform_data_for_logging` returned the head/tail slices without transforming their elements, while the non-elided branch did.
- Text format: `_dataclass_to_string_truncated` stringified list elements untouched in both branches.

Fixes #33164

## Modifications

Transform the list elements in both branches. Lists of plain numbers (token ids) keep the previous `str()` output, and strings, dicts and dataclasses inside lists are rendered as before when they are short.

## Accuracy Tests

Not applicable, logging only.

## Speed Tests and Profiling

Not applicable. Numeric lists take the same `str()` path as before.
