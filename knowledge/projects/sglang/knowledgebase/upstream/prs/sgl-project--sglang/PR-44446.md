# [Perf] hisparse: Preload the PD decode device buffer in one all-layer launch

[Upstream PR](https://github.com/sgl-project/sglang/pull/44446) · state: open · merged: False

## Original PR description

## Motivation

On a PD decode server with `--enable-hisparse`, admitting a request whose sequence fits the device buffer (`seq_len <= device_buffer_size`) preloads its full KV from the host pool into the device buffer. `HiSparseCoordinator._preload_to_device_buffer` does this with a Python loop over every model layer, calling `mem_pool_host.load_to_device_per_layer` once per layer — N separate host→device kernel launches serialized on the scheduler stream ahead of the request's first decode step (78 launches for GLM-5.2). The TODO at the call site (`TODO(hzh0425): Optimize this`) flags this.

The reverse direction already has the batched form: `MLATokenToKVPoolHost.backup_from_device_all_layer` moves all layers in one `transfer_kv_all_layer_mla` / JIT call on the same pool objects and index tensors (used by `admit_request_into_staging`). There is no host→device counterpart.

## Modifications

Four stacked commits, Python-only, no kernel changes.

- `pool_host/base.py`: add a concrete `load_to_device_all_layer(device_pool, host_indices, device_indices, io_backend)` default on `HostKVCache` that loops per-layer. Concrete, not abstract, so the existing subclasses are unaffected; subclasses with a batched kernel override it.
- `pool_host/mla.py`: `MLATokenToKVPoolHost.load_to_device_all_layer`, a mirror of `backup_from_device_all_layer` with src/dst swapped for H2D:
  - `layer_first` + `kernel`: one `transfer_kv_all_layer_mla` (or JIT `transfer_hicache_all_layer_mla`) moves all layers host→device. `dst=device_data_ptrs`, `src=self.data_ptrs`; dst stride `device_row_stride_bytes`, src stride `token_stride_size` (the reverse of backup's stride assignment).
  - `layer_first` + `direct`: symmetric `transfer_kv_direct` swap.
  - `kernel_ascend`: explicit `TransferDirection.H2D` (the dim-exchange kernel takes direction as an argument).
  - `page_first` / `page_first_direct`: the all-layer kernels are directionally baked layer-first→page-first (device→host for backup) and no page-first→layer-first all-layer counterpart exists, so fall back to the per-layer H2D loop (`transfer_kv_per_layer_mla_pf_lf`). No `lf_pf` or staged write-back kernel is called for H2D.
  - Layer-sharded (CP) device pools: per-layer fallback over `_target_layer_indices` + MTP draft slots, matching `backup_from_device_all_layer`.
  - The batched launch covers all host pool rows — target layers plus MTP draft layers — the same coverage `backup_from_device_all_layer` already has. The old per-layer preload loop moved target layers only.
- `pool_host/mla.py` (fix): split `load_to_device_per_layer` into a public wrapper (ownership check + DCP translation) and a private `_load_to_device_per_layer` worker, mirroring `_backup_from_device_per_layer`. The all-layer fallback loops call the private worker, avoiding a double `maybe_dcp_kernel_indices` translation when `dcp_size > 1`.
- `managers/hisparse_coordinator.py`: `_preload_to_device_buffer` calls `load_to_device_all_layer` once. The M3/MiMaha branch keeps its per-layer loop (`HiSparseMHATokenToKVPoolHost` has no batched override; it inherits the base-class default, which is itself the per-layer loop).

## Accuracy Tests

Pure data movement: no kernel, model-forward, or sampling change. One `load_to_device_all_layer` call produces device-pool state byte-identical to N× `load_to_device_per_layer` (verified with an ad-hoc equivalence harness on the `direct` backend; dispatch count confirmed the single all-layer kernel).

## Speed Tests and Profiling

- The win is kernel-launch count on the request-admission path, not steady-state throughput. Admission preload goes from N launches (one per layer) to 1 for the `layer_first` host layout (measured 4→1 on a 4-layer test pool; structural N→1, e.g. 78→1 for GLM-5.2, since the call is layer-count-agnostic).
- Scope: the batched path requires `--hicache-mem-layout layer_first`. The default `page_first` layout takes the per-layer fallback — correct, but no launch-count reduction there.
- E2E (1P1D PD pair + router, HiSparse decode, `layer_first`, 2-layer DSA test model): short-sequence requests admitted cleanly; instrumentation confirmed the preload took the batched `layer_first / kernel / non-sharded` branch once per admission (the `transfer_kv_all_layer_mla` path, not the fallback).
- Unit (branch-matched tree): `test_hisparse_unit.py` — 9 passed, 2 skipped.
