# [Perf] DSv4.1: Bound encoder BCG metadata memory

[Upstream PR](https://github.com/sgl-project/sglang/pull/44963) · state: closed · merged: True

## Original PR description

[codex/claude generated]

## Motivation

Encoder SWA bounded replay now supports breakable prefill graphs, but the BCG metadata context bound and cross-bucket low-ratio index sharing still exclude request-window pools. This retains page-table columns outside the graph's existing context limit and separate index outputs for each bucket.

## Modifications

Apply the existing low-ratio BCG metadata bound and full-metadata index-buffer sharing with encoder replay enabled as well. Capture and replay use the same bound. Reuse the existing storage-lifetime handling; full/tail and ratio/page/raw storage remain distinct. Model context length, graph admission, long-context eager fallback, and feature defaults are unchanged.

## Accuracy Tests

Local GB300 validation against main `3671503e44fa0acbf4f1bba4057e517282a7ccdb`:
- 42 existing encoder-replay, compressed-pool, and late-tail regression tests passed.
- Standalone GPU probes passed: byte-exact bounded page entries and graph input refresh; index-storage sharing, capacity growth, alternating bucket replay, and tail isolation.
- Model requests cover short/ragged inputs, 16,384/16,640-token contexts, and prefix-cache hits on all four DP ranks. For each bucket size, all 52 recorded requests matched main in complete output token sequences and usage/cache/rank/finish metadata, in both candidate runs. KV capacity remained 39,928,064 tokens.

These are focused local checks, not a full model-accuracy suite or CI pass. No new test files are added.

## Speed Tests and Profiling

Matched GB300 x4, DEP4, encoder and decoder replay enabled, FlashMLA Mega, native DSPARK block size 5, memory fraction 0.7, chunk size 8192 (2048 per DP rank), existing graph context limit 16384.

| Maximum prefill graph bucket | Main | Candidate first run | Candidate repeat |
| --- | ---: | ---: | ---: |
| 8192 | 15.98 GiB/GPU | 12.23 GiB/GPU | 12.23 GiB/GPU |
| 2048 | 5.56 GiB/GPU | 4.88 GiB/GPU | 4.88 GiB/GPU |

Numbers are the server's prefill graph capture-end memory increment, not total server memory or startup peak. KV capacity and launch settings are matched. No throughput claim is made.

The capture-end reduction is 3.75 GiB/GPU (23.5%) at 8K and 0.68 GiB/GPU (12.2%) at 2K. Startup reserved peaks at rank 0 changed only from 183.52 to 183.24 GiB (8K) and 173.31 to 173.20 GiB (2K); the capture-end percentage must not be applied to startup peak.
