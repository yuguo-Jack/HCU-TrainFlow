# [Fix] srt: Admit only allowlisted peers on TCP-bound ZMQ IPC sockets

[Upstream PR](https://github.com/sgl-project/sglang/pull/45250) · state: closed · merged: True

## Original PR description

## Motivation

With data-parallel attention and a non-loopback `--dist-init-addr`, the data-parallel controller binds its worker-facing ZMQ sockets on a host-reachable address so that the other nodes can connect. Those sockets decode pickle-wrapped payloads, so anything that can reach the port can push a payload at them (CVE-2026-93034, GHSA-w4hv-c72g-pqx6). Today nothing restricts who may connect.

## Modifications

- `python/sglang/srt/environ.py`: new `SGLANG_ZMQ_ALLOWED_PEERS`, a comma-separated list of peer IP addresses admitted by TCP-bound IPC sockets. Unset or empty admits every peer, which is today's behaviour.
- `python/sglang/srt/utils/network.py`: `restrict_zmq_peers(context, socket)` starts one ZAP `ThreadAuthenticator` per `zmq.Context` (libzmq allows a single ZAP handler per context, so sockets created from the same context share it), allows the configured addresses, and sets `zap_domain` on the socket so that libzmq vets NULL-mechanism connections. Must run before the socket binds; a no-op when the allowlist is unset. `get_zmq_socket` applies it to every TCP bind (random port and explicit endpoint). `get_zmq_socket_on_host` gains `restrict_peers=False`, off by default because disaggregation sockets accept peers from other jobs.
- `python/sglang/srt/managers/data_parallel_controller.py` and `python/sglang/srt/ray/data_parallel_controller.py`: the controller's worker PUSH sockets pass `restrict_peers=True`.
- `python/sglang/srt/managers/load_snapshot.py`: `ZmqShmLoadSnapshotReader` restricts peers when its endpoint is `tcp://`.

IPv6 entries may be written in any valid form; each is normalized to the compressed form that libzmq reports for a peer address, so `2001:DB8:0:0::1` matches a peer at `2001:db8::1`.

A multi-node deployment sets the variable to the addresses of its own nodes before launching every node, for example `SGLANG_ZMQ_ALLOWED_PEERS=10.0.0.1,10.0.0.2`. Single-node serving, serving without data-parallel attention and disaggregation traffic are unchanged.

## Speed Tests and Profiling

Not applicable: with the variable unset the only addition is one empty-tuple check per socket bind; with it set, libzmq's ZAP check runs once per connection.

Functional check on this head with real sockets (pyzmq 27.2.0, libzmq 4.3.5): a PUSH client at the loopback address is delivered to a PULL socket from `get_zmq_socket` when the allowlist is unset, empty, or contains `127.0.0.1` (also when listed in long-form IPv6 company), and is dropped when the allowlist names only another address; the same holds for an explicit `tcp://` endpoint; `get_zmq_socket_on_host` keeps admitting any peer unless `restrict_peers=True`, which then drops a non-member and admits a member. `isort`, `ruff check`, `ruff format --check` and `codespell` at the repository's pinned versions pass on the five files.
