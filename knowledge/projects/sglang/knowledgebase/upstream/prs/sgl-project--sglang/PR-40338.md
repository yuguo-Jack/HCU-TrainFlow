# [Refactor] unified_cache: share the aux component eviction driver between SWA and Mamba

[Upstream PR](https://github.com/sgl-project/sglang/pull/40338) · state: open · merged: False

## Original PR description

## Motivation

`SWAComponent` and `MambaComponent` drive eviction with the same code. Measuring
per-method text similarity between the two files:

| method | similarity | lines |
|---|---:|---:|
| `_evict_device_start` | 1.000 | 12 |
| `_evict_device_next_node` | 1.000 | 55 |
| `_evict_device_end` | 1.000 | 6 |
| `_advance_session_coverage` | 1.000 | 10 |
| `_recede_session_coverage` | 1.000 | 10 |
| `free_host_values` | 0.970 | 6 |
| `drive_host_eviction` | 0.942 | 51 |
| `alloc_prefetch_staging` | 0.898 | 7 |
| `evict_component` | 0.867 | 38 |

95 of those lines are byte-identical. Every remaining difference is one of three
things, and nothing else:

1. `evict_component` expresses the device free with a different tensor — SWA frees via
   the FULL indices, because SWA slots with no pair all map to one sentinel and freeing
   the SWA value directly would double-free them.
2. `free_host_values` / `alloc_prefetch_staging` name a different host pool
   (`_swa_kv_pool_host` / `_mamba_pool_host`, `PoolName.SWA` / `PoolName.MAMBA`).
3. `drive_host_eviction` — Mamba had one extra `_update_evictable_leaf_sets(x)` after
   `_cascade_evict`. That call is redundant: `_cascade_evict` already ends by
   refreshing the leaf sets of the same node. SWA was not missing anything.

The cost of the copies is drift: a new auxiliary component starts by pasting the
eviction loop, and a fix to one walk does not reach the other.

## Modifications

New `AuxLRUComponent(TreeComponent)` in `components/base.py` holds the shared walks;
`SWAComponent` and `MambaComponent` inherit it and supply three hooks —
`_host_pool`, `_host_pool_name` and `_device_free_value` (overridden only by SWA, with
the sentinel explanation kept on the override).

Net **-122 lines** (+243 / -365): 360 lines of duplicated implementations become 218
lines of shared driver plus ~25 lines of hooks. No behaviour change is intended; the
redundant call in item 3 is the only statement dropped.

The Rust core has the same shape (`components/{swa,mamba}.rs`, 199 similar lines by the
same measurement). That is deliberately not in this PR — it needs its own baseline diff
against the 867-test crate suite, and mixing the two would make this unreviewable.

## Accuracy Tests

- `test/registered/unit/mem_cache/`: **2522 passed**, 1441 skipped, 1813 subtests.
- Randomized lock-ledger stress (insert / match / split / lock / early SWA release /
  release / evict), 6 seeds x 150 steps: **0 violations** for `full`, `full,swa` and
  `full,swa,mamba`.
- Tree-invariant repro suite, run on this branch and on the merge-base and compared
  check by check: **identical** (26 checks, the same 8 pre-existing failures on both
  sides, none of them in the eviction walks).

Draft while the Rust half is decided: if reviewers would rather see both cores move
together, say so and I will add it here instead of following up.
