# [Perf] dspark: Combine the draft's mHC streams from bf16 without an fp32 copy

[Upstream PR](https://github.com/sgl-project/sglang/pull/45964) · state: closed · merged: True

## Original PR description

- The DSpark draft head combined its mHC streams with `mhc_combine(x.flatten(1).float(), ...)`. The `.float()` copied the whole `[tokens, hc_mult * hidden]` input to fp32 before the kernel read it.
- `_mhc_combine_kernel` widens every element to fp32 as it loads it, so the bf16 rows now go to the kernel directly, as the target model's final combine already does. bf16 to fp32 is exact, and the kernel computes the same fp32 products in the same order.

Output is bitwise identical to before.

Verification: the combine on the bf16 rows matches the fp32-copy path bit for bit from 1 to 65536 rows on GB300, and the copy no longer runs.
