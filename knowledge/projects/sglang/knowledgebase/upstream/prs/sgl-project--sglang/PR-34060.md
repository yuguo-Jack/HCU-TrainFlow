# managers/detokenizer_manager: fix spurious eviction in LimitedCapacityDict when updating existing key

[Upstream PR](https://github.com/sgl-project/sglang/pull/34060) · state: closed · merged: False

## Original PR description

## Motivation

`LimitedCapacityDict.__setitem__` unconditionally evicts the oldest entry
whenever `len(self) >= self.capacity`, even when the key being written already
exists in the dict. In that case the dict's size does not grow, so no eviction
should occur.

The result is a silent, premature loss of a live request's `DecodeStatus`.
When a key that is already present is overwritten:
- `popitem(last=False)` ejects the oldest entry (a different, still-active request).
- The updated key is re-inserted at the tail, corrupting insertion order.
- The next genuinely new request then evicts what is now the incorrectly promoted oldest entry — one step earlier than it should be.

In the worst case this causes the `RuntimeError` / `KeyError` documented in #2812 for requests that are still actively generating tokens.

## Modifications

`python/sglang/srt/managers/detokenizer_manager.py`

Guard the eviction in `LimitedCapacityDict.__setitem__` with `key not in self`,
so the oldest entry is only ejected when the insertion would genuinely grow the
dict beyond capacity. The eviction loop is also changed from `if` to `while self and ...`
to correctly handle `capacity=0` and any future dynamic shrinking of the dict.

```python
def __setitem__(self, key, value):
    if key not in self:
        while self and len(self) >= self.capacity:
            # Remove the oldest element (first item in the dict)
            self.popitem(last=False)
    # Set the new item
    super().__setitem__(key, value)
```

`test/registered/unit/managers/test_limited_capacity_dict.py`

Added unit tests covering: update of existing key does not evict any other entry;
new key at capacity evicts the oldest; `capacity=0` does not raise; dict length
is stable across updates; insertion order is preserved after an update; sequential
eviction follows FIFO order.
