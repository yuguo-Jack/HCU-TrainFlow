# [DSV4][CP] Write low-ratio page indices when CP prefill runs paged attention

[Upstream PR](https://github.com/sgl-project/sglang/pull/43935) · state: closed · merged: True

## Original PR description

## Motivation

`test/registered/e2e/models/test_deepseek_v41_pd_cp_dspark.py` (8-gpu-b300) fails on main:

```
AssertionError: np.float64(0.755) not greater than or equal to 0.85
```

- Four attempts on main scored 0.755 / 0.74 ([run 38308224671](https://github.com/sgl-project/sglang/actions/runs/38308224671)) and 0.78 / 0.735 ([run 38310731017](https://github.com/sgl-project/sglang/actions/runs/38310731017)).
- The same test scored 0.90 on #40323's head before merge ([run 38212679634](https://github.com/sgl-project/sglang/actions/runs/38212679634)). That head did not contain #38603, which merged just before it.
- It reproduces on a single 4-GPU node without PD, using only the prefill worker's flags:

```bash
python3 -m sglang.launch_server --model-path deepseek-ai/DeepSeek-V4.1-Flash --trust-remote-code \
  --tp 4 --ep-size 4 --language-model-only --attention-backend dsv4 --moe-a2a-backend none \
  --moe-runner-backend flashinfer_mxfp4 --speculative-algorithm DSPARK --speculative-dspark-block-size 5 \
  --cuda-graph-backend-prefill disabled --context-length 16384 --enable-prefill-cp --attn-cp-size 4 \
  --cp-strategy interleave --chunked-prefill-size 1024 --max-prefill-tokens 4096
# GSM8K (the test's call: 200 questions, 8 shots, greedy): 0.75
```

**Cause.**
- #38603 made `_use_sparse_prefill` reject active CP batches, so eager CP prefill now runs paged FlashMLA.
- `_low_ratio_prefill_reads_page_indices` is documented as the negation of that gate, but it was not updated. With `SGLANG_OPT_FLASHMLA_SPARSE_PREFILL` on (the default), it still returns False under CP.
- The c1/c2 low-ratio indexer therefore writes only raw indices, and paged attention reads page indices that were never written for the batch. Nothing errors; accuracy drops.

## Modifications

- `_low_ratio_prefill_reads_page_indices` now derives from `_use_sparse_prefill(forward_batch, num_qo_tokens=0)`, so the two gates can no longer drift. `num_qo_tokens=0` keeps the existing behaviour of dropping the query-count clause, which errs toward True.
- #38603's routing (CP → paged) is unchanged.

## Accuracy Tests

4×GB300, the command above, GSM8K as in the e2e test (threshold 0.85):

| tree | GSM8K |
|---|---|
| main | 0.750 |
| #38603's parent + #40323 | 0.895 |
| main with `SGLANG_OPT_FLASHMLA_SPARSE_PREFILL=0` (forces the page-index gate on) | 0.910 |
| this PR | 0.895 (DSpark accept length 3.36; the CI pass had 3.37) |

B300 CI rerun of `test_deepseek_v41_pd_cp_dspark.py` on this PR ([run](https://github.com/sgl-project/sglang/actions/runs/38322945648)): GSM8K 0.905, passed.


## Speed Tests and Profiling

The attention path is unchanged. CP prefill stays paged; the low-ratio indexer writes its page indices again.
