# [MoE] Add H100 unified block-FP8 config for E128/N768

[Upstream PR](https://github.com/sgl-project/sglang/pull/42804) · state: closed · merged: False

## Original PR description

## Motivation

H100 native block-FP8 MoE with E128/N768 currently uses the generic fallback. Add a measured unified table for Qwen3-30B-A3B-FP8, H10080GB, TP1/EP1, top-k8, using the existing first tuning entry and runtime.

**Draft:** target-model performance and the frozen GSM8K screen pass, but the shared filename omits H/top-k and has a known synthetic H4096 hot-route regression. Resolve this shared-key limitation and complete current-head GPU CI/review before promotion. Omni validation is deferred.

[Unified candidate, paired metrics, question outcomes, source fingerprints and reproduction notes](https://gist.github.com/YzXiao101/c45bb0fdefff3c9fa91bab3b31dc16ed). Start with README.md. All ten published files were fetched back and verified byte-for-byte. The complete local archive additionally retains native responses, search failures and dispatch/compiler records; private activation/routing tensors are not published.

## Modifications

- Add one original first-entry JSON under `triton_3_8_0` for H100 HBM3, E128/N768, FP8 W8A8, block128x128.
- Keep 18 M keys and six shared parameters for both GEMMs; no separate `_down` file, TMA, Split-K or runtime/reader changes. M>=193 selects shipping-default mathematical settings under nearest-M lookup.
- Native SHA256: `3e4387d4624a0797d0d9b83d4bfc38ee7e62bbbc2a9d732352e8f438b377d4ef`.

The table was originally generated by `tuning_fused_moe_triton.py`: 18 M values x1280 settings, 23,040 attempts, 22,464 successful and 576 shared-memory resource failures. Recorded real routes are held-out validation inputs, not used to fit route-specific configurations. A later bounded refinement failed its predeclared gates and was rejected as a whole; the delivered original bytes are unchanged.
