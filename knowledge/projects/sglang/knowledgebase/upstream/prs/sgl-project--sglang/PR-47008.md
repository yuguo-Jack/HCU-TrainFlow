# [Perf] sglang-api-types: Decode flat id lists directly instead of buffering them as Values

[Upstream PR](https://github.com/sgl-project/sglang/pull/47008) · state: closed · merged: True

## Original PR description

## Motivation

The generated deserializers for `TokenIdsOrList` (`input_ids`) and `StringListOrList` (`mm_hashes`) accept either one flat list or a list of lists, and dispatch on the first element's shape. The generated visitor pulled every element out as a `serde_json::Value`, rebuilt a `Value::Array` from them, and ran `from_value` over that array a second time. For a flat list that is a second full pass over the list: a long prompt's `input_ids` can hold hundreds of thousands of ids, each buffered as a `Value` and then decoded again. The Rust frontend's `/generate` decodes its body through a `Value`, so every long-prompt request paid that second pass before it reached the scheduler. The microbenchmark below (source included) puts the second pass at about the cost of parsing the body itself.

## Modifications

- `sglang-api-codegen` (`emit.rs`): for a `one` arm that is a bare list of scalars, the emitted `visit_seq` now streams a flat list straight into the list message's field. Once the first element has the scalar shape, it is decoded as the scalar type and the remaining elements are read with `next_element::<ScalarTy>()`, so no `Value` is kept per element and no second parse runs. The nested (batch) form keeps the reparse path, and `[]` is still one empty list. `bare_scalar_list` returns a small `BareScalarList` struct (list type, field, scalar type, first-element check) instead of a tuple.
- `sglang-api-types` (`generated/sglang.api.v1.serde.rs`): regenerated with `cargo gen-api`. `TokenIdsOrList` and `StringListOrList` get the streaming branch; nothing else changes, and the Python bindings do not change.
- Accepted shapes and error cases are unchanged: the first element still decides the shape, and a list whose later elements break the first element's shape is still refused.
- `tests/json_contract.rs`: `token_ids_or_list_shape_dispatch` now also covers the `Value` path that `/generate` decodes through, and mixed-shape lists (`[1, [2]]`, `[1, "2"]`, `[1, 2.5]`, `[[1], 2]`), refused on both paths. The test passes with and without the change; it pins the new branch's error handling.

## Accuracy Tests

Not applicable: request decoding only, no model forward or kernel code changes. The decoded request is identical.

## Speed Tests and Profiling

Synthetic microbenchmark, one x86 host, release build, mean of 30 iterations: a `/generate` body whose `input_ids` is a flat list of 150k ids, decoded the way the Rust frontend does it (`from_str` to `Value`, then `from_value::<GenerateRequest>`).

| step | before | after |
|---|---|---|
| body to `Value` | 2.65 ms | 2.25 ms |
| `from_value::<GenerateRequest>` | 2.50 ms | 0.58 ms |
| `from_str::<GenerateRequest>` (direct, for reference) | 2.67 ms | 1.50 ms |

At 20k ids: `from_value` 0.39 ms before, 0.10 ms after. The second parse of the id list is gone; what remains in `from_value` is reading the already-parsed elements out of the `Value`. This is request decoding only, so the effect is per-request latency before the request reaches the scheduler.

<details><summary>Benchmark program (a scratch crate depending on `sglang-api-types` by path, run with `cargo run --release -- 150000` before and after this change)</summary>

```rust
use sglang_api_types::api::v1::GenerateRequest;
use std::time::Instant;
fn main() {
    let n: usize = std::env::args().nth(1).map(|s| s.parse().unwrap()).unwrap_or(150_000);
    let ids: Vec<String> = (0..n).map(|i| ((i * 7919) % 128_000).to_string()).collect();
    let body = format!(r#"{{"input_ids":[{}]}}"#, ids.join(","));
    let iters = 30;
    for _ in 0..3 {
        let v: serde_json::Value = serde_json::from_str(&body).unwrap();
        let r: GenerateRequest = serde_json::from_value(v).unwrap();
        std::hint::black_box(r);
    }
    let (mut t_value, mut t_from_value, mut t_from_str) = (0f64, 0f64, 0f64);
    for _ in 0..iters {
        let t0 = Instant::now();
        let v: serde_json::Value = serde_json::from_str(&body).unwrap();
        let t1 = Instant::now();
        let r: GenerateRequest = serde_json::from_value(v).unwrap();
        let t2 = Instant::now();
        let r2: GenerateRequest = serde_json::from_str(&body).unwrap();
        let t3 = Instant::now();
        std::hint::black_box((r, r2));
        t_value += (t1 - t0).as_secs_f64();
        t_from_value += (t2 - t1).as_secs_f64();
        t_from_str += (t3 - t2).as_secs_f64();
    }
    let k = 1000.0 / iters as f64;
    println!(
        "n={n}: body->Value {:.2} ms, from_value::<GenerateRequest> {:.2} ms, from_str::<GenerateRequest> {:.2} ms (mean of {iters})",
        t_value * k, t_from_value * k, t_from_str * k
    );
}
```
