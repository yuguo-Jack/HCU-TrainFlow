# Support CUDA DP attention in the shared DFlash/DFlash2 path

[Upstream PR](https://github.com/sgl-project/sglang/pull/42032) · state: closed · merged: False

## Original PR description

## Motivation

@humansand

Enable CUDA DP attention for DFlash and DFlash2 through their shared `DFLASH` worker. Require `--enable-dp-lm-head` explicitly, following DSpark, so the borrowed target LM head matches the draft attention-TP group. **Draft: native DFlash2 TP4/DP2 validation still hits a target paged-prefill padding failure described below.**

## Modifications

- **Topology:** permit CUDA/NPU attention DP with an explicit DP LM head; reject attention CP > 1 and retain PP=1. No implicit flag changes.
- **Embedding:** reuse replicated target embedding storage. For sharded embeddings, reconstruct the vocabulary once on the embedding's own TP group, preserving padded shards and added vocabulary rows. Draft lookup adds no per-step collective.
- **Planning:** select the existing idle/mixed eager fallback before target graph loading can install incompatible attention metadata. Keep target graphs for eligible batches and the existing eager draft path under DP. Preserve DSpark's default preparation and NPU's deferred planning.
- **Hybrid target:** initialize empty mRoPE positions as a storage-sharing view so idle DP ranks can later be padded for target verification.
- **Performance:** retain the device token-count scalar and fill it only when batch size changes. Reuse already-copied CPU sequence lengths in the fallback path, removing an extra GPU reduction/readback.
- **Tests:** extend the existing DFlash E2E with a small Qwen3-4B TP2/DP2 case using the same server lifecycle. Route isolated and simultaneous unequal-length greedy requests, swapping the short rank. The CUDA file moves to the two-GPU CI lane; existing AMD tests retain their lane and skip this new case.
- **Docs:** describe explicit head/CP/graph requirements and generated GLM flags. GLM NVFP4/MoE validation remains pending.

**Remaining failure:** native DFlash2's Qwen3.5 hybrid/mRoPE target loads and captures graphs but later fails health generation in plain target paged prefill:

```text
ValueError: q.shape[0] (2) does not match qo_indptr[-1] (1).
```

Attention-TP alignment pads query rows while this paged-prefill plan retains the live row count. This occurs before DFlash2 candidate-selection validation. The broader FlashInfer padding fix is deferred; this draft does **not** claim successful native DFlash2 end-to-end support yet. Earlier idle graph-mask and missing mRoPE-position failures motivated the included fixes and are retained in local evidence.

**Limits:** this is isolated-versus-concurrent regression coverage, not non-speculative target parity, full task accuracy, deterministic mixed-prefill coverage, or qualification of GLM NVFP4/MoE/NPU/ROCm configurations. Repo pre-commit and Mint documentation validation pass.
