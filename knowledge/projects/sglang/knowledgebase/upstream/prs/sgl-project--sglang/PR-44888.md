# [Fix] diffusion: pipeline and model-helper bug fixes

[Upstream PR](https://github.com/sgl-project/sglang/pull/44888) · state: closed · merged: True

## Original PR description

Part of #43875 (items 26-33). Split out of #43585 so it can be reviewed on its own. It does not depend on the other two PRs (#43585, #44887).

Item 25 (Plucker rays in float32 for LingBot-World) moved to its own PR, as asked in review, so it can get a GPU check without holding these up.

## Summary
Fixes in pipelines and the model helpers they use. Item numbers match #43875.

26. The blank default texture and the bake buffers used `(width, height)` where `(height, width)` is needed, which breaks non-square textures.
27. `ImageProcessorV2.load_image` raised `UnboundLocalError` for an ndarray or tensor. ndarrays are handled like PIL images and other types raise a `TypeError`.
28. `DiffusersPipeline` output layout: NumPy videos were permuted twice, a nested PIL list kept only the first video, and several images from an image pipeline were stacked as video frames. A nested list is now stacked to `(B, T, C, H, W)` for every video.
29. `DiffusersPipeline.add_stage` took its arguments in the reverse order of the base class. It now swaps the legacy order and delegates to `ComposedPipelineBase.add_stage`, so it also gets the disagg role filtering.
30. SANA-Video always encoded the negative prompt at 300 tokens. It uses `max_sequence_length` now.
31. ErnieImage treated a `[null, null]` `pe` entry as a real prompt-enhancement model. It is treated as absent.
32. HunyuanImage3 ignored `--revision` when downloading weights.
33. Hunyuan3D picked an arbitrary checkpoint when several matched the fallback glob. It picks the first by name now.

## Tests
- New `test_pipeline_regressions.py` (CPU): 12 cases. The layout test uses distinct values per sample, frame and channel, so swapped axes or a dropped video fail. The ndarray case compares against the same image given as PIL.
- With the source changes reverted, 10 fail. The 2 that still pass are guards: a real Ernie `pe` entry is still detected, and the legacy `add_stage` order still works.
- Unit tests that import the touched modules (25 files) on CPU, PR vs base: 590 passed vs 578 on base. The same 5 failures and 4 GPU-only collection errors occur on base too.
- No tests for 32 and 33 (a passed-through kwarg and a sort). No GPU run; these are API, shape and loading fixes.
