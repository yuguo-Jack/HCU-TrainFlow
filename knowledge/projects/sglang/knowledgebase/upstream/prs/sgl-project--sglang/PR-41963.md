# [Fix] function_call: Flush buffered text at stream end in Pythonic, Inkling, Gemma-4 and Poolside V1 detectors

[Upstream PR](https://github.com/sgl-project/sglang/pull/41963) · state: open · merged: False

## Original PR description

## Motivation

Same loss pattern as #41909 / #41914 / #41962: `PythonicDetector`,
`InklingDetector`, `Gemma4Detector` and `PoolsideV1Detector` hold text back
in `self._buffer` while waiting for the closing tool-call marker (or a
matching bracket / tag). `BaseFormatDetector.finish()` returns an empty
result by default, so when the stream ends with an incomplete marker still
buffered, the held-back text is silently dropped:

```python
d = PythonicDetector()
d.parse_streaming_increment("hi [get_weather(city=", [])
d.finish([])  # returns empty; "[get_weather(city=" is lost
```

## Changes

Add a `finish()` override to each detector that flushes `_buffer` as normal
text, matching the existing pattern in `IQuestQ1Detector.finish` and the
fixes in #41909 / #41914 / #41962. Normal streams are unaffected:
`finish()` stays a no-op when `_buffer` is empty.

## Tests

Offline unit tests (no server, no model loading) for each detector cover:
- partial tool call at stream end: `finish()` releases the buffered text;
- clean stream: `finish()` returns an empty result;
- fully parsed stream: no duplication at `finish()`.

All pass locally (`pytest test/registered/unit/function_call/test_{pythonic,inkling,gemma4,poolside_v1}_detector_finish.py`), ruff clean.
