# [diffusion] MiniMax-H3: run the attention section eager under torch.compile

[Upstream PR](https://github.com/sgl-project/sglang/pull/43634) · state: closed · merged: True

## Original PR description

## Motivation

With `--enable-torch-compile`, MiniMax-H3 serves slower than in eager. On 2xGB300, t2va 5 s, Ulysses 2, compile is 61.5 s against 57.7 s eager. vLLM-Omni's default (compiled) run is 60.9 s.

The attention section gates its fast paths on `not torch.compiler.is_compiling()`, so a compiled DiT loses all of them:

- the fused qk-norm + RoPE;
- the head-group pipelined Ulysses exchange over the copy engine;
- the IPC all-to-all.

Those paths cannot be traced. The traceable fallback that compile takes instead (unfused norm and RoPE, a sequential exchange) costs more than inductor saves on the rest of the block.

## Modifications

- The section from the per-head q/k norm through the attention output (before `out_proj`) moves into `MiniMaxH3Attention._attend`.
- Eager calls `_attend` as before. Under compile, `forward` calls `_attend_eager = torch.compiler.disable(_attend)`, so that section runs exactly the eager fast paths, and inductor compiles the QKV/out projections, MLP, AdaLN and norms around it.
- The `is_compiling()` gate inside the section goes away, since compile no longer traces it.

Eager behavior is unchanged: the same calls in the same order.

## Accuracy Tests

Eager is unchanged (same code path). Under compile, the attention section now runs the same fused kernels as eager, instead of the unfused fallback.

## Speed Tests and Profiling

2xGB300, MiniMax-H3 t2va 5 s, Ulysses 2, served. Base: main 3831e7e09, the then-open GB300 fixes and #43602; compile arms use `--offload-during-compile false`. Each cell is the median of 2 requests after warmup, every arm on a fresh server; the second compile round runs the arms in the opposite order.

| | before | this PR |
|---|---:|---:|
| eager | 57.667 s | 57.554 s (unchanged) |
| torch.compile, round 1 | 61.378 s | **58.712 s (−4.3%)** |
| torch.compile, round 2 | 61.590 s | **58.609 s (−4.8%)** |

vLLM-Omni's default (compiled) run is 60.95 s on the same box. Compile is still slightly behind eager for H3, but it no longer loses its fast attention paths.
