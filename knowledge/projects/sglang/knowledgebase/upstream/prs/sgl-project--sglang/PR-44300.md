# [Feat] models: Ling-3.1-flash day-0 support, Hopper decode opts, prefill overlap, Ling3 fixes

[Upstream PR](https://github.com/sgl-project/sglang/pull/44300) · state: open · merged: False

## Original PR description

## Summary

Day-0 support and performance work for **Ling-3.1-flash** (BailingMoeV3, hybrid KDA+MLA, 512 experts, blockwise FP8), developed with the vendor (inclusionAI). The branch is an integration of three independently-reviewable change sets plus their review fixes:

**A. Hopper decode optimizations** (from the vendor's reference implementation, env/shape-gated, SM90-only):
- Small-M blockwise-FP8 + BF16 decode GEMV kernels and a CUDA router-gate matvec (`SGLANG_ENABLE_FP8_BLOCK_GEMV`, default off)
- Fused KDA output finalize-norm + FP8 quantization (`SGLANG_ENABLE_FUSED_KDA_OUTPUT_QUANT`, default off)
- CUDA grouped top-k router for the 512-expert shape (exact shape gate: 512 experts / 8 groups / topk_group 4 / topk ≤ 8 / ≤ 1 shared expert / static bias). Hardened vs the reference: scaling applies with or without renormalization, and zero-sigmoid-sum normalizes by 1 instead of producing NaN
- Defensive `out=` handling in the FP8 GEMV path for callers that own the output buffer

**B. Prefill overlap** (env-gated where it changes scheduling):
- Fold the shared-expert add into the MoE finalize epilogue (`SGLANG_OPT_MOE_FUSED_OUTPUT_ADD`, default on; only BailingMoeV3 passes an addend; LoRA and grouped/registered-runner paths verified)
- Chunked-GEMM prefill all-reduce overlap pipeline (`SGLANG_OPT_CHUNKED_GEMM_AR`, default off — measured no speedup for this model on H200; kept for other targets)
- Split hybrid-Mamba prefills at the cached Mamba fork (`SGLANG_SPLIT_PREFILL_AT_MAMBA_FORK`, default off). Fixes two scheduler bugs found in review: a second unfinished chunked request could be admitted after a continuation fork-split, and an over-delivered HiCache load could skip the fork stop
- Kimi K3 o_proj all-reduce fusion probe made explicit so FP8 checkpoints keep their previous default

**C. Ling3 correctness fixes** (parser/tool-call/grammar/model):
- Nullable JSON `null` preserved for nullable string tool arguments
- Reasoning-only output stays in `reasoning_content` by default (`force_nonempty_content=False`)
- BailingMoeV3 defaults to the `ling3` tool-call and reasoning parsers
- Native XML required/named tool-call constraints; argument values are opaque (a `</tool_call>` inside a string value no longer truncates the call); regex body made linear-time (an exponential-backtracking path and two quadratic paths in the shared GLM-4.5 detector are fixed as well)
- Reasoning grammar replays an implicit tool-start marker with transactional, backend-aware probing (XGrammar/llguidance/Outlines; the reference implementation corrupted the latter two)
- Per-layer shared-expert fusion gate driven by routed/shared SwiGLU limits, with NextN reading limits at its own checkpoint index

Original authors are credited via `Co-authored-by` trailers. This package was reviewed with the vendor ahead of this PR.

## Speed tests

H200 TP8+EP8 + NEXTN, `bench_serving` random:

- bs=1 (2048/512, conc 1): **251.2 output tok/s**, TPOT 3.63 ms, acceptance length 2.61 (random) / 2.13 (real text)
- conc 32 (4096/512): **1458.5 output tok/s** (1640.8 total tok/s/GPU)
- Decode-gate A/B (accept-1.0 checkpoint): 94.6 → 104.1 tok/s (+10.1%) bs=1
- GB300 TP4+EP4 + NEXTN: bs=1 180.0 tok/s, acceptance 2.59; smoke 97/100

Kernel/unit suites: 9 suites pass on SM90 (H200), including router matvec, FP8 GEMV, KDA fusion, top-k router (with zero-sum and no-renormalize-scaling cases), FP8 `out=` contract, chunked-GEMM plan/dispatch, fused MoE output-add contract, and scheduler fork-split regressions. The GB300 SM103 leg skips SM90-only classes by design.

## TP-only (EP=1) support via TP-requantization (validated)

Adds the vendor's TP-requant path so block-FP8 Ling-3.1-flash can serve **TP-only** (EP=1): per-rank 160-wide shards are dequantized with checkpoint-global scales and requantized onto the local block grid at load time (routed experts + standalone shared MLP + NextN draft). EP>1 and non-Bailing models are untouched (control-flow verified with throwing sentinels, and the EP8 serve logs zero requant lines).

Measured on 8×H200, same build, NEXTN on:

| | TP8-only | TP8+EP8 |
|---|---|---|
| bs=1 | **265.7 tok/s** (TPOT 3.29 ms) | 239.5 tok/s (TPOT 3.63 ms) |
| conc 32 | 1384.7 tok/s | **1410.0 tok/s** |
| GSM8K (1319) | **97.12% / stop 99.92%** | 96.89% / stop 99.77% |

The fused SwiGLU K-tail (`128 < N/2 < 256`; N/2 = 160 TP-only) engages on every routed MoE call (profiler-verified; zero on EP8). Co-authored-by the original authors.

## Out of scope (documented for reviewers)

- **Block-FP8 MoE K-tail fusion kernels (K=160)**: excluded from this PR. They are unreachable on upstream — the fusion gate wants per-rank `128 < N/2 < 256` while the block-FP8 loader requires `% 128 == 0` — and need the vendor's TP-requantization machinery, which is a PR of its own. TP-only topologies for this model fail loudly at load time today (pre-existing behavior, unchanged by this PR).
- **DSpark / MXFP4**: no public draft or quantized checkpoint for this model.
- **FlashInfer MLA draft-extend CUDA graph**: an attempted port crashed at capture (kv index fill vs padded indptr mismatch); it is not included. Draft-extend stays eager, as before.
