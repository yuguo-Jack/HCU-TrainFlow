# [rust-server] expand PD bootstrap rooms across parallel choices

[Upstream PR](https://github.com/sgl-project/sglang/pull/43863) · state: open · merged: False

## Original PR description

## Motivation

Fixes #43862.

The Rust worker's `bootstrap_room` normalization disagreed with the Python reference and the sgl-model-gateway PD router for OpenAI `n > 1`:

- **chat `n > 1` arrives from the router with an n-element `bootstrap_room` list** (`get_chat_batch_size` returns `n`); the chat worker hardcoded `prompt_count = 1`, so the list-length check 400'd every such request (`bootstrap_room list length n does not match batch size 1`), while the identical request to a Python worker succeeded.
- **a scalar room fanned out over prompts only**, so all `n` choices shared one room; Python fans over `batch_size * n` (one room per choice, sample-major flat order), so choices `1..n-1` of a mixed Rust/Python prefill-decode pair rendezvoused on rooms the other leg never created and waited out `SGLANG_DISAGGREGATION_*_TIMEOUT`.

Same divergence class as #42029 (renderer), which this brings to `sglang-server`.

## Modifications

- `normalize_bootstrap_columns` now takes `choices_per_prompt` and indexes bootstrap columns **per engine request** over `prompt_count * choices_per_prompt`, in Python's sample-major flat order (`flat = choice * prompt_count + prompt`, matching `GenerateReqInput._normalize_bootstrap_params`):
  - scalar room → advances once per request (`room.wrapping_add(flat)`);
  - `prompt_count`-element list → per prompt, shared by that prompt's choices (Python replicates the list `× n`);
  - full per-choice-length list → passes through one value per request — the router's chat `n` convention (previously a 400);
  - any other length → clear validation error.
- `chat.rs` indexes its per-choice columns by choice; `completions.rs` computes the flat index inside the sample loop (submission stays prompt-major, rooms sample-major — both pinned by tests).
- The host-clone broadcast budget now bounds the expanded column directly, subsuming the handler-side check in `pd_routing.rs`.
- The native `/generate` path passes `choices_per_prompt = 1` (`n > 1` is rejected in `sampling.rs`), so its behavior is unchanged.

## Verification

- `cargo test -p sglang-server --lib`: 318 tests; all pass except 12 pre-existing POSIX-shm failures that also fail on the base commit on macOS (`fallocate`: Bad file descriptor — Linux-only surface; CI runs Linux).
- New coverage:
  - unit: scalar fans across prompts × choices sample-major (`2×3 → 100..105`); per-choice list accepted; per-prompt list shared across choices; unrecognized list length still 400s;
  - end-to-end through the real HTTP handlers with a mock core: chat `n=2` with the router's exact 2-element room list now returns 200 and submits rooms `[101, 102]` (previously 400 at normalization); completions `prompt=[a,b], n=2` with scalar room 100 submits `[100, 102, 101, 103]` — Python's numbering.
- `cargo clippy -p sglang-server --all-targets`: clean; `cargo fmt --check`: clean.

No GPU PD run was performed; the Python-parity expectations are pinned from `io_struct.py`'s expansion order and covered by the in-process handler tests.
