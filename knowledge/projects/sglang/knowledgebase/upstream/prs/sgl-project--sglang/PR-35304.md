# [Feat] [XPU] encoder: Support NomicBERT / ModernBERT embeddings and InternVL3_5

[Upstream PR](https://github.com/sgl-project/sglang/pull/35304) · state: open · merged: False

## Original PR description

Intel XPU model support for encoder embeddings and InternVL3_5 — the XPU-specific
model-enabling changes. The backend-agnostic fixes are reviewed separately: SEP-preserving
truncation and fp32 MEAN pooling in #39754, and the Hunyuan qk_norm reshape in #41160.

## Motivation

- **nomic-ai/nomic-embed-text-v1.5** (`NomicBertModel`) had no SGLang model, so the
  Transformers fallback raised `NotImplementedError: get_input_embeddings ...`.
- **ibm-granite/granite-embedding-english-r2** (`ModernBertModel`) fell back and
  crashed in the forward pass (`RuntimeError` in `set_kv_buffer`) — a bidirectional
  encoder routed through the paged decoder KV cache.
- **OpenGVLab/InternVL3_5-30B-A3B** (Qwen3-MoE backbone) crashed at load
  (`AttributeError: 'InternVLChatConfig' object has no attribute 'num_experts'`) and,
  once loading, hung/crashed the vision encoder under concurrent multimodal at tp>1
  (Level Zero USM-memcpy deadlock on a per-block device->host `.item()`; DEVICE_LOST
  batching ViT tiles).

(`BAAI/bge-base-en-v1.5` needs no new model file; it already runs on XPU as a `BertModel`.
#39754 keeps its trailing `[SEP]` when long inputs are auto-truncated.)

## Modifications

Encoder embeddings:
- `models/nomic_bert.py` (new): `NomicBertModel` — RoPE, SwiGLU, post-norm; SDPA,
  `AttentionType.ENCODER_ONLY`.
- `models/modernbert.py` (new): `ModernBertModel` — RoPE, local/global attention,
  GeGLU; SDPA, `ENCODER_ONLY`.
- `test/manual/prefill_only/test_xpu_encoder_embedding.py`: XPU embedding UT (manual, not in CI). It sends
  one request per prompt, so the result does not depend on how prompts are batched.

InternVL3_5 (XPU):
- `models/internvl.py`: read `num_experts` from `config.llm_config`; pass the host
  `max_seqlen` into the vision attention metadata; chunk the ViT forward to
  `SGLANG_VIT_MAX_TILES` tiles on XPU.
- `layers/attention/vision.py`: `VisionIntelXPUAttention` (XPU-only class) consumes
  the metadata's host `max_seqlen` instead of re-deriving it from GPU `cu_seqlens`.
- `environ.py`: add `SGLANG_VIT_MAX_TILES` (default 12 = InternVL per-image tile cap).

## Accuracy Test

Intel XPU (Arc Pro B60), vs the HuggingFace reference.

Encoders — MTEB SciFact NDCG@10 (300 queries / 5183 corpus), tp-1:

| Model | cosine vs HF | SciFact NDCG@10 | HF ref |
|---|---|---|---|
| nomic-ai/nomic-embed-text-v1.5 | 1.00000 | 0.6803 | (prefix-sensitive) |
| ibm-granite/granite-embedding-english-r2 (ModernBERT) | 1.0 fp32 / >=0.9999 bf16 | 0.6720 | 0.6815 |

InternVL3_5-30B-A3B — tp-4 (61.7 GB bf16): loads with 0 skipped params, MoE
initialized, multimodal smoke (red image -> "Red"); P1 lmms-eval **mathvision_testmini
38.2, mmmu_val 27.4**.

## Speed Test and Profiling

New encoder models are small SDPA (no KV cache). InternVL removes a per-block
device->host sync on XPU and bounds the ViT forward; non-XPU paths are unchanged.

CUDA check of the two encoder models on 1x NVIDIA H200 NVL (tp 1). All runs use the same image (`lmsysorg/sglang:nightly-dev-20261015-a6a8c560`) with the sglang Python source taken from each commit:
- before: merge-base `72730d6360`
- after: this PR, `fcd9c2014a`

I added one commit to this PR, fcd9c2014a: MEAN pooling now accumulates its cumsum in fp32. The cumsum runs over the whole packed batch, so in fp16/bf16 a short request packed after a long one loses most of its own sum to rounding. Because of this the nomic check in `test_xpu_encoder_embedding.py` failed 3 of 8 runs on H200, whenever the short prompts landed after the 2028-token one. The bug is in the shared pooler, so it hits MEAN-pooled embedding models on every device. The commit adds a CPU regression test for it.

| Model / check | Before | After |
| --- | --- | --- |
| `test_xpu_encoder_embedding.py` with `ATTENTION_BACKEND = "triton"` (HF vs SGLang cosine, fp16) | granite crashes at the first prefill in the triton extend kernel (`kv_indptr` is None) | 6/6 runs pass, cosine 0.999999 on the short prompts |
| nomic-embed-text-v1.5, SciFact ndcg@10 | fails at load: `NotImplementedError: get_input_embeddings not auto-handled for NomicBertModel` | 0.7008 |
| nomic-embed-text-v1.5, STSBenchmark | same | 0.8425 |
| granite-embedding-english-r2, SciFact ndcg@10 | fails: `IndexError: tuple index out of range` | 0.7583 |
| granite-embedding-english-r2, NFCorpus ndcg@10 | same | 0.3765 |

- Pooling fix, nomic: SciFact 0.6824 without it, 0.7008 with it (model card 70.28). STS is the same either way (0.8425). Without it the embedding test cosine on the short prompts dropped to 0.98 in the failing runs.
- The new unit test in `test_pooler_score_and_pool.py` fails on main without the fix (max abs diff 0.47, tolerance 0.05) and passes with it (13/13).
- granite uses CLS pooling, which the new commit does not touch, so its rows are from `554cbb2b92`.
- The MTEB rows use `--disable-radix-cache`. The radix cache stays on for encoder embedding models, so later requests reuse prefix tokens computed with an earlier prompt (same separate issue on main as in #39754). With default flags at `554cbb2b92` the numbers are nomic SciFact 0.6947 / STS 0.5633 and granite SciFact 0.1009 / NFCorpus 0.1242.
