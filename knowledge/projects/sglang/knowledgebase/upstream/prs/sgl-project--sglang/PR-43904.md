# [Refactor] scheduler: Check request ownership once at step launch

[Upstream PR](https://github.com/sgl-project/sglang/pull/43904) · state: closed · merged: True

## Original PR description

The scheduler checked request ownership in two places: a duplicate check at each step launch, and a running check after the merge that derived the expected running requests from the batch shapes. The second one held only at that one point: right after it, `update_running_batch` and a mixed step move rows out of the running batch while their requests stay running, which is why it needed rules per forward mode. This replaces both with one check at each step launch, written from per-request state only.

- `SchedulerInvariantChecker.maybe_check_request_lists(batch)` runs in `_on_step_launch`, after the launched prefills join `prefill_launched`. That is the first point of an iteration where every request has an owner (new prefills are in no list between the batch build and the launch) and the step records stop changing. It raises when:
  - a request is in two lists;
  - an unfinished row of a running batch or of a step in flight (the launching step, and under PP every micro-batch's step) is in no list and is not the chunked request;
  - an unfinished row of a running batch, apart from the chunked request, is not in `running`;
  - a request in `running` is in no running batch and has no step in flight (`inflight_steps`). Under overlap a request whose queued result finishes it is out of the running batch but still running; a mixed step holds its decode rows the same way;
  - a request in `prefill_launched` is in a running batch.
- The check reads list membership, the running batches and `Req.inflight_steps`. It reads no forward mode and no step snapshot.
- Removes `maybe_check_running_reqs` and its calls after the merge and in the PD decode scheduling. `maybe_check_batch_consistency` is unchanged.
- `RunningReqs` is removed: `Scheduler.running_reqs` is a `RequestList`, and its meaning moves to a comment at the field.

No behavior change outside the debug checks (`SGLANG_ENABLE_RUNNING_REQS_CHECK`, on in CI).

## Test plan
- New unit tests for each failing case (a duplicate, a row in no list, a running-batch row not in running, a running request with no batch and no step in flight, a prefill_launched request in a running batch), and passing cases for an overlap request finishing in flight and a PP mixed step.
- The unit tests that build a scheduler or an invariant checker pass locally with `SGLANG_IS_IN_CI=1`.
