# [Fix] Reserve remaining tokens for ignore_eos requests during prefill admission

[Upstream PR](https://github.com/sgl-project/sglang/pull/43564) · state: closed · merged: True

## Original PR description

When admitting a new prefill batch with prefix caching enabled, `PrefillAdder` discounts the remaining output tokens of running requests by `new_token_ratio`, including requests with `ignore_eos=True`. These fixed-length requests cannot finish through early EOS. On Qwen3-32B/H200, the ratio decays to 0.098 while the workload still requires 1,024 output tokens, allowing prefills that subsequently force running requests to retract.

Use a ratio of 1.0 for running `ignore_eos` requests, preserving the existing `CLIP_MAX_NEW_TOKENS` cap and the normal EOS-aware policy. Extend the existing admission-budget tests with a real `PrefillAdder` regression covering fixed-length, ordinary, and partially decoded requests. Related earlier investigation: #7328.

Validated against `e35f60b9` on the same H200, Qwen3-32B revision `9216db5781bf21249d130ec9da846c4624c16137`, TP1, C32, 160 requests, nominal 8,192-token inputs and fixed 1,024-token outputs. Request hashes and actual input/output token lengths match across each pair. These are single paired runs; the small throughput differences are not claimed as a stable speedup.

| Mode | Version | Timed retractions | Output tok/s | Median TTFT (s) | Median TPOT (ms) | p99 E2E (s) |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| Default | Baseline | 5 | 465.44 | 16.719 | 45.32 | 124.58 |
| Default | Fix | 0 | 466.95 | 15.792 | 44.65 | 120.28 |
| Mixed chunk | Baseline | 5 | 467.89 | 6.643 | 56.76 | 122.29 |
| Mixed chunk | Fix | 0 | 469.21 | 6.629 | 55.57 | 119.88 |

Validation:
- Existing `test_prefill_memory_budget.py` and `test_prefill_adder.py`: all 65 tests and 46 subtests pass. The new admission regression fails on the baseline. Updated the existing request mock to include the default `ignore_eos=False`, as required by the running-request budget calculation.
- Both fixed runs complete without a retraction; the separate baseline profiles each contain one additional retraction beyond the five timed above.
- Full held-out GSM8K, matched prompts: default 1250/1314 before and after, with identical correctness per case; mixed 1246/1314 before and after, with five losses and five gains. Every request ends with `stop`, with zero errors or token-limit finishes. Equal aggregate scores do not imply identical mixed-batch outputs.
- Pre-commit checks pass. No new test files.

This fixes under-reservation in cached admission; it does not claim to close the entire Qwen3-32B latency gap or remove retractions for every workload.
