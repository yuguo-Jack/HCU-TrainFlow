## Cross-Job Failure Summary

### Common Root Cause
There is no single common root cause. The 7 failures break into **4 distinct categories**: numerical tolerance issues, a LoRA TP correctness regression, a missing CLI entry point, and CI gate propagation.

### Distinct vs Shared Failures

1. **Numerical tolerance too strict (3 jobs):** `stage-b-test-large-1-gpu (12)` (bf16 KDA kernel, diff 3.8e-6), `stage-b-test-small-1-gpu-amd-nondeterministic` (ROUGE-L 0.977 vs threshold 1.0), and partially the AMD finish gate — all fail due to overly tight tolerances on inherently imprecise operations. These are **low priority flaky failures**.

2. **LoRA TP correctness regression (1 job):** `stage-b-test-large-2-gpu (2)` fails deterministically with decode logprobs diff of 7.08 using `csgmv` backend on 2 GPUs. This is a **real regression**, not a tolerance issue.

3. **Missing `sglang` CLI on PATH (1 job):** `build-and-test` (XPU) fails because the Docker environment doesn't expose the `sglang` entry point. This is an **environment/config issue** unrelated to GPU test correctness.

4. **Gate propagation (2 jobs):** `wait-for-stage-b` and `pr-test-finish` / `pr-test-amd-finish` are not independent failures — they cascade from the upstream failures above.

### Fix Priority
**Fix the LoRA TP `csgmv` regression first** — it's the only deterministic correctness failure, it blocks the largest number of downstream CI stages via fail-fast, and it may indicate a real serving accuracy bug in production multi-GPU LoRA inference. The tolerance fixes and Docker PATH fix are straightforward follow-ups.
