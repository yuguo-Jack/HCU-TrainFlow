# [Fix] attention: Do not default to FlashInfer for head dims FA2 prefill cannot run

[Upstream PR](https://github.com/sgl-project/sglang/pull/44238) · state: open · merged: False

## Original PR description

## Motivation

On NVIDIA GPUs other than Hopper and SM100 (for example Ampere, Ada and SM120), `get_default_attn_backend` picks FlashInfer for every MHA model, whatever its head dim. FlashInfer's FA2 prefill only works when the head dim is a multiple of 64. This is the open upstream issue flashinfer-ai/flashinfer#4299, which names Phi-3-mini as an affected model.

Measured on an RTX 4090 with FlashInfer 0.7.1:

| Head dim | FA2 ragged prefill |
|---|---|
| 64, 128, 192, 256 | correct |
| 16, 32, 48 | `FlashInfer Internal Error: Invalid configuration` |
| 80, 96, 112, 160 | returns NaN, no error |

FlashInfer 0.6.18 (the v0.5.21 image) behaves the same. Real models with these head dims fail on the default configuration:

- **`microsoft/Phi-3-mini-4k-instruct` (head dim 96)** crashes during startup with `CUDA error: an illegal memory access was encountered`. With CUDA graph disabled, the first request returns an empty string and the second crashes with `MergeState ... Unsupported head_dim: 96`.
- **`BAAI/bge-small-en-v1.5` and `cross-encoder/ms-marco-MiniLM-L6-v2` (head dim 32)** crash during startup with `Invalid configuration`.

The FlashInfer backend already notes this limitation (`flashinfer_backend.py`, ragged prefill). The cross-encoder server test avoids it by passing `--attention-backend torch_native`.

## Modifications

- `get_default_attn_backend` falls back to triton when the head dim or V head dim is not a multiple of 64. This is the same place and the same way it already falls back for attention sinks.
- An explicit `--attention-backend flashinfer` is kept.
- Hopper (fa3), SM100 (trtllm_mha/fa4), ROCm and the MLA branch are unchanged.
- Regression test in `test_model_overrides.py`, on a faked FA2 platform:
  - head dim 128 resolves to flashinfer;
  - head dims 96 and 32 resolve to triton;
  - an explicit flashinfer choice is kept.

## Accuracy Tests

Setup: one RTX 4090, `lmsysorg/sglang:nightly-dev-20261014-684fea8a` (main at `684fea8a`) with and without this patch, default flags.

- **Phi-3-mini.** Check: three short questions at temperature 0, plus prompt logprobs.
- **bge-small and MiniLM.** Also run with `--disable-radix-cache --chunked-prefill-size -1`, as the existing encoder tests do. That keeps the separate prefix-reuse bug fixed in #44237 out of the comparison. Embeddings were compared with the Hugging Face CLS reference, and rerank scores with `AutoModelForSequenceClassification` logits.

| Model | Main | This PR |
|---|---|---|
| `Phi-3-mini-4k-instruct` (96) | startup crash, illegal memory access | triton by default; answers `Paris`, `144`, `Jupiter`; 0 NaN prompt logprobs |
| `bge-small-en-v1.5` (32) | startup crash, `Invalid configuration` | triton by default; cosine 1.00000 on all 10 request shapes |
| `ms-marco-MiniLM-L6-v2` (32), `/v1/rerank` | startup crash, `Invalid configuration` | triton by default; scores within 0.004 of the reference, same order |
| `Qwen2.5-0.5B-Instruct` (64) | flashinfer | flashinfer (unchanged) |
