# [Chore] docker: Pin Dynamo and grpcio-tools in the Beam image

[Upstream PR](https://github.com/sgl-project/sglang/pull/45292) · state: open · merged: False

## Original PR description

## Motivation

#44747 changed `docker/Dockerfile`'s Dynamo step: a stable `ai-dynamo` pin, the frozen constraints, `inflect`, a `grpcio-tools` pin and `INSTALL_DYNAMO`. This stack leaves `docker/Dockerfile` unchanged and carried equivalent pins in the Beam image (#45253). They now live here so they can be dropped without touching the image layer.

This PR's base branch is `beam-stack-01-docker`, so its diff shows only the pins.

## Modifications

On top of #45253's `docker/beam/beam.Dockerfile`:
- Pins `grpcio-tools==1.84.0` alongside the OpenAI and tileiras pins.
- Adds an `INSTALL_DYNAMO=1` step that installs `ai-dynamo==1.5.1` and `inflect` under the frozen constraints, releases only the pydantic pins for that solve, and records the versions it selects. `INSTALL_DYNAMO=0` skips it.

## Validation

Beam serving does not need these pins:
- An image built from the unchanged upstream `docker/Dockerfile` (arm64, CUDA 13.0.3) serves Beam on 4×GB300: GSM8K 96.36% with zero request errors. It used the cuBLAS router, since that image has no `tileiras`.
- In that image the unbounded Dynamo install resolved to `ai-dynamo==1.6.0.dev20261019`, not the empty placeholder, and `import dynamo.runtime, inflect` works. `grpcio-tools` resolved to 1.84.0 without a pin.
- `pip check` there does report the two conflicts these pins avoid: `inflect` 7.5.0 needs `typeguard>=4` (2.13.3 installed), and `ai-dynamo-runtime` needs `pydantic<=2.13.5` (2.14.1 installed).
- `docker buildx build --check` passes for this file; the image has not been built.

This PR is likely to be closed without merging.
