## Original PR description

# [Perf] paged-experts: load experts without a staging copy

## Motivation

This PR aims to reduce memory footprint while loading checkpoints.

Paged Experts (#42557) keeps every expert in a pinned host store. Today a start first loads every expert into a pageable staging copy in the checkpoint layout, then fills the store from it K experts at a time (on the Marlin runner — GPTQ, AWQ, MXFP4, NVFP4, compressed-tensors W4A16 — through the repack). The staging copy is as large as the store, and while loading, both are in RAM at once, next to the checkpoint's page cache.

So a start needs host memory for every expert twice. Paged Experts exists to serve models whose experts don't fit in VRAM from host RAM, and the staging copy halves which models that is: a model whose experts fit in RAM once but not twice cannot start without swapping heavily, and is killed on a host without enough swap. For example, Qwen3-Next-80B-A3B-Instruct-NVFP4 on an RTX 5070 Ti with 62 GB of RAM:
- the staging copy takes 44 GB,
- 19-26 GB go to swap during the start,
- `load_model` takes 177-352 s, depending on how much it swaps,
- after the start, 3.4-3.5 GB of the server process stay in swap, which raises TTFT.

This PR removes the staging copy: the expert loads replay K experts at a time from the mapped checkpoint, straight into the store (or the repack). On the same machine, Qwen3-Next loads in 125-128 s without swapping, and TTFT p50 drops from 220-231 ms to 192 ms. Models whose experts fit in RAM twice don't gain from it; their start is 1-2 s slower.

## Modifications

- **Loads wait** (`store.py`: `ExpertLoads`). With mapped safetensors (`--load-format auto`, `safetensors`, `mistral`, without `--weight-loader-disable-mmap`), an expert load of a paged layer does not run; it waits as a write on its view of the mapped checkpoint. A load that cannot wait (a stacked checkpoint tensor as in gpt-oss, a tensor torch allocated) and every load of the other loaders go to a table of every expert, as before.
- **The post-load step K experts at a time** (`formats.py`: `PostLoad`, `build_store`). After loading, the waiting loads replay one chunk of K experts into K rows, the base method's post-load step runs on them (a repack on the Marlin runner, from the layer's state before the first chunk), and the result is copied into the pinned store. Each chunk's checkpoint pages are read ahead while the previous chunk runs (`MADV_WILLNEED`) and given back after it (`MADV_PAGEOUT`, on a thread of its own, since the kernel reclaims synchronously; skipped where the kernel lacks it, never `MADV_DONTNEED`). Experts 1..K, which the existing mixing check repacks once more, keep their pages until it ran, so every expert is read from the checkpoint once.
- **Behaviour change: `--load-format`.** #47476 refused only `dummy`. The store fills from `model.load_weights` followed by the post-load step, so the loaders that do that are accepted (`auto`, `safetensors`, `pt`, `npcache`, `mistral`, `fastsafetensors`, `instanttensor`, `runai_streamer`) and every other format is refused at startup with its reason: `dummy` has no real weights, `gguf` holds GGUF-quantized experts (no expert format pages them), the rest load the weights without Paged Experts' loader and post-load step.

Outside Paged Experts nothing changes. Docs: `paged_experts.mdx` ("Load formats", "Startup", "The K-slot table and the host store").

## Accuracy Tests

The pinned store holds the same bytes as before: the same native per-expert loader and post-load step run on the same experts, only in another order. GSM8K (200 questions), Qwen3-Next-80B-A3B-Instruct-NVFP4, base / this PR, two starts each: 0.965, 0.975 / 0.970, 0.960 (standard error about 1.6 points). Unit tests on CPU:

- `TestLoads`: a view of a mapped file waits and a tensor torch allocated does not (a real safetensors file as control); only the mapped safetensors loaders let loads wait; a load that cannot wait moves the waiting ones into the table (negative control: a waiting load left out keeps its created value); replayed views keep their bytes after `madvise`, refused advice leaves anonymous memory alone (negative control: `MADV_DONTNEED` zeroes it); pages are given back on a thread of their own and `drop` waits for it (control: read-ahead stays on the caller); without Linux no libc is loaded and advice is skipped; a build replays each expert once and gives each expert's pages back once, after its last read, also experts 1..K after the mixing check (negative control: giving pages back at every replay re-reads 1..K).
- `TestLoading`: the host loader follows the base method and the parameter's tags; a stacked tensor reaches the native loader after the waiting loads; the repack runs per chunk from the layer's state before the first; a short last chunk pads with real experts (NVFP4A16's scale check passes); a step that mixes experts is refused; a loader that reads the layer's state sees it as loaded at every replay (negative control: without restoring it, the mixing check refuses the result).
- `TestCompat`: every `LoadFormat` member is accepted or refused with its reason.
- GPU (`test_paged_experts_kernels.py`): the store's constructor change.

## Speed Tests and Profiling

Same machine as #42557: RTX 5070 Ti 16 GB, 62 GB RAM, PCIe 5.0 NVMe, `--paged-experts-num-resident auto --max-total-tokens 10240`, page caches dropped before every start, base and this PR alternating twice. `load_model` is the model loader's wall time, swap the most swap in use during the start, decode `1000 / median TPOT` over 8 ShareGPT prompts (256 output tokens, after 2 discarded warm-up requests).

| model | `load_model` base / this PR | swap at start, base / this PR | decode tok/s, base / this PR | TTFT p50, base / this PR |
|---|---|---|---|---|
| Qwen3-Next-80B-A3B-Instruct-NVFP4 | 352.1, 176.6 / 128.3, 125.5 s | 25.6, 19.1 / 0.2, 0.2 GB | 101.6, 100.7 / 102.6, 100.3 | 231, 220 / 192, 192 ms |
| Qwen3-30B-A3B-GPTQ-Int4 | 33.5, 33.0 / 45.4\*, 34.1 s | 0.2 / 0.2 GB | 233.6, 233.2 / 233.7, 233.4 | 41, 40 / 40, 40 ms |
| Qwen3-30B-A3B-FP8 | 52.1, 51.3 / 53.1, 53.1 s | 0.2 / 0.2 GB | 105.0, 105.0 / 105.1, 105.1 | 183, 182 / 182, 183 ms |

On Qwen3-Next the base's start time varies 2x with how much it swaps; this PR does not swap. On the 30B models nothing swaps, and this PR's start is 1-2 s slower than the base: replaying every expert's load into the K rows costs about that much more than the base's direct loads (the page-out of the replayed pages runs on a thread of its own and is off the critical path). \*3 of 7 GPTQ starts of this PR in three runs (none of 7 base starts) spent ~10 s more in the safetensors weights iterator, the part of the load this PR does not change; the other four took 34.1-34.6 s.

Decode is unchanged (the slots and the store hold the same bytes); on Qwen3-Next the base's TTFT is higher because it serves with part of its process in swap.
