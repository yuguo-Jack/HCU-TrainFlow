# [Fix] [AMD] smallm_fp8_blockscale_gfx950: import renamed hipcc helpers

[Upstream PR](https://github.com/sgl-project/sglang/pull/45738) · state: closed · merged: False

## Original PR description

## Problem

`smallm_fp8_blockscale_gfx950` imports `_check`, `_hip_lib`, `_hipcc` and `_Kernel` from `smallm_moe_gfx950`, but those private helpers were moved to `sglang.kernels.jit.utils.hipcc` and renamed (`check_hip`, `hip_lib`, `hipcc_path`, `HipKernel`). `smallm_moe_gfx950` itself was updated to the new names; `smallm_fp8_blockscale_gfx950` was missed, so importing it raises `ImportError: cannot import name '_check'`.

This breaks the FP8 block-scale GEMM path that `aiter_w8a8_block_fp8_linear` uses, so **Qwen3-Next FP8 fails to serve on gfx950 (MI355X)** — the scheduler crashes on the first forward.

## Fix

Import the renamed helpers from their new home and update the call sites, the same way `smallm_moe_gfx950` was updated. (`vattn_asm_gfx950` has its own local copies and is unaffected.)

## Test

Validated on the latest MI355X nightly `lmsysorg/sglang-rocm:v0.5.22-rocm724-mi35x-20261021` (Triton 3.8.0). Qwen3-Next-80B-A3B-Instruct-FP8 loads and serves on MI355X TP4; before this change it crashed at startup with `ImportError: cannot import name '_check' from 'sglang.kernels.ops.moe.smallm_moe_gfx950'`.
