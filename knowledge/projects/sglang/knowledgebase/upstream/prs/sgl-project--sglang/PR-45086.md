# [Fix] [DSV4.1] mHC: don't specialize split-K Triton kernels on row count

[Upstream PR](https://github.com/sgl-project/sglang/pull/45086) · state: open · merged: False

## Original PR description

## Motivation

Triton specializes int args by value (`== 1`, `% 16 == 0`, other) and the mHC split-K kernels take the row count as a plain int. So any batch whose row count lands in a new class recompiles mid-serving on the scheduler thread while the other ranks wait on it.

```
Triton kernel '_hc_mix_reduce_sinkhorn_kernel' took 28.57 s to compile after serving started.
```

On DSV4.1-Flash (4xB200, 8k prompts, 16 concurrency) this showed up as an 11.6 s P99 TTFT vs a 76 ms median.

## Modifications

Add the row count to `do_not_specialize` in `_hc_mix_reduce_sinkhorn_kernel` (`m`), `_hc_mix_stats_partial_kernel` (`M`) and `_hc_mix_stats_bf16x3_kernel` (`M`). Specialization is not useful since it's only used in the bounds check and per-row offsets.

## Accuracy Tests

Outputs of all three wrappers are bitwise identical to main for m in {1, 16, 17, 33, 48, 128, 145, 4000, 4096, 8192, 8193}.
