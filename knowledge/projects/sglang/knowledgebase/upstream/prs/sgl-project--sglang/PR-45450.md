# [Perf] [NVIDIA] dspark: Move the host work between DSv4.1 decode graphs into the graphs for the megakernel path

[Upstream PR](https://github.com/sgl-project/sglang/pull/45450) · state: closed · merged: True

## Original PR description

## Motivation

DeepSeek-V4.1-Flash low-latency decode on GB300 (TP4, DSpark speculative decoding). With the NVIDIA megakernel plugin enabled (`--enable-nvidia-megakernel`), the GPU part of each decode step gets short enough that SGLang's host-side work between graphs (input preparation, verify metadata, accept bookkeeping, KV commits) becomes a large share of the step. This PR moves that work into the existing CUDA graphs, into fewer launches, or off the critical path.

Most changes are behind environment flags that default to off. Two DSpark-only changes are on by default: the draft sampling-param restaging (1) and the draft runner's metadata prep through the glue graph where it applies (2). The two changes that reach beyond DSpark are opt-in: the MoE output-shape fix (3, `SGLANG_OPT_MXFP4_DEFERRED_FINALIZED_SHAPE`) and the CUDA graph fill fast paths (7, `SGLANG_OPT_CUDA_GRAPH_FILL_FAST_PATH`).

## Modifications

One commit per change:

1. **DSpark draft:** restage the draft graph's sampling params only when they change.
2. **DSpark draft runner:** prepare its attention metadata through the glue graph.
3. **MXFP4 trtllm-gen MoE** (`SGLANG_OPT_MXFP4_DEFERRED_FINALIZED_SHAPE`): pass the finalized output shape on deferred-finalize calls above 32 rows, so decode batches hit the tuned tactic instead of the default tile. Off keeps main's 97-384-row window.
4. **Fused static accept tail** (`SGLANG_DSPARK_FUSED_ACCEPT_TAIL`): the static greedy accept and its bookkeeping in one kernel.
5. **One-launch step inputs** (`SGLANG_OPT_DSV41_DSPARK_PREPARE_INPUTS_ONCE`, `SGLANG_OPT_DSV41_DSPARK_MID_FOLD`): the step inputs in one launch; the verify ids come from the draft graph's tail.
6. **Deferred draft context-KV commit** (`SGLANG_DSPARK_DEFER_CONTEXT_KV`): the static verify's draft context-KV commit moves to the next draft graph.
7. **CUDA graph replay fill fast paths** (`SGLANG_OPT_CUDA_GRAPH_FILL_FAST_PATH`): skip the padding reset of an unpadded fill; copy one dense integer dtype pair with one foreach launch.
8. **Target verify metadata through the glue graph** (`SGLANG_OPT_DSV41_TARGET_VERIFY_METADATA_GLUE`).
9. **Engram history commit and block accept lengths inside the verify graph** (`SGLANG_OPT_DSV41_POST_FORWARD_CUDA_GRAPH`).
10. **Draft graph metadata on a side stream** (`SGLANG_OPT_DSV41_DSPARK_DRAFT_PREP_FORK`).
11. **Seq lens and bonus relayed from the verify graph** (`SGLANG_OPT_DSV41_DSPARK_POST_FOLD`).
12. **The deferred context KV projected inside the verify graph**, so that only its stores are deferred.
13. **Simulated bonus:** reads the shared accept length as a stride-0 view. Simulated acceptance only.
14. **The deferred commit's staging in one launch** (`SGLANG_OPT_DSV41_DSPARK_ONE_LAUNCH_COMMIT_STAGE`).
15. **Target verify metadata built beside the draft graph** (`SGLANG_OPT_DSV41_TARGET_METADATA_EARLY`; enabled only when the runner's conditions hold, including the metadata glue graph).
16. **A pre-planned verify replay skips its input re-copies** (`SGLANG_OPT_DSV41_DSPARK_SKIP_PREFILLED_INPUTS`).
17. **Skip the replay ForwardBatch view** once the metadata glue graph is captured (`SGLANG_OPT_SKIP_GLUED_REPLAY_VIEW`).
18. **Draw the simulated acceptance before the draft launch** (`SGLANG_OPT_DSV41_DSPARK_SIM_DRAW_AHEAD`). Simulated acceptance only.
19. **Block-wise rejection sampling for the sampled verify accept** (`SGLANG_OPT_DSV41_BLOCKWISE_REJECTION`).
20. **A CUDA graph for the static verify's temperature-sampling accept** (`SGLANG_OPT_DSV41_SAMPLING_ACCEPT_GRAPH`): the sampling accept, its TP broadcast and the KV / engram commits replay as one graph launch.

## Speed Tests and Profiling

GB300, TP4, DeepSeek-V4.1-Flash. AgentX (InferenceX agentic traces), concurrency 1, 3,600 s, synthetic acceptance 3.51 with the stock accept sampling (the simulated-acceptance shortcut is reverted in every arm). All arms run on SGLang main `f0b65907227` with the same image and settings, and are compared on the same 220 requests. TPS/User = 1 / ITL.

| configuration | TPS/User P50 | TPS/User P90 | decode step p50 (> 256K) |
|---|---|---|---|
| main | 694.0 | 676.1 | 5.06 ms |
| main + this PR (commits 1-18) | 709.7 (+2.3%) | 694.1 (+2.7%) | 4.95 ms |
| main + megakernel plugin (sgl-project/sgl-nvidia-mega#18, default slots) | 762.2 (+9.8%) | 717.4 (+6.1%) | 4.57 ms |
| main + this PR (commits 1-18) + plugin (#18, 42 slots) | 952.0 (+37.2%) | 902.2 (+33.4%) | 3.66 ms |
| main + this PR (all 20 commits) + plugin (#18, 42 slots) | 995.7 (+43.5%) | 972.8 (+43.9%) | 3.54 ms |

Rows with this PR were measured with the changes listed above enabled, including `SGLANG_OPT_MXFP4_DEFERRED_FINALIZED_SHAPE=1` and `SGLANG_OPT_CUDA_GRAPH_FILL_FAST_PATH=1` (on by default at measurement time). With the plugin held fixed, this PR adds +30.6% P50 / +35.6% P90 (rows 3 and 5). Rows 4 and 5 also enable three opt-in plugin slots. Without the plugin, the host work this PR removes is hidden behind the longer GPU step, so the PR alone moves little. Rows 1-3 repeat on a second cluster within 0.3% at P50.

Known interaction: with `NCCL_CUMEM_ENABLE=1` and `NCCL_MNNVL_ENABLE=1` set in the environment, the deferred context-KV commit (`SGLANG_DSPARK_DEFER_CONTEXT_KV`) adds a 45-105 ms stall before the last streamed token of requests above 256K tokens (87 / 209 such requests in one AgentX run). The stall grows with context length. With both NCCL variables at 0, no request stalls (0 / 209) and P90 rises 4.5%. The table above was measured without these variables.

**Issue**

`atexit.register(self._log_draft_glue, ...)` holds a strong reference to this runner until the process exits. The draft glue is on by default for the DSpark draft runner, so that runner, its CUDA graphs and its buffers can never be freed.

**Example**

A weight update with `recapture_cuda_graph=True` calls `ModelRunner.recapture_decode_cuda_graph`, which drops the old runner and captures a new one. The old runner stays alive through the atexit entry, so each recapture keeps another set of graphs in GPU memory and adds another shutdown log.

**Fix**

Remove the atexit hook; `_maybe_log_draft_glue` already logs the counts every 1000 steps. If the shutdown line is needed, register through a `weakref.WeakMethod`.
