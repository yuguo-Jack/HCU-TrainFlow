# [Fix] hicache: Support flat pages for asymmetric K/V host pools (head_dim != v_head_dim)

[Upstream PR](https://github.com/sgl-project/sglang/pull/44774) · state: open · merged: False

## Original PR description

## Motivation

HiCache's `file` storage backend (like the other flat-page L3 backends) moves one page between the host pool and storage through `get_data_page` / `get_dummy_flat_data_page` / `set_from_flat_data_page`. For models with `head_dim != v_head_dim` (e.g. MiMo-V2, K 192 / V 128) `AsymmetricMHATokenToKVPoolHost` raises `NotImplementedError` in all three. There is no start-up guard and backups/prefetches catch the exception, so with `--hicache-storage-backend file` the L3 tier silently stores nothing and the log fills with tracebacks. The error message also names hf3fs/eic/nixl only, although `file` takes the same path.

## Modifications

- `AsymmetricMHATokenToKVPoolHost`: a flat page is K of the page flattened, followed by V of the page flattened. Since K and V live in two buffers with different head dims, `get_data_page` returns a copy (`torch.cat`); `set_from_flat_data_page` splits it back and rejects a page of the wrong size. Supported for the two layouts the class already supports (`page_first`, `page_first_direct`); `flat=False` still raises.
- `_flat_page_unsupported` message updated (now only for `flat=False`).
- New CPU test `test/registered/hicache/test_asymmetric_mha_flat_page.py`: round-trips pages through the real `HiCacheFile` backend for both layouts, restoring into different slots, bit-exact; plus wrong-size and `flat=False` rejection. It fails on current main (3 failed) and passes with this change.

## Accuracy Tests

Does not change model forward code. Run in production-like conditions on our side with the same patch on `lmsysorg/sglang:dev` (nightly 684fea8a), MiMo-V2.6-Pro-MOPD, TP4 on 4× B300, `--enable-hierarchical-cache --hicache-storage-backend file` (hybrid SWA pool, DFlash draft pool):
- prompts of 56k / 250k / 800k tokens restored from disk after an 8M-token flood evicted them from GPU and host memory; answers identical to a cold run (temperature 0, text and token count), 0 tracebacks;
- reasoning benchmarks on the same deployment (AIME 2025+2026, GPQA Diamond, MMLU-Pro, LiveCodeBench, IFEval, HLE-Verified Gold, ARC-AGI-2, …) over ~14 h with the disk tier on: no errors attributable to the cache.

## Speed Tests and Profiling

Not a hot path for models that do not use the file backend. With it, restore times on the setup above (cold / host RAM / disk, seconds): 56k 4.13 / 0.47 / 2.2; 250k 10.7 / 0.56 / 6.1–7.1; 800k 55.8 / 1.37 / 19.5–19.9.
