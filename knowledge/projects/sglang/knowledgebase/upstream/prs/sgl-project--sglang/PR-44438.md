# [Fix] deterministic: Validate the per-phase attention backends

[Upstream PR](https://github.com/sgl-project/sglang/pull/44438) · state: closed · merged: True

## Original PR description

## Motivation

Deterministic mode checked only `--attention-backend`, but this does not guarantee that prefill and decode attention are deterministic: `--prefill-attention-backend` and `--decode-attention-backend` override it for their phase, and they were not checked. This PR adds the check for both flags. Without it, deterministic mode could be on while prefill or decode used a backend that is not deterministic, with no warning.

For example, on MI350X this starts without an error and runs AITER's paged-attention kernels for decode, although `aiter` is not on the deterministic list:

```bash
python3 -m sglang.launch_server --model-path Qwen/Qwen3-8B \
  --attention-backend triton --decode-attention-backend aiter \
  --enable-deterministic-inference
```

The same applies on every platform and to any backend outside the list (for example `flashmla` or `trtllm_mha` for one phase on NVIDIA).

**Which models this affects.** All of them: the check is model-independent. It matters wherever the per-phase flags are set: AMD serving configurations use them to pick AITER per phase (the MI35x configuration for Qwen3.8 sets `--prefill-attention-backend aiter --decode-attention-backend aiter`), and some model defaults set them (Kimi-K3, below). Without this check, such a configuration silently loses the deterministic guarantee.

AITER decode attention is in fact batch-invariant on gfx950; #44489 allows it there on top of this PR, with the evidence. This PR only makes deterministic mode check the per-phase flags at all.

## Modifications

- `_deterministic_attention_backend` (in `arg_groups/overrides.py`): in deterministic mode, also check `prefill_attention_backend` and `decode_attention_backend` against `DETERMINISTIC_ATTENTION_BACKEND_CHOICES` when they are set. The error names the flag and the backend.
- `test_model_overrides.py`:
  - a non-deterministic backend in either per-phase flag is refused, even when `--attention-backend` is on the list;
  - per-phase backends that are on the list are accepted.
- Unchanged:
  - deterministic mode off;
  - per-phase flags unset (the existing fallback for `--attention-backend` is untouched);
  - which backends are on the list.
- Scope: the check runs where deterministic mode is resolved, so it covers per-phase backends that are set explicitly or by model-specific defaults before it. Two later automatic choices are not covered here:
  - the NVFP4 KV-cache prefill/decode pair;
  - CuteDSL MLA's `trtllm_mla` prefill pairing.

  Both are tied to opt-in features (NVFP4 KV cache, CuteDSL MLA decode). Covering them needs a check after those passes; I'd leave that to a follow-up.
- Behaviour change: configurations that combine `--enable-deterministic-inference` with a per-phase backend outside the list now fail at startup instead of running without the deterministic guarantee. This includes model defaults that set such a backend, for example Kimi-K3's backends for decode context parallelism.

## Accuracy Tests

No numerical change: this only refuses configurations at startup.

Unit tests, `python3 -m pytest test/registered/unit/test_model_overrides.py -k deterministic` (MI350X, `rocm/sgl-dev:v0.5.21-rocm724-mi35x-20261013`): before, the new refusal test fails for both flags (2 failed, 5 passed); after, 5 passed.
