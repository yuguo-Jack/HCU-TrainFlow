# [Perf] spec: Default `SGLANG_SPEC_TP_SYNC` to `init`

[Upstream PR](https://github.com/sgl-project/sglang/pull/48111) · state: closed · merged: True

## Original PR description

## Motivation

`SGLANG_SPEC_TP_SYNC` defaults to `all`: on every speculative step, rank 0 broadcasts its draft, plan, accept, and target decisions to the TP group (#33614), `gamma + 3` small broadcasts per DSpark decode step. They guard against TP ranks committing different tokens and then deadlocking in a collective.

The divergence they guard against has a root cause, fixed in #38565: the top-p / top-k renorm kernels summed with float atomics, so ranks renormalizing identical logits could differ in the last bits, and a sampling coin landing in that gap committed different tokens. With every broadcast off, the old kernels hung in every run of #38565's repro and the deterministic ones never diverged. Since #38565, renorm is bit-identical across ranks at `tp_size > 1`, so every per-step decision is computed alike on every rank (identical logits, counter-based draft / rejection noise keyed by the server seed, and the torch RNG seeded alike on every rank). The per-step broadcasts now only cost time, and deployments turn them off by hand (`SGLANG_SPEC_TP_SYNC=rng,-dspark-accept-sample`).

## Modifications

- `SGLANG_SPEC_TP_SYNC` defaults to `init`. Only the two startup memory probes stay synced (`dspark-mem`, `dflash-mem`): free memory differs per rank and decides which draft CUDA graphs are captured, so it stays reduced to the group minimum. Every per-step site is off. The mechanism, presets, and sites are unchanged; `all` restores the previous behavior and is the first thing to try if TP ranks still diverge.
- The broadcast sites are logged at startup only when `SGLANG_SPEC_TP_SYNC` is set, so a default launch no longer warns.
- `SGLANG_SIMULATE_ACC_LEN` stays safe under the new default: since #48298 its draws come from a server-seeded generator, so ranks agree without the accept broadcast.
- Model overrides that set the variable themselves (MiniMax-M3.1 DSpark: `rng`) are unchanged.

## Accuracy Tests

No change in what is computed: a broadcast that is now skipped copied values every rank already held.

- DSpark smoke at TP=2 with the variable unset, overlap scheduling on (`Qwen/Qwen3-14B` + `deepseek-ai/dspark_qwen3_14b_block7`, flags of `test_basic_sanity_dspark.py`, conc 32, 512 in / 512 out):

| sampling | requests (reqs) | succeeded (reqs) | accept length |
|---|---|---|---|
| greedy | 128 | 128 | 4.46 |
| temperature 1.0 | 256 | 256 | 4.15 |
| temperature 0.7, top_p 0.95, top_k 20 | 256 | 256 | 4.22 |
| temperature 1.0, top_p 0.95 | 1024 | 1024 | 4.18 |

`/health_generate` answered after every run; no watchdog, NCCL timeout, or traceback in the server logs. Simulated acceptance with the per-step sites off is covered in #48298.

## Speed Tests and Profiling

Not measured separately: the default drops the per-step speculative broadcasts (`gamma + 3` per DSpark decode step).
