# [Fix] function_call: Flush buffered text at stream end in MiMo, Step3, KimiK2, LFM2 detectors

[Upstream PR](https://github.com/sgl-project/sglang/pull/41909) · state: open · merged: False

## Original PR description

## Motivation

Streaming tool-call detectors hold text back in `self._buffer` while waiting
for a closing marker. `BaseFormatDetector.finish()` returns an empty result
by default, so when the stream ends with an incomplete marker still buffered,
the held-back text is silently dropped.

This is the same loss pattern as #41821, present here in four more detectors:

- `MiMoDetector.parse_streaming_increment` keeps `current_text[start:]` (from
  `bot_token` on) in `_buffer` when `eot_token` has not arrived;
- `Step3Detector` keeps the in-progress tool block in `_buffer`;
- `KimiK2Detector` breaks with the partial call (from `tool_call_begin` on)
  still in `_buffer`;
- `Lfm2Detector` keeps `self._buffer[bot_pos:]` when `eot_token` is missing.

None of them overrides `finish()`, so a stream that ends mid-marker loses the
buffered text:

```python
d = MiMoDetector()
d.parse_streaming_increment("hello <tool_call>get_weather('par", [])
d.finish([])  # returns empty; "<tool_call>get_weather('par" is lost
```

## Changes

Add a `finish()` override to each detector that flushes `_buffer` as normal
text, matching the existing pattern in `IQuestQ1Detector.finish`. Normal
streams are unaffected: `finish()` stays a no-op when `_buffer` is empty.

## Tests

Offline unit tests (no server, no model loading) for each detector cover:
- partial tool call at stream end: `finish()` releases the buffered text;
- clean stream: `finish()` returns an empty result;
- fully parsed stream: no duplication at `finish()`.

All pass locally (`pytest test/registered/unit/function_call/test_{mimo,step3,kimik2,lfm2}_detector.py`).
