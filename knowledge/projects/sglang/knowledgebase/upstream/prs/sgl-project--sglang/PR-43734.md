# [DeepSeek-V4.1] Admit the NIXL transfer backend for DSpark PD

[Upstream PR](https://github.com/sgl-project/sglang/pull/43734) · state: open · merged: False

## Original PR description

## Motivation

`validate_deepseek_v41_features` rejects every DeepSeek-V4.1 PD deployment that runs DSpark unless `--disaggregation-transfer-backend mooncake` (added in #38798 without a stated reason). On GKE A4X (GB300, RoCE over DRA-attached ConnectX-8 rails) Mooncake's RDMA path fails on every device pair ("Local-side RDMA failure detected", same rail included), while NIXL is the transport every SGLang PD deployment on that platform runs. The check therefore blocks DSV4.1 PD there entirely, and dropping DSpark to get past it costs the speculative decoding.

## Modifications

The transport clause of the check accepts `nixl` as well as `mooncake`; the static-verify, prefill-CP, attn-CP and DCP clauses and the rest of the message are unchanged. No transfer code changes: the DSpark aux (first token, draft state, hidden states) goes through the prefill-side aux WRITE path in `disaggregation/common` that both backends implement, and the NIXL connector already tracks aux/state notifications per component.

Adds `test/registered/unit/server_args/test_dsv41_dspark_pd_transport.py` (CPU): `nixl` and `mooncake` pass, another backend still raises.

## Accuracy Tests

DeepSeek-V4.1-Flash 1P1D (prefill TP4 + decode TP4, DSpark block size 3, static verify, NIXL with GPUDirect RDMA) on GB300: needle prompts at 4.5k / 11k / 40k and greedy 24k / 40k / 86k / 300k / 763k-token prompts return the expected key with text matching the Mooncake-free aggregated run; a six-rung real-trace replay (300 s per rung, ISL median 6.7k, p90 127k) completed 100% of requests at every rung; the same configuration has served shadow production traffic for three days. Not exercised: NIXL with DP attention, and NIXL host staging (not in main).

## Speed Tests and Profiling

No kernel or scheduling change; the gate only decides whether the deployment starts.
