# [DeepSeek-V4.1] Admit the NIXL transfer backend for DSpark PD

[Upstream PR](https://github.com/sgl-project/sglang/pull/43734) · state: closed · merged: True

## Original PR description

## Motivation

`validate_deepseek_v41_features` rejects every DeepSeek-V4.1 PD deployment that runs DSpark unless `--disaggregation-transfer-backend mooncake` (added in #38798 without a stated reason). On GKE A4X (GB300, RoCE over DRA-attached ConnectX-8 rails) Mooncake's RDMA path fails on every device pair ("Local-side RDMA failure detected", same rail included), while NIXL is the transport every SGLang PD deployment on that platform runs. The check therefore blocks DSV4.1 PD there entirely, and dropping DSpark to get past it costs the speculative decoding.

## Modifications

The transport clause of the check accepts `nixl` as well as `mooncake`; the static-verify, prefill-CP, attn-CP and DCP clauses and the rest of the message are unchanged. No transfer code changes: the DSpark aux (first token, draft state, hidden states) goes through the prefill-side aux WRITE path in `disaggregation/common` that both backends implement, and the NIXL connector already tracks aux/state notifications per component.


## Accuracy Tests

DeepSeek-V4.1-Flash 1P1D on GB300 (prefill TP4 + decode TP4, DSpark block size 3, static verify, `--disaggregation-transfer-backend nixl` with GPUDirect RDMA), this branch's SGLang (Oct-8 nightly 7760d526 + the one-line change), `sgl-eval` 0.1.2 run from inside the prefill pod against the deployment's OpenAI endpoint:

```
sgl-eval run gsm8k  --base-url http://<frontend>/v1 --model deepseek-ai/DeepSeek-V4.1-Flash \
  --temperature 1.0 --top-p 0.95 --thinking --num-threads 64 --max-tokens 16384
sgl-eval run aime26 --base-url http://<frontend>/v1 --model deepseek-ai/DeepSeek-V4.1-Flash \
  --temperature 1.0 --top-p 0.95 --thinking --num-threads 64 --max-tokens 131072 --n-repeats 4
```

| benchmark | result | notes |
|---|---|---|
| GSM8K (1,319, single-shot) | **97.04%** | stop rate 100%, 0 truncated, avg 250 output tokens (241 thinking) |
| AIME 2026 (30 x 4 repeats), run 1 | **pass@1 93.33% ± 2.72**, pass@4 96.67%, majority@4 96.67% | avg 9.5k output tokens |
| AIME 2026 (30 x 4 repeats), run 2 | **pass@1 95.00% ± 5.77** | |

The only misses in both AIME runs are problem 14, whose thinking exceeds the deployment's 65,536-token output cap (3 of its 4 samples stop at exactly 65,536 generated tokens with no answer; the sample that finished at 54k answered correctly). That cap is the serving config, not the transport. Error rate 0% on every run; no KV-transfer failures on the prefill or decode workers during the evals. The same configuration has served shadow production traffic for three days. Not exercised: NIXL with DP attention, and NIXL host staging (not in main).
