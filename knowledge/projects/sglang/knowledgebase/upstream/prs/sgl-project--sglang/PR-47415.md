# [Perf] detokenizer: Send each step's output ids as one flat column with row offsets

[Upstream PR](https://github.com/sgl-project/sglang/pull/47415) · state: closed · merged: True

## Original PR description

- `BatchTokenIDOutput` and `BatchStrOutput` carry a step's output ids as one flat `array("q")` (`output_ids_flat`) plus row offsets (`output_ids_offsets`) instead of one array per row, so each IPC hop encodes two objects per batch instead of one per request.
- `row_output_ids(output, i)` reads a row and `flatten_output_ids(rows)` builds the two columns (`io_struct.py`). The output streamer, the detokenizer, the tokenizer manager and the multi-tokenizer split go through them; the split rebuilds the columns for each worker's rows.
- The Rust server push sends `output_ids_flat` as one buffer and derives the per-row lengths from the offsets.
- `test_multi_tokenizer` thresholds are recalibrated for its 2-GPU DP-attention config from CI runs on H100 and MI300: median ITL under 11 ms, MMLU above 0.72, CUDA `est_time` 310 s.

No behavior change: every reader gets the same ids for each row.
