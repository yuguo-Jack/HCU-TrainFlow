# [SMG] Preserve Responses payloads when forwarding to HTTP workers

[Upstream PR](https://github.com/sgl-project/sglang/pull/42735) · state: open · merged: False

## Original PR description

## Motivation

`/v1/responses` requests with namespace tools or `additional_tools` are rejected by the gateway before reaching HTTP workers that support them. Even accepted requests are deserialized into `ResponsesRequest` and serialized again, dropping unknown fields and inserting sampling defaults the client did not send.

## Modifications

Keep the request JSON intact for regular and PD HTTP forwarding. Parse only `model`, `stream`, and `background` for routing; let the worker validate the rest. PD still adds bootstrap metadata and rejects detached background requests.

Routes that implement Responses themselves, including gRPC and OpenAI-backed routes, retain typed parsing and validation. Cache-aware routing reads text from the full input, including tool calls and outputs.

Engine support for `additional_tools` is covered separately by #41178.

## Tests

The new integration test runs through the gateway HTTP handler, router selection, and local HTTP workers in regular and PD modes. It compares forwarded bodies and returned JSON/SSE, including namespace calls, array tool outputs, `additional_tools`, `agent_message`, and JSON-schema output requests. It also checks malformed routing fields and detached background rejection.

The regression fails on the base commit because fields are dropped and defaults are inserted.

28 tests passed: 2 request-wrapper unit tests, 17 Responses API tests, and 9 PD routing tests. Pre-commit passed twice. `cargo clippy --all-targets --all-features -- -D warnings` passed.
