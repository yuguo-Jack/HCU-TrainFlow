# [DSv4.1] Read FP8 caches directly on long-prefix prefill steps

[Upstream PR](https://github.com/sgl-project/sglang/pull/43498) · state: open · merged: False

## Original PR description

## Motivation

DeepSeek-V4.1 sparse prefill dequantizes the cached compressed KV into a bf16 workspace on every step. On a prefix-cache hit this cost grows with the cached prefix. The existing direct path (FlashMLA reading the FP8 paged cache) costs per query row instead, but is slower on cold chunks. Choosing the path per step from the batch shape makes long-prefix hits about 6% faster and leaves cold prefill unchanged.

Direct reads on prefill also reach batch sizes where FlashMLA's schedule precompute fails to launch: its 48 KiB guard ignores the kernel's static shared memory, so on a 152-SM GPU batches of 2,212–2,214 rows pass the guard and fail.

```bash
python3 -m sglang.launch_server \
  --model-path deepseek-ai/DeepSeek-V4.1-Flash --trust-remote-code \
  --tp 4 --ep-size 4 --mem-fraction-static 0.8 \
  --speculative-algorithm DSPARK --speculative-dspark-block-size 5 \
  --max-running-requests 64 --chunked-prefill-size 8192
python3 repro.py hit 65536 16   # repro.py below
```

```python
# usage: python3 repro.py cold|hit TOKENS CONCURRENCY
import json, os, random, statistics, sys, time, urllib.request
from concurrent.futures import ThreadPoolExecutor

mode, length, concurrency = sys.argv[1], int(sys.argv[2]), int(sys.argv[3])
url = os.environ.get("URL", "http://127.0.0.1:30000") + "/generate"
rng = random.Random(20261009)
prefix = [rng.randrange(1000, 120000) for _ in range(length)]

def request(ids):
    body = {"input_ids": ids, "stream": True,
            "sampling_params": {"temperature": 0, "ignore_eos": True,
                                "max_new_tokens": 8 if mode == "hit" else 1}}
    req = urllib.request.Request(url, json.dumps(body).encode(),
                                 {"Content-Type": "application/json"})
    start = time.perf_counter()
    first = None
    with urllib.request.urlopen(req, timeout=300) as response:
        for line in response:
            if line.startswith(b"data:") and first is None:
                first = time.perf_counter() - start
    return first

def wave():
    prompts = []
    for _ in range(concurrency):
        new = [rng.randrange(1000, 120000)
               for _ in range(1024 if mode == "hit" else length)]
        prompts.append(prefix + new if mode == "hit" else new)
    with ThreadPoolExecutor(concurrency) as pool:
        return list(pool.map(request, prompts))

if mode == "hit":
    request(prefix)
for _ in range(2):
    wave()
start = time.perf_counter()
times = [value for _ in range(5) for value in wave()]
elapsed = time.perf_counter() - start
print("TTFT p50 %.2f ms" % (statistics.median(times) * 1000))
if mode == "cold":
    print("input %.0f tok/s" % (5 * concurrency * length / elapsed))
```

## Modifications

- Read the FP8 cache directly when the batch's cached prefix is at least *k* × its extend rows (batch totals): *k* = 5 on eager steps, 8 inside breakable prefill CUDA graphs. Defaults apply on SM100 only, where they were measured; other platforms default to 0 (unchanged behavior). Override with `SGLANG_DSV4_SPARSE_PREFILL_DIRECT_PREFIX_PER_ROW` / `..._GRAPH`; 0 keeps the workspace.
- **Behavior change:** on SM100, forcing the workspace with `SGLANG_OPT_FLASHMLA_SPARSE_PREFILL=1` now also needs both thresholds set to 0.
- The per-step choice lives in `DSV4Metadata`. Sparse page indices are built only when a step can read direct (always inside breakable prefill graphs, which reuse one captured indexer).
- `sched_meta_fits()` counts the kernel's static shared memory, so oversized schedules take the existing fallback. Related: #40429 adds the same size check without the static part.
