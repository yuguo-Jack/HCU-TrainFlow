# [Fix] diffusion/bcg: Warm up LTX-2 two-stage at the output resolution

[Upstream PR](https://github.com/sgl-project/sglang/pull/47474) · state: closed · merged: True

## Original PR description

## Motivation

`LTX2TwoStagePipeline` with `Lightricks/LTX-2.5-Diffusers` cannot start with default flags. sgl-project/sglang#45977 turns BCG on by default for this pipeline, and the BCG warmup resolution is seeded from the model's sampling default, 960x544. That is LTX-2.5's stage-1 size, but a two-stage request carries the output resolution and `LTX2HalveResolutionStage` rejects anything not divisible by 64, so the warmup request fails:

```
[Diffusion BCG] enabled by default for LTX2TwoStagePipeline
[Diffusion BCG] --warmup-resolutions unset; capturing the model default 960x544.
ValueError: LTX-2 two-stage requires resolution divisible by 64, got (544x960).
Server warmup failed; aborting startup
```

The non-BCG server warmup path already aligns to 64 through `_resolve_representative_warmup_resolution`; only the BCG branch of `_resolve_default_warmup_resolution` returns the sampling default as is.

## Modifications

`warmup_request_builder.py`: add `_two_stage_request_resolution` and use it where `_resolve_default_warmup_resolution` returns the sampling default as is. For `LTX2TwoStage*` pipelines, a default the halving rejects is treated as the stage-1 size and mapped to twice its size (960x544 -> 1920x1088).

Unchanged:
- explicit `--warmup-resolutions`
- one-stage pipelines
- defaults that already pass the alignment check (LTX-2 768x512, LTX-2.3 HQ 1920x1088)
- a default that doubling cannot fix (for example an explicit `--warmup-sampling-params` override) is left as written and still fails loudly

That early return also serves warmup that is not server-based, so that path gets the same mapping.

Tests: one new case in `test_cfg_parallel_warmup.py` for the default resolution of each pipeline above, and one extra assertion in `test_server_args.py::TestBreakableCudaGraphDefault::test_ltx25_distilled_two_stage_serving_turns_bcg_on` that the auto-enabled path ends up with `warmup_resolutions == ["1920x1088"]`.

## Accuracy Tests

No change to model outputs: only the shape the BCG warmup captures at startup changes.

Unit tests (1xH200 devbox, this commit on top of main 9691e711cd0; `test_cfg_parallel_warmup.py` + `test_server_args.py`):
- with `warmup_request_builder.py` reverted to main: the two new assertions fail (5 failed)
- with this change: 292 passed
- the 3 remaining failures are identical on main and here. Without an HF token `test_cfg_parallel_warmup.py` cannot be collected (importing `gpu_cases` resolves every case's gated model info), so I stubbed `gpu_cases` with empty lists, which breaks 2 tests that index it; the third asserts no warnings and trips on a diffusers Flax deprecation warning in that image. I did not run them with a token.

End to end with the reported command, default flags (`sglang serve --model-path Lightricks/LTX-2.5-Diffusers --num-gpus 2 --model-type diffusion --warmup-mode server --pipeline-class-name LTX2TwoStagePipeline --dit-layerwise-offload false --performance-mode speed --enable-torch-compile false --ulysses-degree 2`), then one `POST /v1/videos` at 1920x1088, 121 frames, 8 steps, seed 42:

| | main | this PR |
|---|---|---|
| 2xH200 | `ValueError ... got (544x960)`, `Server warmup failed; aborting startup` | BCG captures 1920x1088, request completes, ffprobe 1920x1088 / 121 frames |
| 1xH200 (same command without `--ulysses-degree`) | same failure | request completes, ffprobe 1920x1088 / 121 frames |

## Speed Tests and Profiling

Not a performance change. Each server served a single request, so the latencies from those runs (9.3 s on 2xH200, 15.4 s on 1xH200) are not benchmark numbers.

Not verified: a request that omits width/height would use the same 960x544 sampling default and, reading the code, would hit the same halving check on this pipeline. I did not run it and did not change request-side defaults here.
