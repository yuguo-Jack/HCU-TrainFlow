# [Fix] scheduler: Finish aborted running requests during an in_place pause

[Upstream PR](https://github.com/sgl-project/sglang/pull/46459) · state: open · merged: False

## Original PR description

## Motivation

Fixes #44835.

`pause_generation(in_place)` followed by `pause_generation(abort)` while a request is generating never returns, `continue_generation` then blocks too, and the scheduler watchdog eventually kills the server.

Root cause:

1. `Scheduler.abort_request` only sets `req.to_finish` on running requests; the next forward step turns that into a finish, frees the KV and streams the final output.
2. While the engine is paused, the event loop runs `ingest_requests()` and `continue`s, so no forward step runs. In `in_place` mode the requests stay in `running_batch`, so they are never finished.
3. Their `/generate` handlers therefore keep holding `model_update_lock` as readers, and `TokenizerManager.pause_generation(abort)` loops until that lock is free, while holding `is_pause_cond`.
4. `continue_generation` needs `is_pause_cond` to resume the scheduler, so nothing can break the wait.

The other orders do not hang: `abort` mode never pauses the scheduler, and `retract` moves the running requests back to the waiting queue, where an abort finishes them immediately.

## Modifications

- `Scheduler.abort_request`: when the engine is paused, matched running requests are finished immediately in `_finish_aborted_reqs_while_paused`, using the same steps as an abort handled inside a forward step:
  - `update_finish_state()` sets the finish reason from `to_finish`;
  - `release_uncommitted_req` frees the KV (including the hisparse, PD decode offload and MLX paths);
  - `output_streamer.stream_output` sends the final output; this marks it delivered, so a result still queued by the overlap scheduler skips the request instead of committing a token or streaming it twice;
  - `running_batch.filter_batch()` drops the finished requests, so the paused engine is really idle (e.g. for `flush_cache` during a weight update).

  The unpaused path is unchanged. Requests that were not aborted keep their KV and continue after resume, which preserves the `in_place` contract.
- `SchedulerBatchResultProcessor._handle_sampling_mask_abort` is renamed to the public `release_uncommitted_req` so the scheduler can reuse it. The body is unchanged.
- Tests in `test/registered/unit/managers/test_scheduler_pause_generation.py`:
  - an abort-all during an `in_place` pause finishes, releases and reports the running request;
  - an abort by rid finishes only the matching request and leaves the other one in the batch.

  Both fail on `main` and pass with the fix.

Alternatives considered:

- Running a forward step while paused: rejected, since a weight update may be in progress.
- Retracting before aborting: works, but it evicts requests that were not aborted when aborting by rid.
- Releasing `is_pause_cond` in the TokenizerManager loop: only hides the symptom; the requests stay unfinished.

Known limitations, left for follow-ups:

- A request in the middle of chunked prefill keeps the old path, since its middle-chunk accounting drains on resume.
- Beam-search groups are not finished early.
- The watchdog killing the server during long `in_place` pauses is a separate issue.

## Accuracy Tests

No change to model outputs: this only affects requests aborted while the engine is paused.

End-to-end check on an RTX 6000 Ada with `Qwen/Qwen3-0.6B --watchdog-timeout 60`, using the repro script from #44835:

| build | `pause in_place` | `pause abort` | `continue_generation` | result |
|---|---|---|---|---|
| `main` | 200, 2 ms | timeout (30 s) | timeout (30 s) | deadlock, watchdog kills the server after 153 s |
| this PR, overlap scheduler | 200, 2 ms | 200, 1.0 s | 200, 1 ms | ok, healthy 30 s later |
| this PR, `--disable-overlap-schedule` | 200, 2 ms | 200, 1.0 s | 200, 1 ms | ok, healthy 30 s later |

The 1.0 s is the TokenizerManager's existing poll interval in the abort loop.

All pause-mode pairs, with and without the overlap scheduler, with `SGLANG_ENABLE_STRICT_MEM_CHECK_DURING_BUSY=1` and `SGLANG_CHECK_KV_PAGE_INVARIANTS=1`:

| sequence | stream result |
|---|---|
| in_place, abort | abort |
| in_place, retract | length (2000 tokens) |
| retract, abort | abort |
| abort, abort | abort |
| retract, retract | length (2000 tokens) |
| in_place, in_place | length (2000 tokens) |
| abort, in_place | abort |
| two requests, in_place, `/abort_request` one rid | aborted one: abort; the other resumes to length (2000 tokens) |

Server logs: no tracebacks, no memory-check failures, and no `Received output for ... state was deleted` warnings.
