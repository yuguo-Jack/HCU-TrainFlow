# [Doc] sgl-router: Rewrite README and add architecture guide

[Upstream PR](https://github.com/sgl-project/sglang/pull/43592) · state: closed · merged: True

## Original PR description

## Motivation

The sgl-router README had grown to ~740 lines mixing quick start, routing design and per-feature detail, and `POLICY_DESIGN.md` mixed target design with current behavior and had drifted from the code. This PR gives the router a short README, a separate architecture guide for `--chat-routing reorg`, and keeps the detailed feature reference in its own file.

## Modifications

- **`README.md`** rewritten (~350 lines): architecture overview with a deployment diagram, quick start, key endpoints and flags, routing policies and admission caps, deployment examples, how to add a policy, and a short list of other features. Each feature links to its full description in `REFERENCE.md`.
- **`ARCHITECTURE.md`** (new, replaces `POLICY_DESIGN.md`): deployment, request lifecycle, load-aware routing (admission filters engines before power-of-two sampling), cache- and session-aware routing (prefer vs balanced), and annotated CLI and bucket-file configuration examples.
- **`REFERENCE.md`** (new): the detailed sections of the old README, taken verbatim from current main (PD version groups, external indexer, LoRA cache identity, KV-event gap replay, pending prefixes, peer bootstrap, bucket file membership, optional tokenizer, DP-rank routing incl. `--dp-rank-policy`, retries, `--api-key`, fleet-wide sampling contract, chat rendering, `/generate`, OpenAI over `/generate`, embeddings/classify/completions/rerank, Anthropic Messages, DeepSeek V4/V4.1, GLM-5.3, Qwen3.8, Kimi-K3, HTTP/2, native gRPC, `cache_aware_zmq` upgrade notes).
- **`POLICY_DESIGN.md`** removed; `policies_reorg/mod.rs` doc comment points at `ARCHITECTURE.md`.
- **`src/config/cli.rs`**: the `--override-sampling-params` help now says "See REFERENCE.md" (the sampling-contract docs moved there).

Docs only, plus two comment/help-string lines.

This order is outdated after #44218. `power_of_two` now filters out engines that fail admission first and only samples from the admitted ones (`partition_admitted` in `power_of_two.rs`), so a bucket is skipped only when no engine in the group can admit. - ShangmingCai · comment · 2026-10-15T03:33:55Z · [source](https://github.com/sgl-project/sglang/pull/43592#discussion_r4278731726)

File: `experimental/sgl-router/ARCHITECTURE.md` · line None

This isn't the right condition. The bound engine is compared with a sampled alternative B, not with itself: `running(A) > 2 * running(B)` and `running(A) - running(B) > 4` (see `affinity.rs`). Also it's not "only when": the session gets rebound too if the bound engine fails admission, i.e. hits 90% KV here.
