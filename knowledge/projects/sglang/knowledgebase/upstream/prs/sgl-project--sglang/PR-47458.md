# [Fix] nemotron: Accept transformers 5 layer types in NemotronHConfig

[Upstream PR](https://github.com/sgl-project/sglang/pull/47458) · state: open · merged: False

## Original PR description

## Motivation

Fixes #47444.

For `model_type: "nemotron_h"`, SGLang loads its own `NemotronHConfig` through `_CONFIG_REGISTRY`. That config accepts only the legacy layer-type names `mamba`, `attention`, `mlp` and `moe`. transformers 5.13 renamed the NemotronH layer types to `linear_attention` and `full_attention` and writes those names into `config.json`. A NemotronH checkpoint whose config was saved with transformers >= 5.13 therefore fails at server startup, before any weights load. This includes a plain `save_pretrained()` and quantized exports made with transformers >= 5.13.

```
ValueError: layers_block_type contains invalid types: {'linear_attention', 'full_attention'}. Must be one of: {'mamba', 'moe', 'mlp', 'attention'}
```

The public NemotronH checkpoints load today only because their `config.json` was written by transformers 4.x.

## Modifications

- `configs/nemotron_h.py`: `NemotronHConfig.__init__` maps `linear_attention` to `mamba` and `full_attention` to `attention` in `layers_block_type` and `mtp_layers_block_type` before pattern resolution and validation. Unknown names are still rejected.
- `configs/nano_nemotron_vl.py`: removed `_nemotron_h_compatible_config`, which applied the same mapping only for `nemotron_h_omni`. Every VL wrapper builds its `llm_config` through `NemotronHConfig`, so the mapping now lives in one place. This also fixes `NemotronH_Nano_VL_V2` and `NemotronH_Nano_Omni_Reasoning_V3`, which had no mapping and failed on transformers >= 5.13 configs.
- Tests (`test_nano_nemotron_vl_config.py`):
  - New regression test: a `NemotronHConfig` with transformers >= 5.13 names has the same layer pattern, MTP pattern and Mamba/attention layer ids as its legacy-named equivalent.
  - New test: unknown layer types still raise.
  - The existing omni alias test now covers all three VL wrappers.

  On `main`, the regression test and the two newly covered VL wrapper subtests fail.

## Accuracy Tests

Not applicable. This change only affects config parsing. Layer layouts that load today are unchanged.

The issue's reproduction, run on CPU with transformers 5.19.0 (the pinned version), re-saves the public `nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16` config with `AutoConfig.save_pretrained()`:

- On `main`, `NemotronHConfig.from_pretrained` raises the `ValueError` above.
- On this branch, it parses to the same 52-layer `hybrid_override_pattern`, MTP pattern `*E` and Mamba/attention layer ids as the original config.

End to end on GPU: a ModelOpt FP8 export of Nemotron-3.5-Lightning-30B-A3B whose config uses the new names, served on a single GB10 with `--quantization modelopt` and EAGLE MTP (5/1/6) on a `main` nightly. Unpatched, the server exits at startup with the `ValueError` above. With this PR applied to the same image, it loads the target and MTP draft models, starts, and completes a 2000-in/128-out benchmark at concurrency 1. Draft acceptance on this particular export is about 0 in both SGLang and vLLM, which points to the checkpoint's MTP head and is unrelated to this change.
