# [diffusion] comfyui: fix Flux executor silently drops Kontext ref_latents and ControlNet control

[Upstream PR](https://github.com/sgl-project/sglang/pull/43404) · state: closed · merged: False

## Original PR description

## Summary

ComfyUI's `Flux.forward` (`comfy/ldm/flux/model.py`) passes `ref_latents` (set by the `ReferenceLatent` node, used for FLUX.1 Kontext) and `control` (ControlNet) as named arguments. `FluxAdapter.pack()` in `apps/ComfyUI_SGLDiffusion/executors/flux.py` caught both in `**kwargs` and never forwarded them anywhere. Packing a request with or without these inputs produced an identical request, so a Kontext or ControlNet ComfyUI workflow silently ran as plain text-to-image, with no error.

The backend `FluxPipeline` has no Kontext/ControlNet support to route these values into (only the Qwen-Image and LongCat paths consume `image_latent`), so implementing full support is out of scope here. Instead of a silent wrong result, `pack()` now raises a clear `ValueError` for either case, matching the existing `ValueError` convention in `adapter.py`'s `get_adapter_class`.

- `control` is confirmed to default to `None` in ComfyUI core (`comfy/samplers.py`: `control = conds.get('control', None)`) and is only non-`None` when a ControlNet node is actually wired into the conditioning, so this cannot false-positive on an ordinary text-to-image workflow.

## Test plan

- Added `test_flux_pack_rejects_kontext_reference_latents` and `test_flux_pack_rejects_controlnet_control` to `test/unit/test_comfyui_adapters.py`.
- Ran `test/unit/test_comfyui_adapters.py` (CPU): 5 passed, including the 2 new regression tests, confirming they fail on the pre-fix adapter and pass on the fix.
