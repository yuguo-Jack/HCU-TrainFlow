# [Feat] rust-server: Drain on SIGTERM like the Python server

[Upstream PR](https://github.com/sgl-project/sglang/pull/47489) · state: closed · merged: True

## Original PR description

Stacked on #47487, which is itself stacked on #47321; this branch carries both, so review only the top commit. The drain counts a request that an `HttpLayer` holds before `/generate` (`PendingGeneration`, from #47487) as in flight.

## Motivation

With `SGLANG_RUST_SERVER=1`, SIGTERM cut every in-flight request within milliseconds. The main process had no SIGTERM handler, so it died, and PDEATHSIG then killed the scheduler process that hosts the Rust listener. A rolling restart therefore turned every running request into a client error.

The Python server drains instead (`TokenizerManager.sigterm_watchdog`):

1. Health answers 503.
2. Requests are still admitted, and every admitted request finishes.
3. A `ShutdownReq` stops the schedulers, which get 15 s to exit.
4. The process tree is killed and the server exits 0.

This PR gives Rust mode the same behavior.

## Modifications

**Behavior** (matches `sigterm_watchdog`):

- **Health:** `/health` and `/health_generate` answer 503 at once. The gRPC `HealthCheck` answers UNAVAILABLE. New requests are still admitted.
- **Drain:** every admitted client request runs to completion. A request is counted from admission, so one still fetching its media is waited for, and so is a request an `HttpLayer` holds before `/generate`. Health probes are not counted. There is no drain deadline, as in Python; the orchestrator's kill is the bound.
- **Forced exit:** the drain skips its wait when the last health probe stalled (Python's `UnHealthy`) or when `SGL_FORCE_SHUTDOWN` is set. Health probes now run detached and bound their own submission. A prober that gives up early still records the stall, and so does a wedged scheduler whose intake is full.
- **Close:** once the drain ends, axum and tonic shut down gracefully. They stop accepting, finish open responses, and close idle connections, with a 5 s bound on connections still open. Without the bound, a response that never finishes, or a client that never acknowledges the HTTP/2 shutdown, would hold up the scheduler's shutdown.
- **Stop:** when the listeners have closed, the runtime wakes the scheduler's idle wait. On global TP rank 0 it also sends a datagram to the launching process. That rank's scheduler then appends a `ShutdownReq`, which reaches every TP rank through the usual broadcast.
- **Exit:** the main process gives the schedulers Python's 15 s bound, counted from the first scheduler exit or rank 0's datagram. It then kills and reaps the rest and exits 0.

**How:**

- **Rust (`sglang-server`):**
  - `core/drain.rs` holds the drain state: the draining and forced flags, the last probe's outcome, and an in-flight count with a guard (`InFlight`).
  - `CoreHandle` gains `begin_drain`, `drain_ended`, `drain_close_deadline` and `drain_force_reason`. `CoreCall` and `PendingGeneration` hold an `InFlight` guard.
  - `probe_health` returns `HealthStatus::Draining` while draining, without sending a probe.
  - The HTTP and gRPC listeners serve with graceful shutdown.
  - `Runtime` reports the listeners' close and owns the signal-wakeup watcher thread.
  - `ToSchedulerRx` gains a waker for the scheduler's parked wait.
- **pyo3 `Server`:** new `begin_drain`, `drain_complete`, and `drain_signal_fd(signum, force, notify)` methods.
- **Scheduler hosting a listener (`RustServer.install_sigterm_drain`):**
  - Installs a SIGTERM handler, plus a `signal.set_wakeup_fd` pipe that a Rust thread reads. The drain therefore begins even while the scheduler thread is blocked in a GPU call.
  - `RustServer.drain()` appends one `ShutdownReq` once the drain has completed, on global TP rank 0 only.
  - In Rust mode, every scheduler process claims SIGTERM in Python before anything JIT-compiles. Otherwise LLVM's crash-handler restore can silently reset SIGTERM to `SIG_DFL`.
- **Main process (`rust_server/shutdown.py`, `RustServerSigtermDrain`):**
  - Forwards SIGTERM to the local schedulers that host a listener, and stops the subprocess watchdog.
  - Waits for the scheduler processes only, with Python's bound. The bound starts at the first scheduler exit or at rank 0's datagram. A wedged scheduler's listener also sends that datagram, because it closes without waiting.
  - Any local process can send to the abstract socket, so the main process acts on the datagram only after it has itself received SIGTERM.
  - A node >= 1 launcher with local listeners relays SIGTERM to them in the same way. Their schedulers then exit on rank 0's `ShutdownReq`.
- **`--sidecar`:** the drain's handler is installed before the `rust_server_sidecar` block. SIGTERM therefore stops the sidecar first, as the sidecar's handler already does, and then reaches the drain.

**Scope and limits:**

- **Attention DP:** rank 0 sends the `ShutdownReq` once its own listener has drained, so the last requests on the other DP listeners can be cut. Rust mode also forces `enable_dp_attention_local_control_broadcast` on with attention DP, which keeps that `ShutdownReq` in DP group 0. Both are marked as TODOs in the code. Fixing them means sending the shutdown through the control fan-out across DP listeners.
- **Plain data parallelism and elastic EP joiners:** the DP controller starts these schedulers, so the main process keeps its previous SIGTERM behavior.
- **PP and pdmux:** these event loops never check `gracefully_exit`, so their schedulers are killed by the 15 s bound, as in Python mode.
- **Crash dump:** Python dumps requests on the unhealthy force-exit path. That is left as a TODO until the Rust server supports `--crash-dump-folder`.
