# Add JIT CUDA kernels for NewGELU and QuickGELU

[Upstream PR](https://github.com/sgl-project/sglang/pull/43847) · state: open · merged: False

## Original PR description

## Motivation
NewGELU and QuickGELU currently use PyTorch expressions on CUDA. This change adds lightweight JIT CUDA kernels that fuse each activation into a single kernel, improving inference latency without requiring an AOT kernel build. FP16 benchmarks show 1.06–1.39× speedups over torch.compile across the tested sizes.

## Modifications

Add FP16/BF16/FP32 JIT CUDA kernels for NewGELU and QuickGELU, integrated into LLM and diffusion activation layers. Compute in FP32, use scalar accesses through 64K elements and vectorized accesses for larger aligned inputs.

For larger arrays, it launches multiple blocks(one-thread-per-vectorized-values) instead of persistent bounded threads with strided access pattern. The speed test shows launching more blocks outperforms fixed persistent threads. A sideinfo is that for triton kernel generated with inductor, it also seems to have the same kind of pattern without persistent logic.

## Speed Tests and Profiling

Tested on H100-PCIe
FP16 benchmark against torch.compile (latency in µs; shapes are [N]):

N | NewGELU JIT / torch (us) | Speedup | QuickGELU JIT / torch (us) | Speedup
-- | -- | -- | -- | --
1 | 1.155 / 1.426 | 1.23× | 1.167 / 1.377 | 1.18×
128 | 1.155 / 1.492 | 1.29× | 1.170 / 1.401 | 1.20×
4096 | 1.280 / 1.702 | 1.33× | 1.287 / 1.596 | 1.24×
65536 | 1.455 / 1.882 | 1.29× | 1.473 / 1.803 | 1.22×
1048576 | 3.232 / 4.497 | 1.39× | 3.622 / 3.822 | 1.06×

An occupancy-bounded grid-stride variant was also evaluated, which prefers launching multiple blocks to persistent bounded threads:

N | NewGELU vectorized / bounded | QuickGELU vectorized / bounded
-- | -- | --
16M | 39.66 / 40.02 | 40.02 / 41.01
64M | 148.56 / 170.03 | 148.54 / 175.10
256M | 582.25 / 670.17 | 581.88 / 687.84
