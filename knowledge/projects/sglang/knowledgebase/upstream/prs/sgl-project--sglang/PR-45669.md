# [Perf] gdn: Prefill in place on an envelope-strided state pool

[Upstream PR](https://github.com/sgl-project/sglang/pull/45669) · state: open · merged: False

## Original PR description

## Motivation

With `--enable-unified-memory` and the page-major layout, the GDN state pool pitches each slot wider than its state, so `conv_states` and `ssm_states` are strided views. `GDNAttnBackend.forward_extend` gathered every prefill's conv and recurrent states into packed copies, ran the kernels on them with identity indices, and scattered both back: two gathers, an arange and two scatters per GDN layer per prefill batch, whatever the batch's length (the `TODO(ch-wan)` in that code).

Two of the kernels that round trip protected already address slots by the pool's stride:
- GDN prefill reaches the Triton causal conv on CUDA and ROCm (a transposed input with host lengths), which takes every conv-state stride and offsets slots in int64; KDA hands its strided pool to the same kernel.
- FlashInfer's GDN prefill gathers each sequence's state by index and writes it back with `index_copy_`, so on a strided pool it ran a second gather and scatter on top of ours.

The Triton chunk kernel does not: `chunk_gated_delta_rule_fwd_h` steps slots by `initial_state.stride(0)`, but its entry point, `ChunkGatedDeltaRuleFunction.forward`, is wrapped in FLA's `input_guard`, which makes every tensor argument contiguous. On a strided pool it would read the right states and write the final ones into a discarded copy.

## Modifications

- `LinearAttnKernelBase.extend_honors_slot_pitch` (default False): the kernel's `extend()` reads and writes each slot's state at the pool's own slot pitch. `FlashInferGDNKernel` sets it; `TritonGDNKernel` sets it False explicitly; other kernels keep the default.
- `GDNKernelDispatcher.extend_honors_slot_pitch` forwards the prefill kernel's flag.
- `forward_extend` skips the gather/scatter when the platform is CUDA or ROCm (the prefill conv then takes the Triton conv), the prefill kernel declares the flag, and each slot's own state is packed. Otherwise it keeps the packed copies, as before. The contiguous default pool never gathered and is unchanged.
- The page-major allowlist's note on FlashInfer prefill in `kv_cache_hook.py` now says why it is stride-safe on its own.

GDN prefill defaults to FlashInfer on SM90 and SM100 for supported configurations, so that is where this applies by default; with `--linear-attn-prefill-backend triton` (or wherever FlashInfer prefill is not chosen) the round trip stays.

Tests:
- `test/registered/unit/layers/attention/test_gdn_prefill_backend_policy.py` (CPU), `TestGDNPrefillOnStridedStatePool`: a strided pool prefills in place only when the prefill kernel follows the pitch, the platform is CUDA or ROCm and each slot is packed; the FlashInfer kernel declares the flag, and the Triton kernel and the base class do not. All three cases fail on main.
- `test/registered/attention/test_gdn_prefill_strided_state.py` (CUDA): the Triton conv and the FlashInfer prefill on a strided pool against a packed pool holding the same values: the same outputs and states, and the elements between slots untouched.
