## Code Review

This pull request attempts to optimize the calculation of rotary embeddings in `forward_prepare_npu` for Qwen 3.5 and Qwen Next models by ensuring they are calculated only once per pipeline parallel group. However, the reviewer identified two critical issues: first, `self.pp_group` is not defined on the decoder layers, which will cause an `AttributeError` at runtime; second, the tracking list `calculated_pp_groups` is defined locally within the method, resetting on every call and rendering the check ineffective. The reviewer suggested a cleaner and safer approach using the `forward_batch` object to store a calculation flag.

There are two major issues with the current implementation:\n\n1. **AttributeError**: `self.pp_group` is not defined on `Qwen3_5AttentionDecoderLayer`. Accessing `self.pp_group.rank_in_group` will raise an `AttributeError` at runtime.\n2. **Logic Bug**: `calculated_pp_groups` is defined as a local variable `[]` inside `forward_prepare_npu`. Since this method is called per-layer, the list is re-initialized to empty on every call, making the check `self.pp_group.rank_in_group not in calculated_pp_groups` always evaluate to `True` and defeating the optimization.\n\nUsing the `forward_batch` object (which is unique per forward pass) to store a flag is a much cleaner and safer approach that completely avoids both issues.

```suggestion
        if (self.attn.layer_id + 1) % self.config.full_attention_interval == 0:
            if not getattr(forward_batch, "rope_cos_sin_calculated", False):
                self.rotary_emb.get_cos_sin_with_position(positions)
                forward_batch.rope_cos_sin_calculated = True
```
