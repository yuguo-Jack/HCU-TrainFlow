# [diffusion] fix: add LingBot-Video MoE sequence parallelism

[Upstream PR](https://github.com/sgl-project/sglang/pull/47788) · state: closed · merged: False

## Original PR description

## Motivation

LingBot-Video MoE previously entered sequence-parallel attention without sharding its video patch tokens. Each rank therefore repeated full-sequence work, and the output path could not correctly model the replicated text suffix.

## Changes

- Shard video patch tokens at the model boundary while keeping text tokens replicated.
- Slice global RoPE positions to the local video shard and pass the replicated suffix through `USPAttention`.
- Gather video tokens once after the final DiT block.
- Enable sequence sharding for the LingBot pipeline and reject unsupported dynamic batching or an explicitly disabled shard under SP.
- Add CPU validation coverage and a two-GPU dense-vs-SP tiny-DiT parity test.

This is independently useful for plain LingBot sequence parallelism and is the prerequisite for the MoE expert-parallelism PR.

## Validation

- `pre-commit` passed for every touched file.
- Python compilation passed.
- The final two-GPU parity run is pending on the GPU node; the test is included as `test_lingbot_video_moe_sequence_parallel_2_gpu.py`.

## Compatibility

- Default single-request generation is supported.
- Dynamic batching remains rejected because the masked Ulysses path does not support the replicated text suffix.
- Video token counts must divide the SP degree; invalid shapes fail explicitly.
