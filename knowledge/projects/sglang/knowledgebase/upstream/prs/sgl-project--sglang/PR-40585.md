# [diffusion][AMD] kernels: Fix fused QK-norm JIT kernels on ROCm

[Upstream PR](https://github.com/sgl-project/sglang/pull/40585) · state: open · merged: False

## Motivation

#35573 enabled the fused QK-norm and QK-norm+RoPE paths on ROCm, but the kernels behind them still don't build on all models. `elementwise/qknorm.cuh` fails outright, and `diffusion/qknorm_rope.cuh` fails for neox instantiations. Non-neox rope is the one case that already worked, which is why FLUX.2 saw the benefit of #35573 and MiniMax H3 did not. These compile failures do not keep the model from running, it's just slower.

This PR removes two dead CUDA includes in qknorm.cuh, and on ROCm pins the shuffle width to the kernel's 32-lane sub-group instead of letting HIP default it to the physical wave64. With both fixed, MiniMax-H3's QK-norm paths accept ROCm.

Without these changes neither of the kernels work on ROCm. Theser are necessary for eager / compile mode parity.

CUDA is unaffected. The shuffle change is behind `#ifndef USE_ROCM` and the dropped includes were dead.
<!-- Describe the purpose and goals of this pull request. -->

## Modifications

- `elementwise/qknorm.cuh` carried `cuda_bf16.h` / `cuda_fp16.h` as dead includes, which hipcc cannot find ("fatal error: 'cuda_bf16.h' file not found"). The file reaches the GPU only through `impl/norm.cuh` and the `runtime.cuh` macro shims, both of which hipcc builds, so the includes can just go.

-  `__shfl_sync(kActiveMask, ...)` passes a `uint32_t` mask, and HIP static_asserts `sizeof(MaskT) == 8`. On ROCm this now calls `__shfl(..., partner_lane, device::kWarpThreads)` instead.  `device::kWarpThreads` is 32u unconditionally, so the kernel indexes lanes in 32-wide logical warps, while HIP defaults the shuffle width to the physical wave64. `partner_lane` is an index inside that 32-lane sub-group, so the width has to be explicit.

- minimax_h3.py gated `_apply_qk_norm` and `_use_fused_qknorm_rope` on `current_platform.is_cuda()`. Both now accept ROCm, which is what reaches the two kernels above. MiniMax uses is_neox=True, the instantiation that did not
build.
