# [Fix] pd: Pair MiniMax sparse state by layer id under PP

[Upstream PR](https://github.com/sgl-project/sglang/pull/47610) · state: open · merged: False

## Original PR description

## Motivation

PD disaggregation with a pipeline-parallel prefill server (`--pp-size > 1`) fails for MiniMax sparse models (`MiniMaxSparseKVPool`): both Mooncake and NIXL raise `PD disagg: PP>1 not supported for MiniMax state yet.` when sending the `MINIMAX_INDEX_K` / `MINIMAX_DENSE_KV` state.

The guard exists because those state components are compacted per PP stage (each stage only registers its own layers), while the decode peer registers all layers. Pairing entries positionally would write a stage's layers into the wrong decode layers. The generic layer-id pairing in `build_transfer_entry_pairs` already handles this for other state types; the MiniMax components just never published layer ids.

#36095 addresses the Mooncake index-K path only. This PR covers both Mooncake and NIXL, dense-KV state, and the main sparse KV region.

## Modifications

- `mem_cache/memory_pool.py`: `MiniMaxSparseKVPool` reports the global layer id of each entry: `get_kv_layer_ids` (main sparse KV, K then V), `get_index_k_state_layer_ids`, `get_dense_kv_state_layer_ids` (K then V).
- `mem_cache/static_kv_storage.py`: publish these ids for the main KV region of every `MiniMaxSparseKVPool` (previously only the NVFP4 subclass) and for both state components.
- `disaggregation/mooncake/conn.py`, `disaggregation/nixl/conn.py`: drop the PP > 1 guard; pass `state_type` and the src/dst layer ids to the transfer so entries pair by global layer id. Under PP, a peer that did not publish ids is rejected with the existing `Layer metadata` error instead of transferring to wrong layers. The equal-TP requirement is unchanged.
- Tests:
  - `test_minimax_sparse_disagg_state_kv_args.py`: full-model and PP-stage pools publish the expected global layer ids for main KV, index-K and dense-KV, one per registered pointer.
  - `test_mooncake_transfer_batching.py`: a PP stage's compact index-K / dense-KV entries land in the decode entries of the same layers; a decode peer without layer ids is rejected.

## Accuracy Tests

MiniMax-M3.1-Flash (MXFP8), B300, Mooncake over RoCE, mini-LB, GSM8K 5-shot greedy, 200 examples:

| prefill | decode | GSM8K |
|---|---|---|
| main, TP2 (PP1) | TP2 | 0.970 |
| main, TP2 PP2 | TP2 | prefill dies on the first transfer: `RuntimeError: PD disagg: PP>1 not supported for MiniMax state yet.` |
| this PR, TP2 PP2 | TP2 | 0.980 |

Common flags: `--disaggregation-transfer-backend mooncake --moe-runner-backend flashinfer_trtllm_routed --chunked-prefill-size 8192`.

Unit tests: `python -m pytest test/registered/unit/disaggregation/` (429 passed).

## Speed Tests and Profiling

No change on the transfer hot path for PP1; under PP the same per-layer transfers are issued, just paired by layer id.
