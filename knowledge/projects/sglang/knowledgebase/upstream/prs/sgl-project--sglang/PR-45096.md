# [Perf] DSv4/DSv4.1: Skip the pre_hc_head CP gather when DSpark captures aux hidden states

[Upstream PR](https://github.com/sgl-project/sglang/pull/45096) · state: open · merged: False

## Original PR description

## Motivation

With prefill CP, `EagerRunner` all-gathers the model output at the end of every forward. For DeepSeek-V4 that output includes `pre_hc_head` (`[tokens per rank, 4 x hidden]`, e.g. `[4096, 28672]` bf16 = 224 MiB per rank on CP4), but when DSpark captures aux hidden states it is dropped right after the gather. It is also above the aiter custom all-gather size limit, so it goes through RCCL. In a DeepSeek-V4-Pro TP4 + prefill CP4 profile on MI355X, the end-of-forward gathers take 5.4 ms per 16K-token forward, and `pre_hc_head` is 80% of those bytes.

## Modifications

Drop `pre_hc_head` before the CP gather when DSpark aux capture is on, instead of after it. The logits processor receives the same inputs as before.

## Accuracy Tests

No numerical change: only a gather whose result was unused is skipped.

## Speed Tests and Profiling

Expected to remove most of the 5.4 ms above per prefill forward with DSpark + prefill CP (the hidden-state gather stays). I will add measurements with DSpark enabled.
