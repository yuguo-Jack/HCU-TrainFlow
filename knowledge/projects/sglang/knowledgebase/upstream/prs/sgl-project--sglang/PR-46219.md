# [Feat] openai: Parse DeepSeek text for the native endpoints through deepseek-recipe

[Upstream PR](https://github.com/sgl-project/sglang/pull/46219) · state: closed · merged: True

## Original PR description

With #45907, chat and Responses output of DeepSeek-V4 / V4.1 is parsed by deepseek-recipe. The native `/separate_reasoning` and `/parse_function_call` endpoints still parsed it with SGLang's text detectors. This moves them onto recipe as well and removes the text parsing that no serving path uses any more.

## Changes

- `/separate_reasoning` with `deepseek-v4` / `deepseek-v41` and `/parse_function_call` with `deepseekv4` / `deepseekv41` parse through the served model's recipe adapter: the text is tokenized, so the markers it spells count as tokens, and recipe parses it as a whole output.
- The endpoints pick the parser through the chat encoding registry (`native_text_parser`, with the adapter-owned parser names in `ADAPTER_OUTPUT_PARSERS`), so `http_server.py` does not depend on a model's module.
- `/parse_function_call` returns every call recipe parses, as chat does and as the official API does: `tool_index` is the tool's position in `tools`, or -1 for a tool outside it. Without `tools` the text comes back unparsed, as before.
- The DeepSeek detectors keep what the grammar, the scheduler and the serving decisions read (think tokens, excluded tokens, structural tag names, reasoning defaults). Removed:
  - the reasoning detector's DSML tool-start settings and the V4.1 reasoning subclass, which only overrode them;
  - the V4.1 tool detector's `strip_string_param_value`, and two attributes nothing read.

## Behavior changes

- `/separate_reasoning` splits text that closes a thinking block (`a</think>b` -> reasoning `a`, text `b`). The text parser split only text that opened with `<think>`, which V4 output never does, since `<think>` ends the prompt. A leading `<think>` is still accepted.
- A DeepSeek parser name on a server that is not serving that DeepSeek model returns 400: recipe parses with the served checkpoint's tokenizer.
- `/separate_reasoning` treats text that opens with `<think>` as reasoning even when it is cut before `</think>`, as before; a `<think>` in the middle of the text stays text, where the text parser opened reasoning there.
- A second `</think>` is dropped, and newlines that open the reasoning or the answer are trimmed, as recipe does for chat.
- `/parse_function_call` returns calls to tools outside `tools` (with `tool_index` -1); the text parser dropped them unless `SGLANG_FORWARD_UNKNOWN_TOOLS` was set. It also drops a stray `</think>` from `normal_text`.

## Tests

- Added `test_native_endpoints_parse_through_recipe`: the reasoning split, a tool call, and the 400 case.
- Removed the V4 / V4.1 text-parsing tests: the round trip in `test_deepseekv41_detector.py`, DSML routing and chunk invariance in `test_reasoning_parser.py`, and parsing in `test_function_call_parser.py`. The grammar and structural-tag tests stay.
