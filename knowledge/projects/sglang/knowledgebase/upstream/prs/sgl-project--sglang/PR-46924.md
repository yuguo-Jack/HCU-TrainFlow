# [Fix] dflash: Route a from-disk checkpoint to the model that owns it

[Upstream PR](https://github.com/sgl-project/sglang/pull/46924) · state: open · merged: False

## Original PR description

Fixes #46806.

## Motivation

With `--speculative-algorithm DFLASH`, reloading or pushing the target's weights also writes them into the draft model. No error is raised and the call reports success. After that, the acceptance length drops to ~1.0 and the server is slower than with speculative decoding off.

The issue identifies two pieces that combine. Both are addressed here.

### Piece 1: the disk update fans out to the draft runner

`SchedulerWeightUpdaterManager.update_weights_from_disk` loops over `self._select_runners()`, i.e. selector `"all"`, and passes the same `recv_req.model_path` to every runner. `DFlashWorkerV2.weight_update_runners()` returns the draft runner, so the target checkpoint is loaded into the draft model, and the draft runner's `model_config.model_path` is set to the target's path.

### Piece 2: the DFLASH draft accepts weights that aren't its own

`DFlashDraftModel.load_weights` → `resolve_param_name` strips `model.`, so the target's `model.layers.{0..N-1}.*` and `model.norm.weight` land on the draft's `layers.*` and `norm.weight`. Names that don't resolve are skipped silently. The result is a draft whose layers have been replaced by the first N target layers, reported as `"Succeeded to update model weights."`.

## Modifications

### Route the checkpoint to the model that owns it

With the default `selector="all"`, the checkpoint is now routed to the runner whose `model_config.model_path` matches it, and the other runner keeps the weights it has. The comparison uses `os.path.realpath`, so a symlinked or relative path still matches.

Each skip logs a warning naming the path and the selector that overrides it:

```text
update_weights_from_disk(model_path='/models/target') is the target's checkpoint,
so the draft runner is skipped and keeps its own weights. Pass selector='draft'
to update the draft anyway.
```

The rules are:

- An explicit `selector` always wins. It is the caller stating which model it means, so it is never second-guessed.
- When neither runner's checkpoint path is known, the fan-out is unchanged (the checkpoint cannot be attributed to a model).
- When the path belongs to neither runner, it is treated as a new checkpoint for the target, and the draft keeps its weights.

### Refuse weights that provably are not the draft's

`DFlashDraftModel.load_weights` now rejects a checkpoint weight that cannot belong to this draft:

- a name that names a layer at or beyond the draft's layer count (`model.layers.7.*` for a 2-layer draft), and
- a head weight the draft does not own (`embed_tokens.weight`, `lm_head.weight` — the draft predicts hidden states, not tokens; only the Nemotron 3.5 variant carries its own embedding).

The check runs only on names that fail to resolve, so a genuine draft checkpoint, the HF rotary caches, and the draft's own split `q_proj`/`k_proj`/`v_proj` exports are all unaffected.

The check has to work on two different inputs. A materialized weight list can be validated before anything is written, so a foreign checkpoint never lands in the draft at all. The disk loader's weights arrive as a lazy generator, which must not be materialized (that pulls a whole checkpoint into host memory and is the reason the disk loader is lazy in the first place), so there the check runs per name as it streams.

A checkpoint where at least half of the names do not resolve logs a warning, since that is the shape of a checkpoint from another model:

```text
DFLASH checkpoint looks like it belong to another model: 18 of 24 weights did
not match the draft (for example model.layers.4.self_attn.q_proj.weight).
The draft may keep stale weights.
```

### Roll back to the checkpoint that was being served

A failed update re-read the checkpoint that had just failed instead of the one the model was serving:

```python
except Exception as e:
    ...
    self.model_config.model_path = original_model_path   # was left pointing at the failed path
    iter = get_weight_iter(self.model_config)             # re-read the FAILED checkpoint
    model_load_weights(self.get_model(), iter)
```

So a failed update left the model loaded with the failed checkpoint's weights, and left `model_config.model_path` corrupted. The rollback now restores the served path and reads that checkpoint. A failing rollback is logged rather than masking the original error.

This also matters for the routing above: the routing reads `runner.model_config.model_path`, so a corrupted path would misroute every later update.

## Relation to #46852

#46852 adds the `selector` field to `UpdateWeightFromDiskReqInput` and passes it through the Engine API and the HTTP endpoint. That is the escape hatch for a caller who wants to be explicit. This PR is complementary and does not conflict:

- It reads the selector with `getattr(recv_req, "selector", "all")`, so it works both before and after #46852 lands.
- It never overrides an explicit selector, so once #46852 is in, `selector="target"` and `selector="draft"` behave exactly as that PR documents.
- It adds the default behaviour for the case #46852 cannot cover on its own: the default `"all"` update no longer pushes one model's checkpoint into the other model.

Known gap, by design: a brand-new *draft* checkpoint at a path neither runner was loaded from is routed to the target, because a checkpoint at an unknown path is indistinguishable from a new target checkpoint. `selector="draft"` from #46852 is the way to update the draft in that case.

## Accuracy Tests

No model output changes for a correct deployment. A from-disk update of the target's own checkpoint loads exactly the same weights into the target as before, and the draft is now left alone instead of being corrupted. The tensor and distributed paths are untouched: they already honour `selector`, and this PR does not change their default.

Unit tests are added:

- `test/registered/unit/managers/test_weight_update_checkpoint_routing.py` (11 tests) covers the routing: the target's checkpoint skips the draft and vice versa, the skipped runner keeps its own checkpoint, the selected runner receives the requested path, an explicit selector overrides the ownership rule, an unknown path updates the target only, a shared path updates both, unknown runner paths keep the fan-out, and a failing runner stops the fan-out and reports the failure.
- `test/registered/unit/spec/test_dflash_foreign_checkpoint.py` (15 tests) covers the loader: a genuine draft checkpoint still loads, a target head weight is rejected, a layer beyond the draft is rejected, a layer inside the draft is not rejected, extra names are tolerated, a list input is validated before any weight is written, a lazy iterator is checked without being drained, and a mostly-unresolved checkpoint warns while a mostly-resolved one does not.

`26 passed` locally.

**Limitation:** no GPU is available on the machine this was developed on, so the end-to-end acceptance-length numbers in the issue were not re-measured here. The fix was verified at the routing and loader level with unit tests; reproducing the issue's table on a real L40S would confirm it.

## Speed Tests and Profiling

Not measured. The change removes work rather than adding it: the draft runner is no longer reloaded with a checkpoint it does not own.
