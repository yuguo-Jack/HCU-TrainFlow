# [Perf] [AMD] kimi-k2.5: Fuse shared-expert append into AITER grouped topk

[Upstream PR](https://github.com/sgl-project/sglang/pull/38923) · state: open · merged: False

## Original PR description

## Motivation

- Kimi-K2.5 routes with grouped top-k: 8 routed experts plus 1 fused shared expert.
- On ROCm/AITER with one expert-parallel rank, the shared expert's ID and weight are appended after grouped top-k by a separate `fused_append_shared_experts` launch in every MoE layer.
- That launch sits on the latency-critical decode path and only writes constants, so it can be removed.

## Modifications

- New fast path `srt/layers/moe/aiter_topk.py`, tried first by `select_experts` on ROCm/AITER.
- One persistent `[height, routed_k + n_shared]` weight/ID buffer per routing config, with the shared columns pre-filled once. AITER `biased_grouped_topk` writes the routed columns through strided views, so no append launch runs.
- Buffers live in the runtime context (`get_buffer`):
  - Height = max(chunked-prefill size, `max_prefill_tokens`), floored at 8192 and capped at 131072 rows.
  - Cost: `layers x height x (routed_k + n_shared) x 8 B`, e.g. about 71 MB for 60 layers at 16384 rows.
  - Never allocated inside a CUDA-graph capture; that call takes the ordinary path.
- Same kernel inputs as the ordinary path: an fp32 correction bias routes in fp32 (shared helper `aiter_grouped_topk_route_inputs`).
- KT's `mask_cpu_expert_ids` now masks out of place, so it cannot overwrite the persistent shared column.
- No new env var or flag.

Fallbacks (the existing routing + append path runs):

| Condition | Reason |
|---|---|
| Not grouped top-k, no correction bias, or no fused shared expert | nothing to fuse |
| `moe_ep_size != 1` or per-rank shared slots (DeepEP/MegaMoE) | shared IDs are per rank |
| `num_token_non_padded` or expert-location dispatch set | padding mask / EPLB remap edit `topk_ids` in place |
| `SGLANG_SIMULATE_*_EXPERTS`, `SGLANG_OPT_USE_JIT_KERNEL_GROUPED_TOPK` | another router writes the IDs |
| `SGLANG_K3_RADIX4_TOPK` and radix4 covers the shape (Kimi-K3) | radix4 routes it |
| `TopK.forward_native` (torch.compile bs=1) | keeps host-side buffer logic out of the traced graph |
| `apply_routed_scaling_factor_on_output` | AITER path does not implement it |
| Batch taller than the buffer, first allocation during graph capture, or config not published | buffer unavailable |
