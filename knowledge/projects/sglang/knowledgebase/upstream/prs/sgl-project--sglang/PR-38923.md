## Motivation

Kimi K2.5 uses grouped top-k routing with eight routed experts and one shared expert. On the ROCm/AITER single-expert-parallelism path, the shared-expert ID and weight were appended after grouped top-k in a separate operation for every layer. This adds avoidable work to a latency-sensitive MoE routing path.

Fuse the shared-expert append into AITER grouped top-k while preserving the existing routing results, padding behavior, CUDA graph compatibility, and fallbacks for unsupported configurations.

## Modifications

- Added an ROCm/AITER grouped-top-k fast path for eligible routing configurations with fused shared experts and correction bias.
- Allocated persistent per-routing-config output buffers whose shared-expert columns are prefilled with the shared IDs and weights. AITER writes routed results into the strided routed columns, so no per-layer shared-expert append kernel is needed.
- Added GPU tests for Kimi K2.5-shaped routing, exact output equivalence with the existing append path, CUDA graph replay, padding behavior, buffer reuse, and fast-path eligibility fallbacks.
