# [Fix] quantization: List only CPU-supported methods in the CPU validation error

[Upstream PR](https://github.com/sgl-project/sglang/pull/32253) · state: open · merged: False

## Original PR description

## Motivation

When a registered quantization method is unsupported on CPU, `get_quantization_config` rejects it, but the error says "Available methods on CPU" while interpolating every key of `QUANTIZATION_METHODS`. The message therefore advertises methods CPU cannot run, including the one just rejected. For example, `awq_marlin` on CPU is rejected, yet listed as available.

## Modifications

- Build the CPU validation message from `CPU_QUANTIZATION_METHODS` instead of `QUANTIZATION_METHODS`.
- Add a regression test in `test/registered/unit/configs/test_quant_config_parsing.py` that forces the CPU branch (patching only `is_cpu` and `cpu_has_amx_support`) and asserts the exception lists exactly `CPU_QUANTIZATION_METHODS`.

Only the error text changes; method registration and CPU support are untouched.
