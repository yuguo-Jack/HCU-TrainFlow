# [Fix] disaggregation: Retain failed drained-ACK deliveries for retry

[Upstream PR](https://github.com/sgl-project/sglang/pull/47172) · state: open · merged: False

## Original PR description

## Motivation

The existing deferred-release path removes a room's ACK targets before sending, while `_send_abort_ack` catches transport errors. A transient socket failure therefore loses a drained-ACK destination: a later drain check has no target to retry. This is especially costly for destinations that require an ACK to release their buffers.

This PR fixes that existing delivery bookkeeping. It is an **independent ACK-delivery increment of SG09** in #47031; it does not implement the larger external-load abort finalizer or replace the upstream protocol with a downstream four-frame notification.

## Modifications

- Handle send errors in the fan-out owner, retaining only failed destinations for a later drain check while allowing other destinations to complete.
- Preserve a newer target generation registered during a failed send, and avoid restoring a poisoned room's target.
- Add regression coverage for retry, mixed successful/failed destinations, and the generation/poison interleavings, alongside existing ACK fan-out tests.

The existing drain predicate and ABORT/ACK frames are unchanged. This increment requires no coordinated P/D wire upgrade or Mooncake Store change. It provides a retry opportunity on subsequent existing drain checks; it adds no background retry worker or delivery guarantee. The larger SG09 work still depends on the full SG06/SG07 cleanup lifecycle, late-bootstrap/terminal-room integration and supported P/D validation.

This missing increment was identified while adapting the downstream SG09 delivery/retry requirements (`53c80cc8`, `48f0ae83`, `8bdd0f61`, `50942586`) to upstream `f2d31889258d22214d9541e40b1e1e6961ce95e7`; it is not a transplant of the downstream notification format.

Related #38961 is closed without merging and discussed retaining targets until drain; this PR covers socket delivery failure after drain. #41069 discusses arming host ACK tracking before notification; its setup/order work remains separate.
