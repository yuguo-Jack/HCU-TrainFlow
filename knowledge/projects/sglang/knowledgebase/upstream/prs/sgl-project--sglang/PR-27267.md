## Motivation

With `SGLANG_HUGEPAGE_SIZE` set, HiCache host-pool preflight only checked `psutil.virtual_memory().available` (the kernel's `MemAvailable`), which excludes the reserved hugetlb pool. Startup could fail with **"Not enough host memory"** even when a large free hugetlb pool — the very memory `alloc_mmap` maps from — could serve the pool in full.

## Modifications

- **`mmap_allocator.py`**: Add `hugepage_size_requested()`, `hugepage_mode()` (off/prefer/required), `hugetlb_pool_free_bytes()` (sysfs `free - resv`, bounded by the hugetlb cgroup limit), and per-tensor backend tracking (`tensor_mem_backend()`). `alloc_mmap` honors the mode: `required` raises on failure, `prefer` falls back to plain pages.
- **`host_memory.py`**: Generalize `_cgroup_memory_headroom()` into `_cgroup_headroom(controller, ...)` shared by memory and hugetlb controllers; add `cgroup_hugetlb_headroom_bytes()`. `available_host_memory_bytes(allow_cgroup_fallback=...)` keeps reclaimable page cache free.
- **`pool_host/base.py`**: `host_memory_budget_bytes()` takes the larger of plain RAM (after reserve) and the free hugetlb pool, only when the allocator/device dispatch to mmap. New `host_memory_requested_bytes()` rounds each mapping up to a whole hugepage the way `alloc_mmap` does.
- **Call sites**: `HostKVCache`, `MambaPoolHost`, `MHATokenToKOnlyPoolHost`, `DSAIndexerPoolHost`, `DeepSeekV4PagedHostPool`, `DeepSeekV4StateHostPool`, and the unified page-envelope backing route both requested and available bytes through the new helpers. Pools with split mappings (`AsymmetricMHA`, `Mamba`, `MXFP8`) override `get_mapping_bytes()` so each is rounded independently.
- **`environ.py` / docs**: Add `SGLANG_HUGEPAGE_MODE` (off/prefer/required); document the preflight credit and the per-mapping rounding note for 1 GiB pages.
- **Tests**: Cover mode parsing, sysfs reads, cgroup bounds, per-mapping rounding, budget credit, and device/allocator dispatch (`test_host_memory.py`, `test_mem_pool_host.py`, `test_mmap_allocator.py`, `test_hicache_host_register.py`).

Using `exc_info=True` here will print a full traceback to the logs whenever hugepages are requested but not configured on the system (e.g., on non-Linux platforms, or in containers where `/sys` is not mounted). Since this is a common and expected environmental fallback condition, printing a full traceback is unnecessarily noisy and can confuse users. It is better to log the exception message directly without the traceback.

```suggestion
    except (OSError, ValueError) as e:
        logger.warning(
            'Failed to read free_hugepages from %s: %s', sysfs_path, e
        )
```
