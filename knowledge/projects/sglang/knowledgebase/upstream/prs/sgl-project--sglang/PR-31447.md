# [Fix] Confidential-Computing: enable Flashinfer all-reduce fusion

[Upstream PR](https://github.com/sgl-project/sglang/pull/31447) · state: open · merged: False

## Original PR description

## Motivation

Under NVIDIA Confidential Computing (CC), FlashInfer AllReduce + Residual + RMSNorm fusion was effectively off. FlashInfer's usual VMM `SymmDeviceMemory` workspace cannot be allocated under CC, so SGLang's preflight failed and fusion fell back to the normal all-reduce. FlashInfer [flashinfer-ai/flashinfer#3993](https://github.com/flashinfer-ai/flashinfer/pull/3993) (in 0.7.0 and later; SGLang pins 0.7.2) allocates the TRTLLM workspace with torch symmetric memory under CC instead.

This PR lets SGLang run the multicast-free `trtllm` backend under CC, and keeps backend selection and the workspace preflight safe there.

## Modifications

All in `layers/flashinfer_comm_fusion.py` and `arg_groups/overrides.py`, gated on `is_confidential_compute()`:

- **`cc(fix): enable FlashInfer AR+RMSNorm fusion under Confidential Computing`**: `_resolve_backend` forces `trtllm` under CC and raises on an explicit `mnnvl` or `cutedsl` request or on multi-node, which need NVLink multicast.
- **`cc: choose only fusion backends Confidential Computing can run`**: under CC, the fusion auto-enable turns on `trtllm` for single-node systems only, and leaves multi-node and MiMo (`cutedsl`) off. Before, those defaults crashed at startup instead of falling back. An explicit incompatible request still raises in `_resolve_backend`.
- **`cc: keep the AR-fusion preflight vote under Confidential Computing`**: the preflight's cross-rank vote now also runs under CC, so a rank that cannot allocate stops every rank before FlashInfer's workspace rendezvous instead of hanging startup. Under CC the local probe compares free device memory with the CC buffer sizes, since CC blocks the VMM `cuMemCreate` probe. `_flashinfer_trtllm_workspace_allocation_sizes` sizes both allocations; its main buffer now uses the dtype's element size, as FlashInfer does, which enlarges only the fp32 estimate.

Off-CC behavior is unchanged apart from that fp32 preflight estimate.

**Tests**: `test/registered/unit/layers/test_flashinfer_comm_fusion.py` covers CC backend resolution and the preflight vote (a rank or a peer without memory stops every rank; the VMM probe still decides off CC). `test/registered/unit/test_model_overrides.py` covers the CC auto-enable. The existing backend-dispatch tests are pinned to CC off.

**Validation and known limits**
- Validated on SM100 (4x B300) with CC on.
- Not validated in Protected PCIe mode with the CC feature off. SGLang counts that mode as CC, while FlashInfer 0.7.2 does not; [flashinfer-ai/flashinfer#6576](https://github.com/flashinfer-ai/flashinfer/pull/6576) aligns FlashInfer and is merged but not yet released. Until SGLang picks it up, the two checks differ there, and the preflight vote still prevents a hang.
- Enabling fusion swaps the reduction kernel, so numerics can change.

## Code Review

This pull request introduces support for NVIDIA Confidential Computing (CC) in SGLang. It implements an `AsyncD2HCopyWorker` to offload device-to-host copies to a dedicated background thread, preventing scheduler thread stalls caused by synchronous bounce-buffer copies under CC. It also configures FlashInfer allreduce fusion to force the multicast-free `trtllm` backend and disables symmetric-memory preflight checks when CC is enabled. The review feedback suggests unconditionally initializing `enable_async_d2h_copy` and `async_d2h_worker` in `init_overlap` to prevent potential `AttributeError`s when overlap scheduling is disabled.

![medium](https://www.gstatic.com/codereviewagent/medium-priority.svg)

To prevent potential `AttributeError`s when `enable_overlap` is `False`, it is safer to initialize `self.enable_async_d2h_copy` and `self.async_d2h_worker` unconditionally at the beginning of `init_overlap` before the early return check. This ensures these attributes are always defined on the `Scheduler` instance.

```suggestion
        self.enable_async_d2h_copy = False
        self.async_d2h_worker = None

        if not self.enable_overlap:
            return

        # Under NVIDIA Confidential Computing (CC) the per-step D2H result readback is
        # forced synchronous and blocks the scheduler thread at issue, serializing the
        # overlap pipeline. Offload it to a worker thread (AsyncD2HCopyWorker).
        self.enable_async_d2h_copy = is_confidential_compute()
        if self.enable_async_d2h_copy:
            from sglang.srt.managers.async_d2h_copy_worker import AsyncD2HCopyWorker

            self.async_d2h_worker = AsyncD2HCopyWorker(self.device_module)
            logger.info(
                "NVIDIA Confidential Computing (CC) detected: "
                "using async D2H copy worker to preserve overlap scheduling."
            )
```
