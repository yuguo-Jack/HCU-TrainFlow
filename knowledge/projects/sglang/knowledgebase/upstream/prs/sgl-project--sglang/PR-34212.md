# [AMD][DCP] Skip unused QuickAllReduce allocation for DCP groups

[Upstream PR](https://github.com/sgl-project/sglang/pull/34212) · state: open · merged: False

## Original PR description

## Motivation

On ROCm, `GroupCoordinator` currently initializes QuickAllReduce whenever custom all-reduce is enabled. That is useful for TP, but current DCP communication paths do not dispatch to QuickAllReduce:

- `ag_rs`: all-gather plus reduce-scatter for MLA, or an FP32 all-reduce for MHA.
- `a2a` / `fi_a2a`: all-to-all.

In a Kimi-K3 TP8/DCP8 profile on MI350X, constructing the DCP QuickAllReduce communicator reserved 4.002 GiB per GPU. Across 1,152 recorded rank-0 DCP collective dispatches, QuickAllReduce was selected zero times. TP QuickAllReduce remains useful and must stay enabled.

Related to #29736.

## Modifications

- Add an optional `use_quick_allreduce` control to `GroupCoordinator` and `init_model_parallel_group`.
- Preserve the existing behavior by default: the new option inherits `use_custom_allreduce` when unspecified.
- Disable QuickAllReduce only for the DCP group.
- Keep the AITER custom-all-reduce and PyNccl setup unchanged.
- Add a unit test that verifies DCP opts out while TP retains the default behavior.

## Accuracy Tests

This does not change model math or the collective selected by current DCP paths. The targeted construction test passes:

```
1 passed, 5 deselected
```

## Speed Tests and Profiling

This PR targets static memory rather than latency. Measured DCP communicator initialization on MI350X:

| Component | Reserved per GPU |
| --- | ---: |
| PyNccl | 1.883 GiB |
| AITER custom all-reduce | 3.002 GiB |
| QuickAllReduce | 4.002 GiB |

QuickAllReduce had zero selections in the recorded DCP dispatches, so this change reclaims the 4.002 GiB DCP allocation without removing TP QuickAllReduce.

[P1] **Inserting this optional parameter in the middle of the existing positional API is not backward compatible for downstream callers.** A previous call such as `init_model_parallel_group(ranks, rank, backend, None, None, True, "dcp")` mapped `True` to `use_message_queue_broadcaster` and `"dcp"` to `group_name`; it now maps them to `use_quick_allreduce` and `use_message_queue_broadcaster`. All in-repository callers are safe because they use only three positional arguments, so this does not block approval. In a follow-up PR, move the new parameter to the end or make optional controls keyword-only.
