# [Fix] qwen3.8: Fix batch-invariant kernels for Qwen3.8 Flash-Next

[Upstream PR](https://github.com/sgl-project/sglang/pull/42087) · state: open · merged: False

## Original PR description

## Motivation

With deterministic inference enabled, Qwen3.8-Flash-Next can produce different logprobs and generated tokens when the same prompt is placed in a different batch. Compiled HC projections use an unregistered `aten::mm.out` overload, shared-expert gating changes its reduction configuration at 1024 token rows, and QSA changes both its attention launch configuration and selected-index ordering.

## Modifications

- Register `aten::mm.out` using the existing batch-invariant matmul and write the result into the supplied output tensor.
- Apply the shared-expert gate's warp cap to every batch size in batch-invariant mode.
- Use one QSA prefill launch configuration in batch-invariant mode.
- Use FlashInfer deterministic CUDA QSA top-k with smaller-index tie breaking and canonical index ordering, including the decode shortcut.
- Add regressions for output-buffer semantics, cross-batch reductions, ragged top-k inputs, cutoff ties, and CUDA graph replay.

## Accuracy Tests

Validation environment: 8 H20 GPUs, TP=8, BF16 weights, FP32 GDN state, Triton GDN and MoE, decode CUDA graphs enabled, prefill CUDA graphs disabled. PyTorch 2.13.0+cu130, Triton 3.7.1, FlashInfer 0.7.0.post1, and sglang-kernel 0.4.8.

- All 8 GPU regression cases passed on this PR's code. Independently reverting the mm.out, gate, QSA prefill, top-k, or decode-routing change reproduced its corresponding failures.
- Existing QSA tests: 74 passed, 1 skipped.
- Full-model batch probes with radix cache disabled: 27 comparisons against 3 single-request references matched exactly in generated token IDs, selected-token logprobs, and top-5 logprobs. Input lengths were 256, 2560, and 16384, with 32 generated tokens per request. This matrix preceded removal of a redundant post-sort already performed by the pinned FlashInfer implementation; the final operator regressions were rerun.

```bash
python -m pytest -q \
  test/registered/unit/batch_invariant_ops/test_qwen_batch_invariance.py \
  test/registered/kernels/ops/attention/qsa/test_qsa_determinism.py
```

GSM8K: all 1319 test questions, 5 training-set examples, non-thinking chat template, greedy decoding, max 2048 output tokens, concurrency 64, radix cache enabled, and prefill chunks of 8192. The baseline runs and final PR run use identical evaluation settings.

| Variant | Correct | Accuracy | Invalid / truncated |
| --- | ---: | ---: | ---: |
| Unmodified, ordinary inference | 1275/1319 | 96.66% | 0 / 3 |
| Unmodified, deterministic inference | 1278/1319 | 96.89% | 0 / 1 |
| This PR, deterministic inference | 1278/1319 | 96.89% | 0 / 1 |

Against the deterministic baseline, 7 answers changed from wrong to correct and 7 changed from correct to wrong. This measures task accuracy; it does not establish cached-prefix equivalence.

## Speed Tests and Profiling

Both variants were benchmarked sequentially in the same environment: 16 requests, 2560 input tokens and exactly 256 output tokens per request, radix cache disabled, prefill chunks of 32768, one warmup and three timed rounds. Throughput includes prefill and decode.

| Variant | Median output tokens/s |
| --- | ---: |
| Unmodified, deterministic inference | 349.50 |
| This PR, deterministic inference | 324.68 |

The fixes reduce throughput by 7.1% on this workload relative to the unmodified deterministic mode.
