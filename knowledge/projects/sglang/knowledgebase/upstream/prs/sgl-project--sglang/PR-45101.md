# [Feat] unified_cache: Publish direct-UMBP residency as host-tier KV events

[Upstream PR](https://github.com/sgl-project/sglang/pull/45101) · state: open · merged: False

## Original PR description

## Motivation

With the direct UMBP linker, a worker restores prefixes from the node's shared host-memory pool, but its KV events report only device pages. A KV indexer cannot see what the pool holds, so a cache-aware router treats a request whose prefix any worker on the node can restore as cold.

## Modifications

- `UnifiedCacheLinker.kv_event_medium` (default `None`, publishes nothing): the medium for pages the external store acknowledges.
- The direct UMBP linker sets it to `CPU_PINNED`: it restores from node-local host memory (SSD and remote fetch are disabled for it).
- `UnifiedTreeCore` records `BlockStored` with that medium when the store acknowledges a write-through.
- Python TreeCore only; with the Rust TreeCore a warning is logged and nothing is published.

- lixiufei-leo · comment · 2026-10-19T06:59:46Z · [source](https://github.com/sgl-project/sglang/pull/45101#issuecomment-6261585868)

Holding this for now while I discuss the design with the UMBP and unified cache folks.

The plan there was for engines to publish only device-tier KV events and for the router to query the store's lookup interface for what the store holds, which needs a common lookup abstraction across store backends. This PR instead publishes store-acknowledged pages as host-tier events. One known gap: pages the store evicts on its own produce no removal event, so an indexer can keep reporting them.

I'll update this PR after that discussion.
