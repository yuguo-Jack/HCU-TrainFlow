# [Fix] rust-server: Answer media the multimodal processor refuses with a 400

[Upstream PR](https://github.com/sgl-project/sglang/pull/47109) · state: closed · merged: True

## Original PR description

## Motivation

When a client sends an image the multimodal processor refuses (a PNG whose IDAT checksum is wrong, a JPEG truncated mid-scan, a format the decoder does not support), the Python server raises `ValueError` from its processor and `http_server` answers 400 with the processor's message. The Rust server mapped every `Error::Encode` to `CoreError::Internal`, so the same request answered 500 with `encode failed: <message>`. A 500 for bad client input reads as a server fault to routers and alerting, and a disaggregated pair whose prefill and decode run different frontends answers the same request with different status classes.

## Modifications

- `MmProcessor::process` returns `Result<MmProcessOutput, MediaError>` instead of `Result<_, String>`, the type the `fetch_media` hook already uses. `Client` is what Python's processor raises as `ValueError` (refused media, a placeholder matching no item); `Server` is `RuntimeError` and any other exception. `QwenMmProcessor` maps the driver's failure to `Client` and a failed output encode to `Server`.
- `Error::Encode` carries the `MediaError`. Admission (`prepare_generations`) and the MM worker's failure (`translate_runtime_error`) both map it through one `From<MediaError> for CoreError`: `Client` is a 400, or an SSE error event with code 400 on a stream, with the processor's own message and no `encode failed: ` prefix; `Server` stays a 500. Only `Encode(Server)` counts as a server fault.
- The worker's own faults stay 500s: a malformed processor result, a failed `finalize` or a feature buffer that cannot be placed fail as `Error::Internal`.
- `payload.rs` classifies its errors: a malformed data URL, bare base64 or a blown byte budget is `Client`; a prefetch that disagrees with the walk is `Server`.
- Test processors return `MediaError`; `worker_returns_request_with_fsm_advanced` covers refused, failing and malformed processors, and a new runtime test `refused_media_is_a_bad_request` drives `/generate` unary and streaming through a refusing and a failing processor and checks the status, the code and the message.

Files: `rust/sglang-server/src/api_server/core/{error,prefetch}.rs`, `api_server/handlers/{generate,handle}.rs`, `multi_modality/{payload,worker}.rs`, `tokenizer_manager/to_scheduler_tests.rs`, `utils/{error,runtime}.rs`.
