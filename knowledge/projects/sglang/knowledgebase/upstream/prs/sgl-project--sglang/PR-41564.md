# [Fix] [NPU] Adapt pcp-v2 for MHA attention

[Upstream PR](https://github.com/sgl-project/sglang/pull/41564) · state: open · merged: False

## Original PR description

## Problem

Prefill context parallel is broken for **every model that uses the generic (non-DSA) Ascend attention backend** — Qwen3, Qwen3-MoE, and anything else going through `AscendAttnBackend.forward_extend` under CP. The CP v1 runtime was removed for platform backends, but this path was left calling into the removed implementation, so it fails twice:

**1. The KV all-gather call is gone (fails before the first token is produced)**

```
File ".../hardware_backend/npu/attention/ascend_backend.py", line 1902, in forward_extend
File ".../hardware_backend/npu/attention/ascend_backend.py", line 1478, in do_cp_attn_fia
File ".../layers/utils/cp_utils.py", line 19, in cp_all_gather_rerange_kv_cache
    _deprecated_platform_cp()
ValueError: Prefill CP on HIP/NPU/MUSA is deprecated; CP support will be refactored soon.
```

`cp_utils.py` is now an import-only shim; the NPU generic path is its only remaining real caller. Every scheduler rank dies on the first prefill, so the server exits with SIGQUIT.

**2. FIA tiling fails on the padded CP shard (fails once the KV write is fixed)**

```
RuntimeError: npu_fused_infer_attention_score_symint ... NPU function error:
  call aclnnFusedInferAttentionScoreV3 failed, error code is 561002
Execution_Error(EZ1008): Failed to execute operator FusedInferAttentionScore_0.
  Reason: Failed to execute tiling function.
```

`do_cp_attn_fia` handed FIA the **physical** query shard while advertising only the **logical** token counts in `actual_seq_lengths`. The model runner pads the shard to `per_rank_actual_token[0]` rows, so the advertised cumulative sequence lengths did not match the query row count. Traced live on an A3 machine (tp2 + attn-cp2, 6-token prompt, cp_rank 0):

```
q_local=4  per_rank_actual_token=[4, 4]  split_list=[2, 2, 1, 1]  zigzag_index=[0, 3]
prev_list=[2]  next_list=[1]   ->  logical tokens = 3, physical rows = 4
```

and the mismatch is reproducible in isolation — `actual_seq_lengths=[1]` with a 2-row query fails, `[2]` with a 2-row query succeeds:

```
OK   asl=[2] kv=5    FAIL asl=[1] kv=5    FAIL asl=[1] kv=6
```

## Change

`python/sglang/srt/hardware_backend/npu/attention/ascend_backend.py`:

- `_cp_allgather_and_save_kv_npu` now goes through the CP v2 strategy
  (`get_cp_strategy().materialize_full_kv(...)`), with a plain KV write when CP
  is off — the same contract as the `cp_active` branch of
  `flashattention_backend`. The deprecated helper import is dropped.
- `do_cp_attn_fia` trims the physical pad rows before the two FIA calls
  (`logical_tokens = total_q_prev_tokens + total_q_next_tokens`) and re-appends
  zero rows to the output so downstream code still sees the physical shard.

A unit test is added at
`test/registered/unit/npu/attention/test_npu_prefill_cp_backend.py` covering both
paths on CPU tensors (no hardware needed).

## Verification

Hardware: Ascend A3, `tp4 + moe_dp2 + attn_cp2 + prefill CP`
(`--enable-prefill-cp --cp-strategy zigzag`, `ASCEND_USE_FIA=1`).

- **Qwen3-30B-A3B**: server starts and completes a 100-question 5-shot GSM8K
  eval with no scheduler errors (`Ran 1 test in 9.6s ... OK`).
- **Qwen3-0.6B prefill parity vs a non-CP run** (greedy, first-token logprob):
  21 prompt lengths from 1 to 273 tokens, plus a batched bs=4 run — first token
  identical in 25/25 cases, max logprob delta 0.18 (TP reduction noise).
- **Unit tests**: `Ran 8 tests ... OK`.

## Notes / not covered

- The old NPU-only "merge K and V into one all-gather" optimization is dropped,
  because `materialize_full_kv` is the shared CP v2 implementation (two
  gathers). Restoring it belongs in `ZigzagCPStrategy` so every CP backend
  benefits, rather than in this backend.
- Accuracy against a `0.92` GSM8K gate was **not** re-measured: the test
  machine only had a w8a8 checkpoint that scores ~0.37 on GSM8K even without
  CP, so it cannot separate CP correctness from that checkpoint's own noise
  (CP-on 0.35 vs CP-off 0.37). The listed parity checks are the evidence for
  numerical correctness instead.
- Batched multi-sequence prefill correctness is only covered by the bs=4
  logprob parity run above.
