# [Fix] multimodal: Keep per-request images when a batch mixes image and text-only requests

[Upstream PR](https://github.com/sgl-project/sglang/pull/44203) · state: open · merged: False

## Original PR description

## Motivation

A batch that mixes requests with and without images is rejected in two places:

- **`/generate` and the Engine API.** `GenerateReqInput._normalize_image_data` decides whether `image_data` holds one image list per request by looking only at `image_data[0]`. If the first request has no image, as in `[None, ["a.png"]]`, the batch is read as a flat list and every entry is wrapped again (`[[None], [["a.png"]]]`). The request then fails with `Invalid image: [...]`. The same batch in the other order, `[["a.png"], None]`, already works.
- **`/vertex_generate`.** The route collects `image_data` only from the instances that have one. `[{"text": "a", "image_data": "u"}, {"text": "b"}]` therefore sends `["u"]` for a batch of two and fails with `The length of image_data should be equal to the batch size.` Any Vertex batch that mixes image and text-only instances is rejected.

## Modifications

- `GenerateReqInput._normalize_image_data` treats `image_data` as one list per request when any entry is a list, not only the first one.
- `vertex_generate` sends one entry per instance: either `None`, or that instance's images as a list (a single image is wrapped). When no instance has images, `image_data` stays `None` as before.
- Regression tests:
  - `test_first_request_without_images` in `test_io_struct.py`.
  - `TestVertexGenerateRoute` in `test_generate_api_contract.py`, which drives the route with a fake tokenizer manager that runs the real normalization.

The open #41768 also edits `io_struct.py`, but changes `_handle_parallel_sampling`; the two do not overlap.

## Accuracy Tests

N/A for model outputs, since only request normalization changes.

End-to-end check on one RTX 4090 with `Qwen/Qwen2.5-VL-3B-Instruct`. The server was the v0.5.21 image with this patch applied; both changed functions are identical in v0.5.21 and main. Each batch element was compared with the same request sent alone at temperature 0.

| Request | Batch | Before | After |
|---|---|---|---|
| `/generate` | `[None, [img]]` | 400 `Invalid image` | matches |
| `/generate` | `[None, [img, img]]` | 400 `Invalid image` | matches |
| `/vertex_generate` | image instance, then text instance | 400 length mismatch | matches |
| `/vertex_generate` | text instance, then image instance | 400 length mismatch | matches |

Batches that already worked still match: `[img, None]`, `[None, img]`, `[[img], None]`, `[[], [img]]`, `[[img], [img, img]]`, `[img, img]`, and two image instances on Vertex.
