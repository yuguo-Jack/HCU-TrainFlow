# [Fix] CI: Preserve shared HF cache during incomplete retries

[Upstream PR](https://github.com/sgl-project/sglang/pull/45005) · state: open · merged: False

## Original PR description

## Motivation

Follow up on the shared Hugging Face cache race noted in #44975 while re-enabling the Muse Spark B300 PD test from #44666.

In the original failing job, one TP rank found a single `blobs/*.incomplete` file and removed the entire model cache at 07:32:01.334 UTC. The removal completed at 07:32:01.361, and a concurrent tokenizer load failed at 07:32:01.614. The full removal includes the snapshot metadata, tokenizer, and config used by other readers.

The later #44975 B300 run passed all three Muse tests without this patch, so it shows that the startup failure is intermittent rather than demonstrating this fix.

Failure job: https://github.com/sgl-project/sglang/actions/runs/39099912264/job/117611788593

## Modifications

- Do not remove the shared model-cache root merely because an `.incomplete` blob exists.
- Return `False` from local snapshot validation so the existing CI download path handles recovery.
- Keep the existing shared-lock sequence: acquire the cache lock, re-check the cache, remove only incomplete blobs, then download and validate.
- Add a CPU regression using a temporary HF cache. It verifies that:
  - initial validation preserves snapshot/tokenizer/config files;
  - cleanup runs while the shared lock is held;
  - only the incomplete blob is removed;
  - the mocked download and validation retry completes.

## Validation
