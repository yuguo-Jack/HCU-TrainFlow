## AITER prerequisites

None beyond AITER main. Extend calls `aiter.ops.triton.kimi_delta_attn.chunk_kimi_delta_attn`, which main already exports. This path was off in the AgentX hours.

## Motivation

Kimi-K3 KDA prefill (extend) runs the Triton chunked kernel. AITER has a FlashKDA kernel for gfx95x that computes the same thing. This PR adds it as an opt-in backend.

## Modifications

- Add `kda_aiter_flash.py`, which runs KDA extend on AITER `chunk_kimi_delta_attn`, behind one `is_hip()` hook in `kda_backend.py`.
- Mark per layer when beta is passed as raw logits (`extend_beta_is_raw` on the Kimi-K3 attention layer, read by `kda_backend.py` with a `False` default), because the kernel applies the sigmoid itself.
- Fall back to Triton for state tracking inside a chunk and for speculative draft extend.

| New env flag | Default |
|---|---|
| `SGLANG_ENABLE_AITER_KDA_FLASH_PREFILL` | off |

`SGLANG_AITER_KDA_FLASH_PREFILL` remains a deprecated alias, so the recorded runs still apply. `extend` stays one function: it is one prefill launch.

Shared (non-K3) files: `kda_backend.py`.
