# [Fix] scheduler: Publish KV events on every decode step

[Upstream PR](https://github.com/sgl-project/sglang/pull/46258) · state: open · merged: False

## Original PR description

## Motivation

With `--kv-events-config`, a KV-aware router (sgl-router, or Dynamo) builds its view of each worker's cache from the BlockStored / BlockRemoved stream. During decode, the scheduler publishes that stream only every `decode_log_interval` steps (40 by default). Blocks inserted when a request finishes, and blocks evicted to make room for decode, reach the router up to 40 steps late, and a follow-up turn that arrives in that window is routed on a stale view.

Prefill publishes after every batch, so mixed workers partly hide this. PD decode workers run only decode batches, so they always lag.

## Modifications

`report_decode_stats` called `publish_kv_events()` after its periodic early return, so 39 of 40 decode steps skipped it. The call now runs before that return, so every decode step publishes, as every prefill batch already does. On ranks without a publisher it is a no-op, and a step with no events costs one `take_events()` call.

## Accuracy Tests

New case in `test/registered/unit/observability/test_forward_pass_metrics.py`: a real `SchedulerKvEventsPublisher` behind the metrics reporter, one queued event, one decode step that is not a log step.
