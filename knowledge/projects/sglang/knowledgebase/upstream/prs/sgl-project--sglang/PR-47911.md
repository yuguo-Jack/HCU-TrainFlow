# [Fix] [AMD] aiter: Skip the unused decode workspace on the vectorized_5d KV layout

[Upstream PR](https://github.com/sgl-project/sglang/pull/47911) · state: open · merged: False

## Original PR description

## Motivation

With the SHUFFLE 5D KV layout (`SGLANG_AITER_KV_CACHE_LAYOUT=vectorized_5d`), `AiterAttnBackend` still allocates the `paged_attention_ragged` workspace although decode runs through `pa_decode_gluon`, wasting `max_bs * num_heads * ceil(context_len / 256) * (head_dim + 2) * 4` bytes of HBM; this PR skips the allocation whenever decode does not use `paged_attention_ragged`.

The allocation guard checks only `use_mla` and `use_triton_unified_attention`, while `forward_decode` sends 5D pools to `forward_decode_vectorized_5d` before reaching the buffer's only reader. #47042 already uses the full predicate (MLA, unified attention or 5D) for the partition buckets.

Unused workspace at `max_bs = 4096`, TP1:

| Model | context | unused workspace |
|---|---|---|
| Qwen3-8B | 40960 | 10.2 GiB |
| Llama-3.1-8B-Instruct | 131072 | 32.5 GiB |
| MiniMax-M2.7 | 204800 | 76.2 GiB |

On MI355X at `main@f85ca901e2`, MiniMax-M2.7 at TP1 with the 5D layout fails at startup with `torch.OutOfMemoryError: ... Tried to allocate 76.17 GiB`; with this change it starts and decodes.

Only plain MHA pools with the opt-in 5D layout reach this code; the default NHD layout is unchanged. MLA and sliding-window models already skip the allocation, and hybrid linear-attention pools never report the 5D layout.

## Modifications

- Add `AiterAttnBackend._uses_paged_ragged_decode()`, the predicate `_build_decode_partition_buckets` computed inline, and use it for the `workspace_buffer` allocation too.
- Add a CPU test to `test_aiter_verify_metadata.py` that builds the backend on a plain MHA pool and checks the workspace is allocated for NHD and skipped for `vectorized_5d`. It fails on main, on a variant that never allocates the workspace, and on one that keys the guard on the env var instead of the pool's layout.

## Accuracy Tests

Not applicable: the skipped buffer is never read on the 5D path, and the NHD path allocates the same buffer as before.

## Speed Tests and Profiling

Only an init-time allocation is removed; no per-step change is expected. Serving numbers on current main: TBD.
