# [Fix] [AMD] hicache: Book explicitly sized host pools against one host memory snapshot

[Upstream PR](https://github.com/sgl-project/sglang/pull/47584) · state: open · merged: False

## Original PR description

## Motivation

- With an explicit `--hicache-size` or `--hicache-ratio`, every HiCache host pool checks itself against a fresh `psutil` sample of free host memory, divided by the number of local ranks (`host_memory_budget_bytes`).
- Ranks build and pin their pools at different times. A rank that checks after its peers pinned theirs is charged for their pools a second time and fails, even when the host has room.
- Whether a launch passes therefore depends on how the ranks interleave.
- Seen on Kimi-K3 TP8, one 3 TB MI355X host, `--hicache-size 240` with a 140 GB Mamba host pin (`--hicache-mamba-size-gb` in #47867) plus DSpark draft sidecars:

| Per rank | Host memory |
|---|---:|
| KV | 100 GB |
| Mamba | 140 GB |
| Draft | 74.08 GB |

- Seven ranks built their draft pools over 95 s; the eighth then failed while about 582 GB was still free:

```
ValueError: Not enough host memory available. Requesting 74.08 GB but only have 72.77 GB free.
```

- Auto-sizing (default ratio) does not have this problem: it samples once per rank before its all-reduce and books every pool against that snapshot with `host_memory_budget_scope`.

## Modifications

- `hicache_auto_size.py`: for an explicit size (resolution nulls `hicache_host_memory_fraction`), `auto_size_hicache` now:
  - takes one `host_memory_budget_bytes()` snapshot per rank,
  - waits on a world-group CPU barrier, so every rank samples before any allocates,
  - books the pools in `host_memory_budget_scope`.
  - Pool sizes do not change; a size that does not fit still fails, against the snapshot.
- `pool_host/base.py`: inside a scope the allowance is also capped by host memory free now (not divided by ranks), so pinned memory that books nothing (staging buffers, another engine) still counts.
- `memory_pool_host.py`: the DeepSeek V4 paged and state host pools pass their request to `host_memory_budget_bytes`, so they book it like the other host pools (outside a scope the argument has no effect).

| Sizing mode | Before | After |
|---|---|---|
| Auto (default ratio) | one snapshot, booked per pool | unchanged; V4 pools now also book |
| Explicit `--hicache-size` / `--hicache-ratio` | fresh sample per pool, / ranks per host | one snapshot after a barrier, booked per pool, capped by free-now |

- Related PRs: #47867 (`--hicache-mamba-size-gb`) needs an explicit `--hicache-size`, so its pinned Mamba pool goes through this path; #47040 does not interact with it.
