# [Perf] [AMD] glm5_next: Allow AITER shared expert fusion at TP2/EP1

[Upstream PR](https://github.com/sgl-project/sglang/pull/42268) · state: open · merged: False

## Original PR description

## Motivation

The HIP shared-expert fusion gate accepts TP4 and TP8 but rejects TP2/EP1. GLM-5.3-Flash block FP8 at TP2 uses 288 routed experts plus one appended shared expert, with a per-rank intermediate width of 1024. Enable the existing AITER fused path for this topology.

## Modifications

- Admit TP2 while retaining EP1, matching MoE-TP, gfx950/AITER, expert geometry, activation, and precision requirements.
- Keep Quark MXFP4 restricted to TP4/TP8; its newer main-branch support is not broadened to TP2.
- Update CPU gate tests for TP2 acceptance, TP1/TP16 rejection, and the TP2 precision/backend guards.
- Extend the registered MI35x numerical and graph-replay tests to TP2 alongside TP4/TP8.
- Update the branch against main `7d9bc10493275a371989bd03a13147588005f136`.

## Accuracy Tests

Validated commit `f122953f592038066f71566a2437f45399b1c753` on MI355X/gfx950, PyTorch `2.11.0+rocm7.2`, HIP `7.2.26015`, Triton `3.7.0`, and AITER `edb581401f0e60a9fefbe1bc8af6366208484903`:

- Actual GLM gate and weight-loader suite: **11 passed, 17 subtests passed**, using the complete serving imports.
- Fused versus separate shared-expert numerical checks: **18/18 passed** across TP2/TP4/TP8 and 1/8/128/2048/8192/16384 token buckets. Minimum cosine similarity: **0.9998115**; all cases satisfy the existing `rtol=0.05, atol=0.02` comparison.
- Graph capture/replay: **passed at TP2, TP4, and TP8**.

GPU component tests execute the unchanged AITER operations and registered test methods; the external runner substitutes package initialization, CI registration, and the test base class. Each topology is tested with its per-rank weight geometry on one GPU, without distributed collectives or model weights.

```bash
python -m pytest -q test/registered/unit/models/test_shared_experts_fusion_gates.py::TestGlm5NextGate
python test/registered/kernels/ops/moe/test_glm53_shared_expert_fusion.py
```

Full-model TP2/EP1 GSM8K remains pending. Component numerical agreement is not a GSM8K score.

## Speed Tests and Profiling

Quick single-GPU component benchmark at TP2 rank geometry: E=288/top-k=8 plus a separate shared expert versus E=289/top-k=9 fused. Hidden size 4096, per-rank intermediate size 1024, block FP8, BF16 output. CUDA graph replay, three timing windows of 100 calls after warmup; table reports medians. Fused measurements include constructing the appended routing ID and unit weight.

| Tokens | Separate (µs) | Fused (µs) | Latency change |
| ---: | ---: | ---: | ---: |
| 1 | 60.691 | 55.432 | -8.67% |
| 8 | 169.099 | 161.402 | -4.55% |
| 128 | 685.787 | 676.540 | -1.35% |
| 2048 | 1434.611 | 1430.457 | -0.29% |
| 8192 | 3014.244 | 2984.762 | -0.98% |
| 16384 | 5265.221 | 5468.715 | +3.86% |

These are component timings, not serving throughput or independently restarted repetitions. The 16K bucket regresses, and small differences at other large buckets are not established improvements. Online tuning was disabled; no new TP2 tuning sweep was performed. A reviewed TP2 tuning artifact and matched end-to-end serving comparison remain pending. The existing `--disable-shared-experts-fusion` opt-out remains available.
