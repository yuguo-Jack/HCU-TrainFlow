# [Feat] KVShard: Integrate GLM DSA/MTP with PD and CPU HiCache

[Upstream PR](https://github.com/sgl-project/sglang/pull/42973) · state: closed · merged: True

## Original PR description

## Motivation

Co-author: @Shunkangz

Connect GLM DSA/MTP serving to page-sharded KV caches so prefill, P/D transfer and CPU HiCache preserve the same ownership for target/draft latent KV and DSA indexer keys/scales.

## Dependencies and review scope

Base: upstream main `5987ec82ed`. Current head: `346068aaa329cf1692fbb6031f60469fdac77dcb`.

DSA attention/indexer support (#44280), MTP pool/scratch support (#40929), and the control-plane/pool/basic-PD prerequisites are already merged.

The remaining unmerged prerequisite is **#43778**, pinned at `6d1e510b2429a36fe499943ff075472d995d8457`. Its three implementation commits are rebased onto this main base with Shunkang's author attribution preserved. The dependency snapshot is `152e93348ad825449c484fbee2068fc614116c67`.

**Review the integration increment:** https://github.com/HZY-Wade/sglang/compare/codex/kvshard-glm-dependencies-20261026-clean...codex/kvshard-dsa-hicache

GitHub's main-based Files changed view also includes #43778. **Rust support is separate in #46445**; this PR contains no Rust implementation and selects Python for sharded launches when the tree backend is unset.

## Modifications

- Select page-sharded DSA target and single-layer GLM NextN draft pools. Validate matching cache geometry and budget latent/indexer scratch for both runners.
- Preserve the shared sender lifecycle. Pair source/destination DSA pages before owner filtering, transfer every owner's target/draft state, retain empty-final-chunk completion, and account for physical transfer bytes.
- Compose a standalone sharded allocation facade with native host pools. Reuse HybridCacheController and L2TransferEngine; resolve owner-local indices through existing preparation hooks before the H2D start event. Preserve logical queue indices and ACK counts.
- Scope scratch bookkeeping to sharding, cache the controller's sharding flag, retain ordinary transfer descriptor builders, and remove the redundant FULL eviction retry.
- Pass `start_owner` to backups only when the tree node has a shard owner. Preserve owner zero and the non-sharded controller's existing call signature.
- Add a four-GPU GLM P2/D2 E2E with CP2, EAGLE MTP and CPU HiCache. Use fabric NVLink with Mooncake's exportable KV allocator, matching the existing P2/D2 test on the same GB300 runner. CPU tests follow the registered `CustomTestCase` convention.

Supported configuration: CUDA PD-prefill, interleave CP > 1, PP1, TRTLLM DSA prefill/decode, FP8 E4M3/page64, Mooncake, and uncompressed index_kpool=1. Optional MTP is single-layer GLM NextN EAGLE with topk=1. CPU HiCache uses cache mode, kernel I/O and layer_first/page_first. L3, external linkers, DSA layer splitting, HiSparse and two-batch overlap are outside this combination. Decode remains unsharded.

[Configuration requirements, paired launch example and validation guidance](https://github.com/HZY-Wade/sglang/blob/codex/kvshard-dsa-hicache/docs/docs/advanced_features/pd_disaggregation.mdx#glm-dsa-kv-sharding-with-cpu-hicache)
