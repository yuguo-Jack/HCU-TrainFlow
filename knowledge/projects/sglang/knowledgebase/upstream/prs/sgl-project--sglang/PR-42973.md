# [KV Sharding] Integrate GLM DSA, MTP PD transfer and CPU HiCache

[Upstream PR](https://github.com/sgl-project/sglang/pull/42973) · state: open · merged: False

## Original PR description

Integrate page-sharded GLM DSA and MTP across prefill execution, PD transfer and CPU HiCache, preserving shared logical ownership and independent target/draft cache state.

### Changes

- Extend Mooncake transfer to packed target/draft DSA indexer pages. Filter source pages by owner and destination pages by matching positions; reject mismatched counts/layouts, omit empty indexer-layer descriptors, and count only owned transfer bytes.
- Wire DSA prefill/MTP to the sharded pools. Keep logical pages for batched indexer getters and scratch pages for raw readers, route stores through owner-aware APIs, and account for target/draft latent and indexer scratch memory.
- Reuse native packed target/draft host declarations and the L2 engine. Preserve page ownership through host allocation/load-back, localize logical transfer indices only at L2 submission, and fence layer-ahead gathers on restored-layer readiness. Empty owners still publish completion events and ACKs.

### Scope

CUDA interleave prefill CP, PP1, TRTLLM prefill/decode, raw FP8/page64, Mooncake and uncompressed one-key-per-token DSA. MTP is limited to single-layer GLM NextN EAGLE with topk=1. CPU HiCache uses cache mode, kernel I/O and layer_first/page_first layouts; L3, buffer-only and external-linker combinations remain rejected.

P-side prefill/speculative graphs and generic decode-shaped FlashInfer autotuning remain disabled for this path. Decode workers retain their ordinary runtime. This does not add decode HiSparse, fused dual-store optimization or grouped-gather optimization.
