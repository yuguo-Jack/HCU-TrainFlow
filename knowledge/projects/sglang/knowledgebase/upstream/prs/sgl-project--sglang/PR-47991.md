# [Feat] speculative: Build adaptive spec states within an opt-in memory budget

[Upstream PR](https://github.com/sgl-project/sglang/pull/47991) · state: open · merged: False

## Original PR description

## Motivation

Roadmap #23705, Reliability: "Memory-aware state management / lazy init" (the memory-aware half; lazy init is left for a follow-up, see below).

With `--speculative-adaptive`, `AdaptiveController.init_states()` builds a runtime state (CUDA graphs and attention backends) for every candidate step at startup. On a tight `--mem-fraction-static` the optional states can OOM the server at startup even though the policy may never switch to them.

## Modifications

- New opt-in flag `--speculative-adaptive-memory-budget-gb`. Unset keeps today's behavior.
- States the policy can activate without feedback are always built and not charged to the budget: the initial step and every BS slot's start step (`AdaptiveSpeculativeParams.required_steps`). The first batch routed to a slot activates its start step through `activate_step_by_batch`, so these cannot be skipped.
- The other candidates are built in priority order (`prebuild_order()`: nearest hop from a slot's start step first) while the spent cost is below the budget. The cost of a state is only known after capture, so the total may exceed the budget by one state. There is no cost estimator: the per-step cost is not monotonic in the step count, because `cuda_graph_bs_for_step` captures a step's graphs only for the batch sizes whose slot can reach it (step 0 captures every large bs, step 7 only bs < 8).
- Candidates that were not built are removed from every slot for this launch (`restrict_candidates()`); the policy never selects them and `_activate` still fails loud on a missing state. The log lists the dropped steps and the measured cost of each built state so the budget can be tuned on the next launch.
- `SpecRuntimeState.gpu_memory_gb` records the measured cost; `EAGLEWorkerV2.build_adaptive_runtime_state()` max-reduces it across the target TP group so every rank makes the same build/drop decision.
- The flag is validated in the speculative resolution hook: negative values are rejected, and it warns when adaptive speculative decoding is off.

### Follow-up: lazy init

Building a missing state on first use is left to a follow-up PR: capturing while serving races with in-flight batches, so deferred states need to be built at a quiescent point (the scheduler's idle boundary) rather than inside `_activate`.
