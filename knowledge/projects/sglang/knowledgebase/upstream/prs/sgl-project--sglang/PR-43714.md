# [Model] Apply Gemma4 attention overrides to text-only checkpoints

[Upstream PR](https://github.com/sgl-project/sglang/pull/43714) · state: open · merged: False

## Original PR description

Fixes #43434

## Motivation

A text-only `Gemma4ForCausalLM` export of Gemma 4 26B A4B (`model_type: gemma4_text`) fails to load, while the same weights load fine as `Gemma4ForConditionalGeneration`.

`_apply_gemma4_attention_overrides` is what gives SGLang's Gemma 4 configs the full-attention shape on `head_dim` / `num_key_value_heads` and the sliding-window shape on `swa_*`. It only ran for the multimodal model types and always read `config.text_config`, so a text-only config never got it, and `gemma4_causal.py` built the global layers with the sliding-window head dim (256 instead of 512). That is the `Attempted to load weight (torch.Size([512])) into parameter (torch.Size([256]))` error in the issue.

With transformers 5.19 it fails even earlier: `get_hf_text_config` returns the config itself for a text-only checkpoint, and the loop that copies text-config attributes onto the config calls `hasattr` on the still heterogeneous `num_key_value_heads`, which raises `AmbiguousGlobalPerLayerAttributeError`.

## Modifications

* Add `gemma4_text` to `_GEMMA4_MODEL_TYPES`, and let `_apply_gemma4_attention_overrides` use the config itself when there is no `text_config`.
* Skip the text-config attribute copy in `HfModelConfigParser.parse` when the text config is the config (there is nothing to copy).
* Add `test_text_only_checkpoint_gets_the_same_overrides`, which saves a `Gemma4TextConfig` with different sliding and global shapes and loads it through `get_config`. It fails on `main` and passes with this change.

## Accuracy Tests

Not run: I don't have a GPU to load the 26B checkpoint end to end. The change only affects how the config is parsed for `gemma4_text`, and the multimodal path is unchanged.
