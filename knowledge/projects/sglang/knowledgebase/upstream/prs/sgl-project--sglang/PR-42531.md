# [cake_kernels] minimax_h3 route: pass the engine's native operands to the fused stages

[Upstream PR](https://github.com/sgl-project/sglang/pull/42531) · state: closed · merged: False

## Original PR description

> Stacked on #42416 (P1/P2 routes); the diff against `main` includes that stack. Only the nine `cake/12-minimax-h3-engine-operands` commits (route pass-through, facade, pack release, two-launch pre-attention pin + its test/workspace follow-ups, final re-pin to the merged FlashInfer commit) are new here.

## Summary

The `minimax_h3_diffusion` Cake route now hands the MiniMax-H3 DiT's own tensors straight to the four fused stages. The adapters are re-pinned to FlashInfer `745b12352d4` (flashinfer-ai/flashinfer#6039 engine-operand stage operators + flashinfer-ai/flashinfer#6055 two-launch BF16 pre-attention), whose MiniMax-H3 stage operators take the engine's native operands:

- **AdaLN / gate tables** as `[rows, 5376]` views with any `rows >= 1` and a 16-byte row pitch: the column chunks of the `[rows, 6 * 5376]` modulation projection pass as they are (the out-projection also needs `5376 <= stride(0) < 2**32`).
- **int64 row indices** `[M]` (the engine's `combined_indices`).
- **RoPE** as the request `(cos_sin_cache [S, 96], positions int64 [M])` pair, gathered on the device.
- **Separate `eps` / `qk_eps`** for the input norm and the Q/K norms; `eps` is free.
- **Fused QKV weight** in the engine-resident `[kind, head, head_dim]` row order (`[q_all | k_all | v_all]`, what the loader produces) — no re-interleave of the checkpoint order.
- **BF16 pre-attention as a two-launch stage** (norm / indexed-AdaLN workspace kernel + persistent QKV GEMM with the fused Q/K-norm, RoPE and pack epilogue); the `[M, 5376]` BF16 workspace the operator takes is a per-call allocation inside FlashInfer (freed on return), so the route holds no persistent scratch and the pipeline's peak memory stays below stock.
- **Strided q/k/v views** (fused-QKV column chunks or pre-attention pack slices) consumed in place by the BF16 packed-varlen attention, contiguous output.

The route's contiguous-copy, int32-cast and RoPE-gather helpers and the "rows != 9" fallback are removed, so no copy / cast / gather kernel runs between the stages. The admission key now includes strides and `qk_eps`; the DiT passes `norm1.eps` and the Q/K-norm eps separately (gated on `q_norm.eps == k_norm.eps`). Operands outside the kernel contract still fall back to the stock kernels with one log line per reason.

Shared helpers `table_view_ok` / `thd_view_ok` in `cake_kernels/_support.py` implement the view contracts. The MXFP8 / NVFP4 pre-attention chains and `minimax_h3_qkv_quantize_pack` keep their exact-shape contract (contiguous `[9, 5376]` tables, int32 index, per-row RoPE table).

## End-to-end evidence (GB200, sglang:26.07 container, source FlashInfer `f62ffa92a12`, FL2VA t2va 768 / 4 s / 8 steps, TP1)

**Admission (`SGLANG_CAKE_DEBUG=1`).** With the engine's operands passed through, all four stages log `Cake kernel selected` on every call: `bf16_pre_attention`, `out_proj` and `fc1_swiglu` 350 / 350 block calls each (50 calls with 3-row AdaLN / gate tables `(3, 5376)/stride(32256, 1)`, 300 calls with 6-row tables, int64 index), `varlen_attention` 352 / 352 on the strided fused-QKV views `stride(21504, 128, 1)` / pack views `stride(21504, 384, 1)`. Zero fallbacks. A torch.profiler trace of one full DiT forward shows no copy / cast / gather kernels between the stages (the only host→device traffic is the one-shot attention entry's four small plan uploads per block).

**Per-stage kernel time, one DiT forward (T = 32640, 50 blocks, CUPTI via torch.profiler):**

| stage | Cake (ms / block) | stock chain (ms / block) |
|---|---|---|
| pre-attention (norm + AdaLN + QKV + Q/K norm + RoPE) | 18.8 | ≈ 5.6 (RMSNorm 0.15, indexed scale/shift 0.25, cuBLAS QKV 4.2, fused qk-norm+RoPE 0.97) |
| packed-varlen attention | 18.5 – 21.9 | 22.2 (cuDNN SDPA) |
| out-projection + gated residual | 1.48 | 1.93 |
| norm + AdaLN + FC1 + SwiGLU | 5.59 | 6.95 |

**DiT step time (CUDA events around the DiT forward, three alternating stock / Cake pairs, same GPU):** all four stages on Cake: 2427 ms vs 2022 ms stock (1.20×). With the pre-attention stage held back (harness switch) the other three stages give 1999 ms vs 2021–2029 ms (0.985–0.989×).

**Parity.** Block-level stock-vs-Cake comparison inside the real model on identical inputs (stock-vs-stock rerun is bit-identical): with attention + out-proj + FC1 on Cake, relative RMS deviation 0.15–0.23 % (blocks 0 / 24 / 49), i.e. BF16 rounding level; frame-level PSNR vs stock 22.6–27.8 dB over three samples against a 32.8 dB stock run-to-run floor (trajectory divergence of the 8-step sampler, as in the earlier attention-only measurement). **With the BF16 pre-attention stage on Cake the block outputs are wrong** (block 0: RMS deviation larger than the signal, 95 % of elements outside tolerance; frame PSNR 13.6–14.7 dB).

**Root cause (kernel side, not this route):** the FlashInfer entry documents `qkv_weight [21504, 5376]` with row order `[head, qkv_kind, head_dim]`, while the model's fused `qkv_proj` produces `[q | k | v]` column blocks, i.e. rows ordered `[qkv_kind, head, head_dim]`. The route hands the model weight through as it is (as it should), so the fused GEMM pairs the wrong rows with the per-head epilogue. The same kernel is also 3.4× slower than the stock chain at this shape regardless of the Ulysses degree (17.2 ms standalone for P ∈ {1, 2, 4, 8}; cuBLAS QKV GEMM alone 4.4 ms). Both are tracked on the kernel side; until the FlashInfer kernel consumes the model's row order, the pre-attention stage of this route must not be relied on. The PR is therefore kept as a draft.

**Peak device memory (pipeline-reported peak reserved):** stock 125 494 MB; Cake 125 978 MB with all four stages (+484 MB), 126 500 MB with three stages (+1006 MB). Inside the DiT forward the Cake arm peaks ≈ 1.9 GB above stock (123.35 vs 121.40 GB allocated); the pack-lifetime fix in the DiT block is included, the remainder is being attributed per stage.

Harness: alternating one-process-per-run driver, sitecustomize hooks for the DiT forward timer, one-step profiler, route-admission counter, memory probes and the block-level A/B; raw frames, videos and traces stay on the compute node (manifest with sizes and SHA-256 kept with the run).
