# [Feat] diffusion: Add expert parallelism for MoE DiTs

[Upstream PR](https://github.com/sgl-project/sglang/pull/37357) · state: open · merged: False

## Original PR description

## Motivation

MoE DiTs are growing, and SP shards activations but not experts: every rank still stores all routed experts. This PR adds expert parallelism (EP) to SGLang Diffusion, with LingBot-Video MoE (128 routed experts) as the first supported model. On 2×H100, EP2 cuts peak memory by 26.2 GB/GPU (43%) for 12% more latency.

## Modifications

Two commits:

1. **Fix LingBot SP.** LingBot under SP produced wrong output before this PR (RoPE positions restarted at zero on every rank, and replicated text was gathered as distinct shards). It now shards video tokens inside the DiT, slices global RoPE positions per rank, and passes text as `num_replicated_suffix`. 81 frames are no longer rounded to 85. EP depends on this.
2. **Add EP.** `--ep-size`, a per-pipeline capability gate, expert-sharded checkpoint loading, and a fixed-capacity dispatcher.

**Design decision: EP reuses the SP group (`ep_size == sp_degree`).** SP already gives every rank the same token count, so dispatch is one equal-split all-to-all with static shapes and no host sync. Non-local routes carry a `-1` expert ID and are masked; partials are reduced in FP32 by the existing `moe_fused_mul_sum`.

| Alternative considered | Result | Decision |
| --- | --- | --- |
| Replicated tokens (no SP) | 1711 vs 1245 ms/step | Keep SP; replication duplicates attention |
| Variable-split Torch dispatcher | 1133 vs 1051 ms/step, ~20× more variance | Fixed capacity; no per-block host sync |
| Eager / compiled reducer | 3.64 / 1.07 vs 0.211 ms | Reuse `moe_fused_mul_sum` |

## Scope and scaling

- Qualified: EP2/SP2, single-node CUDA, LingBot-Video MoE. Other valid topologies are accepted but unmeasured.
- Rejected with EP: FSDP inference, `torch.compile`, disaggregated serving, live full-weight updates (LoRA updates still work).
- LingBot SP rejects dynamic batching and requires the video token count to divide by the SP degree.
- Dispatch traffic grows linearly with `ep_size`. Large EP (`ep_size ≫ sp_degree`) needs an independent EP group and a route-aware transport; the `dispatch`/`combine` interface allows swapping it in later.

## Accuracy Tests

- **MoE block:** EP vs dense relative Frobenius error 2.96e-3 (limit 5e-3); repeated runs are bit-identical per topology.
- **Full DiT (2 GPUs):** tiny LingBot DiT, dense vs SP2 and dense vs SP2+EP2, both pass.
- **Real model:** 81-frame videos from 1 GPU, SP2, and SP2+EP2 are coherent with no shard seams. EP is not bit-exact, so 40 steps turn small BF16 differences into a different sample for the same seed; a 2-step run confirms all three start from the same noise.
- Unit and kernel suites pass (296 tests on H100).

## Speed Tests and Profiling

2×H100, SP2 (`--ulysses-degree 2`), 81 frames, 480×480, 40 steps, BF16, one warmed-up request per configuration.

| Configuration | Denoise | Request | Peak memory/GPU |
| --- | ---: | ---: | ---: |
| SP2 + EP1 | 1.70 it/s | 27.04 s | 61.2 GB |
| SP2 + EP2 | 1.43 it/s | 30.27 s | **35.1 GB** |

EP2: +12% latency, −26.2 GB/GPU, matching the expected halving of ~54 GB of routed experts.
