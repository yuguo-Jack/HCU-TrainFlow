# [Bugfix] Preserve available host memory for integrated MUSA devices

[Upstream PR](https://github.com/sgl-project/sglang/pull/43398) · state: closed · merged: True

## Original PR description

## Motivation

The MUSA branch of `get_available_gpu_memory()` selects host available memory for integrated devices, then immediately overwrites it with `torch.musa.mem_get_info()`. The CUDA branch already keeps these alternatives separate.

The same conditional fix was proposed by @yinli-systems in the closed, unmerged #25415. This PR is limited to that memory query and adds regression coverage.

## Modifications

Put the device-memory query in `else`. Cover integrated/discrete devices with cache clearing enabled and disabled in the existing CPU-registered platform tests. The test checks both the returned GiB value and that the unused memory source is not queried.

## Accuracy Tests

Normal package imports, CPU-only Linux/Python 3.12, Torch 2.11.0+cu130, Transformers 5.19.0:

```bash
python test/registered/unit/platforms/test_platform_interface.py
pytest test/registered/unit/platforms/test_platform_interface.py -q
```

Direct invocation: 73 tests pass. Pytest: 73 tests and 25 subtests pass. On unchanged main with the new test, the two integrated-device subcases fail (`2.0 != 6.0`); discrete-device controls pass. Both arms emit the same 23 pytest warnings.

The MUSA device/memory boundaries are mocked; no MUSA hardware or model execution was performed. Dependencies are inherited, not a qualification of the complete official CI environment.

Not applicable: this fixes a memory-capacity query, not kernel or inference performance.
