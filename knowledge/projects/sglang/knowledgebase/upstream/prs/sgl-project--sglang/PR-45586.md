# [Fix] dsv4: Write idle SWA stores to an idle request-window layout

[Upstream PR](https://github.com/sgl-project/sglang/pull/45586) · state: closed · merged: True

## Original PR description

- `DeepseekV4AttnBackend.get_swa_out_cache_loc` no longer reads attention metadata on an idle forward under `--enable-encoder-swa-bounded-replay`. It returns the write locations of `RequestWindow.activate_idle`, a cached layout whose rows land in the workspace past an empty history.
- Under speculative decoding, a padded idle forward (a DP-attention rank with no requests, padded to the busy ranks' token count) skips `init_forward_metadata`. The store then read the previous forward's request-window layout, or `None` after an unpadded idle. The result was either a `TensorMatcher` failure in `fused_k_norm_rope_flashmla` (the stale `write_loc` length does not match the padded rows) or `AttributeError: 'NoneType' object has no attribute 'core_attn_metadata'`.
- Repro: DeepSeek-V4.1-Flash, DEP4 on 4x GB300, `--moe-a2a-backend megamoe --speculative-algorithm DSPARK --enable-encoder-swa-bounded-replay`, GSM8K through sgl-eval (200 examples, 64 threads, max tokens 4096, temperature 0, no thinking). The server crashed at 197/200 when one rank ran an idle verify. With this change the run completes 200/200 at 97.50%, the same score as without encoder replay.
- The repro above ran with the Engram idle fix of #40424 applied, since main then failed first with `engram serves extend, target-verify and decode, not 4` on the same idle forward; #40424 has since merged.

No behavior change outside idle forwards with `--enable-encoder-swa-bounded-replay`; idle rows were already discarded and never committed.
