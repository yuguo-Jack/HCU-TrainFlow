# [Spec][DSpark] Use live gamma for DSV4 confidence

[Upstream PR](https://github.com/sgl-project/sglang/pull/40395) · state: closed · merged: False

## Original PR description

## Motivation

`--speculative-num-draft-tokens` may override the DSpark checkpoint block size. The worker and folded proposer honor the runtime gamma, but `DeepseekV4ForCausalLMDSpark.compute_confidence()` reshaped the confidence tap with the checkpoint's `self.gamma`.

When checkpoint and runtime gamma differ, folded graph capture can therefore apply an incompatible confidence shape.

## Modifications

- Derive confidence geometry from the live `sampled_tokens` shape.
- Use the live gamma when constructing Markov-history features.
- Validate sampled-token and hidden-row geometry with actionable errors.
- Preserve view semantics for graph capture.
- Add a CPU regression covering a runtime gamma override.

## Accuracy Tests

- Runtime-override confidence output shape.
- Markov predecessor-token construction.
- Explicit rejection of mismatched hidden-row geometry.

## Speed Tests and Profiling

No behavior or cost change is expected when runtime gamma equals checkpoint gamma. No public performance claim is made in this PR.
