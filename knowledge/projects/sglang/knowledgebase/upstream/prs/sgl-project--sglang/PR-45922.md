# [Fix] disaggregation: Restart a lost prefill's heartbeat miss count

[Upstream PR](https://github.com/sgl-project/sglang/pull/45922) · state: closed · merged: True

## Original PR description

## Motivation

The decode-side heartbeat checker in `CommonKVManager` drops a prefill after `max_failures` consecutive missed `/health` probes. `_handle_node_failure` then removes the prefill's connections, its `prefill_info_table` entry and its room tracking, but leaves `heartbeat_failures[addr]` at `max_failures`.

A later request that reaches the same prefill registers it again, and the checker probes it again. If the first probe after the reconnect succeeds, the count resets. If it misses, for example because the prefill is busy for a few seconds, the count becomes `max_failures + 1` and the prefill is dropped again at once. Every request in flight to it then fails. A prefill that is reached again should need `max_failures` misses before it is dropped, like any other prefill.

## Modifications

- `_handle_node_failure` also removes `heartbeat_failures[addr]`, together with the rest of the prefill's state.
- Tests in `test_nixl_backend_basic.py` (CPU):
  - The existing node-failure test now also checks that the failed prefill's count is removed and the other prefill's count is kept.
  - A new test runs the heartbeat thread through miss, miss (drop), reconnect, miss, success, miss, success. With this change the prefill is dropped once. On main it is dropped twice.
