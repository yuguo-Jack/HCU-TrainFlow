# [Fix] rust-server: Read skip_special_tokens on the OpenAI routes and pin per-request detokenization

[Upstream PR](https://github.com/sgl-project/sglang/pull/47016) · state: closed · merged: True

## Original PR description

## Motivation

Python's OpenAI layer accepts a `skip_special_tokens` request extension on `/v1/completions` and `/v1/chat/completions` (default `true`). The Rust frontend's `/v1/completions` handler and the typed `/v1/chat/completions` handler dropped it, so a client sending `"skip_special_tokens": false` still had special tokens stripped from the output text, although the same request on the Python server keeps them.

## Modifications

- `/v1/completions` and the typed `/v1/chat/completions` handler read `skip_special_tokens` off the request and apply it to the request's sampling params. When the field is absent the sampling default (drop them) still applies. On chat, the request value is applied before the model-specific override that keeps special tokens for reasoning parsers, so that override still wins, as on Python.
- A detokenizer unit test (`special_tokens_follow_each_requests_flag_while_streaming`) with a tiny WordLevel tokenizer fixture (`testdata/special_token_tokenizer.json`, `<eot>` special). It streams `[a] [<eot> b] [c <eot>]` (final chunk: matched stop `<eot>`) through three co-located requests on one shard: keep, skip, and keep with `no_stop_trim`, and expects `a | <eot>b | c`, `a | b | c`, and `a | <eot>b | c<eot>`. This pins per-request decoder state, special tokens kept across chunk boundaries, and matched-stop trimming with special tokens kept.

The per-request plumbing of `skip_special_tokens` from the request to the detokenizer shard (`DetokMsg::Register`, `DetokenizerBackend::new_decoder`) already exists on main; this PR adds the OpenAI request fields that feed it and the regression test.

Local checks: `cargo fmt --all -- --check`, `cargo clippy --locked -p sglang-server --all-targets -- -D warnings`, and `cargo test --locked -p sglang-server` (includes the new test).
