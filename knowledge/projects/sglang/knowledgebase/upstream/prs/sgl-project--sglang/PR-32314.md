## Motivation

https://github.com/sgl-project/sglang/issues/43098

HiSparse (`--enable-hisparse`) enables high-concurrency long-context decode for sparse attention models by keeping only the indexer KV and a small per-request buffer on GPU. It has two structural drawbacks:

1. **Incompatible with the radix cache** (`--disable-radix-cache` is required), so shared-prefix and multi-turn workloads get no prefix reuse;
2. **Full KV lives only on its private host pool** — the regular GPU KV pool is bypassed, so GPU HBM that could cache hot KV goes wasted.

**HiSparse V2** (`--enable-hisparse-v2`) uses **HiCache as the logical KV pool**, which directly fixes both: attention KV lives in the regular GPU pool + radix tree (full prefix reuse, hot KV kept in HBM) and is written back to host only under memory pressure. Indexer KV stays GPU-resident in an expanded region so the indexer can always score the full history, and each decode step swaps in just the top-k attention rows. Works with overlap scheduling and decode CUDA graphs.

## Modifications

- Preserve GPU index pages using Device/Host page addresses, sharing indexes across requests. Default index capacity is **`(1+r)G`**, plus page padding, for Device capacity `G` and Host ratio `r`.
- Reuse the existing MLA CUDA JIT swap kernels with resident-row reads, shared hot/scratch buffers, and MTP miss deduplication.
- Reserve hot/scratch together before prefill; coordinate prefix eviction, Host locks, and release through HiCache. Reuse the indexer page table across layers and refresh it for CUDA graph replay.
- Support chunked prefill, overlap scheduling, decode CUDA graphs, and one linear EAGLE/MTP draft (`topk=1`, 2–4 draft tokens). Add configuration checks, regression tests, and documentation.

Usage:

```bash
--enable-hisparse-v2 --enable-hierarchical-cache \
--hicache-write-policy write_back --hicache-ratio 2 \
--hicache-mem-layout page_first --page-size 64 \
--hisparse-config '{"top_k":2048,"device_buffer_size":4096}'
```

Synthetic prompts contain exactly 64K/128K input tokens and generate 1024 tokens. Shared inputs use **65% identical prefixes**, selected from DSv3.2's shared candidates and reused for GLM.

Each cell is **Decode tok/s (stable concurrency per DP rank)**; multiply concurrency by four. Throughput sums each rank's median at its highest stable batch, excluding prefill/retract intervals; these rank intervals need not occur simultaneously.

## Pull request overview

This PR introduces **HiSparse V2** (`--enable-hisparse-v2`), integrating HiSparse with **HiCache + unified radix cache** so sparse-attention models can reuse shared prefixes and keep hot KV in GPU memory while spilling under pressure to host memory.

**Changes:**
- Adds the HiSparse V2 coordinator and dual-source swap-in Triton kernels for host/device KV sourcing during sparse decode.
- Updates scheduler and budget/admission logic to account for V2’s per-request device buffer floor and host/indexer expanded quotas.
- Hardens unified radix cache write-back eviction behavior (including a write-back fallback path and a cross-rank divergence probe).
