# [Perf] [AMD] spec: Sort-free top-p and many-row softmax for HIP verify

[Upstream PR](https://github.com/sgl-project/sglang/pull/46808) · state: open · merged: False

## Original PR description

## Summary

On ROCm, EAGLE with topk=1 turns on rejection sampling by default. Each verify step then runs a temperature softmax and a top-p renorm over `bs × num_draft_tokens` target rows. For GLM-5.3-Flash (vocab 154880, 6 draft tokens) at concurrency 64 that is 384 rows, and both steps were slow:

1. Top-p found the cutoff with a full `torch.sort` and `cumsum`. It now bisects on the fp32 bit patterns, which order like int32 for non-negative values: 10 passes, no sort.
2. The split softmax stopped at 32 rows and fell back to `torch.softmax`. It now covers any row count.

| Kernel (µs), rows × 154880 | 48 rows base | this PR | 384 rows base | this PR |
| --- | --- | --- | --- | --- |
| top-p renorm | 927 | **116** | 4426 | **739** |
| temperature softmax | 75 | **19** | 261 | **129** |

## Scope

HIP only; CUDA is unchanged. Top-p keeps the same rule (keep every token at or above the pivot, ties included) and can differ from the sort by one token only when the cutoff is within fp32 rounding; the denominator sums the kept tokens, so rows sum to 1 even for tiny top_p. Top-k still sorts. The softmax block is capped at 4096 to avoid register spills; other vocab sizes do not regress (softmax time, this PR / base, MI355X, CUDA graph):

| Vocab | Model | 1–32 rows | 33–1024 rows (base = `torch.softmax`) |
| --- | --- | --- | --- |
| 129280 | DeepSeek-V4.1-Flash, DeepSeek-V4-Pro | 0.77–0.86 | 0.26–0.56 |
| 151936 | Qwen3-Next-80B-A3B | 0.70–0.86 | 0.22–0.55 |
| 154880 | GLM-5.3, GLM-5.3-Flash | 0.70–0.86 | 0.22–0.54 |
| 163840 | Kimi-K3 | 0.71–0.86 | 0.23–0.54 |
| 200064 | MiniMax-M3 | 0.69–0.89 | 0.20–0.57 |
| 202048 | Muse-Spark-Open | 0.69–0.88 | 0.21–0.57 |
| 248320 | Qwen3.5, Qwen3.8 | 0.75–0.88 | 0.18–0.58 |

Max abs error vs `torch.softmax` is 1.1e-6 over all 91 shapes.
