# [Fix] dsv41: Surface malformed tool output as explicit API errors

[Upstream PR](https://github.com/sgl-project/sglang/pull/46009) · state: open · merged: False

## Original PR description

## Motivation

A real V4.1 agent turn ended successfully with an empty assistant message after
the model generated a malformed DSML parameter header:

```text
parameter name="max_output_tokens": 60000
```

The model should have generated the normal `string="false">60000` syntax.
Output capture established that this was malformed model output, not corruption
introduced by the parser. The parser correctly rejected the call, but dropping
it silently turned the result into an apparently successful end of turn.
The intended command did not execute.

## Modifications

- Add `ToolCallParseError`, with V4.1 opting into explicit rejection. V3.2 and V4
  keep their existing drop policies.
- Surface malformed parameters, malformed invoke headers and unfinished invokes
  instead of returning an empty successful turn. Do not repair arguments.
- Preserve the typed error through the serving layer's broad exception handlers.
  Non-streaming returns HTTP 400; an already-started stream emits an SSE error
  through the existing error path and performs normal generation cleanup.
- Do not include rejected arguments in the error, forward DSML as assistant
  content, or issue an automatic retry. Earlier valid streamed calls cannot be
  recalled, so replaying the whole generation could duplicate tool execution.
- Add 15 CPU-registered parser and ASGI serving tests using synthetic generation;
  no model weights or tools are executed.

## Related Work

#42442 addresses strict validation/recovery by returning rejected syntax as text.
This PR deliberately chooses an explicit API failure instead, keeps existing
valid-body parsing rules, and scopes the changed rejection policy to V4.1.
It does not add an environment switch or automatic model recovery.

#44464 handles replaying client-rejected arguments in supplied history. This is
a different failure: malformed generated DSML was discarded before it reached
the client or its saved history.

## Accuracy Tests

On current main `8708d2ee9995`:

```sh
PYTHONPATH=python python test/registered/unit/function_call/test_deepseekv41_parse_errors.py
PYTHONPATH=python python test/registered/unit/function_call/test_deepseekv41_detector.py
PYTHONPATH=python python test/registered/unit/function_call/test_deepseekv4_detector.py
```

All 15 new tests, 10 existing V4.1 tests and 25 existing V4 tests pass. Coverage
includes one-character streaming boundaries, malformed/valid mixed batches,
valid parallel and zero-argument calls, redacted error text, HTTP/SSE responses,
generation cleanup and absence of implicit retries.

The equivalent patch is also deployed on SGLang `ed0b8f433f88` plus the dual-EPYC
integration recipe. The 15 tests pass inside that serving image; normal gateway
Chat, Responses function-tool/result rounds and streaming/non-streaming custom
tools pass. The deployed LiteLLM version propagates synthetic HTTP/SSE parser
errors through both Chat and Responses. These are transport/serving checks, not
proof of automatic agent recovery or GPU qualification of this main-branch port.

## Speed Tests and Profiling

No inference kernels or generation policy change, and no performance improvement
is claimed. The change makes rejected model output visible at the API boundary.
