## Original PR description

# [AMD] Default consumer RDNA to Triton attention

## Summary

Use Triton as the default attention backend on `gfx1100` and `gfx1201`, where AITER is not the validated default. Also disable automatic Lean Attention selection on those targets.

On gfx1201, the Lean kernel selected during decode graph capture exceeded the device shared-memory limit:

```text
Required: 66560 bytes
Hardware limit: 65536 bytes
```

Explicit user choices remain authoritative. Existing defaults on gfx942, gfx950, and gfx1250 are unchanged.

## Changes

- When no attention backend is specified, return `triton` for gfx1100/gfx1201 instead of the generic ROCm `aiter` default.
- Cache whether Lean auto-selection is supported when constructing `TritonAttnBackend`.
- In automatic mode (`enable_lean_attention=None`), use standard Triton decode on gfx1100/gfx1201 before applying the existing Lean heuristics.
- Preserve explicit `--enable-lean-attention` for bring-up and tuning.
- Preserve `SGLANG_DISABLE_LEAN_ATTENTION=1` as the highest-priority kill switch.

## Scope

This changes only default backend selection for gfx1100/gfx1201. It does not modify the AITER, Lean, or standard Triton kernels, and it does not change gfx942/gfx950/gfx1250 policy.

## Validation

Models successfully run on RDNA where Lean Attention is not validated.
