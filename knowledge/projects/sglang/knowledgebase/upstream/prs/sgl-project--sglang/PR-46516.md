# [Refactor] dsv4: Write the replay tail's outputs into caller-held prefill graph bridges

[Upstream PR](https://github.com/sgl-project/sglang/pull/46516) · state: closed · merged: True

## Original PR description

- The DeepSeek V4 replay tail's break in the outer prefill graph writes its outputs (residual, the pre-norm state, aux tensors) into a bridge the caller passes and returns nothing; the captured segment after the break reads views of that same bridge. Before, the break copied into the newest bridge and returned views of it, and the graph wrapper copied those into the views it had captured.
- The caller looks the bridge up with `_bridge` and passes it to the break. On the first run, a warmup, there is none, and the break allocates it from the real outputs; a capture asserts the bridge already exists, which the warmups before each capture guarantee. Bridges are keyed by `(capture_dspark, has_pre)` instead of the outputs' dtypes and shapes; `_write_bridge` asserts the outputs match the bridge it writes. Graphs captured on an older, smaller bridge keep writing and reading it.
- The candidate table break from #46399 relies on the same warmup; its call site gets the same assert.
- A unit test covers a graph that keeps writing its own bridge after a larger block allocates a new one.
- No behavior change intended. The changed path runs only with the breakable prefill graph and the replay tail; GPU runs pending.
