# [Fix] Kimi-K3: tool_choice required/none grammars

[Upstream PR](https://github.com/sgl-project/sglang/pull/46644) · state: open · merged: False

## Original PR description

## Motivation

With Kimi-K3's structural-tag grammar:
- `tool_choice=required` could never finish the turn. K3 emits `MESSAGE_CLOSE` before EOS, and EOS is masked until the grammar completes, so a model that wanted no tool looped on `MESSAGE_CLOSE` until `max_tokens`.
- `tool_choice=none` still let the model emit a tools section. The encoder lists tools even for `none`, and tool-call parsing is off, so raw call markup leaked into `content`.
- Excluding whole markers from free text let near-miss markers through, e.g. `<|open|>tools<|close|>message`.

## Modifications

- The grammar allows an optional `MESSAGE_CLOSE` after the tools close.
- `required`: free text excludes `MESSAGE_CLOSE`, so a tools section is the only continuation.
- `none`: the output excludes `TOOLS_OPEN`/`CALL_OPEN`.
- Free text excludes the `<|open|>tools`, `<|close|>tools` and `<|close|>message` prefixes instead of the whole markers.

## Accuracy Tests

`test_kimik3_structural_tag.py` fails on `main` and passes with this PR. The one unrelated failure (`test_serving_chat.py` `inkling` streaming) also fails on `main`.
The same grammars run in the Kimi-K3 MI355X production build. In BFCL and the edge/API suite there, `required` always produces a call, `none` never does, and no raw markup appears in `content`.
