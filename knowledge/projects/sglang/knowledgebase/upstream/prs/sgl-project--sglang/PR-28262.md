# Fix bug when both enable piecewise cuda graph and mamba extra buffer

[Upstream PR](https://github.com/sgl-project/sglang/pull/28262) · state: closed · merged: False

## Original PR description

## Summary
Fix tc_piecewise prefill coverage for the Mamba tracking path used by extra_buffer scheduling, while keeping the shared piecewise entry model shape-only.

## Motivation
When mamba extra_buffer is enabled, some prefill batches may enter the mamba_track_mask=True branch after crossing the Mamba cache chunk boundary. However, tc_piecewise warmup/capture previously biased toward the default non-tracking path, which could leave replay behavior inconsistent with runtime execution.
This PR makes the CUDA path explicitly cover the Mamba tracking branch and restores a cleaner backend boundary by avoiding tracking state in the shared piecewise entry key.

## Changes
Warm up both Mamba states (track=True and track=False) so torch.compile sees both branches.
Capture an additional track=True graph for shapes that may trigger Mamba tracking.
Dispatch replay to the tracking graph when the runtime batch requires Mamba tracking.
Restore the shared piecewise entry model to shape-only management instead of encoding tracking state into the shared entry key.
Keep tracking-specific graph handling local to the backend implementation, without changing the shared piecewise backend contract.

## Testing
Verified the updated tc_piecewise warmup / capture / replay control flow.

## Code Review

This pull request introduces support for dual CUDA graph capture and replay for Mamba models when tracking is enabled. It adds a new `VariantGraphEntry` dataclass to track extra CUDA-only graph states and refactors `CUDAPiecewiseBackend` and `PrefillCUDAGraphRunner` to handle both tracking states during warmup and capture. Feedback on these changes highlights two critical issues: first, using the PEP 604 union operator `|` in type annotations may cause import-time `TypeError`s on Python 3.9; second, calling `.item()` on a GPU tensor in the hot path of `__call__` introduces blocking host-device synchronization, which negates the latency benefits of CUDA graphs.
