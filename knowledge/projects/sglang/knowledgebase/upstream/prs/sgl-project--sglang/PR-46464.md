# [Perf] [NVIDIA] kimi-k3: FP32 warp split-K GEMM for the MoE front projection on SM107

[Upstream PR](https://github.com/sgl-project/sglang/pull/46464) · state: closed · merged: True

## Original PR description

## Motivation

Kimi-K3's merged MoE front projection (`(N, K) = (6016, 7168)`, FP32 output so the router logits keep their precision) runs through TGV at the spec-verify batch sizes. On SM107 a warp split-K design with cp.async ring loads is faster at `M = 8, 16, 32`.

## Modifications

- `dense_bf16_gemm_warp_splitk.py` (new, **temporary copy**): FlashInfer already ships this kernel as `flashinfer/gemm/kernels/dense_bf16_gemm_warp_splitk.py` (`run_warp_splitk_dense`, also behind `flashinfer.gemm.bf16_gemm_sm100` with the cute-dsl runners), but its input validation only accepts a bf16 `out`, in 0.7.2.post1 and on main. K3's merged front projection needs FP32 output to keep router-logit precision, so this copy differs from FlashInfer's file by 71 lines, essentially `out.dtype in (bf16, fp32)` and keying the compile cache on the output dtype. Plan: land FP32 output in FlashInfer, then delete this module and call FlashInfer's kernel from the dispatch below (the file header and the dispatch carry that note).
- `cutedsl_bf16_gemm.py`: dispatch it (with pinned tactics for M = 8, 16, 32) only on SM107 for the exact `(6016, 7168)` shape at `M in {8, 16, 32}` with FP32 output and no bias; every other case keeps the existing dispatch.
- `test_cutedsl_bf16_gemm.py`: SM107-only test comparing against `torch.mm` in FP32 and checking the router top-16 selection is unchanged (skipped elsewhere).

## Accuracy Tests

Max abs error against PyTorch FP32 output 0.001221 (tolerance 0.005); router top-16 sets match on every row. `test_cutedsl_bf16_gemm.py` on SM107 with this branch: 462 passed (including the three new M cases).

## Speed Tests and Profiling

One SM107 GPU, BF16 inputs, FP32 output, eight rotated weights, 41 interleaved CUDA-graph samples, median us per GEMM:

| M | TGV (current) | warp split-K | reduction |
|---:|---:|---:|---:|
| 8 | 9.400 | 7.604 | 19.1% |
| 16 | 10.704 | 7.944 | 25.8% |
| 32 | 10.820 | 9.212 | 14.9% |

92 front GEMMs per verify step; the M=8 delta projects to about 0.165 ms per step.
