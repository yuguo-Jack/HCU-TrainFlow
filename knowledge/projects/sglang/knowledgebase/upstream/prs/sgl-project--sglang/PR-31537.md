# [1/N] [spec] align draft-extend graph-replay buckets with can_run_graph

[Upstream PR](https://github.com/sgl-project/sglang/pull/31537) · state: closed · merged: False

## Original PR description

## Motivation

Prerequisite of #30877 (enable STANDALONE + DP attention).

Under `require_mlp_tp_gather`, `execute()` sizes CG replay buckets from `global_num_tokens_cpu` (request count scaled by spec width), which diverges from the `max(original_global_num_tokens_cpu)` (raw per-rank request count) used by `can_run_graph()`.

This mismatch causes assertion failures (exceeding the max captured bucket) for STANDALONE. This PR aligns `execute()` to size replay buckets from the same raw request count as `can_run_graph()`.

**NOTE:** EAGLE already applies `// self.captured_req_width` to scale back to the request axis, and the ceil-alignment path is eager-only (see [here](https://github.com/sgl-project/sglang/blob/58f417049d8a387c3d24e165696c0792c7c97716/python/sglang/srt/model_executor/model_runner.py#L1492-L1506)), so this change is a no-op for EAGLE.

## Modifications

Remove the `is_eagle()`-gated `// captured_req_width` branch and size the replay bucket from `max(original_global_num_tokens_cpu)`, matching `can_run_graph()`.

**Out of scope:** the same mismatch exists in `eagle_draft_cuda_graph_runner.py` and `decode_cuda_graph_runner.py`. I leave them untouched to keep this prerequisite minimal and will open follow-up PRs to fix them.

## Unit Tests

Runtime path (STANDALONE + DP attention) is gated on main, so coverage is a CPU unit test asserting `can_run_graph()` admits and `execute()` sizes the replay bucket from the same raw request count:

- Over-pad: pre-fix picks the scaled count `6`, leading to over-padding.
- Crash: pre-fix picks the scaled count `35`, exceeding the max capture bucket.
