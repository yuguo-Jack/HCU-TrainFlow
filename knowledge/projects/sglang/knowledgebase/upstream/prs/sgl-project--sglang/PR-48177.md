# [Fix] glm45: Handle unserializable tool arguments

[Upstream PR](https://github.com/sgl-project/sglang/pull/48177) · state: closed · merged: False

## Original PR description

## Motivation

The GLM-4.5 parser falls back to Python literal parsing when a tool argument is not valid JSON. A set, bytes, or complex value then fails JSON serialization, which drops a non-streamed call. A stream ends with `TypeError: Object of type set is not JSON serializable`, no finish reason, and no `[DONE]`.

GLM-4.5 and GLM-4.6 use this parser. `get_structure_constraint("auto")` returns `None` for `glm45`, `glm`, and `ling3`, so unconstrained model output can reach the fallback for any non-string-typed parameter.

#44111 independently fixes the same fallback in the GLM-4.7 parser.

## Modifications

Check the literal with `json.dumps`. If that fails, keep the original argument text as a string. The Ling3 parser inherits this function. On both parsers, output changed only for inputs that failed on main.

Two limits stay as on main:

- Values of a declared non-string type stream verbatim, so a Python literal still gives invalid JSON deltas.
- `{'a': 1e999}` gives non-standard `Infinity`.

Open #43264 fixes a separate tuple bug on the same lines, so the two PRs conflict. The second to land keeps both changes, with `json.dumps` before the tuple branch, so that `(1, {2})` also keeps the call.

## Accuracy Tests

Each row ran a server on one B200, on main `cbfc0932e3` and then with this diff. The lab has no GLM-4.5, GLM-4.6, or Ling-3 weights, so the server used GLM-4.7-Flash weights with the `zai-org/GLM-4.5` chat template. The parser and template differ from the GLM-4.7-Flash cookbook flags.

```text
--reasoning-parser glm45 --tool-call-parser glm45 --chat-template chat_template.jinja --attention-backend triton --tp 1
```

Requests used temperature 0, thinking off, and `tool_choice` auto unless the row says otherwise. In rows with no client constraint, the prompt asked for the literal after one earlier tool call.

| Route | Case | Main | This diff |
| --- | --- | --- | --- |
| No client constraint | Array parameter, `{"env:prod", "service:web"}`, non-streamed | Call dropped, raw markup as content, finish reason `stop` | Raw text as a string argument, finish reason `tool_calls` |
| No client constraint | Same input, streamed | No finish reason, no `[DONE]`, `TypeError` under `Exception in ASGI application` in the server log | Finish reason `tool_calls`, `[DONE]`, no exception in the log. Deltas stay invalid JSON, `{"value": {"env:prod", "service:web"}}` |
| No client constraint | Number parameter, `b'abc'` | Same failures as the two rows above | Non-streamed `{"value": "b'abc'"}`. The stream finishes, and deltas stay invalid JSON |
| No client constraint | Array parameter, valid `["env:prod", "service:web"]` | Normal tool call | Same output |
| Client `ebnf` forced the value | Set, `{1, 2}`, `b'abc'`, and `1j` | Same failures as the first two rows | Same results as the first two rows |
| Client `ebnf` forced the value | Valid `[1, 2]` and `5` | Normal tool call | Same output |
| `/v1/responses`, no client constraint | Array parameter, `{"env:prod", "service:web"}` | Non-streamed: raw markup as a message. Streamed: ends with `response.completed`, deltas are invalid JSON | Non-streamed: `function_call` with the raw text as a string argument. Streamed: same as main |
| `/v1/messages`, no client constraint | Same input | Non-streamed: raw markup as text, stop reason `end_turn`. Streamed: `error` event, no stop reason | Non-streamed: `tool_use` with the raw text as a string, stop reason `tool_use`. Streamed: stop reason `tool_use`, deltas stay invalid JSON |
| `tool_choice: required`, no client constraint | Array parameter, prompted set literal and `[1, 2]` | Valid JSON arguments, finish reason `tool_calls` | Same output |

The regression test fails on main `1ef3335da1` because the call is dropped. On the merge with that main, it passes, and the function-call and chat-serving unit tests and `pre-commit` found no issue.

Unprompted frequency of these literals is unmeasured and may be low. The server rows did not rerun on `1ef3335da1`. Runtime CI has not run.
