# [CI] rerun: Register the Mooncake test group

[Upstream PR](https://github.com/sgl-project/sglang/pull/46510) · state: closed · merged: True

## Original PR description

## Motivation

`/rerun-group mooncake` was rejected with [Unknown test group `mooncake`](https://github.com/sgl-project/sglang/pull/45578#issuecomment-6331677983). #45578 added a PR label, but labels do not register selective CI groups. This follow-up adds the missing group; it does not change the labeler.

Searched open PRs and issues for Mooncake rerun/group fixes; no overlapping fix was found.

## Modifications

Module: selective CI. Type: CI configuration fix.

Add a named `mooncake` group with 28 existing registered test files:
- Mooncake PD basic integration and the two HiCache Mooncake storage integrations.
- Five Mooncake direct-linker integrations: DeepSeek-V4, DeepSeek-V4.1, GLM-5.2, Inkling, and Kimi Linear.
- PP + Mooncake HiCache and runtime attach/detach coverage (including rejection of switching an already attached backend to Mooncake).
- Mooncake PD transfer/lifetime and L3 configuration/allocation unit tests.
- Shared L3 coverage for the external-linker factory, unified cache linker, embedding-store lifecycle, MLA/KDA attach validation, hybrid host-pool selection, PP prefetch tickets, prefill synchronization, and server-argument validation.

The existing resolver builds five dispatch batches: 17 files on `ubuntu-latest`, four on `2-gpu-h100`, four on `4-gpu-h100`, two on `8-gpu-h200`, and one on `1-gpu-5090`. The mixed CPU/CUDA unified-linker file follows the existing resolver's CUDA registration. Whole-file entries retain the registry's existing format.

Exclude `test_mooncake_ep_small.py`: it is disabled pending the Mooncake release with the PyTorch 2.13 collective-forwarding fix, and selective reruns do not enforce that disabled flag.

## Accuracy Tests

Local validation using the actual slash-command handler, resolver, runner config, and partitioner:
- Reproduced the original unknown-group error with the new entry removed.
- All 28 paths are unique, exist, have enabled CI registrations, and resolve without errors.
- Exercised `handle_rerun_group` through workflow payload construction with HTTP dispatch mocked: five batches, 17 CPU test files and 11 CUDA test files, correct runner labels and fork PR head SHA.
- Repeating the group name does not duplicate tests; partitioning preserves every command.
- `pre-commit run --files scripts/ci/rerun_test_groups.json` and `git diff --check` passed.

This validates dispatch/configuration, not native Mooncake/GPU execution. The underlying 28 test files were not executed locally.
