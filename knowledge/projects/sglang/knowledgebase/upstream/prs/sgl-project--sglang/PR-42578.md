# [Fix] qwen2.5: Fix quadratic regex scan in the tool-call parser

[Upstream PR](https://github.com/sgl-project/sglang/pull/42578) · state: open · merged: False

## Original PR description

## Motivation

`Qwen25Detector` (parsers `qwen`, `qwen25`, and the `trinity` subclass) finds tool calls in `detect_and_parse` with

```python
re.findall(rf"{re.escape(bot)}(.*?){re.escape(eot)}", text, re.DOTALL)
```

When the closing `\n</tool_call>` never arrives, each opening tag rescans to the end of the text, so the cost is quadratic:

| Input (repeated `<tool_call>\n `) | Before | After |
|---|---|---|
| 25 KB | 0.80 s | < 0.1 ms |
| 50 KB | 3.6 s | 0.1 ms |
| 101 KB | 12.6 s | 0.2 ms |

Tool-call parsing runs synchronously on the tokenizer manager's event loop, so one such response stalls every in-flight request. Found with an Atheris fuzzing harness that records per-input parse time.

## Modifications

- `_iter_tool_call_bodies`: a linear `str.find` scan yielding exactly the bodies `findall` returned (the closer is searched for from the end of the opener, so the shared `\n` behaves as in the regex). The now-unused `import re` is removed.
- Regression test `TestQwen25Detector::test_detect_and_parse_unclosed_tags_in_linear_time`: 74.2 s on `main`, fast here.

## Accuracy Tests

- Differential test of `main` vs patched `qwen25` and `trinity` (old `trinity` loaded against the old base), comparing `detect_and_parse` and every streaming result under random re-chunking: **0 mismatches** over 40k random plus 40k mutated well-formed inputs (about 25k produced parsed calls).
- `test/registered/unit/function_call/`: 630 passed.

## Speed Tests and Profiling

See the table above.

Note: streaming for this detector goes through `BaseFormatDetector.parse_streaming_increment`, which re-parses the whole buffer with `partial_json_parser` on every chunk while a JSON body is unclosed. That is O(n) per chunk (about 259 ms per chunk at 89 KB) and affects every detector built on the base class. Fixing it needs incremental JSON parsing, so it is left for a separate change.

Related: #42573, #42574, #42575, #42576, #42577 (same issue class in other tool-call parsers).
