# Fix HiCache storage invalidation after weight update

[Upstream PR](https://github.com/sgl-project/sglang/pull/29443) · state: closed · merged: False

## Original PR description

## Summary

- Clear HiCache persistent storage as part of online weight-update cache flushing.
- Propagate explicit storage-backend clear failures so stale persistent KV is not silently reused after weights change.
- Make `HiCacheFile.clear()` tolerant of concurrent file deletion during multi-rank clears.

Fixes sgl-project/sglang#26792.

## Root Cause

`update_weights_from_tensor(..., flush_cache=True)` clears the live GPU/host KV cache through scheduler `flush_cache()`, but persistent HiCache storage remains addressable with the same token/page keys. A later request with the same prompt can therefore reload KV pages computed under old model weights.

## Validation

- `python -m py_compile` on the touched Python files.
- `git diff --check upstream/main...HEAD` and `git diff --check`.
- Manual E2E on Qwen/Qwen3-30B-A3B with HiCache file storage, after merging latest upstream `main`:
  - Request A populated storage: `4173` files / `410222592` bytes.
  - `update_weights_from_tensor` with `flush_cache=True`, `abort_all_requests=True`, and `weight_version='step-1'` returned success.
  - Storage after update: `0` files / `0` bytes.
  - Request B with the same prompt reported `cached_tokens: 0` and `cached_tokens_details: None`.
  - Negative control with `flush_cache=False` preserved storage: `4159` files / `408846336` bytes before and after update.
  - Final E2E output: `E2E_ALL_PASS`.
