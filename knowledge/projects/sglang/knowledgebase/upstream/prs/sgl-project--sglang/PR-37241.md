# [NPU] Harden nightly multi-node cleanup and trim nightly single-node jobs

[Upstream PR](https://github.com/sgl-project/sglang/pull/37241) · state: closed · merged: False

## Original PR description

## Why are these changes needed?

Fixes multi-node nightly jobs hanging in the `Clear resources` / `Post process` steps and avoids parallel jobs deleting each other's pods.

- **nightly-test-npu-e2e-multi-node.yml**
  - Add `timeout-minutes` to the `Clear resources` and `Post process` steps.
  - Scope all `kubectl` calls to the job namespace and force-delete pods (`--force --grace-period=0`) with a finalizer cleanup fallback.
  - Replace the unbounded `while true` loop with a bounded retry loop and print matching pods for debuggability.
  - Uniquify `KUBE_JOB_NAME` with `test_type`/`run_id`/`run_attempt` so concurrent jobs no longer interfere with each other's pods, while keeping the value short enough for the 63-character Kubernetes pod name limit.
  - Make the shared source path unique per `run_id`/`run_attempt`/`test_config_name` so parallel jobs don't overwrite each other on the shared PVC.
- **nightly-test-npu.yml**
  - Keep only `nightly-1-npu-a3`, `nightly-4-npu-a3`, `debug-nightly-acc-2-npu-a3`, `debug-nightly-perf-16-npu-a3` and the multi-node POC jobs active and comment out the rest.
  - Fix `nightly-poc-multi-node-tests` / `nightly-poc-multi-node-mix-tests` dependencies so they only reference enabled jobs.
- **test_npu_qwen3_6_35b_a3b_1p_in64k_out1k_prefix90_50ms_aime26.py**
  - Register the qwen3_6_35b accuracy case to the `debug-nightly-acc-2-npu-a3` suite for a separate nightly re-run.
- **test_npu_qwen3_235b_w8a8_8p_in3k5_out1k5_50ms.py**
  - Register the qwen3_235b w8a8 performance case to the new `debug-nightly-perf-16-npu-a3` suite and add a workflow job to re-run it separately.
- **_npu-pr-test-stage.yml**
  - Install the `sgl-eval` CLI in the NPU PR test stage when missing.
