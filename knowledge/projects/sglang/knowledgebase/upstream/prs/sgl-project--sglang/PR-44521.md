# [Feat] engram: Unify model lookup storage with EngramStore

[Upstream PR](https://github.com/sgl-project/sglang/pull/44521) · state: open · merged: False

## Original PR description

## Motivation

Use EngramStore as the unified storage abstraction for all supported Engram model families: DeepSeek V4.1, Qwen4-Exp, LongCat Ngram, and Gemma3n/Gemma4.

Models provide row IDs and interpret returned bytes through one table contract. Shared adapters in `mem_cache/engram/` own storage integration, while each model retains its hashing, scales, projections, request history and distributed communication. Model-side changes are limited to selecting the shared adapter.

EngramStore supports local and remote storage backends through the same abstraction. This PR integrates local storage, including CUDA streams, Qwen prefetch and CUDA graph replay. **This is the companion integration for [kvcache-ai/Mooncake#4701](https://github.com/kvcache-ai/Mooncake/pull/4701) and requires a CUDA-enabled build of that PR.** The two PRs provide the storage backend and model integration respectively, and were tested together end to end. Related RFC: kvcache-ai/Mooncake#4692.

All five checkpoints across these four families were tested end to end with real weights. Under the controlled configurations below, **30/30 request outputs match native execution exactly**, including generated tokens and output logprobs.

## Modifications

- Add `--engram-backend native|mooncake` (default `native`) and `--engram-local-dir`.
- Put shared storage and embedding adapters in `python/sglang/srt/mem_cache/engram/`.
- Keep model edits small: route embedding construction through a factory, and route DeepSeek owned-row lookup through the common helper.
- Preserve model hash/history, checkpoint names, scales, projections, TP/DP/CP collectives and Qwen's existing prefetch scheduling.
- Use anonymous Mooncake-owned snapshots so worker termination leaves no named table files.
- Support normal CUDA stream ordering and graph replay without introducing a request-handle type.

Install a CUDA-enabled build of the companion Mooncake PR, then:

```bash
python -m sglang.launch_server \
  --model-path /models/gemma-3n-E2B-it \
  --engram-backend mooncake \
  --engram-local-dir /dev/shm/sglang-engram
```

The README documents ownership, warmup, immutable weights and host-memory requirements. CPU checkpoint parameters are retained in addition to the snapshot, including temporary packed rows for DeepSeek. Live table updates and remote storage are outside this PR.

#### Runtime observations and limits

- Both E2E backends use the same five prefill chunks for 4k: 1024, 1024, 768, 768, 512.
- Native huge-page coverage changed across launches without a code/configuration change. The original run had partial coverage for one Engram layer and almost none for the other; the follow-up reported approximately 100% for both layers on all eight ranks. This host runs kernel 5.10; its explicit `MADV_COLLAPSE` attempt returns `EINVAL`. The separately measured page-policy effect is too small to attribute the old E2E difference solely to that observation.
- After the timed runs, one 4k/one-output-token request per backend was profiled separately on all eight ranks. On TP0, native fused Engram gather kernels total about 1.65 ms; Mooncake byte-gather kernels total about 1.14 ms, **excluding Mooncake's subsequent GPU dequantization/masking**, so those two kernel totals are not equivalent complete-path comparisons. Main-model compute, collectives and GPU execution gaps occupy much more time. The profiled spans were about 0.52–0.53 s; profiler overhead means they must not replace the unprofiled timings above.
- The earlier run has no corresponding trace. Changing run order, startup memory state and prior request history together does not isolate a single cause. The evidence is consistent with run-dependent system state and timing effects, and supports reporting **comparable local performance**, not a causal TTFT speedup.
- This is an additional 40-request performance diagnostic, not a correctness pass: 4/20 complete generated sequences matched between its two backends. The controlled correctness checks and their limits remain documented above.

The layout/profile diagnostics used SGLang `70915471caa4` and the unchanged Engram implementation from Mooncake `e3d395959eee`. The subsequent directory-only move `7d817b57` preserves all three native source files byte-for-byte and was validated with a rebuilt CUDA wheel.

#### Table placement and memory

DeepSeek uses native **shared host tables** versus Mooncake **TP-sharded host snapshots**. Native shared lookup avoids the TP reduction used by the sharded adapter, so this comparison includes that layout/communication difference. Qwen uses native pinned-host PLE versus Mooncake host snapshots, preserving prefetch in both. LongCat and Gemma use **native GPU tables** versus Mooncake host snapshots; those comparisons include host offloading.
