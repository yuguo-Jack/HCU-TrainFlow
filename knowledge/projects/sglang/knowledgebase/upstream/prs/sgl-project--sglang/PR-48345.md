# [Fix] diffusion/realtime: Report generate loop errors with no leading message line

[Upstream PR](https://github.com/sgl-project/sglang/pull/48345) · state: open · merged: False

## Original PR description

## Motivation

`_generate_loop` builds the client error with `str(e).splitlines()[0]`. For an exception with an empty message, this raises `IndexError` inside the `except` block:

- the client gets no `error` message, the socket just closes;
- the original exception is lost, because `generate()` only logs the task's exception at debug level through `_await_realtime_task`;
- `pending_send_task` is never awaited, so a chunk still being sent is left running while the session is cleaned up.

An empty message is easy to hit. `BaseRealtimeModelAdapter.sample_chunk_inputs` and `build_sampling_params` raise a bare `NotImplementedError`, so an adapter that misses one of them fails this way.

A message that starts with a newline does not crash, but the client receives `error during generate loop: ` with no reason.

## Modifications

- Add `_first_error_line`, which returns the first non-blank line of the message, or the exception class name when there is none.
- Add a regression case for both failures to `test_realtime_runtime.py`. It fails on `main` (`IndexError`, then an empty reason) and passes with this change.

## Accuracy Tests

No change to model code or outputs.

## Speed Tests and Profiling

Only the error path changes. No GPU was used for this PR.

- `test/unit/realtime/test_realtime_runtime.py`: 45 passed on CPU (macOS arm64, Python 3.13, torch 2.15.0).
- Over a real socket (uvicorn and a `websockets` client, with an adapter that reaches the bare `NotImplementedError`):

| | Client receives |
|---|---|
| `main` | nothing, the connection drops |
| This PR | `{"type": "error", "content": "error during generate loop: NotImplementedError"}`, then the connection drops |

The connection still ends without a close frame after an error, as it does for every other generate loop failure. I left that out of this PR.
