# [Feat] disaggregation: Support GLM-5.3 CPU-buffer PD

[Upstream PR](https://github.com/sgl-project/sglang/pull/46583) · state: open · merged: False

## Original PR description

## Motivation

GLM-5.3 uses DeepSeek Sparse Attention (DSA). A decode worker needs its index-key pages and scales alongside attention KV to resume generation. The CPU-buffer implementation in the parent PR rejects DSA state. This PR adds that transfer support for GLM-5.3 PD deployments in TDX/Confidential Computing (CC) environments.

This PR is stacked on [#46554](https://github.com/sgl-project/sglang/pull/46554) at `4c1b634eec`, which depends on [#45779](https://github.com/sgl-project/sglang/pull/45779). The GLM-specific diff is relative to that parent.

Tracking issue: #46588

## Modifications

- Pack DSA index-key pages and scales into the CPU transfer buffer and restore them at the destination's physical page indices.
- Skip zero-sized payloads for layers that reuse another layer's top-k indices, while retaining the full component metadata for peer-layout validation.
- Handle empty page-index lists received through the bootstrap protocol.
- Add sparse-page and descriptor-order regressions, real NIXL/UCX transfer coverage, and a GLM-5.3 evaluator using the upstream GSM8K protocol.

This change targets `GlmMoeDsaForCausalLM`. Compressed DSA tail state and hybrid MLA layouts remain unsupported. The tests below use no MTP, PP/CP or offload.

## Accuracy Tests

Model, fault-injection and performance results below were collected at `753db656a5`. The current revision, `47c4cdf309`, includes upstream changes through `d19f19d68c`; full-model evaluations have not been rerun on this revision.

Tests use `GLM-5.3-W4AFP8` on two TDX hosts with eight H20 GPUs each. Unified uses TP8 on one host; cross-node PD uses TP8 per role, sixteen GPUs in total. Both use W4AFP8 weights, FP8 E4M3 KV cache, page size 64, chunked prefill 2,048, context length 65,536, and DSA backends `flashmla_sparse_q8` for prefill and `flashmla_kv` for decode. CUDA graphs and overlap scheduling are enabled. Radix caching is enabled for unified/prefill and disabled for PD decode.

PD uses a 16 GiB CPU pool per worker, checksum verification, and NIXL/UCX with `UCX_TLS=tcp,cuda_copy,self` and `UCX_ACC_DEVICES=''`. PD also sets `SGLANG_MOE_COPY_WEIGHT_VIEWS_BEFORE_H2D=1`, which copies mmap-backed MoE weight slices into separate CPU storage before loading them onto the GPU.

GSM8K follows the [upstream GLM-5.3 GSM8K test](https://github.com/sgl-project/sglang/blob/5828cd49276a419402b316aec0236e5c2161e46d/test/registered/amd/accuracy/mi35x/test_glm53_eval_mi35x.py): `run_sgl_eval`, all 1,319 questions, zero-shot chat with thinking, temperature 1.0, top_p 0.95, seed 42, 64 client threads and a 32,768-token output limit. The upstream test sets a 92% threshold for FP8. Both W4AFP8 runs exceed that threshold; the unified run provides a reference using the same checkpoint.

| Test | Unified TP8 | Cross-node PD, TP8 per role |
| --- | --- | --- |
| GSM8K | 1288/1319 (97.65%) | 1283/1319 (97.27%) |
| Request errors | 0 | 0 |
| Responses at output limit | 1 | 1 |

PD scored five fewer correct answers than unified, a difference of 0.38 percentage points. Responses that reached the output limit are included in both scores.

The upstream logprob parity check passed at 63, 64, 65, 127, 128 and 129 input tokens. It failed at 2,047, 2,048, 2,049, 4,097 and 8,193 tokens, including on repeated requests to the same unified server. Strict parity remains unresolved for these inputs; passing GSM8K and transfer checksums does not establish logprob parity.

Generation checks returned the expected answer for short prompts and prompts longer than `index_topk=2048`. A repeated 4,431-token prompt reused 4,416 cached tokens and returned the expected answer.

At `47c4cdf309`, all 148 regression tests passed, covering buffer lifecycle, queue cleanup, checksum and real NIXL/UCX CUDA transfers. Pre-commit passed.

Cross-node fault tests inject failures during decode receive-buffer allocation, prefill send-buffer allocation, and after a real NIXL write submission. Requests go directly to both workers, bypassing router retries.

Each injected request returned HTTP 500 from both peers. Four subsequent requests returned correct answers without restarting either worker. All sixteen rank pools returned to zero allocated bytes and pending handles, and both request queues emptied. In the post-submission case, buffers were retained until outstanding transfers completed. Host crashes and network partitions were not tested.

## Speed Tests and Profiling

Serving sanity checks use upstream `sglang.bench_serving`: `random-ids`, nominal 1,024-token inputs, 128 output tokens, range ratio 1, seed 42 and unlimited request rate. Each configuration was run once, serially, with 16 warmup requests followed by 80 measured requests. `--flush-cache` clears both PD workers after warmup. The default text sampling mode can change input lengths during server-side retokenization.

The hosts were shared, and no repeated measurements were collected. PD uses twice as many GPUs as unified.
