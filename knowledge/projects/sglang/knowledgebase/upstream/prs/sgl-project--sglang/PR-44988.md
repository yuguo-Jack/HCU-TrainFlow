## Motivation

At decode sizes every rank of a Kimi-K3 MoE layer computes the whole replicated router and latent down-projection in
the merged front GEMM, and the next layer's attention-residual (AttnRes) reads re-score the same bank rows every
layer.

## Modifications

Gated on gfx950 with aiter (`SGLANG_USE_AITER`) and the TP8 LL communicator (`k3_ll_comm_hip.get_comm()`). Builds on
#44985's and #44986's LL collectives and fused reads, #44987's route sort, and #44981's `activated` input to the shared
experts (a SiTU an earlier kernel already computed).

- Column-parallel MoE front (`SGLANG_ROCM_K3_SPLIT_FRONT`, <= 64 tokens): each rank's front GEMM reads its shared
  gate_up and 1/8 of the router and latent down-projection rows; one LL all-gather (`comm/front_gather_hip.cuh`)
  assembles logits and latent and also runs the MXFP8 latent quant (staged for aiter's scale-only sort), the router
  top-k (from 16 tokens; the route sort then only sorts) and the shared experts' SiTU.
- AttnRes bank partials (`attn_res/bank_partial_hip.cuh`, `SGLANG_ROCM_K3_ATTN_RES_BANK_PARTIALS`, <= 16 rows): the
  route sort's spare workgroups compute the next layer's softmax partials over its bank rows (max, sum, fp32
  weighted sum) for both of its reads; the fused reads of #44985 and #44986 take them and fold in only the stream.

| New env var | Default |
|---|---|
| `SGLANG_ROCM_K3_SPLIT_FRONT` | on |
| `SGLANG_ROCM_K3_ATTN_RES_BANK_PARTIALS` | on |

## Accuracy Tests

**Setup for every number below:** 8x MI350X (gfx950, 1000 W), Kimi-K3 (MXFP4 MoE, bf16 attention) at TP8 with EAGLE3
(topk 1, 3 steps, 4 draft tokens), FP8 KV cache, `SGLANG_USE_AITER=1`, aiter's K3 FlyDSL kernels
(`AITER_SITUV2_A8W4=1 AITER_FLYDSL_FORCE=1 SGLANG_AITER_K3_OPT=1`), CUDA graphs for bs 1/2/4/8/16, and an aiter bf16 GEMM table with K3 rows re-tuned on this pod with HBM-resident weights
(`AITER_CONFIG_GEMM_BF16`; not part of this PR, it belongs in aiter's model configs). EAGLE3 on K3 needs the
aux-capture commit of #43599, applied locally for these runs. Microbenchmarks rotate their weights through HBM.
Per-feature numbers were measured on the integration branch of this series as each piece landed (Oct 13-14,
earlier `main`). All branches of the series are on `main` 4eb606b2ae (2026-10-17); the kernel tests below ran on this
branch, and the end-to-end checkpoints on that `main` plus the queue up to each slot.

- GSM8K 400: split front 0.985 / accept 3.62; front gather top-k + quant 0.9825 / 3.618; bank partials 0.985.
  End to end: see below.
- `test_kimi_k3_route_sort.py` (extended): the bank partials match torch.
- `test_k3_ll_collectives.py` (8 GPUs, extended): the front gather equals `dist.all_gather`, its quant / top-k / SiTU
  equal aiter's quant-sort, the route sort and `situ_and_mul`; reads that take the partials equal the reads over the
  bank. On MI350X, with #44985's and #44986's checks: 1 passed.
- On MI350X, `test_kimi_k3_route_sort.py` with the existing layer-boundary tests `test_kimi_k3_stage_kernels.py` and
  `test_attn_bank_residual_ops.py`: 11 passed, 7 failed (23 subtests passed). All 7 failures are in
  `test/registered/unit/layer_boundary/test_attn_bank_residual_ops.py`, which fails the same 7 tests on unmodified
