# Reject disabled expert recorder controls before scheduler dispatch

[Upstream PR](https://github.com/sgl-project/sglang/pull/42098) · state: closed · merged: False

## Original PR description

## Motivation

Fixes #42071. Calling the start/stop/dump expert-distribution endpoints without `--expert-distribution-recorder-mode` sends a control request to the scheduler's disabled recorder, which raises instead of returning a response.

## Modifications

Validate the resolved recorder mode in the shared tokenizer control path before starting the handle loop or sending IPC. Python Engine callers receive a `ValueError`; the three HTTP endpoints return the existing 400 error format. Enabled modes retain their original actions and success responses. Other exception types continue to propagate.

## Accuracy Tests

- Five permanent CPU tests pass. The original source fails 11 assertions across the disabled controls; enabled-mode and transport-failure controls pass.
- Cover all four supported modes, three actions, GET/POST rejection, unchanged success responses, and unrelated `RuntimeError` propagation.
- Actual disabled-recorder, scheduler, tokenizer and HTTP source definitions in a CPU ASGI probe: six GET/POST requests previously reached the scheduler and returned 500; all now return 400 with zero scheduler dispatches. IPC is a synchronous boundary double and eager GPU package initialization is excluded. No GPU execution or full scheduler-process lifecycle test is claimed.
- Applicable pre-commit hooks pass.
