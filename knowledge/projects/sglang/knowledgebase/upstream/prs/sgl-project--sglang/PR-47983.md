## Motivation

<!-- Describe the purpose and goals of this pull request. -->

This PR adds two performance optimizations aimed at FLUX.2-dev.

- **The adaLN modulate runs eager on ROCm.** FLUX.2 fuses LayerNorm and the adaLN modulate into one kernel on NV, but that path is gated to cuda: the kernel uses inline PTX for correctly-rounded division and rsqrt, which LLVM rejects outright on AMD. So on ROCm every adaLN site falls back to `LN(x) * (1 + scale) + shift`. Porting that kernel would not help either: its bit-exactness contract reproduces aten's 32-lane warp reduction, and gfx950 warps are 64 wide. Instead this gives FLUX.2 the third tier FLUX.1 already has. Aten LayerNorm followed by the fused `modulate_scale_shift`. This alone gets most of the way there. The difference between porting the NV feature and incurring the output regression vs this is marginal, benchmarked to be within 0.5% - not worth the bit-exactness loss.

- **The Ulysses exchange copies Q/K/V apart for no reason.** The packed exchange returns one interleaved `[.., 3 * head_size]` buffer and splits it into three contiguous tensors. AITER's FMHA reads Q/K/V through explicit strides and returns bit-identical output from the interleaved views, so those three copies only cost bandwidth. 


## Modifications


<!-- Detail the changes made in this pull request. -->


**Fused adaLN modulate on ROCm**

- `kernels/jit/csrc/diffusion/modulate_scale_shift.cuh` — add `#pragma clang fp contract(off)` on the HIP path in `modulate_value`, so the bf16 rounding boundary between the multiply and the add survives. Without it hipcc folds the pair into an FMA and the kernel stops matching the rounding chain it documents.
- `kernels/ops/diffusion/modulate/modulate_scale_shift_jit.py` — drop the `torch.version.hip is not None` rejection from `can_use_modulate_scale_shift_cuda`, so the fast path serves both backends.
- `multimodal_gen/runtime/models/dits/flux_2.py` — add `_flux2_norm_then_modulate` (aten LayerNorm, then the fused modulate) and route both fallbacks in `_flux2_norm_modulate` through it: the one taken when the single-kernel LN+modulate is unavailable, and the one taken when that kernel raises. The compile and graph-capture branches stay on the plain eager expression, and the bit-exactness reference is unchanged.
- `test/registered/kernels/ops/diffusion/test_modulate.py` — the two cases that asserted ROCm must *not* take the fast path now assert the same contract on both backends.

**Strided QKV handoff**

- `multimodal_gen/runtime/layers/attention/backends/attention_backend.py` — add `AttentionImpl.accepts_strided_qkv`, default `False`: whether a backend reads Q/K/V through explicit strides.
- `multimodal_gen/runtime/layers/attention/backends/aiter.py` — `AITerImpl` sets it to `True`. It is the only backend that does.
- `multimodal_gen/runtime/layers/usp.py` — `_usp_input_all_to_all_qkv` gains a kw-only `allow_strided_qkv` (default `False`). When set it returns the three interleaved views instead of copying them apart, and the receive buffer alternates between two staging roles through `_packed_qkv_recv_role`, so views handed to attention stay valid past the next collective.
- `multimodal_gen/runtime/layers/attention/layer.py` — the plain Ulysses handoff opts in only when `get_ring_parallel_world_size() <= 1` and the impl declares support. The ring path, which reshapes and chunks Q/K/V, keeps the copies.
- `multimodal_gen/test/unit/test_usp_packed_qkv_a2a.py` — two cases: the strided views are bitwise equal to the copied path (a wrong stride would silently read a neighbouring projection rather than fail), and successive strided exchanges name different staging roles.
