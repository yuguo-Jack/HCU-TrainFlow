# [Fix] [SM120] quantization: Requantize block-FP8 MoE weights to UE8M0 for DeepGEMM

[Upstream PR](https://github.com/sgl-project/sglang/pull/43556) · state: closed · merged: True

## Original PR description

## Motivation

On SM120, `should_deepgemm_weight_requant_ue8m0` returns False for every caller, so block-FP8 MoE experts served by the DeepGEMM runner keep their FP32 checkpoint scales. SM120's grouped GEMM converts FP32 scales to UE8M0 itself, and it faults (CUDA error 719) on scales that are not powers of two.

With `nvidia/Qwen3.8-Flash-Next-NVFP4` and `--speculative-moe-runner-backend deep_gemm`, the block-FP8 MTP draft experts crash at the first prefill graph capture, at every token count. The same weights with power-of-two scales run.

#39065 (open, fixing #39063) makes the same guard change by inferring a grouped layer from `weight.ndim == 3`, without tests. This PR differs in two ways:
- `Fp8MoEMethod` passes `grouped_moe=True` explicitly.
- It adds a regression test.

Split out of #42566 at a maintainer's request. #42566 now carries only the TP block-scale refinement, which depends on this change for its DeepGEMM path on SM120.

Fixes #39063

## Modifications

- Keep the SM120 exemption for dense block-FP8 GEMMs, which run on CUTLASS or Triton with FP32 scales there.
- Requantize grouped MoE weights to UE8M0 as on SM90 and SM100.
- `should_deepgemm_weight_requant_ue8m0` and `requant_block_scale_ue8m0_for_deepgemm` take a keyword-only `grouped_moe` flag, which `Fp8MoEMethod` sets for its expert weights.

## Accuracy Tests

`test/registered/unit/layers/quantization/test_deepgemm_ue8m0_requant.py` adds a case for the SM120 grouped-MoE requant.

Two existing tests in that file fail on SM120 hosts both with and without this PR:
- `test_helper_requants_supported_deepgemm_bf16_once`
- `test_compressed_tensors_block_processing_preserves_ue8m0_marker`

They patch DeepGEMM's UE8M0 flags on but not the device, and SM120 deliberately skips the dense requant they exercise. The file passes on the CPU runner it is registered for.

End to end, together with the TP refinement in #42566:
- `nvidia/Qwen3.8-Flash-Next-NVFP4` at TP2 with its own MTP head (NEXTN 3/1/4, draft experts on DeepGEMM) scores 0.976 on GSM8K through the chat template (lm-eval `gsm8k`, 1,319 questions, flexible-extract) on 2x RTX PRO 6000.
- Without this change, the same draft experts on DeepGEMM fault on SM120 at TP1 already.
