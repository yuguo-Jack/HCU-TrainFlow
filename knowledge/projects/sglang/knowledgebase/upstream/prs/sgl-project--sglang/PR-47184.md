# [Fix] [AMD] deepseek_v2: Avoid PPMissingLayer attribute errors in the gfx950 allocator path

[Upstream PR](https://github.com/sgl-project/sglang/pull/47184) · state: closed · merged: False

## Original PR description

## Motivation

With pipeline parallelism on gfx950, `DeepseekV2Model.__init__` crashes on every stage that does not own the embedding:

```
AttributeError: 'PPMissingLayer' object has no attribute 'embedding_dim'
```

The aiter gfx950 allocator sizing (`_use_aiter_gfx95 and config.n_routed_experts == 256 and ...`) reads `self.embed_tokens.embedding_dim` and `self.layers[i].mlp`, which are `PPMissingLayer` placeholders on stages that do not own them. Any 256-expert model of this family hits it, not only DeepSeek-V3: GLM-5.2 (`amd/GLM-5.2-MXFP4`, hidden size 6144) fails the same way as a `--tp-size 1 --pp-size 4` P/D prefill worker on MI355X with `lmsysorg/sglang-rocm:v0.5.22-rocm720-mi35x-20261018`, and only stage 0 comes up.

This is #21194 by @RolaoDenthu, approved by @ch-wan, rebased onto current main. Its first hunk no longer applies (the surrounding a2a sizing code changed) and its title fails the current title check; it has had no activity since March. The change is unchanged and credits the original author (`Co-authored-by`). Happy to close this in favor of #21194 if it gets updated.

## Modifications

`python/sglang/srt/models/deepseek_v2.py`: the four bare attribute reads in the gfx950 allocator block become `getattr` calls, as in #21194. On a stage without the embedding the 7168 check reads `None`, so the block is skipped there; the remaining reads only run when the condition holds.

## Accuracy Tests

No numerical change: the edits only decide whether a stage that has no embedding enters this allocator block. For GLM-5.2 (hidden size 6144) the block is skipped on every stage either way. We have run GLM-5.2 PP4 prefill with an equivalent local fix (`config.hidden_size` in place of `embed_tokens.embedding_dim`) since Oct 21: GSM8K 0.9666 (strict) / 0.9674 (flexible) on 1P1D with real MTP acceptance, and 3,600-second AgentX runs on 1P1D, 1P + 4-GPU decode and 2P1D.

## Speed Tests and Profiling

Not affected.
