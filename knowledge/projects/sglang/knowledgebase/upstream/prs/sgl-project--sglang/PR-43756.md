# [diffusion] bind worker CPUs to the GPU's NUMA node when memory policy is not permitted

[Upstream PR](https://github.com/sgl-project/sglang/pull/43756) · state: closed · merged: True

## Original PR description

## Motivation

Diffusion workers bind to their GPU's NUMA node (#43565). Many Kubernetes pods block the NUMA memory-policy syscalls, because they run without `SYS_NICE`. On those pods `_is_numa_available()` returns False, and the worker skips binding entirely:

```
User lacks permission to set NUMA affinity, skipping NUMA node configuration for GPU.
```

CPU affinity (`sched_setaffinity`) needs no privilege, so the worker could still bind its CPUs. With CPUs bound, first-touch allocation keeps host memory on the node too. srt's V2 path already falls back this way (`--membind` → `--preferred` → CPU only), but the mempolicy gate in `_is_numa_available` returns before that fallback can run.

On a 2x GB300 pod without `SYS_NICE` (rx gb300-tml, GPU0 on node 0, GPU1 on node 1), the unbound FLUX.1 TP2 workers drift between sockets, and the request latency is bimodal (sample spread up to 60%).

## Modifications

- `get_numa_node_if_available(..., cpu_only_ok=False)` and `_is_numa_available(require_mempolicy=True)`: the defaults keep srt's behaviour unchanged. With `cpu_only_ok=True`, a host where only CPU affinity can be set still returns the GPU's node, and logs that only CPUs are bound.
- `numa_bind_to_node`: calls `numa_set_preferred` only when memory policy is permitted. The `sched_setaffinity` step is unchanged.
- The diffusion GPU worker passes `cpu_only_ok=True`.

## Accuracy Tests

No numerical change. This only changes the CPU affinity of the worker process.

- **Binding:** the log confirms it now happens on this pod: `GPU 0 worker bound to NUMA node 0`, `GPU 1 worker bound to NUMA node 1`, `binding CPUs only`.
- **Spread:** lower in 7 of 8 pairs.
- **Median:** lower in 6 of 8 pairs, −0.33 s on average. The signs are not unanimous: this pod sits on a shared node and is noisy, so the latency gain is not established beyond "usually faster, never much slower".
- **With mempolicy permitted:** on a whole-node 4x GB300 pod, main already binds, and this change takes the same path.
