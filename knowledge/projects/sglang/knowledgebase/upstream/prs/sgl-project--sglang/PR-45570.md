# [Feat] [NPU] quantization: Support static compressed-tensors W8A8

[Upstream PR](https://github.com/sgl-project/sglang/pull/45570) · state: open · merged: False

## Original PR description

## Motivation

Static compressed-tensors W8A8 checkpoints fail to load on Ascend because the NPU scheme rejects static activations. This enables dense inference using the checkpoint's fixed calibration scales.

Fixes #45569.

## Modifications

- Use fixed activation calibration scales with per-channel/per-tensor INT8 weights, FP16/BF16 outputs and floating-point bias.
- Allocate fused input scales and asymmetric zero points per logical shard in the shared base scheme, preserving the existing CUDA post-load processing.
- Remove the artificial TP=1 restriction. Keep validation of missing, invalid or unequal fused scales and unsupported NPU activation/dtype configurations.
- Replace the large in-tree model oracle with focused shared-loader, actual NPU linear, real-checkpoint eager/graph and TP2-versus-TP1 regressions. Test/support code is 500 lines, down from 1,018.
- Register CUDA extra-a, single-A3 and two-A3 model checks, and document the checkpoint requirements.

## Accuracy Tests

Revised-source validation on one Ascend910_9362, CANN 9.1, torch 2.10.0, torch_npu 2.10.0.post6:

- Shared CPU regression: 2 tests passed, covering fused QKV/gate-up scales, symmetric/asymmetric calibration and column/row/QKV/GQA/merged TP shard loading.
- Actual NPU linear regression: 2 tests passed, including 48 exact INT64-reference comparisons across FP16/BF16, channel/tensor, dense/QKV/gate-up, 2D/3D and bias/no bias, plus empty inputs and invalid calibration checks.
- Registered Qwen3-0.6B regression: passed in 212.839s; channel/tensor BF16, eager/graph, 4 model instances, 16 single/batched outputs and 128 generated tokens.
- Independent Qwen3-0.6B checkpoint matrix: all 12 reference/eager/graph model instances passed across channel/tensor scales and FP16/BF16. The 8 candidate instances produced 32 single/batched output comparisons and 256 generated tokens, with exact greedy-token equality against the serialized-checkpoint CPU integer reference and maximum selected-token logprob error 0.0 (limit 0.05).
- All applicable pre-commit checks passed on the staged changes. Mintlify 4.2.559 build validation and `broken-links --check-anchors --check-redirects` passed.

CUDA and genuine two-NPU model checks are registered for community CI. The TP2 test compares TP1 eager with TP2 eager and graph decoding, requiring exact greedy tokens and a maximum selected-token logprob difference of 0.05.

- TamirBaydasov · comment · 2026-10-27T14:54:12Z · [source](https://github.com/sgl-project/sglang/pull/45570#discussion_r4390207110)

File: `python/sglang/srt/hardware_backend/npu/quantization/linear_method_npu.py` · line None

Methods under `hardware_backend/npu` should be specific to the device, not to a quantization framework. This class mixes two jobs:

- **Converting llm-compressor output:** one input scale per logical shard, merging fused shard scales, expanding per-tensor weight scales to per-channel, and whichever calibration checks you keep (see the comment on the NaN pre-fill in `create_weights`).
- **The NPU kernel recipe:** a fixed per-tensor activation scale through `npu_quantize`, then `npu_quant_matmul` with that scale passed as `pertoken_scale`.

Could the conversion move into `NPUCompressedTensorsW8A8Int8.process_weights_after_loading`? It would hand this method a single input scale and a per-channel weight scale, plus the int8 weight. Then this class only holds the NPU kernel recipe, and any framework's static W8A8 scheme can reuse it. Its name should describe that recipe, not the checkpoint format.

With the conversion moved out, this class is `NPUW8A8Int8DynamicLinearMethod` with one step swapped. The weight transpose, `npu_format_cast` and scale flatten are the same, and `apply` is the same `npu_quant_matmul(..., pertoken_scale=...)` call with `npu_dynamic_quant` replaced by `npu_quantize`. Could it subclass the dynamic method instead? Call `super().process_weights_after_loading(layer)`, add the static scale and offset, and override only the quantize step. Then a change to the shared weight layout lands in one place.
