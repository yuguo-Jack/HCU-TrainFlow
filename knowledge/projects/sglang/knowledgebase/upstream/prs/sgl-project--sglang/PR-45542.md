# [Fix] sampling: Add upper bounds for top_k, top_logprobs_num and n

[Upstream PR](https://github.com/sgl-project/sglang/pull/45542) · state: open · merged: False

## Original PR description

Fixes #41482.

`SamplingParams.verify()` range-checks almost every field, but `top_k`, `top_logprobs_num` and `n` had no upper bound. A single request with `top_k=2147483648` overflows int32 in the scheduler event loop and takes the whole server down (SIGQUIT, all in-flight requests lost), while a huge `n` fans one prompt out into an unbounded number of copies during request normalization. Out-of-range values for the other fields are rejected cleanly with `ValueError`; these three slipped through.

### Changes

All checks are inline at the point where the value is consumed; no new helpers.

- `sampling_params.py` — `verify()` now rejects `top_k > vocab_size`. The `TOP_K_ALL` sentinel (the post-`__post_init__` form of `top_k=-1`, and also the default) stays exempt, so whole-vocabulary sampling is unaffected.
- `io_struct.py` — `GenerateReqInput._handle_parallel_sampling()` rejects `n` outside `[1, 128]`, immediately after the beam-search adjustment. Normalization replicates the prompt `n` times right after this, which happens before `verify()` is ever called, so this is the last point where a huge `n` can be stopped. Beam-search requests already collapse to `parallel_sample_num == 1` and are unaffected.
- `tokenizer_manager.py` — `_validate_one_request()` validates `top_logprobs_num` (a `GenerateReqInput` field, not a `SamplingParams` field) against `[0, vocab_size]`, immediately after the existing `_validate_token_ids_logprob` check. Both the per-request `int` form and the batch `list` form are covered.

### Tests

- `test_sampling_params.py`: `top_k` above vocab and `2**31` raise; `top_k == vocab_size` and `TOP_K_ALL` are accepted.
- `test_io_struct.py`: `n=128` expands normally; `n=129` and `n=0` raise during normalization; beam search with `n=200` neither raises nor fans out.
- New `test_top_logprobs_validation.py`: `top_logprobs_num` of 32001, -1 and `2**31` raise; 0, 20, 32000 and `None` are accepted.

The new raise-tests fail on the unmodified code and pass with this change. Full files pass locally: `test_sampling_params.py` (81 tests), `test_io_struct.py` (68 tests), plus the neighboring `test_sampling_mask_validation.py`, `test_flat_raw_top_logprobs.py`, `test_hidden_state_server_mode.py`, `test_embed_overrides.py`, `test_serving_completions.py` and `test_serving_chat.py`. `ruff check` / `ruff format` / `isort` are clean on all touched files.
