# [AMD] DSV4 compact_attention_hip imports an aiter module that was removed

[Upstream PR](https://github.com/sgl-project/sglang/pull/43257) · state: closed · merged: False

## Original PR description

## Correction

The original description of this PR was wrong, and the fix it proposes is the wrong direction. Leaving the PR open only to record the finding; see below.

`compact_attention_hip.py` imports a module that aiter **deleted**, so this is not an image-staleness problem and no aiter bump will fix it:

- aiter `b4c7f8c24` (2026-09-18, ROCm/aiter#4919) **removed** `aiter/ops/triton/_gluon_kernels/gfx950/attention/pa_decode_sparse.py` and added `sparse_mla.py` in its place. The symbol `_qkpv_fp8` was deleted outright — it does not appear anywhere in aiter today.
- sgl-project/sglang#41020 added `compact_attention_hip.py` on 2026-09-28, ten days later, with:
  ```python
  from aiter.ops.triton._gluon_kernels.gfx950.attention.pa_decode_sparse import _qkpv_fp8
  ```

So the import has never resolved against any aiter from 2026-09-18 onward. `rocm/sgl-dev:v0.5.21-rocm10-mi35x-20261007` bundles aiter `e7d2453f2` (2026-09-25) and its `gfx950/attention` contains `fp8_mqa_logits`, `mha`, `sparse_attention_dsv4_bwd`, `sparse_mla` — no `pa_decode_sparse`.

This also means `aiter_sparse_decode_fwd` in `hip_flash_mla.py` raises `ModuleNotFoundError` at runtime for the V41 / V41_FP4 KV layouts on gfx950, not just in the test.

Skipping the test, as this PR does, would hide that. The real fix is to port `compact_attention_hip` onto aiter's current gfx950 sparse API, which needs someone familiar with the kernel.
