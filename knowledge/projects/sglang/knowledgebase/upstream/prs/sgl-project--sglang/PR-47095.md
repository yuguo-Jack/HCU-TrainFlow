# [Fix] debug: Align EAGLE dump steps with worker rounds

[Upstream PR](https://github.com/sgl-project/sglang/pull/47095) · state: open · merged: False

## Original PR description


## Motivation

`dumper.step()` previously advanced after every model forward. One EAGLE
speculative decoding round could therefore span multiple dump steps, making
it difficult to compare draft and target dumps from the same round.

CUDA graph capture could also advance the step counter and write synthetic
warmup tensors into the dumps.

Fixes #47069

## Modifications

- Group draft and target forwards into one dumper step per EAGLE worker call.
- Add `spec_role`, `spec_phase`, and `spec_forward_index` metadata to
  distinguish forwards within a step.
- Suppress synthetic dumps and step advances during model graph capture.
- Apply grouped steps to EAGLE, multi-layer EAGLE, and Frozen-KV MTP workers.
- Add regression tests for grouped steps, tensor contents, nested and
  interrupted calls, and capture suppression.

## Accuracy Tests

Tested with Qwen3.8-27B-FP8 on one A100 40 GB GPU, using TP1 and NEXTN
with 3 speculative steps, top-k 1, and 4 draft tokens.

- In both eager and CUDA graph decode modes, one deterministic request
  produced the same text as the pre-change baseline.
- All 8 speculative verification rounds advanced the dumper step once each.
- Verified that CUDA graph capture did not add synthetic `input_ids` dumps.
- 34 selected dumper tests passed.

Multi-GPU, multi-layer EAGLE, and Frozen-KV MTP configurations were not
tested end to end.

CUDA graph replay does not re-execute Python-level dump operations inside
the captured graph. Use eager mode when those internal tensors are needed.

## Speed Tests and Profiling

No performance benchmark was run. This change updates debug dump bookkeeping
and metadata.
