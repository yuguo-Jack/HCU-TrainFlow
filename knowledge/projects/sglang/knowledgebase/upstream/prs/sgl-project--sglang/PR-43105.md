# Enable SM120 GLM DSA NVFP4 KV cache with FlashInfer

## Motivation

Enable `--kv-cache-dtype nvfp4` for GLM DSA on SM120 using the companion FlashInfer sparse MLA implementation. This reduces the MLA cache row from 656 to 416 bytes while retaining BF16 RoPE and the existing FP8 MMA computation path. Q/K/V compensation is absent; baseline P compensation remains in FlashInfer.

Depends on [the companion FlashInfer PR#6280](https://github.com/flashinfer-ai/flashinfer/pull/6280). 

## Modifications

- Add a Triton scatter writer and PyTorch reference for the 416-byte mixed NVFP4/BF16 row. Block-16 scales use the validated restricted E4M3 MSE candidate policy; no residual-bound statistics are computed.
- Allocate byte-addressed DSA cache rows, account for their physical width, and retain stable per-layer FP32 global-scale tensors across cache recreation. The index cache is unchanged.
- Route prefill/decode through a persistent FlashInfer NVFP4 wrapper. Require the GLM 512-latent/64-RoPE geometry on SM120 and `flashinfer_sparse_mla` for both phases. Reject unsupported HiSparse/HiCache, disaggregation, DCP and cache-layer splitting configurations.
- Add backend/configuration/pool tests and GPU writer reference/graph tests.

With the companion FlashInfer branch installed, add these options to the normal GLM-5.3 launch command:
```bash
--kv-cache-dtype nvfp4 --attention-backend dsa --page-size 64 \
--dsa-prefill-backend flashinfer_sparse_mla \
--dsa-decode-backend flashinfer_sparse_mla
```
The implementation targets `GlmMoeDsaForCausalLM` with latent=512 and RoPE=64; it does not enable the different GLM-5.3-Flash NoPE geometry.

## Accuracy Tests

186 targeted tests and 208 subtests passed, including GPU writer/reference byte parity, boundary/scatter cases and CUDA Graph replay. The five targets are:
```bash
pytest -q \
  test/registered/unit/test_flashinfer_sparse_mla.py \
  test/registered/unit/test_model_overrides.py \
  test/registered/unit/model_executor/test_pool_configurator.py \
  test/registered/unit/server_args/test_glm_nvfp4_kv4_gate.py \
  test/registered/attention/test_glm_dsa_nvfp4_cache.py
```

Full-model GLM-5.3 quality is **pending**. The first attempt failed during server startup: the legacy FlashInfer JIT lock directory was a dangling symlink into node-local `/tmp`, causing `FileExistsError` during autotuning. No evaluation examples ran. A filesystem-only initialization fix has passed a targeted dangling-symlink/FileLock check, and the otherwise identical frozen experiment has been requeued on 8 GPUs. The agreed gate is CMMLU/MMLU/GSM8K, 256 fixed examples each, no request errors, and at most 2 percentage points below the previous compensated NVFP4 version on every dataset. Previous counts: 233/227/253; required minimum counts: 228/222/248.

The queued run uses the preserved compensation-OFF experimental binary and writer so that the compensation comparison remains controlled. It does **not** by itself certify this current-main port. The port's writer produces identical bytes on all 16 captured inputs, and its output/LSE agree with the frozen OFF implementation within the recorded local tolerances. Full-model acceptance of the port and 8k-input/1k-output end-to-end throughput remain open; no model smoke test is substituted for those checks.


## Speed Tests and Profiling

Measured on NVIDIA RTX PRO 6000 Blackwell Server Edition (SM120), H=8, QK=576, V=512, top-k=2048, 64-token pages. Attention-only CUDA Graph replay, native FlashInfer autotuning, 384 MiB (3x L2) flushed before **every** profile outside the CUPTI span. No concurrent GPU benchmark. These are not end-to-end throughput results.

Captured GLM inputs: 16 cases (layers 0/26/52/77 x T=1/8/32/2048), mean of the four layer medians in microseconds:

| T | Current-main FP8 KV | NVFP4 KV, P compensation only |
|---:|---:|---:|
| 1 | 18.344 | 17.048 |
| 8 | 33.096 | 26.012 |
| 32 | 74.868 | 66.564 |
| 2048 | 1268.382 | 1279.718 |

**Open performance item:** T=2048 is approximately 0.9% slower than current-main FP8 on these replays. Do not interpret this draft as a completed performance acceptance. The older frozen FP8 baseline was slower in all four groups; the table above deliberately compares with the current main implementation.

Portable synthetic benchmark (same shapes, 65,536 cache rows, seed 19): FP8 / NVFP4 microseconds = 18.080 / 16.369 (T=1), 31.552 / 25.057 (T=8), 62.528 / 53.984 (T=32), 1310.626 / 1311.442 (T=2048). The T=2048 synthetic measurements are effectively tied in this run.

Reproduction is included in the companion FlashInfer PR:
```bash
pip install -U cupti-python
python benchmarks/bench_sparse_mla_glm_nvfp4_sm120.py
```
The benchmark explicitly tunes routes/CPBs; the serving wrapper currently uses its launch heuristic. Full-model serving throughput has not yet been validated for this port.
