#  [PD] Fix the early-send wait event on non-CUDA devices and in nixl

[Upstream PR](https://github.com/sgl-project/sglang/pull/43299) · state: open · merged: False

## Original PR description

## Motivation

Under overlap scheduling, `maybe_send_cached_prefix_chunk` can start the KV transfer for a cached prefix while the *previous* step's prefill forward is still writing those pages on `forward_stream`. It records a completion event and attaches it to the KV sender, so the transfer worker can wait for those writes before reading the pages. Two bugs broke this:

1. **The prefill scheduler crashes on non-CUDA devices.** The event came from `torch.cuda.Event()`, which raises `Tried to instantiate dummy base class Event` on torch builds without CUDA. On Intel XPU with PD + hierarchical cache, the prefill scheduler died on the first request that reused a cached prefix.
2. **nixl reads KV that may still be being written, with no error.** #41395 made the mooncake worker wait on the event, but nixl's `add_transfer_request` had no `wait_event` parameter. The event was recorded, attached and then dropped, so the RDMA read raced the writes it was meant to wait for. `SGLANG_DISAGG_PREFILL_EARLY_SEND_CACHED_PREFIX` defaults to `True`, so this is the default nixl PD path. Nothing fails visibly: the bytes do arrive, they just may not be final yet, and only an output-quality check catches it.

## Modifications

- `disaggregation/prefill.py`: create the event with `self.device_module.Event()`. `device_module` is set once from `self.device` in `init_overlap()`, the same module `forward_stream` was built from, so the event and the stream are always on the same accelerator. Using the process-default accelerator would bring that mismatch back whenever `--device` is not the default.
- `disaggregation/nixl/conn.py`: `add_transfer_request` now accepts `wait_event` and puts it on the queued `TransferKVChunk`. The transfer worker waits on it the same way mooncake's does:
  - before the failed-room check and before the staging gather, since the gather also reads the source pages;
  - not for a room that has already failed;
  - then clears it, so a chunk re-enqueued on a staging-watermark defer doesn't wait again.
- `disaggregation/common/conn.py`: add a `CommonKVSender._take_early_send_wait_event()` helper (returns the event and clears it), and set `_early_send_wait_event` in `__init__`. mooncake, mori and nixl now all read the event through this helper instead of `getattr`.

## Tests

- `test_prefill_abort_result_cleanup.py`: injects a stub device module and checks that the event comes from it and is recorded on `forward_stream`. This fails on the old code, which never touches the stub. The env flag is pinned with `override(True)`.
- `test_nixl_backend_basic.py`: the nixl worker waits before reading KV and before the staging gather, skips the wait for a failed room, `add_transfer_request` puts the event on the queued chunk, and taking the event clears it.
- `test_mooncake_transfer_batching.py`: the mooncake worker waits before the staging gather; the existing early-send test uses the new helper.

## Validation

Intel XPU, PD with nixl transfer + hierarchical cache, overlap scheduling:
- Before: the prefill scheduler crashed on the second request of a shared-prefix group.
- After: a 64-request shared-prefix run finished with 0 KV-transfer failures.
