# [Fix] dspark: Expand [N, H] staged embeds in the DeepSeek-V4 DSpark draft forward

[Upstream PR](https://github.com/sgl-project/sglang/pull/48244) · state: closed · merged: True

## Original PR description

## Motivation

With `SGLANG_DSPARK_EMBED_IN_GRAPH=0`, the DSpark draft worker embeds the draft block outside the model and passes the result as `input_embeds` with shape `[N, H]`. `DeepseekV4ForCausalLMDSpark` uses `input_embeds` as is, but its stages expect the hyper-connection layout `[N, hc_mult, H]` that `forward_embed` builds. On the eager draft path this fails in `mhc_pre` (`assert fn.shape[0] == hc_mult3`), so a server launched with `--disable-cuda-graph` and this env var dies during startup.

## Modifications

- Factor the `[N, H] -> [N, hc_mult, H]` expansion out of `forward_embed` into `_expand_hc`.
- Expand 2-D `input_embeds` in `_forward_impl`; 3-D embeds and the `input_embeds is None` path are unchanged.

## Accuracy Tests

DeepSeek-V4-Flash-0731 with its bundled DSpark head, on 2×B300 (`--tp 2 --moe-runner-backend flashinfer_mxfp4 --speculative-algorithm DSPARK --mem-fraction-static 0.85 --chunked-prefill-size 4096 --swa-full-tokens-ratio 0.1`). This is the cookbook's Flash-0731 recipe at TP 2 instead of TP 4. sgl-eval GSM8K: 200 examples, 32 concurrent, T=0, thinking off.
