# [Fix] rust-server: Match Python on template kwargs, declined V4.1 requests and streamed aborts

[Upstream PR](https://github.com/sgl-project/sglang/pull/45872) · state: closed · merged: False

## Original PR description

Stacked on #45660.

Review follow-ups for the rust-server chat stack: three places where the Rust server still answered differently from Python's `serving_chat.py`.

## Modifications

- **Jinja templates get the effort and the trailing assistant turn.** On the template path, the request's `reasoning_effort` and the `thinking`/`enable_thinking` toggle it implies now reach the template, beneath the request's own `chat_template_kwargs`, as Python's request validator and `_process_messages` do. A server-default `reasoning_effort` wins over the request's, as on Python. A trailing assistant message (null content counting as `""`) is continued apart from the prompt under `continue_final_message` (`_handle_last_assistant_message`), and otherwise asked as a user turn. Previously both were ignored. Legacy conversation templates are unchanged.
- **DeepSeek-V4.1 requests the parity encoder declines render through Dynamo's encoder.** An example is a `developer` turn. #45449 still returns 400 for these; this restores main's behaviour, like the template fallback #45449 gives the other formatters.
- **The template path's chat-layer rules live in the processor.** `TemplateArgs` and `ChatFormatter::render_template` hold Python's template kwargs and `_handle_last_assistant_message`, so rust-server keeps only the choice between the parity renderer and the template.
- **Scheduler aborts in a lowered chat stream keep their status.** The core streams every failure as an error frame, which the processor reads as Python's 400 `ValueError`. A scheduler abort (`CoreError::RuntimeRejected`, any status, 400 included) is now written as Python's abort frame where the stream is built, so a 503 is a `SERVICE_UNAVAILABLE` error event followed by the end of the stream, as on Python. Other failures stay error frames.

## Tests

- Unit:
  - A Jinja template sees the effort and its thinking toggle, and a server-default effort wins.
  - A trailing assistant message, including one with null content, is continued or asked as a user turn.
  - A V4.1 `developer` turn renders.
  - Streamed 503 and 400 scheduler aborts give HTTP 200, a `SERVICE_UNAVAILABLE` or `BAD_REQUEST` event and `[DONE]`; without the fix they gave a 400.
- `cargo test`, clippy and fmt for `sglang-server` and `sglang-processor` pass. Not live-tested on a model.

## Not covered

- A trailing assistant turn whose content is a parts list is left as is: Python flattens it only for string-format templates, which the formatter does not expose.
- Legacy conversation templates still ignore `continue_final_message` and the `<think>` suffix Python appends when reasoning is requested.
- `--tool-call-parser` does not pick the chat encoder (Python's `resolve_chat_encoding_spec`). Both sides already detect DeepSeek-V4/V4.1 and Kimi K3 by architecture.
- `SGLANG_TOOL_STRICT_LEVEL` is not read by the Rust tool constraints, for any parser.
- A streamed abort's usage chunk reports zero tokens, because the abort frame carries no token counts.
