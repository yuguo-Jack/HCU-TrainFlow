# [PD] Send DSA indexer state only past decode_prefix_len

[Upstream PR](https://github.com/sgl-project/sglang/pull/44140) · state: closed · merged: True

## Original PR description

## Motivation

On main (`5569b14d2`), a PD decode worker running `--disaggregation-decode-enable-radix-cache` gives prefill a page-aligned `decode_prefix_len`, and prefill sends KV only past it (`start_send_idx`). The DSA indexer state (`StateType.DSA`) ignores that prefix: both sides build its page list over `[0, seq_len)` with `_full_kv_pages_payload`.

This has two effects when decode has a prefix hit:

- **Prefix restored from L2/L3.** Decode writes the `req_to_token` rows for `[prefix_len, decode_prefix_len)` only when the HiCache restore commits, which happens after this payload is built. The indexer rows for that prefix are therefore sent to whatever page ids those rows held before, which are pages of other requests.
- **Prefix already on device (L1 hit).** Prefill rewrites the indexer rows of pages the radix tree shares with other requests.

The cached prefix already has its own indexer rows. The device hit keeps them, and HiCache restores them along with the KV because the indexer host pool is part of the host pool group. Prefill only needs to send the suffix.

## Modifications

- `mem_cache/common.py`: add `suffix_page_indices(req_to_token, req_pool_idx, prefix_len, seq_len, page_size)`, which returns the pages for tokens `[prefix_len, seq_len)`.
- `disaggregation/prefill.py` and `decode.py`: `StateType.DSA` now sends `suffix_page_indices` starting at `decode_prefix_len` on both sides: `req.disagg_decode_prefix_len` on prefill and `total_prefix_len` on decode. Because the prefix is page-aligned and identical on both sides, the two lists still pair up page by page, which is what the NIXL and Mooncake DSA paths rely on.
- Without a decode prefix (`decode_prefix_len == 0`, including whenever the decode radix cache is off), the payload is identical to before.
- `DSA_TAIL` and the other state types are unchanged.

## Accuracy Tests

- No new test file is included in this PR.
