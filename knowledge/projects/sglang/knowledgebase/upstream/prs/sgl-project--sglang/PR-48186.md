# [Fix] dspark: Keep accept softmax batch-independent under deterministic inference

[Upstream PR](https://github.com/sgl-project/sglang/pull/48186) · state: closed · merged: False

## Original PR description

## Motivation

DSpark's accept softmax calls FlashInfer under `--enable-deterministic-inference`, which promises batch-invariant ops. On B200, FlashInfer selects its launch from the row count, so a request gets different bits in different batches.

These rounding differences can change a sampled token. With `openbmb/MiniCPM5-2B` and its DSpark draft, one seed and prompt pair (`--random-seed 42`) gives row 0 token 19929 at batch 1 and 19930 at batch 8 and 32. Over 16 such pairs, row 0 differs between batch 1 and 8 for one on main and none with this change.

## Modifications

Under the flag, `SoftmaxTemp` skips FlashInfer and uses its existing Triton kernel. Other runs do not change.

I did not use `torch.softmax`, as #47773 does for draft and verify, because it depends on a row's position at 248094.

## Accuracy Tests

No accuracy eval ran. Rounding changes under the flag: row 0 now gets token 19928 instead, and the same 200 tokens at batch 1, 8 and 32.

I compared rows inside larger batches with the same rows alone, on B200 (torch 2.14.1, FlashInfer 0.7.2):

| Vocabulary | FlashInfer | `torch.softmax` | Triton |
| --- | --- | --- | --- |
| 32000 | Differs at 37 rows and above | No difference | No difference |
| 130560 | Differs at 37 rows and above | No difference | No difference |
| 248094 | Differs at 2 rows and above | Differs at odd positions | No difference |

The regression test at 130560 and 248094 fails on main and with `torch.softmax`, and passes with this change.

MiniCPM5-2B server runs use the cookbook's block size 7 (no B200 cell), target and draft `fa4`, `--cuda-graph-backend-prefill=disabled`, temperature 1.0, and a fresh server per batch size.

`openbmb/MiniCPM-V-4.7-1B` (vocabulary 248094) does not start on main: `AttributeError: 'MiniCPMV4_7' object has no attribute 'shared_experts_config'`. #41391 is open and removes this error. With it, Triton attention and the default block size, `torch.softmax` gave different bits for 18 of 35 inputs seen at several positions, and this change for none.

Not fixed: sampled DSpark ignores `sampling_seed`, so it is not reproducible by seed. The prefill sampler and top-k or top-p target probabilities still call `torch.softmax`, untested for position dependence.

Not checked: other Blackwell parts, Hopper, ROCm, NPU, Sail, an accept coin flip or `SGLANG_OPT_DSV41_SAMPLING_ACCEPT_GRAPH=1` on a server, and DeepSeek-V4 (the flag refuses `dsv4`).

## Speed Tests and Profiling

Flag-on calls at vocabulary 130560 take 0.27 ms instead of 0.15 ms at 448 rows, with the same peak allocation.
