# [Fix] rust-server: fix rust response metadata parity

[Upstream PR](https://github.com/sgl-project/sglang/pull/43365) · state: open · merged: False

## Original PR description

**Summary**

add the following fields to generation responses when using the rust server:
- `cached_tokens`
- `cached_tokens_details`
- `reasoning_tokens`
- `num_retractions`
- `dp_rank`

python already returns these scheduler values, the rust transport and response schema omitted them.

`require_reasoning` forwarding is deferred to a separate PR.

**Changes**

The change carries **existing Python counters** through the rust response path. It does not calculate new counters.

Each request can produce multiple chunks over time. Every chunk carries that request’s current counters.

```text
 _____________________________________________
| Python scheduler                            |
| R1 and R2 are separate requests.            |
| Counters are totals so far, not increments. |
|                                             |
| R1: 128 cached tokens · R2: 0 cached tokens |
|_____________________________________________|
           | NEW: send these totals to Rust
           v
 _____________________________________________
| SchedulerMetadataColumns (new)              |
| Packs multiple requests into one message.   |
|                                             |
| requests:      [R1,  R2]                    |
| cached_tokens: [128,  0]                    |
|_____________________________________________|
           | Split back into individual requests
           v
 _____________________________________________
| SchedulerMetadata (new)                     |
| Carries one request's totals through        |
| ChunkEvent → CoreOutput.                    |
|                                             |
| R1 reports 128 again → keep 128, don't add. |
|_____________________________________________|
           | Copy into that request's response
           v
 _____________________________________________
| Response meta_info                          |
|                                             |
| R1: "cached_tokens": 128                    |
| R2: "cached_tokens": 0                      |
|_____________________________________________|
```

Same path for `cached_tokens_details`, `reasoning_tokens`, `num_retractions`, and `dp_rank`.
