# fix(openai): omit DSV tools when tool choice is none

[Upstream PR](https://github.com/sgl-project/sglang/pull/35738) · state: closed · merged: False

## Original PR description

## Motivation

DeepSeek-V4 and DeepSeek-V3.2 still encode tool schemas when a Chat Completions request sets `tool_choice="none"`. Output parsing is disabled for this choice, so a model-generated native tool call can leak into `message.content` as raw DSML.

Fixes #35736

## Modifications

- Remove request-level and message-level tools from the copied DSV4/DSV32 messages when tools are disabled.
- Preserve the existing tool encoding behavior for `tool_choice="auto"`.
- Add regression coverage for DSV4 and DSV32, including system and developer message tools.

## Accuracy Tests

Added prompt-encoding unit tests for `tool_choice="none"` and `tool_choice="auto"`. This change does not modify model execution.

## Speed Tests and Profiling

Not applicable. The change only removes tool fields from copied messages when tool use is disabled.
