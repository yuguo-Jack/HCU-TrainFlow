## Motivation

<!-- Describe the purpose and goals of this pull request. -->

Add optional [SynthID Text](https://github.com/google-deepmind/synthid-text) watermarking to ordinary generation and linear EAGLE/MTP speculative decoding, including explicit per-request opt-in/out within a shared batch.

Targeted validation and the requested public-model benchmark campaign are complete; repository-wide CI remains tracked separately in the footer.

## Modifications

<!-- Detail the changes made in this pull request. -->

- Add the hash-based Algorithm 5 transform, request-slot history, and Triton sampling/rejection kernels.
- Add `--watermark-algorithm synthid`, file-based server key configuration, and per-request `watermark.enabled` controls. Requests are OFF by default unless the server explicitly changes that policy.
- Integrate ordinary sampling, speculative target/draft proposals, mixed ON/OFF batches, CUDA graphs, overlap relays, slot reuse, and cache-flush invalidation.
- Adapt configuration to the current namespace field/hook APIs, keeping the existing Gumbel algorithm as the default.
- Add synthetic reference-law, state-lifecycle, policy, and CUDA-kernel regression tests.

The default candidate cap is 1,024. Wider caps use the existing wide transform; this PR does not add a new fused 2,048-candidate ordinary sampler.

## Public-model SynthID benchmark: Qwen3.5-4B and 9B, K=512

Completed and independently verified **70/70 timed runs**: seven configurations × two public models × five paired replication blocks. **No top-k ablations** were run.

Benchmarked PR commit: `ff058455c40fae45784d0e98cb66368f1e1b7716`. Unmodified upstream control: `a904e4d31a`.

### Performance

| Model | Mode / policy | Output tok/s | Throughput loss vs port OFF [95% CI] | p95 TPOT |
|---|---|---:|---:|---:|
| 4B | Ordinary upstream baseline | 1,980.9 | — | 3.714 ms |
| 4B | Ordinary explicit OFF | 1,994.9 | Reference | 3.714 ms |

“Explicit OFF” uses this PR's implementation with SynthID capability enabled but disabled per request. Losses are paired within each replication block against that same-model/mode OFF control, **not** the separate upstream baseline. Throughput and p95 TPOT columns are means of five run-level measurements. Confidence intervals use the five paired percentage losses and Student's t distribution, df=4; no repetitions were removed. The 9B ordinary-ON and MTP-ON intervals include zero.

At this setting, ordinary watermarking costs less than 1% in mean throughput. Always-ON MTP costs about 4.0% for 4B and 1.7% for 9B; the explicit 50/50 MTP mixture is the larger measured overhead.

### Protocol and public assets

- Hardware/runtime: **one NVIDIA H200**, BF16, TP=1, FA3 attention, FlashInfer sampling, overlap scheduling enabled, full **decode** CUDA graphs with batch sizes 1/2/4/8; prefill CUDA graphs disabled. Language-only serving, context length 2,048, chunked prefill 2,048, max-running-requests 8, static memory fraction 0.60.
- Models: [`Qwen/Qwen3.5-4B`](https://huggingface.co/Qwen/Qwen3.5-4B/tree/851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a), revision `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`; [`Qwen/Qwen3.5-9B`](https://huggingface.co/Qwen/Qwen3.5-9B/tree/c202236235762e1c871ad0ccb60c8ee5ba337b9a), revision `c202236235762e1c871ad0ccb60c8ee5ba337b9a`. All weight shards were SHA-256 checked against their public metadata; both checkpoints include native MTP tensors.
- Performance data: [`HuggingFaceTB/smol-smoltalk`](https://huggingface.co/datasets/HuggingFaceTB/smol-smoltalk/tree/f73fe857d519ff6ac5af2ea67c4d3834da7b8bcc), **Apache-2.0**, pinned revision `f73fe857d519ff6ac5af2ea67c4d3834da7b8bcc`, test split. Conversation prefixes were deduplicated, SHA-256 ordered, chat-templated with thinking disabled, and selected without prompt truncation to contain 128–1,024 input tokens.
- Each timed run: the same **256 prompts × 256 output tokens**, temperature **1.0**, unlimited request top-k, top-p 1, min-p 0, offered request rate ∞, max client concurrency **8**. Exactly **17,920 timed requests / 4,587,520 output tokens** across the experiment. `ignore_eos=true` is used **only for these fixed-output performance runs**.
- Before every timed run: **32 short warmup requests**, followed by the stock SGLang cache-flush operation. Every request success, fixed output length, flush completion, and mixed-policy count was checked. Mixed runs contain exactly **128 explicit ON + 128 explicit OFF** requests.
- MTP: NEXTN resolved to linear EAGLE, **3 speculative steps / 4 draft tokens / eagle-topk=1**, exact rejection sampling, using each public model's native MTP weights.
- SynthID: **candidate cap 512**, 30 public synthetic test keys (`1009 + 7919*i`, `i=0..29`), n-gram length 5, context history 1,024, request-opt-in default. No production key material was used.
- Dependencies: PyTorch **2.14.1 / CUDA 13.0**, Transformers **5.19.0**, FlashInfer **0.7.2**, sglang-kernel **0.4.10**, isolated from older release environments.

Client request execution, timing, and metrics use the stock `sglang.benchmark.serving` implementation. The input adapter supplies fixed public `DatasetRow` token IDs and per-request `watermark.enabled` overrides. All 70 persisted cells were checked for completeness, exact output shape, ON/OFF counts, throughput arithmetic, and independently recomputed latency percentiles before calculating the paired intervals.

Using [`openai/gsm8k`](https://huggingface.co/datasets/openai/gsm8k/tree/740312add88f781978c0658806c59bc2815b9866), **MIT**, revision `740312add88f781978c0658806c59bc2815b9866`:

- **16 fixed public questions per model and decoding mode**, normal EOS/stopping behavior, matched serial batches and cold-cache policy groups.
- Ported ordinary and MTP generation with explicit OFF and ON matched their corresponding upstream baseline **token-for-token and in finish reason**: **64 comparisons for 4B + 64 for 9B, zero differences**.
- This is a controlled greedy-output regression check, **not a claim of full-dataset GSM8K accuracy**. Positive-temperature ON/OFF/mixed serving is exercised by the performance runs above; distribution/state correctness is also covered by the CPU/CUDA reference-law tests.

The controlled regression exposed an upstream-prefill proposal-law difference during porting. Commit `ff058455c4` preserves the original unpinned initial draft proposal for greedy prefill and adds a regression test; the cohort above passes with that fix.
