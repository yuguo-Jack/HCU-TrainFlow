# [CI] [AMD] ci: Follow #47619 on AMD and fix two never-run registrations

[Upstream PR](https://github.com/sgl-project/sglang/pull/48134) · state: open · merged: False

## Original PR description

## Motivation

#47619 sorted CUDA tests by importance: some moved from **base** (every PR) to **extra** (opt-in label), others from extra to **nightly** or **weekly**. The AMD registrations in the same files were not moved, so AMD still runs 8 of these tests on every PR and 20 on every `run-ci-amd-extra` PR. Separately, two tests are registered to suites no CI job runs, so they never run anywhere.

## Modifications

Each test now runs at the same tier on AMD as on CUDA:

- **AMD base -> AMD extra (8):** `hicache_storage_file_backend`, `hicache_variants`, `unified_radix_cache_kl_full`, `sampling_mask`, `load_snapshot_server`, `retract_decode`, `streaming_session`, `dflash`.
- **AMD extra / base -> AMD nightly (20)**, because CUDA runs them nightly or weekly (AMD has no weekly):
  - 16 one-GPU tests -> `nightly-amd-1-gpu` (`basic_perf` latency / throughput / score / embeddings, `test_torch_compile`, `test_vlm_models`, attention, quantization, and 5 LoRA tests)
  - 3 two-GPU `basic_perf` throughput tests -> new `nightly-amd-2-gpu`
  - `test_lora_gpt_oss_20b_logprob_diff` -> `nightly-amd-4-gpu`
- **Never-run tests:**
  - `test_hicache_storage_3fs_backend.py` used a CUDA suite name; it now runs in AMD extra, as on CUDA.
  - `test_fp8_fused_writer_hip.py` pointed at a non-existent AMD CPU job; its checks need no GPU, so it now runs in the CPU suite `base-a-test-cpu`.

Workflow changes:

- `nightly-test-amd.yml`: the 1-GPU nightly job grows from ~5 to ~89 min of tests, so it is split into 3 shards with an 1800 s per-file limit. New `nightly-2-gpu` job on the MI300 2-GPU runners (~35 min).
- `pr-test-amd.yml`: the stage-b 1-GPU-large job needs one shard instead of two.
- `pr-test-amd-extra.yml`: shards set to the new sizes (1-GPU small 4, with the step timeout raised from 45 to 75 min, 1-GPU large 2, 2-GPU large 2). `test_hicache_variants.py` gets its real AMD `est_time` (1500 s, was 524) so the shards balance.

Cost per run: AMD base −~2 GPU-h per PR, AMD extra −~0.7 GPU-h per labeled PR, AMD nightly +~2.8 GPU-h per ROCm image.

## Verification

- Every test registered for both CUDA and AMD is now at the same tier on both (kernel tests excluded), and every AMD PR test is in a suite some job runs.
- The 17 moved tests that were in AMD extra all passed in the last finished scheduled extra run (rocm724, run 41506219333). The fp8 writer test passed on the CPU runner (5 tests OK); the 3FS test passed on an AMD 2-GPU runner (both runs from #47179).
- Lint and PR-title checks pass on this PR.
- Not yet run: the split 1-GPU nightly job and the new `nightly-2-gpu` job. A `nightly-test-amd.yml` dispatch on this branch should confirm them before merge.

## Notes for reviewers

- The 1-GPU nightly job name now ends in ` part N`, after the closing parenthesis, so the AMD job monitor (which matches `<job> (<rocm>, <runner>)`) still groups the shards into one row.
- #47946 changes the same registration lines; it should rebase after this PR.
