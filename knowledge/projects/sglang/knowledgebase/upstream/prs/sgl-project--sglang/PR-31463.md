## Code Review

This pull request introduces support for the W4AFP8 MoE scheme, enabling INT4 group-quantized weights with 8-bit dynamic activations using CUTLASS W4A8 grouped GEMM kernels. It implements weight unpacking/repacking from compressed-tensors format, adds dynamic activation quantization kernels, and integrates these updates into DeepSeek and MiniMax model loaders. Feedback on these changes highlights a critical bug where CUTLASS stride and workspace buffers are allocated on the CPU and never moved to the GPU, which will cause a runtime error. Additionally, it is recommended to add an assertion to enforce 4-bit weight limits and to avoid dynamic allocation of scale tensors on the hot path to prevent GPU memory overhead.

File: `python/sglang/srt/layers/quantization/compressed_tensors/schemes/compressed_tensors_w4a8_fp8_moe.py` · line 230

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

During model initialization (`create_weights`), the layer is typically on the CPU, so `layer.w13_weight_packed.device` is CPU. This causes `_init_cutlass_buffers` to allocate all CUTLASS stride and workspace tensors on the CPU. Since they are never moved to the GPU, this will result in a runtime error (CPU tensor passed to CUDA kernel) during the forward pass.

To fix this, we should re-initialize these buffers on the correct GPU device inside `process_weights_after_loading` once the weights have been loaded and moved to the GPU.

```suggestion
        self._init_cutlass_buffers(
            num_experts=layer.w13_weight_packed.shape[0],
            hidden_size=layer.w2_weight_packed.shape[1],
            intermediate_size=layer.w13_weight_packed.shape[1] // 2,
            device=device,
        )
        layer.is_w4afp8_converted = True
```
