## Motivation

Closes #43196 (after its dependency #43254 merges). RunAI has a separate weights iterator, so Default-loader shard selection does not automatically apply to it. This change consumes the parent PR's model-owned predicate before handing files to ModelStreamer.

[vLLM #60152](https://github.com/vllm-project/vllm/pull/60152) addresses Default loading; [vLLM issue #60691](https://github.com/vllm-project/vllm/issues/60691) and [PR #60759](https://github.com/vllm-project/vllm/pull/60759) cover the corresponding independent RunAI connection. [vLLM #58016](https://github.com/vllm-project/vllm/pull/58016) concerns lazy per-tensor skipping, not this file-level RunAI path. [vLLM #42060](https://github.com/vllm-project/vllm/issues/42060) concerns draft weight-source resolution and is not folded into this change. SGLang's earlier #32488 proposal is also relevant; this version reuses model-owned rules and covers distributed selection/fallback consistency.

## Modifications

- Carry the same optional model predicate through RunAI's source preparation; no architecture names or `mtp.` conventions in the generic selector.
- For local files, reuse safetensors-header selection. For object storage, reuse SGLang's prepared index metadata and map raw names to complete shard URIs before the streamer starts. Do not stage checkpoint weights or download them to inspect headers.
- Keep mixed shards and unindexed extra files. Missing/ambiguous selection metadata, unsupported name transformations, no hook or an all-rejected result preserve the original list. Existing preparation errors are unchanged; model-rule and actual tensor-read exceptions still propagate.
- In distributed mode, union requirements through the existing WORLD CPU group when original ordered file lists agree. A rank retaining the full list makes the group retain it. If original lists differ, preserve each original list rather than substituting another node's local paths; this patch does not repair pre-existing inconsistent-root configurations.

The parent owns the model rules. This commit does not add another model adapter table, change RunAI's internals or tensor/range granularity, or alter ModelExpress P2P.

## Accuracy Tests

At the current combined head after rebase, focused Default/RunAI/prefetch/model/quantization regressions completed with **83 passed, 177 subtests passed, 7 warnings**. Changed-file pre-commit hooks also passed. Five real two-process Gloo scenarios exercise WORLD agreement, missing metadata, differing maps, absent hooks and differing original roots. The four failing pre-fix scenarios and the passing post-fix run are retained.

Real RunAI reads against a local S3 emulator verified selected file requests and tensor values using production Qwen3.5, Qwen3-Next, DeepSeek NextN and GLM NextN predicates, plus no-hook fallback. In a synthetic checkpoint with a ~1 MiB main-only tensor, none of those four adapted draft paths issued a GET for its shard; the no-hook fallback did. Instrumented safetensors GET response bytes were 336/244/276/276 respectively versus 1,049,016 for the no-hook fixture (one run per case). This is a file-I/O behavior check with tiny artificial data, **not** a production-model throughput, OSS-byte, GPU-accuracy or Ready-time benchmark.

A broader offline model-loader run had 154 passes, 19 skips and 8 failures; the failures require uncached HF configurations during ModelOpt setup. It is not reported as an all-green suite. A single H20×8, TP=8 Qwen3.5 MTP GPU pair reached Kubernetes Ready on both arms. The same four fixed `/generate` requests returned HTTP 200 and 256 completion tokens per arm, with speculative-draft counters present (251 proposed, 1 accepted). This confirms that both arms executed the draft-serving path in this smoke check, but the low acceptance count and limited prompts do not establish model accuracy or cross-architecture GPU correctness.

## Speed Tests and Profiling

**Preliminary, one baseline/patch pair (not a repeated benchmark).** Both arms used the same H20×8 node, TP=8, Qwen3.5 MTP checkpoint, SGLang launch flags, BF16, torch.compile, CUDA Graph settings and resource requests; the rendered Pod manifests differ only in name/arm labels and image digest. Startup is measured from the engine container start to Kubernetes Ready, excluding scheduling and image pulling. TP0 log timings are separate main/draft weight-load intervals, not whole-Pod elapsed time.

| Measured stage | Baseline | This PR | Observed difference |
| --- | ---: | ---: | ---: |
| TP0 main weight load | 116.51 s | 106.62 s | -9.89 s |
| TP0 draft weight load | 130.73 s | 9.09 s | -121.64 s (14.38x for this pair) |
| Engine-reported combined weight load | 247.26 s | 115.75 s | -131.51 s |
| Engine-container start → Kubernetes Ready | 484 s | 351 s | -133 s (1.38x for this pair) |

Representative log boundaries: baseline main/draft `116.51s / 130.73s`; patch main/draft `106.62s / 9.09s`, with the same model classes and per-rank HBM use (`14.82 GB / 0.69 GB`). The RunAI progress logger completed 75,881/75,881 items for both baseline passes; on the patch it completed 75,881/75,881 for main and 1,121/1,121 for draft. Thus the reduced draft iterator was actually consumed, rather than merely configured. Progress items are neither measured OSS bytes nor HTTP requests. A post-start checkpoint-index audit on this checkpoint selected 49/49 main shards and 1/49 draft shard; one shard is shared. This is **file count, not bytes transferred**. The mechanism matches the draft-phase reduction, but the baseline ran first and the patch second, so host/object-store cache and temporal drift are not ruled out. No stable end-to-end speedup, OSS-byte reduction or multi-model GPU result is claimed until alternating repeated runs and a read-traffic audit are complete.

Separately, fixed-revision index audits select Qwen3.5-27B main 11/11 and draft 5/11 files, and GLM-4.7-Flash main 47/48 and draft 1/48. Local S3-emulator tests verify selected remote requests and consumed tensor values across Qwen3.5, Qwen3-Next, DeepSeek NextN and GLM NextN; mixed shards can still be fetched for both roles. These are model-coverage and I/O-path checks, not GPU performance measurements.

## Reviewer focus

RunAI has its own iterator: the Default change in #43254 does **not** cause it to skip remote shards. This four-file increment obtains the same model-owned predicate, selects complete files before `runai_safetensors_weights_iterator`, and coordinates a conservative union across WORLD ranks. Please review the remote-index fallback, mixed/unindexed files, and differing per-rank original paths; no model-specific `mtp.` prefix is embedded in this generic loader. The corresponding vLLM [issue #60691](https://github.com/vllm-project/vllm/issues/60691) and [PR #60759](https://github.com/vllm-project/vllm/pull/60759) help explain why RunAI needs a separate integration.
