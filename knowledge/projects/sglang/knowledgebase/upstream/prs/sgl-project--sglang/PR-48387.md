## Motivation

PD streaming can stall because the router waits for prefill’s HTTP completion before forwarding decode output. We observed decode emitting tokens ~0.9s before prefill retired, in a prefill CEP4, decode DEP4 case. The same retirement delay was discussed in [#47015](https://github.com/sgl-project/sglang/pull/47015).

#47015 addresses prefill-side polling, but is opt-in and limited to attention DP=CP=1 without speculative decoding. This PR instead forwards non-logprob streams once decode produces actual output, preserving pre-token prefill failure handling and bounded background prefill cleanup.

## Modifications

Release streaming PD output after actual decode generation without waiting for the prefill HTTP response to finish. Integrate the handoff into the existing dispatch loop; metadata-only output and logprob merging retain the prefill gate. Preserve buffered SSE bytes and accept null error fields.

Finish delayed prefill responses in a bounded helper that retains the load guard and request tracing span. Record late prefill errors against the prefill worker only. Avoid redundant slot releases and successful-body drains; remove stale Content-Length on SSE responses.
