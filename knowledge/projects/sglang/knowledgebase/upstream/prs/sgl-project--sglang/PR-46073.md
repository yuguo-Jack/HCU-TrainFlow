# [Fix] server_args: revalidate LMCache after model capability resolution

[Upstream PR](https://github.com/sgl-project/sglang/pull/46073) · state: open · merged: False

## Original PR description

## Motivation

Model-capability resolution can disable the radix cache after the initial cache compatibility check. With LMCache enabled, an EmbeddingGemma configuration can therefore finish resolution with an unsupported cache combination and reach a cache implementation that does not provide LMCache operations.

Addresses the model-derived configuration case in #45929. Explicitly passing both conflicting flags is already rejected and is not a new fix in this change.

## Modifications

Re-run the existing cache compatibility hook after model-capability adjustments. Keep the early validation and registered hook dispatch while rejecting the final unsupported LMCache/disabled-radix combination with the existing error.

Add four configuration regressions: the late model-derived conflict, the explicit flag conflict, an encoder without LMCache, and a compatible decoder with LMCache. The compatibility hook now runs a second time; this preserves the registered hook dispatch and does not add LMCache support for models that require disabled radix caching.
