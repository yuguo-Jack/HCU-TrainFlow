# [Fix] diffusion: Return latent_step_indices and keep every timestep when rollout filters trajectory steps

[Upstream PR](https://github.com/sgl-project/sglang/pull/45690) · state: open · merged: False

## Original PR description

## Motivation

With `rollout_return_step_indices`, the response does not say which step each kept latent belongs to, and `timesteps` is filtered along with the latents while `sigmas` stays `[T+1]`. Trainers index both by step number. `sglang-miles` already returns `latent_step_indices`; this brings it to main.

## Modifications

- Record every timestep; only latents follow the filter, tagged with their original step in `RolloutDitTrajectory.latent_step_indices`.
- Carry the field through the multi-output merge, the per-output select and the rollout API (missing in `concat` / `select` on `sglang-miles` too).

## Tests

- Filter `[1, 2, 3, 10]` vs unfiltered, same request: kept latents equal `full[:, idx]`; timesteps, sigmas and log-probs bitwise equal. Run on Qwen-Image (rollout API, n=2) and MiniMax H3 (DiffGenerator, n=1 and n=2, with the H3 rollout-controller follow-up stacked).
- Unit tests updated; the new multi-output asserts fail without the `concat` / `select` change.
