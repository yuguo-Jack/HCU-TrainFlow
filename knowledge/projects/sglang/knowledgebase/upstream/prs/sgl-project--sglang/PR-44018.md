# feat(diffusion): add optional TinyVAE image and video decoding

[Upstream PR](https://github.com/sgl-project/sglang/pull/44018) · state: open · merged: False

## Original PR description

## Motivation

Allow native SGLang Diffusion pipelines to use a single-file Tiny AutoEncoder
checkpoint for approximate image and video reconstruction. This provides an
optional lightweight final decoder while preserving the original VAE encoder
and latent metadata for conditioning inputs.

The existing FLUX.2 Tiny AutoEncoder component override remains available.

## Modifications

- Add `--tiny-vae-model` and `--tiny-vae-path`, with matching Python pipeline
  configuration fields. Reject incomplete option pairs and the Diffusers backend.
- Add MIT-licensed TAESD and TAEHV network implementations covering SD/SDXL,
  SD3, FLUX.1, FLUX.2, Qwen Image 2.1, HunyuanVideo, Wan2.1/2.2,
  HunyuanVideo 1.5, MiniMax-H3, and LTX-2 architectures. Accept ComfyUI video
  checkpoint names as aliases. Architecture support does not add generation
  pipelines for models that SGLang does not already support.
- Load full or decoder-only tensor state dictionaries from safetensors or
  PyTorch checkpoints through the existing weight resolver. Validate decoder
  keys strictly and reuse the configured VAE decode precision.
- Wrap the original visual VAE to preserve pipeline latent and pixel contracts,
  including FLUX.2 patchification, H3 pixel normalization, and LTX latent
  denormalization. Original conditioning encodes, text encoders, and audio VAEs
  retain their existing paths.
- Add focused tests and CLI documentation with checkpoint/model mappings.

Example with locally downloaded FLUX.1 Tiny AutoEncoder decoder weights:

```bash
sglang generate \
  --model-path black-forest-labs/FLUX.1-dev \
  --prompt "A lighthouse beside a calm ocean" \
  --tiny-vae-model taef1 \
  --tiny-vae-path /path/to/taef1_decoder.pth \
  --vae-decode-precision fp32 \
  --num-gpus 1 \
  --save-output
```

Limitations: TinyVAE changes reconstruction quality. Original VAE weights remain
loaded. TinyVAE spatial tiling, parallel decoding, layerwise VAE offload, and
incremental frame streaming are not implemented. LTX-2.3/2.5 require separately
trained weights and are rejected for `taeltx2`; TinyVAE cannot be combined with
the LTX diffusion decoder.

## Accuracy Tests

Remote CPU validation in the existing test environment:

- **88 tests passed; 11 subtests passed**, covering the new TinyVAE tests and
  existing VAE loading, decode precision, and decoding parallelism tests.
- Image architectures with 4/16/64/128 latent channels and video architectures
  with 16/24/32/48/128 channels matched the supplied ComfyUI encode/decode
  references. Video comparisons covered batch=2, temporal lengths, and memory
  reset between requests.
- A real MiniMax-H3 TinyVAE checkpoint matched the ComfyUI decoder bit for bit
  on CPU for batch=2 and latent lengths 1, 2, 7, and 37. The H3 pixel contract
  conversion remained finite.
- A decoding-stage test verifies that final pixels and the frame callback
  actually come from the TinyVAE decoder.

```bash
SGLANG_DIFFUSION_PLATFORM_OVERRIDE=cpu OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 \
python -m pytest -q \
  python/sglang/multimodal_gen/test/unit/test_tiny_vae.py \
  python/sglang/multimodal_gen/test/unit/test_vae_loader.py \
  python/sglang/multimodal_gen/test/unit/test_vae_loader_decode_dtype.py \
  python/sglang/multimodal_gen/test/unit/test_decoding_stage_parallelism.py
```

These results were obtained before migration to the latest upstream base; all
eight changed files were verified byte-identical after migration. No runtime
tests have been rerun on the new base. End-to-end GPU generation and
reconstruction quality across model families remain unverified.
