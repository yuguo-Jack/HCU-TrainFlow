# [CI] [AMD] memory_pool: Keep separate K/V allocations on ROCm to fix Mooncake PD accuracy

[Upstream PR](https://github.com/sgl-project/sglang/pull/46875) · state: closed · merged: False

## Original PR description

## Motivation

Since #32272, `MHATokenToKVPool` stores each layer's K and V as two halves of one allocation. On ROCm this breaks Mooncake PD transfers: decode receives corrupted KV without any transfer error. In `stage-b-test-large-8-gpu-mi35x-disaggregation-amd`, `test_disaggregation_basic.py` (Qwen3-8B, Mooncake) dropped from 0.955 GSM8K accuracy to 0.0-0.01 on main ([example job](https://github.com/sgl-project/sglang/actions/runs/40503413710/job/122186653097)). NIXL and MORI tests in the same job are unaffected (NIXL GSM8K 0.765 before and after).

The last passing main run was at 5884e4fec; the failures start with the commit range that includes #32272. The other candidates in that range don't touch this path for a bf16 Qwen3 PD run.

## Modifications

Skip the fused K/V allocation on ROCm (`and not _is_hip`) and keep separate per-layer K and V buffers, as before #32272. The fused layout serves the CUDA trtllm fmha_v2 paged kernels, which don't run on ROCm. Other platforms are unchanged.

## Test plan

- [x] `stage-b-test-large-8-gpu-mi35x-disaggregation-amd` on rocm10, dispatched on this commit: all four files pass. `test_disaggregation_basic.py` GSM8K 0.950 / 0.965, `test_disaggregation_pp.py` 0.945-0.955, NIXL 0.770, MORI OK ([job](https://github.com/sgl-project/sglang/actions/runs/40549450596/job/122349178411)).
