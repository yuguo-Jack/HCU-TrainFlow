# [Feat] [NVIDIA] megakernel: Support prefill and extend steps

[Upstream PR](https://github.com/sgl-project/sglang/pull/47930) · state: open · merged: False

## Original PR description

## Motivation

Extends the NVIDIA megakernel plugin contract to cover prefill and extend steps, in addition to decode. Today the plugin interface handles `target_verify` and `draft_extend` (inside CUDA graphs) but not regular target prefill/extend. This PR adds the framework-side contract so a plugin spec in `sgl-nvidia-mega` can implement a prefill megakernel through the same interface.

Discussed with the SGL team — see linked thread. Yangmin Li confirmed the current interface does not cover regular prefill/extend and a new mode is needed. This PR provides that mode; the in-tree consumer is a separate PR in `sgl-nvidia-mega`.

## Modifications

- **`Requirements.prefill_graph_backends`** (empty by default): a decode-only spec is unaffected on every path. When non-empty, SGLang checks the prefill graph backend at startup and installs a prefill capture-check hook.
- **`BuildContext.prefill_widths`**: the captured prefill graph token buckets, passed to the spec's `build`. Empty for decode-only specs or when prefill graphs are off.
- **`Step.mode`** may now be `"extend"` (a prefill/extend step), in addition to `"decode"` and `"target_verify"`.
- **`_Dispatch.captured_tokens`**: tracks which prefill token buckets ran the megakernel during capture (decode still uses `captured` keyed by batch size).
- **`_CaptureCheck`** now accepts a `phase` argument (`"decode"` or `"prefill"`). A prefill instance is installed only for a spec that declares `prefill_graph_backends`, so decode-only specs are refused on their decode graphs alone and never asked to run a prefill graph they never claimed.
- **`ModelRunner.prefill_capture_tail_hooks`**: separate list for the prefill graph runner, so decode capture hooks are never handed a prefill capture.
- **`PrefillCudaGraphRunner`**: calls `prefill_capture_tail_hooks` after each graph capture, with the same contract as the decode runner's `capture_tail_hooks`.

## Tests

- `test_megakernel_guards.py`: new test verifying that only a spec declaring `prefill_graph_backends` is checked on the prefill graph backend, and that a decode-only spec is unaffected.
- `test_megakernel_runtime.py`: new test verifying that a prefill-covering spec receives `prefill_widths`, gets a prefill `_CaptureCheck`, the check is keyed by token bucket (not batch size), and the check refuses when no prefill graph runs the megakernel.
- Both tests run on CPU.
