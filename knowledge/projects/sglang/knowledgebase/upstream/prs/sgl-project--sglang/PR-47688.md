# [Fix] [Intel] attention: Round the local-attention chunk clamp up to a whole page

[Upstream PR](https://github.com/sgl-project/sglang/pull/47688) · state: open · merged: False

## Original PR description

## Motivation

On the intel_xpu backend, Llama 4's chunked (iRoPE) attention splits sequences that should stay in one chunk. `make_local_attention_virtual_batches` shrinks the chunk to the longest sequence and then rounds that length down to a whole page. With page size 128 and a 1000-token prompt, the 8192-token chunk becomes 896, so tokens 896 to 999 only attend to each other. In decode, a 1000-token request attends to its last 104 keys instead of all 1000. Nothing crashes, the outputs are just wrong.

#32902 found the same rounding (its root cause #2) and fixed the FA3 path with `preserve_attn_chunk_size=True`. XPU still calls the helper's default path, so it still hits it.

## Modifications

Round the longest sequence up to a whole page before clamping, instead of down. If every sequence fits in one model chunk, the clamped chunk now covers all of them, so the blocks match the model chunk and only the block table gets narrower, which keeps the memory saving from #6273. Once the longest sequence passes the model chunk, the clamp returns the model chunk, same as before. The FA3 path isn't touched.

Two new CPU tests in `test_local_attention.py`: the 1000-token case above, and a randomized check (page sizes 1, 16, 64, 128) that the default path gives the same q, cu_seqlens and k decomposition and the same leading block-table columns as `preserve_attn_chunk_size=True`. Both fail on main and pass with the fix. The 12 existing tests are unchanged.

## Accuracy Tests

I don't have an Intel GPU, so I couldn't run Llama 4 on XPU. After this change the XPU kernel gets the same block decomposition FA3 already gets after #32902, which the randomized test checks. If someone with XPU hardware could run a quick Llama 4 eval, that would be great (cc @ckvermaAI, who fixed the XPU local-attention page table in #23757).

## Speed Tests and Profiling

No kernel changes. The block table can be at most one page wider than before.
