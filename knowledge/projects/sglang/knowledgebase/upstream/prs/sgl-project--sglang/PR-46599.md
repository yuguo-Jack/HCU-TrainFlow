# [Feat] disaggregation: Add connex as a KV transfer backend

[Upstream PR](https://github.com/sgl-project/sglang/pull/46599) · state: open · merged: False

## Original PR description

## Motivation

PD deployments change while they serve: instances are added and removed with
load, fail, and come back. The transfer layer is where that shows first: a
transfer to a decode instance that died should fail in milliseconds, not after
a timeout, and an instance that restarts should be reachable again without its
peers restarting.

`connex` keeps the Mooncake backend's protocol (bootstrap, decode
pre-allocation, chunked KV sends, aux data, aborts, failed-session probing)
and swaps the transfer engine for connex-rs, the data plane of
[Connex](https://github.com/HeterInfra/connex):

- one-sided RDMA writes over UCX (GPUDirect RDMA when available), all chunks of
  a batch posted together and waited for together;
- peer-failure events from UCX endpoint errors within milliseconds; a write to
  a dead decode instance fails at once and the request is aborted instead of
  waiting for a transfer timeout;
- endpoints keyed by a logical identity derived from the session address, so a
  decode instance restarted on the same address is reconnected transparently.

The Connex PD router (`connex.serving.pd_router --engine sglang`) uses the
backend's membership registration to add/remove instances at run time and
resumes requests whose decode instance failed (by a new prefill; SGLang's
protocol pushes KV, so there is nothing to re-pull).

The engine wrapper lives in the optional `connex-ai` package; this PR adds the
backend wiring only (like other backends that depend on an external library).

Related: #43437 (UniFlow backend) follows the same pattern of a native backend
next to Mooncake/NIXL. No open PR or issue proposes a Connex backend. A more
general alternative is a registry for out-of-tree transfer backends
(`TransferBackend` is a closed enum and `get_kv_class` an if-chain); connex-ai
currently registers the backend from a `sglang.srt.plugins` entry point by
extending the enum at import time, which a registry would make unnecessary. I
am happy to turn this into that registry PR instead if maintainers prefer.

## Modifications

- `python/sglang/srt/disaggregation/connex/`: `ConnexKVManager` (Mooncake
  manager with `init_engine` returning the connex-rs engine), sender, receiver
  and bootstrap server classes.
- `TransferBackend.CONNEX`, `get_kv_class` mapping, `connex` in
  `DISAGG_TRANSFER_BACKEND_CHOICES`.
- Docs: Connex section in `pd_disaggregation.mdx`, choice in
  `server_arguments.mdx`.
- `test/registered/unit/disaggregation/test_connex_backend.py` (CPU): class
  mapping, engine role selection, install hint without connex-ai.

## Accuracy Tests

Llama-3-8B, 1P1D on one host (A40, ConnectX HDR), SGLang 0.5.22 with this
backend applied as a plugin, Triton attention, page size 16. 48 prompts x 128
greedy tokens through the router, teacher-forced on a non-disaggregated
instance (a token is wrong if more than 0.5 nats below the argmax given its
prefix): 0 of 6,144 tokens wrong. Exact match against a non-disaggregated
SGLang instance: 30 of 48; the non-disaggregated instance against itself at
concurrency 1 vs 8: 25 of 48 (batch-dependent near-ties).

Decode failure under load (1P2D, 240 requests at QPS 2, 256 output tokens,
one decode instance SIGKILLed at 30 s): 240/240 completed through the Connex
router (8 requests resumed with a new prefill), 0 of 61,440 tokens off the
argmax, longest stall 0.53 s.

File: `python/sglang/srt/disaggregation/connex/conn.py` · line 37

[P1] Native initialization calls only `get_engine()`, while connex-ai's plugin skips its separate membership and peer-death reporting hooks when this backend exists. Instances configured with `CONNEX_PD_FRONT_ROUTER` and `CONNEX_PD_HTTP_URL` therefore never register, leaving the Connex router's discovered pools empty. Initialize those optional hooks with the role, rank, attention TP size, and engine, and add regression coverage.

[P2] Selecting `connex` with `SGLANG_DISAGG_STAGING_BUFFER=1` fails at startup because `arg_groups/pd_disaggregation_hook.py:154-162` still allows only Mooncake and NIXL. Add `connex` to the native staging allowlist, update the diagnostic, and cover argument resolution in a regression test.

- copilot-pull-request-reviewer[bot] · comment · 2026-10-26T13:39:32Z · [source](https://github.com/sgl-project/sglang/pull/46599#discussion_r4377838819)

File: `python/sglang/srt/disaggregation/connex/conn.py` · line 24

[P2] This subclass inherits `supports_role_switch = True`, but connex-ai caches one engine without considering its role, and inherited teardown does not reset it. Set the capability to false until role-aware engine teardown and recreation are implemented.
