# [CI] [AMD] disaggregation: Keep Mooncake HIP dma-buf on in the PD tests and bound the KV pool

[Upstream PR](https://github.com/sgl-project/sglang/pull/45759) · state: open · merged: False

## Original PR description

## What
Keep Mooncake's HIP dma-buf registration on in the AMD PD tests, and make the tests fit instead.
- `test_disaggregation_basic.py` and `test_disaggregation_pp.py` (AMD only) start their prefill and decode servers with `--mem-fraction-static 0.4`, set once as `PD_MEM_FRACTION_STATIC`.
- `pr-test-amd.yml`: remove `MOONCAKE_DISABLE_HIP_DMABUF=1` that #45519 added.

No shared test code is changed.

## Why
Disabling dma-buf only hides the failure and moves registration off the path real deployments use. The failure is a memory-accounting problem: on MI355X with the ionic NIC, each dma-buf registration is charged against free GPU memory a second time (the driver's own used-memory counter is unchanged), so the KV cache must be smaller than the free memory left after loading the model. Measured with a standalone HIP + `ibv_reg_dmabuf_mr` program: 100 GiB registered leaves 87 GiB free instead of 187 GiB, and registering by `ibv_reg_mr` does not have this. With the default fraction `test_disaggregation_basic` registers a 223 GB cache with 63 GB free and fails; 0.4 registers about 88 GB. The underlying fix is in the driver and is being reported to AMD.

## Validation
One MI355X node, image `v0.5.22-rocm10-mi35x-20261019`, files from this branch, dma-buf on (no `dmabuf disabled` in the logs):
- `test_disaggregation_basic.py`: 6 tests OK.
- `test_disaggregation_pp.py`: 3 tests OK.
- The same basic test without the bound fails with `out of memory`.

CI on an earlier version of this branch (rocm10): basic 6 OK, pp 3 OK; `test_nixl_transfer_engine_e2e.py` failed with `NIXL_ERR_BACKEND`, which also fails on main with that image. CI on this version: https://github.com/sgl-project/sglang/actions/runs/40025288621 (queued).

The startup OOM is gone on all three lanes, including the rocm720 segfault. The diagnosis also matches what we saw before #45519: the prefill server registered a ~223 GB KV cache with ~63 GB free, and the next HIP allocation, the scheduler stream, failed.

Neither failure comes from this change:
- nixl fails with `NIXL_ERR_BACKEND` on every lane because the branch predates #45722, which fixed the `UCX_NET_DEVICES` override from #43482. Merging main should clear it.
- pp on rocm720 hit `KVTransferError: Failed to send aux data`. The test has failed intermittently this way before, including with dmabuf disabled.

A few small notes on `_with_pd_mem_fraction`:
1. It replaces the test's own value even when that value is lower, so a test that asks for less than 0.4 would get more memory and could hit the OOM again. Every test in this suite uses 0.8 today, so there's no effect yet, but `min(existing, env)` would be safer.
2. Only the `--mem-fraction-static X` form is removed. `--mem-fraction-static=X` would still be passed, which works only because the appended value comes last. The removal could go, or both forms could be handled.
3. Other test settings in `test_utils.py` are registered in `environ.py` and read through `envs` (e.g. `SGLANG_TEST_MAX_RETRY`). `SGLANG_TEST_PD_MEM_FRACTION_STATIC` could follow the same pattern.
4. The override covers every `popen_launch_pd_server` call when the variable is set, so the mori and nixl tests in this stage also run with the smaller pool. They passed or failed for unrelated reasons above, so that looks fine.
