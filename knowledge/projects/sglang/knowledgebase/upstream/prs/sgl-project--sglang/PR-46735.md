# [Feat] [MUSA] fa3: Port production scheduler-metadata backend

[Upstream PR](https://github.com/sgl-project/sglang/pull/46735) · state: open · merged: False

## Original PR description

## Motivation

The community MUSA FA3 backend currently computes MATE scheduler metadata through a call-time wrapper. The production `musa/0.5.16` backend instead prepares scheduler metadata at the attention-backend lifecycle boundaries and stores it with forward/CUDA-graph metadata.

That design avoids process-global backend state and covers decode, extend, target verify, draft extend, MLA/non-MLA, SWA, TBO, and multi-step graph paths in one backend-owned implementation.

This draft ports that complete production implementation first, then adapts it to current community APIs and style. The smaller draft-prefix fix remains available separately in #46725; the backend-instance fix and its device evidence are in #46634.

## Modification

The two commits are intentionally separated:

1. Import the complete backend file from `mcc-ai-serving/sglang` `musa/0.5.16` at `3a24615a9d08fee502295d2218db244220290f1f`.
   - Imported blob: `c49a1da3a1873da4395ffda9de985738044c5d98`
   - The commit records the original internal author with a `Co-authored-by` trailer.
2. Adapt the imported implementation to current `main`.
   - Use current pipeline-parallel and runtime-context APIs.
   - Keep the community MUSA CP compatibility boundary instead of restoring removed generic CP helpers.
   - Remove the obsolete call-time global metadata bridge.
   - Register one MUSA-only FA3 synchronization environment switch.
   - Apply repository Ruff formatting/type style.
   - Add focused registered CPU tests for explicit metadata forwarding, missing-metadata rejection, draft/verify/decode mode selection, and Gemma4 split policy.

Only one line outside the MUSA backend/test directories is changed: the environment-variable registration in `environ.py`.

## Tests

Static and focused tests:

- Imported commit backend blob exactly matches GitLab `musa/0.5.16`.
- `ruff format --check`: passed.
- `ruff check`: passed.
- `compileall`: passed.
- Registered metadata tests: 4/4 passed.

Current-main MUSA smoke:

- 1x MTT S5000, host driver 5.2.0.
- Current PR source mounted into `v0.5.16-ph1-4.3.8-torch2.9.0.post1-20260914`.
- Qwen3-4B BF16, MUSA FA3, eager prefill/decode.
- Server reached readiness and two requests completed with HTTP 200.
- The full-port and current-upstream backend produced the same deterministic response under the identical model/image/command.

Limitations of the available image:

- The image predates current `main`, so the run used a test-only import compatibility shim for old `sgl_kernel`/`tvm_ffi`; this shim is not part of the PR.
- Decode graph metadata generation and MATE compilation completed, but graph capture later failed in generic `F.embedding` with `operation not permitted when stream is capturing`. This is outside the FA3 stack. Therefore graph-mode end-to-end acceptance is still pending a current-main-compatible MUSA image.
- The Qwen3-4B checkpoint/image combination answered the arithmetic probe incorrectly in both the full-port and upstream-backend A/B runs. This demonstrates backend parity, not model-output correctness.
