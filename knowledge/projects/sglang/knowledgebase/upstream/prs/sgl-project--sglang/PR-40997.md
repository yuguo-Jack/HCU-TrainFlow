# fix: support explicit Qwen3 MoE router precision (after cutoff)

[Upstream PR](https://github.com/sgl-project/sglang/pull/40997) · state: open · merged: False

## Original PR description

Support explicit FP32 Qwen3-MoE router logits. Deferred until after the v0.1.1 cutoff, paired with [Miles #3697](https://github.com/radixark/miles/pull/3697).

Gate weights and inputs use FP32 only when configured. Covers normal, DeepEP, MegaMoE and staged execution; defaults remain unchanged. Reject unsupported dtypes and quantized-gate overrides. One file, +15/-4.

The expert-index bounds and complete fused shared-expert pool/loading fixes have moved to cutoff PR #41074. Rebased onto the current `sglang-miles` base; only the router changes remain.

Validation: real-weight router replay covered 6 layers × 2 dtypes × 3 execution paths. Earlier Miles #3584 Qwen full-model CI exercised the router configuration and exposed the paired P2P staging fix now in #3697. Full local pre-commit passed after rebasing. A CPU probe of all four production gate-call expressions passes in default and FP32 modes; before the added MegaMoE cast it fails with a BF16/FP32 matmul mismatch. This is call-site coverage, not MegaMoE GPU execution. Fresh rebased-head GPU CI and throughput validation remain pending.

[Model tracking and release split](https://github.com/radixark/miles/issues/3284#issuecomment-5810394134).
