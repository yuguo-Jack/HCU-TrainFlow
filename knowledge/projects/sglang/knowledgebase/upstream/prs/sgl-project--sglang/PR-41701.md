# [Fix] [AMD] mamba: Keep a chunked prefill cut on the mamba chunk grid so DCP can donate checkpoints

[Upstream PR](https://github.com/sgl-project/sglang/pull/41701) · state: closed · merged: True

## Original PR description

## Motivation

Under DCP, #39115 donates a mamba checkpoint only when
`prefix_len % mamba_cache_chunk_size() == 0`. `PrefillAdder` cuts a chunk
wherever the prefill budget runs out, and every later chunk inherits that
offset, so a request donates every checkpoint or none. With nothing donated,
`effective_cache_len` is 0 and the KV segment never enters the radix tree.
#40907 restored the old rule only on the non-DCP branch. This PR keeps the
DCP mask and makes the cut land on the grid.

Kimi-K3 MXFP4, 8×MI355X, TP=8 DCP=8, fp8 KV, `page_size=32`,
`chunked_prefill_size=8192`, `max_running_requests=96`,
`mamba_radix_cache_strategy=extra_buffer`, HiCache on, agentic workload at
concurrency 48. Each row is the same 240 s window after warmup. The last two
rows share a host, so the recovery is a within-host measurement. The first two
identify the commit that introduced the regression.

| tree | `kv_evictable_tokens` | `mamba_evictable_tokens` | device cache hit | prompt tokens / 240 s |
|---|---|---|---|---|
| `fa8d22e665` (#39115's parent) | 11,382,528 | 473/480 | **91.5%** | 59.8 M |
| `6460082c05` (#39115) | 620,800 | 123/480 | 50.3% | 4.8 M |
| `main` (`8d1643b21e`) | 392,448 | 88/480 | **30.4%** | 3.3 M |
| `main` + this PR | 11,614,464 | 464/480 | **90.7%** | 59.5 M |

## Modifications

No-op unless `enable_mamba_extra_buffer` is set.

- `Scheduler.init_mamba_truncation_align()` folds `mamba_cache_chunk_size()`
  into `truncation_align_size` with an LCM, the same way DSA kpool alignment
  does. This covers `exact_chunk_fill`.
- `PrefillAdder.floor_chunked_tokens()` rounds a truncated chunk down to that
  grid in `add_chunked_req` and `add_one_req_ignore_eos`.

A chunk that finishes a request may stop anywhere. A cut shorter than one
chunk is not rounded to zero. The unit test walks a 100k prompt through six
chunks cut to arbitrary leftover budgets and checks that each one still donates.

Once donation works, the mamba pool's working set grows. A 60-slot pool that
was sized while donation was failing can assert in `_alloc_ping_pong_buffer`
at concurrency 4 and long context. Raise `--max-mamba-cache-size`.
Concurrencies 8, 16 and 48 were unaffected.
