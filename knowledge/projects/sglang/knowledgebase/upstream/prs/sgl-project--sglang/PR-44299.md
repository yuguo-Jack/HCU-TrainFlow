# [Feat] simulator: Add baseline collection and ML latency predictor training tools

[Upstream PR](https://github.com/sgl-project/sglang/pull/44299) · state: open · merged: False

## Original PR description

## Motivation

The simulator can load an ML step-latency predictor, but users also need a way to collect measurements from a real SGLang server and train a compatible model. This PR adds that workflow to the installable simulator package.

## Modifications

- Add `sglang-simulator-collect` under `sglang_simulator.tools.collect_baseline`. It reuses the simulator hook infrastructure to collect request traces and synchronized batch latency. `/start_profile` and `/stop_profile` control collection and export.
- Add `sglang-simulator-train` under `sglang_simulator.tools.train_ml_time_predictor`. It trains monotonic histogram gradient boosting models with squared-error or median-quantile loss, supports independent evaluation data, and saves bundles accepted by the existing ML predictor.
- Share the ordered 18-feature extraction between training and inference. Include usage guides and a small example step dataset in the package.
- Add one basic collection-flow test and one train/load/predict test to the existing CPU CI workflow.

The collector requires `--disable-overlap-schedule`. Device synchronization changes execution timing; the initial scope is ordinary text generation without speculative decoding or multimodal feature modeling.

## Accuracy Tests

- Repository pre-commit checks and explicit Ruff checks on all changed Python files.
- Built and installed the wheel; verified both CLI entry points, packaged documentation, example data, and bootstrap module.
- CPU compatibility suite: 11 passing tests across collection, training, runner, serving, cache accounting, and OFFLINE/BLOCKING behavior.
- Training on DSv4-Pro TP4 measurements: 3,650 training steps and 3,503 steps from an independent trace. Held-out step MAPE is **1.42%** for squared-error loss and **1.38%** for median-quantile loss.
- CPU simulation of all 1,932 requests in the independent trace, modeling TP4:

  | Loss | Held-out step MAPE | Mean TTFT relative error |
  | --- | ---: | ---: |
  | Squared error | 1.42% | -0.61% |
  | Median quantile | 1.38% | -0.89% |

  Request/token identities and aggregate cache-hit statistics match.

The real-data experiment uses L1 cache only, original trace arrival times, and one output token per request. These measurements validate prefill latency; they do not establish long-decode or general L2/L3 prediction accuracy. The example dataset demonstrates usage rather than production accuracy.

## Speed Tests and Profiling

No inference speedup is claimed. Collection is opt-in and synchronizes the device around `Scheduler.run_batch` to measure latency.
