# [Bugfix] Close received POSIX fds when exchange fails

[Upstream PR](https://github.com/sgl-project/sglang/pull/43399) · state: open · merged: False

## Original PR description

## Motivation

`exchange_posix_fds()` transfers ownership of received descriptors only on success. Receive errors, duplicate packets, send errors and timeouts can raise before that handoff, leaving descriptors open. Its caller cannot clean up descriptors it never receives.

A timeout needs extra care: the receive thread may still return from `recvmsg()` after the caller has failed. Closing only the descriptors currently in the dictionary misses a late arrival.

## Modifications

- Track successful ownership handoff and clean accumulated descriptors on every unsuccessful exit.
- Serialize insertion and cleanup with a lock. Once the exchange has failed, the receiver closes a late descriptor instead of publishing it.
- Preserve successful ownership, outgoing descriptors and existing mismatch diagnostics. Socket timeouts and the daemon-thread policy are unchanged.
- Add six registered CPU tests using real UNIX `SOCK_SEQPACKET` sockets, `SCM_RIGHTS` transfer and `fstat()` assertions. Only rendezvous, failure injection and the deterministic late-receiver barrier are mocked.

## Accuracy Tests

```bash
python test/registered/unit/utils/test_cuda_vmm_fd_exchange.py -v
```

Linux/Python 3.12, Torch 2.11.0+cu130, CUDA hidden, normal imports of the exact changed source:

- Unmodified main with the same tests: four regression cases fail; success and mismatch controls pass.
- Patched source: all six tests pass (0.205s).
- Late-receive test repeated 20 times: all pass, `/proc/self/fd` count stays 38 before/after.

The tests check receive errors, duplicate descriptors, send errors, mismatch, late arrival after timeout, and successful caller ownership. Dependencies were inherited rather than rebuilt from the complete official CI lock. No GPU, CUDA VMM mapping, multi-process Gloo, model execution or performance qualification is claimed.
