## Motivation

Enable capturing a PyTorch Execution Trace (ET) alongside the chrome trace for graph-level debuggability during profiling.

## Modifications

**LLM runtime (`srt`)**

Added an opt-in `--export-et-trace` flag (plumbed through `ProfileReq.record_execution_trace`) that attaches a `torch.profiler.ExecutionTraceObserver` to write a `*.et.json` next to the chrome trace, gated to CUDA/XPU/ROCm/CPU (excluded on NPU and MPS), with observer cleanup on stop and on start-failure. ET capture is rejected with an explicit message under `SGLANG_PROFILE_V2`, which does not support it yet.

**Diffusion runtime (`multimodal_gen`)**

Mirrored the same support in `SGLDiffusionProfiler`. The observer is merged into the shared profiler kwargs so both the full-stage and denoise-only scheduled paths pick it up, and `unregister_callback()` -- which is what finalizes the file -- runs in `stop()` and on a failed `start()`.

`record_execution_trace` is added to both `SamplingParams` and `ActionSamplingParams`, which declare their profiling fields independently. `Req.__getattr__` raises `AttributeError` for names missing from a request's params, so the action pipelines (Pi0.5, Flux3) would break when profiled if only the former carried the field.

## Code Review

This pull request adds support for capturing PyTorch Execution Traces (ET) alongside chrome traces to improve graph-level debuggability. The review feedback highlights critical issues with the implementation: passing `execution_trace_observer` to `torch.profiler.profile` will raise a `TypeError` as it is not a supported keyword argument, and failure to start the profiler can leave the observer callback registered. Additionally, the reviewer suggests returning an error when execution trace recording is requested while `SGLANG_PROFILE_V2` is active, as it is currently unsupported and silently ignored.

`torch.profiler.profile` does not accept an `execution_trace_observer` keyword argument in standard PyTorch. Passing it via `**et_kwargs` will raise a `TypeError`. The `ExecutionTraceObserver` registers itself globally with the autograd engine via `register_callback`, so it does not need to be passed to the profiler. We should remove `et_kwargs` entirely.

Additionally, if `self.torch_profiler.start()` fails (raises a `RuntimeError`), the observer's callback is left registered, which can cause issues or memory leaks. We should unregister the callback in the `except` block:

```python
            try:
                self.torch_profiler.start()
            except RuntimeError as e:
                if self._et_observer is not None:
                    self._et_observer.unregister_callback()
                    self._et_observer = None
                self.torch_profiler = None
                return ProfileReqOutput(success=False, message=str(e))
```
