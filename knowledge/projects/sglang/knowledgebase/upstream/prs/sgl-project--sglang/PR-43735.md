# [DCP] Decode context parallelism for DSA (GLM-5.2 / GLM-5.3) with MTP

[Upstream PR](https://github.com/sgl-project/sglang/pull/43735) · state: closed · merged: True

## Original PR description

## Motivation

`--dcp-size > 1` does not work for the RoPE DSA models (GLM-5.2, GLM-5.3, DeepSeek-V3.2): the sparse backend returns no LSE, the index-K cache and the MTP draft pool are sized per rank while the allocator hands out widened slots, and the TRT-LLM buffers are sized for one rank's heads. Builds on the approach of #42536 (co-authored with @vincentzed) and the Flash stack #40433 / #40434.

## Modifications

- **Target KV** stays striped by position (unchanged `main` layout). The **index-K cache is replicated** and addressed by the widened allocator slot, so every rank scores the whole sequence and selects the global top-k.
- **Attention**: one Triton kernel keeps the top-k slots this rank owns, maps them to local rows and compacts them; the TRT-LLM sparse kernel runs on the DCP group's gathered query heads with `return_lse`, and the existing MLA DCP merge combines the partials. Decode, target verify and extend all take this path (no prefix-KV gather). Shared-top-k layers reuse the localized table (21 remaps per step instead of 78).
- **MTP draft (nextn)**: the pool is replicated over the widened slots (`dcp_replicated`, kernel page stays 64) and the draft attends without the DCP group (`is_nextn` / `is_draft_worker`, as the Qwen3.5 draft does), so MTP index share feeds the draft directly.
- **Accounting**: index keys and the draft pool are charged `dcp_size` times per physical token on every platform (the NPU-only guards are dropped).
- **Launch validation**: the generic DCP hook now rejects prefill CP with `--dcp-size > 1`; the DSA override rejects HiSparse, HiCache, PD disaggregation and tree drafting, and defaults the DSA backends to `trtllm` (`index_kpool > 1` was already rejected on `main`).
- **Fast follows** (rejected at launch for now): HiCache and PD disaggregation need the replicated index-K cache's widened page geometry in the host pool and the transfer page-id lists; other DSA backends need to return the LSE under DCP.
- Kept from #42536: the LSE combine keeps all-empty padding rows at zero. Not kept: the head folding to at most 32 heads per trtllm call. Vincent's reproducer (comment below) does fail on B300 with FlashInfer 0.7.0.post1, for exactly 64 heads with short KV at >= 1024 rows per call (16, 32 and 128 heads are clean up to 65535 rows), so this is a kernel bug that only DCP8 extend can hit. It will be filed with FlashInfer once the cause is narrowed down; the gathered heads go to the kernel in one call.

Design notes with permalinks: `dsa-dcp-design.md` (shared separately).

## Accuracy Tests

`zai-org/GLM-5.3` (FP8), 8xB300, `--tp 8 --mem-fraction-static 0.88 --max-running-requests 64`, branch at `28bb3d6074`. MTP = `--speculative-algorithm EAGLE --speculative-num-steps 5 --speculative-eagle-topk 1 --speculative-num-draft-tokens 6`. GSM8K: `few_shot_gsm8k`, 8-shot, 1319 questions. AIME26: `sgl-eval run aime26 --n-repeats 4` with the GLM-5.2-FP8 preset (200k max tokens).

| Config | GSM8K acc | AIME26 pass@1 (avg of 4) | AIME26 pass@4 | AIME26 gen tok/s | MTP accept len |
|---|---|---|---|---|---|
| TP8 | 0.912 | 99.17% | 100% | 1140 | - |
| TP8 + DCP2 | 0.917 | 99.17% | 100% | 1041 | - |

Spot checks (GSM8K, 300-400 questions): `--dcp-comm-backend ag_rs` DCP2 + MTP 0.907; an 8192-token-per-rank pool so the last allocator page is in use, DCP2 0.903 and DCP2 + MTP 0.907; without head folding, DCP8 0.943 and DCP8 + MTP 0.913 (the 64-head case).

AIME26 pass@1 spread is sampling noise: every run loses problem 14 to the 200k cap (including TP8), and the remaining misses are either a correct final line without `\boxed{}` (3 in DCP2 + MTP, 2 in DCP8) or single-sample arithmetic slips; no run shows degenerate output. The DCP2 + MTP run surfaced one bug, fixed in `28bb3d6074`: the DSA draft's one-shot MHA prefill keyed its prefix all-gather on the global DCP flag instead of the layer's `dcp_size`.

```python
import math, torch, flashinfer.decode
TOPK, SCALE = 2048, 1 / math.sqrt(192)
ws = torch.zeros(256 << 20, dtype=torch.uint8, device="cuda")

def run(q, kv, pt, sl):
    rows, _, heads, _ = q.shape
    lse = torch.full((rows, heads), float("nan"), dtype=torch.float32, device="cuda")
    out, _ = flashinfer.decode.trtllm_batch_decode_with_kv_cache_mla(
        query=q, kv_cache=kv.reshape(-1, 1, 64, 576), workspace_buffer=ws,
        qk_nope_head_dim=128, kv_lora_rank=512, qk_rope_head_dim=64,
        block_tables=pt.unsqueeze(1), seq_lens=sl, max_seq_len=TOPK,
        sparse_mla_top_k=TOPK, bmm1_scale=SCALE, backend="trtllm-gen",
        return_lse=True, lse=lse)
    return out.view(rows, heads, -1).float(), lse

def ref(q, kv, pt, sl):
    outs, lses = [], []
    for r in range(q.shape[0]):
        n = int(sl[r]); k = kv[pt[r, :n].long()].float(); s = (q[r, 0].float() @ k.T) * SCALE
        m = s.max(-1, keepdim=True).values; p = torch.exp(s - m); l = p.sum(-1, keepdim=True)
        outs.append((p / l) @ k[:, :512]); lses.append((m + torch.log(l)).squeeze(-1) / math.log(2))
    return torch.stack(outs), torch.stack(lses)

g = torch.Generator().manual_seed(0)
for heads in (32, 64, 128):
    for n in (1, 3, 16, 63, 64, 65, 200, 2048):
        rows = 4
        pt = torch.full((rows, TOPK), -1, dtype=torch.int32)
        for r in range(rows): pt[r, :n] = torch.randperm(4096, generator=g)[:n]
        pt, sl = pt.cuda(), torch.full((rows,), n, dtype=torch.int32, device="cuda")
        q = (torch.randn(rows, 1, heads, 576, generator=g) * 0.25).cuda().to(torch.float8_e4m3fn)
        kv = (torch.randn(4096, 576, generator=g) * 0.25).cuda().to(torch.float8_e4m3fn)
        out, lse = run(q, kv, pt, sl); rout, rlse = ref(q, kv, pt, sl)
        print(heads, n, (out - rout).abs().max().item(), (lse - rlse).abs().max().item())
```

The difference from your runs is the number of rows in one call. It only shows up with large batches, and below a few thousand rows it is intermittent.

One 64-head call is compared with two 32-head calls on the same inputs. Q is FP8, every row has 64 valid KV entries unless noted, `return_lse=True`, PDL off, and the counter buffer is passed.

| Rows in one call | Failing launches | Worst output error | LSE error |
|---|---|---|---|
| 256 | 0 of 5 | 0.00012 | 4.8e-07 |
| 1,024 | 2 of 5 | 54,272 | inf |
| 4,096 | 5 of 5 | 339,968 | inf |
| 8,192 | 4 of 5 | 211,968 | inf |
| 16,384 | 10 of 10 | 31,326,208 | inf |
| 16,384, KV length 2,048 | 0 of 5 | 0.00003 | 9.5e-07 |

- In a failing launch, between 16 and 112 (row, head) pairs are wrong. Which ones are wrong changes from launch to launch.
- The two 32-head calls agree with a PyTorch float32 reference to 0.0015 on 16 sampled rows.
- When I first found this I also saw it with KV lengths 1, 63 and 65. Turning PDL off, zeroing the workspace, a larger KV buffer and non-negative unused indices did not change it.
- Your sweep stops at 1,024 rows, where I see it in 2 of 5 launches, so a few seeds can miss it. A long extend is where the large row counts with short KV come from: one row per new token, and the early tokens have few KV entries.

I have not found the cause inside the kernel and I have not filed it with FlashInfer yet. If you can reproduce it with the script below, I think the folding (or a cap on rows per call) is still needed for extend. If it passes for you at 16,384 rows, tell me and I will compare the two environments.

#!/usr/bin/env python3
"""FlashInfer-only sparse RoPE MLA >32-head corruption reproducer.

CUDA_VISIBLE_DEVICES=4 python flashinfer_sparse_rope_gt32_heads_repro.py
Random FP8 inputs; compare 64 heads against two independent 32-head calls.
The error is intermittent: defaults repeat ten times at 16,384 rows.
Use --length 2048 or --rows 256 for observed non-triggering controls.
"""
import argparse
import json
import math
import torch
import flashinfer
import flashinfer.decode
import flashinfer.utils

p = argparse.ArgumentParser(description=__doc__)
p.add_argument('--rows', type=int, default=16384)
p.add_argument('--length', type=int, default=64)
p.add_argument('--repeats', type=int, default=10)
p.add_argument('--pdl', action='store_true')
a = p.parse_args()
assert 0 < a.length <= 2048 and 0 < a.rows <= 65535
print(json.dumps(dict(torch=torch.__version__, cuda=torch.version.cuda,
    flashinfer=flashinfer.__version__, gpu=torch.cuda.get_device_name(),
    capability=torch.cuda.get_device_capability(), **vars(a))), flush=True)
torch.manual_seed(981)
q = (torch.randn((a.rows,1,64,576),device='cuda',dtype=torch.bfloat16)*.1).to(torch.float8_e4m3fn)
kv = (torch.randn((math.ceil(a.length/64),1,64,576),device='cuda',dtype=torch.bfloat16)*.1).to(torch.float8_e4m3fn)
indices = torch.full((a.rows,1,2048),-1,dtype=torch.int32,device='cuda')
indices[:,:,:a.length] = torch.arange(a.length,dtype=torch.int32,device='cuda')
lengths = torch.full((a.rows,),a.length,dtype=torch.int32,device='cuda')
# stats float2[heads*batch*round_up(q_len,256)] + 1MiB guard + generous scratch
workspace = torch.zeros(8*64*a.rows*256+(1<<20)+(1536<<20),dtype=torch.uint8,device='cuda')
counter_bytes = flashinfer.utils.get_trtllm_gen_multi_ctas_kv_counter_bytes(
    a.rows,64,flashinfer.utils.get_device_sm_count(torch.device('cuda')))
counter = torch.zeros(counter_bytes,dtype=torch.uint8,device='cuda')

def invoke(query):
    return flashinfer.decode.trtllm_batch_decode_with_kv_cache_mla(
        query=query, kv_cache=kv, workspace_buffer=workspace,
        qk_nope_head_dim=128, kv_lora_rank=512, qk_rope_head_dim=64,
        block_tables=indices, seq_lens=lengths, max_seq_len=a.length,
        sparse_mla_top_k=2048,bmm1_scale=1/math.sqrt(192),backend='trtllm-gen',
        return_lse=True,multi_ctas_kv_counter_buffer=counter,enable_pdl=a.pdl)

left=invoke(q[:,:,:32].contiguous()); right=invoke(q[:,:,32:].contiguous())
reference=torch.cat((left[0],right[0]),dim=2).reshape(a.rows,64,512)
reference_lse=torch.cat((left[1],right[1]),dim=-1).reshape(a.rows,64)
assert torch.isfinite(reference).all() and torch.isfinite(reference_lse).all()
# Sanity-check the split reference against PyTorch on 16 sampled rows.
rows=torch.linspace(0,a.rows-1,16,device='cuda').long().unique()
scores=torch.einsum('rhd,sd->rhs',q[rows,0].float(),kv.reshape(-1,576)[:a.length].float())/math.sqrt(192)
ref=torch.einsum('rhs,sd->rhd',scores.softmax(-1),kv.reshape(-1,576)[:a.length,:512].float())
print(json.dumps(dict(split32_vs_torch_max_error=float((reference[rows].float()-ref).abs().max()))),flush=True)
failures=0
for repeat in range(a.repeats):
    out,lse=invoke(q)
    torch.cuda.synchronize()
    max_error=0.; bad_heads=0
    for begin in range(0,a.rows,256):
        err=(out.reshape(a.rows,64,512)[begin:begin+256].float()-reference[begin:begin+256].float()).abs()
        max_error=max(max_error,float(err.nan_to_num(nan=math.inf).max()))
        bad_heads+=int((err.amax(-1)>.02).sum())
    lse_error=float((lse.reshape(a.rows,64)-reference_lse).abs().nan_to_num(nan=math.inf).max())
    failed=bad_heads>0 or not math.isfinite(lse_error) or lse_error>.01
    failures+=failed
    print(json.dumps(dict(repeat=repeat,max_output_error=max_error,max_lse_error=lse_error,bad_heads=bad_heads,failed=failed)),flush=True)
print(json.dumps(dict(failures=failures,repeats=a.repeats)),flush=True)
