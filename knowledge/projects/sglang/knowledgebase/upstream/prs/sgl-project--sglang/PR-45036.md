# [Feat] metrics: expose detokenizer router processing time

[Upstream PR](https://github.com/sgl-project/sglang/pull/45036) · state: open · merged: False

## Original PR description

## Motivation

Part of #43304: router CPU usage is available, but there is no distribution of time spent handling each message. Add the router processing-time item so operators can distinguish costly routing/sends from downstream work.

## Modifications

- Add `sglang:detokenizer_router_processing_seconds`, enabled only by `--enable-metrics` in multi-detokenizer mode.
- Time routing, batch splitting and outgoing sends after `sock_recv` returns. Include blocking/failed sends; exclude receive wait and incoming deserialization.
- Record once per received message, including control broadcasts and empty batches, regardless of fan-out. Disabled metrics create no histogram or clock reads.
- Preserve routing behavior and document metric boundaries and a PromQL example.

This is complementary to #43323 (CPU), #44390 (throughput) and #44524 (worker identity). It covers only router processing time, so it does not close #43304 or add queue-latency/worker-processing metrics.
