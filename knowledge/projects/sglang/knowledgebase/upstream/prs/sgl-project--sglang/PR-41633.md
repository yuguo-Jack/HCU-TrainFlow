# [Fix] [AMD] DSv4/DSv4.1: Stop serving-time recompiles of the FP4 indexer prefill-schedule prep kernel

[Upstream PR](https://github.com/sgl-project/sglang/pull/41633) · state: open · merged: False

## Original PR description

## Motivation

`_prefill_schedule_prep_kernel`, added in #37764 for the ROCm DeepSeek-V4 FP4 indexer, keeps JIT-compiling new variants while serving. Its scalars and buffer-view pointers change with every prefill batch, and Triton specializes on them. Each compile stalls the engine for ~1.5 s, and the log reports `took 1.5 s to compile after serving started`. A 20-min AgentX run logs 289 of these. AITER's `_prefill_row_plan_kernel` has the same problem (120 compiles in the same run) and is fixed in ROCm/aiter#5925.

## Modifications

- Don't specialize any of the kernel's runtime args. Only `BLOCK_T` (9 row-count buckets) is left to select a variant.
- Compile those 9 variants at backend init (~6 s). If the installed AITER provides `warmup_prefill_row_plan` (ROCm/aiter#5925), warm its row-plan kernel too.
- Warm up for the DeepSeek-V4.1 low-ratio indexers as well, which build the same schedule (they recompiled 34-46 times per prefill server in V4.1-Flash PD AgentX runs); draft workers skip it.
