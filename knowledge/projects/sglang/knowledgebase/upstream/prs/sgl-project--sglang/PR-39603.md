# [Test] [NPU] moe: Add reproducible TP/EP benchmarks and A3 analysis

[Upstream PR](https://github.com/sgl-project/sglang/pull/39603) · state: open · merged: False

## Original PR description

## Motivation

[Ascend/sglang #1098](https://github.com/Ascend/sglang/issues/1098) requests a Qwen3 MoE comparison of tensor parallelism and expert parallelism on A3.

## Modifications

The benchmark uses one fixed-seed global input, replicated for TP and partitioned across EP ranks. It reconstructs every EP output and checks every TP replica. The standalone adapter uses FusedMoE's supported reduction flag when current Qwen3 delegates its TP output sum to the FFN boundary. Parallel-context and MoE batch adapters support the current interfaces.

New module records capture the requested DeepEP mode and the implementation selected by the actual dispatcher, including the current dispatcher wrapper. They also capture chip models and UUIDs, rank placement, CANN/driver versions and version-file hashes. Summaries reject unknown hardware, incompatible environments and inconsistent modes across independent runs. Historical records remain unchanged and require explicit, checksum-verified archive mode. Serving runs record launch configuration and environment per process.

This PR reuses the existing SGLang NPU TP and DeepEP implementations. It does not modify inference runtime, model forward or kernel files.

## Accuracy Tests

The October 17 validation passed all 14 complete-output TP/EP comparisons for Qwen3-30B-A3B layer 0 in BF16 eager mode on one A3 card with two Ascend910_9392 chips. These remain the core module-consistency evidence.

The October 22 measurement-identity changes passed 14 CPU regressions, the registered CPU wrapper and nine additional complete-output comparisons on separate single-card Ascend910_9382 pairs. Cases verify Prefill auto, Decode auto and Decode normal, plus both round-count configurations at global N=8192/32768. Every TP replica was identical; maximum relative error remained 0.0064102564 against the unchanged 0.02 criterion. Both round-count candidates produced identical complete EP outputs to their corresponding baselines. Timing entrypoints and strict summaries also passed.

These are complete-output MoE module checks. Serving measurements validate request completion and output token counts; they do not establish full-model quality equivalence. All 77 earlier public evidence files retain their original checksums. Portable exports preserve measurements and identities and record the original and exported file hashes.

After CI raised its minimum base to 6a39ddf1f2e0, the branch was rebased onto 635836129b80dbabd97f43229abb5262077d75d0. The rebased runtime separately passed all 14 CPU regressions, the registered wrapper, three complete-output comparisons and four timing entrypoints. The CPU consumer test follows current Qwen3's TopK interface; inference runtime files remain unchanged in this PR. The earlier performance studies retain their original runtime identity and are not measurements of the rebased runtime.

## Speed Tests and Profiling

The historical three-repeat TP/EP module, full-model serving and profiling study retains its original runtime, software and topology identity.

A controlled October 22 normal-mode study changed only DEEPEP_NORMAL_LONG_SEQ_ROUND, with 10 warmups, 30 measurements and three independently started process pairs in alternating order. At global N=8192, 8 to 1 rounds reduced the median from 4.64439 to 4.16126 ms (10.40%). An independent matched comparison at N=32768 measured 13.56198/13.56182 ms for 8/2 rounds, showing no observable benefit; retain 8 rounds at that point. Samples and hardware identities from the two hosts are not combined. An initial large-token series overlapped another process and is retained as quarantined evidence, without a performance claim.

The analysis and evidence under benchmark/kernels/moe_tp_ep document reproduction, process variation and scope. Module configuration benefits are not extrapolated to serving latency or throughput. The PR retains one commit; upstream hardware CI, review and task acceptance are tracked separately.
