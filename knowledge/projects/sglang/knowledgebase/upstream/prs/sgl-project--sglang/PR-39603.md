# [Test] [NPU] moe: Add reproducible TP/EP benchmarks and A3 analysis

[Upstream PR](https://github.com/sgl-project/sglang/pull/39603) · state: open · merged: False

## Original PR description

## Motivation

[Ascend/sglang #1098](https://github.com/Ascend/sglang/issues/1098) requests a Qwen3 MoE comparison of tensor parallelism and expert parallelism on A3.

## Modifications

The benchmark uses one fixed-seed global input, replicated for TP and partitioned across EP ranks. It reconstructs every EP output and checks every TP replica. Current stage-based Qwen3 layers delegate the TP output sum to their FFN boundary; the standalone benchmark enables FusedMoE's supported reduction flag so timing and correctness include the complete output. Historical layers retain their existing reduction. The adapters also support the current parallel-context and MoE batch interfaces.

Module and serving summaries reject mismatched device counts, software, source and script identities, and experiment settings. New serving runs capture server software and launch configuration per process. The PR adds registered CPU regressions, historical serving/profiling analysis and Ascend troubleshooting documentation.

This PR reuses the existing SGLang NPU TP and DeepEP implementations. It does not modify inference runtime, model forward or kernel files.

## Accuracy Tests

The updated adapters passed all 14 complete-output TP/EP comparisons on October 17 on one A3 card with two SIO-connected Ascend910_9392 devices, using Qwen3-30B-A3B layer 0 in BF16 eager mode. The environment uses CANN 9.1.0, torch 2.10.0, torch-npu 2.10.0.post4 and DeepEP 1.0.0+0234a271.cann.9.1.0.b243. Cases cover Prefill, Decode, uneven partitions, empty input ranks and biased routing. Every TP replica was identical; maximum relative error was 0.0064102564 against the unchanged 0.02 criterion.

The registered CPU test wrapper and all 12 inner CPU regressions passed on the same server. They include the actual FusedMoE reduction branch with CPU linear experts and a real two-process Gloo collective. All four timing entrypoints also passed smoke checks at global N=1/777. Executable SHA256 values, environment, comparison results, per-rank timing samples and CPU logs are included.

These full-output MoE module consistency checks are the core correctness evidence. Serving measurements validate request completion and output token counts; they do not establish full-model quality equivalence.

## Speed Tests and Profiling

The original September 16 environment produced three independent runs with EP/TP module latency ratios of 1.46–1.89 for Prefill and 1.16–1.52 for Decode. Historical full-model serving favored TP at input lengths 1024, 8192 and 16384, with 64 output tokens and concurrency 4. These results retain their original runtime, software and topology identity. The October 17 functional timing checks are a separate dataset and do not replace that performance study; full-model serving was not remeasured.

[The analysis](https://github.com/xchencehn/sglang/blob/a1e52138a63de95492f216e2536d10fc8b335f5f/benchmark/kernels/moe_tp_ep/analysis.md) contains both evidence sets, reproduction details and their limits. All 68 original public evidence files remain unchanged. The submitted executable files match the validated October 17 source snapshot. The PR retains one commit and includes the upstream minimum base. Local pre-commit passes; maintainer-controlled hardware CI and review remain pending.
