# [Fix] tracing: Close filtered thread spans at explicit completion

[Upstream PR](https://github.com/sgl-project/sglang/pull/42521) · state: open · merged: False

## Original PR description

## Motivation

With trace level 1, a level-2 DP dispatch slice is filtered out. The current
early return also discards `thread_finish_flag=True`, so a serialized request
context can retain its thread span after dispatch has completed. Its destructor
may then report normal completion as an unclosed span. Request completion also
ends children using a fresh clock reading instead of the supplied end timestamp.

The async path has the same early return and must still notify the exporter
when a filtered slice completes a thread.

This patch separates lifecycle completion from the decision to record a slice.
It does not change level filtering or add a transfer tracing framework.

## Modifications

- Honor the thread completion flag in both filtered `trace_slice_end` and
  combined `trace_slice` paths, using the supplied completion timestamp.
- Update `TraceReqContextAsync` to enqueue the existing `slice_end` operation
  and flush immediately on filtered thread completion. Preserve the span ID
  stack and keep the request root open until request completion.
- Pass the request end timestamp to existing child-span cleanup.
- Test serialized thread contexts, repeated cleanup, preserved error/cancel/
  timeout status, and matching request/child end timestamps.
- Cover async completion with original and serialized contexts, explicit and
  implicit timestamps, disabled tracing, and filtered calls without completion.

The reviewed open work in [#40413](https://github.com/sgl-project/sglang/pull/40413)
handles mismatched slice stacks; [#40423](https://github.com/sgl-project/sglang/pull/40423)
handles quick-finish stage recording. Their reviewed patches do not implement
these filtered completion paths. The regression was reproduced against the
baseline above. This change is independent of
[#36243](https://github.com/sgl-project/sglang/pull/36243) and
[#37976](https://github.com/sgl-project/sglang/pull/37976), which concern transfer
context and native cache tracing. PR states were checked on 2026-10-05 Asia/Taipei.

## Production deployment and observations

This work comes from tracing fixes used in our production inference deployment. A read-only telemetry inspection on 2026-10-04 examined 12 retained traces containing 708 spans: 36 had OK status, 672 had UNSET status, and none had ERROR status. All 12 gateway roots reported HTTP 200.

Each trace contained `prefill_transfer_kv_cache`, `decode_transferred`, `mooncake_send`, and `mooncake_worker_send`, with recorded parent chains reaching the gateway root. No missing recorded parent or invalid end timestamp was found. A separate completed one-hour search for `have unclosed span, auto closed` returned no traces.

The 12 traces were selected by a transfer-span query from a deployment with a 0.01 sampler ratio; the query hit its result cap before all jobs completed. This is a production observation, not a controlled before/after comparison or a traffic success-rate estimate. It does not isolate this patch's effect. The upstream synchronous and async completion paths are covered by the regressions below.
