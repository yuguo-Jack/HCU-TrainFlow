# [Fix] DeepSeek-V4.1: Align paged indexer score rows for DeepSelect decode

[Upstream PR](https://github.com/sgl-project/sglang/pull/44210) · state: closed · merged: True

## Original PR description

## Motivation

On SM90 the full top-k decode of the ratio-1/2 index layers (`FullTopKIndexer._torch_decode`) runs DeepSelect `topk_page_transform` on the paged fp4 index scores from `fp4_index_logits_paged`. DeepSelect requires 128-byte-aligned rows, but the scores were padded to eight floats only, so any score width that is not a multiple of 32 floats fails:

```
Tensor<256, 524290>[strides=<524296, 1>, dtype=float32]
Root cause: Tensor stride for dimension 0 is not aligned to 128 bytes
```

With the cookbook H200 recipe for DeepSeek-V4.1-Flash, every TP rank hits this at startup and the server exits.

`test_fp4_indexer.py::test_hopper_indexer_backends_replay` also fails on main, first with `AttributeError: 'types.SimpleNamespace' object has no attribute 'page_table'`, because its fake metadata predates the DeepSelect path.

## Modifications

- `fp4_index_logits_paged`: allocate the scores with `aligned_new_empty` at DeepSelect's input stride alignment (128B) instead of padding rows to eight floats; that alignment also covers candidate-amax.
- `decode_scores`: build the top-k v2 plan only when the caller uses it. The SM90 full top-k selects with DeepSelect and never read it, so it no longer launches the plan kernel every decode step; `select_decode` asserts the plan is present.
- `test_hopper_indexer_backends_replay`: give the full top-k a real per-row page table, kept in sync with the shuffled request table on every replay, and an output buffer of exactly live rows by `topk`, as at runtime. The candidate outputs keep their padded shape and padding checks.

## Tests

- The updated test fails on main with the 128B stride error and passes with this change.
- On H200, each registered file that exercises this code passes when run as CI does (`python3 <file> -f`): `test_fp4_indexer.py`, `test_deep_select.py`, `test_dsv4_nonpaged_indexer.py`, `test_dsv41_candidate_blocks.py`, `test_dense_prefill_indexer.py`, `test_dsv41_prefill_sparse_indexer.py`, `qsa/test_qsa.py`, `test_dsv32_indexer_fusion.py`, `test_dsv4_indexer_quant.py`.
- DeepSeek-V4.1-Flash launches and serves on 8xH200 with the cookbook H200 Low-Latency recipe, which fails at startup on main.
