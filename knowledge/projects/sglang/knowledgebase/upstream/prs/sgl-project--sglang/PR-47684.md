## Motivation

The DeepSeek-V4.1 dense prefill indexer (`dense_prefill_topk`) tiles the `[rows, keys]` logits of a chunk by query rows under a memory budget, and DeepGEMM strides each tile's row blocks (`128 // heads` rows) over one CTA per SM. At long context the budget gives tiles that end in a mostly empty wave, e.g. 1308-row tiles at 400K compressed keys are 2.2 waves on 148 SMs, so every tile pays for 3.

## Changes

`flat_index_logits_rows_per_tile`: on CUDA, a tile of more than one wave is rounded down to a whole number of waves (`128 // heads * num_SMs` rows). Tiles only shrink, so the logits stay within the budget; tiling is by rows, so the results are unchanged.

## Validation (B300, `dense_prefill_topk` as V4.1 calls it: 32 heads, top-k 512, DeepGEMM 0.2.3.post2 + DeepSelect)
