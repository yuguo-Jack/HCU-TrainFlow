# [Fix] mimo-v2: Defer fused-qkv FP8 scale_inv in MTP loader

[Upstream PR](https://github.com/sgl-project/sglang/pull/46350) · state: open · merged: False

## Original PR description

## Summary

`MiMoV2ForCausalLM.load_weights` defers fused-qkv FP8 `scale_inv` when the attention TP differs from the checkpoint's interleave TP, then resolves it after loading. `MiMoV2MTP.load_weights` calls the same `load_mimo_v2_qkv_proj_weight` without `deferred_scale_inv`, so in that case loading the MTP layers raises the "block quantization ceiling" error. This PR mirrors the main model:

```diff
 MiMoV2MTP.load_weights
+  deferred_qkv_scale_inv = {}
   load_mimo_v2_qkv_proj_weight(...,
+    deferred_scale_inv=deferred_qkv_scale_inv,
   ...
+  if deferred_qkv_scale_inv:
+    _resolve_deferred_qkv_scale_inv(params_dict, deferred_qkv_scale_inv, expected_tp, config=..., model=self)
```

## Evidence

- **Before:** MiMo-V2.6-Flash with EAGLE MTP fails while loading the draft model's qkv `scale_inv`, the same error the main model avoids by deferring it.
- **After:** the draft model loads, and the server has run MTP in production with the fix applied as a patch.

## Merge Danger

**Door:** two-way

**Blast Radius:** MiMo-MTP-only

The change only affects MiMo-V2 MTP loading, and only when the qkv loader needs to defer the scale. When it doesn't, the dict stays empty and nothing else runs.
