# [Doc] skills: Update the CI skills for the tier layout and current pipeline

[Upstream PR](https://github.com/sgl-project/sglang/pull/47723) · state: closed · merged: True

## Original PR description

- `ci-workflow-guide`: rewrite the stale parts against the current workflows: the four tiers and their workflows, the stage matrix through `_pr-test-stage.yml`, partitioning by `compute_partitions.py` (live estimates, shard count from each row's `run_timeout`), wait-job counts read from the partitions, adding a runner to a tier as one matrix row, and the twice-daily schedule. Drop the hand-kept partition table, the per-job setup recipe, and the slash command table, which the contribution guide already holds.
- `write-sglang-test`: add "Choosing a Tier" with the base / extra / nightly / weekly policy that #47619 applied; fix the `kernels/` directory name.
- `ci-test-audit`: add "Auditing at scale" (inventory first, cheap-model fan-out over exact items, a default-delete brief, re-judging every verdict, re-tiering before deleting, failure evidence from failed runs); add the model-age signal to B2 and the per-file import cost to F3, with #47592, #47603, and #47619 as examples.
- `rerun-test`: note that `/rerun-test` runs each file directly, so a change to the CI runner itself is validated by the PR's own PR Test run.
- `test/README.md`: point the "too slow for per-commit" advice at the tier policy, and drop `nightly=True` from the CUDA registration parameters.

No behavior change: skills and docs only.
