# [Feat] diffusion: Support FastH3 Omni (Ref2VA 8-step PDD)

[Upstream PR](https://github.com/sgl-project/sglang/pull/45530) · state: closed · merged: True

## Original PR description

## Motivation

Serve [FastVideo/FastVideo-FastH3-Omni-8-Step-V1](https://huggingface.co/FastVideo/FastVideo-FastH3-Omni-8-Step-V1), the Ref2VA Parallel Decoding Distillation (PDD) student of MiniMax-H3, the same way FastH3 V2 and VDN-H3 are served: a model overlay adapts the checkpoint offline, and the runtime reuses the native MiniMax-H3 pipeline, the existing PDD head loading, and VSA-H3.

The release ships only `transformer_ref/` (the FastH3 V2 Diffusers export with 32 interval output heads) and `fastvideo_inference.json`; the conditioner and VAEs are the base MiniMax-H3 Ref2VA ones, pinned by that contract.

## FastH3 vs. FastH3 Omni

| | FastH3 8-Step V2 | FastH3 Omni 8-Step V1 |
|---|---|---|
| Model ID | `FastVideo/FastVideo-FastH3-8-Step-V2` | `FastVideo/FastVideo-FastH3-Omni-8-Step-V1` |
| Task | t2va | ref2va (ordered image / video / audio references) |
| Distillation | DMD2, 8 trained rungs (999 → 125) | PDD: 32 intervals, 8 blocks of 4, one backbone forward per block |
| DiT forwards | 8 | 8 |
| Sigma shift (video / audio) | 10 / 3 | 12 / 3, grid scaled by `grid_max_t = 0.999` |
| Output head | standard | 32 interval heads, fused offline into 8 per-step heads |
| VSA-H3 tile | 64 tokens (4, 4, 4) | 128 tokens (4, 4, 8), run as two 64-token kernel blocks |
| VSA sparsity | 0.8 on the generated video | 0.9 on the generated video; each reference video keeps 10% of its tiles |
| References | – | clean (cond noise aug 1.0), target-only flow |
| Shipped components | transformer, VAEs, text encoder | transformer only; text encoder and VAEs come from `MiniMaxAI/MiniMax-H3@9bfb669` (Ref2VA) |
| Runtime model-specific code | config + sampling params | config + sampling params (DiT unchanged) |

## Modifications

FastH3 Omni is served through the existing MiniMax-H3 paths. Like FastH3 V2 and VDN-H3, the checkpoint is adapted offline by a model overlay, so the DiT has no Omni-specific code.

- **Overlay**: maps `transformer_ref` to `transformer`, fuses the 32 PDD heads into 8 (with the existing `fuse_minimax_h3_pdd_heads` math), and links the Ref2VA conditioner and VAEs at the pinned base revision.
- **PDD**: the model index can name fused heads (`_minimax_h3.pdd_fused_heads`), which are loaded through the existing `load_pdd_fused_heads`. `pdd_config.json` gains `sigma_max`, which scales the PDD grid.
- **VSA-H3**: adds ref2va support. Each reference video is tiled as its own region with per-region top-k (FastVideo `p2_multi_region`). Also supports 128-token logical tiles. The t2va/fl2va path is unchanged.
- **Config**: adds `FastH3OmniPipelineConfig` / `FastH3OmniSamplingParams` and the registry entry.


`sglang generate --model-path FastVideo/FastVideo-FastH3-Omni-8-Step-V1` with no overlay override downloads the overlay, materializes it on first launch (3 s on this host with the source weights cached) and generates; the materialized PDD heads, configs, index and re-written shard are byte-identical to the local overlay the results below were measured with.

## Accuracy Tests

2× H200, Ulysses 2, seed 0, 124 frames at 24 FPS with 32 kHz stereo audio.

- Ref2VA single-image (480p) and video-with-audio (480p) requests produce decodable MP4s with 24 FPS video and 32 kHz stereo audio streams; same-config reruns are bit-identical.
- The fused heads match a direct fp32 fusion of the release heads to 2.4e-7 (fp32 rounding); the VSA-H3 region path matches a standalone pure-PyTorch implementation of the same policy on the real 480p geometry to one bf16 ulp.
- This 8-step student is very sensitive to rounding-level differences: the same reference implementation run on 1 vs 2 GPUs differs at SSIM 0.74. Outputs are therefore compared by eye rather than per pixel; FastVideo (seed 0) gives a different but equally valid sample of the same subject and scene, consistent with framework-specific initial noise.

## Speed Tests and Profiling

**Setup.** 2× H200 on one host, BF16 student weights, the same five requests (prompt, references, seed 0, 8 steps), 124 frames at 24 FPS with 32 kHz stereo audio. Each case runs one full warmup request, then three measured requests; latency stops when the MP4 is saved.

| | SGLang (this PR) | FastVideo (`cdda1b75`, official BF16 multi-GPU config) |
| --- | --- | --- |
| Parallelism | Ulysses 2, TP 1 | SP 2, FSDP DiT |
| Offload | DiT, text encoder, VAE to CPU (pinned) | text encoder, VAE to CPU (unpinned) |
| VSA | VSA-H3, Triton 64-token blocks | `FASTVIDEO_VSA_TRITON=1` (64-token halves) |
| Timer | HTTP submit → job completed (50 ms poll) | in-process `generate()` |
| Startup | 40.0 s to `/health` | 118.8 s generator load |

**Stage breakdown, 480p image, warm** (SGLang stage timers; FastVideo with `FASTVIDEO_STAGE_LOGGING=1`, two warm runs):

| Stage | SGLang | FastVideo |
| --- | --- | --- |
| Text + reference conditioning | 0.66 s + 1.78 s | 15.77 / 11.37 s |
| Latent preparation | 0.01 s | 2.96 / 4.42 s |
| Denoising, 8 PDD steps | 21.85 s (2.73 s/step) | 27.82 / 29.97 s |
| Video + audio decode | 1.77 s | 4.95 + 0.18 s |
| Total | 26.67 s | 51.99 / 52.10 s |

Most of the gap is outside the DiT: per-request movement of the offloaded 63 GB text encoder and 9.8 GB video VAE (host-to-device on this host: 55.5 GB/s pinned vs 22.3 GB/s pageable), and the H3 VAE fast path. Denoising is about 25% faster with a full DiT replica per GPU and the pipelined Ulysses exchange versus FSDP weight gathers. These are deployment-recipe comparisons, not isolated kernel measurements.

**FastH3 V2 regression.** The VSA-H3 refactor keeps the 64-token single-region path that FastH3 V2 uses. On 2× H200 (Ulysses 2, VSA-H3 auto-selected), `FastVideo/FastVideo-FastH3-8-Step-V2` t2va (seed 0) produces byte-identical MP4s (same sha256) on this branch and on its base `844d2b5`, at 480p and at 768p.
