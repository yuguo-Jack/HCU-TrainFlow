# [Perf] [AMD] dsa: Row-split the DCP indexer, run owned sparse MLA on the aiter asm kernel, and pipeline the a2a

[Upstream PR](https://github.com/sgl-project/sglang/pull/47309) · state: open · merged: False

## Original PR description

## Motivation

Stacked on the Q replication PR #47180  (Q replication + project-before-merge), which is stacked on [#44322](https://github.com/sgl-project/sglang/pull/44322). With the query all-gather gone, the owned DSA DCP route spends its time in three places this PR goes after:

With the query all-gather gone, nothing on the owned DCP route couples one row to another until the merge. This PR spends that, making the row the unit of 
 - **who** computes it: each rank scores 1/W of the decode indexer rows
 - **what** computes it: owned slots packed per row into CSR for aiter's FP8 MLA asm kernel, [ROCm/aiter#6132](https://github.com/ROCm/aiter/pull/6132)
 - **when** its partial is exchanged : prefill runs in row chunks, each chunk's a2a behind the next chunk's attention.

## Correctness

The a2a payload stays bf16 and no new quantization is added: the asm kernel reads the same FP8 query and FP8 KV the Triton kernel reads.

MI355X, `amd/GLM-5.2-MXFP4`, TP4/EP4 + DCP4, FP8 KV, MTP (EAGLE, 5 steps, 6 draft tokens), real draft acceptance. All columns were measured on the same day with the same scripts.

Kernel tests (`test_dcp_owned_asm_hip.py`):
- The asm kernel is as close to an fp32 reference as the Triton kernel on the same FP8 inputs (both about 2% relative error, which comes from FP8 rounding inside both kernels), with matching base-2 LSE. Rows that own no slot come out zero, and CSR row slices reproduce the whole-batch result bit for bit.
- `build_dcp_csr` packs exactly the owned slots.
- A row slice of the packed top-k with `row_to_batch` selects the same keys as the whole batch.
- The row-chunked a2a pipeline equals one `dcp_a2a_lse_reduce` bit for bit, timed or not.
- The planner's split is no slower in its model than one chunk more or fewer, grows with the rows, and grows when the host cost per chunk drops. The planner measures on the first larger extend, plans once the measurement is settled, and does not retry a measurement that failed.

## Modifications

1. **Split the decode indexer rows across the DCP group** (`dsa_indexer.py`, `dsa_dcp.py`) 6724cd9f851b28fc57b092b6c14bd992faed2dc2
    - Every rank used to score every decode row. Now each rank scores 1/W of the rows, then the top-k is all-gathered.
    - The top-k is gathered as float32, so it takes the custom all-gather instead of NCCL (about 25 → 8 µs per layer).
2. **Run the owned sparse MLA on the aiter FP8 asm kernel** (`asm_sparse_mla_dcp.py`, `dsa_backend.py`, `dsa_dcp.py`, `forward_mla_rocm.py`) 9be9f5d62ce02828fea6aa38f445eb08fbcb8c19
    - The FP8 query is built in one fused step, and the owned KV slots are packed into a CSR once per top-k.
    - Used with FP8 KV, 64 heads, up to 32K rows, and an aiter that has the kernel ([ROCm/aiter#6132](https://github.com/ROCm/aiter/pull/6132), already in the pinned aiter). Otherwise the Triton kernel runs as before.
3. **Pipeline the prefill a2a with the owned attention** (`comm.py`, `dsa_backend.py`, `dsa_dcp.py`, `forward_mla_rocm.py`, `dcp_kernels.py`) f6088a69bd53ec455ef68c0d83f8fbe2a0c64b56
    - Extend batches are attended in row chunks. Each chunk's a2a runs on a side stream while the next chunk is attended.
    - The chunk count is not hard-coded. `DcpA2aChunkPlanner` times the first large extend once, then picks the fastest split, the same on every rank: 1 chunk below about 2K rows, 4 at 6K, 11 at 32K.

Scope: nothing changes without `--dcp-size > 1`. Only the HIP + DSA `triton` path is touched; CUDA is not. No new environment variables or server arguments.
