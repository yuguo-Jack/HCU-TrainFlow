# [Fix] disaggregation: Validate Decode bootstrap endpoints

[Upstream PR](https://github.com/sgl-project/sglang/pull/45619) · state: open · merged: False

## Original PR description

## Motivation

Fixes #45008. Decode workers currently request Prefill route metadata from the client-supplied bootstrap address. This allows SSRF and can block shared request processing.

## Modifications

- Add an opt-in Decode-side allowlist for all Prefill bootstrap endpoints used by the router. By default the allowlist is empty and validation remains disabled for compatibility; production deployments should set it.
- When configured, reject malformed or unregistered request addresses before HTTP and abort those requests with `400`.
- Normalize hostnames consistently for validation and downstream lookups.
- Bound Prefill metadata response reads with connect/read timeouts, a total body deadline, and a 64 KiB response cap; keep retry count and cache growth bounded.
- Log a one-time warning recommending the allowlist when it is unset.
- Document the opt-in default and production recommendation.
- Add CPU unit coverage for both allowlist modes, normalization, retries, and timeout behavior.

### Design choice

Decode has no reliable existing Prefill endpoint registry to seed from: `dist_init_addr` identifies the Decode process group, the bootstrap-port argument supplies no host, and the Prefill bootstrap registry is reached only after connecting to the request-provided address. The gateway selects a Prefill endpoint per request but does not register that set with Decode. Inferring an allowlist from those values would either trust client input or permit unrelated addresses. An explicit list is the smallest safe way to restrict lookups and supports multi-Prefill routers by listing each eligible endpoint.
