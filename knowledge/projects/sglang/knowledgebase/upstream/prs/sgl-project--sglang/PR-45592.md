# [Fix] disagg: Do not gate PD decode radix prefix match on tree SWA

[Upstream PR](https://github.com/sgl-project/sglang/pull/45592) · state: open · merged: False

## Original PR description

Stacked on #45556 (admit the DeepSeek-V4 paged KV layout in the PD decode radix cache). Review only the top two commits.

## Motivation

On a PD decode server with `--disaggregation-decode-enable-radix-cache`, decode matches the prompt against its tree but never reuses tree SWA. It caps the match at `fill - swa_tail_len`, releases the SWA lock, and allocates a fresh SWA tail that prefill always transfers. Paged SWA still gates that match, though. A boundary counts only if a full window of live tree SWA sits before it. Decode evicts SWA behind its window while decoding, so a match capped in the middle of a node finds no live window and falls back to 0.

DeepSeek-V4.1 example (page 256):
- A finished turn leaves a `[0, 3840)` node. A follow-up whose cap lands on 3840 hits 3840, but only because the page `[3584, 3840)` was allocated for the SWA tail and holds live (never written) rows.
- A follow-up 18 tokens shorter caps at 3584 and gets no decode-local hit at all.

## Modifications

- `swa_gates_tree_prefix_match` (`kv_cache_builder.py`) now also turns SWA gating off on a PD decode that re-transfers its SWA tail. It joins the per-request ring and the encoder-replay request window, which already turn it off for the same reason: the tree does not own that SWA.
- `uses_swa_tail_prealloc` is the decode queue's existing predicate, moved next to it so both read one definition. Page-size-1 SWA decode, which does not re-transfer the tail, still gates.

## Tests

- `test_swa_gates_tree_prefix_match.py`: decode with SWA tail prealloc (SWA and DeepSeek-V4 pools) does not gate; prefill, colocated, page size 1 and pools without tail prealloc still gate. The decode case fails with the change reverted.
- Existing decode unit suites pass: `test_decode_queue_cleanup`, `test_decode_radix_lock_ref`, `test_decode_radix_cache_validation`, `test_prefill_complete_integration`, `test_hisparse_allocator`.
- `test_disaggregation_decode_radix_cache_swa` (gpt-oss-20b, decode radix, run over Mooncake locally): passes before and after.

  | | before | after |
  |---|---|---|
  | gsm8k first / second pass | 0.884 / 0.878 | 0.89 / 0.874 |
  | multi-turn hit rate | 0.5385 | 0.5385 |

- New e2e `test_disaggregation_decode_radix_cache_dsv41.py` (DeepSeek-V4.1-Flash 1P1D, DEP2 each, DSpark, decode radix cache): three 3K-token lookup tables, nine lookups each, prefill flushed before every lookup so `cached_tokens` is decode-local. Every follow-up lookup must hit at least the page-aligned table minus two pages, and at least 90% of lookups must be answered correctly. It fails with this fix reverted (0 < 2304).

  | | before | after |
  |---|---|---|
  | decode-local hit, 3K-token table | 0 | 2560 / 2560 / 2816 |

  With the fix, all 27 lookups were correct in each of four runs.
