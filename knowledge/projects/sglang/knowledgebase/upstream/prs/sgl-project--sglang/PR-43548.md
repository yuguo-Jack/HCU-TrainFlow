# [PD][HiCache] Promise prefill only the L3 span the decode prefetch takes

[Upstream PR](https://github.com/sgl-project/sglang/pull/43548) · state: open · merged: False

## Original PR description

## Motivation

Fixes the request failures reported in #30322 (`HiCache load_back failed ... expected decode_prefix_len=64 (l1=0, l2=0, l3=64)`), which the stale #32278 tried to address by deferring the metadata send.

With a decode-side radix cache and an L3 backend, decode promises prefill a prefix that includes the L3 hit (`decode_prefix_len`) before the L3 prefetch is accepted:

1. `_build_decode_prefix_match` queries L3 with the whole suffix. `query_storage_hit_length` only requires the *suffix* to reach `prefetch_threshold` (default 256), so the returned hit can be any page multiple below it.
2. `_pre_alloc` and `_send_kv_metadata` commit `L1 + L2 + L3` to prefill, so prefill skips those tokens.
3. `_start_hicache_prefetch` then prefetches only the hit span. `prefetch_from_storage` declines spans shorter than `prefetch_threshold` (and rate-limited ones) without registering anything.
4. `check_prefetch_progress` returns True for the unregistered request, load-back covers only L1 + L2, the restore is marked `FAILED`, and the request is aborted with a 500.

So every request whose L3 hit is shorter than `prefetch_threshold` (e.g. one shared 128-token system prompt at page size 64) fails deterministically.

## Modifications

- `_start_hicache_prefetch` now uses the prefill scheduler's span shape: the whole suffix, `matched_prefix_tokens` and `storage_hit_end`. The prefetch reuses the queried hit (no second L3 query) and carries the bigram boundary token, as `Scheduler._prefetch_kvcache` does.
- If the prefetch is neither registered nor ticketed, the L3 span is cleared.
- `_start_hicache_prefetch` runs before `_pre_alloc`, and `total_prefix_len` is re-read afterwards, so `decode_prefix_len`, `cache_protected_len` and the restore reservation only cover what will actually load.

An L3 span that is accepted but later completes short (e.g. the object is evicted between query and read) still fails the restore. That is a narrower race than the deterministic failure fixed here.

## Tests

`test_decode_promises_only_the_prefetched_l3_span` (`test_unified_radix_cache_unittest.py`) drives the real `_build_decode_prefix_match` and `_start_hicache_prefetch` against a real `UnifiedRadixCache` and file L3 backend (`prefetch_threshold=16`):

- an 8-token L3 hit is queried (8) but no longer promised (`decode_prefix_len == 0`);
- a 24-token hit is promised, prefetched, and lands as a 24-token host hit.

On `main` the test fails with `8 != 0`. With this change it passes, along with `test/registered/unit/disaggregation` (686 passed), `test_storage_prefetch_lifecycle.py`, and the L3 / prefetch / decode subset of `test_unified_radix_cache_unittest.py` (135 passed). `test_decode_hicache_tree_core.py` is updated for the new call shape.
