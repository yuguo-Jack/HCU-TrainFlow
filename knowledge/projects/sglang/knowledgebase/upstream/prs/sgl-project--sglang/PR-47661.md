# [Fix] openai: honor LoRA adapters in /v1/responses

[Upstream PR](https://github.com/sgl-project/sglang/pull/47661) · state: open · merged: False

## Original PR description

## Motivation

`/v1/responses` accepts a LoRA adapter in the `model` parameter (for example `model="base:adapter1"`), and `_validate_model` even documents that adapters may be addressed by name or through the `base:adapter` form. However, the request is forwarded to the engine without `lora_path`, so the base model serves the request and the client gets a normal HTTP 200 response. The adapter is silently ignored.

Chat and Completions already resolve the adapter with `_resolve_lora_path` and pass it to `GenerateReqInput`. Responses does not.

## Root cause

`create_responses` validates `request.model` but never resolves or forwards `lora_path`:

`python/sglang/srt/entrypoints/openai/serving_responses.py:349`

```python
model_error = self._validate_model(request.model)
if model_error is not None:
    return model_error
```

The initial `GenerateReqInput` is built without `lora_path`, and the request rebuilt after a built-in tool call also omits it.

## Modifications

- Resolve the adapter once in `create_responses` with the same `_resolve_lora_path(request.model, None)` helper used by Chat/Completions.
- Pass `lora_path` to the initial `GenerateReqInput`.
- Preserve `adapted_request.lora_path` when rebuilding the request after a built-in tool call.
- Add regression tests for the initial request and the tool-call continuation.

## Validation

- `python -m pytest test/registered/unit/entrypoints/openai/test_serving_responses.py -k "lora_adapter or standalone_builtin_tools" -q` -> 2 passed.
- `python -m pytest test/registered/unit/entrypoints/openai/test_serving_responses.py::EnginePassthroughTestCase -q` -> 6 passed.
