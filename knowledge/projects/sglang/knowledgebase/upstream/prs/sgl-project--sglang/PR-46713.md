# Fix DeepSeek-V4.1 DSpark decoder-tail run_idle row count mismatch

[Upstream PR](https://github.com/sgl-project/sglang/pull/46713) · state: open · merged: False

## Original PR description

## Summary
- Fixes #46666 where DeepSeek-V4.1-Flash with DSpark, DP attention, and `SGLANG_ENABLE_DP_SPEC_PREFILL_COORDINATION=1` crashes with "next_token_logits row count mismatch"
- The bug occurs when a DP rank verifying under DP spec-prefill coordination is incorrectly treated as idle and sent to `run_idle`
- The fix skips tail graphs on coordinated steps by checking `dp_spec_prefill_coordination_applied` in the `DecoderReplayTail.plan` method

## Root Cause
When DP spec prefill coordination is enabled, a coordinated step sets `is_extend_in_batch = True` on every rank, including the rank running TARGET_VERIFY. The `DecoderReplayTail.plan` method then plans a tail graph for that rank. Since a TARGET_VERIFY forward has no tail, it reports 0 tail rows and the bucket becomes the prefilling peer's size (128 rows).

The model then sends this rank (with `use_tail_graph=True` and `tail=None`) to `run_idle`, which replays the bucket with zero live rows and asks for `out_rows` = the verify's row count. When the verify rank has more rows than the bucket size (e.g., 132 or 192 rows vs 128), the row count check fails.

## Fix
Modified `python/sglang/srt/models/deepseek_v4_replay_tail.py` to check `forward_batch.dp_spec_prefill_coordination_applied` in the `plan` method and skip using tail graphs when this flag is set:

```python
if (
    tail_in_graph
    or get_is_capture_mode()
    or is_unified_kv_triton()
    or get_global_expert_distribution_recorder().recording
    or not self.runner.warm
    or (tail is not None and tail.cp_metadata is not None)
    or not self._can_capture_moe_bound(forward_batch)
    or forward_batch.dp_spec_prefill_coordination_applied  # NEW
):
    return False, None
```

This keeps the verify rank out of `run_idle` on coordinated steps, preventing the row count mismatch.
