# [NPU] Ascend TP MoE optimizations

[Upstream PR](https://github.com/sgl-project/sglang/pull/44525) · state: open · merged: False

## Original PR description

## Motivation

Improve native Ascend TP MoE execution across integer and MXFP formats while preserving per-projection precision and shared-expert semantics. Compatible optimizations are selected automatically, without the previous `SGLANG_NPU_TP_MOE_*` experiment flags.

Offline router quantization follows the checkpoint. Online weight conversion is optional through `--online-quantization`; it changes model numerics and requires accuracy validation.

Scope is native TP/EP1. HCCL sizing (#44483) and DeepEP work (#26408) remain separate. Component ownership follows #25663: quant methods select computation, the runner executes W13/activation/W2, and the dispatcher owns routing and finalization.

## Modifications

- Resolve ModelSlim expert/shared schemes through canonical aliases, including integer W4A4/W4A8, MXFP8 and MXFP4. W13 and W2 resolve independently, including mixed floating-point groups.
- Reuse existing shared-expert slots and checkpoint remapping in DeepSeek, GLM and supported Qwen entry points. Validate shared weights and all side tensors before preparation; preserve MoE-TP-local W4A8 compensation, Qwen sigmoid weights, routed scaling and shared addition exactly once.
- Carry immutable typed operands with explicit arithmetic, packing, scales, logical shape, source dtype and stream readiness. Reuse compatible INT8/MXFP8 input across routed and separate shared consumers.
- Select packed routing modes 9/13 only after installed-runtime payload/scale checks match the existing quantizer. MXFP4 passthrough requires a separate probe; INT4 passthrough stays disabled.
- Reuse eligible shared GMM1, activation/quant, TP dual-stream and finalizer `skip1` paths. Guard fused W13 by both projection contracts, activation/clamp/bias semantics and installed device/CANN support. Preserve GELU and distinct integer clamp behavior.
- Unify single-level dense/MoE MXFP4 activation conversion with explicit `rint`, block32/E8M0 and `scale_alg=0`. Weight rounding and the online dual-level format remain unchanged.
- Load offline-quantized GLM/DeepSeek routers through existing ModelSlim linear schemes and resolve Qwen gate descriptors per layer. Preserve correction-bias precision and shared sigmoid gates.
- Add capability-selected fused add/RMSNorm/quant FFN boundaries for compatible GLM/DeepSeek consumers, GLM QKV and both families' dense FFNs. Preserve residual outputs, effective Gemma gamma and source dtype. Floating routers, incompatible consumers/topologies and Qwen3.5 GDN dual consumers retain the existing norm path.
- Add scoped load-time online conversion for floating router, shared, QKV and dense projections: MXFP8 or dynamic INT8; MoE conversion uses the existing MXFP8 method. Offline-quantized weights retain their checkpoint method. Role-specific MoE/shared conversion keeps shared experts separate.

Example: `--online-quantization gate:w8a8_mxfp8`. Targets are `gate`, `moe`, `shared_expert`, `qkv`, `dense` and `all`; explicit targets override `all`. MXFP8 routers request FP32 logits. INT8 routers produce BF16 matmul output followed by an FP32 cast, which is not FP32 accumulation.

Unsupported requested online INT4/FP4 conversions fail at startup. Existing multi-op paths remain the fallback for unsupported fusion. A custom dual-output norm, additional full integer/FP4 fused W13, split shared scheduling and new GMM2+finalize are not enabled. Unsupported ModelSlim dense integer W4A8 shared projections fail explicitly.

## Accuracy Tests

Host validation at `b9bb06c925`: **154 tests and 86 subtests passed** across the focused TP, routing, shared-weight, model-gate, fused norm/quant and stage-boundary suites.

Coverage includes integer packing, TP1/2/4/8/16 compensation, mixed schemes and shared metadata loading, operand/scale rejection, routing probabilities, activation/clamp semantics, MXFP4 rounding ties, fused norm ABI and residual handling, per-layer offline gate selection, online flag parsing and shared fallback.

Pre-commit, Python syntax/diff checks and model import smoke passed. The host uses CPU PyTorch without torch_npu or sgl-kernel-npu; operator boundaries are mocked.

**A5 model/router accuracy, physical layouts, stream scheduling and eager/decode NPUGraph validation remain pending.** Host results do not establish target correctness.

## Speed Tests and Profiling

A5 measurements are pending; no speedup is claimed. Compare identical checkpoints/settings at TP4/TP8 using at least three fresh-server A/B/A blocks, changing one optimization per comparison. Record median/p95 TTFT, decode latency, peak HBM and selected kernels, with accuracy checks.

Local development artifacts provide routing/norm capability probes and benchmark-only ablations. They are not production configuration flags or published target results.
