# [Fix] diffusion: LoRA rank-0 download hang, QKV LoRA slicing, IPC sync state

[Upstream PR](https://github.com/sgl-project/sglang/pull/46129) · state: open · merged: False

## Original PR description

## Motivation

Three independent LoRA bugs in `multimodal_gen`, one commit each.

1. **A failed rank-0 LoRA download hangs the other ranks.** `load_lora_adapter` downloads on rank 0 only, then calls `dist.barrier()`. If the download raises (typo'd repo id, 404, network error), rank 0 never reaches the barrier and the other ranks wait until the collective timeout, which takes the worker down on one bad `/set_lora`.
2. **`QKVParallelLinearWithLoRA` crashes on every forward.** `slice_lora_b_weights` did `B_q, B_kv = B` and read `q_proj_shard_size` / `kv_proj_shard_size`, which `QKVParallelLinear` does not have. The loader gives a 2D or 3D tensor, so any LoRA on a `QKVParallelLinear` (HunyuanImage3 `qkv_proj`) raised `ValueError: too many values to unpack`, also at TP=1.
3. **IPC LoRA weight sync leaves the pipeline state stale.** `_update_lora_from_tensor` calls `layer.set_lora_weights` directly, so `is_lora_merged` and `cur_adapter_*` keep the previous state. After a merged sync, `unmerge_lora_weights` skips the module and leaves the synced delta in the base weights. A later `set_lora` with the previously active adapter is treated as already applied and skipped.

## Modifications

1. Rank 0 catches the download error and the barrier becomes a `broadcast_object_list` of the result, so every rank raises.
2. `QKVParallelLinearWithLoRA` now extends `MergedColumnParallelLinearWithLoRA` (reusing its stacked 3D path) and overrides the fused 2D slicing: split B into q/k/v by total heads, shard q by TP rank, and shard k/v by `tp_rank // num_kv_head_replicas`.
3. After a successful sync, set `is_lora_merged` for the target module and clear its `cur_adapter_*` entries.

## Testing

Tests added to existing files only (`test_lora_pipeline.py`, `test_fused_lora_compose.py`):
- 2-rank gloo test: rank 0's download raises, rank 1 must raise the broadcast error without downloading. On main rank 1 times out in the barrier.
- QKV forward with a fused GQA B at TP 1 and 2 (replicated kv head). On main: `too many values to unpack`.
- set_lora, IPC sync, set_lora, unmerge: weights must match the adapter, then the base. On main the stale synced delta remains.

Modal CPU, torch 2.14.1: both files `36 passed`. Each new test fails on main. No GPU run.
