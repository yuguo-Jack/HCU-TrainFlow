# [Fix] kda: Give the prefill-graph fake batch a logical_forward_mode

[Upstream PR](https://github.com/sgl-project/sglang/pull/45285) · state: closed · merged: False

## Original PR description

`HybridLinearAttnBackend._forward_metadata` reads
`forward_batch.logical_forward_mode`, added by #34535. This test builds its ForwardBatch as a `SimpleNamespace` and never gained the field, so the whole file fails with:

    AttributeError: 'types.SimpleNamespace' object has no attribute
    'logical_forward_mode'

That fails `jit-kernel-unit-test-1-gpu-large` on main, and the PR health check treats it as a root cause and skips the rest of the run, so every open PR inherits the failure.

The property returns `_original_forward_mode` only when `prepare_mlp_sync_batch` has relabelled a decode batch as a 1-token extend. Nothing in this test does that, so the logical mode is the forward mode.

`logical_forward_mode` is the only `forward_batch` attribute `_forward_metadata` has started reading since before #34535, so this is all the stub is missing.
