# [Fix] [SM120] dsv4: Stop CUDA graphs from writing into freed FlashMLA page-split buffers

[Upstream PR](https://github.com/sgl-project/sglang/pull/42714) · state: open · merged: False

## Original PR description

## Motivation

On SM120, `_split_kv_pages_to_64` re-pages a 256-token SWA pool into 64-token pages for FlashInfer sparse MLA. Its output buffer and its touched-page mask were one grow-only buffer per device, shared by every caller. A call on a larger pool than the current buffer replaced both. Graphs captured before that keep the old addresses. Once the replaced allocations are released and reused, every replay writes into tensors that now belong to someone else.

Target and draft models with different SWA pool sizes trigger this. I hit it in DeepSeek-V4.1-Flash serving with DSpark and `--enable-encoder-swa-bounded-replay`: the target's graphs were captured on its 42-page request-window workspace, and the draft's 235-page pool replaced both buffers at the first prefill. Target replays then wrote the int8 page mask into a compact-verify length tensor that had taken the freed block, so verify lengths read 16777217 (bytes `01 00 00 01`) or 0, and a zero-token commit raised `IndexError` in `update_spec_correct_drafts_histogram`.

## Modifications

The output buffer and the mask are each keyed by their size (destination pages and source pages) and allocated once. They are never replaced, so captured graphs keep valid addresses. Pools of different sizes get separate buffers. Memory is the sum over distinct pool sizes instead of the largest one. For the 42- and 235-page pools above, the extra retained tensors are a 6,289,920-byte output buffer and a 42-byte mask.

This touches the same allocation as #42440 (zero-initializing the output buffer). The fixes address separate problems; combining them keeps the zero-initialization and updates #42440's tests for size-keyed buffers.

## Accuracy Tests

`test/registered/kernels/ops/attention/test_flash_mla_backends.py`:
- New `TestPageSplitGraphBuffers` (CUDA required, no SM120 gate; the page-split kernels are Triton):
  - captures a graph that splits a 2-page pool, then runs an eager split of a 5-page pool;
  - requires every page-split buffer the capture used to still be registered at the same address;
  - then replays with a different touched page and new contents, and requires the output the eager path returns to hold them. This exercises the captured mask and output.
  - With main's `flash_mla_sm120.py` it fails (`flash_mla_sm120_split:cuda:0 was replaced`); with this change it passes.
- The SM120 `TestTouchedPageSplit` test seeds the size-keyed output buffer and passes.

## Speed Tests and Profiling

Not benchmarked. The same kernels run on the same sizes. The change keeps a separate output buffer, and a separate mask when touched-page masking is used, for each distinct pool size per device.
