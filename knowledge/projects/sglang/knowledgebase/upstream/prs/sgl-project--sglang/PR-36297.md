# [Feat] [NVIDIA] deepseek-v4-flash: Enable CP-v2 interleave for FlashMLA sparse prefill in PD serving

[Upstream PR](https://github.com/sgl-project/sglang/pull/36297) · state: open · merged: False

## Original PR description

## Motivation

DeepSeek-V4-Flash prefill previously could not correctly use context parallelism in a PD-disaggregated deployment.

In addition, `_forward_prefill_sparse` assumed that query rows were contiguous and used the same global coordinates on every rank. Under CP-v2 interleave, each CP rank owns a strided subset of query rows, so the sparse-prefill metadata, SWA ranges, and combined sparse indices must be constructed using rank-local query rows while preserving their original global causal positions.And when using cp for prefilling, the chunk-prefill-size can only be set to 16384. If it is set to 32768, an error will occur.

## Changes

This PR adds context-parallel prefill support for DeepSeek-V4-Flash in PD-disaggregated serving.

It also enables `_forward_prefill_sparse` under CP with the following changes:

- Support CP-v2 interleave on the DeepSeek-V4 prefill worker.
- Build sparse-prefill metadata from each CP rank's local requests and query lengths.
- Preserve the global causal position of every rank-local query row.
- Compute rank-local SWA gather ranges for interleaved query rows.
- Use explicit query positions and SWA start positions when combining compressed Top-K and SWA indices.
- Keep `query_start_loc`, per-request query lengths, query positions, and sparse-cache indices in a consistent CP-rank-local coordinate system.
- Handle requests that have no query rows on a given CP rank.
- Restore physical padded rows after sparse attention so downstream layers retain the expected CP tensor shape.
- Combine the small SWA range metadata into one pinned CPU buffer and transfer it asynchronously.
- Add `flashmla_kvcache` as an explicit DeepSeek-V4 prefill backend option, allowing direct comparison between:
  - `flashmla_kvcache`
  - `flashmla_sparse`
  - `flashmla_sparse_q8`
- Add focused tests for CP-v2 interleave SWA range construction.
- Add a benchmark utility for comparing DeepSeek-V4 prefill backends.
- When using cp for prefilling, the chunk-prefill-size can exceed the 16384 limit.

## Scope
Sparse prefill under CP is currently enabled for:

- CP-v2
- `interleave` CP strategy
- DeepSeek-V4-Flash prefill
- PD-disaggregated serving

Legacy CP and the `zigzag` strategy continue to use the regular FlashMLA KV-cache prefill path.

## Compatibility

The non-CP sparse-prefill path keeps its existing behavior.

When CP sparse prefill is unsupported, the backend falls back to `flash_mla_with_kvcache` as before.

## Testing

- Added unit tests for interleave CP SWA range calculation.
- Added coverage for requests with no local query rows on a CP rank.
- Validated both `flashmla_kvcache` and `flashmla_sparse` paths with CP-v2 enabled in a 1P1D PD-disaggregated deployment.
