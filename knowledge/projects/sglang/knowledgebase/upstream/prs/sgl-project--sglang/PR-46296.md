# [Fix] dllm: Resolve LLaDA2 block size and mask ID from checkpoint metadata

[Upstream PR](https://github.com/sgl-project/sglang/pull/46296) · state: open · merged: False

## Original PR description

## Motivation

LLaDA2 initializes its dLLM block size and mask ID from architecture defaults. Declared checkpoint metadata is not used to select these values. For block-routing checkpoints whose declared block size differs from the default, startup requires a matching manual override.

This PR reads the metadata for LLaDA2 while preserving the existing defaults when it is absent, following the scope discussed in #39499:
https://github.com/sgl-project/sglang/issues/39499#issuecomment-6359947022

Related to #39499. Configuration overlap: #31586 and #44385.

## Modifications

- Read `block_size` from the effective model configuration, including JSON model overrides. Fall back to `32` only when the field is absent. Require a positive integer and reject a conflicting YAML value. YAML may supply the value when the checkpoint omits it.
- Resolve the selected tokenizer source through the existing tokenizer source resolver, preserving a separate tokenizer path. Resolve the declared `mask_token` against the selected serialized vocabulary and forward the configured revision. Preserve the existing mask ID when no mask is declared; reject a declared mask missing from the vocabulary, inconsistent IDs, and IDs outside the model vocabulary.
- Resolve the mask before validating the InDel token IDs. The metadata lookup does not execute a checkpoint's custom tokenizer Python code.
- Add regression coverage for metadata fallbacks, conflicts, versioned tokenizer-file selection, source resolution, and propagation through `ServerArgs` to page-size resolution. Document the supported behavior and limitations.

Other model families retain their existing behavior. Algorithm selection remains explicit because the inspected LLaDA2 checkpoints do not declare a default algorithm. Declared masks require a serialized fast tokenizer; slow-only tokenizers and custom code that changes token IDs are outside this lookup's scope.

## Accuracy Tests

Tested against upstream commit [`535aeae2`](https://github.com/sgl-project/sglang/commit/535aeae2a709077e3d17f5efc48350319ac13fc9) with this patch applied:

- 222 registered regression tests passed across six files, plus four committed-token/cache tests. All 226 selected tests passed without skips.
- Configuration checks passed for checkpoint defaults, YAML conflicts, separate tokenizer paths, and non-default block sizes/mask IDs.
- Versioned tokenizer and source-resolution regression tests passed. Source tests use real tokenizer files with mocked download/cache boundaries and do not access live cloud storage.
- Baseline and patched LLaDA2.2-mini BF16 inference produced identical `output_ids` for two prompts with decode CUDA Graph disabled and enabled. The scripts assert exact token-ID equality, and server logs confirm actual graph use in the enabled runs. Prefill CUDA Graph remained disabled.
- Pre-commit and documentation build/link checks passed.

The inference checks used `inclusionAI/LLaDA2.2-mini` at revision `e4f77d25ab5ca86f2223c6cdc6a72b887e20c8a5`, `JointThresholdInDel`, one GPU, one concurrent request, a 1,024-token context limit, temperature 0, and at most 32 new tokens. These are functional checks, not a full model-accuracy benchmark.
