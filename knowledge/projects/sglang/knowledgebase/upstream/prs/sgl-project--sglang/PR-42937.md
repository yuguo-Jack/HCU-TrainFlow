# [Fix] lora: Honor rsLoRA scaling and load Qwen3.5 PEFT GDN adapters

[Upstream PR](https://github.com/sgl-project/sglang/pull/42937) · state: open · merged: False

## Original PR description

## Motivation

PEFT rsLoRA adapters need `lora_alpha / sqrt(r)`, while ordinary LoRA keeps `lora_alpha / r`. Qwen3.5-family PEFT adapters can also target Gated DeltaNet projections and the dense shared expert; these require compatible projection packing and must not wrap untargeted routed experts.

This extends the original scaling-only PR with the two GDN/shared-expert commits from #44704 by @philip-pentatonic. Both commits retain their original author and `cherry picked from` references. The scaling implementation and CPU regressions from this PR are retained; the donor's duplicate scaling commit is not included. Related scaling proposals: #40836, #40837, #41774.

## Changes

- Honor PEFT `use_rslora`, defaulting to false. Test absent/false/true, ranks 1/8/16/64, local config loading and nonzero dense deltas without altering saved factors.
- Pack PEFT GDN `in_proj_qkv` + `in_proj_z` into `in_proj_qkvz`, and `in_proj_b` + `in_proj_a` into `in_proj_ba`, preserving the A/B products and existing split Q/K/V/Z support.
- When every initial adapter targets dense/shared-expert layers, leave routed experts on the base backend and skip their LoRA buffers. Preserve fused shared-expert buffers independently. Reject a later routed-expert load into a dense-only pool instead of silently ignoring it.
- Starting with no initial adapters retains routed-expert capacity, subject to configured targets/rank limits. Include a routed-expert adapter in initial `--lora-paths` if that capacity is needed after a dense-only startup. The dense shared-expert path uses `--disable-shared-experts-fusion`.
- Resolve the memory-pool conflict against current main using its per-pipeline-stage allocator; add a regression that other stages' layers remain unallocated.
- Document supported formats and startup restrictions; retain the public synthetic-adapter reproducer from #44704.

PEFT `target_parameters` / ParamWrapper routed-expert checkpoint conversion remains separate (#42960). No inference kernels or training defaults are changed.
