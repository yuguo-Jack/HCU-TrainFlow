# [Fix] dp-attention: Align prefill graph buckets and decode padding across DP ranks

[Upstream PR](https://github.com/sgl-project/sglang/pull/46138) · state: closed · merged: True

## Original PR description

## Summary
Two DP-attention padding changes:
- With breakable prefill CUDA graphs, every DP rank pads to the same captured token bucket. An idle rank keeps the padded shape for the collectives; a backend that opts in also skips its attention metadata there.
- Decode picks SUM_LEN padding, one TP all-reduce of the summed rows, when the gather spans several ranks, every rank has tokens, the summed buffer fits the CustomAllReduceV2 buffer, and there is no MoE all-to-all or speculative decoding. Otherwise the existing cost-based choice applies.

## Changes to existing code
- `forward_batch_info`: `global_num_tokens` is rounded up to the smallest captured prefill bucket on every rank.
- `DpPaddingMode`: decode selects SUM_LEN under the condition above, both eagerly and in `get_default_mode_in_cuda_graph`, which now receives the captured per-rank token counts.
- `AttentionBackend.skips_prefill_metadata_on_idle_dp_rank` (default `False`): when a backend sets it, `PrefillCudaGraphRunner` skips `init_forward_metadata` and the read snapshot on a rank with no real tokens. No existing backend sets it, so their replay is unchanged.

The prefill change affects every model that uses DP attention with breakable prefill graphs; the decode padding change affects DP-attention decode without idle ranks.

## Verification
- test_dp_attention, test_dsa_backend_dp_padding (an idle rank still selects MAX_LEN), test_runtime_context, test_prefill_cuda_graph_padding, test_prefill_cuda_graph_runner, test_prefill_cuda_graph_runner_helpers, test_prefill_shared_read_done
- TODO: DP-attention serving on an existing DP model, with breakable prefill graphs and with decode CUDA graphs.
