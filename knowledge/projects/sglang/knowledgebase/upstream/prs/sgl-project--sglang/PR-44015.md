# [Fix] pd: Size decode Mamba spec-state scratch by running batch, not decode extra slots

[Upstream PR](https://github.com/sgl-project/sglang/pull/44015) · state: open · merged: False

## Original PR description

## Motivation

On the PD **decode** side, `HybridMambaDecodeReqToTokenPool` sizes the hybrid
Mamba / linear-attention **speculative** intermediate scratch (`intermediate_ssm`,
`intermediate_conv_window`) by `size + pre_alloc_size`, where
`pre_alloc_size = disaggregation_decode_extra_slots` reserves extra `req_to_token`
slots for in-transfer (being-received-from-prefill) requests.

Those in-transfer slots never need the speculative scratch: it is indexed
**positionally by running-batch slot** (`build_verify_intermediate_state_indices`
is seeded from `req_to_token_pool.size`, which is `size`, not `_alloc_size`), and
in-transfer requests are not in the running batch, so they never enter
`target_verify`. The extra rows are pure waste.

The scratch is `[num_layers, spec_state_size + 1, draft_tokens, ...]` fp32. With
MTP on a 34-layer KDA model (GLM-5.3-Flash, TP8) the default
`disaggregation_decode_extra_slots` (2x the per-worker running batch for small
batches) roughly triples it: `max_running_requests=64`, per-worker `size=8`,
`extra_slots=16`, so `spec_state_size=24` instead of `8`, and
`intermediate_ssm_state_cache` is **20.5 GB** instead of **7.4 GB** per GPU. On
96 GB H20 the decode server then has ~2 GB free after weights + KV + mamba state +
decode CUDA graphs, and the first NCCL `all_to_all` in warmup fails with
`NCCL Error 1: unhandled cuda error`. The only workaround today is to pass
`--disaggregation-decode-extra-slots 8` by hand, which only halves the waste.

## Modifications

`python/sglang/srt/disaggregation/decode.py`,
`HybridMambaDecodeReqToTokenPool.__init__`: size the speculative scratch by `size`
instead of `size + pre_alloc_size`, matching the non-PD path
(`mamba_spec_state_size = max_running_requests`).

```python
mamba_spec_state_size = size
if enable_linear_replayssm_spec:
    mamba_spec_state_size = size + pre_alloc_size
```

The `enable_linear_replayssm_spec` branch keeps the padded size for ReplaySSM-spec: GDN keys its spec ring/cursor buffers (sized from `spec_state_size`) by `req_pool_idx`, which spans `size + pre_alloc_size`; KDA's ring is per mamba slot, so the padding is only conservative there. The other `req_pool_idx`-keyed path, `SGLANG_ENABLE_PP_SPEC` stable rows, is a pipeline-parallel feature that is rejected with `--disaggregation-mode` when `pp_size > 1`. The main (non-spec) Mamba conv/temporal state pool is a separate allocation sized by `effective_mamba_size` and is unchanged, so in-transfer requests keep their state storage. The unified-memory decode pool already sizes the scratch this way: its request table covers `size + pre_alloc_size` rows while it passes `mamba_spec_state_size=max_num_reqs` (`unified_memory_pool.py`).

Adds a CPU unit test
`test/registered/unit/disaggregation/test_decode_mamba_spec_state_size.py`
asserting the sizing by default and under `enable_linear_replayssm_spec`.

## Accuracy Tests

2x8 H20, GLM-5.3-Flash, FP8, TP8/EP8, BF16 KV, DP attention, MTP (EAGLE 5/1/6),
mooncake backend, default `disaggregation_decode_extra_slots`:

| | before | this patch |
|---|---|---|
| decode boots | no (NCCL error in warmup) | yes |
| `intermediate_ssm_state_cache` | 20.5 GB | 7.4 GB |
| free GPU mem after startup | ~2 GB | ~15.8 GB |
| consistency | - | PASS |
| GSM8K (20-shot, 500) | - | 0.938 |
| KV transfer errors | - | 0 |

Non-speculative PD (MTP off) regression check vs unpatched baseline: consistency
PASS, GSM8K 0.930 -> 0.924 (run-to-run noise), 0 transfer errors.

Second backend, GDN (Qwen3.5-9B, linear-attn + 1 MTP layer), PD + MTP, with
`--max-running-requests 32` so `pre_alloc_size=64`
(`spec_state_size` 96 -> 32):

| | before | this patch |
|---|---|---|
| `intermediate_ssm_state_cache` | 2.27 GB | 0.77 GB (97 → 33 rows) |
| consistency | PASS | PASS |
| GSM8K (20-shot, 200) | 0.884 | 0.884 |
| accept length | 3.43 | 3.43 |

A GDN run with `pre_alloc_size == 0` produced a byte-identical scratch size before
and after, confirming the change is a no-op when there are no in-transfer slots.

## Speed Tests and Profiling

No inference-speed impact (allocation sizing only). c16/c64 serving throughput was
unchanged within run-to-run noise in all runs above (e.g. GLM-5.3 PD+MTP c64 ~3.5-3.7k
tok/s; Qwen3.5 c16 ~6.5k tok/s before and after).

## Related work

- #42790 (`[Mamba] Allow skipping per-draft intermediate SSM state`) is orthogonal
  and complementary: it adds an opt-in flag to skip the `intermediate_ssm`
  allocation entirely for backends that do their own rollback, which does not apply
  to KDA/GDN (they read the buffer). This PR corrects the buffer's outer dimension
  for the backends that do allocate it. The two touch the same constructor, so a
  rebase will be needed if #42790 merges first.
- #37276 (`fix(memory): skip speculative Mamba verify budget on PD prefill`) is the
  PD **prefill** counterpart (budget accounting); this is the PD **decode**
  allocation-sizing side, which #37276 notes had no aligned PR.
