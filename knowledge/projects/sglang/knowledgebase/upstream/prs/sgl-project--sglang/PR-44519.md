# [AMD][DI][CI] mi355x launcher: per-cluster RDMA device and socket NIC overrides

[Upstream PR](https://github.com/sgl-project/sglang/pull/44519) · state: closed · merged: False

## Original PR description

## What

Lets the MI355X disaggregation nightly run on a second Spur cluster whose RDMA devices and management NIC are named differently from pit2's. Two optional runner-environment variables are added to `launch_mi355x.sh`; with neither set, the pit2 runners behave exactly as before.

## Why

The nightly runs 34 legs (22 two-node, 12 four-node) on the two pit2 runners. #40113 added the Spur profile; this change lets a second group of MI355X nodes share that load.

Every MI355X recipe hardcodes pit2's device names: `ib_devices: rdma0..3` (or `rdma0..7`), and `dist_socket_ifname: eno0` in the EP16 recipes. On the new nodes the backend ports are `ionic_0..7` and the management NIC is `ens3`.

With those names, the Spur port check drops every recipe port as missing and backfills from any ACTIVE port. That includes the 200G front-end `mlx5_0`, which then carries KV transfer.

## Changes

- `IB_DEVICES_OVERRIDE`: the cluster's backend RDMA devices, in rail order. A recipe keeps its device count and takes the first N names. Recipes always list `rdma0..N-1`, so this matches positionally. When it's set, the port check only backfills from devices on this list.
- `ADDR_NIC_OVERRIDE` already sets the socket fallback NIC on Spur. It now also replaces a recipe's `dist_socket_ifname`, so the EP16 recipes don't pin `eno0`.

Both are per-cluster facts, so they belong in the runner's environment next to `CLUSTER`, `SLURM_*` and `MODEL_ROOT`, rather than in per-cluster copies of each recipe.

## Test plan

- `dsv4flash-fp4-1k1k-1p1d` on two of the new nodes with `IB_DEVICES_OVERRIDE=ionic_0,...,ionic_7` and `ADDR_NIC_OVERRIDE=ens3`. The recipe resolved to `ib=ionic_0,ionic_1,ionic_2,ionic_3`. End-to-end result: **not yet verified, run queued**. Comparison point is the pit2 leg from nightly run [38697010422](https://github.com/sgl-project/sglang/actions/runs/38697010422): GSM8K 0.925 in 21 min.
- pit2 path: both variables unset, so the recipe values are used unchanged.
- Not exercised: the restricted backfill (needs a port down on the new nodes) and an EP16 recipe on the new nodes.
