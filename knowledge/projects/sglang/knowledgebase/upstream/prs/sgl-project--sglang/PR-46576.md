# [Feat] disaggregation: Support DeepSeek-V4.1-Flash CPU-buffer PD

[Upstream PR](https://github.com/sgl-project/sglang/pull/46576) · state: open · merged: False

## Original PR description

## Motivation

This PR adds DeepSeek-V4.1-Flash support to NIXL CPU-buffer prefill–decode (PD) disaggregation in Confidential Computing (CC) deployments. It transfers the model’s compressed KV, indexer pages, sliding-window KV, and per-request compression state.

This PR is stacked on [#46554](https://github.com/sgl-project/sglang/pull/46554) at `4c1b634eec`, which adds Qwen3.8-Flash-Next CPU-buffer PD support and depends on [#45779](https://github.com/sgl-project/sglang/pull/45779). The DeepSeek-specific diff is relative to #46554.

Tracking issue: #46588

## Modifications

- Map registered DeepSeek memory regions to their backing tensors, including regions that start inside a tensor. Exclude trailing indexer padding that does not form a complete transfer page.
- Transfer sliding-window and compression state using each component’s own indices. Handle empty pending-state lists received through the bootstrap protocol.
- Extend KV checksum verification to DeepSeek auxiliary state. For sliding-window KV, hash only the pages transferred after the cached prefix. Add unit tests, real NIXL/UCX CUDA-transfer tests, and a model evaluation script.

MTP, PP/CP, and offload are not covered. Retracted text requests use DeepSeek’s existing prefill recomputation path.

## Accuracy Tests

Model, fault-injection, and performance results below were collected with the source recorded in `4a7632c84e`. The current revision, `e527e69f68` (identical source to the tested `9052db6261`), includes upstream changes through `d19f19d68c`. Full-model evaluations have not been rerun on this revision.

The checkpoint is `deepseek-ai/DeepSeek-V4.1-Flash-1017`, revision `9f9818127f`. Unified uses eight H20 GPUs; cross-node PD uses eight per role on two TDX hosts. Both use TP8/EP8, `moe-a2a-backend=none` (no DeepEP), FlashInfer MXFP4, a 16,384-token context, and 2,048-token prefill chunks. Decode CUDA graphs and overlap scheduling are enabled. Radix caching is enabled for unified/prefill and disabled for PD decode. MTP is disabled.

PD uses NIXL/UCX TCP with `UCX_TLS=tcp,cuda_copy,self`, `UCX_ACC_DEVICES=''`, a 4 GiB CPU pool per worker, and KV/state checksum verification. The runtime uses PyTorch 2.14.1+cu130, FlashInfer 0.7.2, and sgl-deep-gemm 0.2.3.

GSM8K follows the [upstream DeepSeek-V4.1 recipe](https://github.com/sgl-project/sglang/blob/3d508d614f28d2c35da2fdafe422c9bfe454c1b8/python/sglang/test/dsv41_flash_common.py): 200 zero-shot chat questions, 64 client threads, and a 4,096-token output limit. Effective sampling is temperature 0 and top_p 0.95. The 95% acceptance floor comes from that test.

| Test | Unified | Cross-node PD |
| --- | --- | --- |
| GSM8K | 194/200 (97.0%) | 195/200 (97.5%) |
| Request errors | 0 | 0 |
| Responses at output limit | 0 | 1 |
| Compression/window/page/chunk boundary checks | 10/10 | 10/10 |

Both deployments exceed the upstream 95% threshold. The response that reached the output limit remains included in the score. Boundary prompts have 127, 128, 129, 255, 256, 257, 2,047, 2,048, 2,049, and 4,097 tokens.

After a cross-node request was cancelled, four subsequent requests completed successfully and both workers’ running, waiting, bootstrap, and transfer queues emptied. GSM8K and boundary-test logs contained no checksum mismatches or runtime exceptions. Peer crashes and network loss were not tested.

Cross-node fault injection uses `test/manual/disaggregation/cpu_buffer_fault_injection/`, with native DeepSeek chat prompts sent directly to both workers to bypass router retries. All three cases run with KV/state checksums enabled.

| Injected failure | Recovery requests | Resource checks |
| --- | --- | --- |
| Decode receive-buffer allocation | 4/4 correct answers | All 16 rank pools and both worker queues drained |
| Prefill send-buffer allocation | 4/4 correct answers | All 16 rank pools and both worker queues drained |
| Exception after a real NIXL write submission | 4/4 correct answers | Buffers retained until submitted writes completed, then released |

The injected request failed in each case. After the recovery requests, every rank had zero pool allocations, allocated bytes, and pending handles. The fault-injection tool also passed its three offline tests.

Strict logprob parity did not pass on 11 boundary prompts. Repeated unified runs also differed in token IDs and exceeded the framework’s logprob tolerance. The repository’s deterministic-inference mode does not support the `dsv4` backend. GSM8K and KV/state checksums provide accuracy and transfer-integrity checks, respectively; they do not establish strict logprob parity.

At `9052db6261`, all 153 regression tests passed, including buffer lifecycle, cached-prefix checksum, and four real NIXL/UCX CUDA-transfer cases. Repository pre-commit hooks passed. The tested files matched the local source hashes.

## Speed Tests and Profiling

Serving sanity checks use upstream `sglang.bench_serving` with `random-ids`, a nominal 1,024-token input target, 128 output tokens, range ratio 1, seed 42, and unlimited request rate. Each configuration runs serially once, with 16 warmup requests followed by 80 measured requests. The sampler uses text mode, so server-side retokenization can change input lengths. Ignore-EOS is enabled. Cache flushes after warmup are confirmed on both PD workers.

| Deployment | Total H20 GPUs | Concurrency | Output tokens/s | Median TTFT (ms) | Median TPOT (ms) |
| --- | --- | --- | --- | --- | --- |
| Unified | 8 | 1 | 103.93 | 188.66 | 8.11 |
| Unified | 8 | 16 | 385.22 | 2208.57 | 24.37 |
| Cross-node PD | 16 | 1 | 89.10 | 394.00 | 8.12 |
| Cross-node PD | 16 | 16 | 564.45 | 1406.97 | 14.75 |

All 320 measured requests succeeded and generated 128 tokens each. Both deployments use TP8/EP8 per worker, a running-request limit of 32, decode CUDA graphs, and overlap scheduling. Radix caching is enabled for unified/prefill and disabled for PD decode. MTP, checksum verification, and fault instrumentation are disabled for timing.

Each row is a single measurement on shared hosts; run-to-run variance was not measured. PD uses twice as many GPUs as unified, so the throughput difference cannot be attributed to the transport alone. The approximately 475 GiB checkpoint does not fit on four 96 GiB H20 GPUs, and two replicas do not fit on a single eight-GPU host.

```bash
python -m sglang.bench_serving \
  --backend sglang --base-url "$ENDPOINT_URL" \
  --model "$MODEL_PATH" --served-model-name deepseek-v4.1-flash \
  --dataset-name random-ids --random-input-len 1024 --random-output-len 128 \
  --random-range-ratio 1 --seed 42 --num-prompts 80 --warmup-requests 16 \
  --flush-cache --max-concurrency "$CONCURRENCY" --output-file "$RESULT_FILE"
```
