# [Perf] dsv4: Gather V4.1 index-K slots once per prefill graph replay

[Upstream PR](https://github.com/sgl-project/sglang/pull/45741) · state: closed · merged: True

## Original PR description

- Prefill graph replays take the same index-K slot snapshot as eager extend (#45577): `prepare_forward_metadata_for_breakable_cuda_graph_replay` calls `_snapshot_low_ratio_k_slots` after refreshing the full and tail metadata, so the full top-k and low-ratio source breaks read `low_ratio_k_slots` and one `PrefillIndexPlan` per ratio instead of gathering from `req_to_token` and rebuilding the plan in every layer. The snapshot's condition moves into the helper, so both callers make the same one-line call; only the capture pass still gathers per layer.
- The late-layer tail that leaves the prefill graph for its row-bucket graphs builds fresh metadata for the live rows; `_share_low_ratio_k_slots` hands it the same snapshot with its own plan cache, as `_snapshot_low_ratio_k_slots` already does for the tail metadata of an eager extend.
- The replay-context test stubs the snapshot like the other backend collaborators.

No behavior change: the snapshot holds the same slots and plans the per-layer path builds, which assertions confirmed on every layer, tail included, of 639 prefill graph replays of DeepSeek-V4.1-Flash (DEP4 with MegaMoE on GB300, 4,096 and 8,192 tokens per rank). At 4,096 tokens per rank the scheduler thread spends about 3.4 ms less per step (sampled), with the index-K gather down from 4.0 to 0.9 ms.
