# [Fix] mem_cache: Skip linker L3 lookup on PD decode

[Upstream PR](https://github.com/sgl-project/sglang/pull/45538) · state: closed · merged: True

## Original PR description

## Motivation

With `--disaggregation-decode-enable-radix-cache` and `--enable-unified-cache-external-linker` on a PD decode server, `UnifiedRadixCache.match_prefix` calls `linker.match`, which reports an external-store hit as `host_hit_length`. Decode's prealloc folds that length into `decode_prefix_len`, so prefill skips sending those pages. Decode never loads them back: the linker load-back runs only from the extend path's `init_load_back`, and PD decode has no extend batch. The request then decodes over unwritten KV rows, and the hit marker is never released.

## Modifications

- `UnifiedRadixCache.match_prefix` skips `linker.match` when `disaggregation_mode == "decode"`. Decode still offloads through the linker. It just never claims an external hit it cannot restore.

## Tests

- `test_decode_match_skips_linker_lookup` (Python and Rust tree cores): in decode mode, a prefix fully present in the store yields `host_hit_length == 0` and no `lookup` call. Outside decode, the same prefix still hits.
- Negative control: with the gate removed, the test fails on both tree cores.
- `test/registered/unit/mem_cache/test_unified_cache_linker.py`: 66 passed.
