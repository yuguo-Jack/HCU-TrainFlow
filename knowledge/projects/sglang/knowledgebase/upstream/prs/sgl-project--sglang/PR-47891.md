# [Feat] [XPU] graph: add context-aware support for XPU graph

[Upstream PR](https://github.com/sgl-project/sglang/pull/47891) · state: open · merged: False

## Original PR description

## Motivation

This PR introduces context-aware support for XPU Grap on Intel GPUs for both decode and prefill phases.

1. **Decode Context-Aware Variants (Aligned with AMD/ROCm pattern)**:
   - Intel XPU FlashAttention uses a single workgroup (`num_splits=1`) for short contexts (<= 4096 tokens) and multi-workgroup Split-KV (`num_splits > 1`) with reduction kernels for long contexts.
   - Leverages SGLang's generic decode graph runner hook `attn_backend.get_decode_graph_variants()` to capture split-aware graph tiers (`short <= 4096`, `medium <= 16384`, `long <= max_context_len`), allowing short sequences to bypass Split-KV reduction overhead without CPU-GPU synchronization.
   - Bakes context upper bounds into `metadata.max_seq_len_k` during capture and dynamically updates it during replay.

2. **Compact Prefill Graph Allocation**:
   - Declares `supports_prefill_cuda_graph_max_context_size = True` and honors `max_seq_len_override` in `_init_full_cg_prefill_metadata` to avoid over-allocating prefill page tables when `--cuda-graph-prefill-max-context` is specified.

3. **Auxiliary Output Support & Accurate Memory Tracking**:
   - Extends XPU full graph runner output buffers to support nested tuple/list outputs.
   - Uses `torch.xpu.mem_get_info` for driver-level device memory tracking.

```text
Request Routing (Decode Graph Variants):
  seq_lens_cpu <= 4096   --> Variant 'short'  (num_splits=1, single-WG, no reduction)
  seq_lens_cpu <= 16384  --> Variant 'medium' (bounded splits)
  seq_lens_cpu > 16384   --> Variant 'long'   (fallback up to max_context_len)
```

## Modifications

- `python/sglang/srt/layers/attention/xpu_backend.py`:
  - Declared `supports_prefill_cuda_graph_max_context_size = True`.
  - Implemented `get_decode_graph_variants()` returning `SeqLenBucketGraphVariants` aligned with XPU FlashAttention split rules.
  - Baked context upper bound into `metadata.max_seq_len_k` at capture time and updated dynamically during replay.
  - Honored `max_seq_len_override` in `_init_full_cg_prefill_metadata`.
- `python/sglang/srt/hardware_backend/xpu/graph_runner/xpu_full_graph_backend.py`:
  - Handled nested tuple/list output buffers in `_allocate_output_buffer` and `_copy_output_to_buffer`.
- `python/sglang/srt/utils/common.py`:
  - Used `torch.xpu.mem_get_info(gpu_id)` in `get_available_gpu_memory` for accurate device memory querying.
- `test/registered/xpu/test_xpu_graph_metadata.py`:
  - Added unit tests covering prefill context override, decode context baking, and variant generation.
