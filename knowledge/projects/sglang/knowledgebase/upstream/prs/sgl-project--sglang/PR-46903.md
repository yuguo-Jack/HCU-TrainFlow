# [Perf] hicache: Replace O(k * N) list.pop(0) drain loops with slice deletion in HiCache ack queues

[Upstream PR](https://github.com/sgl-project/sglang/pull/46903) · state: open · merged: False

## Original PR description

## Motivation

In `python/sglang/srt/mem_cache/hiradix_cache.py` (`UnifiedRadixCache.writing_check` and `UnifiedRadixCache.loading_check`) and `python/sglang/srt/mem_cache/decode_offload_manager.py` (`DecodeKVCacheOffloadManager._check_offload_progress`), completed asynchronous transfer acknowledgements are drained from `ack_write_queue`, `ack_load_queue`, and `ack_offload_queue` using a `for _ in range(finish_count): ... pop(0)` loop:

```python
for _ in range(finish_count):
    ack_list = self.ack_write_queue.pop(0)
    ...
```

Each `list.pop(0)` shifts all remaining elements in the list by one position ($O(k \times N)$ total element shifts for $k = \text{finish\_count}$). Under high-concurrency multi-turn prefix caching or decode KV offload, draining completed ack batches in one slice (`completed_acks = queue[:finish_count]; del queue[:finish_count]`) shifts the remaining tail only once ($O(N)$) and avoids repeated front-of-list memmoves.

### Acknowledgements
Follows up on the `min_finish_count` PP synchronization drain logic introduced in #21378 by @ishandhanani.

## Modifications

- In `UnifiedRadixCache.writing_check` and `UnifiedRadixCache.loading_check` (`python/sglang/srt/mem_cache/hiradix_cache.py`), slice `self.ack_write_queue[:finish_count]` / `self.ack_load_queue[:finish_count]` and delete the prefix once via `del ...[:finish_count]`.
- In `DecodeKVCacheOffloadManager._check_offload_progress` (`python/sglang/srt/mem_cache/decode_offload_manager.py`), slice `self.ack_offload_queue[:finish_count]` and delete the prefix once via `del self.ack_offload_queue[:finish_count]`.
- Verified with `pytest test/registered/hicache/test_hicache_pp_sync_drain.py` (`6 passed`).
