# [Fix] [NVIDIA] deterministic: enable DeepGEMM BF16 deterministic mode when getter is absent

[Upstream PR](https://github.com/sgl-project/sglang/pull/48237) · state: open · merged: False

## Original PR description

## Motivation

`deep_gemm` 0.2+ and upstream `deep_gemm` 2.8.x default `bf16_gemm_nn` to cuBLASLt, whose split-K reduction varies with batch size `M`. While `sgl-deep-gemm` exposes both `get_deterministic_algorithms()` and `use_deterministic_algorithms(bool)`, upstream `deep_gemm` wheels expose `use_deterministic_algorithms(bool)` without `get_deterministic_algorithms()`.

In `_matmul_persistent_deepgemm`, `deterministic = get_deterministic() if get_deterministic else True` treated a missing getter as already deterministic and skipped calling `deep_gemm.use_deterministic_algorithms(True)`, leaving large-K BF16 linear projections (such as `K = 8192`) on non-batch-invariant cuBLASLt split-K kernels under `--enable-deterministic-inference`.

## Modifications

- Call `deep_gemm.use_deterministic_algorithms(True)` in `_matmul_persistent_deepgemm` whenever `use_deterministic_algorithms` exists and either `get_deterministic_algorithms()` returns `False` or the getter is absent (restoring `False` afterward when invoked outside `batch_invariant_mode`).
- Synchronize `deep_gemm.use_deterministic_algorithms` with `enable_batch_invariant_mode`, `disable_batch_invariant_mode`, and `set_batch_invariant_mode`.
- Add hermetic CPU unit tests in `test/registered/unit/batch_invariant_ops/test_deepgemm_bf16_deterministic_guard.py`.
