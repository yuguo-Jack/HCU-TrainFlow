# [CI] tests: Load NVFP4 test scales through the parameter's weight loader

[Upstream PR](https://github.com/sgl-project/sglang/pull/44631) · state: closed · merged: False

## Original PR description

## Motivation

`jit-kernel-unit-test-4-gpu-b200` fails on every PR that runs it since #44418 merged:

```
FAILED registered/kernels/ops/diffusion/test_nvfp4_scaled_mm.py::test_flux2_swizzled_scale_checkpoint_flashinfer_trtllm_matches_cudnn - AssertionError: assert False
```

#44418 moved the swizzled-to-row-major conversion for swizzled NVFP4 checkpoints into the `weight_scale` loader, and marks the parameter as holding row-major scales whenever a loader is present. The test's `_build_layer` passes a no-op loader and copies the checkpoint scales straight into the parameter, so the swizzled bytes reach a layer that now expects row-major ones. The serving path is fine; the test bypasses the step that moved.

## Modifications

`_build_layer` passes a loader that copies, and loads `weight_scale` through the parameter's own `weight_loader`, the way a checkpoint load does. No product code changes.

## Test plan

On a Blackwell GPU (GB300):
- `test_nvfp4_scaled_mm.py` on main: 1 failed, 12 passed. With this change: 13 passed.
- Bisect over the 78 commits since the test last passed locates #44418 (`09b7383624`) as the first failing commit.
- With this change applied before #44418 (`2f5407da28`): 13 passed, so the test does not depend on the new code path.
- Negative control: removing the loader's swizzled-to-row-major conversion makes the fixed test fail again.
- `black`, `isort`, `ruff check --select=F401,F821,F823,UP037` clean on the changed file.
