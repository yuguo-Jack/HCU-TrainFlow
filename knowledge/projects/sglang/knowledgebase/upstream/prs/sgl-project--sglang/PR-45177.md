# [Feat] hicache: Extend shared host reads to V4 and hybrid MLA pools

[Upstream PR](https://github.com/sgl-project/sglang/pull/45177) · state: open · merged: False

## Original PR description

> Part of the HiCache MLA host-dedup series — this final PR also carries the series umbrella (see **Series overview** below). This is `[8/N]`, stacked on `[7/N]` (#45176). Depends on `[3/N]` (#45141 — base shared-CPU read), `[5/N]` (#45173 — V4 multi-pool), and `[6/N]` (#45175 — Kimi hybrid).
>
> **Validation gate:** like `[3/N]` (#45141), this extension was hand-ported onto the post-#43595 pool-construction architecture (including the `MambaPoolHost` buffer-info signature). Before merging, run the shared-read UTs listed under Accuracy Tests on real hardware.

## Series overview

This is the final PR of an **opt-in** host-side deduplication series for MLA/DSA HiCache pools. Under plain tensor parallelism, MLA/DSA KV is **identical across attention-TP ranks**, yet HiCache stores a separate CPU (L2) copy per rank — wasting host memory and, with the `file` L3 backend, making every rank re-read the same bytes. The series keeps a single physical CPU copy of the replicated KV/indexer and restores it either by (a) owner-read-then-broadcast, or (b) all ranks reading the same shared CPU mapping directly. Rank-private Mamba/KDA state and independent draft shards stay per rank; replicated V4 compression-state regions are included in this shared-read extension. Dedup is **off by default**; enabling it defaults to `broadcast`, and `shared` CPU read is an explicit choice.

The design adapts the primitives from #36798 / #36800 and the integration approach from #26691 (closed, kept as prior design) to the current transfer / completion / pool-construction interfaces (including the #43595 / #43596 pool refactor). Each PR is independently reviewable and builds on the previous one:

| # | PR | Scope |
| --- | --- | --- |
| 1/N | #43795 | Register layer-first host pools as whole-layer ranges (host-register correctness fix) |
| 2/N | #43798 | Back up MHA draft on the `file` backend for every TP rank (fixes cross-rank MIN storage-hit collapse) |
| 3/N | #45141 | Integrate MLA/DSA L2 dedup + layer-wise overlap (broadcast, same-layer packing, four-layer grouping) **and** restore deduplicated KV from **shared CPU memory** for base MLA/DSA (absorbs the former standalone shared-read PR) |
| 4/N | #45168 | Support `file` L3 storage with MLA host dedup |
| 5/N | #45173 | DeepSeek V4 / V4.1 multi-pool host dedup |
| 6/N | #45175 | Kimi K3 hybrid MLA dedup (shared MLA KV + rank-private KDA state) |
| 7/N | #45176 | Honor `--dist-timeout` in dedup NCCL/Gloo groups |
| 8/N | *(this PR)* | Extend shared CPU reads to V4 and Kimi hybrid pools |

User-facing flags (introduced in 3/N):

- `--enable-mla-hicache-host-dedup` (default off)
- `--mla-hicache-host-dedup-mode broadcast|shared` (default `broadcast`)
- `--enable-mla-hicache-layerwise-overlap` (default off; broadcast-only layer-wise overlap)

**Aggregate results.** The series was validated on GLM-5.2 FP8, DeepSeek V4 / V4.1 Flash, and Kimi K3 across single-node H20 / H20-3e / SM103 TP8, using cold-vs-restored full-text, full token-ID and stop-state equality, real L2/L3 restore counts, and post-restore decode CUDA-graph checks. Dedup removes the per-rank duplicate CPU copies (e.g. node KV/indexer 210.09 GB → one 26.26 GB copy on GLM-5.2 TP8) and, for `file` L3, cuts process read-call volume by ~74.7%. Restore-path TTFT stays close to the non-dedup baseline; small residual overheads (short-input GLM, first-round V4) are reported honestly and not claimed as universal speedups. Performance is only ever compared **same-node, same-config, same-restore-volume**; numbers are never stitched across models, batches, or historical baselines. Per-PR detail lives in each sub-PR (L2 broadcast/packing in 3/N, L3 read-byte reduction in 4/N, V4 in 5/N, Kimi in 6/N, shared-read base in 3/N and its V4/Kimi extension in this PR).

> **Note.** Aggregate-branch measurements (broadcast same-layer packing / four-layer grouping / layer-wise overlap, and shared read) were evaluated together on the combined source. Each mechanism is reported against its own controls; running the model on the combined branch does **not** imply a trimmed individual PR was independently re-validated.

## Motivation

`[3/N]` (#45141) added shared-CPU-read restore for base single-pool MLA/DSA. This PR extends the shared path to the two model families that carry extra structure:

- **DeepSeek V4 / V4.1**: multiple replicated cache regions (SWA, C4/C128 KV, indexer, RoPE, FP4 data/scale, compressed state) each need their own shared mapping.
- **Kimi K3 hybrid**: only the MLA KV is shared; the rank-private KDA/Mamba linear-attention state must stay per rank.

## Modifications

- Share replicated V4 cache regions and Kimi MLA KV while retaining rank-private KDA state, physical device mappings, and native per-layer completion events.
- Agree on construction failures across ranks, roll back already-registered buffers, and account for **one shared copy plus all private allocations** in the host budget.
- Reuse the `[3/N]` shared-read restore machinery (owner-write publication, per-rank physical indices, all-reader reclaim checks, decode-graph preservation after restored prefill); no new user-facing flag — enable with `--mla-hicache-host-dedup-mode shared` on the corresponding V4/Kimi launch command.

Shared read remains limited to single-node plain-TP L2; it does not extend to file L3, draft, cross-node, or PP/DP/CP/DCP.

## Speed Tests and Profiling

### V4 / V4.1 shared read

Same node/config as `[5/N]` (8×H20-3e, TP8; V4.1 adds EP8, `--moe-a2a-backend none --fp8-gemm-backend triton`). Median restore-round average TTFT (ms):

| Model / batch | No dedup (before) | Broadcast | Shared read | No dedup (after) |
| --- | ---: | ---: | ---: | ---: |
| V4 Flash, first round ×5 | 282.74 | 293.69 | 287.78 | 283.51 |
| V4 Flash, independent repeat 2/5/3 | 290.43 | — | 283.59 | 286.16 |
| V4.1 Flash, ×3 | 250.10 | 248.93 | 246.69 | — |

V4 first-round shared is 1.78% / 1.51% slower than the before/after baseline, while the independent repeat is 2.35% / 0.90% faster; the two rounds are recorded separately, and the latter's own baseline drifted 1.47%, which is not attributed to the new code. V4.1 shows no regression; three samples do not prove a universal speedup.

### Kimi K3 shared read

Same node/config as `[6/N]` (SM103, TP8). Continuing the `nodup → broadcast → nodup → shared → nodup` sequence:

| Mode | Five restore-round avg TTFT (ms) | Median (range), ms | Two-round TPOT median, ms | Two-round throughput median, req/s |
| --- | --- | ---: | ---: | ---: |
| Shared CPU read, native layer wait | 390.33 / 397.23 / 394.42 / 401.10 / 389.01 | 394.42 (389.01–401.10) | 158.621 | 0.25286 |
| No dedup, after baseline | 401.67 / 404.61 / 406.21 / 408.74 / 393.02 | 404.61 (393.02–408.74) | 161.033 | 0.25040 |

Shared read is ~**−2.40%** vs the adjacent no-dedup medians. Sample ranges overlap; this supports "close to baseline" for this workload, not a statistically significant or universal gain. All formal samples have restore-round total hit 95.5224%, identical real host restore volume per mode, and zero GPU-hit delta across eight TP ranks.

### Profile

Shared read removes the cache-content broadcast for V4's replicated regions and Kimi's 24 MLA layers; each GPU reads more than a broadcast non-owner rank by the size of the shared KV (Kimi: 65,470,464 bytes for the main MLA KV), while private-state transfer is unchanged. Receiving-rank NCCL time includes waiting and is not the net latency difference; overlap is judged only by real profile.
