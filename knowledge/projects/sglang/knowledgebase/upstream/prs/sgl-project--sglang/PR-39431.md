# [Fix][DSA] transform_index: support non-2048 topk widths and guard out-of-range indices

[Upstream PR](https://github.com/sgl-project/sglang/pull/39431) · state: open · merged: False

## Original PR description

Two fixes for the DSA transform_index kernels, both hit when serving GLM-5.3-Flash with MTP index-share rows (topk + kpool - 1 = 2051 columns):

1. **Relax hardcoded topk-width assertion** — `transform_index_page_table_{decode,prefill}_fast` asserted `shape[1] == 2048`. The prefill kernel already derived TOPK from the tensor; the decode kernel hardcoded it for both its arange extent and row advance, now parameterized (plus power-of-two BLOCK_TOPK, since 2051 is not a valid tl.arange extent).

2. **Guard out-of-range topk indices in the prefill kernel** — MTP index-share rows carry kpool slot positions that can exceed max_seqlen_k; the unbounded page-table load crashed with an illegal memory access. `page_table_cols` is passed in (added to `do_not_specialize` alongside `page_table_stride_0` so varying context lengths don't grow the loaded cubin set) and out-of-range indices now fall through to the -1 path.

Tests: nonstandard widths (2051/64) on prefill (expanded + padded) and decode paths, plus an out-of-range index test. All 11 tests + 6 subtests pass on H20 (9.6s). pre-commit clean.
