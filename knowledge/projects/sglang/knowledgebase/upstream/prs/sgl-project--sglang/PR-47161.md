# [Perf] rust-server: Pin frontend threads to one shared CPU set, not one core each

[Upstream PR](https://github.com/sgl-project/sglang/pull/47161) · state: closed · merged: True

## Original PR description

## Motivation

The Rust server used to split the cores it was given into disjoint per-group sets (API runtime, tokenizer pool, detokenizer pool, the two router threads) and pin each thread to exactly one core. A thread pinned to a single core cannot migrate: when anything else runs on that core (an MM worker's decoder thread floating over the same set, or another process) it waits in that core's run queue while the rest of the set idles, and every stream it serves stalls with it.

Separately, the Python launch path narrowed the scheduler's own thread to the few reserved launch cores after the server started. A busy neighbour on one of those cores then holds the scheduler thread, and every TP rank waiting on it at the next collective, in that core's queue.

## Modifications

- `rust/sglang-server/src/utils/threads.rs`: replace the per-group core plan with one shared `CpuSet` built from `cores` (`frontend_cpu_set`), and pin each thread to that set with `rustix::thread::sched_setaffinity` (`pin_current`). Core ids outside the set's range are ignored with a warning.
- `rust/sglang-server/src/utils/runtime.rs`: every spawned stage, the tokio API runtime's worker threads and the thread running its `block_on` pin to the shared set. The router-scaling note moves next to the `to-scheduler` spawn.
- `rust/sglang-server/Cargo.toml`, `rust/Cargo.lock`: drop `core_affinity`; `rustix` (already a dependency) gains the `thread` feature. `num_cpus` and `hermit-abi` leave the lockfile with it.
- `python/sglang/srt/rust_server/server.py`, `config.py`: the launch thread narrows its affinity only while the MM threads are created (so they inherit the server cores) and then restores its full mask; the scheduler thread is no longer pinned to the reserved launch cores. The reserved cores are still kept out of the frontend set. Docstring and log wording updated to match.
- `rust/sglang-mm/src/common/par.rs`, `message/config.rs`: comment updates for the new pinning model.
- `test/registered/unit/multimodal/rust/shared/test_rust_server_extension.py`: `launch_context` takes a core partition; a new test launches on a thread of its own with a two-way partition and checks that MM threads are created on the server cores while the launching thread ends with its full mask.
