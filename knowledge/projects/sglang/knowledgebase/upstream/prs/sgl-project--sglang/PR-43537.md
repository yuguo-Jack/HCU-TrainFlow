# Fix serialized KV scale loading in Unified Gemma

[Upstream PR](https://github.com/sgl-project/sglang/pull/43537) · state: open · merged: False

## Original PR description

## Problem and change

Unified Gemma checkpoints can serialize calibrated KV globals as `model.language_model.layers.N.self_attn.k_scale` / `v_scale`, while the runtime parameters live under `self_attn.attn`. The Unified loader currently skips these names, leaving the scale parameters unloaded.

Apply the existing `maybe_remap_kv_scale_name` helper before the non-stacked parameter lookup, as other model loaders do. A registered CPU regression constructs a reduced real Unified model and checks that its real loader populates both K/V parameters and reports their remapped names.

## Validation

- Current-main base `6fc8d9da3288e9710a6f9a1f59503cacf8a984f0`: regression fails with `-1.0 != 0.125` after loading a serialized FP8 scale.
- Candidate: the same regression passes (`1 passed`) with two layers and distinct K/V values.
- Pinned CPU test environment: Transformers 5.19.0, Torch 2.14.1+cu130, compressed-tensors 0.18.0; CUDA disabled for this test.
- Applicable pre-commit checks pass. Three Windows hooks could not locate `python3`; their exact scripts passed under uv Python 3.12.

The test uses current-main FP8 support. Static NVFP4 scheme acceptance is separately addressed in #43510. Text-only/multimodal loading policy, including the existing work in #32425, is outside this change. This PR makes no GPU quality or performance claim.
