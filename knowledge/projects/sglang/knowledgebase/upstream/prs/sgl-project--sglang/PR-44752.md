# [Perf] sampling: JIT softmax and argmax kernels for the sampler and speculative verify

[Upstream PR](https://github.com/sgl-project/sglang/pull/44752) · state: open · merged: False

## Original PR description

> (auto generated by Claude)

## What

- New JIT fp32 softmax (`sglang.kernels.ops.sampling.softmax`): row cached in registers (one read, one write), one row per runtime-sized cluster, per-request temperature fused, safe in place. Used on SM100-family GPUs; other platforms keep Triton (ROCm) / torch.
- New JIT split-vocab argmax (`sglang.kernels.ops.sampling.argmax`): ties take the lowest index, NaN never wins.
- `Sampler`: temperature + softmax run in place on the logits buffer (drops the `div_` and the `logits[:] = ...` copy); greedy rows use the JIT argmax.
- EAGLE / DFlash / UNO / DSpark verify use the same ops; EAGLE passes `rows_per_request` instead of `repeat_interleave`-ing temperatures.
- Removes the Cake softmax dispatch, DSpark's `fused_argmax` switch and the Triton `row_argmax` (kept in `bench_argmax.py` as a baseline).

## Validation (GB300)

- Kernel tests, sampler / EAGLE / UNO / DSpark unit tests, and DSpark greedy accept captured in a CUDA graph vs a `torch.argmax` reference: all pass.
