# [AMD] Extend MiniMax-M3 mono decode kernels to TP2 on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/44686) · state: closed · merged: False

## Original PR description

## Motivation

Extends #44319 (MiniMax-M3 whole-layer fused decode monokernel on gfx950 / MI355X, by @zijiecode) from TP4-only to TP2. This branch is built on top of that PR's commit `60a1c4f1ac`; #44319 is the basis for everything here.

## Modifications

- Kernel shape constants (`LOCAL_Q_HEADS`, `LOCAL_KV_HEADS`, `LOCAL_INDEX_HEADS`, `INTER`) are derived from TP instead of being TP4 literals. TP4 values are unchanged.
- Per-head indexer selection. At TP2 a rank holds 2 index heads and 2 KV heads, so index head `h` selects blocks for KV head `h`. The previous code refused `count > 1` as context parallelism; an own-pair is not context parallelism. The split stage now runs one pass per KV head — the KV cache is addressed by head, so one split pass is one KV head and its GQA group.
- Several expressions that were correct at TP4 only by coincidence are now sized by TP: the merge and MoE mid thread maps, the narrow MoE LDS pool (sized from `INTER`, not `HIDDEN`), and the projection scratch bound.
- At TP2 the LDS budget caps the step width at 12; wider steps route to the module path, which is the existing supported fallback.

## Validation

- `SGLANG_MONO_CHECK` against the module path at TP2, widths 1-4 and 12, 456 rows each, no NaN; also at a 70k-token context exercising the long-selection path, and under CUDA graph capture.
- TP4: unchanged constants (the new code is TP-conditional), compiles clean at S=16, and mono-check passes 912 rows with no NaN.
- The per-head selection was checked by a negative control: deliberately making both split passes use index head 0's blocks — the pre-change behaviour — moves the TP2 width-1 residual median from 0.074-0.090% across three clean runs to 0.178%. So the check does discriminate this failure mode.
- 43 CPU unit tests covering the per-TP constants.

## Remaining work

- TP8 is not done (the merge needs a masked tail round at H=8, plus a padded MoE scale stride).
- A pre-existing fault on contexts shorter than one 128-token page, reproduced on #44319's own commit at TP4 — not introduced here.
- RFC #43949 conformance (directory layout, single `--enable-monokernel` switch, bounded cross-GPU waits) is not addressed yet.
- No throughput measurement yet.

- kevin-mii · comment · 2026-10-16T08:37:15Z · [source](https://github.com/sgl-project/sglang/pull/44686#issuecomment-6211541607)

Thanks for the TP2 extension! Since #44353 landed, model monokernels move to sgl-project/sgl-amd-mono (template: sgl-project/sgl-amd-mono#6). This builds on #44319, so it's probably simplest to port both together with @zijiecode, as one PR to sgl-amd-mono.

One framework note: kernel widths are declared per GPU type (`DeviceLimits.widths`), not per TP size yet, so the 12-row cap at TP2 can't be stated directly. GLM (#6) handles the same limit by running the model's normal forward inside its spec for wider steps. Making widths TP-dependent in the framework is on our list, which would let the framework route these steps itself.
