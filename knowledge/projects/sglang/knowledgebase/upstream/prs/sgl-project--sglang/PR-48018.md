## Motivation

Several rules singled out the prefix tree's first window: admission read its evictable tokens through `swa_evictable_size`, only its frees started above a request's eviction shield, the decode retirement trigger gated on its cursor alone, the memory leak checks conserved only it, and the decode pending-transfer usage charged every window's rows to it. A tree's first window slot also took the window role id, so code meaning "the window" silently meant "the first window". The tail a running request keeps of a window (its length widened by a reader reaching further back) was decided in several places from different inputs.

## Modifications

- Reads: `window_evictable_size(slot)` and `window_available_size(slot)` answer every window slot the same way (the chain from the slot's sub-pool, `units_available`).
- Retirement (`unified_radix_cache.py`, `common.py`, `kv/storage.py`): the eviction shield and lowest freeable position are the request's, for every window (`window_evict_floor`, `window_dead_lo`); the decode trigger is due when any window has slid an eviction interval past its own cursor (`BasePrefixCache.window_lengths`).
- Accounting (`pool_stats_observer.py`, `invariant_checker.py`, `decode.py`): every window pool's stats name the tree slot that keeps it (`WindowPoolStats.component`) and each is conserved with that slot's counts (`window_protected_size`, `session_held_window_tokens`, `kv_private_window_tokens`); `pre_allocated_token_counts` charges each window by its own cursor and `sglang:prealloc_window_token_usage` reports every window.
- Slot ids (`kv/plan.py::tree_slot_ids`, `ChainAllocator.window_component`): every slot is named by its component; only a tree with one window slot gives it the role id (the one the native tree core, the external cache linker and LMCache address). The window component asks the tree for the family's own slot (`slot_id(TREE_WINDOW)`); `KVStorage.advance` has no default window.
- Retention (`kv/storage.py`, `static_kv_storage.py`): the storage owns each window's kept tail; the cache builder binds the readers' reaches and an unstated window's length once at startup (`bind_window_retention`); `retained_window_lengths` and `window_tails` answer every caller (tree slots, `resume_units`, PD prefill and decode, the KV checksum, the cache's retain window, the admission clip). The request window of a static pool (DeepSeek V4 encoder replay) is answered before the no-window-pool case.
- Tests: three-window trees report and evict each window the same way; a shorter further window retires by its own cursor and the shield holds its rows; a further window's leak is caught by its own counts; pending transfers are charged per window; several-window plans name every slot; retention answers per window (`test_unified_window_sub_pools.py`, `test_invariant_checker.py`, `test_prealloc_token_usage.py`, `test_swa_eviction_interval.py`, `test_declared_parts.py`, `test_disaggregation_wire.py` and others).

No intended behavior change for a pool with one window; with several windows, each is retired, accounted and retained by its own rules.
