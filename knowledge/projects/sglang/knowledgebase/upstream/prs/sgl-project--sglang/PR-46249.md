# [Fix] diffusion: Route realtime cleanup to the session owner

[Upstream PR](https://github.com/sgl-project/sglang/pull/46249) · state: closed · merged: True

## Original PR description

## Motivation

Realtime generation chunks are pinned to a DP replica by session ID, but
`ReleaseRealtimeSessionReq` currently falls through to round-robin routing.
Disconnect cleanup can therefore reach the wrong worker and return
`released=False`, leaving the owning worker's session state resident until it
is reset or evicted.

## Modifications

- Recognize session-release requests in the existing shared routing helper.
  Both synchronous and asynchronous clients use the same owner as generation.
- Keep replica-wide control operations on their existing broadcast path and
  ordinary generation on round-robin. No new routing state or configuration.
- Extend existing tests with DP1/2/4 coverage and real two-replica ZMQ
  round trips using `RealtimeSessionCache`: chunk continuity, interleaved
  stateless requests, duplicate release and empty caches afterward.
- Correct the control-protocol module description to distinguish broadcast
  operations from session-scoped cleanup.

## Validation

On a Linux development environment, using the unmodified routing code with
the new tests: **4 failed, 168 passed**. Both real-socket tests reproduced a
release reaching replica 1 with `released=False` while replica 0 owned the session.
With the fix: **172 passed** across DP routing, scheduler clients and realtime
tests. Pre-commit passes.

The tests are discovered by the existing diffusion unit-test suite; no new
server/model CI job is added. This fixes cleanup ownership, not worker failover
or durable session recovery.

## Accuracy and Performance

No model inputs, denoising steps or kernels change. No inference speedup claim.
