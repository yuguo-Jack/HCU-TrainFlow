# [Perf] [AMD] mooncake: pack heterogeneous-TP SWA KV pages

[Upstream PR](https://github.com/sgl-project/sglang/pull/47307) · state: closed · merged: False

## Original PR description

## Motivation

With prefill TP smaller than decode TP, Mooncake still sends SWA head slices as many small ranges, even when full KV uses staging.

## Modifications

Add default-off `SGLANG_MOONCAKE_SWA_PACKING`: gather destination-local heads and write whole pages directly into the final SWA pool. Validate NHD/GQA geometry and page bounds; unsupported peers fall back before submission. Registered scratch defaults to 64 MiB per initialized worker. Uncertain completion quarantines buffers. Existing full-KV staging and native Mooncake are unchanged.

## Accuracy Tests

15 CPU tests pass. Earlier MI355X RDMA fixtures passed byte/sentinel checks; 498 fixed-prompt requests matched the greedy reference. Model results use the documented pre-extraction source and experimental ROCm Muse runtime from #44667; this standalone rebase has CPU validation.

## Speed Tests and Profiling

Muse 816B MXFP4, P4/D8, C1, ISL1024/OSL2, full staging enabled: direct/packed/direct median TTFT **287.4 / 129.4 / 289.1 ms** (30 measured requests per arm). OSL64 total latency/ITL did not improve. See [full statistics and source revisions](https://github.com/Lzy17/sglang/blob/662b0b0462301894dcba28aa0dead119ec952750/test/manual/disaggregation/README_mooncake_swa_packing.md).

Related: #44615 and #47192. This PR applies independently of the MoRI draft.
