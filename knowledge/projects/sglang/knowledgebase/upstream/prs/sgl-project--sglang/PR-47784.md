## What

Rewrites `moe_finalize_fuse_shared` (the deferred-finalize combine of the trtllm-gen MoE path: `out[t] = sum_k w[t, k] * gemm2_out[permuted_idx[t * K + k]] (+ shared[t])`) as a header-only JIT kernel and removes the old cutlass-based `.cu`.

- Each thread owns 8 bf16 of one token and issues all K row gathers at once, so a token costs the index load plus one gather round trip; tokens map to `blockIdx.y`, so even one token spreads over `H / 1024` CTAs.
- The token's route (K row indices and weights) is spread over the warp (lane k holds slot k, read by shuffle), which keeps top-k 16 within one wave.
- Skipped rows (index -1) use a predicated load into zeroed registers with weight -0.0, so the sum stays bitwise unchanged without a branch per slot.
- bf16 weights use the mixed-precision `fma.rn.f32.bf16` (`math::fma_f32_bf16`), fp32 weights the packed `fma.rn.f32x2` (`math::fma_f32x2`, added to `math.cuh`); both give the fp32 FMA's bits.
- One token per CTA row while the grid fits one resident wave; past it, a persistent variant walks tokens and prefetches the next token's route.
- New optional arguments: `out=` writes into a caller buffer with a row stride (e.g. a symmetric-memory buffer); `routing_ready` (default on, with PDL) reads the route and the shared row before the PDL wait, which is valid because the trtllm-gen gemm2 triggers its dependents only after its own wait and the routing runs in an earlier kernel.

Results are bitwise equal to the old kernel (fp32 accumulation in k order, shared row added last).
