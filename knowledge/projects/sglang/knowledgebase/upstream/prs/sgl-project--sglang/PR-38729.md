# Honor X-Data-Parallel-Rank on /generate, carry routed_dp_rank through /v1/messages and Responses tool loops

[Upstream PR](https://github.com/sgl-project/sglang/pull/38729) · state: open · merged: False

## Original PR description

## Motivation

A DP-attention deployment (`--dp N --enable-dp-attention`) is N schedulers with disjoint KV caches, so a gateway that does prefix-aware routing has to pin each request to the rank that holds its prefix. The `X-Data-Parallel-Rank` header is the pinning channel that leaves the request body untouched (no parse/merge/re-serialize on a ~100KB payload), but not every route reads it, and not every route accepts the body field either.

Measured on a live `v0.5.19` server (DeepSeek-V4-Flash, tp4/dp4/ep4), pinning each rank in turn and sampling `num_running_reqs` per rank while the request runs:

| endpoint | body `routed_dp_rank` | body `data_parallel_rank` | header `X-Data-Parallel-Rank` |
|---|:-:|:-:|:-:|
| `/v1/chat/completions` | pins | pins | pins |
| `/v1/completions` | pins | pins | pins |
| `/v1/responses` | **ignored** | **ignored** | **ignored** |
| `/v1/messages` | ignored | ignored | pins |
| `/generate` | pins | pins | **ignored** |

Every "ignored" is an HTTP 200 that round-robins: a pin on those routes fails silently and the request re-prefills cold on another rank.

**Since that measurement**, #35503 landed on `main` and closed the `/v1/responses` row for the first request of a call: `ResponsesRequest` has `routed_dp_rank` (plus the deprecated `data_parallel_rank` alias), and `create_responses` resolves header over body and passes the rank on the `GenerateReqInput`. This PR was rebased on top of it and re-scoped to what is still missing:

- `/generate` does not read the header at all.
- `/v1/messages` (Anthropic) drops a body rank; only the header worked.
- On `/v1/responses`, the continuation turns of a built-in tool loop (`_generate_with_builtin_tools`) are built without the rank, so a pinned conversation leaves its rank after the first tool call.
- Each route had its own copy of the header parsing.

## Modifications

- `request_headers.extract_routed_dp_rank(headers, body_routed_dp_rank)` becomes the single reader of `X-Data-Parallel-Rank` (header over body, 400 on a non-integer header). `OpenAIServingBase.extract_routed_dp_rank_from_header` delegates to it, so chat, completions and responses behave exactly as before.
- `/generate` reads the header through that helper ahead of the env-gated `x-override-*` pass, so precedence matches the OpenAI routes: header over body, `x-override-routed-dp-rank` over both.
- `create_responses`: every continuation `GenerateReqInput` in the built-in tool loop carries `adapted_request.routed_dp_rank`, so a tool loop stays on the rank holding its KV cache.
- `AnthropicMessagesRequest` accepts `routed_dp_rank` (and the deprecated alias) and the converted `ChatCompletionRequest` carries it, so a body pin on `/v1/messages` is honoured too. The header already reached that route through `OpenAIServingChat` and keeps precedence.

No change to `ResponsesRequest` or the `/v1/responses` first-turn path; those are #35503's.
