## Motivation

The unified pool's host (HiCache) side built its host pools from pool-specific knowledge inside `mem_cache/pool_host/unified.py`. Later PRs in this stack let the unified pool carry any number of window sub-pools and fused draft parts, which the host side must mirror without a case per pool shape. This PR moves the shared host backing next to the device memory code and builds host pools from each device layout view's own description.

## Modifications

- `mem_cache/kv/memory/host_backing.py` (new): `_SharedPageEnvelopeHostBacking` moved from `mem_cache/pool_host/unified.py` unchanged in behavior (a mechanical move in the first commit).
- `mem_cache/kv/layout/{base,mha,mla,state}.py`: each layout view describes its host rows (`host_layout()` returning e.g. `MHAHostLayout`, MLA and state equivalents) and builds its host pool from `HostPoolOptions`; MHA host transfers require unsharded token ids.
- `mem_cache/hybrid_cache/hybrid_pool_assembler.py`, `mem_cache/pool_host/unified.py`, `mem_cache/kv/storage.py`: unified host pools are assembled from the layout views' descriptions instead of per-pool-type code.
- Tests: `test/registered/unit/mem_cache/kv/test_host_layout.py` (host rows and storage pages match the existing host layouts; a state layout accepts a KV split without splitting state), updates to `test_hybrid_pool_assembler.py` and `test_unified_kv_storage.py`.

No intended behavior change: host pool sizes, layouts and transfers are the same as before.
