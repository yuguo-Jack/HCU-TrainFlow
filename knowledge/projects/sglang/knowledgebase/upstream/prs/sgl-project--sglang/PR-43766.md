# [AMD][CI] Drop tc_piecewise split-op cases on ROCm and run the breakable ones

[Upstream PR](https://github.com/sgl-project/sglang/pull/43766) · state: open · merged: False

## Original PR description

## Motivation

`tc_piecewise` is being retired in favor of the breakable CUDA graph (BCG). Step 3/9 of that series (#42287) is merged: both config parsers reject `tc_piecewise`, and non-CUDA platforms now default to a disabled prefill graph.

Upstream has already deleted the AMD tests that ran `tc_piecewise`:

| Test | AMD suite | Removed by |
|---|---|---|
| `piecewise/test_piecewise_cuda_graph_support_1_gpu.py` | `stage-b-test-1-gpu-large-amd` | #42571 |
| `amd/test_deepseek_r1_mxfp4_8gpu.py` (forced `--cuda-graph-backend-prefill=tc_piecewise`) | `stage-c-test-large-8-gpu-amd-mi35x` | #42287 |

No AMD CI job runs `tc_piecewise` any more. One AMD-registered leftover remains: `test_runner_mode_split_op_extend_cases` in five attention unit tests. It runs a `tc_piecewise` (`pcg`) variant and a breakable (`bcg`) variant. #27817 skipped the whole method on ROCm because the `pcg` path failed with `AttributeError: 'TcPiecewiseForwardContext' object has no attribute 'num_tokens'`. #27817 named #27811 as the fix, and #27811 restored that field (it merged first; `TcPiecewiseForwardContext` declares it today). The skip was never removed, so the breakable variant has never run on ROCm.

## Modifications

In the five files, remove the method-level `@unittest.skipIf(is_hip(), ...)` and choose the variants inside the method:

- ROCm runs only `breakable=True` (`bcg`). The retired `tc_piecewise` variant no longer runs on AMD.
- CUDA still runs `(False, True)`, as before.

Files: `attention/unittests/dense/test_triton.py`, `gdn/test_torch_native.py`, `gdn/test_triton.py`, `kda/test_triton.py`, `swa/test_triton.py`.

This changes no CUDA behavior, no CI registration, and no shared test kit. It does not overlap with the open TCPCG retirement steps (#42288–#42293). In particular, step 8 (#42292) turns the non-breakable variant into full-graph coverage on CUDA, and this PR leaves that variant in place on CUDA.

## Accuracy Tests

Not applicable: this changes tests only.

- `pre-commit run --files <changed files>` passes.
- CI registry collection with `sanity_check=True`, run the way `test/run_suite.py` does it, collects 2,856 registrations from 2,333 files. The five files keep their CUDA `base-b` and AMD `stage-b-test-1-gpu-large-amd` registrations.
- I extracted the edited method from each file with `ast`, then ran it with `is_hip` and the split-op runner stubbed. CUDA produces `pcg` and `bcg` subtests for every case; ROCm produces only `bcg`.
- **Not run on a GPU.** The `bcg` cases have never run on ROCm, so `stage-b-test-1-gpu-large-amd` needs an AMD CI run before merge. If a `bcg` case fails on ROCm, the fallback is to skip the method on ROCm again, with a reason specific to the breakable path.

## Speed Tests and Profiling

Not applicable. The new ROCm work is a few small subtests per file inside the existing `stage-b-test-1-gpu-large-amd` registrations.
