# [Feat] [XPU] quant: Add MXFP8 W8A8 compressed-tensors

[Upstream PR](https://github.com/sgl-project/sglang/pull/41532) · state: open · merged: False

## Original PR description

using torch,nn.functional.scaled_mm
Enable xpu_scaled_mm choice for `--fp8-gemm-backend`

Adds support for the compressed-tensors ``mxfp8-quantized`` W8A8 format (OCP microscaling FP8: float8_e4m3fn elements with UE8M0 block-32 scales) on GPU, where it maps onto torch native MXFP8 BlockWise1x32 GEMM.

  - CompressedTensorsW8A8MXFp8: loads the pre-quantized E4M3 weights and their UE8M0 scales, dynamically quantizes activations per forward with the fused sgl_per_token_group_quant_8bit kernel, and runs the matmul through torch.nn.functional.scaled_mm. Weights are never requantized -- the only post-load fixup is reinterpreting the UE8M0 scale bytes as float8_e8m0fnu and transpose weight/scales once.
  - Routing: _is_mxfp8_w8a8 detects the format (floating-point W8A8 with the GROUP strategy and group_size 32) and is checked before the generic fp8 W8A8 path.
  - Allowlist mxfp8_quantized as an activation-quantization format.

One non-obvious constraint worth recording:

  - The activation scale is a contiguous row-major [M, K/32] UE8M0 buffer, which is exactly what _scaled_mm's is_blockwise_1x32_scaling probe expects and what the SYCL kernel writes directly. This requires the sgl-kernel-xpu row-major UE8M0 support (port of sgl-project/sgl-kernel-xpu#357); without it the kernel only emits column-major uint32-packed scales.
