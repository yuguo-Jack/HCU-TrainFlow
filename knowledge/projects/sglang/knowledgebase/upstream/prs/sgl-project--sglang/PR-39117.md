# [DCP] Restore GLM-5.3 Flash decode CP and fix virtual KV addressing

[Upstream PR](https://github.com/sgl-project/sglang/pull/39117) · state: closed · merged: False

## Original PR description

## Motivation

Restore GLM-5.3-Flash DCP and fix global KV locations being used against rank-local buffers. Fixes #36886.

## Modifications

- Shard target attention KV; replicate both indexers and EAGLE/MTP draft KV. Translate target writes/reads by ownership and merge partial outputs with base-2 LSE; draft execution bypasses DCP collectives.
- At DCP4/base 64, pool pages are **target KV = 64; draft KV and both indexers = 256**. Indexer kernels retain 64-entry `[keys | scales]` blocks through zero-copy views. Restore `page_size=self.pool_page_size`; remove the `+192` capacity workaround.
- Gather prefill KV in per-request order and use RAGGED indices. Disable MHA one-shot under DCP pending follow-up.
- Reuse main's MLA CPU-copy fix; preserve indexer keys/scales and compressed tails. Local indexer copies use global pool pages; HiCache uses logical capacity. Replicated indexer PD descriptors/checksums use base-page blocks across different DCP widths; sharded target KV transfer across those widths remains unresolved.
- Budget replicated storage explicitly, preserving K3/DSpark allocation and V4 kernel geometry.

Validate supported combinations in server-argument handling: CUDA NoPE MLA, BF16 KV, TileLang, fused top-k; reject HiSparse, prefill CP, and EAGLE topk > 1 with DCP. Normal GLM-5.3 and DeepSeek V3.2 use RoPE DSA and are rejected with DCP; support here is GLM-5.3-Flash's NoPE path. HiCache + DCP + EAGLE/MTP remains guarded pending lifecycle validation.
