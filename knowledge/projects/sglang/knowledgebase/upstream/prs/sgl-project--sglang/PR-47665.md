# [Perf] [NPU] dsv4: Generate compression positions with stepped arange

[Upstream PR](https://github.com/sgl-project/sglang/pull/47665) · state: open · merged: False

## Original PR description

## Motivation

DeepSeek-V4 NPU prefill builds compressed RoPE positions separately for each request and compression ratio. It currently creates consecutive group IDs with `arange`, then multiplies the tensor by 4 or 128.

Generate the positions directly with a stepped `arange`. This removes the extra multiplication and its intermediate tensor for each nonempty request/ratio pair, keeping the same int64 positions and padding.

## Validation

297 cases passed on CPU and Ascend NPU using the actual prefill helper and an independent position oracle. Covers C4/C128, prefix and compression boundaries, empty queries and empty batches.

Helper microbenchmark on one Ascend NPU, approximately 4,096 query tokens per request:

| Batch | Before | After |
| ---: | ---: | ---: |
| 1 | 0.331 ms | 0.295 ms |
| 8 | 0.690 ms | 0.447 ms |
| 32 | 1.972 ms | 1.036 ms |

ABBA order, each arm with 5 warmups and 3 groups of 20 calls, synchronized at group boundaries. These are prefill metadata helper timings, not model TTFT/TPOT. Both arms use the same main source and retain the original CPU readback; #47663 is not stacked here.

Formatting and lint checks passed. Two Windows hooks could not launch `python3`; the same scripts passed with the available Python executable.

[Reproduction scripts, frozen sources and raw results](https://github.com/AkiYangDev/sglang/tree/f1d7db04cea1eb539743914b543e2cf5fc01ed87) are on a separate evidence branch. No test files are added to this PR.
