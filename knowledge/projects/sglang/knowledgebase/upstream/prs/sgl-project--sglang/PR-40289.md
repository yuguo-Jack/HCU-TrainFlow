# [Fix] Fall back from fused KV writes for RL native RoPE

[Upstream PR](https://github.com/sgl-project/sglang/pull/40289) · state: closed · merged: False

## Original PR description

## Motivation

`rl_on_policy_target` forces native RoPE for numerical alignment. Models that use `enable_fused_set_kv_buffer`, including Qwen3-MoE, still pass a fused KV-store payload to RoPE and skip the attention layer's regular KV-cache write. Native RoPE does not consume that payload and asserts during CUDA graph capture:

```text
AssertionError: fused_set_kv_buffer_arg is not supported for native implementation
```

Simply removing the assertion would be unsafe because the caller would still assume that RoPE wrote the KV cache. Unlike #13080, this change does not disable fusion only during graph capture and then lose it during replay. It gates fusion only for the RL on-policy mode that forces native RoPE for the whole run.

## Modifications

- Return `False` from `enable_fused_set_kv_buffer` when `rl_on_policy_target` is configured.
- This makes every existing caller omit the unsupported fused payload and use its existing regular KV-cache write path.
- Add CPU unit tests that pin both the RL fallback and the unchanged standard CUDA bf16 fused path.
