# [NPU] Set Ascend env for all build layers and shell sessions

[Upstream PR](https://github.com/sgl-project/sglang/pull/43777) · state: open · merged: False

## Original PR description

## Motivation

In `docker/npu.Dockerfile` the Ascend `ENV` definitions were placed *after* the
sglang editable install, so every earlier `RUN` step had to manually source
`/etc/environment_new` to see CANN paths, and the final image exposed no CANN
environment to `docker exec` shells. Both make the image hard to extend and to
debug.

## Modifications

- Pin `SHELL ["/bin/bash", "-c"]` so `RUN` steps are parsed by bash consistently.
- Move `ASCEND_HOME_PATH` and `LD_LIBRARY_PATH` up to right after the base image
  `ARG` block, so all later layers inherit them, and drop the now-redundant
  `. /etc/environment_new &&` prefixes from the torch/torch-npu, ModelScope/EvalScope
  and pybind11/triton-ascend steps.
- Set `ASCEND_CUSTOM_OPP_PATH` to the `custom_transformer` and `customize` OPP
  vendors after the custom ops are built.
- Generate `/etc/profile.d/ascend.sh`, sourcing the `customize` and
  `custom_transformer` `set_env.bash`, `ascend-toolkit/set_env.sh` and
  `nnal/atb/set_env.sh`, and source it from `/etc/bash.bashrc` so interactive
  shells match the build environment.
- Harden the `deep-ep` symlink step by capturing the pip install location in
  `PIPDIR`, asserting it is non-empty, and only then `cd` into it.
