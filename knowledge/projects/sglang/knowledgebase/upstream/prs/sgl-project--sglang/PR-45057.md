## Motivation

PR #29421 introduced GLM DSA prefill context parallelism (prefill-CP) and DSA cache layer-split on CUDA. This PR adapts both features to the NPU backend. The two are coupled: layer-split is a prefill-CP-only optimization, so prefill-CP support is a prerequisite. The PR is split into two commits along the same boundary.

## Modifications

#### Part 1: prefill-CP adaptation

1. **`rebuild_cp_kv_cache` for NPU** (`deepseek_v2_attention_mla_npu.py`): the shared MLA path calls `m.rebuild_cp_kv_cache`, which did not exist on NPU (AttributeError). The NPU version unpacks the latent-packed local KV, all-gathers across the CP group, and restores global token order.
2. **Redundant full-sequence indexer** (`dsa_npu_indexer.py`): `npu_lightning_indexer` in TND mode accepts exactly one KV bound per batch and advances it by 1 per row (bottom-right aligned causal). Interleave shards every `cp_size`-th token, so within any multi-row batch the true causal bounds advance by `cp_size` — exact per-row top-k is impossible with a shared bound. Instead of a per-token pseudo batch, we all-gather q and indexer weights to the full sequence and reuse the **identical kernel call as the non-CP path** (including the quantized  variant), then slice local rows by global stride and zero-fill padding rows. This keeps the batched contiguous-causal kernel form and its efficiency, at the cost of one extra per-layer q/weights all-gather.
3. **Half-split attention kept** (`ascend_backend.py`): `npu_sparse_flash_attention` receives explicit `sparse_indices`, so the causal bound only masks candidates. With exact candidates from the full-sequence indexer, a loose bound is provably safe (removes nothing relevant), so the upstream half-split structure (2 calls per layer) is retained. Two robustness fixes: per-request row counts are recomputed from the live batch (`extend_seq_lens_cpu`) instead of cached metadata, which under overlap/disagg scheduling can describe a different batch and previously crashed with a dim0 mismatch (370 vs 368).

#### Part 2: DSA cache layer-split adaptation

1. New `NPULayerSplitMLATokenToKVPool` (`npu/dsa_cache_layer_split.py`): layer-sharded KV pool; layers owned by other CP ranks are read via owner-broadcast into a remote scratch layer.
2. `memory_pool_npu.py`: extract `_kv_local_offset` / `_create_buffers` hooks so the subclass can reorder the layer layout without duplicating every indexing site.
3. `kv_cache_configurator.py`: select the layer-split pool for NPU DSA.
4. `mem_cache/dsa_cache_layer_split.py`: use `current_platform.synchronize`; broadcast via global ranks + device group (HCCL fallback when the CP group is not a subgroup).
5. Disaggregation: `conn.py` applies the MLA layer remap for PP=1 when KV pointer counts mismatch (otherwise per-rank layers overwrite each other); `prefill.py` obtains the transfer span via `get_kv_transfer_layer_span` (NPU pool entries != layer count).
6. `model_hook.py`: allow the `ascend` transfer backend.
