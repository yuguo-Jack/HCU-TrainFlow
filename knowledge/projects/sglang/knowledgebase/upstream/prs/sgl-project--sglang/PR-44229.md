# [Fix] speculative: add pp_proxy_tensors to frozen_kv_mtp and UNO spec-v2 workers

[Upstream PR](https://github.com/sgl-project/sglang/pull/44229) · state: closed · merged: False

## Original PR description

## Background

The scheduler's non-overlap speculative path always passes `pp_proxy_tensors` to the spec worker (`srt/managers/scheduler.py` lines 4514 and 4527), but several spec-v2 workers have diverged on this signature.

Audit of `python/sglang/srt/speculative/` on main:

| Worker | `pp_proxy_tensors` |
|---|---|
| eagle_worker_v2.py | ✅ |
| dflash_worker_v2.py | ✅ |
| ngram_worker.py | ✅ |
| dspark_worker_v2.py | ✅ |
| multi_layer_eagle_worker_v2.py | ✅ |
| frozen_kv_mtp_worker_v2.py | ❌ (this PR) |
| uno_worker_v2.py | ❌ (this PR) |

## Problem

Any model served through FrozenKVMTPWorkerV2 or UnoWorkerV2 dies on the first scheduler step with:

```
TypeError: <Worker>.forward_batch_generation() got an unexpected keyword argument 'pp_proxy_tensors'
```

## Solution

Add `pp_proxy_tensors=None` (and forward it to target_worker) to both workers. The parameter is optional so all existing callers remain unaffected. This makes the interface consistent across all spec-v2 workers.

## Testing

- Python syntax verified with ast.parse on both edited files.
- Signature change is purely additive (`pp_proxy_tensors=None`).

Resolves #40155
