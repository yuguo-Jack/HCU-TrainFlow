## Motivation

Inkling's short convolution can run between output reduction and residual addition, including work deferred to the next layer. Decoder and MTP execution need to preserve that ordering, convolution state and graph handoffs through the layer-boundary API.

## Modifications

Use frozen `msgspec.Struct` containers for short-convolution declarations and invocations, and read the declared `ForwardBatch.positions` field directly when no explicit positions are supplied.

Declare short-convolution reads, producer updates and custom sum completion for decoder and MTP layers. Bind positions and convolution state per invocation, materialize outstanding producer work before replay handoffs, and choose unpadded execution from the declared FFN row layout. Preserve the terminal add/norm ordering and non-consuming DFLASH taps.

| Operation | Implementation |
|---|---|
| Full-width / scattered output sum | `_inkling_sum` and the declared completion |
| Fused sum + short convolution + read | `_inkling_fused_read` |
| Invocation state and short-convolution update | `layer_boundary/residual/short_conv.py` |
| Final read and MTP exit | Model final-read adapter and residual batch lifecycle |

## Accuracy Tests

- Independent Inkling boundary CPU suite: 381 passed, 7,306 subtests. The Inkling patch is unchanged; it now builds on the corrected reader callback binding.
- CPU coverage includes replay, terminal reads, custom sums, invocation cleanup, MTP/LoRA/group selection and strided convolution state; final-stack results are recorded below.
- Earlier B200/H200/GB300 synthetic-model comparisons cover full-width and scattered execution, eager/decode/breakable graphs, shared experts and draft/tap paths. The latest GB300 TP4 comparisons had matching discrete outputs and small floating differences at the A/A noise level. These are prior runs, not new GPU runs for this restack.

## Speed Tests and Profiling

Formal performance acceptance is still open. Earlier host profiling showed about 20% more Python calls; small-sample timings do not establish no regression. Full-weight accuracy and non-CUDA hardware validation are not claimed.

The existing a2a configuration without `--disable-attn-tp-gather` remains an unresolved correctness limitation; this PR does not claim that combination is supported.

## Current Stack Validation

All three updated adapter commits passed pre-commit independently; the two K3 commits are unchanged. The final stack CPU suite passed **481 tests and 7,409 subtests**, with **21 hardware-specific skips**. Independent common-layer and Inkling boundary suites passed **372 tests / 7,315 subtests** and **386 tests / 7,329 subtests**, respectively.

Four new regressions fail on the prior implementation and pass with the fixes. They cover terminal export releasing state retained by an old output handle (including a failing final norm), terminal reader binding for written/pending/fused output with two contexts, rejection and cleanup when binding changes read capabilities, and rejection of bindable update results on both immediate and deferred exit paths. Existing tests cover the converted containers, short-convolution positions and stateless V4 terminal reads.

The earlier callback-selection, transformed-reader and row-transport context regressions remain covered. No GPU tests or formal performance benchmarks were rerun for these fixes; prior GPU evidence retains its stated limitations.

## Landing

Rebased onto main `e1f9fce7b3` for merge. Validation above predates this rebase; no tests or benchmarks were rerun as part of landing.
