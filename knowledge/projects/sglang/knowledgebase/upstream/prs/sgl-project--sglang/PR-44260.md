# [Fix] flux: use true_cfg_scale as the FLUX CFG weight

[Upstream PR](https://github.com/sgl-project/sglang/pull/44260) · state: open · merged: False

## Original PR description

## Motivation

Native FLUX turns on true CFG when `true_cfg_scale` is set with a negative prompt, but then combines the two branches with `guidance_scale`. A request with `true_cfg_scale=4` and the default `guidance_scale=3.5` therefore runs CFG at 3.5, unlike diffusers `FluxPipeline`, where `true_cfg_scale` is the CFG weight and `guidance_scale` only feeds the distilled guidance embedding.

## Modifications

`FluxPipelineConfig.get_classifier_free_guidance_scale` returns `true_cfg_scale` when it is set, the same override Qwen-Image already has. Without `true_cfg_scale`, the weight is still `guidance_scale`, so requests that do not set it are unchanged. FLUX.2 inherits the override.

Docs: the FLUX cookbook gains a "Negative prompts (true CFG)" section (which flag sets the CFG weight, an example, and the over-exposure seen at higher weights), and the `--true-cfg-scale` help now names FLUX.1.

## Accuracy Tests

Unit: `test_flux_true_cfg_scale.py` (new), `test_cfg_policy.py`, `test_cfg_gating.py`: 14 passed.

Against diffusers `FluxPipeline` on FLUX.1-dev (B200, seed 42, four prompts, guidance 3.5, BF16, both uncached), median over prompts:

| Setting | `main` vs diffusers | this PR vs diffusers |
| --- | --- | --- |
| 1024x1024, 50 steps, no true CFG | 25.04 dB / LPIPS 0.076 | identical to `main` |
| 512x512, 20 steps, no true CFG | 29.94 dB / LPIPS 0.020 | identical to `main` |
| 512x512, 20 steps, `true_cfg_scale=4` | 19.92 dB / LPIPS 0.165 | 26.67 dB / LPIPS 0.064 |
| 512x512, 50 steps, `true_cfg_scale=4` | 8.89 dB / LPIPS 0.589 | 17.53 dB / LPIPS 0.218 |

At 50 steps the strongly guided trajectory amplifies small numerical differences, so a gap to diffusers remains.

Note: true CFG 4 on top of FLUX.1-dev's distilled guidance (3.5) over-exposes images in diffusers as well (about 41-43% of pixels clipped to 0 or 255, up to 82% on a bright watercolor prompt), so that is not addressed here.

Two other differences from diffusers are left unchanged:
- the guidance embedding uses the server's `embedded_cfg_scale` (3.5 for FLUX.1), not the request's `guidance_scale`;
- a negative prompt alone enables CFG at weight `guidance_scale`, while diffusers defaults to `true_cfg_scale=1` (no CFG).

## Speed Tests and Profiling

No change in the amount of work: only the CFG combination weight changes.
