[Feat] [NPU] minimax-h3: Add Ascend NPU support for MiniMax-H3 hybrid window attention

## Motivation

MiniMax-H3's VDN hybrid window attention backend (`HYBRID_WINDOW_ATTN_H3`) was CUDA-only:

- the per-segment dense kernel was hard-wired to CUDA FlashAttention;
- the backward path used `torch.cuda` side streams for the linear readout branch;
- `NPUPlatformBase` had no mapping for `AttentionBackendEnum.HYBRID_WINDOW_ATTN_H3`, so the backend silently fell back to Torch SDPA on Ascend.

This PR enables the backend to run natively on Ascend NPU while keeping the existing CUDA behavior unchanged.

## Modifications

**`python/sglang/multimodal_gen/runtime/layers/attention/backends/hybrid_window_attn_h3.py`**
- Import `current_platform` alongside `AttentionBackendEnum`.
- In `_fa_varlen`, when `q.device.type == "npu"`, dispatch to `ascend_fa.fused_infer_attention_varlen(q, k, v, cu_q, cu_k, softmax_scale=scale)` instead of `flash_attn_varlen_func`, preserving the same varlen decomposition and honoring the optional `out` buffer via `copy_`.
- In `HybridWindowAttentionH3Impl.__init__`, select `AscendFAImpl` as the dense fallback on NPU (`current_platform.is_npu()`), and keep `FlashAttentionImpl` on other platforms.

**`python/sglang/multimodal_gen/runtime/models/dits/minimax_h3_vdn_attention.py`**
- In `_vdn_ulysses_hybrid_core`, add an NPU path that runs the softmax branch and the linear readout branch on the current stream (no CUDA side-stream contract on Ascend), while still issuing both backward a2a trips and overlapping them via `softmax_work.wait()` / `linear_work.wait()`.
- CUDA/ROCm path is unchanged: still uses `_linear_branch_stream` with `wait_stream` synchronization around the side stream.

**`python/sglang/multimodal_gen/runtime/platforms/npu.py`**
- Register `AttentionBackendEnum.HYBRID_WINDOW_ATTN_H3` in `NPUPlatformBase` and return `sglang.multimodal_gen.runtime.layers.attention.backends.hybrid_window_attn_h3.HybridWindowAttentionH3Backend`, with an info log.
