## Original PR description

# [Test] [NPU] rl: Add pause/resume scheduler idempotency and 1-NPU smoke tests

Per the RL Test Consolidation RFC (#47624), this PR lands the second feature area (pause/resume) of the NPU-side test consolidation: file ownership, coverage docstrings, and CI integration for Ascend.

**Precision scope: BF16 only.** Per the RFC's BF16 precision target, all cases in this PR plan and assert BF16 only (other dtypes — FP16/FP32/INT8/W8A8 — are explicitly out of scope for this round). The 1-NPU smoke launches the shared server with an explicit `--dtype bfloat16` (never dtype-inferred) and asserts the effective dtype via `/server_info` (`dtype == "bfloat16"` + the flag pinned in `launch_command`) in `setUpClass`, so every scenario below validates the BF16 numerics path — including the retract-recompute parity anchor. The unit tier is dtype-agnostic (mocked devices) and inherits the contract from its smoke sibling.

## What's here

**1. `test/registered/unit/managers/test_scheduler_pause_generation.py`** (extended, CPU tier — 4 new cases)

Pins the pause/continue idempotency and error contracts at scheduler level:

- double pause keeps the FIRST pause timestamp (throughput accounting must not reset the window)
- double retract stays paused without raising
- `continue_generation` without a prior pause is an idempotent no-op (no error, no phantom pause intervals)
- `continue_generation` after a pause records the interval and clears the start timestamp

**2. `test/registered/npu/rl/test_npu_pause_resume_generation.py`** (new, 1-NPU tier — 6 cases)

- **P0 BF16 precision contract**: shared instance launches with `--dtype bfloat16`; `/server_info` must echo `dtype == "bfloat16"` with the flag pinned in `launch_command` (asserted once in `setUpClass`; weights + KV cache follow the model dtype on the ascend attention backend)
- pause freezes the stream: chunk count frozen across a sampling window under `in_place` pause; continue completes with a proper `finish_reason`
- double pause / continue-without-pause / double continue are all idempotent end-to-end (HTTP 200) and the engine keeps serving
- abort-mode contract: `mode="abort"` is a first-class tokenizer-level abort-all (HTTP 200, engine stays healthy)
- late requests queue during pause (zero chunks while paused; served after continue)
- retract parity: pausing mid-stream with `retract` and continuing reproduces the greedy BF16 baseline exactly
- `flush_cache` during a retract pause is legal (idle while paused) and generation continues normally

Both files carry coverage docstrings per the RFC, including the observed HTTP-boundary semantics of `abort` (handled in the tokenizer manager, never dispatched to the scheduler) and a documented robustness gap: unknown non-abort modes are dispatched to the scheduler and hit the scheduler-side assert in the event loop.

## CI registration

## Validation

Validated on Ascend 910 (openEuler 22.03, CANN 9.1.0, torch 2.10 + torch_npu, Qwen3-0.6B, TP=1, `--dtype bfloat16`):
- unit: 35 passed (31 existing on current main + 4 new consolidation cases)
- 1-NPU smoke: 6 passed (BF16 contract asserted at startup; freeze/drain/retract-parity anchors all hold under BF16)

Environment knobs: `RL_FEAT_MODEL_PATH` (model override, defaults to `LLAMA_3_2_1B_INSTRUCT_WEIGHTS_PATH`) and `RL_FEAT_NPU_ID` (die selection, default "0").
