## Motivation

Eviction for an allocation took each component's shortfall: callers read a component's capacity, subtracted it from what they meant to take, and the cache added the same read back to recover a target; under unified memory the cache then turned those targets into one demand for the allocator. Allocation demands also had several shapes: the owner's tokens plus the target window's (`swa_tokens`), with further windows charged the owner's tokens unless a side map named them, so a window a caller forgot was silently charged a default.

## Modifications

- `mem_cache/base_prefix_cache.py`, `unified_radix_cache.py`, `pure_swa_radix_cache.py`: `evict_for_alloc(demand)` takes what the allocation will take. Pools sharing memory reclaim the whole demand at once (`ChainAllocator.reclaim_for_demand`, replacing `reclaim_to_availability`); pools of their own evict each component's shortfall, computed in the cache. The joint walk an allocator drives while reclaiming is its own method, `evict_until(params, satisfied)`.
- `EvictParams` (what to evict) and the new `AllocDemand` (what an allocation takes) are separate types; both and `EvictResult` keep every window in one map by component id (`window_num_tokens`); `swa_num_tokens` and `swa_num_tokens_evicted` are removed. The all-SWA cache names its one pool as the window (`all_windows`).
- `mem_cache/allocator/base.py`: `TokenDemand` (owner tokens, every window's tokens by window pool, state slots) is the one shape of `prealloc_fits`, `prealloc_ceiling_fits`, `reclaim_for_prealloc`, `reclaim_for_load_back`, `ensure_capacity`, `page_demands` and `scoped_physical_takes`, for the chain and static pools alike; a demand that omits a window the allocator keeps, or names one it does not, is an error.
- `disaggregation/decode.py`: every preallocation demand is built by one helper (`_prealloc_demand`); with tail preallocation each window takes the tail it keeps; `ChainAllocator.alloc_extend_swa_tail` and `KVStorage.take_extend` take one map naming every window's tail.
- Callers updated: token and window allocators, state-slot checks, host-load and device-alloc evictors, buffer pipeline, load-back, decode radix eviction, linker loads.
- The int8 state checkpoint slot: a full checkpoint pool evicts one cached state by count, since no allocation demand reads that pool.
- Tests: `python/sglang/test/token_demand.py` (test helper keeping the two-number form explicit), a full checkpoint pool with free active slots evicts a cached checkpoint and takes its slot, the default cache evicts a demand's shortfall, a window demand on the all-SWA cache evicts from its single pool, plus updates across unified allocator and radix-cache tests.

No intended behavior change apart from the int8 checkpoint slot case above; this is an internal API change of the prefix caches and allocators.
