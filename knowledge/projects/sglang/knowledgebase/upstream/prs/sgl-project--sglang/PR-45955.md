# [CI] [NPU] precise-test: recommend multimodal_gen cases at test-case granularity

[Upstream PR](https://github.com/sgl-project/sglang/pull/45955) · state: closed · merged: True

## Original PR description

## Motivation

Follow-up to #45553 (per-case coverage collection for multimodal_gen) and #45571 (bucket skip-all rule). The NPU precise-test pipeline can now collect coverage for diffusion cases, but the recommendation side has no notion of diffusion suites yet: every PR runs the full multimodal suites even when the baseline knows which cases are affected.

This PR makes the bucket side case-aware for `multimodal-gen-test-1-npu-a3` / `multimodal-gen-test-4-npu-a3`. It only emits outputs and the report; the multimodal jobs do not consume them yet (a follow-up wires their `if` gate and `-k` filter).

## Modifications

- `bucket_recommended_tests.py`
  - New `--diffusion-suites job:suite,...` and `--case-map test_case_map.json`.
  - Enumerate the NPU diffusion suites from `testcase_configs_npu.py` with AST only (no torch): `PARAMETRIZED_CASE_GROUPS` + `STANDALONE_FILES`, including suites that only have standalone files.
  - Match recommendations at case granularity: a file-level entry expands to every case of that file, a case-level entry selects one case, and a standalone file is selected as a whole file.
  - Emit `only_tests_<key>` as pytest `-k` tokens (`[case_id]` / standalone module stem), so a shard can run a precise subset.
  - Safety gate: force a diffusion suite to run in full when the baseline has no multimodal keys, or when any of that suite's cases/standalone files is missing from the map. A newly added case has no map key by definition, so no PR could ever recommend it until the baseline is rebuilt. A forced suite also ignores the skip-all rule: "the baseline cannot judge it" is not the same as "nothing is affected".
  - Warn when a standalone `-k` token is ambiguous (same stem in two files, or a stem that is a substring of a case id).
  - Report/summary: diffusion rows plus a "Full suite forced — baseline gaps" section.
- `pr-test-npu.yml`
  - Expose `should_run_*` / `only_tests_*` for both multimodal jobs.
  - Add the diffusion case config to the recommend job's sparse checkout and pass the new arguments.
- `test_selector.py`
  - Detect new/modified/deleted test files under `python/sglang/multimodal_gen/test/`.

## Notes

- No production code or platform-shared `multimodal_gen` test framework is modified; all NPU-specific logic lives in `scripts/ci/npu/precise-test/`.
- Base suites keep their existing precision semantics. Multimodal recommendations now count toward the global precision switch, so a multimodal-only PR can skip base suites whose buckets are empty (expected).
- The two multimodal jobs still run in full until the follow-up wires the outputs, so this PR is safe to merge on its own.

## Verification

- `ruff format --check`, `ruff check`, `isort --check` pass.
- Local scenario runs of `bucket_recommended_tests.py`:
  - case-level and standalone recommendations produce the expected tokens;
  - a file-level recommendation expands to all cases of that suite;
  - a missing baseline key forces the suite to full and appears in the report;
  - skip-all with no forced suite skips everything; with a forced suite it does not.
