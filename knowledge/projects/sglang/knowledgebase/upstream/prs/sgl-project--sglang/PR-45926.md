# [Fix] hicache: Fall back on unresolvable cgroup memory paths

[Upstream PR](https://github.com/sgl-project/sglang/pull/45926) · state: closed · merged: False

## Original PR description

## Why?

- HiCache host pools fail to start when the process's cgroup membership sits above the cgroup mount root.
- A common case: a Slurm `srun --overlap` step that joins another step's container. `/proc/self/cgroup` shows `0::/../../../step_147/user/task_0`.
- `_cgroup_memory_headroom` raises `ValueError` in that case. `available_host_memory_bytes` only catches `OSError` and `RuntimeError`.
- So even an explicit `--hicache-size` crashes at host-pool allocation. It should instead take the documented fallback, which checks explicitly sized pools against host available memory.

## What?

- `_cgroup_memory_headroom` raises `RuntimeError` for an unresolvable membership path. This matches the neighbouring "cannot locate the process memory cgroup" case.
- Explicit sizing now falls back to host available memory, with the existing warning.
- Auto-sizing keeps its strict behavior and still asks for `--hicache-size`.

## Verification?

Production code only, inside a real `srun --overlap --container-name=...` step on an H200 node (observed):

```text
/proc/self/cgroup: 0::/../../../step_147/user/task_0

host_memory_budget_bytes(auto_size=...)
                      Before (main)                     After (this PR)
auto_size=False  ->   ValueError: Cannot resolve        1903.9 GiB (host fallback,
                      cgroup memory path                warning logged)
auto_size=True   ->   ValueError: Cannot resolve        RuntimeError: ... set
                      cgroup memory path                --hicache-size explicitly
```

Repro: inside such a step, call `sglang.srt.mem_cache.pool_host.base.host_memory_budget_bytes(auto_size=False)`. Or launch any server with `--enable-hierarchical-cache --hicache-size <N>`.
