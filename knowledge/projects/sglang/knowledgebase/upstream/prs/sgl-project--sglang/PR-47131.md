# [Refactor] cuda-graph: Register DSpark verify epilogue buffers as declared graph buffers

[Upstream PR](https://github.com/sgl-project/sglang/pull/47131) · state: open · merged: False

## Original PR description

## Motivation

CUDA graphs replay per-step decisions through buffers they captured by address. `CudaGraphBufferRegistry` gives the `ForwardBatch`-mirrored inputs a declared padding policy and stable pointers, but backend-private and spec buffers live outside it. They are allocated, refreshed and tail-cleared by hand, and most graph-capture memory faults in the speculative path fall into three groups:
- values in regions no request owns that were never made valid;
- fill logic that assumes the wrong geometry;
- correct values read from a rebound tensor or at the wrong time.

This PR extends the registry to non-batch buffers and ships the extension together with its first consumer, the DSpark verify epilogue.

## Modifications

**Registry (`cuda_graph_buffer_registry.py`)**
- `GraphBuffer` is a graph-read buffer that mirrors no `ForwardBatch` field. Every buffer must declare a capture value, a padding policy (`ZERO`, `FILL_SENTINEL`, or `KEEP_PAD`) and a `RefreshMode`; none has a default.
  - `STATIC`: never written after it is seeded.
  - `BEFORE_REPLAY`: staged by the host via `stage` / `stage_fill`, never while capturing.
  - `IN_GRAPH`: written only by device work.
- `register_buffer(spec, owner=...)` allocates the buffer seeded with its capture value and binds it to `owner.<name>`. Registering a buffer during graph capture raises.
- `stage(name, src)` and `stage_fill(name, value, num_rows)` write the leading rows and pad the rest according to the buffer's policy. A repeat of the buffer's last fill writes nothing. Staging a non-`BEFORE_REPLAY` buffer raises, and so does staging while capturing. Capture detection is device-agnostic (`is_device_stream_capturing`).
- `prepare_capture()` reseeds the host-owned buffers to their capture values before a capture. It leaves `IN_GRAPH` buffers alone, so a recapture cannot wipe values a graph produced.
- `check_pointers()` raises if an owner rebound a registered attribute; captured graphs would otherwise keep reading the old tensor.

**Wiring**
- `ModelRunner.graph_buffer_registries` is a plain list, like the existing capture hook lists.
- `DecodeCudaGraphRunner` calls `prepare_capture()` before capturing and `check_pointers()` before each replay.
- The DSpark sampling-accept region also calls `check_pointers()` before it replays.

**First consumer: `DsparkVerifyEpilogue`**
- All of its graph-read buffers are now registered:
  - `BEFORE_REPLAY`: verify lens, inject gate, simulated-bonus temperatures and seed.
  - `IN_GRAPH`: draft tokens, accept outputs, gated commit lens, block accept lens, and the lazily created strided logits / hidden.
- Host writes go through the registry, so the epilogue's hand-rolled staging caches are removed.
- The strided outputs now raise on a width or dtype change. The old code silently reallocated, while already-captured graphs kept writing the old buffer.
- The sampling-accept region's gate is a `STATIC` buffer.

**Ratchet**
- `test_graph_buffer_allocation_ratchet.py` counts hand-made `self.<attr> = torch.<alloc>(...)` buffers under `layers/attention`, `speculative` and `model_executor/runner`. The frozen counts may only go down; new graph-read buffers should register through the registry.

Not in this PR: backend-private buffers (DSA ragged verify buffers are the intended next consumer), and host-to-device pinned staging, which will be added together with its first caller.

## Accuracy Tests

DeepSeek-V4.1-Flash with DSpark on 4×B300, using the cookbook B300 low-latency flags (`--tp 4 --ep-size 4 --mem-fraction-static 0.8 --speculative-algorithm DSPARK --speculative-dspark-block-size 5 --cuda-graph-max-bs-decode 64`).
- Two arms: main and this PR, with identical model, flags and environment.
- Two environments:
  - `default`: the static greedy epilogue fold.
  - `opt`: additionally enables the opt-in epilogue features. The env vars are `SGLANG_DSPARK_FUSED_ACCEPT_TAIL`, `SGLANG_DSPARK_DEFER_CONTEXT_KV`, `SGLANG_OPT_DSV41_DSPARK_POST_FOLD`, `SGLANG_OPT_DSV41_POST_FORWARD_CUDA_GRAPH`, `SGLANG_OPT_DSV41_SAMPLING_ACCEPT_GRAPH`, `SGLANG_OPT_DSV41_TARGET_METADATA_EARLY`, `SGLANG_OPT_DSV41_TARGET_VERIFY_METADATA_GLUE`, `SGLANG_OPT_DSV41_BLOCKWISE_REJECTION`, plus related prep options.
- Eval: sgl-eval GSM8K, 200 examples, 32 concurrent, thinking off. Greedy is T=0; sampled is T=1.0, top_p=1.0, since the sampling-accept region excludes top-p.

| arm / env | greedy | sampled | mean accept length |
|---|---|---|---|
| main / default | 98.0% | 98.0% | 3.77 |
| PR / default | 97.5% | 97.5% | 3.88 |
| main / opt | 98.0% | 97.5% | 3.78 |
| PR / opt | 98.0% | 99.0% | 3.72 |

One example is 0.5 pt, so all differences are within noise.
- Every logged decode batch replayed a CUDA graph, with up to 32 running requests.
- In `opt`, both arms captured the fused accept tail for every verify batch size.
- The sampling-accept region captured with no failures.

Qwen3-14B + DSpark in compact verify mode, which builds the epilogue: `test/registered/core/test_basic_sanity_dspark.py` gives 29 passed, 1 skipped.

Unit tests:
