# [Fix] hicache: Budget deduplicated host pools by physical ownership

[Upstream PR](https://github.com/sgl-project/sglang/pull/44540) · state: open · merged: False

## Original PR description

## Motivation

With the MLA/DSA host dedup integration in #44536, only the source rank allocates the target host payload. The per-rank split introduced by #35540 still gives that source only 1/8 of the usable host memory on TP8, rejecting valid explicit cache sizes and unnecessarily reducing the automatically selected ratio.

**Dependency:** this draft is stacked on #44536 at `261559ba6b6d2d58ef65a19173ddd565e5dd052e`. The fix is the final commit, `5dd2784eb5eb0e54b49e1294f529242364b22fa7` ([fix-only diff](https://github.com/HZY-Wade/sglang/compare/261559ba6b6d2d58ef65a19173ddd565e5dd052e...5dd2784eb5eb0e54b49e1294f529242364b22fa7)). The preceding integration commit is unchanged. Merge the dependency first; this PR must then be rebased if that dependency is squash-merged.

## Modifications

- Use the same dedup eligibility gate for sizing and pool construction.
- Before constructing pools, gather each rank's physical host-mirror byte estimate and available headroom. Distribute each host's budget by those estimates, using the minimum headroom reported by its co-located ranks. The collective occurs once before pool construction, where different PP pool counts cannot change its ordering.
- Count target MLA/DSA payload only on source ranks while retaining draft sidecars on every rank. Multiple dedup groups and PP stages share their host budget; hosts containing only dummy peers need no target payload budget.
- Apply the resulting budget scope to both explicit sizes and automatic sizing. MLA KV, DSA indexer and draft allocations book the same snapshot. Keep the cgroup limit, 10 GiB reserve and cumulative allocation checks. With dedup disabled, retain the existing per-rank split.
- Cover the old 1/8 restriction, source/dummy ownership, rank-local drafts, multiple groups, cross-node placement, automatic sizing, cumulative MLA/DSA checks, inactive dedup and large NumPy byte counts.

## Accuracy Tests

- **36 passed, 18 subtests passed** across host-budget, auto-size, dedup primitive and integration tests. Two existing tests that resolve the platform's default MPS configuration were deselected locally because Torch 2.11 does not meet that path's Torch >= 2.13 requirement.
- Replacing only the sizing function with its pre-fix version reproduces both regression failures: source budget `1000` instead of `8000`, and automatic ratio `0.1979167` instead of `1.5833333`.
- A standalone **four-process Gloo** check passed five ownership/placement cases and verified that real collectives synchronize the auto-size ratio across source and dummy ranks. Multi-host placement was simulated on one host; no GPU/NCCL or model-accuracy run was performed.
