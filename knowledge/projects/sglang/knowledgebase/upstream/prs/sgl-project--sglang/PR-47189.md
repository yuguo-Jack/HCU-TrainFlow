# [Fix][CPU] Handle unaligned GPTQ INT4 output widths

[Upstream PR](https://github.com/sgl-project/sglang/pull/47189) · state: open · merged: False

## Original PR description

## Motivation

The CPU AMX INT4 prepacking path requires output channels to be aligned to 32. With TP=3, some GPTQ linear layers can have a local output width of 24, causing weight prepacking to fail during server startup.

## Modifications

- Pad GPTQ weights, zero points, scales, and bias to the next 32-channel boundary before AMX INT4 processing.
- Slice the output back to the original logical width after GEMM.
- Add regression coverage for aligned and unaligned output widths, multiple input shapes and dtypes, and optional bias.

## Accuracy Tests
