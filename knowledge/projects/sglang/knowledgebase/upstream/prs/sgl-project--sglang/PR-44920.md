# [Perf] DSv4.1: Reduce BCG metadata memory

[Upstream PR](https://github.com/sgl-project/sglang/pull/44920) · state: closed · merged: True

## Original PR description

[codex/claude generated]

## Motivation

With encoder bounded replay disabled, DSv4.1 breakable prefill graphs retain oversized page tables and duplicate index buffers across capture buckets and compression ratios.

## Modifications

- Bound low-ratio BCG page-table width by the existing prefill graph context limit in both capture and metadata refresh. Eager context support and graph admission limits stay unchanged.
- Reuse full-metadata index storage across serial capture buckets, keeping c1/c2, raw/page, and full/tail buffers independent and retaining old allocations when capacity grows.
- Share fully overwritten per-layer combined-index scratch between c1/c2 within a prefill chunk. Keep cached c0/c128 outputs separate.

## Accuracy Tests

On main `4eb606b2a`, validation passed 56 existing CPU tests and 60 subtests, plus two local buffer-ownership probes that are not included in this PR. GB300 probes passed byte-exact ragged combined mappings, ratio switches, separate c0/c128 storage, cross-bucket aliases, old-address stability on growth, full/tail isolation, and graph replay with refreshed inputs. Selected Ruff lint checks passed.

On the measured base `4fc86f73c`, two independent GB300 runs passed byte-exact metadata/replay probes and model/cache smoke tests, including 16,384/16,640-token contexts followed by short requests. Each capture-size run recorded 52 responses plus 8 cache-prime requests. Output token IDs and usage/cache statistics matched across repeats. Logprobs showed small run-to-run differences; this is not a full model-accuracy evaluation or a bitwise floating-point equivalence claim.

## Speed Tests and Profiling

Local memory measurements on `4fc86f73c`, 4×GB300, DEP4, decoder bounded replay, FlashMLA mega attention, native DSPARK block size 5, static memory fraction 0.7 and chunk size 8192. Encoder bounded replay is OFF.

| Maximum prefill capture tokens | Baseline | This patch | Repeated result |
|---|---:|---:|---:|
| 8192 | 16.18 GiB/GPU | 12.24 GiB/GPU | 12.24 GiB/GPU |
| 2048 | 6.77 GiB/GPU | 5.10 GiB/GPU | 5.10 GiB/GPU |

These are prefill capture-end memory increments, not whole-server memory. Startup reserved-memory peaks decreased only slightly. The combined-index change improves the 8K result but adds 0.07 GiB at 2K compared with the first two changes alone (5.03 GiB). No throughput claim; memory measurements have not been repeated on the rebased main revision. No allocator-policy toggles are included.
