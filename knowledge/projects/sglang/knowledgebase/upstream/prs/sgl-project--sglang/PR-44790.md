# [Doc] hicache: Explain HiCache host pool sizing with a storage backend

[Upstream PR](https://github.com/sgl-project/sglang/pull/44790) · state: closed · merged: True

## Original PR description

Refs #38452

## Motivation

#38452 reports that a prompt cached to the storage backend is not loaded back after cache pressure, but is loaded after `/flush_cache`. Reproducing the issue's configuration on main (Qwen3-1.7B, `--max-total-tokens 20000 --hicache-size 2`, `file` backend) shows that the storage lookup works and finds the prompt. The hit is then dropped as `host_capacity`, because the host pool has no free room to stage it.

Under `write_through`, every token cached on the GPU keeps a host copy, and host eviction only frees entries no longer on the GPU. `--hicache-size 2` gives a 17,439-token host pool for a 20,000-token GPU pool. Once the GPU pool is full, every host page holds a copy of GPU-resident KV, so no storage hit can be staged.

| Host pool flag | Host vs GPU pool (tokens) | Found in storage | Dropped as `host_capacity` | Cached on re-send |
|---|---|---|---|---|
| `--hicache-size 2` (issue config) | 17,439 < 20,000 | 338 | 338 | **0** |
| `--hicache-ratio 1.1` instead of `--hicache-size` | 22,001 > 20,000 | 338 | 0 | **338** |
| `--hicache-size 4` | 34,878 > 20,000 | 338 | 0 | **338** |

The existing startup warning ("L2 cache effectiveness is reduced") fires for this configuration, but it does not say that storage hits will be dropped. The docs do not explain the sizing rule either. `--hicache-size` is given in gigabytes while the GPU pool is reported in tokens, so the comparison is easy to miss.

## Modifications

Add a "Host Pool Sizing" subsection to `docs/docs/advanced_features/hicache_best_practices.mdx`, under "Key Configurations with Storage Backends Enabled", in the same flag-block-plus-guidelines format as the other subsections. It covers:

- The two host pool flags, and that `--hicache-size` is in GB and overrides `--hicache-ratio`.
- Why storage hits need free host room, and why `write_through` leaves at most the host pool minus the GPU pool for them.
- The symptom of an undersized host pool, and the metric that shows it.
- Checking both pool sizes in tokens from the startup log when using `--hicache-size`.

Docs only. No code changes.
