# [Feat] unified-memory: Evict Full and SWA KV from one shared LRU order (joint_lru)

[Upstream PR](https://github.com/sgl-project/sglang/pull/46827) · state: closed · merged: True

## Original PR description

## Motivation

With `--enable-unified-memory`, a full/SWA hybrid model keeps its full-attention and sliding-window KV in one shared byte buffer. Allocation-time reclamation evicts each component against its own quota from the reclaim plan, so under pressure one side can be drained while the other still holds entries that were used far less recently.

This PR adds an opt-in `--radix-eviction-policy joint_lru` that evicts both kinds of KV by one shared access-time order on the unified radix cache: each step takes whichever Full leaf or SWA entry was used least recently. Everywhere else the value behaves as `lru`, and every other policy keeps today's behavior.

## Modifications

- **Opt-in policy.** `joint_lru` is a new `--radix-eviction-policy` value. `uses_joint_lru(params, component_types)` (`unified_tree_core_interface.py`) decides at construction whether a tree keeps the joint order: the policy is `joint_lru`, the cache is enabled, the tree has an SWA component, and its allocator is the two-ended `ChainAllocator` (an owner and a window band, no state slots). The Python tree core and `UnifiedRadixCache.evicts_by_joint_lru` share this one test.
- **SWA access times.** A tree that keeps the joint order records an access time per device SWA value in a `JointLRU` table keyed by node id, from the same counter that stamps Full's `last_access_time`, so the two compare. The SWA window refresh stamps the nodes it re-ranks in the same walk (deepest newest); storing or restoring a device SWA value counts as an access; a split's prefix inherits the time; the time goes when the device SWA value goes (SWA eviction, Full cascade, node removal, `reset()`).
- **The joint walk.** `start_joint_eviction`, `next_joint_eviction_victim` and `end_joint_eviction` build one min-heap of the Full device leaves and the SWA LRU entries keyed by (access time, component, rank) and pop the oldest still-eligible entry. A Full parent joins the heap once it becomes a leaf; entries a cascade already freed are skipped. An SWA victim evicts through the SWA component's own walk, a Full victim through the existing leaf eviction (backup, demote, cascade).
- **One evict entry.** `UnifiedRadixCache.evict` runs the joint walk when the tree keeps the joint order, the call passes no per-component targets, and the allocator's `compaction_can_run()` reports that bytes freed on one side can serve the other. The requested quotas become one shared-byte target (`shared_bytes`); the walk stops when the freed bytes reach it, when `allocation_reclaim_satisfied` holds, or when no victim is left. Otherwise `evict` runs the per-component walks as before.
- **Per-walk SWA leaf collapse.** The SWA walk takes `collapse_leaves` (default on). The joint walk turns it off so an SWA victim never takes its leaf's Full with it; the next per-component walk collapses leaves as before. The shared eviction helpers read the walking component's `collapses_leaves()`.
- **Split recency under `joint_lru`.** A split does not access the suffix, so the suffix keeps its Full access time whichever path splits it (match or insert). Other policies keep the current behavior, which counts the suffix as just accessed.
- **Construction-time rejections.** The interface declares `supports_joint_eviction` (false by default, true on the Python tree core). `UnifiedRadixCache.__init__` raises `ValueError` for `joint_lru` on a tree core without the walk, such as the `rust` core, instead of failing at the first eviction under memory pressure, and for `joint_lru` with `--enable-session-radix-cache`.
- **`joint_lru` accepted where `lru` was matched exactly:** the eviction-strategy factory (each component's own order stays LRU), the waiting-prefix refresh in `schedule_policy.py`, and the Rust tree-core adapter, which keeps no joint order and passes `lru` to its binding.
- **Docs.** The `--radix-eviction-policy` help text and the eviction-policy docs page describe `joint_lru`.

Interfaces kept: `reclaim_plan`, `evict_to_free_tokens` and `can_reserve` are unchanged; `EvictParams` keeps its per-component quotas and the joint walk reads only their total bytes; the tree-core interface only gains the joint-walk methods and `supports_joint_eviction`.

Unit tests added in `test/registered/unit/mem_cache/test_multi_ended_allocator.py` (`TestJointLRUEviction`, base-b, 1-gpu-small): the cross-component victim order follows access time; the joint walk strips leaf SWA while the next per-component walk collapses the leaf; the dispatch needs `joint_lru` and unblocked compaction; window refreshes stamp SWA times even while compaction is blocked; SWA access times follow the device SWA values through split, cascade, restore and reset; a prefix access keeps the suffix's recency only under `joint_lru`; and the two construction-time rejections. `test_unified_radix_allocation_eviction.py` sets the new `evicts_by_joint_lru` flag on its mocked cache.
