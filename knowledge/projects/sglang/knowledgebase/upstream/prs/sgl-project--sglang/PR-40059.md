# [NPU] Coordinate asynchronous graph replay and parameter updates

[Upstream PR](https://github.com/sgl-project/sglang/pull/40059) · state: closed · merged: False

## Original PR description

## Status update — no longer required for the Qwen3-ASR repair

The Qwen3-ASR repair in https://github.com/sgl-project/sglang-omni/pull/2160 now works without this PR. Omni head `6e039a04` removes the shared submission helper dependency and owns encoder graph updates and cached H2D transfers locally.

With **unmodified SGLang v0.5.19 at `0bcd822377da7b5718e674eaf9c870d349424dd1`**, the operator reports **20/20 independent cold conc8/140 rounds, 2800/2800 successful requests**, WER 0.011373 in every round, zero reference disagreement, zero observed decode graph=False batches and normal cleanup after every round. These results qualify the Omni-only candidate, **not this SGLang PR**.

This PR remains an experimental draft for reference/review; it is not a prerequisite for the ASR fix and is not being proposed for merge based on those results. No code, merge or closure action accompanies this metadata update.

## Experimental change

Coordinate asynchronous NPU graph replay and parameter updates using a shared Host submission context around wait_stream → replay → update. Decoder replay/update run on the caller thread, with the dependency inserted before replay. No device-wide synchronization is added.

The implementation is inspired by vllm-project/vllm-ascend#12944 and #13600, but should not be equated with upstream vLLM behavior.

## Historical evidence and limitations

The earlier experimental pair (SGLang `b950878e`, Omni `7dbecfc5`) had six operator-reported passing cold conc8/140 rounds after adding private encoder update streams and encoder-owned cached transfers. Shared-stream async submission and stream isolation alone had previously stalled. Those combined results did not isolate the necessity of this SGLang change.

The subsequent stock-SGLang validation removes that necessity for the tested ASR workload. It does not establish whether this experimental submission policy benefits other models or workloads, or resolve all error-path/private-API/CI review concerns.

See the Omni PR for the maintained fix and current evidence boundaries.
