# [Feat] beam: support LoRA for BF16 and FP8

[Upstream PR](https://github.com/sgl-project/sglang/pull/48264) · state: open · merged: False

## Original PR description

## Motivation

Enable Beam LoRA serving for BF16 and compressed-tensors FP8 checkpoints with the `csgmv`/`triton` LoRA backends and the `auto`/`triton` MoE runner.

## Modifications

- Preserve `self_attn.gate_proj` as an explicit attention target; bare `gate_proj` continues to target MLP/MoE projections. Qualified attention-gate discovery also applies to other models exposing that module name.
- Keep Beam QKV and attention-gate projections wrappable under LoRA, and disable the deferred expert-sum path that bypasses LoRA wrappers. Retain ordinary attention collective fusion.
- Allocate hybrid-model dense LoRA buffers only on layers containing the target, respecting PP boundaries and preserving existing shared-expert allocation.
- Share compressed-tensors FP8 quant-info construction between ordinary inference and LoRA. Extend existing unit tests for normalization, allocation, Beam construction, and CHANNEL/TOKEN FP8.

## Accuracy Tests

Manual validation on the initial port, `ef6c8bcafb`, before the final allocation/test follow-up:

| Check | Result |
| --- | --- |
| Targeted CPU units on H200 with CUDA hidden | 21 passed; the four added regression cases failed on the pre-port parent |
| Tiny BF16 Beam on H200 and GB300: TP1/csgmv/static adapters and TP2/triton/graph-enabled dynamic adapters | Passed against an independent merged-weight reference; maximum KL 0.003299, below 0.005 |
| Full `reflection/Beam-1.0-501B-A23B-FP8` on GB300, TP4, Triton, dynamic rank-4 adapters | Passed loading/generation smoke; zero adapter matched base greedy tokens and all probed logprobs; nonzero `o_proj`-only and all-target adapters changed first-token logprobs |

The full-checkpoint smoke used synthetic adapters and establishes loading/serving behavior, not model quality or merged-weight FP8 equivalence. Graph capture completed; replay was not explicitly logged. The temporary tiny-model fixtures/E2E scripts are not included in this PR.

For the final follow-up, `fd9a341598`, local source-isolated CPU checks passed 8 allocation cases and 2 loading/clearing probes; the pre-fix allocator failed the intended sparse-layer regression. These checks use production method bodies with real CPU tensors and isolated import/module boundaries. Full unit collection was blocked by missing local `_lzma`/Triton dependencies; this final revision has not been rerun on GPUs.

## Speed Tests and Profiling

No throughput benchmark. Dense-buffer allocation is reduced without changing inference computation.
