# [Fix] Falcon-H1: run the Mamba2 mixer as a breakable graph break

[Upstream PR](https://github.com/sgl-project/sglang/pull/42775) · state: open · merged: False

## Original PR description

## Motivation

Fixes #42774.

With default server args every Falcon-H1 model I tried (0.5B, 1.5B, 3B, 7B Instruct) dies on the warmup request on H100 with `CUDA error: an illegal memory access was encountered`. With `CUDA_LAUNCH_BLOCKING=1` the fault is in `BreakableCUDAGraph.replay` of the prefill graph, and `--cuda-graph-backend-prefill=disabled` avoids it.

Each Falcon-H1 layer runs attention and a Mamba2 mixer side by side. The prefill graph is only skipped when some layer lacks standard GQA attention, which keeps Granite-H off it through its pure Mamba layers ("some layers do not apply Standard GQA" in its log), but Falcon-H1 passes that check. Its mixer is then captured inside a graph segment, so the chunked-scan launch and metadata stay at the capture-time batch. Nemotron-H runs its mixer through an `eager_on_graph` break under this graph, and #34561 fixed the same replay crash on its DP path by routing it there too.

## Modifications

- `falcon_h1.py`: under the prefill breakable graph, call the mixer through `_breakable_falcon_h1_mamba2_with_output`, an `eager_on_graph` break that reads the live batch and Mamba2 metadata from the prefill graph context, runs on the real token count and zeroes the padded rows. This follows Nemotron-H. Eager prefill, decode graphs and `tc_piecewise` keep the current path (same gate as Inkling: breakable and the prefill context is installed).
- `test_breakable_cuda_graph.py`: capture the break once, replay it with 3 and then 8 live tokens, and check that only the live rows are computed and the padded rows are zero. It sits next to the existing `test_qsa_indexer_uses_live_lengths`.

## Accuracy Tests

1x H100, `lmsysorg/sglang` nightly-dev-20261005 image.

Red/green, main `679d2851ba` vs this PR:

| check | main | this PR |
|---|---|---|
| `TestBreakableCUDAGraphBasic` (new case included) | 1 failed, 10 passed | 11 passed |
| `test/manual/models/test_falcon_h1_models.py` `TestFalconH1` / `TestFalconH1NoGatedRMS` server launch (0.5B / 1.5B, default args) | illegal memory access in the warmup, server never ready | prefill graph captured, server ready |

The manual tests then call `run_sgl_eval`, which needs the `sgl_eval` package that the image does not ship, so for accuracy I used `sglang.test.few_shot_gsm8k` (5-shot, 200 questions, greedy) on this PR, with the breakable prefill graph (default args) vs `--cuda-graph-backend-prefill=disabled` (the workaround on main, same code path as main there). One run per cell:

| Falcon-H1 Instruct | breakable prefill graph | prefill graph disabled |
|---|---|---|
| 0.5B | 0.750 | 0.755 |
| 1.5B | 0.770 | 0.780 |
| 3B | 0.835 | 0.840 |
| 7B | 0.855 | 0.830 |

All within run-to-run noise of 200 questions. Only TP1 was tested.

## Speed Tests and Profiling

Same servers, `sglang.bench_serving --dataset-name random-ids --random-input-len 512 --random-output-len 1 --random-range-ratio 1 --num-prompts 64 --max-concurrency 1`, mean TTFT in ms, one run each:

| Falcon-H1 Instruct | breakable prefill graph | prefill graph disabled |
|---|---|---|
| 0.5B | 44.5 | 57.9 |
| 1.5B | 40.9 | 49.7 |
| 3B | 60.8 | 78.7 |
| 7B | 103.1 | 130.7 |

So the default path is now usable and has 18-23% lower TTFT than the workaround at this size. The price is the prefill graph capture at startup, which the logs put at 55-66 s for 0.5B and 1.5B.
