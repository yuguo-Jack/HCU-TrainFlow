# [Fix] openai: strip message-level tool schemas from DSV prompts when tool_choice=none

[Upstream PR](https://github.com/sgl-project/sglang/pull/45549) · state: open · merged: False

## Original PR description

## Motivation
Follow-up to #43006. That PR made the dsv4/dsv32/dsv41 encoders honor `tool_choice="none"` for request-level tools, but the OpenAI protocol also allows `tools` on individual system/developer messages, and those schemas were still rendered into the prompt by the encoders. Since the DSML parser is disabled under `tool_choice="none"`, the model can echo raw DSML markers into `message.content`. This covers the remaining case in #35736.

## Modifications
- `serving_chat.py`: when `tool_choice == "none"`, pop message-level `tools` from the copied messages before encoding. Request-level tools were already gated upstream; the original wire request is left untouched.
- Regression test covering dsv4/dsv32/dsv41 with a developer message carrying tools, asserting the prompt contains no tool schemas and the original request is unmodified.

## Accuracy Tests
Parser-scoped fix; no change to model outputs under default settings.

```
pytest test/registered/unit/entrypoints/openai/test_serving_chat.py -k dsv_tool_choice_none
# 2 passed (includes the existing #43006 test), 9 subtests passed
```

Not applicable — prompt-construction change exercised only under `tool_choice="none"`.
