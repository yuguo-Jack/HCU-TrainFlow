# [CI] [AMD] disaggregation: Keep the NIXL e2e test on the fixture's UCX devices

[Upstream PR](https://github.com/sgl-project/sglang/pull/45674) · state: closed · merged: False

## Original PR description

## What

`test_nixl_transfer_engine_e2e.py` (AMD disaggregation stage) no longer passes `--disaggregation-ib-device` to the NIXL servers. It uses `configure_nixl_pd_backend`, like the other NIXL PD tests, so UCX keeps the fixture's `UCX_NET_DEVICES=rdma0:1,rdma4:1,lo`.

## Why

Since #43482, both NIXL servers fail in `createBackend` on every run of this stage, on rocm10 and rocm724 and on several different MI355X runners:

```
UCX  ERROR   no active messages transport to <no debug data>: self/memory - no peer failure handler,
  sysv/memory - no peer failure handler, posix/memory - no peer failure handler,
  ud_verbs/rdma0:1 - Destination is unreachable, rocm_copy/rocm_cpy - no am bcopy, ...
nixl._bindings.nixlBackendError: NIXL_ERR_BACKEND
```

Example: [job](https://github.com/sgl-project/sglang/actions/runs/39665749264/job/119461271763). The test passed on the same image earlier on Oct 21, at a main commit before #43482 ([run](https://github.com/sgl-project/sglang/actions/runs/39550230191)).

#43482 maps `--disaggregation-ib-device` to the NIXL UCX `device_list`. NIXL applies that with `config.modifyAlways("NET_DEVICES", "rdma0:1")`, which overrides the `UCX_NET_DEVICES` that the fixture sets. That drops `lo`. As the fixture comment in `_maybe_set_ucx_net_devices` notes, NIXL opens an endpoint to itself during `createBackend`, and on these RoCE NICs tcp over `lo` is the only transport that can serve it, because UD loopback on rdma0 is unreachable.

## Notes for the reviewer

This puts the test back on the exact UCX device set it used before #43482, so it still runs over rdma0/rdma4.

It doesn't change #43482's behavior for real deployments. NIXL with `--disaggregation-ib-device` on a RoCE host without UD loopback will hit the same `createBackend` failure. That is worth a separate look, for example keeping `lo` or honoring an existing `UCX_NET_DEVICES`. I left it out of this PR.

## Test plan

- [x] Disaggregation stage on this commit: `test_nixl_transfer_engine_e2e.py` passes on rocm724 ([run](https://github.com/sgl-project/sglang/actions/runs/39687286547)) and rocm10 ([run](https://github.com/sgl-project/sglang/actions/runs/39687291939)). Both runs are 3/4: `test_disaggregation_pp.py` failed with intermittent Mooncake `KVTransferError`s during KV transfer. That test runs on Mooncake, not NIXL, and showed the same failures before this change.
