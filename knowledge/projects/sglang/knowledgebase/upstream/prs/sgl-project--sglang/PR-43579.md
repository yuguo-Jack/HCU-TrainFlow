## Motivation

Follow-up to [#33089](https://github.com/sgl-project/sglang/pull/33089), which introduced sparsity-driven KV offload for Ascend DSA models. This PR adds prefill/decode (PD) disaggregation support and an optional LRU cache to retain useful KV entries across decode steps.

## Modifications

### PD disaggregation with KV offload

- **Prefill:** Keep the native KV cache in HBM and use the native attention path. Local sparse KV offload is disabled on the prefill worker, so its HBM buffers remain valid sources for PD transfer.
- **Transfer:** Reuse SGLang's Ascend PD transfer engine and metadata exchange. Register buffer addresses, lengths, and page strides, and match buffers by layer ID. Transfer K/V into temporary HBM staging buffers on the decode worker; transfer DSA index state directly into its native device cache using separate destination page indices.
- **Decode:** Copy the received K/V from staging into the request's registered host KV cache. Report transfer completion only after the host copy finishes, then release staging for reuse. Decode continues through the sparse offload attention path.

```text
Prefill HBM K/V  -- Ascend transfer engine -->  Decode HBM staging
                                                       |
                                                       v
                                               Registered host KV
                                                       |
                                                       v
                                               Sparse HBM KV cache

Prefill DSA index state  ------------------->  Decode native index cache
```

### Slot-map lookup and LRU caching

The SGLang integration uses the following operators from the companion `sgl-kernel-npu` update:

- **`slot_map_lookup`:** Uses tiled, vectorized lookup with double buffering to overlap memory loads, computation, and result writes. In LRU mode, it also produces a physical-slot hit mask alongside hit flags and slot positions, avoiding a separate mask-building step.
- **`fused_timestamp_lru_metadata_update_with_probation`:** Updates slot ages and selects victims while protecting current hits. It uses stable compaction of the existing LRU order instead of a full sort. Hits reset to age zero; newly inserted misses start at a configurable probation age, so a one-time access does not immediately receive the same priority as a hit.
- **`parallel_lru_metadata_write`:** Updates token-to-slot and slot-to-token mappings across NPU vector cores. It invalidates evicted entries and installs the new mappings. Cache refill writes only misses; hits remain in their existing HBM slots.

LRU is disabled by default. Enable it with `SGLANG_NPU_SPARSE_KV_ENABLE_LRU=1`; this path requires `index_topk=2048`. `SGLANG_NPU_SPARSE_KV_DEVICE_CACHE_FACTOR` sets capacity to 1–4 times top-k (default: 2), and `SGLANG_NPU_SPARSE_KV_PROBATION_AGE` defaults to 4. Dynamic top-k remains supported when LRU is disabled.

Kernel dependency: `sgl-kernel-npu`(https://github.com/ITCJ/sgl-kernel-npu) branch `bw/pr/feat_lru_with_probation`, currently checked against `e7a9cb60fccb3cc66cf32c182b98279a44a3b705`.
