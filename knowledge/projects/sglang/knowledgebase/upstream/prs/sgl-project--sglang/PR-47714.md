# [Refactor] memory-pool: Build QSA indexer host pools as hybrid sidecars

[Upstream PR](https://github.com/sgl-project/sglang/pull/47714) · state: closed · merged: True

## Original PR description

## Motivation

Followup of #40916. QSA still reached HiCache assembly through type checks: `_MambaStrategy` detected `QSATokenToKVPool` and passed a `qsa_pool` argument into `build_hybrid_mamba_stack`, which captured the compressed keys, cut the KV host budget and appended the INDEXER entry by hand, and `build_full_draft_pools` had a second QSA branch. This PR builds QSA through the same sidecar path as the DSA indexer, so the assembler no longer names QSA.

Stacked on #40914, whose changes are the first commits here.

## Modifications

- `prepare_host_pool_config` accepts a `HybridLinearKVPool`, uses its full KV child as the root, and adds the sidecar infos the hybrid pool reports. Packed MTP drafts are unwrapped the same way. `HybridLinearKVPool.get_device_pool_infos()` reports no sidecars, and `QSATokenToKVPool` reports its compressed keys.
- `_build_sidecar_host_pool` builds `QSAIndexerPoolHost` for `KEY_ROWS` sidecars and `DSAIndexerPoolHost` otherwise. The key-row builder rejects uncompressed keys, a page size different from the KV host, and layer-sharded buffers.
- `build_hybrid_mamba_stack` takes the KV host budget share of `KEY_ROWS` sidecars from the config. `_MambaStrategy` passes the hybrid pool and drops the QSA type check.
- `build_full_draft_pools` prepares a config for every full draft and builds each sidecar it reports, replacing the separate DSA and QSA branches.

Behavior change: the QSA INDEXER entry now follows KV and precedes MAMBA, the same order as a DSA indexer in a hybrid Mamba stack. Host pool shapes, the budget split and the H2D transfer sequence are unchanged.

## Accuracy

Qwen3.8-Flash-Next, tp 4, NEXTN, HiCache multi-turn KL with forced host hits against #40914, 3 runs per side. Every assembled host pool matches the parent apart from the entry order above, the H2D transfer sequence is identical, host-served sample counts are equal (prefill 5/8, decode 8/8), and decode-hit KL is identical. Prefill-hit KL varies run to run on both sides.

```
#40914:  prefill_kl 0.00854 / 0.01603 / 0.00412   decode_kl 0.00358 / 0.00358 / 0.00358
this PR: prefill_kl 0.01633 / 0.01079 / 0.00784   decode_kl 0.00358 / 0.00358 / 0.00358
```

With a fixed `--hicache-size`, the KV, INDEXER and Mamba host pools have the same sizes as the parent on every rank.
