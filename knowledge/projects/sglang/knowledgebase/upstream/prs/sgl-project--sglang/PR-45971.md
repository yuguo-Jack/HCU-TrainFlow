# [Fix] true-on-policy: Sample from fp32 probs when logits are bf16

[Upstream PR](https://github.com/sgl-project/sglang/pull/45971) · state: closed · merged: True

## Original PR description

## Summary

Fixes a regression from #44517.
- **What changed in #44517:** the CUDA-graph logits buffer now follows the logits dtype, so under a true-on-policy contract (`qwen3_dense_true_on_policy_v1`) the sampler receives **bf16** logits in graph decode as well as in prefill.
- **Why that breaks filtered sampling:** the standard top-p/top-k path in `Sampler.forward` ran `logits[:] = torch.softmax(logits)` in place, so the probabilities came out bf16. Sampling and the sampling-support log-probs `log(p / support_mass)` then read bf16-rounded probabilities and no longer matched the trainer.
- **The symptom:** miles' `test_qwen3_0_6b_fsdp_sampling_support_replay_true_on_policy.py` fails its true-on-policy check: `log_probs (-1.38827, 8) != rollout_log_probs (-1.38723, 8)`.

**The fix:** upcast the logits to fp32 before the existing in-place softmax (`logits = logits.float()`, which does nothing when they are already fp32). Default serving is unchanged. In graph decode this restores the numerics from before #44517: fp32 softmax of logit values that are exact in bf16. It also makes prefill's first sampled token consistent with decode.
