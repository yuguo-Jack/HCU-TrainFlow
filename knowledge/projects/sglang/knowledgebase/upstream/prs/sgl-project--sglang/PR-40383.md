# [Bugfix] Ignore PREBUILT batches in profile V2 stage mapping

[Upstream PR](https://github.com/sgl-project/sglang/pull/40383) · state: closed · merged: False

## Original PR description

### What this fixes

`_get_stage_from_forward_mode()` (profile V2) maps `prefill`/`decode`/`idle` to a profile stage and falls through to:

```
raise RuntimeError(f"unsupported profile stage: {forward_mode=}")
```

for any other mode. `ForwardMode.PREBUILT` is the disaggregated-decode placeholder for requests whose KV just arrived; it never enters a model forward. With `SGLANG_PROFILE_V2=1`, a scheduled prebuilt batch therefore crashes the profiling step instead of being ignored.

The V1 path already handles this — `SchedulerProfilerManager._profile_batch_predicate` ignores `IDLE` and `PREBUILT` (merged in #40098). This applies the same handling to the V2 path.

### Fix

Treat `is_prebuilt()` like `is_idle()` and return `None` (no stage).

### Test

Added `test/registered/unit/utils/test_profile_utils.py`, a CPU-only unit test covering prefill/decode/idle/prebuilt mapping.

### Duplicate check

#40098 fixed only the V1 predicate in `profiler_manager.py`; it did not touch `profile_utils.py`, so the V2 path is still affected. No open PR addresses the V2 mapping.

### AI assistance

AI assistance was used; the change is a two-line guard plus a CPU unit test.
