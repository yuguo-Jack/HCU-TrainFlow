# [Perf] SM90 single-token W8A16 GEMV for 128x128 block-FP8 linears

[Upstream PR](https://github.com/sgl-project/sglang/pull/43881) · state: open · merged: False

## Original PR description

## Motivation

Closes #43880.

At batch size 1 on SM90, each 128x128 block-FP8 linear quantizes the activation and then runs a block-FP8 GEMM (DeepGEMM by default). That GEMM is tiled for M >= 64. At decode shapes it takes 1.0-2.5x longer than streaming the weight requires.

## Modifications

- `python/sglang/kernels/ops/gemm/block_fp8_gemv.py`: adds a single-launch Triton W8A16 GEMV.
  - Each CTA owns BLOCK_N rows over the full K.
  - BLOCK_N divides 128, so each CTA reads a single scale row. That scale is applied to the bf16 activation, and the reduction is fp32.
  - No activation quantization and no split-K.
  - Scale strides are passed through, so padded or TMA-aligned scale layouts work.
- `Fp8LinearMethod.apply`: when `SGLANG_OPT_HOPPER_BLOCK_FP8_GEMV=1` is set on SM90, a block-quant layer with block size `[128, 128]` takes the GEMV when the input is a single token (`x.numel() == K`). Marlin and MXFP8 are excluded.
- `environ.py`: adds `SGLANG_OPT_HOPPER_BLOCK_FP8_GEMV` (default off).
- Unit test: checks against an fp32 dequantized reference. It covers the masked N tail, K that is not a power of two, padded scales with bias, and the predicate's fallback branches.

## Accuracy Tests

- Kernel relative error vs fp32 dequant: about 1.6e-3, compared with 2.6e-2 for the W8A8 path (the activation is not quantized).
- Qwen3.6-35B-A3B-FP8, GSM8K: GEMV 0.959-0.964 vs stock 0.959-0.963 across all A/B arms.
