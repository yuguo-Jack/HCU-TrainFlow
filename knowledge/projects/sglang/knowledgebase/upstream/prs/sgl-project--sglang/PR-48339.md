# [CI] [NPU] nightly-4-npu-a3: Rebalance partitions, bound retries, retire GLM-5.2 16p accuracy

[Upstream PR](https://github.com/sgl-project/sglang/pull/48339) · state: open · merged: False

## Original PR description

## Motivation

`nightly-4-npu-a3` runs two partitions, but the `est_time` values fed to the LPT packer were never re-measured after the cases moved into this suite, so the packer saw them as balanced while the real wall time was 612 s vs 3568 s (run 41670809407):

- partition 0: only `test_npu_load_balance_method_pd_disaggregation.py` -> 612 s
- partition 1: `test_npu_dp_attention.py` + pd_disaggregation + w4a4 + speculative_multi_npu -> 3568 s

The job therefore spent ~1 h on a ~46 min critical path. The two stale estimates:

- `test_npu_load_balance_method_pd_disaggregation.py`: 3600 s was calibrated for the full 25-parameter non-CI sweep, while CI only runs 3 random combinations (measured 577 s / 581 s / 990 s).
- `test_npu_dp_attention.py`: 2400 s vs measured 2673 s.

Independently, `TestDPAttentionMixedChunk` runs a full 1319-example GSM8K check through evalscope (~32 min per pass) with up to 3 attempts. On run 41324541621 the first pass scored 0.8170 < 0.8217, a retry started, and the file was killed by the 3600 s per-file timeout while the second pass was still running. Two passes need ~4600 s, which exceeds the old budget.

Separately, the `glm_5_2_w8a8_16p_gpqa` case in the multi-node mix matrix is not currently schedulable: its `est_time` (3600 s) is far below its measured runtime (~2 h 08 m), and its generation settings are still being re-tuned. Its matrix entry is retired until it is re-calibrated, instead of leaving a job that cannot meet its own budget.

## Modifications

- `test/registered/npu/basic_function/parallel_strategy/data_parallelism/test_npu_load_balance_method_pd_disaggregation.py`: `est_time` 3600 -> 600 (nightly suite only).
- `test/registered/npu/basic_function/dp_attn/test_npu_dp_attention.py`: `est_time` 2400 -> 2700; `TestDPAttentionMixedChunk` sets `gsm8k_max_attempts = 2`.
- `python/sglang/test/ascend/npu_eval_accuracy_kit.py`: expose the retry cap as the class attribute `gsm8k_max_attempts` (default stays `_NPU_MAX_ACCURACY_ATTEMPTS = 3`, so every other NPU GSM8K case is unchanged) and read it in both retry loops.
- `.github/workflows/nightly-test-npu.yml`:
  - `nightly-4-npu-a3`: `timeout_per_file` 3600 -> 5400.
  - `nightly-poc-multi-node-mix-tests`: comment out the `glm_5_2_w8a8_16p_gpqa` matrix entry, leaving only `kimi_k3_w4a8_32p_gpqa`.

Resulting partition plan (est / measured):

| Partition | Files | est | measured |
|---|---|---|---|
| run 0 | `test_npu_dp_attention.py` | 2700 s | 2673 s |
| run 1 | load_balance + pd_disaggregation + w4a4 + speculative_multi_npu | 1800 s | 1432 s |

5400 s is the two-pass budget: 2656 s for the normal file (classes 1/2/4 plus one evalscope pass) + ~1945 s for the re-run, with ~800 s (~17%) headroom, and it stays below `run_timeout_minutes: 120`.
