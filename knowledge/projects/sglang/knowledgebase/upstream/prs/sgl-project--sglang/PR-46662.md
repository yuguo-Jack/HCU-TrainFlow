# [Doc] [AMD] GLM-5.3: Enable MTP on MI355X and add the agentic recipe with the AMD monokernel

[Upstream PR](https://github.com/sgl-project/sglang/pull/46662) · state: open · merged: False

## Original PR description

Depends on an SGLang pin of sgl-amd-mono at or after [`0a107f1`](https://github.com/sgl-project/sgl-amd-mono/commit/0a107f15362714c45be34ca37e4dec286fa3d303) ([sgl-amd-mono#60](https://github.com/sgl-project/sgl-amd-mono/pull/60)): done. [sglang#46902](https://github.com/sgl-project/sglang/pull/46902) and [sglang#46951](https://github.com/sgl-project/sglang/pull/46951) pin [`90c2355`](https://github.com/sgl-project/sgl-amd-mono/commit/90c23551a323d5badd5b86c1e92151e319072d87). The first MI35x image with this pin is `lmsysorg/sglang-rocm:v0.5.22-rocm720-mi35x-20261028` (`sha256:2456fff6cfaf`). Section 3.6 now names this image, and its command runs on it (tables below).

The next pin brings [sgl-amd-mono#85](https://github.com/sgl-project/sgl-amd-mono/pull/85) and [#86](https://github.com/sgl-project/sgl-amd-mono/pull/86) (`ca929b7d`), which cut the monokernel's decode ITL by about 10 % at concurrency 1 to 4 on the section 3.6 command (local A/B below). `main` pins `b10f3b71` ([sglang#47483](https://github.com/sgl-project/sglang/pull/47483)), which does not contain them; the daily bump bot ([sglang#46685](https://github.com/sgl-project/sglang/pull/46685)) opens that pin. When an MI35x nightly contains it, section 3.6 will name that image and the published-image tables will be measured again on it.

## Motivation

The GLM-5.3 page keeps MTP off on MI355X. No AMD Deploy cell has MTP flags, the Playground turns off both MTP presets on AMD, and the reasons say that more than 3 steps hit a build issue on gfx950. On the page's own MI355X image with the FP8 cells' flags, EAGLE 1-1-2, 3-1-4, and 5-1-6 serve at the GSM8K score of no MTP, and 3-1-4 decodes one request 2.2 times as fast as no MTP. Only 5-1-6 on the high-throughput cell fails: it runs out of memory at startup (tables below).

The page also has no MI355X recipe with MTP, an FP8 KV cache, or the AMD monokernel. On one MI355X node at TP8, EAGLE 3-1-4 with `fp8_e4m3` KV runs, and adding the monokernel improves all three InferenceX AgentX headline metrics (throughput, P90 interactivity, P90 E2EL) at concurrency 1, 2, 4, and 10 (tables below).

InferenceX accepts a recipe only when its production-useful flags are on a merged cookbook page, as [#45693](https://github.com/sgl-project/sglang/pull/45693) did for DeepSeek-V4.1 before [InferenceX#4367](https://github.com/SemiAnalysisAI/InferenceX/pull/4367). This page change comes before the GLM-5.3 MI355X submission.

## Modifications

- `glm-5.3.jsx`:
  - The MI355X FP8 low-latency Deploy cell serves EAGLE 3-1-4. At one request, 3-1-4 decodes faster than 5-1-6 and 1-1-2 on MI355X, and section 3.6 uses the same draft.
  - The Playground's two MTP presets are on for the MI355X FP8 cells, except 5-1-6 on the high-throughput cell (startup OOM). They stay off for BF16 on MI355X and for MI300X and MI325X, which did not run. The reasons no longer say that more than 3 steps hit a build issue.
  - The AMD cell comment says which cell serves MTP.
- `GLM-5.3.mdx`: new section 3.6, "Agentic Long-Context on MI355X (FP8, MTP)". It gives the command and the admission limit per concurrency, in the form of section 3.6 of the DeepSeek-V4.1 page. It names the first MI35x image that runs the command, `v0.5.22-rocm720-mi35x-20261028`. The section-2 AMD tip now says which MI355X cell serves MTP, where the presets run, and where MTP is not validated. It also keeps the MXFP4 AgentX commands that [#46825](https://github.com/sgl-project/sglang/pull/46825) added to the same tip.
- Unchanged: the images, the benchmarks, the other AMD cells, and `verified: false` on all AMD cells. The BF16 cells keep no MTP because no BF16 checkpoint ran. `--kv-cache-dtype fp8_e4m3` lowers KV precision, so it goes in section 3.6 and not in a Deploy cell.
- Left out of the section-3.6 command: harness-only settings (served model name, metrics, keep-alive, and the synthetic acceptance `SGLANG_SIMULATE_ACC_*`), and `SGLANG_OPT_USE_TOPK_V2=false`, which [`model_hook.py`](https://github.com/sgl-project/sglang/blob/5aeb6dfdb64895c7ef17fd385aba3a6ef28ed92a/python/sglang/srt/arg_groups/model_hook.py#L441-L443) already sets for DSA models on HIP.
- No test: documentation-only change.
