# [Feat] cp: Radix cache for padded CP KV layouts

[Upstream PR](https://github.com/sgl-project/sglang/pull/47988) · state: open · merged: False

## Original PR description

## Motivation

#45434 added padded, rank-local KV storage for context parallelism, but sharded `--cp-kv-layout` configurations still have to run with radix caching disabled. The radix tree aligned and freed physical pages rather than CP page groups. This PR makes the unified radix tree work with such a layout, so prefix sharing can stay enabled.

## Modifications

- **Unified radix tree, Python and Rust tree cores.** Under a sharded layout, tree keys, matches, inserts and splits align to logical pages (`cp_size * page_size`). The tree core exposes this width as `logical_page_size`, and the Rust core receives `cp_size` through its init parameters.
- **`UnifiedRadixCache`.** Eviction targets are converted from allocator rows to logical tokens. Freed tree values are converted to rank-local rows, and availability is reported in logical tokens.
- **FULL and SWA components.** Device frees, the FULL-to-SWA translation and SWA re-homing use rank-local rows, while the tree keeps cache-row values. The SWA window clip and tail size use logical pages.
- **SWA eviction threshold.** The out-of-window eviction threshold rounds to logical pages.
- **Prefill chunking.** A chunk is clamped so its padded CP groups fit the remaining token budget.
- **Tree-cache gate.** A sharded layout now admits `UnifiedRadixCache` itself. It still rejects its subclasses and other trees, and it rejects hierarchical caching, session radix caching, the unified-cache external linker and streaming sessions, which are not CP-aware yet.
- **PD prefill.** The bootstrap queue converts its capacity to logical tokens before computing the maximum input length.

Every new branch is gated on a sharded layout, so behavior without one is unchanged.
