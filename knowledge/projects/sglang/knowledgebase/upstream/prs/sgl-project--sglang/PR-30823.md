# [Bugfix] Handle missing chat encoding configs

[Upstream PR](https://github.com/sgl-project/sglang/pull/30823) · state: closed · merged: False

## Original PR description

## Summary

- Make `resolve_chat_encoding_spec()` tolerate missing, dictionary-shaped, and incomplete HF configs.
- Add CPU-only unit coverage for custom encoder dispatch and the Hugging Face fallback path.

## Motivation

The shared chat-encoding resolver introduced by #30623 accesses `hf_config.architectures` directly. Offline callers can pass `None`, a dictionary, or a config object without `architectures`, which currently raises `AttributeError` before the resolver can select the default path.

This is a focused follow-up to #30623 and contributes to the unit-test coverage work tracked in #20865.

## Pull request overview

This PR hardens the shared OpenAI chat-encoding dispatch logic so offline tools (benchmarks/evals) can call it safely even when Hugging Face config objects are missing, incomplete, or provided as plain dictionaries, and it adds CPU-only unit tests to lock in the expected dispatch behavior.

**Changes:**
- Make `resolve_chat_encoding_spec()` tolerate `hf_config=None`, dict-shaped configs, and config objects without an `architectures` attribute.
- Add CPU-only unit tests covering tool-call-parser precedence, DeepSeek custom encoder dispatch (including system-message insertion semantics), and the Hugging Face chat-template fallback behavior.
