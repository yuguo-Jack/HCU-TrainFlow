# [Feat] [AMD] diffusion: use aiter's gfx1201 SageAttention kernel for AITER Sage on RDNA4

[Upstream PR](https://github.com/sgl-project/sglang/pull/43687) · state: open · merged: False

## Original PR description

> **Draft.** Stacked on #43686 (packed varlen for `AITER_SAGE`). Depends on the gfx1201 SageAttention op in aiter: ROCm/aiter#6390 (HIP kernel), then a hand-scheduled code object as the follow-up. This PR stays a draft until those are merged. Until #43686 is merged, the diff here includes its commit; only the last commit belongs to this PR. Overall plan: [ROCm/aiter#6292](https://github.com/ROCm/aiter/pull/6292#issuecomment-6106014448).

## Motivation

On Radeon RDNA4 (gfx1201: Radeon AI PRO R9700 / R9600D, Radeon RX 9070 series), `AITER_SAGE` runs aiter's Triton `fav3_sage` kernel, which is slower than BF16 SDPA. aiter is adding `aiter.gfx1201_sage_attention`, a SageAttention kernel written for gfx1201. It quantizes QK^T to INT8 and PV to FP8, accumulates in FP32, and takes BF16 `[B, S, H, 128]` input.

## Modifications

`AITERSageImpl` calls `aiter.gfx1201_sage_attention(q, k, v, softmax_scale=...)` when all of the following hold:

- the GPU is gfx1201;
- the installed aiter provides the op;
- the layer is non-causal, with `head_size == 128` and `num_kv_heads` equal to `num_heads`;
- the call has BF16 inputs, and Q/K/V have equal shapes.

Everything else keeps the existing `fav3_sage` kernel unchanged. That covers other GPUs (gfx942 / gfx950), other shapes or dtypes, cross-attention with different KV length, and aiter builds without the op. The layer's `softmax_scale` is now passed to the gfx1201 kernel. The `fav3_sage` call is unchanged. The first time the gfx1201 kernel is selected, one info line is logged.

Unit tests are in `test/unit/test_aiter_sage_attn_backend.py` and use a stubbed aiter, so they need no GPU. They check:

- that the gfx1201 kernel is selected and receives the softmax scale;
- that it is also used through `forward_varlen`;
- that every fallback case keeps `fav3_sage`.

## Accuracy and speed

**Kernel.** On a Radeon AI PRO R9700, `forward_varlen` matches direct per-segment `aiter.gfx1201_sage_attention` calls bitwise for trailing padding, multiple segments and a single segment, with both aiter part 1 (HIP) and part 2 (code object).

**End to end.** MiniMax-H3, with the case parameters of `minimax_h3_t2va_2gpu_h100`: t2va, 1344x768, 4 s, 8 steps, seed 42, TP2, on 2x R9700 (PyTorch 2.11 / ROCm 7.15). Same flags as that case. All rows include the fixes of #43686 (varlen, `causal` / `softmax_scale`, contiguous Q/K/V).

| attention | denoise stage | vs BF16 SDPA | video PSNR / audio cos vs SDPA run |
|---|---|---|---|
| `torch_sdpa` (BF16) | 152.3 s | 1.00x | - |
| `torch_sdpa`, K/V token order reversed (rounding-only noise floor) | 152.3 s | - | 34.41 dB / 0.991 |
| `aiter_sage` before this PR (`fav3_sage`, Triton) | 412.7 s | 0.37x | 26.42 dB / 0.68 |
| `aiter_sage`, this PR, aiter part 1 (HIP kernel) | 103.6 s | 1.47x | 33.47 dB / 0.958 |
| `aiter_sage`, this PR, aiter part 2 (code object) | 94.2 s | 1.62x | 32.14 dB / 0.897 |

On gfx1201, `AITER_SAGE` becomes 4.4x faster than with `fav3_sage`, and the video ends much closer to the BF16 run (32-33 dB vs. 26 dB, against a 34.4 dB rounding-only floor). On dumped MiniMax-H3 DiT inputs, the relative error vs. BF16 attention is 0.013 for the gfx1201 kernel and 0.054 for `fav3_sage`. The three Sage runs ran concurrently on separate GPU pairs, so their times vary by a few percent between repeats. The speedup is larger at longer sequences: on the 15 s / 362-frame ref2av case in LightX2V, the same kernel gives 211.6 -> 89.1 s per DiT step (2.38x).

The R9700 runs used `sgl-kernel` built for gfx1201 (#43679), and the custom all-reduce was disabled because R9700s connect over PCIe (#43676).

- Shan2L · comment · 2026-10-11T23:35:17Z · [source](https://github.com/sgl-project/sglang/pull/43687#issuecomment-6115163665)

Note on run-to-run variation in the quality numbers above.

Repeating the same 8-step config (same seed, same tree) gives slightly different videos. For example, the asm path measured 32.84 dB in one run and 32.14 dB in another. We traced this down and it does **not** come from the attention kernels:

- `gfx1201_sage_attention` (asm and HIP) is bitwise deterministic: repeated calls on dirty memory, and 60 calls under concurrent side-stream load, give identical outputs.
- Hashing every DiT module across runs, the first divergence is in two **FP32 GEMMs** that are not part of this PR: the TimeEmbedder `proj_in` (`[1,256] x [2688,256]^T`) and the final-layer `video_out` (`[32704,5376] x [48,5376]^T`). Inputs, weights and bias are bitwise identical across runs, and recomputing in the same process gives the same result. Across processes, however, hipBLASLt/Tensile sometimes picks a different solution for the same shape, e.g. `MT16x8x64` vs `MT64x64x16`. In 12 runs, the output groups matched the kernel-name groups exactly. The 1-ulp difference is then amplified by the 50 DiT blocks over 8 steps.

So expect about ±0.7 dB PSNR jitter between identical runs on this stack, for every attention backend including SDPA. Only differences larger than that are meaningful. We are reproducing the per-process kernel choice standalone to report it to hipBLASLt.


- Shan2L · comment · 2026-10-12T01:01:14Z · [source](https://github.com/sgl-project/sglang/pull/43687#issuecomment-6115895553)

Follow-up: the per-process kernel choice is a hipBLASLt bug. For untuned shapes, the heuristic falls back to a solution list ordered by host pointer value, so the kernel that runs depends on the heap layout. It is fixed on rocm-libraries `develop` (ROCm/rocm-libraries#11340) but not in any TheRock release yet. Reported with a standalone repro in ROCm/rocm-libraries#13476, with a backport to 10.1 in ROCm/rocm-libraries#13477.
