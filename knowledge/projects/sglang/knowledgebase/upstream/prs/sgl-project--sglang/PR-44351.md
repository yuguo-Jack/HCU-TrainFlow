# [Fix] scheduler: Drop finished requests from the running batch before every admission

[Upstream PR](https://github.com/sgl-project/sglang/pull/44351) · state: closed · merged: True

## Original PR description

- Drop finished requests from `running_batch` in `get_next_batch_to_run` on every step, after the `last_batch` merge, and reopen admission (`batch_is_full = False`) when that shrinks the batch. This replaces the prefill-only special case.
- Cause: under overlap, a prefill batch merges into `running_batch` before its result marks the requests that finish at prefill (`max_new_tokens=1`, or a stop on the first token). The only other cleanup, `update_running_batch`, runs on decode steps, which never come while chunked prefill keeps producing batches, so `#running-req`, `num_running_reqs`, and `/v1/loads` grow for the whole run.
- Add a CPU unit test that fails on main, and give two existing scheduler test fixtures the `batch_size` / `filter_batch` the new code reads.

Behavior change: finished requests now leave the running batch before admission on every step, so a workload whose running batch is full can admit a waiting request one step earlier than on main.

Fixes #43961; supersedes #43960.
