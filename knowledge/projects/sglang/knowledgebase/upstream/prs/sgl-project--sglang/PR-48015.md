## Motivation

A unified pool may hold windows of several lengths, and a reader may read a window sub-pool further back than the window's own layers (a fused draft's front rows), which widens the tail a running request keeps. Over PD, the decode node sized every window entry by the scheduler's single sliding window and the prefill sent only the attention window, so:

- host receive allocated a shorter window's rows for the longer window (pages pair by position, so restored rows could hold KV of other positions);
- device preallocation bound further windows to the whole sequence and left their eviction cursors at zero;
- a request received over PD under a draft reach kept less than the cache's window slot retains, and restoring it from its host copy or backing it up after a retraction read unbound window positions and failed the cache's "unmapped window positions" device assertion, stopping the decode server;
- the KV checksum digested every state entry at the target window's rows.

## Modifications

- `mem_cache/kv/storage.py` (`window_lengths`), `disaggregation/utils.py` (`window_tail_len`): each window's length comes from its sub-pool through one tail rule.
- `disaggregation/decode.py`: host receive allocates and reserves per entry by its own window; preallocation binds, admits and reclaims each further window's own tail (`window_tokens`, `window_tail_lens`) and sets its eviction cursor; the reused prefix stops before the longest window's tail.
- `disaggregation/prefill.py`, `decode.py`, `utils.py`: both peers carry the kept tail (`retained_window_lengths`: each window's length widened by readers' reach); the prefill sends it (`resume_units(retain=)`), the decode binds, reserves and receives it on device and host paths. Each window entry's tail is part of the entries peers compare at bootstrap.
- `mooncake/conn.py`, `nixl/conn.py`, `mori/conn.py`: a prefill keeping a longer tail than the decode is accepted, and its send cuts each window entry to the decode's newest pages.
- `disaggregation/checksum.py`: `state_indices_for_request` gives one row list per state entry, each window's from its own sub-pool and length; the checksum digests the kept tail the peers send.
- `kv/alloc/chain.py`, `static_kv_storage.py`: per-window tail allocation.
- Tests: `test/registered/unit/disaggregation/test_unified_window_lengths.py` (windows of 16, 8 and 4 tokens receive and bind exactly what the prefill sends; tails agree under a draft reach; longer prefill tail accepted and aligned; shorter one and mixed pool kinds refused), `test_decode_retraction_backup.py` (host receive under a reach restores every row at its position), `test_kv_checksum.py`, `test_unified_window_wire.py`.

**Behavior changes (PD with unified memory):**
- A prefill whose kept window tail is shorter than the decode's is refused at bootstrap, naming both.
- Pairing a unified-memory server with one that does not use unified memory is refused at bootstrap (mixed pool kinds).
- A prefill keeping a longer tail than the decode is accepted and sends the decode's newest pages.
