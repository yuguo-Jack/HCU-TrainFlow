# [Fix] deepseek-v4: Report allocated KV cache memory usage

[Upstream PR](https://github.com/sgl-project/sglang/pull/37935) · state: open · merged: False

## Original PR description

## Motivation

Fixes #37852. DeepSeek-V4 KV pools allocate tensors without populating inherited `mem_usage`, so cache-memory metrics report zero. The real-constructor regression fails on upstream `c757c4bb7c55` despite 299520 allocated bytes.

## Modifications

- Account for padded KV buffers, active ratio-specific KV/indexer pools, separate unified-FP8 RoPE storage, and compression/request-window state.
- Finalize indexer accounting after backend-specific allocation completes.
- Merge upstream `c757c4bb7c55`, retaining its DevicePoolInfo, HiCache and backend changes.
- Keep the claim limited to KV/compressor tensor storage, not total GPU process memory.
