# [Fix] scheduler: Respect earlier EOS in speculative stop handling

[Upstream PR](https://github.com/sgl-project/sglang/pull/48402) · state: open · merged: False

## Original PR description

## Motivation

A speculative commit can contain an EOS followed by accepted draft or bonus tokens. `Req.update_finish_state` currently selects a later matched stop string or regex before checking EOS. For a verified run decoding as `k<EOS>uSTOP` with `stop=["STOP"]`, the native output path emits `ku`; sequential decoding stops at EOS and emits `k`.

## Modifications

Compare the existing token-stop boundary with the existing text-stop boundary and keep the earlier. A text stop still wins a tie, preserving stop trimming when both conditions complete at the same token. Keep the existing vocabulary, length-cap, grammar and ignored-EOS behavior. Selection among multiple literal or regex matches remains with the existing text-stop helper.

This is separate from #42466 and #42360, which select among literal stops, and #47103, which optimizes text-tail checks. Their source diffs were checked. This also preserves the earlier-text-stop behavior corrected in #28802. I directed this work and take responsibility for the contribution and its follow-up. AI assistance was used in producing the change.
