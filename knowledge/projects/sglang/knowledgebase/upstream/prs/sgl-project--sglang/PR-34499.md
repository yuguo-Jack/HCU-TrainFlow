## Motivation
DeepSeek-V4-Flash-0731 contains three DSpark MTP stages, corresponding to dspark_target_layer_ids=[40, 41, 42] , while num_nextn_predict_layers is set to 1 .

The existing DSV4 KV cache accounting therefore reserves memory for only one draft layer, although the draft model allocates SWA KV cache for three stages. This underestimates draft KV memory and can over-size the target KV pool, increasing the risk of OOM during long generation.

- Original hardcoded one-layer estimate: reserves approximately 1,056.8 bytes per full token , underestimating the actual draft KV cost by about 345 bytes and potentially causing OOM.
- Direct 3/43 layer-ratio scaling: reserves approximately 3,170.5 bytes per full token , overestimating the cost by about 1,769 bytes and reducing token capacity by roughly 3.8% , which may prevent scheduling from making progress.
- Current packed-SWA formula: reserves 1,401.6 bytes per full token , matching the actual three-stage DSV4 draft SWA layout.

<!-- Describe the purpose and goals of this pull request. -->

## Modifications

- Resolve the bundled DSV4 DSpark draft layer count from len(dspark_target_layer_ids) .
- Propagate the resolved count through SpecAuxHiddenStateConfig.dflash_draft_num_layers .
- Use the resolved draft layer count in DSV4 KV cache memory accounting instead of assuming one draft layer.
- Add CPU unit tests covering bundled DSV4 DSpark stage resolution and pool accounting.
