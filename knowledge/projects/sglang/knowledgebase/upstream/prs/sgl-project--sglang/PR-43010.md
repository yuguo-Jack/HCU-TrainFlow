# [DeepSeek-V4.1] Run encoder SWA bounded replay under the breakable prefill CUDA graph

[Upstream PR](https://github.com/sgl-project/sglang/pull/43010) · state: closed · merged: False

## Original PR description

## Motivation

`--enable-encoder-swa-bounded-replay` keeps each request's sliding-window state in a per-request window instead of the paged cache. Today the server refuses to start if the flag is combined with a prefill CUDA graph, so every prefill runs eagerly, and so does the extra pass that rebuilds a window when a request hits a cached prefix.

Eager prefill costs about 120 ms per batch with this flag on 4x B300. A follow-up turn on a cached conversation pays it twice, once for the rebuild pass and once for the new tokens.

Roadmap #42170 lists "Enable encoder bounded replay" with no owner. This PR builds on the decoder PR #42909 and on the crash fix #42902. Until those merge, its diff includes their commits.

## Modifications

1. The request-window layout can be padded. Each graph captures it for its own row count and for one window group per request slot, so a batch of any number of requests fits. Padding rows write to scratch rows and are never committed to a request's window.
2. On each replay the captured layout is refreshed in place and activated again.
3. When a request hits a cached prefix, an extra pass rebuilds its window. That pass now runs through the graph too. It does not need the compressor, and it can still skip it, because under bounded replay the compressor and the indexer run outside the captured graph, at a graph break.
4. Sparse prefill attention reads only the live rows of the padded layout.
5. Only the breakable backend is accepted.

## Accuracy Tests

4x B300, `deepseek-ai/DeepSeek-V4.1-Flash`, TP4 and EP4. Both columns run this branch.

```bash
# eager
python3 -m sglang.launch_server --trust-remote-code --model-path deepseek-ai/DeepSeek-V4.1-Flash --tp 4 --ep-size 4 --mem-fraction-static 0.8 --cuda-graph-max-bs-decode 64 --max-running-requests 16 --chunked-prefill-size 8192 --enable-encoder-swa-bounded-replay --disable-prefill-cuda-graph
# graph
python3 -m sglang.launch_server --trust-remote-code --model-path deepseek-ai/DeepSeek-V4.1-Flash --tp 4 --ep-size 4 --mem-fraction-static 0.8 --cuda-graph-max-bs-decode 64 --max-running-requests 16 --chunked-prefill-size 8192 --enable-encoder-swa-bounded-replay --cuda-graph-backend-prefill breakable
# "all three" rows add: --enable-decoder-swa-bounded-replay --speculative-algorithm DSPARK --speculative-dspark-block-size 5
python3 -m sglang.test.few_shot_gsm8k --num-questions 1319 --parallel 32
```

| GSM8K, 1319 questions | eager | graph |
| --- | --- | --- |
| encoder replay only | 0.900 | 0.904 |
| encoder + decoder replay + DSpark | 0.901 | 0.910 |

Each cell is one run. Repeated runs of one configuration moved between 0.900 and 0.915, so these are within noise. The DSpark accept length is 3.40 in both columns.
