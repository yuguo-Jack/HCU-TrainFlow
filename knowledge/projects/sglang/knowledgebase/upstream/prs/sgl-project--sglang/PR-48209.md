# [Perf] hicache: Skip satisfied Full host eviction heaps

[Upstream PR](https://github.com/sgl-project/sglang/pull/48209) · state: open · merged: False

## Original PR description

## Motivation

In write-back mode, reclaiming Full Host copies that coexist with Device values can already satisfy the eviction target. Both tree cores nevertheless build a heap over all evictable Host leaves before discovering that the eviction loop has nothing to do.

## Modifications

Return before constructing the Full Host heap when the tracker already meets the requested token count, in both Python and Rust. Keep ordinary victim selection unchanged.

Related to #47126: this skips unnecessary heap initialization for a satisfied target; that PR reuses the heap across a device-eviction walk.

## Accuracy Tests

- Two CPU Python cases using the real tree core: duplicate reclaim satisfies the target, or another Host leaf must be evicted. Check freed slots, preserved Device values, surviving Host hits, and priority evaluations. The satisfied case fails on the original implementation.
- Extend the existing Rust duplicate-reclaim test to verify that a Host-only leaf survives when duplicate reclaim meets the target.
- Linux aarch64, Rust 1.90.0, PyTorch 2.14.1+cpu: `cargo test --lib --locked`: **949 passed, 1 ignored**.
- Crate Clippy with `-D warnings`, rustfmt, and non-Rust pre-commit hooks passed. Workspace-wide Rust hooks were replaced by checks of the changed crate in Docker.

## Speed Tests and Profiling

The Python regression test verifies that a satisfied target performs zero Host-leaf priority evaluations; the insufficient-reclaim control still scans the candidate. No GPU serving, TTFT, or throughput improvement is claimed.
