## Motivation

<!-- Describe the purpose and goals of this pull request. -->

Currently one can choose a global attention backend or a specific backend per component.
This PR adds support to choose attention backend per component for each role. That is, a different backend for self-attention and cross-attention.

The motivation here is that when using quantized attention backends, there's a quantization overhead prior to running the lower precision kernel. This overhead is mostly worth it in self-attention, but cross-attention calls are often so light that the overhead can be enough for the entire call to be slower than the un-quantized counterpart.

The backend can be chosen via the component backend selection:
```
--component-attention-backends.transformer.self=backend_1 -component-attention-backends.transformer.cross=backend_2
```

The backend choice tree is as follows:
  1. selected_attention_backend - explicit arg passed directly into `get_attn_backend()`
  2. Global forced backend - `get_global_forced_attn_backend()`, set via `global_force_attn_backend()` (programmatic override)
  3. Component + role override - `get_component_forced_attn_backend_for_role(attention_role)`, i.e. the config key transformer.cross / transformer.self
  4. Component-wide override - `get_component_forced_attn_backend()`, i.e. the config key transformer (no role suffix)
  5. CLI global - `--attention-backend` flag
  6. `default_attention_backend`
  7. Platform default - if everything above is None, platform picks

This now only adds the choice via the `--component-attention-backends`. If desired, I can also add a `--cross-attention-backend` flag.


## Modifications

<!-- Detail the changes made in this pull request. -->

- Enhances the component-attention-backend to support self/cross attn as well
- Adds AttentionRole enum used to specify self/cross role (can support others, like joint, as well, if needed)
- Stores role-qualified entries in a separate `component_attention_backend_roles` map rather than in `component_attention_backends`, so consumers that look a component up by name are unaffected by a role key
