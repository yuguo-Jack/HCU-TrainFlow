# [Perf] EAGLE: broadcast additive penalties over verify tokens

[Upstream PR](https://github.com/sgl-project/sglang/pull/42738) · state: open · merged: False

## Original PR description

## Motivation

EAGLE verification materializes per-request `[B,V]` additive penalties as `[B*D,V]` using `repeat_interleave`, then adds them to the logits. B is the batch size, D is the verification width (`draft_token_num`), and V is the vocabulary size. All D positions of a request use the same penalty row. Broadcasting avoids this copy and intermediate tensor.

## Modifications

Replace `repeat_interleave + add_` in `eagle_sample()` with:

```python
next_token_logits.unflatten(0, (bs, verify_input.draft_token_num)).add_(
    sampling_info.acc_additive_penalties.unsqueeze(1)
)
```

`unflatten` splits the dimension while sharing the original storage. Each logit receives the same in-place addition, preserving the original results.

## Speed Tests and Profiling

**CUDA graph microbenchmarks of the local penalty chain** on NVIDIA L40 with Torch 2.13.0+cu130, contiguous FP32 logits and a vocabulary size of 248,320. Each graph contains 32 complete penalty applications, and each measurement replays it 20 times, timed with CUDA events. Both versions are measured 11 times, alternating which runs first; the median time is reported for each version.

Observed GPU nodes per application, with abbreviated kernel names:

| Version | GPU kernel sequence |
|---|---|
| Before | `elementwise_kernel<128,2,...direct_copy_kernel_cuda...>` materializes the repeated penalties → `vectorized_elementwise_kernel<4,...CUDAFunctor_add<float>...>` performs the in-place add |
| After | One `elementwise_kernel<128,2,...CUDAFunctor_add<float>...>` performs the broadcast in-place add |

GPU kernel nodes decrease from 2 to 1. The new add uses a broadcast-capable elementwise variant.

Previously, `repeat_interleave` allocated and wrote a `[B*D,V]` intermediate, which the add then read. The new implementation broadcasts the original `[B,V]` penalties through a view, eliminating both the copy kernel and the expanded tensor. This reduces memory traffic and peak memory. The removed FP32 tensor has a logical size of `4*B*D*V` bytes:

| B | D | Before, full chain µs | After, full chain µs | Removed intermediate, logical MiB |

| 1 | 6 | 9.03 | 4.59 | 5.68 |
| 4 | 4 | 20.47 | 10.41 | 15.16 |
