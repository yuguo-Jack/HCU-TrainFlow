# [Perf] [AMD] aiter: Query native head support for DCP MLA verify

[Upstream PR](https://github.com/sgl-project/sglang/pull/47591) · state: open · merged: False

## Original PR description

## Motivation

- At DCP, the aiter backend pads the gathered query heads of the target verify up to a count aiter runs natively. It decides with `_MLA_ASM_CPRR_NATIVE_QLENS`, a hand copy of aiter's rule.
- The copy has drifted: ROCm/aiter#7245 makes 96 fp8 heads native at qlen 7-8 under round-robin CP, but the table still pads Kimi-K3's 96 heads to 128. That costs a pad copy plus 33% more rows on every verify step.
- aiter already exposes the rule (`get_mla_decode_shape_support`, ROCm/aiter#6107), so SGLang should ask it instead of copying it.

## Modifications

- The backend asks aiter about the verify's real call: fp8 Q/KV, LSE, round-robin CP, DCP size, `fast_mode`, `intra_batch_mode`, and the latent width `kv_lora_rank` as `v_head_dim`.
- The answer is cached per (heads, q_len). The padded count is computed only for MLA with DCP > 1.

| aiter answer | Head count used natively? |
|---|---|
| `native` and `supported=True` | yes |
| `supported=False`, or not `native` (aiter folds) | no |
| `supported=None` (no kernel table for that backend) | only if `native` and in the copied table |
| aiter without the query (before ROCm/aiter#6107) | copied table, as before |

- `test_aiter_verify_metadata.py` covers aiter's verdict deciding the padding, the latent width, the table fallback, the fold veto, one query per shape, and an unsupported shape.

## Accuracy Tests

Kimi-K3, 8x MI355X, TP8/DCP8, DSpark block 7, with ROCm/aiter#7245. GSM8K: sgl-eval 0.1.3, 1319 questions, real acceptance, Kimi-K3 preset.

| Verify heads | GSM8K | Accept length |
|---|---|---|
| 96 native (this PR) | 0.9386, 0.9500 | 4.28, 4.19 |
| 128 padded | 0.9469 | 4.27 |
| 96 native, with #47645 | **0.9666** | 4.39 |

- Native 96 heads equal the first 96 heads of the padded call bit for bit (ROCm/aiter#7245).
- The first two rows predate #47645, a graph-replay bug that affected both sides alike.

## Speed Tests and Profiling

End to end, AgentX c1 600 s screens, Kimi-K3 DCP8:

| Verify heads | P90 interactivity | P90 ITL |
|---|---|---|
| 128 padded | 208.77 | 4.79 ms |
| 96 native | **215.05 (+3.0%)** | 4.65 ms |

Kernel: aiter cp verify, rank 0 of 8, qlen 8, fp8, LSE, aiter-planned splits, both sides on one GPU. Times exclude the pad copy and come from ROCm/aiter#7245.

| Batch | Global context | 128 padded (us) | 96 native (us) | Change |
|---|---|---|---|---|
| 1 | 16K | 45.5 | 36.0 | -21% |
| 1 | 350K | 98.5 | 89.8 | -9% |
| 16 | 64K | 206.9 | 188.6 | -9% |
| 56 | 350K | 3392.0 | 3304.7 | -3% |

- Without ROCm/aiter#7245, aiter still reports 96 heads at qlen 8 as folded, and SGLang pads to 128 as before.
