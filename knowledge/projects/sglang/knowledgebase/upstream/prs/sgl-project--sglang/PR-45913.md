# [Perf] [AMD] GLM5: Add fused KDA prefill backend on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/45913) · state: closed · merged: False

## Original PR description

## Motivation

GLM-5.3-Flash KDA prefill launches separate kernels for Q/K normalization, gate activation and chunk-local scan, the intra-chunk solve, W/U/Kg materialization, recurrence, and output.

AITER's merged [ROCm/aiter#5866](https://github.com/ROCm/aiter/pull/5866) provides `aiter.ops.triton.attention.chunk_kda`, which fuses the prepare work and uses a recurrent walk kernel for state and output. Merged [ROCm/aiter#6672](https://github.com/ROCm/aiter/pull/6672) adds the BF16 state-cache load/store required by GLM-5.3 while retaining FP32 recurrence.

## Modifications

- Add `aiter` as a KDA prefill backend selected by `--linear-attn-prefill-backend aiter`.
- Default KDA prefill to AITER on gfx950 when the BF16-capable operator is installed. `--linear-attn-prefill-backend triton` remains the explicit opt-out.
- Route measured BF16 `K=V=128`, BT=64 prefill over a contiguous range: 64-16,384 total tokens, 1-8 sequences, and 8 or 16 local heads.
- Keep Triton for unsupported hardware, dtypes, dimensions, layouts, safe-gate contracts, speculative extend, unsupported tracking layouts, and shapes outside the measured range.
- Preserve `extra_buffer` prefix-cache tracking on the dominant single-sequence path by splitting at the tracked chunk boundary, retaining FP32 recurrence and snapshot state, then committing the final state once. Measured tracked dispatch starts at 8,192 tokens for TP4 and 14,336 for TP8; smaller or multi-sequence tracked batches stay on Triton.
- Forward caller-provided chunk indices and offsets; construct them only when absent.
- Resolve the optional AITER operator once at module load.
- Add gfx950 coverage for TP4/TP8 geometry, ragged boundaries, a production 16,384-token single-sequence case, invalid state indices, deterministic execution, CUDA-graph replay, metadata forwarding, FP32-state/tracking fallbacks, and non-gfx950 rejection.
- Register the kernel suite only on the MI35X runner.

This PR is blocked by [#47139](https://github.com/sgl-project/sglang/pull/47139), which updates the gfx942/gfx950 AITER pin to include ROCm/aiter#6672.

## Accuracy Tests

Focused validation on the submitted source passed **33 tests and 24 subtests** on MI355X. Coverage includes TP4/TP8 head geometry, ragged boundaries, production 16,384-token single-sequence parity with FP32 and BF16 state, tracked output/snapshot/final-state parity, padded `-1` state indices, untouched state slots, finite output, determinism, CUDA-graph replay, metadata forwarding, explicit fallbacks, source-less AITER capability detection, and backend policy.
