# [Perf] [AMD] qwen3_5: One wavefront per head and an in-place gate for the fused Q/K norm + RoPE + gate kernel

[Upstream PR](https://github.com/sgl-project/sglang/pull/47779) · state: open · merged: False

## Original PR description

Builds on #45529, which runs `fused_qk_gemma_rmsnorm_rope_gate` on aiter (ROCm) as on CUDA; this PR is the last two
commits on top of it.

## Motivation

In Qwen3.5-style full-attention layers with an output gate, `fused_qk_gemma_rmsnorm_rope_gate` runs one program per
(token, head) over a 256-wide head. With #45529 ROCm uses it instead of the norm + gate split kernel followed by the mrope
kernel, but at the default 4 warps it is barely faster than those two (Qwen3.8-27B on MI355X, 16384 tokens: 542 vs 571 us
per full-attention layer; 16 layers, so ~9 ms per 16384-token prefill chunk). Two more things cost time:

- one 64-lane wavefront covers the 256-wide head with 4 elements per lane; 4 warps leave three of them idle on the
  per-head reductions;
- the kernel also copies each q head's gate out of the interleaved q/gate projection into a contiguous tensor, whose only
  reader is `fused_sigmoid_mul`, which already accepts a strided 3-D gate: 201 MB written and read again per layer at
  16384 tokens.

## Modifications

1. `fused_qk_rmsnorm_rope_gate.py`: on HIP, launch with `num_warps=1` (one wavefront per program). `qwen3_5.py`: the fused
   path takes the token count from `qkv` (the fused allreduce + RMSNorm input can be an (fp8, scale) or MXFP4 tuple). The
   kernel's unit test is registered for AMD CI.
2. `fused_qk_gemma_rmsnorm_rope_gate(..., copy_gate=True)`: with `copy_gate=False` the kernel skips the gate stores
   (`COPY_GATE` constexpr) and returns the gate heads as a strided view of `q_gate`. The Qwen3.5 attention passes
   `copy_gate=False` and hands the view to the output gate. Not ROCm-specific; the default keeps the current behaviour for
   other callers.

## Accuracy Tests

- Commit 1: same kernel, other launch; against the previous ROCm path the gate is identical and q / k differ by one bf16
  ulp in ~5 ppm of the elements at 64-16384 tokens (fp32 operation order). Commit 2: q, k and the gated attention output
  bit-identical (12 cases, 1 to 16384 tokens).
- `test/registered/kernels/ops/attention/test_fused_qk_rmsnorm_rope_gate.py` (new `test_gate_view_without_the_copy`: q and
  k equal with and without the copy, the view points into `q_gate` and equals the copied gate, `fused_sigmoid_mul` gives
  the same bytes from the view): MI355X, this branch, 4 passed, 5 subtests.
- End to end (Qwen3.8-27B MXFP4, one MI355X, TP1), after each commit: greedy output ids identical to before on four
  reference prompts (100k-200k tokens and a short one); needle-in-a-haystack 30/30 at 100k-200k tokens; GSM8K-200
  (`sglang.test.few_shot_gsm8k`) 0.950 / 0.955 (0.920-0.960 on this build without the change).

## Speed Tests and Profiling

MI355X, Qwen3.8-27B shapes (24 q / 4 kv heads of 256, rotary dim 64, interleaved mrope), per full-attention layer, kernel
time from 10 back-to-back calls, median of 15:

| tokens | two ROCm kernels (before #45529) | fused, 4 warps (#45529) | fused, 1 warp (commit 1) | + no gate copy (commit 2, incl. output gate) |
|---|---|---|---|---|
| 16384 | 571 us | 542 us | 274 us | Q/K kernel 270 -> 201 us, output gate 106 -> 97 us |
| 8192 | 292 us | 272 us | 137 us | Q/K kernel 140 -> 99 us |
| 2048 | 60 us | 48 us | 28 us | |
| <= 256 | ~36 us | ~26 us | ~26 us | |

At 16384 tokens 2 warps take 425 us and 8 warps 866 us.

End to end: Qwen3.8-27B MXFP4 (`amd/Qwen3.8-27B-Quark-AWQ-MXFP4`), one MI355X, TP1, chunked prefill 16384, FP8 KV cache,
`--cuda-graph-backend-prefill breakable`. `python3 -m sglang.bench_serving --backend sglang-oai-chat --dataset-name random
--random-range-ratio 1.0 --random-output-len 1 --max-concurrency 1 --request-rate inf --num-prompts 32 --warmup-requests 1
--flush-cache`; same GPU, before / after / after / before; change of the mean of each side's two median TTFTs:

| input tokens | fused kernel at 1 warp vs two ROCm kernels | commit 2 |
|---|---|---|
| 100000 | -29 ms (-1.03%) | -9 ms (-0.36%) |
| 120000 | -31 ms (-0.89%) | -10 ms (-0.31%) |
| 140000 | -36 ms (-0.82%) | -7 ms (-0.16%) |
| 160000 | -39 ms (-0.76%) | -15 ms (-0.30%) |
| 180000 | -41 ms (-0.67%) | -13 ms (-0.23%) |
| 200000 | -28 ms (-0.40%) | -13 ms (-0.18%) |

The first column measures the fused path with commit 1 against the two ROCm kernels (median TTFT 2.792 s at 100k, 7.147 s
at 200k before); by the kernel table, ~90% of that saving (268 of 297 us per layer at 16384 tokens) is commit 1's launch.
Commit 2: median TTFT 2.581 s at 100k, 6.823 s at 200k before; both "after" runs faster than both "before" runs at every
length; the Q/K kernel's time per 16384-token chunk in a profile of a 200k-token prompt goes from 4.89 to 3.58 ms.
