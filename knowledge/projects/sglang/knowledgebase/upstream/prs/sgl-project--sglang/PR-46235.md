# [Fix] diffusion: Preserve metrics collectives after output save errors

[Upstream PR](https://github.com/sgl-project/sglang/pull/46235) · state: closed · merged: True

## Original PR description

## Summary

Keep replica ranks aligned when output persistence fails with perf/memory collection enabled.

Only the output rank saves the generated file. Previously, a save error skipped its replica peak-memory collective while peers still entered it. The affected job failed, but subsequent healthy requests could time out because the other ranks were stuck. This moves the existing memory finalization into `finally`, without swallowing the original save error or changing the success path's collective count.

## Tests

- Extend the existing perf-report test: the output rank must still join memory collection on failure, propagate the save error, and avoid writing a successful perf report.
- Add a small Wan HTTP/GPU regression covering single GPU, dynamic batch2, DP2, Ulysses2, TP2 and CFG2. It exercises concurrent/multi-output jobs, queued deletion, output-save failure, RPC timeout, late results and subsequent generation. Recovery videos are decoded and compared with a same-topology serial reference.
- Single- and two-GPU CI lanes run their respective cases once, on diffusion partition 0. No new model family, GT, or relaxed thresholds.

The production change is limited to one existing finalization function. This is independent of #45919; it does not add progress reporting, persistent jobs, worker failover, or recovery from arbitrary CUDA faults. RPC timeout still does not cancel GPU work.

## Validation

Dedicated H200 development environment, Wan2.1-T2V-1.3B-Diffusers, 512x320, 17 frames, 4/12 steps, seed 42. PyTorch 2.14.1+cu130, CUDA 13, Transformers 5.19.0, Diffusers 0.37.0.

- Before the fix: the targeted unit regression fails; the real Ulysses2 test reproduces a scheduler timeout on a healthy request after the injected save failure.
- After the fix (`b1071bde545`): 13 unit tests pass; real registered-entry-point E2E passes all six configurations (four two-GPU cases in 356.14s, two one-GPU cases in 153.43s). Recovered decoded frames match their same-topology serial references. The final GPU process list is empty.
- Pre-commit passes, including the registered-test checks. The 1-GPU and 2-GPU runs explicitly skip the other lane's configurations rather than counting them twice.

This is functional recovery coverage, not a latency benchmark or long-duration availability guarantee.
