# [DSA] Harden CUDA TileLang raw FP8 KV writes and validation

[Upstream PR](https://github.com/sgl-project/sglang/pull/44012) · state: closed · merged: False

## Original PR description

## Motivation

Extend the CUDA TileLang raw FP8 KV path added in #42957. Kernel dispatch currently accepts packed rows and CUDA-incompatible E4M3FNUZ tensors until a lower-level failure; attention CP is not rejected by the raw-layout validation. CUDA raw KV writes also use separate casts before scattering despite an existing fused writer.

## Modifications

- Reject FP8 KV rows whose width differs from the query and reject E4M3FNUZ on CUDA before kernel dispatch.
- Validate resolved `attn_cp_size` alongside the existing DCP constraint, retaining the existing mixed-backend and HiSparse checks.
- Select the fused cast/paged writer by raw versus scaled layout, including NoPE-only inputs with no RoPE tensor.
- Add numerical, masking, negative-control and page-boundary coverage, plus a model-accuracy report and sampled IDs/hashes. The raw layout remains unscaled; this does not add support for group-scaled packed KV rows.

The earlier raw-layout CUDA approach is documented in #36904. Already merged allocator/backend routing and the existing NoPE kernel logic are retained rather than duplicated.

## Speed Tests and Profiling

No new end-to-end serving benchmark or profile was run for this upstream port, and no throughput gain is claimed. The raw writer uses the existing fused cast/write kernel instead of separate casts and scatter. For a 512-dimensional NoPE row, raw FP8 stores 512 bytes versus BF16's 1024 bytes; this describes row storage, not a measured serving speedup.
