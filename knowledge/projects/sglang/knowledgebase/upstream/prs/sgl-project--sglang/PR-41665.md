# [AMD][MoE] Add a regression test for the aiter ungrouped shared-expert column

[Upstream PR](https://github.com/sgl-project/sglang/pull/41665) · state: open · merged: False

## Original PR description

## Motivation

Regression coverage for the aiter ungrouped-router shared-expert slot accounting
fixed in #40943. The failure mode this locks down is silent: the routed/shared
split can be wrong while the final `topk_ids` width stays correct, so nothing
raises and only the routing quality degrades. 

This surfaced while tuning MiniMax-M3 for **vision-language serving**, where
the shared-expert fusion path is on the per-token decode path of an
image-conditioned workload. 

## What this does

The gate stand-in `_fake_gate` encodes `moe_fused_gate`'s real width contract
(K = total topk columns, last `num_fused_shared_experts` of them filled with
`num_experts + (slot - K_routed)`), including the `topk > num_shared` assertion,
so the fake cannot drift into being more permissive than the kernel.

Runs on any host: the append path reads only `num_fused_shared_experts` and
`_use_aiter`, so `_use_aiter` is patched on and `_is_cpu` off (the only gate on
the JIT gate dispatch). Registered CPU-only, no accelerator required.

## Test plan

`python -m pytest test/registered/unit/layers/moe/test_aiter_fused_shared_experts_append.py`
— 1 passed locally on CPU, against current upstream `main`, i.e. against the
shipped fix rather than a local variant of it.
