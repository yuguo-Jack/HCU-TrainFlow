# [Perf] scheduler: Plan hybrid Mamba extend batches without host-device syncs

[Upstream PR](https://github.com/sgl-project/sglang/pull/45472) · state: closed · merged: True

## Original PR description

## Motivation

With the overlap scheduler, every implicit host-device sync in extend planning waits for the forward that is already running, so the scheduler cannot get ahead of the GPU. On hybrid Mamba models with `--mamba-radix-cache-strategy extra_buffer` or `extra_buffer_lazy`, planning one extend batch synced several times per batch and once more per request. Counted with `torch.cuda.set_sync_debug_mode` on the extend scheduling path:

- `HybridReqToTokenPool.alloc` indexed two device mappings with a Python list (a pageable copy each).
- `_mamba_radix_cache_v2_req_prepare_for_extend` read each request's ping-pong slot id with `.item()`, and `prepare_for_extend` then copied the ids, mask and seqlens back to the device from pageable memory.
- The lazy strategy's "is the other ping-pong entry free" checks, the ping-pong frees (`free_mamba_cache`, streaming-session release) and `kv_mamba_slots` all read `-1` flags off the device buffer.
- Clearing a ping-pong entry assigned the Python int `-1` into a CUDA tensor, a pageable copy that blocks the host until the stream drains.
- `MambaPool.clear_slots` and the ReplaySSM fresh-row reset wrote zeros through list or expanded-tensor indexing.
- `_get_multimodal_mask` used `torch.isin`, which switches to a `unique()`-based path (and syncs on its count) once there are enough placeholders.

#43637 removes two of these sites (the list index in `alloc` and the device-side track indices in `prepare_for_extend`) by keeping per-request device views; this PR covers the same two sites with a single gather from the pool mapping, plus the remaining ones above, so the two overlap on those hunks.

## Modifications

- `ReqKvInfo.mamba_ping_pong_empty` mirrors on the host which entries of the ping-pong buffer hold no slot. `_alloc_ping_pong_buffer` sets it with the buffer, `set_mamba_ping_pong_slot` flips it on every write, and every reader of `buf != -1` (lazy prepare in `schedule_batch.py`, the batch result processor, `free_mamba_cache`, `StreamingSession` release, `kv_mamba_slots`) reads the flags instead. `free_mamba_cache` frees every surviving entry by position, with no device mask. The MLX auxiliary-state pool and model runner set and clear the flags with the buffer like the CUDA pool.
- `prepare_for_extend` records each request's track *position* (`_MambaRadixCacheV2TrackEntry.track_position`) and gathers the slot ids on the device from `req_index_to_mamba_ping_pong_track_buffer_mapping` with one advanced index (`_gather_mamba_track_indices`); `set_mamba_track_indices_from_reqs` uses the same gather. Track positions, mask and seqlens are staged pinned and copied `non_blocking`.
- `HybridReqToTokenPool.alloc` writes its two mappings through a device row index (`async_h2d`); ReplaySSM fresh rows reset through `index_fill_`; `MambaPool.clear_slots` zeroes with `index_fill_` on every branch, the fused conv kernel staying the fast path; `set_mamba_ping_pong_slot` clears an entry with `fill_(-1)`.
- `UnifiedMambaPool` sets `replayssm_spec_write_pos` like `MambaPool`, so `alloc()` reads it as a plain attribute instead of `getattr`.
- `embed_mm_inputs` sorts the placeholder ids once on the host and `_get_multimodal_mask` looks them up with `searchsorted`; an empty placeholder tensor is an assertion.

Behaviour is unchanged: the same slots are tracked, freed and cleared; only where the bookkeeping is read and how the writes reach the device change.

## Tests

New and updated unit tests (all CPU, `base-a-test-cpu`):

- `test_mm_chunked_embedding_unit.py`: the `searchsorted` mask equals the broadcast compare and `torch.isin` on host-sorted placeholders, including a repeated placeholder and int32 ids, at sizes on both sides of `torch.isin`'s sort threshold.
- `test_unified_tri_pool.py`: over a CPU unified pool, the mapping rows equal the request buffers after `alloc()`, donate and set, and the device gather equals the per-request `.item()` reads it replaces; the hand-built kv fixture sets the flags with the buffer.
- `test_mamba_checkpoint_depth.py`: the track position is taken before the ping-pong swap, for both starting positions.
- `test_batch_result_processor_mamba_boundary.py`: calls the production `set_mamba_track_indices_from_reqs` with no pinning shim; the boundary fixture sets the flags.

Run locally on CPU: the four files above plus `test_mamba_capacity.py`, `test_batch_result_processor_spec_grammar.py`, `test_mamba_unittest.py` and `test_unified_radix_cache_core.py` (the other callers that build ping-pong fixtures) pass.
