# [Fix] [NPU] qwen3-asr: Support compiled decode graph capture and replay

[Upstream PR](https://github.com/sgl-project/sglang/pull/44388) · state: open · merged: False

## Original PR description

## Motivation

Addresses #43958: Qwen3-ASR compiled Decode capture fails on Ascend even with CPU offload disabled. This PR includes the shared forward-tracing prerequisites and the NPU graph implementation together so that the fix can be tested end to end.

## Modifications

- Keep cached platform detection outside Dynamo tracing; make residual contributions and exit decisions traceable dataclasses, and construct the static exit policy before forward.
- Explicitly check the Qwen3 auxiliary-state list length, avoiding an incorrect tuple result from compiled forward with an empty list subclass.
- Add a compile-only boundary for the existing NPU fused QKV/RMSNorm/RoPE operation; leave eager execution unchanged.
- Route eligible plain-MHA compiled Decode through graph metadata. Register a TorchNPU graph handler that captures native FIA `.out`, preserving named sequence-length updates during replay rather than capturing stale Python lengths.
- Scope the new attention route away from MLA, sliding-window/hybrid pools, FA, ALiBi, cross attention, sinks and logit caps. No CANN kernel math changes.
- Register checkpoint-free dynamic-replay tests in `per-commit-1-npu-a2`, under `test/registered/npu/basic_function/optimization_debug/test_npu_compiled_mha.py`, with an executable pytest entry point. Add five shared-code compile regression cases.

## Accuracy Tests

**Same-stack text regression completed:** All runs below use torch-npu 2.10.0.post6, A2 TP1 BF16, the same Qwen3-0.6B weights and sampling parameters (temperature=0, max_new_tokens=64). Each mode runs four serial plus sixteen concurrent requests.

- Candidate eager, ordinary Decode graph, and compiled Decode graph: 60/60 requests succeed. Compiled vs ordinary graph: 20/20 texts and all returned per-step top-5 logprobs exactly match.
- Unmodified production-source baseline eager and ordinary graph: 40/40 requests succeed. Each baseline mode exactly matches its corresponding candidate mode for all 20 texts and returned top-5 logprobs.
- Eager vs graph differs for the repeated code-writing prompt, both before and after this patch (15/20 texts match). First differing output token is index 31: eager prefers token 10306 over 4211 by 0.0625 logprob; graph gives both -2.543215274810791 and selects 4211. Compiled graph reproduces the ordinary graph result. Thus the observed divergence predates this patch; it is not introduced by compilation in this regression set.
- These checks compare returned top-5 logprobs, not complete logits or layerwise tensors; they are not a comprehensive model accuracy benchmark. The initial cross-version comparison has been superseded by this controlled experiment.

Hardware: Ascend A2 910B3, TP1 BF16. CANN 9.0.0, kernel 2026.9.0, torch 2.10.0; tested torch-npu 2.10.0 and 2.10.0.post6. CPU offload disabled, Prefill graph disabled, compiled Decode capture sizes 1/2/4/8.

- Qwen3-ASR-0.6B: 96 successful audio requests, including concurrency up to eight, all transcriptions exactly matching the eager reference on the same four public audio samples. This is not a full WER evaluation or a logits-level equivalence claim.
- Seven NPU tests pass: length updates 1→2→1, unequal per-row lengths, live KV values and block-table page changes, plus fused QKV parity at multiple batch sizes. Both TorchNPU versions tested; the final extra page-change assertion was rerun on post6.
- Five new shared-code regression cases fail on unchanged production code and pass with the fix.
- Related unit group: 375 passed after excluding the CUDA/CuTe-specific test file. The unfiltered baseline and candidate both have the same ten failures in that file in this A2 environment.
- Full pre-commit and git diff whitespace checks pass locally.

Not validated: A3/A5, TP>1, CPU offload, Prefill compilation, Omni pipelines or all attention variants. This PR does not fix or supersede the separate pinned CPU-offload work in #43824.

## Speed Tests and Profiling

Functional compile/capture/replay regression, not a performance optimization claim. No controlled throughput/latency benchmark is provided. Eager continues using the original QKV implementation.
