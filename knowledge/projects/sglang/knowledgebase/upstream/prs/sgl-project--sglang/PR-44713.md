# [Fix] hicache: Reset storage existence cache on backend attach

[Upstream PR](https://github.com/sgl-project/sglang/pull/44713) · state: open · merged: False

## Original PR description

## Motivation

In `buffer_only` mode, detaching a storage backend and attaching another retains the old storage existence cache. For example, after switching the `file` backend from directory A to an empty directory B, pages stored in A are still considered present and their backups to B are skipped. A later storage-query miss can invalidate these entries, but the backend change itself leaves them stale.

## Modifications

Clear the storage existence cache after a new backend is successfully attached. Policy updates on the currently attached backend, failed attachments, and rejected backend changes preserve the existing entries.

Add CPU regression tests for switching between two file directories, invalidating KV and auxiliary-pool entries, and preserving entries on the other paths.

## Validation

- The five new tests pass on two Linux x86_64 hosts with Python 3.11.2 and PyTorch 2.10.0+cpu. On the original code at `a448fdf`, the empty-backend backup test and the pool-invalidation test fail.
- Combined with the existing buffer-mode sidecar, prefetch lifecycle, scheduler attachment, and anchor-lock tests: **30 tests and 19 subtests passed on each host**.
- Changed-file pre-commit checks passed, including the repository-wide test registry check.

The new tests use a mocked controller lifecycle and real `HiCacheFile` I/O. Model inference and accelerator transfers were not tested. The four existing `TestUnifiedRadixCacheStorageAttachBackfill` tests could not initialize a device in this environment; CPU-engine mode also requires the unavailable `sgl_kernel` package.

Run the new regression tests with:

```bash
python test/registered/unit/mem_cache/test_storage_attachment.py
```
