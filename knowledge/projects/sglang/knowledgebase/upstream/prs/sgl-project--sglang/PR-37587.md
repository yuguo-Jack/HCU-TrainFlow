# [Fix] attention: Pad hybrid target verify to complete request groups

[Upstream PR](https://github.com/sgl-project/sglang/pull/37587) · state: open · merged: False

## Original PR description

## Motivation

MLP synchronization can pad an eager target-verify batch beyond its logical token count. With 38 requests and a verify width of 6, the recurrent path has 228 logical tokens while TP8 synchronization produces 232 physical rows. Fixed-width hybrid recurrent kernels cannot interpret those 232 rows as complete six-token request groups:

```text
RuntimeError: shape '[38, 6, -1]' is invalid for input of size 237568
```

The previous revision trimmed recurrent inputs back to the logical prefix and repaired each backend around the resulting split logical/physical domains. This revision instead fixes the invariant at the shared MLP-sync batch boundary: fixed-width hybrid target verify is padded only in complete request groups.

This fixes the shared hybrid-linear path in #37585; the GLM DSA KPool path remains handled separately in #37588.

## Modifications

- For non-ragged hybrid target-verify and synchronized idle batches, align token counts to `lcm(attn_tp_size, num_tokens_per_req)` before choosing DP `MAX_LEN` or `SUM_LEN` padding.
- Preserve one collective-facing physical domain while ensuring every recurrent request is a complete fixed-width group.
- Preserve current main's reserved mamba slot 0 for eager padding. Keep negative-slot kernel requests safe by zeroing their outputs and skipping absent state/tree metadata.
- Use the shared target request width on coordinated prefill/verify ranks, so their gathered padding counts agree even when local forward modes differ.
- Restore chunked-prefill outputs to the original query-token count before passing hidden states to the draft model; cached prefixes are not output rows.
- Cover whole-group alignment, DP `MAX_LEN`/`SUM_LEN`, coordinated prefill/verify, reserved slot-0 metadata, unaffected modes, and output restoration.
- Cover dummy convolution/recurrent requests, short metadata, tree cases, and both reserved slot 0 and negative slots in the opt-in fused KDA path.

For TP8 and verify width 6, the alignment is 24 tokens. For example, 38 requests change from 228 logical / 232 TP-padded rows to 228 logical / 240 physical rows, representing 40 complete request groups.

## Validation

### Real mixed attention-DP validation on `cf384e9b9f`

A real attention-DP2 run exposed a follow-on bug in the previous head `8614b200c6`: target ranks agreed on `[12, 516]` for `[6, 512]` query counts and completed, but the second prefill chunk passed 516 hidden-state rows to a 512-token draft extend. `post_forward_mlp_sync_batch` used `seq_lens_sum`, which includes cached prefixes. It now restores the recorded original query-token count. A focused regression fails on the old installed wheel and passes on the new wheel.

Built and installed the wheel from clean commit `cf384e9b9f`; loaded source files matched the commit. Qwen3.5-35B-A3B on 8xH20, TP8/EP8, attention-DP2/attention-TP4, Triton GDN, FA3, DeepEP/DeepGEMM, NEXTN 5/1/6 (resolved EAGLE), deterministic inference, context 16384, resolved prefill chunk 512. DP spec/prefill coordination was explicitly enabled; decode Graph remained enabled and prefill Graph was disabled.

- **60 real mixed coordination cycles**, 30 with each prefill-rank direction. Every cycle recorded EXTEND on one DP rank and TARGET_VERIFY on the other, with all eight TP ranks completing target and the full draft/target/draft-extend sequence.
- All ranks derived the same LCM-aligned counts, including `[6, 512] -> [12, 516]` and the reversed direction; every observed cycle exercised padding.
- **18/18 requests passed**. All six mixed prefill outputs and both mixed decode outputs exactly matched isolated greedy outputs; subsequent isolated decodes also matched. Requests were routed explicitly, and prefill was submitted only after the peer streamed its first decode token while still running.
- Related MLP-sync and DP-coordination tests: **33 passed, 79 subtests passed**. The new query-unpadding regression also passed separately against the installed wheel. Changed-file pre-commit passed.

This validates the tested hybrid mixed-phase path, not a throughput or full model-accuracy claim.
