# [Fix] glm47: Buffer streaming tool calls until complete

[Upstream PR](https://github.com/sgl-project/sglang/pull/39493) · state: open · merged: False

## Original PR description

## Motivation

The GLM 4.7/5.x parser currently streams argument JSON through a character-level XML-to-JSON state machine for schemas that do not require sibling context.

The complete parser already has the schema-aware conversion needed to serialize the arguments canonically. Using it for every completed tool call removes the second argument-conversion path and makes the result independent of token and SSE chunk boundaries.

Related work: #35625 and #36688 address broader streaming/non-streaming parity issues. This PR is deliberately limited to the GLM 4.7/5.x detector and the buffering behavior already introduced for context-dependent schemas in #39136.

## Accuracy Tests

- The focused `TestGlm47MoeDetector` regression passed on the production-pinned branch before rebasing this commit onto current `main`.
- The same call was tested at all 148 possible character split points; each split reconstructed the same arguments as the complete parser.
- A live 48-request concurrent streaming stress run reconstructed valid JSON with the requested values in all 48 responses.
- `git diff --check origin/main...HEAD` passes after the rebase.
