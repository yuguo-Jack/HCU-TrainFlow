# [Refactor] detokenizer: Move the incremental decode state and step into incremental_detokenize.py

[Upstream PR](https://github.com/sgl-project/sglang/pull/47338) · state: closed · merged: True

## Original PR description

Move the detokenizer's per-request incremental decoding state out of `detokenizer_manager.py` into a new module, `incremental_detokenize.py`. No behavior change.

- `DecodeStatus` becomes `DetokenizeState`, a `msgspec.Struct`, and gains `decode_inputs` and `step`, which hold the per-row id slicing and the text step that `_decode_batch_token_id_output` ran inline.
- `DetokenizeStateTable` wraps the capacity-limited dict and owns creating, extending and releasing each request's state.
- `_clamp_decode_ids`, `LimitedCapacityDict` and the state cap move with them; the cap's env var, `SGLANG_DETOKENIZER_MAX_STATES`, is now registered in `Envs` and read through `envs` (same default, still read at import); `DetokenizerManager` keeps the row loop, the grouped batch decode, the beam path and building `BatchStrOutput`.

## Verification

- Every moved body is byte-identical to the old one, or identical after listed substitutions (`s.` to `self.`, `recv_obj.x[i]` to a parameter, `output_strs.append(x)` to `return x`); an AST comparison accounts for every changed unit.
- The only observable differences are at the crash level: the missing-state `RuntimeError` keeps its message but no longer chains a `KeyError`, and `DetokenizeState` is no longer a dataclass (nothing used `dataclasses` helpers on it).
- Detokenizer, router, stop-trim, beam-decode and output-streamer unit tests pass.
