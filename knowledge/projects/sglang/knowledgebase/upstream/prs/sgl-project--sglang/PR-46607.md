# [Fix] responses: Align K3 input token usage with Chat

[Upstream PR](https://github.com/sgl-project/sglang/pull/46607) · state: open · merged: False

## Original PR description

## Motivation

K3 Chat already excludes its assistant generation stub from reported input tokens, but Responses still uses the raw engine count. The same rendered input is therefore reported three tokens higher through `/v1/responses`, in both ordinary and streaming responses.

This is the Responses-side gap noted as out of scope in #35776. #46549 handles the separate Messages count endpoint.

This focused fix is also included in the combined usage feature #46091. Keeping this PR open preserves the smaller review path; the combined PR's validation does not replace evidence for this head.

## Modifications

Reuse Chat's reporting helper after the ordinary response's metadata/ID fallbacks and when a stream supplies a new raw prompt count. Keep the last reported count on chunks without that field, so the stub is never deducted twice. K3 streaming totals use the reported prompt plus completion count. Cached-input details are capped at the reported prompt length, without deducting the stub from partial cache hits. Other models' metadata totals and Harmony accounting stay unchanged.

## Accuracy Tests

Based on main `316ff4dce2f0`.

The focused CPU replay runs the actual production generators, output parsing, real protocol models and OpenAI SSE event serialization. The new cases fail on the baseline and pass with the patch. They cover all three ordinary count sources, streamed chunks with and without repeated prompt metadata, raw engine totals, short inputs, the shared stub setting and a non-K3 control. Cache details are enabled: near-full hits stay within the reported input, partial hits retain their original count, and zero reported input cannot expose cached tokens. A replay of the initial prompt-only patch also reproduces the cache-detail failures before this bound is applied.

The fixture bypasses package/startup imports and supplies a text-only serving object; it is not a full-package, HTTP or GPU run. The package-level regressions still need CI:

```bash
PYTHONPATH=python python -m pytest -q \
  test/registered/unit/entrypoints/openai/test_serving_responses.py \
  test/registered/unit/entrypoints/openai/test_serving_responses_stream.py \
  -k 'prompt_usage or full_response_uses_dict_meta_info_for_usage'
```

Ruff, isort, codespell and the affected registered-test checks pass.
