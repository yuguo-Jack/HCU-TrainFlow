# [Fix] Order EAGLE draft-extend planning after input producers

[Upstream PR](https://github.com/sgl-project/sglang/pull/40026) · state: closed · merged: False

## Original PR description

## Motivation

Closes #40025.

With the optional overlap plan stream enabled, draft-extend metadata preparation needs a dependency on the stream that produced its inputs. The existing reverse join only protects the later compute-stream forward.

Related work: #28034 covers broader spec-v2 ordering races; #37980 covers the draft/tree-to-verify handoff. This patch is limited to the current single- and multi-layer draft-extend entry points.

## Modifications

- Single-layer: wait for the current producer stream before entering the plan-stream context, after the next-token int64 cast.
- Multi-layer: add the same wait only when the existing boundary-KV event is absent. Preserve the event path and avoid an additional wait when that event already orders the inputs.
- Keep the plan-stream-disabled path free of new device queries or waits.
- Add seven CPU source-prefix dependency tests covering enabled/disabled paths and multi-layer boundary-event/staged combinations. The tests execute the actual preparation prefix with stream stand-ins; they do not load CUDA or model weights.

## Accuracy Tests

- Seven CPU cases pass on the patch.
- Against unmodified public base `6c73368c329f811472829927d7185f189e3c8ff3`, the single-layer enabled case and both multi-layer no-boundary cases fail as expected; the other four pass.
- These are dependency-contract tests, not GPU numeric or end-to-end model-accuracy tests. Public-patch GPU validation is not yet run.

## Speed Tests and Profiling

Not run on this public patch. The default-off path is unchanged. With the flag enabled, the missing dependency intentionally constrains overlap until the producer completes; no throughput-neutrality claim is made.
