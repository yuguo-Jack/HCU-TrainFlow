# [Fix] diffusion: HunyuanImage-3 MoE shared MLP and timestep schedule on CUDA

[Upstream PR](https://github.com/sgl-project/sglang/pull/46600) · state: closed · merged: True

## Original PR description

## Motivation

Fixes #46461

HunyuanImage-3 generation on CUDA produced a noise texture (on main too). Split out of #46454 at the maintainers' request so the correctness fixes can land first.

1. **Shared MLP ordering.** The MoE block ran the routed experts before the shared MLP. On CUDA the Triton `FusedMoE` path runs in place (`inplace=True` by default) and overwrites `hidden_states` with the expert output, so the shared MLP read the expert output instead of the layer input and every MoE layer was wrong. The NPU path (AscendTPDispatcher) is not in place, which is likely why the NPU validation in #36311 did not see it. srt's own Hunyuan model already runs the shared MLP first.
2. **Timestep schedule.** Match the official `FlowMatchDiscreteScheduler` schedule, `shift(linspace(1, 0, N + 1))[:-1]` (`use_uniform_sigmas=True`). The old setup shifted the training-sigma range a second time; for 10 steps the last timestep was 8.93 instead of 250.

## Modifications

- `hunyuan_image3.py`: `HunYuanSparseMoeBlock.forward` runs the shared MLP before the in-place experts.
- `pipelines/hunyuan_image3.py`: build the scheduler with the official schedule.
- `test_hunyuan_image3_tp_broadcast.py`: two focused regression tests.

## Accuracy Tests

- `test_shared_mlp_sees_layer_input_when_experts_run_in_place`: the shared MLP sees the layer input when the experts overwrite their input.
- `test_timesteps_follow_official_schedule`: timesteps match the official formula.

With only the two source files reverted, exactly these two tests fail. CUDA end-to-end numbers (noise texture before, correct images after, parity vs the fixed baseline) are in #46454.

## Follow-up

The prefix K/V cache stays in #46454 and will be rebased on top of this PR once it lands.
