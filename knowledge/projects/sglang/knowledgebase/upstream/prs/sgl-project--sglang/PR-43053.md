# [Fix] simulator: Cache random text requests once

[Upstream PR](https://github.com/sgl-project/sglang/pull/43053) · state: open · merged: False

## Original PR description

## Motivation

Iterating a `RandomDataset` for eight requests returns eight entries containing only four distinct request objects and prompts. `RandomIDsDataset` already caches each generated request, and `RandomDataset` appends the same object again after decoding it. This introduces paired duplicate prefixes into random simulator workloads.

## Modifications

Remove the second cache insertion and keep the parent responsible for caching. Add CPU regression coverage through the public dataset factory using the repository's tokenizer assets, covering independent sequential requests, cached rereads, slices, and both text and token-ID modes.

## Accuracy Tests

Rebased onto `9fa9308e95`, which contains the required base `ff8d964cf5`. On this source, both dataset-cache regressions pass on CPU; the duplicate-request cache regression fail with the unmodified main production code.

`pre-commit run --all-files` passes, including the Rust formatting and Clippy checks.

Validation covers dataset generation and caching through the public factory. The simulator-server/model-inference test is outside this dataset regression run.
