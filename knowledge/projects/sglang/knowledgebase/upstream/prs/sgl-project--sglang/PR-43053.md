# [Fix] simulator: Cache random text requests once

[Upstream PR](https://github.com/sgl-project/sglang/pull/43053) · state: closed · merged: False

## Original PR description

## Motivation

Iterating a `RandomDataset` for eight requests returns eight entries containing only four distinct request objects and prompts. `RandomIDsDataset` already caches each generated request, and `RandomDataset` appends the same object again after decoding it. This introduces paired duplicate prefixes into random simulator workloads.

## Modifications

Remove the second cache insertion and keep the parent responsible for caching. Add CPU regression coverage through the public dataset factory using the repository's tokenizer assets, covering independent sequential requests, cached rereads, slices, and both text and token-ID modes.

## Accuracy Tests

Rebased onto `f1ba723c64`, including the required base `6a39ddf1f2e0`.

Both dataset-cache regressions pass on CPU through the public factory and repository tokenizer assets. Unchanged main repeats four request objects across eight entries; the fixed source returns eight independent requests and preserves cached rereads and slices.

Pre-commit checks pass on the changed files. The common main tree also passes `pre-commit run --all-files`, including Rust formatting and Clippy.

Validation covers dataset construction and caching; the simulator-server/model-inference test is outside this regression run.
