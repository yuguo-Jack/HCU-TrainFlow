# [Perf] cuda-graph: Raise the decode graph ceiling default to 128 for 35 to 60 GiB GPUs

[Upstream PR](https://github.com/sgl-project/sglang/pull/46132) · state: open · merged: False

## Original PR description

## Motivation

The default decode graph ceiling reads 8, 48, 32, 256 up the memory tiers, so a 46 GiB L40S or A40 runs decode eager above batch 32, earlier than a 24 GB card. Related to #33483.

## Modifications

The 35 to 60 GiB tier defaults to 128 when tp_size < 4. The test checks the ceiling never drops as memory grows. It fails on main. I left the 20 to 35 GiB tier to #40346.

## Accuracy Tests

No model or kernel code changed.

## Speed Tests and Profiling

L40S, SGLang 02b983603d34c6af09e554ed2b8bf8d85290d9ae, closed loop, 128 in and 256 out. Output tokens/s of ceiling 128 over the default, one run each except the 8B (two, within 0.2%):

| Model | C=32 | C=48 | C=64 | C=128 |
|---|---|---|---|---|
| Qwen3-8B | +0.1% | +2.3% | +2.1% | +1.7% |
| Qwen3-4B | -0.4% | +3.3% | +3.3% | +2.4% |
| Qwen3-1.7B | +0.2% | +32.5% | +21.0% | +6.4% |
| Qwen3-0.6B | +0.2% | +119% | +90% | +31% |

The 8B gains about 2%, and the 0.6B more than doubles at C=48 (median TPOT 10.9 to 4.8 ms). Ceiling 128 costs the 8B 0.19 GB of graph memory, 0.9 s of capture and 1.0% of KV tokens.

```
python -m sglang.launch_server --model-path Qwen/Qwen3-8B [--cuda-graph-max-bs-decode 128]
python -m sglang.benchmark.serving --backend sglang --dataset-name random --random-input-len 128 --random-output-len 256 --random-range-ratio 1.0 --max-concurrency C --request-rate inf --num-prompts N --flush-cache --seed 1
# N = max(128, 4*C), 8*C for the 1.7B and 0.6B
```

Not measured: open-loop arrivals, A100-40GB, speculative decoding.
