# [HiCache][AMD] Move page_first_direct pages with the gather kernel on ROCm

[Upstream PR](https://github.com/sgl-project/sglang/pull/42169) · state: closed · merged: False

## Original PR description

## Motivation

With `--hicache-io-backend direct --hicache-mem-layout page_first_direct`, every L2 (host DRAM) load and write-through backup is one tensor copy per (page, layer). On ROCm the batched-memcpy path is compiled out (`transfer.cu`, `kEnableHipBatch=false`), so a 160K-token GLM-5.2 load (2,500 pages × 78 layers × {MLA KV, DSA indexer}) is ~390K `hipMemcpyAsync` calls issued from the scheduler thread. It runs at ~3.4 GB/s against a ~57 GB/s pinned-copy peak and blocks the scheduler for ~2.4 s per batch.

In a PD prefill serving 120 multi-turn GLM-5.2 sessions (FP8 KV, TP4, MI355X), once the HBM radix cache overflows and hits come from L2, prefill throughput falls from ~9-10K to ~4K new tokens/s: 808 GB loaded back in 258 s (3.1 GB/s), 2.46 s per load.

## Modifications

- MLA and DSA indexer host pools (`mem_cache/pool_host/mla.py`, `dsa.py`): on ROCm, for `direct` + `page_first_direct`, loads and backups move whole pages with the existing AOT gather kernels (`transfer_kv_per_layer_mla_pf_lf` / `transfer_kv_all_layer_mla_lf_pf`), one launch per layer. The layout and the direct backend are unchanged, so the L3 (Mooncake) layout is too. No new AOT kernel. Other platforms keep the per-page copies.
- Pools above `SGLANG_HICACHE_HOST_REGISTER_CHUNK_GB` (256 GiB, e.g. a 300 GB/rank MLA pool) are registered in several page-aligned pieces. A kernel resolves one device-accessible base per launch, so the pages are grouped by the registration that holds them, and each group gets its own launch on a view of the pool that starts at the group's first page. The direct backend keeps its indices on the CPU, so the grouping is cheap.
- The kernel is used only when the pool's registrations are whole pages starting on OS-page boundaries, each (page, layer) block is a multiple of 8 bytes (the gather kernel's requirement; a 1-token DSA indexer page is 132 B), and the indices are whole pages. Anything else takes the per-page path. DSA indexer layers with a 0-row device buffer are skipped.
- Each MLA and DSA indexer host pool logs once, at INFO, which path `io_backend=direct` takes and why, for example `HiCache MLA kv host pool (page_first_direct): io_backend=direct uses the page gather kernel over 2 host registration(s) (104334 pages of 2875392 B).` A transfer whose indices are not whole pages is logged once as a warning.

## Tests

- `test/registered/unit/mem_cache/test_hicache_direct_page_kernel.py` covers:
  - page-id conversion and per-registration routing;
  - registration tiling, OS-page alignment and gating (ROCm only, whole pages, 8-byte blocks), with the logged path and reason;
  - real-pool `page_first_direct` round trips that are bit-identical to the per-page copy path, including 0-row indexer layers, over several host registrations (the registration limit mocked down so that pages fall in different registrations), and a page_size=1 round trip in which MLA takes the kernel and the DSA indexer keeps per-page copies.
- CPU: `test_hicache_direct_page_kernel.py`: 14 passed, 6 skipped (the GPU round trips). Together with `test_dsa_pool_host_unit.py`, `test_hicache_host_register.py` and `test_mla_host_dedup_primitives.py`: 35 passed, 8 skipped.
- GPU, 1x MI355X (gfx950), stock `lmsysorg/sglang-rocm:v0.5.20-rocm724-mi35x-20260919` image with this PR's source tree on `PYTHONPATH`, `test_hicache_direct_page_kernel.py`:
  - default environment (aiter preshuffle indexer, page_size=64): 17 passed, 3 skipped. All three `TestPageFirstDirectRoundTrip` round trips pass (kernel vs per-page copies, 0-row indexer layers, several host registrations). The 3 skips are the `TestPageFirstDirectRoundTripPageSize1` cases: `DSATokenToKVPool` requires page_size to be a multiple of 16 with the preshuffle indexer, and two of them are by design covered at page_size=64.
  - `SGLANG_DSA_HIP_DISABLE_PRESHUFFLE=1` (legacy indexer, page_size=1): the `TestPageFirstDirectRoundTripPageSize1` round trip passes (MLA takes the kernel, the DSA indexer keeps per-page copies, bit-identical to the memcpy path); the page_size=64 round trips skip because the legacy indexer requires page_size=1. 15 passed, 7 skipped.

Microbenchmark on 1× MI355X: a 160K-token random-page load with the real host-pool classes (78 layers, FP8 576 B, page 64), as a PD prefill with `--hicache-size 300` builds them. That is a 300 GB MLA pool (2 host registrations) plus a 68.75 GB DSA indexer pool. Loads are bit-exact on every config.

| Config | MLA path | Load | GB/s | Backup GB/s |
|---|---|---|---|---|
| direct + page_first_direct, per-page copies (MLA) + kernel (indexer) | 2 registrations → per-page | 2.09 s | 4.2 | 4.7 |
| direct + page_first_direct, gather kernel | kernel, 2 launches per layer | 0.135 s (3 ms CPU) | 65 | 53 |

With a single-registration pool (12 GB) the kernel path loads at ~56 GB/s, against 3.4 GB/s for per-page copies. Four GPUs loading at once take 0.30-0.41 s per load, against 2.6 s.
