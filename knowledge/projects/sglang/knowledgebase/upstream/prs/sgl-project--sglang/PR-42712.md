# [Fix] dspark: Calibrate STS temperatures from the drafts each step actually accepted

[Upstream PR](https://github.com/sgl-project/sglang/pull/42712) · state: open · merged: False

## Original PR description

## Motivation

`SGLANG_DSPARK_STS_COLLECT_PATH` collects (confidence logit, accepted-prefix) pairs that `dspark_sts_fit.py` uses to fit the per-position STS temperatures. The labels were wrong in two cases:

1. **Sampled requests.** Each step was labeled by re-running a greedy argmax match of the drafts against the target logits. For non-greedy requests, acceptance uses rejection sampling, so the labels described a different rule from the one that decided acceptance.
2. **Compact verify.** A request with verify length L checks only its first L - 1 drafts, but the argmax match ran over the full verify width. Drafts past the window were compared with the last real target row and then with zero-filled padding rows, so labels past the verify window can reflect comparisons outside that window. These positions should be excluded from fitting.

The new synthetic test scales confidence logits by 2.5 and uses random verify windows. It asserts that masked fitting selects temperatures between 2.5/1.5 and 2.5×1.5 at every position, and that the unmasked fit gives a last-position temperature above 1.5× the true value.

Every TP rank also wrote to the same shard paths.

## Modifications

- `DsparkStepObservers`: label with the step's `correct_len`, the number of drafts the step actually accepted (greedy or rejection sampling), capped at the verify window. Pass the verify layout's `verify_lens` to the recorder, along with the `confidence_raw` the observers receive from the caller (#43790). Collect on TP rank 0 only, as the confidence-metrics probe and `SGLANG_DSPARK_BLOCK_ACCEPT_ESTIMATE_PATH` already do (with attention DP, this records only DP rank 0's batches; separate DP replicas need separate collection paths). Raise on the collecting rank if `SGLANG_SIMULATE_ACC_LEN` is greater than zero, because its `correct_len` is synthetic.
- `StsDataRecorder`: also store `observed_mask`, with position p observed iff p < verify_len - 1 (all ones when no verify layout is supplied). Every row stops being observed past its window, including rows rejected inside it. Keeping only those rows would make every observed label at those positions a rejection.
- `dspark_sts_fit.py`: score each position's ECE and pick its temperature on observed samples only. Shards without `observed_mask` load as fully observed. The output JSON format is unchanged.

The collector records every verify step whose proposal carries `confidence_raw`, folded or not. Fitting a shard collected before this change, which has no `observed_mask`, logs a warning: its labels are right only for all-greedy runs with a static verify window (no compact verify or cap-accept).

## Accuracy Tests

`test/registered/spec/dspark/test_dspark_sts.py` (CPU), added or extended coverage:
- censored fit: `test_compact_verify_censoring_is_masked` runs `fit()` with and without `observed_mask`. Masked temperatures are within a factor of 1.5 of the true scale at every position; the unmasked last-position temperature is above 1.5× that scale.
- recorder: `observed_mask` for compact-verify windows, and all ones without a layout.
- collector: through `observe_verify_step`, with target logits whose argmax accepts every draft while the step accepted fewer, the labels and mask follow the step's `correct_len` and `verify_lens`. On main the labels follow the argmax.

All 14 tests in the file pass (CPU).
