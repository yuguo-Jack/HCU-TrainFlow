# [Perf] session: Cache multimodal prompt token counts across turns

[Upstream PR](https://github.com/sgl-project/sglang/pull/44112) · state: closed · merged: True

## Original PR description

## Motivation

Usage reporting counts the image, audio and video prompt tokens of a request by scanning every item in `req.multimodal_inputs`. The output streamer does this for each output row, and the PD metadata buffer does it once more on the prefill node. A streaming session shares its media history across turns, so a session that appends one audio chunk per turn rescans the whole accumulated history on every turn: the cost of reporting usage grows linearly with the number of turns instead of with the media actually added.

A second, smaller problem sits in the same code: disaggregated decode treated an all-zero transferred count as "not computed" and fell back to recounting locally, so the prefill-side result was authoritative only when it was non-zero.

## Modifications

- `Req` gains `get_mm_token_counts()`, which computes the per-modality counts at most once and caches them with an explicit `mm_token_counts_ready` flag, and `inherit_mm_token_counts(other)`, which copies the counts of a request whose media history is shared.
- `Session.create_req` inherits the counts from the previous turn when the new turn is a plain continuation. It does not inherit on abort or when a `session_params.offset` truncates the inherited history, so those cases fall back to a full count.
- `Req.extend_image_inputs` adds only the counts of the newly appended items when the counts are already cached.
- The output streamer and `MetadataBuffers.set_buf` both read through the accessor. `DecodeTransferQueue` marks the counts received from prefill as ready, so a transferred zero is final.

Behaviour of a single-turn request is unchanged; the change is that repeated reads are served from the cache.

Tests: a new `test_mm_token_counts.py` covers memoisation of all-zero counts and inherit-then-extend across a session turn; `test_session_token_share_unit.py` gains a case where an aborted turn's edits to the counts do not leak into the next turn. The existing `_FakeReq` fixtures in the output-streamer tests and the PD wire test gain the accessor. The three new cases fail on `main` and pass with this change.

## Accuracy Tests

Not applicable: usage token counts are bookkeeping and do not affect generation.

## Speed Tests and Profiling

Not applicable beyond the mechanism described above: with a cached count, appending one item to a history of N items costs one item scan instead of N+1.
