# [Feat] kv-compression: Share encoded KV across P/D transfer and HiCache L2

[Upstream PR](https://github.com/sgl-project/sglang/pull/40551) · state: open · merged: False

## Original PR description

## Motivation

Related to #39740 — Pluggable KV Compression for Disaggregated Serving.

This draft adds an optional shared KV compression layer to Mooncake P/D transfer and Prefill HiCache L2. The same encoded representation can be transferred, retained across requests, reused without re-encoding, and restored after GPU KV eviction. Attention continues to read the model's existing GPU KV layout and dtype.

The contribution is lifecycle integration: sharing representations while preserving source protection, cache identity, request admission, transfer completion, and safe reclamation. LZ4 and ANS are reference lossless backends; this PR does not claim a serving speedup or a stable public plugin ABI.

## Design and Modifications

### Ownership boundaries

HiCache owns prefix matching, backup and restoration admission, eviction, references, and cache publication. P/D owns transfer-range selection, protocol metadata, RDMA submission, and remote completion. The shared layer owns packing, encoding/decoding, representation compatibility, leases, and bounded execution resources.

```text
                     Prefill GPU KV
                           |
                     Pack / Encode
                           |
                  Shared encoded objects
                     /             \
                    v               v
          GPU wire buffer     Prefill HiCache L2
                    |          /             \
             Mooncake RDMA    Restore       Reuse for P/D
                    |             |         without re-encoding
           Decode restoration    v
                    |        HiCache adoption
                    v             |
              Decode GPU KV  Prefill GPU KV
```

P/D compression can run with L2 disabled. Retained Host objects are gathered into an independent GPU wire buffer before transmission; this is representation reuse, not zero-copy Host RDMA. L2 residency is an in-process cache, not durable storage across worker restarts.

### Lossless backends and representation

The fixed backend table supports `passthrough`, nvCOMP LZ4, and nvCOMP ANS. Both compression backends use nvCOMP `5.3.0.16`, `NVCOMP_NATIVE`, and 64 KiB internal chunks. ANS encodes the original BF16 bytes using `data_type="|u1"`; it does not convert BF16 to FP16, quantize KV, or change attention kernels.

One object contains one token's K/V across all layers; execution batches contain at most 64 objects. Explicit encoding IDs distinguish RAW, LZ4, and ANS. Ordinary mode falls back to RAW when encoding does not reduce the payload. Test-only FORCE mode retains the selected algorithm's output and requires VERIFY.

The v2 transfer descriptor carries actual lengths, object encodings, request identity, layout information, and verification data. Algorithm/configuration mismatches and malformed descriptors are rejected before decoding. Decode admission waits for restoration, final KV writeback, verification, and the existing handoff conditions.

### HiCache storage, restoration, and lifetime

The compressed Host pool uses generation-bearing logical handles over non-contiguous 4 KiB physical blocks. It replaces the native Host payload pool in the enabled configuration. HiCache reserves conservative capacity before backup; completed objects release unused blocks according to their actual lengths. Arena, fixed metadata, and bounded Host staging are charged to the Host-pool budget.

A restore ticket separates submission, completion, and request adoption. Target pages are published only after successful restoration and verification. Request-owned target reservations are deducted from remaining admission and load-back demand, without crediting other requests or increasing global free capacity. Cancellation and stale tickets retain their owners until the original completion/ACK path establishes safe reclamation.

Host readers and writers have independent leases. Logical eviction removes reuse eligibility; physical blocks remain protected while accesses are outstanding. Recomputed KV invalidates old representations, while tree splits retain the corresponding page identities.

### Failure handling and Router integration

Safely drained failures terminate the affected request without publishing invalid KV. Uncertain CUDA/RDMA completion retains memory and accounting, quarantines the worker, and blocks further admission. A timeout does not authorize buffer reuse.

Receiver error reporting preserves drain ACK state until the owning release queue completes cleanup. Router changes cancel paired Prefill attempts on early Decode rejection and SSE failures, use separate retry identities where supported, preserve public request identity, and terminate streaming errors correctly. Requests with persistent identities do not use unsafe retry renaming.

### Latest upstream integration

The current head, `3bd93fe24e`, includes upstream `3b72b70ef4` and preserves the experimental fixes through `8674c58d0a`.

Upstream's common `match_kv_cache()` helper now applies the same admissible prefix range for priority matching and request admission. This prevents LPM polling from repeatedly invalidating a valid restore ticket. Compressed restoration returns the adopted prefix length, matching the current HiCache interface, and uses the existing UUID-based Host lock receipts across splits and rollback.

Native transfers retain upstream's generation-bearing abort messages and ACK fan-out. Compressed v2 peers retain nonce-bound ACKs and expected-rank checks. Producer fences and native L2 transfer submission remain in place. Undrained Prefill cancellation and bootstrap failure preserve request ownership; repeated cancellation and late completion cannot release quarantined resources.

## Supported Scope and Configuration

The reference setup is Qwen3-8B on two H20 GPUs, BF16 KV, FlashInfer, 1P1D, TP/PP/DP/CP/DCP=1, page size 1, and chunk size 1,024. Prefill L2 is optional; compressed L2 uses the Python UnifiedRadixCache, write-through, and an 8 GB Host-pool budget. Decode compressed L2 is disabled. The latest historical ANS validation used 640 MiB compression workspace; it does not establish that the full workload fits 512 MiB.

```text
SGLANG_PD_KV_COMPRESSION=off|passthrough|lz4|ans
SGLANG_HICACHE_KV_COMPRESSION=off|passthrough|lz4|ans
```

Both default to `off`. nvCOMP is loaded when LZ4 or ANS is selected. Combined compressed P/D and L2 require the same algorithm and compatible FORCE/VERIFY settings. Compression requires early Decode allocation and device receive destinations. Unsupported enabled combinations are rejected explicitly; mixed-version rolling upgrades are not established.

Launch and validation instructions: [README_pd_compression.md](https://github.com/bytedance-iaas/sglang/blob/3bd93fe24e0a41687c4bfc17dbd2909a8f50ed74/test/manual/kv_transfer/README_pd_compression.md).

## Speed Tests and Profiling

The historical `238c3f6c16` run recorded ANS payload bytes at approximately 85.67% of original KV bytes, a 14.33% payload reduction. This excludes NIC/RDMA/IP framing and other control traffic. It is neither a total-memory reduction nor proof of additional retained prefixes. Ordinary LZ4 fell back to RAW in that workload; forced LZ4 expanded payloads slightly.

No TTFT, throughput, or serving-speedup claim is made. The current upstream integration has not been performance-tested. Compression, packing, staging, synchronization, verification, and conservative backup reservation still require separate cost and capacity measurements.

## Limitations and Follow-up

Multi-rank/topology-converting transfer, MLA/hybrid KV, HiSparse, speculative decoding, LoRA, sessions, external linkers, L3, Decode compressed L2, overlap scheduling, CUDA graphs, deferred Decode allocation, Host receive, and virtual compressed-L2 relocation are outside this draft's supported scope.

Active attention still needs native GPU KV. Compressed L2 continues to reserve output bounds before encoding; allocating persistent storage only after actual encoded lengths are known is not implemented. Pool/workspace budgets do not represent total process or GPU memory, and backend-private allocations remain separate. The nvCOMP wrapper synchronizes on execution workers; it is not a fully asynchronous codec implementation.

The remote [Lint workflow](https://github.com/sgl-project/sglang/actions/runs/38547009895) and the latest PR title check passed. Upstream test workflows are blocked by the Draft gate; skipped jobs are not validation evidence.

The PR remains **Draft**. Feedback is requested on ownership boundaries, compatibility with current HiCache/P/D interfaces, whether Router and L2 changes should be reviewed separately, and the validation required before expanding support.
