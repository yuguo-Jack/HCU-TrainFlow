# [Fix] api: Preserve error details across streaming boundaries

[Upstream PR](https://github.com/sgl-project/sglang/pull/46098) · state: open · merged: False

## Original PR description

## Motivation

HTTP errors lose information at a few serving boundaries:

- `HTTPException` response headers such as `Retry-After` are dropped.
- An abort status deserialized as an integer can fall through as a normal Chat stream completion.
- Messages request conversion preserves an HTTP error for a normal request but turns the same error into a 500 for a streaming request. An invalid `X-Data-Parallel-Rank` header reproduces 400 vs 500 before generation starts.

## Changes

Preserve exception headers, accept integer 4xx/5xx abort statuses, and handle conversion-stage HTTP errors consistently in Messages. Keep the existing status mapping and 5xx message scrubbing. Mounted Messages/Responses routes select their existing error formats after removing the mount prefix.

[#45130](https://github.com/sgl-project/sglang/pull/45130) covers the broader Python/Rust error-envelope change. This PR keeps the current native/OpenAI body formats and focuses on the independent boundaries above.
