## Motivation

Request rows, recurrent-state allocation and per-layer storage access currently overlap across request tables and KV pools. Centralizing those owners makes request admission rollback and layer routing consistent for static and unified storage.

## Changes

- Build recurrent state with the pool builder, bind state parts to the layer router, and translate state IDs through their allocator-owned space.
- Acquire request rows and auxiliary state together, preserving existing ownership when allocation fails.
- Migrate recurrent, short-convolution, N-gram, host-transfer and platform consumers to the new owners.
- Route GDN prefill-graph and EAGLE plugin bindings through the state owner and layer router, with fixtures that exercise noncontiguous layers and storage order.

Clarify state ownership and routing comments, and use `CustomTestCase` in the affected tests.

## Validation

The cleanup changes comments and test base classes; no new state/router execution result is claimed. Tests were not rerun after the rebase.

Historical validation through `2788de7080`:
- Four allocator traces: **0 divergences**; admission: **4,608 unchanged decisions**, including sync-debug.
- TP1 H200, unified HiCache / FA3, GSM8K-200: gpt-oss-120b **96.5% → 97.0%**, Qwen3.8-27B **97.0% → 98.0%**, zero errors. Per-run kernel versions were not fully recorded.

At published `f647f7bede`, CPU regression probes reproduced the old GDN/EAGLE failures and passed after repair, including layer mapping, FP8 scales and tensor identity. GPU serving and graph execution were not rerun on this head.
