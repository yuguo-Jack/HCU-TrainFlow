# [Fix] deepseek: Use the out-of-place MLA value projection while torch.compile is tracing

[Upstream PR](https://github.com/sgl-project/sglang/pull/47347) · state: open · merged: False

## Original PR description

## Motivation

In `DeepseekMLAForwardMixin.forward_absorb_core`, the BF16 value projection writes into a transposed, non-contiguous view through `torch.bmm(..., out=...)`. TorchDynamo does not support `out=` with a non-contiguous output, so tracing `forward_absorb_core` with `torch.compile` or `torch.export` fails on this call.

This branch used to switch to the out-of-place form under the torch.compile piecewise CUDA graph runner (`is_in_tc_piecewise_cuda_graph()`). That check went away with the runner, which leaves every other compile path on the `out=` form.

## Modifications

Add an `elif torch.compiler.is_compiling():` branch ahead of the eager fallback that computes the same product out-of-place:

```python
attn_bmm_output = torch.bmm(attn_output.transpose(0, 1), self.w_vc)
attn_bmm_output = attn_bmm_output.transpose(0, 1).flatten(1, 2)
```

`torch.compiler.is_compiling()` is `False` outside tracing, so eager mode and CUDA graph capture keep the existing `out=` path.

## Accuracy Tests

Same values as the eager branch. With full-graph `torch.compile` decode on an out-of-tree platform: DeepSeek-R1-0528 (TP8) GSM8K (5-shot, flexible-extract) 0.9621 (reference 0.9651 +/- 0.0107); GLM-5.2-FP8 (TP8) in graph mode and DeepSeek-R1-0528 (TP8) in eager mode also pass.
