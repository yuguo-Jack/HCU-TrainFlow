# [Fix] CI: add missing entry point to Muse Spark router test

[Upstream PR](https://github.com/sgl-project/sglang/pull/45845) · state: closed · merged: True

## Original PR description

Fix a CI test-discovery regression introduced by **#45508 — [Perf] [KDA] muse_spark: Run the one-token router GEMV on CuTe DSL**.

That PR registered `test_muse_spark_router_gemv_cutedsl.py` without an `if __name__ == "__main__":` entry point. CI's `collect_tests()` validates every registered file before selecting a suite, so this aborts discovery even for CPU jobs ([example failure](https://github.com/sgl-project/sglang/actions/runs/39809261061/job/119931270681?pr=45839)).

Add `sys.exit(pytest.main([__file__, "-v"]))` so direct execution runs the tests and propagates pytest's exit status.

Validation:
- Full CI discovery passed: **2471 files / 3003 registrations**.
- Verified entry-point dispatch and propagation of a nonzero pytest exit code.
