# [diffusion] comfyui: return several server-mode images as one IMAGE batch

[Upstream PR](https://github.com/sgl-project/sglang/pull/44088) · state: closed · merged: True

## Original PR description

Fixes #43418

## Summary

`SGLDiffusion Generate Image` (server mode) gets a `num_images` input, 1 to 10, default 1, so existing workflows behave the same.

- The count is sent as the image API's `n` in one request (generation and edit both accept it; the server caps it at 10).
- All returned images are decoded in order into one ComfyUI `IMAGE` batch. Before, the node kept only `data[0]`.
- Seeds: the server gives image `i` the seed `seed + i`, so the same settings and seed reproduce the same ordered batch. A seed of `-1` sends no seed and the server picks a random one. Documented in the README.
- Clear errors when the server returns fewer images than requested, when the images have different sizes and cannot be batched, or when `num_images` is out of range (checked before any request).

Contact sheets and speed claims are out of scope, as agreed in the issue.

## Tests

`test/unit/test_comfyui_server_image_batch.py` (new, 7 tests, CPU): default still sends `n=1` and returns a 1-image batch; `num_images=3` sends `n=3` and returns an ordered `[3, H, W, 3]` batch; fewer images than requested; mismatched sizes; out-of-range counts rejected without a request; the node exposes the input. All 7 fail against the current `nodes.py` and pass with this change. The rest of `test/unit/test_comfyui_*.py` is unchanged (the 2 `test_comfyui_profile.py` flux failures also happen on main in my CPU-only environment).

## GPU check

Ran the node against a real `sglang serve` server built from this branch on one L40S (512x512).

Anima (`circlestone-labs/anima-base-v1.0-diffusers`, 20 steps, cfg 4):
- `num_images=1` returns `[1, 512, 512, 3]` float32, `num_images=3` returns `[3, 512, 512, 3]` with three different images.
- The same request twice gives an identical batch (max diff 0.0), so order is stable.
- Batch image 1 shows the same image as a single run with seed 43, so image `i` uses `seed + i`. Pixels differ slightly from the single run, as expected for batched vs single generation.
- `num_images=11` is rejected before any request.

Z-Image-Turbo (`Tongyi-MAI/Z-Image-Turbo`): `n=1` works, but the server itself returns 500 for `n>1` ("Z-Image expects one caption embedding per image, got N images and 1 captions", from `zimage.py` `patchify_and_embed`). This happens with a direct API call too, so it is a server-side Z-Image bug, not part of this PR.

So the node is model agnostic: if the server supports `n>1` for a model, you get a proper batch, otherwise the node raises the server's own error.
