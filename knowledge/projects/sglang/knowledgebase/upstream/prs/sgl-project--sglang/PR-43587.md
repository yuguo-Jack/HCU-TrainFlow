# [Fix] Preserve Qwen3-Coder tag examples in streaming text

[Upstream PR](https://github.com/sgl-project/sglang/pull/43587) · state: open · merged: False

## Original PR description

## Motivation

Fixes #43151.

With `--tool-call-parser qwen3_coder`, streamed prose such as `The format is <parameter=location>Boston</parameter> okay?` loses the parameter example and emits argument deltas with `index=-1`. The same output is correctly returned as text without streaming.

## Modifications

Only parse function, parameter, and closing tags inside a `<tool_call>` block. Outside a block, preserve them as text and buffer only a possible opening `<tool_call>` marker.

Add regressions for every two-chunk split of tag examples, incomplete function/parameter syntax, stray closing tags, and prose surrounding two valid tool calls with one-character and larger chunks.

## Accuracy Tests

The new regressions fail on unmodified main `de487f8039e06853b5f376fd5f068ea9d7c400bb` and pass with this change.

`PYTHONPATH=python .venv/bin/python -m pytest test/registered/unit/function_call/test_function_call_parser.py::TestQwen3CoderDetector -q --tb=short`: **19 passed, 214 subtests passed** on macOS arm64, Python 3.12.13, Torch 2.14.1, Transformers 5.19.0, and XGrammar 0.2.7.

Also checked the example through `FunctionCallParser.parse_stream_chunk`: it returns the complete text and no calls, matching non-streaming parsing. No model inference or GPU evaluation was run; this change is confined to output parsing.
