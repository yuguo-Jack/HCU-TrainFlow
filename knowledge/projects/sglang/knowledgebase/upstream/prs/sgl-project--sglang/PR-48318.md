## Motivation

Out-of-range BF16/FP16 KV values can become NaN when cast directly
  to float8_e4m3fn. This affects the MHA write path and both the combined
  and split MLA write paths.

  Clamp values to the representable FP8 range before casting to prevent
  overflow from introducing NaNs into the KV cache.

## Modifications

  - Apply saturate_to_fp8_range before the existing FP8 casts in
    MHATokenToKVPool.set_kv_buffer.
  - Apply the same handling to MLATokenToKVPool.set_kv_buffer and
    the split NoPE/RoPE write path.
  - Add three CUDA regression tests covering these write paths.
  - Register the tests in base-b with the 1-gpu-small runner.


## Accuracy Tests

Local numerical regression tests on NVIDIA H800:

  - Fixed code: all 3 tests passed.
  - Pre-fix code: all 3 tests failed numerical assertions due to NaNs.
  - Tests check positive and negative overflow and representable values.

  Validation used PyTorch 2.9.1+cu128, which differs from the repository
  pin. Transformers 5.19.0, tokenizers 0.23.2, and compressed-tensors
  0.18.0 matched repository pins. No runtime compatibility patches
  were used.

  Model-level accuracy evaluation has not been run.

## Speed Tests and Profiling

Not run. The change adds clamp operations to the affected FP8 write
  paths; their impact on end-to-end inference performance has not
  been measured.
