> **Draft / dependency scope:** this is opt-in, experimental SM120 support requiring a FlashInfer source build containing flashinfer-ai/flashinfer#6346 (validated at `399b6c1d31a13f38dd827018f89c6a04c8487acb`). The default FlashInfer `0.7.1` pin and Docker/CI dependencies remain unchanged. An older build gives an explicit startup error only when SM120 MegaMoE is selected; the regular SM120 backend remains available. The cookbook includes a fixed-revision source-install recipe. We propose reviewing this guarded integration ahead of a dependency release; out-of-box support and validation against a released dependency will follow a coordinated version bump. The candidate is rebased onto main `2528cd2b91`, including CI maintenance base `ff8d964cf5b6`.

## Motivation

`--moe-a2a-backend flashinfer_megamoe` currently requires SM100. FlashInfer #6346 added `sm120_mxfp4_mxfp8_bf16_cake`, a fused EP all-to-all + MXFP4 x MXFP8 expert-compute kernel for SM120 (RTX PRO Blackwell) that runs through the same `flashinfer.moe_ep.MoEEpMegaLayer` API this backend already uses. This PR wires it into the existing `flashinfer_megamoe` path for FP4-expert checkpoints, starting with DeepSeek-V4-Flash.

The kernel targets **prefill**. On 4x RTX PRO 5000 Blackwell (72 GB, PCIe) it roughly doubles prefill throughput over `--moe-runner-backend flashinfer_mxfp4` at the same TP4 / attention-DP4 layout, while decode with a few requests per rank is slower (numbers below). The recommended use is the prefill server of a PD-disaggregated deployment, with decode on the existing SM120 recipe; the server logs this at startup when it is not a PD prefill server.

The PR also fixes a static-EPLB bug on DeepSeek's `forward_normal` path, which serves `flashinfer_megamoe` (SM100 included) and the plain TP MoE: it only mapped logical to physical expert ids with `--enable-eplb`, so `--init-expert-location` alone (which also selects a dispatch algorithm) left the router's logical ids pointing at the physical layout the weights were loaded in.

## Modifications

1. **[Fix] `models/deepseek_v2.py`**: `DeepseekV2MoE._normal_path_dispatch_info()` always builds `ExpertLocationDispatchInfo` on non-NextN layers, as the DeepEP path already does. `init_new` returns `None` without a dispatch algorithm, so the default path is unchanged.
2. **SM120 branch of `flashinfer_megamoe`** (`layers/moe/flashinfer_megamoe.py`, `arg_groups/moe_hook.py`, `environ.py`):
   - Platform gate: SM120 with compute capability exactly 12.0, FP4 experts, EP >= 2, and a FlashInfer build exporting `Sm120_Mxfp4_Mxfp8_Bf16_Cake_MegaMoeConfig` (clear error otherwise). `--enable-eplb` is rejected (the packed scales are not expert-major); speculative decoding without an explicit `--speculative-moe-runner-backend` is rejected (the default draft runner `flashinfer_trtllm` is SM100-only). Settings the SM120 kernel cannot honor fail at startup instead of after the model loads: an unknown transport table, `NCCL_CUMEM_ENABLE=0`, the SM100-only `SGLANG_FLASHINFER_MEGAMOE_COMBINE_DTYPE` / `..._IN_KERNEL_FC2_REDUCE`, and a per-rank prefill chunk or CUDA-graph batch larger than the workspace (`validate_flashinfer_megamoe_sm120_token_budget`). SM100 behaviour is unchanged.
   - `NCCL_CUMEM_ENABLE=1` by default on this path: the kernel joins the EP group's NCCL communicator through NCCL's Device API, which needs cuMem buffers (SGLang otherwise sets it to 0). Same pattern as the `deepep_v2` branch.
   - Weights: FlashInfer's own preprocessing (`preprocess_sm120_mxfp4_mxfp8_cake_mega_weights`). FC1 is a gate/up row interleave of `w13` and is written back into `w13`; FC1/FC2 alias the layer weights, so the experts stay resident once. The float32 (E8M0-widened) checkpoint scales are converted exactly to UE8M0 bytes and replaced by the packed kernel scales.
   - Forward: one pooled workspace; each call stages `compile_tokens_per_rank = max(get_dp_global_num_tokens())`, identical on every EP rank, so there is no per-layer routing all-gather / host sync, and each decode CUDA-graph batch size captures its own bucket. `MegaMoeTunedForward` is not used on SM120 (it would build one compiled kernel + NCCL window set per profiled capacity). Router ids are widened to int64 for this kernel. The kernel's `protocol_error` flag (BF16 return-codec overflow) is not read on the hot path because that needs a host sync; the default codec reserve is 25 % of a row, real V4-Flash activations need about 0.3 %.
   - `SGLANG_FLASHINFER_MEGAMOE_SM120_TRANSPORT_TABLE` (default `lsa_where_reachable`) selects the peer transport.
3. **Tests** (CPU, `base-a-test-cpu`): `test_flashinfer_megamoe.py` (bucket = max over DP ranks + int64 ids, cake config / no startup tuning, swiglu limit, exact UE8M0 conversion, single resident copy of the experts), `test_server_args.py` (SM120 accept / reject cases, cuMem default, token budget), new `test_deepseek_moe_dispatch_info.py` (both real normal-forward entrypoints exercise physical expert selection without `--enable-eplb`; both fail with the pre-fix bodies, while no-dispatch and NextN controls pass); `test/manual/dsv4/test_sm120_flash.py` runs the cookbook recipe on four SM120 GPUs (sgl-eval GSM8K smoke and AIME25).
4. **Docs**: DeepSeek-V4 cookbook, new "FlashInfer MegaMoE on SM120 for prefill (Experimental)" note.

**Local CPU validation** on the rebased candidate: server-args, FlashInfer MegaMoE, EPLB and normal-forward dispatch suites: 376 passed, 1 skipped; pre-commit passed for all changed files. A cake server smoke also passed on the rebased candidate using FlashInfer source `399b6c1d`; validation against the eventual released dependency remains pending.

**Test environment** (GPU numbers below, collected before the rebase): one host, 8x NVIDIA RTX PRO 5000 Blackwell 72 GB (SM120, PCIe, two CPU sockets), driver 580.95.05; image `lmsysorg/sglang:dev-cu13` built 2026-10-13 (CUDA 13.0, torch 2.14.1+cu130, NCCL 2.30.7, nvidia-cutlass-dsl 4.8.0) with this branch on top of `27b68303d0` and FlashInfer main `399b6c1d` (#6346) from source; model `deepseek-ai/DeepSeek-V4-Flash-0731`; sgl-eval 0.1.2. ## Speed Tests and Profiling

Same setup; `--chunked-prefill-size 16384 --max-prefill-tokens 4096` (4096 prefill tokens per rank), `--mem-fraction-static 0.8`, decode CUDA graphs on (prefill CUDA graphs are disabled for DeepSeek-V4 by SGLang's own rule), `sglang.benchmark.serving --dataset-name random-ids`. Prefill: a dedicated rerun on 2026-10-15 with radix cache disabled, three rounds per point, all three backends on the same production tree. Decode: the earlier c7 session on the same production tree, one round per point; GSM8K-200 (sgl-eval preset) in that session: 96.5 % / 97.0 % / 97.0 %.

**Prefill** (OSL 1, `--max-concurrency 64`, `--disable-radix-cache`), input tokens/s (TTFT mean / median / P99, ms). Both baselines run W4A8 (MXFP4 weights x MXFP8 activations, FlashInfer CUTLASS fused MoE) with the tokens all-gathered over attention DP and reduce-scattered after the MoE; `--ep-size 4` places whole experts per rank like this PR:

| ISL | flashinfer_mxfp4, TP MoE | flashinfer_mxfp4, EP4 | flashinfer_megamoe | vs TP / vs EP4 |
|---|---|---|---|---|
| 512 | 12125 (2669 / 2630 / 3670) | 13853 (2334 / 2279 / 3243) | 24174 (1336 / 1291 / 1982) | 1.99x / 1.75x |
| 1024 | 12332 (5126 / 5289 / 6301) | 14165 (4462 / 4603 / 5483) | 25106 (2518 / 2583 / 3121) | 2.04x / 1.77x |
| 2048 | 12101 (9861 / 10774 / 11961) | 13854 (8611 / 9411 / 10469) | 24085 (4950 / 5367 / 6086) | 1.99x / 1.74x |
| 4096 | 11935 (17502 / 21537 / 23239) | 13644 (15287 / 18821 / 20285) | 23400 (8923 / 10887 / 11918) | 1.96x / 1.72x |

In this serving configuration, EP4 improves the baseline by about 1.14-1.15x and the MegaMoE backend is 1.72-1.77x faster than that EP4 baseline (1.96-2.04x over TP MoE). This comparison measures the complete backend, including communication and integration; it does not isolate kernel fusion alone.

Each prefill round has 524288 requested input tokens (`num-prompts = 524288 / ISL`), request rate infinity, concurrency 64, temperature 0, and client seeds 101, 102 and 103; a separate cold run is excluded. The server uses `--disable-radix-cache` and each benchmark passes `--flush-cache`. All 36 measured runs completed every request without errors; all output lengths are one token. The table reports medians of three run-level metrics (including run-level P99s), not pooled request percentiles. The largest per-point throughput range `(max-min)/median` across the three rounds was 0.8% / 0.6% / 3.1% for TP / EP4 / MegaMoE respectively. The runs were sequential on one host, so these are synthetic serving measurements, not a PD throughput or kernel microbenchmark result.

Decode uses seed 42, concurrency 4/16/64/256 and 32/32/128/512 requests respectively; all measured output lengths are 1024 tokens. These earlier decode runs retained radix caching and did not explicitly flush between cases.

**Decode** (ISL 128 / OSL 1024, ignore_eos), median TPOT (ms):

| concurrency (req/rank) | flashinfer_mxfp4, TP MoE | flashinfer_mxfp4, `--ep-size 4` | this PR |
|---|---|---|---|
| 4 (1) | 15.4 | 16.0 | 21.6 |
| 16 (4) | 21.0 | 22.0 | 27.1 |
| 64 (16) | 33.4 | 33.4 | 37.0 |
| 256 (64) | 61.7 | 60.9 | 60.2 |

Hence the prefill positioning. Decode CUDA graphs capture one bucket per batch size: with `--disable-cuda-graph` the median TPOT of this PR is 65.1 / 62.6 / 62.9 ms at concurrency 4 / 16 / 64 (mxfp4: 66.3 / 65.4 / 66.6 ms).

**Topology (supplementary, historical cache-enabled runs).** The kernel picks a per-peer transport: NCCL LSA (CUDA peer access over PCIe/NVLink) where peers can reach each other and NCCL GIN (GPU-initiated RDMA over the NIC) elsewhere. `SGLANG_FLASHINFER_MEGAMOE_SM120_TRANSPORT_TABLE` selects the table. Prefill, OSL 1, `--max-concurrency 128`, input tokens/s for ISL 2048 / 4096:

| cake layout | GPUs | flashinfer_mxfp4 (TP MoE, EP=1) | this PR, `lsa_where_reachable` (default) | this PR, `all_gin` |
|---|---|---|---|---|
| TP4 / attn-DP4 / EP4 | 0-3, one CPU socket | 12126 / 12130 | 24283 / 23629 (2.00x / 1.95x) | 24563 / 23967 (2.03x / 1.98x) |
| TP8 / attn-DP8 / EP8 | 0-7, two CPU sockets | 13578 / 14855 | 40690 / 42221 (3.00x / 2.84x) | 41629 / 44673 (3.07x / 3.01x) |

At EP8 the two sockets have no CUDA peer path between them, so the default table runs LSA for the 24 directed off-diagonal peer pairs inside the sockets and GIN for the 32 directed pairs across sockets (56 off-diagonal pairs in total); an all-LSA table is not possible on this host. At EP8 this PR needed `--mem-fraction-static 0.70` on these 72 GB GPUs (at 0.80 the first MegaMoE launch ran out of memory); the EP8 rows of both backends use 0.70. GSM8K-200 (`run_eval`) was 0.985-0.990 in every layout.
