# [Fix] session: Wrap SessionParams TypeError to ValueError and add validation unit tests

[Upstream PR](https://github.com/sgl-project/sglang/pull/41535) · state: open · merged: False

## Original PR description

## Motivation

When `SessionParams` is constructed with invalid field types (e.g., `id` as int, `offset` as string), msgspec does not enforce the type annotations at runtime, causing the invalid values to propagate into the scheduler and potentially crash the server. This PR adds runtime type validation to `SessionParams` and wraps the resulting `TypeError` into `ValueError` at the tokenizer manager layer, so that invalid requests return a 400 error instead of crashing the server.

## Modifications

- Added `__post_init__` to `SessionParams` (in `io_struct.py`) to validate types of all fields: `id` (str), `rid` (str), `offset` (int), `replace` (bool), `drop_previous_output` (bool). Fields that are `None` are skipped.
- Wrapped `SessionParams(**obj.session_params)` construction in `tokenizer_manager.py` with a try-except block that converts `TypeError` to `ValueError` with a descriptive message.
- Added unit tests in `test_io_struct.py` covering: valid constructions, invalid type inputs for each field, and verification that `TypeError` is properly wrapped into `ValueError`.
