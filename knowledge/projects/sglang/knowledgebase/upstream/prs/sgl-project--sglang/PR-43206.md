# [unified memory pool] Allocate without transfer waits, pin floating SWA reservations, drop the HiCache startup asserts

[Upstream PR](https://github.com/sgl-project/sglang/pull/43206) · state: closed · merged: True

## Original PR description

## Motivation

Follow-up to #39479 (unified HiCache physical transfers), addressing its review.

| Area | #39479 as merged | This PR |
|---|---|---|
| Free-page allocation | `_alloc_bind_fast_or_slow` and `alloc_physical` waited on every registered HiCache transfer event whenever a lazy hole existed. | No wait. Compaction and frees keep theirs. |
| Floating SWA reservations (FULL/SWA/Mamba tri-pool) | `alloc_physical` counted reservations in `_pending_hicache_load_pages` only on lazy pools. The tri-pool's SWA pool floats and is not lazy, so a Mamba allocation in the same load could move the reserved page (`make_room`) before the load was queued; the queued copy kept the old address, which then lay in Mamba state. | The float counts its reservations, so they block moves until the load is queued or cancelled. End pools are unchanged. |
| Startup checks | `handle_unified_memory_pool` asserted `--pp-size 1` and lazy compaction for unified memory with HiCache. | Both asserts removed. The PD disaggregation asserts and the allocator's own lazy-compaction checks are unchanged. |
| SWA H2D target allocation | Physical reservations, plus an unreachable bind-to-FULL path (`bind_swa_for_loaded_rows`, `device_indices_from_anchor_fn`, `anchor_index_parts`). | The unreachable path is removed. Physical reservation is the only path. |
| FULL load-back spec in `PrefillAdder` | Built for every `UnifiedRadixCache` load-back. | Built only for budgets that declare `load_back_needs_full_tokens` (`SharedSWAPrefillBudget`). |
| SWA write-back eviction | A Rust-core barrier fired after the pending-node barrier when SWA already had a host copy or nothing to back up, and started a FULL write-back that SWA preservation does not need. | The redundant barrier (`backup_kv`) is removed. The pending-node backup stays. |
| Tests | No new permanent tests. | CPU tests for the mechanisms the review asked to test, run on both TreeCores. |

## Modifications

**Allocate free pages without waiting on HiCache transfers** (`unified_sub_pool.py`). Allocation takes pages that no copy uses, and a page under a copy never becomes free while the copy runs: D2H sources hold a device lock until the write ack; an H2D target is owned until its ack (the load-back's tree and host locks in cache mode, the request lock on the published span in buffer-only mode); an uncommitted physical reservation blocks page moves through `_pending_hicache_load_pages`, and a queued or unacknowledged transfer blocks them through the host-transfer move gate. `_flush`, the eager `free` path and `free_physical` still wait on the registered events.

**Count floating SWA reservations as pending HiCache loads** (`unified_sub_pool.py`). `alloc_physical` and `cancel_physical_reservation` count every reservation in every pool. The count holds `make_room` and `compact_holes` until the load event is registered (`set_hicache_transfer_done_event`, which the tri-pool forwards to the float) or the reservation is cancelled. A tri-pool load whose Mamba slot can only be found by moving the float now fails and rolls back, unless evicting a checkpoint frees a slot.

**Drop the unified-memory HiCache startup asserts for PP and lazy compaction** (`kv_cache_hook.py`). This does not claim that pipeline-parallel serving has been validated; the allocator's lazy-compaction checks (`install_move_gate`, `_compact_pending_impl`) are unchanged.

**Remove the unreachable SWA bind-to-FULL load path.** Every unified SWA sub-allocator is a `MultiEndedAllocator`, so `_swa_allocation_callbacks` always selects `alloc_physical` and `cancel_physical_reservation`. Removed: the anchor loop in `_resolve_device_transfers`, `bind_swa_for_loaded_rows`, the `anchor_index_parts` producers (Python core and Rust adapter), and `BufferModePipeline`'s `binds_swa_to_full` branch. `free_swa` stays, because `free_swa_segment` uses it when `page_size == 1`.

**Build the FULL load-back spec only for budgets that use it.** Budgets declare `load_back_needs_full_tokens`. The admission host lock before reclaim stays.

**Remove the redundant SWA write-back eviction barrier.** Removes the Rust walk state and its enable switch, `EvictionStepResult.backup_kv`, its binding field and `EvictDeviceNextNodeResult.backup_kv`, the Python enable call, and the `backup_kv` branch of `_evict_device_next_node`.

**Tests** (all CPU-registered).
- `test/registered/unit/mem_cache/test_unified_hicache_transfer_lifecycle.py` (7 tests) runs the real CPU allocator, cache, controller and page-envelope host pool, recording CUDA stream waits through a stand-in for `torch.cuda.current_stream()`: physical reserve/cancel with the move block, including the tri-pool rollback when a Mamba allocation would move a floating reservation; hole reuse and `alloc_physical` adding no transfer wait; load-back host pins held through reclaim; the joint budget with pending decode demand; the write_back→write_through switch rejected over a host suffix below an unbacked FULL parent; and a SWA reservation retrying once after a device eviction (the scenario of the removed binding-path tests).
- `test/registered/unit/mem_cache/test_hybrid_pool_assembler.py` (1 new test): no backend and `mori` select the shared page envelope; `mooncake` and `dynamic` do not.

**Notes for review**: `kv_cache_hook.py` keeps the EAGLE asserts from #40491; `buffer_mode/pipeline.py` reads the local `prefix_indices` from #42825; the lifecycle test's request mock uses the current request API (`prefix_len` / `extend_end` and `UnifiedRadixCache.prefix_device_indices`).
