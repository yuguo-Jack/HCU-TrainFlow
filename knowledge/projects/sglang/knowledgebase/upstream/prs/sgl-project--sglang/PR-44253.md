# [Feat] simulator: migrate the estimator SDK to AISimulate

[Upstream PR](https://github.com/sgl-project/sglang/pull/44253) · state: open · merged: False

## Original PR description

## Motivation

Migrate SGLang Simulator's existing op-level estimator from the standalone AIConfigurator package to AISimulate, building on the simulator integration introduced in #33824. The existing prediction calculations, scheduling, and cache behavior are retained.

This is the **first of two stacked PRs**:

1. **This PR:** migrate directly to the modern AISimulate SDK namespace and retain the existing op-level calculation 
2. **Follow-up PR [#46012](https://github.com/sgl-project/sglang/pull/46012):** use the same pinned SDK and extend the same predictor with native FPM correction, regression, interpolation, and automatic estimator selection.

Both PRs use the same installation extra, simulator entry point, and JSON configuration interface. The follow-up builds directly on this migration and will link back to this PR.

<!-- Replace this note with the follow-up PR link once it is opened. -->

## Modifications

- Replace the `[aic]` installation extra with `[aisimulate]`, pinned to `aisimulate==0.13.0`.
- Rename the predictor module, class, configuration name, and example files to AISimulate.
- Preserve the existing static op-level path, including database modes and phase scale factors. Extract shared precision/quantization mapping without changing its defaults.
- Import directly from `aisimulate.sdk`, with a concise installation hint when the SDK is missing. Add real-SDK predictor/configuration tests.
- Update documentation and simulator CPU CI for the new dependency.

The integration uses the modern `aisimulate.sdk` namespace directly. There is no fallback to the standalone AIConfigurator package or older SDK namespaces. Both stacked PRs use the same SDK pin; the follow-up enables additional capabilities without another SDK migration.

## Usage and migration

Install the AISimulate extra in a compatible Linux/Python 3.11–3.13 environment:

```bash
pip install -e "tools/sglang-simulator[aisimulate]"
```

Change `predictor.name` from `aiconfigurator` to `aisimulate`. The supplied configurations are renamed to `aisimulate_sol.json` and `aisimulate_silicon.json`.

The launch interface remains unchanged:

```bash
SGLANG_USE_CPU_ENGINE=1 \
SGLANG_SIMULATOR_OUTPUT_MODE=OFFLINE \
python3 -m sglang_simulator.simulation.sglang.launch_server \
  --model-path /path/to/model \
  --sim-config-path tools/sglang-simulator/examples/sim_configs/aisimulate_sol.json
```

The supplied A100/SGLang examples use database slot `0.5.10`. Select matching hardware/backend data for other deployments; this field identifies performance data, not the running SGLang checkout version.

## Validation

Tested on Linux / Python 3.12 with AISimulate 0.13.0:

- SDK import/predictor tests: 10 passed.
- Default runner: 1 passed; offline/blocking: 1 passed; serving: 5 passed.
- Existing SOL/SILICON backend slot `0.5.10` works without changing the adapter.
- Spelling, TOML parsing, and diff checks passed.

This PR validates SDK integration; it makes no new GPU accuracy or inference-speed claim. FPM functionality and version-qualified reference measurements belong to the follow-up PR.
