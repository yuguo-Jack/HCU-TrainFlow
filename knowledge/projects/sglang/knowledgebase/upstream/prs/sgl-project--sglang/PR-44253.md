## Original PR description

# [Feat] simulator: Migrate the estimator SDK to AISimulate

## Motivation

AISimulate is the successor to AIConfigurator and the home for its ongoing development. This PR migrates SGLang Simulator to AISimulate as its sole estimator SDK.

This builds on the original simulator integration contributed by @littlefatfat in #33824.

## Modifications

- Replace the `[aic]` dependency extra with `[aisimulate]`, pinned to `aisimulate==0.12.1`, and remove the legacy-only PyArrow constraint.
- Rename the predictor module, class, and configuration name to AISimulate.
- Update example configurations, installation instructions, and migration documentation.
- Run simulator CPU CI against AISimulate and add real-SDK predictor and import-validation tests.
- Preserve the existing scheduling, timing calculations, and cache behavior.

AISimulate 0.12.1 provides its SDK through the `aiconfigurator.sdk` namespace. These imports therefore remain, but the standalone `aiconfigurator` package is no longer supported. Import checks reject legacy-only and co-installed environments.

This PR does not include FPM integration or cache bug fixes.

## Migration

Install the SDK in a fresh environment:

```bash
pip install -e "tools/sglang-simulator[aisimulate]"
```

Change `predictor.name` from `aiconfigurator` to `aisimulate`. The old name now reports an explicit migration error.

The supplied A100/SGLang examples use performance database slot `0.5.10` instead of `0.5.9`. Other hardware/backend combinations must select an available database slot. This setting identifies performance data, not the SGLang checkout version.

The dependency pin reflects the validated SDK version. Future upgrades require compatibility and predictor regression testing.

The complete SGLang runtime installation in the fresh environment remains unverified due to an installation timeout. The full CPU suite used an existing isolated environment.

### Extended cache checks

A 20-case matrix covered SOL/SILICON, OFFLINE/BLOCKING, and five cache configurations:

| Source | Passed | Assertion failures | Abnormal exits |
| --- | ---: | ---: | ---: |
| Updated integration | 15 | 3 | 2 |
| Previous PR version, same SDK and workloads | 14 | 4 | 2 |

The failing configurations also reproduced on the baseline:

- OFFLINE L3 best-effort cases encountered a cache slice-index `TypeError`.
- BLOCKING L3 cases failed cache-hit assertions.
- Repeated SILICON/BLOCKING/L3 best-effort trials showed instability in both versions.

These results indicate pre-existing cache issues, but do not establish identical failure rates or rule out timing effects from this migration. Those issues remain unresolved and outside this PR's scope.
