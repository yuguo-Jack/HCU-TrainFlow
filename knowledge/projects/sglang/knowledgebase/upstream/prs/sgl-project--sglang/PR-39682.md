# [diffusion] model: support HiDream-O1-Image

[Upstream PR](https://github.com/sgl-project/sglang/pull/39682) · state: open · merged: False

## Original PR description

## Motivation

`HiDream-ai/HiDream-O1-Image` is an 8B pixel-space unified transformer: a Qwen3-VL backbone with a flow-matching pixel head, no VAE and no separate text encoder. Prompt tokens and raw 32x32x3 image patches share one sequence, and the timestep is injected at the `<|tms_token|>` slot. There is no diffusers pipeline and no `model_index.json` in the checkpoint, so serving it needs a native pipeline: a loader for a plain Qwen3-VL directory, a mixed causal/bidirectional mask, interleaved mrope with a fixed image-grid origin, and a denoising loop for a model that predicts the clean image rather than the noise.

Independently, the checkpoint declares `architectures: ["Qwen3VLForConditionalGeneration"]`, so `sglang.srt` routes it to `qwen3_vl.py`, where `load_weights` silently drops names it has no parameter for: an srt text server starts clean against this checkpoint and then answers with empty completions. That silent failure is fixed here too.

## Modifications

### New diffusion pipeline (`sglang.multimodal_gen`)

Hybrid (Style A): model-specific `BeforeDenoisingStage`, standard denoising loop, then decoding.

| File | Adds |
| --- | --- |
| `runtime/pipelines/hidream_o1_image.py` | Owns `load_modules` instead of the diffusers component loaders, since there is no `model_index.json`; builds `FlowUniPCMultistepScheduler(shift=3.0, prediction_type="flow_prediction")` |
| `runtime/models/dits/hidream_o1_image.py` | Backbone plus pixel head (`x_embedder`, `t_embedder1`, `final_layer2`), interleaved mrope (`mrope_section [24, 20, 20]`, axis `i` into channels `i::3`), TP layers, and `TORCH_SDPA` only — the dense additive `[1, 1, S, S]` mask rules out the other backends |
| `.../stages/model_specific_stages/hidream_o1_image.py` | The three stages: prompt / mrope / mask / patchified-noise setup, CFG in `x_pred` space, unpatchify decode |
| `configs/{models/dits,pipeline_configs,sample}/hidream_o1_image.py` | Arch, pipeline and sampling config, plus a `registry.py` entry |

Three details worth a reviewer's attention:

- The DiT returns `x_pred`, not noise, so CFG is applied to `x_pred` and only then converted to velocity (`model_output = (sample - x_pred) / sigma`). That reorder is exact only for affine post-processing, so `--guidance-rescale` and `--cfg-normalization` are rejected.
- The prompt must yield exactly one `<|tms_token|>`. Fast tokenizers split on added tokens even with `add_special_tokens=False`, so a spelled-out token would silently take a copy of the timestep embedding.
- `mrope_section` is validated against both `head_dim / 2` and the interleaved layout, since an over-wide h or w section would otherwise be silently truncated by the channel slice.

Scope limits, each raising with an explanation: non-bf16 precision, sequence parallelism (the dense mask is not shardable along the sequence), every disagg role except monolithic, and more than one prompt per request.

### srt guard

`python/sglang/srt/models/qwen3_vl.py` — `check_not_image_generation_head`, the first statement of the `load_weights` loop, raises instead of dropping the weight. It matches `x_embedder` / `t_embedder` / `final_layer` per dotted name component, so `model.final_layernorm.weight` and `text_model.final_layer_norm.bias` stay clear, and the message notes that dispatch keys off the model path — the realistic victim renamed the checkpoint directory, and the diffusion registry only knows the hyphenated spelling.

Two pre-existing limits left unchanged. Raising inside the loop means `update_weights_from_disk` kills the scheduler rather than returning a failure tuple, because the rollback path re-raises inside its own `except`; rejecting before state is mutated needs a pre-pass in shared loader code. And `_supported_attention_backends` constrains automatic selection only, so an explicit `--attention-backend flash_attn` is ignored rather than rejected — results stay correct because `LocalAttention.forward` falls back to SDPA whenever an `attn_mask` is present.

### Docs

`docs/cookbook/diffusion/HiDream/HiDream-O1-Image.mdx`, a `docs/docs.json` nav entry, and a model-catalog row noting the no-VAE / monolithic-only / no-SP constraints.

### Verified against the reference implementation

The checkpoint ships no `.py` files, so two numeric questions were settled against the reference repo (`inference.py`, `models/pipeline.py`, `models/utils.py`) rather than the model card's prose.

- **`guidance_scale` now defaults to `5.0`, changed from `1.0`.** The reference defaults to `5.0` and passes it through for `--model_type full` (`inference.py:44,79-84`: 50 steps, shift 3.0, FlowUniPC). This pipeline hardcodes that scheduler and shift, so it *is* the `full` recipe, and `1.0` was silently disabling the CFG the recipe assumes.
- **`HIDREAM_O1_NOISE_SCALE = 8.0` is correct and unchanged.** The card's `7.5` is the argparse default for `--noise_scale_start` / `--noise_scale_end`, which reach `generate_image` only on the `dev` + `flash` branch (`inference.py:99-101`); for `full` the function falls back to `NOISE_SCALE = 8.0` (`models/pipeline.py:15,120-121,313`). The interpolated per-step schedule is likewise `flash`-only (`models/pipeline.py:322-328,418-421`), so nothing is missing from this path.

The same pass confirmed the sign convention, the `1.0 - sigma` flow position, `seed + 1` CPU-generator seeding, and `supported_resolutions` against `PREDEFINED_RESOLUTIONS`. A tautological `test_noise_scale_matches_the_reference` — it asserted the constant equalled its own literal — is removed.

One deliberate divergence: the reference snaps to the nearest trained **aspect ratio** ignoring the requested area (`models/utils.py:190-200`), so 512x512 comes back as 2048x2048. This pipeline warns and renders what was asked, matching the rest of `multimodal_gen`; the cookbook wording and resolution list are corrected accordingly.

## Accuracy Tests

1x NVIDIA H200 (143 GB), driver 580.173.02, torch 2.13.0+cu130. 2048x2048, prompt `"A cat is sitting next to a sign that says HiDream-O1"`.

All six runs (8 / 28 / 50 steps x TP 1 / TP 2) render the same coherent scene with the sign text "HiDream-O1" legible. TP 2 is not bit-identical to TP 1 (mean absolute pixel difference 9.7/255) because all-reduce changes the bf16 reduction order, but composition, subject and rendered text are unchanged — the signal that matters, since a patchify transposition, a wrong mrope grid, a broken mask or a sign error present as noise or scrambled 32-pixel blocks, not as subtly worse images. Peak memory of ~16 GB matches the bf16 weight footprint, confirming no VAE or text encoder is resident.

Unit tests: 20 passed / 50 subtests in `python/sglang/multimodal_gen/test/unit/test_hidream_o1_image_stages.py` (mrope grid, mask boundaries, patchify round trip against an einops oracle, seeded-noise offset, CFG-reorder equivalence, velocity round trip, and registry resolution for the HF id, a local directory and a cache snapshot), plus 2 passed / 12 subtests in `test/registered/unit/models/test_qwen3_vl_image_generation_reject.py`. Four candidate cases were dropped per `.claude/rules/unit-test-admission.md`.
```
sglang generate --model-path HiDream-ai/HiDream-O1-Image \
  --prompt "A cat is sitting next to a sign that says HiDream-O1" \
  --num-inference-steps 28 --tp-size 1 \
  --seed 42 --save-output
```

## Speed Tests and Profiling

1x H200, 2048x2048, monolithic, bf16, no torch.compile, warmup off, at the new default `--guidance-scale 5.0` (two forwards per step). One fresh process per cell.

| Steps | TP 1 | TP 2 | TP 2 speedup |
| --- | --- | --- | --- |
| 8 | 5.48 s | 4.70 s | 1.17x |
| 28 | 12.50 s | 8.67 s | 1.44x |
| 50 | 20.39 s | 13.50 s | 1.51x |
| Peak memory | 16102 MB | 8524 MB | 0.53x |

Steady-state denoising is 0.359 s/step (2.78 it/s) at TP 1 against 0.207 s/step (4.84 it/s) at TP 2, a 1.74x per-step gain; end-to-end is lower because setup and decode do not shrink, which is why the speedup grows with step count.


Not yet exercised: cfg-parallel, runtime fp16 rejection, cross-process seed reproducibility, multi-output batching, trajectory decoding, and the HTTP server path. Breakable CUDA graph needs no handling: `_adjust_breakable_cuda_graph_support` force-disables it for configs outside its supported list, so the generic prompt padder never sees this 4-D mask.
