# [feat] Remove wall-clock deadlines from scheduler control-plane comms

[Upstream PR](https://github.com/sgl-project/sglang/pull/39490) · state: closed · merged: False

## Original PR description

## Motivation

Every gloo collective and point-to-point op waits on a `CLOCK_MONOTONIC` deadline fixed at group creation. Any stall that outlasts that budget — process preemption, cgroup freezer, VM suspend/snapshot — turns a recoverable pause into a failed collective: the stalled rank's pending deadlines fire on resume, and its peers' in-flight waits fail against it. No finite timeout closes this class, because the stall duration is unbounded; a larger timeout only widens the window while delaying detection of genuine hangs.

The scheduler's request/control broadcast itself moves off the timed gloo collective and onto the shm `MessageQueue` (`GroupCoordinator.broadcast_object`, gloo fallback when absent), and idle `MessageQueue` readers block on a ZMQ notify socket instead of spinning.

The shm `MessageQueue` used for request broadcast has no wall-clock bound in its data path: readers block on a notify socket whose poll deadline re-arms each iteration, so a resumed rank simply re-checks the ring. This PR routes the scheduler's control-plane waits through transports of that shape:

- `MessageQueue` gains a reverse PUSH/PULL control channel implementing `barrier()` (readers push an arrival ack and block on the release broadcast) and `all_gather_object()` (readers push `(group_rank, obj)`, writer publishes the rank-ordered list).
- `GroupCoordinator.barrier()` / `all_gather_object()` prefer the broadcaster, falling back to gloo when the group has none.
- New `ZmqP2PChannel` for the pipeline-stage edge: each process binds a PULL socket and lazily connects PUSH sockets addressed by global rank, endpoints exchanged once at init via a single gloo `all_gather_object` — an init-time collective, which is the accepted residual. Messages carry a tag mirroring gloo tag semantics so overlapping protocols on the same peer pair stay separated.

## Modifications

- `python/sglang/srt/distributed/device_communicators/shm_broadcast.py`: control channel, `barrier()`, `all_gather_object()`.
- `python/sglang/srt/distributed/device_communicators/zmq_p2p.py`: new `ZmqP2PChannel` + `ZmqP2PWork`.
- `python/sglang/srt/distributed/parallel_state.py`: coordinator `barrier`/`all_gather_object` MQ routing; `send_object`/`recv_object` route through an installed channel (the scheduler installs one on `pp_group`/`world_group`), which also migrates `send_tensor_dict`/`recv_tensor_dict` metadata hops and grammar sync with no callsite changes.
- Callsite conversions: weight-update barriers, profiler barriers (`SchedulerProfilerManager` now takes `dp_tp_group`), the RPC barrier, multimodal `all_gather_object`/`broadcast_object_list` callsites, the reject-path MAX-reduce, disaggregation MIN-reduce polls (`poll_and_all_reduce*` now take coordinators), the PP request/output relay, and `HiRadixCache`/`UnifiedRadixCache` `_pp_sync` (tensor `data.copy_()` on recv preserves in-place fill semantics).
- Tests: `barrier`/`all_gather_object` cases in `test_shm_broadcast_notify.py`; `test_pp_cp_rank_offsets` updated to mock the channel.

Deliberately left on gloo: init-only collectives (seed broadcast, dynamic-chunk profiling — cannot be in flight during steady-state stalls), client-owned `init_weights_update_group` transport (peer-side deadlines are protocol-level), and PP-edge tensor payloads (device-plane traffic). After this PR no scheduler-path pyobj wait carries a deadline it can outlive.

## Accuracy Tests

Unit-level only; collective and p2p semantics unchanged (MIN/MAX-reduces reimplemented as gather + `amin`/`amax`, same result; message ordering preserved per `(src, tag)` pair).
