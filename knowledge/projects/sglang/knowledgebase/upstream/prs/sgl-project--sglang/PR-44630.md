# [Fix] monokernels: Honor resolved CUDA graph configuration

[Upstream PR](https://github.com/sgl-project/sglang/pull/44630) · state: closed · merged: True

## Original PR description

## Motivation

Follow-up to #44353. Enabling a monokernel can override an operator's decode CUDA graph budget: with the AMD plugin, `--cuda-graph-max-bs-decode 4` expands the capture buckets from `[1, 2, 4]` to `1..48`. Explicit bucket lists are also replaced.

The runtime additionally checks the legacy disable booleans instead of the resolved decode backend. Disabling graphs through `--cuda-graph-backend-decode disabled` or JSON therefore leaves graph-key filtering active and can send supported eager draft shapes to the normal forward. Conversely, an explicit backend that overrides a disable flag is treated as disabled.

## Modifications

- Keep automatically aligned buckets within the configured capture ceiling, and preserve explicitly supplied decode bucket lists.
- Skip bucket alignment when the resolved decode backend is disabled.
- Use the resolved decode backend when building monokernel capture keys, so every graph-disable spelling retains full supported eager coverage and explicit backend precedence is respected.
- Extend the existing CPU tests for small ceilings, explicit buckets, unchanged default alignment, disabled graph configuration, eager draft dispatch, and backend precedence.
