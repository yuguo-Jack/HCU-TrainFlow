# [Fix] Mooncake: Resolve per-worker MNNVL physical GPU

[Upstream PR](https://github.com/sgl-project/sglang/pull/48088) · state: open · merged: False

## Original PR description

## Motivation

Mooncake's strict MNNVL EGM Store requires `MC_PHYSICAL_GPU` to contain the
host-local physical GPU ordinal used for requester placement. SGLang
tensor-parallel workers inherit the same parent container environment while
selecting different CUDA logical devices, so a single container-wide scalar
cannot correctly represent every worker.

Without process-local resolution, TP>1 workers may all advertise the same
physical GPU and select the wrong EGM placement.

### Dependency

This PR depends on **kvcache-ai/Mooncake#5161**:

- https://github.com/kvcache-ai/Mooncake/pull/5161
- Commits: https://github.com/kvcache-ai/Mooncake/pull/5161/commits
- `9a331f020a7da1142d5a6164b8437c7eb4cb7999`: strict MNNVL EGM Store support
- `f194d147b0f07854180c651ff057bab5fb0e61ff`: parser and EGM unregister fixes

Mooncake#5161 is a separate PR submitted to the Mooncake repository. This
SGLang PR does not duplicate its implementation; it adapts SGLang Direct Linker
workers to the interfaces and placement requirements introduced there.
Specifically, Mooncake#5161 introduces the Store protocols `mnnvl` and
`nvlink_host`, physical requester placement, and the `MC_PHYSICAL_GPU`
requirement used here. Classic `nvlink`, TCP, and RDMA paths are outside this
change.

## Modifications

- Detect the Mooncake Store MNNVL protocols `mnnvl` and `nvlink_host`.
- Resolve each worker's current CUDA logical device through numeric
  `CUDA_VISIBLE_DEVICES` before the lazy Mooncake Store import/initialization.
- Set the process-local `MC_PHYSICAL_GPU` and log the TP rank, CUDA device, and
  resolved physical GPU.
- Support non-contiguous and reordered visibility such as
  `CUDA_VISIBLE_DEVICES=1,3`.
- Reject a conflicting container-wide `MC_PHYSICAL_GPU` when a numeric
  visibility map proves that it is wrong for the current worker.
- Require an explicit physical ordinal for UUID/MIG visibility instead of
  silently treating CUDA logical device 0 as physical GPU 0.
- Leave non-MNNVL protocols unchanged without querying CUDA or modifying
  `MC_PHYSICAL_GPU`.

The implementation is independent of a particular TP size. Its execution
model requirement is one selected CUDA device per SGLang worker process.

## Accuracy Tests

This change does not modify model forward code, KV keys, page layout, cache
lookup, or load/offload semantics.
