# [Fix] [AMD] quark: Match exclude entries that name a parameter (.weight) by module

[Upstream PR](https://github.com/sgl-project/sglang/pull/47431) · state: open · merged: False

## Original PR description


## Motivation

`amd/Qwen3.8-27B-Quark-AWQ-MXFP4` keeps its MTP (next-token prediction) layer in BF16 and lists it in the Quark `exclude` list by
parameter name, e.g. `mtp.layers.0.mlp.down_proj.weight`: all 15 `mtp.*` entries end in `.weight`. Exclusion is matched against
module names (exact or `re:`), so none of these entries match. Since #39064, `_mtp_quant_config` keeps the Quark config for a draft whose
routed experts are not excluded and relies on the per-layer exclusions to keep the BF16 modules BF16; this dense MTP has no experts, so its
linears are built as packed MXFP4 parameters and loading the BF16 MTP tensors fails:

```
Qwen3_5ForCausalLMMTP.load_weights -> load_merged_column_weight: AssertionError (assert param_data.shape == loaded_weight.shape)
```

MTP speculative decoding therefore cannot start on this checkpoint without editing its `config.json`.

#36158 (checkpoint probe for MTP quantization) does not cover this case: it asks the checkpoint only when the exclude list names no
`mtp.*` layer, and this checkpoint names all of them. Checked on MI355X: current main + #36158, rebased so that #39064's rule stays in force when `mtp.*` entries exist, fails with the same assertion.

## Modifications

`QuarkConfig` normalizes its `exclude` list when the config is read: a plain (non-`re:`) entry that ends in `.weight` is reduced to its
module name. Regex entries are kept as written. Tests in a new file,
`test/registered/unit/layers/quantization/test_quark_exclude_param_names.py`: the checkpoint's 15 `.weight` entries keep the MTP
linears unquantized (fused `qkv_proj` / `gate_up_proj` included) and leave target layers quantized; regex and module-name entries are
unchanged.

## Accuracy Tests
