# [Fix] deepseek-v4.1: Guard bounded replay in the breakable prefill graph off CUDA and under prefill CP

[Upstream PR](https://github.com/sgl-project/sglang/pull/44141) · state: open · merged: False

## Original PR description

## Motivation

Follow-up to #43736. Decoder SWA bounded replay inside the breakable prefill CUDA graph relies on a graph tail block that only the CUDA dsv4 backend builds at capture, and whose metadata covers a rank's full rows. Off CUDA, or with prefill context parallelism, the combination currently fails at graph capture instead of at argument validation.

## Modifications

- `deepseek_v4_hook.py`: with `--enable-decoder-swa-bounded-replay`, reject the breakable prefill graph on a platform other than CUDA and with prefill CP (`--enable-prefill-cp` or `attn_cp_size > 1`). Eager prefill keeps CP and HIP as before; the breakable graph without bounded replay is untouched.
- `deepseek_v4.py`: assert that a tail inside a breakable graph carries the captured `scatter_indices`, so an eager tail can never be gathered live under a replay.
- New CPU unit test `test/registered/unit/server_args/test_dsv41_bounded_replay_graph_guards.py` (3 cases: non-CUDA rejected, prefill CP rejected, eager prefill / no bounded replay still admitted).
