# [Fix] encoder: Prevent scheduler crash on Encoder failure

[Upstream PR](https://github.com/sgl-project/sglang/pull/47243) · state: open · merged: False

## Original PR description

## Motivation

In EPD mode, an Encoder request can fail before multimodal input IDs have been generated. For example, `/scheduler_receive_meta_data` may return HTTP 502 when the Encoder connection is reset.

The Language server then creates an abort request with `origin_input_ids=None`. While streaming the error response, `OutputStreamer` calls `len(req.origin_input_ids)`, raising a `TypeError` and causing the scheduler process to exit. A request-level Encoder failure therefore brings down the Language server.

## Modifications

Normalize missing input IDs to an empty token array when constructing an abort request in the Encoder receiver. This allows the existing abort path to report the Encoder error without crashing the scheduler. Successful requests are unaffected.

## Accuracy Tests

No model computation or successful-request path is changed.

## Speed Tests and Profiling

Not applicable; this change only affects error handling.
