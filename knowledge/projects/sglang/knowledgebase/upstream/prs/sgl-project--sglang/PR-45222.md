# [Perf] unified-memory: Allocate free pages from each sub-pool's own end first

[Upstream PR](https://github.com/sgl-project/sglang/pull/45222) · state: closed · merged: True

## Original PR description

## Motivation

The unified memory pool shares one buffer between sub-pools that grow toward each other from its two ends (for example SWA from the low end and FULL from the high end). When a sub-pool reused freed pages, `MultiEndedAllocator.take_physical` drained `_free_phys_pages[:n]` in list order for both grow directions. Compaction sorts that list ascending and frees append to it unsorted, so a grow-down pool handed out its lowest free pages first: the ones nearest the boundary it shares with its neighbour rather than the ones nearest its own end. Pages in use near the boundary hold it in place until compaction moves them, because a flush retreats the watermark only over free pages already contiguous with it.

## Modifications

- End pools (`grow_direction` "up" or "down"): `take_physical` now drains the free pages nearest the pool's own end, the lowest ids for a grow-up pool and the highest for a grow-down pool.
- `_take_free_pages_from_end` sorts the free list on the device and takes a prefix or a suffix, so the remainder stays ascending. The sort runs only when the list was rebound since it was last known sorted, tracked by tensor identity (`_free_phys_sorted`); there is no host sync because the length comes from tensor metadata. A request that takes every free page needs no sort.
- Float middle pools (`FloatMultiEndedAllocator`): a middle pool has no end of its own, so each request takes its holes from one end of the ascending hole list and the next request takes them from the other end. Only a request that drains holes and succeeds flips the turn.
- Only the order in which already-free pages are handed out changes. Free-list membership, accounting, binding, compaction, the growth path, pending-reuse protection, move gates and rollback are unchanged.

## Test

- `test/registered/unit/mem_cache/test_unified_hicache_transfer_lifecycle.py::TestPhysicalReservation::test_pending_reservation_blocks_moves_until_its_load_is_queued` now frees its interior hole after the reservation instead of before. It used to rely on the reservation landing on the end-of-band rows that list order handed out first; with own-end-first order the reservation would fill the interior hole and leave nothing to relocate. The test checks the same property and passes before and after this change.
- The unified-pool unit tests under `test/registered/unit/mem_cache/` were run on this branch and on its base commit with the same outcomes.
