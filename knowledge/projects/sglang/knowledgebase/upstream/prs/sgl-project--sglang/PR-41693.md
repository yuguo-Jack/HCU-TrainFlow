# [DCP] [HiCache] Support MLA DCP storage in file and Mooncake

## Motivation

HiCache rejects L3 with DCP. Logical token ranges span rank-local physical pages, while replicated MLA cache keys and writer rules do not identify distinct DCP shards. Enable aggregated MLA serving with file and native Mooncake storage.

This work grew out of experiments with Kimi-K3 serving configurations.

## Modifications

- Translate logical DCP pages at the storage boundary and identify fixed-topology shards.
- Publish only the prefix completed on every required rank; budget prefetch in logical tokens.
- Preserve main's batched Mooncake I/O, including selective writes when some pages already exist. Scope new exact-byte checks to DCP storage.

Writers and readers must match topology, page geometry, dtype, layout and model identity. Hybrid and P/D support are in the following drafts. Unsupported backends, `buffer_only`, unified/packed or separate-scale pools, and speculative DCP L3 remain rejected. General Mooncake I/O hardening is outside this change.

## Accuracy Tests

Before means the preceding recurrent-file dependency (`dc47b1be49`); after means this stage (`70a39075a3`). Rejections are verified by argument/controller tests, not failed GPU launches.

| Scenario | Before | After |
| --- | --- | --- |
| DeepSeek-V2-Lite, file L3, TP2/DCP2 and TP8/DCP4 or DCP8 | DCP L3 rejected | Fresh process restores 512 tokens, zero device/host hits; exact writer cached-replay IDs |
| DeepSeek-V2-Lite, native Mooncake DRAM, TP8/DCP8 | DCP L3 rejected | 14 requests including main and patched controls; fresh reader restores 512/1024 tokens on all eight ranks; exact IDs and logprobs |
| HiCache SSD offload through file L3 | DCP L3 rejected | Functional file restore above; physical SSD pressure was tested on the hybrid child tree, not separately on this stage |
| Mooncake SSD offload | DCP L3 rejected | Physical demotion/readback was tested on the hybrid child tree; no stage-only SSD result claimed |

16 changed/neighboring CPU files, six GPU descriptor-copy tests, native Mooncake byte/controller checks, and pre-commit passed. The selective-write regression fails before the logical-page indexing correction and passes after it. Kimi-K3, B200 and hosted CI were not rerun for this refresh. Older stack results are not evidence for this head. No performance claim.
