# [NPU] dspark: complete --speculative-dspark-align-verify-tokens-to-graph-tier on Ascend

[Upstream PR](https://github.com/sgl-project/sglang/pull/48105) · state: open · merged: False

## Original PR description

## Motivation
`--speculative-dspark-align-verify-tokens-to-graph-tier` has both halves in tree already: the planner side (pad every request up to the cuda-graph tier, budget the verify tokens with the SPS table) and the CUDA replay of those tiers. On Ascend the flag was effectively inert as soon as more than one request shared a verify step.

The DSV4 target-verify graph baked its q layout from`bs * draft_width` , so any graph tier whose slots did not each span a full draft row fed the fused compressor a`ropeSin` table of the wrong length and graph capture died. The eager verify metadata carried the same assumption, and`graph_metadata[bs]` aliased every tier that shared a slot count. This PR makes the flag actually work on Ascend.

## Modifications
- `ascend_dsv4_backend.py`
  - Build the graph's`cu_seqlens` /`swa_loc` /`c4_pad` /`c128_pad` /`topk` slices from the batch's compact ragged layout (the cumsum of verify lengths) instead of`bs * width` .
  - Derive per-row verify lengths in the position fillers and in the eager verify compress metadata (new`row_lens_cpu` argument); uniform callers omit it and keep the historical`tokens // n_draft` geometry, so EAGLE / NGRAM / static ragged paths are untouched.
  - Refresh the compressor boundary positions,`cu_seqlens` , and`seqused` from the layout the runner stages on every replay.
  - Declare`supports_ragged_verify_graph = True` and`requires_uniform_ragged_capture = True` .
- `base_attn_backend.py` — add the`requires_uniform_ragged_capture` backend capability (default`False` ).
- `decode_cuda_graph_runner.py` —`_ragged_capture_slots` captures full-width rows when any wrapped backend declares that capability (`max(1, num_tokens // captured_req_width)` ), which keeps`(slots, tier)` unique so one tier cannot overwrite another's graph metadata. Adds a`getattr` guard for the wrapped-backend list.
- `dspark_schedule.py` — bound the planner's topk-selection kernel to the Ascend UB (`BLOCK_C / BLOCK_CP` 64 / 256 → 16 / 32) so graph capture no longer fails with a UB overflow. Non-NPU devices keep the original tiles.
- Unit tests — a case where ragged rows use their own verify length, plus capability tests asserting the DSV4 backend opts in and the generic Ascend backend does not.
## Accuracy Tests
Environment: 8x Ascend,`DeepSeek-V4-Flash-0731-w8a8` , compact ragged mode plus the align flag.

- GSM8K 200@32: 0.970 with a 3.935 mean accept length, on par with the 0.965 single-tier baseline.
- 183 NPU unit tests pass.
