# [Fix] sgl-router: Refuse prefill workers that cannot compute before bootstrap under --decode-dispatch-limit

[Upstream PR](https://github.com/sgl-project/sglang/pull/45120) · state: closed · merged: True

## Original PR description

## Motivation

Follow-up to #44402.

`--decode-dispatch-limit` sends a request on to decode only once earlier requests on the same prefill rank have got their KV. A prefill engine with the default `--optimistic-prefill-attempts 0` and `--disaggregation-decode-allocation-policy early` computes a request only once its decode peer has bootstrapped (`PrefillBootstrapQueue.pop_bootstrapped` pops a request at `KVPoll.WaitingForInput` only). The two then wait on each other: at most N requests per prefill rank ever run, the rest sit in prefill's bootstrap queue until `SGLANG_DISAGGREGATION_BOOTSTRAP_TIMEOUT` (300 s) and the router answers 504 after up to `--stale-request-timeout-secs`. #44402 documents the requirement but nothing enforces it, so a router started with the flag against default engines fails only under load.

## Modifications

- `introspect.rs`: read `optimistic_prefill_attempts` and `disaggregation_decode_allocation_policy` from `/server_info` (both are top-level fields of the engine's resolved server args, next to `disaggregation_mode`) into `ServerInfo::prefill_before_bootstrap`: `Some(true)` when attempts are above 0 or the policy is `prefill_complete` (the engine's `can_prefill_before_bootstrap` accepts either), `Some(false)` otherwise, `None` when the engine predates the field or did not answer.
- `manager.rs`: with `--decode-dispatch-limit` set, refuse to register a prefill worker whose `/server_info` says `Some(false)`, with an `error!` naming both engine flags, the same way a mixed PD/plain worker is refused today. `None` only warns, so older engines keep registering.
- Docs: REFERENCE.md and the CLI help name `prefill_complete` as the other accepted engine setting and say that other prefills are refused.

## Testing

- `introspect::tests::fetch_reports_whether_prefill_runs_before_bootstrap`: the four `/server_info` shapes map to `Some(true)` / `Some(true)` / `Some(false)` / `None`.
- `manager::tests::manager_refuses_prefill_that_cannot_compute_before_bootstrap`: under a limit of 1, a prefill reporting `optimistic_prefill_attempts: 0` never enters the registry and one reporting `2` does. Fails without the `register_one` change (the worker registers).
