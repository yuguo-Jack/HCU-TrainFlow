# [Fix] moe: apply the softmax correction bias on GPU; ERNIE-4.5 router in fp32

[Upstream PR](https://github.com/sgl-project/sglang/pull/46669) · state: open · merged: False

## Original PR description

## Motivation

1. `fused_topk` never reads `correction_bias` on its softmax branch (`python/sglang/srt/layers/moe/topk.py:1259-1315`). The aiter path (1270), the Triton router `_jit_moe_fused_gate(gating_output, None, ...)` (1301) and `topk_softmax` (1309) all drop it. ERNIE-4.5 (`ernie4.py:96`) and ERNIE-4.5-VL (`ernie45_moe_vl.py:210,243`) build `TopK(use_grouped_topk=False, correction_bias=...)` with the default softmax scoring, so on CUDA and ROCm their `moe_statics.e_score_correction_bias` is ignored. The reference router (`Ernie4_5_MoeTopKRouter`) selects with `topk(softmax(logits) + bias)` and weights the chosen experts by the unbiased probabilities. LongCat-Flash routes the same way and avoids the problem only because it forces `self.topk.forward = self.topk.forward_native` (`longcat_flash.py:298`).
2. `ernie4.MoEGate` creates the weight and bias without a dtype, so both are bf16 under the loader's default dtype. The checkpoint stores both in fp32, and HF keeps them in fp32. In ERNIE-4.5-21B-A3B the bias has mean 62.9 / 53.4 / 42.5 (MoE layers 1-3) and a per-expert std of about 1e-3. bf16 spacing at that magnitude is 0.25, so all 64 experts get one value. Fixing only the bias dtype (#38719) does not help while (1) stands.

**Impact**

- ERNIE-4.5 MoE models served by `ernie4.py` (21B-A3B, 300B-A47B) on CUDA and ROCm route 15-22% of tokens per MoE layer to a different expert set than the reference. The load-balancing bias the model was trained with is never applied.
- ERNIE-4.5-VL has fp32 gates and an fp32 bias, but its `TopK` takes the same branch, so it is affected by (1). This is from reading the code; I did not run it.
- RL setups that train with the HF router and sample with SGLang see these tokens routed off-policy.
- Cost: only gates with a softmax correction bias take the new branch, which is a few small torch ops (softmax, add, top-k, gather, renormalize) instead of one Triton kernel. The fp32 gate GEMM is [tokens, hidden] x [hidden, 64].

## Modifications

- `fused_topk`: when scoring is softmax and a correction bias is given, use `fused_topk_torch_native`, which already implements the reference arithmetic (the path LongCat reaches through `forward_native`). The ids are cast to int32, like the fused kernels return. The CPU AMX `fused_topk_cpu` is unchanged; it already applies the bias.
- `ernie4.MoEGate`: fp32 weight and bias, fp32 logits (`F.linear(hidden_states.float(), w)`). The bias is passed to `TopK` as 1-D on every platform. Before, it was squeezed only on NPU/CPU, and `fused_topk_torch_native` needs 1-D. This overlaps with the ernie4 hunk of #38719.

The code, the test and this description were drafted with an AI coding agent (Claude Code).

## Accuracy Tests

I captured gate inputs for the first 4 layers of `baidu/ERNIE-4.5-21B-A3B-PT` on 8192 tokens (4 x 1024 wikitext-2, 4 x 1024 Python source). At each MoE layer I ran SGLang's `ernie4.MoEGate`, built under the bf16 default dtype and loaded with the checkpoint values, then `select_experts` with the `TopKConfig` that `Ernie4Moe` builds, on CUDA. I compared the result with the reference router: fp32 gate, fp32 softmax + bias, top-6.

| MoE layer | tokens with a different expert set: main | top-k fix only (bf16 gate) | this PR |
|---|---|---|---|
| 1 | 17.7% | 1.6% | 0.00% |
| 2 | 15.0% | 1.4% | 0.00% |
| 3 | 22.0% | 1.2% | 0.00% |

On main, adding +10 to the bias of six experts changes no selected expert. vLLM's ERNIE router (fp32 gate, bias applied in `FusedTopKBiasRouter`) gives 0.00% on the same inputs.

End to end, I ran `sgl.Engine` on the same 4-layer model (CUDA graphs, triton attention, `return_routed_experts=True`) on 4 x 512-token prompts. The share of prompt tokens whose expert set differs between main and this PR is 17.2% / 15.6% / 25.7% for MoE layers 1 / 2 / 3.

Environment: main at ce77d5e, torch 2.14.1+cu130, triton 3.8.0, RTX 5070 Ti (sm_120).

**Unit test**

`test/registered/moe/test_topk_softmax_correction_bias.py` runs `select_experts` with softmax scoring and a correction bias (64 experts, top-6, ERNIE-like bias). It checks the ids exactly and the weights against the reference, plus a guard that the inputs depend on the bias.

- On main it fails: 46.7% of the selected ids differ.
- With the fix it passes.

The engine run above completed with the patched build, including prefill and decode CUDA graph capture.

No end-to-end accuracy benchmark (GSM8K / MMLU) was run: the full ERNIE-4.5-21B-A3B does not fit on the 16 GB GPU used here. The routing comparison above covers the first 4 layers.

## Speed Tests and Profiling

Not benchmarked. Only gates that combine softmax scoring with a correction bias (ERNIE-4.5, ERNIE-4.5-VL) take the new branch in `fused_topk`. All other models keep the fused kernels. On that branch, routing is a few small torch ops (softmax, add, top-k, gather, renormalize) over [tokens, 64] instead of one Triton kernel. The ERNIE gate GEMM becomes fp32: [tokens, hidden] x [hidden, 64].
