# [Fix] Preserve text sub-config dtype under thinker_config in get_hf_text_config

[Upstream PR](https://github.com/sgl-project/sglang/pull/43293) · state: open · merged: False

## Original PR description

## Motivation
Fixed #43157 

In `get_hf_text_config`, when handling multimodal models with `thinker_config` (such as Qwen2.5-Omni / Qwen3-Omni), `thinker_config.text_config.dtype` was unconditionally overwritten with `thinker_config.dtype` using `setattr`.
In `transformers-v5`, `thinker_config` typically does not carry an explicit `dtype` (it is `None`). When checkpoints only declare the precision on `thinker_config.text_config` (e.g. `torch.bfloat16`), this unconditional assignment erased the existing valid `dtype` to `None`, causing downstream model loading / dtype verification to fall back to `float32` and downcast unexpectedly.

## Modifications

1. **`python/sglang/srt/utils/hf_transformers/common.py`**:
   - Guard the assignment to `thinker_config.text_config.dtype` so it only populates from `thinker_config.dtype` when `getattr(thinker_config.text_config, "dtype", None) is None`.
2. **`test/registered/unit/utils/test_hf_transformers.py`**:
   - Added `test_thinker_config_preserves_text_sub_config_dtype_when_thinker_dtype_is_none` to verify that an existing `dtype` on `text_config` is preserved when `thinker_config.dtype` is `None`.
   - Added `test_thinker_config_propagates_dtype_when_text_sub_config_dtype_is_none` to verify that parent `dtype` is still properly inherited when `text_config` lacks a `dtype`.

This is a config parsing and precision propagation fix, does not alter numerical kernels
