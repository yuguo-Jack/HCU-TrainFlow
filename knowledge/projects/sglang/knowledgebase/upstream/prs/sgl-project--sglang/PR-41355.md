# [AMD] Fix RMSNorm forward_hip on vLLM's in-place fused_add_rms_norm

[Upstream PR](https://github.com/sgl-project/sglang/pull/41355) · state: closed · merged: False

## Original PR description

## Summary

With `SGLANG_USE_AITER` unset (the default), `RMSNorm` and `GemmaRMSNorm` on ROCm run `forward_hip` on `vllm._custom_ops`. Both call `fused_add_rms_norm` with six arguments, `(out, input, residual_out, residual, weight, eps)`. vLLM and ROCm/vllm both define it as `fused_add_rms_norm(input, residual, weight, epsilon)` and update `input` and `residual` in place. So every layer with a residual fails:

```
TypeError: fused_add_rms_norm() takes 4 positional arguments but 6 were given
```

The six-argument call came in with #13814 (`RMSNorm`) and #21188 (`GemmaRMSNorm`). The argument order doesn't match aiter's `rmsnorm2d_fwd_with_add` either (its `residual_in` comes before `residual_out`), and `forward_hip` only runs when aiter is off.

This PR calls the vLLM op on copies of `x` and `residual`, so `forward_hip` stays out-of-place, and fixes the comment that documented the wrong signature.
