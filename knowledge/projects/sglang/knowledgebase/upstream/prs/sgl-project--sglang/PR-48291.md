# [Fix] model_loader: Stop checkpoint prefetch on interrupted weight loading

[Upstream PR](https://github.com/sgl-project/sglang/pull/48291) · state: open · merged: False

## Original PR description

## Motivation

Both safetensors iterators stop background checkpoint prefetch after normal exhaustion, but skip that cleanup when shard parsing raises or the consumer closes the generator early. The finite worker can continue reading checkpoint shards after its consumer has stopped.

This follows #41588, which explicitly scoped its cleanup to normal exhaustion. It does not change PT checkpoint buffering in #48048.

## Modifications

- Put existing cooperative prefetch cancellation and bounded joining in each iterator's exit path.
- Preserve the original load exception or `GeneratorExit` if prefetch cleanup times out, with a warning. Normal-exhaustion cleanup timeouts still propagate, including when iteration happens inside a caller's unrelated `except` block.
- Extend the existing CPU prefetch suite with deterministic lifecycle regressions and timeout cases.

The buffered shard-loading executor still waits for its own pending loads before prefetch cleanup. This does not interrupt a kernel-blocked read or close a generator retained by a caller without exhausting or closing it.

## Accuracy Tests

Validation base: `f3ef1a32fd79fc3b833afb114d80bf5b58a98a01`. The two changed files were unchanged at the pre-publication upstream head `612cf5c165a59c49bc2f77728a6c581362c419c2`.

- New lifecycle regression: both iterator implementations × corrupt-file parsing / early close after copying a yielded tensor with `default_weight_loader`. All four subcases fail on the base and pass with the fix.
- Uses real SGLang imports, safetensors files/parser, CPU tensors, the prefetch coordinator, cancellation handle and worker threads. An event delays the prefetch file-I/O boundary to make consumer-first termination deterministic.
- Existing prefetch suite: **23 tests passed**, including eight simulated-cleanup-timeout subcases. The timeout cases mock the prefetch handle to exercise an otherwise 60-second timeout boundary.
- Related `test_weight_utils.py` and `test_default_model_loader.py`: **16 tests and 17 subtests passed**.
- Independent AI review and a separate 16-case consumer matrix: **6 failed / 10 passed on the base; 16 passed with the fix**. Two additional caller-exception checks passed.
- `pre-commit run --all-files`: **passed**, including Rust formatting and workspace Clippy.

Local environment: Python 3.12, Torch **2.15.0+cpu** (the repository pins 2.14.1), safetensors 0.8.0 and transformers 5.19.0. No full server/model-inference, GPU, multi-rank, or NFS validation was performed.

AI assistance was used for investigation, implementation, test development and a separate AI review. The independent review was not a human review.

## Speed Tests and Profiling
