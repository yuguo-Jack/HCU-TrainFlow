## Motivation

<!-- Describe the purpose and goals of this pull request. -->

`pyproject_xpu.toml` pins `sglang-kernel-xpu` by the URL of one release asset, so every kernel release needs a new URL. The release workflow already publishes each XPU kernel wheel to a package index. This PR resolves the kernel from that index by version, the way CUDA pins `sglang-kernel==X.Y.Z`. A kernel bump becomes a one-line version change.

## Modifications

<!-- Detail the changes made in this pull request. -->

- `pyproject_xpu.toml` pins `sglang-kernel-xpu==0.5.0` and adds two explicit uv indexes. `[tool.uv.sources]` takes the kernel from the SGLang XPU index and torch, torchaudio, torchvision and triton-xpu from the PyTorch XPU index.
- `triton-xpu` is listed in both the dependencies and the build requirements due to uv source resolution logic.
- pip ignores `[tool.uv.*]`, so a plain `pip install .` looks for torch and the kernel on PyPI and fails. The XPU Dockerfile, the XPU PR CI and the XPU install docs now install with `uv pip install`, and the docs also show the pip form with `--extra-index-url` for the PyTorch XPU and SGLang XPU indexes.
- The Dockerfile's `SG_LANG_KERNEL_SOURCE=source` should work as before.
- `xgrammar` is installed with `uv pip` too.
