# [Fix] benchmark: Share request logging across Python backends

[Upstream PR](https://github.com/sgl-project/sglang/pull/47165) · state: open · merged: False

## Original PR description

## Motivation

`--print-requests` currently asserts for every backend except `sglang-oai-chat`, and multi-turn chat produces a different request ID and log pair for every turn. This addresses the TODOs to share request logging across the other benchmark functions.

## Modifications

Move logging into a wrapper around the selected Python request function, after multi-turn composition. Each logical request, including a whole conversation, gets one UUID and one start/end pair. The wrapper runs after concurrency admission and covers warmup too.

Preserve returned results and progress updates. Redact prompts, generated text and text chunks in the printed copies. Exceptions and cancellation still propagate, with `output="None"` in the end log when no result was returned. Remove the chat-only restriction and clarify the CLI help.

## Accuracy Tests

- Added five CPU tests using fake backends and a local HTTP stub for native generation, OpenAI completions and multi-turn chat.
- New tests plus existing prompt-length/streaming tests: **7 passed, 16 subtests passed**.
- Verified the non-chat and multi-turn regressions fail on the unchanged base: backend assertion and eight log lines instead of four, respectively.
- All applicable pre-commit hooks passed for both changed files.

Model accuracy tests are not applicable to this benchmark logging change.

## Speed Tests and Profiling

No model or inference execution changes. With `--print-requests` disabled, the logging wrapper is not installed.
