# [Refactor] layer-boundary: Bind residual completion to producer updates

## Motivation

A deferred output must retain the producer update that gives its residual meaning. Completing a non-additive update through a generic residual add can lose per-invocation state or complete the wrong operation at a consumer or pipeline handoff.

## Modifications

Bind output completion to the producer update invocation, carry it through consumer reads and terminal/PP handoffs, and validate unsupported handoffs before execution. Resolve the construction-selected reduction, reduce-scatter and gathering callbacks on the invocation-bound reader. Forward consumer invocation binding through output-transform wrappers while keeping their fusion callbacks suppressed. Preserve callback slot order, group and row capabilities; use that same selection for carried completion. Keep neighbour facts free of layer-bound callbacks while retaining the layer-independent token-order gather. Preserve CP gather/take-back ordering. Move reusable boundary test fixtures into the existing test helper module so model tests can run independently.

Terminal reads bind invocation context through the same capability validation as stage entry. Successful terminal/PP export releases pending contribution state, including state retained by stale output handles. Bound producer updates must have `bind = None` before any exit route can use them.

This PR provides the shared completion contract. Inkling and DeepSeek V4 integration are in the next two PRs.

## Accuracy Tests

- Independent common-layer CPU suite: 372 passed, 7,315 subtests.
- The new invocation callback regression fails on the previous implementation for ordinary declared sums, reduce-scatter and gathering, and passes with the fix. It checks two contexts, callback ordering, selected groups/rows and one binding per invocation; carried completion is a passing control.
- Coverage includes bound updates, carried finalizers, PP handoffs, callback-free facts and token-order gathers. The V4 integration adds a bound row-transport binder to the strong facts walker; a mutation that retained that callback failed the test.

## Speed Tests and Profiling

No standalone speedup claim. End-to-end adapter validation and remaining performance limits are described in the model PRs.

## Current Stack Validation

All three updated adapter commits passed pre-commit independently; the two K3 commits are unchanged. The final stack CPU suite passed **481 tests and 7,409 subtests**, with **21 hardware-specific skips**. Independent common-layer and Inkling boundary suites passed **372 tests / 7,315 subtests** and **386 tests / 7,329 subtests**, respectively.

Four new regressions fail on the prior implementation and pass with the fixes. They cover terminal export releasing state retained by an old output handle (including a failing final norm), terminal reader binding for written/pending/fused output with two contexts, rejection and cleanup when binding changes read capabilities, and rejection of bindable update results on both immediate and deferred exit paths. Existing tests cover the converted containers, short-convolution positions and stateless V4 terminal reads.

The earlier callback-selection, transformed-reader and row-transport context regressions remain covered. No GPU tests or formal performance benchmarks were rerun for these fixes; prior GPU evidence retains its stated limitations.

## Landing

Rebased onto main `d59c3448b0` for merge. Validation above predates this rebase; no tests or benchmarks were rerun as part of landing.
