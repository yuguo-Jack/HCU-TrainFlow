# [Fix] flashinfer: Read a replayed draft extend's whole sliding window

[Upstream PR](https://github.com/sgl-project/sglang/pull/46472) · state: open · merged: False

## Original PR description

## Motivation

An EAGLE draft extend writes `num_tokens_per_req` rows per request, the accepted ones first, and each row attends over its own sliding window. Planned eagerly, FlashInfer's window wrapper starts its read a window before the first of those rows. Replayed from a CUDA graph, the draft extend plans without prefix lengths, and `update_sliding_window` derived them as `seq_lens - num_accept_tokens`, as if only the accepted rows were queries. The read then started up to `num_tokens_per_req - num_accept_tokens` tokens too late: once a sequence is longer than the window plus the accepted tokens, accepted row j lost up to `num_tokens_per_req - num_accept_tokens - j` of the earliest keys in its window.

This hits a draft with sliding-window layers (for example an EAGLE3 draft run with `--speculative-draft-window-size`) on FlashInfer with draft-extend CUDA graphs on, on any KV pool. The draft's proposals change; the target still verifies every token.

This PR used to carry wider FlashInfer and TRTLLM MHA window support and backend allow-list changes. Upstream's unified-memory rewrite absorbed those, and this one replay fix is what remains.

## Modifications

A draft-extend input now plans the window from `seq_lens - num_tokens_per_req`, the read its eager plan makes (`layers/attention/flashinfer_backend.py`).

Tests:
- CPU, `test/registered/unit/layers/attention/test_flashinfer_draft_extend_window.py`: a graph replay and an eager plan of the same draft extend read the same window for every row (lengths [12, 5, 12] for a window of 8 and four rows per request); on main the replay reads [9, 5, 10].
- CUDA (SM90), `test/registered/attention/unittests/dense/test_draft_window_attention.py`, with a runner in `python/sglang/test/kits/attention_unittest/runner_modes/speculative_draft_window_runner.py`: the eager draft extend against an independent window reference for every row of the block, then the captured replay against the eager outputs, with fewer tokens accepted than queried. It fails on main and passes with this PR.
