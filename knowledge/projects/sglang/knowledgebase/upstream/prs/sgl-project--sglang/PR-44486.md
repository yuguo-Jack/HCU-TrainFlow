# [Perf] quantization: Add the bias in the cuBLASLt epilogue for per-tensor FP8 linears

[Upstream PR](https://github.com/sgl-project/sglang/pull/44486) · state: open · merged: False

## Original PR description

## Motivation

Since #33148, per-tensor FP8 linears (`ModelOptFp8LinearMethod`) run FlashInfer `bmm_fp8` on SM90 and newer. It takes no bias, so the bias, which the previous CUTLASS path added in its epilogue, now costs a separate `output + bias` pass. Encoders such as BERT/XLM-R have a bias on every Linear (Qwen2 on QKV): `BAAI/bge-reranker-v2-m3` in ModelOpt FP8 spent 43 of 197 ms per batch in these adds on an RTX PRO 6000.

## Modifications

- With a bias, `apply_fp8_linear_bmm_flashinfer` calls `torch._scaled_mm(..., bias=bias, use_fast_accum=True)`: the same cuBLASLt GEMM as `bmm_fp8`, with the bias in its epilogue, as `apply_fp8_linear` already does. Without a bias nothing changes.
- New unit test: the output equals the bias-free path plus the bias, in FP16 and BF16.

## Accuracy Tests

bge-reranker-v2-m3 on 60 questions each of Ko-StrategyQA / MIRACL-ko: Recall@10 0.889 / 0.934 on both main and this PR, mean |logit - FP32| 0.142 / 0.191 vs 0.143 / 0.191. `test_fp8_utils.py`: 8 passed, 1 skipped (needs SM100).

## Speed Tests and Profiling

RTX PRO 6000 (SM120), torch 2.14.1, FlashInfer 0.7.1. GPU time of one `rerank` call on 128 pairs:

| bge-reranker-v2-m3 | FP16 | FP8, main | FP8, this PR |
|---|---|---|---|
| 128 x 320 tokens | 99.8 ms | 99.1 ms | **73.1 ms** |
| 128 x 640 tokens | 203.3 ms | 196.8 ms | **145.3 ms** |

The GEMM with a bias alone, over 12 shapes x M 1-16384 x FP16/BF16: 0.74x of `bmm_fp8` + add at the median, but 4-55% slower at 11 of 264 points, mostly FP16. There `torch._scaled_mm` picks a slower kernel even without the bias, because PyTorch's default cuBLASLt workspace is smaller than the 40 MiB FlashInfer passes; `CUBLASLT_WORKSPACE_SIZE=4096` closes the gap.
