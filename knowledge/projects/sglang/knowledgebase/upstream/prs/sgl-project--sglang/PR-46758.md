# [Fix] [AMD] fp8: Respect token padding in the native static quant fallback

[Upstream PR](https://github.com/sgl-project/sglang/pull/46758) · state: open · merged: False

## Original PR description

## Motivation

Fixes the `SGLANG_USE_AITER=0` crash reported in #46628 (part 2). It does not address the GSM8K accuracy loss tracked in the same issue.

Launching `neuralmagic/Mixtral-8x7B-Instruct-v0.1-FP8` on ROCm with `SGLANG_USE_AITER=0` fails in the qkv projection:

fp8_kernel.py:1030 native_static_quant_fp8: output.copy(output_data)
RuntimeError: The size of tensor a (17) must match the size of tensor b (16) at non-singleton dimension 0

On ROCm without CUTLASS FP8, `apply_fp8_linear` pads activations to 17 rows for `torch._scaled_mm` (`fp8_utils.py`, `output_padding = 17`), so `scaled_fp8_quant` allocates `max(17, M)` output rows. The AITER kernel writes only the first `M` rows, but the native PyTorch fallback copied its `M`-row result into the whole padded tensor. Any batch under 17 tokens therefore crashes: CUDA graph capture at bs=16, or the first batches with `--disable-cuda-graph` (`17 vs 7`).

## Modifications

- `python/sglang/kernels/ops/quantization/fp8_kernel.py`: `_native_static_quant_fp8` copies into `output[: input.shape[0]]` instead of `output`, matching what the AITER `static_per_tensor_quant` kernel writes. Padding rows stay uninitialized as before; the callers slice them away.

## Accuracy Tests

N/A. Behavior changes only where the old code raised. When `M >= 17`, or padding is off, `output[:M]` is the whole tensor and the result is identical. The AITER path is untouched.

## Speed Tests and Profiling

N/A. Same computation, now written to a slice view.
