# [Fix] Align conv layout when copying between mamba checkpoint pool an…

[Upstream PR](https://github.com/sgl-project/sglang/pull/43845) · state: open · merged: False

## Original PR description

## Motivation

The mamba checkpoint pool builds its conv buffers from the logical layout (`cache_params.shape.conv`, `(d, k)`), but the active pool may allocate conv windows transposed — the NPU backend allocates `(k, d)` to match its kernels. Copying conv states between the two pools then fails with a broadcast error, breaking `--enable-int8-mamba-checkpoint` on Ascend NPU in **both** directions:

- `store_from_active` (radix cache store):

  ```
  RuntimeError: shape mismatch: value tensor of shape [30, 1, 3, 4096] cannot be broadcast to indexing result of shape [30, 1, 4096, 3]
  ```

- `load_to_active` (cache-hit copy-on-write): the mirror-image error (`[30, 1, 4096, 3]` → `[30, 1, 3, 4096]`)

This is a completeness gap of the unified ssm-state-layout refactor (#36187): the active pool layout and kernels were updated, but the checkpoint pool copy path was missed. Note #43072 (int8 e2e test) would hit the same crash on NPU.

## Modification

Make both copy sites layout-adaptive: transpose when the last two dims do not match. When the layouts already agree (e.g. CUDA), the condition is false and the code path is unchanged.
