# [Fix] moe: Sync precompile lock and configure deepep_v2 timeouts

[Upstream PR](https://github.com/sgl-project/sglang/pull/44274) · state: open · merged: False

## Original PR description

fixes #44244.

addresses startup crashes with `--moe-a2a-backend deepep_v2` on cold DeepGEMM caches where ranks 1..7 race ahead into dispatch while rank 0 is compiling and hit the 100s ElasticBuffer timeout.

summary:
- in `_maybe_compile_deep_gemm_one_type_all`: removed `_DO_COMPILE_ALL` from the initial check so all local ranks enter `_local_rank_compile_lock`. rank 0 executes the precompile while ranks 1..7 wait on the file lock and skip redundant work.
- added cross-node `tp_group.barrier()` after the local rank compile lock when `tp_size > 1`.
- added `_deepep_v2_precompile_tp_barrier()` in `deepep_v2.py` matching `deepep.py` to synchronize ranks if `SGLANG_IN_DEEPGEMM_PRECOMPILE_STAGE` is set.
- exposed `SGLANG_DEEPEP_V2_CPU_TIMEOUT_SECS` (default 300) and `SGLANG_DEEPEP_V2_GPU_TIMEOUT_SECS` (default 100) and passed them to `ElasticBuffer` so timeout values are configurable.
- added CPU unit tests for precompile rank locking and ElasticBuffer timeout lifecycle.
