# [diffusion][post-training] Shared Flow-GRPO hooks for custom denoise loops (H3 / Cosmos / LTX2)

[Upstream PR](https://github.com/sgl-project/sglang/pull/37940) · state: closed · merged: False

## Original PR description

## Motivation

sglang-d already collects Flow-GRPO on the generic `_denoise` path (Qwen-Image), but the collection is a pile of `if batch.rollout` mixed into serving. Custom loops do not collect at all: Cosmos3 / LTX2 never return a trajectory, and H3 rejects `rollout`. Copying another SDE or collector per family does not scale.

This PR keeps the serving layout and one `flow_sde_sampling` kernel, and hangs three hooks on every custom loop so they return the same `rollout_trajectory_data`.

---

## Background

Flow-GRPO needs two things from the engine. Both already live on `Req.rollout_trajectory_data`:

1. **How each step updates the latent** — `x_t → x_{t-1}` plus that step's log-prob. The generic path is `scheduler.step`; when `rollout=True` it calls `flow_sde_sampling` (SDE / CPS / ODE).
2. **Three tensors/structs for the trainer** — `dit_trajectory` (per-step `x_t`, including the final frame), `rollout_log_probs`, and `denoising_env` (DiT cond at loop start: prompt / layout / guidance).


Replacing a whole `diffuse()` (verl-style) is not available here: sglang-d's grain is Stages. Swapping the loop would drop packed layouts, SP, and cache. RL has to hang off the existing serving loop.

Those three trainer fields are written at **three times**, so there are three hooks:

| When | Hook | If missing |
|---|---|---|
| Start of loop | `init_env` | No cond snapshot (`step` does not see cond) |
| Each step, before `scheduler.step` | `step_latents` | `x_t` is overwritten |
| End of loop | `finalize` | No final latent; lists are not stacked / SP-gathered |

The rollout gate lives inside the hooks. Call sites always invoke them. Serving uses a no-op observer. Loops do not wrap collection in `if batch.rollout`.

---

## Design

```text
init_env(...)                            # snapshot denoising_env, prepare session
for step:
    family DiT / CFG / packing
    step_latents(..., apply=update)      # record x_t, then scheduler.step or SDE
finalize(...)                            # append final frame, pack the three fields
```

<img width="1360" height="928" alt="flow-grpo-hooks" src="https://github.com/user-attachments/assets/be3930f2-14a4-4db9-abc2-13c3cd589329" />


One update kernel, two call sites:

- Families that already have a scheduler (Qwen-Image, Cosmos, LTX2 Euler): `apply = lambda: scheduler.step(...)`. Rollout enters `flow_sde_sampling` inside `step`.
- Families without `scheduler.step` (H3): map `-v`, unsqueeze packed rows, call `batch.scheduler.flow_sde_sampling` directly. No second SDE.

---

## Changes

- Add `denoise_loop_observer.py`: `init_env` / `finalize`; no-op when `rollout=False`.
- Add `step_latents`: record `x_t`, then run `apply`. Log-probs still come from `flow_sde_sampling`.
- Generic `_denoise`: replace scattered `if rollout` with the three hooks. Qwen-Image and other base-loop models need no per-model edits.
- Cosmos3 / LTX2: wrap the video `scheduler.step` in `step_latents`. Cosmos also calls observer start/end (it owns the full loop).
- H3: allow `rollout`; bind a `shift=1` FlowMatch scheduler; `to_flow_model_output = -v`; video uses the shared SDE, audio stays Euler; trajectory timesteps are `σ × 1000`.
- Tests: observer factory, trajectory collection, H3 `-v` ODE vs native Euler, sampling params accept `rollout=True`.

**Out of scope:** Helios / MOVA / LongLive2; LTX2 HQ res2s + rollout; a first-class H3 serving scheduler.

---

## Examples

### Qwen-Image (base loop; smallest diff)

The loop is `DenoisingStage._denoise`. The model does not override it.

- `init_env` reads `pos_cond_kwargs` / `neg` / `guidance` already on the context.
- `step_latents(..., apply=lambda: scheduler.step(...))` keeps FlowMatch Euler; rollout switches to SDE inside `step`.
- `finalize` collects log-probs, appends the last latent, gathers.

**No edits under the Qwen-Image model tree.** The hooks live on the base class.

### Cosmos3 (owns the loop; update already goes through the scheduler)

`Cosmos3DenoisingStage` runs UND/GEN, CFG-parallel, and video/action/sound itself.

- All three hooks: `init_env` cond is `text_ids` / `text_mask` / `fps`; video `step` goes through `step_latents`; then `finalize`.
- The update is unchanged: `scheduler.step` → `flow_sde_sampling`.
- Action / sound steps stay out of GRPO. Rollout still rejects I2V/V2V and action/sound — re-blending conditioned frames breaks the SDE Gaussian assumption. That is a product limit, not a missing hook.

**Hooks only. Cosmos packing is untouched; there is no second SDE.**

### MiniMax H3 (no `scheduler.step`; shows the contract is enough)

Serving: `scheduler=None`, in-place packed Euler, `x_0 = x + σ v`. `main` used to reject rollout.

Rollout adds glue, not a copied SDE:

1. Bind `FlowMatchEulerDiscreteScheduler(shift=1, num_train_timesteps=1000)` on H3's own video sigma table.
2. `to_flow_model_output(v) = -v`, matching miles `compute_noise_pred`.
3. Unsqueeze video target `[n_rows, width]` → `[1, n_rows, width]` and call the same `flow_sde_sampling`.
4. Audio stays deterministic Euler. Trajectory timesteps are `σ × 1000`.
5. `init_env` snapshots `encoder_hidden_states` / `h3_packed_layout` / `h3_token_tags`.

ODE with `-v` matches native H3 Euler (unit test).

**H3-specific work is sign and shape, not a second Flow-GRPO.**

| | Qwen-Image | Cosmos3 | H3 |
|---|---|---|---|
| Loop | base `_denoise` | fully custom | packed `minimax_h3_denoise_loop` |
| This PR | three hooks on the base class | start/end + video step | bind / `-v` / call the shared kernel |
| Latent update | `scheduler.step` | same | `flow_sde_sampling(-v)` |
| Cond | prompt / guidance | text_ids / mask / fps | packed layout + tags |
