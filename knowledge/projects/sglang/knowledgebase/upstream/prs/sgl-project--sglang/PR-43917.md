# [DSA] Split topk across CTAs for small CUDA BF16 TileLang sparse decode

[Upstream PR](https://github.com/sgl-project/sglang/pull/43917) · state: open · merged: False

## Original PR description

## Motivation

On CUDA with a BF16 KV cache, `tilelang_sparse_fwd` always used the single-pass kernel, which launches one CTA per (token, 64-head block). Decode, MTP verify and draft batches are only a few tokens, so the kernel ran on 1-6 of 132 SMs. On GLM-5.3-Flash H200 TP8 that is ~100 us per call, about 10% of TPOT at C=1. The existing split-topk partial/combine kernels were only used on HIP and for FP8 KV.

## Modifications

- On SM90 with BF16 KV, calls with `tokens * padded_heads <= 1024` take the split-topk partial/combine path with one KV tile per CTA. Larger calls keep the single-pass kernel.
- Tests cover the gate at the 64/128-head cutoffs, which kernel runs on each side of the 8-head cutoff (checked against torch and CUDA graph replay), and keep the existing BF16 cases on the single-pass kernels.

## Accuracy Tests

**GSM8K: 97.27%**

`sgl-eval run gsm8k` (48 threads, max tokens 16384, temperature 1.0, top-p 0.95). Server as in the speed tests, without `SGLANG_SIMULATE_ACC_*` and with `--reasoning-parser auto --tool-call-parser auto`.
