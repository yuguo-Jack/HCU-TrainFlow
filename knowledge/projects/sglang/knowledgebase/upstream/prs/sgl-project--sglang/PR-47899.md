# [Fix] qwen3.5: Keep CPU-offloaded GDN input projections separate

[Upstream PR](https://github.com/sgl-project/sglang/pull/47899) · state: open · merged: False

## Original PR description

## Motivation

With V1 CPU offload, `finalize_fused_in_proj()` can concatenate host-resident GatedDeltaNet projection weights into a plain tensor attribute. The offloader stages registered parameters for each forward, but this fused cache stays on the CPU. The first fused GEMM then fails with `mat2 is on cpu`.

Fixes https://github.com/sgl-project/sglang/issues/47896.

## Modifications

- Skip BF16 input-projection fusion when either projection weight is on the CPU, allowing the existing separate projections to use the offloader's staged parameters. Check devices after the existing eligibility checks so quantized projections without a `.weight` attribute remain supported.
- Extend the existing offloader regression coverage to either projection being offloaded and both being offloaded, comparing outputs with the resident projections.
- Put the existing AMD packing fixtures on the GPU so they continue to exercise supported fusion.

## Accuracy Tests

No new GPU model accuracy evaluation on this branch. Issue #47896 records successful warmup and serving with the same CPU guard applied to nightly `c10e0e177` on an RTX 5090, alongside separate model-loading and memory fixes. That run is prior evidence for the guard, not validation of this branch's head.

## Speed Tests and Profiling

No isolated performance comparison. The prior run in #47896 reported 0.98 output tok/s for ISL 2000 / OSL 128 and 0.95 output tok/s for ISL 2000 / OSL 1000 with a 32k shared prefix. Those results include the other fixes and memory settings described in the issue.

**Issue**

`test_gdn_input_projections_after_cpu_offload` looks up the projections with `getattr(model, name)` here and again at line 133. The repo rules do not allow new `getattr` calls. `getattr` also returns any attribute, not only a registered submodule.

**Fix**

Resolve the submodules once through the `nn.Module` API and reuse them:

```python
projections = [model.get_submodule(name) for name in offloaded]
for projection in projections:
    offloader.maybe_offload_to_cpu(projection)
...
for projection in projections:
    self.assertEqual(projection.weight.device.type, "cpu")
```
