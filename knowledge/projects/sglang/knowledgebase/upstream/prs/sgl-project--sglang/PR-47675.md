# [Refactor] memory-pool: Build MiniMax K-only index host pools from buffer info

[Upstream PR](https://github.com/sgl-project/sglang/pull/47675) · state: closed · merged: True

## Original PR description

## Motivation

Followup of #40916. The MiniMax K-only index pool now exports a `KEY_ROWS` `IndexKeyBufferInfo` with its model layer ids. `MHATokenToKOnlyPoolHost` is built from that info and the anchor host, keeps only the captured buffers, and no longer holds the device pool. The assembler takes the K-only index layer mapping from the info instead of `index_k_layer_id_mapping`, and the NPU K-only pool sets the same layer ids. The MiniMax-M3.1 NVFP4 index path is unchanged.

Host capacity, index dtype and the transfer path are unchanged.

## Accuracy

HiCache multi-turn KL with forced host hits against #40916, same commands on both sides. Assembled host pools and the H2D transfer sequence are identical to the parent, and every prefill-hit and decode-hit sample is served from host on both sides.

MiniMax-M3 (bf16 K-only index), tp 4:
```
#40916:  floor_kl 0.010994  prefill_kl 0.002564  decode_kl 0.030043
this PR: floor_kl 0.010994  prefill_kl 0.002564  decode_kl 0.030043
```

MiniMax-M3.1-Flash (NVFP4 index), tp 4, DSpark:
```
#40916:  floor_kl 0.723804  prefill_kl 0.853570  decode_kl 0.436467
this PR: floor_kl 0.723804  prefill_kl 0.853570  decode_kl 0.436467
```
