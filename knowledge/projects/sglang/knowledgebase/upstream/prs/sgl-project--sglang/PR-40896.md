# [Unified Cache] Abort requests whose external linker load fails instead of crashing the scheduler

[Upstream PR](https://github.com/sgl-project/sglang/pull/40896) · state: open · merged: False

## Original PR description

## Motivation

With the external cache linker (Mooncake / UMBP direct L3), any storage read error during a layer-wise load raised inside the model forward and brought the whole server down (SIGQUIT). Nodes were also published to the radix tree before their KV landed, so simply catching the error would have let other requests reuse unloaded slots.

## Modifications

- A linker load now lands in device slots private to the loading request. `load_back` no longer inserts the tail; the request inserts it like computed KV once the load is confirmed (`load_back_is_cache_owned()` keeps `cache_protected_len` at the device hit).
- `LayerWiseLoadCounter.wait_until` no longer raises. After the forward, `run_batch` calls `finish_external_linker_loads()`, which waits for the batch's load and agrees on the result across ranks (MIN), since an MLA dedup peer never sees the source's error.
- Requests whose load failed are aborted with 503 and never inserted into the tree; chunked requests go through the existing chunked-abort path. The MLA dedup source still issues its layer broadcasts on failure, so peers do not hang.
- The two backends share one `LayerWiseLoadCounter` (first commit, behavior-neutral). The pending-load locks, the load completion queues, and the COMMIT / adopted-page load phase are removed.
- A failed forward commits no output (token or embedding) and is aborted like a sampling-mask failure; PD prefill aborts it instead of sending its KV to decode. A refused `load()` frees its slots and falls back to recompute.
- An SWA branch point placed before the L3 hit was known is dropped once the loaded tail covers it.

## Tests

- `test_unified_cache_linker.py`: request-private load, dedup on insert, failed-load cleanup (Full and Full+SWA) on both tree cores, cross-rank verdict, counter semantics.
- End to end with Mooncake on DeepSeek-V3.2 (TP1, and TP2 with `--enable-linker-mla-dedup`), injecting a mid-load failure: the request gets a 503, the server keeps serving, and the next identical request hits L3 with output identical to a cold run.

## Accuracy and performance

Base = upstream `86cb4a0f97`, PR = this branch. DeepSeek-V4-Flash-FP8 on 4x H200, the cookbook H200 FP8 low-latency recipe (TP4 + EAGLE 3/1/4) plus `--enable-unified-cache-external-linker` with Mooncake. Every phase starts from a flushed device cache; two runs per side (base/PR, then PR/base).

**Performance** — `bench_serving`, random 4096 in / 256 out, 128 prompts, concurrency 16. Mean of two runs.

| Scenario | Side | Mean TTFT (ms) | Median TTFT (ms) | Mean TPOT (ms) | Output tok/s |
|---|---|---|---|---|---|
| Backup only (no hit, 0/128 L3 loads) | base | 479.7 | 348.5 | 13.8 | 1016 |
| | PR | 459.5 | 351.6 | 13.9 | 1014 |
| Backup + load-back (same prompts, 128/128 L3 loads, 94% prefill hit) | base | 354.7 | 348.7 | 13.4 | 1070 |
| | PR | 335.0 | 358.2 | 13.0 | 1108 |

All deltas are inside the run-to-run spread (e.g. base load-back mean TTFT was 395 / 314 ms across its two runs).

**Accuracy** — run twice on one server: cold, then again after a device flush so prompts come back from L3.

| Eval | Side | Cold | After flush (L3) |
|---|---|---|---|
| gsm8k 5-shot, 1319 q (74 L3 loads after flush) | base | 0.954 / 0.955 | 0.953 / 0.951 |
| | PR | 0.955 / 0.952 | 0.955 / 0.957 |
| mixed-prefix gsm8k, 1000 q (~810 L3 loads after flush) | base | 0.966 | 0.967 |
| | PR | 0.969 | 0.968 |

Prefill hit tokens and L3 load counts match between base and PR in every phase.

**Agentic accuracy (SWE-bench Pro V2)** — base = `20948cdcc6`, PR = `dfd5534ba9`. 
Same server recipe with Mooncake over RDMA and `--max-total-tokens 524288`. The small device pool sends 65-70% of prefix-hit tokens through L3 load-back.

| | Base | PR |
|---|---|---|
| All 642 tasks, 1 run | 558 (86.9%) | 549 (85.5%) |
| 67 tasks the two sides disagreed on, rerun 3x per side | 138/198 (69.7%) | 140/201 (69.7%) |

The rerun estimate for the full set is -0.03 pt (95% CI [-0.9, +0.8]). Neither side logged a linker load failure or an HTTP error.
