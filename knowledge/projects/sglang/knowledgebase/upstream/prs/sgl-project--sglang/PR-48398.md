## Motivation

<!-- Describe the purpose and goals of this pull request. -->

In an eager GDN extend on the Triton prefill path, `GDNAttnBackend.forward_extend` splits the `[T, q | k | v]` conv output and calls `chunk_gated_delta_rule`. Before the chunk kernels run, q / k / v are always copied:

- when `q_dim + k_dim + v_dim <= 8192`, `fused_qkv_split_gdn_prefill` writes contiguous copies of all three;
- for wider layers, the backend passes `torch.split` views and FLA's `input_guard` makes three `.contiguous()` copies.

These copies are pure memory traffic: `l2norm_fwd` reads q / k once anyway, and `recompute_w_u_fwd` is the only kernel that reads v.

`chunk_fwd_o` also zero-fills its output (`torch.zeros_like`). The kernel stores every row that belongs to a sequence, so the fill matters only for rows past `cu_seqlens[-1]`. Two kinds of batch have such rows:

- the captured GDN prefill graph's buckets;
- eager extends padded for DP attention, where `prepare_mlp_sync_batch` pads `input_ids` and `extend_num_tokens` but not the sequence lengths.

For all other batches the fill is dead work.

Removing both costs is bitwise exact. It makes the q/k/v split + chunked delta-rule step of a GDN prefill layer 1.09x to 1.24x faster (table below). It does not time the in-projection, conv, gating, norm or out-projection.

## Modifications

<!-- Detail the changes made in this pull request. -->

- **`fla/l2norm.py`.** New `l2norm_fwd_strided` normalizes a `[1, T, H, D]` view whose heads are contiguous rows and whose tokens are `stride(1)` apart.
  - Each program loads the same `[16, BD]` block of rows that `l2norm_fwd_kernel` loads from the contiguous copy, with the same warps and stages, so every row is reduced in the same order. Any H works.
  - `l2norm_fwd_strided_supported` requires D <= 512, contiguous heads, a token stride that is a multiple of 16 elements, and a 16-byte-aligned base pointer. The alignment keeps the vectorized load layout of the copy.
- **`fla/wy_fast.py`.** `recompute_w_u_fwd` reads a single-batch v whose heads are contiguous rows in place.
  - This uses a `STRIDED_V` constexpr variant, so the kernel compiled for contiguous v is unchanged. Other layouts are still copied.
- **`fla/chunk.py`.**
  - New `chunk_gated_delta_rule_reads_strided_qk(q, k)` predicate: an NVIDIA device (`fla.utils.is_nvidia`) and `l2norm_fwd_strided_supported` for q and k. The bitwise match is verified on NVIDIA only, so other platforms keep `input_guard`'s copies.
  - When `use_qk_l2norm_in_kernel` is set, q / k / v are not all contiguous and the predicate holds, `chunk_gated_delta_rule` normalizes q / k from the views and passes v through. Every other tensor still gets the guard's `.contiguous()`.
  - The shared forward body moved into `_chunk_gated_delta_rule_fwd_normalized`; `ChunkGatedDeltaRuleFunction.forward` calls it.
  - New `no_padding_rows` argument, default `False`, passed down to `chunk_fwd_o`.
- **`fla/chunk_o.py`.** With `no_padding_rows=True`, the output is allocated with `torch.empty_like` instead of `torch.zeros_like`.
- **`linear/kernels/kernel_backend.py`, `gdn_triton.py`.**
  - New `extend_reads_strided_qkv(q, k)`. It returns False by default; `TritonGDNKernel` returns `is_cuda()` and the FLA predicate. So HIP / XPU keep main's q / k / v handling at every width: the fused split up to 8192 columns, `input_guard`'s copies above.
  - `TritonGDNKernel.extend` forwards `no_padding_rows` to the FLA kernel on every platform that runs it (CUDA, HIP, XPU), not to the CPU / NPU kernels. `chunk_fwd_o` is the same Triton kernel on all three and stores every row of every sequence; the zero-fill skip is tested on NVIDIA only.
- **`linear/gdn_backend.py`, eager `forward_extend`.**
  - The split views go to the extend kernel when it reads them; otherwise the fused split copy is used as before.
  - `no_padding_rows = (forward_metadata.logical_num_tokens == num_rows)`. `logical_num_tokens` is the batch's real token count, computed once per batch in the forward metadata (`hybrid_linear_attn_backend.py`). DP-padded batches therefore keep the zero fill.
- **Other extend paths.** The captured prefill graph (`_forward_extend_in_graph`) and multi-item scoring (`_forward_mis_segments`) are not changed and keep the zero fill, which the graph's padded rows need.
  - Up to 8192 q+k+v columns they keep the fused split.
  - Above 8192 columns they already pass `torch.split` views to the same kernel, so on NVIDIA those views are now read in place instead of copied by `input_guard`.
- **Tests and benchmark.**
  - New `test/registered/kernels/ops/attention/test_gdn_chunk_strided_qkv.py`.
  - New `test_eager_padded_rows_stay_zero` in `test_gdn_prefill_graph.py`, and its existing `test_replays_match_eager` now also runs at 16 / 48 heads (10240 columns), where the captured graph reads the split views.
  - `test_mamba_track_state_dtype.py` now also asserts `no_padding_rows` for a full and a padded batch.
  - `test/registered/attention/unittests/gdn/test_triton.py`: the existing `test_triton_prefill_keeps_contiguous_qkv_materialization` is replaced by `test_triton_prefill_qkv_layout`. The old test asserted that the Triton prefill always runs the fused split copy. On CUDA that copy is now skipped by design, so the new test asserts the opposite there (the extend kernel reads the views in place) and still asserts the fused split on other platforms. Both check the outputs against the reference.
  - New `test/registered/kernels/benchmark/attention/bench_gdn_chunk_strided_qkv.py` (cold-L2 `marker.do_bench`).

## Accuracy Tests

<!-- If this pull request affects model outputs (e.g., changes to the kernel or model forward code), provide accuracy test results. -->

The change is bitwise exact on every row that belongs to a sequence. Padded rows stay zero, as on main. All tests below pass on an RTX PRO 6000 Blackwell (SM120).

- **`test_gdn_chunk_strided_qkv.py`** (new, 4 tests):
  - `l2norm_fwd_strided` vs `l2norm_fwd(x.contiguous())`: bitwise for H in {1, 2, 4, 8, 12, 16, 32}, D in {64, 96, 128}, T in {1, 33, 1000}.
  - `chunk_gated_delta_rule` on split views vs contiguous copies: the output and the whole state pool are bitwise equal.
    - Layouts (key heads / value heads / extra projection columns): 16/32/0, 16/48/6144, 4/8/1024, 2/4/16.
    - Ragged varlen batches with partial chunks and length-1 sequences, permuted state slots, FP32 and BF16 states, and `no_padding_rows` False and True.
    - The test asserts that the strided path is taken. `torch.empty_like` is patched to return NaN, so any row the kernel does not store shows up.
  - Rows past `cu_seqlens[-1]` stay exactly zero on the strided path.
  - Views with an unaligned row stride take the copy path and still match.
- **`test_gdn_prefill_graph.py`** (2 tests):
  - `test_replays_match_eager`, existing: the captured-graph extend (zero-filled padding) is bit-for-bit equal to eager `forward_extend` (split views, no fill) on the output and the state pools. 5 batch shapes x FP32 / BF16 SSM states x 2 layouts:
    - 2 / 4 heads (1024 columns): the graph uses the fused split;
    - 16 / 48 heads (10240 columns), added here: the graph also reads the split views in place.
  - `test_eager_padded_rows_stay_zero`, new: an eager extend with 160 rows, 137 real tokens and `extend_num_tokens = 160`, as DP attention sets it.
    - Its padded rows are exactly zero (`empty_like` NaN-poisoned), and its real rows are bitwise equal to the unpadded extend.
    - This test fails if the flag is keyed on `extend_num_tokens`.
- **Also pass:** `test_chunk_gated_delta_rule.py` (31), `test_gdn_prefill_layout.py` (5), `test_mamba_track_state_dtype.py` (5, CPU), `unittests/gdn/test_triton.py` (13, including the updated `test_triton_prefill_qkv_layout`).
- **Kernel A/B (below):** the output and final states of every arm are bitwise equal to the `copies` arm at every point.
- **Not run in this PR:** end-to-end GSM8K. Outputs are bit-identical, so the score cannot change.

## Speed Tests and Profiling

<!-- If this pull request impacts inference speed, provide benchmarking and profiling results. -->

**Command.** The arms are `make_step` in `test/registered/kernels/benchmark/attention/bench_gdn_chunk_strided_qkv.py` (included). One run of `python3 test/registered/kernels/benchmark/attention/bench_gdn_chunk_strided_qkv.py` is one pass of them with `marker.do_bench` (cold L2), without a CUDA graph because `prepare_chunk_indices` reads `cu_seqlens` on the host.

**Arms.**
- `copies` = main: the fused split copy, or the three `input_guard` copies above 8192 columns.
- `views` = strided reads.
- `no_pad` = views + `no_padding_rows=True`, which is what eager extend now runs.

**Inputs.** Row-major `[T, (2H + HV) * 128]` BF16 conv output. A ragged varlen batch of 1 to 8 sequences. Gates from `fused_gdn_gating`. FP32 state pool.

**Hardware.** NVIDIA RTX PRO 6000 Blackwell Max-Q (SM120, 300 W). Image `lmsysorg/sglang:nightly-dev-20261103-797af717`, torch 2.14.1+cu130.
