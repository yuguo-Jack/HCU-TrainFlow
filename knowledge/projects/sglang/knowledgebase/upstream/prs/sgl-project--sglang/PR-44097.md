## Motivation

Unified Mamba/Conv compaction uses a gathered state tensor when relocating slots, which can OOM precisely when the allocator is reclaiming memory.

Seokwoo Song's four compaction commits are preserved, rebased onto main after #39294 was squash-merged.

## Modifications

- Copy disjoint physical state envelopes directly with the existing `copy_pages` kernel, removing the main-state gather temporary.
- Preserve main's `move_physical_pages` entry point, which calls the optimized move implementation.
- Retain sibling-state copying and ordinary copy-on-write behavior.
- Cover Mamba and Conv-only pools, both growth directions, eager/urgent/opportunistic compaction, state payloads and mappings, CUDA stream ordering, and CUDA graph readback.

## Motivation

<!-- Describe the purpose and goals of this pull request. -->

Unified compaction can OOM while reclaiming capacity because `MambaPool.copy_from` gathers selected states into a temporary GPU tensor. This affects both Mamba state and Conv-only state in FULL/SWA/Conv tri-pools: Conv-only models also use `UnifiedMambaPool`.

## Modifications

<!-- Detail the changes made in this pull request. -->

- Copy disjoint physical state slots directly with the existing `copy_pages` kernel. FULL/SWA already use this path. Ordinary COW, sibling callbacks and allocator synchronization remain unchanged.
- Test Mamba and Conv-only compaction, payload/mapping preservation, graph readback and asynchronous ordering. New real-factory tri-pool tests cover CPU/CUDA, page sizes 1/4, eager/urgent/opportunistic moves, and live SWA relocation after Conv reclamation.
- Remove main-state gather scratch; sibling callbacks and the CPU fallback may still allocate scratch.
