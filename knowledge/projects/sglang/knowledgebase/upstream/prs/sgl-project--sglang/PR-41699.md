# [Perf] [AMD] dsa: Add FlyDSL MQA-logits backend

[Upstream PR](https://github.com/sgl-project/sglang/pull/41699) · state: open · merged: False

## Original PR description

# [AMD] Add FlyDSL DSA MQA-logits backend

## Motivation

The DSA sparse indexer is a major GLM-5.2 long-prefill cost on MI355X. Merged
[ROCm/aiter#4538](https://github.com/ROCm/aiter/pull/4538) provides a FlyDSL FP8
MQA-logits kernel that is faster than the currently used Triton implementation
at the production 32k EXTEND shape.

## Modifications

- Add `--dsa-mqa-logits-backend` with `auto`, `triton`, and `flydsl` choices.
- Preserve Triton as the default.
- Allow FlyDSL only on ROCm gfx950.
- Route both non-chunked and memory-bounded chunked HIP MQA-logits calls
  through the selected backend.
- Preserve `clean_logits=False` and the existing downstream masking/top-k
  contract.
- Add CPU tests for backend resolution and unsupported-platform rejection.

## Accuracy Tests

All four registered backend-dispatch tests pass. The merged AITER #4538 matrix
passed 56/56 eager and 56/56 graph-replay cases on gfx950, covering supported
head shapes, FP8 payloads and scales, and causal, context-parallel, misaligned,
empty, and past-end windows.

Exact-head 60k-input/600-output eager serving completed with the FlyDSL backend.

## Speed Tests and Profiling

Hardware: AMD MI355X, TP4, `amd/GLM-5.2-MXFP4`, FP8 KV cache, AITER DSA
prefill, TileLang DSA decode, and 32,768-token prefill chunks. Candidate and
control differ only in `--dsa-mqa-logits-backend flydsl` versus `triton`.

Matched pure-32k EXTEND stage traces:

| Variant | MQA logits | Complete DSA indexer | Prefill wall |
|---|---:|---:|---:|
| Baseline Triton | 94.7981 ms | 178.5417 ms | 1682.2568 ms |
| FlyDSL | 92.1294 ms | 175.5948 ms | 1681.6625 ms |

FlyDSL reduced MQA-logits time by 2.82% and complete DSA-indexer time by 1.65%.
Prefill GPU wall was neutral at -0.04%.

Matched 60k/c4 serving:

| Metric | Triton | FlyDSL | Change |
|---|---:|---:|---:|
| Output throughput | 119.5089 tok/s | 120.0747 tok/s | +0.47% |
| Mean TPOT | 26.0681 ms | 26.1603 ms | +0.35% |
| Mean TTFT | 3767.9743 ms | 3640.1554 ms | -3.39% |

The serving run used 60,000 input tokens, 600 output tokens, concurrency 4,
seed 15, and 32 prompts after an unrecorded warmup.

## Reproduction

Launch the candidate on MI355X:

```bash
SGLANG_USE_AITER=1 python3 -m sglang.launch_server \
  --model amd/GLM-5.2-MXFP4 \
  --tp 4 \
  --trust-remote-code \
  --attention-backend dsa \
  --dsa-prefill-backend aiter \
  --dsa-decode-backend tilelang \
  --dsa-mqa-logits-backend flydsl \
  --kv-cache-dtype fp8_e4m3 \
  --page-size 64 \
  --disable-shared-experts-fusion \
  --cuda-graph-max-bs-decode 256 \
  --disable-radix-cache \
  --chunked-prefill-size 32768 \
  --max-prefill-tokens 32768
```

For the matched control, change only `--dsa-mqa-logits-backend` from `flydsl`
to `triton`. Run a 60k-input/8-output warmup at concurrency 4 and seed 0,
followed by 60,000 input tokens, 600 output tokens, concurrency 4, seed 15, and
32 prompts.
