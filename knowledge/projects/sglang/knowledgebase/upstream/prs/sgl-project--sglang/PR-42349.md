# [RL] Fix indexer top-k replay: capture token positions, return the layer count, honor the flag in chat and sessions

[Upstream PR](https://github.com/sgl-project/sglang/pull/42349) · state: open · merged: False

## Original PR description

<!-- lint: profile=evidence-heavy -->
## Summary
Fix indexer replay coordinates, layer metadata, grouped routing, and chat/session flag propagation.

## Symptom & Reproduction
- **Symptom:** with `--enable-return-indexer-topk`, fused top-k capture returns KV-cache coordinates; clients also lack the layer count needed to reshape the payload. Chat and session continuations drop `return_indexer_topk`.
- **Reproduction:** at `3ea64f2365`, dispatching two messages to one tokenizer worker with `indexer_topk_num_layers=7` raises `TypeError: object of type 'int' has no len()`. Both token and string output types fail; the expected result retains the scalar in both output types.
- With raw positions `[0, 1, -1]` mapped to attention indices `[64, 65, -1]`, the computed layer captures raw positions but shared layers capture physical indices. Executing all four CUDA/ROCm shared-layer call expressions reproduces this mismatch; the expected result captures raw positions in every layer.

## Root Cause
1. `DSATopKBackend.topk_transform` fuses selection with page-table or ragged remapping.
2. `Indexer.forward_cuda` captures remapped indices, and shared layers receive those same attention indices.
3. `BatchTokenIDOutput` and `BatchStrOutput` originally omitted the layer count; grouped extraction assumes each added field is per-request.
4. `ChatCompletionRequest` omits the flag, so conversion never sets `GenerateReqInput.return_indexer_topk`.
5. `Session.create_req` copies routed-expert capture but omits indexer capture.

## Fix
**Capture.** With a capturer, `topk_transform(..., return_raw_indices=True)` computes sequence-relative indices alongside remapped indices. Capture uses the former; attention retains the latter. Each fused call adds one plain top-k; unfused results are reused. Shared layers copy the preceding layer's captured positions into their capture slot while returning the original attention tensor. The [original capture commit](https://github.com/sgl-project/sglang/commit/3ea64f23654b08302b46a689d4d823075df3171d) attributes the DSA port to `sglang-miles` `64b3f11005` by @yueming-yuan.

**Metadata.** The scheduler derives the layer count from the capturer; IPC structs append it, and detokenizer/tokenizer routing carries it to `meta_info["indexer_topk_num_layers"]`. Both single and grouped routing preserve this batch-wide scalar. This includes the former #42350.

**Entry points.** Chat declares and forwards the flag, and requires `return_meta_info` as its response carrier. Sessions copy the flag to each turn's request.

Servers without a capturer avoid the extra top-k. With a capturer enabled, computation is server-wide even when an individual request does not request the payload. Existing `/generate` and `/v1/completions` request parsing remains unchanged.

Remaining capture gaps: default breakable/piecewise prefill graph split ops and ROCm gfx950 fused decode still capture remapped indices; `IndexerKPool` captures nothing.
