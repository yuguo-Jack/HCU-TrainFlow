# [Fix] [NPU] sparse-kv: Preserve shared prefixes in physical host slots

[Upstream PR](https://github.com/sgl-project/sglang/pull/47654) · state: open · merged: False

## Original PR description

## Summary

Sparse KV offload stores host KV by request ID and sequence position, while radix cache owns physical token slots. When a new request reuses a prefix, only its new tokens are offloaded to its host row. Prefill reads the unwritten prefix from that row, and decode can copy the same wrong data into its device cache. Reusing the original request row can also overwrite a prefix still retained by radix cache.

Store host KV by physical page and offset, using the native pool's size and padding. Write to `out_cache_loc`, and translate prefill reads and decode host misses through `req_to_token`. Host data then follows the allocator/radix lifetime. The request-local device cache still resets on allocation.

Also update the allocation hook and `init_req` to use `req.kv.req_pool_idx`; the old field blocks request allocation before the prefix issue is reached. Host allocation now scales with physical pool capacity, rather than request capacity times maximum context length.

This concerns the explicitly enabled NPU sparse-offload path, including GLM-5.3's DSA architecture. It does not change default serving or DeepSeek-V4's separate path.

## Validation

Compared the actual manager constructor and methods before/after on Ascend with BF16, 512 + 64 head dimensions and top-k 2048. The small harness supplies allocator/model scaffolding and runs real shared-memory copies and slot-map lookup.

- Seven data checks pass after the fix. Four fail before it: cross-request prefix reuse, decode host misses, subsequent device-cache hits, and reuse of the original request row. Fresh prefill, same-request chunking and physical-slot reallocation are controls.
- The request-allocation hook passes with the current request fields.
- NPU graph replay writes to a changed physical destination slot correctly.
- The seven data checks and allocation hook also pass with CPU reference operations.
- Applicable lint checks pass. Two hooks hard-code `python3`, which is unavailable on the local Windows environment; their scripts pass when invoked with `python`.

For example, a shared four-token prefix followed by one new token returns `[-99, -99, -99, -99, 24]` before and `[10, 11, 12, 13, 24]` after. `-99` is deliberate sentinel data. The baseline forward-method probes run independently of its allocation-hook failure.

No full-model accuracy, PD-disaggregation, or throughput claim. The graph check covers the offload write path. A final layout-comment correction is AST-identical to the NPU-tested source.
