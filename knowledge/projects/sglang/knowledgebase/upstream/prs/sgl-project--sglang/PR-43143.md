# [Rust] Pass the media item fps hint to multimodal processors

[Upstream PR](https://github.com/sgl-project/sglang/pull/43143) · state: closed · merged: True

## Original PR description

## Motivation

A media item can be a `MediaRef` object (`{"url": ..., "fps": 2.0, ...}`), and `generate.proto` says the item hints a modality does not support are rejected at the processor. In the Rust server, though, `wire.rs` keeps only `url` and drops every hint, so no processor can see them. A processor implementing the public `MmProcessor` trait outside this crate, for example, cannot honour a per-video sampling rate the client asked for.

## Modifications

- `MmItem::Ref` now carries `MediaHints` beside its `url`. `MediaHints` holds `fps` only for now. The other `MediaRef` hints serve Python-side model families the Rust pipeline does not run; the struct grows when a processor needs more.
- `wire.rs` copies `fps` from the `MediaRef` into `MediaHints`. A bare source string carries none (`MediaHints::default()`).
- `ResolvedMediaWork` gains `image_hints`, `video_hints` and `audio_hints`, one entry per item, parallel to `images`, `videos` and `audios`.
- `MediaHints` is exported next to `MmItem`.
- The built-in processors still ignore hints, so outputs do not change.
- Tests:
  - `wire.rs`: an object item with `fps` carries it.
  - `payload.rs`: hints stay parallel to their items through prefetch, and a bare source gets the default.
  - Existing tests are updated for the new field.
