[Upstream PR](https://github.com/sgl-project/sglang/pull/32848) · state: open · merged: False

## Original PR description

# Support LingBot-Video MoE: image-to-video, text-to-image, refiner, and prompt rewriting

## Motivation

The initial LingBot-Video MoE 30B-A3B port covered text-to-video. The released checkpoint
also ships refiner weights and supports image-to-video and text-to-image, so a deployment
today exercises only part of what the model can do. This PR closes that gap.

Related issue: #32336
Upstream PR: #32341 

## Design

One pipeline serves every task. `task_type` becomes `TI2V`, which makes the input image
optional, so the request decides: `image_path` gives image-to-video, omitting it gives
text-to-video, `num_frames=1` gives a still. The checkpoint leaves little choice here —
`model_index.json` declares a single pipeline class and the registry resolves a single
config, so a second class would be unreachable without an extra CLI flag on every
image-to-video request.

Conditioning uses the frame twice: as visual context for the Qwen3-VL encoder, and as a
clean latent pinned to the head of the diffusion latent and rewritten after every
scheduler step. The DiT forward signature is untouched.

The refiner is the one part behind an explicit `--pipeline-class-name
LingBotVideoRefinerPipeline`, since doubling resident DiT weights is a deployment
decision rather than a per-request one. It loads from the checkpoint's `refiner/`
subfolder by redirecting only the weight path, so the component keeps its
`transformer_2` identity and still resolves the transformer loader. Its second pass
rebuilds text conditioning without vision tokens because the refiner DiT has no
image-conditioning path, drives both posterior samples and the noise draw from one
seeded generator, and rejects single-frame requests.

Prompt rewriting runs as a stage in two turns: a free-text prompt is expanded, then mapped
to JSON. Structured captions pass through untouched. There are two ways to supply the
rewriter: `rewriter_url` points at a served vision language model over an
OpenAI-compatible endpoint, or `rewriter_model_path` plus `rewriter_adapter_path` loads it
inside the diffusion worker. The endpoint keeps another 27B model out of the worker; the
in-process path saves standing up a second server. Setting neither skips the stage.

## Verification

Checked against the reference diffusers implementation on the same hardware, checkpoint,
seed, and parameters. Cross-GPU comparison is not meaningful for this model — identical
code and seed on an H100 and a 5090 produce visibly different motion — so every
comparison below is same-hardware.

## Inference speed

Seed 42, 40 base steps, guidance_scale 3.0, flow shift 3.0, fps 24, structured JSON
captions. Every sglang number is the second or later run of that task on a resident
server, so autotune is warm; for scale, a cold first request costs 0.890 s/step against a
warm 0.700 for T2V on H100. sglang numbers are per-stage wall time from the server log.
Reference numbers come from its own denoising-loop timer and exclude text encoding and
VAE decode.

Base pass, 320x192, 121 frames:

| Runtime | Hardware | s/step | Denoise | Decode | Text encode |
| --- | --- | --- | --- | --- | --- |
| sglang T2V | H100 80GB | 0.700 | 28.0 s | 0.96 s | 0.13 s |
| sglang TI2V | H100 80GB | 0.705 | 28.2 s | 0.96 s | 0.19 s |
| reference T2V | H100 80GB | 0.95 | 38 s | -- | -- |
| reference TI2V | H100 80GB | 0.95 | 38 s | -- | -- |
| sglang T2V | 5090 32GB, dit layerwise offload | 2.122 | 84.9 s | 0.96 s | 0.12 s |
| sglang TI2V | 5090 32GB, dit layerwise offload | 2.122 | 84.9 s | 0.97 s | 0.19 s |

Text to image, 832x480, single frame:

| Runtime | Hardware | s/step | Denoise | Decode |
| --- | --- | --- | --- | --- |
| sglang | H100 80GB | 0.198 | 7.9 s | 0.06 s |
| reference | H100 80GB | 0.30 | 12 s | -- |
| sglang | 5090 32GB, dit layerwise offload | 2.122 | 84.9 s | 0.22 s |

Across 16 requests all three tasks land on the same 2.122 s/step on the 5090, because
layerwise offload streams the whole DiT from host memory every step and the loop is bound
by that transfer rather than by sequence length: a single 832x480 frame carries 1560
tokens against 7440 for the 121-frame clip and still costs the same. On H100 without
offload the three tasks separate as expected, 0.700 / 0.705 / 0.198.

Refiner, 49 frames, 8 refiner steps, t_thresh 0.85, sigma tail 2:

| Runtime | Hardware | Refiner res | Base denoise | Upscale | Refine s/step | Refine total |
| --- | --- | --- | --- | --- | --- | --- |
| sglang | H100 80GB, offload | 1920x1088 | 87.2 s | 5.8 s | 20.18 | 163.2 s |
| sglang | 5090 32GB, offload | 640x384 | 86.5 s | 1.2 s | 2.17 | 17.6 s |
| reference | H100 80GB, 8-way FSDP | 1920x1088 | 121 s | -- | -- | 210 s |

Both sglang refiner rows keep layerwise offload on so the two DiTs share one card, which
is why their base denoise sits near the 5090 figure rather than the 28 s an H100 reaches
without offload. Refiner cost then tracks the refiner resolution rather than the
hardware: 1920x1088 is 8.5x the pixels of 640x384 and costs 9.3x per step.

Image conditioning, condition frame preprocessing plus a single-frame VAE encode:

| Hardware | Resolution | Time |
| --- | --- | --- |
| H100 80GB | 320x192 | 0.30 s |
| 5090 32GB | 320x192 | 0.02 s to 0.06 s |
| 5090 32GB | 832x480 | 0.22 s |

Hey, @mickqian, this PR is ready for review now.

Extends the existing T2V support so one checkpoint covers image-to-video and text-to-image, adds the refiner second pass and the prompt rewriter the model was released with, and makes the DiT sequence-parallel.

## feat

**Sequence parallelism.** The DiT now shards the joint `[video; text]` sequence across ranks and gathers afterwards, so `--ulysses-degree > 1` works. It was not SP-aware before while `USPAttention` engaged its all-to-all, which produced a corrupted clip rather than an error.

**Image-to-video.** Qwen3-VL encodes the condition frame as an image alongside the caption; the first latent frame is pinned to it for the whole denoising loop.

**Text-to-image.** `--num-frames 1`, with frame-count alignment disabled and a still-image negative prompt.

**Refiner second pass.** Decodes the base clip, upscales, re-encodes, and denoises again from `t_thresh` down on the `transformer_2` weights.

**Prompt rewriter.** Turns a plain prompt into the structured JSON caption the DiT expects, in two turns against either a served endpoint or an in-process VLM. Optionally also prunes the negative prompt per request.

Fixes along the way: head divisibility is now checked at startup instead of deep inside the all-to-all; latent frames are no longer rounded up to the GPU count; a Video API request with `n > 1` is split into one request per output.

## Using it

Prompts are structured JSON captions, not free text — see the `recipe` for the schema. The rewriter writes them for you. Both it and the refiner are off by default.

```json
{
  "rewriter_model_path": "Qwen/Qwen3.6-27B",
  "rewriter_adapter_path": "<path to lingbot-video-rewriter-lora>"
}
```

```bash
sglang serve --model-path robbyant/lingbot-video-moe-30b-a3b \
  --pipeline-class-name LingBotVideoRefinerPipeline
```

## Benchmark

8x H100 80GB, 480x832, 121 frames, 40 steps, guidance 3.0, flow shift 3.0, seed 42, same caption and sequential CFG on both sides.

| Stack | Parallelism | Denoise | Per step | End to end |
| --- | --- | --- | --- | --- |
| upstream diffusers | FSDP 8 | 409 s | 10.23 s | 469 s |
| SGLang | `--ulysses-degree 8` | 73 s | 1.83 s | 175 s |

5.6x faster denoise, 2.7x end to end. Sharding weights only on both sides, upstream FSDP against SGLang `--tp-size 8`, SGLang denoises the same workload in 139 s.

| Task | Parallelism | Denoise | Decode |
| --- | --- | --- | --- |
| Text-to-image (1 frame) | `--ulysses-degree 8` | 31.8 s | 0.2 s |
| Image-to-video (121 frames) | `--tp-size 8` | 134 s | 4.7 s |
| Refiner, both passes | `--ulysses-degree 8` + FSDP | 57 s + 100 s | 7.5 s |

Output matches the upstream reference in subject, composition, and motion without being bit-identical: PSNR 20.7 dB / SSIM 0.82 on the luma plane. Some of that gap is unavoidable here — swapping only the attention kernel inside the reference stack, with everything else fixed, already moves its own output by a similar margin, and this model amplifies small input differences over 40 steps. I have not pinned down how much of the remainder is the two stacks disagreeing versus the two GPUs disagreeing; separating those needs the same code on the same card.

## Update: CFG parallel and cache-dit

Two more knobs work on this model now.

**CFG parallel.** `--cfg-parallel-size 2` splits the conditional and unconditional passes across two ranks. This needed no model-side change — the shared denoising stage already handled it once the pipeline was wired up, so this is a report that it works rather than a code change.

**cache-dit.** `--enable-cache-dit` needed one entry in the custom block adapter table: the DiT's blocks live under `blocks` and its block signature is `Pattern_3`, same shape as the MiniMax-H3 entry already there.

Enabling it also turned up a bug in shared code. `DenoisingStage` passed `has_separate_cfg=batch.do_classifier_free_guidance` when setting up cache-dit, which ignores CFG parallel. Under CFG parallel each rank only ever runs one branch, so that rank never sees the conditional/unconditional alternation the flag promises, and cache-dit sat waiting for a pattern that never arrived — it skipped nothing at all. Before the fix, `--enable-cache-dit` on top of `--cfg-parallel-size 2` produced a byte-identical video to leaving it off. This affects any model combining the two flags, not just LingBot.

### Speed

2x RTX 5090 32GB, no NVLink, layerwise DiT offload on. 832x480, 161 frames (10 s at 16 fps),
structured caption, seed 0, guidance 3.0. Per-stage wall clock from the server log.

8 steps, fox prompt:

| Configuration | Denoise | End to end | Peak | s/step |
| --- | --- | --- | --- | --- |
| 1 GPU | 171.3 s | 184.8 s | 11410 MB | 21.18 |
| TP 2 | 113.1 s | 123.5 s | 11370 MB | 13.97 |
| CFG parallel 2 | 86.4 s | 97.3 s | 11410 MB | 10.56 |
| 1 GPU + cache-dit | 119.4 s | 133.2 s | 13310 MB | — |
| CFG parallel 2 + cache-dit | 55.5 s | 66.8 s | 11410 MB | — |

40 steps, the released sampling profile, fox prompt:

| Configuration | Denoise | End to end | s/step |
| --- | --- | --- | --- |
| CFG parallel 2 | 435.7 s | 446.4 s | 10.84 |
| CFG parallel 2 + cache-dit | 171.8 s | 183.7 s | — |

s/step is left out for the cache-dit rows on purpose. cache-dit does not make a step cheaper —
it decides a step is close enough to the previous one and reuses the cached block residuals
instead of running the blocks (`Fn=1, Bn=0`, so only the first block still runs on those steps).
Dividing total denoise by the step count would mix full steps with skipped ones and read as a
per-step speedup that does not exist, so the comparison here is total denoise time.

CFG parallel cuts denoise 1.98x, and it also halves VAE decode because that shards with it.
cache-dit cuts denoise 1.43x on this prompt at 8 steps and 2.54x at 40 steps; across fox, owl
and elephant the range is 1.23x to 1.58x at 8 steps and 2.54x to 2.89x at 40. More steps leaves
more neighbours similar enough to skip, and at 8 steps one skipped step is already an eighth of
the trajectory. The elephant prompt gains least, which fits — its content changes fastest.
Together the two reach 3.09x on denoise at 8 steps (2.57x on elephant). Sequence parallelism is
slower than a single card on this box.

One memory note: cache-dit costs about 1.9 GB extra on a single GPU, where it keeps a separate
set of cached residuals for the conditional and unconditional passes. Under CFG parallel each
rank only runs one branch, so it keeps one set and peak stays where it was.

Short version of what this PR adds to LingBot-Video MoE.

1. **Image-to-video.** The condition frame goes to the Qwen3-VL encoder as an image and is
   pinned to the first latent frame for the whole denoising loop.
2. **Text-to-image.** `--num-frames 1`, with frame-count alignment off and a still-image
   negative prompt.
3. **Refiner second pass.** Decodes the base clip, upscales, re-encodes, then denoises again
   from `t_thresh` down on the `transformer_2` weights.
4. **Prompt rewriter.** Turns a plain sentence into the structured JSON caption the DiT
   expects. Either a served endpoint or an in-process VLM. Can also prune the negative
   prompt per request.
5. **Sequence parallelism.** The DiT shards the joint `[video; text]` sequence and gathers
   after, so `--ulysses-degree > 1` works. It used to produce a corrupted clip instead of
   an error.
6. **CFG parallel.** `--cfg-parallel-size 2` puts the conditional and unconditional passes
   on separate ranks. No model-side change was needed; the shared denoising stage already
   handled it. Cuts denoise 1.98x, and halves VAE decode since that shards along with it.
7. **cache-dit.** `--enable-cache-dit` needed one entry in the custom block adapter table.
   It skips steps whose output is close enough to the previous one, so it helps more at 40
   steps (2.5x to 2.9x on denoise) than at 8 (1.2x to 1.6x). Stacks with CFG parallel.
