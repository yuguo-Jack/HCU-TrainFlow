# [Feat] [AMD] distributed: JIT quick all-reduce for TP4 on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/46692) · state: closed · merged: True

## Original PR description

> Part of the MiniMax-M3.1-Flash AMD series that replaces #45936 (closed with its base branch `minimax-m3.1-flash`): kernel PRs #46690 (attention), #46691 (MoE / GEMM) and #46692 (quick all-reduce), each on `main`; then #46693 with the M3.1 call sites and #46694 (indexer CP). It follows the DeepSeek-V4.1 AMD layout (#41018-#41021, then #41308).

## Summary
- A JIT copy of sgl-kernel's quick all-reduce (`jit/csrc/distributed/quick_all_reduce/`, `quick_all_reduce_hip.cuh`, `ops/communication/quick_all_reduce_hip.py`), restructured for latency (the per-tile wire layout is wave-major) and cut to the INT4 / INT8 codecs at TP4 on bf16 data. It keeps sgl-kernel's buffer sizes, flags and arithmetic, so at the level it runs its outputs are bitwise equal to sgl-kernel's, including a partial last tile and bf16 values past fp16's range. Asked for INT4, it runs all-reduces below `SGLANG_ROCM_QUICK_REDUCE_INT8_BELOW_MB` (default 64 MiB; 0 keeps INT4 at every size) in INT8, about 1/16 of INT4's error, and logs that once at init; the JIT INT4 column below 64 MB in the table is the kernel called at INT4 directly. `jit_serves()` takes only gfx950, and `qr_supports(fa, dtype)` tells a caller that a JIT handle reduces bf16 only.
- Nothing in this PR calls the module: #46693 wires it in (`custom_all_reduce_ops` behind `SGLANG_ROCM_QUICK_ALL_REDUCE_JIT`, on gfx950 only, the GPU it is validated on; `QuickAllReduce` asks `qr_supports()` so float16 goes to the next all-reduce). Review it here as a kernel; the serving numbers below come from #46693.

## Changes to existing kernels
None; every source file is new and HIP-only. The existing `test_quick_allreduce_bf16_range` gains the JIT cases.

## Not in this PR
- Each communicator allocates twice its max size (4 GiB per GPU at the 2 GiB default), as sgl-kernel's does, although the kernel indexes its slots by block and so uses at most 256 tiles per phase. Shrinking it would return that memory to the KV cache; it is left for a follow-up.
- sgl-kernel's own `quick_all_reduce.h` keeps `data_buffer_size` function-static, so the first communicator's size sticks process-wide; this JIT copy sizes it per communicator and leaves the original untouched.

- Serving, measured in the integration PR (MI350X TP 4, NVFP4 KV, DSpark acceptance simulated at 3 tokens per step, 32K-token contexts, two repeats on each of two GPU sets). With sgl-kernel's quick all-reduce instead (`SGLANG_ROCM_QUICK_ALL_REDUCE_JIT=0`) at the same 2.4 MiB custom-AR cutoff, decode TPOT grows 4.0% at 32 concurrent requests and 2.6% at 64, and 32K-token prefill 1.9%. With main's 64 MiB cutoff as well: 3.6%, 6.7% and 4.3%. At 1 and 8 requests every all-reduce stays under the cutoff, on aiter's custom all-reduce.
