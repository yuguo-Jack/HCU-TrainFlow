# [Perf] [NVIDIA] sampling: Enable Cake softmax on SM100

[Upstream PR](https://github.com/sgl-project/sglang/pull/44168) · state: closed · merged: True

## Original PR description

## Motivation

Sampling softmax currently enables FlashInfer's Cake kernel on SM103 but falls back to `torch.softmax` on SM100. FlashInfer 0.7.1 supports Cake on both. This change enables the existing fast path on SM100 without changing its dtype or shape limits.

## Modifications

Extend the runtime and registry gates to SM100 and update the kernel documentation. Extend the existing GPU test with Cake-eligible dense and masked inputs, and run it in B200 CI.

| Sampling case | Before | After |
| --- | --- | --- |
| Qualified, non-deterministic SM100 workload | `torch.softmax` | Cake softmax |
| Qualified, non-deterministic SM103 workload | Cake softmax | Cake softmax |
| Inputs outside the existing Cake dtype or shape limits | `torch.softmax` | `torch.softmax` |
| Deterministic sampling | `torch.softmax` | `torch.softmax` |

This also affects non-deterministic sampling in the regular sampler. The existing dtype and shape limits are unchanged.

## Accuracy Tests

On `71b2b2769`, the GPU temperature-softmax suite and focused CPU routing tests pass locally on an RTX 5070 Ti (SM120), using normal package imports. Scoped pre-commit checks pass. The local GPU uses the Torch fallback, so this does not establish native Cake accuracy on SM100.

The existing `test_temperature_softmax.py` now covers:

| Coverage | Before this review update | After this review update |
| --- | --- | --- |
| FP32 GPU shapes inside Cake's domain | Existing shapes miss the Cake gate | `(1, 131072)`, `(4, 154880)`, `(64, 131072)`, `(1, 262144)` |
| Dense softmax calls | Per-row temperatures | Plain softmax and per-row temperatures |
| Sparse grammar masks with fully masked splits | Vocabulary 65537 | Vocabularies 65537 and 131072 |
| CUDA CI hardware | 5090 | 5090 and B200 |

The existing AMD registration is retained. The B200 lane runs the same numerical comparisons against Torch on SM100, where the eligible inputs use Cake. Its result on this head is pending CI.

Earlier B200 checks with FlashInfer 0.7.1 compared Cake with Torch and a float64 reference. Maximum absolute error was 6.0e-7 against Torch and 2.3e-6 against float64, with finite normalized outputs and the same argmax.

The earlier GLM-5.3-Flash decode/prefill comparison produced:

| Metric | Before (main) | After (Cake enabled) |
| --- | ---: | ---: |
| Mean absolute decode/prefill log-prob difference | 0.0218 to 0.0234 | 0.0225 to 0.0242 |
| Argmax agreement | 0.980 to 0.984 | 0.980 to 0.984 |

These results were within baseline variation. Those GPU checks used a nightly overlay and predate the latest base update. Current-head B200 serving accuracy and performance comparisons for regular and speculative sampling remain unmeasured because no B200 host is available for those runs.

Run the kernel test with `PYTHONPATH=python python -m pytest -q test/registered/kernels/ops/sampling/test_temperature_softmax.py`. Run the focused routing checks with `PYTHONPATH=python python -m pytest -q test/registered/unit/kernels/test_kernels_namespace.py -k sampling_softmax`.

## Speed Tests and Profiling

The server comparison used GLM-5.3-Flash FP8 with EAGLE 4/1/5 on TP4 B200. The branch files were overlaid on nightly commit `7224fce1b5e4`, before the latest base update. No server run of the updated branch is available.

| Streams | Before (main nightly) | After (Cake overlay) | Reduction per verify step |
| --- | ---: | ---: | ---: |
| 1 | 8.413 ms | 8.231 ms | 182 us (2.2%) |
| 4 | 12.119 ms | 11.936 ms | 183 us (1.5%) |
| 16 | 18.329 ms | 18.186 ms | 143 us (0.8%) |

This was a restart A/B comparison. At 16 streams, the observed change was only a few times larger than server-to-server variation. The 80-row verify call remains on Torch because the current gate supports at most 64 rows. The 16-stream result comes from other Cake call sites. TP8, other GPUs, non-speculative workloads and the regular sampler on SM100 remain unvalidated.
