# [Perf] [NVIDIA] sampling: Enable Cake softmax on SM100

[Upstream PR](https://github.com/sgl-project/sglang/pull/44168) · state: open · merged: False

## Original PR description

## Motivation

Sampling softmax currently enables FlashInfer's Cake kernel on SM103 but falls back to `torch.softmax` on SM100. FlashInfer 0.7.1 supports Cake on both. This change enables the existing fast path on SM100 without changing its dtype or shape limits.

## Modifications

Extend the runtime and registry gates to SM100 and update the kernel documentation. This also affects non-deterministic sampling in the regular sampler; deterministic sampling keeps `torch.softmax`.

## Accuracy Tests

CPU routing and registry checks and scoped formatting pass on the updated branch. Earlier B200 checks with FlashInfer 0.7.1 compared Cake with Torch and a float64 reference; maximum absolute error was 6.0e-7 against Torch and 2.3e-6 against float64, with finite normalized outputs and the same argmax. GLM-5.3-Flash decode/prefill comparisons had mean absolute log-prob differences of 0.0225 to 0.0242 with Cake and 0.0218 to 0.0234 on main; argmax agreement was 0.980 to 0.984 for both arms. These results were within baseline variation. Those GPU checks used a nightly overlay and predate the latest base update. The regular sampler has not been measured separately on SM100.

Run the CPU kernel namespace suites with `python -m pytest` and GPU sampling suites through the registered CI runner.

## Speed Tests and Profiling

The server comparison used GLM-5.3-Flash FP8 with EAGLE 4/1/5 on TP4 B200. The branch files were overlaid on nightly commit 7224fce1b5e4, before the latest base update. No server run of the updated branch is available. Time per verify step:

| Streams | Main | Cake enabled | Change |
| --- | ---: | ---: | ---: |
| 1 | 8.413 ms | 8.231 ms | 182 us (2.2%) |
| 4 | 12.119 ms | 11.936 ms | 183 us (1.5%) |
| 16 | 18.329 ms | 18.186 ms | 143 us (0.8%) |

This was a restart A/B comparison. At 16 streams, the observed change was only a few times larger than server-to-server variation. The 80-row verify call remains on Torch because the current gate supports at most 64 rows; the 16-stream result comes from other Cake call sites. TP8, other GPUs, non-speculative workloads and the regular sampler on SM100 remain unvalidated.
