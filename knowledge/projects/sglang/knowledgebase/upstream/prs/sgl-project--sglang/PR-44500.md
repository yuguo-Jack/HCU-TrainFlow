# [Fix] nvfp4: Own streamed tensors while waiting for paired weights

[Upstream PR](https://github.com/sgl-project/sglang/pull/44500) · state: closed · merged: True

## Original PR description

## Motivation

RunAI reuses streamed tensor buffers after the synchronous loader callback returns. Online NVFP4 conversion can retain those borrowed tensors while waiting for a gate/up pair or an FP8 weight/scale pair, including across checkpoint files. A later callback can therefore quantize overwritten data and produce corrupted expert scales or NaNs.

## Modifications

Mark RunAI storage as borrowed so packed-expert slices and detached aliases retain the ownership information. Keep the existing tensor marker for compatibility. Copy borrowed tensors to owned CPU storage only when placing them in a pending queue, covering gated w1/w3 weights, FP8 weights, and FP8 scales. Immediate conversion and tensors with normal ownership keep their existing behavior.

## Accuracy Tests

12 CPU regressions pass. They overwrite the streamer's buffer between paired loads, covering both gate/up arrival orders and both FP8 weight/scale arrival orders for direct tensors, packed views, and detached views. The four direct-tensor cases fail on upstream main (`c4870d98cf`); the eight alias cases fail on the original PR revision (`774e2a19ac`). Tests exercise storage marking through the RunAI iterator with a fake streamer and verify that owned clones do not inherit the borrowed marker.

```bash
python -m pytest test/registered/unit/layers/quantization/test_nvfp4_online_weight_loader.py -q
```

The tests exercise the real loader and replace GPU quantization with a recording CPU function. No new full-model GPU evaluation was run for this upstream port.

## Speed Tests and Profiling

No serving-path change. The additional CPU copy is restricted to borrowed tensors that must survive a loader callback; load-time overhead was not benchmarked.

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Preserve ownership for views of streamed tensors**

When a RunAI-loaded checkpoint exposes packed expert tensors, such as Intern-S2-Mobius FP8 `experts.gate_up_proj` and `experts.gate_up_proj_scale_inv`, `_load_fused_mobius_expert_weight` (`python/sglang/srt/models/interns2_mobius.py:133-147`) chunks and indexes the marked tensor before invoking this loader. PyTorch views do not inherit arbitrary Python attributes, so this check is false and the borrowed weight or scale view is retained across the next streamer yield; once RunAI reuses the backing buffer, quantization still consumes overwritten values. Propagate ownership before slicing or recognize marked base tensors here.
