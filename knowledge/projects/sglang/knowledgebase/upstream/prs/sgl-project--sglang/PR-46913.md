# [Fix] Mooncake: divide global_segment_size by dp_size under DP attention (#46899)

[Upstream PR](https://github.com/sgl-project/sglang/pull/46913) · state: open · merged: False

## Original PR description

## Summary

Under DP attention, every DP rank launches its own Mooncake client and mounts a global segment. The per-rank segment size was only divided by `tp_size * pp_size`, so with TP4 / DP4 each of the 4 DP ranks mounted the **full** configured `MOONCAKE_GLOBAL_SEGMENT_SIZE`.

This pinned `dp_size` times the intended host memory. On 8xB200 hosts the HiCache host pool already holds 200 GiB per DP rank, so `MOONCAKE_GLOBAL_SEGMENT_SIZE=400gb` tried to pin 1.6 TB more, and `fi_mr_reg` failed with "Cannot allocate memory" ("Failed to setup Mooncake store").

## Changes

- `HiCacheStorageConfig`: add a `dp_size` field (defaults to 1).
- `cache_controller._generate_storage_config`: populate `dp_size` from `parallel.attn_dp_size` when DP attention is enabled, otherwise 1.
- `mooncake_store.py`: include `dp_size` in `rank_scale_factor`, so the per-rank segment is `global_segment_size // (tp_size * pp_size * dp_size)`.
- README: document that the total pinned memory equals the configured `global_segment_size` for DP attention as well.

The resulting total across all ranks matches the README's documented behavior: total = global segment size.

## Test plan

- [x] Verified `dp_size` defaults to 1 when DP attention is disabled, so existing single-instance / TP-only deployments are unchanged.
- [x] Verified the scaling factor now matches the number of ranks that actually mount a segment (`tp_size * pp_size * dp_size`).
- [ ] Run a TP4/DP4 HiCache + Mooncake deployment and confirm `master_total_capacity_bytes` equals the configured segment size across all DP ranks.

Fixes #46899.
