# [diffusion] torch.compile: keep Cosmos3's fused kernels in the graph

[Upstream PR](https://github.com/sgl-project/sglang/pull/43577) · state: closed · merged: True

## Original PR description

## Motivation

With `--enable-torch-compile`, Cosmos3 is slower than eager: on 2xGB300 (T2I, CFG-parallel) eager is 0.93 s and compile is 1.43 s, while vLLM-Omni's compile is 0.97–1.02 s. Profiling the compiled run shows more kernels than eager (2264 → 3344 per 4 steps), and `TORCH_LOGS=graph_breaks` shows two causes:

1. `cosmos3video.py` (relu2, fused K/V packing, T=1 fused QK-norm+RoPE) and `layernorm.apply_qk_norm_rope` skip their fused kernels when `torch.compiler.is_compiling()`. Those kernels are already registered custom ops (`_run_unary_activation_inplace`, `fused_qknorm_rope_pack_kv`, `fused_inplace_qknorm_rope`), which dynamo keeps as opaque calls. The gates only replaced them with the unfused forms, and inductor emitted extra kernels for those.
2. The non-fused T=1 path calls the bare JIT `fused_inplace_qknorm`. Its tvm_ffi launch graph-breaks inside every decoder layer (`tvm_ffi/module.py:188 ... Function.__call__`).

## Modifications

- Remove the four `is_compiling()` gates around custom-op fused kernels (three in `cosmos3video.py`, one in `layernorm.apply_qk_norm_rope`).
- In `layers/layernorm.py`, register `fused_inplace_qknorm` as an opaque custom op (mutating `q`, `k`), the same way `srt/models/utils.py` already does. Both register the same function under the same name, so whichever imports first wins with identical semantics. `sglang/kernels` is untouched.

## Accuracy Tests

Cosmos3-Nano T2I 1280x720, 35 steps, CFG 6.0, served on GB300, image of the 3rd request:

| Pair | Result |
|---|---|
| eager, main vs this PR | bit-identical |
| compile, main vs this PR | bit-identical (the gates switched between mathematically identical forms) |
| compile vs eager (main and this PR alike) | PSNR 21.3 dB, pre-existing (inductor re-associates the rest of the layer; 35 steps at CFG 6 amplify it) |

## Speed Tests and Profiling

2xGB300, Cosmos3-Nano T2I CFG-parallel, served. Median of 5 requests after 2 warmups, fresh server per arm, 2 interleaved rounds. NUMA-bound workers (#43565) in all arms.

| | main | this PR |
|---|---|---|
| eager | 0.935 / 0.937 s | 0.933 / 0.939 s |
| compile | 1.424 / 1.435 s | **0.884 / 0.876 s** |
| graph breaks (compile) | 8 | 0 |

With this PR, compile beats eager by ~6% and vLLM-Omni's compile (0.97–1.02 s on the same box). FLUX.1 TP2 on the same tree: compile 3.93–4.03 s vs eager 3.86–4.06 s (it was 35% slower before NUMA binding and these fixes); vLLM-Omni compile is 4.86–5.26 s.

Known follow-ups, not in this PR: the first request after startup still recompiles the 36 Cosmos3 gen layers, because the warmup prompt length differs and the layers compile with `dynamic=False`. TP all-reduce is not traceable (`Communicator.get_world_size`) and graph-breaks FLUX TP compile.
