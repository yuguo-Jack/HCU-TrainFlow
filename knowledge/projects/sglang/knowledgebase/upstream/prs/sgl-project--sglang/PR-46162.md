# [Fix] diffusion/api: Do not publish failed generation outputs

[Upstream PR](https://github.com/sgl-project/sglang/pull/46162) · state: closed · merged: True

## Original PR description

## Summary

Reject worker errors before processing any partial output in the OpenAI and Vertex generation entrypoints.

`GPUWorker` can attach an error to an existing `OutputBatch` when output finalization fails. The deferred-save path can also retain encoded file paths. The HTTP layer previously checked only whether output was present, so failed requests could return images or become video jobs with `status=completed` and `progress=100`.

Also harden the Vertex response boundary:

- Reject missing or empty output files per instance instead of returning an empty success.
- Serialize request metrics with the existing `to_dict()` contract, including denoising-stage sets and memory snapshots.
- Move file reads and base64 encoding off the HTTP event loop so slow output storage does not block health checks.
- Validate the whole input batch before creating scheduler coroutines. Invalid prompts or dimensions return HTTP 400 without leaving unawaited coroutines or dispatching earlier valid instances.

Successful outputs, control RPC semantics and empty-batch behavior are preserved. This does not add retries, delete user-owned files, or change model computation.

## Tests

- Extend existing tests for tensor, encoded-file/image-byte, raw-frame and empty error results, followed by a successful request.
- Exercise the real generation-result handler from image generation/edit routes, with and without persistent output, plus video-job failure state and Vertex output handling. Previously the image fixture mocked that handler out.
- H200 development environment: 159 related tests passed. Regression tests reproduce the original error-publication, output-file, metrics-serialization and invalid-input failures. The input fixtures use local metadata rather than downloading a checkpoint.
- Real HTTP/GPU validation with Wan2.1-T2V-1.3B, 512x320, 17 frames, four steps: inject finalization failures before/after output transport. The unpatched version incorrectly completes both jobs. With the fix, synchronous and `--async-output-save` serving each report both failures, reject content retrieval, and recover on the next request. Both recovery videos match the pre-fault decoded-frame hash.
- Additional real Vertex HTTP/GPU validation with the same model and dimensions, default seed 42 and 50 steps: nine input-boundary cases followed by recovery; missing/empty/slow output reads; and three instances with one failed delivery and two successful predictions. Twelve real generations total, three injected delivery failures. All nine successful outputs decode correctly and match the baseline decoded-frame hash. Health checks remain responsive during the stalled file read, and owned worker processes exit after shutdown.

This is bounded fault/recovery coverage, not a claim of durable jobs or cross-node failover. Legacy raw-output encoding and final JSON serialization remain synchronous; host-memory admission is unchanged.

The separate async-video-progress PR #45919 remains unchanged by this fix.
