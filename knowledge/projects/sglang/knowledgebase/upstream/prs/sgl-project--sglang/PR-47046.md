# [Perf] mooncake: Add optional page-wise direct loads and client buffer tuning

[Upstream PR](https://github.com/sgl-project/sglang/pull/47046) · state: open · merged: False

## Original PR description

## Motivation

Mooncake Direct Linker currently issues a range-get for each layer/pool pair. This adds an optional page-wise mode that collects the same destination ranges across all layers and physical pools into one existing SDK call. Layer-wise loading remains the default because it preserves loading/forward overlap.

This is **SG03** in #47031, extracted from our earlier umbrella #38639. It is independent of ReadPlan and queued promotion. No new Mooncake API is required.

## Modifications

- Read `page_wise_load` (default `false`) and `page_wise_load_threshold` (default `10` physical keys) through the existing `--unified-cache-external-linker-config` JSON configuration. Below the threshold, keep the layer-wise path.
- Pack per-key ranges across layers/pools, including sparse layer metadata; validate range counts and exact returned byte totals. Publish page-wise readiness only after the read and session cleanup finish successfully.
- Register started key batches for cleanup before validating partial session-start results. This includes the small overlapping correction discussed in #44795, needed by the failure cases exercised here; it is not a separate competing cleanup proposal.
- Allow `local_buffer_size` through the same backend configuration, preserving the 16 MiB default and forwarding it to embedded/standalone client setup. Document the options and add targeted CPU regressions.

Related #45106 explores grouped/parallel layer-wise reads to preserve more overlap. This default-off single-call mode has a different tradeoff; maintainer feedback on whether both modes are useful is welcome before expanding it. No speedup is claimed.
