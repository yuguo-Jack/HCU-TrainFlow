# [Fix] Merge request stop with a str or tuple template stop_str

[Upstream PR](https://github.com/sgl-project/sglang/pull/43507) · state: open · merged: False

## Original PR description

## Motivation

`Conversation.stop_str` is typed `Union[str, List[str]]`, and several built-in templates use a plain str (phi-4-mm, gme-qwen2-vl, kimi-vl) or a tuple (minicpmv, minicpmo). `_apply_conversation_template` copied that value and then called `.append` or `.extend` to add the request's `stop`. With these templates any chat request that sets `stop` fails with `AttributeError: 'tuple' object has no attribute 'append'` (or the str equivalent), which the server returns as HTTP 500. Some of these templates are chosen from the model path, so a plain `{"messages": [...], "stop": "STOP"}` request breaks on Phi-4-multimodal or MiniCPM-V.

## Modifications

- When the request adds stops, the template stop value becomes a list first (`[stop]` for a str, `list(stop)` for a tuple or list). Then the request stops are added. Requests without `stop` keep the template value unchanged.
- New unit test `test_request_stop_merges_with_str_and_tuple_template_stop_str`. It renders phi-4-mm and minicpmv with `stop="STOP"` and `stop=["A", "B"]` and checks the merged list. Its 4 subtests fail on main with the AttributeError and pass with this change. `test_serving_chat.py` and `test_serving_completions.py` give 177 passed.

## Accuracy Tests

Not affected. Only the stop list passed to sampling changes, and only for requests that failed before.

## Speed Tests and Profiling

Not affected.
