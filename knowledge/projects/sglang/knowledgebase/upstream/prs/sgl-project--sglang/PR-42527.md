# [WIP]DeepEP Support for Intel XPU in SGLang

[Upstream PR](https://github.com/sgl-project/sglang/pull/42527) · state: open · merged: False

## Original PR description

## Motivation

DeepEP MoE all-to-all on Intel XPU. `--moe-a2a-backend deepep` uses `deep_ep_xpu`, the DeepEP port in applications.ai.gpu.deepsymm (DeepSymm). The path is intranode only: EP ranks on one node exchange buffers over PCIe P2P, so neither iSHMEM nor an RDMA NIC is needed. All three dispatch modes are supported.

| `--deepep-mode` | Prefill | Decode | Ranks |
|---|---|---|---|
| `normal` | normal | normal | up to 8 |
| `low_latency` | low-latency | low-latency | 1, 2, 4 or 8 |
| `auto` | normal | low-latency | 1, 2, 4 or 8 |

## Modifications

- `hardware_backend/xpu/deepsymm.py` (new): `import_deep_ep_xpu()` requires the `deep-symm` distribution, loads `deep_ep_xpu`, and checks that `deep_ep_cpp` is DeepSymm's rather than another DeepEP build's with the same extension name.
- `arg_groups/moe_hook.py`: XPU checks at startup: DeepSymm present, `--nnodes 1`, BF16 dispatch, no TBO/SBO, and the low-latency per-rank token cap against `--chunked-prefill-size`. Decode XPU graph is disabled in every mode.
- `token_dispatcher/deepep.py`: one PCIe buffer sized for normal and intranode low-latency (`num_rdma_bytes=0` selects the PCIe path); low-latency needs 1, 2, 4 or 8 ranks; a runtime per-rank token check, since `deep_ep_xpu` doesn't bound-check; CUDA-style `--deepep-config` keys translated to DeepSymm's names.
- `ep_moe/layer.py`: on XPU the experts run in `quant_method.apply`; quantized checkpoints are rejected at startup.
- `quantization/unquant.py`: XPU expert steps for both dispatch formats. Normal mode has a static shape and no host sync. Low-latency gathers the valid rows of the masked layout and runs them token-major.
- `test/registered/e2e/moe/test_deepep_modes_qwen3_30b_a3b.py` (new): one test for CUDA and XPU with a TP=4 baseline plus each mode. Each class runs sgl-eval GSM8K and a serving benchmark and prints a `DEEPEP_MODES_RESULT` JSON line for cross-device comparison.
- `test_deepep_intranode.py` and `test_deepep_utils.py` run on XPU; `docs/docs/hardware-platforms/xpu.mdx` documents install, modes and limits.

DeepSymm is built from source (not on PyPI). Tested at revision `2b755dd`.

## Accuracy and benchmark

Qwen3-30B-A3B BF16, TP=EP=4, 4× Arc Pro B60 on one socket, single node.
- GSM8K: sgl-eval 0.1.2, 200 examples, non-thinking, temperature 0.7, top_p 0.8, max_tokens 2048.
- Serving: random 1024 in / 256 out, 64 prompts, max concurrency 16, `--chunked-prefill-size 1024`.

| Mode | GSM8K | Output tok/s | Median TTFT | Median TPOT |
|---|---|---|---|---|
| TP=4, no DeepEP | 0.940 | 145.7 | 185 ms | 93 ms |
| `normal` | 0.945 | 85.8 | 374 ms | 164 ms |
| `low_latency` | 0.955 | 66.5 | 994 ms | 215 ms |
| `auto` | 0.950 | 86.9 | 378 ms | 163 ms |

Re-checked on the pushed commit, rebased on current main: `auto` scored GSM8K 0.96 at 90.4 output tok/s.

Accuracy matches the baseline in every mode (standard error is about ±1.5 points at 200 examples). Throughput is lower than TP=4 on this box: every MoE layer's all-to-all crosses PCIe, decode runs without XPU graph, and the low-latency expert step has a host sync per layer. Each row is a single run.

## Known limitations

- Intranode only; BF16 dispatch only; unquantized MoE weights only; no TBO/SBO.
- sgl-kernel-xpu has no BF16 masked grouped GEMM, so the low-latency expert step gathers rows with a host sync and cannot be graph-captured.
- The CUDA side of the new test has not run yet. It assumes BF16 Qwen3 + DeepEP on CUDA through `--moe-runner-backend deep_gemm`.
- The XPU CI registration is disabled until DeepSymm is in the XPU CI image.
