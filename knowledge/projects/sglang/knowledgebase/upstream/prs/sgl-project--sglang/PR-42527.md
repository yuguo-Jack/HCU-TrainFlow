File: `python/sglang/srt/layers/moe/ep_moe/layer.py` · line 115

On XPU this sends every `DeepEPMoE` through `quant_method.apply`, but only the unquantized path understands the DeepEP normal format. An FP8/MXFP4 checkpoint gets through startup and then crashes on the first forward (`'DeepEPNormalDispatchOutput' object has no attribute 'topk_output'`). Could we raise a clear `NotImplementedError` here for anything that isn't `UnquantizedFusedMoEMethod`?

- siju-samuel · comment · 2026-10-12T05:56:28Z · [source](https://github.com/sgl-project/sglang/pull/42527#discussion_r4245045053)

File: `python/sglang/srt/layers/quantization/unquant.py` · line 1292

This `.item()` is a host sync on every MoE layer every step (decode too, since XPU is forced to normal mode), and the trim doesn't save much: a lot of what `fused_experts` computes is still weight-0 padding. `num_recv_tokens_per_expert` is already on the host, so could you compact the valid slots with `torch.nonzero_static` instead, or have `prepare_moe_input` skip `-1`?

File: `python/sglang/srt/layers/moe/token_dispatcher/deepep.py` · line 233
