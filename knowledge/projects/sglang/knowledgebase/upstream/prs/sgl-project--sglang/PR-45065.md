# [Fix] diffusion: Exit the worker after an unrecoverable device error

[Upstream PR](https://github.com/sgl-project/sglang/pull/45065) · state: closed · merged: True

## Original PR description

## Motivation

Fixes #38167.

When a diffusion forward fails with a CUDA error other than OOM (a driver error, a device-side assert, a caching-allocator assert), the device or its allocator can no longer be trusted. The worker logged the error, called `empty_cache()` and kept serving. Every later request either ran on the broken device or failed, and `/health` still returned `{"status": "ok"}`, so no orchestrator would restart the server.

In #38167 the trigger is PyTorch's expandable-segments allocator (pytorch/pytorch#188008, on WSL2 with `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`). That needs a PyTorch fix. This PR makes the server fail cleanly instead of staying up broken.

## Modifications

This builds on the fail-closed path from #46025 instead of adding a separate unhealthy flag.

- `gpu_worker.py`: classify forward errors that leave the device unusable (`torch.AcceleratorError`, `CUDA driver error:`, `CUDA error:`, `HIP error:`, caching-allocator asserts, also through `__cause__`/`__context__`; anything mentioning "out of memory" is excluded). On one, log the restart guidance and raise `_FatalDeviceError`, a `SystemExit` like `_FatalDistributedForward`, so it escapes request-level recovery and skips `empty_cache()`. `run_scheduler_process` catches both and calls `os._exit(1)`.
- The HTTP server's backend monitor from #46025 then fails pending requests, rejects new POSTs with 503 and turns `/health` 503. OOM keeps its current recover-and-continue behavior on a single GPU.

## Tests

Live server on an RTX A6000 (torch 2.14.1+cu130, `Efficient-Large-Model/Sana_600M_512px_diffusers`). A temporary hook, not part of this PR, writes out of bounds on the GPU before `forward_fn()` when the prompt contains a marker, raising a real `CUDA error: device-side assert triggered`.

| Step | Result |
|---|---|
| Normal request | 200 (3.2 s) |
| `/health` before | 200 |
| Request that triggers the assert | 500 after 1.1 s |
| Request queued 0.3 s behind it | 500 after 0.8 s |
| `/health` after, polled from 1.3 s to 11.6 s | 503 `{"status":"unhealthy","error":"Scheduler worker exited; restart the server."}` |
| New request | 503 in 1 ms |
| Scheduler process | exited (`<defunct>` until reaped) |
| GPU memory | 13.5 GB used before, 0.27 GB after |

No `empty_cache()` call after the error. Not covered: multi-rank runs and the original expandable-segments failure from #38167, which can't be triggered on demand.

Unit: `multimodal_gen/test/unit/test_unrecoverable_device_error.py` (CPU) covers the classifier and the exit path.
