# [Fix] multimodal: Cap the default CPU preprocess pool at 16 workers

[Upstream PR](https://github.com/sgl-project/sglang/pull/48359) · state: closed · merged: False

## Original PR description

## Motivation
The multimodal CPU preprocess pool defaults to `os.cpu_count()` workers, and a fork-started `ProcessPoolExecutor` forks them all on the first submit. On a 512-core host the first image request forks 512 processes and misses its timeout (seen as LLaVA test timeouts).

## Modifications
- `base_processor.py`: default `max_workers = min(os.cpu_count(), 16)`. `SGLANG_CPU_WORKERS` still overrides it.
- New CPU unit test `test_base_processor_cpu_pool.py`: cap, small host, unknown CPU count, env override.

This changes the default on all backends, but only for hosts with more than 16 cores.

## Accuracy Tests
No model-output change. LLaVA `test_vision_openai_server_a` video_images and multi_images pass on Arc Pro B60 (512-core host).

## Speed Tests and Profiling
First multimodal request on a 512-core host: no longer forks 512 workers (it was over the 10 s request timeout). Steady-state preprocessing uses at most 16 workers; set `SGLANG_CPU_WORKERS` for more.
