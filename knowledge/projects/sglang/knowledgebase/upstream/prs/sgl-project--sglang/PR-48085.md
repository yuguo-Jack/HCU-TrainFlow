# [Fix] lora: Skip unsupported embeddings when targeting all modules

[Upstream PR](https://github.com/sgl-project/sglang/pull/48085) · state: open · merged: False

## Original PR description

## Motivation

Gemma 3 and Gemma 4 fail to start with `--lora-target-modules all`:

```text
AttributeError: 'Gemma3TextScaledWordEmbedding' object has no attribute 'org_vocab_size'
```

`all` unconditionally adds `embed_tokens` and `lm_head`, even when auto-detection excludes them. Gemma uses a scaled `nn.Embedding` that the embedding LoRA wrapper does not support. Since `lm_head` shares that embedding, adding it as a target triggers conversion to `ParallelLMHead`, which reads the missing `org_vocab_size` attribute.

## Modifications

Only add both embedding targets when auto-detection finds a `VocabParallelEmbedding` or `ParallelLMHead`. Supported parallel embeddings keep the same targets, including a tied `lm_head`.

For Gemma, `all` selects the supported projections and skips the tied-head conversion. The original embedding, its scaling, and the shared output weights remain in use. No embedding LoRA wrappers are installed; existing checks already skip their LoRA buffer allocation and updates.

This fixes startup for projection-only adapters; it does not add Gemma embedding LoRA support. With `all`, an adapter that explicitly lists `embed_tokens` or `lm_head` is rejected by the existing target validation.

Add two regression tests: a tied parallel embedding still gets both targets, and a tied plain `nn.Embedding` gets neither.

## Accuracy Tests

Reproduced on `797af71`, one L4, with no adapter loaded:

```bash
python -m sglang.launch_server --model-path unsloth/gemma-3-1b-it \
  --enable-lora --lora-target-modules all --max-lora-rank 8 \
  --attention-backend triton --disable-cuda-graph --mem-fraction-static 0.5
```

With the fix, the server starts and serves requests both with and without a rank-8 `all-linear` adapter. A tiny Gemma 4 checkpoint reproduces the same embedding error before the fix.

Original CPU validation (PyTorch 2.14.1, Transformers 5.19.0): **33 passed** across the four LoRA unit-test files. The plain-embedding regression fails without the fix; the tied-parallel-embedding test passes before and after.

Pre-commit passes on `c8704818`.
