# [Bugfix] Preserve ordinary JSON in Llama32 streaming responses

[Upstream PR](https://github.com/sgl-project/sglang/pull/42235) · state: closed · merged: False

## Original PR description

## Motivation

Llama32 streaming treats any leading `{` as a potential tool call. Complete ordinary responses such as `{"a": 1} is a dict` then produce no content, even after `finish()`. This addresses the streaming case reported in #35562.

## Modifications

- Return the original text once an untagged complete object is known to have no top-level `name`.
- Preserve the original buffer while classification is pending, so Python-dict quote conversion cannot rewrite ordinary content.
- Keep partial tool markers buffered and disable this fallback after an explicit marker, a recognized call, or a rejected unknown tool. Arguments preceding the name still parse as tools.
- Add regression/control cases for whole responses, character deltas, every two-chunk boundary, Unicode/quotes, nested objects, Python dicts, split markers, and unknown tools.

This is intentionally limited to complete, untagged objects without `name`. It does not change non-streaming parsing, unknown-tool policy, incomplete JSON/partial-marker handling at EOF, or final tool-call draining.

Related work: #35608 and #35894 fix the non-streaming path; #40994 drains real tool calls at stream end. Applying #35608 and #40994 together still fails the ordinary-content regressions without this patch. Their changes are not included here.
