## Motivation

Make the two optional DSpark simulated-acceptance shortcuts opt-in after #45421 enabled them on CUDA as well as HIP.

## Modifications

- Default `SGLANG_DSPARK_SIMULATE_FOLD` and `SGLANG_SIMULATE_ACC_GREEDY` to `False`.
- Update their comments to describe opt-in behavior on CUDA/HIP.
- Explicit `=1` still enables each shortcut. The unconditional simulated accept-sampling bypass introduced in #45421 is unchanged; this does not fully revert that PR.

## Accuracy Tests

Loaded the actual `environ.py` module with the bundled Python runtime and verified both switches return `False` when unset, `True` with `=1`, and `False` with `=0`. `git diff --check` passed. No GPU or end-to-end tests were run.

Related CPU coverage: `test/registered/unit/spec/test_dspark_accept_tail.py` checks eager/folded greedy acceptance parity, but does not exercise these environment defaults.

## Speed Tests and Profiling

Not run. Users can explicitly enable the shortcuts for simulated-acceptance benchmarks.
