# [Feat] elastic-ep: Add orchestrator-safe scale-up bootstrap

[Upstream PR](https://github.com/sgl-project/sglang/pull/39834) · state: open · merged: False

## Original PR description

## Motivation

An external reconciler needs to launch Elastic EP allocations from one immutable
template, retry ambiguous growth requests, and distinguish operation completion
from the engine's current health. This implements the append-growth portion of
#35376 for [Dynamo DEP #13121](https://github.com/ai-dynamo/dynamo/issues/13121).

## Modifications

- Add caller operation/runtime identity, retained pending/terminal results,
  scheduler submission correlation, and safe replay after a lost acknowledgment.
- Accept an optional `expected_topology_token` and report `topology_token` in
  status. Exact replay uses the original token; conflicting reuse and delayed new
  requests are rejected before scheduler effects. A runtime-local monotonic
  revision advances on new acceptance and once on commit, including completion
  discovered through retry. Duplicate completion/replay leaves it unchanged;
  size or operation-ID reuse cannot recreate an older fence.
- Form the complete initial world from allocation indexes and visible accelerator
  width in `auto` mode. Later never-occupied indexes append through the native
  operation-bound cohort handshake. No Kubernetes API or synthetic initial grow
  is required.
- Preserve allocation/rank-range identity and reject unauthorized joiners or
  mismatched widths/attention topology. One joining allocation may contain several
  contiguous physical EP ranks.
- Keep API targets/status in physical EP units and worker/control fan-out in
  logical attention-DP units, integrating merged #33728.
- Preserve completed-operation results separately from later `runtime_health`
  and `runtime_error`. Cohort progress is not inference-readiness proof; engine
  serving readiness remains authoritative without a second controller grant.
- Document the public bootstrap, operation, token/replay and status contract in
  the existing expert-parallelism guide.

## Known limitations

- Append growth only, one joining allocation per operation. No shrink, selected
  retirement, arbitrary rank recovery, or multi-pod allocation admission.
- Automatic bootstrap requires attention TP1/CP1 and DP attention. Existing
  explicit mode retains its fixed attention-topology contract.
- Automatic bootstrap never chooses `recover`. Previously occupied slots fail
  explicitly; allocation zero restart creates a new primary/runtime and requires
  group recreation until authority recovery is supported.
- Existing queued growth and bounded scheduler acknowledgment are reused; no new
  asynchronous submission route or background transaction framework is added.
- Autonomous idle resize completion remains unqualified; the real-GPU growth
  scenarios use explicit inference demand.
- The separately qualified #33111 shrink/correlation/warmup composition is not
  silently included in this growth-only PR.

- julienmancuso · comment · 2026-09-17T15:01:00Z · [source](https://github.com/sgl-project/sglang/pull/39834#discussion_r4038330190)

File: `python/sglang/srt/managers/tokenizer_manager.py` · line None

Good catch—there was no bound here, so a missing scheduler response could keep both the communicator call and `_elastic_scale_lock` held indefinitely. Fixed in e8abbdef: the fan-out now uses `asyncio.wait_for`, bounded by 30 seconds or the configured scale-operation timeout when that is smaller. Cancellation clears the communicator waiter, which releases both locks. Each fan-out attempt also gets a distinct `submission_id` echoed by schedulers, so a late response from the abandoned attempt is dropped instead of being counted toward the retry. `test_submission_timeout_releases_lock_for_retry` and `test_cancelled_call_drops_late_correlated_response` cover those cases.
