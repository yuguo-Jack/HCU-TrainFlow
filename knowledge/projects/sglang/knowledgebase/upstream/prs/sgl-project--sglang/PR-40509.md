# [NPU] Add startup, checkpoint, chat-template, radix-backend, and HiCache tests

[Upstream PR](https://github.com/sgl-project/sglang/pull/40509) · state: open · merged: False

## Original PR description

## Motivation

Ascend lacks dedicated coverage for gated startup, INT8 Mamba checkpoint storage, server-wide chat-template defaults, explicit radix-cache backend selection, and HiCache host-memory modes. Add NPU tests that verify deferred weight loading until activation, recurrent-state checkpoint storage and restoration, per-request overrides of server chat-template defaults, registered cache factories performing real NPU prefix reuse, and host KV retention versus transient staging during storage roundtrips.

The INT8 checkpoint tests also compare Llama-3.2-1B-Instruct with the flag disabled and enabled. Llama has no Mamba layers, so this is a compatibility check: it does not establish INT8 Mamba cache-hit accuracy on a hybrid model.

## Modifications

- Add `test_npu_default_chat_template_kwargs.py`: use Llama-3.2-1B-Instruct's native `date_string`, `tools_in_user_message`, and `custom_tools` template variables to verify server defaults, request overrides, per-key merging, explicit false/empty values, and request isolation. Compare actual inference prompt token IDs with independently rendered tokenizer IDs for both streaming and non-streaming chat completions.
- Add `test_npu_gated_launch.py`: verify control-port health before activation, unavailable serving, waiting/activation logs for every rank, idempotent activation, deferred weight allocation, and successful generation after activation. Support TP1 and optional TP2 through `SGLANG_TEST_TP_SIZE`.
- Add `test_npu_int8_mamba_checkpoint.py`: exercise the existing codec and checkpoint pool on real NPU tensors with BF16 and FP32 states. Check quantization error, zero states, checkpoint/active-copy independence, exact convolution-state restoration, memory accounting, slot exhaustion/reuse, and clearing.
- Validate rejection of INT8 checkpoints combined with hierarchical caching or a custom radix-cache backend through `ServerArgs.resolve_once()`.
- Run Llama with the flag off/on, check the resolved server arguments, compare greedy output tokens and logprobs, and verify ordinary KV prefix-cache hits. Assert that no Mamba checkpoint pool is constructed for this dense model.
- Add `test_npu_radix_cache_backend.py` and an importable Ascend test plugin: load the same plugin in default and explicitly selected backend servers, then compare cold, repeated, shared-prefix, and post-flush requests. Verify cache factory selection, same-process registration, NPU KV-index devices, cache lifecycle events, and exact output token IDs/text.
- Add `test_npu_hicache_host_memory_mode.py`: migrate the GPU file-backend backup/flush/prefetch scenario to Ascend, compare `cache` with `buffer_only`, verify storage-hit attribution and host-slot retention/release, and compare deterministic output tokens/text/logprobs against a no-HiCache baseline. Check invalid argument combinations and the existing FULL+MAMBA rejection before host-pool allocation. Support Llama-3.2-1B-Instruct and a Qwen3-0.6B model-path override with thinking disabled.
- Register the gated-launch, INT8, chat-template, and radix-backend tests in the `full-1-npu-a3` nightly suite, and the HiCache test in `nightly-1-npu-a3`. Reuse the Ascend Llama weights constant. All support model-path overrides and clean up their server processes. The gated-launch, INT8, radix-backend, and HiCache tests support log-directory overrides; the chat-template test supports a base-URL override.

The gated test starts its subprocess directly because `popen_launch_server()` waits for serving readiness before returning. The INT8 compatibility, chat-template, and radix-backend tests use `popen_launch_server()`. No inference runtime implementation changes are included.

## Accuracy Tests

### Gated launch

Validated on host 212 with Llama-3.2-1B-Instruct, Ascend A3, CANN 9.1, Python 3.12.13, PyTorch 2.10.0+cpu, and torch_npu 2.10.0.post6. The tested framework base is `c8eb54c41da1d6b452e77469fda548547dd21b14`; graph mode was disabled.

| Test | Result | Duration |
| --- | --- | --- |
| NPU gated launch, TP1 | PASS | 61.692 s |
| NPU gated launch, TP2 | PASS | 52.569 s |
| Existing CPU/Gloo gated-launch tests | 7/7 PASS | 20.762 s |

Observed device memory (MiB):

| Mode | Gated | After activation and generation | Increase |
| --- | ---: | ---: | ---: |
| TP1 | 526.73 | 3567.51 | 3040.78 |
| TP2, rank 0 | 227.10 | 2432.82 | 2205.73 |
| TP2, rank 1 | 227.10 | 2432.82 | 2205.73 |

Both modes generated text containing `Paris`. TP2 logs confirmed both ranks waited and were activated before weight loading. These are device-wide memory snapshots and require otherwise idle NPUs.

### INT8 Mamba checkpoint storage and Llama compatibility

Validated on host 216 in `sglwmc-914`, Ascend A3 device 15, TP1, graph mode disabled, with CANN 9.1.0, Python 3.12.13, PyTorch 2.10.0+cpu, and torch_npu 2.10.0.post4. The container framework is `a984c78330a8a5085a997818c396353262870429`. The checkpoint-pool implementation and argument-validation hook match this PR's framework base after newline normalization.

**All 4 tests passed in 105.748 seconds, exit code 0, with no skips or xfails.**

| Check | BF16 state | FP32 state |
| --- | ---: | ---: |
| Codec relative error | 0.662000% | 0.646064% |
| Pool round-trip relative error | 0.660624% | 0.647237% |
| INT8 data + scales / native temporal-state bytes | 50.78125% | 25.78125% |

Error measurements use seeded synthetic states, not model-level KL or benchmark accuracy. Memory ratios describe tensor storage, not whole-model memory consumption.

The Llama comparison produced 8 responses across flag-off/flag-on and cold/warm rounds. Both configurations answered `Paris` and `4`; each warm request reused 256 of 266 prompt tokens. Output token IDs matched across configurations and output logprobs passed `atol=rtol=1e-5`. Both incompatible cache combinations were rejected as expected.

The submitted INT8 test matches the hardware-tested file, SHA256 `44e46b19f3d2fb5b8d5822fdddf24048d2f5ee26aa6aafa698ffdd8cb9b26748`.

The existing CUDA hybrid-model KL/GSM8K tests and CUDA FLA KDA decode-error test were not run or ported in this change. Full hybrid-model INT8 checkpoint cache-hit accuracy remains outside this Llama-based validation.

### Default chat-template kwargs

Validated on host 212 in `hanwlax-0920`, Ascend A3 device 0, TP1, graph mode disabled, using Llama-3.2-1B-Instruct, CANN 9.1.0, PyTorch 2.10.0+cpu, torch_npu 2.10.0.post6, and Transformers 5.12.1. The container framework is `76f9213a411018547f4fd6a75f36feaa4d6bed58`; `serving_chat.py` and the serving-argument definitions have identical Git blobs to this PR's framework base, and the JSON-object validation code matches.

**All 8 tests passed in 54.185 seconds, exit code 0: 20 real inference requests, 10 streaming and 10 non-streaming, each generating 4 tokens.**

| Check | Result |
| --- | --- |
| Omitted, null, and empty request kwargs inherit server defaults | PASS |
| Request date overrides the server date | PASS |
| Empty string and false remain explicit overrides | PASS |
| New request keys preserve other server defaults | PASS |
| Overrides and custom tools do not leak to later requests | PASS |

Every request compares the complete `sglext.input_ids` list against `AutoTokenizer.apply_chat_template()` with explicit expected kwargs, and checks generation, usage accounting, and normal completion. Streaming also requires `[DONE]`. The model's native template is unchanged, and `custom_tools` only makes tool-description placement observable; no external tools are executed. This validates ordinary Llama template kwargs; model-specific reasoning-effort normalization and Qwen thinking behavior are outside this test's scope.

The submitted executable test logic matches the hardware-tested file; only the documented repository path and test-category label changed when placing it alongside the other parameter tests. The test server was cleaned up and its NPU released after validation.

### Radix-cache backend selection

Validated on host 212 in `hanwlax-0920`, Ascend A3 physical device 14, TP1, BF16, graph mode disabled, using Llama-3.2-1B-Instruct. The runtime was an isolated source export of this PR's framework base `c8eb54c41da1d6b452e77469fda548547dd21b14`, selected through `PYTHONPATH`. Environment: CANN 9.1.0, Python 3.12.13, PyTorch 2.10.0+cpu, torch_npu 2.10.0.post6, Transformers 5.12.1, and sgl-kernel-npu 2026.9.0.

**The NPU end-to-end test passed in 106.198 seconds, exit code 0, with no skips. The existing radix registry/routing tests also passed: 24/24 in 0.990 seconds.**

Each measured request contains 768 input tokens and generates 8 tokens. The two prompts share exactly 512 input tokens; page size is 128 and chunked-prefill size is 256.

| Scenario | Default cached tokens | Registered-backend cached tokens |
| --- | ---: | ---: |
| Cold A | 0 | 0 |
| Repeated A | 640 | 640 |
| Shared-prefix B | 512 | 512 |
| B after flush | 0 | 0 |
| A after another flush | 0 | 0 |

Output token IDs and text match across backends for all five scenarios. Cold/warm/post-flush A outputs also match, as do shared-prefix/cold B outputs. The selected backend logs `source=registered('ascend_test_radix') impl=ObservedNpuRadixCache`, with one factory invocation and all observed hit indices on `npu:0`. Lifecycle evidence includes 19 inserts, 13 hits, and 4 resets, including warmup and internal chunked-prefill operations. The default server loads and registers the plugin but never invokes its factory.

The fixture uses a temporary `sglang.srt.plugins` entry point so spawned schedulers register the backend themselves. Registration is recorded as a structured event with a PID because plugin loading can precede logging initialization. The backend subclasses the real unified cache and only adds observation; cache algorithms and attention kernels are unchanged.

The submitted files match the hardware-tested files: test SHA256 `ac6f98c4f0ab81026f5c98673d67a2a5be95fd9ec8903799c8c073c65af91f13`; helper SHA256 `157a6619395fa8e7eee21bcffb99a5beb6fc67989b23ceb8fd4549bb511469ad`. This validates the registered-backend interface for Llama full attention on one NPU; hybrid models, eviction pressure, third-party storage, HiCache, and performance are outside its scope.

### HiCache host-memory modes

The test selects Ascend `kernel_ascend` transfers and `page_first_direct` layout. The E2E method starts a no-HiCache baseline and then `cache + file` and `buffer_only + file`, using separate temporary storage directories and the same explicit host/device ratio. It checks a cold miss, an NPU warm hit, and two L3 restores after flushing L1/L2. Restored requests must report device/host hits of zero and positive storage hits. Fresh host-pool metrics must show retained KV in `cache` and returned staging slots in `buffer_only`; nonzero pool capacity and completed backup are required. A sub-page request refreshes gauges before checking them. Greedy tokens and text must match the baseline; output logprobs use fixed `atol=0.02, rtol=0` for BF16 rounding.

Validation on host 209 in `sglang-wy` used an isolated export of framework base `c8eb54c41da1d6b452e77469fda548547dd21b14`, with Python 3.12.13, PyTorch 2.10.0+cpu, torch_npu 2.10.0.post6, Transformers 5.12.1, and sgl-kernel-npu 2026.9.0.

| Check | Result |
| --- | --- |
| Argument defaults, Ascend IO/layout, and invalid combinations | PASS |
| Production `init_hicache` guard rejecting FULL+MAMBA in `buffer_only` | PASS |
| Final validation-only run | 2 tests in 1.394 s, exit 0, no skips |
| Full three-server E2E on 209 | Not run: all 16 NPUs were occupied; preflight stopped before server launch |

The submitted test matches the final validation-only file, SHA256 `25be908dc321095adaa68dfd32f9c6540fdda0ee28c0343d40f7abc261a8f37b`. The two passing checks load configuration but do not establish model inference or KV transfer correctness. An earlier Llama version passed a full roundtrip on host 216 with framework `a984c78330a8a5085a997818c396353262870429`; that historical run does not validate this final file or Qwen3 on 209.

Qwen3.6-35B-A3B's captured configuration has 30 linear-attention and 10 full-attention layers and requires a MAMBA cache component. The current buffer-only implementation supports FULL/SWA trees, so Qwen3.6 is not a valid positive two-mode target. The rejection check calls the existing guard with a component fixture; it is not a Qwen3.6 server-startup test. The prepared full-attention alternative on 209 is Qwen3-0.6B. No runtime support restriction is removed.
