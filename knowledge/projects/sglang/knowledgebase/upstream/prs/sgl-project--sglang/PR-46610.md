# [Feat] [Intel] mem_cache: Enable the HiCache Mamba host pool on XPU

[Upstream PR](https://github.com/sgl-project/sglang/pull/46610) · state: open · merged: False

## Original PR description

# [Feat] [Intel] mem_cache: Enable the HiCache Mamba host pool on XPU

## Motivation

`MambaPoolHost` previously rejected Intel XPU because the existing CUDA/ROCm Mamba transfer kernels are JIT-built from CUDA source. This prevented hybrid Mamba models from using HiCache host offload on XPU.

The `sgl-kernel-xpu` wheel provides AOT SYCL implementations of `transfer_kv_mamba_lf_pf` and `transfer_kv_mamba_pf_lf`, enabling Mamba state transfers between XPU and host memory.

## Changes

- Enable XPU Mamba host-pool transfers through the available SYCL kernels.
- Check required operations at pool construction and report missing kernels clearly.
- Handle MTP draft layers and strided slots by stacking selected states in chunks of up to 256 MiB.
- Fix host/device index placement during state restoration.
- Preserve existing non-XPU code paths.

## Tests

- **42 tests passed** across CPU host-pool unit tests and XPU round-trip tests on Intel Arc Pro B60.
- Verified device → host → device state restoration for kernel and direct-transfer paths, including one MTP draft layer.
- CPU tests validate dispatch and tensor preparation; XPU tests execute the actual transfer paths.

## Performance and correctness

Tested with Qwen3.5-9B on one Intel Arc Pro B60 (`TP=1`, `intel_xpu` linear-attention backend).

| Metric | HiCache off | HiCache on | Change |
|---|---:|---:|---:|
| Shared-prefix output throughput | 21.0 tok/s | 24.2 tok/s | **+15%** |
| Mean TTFT | 36.6 s | 30.7 s | **−16%** |
| P99 TTFT | 52.9 s | 49.3 s | **−7%** |
| Cache hit rate | 19.2% | 40.3% | **2.1×** |
| GSM8K accuracy (50 examples) | 98% | 98% | Unchanged |
| Mean TPOT | 89.4 ms | 87.1 ms | −2.6% |

The benchmark completed 256 requests without server errors and confirmed Mamba state transfers in both directions.

A separate 16-conversation multi-turn check restored host-cached state in all 16 HiCache-enabled conversations, compared with 6/16 without HiCache. Accuracy was 14/16 with HiCache and 15/16 without it. The sample is too small to establish a meaningful accuracy difference; repeated baseline runs also showed output variation.

Overall, the reported results show promising throughput, TTFT, and cache-reuse improvements. Repeated benchmark runs are needed to establish the consistency of the performance gains.

## Environment

- **Hardware:** Intel Arc Pro B60 (`ZE_AFFINITY_MASK=4`)
- **Software:** torch 2.14.0+xpu, `sglang-kernel-xpu` 0.4.0
- **Model:** `Qwen/Qwen3.5-9B`
- **HiCache:** `kernel` I/O backend, `page_first` memory layout
