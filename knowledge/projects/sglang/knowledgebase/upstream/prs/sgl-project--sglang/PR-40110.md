# [NPU] add e2e test for --mamba-max-states-per-path eviction

[Upstream PR](https://github.com/sgl-project/sglang/pull/40110) · state: open · merged: False

## Original PR description

## Motivation

`--mamba-max-states-per-path` is a key knob of the mamba radix cache: it caps how many mamba states are retained per path, with the rest evicted. There was no Ascend NPU end-to-end coverage that actually verifies eviction takes effect, i.e. that a stricter cap leads to fewer retained (evictable) mamba states. This PR adds that coverage.

## Modifications

- Add `test/registered/npu/basic_function/HiCache/test_npu_mamba_path_state_cap_evictable.py`:
  - Launches an NPU server (`Qwen3.5-27B`, TP=2, `--attention-backend ascend`, `--mem-fraction-static 0.8`, `--enable-metrics`) sweeping `--mamba-max-states-per-path` over `[1, 3, 64]`.
  - Runs a shared-prefix multi-turn workload so mamba states keep accumulating on the same radix path, with each turn crossing the 256-token track boundary to guarantee state donation.
  - Reads the `sglang:mamba_evictable_tokens` gauge from `/metrics` (cross-rank summed under TP=2) and asserts it is non-decreasing in cap, plus `cap=1` is strictly smaller than `cap=64`.
  - Registered via `register_npu_ci(est_time=3600, suite="full-2-npu-a3", nightly=True)`.

## Accuracy Tests

This is a cache/eviction behavior test; it does not change model forward code or outputs, so no token-level accuracy comparison is required. Correctness is asserted through the monotonic behavior of the `sglang:mamba_evictable_tokens` metric.

## Speed Tests and Profiling

No inference-speed impact; this adds CI coverage only. No profiling results needed.
