## Motivation

Under `--enable-unified-memory` a pool may hold several window sub-pools (the target's window and draft windows of other lengths). PD transfers registered one state entry per window, but peers found an entry's pages by its state type: the second window had a state type of its own (`auxiliary_swa`) only so that its entry could find its sub-pool, and a third window had none, so such a plan could not list its PD entries. Peers also paired entries by position without checking that both sides registered the same entries.

## Modifications

- `disaggregation/utils.py`, `base/conn.py`, `mem_cache/kv/plan.py`: each registered state entry records the sub-pool it carries (`KVArgs.state_sub_pools`, parallel to `state_types`; `None` for a static pool, whose entries are slices of its pools). Prefill and decode build one payload per entry (`state_indices_per_entry`); a window entry carries its own sub-pool's pages. A transfer's rows are recorded against the entry's sub-pool by position.
- Every window travels as the window state type (`swa`) and is told apart by its sub-pool; the plan lists window entries by sub-pool name, so peers order them alike whatever order a model declares them in. `StateType.AUXILIARY_SWA` and its uses in the Mooncake and NIXL engines are removed.
- `disaggregation/common/conn.py`, `decode.py`, `prefill.py`: the prefill reports its entries to the bootstrap server as (state type, sub-pool) pairs, kept per pipeline stage; a decode whose entries differ refuses to connect and names both lists (`check_state_wire`). Ranks of one stage that register different entries are refused. An older peer that reports no entries is not checked.
- Tests: `test/registered/unit/disaggregation/test_unified_window_wire.py` (two and three windows each register and carry their own entry; mismatched peers are refused; per-stage entries through the bootstrap handlers), plus updates to `test_unified_window_sub_pools.py` and existing PD tests.

**Behavior change:** a PD decode whose state entries differ from its prefill's (same pool kind, different window sub-pools or order) now fails at bootstrap with both entry lists, instead of transferring into mismatched rows. Static pools register no sub-pools and keep their pairing.
