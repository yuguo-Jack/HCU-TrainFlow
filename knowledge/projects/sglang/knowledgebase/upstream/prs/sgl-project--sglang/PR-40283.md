# [mem_cache] Trim out-of-window SWA slots when caching finished requests

[Upstream PR](https://github.com/sgl-project/sglang/pull/40283) · state: closed · merged: False

## Original PR description

## Summary

Call the existing component `free_out_of_window_slots` hook before inserting a finished request into the unified radix cache. `cache_unfinished_req` already invokes this hook; a request finishing directly after prefill previously retained its entire final chunk as live SWA KV.

The frontier is measured from the **page-aligned insertion key**, preserving a live SWA window at the resulting leaf, including for EAGLE bigram keys. The existing **default-on** `SGLANG_OPT_UNIFIED_CACHE_FREE_OUT_OF_WINDOW_SLOTS` guard is reused. No new flag, allocator or pressure heuristic.

**Draft:** cache-operation benchmarks show both benefits and regressions. End-to-end serving performance remains an open validation gate.

## Performance: cache operations, not serving throughput

Unmodified `81421b91e9ad02c526bb3025f66f42e2a7c52059` versus patched source, with the existing flag **enabled in both**. GB300, Python 3.12.3, torch 2.13.0+cu130, Python tree core, page size 256, SWA window 512. Five rounds per workload; fresh fixtures; four warmup requests excluded from timing. Entries are medians of round statistics; brackets give the round min–max, **not confidence intervals**.

| Workload | FULL/SWA pool slots | Baseline cache ops/s [range] | Patched cache ops/s [range] | Change |
|---|---:|---:|---:|---:|
| SWA-bound: 8 shared 4096-token prefixes + unique 256-token tails | 262144 / 16384 | 386.05 [315.09–437.31] | 553.95 [461.36–586.19] | **+43.5%** |
| Fixed set: 4 identical 6144-token prompts | 65536 / 16384 | 394.87 [393.85–412.75] | 1430.98 [1361.48–1476.17] | **3.62×** |
| Unique 8192-token prompts, SWA not binding | 262144 / 262144 | 995.17 [972.15–1038.56] | 644.98 [636.03–680.22] | **−35.2%** |
| Unique 1024-token prompts, SWA not binding | 262144 / 262144 | 1349.14 [1319.94–1402.09] | 782.39 [711.88–839.90] | **−42.0%** |
| EAGLE bigram, unique 8192-token prompts | 262144 / 262144 | 457.03 [438.13–460.18] | 328.04 [268.71–338.28] | **−28.2%** |
| FULL-bound: 4 shared 4096-token prefixes + unique 2048-token tails | 65536 / 16384 | 298.35 [291.05–306.10] | 270.13 [251.76–274.80] | **−9.5%** |

Measured requests per round: 156 for either pressure workload, 44 for the fixed set and 1024-token workload, and 20 for either 8192-token workload. Synchronized host latency around `cache_finished_req` increases by **0.56 ms** for nonbinding 8192-token prompts, **0.51 ms** for 1024-token prompts, and **0.78 ms** for bigram prompts. The added work is SWA page release and tombstone insertion, not just the hook dispatch.

Supporting capacity result: in the **nonbinding 8192-token workload**, retained live SWA across all 24 requests decreases from 196608 to 18432 slots (10.7×). These are pool slots, not reduced CUDA reservation.

### Measurement limits

- These synthetic cache fixtures do **not** execute model inference. The percentages are not serving-throughput changes or quality measurements; no TPM/TTFT A/B is available.
- The fixed-set fixture allows whole-prompt matches with zero unmatched tail. Real scheduling caps the match at `input_len - 1` and page-ceils the extension, so 3.62× must not be interpreted as a serving speedup or full-prefill elimination.
- Source/flag-off controls were also measured. Within-round ordering was fixed, and the late bigram/SWA-pressure batches had same-node co-tenancy. In particular, the bigram baseline-off and patched-off ranges do not overlap; controls do **not** establish that all timing drift canceled.
- Original eviction counters include the four warmup requests, while timing excludes them. No measured-window eviction-rate claim is made here.
- Earlier SWA trimming can affect shorter/branching-prefix reuse; it is not a claim that every removed slot is useless to every possible future request.
