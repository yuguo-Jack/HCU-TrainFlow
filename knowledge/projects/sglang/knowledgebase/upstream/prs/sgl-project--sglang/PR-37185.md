# [Observability] Add --log-schedule-decisions and include pid in scheduler log prefix

[Upstream PR](https://github.com/sgl-project/sglang/pull/37185) · state: closed · merged: False

## Original PR description

## Motivation

When debugging head-of-line blocking or unexpected queueing, the question that matters is what each prefill scheduling pass actually admitted, and why everything else stayed in the queue. That information only exists inside `_get_new_batch_prefill_raw` and is not recoverable after the fact from the periodic stats logs, which report aggregate pool usage rather than per-pass admission decisions. Today the only way to get it is to patch a `logger.info` into the scheduler locally and rebuild.

Separately, when several scheduler subprocesses write to the same stream, their log lines are hard to attribute to a specific rank because the prefix does not carry the pid.

## Modifications

- Add `--log-schedule-decisions` (observability group, default `False`). When enabled, each prefill pass logs the number of requests picked, the number left in the queue, the number running, the KV budget the pass saw (`full_available_size` free + `full_evictable_size` reclaimable via eviction, read from `pool_stats_observer.get_pool_stats()`), and the picked rids.
- Append the OS pid to the scheduler log prefix in `configure_scheduler_process`, so lines from different scheduler subprocesses can be told apart. This is deliberately kept out of the proctitle, since `ps` already shows the pid there.

The flag is opt-in because the log fires on every prefill batch, which would be far too noisy to enable by default. When the flag is off the added code is a single boolean check per prefill pass.

Sample output:

```
Schedule prefill: #picked=8, #left-in-queue=24, #running=12, kv-free-tokens=131072, kv-evictable-tokens=40960, picked-rids=['a1b2...', ...]
```

## Accuracy Tests

No functional change — this only adds logging and a log-prefix suffix. Scheduling behavior is untouched; the new block runs after `waiting_queue` has already been updated and does not mutate any state.

No unit test is added: the change is a gated `logger.info` plus a log-prefix string, and asserting on log text would pin an output format that is explicitly a debugging aid. Happy to add one if reviewers would prefer it.

## Benchmarking and Profiling

No measurable effect when disabled (one boolean check per prefill pass). When enabled, cost is one `get_pool_stats()` call and one log line per prefill batch, which is why it is not on by default.

- fortunecookiee · comment · 2026-09-11T16:00:37Z · [source](https://github.com/sgl-project/sglang/pull/37185#issuecomment-5637158327)

Rebased onto current `main` — the old branch no longer merged, since `server_args.py` no longer declares fields at all. The flag now lives in `arg_groups/fields/observability.py` (the class carries `_NS_PATH`, so the `NS(...)` marker is dropped), and `scheduler.py` reads it via `get_observability().log_schedule_decisions`.

Self-review also turned up three substantive issues, all fixed here:

- **The pid suffix broke the in-tree log parser.** `_PATTERN_DECODE` in `debug_utils/log_parser.py` anchors `\]` immediately after the rank groups, so ` PID12345` made every scheduler line fail to match and `parse()` returned an empty DataFrame. Added an optional `PID` group. While there, the rank groups were reordered to the order `configure_scheduler_process` actually emits them (`DP PP ATTN_CP MOE_DP TP EP`) rather than `DP TP EP PP` — a pre-existing bug that meant no PP, ATTN_CP or MOE_DP run parsed at all. The parser test now covers a full prefix.
- **`#left-in-queue` was wrong under preemption.** The log ran before the `preempt_list` re-queue, so it undercounted by exactly the preempted count — in the head-of-line-blocking scenario the flag exists to diagnose. It now runs after, and reports `#preempted`.
- **Zero-admission passes were never logged.** The `len(can_run_list) == 0` early return skipped the log, hiding the single most diagnostic event. Those passes are now logged too.

Hot-path cost is unchanged when the flag is off (one bool attribute read); when on, `get_pool_stats()` resolves to Python-int counters with no device read.
