# [Fix] Pass speculative tree metadata to LFM2 short-convolution verification

[Upstream PR](https://github.com/sgl-project/sglang/pull/43682) · state: open · merged: False

## Original PR description

## Motivation

LFM2 target verification drops the speculative tree links before calling its short-convolution kernel. With NGRAM branching proposals, the kernel consequently processes the draft tokens as a linear sequence rather than following their tree ancestry. This changes the target computation and can change accepted output tokens.

## Modifications

Pass the existing next-token, sibling, and parent links through `ShortConvMetadata` to `causal_conv1d_update_triton`. Keep `None` defaults for callers without a tree. No new kernel, allocation, synchronization, or configuration option is added. LFM2-MoE shares the helper, but was not tested separately.

Four prompts were checked: a capital-city completion, the story above, a language-model explanation, and a summary of the repository README. The unpatched and core-reverted versions diverged at positions 50, 41, and 19 for three prompts. The remaining story difference moved to position 52, where the relevant BF16 logits were tied or nearly tied. These checks validate speculative target computation, not factual accuracy or a full benchmark dataset.

Full four-prompt client, reading the exact README excerpt from the frozen base (save as `ngram_client.py`):

```python
import json
import sys
import subprocess
from pathlib import Path
import requests

readme = subprocess.check_output([
    "git", "show", "ad8b1e1f851a6445e1211f7f0cf2130028ecae0c:README.md"
], text=True)
prompts = [
    "The capital of France is",
    "Once upon a time",
    "Explain how a language model predicts the next token.",
    readme[:2400] + "\nSummarize the document:",
]
client = requests.Session()
client.trust_env = False
records = []
for prompt in prompts:
    response = client.post("http://127.0.0.1:31241/generate", json={
        "text": prompt, "sampling_params": {"temperature": 0, "max_new_tokens": 64},
        "return_logprob": True, "top_logprobs_num": 5,
    }, timeout=120)
    response.raise_for_status()
    records.append(response.json())
Path(sys.argv[1]).write_text(json.dumps(records, indent=2))
print([len(item["output_ids"]) for item in records])
```
