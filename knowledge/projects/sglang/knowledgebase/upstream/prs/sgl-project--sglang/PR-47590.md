# fix(dspark): honor speculative accept threshold in rejection sampling

[Upstream PR](https://github.com/sgl-project/sglang/pull/47590) · state: open · merged: False

## Original PR description

## Motivation

`--speculative-accept-threshold-acc` raises a draft token's target probability from `p` to `min(1, p / threshold_acc)` so the draft is easier to accept. DSpark rejection sampling hardcoded the value to `1.0`, and the shared Triton chain kernel never passed it in, so the flag and `POST /set_internal_state` did not change acceptance.

## Modifications

- Scale the target probability inside chain rejection sampling, for both the sequential accept test (`coin * q < min(1, p / threshold_acc)`) and block verification's prefix probability. `threshold_acc=1` keeps the previous test for probabilities (`p <= 1`). Values below `1e-9` are clamped.
- DSpark reads the live spec config on every verify step, so a `/set_internal_state` update applies without a restart.
- EAGLE rejection-sampling startup still rejects a non-default threshold. The shared kernel is what EAGLE rejection sampling calls; the launch check is unchanged.

## Accuracy Tests

Measured with the same accept rule on GSM8K (1319 questions, temperature=0.9) on 2026-10-25. Not re-run on this commit.

| threshold_acc | accuracy | accept length |
| --- | --- | --- |
| 1.0 | 0.9227 | 3.619 |
| 0.95 | 0.9189 | 3.546 |

At 0.95, accept length did not increase and accuracy dropped slightly.

## Speed Tests and Profiling

No separate speed benchmark. The change is only in the accept comparison.
