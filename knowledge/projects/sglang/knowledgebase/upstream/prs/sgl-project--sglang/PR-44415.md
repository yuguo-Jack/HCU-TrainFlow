# [Fix] [AMD] GLM-5.3-Flash: Keep the MoE correction bias fp32

[Upstream PR](https://github.com/sgl-project/sglang/pull/44415) · state: open · merged: False

## Original PR description

## Summary

On MI355X with aiter, GLM-5.3-Flash picks MoE experts with a rounded bias. The checkpoint stores each layer's 288 expert correction biases in fp32, within a band about 0.4 wide. With FP8/Quark weights, `MoEGate` stores them in bf16, which steps 0.03–0.06 there, and `select_experts` casts any bias to the bf16 gating dtype before aiter's top-k; CUDA keeps fp32. 59% of real tokens then change their top-8. This PR keeps the bias fp32 for GLM-5.3-Flash at both places; aiter then routes with fp32 logits.

How the cast swaps an expert, illustrative values:

| | Expert A | Expert B | Chosen expert (higher val) |
| --- | --- | --- | --- |
| fp32 bias | 7.410 | 7.420 | |
| Sigmoid score | 0.300 | 0.295 | |
| Score + fp32 bias | 7.710 | **7.715** | B |
| bf16 bias | 7.40625 | 7.40625 | |
| Score + bf16 bias | **7.70625** | 7.70125 | A |

## Scope

MI355X (gfx95) with aiter. The change keys on `model_type == "glm5_next_text"` through a `TopK` `fp32_correction_bias` flag, so only GLM-5.3-Flash moves; GLM-5.2 and other models keep today's routing. CUDA is untouched. The upcast costs 2.7 µs per routing call at 6 tokens.

## Test plan

| Setting | Value |
| --- | --- |
| Image | `rocm/sgl-dev:v0.5.21-rocm10-mi35x-20261012` |
| Base | upstream main `0cf683ea8d` + #41615 + #38764 (GLM-5.3-Flash needs them to run its DSA k-pool on Triton) |
| Model | `amd/GLM-5.3-Flash-Quark-MXFP4`, MI355X TP4 |
| Routing and scoring | prefill only, no MTP; base vs this PR, so bias dtype is the only difference |
| Text | 1319 GSM8K test problems + 150k tokens of wikitext-103 test (228k tokens) |

Each layer's 288 checkpoint biases are distinct fp32 values, up to 288 per layer; the bf16 cast leaves at most 11. Replaying real router logits through `biased_grouped_topk_gpu` with each bias, 59% of tokens get a different top-8, mostly by one expert:

| Experts swapped vs the fp32 bias (42 layers × 18,243 tokens) | 0 | 1 | 2 | 3 | ≥4 |
| --- | --- | --- | --- | --- | --- |
| Share of tokens | 41.1% | **43.8%** | 11.8% | 2.5% | 0.7% |

Scoring the same 228k tokens of real text with each bias, the bf16 bias gives the true next token about 0.65% less probability on average, in both of two runs per arm; rerunning one arm moves it less.

**Accuracy:** GSM8K 97.12 → 96.97, single scoring pass each, within noise.

**Unit tests:** `test_glmmoedsa_correction_bias_fp32.py` (`base-a-test-cpu`) adds `glm5_next_text` under fp8 / compressed_tensors / quark and the bias dtype at the aiter router: 10 passed.

**Cost:** routing call at 6 tokens 4.75 → 7.42 µs, graph-replayed on MI355X. Stacked with #44416, whose router serves target verify, only prefill and the draft layer pay it.
