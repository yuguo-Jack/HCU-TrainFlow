# [Fix] [AMD] GLM-5.3-Flash: Keep the MoE correction bias fp32

[Upstream PR](https://github.com/sgl-project/sglang/pull/44415) · state: open · merged: False

## Original PR description

## Summary

On MI355X with aiter, GLM-5.3-Flash picks MoE experts with a rounded bias. The checkpoint stores each layer's 288 expert correction biases in fp32, within a band about 0.4 wide. With FP8/Quark weights, `MoEGate` casts them to bf16, which steps 0.03–0.06 there; CUDA keeps fp32. 59% of real tokens then change their top-8. This PR keeps the bias fp32 for GLM-5.3-Flash.

How the cast swaps an expert, illustrative values:

| | Expert A | Expert B | Chosen expert (higher val) |
| --- | --- | --- | --- |
| fp32 bias | 7.410 | 7.420 | |
| Sigmoid score | 0.300 | 0.295 | |
| Score + fp32 bias | 7.710 | **7.715** | B |
| bf16 bias | 7.40625 | 7.40625 | |
| Score + bf16 bias | **7.70625** | 7.70125 | A |

## Scope

MI355X (gfx95) with aiter. The change keys on `model_type == "glm5_next_text"`, so only GLM-5.3-Flash moves; GLM-5.2 already keeps fp32 and other models keep today's dtype. CUDA is untouched.

## Test plan

| Setting | Value |
| --- | --- |
| Image | `rocm/sgl-dev:v0.5.21-rocm10-mi35x-20261012` |
| Base | upstream main `0cf683ea8d` + #41615 + #38764 (GLM-5.3-Flash needs them to run its DSA k-pool on Triton) |
| Model | `amd/GLM-5.3-Flash-Quark-MXFP4`, MI355X TP4 |
| Routing and NLL | prefill only, no MTP; this PR vs this PR with the `glm5_next_text` line removed, so bias dtype is the only difference |
| Text | 1319 GSM8K test problems + 150k tokens of wikitext-103 test (228k tokens) |

Each layer's 288 checkpoint biases are distinct fp32 values, up to 288 per layer; the bf16 cast leaves at most 11. Replaying real router logits through `biased_grouped_topk_gpu` with each bias, 59% of tokens get a different top-8, mostly by one expert:

| Experts swapped vs the fp32 bias (42 layers × 18,243 tokens) | 0 | 1 | 2 | 3 | ≥4 |
| --- | --- | --- | --- | --- | --- |
| Share of tokens | 41.1% | **43.8%** | 11.8% | 2.5% | 0.7% |

Teacher-forced NLL over the 228k tokens (mean −log p of each true next token; 95% CI by document bootstrap):

| Comparison | ΔNLL (nats/token) |
| --- | --- |
| fp32 bias vs bf16 bias | −0.0014 |
| fp32 bias vs fp32 bias, rerun | −0.0034 | 

A plain rerun moves NLL more than the bf16 cast does, but fp32 is still the correct bias: it is the checkpoint's dtype and what CUDA uses.

**Accuracy:** GSM8K 97.04 → 96.82 within noise
