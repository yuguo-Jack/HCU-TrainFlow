# [Fix] docker: Pin sgl-nvidia-mega to 3333e4c so the megakernel starts on main

[Upstream PR](https://github.com/sgl-project/sglang/pull/46030) · state: closed · merged: True

## Original PR description

## Motivation

`docker/Dockerfile` and `docker/Dockerfile.cu134` pin sgl-nvidia-mega `d47deb33`. That commit predates two SGLang changes it depends on: the TopKConfig shared-expert field rename (#44912, #44913) and the kernel regrouping (#45112). As a result, it fails while building its MoE slots on current main, and every image built from main ships a megakernel that cannot start under `--enable-nvidia-megakernel`. This also blocks the DSpark megakernel path from #45450 in public images.

#45595 made the same bump and was closed in favor of #45389. #45389 is a larger refactor and currently changes only `docker/rocm.Dockerfile`. This PR is the standalone pin bump for the two CUDA Dockerfiles.

## Modifications

- Pin `SGL_NVIDIA_MEGA_COMMIT` to `3333e4cfac0f2b15603565d702b4c67538f1628f` in `docker/Dockerfile` and `docker/Dockerfile.cu134`.
- `3333e4cf` is the plugin main commit that follows both SGLang changes (sgl-nvidia-mega #15, #16) and includes the Engram prefetch fix (#7). It keeps the `nvidia_megakernel` entry point, so the existing install check is unchanged.

## Validation
