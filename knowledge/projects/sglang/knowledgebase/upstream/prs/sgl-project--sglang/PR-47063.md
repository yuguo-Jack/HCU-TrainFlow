# [Fix] disaggregation: Agree on each decode KV transfer's outcome across PP stages

[Upstream PR](https://github.com/sgl-project/sglang/pull/47063) · state: closed · merged: True

## Original PR description

## Motivation

Decode-side counterpart of #47045.

With pipeline parallelism on a **PD-disaggregated decode** server (`--disaggregation-mode decode --pp-size N`, N > 1), each PP stage receives the KV of **its own layers** through its own `kv_receiver`. The release consensus in `event_loop_pp_disagg_decode` (`_pp_pd_get_decode_transferred_ids` -> ring -> `process_decode_transfer_queue` -> `pop_transferred(rids_to_check)`) only agrees on **which** transfers have concluded (`KVPoll.Success` or `KVPoll.Failed`). Each stage then concludes the request from its own local poll:

| local poll | what the stage does |
|---|---|
| `Success` | commits the KV, admits the request to `waiting_queue` |
| `Failed` | aborts the request, releases its KV, streams a 500 |

A prefill abort that lands after the first prefill stage finished sending (the race #47045 describes) fails only the later decode stages. Decode stage 0 polls `Success`, stages 1..N-1 poll `Failed`. Both count as "concluded", so the consensus passes, and then:

1. Stage 0 admits the request to its waiting queue; the later stages abort it. The stages now schedule **different decode batches**, which PP cannot survive.
2. On top of that, `process_decode_transfer_queue` forwards only the rids a stage **admitted** to the next stage. A rid that failed on stage k is never forwarded to stages k+1..N-1, and since stage k has already dropped it from its transfer queue it can never re-enter the ring consensus either. The later stages hold the request, its KV pages and its metadata slot forever.

## Modifications

- `scheduler_pp_mixin._pp_pd_get_decode_transferred_ids` now returns `{rid: failed}` instead of a list of rids. The concluded set is still the intersection over stages; the failure flag is OR-ed along the ring, so **a failure on any stage concludes the transfer as failed on every stage**. The dict keeps the membership semantics of `rid in rids_to_check`, so the ring code that forwards it is unchanged.
- `DecodeTransferQueue.pop_transferred_with_outcomes(rids_to_check)` concludes each consensus rid with the consensus outcome rather than this stage's own poll, and returns `{rid: failed}` for every request it concluded (admitted, failed, or released as aborted). `pop_transferred` is a thin wrapper that keeps the old return value for the non-PP loop.
- `process_decode_transfer_queue` forwards those outcomes to the next stage instead of the admitted rids only, so a failure on stage k reaches stages k+1..N-1 and they retire the request through the same failure path.
- The outcome is recorded with `rank_consensus_checker.assert_same`, a no-op unless `SGLANG_ENABLE_RANK_CONSENSUS_CHECKER` is set.
- Non-PP decode (`rids_to_check is None`) and the prefill side are untouched.

A stage whose own receiver succeeded but learns another stage failed takes the normal failure path: `failure_exception` raises `is_from_another_rank=True` (debug log only), the fully written pages are released, and stage 0 returns the transfer error to the client instead of admitting a request the other stages cannot decode.

## Accuracy Tests

N/A. There is no model-output change on the success path. On the race path the request is now failed on every stage; it was already failed on the later stages before this change.

## Speed Tests and Profiling

No measurable cost: one extra boolean per concluded rid in the existing per-iteration consensus message, and one dict instead of a list down the release chain.

Unit tests (`test/registered/unit/managers/test_pp_decode_transfer_outcome.py`) cover the ring OR semantics, the forced failure path on a stage whose own receiver succeeded, the outcome forwarding, and the unchanged non-PP return value. The existing decode transfer queue tests (`test_decode_queue_cleanup`, `test_deferred_decode_kv_release`, `test_disagg_idle_step_counters`) pass unchanged.
