# [Fix] [XPU] docker: install oneCCL 2022.1.2 graph-mode runtime set

[Upstream PR](https://github.com/sgl-project/sglang/pull/46605) · state: closed · merged: False

## Original PR description

Temporary until torch's XPU wheel pins oneCCL >= 2022.1.2.

## Motivation

On XPU with TP > 1, decode graphs produce garbage output in the published image. torch 2.14.0+xpu pins oneCCL 2022.1.1, whose collectives fail when called under XPU graphs. Every rank logs, from warm-up on:

```
|ERROR| [__safe_call_impl:51] [onecclAllReduce] caught std::exception: ext_oneapi_get_graph() can only be called on recording queues.
```

The exception is swallowed and the all-reduce does not run, so the ranks never sum their partials.

Reproduced with `lmsysorg/sglang:v0.5.22-xpu`, Llama-3.3-70B-Instruct, TP=8 on 8x Arc Pro B60, `--cuda-graph-backend-decode full --cuda-graph-backend-prefill disabled`:

| | image as published (oneCCL 2022.1.1) | same flags, conda env with the oneCCL 2022.1.2 set |
|---|---|---|
| greedy "The capital of France is" | `acreoooé ? ? ?crecrecre ... in in in in` | `a city of love, art, fashion, and cuisine. Paris, ...` |
| oneCCL errors in the server log | ~14,800 | 0 |
| output throughput | 500 tok/s (invalid) | 419 tok/s |

This is likely the root cause of #45034 (TP ranks diverge on graph replay), where the proposed workaround is to disable decode graphs for TP > 1.

## Change

**Temporary workaround.** Remove this layer once SGLang's XPU build pins a torch whose XPU wheel already requires oneCCL >= 2022.1.2: torch 2.14.0 and the 2.15 nightlies pin 2022.1.1, the 2.16 nightlies pin 2022.1.2 / PTI 1.1.0.

vLLM made the same change when it moved to torch 2.14, in vllm-project/vllm#56013 (v0.31.0 and later):

- `docker/xpu.Dockerfile`: the package block after the last package install, as in vLLM's [`docker/Dockerfile.xpu`](https://github.com/vllm-project/vllm/blob/v0.32.0/docker/Dockerfile.xpu).
- `docs/docs/hardware-platforms/xpu.mdx`: the same set appended to *Install From Source*, and a short note under *XPU Graph* on the TP > 1 requirement.

Unlike vLLM's image, ours builds on `intel/deep-learning-essentials`, whose system oneAPI runtime (2026.1.0) is on `LD_LIBRARY_PATH` ahead of the venv. With only the package upgrade, the venv's `libsycl.so.9` (2026.1.1) resolves the system `libur_loader` and torch fails to import (`undefined symbol: urGraphGetIdExp`), so the venv's `lib` is prepended to `LD_LIBRARY_PATH`.


## Validation

Image built from this Dockerfile (sglang `main` 316ff4dce2), same setup as above, sonnet 1024/1024 at 32 concurrent requests:

| | `v0.5.22-xpu` as published, decode graphs | this PR, decode graphs | this PR, eager |
|---|---|---|---|
| greedy "The capital of France is" | `acreoooé ? ? ?crecrecre ...` | `a city of love, art, fashion, and cuisine. Paris, the City of Light, ...` | same as decode graphs |
| oneCCL errors in the server log | ~14,800 | 0 | 0 |
| decode batches on XPU graph | 127/127 | 127/127 | 0/127 |
| output throughput | 500 tok/s (invalid) | 419.1 tok/s | 408.9 tok/s |
| mean TPOT | 59.8 ms (invalid) | 72.1 ms | 74.0 ms |
