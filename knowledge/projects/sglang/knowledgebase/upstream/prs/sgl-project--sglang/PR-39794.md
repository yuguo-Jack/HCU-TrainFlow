# fix(weight-cache): reject routed MXFP4 experts for IPC

[Upstream PR](https://github.com/sgl-project/sglang/pull/39794) · state: closed · merged: False

## Original PR description

## Motivation

Closes #39762.

DeepSeek-V4 checkpoints with MXFP4 routed experts can report fp8 as their base quantization method. The IPC admission gate therefore accepts them even though the routed-expert tensors require unsupported post-load processing, and import later fails with 172 shape/dtype mismatches.

## Modifications

- Extend the IPC support check with the model-level is_fp4_experts layout flag.
- Pass that flag through both client and daemon admission paths so the model fails before daemon/cache access.
- Report the routed-expert MXFP4 layout explicitly in UnsupportedQuantForIPCError.
- Make the later mismatch diagnostic acknowledge a post-load layout that may have bypassed the base-method gate.
- Add regression coverage proving that a supported FP8 base configuration is still rejected when routed experts use MXFP4.
