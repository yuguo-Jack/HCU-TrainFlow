# [Fix] diffusion: MiniMax-H3 warms up at the short edge --warmup-resolutions names

[Upstream PR](https://github.com/sgl-project/sglang/pull/47583) · state: closed · merged: True

## Original PR description

## Motivation

`MiniMaxH3SamplingParams._synthetic_warmup_target` takes only the aspect ratio from `--warmup-resolutions` and always warms up at the 768 short edge. The flag is meant to name the canvas the server will serve, so this has two effects:

- **32 GB recipe.** The cookbook passes `--warmup-resolutions 864x480`, so warmup runs at a 768 short edge: a larger canvas than the server serves, on the tightest card.
- **544x960 workload.** A server deployed for the common 544x960 workload (`--warmup-resolutions 960x544`) still warms at 768, so its first real request pays the first-shape cost.

## Modifications

- `configs/sample/minimax_h3.py`:
  - When `--warmup-resolutions` is set, the warmup target's `short_edge` is `min(width, height)` of that resolution.
  - The aspect-ratio and duration handling are unchanged.
  - Without the flag, the warmup is still 768 / 16:9 / 5 s.
- `test_minimax_h3_admission.py`: the warmup expectations follow the named canvas: 832x464 now warms at 464, 864x480 at 480, and 960x544 at 544.

## Accuracy Tests

No numerical change. Only the shape of the synthetic warmup request changes.

## Speed Tests and Profiling

- **Steady state is not affected.** Warmed request latency on the 544x960 workload is the same either way. Our benchmark sends 3 warmup requests at the target shape before timing, so it masks the difference. The workload runs at 56.6 s on 1x H200 and 27.6 s on 1x B200.
- **First-request latency is not measured.** This change is meant to move the first-shape cost into warmup, and that first-request latency has not been measured separately.
