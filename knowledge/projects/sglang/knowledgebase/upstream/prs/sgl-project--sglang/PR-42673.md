# [gRPC] Move runtime.v1 bindings to tonic 0.14, report OpenAI status codes, return text on request

[Upstream PR](https://github.com/sgl-project/sglang/pull/42673) · state: closed · merged: True

## Original PR description

`experimental/sgl-router` is adding native gRPC (`sglang.runtime.v1.SglangService`). It already uses tonic/prost 0.14 through `sgl-kv-indexer`. This PR moves `sglang-grpc-types` to the same stack so the router can depend on the crate directly.

## Changes

- **Version bump:** the `rust/` workspace moves from tonic 0.12 / prost 0.13 to tonic 0.14.6 / prost 0.14.4, with codegen through `tonic-prost-build`. The pins match the router's lockfile, so the two share one stack. The `sglang-grpc` and `sglang-server` sources didn't need any changes.
- **`OpenAIStreamChunk.status_code`:** a new optional field, filled on the finished chunk of a non-streaming OpenAI RPC. Before this, a non-streaming `ChatComplete` that failed validation (for example a 400 for an over-long prompt) reached gRPC clients looking the same as a 200.

- **`Rerank` serialization (from #42680):** the native gRPC `Rerank` always failed with "Object of type RerankResponse is not JSON serializable". The bridge now encodes dict and list results with `jsonable_encoder`, as FastAPI does for the HTTP route.

- **Opt-in text from `Generate`:** `GenerateRequest.return_text` and `GenerateResponse.text`, in both the Python-backed server and the Rust adapter.
  - The engine already detokenizes every `Generate` request (HTTP `/generate` returns the text); this returns that text only to callers that ask for it.
  - A router can then tokenize a `TextGenerate` prompt once and call `Generate`, without detokenizing in the router.
  - Existing `Generate` replies are unchanged, so no traffic is added. In the default cumulative streaming mode, always sending text would roughly double the per-stream payload.

- **`Abort` by rid:** the native `Abort` RPC forwarded to the runtime only for ids of streams the bridge itself tracks, and still replied `success`. OpenAI RPCs run under their body's rid, so aborting them by rid silently did nothing. Every abort now reaches the runtime, as HTTP `/abort_request` does.

## Tests

- `cargo test --workspace` in `rust/` passes.
- Real engine: `Abort(rid)` on a running request now stops it after 1.5 s with `finish_reason: abort`. Before, it ran to `length`. The adapter's `generate` stream test now covers `return_text`.
- A new unit test in `test_grpc_bridge.py` covers the `Rerank` fix: it fails without the fix and passes with it.
- Real engine (Qwen3-4B, one B200, `--grpc-port`): a non-streaming `ChatComplete` returns `status_code=200`, an over-long prompt returns `status_code=400`, and streaming chunks carry no status. A real Qwen3-Reranker-0.6B engine's gRPC `Rerank` now returns exactly the HTTP body.
