# [Fix] metrics: Do not count prompt tokens of requests aborted before forward

[Upstream PR](https://github.com/sgl-project/sglang/pull/45136) · state: open · merged: False

## Original PR description

## Motivation

`TokenizerManager.collect_metrics` adds the full prompt length to `sglang:prompt_tokens_total` for every finished request, including requests that were aborted before any forward pass. In PD disaggregation this happens on every bootstrap failure and every KV transfer failure, including the decode-side aborts triggered by client disconnects while the request is still in the prealloc or transfer queue. These requests processed no prompt tokens, and their `cached_tokens` is 0.

As a result, under an abort storm `prompt_tokens_total` is inflated while `cached_tokens_total` is not. Any uncached-token figure derived as `prompt - cached` is inflated too, and so is the apparent prefill load.

We have also implemented early rejection, which rejects a request at admission when its predicted TTFT exceeds a threshold, and plan to upstream it. Without this fix, every rejected request would add its full prompt length to `prompt_tokens_total` even though it never runs, which makes the metric noticeably too high.

## Modifications

- `collect_metrics`: when a finished request has `finish_reason.type == "abort"` and the scheduler never set its `forward_entry_time`, report 0 prompt tokens. The scheduler time stats are already part of every batch output, so this adds no new IPC fields and needs no scheduler changes.
- Requests aborted after entering forward, as well as normal completions, are counted as before. If time stats are unavailable, the previous behaviour is kept.
- `num_requests_total` and the e2e latency histogram are unchanged and still count every finished request.
- Added `test/registered/unit/managers/test_tokenizer_manager_abort_prompt_tokens.py`. It covers an abort before forward, an abort after forward, a normal finish, and the missing-time-stats fallback.

How aborted requests are counted after this change:

| Case | Prompt tokens counted |
|---|---|
| PD prefill bootstrap failure | 0 (was: full prompt) |
| PD decode KV transfer failure, including `SGLANG_DISAGGREGATION_WAITING_TIMEOUT` and client disconnects during prealloc/transfer | 0 (was: full prompt) |
| Aborted while running, including `SGLANG_REQ_RUNNING_TIMEOUT` (requires `forward_entry_time > 0`) | full prompt (unchanged) |
| PD prefill KV transfer failure after the forward pass | full prompt (unchanged) |
| Invalid input or grammar failure (`set_finish_with_abort` shrinks the input to one token and runs one forward) | 1 (unchanged) |
| Aborted in the waiting queue, including `SGLANG_REQ_WAITING_TIMEOUT` | not counted; these are answered with `AbortReq` through `_handle_abort_req` and never reach `collect_metrics` (unchanged) |
