# [Fix] metrics: Do not count prompt tokens of requests aborted before forward

[Upstream PR](https://github.com/sgl-project/sglang/pull/45136) · state: open · merged: False

## Original PR description

## Motivation

> **Scope question for reviewers:** `realtime_tokens_total` already answers "how much the server forwarded". This change only removes requests that never reached a forward pass from `prompt_tokens_total` and the prompt-length histograms; what remains is the prompt-side volume of requests the service actually handled. It also keeps `prompt - cached` and `uncached_prompt_tokens_histogram` correct. Please confirm whether `prompt_tokens_total` should count aborted requests at all: if that is the intended semantics and this PR is not taken, `prompt_tokens_total` and `cached_tokens_total` no longer describe the same population, and any `prompt - cached` figure derived from them is inflated.

`TokenizerManager.collect_metrics` adds the full prompt length to `sglang:prompt_tokens_total` for every finished request, including requests that were aborted before any forward pass. In PD disaggregation this happens on every bootstrap failure and every KV transfer failure, including the decode-side aborts triggered by client disconnects while the request is still in the prealloc or transfer queue. These requests processed no prompt tokens, and their `cached_tokens` is 0.

As a result, under an abort storm `prompt_tokens_total` is inflated while `cached_tokens_total` is not. Any uncached-token figure derived as `prompt - cached` is inflated too, and so is the apparent prefill load.

We have also implemented early rejection, which rejects a request at admission when its predicted TTFT exceeds a threshold, and plan to upstream it. Without this fix, every rejected request would add its full prompt length to `prompt_tokens_total` even though it never runs, which makes the metric noticeably too high.

## Modifications

- `collect_metrics`: a finished request with `finish_reason.type == "abort"` and no `forward_entry_time` from the scheduler is passed to `observe_one_finished_request` with `count_tokens=False`. The scheduler time stats are already part of every batch output, so no new IPC fields and no scheduler changes are needed.
- `observe_one_finished_request` gates `prompt_tokens_total`, `generation_tokens_total`, `cached_tokens_total` and the three length histograms on that flag. They are skipped entirely rather than observed as 0, so `prompt_tokens_histogram_sum / _count` stays an exact mean prompt length.
- Requests aborted after entering forward, and normal completions, are unchanged. Without time stats the previous behaviour is kept.
- `num_requests_total`, the e2e latency histogram and TPOT are unchanged and still cover every finished request.
- No longer derived from `prompt_tokens_total` / `num_requests_total`: that ratio stops being a mean prompt length once the two counters have different populations. Use `prompt_tokens_histogram_sum / prompt_tokens_histogram_count` instead.

`realtime_tokens_total` cannot replace this. It is accounted per admission (and per chunk under chunked prefill) rather than per request, does not separate prompt from generation per request, and cannot be joined with `cached_tokens_total` or `num_requests_total`.

| Case | Prompt tokens counted |
|---|---|
| PD prefill bootstrap failure | 0 (was: full prompt) |
| PD decode KV transfer failure, including `SGLANG_DISAGGREGATION_WAITING_TIMEOUT` and client disconnects during prealloc/transfer | 0 (was: full prompt) |
| Aborted while running, including `SGLANG_REQ_RUNNING_TIMEOUT` (requires `forward_entry_time > 0`) | full prompt (unchanged) |
| PD prefill KV transfer failure after the forward pass | full prompt (unchanged) |
| Invalid input or grammar failure (`set_finish_with_abort` shrinks the input to one token and runs one forward) | 1 (unchanged) |
| Aborted in the waiting queue, including `SGLANG_REQ_WAITING_TIMEOUT` | not counted; these are answered with `AbortReq` through `_handle_abort_req` and never reach `collect_metrics` (unchanged) |
