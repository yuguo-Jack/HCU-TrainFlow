# [Feat] nemotron-asr: Nemotron 3.5 ASR (RNN-T) transcription

[Upstream PR](https://github.com/sgl-project/sglang/pull/46746) · state: closed · merged: False

## Original PR description

## Motivation

[nvidia/nemotron-3.5-asr-streaming-0.6b](https://huggingface.co/nvidia/nemotron-3.5-asr-streaming-0.6b) is a 0.6B multilingual ASR model (FastConformer encoder + RNN-T decoder, ~35 languages). Transformers supports it as `Nemotron3_5AsrForRNNT`; vLLM serves it through an out-of-tree plugin. This adds complete-audio transcription in SGLang through `/v1/audio/transcriptions`. Cache-aware realtime streaming is out of scope.

## Modifications

**How RNN-T maps onto the engine.** RNN-T emits zero or more tokens per encoder frame, so one engine decode step cannot be one model step. Each forward instead advances every request to its *next non-blank token* and returns logits that admit only that token, so the sampler keeps it whatever the sampling settings. When the audio runs out the model emits blank, which the config declares as EOS.

- `models/nemotron3_5_asr.py`: the encoder, prediction network and joint are transformers' modules, as GLM-ASR and Qwen2-Audio do. `RNNTDecodeState` holds per-request state (LSTM h/c, frame pointer, symbols-at-frame, encoder frames) indexed by `req_to_token_pool` slot. `predict` scans to the next token without consuming it; on the next step `commit` feeds the token the engine actually sampled back into the LSTM. A re-prefilled (retracted) request replays its emitted tokens. The KV cache is a 1-layer placeholder that is never written.
- **Speed**
  - New requests are encoded in one padded batch.
  - The encoder replays a CUDA graph captured per (batch, mel frames) bucket (`multimodal/nemotron_asr_encoder_cuda_graph_runner.py`), following the ViT graph runners. On an A6000 the eager encoder takes ~70 ms of wall time for ~9 ms of GPU work.
  - While a request skips blanks its decoder state is fixed, so the joint scores a window of frames per call (8, doubling for rows still scanning) instead of one frame per call.
- **Config** (`configs/nemotron3_5_asr.py`): the transformers config plus the text-model fields the engine reads, `eos_token_id = blank`, and an 8192 context.
- **Model overrides**
  - CUDA graphs and the radix cache are disabled.
  - Attention defaults to Triton, so no kernel is JIT-built for the placeholder shape.
  - `max_total_tokens` defaults to 2^20 (`max_total_tokens` is now `resolvable=True`, pinned in `test_model_overrides.py`). With a pool sized by memory, the placeholder's tiny per-token footprint yields ~10^8 slots, and buffers sized by token count no longer fit: the server OOMs at startup with default flags.
- **Processor and adapter**: `language` (ISO 639-1 or locale; a bare code falls back to its only locale, e.g. `th` to `th-TH`) selects the model's language prompt; without it the model detects the language. Audio over 30 s is split by the existing energy-aware chunker; the adapter restores the word boundary decoding drops at each chunk start.
- **Tokenizer**: `ParakeetTokenizer.decode` merges consecutive duplicate ids by default (a CTC convention). That turned "yeah yeah" into "yeah" here, so SGLang now decodes with `group_tokens=False`. Generated ids are already final.
- **Docs**: a row in the audio transcription table. The model needs `librosa` (its feature extractor uses it), like the existing Parakeet audio path.

## Accuracy Tests

Greedy transcripts compared with transformers' `Nemotron3_5AsrForRNNT.generate` on 5 clips (English and Chinese, 4–15 s), A6000:

| Server dtype | Matching transcripts vs transformers at the same dtype |
|---|---|
| float32 | 5/5 token-identical; also 50/50 with 50 concurrent requests (prefill batches up to 18, padded) |
| bfloat16 | 5/5 token-identical |
| float16 (default for this fp32 checkpoint) | 5/5 within one comma of fp32 |

- `test/registered/unit/models/test_nemotron3_5_asr.py` (CPU) checks the per-slot state machine against transformers' greedy RNN-T on a tiny random model: single requests, staggered batches on non-contiguous slots, re-prefill mid-request, and steps after end of audio. Each case was confirmed to fail when its guarded behavior is removed (no forced frame advance, no replay, frame offsets dropped, tokenizer fix dropped).
- `test/manual/models/test_nemotron3_5_asr.py` (GPU, needs librosa; manual like the Qwen3-ASR test) covers transcripts vs transformers, batched vs sequential, the language prompt, and long-audio chunking.

## Speed Tests and Profiling

RTFx (seconds of audio per wall second), 5 clips of 4–15 s, fp16, A6000 on a 6-core host. SGLang requests arrive continuously at a fixed concurrency; the transformers baseline is pre-batched `generate`. Run-to-run noise is about ±10%.

| Concurrency / batch | SGLang RTFx (p50 latency) | transformers RTFx |
|---|---|---|
| 1 | 17.2 (712 ms) | 15.4 |
| 8 | 92.6 (1.0 s) | 80.1 |
| 32 | 180–197 (1.9 s) | 223 |
| 128 | 299–315 (4.5 s) | 326 |
| 256 | 336–384 (7.7 s) | — |

At high load this host's 6 CPU cores are saturated: the HTTP/tokenizer process uses ~2.3 cores and the scheduler ~1. Single-stream decode is ~9 ms/step: ~5 ms engine overhead without CUDA graphs, ~4 ms in the RNN-T step.

### LibriSpeech test-clean: SGLang vs transformers vs NVIDIA NeMo

2,620 utterances (5.4 h), `language` = en-US for all three, lookahead 3 frames (NeMo's default `att_context_size=[56,3]`, the processor default here). Corpus WER after the Whisper English normalizer used by the Open ASR Leaderboard. A6000, 6-core host. NeMo is `ASRModel.transcribe()` from NeMo `main` (3.1.0) on the official `.nemo`, offline, inputs sorted by length; transformers is batched `generate`; SGLang is `/v1/audio/transcriptions` over HTTP at a fixed concurrency.

| System | Precision | Batch / concurrency | WER | RTFx |
|---|---|---|---|---|
| NeMo `transcribe()` | fp32 | batch 32 | 3.306% | 382 |
| NeMo `transcribe()` | fp32 | batch 128 | 3.306% | 432 |
| NeMo `transcribe()` | bf16 autocast | batch 32 | 3.312% | 536 |
| NeMo `transcribe()` | bf16 autocast | batch 128 | 3.325% | 669 |
| NeMo `transcribe()` | fp16 autocast | batch 128 | 3.323% | 603 |
| transformers | fp32 | batch 32 | 3.310% | 208 |
| transformers | fp16 | batch 32 | 3.315% | 262 |
| SGLang (this PR) | fp16 (default) | 64 concurrent | 3.340% | 229 |
| SGLang (this PR) | fp16 (default) | 128 concurrent | 3.319% | 321 |
| SGLang (this PR) | fp16 (default) | 256 concurrent | 3.334% | 423 |
| SGLang (this PR) | fp32 | 256 concurrent | 3.330% | 247 |

- **Accuracy:** all three agree within 0.04 points. In fp32, SGLang and transformers transcripts differ (after normalization) on 16 of 2,620 utterances, and transformers and NeMo on 10. That is near-tie argmaxes moving with batch padding.
- **Speed:** SGLang is ~1.6x transformers but ~1.6x behind NeMo's offline bf16 batch. NeMo sees the whole dataset up front, length-sorts it into full batches, and graph-captures its greedy RNN-T loop. SGLang additionally pays per request for HTTP upload, audio decoding and IPC; on this 6-core host the HTTP/tokenizer process uses ~2.3 cores and the scheduler ~1 at 256 concurrent.

**Known limits / follow-ups**
- No CUDA graph for the decode step (the blank scan is data-dependent); NeMo's graph-captured greedy loop is the reference for closing the gap above.
- A request that stops before end of audio (token limit, abort) keeps its encoder frames until its slot is reused.
- No cache-aware streaming.
