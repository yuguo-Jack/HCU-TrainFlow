# [Model] Add experimental FlashLoop lazy updates for Ouro

[Upstream PR](https://github.com/sgl-project/sglang/pull/41485) · state: closed · merged: False

## Original PR description

## Motivation

Looped Transformers share parameters across recurrent traversals, but each traversal can still repeat computation and KV-cache traffic. **FlashLoop exploits recurrence as a distinct redundancy axis**, using **lazy updates** to reuse stable state and selectively refresh the state that changes.

This draft proposes an opt-in native SGLang implementation for Ouro, with three independently configurable components.

Paper: [FlashLoop: Fast and Memory-Efficient Looped Transformers via Lazy Updates](https://arxiv.org/abs/2609.29812)  
Reference project: [Superone77/FlashLoop](https://github.com/Superone77/FlashLoop)

## Method

### 1. Token-sparse updates

During prefill, rank tokens by their relative hidden-state change across recurrences. The later loops compute QKV projections and MLP updates only for nested active-token sets, while inactive hidden states and KV rows reuse the preceding loop's state. The last token of each request is retained, and attention preserves the original causal positions.

### 2. Sparse attention

During decode, the second loop supplies a reference attention output and selects keys for later-loop updates. We cache the selected keys' probability mass and their contribution to the output. Later loops recompute that selected contribution and combine it with the cached complement:

```text
new output ≈ reference output
             − reference contribution of selected keys
             + reference mass of selected keys × updated attention over selected keys
```

This preserves the reference contribution outside the selected set rather than renormalizing attention over a pruned cache alone.

### 3. KV-residual quantization

Represent recurrent KV state using an INT4 anchor and packed cross-loop residual streams. K quantization groups span tokens; V groups span channels. Attention readers reconstruct only the requested tiles directly from the packed representation. A rolling BF16 tail handles newly generated tokens, and explicit zero-residual flags preserve inactive prefill rows.

The pool includes packed data, quantization metadata, residual flags, and per-request tails in its capacity accounting. It does not retain a full BF16 shadow cache.

## Modifications

- Add an explicit `flashloop` config parser and native `FlashLoopOuroForCausalLM` model, preserving shared weights with separate logical KV layers.
- Add paged token selection, cached-mass attention correction, packed KV writers and direct Triton readers.
- Integrate the compressed pool through the current KV pool/configurator factories, without the standalone prototype's scheduler monkey patches.
- Expose the components independently through `--json-model-override-args`:

```json
{
  "flashloop_components": {
    "token_sparse_prefill": true,
    "sparse_decode": true,
    "kv_residual_quantization": true
  },
  "flashloop_prefill_fractions": [0.25, 0.1],
  "flashloop_decode_fraction": 0.1
}
```

Each component can be disabled independently. With the explicit parser and no component override, the model uses dense execution. Existing models and the default config parser are unchanged.

- Add CPU configuration tests, manual CUDA numerical tests, and a method/usage guide in `examples/flashloop/README.md`.
- Preserve the originating FlashLoop MIT license notice.

## Current scope and draft status

The proposed path targets NVIDIA CUDA, BF16 compute, four-loop Ouro, and single-rank execution. Prefix reuse, chunked prefill, overlap scheduling, prefill CUDA graphs, speculative verification, and offload are outside this draft. Later-loop packed residual pages are not yet compacted by active-token count.

The standalone implementation was developed against SGLang 0.5.14. This patch adapts it to the current upstream configuration and cache interfaces; current-main end-to-end validation remains pending. Feedback on the model-specific pool integration and configuration surface would be useful before marking this PR ready.
