# [Perf] logits: Cast bf16 logits into the fp32 buffer with a Triton kernel

[Upstream PR](https://github.com/sgl-project/sglang/pull/46167) · state: closed · merged: True

## Original PR description

## Motivation

When a model's lm_head returns bf16 logits and the forward has a shared fp32 logits buffer (CUDA graph decode, speculative verify), `_copy_logits_to_buffer` fills the buffer with `logits_buffer.copy_(logits)`. On Blackwell this dtype-casting copy runs well below memory bandwidth, and at speculative-verify batch sizes (many rows x a full vocabulary) it shows up as one of the larger single kernels of a decode step.

## Modifications

- `softcap.py`: `softcap_inplace_logits_kernel` gains an `APPLY_SOFTCAP` constexpr; the new `cast_to_float32_logits(logits, output)` uses the same launcher without the softcap.
- `activation/__init__.py`: register `activation.cast_to_float32_logits` next to `softcap_to_float32_logits`.
- `logits_processor.py`: in the buffered branch of `_copy_logits_to_buffer`, CUDA fp16/bf16 logits are written by the new kernel; fp32 logits and the unbuffered path are unchanged.

No numerical change: the fp16/bf16 to fp32 conversion is exact, and the buffer contents are byte-identical to the `copy_` result.

## Verification

- Byte-identical fp32 buffer against `copy_` for bf16 and fp16 inputs, contiguous and vocab-padded (sliced) layouts, at several row counts, with inf, NaN, -0.0 and tied maxima in the inputs; argmax of the buffer unchanged.
- `test/registered/rl/test_fp32_lm_head.py` passes on GB300 (covers the buffered path, vocab slicing, softcap and CUDA graph replay).
- Micro benchmark of `_copy_logits_to_buffer` at speculative-verify shapes on GB300 under CUDA graphs: faster at every size tested.
