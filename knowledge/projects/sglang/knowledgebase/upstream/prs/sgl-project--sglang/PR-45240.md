# [Feat] [NVIDIA] diffusion: Enable fp8_fa_sm120 attention on SM89

[Upstream PR](https://github.com/sgl-project/sglang/pull/45240) · state: open · merged: False

## Original PR description

## Motivation

Part of the consumer-GPU item in #43313 ("FP8 attention ... on SM89/SM120"). `fp8_fa_sm120` is gated to compute capability `(12, 0)`, so RTX 40 / L4 / L40S users get cuDNN SDPA in BF16 even when they select it. The kernel itself has nothing SM120-only:

- FP8 `mma.sync.m16n8k32` (E4M3, FP32 accumulate) and `cp.async` loads, no TMA, no `wgmma`, no tcgen05;
- 32 KB of static shared memory per 128-thread CTA, below the 48 KB static limit and well inside SM89's 100 KB;
- since #43390 the block-scaled MMA is selected only for `sm_120a/f` and `sm_121a/f` (`_block_scaled_mma_supported()`); every other target keeps the plain `MmaFP8Op`, which Ada has.

So on SM89 the kernel compiles and runs unchanged. It needs `nvidia-cutlass-dsl` 4.8.0, which `python/pyproject.toml` already pins; with 4.6.2 NVVM rejects it for `sm_89`.

SageAttention (`sage_attn`) also runs on SM89, and on an RTX 4090 it is faster and more accurate than this kernel (numbers below). The case for this backend on SM89 is that it ships with SGLang: SageAttention 2 has no wheel for the current torch 2.14 / CUDA 13 stack and only builds from source after a patch (details below).

Depends on #45239 (the backend could not load a model built on the meta device); this branch carries that commit until it merges.

## Modifications

- `runtime/platforms/cuda.py`: `FP8_FA_SM120_CAPABILITIES = frozenset({(8, 9), (12, 0)})`, used by the resolver as `supported_capabilities` (same pattern as `VSA_H3_CAPABILITIES`). Warning text updated.
- `fp8_fa_sm120_attn.py`: the per-call fallback check uses the same set, so the startup gate and the per-call gate cannot drift. Docstring updated.
- `test_fp8_fa_sm120_attn.py`: runs on SM89 and SM120. `test_block_scaled_mma_is_bit_equal` skips where `_block_scaled_mma_supported()` is false: there both calls would run the plain MMA and the comparison would prove nothing.
- `attention_backends.mdx`: SM89 support and the cutlass-dsl requirement.

The backend name and enum stay `fp8_fa_sm120`; it remains opt-in, and no default changes.

## Accuracy Tests

Unit tests (`test_fp8_fa_sm120_attn.py`), all with cutlass-dsl 4.8.0, torch 2.14.1+cu130:

| GPU | passed | skipped |
|---|---:|---:|
| L4 (sm_89) | 9 | 1 (bit-equality) |
| RTX 4090 (sm_89) | 10 | 1 (bit-equality) |
| L40S (sm_89) | 10 | 1 (bit-equality) |

The 10th test on the 4090 and L40S is the meta-device regression test from #45239. I have no SM120 card to run the edited skip there; @emre570, could you run the suite on your RTX 5080?

Operator accuracy against FP32 SDPA, same on every shape below: relative RMS 0.053 to 0.054, cosine 0.9985 to 0.9986 (the unit-test gates are 0.08 and 0.995). For comparison, `sage_attn` on the same inputs: relative RMS 0.038 to 0.039, cosine 0.9992 to 0.9993.

End to end, MiniMax-H3 on one RTX 4090 (24 GB) with the single-RTX-4090 cookbook recipe (BF16 weights, layerwise offload), `t2va` 1344x768, 5 s (124 frames), 50 steps, seed 42. All three runs on the same pod, changing only `--attention-backend`; the `torch_cudnn_sdpa` row is the BF16 noise floor of this setup:

| pair | SSIM mean / worst frame | PSNR mean / worst frame |
|---|---|---|
| `torch_cudnn_sdpa` vs `fa` (BF16 noise floor) | 0.810 / 0.791 | 22.2 / 20.8 dB |
| `fp8_fa_sm120` vs `fa` | 0.703 / 0.676 | 13.4 / 12.0 dB |
| `fp8_fa_sm120` vs `torch_cudnn_sdpa` | 0.692 / 0.665 | 13.2 / 11.8 dB |

`t2va` in this setup is very sensitive: swapping one BF16 kernel for another already moves the video to SSIM 0.81, far from the 0.987 kernel-swap floor in #43433 (an `fl2va` run on SM120). FP8 still sits about 0.11 SSIM / 9 dB PSNR below that floor, and an L40S run of the same recipe gave the same 0.703 against `fa`, so this is the quantization effect, not SM89: the kernel error per call matches SM120, and a few H3 layers with peaked scores lose too much to per-head FP8 scaling. #43433 reports the same on SM120 (0.847 / 21.6 dB with every layer in FP8, 0.942 / 30.6 dB with four H3 layers kept in BF16). For H3 quality, combine this backend with #43433's `bf16_layers`.

## Speed Tests and Profiling

Operator, RTX 4090, head_dim 128, batch 1, non-causal, cold L2 (5x L2 flush between calls), full backend call including the Q/K/V quantization passes, against cuDNN SDPA (BF16):

| H | S | fp8_fa_sm120 (ms) | cuDNN (ms) | speedup |
|---:|---:|---:|---:|---:|
| 56 | 2048 | 0.70 | 0.84 | 1.20x |
| 56 | 4096 | 2.16 | 3.25 | 1.51x |
| 56 | 8192 | 6.97 | 11.84 | 1.70x |
| 56 | 16384 | 25.88 | 47.29 | 1.83x |
| 56 | 30272 | 86.21 | 161.54 | 1.87x |
| 56 | 60000 | 332.40 | 642.49 | 1.93x |
| 14 | 2048 | 0.17 | 0.23 | 1.32x |
| 14 | 30272 | 21.48 | 40.56 | 1.89x |

At S >= 16k the kernel runs at about 300 TFLOPS. On the much smaller L4 the speedup is 1.6x at S = 30k and FP8 only wins from S = 4096 at H = 56 (0.87x at 2048).

End to end, same RTX 4090 runs as above (GPU at full clocks, about 2.5 GHz / 415 W, in all three):

| | `fa` (BF16) | `torch_cudnn_sdpa` (BF16) | `fp8_fa_sm120` | fp8 vs `fa` |
|---|---:|---:|---:|---:|
| median denoise step | 22.93 s | 23.48 s | 18.08 s | 1.27x |
| denoise, 50 steps | 1147 s | 1176 s | 917 s | 1.25x |
| request total | 1218 s | 1212 s | 954 s | 1.28x |

On an L40S (power-capped at 350 W) the same recipe gave 1.14x per step and 1.19x per request (19.36 s vs 16.92 s median step). Only one call fell back (a causal attention); the joint video+text attention (S = 37721, H = 56) ran in FP8.

### Compared with SageAttention

Same RTX 4090, same harness (cold L2, full backend call, through each backend's `AttentionImpl`); `sage_attn` dispatches to `sageattn()`, which on SM89 runs INT8 QK and FP8 PV:

| H | S | fp8_fa_sm120 (ms) | sage_attn (ms) | cuDNN (ms) | sage_attn vs fp8_fa_sm120 |
|---:|---:|---:|---:|---:|---:|
| 56 | 2048 | 0.70 | 0.56 | 0.84 | 1.25x |
| 56 | 8192 | 6.98 | 5.27 | 11.89 | 1.32x |
| 56 | 16384 | 26.05 | 18.71 | 47.47 | 1.39x |
| 56 | 30272 | 87.14 | 60.74 | 162.49 | 1.43x |
| 56 | 60000 | 336.70 | 237.13 | 644.37 | 1.42x |
| 14 | 30272 | 21.62 | 15.20 | 40.72 | 1.42x |

The gap is the accumulator: GeForce Ada runs FP8 MMA with FP32 accumulation at half rate (about 330 TFLOPS on a 4090), and this kernel reaches about 305 TFLOPS with FP32 accumulation for both QK and PV. SageAttention computes QK in INT8 with INT32 accumulation and PV in FP8 with FP16 accumulation inside a tile, both full rate, and reaches about 430 TFLOPS. Moving PV to an FP16 accumulator on SM89 is a possible follow-up; it is not part of this PR.

SageAttention build used here: PyPI only has `sageattention` 1.0.6, so I built 2.2.0 from `thu-ml/SageAttention@d9704247` (the commit `attention_backends.mdx` points to) with `TORCH_CUDA_ARCH_LIST=8.9`. It fails against torch 2.14 headers (`C++20 or later compatible compiler is required`) until `-std=c++17` in its `setup.py` is changed to `-std=c++20`.

Scripts for the operator and end-to-end numbers: [bench_fp8_attn.py](https://github.com/DaniilKurlovich/sglang/blob/diffusion/fp8-fa-sm89-build/benchmark/diffusion_fp8_attn/bench_fp8_attn.py) on my fork; not part of this PR.
