# [CI] [Intel] release-whl-kernel-xpu: Activate the uv venv of the kernel image

[Upstream PR](https://github.com/sgl-project/sglang/pull/47749) · state: open · merged: False

## Original PR description

## Motivation

sgl-project/sgl-kernel-xpu#593 moves `Dockerfile.xpu_kernel` from Miniforge to a uv venv at `/opt/venv`, and sgl-project/sgl-kernel-xpu#594 moves the kernel repo's own workflows to match. sglang's XPU image and CI are moving to uv in #46519.

`release-whl-kernel-xpu.yml` builds that kernel Dockerfile from the kernel `release/vX.Y.Z` branch, then runs `. /miniforge3/bin/activate && conda activate py<ver>`. #46519 does not touch this file. The first kernel release branch cut after sgl-kernel-xpu#593 merges would fail at that line, and no wheel would be published.

## Changes

- Activate `/opt/venv` in place of the conda env.
- Assert that the active Python matches `matrix.python-version`, so a wrong env fails right away instead of producing a wheel for the wrong Python.

`scripts/build_rel_wheel.py` needs no change: it calls `sys.executable -m pip`, and the uv venv is created with `--seed`, so pip is present.

## Merge order

Merge after sgl-kernel-xpu#593 and before the first kernel release branch cut from it (`release/v0.6.0`). This is uv only, so releases from `release/v0.5.0` or older branches, which still build the conda image, can no longer be built with this workflow.

## Testing

- pre-commit passes.
- Ran the step's shell body (up to the wheel build) with `python-version=3.12`:
  - uv image built from sgl-kernel-xpu#593: `/opt/venv/bin/python`, Python 3.12.14, assert passes.
  - conda image `intel/sgl-kernel-xpu-dev:latest`: fails at once on `/opt/venv/bin/activate: No such file or directory`, as expected.
