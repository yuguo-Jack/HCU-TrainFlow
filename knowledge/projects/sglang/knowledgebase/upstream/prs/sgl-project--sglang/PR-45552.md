## Motivation

DeepEP v1 currently keeps a single process-wide buffer in `DeepEPBuffer` (`deepep_ep_state`). When the target and a speculative draft MoE share one process but use different expert configs (`num_experts` / `hidden_size` / `num_max_dispatch_tokens_per_rank`), the second model reuses the first buffer and can get a wrong size or QP layout.

Typical case: speculative decoding (e.g. DSpark) where the draft has fewer experts than the target, and both use DeepEP.

With no DSpark, or when DSpark and the target share the same key, behavior stays equivalent to the previous single-buffer path.

**Trade-off:** different target/draft keys mean multiple DeepEP buffers and thus higher GPU memory.

## Modifications

- Replace the single `deepep_ep_state` with a keyed `deepep_ep_registry` on `ctx.resources`
- Key each buffer by `(num_experts, hidden_size, num_max_dispatch_tokens_per_rank)`; allocate on miss, reuse on hit
- Log when allocating an additional buffer while other keys already exist (typical target + draft)
- Update `clean_buffer` / dispatch-mode transitions to operate over all registry entries
- Unit tests: update mode-transition / reset coverage; add multi-key (target vs draft) cleanup coverage
