# [Perf] [AMD] deterministic: Allow AITER prefill attention on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/45601) · state: open · merged: False

## Original PR description

## Motivation

In deterministic mode, prefill attention on ROCm runs on SGLang's Triton extend-attention kernel. At long inputs that kernel is most of the remaining cost of deterministic mode: on MI350X, Qwen3-8B at 32k input spends 9.3 s in Triton prefill attention vs 4.1 s in AITER's batch prefill per profiled window, two thirds of the gap to normal mode. #44489 lets deterministic mode use AITER for decode attention; this PR does the same for prefill.

AITER's batch prefill (`mha_batch_prefill_func`) is run-to-run deterministic, and a row's result does not depend on its batchmates, with two conditions found on MI350X (gfx950):
1. **`max_seqlen_q` must be the same in every call.** It sizes the launch, and the output depends on it; with `max_seqlen_q == 1` the wrapper also switches to a non-causal mask. SGLang passes the batch's longest extend, so a request's bits changed with its batchmates.
2. **Prompt splits must fall on multiples of 128 tokens**, the kernel's query tile. The same tokens computed as one extend, or as a cached prefix plus an extend, give the same bits only when the split point is a multiple of 128. Splits come from chunked prefill and from radix-cache hits.

This PR, in deterministic mode on gfx950, accepts `--prefill-attention-backend aiter` and meets both conditions: a fixed `max_seqlen_q`, and page size 128 so that radix-cache prefixes and chunk ends fall on the tile. With either condition missing, the checks below fail (see the control runs).

**Impact**
- Who: `--enable-deterministic-inference` with `--prefill-attention-backend aiter` on gfx950 (MI350X/MI355X), non-MLA models, bf16 KV cache, no speculative decoding.
- Effect: deterministic-mode throughput +9% at 8k input and +48% at 32k on Qwen3-8B; up to +73% at 32k on Qwen3-30B-A3B (tables below). Bitwise batch invariance, cached-prefix and chunk-boundary consistency hold.
- Page size: becomes 128 in this configuration unless already a multiple of 128 (with a warning); a `--chunked-prefill-size` that is not a multiple of 128 is refused.
- Exact chunk fill (gfx95, `SGLANG_EXACT_CHUNK_FILL`) is off in deterministic mode: it ends a chunk wherever the token budget runs out, off the page grid. With page size 1 this makes no difference to where chunks end.
- Refused, with an error naming the reason: other GPUs, MLA models, speculative decoding, an fp8 KV cache (not deterministic end to end in our tests yet; also when `--kv-cache-dtype auto` resolves to fp8 from the checkpoint's KV cache quantization), sliding-window models and the unified-attention / 5D-cache AITER paths (as for AITER decode in #44489).
- Unchanged: deterministic mode with Triton prefill (the default), and everything without `--enable-deterministic-inference`.

## Modifications

- `arg_groups/overrides.py`:
  - `_deterministic_attention_backend`: `--prefill-attention-backend aiter` is accepted in deterministic mode on gfx950 for non-MLA models without speculative decoding and with a bf16 KV cache; otherwise the error says why.
  - `_deterministic_aiter_prefill_page_size` (new pass, run in `handle_attention_backend_compatibility` next to the other page-size constraints): page size 128 unless already a multiple of it; a chunked-prefill size that is not a multiple of 128 raises.
- `layers/attention/aiter_backend.py`: in deterministic mode the batch prefill gets a fixed `max_seqlen_q` (the chunked-prefill size, or the context length without chunked prefill; never below the batch's longest extend), and aiter prefill on a resolved fp8 KV cache raises at startup. The existing deterministic guard now names aiter attention in general.
- `managers/schedule_policy.py`: no exact chunk fill in deterministic mode.
- `test/registered/unit/test_model_overrides.py`: the backend acceptance cases (gfx950, MLA, speculative decoding, KV-cache dtype) and the page-size pass.

## Accuracy Tests

MI350X, `rocm/sgl-dev:v0.5.22-rocm724-mi35x-20261020` (ROCm 7.2.4) with this branch's `python/sglang` (and #43788). Server:

```
SGLANG_USE_AITER=1 python3 -m sglang.launch_server --model-path <model> --tp <N> \
  --attention-backend triton --prefill-attention-backend aiter --decode-attention-backend aiter \
  --chunked-prefill-size 16384 --enable-deterministic-inference
```

(The log shows page size set to 128 and the radix cache on.) Checks: `python3 -m sglang.test.test_deterministic --test-mode {single,prefix,radix_cache} --n-trials 50` (prefix also with `--return-logprob`); a bitwise comparison of 1,275 responses (the same prompt in batches of 1-50, token IDs and log-probabilities) against batch size 1; a 30k-token document followed by different questions, sent repeatedly so later requests hit the cached document (12 comparisons); with YaRN x4, a 64k and a 120k prompt alone vs next to other requests (8), and a 100k prompt split at different chunk boundaries by other requests (12).

| Model | single | prefix (logprobs) | radix_cache | bitwise | cached 30k prefix | 64k/120k | chunk boundaries |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Qwen3-8B | 1 unique | identical | pass | 1,275/1,275 | 12/12 | 8/8 | 12/12 |
| Qwen3-30B-A3B | 1 unique | identical | pass | 1,275/1,275 | 12/12 | | |

The same settings applied through a launcher patch (instead of this branch's code) on `rocm/sgl-dev:v0.5.22-rocm724-mi35x-20261018` also pass every check above for Qwen3-8B at TP2, Phi-4 and Qwen3.8-27B.

**Control (page size 1, i.e. without this PR's page-size rule, everything else equal):** cached prefixes reach the kernel off the 128-token tile, and the prefix check with log-probabilities fails and the cached 30k prefix matches in only 4 of 12 cases, on Qwen3-8B. Without the fixed `max_seqlen_q`, results depend on batchmates already at kernel level.

Rechecked as pushed on the 2026-10-21 nightly (`rocm/sgl-dev:v0.5.22-rocm724-mi35x-20261021`, with #43788): Qwen3-8B every check above incl. cached prefix, 64k/120k and chunk boundaries; Phi-4 every check and a 12k cached prefix.

Unit tests on MI350X: `test_model_overrides.py` 115 passed, 6 failed (the same 6 CUDA-specific failures as on main without this branch).

- aarnetalman · comment · 2026-11-03T05:51:29Z · [source](https://github.com/sgl-project/sglang/pull/45601#discussion_r4451336312)

File: `python/sglang/srt/arg_groups/overrides.py` · line 1132

Good question. Yes. The argument check only sees the flag, and with `--kv-cache-dtype auto` `configure_kv_cache_dtype` switches to an fp8 KV cache at load time when the checkpoint's quantization config sets `kv_cache_quant_algo` to FP8. The fp8 KV prefill kernel was not batch-invariant in our tests, so that case would slip through.

I added a check on the resolved dtype in the AITER backend: in deterministic mode, AITER prefill on an fp8 KV cache now fails at startup with the same advice (`--kv-cache-dtype bfloat16` or another `--prefill-attention-backend`), with a unit test (684e78f9da). The argument check stays as the early error for an explicit fp8 flag.
