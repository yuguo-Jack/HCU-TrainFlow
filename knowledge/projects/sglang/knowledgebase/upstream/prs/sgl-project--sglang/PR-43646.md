# [diffusion] Resolve FastH3 AdaLN cache variant when unset

[Upstream PR](https://github.com/sgl-project/sglang/pull/43646) · state: closed · merged: False

## Original PR description

## Motivation

Enabling the AdaLN sidecar cache on FastH3 (`--minimax-h3-adaln-cache-path`) always fails, even though FastH3 is a supported pipeline:

- `FastH3PipelineConfig.validate_server_args` raises on any explicit `--model-variant` (FastH3 ships a single t2va-distilled partition, so the flag does not apply).
- The sidecar branch in `TransformerLoader` required `model_variant in ("fl2va", "ref2va")` and raised `MiniMax H3 AdaLN cache requires --model-variant fl2va or ref2va` otherwise.

With FastH3 the variant is therefore always `None`, so the two checks deadlock the only supported FastH3 + sidecar path.

## Modifications

- Add `_resolve_minimax_h3_adaln_variant(model_variant)`: an unset variant now falls back to `fl2va`, the same default the base `MiniMaxH3PipelineConfig` already selects when `--model-variant` is omitted. Unsupported values still raise the existing error.
- Use it in the sidecar branch instead of the inline `in ("fl2va", "ref2va")` check.
- Add unit tests covering the three boundary cases (unset -> `fl2va`, supported passthrough, unsupported rejection) to the existing `test_minimax_h3_adaln_cache.py`.

## Accuracy Tests

Validated end to end on a single A100-SXM4-80GB (FastH3 4-step, 1344x768, 5 s, Triton VSA fallback). Output is **bit-exact** with the pre-patch baseline (`MD5 60e0244b...` identical), so the fix only unblocks the path without changing numerics.

`python -m pytest python/sglang/multimodal_gen/test/unit/test_minimax_h3_adaln_cache.py` -> 26 passed.

## Speed Tests and Profiling

Same prompt/seed/resolution/steps, VAE-resident + layerwise offload of `dit text_encoder`:

| run | e2e (s) | peak VRAM (MB) | DiT host pinned (GiB) | output MD5 |
|---|---|---|---|---|
| baseline (no sidecar) | 84.96 | 20210 | 65.15 | 60e0244b... |
| + AdaLN sidecar | 85.67 (+0.8%, noise) | 19236 (-0.97 GiB) | 40.91 (-24.24) | 60e0244b... bit-exact |

The 24.2 GiB of `adaln_proj` weights no longer need to be re-streamed per request; the saving is hidden behind compute for this single-request, compute-bound case, so wall time is unchanged while VRAM and host pinned memory drop.
