## Original PR description

# [metrics] Add cache eviction lifetime/frequency metrics (L1 + L2)

## Motivation

SGLang's radix / HiCache eviction is purely capacity-driven (LRU/LFU/FIFO/SLRU/…).
There is currently **no** notion of *how long a cache entry lives*, *whether it can
survive 1 hour*, or *how often eviction happens*. Operators cannot answer these basic
capacity questions today, so "the hit rate is low" can only be guessed at.

The data already exists on every `TreeNode` (`creation_time`, `last_access_time`,
`hit_count`), and the evicted node is in hand inside `evict()` — this PR simply records
it at the moment of eviction. In addition, the L2 (host / CPU DRAM) eviction path
(`evict_host`) previously had **no metrics at all**, so the host tier was a complete blind
spot.

This is observability only: **no eviction/routing behavior is changed.**

## Modifications

New metrics on `RadixCacheMetricsCollector` (gated by `--enable-metrics`):

Histograms:
- `sglang:cache_eviction_age_seconds` — age (`now - creation_time`) of an L1 (GPU) entry
  at eviction; p50/p90 directly answer "how long does cache live". Buckets span 1s..7200s
  with a **3600s bucket** so the "1 hour" question is directly readable.
- `sglang:cache_eviction_idle_seconds` — idle time (`now - last_access_time`) at eviction.
- `sglang:cache_eviction_reuses` — how many times an entry was reused before eviction.
  (Named `reuses`, not `hit_count`, so the histogram base name does not collide with the
  reserved `_count` suffix.)
- `sglang:hicache_host_eviction_age_seconds` — L2 (host) entry age at eviction.

Counters:
- `sglang:cache_eviction_events_total` — number of eviction passes; `rate(...)` answers
  "how often does eviction happen".
- `sglang:hicache_host_evicted_tokens_total` — tokens evicted from the L2 host cache.

Buckets are configurable via `SGLANG_BUCKET_CACHE_AGE` / `SGLANG_BUCKET_CACHE_REUSES`.

Instrumentation (records only when an entry actually leaves the tier; no behavior change):
- `RadixCache.evict()` — L1, non-HiCache deployments
  (`python/sglang/srt/mem_cache/radix_cache.py`).
- `HiRadixCache.evict()` — L1 under HiCache (separate override; a `write_back` demotion to
  host is treated as "left L1", so age = GPU residency)
  (`python/sglang/srt/mem_cache/hiradix_cache.py`).
- `HiRadixCache.evict_host()` — L2 true end-of-life
  (`python/sglang/srt/mem_cache/hiradix_cache.py`).
- New collector fields + `observe_eviction_age()`, `increment_eviction_events()`,
  `increment_host_eviction_num_tokens()`, `observe_host_eviction_age()`
  (`python/sglang/srt/observability/metrics_collector.py`).

Files:
- `python/sglang/srt/observability/metrics_collector.py`
- `python/sglang/srt/mem_cache/radix_cache.py`
- `python/sglang/srt/mem_cache/hiradix_cache.py`

## Coverage / limitations

Covers `RadixCache` and `HiRadixCache` (and `LMCRadixCache`, which calls
`super().evict()`). The other tree caches — `UnifiedRadixCache`, `SWARadixCache`,
`MambaRadixCache`, `HiMambaRadixCache`, `RadixCacheCpp` — each have their own `evict()` and
are intentionally left as follow-up. The `cache_type` label makes any uninstrumented cache
obvious (no series), so this is safe incremental coverage.

## Test process (verified on a live deployment)

- Engine: `sglang` v0.5.12 (cu129), model **MiniMax-M2.7**, `tp=8/ep=8` on 8×GPU.
- Flags: `--enable-metrics --enable-hierarchical-cache` (HiCache, `write_back`),
  `--hicache-storage-prefetch-policy best_effort`.
- To force eviction quickly the server was relaunched with a deliberately small cache:
  `--hicache-size 2` (≈2 GB host per rank) and `--max-total-tokens 40000` (tiny GPU KV
  pool). This is a test knob only; the metrics themselves are unconditional.
- Workload: ~290 `/generate` requests — 20 prompts sent twice (to create cache *hits* so
  `reuses` is non-zero), then 250 distinct ~1.4k-token prompts to overflow both the GPU KV
  pool (→ L1 eviction / demotion) and the 2 GB host cache (→ L2 `evict_host`).
- Then `curl localhost:30000/metrics`.

Before the patch, none of the metric names below existed in `/metrics`
(`grep -c cache_eviction_age|...|hicache_host_evicted_tokens = 0`).

Example query — "p90 lifetime of an L1 cache entry":

```
histogram_quantile(0.9, sum by (le) (rate(sglang:cache_eviction_age_seconds_bucket[5m])))
```

(In this stress run the cache was intentionally tiny, so entries lived only a few seconds
on average — `age_sum/age_count ≈ 2 s`. On a normally-sized cache these histograms are what
tells you whether your KV cache actually survives an hour.)

In `evict_host`, the eviction age metric is observed before the eviction operation is actually performed. If `self.cache_controller.evict_host` raises an exception or returns `0` (meaning no tokens were actually evicted), the recorded metric will be inaccurate. It is safer and more accurate to observe the age and increment the tokens only after a successful eviction (i.e., when `host_evicted > 0`).

```suggestion
            # Block deleted entirely (GPU already evicted, now CPU freed) --
            # emit remove(CPU) so the router drops the host-tier entry.
            self._record_remove_event(x, medium=StorageMedium.CPU)
            host_evicted = self.cache_controller.evict_host(x.host_value)
            num_evicted += host_evicted
            if collect_lifetime and host_evicted > 0:
                self.metrics_collector.observe_host_eviction_age(now - x.creation_time)
                self.metrics_collector.increment_host_eviction_num_tokens(host_evicted)
```

For better accuracy and robustness, the eviction age metric should be observed after the eviction has successfully completed (i.e., after freeing the memory and deleting the leaf node). This prevents recording metrics for failed or incomplete evictions and aligns with the post-eviction observation pattern used in `HiRadixCache`.

```suggestion
            self.token_to_kv_pool_allocator.free(x.value)
            num_evicted += len(x.value)
            self._delete_leaf(x)

            if collect_lifetime:
                self.metrics_collector.observe_eviction_age(
                    age_seconds=now - x.creation_time,
                    idle_seconds=now - x.last_access_time,
                    hit_count=x.hit_count,
                )
```
