# [Perf] mem_cache: Reclaim a branch's last SWA window last in unified eviction

[Upstream PR](https://github.com/sgl-project/sglang/pull/42840) · state: open · merged: False

## Original PR description

## Motivation

- To continue from a cached prefix, the server needs the SWA KV of the last `sliding_window` tokens of that prefix. Older SWA KV on the same path is no longer needed.
- When the SWA pool is full, the unified cache frees SWA KV in plain LRU order. An idle conversation is the least recently used, so its last window is freed before the old windows that active conversations leave behind on every turn.
- When the idle conversation comes back, only the shared system prompt is a cache hit. The rest is prefilled again, even though its full KV is still cached.
- #35515 by @QAQEthan fixes this in `swa_radix_cache.py`, but that file is no longer on main. This PR brings the same idea to the unified cache, for both the Python core and the Rust core.

## Modifications

- A node counts as the end of a branch when a leaf or a fork lies less than one window of live SWA tokens below it. These nodes hold the windows that a later request needs.
- `_evict_device_next_node` now skips these nodes on its first pass. If it reaches the end of the LRU list and it skipped some nodes, it starts again from the oldest entry and frees them in LRU order. So eviction still succeeds wherever it succeeded before.
- The same change is made in `rust/sglang-radix-tree/src/components/swa.rs`. `ComponentState` gets two new flags to track the two passes.
- One difference from #35515: a window that sits above an already freed (tombstoned) node is not protected. In the unified cache almost every live window sits above one, because of chunk boundaries and older turns, so protecting them would protect everything. A window above a fork, such as the shared system prompt, is still protected.
- Two existing Rust tests expected the old eviction order and are updated.
- Cost: on the first pass, each candidate node needs a short walk down the tree, covering at most one window of tokens. When the pool only holds protected windows, each eviction scans the SWA LRU list once before it frees anything.

Related PRs that do not overlap with this one:

- #39694 limits the number of live windows per path at insert time.
- #40283 frees the slots outside the window when a request finishes.
- #40338 moves this walk into a shared base class. Whichever of that PR and this one lands second will need a small rebase.
- #42703 keeps an opt-in margin of extra SWA tokens behind the end of each insert. If it lands, the span that this PR spares should grow by that margin.
- #43009 rebuilds an evicted window on a cache hit instead of prefilling the whole suffix again. With this PR that rebuild is needed less often.

## Speed Tests and Profiling

4x B300, TP4 + EP4. I use `--max-total-tokens 400000` and `--swa-full-tokens-ratio` to make the SWA pool small, so that eviction happens in a short run. Both builds run in the `nightly-dev-cu13-20261009` image. Its `sglang-kernel` 0.4.9 has no `flash_mla_mega`, so both builds use `--dsv4-attn-backend flashmla`.

```bash
sglang serve --trust-remote-code --model-path nvidia/DeepSeek-V4.1-Flash-NVFP4 \
  --tp 4 --ep-size 4 --host 127.0.0.1 --port 31710 \
  --reasoning-parser auto --tool-call-parser auto --mem-fraction-static 0.8 \
  --speculative-algorithm DSPARK --speculative-dspark-block-size 5 --cuda-graph-max-bs-decode 64 \
  --enable-cache-report --dsv4-attn-backend flashmla --max-total-tokens 400000 --swa-full-tokens-ratio 0.06
```

Workload:

- 40 conversations share a 1024-token system prompt. Each has a first turn of about 4.3k tokens.
- 8 conversations are busy and send one turn every round. 32 are idle and send one turn every 8 rounds.
- 40 rounds, concurrency 4, 160 output tokens, temperature 0.
- "cached / prompt" is the share of prompt tokens served from the cache, from `usage.prompt_tokens_details.cached_tokens`.

- Each row is one server launch. TTFT moves by tens of ms between runs of the same build, so the TTFT columns do not separate the builds.
- 23,808 tokens: the pool has room for the last window of every conversation, but not for the old windows as well. This is the case the PR fixes.
- 39,936 tokens: this workload never fills the pool, so both builds behave the same.
- The remaining idle misses at 23,808 tokens come from main's decoder SWA bounded replay for DeepSeek-V4.1 (#41303). It holds back one window at the end of every match, so the next turn's match can end one page above the branch end, outside the spared window. With `--no-enable-decoder-swa-bounded-replay` this PR has 0 / 160 misses. Sparing that page as well, by keeping two windows per branch, was worse at this pool size (idle cached / prompt of 0.516 and 0.447 in two runs), so this PR does not do it.
- At 9,984 tokens (ratio 0.025), main `14ad64c411` stopped making progress in round 37, so that pool size is not re-measured. At `6697607914`, both builds lost the cache in the same way at that size (idle cached / prompt 0.219 on main, 0.218 with this PR).

```python
"""Multi-turn agent workload against a live server: a few busy conversations, many parked in tool calls.

usage: bench.py <base_url> <out.json>
Each turn appends the model's reply and a short tool result, then asks again. Reports cached prompt
tokens (server usage) and TTFT per request, split by busy / parked conversations.
"""
import json
import random
import sys
import time
import urllib.request
from concurrent.futures import ThreadPoolExecutor

URL, OUT = sys.argv[1], sys.argv[2]
N_BUSY, N_PARKED, PARK_EVERY, ROUNDS, CONC = 8, 32, 8, 40, 4
WORDS = open("/usr/share/dict/words").read().split() if False else None
VOCAB = ["alpha", "bravo", "charlie", "delta", "echo", "foxtrot", "golf", "hotel", "india", "juliet", "kilo", "lima",
         "mike", "november", "oscar", "papa", "quebec", "romeo", "sierra", "tango", "uniform", "victor", "whiskey",
         "xray", "yankee", "zulu", "river", "stone", "cloud", "engine", "ledger", "packet", "socket", "tensor",
         "kernel", "window", "branch", "cursor", "budget", "signal"]


def words(rng, n):
    return " ".join(rng.choice(VOCAB) for _ in range(n))


SYSTEM = "You are a terse operations agent. Rules:\n" + "\n".join(
    f"{i}. {words(random.Random(i), 18)}." for i in range(40)
)
MODEL = json.load(urllib.request.urlopen(f"{URL}/v1/models"))["data"][0]["id"]


def ask(messages):
    body = {"model": MODEL, "messages": messages, "max_tokens": 160, "temperature": 0, "stream": True,
            "stream_options": {"include_usage": True}, "chat_template_kwargs": {"thinking": False}}
    req = urllib.request.Request(f"{URL}/v1/chat/completions", data=json.dumps(body).encode(),
                                 headers={"Content-Type": "application/json"})
    t0, ttft, text, usage = time.perf_counter(), None, [], None
    with urllib.request.urlopen(req, timeout=900) as r:
        for line in r:
            if not line.startswith(b"data: ") or line.strip() == b"data: [DONE]":
                continue
            ev = json.loads(line[6:])
            if ev.get("usage"):
                usage = ev["usage"]
            for ch in ev.get("choices", []):
                d = ch.get("delta", {})
                piece = d.get("content") or d.get("reasoning_content")
                if piece:
                    ttft = ttft or time.perf_counter() - t0
                    text.append(piece)
    return "".join(text), usage, ttft


class Conv:
    def __init__(self, cid):
        self.cid, self.rng, self.turn = cid, random.Random(1000 + cid), 0
        self.kind = "busy" if cid < N_BUSY else "parked"
        doc = words(self.rng, 2200)
        self.messages = [{"role": "system", "content": SYSTEM},
                         {"role": "user", "content": f"Incident {cid} log:\n{doc}\n\nSummarize the next action in two sentences."}]

    def step(self, rnd):
        text, usage, ttft = ask(self.messages)
        cached = ((usage.get("prompt_tokens_details") or {}).get("cached_tokens")) or 0
        row = {"conv": self.cid, "kind": self.kind, "round": rnd, "turn": self.turn, "prompt": usage["prompt_tokens"],
               "cached": cached, "ttft": ttft}
        self.messages.append({"role": "assistant", "content": text or "ok"})
        self.messages.append({"role": "user", "content": f"Tool result {self.turn}: {words(self.rng, 50)}. Continue."})
        self.turn += 1
        return row


convs = [Conv(c) for c in range(N_BUSY + N_PARKED)]
rows = []
with ThreadPoolExecutor(CONC) as pool:
    # Round -1: cold start, one conversation at a time so cold prefills do not fight over the SWA pool.
    rows += [c.step(-1) for c in convs]
    for rnd in range(ROUNDS):
        due = [c for c in convs if c.kind == "busy" or (c.cid % PARK_EVERY) == rnd % PARK_EVERY]
        rows += pool.map(lambda c, rnd=rnd: c.step(rnd), due)
        print(f"round {rnd} done", flush=True)
json.dump(rows, open(OUT, "w"))
```
