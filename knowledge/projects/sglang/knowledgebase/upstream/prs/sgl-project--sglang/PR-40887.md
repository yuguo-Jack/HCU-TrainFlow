# [Fix] Request exact label logprobs for Qwen3-VL reranking

[Upstream PR](https://github.com/sgl-project/sglang/pull/40887) · state: closed · merged: False

## Original PR description

## Motivation

The Qwen3-VL reranker needs both label probabilities to compute `P(yes) / (P(yes) + P(no))`. The current implementation searches the first generated token's top-50 logprobs and leaves a missing label's probability at zero. A label being absent from the returned list does not mean its probability is zero: this can clip scores to 0 or 1, create artificial ties, and change document ranking.

The implementation introduced in [#16403](https://github.com/sgl-project/sglang/pull/16403) uses `top_logprobs_num=50` with the comment "Get enough logprobs to find yes/no tokens". This relies on both labels appearing in a bounded candidate list; neither is guaranteed to rank in the top 50. `top_logprobs_num` controls the returned candidate logprobs and is separate from the sampling parameter `top_k`.

This reproduces with the actual Qwen/Qwen3-VL-Reranker-2B model. For the query "What is the capital of France?" and document "Bananas are yellow fruit.", `/v1/rerank` returns 0 because `yes` is absent from the top-50 list. Explicitly requested logprobs are approximately -7.425894 for `yes` and -5.425894 for `no`, giving a score of **0.119202922**. A small absolute probability can still contribute materially to the ratio between the two labels.

Since the required token IDs are known, requesting their logprobs directly supplies both inputs to the scoring formula. Increasing the arbitrary cutoff would retain the same coverage assumption; returning the entire vocabulary is unnecessary. This change requests only the two required labels.

## Modifications

- Request the cached yes/no token IDs via token_ids_logprob and read output_token_ids_logprobs for the first generated token.
- Use logprob_start_len=-1 because reranking only needs the output-token distribution, avoiding unused prompt logprobs.
- Add registered CPU regressions covering a label outside top-50, correct top_n document selection, and token-ID-based extraction; update the existing VL reranker fixture to the selected-token response field.

Text-only decoder reranking and cross-encoder routing are unchanged.
