# [Fix] mnnvl: Match FlashInfer's arch-specific CuTe DSL AR profiles

[Upstream PR](https://github.com/sgl-project/sglang/pull/46929) · state: open · merged: False

## Original PR description

## Summary

`_config_for_shape` decides whether FlashInfer's MNNVL CuTe DSL `DEFAULT_CONFIG` serves the current shape or SGLang has to supply a re-targeted single-profile config. It checked `StaticProfile.matches()` without a compute capability.

FlashInfer 0.7.2.post1 ships tp=4 hidden=8192 top_k=10 profiles keyed to GB300 (sm_103) and Rubin (sm_107). An architecture-specific profile never matches an unknown (`None`) architecture, so on those GPUs SGLang found no match, discarded FlashInfer's measured tp=4 routes, and served the re-targeted GB300 tp=8 presets instead.

This passes the device's compute capability and uses `MNNVLCuteDSLConfig.find()`. That is the lookup the FlashInfer workspace's `resolve()` performs, so SGLang now re-targets only the shapes FlashInfer ships no profile for on this architecture. It also replaces a stale comment that said `DEFAULT_CONFIG` ships only GB300 H=8192/K=10.

## Dependency

Stacked on #46926: `find()` and the `compute_capability` argument are new in FlashInfer 0.7.2.post1. Until #46926 merges, this PR's diff also contains the bump commit; the change under review is the top commit only.

## Validation

- New CPU unit test `test_a_profile_shipped_for_this_arch_is_not_retargeted` (`test/registered/unit/layer_boundary/test_cutedsl_ar_fusion.py`, `base-a-test-cpu`): at tp=4 / hidden 8192 / top_k 10, sm_103 and sm_107 keep `DEFAULT_CONFIG` and sm_100 is re-targeted. Not run locally (FlashInfer's presets import `cutlass`, which has no macOS wheels), so this relies on CPU CI.
- On the pre-fix code, the sm_103 and sm_107 cases fail. This was checked by reading FlashInfer v0.7.2.post1, not by running the test:
  - `DEFAULT_CONFIG` has no architecture-agnostic tp=4/H8192/K10 profile, only `_H8192_TP4_GB300_PROFILE` (10, 3) and `_H8192_TP4_RUBIN_PROFILE` (10, 7).
  - The workspace resolves with `compute_capability=torch.cuda.get_device_capability(device)` (`flashinfer/comm/mnnvl_cutedsl_ar.py`).
- Repository pre-commit hooks.

Not yet run: GPU E2E or perf on GB300 / Rubin at TP4. That is why this PR is a draft.
