# [Fix] muse: recover channel headers after unframed prose

[Upstream PR](https://github.com/sgl-project/sglang/pull/44831) · state: open · merged: False

## Original PR description

## Motivation

Muse can emit unframed prose followed by a framed tool header without an intervening `<|eom|>`. Both detectors remain inside the unframed body. The client receives raw protocol text instead of a structured tool call.

```text
Let me check.<|start|>assistant to=get_weather<|message|><atem:function_calls><atem:invoke name="get_weather"><atem:parameter name="city">Paris</atem:parameter></atem:invoke></atem:function_calls>
```

## Modifications

Let a reserved `<|start|>` marker end unframed prose in both the Muse reasoning detector and tool detector. Limit recovery to an unset recipient. Explicit answer channels retain quoted tool headers, and tool arguments retain marker-like text.

The reasoning detector also recovers subsequent reasoning and answer channels. This complements the parser-handoff flag fix in https://github.com/ai-dynamo/dynamo/pull/16717.

## Accuracy Tests

The unchanged runtime reproduces the missing call. All 25 tests in the Muse detector suite pass with the patch. The new coverage checks every two-part split, character chunks, buffered input, marker-like arguments, and the reasoning-to-tool chain after an unframed preamble.
