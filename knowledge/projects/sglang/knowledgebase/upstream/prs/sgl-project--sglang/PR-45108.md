# [Fix] hisparse: Keep PD destination host pages until the decode KV release

[Upstream PR](https://github.com/sgl-project/sglang/pull/45108) · state: open · merged: False

## Original PR description

## Motivation

On a PD decode server with `--enable-hisparse`, the prefill writes each request's KV straight into the HiSparse coordinator's host pages. When the transfer fails or the client cancels, `DecodeTransferQueue.pop_transferred` called `hisparse_coordinator.request_finished`, which frees those host pages, **before** it decided to defer the release because sibling prefill ranks may still be writing. The decode KV pages, the req slot and the metadata slot were held until the drain ack, but the host pages were not. A later request could therefore be handed host pages that a stale RDMA write was still landing on, and its KV would be silently overwritten.

Reach: PD decode with HiSparse (the DSV3.2 / GLM-5.x cookbook decode option) and deferred decode KV release (on by default for Mooncake / NIXL). It triggers on any transfer failure or mid-transfer client cancel.

## Modifications

- `_release_request` frees the HiSparse request state (`request_finished`) together with the KV. Both the immediate and the deferred release (`_do_release`) go through it, so the destination stays owned exactly as long as the hold.
- Removed the two earlier `request_finished` calls in `pop_transferred` (the failure branch and the corrupted-transfer branch). Both of those branches already reach `_release_request`.

## Tests

- `test_deferred_decode_kv_release.py::TestHiSparseDestinationFollowsTheHold`: a deferred failure frees nothing at failure time and frees the HiSparse pages, then the KV, at release. A failure that cannot notify prefill still frees both immediately, exactly once. Negative control: with the `decode.py` change reverted, the deferred case fails (`[('hisparse', 'r12')] != []`).
- `test_deferred_decode_kv_release.py`, `test_decode_queue_cleanup.py`, `test_decode_radix_lock_ref.py`, `test_decode_hicache_tree_core.py` and `test_hisparse_unit.py` all pass on 1x B300: 85 passed, 2 skipped. `_make_queue` gained `enable_hisparse=False`, which the real scheduler always has.
- Real-coordinator check (outside CI): the actual `pop_transferred` failure branch was run with the real `HiSparseCoordinator` and its pinned host pool. On main, all 576 destination host pages are returned at failure time and a new allocation hands out all 576 of them again. With this PR, 0 pages are returned until the release.
