# [Fix] model_loader: Refuse state-dict checkpoints that would silently drop MXFP4 triton_kernels expert weights

[Upstream PR](https://github.com/sgl-project/sglang/pull/41616) · state: open · merged: False

## Original PR description

## Motivation

Part of #34448: the fail-loud part. The issue stays open for the full round-trip. With the triton_kernels MoE runner, `Mxfp4MoEMethod.process_weights_after_loading` moves the MXFP4 expert weights into kernel wrappers held by the quant method and deletes `w13_weight`/`w2_weight` from the layer. `model.state_dict()` then has no expert weights, so:

- `ShardedStateLoader.save_model` (and `RemoteModelLoader.save_model`) write a checkpoint without them. The reporter saw a 4.0 GB export for a 13 GB gpt-oss-20b checkpoint.
- Loading any such checkpoint copies nothing into the wrappers, which were built from freshly initialized weights. The `Missing keys` check doesn't fire, because the keys are absent from both the checkpoint and the model. Every expert runs on garbage with no error or warning.

A real round-trip needs the kernel-layout tensors to be reachable from the state dict. #34558 tried that: it passed the 4×B200 `test_gpt_oss_4gpu_mxfp4.py` run, failed on 4×H100, and was closed. This PR only closes the silent-corruption path, so a follow-up round-trip can land on its own schedule.

## Modifications

- `_raise_if_weights_outside_state_dict(model)` (module-level in `loader.py`): raises `NotImplementedError`, naming the module and pointing at #34448, when a module's quant method is `Mxfp4MoEMethod` with `use_triton_kernels`, unless `use_mega_moe` or `_use_aiter` is set (`process_weights_after_loading` returns before the triton_kernels branch for those, so the weights stay Parameters). It uses `getattr(module, "quant_method", None)`, the idiom the loaders already use.
- Called from every state-dict save path (`ShardedStateLoader.save_model`, `RemoteModelLoader.save_model`, the `PreshardedModelLoader` dump) and every state-dict load path (`ShardedStateLoader.load_model` and `RemoteModelLoader._load_model_from_remote_kv` after `process_weights_after_loading`; the `PreshardedModelLoader` reload). The presharded dump checks right after model init, before the full weight load, since its `_collect_extra_tensors` never sees tensors held by a quant method either.
- Other MXFP4 backends keep their weights as Parameters and are not affected.

## Accuracy Tests

No change to the forward path or to any serving configuration; the new code only runs on the state-dict save/load paths.

## Speed Tests and Profiling

Not applicable: one `named_modules()` walk at save/load time.
