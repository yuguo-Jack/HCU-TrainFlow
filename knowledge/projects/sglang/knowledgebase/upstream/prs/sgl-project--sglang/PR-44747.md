# [Feat] beam: Add native Beam serving support

[Upstream PR](https://github.com/sgl-project/sglang/pull/44747) · state: open · merged: False

## Original PR description

## Motivation

Add native serving support for Beam, a 501B-parameter MoE model with 23B active parameters and a 1M-token context configuration.

## Modifications

- Implement Beam's hybrid sliding-window/full attention, SSMax query scaling, attention output gating, sandwich normalization, depth-scaled residuals, and grouped MoE routing.
- Support BF16, ModelOpt NVFP4, and compressed-tensors FP8 checkpoints, with BF16 LoRA serving.
- Integrate DFlash2, attention data parallelism, unified hybrid KV allocation, prefix caching, and HiCache. DFlash attention DP supports the matching FlashInfer MegaMoE runner/all-to-all configuration.
- Add Beam reasoning and tool-call parsing across Chat Completions, Responses, and Messages, including checkpoint response-template handling and structured-output constraints.
- Add fused projection/norm/residual/collective paths, router GEMV/BF16x3/cuTile kernels, and GB300 MoE tuning, together with registered unit, kernel, and end-to-end coverage.
- Include the serving dependency and Docker updates used by this implementation.

## Accuracy Tests

Recorded results at head `f7473673ddf6175f301782af57e684d33d3e3f96`, using the original Beam verifier at `e698bb518d5117a3f1ba93357bfb72999a586020` and its full GSM8K 10-shot preset. All runs use actual DFlash decoding with eight draft tokens and no acceptance simulation.

| Checkpoint | Layout | GSM8K accuracy | Problems | Request errors |
|---|---|---:|---:|---:|
| NVFP4 | TP4, 4 GB300 GPUs | 94.69% | 1,319 | 0 |
| FP8 | TP4, 4 GB300 GPUs | 96.13% | 1,319 | 0 |
| BF16 | TP8, 8 GB300 GPUs across two nodes | 95.68% | 1,319 | 0 |

Startup and the configured 1M context limit were checked. Actual 1M-token prompts and maximum-capacity operation were not exercised. Upstream CI and comparison against current `main` remain pending for this draft.

## Speed Tests and Profiling

Recorded OpenHands multi-turn replay on four GB300 GPUs, NVFP4 TP4/EP1: **127,588.4 total tokens/s/GPU at 185.87 tokens/s/user (p50), concurrency 32**. Total throughput includes cached input. This performance replay uses eight draft tokens, simulated acceptance length 4 with real draft tokens, and 88 GB HiCache per rank. It is a single measurement and does not measure natural draft acceptance or model accuracy.

No fresh performance comparison against current `main` has been run for this draft.
