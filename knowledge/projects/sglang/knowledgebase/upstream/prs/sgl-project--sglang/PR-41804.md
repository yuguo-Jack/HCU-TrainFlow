# fix: bind delayed HTTP abort cleanup to request generation

[Upstream PR](https://github.com/sgl-project/sglang/pull/41804) · state: closed · merged: False

## Original PR description

## Motivation

`TokenizerManager.create_abort_task` schedules a delayed cleanup for streaming HTTP requests. The current implementation sleeps for two seconds and then aborts whatever request is currently registered under the original RID. If the first stream has already completed and a replacement request reuses that RID before the delayed cleanup fires, the old cleanup can abort the replacement generation.

This is related to the request-ID lifecycle area discussed in #38788 / #38850, but it is a different code path and claim: #38850 changes the scripted-runtime test harness and explicitly makes no serving-code change. This PR changes the production `TokenizerManager.create_abort_task` path used by `StreamingResponse` background cleanup.

## Changes

- Snapshot the exact originating request object and `ReqState` generation before the delay.
- After the grace period, abort only when the same `ReqState` is still current, belongs to the same request object, and is not finished.
- Preserve the existing behavior for a still-live original request.
- Add focused regression coverage for:
  - replacement already present before cleanup starts;
  - replacement installed during the delay;
  - the same request object associated with a newer state generation;
  - an initially absent RID that is registered during the delay;
  - mixed batch ownership, where only still-owned members may be aborted;
  - live, finished, and removed originals.

## Scope and limitations

- This is a request-lifetime correctness fix; it does not change model forward, kernels, token values, or inference performance.
- The originating `ReqState` reference is retained for the existing two-second grace period. The state already exists in `rid_to_state` while live; after normal completion this adds bounded temporary retention by the background task.
- Unit coverage includes batched partial replacement, but real-HTTP validation used single requests. Multi-worker deployments, `n > 1`, and other cancellation entry points remain for upstream CI/review.
- Failed startup/diagnostic attempts from the external validation were retained; the table above is from the completed source-bound run only.
