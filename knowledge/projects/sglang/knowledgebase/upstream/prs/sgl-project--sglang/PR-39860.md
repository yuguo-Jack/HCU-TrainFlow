# Add optional strip layout for Inkling speculative convolutions

[Upstream PR](https://github.com/sgl-project/sglang/pull/39860) · state: closed · merged: False

## Original PR description

## Why is this change needed?

Add an opt-in strip layout for Inkling speculative short-convolution intermediates: `--enable-inkling-sconv-strip-layout`. It requires CUDA and a linear draft chain; the default remains off.

For convolution width 4, 8 draft tokens and 128 BF16 channels, dense scratch is `[8, 3, 128]` (6,144 bytes); strip scratch is `[8, 128]` (2,048 bytes). Each fresh input is stored once. Accepted state is reconstructed from the existing history and those inputs: old `[10, 20, 30]`, new `[40, 50, 60]`, accepting two gives `[30, 40, 50]`.

Wire the layout through regular and unified pools, memory reservation, the generic writer, both fused Inkling writers, and acceptance commit. Tracking copies consume the old history before the working state is overwritten. Unified-pool strides and the Inkling convolution channel axis are preserved. Flattened attention padding is cropped before grouping rows by request.

## Test Plan

- 13 checks passed on four GB300 GPUs in 180.09 seconds, including cold compilation: dense/strip numerical parity, padded-slot isolation, tracking order, graph replay with changed inputs, allocation/reservation accounting, unified-pool allocation and strided commit, fused attention writer, and fused all-reduce writer.
- Recurring coverage contains 12 cases, six requiring one GPU. The four-GPU fused all-reduce comparison was an ad hoc run and is not registered in CI. The new CI estimate is 90 seconds; the fused attention writer took 51.906 seconds including cold compilation, while the ad hoc four-GPU check took 103.021 seconds.
- Existing memory-budget tests: 7 passed, including 8 subtests.
- Scoped repository formatting/lint hooks passed. Model-level public Inkling E2E validation remains outstanding; this PR is a draft and keeps the layout opt-in.
