# [Feat] plugins: Add SGLANG_REQUIRED_PLUGINS for fail-fast loading

[Upstream PR](https://github.com/sgl-project/sglang/pull/44444) · state: open · merged: False

## Original PR description

Closes #43133

## Motivation

SRT general plugins are best-effort: a plugin that is missing, filtered out, fails to import, raises in its callback, or has a hook that fails to apply is only logged, and the server starts without it. For a plugin that changes how a model is placed or executed, partial application is worse than none. This implements all three parts of #43133: an opt-in, plugin-agnostic fail-fast (`SGLANG_REQUIRED_PLUGINS`), a read-only hook status, and `required=True` for a single hook.

## Modifications

**Part 1: `SGLANG_REQUIRED_PLUGINS`**

- `environ.py`: add `SGLANG_REQUIRED_PLUGINS = EnvTuple(())` next to `SGLANG_PLUGINS`.
- `plugins/__init__.py`: `load_plugins()` raises a `RuntimeError` naming the plugin and the cause when a listed plugin:
  1. has no entry point in `sglang.srt.plugins`;
  2. is excluded by `SGLANG_PLUGINS` or `SGLANG_PLATFORM`;
  3. raises in `ep.load()`;
  4. raises in its callable;
  5. registered a hook that was never applied: its target failed in `apply_hooks()`, or the hook was registered after an earlier `apply_hooks()` call had already patched that target.

  Load and callable errors are chained (`raise ... from e`).
- The required set is passed to `load_plugins_by_group()` as a new keyword parameter (default empty), so platform discovery, which shares that function, is unchanged.
- From review: `_current_plugin_source` is now also set around `ep.load()`, so hooks registered at import time (module-level `@plugin_hook` or `HookRegistry.register(...)`) are attributed to their plugin.
- For 1.5, failures are collected after the final `apply_hooks()` and raised as one `RuntimeError` listing every `plugins -> target`. It is chained from an `ExceptionGroup` with one `RuntimeError` per target, each chained from that target's original exception, so every cause keeps its traceback.

**Part 2: read-only hook status (`hook_registry.py`)**

- New `_applied_count: dict[str, int]`, next to the unchanged `_patched` set: the number of hooks on a target when it was patched. Hooks only get appended, so the hooks past that count are the ones registered too late. This is the per-hook comparison suggested in review: a required hook that an earlier `apply_hooks()` call already wrapped is not reported. A target patched outside `apply_hooks()` (added to `_patched` by a plugin) is counted the first time `apply_hooks()` sees it.
- New `_failed_targets: dict[str, BaseException]`: the exception from a target's last failed attempt, or a `RuntimeError` when hooks were registered after it was patched. It is cleared when a retry succeeds, and `reset()` clears both dicts.
- New `HookRegistry.applied_targets() -> frozenset[str]` and `HookRegistry.failed_targets() -> dict[str, BaseException]` (a copy). `apply_hooks()` still never raises.

**Part 3: `required=True` per hook**

- `HookRegistry.register(..., required=False)` and `plugin_hook(..., required=False)`. A required hook that is never applied makes `load_plugins()` raise, whether or not its plugin is in `SGLANG_REQUIRED_PLUGINS`. A required hook with no plugin source is reported as `unknown`. Required hooks are kept in a separate `_required` set of `(target, index)` pairs, so `_hooks` entries stay `(hook_type, hook, source)` 3-tuples.

**Diffusion**

- Its `HookRegistry` subclass now also rebinds `_applied_count`, `_failed_targets` and `_required`, so diffusion and SRT state stay separate. Diffusion ignores the `required` flag; its failure semantics are unchanged.

**Docs (`plugin.mdx`)**: env-var table row; SRT paragraph in the failure-semantics section, including hooks registered too late; new "Required hooks and hook status" section under Registration API.

With `SGLANG_REQUIRED_PLUGINS` unset and no `required=True` hooks, behaviour is unchanged. The only new log line is a warning when a hook is registered after its target was already patched, which `main` dropped silently.

**For plugins that read private registry state:** `HookRegistry._patched` and the 3-tuple `_hooks` entries are unchanged, because several out-of-tree plugins read them (for example sglang-omni, and plugins that patch a target themselves and add it to `_patched`). `applied_targets()` and `failed_targets()` are the public way to get the same information.

Example: `offload` is listed in `SGLANG_REQUIRED_PLUGINS` and hooks a renamed method; `late` registers a `required=True` hook after another plugin already applied hooks to the same target (traceback frames trimmed):

```
  | ExceptionGroup: hook apply failures (2 sub-exceptions)
  +-+---------------- 1 ----------------
    | RuntimeError: 1 hook(s) registered after example_target.fn was already patched.
    | The above exception was the direct cause of the following exception:
    | RuntimeError: late -> example_target.fn
    +---------------- 2 ----------------
    | AttributeError: type object 'Scheduler' has no attribute 'renamed_method'
    | The above exception was the direct cause of the following exception:
    | RuntimeError: offload -> sglang.srt.managers.scheduler.Scheduler.renamed_method
    +------------------------------------

The above exception was the direct cause of the following exception:

RuntimeError: Required plugins could not apply hooks: late -> example_target.fn; offload -> sglang.srt.managers.scheduler.Scheduler.renamed_method
```

  - cases 1.1–1.4: 1.1 with and without other plugins installed, 1.2 for both filters, 1.3, 1.4;

- `test/registered/unit/plugins/test_hook_registry.py`: a target that fails, then applies on a retry, leaves `failed_targets()` and appears in `applied_targets()`; `failed_targets()` returns a copy, so a caller clearing it cannot erase the failures `load_plugins()` checks; plugin-style access keeps working: `_hooks` entries unpack as 3-tuples, and a target a plugin patched itself and added to `_patched` is skipped, not wrapped twice.
- `test_diffusion_plugins.py`: a check that the diffusion `HookRegistry` rebinds every mutable state attribute of SRT's, so state added to the base class later cannot leak between the two registries.

On `main`, 14 of the new tests fail: every must-raise test and the three hook-status tests. All pass with this change. The new tests for late hooks, early-applied hooks, `required=True`, hooks registered during `apply_hooks()`, retry, the returned copy, plugin-style access and the diffusion state each also fail when the line they guard is removed.

Hooks registered at import time aren't covered by the final check. `_current_plugin_source` is only set around `func()` in `load_plugins()`, so a required plugin that registers at module scope registers here, during `ep.load()`, with `source=None`. That happens with `@plugin_hook`, or with `HookRegistry.register(...)` at module level as in the "Registration API" section of `plugin.mdx`. The check at the end of `load_plugins()` then skips it (`source is not None and ...`), so a renamed target in such a plugin still starts the server without the hook.

Reproduced on this PR: a required plugin whose `ep.load()` applies `@plugin_hook` to a missing target logs `Failed to apply hooks to ...`, and `load_plugins()` still returns normally.

Setting the context variable around `ep.load()` too would cover it (untested sketch):

```python
            token = _current_plugin_source.set(HookSource(ep.name, dist_name))
            try:
                func = ep.load()
            finally:
                _current_plugin_source.reset(token)
```

A test with a fake entry point whose `load()` applies `@plugin_hook` to a missing target would pin it.
