## Motivation

The one-batch benchmark's dummy tree cache omits `req_to_token_pool`. The shared allocation path now reads both pools from that cache through `allocation._storage()`, so benchmark prefill crashes before inference:

```text
AttributeError: 'TreeCacheNamespace' object has no attribute 'req_to_token_pool'
```

Observed on both platforms while testing #46623:
- [XPU breakable-graph test](https://github.com/sgl-project/sglang/actions/runs/40812402872/job/123245676561)
- [Xeon AMX benchmark test](https://github.com/sgl-project/sglang/actions/runs/40812402949/job/123245685163)

This is a shared benchmark wiring issue, not a device-kernel change. The failure reproduces on upstream main at `60d56ea943b74d8fc1ccf59bb3cfb4f9dedfc3fd`.

## Modifications

- Pass the model runner's existing request pool into the benchmark's `TreeCacheNamespace`.
- Keep this PR to the one-line wiring fix; existing XPU breakable-graph and Xeon AMX benchmark tests exercise the affected path.

No serving configuration, model math, or kernel behavior changes.
