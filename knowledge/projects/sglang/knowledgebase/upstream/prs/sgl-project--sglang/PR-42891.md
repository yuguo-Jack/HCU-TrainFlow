## Motivation

DeepSeek-V4 runs its own two-batch-overlap layer loop (`DeepseekV4Model._forward_layers_tbo`), and its layers carry no residual between them, so each microbatch's output has `residual=None`. Since #42307, the shared `_model_forward_tbo_merge_outputs` reads both outputs' residual as a `ResidualStream`, so DeepSeek-V4 prefill with `--enable-two-batch-overlap` fails at the first merge:

```
AttributeError: 'NoneType' object has no attribute 'pending'
```

The AMD nightly `test_deepseek_v4_flash_fp8_tbo.py` fails with this error; there is no NVIDIA test for DeepSeek-V4 two-batch overlap.

## Modifications

- Move the token-range concatenation into `_model_forward_tbo_merge_key(output_a, output_b, name, original_len)`. DeepSeek-V4 merges its hidden states with it directly; the stream-carrying merge keeps its single caller, `model_forward_stages`. The old path only completed an owed sum on DeepSeek-V4's output, and `hc_post` returns a plain tensor, so dropping it changes no value.
- Add the NVIDIA counterpart of the AMD nightly: `test_deepseek_v4_flash_fp4_b200_tbo.py` (registry `nightly-4-gpu-b200`) launches DeepSeek-V4-Flash with TP 4, attention DP 4, DeepEP and `--enable-two-batch-overlap`, gated on GSM8K ≥ 0.93.

## Accuracy Tests

- The 13 two-batch-overlap and DeepSeek-V4 unit test files give the same results on `main` and with this change.
- 4× B200, `deepseek-ai/DeepSeek-V4-Flash-0731`, launched as the new nightly test does:
  - `main` (`6cc661f223`, and again at `a34cba3c62`): the first two-batch-overlap prefill raises the `AttributeError`.
  - This change on `6cc661f223`: the nightly test passes with GSM8K 0.970. Each of the 4 DP ranks enters and merges the overlapped layer loop 8 times, on prefills of up to 3,907 tokens.
  - The top of this stack on `main` `a34cba3c62`, 200-question 5-shot GSM8K: 0.960 and 0.960 with two-batch overlap (two launches). `main` `a34cba3c62` without two-batch overlap scores 0.970.
