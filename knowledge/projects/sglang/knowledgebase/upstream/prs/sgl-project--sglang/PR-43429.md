# Support smollm3

[Upstream PR](https://github.com/sgl-project/sglang/pull/43429) · state: open · merged: False

## Original PR description

Adds native support for SmolLM3 model implementation. 

#43428 

## Motivation

Add native support for [SmolLM3](https://huggingface.co/HuggingFaceTB/SmolLM3-3B) (`SmolLM3ForCausalLM`). SmolLM3 is a Llama-style architecture, except that RoPE is skipped on the layers that `config.no_rope_layers` marks as NoPE (every 4th layer in the released checkpoint). Without native support, the model only runs through the Transformers fallback backend.

## Modifications

- `python/sglang/srt/models/smollm3.py`: new model built on the Llama classes. `SmolLM3Attention` disables rotary embedding on NoPE layers. It also uses the PP stage's first RoPE layer to refresh the shared cos/sin cache, which only happens on `start_layer`, so this matters when a stage starts on a NoPE layer. Raises `NotImplementedError` for `use_sliding_window=True`, which no released checkpoint uses.
- `test/registered/unit/models/test_smollm3_rope_policy.py`: CPU unit tests for per-layer RoPE selection and the guards for unsupported configs.
- `test/registered/e2e/models/test_generation_models.py`: adds `HuggingFaceTB/SmolLM3-3B` to the HF-vs-SGLang logits comparison.
- `docs/docs/supported-models/generative_models.mdx`: lists SmolLM3.

## Accuracy Tests

All results below were collected on a single NVIDIA T4 (16GB), with the server launched using default flags: `python -m sglang.launch_server --model-path HuggingFaceTB/SmolLM3-3B --port 30000`. The baseline adds `--model-impl transformers`.

GSM8K, 200 examples, `python3 -m sglang.test.run_eval --eval-name gsm8k --num-examples 200`.

| Implementation | GSM8K |
|---|---|
| SGLang native (this PR) | 0.915 |
| Hugging Face Transformers Implementation | 0.910 |

## Speed Tests and Profiling

I collected this by running command:`python3 -m sglang.bench_serving --backend sglang --dataset-name random --random-input-len <in> --random-output-len <out> --max-concurrency 16 --num-prompts 80`, using the same server settings as above. Each server got one warm-up run before measurement. Values are the mean ± stdev over 3 runs.

**input 256 / output 32**

| Metric | SGLang native (this PR) | `--model-impl transformers` | Change |
|---|---|---|---|
| Mean TTFT (ms) | 143.41 ± 32.05 | 215.54 ± 14.73 | −33% |
| Request throughput (req/s) | 13.12 ± 1.79 | 9.14 ± 0.79 | +44% |
| Output token throughput (tok/s) | 207.69 ± 28.33 | 144.73 ± 12.48 | +44% |

**input 2048 / output 128**

| Metric | SGLang native (this PR) | `--model-impl transformers` | Change |
|---|---|---|---|
| Mean TTFT (ms) | 947.68 ± 46.33 | 978.64 ± 37.76 | −3% (within noise) |
| Request throughput (req/s) | 2.05 ± 0.11 | 1.81 ± 0.04 | +13% |
| Output token throughput (tok/s) | 128.66 ± 6.92 | 113.24 ± 2.27 | +14% |

At 2048 input tokens, TTFT is dominated by prefill compute, and the two implementations are at parity on the T4. Native is faster on throughput at both lengths and on TTFT for short prompts.
