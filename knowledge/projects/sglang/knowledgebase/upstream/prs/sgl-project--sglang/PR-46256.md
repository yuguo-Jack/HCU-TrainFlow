# [Perf] deepseek-v4: Reuse combined sparse-prefill indices

[Upstream PR](https://github.com/sgl-project/sglang/pull/46256) · state: open · merged: False

## Original PR description

## Motivation

DSv4.1 sparse prefill reuses indexer top-k results across attention layers, but currently rebuilds the combined compressed and sliding-window indices at every consuming layer. Reuse that combined result until an index producer updates its inputs.

## Modifications

- Cache combined indices and lengths within one forward, with explicit invalidation before each index producer.
- Track the last writer because different compression ratios share output storage; check the original source tensor, generation, shapes, strides and output buffers before reuse.
- Limit reuse to large eager MegaAttention prefill. Keep existing computation for capture, breakable graphs, replay tail, CP, TBO, SBO and smaller batches.

## Accuracy Tests

- 160 local production cache/kernel checks passed, including strided rows, in-place updates after invalidation, ratio alternation, replacement tensors, fallback writes and new forwards.
- Separate full-model shadow validation recomputed every reused result: 4,110 checks matched indices and lengths exactly, including 2,010 full-shape checks per rank. Instrumented timings were excluded.
- Native GSM8K, 1,314 examples, 5-shot, temperature 0, maximum 4,096 output tokens, simulated acceptance disabled: baseline 1,277/1,314 (97.18%), candidate 1,275/1,314 (97.03%). Both runs completed with 1,314 nonempty responses. This is an accuracy comparison, not a claim of identical generated responses. Only the initial cold batches exceed the reuse threshold; later cached small batches use the fallback. The separate full-model shadow run provides direct fast-path equality coverage.

Every arm drained 8,192 requests and passed all official guards. Independent replay of retained completions reproduces the original scored steps, duration, tokens and grouping exactly. Startup Engram huge-page coverage matched across arms.

Earlier measurements used script `e2a4a3bc138903e7b4a788173e7575a0aa129af0`, before rank-local RNG and raw-completion retention. Those separate ABBA groups reported +0.15025% (1,024 requests/rank) and +0.15354% (4,096 requests/rank). They remain historical observations and are not pooled with the new protocol. The latest table is the current repeated confirmation. Full-model shadow coverage confirms 15 avoided index-combination launches per full step per rank.

These are small, workload-specific full-model prefill engine-step gains, not application-level end-to-end gains. No standalone microbenchmark or registered internal-helper test is added.
