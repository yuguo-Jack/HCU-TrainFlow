# [Fix] cutedsl-mla: Use CuTeDSL MLA for draft prefill and extend

[Upstream PR](https://github.com/sgl-project/sglang/pull/43417) · state: open · merged: False

## Original PR description

Make `--speculative-draft-attention-backend cutedsl_mla` select CuTeDSL for draft prefill/extend as well as decode. Previously, the factory silently constructed TRTLLM MLA for prefill/extend.

Construct `CuteDslMLABackend(skip_prefill=False)`, preserve its backend identity, and use the existing MLA model-dispatch handler. **Merge [#46331](https://github.com/sgl-project/sglang/pull/46331) first** for ragged request packing, reusable buffers, and widened graph windows. Those fixes and their regression tests are kept only in that PR. Draft-only selection also validates SM100 support and KV-cache dtype without changing the target prefill backend. No new kernels or default-backend changes.

### Validation

- After merging main `b702f0d80e`, the focused CPU suites pass **149 tests and 253 subtests** (one skipped), covering model overrides, backend selection, and MLA dispatch. Ragged-packing coverage stays in #46331. The draft-only configuration regression fails before the validation fix.
- Prior combined-branch GPU validation, including #46331: **22 GB300 backend comparisons passed** against float32 causal attention, covering CuTeDSL/TRTLLM prefill, uniform/ragged drafts, graph replay, and buffer reuse after graph setup.
- Full-model end-to-end accuracy remains unvalidated.
- Downstream Kimi 2.6 INT4 Pulse results on TP4 GB300 were mixed: batch 1 improved **2.4–3.3%**; completed batch 4–64 points ranged from **−2.8% to +1.1%**. Both curves were incomplete and used a zero LoRA adapter on different nodes. These are not measurements of the upstream head and establish no broad throughput benefit.
