# [Fix] mimo: Keep tool calls with nullable schemas, overflowing numbers, or batched stream chunks

[Upstream PR](https://github.com/sgl-project/sglang/pull/46565) · state: open · merged: False

## Original PR description

## Motivation

`MiMoDetector` (`--tool-call-parser mimo`) drops tool calls in three cases:

1. **A parameter schema uses a `type` list, e.g. `{"type": ["string", "null"]}`.** `_get_param_type` returns the list, and `_convert_param_value` calls `.startswith` on it, which raises `AttributeError`. In the non-streaming path, `serving_chat` catches the exception and returns the whole `<tool_call>` block as plain content, so the call is lost. OpenAI strict-mode schemas and many MCP tools use this form. `anyOf` schemas (`Optional[int]`) don't crash, but they fall back to `"string"`, so `5` comes back as `"5"`.
2. **The model emits a number that overflows, e.g. `1e400`.** `int(float("1e400"))` raises `OverflowError`, which is not in the `except` tuple. The call is lost the same way.
3. **One streaming chunk contains more than one complete `<tool_call>` block** (MTP, `--stream-interval > 1`, parallel tool calls). `parse_streaming_increment` handles only the first block. The rest stays in the buffer and is lost if no further chunk arrives. MiMo doesn't override `finish()`, so nothing flushes it at stream end.

Repro (CPU only):

```python
from sglang.srt.entrypoints.openai.protocol import Function, Tool
from sglang.srt.function_call.mimo_detector import MiMoDetector

tools = [Tool(type="function", function=Function(name="search", parameters={
    "type": "object", "properties": {"site": {"type": ["string", "null"]}}}))]
text = "<tool_call>\n<function=search>\n<parameter=site>github.com</parameter>\n</function>\n</tool_call>"
MiMoDetector().detect_and_parse(text, tools)
# AttributeError: 'list' object has no attribute 'startswith'
```

## Modifications

- `_get_param_type` now resolves the type through the shared `infer_type_from_json_schema` helper (the same approach `Qwen3CoderDetector` uses). It handles `type` lists, `anyOf`/`oneOf`, `enum`, etc.
- The number branch of `_convert_param_value` also catches `OverflowError` and falls back to the raw string, the same fallback it uses for other conversion failures.
- `parse_streaming_increment` loops until no complete block is left in the buffer. Per-block bookkeeping moves into `_parse_complete_block`. Single-block behavior is unchanged.
- New `test/registered/unit/function_call/test_mimo_detector.py`, registered in `base-a-test-cpu`, with one regression case per bug. All four fail on `main` and pass with this change. They are in a new file because `test_function_call_parser.py` is already about 6k lines.

Out of scope, to discuss separately: a string parameter whose value is literally `null` becomes `None`, an invalid boolean silently becomes `false` (the same pattern as #42764 for qwen3_coder), and text after the last tool call is never released in streaming.
