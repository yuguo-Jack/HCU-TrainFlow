# [Feat] nvfp4: Support phase-selective W4A16 and per-token scaling

[Upstream PR](https://github.com/sgl-project/sglang/pull/46339) · state: open · merged: False

## Original PR description

## Motivation

@humansand

Select NVFP4 activation precision independently for prefill and decode while keeping one configured MoE backend. For example, use CuTe DSL per-token W4A4 prefill and W4A16 decode.

## Modifications

- **Environment contract:** `SGLANG_FLASHINFER_CUTEDSL_NVFP4_W4A16` and `SGLANG_FLASHINFER_NVFP4_PER_TOKEN_ACTIVATION` accept `prefill` or `decode`. Existing boolean spellings remain compatible; `true`, `1`, and `all` enable both phases, while `false`/`0` disable them.
- **Backend scope:** W4A16 controls supported FlashInfer CuTe DSL dense/MoE and FlashInfer MegaMoE paths. It is a no-op on other backends, including Muse Spark's custom TRT-LLM experts. Backend selection and backend weight-layout contracts remain unchanged; this PR adds no per-phase backend arguments or cross-backend weight views.
- **Scaling:** per-token selection applies to supported CuTe DSL/TRT-LLM NVFP4 MoE paths. Unset per-token scaling preserves the existing `nvfp4_online` default. All settings load and retain checkpoint activation scales. Static W4A4 uses those scales; per-token W4A4 uses online token scales and W4A16 bypasses activation scaling. Keep calibrated weight-times-activation scales alongside small weight-only scalar copies for W4A16 or per-token use; the kernel call selects the applicable scalars. Common preparation handles custom activation parameters for both variants. Online static W4A4 has only an uncalibrated unit activation scale.
- **Phase contract:** a local batch containing real prompt tokens uses prefill. Ordinary decode, speculative verification, and draft extension use decode. The first generated token still comes from prefill. The selection does not change KV-cache reuse.
- **State and capture:** prepare one shared weight/block-scale layout per backend. Phase selection passes the appropriate kernel and immutable scale arguments directly, without repacking weights or swapping layer metadata; refresh derived scales during weight reload. Warm both enabled precision paths before capture and include applicable selectors in autotune cache keys. Preserve the local batch phase through graph capture and nested overlap contexts.
- **Boundaries:** reject phase-selective execution with attention DP, whose ranks can run prefill and decode concurrently. Global boolean values remain valid with attention DP, and ignored W4A16 selectors remain no-ops on unsupported backends. FlashInfer MegaMoE currently requires attention DP, so its W4A16 control remains global in this PR. Muse Spark's custom NVFP4 path still rejects phase-selective per-token scaling. The new dense CuTe phase mode requires SM100-family GPUs; global W4A16 keeps its existing architecture-specific preparation. Existing backend/device/topology limitations remain. This change does not add a new Muse expert backend.

Example on one SM100-family GPU:

```bash
SGLANG_FLASHINFER_NVFP4_PER_TOKEN_ACTIVATION=prefill \
SGLANG_FLASHINFER_CUTEDSL_NVFP4_W4A16=decode \
python -m sglang.launch_server \
  --model-path Qwen/Qwen3-30B-A3B-Instruct-2507 \
  --quantization nvfp4_online --dtype bfloat16 \
  --moe-runner-backend flashinfer_cutedsl --moe-a2a-backend none
```

### Qwen3 serving smoke

BF16 `Qwen/Qwen3-30B-A3B-Instruct-2507`, all 48 MoE layers converted by `nvfp4_online`; one CuTe DSL runner, no A2A, TP=attention-DP=EP=1. Two batches of four greedy requests include a longer counting response. Prefill graphs are disabled in this server smoke; decode captures batch sizes 1, 2, and 4. The numerical GPU tests separately cover alternating prefill/decode graph replay.

The pinned image/source checkout lacks a usable Rust TreeCore extension, so the server explicitly selects the existing Python tree core. Kernel/tactic caches were warm. This is a functional smoke; startup timing and response latency fields are not benchmark results.

Server command (set `MODEL_PATH` to the downloaded BF16 checkpoint):

```bash
export MODEL_PATH=/path/to/Qwen3-30B-A3B-Instruct-2507
export CUDA_VISIBLE_DEVICES=4
export PYTHONPATH="$PWD/python"
export SGLANG_FLASHINFER_NVFP4_PER_TOKEN_ACTIVATION=prefill
export SGLANG_FLASHINFER_CUTEDSL_NVFP4_W4A16=decode
export SGLANG_FP4_IGNORED_LAYERS=''
export SGLANG_ENABLE_JIT_DEEPGEMM=False
export SGLANG_UNIFIED_RADIX_TREE_CORE_BACKEND=python
python -m sglang.launch_server \
  --model-path "$MODEL_PATH" \
  --tp-size 1 --ep-size 1 --attn-dp-size 1 \
  --quantization nvfp4_online --moe-runner-backend flashinfer_cutedsl \
  --moe-a2a-backend none \
  --cuda-graph-backend-prefill disabled --cuda-graph-max-bs-decode 4 \
  --max-running-requests 16 --max-total-tokens 16384 --context-length 4096 \
  --chunked-prefill-size 1024 --mem-fraction-static 0.4 \
  --watchdog-timeout 600 --log-level info --device cuda --host 127.0.0.1 --port 30124
```

After the server is ready, run the client in another shell with the same `MODEL_PATH`:

```python
import json
import os
import requests
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained(os.environ["MODEL_PATH"], local_files_only=True)
questions = [
    "Reply with only the integer: What is 2 + 3?",
    "Reply with only one word: What is the capital city of France?",
    "Reply with only the integer: What is 7 multiplied by 8?",
    "Count from 1 to 10, separated by commas. Reply with only the numbers.",
]
prompts = [tokenizer.apply_chat_template(
    [{"role": "user", "content": q}], tokenize=False,
    add_generation_prompt=True, enable_thinking=False,
) for q in questions]
results = []
for iteration in range(2):
    response = requests.post("http://127.0.0.1:30124/generate", json={
        "text": prompts,
        "sampling_params": {"temperature": 0, "max_new_tokens": 64},
    }, timeout=180)
    response.raise_for_status()
    values = response.json()
    assert len(values) == 4
    assert all(v["text"].strip() and v["meta_info"]["completion_tokens"] > 0 for v in values)
    assert values[3]["meta_info"]["completion_tokens"] >= 8
    results.append(values)
    print(json.dumps({"iteration": iteration, "responses": values}))
assert [v["text"] for v in results[0]] == [v["text"] for v in results[1]]
for actual, expected in zip(results[0], ["5", "paris", "56", "10"]):
    assert expected in actual["text"].lower()
print(json.dumps({"status": "PASS", "requests": 8}))
```
