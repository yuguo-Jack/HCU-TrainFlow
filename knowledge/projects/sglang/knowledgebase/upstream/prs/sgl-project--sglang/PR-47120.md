# [Fix] multimodal: Preserve strong identities across VLM caches

[Upstream PR](https://github.com/sgl-project/sglang/pull/47120) · state: closed · merged: True

## Original PR description

## Motivation

Multimodal cache equality must depend on actual model-facing content, not a short scalar or a caller-provided hint. The old GPU reduction admits structured collisions, composite keys lose information through `hash(tuple(...))`, and matching only part of a media placeholder can still reuse unrelated KV state.

This is a correctness-first fix across the shared VLM paths, not a model-specific opt-in or a universal speedup claim.

## Modifications

- Add shared CPU/GPU BLAKE3-256 with typed shape/dtype/container/metadata identities. GPU tensors transfer only their digests to the host.
- Preserve full identities through embedding caching, batch deduplication, sessions, EPD and native Rust sidecars. Rust output digests use full SHA-256 and bind the serving configuration at ingress.
- Namespace KV requests using ordered full media identities and `cache_salt`. Short or partial placeholder matches cannot substitute for complete identity equality.
- Stop allowing caller `mm_hashes` to override content identity, including precomputed embeddings. Keep the separate explicit `--trust-mm-content-hashes` boundary documented.
- Preserve Kimi source/config/grid protections; cover composite processors and finalized OCR metadata. Reuse full Qwen/Muse artifact fingerprints on cache hits instead of rehashing their feature tensors.
- Add common-contract, kernel, native/transport and real Qwen input regressions, plus documentation of compatibility and prefix-sharing tradeoffs.

The GPU BLAKE3 kernel is adapted from @xupinjie's #46028; author credit is preserved. Related narrower work: #44653, #46552, #46815 and #47066. This PR does not modify diffusion conditioning caches or include #37537.

## Speed Tests and Profiling

Matched Qwen serving: CUDA IPC, 64 MiB preprocess cache, context 8192, memory fraction 0.45, CUDA graphs off, max running 8, seed 37, one greedy output token. After three warmups: 33 changing images and 20 same-image requests. Baseline was repeated twice. Median milliseconds:

| Workload | Baseline changing | Candidate changing | Baseline same image | Candidate same image |
| --- | ---: | ---: | ---: | ---: |
| 224 image | 40.62-40.70 | 41.47 | 21.83-21.85 | 22.18 |
| 1024 image | 68.26-68.82 | 72.67 | 29.55-29.81 | 29.63 |
| Shared 2048-token text + 224 image | 41.07-41.14 | 42.66 | 22.44-22.74 | 22.74 |

Generated token IDs matched in these benchmark cases. Full identity checking adds work on changing-media requests. Different media deliberately no longer share their common text KV prefix; same ordered media still shares it. Long shared-prefix workloads can incur a larger prefill penalty.

Interleaved 100-sample GPU microbench, including host synchronization: 12 MiB raw BLAKE3 **0.099 ms**, typed identity **0.128 ms**, versus old GPU64 **0.100 ms** and D2H+CPU BLAKE3 **3.068 ms**. At 153 MiB, raw BLAKE3 is **0.301 ms** versus old GPU64 **0.237 ms**. This avoids feature-sized D2H, but is not uniformly faster than the old weak GPU hash. Dense hashing needs small scratch buffers; noncontiguous inputs require a contiguous copy. No saturated-throughput claim.
