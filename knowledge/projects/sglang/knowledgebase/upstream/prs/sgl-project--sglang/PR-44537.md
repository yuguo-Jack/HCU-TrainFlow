# [Fix] tokenizer_manager: re-report only emitted customized_info keys on cumulative streams

[Upstream PR](https://github.com/sgl-project/sglang/pull/44537) · state: closed · merged: True

## Original PR description

## Motivation

Cumulative (non-incremental) streaming re-reports every key in `ReqState.customized_info_accumulated` on each frame, so a key that arrived on an earlier queued output still reaches the client when only the last queued output is returned (#43772). That re-report also exposes accumulators a `TokenizerManager` subclass deliberately keeps out of `meta_info`: a per-token list accumulated on the request state but never written to a response showed up, raw and growing, on every cumulative frame.

## Modifications

- `ReqState` gains `customized_info_reported_keys`: the accumulated keys that `_accumulate_request_meta_info` has written to `meta_info`.
- The cumulative-stream re-report in `_stream_one_response` iterates only those keys. Keys accumulated on the state without being written to a response stay out of it.
- `test_cumulative_stream_backlog_preserves_customized_info` now accumulates the re-reported key through `update_request_meta_info` and adds a hidden accumulator that must not appear in the merged frame. It fails without the fix and passes with it.
