# [diffusion] Hunyuan3D: implement paint_use_remesh (decimate to 40k faces before UV unwrap)

[Upstream PR](https://github.com/sgl-project/sglang/pull/42770) · state: open · merged: False

## Original PR description

## Motivation

Hunyuan3D-2 texturing spends about 3 minutes UV-unwrapping a mesh that the official pipeline decimates first.

- At the default octree resolution (384), the shape stage outputs about 650k faces. The CI reference mesh has 655,500.
- The official pipelines decimate to 40k faces before texturing:
  - Hunyuan3D-2 `gradio_app.py` calls `face_reduce_worker` (`FaceReducer`, `max_facenum=40000`) before `texgen_worker`.
  - Hunyuan3D-2.1 `textureGenPipeline` runs `remesh_mesh` when `use_remesh=True`, which decimates to 40,000 faces.
- #18170 added `paint_use_remesh: bool = True` to `Hunyuan3D2PipelineConfig`, but nothing reads it. `xatlas.parametrize` therefore runs on the full mesh. Its cost grows superlinearly with face count.

In H100 CI, `Hunyuan3DPaintPreprocessStage` takes about 218 s of the 237 s E2E for `hunyuan3d_shape_gen`. That time is CPU-only, so it tracks runner CPU speed: p50 232 s, p90 267 s, max 322 s since 10-03. Since #42505, E2E is this case's most common failure.

## Modifications

- `mesh3d_utils.mesh_simplify`: decimates a mesh to at most 40,000 faces with quadric-error edge collapse, implemented in numpy (`_qem_decimate`). No new dependency is added.
- `Hunyuan3DPaintPreprocessStage._unwrap_mesh`: decimates before `mesh_uv_wrap` when `paint_use_remesh` is set. The default (`True`) is unchanged; set it to `False` to keep the full mesh.
- Unit tests:
  - A mesh with more than 40k faces is decimated when `paint_use_remesh` is set, and left unchanged when it is not.
  - A closed mesh stays closed, with its shape preserved.
  - The boundary of an open mesh is kept.

User-visible change: the textured mesh has 40k faces instead of about 650k, which matches the official pipelines.

## Decimation implementation

`_qem_decimate` is a vectorized quadric-error edge collapse in numpy. Each round collapses many non-adjacent cheap edges at once, skips any collapse that would flip a triangle, and keeps boundary edges.

On the CI reference mesh, it matches `fast-simplification` in quality:

| | `fast-simplification` | numpy (this PR) |
| --- | ---: | ---: |
| Decimate | 0.7 s | ~6 s |
| `_unwrap_mesh` total | 4.6 s | 10.7 s |
| Chamfer vs. reference | 0.0010 | 0.0010 |

`fast-simplification` is the MIT C++ library that trimesh's `simplify_quadric_decimation` wraps. Switching `mesh_simplify` to `fast_simplification.simplify(vertices, faces, target_count=...)` would save about 5 s per request, at the cost of adding it to the diffusion extras.

## Validation

`xatlas.parametrize` time against face count on the CI reference mesh (`hunyuan3d.glb`), measured on a local AMD EPYC 9354:

| Faces | UV unwrap |
| ---: | ---: |
| 655,500 (current) | 186 s |
| 200,000 | 41.9 s |
| 100,000 | 12.3 s |
| 40,000 (this PR) | 4.5 s |

On the same mesh, `_unwrap_mesh` now takes 10.7 s end to end and returns 40,000 faces with UVs.

The CI mesh check is unaffected. Using the same Chamfer check as `validate_mesh_correctness` (4096 samples), the decimated mesh scores 0.0010 against the reference. The reference scores the same 0.0010 against itself, which is the sampling noise. The threshold is 0.0299.

Other meshes reach the exact target face count, with Chamfer at the sampling-noise level:

- An icosphere, a torus and a subdivided box stay watertight.
- An open half-sphere keeps its boundary edges.

Unit tests in `test_hunyuan3d_native_texture_models.py` pass (12) without `fast-simplification` installed. The `hunyuan3d_shape_gen` H100 baselines (E2E and paint stages) will be tightened in a follow-up commit, using this PR's CI measurements.
