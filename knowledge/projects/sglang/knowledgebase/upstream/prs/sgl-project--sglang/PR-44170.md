# [Bugfix] Reserve the symmetric-memory prealloc out of the KV budget

[Upstream PR](https://github.com/sgl-project/sglang/pull/44170) · state: open · merged: False

## Original PR description

## Motivation

Fixes #44106.

`--enable-symm-mem` preallocates a 4 GiB symmetric-memory pool in
`finalize_cuda_graph_capture`, **after** the KV pool is sized. That
allocation is not charged against `--mem-fraction-static`, so a config
that fits without the flag can OOM during warmup or the first NCCL
verify broadcast once the flag is on. MLA models also skip
post-capture KV resize, so the leftover slack never grows to cover the
pool.

This is the same class of bug as the existing multimodal reservation:
memory that is allocated only after KV sizing has to come out of the KV
budget, not the runtime slack.

## Modifications

- Add `symm_mem_runtime_reservation_gb()` next to `mm_runtime_reservation_gb()`.
- Subtract that reservation in `KVCacheConfigurator._profile_available_bytes`.
- Keep the default 4 GiB prealloc, and note in the warning that it is
  taken out of the KV budget.
- CPU regression tests: helper cases plus an explicit
  `--mem-fraction-static=0.90` profile that still loses 4 GiB.

NCCL CUMEM/NVLS buffers still come from leftover slack. The reporter's
0.90 vs 0.88 working delta on B200 is ~4 GiB, which matches the
prealloc pool. Shrinking `SGLANG_SYMM_MEM_PREALLOC_GB_SIZE` is not used
as a workaround (see #36943).

## Accuracy Tests

Not applicable — memory accounting only; no model-forward or sampling
change.

## Speed Tests and Profiling

Not applicable. KV capacity drops by the prealloc size when the flag is
on (4 GiB by default), which is the intended trade for not OOM'ing after
start-up.
