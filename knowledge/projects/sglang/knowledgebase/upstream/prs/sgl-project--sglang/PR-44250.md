# [AMD][DSv4.1] Use the fused Triton router for VL routing on ROCm

[Upstream PR](https://github.com/sgl-project/sglang/pull/44250) · state: open · merged: False

## Original PR description

## Motivation

DeepSeek-V4.1-Flash VL routing uses the fused Triton router only on CUDA. On ROCm, prefill batches with images fall back to an eager softplus → topk → gather → renormalize chain. In a 16k-token VL prefill chunk on MI350X (TP4) that chain costs about 19 ms per chunk, mostly in `gatherTopK`. B200 spends about 1 ms on the fused router for the same chunk.

The Triton router has no CUDA-only code on ROCm: its only CUDA-specific feature is PDL, and PDL is already off on HIP. Text-only routing and decode are unchanged.

## Modifications

## Accuracy Tests

- New GPU test `test/registered/kernels/ops/moe/test_dsv41_vl_router.py`, registered for CUDA and AMD CI. It runs the fused and eager VL routing paths on the same mixed image/text batch (384 experts, top-6, with and without a fused shared expert, with padded rows) and checks that they select the same experts with the same weights, and that padded rows stay empty. Passes on MI355X (`rocm/sgl-dev:v0.5.21-rocm724-mi35x-20261012`, 8/8 subtests), and fails if the fused kernel is disabled, so it does exercise the fused path on ROCm. The edited CPU test passes too.
- Standalone check on MI350X at the DSv4.1 shape (384 experts, top-6, routed scaling 1.5), M from 1 to 16384: identical expert selection in 16/16 cases (one exact score tie), max weight difference 1.8e-7.
- MMMU on MI350X, TP4: 0.7539 with this change (2 runs), the same as without it (0.7539).
