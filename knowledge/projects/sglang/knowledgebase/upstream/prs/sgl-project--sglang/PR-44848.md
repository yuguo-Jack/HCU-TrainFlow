# [Doc] cookbook: Allow PD with DSpark for DeepSeek-V4.1

[Upstream PR](https://github.com/sgl-project/sglang/pull/44848) · state: closed · merged: True

## Original PR description

- Drop `DSPARK` from the DeepSeek-V4.1 Playground's `pdDisagg.incompatibleSpeculativeAlgorithms`, so the prefill and decode roles of a DSpark recipe keep the DSpark flags instead of stripping them
- Replace "PD and speculative decoding cannot be combined." in section 3.4 with the conditions the server checks at startup (`deepseek_v4_hook.py`): Mooncake or NIXL transfer, static ragged verify (the default), and CP=1, DCP=1 on decode

The Playground output changes: PD role commands for the GB300, B200 and B300 low-latency recipes and both MI355X recipes now include `--speculative-algorithm DSPARK --speculative-dspark-block-size 5`.
