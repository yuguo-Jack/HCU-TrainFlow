# [Fix] tracing: report quick_finish stage before trace context aborted

[Upstream PR](https://github.com/sgl-project/sglang/pull/40423) · state: open · merged: False

## Original PR description

## Motivation

`RequestStage.DECODE_QUICK_FINISH` is declared with `metrics_is_observed=True`,
but nothing reports it, so the `quick_finish` span never appears in a trace and
its per-stage latency is never observed. The identifier occurs exactly once in
the tree — at its own declaration.

`set_quick_finish_time()` only stamped timestamps:

```python
def set_quick_finish_time(self, ts=None):
    ts = ts or time.perf_counter()
    self.set_completion_time(ts)
    self.forward_entry_time = ts
```

Its neighbours stamp *and* report. For example `set_decode_prebuilt_finish_time()`,
called on the line immediately before it in `process_batch_result_prebuilt()`:

```python
def set_decode_prebuilt_finish_time(self, ts=None):
    ts = ts or time.perf_counter()
    self.decode_prebuilt_finish_time = ts

    stage = RequestStage.DECODE_FAKE_OUTPUT
    self.observe_per_stage_req_latency(stage, ts - self.last_forward_entry_time)
    self.trace_slice(stage, self.last_forward_entry_time, ts)
```

Of the 13 setters that only stamp, 12 are start/end pairs whose end half reports
the stage — `set_spec_draft_start_time` with `set_spec_draft_end_time`, and so on.
`set_quick_finish_time()` has no end half, so its stage has no reporter at all.

## Ordering

The report has to come **before** `set_completion_time()`. That call does:

```python
if self.trace_ctx.tracing_enable:
    self.trace_ctx.abort()
```

and `abort()` ends with `self.thread_context = None`, after which
`__check_fast_return()` returns True and `trace_slice()` returns at its first
line. A slice appended after `set_completion_time()` would read correctly in the
diff and emit nothing at runtime.

## Modifications

Report the stage the way the neighbouring setters do, before the completion call,
reusing `last_forward_entry_time` as the slice start so the timeline stays
consistent with `DECODE_FAKE_OUTPUT` recorded just before it.

## Accuracy Test

Two tests in `test/registered/unit/observability/test_req_time_stats.py`:

- `test_quick_finish_reports_its_stage` — the collector receives
  `quick_finish` with the expected latency, and `trace_slice()` is called with
  the stage and both timestamps. Fails on `main`, where neither happens.
- `test_stage_is_reported_before_the_context_is_aborted` — records the call
  order and asserts the slice precedes `set_completion_time()`. This is the part
  that would silently regress if the report were ever moved after the abort.
