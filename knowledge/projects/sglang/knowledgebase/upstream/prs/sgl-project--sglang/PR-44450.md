## Motivation

When loading a model from S3 (e.g., via `runai_streamer`) without specifying `--served-model-name`, the default served model name inherits the URI containing a colon (:), such as `s3://xxx.` During engine warmup, the parser mistakenly interprets the colon as a delimiter for a LoRA adapter (<lora_name>:<lora_path>). As a result, the engine crashes because the LoRA adapter cannot be found.

## Modifications

Refactor `_parse_model_parameter` to properly distinguish between URI schemes (e.g., s3://) and LoRA specifications, preventing false-positive LoRA resolution.
