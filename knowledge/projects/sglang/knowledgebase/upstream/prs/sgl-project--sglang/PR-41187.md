# [DCP + L3 1/N] Support MLA DCP with HiCache file L3 across matching engines

[Upstream PR](https://github.com/sgl-project/sglang/pull/41187) · state: open · merged: False

## Original PR description

## Why?

1. HiCache L3 rejects DCP.
2. This stack adds MLA + DCP + L3 support:
   - #41187 (this PR): file storage.
   - #41265: Mooncake storage.
   - #41591: hybrid MLA/KDA storage.

## What?

1. Allow file L3 with DCP for one materialized MLA host pool using `layer_first`, `page_first`, or `page_first_direct`. Keep existing validation; split buffers, separate scale buffers, and additional pools remain unsupported.
2. Pass `is_storage_owner` to file eviction instead of deriving ownership from `is_mla_model`. Select one writer per distinct MLA shard, avoiding duplicate writes and eviction accounting:

```text
TP=4 / DCP=2:
rank 0 writes shard 0 -> ranks 0,2 read
rank 1 writes shard 1 -> ranks 1,3 read
2 files per logical page
```

3. Translate logical page positions into physical rows and count only complete logical pages:

```text
64 physical tokens/shard x 2 = 128 logical tokens
logical start 256 -> physical start 128 on each rank

Both shards present -> complete page hit
Either shard missing -> stop before that page
```

KV-format/layout key separation remains deferred with a TODO; engines sharing files must use compatible formats and layouts.

## Tests?

- Six focused CPU tests added to existing CI-registered file-backend and host-pool tests. No new test files.
- CPU regressions: **62 tests and 40 subtests passed**, covering DCP keys/ownership, page mapping, file eviction, attachment, and prefetch.
- **Previously validated manually on H200**, DeepSeek-V2-Lite-Chat, BF16, TP=4/DCP=2, `page_first`, write-through, complete-prefetch waiting: **1 passed in 149.48 s**.

```text
Cold writer:  1,025 input tokens -> 16 files, zero cache hits
Fresh reader: 1,024 L3 tokens    -> identical output IDs
Missing shard in page 2:        -> 128 L3 tokens, identical output IDs
```

- Ruff, import ordering, registered-test validation, and whitespace checks passed. The history rewrite preserves the cleaned Git tree exactly. CI status is tracked below.
