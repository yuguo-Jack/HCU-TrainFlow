# [Fix] dsv4: Never read attention metadata for idle SWA stores

[Upstream PR](https://github.com/sgl-project/sglang/pull/45699) · state: closed · merged: True

## Original PR description

- `get_swa_out_cache_loc` in the DeepSeek V4 CUDA and HIP backends returns for an idle forward before it reads `forward_metadata`, which an idle forward may leave stale or unset: the request window's idle layout (`RequestWindow.activate_idle`) when there is one, else the zero-padded `out_cache_loc` translated to the dummy slot, as idle already used. The later `not is_idle()` check goes away.
- HIP: with `--enable-encoder-swa-bounded-replay`, an idle forward read the request-window layout of a stale or unset `forward_metadata`, the crash #45586 fixed on CUDA; it now takes the idle layout.
- CUDA and HIP without a request window: an idle forward whose stale metadata still carried a `late_layer_tail` returned that tail's store locations, sized for another batch; it now takes the dummy slot. Whether a stale tail reaches an idle forward was not traced.
- Verified on CUDA: GB300, DEP4 DeepSeek V4.1 Flash with MegaMoE and DSPARK, GSM8K (sgl-eval, 200 examples) 97.00% with encoder SWA bounded replay and 97.50% without, no scheduler exception. The HIP change is untested on hardware.

No behavior change outside idle forwards.
