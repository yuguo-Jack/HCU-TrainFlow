# [Fix] [AMD] rotary: Pass a query-dtype cos_sin_cache to the HIP fallback

[Upstream PR](https://github.com/sgl-project/sglang/pull/46161) · state: closed · merged: True

## Original PR description

## Motivation

On ROCm, Qwen3-Next-80B-A3B-Instruct-FP8 does not start on current `main`  6d6c9cd4ae (main as of 2026-10-23 00:50 PDT). CUDA graph capture fails on MI355X with:

```
Exception: Capture cuda graph failed: expected scalar type BFloat16 but found Float
```

HIP keeps `cos_sin_cache` in fp32 for the fused QSA indexer (#41282). `main` already has `cos_sin_cache_as()` to hand kernels a cached copy in the activation dtype, but the HIP branch of the `fallback_rotary_embedding` path in `rotary_embedding/base.py` does not use it. It passes the fp32 buffer to `sgl_kernel.rotary_embedding`, which reads the cache as the query dtype.

#42483 fixed this by adding a private helper and using it at this call site. It was closed as redundant. Since then `main` gained the equivalent public helper, but not the call-site change, so the crash remains. This PR is only that missing half.

## Modifications

`python/sglang/srt/layers/rotary_embedding/base.py`, fallback branch of `forward_cuda`:

- On HIP, pass `self.cos_sin_cache_as(query.dtype)` to `fallback_rotary_embedding` instead of the fp32 buffer. The fp32 buffer stays in place for the indexer. The cast copy is reused until the buffer is replaced (moved or extended), so steady state adds no cast.
- Only move the buffer when it is on a different device than the query.
- Non-HIP behaviour is unchanged: the buffer is still cast in place to the query device and dtype.

`test/registered/unit/layers/test_rope_hip_fallback_cache_dtype.py`: CPU unit test (`base-a-test-cpu`) that drives the HIP fallback branch with a mocked kernel and checks, for fp16 and bf16:

- the kernel receives the cache in the query dtype, with values equal to the fp32 buffer cast down;
- a second call reuses the same copy, and `cos_sin_cache` is still the original fp32 buffer;
- extending the cache invalidates the copy, and the next call gets a fresh one at the new length.

It fails on `main` with `AssertionError: torch.float32 != torch.float16`.

## Accuracy Tests

4× MI355X (gfx950), TP4, `Qwen3-Next-80B-A3B-Instruct-FP8`, image `lmsysorg/sglang-rocm:v0.5.20-rocm724-mi35x-20260929`, on `main` 6d6c9cd4ae with this change applied:

- Without the change, the server fails CUDA graph capture as above and does not start.
- With it, the server starts, and GSM8K 1319q (`python -m sglang.test.few_shot_gsm8k --num-questions 1319 --parallel 256`) scores **0.942**, `Invalid: 0.000`.

## Benchmarking and Profiling

Not a performance change. The fallback now gets a cast copy that is built once and then reused, instead of the fp32 buffer it could not consume.
