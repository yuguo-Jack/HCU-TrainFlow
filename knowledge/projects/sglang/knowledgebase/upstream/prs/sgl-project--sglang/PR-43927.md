# [Feat] runtime: Include FlashInfer’s default tactic in startup tuning.

[Upstream PR](https://github.com/sgl-project/sglang/pull/43927) · state: closed · merged: True

## Original PR description

## Motivation

Startup tuning can omit FlashInfer's default tactic (`-1`) and select an explicit tactic even when the default is faster for the profiling inputs. This adopts v2 candidate selection with existing v1 persistence.

## Modifications

- Import `autotune_v2` from FlashInfer and enter `autotune_v2(mode="tune", persistent_cache=False)` immediately after the existing `autotune(...)` context. Measurement policy remains unspecified.
- Retain existing v1 JSON load/save persistence, cache-disabled behavior, skip controls, streams, and distributed synchronization. Managed-store migration is excluded; upstream's existing MegaMoE integration is retained without changes.
- Add one `autotune_v2` stub to the existing upstream startup-test fixture, which already mocks the v1 tuner. No new test is added.
