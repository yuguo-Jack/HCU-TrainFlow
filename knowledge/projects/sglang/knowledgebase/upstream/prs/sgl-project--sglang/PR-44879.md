# [Perf] deepseek_v4: write the indexer's page slots with one kernel per prefill layer

[Upstream PR](https://github.com/sgl-project/sglang/pull/44879) · state: closed · merged: False

## Original PR description

## Motivation

Stack-attributed torch-profiler trace of a DeepSeek-V4.1-Flash DEP2 prefill step on GB300 (MegaAttention, MegaMoE, Mega-mHC, eager prefill, one 16K-token cold chunk per rank): each ratio-1 and ratio-2 indexer layer on the DeepGEMM prefill path ends with `DeepGEMMPrefillData.write_page_indices`, which turns the request-local top-k into index-K pool slots with four elementwise launches (`add`, `clamp_min`, gather, `where` plus the slice copy) after `reset_outputs` filled the page buffer with -1. That is 64 launches per step from `write_page_indices` and 14 from the fills, for under 30 µs of GPU work per layer, while each launch costs 40 to 65 µs of dispatch on the eager path.

## Modifications

- `kernels/ops/attention/dsv4/index_page_slots.py`: one Triton kernel, one program per row, that gathers `k_slots[raw + request_start]` where `raw >= 0` and writes -1 elsewhere, over the full width of the raw buffer (512 for DeepSeek-V4.1, looped in 1024-wide blocks for wider ones).
- `v41_indexer/scoring.py`: `write_page_indices` calls it on CUDA; the torch expression stays as the fallback.
- `v41_indexer/types.py`, `full_topk.py`, `sparse_table.py`: `reset_outputs(page_indices=False)` on the two paths whose page write covers every row and column the attention reads, so the page-buffer fill is skipped there. The raw-buffer fill stays. `dense_blocks.py`'s `write_selection` path is unchanged and keeps both fills.
- `test/registered/kernels/ops/attention/test_dsv4_index_page_slots.py`: kernel against the torch expression at widths 1 to 2048, with -1 entries, and checks nothing outside the target rows and columns is written.

Per indexer layer on this path: 6 launches become 2.

## Measured

GB300, DEP2 (TP2 + DP attention, EP2), MegaMoE, Mega-mHC, decoder bounded replay, eager prefill, 16K-token prefill budget per rank, same node, on top of #44875 (job 3487) against that plus #44878 and this change together (job 3488; the two landed in the same run because the cluster worktree is a live mount).

| Rank 0, cold 16K chunk, profiled step | before | after |
|---|---:|---:|
| Kernel launches | 1,407 | 1,303 |
| Page-slot launches per indexer layer on this path (add, clamp, gather, where, copy, fill) | 6 x 8 | 1 x 8 (`_index_page_slots_kernel`) |
| Launches removed by the gate scaling of #44878 | | 40 |

| Unprofiled, median of 3 (ms) | before | after |
|---|---:|---:|
| 1 x 16K cold chunk per rank | 191 | 190 |
| 1 x 128K cold prompt, eight chunks | 1,511 | 1,501 |

GPU kernel time is unchanged; the gain is dispatch on the eager path. GSM8K on GB300 (DEP2, DSpark with real acceptance, greedy, 1,314 examples): 0.9741 with all three of #44875, #44878 and #44879 applied (job 3495) and 0.9741 on the same stack without them (job 3496), the same 1,280 correct.

## Before and after

Perfetto, GPU stream of rank 0, the indexer epilogue of the same ratio-2 layer (from `index_q_kernel` to the attention kernel).

Before (job 3487): 19 slices; after `topk_select` come the add, clamp, gather, where and copy of `write_page_indices` plus the -1 fill, six launches.

![after, indexer epilogue](https://raw.githubusercontent.com/kpham-sgl/sglang/assets-prefill-h2h-2026-10-16/prefill-h2h-2026-10-16/pr44879-after-job3488-indexer-epilogue.jpg)

## Is the gain significant?

Marginal on its own. It removes 64 launches (4% of the step) and no GPU time, so the wall time moves under 1% on a 16K step. Together with #44875 and #44878 the three remove about 210 of the 500 glue launches the step carries over its kernels proper, and the cold 16K step goes 194 to 190 ms on the same node. All three are eager-path gains that vanish under a prefill CUDA graph.
