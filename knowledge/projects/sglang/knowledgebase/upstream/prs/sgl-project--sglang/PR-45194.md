# [Fix] disagg: Bound Mooncake registration decoding

[Upstream PR](https://github.com/sgl-project/sglang/pull/45194) · state: open · merged: False

## Original PR description

## Motivation

Mooncake Prefill decodes registration metadata from a peer-controlled packed-list frame. The list count was trusted before validating the frame or comparing it with the local model layout. As reported in #45012, a 400,004-byte frame can declare 100,000 empty child buffers, causing Python to materialize and retain 100,000 lists for one fake Decode session.

This PR addresses that parser-amplification vector. It intentionally does not claim to add peer authentication or a global peer-table policy.

## Modifications

- Validate packed-list headers, length tables, payload totals, and integer element alignment before decoding.
- Add optional list-count bounds to the shared wire decoder.
- Bound Mooncake registration state lists by the local model state-component count before creating any child lists.
- Decode validated integer lists directly from the original frame, avoiding temporary child-buffer slices.
- Convert malformed registration metadata into a dropped peer registration instead of letting the bootstrap receive thread exit.

## Speed Tests and Profiling

Compared current upstream `72d886efb8` with this PR at `fc82ed6d2d` on Python 3.10.12 pinned to one CPU. Valid-path numbers are medians of 9 paired AB/BA trials. The empty-state case used 50,000 registrations per trial; the 4-component case used 2,000 per trial.

| Registration case | Upstream | This PR | Delta |
| --- | ---: | ---: | ---: |
| Empty state metadata | 6.177 us/op | 6.005 us/op | -2.8% |
| 4 state components, 80 entries each | 35.103 us/op | 34.619 us/op | -1.4% |

The reported attack frame was measured over 7 independent allocations with `tracemalloc` started after the shared 400,004-byte input frame was created, so the memory column is incremental parser allocation.

| 100,000-list attack | Upstream | This PR | Reduction |
| --- | ---: | ---: | ---: |
| Parse result | accepted | rejected | before child-list creation |
| Median parser time | 171.555 ms | 0.0199 ms | 8,610x |
| Median incremental peak | 7,203,115 B | 1,354 B | 5,320x |

`cProfile` attributes the upstream attack to 100,000 list appends and 100,000 element unpack calls. The patched path reads the count and raises before either loop. The validation code runs only for bootstrap/registration metadata, outside model forward execution; the valid-path measurements above show no registration regression.
