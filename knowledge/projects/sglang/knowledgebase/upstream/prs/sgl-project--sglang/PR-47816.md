# [Fix] sampling: Allow seeded min-p sampling in the torch sampler

[Upstream PR](https://github.com/sgl-project/sglang/pull/47816) · state: open · merged: False

## Original PR description

## Motivation

`top_k_top_p_min_p_sampling_from_probs_torch` asserts `sampling_seed is None` whenever min-p is on, with a TODO saying the filtered probabilities would have to be renormalized before `multinomial_with_seed`. So any request that sets both `sampling_seed` and `min_p` fails on the torch sampling backend.

Renormalizing is not needed. `multinomial_with_seed` is a Gumbel-max: it takes `argmax(log w + gumbel_noise)` per row. Dividing a row by its sum only subtracts the same constant from every `log w` in that row, so the argmax, and the sampled token, are unchanged. Tokens zeroed by min-p become `log 0 = -inf` and are never picked.

The same function already relies on this: top-k and top-p zero entries of `probs_sort` without renormalizing, and the seeded branch passes those unnormalized weights to `multinomial_with_seed`. The Ascend path (`top_k_top_p_min_p_sampling_from_logits_ascend`) and the MLX sampler (`hardware_backend/mlx/sampling.py`, "Gumbel-max over the UNNORMALIZED masked weights ... also what keeps a seeded row well-defined under min_p") already sample seeded min-p rows this way.

## Modifications

- `python/sglang/srt/layers/sampler.py`: remove the `sampling_seed is None` assert and the renormalization TODO from the min-p branch of `top_k_top_p_min_p_sampling_from_probs_torch`. The min-p filter itself is unchanged.
- `test/registered/sampling/test_seeded_min_p_sampling.py` (new, 1-GPU CUDA CI next to `test_deterministic_gumbel_u1.py`):
  - Seeded min-p sampling over 4096 rows returns exactly the tokens of a seeded draw from the explicitly renormalized min-p weights.
  - 200k seeded draws from one row never pick a min-p filtered token, and the frequencies match the renormalized min-p distribution within 0.01.

Both tests fail on `main` with the removed assert and pass with this change.

## Accuracy Tests

Only requests that set both `sampling_seed` and `min_p` take the changed path; they previously raised. Other requests are unaffected.

H200, 200k seeded draws from probabilities `[0.40, 0.30, 0.15, 0.10, 0.05]` with `min_p=0.3`:

| Weights passed to `multinomial_with_seed` | token 0 | token 1 | token 2 | tokens 3, 4 |
|---|---|---|---|---|
| min-p filtered, not renormalized | 0.4691 | 0.3535 | 0.1774 | 0 |
| min-p filtered, renormalized | 0.4691 | 0.3535 | 0.1774 | 0 |
| target (renormalized min-p distribution) | 0.4706 | 0.3529 | 0.1765 | 0 |
