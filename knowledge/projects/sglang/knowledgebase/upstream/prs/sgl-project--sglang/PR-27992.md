# [diffusion] Add FlashInfer trtllm-gen skip-softmax (BLASST) attention backend for DiT

[Upstream PR](https://github.com/sgl-project/sglang/pull/27992) · state: closed · merged: False

## Original PR description

## Motivation

PR #19089 added skip-softmax (BLASST) attention to the **LLM serving** path
(`srt`) by wiring `SGLANG_SKIP_SOFTMAX_*_THRESHOLD_SCALE_FACTOR` into the
`trtllm_mha`/`trtllm_mla`/`nsa` KV-cache backends. There is currently **no
equivalent for the diffusion (`multimodal_gen`) path**, whose DiT self-attention
is a long-sequence, no-KV-cache ragged FMHA — exactly the regime where
skip-softmax helps.

This PR adds skip-softmax to the diffusion DiT attention stack and validates it
end-to-end on **Wan2.2-T2V-A14B** (B200 / SM100).

## What this adds

A new opt-in attention backend, `flashinfer_trtllm_skip_softmax`
(`--attention-backend flashinfer_trtllm_skip_softmax`), which runs FlashInfer's
hand-tuned **trtllm-gen** ragged FMHA (`flashinfer.prefill.trtllm_ragged_attention_deepseek`)
with BLASST skip-softmax.

Target HW is **SM 10.x** (B200/B300). On SM 10.x FlashInfer's `auto` dispatch
selects the `trtllm-gen` kernels where skip-softmax is a first-class citizen; on
SM 12.x (consumer Blackwell) the same APIs silently fall back to `xqa`, which
*ignores* the skip-softmax threshold (a silent no-op). The backend therefore
explicitly rejects non-SM10.x GPUs with an actionable error.

### Files

- `runtime/layers/attention/backends/flashinfer_trtllm_skip_softmax_attn.py` (new) — `FlashInferTrtllmSkipSoftmaxBackend` + `Impl`.
- `runtime/layers/attention/backends/_modelopt_skip_softmax_calib.py` (new) — pure-stdlib BLASST calibration helper.
- `runtime/platforms/interface.py` — register `FLASHINFER_TRTLLM_SKIP_SOFTMAX` enum.
- `runtime/platforms/cuda.py` — dispatch + SM10.x preflight gate.
- `configs/models/dits/wanvideo.py` — add the backend to the Wan attention whitelist (kept Wan-scoped until other DiTs are validated).
- `tools/calibrate_wan22_skip_softmax.py` (new) — offline BLASST calibration for Wan2.2 (produces the JSON consumed at inference).
- `tools/README_skip_softmax_calibration.md` (new) — usage notes for the calibration script.
- `test/unit/test_modelopt_skip_softmax_calibration.py` (new) — unit tests for the calibration helper.

### Design notes

- **Threshold semantics.** trtllm-gen uses `effective_threshold = scale_factor / context_length`. The BLASST calibration fits `lambda = a*exp(b*target_sparsity)/seq_len_k`, so we pass `scale_factor = lambda * seq_len_k = a*exp(b*target_sparsity)` to FlashInfer.
- **CLI / calibration.** `--attention-backend-config target_sparsity=...,calibration_path=...`; or `fixed_scale_factor=...` to bypass calibration and pass a raw scale factor.
- **Safe fallbacks** (each falls back to dense `torch_sdpa` for that launch): cross-attention (`Q.seqlen != K.seqlen`), non-bf16/fp16 dtype, non-positive threshold, or any kernel exception. The backend is intentionally **not** marked `is_sparse`, so Wan cross-attention selects it and degrades gracefully to SDPA (rather than being filtered out and falling back to an unrelated backend).

## Correctness

- Microbench vs `torch_sdpa` on Wan shape (H=40, D=128), bf16: dense `max_diff ≈ 2.4e-4` (non-causal), `2.0e-3` (causal); skip path finite across `scale_factor ∈ {1,100,1000}`.
- Backend smoke: 10/10 PASS (self-attn skip ≈ SDPA; cross-attn/fp32/no-config fall back to SDPA; batch=2 distinct-qkv ≈ SDPA; skip-softmax verifiably changes output on structured input — the mechanism is live, not a no-op).

## End-to-end results (Wan2.2-T2V-A14B, 832×480×81f × 50 steps, single B200, SM100)

Baseline = **trtllm-gen dense (skip-softmax off)** — the exact same kernel with
the threshold effectively disabled (`fixed_scale_factor=1e-4`). Reporting against
the dense kernel isolates the contribution of skip-softmax itself. Sparsity is set
via the resolution-agnostic `target_sparsity` knob plus a real Wan2.2-14B BLASST
calibration (`flat (a,b) = (1120.54, 5.208)`, ModelOpt `DynamicThresholdCalibrator`);
the backend converts each target to the per-sequence `scale_factor` internally.

**NVFP4** (peak mem 57.5 GB, constant across targets)

| target_sparsity | s/step | vs dense |
|---|---|---|
| dense (skip off) | 2.759 | 1.00× (baseline) |
| 0.1 | 2.574 | 1.07× |
| 0.2 | 2.545 | 1.08× |
| 0.3 | 2.507 | 1.10× |
| 0.5 | **2.389** | **1.16×** |

**FP8** (peak mem 66.3 GB, constant across targets)

| target_sparsity | s/step | vs dense |
|---|---|---|
| dense (skip off) | 2.629 | 1.00× (baseline) |
| 0.1 | 2.533 | 1.04× |
| 0.2 | 2.509 | 1.05× |
| 0.3 | 2.469 | 1.06× |
| 0.5 | **2.344** | **1.12×** |

Weight-quant precision (NVFP4 vs FP8) is orthogonal to attention here — QKV are
de-quantized to bf16 before attention, so skip-softmax behaves the same: both
dense baselines (FP8 2.629, NVFP4 2.759) scale monotonically with target, and skip
only saves attention FLOPs (peak memory is unchanged; NVFP4 is ~9 GB lighter).

### Attention-kernel level (Nsight Systems, real Wan self-attn, 32k seq, per-call)

Isolating just the self-attention kernel confirms the end-to-end numbers are
attention-driven:

| config | attn kernel time/call | vs dense |
|---|---|---|
| dense (skip off) | 17.53 ms | 1.00× |
| skip t=0.5 | 14.98 ms | **1.17×** |

Skip-softmax removes ~14.5% of the attention-kernel time; end-to-end this dilutes
to ~8.6% because attention is not the only cost of a denoising step.

> Scope: this PR intentionally does **not** claim a speedup vs `torch_sdpa`. On a
> correctly configured fast SDPA path (cuDNN) the dense attention kernel is already
> on par with trtllm-gen dense on this workload; the value reported here is the
> skip-softmax increment on top of the trtllm-gen kernel.

## Speed/quality sweep (target_sparsity, real 14B calibration)

Speedups are vs the **dense (skip off)** kernel of the same precision. Quality is
measured vs each precision's dense output (PSNR/SSIM/LPIPS, 81-frame mean,
LPIPS=AlexNet) and is a **4-prompt average (mean ± std)** — these quantify
**divergence from the dense baseline**, not absolute quality.

**NVFP4** (dense = 2.759 s/step)

| target | s/step | vs dense | PSNR↑ | SSIM↑ | LPIPS↓ |
|---|---|---|---|---|---|
| 0.1 | 2.574 | 1.07× | 19.33 ± 3.52 | 0.679 ± 0.092 | 0.214 ± 0.064 |
| 0.2 | 2.545 | 1.08× | 19.69 ± 5.21 | 0.694 ± 0.097 | 0.221 ± 0.088 |
| 0.3 | 2.507 | 1.10× | 17.91 ± 3.50 | 0.631 ± 0.097 | 0.276 ± 0.073 |
| 0.5 | 2.389 | 1.16× | 13.53 ± 0.94 | 0.469 ± 0.116 | 0.439 ± 0.102 |

**FP8** (dense = 2.629 s/step)

| target | s/step | vs dense | PSNR↑ | SSIM↑ | LPIPS↓ |
|---|---|---|---|---|---|
| 0.1 | 2.533 | 1.04× | 17.82 ± 6.12 | 0.630 ± 0.161 | 0.278 ± 0.132 |
| 0.2 | 2.509 | 1.05× | 17.20 ± 5.71 | 0.602 ± 0.142 | 0.295 ± 0.110 |
| 0.3 | 2.469 | 1.06× | 15.62 ± 4.14 | 0.541 ± 0.121 | 0.358 ± 0.086 |
| 0.5 | 2.344 | 1.12× | 12.40 ± 1.66 | 0.413 ± 0.092 | 0.486 ± 0.041 |

Takeaways: quality degrades monotonically with sparsity (read **SSIM / LPIPS**;
PSNR stays noisy even at a 4-prompt average — diffusion trajectory divergence is
chaotic per prompt). A reasonable operating point is **target ≈ 0.2–0.3** (NVFP4
SSIM ~0.63–0.69, LPIPS ~0.22–0.28); target=0.5 trades a few extra percent of speed
for a large quality drop. **NVFP4 beats FP8 at equal target** — both faster (vs its
own dense) and better quality. Skip-softmax is expected to help more at longer
context / higher resolution (BLASST's target regime).

## Usage

```bash
# SM10.x (B200/B300)
--backend sglang \
--attention-backend flashinfer_trtllm_skip_softmax \
--attention-backend-config 'target_sparsity=0.3,calibration_path=/path/wan22_calib.json'
# or bypass calibration with a raw scale factor:
--attention-backend-config 'fixed_scale_factor=3489'
```

`--backend sglang` is required for the skip-softmax backend to actually engage.
With the default `--backend auto`, if native model-config resolution fails (e.g.
`HF_HUB_OFFLINE`, network/cache issues, or a repo whose `model_index.json` can't be
resolved) the engine silently logs `Falling back to diffusers backend` and runs the
vanilla pipeline's own attention, **ignoring `--attention-backend`** (skip-softmax
never runs). Confirm the log shows `Using FlashInfer trtllm-gen Skip-Softmax (BLASST)
Attention backend`.

### Generating the calibration file

The `calibration_path` above points to a JSON produced offline by
`python/sglang/multimodal_gen/tools/calibrate_wan22_skip_softmax.py`
(see `python/sglang/multimodal_gen/tools/README_skip_softmax_calibration.md`). It loads the real Wan2.2-T2V-A14B pipeline and
runs ModelOpt's `DynamicThresholdCalibrator` to fit
`scale_factor = a*exp(b*target_sparsity)` per denoiser. Requires `nvidia-modelopt`
and a Model Optimizer checkout that ships
`examples/diffusers/sparsity/wan22_skip_softmax.py`.

```bash
python python/sglang/multimodal_gen/tools/calibrate_wan22_skip_softmax.py \
  --modelopt-example /path/Model-Optimizer/examples/diffusers/sparsity/wan22_skip_softmax.py \
  --model-path Wan-AI/Wan2.2-T2V-A14B-Diffusers \
  --width 1280 --height 720 --num-frames 81 \
  --target-sparsity 0.5 --calib-steps 8 --calib-size 2 \
  --out ./wan22_calib_14b_720p.json
```

Calibration is resolution dependent — calibrate at the resolution you serve.
