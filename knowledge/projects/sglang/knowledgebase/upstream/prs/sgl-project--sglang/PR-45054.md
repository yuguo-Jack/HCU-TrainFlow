# [Feat] ngram: let each request draft from its own prompt

[Upstream PR](https://github.com/sgl-project/sglang/pull/45054) · state: open · merged: False

## Original PR description

## Motivation

Code edits, text revisions, and document quotes often repeat parts of the prompt. NGRAM can draft from its online trie and external corpora, but only the last `max_trie_depth` prompt tokens enter the trie. Most of the prompt is unavailable as a draft source.

This PR lets each request draft from its own prompt. It covers the "SAM for user request's input" item in #21052 and builds on #44957.

## Modifications

Add two server args:

| Arg | Default | Purpose |
|---|---|---|
| `--speculative-ngram-prompt-sam-budget` | `0` (off) | Draft nodes for the request's prompt |
| `--speculative-ngram-prompt-sam-max-tokens` | `32768` | Maximum number of recent prompt tokens to index |

```bash
python -m sglang.launch_server --model-path Qwen/Qwen2.5-Coder-7B-Instruct \
  --speculative-algorithm NGRAM --speculative-num-draft-tokens 16 \
  --speculative-ngram-prompt-sam-budget 8
```

The worker builds a suffix automaton (SAM) once for each request. It uses a separate draft budget, so prompt drafts do not take slots from external corpora. Construction runs outside the corpus mutex to avoid a long pause for other requests.

The worker tracks the request itself as well as its ID. A new request that reuses an ID gets fresh state and its own prompt SAM. Later decode steps and prefill retries of the same request keep that state.

## Accuracy Tests

- CPU tests: **144 passed**, plus **31 subtests**. The suite covers the corpus, request state, worker prompt, Mamba updates, and sampling params.
- The six new worker tests also pass through the registered CI entry point. They cover a reused ID with a new prompt or corpus choice, later decode steps, prefill retries, chunked prefill, and cache cleanup.
- Both reuse cases produced old drafts before the fix and adopted the new request data after it.
- Pre-commit checks passed for both changed files.

The earlier `TestNgramPromptSam` run passed on one H100. All three test prompts produced identical output with prompt SAM on and off.

## Speed Tests and Profiling

Earlier result on one H100 80GB with `Qwen/Qwen2.5-Coder-7B-Instruct`, flashinfer, and 16 draft tokens:

| | Prompt SAM off | Prompt SAM on, budget 8 |
|---|---|---|
| Average accept length | 1.35 | 3.60 |
| Decode throughput, one request | 160 tok/s | 408 tok/s |

Each of three prompts asked the model to add type hints to a short Python function. The test used greedy decode, 256 output tokens, and a fresh cache for each prompt. GPU tests and benchmarks were not rerun for the request-state fix.
