# [Feat] ngram: let each request draft from its own prompt

[Upstream PR](https://github.com/sgl-project/sglang/pull/45054) · state: open · merged: False

## Original PR description

## Motivation

Many requests repeat large parts of their input. Some examples are editing code, rewriting text, and answering with quotes from a document. NGRAM speculative decoding should guess these tokens easily, but it can only draft from tokens it has already indexed: the online trie and any external corpora. Most of the prompt is not indexed, because only the last `max_trie_depth` input tokens go into the trie. As a result, copy-heavy requests miss most of the drafts they could get from their own input.

This PR lets each request draft from its own prompt. It implements the "SAM for user request's input" item in #21052.

## What this PR adds

Two server args:

| Arg | Default | Meaning |
|---|---|---|
| `--speculative-ngram-prompt-sam-budget` | `0` (off) | Draft nodes given to the request's own prompt |
| `--speculative-ngram-prompt-sam-max-tokens` | `32768` | Number of most recent prompt tokens to index |

Example:

```bash
python -m sglang.launch_server --model-path Qwen/Qwen2.5-Coder-7B-Instruct \
  --speculative-algorithm NGRAM --speculative-num-draft-tokens 16 \
  --speculative-ngram-prompt-sam-budget 8
```

## How it works

When a request first reaches the NGRAM worker, its prompt is indexed into a suffix automaton (SAM) that belongs only to that request. On every decode step, the request then drafts from three sources: the online trie, the external corpora, and its own prompt SAM. The prompt SAM has its own budget, so it does not take slots from the external corpora. When the request finishes, its prompt SAM is freed together with its match state.

The SAM is built once per request in C++ (`Ngram::setPromptSam`). Building it takes time linear in the prompt length, so it runs outside the corpus mutex, and a long prompt does not block matching for other requests. Later steps send nothing extra from Python.

This PR builds on #44957, because both change the same loop in `Ngram::batchMatch`.

## Results

**Setup:** 1×H100 80GB, `Qwen/Qwen2.5-Coder-7B-Instruct`, flashinfer, 16 draft tokens.

**Task:** Each of 3 prompts asks the model to add type hints to a short Python function, so most of the answer copies the input. Greedy decoding, 256 new tokens, and the cache was flushed before each prompt.

| | prompt SAM off | prompt SAM on (budget 8) |
|---|---|---|
| Avg accept length | 1.35 | **3.60** |
| Decode throughput (1 request) | 160 tok/s | **408 tok/s** |

The outputs were identical for all 3 prompts with the feature on and off.

## Tests

- Unit tests (CPU), `test_ngram_corpus.py`:
  - a request drafts from its own prompt;
  - the feature is off by default;
  - one request cannot see another request's prompt;
  - the prompt SAM is freed when the request ends;
  - only the last `prompt_sam_max_tokens` tokens are indexed;
  - prompt drafts combine with external corpus drafts.
- `test_ngram_corpus.py` and `test_server_args.py`: 357 passed.
- End-to-end on 1×H100: the new `TestNgramPromptSam` passes.
