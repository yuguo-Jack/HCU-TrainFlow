# [Feat] [NVIDIA] deepseek-v4: add opt-in row-wise MoE pipelines

[Upstream PR](https://github.com/sgl-project/sglang/pull/48189) · state: open · merged: False

## Original PR description

## Motivation

Context-parallel prefill can expose a long tail of MoE AllGather and ReduceScatter work when an entire row block is processed at once. This adds an opt-in, model-internal row pipeline for the CUDA SM120 DeepSeek-V4 FlashInfer CUTLASS MXFP4 path, using the current boundary/residual interfaces.

This is a **draft** pending CUDA model accuracy and performance validation on this main-branch port. The historical measurements below motivate the design; they do not validate this revision.

## Modifications

- **Row-wise MoE Pipelining (RMP)** partitions CP-local rows and submits gather, experts, and reduce-scatter in a consistent order. **Epilogue-Pipelined MoE (EPM)** also prepares the attention output projection and mHC per slice. These replace the historical experiment names C004 and C007.
- **Cross-Layer Query Lookahead (QLA)** waits for a slice's RS, adds its local shared expert once, and completes closing mHC before computing the next layer's query front. Full attention/KV dependencies remain in the normal path. Caches are invocation-owned, checked by identity, consumed once, and cleared on request completion/abort.
- Add six explicit environment controls, disabled by default. Configuration is snapshotted at layer initialization. Unsupported topology, routing, shared-expert backend, fusion, capture, and bounded-tail paths retain normal execution. The existing upstream PP1 restriction for pre-from-prev execution is preserved.
- Include a detailed [technical report](https://github.com/xyDong0223/sglang/blob/b98441f/benchmark/deepseek_v4/row_pipeline/REPORT.md), six editable SVG figures, full precision historical measurements, and an offline plotting script. Machine-specific deployment identifiers and paths are excluded. [Controls and reproduction instructions](https://github.com/xyDong0223/sglang/blob/b98441f/benchmark/deepseek_v4/row_pipeline/README.md).

## Accuracy Tests

- Focused CPU suite: **13 tests and 17 subtests passed**. Covers row partitioning, communication submission/drain order, synthetic four-rank nonuniform expert reduction and local shared addition, query results, cache ownership/expiry, scale-layout bytes/padding, and the actual default-off CUDA-layer forward control flow with boundary fakes.

  ```bash
  PYTHONPATH=python python -m pytest test/registered/unit/models/test_deepseek_v4_moe_pipeline.py -q
  ```

- All applicable repository pre-commit hooks passed; Python compilation and new local import-target/symbol checks passed.
- The broader existing boundary/pipeline/platform suites could not collect in the local macOS environment because the GPU-stack dependency `tvm_ffi` is unavailable. These suites and real CUDA event/collective behavior still require the configured CI environment.
- **Not yet run:** new-main CUDA model-output validation, target-GPU integration, and accuracy evaluation. CPU synthetic equivalence is not a replacement for those checks.

## Speed Tests and Profiling

Historical experiment: one uncached 65,536-token request on eight PRO6000 Server GPUs, CP4/EP4/PP2, 10 serial unprofiled samples per path with inputs paired across configurations.

| Historical path | Prefill p50 (ms) | Prefill p90 (ms) |
| --- | ---: | ---: |
| Four row slices, EPM/QLA, packed MXFP8 gather | 1,202.767 | 1,205.738 |
| One row block, controls off, BF16 gather | 1,773.829 | 1,777.293 |

The historical p50 reduction is **32.19% for a combined intervention**: row count, epilogue scheduling, query lookahead, and gather format changed together. No isolated QLA speedup or port performance is claimed. Historical PP2 results do not establish PP2 support for this main-branch path. The report separately identifies native-service data, precision-aligned core UTs, and frozen B200 80K data.

Before leaving draft, validate on the target CUDA deployment: default/off versus enabled logits and model accuracy, ragged/padded request behavior, cache expiry and aborts, unsupported-path fallback, and fresh profiler-free timing plus traces. Keep input format and shared-expert semantics fixed when ablating individual switches.
