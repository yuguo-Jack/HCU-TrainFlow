## Motivation

On Kimi-K3 a4w4, the MoE prologue launches the router and the token-order MXFP4 quant as two kernels. Fuse them into one launch when the tuned GEMM consumes prequant activations. Leave the bf16 and f16in paths on their existing kernels.

## Modifications

- Add a fused radix route + MXFP4 quant launch on gfx942/gfx950 (`grid=2*M`): one half routes, the other quantizes the staged bf16 row in token order. Sort is unchanged and still runs after.
- Stage the routed latent from Kimi-K3 when `SGLANG_K3_RADIX4_TOPK=1` and `AITER_SITUV2_A4W4=1`. The runner takes the published fp4 only for a4w4 prequant token buckets; f16in / small-M keep bf16.
- Drop the DeepSeek-V4 fp4 header from the gfx942 software fallback so the kernel builds when that header still calls CUDA fp4 intrinsics, and pass bf16 as the MoE output dtype when the activation handed to `fused_moe` is fp4.

## Accuracy Tests

On gfx950:

- 36 non-aiter radix-4 unit tests passed
- Fused launch matches route-only ids and weights
- Fused MXFP4 bytes match `quant_mxfp4_hip` on random and all-zero rows
