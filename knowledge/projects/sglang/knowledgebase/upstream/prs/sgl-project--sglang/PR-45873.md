# [Fix] ci: Reduce runner utilization scan overhead and bound API retries

[Upstream PR](https://github.com/sgl-project/sglang/pull/45873) · state: closed · merged: True

## Original PR description

## Motivation

The [October 22 scheduled Runner Utilization report](https://github.com/sgl-project/sglang/actions/runs/39746895425/job/119717497971) passed its unit tests but hit the 55-minute report-step timeout. The October 20 and 21 scheduled reports also timed out. Buffered stdout hid scan progress, so the exact stalled endpoint or timeout cause cannot be recovered from that log.

A sample of 1,000 run records immediately before the failed scan (October 22, 07:41:20–08:19:49 UTC) contains 233 runs selected for job fetching by the current code. Of those, 136 (58%) are PR Check Comment or PR Title: metadata workflows whose only job runs on ubuntu-latest. Their workflow_run / pull_request_target events bypass the existing short pull_request / push filter. The [last successful daily scan](https://github.com/sgl-project/sglang/actions/runs/39222460273/job/117960743886) fetched 5,284 relevant runs and still exhausted retries on an HTTP 502 response.

## Modifications

- Exclude the two metadata workflows by exact workflow path, preserving GPU workflows whose PR-controlled titles mention those names and unknown workflow paths.
- Bound each `gh api` subprocess to 30 seconds and each endpoint's aggregate retry loop to 120 seconds. Keep transient-error retries, clip backoff to the remaining budget, and report the actual attempt count.
- Stream report progress with `python -u` and log retry endpoints/errors immediately.
- Include the report test file in the workflow's PR path filter.

The report's scan window, GPU job accounting, and existing incomplete-fetch handling are unchanged. This reduces measured redundant requests and bounds individual stalls; it does not establish that the full scheduled scan will finish within 55 minutes.

## Accuracy Tests

- Python 3.12: `python -m unittest discover -s scripts/ci/utils -p 'test_runner_utilization_report.py' -v` — 31 passed.
- Added regressions for metadata exclusion through collection, GPU title collisions, unknown paths, successful requests, permanent errors, transient recovery, hung requests, aggregate retry deadlines, and no sleep after the final attempt.
- All applicable repository pre-commit hooks passed, including formatting, import order, YAML/AST checks, and workflow job-name validation.
- Independent code review completed with no blocking findings.

## Speed Tests and Profiling

No inference code changes. The full production scan has not been rerun; the 58% reduction is an observation from the bounded historical sample, not a claimed end-to-end runtime improvement.

Prepared for review. **Do not merge yet.**
