# [Perf] diffusion: Write Wan's normed q/k straight into the Ulysses exchange

[Upstream PR](https://github.com/sgl-project/sglang/pull/46247) · state: closed · merged: True

## Original PR description

Stacked on #46246 (text K/V once per loop), which sits on #46245, #46244 and #46228 (the fused q/k norm-RoPE this PR extends). Also depends on #46145 (pipelined Ulysses same-device copies), carried here as cherry-picks of its two commits; review the commits after #46246 other than those.

## Motivation

Under pipelined Ulysses (Wan2.2 A14B 720p, 4xB300, CFG 2 x Ulysses 2) every block normed and rotated q and k in place, and the exchange then copied this rank's own rows of every head group into its receive slots: one same-device copy per tensor (`_copy_head_groups_kernel`, ~0.073 ms each, 0.27 ms per block for q, k, v and the output gather), on the critical path before the first head group attends. The existing `fill` hook lets a per-head QK-norm write each block itself, but Wan normalizes across all heads, so a block-at-a-time fill would reread whole rows once per block.

## Modifications

- `distributed/device_communicators/ipc_a2a_multi.py`: `pipelined_attention(..., fill_all=None)`: `fill` given every destination block at once, `[(head_start, head_count, q_dst, k_dst)]` over this rank's own slot rows and each peer's send block; the rest of the fill path (v's own rows copied, the peers' q/k blocks sent from the send buffers) is shared with `fill`.
- `layers/attention/layer.py`: `USPAttention.forward_qk_filled(q, k, v, fill_all)` runs the dense pipelined path with that hook (no first-sight reference: the pipelined backends attend a head group exactly as inside the full call) and returns None, having written nothing, whenever the call would not pipeline.
- `kernels/ops/diffusion/rope/rmsnorm_interleaved_rope_cutedsl.py`: `fused_rmsnorm_interleaved_rope_into_blocks(x, ..., dst_table)`: the same kernel, but each thread's 512-column run goes to row m of the contiguous block at `dst_table[run]` instead of back into `x`.
- `models/dits/wanvideo.py`: the block projects q/k/v, then `_attend_qk_filled` writes q and k into the exchange blocks through the address table (built once per set of exchange buffers) and attends; when that returns None (no Ulysses pipeline, capture, compile, offline q/k rotation, another attention op) the block runs its previous path on the untouched projections.

Same kernels on the same values, so outputs are bit-identical.

## Accuracy Tests

- `test_rmsnorm_interleaved_rope.py::test_into_blocks_matches_in_place`: every run lands in its block with the in-place result's bits, from a strided (fused-qkv) input, which stays untouched.
- `test_usp_pipelined_attention_multi_gpu.py` (2 and 4 ranks) passes on the branch.
- Wan2.2 T2V A14B 720p, 4xB300, 3-step lossless (crf 0) mp4: md5 identical to the base for 3 prompts; a profile shows one copy (v) instead of three before the first head group.

## Speed Tests and Profiling

Wan2.2 T2V A14B 720p, 4xB300, harness single_e2e, fresh server per run, interleaved in one round with TRT-LLM: base (#46246) 89.616 / 89.691 s -> 89.454 / 89.482 / 89.488 s (mean 89.475), -0.19%. After the memory-lifetime fixes in #46244 and #46246, the full stack measured 89.517 / 89.540 s against 89.556 s for this commit's stack in the same session: no regression.
