# [AMD] Add an opt-in AITER CK blockscale GEMM for gfx942 block-FP8 linears

[Upstream PR](https://github.com/sgl-project/sglang/pull/41071) · state: closed · merged: True

## Original PR description

## Motivation

On gfx942 with `SGLANG_USE_AITER=1`, `aiter_w8a8_block_fp8_linear` runs every dense block-FP8 linear on the AITER Triton blockscale GEMM; the CK blockscale GEMM it already imports is never used there, while vLLM sends gfx942 to CK. CK is much faster on gfx942 but lowers accuracy on Qwen3-32B-FP8 (below), so this PR adds it behind an opt-in flag instead of changing the default. It revives #26234, which was closed as stale without a review.

## Modifications

- `SGLANG_AITER_GFX942_BLOCKSCALE_USE_CK` (default `false`): on gfx942, run dense block-FP8 linears with the AITER CK blockscale GEMM. The default path and other devices are unchanged.
- `environ.py` and `environment_variables.mdx` add the flag.

## Accuracy Tests

8x MI300X (gfx942), ROCm 7.2.2, torch 2.10, AITER at the Docker pin (`e7d2453f`), main at `23f89061` with this PR; `SGLANG_USE_AITER=1 --mem-fraction-static 0.8 --context-length 16384 --chunked-prefill-size 16384`. One model per GPU (122B at TP 2); the default and CK arms ran as two back-to-back phases under the same load.

GSM8K (`sglang.test.few_shot_gsm8k`, 5-shot, 1319 questions, greedy):

| model | default (Triton) | CK |
|---|---|---|
| Qwen3-8B-FP8 | 0.893 | 0.889 |
| Qwen3-14B-FP8 | 0.880 | 0.877 |
| Qwen3-32B-FP8 (mean of 3 runs) | 0.832 | 0.809 |
| Qwen3-30B-A3B-FP8 | 0.853 | 0.869 |
| Qwen3-Next-80B-A3B-Instruct-FP8 | 0.939 | 0.942 |
| Qwen3.5-122B-A10B-FP8 | 0.960 | 0.957 |

Qwen3-32B-FP8 loses about 2 points with CK: 0.807–0.813 against 0.828–0.839 over three runs each, and 0.754–0.764 against 0.788–0.810 at temperature 0.6. Sending only its `o_proj` (N=5120, K=8192) back to Triton restores it, yet that GEMM's CK output matches Triton to bf16 rounding on every call we checked, including 54k calls inside the server. We could not find the cause, so CK stays opt-in.

## Speed Tests and Profiling

`sglang.benchmark.serving --dataset-name random-ids`, output tok/s, default → CK:

| model | 64 × (1024 in, 512 out), conc 4 | 384 × (8192 in, 1024 out), conc 128 |
|---|---|---|
| Qwen3-8B-FP8 | 445 → 508 (+14%) | 1338 → 1369 (+2%) |
| Qwen3-14B-FP8 | 103 → 388 (+277%) | 641 → 829 (+29%) |
| Qwen3-32B-FP8 | 42 → 173 (+314%) | 225 → 337 (+50%) |
| Qwen3-30B-A3B-FP8 | 275 → 633 (+130%) | 1741 → 2142 (+23%) |
| Qwen3-Next-80B-A3B-Instruct-FP8 | 255 → 524 (+106%) | 1934 → 2319 (+20%) |
| Qwen3.5-122B-A10B-FP8 | 228 → 493 (+116%) | 1476 → 1726 (+17%) |

Median TTFT drops for every model at conc 128, and for all but Qwen3-32B (892 → 910 ms) at conc 4. Qwen3-8B gains least because all four of its linear shapes have a gfx942-tuned Triton config in AITER, while most Qwen3-14B, Qwen3-32B and Qwen3-30B-A3B shapes fall back to Triton's default config.
