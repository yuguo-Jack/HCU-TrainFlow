# [Fix] speculative: Exact NEXTN penalties and add opt-in CORAL H100 overlay

[Upstream PR](https://github.com/sgl-project/sglang/pull/45233) · state: closed · merged: False

## Original PR description

## What

Publishes the framework changes used for Qwen3.6-35B-A3B FP8 + NEXTN MTP-4 on H100, so spec-on submission results have a public commit and PR.

Base: `v0.5.22` / `baa9befa381511cd4d56f83980951e5a45fffc6d`.

## Q6 penalty fix

Presence, frequency and repetition penalties were wrong under speculative verify:

- one requested penalty vector was broadcast to every verify row;
- earlier draft tokens in the block were absent from penalty state;
- only the last committed token was fed back after a multi-token accept.

The fix applies per-row penalties from earlier draft tokens, deduplicates set-based penalties per draft block, counts every prior frequency occurrence, and feeds every newly accepted output token into the penalizers. The result is token-for-token equivalent to the non-speculative target for the tested penalty cases.

## CORAL H100 overlay

`coral/` adds the opt-in `CORAL_*` kernel and SPEC_FUSE switches:

- H100 FP8 decode/MoE/GDN kernels;
- MTP draft-extend graph enablement;
- fused NEXTN top-k 1 draft-extend post-processing on v0.5.22;
- a Dockerfile that builds `coral/sglang:v0.5.22-q6-coral` from the public v0.5.22 image and applies the Q6 patch at build time.

The overlay is opt-in, does not modify the checkpoint or target head, and leaves upstream v0.5.22 commit indexing untouched (it already uses a fused kernel).

Our upstream audit found that the accepted-token accounting portion here overlaps my older #33643 (bot-closed stale draft, not merged). I will keep #33643 closed and track this implementation instead of reopening a competing fix.

The old regressions compared sequential per-token accumulation with a multi-token speculative commit, including unequal accepted lengths, padded tails, frequency/presence/repetition state and `min_new_tokens`. Your `penalty_cumulated_output_len` and accepted-output-token path address the same lost-token issue and additionally handle within-verify-block state. Please preserve the variable-length/padding and min-new-token checks when separating/rebasing the core fix from the CORAL overlay.

This is code/coverage coordination, not a GPU or model-accuracy endorsement of this PR. Its outstanding distribution/serving validation remains required. Our GLM historical throughput used simulated acceptance and is not supporting evidence for sampling correctness.
