# [diffusion] comfyui: return the patched clone from SGLDLoraLoader

[Upstream PR](https://github.com/sgl-project/sglang/pull/43186) · state: closed · merged: False

## Original PR description

## Motivation

Fixes #43184.

`SGLDLoraLoader.load_lora` clones the model, adds the new LoRA to the clone's `patches`, and sends every patch on the clone to `set_lora`, but it returned the original `model`. A chained second LoRA node therefore never saw the first LoRA and called `set_lora` with only its own. The worker's `LoRAPipeline.set_lora` applies with `clear_existing=True`, replacing the active set, so every LoRA but the last was silently dropped (and only the last is re-applied after a worker reload).

## Modifications

- `load_lora` returns the patched clone (`bi`). `SGLDModelPatcher.clone` keeps the same executor, wrappers, options and `model_type`, so nothing downstream changes except that the next LoRA node now sees this one.
- `test/unit/test_comfyui_lora_node.py`: imports the real `nodes.py` (ComfyUI modules stubbed under `mock.patch.dict(sys.modules)`), chains two LoRA nodes, and checks that the last `set_lora` call carries both LoRAs and that the upstream model is not mutated.

## Accuracy Tests

Two real `SGLDLoraLoader` nodes chained on a real `SGLDModelPatcher` (ComfyUI master 58b176f), with the resulting calls fed into the real `LoRAPipeline.set_lora` (set up like `test_lora_pipeline.py`, identity base layer, `style` adds to output[0], `detail` to output[1], input `[1, 1]`):

```
before: set_lora calls [['style'], ['detail']]           -> active=['detail'],          output=[1.0, 2.0]
after:  set_lora calls [['style'], ['style', 'detail']]  -> active=['style', 'detail'], output=[2.0, 2.0]
```
