# fix(voxtral): encode empty audio as one chunk of silence instead of crashing in stft

[Upstream PR](https://github.com/sgl-project/sglang/pull/41912) · state: open · merged: False

## Original PR description

## Motivation

The Voxtral processor's audio token count has a floor of one chunk (`VoxtralMultimodalProcessor._compute_audio_token_count` returns one chunk's worth of `[AUDIO]` tokens even for a zero-sample clip), but `VoxtralForConditionalGeneration._encode_audio` computes `target_samples = chunk_samples * ceil(0 / chunk_samples) = 0`, skips padding, and feeds an empty tensor to `torch.stft`, which raises `RuntimeError: Expected 2D or 3D (batch mode) tensor ... but got: [1, 1, 0]`.

On single-node deployments this currently surfaces as a clean 400, because the shm feature transport (`ShmPointerMMData`) rejects the zero-byte tensor first. The crash is still reachable whenever the empty waveform is transported inline — multi-node deployments (`determine_tensor_transport_mode` returns "default", no shm wrap) or single-node after `/dev/shm` exhaustion (the `OSError` fallback in `_wrap_shm_or_inline`) — and there the exception escapes into the scheduler process, which has no per-request containment, taking the whole server down.

## Modifications

- `python/sglang/srt/models/voxtral.py`: pad to at least one chunk of silence (`max(1, ceil(...))`), keeping the encoder output consistent with the processor's placeholder token count.
- `test/registered/unit/models/test_voxtral_empty_audio.py` (CPU): empty waveform yields one chunk instead of raising in stft (fails before this fix); chunk-count consistency for 1-sample / exact-chunk / multi-chunk inputs.

## Accuracy Tests

No model-output behavior change for non-empty audio: the padding formula is unchanged whenever `n_samples > 0` (`max(1, ceil(n / chunk_samples)) == ceil(n / chunk_samples)`). Empty audio previously crashed; it now encodes as one chunk of silence.

## Speed Tests and Profiling

No performance impact: one extra `max(1, ...)` per audio clip, on an integer.
