# [Fix] Preserve Kimi K3 pipeline graph bank inputs and bound chunk profiling

[Upstream PR](https://github.com/sgl-project/sglang/pull/43604) · state: open · merged: False

## Original PR description

## Motivation

The text-only Kimi K3 wrapper does not expose its pipeline layer range to the model runner. A receiving stage consequently captures an empty inherited attention-residual bank: block-aligned cuts produce incorrect decode results, and cuts inside a block fail graph capture. Dynamic chunk profiling can also allocate requests longer than the request-to-token mapping, leaving KV slots unreachable during release.

## Changes

Expose the text model's actual start/end layers. Bound complete profiling requests by model context and request mapping capacity, preserve the existing 1.25x chunk probe range when capacity allows, and release each prepared profiling request even if its forward fails. The prefill budget continues to constrain predicted chunks.

## Validation

- B200, synthetic 6-layer Kimi K3, bank block size 4, asymmetric dummy weights, TP2, NCCL: unchanged main reproduces the 3+3 capture assertion, 4+2 decode logprob difference of 0.06181, and 477,708 leaked KV slots after dynamic profiling.
- Fixed chunk size 16: graph PP2 at both 3+3 and 4+2 cuts, and eager PP2 at 3+3, match graph PP1 bitwise across all six prompts, including prefill and decode logprobs.
- Dynamic chunking: default chunk budget startup succeeds; both cuts complete eight prompts up to 4,104 tokens with live chunk predictions and graph decode, without idle pool invariant failures. Their complete outputs match bitwise.
- CPU coverage includes three model-range regression methods and two profiler methods. The updated profiler methods pass, covering context/mapping limits, a 20,480-token probe for a 16,384-token base chunk with sufficient context, and forward-failure cleanup. Two probe-range subcases fail with the prior prefill-budget cap. All pre-commit checks pass.

GPU results are from the prior revision. Removing the prefill-budget cap leaves profiling lengths unchanged for those configurations: their 8,192-token context or 1.25x chunk limit is tighter. GPU comparisons were not rerun for this profiler-only revision.
