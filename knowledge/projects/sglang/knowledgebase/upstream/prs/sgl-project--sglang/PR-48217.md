## What

Simplifies the synchronization state shared by the CustomAllReduceV2 push/pull planes and every kernel that borrows them, so that resource sizes no longer depend on launch widths.

- Push plane: the per-block phase counter array is replaced by one u64 `EpochCounter`. Each grid participant does one fire-and-forget `red.add` at exit (participant 0 adds `2^32 - (N - 1)`, the others add 1), so any grid size advances the phase exactly once. All "bumper" / cleanup blocks that flipped unused counters are removed, and push kernels may launch any grid size.
- Pull plane: `Semaphore` keeps one arrival counter per ordering class (relaxed / release). The owner takes `world_size` arrivals with one `atom.add(-W)` and spins only while the balance is negative. `Barrier` / `McBarrier` are stateless (`num_arrives`, the window reservation and `McBarrier::arrive_at` are gone), and the semaphore index defaults to `blockIdx.x`. Separate counters make the release/acquire barrier well-defined under the PTX memory model even when a peer's next-round arrival lands first.
- `PushPlane` takes a `default_blocks` launch width; `PullPlane` has `capacity` (allocated as `max(num_sm, num_pull_blocks)`) and `default_blocks`.
- Migrated kernels: custom AR (push/pull), all_reduce_fusion, beam, tp_qknorm, nvlink_comm, K3 ar_fusion / sp_collective / gemm_ag / attn_res fused TMA, Muse Spark all-gather kernels and the CuTe DSL finalize all-reduce.

- SASS (sm_100a, nvcc 13.4) for every migrated kernel: no stack frame or spills; the push exit is a single `REDG.E.ADD.64.STRONG.GPU`, the pull barrier is `ATOMG` + optional poll with no constructor-time atomic.

Agreed, this was real; fixed in 813c52737a. In the cluster kernels only the cluster leader commits the epoch, but the other CTAs of the cluster also read it. With T=1 the leader's add flips the phase immediately, so a slower non-leader CTA could pick the other workspace half and hang. The same holds for non-leader warps inside the leader CTA.

- `all_reduce_fusion` no-norm path: the cluster arrive/wait before the commit is restored.
- K3 `push_norm_cluster`: a `cluster.sync()` now precedes the commit.
- CuTe DSL finalize AR: the CTA barrier before the commit is restored (with `cluster_size > 1` it already had a cluster barrier).
- The rule is documented on `EpochCounter`: a participant commits only after every thread it covers has read the phase. Every other commit site was already behind `__syncthreads` / `cluster.sync`.

On sm_100a the barrier precedes the commit in every variant (SASS checked; stack 0, register count unchanged). The affected tests (`test_all_reduce_residual_norm`, `test_muse_spark_moe_finalize_all_reduce`, `test_ar_fusion`, `test_beam_all_reduce`) are rerunning on this head.
