# [ModelOpt] Support explicit Qwen vision and MTP NVFP4 metadata

[Upstream PR](https://github.com/sgl-project/sglang/pull/44032) · state: open · merged: False

## Original PR description

## Motivation

Qwen3.5 MTP and Qwen3-VL vision checkpoints can contain serialized ModelOpt NVFP4 or mixed-precision auxiliary weights. The MTP `fc` was always an `nn.Linear`, which cannot allocate the packed weight and scale parameters, and the vision tower discarded the quantization config. Enabling the vision path also exposes its higher-dimensional activations to the W4A4 matrix kernel.

This change opts auxiliary modules into ModelOpt quantization only when their per-layer checkpoint metadata explicitly lists them. It also isolates draft config changes from the target model and allocates one full-attention MTP layer.

The design follows the config/scheme/backend separation described in [Quantization Modifications](https://github.com/sgl-project/sglang/issues/15194). The concrete motivation is an internal minimal reproducer using a Qwen3.5/Qwen3-VL checkpoint with serialized ModelOpt metadata: the visual aliases were not selected, packed MTP `fc` metadata fell back to dense `Linear`, and a three-dimensional visual activation reached a two-dimensional-only NVFP4 GEMM. This PR documents the metadata contract and rejects incomplete auxiliary entries; no existing public issue describes this exact ModelOpt auxiliary-weight combination.

## Modifications

- Use `ReplicatedLinear` for ModelOpt MTP `fc` and unwrap its forward result. Checkpoints without explicit MTP metadata retain the existing BF16 draft behavior.
- Preserve flat and nested NVFP4 `quantized_layers` metadata and apply the model's weight-name mapper. Uniform FP4 treats auxiliary metadata as a whitelist, while respecting exclusions and keeping unlisted auxiliary layers in BF16.
- Match vision `model.visual`/`visual` and `qkv`/`qkv_proj` names for metadata and exclusions. Pass ModelOpt quantization to the vision tower only when it is explicitly listed.
- Preserve already mapped visual `qkv_proj` names when using the real Qwen3-VL substring mapper, avoiding `qkv_proj_proj`.
- Flatten W4A4 activations to a matrix and restore their leading dimensions after the GEMM, including noncontiguous vision inputs. Preserve the existing prequantized tuple path.
- Reject incomplete auxiliary fused-projection metadata and uniform per-expert auxiliary MoE metadata rather than allocating incompatible packed buffers. Uniform auxiliary MoE requires a whole fused-module entry; mixed-precision dispatch retains its existing behavior.
