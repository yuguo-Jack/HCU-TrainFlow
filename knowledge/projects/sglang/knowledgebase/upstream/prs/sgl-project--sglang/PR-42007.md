# [Fix] function_call: Flush buffered text at stream end in MiniMax M2, MiniMax M3 and JsonArrayParser

[Upstream PR](https://github.com/sgl-project/sglang/pull/42007) · state: open · merged: False

## Original PR description

## Motivation

Same loss pattern as #41909 / #41914 / #41962 / #41963: `MinimaxM2Detector`,
`MinimaxM3Detector` and `JsonArrayParser` hold text back in their buffer while
waiting for the closing marker, and `BaseFormatDetector.finish()` returns an
empty result by default. When the stream ends with an incomplete tool call still
buffered, the held-back text is silently dropped.

## Changes

Add a `finish()` override to each parser:

- `MinimaxM2Detector` flushes the buffered partial parameter block. A pure
  trailing closing tag (`</minimax:tool_call>`) is syntax residue, not user
  text, and is not re-emitted.
- `MinimaxM3Detector` flushes a partially streamed parameter value.
- `JsonArrayParser` flushes a partial JSON array; a fully closed array that
  was already parsed into calls is not re-emitted.

Normal streams are unaffected: `finish()` stays a no-op when the buffer is
empty or holds only a complete closing marker.

## Tests

Offline unit tests (no server, no model loading) for each parser cover:
- partial tool call at stream end: `finish()` releases the buffered text;
- clean stream: `finish()` returns an empty result;
- fully parsed stream: no duplication at `finish()`.

All pass locally (`pytest test/registered/unit/function_call/test_{minimax_m2_detector,minimax_m3_detector,json_array_parser}_finish.py`), ruff clean.
