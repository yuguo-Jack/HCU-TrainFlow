# fix(openai): honor include_reasoning=false on chat completions

[Upstream PR](https://github.com/sgl-project/sglang/pull/39113) · state: open · merged: False

## Original PR description

## Motivation

Addresses the chat-completions half of #39103. A request with `include_reasoning: false` still returned `reasoning_content`, because the field never existed in sglang's schema: `ChatCompletionRequest` had no such member and nothing in the serving layer read it. Clients written against vLLM's OpenAI extension reasonably expect it to work.

## Modifications

- `protocol.py`: add `include_reasoning: Optional[bool] = None` to `ChatCompletionRequest`. The default preserves current behavior.
- `serving_chat.py`: gate both emission points when the flag is False: the non-stream `ChatMessage.reasoning_content` and the streaming reasoning SSE chunk. The reasoning parser still runs either way, so visible content stays clean and token accounting is unchanged.
- `test_serving_chat.py`: two no-GPU unit tests pin the suppression and the default.

## Accuracy Tests

No model-output change; this gates response shaping only. `test/registered/openai_server/basic/test_serving_chat.py` passes fully (15/15) locally on CPU, including the two new cases.

## Benchmarking and Profiling

Not applicable; no hot path touched.
