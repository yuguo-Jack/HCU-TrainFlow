## Motivation

HiCache host pools of a unified pool's windows were named by window slot (`swa`, `auxiliary_swa`), so a third window had no host pool and the host stack refused it. Host hits were likewise split: the tree's first window's host hit travelled as `swa_host_hit_length` and further windows' in a separate map.

## Modifications

- `mem_cache/hybrid_cache/hybrid_pool_assembler.py`, `pool_host/group.py`, `kv/plan.py`: each window sub-pool's host pool goes by the sub-pool's own name (`window_<len>`), as its prefix-tree slot does; host pool names are a well-known `PoolName` or a window sub-pool's name (`HostPoolName`). A window sub-pool named like a well-known host pool is refused. `PoolName.AUXILIARY_SWA` is removed.
- `unified_cache/components/swa.py`, `unified_radix_cache.py`: window components read their host pool from their slot; host space for a window's state eviction is reserved in that window's own pool; retraction backup requires every window's host pool.
- PD decode receiving into host memory takes one host pool per window state entry, by the entry's sub-pool, instead of refusing more than one.
- `storage/mooncake_store/mooncake_store.py`: a window host pool's objects are keyed by the pool's name, and each window pool gets the trailing-page hit of its own window; the scheduler passes each window component's trailing pages by host pool name. The prefetch acknowledgment reduces hit pages over every registered pool's name.
- `mem_cache/layout/fused_draft.py`: the fused-draft window host kind is named `window`, after the family it serves.
- `rust_tree_core/adapter.py`, `unified_cache/unified_cache_linker.py`: the native tree core and the external cache linker still keep one window; the adapter maps that pool's name to the core's `swa` at its boundary.
- `prefill_budget.py`, `managers/schedule_batch.py` (`Req.window_host_hit_lengths`), `MatchResult.window_host_hit_lengths`: every window's host hit is in one map and every budget entry point takes it. After a failed host load, the request is re-selected with no host hit at all (previously only the first window's hit was dropped).
- Tests: host retraction restores three windows from their own host pools; attaching HiCache gives three windows their own host pools; Mooncake keys and trails three window pools by name; host receive allocates the window entry in its own pool (`test_hicache_l3_object_layout.py`, `test_storage_prefetch_lifecycle.py`, `test_decode_retraction_backup.py`, `test_unified_radix_cache_hicache.py` and others).

**Behavior change:** under `--enable-unified-memory`, a window host pool is named by its sub-pool (`window_<len>`), and Mooncake store objects of window pools are keyed by that name, so objects written by a build that keyed them as `swa` are not found (a cold L3 cache, not wrong data). Static pools keep the `swa` host pool and keys.
