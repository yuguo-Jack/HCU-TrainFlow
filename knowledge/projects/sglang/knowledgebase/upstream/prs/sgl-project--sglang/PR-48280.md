# [Fix] utils: Handle post-match KMP transition in TokenSequenceMatcher.advance

[Upstream PR](https://github.com/sgl-project/sglang/pull/48280) · state: open · merged: False

## Original PR description

## Motivation

`TokenSequenceMatcher` (`python/sglang/srt/utils/token_sequence_matcher.py`) implements a Knuth-Morris-Pratt (KMP) prefix-table automaton for online token-stream matching.

When `advance(matched, token)` is called from the terminal full-match state (`matched == len(self.pattern)`), the failure-link loop immediately indexes `self.pattern[matched]`:

```python
while matched > 0 and token != self.pattern[matched]:
    matched = self.prefix_lengths[matched - 1]
```

Because valid indices of `self.pattern` are `0 .. len(self.pattern) - 1`, calling `advance()` after a full match raises `IndexError: tuple index out of range` instead of transitioning along the KMP failure link `self.prefix_lengths[matched - 1]` to detect subsequent or self-overlapping occurrences in the stream (e.g., pattern `[1, 2, 1]` on stream `[1, 2, 1, 2, 1]`, or single-token pattern `[7]` on `[7, 7]`).

## Modifications

- In `TokenSequenceMatcher.advance()`, transition `matched = self.prefix_lengths[matched - 1]` when `matched == len(self.pattern)` before entering the failure-link loop.
- Add unit tests in `test/registered/unit/constrained/test_reasoner_grammar_backend.py` (`TestTokenSequenceMatcher`) covering post-match continuation for both self-overlapping multi-token patterns and single-token patterns.
