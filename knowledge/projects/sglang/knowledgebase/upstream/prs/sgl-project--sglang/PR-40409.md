# [Fix] hicache: Force clear Mooncake storage

[Upstream PR](https://github.com/sgl-project/sglang/pull/40409) · state: open · merged: False

## Original PR description

## Motivation

Mooncake's default `remove_all(force=False)` retains objects with active leases, so recently used KV objects can survive `POST /hicache/storage-backend/clear`.

The clear response also ignores backend failures and only checks the first worker's reply. It can report success when a backend or replica failed to clear.

## Modifications

- Use forced removal in `MooncakeStore.clear()` and raise on negative return codes. Zero and positive deletion counts remain successful.
- Pass the clear result through the scheduler, require all worker replies to succeed, and return an HTTP error on failure.
- Add regressions for leased objects, backend errors, storage-presence invalidation, and mixed-success worker replies.

Earlier end-to-end run (2026-09-20, two H20 nodes, Qwen3-4B, TP1, RDMA): replay after clear restored 16,010 tokens before the fix and returned `cached_tokens=0` afterward. The master key count fell from 32,058 to 0.
