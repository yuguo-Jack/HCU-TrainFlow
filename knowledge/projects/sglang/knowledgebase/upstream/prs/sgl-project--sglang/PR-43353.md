# [Fix] Run:ai streamer: copy CPU-path tensors out of the staging buffers

[Upstream PR](https://github.com/sgl-project/sglang/pull/43353) · state: open · merged: False

## Original PR description

## Motivation

Fixes #43352. On the CPU path, `runai_safetensors_weights_iterator` yields views into the Run:ai streamer's staging buffers, which the streamer reuses once its memory limit is reached. A weight loader that keeps a tensor until its counterpart arrives, such as the `nvfp4_online` MoE loader with its w1/w3 and FP8 weight/scale pairs, then reads bytes that belong to a later tensor.

## Modifications

On the CPU path (`device == "cpu"`), the iterator copies each tensor before yielding it, so a yielded tensor owns its memory and stays valid however long a loader keeps it. vLLM's equivalent iterator copies every tensor it yields from the streamer in the same way.

The distributed path, which streams to the GPU, is unchanged. The cost is one host memory copy per tensor on the CPU path.
