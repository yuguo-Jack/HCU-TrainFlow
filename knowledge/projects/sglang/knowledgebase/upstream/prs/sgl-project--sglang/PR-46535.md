# [Refactor] attention: Write the eager break's LSE into a caller-allocated buffer

[Upstream PR](https://github.com/sgl-project/sglang/pull/46535) · state: closed · merged: True

## Original PR description

- `RadixAttention`'s eager break in the breakable prefill graph writes the LSE into a buffer the caller allocates before the break (`[tokens, q heads]`, fp32, only when the batch asks for an LSE) and returns nothing, like the attention output it already writes. Before, the break returned a fresh LSE on every replay and the graph wrapper copied it into the one it had captured.
- The break pads the LSE to the graph's rows with zeros, as before. A replay batch that asks for no LSE leaves a captured LSE buffer as it is, also as before.
- The buffer is sized by query heads (`tp_q_head_num`), so a flat `q` gets the same LSE shape as a 3-D one. The old empty-batch branch sized its zeros from `q.shape[1]`, which for a flat `q` is heads * head dim, so a replay that took it failed to copy them into the captured `[tokens, heads]` LSE. That replay now gets zeros.
- The empty-batch branch runs on a DP-attention rank that is idle while another rank prefills, once MAX_LEN padding turns its idle batch into an empty extend (hybrid-SSM models, or a pplx or forced-MAX_LEN DeepEP v2 all-to-all). The only caller that passes a flat `q` with `return_lse=True` is IQuest Q1's sink attention.
- A unit test covers a flat `q`, including the empty batch.
