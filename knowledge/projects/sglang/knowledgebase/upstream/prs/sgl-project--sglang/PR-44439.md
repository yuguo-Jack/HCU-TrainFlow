# Add DoSA prefill indexing and GLM-5.2 TTFT reproduction

[Upstream PR](https://github.com/sgl-project/sglang/pull/44439) · state: open · merged: False

## Original PR description

## Motivation

DSA prefill scores queries against the visible KV context and selects the top-k keys. At long context lengths, score computation, logits traffic and selection account for a substantial part of prefill latency.

This PR adds **DoSA**, which uses certified upper bounds to skip full-head scoring for keys that cannot enter the top-k, then scores and selects the surviving candidates exactly. On eight GB200 GPUs, it reduces GLM-5.2-FP8's 1M-token TTFT from **133.65 s to 70.40 s (1.90×)**.

## Modifications

### Method

1. **Seed:** each query scores a request-local seed subset. Its k-th score is a lower bound on the full row's k-th score.
2. **Screen:** evaluate partial-head contributions and conservative score bounds, then discard candidates whose upper bound is below that threshold.
3. **Refine and select:** compute exact scores for the surviving candidates and select their top-k. Rows exceeding candidate capacity or the certificate's numerical domain use full-head exact recovery.

For a query with threshold $\tau_q \le s_{(k)}(q)$ and certified bound $U(q,j) \ge s(q,j)$, the pruning rule is:

$$
U(q,j) < \tau_q \quad\Longrightarrow\quad j \notin \operatorname{TopK}(q).
$$

The bounds include rounding guards for the production FP32 score computation. Equality remains eligible, preserving valid choices at the top-k boundary.

### SGLang integration

- Add the opt-in `SGLANG_DOSA_MODE=few` prefill path for SM100 FP8 DSA indexers with 32 or 64 heads, head dimension 128 and top-k 2048. It integrates with single-request PAGED prefill; ordinary SGLang dispatch remains the default.
- Share runtime components across `full` and `few`; `few-decode` also enables request-local H64 decode witnesses.
- Reserve DoSA workspaces before KV-cache sizing. Candidate records, ID pages and task tables share a byte budget; bounded physical query slabs process the requested logical chunk in its original order.
- Include request-mapping storage in the KV-memory budget.
- Repair coarse-bucket overflow in the shared AOT and JIT Top-K selectors with exact refinement before bounded collection.
- Add the real-text TTFT client, original-input preparation, source-build helper and reproduction guide.

Enable DoSA with the normal model launch arguments:

```bash
SGLANG_DOSA_MODE=few python -m sglang.launch_server \
  --model-path /path/to/GLM-5.2-FP8 --tp 8 --kv-cache-dtype fp8_e4m3
```

## Accuracy Tests

- **Complete Indexer:** all **1,260/1,260 cases** pass strict selected-score multiset checks against exhaustive scoring before and after timing. Coverage includes six real-text sources, five KV lengths from 128K to 1M, Q16K/Q32K and 21 layers.
- **H64 capacity and recovery:** at 1M KV, all 4,096 rows exceeded the 114,688-record capacity and recovered exact results. The separate certificate-domain recovery case also passed, including visible/unique indices and buffer guards.
- **Unit tests:** all **16 retained CPU tests** pass, covering query capacity, slab/carry ordering, concurrent request ownership, paged input/output contracts and TTFT request accounting. Shared selector tests also cover unequal FP32 scores overflowing a coarse bucket.

## Speed Tests and Profiling

**GLM-5.2-FP8, 8× GB200 across two nodes in one NVLink domain, TP8/EP1, FP8 KV (`fp8_e4m3`).** Both modes use memory fraction 0.88, page size 64, max-prefill tokens 16K, TRTLLM attention/MoE backends, full decode graphs and breakable prefill graphs. The software stack is PyTorch 2.14.1, DeepGEMM 0.2.2 and FlashInfer 0.7.1.

Each entry is the median of three measured requests after one warmup. Every request uses a fresh ID and a prefix-cache flush. TTFT includes server tokenization, prefill and request-owned prior work, ending at the first streamed completion token.
