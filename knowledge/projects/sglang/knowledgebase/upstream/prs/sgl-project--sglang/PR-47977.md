# [Feat] mm: Add --disable-multimodal to serve a multimodal model text-only

[Upstream PR](https://github.com/sgl-project/sglang/pull/47977) · state: open · merged: False

## Original PR description

## Motivation

`--enable-multimodal` can only turn multimodal on, so a model that is multimodal by default cannot be served text-only. A `--config` YAML cannot set `enable_multimodal: false` either: the loader drops `false` for store-true flags.

Under `SGLANG_RUST_SERVER=1`, such a model is refused at startup unless the Rust server has a multimodal pipeline for its family (today, this is only Qwen-VL) even when every request is text.

`--language-model-only` does not cover this, because it is limited to an architecture allowlist of models whose code skips the encoders. This is intended to be a temporary solution for unsupported multimodal models while that support is pending.

## Modifications

- Add `--disable-multimodal` (`mm.disable_multimodal`, default `False`). When it is set, `ModelConfig.from_server_args` passes `enable_multimodal=False`, so `is_multimodal` is `False` for any architecture. Gemma 3, Llama 4, Step3-VL and Inkling already take this path by default.
- `check_server_args` rejects `--disable-multimodal` together with `--enable-multimodal`.
- The Rust server's refusal message names the new flag.
- Add a row to `server_arguments.mdx`.

No change for launches without the flag.
