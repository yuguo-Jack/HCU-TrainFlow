# [Fix] Reject prompts that cannot reserve paged KV headroom

[Upstream PR](https://github.com/sgl-project/sglang/pull/42519) · state: closed · merged: False

## Original PR description

## Motivation

A prompt can pass the scheduler's input-length check yet exceed the empty-pool prefill budget after page rounding and the reserved decode page. The default allocator currently returns `0` for both a valid zero-output request and an impossible prompt, so the latter is queued instead of aborted and can remain waiting even with no other requests.

For example, with 1,024 KV tokens and page size 16, a 1,009-token prompt passes the 1,018-token input limit. Its rounded prompt already occupies 1,024 tokens, leaving no reserved page. Returning `0` output tokens does not make it schedulable.

Budget clipping also runs before automatic prompt truncation. A long prompt truncated to a valid length can retain a zero generation budget computed from its original length.

## Modifications

- Return the existing `None` rejection sentinel when the default allocator's prompt-plus-reserve budget is negative. Preserve valid zero-output budgets.
- Compute generation limits after prompt validation/truncation in `handle_generate_request`, using the prompt that will actually run. Preserve the original input-validation error when truncation is disabled.
- Extend the existing registered CPU memory-budget tests through the real scheduler request handler and paged allocator, covering page boundaries, valid zero-output requests, and automatic truncation.

Related open PRs were checked: #33814 changes context-length boundary handling, and #38973 isolates batched sampling parameters in the tokenizer manager; neither covers this allocator rejection or worker-side truncation order.
