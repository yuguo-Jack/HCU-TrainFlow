# [Perf] sampler: Remove torch.nonzero() where nonzero(as_tuple=True) is sufficient

[Upstream PR](https://github.com/sgl-project/sglang/pull/44273) · state: closed · merged: False

## Original PR description

## Background

`torch.nonzero()` forces an expensive CPU-GPU synchronization on CUDA tensors because it needs to allocate an output tensor of indeterminate size. This causes unnecessary stalls, especially in multi-modal VLM preprocessing and attention backend paths.

## Problem

Multiple places in the runtime codebase use `.nonzero()` where the more efficient `nonzero(as_tuple=True)` form would suffice without triggering the same overhead.

## Solution

Replace `.nonzero()` with `.nonzero(as_tuple=True)`:
- 1D masks: `mask.nonzero(as_tuple=True)[0]` instead of `mask.nonzero().flatten()` or `.squeeze(1)`
- 2D masks: `mask.nonzero(as_tuple=True)[dim]` instead of `mask.nonzero()[:, dim]`

Files changed:
1. `python/sglang/srt/configs/janus_pro.py` - `image_token_mask.nonzero()` → `nonzero(as_tuple=True)[0]`
2. `python/sglang/srt/models/phi4mm_utils.py` - `nonzero()[:, 1]` → `nonzero(as_tuple=True)[1]`
3. `python/sglang/srt/multimodal/processors/moss_vl.py` - `nonzero()` → `nonzero(as_tuple=True)` tuple with unpacking
4. `python/sglang/srt/layers/attention/qwen_sparse_attn_backend.py` - `nonzero().flatten()` → `nonzero(as_tuple=True)[0]`
5. `python/sglang/srt/layers/attention/dsv4/v41_indexer/scoring.py` - `nonzero().squeeze(1)` → `nonzero(as_tuple=True)[0]`
6. `python/sglang/srt/layers/attention/deepseek_v4_backend.py` - `nonzero().squeeze(1)` → `nonzero(as_tuple=True)[0]`

## Testing

- All 6 modified files pass Python AST syntax validation
- Semantically equivalent: `nonzero(as_tuple=True)[i]` produces identical values to `nonzero()[:, i]`

Closes #9889
