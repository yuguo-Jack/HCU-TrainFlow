# [Refactor] multimodal: [MM refactor 8/9] Check token-space Qwen output against the legacy processor

[Upstream PR](https://github.com/sgl-project/sglang/pull/46414) · state: open · merged: False

## Original PR description

## Motivation

The token-space route must hand the scheduler exactly what the legacy processor does. The one known exception is Qwen3-VL family videos, which legacy resizes with the wrong factor (see 7/9); the comparison preprocesses legacy's videos as token-space does until legacy is fixed.

## Modifications

- CPU: served output and `mm_spans` equal the legacy output and offsets.
- GPU: `test_qwen_processor_bitwise.py` runs pinned prompts through both routes and compares every field and tensor byte except the cache identity (item hash, pad value, padded IDs), which the routes derive differently.
  - Since legacy Qwen3-VL videos are sampled and resized as token-space does (see Motivation), this test does not cover that step, only the steps after it; `test_qwen3_vl_video.py` pins that step to qwen-vl-utils 0.0.14 instead.
- `test_token_id_retokenize_e2e.py`: a token-space server keeps non-canonical request IDs.
