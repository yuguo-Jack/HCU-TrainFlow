# [AMD] Quantize the DSv4 indexer FP4 query with one program per token and 16-head group

[Upstream PR](https://github.com/sgl-project/sglang/pull/42497) · state: open · merged: False

## Original PR description

In prefill, `pack_fp4_query_flydsl` launches one program per (token, head slot of 64), so a 16k-token chunk runs about one million programs, and for DeepSeek-V4.1 (32 indexer heads) half of them only write zero scale bytes for the padded head slots. This PR launches one program per (token, group of 16 heads): each program quantizes its rows with the math of `quantize_fp4_indexer_row` (RNE codes, e8m0 scales) and writes each scale byte straight into the FlyDSL layout, and the first group also writes the zero bytes of the padded slots. The grid goes from (tokens, 64) to (tokens, heads / 16); the existing assert already requires heads % 16 == 0. The output is bitwise identical. Decode steps up to 64 rows use the fused RoPE + pack kernel and are not affected.

Tested on the ROCm 10-06 image (SGLang 679d2851 with #42796), MI355X, TP4; this branch is the same commit rebased on current main, where the file is unchanged. In the server profile of a 16k prompt the kernel takes 536 us per launch before and 47 us after. Median TTFT at one user is 5.2% and 2.9% lower at 8k input in two repeats and within noise at 16k, 60k and 128k, because the kernel is a small part of prefill. Codes and scale bytes are bitwise equal to the old kernel for 16, 32 and 64 heads and 1 to 16,384 tokens (tails, Inf / NaN, non-contiguous input and zero tokens, with output buffers pre-filled), and `test_fp4_indexer_hip.py` passes (52 tests). Related upstream work, not ours: sglang#42911 by RolaoDenthu (open) fuses the prefill index-Q RoPE fake-quant and this pack into one launch; on DeepSeek-V4.1's path it replaces this call when it lands, and this PR then speeds up the fallback path (other head or RoPE shapes) and other callers of `pack_fp4_query_flydsl`.
