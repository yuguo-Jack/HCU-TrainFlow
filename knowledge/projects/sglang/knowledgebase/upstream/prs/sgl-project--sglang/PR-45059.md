# [Perf] deepseek-v4.1: Run decoder replay tail layers from CUDA graphs on eager prefill steps

[Upstream PR](https://github.com/sgl-project/sglang/pull/45059) · state: closed · merged: True

## Original PR description

- Under decoder SWA bounded replay, the layers from `late_layer_start` on run over each request's last 128 extend rows. On an eager prefill step those few rows still pay one host launch per kernel. This PR replays these tail layers from breakable CUDA graphs keyed by the padded tail row count: multiples of 128, up to `SGLANG_DSV4_DECODER_TAIL_GRAPH_MAX_ROWS` (default 2048).
- New model-agnostic `RowBucketGraphRunner` (`model_executor/runner/row_bucket_graph_runner.py`): breakable CUDA graphs of a layer range keyed by padded row count.
  - static input buffers sized once for the largest bucket and shared by every bucket;
  - each bucket captured on first use, largest first, into the global graph pool on the global capture stream;
  - graphs start only after a forward of a full prefill chunk, so lazily sized workspaces have reached their final size.
- New `models/deepseek_v4_replay_tail.py` with `DecoderReplayTail`, the DeepSeek-V4.1 side: when to use the graphs, the tail layer stack the runner records, the mHC state flattening, and the eager SWA KV store break. `deepseek_v4.py` keeps only the hooks.
- Inside a tail graph, the SWA KV store, the attention and the low-ratio sources run as eager breaks that read the step's live tail metadata and real row count.
- Scope: eager prefill steps with attention DP size 1. Prefill-graph steps, DP attention, context parallel, unified-KV Triton and expert-distribution recording keep the current path. Prefill-graph steps and DP attention follow in a stacked PR.
- Behavior change: on by default on CUDA whenever decoder replay is on. Captured graphs add GPU memory that KV sizing does not count: 16 buckets took 2.2 GiB per GPU on GB300 TP4. `SGLANG_DSV4_DECODER_TAIL_GRAPH_MAX_ROWS=0` keeps the current eager path. The graphs are also off with `SGLANG_ENABLE_GRAPH_POOL_BORROW`.
- Verification: DeepSeek-V4.1-Flash, GB300, TP4, eager prefill, DSpark; main (`cff88d6eac`) vs this change on two nodes (A, B), each pair run on one node in opposite orders.
  - Cold-prompt TTFT (`max_new_tokens=1`, median of 5): 128 tokens 150.4 / 154.5 -> 103.6 / 105.3 ms (node A / node B); 8K tokens 162.4 / 169.0 -> 111.7 / 112.2 ms.
  - 64K cached prefix plus 2048 new tokens, TTFT: 172.4 / 179.2 -> 124.2 / 124.4 ms.
  - Saturated prefill (`bench_serving`, random 8K input, 1 output token, concurrency 64): 94.6K / 93.1K -> 125.0K / 125.2K input tok/s (+33%).
  - GSM8K (sgl-eval, 1319 examples, no thinking): 96.66 / 96.89% -> 96.89 / 96.59%.
