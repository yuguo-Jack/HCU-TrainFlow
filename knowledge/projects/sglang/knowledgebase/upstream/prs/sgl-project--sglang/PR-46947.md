# [CI] [AMD] diffusion/flux3: Make exact-quality VAE convolutions deterministic on ROCm

[Upstream PR](https://github.com/sgl-project/sglang/pull/46947) · state: closed · merged: True

## Original PR description

## What

On ROCm, run the FLUX.3 VAE encode and decode with `torch.backends.cudnn.deterministic = True` for `quality="exact"` requests. The flag is set only for the duration of the VAE call and restored afterwards. Other platforms and non-exact tiers are unchanged.

## Why

`TestDisaggFlux3Image::test_t2i_and_edit_match_monolithic` has failed on every scheduled PR Test (AMD) rocm10 run since #45309 landed, e.g. [this job](https://github.com/sgl-project/sglang/actions/runs/40427865857/job/121938136317): text-to-image matches exactly, but the edit differs in ~57% of pixels (max 22).

The disaggregated path isn't the problem. A monolithic server gives a different edit each time the same request is sent ([diagnostic run](https://github.com/sgl-project/sglang/actions/runs/40636143493)). Text embeddings, noise and the prepared reference are bit-identical between runs. The reference's VAE latents are not: 5-9 of 30720 values differ by one bf16 ulp, and the denoiser amplifies that across the image.

Per-module hooks on the VAE alone ([run](https://github.com/sgl-project/sglang/actions/runs/40637699532)) show the first divergence at fp32 `Conv2d` layers whose inputs are identical between runs (`encoder.down.3.block.0.conv1`, `decoder.mid.block_1.conv1`). MIOpen picks a non-deterministic kernel for those shapes. GroupNorm and the attention block are deterministic. Eight repeated calls on MI300X:

| setting | encode distinct outputs | encode time | decode distinct outputs | decode time |
|---|---|---|---|---|
| default | 8/8 | 6.6 ms | 8/8 | 13.0 ms |
| `cudnn.deterministic` | 1/8 | 7.1 ms | 1/8 | 13.4 ms |

Checked it again and tightened it in 177e8f74eb:

- It now also sets `cudnn.benchmark = False` for the call. With `SGLANG_USE_ROCM_CUDNN_BENCHMARK=1`, benchmark mode picks the conv kernel by timing, which could undo the deterministic choice. This matches the existing deterministic helpers in Sana-WM and MiniMax-H3.
- Both flags are saved and restored in `finally`, so the DiT and other stages keep their settings, including when the VAE call raises.
- It is a no-op unless the request is `quality="exact"` and the platform is ROCm.
- Added unit tests in `test_flux3_image_stages.py` for the ROCm exact case (flags set inside, restored after, also on exception) and for every other platform/tier combination (untouched). They pass on MI355.

The target test passed on rocm10 with the first version; a fresh run on this commit is in progress: https://github.com/sgl-project/sglang/actions/runs/40814705814
