# [Fix] flashinfer-megamoe: Fix startup autotune on FlashInfer 0.7.2 and add an optional decode workspace

[Upstream PR](https://github.com/sgl-project/sglang/pull/46213) · state: open · merged: False

## Original PR description

## Motivation

Two FlashInfer MegaMoE changes found while adding Beam (#44747), split out of #45256 at review because neither is specific to Beam.

1. **Startup autotune fails on FlashInfer 0.7.2.**
   - The tuning sweep warms each capacity profile with `knobs="auto"` but passes no output buffer.
   - On backends that support output views, warmup then runs `compute(output=None)`. The NVFP4 CuTe DSL backend rejects that with `ValueError: compute(output=None) is incompatible with knobs='auto'`.
   - So a MegaMoE NVFP4 server with default autotune and a cold tuning cache fails at startup, on every rank.
2. **Small decode batches use the full-capacity workspace.** MegaMoE's per-call cost scales with workspace capacity, and without startup autotuning every forward uses the main profile.

## Modifications

- **Autotune.** `MegaMoeTunedForward` allocates a BF16 output buffer for the sweep and passes it to `warmup`.
- **Optional decode workspace** (`SGLANG_FLASHINFER_MEGAMOE_DECODE_MAX_TOKENS_PER_RANK`):
  - `0`, the default, is off. Otherwise the value must satisfy `0 < capacity < main capacity`; any other value fails when the first MegaMoE layer is built.
  - It is a second workspace profile on the same MegaMoE layer, built only for ModelOpt NVFP4 MoE.
  - A forward uses it only when no DP rank extends and every rank's DP-gathered token count fits. All ranks read the same gathered counts, so they choose the same profile.
  - It is unused (logged once) while startup autotuning runs, since the tuned profiles already size small batches. It takes effect with `--disable-flashinfer-autotune` or `--flashinfer-autotune-skip-ops flashinfer_megamoe`.
- Documented in `environment_variables.mdx`.

## Accuracy Tests

The runs below are on 4×GB300 with FlashInfer 0.7.2, using `reflection/Beam-1.0-501B-A23B-NVFP4` with MegaMoE TP4/DP4/EP4. They ran on the Beam stack (#45256 and its base), which carried these same changes. GSM8K is sgl-eval, 1,319 questions, temperature 0.

| Configuration | GSM8K | Notes |
|---|---|---|
| Before the fix: default autotune, cold tuning cache, with DFlash | — | every rank fails at startup with the `ValueError` above |
| With the fix: default autotune, cold tuning cache | 96.44% | 13 capacities tuned, zero request errors |
| Autotune off, decode workspace off, with DFlash | 96.44% | zero errors |
| Autotune off, decode workspace 256, with DFlash | 96.29% | isolated outputs identical to workspace off; all 4 ranks make the same choice on every forward |
| Autotune off, decode workspace 64, with DFlash | 96.06% | decode profile chosen only up to 64 tokens per rank, main above; CUDA graphs on both sides |

`test_flashinfer_megamoe.py`:
- the autotune sweep now asserts it receives an output buffer;
- a new case covers the decode workspace: skipped under autotune, validated, and chosen only when every rank fits and none extends.

`test_flashinfer_megamoe.py` passes on this branch.
