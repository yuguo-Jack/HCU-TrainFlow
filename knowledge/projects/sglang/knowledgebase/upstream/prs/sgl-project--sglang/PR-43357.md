# [Scheduler] Limit chunked prefill budget share with --chunked-prefill-ratio

[Upstream PR](https://github.com/sgl-project/sglang/pull/43357) · state: open · merged: False

## Original PR description

## Motivation

When chunked prefill is enabled, a single long-prompt request consumes the entire chunk token budget (`rem_chunk_tokens`) per scheduling step. The first chunked request drains the pool to zero and `budget_state()` refuses every other request — however short — until the long request has been fully prefilled. This is the head-of-line blocking reported in #10063.

#34623 addresses this with `--long-prefill-token-threshold`, which adds a per-request prefill ceiling and enables up to `chunked_prefill_size // F` concurrent partial prefills. It is a broad rework: it renames `chunked_req` → `chunked_reqs`, adds reserve-to-completion admission, parking, and `AddReqResult.SKIP` so that N long requests can be mid-prefill simultaneously.

This PR takes a different approach. Instead of enabling multiple concurrent chunked prefills, it limits the share of the budget that a single chunked request can consume. A new `--chunked-prefill-ratio` (default `1.0`) scales the per-pass available chunk tokens:

```scss
int(rem_chunk_tokens * chunked_prefill_ratio)
```

When the ratio is below 1.0, the chunked request leaves part of the budget unused. That remainder is available to short (non-chunked) requests in the same pass. Additionally, once a request is already chunked, other requests are not chunked, preventing multiple long requests from competing for what remains.

When combined with #40024 (shortest-prefill-first scheduling), short requests in the waiting queue are sorted to the front and admitted into the budget left over by the long request, reducing TTFT for short requests under mixed workloads.


## Modifications

- Add `--chunked-prefill-ratio` server arg (default `1.0`, validated to `(0, 1]`).
- Pass `chunked_prefill_ratio` through to `PrefillAdder`; in `add_chunked_req`, scale `available_chunk_tokens` by the ratio.
- Add `has_chunked_req` guard to `add_one_req_ignore_eos` and `_select_prefill_admission` to short-circuit the chunked path for other requests when one is already chunked.

## Speed Tests and Profiling

### Setup

- **Deployment**: PD disaggregated serving, prefill node with `--chunked-prefill-ratio 0.5 --schedule-policy shortest-prefill-first`
- **Model**: `deepseek-ai/DeepSeek-V4-Flash`
- **Workload**: Two concurrent processes — long requests (32K input, 1K output, 5 concurrency, 100 prompts) and short requests (1K input, 0.5K output, 5 concurrency, 100 prompts). Short request process starts right after long request process begins.

### Commands

```bash
# Short requests
python3 -m sglang.bench_serving --backend sglang-oai-chat \
  --host 127.0.0.1 --model deepseek-ai/DeepSeek-V4-Flash \
  --port 30000 --dataset-path /load_test/ShareGPT_V3_unfiltered_cleaned_split.json \
  --dataset-name random --random-range-ratio 1 --seed 1 \
  --random-input-len 1000 --random-output-len 500 \
  --max-concurrency 5 --request-rate 5 --num-prompts 100

# Long requests
python3 -m sglang.bench_serving --backend sglang-oai-chat \
  --host 127.0.0.1 --model deepseek-ai/DeepSeek-V4-Flash \
  --port 30000 --dataset-path /load_test/ShareGPT_V3_unfiltered_cleaned_split.json \
  --dataset-name random --random-range-ratio 1 --seed 1 \
  --random-input-len 32000 --random-output-len 1000 \
  --max-concurrency 5 --request-rate 5 --num-prompts 100
```

### Short Request Performance

| Metric | With ratio (short only as baseline) | Without ratio (long+short) | With ratio (long+short) |
|----------------------|----------------------|--------------------|-----------------------|
| Avg TTFT | 326.35ms | 9435.48ms | 1898.80ms |
| Avg TPOT | 6.72ms | 6.48ms | 6.56ms |
| Avg E2E latency | 3678.88ms | 12670.72ms | 5171.52ms |

### Long Request Performance

| Metric | With ratio (long only as baseline) | Without ratio (long+short) | With ratio (long+short) |
|----------------------|----------------------|--------------------|-----------------------|
| Avg TTFT | 10432.33ms | 10629.74ms | 10683.45ms |
| Avg TPOT | 4.77ms | 5.20ms | 5.54ms |
| Avg E2E latency | 15194.19ms | 15819.97ms | 16221.47ms |

### Conclusion

- With `--chunked-prefill-ratio`, short request latency drops significantly vs stock under mixed workload: **E2E 12.67s → 5.17s, TTFT 9.44s → 1.90s**.
- Long request latency increases slightly: **E2E 15.82s → 16.22s, TTFT 10.63s → 10.68s** — expected, since compute is fixed and the long request now shares prefill budget.
