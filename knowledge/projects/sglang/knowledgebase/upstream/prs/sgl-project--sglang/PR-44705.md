## Motivation

`--speculative-draft-window-size` and `--speculative-draft-sink-size` (StreamingLLM-style sink + windowed KV visibility for the multi-step draft decode path) are supported on the Triton and FlashInfer draft attention backends via KV index clipping, but not on the Ascend (NPU) backend. This PR adds equivalent support for NPU so the flags no longer silently fall back to full-KV draft attention.

## Modifications

Sink+window is implemented as an **attention mask** :

- `spec_utils.py`: add `build_draft_window_mask`, which builds a contiguous KV visibility band `[min(sink, seq_len), max(seq_len - window, s_eff))` per request for each draft-decode step — the mask equivalent of the `generate_draft_decode_kv_indices` Triton kernel's visible set (first `sink` tokens + most recent `window` tokens, plus the always-visible per-step draft tree tokens).
- `ascend_backend.py`: resolve the window/sink pair in `AscendAttnMultiStepDraftBackend.__init__` and thread them into every per-step backend; consume the mask in `init_forward_metadata` and `_apply_cuda_graph_metadata` via an early exit to `npu_fused_infer_attention_score` (BSH layout) before paged attention, since the mask is unsupported by `_npu_paged_attention`.
- MLA / hybrid-SWA drafts are gated off as on CUDA (window/sink reset to 0 with a warning): a draft that already windows itself per layer via its native SWA would be double-windowed by the uniform backend-level mask.
- Tests: new unit test `test/registered/unit/npu/attention/test_npu_draft_window_mask.py` pins the mask semantics against a pure-Python oracle of the kernel's visible-set definition; extend `test/registered/kernels/ops/speculative/test_draft_decode_window.py` with backend-wiring checks for the Ascend multi-step backend.

## Accuracy Tests

Unit tests (all passing):

- `test/registered/kernels/ops/speculative/test_draft_decode_window.py`: 5 passed, including the new Ascend backend wiring checks.
- `test/registered/unit/npu/attention/test_npu_draft_window_mask.py`: mask construction validated against the closed-form visible-set oracle across sink/window/step combinations.

End-to-end on Qwen3.6-35B-A3B NEXTN (NPU, TP2, `--speculative-num-steps 3 --speculative-eagle-topk 1 --speculative-num-draft-tokens 4`, 6 fixed greedy requests):

- Identity-window control (`--speculative-draft-window-size 8192 --speculative-draft-sink-size 0`, mask path active with an empty band): all 6 outputs **byte-identical** to the no-window baseline, including identical per-request accept-length sequences — proving the mask plumbing is lossless.
- Real window (`--speculative-draft-window-size 16 --speculative-draft-sink-size 4`): outputs byte-identical across CUDA-graph and eager modes and across same-config reruns (engine deterministic); `avg_spec_accept_length` 3.04 vs 3.12 baseline (same ballpark — expected to drift slightly as accept-pattern changes alter verify batch shapes).
