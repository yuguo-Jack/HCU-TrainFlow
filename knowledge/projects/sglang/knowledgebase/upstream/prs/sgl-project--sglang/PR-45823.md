## Motivation

GLM’s clamped SwiGLU activation and FP8 activation quantization currently run as separate kernels in the Triton MoE path. This materializes an intermediate BF16 tensor and introduces an additional kernel launch and global-memory round trip.
For a representative BF16 input of shape [160000, 1024], fusing these operations reduced latency from 254.39 μs to 107.13 μs—a 57.9% reduction (2.37× speedup) for the activation-and-quantization portion, excluding the surrounding MoE GEMMs.

## Modifications

Extend the existing CUDA SwiGLU/quantization kernel with optional BF16 intermediate rounding and configurable rows per CTA.
Fuse GLM’s clamp, SwiGLU activation, and group-wise FP8 quantization, eliminating the intermediate BF16 tensor.
Preserve the original BF16 rounding behavior before quantization to maintain numerical equivalence with the separate kernels.
Add an opt-in Triton MoE integration via SGLANG_OPT_MOE_ACT_QUANT_FUSION=1, guarded by the validated GLM configuration. Unsupported configurations retain the existing path.
Preserve existing kernel defaults and compatibility with both non-TMA and TMA expert-row layouts.
Add regression tests covering bitwise FP8 output/scale equivalence, padding handling, CUDA Graph replay, and unchanged default behavior.
