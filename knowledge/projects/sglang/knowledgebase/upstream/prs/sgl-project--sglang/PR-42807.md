# [Rust] Upgrade sglang-radix-tree to PyO3 0.29

[Upstream PR](https://github.com/sgl-project/sglang/pull/42807) · state: closed · merged: True

## Original PR description

## Motivation

tldr; upgrading pyo3.

`rust/sglang-radix-tree` pins PyO3 0.22.6, which has published advisories fixed only in later releases (RUSTSEC-2025-0020, fixed in 0.24.1; RUSTSEC-2026-0177, GHSA-36hh-v3qg-5jq4 and GHSA-chgr-c6px-7xpp, fixed in 0.29.0). This moves the crate to PyO3 0.29.2, the same 0.29 line the `rust/` workspace already uses.

## Modifications

Changes are in `rust/sglang-radix-tree` (`Cargo.toml`, `Cargo.lock`, `src/python_bindings.rs`), plus one comment in `rust/Cargo.toml`. `tch` is unchanged; it does not depend on PyO3.

- `PyTensor`: `FromPyObject::extract_bound` → `FromPyObject<'a, 'py>::extract(Borrowed)`, and `ToPyObject`/`IntoPy` → `IntoPyObject`. Wrapping a tensor now returns a `PyErr` instead of panicking on failure.
- `.into_py(py)` → `.into_py_any(py)?`, `allow_threads` → `detach`, `PyList`/`PyDict`/`PyBytes::*_bound` → the non-`_bound` constructors, and `Py::from_owned_ptr` → `Bound::from_owned_ptr(..).unbind()`.
- The `Clone` pyclasses that are extracted from Python arguments (`TreeCoreInitParamsBinding`, `MatchParamsBinding`, `DecLockRefParamsBinding`, `TlruFloatConfig`) opt into `from_py_object`. This keeps today's extraction behavior and avoids the 0.29 deprecation.
- `skipped_lock_components` on `DecLockRefParamsBinding` and `IncLockRefResultBinding` gets an explicit getter that returns `list[int]`. Since PyO3 0.23, a `Vec<u8>` field would otherwise convert to `bytes`.
- `rust/Cargo.toml`: the `extension-manifests` comment said the crate stays out of the workspace because of the PyO3 0.22 API. After this change, the remaining reason is that it builds against libtorch through `tch`.

## Accuracy Tests

No model-output impact. Parity check: I built the extension from `main` (PyO3 0.22) and from this branch, then ran the same script through `RustUnifiedTreeCoreBinding` and `RustBigramUnifiedTreeCoreBinding`. It covers init, stepped inserts, `match_prefix`, `match_full_device_prefix`, `inc_lock_ref`/`dec_lock_ref`, device eviction, KV events, `skipped_lock_components` get/set, and the wrong-type tensor error. The output is byte-identical between the two builds.

With the pinned Rust 1.92 toolchain, the pre-commit radix-tree steps pass: `cargo fmt --manifest-path sglang-radix-tree/Cargo.toml` and `cargo clippy --manifest-path sglang-radix-tree/Cargo.toml --all-targets --no-default-features --features tch/doc-only -- -D warnings`. `cargo check --locked --all-targets` passes, and the generic pre-commit hooks pass on all changed files.
