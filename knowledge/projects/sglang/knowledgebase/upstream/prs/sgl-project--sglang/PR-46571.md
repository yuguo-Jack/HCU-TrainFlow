# [Fix] gigachat35: Keep streamed tool_index contiguous and honor SGLANG_FORWARD_UNKNOWN_TOOLS

[Upstream PR](https://github.com/sgl-project/sglang/pull/46571) · state: open · merged: False

## Original PR description

## Motivation

`GigaChat35Detector.parse_streaming_increment` has two streaming-only bugs (non-streaming is correct):

1. **Non-contiguous `tool_index`.** The streamed `tool_index` was the raw position of the `<｜GCML｜invoke>` in the region. When an unknown tool is skipped, the next valid call is streamed with `tool_index=1` and no index 0. For the same input, `detect_and_parse` returns index 0.
2. **`SGLANG_FORWARD_UNKNOWN_TOOLS` ignored.** Non-streaming forwards unknown tools when the env var is set (via `parse_base_json`). Streaming always dropped them.

Repro: `<｜GCML｜tool_calls>` + invoke `nope` + invoke `search` + `</｜GCML｜tool_calls>`, with only `search` defined.

| | before | after |
|---|---|---|
| streaming, forward off | `[(1, "search")]` | `[(0, "search")]` |
| streaming, forward on | `[(1, "search")]` | `[(0, "nope"), (1, "search")]` |

## Modifications

- `tool_index` now counts the calls actually emitted (`len(self.prev_tool_call_arr)`) instead of invoke positions.
- Streaming now honors `SGLANG_FORWARD_UNKNOWN_TOOLS`.
- `prev_tool_call_arr` and `streamed_args_for_tool` are appended to directly, since indices are now contiguous; the pad-with-empty logic is gone.
- New `test/registered/unit/function_call/test_gigachat35_detector.py` (CPU CI) with two regression tests. This detector had no tests before. Both tests fail on current main.

Note: #45258 (O(N) streaming) edits the same loop but keeps `i = self._emitted_invokes` as the index. Whichever PR lands second needs a small rebase.
