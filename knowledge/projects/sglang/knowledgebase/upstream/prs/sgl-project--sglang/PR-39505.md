# [AMD][CI] Retire legacy GSM8K/MMLU from AMD CI in favor of sgl-eval

[Upstream PR](https://github.com/sgl-project/sglang/pull/39505) · state: open · merged: False

## Original PR description

## Motivation

`benchmark/gsm8k` and `benchmark/mmlu` are gone from main (#41215), and GSM8K/MMLU evaluation is moving to
sgl-eval through the in-process adapter `sglang.test.sgl_eval_utils.run_sgl_eval` (#41216, #41280). None of
those PRs touched `test/registered/amd/`, so AMD CI is now the largest remaining consumer of the legacy GSM8K
scorers: 35 hand-copied evaluators, roughly 50 callers of the deprecated `sglang.test.few_shot_gsm8k`, and
104 `run_eval(eval_name="gsm8k")` call sites that still hit the 5-shot completion scorer.

This PR moves all of them onto `run_sgl_eval`, so AMD CI no longer depends on `few_shot_gsm8k`,
`simple_eval_mixed_prefix_gsm8k` or the deprecated `run_eval` for GSM8K.

MMLU needs no AMD work: nothing under `test/registered/amd/` referenced it, and main already routes it to
sgl-eval.

## Modifications

Four call patterns are replaced across 90 AMD test files. Three GSM8K tests that reached main after this branch was opened (DeepSeek-V4.1-Flash #41476, MiniMax-M3 MXFP4 TP4 #42602, Qwen3.8-Flash-Next-FP8 #36901) are converted the same way. DeepSeek-V4.1-Flash runs with thinking disabled so its answer stays in `message.content`, which is why that test originally used the completion harness.

| Pattern | Count | What it was |
| --- | --- | --- |
| Inline `run_gsm8k_benchmark()` helpers | 35 files | Near-copies of the old `benchmark/gsm8k/bench_sglang.py`: same dataset URL, same 5-shot prompt, same last-integer extraction |
| `sglang.test.few_shot_gsm8k.run_eval` | ~50 callers | Deprecated few-shot module |
| `run_eval(eval_name="gsm8k")` | 104 call sites | Dispatches to `simple_eval_mixed_prefix_gsm8k.GSM8KEval`, i.e. the same 5-shot completion scorer |
| `python -m sglang.test.few_shot_gsm8k` subprocess | 1 file | `test_qwen35_fp8_ar_fusion_mi35x.py`, which shelled out and regex-parsed stdout |

All call sites now use main's `run_sgl_eval`. It returns the same `accuracy` / `invalid` / `latency` /
`output_throughput` keys these tests already read, so only the eval implementation changes: service lifecycle,
score gates, GitHub step summaries and speculative-acceptance checks stay as they are. It also hands off to a
subprocess when called off the main thread, because `math_verify` grades with `SIGALRM`. The AR-fusion test
depends on that, since it evaluates two servers from a `ThreadPoolExecutor`.

The two Qwen3.5 accuracy tests move off the lm-eval harness to `GSM8KMixin` with `gsm8k_backend = "sgl_eval"`,
so `nightly-amd-accuracy-8-gpu-qwen35` and its MI35x twin no longer install `lm-eval[api]`.

`amd_ci_install_dependency.sh` now installs sgl-eval unconditionally, at the 0.1.2 that main's
`sglang[test]` extra pins. The GSM8K-only stage-C jobs pass
`--skip-test-time-deps` and some jobs pass `--skip-sglang-build`, and both flags skip the `sglang[test]` extra
that would otherwise supply it. The ANTLR 4.9.3 pin that already guards the sgl-eval MMLU path now also
covers GSM8K, so its comment is no longer MMLU-specific.

### Token budgets

56 GSM8K call sites still carried `max_tokens=512`. That was correct for a 5-shot completion, which just
continues the pattern and stops at the next `Question`. It is too tight for a chat answer that has to reason
and then emit `\boxed{}`, and several of these configs (DeepSeek-V3.2/V4, Kimi-K2) also run with a reasoning
parser. Truncation there does not look like truncation: the answer never parses and the score collapses.
These are raised to 2048, which matches `run_sgl_eval`'s own default and what the other AMD call sites already
use. MMMU's `max_tokens=30` is untouched because it grades a single letter.

The first nightly run showed 2048 is still too tight for some models:

- Qwen3.5 runs with thinking on and was truncated on about 60% of questions, so its budget is 16384.
- DeepSeek-V4-Pro and GLM-5/5.1 were truncated on 7–15%, so their budget is 4096.

## Accuracy Tests

**Existing thresholds are carried over unchanged and still need recalibration on AMD hardware.** sgl-eval
grades a zero-shot chat answer with `math_verify`, while the legacy scorer took the last integer out of a
5-shot completion, so the two numbers are not comparable in either direction.

The first nightly run on this branch (rocm10, [run 36380012643](https://github.com/sgl-project/sglang/actions/runs/36380012643)) had no request errors. Its GSM8K misses fall into three groups:

- **Truncation.** The budgets above address these; [run 36505561300](https://github.com/sgl-project/sglang/actions/runs/36505561300) reruns the affected jobs.
- **Small non-thinking chat models in `nightly-accuracy-2-gpu`.** Qwen2.5-7B-Instruct scores 0.24 here, against 0.87 on the legacy scorer. It gets no truncated or unparsable answers, but averages about 7 output tokens per question: given sgl-eval's "put the answer (and only answer) inside `\boxed{}`" prompt at temperature 0, it writes the number without working it out. Qwen2-57B-A14B and Qwen2-72B-FP8 drop the same way. How to gate these models is still open.
- **MTP in `test_moriep_small.py`.** The MTP class scores 0.87 against a 0.90 threshold, with 7.5% unparsable answers and none truncated. The non-MTP class in the same file scores 0.965.

Verified without GPUs:

- **Unit tests for the adapter** (`test/registered/unit/bench/test_sgl_eval_adapter.py`, 15 cases, CPU
  suite, hermetic). main has no unit coverage for `sgl_eval_utils`, so these cover its edges:
  - URL construction with and without a scheme in `host`.
  - The metric names callers read directly.
  - Generation settings reaching the eval.
  - The 2048 default budget, and explicit `max_tokens=None` meaning uncapped with a warning.
  - Thread and repeat counts falling back to the eval's own defaults.
  - An incomplete, unparsable or erroring run raising instead of reporting a low score.
  - The worker-thread hand-off.
- Every call site passes only settings `run_sgl_eval` reads: `eval_name`, `base_url`/`host`/`port`,
  `model`, `num_examples`, `num_threads`, `max_tokens`, `temperature`, `top_p`, `top_k`, `seed`,
  `sgl_eval_thinking` and `chat_template_kwargs`. None of them passes `max_tokens=None`.
- No reference to `few_shot_gsm8k`, `simple_eval_mixed_prefix_gsm8k`, `simple_eval_mmlu`, `lm_eval_kit`,
  `benchmark/gsm8k` or `benchmark/mmlu` remains under `test/registered/amd/`, `scripts/ci/amd/` or the AMD
  workflows. The only remaining `run_eval` import under `test/registered/amd/` is the MMMU test, which is out
  of scope here.
- `pre-commit` and `scripts/lint/check_registered_tests.py` pass.

## Speed Tests and Profiling

No inference-path change. `test_qwen35_fp8_ar_fusion_mi35x.py` keeps reporting throughput; it now reads
`output_throughput` from `run_sgl_eval` instead of regex-parsing a subprocess's stdout.
