# [Fix] benchmark: Pass req_to_token_pool to bench_one_batch dummy tree cache

[Upstream PR](https://github.com/sgl-project/sglang/pull/47185) · state: closed · merged: False

## Original PR description

## Motivation

Since #46988, `allocation._storage()` reads `tree_cache.req_to_token_pool`. The `TreeCacheNamespace` dummy cache that `bench_one_batch`'s `extend()` builds doesn't set that attribute, so `batch.prepare_for_extend()` fails:

```
sglang/srt/mem_cache/allocation.py:160, in _storage
    tree_cache.req_to_token_pool,
AttributeError: 'TreeCacheNamespace' object has no attribute 'req_to_token_pool'
```

This is currently failing XPU stage-a on every PR that reaches it (`test/registered/xpu/test_breakable_cuda_graph.py`, `test/registered/xpu/test_intel_xpu_backend.py`), e.g. job 123227153721. CI Retry doesn't retry it because the error is an AttributeError.

## Modifications

Pass `req_to_token_pool=model_runner.req_to_token_pool` to the dummy tree cache. Its other `tree_cache` reads (`rotation_base_of`, SWA retain) only run with a cached prefix or SWA, and this benchmark uses neither.

## Testing

- `py_compile` and `pre-commit run` on the changed file pass.
- XPU stage-a in this PR's CI checks the fix end to end.
