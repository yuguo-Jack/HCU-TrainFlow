# [AMD][PD] enable mori transfer for PD decode DCP

[Upstream PR](https://github.com/sgl-project/sglang/pull/37358) · state: closed · merged: True

## Original PR description

## Motivation

PD decode with DCP currently rejects the Mori transfer backend because Mori does not implement the token relayout required by round-robin DCP KV shards.

## Changes

- Add DCP rank and layer metadata to Mori peer registration.
- Transfer MLA KV at token granularity into each decode rank's DCP shard.
- Map PP-local KV and Mamba state tensors by global layer ID.
- Handle TP mismatch for replicated latent KV and reject unsupported head-sharded layouts.
- Skip cached-prefix early send when DCP relayout is required.
- Allow Mori in the PD decode DCP backend validation.

## Validation

- Mori DCP unit tests: 6/6 passed.
- ServerArgs DCP tests: 6/6 passed.
- Kimi-K3 PP8/TP1 prefill + TP8/DCP8 decode: both servers healthy, with no KV transfer errors.
- 31K long-context retrieval and arithmetic: 8/8 passed, with no errors or truncation.
- GSM8K: 39/40 (97.5%), with no errors or truncation.
- 32K input, 1 output token, concurrency 16, 128 requests: 16,699 input tok/s and 31.11s median TTFT.
- Pre-commit and lint checks passed.

The Kimi-K3 E2E validation used an AITER DCP-enabled stack; this PR only changes the Mori transfer path.
