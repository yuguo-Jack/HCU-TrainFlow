## Motivation

With `--enable-unified-memory`, whether a demand fits the pool was answered by per-chain-shape rules (two token ends, a floating window, recurrent state priced as FULL-token equivalents), each pricing its own bands. Allocation, its capacity check and admission used different rules, so an allocation could be refused after its capacity check passed, or admitted where the take then failed. A sum of free bytes cannot replace those rules: every band starts on its own page grid, so the bytes between two bands of different page sizes may serve neither.

This PR answers every one of these questions with one layout search over the chain of bands and takes every allocation from the layout it plans.

## Modifications

- Planner (`mem_cache/kv/alloc/pricing.py::plan`, `feasible`, `first_plan`, `move_order`): walks the chain once; bands that stay are fixed points, the floats between two of them are packed on their own page grids. Three worlds: nothing moves; unblocked ends compact; unblocked floats also relocate. `feasible` asks the last; `first_plan` returns the least rearrangement that serves the demand, with relocation targets that split the slack between the gaps; `move_order` orders relocations so no float is copied into a block another still holds.
- Realization (`kv/alloc/chain.py::ChainAllocator.realize`, `kv/alloc/band.py::FloatBand.relocate_into`): compacts the listed ends, relocates floats into their planned blocks (keeping live pages already inside the block, copying only the others), then takes every band's pages in chain order.
- Planned takes (`chain.py`, `kv/storage.py`): token extend, decode, window tail and state slots take from one planned layout; `ensure_capacity` and the decode capacity check ask the same question without side effects; a host load's reservation scope is served from the same planner.
- Several target windows (`kv/plan.py`, `kv/decl.py`, `kv/build.py`): windows of different lengths are planned as separate sub-pools, the longest keeping the single-window name and the others named by their length; a window slot beyond what the prefix tree and PD transfers carry is refused where they read it. The production configurator still declares one target window in this PR.
- One admission rule (`mem_cache/prefill_budget.py`, `managers/schedule_policy.py`, `disaggregation/{prefill,decode,utils}.py`): a request's FULL tokens, for each window sub-pool the window its cache retains, and its state slots, after the cached entries the tree could evict, with one layout search. Prefill admission and chunk sizing, the prompt clip, decode-node preallocation and the load-back budget all ask it. The per-shape admission rules, the state-slot token cost and the per-shape preallocation pricing are removed.
- Draft windows: a draft window rides in the target window sub-pool of the same length; one equal to no target window gets its own band named by its length (`mem_cache/layout/fused_draft.py`, `kv_cache_configurator.py`). A draft's window is resolved from its config by its own architecture's rule, the same value its runner uses after loading (`model_executor/model_runner_components/load_model_utils.py::resolve_sliding_layer_window_size`; `sliding_layer_window_size(config)` on the DFlash, DSpark, Gemma 4 MTP, Inkling MTP, EAGLE3 and Dots3 draft classes, values unchanged).
- Backend capability: the runner lists the window sub-pools its layers read (`kv/alloc/runner_ids.py`), and binding a backend that serves fewer is refused, naming the backend; every backend serves one window sub-pool per runner here, so a target with several windows is refused at startup until a backend can read them separately.
- Pinned bands: when the planner finds no layout while a float band is pinned, its freed boundary pages are absorbed (zero-copy) and the answer re-checked, so `ensure_capacity` and the take agree; a host load's scope lays out its demand before the H2D pins for every chain shape (`kv/alloc/chain.py::scoped_physical_takes`).
- Tests: `test/registered/unit/mem_cache/kv/test_chain_plan.py` (every world against an exhaustive search on random small chains; plan validity; downward closure), `mem_cache/test_unified_chain_realize.py` (CPU and CUDA chains with holes, pending pages and fixed pages: every admitted demand realizes with live bytes kept), `mem_cache/test_unified_admission_rule.py`, `mem_cache/test_unified_window_sub_pools.py`, and updates to the existing admission, budget, tri-pool and multiwindow tests.

**Behavior change (unified memory only):** a prefill request that does not fit whole waits under transient pressure; only a request that could not fit an empty pool is cut to the largest chunk that fits. A chunked request's continuation waits while running requests will free memory, and shrinks only when its chunk could never fit whole or nothing else runs.
