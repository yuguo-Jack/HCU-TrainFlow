# [Refactor] platforms: route device and stream state through current_platform

[Upstream PR](https://github.com/sgl-project/sglang/pull/44966) · state: open · merged: False

## Original PR description

## Motivation

`DeviceMixin` already declares `set_device`, `synchronize` and `empty_cache`, but they were marked `[Planned]`: shared srt code called the torch device module directly instead, through `torch.get_device_module(...)`, the srt `get_device_module()` helper, or a stored `device_module`. The same was true for `current_stream` and `current_device`, which had no platform method at all. As a result, a platform can't own these operations: core always reaches into the device's torch module itself. One site, the Ray scheduler actor, called `torch.cuda.set_device` directly.

This continues the series that routes core through the platform layer (#44958, #44960, #44961).

## Modifications

**`DeviceMixin`**
- New: `current_device()` and `current_stream(device=None)`.
- `get_device`, `set_device`, `synchronize` and `empty_cache` move from `[Planned]` to `[Active]`.
- Defaults:
  - `get_device` returns `torch.device(device_type, id)`.
  - `set_device`, `current_device`, `current_stream` and `synchronize` call torch's device module for `device_type`.
  - `empty_cache` stays a no-op.

  These defaults serve out-of-tree platforms, where they do what the call sites did before (`torch.get_device_module(self.device)`), rather than hitting the old `NotImplementedError` (`get_device`/`set_device`) or no-op (`synchronize`).

**Per-platform implementations.** Every in-tree platform defines these methods itself:

| Platform | Implementation | What was wrong with the default |
|---|---|---|
| CUDA, ROCm (CUDA mixin), NPU, XPU | their own torch module | nothing; now explicit |
| CPU | `torch.cpu`; `current_device()` stays `"cpu"`, as `torch.cpu` returns | nothing (`qwen3_next` uses the value as a tensor device) |
| MPS | `current_device()` is 0; `current_stream()` uses `torch.accelerator` | `torch.mps` has no `current_device` or stream API, so the default raised `AttributeError` |
| MUSA | `torch.musa` for `get_device` (a `musa` device), `set_device`, `current_device`, `current_stream`, `synchronize`, `empty_cache` | it inherited the CUDA mixin and reached MUSA only through torchada's `torch.cuda` redirect |
| HPU | new minimal `HpuSRTPlatform`, resolved when `habana_frameworks` reports an HPU; its defaults go to `torch.hpu` | HPU had no platform class, so it resolved to the base platform with `device_type="cpu"` and these ops became CPU no-ops |

**`torch.accelerator`:** the only use in srt was the fallback in the `get_device_module()` helper, which now returns the module for `current_platform.device_type`. I didn't make it the general mechanism. torchada documents `torch.accelerator` dispatch as broken below torch_musa 2.11.0.post2, which is newer than the pinned version. It also patches `torch.accelerator.synchronize`, because the MUSA implementation syncs a different scope. The two diffusion-kernel `torch.accelerator.current_device_index()` calls in `kernels/` are untouched.

**`set_device` sites** now call `current_platform.set_device(current_platform.get_device(gpu_id))`:
- `distributed/bootstrap.py`
- `ModelRunner`
- `disaggregation/encoder/server.py`
- `disaggregation/nixl/conn.py`
- `ray/scheduler_actor.py` (was `torch.cuda.set_device`)
- `AsyncD2HCopyWorker`

**`synchronize` / `empty_cache` / `current_stream` / `current_device`:** 72 calls across 41 files, rewritten mechanically. They are in the scheduler and its PP mixin, overlap utils, the HiSparse coordinator, the cache controller, the mem-cache pools and linkers, the speculative workers, the graph runners and backends, EPLB, the checkpoint engine, `utils/common.py`, a few models, and `benchmark/one_batch.py`.
- Every call site was already resolving the module of the process's device and calling it without (or with the same) device argument.
- `mem_cache/common.py` passed the KV device to `synchronize(device)`; it now synchronizes the current device, which is the same device.

**Cleanup:**
- `device_module` locals and attributes that became unused are removed, along with the `_prewarm_hccl_group` `device_module` parameter.
- Unit tests that faked a device module for code that now calls `current_platform` patch `current_platform` instead: dynamic chunk sizer, LoRA overlap loader, DSA layer split, NIXL backend init, and the parallel-runtime bootstrap.
- `docs/docs/hardware-platforms/plugin.mdx` lists the full fallback chain.

**Not in this PR:**
- `hardware_backend/npu` and `hardware_backend/xpu`: device-owned code that keeps using its own torch module.
- The multimodal_gen platform layer: once #43443 moves it onto `DeviceMixin`, its call sites follow in a separate PR.
- `Stream`, `Event` and the `stream(...)` context.
- Direct `torch.cuda.*` calls.
