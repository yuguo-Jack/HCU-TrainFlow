# [CI] openai-server: Share the default Python server fixture

[Upstream PR](https://github.com/sgl-project/sglang/pull/46941) · state: open · merged: False

## Original PR description

## Motivation

Every PR that runs full CI pays for two extra launches of the default Python server in `test_openai_server.py`, on CUDA (`base-b-test-1-gpu-small`) and AMD. Removing them saved 102 s of whole-file time on B200 when run the way CI runs it (382 s to 280 s), and 104 s, 146 s, and 52 s in other run pairs on a shared node. No CI runner was measured.

The saving is small. If a CI runner saves about 100 s, that is about 1% of `base-b-test-1-gpu-small` and about 0.1% of the 80,000-114,000 s CI total.

The OpenAI/Anthropic, Responses, and Score groups launch identical servers. The two extra launches took 93-114 s together, and the cases on the shared server took about 20 s.

No open PR I found shares these launches, and #44337 and #29810 only add other tests to this file.

## Modifications

The three groups become mixins on one `TestOpenAIServer` fixture. Launch arguments, other fixtures, CI registration, and remaining requests and assertions do not change.

The Responses `test_regex`, `test_response_prefill`, and `test_model_list` send the same request bytes as the OpenAI tests with those names, so this PR removes them. The Responses `test_penalty` calls `/v1/responses`, so it stays as `test_responses_penalty`.

## Accuracy Tests

`6118eda345` and `700318150f` are commits from before I squashed this branch onto main `7b88f09239`. The squash kept the same diff, and I did not repeat these runs on it. On the squashed commit, only pre-commit ran.

On B200s in the CI environment, I ran the whole file, including the Rust classes, on main 582168dd7c, head 6118eda345 (the fixture change), and head 700318150f (the removal). No case failed. With retries off, `TestOpenAIServer` at 700318150f ran reversed, shuffled, and twice in a row without failures.

No case reads another case's response ID or asserts on cached tokens, and the default server stores no Responses records.

Sharing one server couples these groups, but a crash already aborts the file: a SIGKILL with CI retries gave exit 137 on main and head 700318150f.

I did not run AMD, the small GPU runner, or GitHub CI (this draft has no `run-ci`). `est_time` stays unchanged: weekly-update-est-time.yml refreshes the CUDA value, and no AMD run measured this change.
