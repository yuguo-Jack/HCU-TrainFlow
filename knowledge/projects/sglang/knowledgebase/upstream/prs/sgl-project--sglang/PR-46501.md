# [Fix] hicache: Delegate on_host_pools_registered in the failure injector

[Upstream PR](https://github.com/sgl-project/sglang/pull/46501) · state: closed · merged: True

## Original PR description

## Motivation

The failure injector from #43539 proxies the full HiCacheStorage API, but it misses one method: `on_host_pools_registered`.

The controllers fire that hook once per attach, on whatever the factory returned (cache_controller.py:619, hybrid_cache_controller.py:350). It is the documented place for backends that have to finalize once the pool set is known; the docstring even says raising there fails the attach. With the injector in between, the call lands on the base-class no-op and the backend's finalization is skipped.

Nothing on main overrides the hook today, so nothing is broken right now. It is a small contract fix before someone actually relies on the hook and the injector eats it.

## Modifications

One delegation on `HiCacheStorageFailureInjector`, same shape as the `register_*` callbacks above it.

New unit test file with two cases: the delegation itself, and a check that fails whenever a public `HiCacheStorage` method exists without an injector override. The second one is there so this class of miss cannot quietly come back.

## Accuracy Tests

Test-only path (the injector is only built when the delay/failure env vars are set), so there is no inference path change. Locally I ran ruff format, the pre-commit ruff selection, and py_compile on both files. Could not run the new test on this machine (no torch); it is registered in base-a-test-cpu, so CI will pick it up.
