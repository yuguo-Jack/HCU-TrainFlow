# [Fix] memory: Add per-rank device-memory accounting and an opt-in all-rank allocator-cache release (#46831)

[Upstream PR](https://github.com/sgl-project/sglang/pull/46932) · state: open · merged: False

## Original PR description

## Motivation

[#46831](https://github.com/sgl-project/sglang/issues/46831) reports a ROCm DCP-PD deployment aborting with `HSA_STATUS_ERROR_OUT_OF_RESOURCES` while the PyTorch allocator's *reserved* memory grew ~15.7 GiB against ~0.8 GiB of live allocations, with the driver's own free-memory reading falling from 16.36 GiB to 0.92 GiB a couple of seconds before the abort.

Two things are missing today, and the issue asks for both:

1. **Visibility.** The engine does not log, per rank, `memory_allocated` / `memory_reserved` / `memory_stats` / `mem_get_info` alongside the batch shape, does not capture an allocator snapshot, and cannot separate "the allocator cached a lot" from "something outside Torch took the memory". The quantity needed for that separation is `total - free - reserved` — driver-allocated memory that the Torch allocator does not own at all (HIP workspaces, other libraries, other processes).

2. **A release that is not rank-0-only.** The only periodic allocator-cache release in the tree is the one carried by `IdleSleeper`, and `IdleSleeper` is created only where `pp_rank == 0 and attn_tp_rank == 0 and attn_cp_rank == 0` — the sockets it polls exist only there. `SGLANG_EMPTY_CACHE_INTERVAL` is read only inside `IdleSleeper`, so the release rides along on rank 0 and every other rank keeps its cached blocks for the life of the process. The reporter measured exactly that asymmetry: their rank-0-only control (`S2k`) restored TP0 to 10.7 GiB free while the other decode ranks stayed near full and aborted.

The issue also asks explicitly to "recheck current allocator/graph behavior instead of carrying the old unconditional workaround forward", and notes that the reporter's own all-rank hunk "was not measured in isolation — these builds also retained diagnostics and the earlier TP0 hook". This PR therefore lands the **mechanism and the measurements**, with the **policy off by default**, rather than shipping an unverified workaround.

## Modifications

### New module: `python/sglang/srt/model_executor/device_memory_monitor.py`

* `DeviceMemorySample` — one reading of the device's memory state on a rank, with `cached_bytes` (`reserved - allocated`) and `unaccounted_bytes` (`total - free - reserved`) derived from it.
* `read_device_memory()` / `read_free_bytes()` — driver reads that never raise; `mem_get_info()` and `memory_stats()` failures degrade to `None` rather than taking the serving loop down.
* `DeviceMemoryMonitor` — the per-rank monitor and the opt-in policy:
  * **periodic sampling**: JSON log lines (`device_memory.sample`) with the memory reading, the driver reading, the `unaccounted_bytes` term, the decode batch shape (`batch_size`, `num_tokens`, `forward_mode`, `can_run_graph`) and the rank identity;
  * **opt-in all-rank release**: when the driver-reported free memory drops below a floor, the allocator cache is released **on that rank** — and, because each scheduler process *is* the TP worker process for its own rank, that is every rank rather than only rank 0. Each release is timed (`pause_ms`, plus running `total_release_ms` / `max_release_ms`), and a before/after reading is logged with it, so the latency cost is measured before it is turned into a policy;
  * **allocator snapshots**: `torch.cuda.memory_snapshot()` dumps (before/after each release, plus a post-capture baseline) into a configurable directory, with the driver reading and the rank identity alongside the segment/blocks table;
  * **fail-safe**: the driver cannot be read → no release is attempted; the snapshot cannot be written → the release still proceeds.

### New environment variables (`python/sglang/srt/environ.py`)

| Variable | Default | Meaning |
| --- | --- | --- |
| `SGLANG_DEVICE_MEMORY_LOG_INTERVAL` | `0` | Decode iterations between per-rank memory log lines. `0` disables logging. |
| `SGLANG_DEVICE_MEMORY_LOG_TARGET` | `""` | Comma-separated log targets. Empty → stdout; any other value is treated as a directory receiving `{hostname}_{rank}.log`. |
| `SGLANG_DEVICE_MEMORY_FREE_THRESHOLD_MB` | `0` | Release the allocator cache when driver-reported free memory falls below this many MiB. `0` disables the policy. |
| `SGLANG_DEVICE_MEMORY_RELEASE_INTERVAL` | `8` | Decode iterations between free-memory threshold checks. Matches the reporter's "every eight decode iterations". |
| `SGLANG_DEVICE_MEMORY_SNAPSHOT_DIR` | `""` | Directory for `memory_snapshot()` JSON dumps. Empty disables snapshots. |

All defaults preserve the engine's current behavior: no periodic logging, no periodic release, no snapshots.

The threshold is deliberately expressed in **driver-reported free memory** rather than in Torch's `reserved` count, because the quantity the HIP runtime aborts on is the former.

`SGLANG_EMPTY_CACHE_INTERVAL` gains a comment recording that it is honoured on rank 0 only, pointing at the new module as the all-rank alternative.

### Wiring (`python/sglang/srt/model_executor/model_runner.py`)

* `ModelRunner.__init__` builds the monitor via `DeviceMemoryMonitor.maybe_create(...)`, which returns `None` unless one of the knobs asks for it — the engine's behavior is unchanged by default.
* `ModelRunner.forward` feeds one observation per forward pass. Only decode passes are counted. `input_ids.numel()` is a metadata-only read, so the loop gains **no device synchronization**.
* `ModelRunner.init_cuda_graphs` writes the baseline allocator snapshot after graph capture, since the report compares `--mem-fraction-static` settings *after* capture.

Hooking `forward` keeps the monitor out of the warmup and CUDA-graph-capture paths (neither calls `ModelRunner.forward`).

### Tests

`test/registered/unit/model_executor/test_device_memory_monitor.py` — 40 tests covering the sample arithmetic, the log cadence and payload, the release policy (fires below the floor, does not fire at or above it, honours the iteration cadence, times the pause), the **per-rank** nature of the release (a rank with 10 GiB free does not release while a rank with 2 GiB free does — the `S2k` regression), the environment plumbing and its defaults, the snapshot path, and driver-read failures.

## Accuracy Tests

Not applicable. No kernel, model, or forward-path math is changed — the monitor only reads memory counters and, when explicitly enabled, releases the allocator cache. `input_ids.numel()` is metadata-only and adds no device sync.

## Speed Tests and Profiling

Not applicable for the default configuration: with every knob off, `DeviceMemoryMonitor.maybe_create()` returns `None` and the hot path is a single `is not None` check.

For the opt-in policy, the release cost is *measured at runtime* rather than assumed: every release logs `pause_ms` alongside the running `total_release_ms` and `max_release_ms`, so the wall-clock cost of the policy is observable per deployment before it is relied upon.

**Testing caveats — please read.** This was developed and validated on a macOS arm64 host with no AMD GPU, so the gfx950/ROCm behavior was verified by **static analysis only**; no ROCm run was performed. The issue itself notes that a reproduction on current upstream main is still pending. Concretely, the local environment has no `mlx`, `triton`, `aiter`, or `cutlass`, and `sglang.srt.managers.scheduler` cannot be imported locally. The numbers above are the reporter's, not measurements taken here.
