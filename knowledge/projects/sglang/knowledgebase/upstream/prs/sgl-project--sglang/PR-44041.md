# [AMD] Support DeepSeek-V4 context-parallel prefill two-batch overlap

[Upstream PR](https://github.com/sgl-project/sglang/pull/44041) · state: open · merged: False

## Original PR description

## Motivation

DeepSeek-V4 context-parallel prefill exposes attention KV/compressor AllGather and TP-MoE AllGather/ReduceScatter on the critical path. This ports our downstream CP two-batch-overlap implementation to the current interleave CP strategy so one microbatch's computation can overlap the other microbatch's communication.

**Draft: the current-main port has CPU contract coverage, but has not yet been run on an MI355X model server. GPU accuracy, memory stability, and performance validation are still required. Historical measurements below describe the downstream implementation, not this PR head.**

## Modifications

- Enable `--enable-two-batch-overlap` for DeepSeek-V4 HIP interleave prefill with BF16 unified KV, TP-MoE without EP, PP1/DCP1, and eager prefill. Reject unsupported combinations rather than silently enabling an unvalidated path. V4.1 is outside this PR.
- Split a prefill batch into two token ranges, including within a request. Build each child's CP metadata before attention backend planning. Align boundaries to `CP²`, because the current strategy also pads each rank's local rows to CP size. Preserve parent coordinates for logits and merge outputs using CP-local coordinates.
- Decompose attention into local Q/KV/compressor preparation, asynchronous gathers, and a finish phase that consumes the gathered data. Keep Q local; C4 also prepares the indexer query before communication and computes its indices after compressor results are available. The ordinary attention core and output projection are shared with the non-TBO path.
- Reuse the primary CP communicator and one TBO communication stream for both attention and MoE collectives. Launch/wait phases retain producer tensors and use per-microbatch events and reusable receive buffers.
- Keep non-CP DP/EP schedules intact. Steps below 10,240 new tokens use ordinary CP; `SGLANG_CP_TBO_MIN_EXTEND_TOKENS` allows hardware-specific tuning. Invalid CP child layouts also fall back to ordinary CP.
- Add CPU geometry, dispatch, metadata, and stream-handoff coverage, extend split/merge tests, and update the existing AMD CP-TBO GSM8K test to exercise the supported configuration.

Example additions to an existing ROCm DeepSeek-V4 CP deployment:

```bash
export SGLANG_HACK_FLASHMLA_BACKEND=unified_kv_triton
export SGLANG_DSV4_UNIFIED_KV_FP8=0

python -m sglang.launch_server \
  --model-path deepseek-ai/DeepSeek-V4-Pro \
  --trust-remote-code \
  --tp 4 --dp 1 \
  --enable-prefill-cp --cp-strategy interleave \
  --attention-backend dsv4 \
  --enable-two-batch-overlap \
  --disable-piecewise-cuda-graph \
  --disable-shared-experts-fusion \
  --chunked-prefill-size 32768 --max-prefill-tokens 32768
```

## Accuracy Tests

Completed locally:

- 10 CPU contract tests in `test_dsv4_cp_tbo_contracts.py`, including CP2/4/8 layout reconstruction, invalid-layout fallback, model/topology/layout guards, ordered attention consumption, and shared-stream/independent-buffer behavior.
- Python AST parsing for all changed Python files, Ruff selected lint/import checks, Ruff format checks, and `git diff --check`.
- Compared the extracted ordinary attention core/projection AST with the upstream implementation: unchanged.

The CPU tests isolate production methods and mock GPU transport; they are not distributed GPU correctness tests. The full SGLang unit suite and the AMD GSM8K test have not been run for this port.

Historical downstream GSM8K reference: 1,319 questions, TP4/CP4 on MI355X, temperature 0: ordinary CP **0.920**, CP-TBO **0.928**. This predates this main-branch port and is not a claim of bitwise equivalence or current-head accuracy. The AMD test retains the existing CP-only accuracy threshold for a fresh CI run.

## Speed Tests and Profiling

Historical downstream MI355X, TP4/CP4, 32K prefill chunk:

| Measurement | CP | CP-TBO | Change |
| --- | ---: | ---: | ---: |
| 32K GPU step | 1,073.542 ms | 852.717 ms | 20.57% less time |
| Per-GPU prefill throughput | ~7,395 tokens/s | ~9,100 tokens/s | ~23% higher |

Reference traces: [ordinary CP](https://taco-public-1251001002.cos.ap-shanghai.myqcloud.com/profiles/prefill-tbo/cp-tacops.trace.json.gz), [CP-TBO](https://taco-public-1251001002.cos.ap-shanghai.myqcloud.com/profiles/prefill-tbo/cp-tbo.trace.json.gz).

Those measurements used downstream kernel/communication builds, including AITER AllGather launch-width tuning, which is outside this PR. They motivate the schedule but do not establish performance on current main. An earlier short-extend GSM8K workload regressed despite the large-step gain; the minimum-work fallback avoids applying the two-microbatch schedule indiscriminately to those short steps. The crossover must be remeasured on the final upstream configuration.
