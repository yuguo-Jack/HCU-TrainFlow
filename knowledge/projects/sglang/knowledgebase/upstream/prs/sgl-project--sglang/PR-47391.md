# [Fix] cuda-graph: Keep an aligned top bucket and size draft graphs by their capture width

[Upstream PR](https://github.com/sgl-project/sglang/pull/47391) · state: open · merged: False

## Original PR description

## Motivation

`get_batch_sizes_to_capture` drops the top decode bucket when `--cuda-graph-max-bs` is below the request pool and not a multiple of the attention-TP alignment. Example: DP attention with attn TP 4 and `--cuda-graph-max-bs 15`. The generated buckets are `[1..8, 10, 12, 14, 15]`, and the pool is 16. The pool endpoint is only appended when the max bucket exceeds the pool. The alignment filter then leaves `[4, 8, 12]`, so batches 13–15 fall back to eager.

The EAGLE draft runners also select buckets as if each request were one row. Each runner's real width is:
- draft decode: `topk`
- draft extend: `num_draft_tokens`
- multi-layer draft extend: the window

At width 1 the alignment filter is stricter than the real row alignment, so those graphs get coarser buckets and pad more than needed.

## Modifications

- `get_batch_sizes_to_capture`:
  - Cap at `min(max bucket, pool)`.
  - Align request counts by `mul_base / gcd(mul_base, width)`. This is the same constraint as `bs * width % mul_base == 0`, applied per request.
  - With padding enabled, always keep the aligned endpoint.
  - With `--disable-cuda-graph-padding`, only configured sizes are captured. This drops the unusable endpoint above the cap.
- `EAGLEDraftCudaGraphRunner`, `EAGLEDraftExtendCudaGraphRunner` and `MultiLayerEagleDraftExtendCudaGraphRunner` pass their `captured_req_width`.
- `EagleDraftWorker` computes the draft-decode and draft-extend bucket lists at their own widths. These lists are used in the capture logs.
- The topk=1 chain constants are sized to the TP alignment (x2 under TBO). This keeps the fast path for the padded top bucket instead of falling back to the slow path (and keeps the megakernel's `[:bs]` slice in range).
- Graph-static buffers size from the padded top bucket. Padding rounds the top decode bucket up to the attention-TP alignment (x2 under TBO), so it can exceed `--cuda-graph-max-bs` (max-bs 15 with attn TP 4 captures 16). New `decode_capture_max_bs` (`cuda_graph_config.py`) and `runtime_context.decode_cuda_graph_max_bs()` are the single bound, used by:
  - the topk=1 chain constants
  - LoRA, inkling sconv, kv-canary
  - dflash/dspark draft samplers and epilogues
  - the CuteDSL MoE token budget
  - the DeepEP v2 and MegaMoE decode dispatch budgets
  - the trtllm native FP4 output buffer
- When no configured bucket is aligned below the pool, keep the aligned endpoint and log it instead of asserting.
