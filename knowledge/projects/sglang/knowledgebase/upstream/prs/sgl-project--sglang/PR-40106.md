# dsv4.1: add numa_shared Engram host table layout

[Upstream PR](https://github.com/sgl-project/sglang/pull/40106) · state: open · merged: False

## Original PR description

## Summary

- Add an opt-in `SGLANG_DSV41_ENGRAM_HOST_TABLE_LAYOUT=numa_shared` placement for DeepSeek-V4.1 Engram host tables. Each GPU NUMA node gets one complete memfd copy, `MPOL_BIND`'d before the first page fault, and mapped only by the TP ranks on that node. Lookups stay local and still skip the lookup all-reduce, same as `shared`.
- NUMA discovery uses `torch.cuda.get_device_properties` PCI domain/bus/device plus `/sys/bus/pci/devices/<bdf>/numa_node`. hipify keeps those field names, so the same path covers CUDA and ROCm. No new vendor dependency.
- The default stays `shared`. A single NUMA node degrades to one owner. Unresolved topology, multiple hosts, or `mbind` failure abort table creation instead of silently placing pages on the wrong node.
- MUSA is not in this PR. An internal fork already has a ctypes `musaDeviceGetPCIBusId` path; that can follow once this layout is in.

## Why

On a 2-socket machine the `shared` layout puts the only host copy on whichever node rank 0 first-touches. Ranks on the other socket then gather Engram rows across the CPU interconnect. `numa_shared` keeps a full copy next to those GPUs. The cost is host RAM: one full table per participating NUMA node (about 189 GiB per copy for the V4.1 fp8 tables).

## Measured on MUSA (not a CUDA/ROCm run)

Internal 8-GPU / 2-NUMA machine, FP8, stable fused Engram kernels, BS1 / ISL 1024 / OSL 32, 3 rounds. Compared with `shared` + fused:

| layout | TTFT | TPOT | GSM8K |
| --- | --- | --- | --- |
| shared + fused | 702.543 ms | 95.330 ms | 20/20, invalid 0 |
| numa_shared + fused | 693.847 ms (-1.24%) | 95.472 ms (+0.15%) | 20/20, invalid 0 |

Function, accuracy, and non-regression passed. TPOT did not clear a 3% bar, and host memory doubled, so this stays experimental and is not the default. GPU 0-3 sat on node 0 and GPU 4-7 on node 1; both copies were fully huge-page backed.

Thanks @Lyapunova-cd for the per-NUMA host copy; that placement is still not on main. One thing changed under it: since #46893 the Engram host-table layout is chosen with `--engram-config`, and `SGLANG_DSV41_ENGRAM_HOST_TABLE_LAYOUT` is deprecated (it is only translated for old launches). The old `shared` layout is now `{"placement": "cpu", "replication": "per_node"}`, and the default host layout is one shard per rank (`"replication": "none"`, backed by transparent huge pages).

Could you rebase this as a new `replication` value, for example `per_numa`:

1. Add it to `EngramReplication` in `python/sglang/srt/arg_groups/engram_config.py`.
2. Validate it in `_resolve_engram_config` (`python/sglang/srt/arg_groups/deepseek_v4_hook.py`), next to the `per_node` checks.
3. Build it in `_HostTable` (`python/sglang/srt/layers/engram.py`).
4. Add a row to `docs/docs/advanced_features/engram.mdx`.

A lookup-time comparison against the default `per_rank` table at the same setting would also help decide where it fits.
