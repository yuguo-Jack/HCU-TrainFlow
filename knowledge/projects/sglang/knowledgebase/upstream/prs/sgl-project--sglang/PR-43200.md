# [MemCache] Serve disabled hybrid-SWA models with `UnifiedRadixCache`

[Upstream PR](https://github.com/sgl-project/sglang/pull/43200) · state: closed · merged: True

## Original PR description

- `--disable-radix-cache` on hybrid-SWA layouts (incl. DeepSeek-V4 HiSparse) builds `UnifiedRadixCache(disable=True)` instead of `SWAChunkCache`; the condition collapses to `host_pool or not is_pure_swa`
- `SWAComponent` accepts `DeepSeekV4HiSparseTokenToKVPoolAllocator` (HiSparse forces radix off, where the component only frees through APIs that allocator defines)
- Changes hybrid-SWA PD decode with `cpu_tensor` backup (the default `host_pool` already used `UnifiedRadixCache`), and NPU DeepSeek-V4
- Validated: gpt-oss-20b and gemma-4 retract + strict busy check, hybrid-SWA PD, within noise of `SWAChunkCache`

## Other observable differences
Found by a base-vs-head equivalence check; KV slots, generated tokens and pool usage are unchanged.
- `--enable-session-radix-cache` or `--radix-eviction-policy tlru` with `--disable-radix-cache` used to fail at startup (the check required `UnifiedRadixCache`); they now start and have no effect
- The OOM error text from `available_and_evictable_str` is two lines (`Available full tokens: ...` and `Available swa: ...`) instead of one line that reported the SWA pool as `Available tokens`, and the OOM path prints the (empty) tree via `pretty_print`
- `--enable-metrics` registers a `RadixCacheMetricsCollector` that never records a sample
- KV events (`AllBlocksCleared` on construction and flush) and startup validation of `--radix-eviction-policy-config` are removed again by #43253
