# [Feat] spec: support adaptive speculative decoding for STANDALONE worker

[Upstream PR](https://github.com/sgl-project/sglang/pull/47966) · state: open · merged: False

## Original PR description

## Motivation

Enable adaptive speculative decoding (`--speculative-adaptive`) for the built-in STANDALONE Spec V2 worker, which uses an independent causal draft model.

## Changes

- Allow STANDALONE in adaptive configuration resolution and initialize its `AdaptiveController`.
- Reuse the inherited EAGLE runtime-state build/apply protocol for draft, target verify, and draft-extend backends and graphs.
- Strengthen top-k fallback coverage: with explicit static parameters, `topk=4` disables adaptive decoding while preserving steps=3, draft tokens=8, and maximum allocation width=8.
- Add `test/registered/spec/test_spec_standalone_adaptive.py`, registered for CUDA `base-b / 1-gpu-large` using FA3. Separate cases cover CUDA graphs enabled and disabled.
- Use ungated Qwen2.5-1.5B-Instruct (target) and Qwen2.5-0.5B-Instruct (draft), instead of requiring gated Llama checkpoints. Anonymous weight access and identical tokenizer mappings were verified; hidden sizes differ (1536 vs 896).
- The GPU tests exercise batch-size slots for steps 1/3/5/0, transition above the initial step count, positive-to-zero-to-positive recovery within a live request, greedy token consistency against the zero-step batch, and target verify graph use from decode logs.

## Scope and limitations

- Adaptive decoding requires top-k=1. Fallback is verified for fully specified static parameters; top-k alone still encounters the pre-existing static-configuration assertion.
- Existing STANDALONE PP and attention-DP restrictions remain.
- TP=2 and other attention backends are not covered by the new single-GPU FA3 cases.
- Single-GPU validation is complete. Ready for maintainer review; repository CI and maintainer approval remain separate requirements.
