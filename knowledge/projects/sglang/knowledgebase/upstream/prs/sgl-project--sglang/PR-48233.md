# [Fix] [NVIDIA] deterministic: fix MLA backend selection on SM100

[Upstream PR](https://github.com/sgl-project/sglang/pull/48233) · state: open · merged: False

## Original PR description

## Motivation

On SM100/SM103, `_deepseek_family_overrides` declares `attention_backend = "trtllm_mla"` when no attention backend is explicitly passed. Under `--enable-deterministic-inference` (or `--rl-on-policy-target`), that model override executes before `_deterministic_attention_backend` / `handle_deterministic_inference`, which then treats `"trtllm_mla"` as an explicit user choice and aborts startup with `ValueError: Currently only [...] attention backends are supported for deterministic inference, but you explicitly specified 'trtllm_mla'`.

In addition, `_deterministic_is_deepseek_model` (default backend fill) and `handle_deterministic_inference` (validation) maintained two separate, diverged architecture lists that omitted several DeepSeek-family absorbed-MLA architectures (`KimiK25ForConditionalGeneration`, `HYV4`, `LongcatFlash`, `Dots3Note`, and NextN variants), allowing them to fall back to `flashinfer`, whose MLA split-KV schedule varies with the batch.

## Modifications

- Skip the `trtllm_mla` default in `_deepseek_family_overrides` when `--enable-deterministic-inference` or `--rl-on-policy-target` is requested, leaving backend selection to `_deterministic_attention_backend`.
- Consolidate absorbed-MLA architecture detection into `_DETERMINISTIC_ABSORBED_MLA_ARCHS` (`_DEEPSEEK_FAMILY_ARCHS | {"DeepseekV2ForCausalLM", "Glm4MoeLiteForCausalLM"}`) shared by both `_deterministic_attention_backend` and `handle_deterministic_inference`.
- Add hermetic CPU unit tests in `test/registered/unit/test_model_overrides.py`.
