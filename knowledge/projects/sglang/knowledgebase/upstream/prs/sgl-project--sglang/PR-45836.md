# [Perf] eplb: Cache the physical slots of each logical expert

[Upstream PR](https://github.com/sgl-project/sglang/pull/45836) · state: open · merged: False

## Original PR description

Depends on #45363. This branch is stacked on it, so only the last commit is new here; I will rebase onto `main` once #45363 is merged.

## Motivation

Follow-up to #45363, from @alexnails's [review comment](https://github.com/sgl-project/sglang/pull/45363#discussion_r4345591765) there.

`ExpertLocationMetadata.logical_to_all_physical()` compares a whole row of `physical_to_logical_map_cpu` with the expert id on every call, and the MoE weight loaders call it for every routed expert tensor during loading and weight updates. At the DeepSeek-V3 shape, that review measured 3.66 µs per call, about 0.3 s of lookups per full reload on each rank, and suggested building the lists once.

## Modifications

- The routed lookup reads a table: for each layer and logical expert, its physical expert ids on all ranks, in ascending order. Each lookup returns a new list.
- The table is built on the first lookup and rebuilt when the map tensor, its storage pointer, its `_version` or the logical expert count changes, so writes such as `update()` show in the next lookup. `TopKConfig.correction_bias_for_dtype` keys its cached copy the same way. The version is read before the build, and the key and the table are published as one tuple. Copied and unpickled metadata start without a table. The cache check is inline in `logical_to_all_physical()` rather than in a helper, to save a method call on every lookup.
- Inference tensors keep the row comparison, since writes to them may leave `_version` unchanged. This includes a map that turns into one through `.data` or `torch.utils.swap_tensors`.
- Map entries outside the logical-expert range, such as a `-1` in a hand-written `--init-expert-location`, are ignored as before.
- Unchanged: `update()`, the dispatch maps, the draft-layer fallback and the `require_global_experts` branch. For routed lookups within mapped layers, out-of-range and negative expert ids still raise `IndexError`.

The table does not see changes that keep both the storage pointer and `_version`, such as writes through `.data` or NumPy views, `torch.distributed` collectives, writes from another process through shared memory, or `map.data = map.t()`. Among the write paths in the tree that we checked, only `update()` writes the CPU map of a metadata object in use on GPU deployments; `kt_ep_wrapper` passes one row to an external library's `load_weights`, which we assume only reads it.

## Accuracy Tests

No model accuracy benchmark was run.

- `test/registered/unit/eplb/test_expert_location_weight_loading.py` compares lookups and loaded slots after `update()` of some layers, writes that bypass it, a replaced, transposed, swapped or copied map, inference tensors, a write during a lookup, and the bounds: 15 passed. The same tests also pass with the comparison-based lookup that this PR replaces.
- Together with the rest of `test/registered/unit/eplb/`, `test/registered/unit/model_loader/test_presharded_loader.py`, `test/registered/unit/model_loader/test_modelopt_loader.py` and `test/registered/unit/layers/quantization/test_moe_wna16_ep_shard.py`: 130 passed, 2 skipped (both need a GPU), 106 subtests passed.
- Lint with the versions pinned in `.pre-commit-config.yaml`, plus `scripts/lint/check_registered_tests.py`: clean.

## Speed Tests and Profiling

Not measured on GPU or end to end. A routed lookup now checks `is_inference()` and the cache key, then indexes the table, instead of comparing a row of `num_physical_experts` entries. The table is built in one pass over the map after it changes.
