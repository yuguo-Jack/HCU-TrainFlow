# [Fix] Avoid FP8 descales for FA4 BF16 KV decode

[Upstream PR](https://github.com/sgl-project/sglang/pull/39543) · state: closed · merged: False

## Original PR description

## Motivation

With a ModelOpt FP8 checkpoint and an explicit BF16 KV cache, FA4 prefill succeeds but decode passes the checkpoint's KV scales to attention. Current FA4 rejects these arguments with `q_descale/k_descale/v_descale are only supported for FP8 inputs`.

Addresses the explicit BF16 KV configuration reported in #31640. The current FA4 interface supports FP8 descales, so the old proposal to suppress all FA4 decode descales would discard required scaling for FP8 inputs.

## Modifications

Only pass checkpoint descales to FA4 when the resolved KV dtype is FP8. Preserve query conversion and existing FA3, FP8 and MXFP8 policies.

Extend the CPU paged-MHA tests with BF16 aliases, auto, prefill/decode, and FP8 scaling checks. Reuse the dense attention fixture for a GPU regression with non-unit checkpoint scales and a BF16 KV cache, comparing both extend and decode with the reference output.

## Accuracy Tests

Tested on one NVIDIA RTX PRO 5000 72GB Blackwell (SM120), Python 3.12.3, PyTorch 2.11.0+cu129, and the repository-pinned CUTLASS DSL 4.6.2.

- Before the fix: the new GPU regression fails in decode with the FA4 descale assertion; extend passes. CPU regressions fail for both `bf16` and `bfloat16` decode.
- After the fix: `test/registered/unit/layers/test_flashattention_paged_mha.py`: **3 passed, 12 subtests passed**, with CUDA unavailable.
- Entire `test/registered/attention/unittests/dense/test_fa4.py`: **11 passed, 38 subtests passed**, including the new BF16 regression, existing layout cases, CUDA graphs and speculative decoding cases. GPU checks use the fixture's reference implementation and existing `atol=rtol=0.03`.
- All applicable pre-commit hooks pass for the three changed files.

The original B200/Nemotron-120B full-model scenario was not run. This change does not add support for any new FP8 KV configuration.

## Speed Tests and Profiling

Not benchmarked; this is a decode correctness fix with no kernel changes.
