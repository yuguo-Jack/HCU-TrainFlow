# [Fix] anthropic: don't reject adaptive thinking when there is no reasoning parser

[Upstream PR](https://github.com/sgl-project/sglang/pull/48175) · state: open · merged: False

## Original PR description

## Motivation

Claude Code sends `thinking: {"type": "adaptive"}` on every `/v1/messages` request, including with a local model name. On a server started without `--reasoning-parser` (any instruct-only model), SGLang answers each of those requests with:

```
HTTP 400 invalid_request_error: Anthropic thinking is not supported for models without a reasoning parser
```

So Claude Code can't use an instruct model on SGLang at all: with Qwen3-4B-Instruct-2507, 0 of 6 requests got an answer. The same request without `thinking` gets 200.

With `adaptive`, the model decides whether to think, and Anthropic's docs say "Thinking is optional for the model". A model that can't think should answer without a thinking block instead of failing the request.

Reproduce (any model, no `--reasoning-parser`):

```
python -m sglang.launch_server --model-path Qwen/Qwen3-4B-Instruct-2507 --port 30000
curl -s localhost:30000/v1/messages -H 'content-type: application/json' \
  -d '{"model":"m","max_tokens":64,"thinking":{"type":"adaptive"},"messages":[{"role":"user","content":"Say hi."}]}'
```

## Modifications

- `entrypoints/anthropic/serving.py`: `adaptive` still maps to reasoning on, except when the chat server has no reasoning parser; then it maps to off. An explicit `{"type": "enabled"}` keeps its 400, so a client that really asks for thinking still finds out it can't have it.
- `test_serving.py`: the fake chat server gets a `reasoning_parser`, and a new test checks that `adaptive` without one calls `apply_reasoning_enabled(False)`. It fails on main and passes here.

## Accuracy Tests

No change to model outputs. Only requests that used to get a 400 behave differently.

Verified with a real Claude Code 2.1.316 session against Qwen3-4B-Instruct-2507:
- On main e33cd0c3a1: 0 of 6 requests answered.
- With this fix and #45129 (the `display` fix) applied: 4 of 4 answered, and the coding task finished.
