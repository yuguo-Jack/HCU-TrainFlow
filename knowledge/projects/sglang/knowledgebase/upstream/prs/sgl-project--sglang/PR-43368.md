## Original PR description

# [Fix] Mooncake standalone: register MHA K/V at merged allocation granularity

## Motivation

Standalone Mooncake L3 storage (`--hicache-storage-backend mooncake` with `"standalone_storage": true`) crashes at startup on any model whose HiCache anchor is an **MHA-family host pool** — dense MHA models and hybrid GQA/GDN models alike (first observed on Qwen3.8-27B, a GDN hybrid whose GQA full-attention layers form the anchor):

```
E1009 16:37:59 dummy_client.cpp:726] Invalid buffer address or size for registration:
  Buffer addr: 0x7fa4e4200000, need addr: 0x7fa4e4200000,
  buffer size: 5636096000, need size: 11272192000
Failed to register buffer, error code: -1
RuntimeError: Failed to register buffer to Mooncake Store, error code: -1
  (via attach_hybrid_pool_to_unified_cache → build_hybrid_mamba_stack →
   HybridCacheController.__init__ → register_mem_pool_host)
```

Note `need size == 2 × buffer size`: the standalone client's allocation
book contains one merged K+V allocation, but registration asks for half of it.

Root cause: `MHATokenToKVPoolHost` allocates K and V as a single merged
`(2, ...)` tensor (`kv_buffer[0]` = K, `kv_buffer[1]` = V, via properties),
but `register_mem_pool_host()` iterated `get_hybrid_pool_buffer()`, which
returns the **half views**. In non-standalone mode `register_buffer` is a
range registration with the transfer engine, so sub-view registration is
legal and nothing failed. In standalone (dummy-client) mode the host memory
belongs to the external `mooncake_client` process, and `register_buffer`
must match one of its `MooncakeHostMemAllocator` records **exactly** —
a half view of the merged allocation does not. MLA anchors never hit this
(single latent buffer, exact match), which is why the existing Kimi-K3
standalone validation passed while the first MHA-anchor model failed.

## Modifications

- Add `MooncakeStore._register_pool_buffers()`, shared by
  `register_mem_pool_host()` (anchor) and `register_mem_host_pool_v2()`
  (hybrid side pools):
  - if the pool exposes a single merged tensor `kv_buffer`, register that
    allocation once;
  - skip any `get_hybrid_pool_buffer()` entries whose pointers fall inside
    its byte range (the K/V half views);
  - buffers outside the range (Mamba temporal/conv state, DSA index) remain
    separate allocations and keep registering individually.
- Total registered bytes are unchanged (K half + V half == merged buffer),
  so `_standalone_required_bytes` sizing and the non-standalone range
  registration semantics are unaffected.
- Regression test in `test_mooncake_standalone_dummy_mamba.py`: an MHA-shaped
  anchor (merged `(2, ...)` allocation + K/V half-view properties) plus a
  mamba side pool must register exactly `{merged, temporal, conv}` — the
  K half view must **not** appear. Fails on the pre-fix code, passes after.

## Accuracy Tests

Bug is in memory registration, not numerics; no model-output change
(verified: identical total registered bytes). The regression test is the
guard:

```
$ python -m pytest test/registered/unit/mem_cache/test_mooncake_standalone_dummy_mamba.py -v
test_registration_matches_merged_mha_allocation PASSED
test_setup_dummy_includes_hybrid_buffers PASSED
```

Verified red on pre-fix code (`REJECTED: ptr=0x... size=128 need=256`
→ `RuntimeError: Failed to register buffer ... error code: -1`, matching
the reported crash), green on the fix.
