# [Fix] gemma4: Fix Bolt E4B and Gemma4 prefill CUDA graphs

[Upstream PR](https://github.com/sgl-project/sglang/pull/46663) · state: open · merged: False

## Original PR description

## Motivation

Enable Bolt E4B serving with breakable prefill CUDA graphs, including image inputs for `nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-BF16`. The fix also applies to Gemma4. These models share KV caches between layers, but graph setup needs a separate execution ID for each layer.

Breakable prefill graphs are the default for the text-only path used by the separate Bolt E4B Q4_K_M GGUF target PR, which needs this fix for default startup. For multimodal Gemma4/Bolt BF16, prefill graphs remain disabled by default; use `--cuda-graph-backend-prefill breakable` to opt in. This PR leaves those defaults unchanged.

During validation of the newly enabled graph path, three of eight image checks failed for both Bolt E4B BF16 and Gemma4, while eager execution passed. Multimodal embedding preparation changed the token IDs needed for per-layer embedding lookup during graph replay. Preserving those IDs restores the expected image answers.

## Modifications

- Add an optional graph execution ID to `RadixAttention` and use it when indexing layers for prefill graphs.
- Supply each Gemma4 attention layer's execution ID while keeping its KV-cache owner ID unchanged.
- Accept graph-supplied embeddings alongside IDs used for per-layer lookup.
- Preserve image token IDs before multimodal embedding preparation changes them.
- Add graph-indexing and image-input regressions. Multimodal prefill graph defaults stay unchanged.

Existing callers keep using `layer_id` unless they supply a graph ID. This PR applies the separation to Gemma4, including Bolt E4B; other models remain unchanged. Pipeline padding, repeated-layer handling, and duplicate validation are preserved.

## Accuracy Tests

Bolt E4B BF16 and Gemma4 E4B each passed eight image checks plus a text control with breakable prefill graphs on H100 and Blackwell (SM103). Checks covered colors, positions, counting, OCR, and two-image ordering. Before the token-ID fix, three image checks failed.

H100 used Triton, matching its architecture default. Blackwell left attention options unset and selected `trtllm_mha`; eager controls also passed both models' checks. Each breakable run logged ten graphed prefills and zero eager prefills, including warmup. The default TRTLLM backend warns that it uses causal image attention, so these smoke checks do not establish full vision accuracy.

At main base `1d605b7e` plus this PR, all nine focused CPU tests and full pre-commit passed in Docker, including Rust. The image regression was verified red/green, with 64% changed-line coverage. Validated text and image inputs at TP1. Bolt E4B BF16 also passed all nine text/image smoke checks at TP2 on two H100 NVL GPUs, using default Triton attention with eager and breakable prefill. Answers matched; the breakable run recorded ten graphed prefills and no eager fallback, including warmup.

Full prefill remains unsupported for the tested image path. Triton and default TRTLLM fail capture; H100 FA4 falls back to eager for images, and Blackwell FA4 encounters kernel restrictions before image requests. This PR's image graph results use breakable prefill.

**Issue**

Gemma3n shares KV caches the same way, but this PR sets `graph_layer_id` only for Gemma4. In `gemma3n_causal.py` (line 416), each KV-shared layer still passes the owner's index as `layer_id` and passes no `graph_layer_id`. `index_attention_layers_by_global_id` then sees two layers with one ID and raises `invalid or duplicate attention layer_id`.

**Example**

`Gemma3nForCausalLM` is not multimodal, so breakable prefill graphs are on by default on CUDA. Startup would fail at graph setup, the same way Gemma4 text did before this PR.

**Fix**

Pass `graph_layer_id=layer_id` to `RadixAttention` in `Gemma3nAttention`. If Gemma3n is out of scope, say so in the PR description.
