# [Fix] sampling: deterministic top-p / top-k renorm when attn_tp_size > 1 (TP rank divergence in DFlash/DSpark)

[Upstream PR](https://github.com/sgl-project/sglang/pull/38565) · state: open · merged: False

## Original PR description

## Summary

flashinfer's default top-p / top-k renorm kernels are non-deterministic (float `atomicAdd`); because of this, TP ranks that renormalize the same logits can produce different results. Every consumer of this output (plain sampler, spec-verify) samples against a deterministic coin and commits the result to per-rank KV/radix state. A coin that lands in between the cross-rank gap causes divergence across ranks, and NCCL collectives hang.

Previous PRs (#33549, #33289; #33614) work around this issue by broadcasting rank 0's decision. This PR addresses the root cause and avoids an extra collective, by routing the renorm through flashinfer's `is_deterministic=True` variants. This is turned on where it matters:

| configuration                         | renorm kernels  | why                                                            |
| ------------------------------------- | --------------- | -------------------------------------------------------------- |
| single rank                           | fast            | nothing to agree with                                          |
| `attn_tp_size > 1`                    | deterministic   | each rank computes the same result; bit-identical across ranks |
| `--enable-deterministic-inference`    | deterministic   | self-explanatory                                               |
| `SGLANG_RENORM_DETERMINISTIC=1` / `0` | forced on / off | explicit override                                              |

Repro + results are below. With all relevant broadcasts turned off, the fast kernels reproduce the hang on H100 and B200 in every run. The deterministic kernels never diverge, and the end-to-end cost to TPOT is marginal.

## Root cause

- `sgl_kernel.top_p_renorm_prob` and `top_k_renorm_prob` forward to flashinfer.
    - Top-p on rows longer than 2048 uses the AIR radix kernel (>= 0.6.7, flashinfer-ai/flashinfer#2752) whose default histogram is a float atomic.
    - Top-k (`RadixTopKRenormProbMultiCTA`) pools the kept mass with a float atomic.
    - flashinfer-ai/flashinfer#4831 (0.7.x, sglang pins 0.7.2) added a fixed-point `is_deterministic=True` at unchanged latency.
- In non-greedy verification, each rank compares its own `target_probs` (top-p/top-k output) against a shared coin and samples the bonus token from `relu(q - p)`.
    - If ranks differ slightly, the coin might cross the acceptance or bonus thresholds on some ranks and not others; this will cause KV state to drift and a later prefix match will cause NCCL collectives to hang.
- The sampler's `min_p` path calls the same kernels with no broadcast (`SGLANG_SYNC_TOKEN_IDS_ACROSS_TP` is off by default).
- Earlier synthetic repros were clean because they used `top_p=1.0`, which skips the kernel entirely.

## Repro

**Setup**

- Image: current main (nightly `ed8c3139`, flashinfer 0.7.1, sgl_kernel 0.4.10) with this PR applied.
- Model, config, workload: TP=2 DFlash, Llama-3.1-8B + `z-lab/LLaMA3.1-8B-Instruct-DFlash-UltraChat`, `temperature=1.0`, `top_p=0.9`, 32 concurrent multi-turn streams, fp8 KV.
- Broadcast collectives off:
    - Hard-coded broadcast is only on for the EAGLE path. We use DFlash.
    - `SGLANG_SPEC_TP_SYNC=off` turns off #33614's broadcasts.
    - `SYNC_TOKEN_IDS_ACROSS_TP`, `SGLANG_SYNC_TOKEN_IDS_ACROSS_TP` are off by default.
- Deterministic renorm kernels on using a new environment variable, `SGLANG_RENORM_DETERMINISTIC=1`.
- A probe all-gathers per-verify-step fingerprints of `{rng state, prefix_lens, draft_tokens, target_logits, target_probs, accept_len, bonus, commit_lens, out_tokens}` and reports the first field that differs.
    - It also calls `top_p_renorm_prob` twice on the same input on one rank, counting mismatches after.

**Results**

"knob" below refers to the new env-var, `SGLANG_RENORM_DETERMINISTIC=1`.
| broadcast | renorm | runs | requests per run | first cross-rank `target_probs` difference | rank-local mismatches (top-p calls) | outcome |
|---|---|---|---|---|---|---|
| off | fast (knob=0, same kernels as main) | 4 x H100, 2 x B200 | 1.4k to 6.5k | 1 to 22 s | 0.4 to 0.9 % | **all 6 hung**, at 190 to 610 s |
| off | deterministic (knob=1) | 3 x H100, 2 x B200 | 22.6k to 35.4k | never | 0 of 276,000 | all 5 clean, full 30 min |
| all (#33614) | fast (knob=0) | 1 x H100 | 25.2k | 14 s | 0.9 % | clean: 436 `target_probs` divergences, none reaches a token |
| all (#33614) | deterministic (knob=1) | 1 x H100 | 24.4k | never | 0 of 46,000 | clean, 0 divergences |

Every fast-kernel run with the broadcast off hung, with the same recorded chain each time:

- `target_probs` differs between ranks while logits, `prefix_lens` and RNG are identical.
- `bonus` / `out_tokens` differ on one rank.
- Next step's `draft_tokens` differ.
- Hang.

Toggling only the knob to 1 on the same image, model, load and probe consistently results in zero divergences, zero rank-local mismatches, and no hang.

## Kernel measurements

We perform 99 repeated calls on byte-identical input. Settings: flashinfer 0.7.1, vocab 128256, H100. B200 and B300 give the same results.

`nondet` refers to calls that differ from call 0.

| rows | input distribution | kernel | current default        | `is_deterministic=True` |
| ---- | ------------------ | ------ | ---------------------- | ----------------------- |
| 32   | flat               | top-p  | 0.136 ms, nondet 99/99 | 0.169 ms, 0/99          |
| 32   | peaky              | top-p  | 0.127 ms, 0/99         | 0.149 ms, 0/99          |
| 32   | flat               | top-k  | 0.042 ms, 99/99        | 0.042 ms, 0/99          |
| 32   | peaky              | top-k  | 0.042 ms, 77/99        | 0.042 ms, 0/99          |
| 256  | flat               | top-p  | 0.603 ms, 98/99        | 0.815 ms, 0/99          |
| 256  | flat               | top-k  | 0.288 ms, 99/99        | 0.289 ms, 0/99          |

We observe the following:

- Top-k performs near-identical between both fast and deterministic arms.
- Top-p adds 20 to 45% to a 0.1 to 0.8 ms kernel. We measure how much this matters in the next section.
- The deterministic wrapper adds no host sync and no `cudaMalloc`, so there is no overhead.

## End-to-end speed

**Setup**

- Workload: `sglang.bench_serving`, random 512-in / 256-out, 400 prompts, concurrency 32.
- Model, config: Llama-3.1-8B, fp8 KV, triton attention, H100.
- One container boots four servers in sequence with the knob 1 / 0 / 1 / 0, two trials each, so both arms share a host and an image.
- We look at TPOT, since this code change is exercised during decode. The first trial (warmup) is dropped, and we calculate mean TPOT. We see that differences are on the order of 0.01 ms.

| config                                                                           | knob=1   | knob=0   | delta  | accept len    |
| -------------------------------------------------------------------------------- | -------- | -------- | ------ | ------------- |
| plain TP2 `min_p=0.05` (the path the default policy makes deterministic), host A | 4.974 ms | 4.976 ms | -0.0 % |               |
| same, host B, order 0 / 1 / 0 / 1                                                | 5.058 ms | 5.062 ms | -0.1 % |               |
| plain TP1 `min_p=0.05`                                                           | 8.065 ms | 8.067 ms | -0.0 % |               |
| DFlash TP2 `top_p=0.9` (knob=1 forces the verify path deterministic too)         | 3.992 ms | 3.983 ms | +0.2 % | 4.563 / 4.564 |
| EAGLE3 TP2 `top_p=0.9`                                                           | 7.191 ms | 7.175 ms | +0.2 % | 1.929 / 1.930 |

Thus, we see that there is no measureable end-to-end cost, including the forced-deterministic verify path; the accept length is also unchanged.

The renorm kernel runs once per step over `batch_size` rows (sampler) or `batch_size x draft_tokens` rows (verify), so deterministic top-p adds ~0.03 ms at 32 rows and ~0.2 ms at 256 rows, which is small compared to a step of several ms.

## Modifications

- `python/sglang/srt/layers/sampling_renorm.py` (new):
    - `renorm_deterministic(ranks_agree)` policy.
    - `top_p_renorm_prob` / `top_k_renorm_prob` for the sampler and `spec_top_p_renorm_prob` / `spec_top_k_renorm_prob` for verify, calling flashinfer with `is_deterministic=True` when appropriate (`sgl_kernel` as before otherwise).
    - The flag's presence is checked once at import (`inspect.signature`), so an older flashinfer degrades to the fast kernel rather than failing on the first sampled request.
    - Without flashinfer (MUSA, XPU) `sgl_kernel`'s own single-CTA kernel is already deterministic; no int32-sensitive code is added there.
- `layers/sampler.py`, `speculative/dflash_utils.py`, `speculative/eagle_utils.py` are the only renorm call sites, and now they import from the module above.
    - The `_sync_token_ids_across_tp` and `spec_tp_sync.py` comments name the renorm kernels as a known source of nondeterminism and point at the knob.
- `environ.py`: `SGLANG_RENORM_DETERMINISTIC` next to the other determinism knobs.
- `test/registered/kernels/ops/sampling/test_renorm.py`: existing correctness tests run through the new module; regression tests call each deterministic renorm 30 times on a flat 256 x 128256 input and assert bit-identical output (the default kernels fail this 30 of 30); scoped runtime-context fixture.
- `test/registered/unit/sampling/test_renorm_policy.py` (CPU): single rank fast; TP=2 sampler deterministic and verify fast; `--enable-deterministic-inference` forces on; env overrides both ways.

The fix lives in `sglang` rather than the `sgl_kernel` wrappers, because `sglang-kernel` ships as a pinned prebuilt wheel. A wrapper change there is not testable in CI, and is not delivered until the next kernel release.

This fix is Complementary to #33614: the broadcast keeps replicated state safe against any future non-deterministic operator. This removes the one we found, so rank 0's own output and every other consumer of `target_probs` (logprobs, sampling masks) become reproducible too.
