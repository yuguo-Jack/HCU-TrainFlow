# [Fix] request_logger: Skip watermark redaction when disabled

[Upstream PR](https://github.com/sgl-project/sglang/pull/45935) · state: closed · merged: False

## Original PR description

## Motivation

#37577 added watermark-secret redaction to request logging even when `--enable-watermark` is absent. The redactor recursively copies token lists before the formatter applies its field exclusions, so long prompts consume tokenizer-process CPU even at log level 1, where token IDs are not printed.

## Modifications

Gate the text and JSON request-log redaction calls on `get_exec().features.enable_watermark`. When disabled, return the data unchanged without importing or calling the watermark redactor. When enabled, keep the existing redaction behavior.

Document that request-log watermark redaction follows the server flag. This applies to native Receive/Finish logs and raw OpenAI request logs, including client-supplied watermark fields.

Related: #44692 optimizes redaction when it runs; this change skips it when watermarking is disabled.

## Accuracy Tests

Logging-only change; no inference accuracy run needed.

`PYTHONPATH=python python test/registered/unit/utils/test_request_logger.py`: **2 tests passed**. The tests cover text and JSON logs, default-disabled logging with token lists that fail if traversed, and enabled/disabled redaction for native and raw OpenAI request logs. Both tests fail on the pre-fix main (`b588aa39e9`); the enabled-redaction cases already pass there.

Changed-file pre-commit checks passed.
