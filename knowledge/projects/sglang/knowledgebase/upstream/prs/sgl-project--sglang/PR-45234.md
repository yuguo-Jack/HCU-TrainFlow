# [Perf] dspark: Make the prefill SWA valid-from update sync-free

[Upstream PR](https://github.com/sgl-project/sglang/pull/45234) · state: closed · merged: True

## Original PR description

- After a target prefill with encoder SWA replay, `DSparkWorkerV2._forward_prefill` marks each newly placed request's draft SWA ring valid from its cached prefix. It built the slots by indexing a CUDA tensor with a Python list and the prefix lengths with `torch.tensor(..., device=...)`. Both are pageable host-to-device copies that block the host. They run after the target forward is enqueued, so each prefill step stalled the scheduler until the whole target forward finished.
- Both copies now go through `async_h2d` (pinned, non-blocking), and the slots come from an `index_select` on the device. No behavior change: same slots, same values.
- Verification: DeepSeek-V4.1-Flash on GB300, DP2 attention + MegaMoE (EP2), DSpark, encoder and decoder replay on, a multi-turn agentic prefill trace at concurrency 512, 900 s per run, same-node pairs.
  - Before: py-spy put 50% of the scheduler main thread's samples on the list index line.
  - After: that line is gone from the profile. The step interval went from ~375 to ~312 ms, and throughput rose from 1,459,199 to 1,581,184 tok/s/GPU (+8.4%) on one node and from 1,453,741 to 1,598,164 (+9.9%) on another, with no errors.
