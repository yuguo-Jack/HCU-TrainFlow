# [Fix] stop: Store the matched regex span, not the pattern

[Upstream PR](https://github.com/sgl-project/sglang/pull/47496) · state: open · merged: False

## Original PR description

## Motivation

A non-literal `stop_regex` stops at the right token, but the finish reason stored the pattern. The detokenizer trims with a literal `find`, so the matched text stayed in the output and `no_stop_trim` could not keep or drop it. Fixes #47461.

## Modifications

`FINISHED_MATCHED_REGEX` now stores the matched span (`matched.group(0)`), including the end-anchored path that locates the stop on a prefix of the output.

No model-output change beyond stop trimming. Not applicable.
