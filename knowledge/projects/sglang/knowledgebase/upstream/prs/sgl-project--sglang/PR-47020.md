# [Fix] dflash: Apply request penalties under DFLASH and DSPARK

[Upstream PR](https://github.com/sgl-project/sglang/pull/47020) · state: open · merged: False

## Original PR description

## Motivation

Fixes #46752. With `--speculative-algorithm DFLASH` or `DSPARK`, `repetition_penalty`, `frequency_penalty`, `presence_penalty` and `min_tokens` have no effect. Two causes:

1. `spec_prepare_for_decode` never cumulates penalty output tokens for the DFLASH family (only `eagle_prepare_for_decode` does), so penalizer state stays at identity.
2. DFLASH verify and its fast-path checks read `acc_linear_penalties`, which `SamplingBatchInfo` doesn't have, instead of the `acc_additive_penalties` / `acc_scaling_penalties` that `copy_for_forward()` produces. The dense fallback also scaled a zero buffer, which drops `repetition_penalty`.

## Modifications

- `spec_prepare_for_decode`: cumulate in the `is_dflash_family()` branch, as EAGLE does. It stays per branch so EAGLE doesn't count twice.
- `apply_dflash_verify_logits_adjustments`: apply `acc_additive_penalties` and `acc_scaling_penalties` broadcast over the verify block, as EAGLE verify does. The scheduler always hands workers a `copy_for_forward()` copy, so these buffers are the only way penalties arrive. The grammar fallback now applies only the vocab mask.
- `_can_skip_verify_logits` and `verify_logits_adjustments_are_noop` now see the accumulated buffers, so penalized batches take the eager verify path. This also covers the DSPARK block-accept estimator gate from the issue, which uses the same check.
- `test_dspark_sampling_accept_graph.py`: its fake `sampling_info` had the nonexistent `acc_linear_penalties` field; it now has the two real ones.

Penalties keep EAGLE's relaxed spec-decoding semantics (see Not covered). Requests without penalties are unaffected.

\* MiniCPM5-2B also ignores these on this prompt without speculative decoding. On an open-ended prompt, both change DSPARK output.

To reproduce, start the DFLASH server (docs flags at TP1, plus two flags to fit the L4):

```bash
python3 -m sglang.launch_server --model-path Qwen/Qwen3-4B --speculative-algorithm DFLASH --speculative-draft-model-path z-lab/Qwen3-4B-DFlash-b16 --attention-backend flashinfer --speculative-draft-attention-backend flashinfer --cuda-graph-backend-prefill disabled --cuda-graph-max-bs-decode 4 --mem-fraction-static 0.8
```

Then send the request with and without the penalty and compare the text:

```bash
curl -s localhost:30000/generate -d '{"text": "Repeat the sentence '\''The weather is very nice today.'\'' five times, one per line:\n", "sampling_params": {"temperature": 0, "max_new_tokens": 96, "repetition_penalty": 2.0}}'
```

For DSPARK, use the cookbook command: `--model-path openbmb/MiniCPM5-2B --trust-remote-code --speculative-algorithm DSPARK --speculative-draft-model-path openbmb/MiniCPM5-2B-DSpark --speculative-dspark-block-size 7`, with the same two extra flags.

## Not covered

- No accuracy or throughput runs.
- Not run on Hopper/Blackwell or multi-GPU. Grammar-constrained requests are covered by a unit test only.
- `min_tokens` has no end-to-end check.
- As in EAGLE, one token per request is cumulated per verify step. With multi-token accepts, penalties don't see tokens accepted mid-block, and `min_tokens` counts verify steps, so EOS stays masked for about `min_tokens` times the accept length. Changing that would affect EAGLE too.
