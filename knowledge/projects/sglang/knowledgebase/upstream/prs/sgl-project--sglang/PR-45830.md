# [Fix] ci: Add executable entry point to Muse Spark router test

[Upstream PR](https://github.com/sgl-project/sglang/pull/45830) · state: closed · merged: True

## Original PR description

## Motivation

CI registry discovery scans the registered test tree before selecting a suite. The Muse Spark router GEMV test registers CUDA suites but lacks an executable entry point, so `collect_tests` raises `ValueError` and prevents unrelated CPU and diffusion suites from starting. This is visible in [the CPU job](https://github.com/sgl-project/sglang/actions/runs/39785372882/job/119847619088) and [the diffusion job](https://github.com/sgl-project/sglang/actions/runs/39785372882/job/119847509275).

## Modifications

Add the standard `sys.exit(pytest.main([__file__, "-v"]))` entry point. Preserve the existing tests, kernel calls, and both CUDA CI registrations.

## Accuracy Tests

No model or kernel computation changes. The existing router precision tests remain the accuracy coverage.

## Speed Tests and Profiling

No inference performance changes; this fixes test discovery and execution.
