# [Fix] diffusion/http: Allow bounded graceful shutdown

[Upstream PR](https://github.com/sgl-project/sglang/pull/46169) · state: closed · merged: True

## Original PR description

## Summary

A client that never finishes sending a request body can keep the HTTP server waiting after SIGTERM. `--scheduler-rpc-timeout` cannot help: this request has not reached the scheduler.

Add `--http-graceful-shutdown-timeout`, forwarded to Uvicorn's existing graceful shutdown timeout. Unset preserves the current unlimited wait; zero cancels outstanding HTTP tasks without waiting. Invalid config values fail validation. No inference, kernel, or worker scheduling changes.

Document that this bounds HTTP draining only, not application cleanup/GPU teardown or asynchronous video job completion. Deployments still need a termination grace period and their own durability/retry policy.

## Validation

- New CLI/config/launcher regression tests fail against unmodified main and pass with the fix.
- H200, Wan2.1-T2V-1.3B, real HTTP, 512x320, 17 frames, 4 steps: generated and decoded a video before holding a multipart upload open and sending SIGTERM. With timeouts 0 and 2, shutdown took 0.36s and 2.42s without closing the client connection. No workers survived.
- With the default unset, the server was still waiting after 3s; closing the client let it exit. Decoded frame hashes matched across all three configurations.
- The full server-args/shutdown/load-time suite initially reported 246 passed plus one existing H200-sensitive LTX fixture failure. That same failure reproduces on unmodified main: the fixture mocks memory capacity but reads the real GPU name. No thresholds or test expectations changed here.
- On the exact committed head, excluding only that reproduced pre-existing failure: 246 passed, 121 subtests passed, 1 deselected. The cold-import subprocess test requires access to public model metadata when its cache is empty.
- Pre-commit passed.
