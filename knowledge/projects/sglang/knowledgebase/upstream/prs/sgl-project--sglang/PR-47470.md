# [Fix] observability: Assign correct dp_rank under attention-dp for KV metrics and Prometheus

[Upstream PR](https://github.com/sgl-project/sglang/pull/47470) · state: open · merged: False

## Original PR description

fixes #47409

### what changed
under attention-dp (`attn_dp_size > 1`), `dp_rank` is `None`:
1. `SchedulerKvEventsPublisher` hardcoded `dp_rank or 0` for `kv_metrics.data_parallel_rank`, publishing rank 0 across all attention-dp shards and breaking downstream kv-aware router load balancing (e.g. dynamo).
2. prometheus scheduler series omitted `dp_rank` entirely when `dp_rank is None`, making it impossible to join with radix cache metrics (which use `parallel.attn_dp_rank`).

- use `select_kv_publisher_dp_rank` for `kv_metrics.data_parallel_rank` in `kv_events_publisher.py`
- populate `labels["dp_rank"] = parallel.attn_dp_rank` when `attn_dp_size > 1` in `metrics_collector.py`
- added unit tests for `select_kv_publisher_dp_rank` / `emit_kv_metrics` and scheduler metrics labels under attention-dp
