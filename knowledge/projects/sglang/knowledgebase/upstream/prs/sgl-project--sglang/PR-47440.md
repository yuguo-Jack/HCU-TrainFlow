# [DSV4] Fix CUDA Cluster top-k tie overflow exactness

[Upstream PR](https://github.com/sgl-project/sglang/pull/47440) · state: open · merged: False

## Original PR description

## Problem

The DSV4 CUDA Cluster top-k path still caps each rank's threshold-bin candidate count at 2048 before aggregating it on rank 0. When the actual bin is larger, the kernel silently selects from an arrival-order subset and can miss true top-k scores. PR #37941 made the Register and Streaming paths exact, but left the Cluster path unchanged. Related: #35257.

## Change

- Preserve uncapped threshold-bin counts across Cluster ranks while keeping writes to the fixed tie buffer bounded.
- If the aggregate overflows the buffer, rerun the full row on rank 0 through the existing exact Streaming path. Cluster barriers keep peer shared memory valid until the retry finishes.
- Exercise both the small-batch and persistent Cluster launch shapes with concentrated fp32 scores and compare the selected score multiset against `torch.topk`.

## Validation

- `git diff --check` and Python syntax compilation passed.
- An earlier H20 test of this Cluster fallback combined with #37941 removed strict top-k misses on long rows. This draft is rebased onto current main; GPU CI for this exact branch is still pending.
- No CUDA device is available in the local development environment, so the added GPU tests have not been run here.
