# [Router] Report the tier held and block-0 presence from a prefix lookup (1/3)

[Upstream PR](https://github.com/sgl-project/sglang/pull/39325) · state: closed · merged: False

## Original PR description

## Motivation

> **1 of 3** in the cache-locality stack. The KV storage-tier stack
> (**#39108** → **#39111**) has merged, so this now sits directly on `main`.
> Nothing consumes this PR's output; **#2** adds the `/metrics` families that
> do, and **#3** the panels.

The router cannot currently explain a cache-aware routing decision after the
fact. The KV tree says how much of a queried chain each worker holds, but not
**on which tier** that worker holds it, and — when the walk matches nobody —
not whether the fleet ever published the first block at all. Those are the two
facts that separate the failures a low hit rate lumps together: a hit served
in place from one that cost a load-back, and a block carried but unreachable
from one the tree does not hold at all.

Both fall out of the descent the prefix provider already makes. This PR makes
the tree and the provider produce them, and stops there — **routing and
selection are unchanged, and nothing reads the new fields yet.**

## Modifications

**`HashTree::prefix_depths` returns `PrefixDepth { blocks, tiers }`** instead
of a bare depth. The tiers are read at each worker's OWN frozen depth — the
deepest node that worker itself reached — not at the chain's deepest node,
which a shallower holder never occupies. Reading there would attribute the
deep holder's tier to every shallow one, which is exactly the difference
between "served in place" and "cost a load-back".

**The walk keeps its old cost.** Each live worker carries the tiers it held at
the last level it survived, so freezing one is a move of a value already in
hand. Going back to `child.workers` per level to build the entry instead would
cost three `KvWorkerId` hashes per (level × live worker) where the old loop
cost one — on the synchronous routing path, under a read lock, for a field
only observability reads.

**`HashTree::contains_hash`** answers a question a failed walk cannot.
`prefix_depths` is root-anchored, so a block published as a continuation of a
chain the router never saw is present in the tree and unreachable from it — a
specific fault a zero match alone cannot see. The absent answer is **not** its
complement and does not implicate the engines: events fire on insertion, so a
resident block is never re-published, and the root of a hot shared prefix is
both the most likely to be held and the least likely to be announced. A tree
that starts after the fleet is warm accumulates suffix blocks indefinitely and
still fails every walk at the first step, with no amount of traffic resolving
it. The docs on `contains_hash` carry all three causes of an absent answer and
say to read it against the tree's coverage of the engines' reported occupancy,
so a cold tree is not mistaken for an engine fault. It counts a node only
while some worker holds it — a node that lost its last worker survives as an
ancestor of a still-held child, and its key must not read as "carried". The
tree is sharded and a continuation lands in its parent chain's shard, so it
asks every shard, one read lock at a time. That is a second read of the tree,
so the provider takes it **only when the walk matched nobody** — on a hit
there is nothing to attribute, and a healthy fleet never pays for it.

**`ExternalPrefixSignal` gains a `tree_view` side-channel** carrying both, so a
decision site never has to go back to the tree for a prefix the provider has
already walked — a second lookup there would read a different tree. It is
`None` on the out-of-process indexer path, whose wire contract carries neither
fact, so a consumer can tell "not observable on this deployment" from a real
answer instead of being handed a fabricated one.

Two provider changes come with it:

- **A URL appearing under several dp ranks collapses on depth first**, with the
  tier breaking a tie. The deepest rank is the one routing gets, so its tier is
  the tier that hit will be served from; taking the best depth and the best
  tier independently would report an in-place hit for a prefix that is actually
  loaded back.
- **A walk that reached nobody returns `Some(PrefixOutcome::Empty)`** where it
  returned `None`. `None` means no lookup happened; a tree miss is an answer,
  and keeping them apart is what lets a consumer separate a cold fleet from a
  router that never looked.

## Behaviour

Unchanged. The `None` → `Some(Empty)` return is the only externally visible
difference, and both consumers —
`CacheAwarePolicy::cache_candidate_proposal` and the reorg policy's
`candidates` — already return nothing on a non-`Matched` outcome, so
selection is unchanged. `rank_depths` (`--dp-aware`) reads `.blocks`. `PrefixCachePolicy` keeps scoring on `blocks` alone, and
selection still treats any tier as ownership.

The doc comments name the counters that will consume the tiers and the presence
flag; those land in **#2** of this stack.

## Tests

Added to the tree's unit tests and the provider's component tests:

- per-worker tiers at each worker's own depth, with a shallow holder on a
  different tier from the deep one;
- `best_tier_label` ranking device over host, and falling back to host once the
  device copy is evicted;
- `contains_hash` seeing a block the root walk cannot reach, losing it when
  the last carrier goes, and ignoring a node that survives only as an ancestor
  of a still-held child;
- the dp-rank collapse in both orders (deeper-but-dearer rank wins on depth;
  equal depth breaks on tier);
- a tree miss carrying `block0_in_tree` both ways — not held at all vs.
  carried-but-unreachable;
- no established block size still meaning no signal at all.

Rebased onto `main` @ `89f21671bb` across upstream's tree sharding and the
`state/` move, so this is no longer patch-identical to the reviewed commit:
`contains_hash` fans out over shards and ignores worker-less nodes, and the
new `ExternalPrefixSignal` construction sites and `prefix_depths` callers are
adapted. On the top of the stack: `cargo test` all green — lib 1048, main 8, component 132, proxy 176 passed, 0 failed; `cargo clippy --all-targets -- -D warnings` clean; `cargo fmt` clean.
