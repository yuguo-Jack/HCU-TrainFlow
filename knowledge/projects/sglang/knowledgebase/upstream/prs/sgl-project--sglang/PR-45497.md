# [Perf] attention: avoid concatenating MLA queries for zigzag CP

[Upstream PR](https://github.com/sgl-project/sglang/pull/45497) · state: open · merged: False

## Original PR description

## Motivation

MLA prefill with zigzag context parallelism concatenates `q_nope` and `q_rope` along the feature dimension, slices the resulting tensor along the token dimension, then separates the query components again in the attention callback. FlashAttention already accepts the two components separately, so the concatenation introduces an avoidable allocation and copy in each attention layer.

Pass the components directly and slice each one on the same token boundaries. On DeepSeek-V2-Lite with four H200 GPUs, this removes 27 query-copy kernels per rank from a 64K prefill trace.

## Modifications

- Pass `(q_nope, q_rope)` directly from the MLA CP path to the attention callback.
- Allow zigzag attention dispatch to slice either a single query tensor or a tuple of query components. Preserve the input convention for callbacks, logical token boundaries, and physical output padding.
- Add a unit test covering component alignment, shared storage, noncontiguous input, and padded output.

The change targets the absorbed-MLA zigzag prefill CP path. The attention computation, KV-cache handling, and communication are unchanged. Performance and GPU correctness were validated with FA3; FA4 was not tested.

## Accuracy Tests

- CP unit suite: **25/25 passed**, including the new component-slicing test. Repeated successfully after preparing the local branch.
- FA3 layout checks: **16/16 cases bitwise equal** between concatenate/split inputs and separate components, covering contiguous, broadcast-RoPE, head-major Q, and projection-RoPE layouts. Representative CP rank-0 halves at 32K, 64K, and 128K also produced bitwise-equal outputs.
- Full-model ragged batches `[17, 65, 513]` and `[2049, 4099]`, eight output tokens: identical generated text, token IDs, and output logprobs; maximum absolute logprob difference **0**.
- Independent long-context serving A/B below: **480/480 requests succeeded**, expected input/output token counts verified, and **240/240 paired generated texts matched**.

## Speed Tests and Profiling

Baseline: `ed0b8f433f887995b1ce361b15aaf9f6ca93483f`. Patch: [`0f9fb29`](https://github.com/wjinxu/sglang/commit/0f9fb294f2d5d0bb1828d5ad36e6abd7a7d943e6).

**Setup:** DeepSeek-V2-Lite BF16, 4×H200, TP4/zigzag PCP4, EP4/DeepEP BF16, DeepGEMM, FA3. Prefix caching disabled, maximum request concurrency 1, temperature 0, fixed input token IDs, and `ignore_eos=True` for exact output lengths. Measurements use the official **vLLM serving benchmark client** against the SGLang OpenAI completion endpoint.

**Method:** four isolated service starts in baseline / patched / patched / baseline order. Each start measures 30 requests per case after two benchmark warmups and the client readiness request. Inputs: 65,536 and 131,072 tokens; outputs: 1 and 128 tokens. Each row compares request-latency medians from one baseline start and one patched start. Both restart pairs are shown; no samples were excluded. Positive reductions mean lower latency.
