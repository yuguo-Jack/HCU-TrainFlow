# [Fix] diffusion: select Blackwell subtile attention by execution mode and quality

[Upstream PR](https://github.com/sgl-project/sglang/pull/47301) · state: closed · merged: True

## Original PR description

## Motivation

Keep the captured-kernel improvement from #46107 without imposing FA4's host dispatch cost on eager diffusion requests.

The original B300 E2E evidence used CFG parallel **with BCG**. In LTX-2.3 TI2V eager, routing a short audio side to FA4 reduces GPU work but increases request latency. This is a mode-dependent regression, not evidence that the FA4 kernel should be removed.

## Changes

- Use cuDNN for Blackwell sub-tile attention in eager `lossless`/`high` execution, including eager breaks during BCG replay.
- Keep FA4 within BCG warmup/capture so the measured captured-path benefit remains and the kernel is compiled before capture.
- Preserve the existing FA4 route for `exact` requests and contexts without explicit request quality. The two backends have different floating-point rounding, so this optimization must not silently change the reference route.
- Carry the existing request quality explicitly through forward context in standard denoising and LTX's model-owned context. Do not attach a request object to LTX just to read quality, which would also enable unrelated request-aware LoRA paths.
- Leave the existing long-self-attention SM103 heuristic, other architectures, masks, and failure fallback unchanged.
- Cover both short-query and short-key directions, real CUDA graph capture, changed inputs on replay, and return to cuDNN in eager. The GPU test is registered in the B200 kernel suite; CPU routing tests remain in the diffusion unit suite.

No new public flags or kernel arithmetic changes. Production changes: four existing files, +26/-6; no new production files. Tests/docs: +130/-5.

## Evidence

Same two B300s, checkpoint/cache/dependencies/inputs/placement/quality/timing method. Public `Lightricks/LTX-2.3`, 768x512x121, seed 42, official two-stage schedule, CFG2, TP/SP1, `quality=lossless`, compile disabled, explicit `original` stage-switch mode, DiT resident and auxiliary components layerwise offloaded. No profiler requests are included in latency medians.

- On top of #47270's original launch-cache head `61bb5547b67db0aebbcba15017e5e6921a56e9c6`, independently restoring cuDNN for the affected shapes (`5be34c8ddc10361d6f459aae7444271f40cac30d`) reduces TI2V stage 1 from 10.95-11.01 s to 9.60 s. This isolates the attention dispatch change from the separate AdaLN/layout and stage-2 changes.
- Matched diagnostic traces: original-good vs the launch-cache-only head has GPU active time 371.21 -> 341.92 ms but GPU span 2142.97 -> 2556.79 ms. The added 576 FA4 calls consume 313.91 ms host-inclusive. Profiling overhead is substantial; these numbers explain the mechanism, not the E2E speedup.
- With the layout and stage-2 fixes from #47270, a final 9-request good/fixed/good comparison records TI2V stage 1 at 9.262 / 9.039 / 9.382 s and stage 2 at 0.767 / 0.749 / 0.767 s. The recovery comes from the combined fixes, not this attention patch alone. The original good is `02b983603d34c6af09e554ed2b8bf8d85290d9ae`; the measured combined candidate is `7ad0ae895ae701894dd68fc906362a51ff9a6c54`.
- Final combined head `02dc569408cd24bd6fee91086c93829cd076b1ef` includes model head `698a5afb05c3e9f0738df4a59b66acc5847d4360` and attention head `115643e05b80622fc0a887dc8a8dbec570cde35e`. Nine TI2V eager requests give stage 1 / stage 2 / client E2E = **9.161 / 0.753 / 11.251 s**. Five matching-image TI2V BCG requests give **3.374 / 0.487 / 5.073 s**; five T2V BCG requests give **2.742 / 0.467 / 4.469 s**, retaining the preceding graph-mode benefit.

## Validation

- Pre-commit passed, including registered-test validation.
- Final standalone attention head `115643e05b80622fc0a887dc8a8dbec570cde35e` passed registered B300 GPU routing via the CI-style `python <file> -f` entry point, unit routing and unit selection. This includes exact FA4 preservation and both short-side directions.
- Final combined head `02dc569408cd24bd6fee91086c93829cd076b1ef` passed the complete focused suite, including real CFG/SP folding and graph routing. Additional shared-context/CFG/LoRA/cache/model unit coverage: 69 passed, 4 subtests. All three final performance runs above completed successfully.
- Fresh-input FA4/cuDNN tensors pass the BF16 operator tolerance. Full B300 videos are not bit-exact after changing attention backend and stage-2 reduction topology; combined results against the initial #47270 head have PSNR 25.63-31.31 dB. This measurement alone is not a model-quality pass or an official-reference comparison.
- A full-server `exact` check caught a real precision-contract problem in the ungated candidate: pinned official TI2V CLIP 0.520 < 0.55, versus 0.575 on the preceding head. The model-only patch matched the preceding video pixel-for-pixel; attention-only reproduced the difference. The quality guard fixes this by preserving the reference route.
- Final guarded `exact` TI2V: all 25 video frames and decoded audio samples match the preceding head bit-for-bit. Video SHA256: `2743239da33f0fdbd15c140fa33df165a52cb3c50f5b38b193ea39bae5c21482`. Direct comparison to existing official images at pinned ci-data revision `c7258eb56e9951878c66fc0fb3673d9f4775b0b2` passes original thresholds: CLIP 0.5749, SSIM 0.3431, PSNR 12.0377, max MAD 43.2833.
- Standard-server limitation: B300's `perf_baselines/b200.json` has no LTX baseline, so that test fails before consistency validation. The pinned official TI2V images also lack a `case_map.json` entry; the comparison above explicitly loads the existing pinned images with existing metrics and thresholds. This does not turn the standard server suite into a pass.
- No GT or performance baseline changes. This is not a claim of bitwise equivalence between cuDNN and FA4.
