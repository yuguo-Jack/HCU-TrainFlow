# fix: unblock the DSA prefill split-op graph surface on HIP (is_cuda gate)

[Upstream PR](https://github.com/sgl-project/sglang/pull/35279) · state: open · merged: False

## Original PR description

## Motivation

`--cuda-graph-backend-prefill` breakable / `tc_piecewise` for DSA was historically CUDA-only on ROCm. Since #30575 landed, `main` already contains most of the HIP enablement in this area (`dsa_prefill_cuda_graph.py` / `dsa_indexer.py` now gate on `if _is_cuda or _is_hip:` and carry the head-gate graph ops with fake impls) — **this PR is now the missing 3 lines that finish that enablement**.

The remaining gap: `is_graph_dsa_split_op_surface()` in `dsa/utils.py` still short-circuits on `is_cuda()`, which is `False` under HIP (`torch.version.cuda is None`). Both runtime call sites — `dsa_indexer.py:2000` (indexer graph dispatch) and `deepseek_common/.../forward_mla.py:165/256` (head-gate fusion surface) — are unreachable on ROCm even though the ops they dispatch to are already compiled in and functional on gfx950.

## Modifications

**`dsa/utils.py` — 3 lines (net +1):**
- `is_graph_dsa_split_op_surface()`: drop the `is_cuda()` conjunct so the split-op dispatch surface is reachable on HIP.
- The fake-impl'd graph ops (`scale_head_gate_graph`, `logits_head_gate_graph`) and their `if _is_cuda or _is_hip` registration are already in `main` — no changes needed there.

Everything else from the original PR description (head-gate graph ops, fake impls, HIP import gating) was upstreamed via #30575 and is **not** part of this diff anymore.

## Validation

Original enablement was validated on 4× MI355X (gfx950) with GLM-5.2-MXFP4 before the upstream refactor; the rebase drops the 60 lines of duplicated code, so what remains needs re-validation only for the gate itself:

- [x] rebased onto `main` (2026-09-30), net diff = 3 lines, `py_compile` + repo pre-commit (isort/ruff/black) all pass
- [ ] gfx950 smoke: `--cuda-graph-backend-prefill breakable` + DSA model reaches `is_graph_dsa_split_op_surface() == True` path (the original AssertionError/AttributeError at the first capture shape is the regression signal)

## Test plan

- [ ] one gfx950 end-to-end capture run with breakable prefill graph enabled (no assertion, throughput ≈ baseline ± the original +5.5% at C128 / +11.9% at C8 envelope)
