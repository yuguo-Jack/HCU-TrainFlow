# [CI] [AMD] test: Run UMBP HiCache E2E through standalone DRAM server

[Upstream PR](https://github.com/sgl-project/sglang/pull/40674) · state: closed · merged: True

## Original PR description

## Motivation

The UMBP HiCache E2E started failing after the MORI v1.2.3 upgrade. With no master or standalone address, each TP worker now creates its own embedded client. TP0 writes data that TP1-7 cannot see, so the rank-consensus storage hit is zero.

## Modifications

- Start one explicit `umbp_standalone_server` configured as a masterless 1 GiB DRAM backend with 2 MiB UMBP pages and SSD disabled.
- Connect all TP workers to the same unique Unix-domain socket with client auto-start disabled.
- Mask inherited master/node/backend settings so the CI runner cannot select a different UMBP deployment.
- Stop SGLang clients before the standalone server, then remove the isolated socket/log directory.
- Require the full page-aligned 768-token prefix to load from `UMBPStore`.

The request sequence and device/host cache flushes are unchanged. `/flush_cache` does not clear the out-of-process UMBP DRAM backend, so the second request must restore its side-pool KV from storage.
