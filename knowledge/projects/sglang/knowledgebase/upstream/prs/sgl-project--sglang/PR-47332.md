# [Fix] server_args: Reject non-positive prefill request limits

[Upstream PR](https://github.com/sgl-project/sglang/pull/47332) · state: open · merged: False

## Original PR description

## Motivation

A server started with --prefill-max-requests 0 finishes startup, then never serves its first request, so generate() hangs. The scheduler stops adding requests to a batch once it holds the limit, and an empty batch already holds 0, so nothing is admitted. Negative values behave the same way, and main accepts both. Fixes https://github.com/sgl-project/sglang/issues/23788, which recorded the hang on a live GPU server. @rahul-k-r confirmed that main still has the bug in https://github.com/sgl-project/sglang/pull/23826#issuecomment-6506409265.

## Modifications

The server now refuses to start when the limit is 0 or negative, and the message says the limit must be positive. Unset and positive limits behave as before.

## Accuracy Tests

Not applicable. This validates a configuration value and does not touch model outputs.

## Speed Tests and Profiling

Not applicable. Valid configurations run the same scheduler path.

## Testing Done

CPU only, macOS. The script resolves ServerArgs, the step every launch runs before model setup. The first run is on current main and the second on this branch. The GPU hang itself is recorded in the linked issue and was not rerun here.
