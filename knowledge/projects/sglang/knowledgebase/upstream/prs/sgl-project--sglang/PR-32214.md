## Motivation

<!-- Describe the purpose and goals of this pull request. -->
DeepSeek-V4's `unified_kv` backend on ROCm packs three KV families in one pool: the content-addressed compressed KV (C4/C128), the per-request **SWA ring** (addressed by `req_pool_idx * window + pos % window`), and the compressor's **c4 / indexer overlap state**. Only the compressed KV is content-stable; the SWA ring and the c4/indexer overlap state are not, and are never written into the radix tree.

Two prior PRs made reuse of such prefixes *safe* but only **approximately correct**:

- **#29417** enabled unified_kv HiCache, but it offloads **only** the compressed KV (C4/C128). The SWA ring is not preserved, so on a hierarchical hit the trailing sliding window is **re-prefilled** (`swa_reprefill_tail_tokens()`) rather than restored.
- **#30339** applied the same **re-prefill** idea to the radix-only path: cap the match by the trailing window and recompute it into the request's own ring, so decode never reads a stale ring.

Re-prefill recomputes the trailing window (and, implicitly, the c4/indexer overlap state for that region) instead of reproducing the exact values the original prefill wrote. That is enough to prevent gross stale-ring errors and to keep GSM8K-level accuracy within noise — but it is **not bit-exact**: a partial re-prefill cannot reconstruct the original SWA window and c4/indexer overlap state byte-for-byte, so the reused output can differ from a full fresh compute at the bit level.

This PR closes that gap. Instead of re-prefilling an approximation, it **captures and offloads the true values** of the SWA window and the c4/indexer overlap state across L1→L2→L3, and **restores them exactly** on a hierarchical hit — making unified_kv SWA prefix reuse **strict and bit-exact**. A hard reuse gate re-prefills only when the truth is unavailable (never a stale/approximate read).

This is an **opt-in** gated by `SGLANG_UNIFIED_KV_BIT_EXACT_HICACHE` (default **off**), and it engages only when **all** of the following hold at once:
- running **DeepSeek-V4** on **ROCm/HIP**;
- the **`unified_kv_triton`** attention backend is chosen (`SGLANG_HACK_FLASHMLA_BACKEND=unified_kv_triton`);
- **HiCache is enabled** (`--enable-hierarchical-cache`).

In every other case, the feature is a strict no-op, no pool is allocated, no capture, no restore; behavior is byte-identical to `main`.

## Modifications

History was squashed into four reviewable commits (same tree as the 2026-09-21 validation tip). Each layer is still gated by `SGLANG_UNIFIED_KV_BIT_EXACT_HICACHE` and is a no-op when the flag is off.

**1. Flag + host pools** (`feat(swa-hicache): add the strict bit-exact flag and SWA/c4 host pools`)

- `SGLANG_UNIFIED_KV_BIT_EXACT_HICACHE` and `--hicache-swa-offload-page-stride` (`environ.py`, `arg_groups/fields/memory.py`).
- Dedicated pinned-host SWA-window pool with a capture-done handshake (`memory_pool_host.py`).
- Independent L3 pools for c4 and indexer overlap state, sized from prefix windows rather than cache capacity (`deepseek_v4_memory_pool.py`, `hybrid_cache/hybrid_pool_assembler.py`). Staging slack is `ceil(ISL/(page*stride))+1` at per-rank batch 1, `ISL = min(200k, context_length)`, overridable by `SGLANG_SWA_HICACHE_STATE_STAGING_PAGES`.
- Version-namespaced L3 keys (`hicache_storage.py`, `storage/nixl/hicache_nixl.py`).
- Startup fail-fast: with the flag on, raise unless `--hicache-write-policy write_through`.

**2. Capture** (`feat(swa-hicache): capture SWA windows and c4 state at page boundaries`)

- Snapshot the SWA ring at each completed prefill/decode page, EAGLE-safe geometry (`deepseek_v4_backend_hip_radix.py`, `model_runner.py`, `deepseek_v4.py`).
- Snapshot c4/indexer overlap state for the same window into the independent state pools (`compress_hip.py`, `compressor_v2.py`). Capture/restore address state by request slot (`translate_from_req_position_to_state_loc`), matching the per-request compressor path from #38192.

**3. Restore + strict reuse gate** (`feat(swa-hicache): restore captured windows on reuse with a strict gate`)

- Ride the captured window + state back to device at the correct `buf_lo` on a hierarchical hit (`unified_cache/components/swa.py`, `unified_radix_cache.py`, `schedule_batch.py`).
- Strict gate caps the match and re-prefills any tail that is not provably bit-exact. A matched SWA window with no host backing aborts `load_back` instead of silently using a stale/empty tile.
- The FULL-device-anchor clamp on cross-request reuse is opt-in per component (`TreeComponent.device_anchor_needs_reuse_clamp`, `False` everywhere except strict SWA). Non-strict transfer paths stay on main's behavior.

**4. Tests** (`test(swa-hicache): bit-exact capture, restore, and reuse coverage`)

- Capture / restore / reuse / L3 handshake coverage under `test/srt/mem_cache/test_swa_*.py`, plus the small `mem_cache` unit updates that pin the non-strict path.

## Note to reviewers

**Scope.** Off by default: no pool is allocated, no capture or restore runs.

`deepseek_v4_backend_hip_radix.py` and `compress_hip.py` are ROCm-only by construction. In common files, the L3 key namespace and the `unified_swa_hicache` pool branch are gated on the flag at startup. Everything else is either a new
symbol that re-routes nothing (`BindCapturedSWAHost`, `MatchPrefixParams.for_reuse`, the new arg/env fields, the new host-pool methods) or a call whose callee returns early unless strict mode and the SWA host pool are both live.

`test_reuse_does_not_clamp_when_no_component_asks_for_it` pins that a non-strict tree matches exactly what it matched before.

`build_deepseek_v4_hicache_stack(..., server_args=)` is optional and only resolved inside the strict branch, so main's assembly tests that omit it keep working.

## Speed Tests and Profiling

Both arms HiCache on, `DBG=0`, `--hicache-ratio 1.0`. Same-tree off/base as denominator. Threshold: combined mean ≤ 5% regression.

| scenario | metric | result |
| --- | --- | --- |
| Prefill default hit-rate grid (18 cells, 3 sweeps, median/cell) | tok/s vs off | **−3.94%** mean, worst −6.08% @ 0.90 / ISL 51200 |
| Prefill high-hit grid 0.70–0.95 (15 cells, 2 instances × 3 sweeps) | tok/s vs base | **−4.25%** mean, worst −5.97% @ 0.85 / ISL 76800 |
| Decode TPOT (dp8, EAGLE, ISL 51200, BS 32/48/64) | ms/token vs off | 83.89 / 101.06 / 108.78 vs 83.50 / 100.95 / 109.19 (**−0.5 / −0.1 / +0.4%**) |

The prefill cost is the positional H2D of the SWA window + c4/indexer state on reuse (not a content-addressed page copy), only with the flag on. Decode step time is within noise. TTFT at page-aligned ISL still jumps; that is the same alignment artifact as before, not a regression.

In-repo `bench_serving` still works as a rough check (different, smaller workload). Prefix-reuse correctness is the byte-exact harness above, not TTFT.
