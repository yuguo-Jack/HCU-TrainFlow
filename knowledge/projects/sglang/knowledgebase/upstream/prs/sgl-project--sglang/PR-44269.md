# [Fix] sglang-processor: Send watermark only when the request sets it

[Upstream PR](https://github.com/sgl-project/sglang/pull/44269) · state: closed · merged: True

## Original PR description

## Motivation

Follow-up to #44243, merging into its branch.

#44243 adds `"watermark": request.watermark` to the `/generate` sampling params for chat and completions, so every lowered request now carries `"watermark": null`. The engine side of `watermark` (#37577) merged on 2026-10-14. Older engines build `SamplingParams(**sampling_kwargs)` strictly (a msgspec struct, and since #41585 the `/generate` contract also rejects unknown sampling keys), so they raise:

```
TypeError: Unexpected keyword argument 'watermark'
```

sgl-router lowers OpenAI completions (and chats for verified renderers) to `/generate` under the default `--chat-routing legacy`, with no engine version gate. A router built from #44243 therefore fails every lowered request against any engine older than #37577, which is the usual state during a router-first rollout.

Reproduced on an H200 devbox: engine `lmsysorg/sglang:latest` (v0.5.21, no `watermark` field) serving Qwen2.5-0.5B-Instruct, with sgl-router built from each tree and the default routing:

| sgl-router | unary `/v1/completions` | streaming `/v1/completions` | engine `TypeError`s |
|---|---|---|---|
| main before #44243 (`6daae9c98ec`) | 200 | 200 | 0 |
| #44243 (`2bbcbbef6d`) | 500 | empty reply | 2 |
| #44243 + this PR | 200 | 200 | 0 |

## Modifications

`openai/chat.rs`, `openai/completions.rs`: put `watermark` into `sampling_params` only when the request sets it. Leaving it out is equivalent for the engine, whose default is the same `None`. A request that does set `watermark` is still forwarded and validated by the engine, as in #44243.

## Accuracy Tests

- `cargo test -p sglang-processor --all-features` passes with no skipped cases, including #44243's synthetic `watermark` cases (GLM-5.3 chat, DeepSeek-V4-Flash-0731 completions). The parity test drops default-valued keys before comparing bodies, so the fixtures need no change.
- `cargo fmt --check` and `cargo clippy -p sglang-processor --all-targets --all-features -D warnings` are clean.
- The devbox run above.

## Note for #44243 (not in this PR)

#44243 is 3+ commits behind main. Merged with current main, `openai_parity` fails on `Qwen/Qwen3.8-27B "chat"`: the `qwen3.8-27b.json` fixture from #43689 was recorded before #43027, so it still expects `"tool_calls": null`. This PR also removes the extra `"watermark": null` body diff that fixture would otherwise show, but the fixture still needs regenerating from Python on main after a rebase.
