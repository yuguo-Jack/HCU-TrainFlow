# [Fix] openai: Preserve images in Responses tool outputs

[Upstream PR](https://github.com/sgl-project/sglang/pull/34950) · state: open · merged: False

## Original PR description

Fixes #34927

function_call_output.output can be a list of content parts. We were flattening that list to text, which quietly dropped input_image parts before multimodal processing.

This sends list items through the same Responses-to-chat content normalizer already used for message inputs. Plain string tool outputs are unchanged.

Added a regression test that goes through ResponsesRequest and _make_request, then checks that both the text and image reach chat processing.

Tested the Responses unit test file locally: 33 passed. Black, isort, ruff, and the registered-test check also pass.

Validated this fix end-to-end on one DGX Spark GB10 with Qwen3.8-27B (RadixArk NVFP4), SGLang base commit c4271c3fe1262fc2adbd162c33b25de5255251c5, and the exact PR head bd9d21ba331084f57578d6399a67f94ceee636e4 applied in a derived image.

Before the patch, a Responses API function_call_output whose output array contained input_image was rejected during Responses-to-Chat conversion with HTTP 400 message-content validation errors. After the patch, the same request returned HTTP 200 and the model correctly identified the image. The corrected case passed both directly against SGLang and through LiteLLM.

Related regression checks also passed: regular image input, reasoning low/medium/xhigh, thinking disabled, mid-conversation system messages, strict JSON schema, string-valued function.name, tool call, and tool-result continuation.
