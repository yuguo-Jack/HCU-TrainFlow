# [Fix] [NPU] MLA: preserve NZ cache data during CPU retraction

[Upstream PR](https://github.com/sgl-project/sglang/pull/47659) · state: open · merged: False

## Original PR description

## Motivation

With `SGLANG_USE_FIA_NZ=1`, MLA cache data is stored in `[page, tile, slot, 16]` order. CPU retraction backup indexes the public `[page, slot, 1, D]` view as if it were token-major. A partial-page backup therefore saves the wrong rows, and restoring it loses valid KV data.

This affects the MLA FIA-NZ path when PD decode uses `cpu_tensor` retraction backup. Copying a whole aligned page can hide the problem.

## Modifications

Use the existing NZ scatter-index helper for both CPU backup and restore, after DCP slot localization. Copy K and RoPE as 16-element tile rows. Indexer buffers and packed FP8 records keep their existing layouts.

## Accuracy Tests

Ran the actual source copy methods on CPU and Ascend NPU with an independent reshape/permute reference. The comparison covers the entire destination buffer, including untouched regions.

| Backend | Before | After |
| --- | ---: | ---: |
| CPU, torch 2.5.1 | 49/70 passed | 70/70 passed |
| Ascend NPU, torch 2.10.0 / torch-npu 2.10.0.post6 | 49/70 passed | 70/70 passed |

Coverage includes partial and cross-page copies, empty input, chunked transfers, nonzero layer offsets, DCP rank-local slots, draft-worker global slots, indexer/scales and packed FP8. NPU indexing and host/device transfers are real; pool construction is a fixture. DCP mapping was checked on one device, not in a distributed run. Full-model accuracy was not tested.
