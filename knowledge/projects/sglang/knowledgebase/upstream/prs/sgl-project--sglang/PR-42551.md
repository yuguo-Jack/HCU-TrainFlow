# [Feature] Support API keys from secret environment variables

[Upstream PR](https://github.com/sgl-project/sglang/pull/42551) · state: closed · merged: False

## Original PR description

## Motivation

Deployments currently need to place API credentials in CLI arguments unless they construct server arguments programmatically or use configuration files. Allow environment-based credentials so `SGLANG_API_KEY` and `SGLANG_ADMIN_API_KEY` can enable authentication without putting the secret in process arguments.

Closes #36346.

## Modifications

- Define both variables as secret `EnvStr` fields, excluding them from exported environment snapshots.
- Resolve them through the current configuration hook pipeline only when the corresponding input is absent. Explicit SDK, YAML, and CLI values, including empty strings, retain precedence.
- Preserve the raw input record and carry resolved credentials into the serving namespace and worker configuration. Native gRPC's existing HTTP-auth incompatibility check sees the resolved values.
- Update CLI help and add regression coverage to the existing server-argument suite.

General resolved-configuration and startup-log credential redaction is separately tracked by #42444; this PR does not claim to fix those existing exposure paths.

## Accuracy Tests

CPU validation on macOS arm64, Python 3.12.9, Torch 2.14.1, and Transformers 5.17.0:

- **334 tests and 132 subtests passed** across seven files: server arguments, hook registry, namespace mapping, configuration bags, environment exports, environment descriptors, and raw-input preservation.
- The four new methods verify environment fallback/publication, SDK/YAML/CLI precedence, empty/unset behavior, and native gRPC auth rejection. Disabling the new resolution hook makes seven regression assertions/subcases fail; restoring it passes.
- **100% changed executable-line coverage (12/12)**; repository threshold is 60%.
- Applicable pre-commit hooks and `git diff --check` passed.

Tests use the real CLI parser, configuration resolution, namespace publication, and environment descriptors. Local CPU collection uses the repository's `maybe_stub_sgl_kernel` helper and disables the host Mac's MPS availability probe to avoid unrelated MLX imports. Test files ran in separate processes. No model weights, GPU inference, or live serving deployment was used.
