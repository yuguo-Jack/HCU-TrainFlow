# [Doc] [AMD] cookbook: Qwen3.8-Flash-Next MI355X, add the monokernel command for concurrency 1-8

[Upstream PR](https://github.com/sgl-project/sglang/pull/47951) · state: closed · merged: True

## Original PR description

## Motivation

[InferenceX #4542](https://github.com/SemiAnalysisAI/InferenceX/pull/4542) moves the MI355X AgentX lane `qwen3.8next-fp4-mi355x-sglang-agentic-mtp` (added by [#4680](https://github.com/SemiAnalysisAI/InferenceX/pull/4680), documented here by #47520) onto the `20261031` image and serves concurrency 1, 2, 4 and 8 with the FlyDSL monokernel (`--enable-amd-monokernel`). InferenceX requires the production serving settings on a merged SGLang cookbook page before the PR merges. The page documents one command, the #4680 default path, which no longer matches c1–c8.

## Modifications

`docs/cookbook/autoregressive/Qwen/Qwen3.8-Flash-Next.mdx`, MI355X subsection only:

- Image: `lmsysorg/sglang-rocm:v0.5.23-rocm10-mi35x-20261031@sha256:3867dc07ba2530f914e1f210ed829f7a572a75286c8c362dbc22cbecf9b5a7e6`, built from SGLang `e9c18259c7`, AITER `285579b6` and `sgl-amd-mono` `b10f3b71` (the pin since #47483).
- New "Monokernel (concurrency 1–8)" bullet: what `--enable-amd-monokernel` runs, what it needs (NEXTN 3/1/4, the Quark checkpoint, no `--enable-linear-replayssm-spec`), that it is experimental and that SGLang refuses unsupported setups at startup.
- PLE offload and batch-limit bullets updated: c1–c8 keep the table on the GPU and set both limits to the concurrency (1, 2, 4, 8); c12 and c16 keep the offload and 2x (24, 32).
- Two commands: `Concurrency 12–16` (the existing command, unchanged) and `Concurrency 1–8 (monokernel)` (concurrency 8 shown).
- Not changed: the Deploy panel, the generated AgentX snippets, section 2.1.

## Coverage

Each command was compared with the recipe's merged args for its point (c8 and c16): 0 missing, 0 conflicting, 0 extra settings besides `--host` and `--port`; the recipe's `SGLANG_AITER_HONOR_EXPLICIT_MEM_FRACTION` and `AITER_GDR_FLYDSL` are in both.
