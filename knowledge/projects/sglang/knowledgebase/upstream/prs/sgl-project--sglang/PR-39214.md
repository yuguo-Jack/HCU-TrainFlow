# [Feature] Fuse DeepSeek MoE reduction, all-reduce, and RMSNorm with FlashInfer

[Upstream PR](https://github.com/sgl-project/sglang/pull/39214) · state: closed · merged: False

## Original PR description

## Motivation

DeepSeek's deferred TRT-LLM MoE output can be consumed by FlashInfer's fused MoE reduction, all-reduce, residual addition, and RMSNorm API at the next layer. This integrates that path with the existing `--flashinfer-allreduce-fusion-backend trtllm` option.

Depends on the `trtllm_moe_allreduce_fusion` API in [FlashInfer #4730](https://github.com/flashinfer-ai/flashinfer/pull/4730).

## Modifications

- Convert deferred routed expert outputs and weights to the API's expert-major layout and carry them to the next layer with the shared-expert output. Accept the native flat token-major row map and its equivalent `[tokens, top_k]` view, while rejecting malformed shapes.
- Consume the fused output once and continue layer-input communication without repeating all-reduce or RMSNorm.
- Admit FP16/BF16, hidden size 7168, top-k 8 on B200 (SM100) and B300 (SM103), each at TP4/TP8, when the execution route and existing workspace support the operation. TP2 is excluded.
- Honor explicitly selected TRT-LLM fusion throughout deterministic model configuration, while preserving an explicit `--enforce-disable-flashinfer-allreduce-fusion` selection.
- Add layout, dispatch, fallback, producer/consumer, and configuration tests.

## Accuracy Tests

Correctness validation uses SGLang `5f53aee2a236b870ef6e9dc706628f0bf88fcaf9` and FlashInfer `cc8a5d2cc35c7ad3e078e34e4a494b9ffb09ac72`, running DeepSeek-V3-0324-NVFP4 at **TP8 on B200 (SM100) and B300 (SM103)**, with deterministic Triton attention, FP8 KV cache, 4096-token prefill chunks, and full decode CUDA graphs.

**Numerical validation passed on both architectures: 16/16 real-payload comparisons each.** Two eager BF16 `[128, 7168]` norm/residual pairs per rank were compared with native deferred finalization followed by the existing all-reduce/RMSNorm implementation at `atol=rtol=0.01`. All actual and reference outputs were finite, with zero tolerance mismatches. Maximum absolute errors were 0.0625 for norm and 0.015625 for residual on each architecture, satisfying the combined absolute/relative criterion.

All eight ranks entered the exported fused API during eager execution and graph capture, including batch size 1. Each architecture's short diagnostic recorded **35 full decode graph replay observations**, zero fatal log markers, and an empty server process group after teardown. The server return code was -9 after process cleanup; this is not reported as a graceful server exit. These short model probes check finite, deterministic responses; their model outputs were not compared against native-reference responses.

**B200 GSM8K records 0–15: reference 13/16, fused 15/16 with the existing answer parser.** There were no observed scored regressions. The two scored gains, at zero-based ordinals 5 and 8, are trailing-number scorer sensitivity: both routes correctly computed 64 and 45, but the reference responses ended with “16 glasses” and “4-hour return trip,” so the parser selected 16 and 4. Both routes boxed 12 for ordinal 12, whose expected answer is 13. This score difference does not establish a general model-quality improvement.

Both B200 GSM8K phases completed all 16 responses with finite log probabilities and normal stop reasons; none reached the 1024-token limit. All eight ranks passed the route and consume-once checks, with 5221 reference and 5184 fused full decode graph replay observations, zero fatal log markers, and empty server process groups after teardown. Text and token sequences differed across routes for all 16 examples. **The original B200 per-question score-equality analysis remains FAIL** (`per-question correctness differs across consumer routes`); its receipt is preserved.

**B300 GSM8K records 0–15: reference 13/16, fused 15/16, with the same parser-sensitive differences at ordinals 5 and 8 and the same boxed-answer miss at ordinal 12.** Both phases passed the execution checks: 16 finite, normally stopped responses each, none at the 1024-token limit, all eight ranks passing route and consume-once checks, 5221 reference and 5184 fused full decode graph replay observations, zero fatal log markers, and empty server process groups. Both server return codes were -9 after cleanup. The original B300 per-question score-equality analysis also remains **FAIL**. Within each consumer mode, all 16 response texts and token sequences are exactly identical between B200 and B300; all 16 differ between the reference and fused modes.

The fused API retains its low-precision rounding boundaries, while the native reference uses FP32 accumulation for expert and rank reductions. The numerical checks use the stated tolerances; these runs do not establish token- or logit-level equivalence.
