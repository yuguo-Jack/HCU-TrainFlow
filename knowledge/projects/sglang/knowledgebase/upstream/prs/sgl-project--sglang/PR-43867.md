# [PD] Support runtime role switching for NIXL

[Upstream PR](https://github.com/sgl-project/sglang/pull/43867) · state: open · merged: False

## Original PR description

**Draft — a full-service blocker is now reproduced.** With an aligned Torch 2.14.1 / sglang-kernel 0.4.9 / Transformers 5.19.0 / Cutlass DSL 4.8.0 environment, real Qwen3-8B services start and six HTTP role switches succeed. Three prompts generated before swapping both roles, after swapping, and after restoring produced identical token IDs relative to the original P/D run (nine completed generations). However, leaving the decode peer alive while the prefill instance switches P→D→P causes the next request to hang; it was aborted after a 45-second client timeout. Peer bootstrap/transport refresh must be resolved before this feature is ready. Related #34289 addresses prefill replacement behind a cached endpoint.

Standalone-vs-P/D numerical qualification is also incomplete: two of three prompts matched exactly, and the third already differed before any role switch. This is recorded as an unresolved baseline difference, not attributed to this patch. The servers started with CUDA graphs disabled, but the existing role-switch path subsequently captured decode graphs, as shown in server logs.

The aligned environment also passes the focused 98 tests and 14 subtests. The same-process SDK results below remain narrower transport evidence.

## Motivation

The existing `/pd_role_switch` scheduler flow cannot use NIXL because its workers, sockets and memory registrations live for the entire process lifetime. Add NIXL transport teardown so an idle instance can rebuild its role while retaining its model and scheduler-owned KV pools. This implements the NIXL backend part of the runtime P/D switching work in #43699.

## Modifications

- Advertise role-switch support and implement teardown of the old NIXL manager.
- Stop and join transfer, control and heartbeat workers before releasing prepared transfer lists, deregistering memory, or closing ZMQ sockets. A join timeout or unsettled transfer fails closed and retains the resources.
- Deduplicate shared prepared handles, close decode HTTP sessions, and allow repeated teardown after successful cleanup.
- Keep the existing blocking receive behavior unless `--enable-pd-role-switch` is enabled. Reuse the scheduler's idle, staging and memory-headroom guards and unhealthy-on-failure behavior.
- Document startup, draining, the role-switch request and peer bootstrap refresh requirements.

## Accuracy Tests

Focused CPU tests: **98 passed, 14 subtests passed**. Added coverage exercises repeated P/D manager teardown with real ZMQ sockets and threads, port rebinding, shared-handle release, idempotence, and retention of resources when a worker or transfer has not settled.

```bash
CUDA_VISIBLE_DEVICES=99 PYTHONPATH=python .venv/bin/python -m pytest \
  test/registered/unit/disaggregation/test_nixl_backend_basic.py \
  test/registered/unit/disaggregation/test_nixl_deferred_kv_release.py \
  test/registered/unit/disaggregation/test_nixl_sender_failure_cleanup.py \
  test/registered/unit/disaggregation/test_nixl_dsv4_kv_slots.py \
  test/registered/unit/disaggregation/test_pd_role_switch.py -q
```

Additional local validation used **NIXL 1.5.0 / nixl-cu13 1.5.0, UCX, NVIDIA A30** and the production manager, bootstrap server, sender and receiver. Four CPU-buffer cycles and four CUDA-buffer cycles transferred selected KV slots plus auxiliary data, alternating the roles of the original buffer pools. All eight cycles matched the source data exactly, preserved the original KV buffer addresses and stopped the tracked transport workers before recreating the managers.

That harness is a same-process transport test using TCP/shared memory/CUDA IPC with fresh peers each cycle. It does not validate RDMA, model accuracy, the HTTP role-switch handler end to end, or reuse by a peer that still caches the old bootstrap metadata. These remain explicit draft exit criteria.

Applicable pre-commit checks passed. Mintlify `validate` and `broken-links` passed.

## Speed Tests and Profiling

No serving throughput claim. The real-SDK harness measured approximately 0.26–0.31 seconds to tear down each idle P/D pair. Control-socket polling is enabled only for instances that opt into role switching.
