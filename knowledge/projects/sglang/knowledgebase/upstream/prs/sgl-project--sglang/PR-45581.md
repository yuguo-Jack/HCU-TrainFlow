# [Perf] dsv4: Let the decoder tail leave the prefill graph under DP attention with MegaMoE

[Upstream PR](https://github.com/sgl-project/sglang/pull/45581) · state: closed · merged: True

## Original PR description

- `breaks_out_of_prefill_graph` no longer requires `attn_dp_size == 1` or a non-all-to-all MoE, so under DP attention with MegaMoE the decoder replay tail leaves the prefill graph for its row-bucket graphs, as it already does without DP (#45107), instead of computing every row of the captured bucket in the late layers.
- The clause assumed ranks pick graph or eager independently and agree on tail rows through the eager tail's host gather. Inside the graph neither holds: the DP prefill-graph vote is min-reduced, so all ranks replay or none do, and the in-graph tail break reads every rank's tail rows from `global_late_layer_num_tokens_cpu`, exchanged before the forward since #44948. The module docstring now says so.
- DeepSeek V4.1 Flash on GB300, DEP4, MegaMoE, breakable prefill graph (buckets 4096 and 8192) with #44627's changes applied, encoder replay off, 131,072-token context with 4,096 new tokens per request, one run per point: 4K tokens per rank 78.6 -> 58.7 ms per step (52,127 -> 69,746 tok/s/GPU), 8K 140.3 -> 97.5 ms (58,408 -> 84,027), against 96.2 ms eager. GSM8K (sgl-eval, 200 examples) on that configuration: 98.00%, vs 98.50% on main.

Changes behavior only for prefill graphs under DP attention with an all-to-all MoE; the request-window, CP, and unified-KV Triton exclusions stay.
