# [AMD] Use AITER FP8 block selection for MiniMax-M3

[Upstream PR](https://github.com/sgl-project/sglang/pull/41708) · state: open · merged: False

## Original PR description

## Motivation

MiniMax-M3 scores its index cache and selects KV blocks before sparse attention. This PR uses AITER FP8 score and top-k kernels for that work, reducing index-selection time.

## Modifications

- Select the AITER indexer by default for supported gfx950 FP8 index-cache configurations.
- Handle decode, linear verification and ragged prefill, rebuilding page metadata during graph replay.
- Reuse the existing cross-layer top-k cache and retain the NHD sparse-attention consumer.
- Add FP32-reference, 1M-context, graph-replay and per-batch cache-reuse regressions.

Set `SGLANG_M3_USE_AITER_INDEXER=0` to disable both paths, or `SGLANG_M3_USE_AITER_PREFILL_INDEXER=0` to disable only prefill.

## Accuracy Tests

9 GPU regression tests passed on this branch with the enable flags unset, including the cross-layer and per-batch cache-reuse tests. Tested on MI355X with AITER `e7d2453f25`.

`amd/MiniMax-M3-MXFP4`, TP4/EP1, full 5-shot GSM8K (1,319 questions), chat-completions, 16384-token output budget, temperature 0, and real EAGLE3 verification. The baseline includes the EAGLE fix; the candidate adds only AITER FP8 index selection to the same integration stack.

| Configuration | Strict-match | Flexible-extract |
|---|---:|---:|
| Baseline | 96.74% | 96.66% |
| This PR | 96.59% | 96.51% |

The candidate has two fewer correct answers out of 1,319 in each filter. Both configurations are below the 97% reference threshold.

## Benchmarking and Profiling
