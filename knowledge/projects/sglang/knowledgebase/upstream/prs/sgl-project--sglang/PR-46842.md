## Motivation

GLM KDA under interleaved context parallelism gathers the input hidden states before executing its merged input projection. This exposes communication latency on the critical path.

This change overlaps CP input gathering with projection GEMMs using PyTorch's fused AllGather–matmul operation. It retains the existing KDA state-update and output-reduction behavior and supports CUDA Graph capture and replay.


## Modifications

- Add an opt-in `SGLANG_ENABLE_KDA_CP_ASYNC_TP` environment variable, disabled by default.
- Keep KDA inputs CP-sharded until the merged projection and use `torch.ops.symm_mem.fused_all_gather_matmul` to overlap communication and computation.
- Restore sequence order after projection instead of before projection. This preserves the semantics of the bias-free, row-wise linear operation.
- Extend layer-boundary declarations with compute-owned CP input gathering, avoiding a duplicate boundary AllGather.
- Preallocate symmetric-memory workspace before prefill CUDA Graph capture.
- Retain the original gather-and-project path for small batches, unsupported projections/layouts, and requests exceeding the reserved graph workspace.
- Add a boundary regression test covering input-gather ownership and preservation of the output-reduction contract.

The optimized path currently targets interleaved CP/TP group-sharing configurations with CP=TP>1 and attention DP=1. It requires contiguous BF16 inputs and unquantized BF16 merged projection weights, with at least 4,096 local token rows.

This optimization does not depend on MoE FP8 transport or the Q8 attention backend.
## Accuracy Tests

- Layer-boundary regression tests: **9 passed**.
- FakeTensor shape inference and CPU fallback checks passed.
- Four-GPU numerical validation completed on **4× NVIDIA H200** using:
  - Actual GLM layer-0 KDA projection weights.
  - TP4 merged weight shape: **[6416, 4096] per rank**.
  - Rank-distinct synthetic BF16 inputs.
  - Global token counts: **16,384, 17,408, 32,768, and 65,536**.

For all tested shapes and all four ranks:

- Optimized outputs matched the baseline **element-for-element**.
- Maximum absolute difference: **0**.
- Relative RMSE between optimized and baseline outputs: **0**.
- Both paths had approximately **0.00166 relative RMSE** against an FP32 reference.
- CUDA Graph replay checks passed after modifying the captured input buffers.

Targeted Ruff, isort, formatting, registered-test validation, and `git diff --check` passed.

These tests validate the gather/projection/reorder chain. Full-model GSM8K and end-to-end serving validation have not been run for this branch.

## Speed Tests and Profiling

Measured on **4× NVIDIA H200**, using PyTorch **2.14.1+cu130** and NCCL **2.30.7**.

Compared paths:

```text
Baseline:
BF16 AllGather → restore sequence order → merged projection

Optimized:
overlapped BF16 AllGather + merged projection → restore sequence order
```

Timings include communication, the merged projection, and sequence-order restoration. They exclude subsequent KDA gate projections, convolution, recurrent computation, output projection, and full-model execution.

Methodology:

- Actual GLM projection weights with synthetic BF16 inputs.
- Five alternating A/B trials.
- Twenty samples per trial.
- Each sample uses the slowest of the four ranks.
- Reported latency is the median of the five trial medians.
- Eager samples flush L2 before measurement.
- Graph measurements rotate input buffers exceeding five L2 capacities and retain intermediate/output buffers.

### Eager

| Global tokens | Baseline (ms) | Async-TP (ms) | Latency reduction |
| --- | --- | --- | --- |
| 16,384 | 1.5936 | 1.5660 | 1.73% |
| 17,408 | 1.7034 | 1.6609 | 2.50% |
| 32,768 | 3.2568 | 3.0950 | 4.97% |
| 65,536 | 6.4113 | 6.1083 | 4.73% |

### CUDA Graph

Both variants are captured; these comparisons do not attribute CUDA Graph's own benefit to Async-TP.

| Global tokens | Baseline (ms) | Async-TP (ms) | Latency reduction |
| --- | --- | --- | --- |
| 16,384 | 1.6807 | 1.5893 | 5.43% |
| 17,408 | 1.7530 | 1.6984 | 3.11% |
| 32,768 | 3.3268 | 3.1684 | 4.76% |
| 65,536 | 6.6667 | 6.3588 | 4.62% |

The measured benefit is modest. These are operator-chain microbenchmark results, not end-to-end model speedups. No trace-based breakdown of hidden versus exposed communication is included.

The tests used unmodified PyTorch and feature code. A short project-local `TMPDIR` was required: the longer experiment-local temporary path triggered a symmetric-memory initialization crash in the test environment.
