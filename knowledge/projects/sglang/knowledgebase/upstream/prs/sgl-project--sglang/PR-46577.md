# [Fix] inkling: Skip KV stores for CUDA-graph padding tokens in the fused attn prologue

[Upstream PR](https://github.com/sgl-project/sglang/pull/46577) · state: open · merged: False

## Original PR description

## Motivation

Fixes #46572.

With Inkling, prefill runs under the full CUDA graph by default. The fused attention-prologue extend kernel stores K/V for every token in its launch grid, which under graph replay is the padded bucket. Padding tokens (`t >= cu[B]`) get `out_cache_loc = 0` from the prefill graph buffer registry and carry stale, sometimes non-finite, rows, so they are written into KV slot 0. Sliding-window attention can later read slot 0 (KV page size below 128, the default on H200 with FA4), which turns the logits row into NaN: `torch.multinomial` asserts with `SGLANG_OPT_USE_GUMBEL_SAMPLE=0`, and with the default sampler affected requests silently return token 0 with NaN logprobs. Details and a standalone reproducer are in #46572.

## Modifications

- `inkling_attn_prologue_fused.cuh`: add the real sequence count `B` to `AttnPrologueExtendParams` and skip the KV store in `inkling_attn_prologue_extend_kernel` for tokens at or beyond `cu[B]`. Real tokens are stored exactly as before; the `out` / `k_out` / `v_out` writes for padding rows (the graph's own scratch outputs) are unchanged. `B` is already computed in the launcher (`cache_indices.size(0)`), and `cu` has `B + 1` entries.
- `test/registered/kernels/ops/attention/test_inkling_attn_prologue_extend_pad.py`: new kernel unit test. It fills the padded tail of `qkvr` with NaN, maps padding tokens to slot 0 as the graph runner does, and checks that slot 0 and every other unused slot stay untouched while real tokens are stored bit-identically to the kernel's own `k_out` / `v_out` and are finite (`num_pad` 1 and 8).

## Accuracy Tests

Regression test on 1x H200 (`lmsysorg/sglang:v0.5.22-cu130` environment, this branch's source on `PYTHONPATH`):

| Source | Result |
|---|---|
| this commit with the `.cuh` reverted to its parent | 2 of 2 fail: `AssertionError: padded token K was stored into slot 0` |
| this commit | 2 of 2 pass |

End-to-end with the reproducer from #46572 (Inkling-NVFP4 `test` revision, 1x H200, v0.5.22, `SGLANG_OPT_USE_GUMBEL_SAMPLE=0`): unpatched, the server dies at request 14 (2 of 2 runs); with this change, all 70 requests (5 rounds) pass and the server stays up (1 run). With the default sampler unpatched, 1065 of 2000 sampled-token logprobs are NaN at the same request.

The change only skips stores for padding tokens, which no real request should read, so model outputs for real tokens are unaffected; no separate accuracy benchmark was run.

## Speed Tests and Profiling

Not measured. The change adds one read of `cu[B]` and one comparison per thread on the store path of the extend prologue, and removes the stores for padding tokens.
