# [Perf] [AMD] all-reduce: prefer QuickReduce before CustomAllReduce

[Upstream PR](https://github.com/sgl-project/sglang/pull/40771) · state: open · merged: False

## Original PR description

## Motivation

When QuickReduce and CustomAllReduce are both eligible, the current out-of-place all-reduce dispatch selects CustomAllReduce first. This prevents an explicitly configured QuickReduce codec from being used for overlapping message sizes.

This change gives eligible QuickReduce configurations priority while preserving the existing fallback chain. It also allows ROCm deployments that already enable AITER to use AITER's QuickAllReduce implementation without breaking launch scripts that still use the legacy SGLang environment names.

## Modifications

- Change plain out-of-place all-reduce dispatch from:

  ```text
  CustomAllReduce -> QuickReduce -> PyMSCCL++ -> torch symmetric memory -> PyNCCL
  ```

  to:

  ```text
  QuickReduce -> CustomAllReduce -> PyMSCCL++ -> torch symmetric memory -> PyNCCL
  ```

- Apply the same ordering in eager execution and the runtime `"auto"` resolver
  used by compiled and graph-replayed paths.
- Include QuickReduce eligibility in the eager symmetric-memory shortcut guard so that shortcut cannot bypass an eligible QuickReduce communicator.
- Add a QuickReduce factory that:
  - selects AITER QuickAllReduce when `SGLANG_USE_AITER=1`;
  - falls back to SGLang's bundled implementation only when the AITER import is unavailable; and
  - leaves constructor failures visible to the existing communicator setup error handler.
- Wrap bundled and AITER communicators behind an SGLang-owned adapter instead
  of assuming the out-of-tree implementation exposes SGLang-specific state.
- Close QuickReduce before destroying its process groups.
- Translate legacy environment variables without overwriting explicitly set AITER values:

  | Legacy SGLang variable | AITER variable |
  | --- | --- |
  | `ROCM_QUICK_REDUCE_QUANTIZATION` | `AITER_QUICK_REDUCE_QUANTIZATION` |
  | `ROCM_QUICK_REDUCE_CAST_BF16_TO_FP16` | `AITER_QUICK_REDUCE_CAST_BF16_TO_FP16` |
  | `ROCM_QUICK_REDUCE_MAX_SIZE_BYTES_MB` | `AITER_QUICK_REDUCE_MAX_SIZE_BYTES_MB` |

  The legacy `INT8` codec name maps to AITER's `FP8` name.
- Replace the old single-configuration collective benchmark flow with a one-command TP2/TP4/TP8 eager/graph sweep. The driver runs all backends, isolates each AITER implementation and graph shape in a fresh worker process, preserves unavailable rows, stores worker logs, and emits a Markdown report.
- Keep fused all-reduce + normalization dispatch unchanged.
- Expanded AMD QuickReduce coverage to TP2/TP4/TP8 for both bundled and AITER backends. In-range outputs now use codec-specific normalized-L2 limits, while overflow cases require finite, nonzero results because FP16 saturation makes relative-error thresholds world-size dependent.

## Benchmarking and Profiling

### Collective microbenchmark

Environment:

- AMD MI355X
- BF16 input
- TP2, TP4, and TP8
- eager and HIP graph replay
- powers-of-two message sizes from 1 KiB through 512 MiB
- 20 warmups and 101 timed calls per row
- correctness against RCCL before timing
- latency = maximum of each rank's mean GPU-event time

The six configurations produced 1,320 logical cells: 6 configurations × 20
message sizes × 11 implementations. Unavailable or ineligible cells remain in
the report as `—` instead of being dropped.

| TP | Mode | Fastest lossless backend(s) | First compressed QR win | Largest compressed QR speedup |
| ---: | --- | --- | ---: | ---: |
| 2 | eager | SGLang CAR v1 | 2 MiB | 3.807x (INT3) |
| 2 | graph | SGLang CAR v1 | 1 MiB | 3.743x (INT3) |
| 4 | eager | SGLang CAR v1 | 4 MiB | 2.804x (INT4) |
| 4 | graph | AITER CAR | 2 MiB | 2.800x (INT4) |
| 8 | eager | PyNCCL | 8 MiB | 1.636x (INT4) |
| 8 | graph | AITER CAR | 8 MiB | 1.846x (INT4) |

Full-precision QuickReduce did not beat the fastest available lossless backend
in any retained BF16 row. Reduced-precision codecs remain explicit
configuration choices; this PR does not enable them by default.

No measured row failed the sweep's pointwise correctness check. The benchmark now also bounds normalized L2 error for compressed codecs so a low-information result such as an all-zero tensor cannot pass via loose pointwise tolerances. After this validation change, a TP2 BF16 graph smoke run for INT4 at 2 MiB passed the strengthened check and measured 0.038 ms. The full 1,320-cell performance tables below are retained from the completed full sweep; that full matrix was not rerun after splitting every AITER implementation and graph shape into its own worker.
The report preserves these availability gaps:

- RCCL is not graph-captured by this harness.
- torch symmetric memory was disabled on this ROCm/PyTorch runtime.
- SGLang CAR v2 failed
  `torch._C._distributed_c10d._SymmetricMemory.rendezvous` with `HIP error: invalid argument`.
- INT3 is intentionally unavailable at TP4 and TP8.
- AITER CAR and QuickReduce rows outside their supported message-size ranges remain unavailable.

<summary>Serving launch and benchmark commands</summary>

```bash
# Set MODEL_SCRIPT to the Qwen TP4 or DeepSeek-V4 TP8 launcher.
EVAL_ONLY=true ENABLE_SPECULATIVE=false DISABLE_RADIX_CACHE=true CONC=16 \
  AITER_QUICK_REDUCE_QUANTIZATION="${REGIME}" \

for concurrency in 1 4 16; do
  num_prompts=$((concurrency * 4))
  warmup_requests=$((concurrency * 2))
  output_file="results/e2e_${REGIME}_c${concurrency}.json"
  python -m sglang.benchmark.serving \
    --backend sglang \
    --base-url http://127.0.0.1:8888 \
    --model "${MODEL}" \
    --dataset-name random \
    --random-input-len 8192 \
    --random-output-len 1024 \
    --random-range-ratio 1.0 \
    --num-prompts "${num_prompts}" \
    --max-concurrency "${concurrency}" \
    --request-rate inf \
    --warmup-requests "${warmup_requests}" \
    --output-file "${output_file}" \
    --seed 42
done
```

Run the loop once with `REGIME=NONE` and once with `REGIME=INT4`.
