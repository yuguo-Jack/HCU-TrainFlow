# [MLX] Read radix prefix slots from the model runner's `req_to_token` pool

[Upstream PR](https://github.com/sgl-project/sglang/pull/43291) · state: closed · merged: True

## Original PR description

## Motivation

On the MLX backend, the first request that matches a cached prefix crashes the scheduler:

```text
AttributeError: 'NoneType' object has no attribute 'req_to_token'
  File ".../hardware_backend/mlx/tp_worker.py", in _async_extend_batch
```

Since #42824, `MlxTpModelWorker._async_extend_batch` reads the matched prefix's slot ids from `self.req_to_token_pool`, which is `None` on the MLX worker; the pool belongs to the model runner. With the radix cache on by default, any prefix hit takes the server down.

## Modifications

- Read the prefix slots from `self._model_runner.req_to_token_pool`, the pool the allocation writes and the MLX runner is initialized with. This restores the slots the code read before #42824.

## Verification

- `test_async_prefix_hit_reads_slots_from_runner_pool` drives `_async_extend_batch` with a non-zero `prefix_len` and a worker whose own pool is `None`; it fails without the change.
- MLX server (Qwen3-0.6B-4bit, radix cache on), requests sharing a ~1900-token prefix: main crashes on the first prefix hit; with this change every request completes, and the cached run matches the cold run.
- `test_gpt_oss_mlx_correctness.py -k TestGptOssMlxCorrectness` (gpt-oss-20b, radix cache on): 3 failed / 1 passed on main, 4 passed with this change.

With the crash gone, a prefix hit can still read KV corrupted by chained decode; #43292 fixes that.
