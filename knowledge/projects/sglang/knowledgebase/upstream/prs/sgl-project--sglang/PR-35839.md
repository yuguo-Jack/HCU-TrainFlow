# [Diffusion] Add configurable reference image resizing for MiniMax H3 Ref2VA

## Motivation

<!-- Describe the purpose and goals of this pull request. -->

MiniMax H3 Ref2VA currently resizes every reference image to a fixed 2048-pixel short edge, including upscaling smaller inputs.

This behavior matches the original Diffusers preprocessing, but some distilled Ref2VA checkpoints use a different reference-image preprocessing policy during training. For example, ModelTC's MiniMax-H3-Turbo Ref2VA checkpoint recommends matching the reference-image pixel area to the target video canvas:

https://github.com/ModelTC/Minimax-H3-Turbo#note-on-reference-image-resizing

In addition to this, Comfy also offers two different resize modes:

https://docs.comfy.org/tutorials/video/minimax/minimax-h3#prompting-tips-3

Using a different resize policy at inference time can result in:

- a mismatch between training and inference preprocessing;
- unnecessarily large reference-image token sequences;
- increased memory usage from upscaling small reference images;
- degraded Ref2VA conditioning quality.

This PR adds configurable reference-image resizing for MiniMax H3 Ref2VA while preserving the existing SGLang behavior as the default.

## Modifications

<!-- Detail the changes made in this pull request. -->

### Add `reference_resize_mode`

Add a new MiniMax H3 sampling parameter:

```python
reference_resize_mode: str = "diffusers"
```

Supported values:

| Mode | Behavior |
|---|---|
| `match` | Match the reference-image pixel area to the resolved target canvas while preserving aspect ratio. Smaller references are not upscaled. |
| `max` | Downscale only when the reference-image short edge exceeds 2048 pixels. |
| `diffusers` | Always resize the reference-image short edge to 2048 pixels, including upscaling. |

The default remains `diffusers` to preserve existing SGLang behavior.

### Propagate the parameter through all request paths

The parameter is supported by:

- offline `DiffGenerator` requests;
- JSON `/v1/videos` requests;
- multipart `/v1/videos` requests;
- dynamic batching and disaggregated request transfer through `SamplingParams`.

The HTTP video adapter only adds the parameter to lowered sampling kwargs when it was explicitly provided. This ensures omitted values continue to use the `diffusers` default.

Example:

```json
{
  "task": "ref2va",
  "reference_resize_mode": "match",
  "target": {
    "short_edge": 544,
    "aspect_ratio": "16:9",
    "duration_seconds": 5.0
  }
}
```

### Resolve `match` against the final target canvas

Reference-image geometry is resolved during pre-queue admission, after the target video canvas has been finalized.

For `match`, the scale factor is:

```python
scale = min(1.0, sqrt(target_area / reference_area))
```

The resized dimensions:

- preserve the reference-image aspect ratio;
- are independently rounded to the nearest multiple of 32;
- do not crop the source image;
- do not upscale smaller reference images.

This policy applies only to Ref2VA image references using the `image.reference_preserve` material chain. FL2VA first/last keyframes continue to use the existing `image.target_canvas` path and are unaffected.

### Misc

For the default `diffusers` mode, the existing shape policy identifier is preserved:

```text
reference_image_short_edge_v1
```

The new modes use:

```text
reference_image_match_v1
reference_image_max_v1
```

This avoids breaking external logs, tests, or consumers that depend on the existing `shape_policy_version`.

## Accuracy Tests

<!-- If this pull request affects model outputs (e.g., changes to the kernel or model forward code), provide accuracy test results. -->

This PR changes only MiniMax-H3 Ref2VA reference-image preprocessing. It does not modify model weights, kernels, or forward-pass math.

The default `diffusers` policy remains backward compatible:

- Reference-image short edge remains 2048.
- Upscaling behavior is unchanged.
- `shape_policy_version` remains `reference_image_short_edge_v1`.

The opt-in `match` and `max` policies intentionally change Ref2VA conditioning inputs. Added deterministic unit tests cover:

- `match`: matches the target canvas pixel area while preserving aspect ratio.
- `match`: does not upscale smaller reference images.
- `max`: caps the reference short edge at 2048 without intentional upscaling.
- `diffusers`: preserves the legacy 2048-short-edge behavior and metadata.
- Mode normalization and invalid-mode rejection.
- Invalid target-canvas rejection.
- `/v1/videos` transport of `reference_resize_mode`.
- Preservation of the default when the request omits the option.
- Prequeue propagation of the selected mode and resolved target canvas.
- Backward-compatible prequeue fallback to `diffusers`.

Test command:

```bash
PYTHONPATH="$PWD/python" python -m pytest -q \
  python/sglang/multimodal_gen/test/unit/test_minimax_h3_admission.py \
  python/sglang/multimodal_gen/test/unit/test_minimax_h3_media.py \
  -k "reference_resize or reference_image_resize"
```

All tests have passed. No end-to-end visual-quality benchmark is required for the unchanged default diffusers path. Visual output changes are expected only when callers explicitly select `match` or `max`.

## Speed Tests and Profiling

<!-- If this pull request impacts inference speed, provide benchmarking and profiling results. -->

The benchmark below compares the new optional resize policies against that default within the patched build. 

Shared configurations:

- Ref2VA Turbo LoRA with `lora_scale=1.0` and `lora_alpha=8`
- Same two reference images, prompt, and seed for every run
- Target: `short_edge=544`, `aspect_ratio="16:9"`, 10-second output
- 4 denoiser evaluations
- TP4 + Ulysses2 across 8 GPUs
- 2 warmup runs followed by 10 measured runs per mode

Hardware-specific runtime configurations:

- **8× H100 80 GB:** `performance_mode="speed"`, resident execution
- **8× RTX 5090 32 GB:** `performance_mode="memory"`, layerwise offload for DiT, text encoder, and VAE, 20 resident DiT layers

### Results

| Hardware | Resize mode | Mean | Median | P95 | Change vs. `diffusers` | Peak/GPU |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 8× H100 80 GB | `diffusers` | 10.925 s | 10.923 s | 10.982 s | baseline | 45.71 GiB |
| 8× H100 80 GB | `match` | 6.691 s | 6.700 s | 6.757 s | **−38.76% / 1.633×** | 44.28 GiB |
| 8× H100 80 GB | `max` | 9.631 s | 9.636 s | 9.672 s | **−11.84% / 1.134×** | 46.01 GiB |
| 8× RTX 5090 32 GB | `diffusers` | 46.864 s | 46.858 s | 46.964 s | baseline | 16.49 GiB |
| 8× RTX 5090 32 GB | `match` | 31.175 s | 31.172 s | 31.229 s | **−33.48% / 1.503×** | 15.63 GiB |
| 8× RTX 5090 32 GB | `max` | 41.997 s | 41.988 s | 42.112 s | **−10.39% / 1.116×** | 17.64 GiB |

`match` produced the largest latency reduction on both deployments: 38.76% on H100 and 33.48% on RTX 5090 relative to `diffusers`. It also reduced the highest sampled per-GPU memory by approximately 1.43 GiB on H100 and 0.86 GiB on RTX 5090.
