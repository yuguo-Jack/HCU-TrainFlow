# [Doc] cookbook: add TPU7x recipe for GLM-5.3-Flash

[Upstream PR](https://github.com/sgl-project/sglang/pull/45326) · state: closed · merged: True

## Original PR description

## Motivation

GLM-5.3-Flash runs on TPU7x through [sglang-torchtpu](https://github.com/sgl-project/sglang-torchtpu). This adds that recipe to the cookbook page.

## Modifications

- `glm-5.3-flash.jsx`: a `tpu7x` hardware entry (vendor `tpu`, so no engine edit) and one verified Low Latency FP8 cell. The cell serves one TPU7x host (4 chips, TP 8) with DSA on the Pallas sparse MLA kernels and MTP 5/1/6 on the chain spec worker, sized for 8K in / 1K out at concurrency 1.
- TPU7x guards on the GPU-only options: High Throughput, the TRT-LLM/TileLang KV+DSA pairings (replaced by an `FP8 + Pallas (TPU)` pairing), Breakable CUDA Graph, CPU VLM transport, HiCache, the CUDA/ROCm MoE backends, CP=8, the EAGLE/DFlash2 chips, and a PD note. Run mode is Python only.
- `GLM-5.3-Flash.mdx`: TPU7x in the description, a source-install note (the `v0.1.0-tpu` image predates the GLM-5.3-Flash MTP fixes), and a "Serve on TPU7x" configuration tip.

No benchmark entry for TPU7x yet; its card shows pending.

## Testing

- The generated command (cell plus the default `auto` parsers) was launched with `sglang serve` on a TPU7x host from sglang-torchtpu main. It matched the repo recipe it was converted from on `bench_serving` 8k1k and 1k1k, with no recompiles after warmup. Chat requests at the default sampling returned correct answers, with the reasoning and content split by the parsers.
- `node docs/scripts/check_cookbook_configs.mjs` passes. `mint validate` reports the same three warnings as `main` (from `popular-models.jsx`).
