# [Perf] disaggregation: Stop device admission in a decode transfer pass at the first refusal

[Upstream PR](https://github.com/sgl-project/sglang/pull/46898) · state: closed · merged: True

## Original PR description

## Motivation

In `DecodeTransferQueue.pop_transferred`, a host-staged request whose transfer has completed is admitted to the device through `allocate_host_staged`. When that refuses, the pass moves on with `continue` and tries every later completed host-staged request as well. Near a full decode KV pool almost all of those attempts are refusals, and each one recomputes the running batch's request-independent budgets (the retractable-token sums and the allocatable token budgets), so the CPU cost of a pass grows with the number of waiting requests exactly when the pool is full.

The other decode admission loops in this file, `pop_preallocated` and `resume_retracted_reqs`, stop at the first request that does not fit. The transfer pass cannot simply `break`, because the same loop also handles failed and aborted transfers and commits device-destination transfers.

## Modifications

- A pass-local flag records the first refused device admission in `pop_transferred`. After it, the remaining host-staged requests skip `allocate_host_staged` and keep their queue order for the next pass.
- The rest of the pass still runs for every request: failed transfers are still aborted and released, aborted host-staged requests are still released, and device-destination transfers still commit.
- Behaviour change: a smaller later request no longer overtakes a larger one that did not fit within the same pass; it waits for a later pass in queue order, as in the preallocation loop. Device-destination transfers are not affected, since they already hold their device pages.

Not in scope: caching the per-pass budgets, and any change to `pop_preallocated` or `resume_retracted_reqs`.
