# [Fix] function_call: Preserve JSON array tool calls across inter-call whitespace

[Upstream PR](https://github.com/sgl-project/sglang/pull/47372) · state: open · merged: False

## Original PR description

## Motivation

A valid JSON tool-call array can lose later calls when formatting whitespace appears before an inter-call comma. For example, a second call with an array-valued argument is skipped after `} ,`, while the identical array without that space parses normally. The parser can instead locate `[` inside the later arguments and treat it as the beginning of a new call. Character-sized chunks can also leak the formatting whitespace into normal text.

This affects `JsonArrayParser`, used for required/named tool calls with JSON schema constraints. JSON permits spaces, tabs, CR and LF before commas.

## Modifications

- Normalize only leading JSON whitespace in `JsonArrayParser` while waiting for a later call, combining retained buffer and new chunk before delegating.
- Do not modify the shared base detector or model-specific detectors.
- Add regression coverage to the existing `TestJsonArrayParser` class and use `CustomTestCase` as required by the contribution guide.

The change is scoped to schema-constrained JSON arrays. It does not claim to preserve arbitrary prose after the array: after the closing delimiter has been consumed, leading whitespace on a separate prose suffix may also be stripped. Such mixed prose is outside this parser's constrained-array contract.
