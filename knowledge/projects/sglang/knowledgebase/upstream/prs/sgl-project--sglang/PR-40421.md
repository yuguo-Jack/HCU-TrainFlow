# [Perf] [NVIDIA] deepseek-v4.1: Reuse dequantized compressed KV in PD CP prefill (7/N)

[Upstream PR](https://github.com/sgl-project/sglang/pull/40421) · state: open · merged: False

issue:https://github.com/sgl-project/sglang/issues/39700
base pr: https://github.com/sgl-project/sglang/pull/40179

## Summary

DeepSeek V4.1 consumer layers can share the same compressed KV storage, but sparse prefill currently dequantizes that storage into a BF16 workspace on every layer.

Reuse the dequantized compressed KV within a forward to avoid repeated reads, dequantization, and workspace writes.
<img width="2314" height="610" alt="image" src="https://github.com/user-attachments/assets/528e5051-9a33-4982-b47a-cbc6bae0a527" />

## Changes
- Limit reuse to CP sparse BF16 prefill with compression ratios 1 and 2.
- Keep separate workspaces per compression ratio.
- Track validity by source layer and workspace address within the per-forward gather cache.
- Refresh on producer execution, source changes, workspace reallocation, or a new forward.
- Continue updating SWA and top-k inputs for every layer.

This retains additional scratch memory for the separate workspaces.

## Validation
- GPU regression tests cover shared sources, source updates, ratio interleaving, consecutive forwards, and workspace resizing.
- All 16 short/long-context smoke-test outputs match the baseline.
- In a six-step trace, compressed KV dequantization calls decrease from 228 to 24 (89.5% fewer).

### Performance
DeepSeek V4.1 Flash on 8×B200 with PD disaggregation; prefill uses TP4/EP4, CP, BCG, MegaMoE, and DSpark. Results are medians of three unprofiled runs using the unchanged benchmark script, with 512 requests and an output length of 500, which is 60k unprefix cache of 64k all input length.
