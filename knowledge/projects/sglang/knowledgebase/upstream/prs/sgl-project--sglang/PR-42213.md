# [Perf] openai: Cache tool schema validation

[Upstream PR](https://github.com/sgl-project/sglang/pull/42213) · state: open · merged: False

## Original PR description

## Motivation

The chat endpoint validates each tool's JSON schema on every request. Agents often resend the same tools across turns, repeating a blocking Python check on the API event loop.

## Modifications

Cache successful schema checks in a bounded, per-process LRU keyed by a BLAKE2 digest of the normalized schema with sorted keys. Invalid schemas are checked each time. Schemas that cannot be serialized, and NaN or Infinity values, use the existing validation path. The cache holds at most 4,096 digests.

## Accuracy Tests

Focused schema-cache regressions and scoped formatting pass on the updated branch. Model inputs and sampling are unchanged. An earlier v0.5.20 server returned the same HTTP 400 for repeated invalid schemas. Direct Python callers can pass tuple or Enum values that share a digest with their JSON forms; HTTP JSON requests cannot contain those values.

Run the unit suites with `python -m pytest` and scoped formatting with `pre-commit run --files <changed-files>`.

## Speed Tests and Profiling

A v0.5.20 B200 backport with GLM-5.3-Flash measured median time to first token at 77 ms with the cache and 241 ms without it for the same cached-prefix request on an idle server. This predates the NaN guard; the current branch has not been benchmarked. Multiple API workers and the live gRPC bridge were not benchmarked.
