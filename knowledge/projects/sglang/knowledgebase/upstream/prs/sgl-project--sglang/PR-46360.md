# [Feat] mem_cache: Platform hook for the page_size == 1 allocator

[Upstream PR](https://github.com/sgl-project/sglang/pull/46360) · state: open · merged: False

## Original PR description

## Motivation

`SRTPlatform.get_paged_allocator_cls()` lets a platform replace the paged KV allocator, and its docstring says it is "honored at every paged-allocator construction site". At `page_size == 1`, though, two sites construct `TokenToKVPoolAllocator` directly and never consult the platform:

- the KV cache configurator (`kv_cache_configurator.py`, the `page_size == 1 and not dcp_enabled` branch);
- `SWATokenToKVPoolAllocator.__init__`, in its `page_size == 1` branch.

A platform that needs a different allocator has to monkeypatch the module-level name at page size 1. Examples: CPU-resident free-list bookkeeping, or no device `free_pages` kernels.

## Modifications

- New `SRTPlatform.get_token_allocator_cls() -> Optional[type]`, default `None`. `None` keeps `TokenToKVPoolAllocator`. The class is constructed with the same arguments as the in-tree one.
- Both page-size-1 sites use `current_platform.get_token_allocator_cls() or TokenToKVPoolAllocator`.

Nothing changes for in-tree platforms (they all return `None`).

## How it was found

Found while building an out-of-tree Neuron/Trainium platform plugin. Qwen3.5 serves at `page_size == 1`, where upstream builds `TokenToKVPoolAllocator`, whose device `free_pages` cannot take the CPU indices the plugin's host paths free. The plugin currently patches `kv_cache_configurator.TokenToKVPoolAllocator` to return its paged allocator at one token per page.

## Open questions

- Alternatively, `get_paged_allocator_cls()` could be honored at page size 1 too (constructing it with `page_size=1`). That is what the plugin does internally. It would change behavior for platforms that already override the paged class (NPU, XPU, ...), so I kept a separate hook. Happy to fold them together if preferred.
