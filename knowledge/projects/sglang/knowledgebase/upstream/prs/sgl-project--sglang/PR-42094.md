# [Fix] Use the reduced draft head for a tied Qwen3.5 MTP with --speculative-token-map

[Upstream PR](https://github.com/sgl-project/sglang/pull/42094) · state: closed · merged: False

## Original PR description

## Motivation

With `--speculative-token-map`, a Qwen3.5 MTP draft with tied embeddings never gets the reduced head. Its top-k indices are then vocabulary ids, but they are read as indices into the hot-token list. On Qwen/Qwen3.5-4B this fails at start-up.

Qwen3.5 checkpoints with `tie_word_embeddings` (Qwen/Qwen3.5-4B, for example) build the MTP draft's `lm_head` as its `embed_tokens`. With a token map, `EAGLEWorkerV2.init_lm_head` cuts the target head down to the hot rows and passes it to the draft's `set_embed_and_head` ([eagle_worker_v2.py#L346-L353](https://github.com/sgl-project/sglang/blob/41cbe65de05b209f3263942389267f79bd749d6a/python/sglang/srt/speculative/eagle_worker_v2.py#L346-L353)). But `Qwen3_5ForCausalLMMTP.set_embed_and_head` installs a head only when the embeddings are untied ([qwen3_5_mtp.py#L170-L180](https://github.com/sgl-project/sglang/blob/41cbe65de05b209f3263942389267f79bd749d6a/python/sglang/srt/models/qwen3_5_mtp.py#L170-L180)).

So a tied draft keeps scoring all 248,320 rows of its embedding, and its top-k indices are vocabulary ids. `draft_forward` then maps each index `i` to `hot_token_id[i]` ([#L689-L690](https://github.com/sgl-project/sglang/blob/41cbe65de05b209f3263942389267f79bd749d6a/python/sglang/srt/speculative/eagle_worker_v2.py#L689-L690)), as if it indexed the hot list. Any index at or above the map's length is out of range, and an index below it proposes the wrong token.

<details>
<summary>Reproduction</summary>

On main (40e1bb0f, on a GH200; the code above is unchanged at 41cbe65de0), Qwen/Qwen3.5-4B with `--speculative-algorithm NEXTN --speculative-num-steps 3 --speculative-eagle-topk 1 --speculative-num-draft-tokens 4 --speculative-token-map <map>` fails at start-up, while capturing the draft CUDA graphs. The map holds the 32,768 most frequent tokens, and CUDA graphs are on.

```
.../aten/src/ATen/native/cuda/IndexKernel.cu:111: operator(): block: [0,0,0], thread: [0,0,0] Assertion `-sizes[i] <= index && index < sizes[i] && "index out of bounds"` failed.
...
Exception: Capture cuda graph failed: AcceleratorError: CUDA error: device-side assert triggered
```

Device asserts are reported asynchronously, so the Python traceback stops in `select_top_k_tokens` (called from `draft_forward`), after the hot-token lookup.

</details>

## Modifications

When a tied draft receives a head whose row count differs from its embedding's, `set_embed_and_head` now gives the draft its own head holding those rows. That head is `_ReducedLMHead`, a module with only a `weight`, which is all `LogitsProcessor` reads. Other cases are unchanged. Without a token map, the head has the embedding's row count and the draft stays tied. Untied checkpoints take the existing branch.

The new `TestQwen3_5MTPTiedDraftHead` in `test_qwen3_5_pipeline_parallel.py` covers both cases on a stub MTP module. The reduced-head case fails on main (41cbe65de0) and passes with this change. `python -m pytest test/registered/unit/models/test_qwen3_5_pipeline_parallel.py` gives 7 passed.

#38147 also edits `set_embed_and_head`, to share the target's tensors when the draft skips allocating them. It keeps the untied-only head branch, so it does not change this case. The two PRs touch neighbouring lines.

## Accuracy Tests

With this change, the launch above starts and serves. Greedy speculative decoding checks every token against the full target head, so the map changes which tokens are proposed but not which are emitted, up to numerical differences between verify passes. With and without the map, output tokens match exactly on 79 of 80 prompts at concurrency 1 and 77 of 80 at concurrency 8.

## Speed Tests and Profiling

At concurrency 1 the map is about 2% slower: 405.0 against 413.4 tok/s, the mean of two runs each. The accept length drops from 3.10 to 2.98, and the cheaper draft head does not make up for that on this model. At concurrency 8 the two runs without the map differ by 9%, so that comparison is inconclusive. The PR is a fix rather than a speed change; without it, the map cannot be used with this model at all.
