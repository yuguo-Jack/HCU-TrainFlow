# [Feat] hicache: Honor dist timeout during MLA dedup group setup

[Upstream PR](https://github.com/sgl-project/sglang/pull/45176) · state: open · merged: False

## Original PR description

> Part of the HiCache MLA host-dedup series (see umbrella(#45177)). This is `[7/N]`, stacked on `[6/N]`. Builds on `[3/N]` (#45141 — L2 dedup); the file-prefetch call path additionally depends on `[4/N]` (#45168 — file L3).

## Motivation

MLA host dedup adds new NCCL broadcast groups, and file L3 adds a new Gloo synchronization group. Previously these groups did not inherit `--dist-timeout`, so when a rank is absent, waiting on config exchange or broadcast can exceed the server's configured timeout.

The wait can happen **before** the new group is created: ranks first exchange config over the existing group, and an absentee stalls that step. Setting a timeout only on the newly created group does not cover this, so the arrival check before group creation must also be bounded.

## Modifications

**1. Custom groups inherit the server timeout** (`distributed/parallel_state.py`, `mla_host_dedup.py`)

Pass the existing `--dist-timeout` through the custom group-construction interface to the dedup NCCL broadcast group and the file-prefetch Gloo group; keep the PyTorch default when the server does not set one.

**2. Also bound the config exchange** (`distributed/parallel_state.py`)

When the metadata backend is Gloo and a timeout is set, perform an arrival check before exchanging group-construction config. If a rank is absent before entering `new_group()`, it fails on time instead of only bounding later group collectives. Other backends skip this Gloo-only check.

**3. Add arg-passing and absent-rank tests** (`test_mla_host_dedup_primitives.py`, `test/manual/hicache/test_mla_host_dedup_timeout.py`)

Check timeout passing and normal group construction; a manual CPU script then delays one rank and confirms the absentee is reported within the time limit rather than waiting forever.

## Accuracy Tests

The reported checks below are historical validation of this implementation. In the three GPU missing-sender runs, the probe explicitly exits its processes after verifying the watchdog error; Python error delivery took about 40.5 seconds with `work.wait(40s)`. This proves the configured watchdog is active, not graceful full-service cleanup or a response within the watchdog timeout.

- Timeout and group-construction targeted tests: **15 passed**.
- Two-process CPU repro: two ranks construct a group normally, then rank 1 delays 7s before entering the next construction. With a 3s timeout, rank 0 reports the absent rank at **3.01s** and the script exits cleanly.
- Manual dual-GPU check: two ranks each complete 100 normal NCCL broadcasts; a separate missing-sender check has the watchdog error at the configured limit, exiting cleanly for three consecutive rounds.

These are targeted communication checks and do not guarantee coverage of every full-service hang. The CPU check runs:

```bash
PYTHONPATH=python CUDA_VISIBLE_DEVICES=0 python3 -m pytest -q \
  test/registered/unit/mem_cache/test_mla_host_dedup_primitives.py
PYTHONPATH=python CUDA_VISIBLE_DEVICES=0 python3 \
  test/manual/hicache/test_mla_host_dedup_timeout.py
```
