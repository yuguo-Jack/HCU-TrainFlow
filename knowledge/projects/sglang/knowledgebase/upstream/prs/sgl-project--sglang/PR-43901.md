# [Refactor] scheduler: List every request holder and check no request is in two

[Upstream PR](https://github.com/sgl-project/sglang/pull/43901) · state: closed · merged: True

## Original PR description

Every place a live request can sit in the scheduler is now listed in one call, so later changes can read the requests from one place instead of each walking its own set of queues and batches.

- `Scheduler.request_lists()` returns the lists that hold the live requests, by name, read at call time (a PD role switch rebuilds the queues). It reads the lists that are plain fields (waiting, grammar, chunked, running, PD prefill bootstrap and transfer, the active dLLM requests), and adds the lists of each component that wraps or hides its requests, from that component's `request_lists()`: `DecodePreallocQueue` (prealloc, retracted, held), `DecodeTransferQueue` (transfer, releasing), `HiSparseCoordinator` (staging), `UocrSchedulerRuntime` (held document windows) and `DeferredResponses`.
- A request is in at most one list. A request that PD prefill or HiSparse launched is in none until its result is processed; giving those an owner from launch is a follow-up.
- `SchedulerInvariantChecker.maybe_check_request_lists()` raises when a request is in two lists, under `SGLANG_ENABLE_RUNNING_REQS_CHECK` (on in CI). It runs at every step launch, so it covers every event loop. The running-request cross-check is unchanged.
- The busy memory check (`SGLANG_ENABLE_STRICT_MEM_CHECK_DURING_BUSY`) counts the rows held by every list plus `last_batch` and `running_batch`, instead of the two batches plus the chunked request.

No behavior change, except that the busy memory check now also counts rows held outside the two batches (HiSparse staging, active dLLM requests, PD decode queues). In the normal loops it counts the same rows as before.

## Test plan
- New unit test: a request in both the waiting queue and the running list fails the check.
- The unit tests this PR touches pass locally with `SGLANG_IS_IN_CI=1` (which turns the check on, as in CI).
