# [Feat] pp: Replay breakable prefill graphs on PP stages with zigzag prefill CP

[Upstream PR](https://github.com/sgl-project/sglang/pull/47604) · state: open · merged: False

## Original PR description

## Motivation

Pipeline parallelism combined with prefill context parallelism (`--pp-size > 1 --enable-prefill-cp`) always fell back to eager prefill, even with `--cuda-graph-backend-prefill breakable`. Main already supports breakable prefill graphs on PP stages via proxy tensors (#36248), and zigzag CP already runs each rank's CP-local body inside the breakable graph and only gathers at the logits tail. The missing piece is the PP stage boundary: later stages receive CP-local proxy rows, but the graph path assumed global (un-sharded) rows.

## Modifications

- `layers/cp/bcg/__init__.py`: `supports_prefill_cp_bcg` now allows `pp_size > 1` for the zigzag strategy (other strategies keep falling back).
- `layers/cp/bcg/bcg.py`:
  - track `stage_local_tokens` (the eager CP-local row count);
  - on later PP stages, `prepare` skips the embedding lookup and only shards positions with `cp_shard_position_ids`; proxy rows past the live CP-local count (`[stage_local_tokens:captured_local_tokens]`) are cleared instead of the global bucket padding;
  - a non-last stage returns proxy rows `[:stage_local_tokens]`, i.e. the same layout the eager CP runner produces, so the next stage can replay or run eagerly independently.
- `cuda_graph_buffer_registry.build_prefill_registry`: new `zero_pp_proxy_padding` flag; under CP BCG the PP proxy buffers keep their padding (cleared by the CP prepare step).
- `prefill_cuda_graph_runner.py`: capture PP proxy tensors with the CP-local bucket size, and skip the raw-row slice of the stage output under CP BCG.
- `cuda_graph_setup.py`: PP + prefill CP keeps the prefill graph only when the backend is `breakable` and `supports_prefill_cp_bcg` holds; otherwise disables it as before.
- `test/registered/cp/test_cp_strategy_unit.py`: tests for the zigzag-only gating, later-stage prepare (proxy rows kept, embedding skipped, padding cleared), and non-last-stage output rows.

## Accuracy Tests

Qwen3-30B-A3B-Instruct-2507-FP8, 4x B300, `--tp-size 2 --pp-size 2 --attn-cp-size 2 --ep-size 2 --enable-prefill-cp --cp-strategy zigzag`, GSM8K 5-shot greedy:

| | GSM8K |
|---|---|
| main, eager prefill | 0.9543 |
| this PR, `--cuda-graph-backend-prefill disabled` | 0.9528 |
| this PR, `--cuda-graph-backend-prefill breakable` | 0.9574 |

With `breakable`, both PP stages capture successfully (~15 s, ~1.6 GB) and 1314/1316 prefill batches report `cuda graph: True` in the server log.

Unit tests: `python -m pytest test/registered/cp/test_cp_strategy_unit.py` (28 passed) and the prefill cuda graph runner unit tests pass.
