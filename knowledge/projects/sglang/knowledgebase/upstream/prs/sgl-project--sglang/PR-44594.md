# [Perf] [NVIDIA] gemm: Tune SM120 FP8 GEMV config for small N/K

[Upstream PR](https://github.com/sgl-project/sglang/pull/44594) · state: closed · merged: False

## Original PR description

## Motivation

The M=1 FP8 GEMV (`sm120_fp8_gemv`) leaves bandwidth unused on small projections such as Qwen3.8-27B's `out` (5120x6144), which runs 64x per decode step.

## Modifications

`_config` now takes `k`. When N <= 6144 and K <= 6144, it uses 4 rows per warp `(4, 1, 8)` instead of `(1, 1, 8)`. Larger shapes keep their current config.

The rule covers both N and K because the win does not hold past that region: N=7168 and N=8192 lose 6-7% with 4 rows per warp, and K >= 12288 is neutral.

## Accuracy Tests

Max relative error vs an fp32 reference through the public `sm120_fp8_gemv` is <= 2.9e-3 on all tested shapes, the same as before the change.

## Speed Tests and Profiling

Timing is `marker.do_bench` graph replay with the weights cloned per iteration, median, min over interleaved passes.

| N x K | speedup `(4,1,8)` vs `(1,1,8)` |
|---|---|
| 4096 x 4096 | 1.04x |
| 5120 x 5120 | 1.15x |
| 5120 x 6144 (Qwen3.8-27B out) | 1.12x |
| 6144 x 4096 | 1.07x |
| 7168 x 5120 (unchanged) | 1.00x |
| 16384 x 5120 (unchanged) | 1.00x |

Not yet measured on RTX 5090 / RTX PRO 6000; an A/B there is needed before relying on it.
