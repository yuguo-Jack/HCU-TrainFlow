# [Feature] Support DSA PD with prefill CP and decode DCP

[Upstream PR](https://github.com/sgl-project/sglang/pull/40117) · state: closed · merged: False

## Original PR description

## Motivation

**Deployment**

- **Model / hardware:** `GLM-5.3 NVFP4` with Humming on two nodes, each with 8 H20 GPUs.
- **Prefill:** TP8 + interleaved CP8 + DSA cache layer splitting.
- **Decode:** TP8 + DCP8.
- **KV transfer:** Mooncake between prefill and decode nodes.

**Goals**

- Enable prefill CP and decode DCP to work together in PD serving.
- Support `100w` contexts with distributed cache storage and bounded temporary memory.
- Reduce KV transfer overhead for concurrent long-context requests.

**Dependency:** #35073 (GLM ModelOpt NVFP4 support with Humming on Hopper).

## Modifications

### 1. Enable DSA attention on decode context shards

- **Problem:** DSA index-cache writes, top-k selection and attention metadata did not handle token-sharded decode caches. A rank-local top-k alone cannot select the best tokens across the full context.
- **Change:** Map cache writes and attention metadata to each DCP rank, gather local top-k candidates to select global top-k, and merge local attention outputs using log-sum-exp (LSE). Handle empty shards and CUDA Graph capture/replay.

### 2. Connect layer-split prefill CP to decode DCP

- **Problem:** PD bootstrap rejected prefill CP > 1 with decode DCP. Prefill distributes complete token sequences by layer, while decode needs each layer distributed by token; index-K pages also store keys and scales in separate regions.
- **Change:** Allow prefill CP with DSA cache layer splitting, and add layer/rank mapping and page-layout conversion for MLA and index-K transfers. Update Mooncake and NIXL transfer paths; GPU validation covers Mooncake.

### 3. Bound transfer buffers and reduce RDMA overhead

- **Problem:** Long or cached prefixes can exceed the MLA packing buffer, triggering per-token RDMA fallback. Million-token index-K transfers also produced millions of small descriptors, making descriptor construction and submission expensive.
- **Change:** Split oversized MLA transfers into batches that fit the existing buffer. Pack index-K pages with Triton and coalesce them into larger RDMA transfers. Reuse registered buffers only after transfer completion, keeping packing memory bounded as context length grows.

### 4. Reduce peak prefill temporary memory

- **Problem:** The previous logits chunk could remain live while the next chunk was allocated. Single-request top-k also copied the same page-table row for every query, causing large temporary allocations and allocator OOM retries at million-token lengths.
- **Change:** Release logits and temporary top-k tensors before allocating the next chunk. Use a shared, zero-stride page-table view for single-request prefill instead of duplicating rows.

### 5. Add regression coverage and transfer diagnostics

- Add tests for DCP indexing/top-k, transfer layouts, bounded packing, GPU gather and temporary-memory behavior.
- Add a manual PD request probe and opt-in profiling for transfer queueing, packing, descriptor construction and submission.

## Launch configurations

### Prefill — TP8 + CP8

```bash
export SGLANG_HUMMING_INPUT_QUANT_CONFIG='{"dtype":"float8e4m3"}'
export SGLANG_HUMMING_ONLINE_QUANT_CONFIG='{"force_requant":true,"dtype":"float4e2m1","group_size":32}'
export SGLANG_DSA_MQA_LOGITS_FREE_MEM_FRACTION=0.05

sglang serve \
  --model-path /models/GLM-5.3-NVFP4 \
  --served-model-name GLM-5.3-NVFP4 \
  --host 0.0.0.0 \
  --port 30000 \
  --disaggregation-mode prefill \
  --disaggregation-transfer-backend mooncake \
  --disaggregation-bootstrap-port 8998 \
  --tp-size 8 \
  --enable-prefill-cp \
  --cp-strategy interleave \
  --attn-cp-size 8 \
  --enable-dsa-cache-layer-split \
  --kv-cache-dtype fp8_e4m3 \
  --chunked-prefill-size 8192 \
  --quantization humming \
  --moe-runner-backend humming \
  --disable-shared-experts-fusion \
  --reasoning-parser glm45 \
  --tool-call-parser glm47 \
  --mem-fraction-static 0.85 \
  --enable-metrics \
  --enable-cache-report \
  --enable-request-time-stats-logging
```
