# [Scheduler] Charge the host-hit Mamba node slot in prefill admission

[Upstream PR](https://github.com/sgl-project/sglang/pull/43138) · state: closed · merged: False

## Original PR description

## Motivation

When a request's Mamba state hits on host (HiCache load-back, the external linker, LMCache), `req.mamba_host_hit_length` is 1 and the load-back fills two Mamba slots: the node's and the request's own. `PrefillAdder` charged only the request's slot, and `budget_state` only checks that at least one slot remains, so a host-hit request could be admitted with a single Mamba slot left.

## Modifications

- `_mamba_gap_budget_for_req` also charges the host-hit node slot. It is charged only while the request holds no state yet: a chunked continuation keeps its stale `mamba_host_hit_length`, but its hit was already loaded.
- `_update_prefill_budget` debits `rem_mamba_slots` by the slots charged, not by a fixed 1.
- `add_one_req` returns `NO_TOKEN` when the request needs more Mamba slots than remain.

## Tests

No new test. On H200:

- `TestUnifiedHybridHiCacheBitExact` (Inkling, Mamba host hits): kl_divs 0.0 x 9.
