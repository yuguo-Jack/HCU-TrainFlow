# [Feat] docker: Add AWS EFA image variants built on published images

[Upstream PR](https://github.com/sgl-project/sglang/pull/41006) · state: closed · merged: True

## Original PR description

## Motivation

To improve sglang out-of-box experience on AWS GPU clusters.

## Modifications
Adds AWS EFA variants of the published SGLang CUDA 13 images. Each one is a thin layer over an image that's already published, so `docker/Dockerfile` and the existing release workflows are unchanged.

- **`docker/efa.Dockerfile`**: `FROM ${BASE_IMAGE}`, following the pattern of `docker/sagemaker.Dockerfile`. It adds:
  - The AWS EFA userspace stack: libfabric with the EFA provider, rdma-core and aws-ofi-nccl.
  - On amd64, the EFA Mooncake wheel, pinned to the Mooncake version already in the base image.
  - EFA defaults: `MOONCAKE_PROTOCOL=efa` (`tcp` on arm64, where the EFA wheel isn't published), `SGLANG_DISAGGREGATION_NIXL_BACKEND=LIBFABRIC`, and `NCCL_NET_PLUGIN=ofi` / `NCCL_TUNER_PLUGIN=ofi`.
  - `LD_LIBRARY_PATH=/opt/amazon/efa/lib`. With `--gpus`, the NVIDIA container toolkit reruns `ldconfig`, and the rebuilt cache picks the distro libfabric 1.17.0. That copy lacks `FABRIC_1.7`, so NIXL fails with `createBackend: unsupported backend 'LIBFABRIC'`, the same error as on `nightly-dev-20261013-7224fce1`.
  - Build-time checks: the EFA provider is present, every NIXL LIBFABRIC plugin resolves to the AWS libfabric, the ofi-nccl plugins are in the loader cache, and the Mooncake wheel swap leaves exactly one Mooncake package at the expected version.
- **`.github/workflows/release-docker-efa.yml`**: runs after each base workflow succeeds and publishes amd64 + arm64 images:

  | Base | EFA tags |
  |---|---|
  | `v{version}` | `v{version}-efa`, `latest-efa`, `v{version}-cu130-efa`, `latest-cu130-efa` |
  | `v{version}-runtime` | `v{version}-runtime-efa`, `latest-runtime-efa`, `v{version}-cu130-runtime-efa`, `latest-cu130-runtime-efa` |
  | `nightly-dev-{date}-{sha}` | `nightly-dev-efa-{date}-{sha}`, `dev-efa` |

  Nightly EFA tags reuse the base tag's exact `{date}-{sha}` suffix, so each one matches a `nightly-dev-*` image on the same SGLang commit. A `workflow_dispatch` can layer EFA onto any published tag, and old `nightly-dev-efa-*` tags are pruned.
- **`mooncake_store.py`**: when `"protocol"` is missing from the config file or extra config, the store now falls back to `MOONCAKE_PROTOCOL.get()` instead of the hard-coded default, so it honors the image's `MOONCAKE_PROTOCOL=efa`.
- **Docs**: `install.mdx` lists the EFA tags. `pd_disaggregation.mdx` describes what the images contain, the amd64 limits, a `docker run` example with the EFA devices, and how to build `efa.Dockerfile` on a custom base.

Build of `docker/efa.Dockerfile` on a published nightly image (amd64):

```bash
docker buildx build \
  --platform linux/amd64 \
  --load \
  -f docker/efa.Dockerfile \
  --build-arg BASE_IMAGE=lmsysorg/sglang:nightly-dev-<date>-<sha> \
  --build-arg EFA_IMAGE_TAG=lmsysorg/sglang:nightly-dev-efa-<date>-<sha> \
  -t lmsysorg/sglang:nightly-dev-efa-<date>-<sha> \
  docker/
```

Build of `docker/efa.Dockerfile` on a published latest (amd64):

```
docker buildx build \
  --platform linux/amd64 \
  --load \
  -f docker/efa.Dockerfile \
  --build-arg BASE_IMAGE=lmsysorg/sglang:latest \
  --build-arg EFA_IMAGE_TAG=lmsysorg/sglang:latest-efa \
  -t lmsysorg/sglang:latest-efa \
  docker/
```

Build of `docker/efa.Dockerfile` on a published latest-runtime (amd64):

```
docker buildx build \
  --platform linux/amd64 \
  --load \
  -f docker/efa.Dockerfile \
  --build-arg BASE_IMAGE=lmsysorg/sglang:latest-runtime \
  --build-arg EFA_IMAGE_TAG=lmsysorg/sglang:latest-runtime-efa \
  -t lmsysorg/sglang:latest-runtime-efa \
  docker/
```

Hey team, 

Can we consider an approach where we make a separate thin Dockerfile built on the published runtime image

The repo already does this: docker/sagemaker.Dockerfile is just FROM lmsysorg/sglang:latest plus a few lines. We can the same with a new docker/efa.Dockerfile (we can separate the workflows out from main workflow as well) 

```Docker
ARG BASE_IMAGE=lmsysorg/sglang:latest-runtime
FROM ${BASE_IMAGE}

ARG TARGETARCH
ARG EFA_INSTALLER_VERSION=1.50.0
ARG EFA_INSTALLER_SHA256=fa6dff8593d866866c13cb4640d9059835cd4efa427971f100ab40c97bef2841
ARG MOONCAKE_EFA_VERSION=0.3.13.post1

RUN set -eux; \
    curl -fsSL --retry 3 -o /tmp/efa.tgz \
        https://efa-installer.amazonaws.com/aws-efa-installer-${EFA_INSTALLER_VERSION}.tar.gz; \
    echo "${EFA_INSTALLER_SHA256}  /tmp/efa.tgz" | sha256sum -c -; \
    tar -xzf /tmp/efa.tgz -C /tmp; \
    apt-get update; \
    cd /tmp/aws-efa-installer && ./efa_installer.sh -y --skip-kmod --skip-limit-conf --no-verify; \
    /opt/amazon/efa/bin/fi_info -l | grep -q '^efa:'; \
    rm -rf /tmp/efa.tgz /tmp/aws-efa-installer /var/lib/apt/lists/*

RUN --mount=type=cache,target=/root/.cache/pip \
    if [ "${TARGETARCH}" = "amd64" ]; then \
        pip uninstall -y mooncake-transfer-engine-cuda13 && \
        pip install --no-deps mooncake-transfer-engine-efa-cuda13==${MOONCAKE_EFA_VERSION}; \
    fi

ENV PATH="/opt/amazon/efa/bin:${PATH}"
```
