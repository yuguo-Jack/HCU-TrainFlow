# [Feat] scheduler: add mixed-prefill resource controls

[Upstream PR](https://github.com/sgl-project/sglang/pull/47308) · state: open · merged: False

## Original PR description

A continuing long prefill can spend the input budget even when the chunk budget has nominal room reserved for a short waiter. The upstream base checks that budget before each waiting candidate. This is a scheduling gate, not a universal hard input limit; other versions or paths can admit requests differently.

This adds related controls for mixed-prefill scheduling:

- Account for both input and chunk budgets in the existing shortest-prefill-first reservation, retaining the original DCP and sharded/padded paths.
- Add an opt-in FCFS warm-head reservation. It bounds the continuation's chunk without reordering the queue; normal admission still decides whether the waiter fits.
- Add opt-in pre-admission overlap limits using the pending prefill's token count plus the next chunk's bound and/or minimum free GPU memory across the TP group.

The new controls default to off. FCFS reservation falls back for DCP, Mamba, HiCache/external cache, custom radix backends, encoder SWA replay and other unsupported modes. It does not cover our DCP8/Mamba/HiCache K3 deployment. Overlap budgets require the standard non-disaggregated overlap scheduler with attention DP size 1; enabled controls reject other scheduler loops.

The resource checks run before admission, following main's result-processing order. The token decision uses the pending prefill's `extend_num_tokens` plus the next chunk limit; equality permits overlap, while unknown bounds drain conservatively. A smaller actual batch or a blocked waiter can also drain before a step that ultimately decodes. Memory is sampled at the same preplanning boundary. Decode-to-decode overlap and existing synchronization barriers are unchanged.

`extend_num_tokens` excludes extra encoder SWA replay rows. These controls do not bound all forward work or guarantee a post-admission memory floor or OOM avoidance.

The reservation follows the scheduling work in #40024, #41273 and #39717; encoder replay accounting in #46063 is separate. Overlap controls are incorporated from #46112, which remains unchanged.
