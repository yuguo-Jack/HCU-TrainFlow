# [Fix] [Intel] cpu-kernel: Fix rope for VLA model

[Upstream PR](https://github.com/sgl-project/sglang/pull/40139) · state: open · merged: False

## Original PR description

## Motivation
`torch.ops.sgl_kernel.apply_rotary_pos_emb_cpu` kernel only takes 3D `[num_tokens, num_heads, head_size]` inputs and had no `unsqueeze_dim` argument. Pi0.5 calls it with 4D `[batch, num_heads, seq_len, head_size]` q/k and `unsqueeze_dim=1`, so it failed on CPU:

```
"/python/python/sglang/multimodal_gen/runtime/models/vlas/pi05_core.py", line 382, in forward
    query_states, key_states = native_apply_rotary_pos_emb(
  File "//lib/python3.10/site-packages/torch/_ops.py", line 1350, in __call__
    return self._op(*args, **kwargs)
RuntimeError: sgl_kernel::apply_rotary_pos_emb_cpu() expected at most 4 argument(s) but received 5 argument(s). Declaration: sgl_kernel::apply_rotary_pos_emb_cpu(Tensor query, Tensor key, Tensor cos, Tensor sin) -> (Tensor, Tensor)
```
- https://github.com/sgl-project/sglang/blob/main/python/sglang/multimodal_gen/runtime/models/vlas/pi05_core.py#L902C32-L902C59

## Modifications

- `apply_rotary_pos_emb_cpu` now takes `unsqueeze_dim` (default 1) and supports q/k of 3D and higher, with the head dim at `unsqueeze_dim` (e.g. `[B, H, S, D]` or `[B, S, H, D]`). It is out-of-place, matching `apply_rotary_pos_emb_native`.
- The neox rope path now handles float32 inputs, and the CPU graph fake op is updated for the new signature.

## Test Coverage

- pi0.5 model functionality

- `test_apply_rotary_pos_emb` in `test/registered/cpu/test_rope.py`. It compares against the native reference for:
  (1) 3D with GQA, 4D `[B, H, S, D]` with `unsqueeze_dim=1`, and (2) 4D `[B, S, H, D]` with `unsqueeze_dim=2`
