# [Feat] grpc: Advertise media inputs in GetServerInfo

[Upstream PR](https://github.com/sgl-project/sglang/pull/46882) · state: closed · merged: True

## Original PR description

## Motivation

Since #42833, tokens-in gRPC clients can send images, video and audio. They cannot tell which of these the server reads. Without awareness of the mode's multimodal capability, the model can drop the media and hallucinates answers. The client then gets an answer to a prompt without the media.

## Modifications

- `GetServerInfo` adds `grpc_features`: `image_inputs`, `video_inputs` and `audio_inputs`, one per placeholder token that the model's processor has. A client sends a media kind only when the list has it.
- `BaseMultimodalProcessor.mm_tokens` defaults to `None`, so a processor without these tokens lists none. LLaVA 1.5 and Whisper are examples.
- Only the gRPC leader adds the list. HTTP and follower metadata do not change, and the server-info parity test now checks that.

## Accuracy Tests

`Qwen/Qwen3-VL-2B-Instruct` over gRPC, through a client that sends a media kind only when `grpc_features` lists it (Dynamo's SGLang sidecar):

| Request | without this PR | this PR |
|---|---|---|
| `grpc_features` | absent | `["image_inputs", "video_inputs"]` |
| image URL or `data:` URI | refused by the client | 200, 1041 prompt tokens |
| video URL | refused by the client | 200, 2297 prompt tokens |
| audio | refused by the client | refused by the client, no `audio_inputs` |

Unit tests: `test_grpc_bridge.py` and `test_server_info.py` 41 passed. On main, the new checks fail with `KeyError: 'grpc_features'`.
