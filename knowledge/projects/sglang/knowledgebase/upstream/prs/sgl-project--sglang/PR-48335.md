# [Fix] HiSparse: use logical PD budgets and abort unsupported retraction

[Upstream PR](https://github.com/sgl-project/sglang/pull/48335) · state: open · merged: False

## Original PR description

## Motivation

HiSparse PD keeps the full target KV on the host and a sparse working set on the device. Two boundaries need to agree with that design:

1. The accepted prompt length and generation memory budget must use the full logical capacity rather than the smaller physical working set. For example, with 48,000 device slots and 384,000 logical slots, a 65,536-token prompt should not get its 64-token output budget clipped to zero solely because it exceeds 48,000.
2. A genuinely retracted HiSparse PD request cannot currently be restored by the generic decode backup path: its coordinator has released the sparse workspace and there is no complete host-KV/indexer/draft restoration implementation. Calling the unsupported backup path can raise instead of returning a request-level failure.

## Modifications

- Use the host-backed logical capacity for HiSparse PD prompt limits, retaining request-table capacity handling and existing hybrid-SWA behavior.
- Use `size_full` for the PD decode generation budget, retaining page alignment and reserve slack. Monolithic/prefill behavior and physical pool metrics are unchanged.
- Force the existing no-backup path for `HiSparseTokenToKVPoolAllocator` during PD retraction, clean up the request and report `SERVICE_UNAVAILABLE` instead of attempting an unsupported CPU backup or requeuing lost KV state.
- Return 503 for a HiSparse last-request OOM as well. Preserve ordinary decode backup/requeue and explicit no-offload/rebootstrap paths.

This does **not** implement resumable HiSparse retraction, raise the model context limit, or change the speculative decode-capacity check (that is a separate PR).

For non-streaming requests the error is HTTP 503. For an SSE stream whose HTTP response has already started, the response status cannot change: it emits an error event with code 503 and terminates with `[DONE]`, without reporting a successful finish. Previously emitted text is not recovered or resumed.
