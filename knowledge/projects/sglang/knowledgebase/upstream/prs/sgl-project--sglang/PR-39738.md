# [BugFix] Reset send_token_offset on input_embeds retract

[Upstream PR](https://github.com/sgl-project/sglang/pull/39738) · state: closed · merged: False

## Original PR description

## Motivation

Fixes #39645.

KV retract for `input_embeds` requests discards `output_ids` (the #14110 crash fix) but left `send_token_offset` and the sibling stream/detok cursors at the already-streamed length. The streamer then emitted `B[N:]`, so the client assembled `A[:N] + B[N:]` as one successful response.

## Modifications

In the `input_embeds` branch of `Req.reset_for_retract()`, reset `send_token_offset`, `send_decode_id_offset`, `send_output_token_logprobs_offset`, `send_output_sampling_mask_offset`, and the incremental detok sentinels (`surr_offset` / `read_offset`) after truncating `weight_version_events` with the pre-restart offset. Token-id retractions are unchanged.

CPU unit test covers cursor reset, streamer delivery of the full restarted generation, and the token-id control path.
