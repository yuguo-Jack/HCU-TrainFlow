# [Perf] runtime: Tune FlashInfer MoE tactics on distinct dummy tokens

[Upstream PR](https://github.com/sgl-project/sglang/pull/45543) · state: open · merged: False

## Original PR description

## Motivation

- FlashInfer's MoE autotune runs a decode dummy forward on zero-filled buffers
  ([`base_runner.py`](https://github.com/sgl-project/sglang/blob/1dd0f361b83a0f4c5fe917c37fc60525972c26e2/python/sglang/srt/model_executor/runner/base_runner.py#L392-L416)).
- Every row is token 0, so every row is routed to the same experts.
- FlashInfer tunes its MoE tactics on these repeated routes, a pattern real decode never produces.
- On Kimi-K3 (896 experts, top-16, EP8) the resulting picks are 13-16 % slower per MoE layer at 24-32 tokens,
  and the pick changes from launch to launch.

## Modifications

- `flashinfer_autotune.py`: `autotune_dummy_input_ids()` fills the static `input_ids` with seeded, distinct token ids
  for the tuning forward and zeroes them afterwards.
- `base_runner.py`: the decode tuning forward runs inside it.
- Unchanged: the other dummy buffers, the extend tuning pass, and the cache key and format (an existing cache is reused
  until it is retuned).

## Tests

Four CPU tests in `test/registered/unit/model_executor/runner/test_flashinfer_autotune_sync.py`:
- the tuned forward sees distinct in-vocab ids and the buffer is zero afterwards (fails without the change: `1 != 56`);
- every rank tunes on the same ids;
- the buffer is zeroed when the forward fails;
- more rows than the vocabulary stay in range.
