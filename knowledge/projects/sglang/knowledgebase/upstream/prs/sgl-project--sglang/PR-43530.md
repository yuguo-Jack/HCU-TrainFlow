# Adapt MegaMoE to upstream DeepGEMM APIs and optional weight localization

[Upstream PR](https://github.com/sgl-project/sglang/pull/43530) · state: open · merged: False

## Original PR description

## Summary

Upstream DeepGEMM introduces locality-aware MegaMoE scheduling and changes several interfaces and layout requirements used by SGLang.

This PR adapts SGLang's W4A8 MegaMoE path to those requirements and adds optional expert-weight localization before CUDA Graph capture. It also updates the DeepSeek V4 FP4 indexer calls for the upstream MQA API.

The PR remains a draft until GPU regression and end-to-end accuracy validation are complete.

## Planned work

- [x] Verify the actual DeepGEMM implementation and supported MegaMoE interfaces.
- [x] Add opt-in weight localization through
      `SGLANG_OPT_DEEPGEMM_MEGA_MOE_LOCALIZE_WEIGHTS`.
- [x] Keep routed and fused shared-expert weights consistent during localization.
- [x] Handle weight ownership, repeated preparation, and localizer cleanup.
- [x] Preserve ordinary weights when locality APIs or MLOPart are unavailable,
      or when the configuration is incompatible with localization.
- [x] Use the physical SM count for the upstream locality-aware scheduler,
      then restore the caller's SM budget.
- [x] Support compact and padded input-scale row strides.
- [x] Validate MegaMoE shapes against the two-CTA cluster alignment.
- [x] Support the positional-only upstream block-M query.
- [x] Adapt flat and paged FP4 indexer calls to the upstream MQA signatures.
- [ ] Validate execution with physically localized weights on a supported
      MLOPart configuration.
- [ ] Rerun GPU regression on the current branch and Python 3.10 environment.
- [ ] Validate complete prefill/decode disaggregation and GSM8K accuracy.
- [ ] Measure latency, throughput, and memory usage before enabling
      localization by default.

W4A4 MegaMoE (`mxf4xmxf4`) support is deferred. The current upstream
DeepGEMM build does not provide that path.

## Development steps

### 1. Establish API and capability compatibility

Inspect the imported DeepGEMM module and probe supported MMA types and
locality interfaces. Use interface capabilities rather than package
version metadata to determine compatibility.

For the FP4 indexer, distinguish the legacy signatures containing
`clean_logits` from the upstream signatures using `max_seqlen_k` and
optional metadata.

### 2. Prepare weights before graph capture

Add `prepare_mega_moe_locality(model)` after expert and shared-expert
weight preparation.

Localize routed L1/L2 weights and any fused shared L1/L2 weights. Preserve
the existing scale tensors and their UTCCP layout. Prepare a complete
layer before updating its weight references.

### 3. Manage ownership and failure handling

Update the expert parameters to reference the localized weight storage.
Avoid retaining duplicate routed-expert weight buffers and make
preparation idempotent.

Synchronize outstanding copies before releasing the localizer, including
error paths. Skip localization when EPLB requires the ordinary layout,
when the MMA type is unsupported, or when locality capability is absent.

### 4. Align scheduler configuration and layouts

Run buffer creation, block-M queries, and MegaMoE execution under the
appropriate SM configuration. Restore the previous process-wide SM
budget on both success and failure, and include the effective SM count
in the buffer cache key.

Update pre-dispatch to use the actual scale row stride while retaining
base-pointer alignment and minimum row-width checks.

Accept shapes satisfying `hidden_size % 256 == 0` and
`moe_intermediate_size % 128 == 0`. These shape checks do not imply that
dual-domain scheduling is enabled.

### 5. Update indexer calls

Adapt flat and paged FP4 MQA calls to both upstream and legacy argument
layouts. Verify argument positions, output dimensions, and int32 sequence
length conversion.

### 6. Complete correctness and performance validation

Run CPU regression, real GPU pre-dispatch tests, distributed MegaMoE
forward checks, and CUDA Graph capture/replay.

Then validate the complete PD service with 200 GSM8K questions and require
accuracy strictly above 0.88. Compare ordinary and localized weights for
latency, throughput, and memory usage where localization is available.

## Validation status

Completed:

- 26 CPU tests passed in the current Python 3.10 environment:
  14 MegaMoE API tests, 10 locality lifecycle tests, and 2 indexer ABI tests.
- Earlier GPU validation passed both 72-byte and 80-byte scale-row cases.
- Earlier four-rank W4A8 validation passed routed/shared execution and
  CUDA Graph replay for H/I = 512/512, 2304/1536, and 5120/1536.

Limitations:

- CPU locality and ABI tests use mocked DeepGEMM interfaces.
- Earlier GPU results used ordinary weights and precede the branch migration.
- MLOPart was unavailable in the earlier GPU configuration, so physical
  weight localization has not been validated.
- Complete PD/GSM8K validation and performance comparisons are pending.
- No performance improvement is claimed by this draft.
