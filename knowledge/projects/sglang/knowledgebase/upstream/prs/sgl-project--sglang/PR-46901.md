# [Fix] [AMD] sgl-kernel: honor an explicit AMDGPU_TARGET over GPU autodetection

[Upstream PR](https://github.com/sgl-project/sglang/pull/46901) · state: open · merged: False

## Original PR description

## Motivation

`python/sglang/kernels/aot/setup_rocm.py` reads `AMDGPU_TARGET`, but then overwrites it with the arch of GPU 0 whenever `torch.cuda.is_available()`:

```python
amdgpu_target = os.environ.get("AMDGPU_TARGET", default_target)
if torch.cuda.is_available():
    amdgpu_target = torch.cuda.get_device_properties(0).gcnArchName.split(":")[0]
```

So on any machine with a GPU, an explicit target is ignored without a warning. Building for gfx942 on an MI355X host produces a gfx950-only kernel, exits 0, and the wheel installs and imports cleanly. The mismatch only shows up on the target GPU.

GPU-less builders, such as the Docker builds that pass `AMDGPU_TARGET=$GPU_ARCH_LIST`, never hit this because they take the `else` branch. The developer building on a workstation does hit it. The same fix is already on `amd_march` as part of #44308; this PR is just that behaviour, kept minimal for `main`.

## Modifications

- Autodetect only when `AMDGPU_TARGET` is unset or empty.
- When it is set, use it and print that it came from the environment.
- If detection fails, fall back to the default target as before, and say so in the warning.

Nothing changes when `AMDGPU_TARGET` is unset. That covers the AMD CI kernel build (`amd_ci_install_dependency.sh` runs `python3 setup_rocm.py install` without it), so CI behaviour is unchanged.

## Accuracy Tests

This is build-only; no kernel or model code changed. Each row is one `setup_rocm.py build_ext --inplace` in `rocm/pytorch:rocm7.2.3_ubuntu24.04_py3.12_pytorch_release_2.10.0` on an MI355X host. The arch is read back from the built `common_ops*.so` with `llvm-objdump --offloading` (run on a copy, since it extracts the bundles next to its input).
