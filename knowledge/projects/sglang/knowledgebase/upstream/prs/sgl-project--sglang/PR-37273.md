# [Feat] scheduler: Add opt-in DP-attention phase lockstep

[Upstream PR](https://github.com/sgl-project/sglang/pull/37273) · state: open · merged: False

## Original PR description

## Motivation

Under DP attention the per-pass cuda-graph votes are all-or-nothing: the decode graph needs every rank decode-or-idle and the prefill graph needs every rank extend-or-idle, so any mixed decode+extend pass runs eager on every rank. On long-prefill/long-decode traffic this leaves ~60% of prefill passes eager even with `--enable-prefill-delayer`.

## Modifications

Adds `--enable-dp-phase-lockstep` (default off) by reusing the speculative-decoding path's prefill-first synchronization for non-speculative serving. The collective sees admitted prefill batches. If any rank has prefill, ranks without it idle; otherwise all ranks proceed to decode.

The optimistic prefill-delayer vote can still be followed by a failed admission. Using the admitted batch avoids freezing decode when every request was rejected. No new negotiation fields or chunk-admission changes are needed.

The option is appended to the positional argument list so existing `ServerArgs(...)` calls retain their meaning.

This adds a prefill synchronization before decode-only passes when enabled. The option remains inert without the prefill delayer, under speculative decoding, when `SGLANG_SCHEDULER_SKIP_ALL_GATHER` is set, and at dp=1.

When MAX_LEN padding turns an idle rank into one bucket-sized request, every rank now includes that dummy request in the prefill graph context and sequence-limit checks. If the padded idle request exceeds either limit, all ranks fall back to eager together.

## Validation

The scheduler, admission, and DP-attention suites passed **79 tests and 72 subtests**, including the existing distributed gather test. The compact scheduler regression checks admitted local/remote prefills and continued decoding after an optimistic vote rejects all requests; it fails on the previous implementation and passes with this change.

The server-argument reference documents the flag and its prerequisites. After merging main `af98fcd545`, the scheduler gate, server-argument, documentation-coverage, and distributed prefill-delayer tests passed: **359 tests and 217 subtests**.

The replay-decision regression reproduces the previous `[True, False]` rank split when an 8192-token dummy request exceeds the 4096-token per-request limit. With the fix, the focused prefill-graph, scheduler, MLP-padding, and DP-attention CPU suites pass **46 tests and 23 subtests**, including coverage for both context bounds and the valid replay boundary. After merging main `b702f0d80e`, the focused scheduler-gate and prefill-graph suites pass **16 tests and 19 subtests**. Distributed GPU replay and asymmetric sustained-traffic fairness remain unvalidated; no new GPU experiments were run.

## 1. [P1] Preserve the shared graph decision when lockstep idles a decoding rank

**Location:** [`scheduler.py:4174–4184`](https://github.com/sgl-project/sglang/blob/a15c28903e116ea8b875188367d64369adde4228/python/sglang/srt/managers/scheduler.py#L4174-L4184).

The new prefill-first synchronization can replace a runnable decode batch with an idle batch whose padded representation fails the prefill graph's sequence-length limit, even though every rank voted for graph replay.

A concrete configuration is two attention-DP ranks, non-speculative serving, the prefill delayer, breakable prefill graphs, capture token buckets `[8, 8192]`, and `--cuda-graph-max-seq-len-prefill 4096`. Use sufficient local prefill budget and model/request-table capacity for 8192 tokens. The decoding rank must satisfy the existing decode-to-extend eligibility conditions, including no A2A backend, CP, TBO, SSM, grammar, beam, or logprob restriction.

On one pass:

- Rank 0 admits two 4096-token prompts: 8192 aggregate tokens, with a maximum per-request sequence length of 4096.
- Rank 1 has eight runnable decode requests with sequence length 64 and no admitted prefill.

Capture token buckets and the per-request sequence limit are independent, so the two-prompt prefill batch is valid under this configuration. See the [graph configuration definitions](https://github.com/sgl-project/sglang/blob/a15c28903e116ea8b875188367d64369adde4228/python/sglang/srt/model_executor/cuda_graph_config.py#L70-L116).

With lockstep disabled, the existing [decode-to-extend conversion](https://github.com/sgl-project/sglang/blob/a15c28903e116ea8b875188367d64369adde4228/python/sglang/srt/managers/scheduler_components/dp_attn.py#L777-L808) lets rank 1 participate using its real sequence lengths. Both ranks remain eligible for replay.

With lockstep enabled:

1. Rank 1 submits `None` to the early synchronization and receives idle. The [schedule-time prefill graph vote for `None` or idle is unconditionally true](https://github.com/sgl-project/sglang/blob/a15c28903e116ea8b875188367d64369adde4228/python/sglang/srt/managers/scheduler_components/dp_attn.py#L394-L403).
2. DP padding selects the shared 8192-token bucket and fabricates **one dummy request with sequence length 8192** on rank 1. See [bucket selection](https://github.com/sgl-project/sglang/blob/a15c28903e116ea8b875188367d64369adde4228/python/sglang/srt/model_executor/forward_batch_info.py#L1865-L1880) and [dummy-request construction](https://github.com/sgl-project/sglang/blob/a15c28903e116ea8b875188367d64369adde4228/python/sglang/srt/model_executor/forward_batch_info.py#L1942-L1981).
3. The runner [rechecks the maximum sequence length after padding](https://github.com/sgl-project/sglang/blob/a15c28903e116ea8b875188367d64369adde4228/python/sglang/srt/model_executor/runner/prefill_cuda_graph_runner.py#L1557-L1590). Rank 0 passes with 4096; rank 1 [fails the 4096 limit](https://github.com/sgl-project/sglang/blob/a15c28903e116ea8b875188367d64369adde4228/python/sglang/srt/model_executor/runner/prefill_cuda_graph_runner.py#L1519-L1524) because its synthetic request has length 8192.

The isolated reproduction produced:

| Setting | Schedule-time graph votes | Rank 1 after padding | Final replay decisions |
|---|---|---|---|
| Lockstep disabled | `[True, True]` | Eight real requests; maximum sequence length 64 | `[True, True]` |
| Lockstep enabled | `[True, True]` | One dummy request; sequence length 8192 | `[True, False]` |

Both cases have padded global token counts `[8192, 8192]`. The resulting replay/eager split violates the shared collective contract and can hang: graph capture enables PyNccl, while eager all-gather can use the torch device-group communicator. See [capture communicator selection](https://github.com/sgl-project/sglang/blob/a15c28903e116ea8b875188367d64369adde4228/python/sglang/srt/distributed/parallel_state.py#L649-L686) and [all-gather dispatch](https://github.com/sgl-project/sglang/blob/a15c28903e116ea8b875188367d64369adde4228/python/sglang/srt/distributed/parallel_state.py#L1349-L1359).

The dummy-padding weakness already exists for naturally idle ranks on the base. **This change exposes it to a previously valid step with runnable decoding work.**

**Suggested fix:** preserve a shared replay decision after accounting for the padded idle representation. Construct dummy-request geometry that respects the captured context and request-slot bounds, or make all ranks fall back together when that representation cannot replay. Add a regression covering aggregate prefill tokens greater than the per-request replay limit. Bypassing the limit for idle requires care because captured backend metadata can depend on that bound.

**Validation:** reproduced the eligibility split using the actual voting, forward-padding, and runner method bodies extracted from the reviewed source, with tensor operations and runtime/model services stubbed for CPU execution. Scheduler selection was traced in source. No distributed GPU execution or hang was reproduced.

## Follow-up: decode fairness and current-head performance

With `prefill_decode_interval=0`, sustained prefill traffic on one rank can repeatedly suppress another rank's decode work. For example, a rank serving short, one-output requests can remain below the prefill-delayer token watermark and receive prefill permission every iteration. Lockstep then keeps a peer with long-running decode requests idle. The [low-watermark release path](https://github.com/sgl-project/sglang/blob/a15c28903e116ea8b875188367d64369adde4228/python/sglang/srt/managers/prefill_delayer.py#L323-L350) and the new phase-selection branch provide no bound on that peer's decode wait.

This follows the selected global prefill-first policy, so I am treating it as a workload/fairness concern rather than a third confirmed correctness finding. Please include asymmetric sustained traffic in current-head benchmarks and report p99/max inter-token gaps and per-request progress. The existing [`--prefill-decode-interval` mechanism](https://github.com/sgl-project/sglang/blob/a15c28903e116ea8b875188367d64369adde4228/python/sglang/srt/managers/scheduler.py#L1444-L1476), with its minimum-batch threshold set to zero, is relevant to that evaluation.

The throughput results in the PR description are explicitly from the earlier negotiation-based implementation. This revision adds a synchronization before decode-only passes; its performance should be measured against the current base, which already supports eligible decode-to-extend conversion.

**[bug]** `prefill_in_flight` is `self.chunked_req is not None` at executor construction, before `PrefillAdder.add_chunked_req`. Hybrid SWA already parks a chunk when `rem_swa_tokens <= page_size`: `add_chunked_req` returns the req unchanged, does not append it to `can_run_list`, and returns before the delayer negotiate (`schedule_policy.py:1019-1021`, covered by `test_add_chunked_req_hybrid_swa_defers_when_swa_below_page`). `chunked_req` stays set, so every rank's gather sees field 5 and `is_phase_prefill` becomes true. The parking rank then has `new_batch is None` and lockstep replaces decode with an idle batch (`scheduler.py:3306-3312`). Decode is what frees SWA capacity, so the same park repeats and the cluster idles indefinitely. The PR claim that divergence only costs cuda-graph hits does not hold here: this is a stall, not mixed eager. The existing scheduler already treats this park as a real state (`scheduler.py:3226-3229`).

**[P1] An optimistic prefill vote can suppress decode indefinitely**

**Location:** [`[scheduler.py:3746–3752]`](https://github.com/sgl-project/sglang/blob/23cd081b24dfc2f542cc439b8326b7433e4077b2/python/sglang/srt/managers/scheduler.py#L3746-L3752), using [`[prefill_delayer.py:403–411]`](https://github.com/sgl-project/sglang/blob/23cd081b24dfc2f542cc439b8326b7433e4077b2/python/sglang/srt/managers/prefill_delayer.py#L403-L411).

The new idle injection assumes that `delayer_phase_prefill=True` means some rank will actually execute prefill. That implication is still false for **new-request admission**: a request can vote `local_prefillable=True`, receive permission, and then fail a subsequent admission check.

There is a deterministic trigger with ordinary fixed-pool serving; it does **not require unified memory or SWA**:

- DP attention, the prefill delayer, and phase lockstep enabled.
- `--enable-mixed-chunk` and `--disable-radix-cache`.
- Queued requests with `ignore_eos=True`.
- On each rank, a running batch that consumes the entire chunk budget, while request slots and KV capacity remain available—for example, 512 running requests, chunk size 512, and local request capacity 1,024.

The failure sequence is:

1. **Mixed-chunk scheduling reserves the chunk budget for existing decode requests.** `PrefillAdder` subtracts `num_mixed_decode_tokens` from `rem_chunk_tokens`, leaving zero in this example. See [`[schedule_policy.py:647–657]`](https://github.com/sgl-project/sglang/blob/23cd081b24dfc2f542cc439b8326b7433e4077b2/python/sglang/srt/managers/schedule_policy.py#L647-L657).

2. **The new request votes prefillable before checking that remaining budget.** With radix caching disabled, `ignore_eos=True` selects `add_one_req_ignore_eos()`. Its memory checks can pass, after which it negotiates with `local_prefillable=True`. With every rank voting true and enough free request slots, the delayer allows prefill. See [`[schedule_policy.py:1266–1275]`](https://github.com/sgl-project/sglang/blob/23cd081b24dfc2f542cc439b8326b7433e4077b2/python/sglang/srt/managers/schedule_policy.py#L1266-L1275).

3. **Admission then rejects the request.** The later `rem_chunk_tokens <= 0` check returns `AddReqResult.OTHER`, without adding anything to `can_run_list`. See [`[schedule_policy.py:1316–1318]`](https://github.com/sgl-project/sglang/blob/23cd081b24dfc2f542cc439b8326b7433e4077b2/python/sglang/srt/managers/schedule_policy.py#L1316-L1318).

4. **Lockstep turns every rank’s decode into idle.** `finalize(actual_prefill_bs=0)` leaves the negotiated phase unchanged. The new scheduler condition injects an idle batch, bypassing `update_running_batch()`. Because no decode progresses, the running batch cannot shrink and free chunk budget. The same state repeats. The delayer’s timeout does not help because it is already allowing prefill on every pass.

### Reproduction

I reproduced this control flow using the reviewed commit’s admission, negotiation, phase-executor, and scheduler method bodies, with distributed/GPU operations and unrelated scheduler services stubbed:

| Setting | Scheduler passes | Idle batches selected | Calls to `update_running_batch()` |
|---|---:|---:|---:|
| Lockstep disabled | 100 | 0 | 100 |
| Lockstep enabled | 100 | 100 | 0 |

In both cases, admission returned `OTHER` and the delayer reported `no_wait / phase_prefill=True`. Enabling lockstep alone removed all decode progress.

**Suggested fix:** Move the nonpositive chunk-budget rejection ahead of the prefillable vote in this path. More generally, audit post-vote rejection paths so the phase verdict guarantees executable prefill work before it suppresses decoding. Add a regression that connects actual admission failure to the scheduler decision; the current tests check those pieces separately.

A local `actual_prefill_bs == 0` override is insufficient on its own, because another rank may have admitted real prefill and still require coordinated idling.
