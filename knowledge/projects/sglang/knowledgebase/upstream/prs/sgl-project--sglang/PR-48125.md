# [Feat] unified_cache: Support MiniMax-M3.1 in the direct external linker

[Upstream PR](https://github.com/sgl-project/sglang/pull/48125) · state: closed · merged: True

## Original PR description

## Motivation

`--enable-unified-cache-external-linker` failed at startup on MiniMax-M3.1: the MiniMax sparse strategy had no direct-linker pool group.

## Modifications

- `_MiniMaxSparseStrategy.build_direct_linker_pool_group` builds three entries over the M3.1 NVFP4 pools:
  - `KV`: one main-KV page row per layer (NVFP4 K/V payloads and block scales).
  - `INDEXER`: one index-K page row per sparse layer (payload and scales), addressed by the KV page.
  - `DRAFT`: the DSpark / DFlash draft KV, reusing the sidecar draft entry from the FULL + MAMBA path (factored into `_sidecar_draft_entries`).
- bf16 MiniMax sparse pools, HiSparse and packed draft KV are rejected with an explicit error.

File: `python/sglang/srt/mem_cache/hybrid_cache/linker_pool_assembler.py` · line 636

🟡 (optional) When a sidecar draft pool has more layers than the local main KV pool, its extra layers are never transferred or are rejected. `num_layers` is fixed to `main_pool.layer_num` at linker_pool_assembler.py:636. The `DRAFT` entry maps draft layer i to transfer layer i for every `range(draft_pool.layer_num)`. The Mamba builder this code was split from sizes the group with `max(layer_mapping)+1` so draft layers are always covered. Fix: compute the group size from the largest layer key across all entries (as `_build_mamba_device_pool_group` does), or reject `draft_pool.layer_num > main_pool.layer_num` with a clear error.

<details>
<summary>Why this was flagged</summary>

The trigger needs a sidecar draft pool (DSpark/DFlash) whose `layer_num` is larger than the stage-local `main_pool.layer_num`. That can happen with pipeline parallelism, where `main_pool.layer_num` counts only the stage's own layers. `_sidecar_draft_entries` (linker_pool_assembler.py:576) maps draft layers `0..draft_pool.layer_num-1` onto transfer layers. The new builder still passes `DevicePoolGroup(entries, main_pool.layer_num, page_size)` at :636. In that case `MooncakeDirectLinker` loops only over `range(self.num_layers)` (mooncake_direct_linker.py:261/334), so the higher draft layers are never saved or restored. A restore then leaves stale draft KV, so speculative acceptance diverges without any error. `UMBPDirectLinker` checks `0 <= layer < self.num_layers` (umbp_direct_linker.py:188) and fails at startup instead. The FULL + MAMBA path avoids this by sizing with `max(...) + 1` at :560.

**Verification:** nit. Trigger: a sidecar DSpark draft pool with more layers than the stage-local MiniMax NVFP4 main pool, possible with PP>1 DSpark in PD prefill (speculative_hook.py:716-721). The new builder fixes the group size at main_pool.layer_num (linker_pool_assembler.py:636). Mooncake never loads draft layers beyond it (mooncake_direct_linker.py:334), and UMBP fails at startup (umbp_direct_linker.py:187-198).

</details>
