# [Feat] scheduler: add optional consecutive-prefill resource budgets

[Upstream PR](https://github.com/sgl-project/sglang/pull/46112) · state: open · merged: False

## Original PR description

Continued in #47308, which incorporates these overlap controls together with mixed-prefill reservation and additional scheduler-mode validation. The original proposal and focused tests are retained here for review history.

## Motivation

Two consecutive prefill batches can overlap their temporary workspaces even when each batch fits on its own. Add two opt-in limits: combined new tokens, and minimum free GPU memory across the TP group. Both default to disabled; decode overlap is unchanged.

The memory probe keeps allocator caches intact. Attention DP > 1 is rejected at startup when either limit is enabled, since rank-local prefill decisions need a different consensus protocol. The K3 cookbook documents the knobs and throughput tradeoff.

## Test Plan

Focused CPU regressions cover the token boundary, disabled defaults, decode/first-batch behavior, TP-minimum memory probe and attention-DP startup rejection. The actual scheduler methods were exercised against the published runtime context; only the external memory probe was replaced. These checks pass. Full distributed scheduling and model throughput remain to be validated in upstream CI.

Ruff/isort formatting and focused lint checks pass. No production service changes.
