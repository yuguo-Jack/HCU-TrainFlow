# [Doc] [NPU] cookbook: Add Ascend A3 deployment scenarios for DeepSeek-R1 (W4A8)

[Upstream PR](https://github.com/sgl-project/sglang/pull/46266) · state: closed · merged: False

## Original PR description

## Motivation

Add the Ascend A3 deployment scenarios requested in Ascend/sglang#1206 to the DeepSeek-R1 Cookbook, so you can select a scenario and get the matching launch command: one complete A3 server with PD co-located, or two A3 servers with PD disaggregated (Prefill, Decode and Router).

This change depends on #46265 (grouped ModelSlim W4A8 loading fix). Without it, this checkpoint does not produce valid output on current `main`.

## Modifications

- Add an `Ascend A3` hardware option to the existing Basic Configuration selector with two scenarios: 1×A3 with PD co-located, and 2×A3 with PD disaggregated (Prefill, Decode and Router roles). The generated commands follow the [official R1 W4A8 best practices](https://github.com/sgl-project/sglang/blob/main/docs/docs/hardware-platforms/ascend-npus/model-deployment/best-practices/deepseek_r1.mdx) and use Cookbook ports (30000 for servers, 6688 for the Router). Host-specific values are placeholders: `<network-interface>`, `<prefill-ip>`, `<decode-ip>` and the model path.
- Add the A3 content to the sections the page already uses: `3.4 Ascend A3 deployment` (prerequisites, checkpoint, host tuning, network variables), `4.3 Verify the Ascend A3 service` (Router check and a request), and `5.3 Ascend A3 benchmarks` (the performance and GSM8K commands).
- Add generator tests for the A3 roles to the docs CI entry.

Three documentation files change: the R1 page, its existing selector component and the generator tests. No inference-runtime change.

## Accuracy Tests

Atlas 800T A3 x2 (driver 26.1.1, firmware 9.0.0.9.220), CANN 9.1.0, torch/torch_npu 2.10.0, MemFabric 1.2.1, Router 0.3.2, image `quay.io/ascend/sglang:main-cann9.1.0-a3` (manifest `sha256:9e653832d34f058a0035b5009fe8efcd61358c72fec5cf7412df7a236ff544ae`), SGLang `bb72b47` + #46265, checkpoint revision `8c4f13004d0742b650b9f2c51b751dbef7d0c1ee`.

Full GSM8K test set (1319 questions, `sgl-eval==0.1.3`, thinking on, 16384 output tokens, temperature 0.6, top-p 0.95, seed 1, concurrency 64, context length 32768):

| Deployment | Correct | Score | Request errors |
| --- | --- | --- | --- |
| 1×A3, PD co-located | 1257/1319 | 95.30% | 0 |
| 2×A3, PD disaggregated | 1256/1319 | 95.22% | 0 |

The commands the page generates were launched unchanged on this setup (co-located, Prefill, Decode and Router). Functional checks (plain, streaming, multi-turn and 4 concurrent chat requests) passed for both deployments. For PD, the Router listed one healthy prefill and one healthy decode worker.

## Speed Tests and Profiling

Three consecutive runs of the best-practice benchmark against one running service, with no restart or tuning between runs. Mean TPOT per run:

| Deployment | Run 1 | Run 2 | Run 3 | Average | Reference |
| --- | --- | --- | --- | --- | --- |
| Co-located (896 req, concurrency 224) | 50.77 | 53.06 | 54.13 | 52.65 ms | 50 ms |
| PD (1664 req, concurrency 416, 24 req/s) | 47.88 | 46.17 | 46.27 | 46.77 ms | 50 ms |

All 7680 measured requests completed. PD is below the reference in every run, and co-located averages slightly above it. The reference defines no multi-run aggregation rule.
