# [Fix] api: Enforce integer ranges in generated Python types

[Upstream PR](https://github.com/sgl-project/sglang/pull/46568) · state: open · merged: False

## Original PR description

## Motivation

The generated Python JSON decoders accept integers outside their protobuf widths, while Rust's fixed-width deserializers reject them. This creates an acceptance mismatch in the shared `sglang.api.v1` contract.

Examples include:
- `SamplingParams.max_new_tokens = 2**63`
- `GenerateMetaInfo.prompt_tokens = 2**32`
- `GenerateMetaInfo.completion_tokens = 2**64`

## Modifications

- Enforce signed and unsigned bounds for i32, i64, u32, and u64 in the Python scalar validators.
- Pass integer width explicitly, independently of error descriptions used by one-or-many carriers.
- Apply scalar validation to untagged union arms, including `Matched`.
- Preserve boolean rejection, null/default handling, and tagged-union passthrough behavior.
- Regenerate `python/sglang/api/v1/api_types.py` using `cargo gen-api`.
- Add generator, Rust API, and registered Python CPU regression tests covering boundaries, overflow, scalar fields, lists, nested lists, tuples, and unions.

## Accuracy Tests

CPU-only JSON contract validation:

- Rust tests: `cargo test --locked -p sglang-api-codegen -p sglang-api-types` from `rust/`: 31 tests passed.
- Direct Python decoder checks: 38 shared JSON fixtures round-tripped successfully; 10 valid boundaries were accepted and 15 invalid integer/boolean inputs were rejected.
- Scoped Clippy: `cargo clippy --locked -p sglang-api-codegen -p sglang-api-types --all-targets -- -D warnings` from `rust/`: passed.
- Formatting, lint, and CI registration checks passed.
- Repeated `cargo gen-api --locked` produced byte-identical generated files.

The committed Python test entry point using `CustomTestCase` still requires validation in the full SGLang test environment.

## Speed Tests and Profiling

Inference benchmarks and GPU profiling were not run.
