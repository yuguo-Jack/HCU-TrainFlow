# [Fix] Qwen 3.8 next: Stop retaining per-size PLE outputs in breakable prefill CUDA graphs

[Upstream PR](https://github.com/sgl-project/sglang/pull/44150) · state: open · merged: False

## Original PR description

## Summary

During breakable prefill CUDA graph capture, `eager_on_graph` keeps a strong reference to each eager break's return value so replay can copy fresh output into it. That return value is allocated outside the graph pool, so a break that returns a newly allocated tensor keeps one buffer per captured size for the lifetime of the graphs.

`_breakable_ple_forward` returned a fresh `[num_tokens, hc_count * hidden_size]` tensor, so the PLE layer retained one such buffer for every prefill capture size. With the default prefill capture sizes up to 16384 tokens this adds up to several GiB per GPU, while only the largest size can ever be live.

Use the output-argument pattern already used by `breakable_unified_attention_with_output` and the DSA indexer: `_add_ple_embedding` allocates the output inside the captured segment, from the graph pool, and the eager break writes `residual + ple(...)` into it in place and returns nothing. Graph-pool memory is then reused across capture sizes, and the residual add no longer needs a second graph-pool tensor.

## Memory impact

Measured on 4x B200 with a Qwen4 PLE model at TP4 using breakable prefill CUDA graphs (74 capture sizes up to 16384 tokens), identical launch configuration for both runs; only this change differs. Per GPU (all four ranks consistent):

| | Before | After | Change |
|---|---|---|---|
| Target prefill CUDA graph capture | 14.59 GB | 8.42 GB | **-6.17 GB** |
| Device memory used after startup | 167,601 MiB | 161,549 MiB | **-5.91 GiB** |

The removed retention matches the PLE output size summed over all capture sizes (296,032 tokens x 20,480 B = 5.65 GiB). KV and Mamba cache sizes are unchanged because they are sized before graph capture; the freed memory is left free at startup.

## Validation

- Greedy generation (64 tokens) for prompts of 43, 395, 1931, 7051 and 16651 tokens, cache flushed before each request, with output logprobs, compared against three independent runs of the unchanged code.
  - 43, 395 and 1931 tokens: all 64 output tokens identical and logprob differences exactly 0 against every baseline run.
  - 7051 and 16651 tokens: the unchanged code already diverges between its own runs (first differing token 5-16, max logprob difference up to 0.66); this change stays within that range.
- All applicable pre-commit hooks pass.
