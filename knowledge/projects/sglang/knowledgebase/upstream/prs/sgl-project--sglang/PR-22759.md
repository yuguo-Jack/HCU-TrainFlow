# [1/N][HiCache PP]: use logical clock for deterministic LRU eviction across PP ranks

[Upstream PR](https://github.com/sgl-project/sglang/pull/22759) · state: closed · merged: False

## Original PR description

Replace time.monotonic() with a logical batch-step counter for last_access_time in PP>1 mode. This makes both GPU and host eviction fully deterministic across PP ranks, preventing host-tree divergence that causes deadlocks and shape-mismatch crashes.

Problem: In PP mode, each rank calls match_prefix/insert independently, stamping nodes with wall-clock time.monotonic(). Micro-timing differences cause LRU priorities to diverge, so ranks evict different nodes, leading to host-tree inconsistency, prefetch shape mismatches, and deadlocks.

Hi @xiezhq-hermann, addressed in the latest push:

Main fix: get_access_time() on RadixCache now post-increments the logical clock on every call, so each match_prefix/insert within the same batch gets a distinct tick — no more same-time indeterminism. The per-batch inc_logical_clock() and its scheduler call are removed.
Cleanup: removed all remaining wall-clock leaks from LRU/FIFO ordering — TreeNode.last_access_time / creation_time default to 0.0 and every TreeNode(...) creation site (including lmc_radix_cache.py) now assigns a logical tick. Dropped the duplicate clock and get_access_time override on HiRadixCache.
PP>1 tie-breaker hardening: added an iterative _ensure_node_hash_values() so chained content hashes are always parent-rooted (with descendant recompute when an ancestor was missing); non-root evict candidates without a hash now raise RuntimeError (preserved under python -O).
