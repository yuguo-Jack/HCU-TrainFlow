# [Feat] sail: support PLA recurrent linear attention fast paths [5/N]

[Upstream PR](https://github.com/sgl-project/sglang/pull/48371) · state: open · merged: False

## Original PR description

## Motivation

Part 5 of the SAIL upstreaming series, following [2/N] [#43826](https://github.com/sgl-project/sglang/pull/43826) (platform support), [3/N] [#45946](https://github.com/sgl-project/sglang/pull/45946) (fa3 + flashmla) and [4/N] [#47588](https://github.com/sgl-project/sglang/pull/47588) (DeepGEMM GEMM/MoE).

> [!IMPORTANT]
> **This branch is stacked on #47588's head.** Until #47588 lands, the diff shown here also carries its 76 files; once #47588 merges into `main`, GitHub recomputes the base and this PR shrinks to the 23 files it actually touches. Review it together with #47588 and merge it second. If #47588 goes in as a squash, the top five commits need one more rebase onto the new `main` before this PR's diff collapses.

T-HEAD SAIL ships `pla`, a PPU linear-attention kernel library in its own wheel. Every recurrent step the KDA / GDN paths need exists there as a single fused kernel, but none of it is reachable from SGLang:

- GDN and KDA recurrent decode run the Triton kernels (`fused_sigmoid_gating_delta_rule_update` and the packed `..._k_last_packed` variant). PLA exposes the same math in one call with the KDA gate lower bound folded in, and accepts the width-major conv pools PPU keeps.
- KDA prefill/extend goes through the kernel dispatcher's FlashKDA slot. On SAIL that slot has no fused implementation, and the prefill default never selected it; on top of that the mamba track path asked for per-chunk states unconditionally, which is the one thing a PLA-style extend kernel cannot emit.
- KDA speculative verify/commit (ReplaySSM) has no fused path for the state pool PPU allocates, so the accepted window is folded and the conv rolled back by a chain of Triton scatters. On HGGC that chain also faults: a combined `&` bounds check is not lowered into real branches, and a masked load without `other=` lets masked-out lanes touch out-of-range addresses.
- Kimi-K3's fused decode is hard-coded to the CUDA TP8 layout (12 local heads, `A_log.numel() == 12`), so a PPU TP layout never qualifies.
- Under `--disable-overlap-schedule`, `--mamba-radix-cache-strategy auto` decided "not paged" for a FlashMLA hybrid model, because the mamba pass runs before the pass that snaps the page size to 64.

This PR wires those kernels in behind one gate and leaves the community Triton kernels as the fallback for every batch PLA cannot take.

## Modifications

### 1. The gate and the dependency

- `srt/environ.py`: declares `SGLANG_SAIL_PLA` (`EnvBool(False)`), the only PLA knob in this PR.
- `srt/arg_groups/platform_hook.py`: `handle_sail_backends` probes `import pla`. Present and not explicitly set, the gate turns on, so PLA is the default on a SAIL install. Missing, it logs a warning and forces the gate off, because a PLA-less PPU install is a supported setup. An explicit `SGLANG_SAIL_PLA=0` opts out everywhere.
- `pyproject_other.toml`: adds `pla` to the `srt_sail` extra.

### 2. The vendor code lives under `hardware_backend/sail/`

Six new modules plus a package `__init__`; nothing existing moves.

| File | Purpose |
| --- | --- |
| `srt/hardware_backend/sail/kernels/kda.py` | The only place that imports `pla`. Wraps fused decode, recurrent decode/verify, packed decode, FlashKDA-style prefill and the DSpark MTP kernel, and owns the coverage predicates. |
| `srt/hardware_backend/sail/attention/kda_triton.py` | `SailTritonKDAKernel`: `packed_decode` / `decode` / `target_verify` redirected to PLA, falling back to `super()` per call. |
| `srt/hardware_backend/sail/attention/gdn_triton.py` | The same three slots for GDN. |
| `srt/hardware_backend/sail/attention/kda_flashkda.py` | `SailFlashKDAKernel`: same extend contract, PLA launch, and the CUDA-only sequence-length window dropped. |
| `srt/hardware_backend/sail/attention/kda_backend.py` | `SailKDAKernelDispatcher`, `SailKDAAttnBackend`, and the per-runner `sail_pla_prefill_default`. |
| `srt/hardware_backend/sail/attention/gdn_backend.py` | `SailGDNKernelDispatcher`, `SailGDNAttnBackend`. |

Each kernel falls back to the inherited community implementation when `SGLANG_SAIL_PLA` is off or the batch does not fit the operator, so a SAIL run with the gate closed behaves like upstream.

### 3. Community files keep only subclass hooks

- `srt/layers/attention/linear/kda_backend.py`: the fused-decode call becomes `_fused_decode_covered` / `_run_fused_decode` instead of an inline block, and a new `needs_intermediate_states()` decides whether an extend batch needs per-chunk states (see section 5).
- `srt/layers/attention/linear/kernels/kda_flashkda.py`: the operator call is extracted into `_launch_fused`, so a subclass replaces only the launch. `_should_fall_back` already existed and is overridden on SAIL.
- `srt/layers/attention/attention_registry.py`: on SAIL the hybrid GDN, KDA and GLM5-next branches build the SAIL classes, and the KDA prefill default comes from `sail_pla_prefill_default` (-> `flashkda`). That default stays a *per-runner* value fed into `resolve_linear_attn_backends(prefill_default=...)` and not a process-wide `--linear-attn-prefill-backend`, so a target/draft pair cannot hand a FlashKDA prefill slot to a non-KDA runner. SAIL is asked before the FlashInfer branch on purpose: PPU is CUDA-compatible, so `is_cuda()` plus an SM10x capability can both hold there and would otherwise claim the runner.
- `srt/models/kimi_k3.py`: the fused-decode layout is derived from `layer.num_v_heads` through `sail_kda.supported_fused_decode_heads(...)` instead of the fixed 12, and `bind_fused_decode_weight` stacks the conv weights into `_k3_fused_decode_weight` once, on the first decode step.

### 4. ReplaySSM verify/commit

- `srt/speculative/spec_utils.py` and `srt/layers/attention/hybrid_linear_attn_backend.py`: the commit call is built as kwargs once and offered to `sail_kda.commit_after_verify` first; a `False` answer hands the batch to the community Triton path unchanged.
- `srt/hardware_backend/sail/kernels/kda.py`: `commit_after_verify` accepts only the direct state layout — FP32 `(128, 128)` temporal, BF16 raw K / raw V, 1..32 steps, all five buffers contiguous, no request ring and no source-index remap — and passes the width-major conv pool as views instead of repacking it.
- `python/sglang/kernels/ops/mamba/mamba_state_scatter_sail.py` (new): the SAIL variants of the two masked scatter kernels, with sequential early-return bounds checks and an explicit `other=0.0` on the masked load. `mamba_state_scatter_triton.py` keeps the upstream kernels untouched; the two public wrappers dispatch on `is_sail_runtime()`.

### 5. Prefill: request per-chunk states only when they are read

`needs_intermediate_states` is true only when `track_ssm_h_src` has rows, i.e. only for chunk-unaligned tracked sequences. Chunk-aligned tracked rows copy the final state out of `ssm_states` and snapshot rows read `h_track_buf`, so neither reads `h`. Requesting it unconditionally pushed every tracked prefill onto a kernel that emits `h`, which kept the fused extend kernel out of the dense path. The extend result is now unpacked by type: `(out, h)` when a kernel emits states, a bare tensor when it does not.

### 6. Three fixes that are not SAIL-specific

- `fix(linear-attn): return the FlashKDA extend output without a tuple` — `FlashKDAKernel.extend` returned `(out, None)` even when `return_intermediate_states=False`, handing a tuple to every non-track prefill batch and breaking the `o_norm` / `fused_norm_gate` shape handling downstream. The NVIDIA and PTX prefill kernels return the output tensor alone; this now matches them.
- `fix(kimi-k3): keep the logical idle mode through DP speculative sync` — hybrid speculative DP rewrites an IDLE batch to TARGET_VERIFY so the linear ReplaySSM path can join the collective, but the batch has no full-attention metadata. Two places only looked at the physical mode: the K3 decoder layer ran the attention stack for a rank without metadata, and the hybrid backend's non-linear contributions came back uninitialized for the DP padding rows. Both now check the saved `_original_forward_mode`, and those rows are zero-filled instead of empty-filled. Without this, the uninitialized rows flow through `o_proj`/residual and poison the rank-synchronous MLP result.
- `fix(arg_groups): resolve the mamba cache strategy against the forced page size` — `_mamba_radix_cache_resolution` runs before `_mla_backend_page_constraints`, so `wants_paging` reads the request's raw page size and never sees the 64 that a FlashMLA backend forces. A hybrid-mamba model with FlashMLA and no explicit `--page-size` resolved to `no_buffer` while the KV pool still ended up at 64 tokens per page; `wants_paging` now treats a flashmla attention or decode backend as a paging need. The mismatch was invisible by default because `wants_overlap` short-circuits the same `or` unless `--disable-overlap-schedule` is set, and `validate_mamba_no_buffer` cannot catch it either, since it runs in an earlier slot too.

## Impact on non-SAIL platforms

Everything here sits behind `is_sail()` and a lazy import. What does reach a non-SAIL run:

- `FlashKDAKernel.extend` returns a bare tensor on the fused path (fix 1 above).
- Per-chunk states are requested only when chunk-unaligned tracked rows exist (section 5). Behavior-neutral by construction: those rows are the only readers.
- DP speculative decoding with a hybrid linear-attention model zero-fills rewritten-idle rows and skips full-attention metadata init for them (fix 2).
- `--mamba-radix-cache-strategy auto` counts a flashmla backend as a paging need (fix 3). This can change the resolved strategy for a non-SAIL Kimi-K3 + flashmla configuration under `--disable-overlap-schedule`, so it wants a CUDA check.
- The mamba state-scatter kernels compile from the same source as upstream: the SAIL variants are a separate file and the two shared wrappers gain one `is_sail_runtime()` early return.
- `attention_registry` keeps the previous FlashInfer Blackwell default for KDA prefill off SAIL.

These need a CUDA (Hopper/Blackwell) regression run before merge; the machine this branch was assembled on has neither a CUDA device nor a PPU.

## Known limitations

- The `pla` import is lazy, but a SAIL install without the wheel falls back with a warning rather than failing; the gate is forced off in that case even if it was set explicitly. `srt_sail` now pulls the wheel in.
- PLA fused decode covers head counts `{12, 24, 48, 96}` per rank; other TP layouts stay on the unfused chain.
- The PLA ReplaySSM commit only takes the direct state layout described in section 4; ring-buffer and remapped layouts keep the Triton scatter.
- The PLA packed decode hard-codes the community softplus constants (`beta=1.0`, `threshold=20.0`); if the Triton kernel's numerics change, this has to be revisited.
- `SGLANG_SAIL_PLA=0` returns both decode and prefill to Triton; there is no per-path opt-out, and an explicit `--linear-attn-prefill-backend` still overrides the prefill side alone.
