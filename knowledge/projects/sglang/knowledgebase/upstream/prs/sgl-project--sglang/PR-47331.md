# [Doc] [AMD] cookbook: Add DCP4 to the GLM-5.2 MI355X MXFP4 high-throughput recipe

[Upstream PR](https://github.com/sgl-project/sglang/pull/47331) · state: closed · merged: True

## Original PR description

## Motivation

Add decode context parallelism (DCP4) to the GLM-5.2 MI355X MXFP4 High-Throughput recipe, following the TP4/EP4 DCP4 arm in [SemiAnalysisAI/InferenceX#4064](https://github.com/SemiAnalysisAI/InferenceX/pull/4064).

## Modifications

- High-Throughput MXFP4 cell: add `--dcp-size 4`, remove `--enable-hierarchical-cache --hicache-ratio 1.0`. HiCache has to go because SGLang raises `NotImplementedError` for HiCache with `--dcp-size > 1` and EAGLE (`resolve_hicache_dcp_compatibility` in `arg_groups/hicache_hook.py`).
- Add `--chunked-prefill-size 32768`, matching the InferenceX recipe.
- Bump `dockerImages["mi355x|mxfp4"]` to `lmsysorg/sglang-rocm:v0.5.22-rocm720-mi35x-20261028`, which includes #43735 and #44322 (Triton DSA DCP on ROCm).
- Update the MI355X MTP note and the source comment to match.

The cell stays `verified: false`.

## Accuracy Tests

No new claim. The agentic eval in the InferenceX sweep below passed on the new image.

## Speed Tests and Profiling

No numbers added. The InferenceX sweep for #4064 ([run 40823203064](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/40823203064)) completed the DCP4 arm at concurrency 24, 40 and 48 on this image. The c16 point and one HiCache point failed in `host_setup` on a bad Slurm node before the server started. InferenceX #4064 is not merged yet.
