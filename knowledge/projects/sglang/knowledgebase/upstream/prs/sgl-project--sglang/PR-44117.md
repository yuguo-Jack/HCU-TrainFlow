# refactor: inherit TRTLLMHAAttnBackend directly from AttentionBackend (#28808)

[Upstream PR](https://github.com/sgl-project/sglang/pull/44117) · state: closed · merged: False

## Original PR description

## Problem

TRTLLMHAAttnBackend 继承自 FlashInferAttnBackend，但实际上只复用了少量 __init__ 代码。这导致每次实例化 TRTLLMHAAttnBackend 时都会浪费大量资源：

- 分配 FlashInfer `prefill_wrapper_ragged`, `prefill_wrappers_paged`, `prefill_wrappers_verify`, `decode_wrappers` (BatchPrefillWithPagedKVCacheWrapper, BatchDecodeWithPagedKVCacheWrapper 等)
- 创建 FlashInferIndicesUpdaterPrefill / FlashInferIndicesUpdaterDecode
- 分配 kv_indptr, kv_last_page_len, qo_indptr 等 FlashInfer 专用缓冲区
- 设置 decode_use_tensor_cores, num_wrappers, dispatch_reason, enable_deterministic 等 TRTLLM 从不使用的标志

TRTLLMHAAttnMultiStepDraftBackend 继承自 FlashInferMultiStepDraftBackend，后者同样不是 AttentionBackend 子类，只是实现了 init_forward_metadata/init_cuda_graph_state 等接口方法。

## Solution

### TRTLLMHAAttnBackend
- 改为直接继承 AttentionBackend (base class)
- 将真正共享的池/翻译器/量化器初始化代码直接内联到 __init__ 中
- 将 _kv_write_scales 方法 (仅 3 行) 复制到本类
- 在自身 _swa_kv_pool 赋值后直接设置 use_sliding_window_kv_pool
- 删除了 flashinfer_backend.py 的 import 依赖

### TRTLLMHAAttnMultiStepDraftBackend
- 独立化 (不再继承 FlashInferMultiStepDraftBackend)
- 内联了 __init__ 中 kv_indptr/kv_last_page_len 的分配逻辑
- 不再加载 generate_draft_decode_kv_indices, common_template 等 FlashInfer 专用逻辑

## Changes
仅修改了一个文件: python/sglang/srt/layers/attention/trtllm_mha_backend.py (+52 / -18)

## Testing
- Python 语法检查通过 (ast.parse)
- 所有外部调用者 (attention_registry, draft_utils, eagle_worker_v2 等) 的导入路径不变, 行为不变
