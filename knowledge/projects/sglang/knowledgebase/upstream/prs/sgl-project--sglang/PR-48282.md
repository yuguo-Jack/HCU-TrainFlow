# [Fix] test: Import sgl_kernel in the Xeon thread-binding test

[Upstream PR](https://github.com/sgl-project/sglang/pull/48282) · state: closed · merged: True

## Original PR description

## Motivation

On main, PR Test (Xeon) fails `test/registered/cpu/test_binding.py` in `build-test (xeon-gnr, gnr, stage-a-tp-test-cpu-intel, gnr)`. Every PR whose run reaches that job fails too:

```
AttributeError: '_OpNamespace' 'sgl_kernel' object has no attribute 'init_cpu_threads_env'
✗ FAILED: /sglang-checkout/test/registered/cpu/test_binding.py returned exit code 1
```

The test calls `torch.ops.sgl_kernel` but never imports `sgl_kernel`. It relied on the `sglang` import chain loading the op library as a side effect, and #47731 removed that. The Arm64 MoE test broke the same way (#48221, fixed by #48223).

Evidence:
- **Main fails it.** [Run 41738971626](https://github.com/sgl-project/sglang/actions/runs/41738971626/job/126276036425) (`a4bef204c5`, 11-03 23:25) failed. Only `test_binding.py` failed: the TP server tests in the same suite, and both SPR jobs, passed.
- **It started with #47731.** The last GNR runs on main that completed passed on 11-01, from `0f93be7b65` to `240f2a0a64`. #47731 merged on 11-02 at 21:51, and every GNR run in between was cancelled. Later "green" Xeon runs on main skipped `build-test` entirely, via `check-changes`.
- **It's the only file left.** Across `test/registered/`, the only tests that use `torch.ops.sgl_kernel` without importing `sgl_kernel` are this one and the Arm64 `test_moe.py`, which #48223 covers.

## Modifications

Add `import sgl_kernel  # noqa: F401` to `test/registered/cpu/test_binding.py`. This is how `test/registered/cpu/test_moe.py` and the other CPU tests do it.

Production code isn't affected. `srt/distributed/bootstrap.py` calls the same op, but server launches load `sgl_kernel` some other way, as the passing server tests in the same jobs show.

## Testing

pre-commit passes. I have no Xeon machine, so this needs PR Test (Xeon) to actually run the GNR `build-test` job, via `run-ci` or a CPU-mode `/rerun-test test/registered/cpu/test_binding.py`.
