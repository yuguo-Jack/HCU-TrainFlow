# [Refactor] kernels: Centralize GPU architecture queries in sglang.kernels.arch

[Upstream PR](https://github.com/sgl-project/sglang/pull/47782) · state: closed · merged: True

## Original PR description

> (auto generated by Claude)

## Motivation

Kernels query GPU architecture in many ad-hoc ways: `torch.cuda.get_device_capability(...)`, `get_device_properties(...).multi_processor_count`, `gcnArchName` string checks, `sglang.srt.utils` helpers, and the JIT compile target `get_jit_cuda_arch()`, which several kernels also used for runtime decisions. These are duplicated, sometimes hard-code device 0, and make `sglang.kernels` depend on `sglang.srt`.

This PR adds one self-contained entry point, `sglang.kernels.arch.current_arch()`, and moves kernel arch queries onto it.

## Modifications

- New `sglang.kernels.arch` (torch only, no srt dependency):
  - `current_arch()` returns a process-wide cached object chosen from `PlatformInfo.detect()`: `CudaArch` on NVIDIA, `HipArch` on AMD, a plain `DeviceArch` elsewhere. All GPUs in a node are assumed to be the same model, so there is no device argument. Attributes are `cached_property`, read lazily on first use.
  - Shared: `num_sms`, `warp_size`, `l2_cache_bytes`, `smem_per_block_optin`, `smem_per_sm`, `regs_per_sm`, `max_threads_per_sm`, `name`, `props`, `supports_pdl`.
  - `is_sm(major, minor=None)` / `is_sm_at_least(major, minor=0)`: False off NVIDIA, so call sites need no platform guard.
  - `.cuda` / `.hip` narrow to the platform object (None elsewhere). `CudaArch` adds `major`, `minor`, `capability`, `sm_version`, `max_vec_bytes`, `supports_cluster`; `HipArch` adds `gcn_arch`.
- `PlatformInfo.detect()` is now cached (`_probe()` is the uncached probe) and gains `is_hip` / `is_musa`; the selector drops its own `lru_cache`.
- JIT compile target: `ArchInfo` is renamed to `CompileArch` (a frozen `msgspec.Struct`). `get_jit_cuda_arch()` becomes the internal `get_compile_arch()` used only by the build pipeline, and `make_jit_cuda_arch()` becomes `CompileArch.for_capability()`. `override_jit_cuda_arch()` is removed (its only user compiled for the local GPU anyway). `is_arch_support_pdl()` reads `current_arch().supports_pdl`, and `is_hip_runtime()` / `is_musa_runtime()` read `PlatformInfo`.
- About 80 call sites in `sglang.kernels` (plus a few kernel tests and benchmarks) now use `current_arch()` instead of direct torch/srt queries. Several one-line local helpers (`_num_sms`, `_get_num_sm`, `_mla_core_count`, ...) are removed.

Left unchanged on purpose: vendored code (`flash_attn/cute`, `fla`, code ported from vLLM/aiter/FlashInfer/CUTLASS), import-time queries, srt predicates that also gate on the CUDA toolkit version (`is_sm100_supported`, ...), AMD family predicates (`is_gfx95_supported`, ...), and sites that rely on ROCm reporting gfx-derived capabilities. These can follow once the matching interfaces exist.

Behavior notes:
- Kernel helpers that took a `device` argument for an arch query now ignore it (same-model assumption). The parameters are kept to avoid touching callers.
- CUDA-only paths that used to compare ROCm's gfx-derived capability now treat ROCm as "not NVIDIA".
