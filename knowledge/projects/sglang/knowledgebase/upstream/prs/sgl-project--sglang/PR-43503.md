# [CI] Drop CPU tests with no bug-catching signal and run Rust workspace tests in their own workflow

[Upstream PR](https://github.com/sgl-project/sglang/pull/43503) · state: closed · merged: True

## Original PR description

- Delete 23 CPU unit-test files with no bug-catching signal: self-tests of test, CI, release, benchmark and profiling tooling (scripted-runtime harness, fork worker, precision baseline store, docker and version-tag scripts, MoE tuning helpers), tests that read back constants or restate a one-line predicate, and a test that only exercises its own fake batch.
- Drop cases with no signal from kept files: default/constant readbacks, mock-only `assert_called` checks, log-string checks, library-semantics checks, a wall-clock assertion, cases duplicated by another case on the same path, and CUDA-only cases that no CI registration runs.
- Drop the GPU/AMD duplicates in `test_topk_correction_bias_cache.py` (same logic as its CPU class) and the AMD registration of `test_resolution_is_reproducible.py`.
- Run the Rust workspace tests (`cargo test --workspace`, `sglang-processor` with `openai`, `cargo package -p sglang-api-types`, `sglang-radix-tree`) in a new `pr-test-rust-workspace.yml` with a Rust cache, instead of through two pytest wrappers in the CPU suite. Remove the `rust_workspace` filter output and `SGLANG_SKIP_RUST_TESTS` (now in `_DEPRECATED_ENVS`).
- `base-a-test-cpu`: 833 -> 810 files; per-commit `est_time` 7853 s -> 7422 s.

No behavior change outside CI. The new Rust workflow has not run yet.
