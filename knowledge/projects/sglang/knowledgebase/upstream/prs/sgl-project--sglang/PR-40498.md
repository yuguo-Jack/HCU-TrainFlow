# [Fix] moe: Preserve negative routing sentinel in EP mapping

[Upstream PR](https://github.com/sgl-project/sglang/pull/40498) · state: closed · merged: True

## Original PR description

## Motivation

`select_experts` marks padded routing rows with `topk_ids = -1`. Under expert
parallelism, `StandardDispatcher` translated IDs with
`local_expert_mapping[topk_ids]`; PyTorch negative indexing therefore mapped the
drop sentinel through the table's final entry.

On the EP rank that owns the final expert, every padded top-k slot can therefore
collapse onto that expert and violate dispatch capacity assumptions.

## Modifications

- Preserve negative routing sentinels while translating valid global expert IDs
  to local IDs.
- Add a CPU dispatcher regression test covering a mix of padded, local, and
  non-local expert IDs.

## Accuracy Tests

- Focused CPU dispatcher regression test: **1 passed**.

## Speed Tests and Profiling

Not separately benchmarked. The change only affects EP global-to-local expert
ID translation; routing and model math for valid rows are unchanged.
