# [AMD] Preserve JSON text in RPD trace export

[Upstream PR](https://github.com/sgl-project/sglang/pull/43700) · state: open · merged: False

## Original PR description

## Motivation

RPD trace export interpolates names/descriptions directly into JSON. A quoted kernel description makes the gzip output invalid JSON; a marker such as `C:\tmp\new` can instead parse successfully with its backslashes changed into control characters. Removing quotes/tabs from marker/API text also loses the original content.

## Modifications

Encode textual event values and counter keys with `json.dumps`, without changing event order, timestamp/duration types, flow IDs, counter values, or the object/array envelope. Preserve instant/range marker text, operation names (including the empty-description fallback), API descriptions and synthesized GPU frame names.

The current [ROCm exporter](https://github.com/ROCm/rocmProfileData/blob/4df79268ea602f707c8b2a6a1b8e7bf3f9c71636/rocpd_python/rocpd/tracing.py) uses the same JSON-encoding approach; this is a scoped repair to SGLang's older vendored converter, not a full upstream sync.

## Accuracy Tests

Added three registered CPU test methods with 14 subcases using real SQLite files, the actual exporter, gzip decompression and `json.load`. Coverage includes both output formats, ordinary/Unicode controls, quotes, backslashes, control characters, API/op links, faux GPU frames, optional HSA/SMI events and a graph-event control.

- Unmodified source: 4 subcases pass, 8 JSON decoding errors, 2 silent text-corruption failures.
- Fixed source: 14/14 subcases pass on native Windows CPython 3.12.13 and 3.14.3.
- These local runs load the actual component directly and use stdlib `unittest.TestCase` for the same test bodies. Full registered execution is blocked on Windows by SGLang's transitive `resource` import; Linux/ROCm CI is still needed.
- File-scoped pre-commit formatting/static checks pass. Three local hooks use an unavailable `python3` launcher on Windows; running those exact lint/CI-registration scripts with native `python` passes.
- `git diff --check` passes.

## Speed Tests and Profiling

No inference or kernel behavior changes. No AMD GPU capture or performance claim.
