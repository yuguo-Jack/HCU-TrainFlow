# [Fix] [Intel] kernels: Recognize XPU capabilities

[Upstream PR](https://github.com/sgl-project/sglang/pull/44863) · state: open · merged: False

## Original PR description

Stack (5/6), merge in order: [#44851](https://github.com/sgl-project/sglang/pull/44851) → [#44852](https://github.com/sgl-project/sglang/pull/44852) → [#44853](https://github.com/sgl-project/sglang/pull/44853) → [#44854](https://github.com/sgl-project/sglang/pull/44854) → [#44863](https://github.com/sgl-project/sglang/pull/44863) → [#44869](https://github.com/sgl-project/sglang/pull/44869)

Kernel capability detection currently reports `cpu` when Intel XPU is the available accelerator. Add `DeviceType.XPU` and `CapabilityRequirement.XPU`, and detect XPU after the existing accelerator checks. This lets the inventory describe XPU kernels and excludes XPU processes from CPU-only capabilities.

Validation on an Intel Arc Pro B70 with PyTorch 2.13.0+xpu:

- 123 namespace and fused-op dispatch tests passed across three separate test processes.
- Four Gemma4 XPU serving tests passed, covering one-step and three-step captured MTP.
- The new detection regression fails on the previous source. The patched hardware probe reports `xpu` with XPU available.
- Pre-commit checks passed.
