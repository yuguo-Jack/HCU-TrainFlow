# [CI] [NPU] precise-test: skip suites that register no PR test

[Upstream PR](https://github.com/sgl-project/sglang/pull/46844) · state: closed · merged: True

## Original PR description

## Motivation

On the latest `main`, `base-c-test-acc-16-npu-a3` has **no registered PR test** (the only candidate, `test_npu_glm5_top64_pruned_bf16_8p_gsm8k.py`, is registered for `nightly-acc-16-npu-a3` only). `bucket_recommended_tests.py` treated a 0-file enumeration as a possible `list_tests`/`run_suite` drift and forced the full-suite path: it emitted `should_run_*=true` with an empty `only_tests_*`, so the stage ran `run_suite.py --suite base-c-test-acc-16-npu-a3`, selected 0 tests, and exited 0.

Result: a green job that occupied a 16-card runner for 4m37s and validated nothing.

- Job: https://github.com/sgl-project/sglang/actions/runs/40501668056/job/122181326286 (success, 12:12:26Z → 12:17:03Z, 0 tests executed)
- Same run, `base-c-test-acc-2-npu-a3`: bucket empty but registered pool non-empty -> `should_run=false` -> skipped

`run_suite.py` reads the same registry and applies the same filter as `list_tests.py`, so "the suite enumerates 0 files" means the job cannot run any test — the full-suite fallback has nothing to fall back to.

## Modifications

`scripts/ci/npu/precise-test/bucket_recommended_tests.py`:

- A suite with a 0-file enumeration now takes the precision-mode skip path (`should_run_* = false`) instead of `true`.
- The existing `::warning::` now states that the suite registers no PR test and is skipped, and the recommendation report shows `skipped (suite registers no test)`, so the empty registration stays visible.
- Skipping a 0-file suite is only safe while the enumeration itself is trustworthy. If **every** requested suite enumerates nothing, `test/registered` was unreadable or `list_tests.py` drifted from `run_suite.py`, so that state joins the other "recommendation unusable" signals and runs every suite in full (with a warning) instead of dropping all a3 PR testing.
- Unchanged: the multimodal `force_full` safety gate still runs full suites, and non-precision runs (nightly / full suites) still export `should_run_* = true` plus an empty bucket, i.e. full-suite behavior.

## Verification

Local smoke run of the script on current `main` with an empty recommendation and `--precision-mode true`:

| Suite | Registered | Bucketed | should_run |
|---|---|---|---|
| base-b-test-1-npu-a3 | 9 | 0 | false (skipped, no recommended test) |
| base-c-test-acc-16-npu-a3 | 0 | 0 | false (skipped, suite registers no test) |
| multimodal-gen-test-1-npu-a3 | 7 | 0 | true (forced full by the safety gate) |

Also checked that every other suite in this workflow still enumerates a non-empty pool on `main`: base-b 9/6/4/1/1, base-c acc-2 1, perf-2 3, perf-16 1. With every suite enumerated as empty (broken enumeration), the script now decides `full` and emits `should_run_* = true` for all suites.
