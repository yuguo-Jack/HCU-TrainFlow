# [Fix] DeepSeek-V4.1: keep the mHC next-layer link out of the module tree

[Upstream PR](https://github.com/sgl-project/sglang/pull/44691) · state: open · merged: False

## Original PR description

## Summary
Keep DeepSeek-V4.1 weight updates from missing layers 1+ after `bind_next` links decoder layers.

## Symptom & Reproduction
- **Symptom:** in radixark/miles CI on SGLang `v0.5.22` (`993bf90200`), check `stage-c-8-gpu-h200 (0) / run` ([job 116833022894](https://github.com/radixark/miles/actions/runs/38851892750/job/116833022894), attempt 1), `test_deepseek_v4_1_4layer_ci.py` crashed the scheduler on its first weight update after logging `model.layers.1.mlp.gate.weight not found in params_dict`, with `KeyError: 'model.layers.1.mlp.shared_experts.gate_up_proj.weight'` in `load_weights`.
- **Reproduction:** `test_linked_layers_keep_their_own_parameter_names` fails on `main` (`92580581da`), where the parameter names come back as `0.weight`, `0._next_layer.weight`, ...; it passes with the fix.

## Root Cause
1. `NonCudaDecoderMixin.bind_next` assigns `self._next_layer = next_layer` after every load.
2. `nn.Module.__setattr__` registers that layer as a submodule of the previous one.
3. `named_parameters()` dedups each layer under its first path, `layers.0._next_layer...`.
4. The next `load_weights` misses `model.layers.{i>=1}.*` in `params_dict` and raises `KeyError`.

## Fix
Store the link with `object.__setattr__`, a plain reference outside the module tree, as `inkling_common/util.py` does. Only V4.1 (`hc_pre_from_prev_sublayer=True`) reaches this; V4 returns early and is unchanged. On `main` the CUDA decoder completes mHC in `deepseek_v4_boundary`, so this fixes the non-CUDA platform decoders; `v0.5.22` still has the same line in `DeepseekV4DecoderLayer.bind_next`.

## Verification
- `test/registered/unit/models/test_deepseek_v4_platform_dispatch.py`: 7 passed with the fix; the new case failed before it.
- `ruff format` / `ruff check --select=F401,F821,F823,UP037` (ruff `0.15.1`): clean.
- Not run: a GPU weight update on a non-CUDA platform.

## Review Focus
- `NonCudaDecoderMixin.bind_next`: nothing may rely on `_next_layer` appearing in `named_modules()` or `state_dict()`.
