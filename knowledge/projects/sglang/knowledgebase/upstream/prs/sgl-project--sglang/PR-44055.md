## Motivation

Fixes #44054.

`test/registered/kernels/ops/gemm/test_pi05_modelopt_fp8_cuda.py` imports `sglang.multimodal_gen`, which needs the `diffusion` extra (`imageio`, ...). It is registered in the `base-b` / `1-gpu-small` lane of `PR Test Base`, which installs only `python[dev,runai,tracing]`. On runners whose CI venv does not already have `imageio`, the test fails at import with `ModuleNotFoundError: No module named 'imageio'`, for example in #42760 ([job](https://github.com/sgl-project/sglang/actions/runs/38384431344/job/115259669168)) and #34502 ([job](https://github.com/sgl-project/sglang/actions/runs/38378074749/job/115245167435)).

## Modifications

Register the test with `stage="base-b-kernel-unit"` instead of `stage="base-b"`, keeping `runner_config="1-gpu-small"`. The kernel-unit lane (`pr-test-jit-kernel.yml`) runs `ci_install_dependency.sh diffusion`, and every other CUDA test that imports `sglang.multimodal_gen` already registers there or on a diffusion runner.

Trade-off: the kernel-unit lane runs on PRs that touch JIT-kernel paths and on scheduled `main` runs, not on every PR.
