# [Fix] scheduler: Reap HiCache events while the engine is paused

[Upstream PR](https://github.com/sgl-project/sglang/pull/46502) · state: open · merged: False

## Original PR description

## Motivation

With HiCache on (`--enable-hierarchical-cache`, default `write_through`), an RL weight sync runs `pause_generation(mode="retract")`, then `update_weights_from_disk(flush_cache=True)`. The update returns `success=False`: "Weights were updated, but the cache was not flushed because requests are still running or queued. Retract or finish them, then call /flush_cache." The requests are already retracted, and `/flush_cache` fails on every paused iteration, so the only way out is `continue_generation`, which serves the new weights over the old weights' cache.

The blocker is not the requests: #40779's paused gate already ignores the requeued ones. It is a HiCache write-through still in `ongoing_write_through` and, with an L3 backend, the prefetch the retract requeue starts for a request with 256 or more uncached tokens. Only `check_hicache_events` retires them, and it runs from the batch getters and `process_decode_queue`, which every paused branch skips. #43758 turned the old assert into this message: the update fails cleanly but cannot succeed while paused.

## Modifications

All seven paused branches call `_record_scheduler_state_for_paused_engine()` on each iteration. It now first calls `_process_hicache_events(should_retry_storage_prefetch=False)`: pending acks are reaped before the idle/active record, and no new L3 attempt starts. PD decode reaps only with the decode radix cache, as `process_decode_queue` does. No loop body changes.

Considered and rejected: a blocking drain at pause entry, as #30899 and #43282 do. It cannot retire the prefetch the requeue issues after the retract, and it blocks the control path.

Edits the same helper as #46334 and #46307.

## Accuracy Tests

New file `test/registered/unit/managers/test_scheduler_paused_hicache_events.py`, because #43910/#43911 and #46334 edit the neighbouring test files:

- a paused iteration reaps once, before recording state, and retries no storage prefetch;
- no reap without HiCache, or on PD decode without the decode radix cache;
- real `event_loop_normal`, retract pause, one pending write-through: after one paused iteration the update and `flush_cache()` succeed;
- L3 storage, 300 generated tokens: the requeue starts one prefetch, and one paused iteration retires it.

The tree cache, forward, `retract_all` and weight load are stubbed. On CPU:

- main: 5 failed, 2 passed (the first case's three subtests; both loop cases return the message above)
- this PR: 4 passed, 5 subtests passed; `test_scheduler_pause_generation.py` and `test_scheduler_hicache_events.py` still pass

Not run: a GPU job with a real HiCache backend, or several ranks. Every rank receives pause and resume through the same broadcast, so I expect the all-reduce inside `check_hicache_events` to line up as on an idle running loop.
