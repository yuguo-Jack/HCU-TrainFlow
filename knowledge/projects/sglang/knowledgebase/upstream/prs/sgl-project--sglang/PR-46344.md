# [Perf] dsv41: Reuse request groups from causal expansion

[Upstream PR](https://github.com/sgl-project/sglang/pull/46344) · state: open · merged: False

## Original PR description

## Motivation

DSv4.1 request-window metadata rebuilds request groups after causal expansion has already identified each row's request. Reuse group IDs and group boundaries from that producer to avoid the separate grouping scan. In sampled eager prefill, main and bounded-tail metadata each used the new path; the old grouping scan issued 16 CUDA launches per call.

## Modifications

- Add optional group/first/last outputs to causal expansion and pass them to request-window layout construction.
- Preserve grouping by adjacent actual request IDs, including zero-length entries, repeated IDs, and padding after an empty final entry.
- Admit CUDA, contiguous inputs, CP1, nonempty eager metadata outside capture/full-prefill-graph construction. Existing defaults and unsupported paths retain the original scan. No persistent graph-buffer fields change.

## Accuracy Tests

- Local directed validation: 30 CUDA cases covering int32/int64 request IDs, nonzero storage offsets, 4,224/33,792 rows, eight requests of 4,224 rows, request-count boundaries 17/33/65, zero lengths, repeated IDs and padding. Producer outputs and every request-window layout field match the original implementation exactly. Two additional graph replays verify the unchanged default producer; these are not layout-capture coverage.
- Actual-model diagnostic: both ranks, two measured samples per main/tail path, at 4K and 32K new tokens per rank. All 12 layout fields match the original scan on identical actual inputs. The 32K inputs contain eight requests of 4,224 rows and the corresponding eight 128-row tails.
- Paired native GSM8K using the standard `DSV41FlashAccuracyMixin.test_gsm8k` recipe (200 examples, 64 threads, max 4,096 output tokens): baseline 97.0%, candidate 97.5%, both above the 95% threshold. Canonical example IDs and input hashes match exactly. Both runs have zero errors, truncations, invalid results, or empty generations. Simulation is disabled (`SGLANG_SIMULATE_ACC_LEN=-1`); actual DSpark acceptance is enabled. This is quality validation, not a native-latency comparison or proof of identical generated text.

The helper validation remains local; this PR adds no standalone benchmark or registered helper test.

## Speed Tests and Profiling

Full-model steady engine-step measurements use the unchanged `benchmark/engine_steps/bench_engine_steps.py` from #46006 at `543a2804d5c8f3167c8fd8bb5c3a3ef862c3774f`. These measure prefill step cost, not end-to-end application latency.

Two GB300 GPUs; same public DeepSeek-V4.1-Flash checkpoint and runtime in both arms; TP2/EP2, attention-DP2, DP1, MegaMoE, `flashmla_mega`, encoder and decoder bounded replay enabled. Full prefill/decode graph backends disabled. Context 131,072, suffix 4,096, 4,096 requests per attention rank, seed 733427905. `SGLANG_DP_USE_GATHERV=0`, sparse prefill enabled, Engram extend hash disabled. The step benchmark uses `SGLANG_SIMULATE_ACC_LEN=3.51` with `match-expected` and `real-draft-token`; native quality is evaluated separately with simulation disabled. Requested KV limit is 54,000,000 in every arm (resolved 53,999,872 per rank).

A = baseline, B = this change. Each value is ms/step from the official scorer; all saved completions re-score exactly and all workload/configuration guards pass.
