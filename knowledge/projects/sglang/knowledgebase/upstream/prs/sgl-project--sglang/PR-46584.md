# [Feat] [NPU] GLM: Adapt Mooncake L3

[Upstream PR](https://github.com/sgl-project/sglang/pull/46584) · state: open · merged: False

## Original PR description

## Problem

With HiCache L3 enabled on Ascend, the MLA host pool allocates its storage in the NPU `page_first_kv_split` layout, where one logical page spans **several separate tensors**:

```
k_buffer                (K; on A5 this is the packed FP8 DSA row)
v_buffer                (RoPE mirror; no valid data when FP8 DSA packs V into K)
index_k_buffer          (DSA indexer K, only physical Indexer layers — 21/78 on GLM-5.2)
index_k_scale_buffer    (FP32 indexer dequant scale, A5 FP8 DSA only)
```

`get_page_buffer_meta()` already emits **one pointer per tensor per page**, and Mooncake packs those pointers into a single storage object per page. But only `kv_buffer` was ever registered with the transfer engine, so every other segment was **unregistered**:

| Platform | Behaviour with unregistered segments |
|---|---|
| A3 (sdma / plain mooncake) | transfer engine silently memcpys them → correct, just slow. This is why L3 "worked" on A3 without any code change. |
| A5 (memfabric + `device_urma`) | the copy fallback goes through the URMA batch-copy kernel and aborts with an AICPU fault (`507018`), poisoning the device stream so the next `aclrtMemcpyAsync` / `aclnnCat` also fails; the log also shows `FindLocalRegistrationLocked: registration does not contain range` |
| A5 FP8 DSA | the FP32 `index_k_scale` never reached L3 at all, so an L3 hit loses the dequant scale of the indexer layers and the top-k selection drifts (silent wrong output, no crash) |

## Fix

**`mem_cache/pool_host/mla.py`** — implement `get_hybrid_pool_buffer()`. The store side already has the hook:

```python
get_buffers = getattr(host_pool, "get_hybrid_pool_buffer",
                      lambda: [getattr(host_pool, "kv_buffer", None)])
```

so without this method every host pool falls back to `kv_buffer` only. The new method mirrors `get_page_buffer_meta()`'s inclusion rules exactly (same order, same `dsa_kv_cache_store_fp8` skip of the V mirror), keeping the registration list and the per-page pointer list aligned.

**`mem_cache/storage/mooncake_store/mooncake_store.py`** — drop the `PoolName.DRAFT` special case that registered a single `kv_buffer`:

```python
if host_pool_name == PoolName.DRAFT:
    self.registered_pools[host_pool_name] = host_pool
    super().register_buffer(host_pool.kv_buffer)
    return
```

Draft pools now take the generic hybrid path, which is what an MLA draft needs when its row width differs from the target's packed row (bf16 draft on an FP8 DSA target: 512 vs 656/768). The `{mla_suffix}_draft_k` key scheme is unaffected because `key_multiplier` is derived from the pool class, not from the buffer count, and multi-buffer pages are already packed by `_pack_multi_buffer_meta()`.

## Upgrade note

L3 objects written by the old code cover a different set of buffers, so the storage backend must be flushed after upgrading before cached pages are trusted.

## Verification status

Not runtime-verified in this PR yet. Planned checks:

1. registered buffer count per pool goes `1 → 3` on A3 and `1 → 4` on A5 (`grep register_buffer server log`);
2. `FindLocalRegistrationLocked` / `507018` / `batch copy failed` counts drop to 0 on A5;
3. L3 correctness with greedy decoding (`temperature=0`) run as cold → L2 hit → flush → L3 hit, comparing `output_ids` token-by-token; expected `cold == L2 == L3`;
4. `cached_tokens` stays a multiple of `page_size` (128).
