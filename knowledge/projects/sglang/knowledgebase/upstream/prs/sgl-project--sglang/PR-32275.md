# feat(hicache): support Ascend Mamba host transfers

[Upstream PR](https://github.com/sgl-project/sglang/pull/32275) · state: closed · merged: False

## Original PR description

## Summary

- add `kernel_ascend` D2H/H2D transfer paths for page-first Mamba host pools
- preserve layer/slot/state dimensions and tensor dtypes during transfer
- add a focused CPU round-trip unit test for the Ascend dispatch path
- add an Ascend nightly E2E test covering Qwen3.5-0.8B Mamba write-through and L3 file restore

## Motivation

HiCache on Ascend selected `kernel_ascend`, but `MambaPoolHost` did not implement that backend. Hybrid Qwen3.5 requests therefore failed during device-to-host backup. The initial implementation also exposed a source/destination dimensionality mismatch.

## Validation

- Ascend NPU E2E passed with a 3200-token prompt: L1 warm hit, Mamba file persistence, cache flush, and L3 restore
- restored deterministic output matches the initial generation
- focused CPU round-trip test covers temporal and convolution state shape/dtype preservation
- `python -m py_compile` passed for all changed Python files
- `git diff --check` passed

The local development host does not provide PyTorch/Ascend hardware, so the hardware E2E validation was run in the external Ascend environment.

Supersedes closed PR #32273.

### Ascend HiCache accuracy validation

I additionally evaluated Qwen3.6-35B-A3B using EvalScope C-Eval on a single Ascend 910C node with TP=2.

#### Accuracy results

| Test configuration / cache state | Number of evaluated samples | Mean C-Eval accuracy |
|:---------------------------------|----------------------------:|---------------------:|
| HiCache disabled                 |                         931 |               88.29% |
| HiCache enabled                  |                         900 |               87.00% |
| After cache flush and L3 restore |                         915 |               87.98% |

No meaningful accuracy regression was observed after enabling HiCache or restoring the cache from L3. In particular, the post-flush L3 result (87.98%) was close to the no-HiCache baseline (88.29%).

The number of successfully evaluated samples differed slightly between runs, so this should be treated as an end-to-end accuracy regression test rather than a strict paired per-sample comparison.

#### Common server configuration

```bash
python3 -m sglang.launch_server \
  --model-path /path/to/Qwen3.6-35B-A3B \
  --attention-backend ascend \
  --device npu \
  --tp-size 2 \
  --chunked-prefill-size 16384 \
  --max-prefill-tokens 16384 \
  --mem-fraction-static 0.75 \
  --max-running-requests 16 \
  --context-length 262144 \
  --max-mamba-cache-size 112 \
  --dtype bfloat16 \
  --mamba-ssm-dtype bfloat16 \
  --mamba-scheduler-strategy extra_buffer \
  --enable-cache-report
```

The L3 restore run reused the same HiCache file storage after flushing the in-memory cache.

### Ascend HiCache multi-turn performance validation

I also ran a multi-turn serving benchmark with Qwen3.6-35B-A3B on a single Ascend 910C node with TP=2.

#### Workload

- 20 independent sessions, 5 turns per session, 100 requests in total
- 42,000 tokens for the first turn and 1,000 additional tokens per subsequent turn
- 380 output tokens per request
- Request rate: 0.5 requests/s
- Random scheduling across ready sessions with seed 42
- HiCache: 12 GB Host cache, file storage, `write_through`, `wait_complete`, `kernel`, and `page_first_direct`

#### Results

| Test configuration / cache state | Cache hit rate | Mean TTFT | P90 TTFT | P99 TTFT | Mean E2E | Output throughput |
|:---------------------------------|---------------:|----------:|---------:|---------:|---------:|------------------:|
| HiCache disabled                 |         75.57% |   20.98 s |  34.50 s |  63.81 s |  37.82 s |      133.85 tok/s |
| HiCache first run                |         78.65% |   16.70 s |  26.53 s |  62.15 s |  35.01 s |      133.57 tok/s |
| After flush and L3 restore       |         97.42% |   14.83 s |  24.82 s |  29.56 s |  26.33 s |      151.63 tok/s |

The first HiCache run already improved the cache hit rate from 75.57% to 78.65%, reduced mean TTFT by 20.4%, reduced P90 TTFT by 23.1%, and reduced mean end-to-end latency by 7.4%. Throughput remained comparable to the baseline while the run also built and persisted the hierarchical cache through write-through.

Before the final run, I called `flush_cache` to remove HBM/L1 and Host/L2 cache residency while retaining the L3 file cache. Compared with the baseline, the post-flush run reduced mean TTFT by 29.3%, P99 TTFT by 53.7%, and mean end-to-end latency by 30.4%, while improving output throughput by 13.3%. This confirms that the persisted L3 session prefixes were restored successfully and substantially reduced repeated prefill computation.

Benchmark command (paths sanitized):

```bash
python3 benchmark/hicache/bench_multiturn.py \
  --api-format openai \
  --host 127.0.0.1 \
  --port 9811 \
  --model-path /path/to/Qwen3.6-35B-A3B \
  --dataset-path /path/to/ShareGPT_V3_unfiltered_cleaned_split.json \
  --num-clients 20 \
  --num-rounds 5 \
  --request-length 42000 \
  --sub-question-input-length 1000 \
  --output-length 380 \
  --request-rate 0.5 \
  --ready-queue-policy random \
  --disable-auto-run \
  --seed 42
```
