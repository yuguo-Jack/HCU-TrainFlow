# [Fix] Return a tensor from the FlashKDA prefill fast path

[Upstream PR](https://github.com/sgl-project/sglang/pull/39926) · state: closed · merged: False

## Original PR description

## Motivation

Fixes #39925.

The fused FlashKDA prefill path wraps its tensor in `(output, None)` even when `return_intermediate_states=False`. The KDA caller only unpacks when tracking SSM checkpoints, so untracked GLM-5.3-Flash prefill reaches gated RMSNorm with a tuple and fails on `x.shape`.

## Modifications

Return the fused output tensor directly. Keep the intermediate-state Triton fallback and all routing guards unchanged. One production file changed; no kernel math or serving flags changed.

## Accuracy Tests

Manual validation on GB300 using a downstream `0.5.19+82357279cc` build with the same faulty function:

- Real GPU kernel replay reproduced the tuple failure. The fixed output and updated SSM state are bitwise equal to the original tensor/state; gated norm succeeds with finite output.
- GLM-5.3-Flash TP2/EP2, DeepGEMM, DFlash2 block8, radix cache disabled: original full-model run failed at `glm5_next.py:552 -> fused_norm_gate.py:295`; identical 128-token request after the patch returned HTTP 200 and generated 16 tokens.
- 32/128/1024/2048/4096-token requests and a text chat request returned HTTP 200 after the patch.

Reproduction and environment: #39925. Upstream main was source-checked, not separately GPU-deployed. No task-accuracy suite or PD transport validation was run. GPU replay scripts/logs were kept outside this minimal patch.

## Speed Tests and Profiling

Not applicable: removes a Python tuple wrapper without changing kernel work. Functional requests are not reported as throughput benchmarks.
