# perf(speculative): replace zeros_like with empty_like for draft_probs scratch buffer

[Upstream PR](https://github.com/sgl-project/sglang/pull/44125) · state: closed · merged: False

## Original PR description

## Summary

Closes #12562 (partial — step 1/2 for the "remove draft_probs" TODO).

The `tree_speculative_sampling_target_only` kernel treats `draft_probs` as a scratch output buffer that gets fully overwritten with rejected-token probabilities during verification. The callers were initialising it with `torch.zeros_like(target_probs)` every time, which is wasted work: `(bs, num_draft_tokens, vocab_size)` can be large and the kernel never reads the initial zeros.

This PR:

1. Replaces `torch.zeros_like` with `torch.empty_like` in both call sites (`dflash_utils.py`, `eagle_utils.py`) for the tree-verification path.
2. Adds clarifying doc-comments on the `draft_probs` parameter in both the JIT wrapper (`kernels/ops/speculative/sampling.py`) and the AOT wrapper (`kernels/aot/python/sgl_kernel/speculative.py`) so future contributors don't repeat the mistake.
3. Leaves a TODO pointing at the next step — removing `draft_probs` from the kernel interface entirely, which will require matching C++/CUDA changes.

### Testing

- `torch.empty_like` has identical shape/dtype/device semantics to `zeros_like`, so kernel input validation (which only checks shape/dtype/device) is unaffected.
- Behavioural change: none. The kernel writes every slot before reading, so the uninitialised memory in `empty_like` is safe.
- Not run locally (no GPU in this environment). CI will cover kernel correctness.
