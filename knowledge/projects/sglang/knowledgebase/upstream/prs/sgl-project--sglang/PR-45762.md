# [Fix] deepseek-v41: Split thinking when SGLANG_DEFAULT_THINKING is set

[Upstream PR](https://github.com/sgl-project/sglang/pull/45762) · state: open · merged: False

## Original PR description

## Summary
- `_get_reasoning_from_request` now treats a missing `thinking` kwarg the same way the dsv4/dsv41 encoder does: `SGLANG_DEFAULT_THINKING`.
- With the cookbook env set, a `/v1/chat/completions` request that omits `reasoning_effort` and `chat_template_kwargs.thinking` is parsed with `force_reasoning`, so the thinking block goes to `reasoning_content` instead of `content`.
- An explicit `thinking: false` still disables the split. `enable_thinking` parsers are unchanged, because those templates do not read this env.

Fixes #45614
