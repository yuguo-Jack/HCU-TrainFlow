# [Fix] flashinfer: Reuse CUDA-graph wrappers when a batch size is captured twice

[Upstream PR](https://github.com/sgl-project/sglang/pull/45092) · state: open · merged: False

## Original PR description

## Motivation

`FlashInferAttnBackend._prepare_cuda_graph_metadata` creates a new set of decode (or target-verify)
wrappers for every capture and stores it in `decode_cuda_graph_metadata[bs]`. Replay
(`init_forward_metadata_out_graph`) plans only that stored set. The decode runner captures one batch
size more than once when it records attention graph variants (`graph_variants.py`) or LoRA / no-LoRA
graphs; the earlier graphs then replay kernels bound to wrappers whose plan is never refreshed — stale
indices / lengths, silently.

## Modifications

Reuse the stored wrappers for a batch size if they exist (decode and target-verify). The wrappers are
bound to the same per-bs buffer slices either way, so sharing them is what the replay path assumes.

## Accuracy Tests

- New unit test `test/registered/unit/layers/attention/test_flashinfer_graph_variant_wrappers.py`: fails
  on main (a second capture of bs=4 yields different wrappers), passes with the fix.
- End to end: a model capturing two decode-graph variants per batch size on FlashInfer gives
  decode-vs-prefill logprob consistency of 8 / 2,048 top-1 flips (plain-decode level) with the fix.

## Speed Tests and Profiling

None: fewer wrapper objects, same kernels.
