# [Refactor] [AMD] kimi-k3: Rename two ROCm K3 env vars and read them through Envs

[Upstream PR](https://github.com/sgl-project/sglang/pull/45314) · state: open · merged: False

## Original PR description

## Motivation

- Two ROCm Kimi-K3 env vars break the [env var conventions](https://github.com/sgl-project/sglang/blob/main/.agents/skills/env-var-conventions/SKILL.md):
  - `SGLANG_AITER_K3_OPT` is read with `get_bool_env_var`, so it is not in `Envs`, cannot be overridden in tests and is not documented.
  - Neither name has a verb after `SGLANG_` (`AITER_`, `K3_`).
- Renaming now, with aliases, lets recipes move to the conventional names before the old ones are removed.

## Modifications

| Old name (still accepted) | New name | Kind | Default |
|---|---|---|---|
| `SGLANG_AITER_K3_OPT` | `SGLANG_OPT_HIP_K3_AITER` | perf toggle | `false` (unchanged) |
| `SGLANG_K3_RADIX4_TOPK` | `SGLANG_OPT_HIP_K3_RADIX4_TOPK` | perf toggle | `false` (unchanged) |

- Both new names are `EnvBoolWithAlias` fields with the old name as `deprecated_name` (env-var-conventions Rule 5), so existing scripts keep working.
- Every read site uses `envs.<name>.get()`.
- Both entries sit in the existing AMD, ROCm, and AITER section of `environ.py` and the AMD & ROCm table of the env reference. The `SGLANG_OPT_HIP_K3_AITER` description now matches the code.
- Values are parsed by `EnvBool`: `yes` / `y` now count as true, and an unrecognized value raises instead of warning and reading as false.
- Renames that belong to other open PRs stay there, so the PRs merge in any order:
  - fused KDA decode (`SGLANG_USE_HIP_K3_KDA_FUSED_BACKEND`, `SGLANG_USE_HIP_K3_FLYDSL_SOURCE`): #41794
  - KDA in-proj (`SGLANG_OPT_HIP_K3_FUSE_KDA_INPROJ*`): #44362
- The cookbook keeps the old names, because the pinned image `v0.5.19-rocm720-mi35x-20260916` only reads those.
- When only the old name is set, the shared `Env*WithAlias` code copies the value to the new name in `os.environ`. All aliases in `Envs` do this; this PR does not change it.

## Accuracy Tests

- No numerical change: both switches keep their code path and default.
- `test/registered/unit/test_environ.py` checks both aliases:

| Case | Expected |
|---|---|
| Old name only | New field returns the old value, one `DeprecationWarning` |
| Both names | New name wins, no warning |

- On MI355X, `test_environ.py`, `test_moe_route_radix4.py` and `test_topk_correction_bias_cache.py`: 78 passed. pre-commit passes.

## Speed Tests and Profiling

- No speed change expected. Not measured, because no code path changes.
