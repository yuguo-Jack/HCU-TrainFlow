# [Feat] spec: Capture aux hidden states on the target without a speculative draft

[Upstream PR](https://github.com/sgl-project/sglang/pull/43449) · state: closed · merged: True

## Original PR description

## Motivation

Auxiliary hidden-state capture is the per-layer concatenation that EAGLE3, DFLASH and DSPARK drafts consume. Today it is only reachable by loading a speculative draft; `ModelRunner` carries a `TODO: expose this to server args?` for it.

Data-generation and draft-training pipelines need these hidden states from a plain target server. Without this change they either patch SGLang or re-run the target in a separate process.

## Modifications

- **New server arguments** (`exec.features`, defaulting to `False` and `None`):
  - `--enable-return-aux-hidden-states` wires the target model's existing capture hook without a draft. `--speculative-algorithm` then only names the capture convention: `set_eagle3_layers_to_capture`, `set_dflash_layers_to_capture`, or the native `set_dspark_layers_to_capture` when the model has one. The resolution hook resets `speculative_algorithm` to `None`, so no draft is loaded, nothing is reserved for one, and the speculative stack stays off. The resolved convention lives in a non-CLI `aux_hidden_state_capture` field; it stays an enum because the models' capture hooks still differ by draft family (layer-id conventions, mHC contraction), with a TODO to unify those hooks and collapse it to the bool. It sets `--return-hidden-states-mode` to `full` when unset.
  - `--return-aux-hidden-state-layer-ids` selects layers in the target model's capture convention. It is required for DFLASH and DSPARK; EAGLE3 falls back to the model's default EAGLE3 layers. Draft-checkpoint IDs can differ: DFLASH uses zero-based layer-output IDs for Llama and Qwen3, but layer-input IDs for Muse Glimmer. A Muse `DFlash2DraftModel` or `MuseGlimmerAssistantModel` output-layer ID of 4 therefore becomes capture ID 5; capture-only mode does not perform that conversion automatically.
- **Resolver.** `resolve_spec_aux_hidden_state_config` handles the capture-only case. It resolves no draft layer counts, so the KV pool reserves nothing for a draft.
- **DSPARK hook routing.** It moves from `spec_algorithm.is_dspark()` to the resolved config (`SpecAuxHiddenStateConfig.is_dspark`), so capture-only DSPARK picks the native hook. Behavior is unchanged for speculative runs.
- **Hidden-state capture output.** Requests use the existing `return_hidden_states` and `--return-hidden-states-mode` paths to receive the auxiliary concatenation. Under full capture, `LogitsProcessorOutput.last_hidden_states` separately retains the post-norm final-layer states for in-process consumers (#43450 and the SpecForge capture plugin, sgl-project/SpecForge#945); it is not added to HTTP responses. CUDA, CPU and NPU graph output slicing, DP/MLP padding removal, and encoder-SWA folded-row removal keep these rows aligned with the auxiliary output. Inkling preserves the final-layer states before μP logit scaling while retaining its existing scaled logit computation.
- **Validation.** `handle_aux_hidden_state_capture` runs before any reader of `speculative_algorithm`. It rejects layer ids without the flag, the flag without `--speculative-algorithm` EAGLE3/DFLASH/DSPARK, the flag together with `--speculative-draft-model-path`, DFLASH/DSPARK without layer ids, an empty, negative or repeated layer id, and `pp_size > 1` (the capture hooks only see the last pipeline rank's layers). The resolver rejects a layer id beyond the target's layer count before weights load. At the first forward, `LogitsProcessor` fails if the model captured fewer layers than requested, since most models cannot capture their last layer; a model without the requested hook is reported as a `ValueError`.
- **Docs.** Rows added to `server_arguments.mdx`.

Example (no draft loaded):

```bash
python -m sglang.launch_server --model-path Qwen/Qwen3-8B \
  --speculative-algorithm DFLASH --enable-return-aux-hidden-states \
  --return-aux-hidden-state-layer-ids 1 9 17 25 33 \
  --return-hidden-states-mode full
```

A request with `"return_hidden_states": true` then receives the concatenated hidden states of the five layers.

## Accuracy Tests

The following GB300 results are historical validation of an earlier revision, run with the earlier `--aux-hidden-state-capture <method>` spelling. The examples below use the current flags. These GPU accuracy tests have not been rerun after the latest cleanup, rebase, and output-alignment fixes.

One GB300 (CUDA 13), image `lmsysorg/sglang:nightly-dev-cu13-20261006-f3fe7534` with SGLang main `8c273d6813` + #43448, this PR and #43450 (maocheng23/sglang `spec-capture/integration`) overlaid. The SpecForge capture plugin (sgl-project/SpecForge#945) is the consumer.

- **Against an independent forward.** Tiny Llama target (8 layers, hidden 64), `--speculative-algorithm EAGLE3 --enable-return-aux-hidden-states --return-aux-hidden-state-layer-ids 1 3 4 --return-hidden-states-mode full`:
  - across the three gate tests (EAGLE3 and DFlash feature layouts), the aux states match a separate HF forward of the same layers within bf16 tolerance (2e-2);
  - `lm_head(last_hidden_states)` reproduces HF's logits within that tolerance;
  - one EAGLE3 training step on the captured features gives a finite loss.
- **Real model.** Qwen3.8-27B (hybrid GDN, 64 layers), TP1, `--speculative-algorithm DFLASH --enable-return-aux-hidden-states --return-aux-hidden-state-layer-ids 5 19 33 47 61 --return-hidden-states-mode full`:
  - shapes are `[L, 25600]` (aux) and `[L, 5120]` (last hidden) for L = 7 to 4096;
  - the captured aux rows equal what this PR returns through `return_hidden_states` (max abs diff 0.0);
  - `lm_head` of the last kept hidden state picks the token the server samples greedily.
- On the GPU image, this PR's tests pass together with the #43448 and #43450 suites and `test_auxiliary_output.py` (75 passed).

## Speed Tests and Profiling

With auxiliary capture disabled, `last_hidden_states` stays `None`; existing hidden-state outputs retain their behavior. Enabled full capture retains the final-layer tensor alongside the auxiliary output for in-process consumers. The latest revision has not received a new GPU performance or memory benchmark.

Historical measurement together with #43450 (see the `bench_serving` A/B there) found parity with main on Qwen3.8-27B for both decode and prefill. That result predates the latest cleanup, rebase, and output-alignment fixes.
