# [Fix] hicache: settle storage backups at the agreed written prefix and retry the tail

[Upstream PR](https://github.com/sgl-project/sglang/pull/47626) · state: open · merged: False

## Original PR description

## Motivation

Fixes #39444 (leg 1) and #47481.

A HiCache storage backup is written in 128-page batches. When a batch fails, `HiCacheController._page_backup` stops and the operation is acked with `completed_tokens` short of the request (`python/sglang/srt/managers/cache_controller.py:1513-1533`). The tree's ack drain then treated the operation as complete: in buffer mode `BufferModePipeline.finish_storage_write_ack` fed existence beliefs for every key of the write and freed the staging; in cache mode `_drain_backup` released the node's host lock. The unwritten tail was believed stored, nothing re-wrote it, and a later prefetch of that prefix stopped at the failed batch. Issue #39444 describes this on both host memory modes.

Under host capacity pressure a write-through backup can also fail before any storage write: `_execute_kv_backup` returns None when `evict_host(needed)` cannot free enough host staging and `_execute_and_commit_kv_backup` returned 0. The node then stayed device-only until a later insert hit it again, which under pressure usually means it was LRU-evicted first. Issue #47481 reports the hit-rate dip this produces.

The rank-safety constraint shapes the fix. Backup submission and acks have no collective of their own; the drain pairs operations by position across ranks after a MIN of the ack-queue sizes (`_sync_hicache_ready_counts` / `_drain_queue`). A storage write can fail on one rank only, so a retry decided from a rank-local `completed_tokens` would re-enqueue a tail on that rank alone and desync the ack pairing for good. Any retry of a storage-failed tail therefore needs an agreed trigger. The host-allocation failure is different: it is decided at the existing write-through decision point from host-pool state, so a tick retry needs no agreement of its own (it inherits exactly the rank behaviour that decision already has, see D3).

Relation to other PRs: #39701 (open) retries a failed batch inside the backup worker with a short backoff, marks terminal failure on the operation and adds a failed-tokens counter. This PR keeps the worker unchanged and moves the retry to the scheduler-thread drain because only the drain can make the decision identical on every rank; the terminal-failure accounting and the metric idea are kept (the counter name here is `sglang:hicache_storage_backup_failed_tokens_total`). The tail retry here is immediate (re-enqueued in the drain, picked up by the next worker loop), so it targets single-batch failures; a worker-side backoff such as #39701's remains the complement for outages longer than a few milliseconds, where all attempts would land in the same window. #38316 proposed an all_reduce of `completed_tokens` per operation at the drain; its review found that MLA `backup_skip` ranks report 0, which a MIN would turn into a zero verdict for every write. This PR reduces once per drain, not per operation, and makes non-writer ranks vote the requested length.

## Modifications

Truthful completion (D1).

- The drain reads nothing from an acked operation except `id` and `completed_tokens`, which every controller provides (a native controller's operation exposes no more). The requested KV span, the host indices, token ids, hash chain, prefix keys and riding sidecars of each write come from a scheduler-side record: cache mode stores a `_StorageWriteSpec` (`python/sglang/srt/mem_cache/unified_radix_cache.py:196-209`) per operation id next to the unchanged `ongoing_backup` tuple when `write_backup_storage` submits (`unified_radix_cache.py:2291-2301`; cleared with the backups at reset and detach, `unified_cache/storage_attachment.py:456`); buffer mode derives the same record from its `_UnifiedBufferBackupEntry` (`unified_radix_cache.py:3620-3639`, entry fields `buffer_mode/pipeline.py:131-132`). A write with no KV pages (an aux-pool-only buffer intent) has no record and settles whole, as today.
- `_drain_backup` (`unified_radix_cache.py:3527-3577`) collects the `n_backup` acked operations, computes each rank's written prefix (`min(completed_tokens, requested)`), MIN-reduces the packed vector once, checks the agreed value is a page-aligned prefix of the request (raising on every rank in the same tick otherwise, `3565-3569`) and settles every operation through `_finish_backup_ack` (`3647-3726`) at the agreed value.
- A rank that is not the KV storage writer (`cache_controller.backup_skip`, replicated MLA KV written by one TP rank) votes the requested span (`unified_radix_cache.py:3544-3549`): its `completed_tokens` carries no KV evidence, so the MIN is the writer's prefix and non-writers never look like failures. Its own rank-sharded sidecars (Mamba/draft on skip ranks) are still written whole by the first attempt; a failed sidecar write there is now logged by the hybrid controller (`hybrid_cache/hybrid_cache_controller.py:1743-1751`) and is not retried, since the KV tail retry cannot carry a transfer with its own staging.
- In buffer mode `BufferModePipeline.finish_storage_write_ack` takes the agreed `written_pages` and feeds beliefs only for `keys[written_so_far : +written_pages]` of every pool the write carried (`pipeline.py:1215-1247`; a KV write's pools all share the KV key list). In cache mode the host lock is released only when the operation is final. The tree has no per-node "stored in L3" flag in cache mode, so keeping the lock and not counting the tail is the whole of the state to keep consistent there. The `backuped_tokens` metric logs what this rank wrote of the agreed prefix; a retried tail is logged by its own ack. Terminal failures log `sglang:hicache_storage_backup_failed_tokens_total` once (`observability/metrics_collector.py:2301-2307, 2406-2410`) and one error line; a stale ack whose write was already dropped by reset or detach settles silently and is not counted.

Agreed tail retry (D2).

- Once per drain, when backups were acked in that tick, `_drain_backup` runs one packed MIN (`unified_radix_cache.py:3554-3563`) through `_all_reduce_storage_drain` (`3616-3624`), which uses the same reduction as the count sync: every TP rank of each PP stage in buffer_only mode, else PP0's TP verdict propagated along PP. `n_backup` is already the agreed MIN count, so the tensor has the same shape on every rank, and every rank enters or skips the collective together. The local detach drain (`drain_storage_control_queues_local`, `n_backup=None`) enters no collective and never retries.
- When the agreed prefix is short of the request and the node span has fewer than `STORAGE_BACKUP_MAX_RETRIES = 2` (`unified_radix_cache.py:185`) re-enqueues, `_enqueue_backup_tail` (`3728-3751`) calls `write_storage` for `host_indices[written:]`, `hash_value[written_pages:]`, the prefix keys extended by the written pages, and bare copies of the sidecars that ride the KV pages (the controller re-resolves them against the tail). Every input is the write's own scheduler-side record plus the agreed count, so all ranks enqueue the same tail in the same order. Buffer mode keeps the staging and the in-flight marks and re-registers its entry under the new operation id with `attempts + 1` and the advanced `written_pages` (`pipeline.py:1239-1243`); cache mode moves the `ongoing_backup` tuple (host lock still held) and the advanced record to the new id (`unified_radix_cache.py:3691-3703`).
- Past the bound the tail is given up: counted, logged once, the staging freed (buffer) or the host lock released (cache), and the in-flight marks dropped so the tail reads as absent and the next insert of the span writes it again.
- This adds one packed gloo collective per tick, only in ticks that acked backups. It replaces nothing; it is the only rank-safe trigger for a retry given the positional ack pairing. This is the explicit design point for review.

Host-capacity retry (D3).

- `_execute_and_commit_kv_backup` parks the action's trigger node when `_execute_kv_backup` returns None for a write-through backup (`unified_radix_cache.py:1929-1936`; `_defer_backup_for_host_capacity` at `1948-1975`). The parked node is kept alive by a device lock (`_ParkedBackup`, `212-217`) rather than by a liveness probe, so no new tree-core interface is needed; `_retry_host_capacity_backups` (`1976-1996`) runs at the start of `check_hicache_events` (`4182-4188`) so the flush that follows submits the D2H with the rest, releases the park lock, skips a node a later hit already backed up, and re-runs the backup with the same bound (two retries, then one error line). Each retry increments `sglang:hicache_storage_backup_host_capacity_retries_total` (`metrics_collector.py:2309-2315, 2412-2413`). The counter lives on the storage metrics collector, so a write-through deployment without an L3 backend does not emit it; the retry itself runs regardless. The park is idempotent: a later insert that hits the parked node (still not backuped, so the hit fires its own `BackupKV`) and fails on host staging again returns early (`unified_radix_cache.py:1958-1963`), keeping the one device lock and the retry count the park already holds until the tick retry runs, instead of parking a second time and leaking the first lock.
- Rank behaviour: the park inherits the existing write-through decision point as it is. It follows the same host-pool reads (`available_size`, `evict_host`, the controller's staging alloc) that decide the backup today, so it is rank-identical whenever host frees are lockstep. The hybrid controller frees prefetch staging from worker threads (`hybrid_cache_controller.py:837-843, 1247-1252`), the divergence `writing_check` already tolerates for `ongoing_write_through` (`unified_radix_cache.py:3982-3983`); a rank that parks alone retries alone, without any collective, and catches up with its peer on a later tick instead of dropping the node. No assertion is added on this state because the pre-existing code tolerates the transient on purpose.

Compatibility with controller and tree-core subclasses.

- `ongoing_backup` keeps its `dict[int, tuple[NodeId, DecLockRefParams]]` shape; the retry state lives in a separate dict. No abstract method is added to `UnifiedTreeCoreInterface`. `StorageOperation` is unchanged. A controller that pumps completions on the scheduler thread needs only `id` and `completed_tokens` on its operation objects, `backup_skip`, and the `write_storage(host_indices, token_ids, hash_value, prefix_keys, extra_pools=)` / `extend_storage_prefix` it already serves the first attempt with.

No new configuration knob. The retry bound is a module constant.

## Accuracy Tests

New file `test/registered/unit/mem_cache/test_hicache_backup_retry.py` (CPU, `register_cpu_ci`): a real `UnifiedRadixCache`, a real `HybridCacheController` with its backup thread and the real file backend behind a deterministic proxy that fails the batch carrying chosen keys; only the D2H transfer engine is faked.

- `test_failed_batch_feeds_prefix_beliefs_then_retries_tail` (buffer_only): after the first ack only the 128-page prefix is believed, the tail is in flight again as one operation of 172 pages with `hash_value == chain[128:]`, the staging is kept; after the retry every page is believed and present in the backend, the staging is freed, `backuped_tokens` logged 128 then 172, no failure counted.
- `test_retries_exhausted_counts_terminal_failure` (buffer_only): three write attempts (`[(300, 300), (172, 172), (172, 172)]`), exactly one "gave up" error line, `storage_backup_failed_tokens(172)` once, the prefix believed, the tail neither believed nor in flight, the backend holds 128 pages, no further enqueue in later ticks.
- `test_retried_from_tick_once_capacity_returns` (cache mode, real `StorageMetricsCollector`): a write-through backup short on host staging is parked under a device lock, retried once while still short, backed up on the tick after the host memory is freed with the park lock released, the chained L3 write completes, the retries counter reads 2.
- `test_tail_is_sliced_by_pages` (buffer_only, page_size 4): the same single-batch failure on a 300-page span of 1200 tokens; the re-enqueued tail carries `host_indices[512:]`, `token_ids[512:]` and `hash_value == chain[128:]` (the slice is pages times page size), the agreed 512-token count passes the page-alignment check in the drain, `backuped_tokens` logged 512 then 688, every page ends up believed and present.
- `test_bound_gives_up_with_one_error` (cache mode): two failed tick retries, one error line, the park lock released, the node is not retried again once capacity returns.
- `test_hit_while_parked_keeps_one_lock_and_one_entry` (cache mode): with the node parked, a second insert of the span goes through the real insert path (`write_through_threshold` 1, `_inc_hit_count_and_check` fires a `BackupKV`), `_execute_kv_backup` runs once more and fails again; the park still has one entry at attempt 0 and the node's device lock is exactly one above the baseline (two without the idempotent park); the next tick counts attempt 1, and after the host memory is freed the node is backed up, the park is empty, the lock is back at the baseline and the retries counter read 2.
- `test_rank_local_failure_re_enqueues_the_tail_on_both_ranks` (two-rank gloo, cache mode): only rank 1's backend fails the second batch, once; after every tick the in-flight operation ids, the retry records and every enqueued span are all_gathered and equal on both ranks; both ranks enqueue `[(300, 300), (172, 172)]`; both backends end with all 300 pages; the host lock returns to 0.
- `test_non_writer_rank_vouches_for_the_span` (two-rank gloo, cache mode): rank 1 is made a non-writer (`is_storage_writer` False, so its worker writes nothing and acks with `completed_tokens` 0) while rank 0, the writer, fails the second batch once; the agreed prefix is the writer's 128 pages, not 0, both ranks enqueue the same 172-page tail, rank 0's backend ends with 300 pages and rank 1's with none.

## Speed Tests and Profiling

Not benchmarked. The added cost is one gloo MIN of an `n_backup`-long int64 vector per tick, only in ticks that acked storage backups; the host-capacity retry is a dict walk at the start of the tick, empty in steady state, and holds a device lock on a parked node for one tick. That lock is held from the park until the tick retry runs (at most `STORAGE_BACKUP_MAX_RETRIES` ticks per node), so a parked node is not evictable meanwhile; a hit on the parked node in between adds no second lock. A retried tail re-writes only `[agreed:requested]`; a rank that had written the whole span re-writes that tail idempotently (content-addressed keys).
