# [Fix] sgl-router: Bump rustls to 0.23.46 for RUSTSEC-2026-0346..0349

[Upstream PR](https://github.com/sgl-project/sglang/pull/44509) · state: closed · merged: True

## Original PR description

## Motivation

On 2026-10-14 RustSec published four advisories against rustls < 0.23.46 (advisory-db commit `caee11f41f`):

- RUSTSEC-2026-0346: `Debug` impls for client session values expose TLS secrets
- RUSTSEC-2026-0347: buffered application data sent to the outer server after ECH rejection
- RUSTSEC-2026-0348: Brotli certificate decompression can allocate up to 1 GiB before authentication
- RUSTSEC-2026-0349: an unauthenticated ServerHello can downgrade later connections to classical key exchange

`experimental/sgl-router/Cargo.lock` pins rustls 0.23.45, unchanged since #39457. `cargo deny check advisories` fetches the advisory database on every run, so the router's tier-1 lint now fails on every PR that runs router CI, with no code change involved. Example: https://github.com/sgl-project/sglang/actions/runs/38679761043/job/116241458548 (#42674). Main's own router runs look green only because their tiers are skipped.

## Changes

Lockfile only, via `cargo update -p rustls`: rustls 0.23.45 → 0.23.46. The new rustls depends on getrandom 0.3.4, which is already in the lockfile, so no package is added.

## Tests

In `experimental/sgl-router`:
- `cargo deny check licenses bans sources advisories`: advisories ok, bans ok, licenses ok, sources ok. Before this change it failed with the four advisories above.
- `cargo clippy --all-targets --locked -- -D warnings`: clean.
- `cargo test --locked`: lib 1083, component 138, proxy 211, all passing.

Not in scope: `rust/Cargo.lock` pins rustls 0.23.43, which is also affected, but no CI job runs `cargo deny` on that workspace.
