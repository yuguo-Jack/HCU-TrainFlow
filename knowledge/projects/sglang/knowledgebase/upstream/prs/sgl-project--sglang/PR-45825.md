# [Fix] [XPU] attention: Enable fp8 KV cache and quiet startup logs

[Upstream PR](https://github.com/sgl-project/sglang/pull/45825) · state: closed · merged: False

## Original PR description

## Motivation

Two XPU startup issues with recent nightlies:

1. The `intel_xpu` attention backend had fp8 KV cache hard-disabled, so
   serving any model with `--kv-cache-dtype fp8_e4m3` crashed on the first
   forward pass with `RuntimeError: fp8 KV cache requires k_descale and
   v_descale`.
2. Every XPU launch printed a wall of warnings that only apply to CUDA
   builds, making real problems easy to miss.

## Modifications

**fp8 KV cache (`xpu_backend.py`)** — re-enable the descale path in both
`forward_extend` and `forward_decode`, accounting for two ways
`sgl-kernel-xpu` differs from fa3:
- Its fp8 KV kernels always require `k_descale`/`v_descale`. When the
  checkpoint carries no KV scales (`layer.k_scale is None`), pass a `1.0`
  descale, which matches how an unscaled fp8 cache is written.
- Its MHA kernels take a bf16 query, so the `q`/`q_rope`/`k_rope` fp8 cast
  is kept only on the MLA path. The original comments are preserved.

**Startup log noise** — all off-CUDA only:
- `gguf.py`: emit the "Only CUDA, MUSA and NPU support GGUF" warning when a
  `GGUFConfig` is actually constructed instead of at import time.
- `common.py` + `registry.py` + `multimodal_processor.py`: log skipped
  CUDA-only imports (e.g. `cutlass`) at debug level off CUDA, and filter
  `timm`/PyTorch internal deprecation warnings.
- `arch.py`: demote "Cannot detect CUDA architecture" to debug when no CUDA
  device is present.
- `environ.py`: exempt `sgl-kernel`'s own `SGL_*` variables (which
  `sgl-kernel-xpu` sets on import) from the `SGL_` -> `SGLANG_` deprecation
  rewrite.

## Accuracy Tests

Verified that an fp8 KV cache checkpoint without KV scales no longer crashes
and uses a `1.0` descale consistent with the cache write path. Non-fp8
(bf16/fp16) paths are unchanged.
