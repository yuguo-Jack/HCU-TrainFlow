# [VLM] Reuse Kimi-K3 embeddings before normal-serving preprocessing

[Upstream PR](https://github.com/sgl-project/sglang/pull/34411) · state: closed · merged: False

## Original PR description

## Summary

This PR is now limited to **ordinary serving**. EPD reuse is split into #35033; metrics and the agentic benchmark harness are split into #35034.

- acquires per-image embedding-cache leases on the request final DP route before processor dispatch
- omits a feature only when every required TP rank has pinned the same full feature identity
- transfers lease ownership to the admitted request; consume, cancel, abort, flush, timeout, and one internal cold-path retry release pins safely
- lets repeated Kimi-K3 images skip processor work, feature transport, and ViT in ordinary serving
- keeps CPU, CUDA IPC, and CUDA VMM paths compatible; a featureless hit does not allocate an IPC/VMM proxy or a new fixed HBM pool
- uses typed processor contracts rather than model-name branches or dynamic attribute probing
- adds the canonical VLM preprocessing-cache guide, API examples, model-support guidance, server arguments, and a concise K3 Cookbook reference

## Correctness boundary

False hits fail closed under the default configuration:

- media identity covers the exact bytes plus modality, processor configuration, backend, and per-image preprocess options
- the artifact identity is bound to the processor-output hash; the compact embedding key only selects a candidate and the full feature identity must still match
- K3 namespaces Radix prefix KV by ordered full feature identities, so legacy 30-bit pad-sentinel collisions cannot share language-model KV
- mutable paths and URLs are re-read and re-hashed; same path with changed bytes misses
- partial TP hits, expired leases, and lost leases fall back once to the feature-carrying cold path
- feature-hash disagreement clears the stale processor artifact and rejects reuse
- caller-provided legacy `mm_hashes` cannot redirect artifact, lease, embedding-cache, or Radix identity

`--trust-mm-content-hashes` is the explicit exception: a trusted hot hit can skip reading the media source, so correctness is delegated to the caller. Without it, SGLang reads the actual media bytes, verifies a supplied SHA-256 digest, and rejects mismatches.

## Normal-serving performance

Full real-weight Kimi-K3 (1.56 TB), 2 nodes × 4 NVIDIA GB300, TP8, commit `25eae3c909d7`. Each cell is the median of 3 runs over 32 conversations × 8 turns. The same seeded random image set (512²–2048²) is resent on every turn. Both sides use the same 4096 MiB lazy embedding-cache cap and automatic CUDA VMM/FABRIC feature transport; the A/B switch is K3 auto versus `--mm-preprocess-cache-size-mb 0`.

Four random images, concurrency 32, 16 output tokens:

| Request rate | Output tok/s off → on | Median TTFT off → on | Median E2E off → on |
|---:|---:|---:|---:|
| 1 | 53.29 → 100.14 (+87.9%) | 5846 → 1122 ms (-80.8%) | 6364 → 1479 ms (-76.8%) |
| 4 | 53.83 → 109.46 (+103.3%) | 6128 → 1148 ms (-81.3%) | 6721 → 1482 ms (-78.0%) |
| 8 | 55.53 → 107.57 (+93.7%) | 5830 → 1174 ms (-79.9%) | 6294 → 1502 ms (-76.1%) |
| inf | 54.33 → 106.05 (+95.2%) | 5973 → 1133 ms (-81.0%) | 6366 → 1479 ms (-76.8%) |

The saturated A/B was repeated on the same nodes: duration fell from 75.39 s to 38.62 s, and median hot-turn TTFT fell from 5956 to 1147 ms. Across 896 hot images, processor calls, feature transport, and ViT forwards were all skipped. Aggregate preprocess-stage time fell from 194.28 s to 24.56 s (-87.4%). The CPU cache held 128 entries / 62,692 bytes with no eviction. Peak HBM was 257,304 MiB cache-on versus 265,202 MiB cache-off; this feature adds no fixed HBM reservation.

These numbers establish the cache A/B, not best absolute production throughput: both sides pinned Marlin because the environment automatic TRT-LLM Gen SiTU path hung after one run.
