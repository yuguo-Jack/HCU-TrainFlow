# [Frontend] Expose JSON and SSE completion schemas in OpenAPI

[Upstream PR](https://github.com/sgl-project/sglang/pull/44146) · state: open · merged: False

## Original PR description

## Motivation

`/openapi.json` exposes empty success schemas and no SSE contract for `/v1/chat/completions` and `/v1/completions`. It also advertises 422 although application request validation returns 400.

## Modifications

Reuse native unary/chunk/error models through FastAPI. Publish parsed SSE event schemas, following the OpenAPI 3.1 convention in vllm-project/vllm#60926. Preserve native serialization; add registered CPU tests and documentation. Related #32436 adds a static specification; this change improves the live export.

### Before / after

Captured through the production ASGI app without lifespan or inference, against base `5569b14d26ff`. These excerpts select HTTP 200 content; model definitions and descriptive text are omitted.

Before, both endpoints:

```yaml
application/json:
  schema: {}
# text/event-stream absent
```

After, chat completions:

```yaml
application/json:
  schema:
    $ref: '#/components/schemas/ChatCompletionResponse'
text/event-stream:
  schema:
    type: object
    required: [data]
    properties:
      data:
        type: string
        anyOf:
          - const: '[DONE]'
          - contentMediaType: application/json
            contentSchema:
              $ref: '#/components/schemas/ChatCompletionStreamResponse'
          - contentMediaType: application/json
            contentSchema:
              type: object
              required: [error]
              properties:
                error:
                  $ref: '#/components/schemas/ErrorResponse'
      event: {type: string}
      id: {type: string}
      retry: {type: integer, minimum: 0}
```

For `/v1/completions`, the refs are `CompletionResponse` and `CompletionStreamResponse`. Both chunk models and dependencies are included in `components.schemas`.

| Error declarations | Before | After |
|---|---|---|
| Request validation | 422 / HTTPValidationError | 400 / ErrorResponse |
| Handled serving failure | Absent | 500 / ErrorResponse |
| Other errors | Unspecified | Default response, body unspecified |

SSE `schema` describes **one parsed event**, not the raw HTTP body. Consumers must parse SSE, handle `[DONE]`, then decode JSON and explicitly validate `contentSchema`; ordinary JSON Schema validation does not enforce these annotations. OpenAPI stays 3.1.0, without 3.2 `itemSchema`.
