# [DSA] Support TileLang FP8 KV cache on CUDA

[Upstream PR](https://github.com/sgl-project/sglang/pull/42957) · state: closed · merged: True

## Original PR description

<!-- Thank you for your contribution! Please follow these guidelines to enhance your pull request. If anything is unclear, submit your PR and reach out to maintainers for assistance. Join our Slack community at https://slack.sglang.io to discuss further. -->

## Motivation

<!-- Describe the purpose and goals of this pull request. -->

Enable TileLang DSA with FP8 KV cache on CUDA, removing the backend restriction and reducing KV memory usage for models such as GLM-5.3-Flash.

## Modifications

<!-- Detail the changes made in this pull request. -->

- Dispatch CUDA FP8 KV to the existing TileLang partial/combine kernels.
- Allocate raw FP8 KV rows without the scaled-cache metadata.
- Disable the incompatible one-shot MHA path and validate backend/layout compatibility.
- Extend existing GPU and configuration tests to cover CUDA FP8 KV and CUDA Graph replay.

Requires TileLang for both DSA prefill and decode; DCP and HiSparse are not supported by this path.

## Accuracy Tests

<!-- If this pull request affects model outputs (e.g., changes to the kernel or model forward code), provide accuracy test results. -->

Validated GLM-5.3-Flash on 4 × H200 with BF16 and FP8 KV, with and without MTP.

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3 sglang serve \
  --model-path /path/to/GLM-5.3-Flash \
  --served-model-name llm \
  --trust-remote-code \
  --tp-size 4 \
  --ep-size 4 \
  --mem-fraction-static 0.75 \
  --max-mamba-cache-size 240 \
  --max-running-requests 48 \
  --chunked-prefill-size 8192 \
  --cuda-graph-backend-prefill breakable \
  --cuda-graph-max-bs-prefill 8192 \
  --cuda-graph-max-bs-decode 48 \
  --dsa-prefill-backend tilelang \
  --dsa-decode-backend tilelang \
  --kv-cache-dtype fp8_e4m3 \
  --moe-runner-backend deep_gemm \
  --moe-a2a-backend none \
  --reasoning-parser glm45 \
  --tool-call-parser glm47 \
  --random-seed 42 \
  --host 0.0.0.0 \
  --port 30000
```

Configuration/GPU tests (13 tests, 4 subtests) and pool-configurator tests (51 tests, 11 subtests) passed.

GSM8K: 1,314 scored questions per run, 5-shot, temperature 0, two runs with Prefill BCG enabled.

| KV dtype | MTP | Run 1 (rounded) | Run 2 (rounded) | Mean |
| --- | --- | --- | --- | --- |
| BF16 | Off | 95.8% | 95.9% | 95.852% |
| FP8 E4M3 | Off | 95.7% | 95.7% | 95.738% |
| BF16 | 5/1/6 | 95.4% | 95.6% | 95.472% |
| FP8 E4M3 | 5/1/6 | 95.2% | 95.2% | 95.205% |

Tested both KV dtypes with EAGLE/MTP516 by adding:

```bash
  --speculative-algorithm EAGLE \
  --speculative-num-steps 5 \
  --speculative-eagle-topk 1 \
  --speculative-num-draft-tokens 6
```

Target and draft KV use the selected dtype. Mean acceptance length was 4.15 for BF16 and 4.16 for FP8; prefill and speculative CUDA Graphs passed.

## Speed Tests and Profiling

<!-- If this pull request impacts inference speed, provide benchmarking and profiling results. -->

4 × H200, TP4/EP4, TileLang DSA, DeepGEMM MoE, EAGLE 5/1/6 and Prefill BCG. Only `--kv-cache-dtype` changes between cases.

Workload: 32,768 input / 1,024 output tokens, concurrency 8, 64 requests. Values are medians of three warmed-up runs, using mean TTFT/TPOT per run and the final KV token capacity reported at startup.

| KV dtype | KV capacity (tokens) | TTFT (ms) | TPOT (ms) | Output throughput (tok/s) |
| --- | ---: | ---: | ---: | ---: |
| BF16 | 607,232 | 2,664.34 | 12.76 | 518.63 |
| FP8 E4M3 | 1,177,856 | 2,804.25 | 13.35 | 495.48 |

FP8 provides **1.94× KV token capacity**. At this fixed concurrency, TTFT increases by 5.3%, TPOT by 4.6%, and output throughput decreases by 4.5%.
