# [Fix] observability: Serialize kv_hints in exported request metrics

[Upstream PR](https://github.com/sgl-project/sglang/pull/48338) · state: open · merged: False

## Original PR description

## Motivation

With `--export-metrics-to-file`, any request that carries `kv_hints` is missing from the exported metrics file.

`GenerateReqInput` normalizes `kv_hints` into a `KvHintsEnvelope` (a `msgspec.Struct`), and `RequestMetricsExporter._format_output_data` passes the request fields to `json.dumps`, which can't encode it:

```
TypeError: Object of type KvHintsEnvelope is not JSON serializable
```

`FileRequestMetricsExporter.write_record` catches the error and only logs it ("Failed to write perf metrics to file"), so the record is silently dropped. `kv_hints` is not in `ALWAYS_EXCLUDE_FIELDS` or the exporter's skip lists.

## Modifications

- `_format_output_data` passes `default=msgspec.to_builtins` to `json.dumps`, so msgspec structs in request fields are written as plain JSON (the envelope's dict form). Types that `msgspec.to_builtins` can't handle still raise `TypeError` as before.
- New `test_serializes_kv_hints_envelope` in `test/registered/unit/observability/test_request_metrics_exporter.py`. It uses a local struct with the same shape as `KvHintsEnvelope`, because this file stubs `sglang.srt.managers` to stay free of heavy imports. It checks that `kv_hints` round-trips to the original dict. It fails on `main` with the `TypeError` above and passes with the change.

I also ran a `write_record` repro with the real `decode_kv_hints_envelope`. On `main` it wrote 1 of 2 records; with the change it writes both, including the `kv_hints` dict.
