## Modifications

<!-- Detail the changes made in this pull request. -->
- Remove the startup rejection for system DP and DP attention. Continue rejecting DP attention local control broadcast, EP, PP, MoE all-to-all, and DCP configurations that remain unsupported.
- Add an internal `prepare_only` request flag. The scheduler performs the existing eligibility, idle-state and decode CUDA graph memory checks, then returns readiness without releasing resources or changing roles.
- For multiple DP workers, the tokenizer sends a shallow copy of the request with `prepare_only=True`, collects all expected DP worker responses, and sends the actual switch only if all are ready. Empty response sets are treated as failure, and a prepare request does not update the tokenizer's role.
- Add unit coverage for startup validation, non-destructive preflight, busy workers, insufficient graph headroom, and successful switching for both system DP and attention DP.

Staging-buffer compatibility and new PP support are outside its scope.
## Accuracy Tests

<!-- If this pull request affects model outputs (e.g., changes to the kernel or model forward code), provide accuracy test results. -->
Full GSM8K evaluation with **prefill CUDA graphs disabled on both instances from startup** (`--disable-prefill-cuda-graph`). Decode CUDA graphs remain enabled. The GPU accuracy results below cover **Qwen3.5-0.8B with attention DP** under this configuration.
Every phase evaluates all **1,319 test examples**. The first five training examples are used as few-shot demonstrations; no test example is used as a demonstration.

Model: Qwen3.5-0.8B, real local weights.
Parallelism: `--tp-size 2 --attn-dp-size 2` per instance, system DP size 1 and attention TP size 1. Two instances use four NVIDIA A10 GPUs on an eight-GPU host.
