# [Feat] tracing: Don't trace health checks

[Upstream PR](https://github.com/sgl-project/sglang/pull/45627) · state: open · merged: False

## Original PR description

## Motivation

`/health` and `/health_generate` submit a one-token generation request (rid `HEALTH_CHECK_<uuid>`), and the tokenizer traces it like any user request: root span, tokenizer and scheduler spans. With tracing on, every probe of every server adds a full trace, burying user requests in trace search and sampling.

## Modifications

`init_trace_ctx` gives `HEALTH_CHECK_*` rids a null trace context, in both sync and async tracing, so health checks create no spans. `request_metrics_exporter` already skips these rids for the same reason (they are not user requests).

Docs: a note in `production_request_trace.mdx`.

### Behavior changes

Health check requests are no longer traced.

## Accuracy Tests

Not applicable: tracing only, no change to model outputs.

## Speed Tests and Profiling

Not benchmarked. A health check now skips trace setup entirely.

## Tests

- `test_req_time_stats.py::TestInitTraceCtx::test_health_checks_are_not_traced`: a `HEALTH_CHECK_*` rid gets a null context, and a normal rid still gets a trace context.
