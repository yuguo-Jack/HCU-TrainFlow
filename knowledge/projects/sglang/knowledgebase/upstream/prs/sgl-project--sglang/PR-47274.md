# [Fix] glm5_next: clone RunAI-streamed q_a/kv_a projections before fusing (#37369)

[Upstream PR](https://github.com/sgl-project/sglang/pull/47274) · state: open · merged: False

## Original PR description

  ## Motivation

  Fixes #37369.

  With `--load-format runai_streamer`, `Glm5NextForConditionalGeneration.load_weights` stores whichever of `q_a_proj` / `kv_a_proj_with_mqa` arrives first in `cached_a_proj`, then concatenates the two into `fused_qkv_a_proj_with_mqa` once the second one arrives. The RunAI streamer yields views into a staging buffer that it reuses for later tensors,
  so the cached projection can be overwritten before the fusion happens. The result is a corrupted fused MLA weight and garbage output.

  The DeepSeek loader already copies streamed tensors it holds onto, using `_clone_if_runai_streamed_tensor`. The GLM-5 Next loader did not. The same path also loads the DFLASH draft model.

  This is a minimal version of #37370 (closed without merging). Instead of adding a new module, it reuses the existing helper.

  ## Modifications

  - `python/sglang/srt/models/glm5_next.py`: store `_clone_if_runai_streamed_tensor(loaded_weight)` in `cached_a_proj`. Tensors that the RunAI streamer did not mark are stored as before, without a copy.
  - `test/registered/unit/models/test_glm5_next_runai_ownership.py`: a CPU-only regression test. It streams `q_a_proj` and `kv_a_proj_with_mqa` through one reused, RunAI-marked buffer and checks that `fused_qkv_a_proj_with_mqa == cat(q_a, kv_a)`. It fails on `main` with `Mismatched elements: 12 / 24 (50.0%)` and passes with this change.

  ## Accuracy Tests

  No change to model forward code. This only fixes which weights get loaded under `runai_streamer`; loading from local files is unchanged.

  ## Speed Tests and Profiling

  The extra copy only happens for RunAI-streamed `q_a_proj` / `kv_a_proj_with_mqa` tensors. Each copy is kept only until its partner arrives, so at most one a-projection per layer is held at a time. Other load formats are unaffected.
