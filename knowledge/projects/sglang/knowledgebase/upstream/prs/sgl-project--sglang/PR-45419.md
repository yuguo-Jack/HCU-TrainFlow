# [Fix] [Apple] mlx: Give the stub model a shared-expert layout

[Upstream PR](https://github.com/sgl-project/sglang/pull/45419) · state: closed · merged: True

## Original PR description

## Motivation

Since #44913, every MLX server crashes during startup:

```
File ".../model_executor/runner/base_runner.py", line 250, in model_context
    shared_experts=self.model_runner.model.shared_experts_config
AttributeError: '_DummyModel' object has no attribute 'shared_experts_config'
```

#44913 made the eager and graph runners read `model.shared_experts_config` during warmup. The Torch model loader sets it on every model, but the MLX stub replaces the model with `_DummyModel`, which never had it.

## Modifications

- Give `_DummyModel` a default `SharedExpertsConfig()`. The stub builds no Torch MoE layers, so there is nothing to fuse. This is the same value the loader resolves for a model with no shared-expert hooks.
- Add a regression test that runs `BaseRunner.model_context` on the stub's model.

## Accuracy Tests

Apple M2 Max, `mlx-community/Qwen3-0.6B-4bit`:

- Before: `SGLANG_USE_MLX=1 python -m sglang.launch_server --model-path mlx-community/Qwen3-0.6B-4bit --disable-cuda-graph` exits with the error above.
- After: the server starts, and `/generate` and `/v1/chat/completions` return normal output.
- `SGLANG_USE_MLX=1 pytest test/registered/unit/hardware_backend/mlx`: 226 passed. The new test fails on `main` with the same `AttributeError`.
