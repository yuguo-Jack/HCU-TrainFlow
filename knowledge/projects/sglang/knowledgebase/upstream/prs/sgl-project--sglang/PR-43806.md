# [UMBP] Share one direct-linker key across CP ranks for DeepSeek-V4 pools

[Upstream PR](https://github.com/sgl-project/sglang/pull/43806) · state: open · merged: False

## Original PR description

## Motivation

DeepSeek-V4 prefill CP gathers the whole chunk onto every CP rank before caching it (`cp_materialize_global_token_order` in `deepseek_v4.py` and `dsv4/compressor.py`), so all attention CP ranks hold byte-identical pages. The UMBP direct linker drops the TP term for such rank-replicated pools but keeps `cp{attn_cp_rank}` in every key, so the tier stores `attn_cp_size` copies of each page.

With PCP4, the UMBP linker logs a different suffix per CP rank (`cp0_pp0` .. `cp3_pp0`) for byte-identical pages.

## Plan

1. This PR: the UMBP direct linker shares one key across CP ranks for DeepSeek-V4.
2. Mooncake direct linker: its single-writer rule (`tp_rank == 0`) must cover CP first. Follow-up.
3. DSA (DeepSeek-V3.2 / GLM): stays per CP rank until its CP replication is verified. Follow-up.

## Modifications

- `DevicePoolGroup` gets `cp_replicated` (default `False`); only the DeepSeek-V4 group sets it.
- UMBP `_storage_suffix` uses `cp0` for such groups, so non-CP keys are unchanged and CP and non-CP deployments share pages.
- Every rank still writes; a shared tier keeps one copy per key (`kSuccessAlreadyExists` in mori `page_backend.cpp`). CP ranks already agree on the hit length via `_all_reduce_attn_groups`.

## Tests

`test_umbp_direct_linker_rank_keys.py` and `test_linker_pool_assembler.py`: 17 passed; the new cases fail on `main`.
