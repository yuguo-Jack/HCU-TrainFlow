# [Chore] [NVIDIA] deep_select: List SM107 as supported

[Upstream PR](https://github.com/sgl-project/sglang/pull/48266) · state: closed · merged: True

## Original PR description

## Motivation

DeepSelect's support list (`SUPPORTED_CUDA_ARCHS` and the `attention.deep_select_topk` registry entry) names SM90, SM100 and SM103, but the DeepSeek-V4.1 indexer already runs DeepSelect on SM107 (CC 10.7): the prefill top-k (`v41_indexer/scoring.py:topk_ragged`) and the paged decode top-k (`dsv4/indexer.py:topk_transform_paged_bf16`) call it directly without consulting the list. On SM107 the list only causes `test_deep_select.py` to skip, so the kernel that serves those paths has no test coverage there.

## Modifications

- Add `(10, 7)` to `SUPPORTED_CUDA_ARCHS` and to the registry entry's capabilities, and the matching row to `test_kernels_namespace.py`.
- Update the skip reason and the two comments that list the architectures.

No serving path changes. The other reader of the list, `FullTopKIndexer.use_deep_select_decode`, is `not use_deep_gemm_decode and is_deep_select_supported()`, and `use_deep_gemm_decode` is `is_sm100_or_newer()`, which is already true on SM107. The cluster tiers are chosen by an occupancy query, not by architecture.

## Accuracy Tests
