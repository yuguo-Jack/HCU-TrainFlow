# [Fix] function_call: Stream prose that arrives in the same delta as the first tool call

[Upstream PR](https://github.com/sgl-project/sglang/pull/47753) · state: open · merged: False

## Original PR description

## Motivation

When the text before the first tool-call marker arrives in the **same
streaming delta** as the call itself, `BaseFormatDetector` drops it. The
increment starts parsing at `current_text.find(self.bot_token)`, and when the
call completes the buffer is reset to the remainder *after* the JSON — the
prefix is never emitted as `normal_text`.

Multi-token deltas make this the common case, not an edge case: a larger
`--stream-interval` (documented as the throughput knob) and speculative
decoding / MTP batch several tokens per delta. Reproduced offline with
`FunctionCallParser` on current `main`:

```python
# one delta: 'Sure! <tool_call>\n{"name": "get_weather", "arguments": {"city": "SF"}}\n</tool_call>'
# streaming: normal_text=''        <- 'Sure!' silently dropped
# detect_and_parse: normal_text='Sure!', one complete call
```

`KimiK2Detector` already drains text before its start token as normal text
(`_locate_tool_call_start`); the shared base detector does not, so every
detector relying on `BaseFormatDetector.parse_streaming_increment` (e.g.
`qwen25`) loses the prose.

## Modifications

- `BaseFormatDetector.parse_streaming_increment`: at the entry of the
  tool-call branch, if a non-whitespace prefix precedes the **first**
  `bot_token`, trim it into the result's `normal_text` and process the call in
  the same increment (single bounded recursion — after the trim, `bot_pos ==
  0`).
- Scoped to `current_tool_id == -1`, so markup between later calls stays
  suppressed and cannot leak into content.
- Whitespace-only prefixes keep the old drop behavior, so constrained
  pure-JSON output (`JsonArrayParser`, `tool_choice="required"`) gains no
  content chunks — covered by a dedicated test.
- Detectors with custom streaming (deepseekv3, glm, kimik2, ...) are
  unaffected; `finish()` behavior is unchanged.

## Tests

Offline unit tests (no server, no model loading), added to the existing
classes:

- `TestQwen25Detector.test_streaming_prefix_text_arriving_with_tool_call`:
  prose + call in one delta streams `Sure! ` and the complete call.
- `TestQwen25Detector.test_streaming_whitespace_only_prefix_stays_unstreamed`:
  whitespace-only prefix produces no content chunk.
- `TestQwen25Detector.test_streaming_inter_call_markup_not_streamed_as_content`:
  markup between two calls does not leak into streamed content.
- `TestJsonArrayParser.test_whitespace_prefix_before_array_stays_unstreamed`:
  constrained pure-JSON output keeps the old behavior.

The full `test/registered/unit/function_call/` suite was run against both
unmodified `main` and this branch: identical results apart from the new tests
(561 → 565 passed, the 4 pre-existing environment-bound failures and 18
xgrammar-stub errors unchanged) — no regressions.
