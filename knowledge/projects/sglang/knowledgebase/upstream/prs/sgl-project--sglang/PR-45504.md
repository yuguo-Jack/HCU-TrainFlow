# [Refactor] spec: Move platform dispatch and Triton kernels into `kernels/ops`

[Upstream PR](https://github.com/sgl-project/sglang/pull/45504) · state: closed · merged: True

## Original PR description

- Cache locs: add `fill_front_out_cache_loc_func` and `assign_draft_cache_locs_contiguous_func` in `kernels/ops/speculative/cache_locs.py`, each dispatching to the Triton kernel or the `sgl_kernel` CPU op; `move_accept_tokens_to_target_kvcache` and the draft cache-loc assignment call them, and `spec_utils` drops its CPU-op imports, `next_power_of_2`, and the unused `assign_extend_cache_locs` forward
- Move Triton kernels out of `srt`: `compute_dflash_correct_drafts_and_bonus` to `kernels/ops/speculative/dflash.py` (so `dspark_accept` no longer imports it from `srt`), `table_qk_norm_rope_` to `kernels/ops/attention/table_qk_norm_rope.py`, and `uno_tree.py` to `kernels/ops/speculative/uno_tree.py` unchanged
- Add `reconstruct_indices_from_tree_mask_func` in `reconstruct_tree.py` (Triton on XPU, the compiled op elsewhere); `ngram_worker` drops its per-platform imports
- Move `TreeMaskMode`, the tree-build and greedy-verify Triton launchers, and `verify_tree_greedy_func` into `kernels/ops/speculative/spec_tree.py`, and split the platform dispatch out of `build_tree_kernel_efficient` into `build_tree_kernel_efficient_func`; `eagle_utils` keeps the mask allocation
- Resolve the speculative sampling ops once per platform in `kernels/ops/sampling/renorm.py` (`top_k_renorm_prob`, `top_p_renorm_prob`) and `kernels/ops/speculative/verify_sampling.py` (`tree_speculative_sampling_target_only`, `chain_speculative_sampling_triton`), `None` where a platform has no kernel; DFlash and EAGLE import from there instead of each keeping its own table
- Remove dead code: the unused cache-loc kernels `align_evict_mask_to_page_size`, `get_src_tgt_cache_loc`, `get_target_cache_loc`, and `filter_finished_cache_loc_kernel` with their `spec_utils` forwards (and the unused `assign_req_to_token_pool` forward), `create_num_accept_tokens_filter`, `compute_ragged_extend_lengths`, `read_draft_checkpoint_gamma`, and the decoupled-spec request-id codec, `DraftControlInbox`, and `ReadyDraftControls`, which only their tests used
- Register the new entry points; `test_next_verify_prep.py` calls the draft wrapper over a smaller matrix; `test_graph_pool_borrow.py` patches the sampling op where `eagle_utils` binds it; drop `test_decoupled_spec_io.py`, whose schema has no production caller

No behavior change on CUDA. Elsewhere: on NPU, DFlash's target-probability renormalization uses the `sgl_kernel_npu` ops EAGLE already uses, with the `torch_npu` path as fallback; on CPU the draft assignment passes `window_cols`, which equals `num_steps` there.
