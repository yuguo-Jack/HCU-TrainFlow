# [Perf] [NVIDIA] qwen3.8: Fuse MoE finalize with the shared-expert gate

[Upstream PR](https://github.com/sgl-project/sglang/pull/46632) · state: open · merged: False

## Original PR description

## Motivation

In Qwen3.8's NVFP4 MoE block, the routed-expert finalize kernel and the shared-expert sigmoid gate + add run as two serial, latency-bound kernels on the critical path (~12.7 µs + 2.7 µs per layer at 256 tokens).

## Modifications

- Use the existing deferred-finalize output (`do_finalize=False`) and add one Triton kernel that does the top-k weighted gather-sum, the sigmoid gate and the shared-expert add.
- The kernel keeps the same FP32 accumulation order over k, rounds the routed sum to BF16 first, and reduces the gate with the same block size as the existing gate kernel, so the output is bitwise identical.
- Enabled by default for the measured shape (CUDA, BF16, hidden 2560, top-10); other shapes and FP32 expert weights keep the existing path.
- Tests: bitwise vs the unfused pair over production shapes with padded expert maps and strided GEMM output, CUDA graph replay, and the FP32 fallback.

## Accuracy Tests

Bitwise identical to the unfused finalize + gate/add for 1–8192 tokens with synthetic weights, and with the real FlashInfer NVFP4 MoE at 64/256/384/1024 tokens.

## Speed Tests and Profiling

All numbers: Qwen3.8-Flash-Next-NVFP4 on one Rubin (VR200) GPU, TP1, FP8 KV cache, NEXTN MTP (3 steps, 4 draft tokens), CUDA graphs on.

- MoE tail per layer: 12.7 → 3.4 µs; full MoE layer in a CUDA graph at 256 tokens: 172.7 → 162.3 µs.
- Decode step (concurrency 64, 8K, same node): 18.22 → 17.65 ms (−3.1%); repeated baseline 18.24 ms.
