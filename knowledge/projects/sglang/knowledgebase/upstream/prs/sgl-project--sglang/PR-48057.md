# [Perf] [AMD] distributed: Add opt-in AITER QuickReduce-first policy

[Upstream PR](https://github.com/sgl-project/sglang/pull/48057) · state: closed · merged: False

## Original PR description

## Motivation

SGLang currently uses its in-tree QuickReduce implementation on ROCm and considers QuickReduce only after custom all-reduce during collective selection. AITER also provides a native QuickReduce implementation with its own supported-shape checks, quantization settings, and kernel thresholds.

This PR adds an opt-in path that uses AITER's native QuickReduce communicator for tensor-parallel groups and considers eligible QuickReduce operations before custom all-reduce. AITER leaves QuickReduce disabled unless `AITER_QUICK_REDUCE_QUANTIZATION` selects a codec. The intended setting for this path is `INT4`. This matches AITER's intended selection policy while leaving SGLang's default communicator and ordering unchanged.

## Modifications

- Add `SGLANG_USE_AITER_QUICK_REDUCE`, default off, through SGLang's typed environment-variable interface.
- When enabled on a HIP tensor-parallel group, initialize QuickReduce from `aiter.dist.device_communicators.quick_all_reduce`.
- Prefer an eligible AITER QuickReduce operation before custom all-reduce. Unsupported shapes continue through the existing communicator selection chain.
- Fall back to SGLang's in-tree QuickReduce implementation and default ordering if the AITER QuickReduce module is unavailable.
- Keep non-TP groups, non-HIP platforms, and the default-off path unchanged.
- Enable the path with `SGLANG_USE_AITER_QUICK_REDUCE=1` and `AITER_QUICK_REDUCE_QUANTIZATION=INT4`. The first switch selects AITER QuickReduce. The second configures and enables its INT4 codec.
- Add CPU unit coverage for the HIP/TP opt-in gate, default-off behavior, QuickReduce-first ordering, and unsupported-shape fallback.
