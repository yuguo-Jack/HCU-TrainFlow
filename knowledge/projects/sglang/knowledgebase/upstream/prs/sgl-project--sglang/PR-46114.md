# [Perf] mem_cache: Anchor session refs at the prompt end, with a configurable session header (opt-in)

[Upstream PR](https://github.com/sgl-project/sglang/pull/46114) · state: open · merged: False

## Original PR description

Stacked on #45620; review the last commit.

## Motivation

With `--enable-session-radix-cache`, a finished request references the leaf its output ended on. Many multi-turn clients resend the conversation history on the next turn, with the assistant turn re-rendered, instead of extending the generated output. For those clients:

- each session keeps adding referenced dead branches;
- the window the next turn actually matches, at the end of the previous prompt, stays unreferenced;
- on hybrid sliding-window models with HiCache, the referenced dead branches fill the SWA host tier, and the windows the next turns need are evicted;
- after an idle gap, the next turn then recomputes its whole context.

This PR places a session's single reference at the end of its last prompt and releases its other references. Older prompt ends and outputs become ordinary LRU entries, evicted first on device and host. Server-managed sessions (`session_params`) extend the previous output, so they are unchanged.

Clients and proxies carry the conversation id in different headers. On top of #45620, which fills a missing `session_id` from `X-Session-ID`, the header name becomes configurable, as sgl-router's `--session-id-header` already is.

#45430 protects the prompt-end windows of running requests on device. This PR keeps a finished session's window on device and on the host tier, across idle gaps.

Related: #41865 refreshes a parent session's cached tail on subagent requests, and #35515 evicts a branch's trailing sliding window last in the SWA radix cache.

## How to enable

```bash
python -m sglang.launch_server ... --enable-session-radix-cache
SGLANG_OPT_SESSION_REF_PROMPT_TAIL=1            # default off
SGLANG_SESSION_ID_HEADER=x-my-session-header    # default x-session-id; empty disables the header
```

Requests carry a session id, either `session_id` in the body or the session header.

## Performance

Muse-Spark-Open NVFP4, 4x GB300, TP4/EP4, FP8 KV cache, DFLASH with 8 draft tokens, HiCache (write-back), at most 44 running requests. Multi-turn long-context sessions at concurrency 64; the client resends each conversation's history. Both arms run `--enable-session-radix-cache` with #45620 and the configurable header; the baseline leaves `SGLANG_OPT_SESSION_REF_PROMPT_TAIL` off. Both arms also run the KV split of #46082 and the draft KV on SWA slots of #46116.

## Tests

`test/registered/unit/mem_cache/test_session_unified_radix_cache.py`, 4 new CPU cases on FULL+SWA with a simulated host tier:
- each session holds one ref, at its last prompt end; with the flag off, refs pile up as before; close releases everything;
- after host SWA eviction, each session's next turn still hits its whole previous prompt;
- a turn anchored at the root releases the session's older ref;
- a server-managed session keeps its ref on the output.

`test/registered/cpu/test_request_headers.py`, 1 new case: a configured header replaces the default, and an empty value disables the fallback.

The model math is unchanged; only which prefixes hit the cache changes.
