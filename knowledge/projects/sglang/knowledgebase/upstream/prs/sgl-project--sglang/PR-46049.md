# [Fix] grammar: Give grammar accept failures an error status

[Upstream PR](https://github.com/sgl-project/sglang/pull/46049) · state: closed · merged: True

## Original PR description

## Motivation

A grammar `accept_token` failure in the shared result processor aborts the request with a bare `FINISH_ABORT()`, which has no status code ([L730](https://github.com/sgl-project/sglang/blob/fa622d311d/python/sglang/srt/managers/scheduler_components/batch_result_processor.py#L730), [L872](https://github.com/sgl-project/sglang/blob/fa622d311d/python/sglang/srt/managers/scheduler_components/batch_result_processor.py#L872)). `TokenizerManager._handle_abort_finish_reason` turns an abort into an HTTP error only when its status is 4xx/5xx, so the client receives a 200 whose finish reason is `abort`. The OpenAI streaming path likewise treats it as a graceful abort rather than an error.

The rejected token was sampled under the grammar's own bitmask, so the failure is a server-side fault, such as an FSM/bitmask desync or an xgrammar issue. Other grammar handlers already report it that way: the PD prefill handler (`process_batch_result_disagg_prefill`) and the PD decode prebuilt path both abort with 500. The sampling-mask INVALID failure in the same file does too.

Scope: these two sites run on aggregated servers and on PD decode workers. A PD prefill server never reaches them, because it processes extend results in `process_batch_result_disagg_prefill`. This change therefore does not affect how PD frontends cancel a paired decode request.

This PR originally made prefill send `KVPoll.Failed` to decode on prefill-side aborts. Following the review discussion, that is left to the frontend, and this PR only makes this abort report a status.

## Modifications

Both grammar `accept_token` failure sites abort with `HTTPStatus.INTERNAL_SERVER_ERROR` and `InternalServerError`, with the `accept_token` error as the message. This matches the PD grammar handlers and the sampling-mask failures.

Behavior for an affected request:
- Non-streaming requests get a 500.
- OpenAI streaming requests get an error chunk.
- Native `/generate` streaming carries `status_code` 500 in the final `finish_reason`.

## Accuracy Tests

No numerical change. Only the abort's status and message change.
