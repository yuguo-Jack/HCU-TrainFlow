# [Perf] diffusion: Skip the cross-request cache for Qwen3-VL vision features

[Upstream PR](https://github.com/sgl-project/sglang/pull/47466) · state: closed · merged: True

## Original PR description

## Motivation

For a Qwen-Image-2.1 edit request, the cross-request conditioning cache on `Qwen3VLModel._get_flat_visual_features` cost more than the vision tower it skips (B300, 1024x1024 reference, nsys):

- the lookup hashes `pixel_values` on the host: a 25.9 MB device-to-host copy plus SHA-256 (~22 ms, GPU idle);
- every miss pins fresh host pages for the four 8.6 MB outputs (`cudaHostAlloc` 4 x 6.7 ms) until the 512 MB cache fills;
- the vision tower itself is ~11 ms of GPU work.

With distinct references every request pays both; with the same reference and a new prompt, a hit is no faster than recomputing.

## Modifications

Drop `@cached_conditioning` from `_get_flat_visual_features`. The stage-level entry keyed on the prompt and the reference image and the VAE posterior cache still serve repeated requests.

## Accuracy

Unchanged: the same features are computed instead of restored. Decoded PNG pixels of every request are identical to main (md5 of the RGBA array).

## Benchmark (B300, Qwen-Image-2.1 edit 1024, one GPU, harness-shaped requests, 6 measured)

| | main | this PR |
|---|---|---|
| distinct reference per request (s, median) | 2.604 | 2.562 |
| same reference, new prompt each request (s) | 2.557 (vision cache hit) | 2.555 (recomputed) |

MiniMax-H3 uses the same encoder with 2048-pixel references, where the hashed `pixel_values` are several times larger.

Qwen2.5-VL (`get_image_features`, Qwen-Image-Edit) keeps its cache: that pipeline conditions the VLM on a ~384x384 image, so its `pixel_values` hash is a few ms.
