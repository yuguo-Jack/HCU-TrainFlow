# [Fix] diffusion: LingBot QKV sharing, causal RoPE on no-cache path, uneven split guard

[Upstream PR](https://github.com/sgl-project/sglang/pull/46601) · state: closed · merged: True

## Original PR description

Part of #43875. Split out of #45638 at the maintainers' request; that PR now only has the float32 Plucker change. These three fixes are independent of it.

## Fused QKV made a copy and ignored LoRA and weight updates

- **Bug:** `fuse_qkv_projection` stored a registered `nn.Parameter` copy of `to_q/to_k/to_v` (about +6.3 GB at TP=1 across 40 blocks). After that, `_project_qkv` always used the copy, so in-place LoRA merges and weight copies on the original layers never reached the forward. A weight swap left the copy stale.
- **Fix:** the layers alias one packed buffer, so no second copy is kept and in-place updates land in the fused GEMM. `repack_qkv_projection()` re-packs after a loader replaces `.data`, and `refresh_weight_derived_caches` calls it for every block. The fused path is skipped while a dynamic LoRA is active.
- **Device and dtype moves:** `block.to(dtype=...)`, device moves and layerwise offload give each layer a new weight, which left the packed buffer on the old storage and dtype (`mat1 and mat2 must have the same dtype`). `_project_qkv` now checks that the packed weight and bias still share storage, dtype and device with the layers, and repacks if not.
- **Tests:** shared storage and in-place update visible in the fused output; repack after `.data` replacement; model refresh hook repacks; fused projection after `.to(float64)`.

## Causal attention applied RoPE twice on the no-cache path

On CUDA, flashinfer RoPE rotates `q/k` in place, then the `kv_cache is None` branch passed those rotated tensors to `super().forward`, which rotates again. The model forward always passes a KV cache, so this is latent today. The no-cache return now runs before RoPE. The sequence-shard `NotImplementedError` on that branch was unreachable and is removed.

## Uneven sequence splits with ring and kv-gather

`kvgather_replicated`, `kvgather_sharded` and `ring` assume equal per-rank chunks, and nothing checked the splits. `_check_sequence_split_strategy` now raises `NotImplementedError` for uneven splits on those three. `ulysses` handles uneven splits and is unchanged.
