# [Fix] Propagate profiling failures from all workers

[Upstream PR](https://github.com/sgl-project/sglang/pull/39733) · state: closed · merged: False

## Original PR description

## Motivation

With multiple data-parallel workers, `_execute_profile` waits for all profiling replies but checks only the first one received. A successful reply followed by a failed reply therefore reports success, while the reverse arrival order raises an error. Both `start_profile` and `stop_profile` share this helper.

## Modifications

Aggregate the replies with the existing `FanOutCommunicator.merge_results` helper and raise if any worker fails. Preserve the original first response object when all workers succeed.

Add CPU regressions using the real fan-out communicator for single-worker failure, both reply orders, a failure between successful replies, and all-success response preservation with one, two, and four workers.

## Scope

This reports partial failure; it does not roll back profiling already started on successful workers. It changes neither model outputs nor the inference execution path, so model accuracy and throughput benchmarks are not applicable.

Related #39506 handles snapshot exceptions inside the scheduler profiler; this change handles aggregation of worker responses at the tokenizer and does not modify those files.
