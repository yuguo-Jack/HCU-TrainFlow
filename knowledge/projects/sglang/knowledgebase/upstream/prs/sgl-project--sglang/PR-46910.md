# [Fix] [AMD] sgl-kernel: backport wave32 DSA top-k (#41687) to amd_march

[Upstream PR](https://github.com/sgl-project/sglang/pull/46910) · state: open · merged: False

## Original PR description

## Motivation

On `amd_march`, the DSA indexer top-k kernels in `include/hip/dsa_topk_coop.cuh` hard-code `kWaveSize = 64`. On RDNA (wave32), every wave-level scan and ballot in them is wrong, so `fast_topk*` / `fast_topk_transform*` / `deepseek_v4_topk*` return wrong indices.

On unmodified `amd_march`, `tests/test_topk.py` gives `157 failed, 5 passed` on both gfx1100 (W7900D) and gfx1201 (R9700), for example:

```
E   AssertionError: wrong_values=92, max_permit_error=5
```

`main` already fixed this in #41687. That PR selects `kWaveSize` by arch macro and traps if the launched wavefront size disagrees. This PR is a clean `git cherry-pick -x` of it onto `amd_march`, with no conflicts and the original authorship kept. Part of the RDNA plan in #46900.

## Modifications

Cherry-pick of 682f4ef32f (#41687), `include/hip/dsa_topk_coop.cuh` only (+20):

- `kWaveSize = 32` for `__GFX10__` / `__GFX11__` / `__GFX12__`, and 64 otherwise.
- `check_wave_size()` traps when `__builtin_amdgcn_wavefrontsize()` disagrees with `kWaveSize`.

CDNA (`__GFX9__`) keeps `kWaveSize = 64`, so the gfx942/gfx950 code is unchanged.
