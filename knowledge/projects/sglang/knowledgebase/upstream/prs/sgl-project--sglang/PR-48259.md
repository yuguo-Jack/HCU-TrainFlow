# [Fix] hicache: carry routed-experts rows through the host tier

[Upstream PR](https://github.com/sgl-project/sglang/pull/48259) · state: open · merged: False

## Original PR description


## Motivation

The routed-experts capturer (`--enable-return-routed-experts`) keeps one row per device KV slot, and `get_topk` reads a request's rows through `req_to_token`. With `--enable-hierarchical-cache`, a prefix that comes back from the host tier is loaded into new device slots, but its rows are not. The prefix rows of every host-tier hit therefore come from whatever request used those slots before. Nothing fails; the client just receives wrong routing for the cached part of the prompt.

On upstream main, 3,916 of 3,918 prefix rows of a host-tier hit differed from the cold run of the same prompt (H100, `Qwen/Qwen3-30B-A3B`).

## Modifications

- New `mem_cache/hicache_topk_rows.py` (`HostTopkRows`), created by `HiCacheController` only when the routed-experts capturer exists.
  - The capturer allocates (and frees in `destroy()`) a host-tier rows buffer with its own host allocator: `host_kv_tokens x layers x top_k x 4 B` (Qwen3-30B-A3B: 0.09 GB for a 65,600-token host pool, logged at startup as `HostCache[routed_experts_hicache]`).
  - `start_writing` / `start_loading` copy the transfer's slot indices to the host on the transfer engine's index stream (after the stream that produced them, never behind earlier KV copies), and attach the resulting `TopkRowCopy` to the transfer's `HiCacheAck`.
  - When a write ack is processed (before the device slots can be freed), the rows of its device slots are copied to its host slots. When a load ack is processed, the rows of its host slots are copied into the new device slots. `get_topk` first applies any load not yet acked (a pre-read hook on the capturer); it waits for the index copies of pending loads, which run on the index stream after the work that produced the indices, not for the KV transfers. A load is applied once.
  - `HiCacheController.reset()` (cache flush) drops pending loads with the queues.
- `UnifiedRadixCache.writing_check` / `loading_check` and the PD decode KV offload manager apply the row copy carried by each processed ack.
- Rows are not persisted to L3 storage backends: with `--hicache-storage-backend`, rows of prefix pages loaded from storage are stale. The server warns at startup and the HiCache best-practices page says so.
- Tests:
  - `test/registered/rl/test_return_routed_experts_hicache.py` (`extra-a`, `1-gpu-large`, est. 400 s): a host-tier hit returns the cold run's prefix rows. Fails on main.
  - `test/registered/unit/mem_cache/test_hicache_topk_rows.py` (CUDA, `1-gpu-small`): rows come back in the new slots through the ack or the pre-read hook, an acked load is not reapplied, reset drops pending loads, the rows are freed with the capturer.

## Accuracy Tests

`Qwen/Qwen3-30B-A3B`, TP1, `--enable-return-routed-experts --enable-hierarchical-cache --hicache-ratio 4 --max-total-tokens 16384 --page-size 1`. Prompt A (3,919 tokens) cold, then 8 other long prompts that push A's prefix out of the device pool, then A again (a host-tier hit). Baseline `8d4e1ce4c7` and this PR on the same GPU in the same container.

| | upstream main | this PR |
|---|---|---|
| 1x GB300 (`--moe-runner-backend triton`): cached prefix rows that differ from the cold run | 3,902 / 3,904 | 0 / 3,904 |
| 1x H100 (default MoE runner): same | 3,916 / 3,918 | 0 / 3,918 |
| Output ids of the warm run == cold run | yes | yes |

The generated tokens never depended on these rows; only the returned routed experts change, from wrong to right.

## Speed Tests and Profiling

With routed experts and HiCache on, a shared-prefix workload whose prefixes move between the device and host tiers, arms main / PR / PR / main, 2 runs per launch. 1x GB300 (`--moe-runner-backend triton`) at commit `2471219a91` of this PR, where the slot-index copy still ran on the transfer stream:

```
python3 -m sglang.benchmark.serving --backend sglang --dataset-name generated-shared-prefix \
  --gsp-num-groups 32 --gsp-prompts-per-group 8 --gsp-system-prompt-len 2048 \
  --gsp-question-len 128 --gsp-output-len 64 --max-concurrency 16 --return-routed-experts
```

| | output tok/s (4 runs) | median |
|---|---|---|
| main `8d4e1ce4c7` | 917.6, 994.7, 985.5, 1002.8 | 990.1 |
| this PR | 979.1, 1023.7, 976.9, 1021.4 | 1000.3 |

Same bench on 1x H100 (default MoE runner), at `2471219a91` and at the final head `a4f1ff527d` (index copy on the index stream):

| | output tok/s (4 runs) | median |
|---|---|---|
| main `8d4e1ce4c7` (session 1) | 515.6, 487.1, 495.4, 455.4 | 491.3 |
| this PR at `2471219a91` | 496.2, 465.0, 481.3, 445.8 | 473.2 |
| main `8d4e1ce4c7` (session 2) | 567.8, 577.6, 572.1, 578.0 | 574.8 |
| this PR at `a4f1ff527d` | 567.1, 573.1, 565.5, 571.4 | 569.3 |

GB300: no measurable cost (+1.0 %, within the run spread). H100: -3.7 % at `2471219a91` and -1.0 % at the final head in the median, with overlapping ranges in both; the cost is the row copy at each write and load ack on the scheduler thread, paid only with `--enable-return-routed-experts`. Host memory: the rows mirror for a 65,600-token host pool is 0.09 GB (`HostCache[routed_experts_hicache]` in the server log). Without `--enable-return-routed-experts` nothing is allocated and the hooks are skipped.
