# [Feat] gemma4: per-layer attention backend

[Upstream PR](https://github.com/sgl-project/sglang/pull/44399) · state: open · merged: False

## Original PR description

## Motivation

Gemma-4-31B mixes two kinds of attention layer:
- 50 sliding-window layers with head_dim 256;
- 10 full-attention layers with head_dim 512.

FA3 cannot run head_dim 512, so on SM90 the model runs FA4 for every layer. On the hd256 sliding-window layers, FA3 is faster than FA4 out of the box at small batch (H200 kernel benchmark):
- bs1 decode: 2.1-2.9x faster;
- bs4 MTP verify: 4.3x faster.

At bs >= 8 and in prefill, the two are within about 10% of each other.

## Modifications

`--attention-backend fa3_fa4` (SM90 only) builds `FlashAttentionBackend(fa_impl_ver=4, fa3_fa4_hybrid=True)`.

Layer routing:
- `_ver_for(layer)` sends a layer to FA3 when `max(head_dim, v_head_dim) <= 256`, and to FA4 otherwise.
- Calls that need FA4-only features go to FA4 for every layer. These features are Gemma-4 image masks, `score_mod` and `rel_bias`.
- Every kernel call site and every FA4-only guard uses the per-layer version.

What stays on the FA4 stack:
- Init policy: runtime policy, num_splits and deterministic batch invariance.
- The FA3 scheduler-metadata precompute stays off. It is sized from the model-level head_dim, which is 512 for Gemma-4.
- `fa_impl_ver` stays 4, so code that reads it (dots_hybrid, minicpm) still sees FA4.

Validation and allowlists:
- Init rejects MLA and any KV cache that is not BF16. FP8 SWA KV is a follow-up.
- The frozen-KV MTP drafter (topk=1) reuses the runner's backend, so its assistant layers follow the same per-layer rule.
- `fa3_fa4` is added to the backend choices, Gemma-4's accepted backends, the unified-memory full-graph set, the page-major allowlist and the CP backend kind.
- `docs/docs/advanced_features/attention_backend.mdx` gains a usage example.

Recommended launch:
- `--attention-backend fa4 --decode-attention-backend fa3_fa4 --speculative-attention-mode decode`, or simply `--attention-backend fa3_fa4`.
- With split backends, `--speculative-attention-mode decode` is needed. Without it, MTP verify runs on the FA4 prefill backend.

## Accuracy

GSM8K, 200 questions, few-shot, parallel 8. Model: RedHatAI/gemma-4-31B-it-FP8-block on 1x H200, TP1.

| config | GSM8K |
|---|---|
| fa4, no spec | 0.825 |
| fa4 prefill + fa3_fa4 decode, no spec | 0.825 |
| fa4, MTP4 | 0.815 |
| fa4 prefill + fa3_fa4 decode/verify, MTP4 | 0.830 |
| fa3_fa4 everywhere, MTP4 | 0.815 |
| triton, no spec (reference, job 3391) | 0.810 |

## Benchmark

Iteration time = median decode-iteration wall time from `SGLANG_RECORD_STEP_TIME`, over closed batches.

Setup:
- Load: 8192-token input, 1024-token output, two reps per concurrency.
- Serving: SWA ratio 0.2, chunked prefill 8192, hrrn scheduling, max running 8.
- Hardware: 1x H200, all lanes in the same image.

Slurm job 3389.

No speculative decoding (fa4 vs fa4 prefill + fa3_fa4 decode):

| conc | fa4 iter ms | hybrid iter ms | change |
|---|---|---|---|
| 1 | 14.21 | 12.64 | -11.0% |
| 8 | 20.25 / 18.01 | 21.23 / 18.29 | +4.8% / +1.6% |

MTP4, topk 1:

| conc | fa4 | hybrid, verify on fa4 | hybrid, verify on fa3_fa4 | fa3_fa4 everywhere |

| 1 | 17.32 | 16.94 (-2.2%) | 15.42 (-11.0%) | 15.44 (-10.9%) |

At c8, accept length varies across lanes (2.8-4.1). FA3 and FA4 round differently, so greedy outputs and therefore acceptance diverge on these synthetic prompts. TPOT and tok/s at c8 follow acceptance, not attention cost.

## Tests

- `test/registered/unit/layers/test_flashattention_paged_mha.py` (CPU):
  - `_ver_for` routes at the head_dim 256 limit, using the wider of K and V;
  - FA4-only features force FA4;
  - single-version backends are unchanged;
  - `forward_decode` dispatches hd256 SWA layers to FA3 and hd512 full layers to FA4.
- `test/registered/kernels/ops/attention/test_flash_attention_4.py::TestFlashAttention4SM90::test_fa3_matches_fa4_on_gemma4_swa_layer`:
  - FA3 and FA4 match on a Gemma-4 SWA layer (hd256, window 1023, GQA 32/16) for decode and q_len 5 verify, at page sizes 1 and 64;
  - contexts are shorter and longer than the window;
  - large +-V values on the window edge keys make the test fail if either kernel's window is off by one key.
- Run on H200 in job 3389: all pass, together with the existing SM90 FA4 class and `test_flashattention_return_lse.py`.

## Not covered / follow-ups

- Hybrid prefill with image masks routes the whole batch to FA4 (unit-tested routing). It has not been run end to end on an image prompt.
- FP8 SWA KV for the FA3 layers.
- FA4 `intra_wg_overlap` for the hd512 layers is tracked separately.
- EAGLE multi-step draft backends (`draft_utils`) have no `fa3_fa4` entry; only frozen-KV topk=1 is covered.
- Pre-existing: `forward_extend`'s `fa_skip_kv_cache` path calls `flash_attn_varlen_func` without `ver=`, so it always runs FA3, even on the fa4 backend.
