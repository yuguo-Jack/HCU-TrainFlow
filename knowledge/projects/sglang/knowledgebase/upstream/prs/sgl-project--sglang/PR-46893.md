# [Feat] dsv41: Choose where Engram tables live with `--engram-config`

[Upstream PR](https://github.com/sgl-project/sglang/pull/46893) · state: closed · merged: True

## Original PR description

- Add `--engram-config`, a JSON object that chooses where the DeepSeek-V4.1 Engram tables live. Each key is one independent choice, and omitted keys keep their defaults:
  - `placement`: `gpu` (default) or `cpu` (pinned host memory, read by the GPU in place).
  - `replication`: `none` (default; one table, rows split across the TP group) or `per_node` (one full copy per node, mapped by its ranks).
  - `lookup`, with `replication` `none`: `collective` (default; each rank looks up its own rows and a reduction assembles them) or `peer_read` (each rank reads its rows from the owning GPU's shard).
- Resolve it once in `_resolve_engram_config` (`arg_groups/deepseek_v4_hook.py`), which fills the defaults, rejects unknown values and combinations that cannot work (`per_node` off `cpu` or across nodes, `peer_read` off `gpu` or off CUDA, the argument on a model without Engram layers), and logs the resolved configuration at startup. `EngramEmbedding` reads only the resolved `get_exec().offload.engram_config`.
- Deprecate `SGLANG_ENABLE_DSV41_ENGRAM_HOST_TABLE`, `SGLANG_DSV41_ENGRAM_HOST_TABLE_LAYOUT` and `SGLANG_OPT_DSV41_ENGRAM_PEER_SHARDS`. Without `--engram-config` they are translated to it, with a warning that prints the equivalent JSON; with it, they are ignored.
- Add an Engram tables page to the docs and a row to the server arguments; switch the cookbook commands and the GB300 DeepSeek-V4.1-Flash accuracy tests to `--engram-config '{"placement": "cpu"}'`.

No behavior change, except that a host table enabled by `SGLANG_ENABLE_DSV41_ENGRAM_HOST_TABLE=1` without a layout now gets one shard per rank (`per_rank`) instead of the single shared mapping. The shared mapping gets no transparent huge pages unless shmem THP is enabled, which makes large lookups several times slower; the cookbook commands already set `per_rank`.

Open PRs that read the deprecated variables or add layout values (#40106, #42919, #42920, #44028, #45968, #46092) would read `engram_config` instead.
