# [Fix] multimodal: Clip pad spans to a truncated prompt

[Upstream PR](https://github.com/sgl-project/sglang/pull/46638) · state: closed · merged: True

## Original PR description

## Motivation

With `--allow-auto-truncate`, the context length can cut a multimodal prompt inside or before an image, audio or video span. The multimodal item offsets still describe the untruncated prompt, so `pad_mm_tokens` in `mm_utils.py` assigns a full-length `padding_sequence(end - start + 1)` into a slice that torch clips to the prompt. The resulting shape mismatch raises in the scheduler:

```
RuntimeError: The expanded size of the tensor (3) must match the existing size (6) at non-singleton dimension 0.
```

The scheduler pads in `_handle_generate_request` outside the `try` that guards multimodal input parsing, so the exception propagates out of the scheduler process and takes the whole server down, instead of the request being rejected. Before the wide pad sentinels, a scalar `pad_value` was assigned and an overrunning slice was clipped silently, so the scheduler's existing "Multimodal prompt is too long after expanding" check returned a 400.

## Modifications

- `pad_mm_tokens`: pad only the part of each span that is still in the prompt, `[start, min(end + 1, len(input_ids)))`, and skip spans that lie entirely past the cut. `padding_sequence(n)` is a prefix of the full sequence, so the kept tokens get the same radix key as the untruncated padding would.
- New unit test `test/registered/unit/managers/test_mm_pad_input_tokens.py` (registered in `base-a-test-cpu`): two image spans, one cut in the middle and one entirely past the cut; checks that the kept prefix equals the untruncated padding and that the input ids are left as they were.

## Accuracy Tests

No numerics change. Prompts that fit in the context length pad exactly as before, since `min(end + 1, len(input_ids))` equals `end + 1` for every span.

## Benchmarking and Profiling

Not applicable: one `min` and one comparison per multimodal span.

## Checklist

- The new test fails on current main with the `RuntimeError` above and passes with this change.
- `test/registered/unit/managers/test_mm_utils_split.py`, `test_mm_hashes.py` and `test_mm_embedding_length.py` pass with the change.
- `pre-commit` on both files passes.
- End to end (dummy weights, `--context-length 128 --allow-auto-truncate`, a text prefix plus a 112-token image): without the change the scheduler crashes with the `RuntimeError` above and the server is gone; with it the server answers 400 "Multimodal prompt is too long after expanding" and the next request succeeds, in both the Python and the Rust server mode. An image entirely past the cut also gets a 400.
