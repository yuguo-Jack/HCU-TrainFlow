# Fix InternlmDetector drops streamed tool calls after the first

[Upstream PR](https://github.com/sgl-project/sglang/pull/46712) · state: open · merged: False

## Original PR description

## Summary
- Fixes #46661 where `InternlmDetector.parse_streaming_increment` drops every streamed tool call after the first
- The bug occurs when the second tool call's start marker (`<|action_start|> <|plugin|>`) arrives in multiple chunks
- The fix checks if the buffer contains a partial bot_token before clearing it, allowing the parser to correctly handle split markers

## Root Cause
After the first tool call is processed (`current_tool_id > 0`), any new text that doesn't contain the full bot_token causes the buffer to be cleared immediately. This means if the second tool call's marker arrives split across chunks (e.g., `<|action_start|>` in one chunk and `<|plugin|>` in another), the first chunk is discarded and the second marker can never complete.

## Fix
Modified `python/sglang/srt/function_call/internlm_detector.py` lines 171-173 to check if the buffer might contain a partial bot_token before clearing it:

```python
if self.current_tool_id > 0:
    # Check if buffer might contain a partial bot_token
    if not self._ends_with_partial_token(current_text, self.bot_token):
        self._buffer = ""
    return StreamingParseResult(normal_text="")
```
