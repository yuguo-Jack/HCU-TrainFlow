# [Feat] hicache: Deduplicate MLA/DSA host KV with broadcast L2 restore

[Upstream PR](https://github.com/sgl-project/sglang/pull/45141) · state: open · merged: False

## Original PR description

## Motivation

Under tensor parallelism, MLA/DSA KV is replicated across attention-TP ranks. Keeping a separate HiCache host copy on every rank consumes host memory without increasing the number of reusable prefixes.

This PR connects the components from [#36800](https://github.com/sgl-project/sglang/pull/36800) and the integration approach from [#26691](https://github.com/sgl-project/sglang/pull/26691) to the current HiCache transfer and completion interfaces. It stores one physical CPU KV/indexer copy and supports two restoration methods: the owner loads and broadcasts, or every GPU reads the same shared CPU allocation. The shared path avoids cache-payload broadcasts and their communication ordering requirements. Dedup remains opt-in, and broadcast remains the default restoration mode.

This follows [#43795](https://github.com/sgl-project/sglang/pull/43795) and [#43798](https://github.com/sgl-project/sglang/pull/43798). File L3 and V4/Kimi extensions are outside this PR.

## Modifications

- Add `--enable-mla-hicache-host-dedup` (default off) and `--mla-hicache-host-dedup-mode broadcast|shared` (default `broadcast`), with documented configuration checks.
- **Broadcast restoration:** allocate real host buffers on the owner; other ranks keep allocation metadata without duplicate payloads. Construct allocator-only MLA pools from `MLAHostAllocation`, preserving target/draft geometry and packed DSA row widths.
- **Shared CPU restoration:** map one allocation into all local TP ranks and register each mapping with CUDA. The owner publishes its write only after D2H completes; each GPU then loads through its own physical device indices and native layer-completion events. Wait for all readers before reclaiming shared rows, and propagate allocation/transfer failures to every rank.
- **Layer-wise broadcast:** add `--enable-mla-hicache-layerwise-overlap` (default off). Pack same-layer KV/indexer payloads and group up to four ready layers to reduce broadcast submissions. Protect staging-buffer reuse and publish load completion only after the final broadcast.
- Fence transfers against KV production and previous forwards. Preserve local physical index order and skip empty GLM-5.2 indexer placeholders without skipping main KV restoration. Preserve decode CUDA graphs after shared restoration.
- Account for one physical host KV/indexer copy while retaining container memory limits, automatic-sizing headroom, and explicit ratio/size behavior.

Shared mode supports single-node CUDA MLA/DSA, TP > 1, PP = DP = attention-DP/CP = DCP = 1, the default allocator, and `direct` / `page_first_direct`. It rejects draft, mixed/state pools, disaggregated serving and L3. Shared mode uses native per-layer waits; the layer-wise-overlap flag applies to broadcast mode.

## Speed Tests and Profiling

### Sufficient L2 capacity

GLM-5.2 FP8, 8×NVIDIA H20, TP8, PyTorch 2.14.1+cu130 and sglang-kernel 0.4.9. Use L1 = 8192 tokens and host ratio = 32, keeping logical L2 capacity equal. The node-wide KV/indexer payload drops from **210.09 GB to 26.26 GB**.

Use community `benchmark/hicache/bench_multiturn.py`: short inputs are 16×3072 tokens and long inputs are 8×6144; two rounds, append length 64 (about 80 actual tokens), output length 16, concurrency 2, request rate 64/s, seed 42. Warm up each configuration, then measure three times. Confirm real host restoration outside the timed interval. The table reports the median of three restore-round mean TTFTs, in milliseconds.

| Restoration method | Short TTFT (vs. no dedup) | Long TTFT (vs. no dedup) | Cache broadcasts / restore |
| --- | ---: | ---: | ---: |
| No dedup | 423.32 | 695.47 | 0 |
| Whole-load broadcast, unpacked | 442.09 (+4.43%) | 719.65 (+3.48%) | 156 |
| Whole-load broadcast, same-layer packed | 439.73 (+3.88%) | 701.77 (+0.91%) | 78 |
| Layer-wise broadcast, unpacked | 458.81 (+8.38%) | 726.50 (+4.46%) | 156 |
| Layer-wise broadcast, same-layer packed | 455.90 (+7.70%) | 724.08 (+4.11%) | 78 |
| Layer-wise broadcast, packed with four-layer groups | 442.11 (+4.44%) | 712.18 (+2.40%) | 20 |
| Shared CPU, whole-load wait (experimental control) | 430.14 (+1.61%) | 717.97 (+3.23%) | 0 |
| Shared CPU, native layer waits | 430.34 (+1.66%) | 710.56 (+2.17%) | 0 |

Shared reads have lower short-input latency here; packed whole-load broadcasting has lower long-input latency. Neither method is universally faster. Unpacked and single-layer broadcast variants, and whole-load shared waiting, are experimental controls rather than additional public flags.

A separate same-node confirmation compares two no-dedup runs, five native-shared runs, then three no-dedup runs. Shared median TTFT is **427.36 ms / 695.30 ms** for short/long inputs: +1.19% / +0.23% versus the following no-dedup controls. The small remaining differences do not establish zero overhead for every workload.

### Equal physical host memory

A separate H20-node experiment uses approximately 13.18 GB of physical KV/indexer memory and 8×6144-token sessions. No dedup uses ratio 2; shared reads use ratio 16.0546875. Both configurations warm up and run three times.

| Configuration | Restore-round hit rate, three runs | Median TTFT, ms | Two-round throughput, req/s |
| --- | --- | ---: | ---: |
| No dedup | 0% / 0% / 12.34% | 5335.75 | 0.27515 |
| Shared CPU reads | 98.71% / 98.71% / 98.71% | 733.86 | 0.41471 |

Both configurations pass 36/36 complete-answer checks. The working set exceeds ordinary host capacity but fits after dedup; the improvement comes from retaining more prefixes. This experiment uses an earlier shared-read implementation on another node, so its absolute latency is separate from the restoration-overhead table.

Profiling shows that same-layer packing reduces broadcasts from 156 to 78, and four-layer grouping reduces them to 20. Owner CPU communication submission falls from about 8.3–9.0 ms to 4.9–5.2 ms with same-layer packing. The inspected broadcast windows show no overlap with main model computation; receiver NCCL duration includes waiting and is not the net request overhead.

### Reproduce the main production configurations

The commands below cover dedup off, whole-load broadcast, four-layer-grouped layer-wise broadcast and shared reads. Unpacked, one-layer-packed and whole-load-shared controls use isolated diagnostic variants, not additional production flags.

Generate the shared public dataset once:

```python
import json
rows = [{"conversations": [
    {"from": "human", "value": f"Session {i:03d}. Marker CEDAR-{i:03d}. "
     + (f"The river crosses the stone bridge in session {i:03d}. " * 120)},
    {"from": "gpt", "value": f"Marker CEDAR-{i:03d}."},
]} for i in range(32)]
with open("glm52-public-synthetic.json", "w") as f:
    json.dump(rows, f)
```

Restart a separate server per mode, keeping other arguments unchanged:

```bash
MODEL=/path/to/GLM-5.2-FP8
PORT=30000
MODE=shared  # nodup, broadcast, broadcast-layerwise, shared
FLAGS=()
case "$MODE" in
  nodup) ;;
  broadcast) FLAGS=(--enable-mla-hicache-host-dedup) ;;
  broadcast-layerwise)
    FLAGS=(--enable-mla-hicache-host-dedup --enable-mla-hicache-layerwise-overlap) ;;
  shared)
    FLAGS=(--enable-mla-hicache-host-dedup --mla-hicache-host-dedup-mode shared) ;;
  *) exit 1 ;;
esac
OMP_NUM_THREADS=4 NCCL_NVLS_ENABLE=0 PYTHONPATH="$PWD/python" \
python -m sglang.launch_server \
  --model-path "$MODEL" --tp 8 --host 127.0.0.1 --port "$PORT" \
  --trust-remote-code --weight-loader-prefetch-checkpoints \
  --enable-cache-report --enable-metrics --enable-hierarchical-cache "${FLAGS[@]}" \
  --hicache-ratio 32 --hicache-write-policy write_through \
  --hicache-io-backend direct --hicache-mem-layout page_first_direct \
  --kv-cache-dtype bfloat16 --dsa-prefill-backend flashmla_sparse \
  --dsa-decode-backend flashmla_sparse \
  --max-total-tokens 8192 --context-length 8192 --max-running-requests 4 \
  --chunked-prefill-size 512 --cuda-graph-backend-prefill disabled \
  --cuda-graph-backend-decode full --cuda-graph-max-bs-decode 4 \
  --mem-fraction-static 0.96 --random-seed 42 --dist-timeout 120
```

Warm each workload once with four clients, then measure three times with all clients, alternating short/long order. The fresh confirmation uses the 2→5→3 stages above.

```bash
LENGTH=3072
CLIENTS=16
# Long workload: LENGTH=6144, CLIENTS=8.
CLIENTS_TO_RUN=4                 # Warm up once; then set to "$CLIENTS".
RUN=warmup                      # Formal runs: 1, 2, 3 (five for confirmation).
curl -fsS "http://127.0.0.1:$PORT/metrics" > "$MODE-$LENGTH-$RUN-before.txt"
PYTHONPATH="$PWD/python" python benchmark/hicache/bench_multiturn.py \
  --model-path "$MODEL" --host 127.0.0.1 --port "$PORT" --api-format sglang \
  --dataset-path glm52-public-synthetic.json \
  --num-clients "$CLIENTS_TO_RUN" --request-length "$LENGTH" \
  --sub-question-input-length 64 --output-length 16 --num-rounds 2 \
  --enable-round-barrier --max-parallel 2 --request-rate 64 \
  --disable-auto-run --seed 42 --log-file "$MODE-$LENGTH-$RUN.jsonl"
curl -fsS "http://127.0.0.1:$PORT/metrics" > "$MODE-$LENGTH-$RUN-after.txt"
```

Compare `round.round_1.average_ttft` and verify host/device counter deltas outside timing. A first-seen counter uses zero as its previous value. Combined GPU+host hit rates alone do not establish genuine L2 restoration.
