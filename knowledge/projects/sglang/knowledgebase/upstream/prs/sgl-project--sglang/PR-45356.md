# [Fix] muse_spark: support unified KV memory with TRT-LLM

[Upstream PR](https://github.com/sgl-project/sglang/pull/45356) · state: closed · merged: True

## Original PR description

## Motivation

Muse Spark's fused decode/verify KV store assumes contiguous per-layer cache rows. Unified KV memory interleaves layers in each token row, so this path rejects the strided cache during CUDA graph capture.

## Modifications

- When unified memory is enabled, reuse Muse Spark's existing prefill QK norm/RoPE preparation and the attention backend's strided KV writer for decode and target verification. Forward modes, speculative masks, and the `trtllm_mha` backend remain unchanged.
- Resolve the implicit FA4 draft KV dtype when deciding fused draft placement. A BF16 DFLASH-family draft now keeps a separate pool when the target uses FP8, avoiding a dtype mismatch at draft binding.

- Add `test_muse_spark_unified_memory.py` to `extra-b-test-4-gpu-b200`, using the validated TP4/EP4 launch settings and a full GSM8K accuracy gate of 0.93. Pass the existing gated-model credential to this suite and its named main-branch rerun, preserving the rerun PR-head restriction.

## Accuracy Tests

Tested on 4 B200 GPUs with `meta-models/Muse-Spark-Open-816B-A42B-NVFP4`, TP4/EP4, `modelopt_fp4`, `flashinfer_trtllm` MoE, `trtllm_mha` attention, unified memory, FP8 KV, page size 128, layernorm SP and MegaMoE. DFLASH uses `RadixArk/Muse-Spark-Open-DFlash2`, FA4, and 8 draft tokens. Native context length is 1,048,576; multimodal features use CPU transport and HiCache is disabled.

The new registered GSM8K test passed on 4 B200 GPUs: **1285/1319 (97.42%)**, with zero request errors, zero truncated responses, and zero invalid answers. It uses 64 evaluation workers, a 32,768-token output cap, temperature 1, top-p 0.95, and xhigh reasoning. The unmodified test file completed its server startup, evaluation, assertions, and graceful teardown in 263 seconds. Pre-commit and actionlint passed for the new test and CI changes.

All three evaluations use temperature 1, top-p 0.95, and xhigh reasoning:

| Evaluation | Configuration | Correct / total | Accuracy |
| --- | --- | --- | --- |
| AIME26 | 30 problems × 8 repeats, 400K output cap | 226 / 240 | 94.17% |
| GPQA Diamond | 198 questions, 250K output cap | 178 / 198 | 89.90% |
| Video-MME | 900 short questions, 96-frame input videos, no subtitles | 787 / 900 | 87.44% |

One AIME and one GPQA response reached the configured output cap; both remain in the denominators. Actual DFLASH verification counters were recorded for responses.

Existing cache-placement and kernel tests passed on the runtime implementation in this PR. Text and image server smoke checks passed; CUDA graphs are enabled. Pre-commit passed for all changed files.

Fixed-input CUDA graph replay checks passed bit for bit: original packed fused QK norm/RoPE/KV store vs the fallback with 16-layer GQA and 46-layer SWA strided FP8 views (1, 8, 17, 128, and 512 tokens); TRT-LLM decode and 8-token verify with packed vs strided caches at 8K/64K context lengths, including SWA. Each case replays three times with changed inputs and cache locations/page tables.

## Speed Tests and Profiling
