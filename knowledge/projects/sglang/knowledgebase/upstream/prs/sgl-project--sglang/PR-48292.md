# [Fix] disaggregation: Reject the KV checksum with DeepSeek-V4 and on a HiSparse decode

[Upstream PR](https://github.com/sgl-project/sglang/pull/48292) · state: closed · merged: True

## Original PR description

`--disaggregation-enable-kv-checksum` cannot work in two configurations; both are now rejected at startup instead.

- DeepSeek-V4 in PD: its KV pool registers state entries (SWA, the SWA ring, request state) but `state_indices_for_request` returns no indices for it, so the prefill asserts in `KvChecksumComputer.compute` on its first request (and the decode would at verification).
- A HiSparse decode: it receives KV into its host pool, but the checksum indexes that pool by the request's logical ids, so it reads the wrong rows. When the layout signatures differ, every request is admitted unverified with a warning; when they match, it would digest the wrong memory.

The same assert also fires for a plain MHA model with `--kv-cache-dtype mxfp8` (its block-scale state has no indices either); not rejected here, since a dtype-only check would also reject hybrid-linear models where the checksum works.

cc @ispobock: these may be on your list for the checksum.
