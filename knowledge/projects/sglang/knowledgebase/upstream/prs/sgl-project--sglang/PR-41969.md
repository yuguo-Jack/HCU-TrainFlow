# [Feat] [AMD] diffusion: Add gfx1250 Gluon FAv3 attention backend

[Upstream PR](https://github.com/sgl-project/sglang/pull/41969) · state: open · merged: False

## Original PR description

## Motivation

Add an opt-in Gluon/Triton FAv3 attention backend for AMD gfx1250 in SGLang Diffusion. It supports **BF16 and FP16, head dimensions 64/128/256, dense noncausal MHA, zero dropout, and rectangular Q/KV lengths**. Dispatch uses tensor properties and device occupancy; it does not depend on a model identifier.

Select it with `--attention-backend gluon_fav3`. AITER remains the ROCm default. Unsupported dense contracts reaching the backend use AITER; shared masked-attention routing may use SDPA.

## Modifications

- Add stable pipeline and ping-pong schedules with FP32 softmax state and round-to-nearest probability conversion to the input dtype. D256 uses the four-wave pipeline to avoid the severe register-spill slowdown of the wide tile.
- Use default scheduling and full TDM waits before reading pipeline K/V tiles for FP16. Automatic `max-ilp` intermittently corrupted storage-offset inputs; disabling it alone still failed for D64. Full waits also protect explicitly configured FP16 pipeline launches. The underlying compiler/synchronization defect remains unresolved.
- Preserve BF16/D128 persistent K/V reuse for eligible contiguous short-KV inputs and input-checked optimizations for long attention. GPU checks rerun on every CUDA graph replay. FP16 and other dimensions use stable generic softmax; the BF16 fixed shift would underflow FP16 probabilities.
- Replace the former model-specific fixed-shift environment opt-in with guarded dispatch and numerical fallbacks. Retain 64-bit tile-base addressing, independent tensor strides, partial tiles, and custom softmax scale.
- Integrate the measured TokenSpeed-derived stride specialization and earlier first-block maxima in persistent cross attention. Variants that failed numerical checks or regressed performance are excluded.
- Preserve explicit backend identity, check required Gluon/TDM APIs, and retain fallback configuration.
- Add dtype/head-size benchmark arguments and independent FP64 checks for selected providers. Automatic benchmarks now exercise the production automatic dispatch.

## Accuracy Tests

**243 tests passed** under the actual host `gpu-lock`, covering:

- `test/registered/amd/test_gluon_fav3_gfx1250.py`
- `python/sglang/multimodal_gen/test/unit/test_gluon_fav3_backend.py`
- `python/sglang/multimodal_gen/test/unit/test_aiter_attention_impl.py`

New coverage includes both dtypes and all three head sizes, both generic schedules, tails, independent sliced/transposed inputs, custom scale, large positive/negative uniform logits, late outliers, automatic short-KV dispatch, and a 65,536-token FP16 underflow regression. Existing graph-replay guards and addressing tests remain covered.

The review fix adds 12 repeated automatic FP16 pipeline cases: D64/D128/D256 with one-element storage offsets on Q, K, V, or all three. All 500 launches per case pass independent full-output FP64 attention checks (6,000 launches total). Supplemental graph validation passes 3,000 replays across all three head sizes, using both automatic dispatch and explicitly requested `max-ilp`. The reviewer's exact reproducer also passes 100/100 offset-input launches after the fix.

All 12 dtype/head-size/self-or-cross benchmark cases pass independent sampled FP64 attention over all keys. Relative RMS thresholds are 0.003 for BF16 and 0.001 for FP16, with a separate pointwise error check. At `e49fd55ce35a`, full outputs on all four original BF16/D128 targets were also bitwise identical to the saved previous implementation. The review fix changes FP16 pipeline scheduling/synchronization; BF16 and ping-pong/persistent schedules retain their existing waits.

The PR is rebased onto main at `c15edf314d20`. All 243 tests and all 12 dtype/head-size benchmark cases pass on review-fix commit `91033140f0`.

Validation uses synthetic tensors; no model weights or full generation. Pre-commit passes. Mintlify site validation could not run because the container lacks Node and `mint`.

These are local gfx1250 validation results. No checked-in workflow currently invokes the registered `nightly-amd-1-gpu-mi45x` suite. Full-model generation quality, multi-GPU execution, and independent performance verification remain outside this validation.

## Speed Tests and Profiling

Regression measurements at `e49fd55ce35a` use BF16, H40, D128, Sq176400; self attention has Sk176400 and cross attention Sk512. These timings predate the FP16 pipeline review fix; the BF16/D128 schedules below are unchanged.

| Attention | Batch | Gluon ms | AITER assembly ms | Latency reduction |
|---|---:|---:|---:|---:|
| self | 1 | 273.682 | 276.516 | 1.02% |
| self | 2 | 548.163 | 569.013 | 3.66% |
| cross | 1 | 1.180 | 1.206 | 2.11% |
| cross | 2 | 2.352 | 2.403 | 2.15% |

Measured on gfx1250 with PyTorch `2.11.0+rocm10.0.0`, Triton `76940ad348795521b3dc9f6c79acd7309ff924e3`, and AITER `a6d2b564fd671724a3720b8edf70e8d674e4d694`. The shared AITER checkout contains pre-existing edits; this change does not modify it. The direct baseline is `fmha_fwd_with_sink_asm`, using default scale, noncausal attention, and no LSE.

All GPU runs use `/usr/local/bin/gpu-lock docker exec sglang-fav3-goal2 ...` and dynamic clocks. The table uses seed 907 and six paired rounds with alternating order and balanced warmups. Each graph contains two calls; each measurement uses eight replays for B1 self attention, two for B2 self attention, and twenty for cross attention. Each case wins all six paired assembly comparisons; maximum provider CV is below 1%. GPU guards are included; host Python/allocation overhead is excluded. Two noisy short-window B1 self trials are retained; the complete case was repeated with a longer timing window.

The D256 pipeline avoids the severe register-spill cost of the initial wide-tile generalization. Fresh measurements after the review fix use B1/Sq8192/Sk8192/H16 for self attention and B1/Sq32768/Sk512/H40 for cross attention:

| D256 dtype | Self ms | Cross ms |
|---|---:|---:|
| BF16 | 0.587 | 0.629 |
| FP16 | 0.974 | 0.908 |

The conservative FP16 synchronization costs performance: earlier FP16 pipeline measurements were 0.621 ms self and 0.689 ms cross. These are separate dynamic-clock runs, not a paired before/after comparison. These are not AITER speedup claims: the installed AITER API rejects the tested FP16 and D64/D256 inputs. The smaller BF16/D128 cases also remain slower than AITER. Performance wins are limited to the four original target shapes, not every supported contract or end-to-end generation.

The maintained benchmark supports `--dtype {bf16,fp16}`, `--head-size {64,128,256}`, `--preset wan-self` / `wan-cross`, and `--batch`. Use `--provider gluon` for combinations unsupported by the installed AITER build; FP64 correctness checks still run.
