# [Fix] [AMD] quark: Load MXFP4 MoE checkpoints on gfx95 and gfx1250 without SGLANG_USE_AITER

[Upstream PR](https://github.com/sgl-project/sglang/pull/45332) · state: closed · merged: True

## Original PR description

## Motivation

`QuarkW4A4MXFp4MoE` imports its AITER shuffle helpers only when `SGLANG_USE_AITER=1` but always calls them after loading, so outside `docker/rocm.Dockerfile` (the only place that sets it) every Quark MXFP4 MoE checkpoint fails with `NameError: name 'e8m0_shuffle' is not defined`; this PR binds those helpers and the matching weight layout on gfx95 and gfx1250 regardless of the env var.

`process_weights_after_loading` calls `e8m0_shuffle` on gfx950 and `moe_shuffle_scale`/`moe_shuffle_weight` on gfx1250. The scheme has no other path, since `create_moe_runner` accepts only the AITER runner. The failure also hits `--quantization quark_mxfp4`, which `test/registered/e2e/quantization/test_quark_mxfp4.py` launches without the env var.

## Modifications

- On gfx95 and gfx1250, `_use_aiter` in `quark_w4a4_mxfp4_moe.py` no longer depends on `SGLANG_USE_AITER`. This binds the imports together with the weight layout (`_is_shuffle_moe_mxfp4`, AITER padding). Other HIP arches still follow the env var, because AITER defines no FP4 MoE layout for them; #41389 handles gfx1151.
- Binding only the imports, as #31805 does, is not enough: the weights stay unshuffled and AITER falls back from the FlyDSL kernels to CK 2-stage, which is 23–37 % slower at M ≥ 257.
- With `SGLANG_USE_AITER=1` the expression evaluates the same, so the weights handed to the MoE kernel are byte-identical to main's.
- `TestQuarkMxfp4MoEShuffleImports` reloads the module without the env var for gfx95, gfx1250 and other HIP arches. main fails the gfx95 and gfx1250 cases.

## Accuracy Tests

MI355X, TP1, `SGLANG_USE_AITER` unset unless noted:

| model | main | this PR |
|---|---|---|
| Qwen3.5-35B-A3B `--quantization quark_mxfp4`, real weights | NameError | GSM8K 0.820 (200 q, 5-shot) |
| same, main with `SGLANG_USE_AITER=1` (reference) | GSM8K 0.835 | — |
| Qwen3.5-397B-A17B, Qwen3.8-2.4T-A95B, MiniMax-M3, Kimi-K2.6, GLM-5.2 (MXFP4, dummy weights, 8 layers) | NameError | loads and serves |

The 0.015 gap is within the ±0.027 standard error at 200 questions. With the env var unset, attention and top-k also leave AITER, so the two arms differ outside the MoE as well.
