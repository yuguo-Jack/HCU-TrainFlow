# [Perf] dsv41: Write large eager mHC output directly into MegaMoE buffers

[Upstream PR](https://github.com/sgl-project/sglang/pull/46056) · state: open · merged: False

## Original PR description

## Motivation

Remove an intermediate activation copy in large eager DeepSeek-V4.1 prefills by writing mHC output directly into MegaMoE's existing symmetric buffers.

Main's #46163 covers MegaGate decode/target-verify. This PR adds the large eager-prefill path, including routing metadata outside MegaGate, while reusing the shared Mega-mHC output interface.

## Modifications

- Write quantized activations and scales into validated, preallocated buffers without collective allocation.
- Preserve routing metadata handling and the existing fallback for small/idle batches, CUDA graph capture, and unsupported configurations.
- Enable the fast path for eager SM10x prefills with at least 16,384 rows.

Adapted from the producer/buffer boundary in [DeepInfer](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/deepinfer/model_executor/models/v4_modules/hc.py).

## Accuracy Tests

Merge validation: pre-commit and local mocked control-flow checks passed (4 producer combinations, 24 consumer cases). The GSM8K and earlier exact-output results below predate the merge.

The current-head DSv4.1 DP2/EP2 model CI is a regression check, not coverage of this optimization: it uses `--moe-a2a-backend none` and does not exercise the >=16,384-row MegaMoE branch. Current-head directed numerical validation passed on two GPU ranks using production producer/consumer code with random weights at model dimensions: 27 records per rank cover 33,792-row batches, unequal and idle ranks, the 16,384-row boundary, routing metadata ownership, descriptor-identity fallback, and actual CUDA graph fallback. Valid quantized activation/scales/routing buffers, mHC boundary outputs, and final MoE outputs matched exactly. Buffer poisoning checks were included. This establishes the tested numerical boundary behavior; it is not a full-checkpoint accuracy evaluation.

Current-head checkpoint-backed shadow validation also passed: 256 measured comparisons per rank at 33,792 rows, visiting source layers 0–19 with real checkpoint weights/activations. The tested mHC/MoE boundary outputs matched exactly. This exercised `routing_in_buffer=False`; the alternate routing-buffer path is covered by the directed tests above. This is boundary validation, not a current-head full quality benchmark.

Selected current-head `/rerun-test` runs passed: [MegaMoE API](https://github.com/sgl-project/sglang/actions/runs/40067841992), [pre-dispatch](https://github.com/sgl-project/sglang/actions/runs/40067849548), [mHC kernels](https://github.com/sgl-project/sglang/actions/runs/40067856516), and [DSv4.1 DP2/EP2 regression](https://github.com/sgl-project/sglang/actions/runs/40067863921). The model regression's backend limitation above still applies.

Earlier-head validation:

- Reported exact-output checks passed for uneven/idle batches, routing metadata paths, capacity padding, and CUDA graph fallback.
- GSM8K (1,314 examples): baseline **97.34%**, candidate **97.56%**. No accuracy improvement is claimed; most cached-suffix batches exercised the fallback.
