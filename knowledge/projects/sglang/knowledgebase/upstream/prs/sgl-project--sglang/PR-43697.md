# [Feat] comfyui: Add SGLDWorkerStatus diagnostics node

[Upstream PR](https://github.com/sgl-project/sglang/pull/43697) · state: closed · merged: True

## Original PR description

Adds an `SGLDWorkerStatus` output node that prints what the local SGLD worker is running, for debugging slow graphs and for bug reports.

It takes the SGLD `MODEL` and the sampler's `LATENT` output, so ComfyUI always runs it after sampling, and it is never served from cache. It reads only what SGLang already has, with no extra timing on the request path:

- model, pipeline, worker liveness and pids
- loader settings, under the `SGLDOptions` widget names and values (for example `attention_backend=flash_attention`, `quantization=none`). These are what the worker runs and stay fixed until it restarts. Fields that don't apply to the chosen mode are left out, such as `resident_layers` with `memory_mode=resident`.
- per-run settings (`cache_mode`, `cache_dit_params`), which apply to the next request
- the worker's own `RequestMetrics` for the last DiT call: forward time and peak VRAM for one sampler step (with CFG, one of its two calls)

Tested on CPU (`test_comfyui_*.py`) and end to end on an H100 with ComfyUI v0.39.2 and Flux.1-dev (25 steps, 1024x1024). There the node ran after the sampler on the first run too, and reported `attention_backend=torch_sdpa`, about 37 ms per DiT call and about 23 GB peak VRAM.

Baseline: plain `sgl-project/sglang` main on the same image gives 117 passed, 1 skipped, 3 xfailed.

**What the GPU run found along the way.** The first run gave 120 passed, 3 failed. All three were bugs in this branch that only show up with ComfyUI installed:
1. `test_worker_status_node_show_without_worker`: `AttributeError: property 'step_latency' ... has no setter`. `step_latency` is created lazily so executors built without `__init__` work, and the test assigns to it. Fixed by adding a setter.
2. `test_chained_lora_nodes_keep_every_lora` and `test_chained_lora_targets_that_overlap_are_rejected`: `folder_paths has no attribute get_full_path`. The `show()` test imported `nodes.py` against a stub `folder_paths` and left that module cached in `sys.modules`, so the LoRA tests reused it. The test now drops the module after importing and the stub has `get_full_path`.

**Added:** `test_query_gpus_reports_the_real_device`, which checks `query_gpus()` returns one entry per CUDA device with sane memory numbers. It passes on the L4.

**Not covered:** a full ComfyUI graph with a live worker. Per-step latency is only tested with fake timings.

- niehen6174 · comment · 2026-10-21T04:13:38Z · [source](https://github.com/sgl-project/sglang/pull/43697#discussion_r4332964794)

File: `python/sglang/multimodal_gen/apps/ComfyUI_SGLDiffusion/nodes.py` · line 1077

Currently, requiring an explicit `after_sampling` (LATENT) dependency forces this  diagnostic node to run only after sampling finishes. 
This prevents users from inspecting  static loader settings and worker readiness upfront before triggering expensive generation. 
We should allow independent execution so status can be checked at any point in the workflow.
