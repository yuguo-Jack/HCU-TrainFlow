## Motivation

SGLang adds the support for per-token MoE support in #22918. Since then, we've extended the support of per-token NVFP4 MoE for more activations like ReLU2 in FlashInfer https://github.com/flashinfer-ai/flashinfer/pull/4618. In this PR, we bridge the ReLU2 support from FlashInfer into SGLang.

## Modifications

- `layers/moe/moe_runner/flashinfer_trtllm.py`: pad hidden dim to 512 for per-token NVFP4 + ReLU2 TRT-LLM MoE (weights, activations, output slice).
- `layers/quantization/modelopt_quant.py`: pass the hidden alignment into weight prep and the padded size into the MoE quant info.
- `test/.../test_modelopt_nvfp4_moe_scales.py`: CPU unit tests for hidden/intermediate padding and the alignment rule.
- `test/.../test_flashinfer_trtllm_gen_moe_backend.py`: add per-token ReLU2 e2e on Nemotron 3 Super NVFP4 (threshold 0.93).
- `test/.../test_nvidia_nemotron_3_super_nvfp4.py`: add per-token nightly class on `flashinfer_trtllm` with a 0.93 threshold.
