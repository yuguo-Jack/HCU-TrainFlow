# [Perf] dsv41: Read Engram shards directly over NVLink

[Upstream PR](https://github.com/sgl-project/sglang/pull/45679) · state: closed · merged: False

## Original PR description

Engram currently gathers local FP8 rows and all-reduces the BF16 result. This maps immutable shards once during loading and adds owner selection to the existing gather kernel, allowing eligible ranks to read rows directly from the owning GPU.

Support is limited to single-node SM10x TP4 / attention DP1 / CP1, verified full NVLink/P2P, standard auto/safetensors loading, and no IPC weight cache, CPU/offload backup or memory saver. Other configurations keep the existing path. Symmetric storage and its rendezvous handle remain alive for CUDA Graph replay; normal in-place reload uses the existing collective finish_load hook.

No new environment variable or registry entry is added. The final diff is 3 files, +237/-6: 125 added runtime lines and one focused 112-line distributed test. The two separate peer helper files have been removed. Final head: `99934e03ade7392ea9c6c5da97ce5349387d4077`.

### Correctness and decision

Four-rank GB300 integration tests pass for uneven/empty shards, int32/int64 IDs, invalid IDs, exponent zero, independent rank requests, zero-token lookup, changed-input graph replay, in-place reload, and dummy/IPC-cache loader fallback. Comparisons use zero numerical tolerance; no signed-zero bitwise-equivalence claim is made. The unchanged local gather also passes its external parity checks. Ruff, compile and whitespace checks pass.

GSM8K zero-shot repeats (same 200 examples, max 4096 and real EOS): 03_engram_dspark: 195/200, 04_baseline_dspark: 196/200, 07_baseline_dspark: 196/200, 08_engram_dspark: 195/200, 11_engram_nospec: 195/200, 12_baseline_nospec: 195/200. All predictions, answer changes and truncations are retained; this finite check does not prove population-level quality equivalence.

Post-timing traces on all four ranks confirm 24 Engram collectives removed over 12 forward steps. The peer gather itself is slower than a local gather; the benefit comes from removing the subsequent all-reduce. Profiled kernel intervals are not reported as endpoint speedups.

This remains draft. The DSPARK point estimates are positive, but five of six descriptive paired-bootstrap intervals include zero, all six paired log-ratio t intervals (df=3, sensitivity check) include zero, and several crossover blocks change sign. Non-speculative gains of +0.06% and +0.21% also reverse sign between the two startup pairs and are smaller than same-code startup drift. Stable incremental endpoint benefit over current main has not been established. The finite quality differences remain documented, without declaring either a proven regression or equivalence. Earlier measurements against ed89693 and local kernel improvements are not used to promote this PR. Lint and the updated title check pass; upstream GPU CI is gated by draft status, while the GPU validation above was run independently.
