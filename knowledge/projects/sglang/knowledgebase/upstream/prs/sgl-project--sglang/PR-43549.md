# [Fix] chat_encoding: Preserve inline system messages for the dsv41 native encoder

[Upstream PR](https://github.com/sgl-project/sglang/pull/43549) · state: open · merged: False

## Original PR description

Anthropic's `/v1/messages` converter hoists any in-message `system` turn into the leading system block unless the prompt renderer says it keeps system turns where they are. For `dsv41` that question was answered by the Jinja probe, and DeepSeek-V4.1-Flash ships no `chat_template`, so the probe answers False and every multi-turn Anthropic request gets a rewritten prompt prefix — which is exactly what defeats the radix cache.

`spec_supports_inline_system` already exists as the escape hatch for encoders with no Jinja source (`kimi_k3` uses it); `dsv41` belongs in the same set.

The `dsv4` family now renders through `deepseek-recipe`, which converts the message list itself, so there is nothing for the probe to read either way — the allowlist is still the right place to answer, and the comment now points at that instead of the removed `encoding_dsv41.render_message`.

Tests: `test/registered/unit/entrypoints/anthropic/test_serving.py` covers the allowlist answer and that `AnthropicServing` stops merging inline system turns for `dsv41`.
