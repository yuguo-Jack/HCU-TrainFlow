## Motivation

When FIA is enabled, the current Ascend MHA KV-cache write path launches two `npu_scatter_nd_update_` operators per layer: one for the key cache and one for the value cache.

CANN provides `ScatterPaKvCache`, exposed through torch_npu as `npu_scatter_pa_kv_cache`. It can update the paged key and value caches in a single operator, reducing kernel-launch and slot-mapping overhead for decode workloads.

Downstream profiling also shows that the optimal write path depends on the forward stage:

- Decode and speculative decode with a small number of new tokens can benefit from ScatterPaKvCache.
- Large prefill writes perform better with the existing ScatterNdUpdate path.

Therefore, this PR introduces ScatterPaKvCache as an optional, decode-oriented backend instead of replacing the existing implementation unconditionally.

Closes #39355.

## Modifications

This PR includes the following changes:

- Add the `SGLANG_NPU_USE_SCATTER_PA_KV_CACHE` environment variable.
  - Disabled by default.
  - Existing behavior remains unchanged when it is not enabled.
- Use `torch_npu.npu_scatter_pa_kv_cache` for:
  - regular decode;
  - decode graph execution;
  - speculative decode and MTP verification.
- Keep prefill and extend writes on the existing two-ScatterNdUpdate implementation.
- Use `cache_mode="Norm"` for the current PA-ND cache layout:
  - key/value: `[num_tokens, num_kv_heads, head_dim]`;
  - cache: `[num_blocks, page_size, num_kv_heads, head_dim]`;
  - slot mapping: one flattened physical slot per token.
- Convert the slot mapping to contiguous `int32`, as required by the operator interface.
- Forward the decode write-backend hint through hybrid SWA pools to the selected NPU KV-cache sub-pool.
- Add explicit validation for:
  - `ASCEND_USE_FIA=1`;
  - availability of `torch_npu.npu_scatter_pa_kv_cache`;
  - portable FP16, BF16, and INT8 KV-cache data types.
- Add registered NPU unit tests covering:
  - key/value paged-cache layout;
  - slot-mapping semantics and cache contents;
  - environment-variable gating;
  - prefill fallback to ScatterNdUpdate;
  - unsupported configuration errors;
  - hybrid SWA forwarding.
- Document the new environment variable in the Ascend NPU environment-variable reference.

The feature can be enabled with:

```bash
export ASCEND_USE_FIA=1
export SGLANG_NPU_USE_SCATTER_PA_KV_CACHE=1
