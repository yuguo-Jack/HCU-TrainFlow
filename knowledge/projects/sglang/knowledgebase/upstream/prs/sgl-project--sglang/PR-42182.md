# [Fix] [NPU] moe: Keep routing weights in FP32 through AscendTPDispatcher

[Upstream PR](https://github.com/sgl-project/sglang/pull/42182) · state: open · merged: False

## Original PR description

Closes #39351

Supersedes #39369 and #39394 (same one-line fix): #39369 could not run its
test or validate on NPU hardware; #39394's CI is failing. This PR adds
real-hardware numerical validation on 910B3. If maintainers prefer to land
via #39369 with this evidence appended, I'm happy to close this one.

## What
`AscendTPDispatcher.dispatch()` downcasts the FP32 routing weights produced by
the TopK layer to the hidden-state dtype before they reach
`npu_moe_finalize_routing`. The finalize kernel natively accepts FP32 scales,
so the cast discards precision in every MoE layer on the default NPU path
(`a2a_backend.is_none() and is_npu()` -> AscendTPDispatcher).

This keeps routing weights in FP32 through dispatch/combine.

## Evidence (910B3, CANN 9.0.0, torch_npu 2.10.0, sglang v0.5.18)
Against an FP64 reference recomputation of the finalize semantics
(256x512 hidden, 16 experts, top-8, drop_pad_mode=2):

| path | max abs err vs FP64 ref |
|---|---|
| kernel with FP32 weights | 4.0e-07 |
| kernel with BF16 weights (current) | 1.6e-02 |
| pure-math BF16 weights | 8.0e-03 |

Quantized paths (INT8/MXFP8) are untouched: the change only affects routing
weights; hidden-state quant mode is selected separately via
`ascend_dispatcher_output_dtype`.
