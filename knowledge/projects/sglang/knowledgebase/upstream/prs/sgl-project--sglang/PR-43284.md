# [MLX] Drop a retracted request's runner state at its re-prefill

[Upstream PR](https://github.com/sgl-project/sglang/pull/43284) · state: closed · merged: True

## Original PR description

## Motivation

The MLX runner keeps each request's KV cache outside the scheduler's pool. When the scheduler retracts a request, it frees the request's pool KV without a tree insert and requeues it, but the runner's state for that request remains. On re-prefill, `_route_extend_request` finds the stale state, routes the request as a continuation, and extends the old KV a second time.

## Modifications

- `MlxTpModelWorker` records `req.retraction_count` when it creates a request's runner state.
- Before routing a request in an extend batch, the worker drops that state, without syncing it to the pool, if the request has been retracted since; the re-prefill then starts from scratch.
- `MlxModelRunner.remove_request` gains `sync_kv` (default `True`, so the finish path is unchanged).

The fix is confined to the MLX backend: every retraction path (decode retraction, priority preemption, retract-mode `pause_generation`) goes through `Req.reset_for_retract`, which increments `retraction_count`, so the scheduler needs no hook. This also covers the decode-retraction case addressed by #38179.

## Verification

- `test_retracted_request_reprefills_from_scratch`: a request whose `retraction_count` changed after its first prefill drops its state and re-prefills from scratch; it fails without the change.
- MLX server (Qwen3-0.6B-4bit, `--disable-radix-cache`), two concurrent greedy 300-token requests with three retract pauses per round, 3 rounds: re-prefills routed as continuations drop from 18 on #43282 to 0, and all outputs match an unpaused run. Under `SGLANG_TEST_RETRACT=1`, 299 retractions complete without error and every re-prefill starts from scratch.
- `test/registered/unit/hardware_backend/mlx/`, `test_scheduler_pause_generation.py` and `test_prefill_result_polling.py` pass on Apple Silicon.
