# [Perf] function_call: Eliminate O(N^2) streaming bottleneck in BaseFormatDetector

[Upstream PR](https://github.com/sgl-project/sglang/pull/45113) · state: open · merged: False

## Original PR description

## Motivation

During incremental tool-call streaming (`FunctionCallParser.parse_stream_chunk`), `BaseFormatDetector.parse_streaming_increment` currently re-runs four $O(N)$ operations across the entire accumulated buffer on **every token chunk** while streaming a tool call's arguments:

1. `_partial_json_loads(current_text[start_idx:], flags)` (`partial_json_parser` scans the entire open JSON string character-by-character in Python to complete it, followed by `json.loads`).
2. `_is_complete_json(raw_slice)` (`orjson.loads` over the growing slice).
3. Two full `json.dumps(..., ensure_ascii=False)` serializations (`cur_arguments` and `prev_arguments`).
4. `_find_common_prefix(prev_args_json, cur_args_json)` in `sglang/srt/function_call/utils.py`, which loops character-by-character in Python (`prefix += s1[i]`) from index `0` on every chunk.

For tool calls with medium-to-large string arguments (such as coding-agent `write_file`, `edit_file`, patch, or SQL/document payloads of 12–20 KB streamed in ~3-character token chunks), this quadratic $O(N^2)$ work blocks the serving loop for **7–20+ seconds of CPU time per tool call** across all detectors backed by `BaseFormatDetector` (`Qwen25Detector`, `HermesDetector`, `Llama32Detector`, `MistralDetector`, `TrinityDetector`, `JsonArrayParser`, and `IQuestQ1JsonToolParser`, as well as `tool_choice="required"` fallback via `JsonArrayParser`).

### `cProfile` Breakdown Before Optimization (13.3 KB `write_file` tool call, 4,500 chunks on `Qwen25Detector`)
- `_find_common_prefix` (`utils.py:177`): **47.4% (3.53s)** — 4,492 calls scanning and concatenating `prefix += s1[i]` char-by-char in Python
- `_partial_json_loads` -> `partial_json_parser.core.myelin.fix_fast` / `complete_str`: **43.1% (3.20s)** — 4,499 full scans + `json.loads`
- `json.dumps`: **7.1% (0.53s)** — 8,985 full dict re-serializations

(Cross-pollinated from the corresponding streaming tool-parser optimizations in `vllm-project/vllm#61253`, `vllm-project/vllm#61494`, and `vllm-project/vllm#62334`.)

## Modifications

1. **`python/sglang/srt/function_call/utils.py` (`_find_common_prefix`)**:
   - Replace the $O(N)$ Python character-by-character loop + string concatenation (`prefix += s1[i]`) with C-level slice comparisons via binary search (`s1[low:mid] == s2[low:mid]`), with an $O(1)$ fast check when `s1[:min_length] == s2[:min_length]`.
2. **`python/sglang/srt/function_call/base_format_detector.py` (`BaseFormatDetector.parse_streaming_increment`)**:
   - Add an $O(|\text{delta}|)$ open-string streaming fast path when `BaseFormatDetector` is streaming inside an open top-level string argument of `arguments`/`parameters` (brace depth 2: outer tool-call object `{` and inner `arguments` object `{`).
   - Subsequent chunks that only append simple characters or 2-character escapes (`\"`, `\\`, `\b`, `\f`, `\n`, `\r`, `\t`) decode and emit the exact JSON string delta in $O(|\text{delta}|)$ without invoking `_partial_json_loads`, `_is_complete_json`, or `json.dumps` on the full buffer.
   - Preserve exact chunk-by-chunk parity with `partial_json_parser` and `BaseFormatDetector`:
     - Hold back trailing whitespace inside open strings (matching `partial_json_parser.core.complete._fix`, which calls `.strip()` before closing an incomplete string) and trailing odd backslashes until the next non-whitespace character arrives.
     - Hold back the last character via `_open_arg_pending_delta` on entry so each chunk emits the exact prefix shared between `prev_args_json` and `cur_args_json`.
     - Guard against retroactive single-quote buffer rewrites in `Llama32Detector` (`_open_arg_quote_pos`) and fall back seamlessly to the full parser whenever a closing quote `"`, complex escape (`\uXXXX`, `\/`, etc.), or structural transition arrives.
3. **`test/registered/unit/function_call/test_function_call_parser.py`**:
   - Add unit tests in `TestBaseFormatDetector` covering split escape sequences (`\"`, `\\`, `\n`, `\t`, `\b`, `\f`, `\r`, `\/`, `\uXXXX`), whitespace runs, multi-argument transitions, `_find_common_prefix` edge cases, and a regression check verifying `_partial_json_loads` is called $O(1)$ times (< 30 calls) across a >1,500-chunk string stream.

## Accuracy Tests

- Verified 100% chunk-by-chunk `StreamingParseResult`, `prev_tool_call_arr`, and `streamed_args_for_tool` equivalence across 2,000 randomized differential fuzzing trials (varying chunk sizes `1..25`, simple/unicode escapes, whitespace runs, quotes, braces, parallel tool calls, and truncated streams) across `Qwen25Detector`, `HermesDetector`, `Llama32Detector`, `MistralDetector`, `JsonArrayParser`, and `IQuestQ1JsonToolParser`.
- Ran existing + new unit test suites in `test/registered/unit/function_call/` (`TestBaseFormatDetector`, `TestQwen25Detector`, `TestHermesDetector`, `TestLlama32Detector`, `TestMistralDetector`, `TestJsonArrayParser`, `TestParallelToolCalls`).

## Speed Tests and Profiling

End-to-end streaming benchmark on a 13.3 KB `write_file` tool call streamed in 3-character chunks (~4,500 chunks) on ARM64 CPU:

| Detector | Before (ms) | After (ms) | Speedup |
| :--- | ---: | ---: | ---: |
| `Qwen25Detector` | 10,622.3 ms | **44.0 ms** | **241.5x** |
| `HermesDetector` | 10,469.1 ms | **47.5 ms** | **220.3x** |
| `JsonArrayParser` | 10,451.8 ms | **47.7 ms** | **219.2x** |
| `MistralDetector` | 10,478.8 ms | **60.1 ms** | **174.4x** |
| `Llama32Detector` | 10,614.0 ms | **126.6 ms** | **83.8x** |
