# [Fix] [AMD] diffusion: Compare ReduceOp by identity so the compiled TP all-reduce stays one graph

[Upstream PR](https://github.com/sgl-project/sglang/pull/43770) · state: closed · merged: True

## Original PR description

## What

Makes `GroupCoordinator.all_reduce` compare its `op` argument by identity (`op is ReduceOp.SUM`) instead of with `==`. This fixes `test_compiled_all_reduce_is_one_graph` on the ROCm lanes, e.g. https://github.com/sgl-project/sglang/actions/runs/38249882022/job/114813200452

## Why

Dynamo in torch 2.9 and 2.11 (the AMD images run these) cannot trace `RedOpType.__eq__`. The compiled all-reduce therefore raises `Unsupported: Builtin operator.* comparison with constant self failed` under `fullgraph=True`, and graph-breaks otherwise. torch 2.14 handles `==`, which is why CUDA CI passes.

The CPU shm branch of the same method already uses `is`. Every caller passes the `ReduceOp.SUM` class attribute itself (the default or `cfg_model_parallel_all_reduce`'s default), so the fast path is chosen exactly as before. A caller passing another op still falls through to `torch.distributed.all_reduce`.

The IPC all-to-all test failure in the same job is handled in #44096.

## Test plan

- A standalone repro of this condition under `torch.compile(fullgraph=True, backend="eager")` on CPU torch wheels: `==` fails on 2.9.1 and 2.11.0 and passes on 2.14.1. `is` passes on all three.
- ROCm 10 (MI300): `test_compiled_all_reduce_is_one_graph` passes in [multimodal-gen-test-1-gpu-amd (rocm10, 1)](https://github.com/sgl-project/sglang/actions/runs/38429220418/job/115408085238), and the TP2 server case `flux2_modelopt_fp8_tp2_t2i` passes in [multimodal-gen-test-2-gpu-amd (rocm10, 0)](https://github.com/sgl-project/sglang/actions/runs/38429220418/job/115408085022). The other failures in that run are unrelated: tests that already fail on `main`, Hugging Face rate limits on LoRA downloads, and a GPU hang in a single-GPU server test.
