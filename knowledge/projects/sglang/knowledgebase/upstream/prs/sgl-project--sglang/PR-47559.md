# [Fix] openai: Prevent infinite loop in split_audio_energy_aware when max_clip_s <= search window

[Upstream PR](https://github.com/sgl-project/sglang/pull/47559) · state: open · merged: False

## Original PR description

## Motivation

In `python/sglang/srt/entrypoints/openai/audio_chunking.py`, `split_audio_energy_aware(audio_data, max_clip_s, sample_rate=16000)` computes:

```python
chunk_size = int(sample_rate * max_clip_s)
search_size = int(sample_rate * SPLIT_SEARCH_WINDOW_S)  # 1.0 s
...
search_start = i + chunk_size - search_size
search_end = min(i + chunk_size, total)
split_point = find_split_point(audio, search_start, search_end)
raw_chunks.append(audio[i:split_point])
i = split_point
```

Two boundary conditions cause `split_audio_energy_aware` to hang in an infinite loop:
1. When `0 < max_clip_s <= SPLIT_SEARCH_WINDOW_S` (`1.0` second), `chunk_size <= search_size`, so `search_start = i + chunk_size - search_size <= i`:
   - For `max_clip_s < 1.0` (e.g., `0.5`s), on the first iteration (`i = 0`), `search_start < 0` while `search_end > 0`. In `find_split_point`, `wav[start_idx:end_idx]` slices from a negative index to a positive index in NumPy (returning an empty array), returning a negative `split_point = search_start < 0`, appending `audio[0:negative]`, and setting `i < 0` in an unbounded loop.
   - For `max_clip_s == 1.0`, `search_start == i`; whenever the first stride is the quietest (e.g., silence or decreasing energy) or `len(segment) <= MIN_ENERGY_WINDOW_SIZE`, `find_split_point` returns `split_point == i`, appending empty `audio[i:i]` chunks forever (`i` never advances).
2. When `max_clip_s <= 0`, `sample_rate <= 0`, or `int(sample_rate * max_clip_s) <= 0`, `chunk_size <= 0` is not validated prior to decoding and entering the chunking loop.

## Modifications

- Validate `max_clip_s > 0`, `sample_rate > 0`, and `chunk_size = int(sample_rate * max_clip_s) > 0` up front with clear `ValueError` messages before decoding audio.
- Clamp `search_start = max(i + 1, i + chunk_size - search_size)` so `i < search_start <= split_point <= search_end` always holds and `i` strictly advances by at least 1 sample on every iteration while preserving bit-identical split points whenever `max_clip_s > SPLIT_SEARCH_WINDOW_S`.
- Add unit tests in `test/registered/unit/entrypoints/openai/test_audio_chunking.py` covering `max_clip_s <= SPLIT_SEARCH_WINDOW_S` (`0.5`s and `1.0`s) and invalid `max_clip_s` / `sample_rate` inputs.
