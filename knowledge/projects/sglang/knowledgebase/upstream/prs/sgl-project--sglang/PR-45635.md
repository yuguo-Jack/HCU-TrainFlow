# [Perf] dsv41: Token-interleaved V4.1 KV caches for the FlashMLA V4.1 kernels

[Upstream PR](https://github.com/sgl-project/sglang/pull/45635) · state: closed · merged: False

## Original PR description

## Motivation

The latest FlashMLA DeepSeek-V4.1 kernels read a token-interleaved KV cache (each token's data followed by its scales). Serve with them.

The kernels come from the `sgl-flash-mla` wheel built from sgl-project/FlashMLA's `sgl` branch (release workflow: #45651); this PR adds `sgl-flash-mla==1.0.0` to the dependencies and leaves sgl-kernel's FlashMLA untouched for every other path.

## Modifications

- V41 / V41_FP4 pages store 528 B / 288 B per token (data then scales), unpadded; `PagedKV::row`, the Triton dequant, the request-window copy and `kv_layout.py` address the new layout.
- MegaAttention decode and the V4.1 sparse decode call `flash_mla.fused_norm_rope_attn_rope_cast.decode` and `flash_mla.flash_mla_with_kvcache` from the wheel through `sglang.kernels.ops.attention.dsv4.flashmla_v41`.
- PD layout handshake gains a `;token-interleaved` suffix; HIP refuses the V4.1 layouts.
- Tests: new `test_flashmla_v41.py`; mega-attention test uses the new op; V4.1 dequant tests enabled on SM100; c128 pool page expects 1056 B.
