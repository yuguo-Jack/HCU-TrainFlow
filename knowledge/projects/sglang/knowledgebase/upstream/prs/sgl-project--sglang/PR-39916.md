# [Anthropic] Fix /v1/messages usage cache field mapping

[Upstream PR](https://github.com/sgl-project/sglang/pull/39916) · state: closed · merged: False

## Original PR description

## Motivation

Fixes #39900.

`/v1/messages` usage did not follow Anthropic's disjoint input contract. Cold requests never emitted `cache_creation_input_tokens` (the radix write was billed as `input_tokens`). Warm requests could still count the cached span in `input_tokens` while also reporting `cache_read_input_tokens`.

OpenAI `/v1/chat/completions` already exposes `prompt_tokens` + `prompt_tokens_details.cached_tokens`. This is a mapping gap in the Anthropic handler.

## Modifications

Map OpenAI cache stats onto Anthropic's three exclusive fields:

- `cache_read_input_tokens` = prefix-cache hit (`cached_tokens`)
- `cache_creation_input_tokens` = remainder of the prompt (tokens computed and inserted into the radix tree)
- `input_tokens` = 0 when cache stats are available, so it does not overlap either cache field

Without `--enable-cache-report` (or with radix cache disabled), behavior is unchanged: the whole prompt stays in `input_tokens`.

Requires `--enable-cache-report`, same as the OpenAI cached-token path.
