# [Perf] [NVIDIA] attention: Tune long FP8 asymmetric prefill on RTX PRO 6000

[Upstream PR](https://github.com/sgl-project/sglang/pull/42451) · state: open · merged: False

## Original PR description

Reopened from #40742. GitHub closed that PR on 2 October when the fork it came from was deleted; its review history is still there.

## Motivation

Long-prefix Triton attention is the main prefill cost for MiMo-V2.6-Flash-RL on two RTX PRO 6000 Blackwell Server Edition GPUs. In a six-step late-prefill profile, the nine global-attention layers consumed 13,124 ms per rank, versus 102 ms for the 39 sliding-window layers.

## Modifications

Use a 128-row query tile and 128-row prefix tile for the measured RTX PRO 6000 shape: BF16 current Q/K/V, E4M3 FP8 cached K/V, QK192/V128, 32 query heads, two KV heads, page size one, at least 512 queries and every prefix at least 8,192 tokens. The current-token tile remains unchanged.

Pass the existing CPU prefix lengths through an optional trailing argument. Short prefixes, other devices or geometries, custom masks, window/sink attention and CUDA graph capture retain the original dispatch. Captured graphs can replay with different device prefix lengths, so capture deliberately retains the original partition.

## Accuracy Tests

- Sixteen real-GPU regression cases passed on each of the two cards, including ragged prefixes, exact fallback comparisons and CUDA graph replay from an 8,192-token prefix to a 257-token prefix.
- The isolated 524K-prefix configuration screen measured relative RMS difference 0.001762 and maximum absolute difference 0.0000611 against the original partition.
- A matched whole-model likelihood check used 64 fixed 16K contexts, 1,024 scored suffix tokens each, with the same FP8 KV and 4K prefill chunk on both runtimes. NLL was 1.9191643658 before and 1.9151446877 after; all 65,536 scored positions were finite and the cached prefix was verified for every case. This measures numerical agreement, not byte identity.
- Full-model validation used the public `tiyuvta/MiMo-V2.6-Flash-RL-NVFP4` artifact at `58edbd0c60ace653512b8f423bf41813331ef9e3`, plus the loader fixes proposed separately in #42450 and #42452.

## Speed Tests and Profiling

On RTX PRO 6000 Blackwell Server Edition, a 2,048-query / 524,288-prefix isolated attention call measured 184.636 ms with M64/N64 and 91.568 ms with M128/prefix-N128 (eight warps, one stage; five timed calls after warm-up). The latter uses 90,112 shared bytes under the device's 101,376-byte limit.

A complete 786,034-token cold request with the optimized runtime produced its first token in 291.394 s and correctly retrieved three planted values. The earlier runtime required 536.462 s. This complete-runtime comparison also increases the prefill chunk from 2,048 to 4,096, so it is not an isolated attribution to this patch. Both runs used TP2/EP2, FP8 KV, host caching and the vendor's sampled defaults.

The qualification image pins upstream `0f6761b54facebb47f2068f87ecccd8f14da3a0e`, Torch 2.13.0+cu130 and FlashInfer 0.6.18. No result is claimed for another GPU family.
