# [Fix] olmoe: apply q/k norm over all heads under tensor parallelism

[Upstream PR](https://github.com/sgl-project/sglang/pull/47272) · state: open · merged: False

## Original PR description

## Motivation

OLMoE can't run with `--tp-size > 1` on any platform (#11651, which was auto-closed and is still reproducible on current `main`). `OlmoeAttention` applies `q_norm` / `k_norm`, which are RMSNorms over **all** heads (`hidden_size`), directly to the per-rank q/k shards. The first forward fails:

```
File ".../models/olmoe.py", line 191, in forward
ValueError: Expected hidden_size to be 2048, but found: 1024
```

Comments on #11651 report the same failure on NVIDIA (A100, TP=2, in a FlashInfer RMSNorm shape check). I hit it on AMD Radeon while validating TP2 there.

## Modifications

Same approach as `olmo2.py`'s `_apply_qk_norm` (and vLLM's OLMoE):

- When `tp_size > 1`, all-gather q and k across the TP group, apply the full-width norms, then take this rank's slice back with `split_tensor_along_last_dim`.
- `k_norm` is sized `total_num_kv_heads * head_dim` instead of `hidden_size`. They are equal for OLMoE checkpoints (16 KV heads), so nothing changes there, but the norm now matches k's width.

TP=1 does exactly the same arithmetic as before.

## Accuracy Tests

allenai/OLMoE-1B-7B-0125-Instruct on RDNA4 (gfx1201 ×2, PCIe):

- Stock `rocm/pytorch` image.
- `main` + #43679 + #47254 (needed for this GPU) + a local quark-import guard.
- Default server flags (Triton attention, decode CUDA graphs).
- gsm8k: `sgl-eval==0.1.2`, 200 questions, temperature 0.7, top_p 0.8.
- Throughput: `bench_serving` random-ids 512/256.

| | without this PR, TP2 | with this PR, TP2 | with this PR, TP1 |
|---|---|---|---|
| server | ❌ `ValueError: Expected hidden_size to be 2048, but found: 1024` | ✅ | ✅ |
| gsm8k (200) | — | 59.0% | 60.5% |
| c=1 output tok/s (median TPOT) | — | 122.8 (8.0 ms) | 97.8 (10.1 ms) |
| c=8 output tok/s (median TPOT) | — | 623.4 (12.3 ms) | 446.4 (17.5 ms) |

TP2 matches TP1 accuracy within sampling noise.
