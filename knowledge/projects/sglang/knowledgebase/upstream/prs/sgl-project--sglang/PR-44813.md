# [Fix] deepseek_v4: route unquantized BF16/F16/F32 checkpoints off the MXFP4 expert path

[Upstream PR](https://github.com/sgl-project/sglang/pull/44813) · state: open · merged: False

## Original PR description

## Motivation

Fixes https://github.com/sgl-project/sglang/issues/44810.

A DeepSeek-V4 BF16 checkpoint carries no `quantization_config`. In `ModelConfig`, `is_fp4_experts` is initialized from the `SGLANG_DSV4_FP4_EXPERTS` env var (default `True`) and is only overridden when `try_detect_fp4_experts()` returns a non-`None` value. That detector returned `None` for any dtype other than the mxfp4-packed (`U8`/`I8`/`F4`) or FP8-converted (`F8_E4M3`) layouts — including unquantized `BF16`/`F16`/`F32`. As a result, an unquantized DSV4 checkpoint kept `is_fp4_experts=True` under default settings and the auto MoE-runner backend routed it to the `flashinfer_mxfp4` path, while the rest of the stack treated it as unquantized, crashing the first request with `ValueError: too many values to unpack (expected 3)`.

## Modifications

- `python/sglang/srt/configs/deepseek_v4.py`: `try_detect_fp4_experts()` now returns `False` for unquantized routed-expert dtypes (`BF16`/`F16`/`F32`), so unquantized checkpoints take the unquantized expert path instead of falling back to the FP4-experts env default. Genuine MXFP4 (`U8`/`I8`/`F4` → `True`) and FP8-converted (`F8_E4M3` → `False`) detection is unchanged; unknown or unreadable headers still return `None` and fall back to the user/env default.
- `test/registered/unit/configs/test_deepseek_v4_fp4_detect.py`: new unit tests covering `BF16`/`F16`/`F32` → `False`, `U8`/`I8`/`F4` → `True`, `F8_E4M3` → `False`, and `None` for unreadable/empty checkpoint dirs.

## Reproducer (no GPU required)

A full GPU repro is infeasible here (needs 8x B300 plus a DSV4 BF16 checkpoint), so the bug is demonstrated at the config-routing layer where it lives. Save the script below as `repro_44810.py` in the repo root and run `python3 repro_44810.py`. It builds fake checkpoint dirs (a single safetensors shard whose header declares one routed-expert weight tensor of the given dtype) and drives the real `try_detect_fp4_experts()` plus the real `probe_routed_expert_weight_dtype()` (AST-extracted from the repo; the only stubs are `transformers`/`QuantizationConfig` class-level deps and `find_local_repo_dir`, which is unreachable for local dirs), then applies the same `None`-vs-env-default logic `ModelConfig` uses.

```python
import ast, json, os, re, struct, sys, tempfile, types
from pathlib import Path
from typing import Optional

REPO = os.path.dirname(os.path.abspath(__file__))

weight_utils_src = open(f"{REPO}/python/sglang/srt/model_loader/weight_utils.py").read()
tree = ast.parse(weight_utils_src)

def _wanted(n):
    if isinstance(n, ast.Assign):
        return any(getattr(t, "id", "") == "_ROUTED_EXPERT_KEY_RE" for t in n.targets)
    return getattr(n, "name", None) == "probe_routed_expert_weight_dtype"

seg = [n for n in tree.body if _wanted(n)]
wmod = types.ModuleType("sglang.srt.model_loader.weight_utils")
wmod.__dict__.update({"re": re, "json": json, "struct": struct, "os": os,
                      "Path": Path, "Optional": Optional,
                      "logging": __import__("logging")})
exec(compile(ast.Module(body=seg, type_ignores=[]), "<wu>", "exec"), wmod.__dict__)

def make_pkg(name):
    m = types.ModuleType(name); m.__path__ = []; sys.modules[name] = m; return m

for pkg in ["sglang", "sglang.srt", "sglang.srt.configs",
            "sglang.srt.model_loader", "sglang.srt.utils"]:
    make_pkg(pkg)
sys.modules["sglang.srt.model_loader.weight_utils"] = wmod
sys.modules["sglang.srt.utils"].find_local_repo_dir = lambda *a, **k: None

dv4_tree = ast.parse(open(f"{REPO}/python/sglang/srt/configs/deepseek_v4.py").read())
fn_node = next(n for n in dv4_tree.body
               if getattr(n, "name", None) == "try_detect_fp4_experts")
dv4 = types.SimpleNamespace()
dv4.__dict__.update({"os": os, "logging": __import__("logging"), "Optional": Optional})
exec(compile(ast.Module(body=[fn_node], type_ignores=[]), "<dv4>", "exec"), dv4.__dict__)

KEY = "model.layers.0.mlp.experts.0.w1.weight"

def make_ckpt(dtype_str):
    d = tempfile.mkdtemp()
    header = json.dumps({KEY: {"dtype": dtype_str, "shape": [2048, 4096]}}).encode()
    with open(os.path.join(d, "model.safetensors"), "wb") as f:
        f.write(struct.pack("<Q", len(header))); f.write(header)
    return d

for dtype in ["BF16", "F16", "F32", "U8", "I8", "F4", "F8_E4M3"]:
    detected = dv4.try_detect_fp4_experts(make_ckpt(dtype))
    is_fp4_experts = detected if detected is not None else True  # env default
    print(f"safetensors dtype={dtype:8s} -> try_detect_fp4_experts()={detected!s:5s}"
          f"  is_fp4_experts={is_fp4_experts}")
```

## Accuracy Tests

This change only affects config-time routing for DeepSeek-V4 checkpoints without an explicit `quantization_config`; no kernel or forward-path code is touched. The new unit tests assert the detection matrix above (the full sglang import chain is GPU/heavy-dep bound in this environment, so the test logic was additionally validated by executing the real extracted functions against fake checkpoint shards — all 9 cases pass). Please let CI run the new `test/registered/unit/configs/test_deepseek_v4_fp4_detect.py`.
