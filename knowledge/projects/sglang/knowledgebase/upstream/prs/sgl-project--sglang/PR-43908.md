# [Refactor] scheduler: Hold wrapped requests in request lists and abort through each list

[Upstream PR](https://github.com/sgl-project/sglang/pull/43908) · state: closed · merged: True

## Original PR description

Request lists whose owners keep extra state with each request (a `DecodeRequest`, a release record, a HiSparse action, a deferred response) use the same `_RequestList` as the plain lists, and their aborts move onto the lists.

- `_RequestList` takes `req_of`, which finds the request in a joined item: it iterates requests, keys `leave` / `take` / `clear` by request, and gives the owner its items through `items()`.
- The PD decode prealloc, transfer and releasing queues, HiSparse staging and deferred responses are `_RequestList`s. The prealloc, transfer and deferred aborts move from `Scheduler.abort_request` onto the lists; releasing and HiSparse staging keep having none. Poll loops take one snapshot per pass, as the queue order is all-reduced across ranks; the priority sort writes the new order back with `clear` and `join`.
- uOCR keeps its held document windows in two lists, `UOCR_PARKED` (waiting for the previous window) and the new `UOCR_RELEASED` (waiting to be queued); their abort replaces `drop_parked` and the uOCR block in `abort_request`.
- `DecodeRequest.seqlen` and `.priority`, `DeferredResponses.held_reqs()` and `DocPrefetch.held_reqs()` / `drop()` are removed: readers get the request from the list.
- Test fakes build these queues with `decode_queue` / `_RequestList` and identity-hashed `FakeReq`s.

Behavior changes:
- Within one abort, these lists are aborted in `request_lists()` order, so the abort outputs of different requests can be sent in a different order.
- Fixes a uOCR follow-up window being lost: when two follow-ups waited on the same window, the second replaced the first, which was then never queued, aborted or reset. Both now stay parked, and both are released with the remaining budget when the window finishes.

## Test plan
- `test_every_follow_up_of_a_window_is_released` covers the uOCR fix.
- `test_decode_loads_count_prealloc_requests_waiting_for_input` covers the prealloc ready count read through the wrapped queue.
- The unit tests that build these queues or call the changed methods, and the unit tests under `test/registered/unit/{managers,disaggregation,dllm,constrained,mem_cache,observability,session}`, pass locally with `SGLANG_IS_IN_CI=1`, apart from failures the base has too.
