## [DSA][DCP] HiCache host tier under decode context parallel

**Stacked on #39638** (itself stacked on #39330) — this PR carries both; only the last 3 commits (`edc5dedea7`, `77f281ee0f`, `05d27a97a8`; 5 files, +149/−49) are new. Merge order: #39330 → #39638 → this PR. Opened as a draft until the two below it land.

### Motivation

Under DCP each rank holds 1/dcp of the MLA latent KV, and upstream's HiCache already stripes the anchor MLA host pool per rank. The DSA indexer's index-K, however, is replicated over the virtual loc space (#39330), so its host pool must not be translated per rank — which is why #39330's guard rejects `--enable-hierarchical-cache` under DCP. This PR gives the DSA index-K host pool the right addressing and admits the host (L2) tier. In production the host tier is what turns a 725K-context re-prefill from 156 s into 2.2 s.

### Modifications

1. **`mem_cache/pool_host/dsa.py`** — the DSA indexer host pool addresses the anchor's LOGICAL slot space (replicated index-K, no per-rank translation) and packs only the layers that own index-K (top-k reuse layers are skipped; on GLM-5.3 that is 22 of 78 layers). Top-k layer index-K elision is kept with HiCache under DCP (`kv_cache_configurator.py`: elide when DCP is on and no L3 storage backend is configured). The guard (`overrides.py`) admits HiCache without L3 storage; `--hicache-storage-backend` stays rejected because storage page keys are not `dcp_rank`-aware.
2. **`arg_groups/hicache_hook.py`** — the HiCache × DCP gate (previously DSPARK-only) admits EAGLE / NextN **only as the packed NextN/MTP draft** (`num_nextn_predict_layers > 0`, no `--speculative-draft-model-path`): its single MLA layer rides in the anchor host pool with the anchor's striped translation. A separate EAGLE draft model stays rejected (it gets a sidecar host pool without translation). The comparison is normalized (upper-cased, `NEXTN` alias) because `handle_hicache` runs before `handle_speculative_decoding` collapses the alias.
3. **`mem_cache/hybrid_cache/hybrid_cache_controller.py`** — transfer byte accounting (`_transfer_num_bytes`) counts this rank's 1/dcp slots for striped pools.

### Evidence (GLM-5.3 base, fp8, 8×H200, DCP8 + EAGLE + HiCache 48 GB host = 7.41M logical tokens)

- 128K document round trip: cold 19.7 s → device hit 0.68 s → after 2.57M fresh tokens evict it from device: **host hit 0.69 s**, output byte-identical; `sglang:prefill_effective_tokens_total{mode="host_hit"}` +128,512.
- 725K needle after full demotion: **+656,896 tokens served from host, 0 from device**, TTFT 2.22 s vs 156 s cold, answer correct.
- Host pool accounting 7.40M / 7.41M used, 0 host-pressure drops; device pool unchanged versus the no-HiCache boot (index-K elision held).
- TTFT p50 at 1 session 1.33 s → 0.44 s versus the EAGLE-only column of the same benchmark; 0 scheduler exceptions / OOM / CUDA errors / watchdog across the sweeps.
- EAGLE acceptance is unchanged with the host tier on (4.3 tokens/step at 32 running requests, fixed 5 steps, same as the EAGLE-only boot).
- Full stack (DCP8 + EAGLE fixed 5 steps + HiCache, max-running 32) against the TP8-replicated production recipe (EAGLE adaptive, HiCache 128 GB) on the same trace and protocol: TTFT p50 0.74 s vs 17.25 s at 16 sessions; aggregate output 466 vs 225 tok/s at 24 sessions with 357/357 vs 151/178 requests served (the misses are serving-layer 429s, not engine errors).
- Our production DCP8 replicas run this with a 96 GB host tier (14.8M logical tokens).
