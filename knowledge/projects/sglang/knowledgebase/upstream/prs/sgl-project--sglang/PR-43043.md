# [Fix] VLM: harden Kimi image cache identity across preprocessing and radix hashing

[Upstream PR](https://github.com/sgl-project/sglang/pull/43043) · state: closed · merged: True

## Original PR description

## Motivation

Supersedes #41792. Thank you to **@rchalamala (Rahul Chalamala)** for identifying the Kimi image-cache identity problem and implementing the original fix. This PR retains his original authored commit and builds on that implementation.

Multimodal padding previously reduced an item hash to 30 bits. Different images can therefore share radix-prefix keys and reuse incorrect KV entries. Kimi K2.5/K3 also need image identities that distinguish preprocessing configuration and patch grids, not only feature bytes.

## Modifications

- Share four 62-bit sentinel generation through `MultimodalDataItem.set_hash`, `set_pad_value`, and `set_identity`. Common padding repeats the pattern without changing image-token counts; existing scalar-padding consumers retain the first wide sentinel.
- Derive Kimi image identities from source content, preprocessing configuration, and grid. Cover ordinary, preprocess-cache, preprocessed/precomputed-input, and EPD item-construction paths, including HF `grid_thws` aliases and multi-image splitting. Reject caller overrides of Kimi cache identities.
- Hash the exact input snapshot before decoding and carry its digest alongside the decoded image, avoiding a GPU-to-CPU copy solely to hash ordinary nvJPEG output. Include normalization, patch settings, and the effective backend in the processor fingerprint.
- Recognize all sentinels in embedding scatter and ERNIE's visual mask, including partial chunks.
- Support wide placeholder tokens in C++/Rust page hashing instead of disabling PD, HiCache storage, or KV events. Existing uint32-only page hashes remain unchanged; wide pages use a distinct encoding.

**Why 62 bits per sentinel, not four 30-bit values?** Radix matching can stop after the first sentinel. Actual Python and Rust radix tests reproduce a false image-token hit with four 30-bit values at page size 1, and at page size 16 with 15 preceding text tokens. Later sentinels do not prevent that partial hit.

This hardens prefix-cache identity; it does **not** make every cache key 256 bits or eliminate all theoretical collisions. Generic item hashes and the embedding-cache integer hash remain 64 bits; expanding a 64-bit hash does not create additional entropy. Other models retain their existing identity semantics.

## Validation

Validated at `b28fc89a0b6501b52bd84f375920fce0d051fbc8` on NVIDIA B300 with PyTorch 2.14.1+cu130:

- **153 focused Python tests + 74 subtests passed**, covering Kimi identity, ordinary/EPD item construction, CPU/CUDA embedding scatter, nvJPEG input snapshots, shared hash assignment, and ERNIE's visual mask.
- **82 radix/native hash tests passed**, including 80 combinations across actual Python/Rust trees, page sizes 1/16, image-span lengths, and text-prefix alignment.
- **Four real-weight Qwen2.5-VL-3B-Instruct serving tests passed**: raw images, processor outputs, precomputed embeddings, and a low-30-bit hash-collision regression. Model revision: `66285546d2b821cf421d4f5eb2576359d3770cd3`.
- The same serving regression **fails on the previous PR head `0be7358013f`**: after caching a red image, a blue image with a different caller hash but identical low 30 bits incorrectly receives “Red”; the cold blue control receives “Blue”. The fixed head passes the identical test.
- CPU-hidden validation at `485cfee3ed95` (same production code): 58 tests + 44 subtests passed, with CUDA device count verified as zero.
- Changed-file pinned pre-commit hooks passed. Current-head lint and Rust workspace CI passed. NVIDIA Base is blocked by an unrelated [DeepSeek-V4 test-fixture failure](https://github.com/sgl-project/sglang/actions/runs/39094516913/job/117582869201): main #44920 added a `token_to_kv_pool` access, but the test constructs the backend without that attribute. Both affected files are identical between the tested CI merge `5423749ec971` and its main parent `a0b77db84d9e`; this is not a multimodal identity regression. Remaining CI jobs have not been cancelled, and the full Base cycle has not passed.

Full-weight Kimi serving, two-node PD/EPD, and end-to-end accuracy/performance benchmarks have **not** been run. Qwen serving and item-construction tests do not establish all-model or multi-node deployment compatibility. No serving speedup is claimed.
