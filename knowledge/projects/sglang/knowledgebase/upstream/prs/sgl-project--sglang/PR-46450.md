# [Perf] unified_cache: Drain completed offloads in a single slice in UnifiedCacheLinkerWrapper

[Upstream PR](https://github.com/sgl-project/sglang/pull/46450) · state: open · merged: False

## Original PR description

## Motivation
In `UnifiedCacheLinkerWrapper.commit_completed_offloads()` (`python/sglang/srt/mem_cache/unified_cache/unified_cache_linker.py`), completed pending offload records are drained FIFO from the head of `self.pending_offloads: list[_PendingOffload]`. Previously, this used `self.pending_offloads.pop(0)` inside a `for _ in range(n):` loop, shifting the remaining list elements left $n$ separate times ($O(n \cdot L)$ list shifts per batch commit). Additionally, `replace_pending_offload_node()` reassigned `pending.publish_node_ids = [...]` instead of mutating the list in place.

## Modifications
1. Slice the completed prefix once (`completed = self.pending_offloads[:n]`) and delete it in a single bulk operation (`del self.pending_offloads[:n]`) before iterating over `completed` to mark `external_cache_stored = True` and decrement lock refs.
2. Update `pending.publish_node_ids[:] = [...]` in place in `replace_pending_offload_node()`.

## Accuracy & Unit Tests
- Added `test_commit_completed_offloads_batch_fifo_slice` in `test/registered/unit/mem_cache/test_unified_cache_linker.py` verifying partial FIFO prefix draining, lock reference release, and in-place node replacement.
- `pytest test/registered/unit/mem_cache/test_unified_cache_linker.py`: passed.
