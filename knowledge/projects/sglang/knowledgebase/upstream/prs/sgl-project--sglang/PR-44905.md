# [Perf] [XPU] activation: Add native-BF16 GELU lookup

[Upstream PR](https://github.com/sgl-project/sglang/pull/44905) · state: open · merged: False

## Original PR description

Add `sglang.kernels.ops.activation.bf16_gelu_tanh_mul_lut`, an inference-only Triton XPU operator for BF16 `[gate, up]` matrices. It indexes a caller-owned 65,536-entry BF16 table by the gate's raw bits, then multiplies the looked-up native GELU result by `up` with FP32 opmath and BF16 output rounding. This retains the native BF16 activation intermediate and leaves GEMMs and model weights unchanged.

The namespace entry is lazy, and the wrapper supports fullgraph compilation and XPU graph replay. Guards enforce contiguous BF16 inputs/table on one XPU, inference-only use, the table size, and the 32-bit addressing limit; empty outputs are supported. The caller owns table construction and lifetime. A following Gemma4 integration supplies a table populated through the existing native activation.

Stacked on #44890 (`797dbef49803cd37f4da51383b0e9188e427f439`). This GELU value table is separate from that PR's softcap comparison-rank table.

Validation on Arc Pro B70 with Torch 2.13.0+xpu:

- Three registered GPU tests pass: fullgraph and changed-input/poisoned captured replay at offsets 0/1/32; exhaustive 65,536 BF16 gate patterns with finite/nonfinite up values; and an allocation-free addressing-bound check. Finite values, signed zeros, and infinities match the native activation exactly; NaNs match by classification.
- Two independent trained-projection microbenchmarks at M4096 show 17.97–18.04% lower activation latency for I12288 and 18.63–18.79% for I6144 versus the native activation. Physical projection banks are 805 MB / 402 MB, and retained-output poisoning and changed-input replay are checked. These are activation-only results.
- The following model integration has separately passed nine GPU tests and a serving dispatch/profile check; those changes and serving claims are outside this three-file PR. Its model integration is published as draft #44908 and is not ready to land: a paired 200-question long-context check scored 168/200 for control and 160/200 for candidate (zero request errors; 10 control-only and two candidate-only correct). A subsequent diagnostic compared lookup and the saved standard native activation on identical serving tensors for all 35 layers across the same 200 questions: 6,300 comparisons / 249,141,657,600 elements, with zero bit or NaN-class mismatches. The full serialized pair verified matching prefill batch shapes and scored 164/200 versus 163/200, with 101/200 identical generations. The two servers used different uncontrolled global seeds despite request seed 42; greedy source paths do not show an active RNG consumer, so this is a disclosed protocol difference, not an established cause. A bounded unchanged-baseline repeat with both global and request seeds fixed at 42 changed two of four completions within the same server (eight requests total). This establishes baseline variation under that protocol; the feature's quality effect remains unresolved. The model integration remains a draft. No model-quality claim is made for this kernel PR.
