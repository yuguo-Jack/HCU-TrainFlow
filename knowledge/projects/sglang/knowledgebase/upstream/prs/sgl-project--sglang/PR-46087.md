# [Perf] mem_cache: Avoid O(R) list shifts and free_pages scans in RangePageAllocator

[Upstream PR](https://github.com/sgl-project/sglang/pull/46087) · state: open · merged: False

## Original PR description

## Motivation

In `RangePageAllocator` (`python/sglang/srt/mem_cache/embedding_cache_controller.py`, introduced in #19388):

1. `free_pages` recomputes `sum(length for _, length in self.free_ranges)` in $O(R)$ on every `allocate()` call and on every iteration of `EmbeddingCacheController._evict_for_pool` (`while pool.allocator.free_pages < required_pages:`).
2. When no single contiguous run satisfies `required_pages`, the scatter fallback loop calls `self.free_ranges.pop(0)` on every consumed range ($O(R)$ list shift per range, $O(K \cdot R)$ total) and `self.free_ranges.insert(0, ...)` on a partial range ($O(R)$ list shift).

## Modifications

- Track `self._free_pages` across `__init__`, `allocate`, and `free` so `RangePageAllocator.free_pages` is $O(1)$.
- Walk `self.free_ranges` by index during scatter allocation, update any partially consumed trailing range in place, and delete the consumed prefix once via `del self.free_ranges[:consumed]`.
- Add unit test `test_scatter_fallback_partial_last_run_and_free_pages` in `test/registered/unit/mem_cache/test_embedding_cache_controller.py`.

### Micro-benchmark ($R = 8,000$ fragmented free ranges)
- `free_pages` (1,000 queries): `337.39 ms -> 0.125 ms` (**2,706x faster**)
- Scatter `allocate` (10 allocations of 500 pages): `16.04 ms -> 6.84 ms` (**2.3x faster**)
