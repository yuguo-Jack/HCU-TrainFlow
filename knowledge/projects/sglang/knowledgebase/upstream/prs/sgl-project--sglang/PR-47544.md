# [Refactor] disaggregation: Commit the PD handoff token through the shared per-token commit

[Upstream PR](https://github.com/sgl-project/sglang/pull/47544) · state: closed · merged: True

## Original PR description

The decode worker committed the PD handoff token (the token the prefill worker samples) with its own copy of the per-token bookkeeping, separate from the prefill and decode result paths; it has missed a field before (the reasoning count in #32897, the sampling mask in #41235).

- `SchedulerLogprobResultProcessor.append_output_token_logprobs` appends one output token's logprob, top-k and token-ids rows; the conditions on `top_logprobs_num` and `token_ids_logprob` live only there. `add_logprob_return_values` (prefill), `_apply_decode_logprobs` (each accepted decode token) and the handoff call it.
- `SchedulerBatchResultProcessor.commit_handoff_token` appends the token to `output_ids`, updates the reasoning count, and appends its logprob and sampling-mask rows. `DecodeTransferQueue._commit_transfer_to_req` reads the metadata buffer and calls it; PD-only state (cached tokens, multimodal token counts, speculative seeds) stays there, and a rebootstrap still commits nothing.

Behavior change: without a top-k request the handoff no longer appends an empty top-k row, as the prefill and decode paths never did. The Python tokenizer manager ignored that row; the Rust server streamed it as `output_top_logprobs: [null]` in the first chunk.

Also updates `test_srt_endpoint` to expect the 400 that #47521 returns for out-of-vocab ids in `/detokenize`.
