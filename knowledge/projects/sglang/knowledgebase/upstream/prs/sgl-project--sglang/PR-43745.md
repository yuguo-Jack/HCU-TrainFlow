# [Diffusion] MiniMax H3: allow the AdaLN cache with a quantized DiT

[Upstream PR](https://github.com/sgl-project/sglang/pull/43745) · state: open · merged: False

## Original PR description

## Motivation

`--minimax-h3-adaln-cache-path` replaces H3's AdaLN projections with precomputed BF16 outputs. In cache mode the blocks and the final layer build no `adaln_proj` at all. Even so, `MiniMaxH3DiTModel.__init__` raises `MiniMax H3 AdaLN cache is only compatible with unquantized weights` whenever a `quant_config` is present. That blocks the combination that needs the cache most: an INT8 ConvRot DiT. This covers both a serialized Comfy-marker INT8 file and `--quantization convrot_int8`.

The quantization of the other linears has no effect on the sidecar. The only path that does depend on quantization is the online rebuild (`--minimax-h3-adaln-online`), which streams `adaln_proj` from the checkpoint shards.

A second, smaller issue sits in the loader. In cache or online mode it replaced the Comfy marker key filter (`comfy_quant_key_filter`) with the AdaLN one. A marker checkpoint therefore logged all of its `.comfy_quant` tensors as "Checkpoint keys not loaded (no matching model parameter)". On an H3 INT8 file that is 200 keys. Generation is unaffected, but the warning reads like a checkpoint/architecture mismatch.

## Modifications

- `minimax_h3.py`: the check moves into `_validate_adaln_precompute_config(quantized=..., online=...)`.
  - Online rebuild + quantized weights is still rejected, now with an error that names `--minimax-h3-adaln-online`.
  - Sidecar + quantized linears is accepted.
- `transformer_loader.py`: `_select_checkpoint_key_filter(uses_comfy_layer_markers=..., drops_adaln_proj=...)` picks the filter once, after both AdaLN branches. With markers and an AdaLN source it combines both filters, instead of the AdaLN branch overwriting the marker filter.
- Docs: the `--minimax-h3-adaln-cache-path` help text, `api/cli.mdx` and the H3 cookbook's AdaLN cache section now say that the other linears may be quantized. The online rebuild text is unchanged. The GGUF guard in `transformer_load_utils.py` is unchanged too, because the GGUF loader does not go through this key filter.
- Tests (`test_minimax_h3_adaln_cache.py`):
  - `test_sidecar_pairs_with_quantized_linears_but_online_rebuild_does_not`
  - `test_comfy_marker_filter_survives_adaln_precompute`
  - Both fail on `main` and pass on this branch.

## Accuracy Tests

`python/sglang/multimodal_gen/test/unit/test_minimax_h3_adaln_cache.py`: 24 passed on an RTX PRO 6000 (SM120). That is 22 existing cases plus the 2 new ones.

End to end on one RTX PRO 6000:
- Setup: FL2VA, t2va, 4 s, 16:9, 768p, 50 steps, seed 7, flow shift 12 / audio 3, exact attention.
- The sidecar was built with this branch's `build_minimax_h3_adaln_cache`.
- These runs used the `python/sglang` tree of this branch, and of `main` for the first row, on top of the v0.5.21 image's dependencies. INT8 layers ran on SGLang's JIT ConvRot ops: `jit 200` / `jit 209`, `comfy_kitchen 0`.

- **Identical output:** the last two rows produce byte-identical MP4s (md5 `c6627952...`). `convrot_int8` leaves the 51 AdaLN linears in BF16, and the sidecar reproduces their outputs exactly.
- **Memory:** peak memory falls by 24.2 GB (58.0 -> 33.8 GB), which puts an INT8 H3 within a 48 GB card. Generation time is unchanged.
- **Serialized file:** a GPTQ-calibrated INT8 ConvRot export of the FL2VA DiT in Comfy marker format, covering the 200 block linears. It stores no `adaln_proj`, so it only runs in cache mode.

## Speed Tests and Profiling

No kernel or scheduling change. The table above shows the cache leaves generation time unchanged, within 0.5 s of the resident path; the gain is the 24.2 GB of AdaLN weights that no longer have to be resident.
