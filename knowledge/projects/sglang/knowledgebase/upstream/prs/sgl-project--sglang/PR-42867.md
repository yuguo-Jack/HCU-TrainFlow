# [Perf] lm-head: Add an opt-in batch-invariant BF16 GEMM for decode-sized batches

[Upstream PR](https://github.com/sgl-project/sglang/pull/42867) · state: open · merged: False

## Original PR description

## Motivation

At decode and speculative-verify batch sizes, an unquantized BF16 LM head is a bandwidth-bound GEMM: the whole vocab shard is read for a handful of rows. cuBLAS can pick a different kernel as the row count changes, so a row's logits can depend on how many other rows share the batch.

## Modifications

- New `sglang/kernels/ops/gemm/bf16_skinny_gemm.py`: a Triton kernel for `x[M, K] @ weight[N, K].T` with 1 <= M <= 16, BF16 inputs, K % 128 == 0, unit stride along K and arbitrary row strides, both tensors on the same CUDA GPU. ROCm builds are not accepted, as the kernel has not been validated there.
  - Each CTA streams 64 weight rows over all of K, with no split-K.
  - A row's tiling and FP32 accumulation order depend only on (N, K), so its result is the same alone or in any batch of up to 16.
  - Row offsets are 64-bit, so a weight whose rows start beyond 2^31 elements (a large head, or a large row stride) is addressed correctly.
  - The launch runs under `torch.cuda.device(x.device)`, so operands on a GPU other than the current one run on that GPU's current stream.
- The kernel is registered in the `gemm` kernel inventory (`gemm.bf16_skinny_gemm`, CUDA only). Unsupported operands raise `ValueError`.
- `bf16_lm_head_matmul()` in `logits_processor.py` uses the kernel when `SGLANG_ENABLE_BF16_SKINNY_LM_HEAD=1` (default off) and the inputs qualify. Otherwise it uses the existing `torch.matmul`.
  - It serves the unquantized BF16 LM head in `LogitsProcessor._compute_lm_head` (outside the AMX, FP32 and RL on-policy branches) and `project_through_lm_head` (the DSpark draft logits).

## Accuracy Tests

`test/registered/kernels/ops/gemm/test_bf16_skinny_gemm.py` (CUDA, registered in the `base-b-kernel-unit` stage on the 1-gpu-small runner):
- **Error bound.** Every output is within the error bound of an FP32-accumulated dot product rounded once to BF16, measured against FP64: `gamma_K * (|x| @ |w|.T)` plus one BF16 ulp. Tested at M = 1, 6 and 16 on the TP4 DeepSeek-V4.1 shard (32320 x 4096) and on a 1000 x 256 shape.
- **Batch invariance.** Every row is bit-identical (compared as int16) alone and in batches of 2..16.
- **CUDA graphs.** A captured call replays on new activations with the eager result.
- **Strided rows.** Operands with padded row strides give the same bits as compact ones.
- **64-bit row offsets.** A strided weight whose last row starts past 2^31 elements gives the same bits as a compact copy. The test needs about 5 GiB of free GPU memory and is skipped otherwise.
- **Non-current device** (`test_bf16_skinny_gemm_multi_gpu.py`, registered on the 2-GPU runner). Operands on `cuda:1` called while `cuda:0` is current (and busy) give a result on `cuda:1` within the error bound.
- **Unsupported inputs are rejected:** more than 16 rows, FP16, K % 128 != 0, strided columns of either operand, a weight on the CPU, and a ROCm build. The kernel raises `ValueError` on them.

`test/registered/unit/layers/test_logits_processor_bf16_lm_head.py` (CPU, `base-a-test-cpu`): both production callers (the default branch of `LogitsProcessor._compute_lm_head`, and `project_through_lm_head`) and `bf16_lm_head_matmul` call the kernel, with the hidden states cast to BF16, only when the flag is set and `bf16_skinny_supported` accepts the operands; otherwise they return `torch.matmul`'s result. The kernel and the predicate are stubbed; a separate case checks that the real predicate rejects CPU operands. `test/registered/unit/kernels/test_kernels_namespace.py` checks the registration's target and that it is CUDA only.

On 4x RTX PRO 6000 Blackwell (torch 2.14.1+cu130, Triton 3.8.0), `test_bf16_skinny_gemm.py`, `test_bf16_skinny_gemm_multi_gpu.py` and the CPU dispatch test pass with no skips (10 tests, 53 subtests).

```python
"""Per-call time of the BF16 skinny LM-head GEMM against cuBLAS (x @ w.T).

Each call is captured 20 times in one CUDA graph; the graph is warmed once and replayed
10 times; the reported value is the mean time per call. Shape: the DeepSeek-V4.1-Flash
LM head shard at TP4 (N=32320, K=4096), BF16.

usage: python bench_bf16_skinny_lm_head.py   (with the change on PYTHONPATH)
"""

import torch
import triton

from sglang.kernels.ops.gemm.bf16_skinny_gemm import bf16_skinny_gemm

CALLS, REPLAYS = 20, 10


def per_call_us(fn):
    stream = torch.cuda.Stream()
    stream.wait_stream(torch.cuda.current_stream())
    with torch.cuda.stream(stream):
        fn()
    torch.cuda.current_stream().wait_stream(stream)
    graph = torch.cuda.CUDAGraph()
    with torch.cuda.graph(graph):
        for _ in range(CALLS):
            fn()
    graph.replay()
    torch.cuda.synchronize()
    start, end = torch.cuda.Event(enable_timing=True), torch.cuda.Event(enable_timing=True)
    start.record()
    for _ in range(REPLAYS):
        graph.replay()
    end.record()
    torch.cuda.synchronize()
    return start.elapsed_time(end) / (CALLS * REPLAYS) * 1000


def main():
    n, k = 32320, 4096
    print(f"{torch.cuda.get_device_name()}, torch {torch.__version__}, triton {triton.__version__}")
    w = (torch.randn(n, k, device="cuda") / k**0.5).bfloat16()
    for m in (1, 2, 4, 6, 8, 12, 16):
        x = torch.randn(m, k, device="cuda").bfloat16()
        cublas = per_call_us(lambda: x @ w.T)
        skinny = per_call_us(lambda: bf16_skinny_gemm(x, w))
        print(f"M={m:2d}: cuBLAS {cublas:6.1f} us, skinny {skinny:6.1f} us")


if __name__ == "__main__":
    main()
```
