# [Fix] deepseek-v4.1: Fix bounded replay with CP and DSpark

[Upstream PR](https://github.com/sgl-project/sglang/pull/47406) · state: open · merged: False

## Original PR description

## Motivation

Enabling `--enable-decoder-swa-bounded-replay` with context parallelism (CP) and DSpark could fail during prefill output gathering.

Bounded replay keeps only the required SWA tail in the late decoder layers. With DSpark auxiliary hidden-state capture, the model returns compact tail outputs instead of restoring the full prefill chunk.

However, `EagerRunner._execute_extend_cp` bypassed the model's tail-aware output postprocessing and gathered these compact outputs using the original full-chunk CP metadata. The gather therefore expected more local rows than the model actually returned.

For example, with a 16,384-token chunk, CP4, and a 128-token tail, each rank returns 32 tail rows, while the original metadata expects 4,096 rows:

```text
Interleave CP gather received an unexpected local token count:
got=32, expected_at_least=4096, total=16384, cp_size=4
```
<img width="2110" height="1042" alt="image" src="https://github.com/user-attachments/assets/4862119a-dabc-4a86-b445-d47d453db444" />

CP configurations previously disabled bounded replay by default, but explicitly enabling it could still reach this incompatible path.

## Modifications

- Add an optional model-specific `postprocess_cp_output` hook to the eager CP runner, allowing DeepSeek V4/V4.1 to handle compact outputs before generic CP gathering.
- Preserve the original global token indices in `LateLayerTail`, alongside rank-local indices.
- Gather compact hidden states and DSpark auxiliary states with the tail-specific CP metadata. Restore the original forward-batch metadata in a `finally` block.
- Share tail-aware output postprocessing between the regular model forward path and the eager CP path. Preserve input-token alignment, logits metadata, and the global token indices used by DSpark.
- Reject explicitly enabled bounded replay with CP plus prefill CUDA graphs, which remains unsupported.

This enables explicit bounded replay for eager CP prefill without changing the default CP policy or the quantization algorithms.

## Accuracy Tests

Validation used the original `DeepSeek-V4.1-Flash` checkpoint in the `abing-v4` environment.

- CPU regression suite: 38 tests passed, including 34 subtests.
- Four-rank NCCL validation: six cases per rank passed, covering long chunks, cached prefixes, mixed request lengths, padding, and zero-length entries. Checks verified hidden states, auxiliary states, global token mappings, and metadata restoration.
- Full-model disaggregated serving on 8 H200 GPUs:
  - Prefill: TP4 / CP4, interleave strategy, eager execution, bounded replay enabled.
  - Decode: TP4 / DP4 with DSpark.
  - All nine functional requests passed, including chunked prefill, prefix reuse, mixed lengths, and prompt logprobs.
  - Prefix reuse was observed: 49,152 cached tokens out of 65,541 prompt tokens.
- GSM8K smoke evaluation: 32/32 correct, with zero errors and zero truncated outputs.
