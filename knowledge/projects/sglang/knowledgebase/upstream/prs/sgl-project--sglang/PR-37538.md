# [Feat] memory: Report which prefill phases consume GPU memory before an OOM

[Upstream PR](https://github.com/sgl-project/sglang/pull/37538) · state: open · merged: False

## Original PR description

## Motivation

The allocation that fails during an image or long-prompt prefill may follow the operation that consumed the available memory. Whole-forward peaks do not identify that phase.

## Modifications

Add opt-in `SGLANG_EXTEND_MEM_PROFILE=1` counters around multimodal embedding, KDA, KV writes, sparse attention and indexing, with whole-extend peaks and immediate large-delta logging. This PR includes #37169's allocator-history recorder, including its handling of the CUDA graph capture profiler, and will be rebased to remove that dependency after it merges.

Record only qualifying eager EXTEND batches with at least 1,024 real tokens, counted from the pre-padding token count or `global_num_token_non_padded_cpu`. Disabled entry points make no CUDA calls. Diagnostic failures preserve the original exception. Counters cover PyTorch allocator memory; phase deltas are not additive, and profiling assumes serialized forwards on the current device. This diagnoses memory growth; it does not reduce allocations.

## Accuracy Tests

45 CPU tests passed, covering accounting, disabled behavior, snapshot requests, exception cleanup and call-site placement. The eager gate tests build real `ForwardBatch` objects, including an unpadded single-rank EXTEND. GPU profiling hooks have not been tested.

## Speed Tests and Profiling

Disabled by default. Profiling overhead was not measured.
