# [CI] [Intel] disaggregation: Run XPU P/D nightly on Mooncake and NIXL

[Upstream PR](https://github.com/sgl-project/sglang/pull/45377) · state: closed · merged: True

## Original PR description

[CI] [Intel] disaggregation: Run XPU P/D nightly on Mooncake and NIXL

## Dependencies

- **#43299**, "[Fix] disaggregation: Fix the early-send wait event on non-CUDA devices and in nixl". Merge it first.
  - Without it, `maybe_send_cached_prefix_chunk` in `disaggregation/prefill.py` calls `torch.cuda.Event()` on XPU and kills the prefill scheduler. That function sends a request's cached prefix early, and with overlap scheduling (the default) it also runs on the later chunks of a chunked prefill.
  - This PR's `test_long_prompt_multi_page_transfer` prefills in 256-token chunks, so it takes that path even with no prefix shared between requests. Until #43299 merges, that test kills prefill and the fixture aborts the rest of the file.
  - `test/registered/xpu/test_disaggregation_staging_xpu.py` also takes that path (its concurrent case reuses a cached prefix). It now runs in the 4-GPU nightly, because this image installs Mooncake; this PR leaves it on TCP.

## Motivation

XPU P/D disaggregation landed on NIXL (#24188), but the XPU CI image does not install NIXL, so its registered test could not run, and Mooncake has no XPU support in its PyPI wheel. This PR builds both transfer backends into `docker/xpu.Dockerfile` and runs the registered XPU P/D test on both nightly.

Mooncake is pinned to a commit with kvcache-ai/Mooncake#4379, which adds intra-node XPU peer-to-peer copies, so both backends copy KV card to card through Level Zero IPC. 

## Modifications

**`docker/xpu.Dockerfile`**
- Builds the Mooncake transfer engine from a pinned upstream commit (`c67a88f3`) with icpx (`-DUSE_XPU=ON -DUSE_TENT=ON -DWITH_STORE=OFF`; the store does not build with icpx at that commit).
  - The pin includes kvcache-ai/Mooncake#4379 (merge commit `db4f146e`). On one node, TENT's XPU transport copies KV card to card through Level Zero IPC, so no RDMA NIC is needed.
- Also installs a pinned `sglang-router` (0.3.2), which the P/D tests launch between prefill and decode.
- Rewrites `libboost-all-dev` to `libboost-dev` in Mooncake's `dependencies.sh` before running it. Mooncake uses Boost headers only, and `libboost-all-dev` pulls OpenMPI, libfabric and a second UCX (Ubuntu's 1.16) into the image.
  - The script itself makes the same swap on SHCA hosts.
  - A grep anchored to the package entry fails the build if a `MOONCAKE_COMMIT` bump renames or drops it.
  - The rest of the script still runs, so Go, the submodules and the other dependencies (including `libcli11-dev`, new at this pin) follow upstream once the Mooncake store and P2P store are enabled. Go is removed after the build, along with its `PATH` line in `.bashrc`.
- Builds Mooncake with Ninja as `Release`, with `-DENABLE_DEBUG_SYMBOLS=OFF -DBUILD_BENCHMARK=OFF`.
  - Its CMake defaults build the transfer-engine benchmark and use `RelWithDebInfo` plus `-g`, and the nightly image is always built with `--no-cache`.
  - With these, the Mooncake step takes 109 s in a `--no-cache` build.
- Builds UCX from a pinned master commit (`d76cd54b`, `--with-ze --with-mlx5 --enable-mt --enable-optimizations --disable-static`) into its own prefix, `/opt/ucx`.
  - It is a master commit because ZE IPC for Intel GPUs (openucx/ucx#11218) is in no UCX release yet. Move to the first release tag that contains it.
  - On x86, `--enable-optimizations` adds only `-mavx` on top of UCX's default `-O3`, so the image still runs on any AVX-capable host.
  - Nothing registers UCX system-wide. NIXL's UCX plugin finds it through its RUNPATH (`-Ducx_path`), so other UCX users in the image are not affected.
- Builds a static Abseil 20250814.1 into `/opt/abseil`. Mooncake's `dependencies.sh` pulls in Ubuntu's `libabsl-dev` 20220623, which is too old for NIXL (`VLOG` not declared), so the new Abseil goes first on `PKG_CONFIG_PATH`.
- Builds NIXL from a pinned commit (`466ebb1`) with NIXL's documented source install: the `nixl-cu12` package, the C++ libraries and plugins, then the `nixl` meta package.
  - `nixl-cu12` keeps a RUNPATH to the meson prefix, so pip and meson share `--prefix=/opt/nixl`.
  - No `PYTHONPATH`, `LD_LIBRARY_PATH` or `NIXL_PLUGIN_DIR` is needed at runtime.
  - The pin includes ai-dynamo/nixl#1536. Its UCX plugin passes the VRAM memory type to UCX at registration, so UCX does not classify XPU memory as host memory, and no `UCX_MEMTYPE_CACHE=n` override is needed. Before ai-dynamo/nixl#1536, registering the KV cache failed at startup with `NIXL_ERR_BACKEND` unless the cache was turned off.
- After the NIXL build, removes only the build tools the venv did not already have. Packages sglang depends on (`ninja`, `pyyaml`) stay.

**`test/registered/disaggregation/test_disaggregation_xpu.py`**
- Runs Mooncake and NIXL on `nightly-xpu-kernel-main-2-gpu` through a shared mixin. The manual NIXL test (`test/manual/kv_transfer/test_disaggregation_nixl_xpu.py`) is folded in here.
- Mooncake sets only `MC_USE_TENT=1`. With `MOONCAKE_PROTOCOL` at its default, TENT copies KV card to card through Level Zero IPC. NIXL needs no environment variables.
- Both servers see both cards: the fixture gives them the same `ZE_AFFINITY_MASK` and puts decode on `--base-gpu-id 1`. TENT needs that to copy card to card; with one card per server it logs `... is on a device not visible here ... using another route`.
- Both servers use `--attention-backend intel_xpu`, the documented XPU attention backend, which has page size 128. Prefill uses `--chunked-prefill-size 256`.
- A new long-prompt test sends a ~1k-token greedy prompt that must recall a code from its first KV page. The prompt spans about 8 pages and 4 prefill chunks, so a dropped or misplaced page changes the answer.
- The Mooncake class checks that KV really goes card to card (separate commit). When TENT cannot map the peer's KV buffer, for example in a container without `--cap-add SYS_PTRACE`, it logs `using another route` and the request still succeeds. The class sets `capture_per_side_logs = True`, and `test_kv_copied_card_to_card` sends a request and asserts the prefill log has `XpuTransport: mapped peer buffer` and no `using another route`.
- Failing instead of skipping:
  - Each class names its backend module (`mooncake.engine`, `nixl._api`), and the mixin imports it first, so a class fails rather than skips when its backend is missing. The nightly therefore also checks that the image carries both builds.
  - In CI, the classes fail rather than skip when fewer than two XPUs are visible, so a runner with a missing card does not leave the nightly green. Outside CI they still skip.
- The shared mixin sets the fixture's new `use_rdma = False` (see below). Otherwise, in CI (`SGLANG_IS_IN_CI=true`) the fixture gives both servers its CUDA-runner default NICs (`mlx5_roce*`). The XPU runners have no RDMA NIC, so Mooncake refuses to start (`No IB devices found in /sys/class/infiniband`).
- Decode keeps the default `host_pool` retraction backup, now that #32503 enables HiCache L1<->L2 transfer on XPU. No `--disaggregation-decode-retraction-backup` override is needed.

**`python/sglang/test/server_fixtures/disaggregation_fixture.py`**
- Adds a `use_rdma` class flag to `PDDisaggregationServerBase`, default `True`, so existing tests are unchanged.
- With `use_rdma = False`, CI mode still defaults to Mooncake but skips the RDMA NIC lookup. It also skips `--disaggregation-ib-device` and the `MC_GID_INDEX` and `UCX_NET_DEVICES` exports, and `rdma_devices_for()` returns no devices.
- `get_rdma_devices_args()` counts cards with `get_gpu_count()` (`torch.accelerator`) instead of `torch.cuda.device_count()`.
  - Off CUDA the old count was 0, so the fixture assumed 8 cards and could map cards to the wrong NIC. For example, with 4 XPU cards and 2 NICs, every card mapped to the first NIC.
  - On CUDA the count is unchanged.

**`scripts/ci/xpu/xpu_ci_start_container.sh`**
- Starts the CI container with `--cap-add SYS_PTRACE`, which XPU P/D needs to copy KV card to card on both backends.
  - **Why:** to share a KV buffer, a process exports a Level Zero IPC handle. On Linux that handle is a dma-buf file descriptor, valid only inside the owning process.
    - The peer copies the fd into itself with `pidfd_open()` and `pidfd_getfd()`. NIXL does this in UCX's ze_ipc transport (`uct_ze_ipc_dup_fd_from_pid`), and Mooncake in TENT's XPU transport.
    - The kernel gives `pidfd_getfd()` the same access check as ptrace, and Docker's default seccomp profile only allows it when the container has `CAP_SYS_PTRACE`.
  - **Without it:**
    - NIXL transfers fail with `pidfd_getfd(...) failed: Operation not permitted` and then `NIXL_ERR_BACKEND`.
    - Mooncake logs `cannot map peer buffer ... needs ptrace access ... [Operation not permitted]; using another route`. Requests still succeed, but KV no longer goes card to card.
  - **Why this option:** `SYS_PTRACE` is the narrowest built-in Docker option that works. `--privileged`, which the XPU docs' `docker run` example already uses, grants far more. The capability only lets processes inside the container trace each other; it gives no access to the host.

**`.github/workflows/pr-test-xpu.yml`**
- Drops `test_disaggregation_xpu.py` from the PR-CI path filter, since the test now runs only in the nightly.

**`python/sglang/srt/arg_groups/validation_hook.py`**
- `check_server_args` now rejects `SGLANG_MOONCAKE_CUSTOM_MEM_POOL` at startup on `--device xpu` when the variable enables a pool (`NVLINK`, `BAREX`, `INTRA_NODE_NVLINK`). Those pools use CUDA allocators, which XPU lacks.
- Values that leave the pool off are accepted. CUDA, ROCm, MUSA and Ascend NPU keep their existing behaviour.
- `test_server_args.py` covers the rejection on XPU, and checks that CUDA, NPU and a disabling value on XPU are still accepted.

**Docs**
- The XPU page's P/D section adds a Mooncake subsection and adds Mooncake and NIXL nightly rows to the tested table. The subsection covers:
  - the build or Docker image, and `MC_USE_TENT=1`, with KV copied card to card through Level Zero IPC;
  - that both servers must see both cards, with a prefill/decode example that gives both `ZE_AFFINITY_MASK=0,1` and puts decode on `--base-gpu-id 1`;
  - that containers need `--cap-add SYS_PTRACE` (or `--privileged`) for the card-to-card path, and what TENT logs without it.
- NIXL subsection:
  - It now requires a UCX built with Level Zero, because the PyPI `nixl` wheel bundles a UCX without the ze transport.
  - It says containers need `--cap-add SYS_PTRACE` (or `--privileged`), and why.
  - Its launch commands no longer set `UCX_POSIX_USE_PROC_LINK=n`, matching the nightly. The note now gives that variable as the fix when UCX's shared-memory transport cannot open a peer's `/proc/<pid>/fd/<fd>`.
- `pd_disaggregation.mdx` adds XPU notes for Mooncake and NIXL, and notes that `SGLANG_MOONCAKE_CUSTOM_MEM_POOL` is CUDA-only.

On CUDA and ROCm, every change resolves to the same `torch.cuda` calls as before.

UCX_POSIX_USE_PROC_LINK=n isn't XPU-specific: by default UCX's posix shared-memory transport attaches the peer's segment through /proc/<pid>/fd/<fd>, which needs ptrace-level access, and =n opens it by its /dev/shm path instead. The container setup in this PR grants SYS_PTRACE (needed for ze_ipc), so the default path works, which is why the nightly doesn't need it. I aligned the docs to the nightly: the launch commands no longer set it, and it's documented as a fix if shared-memory attach fails.
