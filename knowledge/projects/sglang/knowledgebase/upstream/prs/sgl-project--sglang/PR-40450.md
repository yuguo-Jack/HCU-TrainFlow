# [Doc] [NPU] cookbook: add A3 deployment scenarios to Kimi-K2.6

[Upstream PR](https://github.com/sgl-project/sglang/pull/40450) · state: open · merged: False

## Original PR description

## Motivation

Refs Ascend/sglang#1213.

The Kimi-K2.6 cookbook had no Ascend NPU option, although the Ascend NPU documentation ships verified Kimi-K2.6 best-practice recipes for both a single-node PD co-located shape and a two-node PD disaggregated shape. This PR adds both to the cookbook as a new "3.3 Ascend NPU Deployment" section, so users can obtain the correct command for each scenario without translating a platform-specific tutorial by hand.

## Modifications

- `docs/cookbook/autoregressive/Moonshotai/Kimi-K2.6.mdx` (+317 lines): a new **3.3 Ascend NPU Deployment** section with two scenario Tabs:
  - **1×A3 · PD Co-located (Low Latency)** — W4A8 + EAGLE3, TP16, reference TPOT ≈ 20 ms
  - **2×A3 · PD Disaggregated (High Throughput)** — prefill / decode / router commands split per node role, reference TPOT ≈ 100 ms
  - Per-scenario **measured accuracy and speed tables** (GSM8K, TPOT, TTFT, throughput, EAGLE3 acceptance)
  - Shared env block, launch commands, an inference-check curl, and a `bench_serving` command per scenario
  - A Warning documenting a device-OOM condition under burst load on self-built venvs (with the `--mem-fraction-static` mitigation), and a Note on the `ascend` transfer backend / `memfabric_hybrid` / driver-version setup
  - Cross-links to the Ascend tutorial, best-practices, and accuracy-evaluation pages
- Commands are transcribed from the verified best-practice recipes; deprecated flags are replaced with their current `main` spellings (`--cuda-graph-backend-{decode,prefill}=disabled`, `--cuda-graph-bs-decode`).

## Accuracy Tests

Verified on real Atlas 800I A3 hardware (16 dies/node, CANN 9.0.1, driver 26.1.1, SGLang Ascend fork @ fdebc93 with the ascend transfer-engine session-port fix).

| Scenario | Accuracy (EvalScope, GSM8K, limit 100) | Inference spot-checks |
| --- | --- | --- |
| 1×A3 PD co-located | 98% | 5/5 correct |
| 2×A3 PD disaggregated | 99% | 5/5 correct |

## Speed Tests and Profiling

`sglang.bench_serving`, random dataset, seed 1, via the router (port 6688).

**1×A3 PD co-located** (3.5k input / 1.5k output, max-concurrency 64, 256 prompts):

| Metric | Result | Reference |
| --- | --- | --- |
| Median time per output token | 21.5 ms | ≈ 20 ms |
| Mean time per output token | 26.55 ms | — |
| Output throughput | 1491 tok/s (peak 2745) | — |
| EAGLE3 acceptance length | 4.25 | — |

The median ITL is within ~7% of the 20 ms reference; the mean is pulled up by tail latency under a 64-way concurrent burst (P99 ITL 228 ms). Lowering `--mem-fraction-static` to 0.85 (from the 0.865 reference) was required on the self-built venv to avoid device OOM under that burst; the reference container image should run at the documented value.

**2×A3 PD disaggregated** (64k input / 1.5k output, max-concurrency 1, 1 prompt):

| Metric | Result | Reference |
| --- | --- | --- |
| Time per output token | 35.77 ms | ≈ 100 ms |
| Mean time to first token | 8318 ms (64k prefill) | — |

This is a single-request long-context latency run (the 100 ms reference is a TPOT target, not a throughput target), so no throughput row is reported.
