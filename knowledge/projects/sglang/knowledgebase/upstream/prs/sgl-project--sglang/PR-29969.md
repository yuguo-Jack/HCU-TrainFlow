# fix(nixl): prevent read-during-write via atomic temp file rename

## Motivation

<!-- Describe the purpose and goals of this pull request. -->
The NIXL backend writes KV cache pages directly to the final file path. A concurrent `batch_get_v1` (READ) or `batch_exists` query can observe a partially-written file. The `batch_exists` returns a false positive because the file exists on disk before the transfer completes, and a READ against it returns incomplete/corrupt data. This is a read-during-write race with no backend-level guard today.

## Modifications

<!-- Detail the changes made in this pull request. -->
- **`hicache_nixl.py` `_batch_xfer`**: for WRITE, transfer to `<path>.tmp` and `os.rename` to the final path only after the transfer succeeds. On failure, remove the temp file. READ path is unchanged. It only sees the final path, which either exists (fully written) or doesn't.
- **`nixl_utils.py` `NixlFileManager`**: add `get_temp_file_path`, `finalize_temp_file` (atomic `os.rename` + cleanup on failure), and `remove_file` (best-effort, swallows `FileNotFoundError`, logs other `OSError` as warnings).

No locks are needed. The `os.rename` provides POSIX atomicity. Stale temp files from a crash are never read by READ/`batch_exists` (they only look at final paths) and are cleaned on `clear()`.
