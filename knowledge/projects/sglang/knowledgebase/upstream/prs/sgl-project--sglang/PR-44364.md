# [Fix] [NPU] qwen3.5: Support ModelSlim mixed gate/up precision

[Upstream PR](https://github.com/sgl-project/sglang/pull/44364) · state: open · merged: False

## Original PR description

## Motivation

A ModelSlim Qwen3.5 Dense checkpoint can store `gate_proj` as FLOAT and `up_proj` as W4A8_MXFP. Constructing a merged `gate_up_proj` rejects this valid mixed-precision pair before loading. Keep these projections separate when the checkpoint explicitly assigns different schemes.

## Modifications

- Add a ModelSlim query that requires both precision entries to be present and different; missing metadata still reaches the existing fused-layer checks.
- Opt Qwen3.5 Dense MLPs into two existing `ColumnParallelLinear` layers for heterogeneous gate/up pairs. Each retains its own weight format, scale, loader, and post-load processing; forward concatenates gate then up for the existing activation and down projection.
- Preserve individual parameter names in both Qwen3.5 loaders and skip fused NVFP4 setup for the split structure. Uniform pairs keep the merged path.
- Cover precision selection, TP weight/scale partitioning, forward order, and both loaders.

This fix is independent of the shared W4A8 execution refactor. The already-merged preprocessing resize fix from #43309 is excluded.

## Accuracy Tests

- 7 tests passed in an isolated CPU harness using production Linear/ModelSlim modules and extracted production MLP/loader bodies, with serving and hardware imports isolated. These are CPU contract checks, not a full serving test.
- Ruff, isort, codespell, syntax, and diff checks passed. Full package execution remains unverified locally because serving dependencies are incomplete.
- Earlier Ascend 950 testing of the ModelSlim W4A8 checkpoint on `TallMessiWu/sglang@2ef4c276be` was reported successful, with normal responses after restarting with BF16 SSM and removing the graph-disable override. That integration branch included the shared W4A8 execution and preprocessing fixes. This new standalone PR head has not been rerun on NPU; no numerical accuracy comparison was performed.
