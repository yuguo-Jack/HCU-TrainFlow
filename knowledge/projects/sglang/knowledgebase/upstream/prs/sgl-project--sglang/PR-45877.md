# [CI] [AMD] test: Skip Mistral-7B and Mixtral-8x7B FP8 in nightly GSM8K eval

[Upstream PR](https://github.com/sgl-project/sglang/pull/45877) · state: closed · merged: True

## Original PR description

## What

Add `neuralmagic/Mistral-7B-Instruct-v0.3-FP8` and `neuralmagic/Mixtral-8x7B-Instruct-v0.1-FP8` to `failing_models` in the AMD nightly GSM8K eval, so the test skips them like the other known-broken models there.

## Why

These two are the only failing models in `test_gsm8k_eval_amd.py`. They miss the threshold by a wide margin on rocm10, rocm720 and rocm724:

| Model | Score (3 attempts) | Threshold |
|---|---|---|
| Mistral-7B-Instruct-v0.3-FP8 | 0.308 / 0.321 / 0.316 | 0.46 |
| Mixtral-8x7B-Instruct-v0.1-FP8 | 0.182 / 0.136 / 0.156 | 0.69 |

The test failed in all 21 nightly runs on these models over the last 7 days (3 lanes x 7 nights). I found no passing run in the logs back to 2026-07-31. Every other model in the file passes. Because the failure is not intermittent, the job retry reruns the whole ~1.5 h job and fails again every night.

Example: [rocm10](https://github.com/sgl-project/sglang/actions/runs/39645680073/job/119380497709), [rocm720](https://github.com/sgl-project/sglang/actions/runs/39645680073/job/119380496977), [rocm724](https://github.com/sgl-project/sglang/actions/runs/39645680073/job/119380497457).

## Notes for the reviewer

Triage of the low scores (MI300X, rocm10):

- **Mistral-7B-FP8: scorer artifact.** The legacy scorer puts the 5-shot prompt in one chat turn, generates up to 2048 tokens with no stop, and grades the last number. The model answers (`#### 64`) and then keeps writing made-up Q&A blocks, so the last number is wrong. Score 0.391; 0.511 when each response is cut at the next `Question:`; 0.472 with the completion API and `stop=["Question"]`. On sgl-eval it is within 1.4 pt of bf16 (0.237 vs 0.250). [Scorer run](https://github.com/sgl-project/sglang/actions/runs/39999772206).
- **Mixtral-8x7B-FP8: scorer artifact plus a real ROCm accuracy gap.** The same scorer gives bf16 Mixtral only 0.320 (0.644 truncated). On sgl-eval, the neuralmagic static-scale checkpoint scores 0.30 vs 0.425 for bf16 and 0.40 for online `--quantization fp8`, and 0.403 on H100. That gap, plus a crash of the same checkpoint with `SGLANG_USE_AITER=0`, is tracked in #46628.

This is still a stop-gap until #39505 moves the AMD suite to sgl-eval. Mixtral-8x7B-FP8 should come back once #46628 is fixed.

### issue_comments

- michaelzhang-ai · comment · 2026-10-26T17:06:06Z · [source](https://github.com/sgl-project/sglang/pull/45877#issuecomment-6422345647)

Thanks, I ran the triage on MI300X rocm10 ([scorer run](https://github.com/sgl-project/sglang/actions/runs/39999772206), [online FP8 run](https://github.com/sgl-project/sglang/actions/runs/39999953126)).

1. Most of the gap is the legacy scorer, not accuracy. It puts a 5-shot prompt into a single chat turn, generates up to 2048 tokens with no stop, and grades the last number. Both models answer correctly (`#### 64`) and then keep generating made-up Q&A, so the last number is wrong. Even bf16 Mixtral scores 0.32 under this scorer (threshold 0.69). Cutting each response at the next `Question:` gives 0.64 for bf16 Mixtral, 0.62 for Mixtral FP8, and 0.51 for Mistral FP8.
2. Mixtral FP8 also has a real AMD-specific gap with the neuralmagic static-scale checkpoint. On sgl-eval: bf16 0.425, online `--quantization fp8` 0.398-0.412, neuralmagic FP8 checkpoint 0.30, compared with 0.403 for the same checkpoint on H100. Mistral-7B in the same format is within 1.4 pt of bf16, so the loss looks like it is in the static-scale MoE path rather than the dense layers.
3. Separately, with `SGLANG_USE_AITER=0` that checkpoint crashes in `_native_static_quant_fp8` (17-vs-16 row mismatch).

I filed #46628 for (2) and (3), and updated the PR: Mistral-7B-FP8 is skipped as a scorer artifact, and Mixtral-8x7B-FP8 is skipped with a link to #46628 until that is fixed. If you'd rather keep Mixtral FP8 failing in the nightly until #46628 lands, I can drop it from this PR.
