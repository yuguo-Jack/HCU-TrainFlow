# [Fix] hicache: Bound CPU collective waits and watch idle event polling

[Upstream PR](https://github.com/sgl-project/sglang/pull/47846) · state: open · merged: False

## Original PR description

## Motivation

HiCache event polling performs synchronous CPU collectives before selecting a batch. If a peer stops participating after an idle iteration, the scheduler can wait while its forward watchdog is inactive. The CPU Gloo groups also use a separate two-hour timeout even when `--dist-timeout` is set.

## Modifications

- Apply an explicit `--dist-timeout` to CPU Gloo groups, retaining the existing default when it is unset. This affects all CPU groups created by `GroupCoordinator`.
- Watch HiCache event checks with a named, independently timed scope on the existing hard watchdog, including PD decode entry points. Normal idle remains exempt, and inactive polling refreshes the forward watchdog baseline.
- Allow watchdog diagnostics when there is no current batch.

This bounds failure detection; it does not repair the rank divergence or transport failure that originally stalls a collective. Collective ordering is unchanged.

## Accuracy Tests

- All applicable pre-commit hooks passed for the five changed files.
- Local deterministic checks against the source-extracted watchdog class passed: idle HiCache stall triggers fatal shutdown; preceding idle time is excluded from the scope deadline; prolonged idle and repeated completed checks do not trigger shutdown; exceptions clear the scope; existing stalled-forward detection remains functional.
- Evaluated the CPU-group timeout expression for both an explicit 120-second timeout and the unchanged 7200-second fallback.
- No committed test files added. Real multi-process Gloo and GPU serving validation were not run.

## Speed Tests and Profiling

Not run; no performance claim. The watchdog scope adds a context-manager entry/exit and a clock read per HiCache event check.
