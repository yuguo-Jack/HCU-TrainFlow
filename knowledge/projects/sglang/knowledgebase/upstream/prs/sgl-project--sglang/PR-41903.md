# [Perf] [AMD] dsv4: reuse the q_lora fp8 quant for the C4 indexer wq_b (4/8)

[Upstream PR](https://github.com/sgl-project/sglang/pull/41903) · state: closed · merged: True

## Original PR description

## Motivation

On the fused qk-norm/rope path (gfx95/gfx1250), `MQALayer._forward_prepare` already quantizes the normed `q_lora` to fp8 group-128 (`_fused_rmsnorm_fp8_quant`) for the attention `wq_b`. The C4 indexer's `wq_b` takes the same `q_lora` and quantizes it again with a standalone `dynamic_per_group_scaled_quant`. For DeepSeek-V4-Pro that adds 30 extra launches per decode/verify step.

## Modifications

- `_forward_prepare` passes the existing quant (`q_lora_quant`) through `C4Indexer.forward` -> `forward_c4_indexer` -> `compute_q`, and the indexer `wq_b` consumes it directly.
- It is dropped (set to `None`) when the indexer trims `q_lora` to fewer queries. The non-fused path, the multi-stream path, NPU and the low-ratio arms are unchanged. `forward_c4_indexer` only receives the kwarg when it is set.

## Accuracy Tests

- The quantized input is the same tensor the attention `wq_b` already uses, so the indexer `wq_b` input is identical to its own quant of `q_lora`.
- DeepSeek-V4-Pro TP8, stock image `lmsysorg/sglang-rocm:v0.5.20-rocm724-mi35x-20260927` + this PR only: gsm8k 200q **0.965**. A capture-time print confirmed that the reuse path runs on all 8 ranks.
- On the stack below, DSpark b6 gsm8k 1319q over 2 boots: before 0.945 / 0.939, after 0.945 / 0.948. Accept length 4.36 -> 4.37.

## Speed Tests and Profiling

Kernel: each removed `dynamic_per_group_scaled_quant` launch shows as 4.3 us in the graph-mode trace (about 3.8 us after subtracting profiler overhead). With 30 launches per step, the trace estimate was about 0.11-0.13 ms per step. The measured E2E saving is 0.06-0.09 ms per step, which is about 2-3 us per launch.

E2E, DeepSeek-V4-Pro fp8, TP8 MI355X, image `lmsysorg/sglang-rocm:v0.5.20-rocm724-mi35x-20260927`, 8k in / 1k out. Measured on our DSv4 decode stack: sgl-project/sglang#41383 (FlyDSL fused decode, with ROCm/aiter#5882 and the aiter fp32-out HGEMM fix), the DSpark verify ring write, sgl-project/sglang#38919 + sgl-project/sglang#38920 (env on), the MoE small-batch sort and the fp32 GEMM aiter route. Before = that stack; after = stack + this PR. It was developed there; the diff on main is the same minus the sgl-project/sglang#38920 `kv_score_input` plumbing. 2 boots x 3 reps, paired:
