## Motivation

<!-- Describe the purpose and goals of this pull request. -->
The current KTransformers MoE integration in this branch is not compatible with the current kt_kernel API, which breaks SGLang on the heterogeneous CPU+GPU MoE path during initialization or weight loading.

There are two main issues:

1. The current code still initializes KTMoEWrapper with the legacy num_gpu_experts argument, while newer kt_kernel versions expect gpu_experts_mask.
2. The current KT path assumes GPU experts are a contiguous prefix during weight loading. It does not skip CPU experts based on the GPU expert mask, and it does not remap logical expert ids to GPU-local weight indices. This leads to incorrect weight loading and runtime failures.

This PR restores compatibility with current kt_kernel versions and fixes expert remapping and weight loading for the KT path.

## Modifications

<!-- Detail the changes made in this pull request. -->
1. Add backward-compatible KTMoEWrapper initialization:
     a) pass gpu_experts_mask when supported by kt_kernel
     b) otherwise fall back to the legacy num_gpu_experts argument
2. Add GPU expert mask and logical-to-GPU-local expert index mapping in the KT wrapper, so the KT path can:
    a) mask out CPU experts before GPU execution
    b) remap logical GPU expert ids to GPU-local weight indices
3. Fix fused MoE weight loading for the KT path:
    a) skip experts that are not placed on GPU
    b) load weights using the remapped GPU-local expert index
    c) avoid narrowing weights again when they are already local shards, which fixes the previous w2 and w13 out-of-range failures
4. Add the missing sglang.srt package init file to avoid import issues in affected environments

The `expert_id` at this point in the code is a local expert ID. However, it's being used to index `kt_method.gpu_experts_mask`, which is intended to be a mask over global expert IDs to differentiate between CPU and GPU experts. Using a local ID to index this mask is incorrect if `moe_ep_size > 1` and can lead to incorrect weight loading, as CPU expert weights might be loaded as if they are GPU experts.

The root cause appears to be that `KTEPWrapperMethod` is initialized with the number of local experts instead of the global number of experts, leading to `gpu_experts_mask` having an incorrect size and scope.
