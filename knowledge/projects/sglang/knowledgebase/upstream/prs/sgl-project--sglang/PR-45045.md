# [Chore] [AMD] monokernels: Pin sgl-amd-mono at plugin main with the GLM and MiniMax-M3 specs

[Upstream PR](https://github.com/sgl-project/sglang/pull/45045) · state: open · merged: False

## Original PR description

## Motivation

`--monokernel-backend amd` loads its kernels from sgl-project/sgl-amd-mono, through the `monokernels_hip` extra (sgl-project/sglang#44601). The pin is still e07665c, which has DeepSeek-V4.1 only. Plugin main has three more models and a set of fixes:

- GLM-5.3-Flash (sgl-project/sgl-amd-mono#6) and GLM-5.3 (sgl-project/sgl-amd-mono#7) decode monokernels.
- MiniMax-M3 (sgl-project/sgl-amd-mono#8). On this SGLang it refuses to start with a reason naming sgl-project/sglang#41998 and #41708, until those land.
- DeepSeek-V4.1 fixes (sgl-project/sgl-amd-mono#10):
  - startup refusals for configurations the kernels misread;
  - the Engram image mask matching SGLang;
  - aiter's FlyDSL helpers in the kernel cache key.
- Kernel cache keys (sgl-project/sgl-amd-mono#11): each kernel is keyed on the plugin and aiter FlyDSL modules it imports and on every build argument, so an edit to any of them rebuilds it.

## Modifications

- `python/pyproject_other.toml`: the `monokernels_hip` pin moves from e07665c to e952b22, plugin main.
- The ROCm image needs no change. It checks out the commit pip installed.

## Accuracy Tests

MI350X, TP4. This branch (SGLang main da414adda7) with the plugin's tree at e952b22 (tested as 397b87f, the same tree), running the plugin's serving tests:

- DeepSeek-V4.1 (`test/e2e/test_deepseek_v41_server.py`): 9 passed.
- GLM-5.3-Flash (`test/e2e/test_glm53_flash_server.py`): 4 passed.
- The plugin's `test/unit`: 120 passed. This includes the contract test, which checks every SGLang name the plugin reads against this SGLang.

The earlier pin candidate 6f096de passed the same tests on this branch. There, GLM-5.3-Flash's KL for each batch was 0.008 to 0.026 against a bound of 0.06, and GSM8K-200 was 0.98.

Not run here:

- GLM-5.3 needs 8 GPUs to serve, and its author validates it. Here its launch compiles with the runner's arguments on one GPU.
- MiniMax-M3 refuses on this SGLang. Its 3 decode tests passed at 397b87f against SGLang main 6c3db0f520 + #44601 + #41998.

No SGLang code changes. The plugin PRs above report their own numbers.
