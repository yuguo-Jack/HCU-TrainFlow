# [Perf] [NVIDIA] moe: Fused NVFP4 SwiGLU MoE kernel for SM120

[Upstream PR](https://github.com/sgl-project/sglang/pull/48262) · state: open · merged: False

## Original PR description


## Motivation

On SM120 GPUs (RTX PRO 6000 Blackwell, RTX 5090), `modelopt_fp4` MoE models default to the `flashinfer_cutlass` runner. For small batches (decode, speculative verify), FlashInfer's CUTLASS MoE runs as a chain of separate kernels (routing/sort, input expansion and FP4 quantization, grouped GEMM1, SwiGLU + FP4 quantization, grouped GEMM2, finalize), and at decode batch sizes most of their time is launch and synchronization overhead rather than math.

This PR adds a JIT kernel that computes the same MoE in two launches and is **bitwise identical** to FlashInfer's CUTLASS path in SGLang's default configuration (`SGLANG_FLASHINFER_MOE_FUSED_FINALIZE=0`). It is templated on the expert count, top-k, hidden and intermediate size, so it covers SwiGLU NVFP4 MoE models such as `nvidia/Qwen3.8-Flash-Next-NVFP4` (512 experts, top-10) and `nvidia/Qwen3-30B-A3B-NVFP4` (128 experts, top-8). It follows the existing SM120 native NVFP4 MoE path for non-gated ReLU² models (`sm120_nvfp4_moe.py`).

## Modifications

- `python/sglang/kernels/jit/csrc/gemm/sm120_nvfp4_moe_swiglu.cuh` (new):
  - **prologue:** routes tokens into per-expert units of up to 32 tokens and quantizes each input row to NVFP4 once per token (not once per (token, expert)).
  - **persistent kernel:** CTAs pull tiles from one atomic queue. A GEMM1 tile (unit, 64 intermediate channels) runs the block-scaled FP4 MMA over the hidden size for the up and gate rows, applies alpha, rounds to BF16, applies SwiGLU and quantizes the intermediate to NVFP4. A GEMM2 tile (unit, 128 output columns) waits for its unit's GEMM1 tiles, runs the FP4 MMA over the intermediate size, and the last contribution to a token's column block performs that token's weighted top-k reduction.
  - The arithmetic follows FlashInfer's CUTLASS kernels step by step: the same FP4 quantizer (fast-math reciprocal), `mma.sync` block-scaled m16n8k64 accumulated in ascending K with no split-K, `bf16(alpha * acc)` epilogues, CUTLASS's `SiLu`, and an FP32 finalize over k = 0..top_k-1. Expert ids outside `[0, num_experts)` are skipped, as in FlashInfer's finalize. It is built with `--use_fast_math` against FlashInfer's bundled CUTLASS headers (`extra_dependencies=["cutlass"]`).
- `python/sglang/kernels/ops/gemm/sm120_nvfp4_moe.py`: `nvfp4_moe_swiglu()` (allocates the workspace per call, CUDA-graph safe) and `try_nvfp4_moe_swiglu()` (shape/dtype gate, up to 512 tokens). Registered as `gemm.nvfp4_moe_swiglu`.
- `python/sglang/srt/layers/moe/moe_runner/flashinfer_cutlass.py`: with `SGLANG_OPT_SM120_NVFP4_FUSED_MOE=1`, `_run_flashinfer_cutlass` uses the fused kernel for FP4 SwiGLU MoE on SM120 when EP = MoE TP = 1, the input is BF16 and unquantized, there is no all-to-all and no custom SwiGLU alpha/beta/limit, FlashInfer's default FP4 quantizer and the unfused finalize are active, and FlashInfer is not autotuning. Every other case keeps the CUTLASS call. The FlashInfer quantizer check is shared with the existing SM120 ReLU² path (`_flashinfer_default_fp4_quant()`).
- `python/sglang/srt/environ.py`, `docs/docs/references/environment_variables.mdx`: the opt-in `SGLANG_OPT_SM120_NVFP4_FUSED_MOE` (default off).
- Tests: `test/registered/kernels/ops/gemm/test_sm120_nvfp4_moe_swiglu.py` (bitwise vs `flashinfer.fused_moe.cutlass_fused_moe`), `test/registered/kernels/benchmark/gemm/bench_sm120_nvfp4_moe_swiglu.py` (nightly, since it autotunes CUTLASS for every shape).

## Accuracy Tests

The fused kernel reproduces the CUTLASS output bit for bit, so outputs do not change.

**Kernel test** (RTX PRO 6000 Blackwell, SM120, 300 W and 600 W): `test_sm120_nvfp4_moe_swiglu.py` compares `int16` views of the BF16 outputs against `cutlass_fused_moe(..., use_fused_finalize=False)` for the Qwen3.8-Flash-Next shape (512 experts, top-10, 2560, 640) and the Qwen3-30B-A3B shape (128, top-8, 2048, 768), T = 1, 2, 7, 31, 32, 33, 128, 333, 512, two input scales, with a zero input row, skipped expert ids (`-1`), 96 tokens on one expert, and CUDA-graph replay with NaN-poisoned outputs: 0 differing elements. CUTLASS's own output does not depend on its tactic (default vs autotuned tactic, T = 1..512: 0 differing elements).

**End-to-end, deterministic**: `nvidia/Qwen3-30B-A3B-NVFP4`, `--quantization modelopt_fp4 --moe-runner-backend flashinfer_cutlass --enable-deterministic-inference`, upstream main vs this PR with `SGLANG_OPT_SM120_NVFP4_FUSED_MOE=1`, launches A, B, B, A on the same GPU. 64 short prompts plus 4 prompts of about 2,500 tokens in one batched request and 7 single requests, greedy, 96 new tokens (7,200 tokens per launch):

| GPU | pair | batched | single |
|---|---|---|---|
| RTX PRO 6000 Blackwell 300 W | every pair of A0, B1, B2, A3 | 68/68 identical | 7/7 identical |
| RTX PRO 6000 Blackwell 600 W | every pair of A0, B1, B2, A3 | 68/68 identical | 7/7 identical |

**`nvidia/Qwen3.8-Flash-Next-NVFP4` in the serving process** (RTX PRO 6000 Blackwell 300 W): on SM120 this model cannot run with `--enable-deterministic-inference` (the indexer top-k needs 128 KiB of shared memory), and default serving is not launch-reproducible on main (main vs main: 64/68 batched and 0/7 single prompts identical, because the scheduler forms different prefill batches on every launch). So for this model a test-only hook re-ran every fused MoE call through `cutlass_fused_moe` on the same inputs inside the server, while it served the 75 prompts above and gsm8k (200 questions): 265,600 calls with up to 274 tokens, 0 differing output elements.

`sgl-eval` is not needed: every output of the fused kernel equals the CUTLASS output.
