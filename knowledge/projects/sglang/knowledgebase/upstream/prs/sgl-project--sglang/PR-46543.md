# [Refactor] qwen4: Write QSA top-k and PLE batch breaks into caller-held outputs

[Upstream PR](https://github.com/sgl-project/sglang/pull/46543) · state: closed · merged: True

## Original PR description

- **QSA top-k break.** The break in the breakable prefill graph writes the top-k indices into the caller's rows of the layer's bridge and returns nothing; the captured consumers read those same rows. Before, the break returned a view of the newest bridge on every replay and the graph wrapper copied it into the view it had captured.
  - The caller looks up the newest bridge that holds its rows and passes that slice to the break. On the first run, a warmup, there is none, and the break allocates one; a capture asserts the bridge already exists, which the warmups before each capture guarantee.
  - Buckets share the newest bridge as before. The layer now keeps older, smaller bridges in a list for the graphs captured on them; before, the wrapper's captured output kept them alive.
- **PLE batch break.** The caller creates the `_BreakablePLEBatch` holder before the break, and the break fills its `batch` with the live batch's PLE layout on every replay. Before, the break returned a new holder and the wrapper rewrote the captured holder's attributes from it.
- Tests: a unit test covers a capture that reuses the bridge its warmup allocated; the existing QSA and PLE break tests follow the new signatures.
- No behavior change intended. The changed paths run only for Qwen4-exp QSA and PLE layers under the breakable prefill graph.
