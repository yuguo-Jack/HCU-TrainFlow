# [Fix] flashinfer: honor DECODER_BIDIRECTIONAL in extend attention

[Upstream PR](https://github.com/sgl-project/sglang/pull/45056) · state: open · merged: False

## Original PR description

## Motivation

Fixes #36663.

The FlashInfer and inherited TRT-LLM MHA prefill paths treated `AttentionType.DECODER_BIDIRECTIONAL` as causal. This caused bidirectional decoder layers to use a different attention mask from the Triton backend when running with a complete prefill.

## Modifications

- Share the causal decision across the paged and ragged prefill paths.
- Apply the shared decision to TRT-LLM MHA's fmha_v2 mask mode and batch-context prefill path, including the bidirectional sliding-window behavior.
- Honor `DECODER_BIDIRECTIONAL` when chunked prefill is disabled and CUDA graphs are disabled or prefill uses the breakable backend, matching Triton's gate.
- Keep DLLM extend bidirectional regardless of the generic prefill gate.
- Disable the left sliding window for bidirectional extend, matching Triton's full-sequence behavior; preserve the multi-item scoring override.
- Update the HRM backend note and add registered CPU unit coverage for the gate, DLLM extend, other attention types, and multi-item scoring.

## Accuracy Tests

Added `test/registered/unit/layers/attention/test_flashinfer_extend_causal.py` with four focused unit tests.

CPU regression tests were not rerun for this submission. GPU/model accuracy evaluation has not been run.

To run the registered test:

```bash
python3 test/registered/unit/layers/attention/test_flashinfer_extend_causal.py
```
