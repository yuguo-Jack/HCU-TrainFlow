## Motivation

<!-- Describe the purpose and goals of this pull request. -->

Some models use the same architecture name in SGLang but need different mono kernel specs. For example, dsv4-pro and dsv41 both run as `DeepseekV4ForCausalLM`. The mono kernel registry looks up a spec by architecture only, so it cannot tell these two models apart.

This PR lets the registry also use the model type (`model_type` in the model's config) to choose the spec.

Needed by sgl-project/sgl-amd-mono#48. Merge this PR before it.

## Modifications

<!-- Detail the changes made in this pull request. -->

- Registering (plugin side): `register()` in `kernels/plugin_kernels/amd/spec.py` takes an optional `model_type`. A plugin can register a spec for one model type, or leave `model_type` out (`None`).
- Looking up (sglang side): Sglang's startup check and runtime in `srt/kernel_plugins/amd/binding.py` pass the served model's `hf_config.model_type` to `find_spec()` and `spec_registered()`. A lookup first tries a spec registered for that model type, then a spec registered without one.

With the current sgl-amd-mono repo, every model gets the same spec with and without this PR.
