# [Feat] [AMD] mori: Allow MoRI for DeepSeek-V4.1 DSpark PD

[Upstream PR](https://github.com/sgl-project/sglang/pull/42457) · state: closed · merged: True

## Original PR description

## Motivation

`validate_deepseek_v41_features` only accepts Mooncake and NIXL (#43734) for DeepSeek-V4.1 DSpark PD, so `--disaggregation-transfer-backend mori` fails at startup. The V4.1 DSpark PD support is backend-agnostic: the layout and TP checks run in `CommonKVManager.try_ensure_parallel_info`, and MoRI already transfers the target and draft SWA states through its generic state path.

## Modifications

Accept `mori` next to `mooncake` and `nixl` in the V4.1 DSpark PD check and update the error message.

## Accuracy Tests

DeepSeek-V4.1-Flash, 1P1D on one 8x MI355X node (prefill TP4 + decode TP4), DSpark, MoRI, `lmsysorg/sglang-rocm:v0.5.21-rocm724-mi35x-20261003` + this PR:

| Test | 1P1D MoRI | Aggregated (reference) |
|---|---|---|
| Needle at 213 / 1.1K / 2.7K / 5.4K / 21K / 110K prompt tokens | all correct | all correct |
| GSM8K 5-shot, 400 questions | 0.907 | 0.900 - 0.910 |
| DSpark accept length (decode) | 3.46 | 3.4 - 3.5 |
| Chat with thinking, tool call | correct | correct |

With the UMBP direct linker on the prefill side (#42197), a 110K-token prompt after `flush_cache` on both servers restores 110,080 cached tokens and produces greedy output identical to the cold run.

These runs use CP=1 on both servers. Since #40323 the same check also admits prefill CP; MoRI with prefill CP is not covered here.
