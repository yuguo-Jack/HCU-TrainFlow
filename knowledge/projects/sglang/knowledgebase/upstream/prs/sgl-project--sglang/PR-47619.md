# [CI] ci: Re-tier CUDA tests across base, extra, nightly, and weekly by importance

[Upstream PR](https://github.com/sgl-project/sglang/pull/47619) · state: closed · merged: True

## Original PR description

Re-tier the CUDA test registrations by what each test guards, so the per-PR gate keeps the core paths and the rest runs on the cadence its signal needs.

- Tiers after this change: `base` (every PR) keeps the core default paths (scheduler, radix cache, default attention backends, chunked prefill, default speculative decoding, OpenAI API, basic PD/TP/DP-attention/PP) and cheap unit tests; `extra` (labeled PRs, and `main` every few hours) holds current flagship-model end-to-end tests and features people use that are off the default path (PD variants, HiCache storage backends, non-default speculative decoding, LoRA variants); `nightly` holds niche paths and tests whose only assertion is an accuracy or performance gate; `weekly` holds tests of old, unpopular, or superseded models.
- 130 registrations in 128 files change stage; every test keeps its `runner_config`.
- Estimated from recent measured per-file times (time x GPUs): `base` drops by about 63,600 GPU-seconds per run (about 70%), `extra` by about 39,000 net (about 17%).
- `extra` gains `2-gpu-gb300` and `4-gpu-gb300` matrix rows. These rows pass no Rust-extension artifact, since that artifact is built for x86_64, so they restore the aarch64 cache that `pr-test.yml` seeds. A PR that changes sgl-kernel has no aarch64 wheel in this workflow, so those rows cannot run for it.
- `nightly-test-nvidia.yml` folds its per-runner jobs into one matrix job, as `weekly-test-nvidia.yml` already does; the timeouts are unchanged and `runner_filter` becomes a free-text field matched in `_pr-test-stage.yml`. On top of that, `nightly` gains `1-gpu-small` and `8-gpu-b300` rows, so tests on those machines move to nightly on the same hardware.
- Drop the `base-c` `8-gpu-h20` and `8-gpu-h200` matrix rows and suite names: no test registers there any more, and an empty suite would fail its stage job.
- A PR that touches a demoted path can still run those tests with `/rerun-test`, which resolves extra, nightly and weekly registrations the same way as per-commit ones.
- Add a `rerun-test` skill (`.agents/skills/rerun-test/SKILL.md`) on picking and running the tests a change touches; `ci-workflow-guide` and `write-sglang-test` point to it. The bot-managed CI States block gains a TIP alert with a one-line hint and a copyable agent prompt that links to the skill.

Each list below gives the file, its runner, and its GPU-seconds per run.
