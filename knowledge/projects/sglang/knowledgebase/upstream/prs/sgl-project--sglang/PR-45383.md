# [CI] sgl-router: Gate on live run-ci label so /tag-and-rerun-ci can start the tiers

[Upstream PR](https://github.com/sgl-project/sglang/pull/45383) · state: closed · merged: True

## Original PR description

## Motivation

`/tag-and-rerun-ci` never starts the sgl-router CI tiers. Seen on #45103 (and #42818 before it): the PR ends up with the `run-ci` label, the "PR Test (sgl-router)" check is green, and every tier job is `skipped`.

Three things in `pr-test-sgl-router.yml` combine to cause it:

1. The gate reads `github.event.pull_request.labels`, a payload frozen when the run was triggered. A rerun replays that payload, so a rerun after the label was added skips again.
2. The slash handler adds `run-ci` with `GITHUB_TOKEN`, and GitHub fires no `labeled` event for such label changes, so no new run starts either.
3. The all-tiers-skipped run concludes `success` (`finish` echoes OK), and the handler only reruns unsuccessful runs, so the hollow run is never rerun at all.

The only ways to get the tiers running were a human removing and re-adding the label by hand, or pushing another commit.

## Modifications

Port the pattern `pr-test.yml` and `pr-test-sgl-processor.yml` already use:

- Split path detection into a `changes` job that only answers "does this PR touch sgl-router?".
- Call the shared `pr-gate.yml` for the `run-ci` label. It fetches the labels live and **fails** the gate when the label is missing, instead of skipping. The run is then red, `/tag-and-rerun-ci` reruns it, and the rerun sees the label. `push` to main and `workflow_dispatch` pass straight through as before.
- `finish` checks each tier's result explicitly: success when all tiers passed, or when no router path changed and all tiers were skipped; failure otherwise.

Behavior change for router PRs without `run-ci`: the `gate / pr-gate` and `finish` checks are red rather than green-with-everything-skipped, matching what `call-gate / pr-gate` already does for the Python test workflows.

The `gate` check is now reported as `gate / pr-gate` (reusable-workflow naming, same as `call-gate / pr-gate`). `finish` keeps its name.

## Verification

- `actionlint` on the new file reports only the pre-existing unknown self-hosted label `2-gpu-h100`, identical to main.
- Evidence the rerun path works with the shared gate: pr-test run 39407165818 had `pr-gate` fail on attempt 1 for a missing label and pass on attempt 2 after the label was added, with the test jobs then running.
- This PR touches the workflow file itself, so its own "PR Test (sgl-router)" run exercises the new gate: red without the label, then `/tag-and-rerun-ci` should start tier-1 through tier-3.
