# [Doc] Cookbook: update GB300 DSV4.1 agg AgentX launches from InferenceX #4434

[Upstream PR](https://github.com/sgl-project/sglang/pull/46490) · state: closed · merged: False

## Original PR description

Update the GB300 aggregated Dynamo-SGLang AgentX commands from [InferenceX #4434](https://github.com/SemiAnalysisAI/InferenceX/pull/4434) at `6e0aec9ff3ef06dc985a6408b2461b0184296e6c`. The aggregated line moves to the digest-pinned October 25 nightly (`lmsysorg/sglang:nightly-dev-cu13-20261025-65633129`), which ships ai-dynamo 1.6.0 and the sgl-nvidia-mega plugin (`6fd7ac30`) that `--enable-nvidia-megakernel` loads, so no setup step is needed.

- **TP4 c1** is now the batch-1 NVIDIA megakernel launch from `override_tp4_c1`. It uses `--enable-nvidia-megakernel` with 42 kernel slots, `--max-running-requests 1`, `--cuda-graph-max-bs-decode 1`, FP8 KV, `--moe-a2a-backend none`, LPM scheduling with 128 SWA prefix tails, the DSpark decode-graph gates, and `NCCL_CUMEM_ENABLE=0` / `NCCL_MNNVL_ENABLE=0`.
- **TP4 c4, TP4 c16 and TP2/EP2 c16** add `--dsv4-attn-backend flashmla`. On this image `auto` resolves to MegaAttention, which pads each rank's heads to 64, so it is slower at TP4 and TP2.

The usual deployment substitutions apply, and SA-specific settings (the metrics flags and Python env) are removed. The simulation-only `SGLANG_SIMULATE_ACC_GREEDY` and `SGLANG_OPT_DSV41_DSPARK_SIM_DRAW_AHEAD` are also left out: the page already discloses that the synthetic acceptance length is not part of these commands, and both variables do nothing without it. Both points are marked verified in #4434, with a link to its full sweep. Two GB300 SGLang-router blocks referenced the old c1 worker. They are now written as full blocks, and their decoded commands are unchanged. All other configurations are unchanged, and the hand-written MDX section from the first commit is removed again.

Validation: the [complete InferenceX sweep](https://github.com/SemiAnalysisAI/InferenceX/actions/runs/40153045152) passed all 18 jobs. Its aggregated P90 interactivity was 952 (TP4 c1), 581 (TP4 c4), 458 (TP4 c16) and 321 (TP2/EP2 c16) tok/s/user.

All eight aggregated worker launches (four points, Dynamo and SGLang routers) match the #4434 recipes after deployment substitutions. They were decoded with the page's own AgentX decoder. The other 378 of the page's 402 launch variants decode exactly as on main. The cookbook configuration check, pre-commit, Mintlify build validation and the link check pass.

Known limit: the page also derives a HiCache variant for every point. For TP4 c1 that variant does not start, because the megakernel refuses KV offload at startup. The Mooncake variant of c1 is not validated. `kv.available` applies to the whole cell, so c1 cannot be excluded on its own without also dropping HiCache for c4 and c16.

GSM8K on the TP4 c1 megakernel configuration matches the default launch within noise:

| launch (October 25 image, real DSpark acceptance) | GSM8K | truncated / errors |
|---|---|---|
| TP4 c1 megakernel config (this PR's c1 server settings) | 96.74% | 0 / 0 |
| default GB300 TP4 low-latency launch from the Deploy panel (TP4/EP4, no megakernel) | 96.51% | 0 / 0 |

The 0.23 pt gap is 3 of 1319 questions, inside one standard error (about 0.49 pt). Both arms ran sgl-eval 0.1.3 GSM8K on all 1319 examples with 4 threads. They used the DeepSeek-V4.1 preset: temperature 1.0, top_p 0.95, `chat_template_kwargs.thinking=true`, reasoning effort high. The megakernel arm ran `sglang serve` without Dynamo. It used the c1 env and args, leaving out the served model name and watchdog timeout, plus two flags that equal their defaults (`--context-length`, `--startup-weight-load-mode`). It served one request at a time. Its startup log reported the megakernel `active` for both the DeepSeek-V4.1 target and the DSpark draft on TP0-3. During the eval its accept length was 3.60 (median of the server's decode log), and its median decode step was 3.75 ms (log intervals with no prefill).
