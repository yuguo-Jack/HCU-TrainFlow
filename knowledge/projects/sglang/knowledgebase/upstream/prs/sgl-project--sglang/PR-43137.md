# [diffusion] comfyui: zero-fill missing Flux pooled vector

[Upstream PR](https://github.com/sgl-project/sglang/pull/43137) · state: closed · merged: False

## Original PR description

## Motivation

Fixes #43115.

When a Flux conditioning has no `pooled_output`, ComfyUI calls the DiT with `y=None`, and its native Flux zero-fills `y`. `FluxAdapter.pack` passed it through as `pooled_embeds=[None]`, so on the worker `prepare_pos_cond_kwargs` handed `pooled_projections=None` to `time_text_embed`:

```
AttributeError: 'NoneType' object has no attribute 'dtype'
```

The cond was also never cached, since `_cond_key` needs `prompt_embeds[0]` to be a tensor.

**Depends on #43109, please merge that first.** This branch is stacked on it (the first two commits are #43109). With a zero-filled `y` the cond gets a cache key, and on main's old shape + first/last-scalar key every y-less cond would get the same key (zeros everywhere), so the second prompt, or the CFG negative, would silently reuse the first one's T5 context. I checked this: the new session test fails with this commit on top of main's key.

## Modifications

- `FluxAdapter.pack`: if `y is None`, use `torch.zeros(batch, 768)` with the context's dtype/device, like `comfy/ldm/flux/model.py`. 768 is Flux.1's CLIP-L width (`pooled_projection_dim`); `FluxAdapter` only handles `model_type="flux"`.
- Tests: `test_flux_pack_zero_fills_missing_pooled` (pack + the real `CombinedTimestepGuidanceTextProjEmbeddings`), `test_cond_key_flux_without_pooled_keeps_t5_apart` (two y-less conds with different T5 stay apart, a repeat still hits the cache).

## Accuracy Tests

CPU end-to-end repro: real ComfyUI KSampler (ComfyUI master 58b176f) with the plugin's `FluxExecutor` + `SGLDModelPatcher`, a cond with no `pooled_output`, and the worker half in-process (real `bind_comfyui_session` -> `FluxPipelineConfig.prepare_pos_cond_kwargs` -> the DiT's `time_text_embed`):

```
before: CRASH after 0 DiT calls: AttributeError: 'NoneType' object has no attribute 'dtype'
after:  OK: 4 DiT calls, time_text_embed out (1, 64), cond key set on 4/4 calls
```

GPU: not run. I set up a 2-GPU sanity run (FLUX.1-dev in comfyui mode, the plugin's `test_flux_pipeline.py` plus the real `FluxExecutor` with `y=None` compared against an explicit zero `y`), but it sat in the queue for 2x L40S for about 50 minutes and never started, so I stopped it. Happy to run it if someone can trigger GPU CI.

Unit tests (CPU):

## Speed Tests and Profiling

No change to the normal path. When `y` is missing, one `(B, 768)` zero tensor is allocated per call.
