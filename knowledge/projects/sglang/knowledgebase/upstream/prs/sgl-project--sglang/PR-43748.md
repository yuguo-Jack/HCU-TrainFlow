# [NPU] Initialize padded vision attention outputs to prevent MiniCPM NaNs

[Upstream PR](https://github.com/sgl-project/sglang/pull/43748) · state: open · merged: False

## Original PR description

## Motivation

MiniCPM-V-2.6 pads image slices to the largest patch count in the batch. `VisionAscendAttention` removes those padded rows before FIA, then scatters the compact result into an output allocated with `torch.empty_like(q)`. Only valid rows are written, so padding retains uninitialized memory (or stale graph workspace contents).

During an Ascend A3 reproduction, one image produced slice lengths `[1014, 1036, 1036]`: 3086 valid rows in a 3108-row padded tensor. The first vision attention output had no nonfinite values in valid rows but 49 in padding. Nonfinite values subsequently appeared in the resampler output, and greedy decoding repeated `!` without reaching EOS. Requests without an explicit output limit continued decoding.

## Modifications

- Zero the padded output before restoring FIA results, for both multiple sequences and a single padded sequence. The unpadded path continues returning the FIA output directly.
- Add deterministic regression coverage using NaN-filled allocations and graph workspaces. Check valid Q/K/V packing, restored results, and zero padding across eager, metadata, and graph paths, including an unpadded control.

## Accuracy Tests

Used the `TestMiniCPMV4Server` class from the Ascend test module, whose model is MiniCPM-V-2.6, with local weights and the original generation limits. This end-to-end run validates the fix on the B083 runtime; the unit suite above validates the current target source.
- The previously failing single-image response completed naturally after 42 tokens with `finish_reason=stop`.

## Speed Tests and Profiling

No throughput benchmark. The fix adds zeroing only when restoring a padded output. In the end-to-end run, the mixed-batch test completed in 7.839 s and the single-image test in 0.902 s.
