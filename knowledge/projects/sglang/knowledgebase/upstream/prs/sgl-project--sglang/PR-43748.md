# [Fix] [NPU] vision: Initialize padded attention outputs to prevent MiniCPM NaNs

[Upstream PR](https://github.com/sgl-project/sglang/pull/43748) · state: open · merged: False

## Original PR description

## Motivation

MiniCPM pads image slices to the largest patch count in the batch. `VisionAscendAttention` removes those padded rows before FIA, then scatters the compact result into an output allocated with `torch.empty_like(q)`. Only valid rows are written, so padding retains uninitialized memory (or stale graph workspace contents).

An Ascend A3 reproduction with MiniCPM-V-2.6 produced slice lengths `[1014, 1036, 1036]`: 3086 valid rows in a 3108-row padded tensor. The first vision attention output had no nonfinite values in valid rows but 49 in padding. Nonfinite values subsequently appeared in the resampler output, and greedy decoding repeated `!` without reaching EOS. Requests without an explicit output limit continued decoding.

## Modifications

- Allocate zero-initialized outputs with `torch.zeros_like(q)` in the eager and metadata paths.
- Clear the existing graph output workspace in place with `output_ws.zero_()` before reuse, preserving the workspace allocation.
- Restore FIA results into the initialized output without additional clearing at writeback.
- Add deterministic regression coverage for valid Q/K/V packing, restored results, and zero padding across eager, metadata, and graph paths, including an unpadded control. Graph tests start with a NaN-filled workspace.
