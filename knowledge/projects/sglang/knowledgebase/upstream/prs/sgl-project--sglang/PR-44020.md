# [Fix] Pass return_dict=False to apply_chat_template(tokenize=True) for transformers 5

[Upstream PR](https://github.com/sgl-project/sglang/pull/44020) · state: open · merged: False

## Original PR description

## Motivation

transformers 5 returns a `BatchEncoding` from `apply_chat_template(..., tokenize=True)` unless `return_dict=False` is passed (`return_dict: bool = True` in 5.12.1, flipped to `False` only when `tokenize=False`). `len()`, `list()` and iteration on that object act on its two keys, not on the token ids. #43929 reports this for the `openai` bench loader (fix in #34511); the same call pattern exists at four more sites, none covered by a test. Each one was reproduced against transformers 5.12.1:

| Site | Observed on current main |
|---|---|
| `benchmark/datasets/speed_bench.py` | every row records `prompt_len == 2` (`decode()` accepts the dict, so the `except` fallback is never taken) |
| `entrypoints/openai/chat_encoding.py` (`encode_simple_chat`, HF-template branch) | `one_batch_server --apply-chat-template` sends `['input_ids', 'attention_mask']` as the prompt |
| `entrypoints/ollama/serving.py` (`/api/chat`) | the dict is passed as `GenerateReqInput.input_ids` |
| `multimodal/processors/voxtral.py` | with the real Voxtral tokenizer (`MistralCommonBackend`), `_build_input_ids_with_audio` raises `TypeError: unsupported operand type(s) for +: 'dict' and 'list'` |

## Modifications

- Pass `return_dict=False` at the four sites, the convention the other loaders and the server chat endpoint already use (#13229). It is a no-op on transformers 4.
- `test_speed_bench_sampler`: replace `prompt_len > 0` (which 2 satisfies) with the templated token count of the source prompts.
- New CPU tests, each failing on the old code: `test/registered/unit/entrypoints/test_chat_template_token_ids.py` (`encode_simple_chat` and the Ollama chat route, with a tiny word-level tokenizer carrying a chat template) and `test/registered/unit/multimodal/test_voxtral_processor.py` (audio tokens spliced after the last `[INST]`).

`openai_dataset.py` is intentionally left to #34511. `cosmos3.py` already handles both return types.
