# [Feat] CP: Prefill context parallelism for Kimi K3

[Upstream PR](https://github.com/sgl-project/sglang/pull/38344) · state: open · merged: False

## Original PR description

## Motivation

K3 = 93 layers: 69 KDA (linear attention, chunked delta rule) + 24 MLA (softmax attention). Every layer except the dense layer 0 is followed by a latent MoE (896 NVFP4 experts, top-16, latent width 3584, two bf16 shared experts, SiTU activation). Hidden size 7168, 96 attention heads, attention projections in FP8 (DeepGEMM), MoE front/back projections in bf16.

The branch's prefill CP is "full-sequence CP": only the MLA layers see a token shard (zigzag, balanced causal work) with attention TP width A = tp / cp; KDA and MoE run the full sequence on every rank with the usual TP8 collectives. CP8 means A = 1: every rank holds all 96 MLA heads for its N/8 query rows and the MLA o_proj all-reduce disappears. Structurally, CP cannot reduce attention, KDA or expert FLOPs per rank (heads × queries is conserved) and it does not touch the KDA/MoE collectives, so on its own it can only trade the MLA all-reduce against the cost of replicating the K/V expansion. Two things had to change for CP8 to win.

## Speed Tests and Profiling

<!-- If this pull request impacts inference speed, provide benchmarking and profiling results. -->
This PR makes Kimi K3 prefill with context parallelism (CP) faster than plain TP8 on 8x B200. Measured on a real-weight 8-layer Kimi-K3-NVFP4 proxy (6 KDA + 2 MLA layers, 7 MoE blocks), single request, --attention-backend fa4, flashinfer_trtllm MoE runner, median of 5 forwards:


configuration | 32K prefill | 64K prefill
-- | -- | --
TP8 (baseline) | 121.7 ms | 244.5 ms
TP8 + CP8, before this PR (branch default) | 177.0 ms (+45%) | 457.2 ms (+87%)
TP8 + CP8, before this PR, expanded-MHA opt-in | 124.2 ms (+2.1%) | 254.4 ms (+4.0%)
TP8 + CP8, Phase 0 (this PR, default) | 122.1 ms (+0.3%) | 250.4 ms (+2.4%)
TP8 + CP8, Phase 0 + Phase 1 (SGLANG_K3_CP_SP_RESIDUAL=1) | 101.5 ms (−16.6%) | 207.0 ms (−15.4%)

- Stone749990226 · comment · 2026-10-13T07:00:21Z · [source](https://github.com/sgl-project/sglang/pull/38344#issuecomment-6140149302)

Could we add a TP baseline with equivalent sequence-parallel optimizations to better isolate the benefit of MLA CP?
From the benchmark table, Phase 0 alone is roughly on par with plain TP8, while the reported 15–17% improvement appears after enabling the SP residual stream. This demonstrates the benefit of the combined CP+SP implementation, but does not establish how much of that improvement requires CP.
With TP attention + EP/MegaMoE, we can reduce-scatter the TP-partial o_proj outputs into token shards and feed those directly into MegaMoE. Norms, residual additions, routing, and latent projections can then run only on local tokens. We can also keep the residual stream sharded across layers, perform the next layer’s input norm/AttnRes locally, and all-gather only when TP attention needs the full sequence. These optimizations do not inherently require MLA CP.
Would it be possible to compare TP8+SP against CP8+SP with the same MoE configuration and otherwise matched settings? A TP8+EP8/MegaMoE+SP baseline would also be useful for deployment comparisons, although it changes the expert parallelism strategy. This would help distinguish the gains from removing replicated token-wise work from the additional benefits and costs of MLA CP.
