# [Perf] disaggregation: Send replicated KV heads from one prefill rank

[Upstream PR](https://github.com/sgl-project/sglang/pull/47405) · state: open · merged: False

## Original PR description

## Motivation

When a model has fewer KV heads than the prefill attention TP size, several prefill ranks hold an identical copy of the same head. In the Mooncake heterogeneous-TP path every one of those ranks writes its copy into the same decode buffer. With one KV head and prefill attention TP8 → decode TP1, each decode rank receives 8x the logical KV bytes. The slice path also posts one RDMA descriptor per token slot, so long prompts pay for both the duplicate writes and the descriptor count.

## Modifications

- `should_send_kv_replica` in `disaggregation/common/utils.py` elects one writer inside each group of prefill ranks that map to the same decode rank and hold the same head.
  - The election hashes the shared bootstrap room with BLAKE2b, so every chunk and every PP stage agrees on the writer.
  - The hash spreads load across replicas. Raw room bits can correlate with DP routing, so they are not used directly.
- Mooncake slice path (`send_kvcache_slice`): non-elected ranks skip the write.
- Mooncake staging path:
  - Prefill writer offsets, decode staging allocation and decode scatter all use one compact slot per distinct head: `staging_writer_ranks` / `staging_writer_slot`, and `compute_staging_layout(..., deduplicate=)`.
  - A single per-backend switch, `BaseKVManager.deduplicate_kv_staging`, keeps the three in agreement. Mooncake enables it; NIXL keeps the current layout.
- Whole-page fast path (`_can_send_whole_kv_pages`): when both sides hold at most one KV head per rank, page byte layouts match and unified memory is off, the elected rank sends whole pages with `send_kvcache` instead of `send_kvcache_slice`. This is one descriptor per layer per page instead of one per layer per token slot.
- Every prefill rank still sends its completion notification and staging `CHUNK_READY`. Decode readiness, the final ACK fan-in and failure propagation are unchanged.
- Same-TP transfers, MLA, P TP < D TP without replicated heads, and other backends keep their current paths.

**Compatibility:**
- With `SGLANG_DISAGG_STAGING_BUFFER=1`, prefill and decode must both run this version, because the staging slot layout changes.
- The slice and whole-page paths need no decode-side change.

## Accuracy Tests

The model forward is unchanged. Transfer correctness is checked byte-for-byte below, and by the unit tests.

## Speed Tests and Profiling

Setup:
- Two 8-GPU nodes over RoCE; prefill attention TP8 → 8 decode TP1 instances.
- A synthetic KV pool with 1 KV head and `page_size=128`; chunk size 16384; 4 queues × 3 threads.
- Transfer only: no model weights, forward, HTTP or scheduling.
- Measured with the same transfer logic on an earlier `main` base; I have not rerun the two-node benchmark on this rebase.
- Median of 5 runs after 2 warmups. Times include Python descriptor construction and synchronous RDMA.
- Every run was verified byte-for-byte on the receiver for all layers. Submitted RDMA bytes are 8x the logical size on main and 1x with this PR.

## Tests

`test/registered/unit/disaggregation/test_kv_replica_selection.py` (new, CPU) covers:
- Exactly one writer per destination head, stable across calls, over every heterogeneous (src TP, dst TP, heads) combination.
- Writers spread across all replicas over many rooms.
- Prefill staging slots tile the decode layout exactly, with and without deduplication, including P TP < D TP.
- The whole-page path writes each destination exactly once, and the destination bytes match the source pages for P > D and P < D.
- The whole-page path is refused when the decode rank holds more heads, when page byte layouts differ, or when unified memory is on.
