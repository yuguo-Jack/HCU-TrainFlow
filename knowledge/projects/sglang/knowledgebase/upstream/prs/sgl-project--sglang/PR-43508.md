# [diffusion] Run head_dim-128 QK-norm + RoPE two rows per warp for every RoPE layout

[Upstream PR](https://github.com/sgl-project/sglang/pull/43508) · state: closed · merged: True

## Original PR description

## Motivation

#43337 runs the head_dim-128 QK-norm + RoPE kernel two rows per warp: 16 lanes per row, 16-byte loads. That removed a fifth of the kernel's time, but only for MiniMax-H3's configuration, NeoX RoPE with the norm rounded before it and a half-width cache.

Every other head_dim-128 caller kept the one-row-per-warp kernel:

| Callers | RoPE | Norm rounded before RoPE | Cache |
|---|---|---|---|
| FLUX.1/2, Qwen-Image, Z-Image, FLUX 3, Krea2, Joy | interleaved | no (FP32 path) | FP32, half width |
| LongCat | interleaved | yes | full width |
| Ernie-style | NeoX | yes | full width |

## Modifications

- `fused_qknorm_rope_half_warp` now takes the RoPE layout, the rounding mode and the cache width as template parameters. It covers:
  - interleaved RoPE in both rounding modes;
  - NeoX RoPE with the norm rounded;
  - full- and half-width caches;
  - BF16, FP16 and FP32 caches;
  - every rope width that ends on a lane boundary (multiple of 8; of 16 for NeoX).
- Each lane still covers two lanes of the one-row kernel and repeats their arithmetic step for step:
  - the same partial sums and xor butterfly;
  - on the FP32 path, the one-row kernel's pairwise square sums and `x * (norm * w)`;
  - on the rounded path, its per-element sums and `(x * norm) * w`;
  - the same rotary expressions.
- **NeoX on the FP32 path keeps the one-row kernel.** There, nvcc's choice of which product of `e * cos + swapped * sin` to fuse into the FMA depends on the cache dtype. The one-row kernel compiles to `fma(cos, e, sin * swapped)` with an FP32 cache and to `fma(swapped, sin, cos * e)` with a BF16 one. A second kernel cannot be guaranteed to make the same choice, and the first version of this PR did not: about 1 element in 10⁵ differed. No interleaved or rounded path has this ambiguity in either kernel.

## Accuracy Tests

- `test_two_rows_per_warp_match_one_row_per_warp` now covers every layout that runs two rows per warp, against the one-row kernel with `torch.equal`:
  - NeoX and interleaved RoPE;
  - both rounding modes;
  - full- and half-width caches;
  - BF16, FP16 and FP32 caches;
  - rope widths 32 to 128 (including 120);
  - in place and out of place.

  13 passed on B300.
- A wider sweep on B300 compared the two kernels over every combination of rope width (64, 96, 128), layout, rounding mode, cache width and cache dtype, with 6 seeds of 4099 tokens × 8 heads each. Every layout this PR routes to the two-rows kernel matched in all 8.4M elements of every seed. The FP32 NeoX path was the only one that differed, which is why it stays on the one-row kernel.
- These checks ran on sm_103 (B300). The registered test compares the two kernels' bytes the same way on the B200 and H100 CI runners, and a contraction mismatch shows up in the large row count as above.

## Speed Tests and Profiling

In-place kernel time on B300 (triton `do_bench`, median), at each model's 1024² token count, FP32 cache unless noted:

| Config (callers) | one row per warp | two rows per warp |
|---|---:|---:|
| interleaved, FP32 path: FLUX.1/2, FLUX 3, Krea2 (4608 × 24 heads) | 42.0 µs | 33.8 µs (−19.5%) |
| interleaved, FP32 path: Qwen-Image (4352 × 24) | 39.9 µs | 31.7 µs (−20.5%) |
| interleaved, FP32 path: Z-Image (4352 × 30) | 48.0 µs | 37.8 µs (−21.2%) |
