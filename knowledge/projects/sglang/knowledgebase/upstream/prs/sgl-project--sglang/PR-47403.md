# [Fix] speculative: Validate adaptive policy options before startup

[Upstream PR](https://github.com/sgl-project/sglang/pull/47403) · state: closed · merged: False

## Original PR description

## Motivation

An adaptive EMA config with `update_interval: 0` passes startup validation, loads the model, captures CUDA graphs, and then crashes the scheduler with `ZeroDivisionError` when verify feedback reaches the first update. With the default warmup this is the 11th feedback batch. Non-finite EMA options can instead leave the policy stuck with a NaN acceptance estimate.

Reproduced against `ca939407423088dffd33304e0ea7d092cba355d2`. The minimal config is `{"1": {"candidate_steps": [0, 1, 3], "update_interval": 0}}`. The failure is in `AdaptiveStepSlot.update`, reached through the scheduler's verify-result callback.

## Modifications

Validate effective per-batch-size options in `_load_adaptive_config`, which is already called during argument resolution before model initialization. Check integer update/warmup counts, finite policy coefficients, EMA bounds, and JSON object structure; reject booleans in candidate steps. Errors identify the batch-size slot and option. Per-slot overrides continue to take precedence over global defaults, including the supported zero-step candidate and zero warmup.

Add regression coverage for both early candidate resolution and policy construction. Existing valid configurations and runtime selection logic are unchanged.

## Accuracy Tests

- New tests against the unmodified base: 33 tests, with 71 failing subtests and 8 error subtests exposing the missing validation.
- Patched adaptive parameter and runtime-state suite: **38 tests passed**, using `python3 -m unittest discover -s test/registered/unit/spec -p 'test_adaptive*.py'`.
- Real serving repro on **1x GB300**, Qwen3.6-27B native NEXTN/MTP, BF16, TP1, Triton attention, overlap and decode CUDA graphs enabled: with zero interval and zero warmup, the baseline reaches readiness and crashes on the first request with the expected `ZeroDivisionError`; the patch rejects the config before loading weights.
- Valid-config control on the same model/GPU: candidates `[0,1,3]`, `ema_alpha=1`, `update_interval=1`, zero warmup, greedy sampling, seed 42. Two prompts produce 64 tokens each; both **complete output token sequences match** between baseline and patch (128/128 tokens). Both versions report 43 verify rounds per prompt. This is a smoke test, not a held-out accuracy evaluation.

Environment: Python 3.12.15, PyTorch 2.14.1+cu130, Transformers 5.19.0, sglang-kernel 0.4.10, FlashInfer 0.7.0.post1. Valid-config serving controls were run serially in an isolated container.

## Speed Tests and Profiling

No inference-speed claim. Validation runs when loading configuration and adds no work to the decode loop.
