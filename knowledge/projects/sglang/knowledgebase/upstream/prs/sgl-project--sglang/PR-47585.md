# [Fix] [AMD] quark: Widen the Quark MXFP4 W4A16 MoE gate to consumer RDNA and fail clearly without aiter

[Upstream PR](https://github.com/sgl-project/sglang/pull/47585) · state: open · merged: False

## Original PR description

## Motivation

**What goes wrong**
#47408 restricted the Quark MXFP4 W4A16 MoE path to gfx1151. On any other consumer RDNA GPU (gfx11xx, gfx1200, gfx1201) the gate is now false, so `process_weights_after_loading` falls into the AITER branch and calls `e8m0_shuffle`, which is only imported when `_use_aiter` is set. Without aiter the server fails at startup with `NameError: name 'e8m0_shuffle' is not defined`. The same applies to `moe_shuffle_scale` on gfx1250 when aiter is off, and to `SGLANG_ENABLE_QUARK_MXFP4_MOE_W4A16=0`.

**Where it shows up**
Every consumer RDNA GPU other than gfx1151. Reported by @vivienfanghuagood on gfx1201 (RDNA4, 32 GB, ROCm 7.2.3, no aiter): before #47408 the W4A16 path served amd/Qwen3.5-35B-A3B-MXFP4; after it, startup fails with the NameError. gfx942 and gfx1250 (MI455) must keep the AITER path.

**How to fix**
Gate the W4A16 path on consumer RDNA again (`gfx11*` and `gfx120*`, not `gfx12*` because gfx1250 also matches), inlined so this does not depend on #47254. In the non-W4A16 branch, raise a clear "requires aiter" error when `_use_aiter` is false instead of falling through to the NameError.

## Modifications

- `quark_w4a4_mxfp4_moe.py`: replace `_is_gfx1151` with `_is_consumer_rdna = gcnArchName.split(":")[0].startswith(("gfx11", "gfx120"))`; `_use_triton_w4a16` keys on it. gfx1250 and gfx942 stay on AITER.
- `quark_w4a4_mxfp4_moe.py`: `process_weights_after_loading` raises a `RuntimeError` ("requires aiter") at the top of the non-W4A16 branch when `_use_aiter` is false.
- Update the gate comment, the W4A16 `info_once` message, and the `SGLANG_ENABLE_QUARK_MXFP4_MOE_W4A16` comment in `environ.py` so they no longer say gfx1151 only.
- `test_quark_w4a4_mxfp4_moe_w4a16.py`: gate cases gfx1100 / gfx1151 / gfx1200 / gfx1201 on, gfx942 / gfx1250 off, and the env switch off on gfx1151 and gfx1201. The EP, -1 bucket and SwiGLU tests are architecture independent and unchanged.

## Accuracy Tests

The W4A16 compute path is unchanged; only the gate that selects it changes. Measured by @vivienfanghuagood on an equivalent gate (`startswith(("gfx11", "gfx1200", "gfx1201"))`, same behavior as this PR's `("gfx11", "gfx120")` on all current archs), amd/Qwen3.5-35B-A3B-MXFP4, tp=1, `--context-length 8192`, no aiter, Triton 3.7.0 + triton-kernels 1.0.0, sgl-eval gsm8k, 100 questions, thinking off, T=0.7. 100 questions is about +/-5 points of noise.

| GPU | main before #47408 | #47408 | #47408 + gate widening |
|---|---|---|---|
| gfx1201 (RDNA4) | 57% | NameError at startup | 61% |
| gfx1100 (RDNA3) | 55% | NameError at startup | 58% |

The `requires aiter` guard and the exact gate expression in this PR were not run on a GPU by the author.

## Benchmarking and Profiling

Same setup and runs as above, separate server processes (c1 / c8 tok/s):

| GPU | main before #47408 | #47408 | #47408 + gate widening |
|---|---|---|---|
| gfx1201 (RDNA4) | 31.8 / 246.9 | NameError at startup | 31.1 / 237.6 |
| gfx1100 (RDNA3) | 17.0 / 192.4 | NameError at startup | 16.5 / 174.2 |

gfx1100 c8 is 9.5% below the pre-#47408 run, more than the other three deltas (-2% to -4%); whether that is noise or an effect of the #47408 EP changes was not isolated.

Unit tests (#47408's test file plus the new gate cases): 7 passed on both cards, including the two EP cases.
