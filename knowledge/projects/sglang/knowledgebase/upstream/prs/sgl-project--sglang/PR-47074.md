# [Fix] pp: Wait on the forward event when skipping output comm

[Upstream PR](https://github.com/sgl-project/sglang/pull/47074) · state: open · merged: False

## Original PR description

## Motivation

`SGLANG_PP_SKIP_PURE_CHUNKED_OUTPUT_COMM` (#26148) lets the last PP rank skip the output send/recv for a batch that holds a single non-final chunked-prefill request. That output is a placeholder nobody reads. Under PD prefill with chunked prefill, enabling the flag currently corrupts the KV cache that is transferred to decode.

**Root cause.** On the last PP rank, `q_event` marks the end of the batch's forward. The output send is the only place the scheduler stream waits on it: `_pp_send_dict_to_next_stage(..., ready_event=q_event)` calls `current_stream().wait_event(q_event)`. Without `SGLANG_PP_COMM_OVERLAP`, the current stream is the scheduler stream. When the send is skipped, that wait is skipped too:

1. `_pp_make_skip_output_result` records `d2h_event` on the scheduler stream. Nothing orders that stream after the forward, so the event completes at once.
2. The scheduler moves on. In the next iteration, `process_prefill_chunk` calls `send_kv_chunk` for the middle chunk that was just computed. The page-index copy and its ready event are recorded on the scheduler stream, so they do not wait for the forward either.
3. The transfer backend (Mooncake here) starts reading those KV pages while the forward is still writing them, and decode receives partially written KV for that chunk.

Only the last PP rank is affected. Non-last ranks still wait on `launch_event` before sending the proxy, so their scheduler stream stays ordered after their forward.

## Modifications

- `scheduler_pp_mixin.py`, `_pp_send_output_to_next_stage`: when the last rank skips the output send, it still calls `current_stream().wait_event(q_event)`. Only the send is skipped. The non-skip path and prebuilt batches are unchanged.
- `scheduler_pp_mixin.py`, `_pp2_only_send_recv_output_tensors_npu`: the NPU path sends a `__skip__` marker instead of the output and had the same missing wait. The wait now runs before either message is built. I have no NPU hardware, so this part is covered only by the unit test.
- New CPU unit test `test/registered/unit/managers/test_pp_skip_output_comm.py`. It calls the real functions with a mocked stream and checks that the last rank waits on `q_event` exactly once whether or not the output is sent, for both the CUDA and the NPU paths, and that prebuilt batches neither send nor wait. On main, the two skip cases fail (`wait_event` called 0 times); with this PR all cases pass.

With `SGLANG_PP_COMM_OVERLAP=1`, the non-skip send waits on the PP comm stream rather than the scheduler stream. Ordering the scheduler stream after the forward in that mode is a separate issue (see #45524) and is not changed here.

## Accuracy Tests

**End-to-end needle test, PD disaggregation on one 8 × B300 node.**

- Model: Qwen3-30B-A3B-Instruct-2507.
- Prefill: `--pp-size 2 --tp-size 1 --chunked-prefill-size 16384 --disable-radix-cache`, on GPUs 2–3.
- Decode: `--tp-size 1`, on GPU 4.
- Transfer: Mooncake over RDMA. Requests go through `sglang_router --pd-disaggregation --mini-lb`.

The workload has 16 prompts of 43K–112K tokens. Each prompt is Python source code with 8 random 8-digit secret numbers inserted as comment lines. Every secret sits at least two chunks before the end of the prompt, so it lands in a middle (non-final) prefill chunk. Decode is asked to list the secrets with greedy sampling, 128 secrets per run. Corrupted middle-chunk KV shows up as missed secrets. Numerical noise does not flip these answers: with the flag off, every run recalls all 128.

| Code | `SGLANG_PP_SKIP_PURE_CHUNKED_OUTPUT_COMM` | Sequential (concurrency 1) | Concurrency 16 |
|---|---|---|---|
| main | 0 | 128 / 128 | 128 / 128 |
| main | 1 | 0 / 128, 6 / 128, 0 / 128 | 29 / 128, 25 / 128 |
| This PR | 1 | 128 / 128 (3 runs) | 128 / 128 (3 runs) |

On main with the flag on, decode mostly invents numbers (for example `12345678`, `23456789`, ...) or repeats one value, because the needles are no longer in the transferred KV.

**Unit tests:** `test_pp_skip_output_comm.py` (new), `test_pp_output_exchange_order.py`, `test_pp_cp_rank_offsets.py`, `test_pp_comm_overlap.py`, `test_auxiliary_output.py`, `test_batch_result_processor_hidden_states.py`, `test_disagg_idle_step_counters.py`, and `test_forward_pass_metrics.py` pass (111 passed).
