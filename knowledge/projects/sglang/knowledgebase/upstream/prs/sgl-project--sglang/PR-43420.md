# [VLM][MM refactor 1/6] Move multimodal enums to a shared module

[Upstream PR](https://github.com/sgl-project/sglang/pull/43420) · state: open · merged: False

## Original PR description

## Motivation

Modality and MultimodalInputFormat live in managers/schedule_batch.py, so any code that only
needs the enums (for example a trainer-side media processor) has to import the scheduler
module and everything it pulls in.

## Modifications

- Move Modality and MultimodalInputFormat verbatim into sglang/srt/multimodal/modality.py.
  schedule_batch.py re-imports them, so existing `from sglang.srt.managers.schedule_batch
  import Modality` call sites keep working and can migrate incrementally.
- Add ("sglang.srt.multimodal.modality", "Modality") to SafeUnpickler.ALLOWED_GLOBALS, since
  Modality now pickles under its new module. The schedule_batch entry stays, so payloads from
  encoders built before this change still load on an upgraded receiver during a rolling
  upgrade.

The move pays off later in this stack: media_processor.py and token_space/process_strategy.py
import Modality from sglang.srt.multimodal.modality, and importing media_processor (the
trainer-side entry point) does not load sglang.srt.managers.schedule_batch.

## Review guide

- `refactor(move): relocate multimodal enums` is mechanical and comes with a reproducible
  proof: replaying the recorded move on the parent commit gives the commit's tree exactly.
- Enum values, Modality.all() and from_str are unchanged. Pinning explicit member values and
  the related cleanups are left for a separate PR.

## Tests

- test_safe_unpickler.py::test_modality_loads_from_its_current_and_pre_move_paths: a payload
  pickled under the current module and one pickled under the pre-move schedule_batch path both
  load as the same Modality member through safe_pickle_loads.
- test_encode_server.py::test_grid_metadata_is_safe_to_deserialize (existing) round-trips
  EmbeddingData carrying a Modality through safe_pickle_loads.
