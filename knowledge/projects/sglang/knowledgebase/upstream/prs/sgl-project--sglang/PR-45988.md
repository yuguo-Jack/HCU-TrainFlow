# [Fix] dsa: Isolate masked KV rows in FP8 TileLang attention

[Upstream PR](https://github.com/sgl-project/sglang/pull/45988) · state: open · merged: False

## Original PR description

## Motivation

Invalid (`-1`) sparse indices in `sparse_mla_fwd_decode_partial_fp8` map to KV row 0. Masking the attention score does not isolate that row: a NaN in it can propagate through both QK (`-inf + NaN`) and PV (`0 * NaN`), corrupting otherwise valid outputs and generation logprobs.

This was reproduced on GLM-5.3-Flash with FP8 KV and TileLang DSA on H20, with both PP1 and PP2, including a plain-main deployment without EPLB. A direct operator reproduction changed only padding KV row 0 from zero to NaN and changed the output from finite to 196608 NaN elements. This is a correctness fix; it does not require changing the deployment's CUDA Graph, overlap, or speculative decoding settings.

Related prior work: #44541 applies the same masked-load isolation to the BF16 kernel and explicitly leaves the FP8 kernel unchanged. This PR covers that FP8 gap. #36207 tracks producer-side writes to reserved KV row 0; this consumer-side fix does not depend on row 0 remaining finite and does not claim to resolve every writer path. The FlashInfer masked-gather fix discussed in #42440 concerns a different backend.

## Modifications

- Zero invalid KV rows before the FP8 kernel's QK and PV matrix multiplications, including the optional RoPE tail. Keep the existing score mask and valid KV values unchanged.
- Add poisoned-padding regressions for 256+0, 512+0, and 512+64 geometries, eager and CUDA Graph execution, and all-masked outputs remaining zero.

GPU results were collected on base `8d8916815b9f2717a34dac16190157189e54fb57` plus fix `985608ef7795830643a2fa74f5f287c286640643`. The delivery branch merges main `3f36fc08331f64cd63c4fbbdf39cc402f38bb38b`; both modified files are byte-identical to those GPU-tested files, and both corresponding pre-fix files are unchanged between the two main snapshots. GPU tests and the full service were not rerun on the refreshed base. This is a small quality check, not a full-model accuracy evaluation. AMD and other hardware are unvalidated for this FP8 change.

Reproduce in an installed SGLang GPU environment:

```bash
PYTHONPATH=python python -m pytest -q test/registered/kernels/ops/attention/test_tilelang_dsa_zero_rope.py
```

The initial runtime write that made row 0 non-finite was not captured. The deterministic masked-index defect and the only-kernel-change recovery are confirmed; allocator initialization is not claimed as the cause.

## Performance

No speedup is claimed. This restores correct outputs, so the incorrect-output deployment is not a performance baseline. End-to-end automatic-EPLB performance measurement is a separate, incomplete validation effort.
