# [Perf] [NVIDIA] moe: Release localized Mega MoE originals so KV capacity matches non-localized

[Upstream PR](https://github.com/sgl-project/sglang/pull/48099) · state: closed · merged: True

## Original PR description

## Motivation

With `SGLANG_OPT_DEEPGEMM_MEGA_MOE_LOCALIZE=1` (#47976), DeepSeek-V4.1-Flash loads 1.5 GB more weight memory (89.18 vs 87.65 GB) and gets 1.47% fewer KV tokens, although the routed experts keep a single copy.

A memory snapshot at the end of loading shows where it goes:
- `build_mega_moe_experts_weights` interleaves the L1 weight (a 1.05 GiB temporary) before it interleaves the L1 scale and builds both UTCCP scales. Those scale tensors are carved out of the freed temporary's segment and keep it reserved: one 1080 MiB segment is left with 877.5 MiB free, held by four scale tensors. The non-localized path has the same hole, but the fused shared expert's interleaved L1 copies (40 × 22.5 MiB, built later) fill it. With localization those copies move into locality-domain memory, so the hole stays.
- The fused shared expert's L2 is held twice: `deep_gemm.localize` copies it and `down_proj.weight` keeps the original.

## Modifications

- `build_mega_moe_experts_weights`: builds the scales before the L1 weight interleave. When localized, frees the replaced weights and calls `torch.cuda.empty_cache()` per layer, so the next layer's scales do not land in them.
- `build_mega_moe_shared_weights`: when localized, frees the shared expert's `gate_up_proj` / `down_proj` weights (localized weights have no non-mega fallback) and calls `torch.cuda.empty_cache()`.
- `autotune_prefill_kernels`: skips linears whose weight was freed.

## Memory and accuracy

DeepSeek-V4.1-Flash, one node, DP-attention 4 / EP 4, `--moe-a2a-backend megamoe`, DSPARK, `--mem-fraction-static 0.76`, sgl-deep-gemm v0.2.5.post3 built with CUDA 13.4, `SGLANG_OPT_DEEPGEMM_MEGA_MOE_NUM_MAX_TOKENS_PER_RANK=16384`. Rank 0. Measured on the #47976 branch plus this commit (the code this PR touches is unchanged on main).

| | Localize | Weights (GB) | Draft weights (GB) | Available before KV pool (GB) | KV tokens | GSM8K (200) |
|---|---|---|---|---|---|---|
| main | off | 87.65 | 2.66 | 179.58 | 98,056,960 | 0.995 |
| main | on | 89.18 | 2.85 | 178.36 | 96,620,032 | 0.990 |
| this PR | off | 87.45 | 2.67 | 179.77 | 98,282,240 | 0.995 |
| this PR | on | 88.06 | 2.14 | 179.69 | 98,187,776 | 0.995 |
| this PR | on, EPLB (32 redundant experts, rebalance every 100 iterations, `SGLANG_EXPERT_LOCATION_UPDATER_CANARY=1`) | 101.68 | 1.65 | 165.26 | 81,701,888 (main: 80,294,912) | 1.000, 12 rebalances |

Localized KV capacity goes from -1.47% to -0.10% of non-localized. The reordering also helps the non-localized path (+0.23% KV tokens).

What remains: the freed shared-expert originals sit in loader segments shared with live weights, so only part of them returns to the driver (the draft model reuses some of it). Allocating them in their own segments would need a loader change.
