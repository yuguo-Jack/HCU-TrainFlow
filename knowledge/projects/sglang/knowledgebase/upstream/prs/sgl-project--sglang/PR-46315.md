# [Feat] weight-cache: Add --weight-cache-max-bytes to the daemon

[Upstream PR](https://github.com/sgl-project/sglang/pull/46315) · state: open · merged: False

## Original PR description

## Motivation

Part of #33522 (fast recovery: `--weight-cache-max-bytes`, refcount-aware eviction, admission check). This PR adds the byte cap and the admission check; eviction is left out for a reason explained below.

## Modifications

- New `--weight-cache-max-bytes` (model arg group, `field_order`, docs). Unset keeps the current behavior.
- Before loading, the daemon estimates the checkpoint size from safetensors headers (using the index when present, falling back to file size) and refuses to start if it's over the cap, so nothing is allocated. After loading, the measured weight bytes are checked again.
- With the cap set, weights that don't fit the `--mem-fraction-static` budget are refused too.

## Why no eviction yet

I implemented in-process eviction (client PID tracking, refuse while clients are alive, unload otherwise) and tested it on an RTX 3090, but it can't actually free memory: once the weights are exported over CUDA IPC (`torch_ipc` transport), the storage stays pinned in the daemon. `gc.collect()`, `torch.cuda.empty_cache()` and `torch.cuda.ipc_collect()` all leave it in place (1310 MiB before and after), even in a single process where nothing ever imported the handles; only stopping the daemon returns it. So refcount-aware eviction probably means restarting the daemon process, or building on the `vmm_fd` transport. Which direction would you prefer? Happy to do that as a follow-up.

## Accuracy / tests

CPU: `pytest test/registered/unit/model_loader/test_weight_cache_protocol.py test/registered/unit/model_loader/test_weight_cache_max_bytes.py` → 48 passed. The new tests cover the estimate (headers, index, file-size fallback, no local files), refusing before load, the post-load check, and the unset path.

RTX 3090, Qwen2.5-0.5B-Instruct (weights ~988 MB), TP1:

| cap | result | GPU memory |
|---|---|---|
| unset | serves, HTTP 200 | 4 → 1310 → 18233 (with engine) → 1310 → 4 MiB |
| 300 MiB | refused before loading, exit 1 after 7 s | stays at 4 MiB |
| 8 GiB | serves, HTTP 200 | same as unset |

The estimate was 988,065,536 bytes vs 1,048,576,000 measured after load. It counts the whole checkpoint, so it's conservative for TP>1, and an uncached Hub model can only be checked after loading.
