# [DSv4.1] Support SM90 candidate indexers

[Upstream PR](https://github.com/sgl-project/sglang/pull/40860) · state: open · merged: False

## Original PR description

## Motivation

Enable candidate-only indexer scoring on SM90 for DeepSeek-V4.1, following #40574.

The current protocol already publishes compact candidate block IDs, but Hopper consumers still traverse the full logical score space before selecting among the candidates. This PR uses those block IDs during scoring, so consumers produce compact scores directly instead of a context-width score matrix.

The Triton implementation reads candidate K positions directly, avoiding a per-query `[queries, candidates, head_dim]` K tensor.

## Modifications

- Reuse the existing `DenseBlocksBackend`, `BlockIds`, and `publish_*` / `consume_*` interfaces.
- **Prefill:** score candidate positions directly from shared BF16 index K with Triton. Per-request K retrieval/dequantization remains unchanged; no per-query candidate K tensor is materialized. Retain the independent Torch reference and fallback for unsupported shapes.
- **Decode/verify:** add `fp4_index_logits_candidates`, reusing the upstream FP4 scoring tile. Address candidate K through the request-to-token table without constructing a context-sized slot map or candidate mask for compact consumers.
- **Selection:** keep scores compact through ragged/paged Top-K v2. Reuse `finish_paged_indexer_topk` for compact-to-logical mapping, invalid-position filtering, sorting, and output mapping. Preserve causal bounds, padding, and prefill tail slicing.
- **CUDA graphs:** enable the existing length-based variants on SM90: four for ordinary decode and two for DSPARK target verify.
- Preserve upstream source-layer scoring, the FullTopK DeepSelect path, 128B paged-score row alignment, and conditional Top-K v2 plan generation. SM100 backend selection remains unchanged.

## Speed Tests and Profiling

Same model and 1P1D hardware configuration as above.

### Prefill TTFT

D is fixed; only P switches between A/B. Chunked prefill=1024, BS1, OSL1, fixed input IDs and cache flushes. Values below are mean streaming TTFT from three measured requests per length after warmup.

| ISL | Baseline TTFT (s) | Candidate TTFT (s) | Reduction |
|---|---:|---:|---:|
| 32K | 6.101 | 5.790 | 5.09% |
| 64K | 13.910 | 12.234 | 12.05% |
| 128K | 34.299 | 27.209 | 20.67% |
| 256K | 100.155 | 72.486 | 27.63% |

16K was effectively unchanged in a dedicated repeat check: 3.345 s baseline versus 3.359 s candidate.

### DSPARK decode/verify

P is fixed; only D switches between A/B. DSPARK block5, full CUDA graphs, steady-state BS8.

| ISL | Baseline throughput (tok/s) | Candidate throughput (tok/s) | Throughput gain | Baseline effective TPOT (ms) | Candidate effective TPOT (ms) |
|---|---:|---:|---:|---:|---:|
| 16K | 1427.71 | 1543.44 | 8.11% | 5.607 | 5.191 |
| 32K | 1358.83 | 1528.88 | 12.51% | 5.888 | 5.234 |
| 64K | 1193.78 | 1411.98 | 18.28% | 6.704 | 5.667 |
| 128K | 523.30 | 680.07 | 29.96% | 15.454 | 12.027 |
