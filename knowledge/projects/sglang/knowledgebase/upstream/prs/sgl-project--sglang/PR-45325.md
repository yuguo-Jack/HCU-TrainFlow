# [Feat] hicache: Align LayerSplit CP shards with unified L3 layer chunks

[Upstream PR](https://github.com/sgl-project/sglang/pull/45325) · state: open · merged: False

## Original PR description

Part of #44635.

## Motivation

First step of the LayerSplit part of #44635: let `--enable-dsa-cache-layer-split` CP ranks derive unified L3 keys (`--hicache-storage-key-scheme unified`).

Under LayerSplit each CP rank owns a contiguous range of layers for every token, so from the storage point of view it is a PP stage, not the full-page CP that #39728 handles by electing CP rank 0. Two things stand in the way today:

- The even split does not land on the L3 layer grid. 78 layers over CP8 split as 10 × 6 + 9 × 2, so a rank starts at layer 69, and `_layer_chunks` refuses any `--hicache-storage-layer-partition` other than 1.
- The controller keys every rank by the full model range and elects a single CP writer, which would drop the layers the other ranks own.

## Modifications

- `layers/cp/utils.py`: `get_layer_shard_range` / `get_layer_owner` take `chunk_layers` (default 1, which is exactly today's split). Layers are cut into chunks and whole chunks are dealt out evenly; with P = 10, 78 layers over CP8 become `[0, 10) … [60, 70), [70, 78)`. `validate_layer_shard_chunk` refuses a chunk size that would give any rank more than the `ceil(layers / ranks)` layers the device and host pools are sized for, so pool sizing is unchanged.
- `get_glm_dsa_layer_shard_chunk()` takes the chunk from `--hicache-storage-layer-partition` when the unified scheme is on, else 1. `LayerSplitDSATokenToKVPool` stores it, validates it before allocating, and exposes `layer_shard_end` next to `layer_shard_start`. The indexer sizing loop in `pool_configurator.py` uses the same chunk.
- `HiCacheController`:
  - `_unified_layer_range` keys a LayerSplit rank by its owned absolute range; only the range ending at the model's last layer may end short.
  - `_generate_storage_config` sets the new `HiCacheStorageConfig.layer_split_attn_tp_rank` for a unified LayerSplit rank. `is_storage_writer` then makes every LayerSplit CP rank a writer, and only attention-TP replicas skip. The rule lives in the config because `backup_skip` and the file backend's evictor both read it, and it uses the attention-TP rank because `tp_rank` spans the whole CP x attention-TP grid without DP attention.
  - LayerSplit configurations where some rank owns fewer layers than its host block holds (e.g. 78 over CP8) are refused on every rank alike, so the attach decision cannot diverge across ranks. Unified chunk spans must cover the whole page, so such a rank would otherwise fail on its own while the others attach.

## Not in this PR

- The DSA indexer component. `_build_unified_suffixes` still refuses composite pools, so a real LayerSplit (DSA) deployment is refused before reaching the new path. That is the next PR in #44635.
- `page_unified` per-layer write-back for layer-sharded host pools.
- Mooncake: unified keys still accept only the `file` backend; Mooncake support is in progress separately.

## Accuracy Tests

No numerics change. The default chunk is 1, which reproduces the existing split exactly; the chunked split only applies under `--hicache-storage-key-scheme unified` with a layer partition, and that path is refused for DSA until the indexer PR lands.

## Speed Tests and Profiling

N/A: no hot-path change.

## Tests

`test/registered/unit/mem_cache/test_dsa_layer_shard_utils.py` and `test_hicache_unified_key_scheme.py` (CPU):

- Chunked ranges for 78 layers over CP8 at P = 10 start on the grid, and owners match.
- A chunk size that would grow a rank past its pool capacity is refused.
- CP8 LayerSplit ranks' chunks, taken together, equal a DP reader's chunks on the same grid (80 layers, P = 10).
- A padded LayerSplit configuration is refused on every rank, not only the short one.
- Every LayerSplit CP rank writes under unified keys; attention-TP replicas skip.

Each new case was checked to fail when the behavior it guards is reverted. Locally on CPU: 35 passed in the two touched test files. No GPU or end-to-end run, since DSA deployments are still refused before this path.
