# [Fix] [AMD] qwen3: Guard dtype alignment when fused decode omits KV

[Upstream PR](https://github.com/sgl-project/sglang/pull/47926) · state: closed · merged: True

## Original PR description

## Problem

Since the October 31 rebase of `sglang-miles`, dense Qwen3 decode on ROCm crashes while the server captures its decode CUDA graphs:

```text
  File "/sgl-workspace/sglang/python/sglang/srt/models/qwen3.py", line 364, in forward
    if should_force_bfloat16_dense_tensor_math() or q.dtype != v.dtype:
AttributeError: 'NoneType' object has no attribute 'dtype'
```

The AITER fused decode path from #44267 writes K/V straight into the KV cache and returns `v=None`. The true-on-policy commit on this branch ([1/76], 41d9f48) also compares `q.dtype != v.dtype` when true on-policy is off, so ordinary decode now reads `v.dtype`. `main` casts only under true on-policy and is not affected.

The server exits during startup, so each affected test waits about 30 minutes for its timeout instead of failing fast. In the [November 1 ROCm 10 nightly](https://github.com/sgl-project/sglang/actions/runs/41355785159), ten tests that passed in the [October 31 nightly](https://github.com/sgl-project/sglang/actions/runs/41246952254) crashed this way. The timeouts also pushed four of the five jobs past their 180-minute limit, so 45 more tests that passed on October 31 never started (three of those jobs also had unrelated DeepSeek-V4 failures).

## Change

Only align Q/K to V when V exists. The fused path has already written K/V to the cache and passes `save_kv_cache=False`, so there is nothing to align, the same as on `main`. Non-fused decode keeps the existing condition, and so does true on-policy, whose contract disables the fused path.

## Validation

On MI350X with the November 1 ROCm 10 nightly image and only this file changed:

- `test_chat_input_ids_equivalence.py` passed (42 s); it failed in 35 s in the nightly.
- `test_qwen3_0_6b_lora_native_ci.py` passed (284 s): TP2 with sequence parallelism, two rollout/train/adapter-sync rounds with the existing checkers, and all 52 decode graphs captured.
- `test_qwen3_aiter_fused_qk_norm_rope.py` passed (3 tests, 16 subtests) once the runtime context is initialized. Run bare, it fails before reaching this code, identically with and without this change.

A CPU run of the original `forward` over 16 mode, TP and RoPE combinations reproduced the four fused-decode crashes. With the fix all 16 pass, and the other 12 keep the same calls and outputs.
