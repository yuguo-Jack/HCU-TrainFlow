# [Fix] responses: fix reasoning.effort in non-streaming responses and max_output_tokens=1 validation

## Summary

 Two independent bugs on `/v1/responses`:

 ###  1. `reasoning.effort` echoed as `null` in the response

 ```json
  curl -X POST http://<server>/v1/responses \
    -H "Content-Type: application/json" \
    -d '{"model": "...", "input": "hi", "stream": false, "reasoning": {"effort": "max"}}' 
```

  The response carried "reasoning": {"effort": null, ...} even though the tier was accepted and applied to generation.   OpenAI's API echoes the requested tier back, so clients that round-trip the response (e.g. agents replaying previous_response_id payloads) see a setting that silently differs from what they asked for.

  Root cause: ResponsesResponse.from_request masked the effort through ECHOABLE_REASONING_EFFORTS ({minimal, low, medium, high}). That mask exists to protect the non-harmony streaming path only: the typed OpenAI SDK stream events (ResponseCreatedEvent, ResponseCompletedEvent, ...) validate the embedded response against the SDK's narrower Reasoning.effort literal, and echoing none/xhigh/max there raises a pydantic ValidationError that kills the stream before the first SSE byte. But the mask lived in from_request, which is shared by the non-streaming path and the harmony streaming path (whose events are plain dicts with no such validation) — so responses that could safely echo the real tier returned null instead.

  ###  2. "max_output_tokens": 1 rejected with HTTP 400

  ResponsesRequest.to_sampling_params subtracted the 2-token BOS/EOS headroom unconditionally, so an explicit max_output_tokens=1 became max_new_tokens=-1, which fails SamplingParams validation (max_new_tokens must be at least 0, got -1.) and surfaces as a 400. The headroom only makes sense for the server-derived default budget, not for a cap the client asked for explicitly.

## Modifications

  - protocol.py (ResponsesResponse.from_request): echo request.reasoning.effort verbatim instead of filtering it through the echoable set.
  - serving_responses.py: hoist the stream-event sanitizer to module level (_sanitize_response_dict) and extend it to also mask reasoning.effort to None when the tier is outside the SDK-echoable set. It is applied only in the non-harmony streaming path (response.created, response.in_progress, terminal events, response.failed), where the SDK validation lives. Non-streaming responses and harmony streaming events now echo the requested tier as-is.
  - protocol.py (ResponsesRequest.to_sampling_params): apply the BOS/EOS  headroom (-= 2) only to the default budget derived when max_output_tokens is unset; an explicit max_output_tokens is passed through as-is.
  - Updated test_responses_protocol.py accordingly (see below).
