# [Perf] [NVIDIA] dsv41: Split small-batch decode mHC post-combine-norm rows over a CTA cluster

[Upstream PR](https://github.com/sgl-project/sglang/pull/47949) · state: closed · merged: True

## Original PR description

## Motivation

Follow-up to #46088. The fused decode mHC post + combine + RMSNorm kernel runs one CTA per row, so each row's ~50 KB of stores (4×5120 bf16 residual + normed output) drains through a single SM at ~32 B/cycle — ≥0.8 µs on its own — and the norm weight is only loaded after the RMS barrier. At decode batch sizes that are a fraction of the SM count this leaves most of the GPU idle.

## Modifications

- **Cluster split.** The kernel is now templated on `Split`. With `Split > 1` the grid is `(Split, rows)` with cluster dims `(Split, 1, 1)`, and each CTA handles `640/Split` vectors of the row. Each warp `st.async`s its partial sum of squares into every peer's 20-float shared pool, tracked by the peer's mbarrier (`expect_tx`), same idiom as `softmax.cuh`. Every warp reduces the pool in the same order, so `inv_rms` is bit-identical across the cluster.
- **Unsplit rows** keep the 1-D `(rows)` grid and use one `__syncthreads` instead of two.
- **Weight prefetch** before the RMS barrier, only where `Split > 1 || kVPT == 1` — doing it everywhere raised 160-thread registers 48 → 64 (8 → 6 CTAs/SM) and slowed large m by 16–82%.
- **Config pick** (`_pick_config`):
  - m ≤ 128: 4 × 160 threads, or 5 × 128 with MXFP8 output
  - #SMs < m ≤ 640: 2 × 160 threads
  - otherwise: the existing fewest-waves pick, unsplit

  Splits stop there because cluster launch cost grows with the grid (an empty 4-CTA-cluster grid at m=1024 costs 3.1 µs vs 1.0 µs unclustered), and past 640 rows the 2-CTA split no longer wins reliably.
- SM count comes from the existing `get_device_core_count`, cached.
- `CHECK_HOST(rows <= 65535)` for split configs, since rows go in `grid.y` there.
- Test: added the new config boundaries (128/129, #SMs/#SMs+1, 640/641) to the transition rows.

## Accuracy Tests

- `test/registered/kernels/ops/layernorm/test_mhc_post_combine_norm_decode.py`: 4/4 pass on B300.
- Standalone check over m ∈ {1..1024 sweep, 3, 127, 129, 1023}, every config: updated residual bitwise-equal to `mhc_post_split_h`; normed row within 1e-2 of `hc_combine_norm`; MXFP8 values and scales bitwise-equal to flashinfer's quantize of the normed row; repeated runs bit-identical.
- SASS: no generic `LD.E`, no stack, all global access `LDG`/`STG`.
- No end-to-end model accuracy run yet (see below).
