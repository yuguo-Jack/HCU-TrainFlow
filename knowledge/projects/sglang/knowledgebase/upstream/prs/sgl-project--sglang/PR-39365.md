# [Perf] dsv4: read only the shards holding the DSPARK draft head

[Upstream PR](https://github.com/sgl-project/sglang/pull/39365) · state: open · merged: False

## Original PR description

## Motivation

The DSPARK draft head is packed into the target's checkpoint, and
`speculative_draft_model_path` defaults to `--model-path`, so the draft's
`ModelRunner` resolves to the same safetensors set as the target.

`_remap_dspark_weight_name` drops every tensor whose name does not start with
`mtp.`, but the drop happens after the read. The multi-threaded safetensors
iterator materializes a whole shard with
`{k: f.get_tensor(k) for k in f.keys()}` before yielding, so each rank streams
the entire target checkpoint a second time to keep a small slice of it.

On `deepseek-ai/DeepSeek-V4-Flash-0731`:

```
total tensors 72317, files 48
files containing mtp.*: 3   (model-000{46,47,48}-of-00048)
total 155.4 GB, mtp-bearing shards 10.1 GB
```

## Modifications

- `filter_safetensors_files_by_weight_prefix` in `weight_utils.py`: given a set
  of checkpoint name prefixes, keep only the shards that the safetensors index
  says hold at least one matching tensor. Returns the input unchanged when the
  index is absent, when no indexed tensor matches, or when the filter would
  leave nothing, so an unindexed or differently-packed checkpoint keeps loading
  whole.
- A `weight_prefixes` field on `DefaultModelLoader.Source`, populated from an
  optional `checkpoint_weight_prefixes` model attribute the same way
  `allow_patterns_overrides` already is, and threaded into `_prepare_weights`.
  No-op for every model that does not declare it.
- `DeepseekV4ForCausalLMDSpark.checkpoint_weight_prefixes = ("mtp.",)`. Both the
  CUDA and the NPU remap return `None` for anything outside that prefix, and the
  NPU vocab modules come from `mtp.<stage>.embed.weight` /
  `mtp.<stage>.head.weight`, so the prefix covers both paths.
- `_assert_draft_body_loaded`: raise if any `stages.*` or `markov_head.*`
  parameter never received a checkpoint tensor. The existing completeness check
  only covered `confidence_head.*`, so a dropped shard would otherwise leave a
  parameter at its uninitialized value, which costs acceptance rate and raises
  nothing. The vocab modules are excluded because they exist only under
  `uses_own_vocab_modules` and a checkpoint may legitimately omit them.

## Accuracy Tests

DeepSeek-V4-Flash-0731 with DSPARK, 4 fixed prompts, temperature 0, 128 tokens.
Output text is identical before and after. Text alone proves little here, since
verification corrects a bad draft, so the check that matters is that
`spec_accept_length` and `spec_verify_ct` are equal per request, which they are:

```
SAME  accept 2.667 vs 2.667   verify 48 vs 48
SAME  accept 3.048 vs 3.048   verify 42 vs 42
SAME  accept 4.129 vs 4.129   verify 31 vs 31
SAME  accept 2.370 vs 2.370   verify 54 vs 54
```

New unit tests in `test/registered/unit/model_loader/test_weight_utils.py` cover
the filter and its three degradation paths (no index, prefix absent from the
index, no prefixes declared). Suite goes 157 -> 162 passed, 57 subtests
unchanged.

## Speed Tests and Profiling

`Load weight end` for the draft worker, `deepseek-ai/DeepSeek-V4-Flash-0731`:

| | before | after |
|---|---|---|
| 4x GB300 TP4, cold page cache | 5.4 s | 2.9 s |
| 4x GB300 TP4, warm page cache | 6.2 s | 2.6 s |

The saving is small here and that is expected: the test machines have enough RAM
to hold the whole checkpoint in page cache after the target's pass, so the
second read is memory bandwidth rather than disk. The read it removes is a full
one per rank, so the gain scales with how badly the checkpoint fits in host RAM
(larger variants, higher TP, smaller hosts). Please do not read the seconds
above as the general number.

## Notes for reviewers

Draft, and this one has the most to check of the three:

- **`_assert_draft_body_loaded` has not been exercised by a real load.** It was
  added after the GPU runs above, in response to review feedback that the filter
  needed a guard. The accuracy run is strong evidence that nothing is missing on
  this checkpoint, but the assert itself is a new hard failure on the default
  DSPARK path and wants one real load before this leaves draft. A CI job that
  serves a DSPARK model would settle it.
- **The prefix tuple and the remap must stay in sync, and nothing enforces it.**
  If a future remap starts consuming a name outside `mtp.`, the assert is what
  catches it, which is the whole reason it is here. A reviewer who prefers
  deriving the prefixes from the remap rather than declaring them would get a
  stronger invariant; I did not see a clean way to do that.
- **NPU is reasoned about, not tested.** The argument is in Modifications above.
- **EAGLE / NextN is deliberately not touched.** `DeepseekV4ForCausalLMNextN`
  reuses the target checkpoint the same way, but it also consumes `embed.`,
  `head.` and `norm.weight`, and I had no checkpoint for that variant to verify
  the prefix set against. An untested weight filter fails silently, so it is out
  of scope here.
- `_prepare_weights` is on every model's load path. The change is inert unless a
  model declares the attribute, but the blast radius is the reason to look.
