# [Fix] speculative: Align all spec workers on the scheduler-facing forward_batch_generation signature

[Upstream PR](https://github.com/sgl-project/sglang/pull/47883) · state: open · merged: False

## Original PR description

## Motivation

Fixes #40155.

The non-overlap scheduler path always calls the spec worker through `forward_batch_generation(batch, pp_proxy_tensors=pp_proxy_tensors)` (`scheduler.py` passes the keyword unconditionally), but the spec-v2 workers drifted apart on this signature and nothing enforced it — `BaseSpecWorker` never declared the method. Each drift only surfaced at the first request as `TypeError: ... got an unexpected keyword argument 'pp_proxy_tensors'`.

**Audit of current main** (the issue's table is from September; two entries were fixed since):

| Worker | `pp_proxy_tensors` |
|---|---|
| `eagle_worker_v2` | ✅ |
| `dflash_worker_v2` | ✅ |
| `ngram_worker` | ✅ |
| `dspark_worker_v2` | ✅ (already fixed on main, #39262) |
| `multi_layer_eagle_worker_v2` | ✅ (fixed inline in #29189) |
| `frozen_kv_mtp_worker_v2` | ❌ **still broken on main** |
| `uno_worker_v2` | ❌ **still broken on main** |

**Relationship to #44211:** that PR was closed unmerged along with all other PRs from its account (closed for a spam pattern of 37 near-duplicate PRs, not for technical reasons). The underlying signature divergence is still unfixed on main, verified today — any FROZEN-KV-MTP or UNO run through the non-overlap path still dies with the TypeError above. This is a fresh, tested take.

## Modifications

- **`frozen_kv_mtp_worker_v2.py`** — accept `pp_proxy_tensors` and forward it to the target prefill call and to `self.verify(...)`, exactly matching the `EAGLEWorkerV2` path this worker mirrors and inherits from.
- **`uno_worker_v2.py`** — accept `pp_proxy_tensors`; when it is not None (i.e. pipeline parallelism is active), raise `NotImplementedError`. UNO drives the target model runner directly and never forwards inter-stage proxy tensors, so silently swallowing them — the `del grammar_barrier` treatment — would corrupt a PP run instead of failing. A loud refusal matches the worker's existing style of explicit `NotImplementedError`s for unsupported features.
- **`base_spec_worker.py`** — declare `forward_batch_generation` as an `@abstractmethod` with the full scheduler-facing signature, so the next worker that forgets it fails at instantiation (import time) instead of at the first request.

## Regression Tests

New `test/registered/unit/speculative/test_spec_worker_interface.py`:

- walks every concrete `BaseSpecWorker` subclass (all **7** worker families on main are enumerated: EAGLE, DFlash, NGRAM, DSpark, multi-layer EAGLE, FrozenKVMTP, UNO) and fails if any concrete worker's `forward_batch_generation` cannot accept `pp_proxy_tensors` as a keyword;
- asserts the base-class declaration stays abstract with `batch`/`pp_proxy_tensors` in the signature;
- pins the known worker families so the walk cannot silently miss a module.

**Verified the test bites:** with the worker fixes stashed (test kept), 2 of 3 tests fail exactly on the frozen/uno gaps; with the fixes, 3/3 pass.
