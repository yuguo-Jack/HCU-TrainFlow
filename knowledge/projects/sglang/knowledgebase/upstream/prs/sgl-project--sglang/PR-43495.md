# [diffusion] comfyui: fail early instead of silently dropping features in SGLD integrated mode

[Upstream PR](https://github.com/sgl-project/sglang/pull/43495) · state: closed · merged: True

## Original PR description

## Motivation

In ComfyUI integrated mode the SGLD worker runs the DiT and owns its weights. The
diffusion model that ComfyUI holds is only an architecture companion. As a result,
several ComfyUI features either had no effect while the run still succeeded, or failed
late with an unrelated error:

- **Silently ignored:**
  - ControlNet, attention-backend patches and `weight_dtype=fp8` produced output bit-identical to the plain model.
  - With chained `SGLDLoraLoader` nodes, only the last LoRA stayed active.
  - The LoRA applied at sampling time came from whichever loader node ran last.
- **Late or misleading errors:**
  - The stock `LoraLoader` crashed with `RecursionError`.
  - An attention backend missing in this environment failed after the model loaded, or ran as another backend.
  - `dp_size > 1`, or a GPU layout that leaves a GPU unused, failed or hung at worker startup.
  - A worker error reply surfaced as an unrelated adapter `TypeError`.

This PR fixes these in the ComfyUI plugin only. No file under `runtime/` changes.

Fixes #43184. It includes #43186 by @OnePunchMonk, with authorship kept, because the LoRA binding below builds on it.

## Changes

**Fail in the loader node, before the worker starts** (`core/preflight.py`, `core/generator.py`)
- Attention backends, including per-component ones, are checked with SGLang's own backend resolution, which gives the same answer the worker would. SageAttention 2/3 come with install hints.
- `dp_size > 1` is rejected, because ComfyUI runs one prompt at a time. So is `num_gpus != tp_size * sp_degree * cfg_parallel` when the degrees are explicit.
- `SGLDUNETLoader weight_dtype` must be `default`; the worker loads its own weights and ignores it.
- A worker that exits while loading, or replies with an error, surfaces its real message.

**Reject what the worker cannot apply** (`executors/base.py`, `executors/adapter.py`)
- ComfyUI model patches (ControlNet block patches, attention overrides, block patches) are rejected with the patch names.
- `control` (ControlNet residuals) and `ref_latents` (reference latents) are rejected for adapters that do not forward them. Each adapter declares what it forwards in `applied_conditioning`; today only Qwen-Image-Edit forwards `ref_latents`.
- MiniMax H3 latents with batch size > 1 are rejected, with the same message as ComfyUI's own H3 model.

**LoRA** (`nodes.py`, `executors/base.py`, `core/model_patcher.py`)
- `SGLDLoraLoader` returns the patched clone. The LoRA set is applied from the MODEL the sampler received, at sampling time; the worker unmerges before applying a changed set. SGLD clones keep their parent link.
- The stock `LoraLoader` / `ModelSave` / merge nodes now get a clear error that points at `SGLDLoraLoader`.
  - The executor no longer registers the `BaseModel` as a submodule; that cycle caused the `RecursionError`.
  - `state_dict()` raises, because without it the stock LoRA would only log "lora key not loaded" and apply nothing.
- Chaining `target="all"` with a named target is rejected; the worker would keep only one of the two LoRAs.

## Test plan

**Unit:** `pytest python/sglang/multimodal_gen/test/unit/test_comfyui_*.py` reports 89 passed. Every new regression test fails on the pre-fix code, and every commit passes its tests and `pre-commit` on its own.

**End-to-end on H200:** MiniMax H3 single file, 864x480, 33 frames. ComfyUI loads only this plugin tree, and the worker imports the same tree.

| Workflow | Result |
|---|---|
| t2v; one `SGLDLoraLoader`; two LoRAs on a BF16 checkpoint; `CFGGuider` cfg=3 | completes |
| Stock `LoraLoaderModelOnly` | clear error (before: `RecursionError`) |
| Two LoRAs on an INT8 checkpoint (dynamic LoRA) | the worker's "only one adapter per target" error |
| LoRA targets `all` + `transformer` | rejected at the LoRA node |
| `sage_attn_3` on Hopper; `dp_size=2`; `num_gpus=2` with `tp=sp=1` | rejected before the worker starts |
| `weight_dtype=fp8_e4m3fn`; H3 Fun ControlNet | rejected |

## Not in this PR

- **Conditioning-cache keys, per-row batching and resend-after-rebuild** are in #43492 / #43493.
- **A worker killed mid-step can hang ComfyUI** inside `cudaIpcCloseMemHandle` with the GIL held. A core fix in the scheduler client will follow separately.
