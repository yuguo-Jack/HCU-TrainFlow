# [Fix] kernels: Port rmsnorm and softmax bench off the removed get_jit_cuda_arch

[Upstream PR](https://github.com/sgl-project/sglang/pull/47915) · state: closed · merged: True

## Original PR description

> (auto generated by Claude)

#47782 removed `get_jit_cuda_arch` from `sglang.kernels.jit.utils` (runtime arch queries now go through `sglang.kernels.arch.current_arch()`), but #47503 and #47512 merged in between and still import it:

- `python/sglang/kernels/ops/layernorm/norm.py` (JIT rmsnorm): importing the module fails with `ImportError: cannot import name 'get_jit_cuda_arch' from 'sglang.kernels.jit.utils'`, e.g. in `test_humming_runner_gpu.py` on `jit-kernel-unit-test-4-gpu-b200`.
- `test/registered/kernels/benchmark/sampling/bench_softmax.py`.

Both now use `current_arch()`: `get_jit_cuda_arch().major >= 10` becomes `current_arch().is_sm_at_least(10)`, and `major != 10` becomes `not current_arch().is_sm(10)`. Both checks already sit behind the HIP / MUSA guards, so behavior is unchanged. No other references to the removed names remain on main.

Validation: `/rerun-test` of the rmsnorm, layernorm fusion and humming runner tests.
