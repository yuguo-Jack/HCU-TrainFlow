# [Refactor] hicache: Route buffer-mode backup admission keys and FULL transfers through pipeline hooks

[Upstream PR](https://github.com/sgl-project/sglang/pull/45701) · state: closed · merged: True

## Original PR description

## Motivation

`BufferModePipeline` decides a buffer-mode backup in two places that read the tree core directly:

- `_backup_pool_keys` asks `tree_core.buffer_backup_pool_keys(...)` for the per-component pool-key overrides that admission uses.
- The D2H spec builder asks `tree_core.build_hicache_transfers(ComponentType.FULL, node_id, CacheTransferPhase.BACKUP_HOST)` for the FULL component's transfers, which replace the KV rows or ride as auxiliary pools.

A component can already supply its own pipeline class through `TreeComponent.create_buffer_pipeline`, but such a subclass has no seam to replace either query when it plans backups outside the tree core. Its only option is to copy the whole method.

## Modifications

- Move the two calls into `_backup_pool_key_overrides(snapshot)` and `_full_backup_transfers(node_id)` on `BufferModePipeline`. The base implementations delegate to the same tree-core methods, so admission and launch behaviour are unchanged.
- Tidy the two docstrings that described these calls.

No new configuration, no behaviour change for existing callers.
