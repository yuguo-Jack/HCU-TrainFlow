# [Fix] sgl-router: Wait for the detached PD prefill in routing tests

[Upstream PR](https://github.com/sgl-project/sglang/pull/45502) · state: closed · merged: True

## Original PR description

## Motivation

Four sgl-router proxy tests fail intermittently. In a loaded `cargo test --release --test proxy` run, about 2 in 10 runs fail on main, always the same way:

```
left:  [false, false, false, true]
right: [false, true, false, true]
```

Decode got the request, but the chosen prefill mock hadn't recorded a body yet. In PD mode the router sends prefill as a detached task, and `forward_pd` returns as soon as decode responds. The tests read the prefill mock's `last_body` right after the response, so under load the spawned prefill hasn't reached the mock yet. Routing is correct; the tests check too early.

Affected tests:
- `bucket_routing::decode_bucket_mismatch_falls_back_to_another_version_group` (#41613)
- `bucket_routing::version_group_capacity_fallback_preserves_decode_limits` (#41613)
- `chat_routing::reorg::full_decode_group_falls_back_to_another_version_group` (#41613)
- `chat_routing::reorg::default_pd_groups_apply_configured_inflight_admission` (#40766)

## Modifications

Before checking the dispatch pattern, wait for the expected prefill worker to receive its body. Each file reuses its existing pattern:
- `bucket_routing.rs`: the existing `wait_for_prefill` helper (2s timeout)
- `reorg.rs`: the inline `timeout(TEST_TIMEOUT, …)` loop its other PD tests already use

The assertions themselves are unchanged. If prefill went to the wrong worker, the wait times out and the test still fails.

Test-only change; no router code changes.

## Verification

`cargo +nightly fmt --check` and `cargo clippy --workspace --all-targets -D warnings` pass.

Out of scope: one of the 20 runs on this PR hit an unrelated timing flake, `chat_routing::janitor_expiry_returns_504_stale_request_expired`, which races a 2s hanging mock against the stale-request janitor. It's a separate test with a different cause, not a PD prefill check.
