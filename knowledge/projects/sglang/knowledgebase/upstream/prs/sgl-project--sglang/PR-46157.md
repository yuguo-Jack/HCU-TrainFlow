# [Fix] diffusion/scheduler: Isolate invalid IPC requests

[Upstream PR](https://github.com/sgl-project/sglang/pull/46157) · state: closed · merged: True

## Original PR description

## Summary

One invalid scheduler message can discard unrelated requests received in the same poll. The previous exception filter missed errors such as an unsupported pickle protocol or a missing request module, and CUDA IPC reconstruction happened over the entire batch. On multiple ranks, a rank-0 decoding failure can also prevent the expected broadcast.

- Decode, normalize and reconstruct IPC references per message before adding it to the batch.
- Return an error for invalid payloads in complete REQ envelopes. A failed nonblocking error reply does not discard valid requests.
- Keep the existing valid-request broadcast and execution paths. Remove the redundant catch-and-reraise wrapper; production code grows by nine lines in one existing file.
- Extend the existing scheduler-client tests and clarify internal transport and timeout boundaries in the CLI docs.

This complements #46120 for the monolithic scheduler receive path. It is request isolation, not authentication, general GPU recovery, or backpressure. Pickle endpoints must remain on a trusted network.

## Validation

- Remote baseline: all six malformed-message cases fail. Fixed related suite: **110 passed**, including CUDA IPC round-trips and rejection-send backpressure coverage.
- Two real CPU/Gloo ranks: SP, CFG and TP request-broadcast paths each preserve the same valid requests across three malformed-payload cases. This is a collective transport test, not multi-GPU model inference.
- Real **Wan2.1-T2V-1.3B / 1x H200**, FA, 512x320, 17 frames, four steps, seed 42: pause the owned worker briefly to queue two HTTP video requests together with an invalid internal message, then resume it. Before the fix both valid jobs remain queued through their polling windows, while health is 200 and a later request succeeds. After the fix only the invalid message returns an error; both videos and the recovery request complete.
- All successful before/after videos have identical decoded pixel hashes. Both servers shut down cleanly without remaining child processes.
- Pre-commit passed. No model math, GT, tolerance or baseline changes; no performance claim.

The suite needs a writable Hugging Face cache. Internal RPC timeout/cancellation stops the caller waiting; it does not cancel already submitted GPU work.

Environment: Python 3.12.15, PyTorch 2.14.1+cu130, Diffusers 0.37.0, PyZMQ 27.2.0.
