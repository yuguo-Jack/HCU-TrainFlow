# [Feature] Add AdaFlash adaptive verification for DFlash speculative decoding

[Upstream PR](https://github.com/sgl-project/sglang/pull/34171) · state: open · merged: False

## Original PR description

## Motivation

This PR adds AdaFlash support on top of SGLang's DFlash speculative decoding implementation.

AdaFlash introduces an Adaptive Length Head that predicts the verification length dynamically from the draft model's hidden states. Instead of always verifying a fixed-size draft block, the target model verifies only the dynamically selected number of tokens, reducing unnecessary target-model computation while retaining DFlash's block drafting behavior.

The implementation supports:

- Qwen3-8B
- Qwen3-Coder-30B-A3B-Instruct
- Qwen3.5-9B

For standard transformer models such as Qwen3 and Qwen3-Coder, AdaFlash uses packed variable-length verification. For Qwen3.5 hybrid GDN/Mamba models, it uses a rectangular hard-clipped verification layout compatible with the hybrid attention and Mamba state update paths.

## Modifications

### Adaptive Length Head

- Add `ThreshHeadTwoModel`, which predicts the verification-length ratio from draft hidden states.
- Use mean-pooled and last-position draft features as the head input.
- Run the Adaptive Length Head on a separate CUDA stream in parallel with draft LM-head computation.
- Support tensor-parallel broadcasting of predicted candidate lengths.
- Require `dflash_config.thresh_head_direct_len=true` for the AdaFlash serving path.
- Preserve the original fixed-window DFlash behavior when dynamic verification is disabled.

### Dynamic verification

- Add per-request `candidate_lens` support to DFlash verification inputs.
- Support packed verification with `sum(candidate_lens)` tokens for Qwen3 and Qwen3-Coder.
- Use the full rectangular CUDA Graph path for small batches to avoid packed-layout overhead.
- Add a CUDA-Graph-compatible rectangular hard-clip path for Qwen3.5 hybrid GDN/Mamba models.
- Add variable tokens-per-batch-element CUDA Graph capture for DFlash target verification.
- Update KV-cache allocation, attention metadata, verification masks, and token commit logic for variable verification lengths.
- Add an EMA-based estimate of the dynamic verification length for continuous batching and memory planning.
- Add verification-budget checks and candidate-length clamping when the available KV cache is insufficient.

### Qwen3.5 hybrid attention support

- Update the Qwen3.5 model, GDN backend, hybrid linear-attention backend, Mamba metadata, and related Triton kernels for dynamic DFlash verification.
- Add the fused GDN projection kernel.
- Add the current formal Qwen3.5 rectangular verification and Mamba-state commit path.
- Preserve compatibility with EAGLE-3 and MTP execution paths.

### Metrics

- Track the actual number of tokens proposed to the target model.
- Expose the average dynamic verification length as `spec_verify_len` in benchmark metadata.
- Preserve the existing speculative acceptance metrics and histograms.

### Online draft weight updates

- Allow `Engine.update_weights_from_disk(..., update_speculative_draft=True)` to update only the speculative draft worker.
- Route disk and tensor weight updates to the DFlash draft worker.
- Preserve the target model when updating draft weights during online training or serving.

### Training hidden states

- Return dedicated `teacher_hidden_states` and `last_hidden_states` for draft-model training.
- Preserve these outputs through CUDA Graph replay.
- Keep the concatenated auxiliary hidden states used by speculative decoding while exposing the final-layer teacher representation separately.
