# [Feat] [NVIDIA] flash-attn: FA4 SM90 FP8 e4m3 KV cache for head_dim 512 (Gemma-4)

[Upstream PR](https://github.com/sgl-project/sglang/pull/46965) · state: open · merged: False

## Original PR description

**Stacked on #44399** (per-layer FA3/FA4 for Gemma-4). This branch is #44399's head plus one commit; review only the last commit, "[Gemma4][Attention] FA4 SM90: FP8 e4m3 KV cache for head_dim 512". I will rebase it once #44399 lands.

## Motivation

With #44399, `--attention-backend fa3` runs Gemma-4's head_dim-512 full-attention layers on FA4, which has no FP8 KV path on SM90. `--kv-cache-dtype fp8_e4m3` is therefore rejected at init, even though FA3 handles the sliding layers in FP8. This PR adds FP8 e4m3 KV reads to FA4's SM90 forward so the whole model can serve with an FP8 KV cache on H100/H200, which doubles KV capacity.

## Modifications

**Interface** (`flash_attn/cute/interface.py`):
- bf16/fp16 Q with fp8 e4m3 K/V on SM90 selects this path, and the Q/K/V dtypes join the compile key.
- Unsupported cases raise `NotImplementedError`: non-paged KV, head_dim != 512, e5m2, rel_bias, block sparsity, qv.

**Backend** (`flashattention_backend.py`, ~25 lines):
- The fa3 backend accepts an `fp8_e4m3` cache when it upgrades head_dim > 256 layers to FA4.
- Those layers keep Q unquantized and receive the k/v descales. The FA3 layers still quantize Q as before.

**Tests:**
- FP8-KV cases in `test_flash_attention_4.py`, checked against a dequantized reference over page sizes, query lengths, cache lengths, splits and both `intra_wg_overlap` values.
- A unit test for `prepare_paged_mha_query` in `test_flashattention_paged_mha.py`.
