# [Fix] [NPU] qwen: Fix shared-expert routing with Ascend FuseEP

[Upstream PR](https://github.com/sgl-project/sglang/pull/40516) · state: closed · merged: True

## Original PR description

## Motivation

Qwen3.5-35B-A3B with ModelSlim W8A8 produces garbled output with `--moe-a2a-backend ascend_fuseep --fuseep-mode 2 --tp-size 4`, while the unfused baseline answers the same prompts correctly.

`Qwen2MoeSparseMoeBlock`, also used by Qwen3.5, omits FuseEP from its dispatch/combine path. FuseEP has already combined routed experts for each source token, but the block keeps a TP-sharded shared expert and applies the ordinary TP all-reduce to different ranks' token rows.

## Changes

Include Ascend FuseEP in the existing shared-expert dispatch/combine path in `qwen2_moe.py`:

- Construct the shared expert with `tp_rank=0, tp_size=1`.
- Initialize the expert-parallel metadata.
- Route through `_forward_deepep` to add the complete shared contribution without the ordinary TP all-reduce.

## Validation

Previously recorded A3 validation of this model change used Qwen3.5-35B-A3B W8A8, TP4, and FuseEP mode 2. Concurrent arithmetic changed from garbled output to all four correct answers. Against the unfused baseline, aligned input-logprob mean absolute error decreased from 5.716665 to 0.051821, and maximum error decreased from 21.028971 to 0.451154.

The runtime model change is unchanged from that validation. The final PR diff is limited to `qwen2_moe.py`; both test trees match the PR merge base. Python syntax and diff checks pass. No new NPU inference run was performed for this test-only removal.
