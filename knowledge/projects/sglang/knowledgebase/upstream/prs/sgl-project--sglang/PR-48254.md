# [Fix] routed-experts: return no tokens in the abort echo of a request whose routing is gone

[Upstream PR](https://github.com/sgl-project/sglang/pull/48254) · state: open · merged: False

## Original PR description


## Motivation

Clients that abort in-flight requests and keep the partial outputs rely on one routed-experts row per returned token. For a request that holds no KV (queued, retracted, or mid-chunk) the scheduler echoes the abort and the tokenizer answers with the tokens it has seen so far. A retracted request has already produced tokens, but their routed experts went away with its KV, so a non-streaming `return_routed_experts` response carries N output tokens, N logprobs and no routed experts.

## Modifications

- `TokenizerManager._handle_abort_req`: for a non-streaming request with `return_routed_experts`, the abort echo returns no output tokens, empty output-side logprob lists, `completion_tokens=0` and an empty `routed_experts`; the weight versions are computed for the tokens actually returned. Streaming requests (which already received their tokens) and requests without routed experts are unchanged.
- `sampling_params.mdx`: one sentence on this case (queued, retracted or mid-chunk requests) below the parameter table.
- `test/registered/unit/managers/test_tokenizer_manager_rid_cleanup.py` (CPU): the non-streaming echo has no tokens, no output logprobs and empty routed experts (fails on main), and its weight versions cover the 0 tokens it returns; the streaming echo keeps its tokens.

A related fix for client aborts that land in a step reaching a stop or the length cap is a separate PR ("[Fix] scheduler: let a client abort yield to the stop or length cap of its step").

## Accuracy Tests

`Qwen/Qwen3-30B-A3B`, TP1, `--enable-return-routed-experts --max-total-tokens 8192`, upstream's forced-retraction test knob (`SGLANG_TEST_RETRACT=1 SGLANG_TEST_RETRACT_INTERVAL=10`). 32 concurrent non-streaming greedy requests (`max_new_tokens=1024`, `return_logprob`, `return_routed_experts`), then `abort_all` after 15 s. Baseline `8d4e1ce4c7` and this PR on the same GPU in the same container (GB300 runs use `--moe-runner-backend triton`).

| | main | this PR |
|---|---|---|
| abort echoes with tokens and logprobs but no routed experts, per run of 32 requests | 1x GB300: 10-13 (4 runs: 13, 13, 10, 11); 1x GB200: 13 (1 run); 1x H100: 10-18 (3 runs: 10, 18, 18) | 0 in every run (those echoes return 0 tokens, 0 logprobs, 0 rows) |
| running requests aborted (rows = prompt + completion - 1) | 7, consistent | 7, consistent |

The count on main depends on which requests are retracted when the abort lands, so it varies from run to run; on this PR it is 0 in every run. Requests that are not aborted, and streaming requests, run the same code as before.
