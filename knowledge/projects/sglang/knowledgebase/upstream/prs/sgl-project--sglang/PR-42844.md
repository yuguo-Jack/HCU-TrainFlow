# [Inkling] Render and parse chat through tml-renderers

[Upstream PR](https://github.com/sgl-project/sglang/pull/42844) · state: open · merged: False

## Original PR description

## Motivation

Inkling's chat wire format (TMLv0: message framing, tool declarations, tool calls, thinking blocks, effort, multimodal placeholders) was hand-reimplemented in sglang, on both the prompt side and the output-parsing side. Thinking Machines publishes the reference implementation as [`tml-renderers`](https://tinker-docs.thinkingmachines.ai/cookbook/inkling/tml-renderers/). This PR delegates both directions to that library, so sglang matches the model's training format by construction rather than by hand-maintained parity.

## Modifications

**Prompt rendering**: `python/sglang/srt/parser/inkling_renderer.py`
- OpenAI-shaped messages go through `tml_renderers.chat.OpenAIMessage` and `v0.Renderer.render_for_completion_with_effort`.
- sglang still owns three pieces:
  - the `tool_declare` message, placed after the leading system messages, as in the Cookbook prefix;
  - the image and audio placeholder IDs that the MM processor expands;
  - the open model text block for `continue_final_message`.
- `encode_simple_chat` uses the same path.

**Output parsing**: `python/sglang/srt/parser/inkling_output.py`, wired through `entrypoints/openai/inkling_chat_adapter.py`, which `serving_chat.py` delegates to
- Chat responses are parsed incrementally from output token IDs with `v0.Parser`, so control tokens are recognized by ID only. Reasoning, content and tool calls come from parsed messages, and tool-call arguments come from the library's bridge.
- Stream and non-stream share one parser.
- Matched stops are cut in the raw sampled stream, honoring `no_stop_trim`, and a matched special stop never renders as text.
- Header-less constrained output (`response_format` / `regex` / `ebnf` after the reasoning terminator, or from the first token) is parsed as model text.

**Dependency and startup guard**
- `python/pyproject.toml` adds `tml-renderers==0.1.0 ; python_version >= '3.11' and sys_platform == 'linux'`. The package is Apache-2.0; PyPI ships only `cp311-abi3` wheels (linux x86_64/aarch64, macOS arm64).
- Serving an Inkling checkpoint calls `load_tml_renderers()` in `OpenAIServingChat.__init__`. If the package is missing, startup fails with an install hint instead of failing on every request.

**Removed**: the hand-written TMLv0 tokenizer and renderer (`InklingTokenizer` and helpers in `inkling_tokenizer.py`).

### Behavior changes (all follow the reference library)

- A tool result without `name` renders with an empty author. It is no longer resolved from `tool_call_id`.
- A top-level `reasoning_content` on assistant history is no longer rendered; only `{"type": "thinking"}` content parts are. Clients or adapters that carry prior thinking in `reasoning_content` lose it from the prompt.
- With tools and a system prompt, the order is now `system → tool_declare → effort`. It was `tool_declare → system → effort`.
- Control tokens are recognized by token ID only. Model text that spells a marker (`<|end_message|>`) stays text.
- A malformed tool call surfaces as content text instead of being dropped or half-parsed.
- Audio input is rejected (400) outside user messages, as the library does.

### Known scope limits

- The Responses API and the `/parse_function_call` and `/separate_reasoning` utility endpoints still use the string-based Inkling detectors.
- Non-16 kHz audio is not compared against the library, which resamples through `librosa`. At 16 kHz, sglang's DMel features are bit-exact with the library's.
- `response_format` JSON can be malformed: the grammar activates at the first `<|end_message|>` of any message, so with thinking off the model's own answer and a constrained JSON both appear. This is pre-existing and identical on `main`; this PR does not change the grammar side.

### CI coverage

`tml-renderers` ships only `cp311-abi3` wheels, and the CUDA CI runners use Python 3.10. Tests that need the library skip where it is not installed:
- unit tests that render or parse through `tml-renderers` (`test_inkling_renderer.py`, and the Inkling cases in `test_serving_chat.py`);
- the Inkling server-launch tests (per-commit, extra and nightly), because serving an Inkling checkpoint requires the library at startup.

Full CI coverage needs either a `cp310` wheel from TML or a CI Python upgrade. Both are out of scope for this PR; the devbox results below verify this change.

## Accuracy Tests

Devbox: 4x GB300 with `thinkingmachines/Inkling-NVFP4` @ `42a75a99a40eb2ba1e0717db6357a0bf15205044`, using the cookbook GB300 NVFP4 TP4 recipe plus `--reasoning-parser inkling --tool-call-parser inkling`:

```bash
python -m sglang.launch_server --trust-remote-code --model-path thinkingmachines/Inkling-NVFP4 \
  --tp 4 --quantization modelopt_fp4 --attention-backend fa4 --page-size 128 \
  --fp4-gemm-backend flashinfer_trtllm --moe-runner-backend flashinfer_trtllm_routed \
  --enable-torch-symm-mem --mamba-radix-cache-strategy extra_buffer --mem-fraction-static 0.85 \
  --swa-full-tokens-ratio 0.1 --mamba-full-memory-ratio 0.1 --enable-multimodal \
  --reasoning-parser inkling --tool-call-parser inkling --port 30000
sgl-eval run gsm8k --base-url http://localhost:30000/v1 --temperature 1.0 --top-p 0.95 --max-tokens 32768
```

GSM8K, full 1319 questions:

| Build | Accuracy | finish_reason `stop` | Empty answers |
|---|---|---|---|
| This PR | 96.36% | 1319/1319 (100%) | 0 |
| Baseline (parent `main`, same env and flags) | 96.82% | 1319/1319 (100%) | 0 |

Earlier runs of this branch on the same recipe scored 96.29–96.74%, so the gap is within run-to-run noise at temperature 1.0. Every response carries non-empty `reasoning_content`, and no control-token text leaks into `content`.

- Prompt renders of the GSM8K questions are token-identical between the old and new renderers (200/200).
- Prompt parity against the reference library: 26/28 corpus cases are byte-identical. The 2 that differ are intentional supersets (`developer` role, null tool parameters).
- Golden prompt and output fixtures are generated by `tml-renderers` itself (`inkling_tmlv0_golden.json`).

Other checks:

| Check | Result |
|---|---|
| Tool-call smoke (single and parallel calls; `tool_choice` auto/required/named/none; multi-turn with and without `name`; unicode and float args; `stream_reasoning`; `separate_reasoning=false`; `continue_final_message`; every `reasoning_effort` preset; stream and non-stream) | 27/27 |
| Forced-token server checks (custom logit processor) | 26/26 |
| Multimodal (image in user and tool messages, 597 placeholder tokens per image; audio in user; audio in tool message returns 400) | 5/5 |

| Unit tests | 170 passed on Python 3.12 (`test_inkling_renderer.py` + `test_serving_chat.py`); 33 passed for the Inkling function-call and reasoning suites; with `tml-renderers` absent, the same two files give 148 passed and 22 skipped |

The forced-token checks cover:
- stop strings across text blocks and overlapping inside a token;
- special stop IDs inside open blocks;
- `no_stop_trim`;
- marker kinds after a stray prefix;
- literal marker spellings;
- constrained JSON without a header.

### Review

Four rounds of independent Codex code review. Rounds 1–3 requested changes to stop-string position and overlap in the raw token stream, header-less constrained output, and marker recovery after stray text. Each of these findings has a regression test in this series. Round 4 approved.

## Speed Tests and Profiling

`sglang.bench_serving`, random 1024/1024, 256 prompts, concurrency 64, `--flush-cache`, on 4x GB300. Each cell shows two runs. The baseline is the parent `main` commit with the same env and flags.

| Build | Endpoint | Output tok/s | Median TPOT (ms) | Median TTFT (ms) |
|---|---|---|---|---|
| This PR | chat, streaming | 3108 / 3127 | 19.33 / 19.29 | 1263 / 1267 |
| Baseline | chat, streaming | 3103 / 3125 | 19.33 / 19.26 | 1294 / 1306 |

Prompt rendering costs 0.17 ms per request, versus 1.59 ms for the previous HF-template encode. Per-token parsing on the event loop shows no TPOT cost.
