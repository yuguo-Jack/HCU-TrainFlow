# [Fix] Reject malformed native generation inputs before dispatch

[Upstream PR](https://github.com/sgl-project/sglang/pull/41546) · state: closed · merged: False

## Original PR description

## Motivation

A malformed field in a native `/generate` request can pass request construction and reach the scheduler or detokenizer, where a type error terminates the server. For example, a list-valued `regex` becomes an unhashable grammar-cache key, and an oversized `top_k` overflows the scheduler's int32 tensor.

Fixes #41466. All ten fields listed in the report are covered: `positional_embed_overrides`, `lora_id`, `max_new_tokens`, `beam_width`, `regex`, `json_schema`, `ebnf`, `structural_tag`, `skip_special_tokens`, and `top_k`.

## Modifications

- Add shared, non-mutating request preflight before HTTP streaming starts and before request normalization/fan-out. Malformed reported inputs return JSON HTTP 400 for both streaming and non-streaming `/generate`; Python callers receive `ValueError` before scheduler dispatch.
- Validate sampling scalar/grammar types and int32-safe `top_k`, preserve null defaults and disable sentinels, and reject caller-supplied transport normalization state. Model-processor extras such as Whisper's fields remain available.
- Validate session fields, positional-embedding objects/shapes/dimensions, and single/batched LoRA metadata. Normalize valid LoRA path lists and preserve per-request metadata during parallel-sampling expansion.
- Add CPU regressions through the production ASGI routes and tokenizer-manager admission path, plus component, batch, compatibility, and MessagePack tests.

## Prior work and attribution

This consolidates the reported failure cases into one request-boundary fix, with adapted work from:

- #37181 by [fortunecookiee](https://github.com/fortunecookiee): positional-embedding type/rank/dimension validation, adapted from `fe26b926a7ca3d68d6688dd803916054b23b00bb`.
- #34885 by [taking-lying-flat](https://github.com/taking-lying-flat): `normalize_lora_paths` and shared request-boundary integration, from `ff097dc88a5f83bc0c38dcfb19246a3ecac3db9c`.
- #41535 by [sunshinejiali](https://github.com/sunshinejiali): session-field validation policy, implemented here with `ValueError` at the shared boundary.

Related resource-limit work in #36856/#28794, per-prompt session-list support in #28796, schema-complexity limits in #40373, and stop-regex syntax handling in #40985 remain separately scoped. This PR does not add a parallel-sample resource cap or claim to validate every possible native request field.
