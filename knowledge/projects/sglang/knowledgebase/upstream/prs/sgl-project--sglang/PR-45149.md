# [Feat] [MLU] platform: Add initial support for Cambricon MLUs

[Upstream PR](https://github.com/sgl-project/sglang/pull/45149) · state: open · merged: False

## Original PR description

## Motivation

Add the initial device, communication, and operator support for Cambricon MLUs. This builds on the MLU CI infrastructure introduced in [#41005](https://github.com/sgl-project/sglang/pull/41005) and enables its single-device and two-device suites to exercise SGLang runtime code.

Cambricon devices use the `mlu` device type provided by `torch_mlu` and CNCL for device communication. This PR adds an in-tree platform identity, integrates the communicator with SGLang's distributed layer, and adds an RMSNorm implementation backed by `torch_mlu_ops`.

The scope is limited to these foundations and their installation and tests. **This PR also provides tests to validate that the MLU CI infrastructure works end to end.**

## Modifications

### 1. Device platform and detection

- Add `PlatformEnum.MLU`, `DeviceMixin.is_mlu()`, and the in-tree `MluSRTPlatform`.
- Discover the MLU platform when no external platform plugin activates.
- Add device selection, memory queries, synchronization, cache management, and random-seed support.
- Detect MLU availability through `torch.mlu.is_available()`; an unavailable device returns `False`.

### 2. Distributed communication

- Add `MluCommunicator` and the `mlu → cncl` backend mapping.
- Route `GroupCoordinator.all_reduce()` and `all_gather()` through the MLU communicator.
- Disable the default PyNCCL path for MLU model-parallel groups and reuse the shared all-gather compatibility interface.

### 3. RMSNorm

- Add `forward_mlu` selection to `BaseFusedOp`.
- Implement RMSNorm and residual fusion using `torch_mlu_ops.fused_rms_norm`.

### 4. Installation and documentation

- Add `srt_mlu`, `all_mlu`, and `dev_mlu` extras to the shared `python/pyproject_other.toml`.
- Record the reference container tag and vendor component versions in `scripts/ci/mlu/component_versions.properties`.
- Document container creation, vendor package preparation, source installation, and CI suite verification. Vendor packages are obtained separately through Cambricon support.

### 5. Tests and CI integration

- Register `HWBackend.MLU`, `register_mlu_ci()`, and `--hw mlu`.
- Add `pr-test-1-mlu` for RMSNorm correctness and `pr-test-2-mlu` for two-device communication.
- Test RMSNorm against its native reference, including residual fusion, empty inputs, and non-contiguous layouts.
- Test all-reduce and all-gather through `GroupCoordinator → MluCommunicator`.
- Extend the existing CPU platform and fused-op dispatch tests.
- Update CI coverage reporting, registration lint, and slash-command backend recognition.

## MLU CI triggering

This PR adds MLU options to the existing label commands and a dedicated command for rerunning MLU CI. MLU PR tests require both `run-ci` and `run-ci-mlu`.

| Command | Behavior |
| --- | --- |
| `/tag-run-ci-label mlu` | Add `run-ci` and `run-ci-mlu`. |
| `/tag-and-rerun-ci mlu` | Add both labels, rerun unsuccessful CI workflows, and rerun the current commit's MLU workflow. |
| `/run-mlu-ci` | Add both labels and rerun only MLU CI. |

The updated labels are picked up on the next push or rerun. The label commands also accept `extra mlu` to opt into both tiers. Authorization reuses the existing permissions in `.github/CI_PERMISSIONS.json`.

The MLU suites cover:

- `pr-test-1-mlu`: single-device RMSNorm correctness.
- `pr-test-2-mlu`: two-device all-reduce and all-gather through the SGLang communicator.

## Accuracy Tests

Validated locally on Cambricon MLU hardware:

- RMSNorm numerical correctness against `forward_native()`, including residual and post-residual addition.
- Empty and non-contiguous RMSNorm inputs.
- Two-device all-reduce and all-gather through the SGLang communicator.

CPU tests cover platform interfaces and fused-op dispatch, including MLU forward selection and native fallback. Additional local checks verified non-default RMSNorm configurations against the native reference.

These are operator and communication checks. Model-level accuracy evaluation will accompany subsequent inference support.

MLU CI passed
([run](https://github.com/sglang-mlu/sglang/actions/runs/39231498205/attempts/5)):

- `pr-test-1-mlu`: 5 RMSNorm correctness tests passed.
- `pr-test-2-mlu`: two-device all-reduce and all-gather test passed.

This validates environment installation, hardware tests, and result/log reporting
through the MLU CI infrastructure.
