# [Feat] [MLU] platform: Add initial support for Cambricon MLUs

[Upstream PR](https://github.com/sgl-project/sglang/pull/45149) · state: open · merged: False

## Original PR description

## Motivation

Add initial Cambricon MLU support, including device management, CNCL communication, RMSNorm, installation instructions, and CI tests.

## Modifications

### Initial MLU support

- Platform detection and device management, including device selection, memory queries, synchronization, cache management, and random-seed support.
- Reuse generic all-reduce and all-gather paths with CNCL and MLU custom-op registration.
- Fused RMSNorm and residual addition, with reshaping for 1D, higher-rank, and transposed inputs, and native fallback for unsupported configurations, layouts, and mixed dtypes.
- Reject deterministic mode explicitly for MLU RMSNorm; deterministic inference support is deferred to a follow-up.

### Tests and CI integration

- Add MLU test registration and suite execution through `--hw mlu`.
- Add single-device RMSNorm and two-device communication suites, covering eager and `torch.compile(fullgraph=True)` collectives, with platform and operator-dispatch unit tests.
- Include MLU tests in CI coverage reporting and registration validation.
- Add MLU test recognition to `/rerun-test`.

### Installation and documentation

- Add `srt_mlu`, `all_mlu`, and `dev_mlu` installation extras. Pin `torch-mlu`, `torch-mlu-ops`, and Triton to their versions in `scripts/ci/mlu/component_versions.properties`.
- Record the reference container tag and vendor component versions.
- Document container setup, vendor package preparation, source installation, and CI suite execution.

## Accuracy Tests

Local validation on MLU hardware:

- `pr-test-1-mlu`: all 7 RMSNorm tests passed, covering native-reference comparisons, residual fusion, empty and non-contiguous inputs, mixed-dtype fallback, and shape preservation for 1D, higher-rank, and transposed inputs across FP32, FP16, and BF16.
- `pr-test-2-mlu`: the two-device CNCL all-reduce and all-gather test passed in eager and `torch.compile(fullgraph=True)` modes, including checks that collectives remain opaque custom ops in the compiled graph.

## Speed Tests and Profiling

Model-level performance benchmarks are outside the scope of this initial platform support.
