# [AMD] Disable torch.compile for ROCm diffusion layernorm

## Motivation

This is a follow-up fix for #25256.

#25256 added `torch.compile` to the Wan diffusion native layernorm paths to improve MUSA/CUDA inference speed. The compile decorator only disabled NPU:

```python
@torch.compile(disable=current_platform.is_npu())
```

However, on ROCm/HIP these diffusion layernorm custom ops use `forward_hip`, which intentionally falls back to `forward_native` because the CUDA/CuTeDSL fused kernels are not supported on HIP. After #25256, the HIP fallback path also went through `torch.compile`, which is not the supported ROCm path for these diffusion layernorm ops and caused the AMD diffusion tests to fail.

This PR disables `torch.compile` on HIP while keeping the #25256 behavior unchanged for the other platforms.

## Modifications

Disable `torch.compile` on ROCm/HIP for the three diffusion layernorm native fallback paths:

- `_ScaleResidualNormScaleShift.forward_native`
- `_NormScaleShift.forward_native`
- `_NormTanhMulAdd.forward_native`

The disable condition is changed from:

```python
current_platform.is_npu()
```

to:

```python
current_platform.is_npu() or current_platform.is_hip()
```

No speed benchmark impact is expected on ROCm because this PR restores the native fallback behavior for HIP instead of enabling a new optimized path. The MUSA/CUDA `torch.compile` optimization from #25256 is unchanged.
