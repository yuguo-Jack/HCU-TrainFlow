# [HiCache] Extract the buffer-mode prefetch and load-back lifecycle into pipeline operations

[Upstream PR](https://github.com/sgl-project/sglang/pull/43870) · state: closed · merged: True

## Original PR description

## Motivation

`BufferModePipeline` handles a storage prefetch in three long stretches: the IO-commit allocation inside `UnifiedRadixCache._try_alloc_storage_hit` (interleaved with the cache-mode path behind `buffer_mode` branches), the staged-record construction in `stage_completed_prefetch`, and one `init_load_back` that checks FULL capacity, prepares every component, queues the H2D copy, inserts the prefix and registers the ack record. A pipeline variant with a different resident layout cannot change one of those decisions without copying the whole method.

This PR splits those stretches into named operations on the pipeline while keeping the ownership lifecycle in one place. Behavior is unchanged for the stock pipeline.

## Modifications

- `BufferModePipeline.allocate_and_queue_prefetch` owns the buffer-mode IO commit (oversize rejection, bounce allocation, aux staging, parking on host capacity, queueing). `UnifiedRadixCache._try_alloc_storage_hit` keeps the cache-mode path and the buffer-mode anchor decisions.
- `_build_staged_prefetch` constructs the held span; `_set_request_device_prefix` and `_build_staged_prefetch_plan` rebuild the admission plan from the joint match.
- `_ensure_full_capacity`, `_allocate_and_queue_load_back`, `_insert_loaded_prefix` and `_free_completed_load_back_buffers` carry a typed load receipt from allocation through insertion to the fill ack. `_OngoingBufferLoadBack` now records the allocated device rows, the submitted transfer list and the component load contexts, so the insert and the redundant-slot release read them off the receipt. The checks run in the same order as before (FULL capacity, component preparation, `cc.load`, finalize).
- `try_lock_anchor` documents an `"unservable"` outcome (a resident device prefix that cannot be read). The cache declines such a fetch outright, counts it as `declined_unservable_prefix`, and lets the request recompute and heal the prefix instead of splicing onto it. The stock pipeline never reports this outcome; the decline path gets a unit test so it is not dead upstream.
- The FULL component constructs the pipeline through `TreeComponent.create_buffer_pipeline`, and the buffer-mode prefetch asks it for prefix-keyed PREFETCH transfers without a resident node (`build_hicache_transfers(None, PREFETCH, prefix_key=...)`); the stock `FullComponent` returns none. `Scheduler.get_prefill_adder_class` selects the prefill adder the way `get_rust_server_class` selects the server.
- `prefetch_prefix_key` exposes the device-matched prefix of a pending prefetch as a `RadixKey` for pipeline variants that query their own storage by prefix.

The buffer-mode oversize warning keeps its previous logger category (`sglang.srt.mem_cache.unified_radix_cache`) so existing log filters keep matching after the move.
