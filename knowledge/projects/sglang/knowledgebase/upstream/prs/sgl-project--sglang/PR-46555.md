# [Perf] sampling: Warm up the FlashInfer sampling module at server startup

[Upstream PR](https://github.com/sgl-project/sglang/pull/46555) · state: open · merged: False

## Original PR description

## Motivation

The startup warmup requests set `temperature` to 0. `SamplingParams` changes this to `top_k=1`, so the batch is `is_all_greedy` and the sampler runs `torch.argmax`. The warmup does not call FlashInfer sampling, so `get_sampling_module()` does not load the FlashInfer `sampling` module.

The first user request that sets top-k, top-p, or min-p loads the module. If `flashinfer-jit-cache` is not installed (the Docker default is `INSTALL_FLASHINFER_JIT_CACHE=0`), FlashInfer compiles `sampling.cu` with nvcc during that request.

We observed a 60 s stall on the first request without this change.

## Modifications

The warmup requests now send `top_k: 2` in place of `temperature: 0`. This applies to the `/generate` warmup, the VLM chat warmup, and the PD disaggregation warmup. The sampler then calls `top_k_top_p_sampling_from_probs`, and the module loads before the server is ready.

## Accuracy Tests

Not applicable. The change does not touch model code, and the server discards the warmup outputs.
