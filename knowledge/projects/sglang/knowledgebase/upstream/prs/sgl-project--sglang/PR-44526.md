# [Feat] linker: Support runtime attach and detach of the unified cache external linker

[Upstream PR](https://github.com/sgl-project/sglang/pull/44526) · state: open · merged: False

## Original PR description

## Motivation

UnifiedRadixCache external linkers can be detached and re-attached while an idle server is running, for example while the external store is under maintenance. The linker mode, backend and configuration remain launch-time declarations; the server starts attached and re-attach reuses the launch-time linker.

## Modifications

- New admin endpoints `DELETE /unified-cache/external-linker` (detach) and `PUT /unified-cache/external-linker` (re-attach, no request body). The HiCache storage-backend endpoints, message types and handlers are unchanged.
- `CacheLinkerAttachment` owns the linker lifecycle for startup, runtime attach/detach and process teardown. It depends on two callables built by the registry: one builds the linker from the launch-time backend/config, the other publishes the linker's layer counter (and Mamba layer-wise loading) or clears it on detach.
- Attach reduces constructor success across attention groups so all participating ranks link or none does, and backfills storage hashes for nodes inserted while detached.
- Detach reaches a consistent cleanup decision across attention groups, including already-detached ranks; a cleanup failure terminates the schedulers instead of resuming inconsistent state. Process teardown cleans up locally without collectives. Detach restores the write-through threshold and clears stale `external_cache_stored` marks in both Python and Rust tree cores so the store receives those prefixes again.
- Scheduler handlers only check the launch flag and idleness and delegate to the cache; runtime changes are rejected inside the cache with `--enable-linker-mla-dedup`. Endpoints keep the admin authentication requirement.
- Tests: one runtime detach/re-attach E2E, plus unit cases for cross-rank attach consensus, detach/re-attach tree state, and fatal detach failure.

## Validation

- Affected unit files (`test_unified_cache_linker`, `test_registry`, `test_external_linker_factory`, `test_hicache_pp_sync_drain`, `test_scheduler_hicache_attach`, `test_tokenizer_config_updates`): 131 passed on H200 with the Rust tree core built from source. A negative control (not clearing the published counter on detach) fails the detach/re-attach case.
- `test/registered/unit/mem_cache` + `test/registered/unit/managers`: same failure set as the previous head (pre-existing environment failures in `test_unified_hicache_transfer_lifecycle` and `test_mm_process_config`), no new failures.
- Runtime detach/re-attach E2E on `yujiepan/kimi-linear-tiny-random` (TP1, Mooncake over RDMA): launch-time hit, detach + idempotent detach, no host hit while detached, HiCache route rejection, re-attach + idempotent re-attach, and host hits after re-attach for both the prefix stored before detach and a prefix offloaded after re-attach. Results match the previous head.
- The registered DSV4-Flash TP4 E2E was not rerun for this revision.

## Accuracy Tests

KV transfer and model computation are unchanged; existing linker KL tests cover restored-KV correctness.

No performance claim.
