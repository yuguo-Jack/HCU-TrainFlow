# [Feat] linker: Support runtime attach and detach of the unified cache external linker

[Upstream PR](https://github.com/sgl-project/sglang/pull/44526) · state: open · merged: False

## Original PR description

## Motivation

The UnifiedRadixCache direct linker (`--enable-unified-cache-external-linker`) is wired once at startup and cannot be detached or re-attached while the server runs. HiCache L3 already supports this through `PUT/DELETE/GET /hicache/storage-backend`; this PR gives the linker the same lifecycle through the same endpoints.

The linker mode itself stays a launch-time declaration, because several startup decisions depend on it (DSA index-K layout, packed MTP draft plan, mutual exclusion with HiCache / unified memory / KV sharding). Runtime calls only detach the store and attach it again; the server still boots attached.

## Modifications

- **One attach flow, one detach flow.** New `CacheLinkerAttachment` (`mem_cache/unified_cache/linker_attachment.py`), modeled on `StorageAttachment`. Startup (`registry.create_unified_radix_cache`) and the admin API both call `attach()`. The admin API and process teardown (`release_host_resources`) both call `detach()`.
  - `attach()` builds the linker, then runs a MIN all-reduce over the attention groups so that either every rank links or none does. The linker hooks issue collectives (`match`, `finish_loads`, `check_hicache_events`), so a partial attach would hang. It then backfills storage hashes for nodes inserted while detached (`backfill_missing_hash_values`) and registers the layer counter on the KV pool and the TP worker.
  - `detach()` drains and closes the linker, releases pending offloads, and unregisters every counter, including the Mamba req-pool counter the linkers register themselves. It also restores `write_through_threshold`.
- **Stale store marks.** `external_cache_stored` describes the store being detached, not the next one. Left in place, it would make the tree skip offloading those prefixes forever after a re-attach. Disabling the linker on the tree core (`enable_external_cache_linker = False`) now clears it, in both the Python and Rust cores.
- **Endpoint reuse.** In linker mode the scheduler routes `/hicache/storage-backend` attach/detach to the linker:
  - `hicache_storage_backend` selects `mooncake` / `mori`.
  - `hicache_storage_backend_extra_config_json` is passed to the linker explicitly; the linkers no longer read the global bag for it.
  - Prefetch and write policies are rejected.
  - `GET` also reports `unified_cache_external_linker_backend`.
- **Unsupported at runtime:** `--enable-linker-mla-dedup` rejects runtime attach and detach, because its broadcast groups are built once at startup. Startup with dedup is unchanged.
- The idle check shared by the four admin handlers is now `Scheduler._admin_busy_message`.

## Accuracy Tests

No numeric path changes: load and offload transfers are unchanged. The existing KL linker tests cover loaded-KV correctness.

## Tests

- Unit (`test_unified_cache_linker.py`, both tree cores):
  - detach clears marks, threshold and counters; re-attach to an empty store offloads the whole path again, including a node inserted while detached;
  - a local or remote rank failure leaves nothing linked;
  - backend-to-class mapping.
- Scheduler unit (`test_scheduler_hicache_attach.py`): linker-mode dispatch, config bags, and the policy / MLA-dedup rejections.
- Negative controls:
  - Removing the mark clearing fails the round-trip test on both cores.
  - Removing the hash backfill makes the re-attach offload produce empty transfers.
- E2E `test_unified_cache_linker_runtime_attach.py` uses the DSV4-Flash TP4 linker config of the existing linker KL test. It checks: store hit → detach (no lookup) → re-attach (rejects a write policy) → hits for both a pre-detach prompt and one inserted while detached. It passed on 4x GB300; the local run used Mooncake over TCP and `SGLANG_OPT_FP8_WO_A_GEMM=0`, see the note below. A single-GPU GLM-5.2 (5-layer) DSA variant of the same flow also passed.
- Unit suites `test_unified_cache_linker.py`, `test_registry.py`, `test_umbp_direct_linker_rank_keys.py`, `test_scheduler_hicache_attach.py`, `test_unified_radix_cache_unittest.py`: 1444 passed, 0 failed.

Note: the current HF snapshot of `sgl-project/DeepSeek-V4-Flash-FP8` ships a bf16 `wo_a`, which the default `SGLANG_OPT_FP8_WO_A_GEMM=1` rejects at load. This is unrelated to this PR, and it also affects the existing DSV4 linker / URC KL tests on a fresh model cache.
