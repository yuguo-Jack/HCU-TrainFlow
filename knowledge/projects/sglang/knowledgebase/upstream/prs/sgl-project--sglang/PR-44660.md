# [Feat] [AMD] kv-shard: Support KV cache sharding with aiter and MoRI

[Upstream PR](https://github.com/sgl-project/sglang/pull/44660) · state: open · merged: False

## Original PR description

## Motivation

ROCm support for logical-page KV cache sharding (`--enable-kv-cache-sharding`, #30501): MLA models on PD prefill workers stripe at-rest KV across attention-TP ranks with aiter attention and MoRI transfer. At prefill TP4, K2.6 gets a 3.68x larger logical prefix cache and higher AgentX throughput once the replicated pool is under pressure (S1-S4).

Also a page-striped HiCache host tier for aggregated DSv4 (`--hicache-host-shard stripe`), where device KV stays replicated: each TP rank stores 1/N of the host pages. CPU-tested only; GPU e2e pending.

Depends on #38473 (squashed as the first commit).

## Modifications

**kv-shard on ROCm (aiter + MoRI, PD prefill, MLA over attention TP)**
- `aiter_backend.py`: shard gather plan at metadata time; extend `kv_indices` point at scratch rows (FA3/trtllm_mla contract).
- `forward_mha_rocm.py`: sharded pools read prefix latents through `get_mla_kv_buffer`.
- `page_interleave_pool.py`: less host work per sharded prefill forward (host-launch-bound on MI355X): whole-chunk MLA write with non-owned tokens aimed at the reserved slot 0, sync-free per-batch plan, one ready wait per layer, one fork event + one all-gather per layer-ahead gather (`PyNcclCommunicator.all_gather` takes an optional `stream`).
- `kv_shard_hook.py`: accept aiter and MoRI; refuse `--disaggregation-enable-kv-checksum` with sharding.
- `conn.py`: drop the equal prefill/decode attn-TP assert (decode already pulls from every prefill rank).
- AMD PD E2E caps the decode pool at 262,144 tokens (MoRI dma-buf pin counted twice, ROCm/mori#721).
- Scope: MLA over attention TP; DSA stays rejected; GQA under prefill CP not yet supported with aiter.

**DSv4 page-striped HiCache host tier (default off = stock)**
- `striped_host.py`: logical pool over N x per-rank pages (`owner = page % N`); rolling digest of alloc/free checked in existing MIN all-reduces.
- Backup: each rank copies only its owned pages; MIN-agreed admission with exact rollback.
- Load: owned H2D, then a pynccl all-gather at the next extend forward entry after a CPU consensus; acks and frees wait for the gather.
- Fail-closed gate: TP > 1, unified KV, `write_through`, DSpark only; refuses DP-attn, PP, DCP, kv-shard, PD, storage. New metrics `hicache_stripe_*`; staging `SGLANG_HICACHE_STRIPE_STAGING_MB` (512).
- Cost: no new collective on decode; one 6-int CPU all-reduce per extend; one 1-int all-reduce per backup (0.33 ms p50, gloo).
- Limits: aggregated serving only; HIP stream/event ordering so far verified only with CPU mocks and gloo.
