# [sgl-router] Serve /v1/completions through /generate, with the shared OpenAI layer

[Upstream PR](https://github.com/sgl-project/sglang/pull/42997) · state: closed · merged: True

## Original PR description

First of the stack that serves the router's OpenAI routes through the engine's `/generate`, so a request through the router behaves as the Python engine's own route does. This PR builds the shared OpenAI layer and uses it for **`/v1/completions`**, which needs no prompt rendering and no output parsing. Stacked on #42996.

## What this PR adds

**`/v1/completions` (`openai/completions.rs`)**
- Lowers the request to the `GenerateReqInput` `serving_completions.py` builds. The client's `prompt` goes through as given: text as `text`, token ids as `input_ids`.
- Builds the OpenAI response, JSON or SSE, from the `/generate` output: echo, logprobs, usage, `n`, batches, stop reasons and errors.

**The shared OpenAI layer, reused by chat in #42998**
- **`sglang-processor` `openai` feature:** the `Responder` API, `OpenAiSettings`, and `Unsupported` for requests not reproduced exactly. Python-shaped errors and usage (`wire.rs`), and logprob token bytes (`pieces.rs`).
- **Router plumbing:**
  - reads the OpenAI server args from each worker's `/server_info`;
  - decides between `/generate` and the engine's own route;
  - rewrites SSE frames;
  - counts each outcome in `sgl_router_openai_route_total{outcome}`.

  Sampling overrides, rid, PD bootstrap and DP rank apply as for `/generate`.
- **Fallback:** these go to the engine's own `/v1/completions` as sent:
  - workers that disagree on the server args or never report them;
  - `--completion-template`;
  - `sglext` outputs;
  - `echo` or `logprobs` without a router tokenizer;
  - bodies SGLang would reject.
- **Parity harness:** `tests/openai_parity.rs` replays fixtures that `tests/scripts/generate_openai_parity.py` records by running SGLang's own handler on a live engine's `/generate` output.

- Router lib, component and proxy tests pass, and clippy and fmt are clean.
