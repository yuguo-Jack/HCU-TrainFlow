# [Fix] scheduler: Bind request receivers to their selected transport

[Upstream PR](https://github.com/sgl-project/sglang/pull/47456) · state: open · merged: False

## Original PR description

## Motivation

A request receiver must use the transport selected by its scheduler. It currently re-reads `SGLANG_RUST_SERVER` on every poll, and its constructor rejects callers that pass an explicit `rust_server_mode`. If the environment no longer matches the initialized transport, polling can try to call `drain` on a ZMQ socket.

## Modifications

Capture the transport mode when `Scheduler.init_request_receiver` constructs the receiver. Add a default-false constructor field for existing socket callers and use that field for dispatch. Add CPU regressions for both constructor modes, the actual scheduler initialization method, bounded ZMQ/msgpack receives, and ring dispatch after an environment change.

## Accuracy Tests

- The new regressions fail on the unmodified source and pass with this patch.
- CPU tests in `test_pp_cp_rank_offsets.py`, `scheduler_components/test_shm_tag_exchange.py`, and `test_mm_shm_error_consensus.py`: **22 passed, 7 subtests passed**. These include real ZMQ and Gloo/shared-memory checks. The ring uses a test double; native Rust frontend and accelerator execution were not tested.
- Changed-file pre-commit checks, the normal commit hook, and the full-repository pre-push hooks pass.

## Speed Tests and Profiling

This is a transport compatibility fix. No inference speed or model-output claim is made.
