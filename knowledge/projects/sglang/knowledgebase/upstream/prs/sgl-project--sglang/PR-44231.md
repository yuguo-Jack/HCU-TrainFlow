# [Perf] gemma3: Pool the projector input in channels-last

[Upstream PR](https://github.com/sgl-project/sglang/pull/44231) · state: open · merged: False

## Original PR description

## Motivation

`Gemma3MultiModalProjector` makes the vision output NCHW-contiguous before `avg_pool`. After `flatten(2).transpose(1, 2)` the pooled tokens are `[B, 256, hidden]` with `stride(-1) = 256`, so `mm_soft_emb_norm` gets a transposed input and the XPU path needs a copy before `gemma_rmsnorm` (#44225).

The view before that `.contiguous()` is already channels-last, since it comes from the token-major vision output. Pooling it directly keeps that layout, so the pooled tokens come out contiguous.

## Modifications

- `models/gemma3_mm.py`: drop the `.contiguous()` before `avg_pool`.

With this, the `stride(-1) != 1` copy in `Gemma3RMSNorm.forward_xpu` (#44225) no longer triggers for Gemma-3.

## Test

Pooled output vs the current code, for a `[B, 4096, 1152]` vision output:
- Intel Arc Pro B60 and CPU, bf16/fp16/fp32: bit-equal, and now contiguous (`stride (294912, 1152, 1)`).
- B60, bf16, B=8: pooling plus the copy for the norm, 660.6 µs → 377.8 µs.
