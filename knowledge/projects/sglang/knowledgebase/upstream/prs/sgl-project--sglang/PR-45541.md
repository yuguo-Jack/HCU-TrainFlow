# [Fix] [NPU] dspark: Dispatch Markov sampling to sgl-kernel-npu

## Original PR description

<!--StartFragment-->
<h2>Motivation</h2>
<p>DSpark sampling and greedy verification on NPU still use several PyTorch operations in the inference path. This PR integrates the Triton implementations from sgl-kernel-npu through sampling interfaces compatible with the GPU implementations.</p>
<p>Requires the companion sgl-kernel-npu change at <code>23feeece4c</code>.</p>
<h2>Modifications</h2>
<ul>
<li>Add platform dispatch through <code>ops/sampling/renorm.py</code>, including the MarkovSampleStep entry point.</li>
<li>Route NPU Markov greedy sampling, row argmax, and temperature softmax through sgl-kernel-npu.</li>
<li>Route the shared DFlash/DSpark acceptance-length and bonus-token calculation through the fused NPU implementation.</li>
<li>Preserve existing CUDA and CPU execution paths.</li>
</ul>
<h2>Accuracy Tests</h2>
<p>Validated SGLang <code>4a843b025c</code> with sgl-kernel-npu <code>23feeece4c</code> on 8 Ascend 910C cards, using TP=16 and attention DP=16.</p>
<p>Test case:
<code>test_npu_deepseek_v4_flash_w8a8_8p_gpqa</code></p>
<p>Model: DeepSeek-V4-Flash-0731-w8a8.</p>
<p>Evaluated all 198 GPQA Diamond questions with batch size 128, temperature=1, top_p=1, high thinking effort, and max_tokens=125000. The harness used local weights/dataset paths and installed EvalScope, with one evaluation attempt per variant.</p>

Metric | Parent baseline | This change
-- | -- | --
Correct answers | 178/198 | 180/198
Accuracy | 89.90% | 90.91%
Weighted draft acceptance rate | 39.66% | 39.19%
Weighted acceptance length, including bonus | 3.379 | 3.351


<p>Mean TPOT changed from 13.494 to 13.461 ms for greedy sampling and from 20.766 to 20.467 ms for probability sampling. All measured cases completed 128/128 requests.</p>
<p>These are single warmed measurements; repeated-run variance is unknown. Initial runs showed higher latency: GPQA mean TTFT increased from 9.99 to 32.93 seconds, and mean TPOT from 66.70 to 176.49 ms. Further profiling is needed to explain these initialization-inclusive differences. No GPU performance-parity claim is made.</p>

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Pin the NPU package that provides this sampler**

In the official NPU image and CI environment, `sgl-kernel-npu` is still pinned to `2026.9.0.post9` (`docker/npu.Dockerfile` and `scripts/ci/npu/npu_ci_install_dependency.sh`), while `markov_sample_step` is introduced only by the companion 998f742 change called out in this commit. Consequently, selecting DSpark (and also DFlash, which imports this module for `resolve_greedy_mask`) with the repository's pinned NPU environment raises `ImportError` while importing `dspark_draft`, before a worker can start. The companion implementation needs to be released and the pin updated as part of this integration, or this import needs a compatible fallback.
