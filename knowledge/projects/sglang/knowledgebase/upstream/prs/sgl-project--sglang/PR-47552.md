# [Perf] R3: Keep the routed-expert host cache only on the output rank (1/3)

[Upstream PR](https://github.com/sgl-project/sglang/pull/47552) · state: closed · merged: True

## Original PR description

## Why?

With `--enable-return-routed-experts`, every rank keeps a pinned host copy of the routed experts, but only one rank per DP group, the one that talks to the detokenizer, ever sends them out. This is bad for CPU RAM constrained case like GB300.

```text
Before (TP8, no DP attention)                      After (TP8, no DP attention)
rank 0: capture → D2H → host cache → output        rank 0: capture → D2H → host cache → output
rank 1: capture → D2H → host cache   (never sent)  rank 1: capture
  ...                                                ...
rank 7: capture → D2H → host cache   (never sent)  rank 7: capture

Nemotron 3 Ultra, 11.4M-token KV pool, pinned host memory:
        8 × 101 GiB = 808 GiB                      1 × 101 GiB = 101 GiB
```

With DP attention, each DP group has its own output rank, so one cache per group stays:

```text
TP8, --attn-dp-size 2 (attention TP 4 per group), DeepEP

               Before                                         After
group 0  r0:   capture → AG → D2H → host cache → output       capture → AG → D2H → host cache → output
         r1-3: capture → AG → D2H → host cache (never sent)   capture → AG
group 1  r4:   capture → AG → D2H → host cache → output       capture → AG → D2H → host cache → output
         r5-7: capture → AG → D2H → host cache (never sent)   capture → AG

AG = attention-TP all-gather of DeepEP's scattered tokens; r1-3 and r5-7 still join it.
Pinned host caches: 8 → 2, one per DP group.
```
## What?

- Only the output rank of each DP group (`pp_rank == attn_tp_rank == attn_cp_rank == 0`, the scheduler's `is_rank_zero`) allocates the host cache.
- Other ranks still capture on the device (the all-gather needs them) but skip the copy and the readback.

## Verification?

8×H200, Qwen3-30B-A3B-Instruct-2507, base `main` at `7146002be8`. ITL = median inter-token latency from `bench_serving`, 1024 in / 256 out, median of 3 runs. Each setup ran main and this PR on one node with no profiler; a repeat of main at the end matched to 0.004 ms (**observed**):

```text
                                         main                   this PR
A  --tp 8                   host cache   8 × 6.88 = 55.0 GB     1 × 6.88 =  6.9 GB   (−48 GB)
                            ITL c1       3.620 ms               3.621 ms
                            ITL c128     8.210 ms               8.227 ms
B  --tp 8 --dp 2            host cache   8 × 7.08 = 56.6 GB     2 × 7.08 = 14.2 GB   (−42 GB)
   DP attention + DeepEP    ITL c1       5.429 ms               5.421 ms
                            ITL c128     7.458 ms               7.462 ms
                            TTFT c1      60.9 ms                60.9 ms
routed experts, 4 greedy prompts                                bitwise identical to main
```

Repro:

```bash
# A
python -m sglang.launch_server --model-path Qwen/Qwen3-30B-A3B-Instruct-2507 --tp 8 \
  --enable-return-routed-experts --mem-fraction-static 0.85
# B (FP8: on main, BF16 DeepEP low-latency mode asserts)
SGLANG_DEEPEP_NUM_MAX_DISPATCH_TOKENS_PER_RANK=1024 python -m sglang.launch_server \
  --model-path Qwen/Qwen3-30B-A3B-Instruct-2507-FP8 --tp 8 --dp 2 --enable-dp-attention \
  --moe-a2a-backend deepep --deepep-mode auto --enable-return-routed-experts --mem-fraction-static 0.85
# client, concurrency 1 / 8 / 32 / 128
python -m sglang.bench_serving --backend sglang --dataset-name random-ids \
  --random-input-len 1024 --random-output-len 256 --random-range-ratio 1 \
  --num-prompts 8 --max-concurrency 1 --extra-request-body '{"return_routed_experts": true}'
```

- Speed is unchanged: the output rank does the same work as before.
- The 101 GiB per rank for Nemotron 3 Ultra was **observed** on our internal sglang fork.
