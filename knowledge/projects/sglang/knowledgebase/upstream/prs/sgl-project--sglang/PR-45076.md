# [Fix] hicache: Count the EAGLE bigram boundary token in PD decode restores

[Upstream PR](https://github.com/sgl-project/sglang/pull/45076) · state: closed · merged: True

## Original PR description

## Motivation

#40857 lets EAGLE / EAGLE3 run with `--disaggregation-decode-enable-radix-cache`, so the decode tree of a non-Mamba model uses bigram keys: N cached positions are keyed by N + 1 token ids. Decode HiCache counts its prefix lengths (`l1`, `l2`, `l3`, `decode_prefix_len`) in bigrams, but passes them back as token counts in two places:

- `_try_hicache_queue_load_back` rematches with `max_prefix_len=decode_prefix_len`. That becomes `RadixKey.limit` (a token cap), so the bigram key has `decode_prefix_len - 1` entries and the page-aligned rematch stops one page short. `device_prefix_len + loaded_len < decode_prefix_len` then always holds, the restore is marked FAILED, and every request that hits L2 or L3 is aborted ("HiCache restore failed").
- `_start_hicache_prefetch` slices `l3` token ids for the prefetch, which `prefetch_from_storage` turns into `l3 - 1` bigrams, so the prefetch also lands one page short.

Mamba trees disable bigram keys and are not affected. The non-PD path passes every remaining token and is not affected either.

## Modifications

- Both call sites add the bigram boundary token (`int(tree_core.is_eagle)`) when they turn a prefix length into a token count.

## Tests

- `test_decode_restore_rematch_covers_bigram_prefix` (CUDA): a real EAGLE `UnifiedRadixCache` with a host-only 16-position prefix, the real `match_kv_cache`, and the real `_try_hicache_queue_load_back`. It runs on both the Rust and the Python tree core.
- `test_storage_probe_and_prefetch_use_node_handles` now also checks the EAGLE prefetch span.
- Negative control: with the fix reverted, both tests fail. The real-cache test logs `HiCache load_back failed ... new_indices=12, expected decode_prefix_len=16`.
- `test_decode_hicache_tree_core.py`, `test_decode_queue_cleanup.py`, `test_decode_radix_lock_ref.py` and `test_unified_radix_cache_unittest.py` all pass on 1x H200: 1386 passed, 1585 skipped, 89 subtests passed. The new class also passes with `SGLANG_UNIFIED_RADIX_TREE_CORE_BACKEND=python`.
