# [Perf] [AMD] dsa: Replicate the DCP query projection on the owned route

[Upstream PR](https://github.com/sgl-project/sglang/pull/47180) · state: closed · merged: True

## Original PR description

## Motivation

On the owned DSA DCP route from [#44322](https://github.com/sgl-project/sglang/pull/44322), every MLA layer all-gathers the full-head query (`[T, H, 576]`) before attention, in decode and in every DSA extend, and the a2a merge ships each head's partial at `kv_lora_rank` (512) wide. This PR removes the query all-gather and halves the a2a payload, without changing what attention computes:

- **Q replication**: every rank holds the whole DCP group's `q_b_proj` and `w_kc`, so it projects all query heads locally. `--dcp-replicate-q-proj` (already on by default for DeepSeek-family models on the a2a backend) now also covers DSA extend on HIP, not just decode.
- **Project before merge**: the LSE merge is linear in the partial output, so every partial is V-projected first and the a2a carries `v_head_dim` (256) instead of `kv_lora_rank` (512) per head.

## Modifications

- **Replicate `q_b_proj` / `w_kc` across the DCP group** (`model_runner.py`, `forward_mla.py`)
    - The model runner all-gathers `q_b_proj` and `w_kc` once before graph capture. The local `q_b_proj` weight then aliases its own slice of the replica, so replication adds `(W-1)/W` of the weight instead of doubling it.
    - GLM keeps `w_kc` / `w_vc` as per-tensor FP8 on gfx95; they are dequantized to bf16 before the gather instead of skipping the layer.
    - `is_dcp_q_replicate_phase` also returns true for DSA extend on HIP, so prefill skips the Q all-gather too.
- **Project before merge** (`forward_mla_rocm.py`, `deepseek_v2.py`)
    - With the a2a backend and an unquantized `o_proj`, each rank V-projects the partials of every group head with the replicated `w_vc` before the a2a, and the merged result goes straight to `o_proj`.
- **Token-major absorb** (`forward_mla_rocm.py`, `dcp_kernels.py`)
    - The absorb bmm writes `[T, H, kv_lora_rank]` directly instead of transposing a head-major result. A small Triton per-head bmm (`head_bmm`) serves batches up to 288 tokens; larger ones use `torch.bmm` on transposed views.

Scope: Without `--dcp-size > 1` nothing changes. The new extend path is gated on `is_hip()` and DSA; CUDA keeps the decode-only behavior. `--no-dcp-replicate-q-proj` restores the old route. No new environment variables.
