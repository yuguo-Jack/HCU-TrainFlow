# [Perf] [AMD] Kimi-K3: select MLA verify kernel on the host with per-regime verify graphs

[Upstream PR](https://github.com/sgl-project/sglang/pull/46651) · state: open · merged: False

## Original PR description

## Motivation

With an FP8 KV cache on gfx950, Kimi-K3 `target_verify` is slow on any single kernel: `mla_gluon` wins at short contexts and the HipKittens kernel wins from a few thousand tokens up (up to 7x at bs=12, 128k). This PR picks the kernel on the host and captures one verify graph per kernel, following the review on ROCm/aiter#6961.

## Modifications

- `SGLANG_AITER_MLA_VERIFY_BACKEND` defaults to `auto`. `asm` and `gluon` still force those paths and bypass K3 selection.
- In `auto` on gfx95 with FP8 KV, 8 draft tokens and no DCP, the AITER backend picks the kernel with AITER's `select_mla_verify_kernel(bs, max(seq_lens_cpu) + num_draft_tokens)` and calls `mla_verify_hk` or `mla_gluon`. When the host `seq_lens_cpu` is missing it picks `mla_verify_hk`, which serves any length, instead of reading the device lengths.
- `K3MlaVerifyGraphVariants` (`graph_variants.py`) captures a `gluon` and an `hk` verify graph per batch size through the existing attention-variant graph machinery, and replays the one the host picked.
- The K3 path no longer builds `get_mla_metadata_v1`, which neither kernel reads.
- The HipKittens kernel now lives in AITER, so its SGLang JIT source, asm generator, wrappers and kernel test are removed.

## Accuracy Tests

Kimi-K3, TP8 MI355X, FP8 KV, DFlash, `max-running-requests=12`, vs the same deployment on the previous on-device switch (McNemar):
- GPQA-D: 87.9% vs 87.4% (p=1.0); B300 86.9%
- AIME25: 93.3% vs 90.0% (29/30 graded on the baseline); B300 96.7%

`test/registered/unit/layers/test_k3_mla_verify_graph_variants.py` (selector input, both variants, decode/forced/unsupported paths): 3 passed on MI355X.

## Speed Tests and Profiling

One verify layer under graph replay, 1x MI355X, 25 shapes (bs 1-12, ctx 1k-128k): host selection is 1.0-5.8 us/layer faster than the on-device switch on 22 shapes and within run-to-run noise at bs 8/12 with 128k (3 repeated runs). Capturing both variants takes 0.46 GB vs 0.44 GB for the single graph. Full table in the AITER PR.

## Dependencies

ROCm/aiter#6961 (`aiter.mla_verify`). Without it, `auto` keeps the previous `asm` default.
