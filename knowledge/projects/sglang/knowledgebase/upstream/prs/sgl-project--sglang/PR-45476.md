# [Test] [AMD] moe: Expect gfx1250 W4A8 layers to build with expert parallelism

[Upstream PR](https://github.com/sgl-project/sglang/pull/45476) · state: closed · merged: True

## Original PR description

## Motivation

`base-a-test-cpu` has been red on `main` since #44993 merged: `TestLayerRunnerDispatch.test_gfx1250_internal_router_requires_full_expert_weights` fails with `AssertionError: ValueError not raised` (for example [this run on #45472](https://github.com/sgl-project/sglang/actions/runs/39522706249/job/118970333904); it reproduces on `main` at c0d18c0254).

The test asserts the behaviour from before #45365: that building a gfx1250 W4A8 MXFP4 MoE layer with expert parallelism raises, because the kernel routed raw logits over the full expert set. #45365, merged a few hours before #44993, made that path EP-aware: `_ep_routing` takes top-k over the global experts and maps it onto this rank's shard through `build_ep_expert_map`. Nothing raises any more, so the expectation is stale. The conflict went unnoticed because `base-a-test-cpu` was skipped on #44993's final head (79da05c6), so the new test never ran against #45365's code before merging.

## Modifications

Test-only. The test now asserts the current contract:

- the layer builds as a direct kernel (`runner_backend is None`, local-ID dispatch) at both `moe_ep_size=2` (the class default) and `moe_ep_size=1`;
- `build_ep_expert_map` gives rank 1 of 2 global experts 2 and 3, with the trailing slot keeping the -1 padding route at -1.

Renamed to `test_gfx1250_internal_router_maps_global_routes_to_the_local_shard`.

## Test plan

- The base-a CPU suite on this PR runs the updated test. It was not run locally.
- `black --check` is clean on the changed hunk.
