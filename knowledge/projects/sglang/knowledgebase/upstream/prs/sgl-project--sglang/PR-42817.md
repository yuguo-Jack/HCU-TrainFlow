# [KV events] Publish opaque LoRA block IDs and adapter names

[Upstream PR](https://github.com/sgl-project/sglang/pull/42817) · state: open · merged: False

## Original PR description

LoRA blocks need a public adapter name for prompt lookup and an opaque block ID for stores, parent links, and removals. This adds LoRA support to the default KV-event mode while preserving existing base-model and salt-only events.

## Changes

- Publish `BlockStored.lora_name` for admitted LoRA requests in both existing event modes. The optional name is appended to the tokenized IPC structs; older senders can omit it and resolve the name from the admitted adapter ID.
- In default mode, namespace LoRA block IDs by the internal `extra_key`, including the adapter load's UUID. Two loads of the same public adapter name retain different external IDs. Use the same mix for stored blocks, parent links, and removals.
- Keep the existing Dynamo-mode block-ID algorithm. Routers derive their own lookup keys from tokens, `lora_name`, and `cache_salt`; external IDs do not need to be reproducible from a request.
- Keep non-LoRA default events byte-identical, including salt-only events and omitted `lora_name` fields. Tree keys, HiCache storage keys, model execution, and LoRA loading/scheduling are unchanged.
- Retain selected namespace names for the publisher lifetime. A write-back host store can arrive after the last GPU removal and after the request has finished, so request/block counts alone cannot safely prune identities. The table costs one name entry per selected `(adapter load, extra_key)` namespace.
- Both Python and Rust tree paths emit the same default LoRA IDs. Rust event coalescing preserves `extra_key` boundaries and the Python adapter applies the default mix.

The router follow-up is #42818, which separates external IDs from canonical prompt lookup keys.

## Validation

- Native Rust tree-core tests: 931 passed, 1 ignored.
- Python CPU checks: 44 radix-cache tests, 35 cache-hash utility tests, 14 unified-cache KV-event tests, and 23 publisher/wire tests passed.
- All 10 engine-derived prompt lookup parity cases passed, including LoRA, salt, and combined namespaces; the checker also validates opaque LoRA IDs.
- Black, isort, and diff whitespace checks passed.

Python checks ran on macOS with the production native hash C++ source compiled against the system SHA-256 provider. The Linux-only extension loader was replaced with that compiled module for the checks. Python/Rust binding integration, CUDA HiCache transitions, and serving E2E were not rerun: the GPU devbox was evicted for low ephemeral storage.

## Limit

Reloading different weights under the same public adapter name can still credit old blocks until eviction, as in Dynamo/vLLM. Distinct external IDs prevent removals of one load from revoking another; versioned public names are needed to distinguish weights in request lookup.
