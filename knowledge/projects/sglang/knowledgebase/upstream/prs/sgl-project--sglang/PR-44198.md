# [Fix] [AMD] activation: Run ReLU2 natively on ROCm

[Upstream PR](https://github.com/sgl-project/sglang/pull/44198) · state: closed · merged: True

## Original PR description

## Motivation

`ReLU2` (squared ReLU, used by Nemotron-H's MLP) has no `forward_hip`. On ROCm the dispatcher falls back to `forward_cuda`, which calls the JIT `relu2` kernel; that kernel is CUDA-only and is only imported on CUDA, so the model fails to start:

```
NameError: name 'relu2' is not defined
```

## Modifications

- `ReLU2.forward_hip`: use `forward_native` (`relu(x) * relu(x)` in torch).
- No change on CUDA or other platforms.

## Accuracy Tests

MI350X, `rocm/sgl-dev:v0.5.22-rocm724-mi35x-20261019` (upstream/main of 2026-10-19), `nvidia/NVIDIA-Nemotron-Nano-9B-v2`, `--attention-backend triton --enable-deterministic-inference`, with this change and the Mamba2 import fix (#44197; without it the model stops earlier): before, `NameError: name 'relu2' is not defined` at startup; after, the server starts and serves (GSM8K 75.28%, all 1,319 questions, temperature 0, `sgl-eval` 0.1.2; 26% of answers hit the 2,048-token limit). `SGLANG_USE_AITER=0`.

Normal mode on ROCm still needs `flashinfer`, which the ROCm image does not ship (`ModuleNotFoundError: No module named 'flashinfer'`, from the model's other code paths); not addressed here.

## Speed Tests and Profiling

ROCm only, and the model did not run before.
