# [Fix] MoE: reject K tiles that cross block-scale boundaries

[Upstream PR](https://github.com/sgl-project/sglang/pull/42737) · state: open · merged: False

## Original PR description

## Motivation

Each `tl.dot` in the block-scaled FP8/INT8 MoE kernel applies the scale of its starting K group. `BLOCK_SIZE_K` must therefore divide `group_k`. A tile crossing a scale boundary applies one scale to multiple groups and produces incorrect results.

The following H100 profile uses K tile 256 with quantization group 128 at M=64/128/256/512. The cross-version Triton configuration fallback can still load it:

```text
python/sglang/srt/layers/moe/moe_runner/triton_utils/configs/triton_3_5_1/E=512,N=256,device_name=NVIDIA_H100_80GB_HBM3,dtype=fp8_w8a8,block_shape=[128, 128].json
```

## Modifications

- Add `tl.static_assert(group_k % BLOCK_SIZE_K == 0)` in the block-scaled kernel branch as a lightweight compile-time check.
- Filter invalid candidates in the shared tuning worker, including the single-M entry point.
- Replace the four H100 entries with the existing valid M=96 configuration from the same file. Other parameters are unchanged.
- Extend the existing CPU configuration test to check all shipped block-scaled MoE profiles.
