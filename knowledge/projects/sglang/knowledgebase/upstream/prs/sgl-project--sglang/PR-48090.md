# [Perf] [AMD] spec: Skip the vocabulary-wide sort in MTP rejection-sampling verify

[Upstream PR](https://github.com/sgl-project/sglang/pull/48090) · state: open · merged: False

## Original PR description

## Motivation

On ROCm, EAGLE/NEXTN with `--speculative-eagle-topk 1` turns on rejection sampling by default. Each verify step then builds dense target probabilities for all `bs × num_draft_tokens` rows: a softmax over the vocabulary, `top_k_renorm_prob`, and `top_p_renorm_prob`. On HIP both renorms run a vocabulary-wide `torch.sort`, and top-p adds a `cumsum`. #46808 makes the top-p renorm sort-free, but the top-k renorm still sorts. The compact top-k branch (`SGLANG_OPT_SPEC_COMPACT_VERIFY_SAMPLING`) does not help either, because it requires rejection sampling to be off.

When every request has a top-k, only the top-k tokens of a row carry mass. Qwen3.8 ships `top_k=20` in `generation_config.json`, so every AgentX request has one. For Qwen3.8-Flash-Next (vocab 248,320) on MI355X at concurrency 16, the dense target probabilities take 2.2 ms of each decode step.

This PR builds the target probabilities on the top-k support and passes them to the unchanged `chain_speculative_sampling_triton`. The output matches the dense path, ties included. The target probabilities go from 2.74 ms to 0.30 ms at 64 rows, and eager time per decode step goes from 3.34 ms to 1.23 ms. Batches where a request has no top-k keep the dense path, which #46808 speeds up. #41283 takes the same top-k approach on CUDA, with a new chain kernel; it is CUDA-only and no longer applies to `main`.

## Modifications

- `eagle_utils.py`:
  - New `_sparse_rejection_target_probs` builds the target probabilities on each row's top-k support: `torch.topk` of `max_top_k + 32` logits, top-k mask, softmax, top-p mask, then a scatter into a zero `(rows, vocab)` tensor. The top-p cutoff is taken on the full distribution (`_adjust_top_p_for_top_k`), so the result equals the dense path of #41916 (top-p, then top-k), ties included. The 32 extra slots keep tokens tied with the k-th value.
  - `eagle_sample` uses it when rejection sampling is on and every request has `1 < top_k <= 128`. Otherwise the dense path runs.
  - `compact_verify_max_top_k` turns it on by default under rejection sampling when `_use_aiter` is true (`SGLANG_USE_AITER=1` on ROCm). CUDA and ROCm without AITER keep the dense path. `SGLANG_OPT_SPEC_COMPACT_VERIFY_SAMPLING=0` turns it off and `=1` turns it on everywhere.
- `uno_utils.py`: import `flashinfer.top_k` inside the one function that uses it, so ROCm can import the module.
- Tests:
  - `test_sparse_rejection_target_probs.py`: sparse vs dense Triton renorms on bf16-rounded logits, with mixed per-request top-k, top-p and temperature.
  - `test_eagle_post_verify_graphs.py`: the new default with `_use_aiter` on and off, and the off switch.

## Accuracy Tests

Image `rocm/sgl-dev:v0.5.23-rocm10-mi35x-20261102`, Qwen3.8-Flash-Next MXFP4, MI355X TP1, NEXTN 3 steps / 4 draft tokens. `main` is `f3ef1a32fd` and this PR is `5ad8f51b3c`; each arm ran on its own GPU with its `python/` tree first on `PYTHONPATH`, with `SGLANG_OPT_SPEC_COMPACT_VERIFY_SAMPLING` unset.

### Decode step profile

AgentX replay at concurrency 16, TP0 trace, 93 (main) and 97 (this PR) decode steps. Eager GPU ms per decode step, main → this PR:

| Kernel | ms/step |
|---|---:|
| rocprim sort (top-k and top-p renorms) | 1.34 → 0 |
| `tensor_kernel_scan_innermost_dim` (top-p cumsum) | 0.61 → 0 |
| `sort_postprocess_kernel` + vocabulary softmax | 0.26 → 0 |
| `torch.topk` (`mbtopk`) | 0 → 0.16 |
| Full-vocabulary top-p mass (`triton_red_fused_div_exp_sub_sum`) | 0 → 0.02 |
| Total eager time per decode step (median) | 3.34 → 1.23 |

The median graph time per decode step is 25.9 ms for main and 26.4 ms for this PR.

### AgentX benchmark

- Hardware: MI355X, TP1/EP1, one point at a time with nothing else on the node, one run per arm.
- Model and recipe: Qwen3.8-Flash-Next MXFP4, InferenceX recipe `qwen3.8next/sglang/mi355x-fp4-mtp/agentic.yaml` (NEXTN 3 / 1 / 4), image `rocm/sgl-dev:v0.5.23-rocm10-mi35x-20261102`.
- Client: the CI AgentX command on `semianalysis_cc_traces_weka_062126_256k`, 3600 s per run.
- Baseline is `main` at `f3ef1a32fd`; This PR is `5ad8f51b3c`. Each tree is mounted over the image's `python/` and run first on `PYTHONPATH`. Both arms run the same command; this PR needs no extra flag (the image sets `SGLANG_USE_AITER=1`, which turns the new path on). Higher throughput and interactivity are better.
