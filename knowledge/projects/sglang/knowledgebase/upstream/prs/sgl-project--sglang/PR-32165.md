# [ROCm] Tune MiniMax-M3 sparse prefill

[Upstream PR](https://github.com/sgl-project/sglang/pull/32165) · state: closed · merged: False

## Original PR description

## Motivation

MiniMax-M3 sparse prefill on ROCm currently processes each selected KV block as one full `BLOCK_SIZE_K` tile in the Triton kernel. For the 128-token sparse KV block shape used by MiniMax-M3, that creates a larger dot-product tile than needed for efficient MFMA scheduling and increases register/shared-memory pressure in the prefill kernel.

This PR tunes the sparse prefill kernel so each selected KV block is processed through smaller K sub-tiles while preserving the same online softmax accumulation across the whole sparse block list.

## Modifications

- Add a `SUB_K` compile-time parameter to the MiniMax sparse prefill Triton kernel.
- Split each selected `BLOCK_SIZE_K` KV block into `SUB_K` chunks for the QK and PV dot products.
- Keep the existing online softmax state (`m_i`, `lse_i`, and `acc_o`) across sub-tiles so the output remains mathematically equivalent to processing the full selected KV block at once.
- Use a single CDNA-tuned autotune candidate for this kernel path: `num_warps=1`, `num_stages=1`.
- Pass `matrix_instr_nonkdim=16` and `kpack=2` to guide Triton codegen for the sub-tiled dot products.

## Accuracy Tests

This change preserves the existing sparse attention computation order at the selected-block level and updates only the internal K tiling within each selected block.

Static validation:

