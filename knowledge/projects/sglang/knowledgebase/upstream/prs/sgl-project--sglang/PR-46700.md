# [Fix] mem_cache: Clamp SWA tombstone recovery to the request's protected prefix

[Upstream PR](https://github.com/sgl-project/sglang/pull/46700) · state: closed · merged: True

## Original PR description

## Motivation

The unified radix tree could free FULL KV pages that a node still mapped. A request owns FULL pages only from its protected prefix (`prev_prefix_len`) upward; below it, the request's row holds the node's own canonical page ids by reference. `SWAComponent.update_component_on_insert_overlap` recovered an SWA-tombstoned fragment from the request's row starting at the request's SWA eviction cursor, and clamped that cursor to the protected prefix only for independent windows.

A single-chunk request has a cursor of 0, and a read-only FULL prefix match can leave the protected prefix strictly inside a node, so the recovery also covered pages the request never owned. Those pages were freed as if they were the request's duplicates (the swap branch's old FULL ids, or the locked branch's incoming ids) while the node kept mapping them. Once they re-entered the free list, the next allocation overwrote KV the node was still serving, so a later reader of that node could see another request's KV.

```
position     0                16            24      (page size 4, SWA window 8)
             |-- protected ---|---- own ----|
node N       [ p0 p1 p2 p3 ]  [ p4 p5 ]              FULL resident, SWA evicted
request row  [ p0 p1 p2 p3 ]  [ q4 q5 ]              p0..p3 borrowed by reference, q4 q5 fresh

before: recovery starts at the SWA cursor (0)
        locked node   -> frees "incoming" p0..p3     node still maps p0..p3   => double free
        unlocked node -> adopts p0..p3, frees "old" p0..p3                    => double free
after:  recovery starts at max(cursor, 16) = 16
        only [p4 p5] vs [q4 q5] is reconciled; p0..p3 untouched
```

## Modifications

`python/sglang/srt/mem_cache/unified_cache/components/swa.py`: the recovery window now starts at `max(evicted_seqlen, prev_prefix_len)` for both window kinds instead of only for independent windows. A node straddling the protected prefix is clipped there, so the head keeps its canonical ids and only the tail is recovered. Positions below the protected prefix are never the request's contribution.

Behaviour is unchanged when the cursor is already at or above the protected prefix (chunked and decode inserts) and for independent windows, which were clamped before. No allocator, scheduler, or controller change. The Rust tree core under `rust/sglang-radix-tree` keeps its own recovery path and is not changed here.
