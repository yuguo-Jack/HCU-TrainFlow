# [Disagg] Fix NIXL TypeError when SGLANG_DISAGG_STAGING_BUFFER=1

[Upstream PR](https://github.com/sgl-project/sglang/pull/42685) · state: closed · merged: False

## Original PR description

## Motivation

Fixes #42684.

`NixlKVManager.set_kv_buffer_tensors()` does not accept the `slot_layer_ids` keyword, but both call sites pass it whenever `SGLANG_DISAGG_STAGING_BUFFER=1` and the model is non-MLA:

- `python/sglang/srt/disaggregation/prefill.py` (`_init_kv_manager`)
- `python/sglang/srt/disaggregation/decode.py` (role-switch path)

With `--disaggregation-transfer-backend nixl` the server therefore crashes during kv_manager init, before serving any request:

```
File ".../sglang/srt/disaggregation/prefill.py", line 332, in _init_kv_manager
    kv_manager.set_kv_buffer_tensors(
TypeError: NixlKVManager.set_kv_buffer_tensors() got an unexpected keyword argument 'slot_layer_ids'
```

The Mooncake backend (`mooncake/conn.py`) already accepts and stores this argument; NIXL was not updated when the parameter was introduced. This happens regardless of TP topology (the flag is evaluated at init), and only for non-MLA models (MLA skips the call via the `is_mla_backend` guard).

Reproduced on v0.5.19, v0.5.20 and current `main`. Full repro, control run and `check_env` are in #42684.

## Modifications

Align the NIXL signature with Mooncake in `python/sglang/srt/disaggregation/nixl/conn.py`:

- add `slot_layer_ids: Optional[List[int]] = None` to `NixlKVManager.set_kv_buffer_tensors`
- stash it in `kv_buffer_tensors["slot_layer_ids"]` for parity

The NIXL staged send path does not yet consume `slot_layer_ids` (it does not pair slots by layer id for PP>1 the way Mooncake does), so runtime behaviour is otherwise unchanged. This PR only removes the startup crash; PP>1 + draft-pool support for the NIXL staged path can follow separately.

**Overlap note:** the same hunk is present incidentally in #40909 (hetero-TP for hybrid SWA) and #40861 (Intel XPU staging), both of which need it to get past init. It is split out here so it can land independently of those larger changes; whichever merges second needs only a trivial rebase.

N/A — no change to transfer logic; a pure signature fix. Homogeneous-TP requests do not use the staging path at all (`require_staging` is only set when `prefill attn_tp_size != decode attn_tp_size`).
