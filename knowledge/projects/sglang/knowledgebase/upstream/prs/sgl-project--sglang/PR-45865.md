# [Fix] qsa: Carry QSA indexer state through cpu_tensor retraction

[Upstream PR](https://github.com/sgl-project/sglang/pull/45865) · state: open · merged: False

## Original PR description

## Motivation

Fixes #45864. `QSATokenToKVPool` inherits a `get_cpu_copy` / `load_cpu_copy` that doesn't know about the QSA buffers, so a request resumed after `cpu_tensor` retraction uses another request's compressed index keys and pending ring.

## Modifications

Override `get_cpu_copy` / `load_cpu_copy` in `QSATokenToKVPool` to also carry the request's compressed index keys and its pending key/RoPE ring. Groups keep request order, so restoring into different pages still lines up.

## Accuracy Tests

- New CPU test `test/registered/unit/mem_cache/test_qsa_retraction_backup.py`: 4 of 5 fail on main, all pass here.
- mem_cache / disaggregation unit tests: no new failures vs main.
