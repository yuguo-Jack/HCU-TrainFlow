# [Fix] multimodal: Redact media from loader errors

[Upstream PR](https://github.com/sgl-project/sglang/pull/37449) · state: open · merged: False

## Original PR description

## Motivation

Refs #37419. Failed multimodal loads can include authenticated URLs or inline media in both the outer error and its chained traceback. Truncating the input still exposes credentials and payload prefixes.

## Modifications

```diff
 _load_single_item
-  include raw input and chain the original loader exception
+  describe the input without its contents
+  redact URLs and inline media throughout the exception chain
+  preserve client ValueError versus server RuntimeError classification
```

The registered CPU regression covers malformed URLs, authenticated ImageData URLs and inline data URIs. This update merges current main, satisfies the current MIN_BASE_SHA, and removes one parser-version-specific diagnostic assertion while retaining the privacy and exception-type assertions. Existing image decoding and video device selection remain unchanged.

- Before the fix on current main: the 10 original bad-input tests passed, while three additional privacy reproductions exposed request media in formatted exceptions.
- After integration: 13 bad-input tests and 10 original image-decoding tests passed.
- A separate CPU harness used the real BaseMultimodalProcessor constructor, production task submission and ThreadPoolExecutor/Future path: nested client-error redaction, malformed URL redaction and valid PNG eager decoding passed.
- Changed executable line coverage: 47/57 (82.46%) against current main. Coverage started after normal imports because instrumenting package startup crashed on this environment; unmeasured declaration lines remain counted as uncovered.
- `pre-commit run --all-files` passed, including Rust formatting and clippy.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Avoid parsing malformed URLs during error handling**

When a client supplies a URL with a malformed bracketed host, such as `https://[invalid`, the media loader rejects it and enters this sanitization path, but `urlsplit(data)` itself raises `ValueError: Invalid IPv6 URL`. Because this occurs outside the loader's exception handler, it replaces the intended modality-aware error and sanitized cause chain. Derive the already-recognized scheme without reparsing the untrusted URL, or catch parser failures here.
