# [Perf] dsv41: Cut encoder SWA bounded-replay window copies from ~4.2 ms to ~0.1 ms per decode step

[Upstream PR](https://github.com/sgl-project/sglang/pull/42715) · state: open · merged: False

## Original PR description

## Motivation

With `--enable-encoder-swa-bounded-replay`, the DeepSeek-V4.1 target keeps each request's SWA state in a `RequestWindow`. Before each attention layer, `buffer` gathers the window history into the workspace. After the layer, `commit` writes the step's tokens back and tags them.

Both went through `copy_packed_tokens`, which moved the data and scale rows with tensor indexing, and each layer recomputed the row indices with `torch.where`. That is 72 kernel launches per layer for one gather and one commit, measured with `torch.profiler` in the benchmark below; for the 43 layers of DeepSeek-V4.1-Flash that is 3,096 launches per decode step, all inside the decode CUDA graph.

## Modifications

- New `sglang/kernels/ops/attention/dsv4/request_window.py` with two Triton kernels, registered in the attention kernel inventory:
  - `gather_window_history` computes each history row's source (`req * capacity + pos % capacity`, or the zero row when masked) and copies its data and scale rows.
  - `commit_window_tokens` computes each new token's destination (or the sink row), copies the token, and records its position in `tags`.
  - Both run one program per token and copy int32 words, with the index math inside the kernel.
- `window_layout` makes `req` and `pos` contiguous. `.to(torch.int64)` returns an already-int64 view unchanged, and the commit kernel reads these arrays by program id without strides, so before this fix a strided view could select the wrong request rows and write past the state buffer. Both wrappers assert contiguous 1-D index and mask inputs.
- `RequestWindow.buffer` and `commit` call them. `copy_packed_tokens` is removed; it had no other callers. The eager history check in `buffer` is unchanged.

## Accuracy Tests

`test/registered/kernels/ops/attention/dsv4/test_request_window_copy.py` (CUDA) drives `RequestWindow.commit` (which runs `buffer`) and compares the state buffer, the workspace and the tags with a reference built from plain tensor indexing:
- **Eager**, for all three KV layouts (V4, V41, V41 FP4) and page sizes 16 and 64. The steps include multi-token requests, masked history before position 0, and a request with one more new token than its rounded capacity, so its oldest token goes to the sink row.
  - The sink row is excluded from the comparison, because several masked tokens can write it in no defined order.
- **CUDA graph**, for all three layouts at page size 16. The layout is refreshed in place after capture, with partly masked history, fresh state bytes and a poisoned workspace. A replay that skips the gather fails the test.
- **Strided inputs**: `test_strided_request_inputs` builds the layout from every-other-element views with an out-of-range request in the gaps and checks the commit against the indexing reference for all three KV layouts.

The eager and CUDA-graph tests also pass with main's `dsv41_request_window.py`, so they pin the copy behavior the kernels must keep; the strided-input test additionally checks that `window_layout` returns contiguous `req` and `pos`. All three pass with this change on an RTX PRO 6000 Blackwell (8 passed, 12 subtests).

## Speed Tests and Profiling

RTX PRO 6000 Blackwell Max-Q (SM120), torch 2.14.1+cu130, triton 3.8.0. Script: `bench_request_window_copy.py` (below), comparing main's `copy_packed_tokens` with this PR's kernels.
- 43 repetitions of one history gather and one commit (one per layer of DeepSeek-V4.1-Flash) are captured in a CUDA graph for each implementation.
- KV layout V4, page size 256, window 128, capacity 256, 6 new tokens per request.
- 5 warm replays, then 50 timed replays; the mean per step is reported.

```python
"""Per-step request-window copy cost, torch indexing vs the fused kernels.

One decode step of DeepSeek-V4.1-Flash encoder SWA replay copies (43 layers, each
a history gather and a commit, V4 KV layout, page size 256, window 128, capacity
256, 6 new tokens per request) is captured in a CUDA graph per implementation.
After 5 warm replays, 50 timed replays give the mean time per step. One eager
layer under torch.profiler gives the kernel launches per layer.

Run inside an image whose SGLang still has ``copy_packed_tokens``, with the
branch's ``sglang/kernels/ops/attention/dsv4/request_window.py`` copied to the
path in RWK (default /tmp/rwk.py):

    CUDA_VISIBLE_DEVICES=1 python bench_request_window_copy.py
"""

import importlib.util
import os

import torch
from torch.profiler import ProfilerActivity, profile

from sglang.kernels.ops.attention.dsv4.kv_layout import KVLayout
from sglang.srt.mem_cache.dsv41_request_window import copy_packed_tokens, window_layout

spec = importlib.util.spec_from_file_location("rwk", os.environ.get("RWK", "/tmp/rwk.py"))
rwk = importlib.util.module_from_spec(spec)
spec.loader.exec_module(rwk)
layout, page, LAYERS, cap, win = KVLayout.V4, 256, 43, 256, 128
dev = "cuda"


def timed(step):
    s = torch.cuda.Stream()
    s.wait_stream(torch.cuda.current_stream())
    with torch.cuda.stream(s):
        step()
    torch.cuda.current_stream().wait_stream(s)
    g = torch.cuda.CUDAGraph()
    with torch.cuda.graph(g):
        step()
    for _ in range(5):
        g.replay()
    torch.cuda.synchronize()
    a, b = torch.cuda.Event(enable_timing=True), torch.cuda.Event(enable_timing=True)
    a.record()
    for _ in range(50):
        g.replay()
    b.record()
    torch.cuda.synchronize()
    return a.elapsed_time(b) / 50 * 1000


def launches(layer_fn):
    layer_fn()
    torch.cuda.synchronize()
    with profile(activities=[ProfilerActivity.CUDA]) as prof:
        layer_fn()
        torch.cuda.synchronize()
    return sum(1 for e in prof.events() if e.device_type.name == "CUDA")


for bs in (1, 4, 8, 16):
    req = torch.arange(bs, device=dev).repeat_interleave(6)
    pos = (1000 + torch.arange(6, device=dev)).repeat(bs)
    lw = window_layout(req, pos, window=win, capacity=cap, num_groups=bs)
    rows = 16 * cap
    state = torch.zeros(rows // page + 1, layout.page_bytes(page), dtype=torch.uint8, device=dev)
    ws = torch.zeros(-(-lw.size // page), layout.page_bytes(page), dtype=torch.uint8, device=dev)
    tags = torch.full((rows + page,), -1, dtype=torch.int64, device=dev)
    zero_row, sink_row = rows, rows + 1

    def old_layer():
        src = torch.where(lw.history_valid, lw.history_req * cap + lw.history_pos % cap, zero_row)
        copy_packed_tokens(state, ws, src, lw.history_loc, page_size=page, layout=layout)
        dst = torch.where(lw.commit_mask, lw.req * cap + lw.pos % cap, sink_row)
        copy_packed_tokens(ws, state, lw.write_loc, dst, page_size=page, layout=layout)
        tags[dst] = lw.pos

    def new_layer():
        rwk.gather_window_history(
            state, ws, history_req=lw.history_req, history_pos=lw.history_pos,
            history_valid=lw.history_valid, history_loc=lw.history_loc,
            capacity=cap, zero_row=zero_row, page_size=page, layout=layout)
        rwk.commit_window_tokens(
            ws, state, tags, write_loc=lw.write_loc, req=lw.req, pos=lw.pos,
            commit_mask=lw.commit_mask, capacity=cap, sink_row=sink_row,
            page_size=page, layout=layout)

    def steps(layer):
        return lambda: [layer() for _ in range(LAYERS)]

    print(
        f"bs={bs}: torch indexing {timed(steps(old_layer)):.0f} us/step "
        f"({launches(old_layer)} launches/layer), fused {timed(steps(new_layer)):.0f} "
        f"us/step ({launches(new_layer)} launches/layer)"
    )
```
