# [AMD] Select Quark MXFP4 dense GEMM via --fp4-gemm-backend aiter|triton

[Upstream PR](https://github.com/sgl-project/sglang/pull/43360) · state: open · merged: False

## Original PR description

## Summary

Follow-up to #39598 as requested in review: extends the existing `--fp4-gemm-backend` CLI argument to support `aiter` and `triton` on ROCm, removing the need for a separate environment variable (`SGLANG_ROCM_USE_AITER_FP4_ASM_GEMM`).

- Add `'aiter'` (AITER CK/ASM `gemm_a4w4` with preshuffled weights on gfx95) and `'triton'` (AITER Triton `gemm_afp4wfp4`) to `Fp4GemmRunnerBackend` and valid choices.
- On ROCm, `--fp4-gemm-backend auto` maps to `triton` to keep existing baseline behavior unchanged.
- `QuarkW4A4MXFP4` reads the resolved backend at initialization instead of inspecting environment variables at import time.
- Deprecates `SGLANG_ROCM_USE_AITER_FP4_ASM_GEMM` with a clear deprecation warning when `--fp4-gemm-backend` is unset (`auto`).
- Updates documentation in `server_arguments.mdx` and `quantization.mdx`.
- Adds unit tests in `test_quark_mxfp4_asm.py`.

Stack: Depends on #39598.
