## Motivation

This PR enables Gemma4 GPTQ INT4 inference on CPU by addressing three limitations:
1. The input dimension per partition must be divisible by the quantization group size.

2. The Gemma4 Router projection disables quantization, preventing GPTQ INT4 weights from being loaded correctly.

3. The CPU INT4 fused-experts kernels only support SiLU, while Gemma4 requires GELU.
## Modifications
1. Introduce GPTQCPUGroupPadding to support non-group-aligned input dimensions by padding partition boundaries to align with quantization group boundaries. Both weights and activations are padded consistently, preserving the original group mapping and computational correctness.

2. Update the Gemma4 Router projection to use the model's GPTQ quantization configuration instead of unconditionally disabling quantization.

3. Extend the INT4 fused-experts execution path to support both SiLU and GELU activations.
