# [Perf] Compact GDN causal-conv grids for skewed prefill batches

[Upstream PR](https://github.com/sgl-project/sglang/pull/43570) · state: closed · merged: True

## Original PR description

## Motivation

GDN's prefill convolution launches a rectangular grid sized by the longest sequence. With an 8K prefill chunk and 127 decode rows, this schedules about 3.1 million CTAs, most of which immediately return. The same overhead is repeated across 36 GDN layers in Qwen3.5-122B-A10B.

## Modifications

Build a compact `(sequence, chunk)` table once per forward and reuse the existing causal-conv kernel's `block_table` path across layers. This reduces the example above to 27,264 CTAs without changing convolution arithmetic or state updates.

Enable this for CUDA EXTEND/MIXED batches only when the rectangular grid has more than four times as many sequence/chunk blocks as the compact grid. Uniform and mildly ragged batches keep the existing launch to avoid table-construction overhead. MIS, TBO, speculative modes, non-CUDA paths, and unavailable or mismatched host lengths retain the existing behavior.

This is narrower than the prefill/decode split in #36065: it only compacts the convolution grid and does not change GDN attention dispatch.

## Accuracy Tests

- Extended three existing test files; no new test files. On both H200 and GB300, all 29 tests and 55 subtests pass:
  ```bash
  python -m pytest -q \
    test/registered/unit/layers/attention/test_gdn_prefill_backend_policy.py \
    test/registered/unit/layers/attention/test_mamba_track_state_dtype.py \
    test/registered/attention/test_gdn_prefill_layout.py
  ```
- CUDA tests compare convolution output and the entire state cache bitwise, including strided QKV, ragged/empty rows, initial state, permuted cache indices, and a padded cache slot. A separate microbenchmark also checks bitwise output/state at the model's actual convolution dimension of 6,144.
- Full held-out GSM8K validation uses 1,314 cases, five separate few-shot examples, temperature 0, seed 42, concurrency 64, and a 2,048-token limit. Case IDs and prompt hashes match; all runs have zero request errors. The first and reverse-order pairs give:

  | Run | Correct / 1314 | Token-limit case IDs |
  | --- | ---: | --- |
  | Baseline A | 1270 | 119, 423, 641, 1176, 1183 |
  | Compact A | 1273 | 119, 711 |
  | Compact B | 1273 | 119, 304, 423 |
  | Baseline B | 1276 | 119, 423, 1176 |

  The first pair has three losses/six gains; the reverse pair has five losses/two gains. Case 711 is correct on the candidate repeat; case 304 is newly capped there. No case is correct in both baseline runs and incorrect in both candidate runs. Baseline answers also vary across repeats. These measurements do not establish identical full-model outputs or statistical non-inferiority.

- Default cached-path regression check (mixed chunk disabled): C128 throughput 2693.96 -> 2699.97 output tok/s, median TTFT 12.886 -> 12.913 s, TPOT 34.90 -> 34.86 ms, and p99 E2E 48.87 -> 48.72 s. Exact requests/token counts match. GSM8K is 1277/1314 in both runs, with three losses and three gains and zero errors; token-limit finishes increase from two to four (new cases 87 and 157). This is a completed regression check with the per-case differences disclosed, not a claim of identical model outputs.

## Speed Tests and Profiling

Same 2x H200, TP2, Qwen3.5-122B-A10B-FP8 revision `a099dee70ccfcd8d5dda56aaa0b60cb8ecadabc9`; baseline `e35f60b9`, candidate adds only this patch. Nominal 8192-token inputs and fixed 1024-token outputs, seed 42, 320/640 requests at C64/C128. Exact request records and actual token counts match. Timings exclude profiling and follow warmup/cache flush.

Both versions use FlashInfer full attention, Triton GDN prefill, BF16 Mamba state, `--enable-mixed-chunk`, and `--disable-radix-cache`. These numbers isolate the convolution change; they do not validate enabling mixed chunk with the default prefix-cache path.

| Concurrency | Version | Output tok/s | Median TTFT (s) | Median TPOT (ms) | p99 E2E (s) |
| --- | --- | ---: | ---: | ---: | ---: |
| 64 | Baseline | 2126.54 | 1.120 | 28.94 | 42.68 |
| 64 | Compact grid | 2204.10 | 1.024 | 27.85 | 40.95 |
| 128 | Baseline | 2470.12 | 1.205 | 50.92 | 79.48 |
| 128 | Compact grid | 2686.89 | 1.073 | 46.36 | 72.63 |
| 128 | Compact grid, repeat | 2698.68 | 1.068 | 46.09 | 72.21 |
| 128 | Baseline, reverse repeat | 2475.35 | 1.273 | 50.62 | 78.95 |

C64 output throughput improves by 3.6%. C128 improves by 8.8% in the first pair and 9.0% in the reverse-order pair (A-B-B-A), with matching request records and actual token counts. Median TPOT and p99 E2E also improve in both C128 pairs.

A second full pair using `--prefill-attention-backend fa3` also improves C64 from 2193.74 to 2275.06 output tok/s and C128 from 2564.33 to 2797.15 (+9.1%). At C128, median TTFT changes from 1.205 to 1.000 s, TPOT from 48.94 to 44.55 ms, and p99 E2E from 75.45 to 68.98 s. Inputs and actual token counts match. GSM8K is 1272/1314 in both versions, with three losses and three gains, zero request errors, and three token-limit finishes each (candidate case 425 is newly capped). This separately checks the FA3 prefill backend; the repeated same-configuration results above isolate the convolution patch.

For `[8065] + [1] * 127`, dimension 6144 and width 4, isolated convolution time changes from 1873.5 to 104.0 us on H200 and 1568.4 to 86.7 us on GB300. Host table construction plus transfer takes about 280 us once per forward, amortized across layers. The approximately 18x kernel speedup is not an end-to-end model speedup.

A separate TP2 trace with 127 active decode requests confirms the actual dispatch: across eight mixed steps and 288 convolution launches, per-rank convolution GPU time drops from 525.87 to 29.26 ms on rank 0 and 525.88 to 29.79 ms on rank 1. Decode progress differs between those profiling probes, so their total wall times are not treated as matched end-to-end measurements.
