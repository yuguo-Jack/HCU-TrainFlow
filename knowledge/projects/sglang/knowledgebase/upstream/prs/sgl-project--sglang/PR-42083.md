# [Encoder] Release conditions after abandoned metadata waits

[Upstream PR](https://github.com/sgl-project/sglang/pull/42083) · state: closed · merged: False

## Original PR description

## Motivation

An EPD decoder can request embedding metadata before `/encode` publishes it. When that encode never arrives, `/scheduler_receive_meta_data` returns 504 but leaves its condition in `rid_to_cond`. These requests have no metadata or TTL entry, so the stale-request sweeper cannot reclaim the conditions. Repeated failures grow the dictionary indefinitely.

## Modifications

- Keep conditions in a weak value registry. Active waiters and notifiers already retain their own condition references; metadata and destination predicates remain in their existing maps.
- Hold a strong local reference throughout condition lookup/creation and return, preserving one shared rendezvous while any caller uses it.
- Add timeout, cancellation, shared-waiter, publish-before-wait, and ownership tests. Retain a local condition owner in the existing ZMQ cleanup fixture.

This does not change explicit request discard behavior or metadata expiration.

## Accuracy Tests

- Five new CPU tests: original source fails four and passes the shared-waiter control; corrected source passes all five.
- Five existing registry and ZMQ lifecycle tests pass, including release waking a destination waiter.
- Actual FastAPI route/registry through ASGI transport: 64 timeout responses retain 64 conditions before the change and zero afterward, with zero metadata/TTL entries in both cases.
- Local tests execute repository definitions while excluding unavailable GPU-heavy import initialization. No GPU, native transfer, or model execution is claimed.
- All applicable pre-commit hooks pass.

Not applicable: this fixes retained rendezvous objects after failed metadata waits.
