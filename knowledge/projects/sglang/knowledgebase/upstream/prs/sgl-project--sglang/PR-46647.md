# [Perf] [AMD] Kimi-K3: KDA verify with fused ring, BF16 state, fused o_norm + o_proj

[Upstream PR](https://github.com/sgl-project/sglang/pull/46647) · state: open · merged: False

## Original PR description

## Motivation

Spec verify on K3's KDA layers ran conv, recurrent update and output norm+proj as separate kernels over an fp32 state.

## Modifications

- One fused conv+recurrent verify kernel over a ring of BF16 states.
- A fused `o_norm + o_proj` HIP GEMM (`k3_norm_gemm`).
- Prefill-graph state tracking accepts a non-fp32 SSM pool.
- `SGLANG_ROCM_NO_EXTEND_SYNC` defaults to `False`.

## Accuracy Tests

- `test_k3_norm_gemm.py` and `test_kda_prefill_graph_track.py` pass.
- On top of `main` with the upstream gfx950 KDA kernels (#45713/#45710), endpoint-dev outputs, tool calls and perf match the pre-rebase build. Under K3's serving config neither upstream kernel is selected: the HIP prefill requires an fp32 SSM pool, while K3 runs with `--mamba-ssm-dtype bfloat16`, and the decode backend is `aiter`.

Full K3 stack on MI355X TP8 (DFlash, prod config) vs B300, McNemar:
- GPQA-D 89.4 vs 87.9 (p=0.55)
- AIME25 96.7 vs 93.3 (p=1.0)
- MATH500 92.2 vs 92.2 (p=1.0)
- MMLU-Pro 89.6 vs 90.0 (p=0.77)
- GSM8K 97.2%

## Speed Tests and Profiling

- Turning it off costs -5.6/-23.0/-8.4% on the agentic replay and -11.5/-2.5% at 90k prefix (mean -10.2%).

Speed numbers: throughput change from turning this feature off on the full stack, agentic replay at C=1/8/32 and 90k-prefix at C=1/8.
