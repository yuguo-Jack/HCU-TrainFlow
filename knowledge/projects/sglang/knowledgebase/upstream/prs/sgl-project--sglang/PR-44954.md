# [Fix] [NVIDIA] kda: Invert diagonal A_kk blocks in fp32 to fix prefill NaN

[Upstream PR](https://github.com/sgl-project/sglang/pull/44954) · state: open · merged: False

## Original PR description

## Motivation

Fixes #44758. With `--linear-attn-prefill-backend nvidia_kda`, Kimi-K3 prefill returns NaN after about 1,800 tokens. Triton is correct on the same inputs.

The A_kk inverse kernel inverted each 16x16 diagonal block with a power series on bf16 operands. When beta is close to 1 and the keys are similar, the terms of the series get large and bf16 loses the result. The inverse was wrong in every chunk, so the recurrent state grew each chunk until it overflowed. Against an fp64 reference, every stage before the inverse matches.

## Modifications

- Invert the diagonal blocks by forward substitution with fp32 arithmetic. L is still read as bf16, and the off-diagonal blocks still use bf16 MMA. The output layout is unchanged.
- Add `test_nvidia_prefill_correlated_keys`: similar keys, beta near 1, slow decay, a partial last chunk and a nonzero initial state. It fails on main and passes here. The existing test uses random keys, which do not hit this.

## Accuracy Tests

Issue repro (`minimal.pt`, 2,048 tokens):

| | NaN rows | max abs diff vs fp32 reference |
| --- | --- | --- |
| main | 256 (from row 1792) | 1.2e37 |
| this PR | 0 | 1.9e-4 |
| Triton | 0 | 1.4e-4 |

The inverse now stays within 7.5e-3 of an fp64 inverse in every chunk. `test_kda_prefill.py` passes on B200 and B300 (the PTX tests skip on B200).
