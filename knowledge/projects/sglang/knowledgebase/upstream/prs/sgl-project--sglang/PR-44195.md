# [Fix] GDN: Take prefix-cache checkpoints from the fp32 state in the Triton kernel

[Upstream PR](https://github.com/sgl-project/sglang/pull/44195) · state: open · merged: False

## Original PR description

## Motivation

For hybrid Gated DeltaNet (GDN) models with the mamba radix cache, a request that reuses a cached prefix gets slightly different results than the same prompt computed without the cache. Under `--enable-deterministic-inference` this breaks the guarantee: whether a request hits the cache depends on scheduling and timing, so its log-probabilities change from run to run.

Cause: when a prefill crosses a radix-cache checkpoint, `GDNAttnBackend` asks the extend kernel for an fp32 snapshot of the recurrent state at that chunk boundary (`track_state` / `track_chunk_idx`). `TritonGDNKernel` does not declare `supports_track_state_snapshot`, so the backend falls back to the per-chunk states `h`, which `chunk_gated_delta_rule` stores in the activation dtype (bf16) - the fallback's docstring says so ("already rounded to the activation dtype"). A request resuming from that checkpoint starts from a rounded state; its prefill output can still match (the output kernel reads the same rounded `h`), but the state it then decodes from differs, so the first decode step changes.

The shared chunk kernel (`chunk_gated_delta_rule_fwd_h`) already writes the fp32 snapshot; KDA's Triton kernel uses it. Only the GDN path does not pass it through.

Measured on MI350X with Qwen3.8-27B, `test_deterministic --test-mode prefix --return-logprob` workload with each sample's `meta_info.cached_tokens` recorded (1,700+ samples per run): with `--max-running-requests 16`, every sample that hit a checkpoint (at 64, 384 or 768 tokens) differed from the reference at its first decode step, and every sample without a hit matched. At default settings few samples hit the cache, and the mismatches (14 and 24 samples in two runs) were all among them.

## Modifications

- `chunk_gated_delta_rule` (and its autograd function and `chunk_gated_delta_rule_fwd`): optional `track_state` / `track_chunk_idx`, passed to `chunk_gated_delta_rule_fwd_h`.
- `TritonGDNKernel`: `supports_track_state_snapshot = True` where it uses that kernel (not on CPU, NPU or XPU, which have their own kernels), and `extend` passes the snapshot arguments through.
- `test_chunk_gated_delta_rule.py`: new case `test_resume_from_track_snapshot_matches_full_prefill`: resuming the second chunk of a 128-token sequence from the fp32 snapshot gives bitwise the same output and final state as one prefill; resuming from the bf16 per-chunk state does not.
- `test_mamba_track_state_dtype.py` (CPU): new `TestTritonGDNTrackSnapshot`: `TritonGDNKernel` declares the snapshot capability, `extend` forwards `track_state` / `track_chunk_idx` to `chunk_gated_delta_rule`, and forwards nothing when the capability is off.
- No change to checkpoint positions or to requests without cache hits. This applies in all modes: cached-prefix results now match uncached ones.

## Accuracy Tests

MI350X, `rocm/sgl-dev:v0.5.21-rocm724-mi35x-20261012` with this change applied, Qwen3.8-27B BF16, `--attention-backend triton --linear-attn-prefill-backend triton --linear-attn-decode-backend triton --enable-deterministic-inference` (with #43788, #34543, #44076 and #44194 also applied, so that only this effect remains).

Unit tests: `test_chunk_gated_delta_rule.py`: before, 1 failed, 30 passed; after, 31 passed. `test_mamba_track_state_dtype.py` (CPU): before, 2 of the 3 new wiring tests fail (6 passed); after, 8 passed.

Prefix workload with `cached_tokens` recorded, samples whose log-probabilities differ from the first sample of the same prompt:

| Setting | before | after |
| --- | --- | --- |
| `--max-running-requests 16` | 694 of 1,285 samples differ: exactly the 694 cache hits | 0 of 1,285 and 0 of 1,300 (694 and 714 cache hits) |
| defaults | 14 of 1,285 and 24 of 1,300 differ, all cache hits (32 and 37 hits) | 0 and 0 (32 and 37 cache hits) |

(Prompts with the 511-, 2,048- and 4,097-token prefixes; the 1-token prefix never hits the cache.)

`python3 -m sglang.test.test_deterministic` (50 trials) and the bitwise check of 1,275 responses, default settings (overlap scheduler and radix cache on). These runs follow the existing deterministic end-to-end tests (`TestDeterministicBase`, e.g. `test_qwen35_deterministic.py`), which are CUDA-only and compare decoded text only; here log-probabilities and the bitwise check are compared as well. Happy to add an AMD end-to-end test if wanted.

- Before: the `prefix --return-logprob` log-probability comparison differed in 8 of 13 runs (TP1 and TP2, `SGLANG_USE_AITER` 0 and 1).
- After: TP1 with `SGLANG_USE_AITER=0`, TP1 with `SGLANG_USE_AITER=1` and TP2 with `SGLANG_USE_AITER=0` pass every mode (`single`, `prefix`, `prefix --return-logprob` with identical log-probabilities, `radix_cache`) and the bitwise check (1275 / 1275).

`p_vs_d` (prefill vs decode) still differs, as it does for every model.

GSM8K (all 1,319 questions, temperature 0, `sgl-eval` 0.1.2), Qwen3.8-27B: 95.91% in normal mode (`--attention-backend aiter`, without these changes), 96.06% with `--enable-deterministic-inference` and this change together with #43788, #34543, #44076 and #44194.
