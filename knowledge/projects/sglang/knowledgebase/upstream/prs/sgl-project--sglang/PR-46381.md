# [Feat] unified-memory: Fuse MLA drafts into MLA hosts

[Upstream PR](https://github.com/sgl-project/sglang/pull/46381) · state: open · merged: False

## Original PR description

## Motivation

Under `--enable-unified-memory` a draft fuses its KV into the target's sub-pool entries only when its attention is MHA. An MLA draft, such as the NEXTN head of an MLA hybrid (Ling-3.x on a KDA + MLA trunk), was declined, and on a Mamba-hybrid host an EAGLE draft that does not fuse refuses the boot. A fused draft reads and writes its rows through the same views and id spaces as the target, and MLA targets already run on those views; what was missing is a place for MLA rows in the host's entries and a draft view over them.

## Modifications

- An MLA draft's layers now profile as latent rows (`kv_lora_rank + qk_rope_head_dim`, whole on every attention-TP rank) and place a `LatentDraftRegion` in an MLA host's full sub-pool: one more part of every slot's entry, after the host's own latent rows, so one slot id, one allocation and one whole-page move still carry target and draft (`mem_cache/layout/fused_draft.py`, `kv_cache_configurator.py`).
- The dense binder hands the draft runner a `DraftMLAView` (`mem_cache/kv/layout/mla.py`), an `MLAView` over its lanes of that part, addressed by the draft's model layer ids: `MLAView`'s per-layer methods now offset by `start_layer` as `MHAView`'s do, and the target's view keeps 0. Its write door takes physical ids, so `RunnerIds` gives the draft runner the fused disposition: reads translated through the target's tables, writes at the target's physical ids. The binder refuses a built draft whose rows are narrower or wider than the region it was placed with. Like the default pool's draft pool on a hybrid-linear host, the view reports its value head dim, which the triton backend reads at startup.
- An MLA draft fuses only into an MLA host and only for the EAGLE family (EAGLE, EAGLE3, NEXTN). One with sliding-window layers still declines, and so does a DFLASH or DSPARK MLA draft, which commits its context rows through prefix-valid latent writes the fused view does not provide, so it keeps today's private pool or boot refusal. An MHA draft on an MLA host fuses dense rows as before.

Tests (CPU), `test/registered/unit/mem_cache/test_fused_draft_placement.py` and `test_dense_fused_draft_geometry.py`: an MLA draft profiles latent rows; a latent profile places a latent region, and a misaligned one declines; the fusion decision fuses an EAGLE MLA draft into an MLA host, and declines it on an MHA host, with window layers, and for DFLASH and DSPARK; an MLA host's entry lays out the latent part, and an MHA host refuses it; the draft view writes only its own lane of a slot, every per-layer door addresses the lane of the draft's model layer id, a host page move carries its rows, and it reports its value rows' width as its value head dim; on a pool the production builders build, the binder binds the view, its runner ids take the fused disposition, a draft row shares the target's slot without touching the target's rows, and a draft of another width refuses to bind.

## Accuracy Tests

The unified-memory servers ran with `SGLANG_DEBUG_POISON_POOL=1`, so a read of a never-written pool row shows up as a wrong answer.
