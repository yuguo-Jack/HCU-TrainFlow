# [Fix] server-args: Redact credentials from logs and server info

[Upstream PR](https://github.com/sgl-project/sglang/pull/42444) · state: open · merged: False

## Original PR description

Reopened from #39449. GitHub closed that PR on 2 October when the fork it came from was deleted; its review history is still there.

## Motivation

`ServerArgs.resolved_dict()` publishes configured credentials in startup logs, `/server_info`, its gRPC and in-process equivalents, and configuration snapshots. A caller holding only `api_key` can read `/server_info`, including the higher-privilege `admin_api_key`. The captured `launch_command` also repeats CLI or `Engine(...)` credentials verbatim.

Fixes #37457. Related: #37499, #18518 and #30343.

## Modifications

Mark `api_key`, `admin_api_key` and `ssl_keyfile_password` with `Arg(secret=True)`. `resolved_dict()` replaces configured secrets with count-preserving markers (`<redacted:1 value>` or `<redacted:N values>`), and leaves unset secrets as `None`. The raw fields stay available to authentication, SSL and process transfer.

Redact the command at capture. The CLI helper covers exact flags, aliases, unique argparse abbreviations, both value spellings, and a parsed-value backstop for unknown spellings. Known public flags keep their own values when they happen to equal a credential. `Engine(...)` applies the same metadata to keyword arguments. The tokenizer crash dump uses the captured redacted command.

Redact raw runtime overrides before applying them to the already-redacted configuration. This preserves list-valued credential counts through scheduler and tokenizer readbacks instead of turning an existing marker into `1 value`. A new regression checks the base count, rotated count and removal of a credential. The classification guard checks every credential-shaped field against the three marked fields and the reviewed public token-count fields.

The rebase retains the current `/hicache/storage-backend/clear` endpoint spelling and upstream's configuration refactor. No configuration fields are removed from the response. The serialized record used to replay crash dumps deliberately retains its raw values; this change covers the human-readable command and resolved snapshot, not the replay record.

- Tardfyou · comment · 2026-10-11T05:10:37Z · [source](https://github.com/sgl-project/sglang/pull/42444#issuecomment-6105715635)

Runtime confirmation plus one uncovered surface, in case it helps the fix land.

**Reproduced on sglang 0.5.21 (PyPI), full server, CPU device:** started with `--admin-api-key SECRET123` (no `--api-key`) in both single-tokenizer and `--tokenizer-worker-num 4` modes — an unauthenticated `GET /server_info` returns `launch_command` containing `--admin-api-key SECRET123` verbatim in both modes. This matches the NORMAL-level/auth-gap framing in this PR and in #29655 / #37457.

**Uncovered surface — the Rust gateway (`sgl-model-gateway`) also serves these endpoints unconditionally:** `src/server.rs:593-605` puts `/server_info` and `/get_server_info` in `public_routes` (merged without the auth middleware, :678), and the handler (:160-162) proxies straight to the worker's /server_info. So even a deployment that fronts the Python server with the gateway and configures the gateway's `--api-key` still exposes the worker's `launch_command` (with any configured keys) without credentials. It would be great if this fix, or a follow-up, moves `/server_info`/`get_server_info` out of the gateway's public routes (or redacts at the source as proposed here, which would also fix the gateway path).

Harness (offline, localhost-only, both modes + unauthenticated/401 controls) available on request.
