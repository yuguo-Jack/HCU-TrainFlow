## Motivation

Builds on #44480's focused FP8 fallback expert-ID repair. This PR extends the contract to wrapped and direct methods, routing formats, weight handling and transport payloads.

A mixed-precision or draft MoE layer can fall back to Triton while the requested backend remains FlashInfer or AITER. Dispatch and routing previously followed that request, so a local-ID kernel could receive global expert IDs or the wrong TopK format. Direct kernels and dormant fallback runners also mean that runner construction alone does not identify the execution contract.

## Modifications

- Quant methods expose their effective execution backend, including wrapped schemes, secondary AITER runners and direct kernels. FusedMoE records it before creating dispatch and binding each model router.
- Expert-ID mapping, TopK format, backend-specific post-load transforms, scaling, in-place behavior, DeepEP dtype and FlashInfer payloads consume the layer's contract. Missing implicit router bindings fail before invoking a kernel.
- Fallback layers preserve the model's DP all-gather/reduce-scatter layout using BF16 payloads. Ordinary block-FP8 post-load shuffling runs only for the actual AITER backend, including both FNUZ and non-FNUZ layouts.
- Backend binding is one-time and idempotent for the same contract; conflicting rebinding fails before changing router state. LLaDA2 consumes the authoritative layer backend, including the direct-kernel None case.
- The gfx1250 W4A8 internal router rejects unsupported expert sharding at startup.
- Muse Spark BF16/FP4 custom SP configs declare the direct execution backend; update the Kimi weekly experts fixture to model the same backend association.

Ordinary W13/W2 loaders explicitly zero every untouched tail after checkpoint shard selection. This preserves already-padded allocations when the requested TRTLLM runner falls back to Triton, including repeated loads.

Requested backend reads remain where they select a quant method, allocate compatible weight shapes, enforce startup compatibility or establish model-wide layout/default policy.
