## Motivation

A MoE quantization method can execute on Triton while the requested backend remains FlashInfer or AITER. Dispatch, weight preparation and routing must follow the layer that actually executes. Backend identity also does not prove that a native router implements the model's routing policy: AUTO-resolved NVFP4 must preserve custom routing and renormalization.

## Modifications

- Quantization methods expose their effective execution backend, including wrapped methods, secondary runners and direct kernels. FusedMoE binds dispatch, expert-ID layout, transport payloads, post-load transforms and each model router to that contract.
- TRT-LLM in-kernel routing requires a declared policy matching the model's scoring, grouping, bias, renormalization, custom-router and shared-slot behavior. Other routers retain materialized STANDARD output. Explicit `Default` enum value 0 remains a real policy, distinct from an unspecified selector.
- TRT-LLM routed adapters consume materialized weights without renormalizing them again. Unsupported materialized per-tensor FP8 input fails before the kernel; an undeclared per-tensor router retains the Triton fallback and its compatible weight layout.
- Materialized TRT-LLM routes include the routed factor for every effective quantization method, including compressed-tensors FP8/NVFP4 schemes. Grouped/biased fallback producers apply the factor independently of renormalization while preserving shared contributions. Native routers still apply their own factor once. Ordinary loaders zero untouched padded weight tails, including repeated loads.
- Preserve model-wide DP layout for fallback payloads, gate AITER-specific transforms on the effective backend, and keep weight-only helpers with no runner valid. Binding is idempotent for the same contract and rejects conflicting reuse. The gfx1250 W4A8 internal router rejects unsupported expert sharding.

Equivalent native policies are declared for normalized MiMoV2 grouped sigmoid/bias, BailingMoE grouped sigmoid/bias or plain softmax, and Cohere2 sigmoid. Other configurations remain materialized. DeepSeek's logits-only dual-stream graph requires a BYPASSED router even when this PR is used independently.

Llama4 FP8 explicitly selects the model's top-1 sigmoid native policy. Gemma4 NVFP4 materializes its model router so selected-expert softmax weights retain the learned per-expert multiplier. These change behavior relative to the earlier native defaults; CPU contract tests cover the boundaries, but no full-model accuracy A/B is claimed for either model.

BailingLinear resolves its optional AWQ provider only when AWQ weights are loaded, so ordinary model construction does not require `vllm`. The Kimi constructor fixture declares the routing selector explicitly.

Requested-backend reads remain where they select a method, allocate compatible shapes or establish model-wide policy.
