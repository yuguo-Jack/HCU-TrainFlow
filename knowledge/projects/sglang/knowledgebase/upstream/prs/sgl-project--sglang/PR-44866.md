# [Feat] speculative: Online acceptance estimator for DSpark confidence-scheduled verification

[Upstream PR](https://github.com/sgl-project/sglang/pull/44866) · state: open · merged: False

## Original PR description

## Motivation

DSpark's confidence-scheduled ("ragged") verification trims low-survival draft
tokens before the target verify, but it needs a trained confidence head, so
checkpoints without one cannot use it. vLLM's
[online acceptance estimator](https://vllm.ai/blog/2026-10-14-adaptive-verification-online-estimator)
(vllm-project/vllm#52228) replaces the head with a logistic model of the draft
distribution fitted while serving. This PR brings that to SGLang, with a more
robust fit.

## Modifications

- `--speculative-dspark-confidence-source {auto,head,online}` (default `auto`).
  `online` scores each draft position with
  `sigmoid(slope * logit(q_max) + intercept[position])`; `auto` uses the trained
  head when the checkpoint ships one and the estimator otherwise (config
  `enable_confidence_head: false`, or no confidence weights at all).
- `OnlineAcceptanceEstimator` (`srt/speculative/online_acceptance_estimator.py`):
  DSpark drafts and verifies in the same step, so prediction and grading run back
  to back with no per-request state. Labels are the drafts before and at the first
  rejection, restricted to drafts checked against a real target row.
- Fit: exact MAP IRLS on binned `(position, logit(q_max) bin, label)` counts with
  a decayed history (Newton iterations with a batched line search, on device, every
  100 steps). A single Newton step per round, as in vLLM, freezes the slope and
  over-predicts survival when acceptance saturates below 1 for confident drafts
  (sampled targets): in simulation it over-predicted the expected accepted length
  by 0.45 tokens per request, the binned fit by -0.02.
- Two launches per decode step: a Triton pass computes logit(q_max) and the
  prediction together, and one atomic-add kernel bins the labels.
- Fix (pre-existing on main): compact ragged verify padded the trimmed slots of the
  full-width logits with zeros, and the sampling accept's top-p renormalization of a
  uniform row is flashinfer's radix top-p worst case (22 ms vs 0.75 ms for 512 x 152k
  rows). On Qwen3-14B + DSpark at c=64 that was ~15 ms of a 36 ms step and made compact
  ~50% slower than static, whatever the confidence source. Padding rows now hold a point
  mass (they are never accepted from; block verification is lossless for any padding).
- Docs: a confidence-scheduled verification section and the new server argument.

## Losslessness

Trimming is lossless iff whether position i is verified depends only on the
drafts before i (plus independent randomness and history). The estimator's
feature reads `q_i`, never the drafted token; survival is a running product over
positions <= i; ties in the top-B break toward earlier positions; and the budget
is sized from confidences two steps old. An exact rational enumeration (not part of
this PR) confirms
losslessness for token-wise and block verification (and shows the failure modes:
scoring `q(x_i)`, or sizing the budget from current survivals of a
semi-autoregressive drafter). `test_ragged_cutoff_preserves_distribution` checks
the real accept kernels on 400k rows with compact padding and the verify cap,
block and token-wise.

Repeat runs on other GPUs reproduce the c=128 gains within about one point. Before the padding
fix, every compact arm was 45-50% slower than static at c >= 32 (top-p on zero-logit padding rows
took ~22 ms of a ~36 ms step).

Known limitation: at c <= 8 compact mode is still up to 9% slower than static even though its budget
verifies every draft there; that is the compact pipeline's fixed per-step cost, independent of
the confidence source. `SGLANG_RAGGED_VERIFY_MODE` stays `static` by default, so default
deployments are unaffected; reducing that cost is left to a follow-up.
