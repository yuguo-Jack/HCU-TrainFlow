# [Fix] disaggregation: Synchronize deferred decode KV release across TP ranks

[Upstream PR](https://github.com/sgl-project/sglang/pull/45453) · state: closed · merged: True

## Original PR description

## Motivation

After a failed prefill-to-decode transfer, acknowledgments and timeout deadlines can differ across attention-TP ranks. Releasing KV capacity on only some ranks lets admission and transfer queues diverge, leading to mismatched polling collective sizes. Rank-local abort notification state can also make ranks disagree on whether to defer a release at all.

## Modifications

- Hold a failed transfer on every attention-TP rank when any rank needs to defer it.
- Release each held request only when every rank has drained or reached its existing device timeout. Host destinations still require a drain acknowledgment regardless of timeout.
- Require no local acknowledgments on ranks that hold only for a peer.
- Add a two-process Gloo regression covering staggered acknowledgments and deadlines, asymmetric notifications, per-request progress, host drain requirements, and disabled deferral. Preserve the existing upstream coverage.

## Accuracy Tests

The new regression fails on upstream `1dd0f361b83a`: rank 0 frees `[0, 1]` while rank 1 frees only `[1]`, and asymmetric notifications leave held counts `[1, 0]`.

With the fix, both affected test files pass: **59 passed, 6 subtests passed**.

```bash
PYTHONPATH=python python -m pytest \
  test/registered/unit/disaggregation/test_deferred_decode_kv_release.py \
  test/registered/unit/disaggregation/test_decode_queue_cleanup.py -q
```

The regression uses real Gloo collectives and queue/acknowledgment logic; GPU cache operations and transport notifications are mocked. No model accuracy or GPU/RDMA end-to-end run was performed.

## Speed Tests and Profiling

Not benchmarked. The added collectives run when processing failed transfers or resolving deferred releases; empty lists and single-rank groups skip the collective.
