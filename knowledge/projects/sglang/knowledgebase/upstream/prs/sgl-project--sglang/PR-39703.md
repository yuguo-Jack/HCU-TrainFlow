# [Attention] Honor custom masks beyond causal query tiles in Triton extend

[Upstream PR](https://github.com/sgl-project/sglang/pull/39703) · state: closed · merged: False

## Original PR description

**Incremental review:** [Files changed](https://github.com/sgl-project/sglang/pull/39703/files) against `main`.

Triton extend attention already lets a custom mask replace the elementwise causal mask, but its key-loop bound still stops at the end of the causal query tile. Custom masks that expose later tiles, including bidirectional dLLM blocks, therefore silently miss allowed keys when `is_causal=True`.

Traverse the full extend region when a custom mask is supplied. Add a CUDA regression comparing the two-stage Triton kernel, the unified deterministic kernel, FlashInfer FA2, and a dense FP32 reference. The cases include GQA, heterogeneous lengths, a non-aligned cached prefix, block-causal and non-triangular custom masks, FP16/BF16, both causal flag values, and CUDA graph replay.

This integration harness strictly loads every tensor from `JetLM/SDAR-1.7B-Chat-b32` into the matching Qwen3 module structure and routes all 28 attention layers through the tested kernels. It retains embeddings, RoPE, Q/K norm, MLPs and LM head. Inputs: 193 fixed random tokens, GQA 16/8 heads, head dim 128, BF16, `is_causal=True`. Each forward invokes the target kernel 28 times. The unchanged unified kernel is the exact-parity reference. Block 128 is a cross-tile mask stress case, not a claim that the checkpoint was trained with block size 128.

| Additional check | Result / limitation |
| --- | --- |
| Real SDAR HTTP serving regression on this kernel patch | PASS: 7 prompt lengths, 32 generated tokens each, identical IDs/text to the prefix-fix server with cold/hot cache; this server runs with radix disabled |
| Full-model dense FP32 diagnostic | Strict parity did not pass: both Triton variants have the same BF16 accumulation differences; argmax agreement 97.41% / 97.93% |
| Full-model FlashInfer vs unified diagnostic | Not an exact-parity pass: max logits differences 0.25 / 0.21875 and argmax agreement 97.93% for both masks |
| Native multi-block custom-mask HTTP serving | Not claimed: the existing ordinary SDAR scheduler does not provide a custom mask; the model harness supplies it explicitly |

Hardware/runtime: RTX PRO 4000 Blackwell 24 GB, PyTorch 2.13.0+cu130, sglang-kernel 0.4.7. Full-model numerical diagnostics do not replace the separate dense-reference kernel assertions above. The baseline is clean commit `17ba2c2e`; only the two-stage key-loop fix changes between baseline and fixed model runs.

The HTTP harness uses a **test-only mask provider** at `TritonAttnBackend.init_forward_metadata`; the public `/generate` API does not accept arbitrary masks. Requests then pass through the native scheduler, all 28 model layers, KV writes, sampling, decoding and HTTP response. A read-only per-layer comparison verifies the actual two-stage output against `_forward_extend_unified`. All 336 comparisons pass exactly. Native multi-block dLLM scheduling is still outside this PR and remains in #31586. HTTP tests use BF16, Triton, TP=1, radix disabled, CUDA graphs disabled; the earlier kernel test separately covers non-aligned prefixes and graph replay.

## Scope and coordination

This PR contributes to the custom / block-causal mask qualification in #39499 and is intentionally limited to the existing two-stage Triton extend-attention kernel contract plus its regression coverage.

It complements #31586 without taking over that PR's work. In particular, #31586 remains responsible for multi-block dLLM prefill scheduling, phase selection, FlashInfer mask construction and wrapper isolation, and Breakable prefill CUDA Graph integration. This PR does not add multi-block scheduling, change the FlashInfer path, or expose a public custom-mask API.

Supersedes the closed drafts #39591 and #39593 with the same implementation and validation evidence on the renamed source branch.
