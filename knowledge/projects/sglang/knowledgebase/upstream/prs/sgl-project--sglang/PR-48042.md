# [Perf] [AMD] hicache: make the block_quota of the all-layer D2H backup copy configurable

[Upstream PR](https://github.com/sgl-project/sglang/pull/48042) · state: open · merged: False

## Original PR description

## Motivation

With HiCache `write_back`, an eviction copies its victims to the host pool with `transfer_kv_all_layer_mla_lf_pf` (MLA KV and the DSA indexer), and the scheduler waits for that copy. The op takes a `block_quota` argument (workgroups launched, default 2). On MI355X the default caps this copy at about 22 GB/s; 16 workgroups reach about 49 GB/s. There is currently no way to change it without editing the call sites.

## Modifications

- `environ.py`: new `SGLANG_HICACHE_BACKUP_BLOCK_QUOTA` (`EnvInt`, default unset).
- `pool_host/common.py`: `hicache_backup_copy_kwargs()` returns `{}` when unset and `{"block_quota": N}` when set.
- `pool_host/mla.py`, `pool_host/dsa.py`: the one `transfer_kv_all_layer_mla_lf_pf` call in each passes `**hicache_backup_copy_kwargs()`.
- Unit test for the helper: `test/registered/unit/mem_cache/pool_host/test_hicache_backup_block_quota.py`.

Default behaviour is unchanged: when the variable is unset no extra argument is passed, so the kernel default (2) applies and backends whose op has no `block_quota` argument (e.g. the XPU shim) are not affected. MHA host pools are not touched in this PR.

## Accuracy Tests

The grid size only changes how items are split across warps (each warp owns a disjoint item range, no cross-warp communication), so results must not change. Checked on a v0.5.22-based build (MI355X, GLM-5.2-MXFP4):

- Microbenchmark in the production shape (KV: 20 layers x 576 B, DSA indexer: 5 layers x 8,448 B, one eviction = 75 nodes): output is byte-identical to the default for every `block_quota` from 1 to 64, and host memory outside the target rows keeps its sentinel value (no out-of-bounds writes).
- Capped-pool gate (device pool limited to 300K tokens per rank so evictions are continuous and a second 16k x 128 pass loads the host copies back), with `SGLANG_HICACHE_BACKUP_BLOCK_QUOTA=16`: GSM8K 200-prompt probe 0.985 with 0 garbled outputs, long-context needle 64/64, long-prefix GSM8K 62/63.

## Speed Tests and Profiling

Same build, 1 prefill (TP1 x PP4) + 1 decode (TP4/DP4), AgentX trace replay at concurrency 104, 1 hour:

- Copy of one eviction (~6.5 GB): 278 ms -> 125 ms (quota 2 -> 16).
- Time per eviction summed over the four PP ranks: 1.45 s -> 1.04 s.
- Throughput 49,719 -> 51,374 tok/s/GPU (+3.3%; mean of two runs vs one run, both with the same other settings).

Limits: measured on one GPU type (gfx950) and one model. I do not know the best value on other GPUs, hence an opt-in environment variable rather than a new default. The code change was validated on the v0.5.22-based build; on current `main` I checked that the files import and the helper behaves as above, but I could not run the end-to-end benchmark on `main`.
