# [NPU] Fix MoE none EP routing and draft backend inheritance

[Upstream PR](https://github.com/sgl-project/sglang/pull/40705) · state: open · merged: False

## Original PR description

## Motivation

On Ascend, `--moe-a2a-backend none --tp-size 2 --ep-size 2` fails with Qwen3.6-35B-A3B even without speculative decoding. The shared `AscendTPDispatcher` counts all 256 global experts while each rank owns 128 expert weights:

```text
groupList(tensor) 256 should be equal to weight dim 0 128
```

This affects the target model and any draft using the `none` dispatcher. Route tokens to each rank's local experts and combine its valid contributions through the model's existing all-reduce. Filtering also requires finalize mode 3: mode 2 does not handle the resulting `-1` row indices correctly.

Also make an explicit `--speculative-moe-a2a-backend none` inherit the target backend, matching an omitted option. With a DeepEP target, this selects DeepEP for the draft; with a `none` target, it still selects `none`, which needs the EP routing fix above.

## Modifications

- Map global expert IDs to local weight indices in the Ascend `none` dispatcher, preserve fused shared experts, and filter nonlocal/padding IDs using a nonnegative sentinel.
- Pass the local active expert range to NPU init routing so the expert-count tensor matches the local weights. Use finalize drop mode 3 for EP and view packed GMM output as a 3D capacity buffer without copying; EP1 retains mode 2.
- Resolve the draft backend with `spec.speculative_moe_a2a_backend not in (None, "none")`; otherwise use the target backend's default draft policy, preserving the upstream `flashinfer_megamoe` fallback to `none`. Keep raw-argument consumers consistent, including DeepEP v2 validation, DSpark validation, DeepGEMM memory planning, and FlashInfer autotuning.
- Update CLI help and documentation, add inheritance unit coverage, and make the Qwen3.6 NPU regression default to target `none`. It covers target-only inference plus MTP with the draft option omitted and explicitly set to `none`.

**Compatibility:** explicit draft `none` follows the same default policy as an omitted option across platforms. It normally inherits the target backend; the upstream `flashinfer_megamoe` exception is preserved and defaults the draft to `none`, because its global-expert-ID dispatch does not support typically unquantized draft layers. Other explicit backend values continue to override the target, subject to backend/model support. Inheriting a backend does not imply every model, quantization, or speculative algorithm is supported by it.

## Accuracy Tests

Validated on machine 151 with Ascend A3, Qwen3.6-35B-A3B BF16, TP2/EP2, CANN 9.1.0, PyTorch 2.10.0, and torch_npu 2.10.0.post6. NPU graphs are disabled and Mamba state uses BF16.

Controlled comparisons against base `8ac19cc19f` establish the routing bug independently of draft inheritance:

| Configuration | Without the NPU routing fix | With the NPU routing fix |
| --- | --- | --- |
| Target `none`, TP2/EP2, no speculative decoding | GMM fails: 256 expert counts vs. 128 weights | 5/5 answers correct; no speculative verification or draft tokens |
| Target/draft `none`, TP2/EP2, MTP; inheritance rule applied to both variants | Same GMM failure in the target worker | 5/5 answers correct; 5 verify calls, 5 proposed and 5 accepted draft tokens |
| Target/draft `none`, TP2/EP1, MTP; inheritance rule applied to both variants | Pass | Pass |

Updated-source validation at `fe717ffe5a`:

| Test | Result |
| --- | --- |
| MoE runtime-context and DeepEP v2 argument unit tests | 37/37 passed |
| Real-NPU dispatcher kernel regression | 7/7 passed |
| Target `none`, target-only inference | 5/5 answers correct; zero speculative verification/proposal/acceptance counts |
| Target `none`, MTP, draft option omitted vs. explicit `none` | Both passed; 5/5 answers and 5 verify/proposed/accepted draft counts per configuration; identical outputs |
| Target `deepep`, MTP, draft option omitted vs. explicit `none` | Both passed; 5/5 answers and 5 verify/proposed/accepted draft counts per configuration; identical outputs |

Two initial MTP launches stopped at the pre-model-load memory-balance check because other workloads occupied the selected NPUs. Their logs were retained. Both complete MTP comparisons passed after selecting available devices 10 and 11.

All successful model configurations return `42, 42, 56, 81, 15` for one single request and one four-request batch. The DeepEP comparison checks draft inheritance; it does not exercise the local `none` dispatcher.

Kernel coverage includes EP1, EP2, 256 global/128 local experts, no local tokens, shared experts and padding, INT8 routing, and empty batches. Logical ranks run sequentially on one NPU against a CPU dense reference; summing partial outputs checks the complete result. Unused GMM rows contain NaNs to detect invalid reads from dropped routes. The model tests cover actual cross-rank execution.

### Additional TP4/EP2 validation

Validated on machine 151 on 2026-09-29 using the same PR commit `fe717ffe5a`, Qwen3.6-35B-A3B BF16, and four NPUs (devices 12–15). Both cases use `--tp-size 4 --ep-size 2 --moe-a2a-backend none`, Ascend attention, BF16 Mamba state, and disabled NPU graphs.

| Configuration | Correct answers | Verify calls | Proposed draft tokens | Accepted draft tokens |
| --- | --- | --- | --- | --- |
| Target only, no speculative decoding | 5/5 | 0 | 0 | 0 |
| Target + MTP, explicit `--speculative-moe-a2a-backend none` | 5/5 | 5 | 5 | 5 |

Both cases returned `42, 42, 56, 81, 15` for the same single-request and four-request-batch checks. MTP used `--speculative-algorithm EAGLE --speculative-num-steps 1 --speculative-eagle-topk 1 --speculative-num-draft-tokens 2` with an unquantized draft and Ascend draft attention.

Read-only runtime probes confirmed the hybrid expert/tensor-parallel layout on all four ranks:

- `moe_ep_size=2`, `moe_tp_size=2`, and `moe_dp_size=1`.
- 256 global experts and 128 local experts per rank; `group_list_len=128` and `drop_pad_mode=3`.
- Ranks 0/1 hold different TP slices of experts 0–127; ranks 2/3 hold different TP slices of experts 128–255. The local expert intermediate dimension is 256, half of the full dimension 512.
- Stored BF16 parameter shapes are `w13_weight=[128, 512, 2048]` and `w2_weight=[128, 2048, 256]` on every rank. The group-count length matches the local expert dimension of both weights.
- Probes covered all 40 target MoE layers on each rank and, in the MTP case, `mtp.layers.0.mlp.experts` on each rank (160 and 164 total probe records, respectively).

This run used an isolated copy of `test_npu_speculative_moe_a2a_qwen36.py`, changing its device requirement, TP launch argument, and TP assertion from 2 to 4 and removing the 2-NPU CI registration. Source and probe changes were recorded with SHA-256 hashes. The probes only read metadata and tensors; they do not change routing or computation. Server responses and every probe record were checked after execution.

These results validate the `none` dispatcher with TP greater than EP for the tested BF16, graph-disabled model configurations. They are functional smoke tests, not a throughput benchmark or coverage of quantized/graph-enabled execution.

### Reproduction

Reproduce the registered TP2/EP2 tests from the repository root:

```bash
python test/registered/npu/basic_function/parallel_strategy/expert_parallelism/test_npu_none_dispatcher.py -v

# Default target/draft backend: none. Runs target-only and both MTP variants.
ASCEND_RT_VISIBLE_DEVICES=0,1 \
SGLANG_TEST_MODEL_PATH=/path/to/Qwen3.6-35B-A3B \
python test/registered/npu/basic_function/speculative_inference/test_npu_speculative_moe_a2a_qwen36.py -v

# Both draft settings resolve to DeepEP; this checks inheritance.
ASCEND_RT_VISIBLE_DEVICES=0,1 \
SGLANG_TEST_MODEL_PATH=/path/to/Qwen3.6-35B-A3B \
SGLANG_TEST_TARGET_A2A=deepep \
python test/registered/npu/basic_function/speculative_inference/test_npu_speculative_moe_a2a_qwen36.py \
  TestNpuSpeculativeMoeA2AQwen36.test_draft_backend_override -v
```
