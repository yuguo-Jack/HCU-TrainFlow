# Release fastsafetensors file buffers after each shard

[Upstream PR](https://github.com/sgl-project/sglang/pull/40065) · state: open · merged: False

## Original PR description

## Motivation

Closing the fastsafetensors loader alone leaves its returned file buffer allocated after each shard.

## Change

Close the buffer before the loader. Tests cover normal loading, early iterator close, and read and cleanup errors.

## Validation

The targeted suite passes: 24 tests and 2 subtests. On one GB10, the 52-shard NVIDIA-Nemotron-3.5-Lightning-30B-A3B-NVFP4 model loaded and served. Reported warm-cache weight-load memory fell from 47.12 GB to 27.03 GB; load time was 12.67 s versus 12.42 s. This is not a throughput or accuracy benchmark.

The cached image used sglang-kernel 0.4.6.post1 rather than the 0.4.7 required by current main, so its version check was bypassed for the model run. The unit tests were rerun on current main. This change does not address the separate multi-node device-index issue in #29272.
