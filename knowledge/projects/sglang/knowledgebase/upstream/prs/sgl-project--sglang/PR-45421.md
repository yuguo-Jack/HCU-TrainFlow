# [Perf] [NVIDIA] DSpark: Enable the simulated-acceptance fast paths on CUDA

[Upstream PR](https://github.com/sgl-project/sglang/pull/45421) · state: closed · merged: True

## Original PR description

## Motivation

With `SGLANG_SIMULATE_ACC_LEN` set (simulated acceptance for benchmarking), DSpark already has three fast paths, but they are gated to HIP:

- the verify skips the draft / target accept sampling (softmax + rejection), whose result the simulated length overwrites;
- the accept and the sampled bonus fold into the verify CUDA graph (`SGLANG_DSPARK_SIMULATE_FOLD`);
- temperature-only rows are treated as greedy (`SGLANG_SIMULATE_ACC_GREEDY`).

On CUDA the same simulated runs still pay for the discarded sampling and the unfolded accept. This PR lets CUDA take the same paths.

## Modifications

- `dspark_verify.py`: skip the accept sampling under simulated acceptance on every platform (was `simulate and _is_hip`).
- `dspark_worker_v2.py`: `simulate_fold` and `_simulate_acc_greedy` no longer require HIP; both keep their existing env switches (default on), so either can still be turned off.
- Remove the now-unused `_is_hip` / `is_hip` imports in both files.

No effect when `SGLANG_SIMULATE_ACC_LEN` is unset, so real serving is unchanged.

## Accuracy Tests

Only the simulated-acceptance path changes. Accuracy runs use real acceptance (`SGLANG_SIMULATE_ACC_LEN` unset) and take the same code as before.

## Speed Tests and Profiling

DeepSeek-V4.1-Flash, TP4 GB300, DSpark, `--enable-nvidia-megakernel`, AgentX agentic-coding, concurrency 1, `--max-running-requests 1`, `SGLANG_SIMULATE_ACC_LEN=3.51` (match-expected, real-draft-token), 3,600 s. Measured on main `8e7601ae4a4` + #44945; the two arms differ only by this change (one boot each, different nodes):

|---|---|---|---|---|
| without this change | 404 | 760.0 | 719.3 | 102 ms |
| with this change | 474 | 949.7 | 926.0 | 96 ms |

The two runs reached different context mixes (ISL p50 294K vs 153K), so here is the steady decode step from the server's decode-batch log, binned by context and matched on (conversation, turn):
