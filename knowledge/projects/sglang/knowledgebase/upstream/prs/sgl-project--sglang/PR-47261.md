## Motivation
Qwen3-30B-A3B with TP8/DCP2, Triton attention and BF16 KV can write DCP logical slot IDs directly into a rank-local KV buffer through fused RoPE + KV storage. This causes incorrect output and can produce CUDA illegal memory accesses as the cache allocation advances.
<!-- Describe the purpose and goals of this pull request. -->

## Modifications

<!-- Detail the changes made in this pull request. -->
`enable_fused_set_kv_buffer()` checks `forward_batch.dcp_kv_mask` to avoid DCP, but eager batch construction only populates that mask on HIP. CUDA batches can therefore have DCP enabled with a `None` mask.

Qwen3 MoE then selects fused RoPE storage, whose `FusedSetKVBufferArg.cache_loc` is the unchanged `out_cache_loc`, and skips the attention backend's KV store. That bypasses the Triton DCP path's owner mask and `loc // dcp_size` translation. 
- Reject the generic fused RoPE KV-store path when `get_parallel().dcp_enabled` is true. The existing attention backend performs the DCP-aware store.
- Add a regression to the existing gate test for CUDA/HIP, DCP1/2/4, and an absent batch mask. Keep DCP1 eligible for fusion.
