# [DeepSeek-V4.1] Allow bounded replay with breakable prefill

[Upstream PR](https://github.com/sgl-project/sglang/pull/42078) · state: closed · merged: False

## Original PR description

Superseded upstream by #43736, with follow-up fixes in #44850, #45301 and #45407. Closed because current main already implements the bounded replay support and tail-buffer fixes.

## Motivation

Bounded prefill runs all input rows through the KV-source layers, then runs the remaining layers on the last up to 128 extend rows per request. With breakable prefill, the late layers can inherit tail metadata from a previous batch.

## Modifications

Split at the last layer in `kv_source_layer_ids` and capture the two regions separately. Replay the early layers, gather the current batch's tail rows, then replay the smallest tail graph that fits. For V4.1 Flash the split is between layers 20 and 21. Both regions use the same model layer loop.

Attention and indexer calls remain eager graph breaks and read the current forward's metadata. Tail graphs own their input buffers and padded-query workspace. Capture each bucket with a matching batch and rebuild the graphs on recapture. LoRA and multimodal batches keep the eager tail path.

Keep tail metadata on its owning forward, exclude padding from tail slices, check candidate row bounds, and preserve DSpark's hidden-state row indices. Reject unsupported prompt-logprob requests before scheduler dispatch. Allow BCG with bounded replay on CUDA with `attn_cp_size=1`.

## Accuracy Tests

- 20 CPU tests and two GPU tests covering 73 replay transitions passed. The stale-tail regression fails on the base. Pre-commit passed twice.
- On 4×B300, the 16K capture configuration passed six boundary batches and all 19 adversarial tests.
- With DSpark, GSM8K scored 90.87% on 1,314 questions. 18/19 adversarial tests passed; the raw long-prompt test returned EOS immediately where the assertion expected visible text.
- The regular 2K-capture attempt timed out in FlashInfer autotuning before graph capture. The regular configuration and a matched DSpark control are being rerun, including paired serving benchmarks against `b3244492d9`.
