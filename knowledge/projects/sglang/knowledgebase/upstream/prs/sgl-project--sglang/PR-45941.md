# [Perf] dsv4: Replay the V4.1 prefill graph past 16K contexts on SM90

[Upstream PR](https://github.com/sgl-project/sglang/pull/45941) · state: closed · merged: True

## Original PR description

- On CUDA, the DeepSeek-V4.1 prefill CUDA graph builds its replay metadata at the live context width whenever no c4/c128 compress metadata is captured, so SM90 replays contexts past 16K as SM100 already does. Nothing captured on that path depends on the width: the width-sized metadata is swapped in per replay, and without two-level candidates the ratio-1/2 sources run as one eager break.
- The 16K default moves to the HIP backend, whose prefill graph metadata is captured at a fixed width; HIP keeps its behavior.
- `TestPrefillGraphReplayContext` checks the live width for V4.1 and the fixed width with c4/c128 metadata.

Behavior change only for V4.1 with `--cuda-graph-backend-prefill breakable` on CUDA without two-level candidates (SM90): contexts past 16K replay the graph instead of running eager. Under attention context parallelism, which had no default limit, replay metadata is built at the live width instead of the table width. Follows #45407.
