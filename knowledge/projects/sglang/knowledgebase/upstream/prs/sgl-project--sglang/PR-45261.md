# [Fix] [NVIDIA] deepseek_v4: Use DeepGEMM paged-MQA metadata for low-ratio indexers on SM120

[Upstream PR](https://github.com/sgl-project/sglang/pull/45261) · state: open · merged: False

## Original PR description

## Motivation
On SM120 (RTX PRO 5000/6000 Blackwell), DeepSeek-V4.1-Flash crashes on the first forward once the candidate indexer is allowed to run (see #42371):
```
deep_gemm.fp8_fp4_paged_mqa_logits -> Assertion error (layout.hpp:45): t.is_cuda()
  via _low_ratio_index_topk -> full_topk._deep_gemm_decode
```
The c1/c2 (low-ratio) indexers always score with DeepGEMM's FP4 paged MQA kernel. On SM120 that kernel schedules split_kv=128, but the default JIT metadata planner (`SGLANG_OPT_USE_JIT_INDEXER_METADATA=1`) encodes split_kv=256. The existing guard covers only the FP4 c4 indexer (`--enable-deepseek-v4-fp4-indexer`).

## Modifications
`force_deep_gemm_metadata` is now also True for `compress_ratio in (1, 2)` on SM120. Other platforms and the c4 path are unchanged.

## Accuracy Tests
8x RTX PRO 5000 72GB, DP8 attention + EP8. Tree: upstream `a90e9c5d` + #42371 + the other SM120 PRs.
- Without this change, the first forward crashes in `deep_gemm_fp4_paged_mqa_logits` (`index_logits.py:108`) with the traceback above.
- With it: GSM8K (5-shot, 1319 questions) 0.905, invalid 0.000.

## Speed Tests and Profiling
No perf change is intended; this is a correctness fix.
