# [Feat] dcp: Replicate a block-FP8 q_b_proj under --dcp-replicate-q-proj

[Upstream PR](https://github.com/sgl-project/sglang/pull/46359) · state: closed · merged: True

## Original PR description

## Motivation

`--dcp-replicate-q-proj` only accepts an unquantized bf16/fp16 `q_b_proj`, so models whose `q_b_proj` is 128x128 block FP8 (e.g. the Kimi-K3 NVFP4 checkpoint, which enables the flag by default on the a2a / fi_a2a backends) skip every MLA layer and keep the per-layer Q all-gather in the decode graph.

## Modifications

- `model_runner.py`: accept a 128x128 block-FP8 `Fp8LinearMethod` `q_b_proj`. `_gather_block_fp8_linear` recovers the logical fp32 block scales (undoing UE8M0 packing), all-gathers weight and scales along the output dim, and re-runs the layer's `process_weights_after_loading` on the replica so it uses the same GEMM as the per-rank shard.
- `deepseek_v2.py` / `forward_mla.py`: `q_b_proj_replicated_forward()` covers both the bf16 weight and the FP8 replica; the full-head `bmm_q` result is passed on as the transposed view instead of a copy, as in the non-DCP absorb path.
- Docs: list the supported q-proj formats.

## Accuracy Tests

Replica check on GB300 (SM103): a block-FP8 linear split into 4 DCP-style row shards and rebuilt through `_gather_block_fp8_linear` is bit-identical to the unsharded layer (weight bytes and GEMM output at M = 1, 8, 48) on triton, deep_gemm, flashinfer_trtllm and flashinfer_cutlass. The deep_gemm case showed that re-running the UE8M0 requant on the gathered weight is not idempotent, hence the re-pack in `_gather_block_fp8_linear`.

GSM8K, `sglang.test.few_shot_gsm8k` 200 questions, 5-shot, temperature 0. Kimi-K3 NVFP4 (`nvidia/Kimi-K3-NVFP4`), TP8/DCP8 across two 4-GPU GB300 nodes, `fi_a2a`, fp8_e4m3 KV, DSpark block 7 with real acceptance, no HiCache. Same build for both arms; the baseline arm passes `--no-dcp-replicate-q-proj`, which is what main effectively does on this checkpoint (every MLA layer is skipped).

| Arm | Replicated layers | Accuracy | Invalid |
|---|---:|---:|---:|
| `--no-dcp-replicate-q-proj` | 0 | 0.975 | 0.005 |
| this PR (replicate on) | 24 | 0.970 | 0.005 |

## Speed Tests and Profiling

Same servers, `sglang.benchmark.one_batch_server --base-url`, batch 1, 128k input / 1k output, 95% cache hit, three repeats each. Acceptance length is 4.53 in both arms.

| Arm | Latency (s) | Output tok/s | Steady-state tok/s | TTFT (s) |
|---|---:|---:|---:|---:|
| `--no-dcp-replicate-q-proj` | 4.037 / 4.021 / 4.024 | 287.8 / 287.7 / 287.8 | 287.5 | 0.54-0.56 |
| this PR (replicate on) | 3.963 / 3.976 / 3.958 | 294.3 / 294.2 / 294.3 | 294.0 | 0.56-0.58 |

Decode output throughput +2.3% at batch 1 from removing the per-layer Q all-gather in the 24 MLA layers.
