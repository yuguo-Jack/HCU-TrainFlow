# fix: reject scalar bootstrap_room whose fan-out would overflow i64

[Upstream PR](https://github.com/sgl-project/sglang/pull/43890) · state: open · merged: False

## Original PR description

## Summary

Fixes #43882.

The Rust normalizer (`normalize_bootstrap_columns`) uses `wrapping_add` to fan out a scalar `bootstrap_room` across a batch, while the Python normalizer (`io_struct.py`) uses arbitrary-precision addition. For rooms near `i64::MAX` the two frontends derive different room values for the same request body, breaking the PD rendezvous contract — the prefill and decode legs rendezvous on different rooms and the KV transfer times out.

## Change

Reject with `Error::Validation` when `room > i64::MAX - (prompt_count - 1)` — exactly the condition under which `wrapping_add` would wrap and diverge from Python. The boundary room `i64::MAX - (prompt_count - 1)` is still accepted (its fan-out reaches exactly `i64::MAX` without wrapping).

- `prompt_count >= 1` is guaranteed by `into_requests` (empty batches are rejected), so the subtraction cannot underflow.
- The `wrapping_add` fan-out is unchanged for accepted rooms, preserving distinct pairing keys.
- Python is unchanged: its arbitrary-precision semantics are the correct reference.

## Test

`bootstrap_room_fan_out_overflow_rejected`:
- scalar room `i64::MAX` with 2 prompts → rejected with a Validation error naming `bootstrap_room`
- boundary room `i64::MAX - 1` with 2 prompts → accepted with rooms `[MAX-1, MAX]`
