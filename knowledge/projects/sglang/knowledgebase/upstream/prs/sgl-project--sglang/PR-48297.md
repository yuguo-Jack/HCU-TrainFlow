# [Fix] responses: Recover malformed Harmony tool headers

[Upstream PR](https://github.com/sgl-project/sglang/pull/48297) · state: open · merged: False

## Original PR description

## Motivation

Harmony Responses requests can fail or silently lose function calls when generated tool headers contain duplicated metadata or omit `<|message|>`. This PR recovers those two recognized forms and returns the function call in both streaming and non-streaming responses.

This is a separate, complementary fix to the **oss-harmony migration in #48267**. The malformed streams reproduce with both `openai-harmony==0.0.4` and `oss-harmony==0.0.12`; changing the package alone does not repair them. This PR changes output parsing, with no dependency or prompt-rendering changes. The branches merge cleanly at migration commit `afbe4d556217b6cc9668aeea1ec58fec1d592020`.

The recovery approach is adapted from the unmerged [vLLM PR #59387](https://github.com/vllm-project/vllm/pull/59387), commit `756ee24f369475638e4bb887828fa45333425864`, with attribution in the new module.

### Symptoms

1. **Spliced header metadata** makes the native parser raise `HarmonyError: unexpected tokens remaining in message header`. The non-streaming Responses handler returns HTTP 400; the streaming generator raises before completing the response.

   ```text
   <|channel|>commentary to=functions.echo <|constrain|>commentary to=assistant <|constrain|>analysis to=functions.echo json<|message|>{"x":1}<|call|>
   ```

2. **A missing message separator** leaves the arguments buffered as header text, so the completed response omits the function call. The same happens with an empty `<|constrain|>` immediately before the JSON.

   ```text
   <|channel|>analysis to=functions.echo{"x":1}<|call|>
   <|channel|>analysis to=functions.echo<|constrain|>{"x":1}<|call|>
   ```

The handler also currently classifies valid `analysis`-channel function recipients as reasoning. The output routing fix below is needed to expose recovered analysis-channel function calls correctly.

## Modifications

- Wrap the native `StreamableParser` with narrow recovery. Valid streams continue through the native parser. Recognized duplicate metadata is repaired only after a parser error at the message separator; earlier completed messages and body text are preserved.
- At generation completion, repair a missing separator only for an analysis/commentary `functions.*` recipient declared in the request, a complete JSON object, and a real `<|call|>` terminator. Reject unrelated recipients, undeclared tools, truncated/non-object JSON, authored prose, and control tokens inside the payload.
- Preserve original argument tokens, including literal Harmony-looking text and Unicode; only a token spanning the header/body boundary needs retokenization.
- Route function recipients before generic analysis reasoning in completed and partial output conversion. Preserve surrounding reasoning/text and streaming item IDs, sequence numbers, deltas, and completion events.
- Add regressions to the existing Responses suites, including cumulative/incremental token delivery and token-by-token/coalesced chunks. No legacy rendering helper is introduced.
