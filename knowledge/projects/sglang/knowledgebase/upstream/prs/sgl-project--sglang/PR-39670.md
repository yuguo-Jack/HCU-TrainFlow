# [CI][NPU] Stop running the NPU PR suite on every PR

[Upstream PR](https://github.com/sgl-project/sglang/pull/39670) · state: open · merged: False

## Original PR description

## Motivation

`pr-test-npu.yml`'s `check-changes` filter currently matches **every file in the
repository**, so the NPU PR suite runs on every PR — including ones that touch no
Python at all.

#39110 is the case that surfaced it: a two-file change under
`experimental/sgl-router/tests/e2e/` pulled in the full A2/A3 NPU fleet
(`base-a-test-1-npu-a2`, `base-b-test-{1,2,4,8,16}-npu-a3`,
`base-c-test-acc-{2,16}-npu-a3`), and `pr-test-npu-finish` went red on failures
in NPU accuracy jobs that the PR could not possibly have caused. That run's own
paths-filter log lists both router files as matches:

```
Detected 2 changed files
##[group]Filter main_package = true
Matching files:
experimental/sgl-router/tests/e2e/chat_completions/test_hicache_storage_tiers.py [added]
experimental/sgl-router/tests/e2e/infra/model_pool.py [modified]
```

### Cause

#39411 rewrote `main_package` from a single extglob into a pattern plus two
standalone negations:

```yaml
main_package:
  - "python/sglang/**/!(*.md)"
  - "!python/sglang/multimodal_gen/**"
  - "!python/sglang/kernels/ops/diffusion/**"
```

`dorny/paths-filter` ORs a filter's entries together — `predicate-quantifier`
defaults to `some`, so each entry is an independent rule and a file matches the
filter if **any** rule matches it. A negated rule matches every path *outside*
the path it names, so `!python/sglang/multimodal_gen/**` matches the whole
repository minus that one directory. The intended subtraction became a
repo-wide union.

## Modifications

Spell the exclusions as extglobs *inside* the patterns, so there are no
standalone negated entries. This is the form `_pr-test-check-changes.yml`
already uses for the same two directories:

```yaml
main_package:
  - "python/sglang/!(multimodal_gen|kernels)/**/!(*.md)"
  - "python/sglang/kernels/!(*.md)"
  - "python/sglang/kernels/!(ops)/**/!(*.md)"
  - "python/sglang/kernels/ops/!(*.md)"
  - "python/sglang/kernels/ops/!(diffusion)/**/!(*.md)"
```

#39411's intent is preserved: `python/sglang/kernels/ops/diffusion/**` still
routes to `multimodal_gen` only, and the `multimodal_gen` filter and the daily
schedule are untouched. A comment records why the negations cannot come back.

## Tests

The filter block was parsed straight out of the workflow file and run through
`picomatch` (same major as the one `dorny/paths-filter@v3` ships) with
`{dot: true}` and the default `some` quantifier, against all 9176 tracked files.

| | before | after |
| --- | --- | --- |
| files matching `main_package` | 9176 (100%) | 3840 (41.8%) |
| non-`python/` files matching `main_package` | 8681 | 0 |

Per-case, with both filters evaluated:

| changed paths | `main_package` | `multimodal_gen` | NPU jobs |
| --- | --- | --- | --- |
| #39110's two router test files | false | false | **skip** |
| `experimental/sgl-router/src/**` | false | false | **skip** |
| `rust/**`, `docs/**` | false | false | **skip** |
| `python/sglang/srt/managers/scheduler.py` | true | true | run |
| `python/sglang/kernels/ops/moe/topk.py` | true | false | run |
| `python/sglang/kernels/aot/csrc/*.cu` | true | false | run |
| `python/sglang/kernels/ops/diffusion/**` | false | true | run (mm-gen only) |
| `python/sglang/multimodal_gen/**` | false | true | run (mm-gen only) |
| `scripts/ci/npu/npu_ci_install_dependency.sh` | true | true | run |
| `.github/workflows/pr-test-npu.yml` | true | true | run |

Against the pre-#39411 filter the only behavioural difference over all tracked
files is the 86 `python/sglang/kernels/ops/diffusion/**` files that #39411
deliberately moved out of `main_package`.

Note that this PR touches `pr-test-npu.yml`, which is itself in the filter, so
the NPU suite runs on this PR and exercises the new filter end to end.
