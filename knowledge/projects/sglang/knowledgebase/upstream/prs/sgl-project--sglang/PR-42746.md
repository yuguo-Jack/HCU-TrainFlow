# Use a separate workspace for fmha_v2 prefill in trtllm_mha

[Upstream PR](https://github.com/sgl-project/sglang/pull/42746) · state: open · merged: False

## Original PR description

## Motivation

On SM90/SM120, `trtllm_mha` runs prefill with `trtllm_fmha_v2_prefill` and decode with XQA, and both used the same `trtllm_mha_zero_workspace`. fmha_v2 leaves its 4-byte tile counter at offset 0 of its workspace; XQA keeps its multi-block semaphores in the first 8 MB of the same buffer and needs them to start at zero. After any prefill, long-KV (multi-block) XQA decodes merge partial results at the wrong time and return wrong output for a batch slot. XQA does not clear a dirty semaphore, so the corruption persists.

This silently drops accuracy with `--attention-backend trtllm_mha` on H100 (MTP off). The split config (`--prefill-attention-backend flashinfer --decode-attention-backend trtllm_mha`) is not affected.

## Modifications

- Give fmha_v2 prefill its own small workspace (`trtllm_mha_fmha_v2_workspace`, 16 MB, SM90/SM120 only); XQA decode keeps the existing buffer.
- Add `test_fmha_v2_extend_then_xqa_long_kv_decode` (SM90/SM120): a long-KV XQA decode must return bit-identical output before and after an fmha_v2 extend. It fails without the fix on H100.

## Accuracy Tests

GSM8K (lm_eval, 5-shot, flexible-extract), Nemotron-H hybrid model, BF16, TP4, H100, FP8 KV, `--attention-backend trtllm_mha`, MTP off:

| | GSM8K |
|---|---|
| MTP0, no fix (3 runs) | 0.8825 / 0.8863 / 0.8779 |
| MTP0, with fix | 0.9166 |

The no-fix runs used an earlier nightly with an older memory config; for reference, FlashInfer prefill + XQA decode on the with-fix setup scores 0.9196.
