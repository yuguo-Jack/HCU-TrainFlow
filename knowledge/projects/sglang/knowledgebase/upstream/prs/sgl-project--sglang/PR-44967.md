# [Test] [NPU] kimi_k3: add 128k prefill/decode perf acceptance cases on 4-node mix

[Upstream PR](https://github.com/sgl-project/sglang/pull/44967) · state: closed · merged: True

## Original PR description

## Summary
Scoped follow-up of #44398: validate the AISBench perf path of the NPU nightly multi-node pipeline with the shortest acceptance scenario — cold prefill 16k in / 1 out, C1/N1, GSM8K exact-length dataset, 4-node mix 32P (server launch identical to the scoped accuracy case).

- Add `python/sglang/test/ascend/e2e/run_aisbench.sh`: `run_aisbench()` in `test_npu_performance_utils.py` references this script, but it was never checked in, so the `AISBENCHMARK` branch of the perf framework could not run. The script installs `ais-bench-benchmark` from the Tsinghua mirror into a local venv (reusing a system-wide install when present), renders a single-file task config (SGLang streaming API + custom jsonl + `default_perf`) and streams the result tables consumed by the metric parser.
- Add `test/registered/npu/performance/kimi_k3/test_npu_kimi_k3_w4a8_32p_mix_in16k_out1_prefill.py`: 16k in / 1 out, TTFT gate 6000 ms is a pipeline-validation threshold (historical ~5 s at C1); the 4.0 s acceptance SLO is tracked separately.
- Scope `nightly-test-npu.yml` to this perf trial only (B103 image kept); the L2 HiCache accuracy case stays with #44398 to keep 4-node pool load minimal.

## Test plan
- [ ] CI run of `nightly-test-npu.yml` triggered by this PR
- [ ] `multi-node-mix-poc (kimi_k3_w4a8_32p_mix_in16k_out1_prefill_aisbench)` job starts 4-node B103 pods
- [ ] aisbench venv install + task config render in-pod
- [ ] Common Metric table parsed (mean_ttft dumped to metrics file)
