# [DSpark] Draft the proposal through one `run_draft_proposal` for the graph tail and eager

[Upstream PR](https://github.com/sgl-project/sglang/pull/43893) · state: open · merged: False

## Original PR description

- `run_draft_proposal` (`dspark_draft.py`) drafts a block from the draft forward's hidden rows: it selects the draft rows, computes the base logits, runs the Markov steps and computes confidence. The draft graph tail and the eager `DraftBlockProposer.propose` both call it, and each path's own assembly is removed.
- `DsparkDraftSampler` is renamed `DraftProposalGraphTail` (`dspark_proposal_graph_tail.py`), since it runs the whole proposal.
- The graph tail sizes its step-logits buffer from the step logits its first (warmup) call returns.
- `propose` takes the graph path when a graph tail is attached and the draft graph ran; `SGLANG_DSPARK_FOLDED_PROPOSAL` is read only in the worker.

No behavior change.

## Verification

- Old vs new draft outputs (tokens, step logits, greedy mask, temperatures, confidence, raw confidence, noise offset) bit-identical over 96 cases (vanilla, gated, RNN Markov heads; with and without a confidence head; `sample_from_anchor`; greedy and sampling).
- DeepSeek-V4.1 DSpark at TP4 on GB300, temperature 0, batch sizes 1, 8 and 80: output tokens, per-step draft tokens and commit lengths identical to main; median TPOT within run-to-run noise of main.
- DSpark draft graph, STS, kernel parity, accept and greedy-draft accept tests pass on GB300.
