# [Fix] MegaMoE: stop double-dividing the DP prefill budget

[Upstream PR](https://github.com/sgl-project/sglang/pull/46267) · state: closed · merged: True

## Original PR description

## Motivation

MegaMoE's startup token-budget check can accept an undersized per-rank token budget when attention DP is enabled. The check is the guard that ensures `SGLANG_OPT_DEEPGEMM_MEGA_MOE_NUM_MAX_TOKENS_PER_RANK` covers the largest per-rank prefill / verify batch. When it under-reports, an undersized cap passes startup and the runtime later either fails its token-cap assertion during CUDA graph capture or silently falls back off the MegaMoE path for oversized batches.

## Root cause

`handle_data_parallelism` already divides `chunked_prefill_size` by `attn_dp_size` and declares the per-rank value:

`python/sglang/srt/arg_groups/parallel_hook.py:331`

```python
chunked_prefill_size=cfg.chunked_prefill_size // cfg.attn_dp_size,
```

`validate_mega_moe_token_budget` reads that resolved value through `resolving_view`, but then divides it by `attn_dp_size` a second time:

`python/sglang/srt/arg_groups/mega_moe_hook.py:206-212`

```python
elif attn_dp_enabled_of(cfg):
    token_partition_size = cfg.attn_dp_size
    ...
    local_chunked_prefill_size = cfg.chunked_prefill_size // token_partition_size
```

With `--chunked-prefill-size 16384 --attn-dp-size 2`, the real per-rank chunk is 8192, but the validator computes 4096. `SGLANG_OPT_DEEPGEMM_MEGA_MOE_NUM_MAX_TOKENS_PER_RANK=4096` then passes validation even though each rank can receive 8192 prefill tokens.

At runtime, `mega_moe.py:440` asserts `num_tokens <= cap` during CUDA graph capture; outside capture, `should_use_mega_moe` falls back off the MegaMoE path for batches above the cap.

## Modifications

- Use the already-resolved per-rank `chunked_prefill_size` directly in the attention-DP branch.
- Update the diagnostic label to make clear the DP division was already applied.
- Add `test_megamoe_token_budget_uses_resolved_dp_chunked_prefill` in `test/registered/unit/server_args/test_server_args.py`. It declares an 8192-token per-rank chunk (the state after `handle_data_parallelism`), verifies 8192 passes, and verifies 4096 is rejected with `required_per_rank=8192`.

## Validation

- `python -m pytest test/registered/unit/server_args/test_server_args.py -k megamoe -q` -> 19 passed.
- `pre-commit run --files python/sglang/srt/arg_groups/mega_moe_hook.py test/registered/unit/server_args/test_server_args.py` -> all passed.
- The new test fails when the second division is restored (`AssertionError: ValueError not raised`), so it covers the regression.
- I also invoked the real `handle_data_parallelism` hook: it logs `adjusted from 16384 to 8192` and records `{'chunked_prefill_size': 8192}`.
- Branch is based on `main` at `1335d372f`.
