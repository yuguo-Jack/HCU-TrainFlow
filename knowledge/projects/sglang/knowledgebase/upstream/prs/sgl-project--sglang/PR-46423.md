# [Feat] disaggregation: Verify the KV checksum under a decode-side radix cache

[Upstream PR](https://github.com/sgl-project/sglang/pull/46423) · state: closed · merged: True

## Original PR description

## Motivation

Follow-up to #39729. Two gaps it left:

1. With `--disaggregation-decode-enable-radix-cache` the decode holds the prefix it cached and prefill sends only the suffix. The digest covered the whole prompt, so every hit would have looked like corruption, and the decode turned the checksum off with a warning. That is the common production shape, so the flag could not run where it matters.
2. The layout signature hashed only page size and per-buffer byte lengths. Two layouts with equal byte sizes but different bytes (fp16 vs bf16, two DeepSeek-V4 page layouts, a different state type set) collided, which would surface as a mismatch on every request instead of one logged skip.

## Modifications

- Prefill digests `[req.disagg_decode_prefix_len, end_idx)`, the pages it actually sends. Decode digests the same range of its own row, starting at `req.kv.cache_protected_len`, which preallocation already sets to the prefix it promised prefill at bootstrap. Both come from the same `prefix_match.decode_prefix_len`, so nothing new goes over the wire and the metadata row is unchanged. The SWA window start and the DSA page rows clamp to the same start; the Mamba state is per request and unchanged.
- The decode no longer disables the checksum when its radix cache is on.
- `kv_layout_signature` folds in `kv_cache_dtype_str`, `kv_layout`, `swa_kv_cache_layout` and the state types. The attention backend is deliberately left out: it may differ between roles over the same KV bytes.
- Flag help text mentions both.

Rollout note: the signature changes, so a decode on this PR paired with a prefill on #39729 logs one "layout differs" warning and admits that prefill's requests unverified until the prefill is upgraded. No abort, no hang.

Scope note: with decode HiCache the `[l1_prefix_len, total_prefix_len)` gap is restored from host, not sent by prefill, so it stays outside the digest. A full-prompt hit digests an empty range on both sides (Adler-32 of nothing is 1).

## Tests

- `test/registered/unit/disaggregation/test_kv_checksum.py`: prefill digests from the decode prefix; the decode digest skips the decode-cached prefix (CUDA); the signature separates dtype, page layout and state types. CPU part run locally: 12 passed, 16 CUDA-skipped. Whole `test/registered/unit/disaggregation/` sweep against main: identical failure set (the 6 local-only multi-rank gloo cases), +1 pass +1 skip.
- `test/registered/disaggregation/test_disaggregation_kv_checksum.py`: a second class with `--disaggregation-decode-enable-radix-cache` sends prompts sharing a long prefix; every hit must verify and both engines must stay up. In CI a false mismatch raises, so a whole-prompt digest cannot pass it.
