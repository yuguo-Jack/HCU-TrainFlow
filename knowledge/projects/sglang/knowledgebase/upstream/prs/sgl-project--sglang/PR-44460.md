# [Feat] sgl-router: Add a Tair KVCache backend to the KV Indexer

[Upstream PR](https://github.com/sgl-project/sglang/pull/44460) · state: open · merged: False

## Original PR description

## Motivation

The KV Indexer answers the Router's prefix queries from process-local state, so an Indexer restart drops every placement and each deployment has to rebuild them from the workers' KV-event streams. Deployments that already run a [Tair KVCache Manager](https://github.com/alibaba/tair-kvcache) (KVCM) keep the same information there, and the manager already tracks reporter liveness and capacity eviction for them.

This adds a `tair_kvcache_kvcm` backend that keeps the Indexer's placement state in that manager's `MetaService` instead of the Indexer process. The Indexer becomes stateless: restarts no longer lose affinity, and the manager's own view of which reporter holds which block is the single source of truth for routing.

The component name and the clear mapping were coordinated with the Tair KVCache maintainers; the semantics this backend relies on were verified against the manager's implementation and its own tests.

## Modifications

- `KV_INDEXER_BACKEND=tair_kvcache_kvcm` selects `TairKVCacheIndexerBackend` (`experimental/sgl-router/sgl-kv-indexer/src/tair_kvcache_backend.rs`), configured through `KV_INDEXER_TAIR_KVCACHE_KVCM_*` environment variables.
- Apply batches translate to `ReportEvent` mutations: REPORT → `BLOCK_ADD` (one location spec per resident component), REVOKE → `BLOCK_DELETE`, `CLEAR_ALL_AT_TIER` → an empty `BLOCK_SNAPSHOT`, and the first batch per worker prepends `NODE_REGISTER`. Prefix queries translate to `GetHostCacheState` (`QT_PREFIX_MATCH`).
- Component-aware workers are excluded from answers rather than over-reported: the manager's whole-block answer cannot express SWA windows or MAMBA boundaries, so the backend fails closed exactly where the in-memory rule engine would.
- The clear-as-empty-snapshot semantics are documented in the README: the snapshot commits synchronously and fences the reporter's older locations behind strict visibility (scope: the whole reporter × storage channel, every medium); it travels alone in its request and in action order; snapshots are rate-limited per (instance, channel, reporter), 30s by default, and a flush inside that window is dropped with a warning instead of failing the batch.
- A vendored `tair_kvcache_meta_service.proto` (the manager's `MetaService`), a mock-based contract suite, and an env-gated live suite that runs the backend against a real manager (`tests/tair_kvcache_live/`).

## Accuracy Tests

Unit and contract suites need no external service:

```bash
cargo test -p sgl-kv-indexer
```

- `tests/tair_kvcache_contract.rs`: the backend against an in-process mock `MetaService` over real gRPC (translation both ways, KVCM acceptance rules, registration and error classification, clear retry/degrade paths), including one end-to-end pass behind the real `KVIndexer` service.
- `tests/tair_kvcache_live.rs` (`#[ignore]`d, real manager): 23 tests pinning the manager's observable behavior — accepted events and spec/URI rules, liveness reclamation and the `NODE_NOT_REGISTERED` self-heal, `snapshot_required`, medium filtering, and the clear (placements gone after a flush, a report after a clear landing on the fresh generation, and the rate-limit degradation path). Run them with `--ignored` after `python3 sgl-kv-indexer/tests/tair_kvcache_live/setup_tair_kvcache_manager.py start`; the README has the two commands.

End to end, on a 3-worker/3-bridge deployment with the Router on `cache_aware` + `--cache-prefix-provider indexer`: prefix answers matched the workers' own ZMQ event streams block for block under concurrent load and natural eviction, and the `flush_cache` wave went from 12/12 stale placements (before the empty-snapshot clear) to 0.

## Speed Tests and Profiling

Not applicable: this adds a storage backend to the Indexer's metadata path and does not change model execution. Query latency is bounded by `QUERY_TIMEOUT_MS` (default 50ms, half the Router-side prefix deadline).
