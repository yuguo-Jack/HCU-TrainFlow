# [Feat] valen: add native multimodal shared-state decisions

[Upstream PR](https://github.com/sgl-project/sglang/pull/44709) · state: open · merged: False

## Original PR description

## Motivation

Valen's complete dense Qwen3.5 checkpoints answer Choice, Noul, and Score
questions using one shared causal prefill and a trained FP32 Mixer. This adds
native checkpoint loading and text/image/video decisions through `/v1/valen`.
All questions read the same processed state and retain the trained role/readout
layout and original answer formulas.

## Modifications

- Register `valen_qwen` and `ValenQwenForDecisionMaking`, reuse Qwen3.5 language
  and vision kernels/fused loaders, and strictly validate backbone and Mixer
  loading. Keep the Mixer parameters and computation in FP32.
- Carry request-local layouts through embedding IPC, scheduling, and forward
  batches. Require TP=PP=1 with complete prefill, disabled radix/chunking/CUDA
  graphs, and explicit errors for unsupported quantization or prompt truncation.
- Preserve Choice order, fixed bilingual Noul descriptions, and 2–255-level
  native Score. Add `/v1/valen` and a limited text/image `/v1/systemone` adapter.
- Use checkpoint HF media settings before appending schema tokens; transfer
  expanded IDs, pixels, and grids as `processor_output`. Preserve the training
  processor's video wrapper semantics with current Transformers. Reuse bounded
  URL loading, count assets before bundling, and clean temporary media on errors.
- Validate reserved controls against tokenizer.json added-token metadata as well
  as the tokenizer's special-token map. Add API documentation and CPU regressions.

## Accuracy Tests

- **39 CPU tests passed, 1 skipped** (37 Valen tests and two neighboring Clef CPU
  tests; the skipped neighboring test requires CUDA). Includes prompt/layout,
  FP32 head math, packed request isolation, media/limit errors, URL staging and
  cleanup, response semantics, and generator lifecycle.
- Ten component cases match the original Valen compiler, role spans, media
  pixels, MRoPE, and answer function. Random shared Mixer weights with FP32/BF16
  hidden inputs: maximum logit error 1.2e-7. Nine cases with the actual released
  2B Mixer weights and random hidden inputs: 1.4e-6. Real SGLang CPU media
  splitting/offset/MRoPE checks passed image, video, and interleaved fixtures.
- **Native GPU validation on one H200**, with complete Valen-2B weights and
  `model_impl=sglang`: strict loading, vision encoding, hybrid GDN/attention,
  pooling, and serving passed eight synthetic text/image/video/mixed multi-turn
  cases, including mixed Choice/Noul/Score questions.
- Original HF reference: FP32 stored backbone + BF16 autocast, PyTorch 2.6 and
  Transformers 5.4. Native runtime: BF16 backbone + FP32 Mixer, PyTorch 2.14.1
  (CUDA 13), Transformers 5.19, sglang-kernel 0.4.10, and FlashInfer 0.7.2.
  Language/GDN attention used Triton; vision used FA3. Prompt IDs matched exactly.

| Full-model comparison to original HF | Maximum absolute error | Smoke tolerance |
| --- | --- | --- |
| Probability / Noul | 0.005102 | 0.02 |
| Score | 0.009516 | 0.1 |
| Confidence | 0.014274 | 0.05 |
| Raw candidate logits | 0.439496 | Reported separately |

All Choice decisions matched. These are synthetic correctness checks, not a
workload-level quality evaluation. Raw logits are not bitwise equivalent across
these storage/compute precisions and kernels.

- Concurrent versus isolated native requests: Choice decisions matched; maximum
  probability change 0.007273, below the explicit 0.01 tolerance. Raw logit change
  reached 0.036502 on a soft-label case; the report retains that drift rather
  than claiming identical BF16 reductions across batch shapes.
- **Actual HTTP server**: eight isolated and eight concurrent `/v1/valen`
  requests passed, including image/video/mixed inputs and response token counts.
  A tokenizer.json control-token injection was correctly rejected with 400.
- Ruff/isort/formatting, registered-test lint, diff whitespace, Mintlify build
  validation, and internal link checks passed.

## Speed Tests and Profiling

No controlled performance benchmark yet. The validation records smoke forward
and HTTP timings, including initial compilation. The HF baseline uses its torch
fallback, so those timings are not presented as a speedup claim.

- [x] Complete native weights/backbone/Mixer execution on an H200.
- [x] Original HF comparisons with numerical differences explicitly reported.
- [x] Concurrent requests and actual multimodal HTTP checks.
- [x] API docs, formatting, and Mintlify checks.

Valen-2B; TP/PP, quantization, and other head architectures are outside this PR.
