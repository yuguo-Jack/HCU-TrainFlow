# [Fix] diffusion: Handle seed lists in multi-output dynamic batches

[Upstream PR](https://github.com/sgl-project/sglang/pull/46281) · state: open · merged: False

## Original PR description

## Motivation

Compatible multi-output diffusion requests with explicit seed lists work individually but raise `TypeError` when dynamically batched.

Related: #39377 normalizes single-output seed lists in the shared scheduler and excludes SenseNova's sequential multi-output requests from dynamic batching. For other pipelines that allow multi-output batching, the scheduler still preserves each request's seed list. `InputValidationStage._generate_seeds` then applies `int()` to that list.

Reproduced with QwenImage21 requests through the real scheduler and input stage:

| Request | Outputs per prompt | Seed |
|---|---|---|
| A | 2 | `[7, 101]` |
| B | 2 | `[17, 203]` |

Individually, both requests produce the requested seeds. Merging them stores `[[7, 101], [17, 203]]` in `dynamic_batch_seeds`, causing `int(list)` to fail. This fix produces `[7, 101, 17, 203]` in request/output order.

## Modifications

- Reuse `normalize_output_seeds` in the input stage to expand each prompt's scalar or explicit seed list, completing the multi-output case left uncovered by the scheduler's single-output normalization.
- Preserve scalar expansion, explicit list values, duplicates, and request/output order. Keep scheduler admission rules and SenseNova's sequential multi-output handling unchanged.
- Extend the existing scheduler batching test to exercise the input stage and compare merged random tensors with individual requests. Cover non-consecutive lists, mixed scalar/list seeds, duplicate seeds, reordered requests, and one/three-output cases.
- Add input-stage regression coverage for invalid metadata/list lengths and unchanged single-request behavior.

## Accuracy Tests

Base: `25ba24e9a7b7cfd3859552444f44c5b473fa1646`. Python 3.12.14, PyTorch 2.14.1+cu130, pytest 9.1.1.

- Before the fix, six multi-output list/mixed-list parameter cases fail with `TypeError`; three invalid-length subtests also raise `TypeError` instead of the expected `ValueError`. Scalar and single-output controls pass.
- Both affected test files on CPU: **122 passed, 8 CUDA-only cases skipped**, plus 9 subtests passed.
- Both affected test files on one RTX 4090: **130 passed, no skips**, plus 9 subtests passed. These are full-file totals, including existing tests.
- A separate CUDA comparison covers nine input combinations in FP32/FP16/BF16 (**27 checks**). Every fixed merged random tensor is elementwise identical to individually generated tensors using the unmodified base implementation; scalar merged streams also match the unmodified base.
- Targeted and full-repository `pre-commit run --all-files` checks pass. The full-repository check used a separate worktree containing the same patch and introduced no additional diff.

Run the affected tests from the repository root with its source on `PYTHONPATH`:

```bash
PYTHONPATH=python CUDA_VISIBLE_DEVICES=0 python -m pytest -q \
  python/sglang/multimodal_gen/test/unit/test_input_validation.py \
  python/sglang/multimodal_gen/test/unit/test_qwen_image21.py
```

The tests use CPU generators for the seed regression and CUDA where existing cases require it. No model weights or inference server were used; these results establish batching/RNG correctness, not final generated-image equivalence.

## Speed Tests and Profiling

No inference speedup is claimed. This corrects per-output seed handling before model execution and does not change model kernels or scalar-seed behavior. No model latency or throughput benchmark was run.
