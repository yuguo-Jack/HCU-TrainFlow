# [diffusion] model: add native Ovis-Image support

[Upstream PR](https://github.com/sgl-project/sglang/pull/43152) · state: open · merged: False

## Original PR description

## Motivation

Add native text-to-image inference for [Ovis-Image 7B](https://huggingface.co/ATH-MaaS/Ovis-Image-7B) (Diffusers format). It is available through `sglang generate` and the OpenAI-compatible image API. `ATH-MaaS/Ovis-Image-7B`, the legacy `AIDC-AI/Ovis-Image-7B`, and local Diffusers component directories all resolve to the native pipeline. Defaults follow the official recipe: 1024 × 1024, 50 steps, CFG 5, 256 text tokens, BF16.

## Modifications

**Model and pipeline**
- Native Ovis DiT: 6 dual-stream and 27 single-stream blocks, context RMSNorm, SwiGLU, and the official weight mapping. Value/gate and attention/MLP output weights keep their own TP partitions.
- Reuses native Qwen3, AutoencoderKL, the shared denoising and residency stages, packed FLUX latents, and the conditioning cache.
- Follows the official prompt template, prefix masking, fixed-length text attention, dynamic scheduler shift, and `[A,A,B,B]` multi-output ordering.
- Supports serial and parallel CFG, DiT TP, Ulysses and Ring SP, and component/layerwise offload, with no new production CLI flags.
- Image editing, single-file weights, quantization, LoRA, caching accelerators, `torch.compile`, and breakable CUDA graphs are rejected with explicit errors.

**Numerics.** The goal is that single-GPU runs match pinned Diffusers bit for bit, and parallel runs stay within the reference's own noise.
- The QK RMSNorm rounds to BF16 before the FP32 RoPE, as the official `nn.RMSNorm` does. This is Ovis opt-in; FLUX defaults are unchanged.
- **Row-parallel projections**: TP row projections in the Ovis DiT (`OvisImageRowParallelLinear`) all-reduce FP32 partial products and round once with the bias, which is what the dense GEMM does. Reducing BF16 partials alone already puts short-text first predictions outside the BF16 tolerance; that was measured on one GPU with a K-split emulation.
- **Flash split-KV**: PyTorch flash attention switches to split-KV once `B·H·⌈Sq/128⌉ < 0.8·SMs`. TP and Ulysses shrink the local head count, so at short sequence lengths the shards take a different summation order than the full-head reference. On B200, at seq 1025, 24 heads and 12/6-head shards differ in 1.29M elements; at seq 4224 they match exactly. `OvisImageSDPAImpl` pads query rows past the threshold, but only when the full-head model would not split. This restores bitwise per-head equality, which a unit test checks.
- **Tail padding**: Ulysses tail-padded attention trims the padding after the all-to-all instead of masking it.
- Ovis-only, opt-in HF-compatible Qwen TP numerics. Text-encoder row projections gather the input and weight and run the full-K GEMM.

**Shared code**
- **VAE**: `AutoencoderKLMixin` now runs each tile of a tiled decode through spatial-parallel decode. Inputs shorter than the decode world size fall back to local decode. Before this, tiled + spatial decode called the sharded decoder on whole tiles. The Flux2 KL VAE shares this mixin and gets the same fix.
- **USP**: fixes receive-buffer ownership for sequential unpacked FP32 Q/K/V collectives.

**Tests and docs**
- Unit tests in `python/sglang/multimodal_gen/test/unit/` cover component numerics against the official small models, the TP and attention numerics above, config, the validator, USP buffers, and tiled spatial VAE on real Gloo groups.
- A B200 HTTP e2e test.
- A manual oracle and multi-GPU runner in `test/manual/diffusion/`. It requests `quality="exact"` by default, because the serving default `lossless` mounts VAE fast paths that only move rounding.
- Cookbook page, catalog entry.

Attribution and sources: [official transformer](https://github.com/huggingface/diffusers/blob/c6df88a511a98740646ee55577b590c9852650ce/src/diffusers/models/transformers/transformer_ovis_image.py), [official pipeline](https://github.com/huggingface/diffusers/blob/c6df88a511a98740646ee55577b590c9852650ce/src/diffusers/pipelines/ovis_image/pipeline_ovis_image.py), [checkpoint](https://huggingface.co/ATH-MaaS/Ovis-Image-7B/tree/41be1c5821a92c970d63d7eb595a2fd3fe32b22e).

## Accuracy Tests

**Setup**
- Pins: checkpoint `41be1c58`, independent official Diffusers `c6df88a5`.
- Inputs: identical CPU initial latents. Reference SDPA excludes cuDNN, matching the native platform policy.
- Tolerances are unchanged: BF16 `atol=0.05, rtol=0.02`; FP32 `1e-4`.
- Commit: every result below is from this branch's HEAD, on B200, with a clean tree.

**Single GPU (exact tier)**
| Check | Result |
|---|---|
| 512² L1/L64 and 1024²/50 quality scenes | Conditioning, every prediction, the full trajectory, and the decoded images are bit-exact vs official (PSNR ∞) |
| CFG2 L64 | Bit-exact |
| Same-latent dense VAE decode | Bit-exact vs official |

**Parallel, first predictions at the original tolerance**
| Topology | max abs / out-of-tolerance |
|---|---|
| L1 512² TP2 | 0.049 / 0 |
| L1 512² Ulysses2 | 0.016 / 0 |
| L1 512² TP2 × Ulysses2 | 0.049 / 0 |
| 1024² TP2 × Ulysses2 | 0.031 / 0 |

**Later steps against the noise baseline.** A late-step same-input check at the original tolerance cannot tell a parallel bug from evaluation-order noise. On a single GPU, changing only the FP32 summation order already puts step 49 at 496 out-of-tolerance elements.

We therefore gate the same-input four-GPU TP2 × Ulysses2 replay (1024², steps 0/11/12/49) against single-GPU controls:
- The controls are efficient-kernel SDPA, split-K with FP32 reduction, and split-K with BF16 reduction.
- Rule: per step, take the worse CFG branch. Max abs and the out-of-tolerance count must not exceed the worst control; RMSE must stay within 1.05× of it, because RMSE saturates at the BF16 floor.

| Step | TP2 × SP2 (max / count / rmse) | Worst control |
|---|---|---|
| 0 | 0.031 / 0 / 0.0044 | 0.031 / 0 / 0.0051 |
| 11 | 0.039 / 0 / 0.0057 | 0.148 / 23 / 0.0071 |
| 12 | 0.137 / 2 / 0.0065 | 0.270 / 93 / 0.0079 |
| 49 | 0.219 / 1693 / 0.0200 | 0.375 / 2242 / 0.0223 |

**Spatial VAE (same latent).** Raw decoder output has 17 out-of-tolerance values at max 0.090. The worst control (cuDNN autotune) is at 45 / 0.098, so this is within noise. Decoded images pass at the original tolerance.

**Runtime matrix.** All cases pass:
- single GPU, no-CFG, batch 2, prompt batch;
- component and layerwise offload;
- tiny TP2, tiny Ulysses2, tiny TP2 × SP2;
- TP2, Ulysses2, Ring2, CFG2, TP2 × SP2;
- tiled and spatial VAE;
- the HTTP lifecycle.

The cookbook HTTP recipe (1024²/50, one GPU) passes in 7.9 s including HTTP. Unit tests: 64 passed, 2 skipped.

## Speed Tests and Profiling

The FP32 TP reduction doubles row-projection all-reduce traffic.

| Configuration | BF16 reduction | FP32 reduction (this PR) |
|---|---|---|
| TP2, 1024², 50 steps, 2 × B200 (s/step, median of 4) | 0.083 | 0.099 |

Query padding only triggers at short sequences and does not run at 1024². These are DiT-step timings, not a serving benchmark.

## Follow-ups (not in this PR)

- The flash split-KV head-count dependence affects any DiT that shards heads at short sequence lengths, for example FLUX, Qwen-Image, and Anima. The shared fix is in #43242 (`SDPAImpl` / `USPAttention`, exact tier). Whichever PR lands second will switch `OvisImageSDPAImpl` to the shared implementation.
- `.github/workflows/_pr-test-check-changes.yml` still references the old `test/registered/unit/diffusion` path. This predates this branch.
