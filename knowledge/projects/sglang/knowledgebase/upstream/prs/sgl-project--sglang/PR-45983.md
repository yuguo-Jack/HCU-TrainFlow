# [CI] [AMD] diffusion: Drain the Cosmos Dreams decode stream after freeing its outputs

[Upstream PR](https://github.com/sgl-project/sglang/pull/45983) · state: closed · merged: True

## Original PR description

## What

`CausalDecodeQueue.__exit__` now resets the VAE and drops the pending outputs first, and synchronizes the decode stream last.

## Why

`test_cosmos_dreams.py::TestCosmosDreamsRuntime::test_overlap_and_serial_vae_inputs_match` (float32 subtest) fails on every scheduled rocm10 run of `multimodal-gen-test-1-gpu-amd` partition 3 since #39475 landed, at `self.assertTrue(queue.stream.query())` right after the context exits on an exception. Example: [job 119821718685](https://github.com/sgl-project/sglang/actions/runs/39777958482/job/119821718685), also [39879522486](https://github.com/sgl-project/sglang/actions/runs/39879522486), [39701015338](https://github.com/sgl-project/sglang/actions/runs/39701015338), [39522599360](https://github.com/sgl-project/sglang/actions/runs/39522599360).

On the exception path, `__exit__` synchronized the stream and only then called `self.outputs.clear()`. Those outputs are pinned host buffers that were the targets of `non_blocking` D2H copies on the decode stream, so freeing them makes PyTorch's caching host allocator record an event on that stream (`CachingHostAllocator::free`). The stream therefore has new work queued after the sync, and the class docstring's promise that leaving the context drains the stream no longer holds. On ROCm, `hipStreamQuery` reports that event as not ready yet.

Doing the cleanup first and the sync in the `finally` drains everything cleanup enqueues. Freeing these buffers before the sync is safe: the host allocator won't reuse a pinned block until its event completes, and the VAE feature-cache tensors were allocated on the decode stream.

## Test plan

- `multimodal-gen-test-1-gpu-amd` on rocm10, dispatched from this commit: [run 39905817439](https://github.com/sgl-project/sglang/actions/runs/39905817439).
