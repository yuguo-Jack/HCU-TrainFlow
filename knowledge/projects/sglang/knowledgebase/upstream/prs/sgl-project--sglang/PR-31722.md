# [AMD] Enable MTP/spec decoding with HiSparse on DSV4 unified-KV (ROCm)

[Upstream PR](https://github.com/sgl-project/sglang/pull/31722) · state: closed · merged: False

## Original PR description

## Summary

Enable speculative (EAGLE MTP) decoding with HiSparse KV offloading on the DSV4 unified-KV ROCm backend.

> **Depends on #29168** (unified-KV HiSparse on ROCm) and #26445 (HiSparse MTP for DSA). This PR adds the MTP-specific changes on top of #29168's unified-KV HiSparse support. File changes only include the MTP delta.

### Changes

- **hisparse.cuh/py**: Multi-step swap-in kernel (`num_steps`) with ROCm/HIP adaptations
- **hisparse_coordinator**: `swap_in` with `num_steps` + 3D reshape, draft slot lifecycle (`get_draft_device_slots`, `finalize_accepted_tokens`), DSV4 `token_position_space` conversion
- **dsv4/indexer**: `TARGET_VERIFY` uses `swap_in` (not mapping translate)
- **eagle_utils**: Integrate draft slot allocation into the verify path
- **eagle_worker_v2**: `finalize_accepted_tokens_spec_v2` + `finish_pending_draft_extend_backup`
- **eagle_info**: `slice_single`/`merge_batch` for spec_info staging relay
- **scheduler/batch_result_processor**: Per-request spec_info carry through HiSparse staging
- **allocator**: `alloc_extend_with_device_mapping` for DSV4 allocator
- **deepseek_v4_memory_pool**: `transfer_values_on_device` for unified C4 pool

### Follow-up fix: re-enable TARGET_VERIFY CUDA graph, fix a HiSparse+MTP memory-corruption bug

The verify CUDA graph was initially disabled whenever HiSparse was enabled (host↔device DMA was assumed incompatible with graph capture). Root-causing an intermittent "Memory access fault" crash under HiSparse+MTP concurrency led to two fixes, which also make it safe to re-enable the verify graph:

1. **CUDA-graph-unsafe buffer resize**: `swap_in_selected_pages` resized `top_k_device_locs_buffer`/`raw_indices_buffer` at runtime when the batch grew. Resizing invalidates addresses baked into a captured CUDA graph (stale-pointer writes on replay). Fixed by pre-sizing these buffers to the worst case (`max_num_req_slots * speculative_num_draft_tokens`) up front and asserting instead of resizing.
2. **Full-vs-compressed KV position mismatch (the actual root cause of the crash)**: `finalize_accepted_tokens`/`finalize_accepted_tokens_spec_v2` wrote raw (uncompressed) KV cache positions (`batch.out_cache_loc`) directly into `full_to_hisparse_device_index_mapping` (indexed by *compressed* positions) and into `req_device_buffer_token_locs`/`transfer_values_on_device` (which expect a *physical HiSparse device row*). Under concurrent load these raw positions regularly exceed the HiSparse device pool size, driving out-of-bounds device memory accesses and letting two unrelated, concurrently-active requests end up sharing the same physical HiSparse row. Fixed by only translating compress-group-boundary positions to compressed indices before touching the mapping, and by using the request's own reserved-slot physical row (`req_to_device_buffer[req_idx, device_buffer_size]`) instead of the raw KV position.

Verified with the debug-only ownership-tracking instrumentation used to root-cause this (not included in the final diff): the fix eliminates the double-allocation / out-of-bounds pattern under the same concurrent workload that reliably reproduced the crash before.

There are two issues here:
1. `swap_top_k_result` is sliced using `[:needed]` where `needed = num_reqs * num_steps`. Since the first dimension of `top_k_result` represents requests (`num_reqs`), slicing it by `needed` is incorrect when `num_steps > 1` (as `needed` is larger than `num_reqs`). It should be sliced to `[:num_reqs]` instead.
2. Inside the `if token_position_space == "full" and self.is_dsv4_hisparse:` block, the code incorrectly uses the unsliced `top_k_result` instead of `swap_top_k_result`. If `top_k_result` is padded (i.e., `top_k_result.size(0) > num_reqs`), this will cause a broadcasting shape mismatch `RuntimeError` when evaluating `top_k_result < seq_lens_for_compare` (since `seq_lens_for_compare` is sized to `num_reqs`).

Please slice `top_k_result` to `[:num_reqs]` first and perform all subsequent operations on `swap_top_k_result`.

```suggestion
        swap_seq_lens = compressed_seq_lens
        swap_top_k_result = top_k_result[:num_reqs] if top_k_result.size(0) > num_reqs else top_k_result
        if token_position_space == "full" and self.is_dsv4_hisparse:
            if num_steps > 1:
                seq_lens_for_compare = compressed_seq_lens.view(
                    num_reqs, num_steps
                ).unsqueeze(2)
            else:
                seq_lens_for_compare = compressed_seq_lens.unsqueeze(1)
            valid_compressed_token = (
                (swap_top_k_result >= 0)
                & (swap_top_k_result < seq_lens_for_compare)
                & ((swap_top_k_result + 1) % self.compress_ratio == 0)
            )
            swap_top_k_result = torch.where(
                valid_compressed_token,
                swap_top_k_result // self.compress_ratio,
                torch.full_like(swap_top_k_result, -1),
            )
```
