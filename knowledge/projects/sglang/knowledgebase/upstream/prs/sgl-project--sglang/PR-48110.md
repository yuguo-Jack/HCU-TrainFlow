# [Doc] [NVIDIA] qwen3: Add 16 GB consumer GPU (SM89) config tip to the cookbook

[Upstream PR](https://github.com/sgl-project/sglang/pull/48110) · state: open · merged: False

## Original PR description

## Motivation

The Qwen3 cookbook covers datacenter GPUs, Intel Arc, and Xeon, but has no guidance for 16 GB consumer cards, where the default KV pool is the main limit. This was discussed in #46804, where measuring and adding a 3.2 config-tip bullet was suggested as the low-friction route.

## Modifications

Adds one bullet to section 3.2 (Configuration Tips) of `docs/cookbook/autoregressive/Qwen/Qwen3.mdx`:
- On a 16 GB card, `Qwen/Qwen3-8B-FP8` with default flags gets a ~16K-token KV pool, compared with a 40,960-token default context.
- `--kv-cache-dtype fp8_e4m3` doubles the pool. The bullet gives the measured TTFT/TPOT trade-off and the GSM8K comparison, so readers can judge the accuracy cost.
- The scheduler reserves KV based on `max_tokens`, clipped at `SGLANG_CLIP_MAX_NEW_TOKENS_ESTIMATION` (default 4096). It covers the client cap and the server-side env var.
- It links the open pip-install issues on recent toolchains.

The command generator (`qwen3-deployment.jsx`) is unchanged. The FP8 KV flag is lossy, so it lives only in the tip and not in a generated cell. The command in the bullet uses `sglang serve`.

## Accuracy Tests

GSM8K with sgl-eval 0.1.3, using Qwen3's recommended non-thinking settings (sgl-eval has no Qwen3 preset):
`sgl-eval run gsm8k --base-url http://127.0.0.1:30000/v1 --num-examples 200 --n-repeats 3 --chat-template-kwarg enable_thinking=false --temperature 0.7 --top-p 0.8 --max-tokens 4096 --seed 0`

| config | pass@1 (3 repeats) | std | majority@3 |
|-|-|-|-|
| default (BF16 KV) | 0.955 | 0.015 | 0.963 |
| `--kv-cache-dtype fp8_e4m3` | 0.938 | 0.008 | 0.950 |

## Speed Tests and Profiling

Environment: RTX 4070 Ti SUPER (SM89, 16 GB), driver 610.88, WSL2, glibc 2.43, sglang `0.5.6.post3.dev13281+gdea05ca16` (main), torch 2.14.1+cu130, FlashInfer 0.7.2, Triton 3.8.0. All runs were cache-cold.

bench_serving uses the page's 5.1.1 commands plus `--flush-cache` (`--dataset-name random --random-input-len 1000 --random-output-len 1000`):

| config | c | median TTFT | P99 TTFT | median TPOT | output tok/s |
|-|-|-|-|-|-|
| default (BF16 KV) | 1 | 36 ms | 105 ms | 17.6 ms | 56.5 |
| `--kv-cache-dtype fp8_e4m3` | 1 | 36 ms | 106 ms | 17.6 ms | 56.5 |
| default (BF16 KV) | 16 | 1159 ms | 7448 ms | 26.4 ms | 458 |
| `--kv-cache-dtype fp8_e4m3` | 16 | 126 ms | 652 ms | 28.6 ms | 490 |

The max_tokens/admission sweep (128 concurrent short-answer requests, same output length in every arm) and its script are in https://github.com/sgl-project/sglang/discussions/46804. At the default bf16 pool, raising the client cap from 256 to 4096 cuts peak running requests from 23 to 9, while 8192 matches 4096 because of the clip. `SGLANG_CLIP_MAX_NEW_TOKENS_ESTIMATION=1024` with a client cap of 8192 matches a client cap of 1024.
