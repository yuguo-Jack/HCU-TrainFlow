# [Fix] openai: keep explicit thinking aliases consistent

[Upstream PR](https://github.com/sgl-project/sglang/pull/46115) · state: open · merged: False

## Original PR description

## Motivation

With `reasoning_effort="high"` and `chat_template_kwargs={"thinking": false}`, normalization currently adds `enable_thinking=true`. Templates and reasoning parsers can then disagree about whether thinking is enabled. Supplying only one alias without an effort leaves the other alias unset.

Make either explicit boolean alias override the inferred effort for both consumers. Reject conflicting/non-boolean aliases and preserve unrelated kwargs without mutating the caller's dictionary. This does not add a new top-level vendor thinking field; MiniMax's typed input is being handled separately in #32301.

## Test Plan

The new CPU regression reproduces both inconsistencies on base. The full existing protocol suite passes with the fix, including precedence, validation, input preservation and unchanged defaults. Focused lint/formatting pass; model/server integration remains for CI.
