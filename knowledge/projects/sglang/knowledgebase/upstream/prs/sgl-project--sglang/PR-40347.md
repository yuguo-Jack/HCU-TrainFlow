# [Fix] Move weight version fields from response `metadata` to `sglext`, fixing OpenAI SDK validation

[Upstream PR](https://github.com/sgl-project/sglang/pull/40347) · state: closed · merged: False

## Original PR description

## Motivation

The official `openai` SDK cannot parse `/v1/chat/completions` responses from any SGLang server reporting weight versions the entire completion errors due to a schema error on a successful response.

```
openai.APIResponseValidationError: Data returned by API invalid for expected schema.
metadata.weight_versions
  Input should be a valid string [type=string_type, input_value=[{'version': 'v1', ...}], input_type=list]
```

`build_endpoint_weight_version_metadata` copies `meta_info["weight_versions"]`,  a list of `{version, start, end}` span objects from the per-token weight attribution into the response-level `metadata` of both `/v1/chat/completions` and `/v1/completions`. 

OpenAI types `metadata` as a flat string-to-string map, so strict clients reject the response. Servers with no configured weight version fail the same way via `{"weight_version": null}`.

## Modifications

Report the fields under `sglext`, which already carries `routed_experts` and `cached_tokens_details`, instead of the spec-reserved `metadata`, and omit `metadata` when unset. 

Breaking change: clients reading `response.metadata.weight_version(s)` must switch to `response.sglext.weight_version(s)`. The native `/generate` `meta_info` is unchanged, and strict SDK clients could not read the field at all before.

- Failing before / passing after against the official SDK (`openai` 3.16.2, `pydantic` 2.13.5): a response built through the changed code passes `ChatCompletion.model_validate`; the same payload in the old shape raises the `metadata.weight_versions` error above.
- Span data path exercised end to end (scheduler events → spans → `meta_info` → response): `sglext.weight_version` and both spans present and contiguous, `metadata` absent; servers without a configured version emit neither block.
