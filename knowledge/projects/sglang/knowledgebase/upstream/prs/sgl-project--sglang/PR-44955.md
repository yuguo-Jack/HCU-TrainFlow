# [Feat] diffusion: support dynamic multi-LoRA in ComfyUI

[Upstream PR](https://github.com/sgl-project/sglang/pull/44955) · state: open · merged: False

## Original PR description

## Motivation

ComfyUI workflows often chain multiple LoRAs or use different combinations at different samplers. SGLD currently rejects multiple dynamic adapters on the same target, and its ComfyUI LoRA loader does not expose the merge mode. This adds multi-adapter dynamic execution and a mode selector on the existing loader.

## Modifications

- Add `merge_mode=dynamic|merge` to `SGLDiffusion LoRA Loader`, defaulting to `dynamic`, including older workflows that omit the field. All loaders chained on one MODEL must use the same mode; separate MODEL branches can choose independently.
- Forward the selected mode through the existing sampler-time binding, so switching modes on the same adapters reconfigures the shared worker.
- Accumulate every dynamic adapter's delta and output offset with its own rank, alpha, and strength, preserving the existing single-adapter computation path.
- Clear old adapters on the first matching adapter for each layer, and finalize cached merges even when the last adapter does not cover that layer. Update all adapter strengths during dynamic reactivation.
- Document the compute and BF16 rounding tradeoffs; retain compact regression coverage.

## Accuracy Tests

After rebasing onto main (`e5dc10e73b`), **131 tests passed** on H200 (CPU and CUDA); pre-commit passed on all changed files. Coverage includes:

- Existing single-adapter numerical regressions.
- Multiple dynamic adapters with different ranks, alpha values, strengths, and output offsets, for ordinary and stacked matrices in exact/lossless modes.
- `A -> A+B -> B -> no LoRA`, mode changes, partial layer coverage, and strength reactivation.

Full H3 workflow output-quality validation is still pending.

## Speed Tests and Profiling

Not benchmarked end to end. Dynamic mode adds per-adapter forward computation; merge mode trades adapter binding work and weight rounding for less per-step computation. Full H3 workflow timing and multi-GPU validation remain pending, so this PR is a draft.
