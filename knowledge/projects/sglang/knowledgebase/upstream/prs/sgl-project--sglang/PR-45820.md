# [CI] [AMD] dsa: Run the DSA dense-MHA fallback cases on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/45820) · state: open · merged: False

## Original PR description

## Motivation

On MI355X, short prefills of DSA models such as DeepSeek-V3.2 take a separate dense-attention path, and no AMD CI test covers it, so a change can break it unnoticed. This PR runs, on an MI35x runner, the same correctness cases that already protect this path on NVIDIA GPUs.

In detail: on gfx95x, the _IS_GFX95 clause of the use_mha gate in set_dsa_prefill_impl sends short-context DSA prefills to the dense-MHA path (aiter's flash_attn_varlen_func) instead of sparse MLA. The CUDA suite (test/registered/attention/unittests/dsa/test_dsa.py) runs the same dense-fallback cases on SM90 and SM100 only. It was split out of #39409, whose fixes it does not test.

## Modifications

- New `test/registered/amd/test_dsa_dense_mha_gfx950.py`: runs the shared dense-fallback cases (`make_dsa_dense_fallback_cases`, head dim 128 as in the CUDA suite) on an MI35x runner (`stage-b-test-1-gpu-small-amd-mi35x`).
- It skips unless the GPU is gfx95x and aiter's preshuffle paged-MQA path is available, because the HIP DSA pool accepts the shared cases' paged layout only on that path. The sparse cases are left out: they need kernels with no gfx950 implementation.

## Accuracy Tests

Test-only. On one MI355X (image `rocm/sgl-dev:v0.5.21-rocm724-mi35x-20261015`, SGLang `bba535ebb4`), the file passes: 1 test, 8 subtests.
