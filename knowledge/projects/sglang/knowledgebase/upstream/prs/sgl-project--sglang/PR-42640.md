# [Rust] Retry prefill bootstrap registration until the timeout

[Upstream PR](https://github.com/sgl-project/sglang/pull/42640) · state: closed · merged: False

## Original PR description

## Motivation

In Rust mode (`SGLANG_RUST_SERVER=1`), the PD KV bootstrap registry starts inside a scheduler, so other prefill ranks can finish loading before its listener is up. Their registration gives up after five attempts and only logs an error. That leaves the rank directory incomplete, and every PD request is unroutable while the server otherwise looks healthy.

## Modifications

- In Rust mode, prefill ranks keep retrying registration until `SGLANG_DISAGGREGATION_BOOTSTRAP_TIMEOUT`, and fail startup at the deadline. The Python frontend keeps its five attempts.
- The Rust registry no longer counts a retried registration as a new rank, so it doesn't advertise readiness while a rank is still missing.
- Test: Rust-mode registration waits for a delayed listener and fails at the deadline.

## Tests

- `python -m pytest -q test/registered/unit/disaggregation/test_register_to_bootstrap.py`: 14 passed.
- In `rust/`: `cargo test -p sglang-server` (334 passed), `cargo clippy -p sglang-server --all-targets -- -D warnings` and `cargo fmt --all -- --check` are clean.
- `pre-commit run --from-ref origin/main --to-ref HEAD`: all hooks pass.
- `test/registered/disaggregation/test_disaggregation_rust_server.py` on two A100s, run on a tree with all the related Rust-frontend PRs merged (Llama-3.1-8B-Instruct, nixl transfer; triton attention and pytorch sampling because of the local FlashInfer build; `test_gsm8k` skipped because it needs a dataset download): 5 passed, both with the shared API/bootstrap port and with a distinct `--disaggregation-bootstrap-port`.
- Not reproduced on GPUs: the multi-rank startup race itself, which needs a prefill server with several ranks where the registry starts late.
