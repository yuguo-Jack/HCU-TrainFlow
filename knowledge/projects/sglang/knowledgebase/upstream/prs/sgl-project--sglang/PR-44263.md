# [Test] dsv4: Cover DeepSelect full-topk CUDA graph replay.

## Motivation

https://github.com/sgl-project/sglang/pull/44193.

The existing Hopper CUDA Graph replay test was written for the legacy paged
`select_decode` path. Its fixture and assertions intentionally cover that
path's contract, including sorted page indices and fully reset output padding.

After `FullTopKIndexer` gained the DeepSelect decode dispatch, pinning the
legacy test to `use_deep_select_decode = False` preserved its original
coverage, but left the `FullTopKIndexer -> DeepSelect` integration path without
CUDA Graph capture/replay coverage. This PR closes that gap with a dedicated
test while keeping the legacy contract test unchanged in scope.

## Modifications

- Keep `test_hopper_indexer_backends_replay` on the legacy `select_decode`
  path and clarify its purpose in the test comment.
- Add `test_hopper_deep_select_full_topk_replay` for Hopper, parameterized over
  compression ratios 1 and 2.
- Build production-shaped paged metadata with `page_table`,
  `compressed_page_size`, and a page-aligned score capacity of 32768 entries
  so the DeepSelect row stride satisfies its 128-byte alignment requirement.
- Capture the DeepSelect path in a CUDA Graph, then replay it while changing
  query values, sequence lengths, request rows, and page-table mappings.
- Exercise empty and short sequences, the `topk=512` boundary
  (`511/512/513`), and `width=1025` so both the short-sequence shortcut and the
  real score-based Top-K path are covered.
- Validate DeepSelect's unordered Top-K contract by comparing selected score
  multisets, and verify that unused entries within each active output row are
  reset to `-1` after the output is poisoned before replay.
