# [Perf] [AMD] mori: pack KV pages for heterogeneous TP

[Upstream PR](https://github.com/sgl-project/sglang/pull/47312) · state: open · merged: False

## Original PR description

## Motivation

With prefill TP smaller than decode TP, MoRI submits token-sized GQA head slices. Packing destination-local heads into contiguous pages reduces descriptor construction and submission overhead. This applies the page-packing approach in #44615 to MoRI; #38317 addresses a different DCP layout.

## Modifications

Add opt-in `SGLANG_MORI_KV_PACKING` for proven NHD full/SWA layouts, including a direct SWA reference path. Validate peer geometry, dtype, registration order and page bounds. Keep registered buffers alive until completion and quarantine failed or ambiguous submissions. Packing defaults off; the configurable cap defaults to 64 MiB per initialized sender worker.

## Accuracy Tests

41 CPU/GPU tests and real RDMA single/multi-batch byte/sentinel checks passed. On the rebased source, 450 fixed-prompt greedy sequences matched the direct reference, including 54 sequences of 64 tokens that exercise decode consuming KV. Serving additionally uses the pinned experimental ROCm Muse runtime from #44667 with API compatibility fixes.

One existing deferred-release test encounters an unavailable `StatusCode.FAILED` in the installed MoRI.

## Speed Tests and Profiling

MI355X, Muse P4/D8, C1, ISL1024/OSL1, 50 requests/arm: direct median TTFT 137.8/136.9 ms; packed64 119.7/119.0 ms. Means were 137.9/137.0 versus 123.7/146.8 ms: occasional ~1.5 s forward stalls remain under investigation. Small buffers/transfers can regress. Payload/API-call counts are unchanged; descriptors fall 16×. A separate trace confirms full/SWA packing on all four prefill ranks. Reproduction details and all arm summaries are in the manual harness README.
