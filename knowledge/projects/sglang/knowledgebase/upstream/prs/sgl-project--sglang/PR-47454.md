# [Fix] function_call: Preserve MiniCPM5 boundaries inside CDATA

[Upstream PR](https://github.com/sgl-project/sglang/pull/47454) · state: open · merged: False

## Original PR description

## Motivation

MiniCPM5 supports XML CDATA in tool arguments, but the outer block scan still treats a literal `</function>` inside CDATA as the end of the call. This matters when a tool writes XML or searches for markup.

For example, a `note` string containing `<function name="inner">content</function>` inside `<![CDATA[...]]>` is truncated before the XML parser sees it. A required parameter makes the call disappear; an optional parameter can instead be emitted as an empty argument dictionary. Streaming can emit that incomplete call before the CDATA section closes.

## Modifications

- Scan each function block for its closing boundary while skipping XML CDATA and comments.
- Parse the original, unmodified XML slice so CDATA values are preserved.
- Hold incomplete CDATA sections until a later chunk supplies their terminator.
- Add three regression methods to the existing MiniCPM5 test file using `CustomTestCase`.

Related work: #42577 replaces the non-streaming boundary scan for performance. Its full diff was reviewed; it does not handle CDATA, so this is a different correctness fix, but both touch the same scanning area and may need integration/rebasing. #41962 addresses end-of-stream flushing and is not included here.
