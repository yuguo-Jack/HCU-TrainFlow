## Motivation

DeepSeek-V4 decoder-tail graphs need the current live token prefix on every replay. A row graph previously owned only the LOCAL count, so a distinct GLOBAL MoE count could not safely follow changing replay sizes. This prevented capture of supported attention-TP-sharded tails; borrowing the parent counter would instead leave captured kernels reading another batch's state.

This change gives each opted-in graph its own LOCAL and GLOBAL count views. Replay updates both while preserving the parent batch's counters and the existing default row-runner behavior.

## Changes

- Pass the gathered tail's live row count from `DecoderReplayTail.run` to `RowBucketGraphRunner`.
- Derive the LOCAL count for the captured TP bucket and keep the GLOBAL prefix in its own graph-owned view.
- Pack both int32 counts into one int64 allocation and update them with one fill, preserving the single-allocation/single-update structure.
- Separate graph cache entries by count domains and attention-TP sharding. Custom MoE bounds without a supported owner continue to decline capture.
