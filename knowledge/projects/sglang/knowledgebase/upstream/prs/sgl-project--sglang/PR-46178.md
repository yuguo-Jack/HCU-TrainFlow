# [Perf] mem_cache: Replace O(N) list.pop(0) with deque in StagingAllocator, FlexKVComm, and LMCacheUnifiedRadixCache

[Upstream PR](https://github.com/sgl-project/sglang/pull/46178) · state: open · merged: False

## Original PR description

## Motivation

Three FIFO queues on SGLang's disaggregation and hierarchical KV storage hot paths currently use a Python `list` with `pop(0)`, incurring $O(N)$ pointer shifts on every drain:

1. **`StagingAllocator.alloc_order` (`python/sglang/srt/disaggregation/common/staging_buffer.py`)**:
   - `StagingAllocator.assign()` appends `alloc_id` to `self.alloc_order` and `StagingAllocator.free()` drains consecutive freed entries from the head via `self.alloc_order.pop(0)` while holding `self.lock`. Under out-of-order RDMA completions across many concurrent requests, draining the head when the oldest request completes shifts all remaining entries on every `pop(0)`.
2. **`FlexKVComm._async_works` (`python/sglang/srt/mem_cache/storage/flexkv/flexkv_comm.py`)**:
   - `FlexKVComm._reap_completed_async_works()` drains up to `_REAP_MAX_DRAIN = 512` completed `dist.isend` work handles from `self._async_works` using `self._async_works.pop(0)` when the backlog exceeds `self._reap_high` (which adapts between `_REAP_HIGH_BASE = 1024` and `_REAP_HIGH_MAX = 32768`). At 32,768 queued works, each `pop(0)` shifts tens of thousands of pointers.
3. **`LMCacheUnifiedRadixCache._pending_stores` (`python/sglang/srt/mem_cache/storage/lmcache/lmcache_unified_radix_cache.py`)**:
   - `check_hicache_events()` drains `ready_stores` completed store operations from the head of `self._pending_stores` at every scheduler safe point via `self._pending_stores.pop(0)`.

## Modifications

- Replace `self.alloc_order: List[int]` with `Deque[int] = deque()` and `popleft()` in `StagingAllocator`.
- Replace `self._async_works: List` with `Deque = deque()` and `popleft()` in `FlexKVComm`.
- Replace `self._pending_stores: list[LMCachePendingStore]` with `deque[LMCachePendingStore] = deque()` and `popleft()` in `LMCacheUnifiedRadixCache` (iterating `self._pending_stores` directly works identically with `deque`).
- Add a unit test (`test_check_hicache_events_drains_pending_stores_fifo_with_deque`) in `test/registered/unit/mem_cache/test_lmcache_component_cursors.py`.

## Benchmark

- `FlexKVComm._async_works` full backlog drain ($N = 32,768$, draining 512 per call): **168.63 ms $\rightarrow$ 3.31 ms (50.9× speedup)**
- `StagingAllocator.alloc_order` watermark advancement ($N = 10,000$ in-flight chunks): **13.46 ms $\rightarrow$ 1.56 ms (8.6× speedup)**
