# [Fix] minicpmv: Preserve chaining on delegated methods

[Upstream PR](https://github.com/sgl-project/sglang/pull/41391) · state: open · merged: False

## Original PR description

## Motivation

`MiniCPMV` delegates every undefined attribute to the inner `self.minicpmv` module, so `model.eval()`/`train()`/`to()`/`cuda()` returned the inner module instead of the wrapper — breaking method chaining. Concretely, `loader.py` has ~16 sites returning `model.eval()`; for MiniCPM-V 2.6/4.0/4.5 the returned object is the inner `MiniCPMBaseModel`, which lacks the `load_weights` defined on the wrapper — so the RL weight-update path (`weight_updater.py` → `get_model().load_weights(...)`) receives a module without that method.

Continues the work from cjhgo's #7281, rebased and extended onto current master.

## Modifications

- `__getattr__("minicpmv")` now raises `AttributeError` instead of returning `None` — the old code made `hasattr(obj, "minicpmv")` wrongly return `True` before `__init__` assigned it (and returning `None` would mask infinite recursion if the guard were ever reordered).
- Delegated callables get wrapped: if the call result `is self.minicpmv`, it is rewritten to `self`. The guard `not isinstance(attr, nn.Module)` keeps submodule attributes like `model.llm`/`model.vpm` passing through as real modules — nn.Module is callable, so without the guard they would be wrapped into closures. `functools.wraps` keeps `__name__` and `inspect.signature` intact on wrapped methods.
- The one-off `eval()` override in `MiniCPMV4_5` is removed — it was a semantic no-op (`nn.Module.eval()` already returns `self`), and the general wrapper now covers chaining for all versions including `MiniCPMV4_6ForConditionalGeneration`.

## Testing

Extracted the real `__getattr__`/`__call__` source from the modified file via `ast` (the module can't be imported without the full sglang runtime) and grafted it onto a stub wrapping a real `torch.nn.Module`, 27 checks covering: `eval()`/`train()`/`to()`/ `float()`/`half()`/`cuda()` all return the wrapper and mutate the inner module; `train(mode)` propagates the flag; `eval().train().eval()` chains; `load_state_dict` returns `_IncompatibleKeys` untouched; submodule attributes (`model.llm`) stay real modules with working `.weight`; non-callable attributes pass through by identity; `hasattr(w, "minicpmv")` is False before init and True after; `__call__` forwards to the inner module.

Known pre-existing quirks (unchanged by this PR): `setattr` on the wrapper writes to the wrapper's `__dict__` rather than delegating to the inner module, and Python <3.11 pickle edge cases — both behave identically on master.
