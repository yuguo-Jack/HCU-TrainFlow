# [Fix] gateway: Drop unused npyz dev-dependency to unbreak builds after zip yank

[Upstream PR](https://github.com/sgl-project/sglang/pull/44720) · state: closed · merged: True

## Original PR description

## Motivation

On 2026-10-16 the `zip` maintainer yanked every release except 9.0.3 after security advisories GHSA-vv5m-jxxh-4627, GHSA-4v9h-p7m9-rh26, and GHSA-4684-h2q9-2vcp; old lines such as 0.6.x will not get backports (zip-rs/zip2#1075). `sgl-model-gateway` declares `npyz` with the `npz` feature as a dev-dependency, which requires `zip ^0.6` (still the case in the latest npyz, 0.9.1). The gateway does not commit a `Cargo.lock`, so every fresh resolve — docker image builds, fresh checkouts — now fails:

```
error: failed to select a version for the requirement `zip = "^0.6"`
required by package `npyz v0.8.0`
    ... which satisfies dependency `npyz = "^0.8"` of package `sgl-model-gateway v0.3.2`
```

Example: the release-docker build in https://github.com/sgl-project/sglang/actions/runs/38871712398 fails at the `maturin build` step with this error.

## Modifications

- Remove the `npyz` dev-dependency. No gateway code references `npyz`, and with it gone `zip` is no longer in the dependency graph.
- Remove `scripts/generate_vision_golden.py`, the CI step in `pr-test-rust.yml` that installs torch/transformers to run it, and the `.gitignore` entry for its output. No gateway test reads the `.npz` fixtures it produced.

## Verification

On clean `git archive` trees of `sgl-model-gateway`:

| | `cargo metadata --format-version 1 -q` |
|---|---|
| `upstream/main` | exit 101 (`failed to select a version for the requirement zip = "^0.6"`) |
| this PR | exit 0 |

On this PR, `cargo fetch` succeeds, `cargo metadata` from `bindings/python` (the maturin entry point) and `bindings/golang` exits 0, and `cargo tree -e normal,build,dev -i zip` finds no `zip` package.
