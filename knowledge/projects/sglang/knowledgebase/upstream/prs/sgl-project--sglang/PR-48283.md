# [Refactor] scheduler: Retire every queued abort through one RequestRetirer entry

[Upstream PR](https://github.com/sgl-project/sglang/pull/48283) · state: closed · merged: True

## Original PR description

Requests aborted while queued, or refused at the waiting-queue door, used to be cleaned up by six hand-written sequences that each picked a different subset of the steps, in a different order. They now all go through one entry, `RequestRetirer.abort_queued`, which runs one sequence: finish the request, release its cache-side state, retire its beam group, send one abort, then release the memory it holds (KV backup, HiSparse rows, KV and mamba state).

- Add `RequestRetirer` (`scheduler_components/request_retirer.py`), built by `Scheduler.init_request_retirer`; `Scheduler.release_aborted_request` delegates to it while callers outside this PR still use it.
- Callers: `_abort_waiting`, the queue-limit eviction and refusal and the priority reject (through `_retire_unavailable`), the dLLM waiting abort, the uOCR document-window abort, and the PD decode held and retracted aborts.
- `discard_kv_cache_backup` reads the backup kind from the backup itself (a host-pool backup carries host indices), so callers no longer pass the configured backend.
- Kept per site: `checkpoint=True` only for the PD decode waiting abort; the PD prefill waiting abort keeps its sender-first memory release at the caller.
- Add a test that lists every function outside the retirer calling `release_kv_cache` or `release_aborted_request` directly; later PRs move those exits (finishes in output processing, PD exits, retract / pause / chunked abort) and the list only shrinks.

Behavior changes, each with a unit test that fails on main:
- An evicted waiting request releases the KV / mamba / HiSparse state it holds (its mamba slot leaked).
- A request refused at the waiting-queue door (queue full, invalid priority) is finished with its 503 reason and its beam group is retired, so the group no longer counts as live.
- When the evicted request shares the incoming rid, the incoming one is retired like any other refusal, including its own abort send.
- The PD decode retracted abort sets a finish reason and releases its cache-side state, like the other queued aborts.
- The uOCR document-window abort goes through `send_abort_output` and sets a finish reason, so it reaches the tokenizer in every server mode and releases the detokenize state.

## Test plan
- A call trace of the cleanup steps over 95 exit configurations differs from main only in the changes above (and a hoisted config read).
- The unit tests of the changed sites pass locally.
