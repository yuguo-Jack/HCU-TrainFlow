# [Feat] hicache: Add opt-in tail-only SWA backups in buffer mode

[Upstream PR](https://github.com/sgl-project/sglang/pull/44173) · state: closed · merged: True

## Original PR description

Builds on #43932 (now merged); rebased onto main so this PR carries only its own commit.

## Motivation

In `--hicache-host-memory-mode buffer_only`, a sliding-window component's backup writes every SWA page of a radix node to storage, while a prefetch that ends at that node only ever restores the trailing window. For long nodes that is many pages written per node that no reader can use.

## Changes

`SGLANG_ENABLE_HICACHE_SWA_TAIL_ONLY_BACKUP=1` (default off) limits each node's SWA backup to the window ending at that node.

- `BufferModePipeline` reads the flag once at construction. Admission keys (`_backup_pool_keys`), the staged D2H rows and the per-pool storage-existence beliefs all cover the same trailing pages: `_trim_swa_backup_transfer` cuts a backup transfer's device rows and keys to the pool's `full_window_pages` and marks it `TRAILING_PAGES`. Nodes shorter than the window keep every page they have, each window component (`SWA`, `AUXILIARY_SWA`) uses its own window size, and derived sidecars follow their source transfer.
- A trimmed SWA write advances the backend's prefix context past the omitted node pages through a new `HiCacheController.extend_storage_prefix` hook (the base implementation appends the omitted hashes to the prefix list), so a backend that derives placement from the prefix chain writes the window where a reader of the complete chain looks for it. Storage keys and the read protocol do not change.
- A hit whose window is not fully stored falls back to the last node end whose window is stored, which the existing `TRAILING_PAGES` query already yields; a later split at an interior page makes that point restorable once the parent is backed up again.

## Test plan

Run locally on this branch:

- CPU: `test/registered/unit/mem_cache/test_buffer_swa_tail_only.py` (new) and `test_buffer_mode_sidecar.py`: 8 passed, 9 subtests passed. `test_hicache_staged_write_back_dispatch.py`, `test_storage_prefetch_lifecycle.py`, `test_unified_hicache_regressions.py`: 37 passed, 1 skipped.
- GPU (one GPU): `test/registered/unit/mem_cache/test_unified_radix_cache_unittest.py -k "swa_tail_only or buffer"`: 143 passed, 242 skipped. The new `test_buffer_only_swa_tail_only_backups` runs on the 7 SWA fixtures whose chain fits the device pool and checks the file backend's contents, the existence beliefs, the staged row count of every SWA write, the per-prefix hit count, an end-to-end prefetch from the sparse store, and the split-then-re-backup case.
- `isort`, `ruff check --select=F401,F821,F823,UP037`, `ruff format --check` and `codespell` at the pre-commit pins are clean on the changed files.

Not run: a live multi-process storage backend; the behaviour was validated with the file backend only.
