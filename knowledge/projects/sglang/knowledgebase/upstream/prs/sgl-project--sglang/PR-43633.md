# [diffusion] fix: replay Qwen-Image-2.1 BCG graphs across prompt lengths

[Upstream PR](https://github.com/sgl-project/sglang/pull/43633) · state: closed · merged: True

## Original PR description

## Motivation

Qwen-Image-2.1 with `--enable-breakable-cuda-graph` never replays a captured graph for a prompt whose length differs from the warmup placeholder. On GB300 (main 3831e7e09) the warmup captures 33 segments with 72 inputs, yet every real request logs `serving signature MISSED` and runs eager, on 1 GPU and under TP2 alike.

`QwenImage21DenoisingStage` disables prompt padding on purpose. Prefill (step 0) is eager anyway. After it, a DiT step reads nothing of the prompt except each layer's prefix K/V and the target RoPE, and the K/V are at the exact prompt length. 72 = 4 step inputs + 4 layout tensors + 32 layers x K/V.

## Modifications

- `model_padders/qwen_image21.py` acts only on cached steps (single sample, caches filled, sp == 1). It left-pads the prefix K/V to the text bucket and stacks all layers into one tensor, so a replay copies one input instead of 64. It also drops the prefill-only inputs and adds a 0-d `prefix_pad`. A prefix longer than the largest bucket is left alone; the runner reports the miss once.
- The DiT's target attention runs at a model-level `eager_on_graph` break point (`attend_past_prefix_pad`). It reads the live pad once per forward and slices `k[:, pad:]`. Because the pad is on the left, the valid K/V form one strided view, so the kernel receives exactly the eager K/V.
- The stage-level override that disabled padding is removed.

## Accuracy Tests

BCG against eager, four prompt lengths (including ~350 tokens in the 512 bucket): bit-identical (max_abs = 0), on 1x H200, on 2x H200 TP2 and on 2x GB300 TP2. Before this PR the comparison was trivially identical, because every request ran eager.

## Speed Tests and Profiling

Qwen-Image-2.1 1024x1024, served. Median of 5 per round, three interleaved rounds; the arms differ only in `--enable-breakable-cuda-graph`.

| | eager | BCG, this PR |
|---|---|---|
| 1x H200 | 4.521 / 4.525 / 4.518 s | 4.546 / 4.540 / 4.544 s (+0.5%) |
| 2x H200, TP2 | 2.788 / 2.790 / 2.792 s | **2.737 / 2.731 / 2.740 s (−1.9%)** |

On one H200 the step is GPU-bound (103 ms), so replay saves no launch time. What remains is BCG's own cost: each attention break copies its output into the bridge buffer, plus 33 graph launches. Under TP2 each rank's GPU work halves, the launch cost shows, and BCG wins.
