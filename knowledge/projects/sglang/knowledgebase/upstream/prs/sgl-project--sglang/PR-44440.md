# [Fix] utils: Allowlist torch.bcomplex32 in SafeUnpickler

[Upstream PR](https://github.com/sgl-project/sglang/pull/44440) · state: closed · merged: True

## Original PR description

## Motivation

torch 2.14 adds the `torch.bcomplex32` dtype. A pickled tensor carries its dtype as a GLOBAL opcode, so with the pinned torch 2.14.1 `safe_pickle_loads` refuses any payload that holds a bcomplex32 tensor:

```
RuntimeError: Blocked unsafe global (torch.bcomplex32) during pickle deserialization
```

Every other dtype the installed torch exposes is already in `SafeUnpickler.ALLOWED_GLOBALS`; this one was missed when the pin moved.

## Modifications

- Add `("torch", "bcomplex32")` to `SafeUnpickler.ALLOWED_GLOBALS` in `python/sglang/srt/utils/common.py`.
- Add `test_allowlist_covers_torch_dtypes_and_tensor_classes` to `test/registered/unit/utils/test_safe_unpickler.py`. It diffs the allowlist against the dtypes, storage classes and tensor classes the installed torch exposes, so the next dtype torch introduces fails a CPU unit test instead of refusing a payload at runtime.
