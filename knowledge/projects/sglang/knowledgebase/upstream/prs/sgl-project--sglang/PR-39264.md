# [Perf] weight-sync: Allocate packed receive buffers from metadata

[Upstream PR](https://github.com/sgl-project/sglang/pull/39264) · state: closed · merged: True

## Original PR description

## Motivation

@humansand

Packed distributed weight updates allocate every destination tensor and concatenate their uninitialized bytes immediately before the broadcast overwrites that buffer. Allocate the receive buffer directly from metadata to remove the discarded concatenation and temporary tensor allocations.

- **Roadmap:** [Miles #3734 — NVFP4 weight update enhancements](https://github.com/radixark/miles/issues/3734) tracks the broader weight-sync work.
- **Merged counterpart:** [SGLang #39265](https://github.com/sgl-project/sglang/pull/39265) merged the corresponding receiver-allocation optimization into `sglang-miles`. This PR brings it to `main`.

## Modifications

- **Allocation:** add `FlattenedTensorBucket.empty(names, dtypes, shapes, device)` to allocate one contiguous uint8 receive buffer. Preserve sender byte offsets, dtype, shape, and shared-storage reconstruction.
- **Activation:** use the factory only for distributed updates requesting `load_format="flattened_bucket"`. Ordinary per-tensor updates and tensor IPC are unchanged. This optimization is not specific to NVFP4.
- **Validation:** reject inconsistent metadata lengths, negative dimensions, empty metadata, and offsets incompatible with dtype alignment. Keep the existing wire format without padding or dtype promotion.
- **Lifecycle:** preserve the single broadcast, target-runner receive, selected-runner loading, and separate begin/restore and end/postprocess operations. No loader, quantization, or collective-group changes.
- **Scope:** two commits and three changed files, directly based on upstream `main` at `86cc2e02ecb207853377e2c034337e9e0442ce60`. Validated head: `8e987e1256ada5575245fa47a75cecce340c1a9f`. Both feature and CI-entry-point patches are unchanged by rebase. Full-model weight-sync benefit remains unmeasured.

## Speed Tests and Profiling

Previously measured on one B300 in the same image:2 warmups and10 alternating trials per variant. Both variants include an identical local device overwrite and typed-view reconstruction. Completed wall time includes device synchronization. Peak allocation is live PyTorch tensor allocation above the preallocated payload, not RSS or reserved memory.

| Tensors | Payload bytes | Original median wall ms | Metadata-only median wall ms | Original peak allocation bytes | Metadata-only peak allocation bytes |
|---:|---:|---:|---:|---:|---:|
| 10 | 21245964 | 0.144953 | 0.095179 | 42493952 | 21246464 |
| 37 | 84946992 | 0.408382 | 0.221236 | 170936320 | 85983232 |
| 145 | 339751104 | 1.403790 | 0.634502 | 679526912 | 339751424 |

Original construction has one `aten::cat`; the metadata-only path has none. Local completed-wall reduction is0.050–0.769ms per bucket and temporary allocation is approximately halved. This earlier construction benchmark used an equivalent metadata-only function; the subsequent real NCCL test used the actual production factory. Neither measures full-model loading/finalization or end-to-end synchronization benefit. Unflatten host work and per-name model loading remain unchanged. The larger NVFP4-vs-MXFP8 sync gap is not attributed to this small result.
