# [Fix] bench: Size the one-batch KV-capacity skip by the heaviest attention-DP rank for ragged batches

[Upstream PR](https://github.com/sgl-project/sglang/pull/47130) · state: closed · merged: True

## Original PR description

## Motivation

`bench_one_batch_server` skips a `(batch_size, input_len, output_len)` point when its resident tokens would not fit the server's KV pool, so a sweep does not spend a timeout on a batch the scheduler can never admit at once. With `--input-len-list` (per-request ragged input lengths) that check sums the per-request lengths, which is the right total for a single attention group.

With attention data parallelism the total is not enough. The DP controller round-robins requests over the DP ranks, so request `i` lands on rank `i % num_dp_ranks`, and a ragged list that cycles with the rank count puts every long request on the same rank. The batch can fit the pool in aggregate while that rank's share overflows, and the surplus requests queue behind the batch instead of running with it: the point is then measured as a smaller batch plus a second wave, which is not the shape the sweep asked for.

## Modifications

- `should_skip_due_to_token_capacity` takes `num_dp_ranks` (default 1). For a ragged batch on more than one rank it also computes the heaviest rank's resident tokens under round-robin placement and skips when that rank's share, scaled to the whole pool, exceeds the threshold. Uniform batches and single-rank servers are unchanged.
- `run_benchmark_internal` passes the server's `num_dp_ranks` (already read from `/server_info`) to the check; the vLLM path sets it to 1.
- `test/registered/unit/bench/test_one_batch_ragged_capacity.py` (CPU, `base-a-test-cpu`) pins the uniform total, the ragged total, the heaviest-rank bound with a two-rank round-robin example, and that uniform batches ignore `num_dp_ranks`.
