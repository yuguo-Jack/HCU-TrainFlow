# [Feat] srt: Balance uvicorn tokenizer workers with per-worker SO_REUSEPORT listeners

[Upstream PR](https://github.com/sgl-project/sglang/pull/45482) · state: closed · merged: True

## Original PR description

## Motivation

With `--tokenizer-worker-num N` the HTTP server runs N uvicorn workers that all accept from one shared listening socket. Linux does not round-robin a shared accept queue: whichever workers wake first take the connections, so a burst can land mostly on one worker. A long-lived connection (a streaming response, a WebSocket session) then stays on that worker for its whole life, so the imbalance persists and the busy worker's event loop adds latency to every request it holds.

## Modifications

- `python/sglang/srt/arg_groups/fields/serving.py`: new opt-in `--enable-http-worker-reuseport` (default off). With it set, every uvicorn worker owns a private `SO_REUSEPORT` listener on the configured host and port, so the kernel spreads new connections across the reuseport group instead of one shared accept queue. Default off keeps uvicorn's standard shared listener; nothing changes for existing deployments.
- `python/sglang/srt/entrypoints/http_server.py`: `_ReusePortMultiprocess`, a subclass of uvicorn's `Multiprocess` supervisor. uvicorn reads `self.sockets` once for every worker it spawns (at start, after a health-check failure, on `SIGHUP` restart, on `SIGTTIN`), so the subclass hands out a fresh private listener on each read and closes the parent's copy once the child holds it; the lifecycle itself (health checks, ready-wait on restart, start-up-failure handling) stays uvicorn's own. A spawn that fails part-way at start-up terminates the workers already started. Start-up still fails fast on a port that is already in use: before the first reuseport bind the supervisor probes the address once without `SO_REUSEPORT`, under a per-port lock (an abstract Unix socket name), so two servers started at the same time on one fixed `host:port` cannot both come up; `--port 0` keeps picking an ephemeral port. An unresolvable host exits with the error logged, as the plain uvicorn path does. The non-reuseport branch is the existing `uvicorn.run` call with the same options.
- `python/sglang/srt/arg_groups/serving_hook.py`: the flag is rejected with a single tokenizer worker (nothing to balance) and with `--enable-http2`, whose server does not run under the uvicorn supervisor.
- `python/sglang/srt/arg_groups/field_order.py`: the new field is appended to `POSITIONAL_FIELD_ORDER` so `test_builtin_fields_have_explicit_positional_slots` stays green.
- `python/pyproject.toml`: `uvicorn>=0.51`, the release in which `Process` and `Multiprocess` dropped their `target` argument and `Process` started building its own `Server`; the subclass relies on that shape.
- `docs/docs/advanced_features/server_arguments.mdx`: the row for the new flag that `test_server_args_docs_coverage.py` requires.
- `test/registered/unit/entrypoints/test_http_server_reuseport.py` (new, `base-a-test-cpu`): each worker gets its own `SO_REUSEPORT` listener and the parent's copy is closed after the hand-off, the address is resolved once, a replaced, restarted or `SIGTTIN`-added worker gets a fresh listener and the old one is closed; a spawn that fails part-way terminates and joins the workers already started; an unresolvable host exits cleanly with the error logged; two supervisors racing for the same fixed `host:port` admit exactly one, two with `--port 0` both start, and two on different addresses both start; a real uvicorn worker process serves a request on the listener it was handed.
- `test/registered/unit/server_args/test_server_args.py`, `test/registered/unit/test_server_args_cli_metadata.py`: the flag is rejected with one worker and with HTTP/2, accepted with several workers, and is off unless given on the command line.

`SO_REUSEPORT` load balancing and the abstract socket namespace used for the lock are Linux semantics, which is why the behaviour is opt-in.

## Speed Tests and Profiling

With the flag unset the only addition is one boolean check before `uvicorn.run`. With the flag set, each worker accepts from its own `SO_REUSEPORT` listener, so new connections are distributed by the kernel across the reuseport group rather than taken from one shared accept queue by whichever worker wakes first. No benchmark numbers are included here; the effect on connection placement and latency depends on the workload and is best measured with a synthetic burst of long-lived streaming connections against several tokenizer workers.

On this head, with uvicorn 0.54.0 (what CI installs): `pytest test/registered/unit/entrypoints/test_http_server_reuseport.py` passes (7 tests), also when the file is run directly as `run_suite.py` does; `test_server_args_docs_coverage.py` passes; `test/registered/unit/server_args/test_server_args.py` and `test/registered/unit/test_server_args_cli_metadata.py` pass apart from `TestDcpCommBackendDefault::test_a5_npu_supports_dcp`, which fails identically on `main` on the same host. `pre-commit run` on the nine files passes.
