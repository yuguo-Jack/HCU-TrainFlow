# fix(rotary_embedding): support partial rotary embeddings in forward_xpu fallback

[Upstream PR](https://github.com/sgl-project/sglang/pull/41088) · state: closed · merged: False

## Original PR description

## Summary

`RotaryEmbedding.forward_xpu()`'s fallback-kernel branch (used when `head_size` is not in `[128, 256, 512]`) calls `torch.ops.sgl_kernel.rotary_embedding(positions, query, key, self.head_size, self.cos_sin_cache, self.is_neox_style)` without slicing to `rotary_dim` first. That compiled kernel asserts `rotary_dim == head_size` internally and raises:

```
RuntimeError: Rotary dim doesn't match query head_size
```

for any model with partial rotary embeddings (`rotary_dim < head_size`). This affects GPT-NeoX-style architectures with `partial_rotary_factor < 1.0` on XPU (e.g. `adept/persimmon-8b-chat`, `microsoft/phi-2`, `stabilityai/stablelm-2-1_6b`, `stabilityai/stablelm-3b-4e1t`, `stabilityai/stablelm-zephyr-3b`), independent of the `--attention-backend` choice (`triton` or `intel_xpu`), since rotary embedding dispatch is keyed on device type (`is_xpu()`), not attention backend.

The fix adds an `elif self.head_size != self.rotary_dim` branch that falls back to `forward_native()`, which already implements generic partial-rotary math correctly (splitting `query[..., :self.rotary_dim]` / `query[..., self.rotary_dim:]`). This mirrors the existing pattern where `forward_cpu`/`forward_npu` already fall back to `forward_native` for their own unsupported cases, and the aligned-head_size branch of `forward_xpu` itself already slices to `rotary_dim` before its fused call.

## Test plan

Hardware-validated on Intel XPU with the patched build, running a 20-example accuracy smoke check per model (server + client, real GPU):
- `adept/persimmon-8b-chat` (intel_xpu backend, gsm8k) — passed, no crash
- `microsoft/phi-2` (triton backend, gsm8k) — passed, no crash
- `stabilityai/stablelm-3b-4e1t` (triton backend, hellaswag) — passed, no crash
- `stabilityai/stablelm-zephyr-3b` (triton backend, gsm8k) — passed, no crash

All four previously failed with `RuntimeError: Rotary dim doesn't match query head_size` on this code path; all four now serve and produce results after the fix. `stabilityai/stablelm-2-1_6b` hits the same root cause and is also fixed by this change.
