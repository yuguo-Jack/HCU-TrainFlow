# [Refactor] [AMD] docker: Slim ROCm images with multistage builds

[Upstream PR](https://github.com/sgl-project/sglang/pull/22037) · state: open · merged: False

## Original PR description

## Summary

Slim `docker/rocm.Dockerfile` while preserving all **10 existing ROCm/GPU selectors** and the default `gfx950`. Release workflows retain their existing `--no-cache` policy; this PR changes only the Dockerfile.

## Size reduction

| ROCm 10 / MI355X | Original | Multistage | Saved |
|---|---:|---:|---:|
| Docker image size | 58.52 GB | 37.63 GB | **20.89 GB (35.7%)** |

Measured at the same SGLang revision (`9691e711cd`), with `gfx950-rocm1000`, `ENABLE_MORI=1`, `BUILD_TYPE=srt`; decimal GB.

| Component | What no longer remains in runtime layers |
|---|---|
| Gateway / Cargo | Gateway build tree and Cargo targets; targets use a BuildKit cache mount. The minimal runtime Rust toolchain is retained. |
| TileLang / FHT | Builder source trees, compilation intermediates and TileLang-only build dependencies; install wheels through read-only mounts. |
| Mooncake / Go | Mooncake build tree, temporary Go toolchain and Go caches, removed before committing the layer. |
| AITER | Object files; editable sources and prebuilt runtime kernels remain. |
| Source / wheel staging | Temporary source copies and wheel archives are mounted rather than retained in image layers. |

**20.89 GB is the measured aggregate net reduction, not a sum of separately measured components.** Per-component GB values were not recorded. Custom Triton builders also discard build artifacts where enabled, but the measured `gfx950-rocm1000` flavor uses SDK Triton and has no custom-Triton-build savings.

## Build flow

Before: most modules build sequentially into the same runtime stage, with SGLang arguments declared early:

```text
Base/SDK → AITER → Mooncake → SGLang → Gateway → TileLang → FHT
         → MORI → NIXL/RCCL → Triton → Runtime
```

After: separate wheel builders feed a dependency chain ordered by update frequency:

```text
Base/SDK → Stable dependencies → MORI → AITER → SGLang → Runtime
           ↑ TileLang/FHT/Triton wheels          ↑ DLPack   ↑ Gateway wheel
```

Stable dependencies include Mooncake, NIXL/RCCL and the selected Triton. Independent builders can run in parallel. Arguments are scoped to their consuming stage: **with caching enabled**, changing SGLang preserves MORI/AITER; changing AITER preserves MORI and stable dependencies. Runtime sources, prebuilt kernels and JIT requirements remain available.

## Validation

- All 10 selectors pass BuildKit checks; gfx942/gfx1250 received static validation only.
- MI355X full builds and DeepSeek V4.1 Flash GSM8K pass on ROCm 7.0/7.2.0/7.2.4/10.0: TP4/EP4, 1319 questions, 89% threshold. **The 7.0 result includes the separate fixes in #47719**, excluded from this PR.
- Cache probes, `pip check`, runtime imports and pre-commit checks pass. No recurring GPU test is added.

## Code Review

This pull request refactors the `docker/rocm.Dockerfile` to utilize multi-stage builds for components such as `sgl-model-gateway`, `Mooncake`, `TileLang`, and `Triton`. These changes significantly optimize the final image size by isolating build-time dependencies (like Rust and Go) and source code within discarded builder stages. The PR also consolidates package installations, introduces cleanup steps for object files, and applies specific hot patches for ROCm 7.2. Feedback identifies a redundant installation of `pybind11` and suggests a refinement to the `sccache` removal logic to prevent noisy shell errors when the binary is not present.

- gemini-code-assist[bot] · comment · 2026-04-03T10:34:25Z · [source](https://github.com/sgl-project/sglang/pull/22037#discussion_r3032371475)

File: `docker/rocm.Dockerfile` · line None

![medium](https://www.gstatic.com/codereviewagent/medium-priority.svg)

The command `rm -f "$(which sccache 2>/dev/null)"` will attempt to remove an empty string if `sccache` is not found, which results in a noisy error message on stderr (e.g., `rm: cannot remove '': No such file or directory`). Removing the quotes allows the shell to expand an empty result into no arguments for `rm`, which is a clean no-op in GNU `rm`.

```
    && apt-get purge -y sccache 2>/dev/null || true; python -m pip uninstall -y sccache 2>/dev/null || true; rm -f $(which sccache 2>/dev/null) || true
```
