# fix(mem_cache): restore default on UnifiedRadixCache.dec_lock_ref params

[Upstream PR](https://github.com/sgl-project/sglang/pull/41142) · state: closed · merged: False

## Original PR description

## Summary

`BasePrefixCache.dec_lock_ref` declares `params: Optional[DecLockRefParams] = None`, but `UnifiedRadixCache`'s override (introduced in #36848) dropped the default, requiring `params` positionally.

`schedule_policy.py`'s `_lock_node` calls `self.tree_cache.dec_lock_ref(last_node)` with no `params` whenever the acquire receipt's `to_dec_params()` returns `None`, even though `is_tree_cache()` is `True` for `UnifiedRadixCache`. This crashes with:

```
TypeError: UnifiedRadixCache.dec_lock_ref() missing 1 required positional argument: 'params'
```

Restoring the default on the override matches the abstract interface it implements (and every other concrete `dec_lock_ref` implementation, which all keep `params` optional) and fixes the crash. This is backend-agnostic — reproduced on Intel XPU across 17 accuracy runs, but the code path itself has no device-specific branching.

## Test plan
- Reproduced the crash on `lmsysorg/sglang:v0.5.20-xpu` running `docvqa_val`/`gsm8k` accuracy evals for several models (e.g. `HuggingFaceTB/SmolVLM2-2.2B-Instruct`, `CohereLabs/aya-vision-8b`).
- With this one-line fix overlaid onto the same image, a 20-example `docvqa_val` run against `HuggingFaceTB/SmolVLM2-2.2B-Instruct` completes successfully (exit 0, accuracy 0.4831, no crash).
