# [Perf] lingbot-video-moe: compute timestep modulation once per sample

[Upstream PR](https://github.com/sgl-project/sglang/pull/46872) · state: open · merged: False

## Original PR description

> Depends on #46871. On current main, LingBot-Video-MoE crashes in text encoding before the DiT runs under default flags; the numbers below were taken on main + #46871. This PR's diff does not touch that code, and I will rebase it once #46871 lands on main.

## Motivation

`LingBotVideoTransformer3DModel.forward` expanded the timestep embedding to every joint token before projecting it. `time_modulation` (FP32 `D -> 6D`) and `norm_out_modulation` (`D -> 2D`) ran as `[B*S, D]` GEMMs, and every block then materialized a `[B, S, 6D]` FP32 modulation tensor. The modulation depends only on the timestep, so every row was the same per sample.

## Modifications

- `time_modulation` and `norm_out_modulation` run once on `t_emb` `[B, D]`; their outputs broadcast as `[B, 1, *]`.
- `LingBotVideoBlock.forward` takes `temb6` as `[B, 6D]` (was `[B*S, 6D]`) and builds `mod` as `[B, 1, 6D]`.
- When the quality-gated fused site is enabled (`quality="lossless"/"high"`), the block still expands `mod` to a contiguous `[B, S, 6D]`, because `rmsnorm_scale_shift_per_token` and `residual_gate_add` require per-token operands. The default `exact` path gets the full saving; the gated path still drops the large GEMM.
- No parameter names or shapes change, so checkpoints load as before.
- One test in the existing `test_lingbot_video_moe.py` checks the per-sample block output against the per-token path (B=2, S=5).

## Accuracy Tests

1x H100 80GB, `robbyant/lingbot-video-moe-30b-a3b`, cookbook JSON prompt, `sglang generate --height 480 --width 480 --num-frames 81 --num-inference-steps 40 --seed 0`, default flags.

## Speed Tests and Profiling

Same setup, runs alternated base/PR, 2 runs each. Step 0 includes warmup, so steady-state is the median of steps 1-39 from `--perf-dump-path`.

| | main+#46871 | + this PR | change |
|---|---|---|---|
| denoise step, median ms | 1069.4 / 1070.4 | 1047.6 / 1047.4 | -22.4 ms (-2.1%) |
| peak GPU memory (nvidia-smi), MiB | 64373 / 64371 | 63921 / 63923 | -450 MiB |

Isolated microbench of only the modulation work (B=2, S=19156, 48 blocks, strict FP32): 129.97 ms -> 1.25 ms per forward and 5.26 GiB -> ~0 GiB transient. The e2e gain is much smaller than this, so treat the microbench as an upper bound. Videos and per-run details are in the comment below.
