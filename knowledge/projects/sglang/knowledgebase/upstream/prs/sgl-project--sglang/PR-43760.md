## Motivation

<!-- Describe the purpose and goals of this pull request. -->
Fixes https://github.com/sgl-project/sglang/issues/43557.

An engine launched in decode mode captures its decode CUDA graphs during `ModelRunner.init_cuda_graphs()`, but that path leaves `decode_cuda_graph_captured` false and `decode_cuda_graph_capture_bs` empty. After a decode → prefill → decode round trip, `ensure_decode_cuda_graphs()` therefore captures another runner instead of reusing the startup graphs. The original v0.5.21 source reproduced CUDA illegal memory access on the first returned-decode workload in two independent concurrent runs.

## Modifications

- Record the captured flag and batch sizes when assigning the startup decode graph runner, matching the bookkeeping already performed by `init_decode_cuda_graph()`.
- Reuse startup graphs on later role switches while retaining deferred capture when startup produced no decode graph.
- Add the regression to the existing `test/registered/unit/disaggregation/test_pd_role_switch.py`, covering startup-graph reuse and first capture when no startup graph exists.
