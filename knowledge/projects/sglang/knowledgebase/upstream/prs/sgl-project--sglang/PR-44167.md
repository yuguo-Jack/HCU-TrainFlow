# [Spec] Abort only the request when grammar traversal rejects a draft token

[Upstream PR](https://github.com/sgl-project/sglang/pull/44167) · state: open · merged: False

## Original PR description

## Motivation

`traverse_tree` which is used by DFlash and other specdec paths to build the grammar bitmask over the draft tree  calls `grammar.accept_token()` on every draft token that passed its parent's mask row. If the matcher rejects one anyway, the `ValueError` is not caught and kills the scheduler rather than just aborting a single request.

I'm still looking for reproducible root cause, this PR is for containment to avoid bad state.

## Modifications

- `traverse_tree`: track how many draft tokens are accepted along the DFS path. On `ValueError`, roll those back so the grammar is at its pre-traversal state, then re-raise.
- `generate_token_bitmask`: catch the `ValueError` per request, log it, set that request's mask rows to all-allowed, and set `req.to_finish = FINISH_ABORT()`, as `_accept_grammar_tokens` does.

## Tests

Unit tests in `test_spec_utils_traverse_tree.py`:
- `traverse_tree` leaves the grammar rolled back to its starting state when a deep draft token is rejected.
- `generate_token_bitmask` aborts only the rejecting request; the other request in the batch is untouched and its grammar is restored.

End-to-end, since I can't trigger the real desync on demand: I injected the failure by making `XGrammarGrammar.accept_token` raise `ValueError` when called from `dfs` for requests whose schema contains a marker key. Setup was Qwen3-0.6B, 1x L40S, `--speculative-algorithm NGRAM --grammar-backend xgrammar`, one poisoned `json_schema` request sent concurrently with six normal ones, on the nightly-dev-20261014 image with `python/` overlaid from each tree:

| | poisoned req | other 6 reqs | server |
|---|---|---|---|
| main (44b44774c3) | connection dropped | all dropped | scheduler exception, SIGQUIT, `/health_generate` unreachable |
| this PR | `finish_reason: abort` | all `stop`, valid JSON | alive, `/health_generate` 200, follow-up request OK |

## Accuracy / speed

No change to the non-error path; the added bookkeeping is one integer increment per traversed node.
