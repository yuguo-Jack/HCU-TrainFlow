# [Fix] weight-sync: Add selector to update_weights_from_disk

[Upstream PR](https://github.com/sgl-project/sglang/pull/46852) · state: open · merged: False

## Original PR description

## Motivation

Fixes #46806. `update_weights_from_disk` always reloads every model runner. Under speculative decoding with a separate draft checkpoint (DFLASH in the issue), the target's `model_path` is therefore also loaded into the draft. The DFLASH loader accepts the target's `model.layers.*` and `model.norm.weight` as its own, so the call reports success, but the acceptance length drops to ~1.0. The tensor and distributed requests already have a `selector` field to avoid this, but the disk request has none, so callers such as RL frameworks doing disk-based refits can't keep the draft out.

## Modifications

- `managers/io_struct.py`: add `selector: Optional[Literal["target", "draft", "all"]] = None` to `UpdateWeightFromDiskReqInput`, like the tensor and distributed requests. The HTTP endpoint picks the field up from the struct.
- `scheduler_components/weight_updater.py`: `update_weights_from_disk` uses the selector. Without one, the draft is reloaded only when it was loaded from the target's checkpoint (`speculative_draft_model_path` unset or equal to `model_path`, e.g. a bundled MTP layer), so that behavior is unchanged. A draft with its own checkpoint, such as DFLASH, keeps its weights. The cache is still flushed only when the target was reloaded.
- `entrypoints/engine.py`: `Engine.update_weights_from_disk` accepts `selector`.
- `docs/.../sglang_for_rl.mdx`: add `selector` to the request table and the Engine API signature.

This PR doesn't change the DFLASH loader silently skipping names it doesn't recognize. I asked in the issue whether a warning there is wanted.

## Validation

- `test_scheduler_weight_version_tracking.py`: new tests for explicit `"target"` / `"draft"`, and for the default with a separate draft (skipped) and a bundled or absent draft path (reloaded). 92 passed together with `test_msgpack_ipc_roundtrip.py` and `test_io_struct.py`. With the old always-`"all"` default, the separate-draft test fails.
- `pre-commit run` passes on the changed files.

The issue shows that the target-only path (`selector="target"` on the tensor update) keeps the draft unchanged; for a DFLASH draft, the disk update now takes that path by default.

**Pending GPU validation** (I don't have a GPU; help welcome). With a separate DFLASH draft:
1. Record the draft's weight checksum and `model_path`, call `update_weights_from_disk` without a `selector`, and check that both are unchanged.
2. Compare the acceptance length on the same workload before and after the update.
