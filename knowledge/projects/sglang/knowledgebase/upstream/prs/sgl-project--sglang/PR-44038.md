# [AMD] Keep NVIDIA-only KDA parity mode off ROCm

[Upstream PR](https://github.com/sgl-project/sglang/pull/44038) · state: closed · merged: False

## Original PR description

The AMD test suite was running a special comparison mode that copies an NVIDIA-specific GPU instruction sequence. PyTorch exposes AMD GPUs through the same `torch.cuda` API, so the old device check did not skip those tests on ROCm.

On MI300, the AMD compiler reports `could not allocate output register for constraint 'f'`, and the comparison returns the wrong result.

This change:

- stops `match_cutedsl_decode` with a clear error before it reaches the GPU on ROCm;
- skips only the two NVIDIA instruction-parity tests on ROCm;
- keeps the normal KDA recurrence test running on ROCm;
- adds a ROCm regression test for the clear error.

No production caller currently enables `match_cutedsl_decode`, so this does not change AMD serving behavior.

Related: #43991 addresses a separate KDA Q/K normalization mismatch.
