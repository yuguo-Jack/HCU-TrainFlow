# [Fix] metrics: Refresh idle DP gauges after empty batches

[Upstream PR](https://github.com/sgl-project/sglang/pull/40215) · state: open · merged: False

## Original PR description

## Motivation

A locally idle data-parallel (DP) rank can still execute empty synchronization batches while peers are decoding. That path bypasses the scheduler's normal idle handler, so `sglang:num_running_reqs` can retain an old nonzero value. A monitor that combines a stale running count with no generation progress can then report a stalled Decode rank.

Merged #31517 refreshes stale gauges inside the idle reporter, but the empty-batch result path still needs to call that reporter.

## Modifications

- Refresh idle metrics after processing an empty IDLE result, through the existing metrics-enabled gate and throttling.
- Skip the refresh when the current running or selected batch has requests. This prevents an older IDLE result from overwriting active decode or prefill metrics during overlap scheduling.
- Add seven registered CPU regressions for stale gauges, throttling, disabled metrics, and both overlap guards.
- Update the fixtures for current main's deferred-release queue and host-receive configuration, and use CustomTestCase.

## Production deployment and results

The original empty-batch metrics fix is deployed in our production inference service. A read-only inspection on 2026-10-04 confirmed the refresh call in both Decode workers, each with four DP ranks.

Over a 24-hour window, all eight running-request series were present at all 5,761 evaluation points. We observed 81 sampled transitions from a positive running count to zero while another rank in the same worker remained active. One example changed from `[0, 1, 1, 0]` to `[0, 0, 1, 0]`. This confirms the intended idle-gauge behavior under partial DP activity.

These are sampled metric transitions, not unique requests or a measured false-alert reduction. This upstream version additionally protects active batches during overlap scheduling; that guard has focused regression coverage and was not part of the inspected deployment.
