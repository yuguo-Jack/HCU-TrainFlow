# [CI] [Intel] ci/xpu: Rename rolling Docker tag and add release-cut results CSV

[Upstream PR](https://github.com/sgl-project/sglang/pull/46394) · state: closed · merged: True

## Original PR description

## Motivation

Source-kernel XPU nightly images are tagged `nightly-dev-xpu-bmg-<date>-<sha>-main-main-<kernel sha>`, but their rolling tag was `latest-kernel-main`. Rename the rolling tag to `latest-main-main` to match.

Also, when `release-branch-cut.yml` runs the XPU wheel nightly, dump one CSV of every test file run in that job (stage-a/stage-b PR suites + wheel nightly suite), so the release result can be read without digging through logs.

## Modifications

- `release-docker-intel-xpu-nightly.yml`: `latest_tag=latest-kernel-main` -> `latest_tag=latest-main-main` (and the comment).
- `nightly-test-intel.yml`: the 4 `--image-tag latest-kernel-main` container pulls now use `latest-main-main`, so the nightly tests keep tracking the fresh image.

The wheel rolling tag (`latest`) is unchanged.

- `nightly-test-intel-wheel.yml`, **release branch cut only** (`inputs.ref` set; scheduled/dispatch runs unchanged):
  - The stage-a + stage-b step also writes per-file metrics (`SGLANG_TEST_METRICS_FILE`).
  - New steps merge it with the wheel nightly metrics into `xpu-wheel-1-gpu-results.csv` (`file_name,suite,status,duration`) and upload it as the `xpu-wheel-1-gpu-results-csv` artifact.
- `scripts/ci/xpu/metrics_to_csv.py`: the merger. Each file's suite comes from its `register_xpu_ci` call, since stage-a and stage-b run pooled in one `run_suite.py` call.

## Rollout note

`intel/sglang-dev:latest-main-main` exists only after the first release-docker run on `main` after merge, so trigger `release-docker-intel-xpu-nightly` manually right after merging, before the next Intel nightly. The old `latest-kernel-main` tag stays on Docker Hub but stops advancing.
