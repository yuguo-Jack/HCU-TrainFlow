# [Fix] kimi-k3: move temporal position weights to the embedding device

[Upstream PR](https://github.com/sgl-project/sglang/pull/46077) · state: open · merged: False

## Original PR description

K3 vision warmup can fail when selective loading leaves the non-persistent temporal buffer on CPU while spatial embeddings are on CUDA. The existing cast changes dtype only.

Move the temporal slice to the spatial embedding's device and dtype before addition. The existing vision test now covers split parameter/buffer placement.

## Validation

The actual position-embedding method reproduces the device mismatch in an isolated CPU/meta fixture and passes with this change.

The [CUDA follow-up on the unchanged head `87ddff05`](https://github.com/sgl-project/sglang/pull/46077#issuecomment-6369686071) also reproduces the original CPU/CUDA failure. The patched positional-embedding class and its real sin/cos/interpolation helpers match a fully GPU-resident reference exactly in FP32 and BF16 for single-frame, temporal and resized-grid inputs, using Torch 2.13.0+cu130 on B30Z.

These are isolated class/helper checks. Full K3 execution and the complete upstream vision suite remain unverified. No performance claim.
