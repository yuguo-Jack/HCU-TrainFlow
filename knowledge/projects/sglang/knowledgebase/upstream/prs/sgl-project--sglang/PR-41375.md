# [VLM] Rebuild padded input ids after caller mm_hashes

[Upstream PR](https://github.com/sgl-project/sglang/pull/41375) · state: open · merged: False

## Original PR description

## Motivation

A request that sends caller `mm_hashes` with an image crashes the scheduler on a cold cache (`index_copy_(): index out of bounds`), and the server stops. On a warm cache it does not crash, but it ignores the caller hash, so an external KV-aware router that sends hashes never gets a prefix match. The cause: the processor (for example Qwen3-VL) builds `padded_input_ids` from its own hash. `TokenizerManager` then applies the caller hash with `set_hash`, which changes each item's pad value but not `padded_input_ids`, and the scheduler reuses the stale ids. This PR rebuilds the ids after `set_hash`, with the same builder that the processors use. Setting the ids to `None` (#40225) also stops the crash, but it moves padding back into the scheduler, which #26097 and #36411 removed on purpose.

## Modifications

- After `TokenizerManager` applies caller hashes, it rebuilds `padded_input_ids` with `MultimodalProcessorOutput.build_padded_input_ids`, if the processor built them. Other processors see no change.
- A new unit test checks that the caller-derived pads reach the processor-built ids.

## Accuracy Tests

Qwen3-VL-2B-Instruct on one GPU, tokens-in `/generate` with `image_data`, main at 450837e770 vs this PR merged with it. The caller hash maps to pad 948526808. The processor's own pad for the image is 1023635744.

| Same image, caller `mm_hashes` | main | this PR |
|---|---|---|
| Cold cache | Scheduler crash: `index_copy_(): index out of bounds` | 200, KV event pad 948526808 |
| Cached before without hashes | 200, cached_tokens 208 (caller hash ignored) | 200, cached_tokens 0, KV event pad 948526808 |
| Same request again | Not run (server down) | 200, cached_tokens 208 |

Requests without `mm_hashes` are unchanged: same caption, 213 prompt tokens and KV event pad 1023635744. Unit: all 11 tests in `test_mm_hashes.py` pass, and the new test fails on main.
