# [Fix] VLM: Rebuild padded input ids after caller mm_hashes

[Upstream PR](https://github.com/sgl-project/sglang/pull/41375) · state: closed · merged: False

## Original PR description

## Motivation

A request that sends caller `mm_hashes` with an image crashes the scheduler on a cold cache (`index_copy_(): index out of bounds`), and the server stops. On a warm cache it does not crash, but it ignores the caller hash, so an external KV-aware router that sends hashes never gets a prefix match. The cause: the processor (for example Qwen3-VL) builds `padded_input_ids` from its own hash. `TokenizerManager` then applies the caller hash with `set_hash`, which changes each item's pad values but not `padded_input_ids`, and the scheduler reuses the stale ids. This PR rebuilds the ids after `set_hash`, with the same builder that the processors use. Setting the ids to `None` (#40225) also stops the crash, but it moves padding back into the scheduler, which #26097 and #36411 removed on purpose.

## Modifications

- After `TokenizerManager` applies caller hashes, it rebuilds `padded_input_ids` with `MultimodalProcessorOutput.build_padded_input_ids`, if the processor built them. Other processors see no change.
- A new unit test checks that the caller-derived pads reach the processor-built ids.

## Accuracy Tests

Qwen3-VL-2B-Instruct on one GPU, tokens-in `/generate` with `image_data`, main at 5ed306bd69 vs this PR merged with it. "Caller pads" are the pad values that `set_hash` derives from the caller hash.

| Same image, caller `mm_hashes` | main | this PR |
|---|---|---|
| Cold cache | Scheduler crash: `index_copy_(): index out of bounds` | 200, KV event carries the caller pads |
| Cached before without hashes | 200, cached_tokens 208 (caller hash ignored) | 200, cached_tokens 0, KV event carries the caller pads |
| Same request again | Not run (server down) | 200, cached_tokens 208 |

Requests without `mm_hashes` are unchanged: same caption, 213 prompt tokens and the processor's own pads in the KV event. Unit: all 13 tests in `test_mm_hashes.py` pass with hash precompute off and on, and the new test fails on main.

                    # The scheduler reuses these ids as-is; set_hash changed the pads.

                        for item in mm_inputs.mm_items:
