# [Bugfix][PD] Accept slot_layer_ids in NixlKVManager.set_kv_buffer_tensors

[Upstream PR](https://github.com/sgl-project/sglang/pull/42970) · state: closed · merged: False

## Original PR description

## Motivation

Fixes #42684.

With `SGLANG_DISAGG_STAGING_BUFFER=1` on non-MLA models, both `prefill.py` and `decode.py` call

```python
kv_manager.set_kv_buffer_tensors(k_buffers, v_buffers, page_size, slot_layer_ids=...)
```

unconditionally. `MooncakeKVManager` accepts the `slot_layer_ids` kwarg, but `NixlKVManager` never got it, so picking the NIXL backend in staging mode kills the kv manager with

```
TypeError: NixlKVManager.set_kv_buffer_tensors() got an unexpected keyword argument 'slot_layer_ids'
```

during init and the server never comes up.

## Modifications

`NixlKVManager.set_kv_buffer_tensors` now takes `slot_layer_ids` and stashes it in `kv_buffer_tensors`, matching the Mooncake signature. This is parity only: the NIXL staged gather walks the registered buffers in list order and nothing reads the mapping back. The same scoped fix is currently carried inside the larger #40909 and #40861; this PR lands it on its own so staging mode works on main without waiting for those.

Added two unit tests to `TestNixlStaging` covering the kwarg and its default.
