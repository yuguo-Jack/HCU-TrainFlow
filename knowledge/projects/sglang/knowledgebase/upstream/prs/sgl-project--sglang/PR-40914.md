# [Refactor] memory-pool: Build draft sidecar host pools from buffer info

[Upstream PR](https://github.com/sgl-project/sglang/pull/40914) · state: closed · merged: True

## Original PR description

## Motivation

Followup of #40916. The separate draft sidecar builders now take the draft pool's buffer info from their caller instead of reading the device pool. `_build_mha_mla_host_pool` and `_mha_host_inputs` receive the info explicitly. For a DSA draft, `build_full_draft_pools` reads the KV info from the same host pool config that registers the draft indexer, so both come from one `get_device_pool_infos()` call. This replaces the earlier declaration based approach of this PR.

One behavior change: the DeepSeek V4 draft SWA sidecar in `build_swa_draft_pools` is built from the draft pool's `paged_buffer_info()` and moves whole pages only when its layout does not support the token-granular copy, as the target SWA host pool already does. On main a v41 or uniform FP8 draft SWA sidecar sent partial pages through the token-granular V4 copy, which assumes a 576-byte value plus an 8-byte scale per token.

## Accuracy

HiCache multi-turn KL with forced host hits against #40916, same commands on both sides. Assembled host pools, the H2D transfer sequence and the KL verdict match the parent for Qwen3.8-27B with NEXTN, Qwen3 and DeepSeek-V2-Lite with a STANDALONE draft, and gpt-oss with an SWA draft.

MiniMax-M3.1-Flash (NVFP4 KV), tp 4, DSpark with a separate draft host pool: identical to the parent, with every prefill-hit and decode-hit sample served from host.

DSpark and NEXTN MTP pack DeepSeek V4 drafts into the target pools, so the runs above do not reach the DeepSeek V4 draft SWA sidecar. `test_dsv4_v41_draft_swa_sidecar_moves_whole_pages` builds that sidecar from a real V4.1 draft pool on GPU, round-trips whole pages byte for byte, and checks that a partial page is rejected. It fails on main, where the partial page goes through the V4 token copy.
