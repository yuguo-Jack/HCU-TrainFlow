# [Fix] disaggregation: Send aux_item_lens next to aux_ptrs in PD registration

[Upstream PR](https://github.com/sgl-project/sglang/pull/47638) · state: closed · merged: True

## Original PR description

## Motivation

Follow-up to #40107. The `aux_item_lens` registration frame was appended at the end of the message (Mooncake frame 20, NIXL frame 24 after GUARD) and only when customized-info transfer was enabled. Registration frames are positional, so any frame appended after it would land at a different index depending on whether the feature is on.

Rather than keep patching around a trailing optional frame, this puts the frame where it belongs, right after `aux_ptrs`, and always sends it.

## Modifications

- Mooncake: `aux_item_lens` is now frame 6; frames 6-19 move to 7-20 (staging fields move to 15/16, slot layer ids to 19).
- NIXL: `aux_item_lens` is now frame 7 (after GUARD); frames 7-23 move to 8-24.
- The frame is always sent, empty when customized-info transfer is disabled, and an empty frame parses as `None`. The builders return a plain list again instead of conditionally appending.
- `test_registration_wire_is_preserved_for_all_peers` expects the new frame right after `aux_ptrs`.

**Compatibility:** this changes the decode -> prefill registration layout, so prefill and decode must run the same SGLang version. Mixing a build with this change and one without it is not supported.
