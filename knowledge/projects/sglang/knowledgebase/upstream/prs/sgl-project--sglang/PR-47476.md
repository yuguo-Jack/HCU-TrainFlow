## Original PR description

# [Feat] paged-experts: size the resident experts automatically

## Motivation

This PR aims to make Paged Experts work without hand-tuning K.

Currently, Paged Experts (#42557) needs `--paged-experts-num-resident K`. K and the KV cache share the static budget (`--mem-fraction-static`), so the right K depends on the GPU, the model, the quantization, the KV cache dtype and how much context the server should hold. Users find it by trial: a K too large fails at startup with too little memory for the KV cache, and a K too small leaves memory idle and pages more than needed. On Qwen3-30B-A3B-GPTQ-Int4 with a 16 GB GPU, decode is 208 tok/s at K = 63 and 233 tok/s at K = 92.

## Modifications

`--paged-experts-num-resident` takes a count or `auto`; omitted means `auto`. An explicit count works as before.

**The KV cache comes first** (`sizing.py`, one guarded call before and after the KV configure step in `model_runner.py`).
- By default it keeps room for one request of the model's own context, in whole pages.
- `--context-length` sets that length, and `--max-running-requests`, if you set it, how many such requests it aims for. One full-length request is a promise; the rest is a target that the expert slots never take memory from. A `--max-running-requests` SGLang resolves itself (e.g. a model's default of 256) still caps the request pool, but is no target.
- `--max-total-tokens`, if set, is what the KV cache keeps instead.
- The aim is applied as `--max-total-tokens`, the cap every KV pool type already honors, so the KV configurator is unchanged.
- If a `--max-total-tokens` or `--context-length` the user set does not fit even at K = `top_k`, startup fails naming the flag. If the model's own context does not fit, K stays at `top_k`, the KV cache takes what is left and requests are capped at its size, as SGLang caps them whenever the KV cache is shorter than the context; a warning names `--context-length`. Requests beyond what the KV cache holds queue, as everywhere in SGLang.

**The expert slots take the rest** (`sizing.py`, `method.py`).
- Layers are built with K = `top_k`. After the KV cache is allocated, these tables are freed and what is left of the static budget is measured: free memory less the non-static slack and the multimodal reserve, as the KV configurator measures it.
- Every layer grows by whole rounds of one slot while a round fits, up to all its experts. The slot tables of all layers are one allocation; if the allocator refuses it, startup fails naming the flags.
- The K = `top_k` tables live in a `torch.cuda.MemPool` of their own, so freeing them returns their memory; freed between the weights, they left about 0.5 GB of holes the new allocation could not use.
- The runner, residency, executors and decode capture cap are built once, for the final K. The cap (`K // top_k`, the smallest over layers) applies only to full decode graphs, which cannot break out for host-planned waves.

**The log says how it decided.** One line names K, its size, the KV cache, how many full-length requests it holds at once, the flags its aim comes from, and the flag that pins this K:

```
Paged experts: K=63 of 128 experts per MoE layer resident (6.85 GiB); KV cache 40960 tokens, 1 request(s) of 40960 at once (aim 40960: the model's context 40960 x 1 request(s)). To pin: --paged-experts-num-resident 63
```

**Interactions.**
- Mamba hybrids without `--max-mamba-cache-size`: SGLang gives the Mamba state `r / (1 + r)` of what the budget leaves (`r = --mamba-full-memory-ratio`). Here that budget is the experts', so the state pool holds the requests the KV cache aims for instead: the `--max-running-requests` you set, or one, never more than SGLang's own share.
- `auto` refuses post-capture KV sizing (`SGLANG_ENABLE_POST_CAPTURE_KV_SIZING`; it would resize the KV cache the slots were sized against), `--enable-memory-saver`, `--enable-lora` and `--enable-nvidia-megakernel` (they bind or move the slot tables); set an explicit K with those.

Outside Paged Experts this touches only `model_runner.py`, besides the flag's own field (`arg_groups/fields/exec_.py`): 12 lines in `alloc_memory_pool`, guarded by `--enable-paged-experts` with `auto`. From Python, `paged_experts_num_resident="auto"` works like the CLI's `auto`. Docs: "Choosing K" in `paged_experts.mdx`, rewritten around how `auto` decides, and the flag's row in `server_arguments.mdx`.

## Accuracy Tests

The slots hold the same bytes as with an explicit K; only K and where the tables live change.

**Unit tests** (`TestSizing`, `TestCompat`, and a GPU test in `test_paged_experts_kernels.py`).
- Two paged layers sized from a budget of 4 slots each get K = 4, share one allocation, and serve a step routed only to the grown slots exactly like the unpaged layer, with nothing paged in. Corrupting a grown slot must break that, and does.
- Growth by whole rounds, layers stopping at their expert count; the decode cap per layer (router top-k 2 and 4); a refused allocation fails naming the flags; a `--max-total-tokens` or `--context-length` that does not fit fails naming its source; the model's own context that does not fit keeps K = `top_k` and warns (control: one that fits does not); the log line names K, the KV cache, the aim and how to pin K.
- Mamba state: one request by default, the requests set, SGLang's share as the cap, one request at least, none when `--max-mamba-cache-size` is set.
- Only a `--max-running-requests` the user set is a target (negative control: the same value resolved by SGLang is not); a request is held in whole pages (control: page size 1).
- Layers with an explicit K are not sized and leave `--max-total-tokens` alone (control: an auto layer); an explicit K caps decode capture when built, `auto` (also the string from Python) only once sized; breakable or disabled decode graphs are not capped (control: a full one is).
- The flag parser takes `auto` or a positive count; `auto` with post-capture KV sizing, memory saver, LoRA or the megakernel is refused.
- On the GPU, a pooled table returns its memory once dropped (negative control: while the pool lives, the memory stays reserved), and so do a sized layer's released tables (negative control: a view kept elsewhere holds them).

**GSM8K (200 questions), Qwen3-30B-A3B-GPTQ-Int4, `--context-length 4096 --max-running-requests 4 --max-total-tokens 10240`, this PR:** K = 92 0.945 / 0.940, `auto` (K = 92) 0.950.

The 4-layer test models used for the other Paged Experts PRs cannot show `auto`: with 32 experts every expert fits, so nothing pages.

## Speed Tests and Profiling

Same machine as #42557: RTX 5070 Ti 16 GB (PCIe 5.0 x16, 62 GB RAM), `--mem-fraction-static 0.88`, prefix caching off, 16 ShareGPT warm-up requests discarded. Decode tok/s is `1000 / median TPOT` over 8 ShareGPT prompts sent one at a time (256 output tokens each). 4 requests: 16 ShareGPT prompts from 4 clients at once. The first cell is repeated last; a difference inside that spread is no difference.
