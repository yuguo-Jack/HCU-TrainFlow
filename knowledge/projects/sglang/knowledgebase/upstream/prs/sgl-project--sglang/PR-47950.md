# [Perf] parser: Avoid O(N^2) buffer copies and scans in BaseReasoningFormatDetector streaming

[Upstream PR](https://github.com/sgl-project/sglang/pull/47950) · state: open · merged: False

## Original PR description

## Motivation

When `stream_reasoning=False` (or `force_nonempty_content=True` before normal content arrives), `BaseReasoningFormatDetector._parse_streaming_increment_impl` accumulates reasoning chunks in `self._buffer` until `think_end_token` or a tool-call start delimiter (`tool_start_token`) is encountered.

Previously, each streaming chunk incurred three quadratic $O(N^2)$ bottlenecks over the accumulated reasoning buffer of length $N$:
1. **Full-buffer string copy on every chunk**: Appending via `self._buffer += new_text` on an instance attribute (and reading `current_text = self._buffer` while `self._buffer` remained bound) kept `ob_refcnt > 1` and used `STORE_ATTR`, preventing CPython's in-place unicode resize optimization (`BINARY_OP_INPLACE_ADD_UNICODE`). In addition, generator expressions inside `_parse_streaming_increment_impl` captured `current_text` into a closure cell (`MAKE_CELL` / `LOAD_DEREF`), which also bypasses CPython's `LOAD_FAST` in-place append path.
2. **Full-buffer `think_end_token` scan from index 0**: `current_text.find(self.think_end_token)` re-scanned the entire prefix that had already been checked on previous chunks.
3. **Full-buffer `_find_tool_start` scan from index 0**: `self._find_tool_start(current_text, ...)` re-scanned the entire accumulated buffer from index `0` on every token increment.

For long reasoning traces (e.g., DeepSeek-R1 / Qwen3 / QwQ generating 100K–800K characters of chain-of-thought with `stream_reasoning=False`), CPU time in `parse_streaming_increment` scaled quadratically and blocked the detokenizer/HTTP streaming loop for seconds to minutes.

## Modifications

- Detach `self._buffer = ""` before appending `current_text += new_text` on a pure `FAST` local variable (replacing generator expressions that captured `current_text` into closure cells with inline list comprehensions) so CPython mutates `current_text` in-place in amortized $O(1)$ time per chunk.
- Bound `current_text.find(self.think_end_token, search_offset)` to start at `max(0, prev_len - len(self.think_end_token) + 1)`, the earliest index where a newly completed `think_end_token` could begin.
- Add an optional `start` offset to `_find_tool_start` and bound streaming tool-start scans to `max(0, prev_len - len(self.tool_start_token) + 1)` while checking `current_text[idx - 1]` when `idx > 0` for newline-only tool delimiters.
- Add unit tests in `test/registered/unit/parser/test_reasoning_parser.py` covering `stream_reasoning=False` with multi-chunk streaming and boundary-split `think_end_token` / `tool_start_token` delimiters.
