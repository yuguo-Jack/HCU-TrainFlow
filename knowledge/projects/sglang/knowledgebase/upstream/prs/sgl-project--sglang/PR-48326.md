# [Fix] metrics: Correct FLOPs estimate for hybrid Mamba/attention/MLP models

[Upstream PR](https://github.com/sgl-project/sglang/pull/48326) · state: open · merged: False

## Original PR description

## Motivation

For hybrid Mamba+attention architectures (e.g. NemotronH), `_init_estimated_perf_constants` in `metrics_reporter.py` scales both the attention-FLOPs term and the MLP-FLOPs term by `num_attention_layers`, which `ModelConfig` sets equal to `num_hidden_layers` for these models (no hybrid-Mamba special case exists there). In practice only a small fraction of layers are true attention layers; the rest are Mamba-mixer-only or MLP-only layers with no attention sublayer and, for Mamba layers, no MLP sublayer either.

This inflates the estimated prefill TFLOPS by roughly an order of magnitude for mostly-Mamba stacks. Concretely, on `nvidia/Nemotron-H-4B-Instruct-128K` (52 layers: 4 attention, 24 Mamba, 24 MLP-only), live on H200 (SGLANG_ENABLE_METRICS_DEVICE_TIMER=1, bench_serving, 1536-in/512-out, 500 prompts, concurrency 128), the device-timer-weighted ground-truth prefill TFLOPS was 1631.1 TFLOPS/s — 165% of H200's 989 TFLOPS/s physical peak, which is impossible. The same run after this fix reports 933.3 TFLOPS/s (94.4% of peak), a physically plausible value.

## Modifications

- In `_init_estimated_perf_constants`, read `hf_text_config.layers_block_type` (the per-layer type list the model builder itself reads at construction time, e.g. `models/nemotron_h.py`) when available, and derive separate `num_attn_layers` (count of `"attention"`) and `num_mlp_layers` (count of `"mlp"` + `"moe"`) instead of using a single shared `num_layers` for both.
- Falls back to the existing `full_attention_layer_ids`-based attention-layer count (with `num_mlp_layers = num_layers`) when `layers_block_type` isn't present, preserving current behavior for non-hybrid architectures.
- Scale `attn_linear_flops` by `num_attn_layers`, `mlp_flops` by `num_mlp_layers`, and `_attn_dot_flops_coeff` by `num_attn_layers` (previously all three were scaled by the same `num_layers`).
- Mamba/SSM-layer compute itself is intentionally left uncosted (not estimated) rather than guessed at — a conservative gap that, if anything, slightly under-reports FLOPs/MFU for heavily-Mamba models rather than over-reporting.

This only affects the analytical FLOPs estimator used for `--enable-mfu-metrics` telemetry; it does not change model execution.

## Accuracy Tests

Not applicable — this only changes a telemetry estimator used for `est. prefill/decode TFLOPS/s` logging, not model forward computation.

## Speed Tests and Profiling

Hardware-validated live on an H200 GPU running `nvidia/Nemotron-H-4B-Instruct-128K` with `SGLANG_ENABLE_METRICS_DEVICE_TIMER=1 --enable-metrics --enable-mfu-metrics`, using `sglang.bench_serving` (`--dataset-name random --random-input-len 1536 --random-output-len 512 --num-prompts 500 --max-concurrency 128`):

| Stage | Ground-truth prefill TFLOPS/s | % of H200 peak (989 TFLOPS/s) |
|---|---|---|
| Before fix (all 52 layers costed as attention) | 1631.1 | 165% (impossible) |
| After fix (4 attention, 24 MLP, 24 Mamba layers split correctly) | 933.3 | 94.4% |
