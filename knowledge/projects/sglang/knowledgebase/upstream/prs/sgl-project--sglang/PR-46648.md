# [Perf] [AMD] Kimi-K3: DFlash draft split-KV sliding-window verify kernel

[Upstream PR](https://github.com/sgl-project/sglang/pull/46648) · state: open · merged: False

## Original PR description

## Motivation

On ROCm, the DFlash draft runner's TARGET_VERIFY block used the generic Triton path.

## Modifications

A split-KV, GQA-packed sliding-window kernel reads the strided q/k/v directly, and builds its metadata in one fused launch.

## Accuracy Tests

- `test_k3_draft_swa_verify.py` and `test_triton_verify_metadata.py`: 9 pass.

Full K3 stack on MI355X TP8 (DFlash, prod config) vs B300, McNemar:
- GPQA-D 89.4 vs 87.9 (p=0.55)
- AIME25 96.7 vs 93.3 (p=1.0)
- MATH500 92.2 vs 92.2 (p=1.0)
- MMLU-Pro 89.6 vs 90.0 (p=0.77)
- GSM8K 97.2%

## Speed Tests and Profiling

- Turning it off costs -9.0/-2.4/-0.9% on the agentic replay and -9.9/-2.9% at 90k prefix (mean -5.0%).

Speed numbers: throughput change from turning this feature off on the full stack, agentic replay at C=1/8/32 and 90k-prefix at C=1/8.
