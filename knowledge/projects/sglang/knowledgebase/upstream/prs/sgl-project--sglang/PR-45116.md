## Motivation

Add an opt-in asynchronous admission path for pipeline-parallel PD prefill with HiCache and L3 storage. Each PP stage advances its own prefetch operations. Before a request enters computation, an admission gate agrees on a common usable full-prefix length and hands the selected request back to the native prefill scheduler.

This moves cross-stage coordination to the request admission boundary, allowing storage progress to differ across stages without allowing incompatible prefix lengths into the same pipeline computation. Admission messages use the existing ordered PP control flow; the path does not add a separate voting channel or a new cross-PP collective. Stage-local TP/CP synchronization remains in place.

Enable it with:

```bash
SGLANG_ENABLE_PP_L3_CACHE_ASYNC_ADMISSION=1
```

The flag defaults to disabled. The measured **B** configuration uses the native implementation with the flag set to `0`; **C** uses asynchronous admission with the flag set to `1`.

## Modifications

```text
PD Prefill Scheduler
│
├── Native Request Lifecycle
│   └── Request relay / PD bootstrap → waiting_queue
│
├── Independent Prefetch: L3 → L2
│   ├── PP0: prefetch KV for its local layers
│   ├── PP1: prefetch KV for its local layers
│   └── PP2: prefetch KV for its local layers
│
├── PPAdmissionGate
│   │
│   ├── Readiness
│   │   ├── PP0 → PP1 → PP2: accumulate local ready bits
│   │   ├── PP2 → PP0: return readiness
│   │   └── Any stage not ready: keep request pending
│   │
│   ├── Prepare / Full-Prefix MIN
│   │   ├── Each stage finalizes prefetch and protects its prefix
│   │   ├── PP0: prefix=1024 → cap=1024
│   │   ├── PP1: prefix=960  → cap=960
│   │   ├── PP2: prefix=1024 → cap=960
│   │   └── PP2 → PP0: return the common cap
│   │
│   └── Commit / Selection
│       ├── PP0 accepts the cap and selects the compute layout
│       └── PP0 → PP1 → PP2: forward commit and layout
│
└── Native Execution
    ├── Allocation / L2 → L1 H2D
    ├── PP computation
    └── KV transfer to Decode
```

- **One policy-independent protocol.** `best_effort`, `timeout` and `wait_complete` use the same readiness/prepare/commit flow. Policy evaluation stays in the cache layer. Readiness means permission to stop waiting; it does not necessarily mean that every requested page was fetched.
- **Full-prefix agreement.** The agreed cap is the usable prefix after local prefetch finalization and cache matching, including usable L1/L2 coverage. It is not the MIN of only the newly fetched L3 suffix lengths.
- **Preserve native request ownership.** Requests remain in the native queues. The gate provides a filtered candidate view instead of maintaining a second scheduling queue or cancellation lifecycle.
- **Protect promises across PP beats.** Prefix leases and capacity credits cover the interval between preparation and native selection. Credits are scheduler accounting, not early placeholder GPU allocations. Native selection performs allocation and H2D.
- **Replay one compute layout.** PP0 chooses request order and chunk endpoints; downstream stages replay that layout instead of independently selecting different chunk boundaries.
- **DSA index sharing.** When the selected path shares top-k indices across a PP boundary, use logical token positions rather than relaying allocator-local KV slots between independently managed stage caches.
- **Preserve wait accounting.** The gate calls the native storage-prefetch wait observer before latching local readiness. This measures the interval from the first blocked local poll to local stop permission; subsequent PP agreement and capacity waits are not included in that field.

## Accuracy Tests

- Dataset: GSM8K
- Prefill: **TP1PP16**, Mooncake L3, `timeout` policy.
- Generation: temperature `0`, top-p `1`, maximum output tokens `2048`, concurrency `16`, `enable_thinking=false`.
- First pass: start with empty L1/L2 and an empty Store.
- Second pass: drain the first pass and storage writes, call native Prefill `flush_cache` to clear L1/L2, retain L3, and rerun the same full test set.

| Implementation | Pass | Accuracy |
|---|---|---:|
| Native L3 | First, cold Store | 95.982% |
| Native L3 | Second, after L1/L2 flush | 96.058% |
| Async L3 | First, cold Store | 95.830% |
| Async L3 | Second, after L1/L2 flush | 95.375% |

### Performance results

Configuration:

- Model: GLM-5.2-FP8, with FP8 KV (`fp8_e4m3`).
- Prefill: 16 GPU ranks, tested as TP8PP2, TP4PP4, TP2PP8 and TP1PP16; no prefill MTP; L1 capacity fixed at **800,000** tokens and L2 ratio 2 in cache mode.
- Decode: a retained 16-GPU TP16/EP16/attention-DP16 DeepEP deployment with MTP steps/top-k/draft tokens = 5/1/6 and static memory fraction 0.85.
- Storage: Mooncake, four 600 GiB RDMA segments, SSD offload disabled, client-contributed global segment size 0. Store state was cleared and restarted for each L3 arm. The prefetch threshold was 256 tokens; timeout configuration used a 1 s base and 0.25 s per 1,024 tokens.
- Workload: 4,000 agent-task replay requests per configuration, 32 users (i.e., 32 tasks served in rotation at a maximum concurrency of 16 to increase the likelihood of cache eviction), maximum concurrency 16, seed 0, original output lengths and `ignore_eos`. Across configurations, mean input length was approximately 53.1–53.4K tokens and mean output length 306–316 tokens. Warmup requests were excluded from reported results.

The four prefill deployments below each compare five configurations:

- **w/o L3:** hierarchical L1/L2 cache without storage prefetching; no L3 policy applies.
- **Native L3 (BE/TO):** the community L3 admission path with asynchronous admission disabled.
- **Async L3 (BE/TO):** this work with asynchronous admission enabled, using the same Mooncake storage backend.

**BE** means `best_effort`; **TO** means `timeout`. Each row contains 4,000 successful requests.
