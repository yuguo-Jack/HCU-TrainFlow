# [Feat] HiCache: Add PP storage query and completion consensus

[Upstream PR](https://github.com/sgl-project/sglang/pull/45116) · state: open · merged: False

## Original PR description

## Motivation

Pipeline-parallel HiCache prefetch needs a common storage result before native scheduling can consume it. Background completion collectives couple PP stages to each other's I/O progress, while stopping a fetch before its agreed ACK arrives can finalize a stale prefix.

This change shares the storage query and moves PP completion agreement into the existing scheduler loop. Native request ownership, cache allocation, stop policies, prefix insertion and H2D remain responsible for admitting and executing requests.

## Modifications

- Bind each cache-mode operation to a shared query ticket at native prefetch submission, after grammar and skip checks. PP0 submits the query; existing query collectives agree the storage-only root endpoint and component results. Local L1/L2 coverage is excluded from this MIN.
- Preserve ordered query delivery, including cancellation, and identify retries by the native request handle and attempt counter. Resolve the agreed root result to each stage's local suffix before native allocation and GET.
- Keep TP/CP completion reduction in the worker. Fold available ACKs through PP0 -> PP-last -> PP0 in the PP loop, using the existing P2P helpers with a distinct message tag. Slow stages shorten the proposed batch instead of waiting for local I/O.
- Preserve operation ownership until the ordered query drain or agreed terminal ACK retires it. For cache-mode PP, best_effort requires positive agreed progress before requesting stop. A stopped candidate pauses selection until settlement so later requests are not stopped before its token/chunk budget is charged. Timeout retains its deadline; wait_complete retains natural completion.
- Fence late results across reset/detach with a storage generation. Reuse native component descriptors, buffer publication and release paths, including SWA/Mamba endpoint requirements.

The implementation uses native PP/HiCache/L3 configuration and has no separate admission opt-in flag, prefix lease or capacity-credit protocol. It retains native PP0-led L2/cache-event ordering and its assumptions. Although the completion hook is installed in unified, PD Prefill and PD Decode loops, PD Decode + PP + L3 is not qualified: the native PP decode loop does not drain HiCache events.
