# [Fix] Link cuda_ipc JIT against CUDA driver stubs dir

[Upstream PR](https://github.com/sgl-project/sglang/pull/43764) · state: closed · merged: True

## Original PR description

## What

`_init_ipc_manager` links the `cuda_ipc` JIT module with a bare `-lcuda`. Where `libcuda.so` isn't on the linker search path, the build fails (`ld: cannot find -lcuda`); `parallel_state.py` catches it with a warning and continues with custom allreduce disabled, so affected setups fall back to NCCL (~5x slower per call in the incident we measured). Fix: use `cuda_stubs_dir()`, same as `dsv4/wo_a.py` and `kda_ptx_prefill`.

## Why it wasn't caught before

Not a recent regression — bare `-lcuda` dates to the v2 rewrite (#31049). It's masked only in images that symlink the stub into the system libdir (AOT, sgl-deep-ep). The main `docker/Dockerfile` (release + dev images) doesn't; we hit it on a dev-image GB300 box with no `/usr/lib/aarch64-linux-gnu/libcuda.so`.

Sibling with the same flags: `vsa_block_sparse_sm100_jit.py` (untouched here — different subsystem, source-level exposure only).

## Verification (GB300, previously failing)

- old flags → build fails (control)
- fixed flags → links, `register_once()` succeeds
- no change where the link already worked
