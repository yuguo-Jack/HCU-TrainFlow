# [Fix] [XPU] benchmark: Run the fused MoE Triton tuner on XPU

[Upstream PR](https://github.com/sgl-project/sglang/pull/47002) · state: open · merged: False

## Original PR description

## Motivation

`benchmark/kernels/fused_moe_triton/tuning_fused_moe_triton.py` fails on XPU before it benchmarks the first config:
- It hard-codes CUDA: `torch.cuda.synchronize`, `torch.cuda.CUDAGraph`, `torch.cuda.Event`, and a `"cuda"` cache-flush tensor.
- It uses Ray's global GPU id as the local device ordinal. Ray already isolates one card per worker, so on XPU that ordinal is out of range, as it is on ROCm.

The sibling `tuning_fused_moe_triton_sep.py` already uses the device-generic APIs.

## Modifications

- `tuning_fused_moe_triton.py`:
  - Synchronize, capture the graph and create events through `torch.get_device_module()`, with `torch.xpu.XPUGraph` on XPU.
  - Allocate the L2-flush buffer on the current device.
  - Seed through the device module.
  - Use device ordinal 0 on XPU, as on ROCm.
  - CUDA behavior is unchanged: every call resolves to `torch.cuda`.
- `README.md`: new "Intel XPU" section. Ray only registers Intel GPUs as `GPU` resources when `dpctl` is installed (it is part of the `ray` extra in `pyproject_xpu.toml`). Cards are selected with `ZE_AFFINITY_MASK`.

## Accuracy Tests

Benchmark tooling only; no runtime code changes.

## Speed Tests and Profiling

The tuner now runs end to end on Arc Pro B70; it was used to tune Qwen3-30B-A3B at TP4 for batch sizes 1-32.

For reference, those configs with `--moe-runner-backend triton` (4x B70, TP4, `bench_serving` random 512 in / 256 out, same tuned server flags as the default runner):

| | c=1 TPOT | c=1 TTFT | c=4 TPOT | c=16 TPOT |
|---|---|---|---|---|
| Triton runner, default configs | 6.70 ms | 119 ms | 11.08 ms | 20.68 ms |
| Triton runner, B70-tuned configs | 6.62 ms | 37 ms | 25.84 ms | 23.30 ms |
| default XPU runner (sgl-kernel-xpu grouped GEMM) | 6.72 ms | 35 ms | 10.69 ms | 20.19 ms |

The tuned configs fix the Triton runner's prefill and help at c=1. They are worse at c>=4, and the default XPU runner is the better choice there, so this PR does not add config files. It only makes the tuner usable on XPU.
