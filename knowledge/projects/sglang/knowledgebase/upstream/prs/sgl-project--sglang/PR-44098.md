# [GLM-5.3-Flash] Drop the NextN layer from the KDA state pool

[Upstream PR](https://github.com/sgl-project/sglang/pull/44098) · state: closed · merged: True

## Original PR description

## Motivation

With speculative decoding on, the GLM-5.3-Flash KDA state pool also allocates a slot for the NextN layer (layer 45). The NextN draft is an MLA/DSA layer that runs full attention: the draft worker routes `full_attn_layers=[0]` in `attention_registry.py`, so it never reads or writes KDA state. Every KDA buffer (conv, SSM, intermediate SSM, intermediate conv window) therefore carried 35 layers for 34 real KDA layers, and the memory budget in `_handle_max_mamba_cache` charged only 34.

## Modifications

- `_get_mamba_layer_ids_for_req_pool` returns only the config's KDA layers on this rank.
- Remove the `Glm5NextTextConfig.nextn_layer_ids` property, which has no other users.

Side effects:

- Under pipeline parallelism the NextN layer was appended on every stage without the `[start_layer, end_layer)` filter; each stage now allocates only its own KDA layers.
- `HybridReqToTokenPool.copy_mamba_state` waits on `max(self.mamba_map)` under HiCache layer transfer; that is now the last KDA layer instead of the NextN layer.
- With speculative decoding, the KDA state buffers registered for PD transfer have 34 layers instead of 35, so prefill and decode nodes must run the same version.

## Accuracy Tests

GB300 x4, cookbook Low Latency recipe (TP4, EAGLE 5/1/6, `--kv-cache-dtype fp8_e4m3`, trtllm DSA prefill/decode, `--moe-runner-backend flashinfer_trtllm`). `python -m sglang.test.few_shot_gsm8k --num-questions 200 --parallel 48`:

| | main | this PR |
|---|---|---|
| GSM8K accuracy | 0.915 | 0.920 |
| MTP accept length | 3.99-4.18 | 3.95-4.15 |

## Memory

Same setup, per rank (identical on all 4 ranks):

| | main | this PR | this PR, `--mem-fraction-static 0.86059` |
|---|---|---|---|
| KDA ssm_state | 33.50 GB | 32.54 GB | 32.80 GB |
| KDA conv_state | 1.18 GB | 1.14 GB | 1.15 GB |
| intermediate_ssm_state | 10.05 GB | 9.76 GB | 9.76 GB |
| intermediate_conv_window | 0.35 GB | 0.34 GB | 0.34 GB |
| Allocated after CUDA graphs | 243.55 GiB | 242.26 GiB | |
| Free after CUDA graphs | 29.43 GiB | 30.72 GiB | 29.45 GiB |
| max_total_num_tokens | 18,578,176 | 18,578,176 | 18,742,016 |
| max_mamba_cache_size | 979 | 979 | 987 |

The PR frees 1.287 GiB per rank (1/35 of the KDA buffers). The last column raises `--mem-fraction-static` by the freed amount (from the default 0.85595), which brings free memory back to the main level and adds 163,840 KV tokens and 8 KDA slots.
