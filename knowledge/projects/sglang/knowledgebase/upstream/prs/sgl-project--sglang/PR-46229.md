# [Perf] dsv41: Translate SWA locations once per prefill graph step

[Upstream PR](https://github.com/sgl-project/sglang/pull/46229) · state: closed · merged: True

## Original PR description

Two per-step costs in the DeepSeek-V4.1 prefill CUDA graph, removed without changing any output bit.

- **SWA locations**: with no request window or SWA ring, every full-attention layer's KV store translated `out_cache_loc` to SWA locations again (an index gather and an int32 cast per layer). The prefill graph's metadata prep now translates it once into `core_attn_metadata.swa_out_cache_loc`, and replay refreshes that captured buffer in place, so every layer store reads the cached locations.
- **Tail bridge**: `DecoderReplayTail._bridge_outputs` no longer zero-fills the bridge rows past the tail. The graph's row-wise readers carry those rows only into rows that `_scatter_tail_rows` and the `real_rows_count` cut drop.

## Verification

- The breakable-CUDA-graph metadata contract test now checks that replay refreshes the captured SWA location buffer by address with the replayed batch's translated locations.
- Existing DSv4 backend and late-layer tail reader unit tests pass.
