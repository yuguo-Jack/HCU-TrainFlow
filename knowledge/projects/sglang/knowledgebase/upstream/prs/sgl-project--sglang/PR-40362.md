# fix(gdn): keep gating beta in fp32 on the extend/prefill path

[Upstream PR](https://github.com/sgl-project/sglang/pull/40362) · state: closed · merged: False

## Original PR description


**What.** `fused_gdn_gating_kernel` allocates `beta_output` as an fp32 buffer, but stores
`sigmoid(b)` narrowed to the *input* dtype:

```python
# python/sglang/kernels/ops/attention/fla/fused_gdn_gating.py
blk_beta_output = tl.sigmoid(blk_b.to(tl.float32))
tl.store(beta_output + off, blk_beta_output.to(b.dtype.element_ty), mask=mask)
```

No bf16 arithmetic happens between the fp32 sigmoid and the narrowing, so the round-trip only
discards the low mantissa bits — up to bf16 epsilon (~0.39%) per value — and the fp32 buffer
ends up holding bf16-precision contents.

**Why it matters.** That tensor is what the extend path feeds into the delta-rule update of the
persistent SSM state (`gdn_backend.py`, `kernel_dispatcher.extend(beta=beta, ...)`); the same
tensor is used by the non-packed decode path and by the NPU backend
(`hardware_backend/npu/attention/ascend_gdn_backend.py`). `beta` scales the state on every step,
and the state is read, scaled and written back each token, so the rounding is not a one-off loss.

**Fix.** Store the fp32 value into the fp32 buffer:

```python
tl.store(beta_output + off, blk_beta_output, mask=mask)
```

**Relationship to #38977 (do not duplicate).** #38977 fixes a *different* pair of sites —
the sigmoid expression itself in `fused_recurrent.py` (GDN packed decode) and
`fused_recurrent_linear_replayssm.py` (KDA replay decode), both of which narrow the sigmoid
before it is used at all. This change is on the gating kernel, which computes the gate for the
extend/prefill path and stores it for another kernel to consume. The two are independent: they
touch different files and different code paths, and either can land without the other. Same
underlying defect class, same origin as vllm-project/vllm#53877.

**Test.** `test/registered/unit/layers/attention/test_gdn_gating_beta_fp32.py` — a CPU source
guard (the kernel needs a GPU, so the guard is a scan of the kernel source) plus a CPU
demonstration of the error class: a bf16 round-trip of `sigmoid` has max relative error ~3.8e-3,
well above fp32 noise. Verified red→green: the store check fails on the pre-fix source and
passes after.

```
$ python -m pytest test/registered/unit/layers/attention/test_gdn_gating_beta_fp32.py -q
3 passed
```
