# [Fix] moe: Eliminate cross-warp race in EP scatter indices

[Upstream PR](https://github.com/sgl-project/sglang/pull/44484) · state: open · merged: False

## Original PR description

## Motivation

`_fwd_kernel_ep_scatter_1` writes the entire expert prefix-sum table and immediately reloads the current expert's start. The vector store is distributed across warps, but the subsequent load has no cross-warp synchronization. A warp can read a stale start and write `m_indices` into the wrong segment, leaving incorrect expert IDs for the grouped GEMM.

The same race was reported and fixed in [vLLM #34991](https://github.com/vllm-project/vllm/pull/34991), merged on March 13, 2026 as [55d8073d066d](https://github.com/vllm-project/vllm/commit/55d8073d066dee229ea218579f3884305f27c327). That report describes sporadic `Warp Illegal Address` crashes during DeepGEMM MoE permutation.

## Modifications

Compute each program's start directly by reducing the token counts of preceding experts, then publish only that program's `expert_start_loc` entry. This removes the global-memory write/read dependency and the redundant writes from other programs while preserving the existing segment and padding layout.

Both fixes keep the offset within the CTA and write only its own table entry. vLLM extracts the current offset from a computed prefix-sum vector; this change directly sums the preceding experts' counts.
