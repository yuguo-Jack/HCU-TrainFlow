# fix(moe): keep the -1 drop sentinel out of EP local-expert mapping (masked-GEMM per-expert overflow, engine crash)

[Upstream PR](https://github.com/sgl-project/sglang/pull/43330) · state: open · merged: False

## Original PR description

Fixes #43324

## Motivation

`StandardDispatcher` translates routing ids with `local_expert_mapping[topk_ids]`. PyTorch advanced indexing wraps negative indices, so every slot carrying the `-1` drop sentinel — rows masked past `num_token_non_padded` by the top-k post-pass, e.g. CUDA-graph padded rows in speculative verify — is re-labeled to the mapping table's final entry, which is the **last local expert of the last EP rank**. The masked-count kernel (`fused_moe_dispatch_index`) has no notion of padding and counts those fake assignments as real; with graph-padded spec-verify batches that means `top_k × padded_rows` assignments on one expert (we captured `masked_m[143] = 4032` against the per-expert slab capacity `m_max = (512//256+1)×256 = 768`). The UE8M0 scatter and the varlen SiLU then iterate that count and **store out of bounds**, corrupting neighboring tensors; downstream this surfaces as NaN hidden rows and engine failure (illegal memory access) within the first few dozen requests at low batch. Regressed by #39574, which first let masked `-1` rows reach the standard EP dispatch path. See #43324 for the full incident report, the captured numbers, and the verify-width threshold analysis (fails for *any* speculative verify width; only the masked standard layout is vulnerable).

## Modifications

- `python/sglang/srt/layers/moe/token_dispatcher/standard.py`: clamp indices before the gather (so `-1` never indexes past the table) and restore the `-1` sentinel afterwards. One code point, covers every padding source (dp-max-padding, spec-verify graph padding, anything writing `-1`), zero semantic change for valid ids.
- `test/registered/unit/layers/moe/test_standard_dispatcher_padding_alias.py`: CPU regression test shaped after the captured production batch (512×8 ids, 8 valid rows, 504 fully-masked rows) asserting (a) padded slots survive translation as `-1`, (b) no expert accumulates more than the valid-row assignments, (c) legitimate last-expert routes still translate.

## Accuracy Tests

- New CPU regression test (this PR).
- Additionally validated end-to-end out of tree on the reported workload (GLM-5.3-Flash, EP2, deep_gemm masked standard layout, DFLASH verify, full decode CUDA graphs, 400 ShareGPT requests, seed 42): unpatched build died early in 5 independent attempts; with this exact translation logic the build completed 400/400 requests with zero illegal-memory-access events (618.85 tok/s output).
- The translation expression itself was micro-validated on the captured id distribution: old path piles 4040 assignments on the last expert (4032 fake + 8 legit), new path keeps only the 8 legit.

## Speed Tests and Profiling

One additional elementwise `clamp` + `where` over the top-k ids per MoE dispatch; negligible relative to dispatch. No hot-path regression expected; not separately profiled.
