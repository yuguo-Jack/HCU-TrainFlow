# [Perf] kimi-k3: Optimize single-token MoE routing and finalize

[Upstream PR](https://github.com/sgl-project/sglang/pull/45348) · state: open · merged: False

## Original PR description

Depends on #45126. This draft includes the parent changes; [view only this follow-up](https://github.com/leonardHONG/sglang/compare/0bdc4b842fa91d1d91dae08ca35046926cc1b982...15f15e4c794b90174b1ac306551e520f1e7d7729).

## Motivation

Single-token decode repeatedly prepares fixed MoE routing layouts and waits for GEMM2 before loading metadata that is already ready. This PR reduces that overhead on top of the front-sharding path in #45126.

## Modifications

- Reuse single-row mappings and padding, and write expert IDs and weights directly from the routing kernel. Keep the native FC1/FC2 kernels and autotuner.
- Prefetch routing metadata and norm weights before the PDL wait, preserving the dependency on GEMM2 data and the arithmetic order.
- Use one shared-expert AllReduce block instead of four for the eligible single-row path.

## Accuracy Tests

- Generated tokens match the baseline for all 30 measured requests, 64 warmups and 3 boundary requests in each mode.
- DFlash verification, accepted-draft and proposed-draft counts match exactly.
- TP8 M1/M8 eager execution and CUDA Graph replay with updated inputs pass 208 bitwise checks.

## Speed Tests and Profiling

Kimi-K3 on 8×B300, TP8, concurrency 1, 8192 input / 1024 output tokens. Same inputs and client, 64 warmups with 32 output tokens and 30 measured requests per mode, without profiling. The baseline already includes the front-sharding optimization in #45126.

| Mode | Baseline decode | This PR decode | Speedup | E2E latency |
| --- | ---: | ---: | ---: | ---: |
| Native decode | 125.75 tok/s | 131.49 tok/s | +4.56% | 8600.49 → 8236.88 ms |
| DFlash | 206.73 tok/s | 206.79 tok/s | +0.03% | 5423.28 → 5452.95 ms |

Native-decode E2E latency decreases by 4.23%. DFlash shows no additional speedup.

[Reproduction scripts](https://gist.github.com/leonardHONG/82b9737d8ea25336420d7c46504a5be4) include the service launcher, fixed-input generator, streaming client and timing calculation. Model, source and output paths are supplied by the user.
