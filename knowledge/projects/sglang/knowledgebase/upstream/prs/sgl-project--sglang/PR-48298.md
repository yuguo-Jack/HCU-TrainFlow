# [Fix] spec: Draw `SGLANG_SIMULATE_ACC_LEN` once per step from the server seed

[Upstream PR](https://github.com/sgl-project/sglang/pull/48298) · state: closed · merged: True

## Original PR description

- Under `SGLANG_SIMULATE_ACC_LEN`, DSpark draws each step's forced correct length and bonus seed once, in `TargetVerifyExecutor.begin_simulated_step`, from a generator seeded by the server seed. The graph path's seed buffer is filled there, `begin_sim_bonus` no longer draws, and the eager path takes the same seed. Every TP rank draws the same values whatever else reads the process RNG.
- The `simulated_bonus_sample` op, whose only job was drawing that seed from the process RNG, is removed; its one caller passes the step's seed to `simulated_bonus_sample_graph`. The top-k / top-p simulated bonus stays a `torch.multinomial` draw, on the CUDA RNG that every rank's sampled accept already shares.
- DFlash draws its forced length from the same kind of generator. It overwrites `accept_len` after the accept broadcast, so the forced length was never synced across TP ranks, even with `SGLANG_SPEC_TP_SYNC=all`.
- `simulated_acc_len_generator` moves unchanged from `eagle_post_verify_graphs.py` to `spec_utils.py`, shared by EAGLE, DFlash, and DSpark.
- Test: two ranks that consume the process RNG a different number of times stage the same draws, at both draw points (DSpark, DFlash).
- DSpark TP=2 (`Qwen/Qwen3-14B` + `deepseek-ai/dspark_qwen3_14b_block7`) with `SGLANG_SPEC_TP_SYNC=init` and `SGLANG_SIMULATE_ACC_LEN=3`: 512 sampled requests, accept length 3.00, no hang.

No behavior change outside `SGLANG_SIMULATE_ACC_LEN`; with it set, the simulated lengths and temperature-only bonus seeds keep their distribution but follow a different sequence.
