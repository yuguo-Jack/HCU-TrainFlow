# [Refactor] [AMD] hicache: Isolate HIP host allocation

[Upstream PR](https://github.com/sgl-project/sglang/pull/42991) · state: open · merged: False

## Original PR description

## Summary

- move the ROCm-specific HiCache GTT allocation helpers out of the shared `pool_host/common.py` module
- add a dedicated `pool_host/hip_host_allocator.py` implementation
- keep only a lazy HIP dispatch and generic registration bookkeeping in `common.py`
- preserve the existing allocation, lifetime, error, and fallback behavior

## Stack

This is stacked on #42553 and follows the non-blocking review suggestion in https://github.com/sgl-project/sglang/pull/42553#pullrequestreview-5441052639.

Only commit `7b9b3ae4ac` is new in this follow-up. The PR is intentionally kept as Draft until #42553 merges so the draft gate prevents duplicate heavy CI. After the parent merges, the visible diff will reduce to this refactor.

## Behavior preserved

- exact-size `hipHostMalloc` allocation for GTT-backed HiCache pools
- last-view `hipHostFree` lifetime via `weakref.finalize`
- no fallback to USERPTR on GTT exhaustion
- custom/storage allocators remain on their existing paths
- GTT buffers remain marked as not host-registered, so destroy does not call `cudaHostUnregister`

## Validation

- `test_hicache_host_register.py`: 15/15 passed
- neighboring host-pool suites: 21 passed, 3 existing platform-specific skips
- isort 7.0.0, ruff 0.15.1 lint, and ruff-format passed
- real ROCm smoke with `HSA_USERPTR_FOR_PAGED_MEM=0`: `hipHostMalloc`, tensor construction, registration metadata, and `hipHostFree` completed successfully
