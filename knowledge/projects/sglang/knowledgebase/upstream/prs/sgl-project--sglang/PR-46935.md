# [Fix] hicache: Look up L3 below a device-only anchor under write-back

[Upstream PR](https://github.com/sgl-project/sglang/pull/46935) · state: open · merged: False

## Original PR description

## Motivation

`Scheduler._prefetch_kvcache` looks up L3 only from a backed-up anchor or the root (plus buffer mode), assuming an unbacked anchor means a storage miss. That holds for write-through, whose host copy is contiguous from the root, but not for `write_back`: a prefix stays on device with no host copy while another writer, e.g. a PD decode offloading its output KV, has stored the continuation. The prefill never looks it up and recomputes it.

End to end (PD with decode KV offload and a `write_back` prefill, window 512, page 128), the second turn's prefill reuse of the 256 tokens the decode wrote: **0 before, 256 after**. Run on a fork carrying this change.

## Modifications

The tree already keeps a host-only suffix below a device-only anchor under `write_back`, so the lookup opens there:

```diff
                 or (
-                    buffer_mode
+                    (buffer_mode or tree_cache.is_write_back)
                     and tree_cache.get_last_hash_value(last_host_node) is not None
                 )
```

Cost: one existence query for a `write_back` request whose deepest match is device-only and whose rest reaches the prefetch threshold. Write-through and buffer mode are unchanged.
