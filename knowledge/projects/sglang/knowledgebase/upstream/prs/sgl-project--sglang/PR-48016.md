## Motivation

A pool with several sliding-window sub-pools reported one window: pool stats, scheduler stats and the Prometheus series each had a single `swa_*` slot, filled from whichever window was called "swa". Further windows went unreported, and the bottleneck usage and busy log ignored them.

## Modifications

- `managers/scheduler_components/pool_stats_observer.py`: `SubPoolUsage` carries a family (`full`, `window`, `mamba`) and a label; `PoolStats.windows` lists one `WindowPoolStats` per window in the prefix tree's window order, each with evictable tokens read from its own tree slot. `token_usage`, `num_used_tokens` and the prefill/decode log lines cover every window.
- `observability/metrics_collector.py`, `metrics_reporter.py`: `SchedulerStats` holds per-window maps, published with a `window` label.
- `managers/scheduler_components/memory_usage.py`, `rust/sglang-server/src/api_server/http/info.rs`, `src/message/info.rs`: server info reports `memory_usage.token_capacity_window`, a map from window name to its capacity.
- `invariant_checker.py`: the busy and idle leak checks conserve the tree's first window (further windows are checked by a later PR in this stack).
- Every window is named the way a unified pool names its window sub-pool (`window_<length>`, or `window` when the length is unstated); a static pool's single window gets the same name from its window length.
- Tests: `test/registered/unit/observability/test_window_pool_metrics.py` (new), updates to `test_prealloc_token_usage.py`, `test_stat_loggers_di.py`, `test_forward_pass_metrics.py`, `test_invariant_checker.py`, `test/registered/core/test_srt_endpoint.py`.

**Behavior change (public metrics and API, no compatibility alias):**
- Removed: `sglang:swa_token_usage`, `sglang:swa_available_tokens`, `sglang:swa_evictable_tokens`, `sglang:swa_used_tokens`, `sglang:prealloc_swa_token_usage`, `sglang:max_total_num_tokens_swa`.
- Added, each with a `window` label (`window="window_<len>"`): `sglang:window_token_usage`, `sglang:window_available_tokens`, `sglang:window_evictable_tokens`, `sglang:window_used_tokens`, `sglang:prealloc_window_token_usage`, `sglang:max_total_num_tokens_window`.
- `/server_info` `memory_usage.token_capacity_swa` is replaced by `memory_usage.token_capacity_window` (a map by window name).
- This applies to static SWA pools as well as unified memory; dashboards and alerts reading the `swa` series need updating.
