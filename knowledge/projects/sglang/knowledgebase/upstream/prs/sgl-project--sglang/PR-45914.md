# [Feat] rust-server: Let a multimodal processor finalize item layout after caller hashes

[Upstream PR](https://github.com/sgl-project/sglang/pull/45914) · state: closed · merged: True

## Original PR description

## Motivation

In the Rust frontend's multimodal worker, `MmProcessor::process` returns the encoded items with their hashes, and the worker then replaces those hashes with the caller-supplied `mm_hashes` before it builds the ring buffers and publishes the features.

A processor that derives further items from a parent item, for example one that splits a long input into fixed-size windows whose cache identities and token spans depend on the parent's final hash, has no step at which the caller overrides are already applied and the buffers are not yet built. It can only recompute the layout before the overrides, which the overrides then invalidate.

## Modifications

- `MmProcessor` gains `finalize(&self, entry: &mut MmEncodedEntry) -> Result<(), String>`, a default no-op.
- `process` calls it after `apply_caller_hashes` and before `make_buffers`, then validates the entry again against the expanded input length, so a finalizer that produces an out-of-range span is rejected like any other malformed result.
- The built-in processor does not override it, so its behaviour and the existing tests are unchanged.
- Test: `finalization_runs_after_caller_hashes_and_is_validated` installs a processor whose finalizer reads the caller hash, rewrites it, and appends a derived item. It checks that the derived item reaches the ring with its own `mm.feature.1` buffer and metadata entry, and that the same finalizer with an out-of-range span fails the request.
