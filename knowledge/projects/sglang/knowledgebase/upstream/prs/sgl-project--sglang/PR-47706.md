# [Perf] rerank: Score Qwen3-VL reranker candidates concurrently

[Upstream PR](https://github.com/sgl-project/sglang/pull/47706) · state: open · merged: False

## Original PR description

## Motivation

`OpenAIServingRerank._handle_vl_reranker_request` (the Qwen3-VL reranker path) scores documents in a serial loop: it builds a `GenerateReqInput` for one document, awaits it, then moves to the next. The scheduler never sees more than one document of a request at a time, so latency grows linearly with the number of documents (~40 ms per document in our deployment, see below). The text Qwen3 reranker path in the same file already submits all pairs in one batch.

Each per-document request also sets `logprob_start_len=0` with `top_logprobs_num=50`, which asks the engine to compute and return top-50 logprobs for every prompt position. `_extract_score_from_logprobs` only reads `output_top_logprobs[0]`, so the input-position logprobs are discarded.

## Modifications

`python/sglang/srt/entrypoints/openai/serving_rerank.py`:
- Move the per-document body into a local `async def _score_one(doc)` and run all documents with `asyncio.gather`, so the scheduler can batch them. `gather` preserves input order, so `scores[i]` still corresponds to `request.documents[i]`.
- Set `logprob_start_len=-1` so only the output token's logprobs are computed.
- Add `import asyncio`.

No public API change. Prompt rendering, `top_logprobs_num`, and the scoring formula are unchanged.

`test/registered/unit/entrypoints/openai/test_serving_rerank_vl.py` (new, registered CPU test):
- All documents of a request are in flight at the same time (a serial implementation times out instead of hanging).
- Scores still map to input order when requests finish in reverse order.
- Per-document requests use `logprob_start_len=-1`.

The first and third tests fail on `main`. With this change, the new tests and the existing `test/registered/prefill_only/test_serving_rerank.py` pass (16 passed):

```bash
CUDA_VISIBLE_DEVICES=99 python -m pytest -q \
  test/registered/unit/entrypoints/openai/test_serving_rerank_vl.py \
  test/registered/prefill_only/test_serving_rerank.py
```

`CUDA_VISIBLE_DEVICES=99` hides the GPU; an empty value currently breaks the import of `sglang.test.test_utils`.

## Accuracy Tests

Scores come from the same yes/no logprobs of the first output token. Skipping prompt logprobs does not change the label logprob gap: for a probe prompt, `logprob_start_len=0` and `-1` return yes/no logprobs of -7.748/-9.748 and -7.700/-9.700, so `p_yes / (p_yes + p_no)` is identical. On a 16-document request, the largest absolute score difference against the serial implementation is 0.012. This comes from batching changing the GPU reduction order in bf16, not from a logic change. The ranking is identical apart from the order of exact ties.

## Speed Tests and Profiling

Qwen3-VL-Reranker-2B, 1x NVIDIA L20 (shared with two other SGLang instances; reranker KV capped at 8000 tokens), `/v1/rerank`, ~60-character Chinese documents, best of 3:

| Documents | Before | After |
|---|---|---|
| 1 | 42.3 ms | 33.1 ms |
| 4 | 161.8 ms | 63.0 ms |
| 8 | 321.0 ms | 65.6 ms |
| 16 | 644.4 ms | 98.5 ms |

"Before" was measured on v0.5.22 and "after" on v0.5.23 with this patch; `serving_rerank.py` in v0.5.23 is identical to `main`, and `_handle_vl_reranker_request` is unchanged since v0.5.22.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Cancel sibling scoring tasks when one document fails**

If one document fails—for example, because its prompt exceeds the model's context length—`asyncio.gather` propagates the exception without cancelling the other `_score_one` tasks, and the outer handler immediately returns an error response. The remaining tasks can continue multimodal preprocessing and consume scheduler/GPU capacity for results that can no longer be returned; `generate_request` only cleans up the failing task's request state. Keep task handles and cancel and await unfinished siblings on failure, as `TokenizerManager._collect_batch_responses` already does.
