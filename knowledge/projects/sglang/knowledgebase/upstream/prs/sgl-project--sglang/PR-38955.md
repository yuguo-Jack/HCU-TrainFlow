# [Perf] pd: Stage decode-side KV preallocation lengths through pinned memory

[Upstream PR](https://github.com/sgl-project/sglang/pull/38955) · state: closed · merged: True

## Original PR description

- `alloc_for_decode_prealloc`, `alloc_for_decode_prealloc_hisparse` and `SWATokenToKVPoolAllocator.alloc_extend_swa_tail` copy their device length and `last_loc` arguments with `async_h2d` instead of `torch.tensor(..., device=...)`. A pageable copy runs `cudaStreamSynchronize` on the scheduler stream, which under overlap parks the host until the in-flight forward drains.
- `test_decode_prealloc_no_host_sync.py` runs the paged, SWA-tail and HiSparse prealloc paths under `torch.cuda.set_sync_debug_mode("error")`.

No behavior change: the copied values, dtypes and devices are identical.

Verification: the new test fails on main (all three paths synchronize) and passes with this change on an H200.

Follows #38159.
