# [diffusion] Qwen-Image-2.1: skip QKV packing while layers are offloaded

[Upstream PR](https://github.com/sgl-project/sglang/pull/43576) · state: closed · merged: True

## Original PR description

## Motivation

`--enable-torch-compile true` on Qwen-Image-2.1, with the default `--offload-during-compile`, dies at startup:

```
qwen_image21.py, in _apply -> pack_qkv_weights -> packed_qkv_weight
    rows, cols = q.shape
ValueError: not enough values to unpack (expected 2, got 1)
```

Offload-during-compile puts the DiT under layerwise offload, which swaps every offloaded weight for one shared `torch.empty((1,))` placeholder. `QwenImage21Attention._apply` re-runs `pack_qkv_weights` on every `.to()`, and `packed_qkv_weight` unpacked that placeholder as `[rows, cols]`. `pack_qkv_weights`' own eligibility check would also have accepted three identical 1-D placeholders and re-pointed them at a fresh buffer, detaching them from the offload manager.

## Modifications

Both functions only act on 2-D weights. While the layers are offloaded, packing is skipped; the next `_apply` after the weights return re-packs them, as before.

## Accuracy Tests

No change once the weights are resident (the packed path is unchanged).

## Speed Tests and Profiling

GB300, `sglang generate --model-path Qwen/Qwen-Image-2.1 --num-gpus 2 --ulysses-degree 2 --performance-mode speed --attention-backend fa --enable-torch-compile true`: main fails with the error above; with this PR the run completes (`Compiling transformer with mode: max-autotune-no-cudagraphs`, image written).
