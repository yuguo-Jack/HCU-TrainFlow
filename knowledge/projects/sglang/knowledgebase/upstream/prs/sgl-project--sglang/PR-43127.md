> Part 2, based on #41794. Review `45657adf5e` (633 lines). Compare: https://github.com/yuychang/sglang/compare/k3-pr1-quark-weights...up/b3-mla-gate-q-cache


## AITER prerequisites

None beyond AITER main. The fused launch is `aiter.fused_qk_rope_concat_and_cache_mla`, which main already exports, including `q_scale`.

## Motivation

Kimi-K3's MLA has no RoPE, but decode still builds the query (`q_nope` absorbed + `q_pe`) and writes the latent KV cache as separate launches before attention.

## Modifications

**`45657adf5e` fuse the ROCm MLA decode Q build and latent KV cache write**
- Add an AITER adapter that writes the identity-RoPE MLA query and the latent KV cache in one launch on gfx950.
- Call it from the ROCm MLA decode and target-verify path through a mixin hook that other MLA models leave as a no-op.
- Fuse only for Gluon and Triton decode, which take the 12-head BF16 Q as written; ASM decode keeps the split chain.
- Write Q into a persistent grow-and-retain buffer so CUDA graph replays reuse the same storage.
- Pass all-zero positions to both kernels so no read leaves the one-row identity cos/sin tables.
- Fall back to the Triton fused rope/cache kernel when the AITER op or gfx950 is missing.
- Keep Gluon MLA decode on BF16 Q only and gate the path behind SGLANG_OPT_HIP_K3_MLA_Q_CACHE_FUSION, off by default.
- Add numerical tests for the adapter and document the switch.

Switch: `SGLANG_OPT_HIP_K3_MLA_Q_CACHE_FUSION`. Everything is ROCm only; CUDA and other checkpoints keep the existing path.
