# fix(quantization): handle unquantized MTP/NEXTN draft layers in compressed-tensors

[Upstream PR](https://github.com/sgl-project/sglang/pull/40002) · state: closed · merged: False

## Original PR description

## Motivation

Resolves #38574.

When serving a `compressed-tensors` checkpoint with `--speculative-algorithm NEXTN` (such as Qwen3-Next hybrid MoE models exported via `llm-compressor`), model construction crashes with `NotImplementedError: No compressed-tensors compatible scheme was found.` inside `CompressedTensorsConfig._get_scheme_from_parts`.

1. `llm-compressor` checkpoints emit generic module-type targets (e.g. `targets: ["Linear"]`) for the main decoder layers and omit the multi-token prediction (MTP/NEXTN) draft head from both `targets` and `ignore` because the MTP head is outside the Hugging Face model graph traced during quantization.
2. When SGLang constructs the NEXTN draft model through the same `CompressedTensorsConfig`, its dense `Linear` and `FusedMoE` layers match `"Linear"` by module class name, causing `_get_scheme_from_parts` to attempt resolving a quantized scheme (such as W4AFP8) that does not exist for dense linear layers.
3. Furthermore, when `_get_scheme_from_parts` raises `NotImplementedError`, the exception message does not include `layer_name` or mention `quantization_config.ignore`.

## Modifications

- **`python/sglang/srt/layers/quantization/compressed_tensors/utils.py`**:
  - Added `is_mtp_layer_name(layer_name)` to detect MTP/NEXTN draft module prefixes (`mtp.`, `model.mtp.`, `mtp_layers.`, `mtp_block.`, `.mtp.`, `.mtp_layers.`, `.mtp_block.`).
  - Added `find_matched_target_by_name(layer_name, targets, fused_mapping)` to match layers strictly by explicit layer name or regex pattern rather than falling back to generic module class names.
- **`python/sglang/srt/layers/quantization/compressed_tensors/compressed_tensors.py`**:
  - Updated `get_scheme_dict` so that MTP/NEXTN draft layers only resolve a quantization scheme when explicitly targeted by layer name or regex pattern in `config_groups`. Unmentioned MTP draft layers return `None` and fall back to `UnquantizedLinearMethod` / `UnquantizedFusedMoEMethod`, consistent with how `get_lm_head_scheme` handles `lm_head`.
  - Updated `_get_scheme_from_parts` to accept `layer_name` and include both the layer name and a hint pointing to `quantization_config.ignore` (e.g. `'re:mtp\\..*'`) in `NotImplementedError`.
- **`test/registered/unit/layers/quantization/test_compressed_tensors_mtp.py`**:
  - Added unit tests verifying unmentioned MTP `Linear` and `FusedMoE` fallback to unquantized, explicit regex target resolution for MTP layers, and the improved `NotImplementedError` message.
