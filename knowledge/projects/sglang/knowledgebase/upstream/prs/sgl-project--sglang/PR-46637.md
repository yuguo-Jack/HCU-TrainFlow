# [Feat] rust/grpc: Report the node's Rust listeners in api.v1 discovery

[Upstream PR](https://github.com/sgl-project/sglang/pull/46637) · state: open · merged: False

## Original PR description

## Motivation

With `SGLANG_RUST_SERVER=1`, each DP-group leader embeds its own listener, which only feeds its own scheduler. A client that runs once per node needs a way to find all listeners on the node.

## Modifications

- api.v1: new `NodeRustListener` message and `DeploymentInfo.node_listeners` (proto, Python types, generated Rust, JSON parity fixture).
- `rust_server/config.py`: `_node_listeners` builds the table, in port-offset order, so every listener on the node reports the same one. The Rust server forwards it in `deployment_info`.
- Tests: node-listener table cases for attention DP and plain DP, and the DP fields in the Rust server extension test fixture.

## Dependencies

The `plain-dp` test case needs the plain-DP ports PR (#45996), since the table lists plain-DP replicas at offsets 0..dp_size-1. Merge that first, or the case fails until it lands. The attention-DP cases pass on their own. Otherwise independent of the sidecar and attention-DP idle PRs.
