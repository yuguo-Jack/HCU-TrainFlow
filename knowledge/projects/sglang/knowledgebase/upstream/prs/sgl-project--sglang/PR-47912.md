# [Perf] [AMD] mxfp8: Split K in the gfx950 dot_scaled GEMM for underfilled decode grids

[Upstream PR](https://github.com/sgl-project/sglang/pull/47912) · state: open · merged: False

## Original PR description

## Motivation

At decode batch sizes the gfx950 MXFP8 `dot_scaled` dense GEMM launches only `cdiv(M, 64) * cdiv(N, BLOCK_N)` workgroups (20 for MiniMax-M3 TP8 qkv on a 256-CU MI355X), each walking all of K, so this PR splits K across extra programs when that grid underfills the CUs and K is long, then reduces the fp32 partials.

This kernel is the default dense path for MXFP8 checkpoints on gfx950. With the MiniMax-M3-MXFP8 MI355X cookbook recipe (TP8, `--quantization mxfp8`), qkv (1280x6144) and the dense-layer gate_up (3072x6144) split; o_proj and dense down (K = 1024 / 1536) are unchanged. Online `--quantization mxfp8` reaches it too; DeepSeek-V4.1 only with `--fp8-gemm-backend triton`. #44497 (draft) adds an opt-in FlyDSL route for seven TP4 shapes under `--fp8-gemm-backend=aiter` and falls back to this kernel for all other shapes, so the two compose.

## Modifications

- `_mxfp8_linear_split_k_kernel`: the existing kernel, with program `pid_k` accumulating every `SPLIT_K`-th k-tile into an fp32 `[SPLIT_K, M, N]` buffer; the caller sums it with `sum(0)` (no atomics, so the output is run-to-run deterministic).
- `_mxfp8_linear_split_k`: split only when `cdiv(M, 64) * cdiv(N, BLOCK_N) < num_CUs` and K >= 4096; target ~4 workgroups per CU, keep >= 4 k-tiles per program, cap at 32. Every other shape runs the single-pass kernel as before. Batch-invariant mode (`--enable-deterministic-inference`) never splits.
- Tests: a CPU test of the split decision in `test_mxfp8_amd_gfx95.py` (fails on main; also fails with the K floor, the k-tile cap, the M term of the grid, the empty-grid guard or the batch-invariant guard removed), and a `dot_scaled` linear case whose 33 k-tiles split unevenly in `test_minimax_m3_mxfp8.py` (gfx950, not run here).

## Accuracy Tests

Kernel output against main over the 168 benchmark cells below: the 80 non-split cells are bit-identical; 86 of the 88 split cells are bit-identical and 2 differ by bf16 rounding, with unchanged max error against an fp32 reference.

## Speed Tests and Profiling

`_run_mxfp8_linear_kernel` device time on MI355X (gfx950, 256 CUs), main@d9521615b7 vs this PR (the file is unchanged on current main). HIP graph, weights rotated over 512 MiB for a cold L2, two blocks of four runs per arm in opposite order, first run of each block dropped, median of the other three:

| shape (N x K) | M | split | main (us) | this PR (us) | speedup |
|---|---:|---:|---:|---:|---:|
| M3 TP8 qkv 1280x6144 | 1 | 8 | 26.99 | 10.92 | 2.47x |
| | 64 | 8 | 28.16 | 12.47 | 2.26x |
| | 256 | 8 | 28.81 | 18.40 | 1.57x |
| M3 TP8 gate_up 3072x6144 | 1 | 8 | 34.45 | 13.27 | 2.60x |
| | 64 | 8 | 35.67 | 16.90 | 2.11x |
| | 256 | 4 | 37.84 | 29.64 | 1.28x |
| M3 TP1 dense down 6144x12288 | 1 | 8 | 79.37 | 24.54 | 3.23x |
| Qwen3-8B down 4096x12288 | 1 | 16 | 78.41 | 19.94 | 3.93x |

Over 14 shapes x 12 M values (1 to 512): the 88 split cells have a median speedup of 2.24x (+124 %), minimum +8.7 % (3072x6144, M = 320); M3 TP8 qkv and gate_up at M <= 256 have a median of +127.7 %. The 80 non-split cells run the same code, median -0.07 %. Within-arm spread is 0.2-0.4 %.
