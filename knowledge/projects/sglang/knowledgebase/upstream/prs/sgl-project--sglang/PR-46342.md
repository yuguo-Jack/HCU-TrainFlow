# [Feat] logprobs: Support temperature-scaled input token scores

[Upstream PR](https://github.com/sgl-project/sglang/pull/46342) · state: open · merged: False

## Original PR description

## Motivation

Off-policy distillation needs teacher scores at the rollout temperature. SGLang currently scores input tokens at temperature 1, and a single token's logprob is not enough to recover the score at another temperature. This is needed by THUDM/slime#2325.

This continues my earlier #36213, which was closed by the idle-PR bot. The branch is now rebased onto current main; the original commits and authorship are preserved.

## Modifications

Add `input_logprob_temperature` to the Python Engine and `/generate`. It accepts a positive finite temperature per request and defaults to 1. Input token, top-k, and selected-token scores use that temperature; decode sampling keeps its own temperature. The parameter is documented in the native API reference.

The default path avoids the extra temperature tensor and division. The tokenized request field stays at the end of the defaulted wire fields, preserving the existing Rust positional prefix.

## Accuracy Tests

On the refreshed branch, seven CPU cases from `test_logprob_fast_input.py` passed in an isolated source-loading harness. They cover fast/reference agreement, explicit temperature-scaled math, unchanged sampling logits, mixed request temperatures, and multi-item scoring. Seven CUDA cases were skipped. This harness exercises the actual processor definitions but excludes GPU/runtime imports; it is not a full registered-suite run.

The earlier branch reported 101 passed, 9 skipped, and 22 subtests across the four focused suites. Those full suites have not been rerun on this refresh. GPU accuracy and graph-pool behavior still need CI.

Changed-file pre-commit checks and `git diff --check` pass.

## Speed Tests and Profiling

Not run. Non-unit temperatures add division over input-scoring rows; no speedup is claimed.
