# [Perf] srt: Replace torch.nonzero() with torch.where() for index extraction (#9889)

[Upstream PR](https://github.com/sgl-project/sglang/pull/46866) · state: open · merged: False

## Original PR description

Fixes #9889

Replaces `torch.nonzero(mask, as_tuple=False).flatten()` with `torch.where(mask)[0]` in 10 files: attention-mask index extraction, expert-assignment masks, KV-pool valid-index selection, and multimodal sequence indexing.

Why: `torch.nonzero()` on a CUDA tensor forces a host-device synchronization (it must discover the count on the host before allocating). `torch.where()` on a boolean tensor follows the same kernel path without the explicit sync point, and the resulting form matches patterns already used elsewhere in the codebase (e.g. `srt/managers/hisparse_coordinator.py`, `multimodal/processors/glm_image.py`).

Scope: mechanical, one line per site. No control flow, dtype, or semantics changes — `torch.where(mask)[0]` and `torch.nonzero(mask, as_tuple=True)[0]` return identical indices. Non-CUDA paths (`configs/janus_pro.py`, NPU backend) are unaffected functionally.

Validation:
- All 10 changed files parse clean (`ast.parse`).
- Rebased onto current `main` (de26bb16a9); no conflicts.
- No SM/HW-dependent behavior changed, so no device-specific test is required beyond existing CI.
