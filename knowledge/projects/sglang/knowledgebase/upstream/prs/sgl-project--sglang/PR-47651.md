# [Perf] kda: Batch strided FlashInfer prefill input copies

[Upstream PR](https://github.com/sgl-project/sglang/pull/47651) · state: closed · merged: True

## Original PR description

## Motivation

Kimi-K3's token-major prefill convolution leaves strided Q/K/V views, and its merged gate projection leaves a strided beta view. FlashInfer's KDA wrapper materializes these inputs with separate copies. Batch those required copies into one Triton launch without changing KDA arithmetic, gates, state precision, or checkpoint handling.

This integrates the measured PP8 prototype into upstream `main`. Full-model serving validation now passes for these production changes on the common upstream `main` base `592754fc5e`, with FlashInfer 0.7.2; the standalone and repeated combined results are reported below. Real GPU operator tests pass on both FlashInfer 0.7.1 and the pinned 0.7.2.

### Relationship to sgl-project/sglang#47451

The optimizations overlap on the Q/K/V materialization cost, but use different approaches:

- #47451 changes the convolution producer to write contiguous Q/K/V groups, eliminating those three copies. It also covers the FlashInfer prefill-graph producer path.
- This PR leaves the producer layout alone and combines outstanding consumer-side copies, including beta. It covers both `FlashInferKDAPrefillKernel.extend` and `FlashInferKDAPrefillGraph.run` through the same helper.
- Contiguous inputs are returned unchanged. When fewer than two inputs require copying (e.g. grouped Q/K/V plus only strided beta), the ordinary contiguous path is retained. There is no redundant Q/K/V copy or extra fused-copy launch in that case.
- Their standalone speedups must **not** be added. Prefer the producer-layout solution where applicable; this is a separately reviewable alternative for remaining token-major inputs, not a second claimed gain on top of #47451.

## Modifications

- Add a bit-preserving multi-input copy kernel under `kernels/ops/attention` and use it at the FlashInfer KDA input boundary.
- Keep contiguous tensors aliased, validate device/dtype/indexing bounds, and fall back to PyTorch for unsupported inputs or autograd.
- Preserve input slicing and all existing KDA computation arguments. No new environment variable or CLI option.
- Add registered GPU coverage for the real 16K/96-head K3 layout, short/tail/empty shapes, BF16/FP32 bit patterns, already-grouped QKV, CUDA Graph replay, and real FlashInfer outputs/state.

## Accuracy Tests

On an idle B300/B30Z (SM103), PyTorch 2.14.1+cu130, separately using FlashInfer 0.7.1 and 0.7.2:

- **5 GPU tests passed on each version**, including actual Triton execution at `[1, 16384, 96, 128]` and CUDA Graph replay with changed inputs.
- Raw-bit comparisons cover NaN payloads, infinities, subnormals, and signed zero.
- Real FlashInfer KDA calls on strided inputs match contiguous-reference outputs and recurrent state exactly, in eager mode and through the production graph adapter replayed with updated inputs. Warmup and capture use the same stream, as required by the FlashInfer workspace.
- The candidate kernel and wrapper were loaded from this branch into the existing GPU environment; no installed source was modified. FlashInfer 0.7.2 was tested in an isolated wheel overlay without bypassing its version checks.
- Ruff, isort, AST parsing, registered-test lint, and `git diff --check` passed.

The current six full-service runs each pass 12 fixed greedy output checks covering input lengths 1,024 / 16,383 / 16,384 / 16,385 / 32,768 / 65,536, each repeated twice. All 60 comparisons against A1 match output token IDs and input SHA256 hashes. An additional eight C4 concurrent fixed-input checks match between A2 and B2. These are finite output-regression checks, not logits-level equality or a full task-accuracy benchmark.

## Speed Tests and Profiling

### Full serving validation of the upstream integration (2026-11-01)

Tested production changes from #47651 (`7933473906e`) and #47653 (`34238f31a5d`) on the same upstream `main` base `592754fc5e`, using FlashInfer 0.7.2 for every arm. Kimi-K3, one 8-GPU B300/B30Z, TP1/PP8/EP1, chunk 16,384, pipeline async depth 1, client C4, ISL 65,536 / OSL 1. CUDA Graphs and radix caching disabled; model precision and all serving settings held fixed. Each formal run contains 128 requests after a separate 8-request warmup. Formal measurements exclude profiler/diagnostic requests and prototype hooks.

Each run uses an independent autotune cache cloned from the same baseline startup cache. Baseline/KDA caches contain no 16K MoE seed; MoE/combined caches contain the FlashInfer 0.7.2 `(128, 4)` record on all eight PP ranks. Separate post-benchmark Torch GPU traces of all eight PP ranks confirm the actual production paths: 1,104 KDA input-copy kernels become 276 pack kernels, and all 736 MoE GEMMs change token tile 192 to 128. These C1 diagnostic traces verify execution paths; their timings are not used as C4 serving measurements.
