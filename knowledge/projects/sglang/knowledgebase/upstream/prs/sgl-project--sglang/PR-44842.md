# [Perf] deepseek_v4: run FlashInfer autotune for block-FP8 models served as MXFP8

[Upstream PR](https://github.com/sgl-project/sglang/pull/44842) · state: closed · merged: True

## Original PR description

## Motivation

Torch-profiler trace of DeepSeek-V4.1-Flash DEP2 prefill on GB300 (MegaAttention, MegaMoE, DSpark, 16K-token prefill budget per rank), one 16K-token cold chunk per rank, rank 0:

| Dense MXFP8 GEMM (`flashinfer_mm_mxfp8` → CuTe-DSL `dense_blockscaled_gemm_sm100`) | |
|---|---:|
| Launches per step | 210 (130 after #44837 removes the shared-expert MLP) |
| Per launch | 221 µs |
| Total per step | 46.5 ms of a 322 ms step |
| Shapes at M=16,384 | fused wqkv_a N=1792 K=5120; wq_b N=32768 K=1280; wo_b N=5120 K=8192 |

Every one of these launches runs on FlashInfer's untuned fallback tactic: the server log has no autotune pass at all, and `Fp8LinearMethod.apply` keeps `pin_tactic=True` for block-FP8-as-MXFP8 layers until the prefill autotune hook sets `mxfp8_prefill_autotune_min_tokens`, which never happens.

## Why

`should_run_flashinfer_autotune` treats FP8 dense GEMMs as tunable only for `quantization == "mxfp8"` (and modelopt per-tensor FP8). DeepSeek-V4.1 checkpoints are block-FP8 `[32, 32]` with `ue8m0` scales, which `Fp8LinearMethod` serves through the MXFP8 view on FlashInfer CuTe-DSL, the same tunable `mm_mxfp8` op. The model already has `autotune_prefill_kernels` / `wants_prefill_autotune` (from #38798) to tune exactly those GEMMs at the prefill token ceiling, but it is only reached from the gated autotune pass, so it never ran.

## Modifications

- `should_run_flashinfer_autotune`: also return True when a resident FP8 linear serves block-FP8 as MXFP8 on a FlashInfer CuTe-DSL/CUTLASS backend (`_model_serves_block_fp8_as_mxfp8_on_flashinfer`). The existing decode-shaped pass and the DeepSeek-V4.1 prefill hook then run and persist tactics under `SGLANG_CACHE_DIR/flashinfer/autotune/...` exactly as for `mxfp8` models, so restarts stay fast.
- Drops the stale "SGLang temporarily skips mxfp8_gemm by default due to an IMA" help text on `--flashinfer-autotune-skip-ops`; `FLASHINFER_AUTOTUNE_WORKAROUND_SKIPS` has been empty since #33962.
- Numerics: tuned tactics change only the GEMM tile/cluster schedule. Batch-invariant and deterministic modes keep the pinned tactic as before (`pin_tactic` override in `Fp8LinearMethod.apply` is unchanged).
