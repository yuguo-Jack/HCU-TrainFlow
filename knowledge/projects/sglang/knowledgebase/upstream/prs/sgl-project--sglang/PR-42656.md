# [Fix] lora: Reject per-module rank and alpha overrides in PEFT adapters

[Upstream PR](https://github.com/sgl-project/sglang/pull/42656) · state: open · merged: False

## Original PR description

## Motivation

A PEFT `adapter_config.json` can carry `rank_pattern` and `alpha_pattern`, which override `r` and `lora_alpha` for the modules they match. LoRA serving reads neither field. It applies `config.r` and one `lora_alpha / r` scaling to every module of an adapter, so these adapters load and are then served with the wrong math:

* `alpha_pattern`: the matched modules get the adapter-wide scaling. For `r=2, lora_alpha=2, alpha_pattern={"o_proj": 32}` PEFT scales `o_proj` by 16.0 and SGLang by 1.0.
* `rank_pattern`: the matched modules keep weights of a rank other than `config.r`, which is the rank the memory pool slices its buffers by. The load succeeds, and the copy into the pool fails later, when the adapter is first used: `AssertionError: LoRA buffer shape torch.Size([2, 4]) does not match weight shape torch.Size([4, 4])`.

## Modifications

`LoRAConfig` keeps the pattern entries that change a value, and `LoRAManager.validate_new_adapter` rejects an adapter that has any, before configuration is stored or weights are loaded. This is the check that already rejects DoRA adapters, so initial, file and tensor loads are all covered. Patterns that are absent, empty, null, or that only repeat the adapter-wide value are accepted as before. The check reads the config only, because module names are not known at admission. An entry that differs from the adapter-wide value is therefore rejected even if it matches no adapted module, and the message names the entry so it can be dropped.

Real adapter loaders with saved safetensors and tensor input, `r=2, lora_alpha=2`, same result on macOS arm64 and on Linux x86_64 with CUDA torch:

| Adapter | Before | After |
| --- | --- | --- |
| `alpha_pattern={"o_proj": 32}` | Loaded, scaling 1.0 for every module | Rejected, configuration and registry unchanged |
| `rank_pattern={"o_proj": 4}` | Loaded, then `load_lora_weight_to_buffer` asserts on the first use | Rejected, configuration and registry unchanged |
| `rank_pattern={"q_proj": 4}` | `Sizes of tensors must match except in dimension 0` | Rejected with the message below |
| no pattern, or `{}` | Loaded | Loaded, identical matrices |

```
Failed to load my-adapter because LoRA serving currently doesn't support per-module rank or alpha overrides (alpha_pattern for ['o_proj']). Use an adapter with a single r and lora_alpha.
```

Tests: `test/registered/unit/lora/test_lora_pattern_validation.py` covers the file, tensor and initial load routes, the unchanged loading state after a rejection, and the accepted uniform cases. It fails on `main` and passes with this change. `test/registered/unit/lora` passes 112 tests before and after on an L40S node with the pinned dependencies.
