# [Fix] [NPU] Support bounded encoder-decoder SDPA graphs

[Upstream PR](https://github.com/sgl-project/sglang/pull/48102) · state: open · merged: False

## Original PR description

## Motivation

Compiled encoder-decoder decode on Ascend reaches per-request scalar slicing in native SDPA, which cannot be captured with fullgraph compilation. This prevents Whisper from using its normal attention interface while retaining NPU decoder graph replay.

This companion to [sglang-omni#2277](https://github.com/sgl-project/sglang-omni/pull/2277) fixes the shared backend instead of adding a model-specific attention helper. It targets **release/v0.5.22**, the measured baseline baa9befa381511cd4d56f83980951e5a45fffc6d. The submitted head f4e69345c9926734545bcca907926735ce6de72f is the exact hardware-tested source, without rebasing onto untested main.

## Modifications

- Add a tensor-only encoder-decoder graph path with separate self/cross address ranges, valid-length masks, same-step self K/V writes and existing cross-cache reads.
- Bound the fixed dense read span using existing max_target_positions/max_source_positions configuration. The measured Whisper request table is 1992 tokens wide; its self/cross bounds are 448/1500. The global KV pool and token-to-slot mapping are unchanged.
- Check CPU sequence lengths before replay. Over-bound requests or missing length metadata use the complete eager path, preventing silent KV truncation.
- Enable the bounded path only for ordinary single-device encoder-decoder execution. Distributed/speculative execution retains full width; an absent or invalid bound leaves its corresponding self/cross side at full width.
- Extend three existing NPU test modules. No model-name checks, model-specific helper, new public option or paged-kernel migration.

## Speed Tests and Profiling

Controlled comparison: fixed first 128 samples, concurrency 32, **three fresh-service repetitions per implementation**, same physical NPU/software/Omni, memory fraction 0.85, compile and decoder graphs enabled. Service startup is excluded, no extra request warmup, OS/compiler disk caches are not reset, and no Python profiler is active during request timing. The old helper is grafted onto the same Omni solely as a control.

| Implementation | Mean requests/s | Range | Relative to old helper |
| --- | ---: | ---: | ---: |
| Old model-helper control | 5.122265 | 5.089916–5.172569 | baseline |
| Intermediate full-width shared path | 3.165244 | 3.120772–3.197905 | -38.21% |
| This bounded shared path | **5.076863** | 5.034095–5.162107 | **-0.89%** |

All nine runs succeed 128/128 with identical transcripts and WER 14/1674 = 0.836320%. The candidate is **60.39% faster than the regressed full-width path**, restoring the major regression rather than establishing a speedup over the old helper. Three repetitions do not prove strict equivalence. Auto-sized KV capacity is 158976 for controls and 158592/158976/158592 for candidate repetitions despite the same memory fraction.

A same-function, same-pool compiled NPU graph microbenchmark changes only the read span (B32/H20/D64/FP16, six alternating rounds of 50 replays, five warmups, event timing, independent FP64 references). Median self attention: 1992 span **7.109241 ms**, 448 span **1.574773 ms**; cross attention: 1992 **3.958994 ms**, 1500 **3.070369 ms**. This isolates span cost, not its exact fraction of whole-model runtime.

Final separate 1088-sample run: **6.414147 requests/s**, **169.625051 s** wall time, **4.956834 s** mean latency, **6.773035 s** p95. Periodic logs record decode graph True 14 times and False zero times; these are periodic observations, not exhaustive replay counts. Startup instrumentation was disabled before requests.
