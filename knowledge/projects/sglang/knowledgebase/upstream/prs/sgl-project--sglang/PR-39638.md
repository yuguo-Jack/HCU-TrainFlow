## [DSA][DCP] EAGLE / NextN chain drafting under decode context parallel

**Stacked on #39330** — this PR carries its 7 commits; only the last commit (`b33c0c7a8a`, 3 files, +58/−25) is new. Merge order: #39330 → this PR → #39639 (HiCache host tier, stacked on this PR). Opened as a draft until #39330 lands.

### Motivation

#39330 rejects every speculative algorithm under DSA+DCP ("milestone 2"). GLM-5.3 ships a packed NextN/MTP head, and EAGLE chain drafting with that head is the configuration our production DCP8 replicas run. This PR admits exactly that composition and nothing wider.

### Modifications

- **The draft pool is owner-striped by the same shared write kernel as the target** (`set_mla_kv_buffer_triton` masks and divides by the global DCP rank/size), so every phase that reads it must owner-filter and LSE-merge like the target: draft decode, draft-extend (`DRAFT_EXTEND_V2` joins the LSE path in `dsa_backend.py` / `forward_mla.py`), and target-verify. `dcp_localize_topk` now applies on the draft worker too.
- **Wrapper-aware LSE base**: on the draft the active backend is `DeepseekSparseAttnMultiStepBackend`; the published `dcp_lse_base_on_e` is read from its first per-step backend.
- **Guard** (`overrides.py`): admits `EAGLE` / `NEXTN` with `speculative_eagle_topk == 1` only. Tree drafting stays rejected: `move_kv_cache` is not DCP-aware, and all three of its speculative call sites are tree/NGRAM paths — `duplicate_prefix_tail_to_draft_branches` (direct, early-return at `topk <= 1`), `_finalize_accept_tree_path` and `ngram_worker` (both via `move_accept_tokens_to_target_kvcache`). Giving it the widened bound + translation its sibling methods have is the separable follow-up that would unlock `topk > 1`; that work is tracked on #31218, not here. The guard runs before `handle_speculative_decoding` collapses the `NEXTN` alias, so both spellings are accepted there.

### Evidence (GLM-5.3 base, fp8, 8×H200, DCP8 a2a, EAGLE 5 steps / topk 1 / 6 draft tokens)

- Acceptance 3.2–4.6 tokens/step; 4.25–4.39 at 8–32 running requests (fixed 5 steps).
- Needle retrieval 100K / 400K / 725K correct; greedy determinism 15/15 within a boot; 909/909 requests in the stress sweep with 0 scheduler exceptions / OOM / CUDA errors / watchdog.
- Per-user decode tok/s (p50), DCP8 without → with EAGLE on the same trace: 57 → 271 at 1 session, 57 → 150 at 2, 49 → 103 at 4, 38 → 75 at 8.
- This is what our production DCP8 replicas serve today. The independent GLM-5.3-W4AFP8 / 8×H100 data point in the #39330 discussion (EAGLE topk 1, accept length unchanged by DCP, 13k samples) — reached separately on a v0.5.17 base, not a run of this branch — is consistent with it: DCP changes KV addressing, not draft/verify semantics.

### Notes for reviewers

- Review the last commit only; the rest is #39330.
- No new kernels — the change is which forward modes take the existing owner-filter + LSE-merge path, plus the guard.
- Followed by #39639 (stacked on this one), which additionally admits this packed NextN draft in the HiCache × DCP combination.
