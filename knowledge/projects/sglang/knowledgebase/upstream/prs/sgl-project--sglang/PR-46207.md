# [Fix] request_logger: Skip watermark redaction when watermarking is disabled

[Upstream PR](https://github.com/sgl-project/sglang/pull/46207) · state: closed · merged: True

## Original PR description

## Motivation

Request logging (`--log-requests`) redacts watermark secrets on every logged request, even when the server was started without `--enable-watermark`. The redaction walk copies containers and token lists, so long prompts spend tokenizer-process CPU on a feature that is off. #44692 made the walk cheaper when it runs; this change skips it entirely when watermarking is disabled.

## Modifications

- `python/sglang/srt/utils/request_logger.py`: read the resolved `enable_watermark` flag from the `exec` config namespace. When it is false, `_redact_field` returns the value unchanged and the scalar and list fallbacks in both formatters render the data as is, without calling the redactor. When watermarking is enabled, redaction is unchanged. Standalone formatting with no published server config keeps redacting, so callers outside a server keep the safe default.
- `python/sglang/srt/sampling/watermarking/README.md`: document that request logs redact watermark keys only when `--enable-watermark` is set.

With the flag absent, watermark fields supplied by clients are logged without redaction; request validation is unchanged.

## Accuracy Tests

Logging-only change; inference is untouched.

- `test/registered/unit/utils/test_request_logger_redaction.py`: 7 tests pass on this branch.
- Local behaviour check (not added to the tree): with `override_server_args()` and no `enable_watermark`, level-1 Receive/Finish logs in text and JSON format never iterate a skipped token list; with `enable_watermark=True` the same requests and raw OpenAI request logs still render `<redacted>` for watermark keys, and with it false the original values appear. Both checks fail on `main` and pass here.

## Speed Tests and Profiling

Not run end to end. The change removes the per-field and per-list redaction calls when watermarking is off; when it is on, the code path is the same as before.
