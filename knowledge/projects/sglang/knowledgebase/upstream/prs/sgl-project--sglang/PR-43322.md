# [Bugfix] Fix repetition penalty updates under overlap scheduling

[Upstream PR](https://github.com/sgl-project/sglang/pull/43322) · state: open · merged: False

## Original PR description

## Motivation

While comparing inference results between SGLang and Transformers on Qwen models, I noticed that repetition penalties could lag behind generation when overlap scheduling is enabled.
In non-speculative overlap decoding, the CPU-side request history may not yet contain the most recently generated token when penalties are accumulated. Consequently, that token may be missing from the repetition penalty state used for the next sampling step.
The added regression test reproduces the issue with `Qwen3-8B` using greedy decoding and two generated tokens. Before the fix, with repetition_penalty=2.0, the non-overlap run produces `[21927, 23811]`, while the overlap run produces `[21927, 21927]`. I also distinguish this bug from numerical differences between attention execution paths by verifying the logits.

## Modifications

1. Update repetition penalties after resolve_forward_inputs, using the resolved tokens before the forward pass under non-speculative overlap scheduling.
2. Skip the existing CPU-side repetition penalty accumulation in this path to avoid using stale token history, while preserving other penalties and speculative decoding behavior.
3. Add end-to-end regression tests for overlap and mixed scheduling, including checks against independently computed expected penalized logits.

## Accuracy Tests

- `test_repetition_penalty_overlap.py` (GPU):
  - Runs Qwen3-8B through the offline `Engine` with overlap enabled and disabled, using greedy decoding and repetition penalties of `1.0` and `2.0`.
  - Checks that the no-penalty controls agree, that repetition penalty changes the baseline output, and that the penalized outputs agree across scheduling modes.
  - Generates two tokens to exercise the first decode step, which must penalize the token produced by prefill.

- `test_repetition_penalty_mixed_overlap.py` (GPU):
  - Introduces new prefill requests while a long request is decoding, and asserts that real MIXED batches contain both prefill and decode rows.
  - Records actual sampled tokens independently of `Req.output_ids` and the penalizer state.
  - Computes expected penalized logits from the pre-penalty logits and recorded token history, then checks the full vocabulary for missing or unexpected penalties.
  - Covers repetition penalties of `1.0`, `1.2`, and `2.0`, and checks that recorded samples match the returned output tokens.

Both regression tests passed on one `NVIDIA RTX PRO 6000 Blackwell GPU` with Qwen3-8B, `PyTorch 2.14.1+cu130`, `Triton 3.8.0`. CUDA graphs are disabled in these tests.

Run from the repository root:

```bash
export PYTHONPATH=python
export TEST_MODEL_PATH=Qwen/Qwen3-8B

python test/registered/e2e/sampling/test_repetition_penalty_overlap.py -v
python test/registered/e2e/sampling/test_repetition_penalty_mixed_overlap.py -v
```
