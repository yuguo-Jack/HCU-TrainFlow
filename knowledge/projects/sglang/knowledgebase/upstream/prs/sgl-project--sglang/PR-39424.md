# [Fix] Let parserless xgrammar tool-call tags admit the template's reasoning prefix

[Upstream PR](https://github.com/sgl-project/sglang/pull/39424) · state: closed · merged: False

## Original PR description

## Motivation

Fixes #36675 (reported by the issue author; root cause confirmed in the thread by @mukeshbhandarkar).

`_process_messages` computes `xgrammar_reasoning = thinking_mode and (self.reasoning_parser is None)`, but `_get_reasoning_from_request()` returns `False` whenever no reasoning parser is configured. The two conjuncts are mutually exclusive, so `xgrammar_reasoning` is always `False`. With no `--reasoning-parser`, a chat template that turns thinking on (e.g. the Qwen3 `enable_thinking` default), a tool-call parser, and `tool_choice="required"`, the builtin xgrammar structural tag omits the `<any_text></think>` prefix and forces the model straight into a tool call while it is mid-thought — the opposite of what the adjacent comment says is intended.

## Modifications

- `serving_chat.py`: extract the template-toggle evaluation (the tail of `_get_reasoning_from_request`) into `_template_enables_reasoning()`, and gate `xgrammar_reasoning` on `reasoning_parser is None and _template_enables_reasoning(request)`. `thinking_mode` / `require_reasoning` are unchanged, so scheduler-side `ReasonerGrammarBackend` behavior (which requires a parser) is untouched; parser-configured behavior is unchanged (the existing kimi_k2 test still asserts `thinking_mode=False`).
- `test_serving_chat.py`: `test_parserless_template_thinking_reaches_xgrammar_tag` asserts on the real structural tag (`format.type == "sequence"` when thinking is on, including the template default; `"tags_with_separator"` when `enable_thinking=False`) and that `require_reasoning` stays `False`. It fails before the fix (`'tags_with_separator' != 'sequence'`) and passes after.
