## Motivation

`fused_conv_window_scatter_with_mask` copies the conv windows of the accepted speculative-decode steps into the mamba conv-state pool. The source side already goes through the view's strides, because the per-step windows are overlapping, non-contiguous views. The destination side assumed every pool entry is contiguous in `(dim, K-1)` order. It addressed the destination with a flat element index and rejected anything else with `_require_entry_contiguous_dst`.

That assumption blocks pools whose conv state is stored channel-contiguous, that is, as `[K-1, dim]` storage viewed as `[dim, K-1]`. This layout lets a backend's conv kernels read the window along the channel dimension. Such a pool is not entry-contiguous, so speculative decoding (NEXTN/MTP) hit the assert.

Contiguous pools give the same result, because the strides reduce to the old flat index. No backend or flag changes.

## Modifications

The kernel now takes the destination's `dim` and `K-1` strides and addresses the destination exactly as it does the source. The entry-contiguous assert is removed, since the kernel is correct for any strides.

`test_channel_contiguous_dst` scatters into a transposed pool with both the single-layer and the multi-layer entry points. It compares against a reference with `atol=0`, including a masked row (`step_idx < 0`).
