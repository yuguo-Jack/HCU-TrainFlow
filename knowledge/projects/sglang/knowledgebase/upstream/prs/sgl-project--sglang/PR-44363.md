# [Refactor] [NPU] quantization: Share online/offline W4A8 execution

[Upstream PR](https://github.com/sgl-project/sglang/pull/44363) · state: open · merged: False

## Original PR description

## Motivation

Ascend online and ModelSlim offline W4A8 Linear methods duplicate the same activation quantization and matmul. Their execution should share one contract after each loader has prepared the packed weights and scales.

## Modifications

- Route both methods through `npu_w4a8_mxfp4_linear`, preserving prepared weight/scale views, activation conversion, and output shape restoration.
- Normalize A8W4 bias to BF16 `[1, N]` and remove the online FP32 bias cache. This corrects the bias contract as part of sharing execution; weight quantization and loading remain in their existing methods.
- Add CPU regressions for both entry points, bias, noncontiguous inputs, and identical prepared tensors.

This is a standalone change against main; it does not require the online W4 MoE feature stack.

## Accuracy Tests

- 6 tests passed in an isolated CPU harness using the production methods with NPU calls mocked. These verify Python/operator contracts, not NPU numerical equivalence.
- Ruff, isort, codespell, syntax, and diff checks passed. The standard test entry point could not start in the local environment because `orjson` is missing.
- Earlier integration testing on Ascend 950 was reported successful for online and offline Dense W4A8 requests. The offline deployment was `TallMessiWu/sglang@2ef4c276be` and also contained the mixed gate/up and preprocessing fixes. Online visual layers with K=4304 retained the existing BF16 fallback. This new main-based PR head has not been rerun on NPU; numerical equivalence was not measured.

## Speed Tests and Profiling

Not run; no performance claim.
