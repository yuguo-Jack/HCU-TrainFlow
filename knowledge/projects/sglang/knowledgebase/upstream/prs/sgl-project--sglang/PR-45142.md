# [Fix] qwen4_exp: Capture DFlash aux hidden states on Qwen3.8-Flash-Next

[Upstream PR](https://github.com/sgl-project/sglang/pull/45142) · state: open · merged: False

## Original PR description

> **Status: pending GPU validation.** The CPU unit test passes, but this branch hasn't been run on GPU yet. I'll post GB300 acceptance numbers here and mark the PR ready once they match the reference below.

## Motivation

Fixes #38589. Qwen4-Exp (Qwen3.8-Flash-Next) cannot feed a DFLASH drafter today:

- The decoder layers take `captured_last_layer_outputs` into `**kwargs` and never fill it, so the aux list stays empty.
- `Qwen4ExpModel.forward` puts the MTP hyper-connection streams in the second return slot, which `Qwen3VLForConditionalGeneration` unpacks as aux states.
- `set_dflash_layers_to_capture` is inherited and succeeds silently, so nothing warns that capture is off.

[`incoai/Qwen3.8-Flash-Next-DFlash2`](https://huggingface.co/incoai/Qwen3.8-Flash-Next-DFlash2) currently ships an out-of-tree patch for this. This PR replaces that patch with an upstream implementation.

## Modifications

All changes are in `python/sglang/srt/models/qwen4_exp.py`:

- **Capture point.** Each DFLASH target layer `k` is captured right after it completes. Its hyper-connection streams are reduced with `hc_contract` (the stream mean), as `glm5_next` already does for GLM-5.3-Flash (#36708).
- **No +1 shift.** `Qwen4ExpForConditionalGeneration.set_dflash_layers_to_capture` passes the drafter's `target_layer_ids` through unchanged. Ids outside the last pipeline stage raise a `ValueError`.
- **Return slot.** When capture is on, `Qwen4ExpModel.forward` returns `(hidden_states, aux_hidden_states)`. `Qwen4ExpVLModel` passes that tuple through to `Qwen3VLForConditionalGeneration`. `last_hc_hidden_states` stays `None`, so the outer forward doesn't overwrite the packed aux states. MTP and aux capture never run together.
- **CP.** Under CP row sharding, the aux states are gathered the same way `hidden_states` is.
- **Cleanup.** The dead `captured_last_layer_outputs` kwarg is removed.

With DFLASH off, the code path is unchanged: the MTP streams are still returned and stashed.

## Relation to #38642

#38642 (now a draft) reduces the streams with the *next* layer's learned `attn_hyper_connection.mix`. That gives a different feature: layer k+1's attention input rather than layer k's output. Drafters trained on the stream mean need the mean, and that includes `incoai/Qwen3.8-Flash-Next-DFlash2`. It is also the same definition `glm5_next` uses for hyper-connection models. If drafters trained on the mixed definition exist, a `dflash_config` key naming the reduction could select between the two; happy to add one if maintainers want both supported.

## Accuracy Tests

Speculative decoding here is lossless, so output accuracy is unchanged; the metric that matters is acceptance length.

**Reference: the validated out-of-tree patch.** It uses the same capture (mean of 4 streams after layers 5/15/25/35/45). Setup: `Qwen/Qwen3.8-Flash-Next-FP8`, 1x GB300, TP1, 3 draft tokens. Acceptance at concurrency 1:

| Task | MTP | DFlash 2 |
| :--- | ---: | ---: |
| GSM8K | 3.08 | 3.26 |
| MATH-500 | 2.93 | 3.17 |
| HumanEval | 2.52 | 2.94 |
| MBPP | 2.65 | 3.06 |
| MT-Bench | 2.50 | 2.83 |

**Pending:** the same run on this branch.

**Unit test.** `test/registered/unit/models/test_qwen4_exp_dflash_capture.py` (CPU, `base-a-test-cpu`):
- The capture case fails on main and passes here. It also fails if capture shifts by one layer or reads one stream instead of the mean.
- The MTP case passes on both.
