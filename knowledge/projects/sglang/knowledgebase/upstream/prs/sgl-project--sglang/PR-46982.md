## Motivation

HiCache and disaggregation currently reconstruct unified pool structure from pool variants. A storage transfer surface can expose the same regions, IDs and layout directly from the pool plan.

## Changes

- Introduce named KV storage entries with transfer regions, metadata and ID mappings.
- Build HiCache host stacks and disaggregation registration from those entries, including state and window regions.
- Derive shared host-envelope eligibility and budgets from the plan, and add a manual transfer-surface comparison utility.

## Validation

Historical validation at `ca400c908c`:
- Eight configurations: **0 PD-registration differences**; HiCache had **33 expected metadata differences**.
- Storage tests: **7 passed**; assembler: **43 passed**.
- Mooncake TP1 prefill/decode on two H200 GPUs per pair, GSM8K-200: gpt-oss-120b **96.5% → 96.5%**, Qwen3.8-27B **97.0% → 97.5%**, with no transfer errors.

Environment: PyTorch 2.14.1, FlashInfer 0.7.2, sglang-kernel 0.4.10, Mooncake 0.3.13. GPU/PD validation was not rerun after the latest rebase.
