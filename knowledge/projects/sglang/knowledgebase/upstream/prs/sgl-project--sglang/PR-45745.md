# [Fix] deepseek-v4.1: score the torch indexer chunk in place

[Upstream PR](https://github.com/sgl-project/sglang/pull/45745) · state: open · merged: False

## Original PR description

## Motivation

The torch indexer of DeepSeek-V4.1 (the path GPUs without DeepGEMM's paged MQA logits take, e.g. SM12x) scores a prefill in chunks of a bf16 `[rows, 64 heads, keys]` product capped at `_TORCH_SCORE_BUDGET_BYTES` (1 GiB). `scores()` then did `(s.relu() * weights.unsqueeze(-1)).sum(dim=1)`: `relu()` and the multiply each allocated another tensor of the chunk's size, so a chunk peaked at 3 GiB. On 12-16 GB cards that is the largest transient of a long prefill, and it is where the prefill runs out of memory.

## Modifications

- `dsv41_sparse.py`, `DeepseekV41Indexer.scores()`: `relu_()` and `mul_()` on the einsum's own output, then the same `sum(dim=1).float()`. The einsum returns a fresh tensor and `scores()` has one caller (`_score_chunks`), so nothing else sees it.
- `v41_indexer/scoring.py`: the budget's comment no longer says transients run ~3x the cap.

## Accuracy Tests

Same operations in the same order. On an RTX 5070 Ti (SM120), random bf16 inputs at four chunk shapes (rows x keys = 256 x 32768, 1024 x 8192, 4096 x 2048, 128 x 65536; 64 heads, d = 128): `torch.equal` between the old and new outputs at every shape.

## Speed Tests and Profiling

Same shapes, 20 calls each after warm-up (`torch.cuda.max_memory_allocated` above the inputs):

| | time a call | peak |
|---|---|---|
| out of place (before) | 9.0-9.1 ms | 3072 MiB |
| in place (this PR) | 9.2-9.3 ms | 1072 MiB |

In a server (2x RTX 5070 Ti 16 GB, TP2, KTransformers CPU experts, DeepSeek-V4.1-Flash-1017): before this change, with 12 GB of each card usable an 11.8K-token prompt ran out of memory allocating 1 GiB in `scores()`, and with 16 GB a second 35K-token prompt (four 9,216-token chunks) did the same after the first had passed; with it, both prompts pass. The 35K prefill's speed is unchanged within launch noise (675 / 663 tok/s with the change, 678 / 671 without).
