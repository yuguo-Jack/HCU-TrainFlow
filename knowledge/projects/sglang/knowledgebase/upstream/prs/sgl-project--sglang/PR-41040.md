# [Fix] Transfer DFlash draft KV across asymmetric PD TP

[Upstream PR](https://github.com/sgl-project/sglang/pull/41040) · state: closed · merged: False

## Original PR description

## Motivation

Fixes #41038. For GLM-5.3-Flash DFlash2 with Mooncake PD disaggregation and asymmetric P/D TP (for example, P TP2 to D TP4), the draft KV source and destination have different per-rank layouts. Reusing the source KV item lengths for destination addressing can fail at the tail of a transfer.

## Modifications

- Keep the normal target-KV transfer path.
- Split the DFlash draft-KV transfer into the corresponding destination TP ranks, pack source pages into a registered GPU staging buffer, and pass destination KV item lengths separately.
- Scope the path to DFlash with unequal P/D TP, leaving other speculative algorithms and equal-TP transfers on the existing path.
- Build on the destination-length support in #40045.

## Accuracy Tests

- The original internal prototype completed a 256/256-request short regression that previously completed 228/256. This result is not a GPU validation of this exact community commit.
- `git diff --check` and Python 3.11 `py_compile` passed on the rebased patch.
- Full output-token equivalence and a GPU rerun on current community main are pending. Local pytest collection was not completed because the default Python 3.9 environment cannot parse this repository's Python 3.10+ syntax.

- Leslie360 · comment · 2026-09-25T04:00:40Z · [source](https://github.com/sgl-project/sglang/pull/41040#issuecomment-5826461552)

Verified this on main against #41038 — the mechanism is real and the implementation is sound overall. Two small notes and one scope remark.

What's checked: the non-DCP `send_kvcache` does pass `kv_args.kv_item_lens` as both source and destination strides into `_send_kvcache_generic` (the generic call site uses `item_lens[i]` for both ends), so the P TP2 → D TP4 draft-page mismatch is as described. The ownership mapping (`dst_tp_rank // ratio == src_tp_rank` gates the send, `slice_num = dst_tp_rank % ratio` picks the head slice) covers every decode rank exactly once — I enumerated ratio=2 and it partitions cleanly. `RegistrationInfo.dst_tp_rank` / `dst_kv_item_lens` already exist from #40045 and the wiring reuses them as intended; `gather_all_layers_to_staging`'s signature matches main; the `can_pack` guards are conservative in the right ways; the `prefill.py` insertion point has `draft_kv_pool` in scope.

Notes:
1. The branch keys on `self.server_args.speculative_algorithm == "DFLASH"`, an exact match on the raw CLI string. `--speculative-algorithm dflash` is accepted elsewhere (`SpeculativeAlgorithm.from_string` upper-cases), so lowercase input would silently bypass this branch — the same silent-failure class this PR fixes. This follows the existing convention in the arg_groups hooks (several do `== "EAGLE"` / `== "DSPARK"` on the raw string), so it is a tree-wide gap rather than something introduced here; a `.upper()` is still cheap insurance.
2. Skewed-peer edge: if a destination ever sends `dst_kv_item_lens` without `dst_attn_tp_size`, the `!=` guard enters the branch and the `%` raises TypeError instead of the clean RuntimeError the lens check produces for the common skew. `dst_attn_tp_size and dst_attn_tp_size != self.attn_tp_size` would make it uniform. Marginal.

Scope remark (not blocking): the DCP path handles asymmetric draft TP algorithm-agnostically, while this branch is DFLASH-only — a NEXTN/MTP draft over non-DCP asymmetric TP still takes the old path silently. Follow-up material.

Happy to run the P TP2 → D TP4 mooncake validation with a DFlash2 draft once we regain GPU access.
