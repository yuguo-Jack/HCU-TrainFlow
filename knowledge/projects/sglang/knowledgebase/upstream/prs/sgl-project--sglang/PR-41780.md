## What changes

**Who sees it:** users who run a HiSparse decode server with native MTP (EAGLE) speculative decoding. They set `--enable-hisparse` and a speculative algorithm.

**Before this PR:** the server stops at startup. The draft worker builds its own `HiSparseDSATokenToKVPool`. That pool needs a logical-to-device slot mapping, and the shared allocator registers the mapping only on the target pool. Draft CUDA graph capture then fails:

```
dsa_backend.py, in init_forward_metadata_in_graph
    physical = first.token_to_kv_pool.translate_write_locations(
hisparse_memory_pool.py, in translate_loc_to_hisparse_device
AttributeError: 'HiSparseDSATokenToKVPool' object has no attribute 'full_to_hisparse_device_index_mapping'
```

**After this PR:** draft graph capture completes. The draft worker keeps its KV in a normal `DSATokenToKVPool` on the GPU. That pool covers every logical target slot. Its size is the device token count times `host_to_device_ratio`. The draft does not need slot translation.

The target worker is unchanged. No change applies without `--enable-hisparse` and a draft worker.

**Cost:** the draft KV uses more GPU memory. The memory budget now charges the draft for the full logical size. A larger `host_to_device_ratio` leaves fewer target KV tokens on the GPU. No speed change is measured for this PR.

**Needs [7/N] #41781.** This PR fixes the startup failure. Without 7/N, the server starts but returns wrong tokens after the first token.

## Why the draft pool stays resident

The draft shares logical slot numbers with the target. It does not share the target's KV remapping. When the target moves a slot between host and device, the draft KV must stay in place. A resident pool over all logical slots gives this.

## Implementation

- `kv_cache_configurator.py`: the draft worker builds a `DSATokenToKVPool` with `max_total_num_tokens * host_to_device_ratio` slots. The target still builds `HiSparseDSATokenToKVPool`.
- `pool_configurator.py`: the memory budget multiplies the draft KV cell size by `host_to_device_ratio`.
- `model_runner.py`: `maybe_init_hisparse_coordinator` returns early for a draft worker that has a resident pool. Only the target owns a HiSparse coordinator.

## Tests

`test/registered/unit/model_executor/test_hisparse_pool_configurator.py` has three new tests:

1. The draft pool is resident and has the logical size. The target pool is unchanged. The test covers ratios 1, 2 and 4.
2. The memory budget scales the draft KV by the ratio.
3. The draft worker builds no coordinator. The target worker still builds one.

## Measured

End-to-end check on a HiSparse fork build: GLM-5.2 MXFP4, PD 4:4 (TP4 prefill, TP4 decode), HiSparse decode, MI355X, native MTP (EAGLE, 3 steps, top-k 1).

- Before this PR: draft CUDA graph capture fails with the `AttributeError` above.
- With this PR and [7/N] #41781: capture completes and the server answers 8 of 8 greedy chat prompts correctly. Two of the prompts are needle prompts of about 16K tokens.

Throughput is not measured for this PR.
