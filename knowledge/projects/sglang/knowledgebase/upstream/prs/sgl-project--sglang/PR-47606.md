# [Fix] function_call: Drain tool calls stranded in the buffer when the stream ends

[Upstream PR](https://github.com/sgl-project/sglang/pull/47606) · state: open · merged: False

## Original PR description

## Motivation

`BaseFormatDetector.parse_streaming_increment` emits at most one tool-call
unit per delta: a tool name with empty parameters, then that call's argument
diff, then the next call. When a final delta carries more than one complete
tool call (larger `--stream-interval`, multi-token decode steps), the
remainder is left stranded in `self._buffer`, and `BaseFormatDetector.finish()`
returns an empty result — the trailing calls are silently dropped. The
serving-side top-up (`_check_for_unstreamed_tool_args`) only covers argument
bytes of the last *tracked* call, so a stranded call is unrecoverable.

Reproduced offline with `FunctionCallParser` directly: streaming
`<tool_call>{...NYC...}</tool_call><tool_call>{...LA...}</tool_call>` as one
delta emits only `[(0, 'get_weather', '')]` — the argument bytes and the
second call are lost — while `detect_and_parse` returns both calls. With
fine-grained chunks the second call lands complete in the buffer and
disappears at flush. The same loss pattern was already fixed per-detector in
#31860 (Inkling) and #33901 (GLM-4.7), and is being patched
detector-by-detector in #36129/#40994/#41909/#41914. `JsonArrayParser.finish()`
already implements the drain pattern; the shared base default does not.

## Modifications

- `BaseFormatDetector.finish()`: re-run `parse_streaming_increment("")` until
  it stops emitting calls (identical to the existing
  `JsonArrayParser.finish()`), accumulating normal_text and calls.
  Termination: every call-emitting pass either consumes the completed call
  from the buffer or flips `current_tool_name_sent`. Detectors with their own
  `finish()` overrides are unaffected; normal streaming paths are unchanged
  because `finish()` is only called once at stream end.

## Tests

Offline unit tests (no server, no model loading), added to the existing
classes:

- `TestQwen25Detector.test_flush_drains_calls_stranded_in_final_chunk`: a
  final delta with two complete calls now yields both, and `finish()` is
  idempotent.
- `TestQwen25Detector.test_streaming_with_flush_matches_non_streaming`:
  streaming + flush equals `detect_and_parse` for chunk sizes 1 / 7 / full.
- `TestLlama32Detector.test_flush_drains_calls_stranded_in_final_chunk`.

A sweep of all 45 registered parsers (per-format text generated from each
detector's `structure_info()`, non-streaming oracle, chunk sizes 1/7/full,
30s timeout) goes fail→pass for qwen, qwen25, llama3, trinity, apertus2509
and strictly improves hermes (argument bytes recovered); all other results
are identical to unmodified main — no hangs, no regressions.
