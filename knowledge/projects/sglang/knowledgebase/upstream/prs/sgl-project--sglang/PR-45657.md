# [Fix] [AMD] docker: Drop the deadsnakes PPA before the Mooncake apt update

[Upstream PR](https://github.com/sgl-project/sglang/pull/45657) · state: open · merged: False

## Original PR description

## What

Remove the deadsnakes PPA source list from the ROCm image at the start of the Mooncake build step.

## Why

The nightly `gfx950-rocm724` build failed in [this run](https://github.com/sgl-project/sglang/actions/runs/39597874446) after about 2.4 hours of AITER compilation: Launchpad returned 503 for the deadsnakes PPA index, so `apt update` in the Mooncake step exited with 100.

```
E: Failed to fetch https://ppa.launchpadcontent.net/deadsnakes/ppa/ubuntu/dists/noble/main/binary-amd64/Packages  503  Service Unavailable
E: Some index files failed to download. They have been ignored, or old ones used instead.
```

The PPA comes from the `rocm/pytorch` base images. Nothing in `rocm.Dockerfile` installs from it: the Python in each base image is the distro default (3.10 on jammy, 3.12 on noble), and the later apt installs only pull distro packages such as `python3-dev`.

## Notes for the reviewer

- The removal is at the top of the RUN rather than just before `apt update`, because Mooncake's `dependencies.sh` runs its own `apt-get update`.
- It runs regardless of `BUILD_MOONCAKE` and is not restored afterwards. That way the later `apt-get update` steps (TileLang, MORI, NIXL) are covered too. As a side effect, the published image no longer has the deadsnakes PPA configured.
- `rm -f` with the glob is a no-op on bases that don't have the PPA (the ROCm 10 base is plain `ubuntu:24.04`).

## Test plan

Not yet verified: this needs a ROCm image build. I haven't dispatched one because the release workflow pushes images.
