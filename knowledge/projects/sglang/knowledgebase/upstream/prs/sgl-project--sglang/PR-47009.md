# [Fix] docker: Pin sgl-nvidia-mega to 9a21cb0 for megakernel API version 2

[Upstream PR](https://github.com/sgl-project/sglang/pull/47009) · state: open · merged: False

## Original PR description

## Motivation

#45266 raised `MEGAKERNEL_API_VERSION` to 2. `docker/Dockerfile` and `docker/Dockerfile.cu134` still pin sgl-nvidia-mega `6fd7ac30`, whose specs declare API version 1. As a result, every image built from main since then (the first nightly is `nightly-dev-cu13-20261028-586355a8`) fails at startup under `--enable-nvidia-megakernel`:

```
ValueError: --enable-nvidia-megakernel cannot run this setup: sgl_nvidia_mega.deepseek_v41.spec:SPEC uses megakernel API version 1; this SGLang requires version 2
```

## Modifications

- Pin `SGL_NVIDIA_MEGA_COMMIT` to `9a21cb037a85fdfdb2978d7dc80df69cfcd575ec` in `docker/Dockerfile` and `docker/Dockerfile.cu134`.
- `9a21cb0` is the current sgl-nvidia-mega main. It moves the DeepSeek-V4.1 and Qwen3.5 specs to API version 2 (sgl-nvidia-mega #20) and includes the DeepSeek-V4.1 indexer fix (#26). It keeps the `nvidia_megakernel` entry point, so the existing install check is unchanged.

## Dependency: sgl-nvidia-mega #29

`9a21cb0` alone does not start DeepSeek-V4.1 with the Engram host table on, either on `nightly-dev-cu13-20261028-586355a8` or on main `8fabf5e65c`. SGLang's `_HostTable` no longer has a `layout` attribute, and the plugin's Engram prefetch still reads it:

```
File ".../sgl_nvidia_mega/deepseek_v41/engram/prefetch.py", line 95, in reason
    if table is None or table.layout != "per_rank":
AttributeError: '_HostTable' object has no attribute 'layout'
```

sgl-nvidia-mega #29 (open, one commit on top of `9a21cb0`) fixes this: with its head `3f83a55f`, every rank on both SGLang versions reports the target and DSpark draft megakernels active. This PR stays a draft until #29 merges, and the pin then moves to that merge commit.

## Validation

DeepSeek-V4.1-Flash on 4x GB300, TP4/EP1, DSpark block size 5, `--enable-nvidia-megakernel` with the Engram host table on, batch-1 (`max-running-requests 1`, `cuda-graph-max-bs-decode 1`), plugin `9a21cb0` + sgl-nvidia-mega #29 (`3f83a55f`), on `nightly-dev-cu13-20261028-586355a8` and on main `8fabf5e65c`:

- Every rank (TP0-3) reports `NVIDIA megakernel: active` for the DeepSeek-V4.1 target and the DSpark draft, on both SGLang versions.
- GSM8K, 50 questions, real acceptance, main + #29: 0.96 (48/50), mean accept length 3.88.
- AgentX trace replay at concurrency 1, 20 min, golden acceptance length 3.51: P90 interactivity 934.3 tok/s/user (586355a8) and 941.3 (main), TPOT P90 1.07 / 1.06 ms.
- `9a21cb0` without #29 fails at startup on both versions with the `_HostTable.layout` error above.

`pre-commit run` passes on the changed files.
