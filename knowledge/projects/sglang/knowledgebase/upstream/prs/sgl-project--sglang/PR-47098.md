# [Fix] moe: Stabilize MXFP4 Marlin expert token ordering

[Upstream PR](https://github.com/sgl-project/sglang/pull/47098) · state: open · merged: False

## Original PR description

## Motivation

MXFP4 Marlin's reduction result can depend on a token's position within its expert blocks. The current atomic routing scatter can change that position between forwards, producing different BF16 expert outputs for identical hidden states, top-k IDs/weights, and expert weights. Fixing the grouping order removes this variation in captured DeepSeek-V4-Flash-0731 inputs.

Related to #45525.

## Modifications

- Add stable block-padded expert alignment using PyTorch's stable sort and GPU offset/scatter kernels. Preserve the filtered-expert bucket, padding sentinel, and inactive-prefix count contract without reading routing counts back to the host.
- Use stable alignment for MXFP4 Marlin batches above the existing tiny-batch threshold. Retain the existing single-token and tiny-batch implementations.
- Add registered GPU tests for exact alignment, filtered routes, empty inputs, both expert-ID dtypes, updated routing under CUDA Graph replay, and actual MXFP4 Marlin decode/prefill against a dequantized FP64 reference with BF16 rounding/error budgets. Repeated eager and CUDA Graph outputs must match elementwise.

## Accuracy Tests

Tested on H20 with PyTorch 2.13.0+cu130 and Triton 3.7.1, based on upstream `286e01859487535bfbc6355cee1bb5c6bff9c08d`.

```bash
python -m pytest -q test/registered/kernels/ops/moe/test_moe_align_stable.py
# 45 passed
```

Replayed captured layer-0, TP-rank-1 inputs and packed expert weights from DeepSeek-V4-Flash-0731: 410 tokens, hidden size 4096, 256 experts, top-k 6. On the upstream implementation, 1 of 20 eager repetitions differed from the first output (27 elements, maximum absolute difference 0.0009765625). With this change, all 20 repetitions were identical, and CUDA Graph replay matched the eager output.

In the original TP4 serving reproduction checkout, applying stable alignment together with the current upstream V4 `wo_a` fast-path restriction reduced decode/DSPARK disagreements from 6/16 to 0/16 paired trials. Each version completed 32 valid requests, covering cold/hot cache and both `prefill4` and natural generation at temperature 0. This serving check includes that separately existing `wo_a` change; this PR contains the Marlin alignment fix. Broader execution-shape/backend parity requires separate validation.

CI status: Lint passed. The GPU workflow stopped at `pr-gate` because the required `run-ci` label is missing; a maintainer needs to enable it.

## Speed Tests and Profiling

Warmed operator timing on the same captured H20 input/weights; medians of five batches of 50 executions:

| Execution | Upstream | Stable alignment |
|---|---:|---:|
| Eager | 1.002225 ms | 0.989678 ms |
| CUDA Graph | 0.950465 ms | 0.977287 ms |

CUDA Graph operator time increased by 2.82% for this 410-token prefill case. Eager samples showed CPU dispatch variability. The single-token decode and existing tiny-batch alignment implementations are retained.
