# [Feat] speculative: Seed rejection-sampling draft proposals for deterministic inference

[Upstream PR](https://github.com/sgl-project/sglang/pull/33395) · state: open · merged: False

## Original PR description

## Motivation

Classic EAGLE/NEXTN rejection sampling draws each draft proposal with `fast_sample()`. Although target sampling and verify-side rejection coins support request-local seeds, this proposal draw used the global PyTorch RNG (`exponential_()`), so `--enable-deterministic-inference` still changed outputs with batch shape and CUDA graph replay.

This is the draft-worker follow-up documented in #30822. Before this change, Qwen3.5-9B NEXTN rejection sampling produced 12 unique outputs in 12 changing-batch trials with a fixed sampling seed.

## Modifications

- Add an optional deterministic path to `fast_sample()` keyed by:
  - request sampling seed
  - absolute sequence position
  - draft step / MTP layer
  - vocabulary entry
- Domain-separate draft proposal randomness from target sampling and verify-side rejection coins.
- Convert MurmurHash32 output to open-interval uniforms with midpoint binning, then use exponential-race categorical sampling in float64.
- Preserve the existing RNG-backed fast path when deterministic inference is disabled.
- Plumb request seeds and positions through eager and CUDA-graph EAGLE/NEXTN workers.
- Support both ordinary and multi-layer EAGLE, including the single-CUDA-graph multi-layer draft-extend path.
- Keep deterministic rejection sampling guarded on non-CUDA-compatible devices because this implementation uses a Triton hash kernel.
- Add sampler tests for replay, batch permutation/splitting, seed/position/step separation, hash endpoints, CUDA graph updates, and categorical distribution sanity.
- Add dedicated deterministic E2E smoke tests without changing the existing unseeded rejection-sampling and chain-MTP test configurations.
- Add a reproducible seeded/unseeded sampling microbenchmark.

[by Claude Code] **Severity: functional | Confidence: High**

**Issue**

`_draft_extend_for_decode` keys its step-0 draw with `batch.seq_lens`, which still holds the length from before verify. After prefill, the first decode round has the same `batch.seq_lens` as `_draft_extend_for_prefill` (line 1019). Both draws hash `(seed, L0, step 0)`, so they reuse the same exponential noise.

**Example**

Prompt length 100. The prefill draft for verify round 1 and the round-1 draft-extend draft for verify round 2 both hash `(seed, 100, 0)`. Both drafts reach the verify, so the second draw is not independent of the first. The rejection-sampling output is then no longer exactly the target distribution.

**Fix**

Key the draw by the length after verify, for example `positions=batch.seq_lens + batch_result.accept_lens`. Add a test that the keys for one request never repeat across rounds.

- nvpohanh · comment · 2026-10-01T06:40:29Z · [source](https://github.com/sgl-project/sglang/pull/33395#discussion_r4152539354)

File: `python/sglang/srt/speculative/spec_utils.py` · line None

[by Claude Code] **Severity: functional | Confidence: Medium**

**Issue**

`salted_seed = sampling_seed + _DRAFT_GUMBEL_SEED_SALT + draft_step` adds the step to the seed. So seed `s` at step 1 gives the same key as seed `s + 1` at step 0. Requests with adjacent seeds share draft noise.

**Example**

With multi-layer EAGLE, send one prompt twice with seeds 42 and 43. Both requests use `positions=forward_batch.seq_lens` for every step. Request 42's step-1 draft and request 43's step-0 draft then hash the same key, so their proposals are correlated. Assigning `seed = base + i` is a common way to get independent samples, such as RL rollouts.

**Fix**

Keep the user seed intact and pass the step through a separate hash input. For example, fold it into the position input, or hash `(salted_seed, draft_step)` into a new seed first.

File: `python/sglang/srt/speculative/eagle_draft_cuda_graph_runner.py` · line None

[by Claude Code] **Severity: perf | Confidence: High**

**Issue**

`execute()` now clones `draft_probs`. Its only caller, `EagleDraftWorker.draft()` in `eagle_worker_v2.py` (line 654), already clones the same tensor after `execute()` returns. That clone came from #37134, so this PR's merge now copies the tensor twice.

**Why it matters**

`draft_probs` is a `[bs, num_steps, vocab]` float32 tensor. At bs 64, 3 steps, and a 248K vocab, each copy moves about 190 MB and allocates another 190 MB. The extra copy runs on every graph-replayed decode round whenever rejection sampling is on, including non-deterministic runs.

**Fix**

Remove this clone and keep the one in `draft()`.
