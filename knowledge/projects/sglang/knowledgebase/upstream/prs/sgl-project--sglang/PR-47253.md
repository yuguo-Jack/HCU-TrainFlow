# [Perf] diffusion: Enable verified eager LN fusion for SANA-Video

[Upstream PR](https://github.com/sgl-project/sglang/pull/47253) · state: open · merged: False

## Original PR description

## Motivation

SANA-Video eager inference inherits the image model's restriction that enables LN+modulation fusion only on CUDA-graph streams. For the tested video activation, `[1, 32760, 2240]`, the existing fused kernel passes live exactness verification. It preserves the required contiguous input copy while fusing LayerNorm, scale and shift, avoiding the intermediate tensors between those operations. A separate final-head profile replaces 82 ATen LayerNorm chains with 82 existing fused kernels per CFG iteration, reducing the total GPU kernel count from 2,309 to 2,063.

The image restriction remains the default: prior image measurements in #34015 found an eager regression. Video opts in at its two transformer-block normalization sites and its final modulated normalization. Main's existing video BCG path already uses this fusion; this PR extends eager execution rather than claiming new BCG support.

Frozen SGLang main: `af21e2b989e482cfdce39689126562f2209d53ac`.
Final tested head: `e0d694593a65cb5b463c4011b84ee50abefa5e43`.
Frozen vLLM-Omni: `817d4c17feb702289a2d2b2cbacfd594c262b7a7`.

## Modifications

- Add an optional `allow_eager=False` keyword to the existing `sana_ln_modulate` wrapper and reuse its existing stream/device/compile dispatch helper.
- Opt in only from SANA-Video's three call sites. Preserve the fused kernel, per-signature live-ATen exactness gate, unverified-capture protection and mismatch fallback.
- Extend the existing four-shape wrapper test across both stream policies, with fresh gate state, default image inference and grad-enabled fallback checks. Reuse the generic gate tests and update the existing kernel README.

No new kernel, environment variable, tuning setting or unrelated refactor is included.

## Accuracy Tests

One physical RTX PRO 6000 Blackwell Server Edition GPU0, SM120, 97,887 MiB, 600 W, driver 595.84. GPU1 remains idle. SGLang uses PyTorch 2.14.1+cu130 / Triton 3.8.0; Omni uses PyTorch 2.13.0+cu130. Dependencies and resolved launch commands are archived.

The common checkpoint is `Efficient-Large-Model/SANA-Video_2B_480p_diffusers@db5f398b13ca086d09a50ce156c20527773841b1`, with verified file hashes. Both native pipelines run 832×480, 81 frames at 16 fps, 50 steps, CFG 6, CPU seed 1101, empty negative prompt, maximum 300 selected text tokens, batch/concurrency 1. DiT and text encoder are BF16; VAE, initial noise and solver arithmetic retain the native FP32 contract. The effective positive text includes the same motion-score instruction. Both encode H.264/yuv420p with CRF 0; native encoder versions differ and all quality comparisons use the same decoder.

Actual runtime observations establish equal token IDs/masks, initial noise, timesteps and sigmas. Native BF16 text-encoder outputs and subsequent model predictions differ across frameworks; they were measured, not replaced. The observer preserves all eight qualification MP4s byte-for-byte.
