# [sgl-router] Pair PD prefill and decode only within a version group

[Upstream PR](https://github.com/sgl-project/sglang/pull/41487) · state: closed · merged: False

## Original PR description

Stacked on #41268.

In PD mode the router picked a decode worker from the model's whole decode pool. When two engine versions run side by side, for example during a rollout, a prefill worker could be paired with a decode worker from the other version and transfer KV across it. This PR stops that: the router only pairs a prefill worker with a decode worker from the same version group.

**Where the group comes from.** A new flag, `--pd-version-group-label <key>`, applies to Kubernetes PD discovery. A worker's group is the value of that label on its EndpointSlice. EndpointSlices copy their Service's labels, so each (role, version) needs its own labeled Service. That is the same way the prefill and decode selectors already classify slices. If a slice lacks the label, its workers get no group and pair only with other unlabeled workers; the router logs a warning. When the flag is unset every worker is unlabeled, so routing is unchanged.

**Routing**
- `PdPoolResolver::prefill_candidates` keeps only prefill workers whose group has a healthy decode worker. A request therefore never lands on a prefill worker that has no peer. If prefill workers exist but no group has both roles, the request gets 503 `no_decode_workers_available`.
- The new `PdPoolResolver::decode_peers(model, prefill)` limits decode selection to the chosen prefill's group. The chat handler uses it.
- `/readyz` requires at least one group that has both roles.

**Discovery**
- `WorkerSpec` and `Worker` carry `version_group`. It defaults to `None` when deserializing, and reconcile-time re-introspection keeps it.
- If a slice's group label changes, its workers are removed and re-added, so they never stay paired under the old group.

**Validation.** The flag is rejected with static URLs, with a plain-mode `--selector`, when empty, and with `--chat-routing reorg`. The reorg path selects decode through its own bucket groups and does not enforce version groups yet.

**Tests**
- Resolver unit tests: pairing stays in the group; unlabeled workers don't pair with labeled ones; a group whose decode breaker is open drops its prefill workers.
- k8s tests: the label is read from the slice; relabeling emits Removed then Added.
- CLI parsing and rejection tests, and a readiness table case with prefill and decode in different groups.
- End-to-end proxy test with two groups over 12 requests. For each request it reads the `bootstrap_port` in the decode body to identify the paired prefill. The test fails if `chat.rs` goes back to the ungrouped decode pool.

`cargo fmt --check`, `cargo clippy --locked --workspace --all-targets -- -D warnings`, and all 1,025 tests pass.
