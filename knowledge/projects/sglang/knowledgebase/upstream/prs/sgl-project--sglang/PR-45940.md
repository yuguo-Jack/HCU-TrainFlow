# [Perf] dsv4: Combine the final mHC streams from bf16 without an fp32 copy

[Upstream PR](https://github.com/sgl-project/sglang/pull/45940) · state: closed · merged: True

## Original PR description

- With `hc_pre_from_prev_sublayer`, the model output combined the four mHC streams with `mhc_combine(pre_hc_head.float(), ...)`. The `.float()` copied the whole `[tokens, 4 * hidden]` residual to fp32 before the kernel read it.
- `_mhc_combine_kernel` already widens every element to fp32 as it loads it, so the bf16 rows now go to the kernel directly. The sums are the same fp32 products in the same order.
- `mhc_combine` asserts the unit inner stride that its indexing assumes, which the fp32 copy used to guarantee.

Output is bitwise identical to before.

Verification:
- `mhc_combine` on the bf16 rows matches the old fp32-copy path bit for bit from 1 to 65536 rows, including offset row views, on B300 and GB300.
- A micro benchmark on V4.1-Flash shapes shows the combine several times faster without the copy, from decode to large prefill batches, on B300 and GB300.
