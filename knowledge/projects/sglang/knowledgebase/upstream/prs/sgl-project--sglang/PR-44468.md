# [Fix] attention: Ignore inactive splits when merging split-KV verify outputs

[Upstream PR](https://github.com/sgl-project/sglang/pull/44468) · state: open · merged: False

## Original PR description

## Motivation

In `verify_splitkv.py`, stage 1 marks an inactive split by writing `-inf` to its LSE, but it never writes that split's `Att_Out`. Stage 2 still loads the scratch and multiplies it by a zero weight, so a NaN left over in the buffer turns into a NaN in the output (0 × NaN = NaN). Separately, when every prefix split is empty, `exp(-inf - (-inf))` is itself NaN.

I haven't seen this happen on its own in a running server, but it reproduces every time the scratch holds NaN. The output shouldn't depend on what an unused buffer happened to contain.

## Changes

All in `_verify_combine_stage2`:

- skip the load for splits whose LSE is `-inf`;
- if every split is empty, use zero weights and guard the 0/0.

No extra memory and no change to the launch config.

## Tests

The new test fills the scratch with NaN, then checks a 1-token prefix and an empty prefix (expected 3/4/5 and 4/5/6) in both eager mode and CUDA graph replay. On main, all 12,288 outputs are NaN for the 1-token case. With this change `test_verify_splitkv.py` passes 10/10 on H20.

## Notes

This kernel is only dispatched on gfx95 today. #39316 would turn it on for CUDA by default, which makes this hardening matter more. cc @HaiShaw @chuyeh @1am9trash
