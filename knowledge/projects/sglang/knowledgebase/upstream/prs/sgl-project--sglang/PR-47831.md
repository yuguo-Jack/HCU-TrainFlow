# [Feat] diffusion: support BRIA Fibo 2.0 generation and editing

[Upstream PR](https://github.com/sgl-project/sglang/pull/47831) · state: open · merged: False

## Original PR description

> Reopened as one PR after #46580 was reverted in #48054: the model half alone was 2126 lines that nothing in the serving path used. Per that revert note, the transformer and the pipeline that serves it now land together.

## Motivation

Add [BRIA Fibo 2.0](https://huggingface.co/briaai/Fibo-2.0-edit-turbo) to SGLang Diffusion. Fibo 2.0 is an 8B flow-matching model that both generates and edits images in the FLUX.2 VAE latent space: Qwen3-VL-4B encodes structured JSON captions, a two-layer Perceiver resamples those features into 256-512 "gist" tokens, and five transformer blocks additionally cross-attend to Qwen3-VL's internal layers. `Fibo-2.0-edit-turbo` is distilled for 4-step, guidance-free editing; `Fibo-2.0-dev` serves 30-step generation and editing with classifier-free guidance.

The weights are released under CC BY-NC 4.0 and require accepting BRIA's license on Hugging Face, which is why the end-to-end test is opt-in.

## Modifications

**Model**
- `runtime/models/dits/bria_fibo2.py`: the Fibo 2.0 transformer. It keeps the Z-Image single-stream block and adds a Perceiver resampler, five injection blocks with gated cross-attention, per-token noisy/clean modulation, three-axis RoPE over the gist, image and context-image planes, and patchify/unpatchify around the FLUX.2 latent layout.
- `configs/models/encoders/bria_fibo2.py`: builds the six text bundles from fifteen Qwen3-VL hidden states, each normalized to unit RMS per token before concatenation. The in-tree text tower returns one hidden state per decoder layer, one fewer than the reference, so the reference layer indices are shifted and the tuple length is asserted, turning a future collection change into an error instead of silently wrong conditioning.
- Parameter names match the checkpoint one to one; q/k/v stay unfused, because an injection block reads a 7680-wide text bundle through a 3584-wide query.

**Pipeline and serving**
- `configs/pipeline_configs/bria_fibo2.py` + `runtime/pipelines/bria_fibo2_pipeline.py`: one pipeline serves both paths, since sglang resolves the pipeline class from `model_index.json` and both checkpoints declare the same one.
- `model_specific_stages/bria_fibo2/source.py`: VAE-encodes every reference image into its own clean latent in `batch.source_latents`, the field the in-tree LLaDA edit model already uses; the images can have different sizes, so they cannot be concatenated onto the sequence.
- `model_specific_stages/bria_fibo2/condition_encoding.py`: two stages, one text-only and one image-aware, each stepping aside for the other's requests. They stay separate stages so each keeps its own name and component-residency bookkeeping; wrapping one inside the other left the inner stage unregistered and its encoder on the CPU.
- Edit requests default to `TI2I` in `resolve_task_type`: images plus an instruction fit both I2I and TI2I, and the shared resolver otherwise refuses to choose.
- Caption handling mirrors the reference, and an edit prompt becomes one JSON object with a vision marker per image plus the instruction. Qwen3-VL sees the same crop the VAE encodes, shrunk to 768 pixels on the long side.
- A repaint mask greys out the marked region on the original image in `preprocess_vae_image`: the first hook that receives the batch, and the one that runs before the crops are taken. A mask applies to one image and must match its size; both are rejected otherwise.
- Decoding reuses the FLUX.2 VAE chain, including its BatchNorm latent statistics, and the timestep schedule uses the FLUX linear shift computed from the image token count. The released checkpoints ship no separate `tokenizer`, so the pipeline exposes the one its processor carries.

**API**
- `POST /v1/images/edits` declared a `mask` upload and dropped it, so a masked edit silently ran as a plain edit. It is now saved and forwarded as `SamplingParams.mask_path`, the counterpart of `image_path`.

**Docs**
- `docs/cookbook/diffusion/Fibo/Fibo-2.0.mdx` with a command builder and the editing, masked and multi-reference requests.

## Limitations

- Single GPU: the new blocks do not implement sequence, tensor or Ulysses parallelism yet.
- Text-render hint images (`text_images` / `fonts`) are not supported yet; captions carrying `text_render` entries are accepted, they are just not turned into images.
- Requests whose prompts would need different gist-token counts in the same batch are rejected; send them as separate requests.
- Cache-DiT and the other diffusion acceleration features are not wired up for this model.
- Latents stay in float32 between steps, as in the reference.
