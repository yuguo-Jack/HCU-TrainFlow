# [Fix] batch-invariant: restore the dispatcher state when a scope exits

[Upstream PR](https://github.com/sgl-project/sglang/pull/48061) · state: open · merged: False

## Original PR description

Stacked on #48028 (`oss-sync-5cf60d009b`), which this pull request is opened against; only the top commit is this change. Review the two together or merge #48028 first.

## Motivation

`set_batch_invariant_mode()` snapshots the module globals on entry and assigns them back on exit. That is wrong whenever the scope starts with batch-invariant mode already enabled: `enable_batch_invariant_mode()` destroys the existing `torch.library.Library` and registers a fresh one, so the snapshot points at a destroyed library. On exit `_batch_invariant_MODE` reads `True` while the aten overrides (`mm`, `addmm`, `_log_softmax`, `mean.dim`, ...) are gone.

Concretely, with #48028 applied:

```python
enable_batch_invariant_mode()
with set_batch_invariant_mode(False):   # or a nested set_batch_invariant_mode()
    ...
# is_batch_invariant_mode_enabled() -> True, but torch.mm runs the default kernel
```

and a prior `enable_batch_invariant_mode(enable_bmm=False)` comes back with the Triton `bmm` patched in, because the inner enable defaulted `enable_bmm=True` and the snapshot cannot express "restore the previous registration".

## Modifications

- `set_batch_invariant_mode()` remembers two facts on entry: whether the mode was on, and whether `torch.bmm` was patched (`_original_torch_bmm is not None`).
- In `finally`, if either differs from the current state, it calls `disable_batch_invariant_mode()` and, when the mode was on before, `enable_batch_invariant_mode(enable_bmm=<previous>)`. State is restored through the same functions that build it, so the restored library is a live registration, `enable_bmm=False` round-trips, and an unchanged active registration is left alone.
- The enable/disable call moved inside the `try`, so a failure there also unwinds.
- New CPU unit test `test/registered/unit/batch_invariant_ops/test_batch_invariant_context.py` (registered to `base-a-test-cpu`, ~5 s). A fixture points the dispatcher at the CPU key with tiny CPU replacements (`a + b`) and checks `torch.mm`, `torch.bmm` and `torch.ops.aten.bmm.default` dispatch before, inside and after plain, failing, repeated and nested scopes, with `torch.bmm` patching on and off.

Behaviour inside the scope is unchanged; only what the scope leaves behind changes.

## Accuracy Tests

No model output changes. The new test is the regression check:

```
pytest test/registered/unit/batch_invariant_ops/test_batch_invariant_context.py -q
```

20 passed on this branch; on #48028 alone 16 of the 20 fail (every case that starts with the mode enabled or nests a scope). The existing `test_batch_invariant_ops.py` only enters the scope from a disabled state and is unaffected.
