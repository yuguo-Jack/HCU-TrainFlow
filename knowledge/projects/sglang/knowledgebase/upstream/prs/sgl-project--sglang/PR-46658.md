# [Fix] elementwise: Avoid data-dependent token-count guards in sigmoid-mul launchers

[Upstream PR](https://github.com/sgl-project/sglang/pull/46658) · state: closed · merged: True

## Original PR description

## Motivation

`fused_sigmoid_mul` and `_launch_fused_gate_sigmoid_mul` pick their launch config
in Python with `num_tokens >= 1024`. Under `torch.compile(fullgraph=True)` with an
unbacked token count (e.g. `torch._dynamo.mark_unbacked` on the token dim), Dynamo
fails with `Could not guard on data-dependent expression u0 >= 1024`. Hit in the
Qwen3.5 attention output gate and shared-expert gate.

## Modifications

- Wrap both checks in `torch.fx.experimental.symbolic_shapes.guard_or_false`.
- Backed sizes (eager, and `torch.compile` without unbacked dims) evaluate the
check exactly as before. Unbacked sizes take the small-batch config instead of
failing to trace. The threshold only selects `BLOCK_H` / `num_warps`, so outputs
are unchanged either way.

## Accuracy Tests

Not applicable. Only the launch config can change, and only for unbacked sizes.

## Speed Tests and Profiling

Not applicable. Eager and backed-shape configs are unchanged.
