# [Fix] [XPU] nightly: Fix rerank, zimage, flux2 and EAGLE parity

[Upstream PR](https://github.com/sgl-project/sglang/pull/44100) · state: closed · merged: True

## Original PR description

## Motivation

Four tests fail in the Intel XPU nightly on `sglang-kernel-xpu==0.4.0`:

| Test | Suite | CI error |
|---|---|---|
| `test_xpu_rerank` (exit -9) | 1-GPU | `RuntimeError: store_cache only supports k/v dtype in {fp16, bf16, uint8}; got Float` |
| `test_xpu_zimage_turbo` (exit 1) | 1-GPU | `fixture 'perf_results' not found` |
| `test_spec_eagle_parity` (exit 1) | 1-GPU | `torch.OutOfMemoryError: XPU out of memory. Tried to allocate 2.25 GiB` |
| `test_xpu_flux2_dev` (exit 1) | 4-GPU | `fixture 'perf_results' not found` |

Seen in e.g. `nightly-xpu-kernel-wheel-1-gpu` [run 38281560127 / job 114919788483](https://github.com/sgl-project/sglang/actions/runs/38281560127/job/114919788483) and the kernel-main [run 38299359135](https://github.com/sgl-project/sglang/actions/runs/38299359135).

The workflow split that was originally in this PR moved to a separate PR.

## Modifications

- `test_xpu_rerank.py`: sgl-kernel-xpu 0.4.0 `store_cache` rejects fp32 K/V, and the bge-reranker-v2-m3 cross-encoder runs fp32. Per review, `memory_pool.py` is left unchanged because more XPU KV cache dtypes are being upstreamed. `TestXPUCrossEncoderRerank` is skipped (`@unittest.skip` with the error and a re-enable note) until then. `TestXPUDecoderRerank` (bf16) still runs.
- `test/registered/xpu/conftest.py` (new): re-export `perf_results` so `DiffusionServerBase`'s autouse fixture resolves, same as `test/registered/amd/conftest.py`.
- `test_xpu_zimage_turbo.py`, `test_xpu_flux2_dev.py`: pass `load_time_ms=diffusion_server.load_time_ms` to `_validate_and_record`; it became mandatory in #39206, so without it the tests fail with `Load duration missing or invalid: None` once the fixture resolves.
- `test_xpu_flux2_dev.py` + `perf_baselines/xpu_b60.json`: flux2 then fails with `Testcase 'flux2_dev_image_t2i' not found in .../xpu_b60.json`, because `_validate_and_record` requires a scenario and always applies the e2e/load guards even with `run_perf_check=False`. Added a `flux2_dev_image_t2i` scenario and set `SGLANG_DIFFUSION_SYNC_STAGE_PROFILING=1` via `env_vars` on this case only, so its step timings record device time like the other `xpu_b60.json` scenarios. Values are the max over 3 local runs on 4x Arc Pro B70 (denoise spread <0.5%); `zimage_image_t2i` in the same file already serves the B70 nightly. The multimodal-gen XPU suite (`1-gpu-xpu`) does not run this case.
- `test_spec_eagle_parity.py` (`TestEagle3ParityXPU` only): `mem_fraction_static = 0.70`. XPU captures target-verify (2.78 GB), draft-decode (1.76 GB) and draft-extend full graphs; at 0.80 the 2.25 GiB draft-extend `attn_logits` buffer OOMs at capture, and at 0.75 capture succeeds but the first prefill hits `UR_RESULT_ERROR_OUT_OF_RESOURCES`.

## Accuracy Tests

Reproduced locally on Arc Pro B70 with `intel/sglang-dev:latest-kernel-main` (sglang-kernel-xpu 0.4.0, torch 2.14.0+xpu); each test run separately (CI runs files serially):

| Test | Before | After |
|---|---|---|
| `test_xpu_rerank` | `store_cache ... got Float`, server killed | 1 passed (decoder), 1 skipped (fp32 cross-encoder) (51 s, Arc Pro B60) |
| `test_xpu_zimage_turbo` | `fixture 'perf_results' not found`, then `Load duration missing` | 1 passed (66 s) |
| `test_spec_eagle_parity` | OOM `Tried to allocate 2.25 GiB` | 1 passed, 1 skipped (CUDA-only) (271 s) |
| `test_xpu_flux2_dev` (4-GPU) | `fixture 'perf_results' not found`, then missing `xpu_b60.json` scenario | 1 passed (144 s), `avg_denoise=952.57ms` vs baseline 952.30 ms |

Not covered here: `test_dflash_intel_xpu` (1 of 179 cases, `test_finish_stop_regex_str`, intermittently gets `finish_reason: length`).
