# [Feat] entrypoints: add a chat encoding adapter registry

[Upstream PR](https://github.com/sgl-project/sglang/pull/45300) · state: closed · merged: True

## Original PR description

## Summary

Split out of #42844 to land the registry separately from the tml-renderers integration.

- Introduce a chat-encoding adapter registry: `ChatEncodingAdapter` / `ChatEncodingOutputAdapter` protocols, a frozen `ChatEncodingAdapterContext`, and a `{spec: {backend: builder}}` registry (`chat_encoding_adapters.py`) used by `serving_chat` and `serving_responses`. Handlers build one adapter per chat encoding spec at construction; unregistered specs fall through to the existing branches.
- Move the inline `chat_encoding_spec == "inkling"` prompt-encoding branch into a legacy `InklingChatEncodingAdapter`. Its `output` is `None`, so output parsing stays with the registered text parsers exactly as before.
- The context carries what current and upcoming adapters need: tokenizer, reasoning/tool-call parser selection, chat output hooks, `hf_config`, `model_path`, `revision`, and a `backend` selector (`"builtin"` by default; an unregistered backend fails at startup with the available list).

## Behavior: zero change

The same 10 unit-test files run on main and on this branch produce identical outcomes for all 825 test ids (the only 12 failures are a pre-existing environment issue in `test_function_call_parser.py::structural_tag`, identical on both sides). Dispatch seams verified path by path: encode, boot-time effort default (same failure mode on a bad env value), media-collection set, stream/non-stream fall-through, Responses item ordering, non-registered specs building no context and making no `get_model()` call, and `skip_tokenizer_init` behavior.

One test-fixture adjustment: three `InklingReasoningEffortTest` fixtures construct the handler with `object.__new__` and bypass `__init__`, so they now inject the adapter directly; assertions unchanged.

## For the next tenants

- A follow-up PR swaps the legacy Inkling adapter's internals to delegate rendering/parsing to `tml-renderers` (the #42844 integration, rebased onto this base).
- A second encoding backend family can register builders under `backend="recipe"` without touching the serving layer. When a producer for that opt-in lands, backend validation must precede the unregistered-spec early return, and checkpoint file resolution should follow the explicit `model_path`/`revision` contract.
- Offline encoding (`encode_simple_chat`) does not go through the registry.
