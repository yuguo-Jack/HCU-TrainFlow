# [Feat] systemone: serve Kev pointer head decision models

[Upstream PR](https://github.com/sgl-project/sglang/pull/45413) · state: closed · merged: True

## Original PR description

## Motivation

[Kev](https://huggingface.co/collections/jaredpalmer/kev) is an open family of decision models that implements the System One API, and users want to serve it next to other decision checkpoints on SGLang. None of its checkpoints start today. Kev-27B names `Qwen3_5TextModel` and ships no LM head, and Kev-9B, Kev-4B, and Kev-0.8B are LoRA adapters with no model config. All of them answer from a pointer head in `head.pt` that compares the final hidden state at each option's closing token with the one at the last token of a per-question prompt, so the label scoring of `/v1/decisions` cannot reproduce them.

## Changes

- `ModelConfig` detects a `Qwen3_5TextModel` checkpoint with a `head.pt`, reads it with `weights_only=True` and the reference defaults for older fields, refuses head settings the per-question prompt cannot serve, and serves it with the text-only `Qwen3_5ForCausalLM`.
- When a checkpoint's config fails to load, `get_config` checks for a Kev adapter (`head.pt` plus `adapter_config.json`) and returns the text config of the base and revision that `head.pt` pins, so the weights load from that base. Adapters trained on a BF16 backbone, which the reference applies unmerged, and bases other than Qwen3.5 are refused with a message.
- In embedding mode the text-only class skips the LM head, loads the backbone from either layout, merges each LoRA delta into its base weight in FP32 with one rounding, fails if an adapter factor matches no base weight, and returns logits from a new FP32 `PointerPooler` at the calibrated temperature.
- `/v1/systemone` renders each question as the reference encoder does (delimiter tokens, escaping of delimiter-like text, flattened JSON states, options in request order) and sends one embedding row per question with a one-question decision layout.
- The Clef path's tokenizer guard, warmup, and server defaults now also cover Kev (embedding mode, no radix cache, chunked prefill, or CUDA graphs, and TP and PP fixed at 1). Clef behavior and messages are unchanged.
- A Kev cookbook page with every size, a nav entry, a homepage card, and mentions on the decision models page.

## Validation

```bash
sglang serve --model-path jaredpalmer/kev-27b
sglang serve --model-path jaredpalmer/kev-9b
sglang serve --model-path jaredpalmer/kev-4b
sglang serve --model-path jaredpalmer/kev-0.8b
```

- Prompt ids, decide positions, and option ends match the reference encoder on 17 cases for each size's tokenizer, including 255 options, a 29k token state, escaped delimiters, and both size limits at their exact boundaries.
- Against the reference implementation in FP32 on 13 request shapes, the largest probability difference is 0.015 for Kev-27B, 0.015 for Kev-9B, 0.005 for Kev-4B, and 0.009 for Kev-0.8B, with no change of top answer among the questions with a clear margin, inside twice the reference's own BF16 against FP32 difference plus 0.01 for each size. Response fields match the reference formulas to its four decimal rounding.
- The TypeSafe Python SDK example from the model card runs unchanged with only the base URL set.
- Refusals return 400 for generation, chat, `/v1/decisions`, `/encode`, images, `chat_template_kwargs`, a LoRA model name, a state over the reference limit, and a prompt over one prefill, also under `--allow-auto-truncate`. `--tp-size 2`, the Kev-27B `v1-lora` revision, and Kev-0.5B fail at startup with a message.
- For each size, 64 concurrent requests with a quarter dropped mid request all complete, the server stays healthy, and later answers equal the sequential ones.
- Qwen3.5-35B-A3B on `/v1/systemone`, `/v1/decisions`, and `/generate`, and Clef-Flash on `/v1/systemone`, give byte equal responses on main and on this branch.
- New cases in the existing System One and config loading unit suites fail on main. The affected decision, System One, config loading, model config, and Qwen3.5 suites pass, with the one remaining failure also failing on main. Pre-commit passes.

## Limits

- Each question's prompt must fit one prefill, 16,384 tokens by default, while the reference accepts states of up to 65,536 tokens. On one H200, raising `--max-prefill-tokens` toward that limit lets a large concurrent batch run out of memory, because the activation reserve does not grow for unchunked prefills, so the docs do not recommend it.
- The state is prefilled once per question, without prefix reuse across the questions of a request.
- Kev-27B v1 and Kev-0.5B are not served.
- Answers can vary slightly with batch composition, as on `/v1/decisions`.
- The docs checks that need Node were not run locally.
