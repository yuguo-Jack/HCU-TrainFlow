# [Fix] multimodal: Clear VLM embedding cache on flush

## Motivation

The scheduler-side VLM embedding cache controlled by `SGLANG_VLM_CACHE_SIZE_MB` was not cleared by `flush_cache()`.

As a result, cached embedding tensors remained referenced even after `current_platform.empty_cache()` was called. This could:

- prevent colocated workloads from reclaiming the memory when switching from rollout to training;
- reuse stale multimodal encoder outputs after model weights are updated.

## Modifications

- Clear `mm_schedule.embedding_cache` during a successful, fully-idle scheduler flush.
- Clear embedding references before trimming the device allocator cache.
- Update the `/flush_cache` docstring to reflect that runtime caches include multimodal embeddings.
- Add a unit test verifying that the embedding cache is cleared before the allocator cache.

- augustuszzq · comment · 2026-10-15T14:26:48Z · [source](https://github.com/sgl-project/sglang/pull/36468#issuecomment-6194458893)

We hit this bug in an RL setup. This PR fixes a correctness problem, not only a memory problem.

The vision feature cache (`SGLANG_VLM_CACHE_SIZE_MB`, default 100 MB) keeps the encoder output of each image by image hash. `/update_weights_from_disk` with `flush_cache: true` and `/flush_cache` both log `Cache flushed successfully!`. Neither clears this cache. So after a weight update, an image that the server saw before still gets the encoder output of the old weights.

I ran the scripts below on SGLang `f7ea06e1` (`sglang-miles-v0.5.15-final`) with Qwen/Qwen3.5-0.8B on one GPU. The new weights have `model.visual.merger.linear_fc2.{weight,bias}` set to zero. Image A and image B are the same picture with one pixel changed, so they have different hashes.

Default cache:

```
original weights, image A              ' red'                         sum of output logprobs -0.012595
update_weights_from_disk /ckpts/zeroed 200 {"success":true,"message":"Succeeded to update model weights.","num_paused_requests":0}
zeroed merger, image A (cached)        ' red'                         sum of output logprobs -0.012595
zeroed merger, image B (new)           ' white'                       sum of output logprobs -1.339829
flush_cache 200
zeroed merger, image A after flush_cache ' red'                         sum of output logprobs -0.012595
update_weights_from_disk /models/Qwen3.5-0.8B 200 {"success":true,"message":"Succeeded to update model weights.","num_paused_requests":0}
original weights, image B (cached)     ' white'                       sum of output logprobs -1.339829
```

`SGLANG_VLM_CACHE_SIZE_MB=0`:

```
original weights, image A              ' red'                         sum of output logprobs -0.012595
update_weights_from_disk /ckpts/zeroed 200 {"success":true,"message":"Succeeded to update model weights.","num_paused_requests":0}
zeroed merger, image A (cached)        ' white'                       sum of output logprobs -1.339829
zeroed merger, image B (new)           ' white'                       sum of output logprobs -1.339829
flush_cache 200
zeroed merger, image A after flush_cache ' white'                       sum of output logprobs -1.339829
update_weights_from_disk /models/Qwen3.5-0.8B 200 {"success":true,"message":"Succeeded to update model weights.","num_paused_requests":0}
original weights, image B (cached)     ' red'                         sum of output logprobs -0.015162
```

With the cache on, image A still gets ` red`, the answer of the original weights, after the update to the zeroed merger and after `/flush_cache`. Image B still gets ` white`, the answer of the zeroed merger, after the update back. With the cache off, every answer follows the current weights.

On `main` (a50c17e979), the code looks the same. `Scheduler.flush_cache` (`python/sglang/srt/managers/scheduler.py:5381`) does not touch `mm_schedule.embedding_cache` (`python/sglang/srt/managers/mm_schedule.py:21`). I found no server code that calls `MultiModalStaticCache.clear()` (`python/sglang/srt/mem_cache/multimodal_cache.py:148`). The weight-update paths call `flush_cache` through `flush_cache_after_weight_update` (`python/sglang/srt/managers/scheduler_components/weight_updater.py:120`). So this PR also fixes the weight-update case when `flush_cache` is true. I did not run `main` or this PR.

# make_ckpts.py
"""Make two copies of Qwen/Qwen3.5-0.8B for the repro. Text weights are unchanged.

zeroed/  : model.visual.merger.linear_fc2.{weight,bias} set to zero
renamed/ : the same two tensors stored as model.visual.merger.linear_fc2_renamed.{weight,bias}
Usage: python make_ckpts.py <path to Qwen3.5-0.8B> <output dir>
"""
import json
import os
import shutil
import sys

import torch
from safetensors.torch import load_file, save_file

src, dst = sys.argv[1], sys.argv[2]
shard = "model.safetensors-00001-of-00001.safetensors"
targets = ["model.visual.merger.linear_fc2.weight", "model.visual.merger.linear_fc2.bias"]
state = load_file(os.path.join(src, shard))


def write(name, tensors):
    out = os.path.join(dst, name)
    os.makedirs(out, exist_ok=True)
    for f in os.listdir(src):
        if os.path.isfile(os.path.join(src, f)) and not f.endswith(".safetensors") and f != "model.safetensors.index.json":
            shutil.copy2(os.path.join(src, f), out)
    save_file(tensors, os.path.join(out, shard), metadata={"format": "pt"})
    index = {"metadata": {}, "weight_map": {k: shard for k in tensors}}
    json.dump(index, open(os.path.join(out, "model.safetensors.index.json"), "w"))


zeroed = dict(state)
renamed = dict(state)
for t in targets:
    zeroed[t] = torch.zeros_like(state[t])
    renamed.pop(t)
    renamed[t.replace("linear_fc2.", "linear_fc2_renamed.")] = torch.zeros_like(state[t])
write("zeroed", zeroed)
write("renamed", renamed)
print("wrote", os.path.join(dst, "zeroed"), os.path.join(dst, "renamed"))
```

# repro_cache.py
"""Vision feature cache after /update_weights_from_disk. Server: python -m sglang.launch_server
--model-path <Qwen3.5-0.8B> --port 30000 --disable-radix-cache (SGLANG_VLM_CACHE_SIZE_MB unset = 100).
Usage: python repro_cache.py <path to Qwen3.5-0.8B> <path to zeroed/>   (paths as the server sees them)"""
import base64
import io
import sys

import requests
from PIL import Image, ImageDraw

URL = "http://127.0.0.1:30000"
original, zeroed = sys.argv[1], sys.argv[2]


def image(variant):
    """A red circle. variant > 0 changes one pixel, so the image hash changes."""
    img = Image.new("RGB", (320, 256), "white")
    ImageDraw.Draw(img).ellipse((80, 48, 240, 208), fill="red")
    if variant:
        img.putpixel((variant, 0), (254, 254, 254))
    buf = io.BytesIO()
    img.save(buf, format="PNG")
    return "data:image/png;base64," + base64.b64encode(buf.getvalue()).decode()


def ask(variant, label):
    body = {"messages": [{"role": "user", "content": [
        {"type": "image_url", "image_url": {"url": image(variant)}},
        {"type": "text", "text": "What color is the circle? Answer in one word."}]}],
        "temperature": 0, "max_tokens": 8, "logprobs": True}
    r = requests.post(URL + "/v1/chat/completions", json=body, timeout=600)
    r.raise_for_status()
    choice = r.json()["choices"][0]
    lp = sum(t["logprob"] for t in choice["logprobs"]["content"])
    print(f"{label:38s} {choice['message']['content']!r:30s} sum of output logprobs {lp:.6f}")


def update(path):
    r = requests.post(URL + "/update_weights_from_disk", json={"model_path": path, "flush_cache": True}, timeout=1200)
    print("update_weights_from_disk", path, r.status_code, r.text)


ask(0, "original weights, image A")
update(zeroed)
ask(0, "zeroed merger, image A (cached)")
ask(2, "zeroed merger, image B (new)")
print("flush_cache", requests.post(URL + "/flush_cache", timeout=120).status_code)
ask(0, "zeroed merger, image A after flush_cache")
update(original)
ask(2, "original weights, image B (cached)")
```
