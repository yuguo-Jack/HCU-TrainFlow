# [diffusion] Fix TeaCache CFG state lifecycle and skip boundaries

[Upstream PR](https://github.com/sgl-project/sglang/pull/42422) · state: closed · merged: True

## Original PR description

Fixes #35054.

TeaCache used the previous CFG branch to decide when to reset request state. That discarded the positive cache during serial CFG, and kept the previous request's state on the negative CFG-parallel rank. This PR resets from the current branch and topology instead.

It also measures the Wan skip window in denoising steps rather than in local forward calls. Serial CFG, CFG parallel, and CFG gating (which stops running the negative branch after the gate step) now share one definition. Before, a CFG-gated run started skipping late, and could skip the final step that `end_skipping` should always compute. `TeaCacheParams` now uses `get_skip_step_range()`; the obsolete forward-count `get_skip_boundaries()` API is removed, and its tests now check denoising-step ranges.

Based on @Oxygen56's unmerged implementation in #35136. Adds regressions that call the production Wan methods with real tensors. They cover branch isolation, completed/interrupted requests, and the skip window under serial CFG, CFG parallel, and CFG gating.

Supersedes #42154 (branch renamed to follow the repository's branch naming).

> **CI note:** this changes the output of `wan2_1_t2v_1.3b_teacache_enabled`. Its server sends warmup requests with TeaCache before the test request, and on `main` the test request inherits their stale state. On the same GPU, the test's key frames differ between `main` and this PR (max abs pixel diff 211–228), while each tree reproduces itself exactly across runs. The case's H100 ground truth in `sgl-project/ci-data-diffusion` was produced with `main`'s behaviour and will likely need regenerating.

### Validation

**Unit:** the new lifecycle tests, run against upstream `main`, `main` with both fixes, and both fixes with this PR's step-based skip window reverted (Wan counts the window in forward calls again):

| Test | `main` | `main` + both fixes | both fixes, skip window in forward calls |
|---|---|---|---|
| `test_new_request_clears_completed_or_interrupted_state` | ❌ | ✅ | ❌ |
| `test_serial_cfg_preserves_both_branches_at_first_timestep` | ❌ | ✅ | ✅ |
| `test_skip_window_is_measured_in_denoising_steps` | ❌ | ✅ | ✅ |
| `test_wan_skip_window_follows_timesteps_under_cfg_gating` | ❌ | ✅ | ❌ |
| `test_wan_skip_window_matches_timesteps_on_each_cfg_rank` | ❌ | ✅ | ❌ |

`test_skip_window_is_measured_in_denoising_steps` checks the new `get_skip_step_range()` API itself, so only `main` fails it. `test_new_request_clears_completed_or_interrupted_state` also needs the step-based window: its CFG-parallel case relies on step 1 being inside the window.

Together with the other fix on top of `main`, the Spectrum/TeaCache lifecycle tests, existing Spectrum forecaster, MiniMax-H3 Spectrum, CFG gating/policy, DiT config boundary and sampling-parameter tests give 77 passed and 59 subtests passed. Repository pre-commit hooks pass.

**End to end** on B200 (Wan2.1-T2V-1.3B-Diffusers, 832x480, seed 42, guidance 3.0, Torch SDPA; compile/BCG/warmup off), comparing upstream `main` with `main` + both fixes.

*Request isolation:* a different 13-frame request runs first, then the 9-frame, 12-step target is compared with a fresh instance.

| Topology | `main` | `main` + both fixes |
|---|---|---|
| 1 GPU, serial CFG | crash: `size of tensor a (4680) must match … (6240)` (stale residual from the previous request) | bit-identical to fresh (frames and latents) |
| 2 GPU, CFG parallel | crash on the negative rank → other rank hangs until timeout | bit-identical to fresh |

*CFG gating:* 30 steps, serial CFG, compared with the per-step decisions of the ungated run.

| Window | Gate step | Window in forward calls | Step-based window (this PR) |
|---|---|---|---|
| 1.3B preset (start 5) | 3 | skipping starts at step 7 instead of 5 | same decisions as ungated |
| start 1, end −1, threshold 10 (stress: the L1 test never forces a compute) | 9 | **final step skipped** | same decisions as ungated; final step computed |

At the default thresholds, TeaCache's L1 test happened to compute the final step anyway, so the end-boundary miss only shows once the window alone decides.

*Cost:* 33 frames, 30 steps, 3 prompts × 3 requests each. TeaCache skips 30% of DiT forwards in both topologies: 1.35× (1 GPU) and 1.28× (2 GPUs, CFG parallel) median speedup, mean PSNR vs no cache 32.4 / 33.7 dB (worst prompt 23.8 / 23.4 dB). Repeated requests on the same instance were bit-identical.
