# [Fix] trtllm_mha: Pack the plan's page tables on the graphs-off path

[Upstream PR](https://github.com/sgl-project/sglang/pull/45667) · state: open · merged: False

## Original PR description

## Motivation

With `--enable-unified-memory`, trtllm_mha's graphs-off forwards read the iteration's translated page tables from its `IterationIds` plan. FlashInfer's XQA decode and fmha_v2 prefill are handed only the table's data pointer and take its row length from its width (`max_seq_len = width * page_size` for XQA, `block_tables.shape[1]` for fmha_v2); they ignore its strides.

The plan's table is packed when a graphs-off read is the first to build it. When an earlier reader in the same iteration is a captured CUDA graph, the table is built inside that graph's capture-stable buffer. If the batch's host-side sequence lengths make the table narrower than the buffer, the plan's table is a column view of a wider tensor. One plan serves a speculative iteration's draft steps, verify and draft extend, so graph-backed drafting followed by an eager draft extend reads such a view. Today that read stops on the assert that the tables are packed ("trtllm_mha reads its page tables as packed rows, but the plan's table is a strided view of a wider buffer").

This is reachable in serving: on SM90, Qwen3.5-9B with NEXTN on `--attention-backend trtllm_mha`, the non-overlap scheduler and `SGLANG_DISABLE_DRAFT_EXTEND_CUDA_GRAPH=1` stops on that assert on every unified-memory server. Under the overlap scheduler the draft plan carries no host-side lengths, so its table keeps the captured width and the assert does not fire.

## Modifications

- The graphs-off path in `TRTLLMHAAttnBackend` now packs both of its tables, full-attention and sliding-window, with `.contiguous()`: a copy only when the plan's table is such a view, the same tensor otherwise. The capture buffer and the plan's table are left as they are, and the assert goes.
- These tables stay as wide as the batch needs, while the captured and static tables are `max_num_pages` wide. XQA sizes its multi-block split from the width, so graphs-off decode can reduce in a different order and round differently from graphs-on decode and from the default pool: not bit-identical, but the same attention.

Test (CPU), `test/registered/attention/test_trtllm_mha_graph_metadata.py`: `test_unified_eager_reader_packs_a_graph_built_table` replaces `test_unified_eager_table_must_be_packed`. It builds the iteration plan's table inside a capture buffer (a 2 x 3 view with a row stride of 8), runs an eager draft extend on that plan, and checks that the page table is packed, equals the plan's rows and reads only the current pages, while the capture buffer and the plan's table are unchanged. A graphs-off first reader still gets the plan's own table without a copy. On main the test stops on the packed-rows assert; with this PR it passes.
