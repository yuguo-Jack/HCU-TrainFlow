# [Bugfix] Preserve routed expert history across KV retraction

[Upstream PR](https://github.com/sgl-project/sglang/pull/43966) · state: open · merged: False

## Original PR description

## Motivation

When a request is retracted, its sampled tokens and logprobs survive, but its routed experts are later read from recyclable KV-cache slots. Re-prefilling the prefix can overwrite those routes, especially across a weight update, so the final response can contain expert choices that did not produce the retained tokens.

## Modifications

Snapshot request-owned CPU routing rows before releasing KV slots. Repeated retractions append only newly accepted rows; final collection combines that history with the new suffix and respects `routed_experts_start_len` and stop truncation. Skip uncomputed initial prefill and discard history when an input-embedding restart discards the generated tokens.

The existing response path remains in use for requests without a saved history. This preserves expert-choice provenance; generation spanning weight updates still uses mixed policy versions.

## Accuracy Tests

On upstream `7224fce1b5e4`, the new CPU suite reports 9 failures and 6 passes. After the fix, all 15 cases pass. Another 78 related scheduler, retraction, weight-version, stop, logprob, Mamba-backup and routed-expert tests pass, plus 8 subtests.

Existing tests cover pausing and capture independently; these regressions connect cache-slot reuse to final response collection. New test contracts in `test_routed_experts_retraction.py`:

| Test | Contract |
| --- | --- |
| `test_reprefill_cannot_overwrite_routes_for_accepted_tokens` | Preserve original routes across slot reuse, including start offsets, with retained tokens and logprobs. |
| `test_multiple_retractions_append_only_new_rows` | Preserve routes across successive retractions and avoid reading a partially rebuilt prefix. |
| `test_no_uncomputed_or_empty_prefix_gather` | Skip uncomputed initial prefill and empty requested ranges; collect the first accepted output correctly. |
| `test_stop_truncation_crops_saved_history` | Return only rows belonging to the visible output. |
| `test_non_routing_requests_do_not_snapshot` | Requests without routing enabled incur no capture reads. |
| `test_no_retraction_preserves_existing_response_path` | Uninterrupted requests retain their existing routing values. |
| `test_embedding_restart_discards_routes_with_output_ids` | Restarted embedding requests return routes from the new generation. |
| `test_short_capture_fails_before_freeing_slots` | Reject incomplete snapshots before releasing request slots. |
| `test_overlap_weight_pause_finalizes_routes_before_snapshot` | Drain pending overlap results before saving the routes for retraction. |

GPU smoke passed on one B300 with a randomly initialized two-layer Qwen3 MoE (8 experts, top-2). With overlap enabled, two pause/retract/resume cycles produced the same 96 output tokens and all 412 expert IDs as uninterrupted generation (routing shape `103 × 2 × 2`). The maximum logprob difference was 0.003978 against a 0.005 tolerance. A request without routed experts also passed. CUDA graphs and radix caching were disabled for this smoke.

The smoke used public `radixark/miles:latest`, pinned to amd64 digest `sha256:296d5f3d9afad05249c34848aa7fafbe94b719473c0055df11f64e94de7b3aff`, with its disposable environment updated for current upstream: Torch 2.14.1, sglang-kernel 0.4.9, Transformers 5.19.0, and FlashInfer 0.7.1. Stale optional FlashInfer binary caches were removed so current kernels could be built. The 15 regression cases passed in both the original Miles image and the updated environment.

## Speed Tests and Profiling

No throughput benchmark run. History copies occur at retraction boundaries and final response assembly; repeated retractions avoid recopying the saved prefix.
