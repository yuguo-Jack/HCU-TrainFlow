# [Refactor] diffusion: Rollout controller as a scheduler-step plugin instead of mixins

[Upstream PR](https://github.com/sgl-project/sglang/pull/44603) · state: open · merged: False

## Original PR description

## Summary

Rollout stops being a scheduler / denoising-stage mixin: each latent stream of a rollout request gets a `FlowRolloutController` whose `transition` the loop passes into `scheduler.step`. Serving is untouched; rollout numerics do not change.

It supersedes the design in #37940; @niehen6174 is co-author on the derived commits. @JingwenGu0829 found the issues fixed in commits 13 and 14 (Rockdu/sglang#4) and is co-author on commits 13 to 15.

## How it works

- `FlowMatchEulerDiscreteScheduler.step(..., transition=None)` runs `transition or self._transition`. Loops pass `**rollout_step_kwargs(batch)`, which is empty for serving requests, so every scheduler keeps its serving call.
- Hooks in `rollout_hooks.py`: `prepare_rollout_if_enabled` (before the SP shard), `init_rollout_env_if_enabled`, `rollout_step_kwargs`, `finalize_rollout_if_enabled`; all no-ops for serving.
- Wired into generic `DenoisingStage`, Cosmos3 and LTX-2. A loop without a scheduler (MiniMax H3, next PR) passes its own `build_controller` and `ode_transition`.

The only intended change: bf16 models now return fp32 `dit_trajectory.latents` with the same values. The A/B predates commits 13 to 15, which the e2e below covers.
- miles-diffusion full e2e on `sglang-miles` plus this chain: every suite passes, bitwise equal to its standard.
