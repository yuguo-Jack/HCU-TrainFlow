# [Feature] Streaming ASR: sliding window, server-side VAD, and segment-streaming mode

[Upstream PR](https://github.com/sgl-project/sglang/pull/31055) · state: closed · merged: False

## Original PR description

Fixes https://github.com/sgl-project/sglang/issues/31053
## Motivation

SGLang's streaming ASR (Qwen3-ASR on `/v1/audio/transcriptions` with `stream=true` and the `/v1/realtime` WebSocket) had three gaps that this PR closes:

1. **Unbounded per-chunk cost.** Chunked streaming re-encoded the *entire* cumulative utterance on every chunk. Because a bidirectional audio tower cannot extend a KV cache over one growing clip, total compute grew quadratically (O(n²)) with utterance length, and the SSE path additionally materialized every cumulative WAV up front. A long-running microphone stream got progressively slower per chunk.

2. **No server-side VAD.** The `/v1/realtime` endpoint rejected `turn_detection: {type: "server_vad"}` outright — clients had to detect end-of-speech themselves and commit manually. An open mic either burned compute on silence or hit the buffer cap.

3. **No segment-streaming mode.** For models trained to transcribe fixed disjoint audio segments (Qwen3-ASR, mirroring vLLM's `qwen3_asr_realtime`), there was no mode that encodes each second of audio exactly once instead of re-encoding a sliding window.

## Modifications

Four self-contained feature/fix commits (feature-layer only — no engine/kernel/model-forward changes), plus a `[Docs]` commit:

**1. `[Feature]` streaming ASR: bound per-chunk cost with a sliding audio window**
- Adds `window_chunk_num` to the chunked streaming config. When buffered audio exceeds the window, the head whose transcript is already emitted is dropped; the emitted text conditions the next inference as the prompt prefix, so nothing is lost. Never-inferred audio is never dropped, so any append cadence is safe.
- New `compute_window_drop()` helper (unit-agnostic: bytes or samples) shared by the SSE and WebSocket paths; refactors `split_audio_chunks` into `decode_audio_mono` + `encode_wav`.
- Qwen3-ASR defaults to an 8-chunk (16 s) window; `0` keeps the old unbounded behavior.

**2. `[Feature]` /v1/realtime: server-side VAD (`turn_detection: server_vad`)**
- New `realtime/vad.py`: a silero-vad frame state machine (512-sample / 32 ms windows @ 16 kHz), ported from sglang-omni, with a lazy-loaded model and an injectable scorer for deterministic tests.
- Drives `input_audio_buffer.speech_started` / `speech_stopped` events and auto-commits each utterance at end of speech. Manual commits are rejected in VAD mode (per the OpenAI spec). Between utterances the buffer is trimmed to the prefix-padding window and inference is skipped, so an open mic idles indefinitely without burning compute or hitting the buffer cap.
- `session.update` turn_detection handling becomes partial-update aware (absent keeps current, explicit `null` disables) and validates threshold / padding / silence-duration and the required 16 kHz model rate.
- silero-vad ships as a new optional `asr-vad` extra; requesting `server_vad` without it returns a structured error with an install hint.

**3. `[Feature]` + 4. `[Fix]` segment-streaming ASR**
- New `--asr-streaming-mode {chunked,segment}` server arg and `SegmentStreamingASR`. Audio is cut into fixed disjoint segments (5 s for Qwen3-ASR); each segment is transcribed independently and the per-segment texts are concatenated, so each second of audio is encoded exactly once (no re-encoded window), at the cost of accuracy at segment boundaries.
- Adapter capability flags `supports_segment_streaming` / `segment_streaming_config`; falls back to chunked for adapters that don't support it. Wired into the SSE transcription stream.
- **Design correction (commit 4):** the first increment threaded segments through one growing engine streaming session (`user(audio) -> assistant(transcript)` rounds). That re-fed each turn's transcript back as context, and the model re-emitted the previous transcript instead of transcribing the new segment — segments 2..N all repeated segment 1. This was confirmed to be **model behavior, not an SGLang bug**: a direct HF-transformers probe (well-formed chat template, both audios embedded, greedy) reproduces the copy, and vLLM's resumable session would hit the same copy for Qwen3-ASR. Fix: transcribe each disjoint segment as a standalone request (bare template + that segment's audio only) and concatenate. This drops the `--enable-streaming-session` coupling; `close()` becomes a no-op kept for API symmetry.

The `/v1/realtime` WebSocket path stays on chunked mode by design; segment mode applies to the SSE path.

**Files:** `streaming_asr.py`, `segment_streaming.py` (new), `realtime/vad.py` (new), `realtime/session.py`, `serving_transcription.py`, `transcription_adapters/{base,qwen3_asr}.py`, `server_args.py`, `pyproject.toml` (+3 unit-test files). +1116 / −17 across 12 files.

**Docs:** new `docs_new/docs/advanced_features/streaming_asr.mdx` guide (chunked vs. segment, the `/v1/realtime` WebSocket, server-side VAD, `asr-vad` extra, event reference), wired into `docs.json` nav; `--asr-streaming-mode` added to the server-arguments reference.

## Accuracy Tests

Unit tests — **27/27 pass** (`test/registered/unit/entrypoints/openai/test_{streaming_asr,realtime_vad,segment_streaming}.py`): `compute_window_drop` boundary cases, cross-roll delta continuity, audio decode/encode round-trip; VAD start/stop offsets, prefix-padding, silence thresholds, multi-utterance, missing-silero hint; segment per-request shape, whitespace accumulation, routing-key propagation.

End-to-end — H100, `Qwen/Qwen3-ASR-0.6B`, FLEURS `en_us` clips (16 kHz). WER = word-level Levenshtein after lowercase/punctuation normalization.

| Path | Clip | WER | Notes |
|------|------|-----|-------|
| HTTP SSE **chunked** | en_us_1950 | 0.030 | full transcript |
| HTTP SSE **chunked** | en_us_1972 | 0.000 | exact |
| HTTP SSE **chunked** | en_us_1904 | 0.158\* | \*number-format artifact ("25 to 30 year" vs "twenty-five to thirty years"); transcript correct |
| HTTP SSE **segment** | en_us_1904 | 0.053 | one minor trailing "嗯。" on the short final segment (segment-boundary cost) |
| HTTP SSE **segment** | en_us_1950 | 0.061 | full transcript |
| HTTP SSE **segment** | en_us_1972 | 0.000 | exact |
| WS **manual commit** (chunked) | en_us_1950 | 0.030 | committed + completed |
| WS **server_vad** | en_us_1950 | 0.030 | 1 utterance; started/stopped/committed/completed all fire |
| WS **server_vad** | en_us_1904 | — | correctly split into **2 utterances** at the real pause after "communication channels"; boundary word clips ("channels"→"channel"), inherent to VAD segmentation |

All four code paths behave correctly on GPU. Segment-boundary artifacts (a word straddling a 5 s cut, a filler token on a very short final segment) are the documented, inherent cost of segment mode — which is exactly why chunked mode overlaps its window.

## Speed Tests and Profiling

The sliding-window change is a cost *reduction*: chunked per-inference audio is bounded to the adapter window (16 s for Qwen3-ASR) instead of growing with the whole utterance, turning total streaming cost from O(n²) to O(n·window). Segment mode encodes each second of audio exactly once (no re-encoded window). No dedicated throughput benchmark is included — the changes are in the entrypoint/streaming layer and do not touch the model forward path or kernels. `window_chunk_num = 0` preserves the previous behavior exactly.
