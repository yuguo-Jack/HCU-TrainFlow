# [diffusion] comfyui: split batched DiT calls into per-row requests

[Upstream PR](https://github.com/sgl-project/sglang/pull/43163) · state: closed · merged: False

## Original PR description

## Motivation

Fixes #43111.

ComfyUI puts CFG cond and uncond into one `diffusion_model` call whenever their shapes allow it and memory permits (for Flux, T5 is fixed length, so that is the normal case), and a latent with `batch_size > 1` is batched too. The ComfyUI executor crashed on the first such call:

```
RuntimeError: a Tensor with 2 elements cannot be converted to Scalar   (should_suppress_logs)
```

Fixing that line alone would not help, because the worker's comfyui path is per-sample: `ComfyUIPassThroughScheduler` takes `req.timesteps` as the step schedule, and Flux's `require_text_seq_lens` expects one seq len per row while the adapters send one per request.

**Depends on #43109, please merge that first** (the first two commits here are #43109). Once rows go through the per-run conditioning cache one by one, main's old key makes two rows with the same text but different reference latents (Qwen-Image-Edit) share a key, and the second row silently runs on the first row's reference image. `test_batched_rows_with_same_text_keep_their_own_reference` fails with this change on top of main's key and passes on #43109.

## Modifications

- `SGLDiffusionExecutor.forward`: when `x` has batch > 1, run each row as its own request through the existing single-sample path and `torch.cat` the outputs. `_row` slices tensors whose leading dim equals the batch (recursing into plain lists/tuples such as `ref_latents`) and passes everything else through (`transformer_options`, shared refs). MiniMax-H3 passes `x` as `[video, audio]` and is not split, matching ComfyUI's native H3, which only supports batch 1.
- Tests: one request per row with the right inputs and output order (Flux adapter); only batched values are sliced; batch 1 and list-shaped `x` are not split; same text with per-row reference latents keeps each row's own reference through the real cache path.

Limitation: a batched call now costs B worker round trips instead of one. True batching on the worker would need per-row timesteps and seq lens in the comfyui request contract; that is a bigger change and could be a follow-up.

## Accuracy Tests

CPU end-to-end: real ComfyUI KSampler (ComfyUI master 58b176f) with the plugin's `FluxExecutor` + `SGLDModelPatcher`, worker half in-process (real `bind_comfyui_session` -> `FluxPipelineConfig.prepare_pos_cond_kwargs` -> the DiT's `time_text_embed`), and a noise_pred that depends on each row's conditioning. The reference is the same run with ComfyUI batching disabled (or each latent row sampled alone):

```
before (main e2fbc6a):
cfg=3.5, batch_size=1: CRASH RuntimeError: a Tensor with 2 elements cannot be converted to Scalar
cfg=1.0, batch_size=2: CRASH RuntimeError: a Tensor with 2 elements cannot be converted to Scalar
after:
cfg=3.5, batch_size=1: OK, 8 worker requests, each latents (1, 64, 64); matches unbatched reference: True (max diff 0.00e+00)
cfg=1.0, batch_size=2: OK, 8 worker requests, each latents (1, 64, 64); matches unbatched reference: True (max diff 0.00e+00)
```

GPU: not run. I set up a 2-GPU sanity run (FLUX.1-dev in comfyui mode: a 2-row batched call through the real `FluxExecutor`, compared against each row run alone, plus the plugin's `test_flux_pipeline.py`), but no 2x L40S container was scheduled within 10 minutes, so I stopped it. Happy to run it if someone can trigger GPU CI.

Unit tests (CPU):

```
before fix: 2 failed, 4 passed   test_comfyui_adapters.py
after fix:  100 passed, 11 skipped (CUDA only), 3 xfailed   test_comfyui_{session,adapters,h3,generator,profile}.py, test_conditioning_cache.py
            12 passed   apps/ComfyUI_SGLDiffusion/test/test_h3_request.py
```

## Speed Tests and Profiling

Batch-1 calls are unchanged. Batched calls (CFG > 1, batch_size > 1) used to crash; they now make one worker request per row.
