# [Fix] Load FP8 KV-cache scales for Qwen3.5

[Upstream PR](https://github.com/sgl-project/sglang/pull/37446) · state: open · merged: False

## Original PR description

## Motivation

Fixes #37379.

When `--kv-cache-dtype fp8_e4m3` is used with
`--quantization-param-path`, Qwen3.5 failed during startup because its model
classes did not expose `load_kv_cache_scales`. The architecture mixes full
attention and GatedDeltaNet layers, so the implementation must only apply the
loaded factors to full-attention layers. Pipeline-parallel ranks also contain
placeholder layers for stages they do not own.

## What changed

- Added `Qwen3_5ForCausalLM.load_kv_cache_scales`.
- Skip GatedDeltaNet and pipeline-placeholder layers when applying factors.
- Populate `k_scale`, `v_scale`, `k_scale_float`, and `v_scale_float` for the
  Triton/FlashInfer paths.
- Added delegation through both Qwen3.5 conditional-generation wrappers.
- Added CPU unit coverage for skipping non-attention layers and wrapper
  delegation.

No open or historical PR references #37379 or this Qwen3.5 KV-scale-loading
fix (checked immediately before submission).

Hi @saichowdary007, I'm the issue author (#37379). The overall approach is correct — I had a nearly identical implementation in a local patch and validated it on L20 x8 / TP=8 with `Qwen3_5MoeForConditionalGeneration`.

A few notes:

**1. P1: `k_scale`/`v_scale` should be tensors, not floats**

`kv_cache_scales_loader` yields Python `float` values. The AITER backend calls `.reshape(1)` on `layer.k_scale` and `layer.v_scale`, so those two must remain tensors:

```python
layer.attn.k_scale = torch.tensor(scaling_factor)
layer.attn.v_scale = torch.tensor(scaling_factor)
layer.attn.k_scale_float = float(scaling_factor)
layer.attn.v_scale_float = float(scaling_factor)
```

(The `_float` fields are used by the Triton path and should stay as scalars.)

**2. `Qwen3_5ForConditionalGeneration` delegation is correct and needed**

Good catch adding it — that class was also missing in my local fix.

**3. Validation**

My local patch (same logic, duck-typed layer guard) on NVIDIA L20 x8: server starts without the `RuntimeError`, FP8 KV cache scales load correctly for all 12 attention layers, SSM layers silently skipped. Happy to re-test once the tensor fix is applied.

When Qwen3.5 runs with FP8 KV cache on gfx95 using the AITER backend, a prefix-free extend for the 256-dimensional attention heads enters the fused path in `aiter_backend.py:2350-2373`, which calls `.reshape(1)` on `layer.k_scale` and `layer.v_scale`. `kv_cache_scales_loader` returns Python floats, so these assignments replace the tensor-valued backend fields with floats and the first such request fails with `AttributeError: 'float' object has no attribute 'reshape'`; retain tensor values for `k_scale`/`v_scale` while keeping the scalar copies in the `_float` fields.
