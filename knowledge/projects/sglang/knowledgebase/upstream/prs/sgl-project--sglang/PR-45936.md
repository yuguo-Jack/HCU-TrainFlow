# [Feat] [AMD] minimax: Support MiniMax-M3.1-Flash on gfx950 with DSpark and fused kernels

[Upstream PR](https://github.com/sgl-project/sglang/pull/45936) · state: closed · merged: False

## Original PR description

## Motivation

Run MiniMax-M3.1-Flash on AMD Instinct MI350X / MI355X (gfx950) with DSpark speculative decoding, at TP 4 per server. The same paths serve AMD's Quark MXFP4 export of the model.

**Dependency stack:** this PR is stacked on #45925 (MiniMax-M3.1-Flash support) and targets its branch `minimax-m3.1-flash`, so the diff is AMD-only. Review #45925 first. Once it merges, retarget this PR to `main`.

## Modifications

- **Model override** (`model_overrides/minimax_m3_hip.py`): gfx950 defaults for the NVFP4 checkpoint and the Quark export.
  - Attention runs on the Triton backend, and the DSpark draft on Triton.
  - The MoE runner is AITER, with page size 128.
  - The KV format defaults to NVFP4 under DSpark.
  - The quick all-reduce level and AITER's tuned tables are set here too.
  - Guards: M3.1 NVFP4 on ROCm refuses TP above 4 (TP8 with attention DP produced runaway whitespace in GSM8K answers), and attention TP above the KV head count, which returned garbage on ROCm.
- **Weights**
  - Routed experts are requantized from NVFP4 to MXFP4 at load and run on AITER's FlyDSL fused MoE, with tables tuned for the M3.1 TP4 shapes.
  - The MXFP8 attention, dense and shared-expert projections are converted to FP8 at load and run on AITER GEMMs with tuned block-scale and rowwise tables. Up to 128 tokens they use a per-channel copy; above that, block scaling.
  - A small-M FP8 GEMM serves the smallest batches.
- **KV cache and attention**
  - Under DSpark, the cache is the packed NVFP4 KV and indexer-K pool (MSA-v1 layout, as on Blackwell), with Triton quantize/dequantize and a fused store.
  - Sparse decode runs on a gfx950 Gluon kernel. Prefill runs on a Gluon kernel from 2048 tokens and on AITER's Gluon paged attention below that. Indexer scoring is Triton.
  - `SGLANG_MINIMAX_M3_AMD_KV_FORMAT=fp8` selects an FP8 cache instead, which is the default for the Quark export.
  - HiCache copies of the packed pages run on HIP.
- **Fusions**
  - QK-norm, RoPE and the KV-cache write run as one kernel.
  - RMSNorm and SwiGLU write the FP8 input of the next GEMM directly.
  - The shared-expert output folds into the MoE reduction.
  - Up to 16 tokens, all-reduce + residual add + RMSNorm + FP8 quant run as one kernel on AITER's custom all-reduce, and so do router GEMV + top-k + expert sort.
- **All-reduce:** AITER custom all-reduce handles messages up to 2.4 MiB. Above that, at TP 4, a JIT-built quick all-reduce takes over: INT8 below 64 MiB, INT4 above, bitwise equal to sgl-kernel's. `SGLANG_ENABLE_MINIMAX_M3_AMD_QUICK_REDUCE_INT4=0` keeps INT8. Other world sizes, levels and dtypes fall back to sgl-kernel.
- **DSpark**
  - Draft attention runs on the Triton backend.
  - The Markov step bias (w1 gather + w2 GEMV) is one kernel.
  - The draft's context K/V for all layers is written through one block-FP8 GEMM plus one norm/RoPE/store kernel.
  - The verify argmax runs without gathering the logits across GPUs.
  - The draft step is queued before the host waits for the previous step's sequence lengths.
- **AITER integration:** two runtime patches, each applied only if AITER's function signature matches and otherwise left unpatched with a log line:
  - `aiter_moe_addend` folds an addend into AITER's stage-2 reduction.
  - `moe_sorting_small` hands AITER a presorted routing.
  - The tuned tables ship under `layers/quantization/aiter_tuned_configs` and are merged after AITER's defaults through its `AITER_CONFIG_*` variables.
- ROCm code lives in `_hip` modules or behind `is_hip` / gfx950 checks, so CUDA paths are unchanged.
- **Indexer CP for DSpark** (second commit, opt-in `SGLANG_MINIMAX_M3_INDEXER_CP=1`): the decode indexer's context partitioning now covers DSpark verify on the NVFP4 index cache.
  - Each rank scores a quarter of the index-K blocks for all four index heads in one tile; the merge picks exactly what the per-rank selector picks.
  - Candidates go straight into the head owner's IPC receive buffer instead of an all-gather. It engages from 12 verify requests.
  - Per layer at 64 requests x 110K context: 165.7 -> 84.0 us. AgentX c64 (3600 s, HiCache): 86,995 -> 90,140 tok/s/GPU.

## Accuracy Tests

On MI350X with ROCm 7.2.0, torch 2.9.1+rocm7.2, Triton 3.7.0 and AITER `acf8fdf93` (image `rocm/sgl-dev:v0.5.20-rocm720-mi35x-20260926`), with sglang-kernel 0.4.9 built for gfx950:

- **Publication revision `af6d50a85e`**
  - GPU unit suite: 23 gfx950 test files, **321 passed, 6 skipped, 828 subtests**.
  - Four-GPU all-reduce tests: 4 passed.
  - CPU model tests: 33 passed, 24 subtests.
  - pre-commit (every hook in `.pre-commit-config.yaml`) passes on all changed files.
- **Four-GPU TP4 serving smoke**, using the cookbook's AMD command:

| GSM8K (`sgl-eval`, max 8192 tokens) | NVFP4 KV (default) | FP8 KV |
|---|---:|---:|
| 1,319 questions, greedy | **96.13** | **95.75** |
| 600 questions, temperature 1.0, top-p 0.95, seed 0 | 95.83 | |

- **Image checks:** image-understanding checks pass, including rendered text in PNG and JPEG, shape counting, two-image order, small text in a 2048×1536 image, a 37×53 image, and 16 concurrent image requests.
- **Real DSpark acceptance during GSM8K:** about 3.7 tokens per step with NVFP4 KV (mean of decode-log samples).

Serving used `MiniMaxAI/MiniMax-M3.1-Flash` revision `9e7ebacac350497ad4a1272a2e817639bf11561c` with `SGLANG_USE_AITER=1` and these flags:

```
--tp 4 --reasoning-parser minimax-m3 --tool-call-parser minimax-m3 --speculative-algorithm DSPARK
--cuda-graph-backend-prefill breakable --fp8-gemm-backend aiter --chunked-prefill-size 32768
--max-running-requests 128 --cuda-graph-max-bs-decode 128 --mem-fraction-static 0.8
```

Greedy GSM8K on this stack varies between runs by about one point. For example, 96.29 / 96.59 at this revision with a pre-release draft checkpoint, and 95.9–96.9 on earlier revisions. AITER's stage-2 MoE kernels accumulate with atomics, so outputs are not bitwise deterministic run to run.

## Speed Tests and Profiling

Four MI350X GPUs, TP 4, NVFP4 KV, **DSpark acceptance simulated at 3 tokens per step** (`SGLANG_SIMULATE_ACC_LEN=3`, `match-expected`, `real-draft-token`). Real-acceptance throughput was not measured for this PR.

Decode throughput is output tokens/s per server, median over 2 crossed rounds × 2 GPU sets with 3 repeats each. Every column uses 150K-token distinct contexts, except 64 requests, which uses 64K.

| Concurrent requests | 1 | 2 | 4 | 8 | 16 | 32 | 64 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Output tok/s | 376 | 640 | 1,016 | 1,629 | 2,515 | 3,978 | 5,765 |

Prefill is the latency of one extend on a cached prefix, median of 9 repeats over 2 crossed rounds × 2 GPU sets:

| Cached prefix + new tokens | 0 + 32K | 100K + 2K | 100K + 8K | 200K + 8K | 100K + 32K |
|---|---:|---:|---:|---:|---:|
| Latency (ms) | 551 | 91 | 191 | 220 | 630 |

These numbers were measured on a branch with the same AMD code. It differs from this PR only by #45925's `_draft_context()` wrapper around the prefill KV injection, which is a no-op without attention DP. They describe this stack's throughput, not gains attributable to individual changes.

## Remaining validation and follow-ups

Re-validated at c9b64080b3 (rebased onto `minimax-m3.1-flash` 65db54509e, plus indexer CP), MI350X, ROCm 10:

- GSM8K 400 with DSpark 7, `SGLANG_MINIMAX_M3_INDEX_TOPK_FREQ=1`, indexer CP and HiCache: 0.9675. Accept length 4.765 over decode batches with 12+ running requests. Long shared-prefix prompts reuse the cached prefix.
- `test_minimax_indexer_cp` (134 subtests), `test_minimax_indexer_cp_ipc` (4 GPUs), `test_minimax_verify_topk_idx` (76), `test_minimax_m31_hicache`, `test_minimax_m31_model` (24).
- These runs set `AITER_CONFIG_GEMM_BF16` to a copy of the bf16 table without its 27 hipBLASLt rows: their solution indices belong to one hipBLASLt build, and on ROCm 10 they fail in verify graph capture (`HIPBLAS_STATUS_INVALID_VALUE`).


Not executed at this revision:

- MI355X. Earlier revisions of this AMD work were served on MI355X with both the NVFP4 and Quark MXFP4 checkpoints.
- The Quark MXFP4 checkpoint.
- The HiCache high-throughput recipe.
- An AgentX ladder.
- ROCm 10 images.
- The sglang-kernel 0.4.10 ROCm wheel pinned in `pyproject.toml`; validation used a gfx950 build of 0.4.9.
- CUDA. Its paths are untouched by this diff.
- PD disaggregation and attention DP.

The FP8 GEMM path launches AITER's split-K block-scale assembly kernel into an output that RMSNorm has already zeroed. This needs a local copy of the launcher, because AITER always memsets the output first. ROCm/aiter#6786 (draft) adds an `out_zeroed` argument. Remove the local launcher once the pinned AITER includes it.
