# [Feat] disaggregation: Support SWA hybrid models in decode radix tree

[Upstream PR](https://github.com/sgl-project/sglang/pull/45961) · state: open · merged: False

## Original PR description

## Motivation

Enable decode-side radix caching for hybrid models with sliding-window attention (SWA) and full-attention layers in PD disaggregation.

Full-attention KV retains prefix reuse and incremental transfer. Each request receives fresh SWA state from Prefill, without reusing SWA state across requests or storing it in decode-side L2/L3.

## Modifications

- Enable Full-only prefix matching for SWA hybrid models on Decode.
- Preserve the existing incremental Full KV transfer path while receiving the required SWA window from Prefill.
- Retain Full KV for reuse; keep SWA state request-local and release it after use.
- Build a Full-only decode host cache and reuse the existing per-request SWA capacity calculation.
- Apply the matching behavior consistently to both Python and Rust tree backends.

This PR covers SWA + full-attention models. Mamba support is outside its scope.

## Accuracy Tests

Tested MiMo-V2.5 with two matched 1P1D groups, each using Prefill TP4 and Decode TP4, based on main commit `d0a75654368a470d8484e3ea45b06e500fee57af`.

The baseline disables decode radix caching and decode L2. The candidate uses the Rust tree backend with Full-only decode L2 enabled. Prefill L2 is enabled in both groups.

Both groups use the same questions and generation settings: temperature 0, top_p 1, seed 0, max output 2,048 tokens, 32 evaluation threads, and thinking disabled.

| Dataset | Baseline | Candidate |
| --- | ---: | ---: |
| MMLU, 1,000 questions | 887/1,000 | 889/1,000 |
| GSM8K, 1,000 questions | 973/1,000 | 972/1,000 |

Both groups had zero request errors and zero empty responses.

MMLU had 3 baseline and 6 candidate truncated responses. GSM8K had none. No statistically significant paired accuracy difference was observed in these samples; these results do not establish numerical equivalence.

## Speed Tests and Profiling

Used the unmodified official `bench_multiturn.py` with the following workload:

- 100 sessions with an identical initial 98,304-token prefix.
- 114 turns per session, adding 1,024 input tokens and generating 128 tokens per turn.
- 11,400 requests per group.
- Average prompt length: 163,392 tokens.
- Final prompt length: 228,480 tokens.

Serving configuration:

- Each group uses Prefill TP4 and Decode TP4.
- Context length: 262,144; max running requests: 100.
- Page size: 64; KV cache dtype: FP8 E4M3.
- FA3 attention backend; CUDA graphs disabled.
- Prefill L2: 192 GB/rank in both groups.
- Baseline Decode: radix caching and L2 disabled.
- Candidate Decode: Rust radix tree with Full-only L2 at 16 GB/rank.

Both benchmark processes completed successfully. The following numbers are from the complete official benchmark results:

| Metric | Baseline | Candidate | Change |
| --- | ---: | ---: | ---: |
| Mean TTFT | 3,766.65 ms | 3,120.39 ms | -17.16% |
| Median TTFT | 2,169.03 ms | 1,717.82 ms | -20.80% |
| P90 TTFT | 7,878.15 ms | 6,621.82 ms | -15.95% |
| P99 TTFT | 8,805.21 ms | 7,527.54 ms | -14.51% |
| Mean TPOT | 82.83 ms | 88.37 ms | +6.68% |
| Mean request latency | 14.2866 s | 14.3434 s | +0.40% |
| Output throughput | 886.16 tokens/s | 882.36 tokens/s | -0.43% |

Decode rank-0 periodic samples showed:

| Metric | Baseline | Candidate |
| --- | ---: | ---: |
| Peak Full KV used tokens | 17,198,400 | 13,102,208 |
| Peak SWA used tokens | 22,400 | 22,400 |
| Peak running requests | 100 | 100 |
| Peak preallocation queue requests | 25 | 0 |

This run shows improved TTFT with higher TPOT and approximately unchanged output throughput.
