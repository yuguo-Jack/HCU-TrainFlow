# [Fix] diffusion: Give every SP rank the same Wan TI2V timestep

[Upstream PR](https://github.com/sgl-project/sglang/pull/45994) · state: closed · merged: True

## Original PR description

## Motivation

Wan2.2-TI2V-5B with an image input uses a per-token timestep: 0 on the conditioned first frame and `t` everywhere else. `expand_wan_ti2v_timestep` built that tensor only on SP rank 0. The other ranks took a different branch, so the ranks disagreed in two ways:
- The first-frame mask is in the DiT dtype, so rank 0 multiplies by a bf16 `t`. Integer timesteps above 256 do not all fit in bf16 (999 -> 1000, 995 -> 996). Ranks > 0 used the exact `t`. With the default 50 steps and shift 5, 37 of the 50 timesteps differ by 1–2, and the sinusoidal time features at those steps differ by about 24% (relative L2).
- Ranks > 0 also kept `t` on the first-frame tokens.

Wan uses sequence shard by default. Under sequence shard every rank holds the full latents, embeds the full-length timestep, and applies that `temb` to every token in the output norm after the all-gather. So with SP > 1 the ranks produce different noise predictions for the same tokens, and their copies of the latents drift apart over the steps. The model input for each token comes from the copy on the rank that owns its shard, but rank 0 steps its own copy with its own prediction. The video that rank 0 returns therefore mixes the two ranks' trajectories, and SP output does not match single-GPU output beyond reduction-order noise.

This affects Wan2.2-TI2V-5B with an image (`should_apply_wan_ti2v`) and SP > 1: explicit `--ulysses-degree`/`--ring-degree`/`--sp-degree`, or 4+ GPUs with default flags (CFG parallel 2 x SP). The rank-0-only branch has been there since TI2V SP support was added in #12926. It has made the ranks' latents drift apart since Wan switched to sequence shard by default in #19311. The original comment there says the rounding is applied "consistently before it's used by any rank", but the non-zero-rank branch used the unrounded value. The existing helper test uses `t=1000` in fp32, which does not exercise the rounding, and the only TI2V CI case (`wan2_2_ti2v_5b`) runs on one GPU.

## Modifications

`wan_ti2v.py`: every rank now expands the timestep from its own mask. Under sequence shard each rank has the full mask, so all ranks build the same full-length timestep. Under time shard each rank has its own mask shard (rank 0 holds the zeros), so the ranks' timesteps concatenate to the single-GPU one. Single-GPU output is unchanged.

`test_wan_ti2v_helpers.py`: new test with `t=999` and a bf16 mask. It checks that both ranks match the single-GPU expansion under sequence shard, and that the time-shard ranks concatenate to it.

Follow-up, not changed here: the diffusers and original Wan2.2 pipelines build this tensor from a float32 mask, so they use the exact `t`. Removing the bf16 rounding would change single-GPU TI2V output and needs a GT refresh for `wan2_2_ti2v_5b`.

## Accuracy Tests

- `test_wan_ti2v_helpers.py`: on main, rank 1 differs from the single-GPU expansion on all 16 tokens under sequence shard (999 vs 0/1000), and the time-shard concatenation differs on rank 1's 8 tokens (999 vs 1000). Both pass with this PR. Rank 0's output is unchanged.
