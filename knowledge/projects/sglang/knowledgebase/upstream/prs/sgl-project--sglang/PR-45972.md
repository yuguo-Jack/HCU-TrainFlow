# [Fix] kimi_k3: Use uuid tool_call_id instead of history-count id

[Upstream PR](https://github.com/sgl-project/sglang/pull/45972) · state: closed · merged: True

## Original PR description

## Summary
Remove the `kimi_k3` special case in `OpenAIServingChat._process_tool_call_id` so Kimi-K3 gets the default `call_<uuid>` tool call id.

```python
if self.tool_call_parser == "kimi_k3":
    return f"{call_item.name}:{history_tool_calls_cnt + call_item.tool_index}"
```

## Why
- Kimi-K3's encoder treats tool call ids as opaque (the index comes from position), so it doesn't need the `name:idx` format. Only Kimi-K2's chat template requires `functions.{name}:{idx}`, and that path is unchanged.
- An id built from the history count repeats whenever the client sends a shorter history. Clients that dedupe `tool_use` ids (e.g. Claude Code) then drop the call.

## Test plan
- Added `test_kimi_k3_tool_call_id_unique_when_history_count_repeats`: two `_process_tool_call_id` calls with the same history count return different `call_` ids.
- Existing `test_kimi_k2_*_tool_call_id_with_history` tests still pin K2's positional `functions.{name}:{idx}` ids.
