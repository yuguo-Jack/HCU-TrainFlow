# [CI] [NPU] unit: Fix two stale NPU unit test assertions

[Upstream PR](https://github.com/sgl-project/sglang/pull/47377) · state: open · merged: False

## Original PR description

## Motivation

Two NPU unit tests asserted behavior that no longer matches the current implementation, so they were guaranteed to fail (or never exercised):

1. `test_fia_nz_without_mlapo_raises` in `test_npu_mla_preprocess.py` expected `is_fia_nz()` to raise when MLAPO is off. `is_fia_nz` now returns `SGLANG_USE_FIA_NZ` directly: FIA NZ is a cache-layout choice, not an MLAPO-only optimization, so models such as Kimi-K3 select it with MLAPO off. The old assertion always failed.

2. `test_rejects_non_ue8m0_scale_format` in `test_npu_mxfp8_linear.py` expected a `ValueError` from `process_npu_arch35_mxfp8_linear_weights`, but that function never had such a guard: plain block-FP8 checkpoints carry arbitrary fp32 scales and are requantized through `_layout_npu_arch35_e4m3_weights`, so the test only ever reached `layer.weight.data` on an empty stub.

These two test fixes are split out of #46759 so that PR only carries test-case additions.

## Modifications

- `test/registered/unit/npu/attention/test_npu_mla_preprocess.py`: rename `test_fia_nz_without_mlapo_raises` to `test_fia_nz_without_mlapo_returns_true` and assert `is_fia_nz()` returns `True` with `SGLANG_USE_FIA_NZ=1` and MLAPO unset.
- `test/registered/unit/npu/quantization/test_npu_mxfp8_linear.py`: replace the never-raising reject test with `test_non_ue8m0_scale_format_uses_e4m3_requant_path`, asserting the e4m3 requant layout path is called once and the ue8m0 layout-only path is not.
- Promote both files' `register_npu_ci` suite from `stage-a-unit-test-npu` (nightly-only) to `base-a-test-npu` so the fixed tests now run in the PR pipeline.
