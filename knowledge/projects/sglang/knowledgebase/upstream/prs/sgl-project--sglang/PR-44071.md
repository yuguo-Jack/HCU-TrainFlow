# perf(sglang): avoid implicit host-device sync from torch.nonzero() (#9889)

[Upstream PR](https://github.com/sgl-project/sglang/pull/44071) · state: closed · merged: False

## Original PR description

## Summary
Fix sgl-project/sglang#9889.

Analyzed all three `torch.nonzero()` call sites flagged in the issue:

| File | Before | Fix |
|------|--------|-----|
| `gemma3_mm.py:212` | `(...).cpu().nonzero()` | already on CPU — no change needed |
| `janus_pro.py:479` | `image_token_mask.nonzero()` (on CUDA input_ids) | explicitly `.cpu()` before `.nonzero()` |
| `phi4mm_utils.py:84` | `(...).nonzero()` (seq_range from `torch.arange` on CPU) | already on CPU — no change needed |

Only `janus_pro.py` actually forces an implicit host-device sync today.
The other two call sites are already CPU-resident.  Making the sync
boundary explicit in the remaining case avoids accidental performance
regressions in future refactors.

## Test Plan
