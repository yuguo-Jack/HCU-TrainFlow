# [Feat] platforms: Let platforms default unset profile request fields

[Upstream PR](https://github.com/sgl-project/sglang/pull/47099) · state: open · merged: False

## Original PR description

## Motivation
`TokenizerControlMixin.start_profile` fills an unset `ProfileReq.with_stack` / `record_shapes` from `SGLANG_PROFILE_WITH_STACK` / `SGLANG_PROFILE_RECORD_SHAPES` (both default `true`) before the request leaves the tokenizer process. By the time a platform's scheduler-side profiler sees the request, "unset" and "explicitly true" are indistinguishable.
An out-of-tree platform may want server-wide capture defaults (for example, stacks and shapes off by default because they add noise to device traces, or a default `num_steps`) while still letting explicit `/start_profile` fields override them. Today that requires monkey-patching `start_profile`.
## Modifications
- Add `SRTPlatform.apply_profile_request_defaults(req: ProfileReq) -> None` to `sglang/srt/platforms/interface.py`. The base implementation is a no-op, so in-tree platforms behave exactly as before.
- Call it at the start of `TokenizerControlMixin.start_profile`, right after the request type is set and before the env-based normalization. The env vars still apply afterwards, so `SGLANG_PROFILE_WITH_STACK=false` / `SGLANG_PROFILE_RECORD_SHAPES=false` continue to force those options off.
- Add `test/registered/unit/managers/test_tokenizer_control_mixin.py`, which checks that a platform's defaults for unset fields reach the scheduler-bound request even though both env vars are `true`, both for `start_profile()` with no request and with an empty `ProfileReq()`.
## Testing
