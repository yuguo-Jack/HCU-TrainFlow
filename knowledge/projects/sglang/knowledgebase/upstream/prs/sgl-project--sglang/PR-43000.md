# [sgl-router] Serve DeepSeek-V4.1 Flash through sglang-processor

[Upstream PR](https://github.com/sgl-project/sglang/pull/43000) · state: closed · merged: True

## Original PR description

Adds DeepSeek-V4.1 Flash to sglang-processor and the router's `/generate` path. Stacked on #42999; the V4 support came in #42664.

## Modifications

- **Render:** `ChatFormatter::DeepSeekV41` (`render/models/deepseek_v41.rs`) renders V4.1 as `serving_chat.py` does, on Dynamo's V4.1 encoder. On top of the V4 message dump, it:
  - keeps text parts lists;
  - renders only the request tool fields the client set (`dsv41_tool_payload`);
  - adds the empty system turn only when request tools need it;
  - maps `reasoning_effort` to the encoder's 1-100 budget.

  Developer turns and media return an error, so hosts leave them to the engine: Dynamo renders developer turns as system turns.
- **Parsers:** V4.1's rows in `parser/models/deepseek_v4.rs`:
  - `deepseek-v41` reasoning (the spaced `<｜DSML｜ calls>` anchor);
  - `deepseekv41` tools (spaced DSML tags, string values unstripped).

  V4.1 also reuses V4's continuation-prefix and merged-turn task helpers.
- **Router:** renders V4.1 through the processor in place of its own unverified copy, so V4.1 chats forward `input_ids` and are served through `/generate`.

## Checks

- **Render:** 65 cases match SGLang's prompt text and token ids at the pinned V4.1-Flash revision. Two are marked known gaps, both developer-message cases. The float-formatting cases (`1e-06`) match.
- **Parsers:** the reasoning and tool fixtures replay SGLang's `ReasoningParser` and `FunctionCallParser`, and fail if V4.1's tag or stripping differences are removed.
- **Live:** V4.1-Flash on the cookbook B200 Low-Latency recipe, plus `--log-requests-level 3` and `--served-model-name`.
  - All 42 OpenAI-layer cases match Python.
  - Every chat and tool request served through `/generate` reaches the engine with an identical `GenerateReqInput`.
- `cargo clippy --workspace` in `rust/` and the router suites pass.
