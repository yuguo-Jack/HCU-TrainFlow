# fix(bench): Accept optional spaces in SSE data fields

[Upstream PR](https://github.com/sgl-project/sglang/pull/43641) · state: open · merged: False

## Original PR description

## Motivation

I was testing the benchmark clients against a local SSE server and hit a framing issue: `data:{...}` and `data:[DONE]` are valid SSE, but four request clients only strip `data: ` with a space. Without that space, the JSON decoder receives the field prefix and the request is marked unsuccessful.

The SSE spec makes that space optional: split at the colon, then remove one leading space if present. [Spec](https://html.spec.whatwg.org/multipage/server-sent-events.html#event-stream-interpretation).

## Modifications

- Accept `data:` with or without a following space in OpenAI completions, chat completions, Truss and native SGLang generate benchmark clients.
- Keep native generate parsing on bytes with `orjson`.
- Extend the existing registered loopback HTTP tests. JSON-event spacing and `[DONE]` spacing vary independently for each client.

This is independent of #37986 (SSE comments), #24255 (completion-token accounting), and #43209 (streamed server errors). Those behaviors are outside this change.

## Accuracy Tests

The tests call the actual request functions against a local HTTP SSE server, without replacing the parser or mocking request output.

```bash
PYTHONPATH=python python test/registered/bench_fn/test_bench_serving_reasoning_stream.py -q
```

On main at `3458c94fad9f346b8d650f9979bd4e82764a36ba`, the new tests reproduce 12 failing subcases: every combination with an unspaced JSON or `[DONE]` event. All four fully spaced controls and the 10 existing streaming/non-streaming tests pass.

With this patch: all 14 test methods pass, including all 16 new spacing combinations and the 10 existing tests.

The new cases check success, reconstructed text, output length, positive TTFT and one inter-token interval. CPU/HTTP only; no model, CUDA or GPU accuracy run. Local environment: macOS Apple Silicon, Python 3.13, PyTorch 2.14.1 and Transformers 5.19.0. Linux CI with the upstream environment remains pending.
