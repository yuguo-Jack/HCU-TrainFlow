# [Feat] comfyui: Free the SGLD worker's GPU memory when ComfyUI unloads the model

[Upstream PR](https://github.com/sgl-project/sglang/pull/44086) · state: open · merged: False

## Original PR description

Fixes #44084. Split out of #43536 per review (sleep/wake is a feature, not a fix).

## Summary

In integrated mode the DiT weights live in the SGLD worker, so ComfyUI's "Unload models" / "Free memory" (and its own unloads to make room for the VAE or a text encoder) never freed them.

- `SGLDModelPatcher.detach`, the end of every ComfyUI unload path, now puts the worker to sleep via `release_memory_occupation`.
- `ensure_executor` and `set_lora` wake it before the next use.
- `loaded_size()` reports the real size while the worker is awake and 0 while asleep, so ComfyUI actually considers it for unloading.
- Clones of the patcher share a worker token, so a patcher left over from a replaced worker cannot sleep the new one.

Limit: sleep only frees VRAM when the worker keeps the DiT resident (`dit_cpu_offload=False`, no layerwise offload). With the default CPU offload there is nothing to free.

## Dependency on #43536

The first commit is the VRAM accounting fix from #43536. `loaded_size()` returns `model_size()`, which is 0 for every model type except flux/lumina2 without it. Once #43536 merges this commit drops out on rebase; review the second commit here.

## Tests

`test/test_sgld_worker_sleep.py` (new): 10 tests (stubbed `comfy` / `folder_paths`, no ComfyUI install or GPU): detach sleeps the worker, `loaded_size` while awake/asleep, clone keeps the worker handle, sleep/wake scheduler requests, stale and dead worker cases, `ensure_executor` and `set_lora` wake a sleeping worker. 10/10 pass on CPU.

GPU check (1x L40S, real FLUX.1-dev worker, unloading a clone of the patcher): 24.3 GiB used awake, 1.6 GiB asleep, and the next forward woke the worker with a bit-identical output.

- niehen6174 · comment · 2026-10-14T09:47:27Z · [source](https://github.com/sgl-project/sglang/pull/44086#issuecomment-6165562671)

I think the direction is right, but it needs to depend on topology:
- Only take part in ComfyUI's memory management when the worker shares ComfyUI's GPU. On a different GPU, report 0 and make `detach` a no-op.
- Use the bytes the worker actually keeps resident on that GPU (after offload, TP and quantization) rather than the checkpoint size.
- A cheap first step is to release the worker's allocator cache at the end of each sampler run, so VAE decode gets that memory without moving any weights.

Could you also share timings for a sleep/wake cycle on a large model (e.g. H3), and confirm it works with merged LoRA and layerwise offload?


- OnePunchMonk · comment · 2026-10-14T18:17:27Z · [source](https://github.com/sgl-project/sglang/pull/44086#issuecomment-6175219113)

Partial results on MiniMax-H3 (fl2va, 1x H200, DiT resident, text encoder layerwise offloaded, `--performance-mode speed`):

| | |
|---|---|
| VRAM awake | 80.3 GB |
| VRAM asleep | 6.2 GB |
| Sleep, 1st cycle | 122.9 s |
| Sleep, 2nd cycle | 11.5 s |
| Wake (both cycles) | 5.0 s |
| Weight checksums before vs after wake | identical (text encoder, transformer, both VAEs) |
| Seeded generation before vs after wake | identical output hash |

The first sleep is much slower than the second. I have not confirmed why yet. These are single runs, not averaged.

Merged LoRA and layerwise offload runs are in progress, I will add them here when done.


- OnePunchMonk · comment · 2026-10-14T18:40:08Z · [source](https://github.com/sgl-project/sglang/pull/44086#issuecomment-6175643738)

Merged LoRA on MiniMax-H3 (same setup as above, `fal/MiniMax-H3-Realism-People-LoRA`, `--lora-merge-mode merge`, applied to 104 layers):

| | |
|---|---|
| VRAM awake | 80.5 GB |
| VRAM asleep | 29.9 GB |
| Sleep, 1st / 2nd cycle | 23.4 s / 2.0 s |
| Wake, 1st / 2nd cycle | 1.3 s / 1.4 s |
| Transformer checksum before vs after wake | identical (and different from the no-LoRA checksum, so the merge is in the weights) |
| Seeded generation before vs after wake | identical output hash |

So sleep/wake works with merged LoRA and the merged weights come back bit-exact. Note that asleep VRAM is 29.9 GB here versus 6.2 GB without LoRA. I have not looked into what is still resident yet. Single run, not averaged.

Layerwise offload results to follow.
