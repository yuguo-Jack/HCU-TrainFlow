# [Feat] SenseNova-U1: CFG parallelism on two GPUs (1.95x, bit-identical)

[Upstream PR](https://github.com/sgl-project/sglang/pull/45161) · state: open · merged: False

## Original PR description

## Motivation

Part of #37742 (the "Multi-GPU inference ... including CFG / sequence parallelism" item).
#40663 covers data-parallel replicas and states that CFG parallelism is not supported, so
this PR adds that part.

SenseNova-U1 runs classifier-free guidance by default (`guidance_scale=4.0`), so every
denoising step does two full backbone forwards: one over the condition prefix KV cache and
one over the empty-prompt unconditional cache. The pipeline config rejected `num_gpus > 1`
outright, so a second GPU could not help a single request. The official deployment stack
(LightX2V `neopp`) runs exactly this split, cond on CFG rank 0 and uncond on rank 1, and
reports ~1.97x on 2x H100.

Merging the two branches into one B=2 forward on a single GPU does not help at the
recommended 2K resolution: measured on H200 it is 1.7% slower per image (GPU-bound), so
splitting across GPUs is the lever.

## Modifications

Design:

- The stage stays `REPLICATED`: the scheduler already broadcasts each request to every rank
  and only the output rank replies. `t2i_generate` receives the CFG `GroupCoordinator` and
  splits the work by `rank_in_group`.
- Rank 0 prefills and denoises only the condition branch (including the `think_mode`
  decode), rank 1 only the unconditional branch, so the two prefix forwards also run
  concurrently.
- Each step: one local forward, then `all_gather` of the bf16 `v_pred` (25 MB at 2K, ~0.2 ms
  over NVLink). Every rank combines the two predictions with the unchanged serial code
  (`none` / `global` / `channel` / `cfg_zero_star`) and steps its own copy of the latent. No
  all-reduce of `g*cond + (1-g)*uncond`: that changes bf16 rounding and cannot express the
  norm variants.
- Steps outside `cfg_interval`: rank 1 skips the forward and rank 0 broadcasts the condition
  prediction.
- Noise comes from the per-request seed on each rank, so all ranks hold the same latent
  without a broadcast.
- `guidance_scale <= 1`: both ranks run the serial single-branch path (the runtime's
  documented behavior for CFG-off requests under CFG parallel).
- Failure handling: only rank 0 does prompt-dependent work (tokenization, condition prefill,
  think decode), so a long prompt can fail on rank 0 alone, e.g. OOM in the eager prefix
  attention. Without coordination rank 1 would already sit in the step-0 `all_gather`, the
  scheduler's next `broadcast_pyobj` would hang until the group timeout, and a request
  arriving in between could pair with the stale collective and return a wrong image. The
  prefill (through the flash-cache setup) therefore ends with a one-element `all_reduce` of a
  preallocated failure flag; if either rank failed, both raise and the request fails
  cleanly. The per-step forwards see the same image tokens on both ranks (only the prefix
  length differs), so the loop adds no checks.

Files:

- `neo_unify/modeling_neo_chat.py`: `t2i_generate(cfg_group=...)`; the branch prefill
  (`_t2i_prefill`, `_t2i_think_prefill`), the batch expansion of the prefix cache and the
  CFG combine (`_apply_t2i_cfg`) move into helpers with their bodies unchanged;
  `_cfg_ranks_fail_together` wraps the prefill.
- `stages/generation.py`, `pipelines/sensenova_u1.py`: pass the CFG group when
  `--enable-cfg-parallel` is set.
- `configs/pipeline_configs/sensenova_u1.py`: accept `num_gpus=2` with
  `--enable-cfg-parallel` (degree 2, `tp_size == sp_degree == dp_size == 1`); keep rejecting
  every other multi-GPU layout. `ServerArgs` never checks `sp_degree` against
  `num_gpus / cfg degree`, so `--sp-degree 2` used to pass and then fail at distributed init
  with a world-size error. Reject dynamic batching (`--batching-max-size > 1`) together with
  CFG parallel (see Notes). Drop the unread `supports_cfg_parallel=False` field and
  deployment flag.
- `configs/sample/sensenova_u1.py`: `should_use_classifier_free_guidance()` follows
  `guidance_scale` alone (the model builds its own empty-prompt uncond). Without it every
  CFG request logged "CFG parallelism is enabled but this request does not use
  classifier-free guidance ... recompute it redundantly".
- Cookbook page + deployment snippet: two-GPU recipe (§5.2) and benchmark tab; the snippet
  refuses the 2-GPU + dynamic batching combination.

## Accuracy Tests

#44690's change). The unit tests below were rerun on the rebased branch.

The output is bit-identical, not merely close. On `4ec19ca27f`, cookbook §3.1 command
(2048x2048, 50 steps, CFG 4, seed 42), two runs each: main on 1 GPU, this PR on 1 GPU and
this PR on 2 GPUs all write a PNG with md5 `b95d2e9f57b48dc4e91fa20de8deca74`. So the
refactor is a no-op for single-GPU users and the split reproduces it exactly.

On an earlier base (`f7ad4345b8`), also byte-identical between 1 and 2 GPUs:

- Python API at 1024x1024: default, `cfg_norm=global` + `cfg_interval=(0.2, 1.0)`,
  `cfg_zero_star` + `cfg_interval=(0, 0.5)`, `guidance_scale=1`, `think_mode=True`.
- With the layout / fused-MLP PR (#44922) and the FA3 attention change stacked underneath:
  `ca5f3dc015ac07a3b31a46cc822a3e42` on 1 and 2 GPUs.

Failure path, 2-GPU server: a 50,000-word prompt OOMs in rank 0's condition prefill
(`Tried to allocate 150.52 GiB`); rank 1 raises "SenseNova-U1 prefill failed on the other
CFG rank", the client gets HTTP 500 after 0.9 s, and the next request returns the same
image as before the failure. Launching with `--batching-max-size 2` or `--sp-degree 2` stops
with the SenseNova `ValueError`.

Unit tests, `python/sglang/multimodal_gen/test/unit/test_sensenova_u1.py`: 81 passed,

- `test_sensenova_u1_cfg_parallel_splits_branches_and_matches_serial`: a tiny random
  NEO-Unify model on CPU, two ranks simulated by threads with a barrier-backed group;
  asserts both ranks reproduce the serial image bit for bit and that rank 0 runs only cond
  forwards and rank 1 only the CFG steps' uncond forwards (covers the broadcast path and
  B=2). Mutation-checked: a rank that also runs the other branch, and a broadcast from the
  wrong rank, both fail it.
- `test_sensenova_u1_cfg_parallel_prefill_error_fails_both_ranks`: rank 0's condition
  prefill raises OOM; both ranks must fail that request, and the next request must match the
  serial image. Without the flag exchange rank 1 does not fail at all: its denoise loop pairs
  with rank 0's next request.
- Parallelism validation: 2 GPUs without CFG parallel, CFG degree 2 on 4 GPUs, degree 4, and
  `sp_degree=2` are rejected (main accepted the last one); dynamic batching with CFG
  parallel is rejected; 2 GPUs with degree 2 is accepted.
- The generation stage forwards the CFG group only when enabled.

## Notes

- Conflicts with #40663 (DP replicas) in the parallelism validator, `load_modules`, the
  validator tests and cookbook §5.2: both replace the `num_gpus != 1` check. The combined
  rule is one replica per `dp_size`, each with 1 GPU or 2 GPUs with CFG parallel; whichever
  lands second merges them. Merges cleanly with #44922.
- Dynamic batching with CFG parallel is rejected for now. Each rank applies the batching
  delay to its own enqueue timestamps, so the two ranks can dispatch different batches into
  the same collectives (reproduced on CPU with the real scheduler loop: about 1 hang in 380
  delay-triggered dispatches, deterministic with a 1 ms stall). The fix belongs in the
  generic scheduler: let the output rank decide and broadcast the batch. That logic is
  shared by every dynamic-batching pipeline running on more than one GPU, so it is a
  separate PR.
- Ascend NPU: the code path is backend-agnostic (HCCL collectives through the same
  `GroupCoordinator`), but it was not run on NPU.
- `--num-gpus 2` does not auto-enable CFG parallel: `_model_default_uses_cfg()` keys on
  `negative_prompt`, which SenseNova does not use. Pass `--enable-cfg-parallel` explicitly.
- `guidance_scale <= 1` requests compute the single branch on both GPUs; the rank-1 result
  is discarded.
- `think_mode` has a separate pre-existing bug on main (the image tokens cannot attend to
  the reasoning, so the image is noise); a fix follows in its own PR. Whichever lands second
  moves the one-line change between `t2i_generate` and `_t2i_think_prefill`.
