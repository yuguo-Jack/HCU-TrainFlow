# [Fix] rust-server: Validate gathered listener ranks and address families

[Upstream PR](https://github.com/sgl-project/sglang/pull/47691) · state: closed · merged: True

## Original PR description

## Motivation

A gathered Rust listener table can omit or repeat an attention-DP rank, leaving control fanout incomplete. A listener bound to `0.0.0.0` can also advertise an IPv6 address that it cannot accept connections on. Reject these configurations during startup, after the collective completes, so listener and non-listener ranks report the same failure.

## Modifications

- Require exactly one listener for every attention-DP rank when attention-DP spans multiple ranks.
- Gather IPv4 bind / IPv6 advertised-address errors with the listener records and raise on every participating rank.
- Keep the successful endpoint table format and elastic-EP joiner behavior unchanged.

Related fixes: #47541 handles advertised-address discovery and cross-node loopback rejection; #47519 validates the recipient DP rank on peer requests. This PR adds the listener-table and bind-family checks.
