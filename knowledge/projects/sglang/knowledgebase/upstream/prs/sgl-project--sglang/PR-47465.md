# [Perf] diffusion: Hold a Qwen-Image-2.1 Q/K norm + RoPE row with a half-warp

[Upstream PR](https://github.com/sgl-project/sglang/pull/47465) · state: closed · merged: True

## Original PR description

## Motivation

On B300 the fused Q/K RMSNorm + complex RoPE + K/V packing kernel of Qwen-Image-2.1 took 89 us per launch inside a 1024x1024 request (1280 launches, ~114 ms of GPU time per request): one warp per 128-wide row, 8-byte accesses and 64-bit work indices kept it near 1.5 TB/s.

## Modifications

- A half-warp holds a row: each lane owns 8 elements (16-byte loads/stores), i.e. two of the reference's 4-element groups. The aten mean order is kept exactly: four squares left to right per group, then the same tree (reference lane offsets 16, 8, 4, 2 become lane offsets 8, 4, 2, 1, offset 1 becomes the in-thread add of the two groups).
- 32-bit work indices (host check that the row count fits), 128-thread blocks.
- Tests: odd head counts (6 heads, a partial last warp) added to the existing bit-exactness tests.

## Accuracy

Bit-identical. `torch.equal` against main's kernel on the production pack shape ([1, 4096, 32, 128], 27-token prefix), the kept-buffer edit shape, copy-V, odd heads and the single-tensor entry point; the existing eager-reference tests pass (`test_complex_rope.py` + `test_qwen_image21_cuda.py`: 70 passed on B300). End to end, the decoded PNG pixels of every request match main (md5 of the RGBA array, T2I and edit, 6+ requests each).
