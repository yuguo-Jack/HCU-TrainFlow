# [Fix] rust-server: Keep a transfer backend's own bootstrap port on prefill

[Upstream PR](https://github.com/sgl-project/sglang/pull/46066) · state: closed · merged: True

## Original PR description

## Motivation

With `SGLANG_RUST_SERVER` set on a prefill worker, `handle_pd_disaggregation` aliases `--disaggregation-bootstrap-port` to `--port`, because the embedded Rust server answers the KV bootstrap registry on its API listener and every consumer of the resolved field (KVManager registration, `PrefillBootstrapQueue`) has to agree with it. That alias is only correct when the Rust registry really stands in for the transfer backend's bootstrap server, which is the case for the built-in backends: their `KVClassType.BOOTSTRAP_SERVER` is a `CommonKVBootstrapServer`, the HTTP registry the Rust server reimplements.

A transfer backend that brings a bootstrap server of its own, one that does not derive from `CommonKVBootstrapServer`, still runs that server on the configured bootstrap port. Rewriting the field to the API port then points the backend's registration at a port nothing of its own listens on, and a deliberately separate `--disaggregation-bootstrap-port` is rejected as a conflict with `--port`.

## Modifications

- `python/sglang/srt/managers/disagg_service.py`: add `rust_server_serves_kv_bootstrap(transfer_backend)`. It resolves the backend's bootstrap server class through `get_kv_class` and returns whether that class is a `CommonKVBootstrapServer`; a backend with no bootstrap server at all (`fake`) returns `False`.
- `python/sglang/srt/arg_groups/pd_disaggregation_hook.py`: `_alias_bootstrap_port_to_api_port` returns early, logging that the configured port is kept, when the helper returns `False`. The import is lazy so the argument hook does not import the disaggregation package at module import time and so a `get_kv_class` bound at runtime is the one consulted. The built-in backends take the same path as before.
- `test/registered/unit/entrypoints/test_rust_server_dp_ports.py`: `test_rust_prefill_bootstrap_port_alias` runs `handle_pd_disaggregation` on a prefill `ServerArgs` under `SGLANG_RUST_SERVER` with `get_kv_class` patched to a `CommonKVBootstrapServer` subclass or a bare `BaseKVBootstrapServer` subclass. The HTTP-registry cases keep the previous behaviour (default port aliased to `--port`, a port equal to `--port` kept, a separate port raises `conflicts with --port`); the own-bootstrap-server cases keep the default and a separate port as configured.
