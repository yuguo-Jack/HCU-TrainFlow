# [Fix] openai: Tool schema ids, explicit include_usage=false, and Kimi-K3 prompt fidelity

[Upstream PR](https://github.com/sgl-project/sglang/pull/48343) · state: closed · merged: True

## Original PR description

## Motivation

Four small request-handling bugs in the OpenAI chat endpoint. Two affect every model, two affect Kimi-K3 prompts.

1. **Draft-07 tool schemas are rejected.** A tool whose `parameters` carry a plain-name id such as `"$id": "#lookup"` is valid draft-07, but the draft 2020-12 metaschema used by `check_schema` forbids a non-empty fragment in `$id`. The request gets a 400 although the id constrains nothing.
2. **`include_usage: false` is ignored when the server default is on.** With `--stream-response-default-include-usage`, `should_include_usage` combines the two with `or`, so a client cannot turn the usage frame off.
3. **Kimi-K3 history tool-call arguments are re-serialized.** The Kimi-K3 encoder parses string `arguments` itself and keeps the original bytes of nested values. The server parsed them into a dict first, so the encoder re-serialized them and the prompt drifted by a few tokens from the reference rendering.
4. **Kimi-K3 drops an explicit `tool_choice: "none"` without tools.** The encoder renders `tool_choice="none"` as a control message whether or not tools are present, but the server passed it only when tools were present. A request without tools gets the default `"none"` from `set_tool_choice_default`, so the server could not tell the client's explicit value from the default.

## Modifications

- `function_call/utils.py`: `without_schema_identifiers` returns a copy of the schema without `$id`, `$anchor` and `$dynamicAnchor`. `_validate_request` runs `check_schema` on that copy. The schema itself is unchanged.
- `protocol.py` / `openai/utils.py`: `StreamOptions.include_usage` defaults to `None`. An explicit value wins, and only an unset value falls back to the server default.
- `serving_chat.py`: for Kimi-K3 without an encoding adapter, history tool-call arguments are passed to the encoder as sent. Other encodings keep the existing normalization and strictness.
- `protocol.py`: `set_tool_choice_default` becomes a wrap validator that records whether the client sent `tool_choice` (`_tool_choice_explicit`). The Kimi-K3 encoder receives an explicit `"none"` even without tools. The resolved `tool_choice` values are unchanged for every request.

## Tests

- New unit tests in `test_serving_chat.py`, one per fix. All four fail on main and pass here:
  - `test_validate_request_accepts_draft07_schema_identifiers`
  - `TestShouldIncludeUsage`
  - `test_kimi_k3_keeps_tool_call_arguments_bytes`
  - `test_kimi_k3_explicit_tool_choice_none_reaches_encoder_without_tools`
- `test/registered/unit/entrypoints/openai/` and `test/registered/unit/function_call/` give the same results before and after the change, apart from the four new tests.
