# [Fix] DFLASH: Reuse length buffers for unindexed CUDA devices

[Upstream PR](https://github.com/sgl-project/sglang/pull/46507) · state: open · merged: False

## Original PR description

## Motivation

`DFlashDraftInputV2._ensure_prepare_length_buffers()` compares the requested device with each existing tensor's device as strings. An unindexed CUDA request (`"cuda"` or `torch.device("cuda")`) differs from the allocated tensor's indexed device (`cuda:N`), even when both refer to the current CUDA device. Repeated preparation on the same draft-input object therefore reallocates both GPU length buffers and doubles their capacity despite an unchanged batch size.

This fixes the scratch-buffer reuse contract. These are sequence-length staging buffers, and the normal worker also creates new draft-input objects between steps; this PR does not claim a reproduced serving OOM or an end-to-end throughput improvement.

## Modifications

- Resolve an unindexed CUDA target to the current CUDA device before comparing devices or allocating buffers. Preserve explicit device indices and reallocate when the current CUDA device changes.
- Keep the existing capacity-growth policy, CPU buffer storage and dtypes.
- Add six CPU tests calling the actual production method with simulated CUDA allocation metadata, plus registered CUDA tests for real storage reuse/growth and a current-device switch. The latter requires two GPUs and skips on a single-GPU runner.

## Accuracy Tests

The registered test file was run using Python 3.12 and PyTorch 2.14.1 on macOS. The final fix is based on community main `d7f832d30ac3d88cf111ba242e3217dbf6ee6212`; the before-fix control used the identical production helper at `132b0f0ae73aa8cf812b72e9b98c89d1a3e1ac85`:

- Before the fix: three CPU regression tests failed; three CPU controls passed.
- With the fix: all six CPU tests passed. The two CUDA tests skipped because the local host has no CUDA device.
- `pre-commit run --files <two changed files>`, the registered-test validator, and `git diff --check` passed.

Reproducer:

```bash
PYTHONPATH=python python test/registered/unit/spec/test_dflash_prepare_length_buffers.py -v
```

No model accuracy evaluation or real CUDA execution was performed locally. The patch does not change length values, KV allocation arithmetic or attention computation.

## Speed Tests and Profiling

Not benchmarked. The CPU regression checks verify buffer identity and bounded capacity under repeated fixed-size preparation; they do not measure CUDA allocation latency or serving performance.
