# [Fix] hicache: Fix NIXL hybrid bounce buffers: copy page bytes exactly and pad slots for O_DIRECT

[Upstream PR](https://github.com/sgl-project/sglang/pull/42491) · state: open · merged: False

## Original PR description

## Motivation

When a hybrid host pool cannot use zero-copy, `HiCacheNixl` moves its pages through per-pool bounce buffers. Two defects in that path make NIXL L3 unusable for Qwen3.8-Flash-Next (Qwen4-Exp) under the default O_DIRECT setting:

1. **Bytes are converted, not copied.** The bounce buffers are allocated with `host_pool.dtype`, but they hold flat data pages, whose dtype can differ. `MambaPoolHost` stores bf16 state and returns uint8 pages, so `bounce[i].copy_(src)` casts every byte to a bf16 number, and the slot addresses (`base + i * page_bytes`) no longer match the rows (`2 * page_bytes` each). A page written and read back through this path comes back as byte values (e.g. `23., 63., 77., 191.` for an original `0.5898, -0.8008, ...`).
2. **O_DIRECT short I/O.** Bounce slots are exactly one page long. #39862 added the PLE side states to every Mamba page, which on Qwen3.8-Flash-Next moved it from 58,834,944 bytes (a multiple of 4096) to 59,019,280 bytes (16 past one). With O_DIRECT every Mamba transfer then fails with `POSIX transfer failed: an io completed short or with an error`, and every Mamba object on disk is 0 bytes.

On main the bounce path is taken for Mamba under O_DIRECT whenever its per-slot state is not a multiple of 4096 bytes, because `is_stride_page_aligned()` is then false. Qwen3.8-Flash-Next with PLE side states is one such model. Models whose Mamba page is aligned (e.g. Qwen3.5-0.8B) use zero-copy and are not affected.

## Modifications

- Allocate hybrid bounce buffers with the flat data page's dtype and copy pages into and out of the leading `page_numel` elements of each slot.
- Under O_DIRECT, round each bounce slot up to a multiple of 4096 bytes so every transfer's offset and length are page aligned. Without O_DIRECT the slot size is unchanged.

## Accuracy Tests

Unit tests in `test_hicache_nixl_storage.py`:
- `test_bounce_round_trip_keeps_bytes_of_wider_storage_dtype`: a bf16-storage pool with byte pages round-trips through the real POSIX backend.
- `test_odirect_bounce_round_trip_pads_unaligned_page`: a page 16 bytes past a 4096 boundary round-trips under O_DIRECT, and every transfer's address and length is page aligned.

Both tests fail on main and pass with this change. The O_DIRECT test checks alignment with an in-memory transfer stub, because NIXL's O_DIRECT file registration fails on overlayfs `/tmp`.

End to end, `nvidia/Qwen3.8-Flash-Next-NVFP4`, 1x B200, TP1, NIXL POSIX with O_DIRECT (default), ~12.5K-token prompts with five random codes. Each restore leg must hit the asserted tier in full, recall 5/5 codes and match the device-hit leg's output tokens. Three samples per leg.

| Leg | main | this PR |
|---|---|---|
| Host restore after device eviction | pass | pass |
| L3 restore after `/flush_cache` | no hit (237 `NIXL_ERR_BACKEND`, 0-byte Mamba objects) | pass |
| L3 restore after server restart | not run | pass |
| NEXTN (3 steps, topk 1, 4 draft tokens), host + L3 | not run | pass (measured together with #42490) |

## Speed Tests and Profiling

No change for pages that are already 4096-byte multiples. Unaligned pages under O_DIRECT move up to 4095 extra padding bytes each (4,080 bytes on a 59 MB Qwen3.8-Flash-Next Mamba page).
