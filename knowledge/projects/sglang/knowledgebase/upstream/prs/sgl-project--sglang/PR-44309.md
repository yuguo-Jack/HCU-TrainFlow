# [Fix] diffusion: Fix LoRA multi-adapter clearing, alpha scaling and merge-cache keys

[Upstream PR](https://github.com/sgl-project/sglang/pull/44309) · state: open · merged: False

## Original PR description

## Motivation

Follow-up to #44770, which fixed old adapters staying merged into layers the next adapter skips. Reviewing the rest of `pipelines_core/lora` turned up 17 more bugs in multi-adapter clearing, alpha and rank scaling, merge-cache keying, adapter loading and merge/unmerge state. Each one was checked against `main` before patching.

## Issues fixed

Critical (silent weight corruption)

| # | Issue | Fix |
|---|---|---|
| 1 | `clear_existing and idx == 0` stacks adapters when adapter 0 misses a layer that adapter 1 covers. | Clear on the first adapter that covers the layer. |
| 2 | The merge-cache key has no real content identity: user path string, no `weight_name`, `realpath` on repo ids and module names, no eviction. | Key on the resolved local file (name, resolved name, size, mtime, inode). Resolve only entries containing a path separator. Keep the newest 4 stores. |
| 3 | Fused-section `.alpha` keys are stacked and consumed, which crashes for equal sections and loses per-section scale for unequal ones. | Defer `.alpha` with A/B. |

High

| # | Issue | Fix |
|---|---|---|
| 4 | The cache merge only fires if the last adapter covers the layer. | `_merge_via_cache` runs once after the inner loop. |
| 5 | The config-match skip checks only the first module. | Every target module must match. |
| 6 | The critic offload lookup uses `"critic"` but the module is `fake_score_transformer`. | New `_lora_module()` maps the name. |
| 7 | `load_lora_adapter` clears the dict before parsing, so a failure leaves a broken adapter. | Build into a local dict and swap at the end. |

Medium and low

| # | Issue | Fix |
|---|---|---|
| 8 | `unmerge_lora_weights` enters the weight-update context per module, materializing all targets repeatedly. | One context for the merged modules. |
| 9 | `int(alpha)` truncates fractional alpha (0.5 becomes 0). | Use float. |
| 10 | AI-toolkit Flux `.alpha` keys are orphaned. | Remap alpha with the renamed modules. |
| 11 | RSLoRA and `alpha_pattern` miss keys without `.weight`. | Accept both suffixes. See limits for the ordering part. |
| 12 | A failed `put()` deletes the final path instead of the temp file. | Delete only the temp file. |
| 13 | `maybe_convert_state_dict` does not exist in diffusers 0.41, so the helper was dead code. | Remove the helper. |
| 14 | Rank uses `shape[-2]`, which is wrong for conv A. | New `lora_rank()` helper. |
| 15 | The dynamic reactivation fast path bails on uncovered layers. | Only covered layers need exactly one entry. |
| 16 | `name.replace(".weight", "")` replaces every occurrence. | `removesuffix`. |
| 17 | `merge_lora_weights(strength=...)` flattens per-adapter strengths and does not update `cur_adapter_config`. `deactivate_lora_weights` leaves `cur_adapter_name` set. | `strength=None` keeps per-adapter strengths, config is updated on override, and deactivate clears name and path. |

Behavior change: `merge_lora_weights` now defaults to `strength=None` (keep each adapter's own strength). `MergeLoraWeightsReq`, the `/merge_lora_weights` body, `DiffusionGenerator.merge_lora_weights` and `gpu_worker.merge_lora_weights` default to None instead of 1.0. Passing an explicit strength behaves as before.

## Tests

19 new regression tests. All fail on current `main` (`8c4680cb65`) and pass here.

- `test_lora_pipeline.py`: clear follows the first covering adapter; fractional alpha; failed adapter load keeps the previous adapter; critic offload lookup; set_lora skip needs every module to match; merge without strength keeps per-adapter strengths; deactivate clears identity; unmerge enters one context; reactivation fast path with uncovered layers; cache merge covers a layer the last adapter misses.
- `test_lora_merge_cache.py`: key tracks file identity and ignores cwd; failed put removes only the temp file; old stores are evicted; adopting a store protects it from eviction; get returns None when the store vanished.
- `test_fused_lora_compose.py`: per-section alpha folded into the fused group; equal sections with alpha do not crash.
- `test_lora_peft.py`: RSLoRA and `alpha_pattern` accept keys without `.weight`, plus `lora_rank` shapes; AI-toolkit Flux alpha follows renamed modules.
- Four existing test files get one `loaded_adapter_files = {}` line in their pipeline helpers.

CPU: `test_lora_*.py`, `test_fused_lora_compose.py`, `test_kandinsky6_lora.py` and `test_comfyui_lora_node.py` give 169 passed, 23 skipped. `test/registered/unit/multimodal_gen/test_lora_merge_cache_key.py` (from #44204) gives 2 passed. ruff, ruff-format, isort and codespell are clean.

GPU (Modal L4, real CUDA `BaseLayerWithLoRA` layers, fp32 and bf16, run on `d2a436446c` before the rebase):

| Check | Old | New |
|---|---|---|
| Merge adapter A equals base + reference delta | pass | pass |
| Switch A to B, attn equals base + B | pass | pass |
| Multi-LoRA `[b, c]`, ffn equals base + c only (#1) | fail | pass |
| `alpha=2.0` scales the delta | pass | pass |
| Fractional alpha 0.5 not truncated (#9) | fail | pass |
| Merged forward equals dynamic forward | pass | pass |

`sgl_kernel` and `flashinfer` imports were stubbed on the GPU box because the wheels did not match its torch build. The LoRA layers do not call them.

## Known limits

- No real-model end-to-end, layerwise-offload or DTensor run on GPU.
- `lora_rank` cannot tell a Conv1d `(r, in, k)` A from a stacked `(N, r, in)` A. Only stacked 3-D occurs in these paths.
- Atomic load is per adapter. If a later adapter in one `set_lora` call fails, an earlier one stays reloaded.
- `alpha_pattern` still runs after format renaming.
- The model revision is only part of the cache key when `model_path` is a local snapshot dir.
