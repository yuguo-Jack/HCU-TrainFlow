# [Fix] spec: Prune the draft branch instead of crashing when the grammar rejects a token

[Upstream PR](https://github.com/sgl-project/sglang/pull/48117) · state: open · merged: False

## Original PR description

## Motivation

`traverse_tree` (used by DSPARK/DFLASH and other spec-decode paths to build the grammar bitmask over the draft tree) calls `grammar.accept_token()` on every draft token that passed its parent's mask row. The matcher can still reject one — a mask/matcher desync, e.g. a disaggregation retracted-request double-accept — and `XGrammarGrammar.accept_token` raises `ValueError: Tokens not accepted`.

That exception was **uncaught**, so it propagated out of the scheduler event loop and **killed the engine**:

```
File ".../speculative/spec_utils.py", line 717, in dfs
    grammar.accept_token(int(draft_tokens[curr]))
File ".../constrained/xgrammar_backend.py", line 103, in accept_token
    raise ValueError(f"Tokens not accepted: {token} ...")
ValueError: Tokens not accepted: 1
# -> "Scheduler hit an exception" -> process exit -> liveness probe fails -> pod recreated
```

Observed on a PD-disaggregated DeepSeek deployment running DSPARK speculative decoding with xgrammar JSON-schema structured output: a single structured-output request takes down the whole decode engine.

## Modifications

A grammar-rejected draft token is exactly what speculative decoding already handles — it simply should not be accepted. In `dfs`, on the `ValueError`:

- Clear that token in the **parent mask row**, so the verify step will not accept it (the mask now agrees with the matcher).
- **Prune** the branch (skip fill / children). The accept failed, so the grammar is still at the parent state and **no rollback is owed** for the node.
- Sibling branches keep being verified; the request stays alive and its output stays grammar-correct (verify is the source of truth, and the offending token is masked off).

This keeps the engine up *and* keeps the request, versus aborting the whole request. It is orthogonal to, and complements, the root-cause grammar-sync work (e.g. #42401) and the containment approach in #44167.

## Tests

`test/registered/unit/spec/test_spec_utils_traverse_tree.py::test_grammar_reject_prunes_branch_without_raising` (CPU, `base-a-test-cpu`): a grammar mock rejects a token that passed the parent mask row. Verified red/green — pre-fix it fails with `ValueError: Tokens not accepted` escaping `traverse_tree`; post-fix `traverse_tree` does not raise, the rejected token is cleared from its parent row, and the sibling branch is still accepted and filled.

The new handler assumes a failed `accept_token` leaves the grammar at the parent state. The llguidance backend raises from `_check_err` only once `ll_matcher.is_error()` is set, and that error state may be sticky. Later sibling accepts and the parent's `grammar.rollback(1)` at spec_utils.py:745 then raise a ValueError the handler does not catch. Fix: make the pruning hold for every backend, for example with a backend-level `try_accept_token` that leaves state unchanged when it rejects.

<details>
<summary>Why this was flagged</summary>

Trigger: a request that uses the llguidance grammar backend, where the matcher rejects a draft token at depth 2 or deeper. `accept_token` (llguidance_backend.py:141-148) calls `ll_matcher.consume_token` and then `_check_err`, which raises `ValueError(self.ll_matcher.get_error())` (line 229) only after the matcher is in error state. The new `except ValueError` at spec_utils.py:719 skips this node's rollback. Control then returns to the parent frame, which calls `grammar.rollback(1)` at spec_utils.py:745 outside any try. `GuidanceGrammar.rollback` calls `_check_err` again (line 158), so if the error state persists the ValueError escapes `traverse_tree`. The scheduler crashes just as on the base branch. Whether the error state persists across rollback depends on the llguidance library. For xgrammar the assumption holds, because `matcher.accept_token` returns False without changing state.

**Verification:** pre-existing. The base branch already crashes this way (the uncaught ValueError from accept_token), so merging makes nothing worse. `GuidanceGrammar.rollback` (python/sglang/srt/constrained/llguidance_backend.py:150-158) ends with `_check_err()`. `grammar.rollback(1)` at spec_utils.py:744-745 sits outside the try, so its ValueError reaches the scheduler.
