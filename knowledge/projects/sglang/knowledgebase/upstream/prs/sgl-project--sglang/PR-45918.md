# [Fix] weight_checker: Make the checksum device-agnostic

[Upstream PR](https://github.com/sgl-project/sglang/pull/45918) · state: closed · merged: True

## Original PR description

Upstream of sgl-project/sglang-torchtpu#1578.

`/weights_checker` with `action="checksum"` calls `torch.cuda.synchronize()` around the checksum, so the action fails on every non-CUDA engine. That includes CPU, NPU, XPU and MPS, as well as out-of-tree platforms such as TPU, whose engines RL trainers (e.g. miles) checksum after each weight update.

This replaces both calls with `current_platform.synchronize()`, the existing per-platform hook:
- CUDA and ROCm keep calling `torch.cuda.synchronize()`, so their behavior is unchanged.
- CPU calls `torch.cpu.synchronize()`.
- Each other platform uses its own hook, or the no-op default.

The hashing already handles non-CUDA tensors through the host sha256 fallback.

Not changed: the `compare` action is still CUDA-only, since `weight_checker_comparator.py` calls `.cuda()`.

## Tests
- New `test/registered/unit/utils/test_weight_checker_cpu.py` (CPU suite): runs `checksum` with `torch.cuda.synchronize` patched to raise. With GPUs hidden, it fails on `main` and passes with this change.
- The existing `test_weight_checker.py` and `test_weight_checker_comparator.py` still pass on H200: 75 passed both before and after.
- The same change is merged in sglang-torchtpu and exercised on TPU v7x engines.
