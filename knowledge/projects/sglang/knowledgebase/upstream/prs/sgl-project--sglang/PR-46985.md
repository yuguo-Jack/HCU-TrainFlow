## Motivation

Compaction must keep pages stable while either disaggregation or HiCache owns an in-flight reference. Independent pin sources make that lifetime decision explicit without coupling it to device view types.

## Changes

- Register transfer pin sources through KV storage and combine them at the allocator boundary.
- Preserve explicit H2D reservations and invalidate capacity estimates when pin availability changes.
- Move host-transfer ID translation from device views to storage entries.

Remove two AST/name-only checks while retaining all four behavioral pin-lifetime tests.

## Validation

The cleanup retains the four behavioral tests and removes only the two AST/name checks. Tests were not rerun after the rebase.

Native Linux CPU validation of the integrated stack: `test_page_interleave_shard.py` passed **97 tests** after replacing incomplete transfer-entry fixtures with `PoolEntry`.

Review follow-up: the CPU source-level role-switch regression passed through four switches, including independent HiCache pins. GPU/RDMA tests were not run.

Historical validation at `86a18b9633` / `d84c991272`:
- Four-chain replay: **0 divergences**; admission: **4,608 unchanged decisions**, including sync-debug.
- After the fixture repair, HiCache tests passed **174 tests**.
- TP1 H200 PD, GSM8K-200: gpt-oss-120b **96.5% → 97.0%**, Qwen3.8-27B **97.0% → 97.0%**; no transfer errors. Complete per-run kernel versions were not recorded.

Post-rebase CPU checks passed pin ownership and transfer-ordering boundaries. GPU/PD execution was not rerun on this head.
