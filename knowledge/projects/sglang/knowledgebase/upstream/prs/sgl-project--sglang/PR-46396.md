# [CI] [AMD] diffusion: Skip the Wan CuTe DSL q/k norm RoPE imports on ROCm

[Upstream PR](https://github.com/sgl-project/sglang/pull/46396) · state: closed · merged: True

## Original PR description

## What

Stub out the CuTe DSL fused q/k RMSNorm + RoPE names in `wanvideo.py` on ROCm, the same way #46393 does on XPU.

## Why

#46228 imported these names at module level in `wanvideo.py`. They resolve to `rope/rmsnorm_interleaved_rope_cutedsl.py`, which does `import cuda.bindings.driver`. ROCm images have no cuda-python, so importing `wanvideo` fails, and so does every model that imports it:

```
File ".../models/dits/wanvideo.py", line 12, in <module>
  from sglang.kernels.ops.diffusion import (
File ".../kernels/ops/diffusion/rope/rmsnorm_interleaved_rope_cutedsl.py", line 11, in <module>
  import cuda.bindings.driver as cuda
ModuleNotFoundError: No module named 'cuda'
```

In the scheduled PR Test (AMD) run on main, `multimodal-gen-test-1-gpu-amd (rocm10, 0)` fails at server startup for `longlive2_t2v` and `wan2_2_animate_2_14b_distilled_ref2v` (no diffusers fallback for those architectures): https://github.com/sgl-project/sglang/actions/runs/40147750783/job/121032677999. The Wan T2V cases in the same job pass only because the loader falls back to the diffusers transformer.

#46393 added an `is_xpu()` guard with stubs for the same names; this adds `is_hip()` to it. Other platforms are untouched.

## Notes for the reviewer

Every use of the four names goes through `_fuses_qk_norm_rope`, which needs `fuse_qk_norm_rope`, which needs the q/k norm to dispatch to `forward_cuda`. On ROCm `RMSNorm` dispatches to `forward_hip`, so the stubs are never called beyond `can_use_* -> False`. CUDA behaviour is unchanged.

## Test plan

- [x] `multimodal-gen-test-1-gpu-amd` (rocm10) on this commit: https://github.com/sgl-project/sglang/actions/runs/40365033657. All server testcases pass in every partition, including `longlive2_t2v` (https://github.com/sgl-project/sglang/actions/runs/40365033657/job/121720563957), `wan2_2_animate_2_14b_distilled_ref2v` (https://github.com/sgl-project/sglang/actions/runs/40365033657/job/121720563784), `wan2_2_animate_2_14b_ref2v` and `longlive2_i2v`; no `No module named 'cuda'` anywhere. Partitions 0, 1 and 3 still fail in the unit-test step on tests that don't import `wanvideo` (`test_zimage_rope_cache.py`, `test_vae_tiled_decode_groups.py`, `test_nomas.py` bitwise checks, `test_ci_gpu_idle.py` missing `pynvml`); on main that step was cut short by the collection errors from this import, so these were hidden rather than caused by this change.
