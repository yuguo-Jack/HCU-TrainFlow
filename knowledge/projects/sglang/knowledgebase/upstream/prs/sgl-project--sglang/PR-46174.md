# [Perf] diffusion: Build spatial-parallel causal conv inputs in one pass

[Upstream PR](https://github.com/sgl-project/sglang/pull/46174) · state: closed · merged: True

## Original PR description

Branch: mick/diffusion-parallel-conv-halo-in-place, stacked on #46149 (93ccc5dc4f), commit 56c7668c91

## Motivation

Under spatial-parallel VAE decode, `SpatialParallelCausalConv3d` builds each conv input in three full passes over the activation:

1. `torch.cat` of the temporal feature cache.
2. `F.pad` for the width and time padding, plus its zero fill.
3. `halo_exchange`'s `torch.concat` of the neighbours' halo rows.

The single-GPU `WanCausalConv3d` already builds the same input in one channels_last pass (`cat_pad_channels_last_3d`), but the parallel conv had no route to it. The fused NCDHW cat-pad also needs a contiguous input, so channels_last activations fell back to the aten ops.

Profiled 189-frame Cosmos3-Nano decode on 4xB300 (rank 0), out of 1.45 s of GPU busy time:

| op | GPU time |
|---|---|
| halo concat | 134 ms |
| cat/pad fallback (copies, zero fill, cache cat) | 193 ms |

## Modifications

- `layers/parallel_conv.py`:
  - `SpatialParallelCausalConv3d.forward` handles the common case in one pass: a height-preserving conv with channels_last_3d weights, a "zeros" height pad, a matching cache, and no ROCm conv hook. One `cat_pad_channels_last_3d` writes the cache frames, the shard, the width/time padding and zero halo rows.
  - The new `fill_halo_rows_` then exchanges the shard's edge rows with the adjacent ranks, using the same P2P pairs as `halo_exchange`, and copies the received rows into the halo rows in place. The global top and bottom halos stay zero.
  - Every other case keeps the existing path.
- `test_vae_spatial_parallel_decode.py::test_halo_rows_filled_in_place_match_the_concatenated_halo`: two gloo ranks with uneven shards check that `fill_halo_rows_` gives bitwise the tensor `halo_exchange` concatenates. The test uses NCDHW tensors because gloo only sends default-contiguous ones; the channels_last path runs on GPUs and is covered by the md5 checks below.

## Speed Tests and Profiling

Cosmos3-Nano T2V 720p 189 frames, 4xB300, synchronized stage timers, two requests per build. The decode stage includes the MP4 encode streamed during the decode ("Encode Cosmos3 video while it decodes").

| | decode stage | client e2e |
|---|---|---|
| base | 1.266 / 1.286 s | 22.631 / 22.638 s |
| this PR | 1.124 / 1.137 s | 22.463 / 22.461 s |
| this PR + the epilogue follow-up | 1.117 / 1.224 s | 22.469 / 22.522 s |

The passes removed here are the ones profiled on the base (rank 0): the 134 ms halo concatenation and the 193 ms of unfused cat/pad. The decode was not re-profiled with this change.

Wan2.2 multi-GPU decodes run the same parallel conv on channels_last weights since #46149, so they take this path too (not measured here).
