# [Fix] dsv4: Build the DSpark draft block metadata without host sequence lengths

[Upstream PR](https://github.com/sgl-project/sglang/pull/46891) · state: closed · merged: True

## Original PR description

## Motivation

Since #45925, the DSpark draft batch carries no host sequence lengths when the draft attention backend sets `needs_cpu_seq_lens = False`. That is right for `trtllm_mha`, but the DeepSeek-V4 backend also sets it to False under DSpark on CUDA. Its draft-block prep, `init_forward_metadata_dspark_draft_block`, then read the lengths back with `seq_lens.tolist()`, which caused two problems:

- **The metadata glue graph turned off.** The first glue capture of each server fails with `Cannot copy between CPU and CUDA tensors during CUDA graph capture`, and the runner falls back to eager draft metadata prep for the rest of the run:
  ```
  Metadata glue-graph capture failed for key (1, '5', '5'); falling back to eager metadata prep permanently.
  ```
- **A device-to-host sync on every draft step.** From then on, every eager prep calls `seq_lens.tolist()` again.

On CUDA the draft-block prep does not need host lengths at all:

- The extend lengths are `[block_size] * bs`.
- The causal expand runs its Triton kernel from the device tensors and drops the host lists.
- Compression is off for the draft block.

## Modifications

- `compute_uniform_extend_lengths` accepts `seq_lens_cpu=None`. It then takes the batch size from `seq_lens` and returns no host copy of the extended lengths.
- The DeepSeek-V4 draft-block prep passes `None` through instead of calling `seq_lens.tolist()`.
- One CPU test for the helper, with and without host lengths.

## Accuracy Tests

The draft metadata comes from the same device tensors as before. Accept length is unchanged with real drafts: DEP2 with real acceptance gives a median of 2.0 to 2.2 on both arms at every batch size.

## Speed Tests and Profiling

GB300, DeepSeek-V4.1-Flash, DSpark block 5, one node per arm, one run each. Main is `cb55d77d37`, and the fix is the same commit plus this change. sa-bench uses input length 1024.
