# [DeepSeek-V4.1] Run decoder SWA bounded replay inside the breakable prefill CUDA graph

[Upstream PR](https://github.com/sgl-project/sglang/pull/43736) · state: open · merged: False

## Original PR description

## Motivation

`--enable-decoder-swa-bounded-replay` refuses every prefill CUDA graph backend, so DeepSeek-V4.1 prefill runs eager whenever bounded replay is on. On GB300 the eager prefill step is host-launch-bound (~2.5k launches per request per rank, ~10 ms of GPU work inside a ~230 ms step), so this is the dominant TTFT cost at low and medium concurrency.

This is the same gap #42078, #42909, #43440 and #43534 address. The variant here keeps the late layers on their bounded-replay tail **inside the same breakable prefill graph** instead of capturing separate late-layer graphs or running the captured late layers on full rows; the measurements below are why.

## Modifications

- The late layers (after the last KV source layer) run over a per-shape tail block inside the captured graph: `tail_rows = min(max_running_requests x 128, shape tokens)`. The tail's extend/positions/scatter indices and SWA write locations live in persistent, block-sized buffers (padding rows point at slot 0), so the graph replays with no reallocation; one tail metadata per block size is built the prefill-graph way (`use_prefill_cuda_graph=True`) and refreshed in place on every replay (`_prefill_graph_tail_metadata`, `prefill_graph_enter/exit_late_layer_tail`).
- `DeepseekV4Model.forward` switches to the tail at the `enter`/`exit` eager breaks and scatters the tail rows back (`_scatter_tail_rows` graph branch); the outer forward slices logits by `hidden_states_token_indices`, which the runner's `_trim_logits_output` now carries so the DSpark injector sees the right rows.
- `init_forward_metadata_in_graph` clears `tail_forward_metadata` on the decode/target-verify graph paths: the prefill graph capture/replay leaves it set, and the decode graph capture that follows otherwise slices a decode publish in `_publish_candidate_metadata` (`NotImplementedError: _SparseTable is not a prefill publish`).
- `validate_deepseek_v41_features` admits `Backend.BREAKABLE` with decoder bounded replay (encoder replay still eager).

With this, `--enable-decoder-swa-bounded-replay` and `--cuda-graph-backend-prefill breakable` work together; the capture width (`--cuda-graph-max-seq-len-prefill`, default 16k) is unchanged. #43733 builds on this to replay the graph at any context length.

## Accuracy Tests

DeepSeek-V4.1-Flash 1P1D on GB300 (prefill TP4 + decode TP4, DSpark PD, FlashMLA): capture of 74 shapes; needle prompts at 4.5k / 11k / 40k and greedy 24k / 40k / 86k-token prompts return the expected key with text matching the eager run (divergence within eager run-to-run noise); six-rung real-trace replay (300 s per rung) 100% success at every rung. Validated on the Sep-24 nightly series and on the Oct-8 nightly (7760d526) stack; the rebase onto current `main` applies cleanly and is compile- and lint-checked. A GPU run on `main` itself is still owed.

## Speed Tests and Profiling

Same deployment, real DeepSeek-V4.1-Flash production trace (ISL median 6.7k / p90 127k), three arms that differ only in the late-layer handling: eager + bounded replay (today), breakable graph with the late layers on full rows (bounded replay off inside the graph), and this PR (late layers on the tail inside the graph). All graph arms capture at 16k.

| conc | TTFT p50 eager / full rows / tail | TTFT p90 | output tok/min per chip | TPOT |
|---|---|---|---|---|
| 1 | 272 / 179 / **152** ms | 1,071 / 1,162 / **1,026** | 2,292 / 2,268 / **2,375** | 2.67 / 2.75 / 2.64 |
| 4 | 496 / 362 / **327** | 1,903 / 1,900 / 1,940 | 7,687 / 7,618 / **7,989** | 2.87 / 2.97 / 2.87 |
| 8 | 748 / **519** / 545 | 2,498 / 2,561 / **2,149** | 12,790 / 12,813 / **13,870** | 3.11 / 3.24 / 3.11 |
| 16 | 1,215 / 1,397 / **1,226** | 6,419 / 10,017 / **6,512** | 17,123 / 16,270 / **17,340** | 3.64 / 3.73 / 3.70 |
| 32 | 3,304 / 3,667 / **3,415** | 17,899 / 19,676 / **17,841** | 20,115 / 19,833 / 20,073 | 4.12 / 4.12 / 4.15 |

Idle-worker floor: an 11-token request 258-302 ms -> 59-60 ms end to end, an 11k cached-prefix request 298-320 ms -> 65-72 ms. Full rows inside the graph wins the floor but returns the bounded-replay saving once the batch fills (at 16 concurrent it is behind eager on p50 and p90); the tail inside the graph keeps eager-level p90 and adds 5-8% output per chip at 4-16. Graph pool at 16k capture is ~39 GB on GB300 (prefill `mem_fraction_static` 0.78 -> 0.70 in our deployment).

## Same-base A/B on the Oct-8 nightly (added 2026-10-11)

Both arms on the identical stack (SGLang Oct-8 nightly 7760d526 + the same patch series and runtime), differing only in the prefill graph (this change plus the any-context replay on top; eager arm `cuda_graph_backend_prefill: disabled`). Same GB300 1P1D deployment and real-trace ladder as above, 300 s per rung, 100% success at every rung, 5,804 graph batches to 1 eager batch, 0 worker restarts.

| conc | TTFT p50 eager → graph | TTFT p90 | TPOT | output tok/min per chip |
|---|---|---|---|---|
| 1 | 263 → 142 ms (−46%) | 847 → 690 (−18%) | +1% | +3% |
| 2 | 334 → 205 (−39%) | 1,118 → 1,088 (−3%) | +1% | +1% |
| 4 | 447 → 210 (−53%) | 1,341 → 1,227 (−9%) | +1% | +5% |
| 8 | 494 → 289 (−41%) | 1,547 → 1,397 (−10%) | +2% | +2% |
| 16 | 703 → 437 (−38%) | 2,733 → 3,988 (+46%, see note) | −1% | +2% |
| 32 | 1,823 → 1,594 (−13%) | 9,423 → 8,057 (−14%) | +1% | +3% |

Note: the eager p90 of 2.7 s at 16 concurrent is far below the same arm's 6.4 s on the Sep-24 series; the graph's 4.0 s is within that spread, so the +46% is run variance rather than a regression. Idle-worker floor: 11-token request 200 → 72 ms, 11k cached-prefix request 230 → 78 ms.

Compared with the Sep-24-series numbers above, the nightly upgrade itself took most of the throughput gain (and the decode-side TPOT cost); what the prefill graph adds on current code is TTFT: p50 roughly −40% up to 16 concurrent, p90 roughly −10%, throughput +1…+5%, TPOT flat.
