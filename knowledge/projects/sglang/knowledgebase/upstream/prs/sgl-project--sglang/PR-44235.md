## Motivation

Fixes #44234.

At 2026-10-14 06:17:59 UTC, the Hugging Face repo `baidu/Unlimited-OCR` was updated ([`8249d20b`](https://huggingface.co/baidu/Unlimited-OCR/commit/8249d20b2822a7d8a4c22c8d8c9069b5ac36bda3)). The update renamed the config's `model_type` from `unlimited-ocr` to `unlimited_ocr`. sglang registers `UnlimitedVLConfig` only under `unlimited-ocr`, so transformers now treats the config as remote code. `test/registered/vlm/test_unlimited_ocr_server.py` launches without `--trust-remote-code`, so its server fails during argument resolution:

```
ValueError: The repository baidu/Unlimited-OCR contains custom code which must be executed to correctly load the model.
```

Example failure: https://github.com/sgl-project/sglang/actions/runs/38514395774/job/115695664058

## Modifications

- Pin the test to the last HF revision before the update: `--revision=07dea832e22aefee32ad281d4b80551282e1c168`.
  - sglang passes `--revision` through to its config, tokenizer, processor and weight loaders.
  - The weight blob is identical across both revisions, so the CI HF cache is reused.
  - If the offline-cache check enables `HF_HUB_OFFLINE=1` and the pinned snapshot is missing, `popen_launch_server` already retries online.

The same HF commit also added `chat_template.jinja`, `generation_config.json` and `preprocessor_config.json`, and it changed `processor_config.json`. Supporting the new upstream layout (registering `unlimited_ocr` and checking output parity) is a follow-up for the model owners. After that, the pin can be removed.

## Accuracy Tests

N/A (test-only change). CPU validation on latest `main` with transformers 5.17.0:

- `get_config("baidu/Unlimited-OCR", trust_remote_code=False, revision="main")` raises the `ValueError` above.
- With `revision="07dea832..."`, it returns `UnlimitedVLConfig` (`['UnlimitedOCRForCausalLM']`), and `get_processor` returns `UnlimitedOCRHFProcessor`.

I couldn't run the full GPU test locally (it needs an H100 with fa3), so CI will confirm.
