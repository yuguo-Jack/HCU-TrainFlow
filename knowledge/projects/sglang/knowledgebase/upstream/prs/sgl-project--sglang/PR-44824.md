# [Perf] [AMD] GLM5: Skip redundant -inf pre-fill of KPool MQA-logits

[Upstream PR](https://github.com/sgl-project/sglang/pull/44824) · state: open · merged: False

## Original PR description

## Motivation

This affects prefill serving of GLM-5.3-Flash, which uses the pooled DSA `IndexerKPool`.

`IndexerKPool._kpool_topk_by_row_chunks` calls `fp8_mqa_logits` with `clean_logits=True`, which `torch.full(-inf)`-initializes the full `[query rows x concatenated pooled KV rows]` FP32 logits buffer before the scorer writes each row's valid range. The buffer can be several GiB at long context.

The downstream KPool top-k already receives `row_starts` and `pool_lens` and reads only `score[row, row_start : row_start + pool_len]`. Initializing positions outside those ranges is therefore redundant. This is the KPool equivalent of the non-pooled indexer optimization merged in #28757.

## Modifications

- `python/sglang/srt/layers/attention/dsa/dsa_indexer_kpool.py`: pass `clean_logits=False` to the ragged KPool MQA-logits call. Valid logits are unchanged; positions outside each row's declared range remain uninitialized and are not read by KPool top-k.
- Extend the gfx950 real-kernel test through the production KPool top-k transform at GLM-5.3-Flash geometry (`32 x 128`, KPool 4, token top-k 2048).
- Make KPool chunking unit tests require `clean_logits=False` on both ROCm/AITER and CUDA/DeepGEMM paths.

## Accuracy Tests

Full GLM-5.3-Flash Quark MXFP4 GSM8K on snapshot `b5688f25491202978c19c4d036eef579f61bbe07`. The baseline is frozen integrated source `4a2714fbe3`; the candidate is `f6b4661f24`, which adds only #44824. Both include #38764 at `ed418ce926` and #41615 at `acca6a72db`, use `aiter_sparse_mla`, `SGLANG_OPT_GLM53_KDA_PTPC_MODULES=qkv_proj,f_a_proj,g_a_proj,o_proj`, AITER `e7d2453f25`, separate fresh caches, thinking enabled, temperature 1.0, top-p 0.95, and seed 0.

| Configuration | Score | Stop rate | Truncated rate | Error rate |
| --- | ---: | ---: | ---: | ---: |
| TP4 baseline — `clean_logits=True` | 97.19% | 99.92% | 0.08% | 0.00% |
| TP4 candidate — `clean_logits=False` | 96.74% | 100.00% | 0.00% | 0.00% |
| TP8 baseline — `clean_logits=True` | 96.36% | 99.47% | 0.53% | 0.00% |
| TP8 candidate — `clean_logits=False` | 97.19% | 99.70% | 0.30% | 0.00% |

TP4 used a 65,536-token context, 64 evaluator threads, and 32,768 maximum output tokens. TP8 used a 131,072-token context, 1,200 evaluator threads, and 4,096 maximum output tokens. All four runs completed 1,319 questions without errors; the score deltas are within single-pass sampling variation.

The real-kernel tests produced identical selected KV sets with `clean_logits=True` and `False` through both the ordinary masked top-k and KPool fused top-k paths. `test_dsa_skip_logits_clean.py`: 2 passed. `test_kpool_stream_scheduling.py`: 13 passed.
