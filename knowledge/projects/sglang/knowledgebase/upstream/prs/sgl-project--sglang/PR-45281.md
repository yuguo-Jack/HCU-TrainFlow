## Motivation

<!-- Describe the purpose and goals of this pull request. -->

The CPU monitor tests exercise generic threading, psutil CPU-time accounting, and Prometheus metrics. They do not require Xeon-specific hardware.

An existing test-isolation race caused the Xeon PR job to fail: the real monitor thread from the first test remains alive and can call the second test's mocked `time.sleep` with `0.1`, while the assertion expects `3.0`. Failure evidence: https://github.com/sgl-project/sglang/actions/runs/39217692176/job/117945459734.

The crash-dump integration test also exercises generic diagnostics rather than Xeon-specific behavior. Its intentional server crash successfully writes the dump, but the fixture fail-fast watcher treats the expected server exit as a failure and aborts the test process with exit code 137. Failure evidence: https://github.com/sgl-project/sglang/actions/runs/39191014606/job/117863701840.

This PR removes both tests from Xeon per-commit CI. CPU monitor coverage remains in generic CPU nightly; crash-dump coverage remains in CUDA and AMD nightly, with no CPU registration retained for that test. The existing thread-isolation and fail-fast issues are not fixed here.

## Modifications

<!-- Detail the changes made in this pull request. -->
