## Original PR description

## Summary
- allow the ROCm AOT extension build to target RDNA3 `gfx1100`
- select E4M3 FP8 definitions for gfx1100
- use a 48 KiB TopK dynamic shared-memory budget to fit gfx1100's 64 KiB LDS limit

- vivienfanghuagood · COMMENTED · 2026-10-28T00:40:08Z · [source](https://github.com/sgl-project/sglang/pull/37398#pullrequestreview-5676379448)

Thanks for this. I built this PR's head for gfx1100 and ran the AOT kernel unit tests on a Radeon PRO W7900D (gfx1100). The build and `import sgl_kernel.common_ops` both succeed, but two of the MoE gating kernels fail at runtime:

| test (one pytest per file) | this PR on gfx1100 |
|---|---|
| test_moe_topk_softmax | process aborts (`Fatal Python error: Aborted`) |
| test_moe_topk_sigmoid | `torch.AcceleratorError: HIP error: unspecified launch failure` (first case, `test_topk_sigmoid[1-4-1]`) |
| test_activation | 945 passed |
| test_apply_token_bitmask_inplace | 1 passed |
| test_topk | 118 passed |
| test_dsv4_norm_rope | 16 passed |
| test_moe_align | 4368 passed, 72 skipped |

The cause is the warp size. `include/utils.h` defines `WARP_SIZE` as 64 in the host pass and 32 in the gfx11 device pass. `topkGatingSoftmax` / `topkGatingSigmoid` are launched with `dim3 block_dim(WARP_SIZE, WARPS_PER_TB)` and with template constants derived from the host value, while the kernel bodies assume 32 lanes. The same failures reproduce on gfx1201 (R9700) with only the allowlist widened on current `main`.

The fix already exists on `amd_march` as #44600 (mixed wave32/wave64 AOT kernels). With that change ported onto current `main` plus the allowlist, all of the tests above pass on both gfx1100 and gfx1201:

- topk_softmax 744 passed
- topk_sigmoid 774 passed
- topk 164 passed, 1 skipped

Two smaller points:

- `main` has since lowered the non-gfx942 TopK dynamic-smem budget to 40 KB, which already fits gfx1100's 64 KB LDS. The 48 KB change is optional now.
- This PR is based on a September `main`, and `setup_rocm.py` has moved since.

Merged as is, this would ship a kernel that imports fine but faults or mis-routes on MoE models. We've proposed the full RDNA kernel-build change (allowlist for gfx110x/gfx120x plus the #44600 launch fix) in #46900, along with a question to the AMD maintainers about RDNA CI, which they asked for before RDNA lands on `main`. I'd suggest closing this in favour of that, or rebasing it on that change. Happy to help either way.
