# [Test] [NPU] kimi_k3: enable L2 host HiCache for 32p gpqa accuracy test with host hit-rate bench

[Upstream PR](https://github.com/sgl-project/sglang/pull/44398) · state: open · merged: False

## Original PR description

## Motivation

Extend the Kimi-K3 W4A8 32p gpqa_diamond accuracy test (which already serves with the L1 prefix cache enabled since #38125) to the L2 (host) HiCache setup, and guard the L2 behavior with a benchserving cache-hit assertion.

## Modifications

1. `test/registered/npu/accuracy/kimi_k3/test_npu_kimi_k3_w4a8_32p_gpqa.py`
   - Append the L2 (host) HiCache flags to the server args: `--enable-hierarchical-cache`, `--hicache-io-backend kernel_ascend`, `--enable-cache-report`, `--hicache-ratio 2`, `--hicache-write-policy write_through`.
   - Keep the `--dp-size N --enable-dp-attention` spelling: the deprecated form is auto-converted to `--attn-dp-size` on main, while the older sglang build shipped in the nightly image only accepts this form.
   - Add a second test method `test_npu_kimi_k3_w4a8_32p_l2_host_hit_rate` (master node only): flush the server cache, run one `generated-shared-prefix` benchserving round at the 64k operating point (3 groups x 32 prompts, 57600 + 6400, output 1024, concurrency 32), and assert the host (L2) hit rate is above 10%.

2. `python/sglang/test/ascend/e2e/test_npu_performance_utils.py` — extend `run_bench_serving` (backward compatible):
   - New optional args `gsp_num_groups` / `gsp_prompts_per_group` (previously hardcoded to 1 group) and `cache_report`;
   - Parse the `Cache Hit Details` report into the returned metrics (`cache_hit_rate_pct` / `device_hit_rate_pct` / `host_hit_rate_pct`);
   - Pass `--seed` / `--warmup-requests` through in the GSP branch as well.

## Accuracy Tests

Validated on the real 4-node nightly pipeline (multi-node-mix-poc, scoped run on the `cann9.1.0-a3-B103` image, [run 39103811460](https://github.com/sgl-project/sglang/actions/runs/39103811460)):

- gpqa_diamond accuracy **0.914** (181/198) - within the dataset fluctuation tolerance of the 0.935 baseline (threshold = 0.935 - 5/198 = 0.910).
- `Ran 2 tests ... OK`.

## Speed Tests and Profiling

Same nightly run, the 64k GSP bench round:

| total hit rate | device | **host (L2)** |
|---|---|---|
| 78.3% | 81.8% | **18.2%** (assertion >= 10% passed; local measured range 15.9%~20.5%) |

(3.5k/8k keep the host hit rate at 0% as expected -- L1 holds it; 128k reaches 42%~55% host. The 64k point is the smallest one where L2 is meaningfully exercised.)

## Notes

- `est_time` raised 3600 -> 5400 to account for the ~18 min bench round.
- The case stays registered with `disabled="accuracy testcase"`, so it will not consume NPU resources until enabled.
- Off-note for NPU maintainers: the nightly image `main-cann9.1.0-a3` currently fails to compile the `kda_target_verify` triton kernel at graph capture (`ub overflow, requires 1589248 bits while 1572864 bits available`), which breaks the `kimi_k3_w4a8_32p_gpqa` entry on main for 2+ weeks; the B103 image works.
