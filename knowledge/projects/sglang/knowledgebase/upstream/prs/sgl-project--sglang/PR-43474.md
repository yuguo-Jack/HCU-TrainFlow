# [MemCache] Fix the strict busy check on prefill-aware SWA and tidy small leftovers

[Upstream PR](https://github.com/sgl-project/sglang/pull/43474) · state: closed · merged: True

## Original PR description

- `kv_private_swa_tokens`: count `[cache_protected_len, swa_dead_lo)` as still held. With prefill-aware SWA (e.g. Unlimited-OCR) and the radix cache disabled, window eviction moves the SWA cursor to `swa_evict_floor` without freeing the prompt, so `SGLANG_ENABLE_STRICT_MEM_CHECK_DURING_BUSY` reported `SWA Pool Mem Leak` on the first warmup decode
- `_check_tree_cache`: fix the `and` / `or` precedence so the mamba branch also requires prefix sharing
- `_maybe_namespace_elastic_radix_cache`: drop the `disable_radix_cache` clause; `supports_prefix_sharing()` already covers it
- Remove `TestRetractDecodeLongOutputRadixDisabled`: it is skipped in CI, and with `ignore_eos` the radix-disabled admission reserves the full output, so it never retracts; `TestRetractDecodeRadixDisabledPaged` covers radix-disabled retraction
- Add tests for the first two in `test_invariant_checker.py`

No behavior change outside the strict memory checks and the tree sanity check.
