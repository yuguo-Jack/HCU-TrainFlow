# [Perf] phi4mm: Avoid dense chunk lookup masks

[Upstream PR](https://github.com/sgl-project/sglang/pull/46333) · state: open · merged: False

## Original PR description

## Motivation

Phi4 streaming masks compare each token against every chunk interval and call `nonzero` just to recover chunk IDs. This creates an unnecessary CPU lookup table of shape `[sequence_length, num_chunks + 1]`.

Related to #9889. Credit to @imxj's closed #25508 for the earlier Phi4 bucketize approach. This is a narrower continuation of that idea, preserving the existing input conversion and CPU behavior.

## Modifications

Use `torch.searchsorted(..., right=True)` over sorted chunk starts. Upper-bound semantics preserve exact-boundary behavior and skip duplicate starts that represent empty chunks. The final boolean attention mask and window handling stay unchanged.

Add four registered CPU regression tests covering empty and repeated boundaries, adaptive chunks, wide windows, input representations, strided inputs, unchanged caller inputs, and absence of dense interval enumeration.

## Accuracy Tests

- Native WSL Linux run of `test/registered/unit/models/test_phi4mm_utils.py -v`: all four tests passed, using real SGLang package imports and `CustomTestCase` without shims.

- Repository pre-commit checks passed for both changed files; `git diff --check` passed.
- Earlier baseline comparison passed the mask-equivalence cases and failed the new nonzero-enumeration regression as expected.
- No Phi4 model inference or accuracy evaluation was run.

## Speed Tests and Profiling

Existing synthetic CPU profiling of the full helper at 2,048 audio steps, 18-step chunks, and left window 2 measured summed positive operator self allocations of **13,427,880 to 12,704,936 bytes**. This is allocated-byte accounting, not peak live memory. Output equality was checked, and the candidate trace contained no `nonzero`.

The final quadratic mask remains. Timing ranges overlap, so speedup is inconclusive. No GPU synchronization or serving-throughput improvement is claimed. This does not fully resolve #9889.
