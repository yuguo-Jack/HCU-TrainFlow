# [Feat] diffusion: support FLUX 3 Image Klein

[Upstream PR](https://github.com/sgl-project/sglang/pull/44418) · state: closed · merged: True

## Original PR description

## Motivation

Add native FLUX.3 Image text-to-image and multi-reference editing support, using the self-contained `black-forest-labs/flux-3-image-klein-base` and `black-forest-labs/flux-3-image-klein` release packages, including FP8R/NVFP4 variants.

## Changes

- Reuse the FLUX.3 transformer, native parallel linears, attention dispatcher, loader, residency manager, and existing grouped-request scheduler.
- Support concurrent requests and multiple outputs without mixing prompts, seeds, references, CFG branches, or output order. Bucket text encoding and VAE decoding; pack independent DiT samples.
- Fail attention initialization explicitly instead of silently dropping SP collectives through a local fallback.
- Honor CPU-first loading and reuse strict meta/assign loading. Replace custom config parsing and boolean handling with shared utilities.
- Add an opt-in full-checkpoint HTTP regression and a cookbook picker covering RTX 5090, Hopper, and Blackwell with one to eight GPUs. Unmeasured recipes remain labeled unverified.

The follow-up adds batching while reducing production code by 44 lines relative to the original implementation after merging main. No separate scheduler or new runtime dependency is introduced.

## Validation

- 92 focused tests and 21 subtests passed on H200; pre-commit and 64 cookbook command-generation combinations passed.
- Base BF16 single-request PNGs match the original branch exactly at 512x512/4 steps and 1024x1024/50 steps, seed 42, Torch SDPA.
- Real HTTP tests cover T2I, I2I, independent concurrent requests, `n=2`, and exact repetition of a single request after batching. Also exercised TP2, Ulysses SP2, CFG2, distilled sampling, and layerwise/component offload.
- PNG batch-1/batch-2 comparison: SSIM 0.9885-0.9955 across four 512x512/8-step samples. Batching changes floating-point reductions; it is not a bitwise-equality promise across batch sizes.

The full-checkpoint test is opt-in because checkpoint access is required. Official Diffusers parity is deferred; no official GT or universal fidelity guarantee is claimed. Release BF16/FP8R were exercised on GB300/H200, NVFP4 on GB300, and Base BF16 on RTX 5090. Four-GPU validation is in progress.

## Release Checkpoint Validation

- Base/Distilled: 1024x1024 T2I/I2I, 50/16 steps, two prompts/seeds, repeated PNG requests. Repeats matched within each tested configuration.
- GB300 Base FP8R/NVFP4: T2I 2.18/2.14s vs BF16 3.21s; I2I 4.49/4.31s vs 6.31s. Quantization is lossy: observed minimum SSIM 0.958/0.919 (T2I) and 0.981/0.958 (I2I).
- Request-scoped fixed conditioning reuse and full-context FP32 VAE attention reduce work/workspace without pruning attention. For a 2048x2048 reference, peak allocated GPU memory fell from 54.3 to 29.5 GiB on GB300; latency was effectively unchanged. Reduction order can change pixels; exact keeps the original VAE path.
- BF16 synthetic rank-4 LoRA: dynamic/merge, repeatability and exact base restoration verified. Late LoRA on PrimsTS-packed weights is rejected before wrapping; startup LoRA selects the generic layout.
- Image-edit Cache-DiT form fields now reach sampling params and are validated; GB300 Base I2I 6.31→3.08s at threshold 0.12, observed SSIM 0.9786–0.9975. Approximate and opt-in.
- Cookbook includes measured profiles and explicit unverified combinations. Software/timing boundaries and full precision limitations are recorded there.

## Pre-release Batching Measurements

One GB300 (about 277 GiB), Base BF16, resident components, eager, Torch SDPA, PyTorch 2.14.1+cu130, Transformers 5.19.0. Checkpoint revision `5de4fe32f17aee3dbc34375a94935f09206dba2c`. Three-round medians, two different prompts/seeds, local HTTP and JPEG serialization included; both shapes and reference encoding warmed.

| Workload | Serial pair | Batch-2 pair | Throughput ratio |
| --- | --- | --- | --- |
| T2I, 512x512, 8 steps | 0.649 s | 0.324 s | 2.00x |
| I2I, 512x512, 8 steps | 0.737 s | 0.546 s | 1.35x |
| T2I, 1024x1024, 50 steps | 6.248 s | 6.050 s | 1.03x |
| I2I, 1024x1024, 50 steps | 13.171 s | 12.996 s | 1.01x |

The 8-step runs test short-request behavior, not recommended Base sampling quality. The standard 50-step workload gains little; FlashAttention shows the same limitation. Batch 1 remains the default. For the measured 50-step requests, batch-1 versus batch-2 JPEG SSIM was 0.9920-0.9977. These samples are not a general quality bound.
