# [Fix] debug_utils: Stop grafter tests hanging on a reused port

[Upstream PR](https://github.com/sgl-project/sglang/pull/47974) · state: open · merged: False

## Original PR description

## Motivation

`test/registered/debug_utils/test_dumper.py` in `nightly-test-2-gpu-large` occasionally hangs until it is killed at its 1830 s limit: [Oct 29](https://github.com/sgl-project/sglang/actions/runs/40888373759/job/123498356383) and [Sep 25](https://github.com/sgl-project/sglang/actions/runs/36145732791), 2 of the last 30 nightlies. Both logs stop at the 71% progress line (178 of 249 cases); every multi-process grafter test runs after that point.

Each grafter test picks three ports with `find_available_port`, which returns a random free port from `[base+100, base+1000]` and reserves nothing: a graft port (bases 29600–29680, chosen in the test) and two role ports (bases 29700/29800, or 29800/29900 in the CPU multi-rank helper), all chosen before any process binds. The ranges overlap, so two can come back equal; simulating the file's actual bases gives about 0.3% per test and about 4.4% per file run.

When the two role ports match:

1. The worker that loses the bind fails in `dist.init_process_group` with `EADDRINUSE`. That call sits outside the `try` in `_graft_worker_entry` / `_graft_cpu_worker_entry` (and the split entry's error path also skips `result_queue.put`), so the worker exits without reporting.
2. Its peer waits in the graft-group rendezvous (default 30 min process-group timeout).
3. The parent blocks in `p.join()` (no timeout), then in `result_queue.get()` (no timeout) for a result that never comes.

I reproduced steps 1–3 on CPU with gloo by forcing the two role ports to match.

## Modifications

All in `test/registered/debug_utils/test_dumper.py`:

- `_distinct_free_ports(count, exclude)`: bind `count` sockets to port 0 at once and return their ports, skipping any in `exclude`. The three grafter helpers use it for their role ports, excluding the test's graft port (from the `graft_port` kwarg, or `DUMPER_GRAFTER_MASTER_PORT` for the E2E split test).
- Every worker entry initializes its default process group inside the `try` and only destroys it if it was initialized, so a failed start is reported to the parent.
- `_collect_graft_results`: read results with a 300 s deadline **before** joining (a child cannot exit until its queued result is flushed, which matters for the split test's captured stdout), stop early if every worker has exited, then join with a timeout and terminate any worker still running. Missing results raise an `AssertionError` with the reason and each worker's exit code.

## Validation

Ran the new helpers and the real `_graft_cpu_worker_entry` (extracted from this file) on CPU with torch/gloo, using spawned processes:

| Scenario | Before | After |
|---|---|---|
| Both workers succeed | passes | passes (0.1 s) |
| Worker result of ~5 MB | — | passes (read before join) |
| One worker exits without reporting | parent blocks forever | `AssertionError … (exited without reporting; exit codes [0, 3])` in 6 s |
| One worker hangs (deadline set to 8 s for the check) | parent blocks forever | worker terminated, `AssertionError … (still running after 8s; …)` |
| Role ports forced equal, stand-in graft rendezvous with a 20 s timeout | parent blocks forever | both workers report (bind error and rendezvous timeout); parent fails in 26 s |
| `_distinct_free_ports(200, exclude=…)` | — | 200 distinct ports, exclusion respected |

`ruff format` and the repo's ruff lint selection pass. The full file has not been run here (needs 2 GPUs); please run `/rerun-test test/registered/debug_utils/test_dumper.py` before marking ready.
