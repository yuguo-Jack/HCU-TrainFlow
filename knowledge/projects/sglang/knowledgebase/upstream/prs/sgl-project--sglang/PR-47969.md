# [CI] [AMD] pr-test: Run the MI35x 1-GPU stage after MI300 stage-b; move test_flydsl_v4nm_decode to nightly

[Upstream PR](https://github.com/sgl-project/sglang/pull/47969) · state: closed · merged: True

## Original PR description

## What

- `stage-b-test-1-gpu-small-amd-mi35x` now needs `wait-for-stage-b-amd`, as the stage-c jobs do. A PR run only asks the MI35x 1-GPU pool for a runner once its MI300 stage-b tests have passed. Scheduled runs skip the wait jobs, so they still run it in parallel.
- `test_flydsl_v4nm_decode` (~10 min) moves to the `nightly-amd-1-gpu-mi35x` suite, which the nightly `nightly-test-1-gpu-mi35x` job already runs.

## Why

`linux-mi35x-gpu-1` has about 4–5 runners and is the bottleneck of AMD PR CI. On PR runs from Oct 30 to Nov 1:

| | MI35x 1-GPU job | every other AMD job |
|---|---:|---:|
| median wait for a runner | 683 min | 0 min |

So a PR run that finishes its other GPU work in about 80 min (stage-b) takes a median ~11.6 h to report.

- **Fewer jobs:** 19 of the 100 PR runs in that window failed MI300 stage-b, yet each one still queued an MI35x job. Waiting for stage-b drops those, and also drops runs that a newer push supersedes before stage-b ends.
- **Shorter job:** with `test_quark_mxfp4` (#47150) and now `test_flydsl_v4nm_decode` in nightly, the job runs about 26 min of tests, against about 46 min before #47150.

Together, each PR run asks the pool for roughly half the runner time it did on Oct 30. The wait should drop by more than that once demand falls below capacity, but that depends on PR volume and will be measured after merge.

## Notes for the reviewer

- The job name is unchanged, so dashboards and `target_stage` dispatches keep working. `wait-for-stage-b-amd` waits only on the MI300 stage-b jobs, so there is no cycle.
- On passing runs, the MI35x result now arrives after stage-b (~80 min) instead of alongside it. Today it arrives after the ~11 h queue anyway.
- `test_flydsl_v4nm_decode` stayed in PR CI in #47150 because editing a file under `test/registered/kernels/` triggers NVIDIA's JIT kernel suite, which was failing on main (`test_gdn_prefill_graph.py`). That suite has passed on main's last three scheduled runs.
- The nightly MI35x 1-GPU suite becomes `test_quark_mxfp4` (~10 min), `test_flydsl_v4nm_decode` (~10 min) and a 10 s unit test. That's about 20 min, with a 90 min step timeout and 15 min per file.
