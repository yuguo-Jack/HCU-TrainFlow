# [AMD][DSV4][CP] Support interleave prefill CP with breakable CUDA graphs on ROCm

[Upstream PR](https://github.com/sgl-project/sglang/pull/43819) · state: open · merged: False

## Original PR description

## Motivation

#38603 lets DeepSeek V4 prefill use interleave context parallelism (CP) together with breakable CUDA graphs (BCG), but only the CUDA `DeepseekV4AttnBackend` was updated. On ROCm the CP+BCG gate (`supports_prefill_cp_bcg`) already passes for `--attention-backend dsv4`, so `--enable-prefill-cp --cp-strategy interleave --cuda-graph-backend-prefill breakable` enables CP capture on the HIP backend, which then fails. Today ROCm deployments have to choose between CP and breakable prefill graphs (the MI355X InferenceX DSv4 recipe uses BCG at low concurrency and CP from conc 16).

This PR ports #38603 to the HIP DSv4 backend (`DeepseekV4HipRadixBackend`, unified-KV path) for DeepSeek-V4-Pro and DeepSeek-V4-Flash. DeepSeek-V4.1-Flash needs HIP prefill CP first (#43465) and will follow in a separate PR.

## Modifications

- **HIP prefill metadata** (`deepseek_v4_backend_hip_radix.py`): same as the CUDA change in #38603. Under prefill graphs, the global KV-write fields use the bucket-sized `out_cache_loc` (`num_write_tokens`), so capture and replay shapes match when the live batch is smaller than its bucket. Otherwise `init_compression_metadata` asserts on the first padded replay. Also passes `cp_metadata.local_index` to `apply_cp_reindex` and pads `swa_replay_start` to the physical CP layout.
- **CP BCG inputs** (`layers/cp/bcg.py`, `prefill_cuda_graph_runner.py`):
  - `forward_batch.positions` now stays in global token order, as in eager CP. The captured body gets the CP-local positions and ids through `_cp_positions` / `_cp_input_ids`. The HIP unified-KV attention reads `forward_batch.positions` as global positions for the SWA ring store after the CP KV all-gather; with local positions it asserts at capture and would store wrong positions.
  - `input_ids_global` is set from fixed-address buffers: rank-major for TP MoE (a2a `none`, which routes the CP all-gathered rows) and CP-local for a2a backends. Without this, the DSv4 hash-routed MoE layers route on token-order ids during CP BCG replay. This affects both CUDA and ROCm. The `input_ids` / `positions` / `input_ids_global` handling is taken from #40333, limited to what DSv4 CP BCG needs.
- **Tests:**
  - `test_dsv4_prefill_cp_bcg.py`: replay keeps global positions; CP-local positions and ids use fixed addresses.
  - `test_dsv4_hip_bcg_metadata.py`: the HIP CP prefill metadata uses the bucket write length under prefill graphs.

## Usage (MI355X)

```bash
--attention-backend dsv4 --enable-prefill-cp --cp-strategy interleave \
--cuda-graph-backend-prefill breakable   # must be explicit; the DSV4 auto rule disables BCG otherwise
# env: SGLANG_HACK_FLASHMLA_BACKEND=unified_kv_triton (required by HIP prefill CP)
```
