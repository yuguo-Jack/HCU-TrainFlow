# [Feat] [AMD] dsv4: Support interleave prefill CP with breakable CUDA graphs

[Upstream PR](https://github.com/sgl-project/sglang/pull/43819) · state: open · merged: False

## Original PR description

## Motivation

#38603 added interleave prefill context parallelism (CP) with breakable CUDA graphs (BCG) for DeepSeek V4, but only in the CUDA backend. On ROCm, prefill graph capture fails under CP (`deepseek_v4_backend_hip_radix.py: assert cp_metadata is not None`), so deployments must choose between CP and BCG; the MI355X InferenceX DSv4 recipe, for example, uses BCG at conc 1/4 and CP at conc 16.

#44022 later disabled DSv4 CP + BCG because the capture path did not shard token IDs consistently with hidden states for hash routing. This PR fixes that in the shared CP BCG path and enables DSv4 CP + BCG on ROCm, for DeepSeek-V4-Pro and DeepSeek-V4-Flash. DeepSeek-V4.1-Flash is in #44013.

## Modifications

- **HIP prefill metadata** (`deepseek_v4_backend_hip_radix.py`): under prefill graphs, use the bucket-sized `out_cache_loc` for KV writes, pass `cp_metadata.local_index` to `apply_cp_reindex`, and pad `swa_replay_start` to the CP layout, as #38603 does for CUDA.
- **CP BCG inputs** (`layers/cp/bcg.py`, `prefill_cuda_graph_runner.py`): the captured body gets CP-local positions and `input_ids`, while `forward_batch.positions` stays global for the SWA ring store. `input_ids_global` is filled in eager CP's layout so hash-routed MoE layers route the right tokens (the #44022 issue; follows #40333).
- **CP prefill tail** (`layers/cp/utils.py`, `bcg.py`, `eager_runner.py`): skip all-gathering the pre-mHC-head states unless they are read. This removes ~4x extra gather traffic and an ~8.5 s TTFT stall on the first large prefill.
- **Supported combinations** (`layers/cp/bcg.py`): add `(INTERLEAVE, DSV4)` on ROCm. CUDA is unchanged.
- **Tests:** restore `test_dsv4_prefill_cp_bcg.py` and update `amd/test_dsv4_hip_bcg_metadata.py`.

## Usage

```bash
SGLANG_HACK_FLASHMLA_BACKEND=unified_kv_triton \
python -m sglang.launch_server ... --attention-backend dsv4 \
  --enable-prefill-cp --cp-strategy interleave --enable-cp-decode-attn-tp
```

On ROCm, BCG is selected automatically for this configuration (log: `Enabling breakable prefill CUDA graph for supported prefill CP`). Pass `--cuda-graph-backend-prefill disabled` to run eager CP instead.

## Test setup

- **Hardware:** 8x MI355X, TP8, DeepSeek-V4-Pro.
- **Image:** `lmsysorg/sglang-rocm:v0.5.21-rocm724-mi35x-20261011`. Stock is main `3b72b70ef4` and this PR is `0ccacc8055`, both overlaid on the same image.
- **Server:** InferenceX MI355X DSv4 recipe (`benchmarks/single_node/srt-slurm-recipes/dsv4/sglang/mi355x-fp4-mtp/agentic.yaml`):
  - KV cache: FP8 unified KV in every arm (`SGLANG_HACK_FLASHMLA_BACKEND=unified_kv_triton SGLANG_DSV4_UNIFIED_KV_FP8=1 --kv-cache-dtype fp8_e4m3`, two-pool FP8 nope + bf16 rope on gfx950). Under CP the packed FP8 KV is all-gathered before the store (`_materialize_cp_unified_fp8_kv`), and prefill attention runs `prefill_fp8_2buff`.
  - Other flags: FP4 indexer, `--chunked-prefill-size 16384`, `--mem-fraction-static 0.86`.
  - `--max-running-requests` and `--cuda-graph-max-bs-decode` are 2x conc, and the server is restarted per conc.
  - `SGLANG_DSV4_GROUPED_ASM=1` at conc 16 for all arms.
  - DSpark is off because the base V4-Pro checkpoint has no draft head.
- **Arms:**

| Arm | Code | Prefill flags |
|---|---|---|
| BCG | stock | `--cuda-graph-backend-prefill breakable` |
| CP | stock | `--enable-prefill-cp --cp-strategy interleave --enable-cp-decode-attn-tp` |
| CP+BCG | this PR | CP flags + `--cuda-graph-backend-prefill breakable` |

- **Client:** InferenceX fixed-seq client (`infx.bench_serving.benchmark_serving`): random dataset, `--random-range-ratio 0.8`, num-prompts 10x conc, 2x conc warmups, request rate inf, `--ignore-eos`.

**Summary**
- **CP+BCG matches or beats the better of BCG and CP at every point** on mean, P50 and P90 TTFT, except 8k/1k conc 4 P90 (425 vs 419 ms for CP).
  - Short prompts keep BCG's launch-free prefill: 1k/1k conc 1 is 67 ms, vs 210 ms for CP.
  - Long prompts keep CP's prefill split: 8k/1k conc 1 is 216 ms, vs 300 ms for BCG.
  - The largest mean gains come at 8k/1k conc 16 (−26% vs BCG, −30% vs CP) and 8k/1k conc 1 (−13% vs CP).
  - 8k/1k conc 4 is on par with CP: mean 302 vs 322 ms, P50 240 vs 244 ms, P90 425 vs 419 ms.
- **Decode:** TPOT and output throughput are within 2% of the best baseline. At conc 16, CP+BCG gives the best output throughput (1047 and 891 tok/s).
- **Tail:** the P99 TTFT at 8k/1k conc 16 (BCG 5.4 s, CP 6.5 s, CP+BCG 4.1 s) is queueing of 16 concurrent 8k prompts behind the 16k prefill chunk, not a stall. CP+BCG server logs show no step gap ≥ 1.5 s. The stock arms had 2–5 s step gaps at some points, which raise their means there.
- **First large prefill:** with the prefill-tail fix, the first large CP+BCG prefill on a fresh server shows no stall. Before the fix, the first 4x8k batch took 9.0–9.3 s, with RCCL communicator init in the window; after the fix it takes 0.7–1.0 s, with no RCCL init.

## AgentX (DeepSeek-V4-Pro-0813, TP8, DSpark gamma 6)

**Setup**
- InferenceX AgentX client (`srt_agentic.sh`, traces `semianalysis_cc_traces_weka_062126`, 900 s per point, all points `submission_valid`), using the recipe's own conc 1/4/16 points.
- **Recipe** = the InferenceX recipe as-is, on stock: BCG at conc 1/4, CP at conc 16.
- **CP+BCG** = this PR at every conc, plus `SGLANG_ENABLE_WAR_BARRIER=1`. DSpark with BCG needs the WAR barrier for correctness on ROCm; the recipe's BCG arms run without it.

| 4 | BCG + barrier | 441 / 241 / 986 | 6.48 / 6.32 / 8.18 | 19.9 | 3.63 |

**Takeaways**
- **conc 16:** CP+BCG beats the recipe's CP on every TTFT stat (mean −28%, P50 −44%, P90 −26%) and on ITL (mean −5.2%, P90 −14%), with the same throughput.
- **conc 1/4:** CP+BCG lowers mean and P90 TTFT by 18–30% vs the recipe's BCG.
  - ITL is about 20% higher, but that comes from the WAR barrier, not from CP+BCG.
  - With the barrier in both arms (conc 4), CP+BCG ITL is within 2% of BCG.
  - Without the barrier in both arms, CP+BCG ITL matches the recipe (5.57 vs 5.60 ms).
  - Making the HIP WAR barrier cheaper is a separate follow-up.
- **No stall:** server logs show no busy-time gap ≥ 1.5 s in any CP+BCG point. That covers about 103 large prefill batches at conc 16.

## BF16 unified KV (DeepSeek-V4-Flash, TP4)

All data above uses FP8 unified KV. This PR's position and KV-gather changes also apply to the BF16 unified layout, so it was checked separately. Settings are the same as the V4-Flash runs, except `SGLANG_DSV4_UNIFIED_KV_FP8=0` (server log: `unified=True unified_fp8=False`). Arms: CP and CP+BCG at conc 4 and 16, each run twice on fresh servers.

- **Correctness**
  - GSM8K: CP 0.9682, CP+BCG 0.9682. FP8-KV CP+BCG was 0.9697.
  - Greedy outputs (11 prompts of 2 to 30k tokens): CP vs CP+BCG diverge only at near-ties (top-1/top-2 gap ≤ 0.625 nats). Stock CP compared with itself on two fresh servers diverges just as often, so this is BF16 run-to-run noise.
  - The 12k, 17k and 30k prompts, which go through multi-chunk CP prefill, match for 22–32 of 32 tokens.
- **Performance vs CP** (mean / P50 / P90 TTFT in ms, second pass)

| ISL/OSL | conc | CP TTFT | **CP+BCG TTFT** | TPOT mean (CP / CP+BCG) |
|---|---|---|---|---|
| 1024/1024 | 4 | 169 / 131 / 254 | **63 / 46 / 65** | 8.17 / 7.93 |
| 1024/1024 | 16 | 397 / 190 / 460 | **127 / 64 / 269** | 11.27 / **10.05** |
| 8192/1024 | 4 | 548 / 168 / 332 | **201 / 158 / 280** | 8.59 / **8.28** |
| 8192/1024 | 16 | 408 / 217 / 655 | 401 / 218 / 640 | 11.68 / 11.42 |
| 8192/2 | 16 | 1745 / 1788 / 2026 | 1746 / 1786 / 2024 | – |

- Stock CP had a 2–4 s step gap at 1k/1k conc 16 and 8k/1k conc 4, which raises its mean there.
- **BF16 vs FP8 KV for CP+BCG:** no meaningful difference. TTFT is within run-to-run noise, and BF16 TPOT P50 is 1.5–2.2% lower.
- These BF16 runs shared the node with another TP4 job, so absolute numbers are a bit noisier than the FP8 runs above.
