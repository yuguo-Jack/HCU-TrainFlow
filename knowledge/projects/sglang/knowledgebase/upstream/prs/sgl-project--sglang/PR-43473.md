# [HiCache] Add staging buffers for LayerSplit L3 storage

[Upstream PR](https://github.com/sgl-project/sglang/pull/43473) · state: open · merged: False

## Original PR description

## Motivation

LayerSplit distributes the L2 KV cache across ranks by layer. With direct L3
storage, each rank writes its layer shards as separate objects. As the number
of ranks and cached pages grows, this increases L3 object count and metadata
overhead.

This PR introduces optional, per-rank staging buffers to store full-layer pages
in L3 while retaining the layer-sharded L2 layout.

A shared page-owner plan assigns each full-layer page to exactly one rank.
Each rank is responsible for only a subset of the pages:

- **Backup:** ranks exchange their layer shards so each page owner can assemble
  its full-layer pages. Each rank then writes only the pages it owns to L3.
- **Prefetch:** each rank reads only the full-layer pages it owns from L3, then
  uses all-to-all exchange to distribute their layer shards to the corresponding
  ranks.

```text
HybridCacheController
│
├── Shared Page-Owner Plan
│   ├── Each full-layer page is assigned to exactly one rank
│   └── Each rank owns only a subset of the pages
│
├── Backup: L2 → L3
│   │
│   └── L2 Host Pools
│       │   Each rank holds its layer shards for the pages being backed up
│       │
│       └── Staging Buffer (backup, per rank)
│           │
│           │   All-to-all exchange:
│           │   1. Each rank sends its shards to the corresponding page owners
│           │   2. Each owner gathers shards from all ranks
│           │   3. Each rank assembles ONLY the full-layer pages it owns
│           │
│           └── L3 Storage (Mooncake)
│               │   Each rank writes ONLY its owned full-layer pages
│               │
│               └── Per owned page:
│                   ├── SET full-layer KV object
│                   └── SET full-layer indexer object
│
└── Prefetch: L3 → L2
    │
    └── L3 Storage (Mooncake)
        │   Each rank reads ONLY its owned full-layer pages
        │
        └── Staging Buffer (prefetch, per rank)
            │
            │   All-to-all exchange:
            │   1. Each owner splits its full-layer pages into layer shards
            │   2. Each owner sends each shard to the rank responsible for its layers
            │   3. Each rank receives its layer shards from all page owners
            │
            └── L2 Host Pools
                └── Each rank stores its layer shards for all prefetched pages
```

Page ownership distributes L3 reads and writes across ranks, while layer
ownership determines each rank's L2 contents. Ranks with no owned pages in a
window still participate in the shard exchange.

Each rank maintains separate, fixed-capacity backup and prefetch buffers,
reused across transfer windows to bound staging memory usage.

For CP8 with non-empty KV and indexer shards on every rank, this reduces L3
objects per logical page from **16 shard objects to 2 full-layer objects**:
one KV object and one indexer object. The resulting **87.5% reduction in object
count** lowers storage metadata overhead.

## Modifications

- Add `--enable-hicache-layer-split-staging`, disabled by default.
- Introduce bounded, window-based staging buffers for L3 backup and prefetch.
- Reuse native host pools and the prefetch ACK lifecycle.
- Support the Mooncake storage path, including uneven layer ownership and empty
  indexer shards.
- Add configuration validation, unit tests, and CLI documentation.

The initial scope is DSA LayerSplit with Mooncake, `layer_first` host layout,
`cache` host memory mode, and PP=1 PD prefill workers. Draft/MTP layers are not
supported.

## Accuracy Tests

### GSM8K

For each mode, we ran GSM8K twice and issued a cache flush between runs,
retaining L3 data to exercise L3-backed prefetch in the second run.

| Mode | Accuracy |
| --- | ---: |
| Direct | 93.56% |
| Staging | 92.65% |

Staging scored **0.91 percentage points** below Direct in these runs.

## Speed Tests and Profiling

### Workload and data distribution

We replayed **8,000 requests** from an internal multi-turn agent dataset,
preserving turn order within each task. The sample covered **446 tasks**,
with approximately **18 replayed turns per task**.

- **Mean input/output per request:** **45.2K:63.5 tokens**, with output capped at 64 tokens.
- **Theoretical cache hit rate:** **94.558%**
- **Load configuration:** **MC=32, Task=200**. MC limits concurrent in-flight
  requests; Task is the active task pool size. A larger task pool increases
  the cache working set and eviction pressure on L1/L2.

### P/D configuration

Model: **GLM-5.2-FP8**, with separate prefill and decode workers, both using PP1.
Relevant launch options are shown below; model paths and network endpoints are omitted.

**Prefill (P): TP8/CP8, 64 GiB host cache per rank**

```diff
 --disaggregation-mode prefill
 --disaggregation-transfer-backend mooncake
 --tp-size 8
 --attention-context-parallel-size 8
 --enable-prefill-cp
 --cp-strategy interleave
 --enable-dsa-cache-layer-split
 --kv-cache-dtype fp8_e4m3
 --page-size 64
 --mem-fraction-static 0.85
 --chunked-prefill-size 16384
 --enable-hierarchical-cache
 --hicache-host-memory-mode cache
 --hicache-size 64
 --hicache-write-policy write_through
 --hicache-io-backend kernel
 --hicache-mem-layout layer_first
 --hicache-storage-backend mooncake
 --hicache-storage-prefetch-policy timeout
-# Direct: omit the staging flag; each rank stores its layer shards directly.
+# Staging: assemble owned full-layer pages before L3 writes and redistribute after reads.
+--enable-hicache-layer-split-staging
```

The storage prefetch threshold was `0`. Staging used **8,192-token windows**
and **8 exchange groups**.

**Decode (D): TP8, identical for both modes**

```text
--disaggregation-mode decode
--tp-size 8
--kv-cache-dtype fp8_e4m3
--page-size 64
--mem-fraction-static 0.85
--cuda-graph-max-bs-decode 64
```

### Results

Both modes completed **8,000/8,000 requests**, with matching request coverage
and total input/output token counts. Both started with cold KV cache data.
Direct uses the repeat-run baseline with reused runtime/JIT caches.

| Metric | Direct | Staging | Change vs. Direct |
| --- | ---: | ---: | ---: |
| Client preparation time (s) | 17.86 | 17.91 | +0.05 s |
| Input throughput, including client preparation (tok/s) | 117,526 | 113,962 | −3.03% |
| Input throughput over active request span (tok/s) | 118,214 | 114,611 | −3.05% |
| Mean TTFT (s) | 11.56 | 11.95 | ≈ +3.4% |
| P99 TTFT (s) | 60.93 | 60.70 | ≈ −0.4% |
| Overall cache hit rate (%) | 94.558 | 94.365 | −0.193 pp |
| L3 data objects | 4,852,128 | 606,516 | −87.50% |
| Mooncake Master RSS increase (GiB) | 5.74 | 0.79 | −86.16% |

Overall cache hit rate includes L1/L2/L3. RSS reduction is calculated from
unrounded measurements. Results are from benchmark commit `d8094d282d`.
