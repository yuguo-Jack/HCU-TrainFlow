# fix(router): count shared prompt tokens once for n>1 in gRPC chat streaming

[Upstream PR](https://github.com/sgl-project/sglang/pull/31651) · state: closed · merged: False

## Original PR description

## Summary

In the gRPC chat streaming path (`process_streaming_chunks`), the prompt token count is inflated by a factor of `n` whenever `n > 1`.

Each choice's `Complete` message stores the **shared** prompt length into `prompt_tokens[index]`:

```rust
prompt_tokens.insert(index, complete.prompt_tokens() as u32);
```

The prompt is prefilled once and reused across all `n` choices, so every index holds the *same* value. The usage chunk and the streaming metrics then did:

```rust
let total_prompt: u32 = prompt_tokens.values().sum();
```

which adds the shared prompt once per choice → `usage.prompt_tokens`, `total_tokens`, and the `input_tokens` metric are all reported as `prompt × n`.

## Fix

Aggregate the prompt with a small helper that takes the shared value (`max`) so the prompt is counted exactly once:

```rust
fn aggregate_prompt_tokens(prompt_tokens: &HashMap<u32, u32>) -> u32 {
    prompt_tokens.values().copied().max().unwrap_or(0)
}
```

Applied at both sites (usage chunk + metrics). Completion tokens stay summed (`.values().sum()`), since those legitimately differ per choice. Behavior for `n = 1` is unchanged (`sum == max`).

## Test plan

- [x] New `#[cfg(test)]` unit tests for `aggregate_prompt_tokens`:
  - `prompt_tokens_counted_once_for_n_choices`: `{0:100, 1:100, 2:100}` → `100` (not `300`)
  - `prompt_tokens_single_choice_unchanged`: `{0:42}` → `42`
  - `prompt_tokens_empty_is_zero`: `{}` → `0`
- [x] Confirmed `cargo` isn't required to see the bug: the pre-fix `sum()` yields `300` for an `n=3` shared-100-token prompt; the helper yields `100`.
