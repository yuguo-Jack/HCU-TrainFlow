# [Fix] spec: Share draft embed/head before target KV pool sizing

[Upstream PR](https://github.com/sgl-project/sglang/pull/45151) · state: open · merged: False

## Original PR description

  ## Motivation

  Fixes #44145.

  `EagleDraftWorker` loads its own `embed_tokens`/`lm_head`, but only binds them
  to the target's tensors in `alloc_memory_pool()`. The scheduler sizes the target
  KV pool in `init_target_memory_pool()` before that, so the duplicate draft
  tensors are still resident during profiling and the KV pool is permanently
  undersized.

  ## Modifications

  - Call an idempotent `_share_embed_and_head()` at the end of
    `EagleDraftWorker.__init__`, before the scheduler profiles free memory.
  - `alloc_memory_pool()` reuses that state instead of calling
    `init_token_map()` / `init_lm_head()` again.

  ## Verification

  RTX 4090, Qwen3.5-2B, `--speculative-algorithm NEXTN`:

  | Config | max_total_num_tokens |
  | --- | --- |
  | no speculation | 1,315,939 |
  | MTP, before | 1,193,623 |
  | MTP, after | 1,276,396 |

  Greedy output and `spec_accept_length` are unchanged.

  New CPU regression test:
  `test/registered/unit/spec/test_eagle_share_embed_and_head.py` — 2 passed.

  ## Note

  This fixes the KV sizing order. It does not reduce peak memory while the draft
  model itself is being constructed; on a 24 GB GPU a 27B untied-embedding model
  can still need more memory than is available before the sharing point.
