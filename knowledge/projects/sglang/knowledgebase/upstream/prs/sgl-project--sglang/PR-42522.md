# [Fix] logging: Honor no_logs when logging requests

[Upstream PR](https://github.com/sgl-project/sglang/pull/42522) · state: open · merged: False

## Original PR description

`GenerateReqInput.no_logs` is documented as the per-request opt-out of request
logging ("Whether to disallow logging for this request (e.g. due to ZDR)",
`managers/io_struct.py`) and it is plumbed through to the internal
`TokenizedGenerateReqInput`, but no code path ever reads it. A request that sets
`no_logs=true` is still logged in full — at `--log-requests-level 3` the prompt
text and tokenized input end up in the request log.

## Reproduce

Serve with `--log-requests --log-requests-level 3` and send
`{"text": "<prompt>", "no_logs": true}` to `/generate`: the server still writes
`Receive: obj=GenerateReqInput(..., text='<prompt>', ...)` and the matching
`Finish: obj=...` records.

## Fix

`RequestLogger.log_received_request` / `log_finished_request` are the only paths
that emit request payloads, so both now skip a request that carries `no_logs`.
`getattr(obj, "no_logs", False)` keeps request types that do not define the
field (`EmbeddingReqInput`) logging as before.

Scope: this only changes request logging. Debug/crash dumping
(`dump_requests_folder`) is untouched — it is an explicit operator opt-in, while
`no_logs` is the per-request contract.

## Test

New CPU-only `test/registered/unit/utils/test_request_logger.py`:

- `no_logs=true` writes nothing for received or finished requests (both fail
  against unpatched `main`, verified)
- `no_logs=false` still logs the request content
- a request type without the field still logs

Duplicates: no open PR or issue touches `no_logs` or this logging gate (checked
PRs/issues and code search at main before writing this).
