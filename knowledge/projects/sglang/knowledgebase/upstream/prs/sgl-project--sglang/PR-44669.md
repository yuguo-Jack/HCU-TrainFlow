# fix: bound decoded client audio resource usage

[Upstream PR](https://github.com/sgl-project/sglang/pull/44669) · state: open · merged: False

## Original PR description

## Summary

Bound decoded client audio before an unbounded waveform is retained, addressing the compressed-audio expansion reported in #43708.

- Add `--max-audio-decoded-bytes` (256 MiB by default; `0` disables) and optional `--max-audio-duration-seconds`, with argument validation and documentation. This budget is **not** a peak RSS or aggregate concurrency limit.
- Enforce the limits on TorchCodec, SoundFile, and PyAV/container decoding paths. Preserve limit errors instead of masking them in decoder fallbacks, and cover additional streaming ASR, transcription, and model-specific decoding paths.
- Add tests for encoded-to-decoded expansion, decoder budgets, argument validation, and the transcription handler's HTTP 400 response without model dispatch.

## Validation

- H20 host with real TorchCodec 0.17.0+cu130, PyAV 19.0.1, and SoundFile 0.14.0: a 5,588-byte, 120-second silent FLAC was rejected at a 30-second duration cap or a 1 MiB decoded-byte budget; a 16 MiB budget allowed decoding to a 7,680,000-byte float32 waveform on the TorchCodec path.
- Transcription and server-argument suites: **37 passed, 6 subtests passed**. The new handler-level test confirms status 400 and no model dispatch for an over-duration input.
- Audio container suite on the same host: **19 passed, 1 skipped, 8 subtests passed** using a temporary test copy that skips the AMR-only case; the host's FFmpeg build lacks the optional `libopencore_amrnb` encoder, so the unmodified suite fails during shared fixture setup before individual tests run.
- `compileall` for modified runtime files and `git diff --check` passed.

The tests do not measure peak process RSS, concurrent-request behavior, or a running model-backed HTTP endpoint; no OOM was attempted.
