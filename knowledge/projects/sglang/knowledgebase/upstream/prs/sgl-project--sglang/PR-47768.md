# [Perf] hicache: Extend prefix_keys in place across storage batches

[Upstream PR](https://github.com/sgl-project/sglang/pull/47768) · state: open · merged: False

## Original PR description

## Motivation

In `HiCacheController._page_transfer`, `_storage_hit_query`, and `_page_backup` (`python/sglang/srt/managers/cache_controller.py`), pages are processed in chunks of `STORAGE_BATCH_SIZE = 128`, advancing `prefix_keys` after each batch via:

```python
if prefix_keys is not None:
    prefix_keys = prefix_keys + batch_hashes
```

Across $B$ batches, `prefix_keys + batch_hashes` reallocates and copies the entire accumulated `prefix_keys` list on every batch ($O(B^2)$ list copies), spending ~195 ms in pure Python list reallocation for a 100k-page sequence.

## Modifications

- Copy `operation.prefix_keys` once at the start of `_page_transfer`, `_storage_hit_query`, and `_page_backup` (`list(operation.prefix_keys) if operation.prefix_keys is not None else None`) so `operation.prefix_keys` is never mutated.
- Advance `prefix_keys` in place on each batch with `prefix_keys.extend(batch_hashes)` ($O(B)$ total work, reducing 100k-page prefix tracking overhead from ~195 ms to ~0.4 ms).
- Added unit tests in `test/registered/unit/mem_cache/test_hicache_prefix_keys_batching.py` covering `_storage_hit_query`, `_page_transfer`, and `_page_backup`.

## Accuracy & Benchmark Tests
- `pytest test/registered/unit/mem_cache/test_hicache_prefix_keys_batching.py -v` (`3 passed`)
