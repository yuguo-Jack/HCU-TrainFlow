# [Fix] speculative: Reduce available_memory_gb across caller-supplied TP group

[Upstream PR](https://github.com/sgl-project/sglang/pull/42296) · state: open · merged: False

## Original PR description

## Description

Fixes #39886.

`SpecTpSync` binds to the attention TP group at construction and disables every sync site when that group has a single rank. DSpark's DP-attention draft configuration (attention TP=1, full TP>1, DeepSeek-V4/MoE draft) then calls `available_memory_gb` with the **full TP group**: the site gate leaves `distributed=False`, so each rank reads rank-local free memory instead of the group minimum. Ranks can straddle the 1 GiB decode-graph threshold, disagree on `capture_decode_cuda_graph`, and stall startup inside the capture backend's barrier+forward collectives.

The fix: when the caller supplies a group **other than the one this sync was built from**, the reduction is a collective-alignment requirement, so the site gate does not apply:

```python
distributed = group.world_size > 1 and (
    self.enabled(site) or group is not self._tp_group
)
```

Same-group callers (e.g. EAGLE workers passing the sync's own group) keep their exact site-gated semantics.

## Verification

Unit-level (the issue's mock repro, no GPU needed), run against `main` before/after:

```python
sync = SpecTpSync(SimpleNamespace(world_size=1))            # attn TP=1
full_tp2 = SimpleNamespace(world_size=2, cpu_group=object())
sync.available_memory_gb(SpecTpSyncSite.DSPARK_MEM, "cuda", 0, group=full_tp2)
# get_available_gpu_memory kwargs["distributed"]: before False (bug), after True
```

Regression matrix (test/srt/test_spec_tp_sync.py, all pass):

| case | distributed |
|---|---|
| foreign multi-rank group (the bug) | False → **True** |
| constructor multi-rank group (sites default on) | True → True (unchanged) |
| constructor group with `SGLANG_SPEC_TP_SYNC=-all` | False → False (gate preserved) |
| single-rank group | False → False (unchanged) |

We could not reproduce the full multi-GPU startup stall (needs DSpark + DP attention + straddling memory readings), same as the reporter — the fix follows from the unit-reproduced skipped reduction plus the collective-mismatch code path cited in the issue.
