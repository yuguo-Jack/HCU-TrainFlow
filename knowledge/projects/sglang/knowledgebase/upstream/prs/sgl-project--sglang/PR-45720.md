# [Feat] [MLU] Add Qwen3 BF16 inference and graph execution

[Upstream PR](https://github.com/sgl-project/sglang/pull/45720) · state: open · merged: False

## Original PR description

## Motivation

Enable Qwen3 BF16 inference through the in-tree Cambricon MLU backend, building on the device, CNCL, RMSNorm, installation, and CI foundations in #45149.

**Depends on #45149.** The Phase 2 commit is based on its current head, `a93e9e08b9`. Until that PR merges, this PR's comparison against `main` also includes the foundation changes.

## Modifications

- Resolve MLU attention, page-size, and sampling defaults through the existing platform configuration hook; reject unsupported backend, quantization, and speculative settings during resolution.
- Add MLU SiLU gating and RoPE, including Neox/interleaved layouts, partial rotary dimensions, offsets, and cache replacement.
- Add an HND MHA KV pool with vendor paged-cache writes. Reuse the shared paged allocator and its torch-native implementation.
- Add paged GQA prefill/decode attention for causal decoder self-attention; explicitly reject nonzero logit caps, noncausal attention, and cross-attention before KV writes or kernel execution. Ragged query/KV lengths support cached prefixes, chunked prefill, and mixed prefill/decode batches.
- Reuse shared weight loading, TP execution, CNCL communication, and DP replica scheduling.
- Add full decode graphs and prefill breakable graphs using shared runner/capture lifecycles, MLU graph primitives, stream-capture checks, and non-owning tensor views.
- Add MLU activities to both profiling interfaces and decode graph profiling.
- Add numerical operator/attention tests, platform resolution tests, a Qwen3 eager/graph/TP/DP nightly test, the missing nightly suite registration, and serving documentation.

## Validation

Local Cambricon MLU590 hardware, with the separate `sglang-mlu` plugin disabled (`SGLANG_PLUGINS=none`):

- 47 focused operator, attention, fused-op dispatch, and full-graph backend tests passed after rebasing onto the latest #45149 head.
- Four MLU platform tests passed, including raw-input preservation, resolved defaults, and rejection of unsupported settings.
- Qwen3-0.6B: the registered test passed for TP1 eager, TP1 graphs, TP2 graphs, and DP2 graphs, including cached-prefix hits and chunked prefill. Additional overlap-enabled TP2 and TP2×DP2 generation checks passed. DP2 generation, cached prefixes, and chunked prefill were also rerun successfully on the rebased head.
- Qwen3-8B BF16 TP2: eager and graph generation passed. Tested decode graph capture/replay, prefill BCG, changing batch sizes, cached prefixes, and eager fallback outside capture buckets. Eager and graph runs produced the same text for the tested prompts.
- The selected next token agreed with a Hugging Face BF16 CPU reference on two prompts. This is a smoke comparison, not a model accuracy benchmark.
- Profiling exported a Chrome trace containing MLU kernels, and decode graph profiling produced an MLU memory snapshot.
- Pre-commit, `mint validate`, and `mint broken-links` checks passed.

## Remaining validation

This PR remains a draft. Qwen3-8B TP1 and TP1×DP2, a full accuracy evaluation, and representative performance benchmarks still need dedicated hardware validation. The current shared host has approximately 8.5 GiB free per device; the 8B TP2 smoke run therefore used a 512-token pool and small graph buckets. Qwen3-0.6B covers the TP1/DP and larger prefill capture paths in the meantime.

MLU graph memory saver and graph deduplication are unsupported. Prefill graph shapes outside supported buckets fall back to eager execution.
