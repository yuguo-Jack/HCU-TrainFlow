# [Feat] [Ascend] quantization: :sparkles: Support online W4A8 MoE

[Upstream PR](https://github.com/sgl-project/sglang/pull/43739) · state: open · merged: False

## Original PR description

## Summary

Add `--quantization mxfp_w4a8` support for Ascend MoE experts and completion-tracked loading for online W4A8 Linear/MoE weights. FP16/BF16 weights are converted to packed MXFP4 as each logical weight finishes loading, then run with MXFP8 activations. Pre-quantized ModelSlim checkpoints keep their existing path.

## Scope

This PR is limited to online W4A8 functionality, loading lifecycle, and explicit FP4 weight policy. The later TP routing-fusion/threshold and GDN input-reuse experiments have been archived and removed from this PR. Performance optimization will be handled separately; no serving speedup is claimed here.

The feature branch was restored to `3cdd0182b9dbb18c336594564fb7b98a2d97f87a` and merged with upstream main `9e9296fdf352d767e66d49367b8763fd788184b6`. The current head is `c0e0fab8e6a039793782c6be92a7f0b245d32212`. The general local-K/per-matmul fixes identified during #32602 review now live in this prerequisite PR. Its separate #36426 validation branch was updated in the same round; #32602 inherits these fixes via an ordinary merge. No W4A4 feature or #36426 patch was brought into this PR.

## Changes

- Allocate floating-point source weights lazily, preserve native TP/EP shard loading, and quantize Linear weights and MoE W13/W2 independently when their local shards are complete. Release source backing storage even when a caller retains an old Parameter handle.
- Validate completion during post-load processing, reject duplicate/incomplete loads, and support reloads through registered weight loaders. Reuse `CopyNumelCounter`.
- Explicitly use `round_mode="rint", scale_alg=2, dst_type_max=7.25` for online Linear/MoE FP4 weights. Do not copy those settings into MXFP8 activation quantization or requantize offline packed weights; W4A4 is unchanged.
- Reuse upstream W4A8 grouped matmuls, prepared weight/scale layouts and dispatcher contracts. Support the `auto` and `ascend` MoE runners.
- Handle Dense A8W4 bias and retain floating-point fallback for non-aligned Linear layers. Check local K using the bound TP group for RowParallelLinear before `input_size_per_partition` exists; Column/replicated layers do not divide K by TP.
- Make runner construction and execution both consult W13 for gmm1 fusion. Add keyword-only `weight_prefix` to the W4A8 kernel while preserving its existing positional quant-policy argument. Online, ModelSlim, compressed-tensors, DeepSeek FP4 and FP8-config FP4-expert entrypoints bind W13/W2 explicitly; W2 no longer creates a fused component. Weight/activation policies and layouts are unchanged.
- Resolve concrete post-load device aliases before residency checks, avoiding unsupported restore copies of already-resident NZ views while retaining real cross-device staging.
- Preserve upstream EPLB all-local-replica/shared-slot filtering. Adapt its stand-in test fixture to the extracted `_weight_loader_expert_ids` helper.

## Usage and references

Use an unquantized FP16/BF16 checkpoint with `--quantization mxfp_w4a8`. No separate `--online-quantization` flag is added.

Replaces #32601 and uses the merged #32745 fixes. Ascend 950 Qwen3.5 requires a compatible Gemma kernel wheel/API containing [sgl-kernel-npu#638](https://github.com/sgl-project/sgl-kernel-npu/pull/638).

The loading lifecycle is adapted from #29048; it is a reference, not a merge dependency. The FP4 weight policy follows #43367. #44738 covers a separate diffusion W8A8 path.

- Before: `493372ce8fee`, the direct parent of loading-lifecycle change `ab8f7cd9ce`; online W4A8 is already supported, with quantization deferred until post-load.
- After: `c0e0fab8e6a0`, the current formal PR head, without the separate #36426 combination patch.

| NPU allocator metric | Before (GiB) | After (GiB) | Reduction |
| --- | ---: | ---: | ---: |
| Peak allocated | 65.964 | 20.603 | **45.361 GiB / 68.77%** |
| Peak reserved | 66.129 | 20.869 | **45.260 GiB / 68.44%** |

Percentages use the rounded summary values. The loading peak decreased substantially while end-of-load allocation stayed approximately constant, consistent with reducing transient loading residency rather than substantially changing the final resident footprint.

**Measurement scope:** the same collector synchronizes and resets NPU allocator peaks at each worker's `ModelRunner.load_model` entry, then synchronizes and reads the counters when the method returns. The window includes construction, weight loading and post-load preparation, but excludes subsequent KV-pool allocation, graph capture and serving warmup. These are **loading-stage allocator peaks, not total-device HBM or whole-startup peaks**.

This is user-reported deployment evidence, not a locally executed NPU test. The version pair also includes upstream synchronization, weight-policy changes and later fixes, so it is not a loader-only ablation or a per-source-buffer lifetime trace. Full configuration, software and physical-device mapping remain in the original JSON reports/server logs and were not included in the pasted summary. No inference-memory, warmup/request, accuracy or throughput result is implied by these measurements.
