# [Perf] [AMD] aiter: Run 12-head MLA decode and 8-token verify on fp8-Q ASM

[Upstream PR](https://github.com/sgl-project/sglang/pull/45320) · state: open · merged: False

## Original PR description

## Motivation

- Kimi-K3 TP8 on gfx950 runs 12 MLA heads per rank (zero-padded to 16) with an FP8 KV cache.
- Decode and short verify windows default to AITER Gluon. On AgentX c1 traffic (long context, DSpark block 7 / 8-token verify) Gluon is the per-step latency bottleneck: P90 ITL 6.77 ms vs 6.18 ms on the persistent FP8-query ASM kernel (5.18 vs 4.50 ms with the AMD MonoKernel on).
- The ASM route cannot be turned on for this backend alone today: `SGLANG_AITER_MLA_PERSIST` is process-wide and would also move draft extend and other backends.
- AITER's FP8-query kernels return wrong output for 2-4 token windows (ROCm/aiter#7007), so the route must skip those windows.

## Modifications

- New opt-in route: on an eligible backend, decode and the target-verify window run on the persistent FP8-query ASM MLA kernel.
  - Eligible: gfx950, 12 heads with zero padding, FP8 KV, `SGLANG_AITER_MLA_DECODE_BACKEND=asm` and `SGLANG_AITER_MLA_VERIFY_BACKEND=asm`, no DCP.
  - Persistence is scoped to that backend instance (`_mla_ps_kernel_enabled()`); under `SGLANG_AITER_MLA_PERSIST=0`, draft extend and other backends keep the non-persistent path and a bf16 query.
  - Metadata uses the `PERSIST=1` schedule; KV splits follow `SGLANG_AITER_MLA_AUTO_KV_SPLITS`.
  - The query is quantized with the saturating static FP8 quant (scale 1.0), so out-of-range values clamp instead of becoming NaN. This also applies to the existing >4-token FP8-query cast.

| New env var | Default | Effect |
|---|---|---|
| `SGLANG_OPT_HIP_MLA_FP8_Q_ASM` | `false` | Run decode and short verify on the FP8-query ASM kernel for an eligible backend |
| `SGLANG_OPT_HIP_MLA_FP8_Q_ASM_MAX_QLEN` | `4` | Widest verify window (1-8) the route takes; 5-8 fold onto AITER's 32-head qlen-4 kernel, which beats Gluon only from about 128K context on MI355X. Out of range raises at startup when the route is on |

| Verify window (`num_draft_tokens`) | Route with the opt-in on |
|---|---|
| 1 (no spec, decode only) | FP8-query ASM |
| 2-4 | previous routing (ROCm/aiter#7007) |
| 5 to `MAX_QLEN` (needs `MAX_QLEN` >= 5) | FP8-query ASM, folded |
| above `MAX_QLEN` | previous routing |

- Tests (`test_aiter_gluon_h12_fp8.py`, CPU): selector conditions, window bounds, per-instance persistence scope under `PERSIST=0`, module modes under `PERSIST=1` with auto KV splits, query cast, saturation, and the bf16 query on non-persistent calls.
