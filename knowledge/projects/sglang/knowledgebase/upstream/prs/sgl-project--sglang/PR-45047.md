# [Refactor] scheduler: Bill encoder replay rows in `_update_prefill_budget`

[Upstream PR](https://github.com/sgl-project/sglang/pull/45047) · state: closed · merged: True

## Original PR description

Follows up #45040.

- `_PrefillAdmission` carries `replay_len`, read once in `_select_prefill_admission`; chunk sizing and the commit both use it. When a host load-back delivers more than the promised prefix, the rebuilt admission recomputes it from the loaded prefix.
- `_update_prefill_budget` takes `replay_len` and bills it to the compute budgets together with the extend. Its docstring lists what a request adds to a step. `log_replay_tokens` moves next to `log_input_tokens`, and `_account_prefill_cache_admission` no longer touches the budgets.
- `_update_prefill_budget` picks the exact-chunk-fill charge itself, which drops the `compute_charge` parameter and the same conditional at its four call sites. The dLLM callers keep the page-ceiled charge, since exact-chunk-fill is off under dLLM.
- `_replay_rows` is renamed `_replay_len`, after `encoder_swa_replay.replay_len`, and the chunk-sizing comment states the rule instead of its consequence.
- `encoder_swa_replay.resets_swa_window` holds the check for a request whose SWA window starts this step. `_replay_len` and `ScheduleBatch.encoder_swa_reset` both call it, so the budget and the fold agree on which requests replay.
- A dLLM test that builds a bare `PrefillAdder` stubs `_replay_len` next to its other stubs.

No behavior change, except with a dLLM model and `--enable-encoder-swa-bounded-replay`: replay tokens now bill `rem_dllm_tokens` instead of `rem_chunk_tokens`. Encoder replay is a DeepSeek-V4.1 feature, so that combination is not supported.
