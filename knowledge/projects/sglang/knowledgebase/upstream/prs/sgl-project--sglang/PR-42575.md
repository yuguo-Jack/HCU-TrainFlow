# [Fix] glm-4.7: Fix quadratic regex scans in the tool-call parser

[Upstream PR](https://github.com/sgl-project/sglang/pull/42575) · state: open · merged: False

## Original PR description

## Motivation

`Glm47MoeDetector` (`glm47`) and its `IQuestQ1Detector` subclass (`iquest_q1`) scan model output with patterns that go quadratic on unpaired tags:

1. **Tool-call blocks:** `detect_and_parse` runs `re.finditer` / `re.findall` with `<tool_call>.*?</tool_call>`, which rescans to the end of the text from every opening tag when the closing tag never arrives.
2. **Arguments:** `<arg_key>(.*?)</arg_key>(?:\\n|\s)*<arg_value>(.*?)</arg_value>`. Every `<arg_key>` whose pair never completes rescans the rest of the call. The same `findall` also runs in `_finalize_tool_call` (streaming), and `IQuestQ1Detector` runs it through `findall` + `sub`.

| Input | Before | After |
|---|---|---|
| 96 KB of `<tool_call> `, non-stream | 18.8 s | < 1 ms |
| 160 KB call of repeated `<arg_key>a</arg_key>`, non-stream | 24.9 s | 57 ms |
| same, the **single streaming chunk** that closes the call | 26.8 s | 24 ms |

Tool-call parsing runs synchronously on the tokenizer manager's event loop, so one such response stalls every in-flight request. Found with an Atheris fuzzing harness that records per-input parse time.

## Modifications

- `_iter_tool_call_spans`: a linear `str.find` scan returning the same spans `finditer` did. The unused `func_call_regex` is removed.
- `iter_arg_pair_matches`: a linear scanner yielding the same `(start, end, key, value)` matches as `finditer` on the argument regex. It first records each `</arg_key>` that is followed by a value opener; each key then ends at the first such tag after it, which is exactly where the lazy regex stops. `find_arg_pairs` replaces every `func_arg_regex.findall`, and `IQuestQ1Detector` derives its `findall` / `sub` results from the same matches.
- Regression test in `TestGlm47MoeDetector` (fails on `main`, passes here).

## Accuracy Tests

- Scanner vs `re.finditer` on the argument regex: identical on 600k random and mutated strings (458k matches).
- Differential test of `main` vs patched detectors (`glm47` and `iquest_q1`), comparing `detect_and_parse` and every streaming result under random re-chunking: **0 mismatches** over 40k random plus 60k mutated well-formed inputs.
- `test/registered/unit/function_call/`: 630 passed.
