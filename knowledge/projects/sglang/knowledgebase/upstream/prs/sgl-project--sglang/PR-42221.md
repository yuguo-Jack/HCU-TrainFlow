# [Fix] [NPU] diffusion: Support MXFP8 attention for MiniMax H3 and relax sequence length constraints

[Upstream PR](https://github.com/sgl-project/sglang/pull/42221) · state: open · merged: False

## Original PR description

<!-- Thank you for your contribution! Please follow these guidelines to enhance your pull request. If anything is unclear, submit your PR and reach out to maintainers for assistance. Join our Slack community at https://slack.sglang.io to discuss further. -->

## Motivation

* Enable MXFP8 Flash Attention for MiniMax H3 on Ascend and remove unnecessary sequence length restrictions that prevent otherwise supported inputs from using MXFP8 attention.

Bugfix:
* MiniMax H3 crashes with NPU MXFP8 because it calls the Diffusion-only ```accepts_mxfp8_input``` method on an SRT quantization method.
* Reference video decoding fails when ```os.memfd_create``` is unavailable in the Python build, since the existing ```OSError``` handler does not catch the resulting ```AttributeError```.


<!-- Describe the purpose and goals of this pull request. -->

## Modifications

* Pass MiniMax H3's quantization configuration to its attention implementation and remove unnecessary sequence length restrictions

* Document MXFP8 Flash Attention requirements, usage, and limitations on Ascend.

Bugfix:
* Check against Diffusion’s ```LinearMethodBase``` before querying the capability, preserving the standard tensor input path for SRT/NPU methods.
* Centralize memfd creation with an API availability check

Removing the sequence-length divisibility check means that more inputs now use MXFP8 attention. However, the MXFP8 path does not support returning softmax LSE.

For example, with a sequence length of 65 and `return_softmax_lse=True`, the previous code fell back to BF16 attention and returned the LSE. With this change, it selects MXFP8 attention instead and raises `NotImplementedError`.

Could we add `not return_softmax_lse` to the MXFP8 condition so these calls continue to use the BF16 path? A test with a non-64-aligned sequence length would help prevent this regression.

- OrangeRedeng · comment · 2026-10-12T14:00:20Z · [source](https://github.com/sgl-project/sglang/pull/42221#discussion_r4248870620)

File: `python/sglang/multimodal_gen/runtime/models/dits/minimax_h3.py` · line 424

`_accepts_mxfp8_input()` now reads `linear.quant_method` before checking whether `linear` is a `LinearBase`. If it receives a regular `nn.Linear`, it will raise `AttributeError`; previously, it simply returned `False`.

The current internal callers appear to pass `LinearBase` instances, so this is a defensive fix rather than a known failure in the MiniMax H3 execution path. Still, it's worth keeping the original type-safety behavior:

```python
def _accepts_mxfp8_input(linear: nn.Module) -> bool:
    if not isinstance(linear, LinearBase):
        return False

    quant_method = linear.quant_method
    return (
        isinstance(quant_method, LinearMethodBase)
        and quant_method.accepts_mxfp8_input(linear)
    )
```
