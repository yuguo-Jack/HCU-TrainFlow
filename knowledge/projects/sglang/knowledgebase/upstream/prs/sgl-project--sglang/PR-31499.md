# [Spec] Extract the shared forward step and introduce EagleWorkerContext

[Upstream PR](https://github.com/sgl-project/sglang/pull/31499) · state: closed · merged: False

## Original PR description

Consolidate the `forward_batch_generation` step of `EAGLEWorkerV2` and `MultiLayerEagleWorkerV2` into one `eagle_worker_common.eagle_forward_generation` function, and introduce `EagleWorkerContext` — a frozen `msgspec.Struct` bundling the stable collaborators (workers, pools, plan stream, device) plus capability flags — so the shared worker-step functions stop threading 12 keyword arguments per call. `run_eagle_verify` shrinks to `(batch, ctx, *, topk, num_steps, num_draft_tokens)`.

## EagleWorkerContext

- A derived, frozen **view** of the worker's state, rebuilt unconditionally at the end of `alloc_memory_pool`; the worker's `self.*` fields stay authoritative. `build()` asserts pools exist (single-shot allocation assumption fails loudly if it ever breaks).
- Values rewritten at runtime by adaptive spec (`topk` / `num_steps` / `num_draft_tokens`) deliberately stay per-call arguments — the ctx holds identity-stable handles only, so backend/graph-runner swaps by adaptive spec remain visible through the handles at call time.
- The two verify switches move in as capability-named flags: `metadata_ready_pre_pad` -> `preplans_verify_metadata`, `finalize_tree_path` -> `compacts_accept_path` (same values per worker, unchanged behavior); a third flag `captures_hidden_states` absorbs the scattered `is_standalone()` capture-mode branches.
- Admission rules (no methods, no subclassing, no callable hooks, flags need a removal path) are in the class docstring.

## Skeleton consolidation (single-layer body is the source of truth)

| Difference | Resolution |
|---|---|
| Draft-side context wrapping (draft-TP + speculative-MoE + stage span) — single-layer wrapped at the call site, multi-layer never wrapped | New `EagleDraftWorkerBase.draft_stage_ctx(stage)` contract method: base default is `nullcontext` (multi-layer behavior kept verbatim), single-layer's draft worker overrides with its real stack. The skeleton wraps `draft` / `_draft_extend_*` calls with it |
| `activate_step_by_batch` (adaptive hook, single-layer only) | Called in the single-layer wrapper before delegating; `BaseSpecWorker` default is a no-op anyway |
| `num_steps == 0` trivial-verify path + `SGLANG_SPEC_SKIP_ZERO_STEP_DRAFT_EXTEND` stub | Stays in `EAGLEWorkerV2._forward_decode_zero_steps` (preserved verbatim); multi-layer can never hit it (`num_draft_tokens == num_steps + 1` invariant) |
| Idle draft-input `topk` (single: `topk`; multi: `topk * num_steps`) | `idle_topk` call-site argument |
| Idle draft-input `vocab_size` (multi-layer never passed it) | Unified: multi-layer now passes it. Only observable under rejection sampling, where the idle `draft_probs` placeholder becomes `[0, vocab]` instead of `[0, 0]` — zero-row either way |
| `_draft_extend_for_prefill` `mm_input_embeds` (multi-layer's signature lacked it) | Multi-layer gains the parameter with `assert mm_input_embeds is None` (it has no multimodal path); call shape unified |

## Verification

- `run_eagle_verify`'s body is byte-unchanged: the retrofit is a signature swap plus a 6-line unpack prologue (`target_worker = ctx.target_worker`, ...), and the two flag reads rename to the ctx fields.
- Old flag names have zero remaining references repo-wide; compile + ruff (F401/F821) clean across `speculative/`; pre-commit black reflow checked AST-equivalent.
- Inheritors audited: `FrozenKVMTPWorkerV2` keeps its own `forward_batch_generation` and inherits the ctx-based `verify` + the `alloc_memory_pool` override (so its ctx is built) with the same flag values it effectively inherited before; `StandaloneWorkerV2` inherits everything and `captures_hidden_states=False` reproduces its NULL capture modes.
- No test patches any touched name (the topk1-fastpath test's patch targets `prepare_for_draft` / `build_tree_kernel_efficient` are untouched).
