# [Fix] attention: Read sliding-window KV at its SWA slots in torch_native

[Upstream PR](https://github.com/sgl-project/sglang/pull/47771) · state: open · merged: False

## Original PR description

## Motivation

With a hybrid SWA KV pool, the torch_native backend writes a sliding-window layer's K/V at SWA-pool ids (`swa_out_cache_loc`), but reads it back with the full-pool ids in `req_to_token`. The SWA sub-pool numbers its slots on its own, so once the two id spaces drift apart the reads gather other tokens' rows, and once a full id passes the SWA pool's size the gather raises `IndexError` and the forward crashes.

intel_amx had the same problem and got `_swa_kv_indices` in #44666, but torch_native wasn't changed. It's the default backend on Apple MPS, arm64 CPU hosts and HPU, and `_hybrid_swa_memory_backend_disable` only drops the SWA pool for aiter, wave and flex_attention, so hybrid-SWA models like Gemma 3 and Gemma 4 hit this there.

## Modifications

- `torch_native_backend.py`: add `_kv_indices`, which for a layer routed to the SWA sub-pool translates this batch's `req_to_token` rows to SWA ids once per forward (the same thing intel_amx does) and returns that table with `arange` row indices. Full-attention and cross-attention layers keep reading `req_to_token` as before. `forward_extend` and `forward_decode` pass its result to the SDPA loops, which don't change.
- New CPU test `test/registered/unit/layers/attention/test_torch_native_swa_pool_reads.py` (base-a-test-cpu). It builds a real `SWAKVPool`, `SWATokenToKVPoolAllocator` and `RunnerIds`, makes the full and SWA ids diverge the way eviction does, runs extend then decode on a sliding-window layer, and checks the output against SDPA over the raw q/k/v with the window mask. One subtest keeps the full ids inside the SWA buffer (wrong rows), the other lets them run past it (`IndexError`). A full-attention layer is checked too.

## Accuracy Tests

On main the new test fails with every element mismatched in the first subtest and `IndexError: index 25 is out of bounds for dimension 0 with size 25` in the second. With this change both pass. Layers that don't live in the SWA sub-pool read exactly what they read before. I haven't run a model end to end on MPS or an arm64 host.

## Speed Tests and Profiling

Only SWA-routed layers on a hybrid pool pay anything: one gather over the batch's rows per forward, shared by every sliding-window layer.
