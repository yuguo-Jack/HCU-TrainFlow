# [Perf] allreduce: enable FlashInfer AllReduce Fusion auto-enable for Kimi-K3

[Upstream PR](https://github.com/sgl-project/sglang/pull/47306) · state: closed · merged: True

## Original PR description

## Motivation

`_flashinfer_allreduce_fusion_auto_enable` arms
`flashinfer_allreduce_fusion_backend="auto"` only for architectures in
`_FLASHINFER_ALLREDUCE_FUSION_ARCHS` (`python/sglang/srt/arg_groups/
overrides.py`). `KimiK25ForConditionalGeneration` is listed;
`KimiK3ForConditionalGeneration` is not (checked at current main, b960aa9),
so Kimi-K3 serves run every TP all-reduce on the stock path even though all
other auto-enable conditions pass on the measured deployment (SM100-family,
TP > 1, no DP attention, `moe_a2a_backend == "none"`; multi-node is allowed
on SM100 by the existing gate).

Measured end-to-end on a 2-node TP8 GB300 NVL (SM103) serve of Kimi-K3
NVFP4, enabling the fusion backend gives **+9.1% mean / +9.7% median p90
per-user interactivity** (normalized output tok/s per user) over a 5-point
concurrency ladder, 4 of 5 points positive, zero request errors everywhere.

Users can already opt in today with
`--flashinfer-allreduce-fusion-backend auto` (the flag sets exactly the
field the auto-enable pass sets; all evidence below was collected through
that route with an otherwise byte-identical serve). This PR only makes the
measured-better configuration the default for this architecture.

## Modifications

One line in `python/sglang/srt/arg_groups/overrides.py`:

```python
_FLASHINFER_ALLREDUCE_FUSION_ARCHS = frozenset(
    {
        ...
        "KimiK25ForConditionalGeneration",
        "KimiK3ForConditionalGeneration",   # <-- added
        ...
    }
)
```

No other behavior changes. FlashInfer strategy-threshold changes and
engine-side completion-mode changes investigated in the same study are
explicitly NOT part of this PR (separate tracks); the enabled arm below runs
stock FlashInfer strategy selection.

## Accuracy Tests

All-reduce fusion swaps the kernel, not the reduction semantics. Request
error rates were zero in every run and output-length distributions matched
between arms, but no pinned accuracy set exists for this serve recipe —
flagged for reviewers rather than waived. (Happy to run a maintainer-
suggested accuracy suite on the same deployment.)

## Speed Tests and Profiling

Serve: Kimi-K3 NVFP4, TP8 (+ decode-context-parallel 8) across 2x GB300 NVL
nodes (4 GPUs each); agentic-coding replay (900 s windows, fixed seed);
metric `e2e_normalized_interactivity_tps` (higher is better). One run per
arm per point, arms of a pair launched back-to-back.

Pooled p90 delta over the six measurements: **+9.1% mean / +9.7% median,
sign 5/1**. The single negative (−4.4% at concurrency 8) sign-flipped to
+10.7% in a full repeat of that pair on different node pairs a day later —
i.e. the c8 point is run-to-run noise, not a stable regression; both pairs
are shown above. An earlier
independent 3-point A/B of the same flag on the same topology measured p50
+0.4% / +1.5% / **+24.2%** at concurrency 8/20/40 with identical record
counts, corroborating the direction.

Noise context measured in the same campaign: a repeated stock baseline on
this 2-node topology reproduced p90 to ±5.4%; an identical-arm control pair
(a TP1 serve where the flag changes nothing) differed by −4.2% p90. The
c1/c20/c40/c60 gains sit at or beyond that band; the single −4.4% point is
inside it and did not reproduce (repeat pair: +10.7%). Concurrency 40/60 run deep in queue saturation (absolute p90
~0.6–1.2 tok/s/user), so their relative deltas carry small absolute
magnitudes; c1 and c20 carry the practical win.

Dispatch verification: per-rank FlashInfer API census — stock arm logs
**zero** `allreduce_fusion` calls; enabled arm logs **264,048** calls across
the 8 TP ranks in the concurrency-8 window alone (equal per rank), with the
serve log attesting `flashinfer_allreduce_fusion_backend='auto'`. MNNVL
workspace rendezvous succeeded across both nodes in every enabled run; on
topologies where MNNVL is unavailable the existing
`_flashinfer_allreduce_unavailable` plumbing falls back to the stock path,
so the default change is safe there.

Scope caveats:
- Measured on GB300 NVL (SM103) 2-node TP8 over the MNNVL fabric only; the
  auto-enable gate already restricts to SM90/SM100-family (multi-node:
  SM100).
- One run per cell, arms on different node pairs (the repeat-band numbers
  above quantify that); more repeats would tighten the c8 point.
- GLM-5.3 (`Glm5NextForConditionalGeneration`) was ALSO tested and is
  deliberately NOT included: its deltas did not reproduce across the ladder
  (one +28.5% p90 cell at concurrency 8, −14.7% at 20, ~0 elsewhere). This
  PR adds only the architecture with reproducible evidence.
