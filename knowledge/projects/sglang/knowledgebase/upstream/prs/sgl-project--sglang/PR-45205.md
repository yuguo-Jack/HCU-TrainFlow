# [Feat] [AMD] hicache: Enable HiCache for DSA DCP with a packed MTP draft

[Upstream PR](https://github.com/sgl-project/sglang/pull/45205) · state: open · merged: False

## Original PR description

## Motivation

[#44322](https://github.com/sgl-project/sglang/pull/44322) enables DCP for the DSA models on ROCm (triton sparse-MLA backend), but DSA DCP still rejects HiCache (`DSA DCP does not support HiSparse or HiCache.`). On agentic workloads with long shared prefixes this matters most at high concurrency: at c48 the working set no longer fits in HBM, prefixes get evicted and re-prefilled, and P90 interactivity collapses (6.05 tok/s/user at c48 vs. 19.56 at c40).

This PR is stacked on #44322 and enables HiCache (L1 device + L2 host) for DSA DCP on ROCm, including the MTP draft.

- **Depends on #44322**: it uses `dsa_draft_shards_under_dcp()` and the DCP-sharded DSA MTP draft from that PR.
- **Result (GLM-5.2-MXFP4, TP4/EP4 + DCP4, MI355X):** at c48, P90 interactivity goes from 6.05 to **19.90** tok/s/user (3.3x) and per-GPU throughput from 18,169 to **31,935** tok/s (+76%). c16 / c24 are unchanged, since the working set already fits in HBM there.

## Modifications

Under DCP each rank keeps 1/`dcp_size` of the latent KV: global slot `p` lives on rank `p % W` at row `p // W`. The host pool already translates transfer indices with this rule (`maybe_dcp_kernel_indices`) and is sized over `logical_size = size * dcp_size`. This PR plugs the DSA pieces into it.

**1. Allow HiCache with DSA DCP on ROCm only** (`model_overrides/deepseek_v2.py`)

- HiSparse stays rejected under DSA DCP.
- HiCache is rejected only when not on HIP (`DSA DCP supports HiCache only on ROCm.`), so CUDA behavior is unchanged.

**2. The MTP draft packs into the target's host rows** (`arg_groups/hicache_hook.py`)

- With #44322 the DSA MTP draft is sharded like the target under DCP (`dcp_replicated=False`, same owner rule). Its host rows therefore follow the same translation as the target's, and the draft layer packs into the target's MLA host pool. No separate draft host pool and no second translation are needed.
- `resolve_hicache_dcp_compatibility` still rejects draft models under HiCache + DCP, except when `_dsa_mtp_packs_into_dcp_host()` holds: non-EAGLE3 EAGLE/MTP and `dsa_draft_shards_under_dcp(hf_config, dcp_size)`.

**3. The DSA indexer host spans the widened slot space** (`pool_host/dsa.py`)

- The device index-K is replicated and spans every DCP rank's slots (`index_buf_size = (size + page) * dcp - page`), so its host mirror must cover the widened transfer indices, untranslated.
- `DSAIndexerPoolHost` is sized as `size = anchor_host.logical_size` and `page_num = anchor_host.page_num * anchor_host.dcp_size`.

**4. Keep the skip-topk index-K elision under HiCache on ROCm DCP** (`kv_cache_configurator.py`)

- `_should_elide_dsa_index_k` used to turn elision off whenever HiCache was on. The DSA indexer host already declares only index-owning layers, so elision is safe here.
- It is now kept when `_is_hip and attn_dcp_size > 1`; every other configuration is unchanged.
- Without this, index-K costs ~28 KB more per token and the device KV pool shrinks by about a third under DCP4.

## Scope

- **No behavior change without DCP, or on CUDA**: every new branch is gated on HIP and `dcp_size > 1`.
- **L1/L2 only**: L3 storage backends stay rejected under DCP (`dcp_rank`-aware storage keys are a follow-up).
- **Same other limits as #44322**: no HiSparse, PD disaggregation, prefill CP or tree drafting; `--speculative-eagle-topk 1`.
- Six files, +247 / -8 (4 source files with +33 / -8; the rest are tests).

## Correctness

MI355X (gfx950), `amd/GLM-5.2-MXFP4`, TP4/EP4 + DCP4, `--kv-cache-dtype fp8_e4m3`, triton DSA prefill/decode, MTP (`EAGLE`, topk 1), `--enable-hierarchical-cache --hicache-write-policy write_through`.

**Unit tests** (`test/registered/unit/mem_cache/test_hicache_dcp_host_pool.py`, 13 pass, CPU only)

- `test_packed_draft_rows_share_the_target_translation`: a packed draft layer's backup uses the same physical rows as the target layers.
- `TestDsaIndexerHostUnderDcp`:
    - `test_sized_over_the_widened_slot_space`
    - `test_backup_pages_widened_indices_untranslated`
    - `test_packed_draft_adds_a_widened_tail_layer`

**End-to-end** (`test/registered/dcp/test_glm52_dcp4_hicache_amd.py`, 9 pass, `stage-c-test-large-4-gpu-amd-mi35x`)

- `TestGLM52MXFP4DCP4MTPHiCache`: GSM8K accuracy, MTP accept length, KL vs. the reference logprobs, and radix-cache prefill / decode asserts at the widened page size (`64 * DCP_SIZE`).
- `TestGLM52MXFP4DCP4MTPHiCacheEvicted`: same checks with `--max-total-tokens 4096 --hicache-size 60`, so the device pool evicts. `test_evicted_prefix_reloads_from_host` sends 8 prompts of 3000 tokens, re-sends the first one, and asserts `cached_tokens_details["host"] > 0`.
- **KL threshold is 0.25**: GLM-5.2 MXFP4 with fp8 KV + MTP already shows KL around 0.09-0.20 on plain TP4, without DCP or HiCache. Control runs with the same harness gave the same range, so HiCache adds no measurable divergence.
- **Agentic runs**: every server start runs a probe (math prompt, expect `29`), and all of them answered correctly.

## Performance

`glm5.2-fp4-mi355x-sglang-agentic-mtp` agentic replay with InferenceX, MI355X TP4/EP4 + DCP4, golden simulated AL 3.61, 3600 s profiling window, `--hicache-size 180`. The baseline is #44322 without HiCache.

| Conc | Config | P90 Interactivity (tok/s/user) | P90 E2E Normalized Interactivity | TPUT per Chip (tok/s/GPU) | P90 TTFT (s) | P90 E2E (s) | CPU Cache Hit Rate |
|---|---|---|---|---|---|---|---|
| 16 | #44322 | 49.22 | 40.46 | 17,976 | 1.175 | 28.14 | — |
| 16 | #44322 + HiCache | 49.88 | 41.93 | 18,198 | 1.054 | 28.45 | 0.01% |
| 24 | #44322 | 36.34 | 30.80 | 25,029 | 1.155 | 46.75 | — |
| 24 | #44322 + HiCache | 37.27 | 31.90 | 24,975 | 1.189 | 47.33 | 0.07% |
| 40 | #44322 | 19.56 | 15.50 | 25,925 | 2.714 | 89.83 | — |
| 40 | #44322 + HiCache | **25.55** | **22.27** | **29,339** | 1.600 | 72.01 | 2.69% |
| 48 | #44322 | 6.05 | 4.75 | 18,169 | 9.936 | 181.77 | — |
| 48 | #44322 + HiCache | **19.90** | **17.52** | **31,935** | 2.155 | 83.39 | 9.23% |

- **c16 / c24**: the working set fits in HBM (CPU hit < 0.1%), and the numbers are within run-to-run noise (≤3%), so HiCache costs nothing when it is not needed.
- **c40**: P90 interactivity +31%, throughput +13%, P90 TTFT 2.71 s → 1.60 s.
- **c48**: P90 interactivity 3.3x, throughput +76%, P90 TTFT 9.94 s → 2.16 s. Without HiCache, evicted prefixes are re-prefilled; with it they reload from host (9.2% of cached tokens).
