# [Feat] [AMD] hicache: Enable HiCache for DSA DCP with a packed MTP draft

[Upstream PR](https://github.com/sgl-project/sglang/pull/45205) · state: open · merged: False

## Original PR description

## Motivation

[#44322](https://github.com/sgl-project/sglang/pull/44322) enables DCP for DSA models on ROCm, but DSA DCP still rejects HiCache. On agentic workloads this hurts at high concurrency: the shared prefixes no longer fit in HBM, get evicted, and have to be prefilled again. At c48, P90 interactivity drops to 3.26 tok/s/user.

This PR enables HiCache (device + host, L1/L2) for DSA DCP on ROCm, including the MTP draft. It is stacked on #44322 and uses its DCP-sharded MTP draft.

**Result** (GLM-5.2-MXFP4, TP4/EP4 + DCP4, MI355X, AgentX):

| Conc | P90 interactivity (tok/s/user) | Throughput (tok/s/GPU) |
|---|---|---|
| 40 | 21.31 → **26.86** (+26%) | 27,087 → **30,712** (+13%) |
| 48 | 3.26 → **21.72** (6.7x) | 13,252 → **34,096** (2.6x) |

c16 and c24 are unchanged, since everything already fits in HBM there.

## Scope

- Only affects ROCm with `dcp_size > 1`; nothing changes on CUDA or without DCP.
- L1/L2 only; L3 storage backends are still rejected under DCP.
- Otherwise the same limits as #44322: no HiSparse, PD disaggregation, prefill CP or tree drafting, and `--speculative-eagle-topk 1` only.

## Correctness

MI355X, `amd/GLM-5.2-MXFP4`, TP4 + DCP4, fp8 KV, MTP (EAGLE), HiCache `write_through`.

**Result: all pass.**

| Test | Result |
| --- | --- |
| CPU unit tests (host pool, draft layout guard, argument gate) | 33 pass |
| Guard on GPU without #44322 | Startup refused as expected |
| E2E `test_glm52_dcp4_hicache_amd.py` (on #44322) | 9 pass, ~10.5 min |

E2E details:
- **Accuracy:** GSM8K 0.94 (normal) / 0.935 (device pool forced to evict), threshold 0.9.
- **Host reload:** after eviction, a re-sent prompt hits the host cache (`cached_tokens_details["host"] > 0`).
- **KL ≤ 0.25:** measured 0.10–0.18, the same range as plain TP4 without DCP or HiCache, so HiCache adds no drift.

On this branch, `dsa_draft_shards_under_dcp` is only called here. The draft pool still uses `loc_space_scale = dcp_size`, so it's `dcp_replicated=True`. On ROCm with DCP, EAGLE and HiCache, this returns True.
