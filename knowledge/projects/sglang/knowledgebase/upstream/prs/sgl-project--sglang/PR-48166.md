# [Perf] [NVIDIA] moe: Add L4 Triton fused MoE configs for Qwen3-30B-A3B

[Upstream PR](https://github.com/sgl-project/sglang/pull/48166) · state: open · merged: False

## Original PR description

## Motivation

There are no fused MoE Triton configs for the NVIDIA L4 (AWS g6) yet, so MoE models on L4 run with the default kernel heuristic (`Using default MoE kernel config. Performance might be sub-optimal!`). This adds tuned configs for Qwen3-30B-A3B, which fits on 2x L4 in FP8 and 4x L4 in bf16.

## Modifications

Two new files in `configs/triton_3_8_0/`:

- `E=128,N=384,device_name=NVIDIA_L4,dtype=fp8_w8a8,block_shape=[128, 128].json`: Qwen3-30B-A3B-FP8 at TP2
- `E=128,N=192,device_name=NVIDIA_L4.json`: Qwen3-30B-A3B (bf16) at TP4

`N` is `768 / tp`. Other models with the same expert shape (e.g. Qwen3-VL-30B-A3B, Qwen3-Coder-30B-A3B) use the same files, but I only measured Qwen3-30B-A3B. FP8 at TP4 isn't valid for this model (192 isn't a multiple of the 128 block), and bf16 TP8 (`N=96`) isn't covered here. There's no `_down` file, so the down projection reuses the up config (the server logs `reusing the tuned up-projection config without TMA`), as #47070 and #46731 do.

Generated with the default search space and batch sizes:

```
python benchmark/kernels/fused_moe_triton/tuning_fused_moe_triton.py --model Qwen/Qwen3-30B-A3B-FP8 --tp-size 2 --dtype fp8_w8a8 --tune
python benchmark/kernels/fused_moe_triton/tuning_fused_moe_triton.py --model Qwen/Qwen3-30B-A3B --tp-size 4 --tune
```

Setup: 4x NVIDIA L4 (g6.12xlarge), torch 2.14.1+cu130, Triton 3.8.0, sglang at 23c6442cde. Tuning and the kernel numbers below ran on driver kernel module 595.91.07; the end-to-end and accuracy runs ran on 595.112.07. Both arms of each comparison ran on the same driver. There is no `NVIDIA_L4` file in any `triton_*` folder today, so the default arm is what L4 users get now.

## Accuracy Tests

GSM8K with sgl-eval 0.1.3, one run per arm:

```
sgl-eval run gsm8k --num-examples 1319 --temperature 0.7 --top-p 0.8 --max-tokens 2048 --seed 42 --chat-template-kwarg enable_thinking=false
```

| | default | tuned |
|---|---|---|
| Qwen3-30B-A3B-FP8, TP2 | 95.22% | 95.30% |
| Qwen3-30B-A3B, TP4 | 94.77% | 94.62% |

That is +1 and -2 questions out of 1319, within the noise of a single sampled run (one standard error is about ±0.6 points).

## Speed Tests and Profiling

**End to end.** Fresh server per run, 3 runs per arm, alternating default and tuned. The default arm points `SGLANG_MOE_CONFIG_DIR` at an empty config tree and the tuned arm at the new files; every server log was checked for the expected config line.

```
python -m sglang.launch_server --model-path Qwen/Qwen3-30B-A3B-FP8 --tp 2 --mem-fraction-static 0.85
python -m sglang.launch_server --model-path Qwen/Qwen3-30B-A3B --tp 4 --mem-fraction-static 0.85
python -m sglang.benchmark.serving --backend sglang --dataset-name random --random-input-len 1024 \
  --random-output-len 256 --random-range-ratio 1.0 --num-prompts 200 --max-concurrency 32 --seed 42
```

Concurrency 32 (medians of 3):

| | output tok/s | median TPOT | median TTFT |
|---|---|---|---|
| FP8 TP2, default | 381.7 | 69.2 ms | 2.77 s |
| FP8 TP2, tuned | **393.7 (+3.2%)** | **66.6 ms** | 2.78 s |
| bf16 TP4, default | 408.0 | 64.0 ms | 2.83 s |
| bf16 TP4, tuned | **420.1 (+3.0%)** | **62.0 ms** | 2.81 s |

At concurrency 32, every tuned run beat every default run on output throughput and TPOT, for both models.

Concurrency 1 (16 prompts, same lengths), median TPOT: FP8 TP2 11.17 → 10.77 ms (-3.6%), bf16 TP4 9.65 → 9.62 ms (no change).

**Kernel.** The tuning script without `--tune`, median of 3 runs per arm, in microseconds. For M=1 and 2 the weights the kernel reads (about 19 and 38 MB) fit in the L4's 48 MB L2, and the script replays the same inputs, so the FP8 1.50x/1.48x at M=1 and 2 overstates the gain (at M=4 the working set leaves L2 and the time jumps to about 290 us in both arms). The concurrency-1 numbers above are the better guide for small batches.
