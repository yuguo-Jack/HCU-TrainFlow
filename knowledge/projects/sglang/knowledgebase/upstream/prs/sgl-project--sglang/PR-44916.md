# [Feat] linker: Add a local DRAM backend for the unified cache direct linker

[Upstream PR](https://github.com/sgl-project/sglang/pull/44916) · state: open · merged: False

## Original PR description

Depends on #44915; only the last commit belongs to this PR.

## Motivation

The unified cache direct linker can only use Mooncake or mori. This adds a `local` backend that keeps pages in this node's pinned DRAM, so a single node can use the linker without an external service, and CI can run linker tests without Mooncake.

## Modifications

- `--unified-cache-external-linker-backend local`, sized by `--hicache-storage-backend-extra-config '{"capacity_gb": N}'`.
- Only the attention-TP source rank stores pages. Peers receive each loaded layer through `LinkerLoadBroadcast` (so the backend needs rank-replicated pools when attention TP > 1). Peers answer `lookup`/`load`/`offload` from the transfers alone; the source's verdicts reach them through the tree's existing MIN reductions.
- `LocalPageIndex`: one slot per page key for all pools, LRU eviction (prefix head outlives its tail), pins taken by `lookup` until the consuming load ends, and by writes until they are published.
- New `UnifiedCacheLinker.release_lookup(rid)` hook (no-op by default), called from `release_request`, so pins of a request that leaves before loading are dropped.
- Copies use the existing `kvcacheio` kernels: one all-layer kernel per pool for offload, one per-layer kernel per buffer for load, with a CUDA event per layer for the layer wait.
- The DSV4 linker KL test now runs for both Mooncake and `local`.
- TODO (not in this PR): spill to local SSD; an SSD hit needs a DRAM prefetch before admission, which the linker contract does not have yet.

## Accuracy Tests

DeepSeek-V4-Flash-FP8 TP4 linker KL test on 4x B300 (threshold 0.01):

| case | local | Mooncake (TCP) |
|---|---|---|
| decode_cache_hit_branching | 0.0051 | 0.0024 |
| logprobs_match | 0.0019 | 0.0008 |
| prefill_cache_hit_branching | 0.0027 | 0.0028 |

Loaded tokens per case: 35840 / 28672 / 45056 on both backends.

Load ordering was checked with an injected-delay probe: destination rows poisoned before the load and each layer's copy delayed by ~10 ms. Without the layer wait `logprobs_match` KL is 3.89; with it 0.0042.

## Tests

- `test_local_page_index.py` (CPU), `test_local_direct_linker.py` (CUDA offload/load round trip and pin behavior), plus a `release_lookup` assertion in `test_unified_cache_linker.py`.
- Each new test fails under a matching mutation (touch order, abort scope, missing `release_lookup`, wrong layer buffer, missing lookup pin, wrong row span).
