# [Feat] [CPU] model: Support LTX and MOVA models on CPU

[Upstream PR](https://github.com/sgl-project/sglang/pull/36632) · state: closed · merged: True

## Original PR description

## Motivation
This PR primarily addresses issues encountered when running the LTX-2.3 and MOVA models in a CPU environment.

CPU execution for the LTX vocoder path was not reliably preserving the expected float32 behavior, and device cache operations were still using backend-specific assumptions. 

Also, CPU execution for the MOVA path was not reliably preserving the expected float32 behavior. 

## Modifications

- Added `temporary_module_fp32_dtype` function in the LTX vocoder and MOVA to temporarily cast the module to float32 during the forward pass.  Added a `temporary_modules_fp32_dtype` function to handle type conversion for multiple modules in MOVA. A cache has been added to the function to reduce overhead associated with type switching during inference.

## Accuracy Tests
No dedicated accuracy benchmark was added for this patch. The change is intended to preserve existing model behavior while fixing CPU compatibility and runtime stability.

```      
if enabled:
            # Special case for CUDA AMP and bfloat16 support
            if self.device == "cuda":
                if torch.cuda.amp.common.amp_definitely_not_available():
                    warnings.warn(
                        "CUDA is not available or torch_xla is imported. Disabling autocast.",
                        stacklevel=2,
                    )
                    enabled = False
                elif (
                    self.fast_dtype == torch.bfloat16
```
