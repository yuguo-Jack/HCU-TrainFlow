# [Perf] [NVIDIA] moe: Add the H200 FP8 per-channel Triton config for Beam-1.0 TP8

[Upstream PR](https://github.com/sgl-project/sglang/pull/47310) · state: closed · merged: False

## Original PR description

## Motivation

On H200, Beam-1.0 FP8 runs its routed experts through the Triton fused MoE kernel with per-channel FP8 weights and per-token FP8 activations. A TP8 rank is E=256, N=320. There is no config for that shape, so every batch size uses the default heuristic.

Follow-up to #45254, which brought the Beam model to main. Beam roadmap: #45370.

## Modifications

Add `triton_3_8_0/E=256,N=320,device_name=NVIDIA_H200,dtype=fp8_w8a8,per_channel_quant=True.json` with 22 entries from M=1 to 8192. It loads through the existing config loader, no code changes. There is no `_down` file, so the down projection reuses the same entry, like the other per-channel files.

Tuning used the path Beam actually runs: `[E, N, 1]` weight scales, `a1_scale`/`a2_scale` None so activations are quantized per token. I did a grid search with uniform routing, then re-timed the top 5 per M with real Beam routing, with every call reading cold experts, and kept the fastest.

## Accuracy Tests

Only tile parameters change. On the Beam shape the tuned and default configs give bitwise identical outputs at M = 8, 64, 128, 512, 1024, 4096 (both use BLOCK_K=128), rechecked on main `acdad27d74`. Both are 1.7-1.8% relative error against a float32 per-token/per-channel reference.

## Speed Tests and Profiling

Kernel level. 1x H200, torch 2.14.1, Triton 3.8.0, main `acdad27d74`. One call = `fused_experts` for one TP8 rank (per-token quant, both GEMMs, combine). Each CUDA graph holds 10 calls with different routing, so experts come from HBM (1.26 GB of expert weights). 40 replays per point, default and tuned alternate over 3 rounds, median. Run-to-run spread is under 3.5%, and the two configs' ranges don't overlap at any point.

Routing comes from prefill steps recorded with the real Beam-1.0-FP8 weights (MoE layers 3-5, code prompts below; wikitext prompts are within 2.9 points). decode = one token sampled from each of M different prompts, verify = 8 consecutive tokens from each of M/8 prompts (DFlash2 block 8), prefill = one 2048-8192 token step.

Bound = bytes of the experts touched in that call (FP8 weights and scales) plus the BF16 input and output, / 4.8 TB/s. At M=8192 it's FP8 FLOPs / 1979 TFLOPS instead.

With uniform routing the numbers are about the same (-16% to -29% for M up to 1536, -3% to -9% above).

End to end on one H200: a dummy-weight server with one TP8 rank's shapes (6 Q heads, 1 KV head, expert width 320, dense FFN 2560), all 52 layers and all 256 experts, FP8 config from the Beam-1.0-FP8 checkpoint, default attention backend, decode CUDA graph. Routing uses `SGLANG_SIMULATE_UNIFORM_EXPERTS=1`, since dummy router logits are nearly tied. The default arm points `SGLANG_MOE_CONFIG_DIR` at a config tree without this file. Arms alternate twice in one container. Decode step in ms (512-token prompts, 160 greedy tokens), median of 14 log windows of 10 steps:

| batch | default (2 runs) | tuned (2 runs) | change |
|---|---|---|---|
| 1 | 5.98 / 5.98 | 5.66 / 5.65 | -5.5% |
| 8 | 9.82 / 9.79 | 8.53 / 8.53 | -13.0% |
| 32 | 18.08 / 18.09 | 15.79 / 15.78 | -12.7% |
| 64 | 22.70 / 22.72 | 19.60 / 19.61 | -13.7% |
| 128 | 25.47 / 25.48 | 22.17 / 22.18 | -12.9% |

Per MoE layer that saves 26 us at batch 8, 47 us at 32 and 67 us at 128, about what the kernel table gives with uniform routing (30, 50 and 68 us). So the gap between the two tables is just MoE's share of the step. This proxy has no TP all-reduce, so on a real TP8 step the relative gain is smaller.

Prefill: in a torch profile of one 2048-token prefill, the fused MoE GEMMs over the 49 MoE layers go from 26.6 to 24.4 ms and GPU busy time from 42.2 to 40.0 ms. The request itself takes about 77-81 ms at both 2048 and 4096 tokens in this eager one-GPU proxy, so it is host-bound, and its wall time doesn't resolve the change: the arms land 1-4 ms apart, tuned slower at 2048 and 4096 and faster at 8192.
