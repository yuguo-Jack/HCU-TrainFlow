# [Fix] [NPU] tests: Align Moonlight GSM8K cases with the sgl_eval harness

## Motivation

The Moonlight-16B-A3B accuracy cases were migrated onto `NPUGSM8KMixin`, whose default GSM8K backend grades through the OpenAI completion API with 5-shot prompting. Moonlight-16B-A3B-Instruct scores only ~0.72 on that harness, while the 0.83 threshold was taken from the `evalscope` chat-template baseline (~0.837). As a result the nightly GSM8K runs fail deterministically (`nightly-2-npu-a3`: 0.7291, `nightly-4-npu-a3`: 0.7245) even though the model output is fine.

## Modifications

- `test_npu_mla_fia_hicache_bf16.py` and `TestDPAttentionMixedChunk` in `test_npu_dp_attention.py`: set `gsm8k_backend = "sgl_eval"` and `gsm8k_max_tokens = 4096` so these cases grade with the chat template, matching the harness the 0.83 baseline was measured with. The PR smoke path and the 3-attempt retry logic still come from the mixin and are unchanged.
- `npu_eval_accuracy_kit.py`: key `_is_pr_pipeline` on `GITHUB_WORKFLOW_REF` instead of `GITHUB_EVENT_NAME`. `nightly-test-npu.yml` is itself triggered by `pull_request` through path filters, so the old check misclassified the nightly pipeline as the PR pipeline and silently downgraded the accuracy runs to the smoke request. An empty ref (local runs) is treated as non-PR so local behavior is unchanged.
- `test_npu_mla_fia_hicache_bf16.py` now imports `_is_pr_pipeline` from the mixin instead of duplicating the definition, matching the other NPU cases.
- `nightly-test-npu.yml`: gate every job except `nightly-2-npu-a3` and `nightly-4-npu-a3` on `github.event_name != 'pull_request'`, so a PR-triggered nightly run only exercises the two GSM8K suites instead of occupying every NPU runner. Scheduled, dispatched and reusable-workflow runs are unaffected.

## Accuracy Tests

Nightly GSM8K on Moonlight-16B-A3B, full 1319-question set:

| Harness | Accuracy | Threshold | Result |
|---|---|---|---|
| `run_eval` (completion, 5-shot) | 0.7291 / 0.7245 | 0.8217 | fail |
| `evalscope` (chat template), acc-2 suite | 0.853 | 0.8286 | pass |
| `sgl_eval` (chat template), this PR | pending nightly run | 0.8217 | - |

The 0.83 threshold is carried over as a starting point and annotated with a TODO; it will be re-calibrated from the first `sgl_eval` nightly result.
