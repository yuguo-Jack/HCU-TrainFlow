## Motivation

The ROCm 10.1 SDK ships `triton 3.8.0+git669b31ac.rocm10.1.0` (ROCm/triton `669b31ac`, `release/internal/3.8.x`). 
On gfx1250, with `TRITON_HIP_USE_EXPERT_SCHEDULING` at its default (`is_expert_scheduling_enabled()` returns true for gfx1250):
- kills gpt-oss-120b-w-mxfp4-a-fp8 under load -- single requests answer, then a memory
  access fault in `_moe_gemm_a8w4_decode` 4 requests into a 600-request run

None of this is there with the Triton the rocm10 image builds (triton-lang/triton `76940ad3`, from main)
But `76940ad3` is past triton-lang/triton#10833 (`9debefe44`, merged 2026-07-15), which removed block pointers, and sglang's FLA kernels still call `tl.make_block_ptr`. So this builds `76940ad3` and reverts `9debefe44` on top.
