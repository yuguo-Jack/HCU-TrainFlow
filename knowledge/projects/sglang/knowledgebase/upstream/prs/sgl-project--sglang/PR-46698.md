# [Perf] mem_cache: Avoid full free-hole sort and extent rebuild in UnifiedHostPageEnvelope

[Upstream PR](https://github.com/sgl-project/sglang/pull/46698) · state: open · merged: False

## Original PR description

## Motivation

In `_SharedPageEnvelopeHostBacking` (`python/sglang/srt/mem_cache/pool_host/unified.py`), three hot-path operations during host KV page allocation and deallocation perform unnecessary full-collection work:

1. **`_take_physical_pages(side, page_count)`**:
   - Even when `page_count == 0` (when all required physical pages were already mapped to the requested logical pages), it still constructed and sorted `reusable = sorted(p for p in side.free_physical_pages if ...)` before slicing `reusable[:0]`.
   - When `page_count` is much smaller than the number of reusable interior holes in `side.free_physical_pages`, sorting the entire filtered hole list costs $O(H \log H)$ instead of selecting only the `page_count` nearest pages via `heapq.nsmallest` / `heapq.nlargest`.
2. **`_reserve_logical_pages(extents, page_count)`**:
   - Iterated through every remaining `(start, end)` tuple in `extents` even after `needed == 0`, copying all unvisited extents into a new list and re-running `_merge_extents` (which sorts and merges the entire extent list). Because `extents` is already maintained in sorted, coalesced order and reservation only consumes a prefix of extents (plus at most one truncated extent), we can stop immediately once `needed == 0` and update only the consumed prefix via slice assignment.
3. **`free(side_name, indices)`**:
   - Re-sorted the combined `side.free_logical_extents + freed_extents` list on every `free()` call (`O((E + F) log(E + F))`), even though `side.free_logical_extents` is already sorted and `freed_extents` is constructed in sorted order from `sorted(logical_pages)`. Merging the two sorted runs with `heapq.merge` coalesces them in linear $O(E + F)$ time.

## Modifications

- Short-circuit `_take_physical_pages` when `page_count <= 0` and use `heapq.nsmallest` / `heapq.nlargest` when selecting a subset of reusable physical pages (`page_count * 4 < len(reusable)`).
- Break out of `_reserve_logical_pages` as soon as `needed == 0` and replace only the consumed prefix `extents[:consumed]` in place.
- Add `_merge_sorted_extents` and use `heapq.merge(side.free_logical_extents, freed_extents)` in `free()` to coalesce sorted extent runs in linear time without re-sorting.
- Add unit tests in `test/registered/unit/mem_cache/test_hicache_storage_format_tag.py` covering prefix extent reservation, zero-page and partial-hole physical page selection (`up` and `down` growth directions), and sorted extent merging on `free()`.
