# [Fix] [AMD] grok: accept allow_patterns_overrides in presharded _prepare_weights patch

[Upstream PR](https://github.com/sgl-project/sglang/pull/45217) · state: closed · merged: True

## Original PR description

## What

`_prepare_presharded_weights` in `grok.py` now accepts the `allow_patterns_overrides` argument that `DefaultModelLoader._prepare_weights` gained in #33572.

## Why

`Grok1ForCausalLM.__init__` replaces `DefaultModelLoader._prepare_weights` with `_prepare_presharded_weights` when `tp_size > 1`. Since #33572, `_get_weights_iterator` and the resolve-sources path call `_prepare_weights` with four positional arguments, but the Grok replacement only takes three, so every Grok launch with TP > 1 dies during weight loading:

```
TypeError: _prepare_presharded_weights() takes 4 positional arguments but 5 were given
```

In the latest AMD nightly, all 12 Grok jobs (grok1-int4 and grok2, MI300 and MI35x, all ROCm versions) fail this way: https://github.com/sgl-project/sglang/actions/runs/39150288819/job/117742354680

## Notes for the reviewer

When an override is passed, the patch hands off to the original `_prepare_weights` instead of applying the per-rank shard patterns, because the override means "load exactly these patterns". Grok itself never sets an override, so its loading path is unchanged; this only matters if some other model is loaded in the same process after the class-level patch.

## Test plan

- Checked that the new signature binds both call shapes used in `loader.py` (four positional args, and `download_model`'s `fall_back_to_pt=` keyword).
- Dispatched the four Grok nightly jobs on this commit (rocm10): https://github.com/sgl-project/sglang/actions/runs/39304489973. All four load weights and serve; no `TypeError`.

  | Job | GSM8K acc (threshold) |

  | MI35x grok1-int4 | 0.840 (0.8) |
  | MI300 grok1-int4 | 0.810 (0.8) |
