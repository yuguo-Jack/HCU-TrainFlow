# Fix issue #46461: HunyuanImage-3 shared MLP execution order

[Upstream PR](https://github.com/sgl-project/sglang/pull/46492) · state: open · merged: False

## Original PR description

## Summary

Fix HunyuanImage-3 generating garbled/incorrect images due to shared MLP reading corrupted hidden states in `HunYuanSparseMoeBlock.forward()`.

## Root Cause

In `HunYuanSparseMoeBlock.forward()`, the shared MLP was executed **after** `self.experts()`. On CUDA, `FusedMoE` runs in-place by default (`inplace=True`) and overwrites `hidden_states` with the expert output. This meant the shared MLP was reading the already-overwritten tensor (expert output) instead of the original input, producing incorrect results and causing the model to generate garbled images.

## Fix

Reorder the execution in `HunYuanSparseMoeBlock.forward()`:
1. Run `self.shared_mlp(hidden_states)` **before** `self.experts()` so it reads the original input
2. Then run `self.experts(hidden_states, topk_output)` which overwrites hidden_states in-place
3. Add the shared MLP output to the expert output

**File changed:** `python/sglang/multimodal_gen/runtime/models/dits/hunyuan_image3.py`

## Testing

- Verified HunyuanImage-3 produces correct images after the fix.
- Non-CUDA backends (where FusedMoE does not run in-place) are unaffected by this change since the reordering is semantically correct regardless.

Closes #46461
