# [DSv4.1] Capture the full-width layers of eager prefill steps in CUDA graphs under decoder SWA bounded replay

[Upstream PR](https://github.com/sgl-project/sglang/pull/43535) · state: open · merged: False

## Original PR description

## Motivation

**Stacked on #43534**; review that one first. This PR adds one commit range on top of it.

With the late layers replayed from graphs (#43534), layers 0–20 of an eager prefill step still run at full width with one launch per kernel, so cold prefill is still paced by the host. Repro: the same launch and `prefill_repro.py` as in #43534.

## Modifications

- `EagerReplayGraphs` generalizes the bank to a layer range. Two ranges use it:
  - the full-width layers before the last KV-source layer, keyed by the step's token count in 256-token buckets;
  - the trimmed late layers, keyed by tail rows, as before.
- **Startup capture:** every bucket of both ranges is captured once the prefill and decode graphs are captured, after one full-chunk dummy eager forward has grown every row-sized workspace. A step without a captured bucket runs eagerly; with speculative decoding nothing is captured.
- **Replay pointer guard:** before each replay, the buffers its kernels read by address (owned static inputs, the request-window workspace, FlashInfer workspaces) are checked against the capture. A moved buffer raises instead of reading stale memory.
- The graphs capture on the shared capture stream into the global graph pool (`SGLANG_DSV4_EAGER_GRAPH_GLOBAL_POOL=1`, default), because they never run at the same time as the prefill graphs.
- Fewer host operations in the eager breaks: one break per late layer for the SWA store and the attention; no pad-row zeroing (no real row reads a pad row); the attention break calls the attention body directly; the DeepGEMM prefill indexer builds a step's row plumbing once and shares it across that step's index layers; the fused K store keeps one RoPE view per layer. The last two also apply to eager steps with the flag off; `SGLANG_DSV4_EAGER_GRAPH_LEAN_BREAKS=0` disables them.
- The request-window history check runs inside these eager breaks as it does in an eager forward.
- **On by default under the decoder flag:** `SGLANG_DSV4_FULL_LAYER_GRAPH_MAX_TOKENS=-1` = the chunked prefill size, at most 8,192 (32 graphs); `0` turns the full-layer graphs off.
- Unit tests: startup plan, pointer guard, run and capture with static buffers, and the step-rows cache never crossing steps.

**Memory (per GPU, defaults, `--mem-fraction-static 0.8`):** free memory after startup capture drops from 49.8 to 23.3 GiB, of which 15.0 GiB is logged as graph memory; the largest bucket is the biggest share. KV capacity is unchanged, because the KV pool is sized before capture. Startup capture takes about 19 s. `SGLANG_DSV4_FULL_LAYER_GRAPH_MAX_TOKENS=4096` captures half the buckets and saves about half of that memory; hit steps up to 4K new tokens still replay, and 8K cold chunks run layers 0–20 eagerly.
