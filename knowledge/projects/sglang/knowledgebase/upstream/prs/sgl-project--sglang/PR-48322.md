# [Feat] [Intel] diffusion: DeepSymm IPC ring attention on XPU

[Upstream PR](https://github.com/sgl-project/sglang/pull/48322) · state: open · merged: False

## Original PR description

## Motivation

On Intel XPU (CRI), diffusion ring attention (`--ring-degree N`) runs torch's templated ring over BF16 flash attention. It is slow, and under `torch.compile` it hangs. DeepSymm (`applications.ai.gpu.deepsymm`) has an IPC ring for CRI. It moves K/V over the copy engine, overlaps the transfer with compute, and runs attention in bf16, fp8, fp8_mixed or mxfp4.

## Modifications

- New `backends/xpu_deepsymm_ring.py`: loads `deep_symm.ring_attn` and checks which layers the kernel supports: non-causal self-attention, head size 64/128, default softmax scale. MX/FP8 precisions need MHA with head size 128. Layers that only satisfy the base checks run at bf16, and the others keep the torch ring.
- `USPAttention` ring branch: routes to DeepSymm when `SGLANG_DIFFUSION_XPU_DEEPSYMM_RING_PRECISION` is set to `bf16` / `fp8` / `fp8_mixed` / `mxfp4`. The default `off` keeps current behaviour. The check runs only for XPU tensors, so other platforms see no change and no graph break.
- `destroy_model_parallel` releases the ring's IPC cache.
- Unit test: per-layer precision rules, plus a 2-rank ring vs full attention for every precision.

## Accuracy Tests

The 2-rank ring vs an fp32 full-sequence reference (rel L2): bf16 0.0026, fp8 0.054, fp8_mixed 0.172, mxfp4 0.288.

Wan2.2-T2V-A14B 1280x720x81 with `mxfp4` on every block: the video keeps the scene and motion, but shows a fine-grained (grainy) high-frequency texture. With `bf16` it is clean. Keeping a few sensitive blocks (0, 33, 34, 38) at bf16 gives a clean video at near-mxfp4 speed. That needs a per-block override, which #48059's BF16 block list provides for the Sage V3 path, so this PR does not include one.

## Speed Tests and Profiling

Wan2.2-T2V-A14B 1280x720x81, 40 steps, 2 Intel CRI cards at 2500 MHz, cache off, DeepSymm `8cf4100`.

| Setup | End to end |
|---|---|
| This PR, compiled, `mxfp4` | 498.4 s |
| This PR, compiled, `bf16` | 1755.8 s |
| With #48059 and #48060 (MXFP8 GEMMs), eager, torch ring | 902.9 s |
| With #48059 and #48060 (MXFP8 GEMMs), eager, DeepSymm `mxfp4` | 507.6 s |
