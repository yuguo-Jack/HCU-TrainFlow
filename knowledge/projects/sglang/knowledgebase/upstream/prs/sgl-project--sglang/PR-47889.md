# [Perf] cosmos3: optimize Sim-Bimanual kv cache management

[Upstream PR](https://github.com/sgl-project/sglang/pull/47889) · state: open · merged: False

## Original PR description

Motivation

Cosmos3 Nano Sim-Bimanual repeatedly concatenates text, history, and current KV during inference, and rebuilds history after each clean-frame commit. This adds memory traffic, allocation overhead, and temporary KV copies, especially with full history.

Related issue: https://github.com/sgl-project/sglang/issues/48144

## Modifications

- Reuse request-local, per-layer `[text | history | current]` KV buffers across denoising steps. Only clean frames commit history.
- Preallocate full-history capacity for each request and reject requests exceeding the configured history limit.
- Preserve sliding-window sink/recent retention using one scratch buffer sized for a single layer's recent-window K/V (**48.125 MiB total** in this benchmark), reused across all 36 layers. Full history requires no scratch storage. Overlap compaction with subsequent computation through per-layer CUDA events, with stream cleanup on normal and exceptional exits.

## Accuracy Tests

- Both full and sliding modes produce **bit-identical BF16 latents and all 901 decoded RGB frames** compared with the original KV implementation.
- Targeted unit suites: **217 tests and 116 subtests passed**. Coverage includes history retention, clean/noisy KV separation, request isolation, stream ordering, and exception cleanup.
- Pre-commit checks passed.

## Speed Tests and Profiling

Tested on one **RTX PRO 6000 Blackwell Server Edition**, Intel Xeon Gold 6444Y, PyTorch 2.13.0+cu130.

Official `mixed028` input: **640×352, 901 frames, 30 FPS**, BF16, four-step sampler, guidance 1, seed 2026. Offload, compilation, and CUDA Graph were disabled. **NVENC was enabled for both baseline and optimized runs.**

Each variant used a fresh process, one complete warmup with different image/actions/prompt, then one measured target request with no conditioning-cache hits. End-to-end time includes MP4 encoding and saving.

History | Baseline E2E (s) | Optimized E2E (s) | Speedup | Baseline allocated peak (GiB) | Optimized allocated peak (GiB) | Allocated memory saved |
|---|---:|---:|---:|---:|---:|---:|
| Full | 52.266 | 42.886 | **1.219×** | 43.346 | 37.631 | **5.715 GiB (13.18%)** |
| Sliding | 39.785 | 36.471 | **1.091×** | 33.460 | 32.694 | **0.766 GiB (2.29%)** |
| Frustum | 44.154 | 37.186 | **1.187×** | 44.397 | 40.029 | **4.368 GiB (9.84%)** |

Full uses `history_max_frames=901`; sliding uses a 64-frame window with 8 sinks. Memory statistics were reset after warmup and report peak PyTorch allocated memory, excluding unused allocator cache.
