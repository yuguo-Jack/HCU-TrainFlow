# [Refactor] sparse-mla: Expose arithmetic and DSA metadata hooks

[Upstream PR](https://github.com/sgl-project/sglang/pull/44503) · state: open · merged: False

## Original PR description

## Motivation

Expose four narrow extension points so subclasses can change the arithmetic while retaining the SRT forward lifecycle.

## Modifications

- `run_mla_indexer` wraps the existing indexer call in both normal and stream-overlap preparation paths. Shared-index layers keep their existing reuse behavior.
- `prepare_mla_qkv` receives the absorbed query and normalized KV on the unfused rotary path. Its default calls the existing rotary embedding and returns Q/KV unchanged otherwise. Overriding this hook disables deferred BMM-attention fusion and born-FP8 query packing (including early query/indexer overlap), so the hook receives a materialized query and its result reaches attention. The default implementation retains these fast paths. Fused rotary paths retain their existing behavior.
- `project_mla_values` contains the existing value-projection branches. LoRA correction, attention output gating, output projection, and top-k carry remain in `forward_absorb_core`.
- `DeepseekSparseAttnBackend.init_kernel_metadata` is a no-op by default and runs after eager or out-of-graph metadata refresh, including every child of multi-step replay. Looped, sibling-copy, fused-copy, and fallback replay paths share one hook-dispatch point outside the copy fallback handler, so custom metadata errors propagate.

No new server options or kernel implementations are required.

## Accuracy Tests

48 CPU tests and 20 subtests pass: the two new hook test files plus the existing MLA-dispatch and DSA-padding tests. The new coverage checks:

- Hook dispatch for prefill, decode, and target verification, including shared-index reuse and propagation of overridden Q/KV tensors into KV preparation.
- Bitwise default value-projection results for ordinary BMM, the piecewise-graph BMM branch, and the CPU FP8 branch.
- Value-projection overrides followed by LoRA correction, output gating, output projection, and index carry in the existing order.
- Metadata refresh before the custom hook, including reordered requests, repeated graph setup, empty graph batches, and all multi-step replay copy paths. Hook errors propagate.
- Materialized queries for custom preparation on the graph-split surface and with born-FP8 enabled, while default preparation retains BMM fusion and born-FP8 eligibility. Seven born-FP8 regression cases fail before the fix (`99490da636`) and pass afterward. Six query-arithmetic checks and four multi-step replay checks fail on the original PR revision (`8a6b5e95e5`) and pass with these changes.

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Materialize the absorbed query before invoking its hook**

When `_can_fuse_bmm_into_attention()` is true on the default DSA graph-split surface, `q_nope_out` here is only the `new_empty` view created by `_make_mla_bmm_fusion_plan`; the absorbed BMM does not run until `forward_absorb_core`. An override that performs the advertised arithmetic on `q` therefore reads uninitialized memory, while an in-place transformation is overwritten by the later BMM, producing incorrect attention. Disable this fusion when the preparation hook is overridden or materialize the BMM before invoking the hook.
