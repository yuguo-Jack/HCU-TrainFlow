# [Bug] eagle: broadcast finalized verify decision across TP ranks (#31071)

[Upstream PR](https://github.com/sgl-project/sglang/pull/31478) · state: closed · merged: False

## Original PR description

## Motivation

Fixes #31071.

In EAGLE / spec-v2 verify (`eagle_sample` in `python/sglang/srt/speculative/eagle_utils.py`), the **greedy** branch computed the accepted-token set from a **per-rank local `torch.argmax(next_token_logits)`** and did **not** broadcast the result across tensor-parallel ranks. Only the **sampling** branch broadcast `predict` / `accept_index` / `num_correct_drafts` from rank 0.

When per-rank `next_token_logits` differ from a non-deterministic all-reduce (e.g. AMD `--enable-aiter-allreduce-fusion`) and a logit is **near-tied**, `argmax` picks a **different token per rank** → ranks **accept a different number of drafts** → committed `seq_lens` / batch shapes diverge → **the next TP collective deadlocks**. Both scheduler ranks wedge in `resolve_seq_lens_cpu → Event.synchronize`, `num_running_reqs` freezes, gen tok/s → 0, and `/health` still returns 200 until the scheduler watchdog kills the process.

Observed in production on **sglang v0.5.12.post1** (ROCm 7.2, MI350X/gfx950), **tp=2**, EAGLE (`--speculative-num-steps 3`, `--speculative-eagle-topk 1`), `--attention-backend triton`, `--enable-aiter-allreduce-fusion`. The greedy-branch condition also includes `_is_hip` / `_is_cpu` / `_is_npu` / `_is_xpu`, so those backends always took the no-broadcast path. Likely the same root cause as #24440 (EAGLE accuracy on AMD), which surfaces the divergence as wrong output rather than a hang.

## Modifications

Per review feedback on #31071 (thanks @Allyyi), instead of duplicating the broadcast into the greedy branch, the rank-0 broadcast is **hoisted to a single location after the accept decision is finalized** and before the worker consumes it:

- Removed the sampling-branch-only broadcast.
- Added one broadcast of `predict` / `accept_index` / `num_correct_drafts` just before `return`. It is placed **after** the `SIMULATE_ACC_LEN` block on purpose — that block re-derives `target_predict` from per-rank `argmax`, so broadcasting earlier would reintroduce divergence. This makes the greedy path, the sampling path, and simulation TP-consistent by construction.

## Accuracy Tests

- Mechanism isolation (deterministic, from #31071): on a `tp>1` EAGLE deployment, forcing one rank's post-argmax `target_predict` to differ for a single verify step reproduces the hang on `main` (both ranks wedged in `resolve_seq_lens_cpu → Event.synchronize`). Adding the unified broadcast eliminates the divergence and the hang.
- The maintainer noted AMD GPUs were hard to rent for repro; the added CPU unit test below is the CI-runnable guard for the regression.

## Speed Tests and Profiling

No hot-path change: the broadcast already existed on the sampling path and is only relocated. The greedy path adds three small rank-0 broadcasts of the already-tiny `predict` / `accept_index` / `num_correct_drafts` tensors, gated on `world_size > 1`, once per verify step. Single-GPU is unaffected.

## Code Review

This pull request addresses a potential deadlock in EAGLE speculative decoding by ensuring that verify decisions are consistently broadcast across TP ranks, even in the greedy path. Previously, the greedy path lacked this synchronization, which could lead to divergent states when per-rank logits differed due to non-deterministic reductions. A regression test has been added to verify this behavior. The review feedback suggests improving the test coverage by parameterizing the test cases to also validate the `is_dp_attention_enabled=True` scenario, ensuring the correct tensor parallel group is utilized.

```python

        mock_parallel_state = MagicMock()
        mock_parallel_state.attn_tp_group = tp_group

             patch("sglang.srt.distributed.get_tp_group", return_value=tp_group), \

                "sglang.srt.layers.dp_attention.is_dp_attention_enabled",
```
