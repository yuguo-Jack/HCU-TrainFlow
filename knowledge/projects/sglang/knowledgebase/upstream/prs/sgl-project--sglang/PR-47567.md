# [Perf] [ROCM] diffusion: Pipeline MiniMax-H3's Ulysses exchange over head groups on RCCL

[Upstream PR](https://github.com/sgl-project/sglang/pull/47567) · state: closed · merged: True

## Original PR description

## Motivation

Without the copy-engine transport (ROCm), each H3 layer packs q/k/v, waits on the input all-to-all, attends, then waits on the output all-to-all: ~2.5 ms of exposed RCCL per layer at 1280x704 on 4xMI355X (14.5% of a denoise step).

## Modifications

- Split the local heads into two groups: queue both input exchanges up front on the collective stream, and send group g's output while group g+1 attends. aiter attends a head group with the same bytes as inside the full call (verified), so the output is bit-identical.
- Two groups was the best choice: 7 groups, 14 groups and unequal splits ([4,10], [2,10,2]) are all slower because attention gets a partial extra wave per call.
- Test added to `test_usp_pipelined_attention_multi_gpu.py`.

## Accuracy Tests

Bit-identical output: 22/22 MP4 md5s equal to main in the final run.

## Speed Tests and Profiling

Setup for all numbers below: 4x MI355X, MiniMax-H3 T2VA, 1280x704 (SemiAnalysis "720p"), 124 frames, 49 forwards, Ulysses 4 + aiter, single stream. Each arm is a fresh server (1 warmup + 3 timed requests), ABAB across two rounds, base = main `75a5da7f`.

720p median -3.24 s (the largest single item). Per step, ~63 ms of RCCL is now hidden behind attention; 849.5 -> 738 ms/step together with the QK norm change.

Note: this touches the same H3 pipelined-Ulysses block in `minimax_h3.py` as the CUDA-side PR that skips the packing's alignment rows; whichever lands second needs a small rebase.
