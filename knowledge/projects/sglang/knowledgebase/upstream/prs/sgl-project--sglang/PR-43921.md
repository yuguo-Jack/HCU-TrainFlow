# [DSv4.1] Reduce sparse-prefill workspace padding

[Upstream PR](https://github.com/sgl-project/sglang/pull/43921) · state: closed · merged: True

## Original PR description

[codex/claude generated]

## Motivation

Sparse-prefill history gathering reserves `num_reqs * max_seq_len // ratio` rows, so short requests in a mixed-length batch pay for the longest history. Each gathered BF16 KV row costs 1 KiB. This can consume several GiB even when the batch extends only a small number of tokens.

## Modifications

- Pack ratio-1/2/4 histories using each request's compressed length and cumulative workspace offsets.
- Rebase the existing top-k and SWA indices to the packed layout.
- Supply host sequence lengths from both backend builders to avoid device synchronization when sizing the gather.
- Add metadata regression coverage and standalone CUDA attention/allocation tests.

Ratio-128 gathering, workspace retention, and indexer logits tiling are unchanged. Equal-length batches have no padding to remove; this does not claim to resolve all production OOMs.

## Accuracy Tests

Local GB300 validation: 12 cases across ratios 1/2/4 compare gathered KV values and FlashMLA outputs against the original rectangular layout. Outputs match bit-for-bit, including mixed/equal lengths, zero-query requests, empty compressed histories, SWA, and sentinel indices.

Standalone CUDA tests: 3 passed. Sparse-prefill metadata tests: 7 passed, 18 subtests passed. No full-model traffic replay or AMD execution validation.

## Speed Tests and Profiling

Workspace allocation measurements (not throughput benchmarks):

| Sequence lengths | Before | After |
| --- | ---: | ---: |
| 44,198 / 577,152 / 95,723 / 51,427 / 6,144, plus 16,751 SWA rows | 2.768 GiB | 0.755 GiB |
| Fourteen equal 820,552-token histories, plus 2,786 SWA rows | 10.958 GiB | 10.958 GiB |

Under a 2 GiB allocator limit in an isolated test process, the original mixed-batch workspace allocation raises OOM while the packed gather and workspace succeed. This is a controlled allocation test, not a reproduction of a production incident. Throughput has not been benchmarked.
