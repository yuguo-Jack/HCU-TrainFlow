# [Fix] [XPU] rope: Fall back to native RoPE for head sizes the XPU kernel lacks

[Upstream PR](https://github.com/sgl-project/sglang/pull/46997) · state: open · merged: False

## Original PR description

## Motivation

`RotaryEmbedding.forward_xpu` sends every full-rotary head size that has no fused path to `sgl_kernel.rotary_embedding`. That kernel only accepts head sizes 32, 64, 96, 128 and 256 and raises a `RuntimeError` on anything else.

The EAGLE3 draft for Qwen3-32B (`AngelSlim/Qwen3-32B_eagle3`) has head_dim 80. Serving Qwen3-32B with that draft on XPU therefore crashes the server on the first draft forward.

## Modifications

- `layers/rotary_embedding/base.py`:
  - New `_XPU_ROTARY_EMBEDDING_HEAD_SIZES`, the head sizes `sgl_kernel.rotary_embedding` accepts.
  - `forward_xpu` sends any other full-rotary head size to `forward_native`, as it already does for partial rotary.
- Supported head sizes still take the kernel, so existing models are unaffected.
- New `test/registered/xpu/test_rope_xpu.py`: it checks head size 80 (neox and non-neox) against `forward_native`. Without this fix it fails with the kernel's `RuntimeError`; with it, it passes.

## Accuracy Tests

- `test_rope_xpu.py` passes on Arc Pro B70 with sgl-kernel-xpu 0.4.0 and 0.5.0. The head sizes the kernel supports did not change between those versions.
- No behavior change for supported head sizes.

## Speed Tests and Profiling

Not a performance change: supported head sizes keep the kernel path. Only unsupported head sizes, which used to crash, take the native path. For the Qwen3-32B EAGLE3 draft that is a single layer.

The draft's attention needs a separate fix (#46998). With both, Qwen3-32B + EAGLE3 on 4x B70 reaches 42.4 tok/s at c=1, against 31.5 tok/s without speculative decoding. That run used greedy ShareGPT prompts and 3 draft steps with topk 1.
