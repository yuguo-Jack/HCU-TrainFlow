# [Fix] deepseek-v4.1: Reject encoder replay on a chunk too small for a hit or on other models

[Upstream PR](https://github.com/sgl-project/sglang/pull/45051) · state: closed · merged: True

## Original PR description

- With encoder SWA replay, a prefix hit's first chunk also runs up to 128 replay rows, and its extend is floored to whole pages. A per-rank chunk below `128 + page_size` (256-383 tokens with the 256-token page) floored that extend to zero, so `_select_prefill_admission` returned `OTHER` on every step and the waiting queue stalled behind the hit.
- `validate_deepseek_v41_encoder_replay_budget` now requires at least `128 + page_size` chunked prefill tokens per attention DP rank, up from 128.
- `handle_model_capability_adjustments` rejects `--enable-encoder-swa-bounded-replay` on models other than DeepSeek-V4.1. Only the DeepSeek-V4 architecture checked the flag before, so on any other model the generic scheduler and worker code still acted on it.
- `test_encoder_swa_replay.py` checks the floor; `test_prefill_adder.py` adds the boundary case, which still admits one page.

Servers with encoder replay and a per-rank chunk below that floor now fail at startup instead of stalling on the first prefix hit. Other models with the flag now fail at startup too. On gfx950, where exact chunk fill skips the page floor, chunks of 129-383 tokens also ran before; they now need 384 too.
