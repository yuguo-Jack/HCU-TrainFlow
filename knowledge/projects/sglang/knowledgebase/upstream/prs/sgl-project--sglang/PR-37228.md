## Summary

Adds serving support for **XingChen4** (architecture `XingChen4ForCausalLM`)
— China Telecom's MoE model with:

- **MLA** attention
- **mHC** (Manifold-constrained Hyper-Connection) residual streams
  (`hc_hidden_size`, e.g. 14336 = 4 × 3584)
- Native **MTP** speculative decoding (reuses `DeepseekV3ForCausalLMNextN` as
  the draft arch), including a fix for `spec_hidden_size` on mHC
  contracted-draft models
- **Tool calling** via a dedicated `xingchen4` tool parser
- **Reasoning** via `XingChen4Detector` (`` style markers)

## Changes

### New files
- `python/sglang/srt/models/xingchen4.py` — model implementation
- `python/sglang/srt/configs/xingchen4.py` — `XingChen4Config`
- `python/sglang/srt/function_call/xingchen4_detector.py` — tool-call detector

### Modified (registration-level, small)
- `configs/model_config.py` — arch registration + MTP draft handling +
  `spec_hidden_size` fix for mHC contracted draft
- `configs/__init__.py`, `utils/hf_transformers/common.py` — config export
- `function_call/function_call_parser.py` — register `xingchen4` tool parser
- `parser/reasoning_parser.py` — `XingChen4Detector` for reasoning parsing
- `arg_groups/speculative_hook.py` — arch hook for speculative decoding
- `arg_groups/overrides.py` — add `XingChen4ForCausalLM` to the DeepSeek
  family, FlashInfer AllReduce Fusion, and DeepSeek-model-detection arch lists
- `arg_groups/model_hook.py` — disable `SGLANG_OPT_DEEPGEMM_HC_PRENORM` for
  XingChen4 (torch.compile cannot trace DeepGEMM's raw C extension; falls
  through to the TileLang splitk path that already supports
  `hc_hidden_size=14336`)
- `kernels/ops/layernorm/mhc.py` — support `hc_hidden_size=14336` in the mHC
  split-K kernel (`hidden_block=256`)
- `docs/.../tool_parser.mdx`, `docs/.../generative_models.mdx` — docs entry
  (marked "coming soon")

## Architectural notes

The per-model default-value logic was migrated out of `server_args.py` by
recent upstream config refactors (#36896, #36972, #36973, #36975, #37086,
#37087). Accordingly, XingChen4's arch registration follows the new layout:
- arch lists → `arg_groups/overrides.py`
- per-model env adjustments → `arg_groups/model_hook.py`

`server_args.py` itself is unchanged.
