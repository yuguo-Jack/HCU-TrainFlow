# [Fix] modelopt: Defer serialized CUTLASS NVFP4 scale layouts until loading

[Upstream PR](https://github.com/sgl-project/sglang/pull/42452) · state: open · merged: False

## Original PR description

Reopened from #40682, which was closed by mistake on 22 September; its review history is still there.

Serialized CUTLASS NVFP4 models swizzle uninitialized expert scales during construction, then rebuild those layouts after loading. Those duplicate buffers can make a checkpoint fail before its weights are read. MiMo-V2.6-Flash-RL on TP2/EP2 RTX PRO 6000 reaches the 95 GiB device limit during audio-encoder construction; the redundant MoE scale buffers account for 8.8125 GiB per rank.

Defer the derived layouts for serialized CUTLASS checkpoints, as the TRTLLM and MegaMoE paths already do. The normal post-load code creates and aliases the populated scales. The online quantization allocation path stays intact.

Validation: five remote CPU tests cover cold allocation, online initialization, post-load values, reloads, and non-gated padding. With this change, the same complete MiMo NVFP4 artifact loads and serves on two RTX PRO 6000 Blackwell cards, including sampled bring-up, cached conversation and bounded-context checks. No weight or activation precision is changed. The separate MiMo packed-module mapping fix used by that mixed checkpoint is #42450.

Duplicate preflight on 2026-09-22 applies cleanly to upstream 264da633191d. Inspected #38216: it changes FP4 dispatch and per-token all-gather scales, not construction-time derived buffers.

Rebased onto upstream `f2385314b2b3` on 2026-10-04. Since the first version, #39939 made the CUTLASS post-load path read the runner's activation settings, so the unit test now builds its runner config from `MoeRunnerConfig` instead of a bare namespace. No upstream change since then defers these scale layouts. All 5 tests pass, with 4 subtests. The repo's pre-commit hooks pass on the changed files.
