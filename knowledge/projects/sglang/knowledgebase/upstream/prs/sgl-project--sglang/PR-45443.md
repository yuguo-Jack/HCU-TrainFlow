# [Fix] [AMD] imports: Skip import-time device probes when no GPU is visible

[Upstream PR](https://github.com/sgl-project/sglang/pull/45443) · state: closed · merged: True

## Original PR description

## Motivation

On a ROCm build of torch, `torch.version.hip` is set whether or not the process can see a GPU. Several sglang modules query the device at import time on the HIP path, so a ROCm process without a visible GPU (a CPU-only worker, a router, CPU unit tests) dies while importing `sglang.srt`:

```bash
$ docker run --rm -e HIP_VISIBLE_DEVICES= -e SGLANG_USE_AITER=0 <rocm image> python -c "import sglang.srt.layers.quantization"
  File ".../sglang/kernels/ops/quantization/fp8_kernel.py", line 102, in <module>
    if is_fp8_fnuz():
  File ".../sglang/kernels/ops/quantization/fp8_kernel.py", line 98, in is_fp8_fnuz
    return "gfx94" in torch.cuda.get_device_properties(0).gcnArchName
RuntimeError: No CUDA GPUs are available
```

The CUDA path does not have this problem: `is_cuda()` already requires `torch.cuda.is_available()`, so the CUDA arch checks return False on a machine with no visible device.

## Modifications

- `srt/utils/common.py`: `is_hip()` also requires `torch.cuda.is_available()`, like `is_cuda()` and the platform layer's `_is_rocm_available()`. `is_gfx95_supported`, `is_gfx942_supported` and `is_gfx1250_supported` check `is_hip()` instead of `torch.version.hip`. In a process with no visible GPU, the `_is_hip`-guarded device queries and aiter imports that run at import time (`is_fp8_fnuz`, `ON_GFX950`, `CUDA_CAPABILITY`, ...) are then skipped, as the `_is_cuda`-guarded ones are on CUDA.
- `kernels/ops/attention/rocm_mla_decode_rope.py`: drop the local `is_hip()`, which asked Triton's active driver at import ("0 active drivers" without a GPU), and use `sglang.srt.utils.is_hip` like the rest of the kernels.

With a GPU visible, `is_hip()` is True as before, so every caller gets the same value; CUDA and CPU builds stop at `torch.version.hip is not None`. `torch.cuda.is_available()` does not run torch's CUDA lazy init, and `import sglang` already calls it (in the platform checks), so HIP is not touched earlier than before. Without a GPU, a ROCm process takes the paths a CUDA process without a GPU takes: `is_hip()`, `is_cuda_alike()` and the gfx probes are False, and `fp8_dtype` / `FP8_E4M3_MAX` are the `float8_e4m3fn` values.

## Accuracy Tests

Not applicable: with a GPU visible, `is_hip()` and every value derived from it are unchanged.

## Testing

`python -m pytest test/registered/unit/utils/test_common.py`, CPU torch 2.11.0:

- main + the new test: `test_returns_false_without_querying_the_device` fails for all four probes (`is_hip()` returns True, each gfx probe raises `RuntimeError: No CUDA GPUs are available`).
- this PR: 13 passed, 2 skipped, 8 subtests passed.

GPU-less import check: 22 `sglang.srt` / `sglang.kernels` modules, each imported in a fresh interpreter, in `rocm/sgl-dev:miles-rocm10-mi35x-20261019` with no GPU device (`HIP_VISIBLE_DEVICES=`), aiter main (includes ROCm/aiter#6738). The list includes `layers.quantization`, `model_executor.model_runner`, `managers.scheduler`, `entrypoints.http_server`, `entrypoints.engine` and `models.qwen3_5`. 7/22 import on main (the rest stop at `is_fp8_fnuz`, `is_gfx95_supported` or `is_gfx1250_supported`), 22/22 with this PR, for `SGLANG_USE_AITER=1` and `=0`.

I also imported every module under `srt/models`, `srt/layers`, `srt/managers`, `srt/entrypoints` and `kernels/ops` (1646 modules) the same way, with `SGLANG_USE_AITER=1`. On main, 681 fail at a device query. With this PR, no module that imports on main fails, and 2 still query the device at import: `kernels/ops/diffusion/norm/norm_triton.py` (fails the same way with CPU-only torch) and `kernels/ops/attention/unified_attention_3d_mtp.py` (imports `e4m3_dtype` from aiter, which derives it from the GPU arch; no module imports it at import time). The other failures are missing optional packages, NPU/XPU-only modules, import paths that current aiter does not have, and models that fail the same way with CPU-only torch (Mamba, DBRX, XVERSE MoE).
