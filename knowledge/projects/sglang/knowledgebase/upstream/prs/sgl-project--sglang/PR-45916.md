## Motivation

GGUF MoE must discard padded and nonlocal routes without consuming their expert outputs or NaN scores. Preparing safe IDs and clearing intermediate tensors on every call adds allocations and launches, while an unguarded native projection can form a weight address from a negative ID.

This PR moves CUDA vector-route safety into a local native consumer, shares its format math with the AOT implementation, and preserves per-slot product rounding before the existing MoE reduction. It also restores lazy fallback accumulation and repairs the shared native MMQ bounds/scale indexing.

## Changes

- CUDA MMVQ uses a local JIT entry with negative-ID checks before expert-address formation. Ordinary contiguous int32 routes retain their storage; exceptional layouts/widths normalize explicitly. The quantize/project structure and zeroed projection output remain intact.
- CUDA weighting excludes inactive outputs and scores inside its product kernel, removing activation-sized input copies and separate intermediate clears. Products still round to the output dtype before native `moe_sum`.
- Shared native GGUF code checks MMQ slack bounds before access and indexes Q8_1 scales with the same routed row as the values. Rebuilt MUSA providers can use the native in-place weighting operator; older providers retain their compatibility path.
- The slow fallback adopts the first valid expert result, adds later contributions in order, and zeros the existing final row only when all routes are inactive.
- A local non-flushing FP32 multiply preserves subnormal operands/results and signed zero in CUDA weighting, including SM90 fast-math builds. MUSA multiplication and the reducer are unchanged.
- Shared GGUF headers have one AOT source owner, with JIT forwarding links. Source-distribution staging materializes those headers so the runtime package remains self-contained.
