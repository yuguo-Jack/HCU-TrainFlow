# [Perf] diffusion: Parallelize heavy component loading

[Upstream PR](https://github.com/sgl-project/sglang/pull/48036) · state: open · merged: False

## Original PR description

## Summary

Overlap the DiT and text-encoder weight loads with a small thread pool so
diffusion cold-start is no longer strictly serial. VAE/tokenizer loads stay
on the serial path, and worker threads pin the platform device to avoid
cross-device weight placement.

## Changes

- `component_loading_order.py`: new `is_parallel_load_candidate()` and
  `partition_component_load_specs()` split load specs into weight-heavy
  (DiT/text-encoder) and serial helpers.
- `composed_pipeline_base.py`: parallelize heavy loads in `load_modules()`
  with a small thread pool (max 2 workers); VAE/tokenizer stay serial;
  worker threads pin the platform device.
- `test_component_loading_order.py`: 7 unit tests for ordering/partitioning.
- `test_parallel_component_loading.py`: 2 unit tests for parallel-vs-serial
  behavior of the load helper.

## Tests

- Local CPU-only unit tests: 9/9 passed (no GPU required).
- `pre-commit run --files` on all 4 changed files: all hooks green.
- CI not triggered yet (needs `run-ci` label from a maintainer).
