## Motivation

The NPU precise-test recommend job needs a fresh coverage baseline
(`outputs.tar.gz` + `test_case_map.json`) in Huawei OBS, which it downloads over
anonymous HTTPS to pick which tests to run. Today that baseline has to be
uploaded by hand after every run, so it drifts stale, and each step of the
pipeline has its own gaps:

- **Retries lose coverage.** `Re-run failed jobs` only re-executes the failed
  jobs, so a new attempt dir holds just a subset of the tests. Merging only the
  current attempt produces an incomplete report.
- **The gate and the displayed number can disagree.** The NPU-only percentage
  was computed inline while rendering `GITHUB_STEP_SUMMARY`, which may be unset
  on the k8s runner pool, so no persisted value existed for a threshold check.
- **The baseline was never gated.** A run with little or no coverage data could
  overwrite a good baseline in OBS.
- **Unowned run dirs accumulate.** Per-attempt dirs were cleaned up only when
  the publish step succeeded, so failures left them behind indefinitely.
- **Too little PR-time NPU coverage.** Several NPU tests were registered
  nightly-only, so PR runs collected almost nothing to build the baseline from.

## Modifications

### `.github/workflows/pr-test-npu.yml`

- Merge all attempts of the current run into a single run dir (`<run_id>-attempt-*`),
  newest first with the current attempt winning, so a re-run keeps coverage from
  the jobs it did not re-execute.
- Fold per-attempt date dirs (`outputs/sglang@<date>`) into one destination to
  handle attempts that cross midnight UTC and split across two date tags.
- Compute the NPU-only total once and persist it to `${RUN_DIR}/npu_coverage.txt`;
  the run-page summary and the OBS gate both read that value, so the gated and
  displayed numbers cannot diverge.
- Add an **Upload baseline to OBS** step that installs `obsutil` on demand and
  uploads `outputs.tar.gz` and `test_case_map.json` with `-acl=public-read`,
  then verifies an anonymous HTTPS `HEAD` returns 200 (a stale private ACL would
  otherwise only show up as a confusing failure in the next run).
- Gate the upload on NPU-only coverage >= 10%, failing closed when the value is
  missing; skip with a warning when there is no coverage data or the OBS secrets
  are unset, so a partial run never overwrites a good baseline.
- Let **Publish outputs and map to shared disk** run with `if: ${{ !cancelled() }}`
  — the shared-disk baseline is the primary product and must not be blocked by
  an OBS failure.
- Cleanup now removes every attempt dir of the current run and sweeps
  `*-attempt-*` dirs older than 480 min (above the 6h job limit, so a live run can
  never match), while keeping the shared `coverage/` dir out of reach.

### Test registrations

- `test_npu_glm5_top64_pruned_bf16_8p_gsm8k.py`: also register in
  `base-c-test-acc-16-npu-a3`.
- `test_npu_return_indexer_topk_deepseek_v4.py` and
  `test_npu_return_indexer_topk_glm52.py`: also register in
  `base-b-test-2-npu-a3`.

Nightly registration is unchanged; these tests now also run in PR CI, which both
widens PR-time coverage and feeds real data into the baseline.
