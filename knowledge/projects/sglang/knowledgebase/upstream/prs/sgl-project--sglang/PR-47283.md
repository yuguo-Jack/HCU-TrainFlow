# [Fix] [AMD] deepseek-v4: Respect AITER selection for Q-LoRA quantization

[Upstream PR](https://github.com/sgl-project/sglang/pull/47283) · state: closed · merged: True

## Original PR description

## Motivation

On gfx95/gfx1250, DeepSeek V4 can select fused Q/K normalization and RoPE while `SGLANG_USE_AITER=0`. When the non-e8m0 producer is selected, both Q-LoRA prepare paths call the fused quantizer, although `fused_rms_fp8_group_quant` is imported only when AITER is enabled. This raises `NameError` before attention preparation completes.

## Modifications

Gate the AITER-dependent producer on the AITER switch and reuse the existing normalization/projection fallback when it is disabled. Keep the independent e8m0 producer available and preserve the downstream Q/K normalization, RoPE and cache-store path. Add a regression test for both prepare methods and the AITER/e8m0 choices.

## Accuracy Tests

On MI355X, PyTorch 2.11.0 with ROCm, using upstream `5007cbd6a57515bf5e008ff2fd2bdb834356b53c` and the patch:

- Both real prepare methods at batch sizes 1 and 5: all four AITER-off baseline cases reproduce the exact `NameError`; all four patched cases pass normalization, Q/RoPE, KV-cache and indexer checks using real block-FP8 projections.
- AITER-on: four base/head pairs complete, with all saved outputs compared byte-for-byte by the validation runner.
- Existing e8m0 tests pass: eight producer and two consumer cases, with no skips.
- The same 12-case dispatch regression yields four expected baseline failures and no patched failures.

These are fixed-weight component tests using DeepSeek-V4-Flash-FP8 configuration dimensions, not full-model accuracy or gfx1250 hardware results. AITER is installed; the disabled-switch cases use the existing Triton block-FP8 path.

The branch is aligned with upstream `68e57f40057175ff22a17ea0bdbe7ecbc69d9d91`; the changed model file and regression test are byte-identical to the GPU-validated versions. The local dispatch control was rerun after alignment; GPU results belong to the stated baseline.

## Speed Tests and Profiling

No performance improvement is claimed. This fixes a failing dispatch and leaves the AITER-on producer unchanged.
