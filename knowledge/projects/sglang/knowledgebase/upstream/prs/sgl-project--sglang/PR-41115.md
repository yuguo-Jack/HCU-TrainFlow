# memoize stop-string tail decoding within a step

[Upstream PR](https://github.com/sgl-project/sglang/pull/41115) · state: closed · merged: False

## Original PR description

## Motivation

`Req.tail_str` can be called multiple times for the same request step, including during finish checks and streaming prefix checks. Cache the decoded tail string using `(len(output_ids), tail_len)` as the key so identical decodes within a step are performed only once.

The key changes when tokens are appended, retracted/reset, or multiple speculative tokens are accepted, so no explicit invalidation is required in those cases. When `output_ids` is rewritten in place without changing its length, clear the memo explicitly before finishing the request.

## Modifications

- Memoize the most recently decoded tail string in `Req`.
- Key the cache by `(len(output_ids), tail_len)`.
- Reuse the cached value across finish and streaming prefix checks within the same step.
- Clear the memo when `_check_vocab_boundary_finish` rewrites `output_ids` in place at the same length.
- Preserve the existing decoding path and behavior for all other cases.
