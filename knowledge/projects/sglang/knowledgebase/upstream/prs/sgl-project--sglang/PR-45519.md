# [CI] [AMD] disaggregation: Register Mooncake KV buffers without HIP dmabuf

[Upstream PR](https://github.com/sgl-project/sglang/pull/45519) · state: closed · merged: True

## Original PR description

## What

Set `MOONCAKE_DISABLE_HIP_DMABUF=1` for the `stage-b-test-large-8-gpu-mi35x-disaggregation-amd` stage so Mooncake registers the KV cache with `ibv_reg_mr` instead of exporting it through HIP dmabuf.

## Why

Since the ROCm images picked up Mooncake v0.3.14-rc1 (#44404), `test_disaggregation_basic.py` and `test_disaggregation_pp.py` fail on every scheduled run, on all three ROCm lanes. Both Mooncake servers crash right after the KV cache registration finishes, at the first HIP stream use in `run_event_loop`:

- rocm10: `torch.AcceleratorError: CUDA error: out of memory` at `self.schedule_stream.cuda_stream` ([job](https://github.com/sgl-project/sglang/actions/runs/39421857090/job/118624623534))
- rocm720: `Fatal Python error: Segmentation fault` at the same line ([job](https://github.com/sgl-project/sglang/actions/runs/39150301666/job/117742424344))

The device has ~50 GB free at that point and the memory numbers match the last passing runs, so this is not a real VRAM shortage. The onset lines up with the image date: the last rocm10 run on `v0.5.22-rocm10-mi35x-20261017` (old Mooncake) passed the basic test; every run on the 20261018+ images fails it. The mori and nixl tests in the same job keep passing, so it is specific to Mooncake.

## Notes for the reviewer

I tried two env switches on the same stage before picking this one:

- `MC_IB_PCI_RELAXED_ORDERING=0` (relaxed ordering became the default in this Mooncake range): still crashes with the same OOM ([run](https://github.com/sgl-project/sglang/actions/runs/39541952032)).
- `MOONCAKE_DISABLE_HIP_DMABUF=1`: `test_disaggregation_basic.py` passes, no crash ([run](https://github.com/sgl-project/sglang/actions/runs/39541955700)).

The CI hosts support `ibv_reg_mr` on GPU memory, which is what the basic test's KV transfer uses in that run. This is a CI-side workaround; the dmabuf path in Mooncake itself still needs a fix upstream.

`test_disaggregation_pp.py` failed in the probe run with `KVTransferError ... Failed to send aux data`, which is the intermittent failure it already had on the old image (for example [this run](https://github.com/sgl-project/sglang/actions/runs/39083798380/job/117546079587)), not the startup crash.
