# [Perf] managers: reduce temporary buffers in expert base64 encoding

[Upstream PR](https://github.com/sgl-project/sglang/pull/45080) · state: open · merged: False

## Original PR description

## Motivation

Expert output encoding creates temporary byte buffers before it returns a base64 string.
This change removes those buffers in the detokenizer and tokenizer fallback.

## Modifications

- Encode contiguous NumPy buffers directly into base64 strings.
- Preserve C-order bytes for non-contiguous tensors.
- Keep missing items and pre-encoded strings unchanged.

This PR changes no IPC socket behavior.
The optional MessagePack socket optimization is separate in https://github.com/sgl-project/sglang/pull/45097.

## Accuracy Tests

The tests check byte equality, non-contiguous tensors, empty tensors, missing items, and pre-encoded strings.
Both routed experts and indexer output use the same encoding checks.

`isort --check-only`, `ruff format --check`, `ruff check --select F401,F821,F823,UP037`, and `git diff --check` passed for the changed files.

## Speed Tests and Profiling

| CPU operation | Payload | Before | After | Change |
|---|---|---:|---:|---:|
| Base64 encoding | 6 MiB tensor → 8 MiB string | 1.420 ms | 0.489 ms | -65.6% |

The encoding gain applies to both pickle and MessagePack IPC.
The measured encoding code stays the same after the PR split.
The benchmark uses thread CPU time and three interleaved runs, with five batches per run.
The host uses an Intel Xeon Platinum 8568Y+, Python 3.12, PyTorch 2.14.1 CPU, and pybase64 1.5.1.
These results measure CPU cost, not model throughput.
No GPU serving benchmark ran.
