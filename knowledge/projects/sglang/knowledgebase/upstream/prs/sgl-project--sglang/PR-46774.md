# [CI] [AMD] deps: Install openai 2.8.0 in AMD CI for the Responses API

[Upstream PR](https://github.com/sgl-project/sglang/pull/46774) · state: closed · merged: True

## Original PR description

## Motivation

Since #45254, `serving_responses.py` imports `responses_tools/beam.py` at module level, and `beam.py` uses `ResponseFunctionShellToolCall`, which only exists in openai>=2.8.0. #45291 moved `python/pyproject.toml` to 2.8.0 but left `pyproject_other.toml` at 2.6.1, and AMD CI installs from `pyproject_other.toml`. On AMD the Responses handler now fails to import at startup:

```
OpenAI Responses API (/v1/responses) disabled: OpenAIServingResponses init failed (ImportError: cannot import name 'ResponseFunctionShellToolCall' from 'openai.types.responses')
```

Every `/v1/responses` request returns 500. `TestOpenAIServerv1Responses.test_error` in `test/registered/openai_server/basic/test_openai_server.py` expects 400, so `stage-b-test-1-gpu-small-amd` fails on main ([example job](https://github.com/sgl-project/sglang/actions/runs/40427865857/job/121938136781)). The same shard passed on main before #45254 landed.

## Modifications

`scripts/ci/amd/amd_ci_install_dependency.sh` installs `openai==2.8.0` after the sglang install. This applies to the AMD CI installer only: `pyproject_other.toml`, the other platforms that use it, and non-CI installs are unchanged. The step can go once `pyproject_other.toml` moves to 2.8.0.

## Test plan

- [x] `stage-b-test-1-gpu-small-amd` on rocm10, dispatched on this commit: `test_openai_server.py` passes, 53 tests OK including `TestOpenAIServerv1Responses.test_error` ([job](https://github.com/sgl-project/sglang/actions/runs/40470481717/job/122076302939)). Shard 0 of that run lost its self-hosted runner, which is unrelated to this change.
