# [Perf] dsv41: Drop the MegaGate padded-row copy on sgl-deep-gemm 0.2.3.post2

[Upstream PR](https://github.com/sgl-project/sglang/pull/45933) · state: closed · merged: True

## Original PR description

## Motivation

Follow-up to #43262. sgl-deep-gemm 0.2.3.post2 carries sgl-project/DeepGEMM#116 (the `release/v0.2.3` port of #112), which skips the finite-score check on masked rows, so `bf16_mega_gate` no longer needs its input zeroed on padded rows before every MoE layer. That `torch.where` reads and rewrites the full bf16 input per layer on padded batches and offsets much of the fusion's gain.

## Modifications

- `python/pyproject.toml`: `sgl-deep-gemm==0.2.3` -> `0.2.3.post2`; `docker/Dockerfile.cu134` builds the matching `v0.2.3.post2` tag. Besides #116, post2 carries sgl-project/DeepGEMM#117, the faster SM100 `fp8_fp4_mqa_logits` paths that the V4.1 indexer's prefill logits use (logits unchanged).
- `python/sglang/kernels/ops/moe/mega_gate.py`: drop the `torch.where` on `valid_token_mask`; the mask still goes to the kernel.
- `test/registered/kernels/ops/moe/test_mega_gate.py` already replays graphs with NaN and inf in padded rows, so it is the regression guard for the kernel change.
