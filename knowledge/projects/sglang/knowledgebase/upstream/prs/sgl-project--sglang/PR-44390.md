# [Feat] detokenizer: Expose router message throughput

[Upstream PR](https://github.com/sgl-project/sglang/pull/44390) · state: open · merged: False

## Original PR description

## Motivation

Part of #43304. The detokenizer router now exposes CPU usage through #43323, but its message throughput is still invisible. Add counters for incoming messages, incoming request output entries, and successful sends after grouping or broadcasting.

## Modifications

Enable these counters only with `--enable-metrics`. Streaming outputs count again for the same request. Control messages and idle batches contribute no request output entries. Failed sends do not increment the sent counter. Document these boundaries so the counters are not mistaken for completed requests or queue depth.

This covers the router throughput portion of #43304. It does not duplicate #43323 or implement worker identity, queue latency, or processing time histograms. Searches for 43304, detokenizer metrics, and router throughput found no open PR for these counters.

## Accuracy Tests

23 tests passed, including repeated streaming outputs, grouped sends, idle batches, control broadcasts, and failed sends. The new regression fails against the original router implementation. No model weights or GPU generation were needed.

## Speed Tests and Profiling

No throughput improvement claimed. Enabled metrics add counter increments in the router process. The disabled path does not create counters. Full serving performance has not been benchmarked.
