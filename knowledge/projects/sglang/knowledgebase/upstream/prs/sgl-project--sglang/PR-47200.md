### Default behavior (runtime master switch off)

`SGLANG_ENABLE_NV_MEGA_RUNTIME_OPTIMIZATION` defaults to off, and its child switches follow it. With it off, execution matches `main`:
- EAGLE / multi-layer / UNO / NGRAM eager verify calls `eagle_sample` with the same arguments as `main` (no provider hooks or post-verify views are built).
- The asynchronous staging-metadata readback is not used; the original synchronous path runs.
- FlashMLA stays in the draft-extend graph-supported backend list, as on `main`.

Remaining differences on the default path are structural only and do not change execution: new dataclass fields with defaults, attribute initialization, imports, the decode admission `wait_stream` placement (same position relative to `prepare_for_prebuilt` and the KV checksum, with no GPU work between), and one `.to(bonus.dtype)` cast in the existing verify-commit Triton kernel that is a no-op for the default `int32` bonus buffer. Paths that remove clones, take the FP8 pre-quantized input, add the staging chunk-arrival lock, or pass an LM-head `out=` buffer are reached only through the optimized (switch-on or plugin) callers.

## Motivation

Speculative decoding performs many small index-building launches, copies, allocations, graph metadata updates, and recurrent-state operations between draft rounds. This PR adds model-independent, capability-checked fast paths while retaining the existing SGLang implementation as the fallback.

This PR contains runtime optimizations only: no provider ABI, provider factory, model-name check, or Qwen-specific kernel policy. It is based directly on `main` and does not depend on the companion binding PR.

**Switch inventory:** this standalone runtime tree has **28** Boolean child switches that follow `SGLANG_ENABLE_NV_MEGA_RUNTIME_OPTIMIZATION` when unset. The base `main` supplies 27; R7 adds exactly one, `SGLANG_TRTL3_EP_DEFER_FINALIZE`, as the 28th. This PR declares no other master-following child switch.

| ID | Purpose | Switch |
|---|---|---|
| R1 | Verify directly on vocabulary shards | `SGLANG_ENABLE_NV_MEGA_RUNTIME_OPTIMIZATION` |
| R2 | Fuse EAGLE index preparation | Master switch |
| R3 | Prepare the next EAGLE draft round | `SGLANG_ENABLE_EAGLE_POST_VERIFY_CUDA_GRAPH` inherits master when unset |
| R4 | Capture the EAGLE post-verify tail | Master + post-verify graph switch |
| R5 | Commit ReplaySSM state in one CUDA launch | Master switch |
| R6 | Capture generic GDN prefill state updates | `SGLANG_ENABLE_GDN_PREFILL_GRAPH_EXTEND` inherits master when unset |
| R7 | Reuse graph resources and speculative relays | Master; explicit child values take precedence |

## Modifications

### R1 — Verify directly on vocabulary shards

- **What:** Produce native or provider-supplied token keys from rank-local vocabulary logits and reduce the compact keys across tensor-parallel ranks. SGLang owns the reducer and every collective.
- **Why:** Greedy verification needs only the winning token, so this avoids a full-logit all-gather, temporary full-vocabulary tensor, and following argmax.
- **Switch:** `SGLANG_ENABLE_NV_MEGA_RUNTIME_OPTIMIZATION`.
- **Fallback:** Sampling, penalties, watermarking, logprob requests, provider decline, or a consumer without shard support returns to the original full-logit gather and verifier before provider RNG is consumed.

### R2 — Fuse EAGLE index preparation

- **What:** Fuse chain-tree construction, draft-extend layout, draft/cache locations, positions, and mRoPE indices in generic CUDA kernels.
- **Why:** Remove repeated small launches and intermediate tensors from model-neutral EAGLE index production.
- **Switch:** The master runtime switch.
- **Fallback:** Dtype, layout, shape, or device rejection occurs before JIT loading and uses the existing Triton/stock producers.

### R3 — Prepare the next EAGLE draft round

- **What:** During post-verify, stage request rows, accepted sequence lengths, positions, and KV write-window locations directly into the next draft graph's static buffers. A fresh host key and one-shot lease guard request-pool reuse; scheduler and runner tensors remain distinct.
- **Why:** Avoid returning through a scheduler gather and runner copy when the next graph-compatible destination is already known.
- **Switch:** `SGLANG_ENABLE_EAGLE_POST_VERIFY_CUDA_GRAPH`; when unset it follows the master switch, while an explicit value takes precedence.
- **Fallback:** Unsupported algorithm, top-k, EP/layout, graph miss, stale key, invalid lease, or insufficient reservation executes the original scheduler gather and runner copy.

### R4 — Capture the EAGLE post-verify tail

- **What:** Fuse chain acceptance and, for compatible cases, capture sampling, acceptance, commit-output preparation, and next-draft layout. Eager, graph, EAGLE, MultiLayerEAGLE, NGRAM, and UNO paths call one always-present strategy; runtime-only builds resolve a structural stock strategy.
- **Why:** Remove the multi-launch eager tail while keeping the stock verifier authoritative outside the graph contract.
- **Switch:** Fused chain acceptance uses the master switch. Capture/replay uses `SGLANG_ENABLE_EAGLE_POST_VERIFY_CUDA_GRAPH`, which follows the master only when unset.
- **Fallback:** Missing binding capability, unsupported device/tree/sampling/watermark/graph key, or provider decline invokes `eagle_sample` and the original eager path.

### R5 — Commit ReplaySSM state in one CUDA launch

- **What:** Fold accepted rows and update circular cache, tracking rows, cursor, and stable state in one generic CUDA launch before unchanged circular-fold bookkeeping.
- **Why:** Replace a multi-operation Triton state update and its intermediate launches/traffic.
- **Switch:** The master runtime switch only.
- **Fallback:** BF16, contiguous layout, supported shape/index, SM90+, CUDA binding availability, and successful NVRTC prebuild are all required; any miss uses the stock Triton commit. The CUDA path changes FP32 accumulation order and is tolerance-equivalent at `rtol=2^-7, atol=1e-6`, not bitwise-equivalent.

### R6 — Capture generic GDN prefill state updates

- **What:** Capture compatible GDN prefill/extend state tracking and FlashInfer calls in reusable CUDA graphs with caller-owned dynamic-input bridges.
- **Why:** Remove repeated host dispatch and allocation at graph-stable shapes.
- **Switch:** `SGLANG_ENABLE_GDN_PREFILL_GRAPH_EXTEND`; when unset it follows the master, while an explicit value takes precedence.
- **Fallback:** Unsupported mode, shape, graph size, backend, or capture error uses the existing eager implementation.

### R7 — Reuse graph resources and speculative relays

- **What:** Pool speculative tensors/events, reuse graph buffers and TRT graph metadata, batch small field copies, retain unchanged top-k-1 relay rows, and skip allocation work when prepared-next already owns the destination. It also adds capability-checked FP8 prequantized-input reuse, MNNVL shape/EP tuning, EP deferred finalization, and an optional lazy FlashMLA graph import.
- **Why:** Remove repeated allocation, copy, metadata construction, synchronization, and backend setup at draft/verify boundaries.
- **Switch:** The master runtime switch. R7 declares `SGLANG_TRTL3_EP_DEFER_FINALIZE` as the 28th master-following child; it and the 27 inherited child controls honor explicit `0` or `1` values before inheriting the master.
- **Fallback:** Shape, EP, backend, layout, graph-lifetime, or optional-import rejection performs the original copy, allocation, metadata construction, finalize, or backend path.
