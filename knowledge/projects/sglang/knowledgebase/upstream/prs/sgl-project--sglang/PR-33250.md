# [Fix] deepseek-v4: Fix DeepSeek-V4 non-EP TBO for attention TP > 1

[Upstream PR](https://github.com/sgl-project/sglang/pull/33250) · state: closed · merged: True

## Original PR description

## Motivation

Depends on #31700 (merged).

DeepSeek-V4 two-batch overlap (TBO) with DP attention, `moe_a2a_backend=none` and attention TP > 1 applied full-TP variable-length collectives to tensors replicated within each attention-TP group. On older `main` this corrupted the gather and combine layouts and produced invalid output (the H100 report below); on current `main` the same configuration fails in the TBO gather, because each child's DP counts have one entry per TP rank (`dp_slot_in`: "a per-replica sequence of 4 entries does not belong to a DP gather of width 2").

This change gives each full-TP rank one shard of its replicated DP-local tensor and reconstructs the DP-local result across the attention-TP group after the combine, and fixes the problems the same configuration hit next.

## Modifications

Original commits:
- Derive and validate DP-local token counts and full-TP shard counts for each TBO child batch.
- Shard replicated hidden states and input IDs across attention-TP ranks before the full-TP variable-length gather.
- Reduce-scatter the MoE output into one shard per full-TP rank, then all-gather within the attention-TP group to reconstruct the replicated DP-local output.
- Select the non-EP TBO strategy for CP 1, multi-rank DP and SUM_LEN padding; MAX_LEN batches take the non-overlapped path.
- Exercise attention TP in the registered DeepSeek-V4 TBO tests (AMD and H200) and add focused tests for collective-size mapping and validation.

Added after review:
- **Empty micro-batch.** TBO can split a short extend so that one micro-batch has no tokens on any DP rank; the overlapped MoE then ran the experts on zero rows, and the triton runner's fused SiLU-and-mul with the SwiGLU clamp rejected the zero-block launch, crashing the server on a single short request (also on `main`). The experts are now skipped for such a micro-batch; every rank gathers the same rows, so all skip together.
- **Eager decode at attention TP > 1.** TBO children are padded to a multiple of attention TP tokens, but a decode child kept its request count, so a one-request child carried two token rows and DeepSeek-V4's decode metadata asserted (`req_pool_indices 1, out_cache_loc 2`). A decode child now pads its requests with its tokens, as `prepare_mlp_sync_batch` does for the whole batch.
- **Shared expert locality.** The TBO path again computes a replicated TP1 shared expert on local rows only under `SGLANG_DP_SHARED_EXPERT_LOCAL`; inside the MoE it is added on TP rank 0 and the reducing combine counts it once (verified below).
- **AMD unit test stub.** `DeepseekV2MoE` now always sets `shared_experts`, and `forward_normal` reads it directly; the MoE stub in `test_deepseek_v4_amd_tp4.py` is built with `__new__` and failed with "no attribute 'shared_experts'" on MI35x. The stub now sets it to `None`.
- **AMD chat probe.** The single-request check added to the AMD TBO test runs on a server that thinks by default (`SGLANG_DEFAULT_THINKING=1`), so the reasoning counted against `max_tokens: 32` and the reply was cut off before the answer (`'7 + 5 equals'`). The budget is now 512 tokens, and a failure reports `finish_reason`.
- **ROCm.** The combine's attention-TP all-gather runs on the TBO communication stream while the other micro-batch's attention uses the same group's collectives on the compute stream. On ROCm `all_gather_into_tensor` takes aiter's custom all-gather, and MI355X failed later in unrelated kernels with "invalid configuration argument" (this PR's AMD CI failure), passing with `SGLANG_USE_AITER_AG=0`. The shards now go through the attention-TP device process group.
