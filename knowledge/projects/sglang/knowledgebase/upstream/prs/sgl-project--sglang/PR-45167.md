# [Perf] [Apple] mlx: Bound request map allocation by KV capacity

[Upstream PR](https://github.com/sgl-project/sglang/pull/45167) · state: open · merged: False

## Original PR description

## Motivation

MLX allocates each CPU request-map row for the model's full context, even when the KV pool limits requests to a much shorter length. With a 262,144-token context, 2,048 KV slots and the default 1,024 request slots, this table takes 1,025 MiB instead of about 8 MiB.

## Modifications

Bound the row width by KV capacity plus the existing decode headroom for dense and hybrid models. Model context, token capacity and concurrency limits stay unchanged. Add an initialization regression test covering both pool types and boundary cases.

## Accuracy Tests

- 29 related unit tests and eight boundary subcases pass. The new test fails before this change in two subcases.
- Default-overlap HTTP A/B: nine generation cases per model have identical output token IDs, counts and finish reasons, covering chunked prefill, concurrent requests, repeated prompts, abort recovery and invalid-input recovery.
- Dense overlap-off: seven serial cases also match.
- Hybrid overlap-on: the same cases match with radix cache disabled; the long case uses 1,792 input / 30 output tokens.

### Known pre-existing issues (not caused by this PR)

These configurations already fail on `main` without this change, so they were excluded from the A/B:

- Hybrid overlap-on (radix cache disabled) stalls at 2,016 input / 30 output tokens.
- Dense overlap-off fails under concurrent requests.
- Hybrid overlap-off with radix cache enabled fails.

I plan to file these separately.
