# [Doc] forward-hooks: Say that hooks don't run under CUDA graphs

[Upstream PR](https://github.com/sgl-project/sglang/pull/45318) · state: open · merged: False

## Original PR description

Fixes #45317

## Motivation

The forward hooks page says hooks are attached in `ModelRunner.initialize` and "run on every forward pass". That's not what happens. Hooks are registered **after** CUDA graph capture (`finalize_cuda_graph_capture`), and CUDA graph replay never runs Python hooks. With default settings on CUDA, decode and prefill both use CUDA graphs, so a hook can silently never run.

In #45317, a hook on `model.layers.14` of Qwen2.5-1.5B-Instruct (v0.5.21, NVIDIA L4) ran **0 times** for a 128-token request with default settings. It ran **128 times** with CUDA graphs disabled.

## Modifications

Docs only: `docs/docs/advanced_features/forward_hooks.mdx`.

- Fix the intro line: hooks are attached after CUDA graph capture and don't run on graph replay.
- "Hook lifecycle": replace the old `ModelRunner.initialize()` snippet with the real registration code from `finalize_cuda_graph_capture`.
- Key points: say hooks run only on the eager path.
- New section **"Hooks and CUDA graphs"**: why hooks don't run, and how to make them run on every step (`--disable-decode-cuda-graph --disable-prefill-cuda-graph`, or the engine kwargs `disable_decode_cuda_graph=True, disable_prefill_cuda_graph=True`). It also notes that this lowers throughput.
- Summary: same correction.

No code changes. A startup warning when `forward_hooks` are set while CUDA graphs are on could be a follow-up PR.
