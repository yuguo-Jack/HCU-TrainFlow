# [Fix] profiler: Init profile-by-stage counters when num_steps is not given

[Upstream PR](https://github.com/sgl-project/sglang/pull/47475) · state: open · merged: False

## Original PR description

Fixes #47294

## Motivation

`POST /start_profile` with `profile_by_stage=true` and no `num_steps`
returns 200 OK and then crashes every scheduler on the first batch:

```text
File ".../srt/managers/scheduler_components/profiler_manager.py", line 422,
  in _profile_batch_predicate
    self.profiler_prefill_ct += 1
TypeError: unsupported operand type(s) for +=: 'NoneType' and 'int'
```

`_init_profile` only initialized the stage counters (`profiler_prefill_ct` /
`profiler_decode_ct`) inside `if num_steps:`, so a stage-profiled session
without `num_steps` left them at `None`. The same latent `None` comparison
(`curr_count > target_count`) existed in the v2 `_StageBasedTrigger` in
`profile_utils.py`, crashing on the second batch of a stage.

## Modifications

- `profiler_manager.py` (`_init_profile`): initialize the stage counters
  whenever `profile_by_stage` is set, independent of `num_steps`. The stage
  targets are set to `num_steps` (or `None` when absent, which also clears
  any stale targets from a previous session), so a session without
  `num_steps` profiles until an explicit `/stop_profile`.
- `profiler_manager.py` (`_profile_batch_predicate`): guard both auto-stop
  comparisons with `target is not None`, so no target means no auto-stop.
- `profile_utils.py` (`_StageBasedTrigger`): accept `num_steps=None`
  (`target_count: Optional[int]`) and skip the auto-stop comparison when the
  target is `None`; a stage then profiles until the stage changes, matching
  the v1 behavior.

No behavior change when `num_steps` is given: counters start at 0 and the
profile still auto-stops once the count exceeds the target.

## Tests

No GPU on this machine, so the scheduler path could not be run end to end.
Verified with a stub harness (`harness_47294.py` in the contributor
workspace, AST-extracts the real methods and runs them on stubbed
manager/batch objects, no torch needed) — 27 checks, all passing:

- The pre-fix code reproduces the reported crash: `TypeError: NoneType`
  on the first prefill batch (v1) and on the second prefill step (v2).
- With the fix, `profile_by_stage=true` + no `num_steps`: counters start at
  0, the profile starts on the first prefill batch, counts keep incrementing
  across prefill/decode batches, and no auto-stop fires.
- Regression: `num_steps=2` still auto-stops once the count exceeds the
  target, in both v1 and v2.
- Regression: the non-stage paths are unchanged (`num_steps=3` still sets
  `profiler_target_forward_ct = forward_ct + num_steps + 1`).
- Re-initializing a session clears stale targets/counters from a previous
  session.

`ruff check --select F401,F821,F823,UP037`, `ruff format --check`, and
`py_compile` pass on both touched files; `git diff --check` is clean.
