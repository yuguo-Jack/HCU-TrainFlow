# [Refactor] moe: Derive routing inputs from the layer and active forward

## Motivation

Model forwards can omit expert placement or the live token count, routing logical IDs against physical expert weights or processing padding as real tokens. Move those decisions into TopK and the active forward. Automatic padding also makes inactive routes reachable at EP1, so every affected consumer must skip their data, weights and expert addresses safely.

## Modifications

- Resolve placement per call and capture draft identity during construction. Align draft weight loading with identity routing, including in-range draft layer IDs; retain target placement-aware loading.
- Bind the prepared ForwardBatch across eager execution, graph capture/replay, CPU graphs and TBO children. Bind copied row/tail batches too. Decline DeepSeek row-tail capture when its MoE count is a separate GLOBAL buffer, using the existing eager path.
- Preserve lazy routing metadata until materialization. Keep the producing layer ID in TopKConfig, including piecewise reconstruction, so lazy LP conversion defaults to the correct solver while explicit overrides (including 0) still win. Keep the existing five-field tuple ABI. Reject logits-only consumers that cannot apply required remapping. Route DeepSeek graph admission through the same layer contract. Keep shared expert columns outside LP solving and routed-only remapping.
- Make Triton, Marlin, GGUF, W4AFP8 and Humming consumers honor inactive routes independently of EP, including NaN inputs/weights and poisoned intermediate buffers. Generic Marlin reuses its projection allocation, clearing the down view after activation consumes the up view; LoRA retains separate zeroed buffers.
- Support the published `sglang-kernel==0.4.10` GGUF provider with Python block-size selection, safe vector indices, masked inactive intermediates/contributions, and initialized MMQ slack metadata. Retain the AOT source fixes for future wheel builds.
- Initialize CUTLASS FP8 gather maps and use a masked Triton reduction that skips inactive data and weights. Pass token count and supported weight strides at runtime without value specialization so new lengths reuse compiled kernels. This fixes both block-FP8 and MXFP8 without requiring a newly released AOT wheel.
- Reject LongCat zero-expert placement configurations at startup, since routed-only placement tables cannot represent its identity experts safely. Plain identity placement remains available.
- Assert the Marlin allocation property rather than an incidental `.zero_()` call; set its CI runtime estimate to 720 seconds to cover cold compilation.
