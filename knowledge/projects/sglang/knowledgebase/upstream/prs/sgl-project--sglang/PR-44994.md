# [Refactor] moe: Derive routing inputs from the layer and active forward

## Motivation

Qwen3 MoE's normal forward can omit configured expert placement, selecting logical IDs against physical expert weights after a nontrivial initial placement or EPLB rebalance. Model forwards also repeat dispatch metadata, padding-bound and draft checks. Centralizing those inputs exposes padded routes to consumers at EP1, so their inactive-route handling must work independently of expert parallelism.

## Modifications

- Let TopK and HashTopK derive placement from their layer and construction-time draft identity, resolving placement views per call so rebalances remain visible. Remove repeated model-side metadata assembly and rejoin common vision-routing finalization.
- Bind the prepared ForwardBatch's padding-bound getter in ForwardContext across eager execution, capture/replay, retained debug callbacks, CPU graphs and TBO children. Preserve persistent graph buffers and the existing layout/tracking policy; ordinary CPU EP1 captures publish no inactive count. Derive draft decode counts from prepared speculative width when needed.
- Preserve logical capture separately from dispatch IDs. Keep NPU padding contributions zero and reject formats that cannot apply required nonidentity placement.
- Complete CUDA inactive-route handling before expert indexing and output reduction. Triton and Marlin skip canonical `-1` independently of EP. Marlin uses disjoint zeroed projection views in its generic, stock LoRA, experimental LoRA and MuseSpark callers; preserve sentinels during MuseSpark localization and mask inactive LoRA/MuseSpark weights. Public Marlin allocation mode initializes skipped rows while caller-provided output ownership stays unchanged.
- GGUF vector/MMQ kernels write zero for inactive routes before weight access; MMQ checks the used block range before metadata reads. Use the allocating alignment helper, skip negative IDs in the slow fallback and exclude inactive NaN weights. Repair the obsolete method assertion and no-Tensor block-size operator registration needed by these paths.
- W4AFP8 translates inactive IDs to its sink before sorting at EP1/EP2 and excludes fully inactive rows from dynamic input-scale statistics. Humming permutation/finalization excludes inactive data and weights independently of EP, including safe expert-map lookup.

## Validation

Current stacked head: `3dbf557c84a92d8190d467e3b3b704161aa67e9e`.

- Real Torch CPU integration: **396 tests + 166 subtests passed** across ten files. All 140 changed source/test path hashes were verified before and after execution against the final tree.
- **18 Marlin CUDA cases passed**: GPTQ 4/8-bit, AWQ 4-bit, single-token/tiny/generic alignment, changing live counts through captured graphs, all-inactive output allocation, the stock core with hook-weight checks, zero-adapter factored LoRA, nonzero direct LoRA projections, and MuseSpark NVFP4 with both post-norm tails. Padded logits/weights and output storage are poisoned; live results use independent dense references. The initial 13-case regression failed on the previous native implementation and passed after repair.
- **4 GGUF tests + 6 subtests passed**: Q4_0/Q8_0 vector and MMQ, automatic TopK through StandardDispatcher and the real GGUF method, graph replay, local/nonlocal EP mapping, no-Tensor metadata dispatch and the eager F16 fallback. Native intermediate buffers are poisoned before replay and must be finite with exact-zero inactive rows. Vector and MMQ controls using the old native kernels fail. Dense references include Q8_1 activation quantization; tolerances were not increased. These tests load a selective rebuild of the production GGUF CUDA translation unit and scalar-registration fragment; a complete AOT wheel build was not run.
- **3 W4AFP8/Humming tests + 24 subtests passed** on real CUDA routing/count/permutation/activation/finalization kernels: EP1/EP2, static/dynamic scales, NaN inactive weights and zero/large/Inf/NaN inactive inputs. Only the external CUTLASS GEMMs are replaced with dense expert GEMMs; native INT4 and external Humming GEMM numerics are not claimed.
- Hardware/software: single-GPU NVIDIA B300 processes; Python 3.12.15, Torch 2.14.1+cu130, Triton 3.8.0, FlashInfer 0.7.1, CUDA 13.0. Marlin used a fresh JIT cache and GGUF used the rebuilt source above.
- Same-GPU cold-L2 Marlin comparison, 100 samples with a 512 MiB flush outside timing: valid-route full-wrapper medians were 18.46 → 20.48 µs for a tiny decode shape, 28.67 → 30.72 µs for H=2048/I=768/top-k=8 decode, and 112.77 → 116.96 µs for the corresponding 64-token prefill. This is a measured overhead, not a throughput improvement. Generic/MuseSpark scratch grows by `tokens * top_k * min(gate_up_width, hidden_width)` elements (24 KiB decode / 1.5 MiB prefill in those BF16 shapes); stock/experimental LoRA payload is unchanged.
- Configured pre-commit, independent source review, strict CI registration and suite validation passed: **2,442 files / 2,974 registrations**, including executable entries for the new files.

Earlier reduced BF16 Qwen3 TP4/EP4 reverse-placement graph smoke matched all 72 generated IDs and logprobs against identity placement; the Triton/CSGMV MoE LoRA graph matrix and routing checks also passed at their previously recorded revisions. They were not rerun as full-model validation of this final head. Full-model GSM8K, complete CI, ROCm/NPU/AMX execution and external FlashInfer/HPC/KT native consumer coverage remain unverified.
