# [Perf] [NVIDIA] kernels: Add Blackwell SM100 CuTe DSL NVFP4 DualGEMM+SwiGLU, PDL-safe GEMM, Grouped GEMM, and Fused MoE

[Upstream PR](https://github.com/sgl-project/sglang/pull/47589) · state: open · merged: False

## Original PR description

## Motivation

On NVIDIA Blackwell SM100 (B200), ModelOpt NVFP4 (`w4a4`, `E2M1` 2x-packed weights/activations with `E4M3` 16-element block scales and per-tensor FP32 `alpha`) dense MLP layers (`LlamaMLP`, `Qwen2MLP`, `Qwen3MLP`) and Mixture-of-Experts (`MoE`) grouped GEMM workloads incur extra kernel launch, global memory round-trip, and tensormap update overhead when executing unfused `gate_up_proj -> SiluAndMul`, non-persistent large-M GEMMs, or unfused `GEMM1 + SwiGLU + scaled_fp4_grouped_quantize + GEMM2` MoE pipelines.

This PR adds four warp-specialized Blackwell SM100 CuTe DSL NVFP4 operator modules under `sglang.kernels.ops.gemm` and `sglang.kernels.ops.moe` and integrates them with `DualGemm`, `ModelOptFp4LinearMethod`, and `flashinfer_cutedsl_moe`:

1. **`gemm.nvfp4_dual_gemm_swiglu` (`cutedsl_nvfp4_dual_gemm.py`)**:
   - Fuses `C = silu(alpha * (A @ B1.T)) * (alpha * (A @ B2.T))` into a single 2-CTA (`256x128x256`, cluster `(2, 1)`, 5-stage) or 1-CTA (`128x128x256` / `128x64x256`) `tcgen05.mma.cta_group::2.kind::mxf4nvf4` kernel.
   - Concatenates `sB1` and `sB2` along the N-mode in SMEM so a single `256x256` 2-CTA UMMA computes both gate and up accumulators simultaneously into 512 TMEM columns, cutting `sA` SMEM-to-UMMA descriptor traffic and `SFA` S2T copies (`tcgen05.cp`) in half.
   - Balances `MUFU.RCP` (`1/4` of pairs) with 2-step `FMA` Newton-Raphson refinement (`3/4` of pairs) in the SwiGLU epilogue.
   - **1.52x** faster than the strongest `cuBLASLt 13.0` baseline (`Concat[B1;B2]` `torch._scaled_mm` + compiled SwiGLU) in PDL-safe mode, and **2.57x** faster in fast mode.

2. **`gemm.nvfp4_gemm_pdl_safe` & `gemm.sm100_nvfp4_gemm` (`cutedsl_nvfp4_gemm.py`)**:
   - Implements a PDL-safe (`griddepcontrol.wait` before TMA SMEM loads + `cp.async.bulk.wait_group.read 0` before CTA exit) 1-CTA 8-stage (`128x64x256`, `sC`-in-`sA` SMEM aliasing), 2-CTA 5-stage (`256x128x256`), and `StaticPersistentTileScheduler` 2-CTA (`Sm100Nvfp4GemmPersistent2CTA`, `tile_n in {64, 128, 192, 256}` with wave-quantization selector and `(1, 4)`/`(1, 2)` A-multicast) NVFP4 dense GEMM.
   - Achieves **1.24x–1.38x** over `cuBLASLt 13.0` `torch._scaled_mm` at `M=128` on 8 of 9 shapes (`0.61x–1.23x` at `M=640..2048` after the 196 KB persistent SMEM cap); against autotuned `FlashInfer 0.7.2` `mm_fp4(cute-dsl)` across 30 `Llama-3.1-8B` / `Qwen3-32B` linear configs (`M=128..2048`), it measures `0.72x–1.00x` on 25 of 30 configs (`0.79x–0.99x` on all 10 `down_proj` configs, `30/30` bitwise equal), so it is opt-in (`SGLANG_USE_CUTEDSL_NVFP4_DOWN_GEMM=0`). **0/4,800** failed reps across 16 Operand-A and Operand-B RAW aliasing chain tests (`pdl_chain_test.py`).

3. **`gemm.nvfp4_grouped_gemm` & `gemm.nvfp4_masked_grouped_gemm` (`cutedsl_nvfp4_group_gemm.py`)**:
   - Passes all `G` groups' host-constructed TMA descriptors via SM100's 32 KB `CONSTANT[0]` parameter bank into a single fused 1-CTA 6-stage / 2-CTA (`tile_n in {128, 256}`) `@cute.kernel` launch, plus persistent 3D-TMA masked grouped GEMM (`Sm100Nvfp4MaskedGroupGemmPersistent`) with dynamic 1024B-aligned SMEM prefix-scan headers for arbitrary `G`.
   - Achieves **1.59x** speedup (PDL-safe default) and **1.83x** speedup (fast mode) over pre-queued `cuBLASLt 13.0` on small-M grouped shapes, and **1.18x–1.86x** on 8-group shapes with 256 rows per group (`0.95x–0.96x` at 2048 rows per group).

4. **`moe.nvfp4_masked_grouped_moe` & `moe.nvfp4_routed_grouped_moe` (`cutedsl_nvfp4_moe.py`)**:
   - Fuses 3D-TMA Dual-B GEMM1 + SwiGLU + in-register UE8M0/FP4 epilogue quantization (`Sm100Nvfp4MaskedDualGemmSwiGLUQuantV2`) with persistent 3D-TMA masked GEMM2, eliminating the `(G, M_max, N)` BF16 intermediate global memory round-trip and separate quantization kernel launch.
   - Measures **0.98x–1.25x** over `FlashInfer CuteDSL` masked MoE under CUDA Graph (parity on the smallest DeepSeek-R1 shape) and **1.05x–1.28x** in eager mode across DeepSeek-R1 and Qwen3-235B expert shapes, with bitwise-identical outputs.

## Relative Speedup Summary on NVIDIA B200 (`SM100`)

| Operator | Workload / Shapes | Baseline | Speedup (This PR vs. Baseline) |
| :--- | :--- | :--- | :---: |
| `nvfp4_dual_gemm_swiglu` | `(256..512, 3072..4096, 4096..7168)` | `cuBLASLt 13.0` `Concat[B1;B2]` + compiled SwiGLU | **`1.52x`** (PDL-safe) / **`2.57x`** (fast) |
| `nvfp4_gemm_pdl_safe` (opt-in) | `M=128` / `M=640..2048` (9 `(N, K)` shapes) | `cuBLASLt 13.0` `torch._scaled_mm` | **`1.24x–1.38x`** (`M=128`, 8 of 9 shapes) / `0.61x–1.23x` (`M=640..2048`) |
| `nvfp4_grouped_gemm` | `G=2..8` Grouped GEMM | Pre-Queued `cuBLASLt 13.0` | **`1.59x`** (PDL-safe) / **`1.83x`** (fast) / **`1.18x–1.86x`** (`G=8`, 256 rows/group) / `0.95x–0.96x` (`G=8`, 2048 rows/group) |
| `nvfp4_masked_grouped_moe` | `G=8, m_max=256..512` Fused MoE | `FlashInfer CuteDSL` Masked MoE | **`0.98x–1.25x`** (CUDA Graph) / **`1.05x–1.28x`** (Eager) |
| In-Tree `Llama-3.1-8B-NVFP4` & `Qwen3-32B-NVFP4` ¹ | ShareGPT Prefill TTFT & Batched Decode TPOT (`B=128, 256`) | SGLang Default (`DUAL=0, DOWN=0`, `FlashInfer 0.7.2`) | **`0.99x–1.03x`** Prefill / **`1.01x–1.09x`** Decode (CUDA Graph, tuned) · **`1.08x–1.09x`** / **`1.02x–1.21x`** (Eager) |

¹ Measured at `5d849d61cd` with `FlashInfer 0.7.2` at default `DUAL=1, DOWN=0` (synthetic prefill `M=128..4096`: `0.96x–1.04x` tuned / `0.99x–1.25x` untuned eager; opt-in `DUAL=1, DOWN=1` reaches `1.44x–1.56x` ShareGPT prefill and `1.53x–2.02x` decode in untuned eager `one_batch` mode by avoiding per-layer Python runner dispatch, but measures `0.95x–1.07x` in CUDA-graph decode and `0.92x–1.02x` in tuned prefill, so `DOWN=0` remains default).

## Default Behavior

DualGEMM and grouped MoE are on by default; the dense GEMM is opt-in. Each integration runs only on SM100 when its shape and layout guards pass; otherwise the existing path runs.

| Environment variable | Default | Effect |
| :--- | :---: | :--- |
| `SGLANG_USE_CUTEDSL_NVFP4_DUAL_GEMM` | `1` | `0`: `DualGemm` keeps the existing `gate_up_proj` + `SiluAndMul` path |
| `SGLANG_USE_CUTEDSL_NVFP4_DOWN_GEMM` | `0` | `1`: `fp4_gemm` sends w4a4 layers with `M >= 128` to `nvfp4_gemm_pdl_safe` (`SGLANG_USE_CUTEDSL_NVFP4_GEMM=1` does the same) |
| `SGLANG_USE_CUTEDSL_NVFP4_GROUPED_MOE` | `1` | `0`: `flashinfer_cutedsl_moe_masked` keeps the existing `scaled_fp4_grouped_quantize` + FlashInfer CuteDSL grouped GEMM path |
