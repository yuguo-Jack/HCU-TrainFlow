# [Perf] diffusion: Tile the 3D scale-shift Triton kernel by rows

[Upstream PR](https://github.com/sgl-project/sglang/pull/46147) · state: closed · merged: True

## Original PR description

Branch: mick/diffusion-scale-shift-row-tiles (on main efd2ce8a9d), commit ca74a81722

## Motivation

`fuse_scale_shift_kernel`'s `[B, L, C]` path (`MulAdd` - Wan's FFN gated residual - and the native norm modulation) launches 128x128 tiles, which read each row in 256-byte pieces. On Wan2.2 A14B 720p (`[1, 37800, 5120]` per rank) the kernel moved 1.16 GB in 0.29 ms in isolation and 0.35 ms inside the denoising loop: one of the slowest elementwise kernels in the block.

B300, bf16 x, fp32 gate `[1, 1, C]`, bf16 shift `[B, L, C]`:

| B, L, C | 128x128 | rows x 1024 | speedup |
|---|---|---|---|
| 1, 37800, 5120 | 0.2933 ms | 0.1851 ms | 1.58x |
| 2, 4096, 3072 | 0.0449 ms | 0.0273 ms | 1.65x |
| 1, 4608, 3072 | 0.0189 ms | 0.0183 ms | 1.04x |
| 1, 75600, 1536 | 0.1766 ms | 0.1144 ms | 1.54x |
| 2, 8192, 2560 | 0.0681 ms | 0.0435 ms | 1.56x |
| 1, 32760, 4096 | 0.2041 ms | 0.1315 ms | 1.55x |
| 1, 1000, 5120 | 0.0193 ms | 0.0180 ms | 1.07x |
| 1, 37800, 3840 | 0.2209 ms | 0.1392 ms | 1.59x |

## Modifications

`kernels/ops/diffusion/modulate/scale_shift_triton.py`: on NVIDIA GPUs the 3D path launches up to 1024 channels by `4096 / BLOCK_C` rows per program. The per-element arithmetic is unchanged, so the output is bit-identical. ROCm and XPU keep their tiles.

## Accuracy Tests

`test_modulate.py::test_scale_shift_3d_tiling_is_bit_exact`: the new tiling equals a 128x128 launch of the same kernel bitwise (C from 96 to 5120, scale constant 0 and 1), and stays within the existing tolerance of the eager formula.

## Speed Tests and Profiling

Wan2.2 T2V A14B 720p, 4xB300, CFG 2 x Ulysses 2: MulAdd 0.349 -> ~0.2 ms per block. E2E, two interleaved rounds of fresh servers, 3 requests each: 91.230 / 91.381 / 91.436 / 91.332 / 91.321 / 91.347 s (median 91.34) -> 91.283 / 91.254 / 91.268 / 91.226 / 91.220 / 91.317 s (median 91.26). The GPUs run at their power cap through the denoise, so a bandwidth-bound kernel's saving shows up at about half its length.
