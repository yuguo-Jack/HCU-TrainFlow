# [Fix] diffusion: Align Qwen-Image 2.1 resolution and handle RGBA JPEG output

[Upstream PR](https://github.com/sgl-project/sglang/pull/44275) · state: closed · merged: True

## Original PR description

## Motivation

Qwen-Image 2.1 requests with dimensions not divisible by 32 can fail validation. Saving its RGBA outputs as JPEG also raises an encoding error.

## Modifications

- Align positive request dimensions to multiples of 32, with a minimum of 32 pixels. For example, 1280x720 becomes 1280x704.
- Apply the same alignment to synthetic warmup requests.
- Composite RGBA images onto a white background before JPG/JPEG encoding, preserving PNG transparency and the original image array.
- Add regression coverage for request parsing, CLI parameters, warmup, and output saving.

## Accuracy Tests

Validated with Qwen-Image 2.1 Turbo using the native SGLang backend and Torch SDPA.

- 118 unit tests passed with no skips: 90 in `test_qwen_image21.py` and 28 in `test_output_saving.py`.
- HTTP generation verified aligned dimensions, JPEG/RGB output, PNG/RGBA output, explicit dimension overrides, and rejection of invalid dimensions.
- Synthetic warmup passed in both eager and breakable CUDA graph modes.
- BCG capture was verified, and two consecutive JPEG requests succeeded without a graph-miss warning.
- CLI `--720p` successfully saved a 1280x704 JPEG.

The complete validation script exited with code 0.

This change does not modify model forward code, denoising, or kernels. No inference speedup is claimed.
