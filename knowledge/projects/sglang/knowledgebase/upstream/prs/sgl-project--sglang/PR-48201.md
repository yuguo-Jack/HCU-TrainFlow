# [Fix] [AMD] layernorm: call vLLM fused_add_rms_norm in place

[Upstream PR](https://github.com/sgl-project/sglang/pull/48201) · state: open · merged: False

## Original PR description

## Motivation

On ROCm without aiter (`SGLANG_USE_AITER` unset) and with vLLM installed, `layernorm.py` binds `fused_add_rms_norm` from `vllm._custom_ops`. vLLM's signature is the four-argument in-place op:

```
fused_add_rms_norm(input, residual, weight, epsilon) -> None
```

`RMSNorm.forward_hip` and the vLLM branch of `GemmaRMSNorm.forward_hip` called it with the six-argument out-of-place form `(out, x, residual_out, residual, weight, eps)`. The first forward that has a residual, the second decoder layer, failed:

```
TypeError: fused_add_rms_norm() takes 4 positional arguments but 6 were given
```

This is the same bug as the closed, unmerged #32034. #46915 fixes it on `amd_march` and does not target `main`. The aiter path is unchanged: with aiter enabled, `RMSNorm` uses `forward_aiter`, and `GemmaRMSNorm.forward_hip` returns before this call.

An empty batch is sent to `forward_native`. The vLLM HIP kernels fail to launch with an empty grid (`hipErrorInvalidConfiguration`).

## Modifications

`python/sglang/srt/layers/layernorm.py`

- `RMSNorm.forward_hip`, when `residual` is not `None`:
  - Add `post_residual_addition` into `residual` when it is present.
  - Make `residual` contiguous. vLLM's kernel requires that.
  - Call `fused_add_rms_norm(x, residual, self.weight.data, self.variance_epsilon)` and return `(x, residual)`.
  - Drop the `out` and `residual_out` allocations.
  - If `x.numel() == 0`, return `forward_native` before the HIP call.
- `GemmaRMSNorm.forward_hip`, vLLM branch only (`_use_aiter` is false): the same change, using `self.gemma_weight`. The comment above that call now documents the four-argument in-place signature. The no-residual `rms_norm(out, x, weight, eps)` call is unchanged.

`test/registered/unit/layers/test_layernorm_hip_vllm.py`

- CPU test registered in `base-a-test-cpu` (`est_time=5`).
- Forces `_use_aiter=False` and `_has_vllm_rms_norm=True`, and patches `fused_add_rms_norm` with a reference that has vLLM's exact signature and in-place semantics: `residual += input`, then `input = rms_norm(residual) * weight`.
- `RMSNorm`: hidden size 64, 0 and 7 tokens, no `post_residual_addition`.
- `GemmaRMSNorm`: 0 tokens, and 7 tokens with and without `post_residual_addition`.
- Each case compares `forward_hip` to `forward_native` with `torch.testing.assert_close`. A six-argument call fails this test because the reference accepts only four arguments.

## Accuracy Tests

No full-model GPU accuracy run was done for this PR. The old six-argument call did not execute, so there is no previous kernel output to compare.

The CPU unit test above is the accuracy check. `forward_hip` must match `forward_native` for both the output and the residual. That has not been executed in the environment where this branch was prepared; `base-a-test-cpu` should run `test/registered/unit/layers/test_layernorm_hip_vllm.py`.

## Speed Tests and Profiling

No serving benchmark or profile was collected. The residual path no longer allocates `out` and `residual_out`. That should be neutral or slightly cheaper, and it does not change the aiter kernels.
