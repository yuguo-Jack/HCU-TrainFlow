# [HiCache] Preserve all MTP KV and recurrent state

[Upstream PR](https://github.com/sgl-project/sglang/pull/40223) · state: closed · merged: True

## Original PR description

## Motivation

An Inkling MTP request that reuses a HiCache prefix must recover every draft head's KV and convolution/recurrent state. The hybrid SWA/Mamba path omitted separate draft state, and its transfer schedule could leave later draft heads unrestored. Inkling also addresses draft SWA buffers with full-token IDs, while target SWA uses independently allocated physical IDs; packing both into the target SWA host pool copies the wrong draft rows.

This change supports all-SWA, mixed, and all-full MTP draft attention. A host hit restores every draft's state before the final target-layer completion event, using the indices owned by each pool.

## Modifications

- Expose Inkling's checkpoint MTP depth to packed-cache discovery and collect every separate draft convolution/temporal pool. Validate compatible state-slot ownership and avoid packing shared target state twice.
- Preserve Inkling's global MTP depth IDs during single-block runner setup, so SWA heads at depth 2 and later receive SWA pools.
- Pack full-attention draft KV into the full host pool. Pack SWA drafts that share target SWA indices into the SWA host pool. Give identity-mapped SWA drafts a separate host pool derived from full-token indices, preserving their SWA head geometry and including their memory in fixed HiCache budgets.
- Pack compatible draft convolution/temporal state, and schedule all packed KV/state restores within the target transfer range. Keep the portable per-layer NPU fallback for separate state allocations.
- Add registered CPU/GPU regressions for config setup, pool discovery, byte-exact restoration, distinct target/draft indices, mixed attention, and host-memory accounting.

No new flags. The existing MXFP8 host-cache restriction on packed MTP remains.

## Accuracy Tests

Validated on base `248c202b46d4a44ad46a3f09d48661b0d9ce6257`:

- **105 tests and 16 subtests passed**, including assembly, HiCache dispatch, layer setup, and packed-state regressions.
- **64 GPU transfer cases** on NVIDIA GB300: all-SWA/mixed/all-full drafts and legacy shared-SWA indexing, BF16/FP16 KV, kernel/direct transfers, differing full/SWA head counts, two/four target layers versus three drafts, convolution-only/convolution-plus-temporal state, and ratio/fixed host sizing. Tests clear device buffers after backup and compare every restored byte at different destination slots.
- **Four end-to-end serving cases** with generated Inkling checkpoints: `sss`, `sfs`, and `fff` draft patterns with kernel I/O, plus `sfs` with direct I/O. All restored **768 host tokens and 0 device-cache tokens** after device eviction. Each generated **32 identical tokens with zero logprob difference** versus a cold run and reported 31 speculative verification steps.
- All applicable upstream pre-commit checks passed for the full PR diff, including CI registration against the PR base.

Serving used BF16, FA4, torch GEMM, TP1, write-through HiCache, and disabled CUDA graphs. The environment had sgl-kernel 0.4.6.post1+cu130, so serving bypassed the tree's 0.4.7 minimum-version check. These are synthetic-weight correctness tests, not trained-model accuracy or acceptance-rate measurements. GPU unit tests bypass controller background threads; serving exercises the actual scheduler/controller. NPU state copying was checked with CPU tensors, not NPU hardware. External L3 storage was not exercised.
