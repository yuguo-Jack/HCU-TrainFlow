# [Fix] multimodal_gen: Fix dynamic-batching bugs - non-output-rank split, OOM memory climb

## Motivation

Two bugs in the diffusion dynamic-batching path (`multimodal_gen`):

**Bug 1 — spurious warning on every TP>1 non-output rank.** `_split_batched_output()` required `output` or `output_file_paths` to be non-`None`, but only the replica's output rank (`worker.is_output_rank`) materializes either field — every other TP/SP rank legitimately has both as `None` after a successful forward. This made every successful TP>1 dynamic batch log "Failed to split dynamic batched output cleanly" once per non-output rank, even though all requests completed and the actual client-visible reply (sent only from the output rank) was correct.

**Bug 2 — device memory climbs across consecutive OOMs.** A failed dynamic-batch forward left allocated (not just reserved) device memory climbing across consecutive OOMs, so a later request that should fit could OOM on an otherwise-idle server. `empty_cache()` only returns cached-but-unallocated memory; it cannot free tensors still referenced. The `except` block's own `logger.error(..., exc_info=True)` was the reference holder: `exc_info` captures the traceback, which keeps every frame of the failed `forward_fn()` call alive — including its tensor locals — until the cyclic GC collects it.

## Modifications

- `scheduler.py`: gate the `output is None and output_file_paths is None` check in `_split_batched_output()` on `self.worker.is_output_rank`, so non-output ranks no longer report a false split failure.
- `gpu_worker.py`: move `gc.collect()` + `empty_cache()` out of the `except` clause to run after the `finally` block, once the exception (and the traceback pinning the failed forward's tensors) has gone out of scope. Same pattern already used at worker shutdown (`gpu_worker.py` `run_scheduler_process` `finally` block).
- `test_qwen_image21.py` / `test_sensenova_u1.py`: existing `Scheduler` test stubs built via `object.__new__(Scheduler)` that exercise `_split_batched_output()` now set a `worker` stub; added `test_dynamic_batch_split_succeeds_on_non_output_rank` to cover the `is_output_rank=False` path explicitly.

Both fixes are device-agnostic: Bug 1 only touches a plain Python rank-routing bool, Bug 2 only adds `gc.collect()` (not device-specific) ahead of the pre-existing, already-generic `empty_cache()` call.

## Accuracy Tests

Not applicable — neither fix touches model math or outputs; both are scheduler/worker bookkeeping around rank routing and cache release.
