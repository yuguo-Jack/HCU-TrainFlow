# [diffusion] Fix dynamic-batching bugs: non-output-rank split, OOM memory climb

[Upstream PR](https://github.com/sgl-project/sglang/pull/43750) · state: open · merged: False

## Original PR description

Bug 1: _split_batched_output() required output or output_file_paths to be non-None, but only the replica's output rank (worker.is_output_rank) materializes either field -- every other TP/SP rank legitimately has both as None after a successful forward. This made every successful TP>1 dynamic batch log "Failed to split dynamic batched output cleanly" once per non-output rank, even though all requests completed and the actual client-visible reply (sent only from the output rank) was correct. Gated the None/None check on worker.is_output_rank.

Bug 2: a failed dynamic batch forward left allocated (not just reserved) device memory climbing across consecutive OOMs, so a later request that should fit could OOM on an otherwise-idle server. empty_cache() only returns cached-but-unallocated memory; it cannot free tensors still referenced. The except block's own logger.error(..., exc_info=True) is the reference holder: exc_info captures the traceback, which keeps every frame of the failed forward_fn() call alive -- including its tensor locals -- until the cyclic GC collects it. Added gc.collect() right before empty_cache() to drop that reference first; same pattern already used at worker shutdown (gpu_worker.py run_scheduler_process finally block).

Both fixes are device-agnostic: Bug 1 only touches a plain Python rank-routing bool, Bug 2 only adds gc.collect() (not device-specific) ahead of the pre-existing, already-generic empty_cache() call.
