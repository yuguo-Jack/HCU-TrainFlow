# [Test] [AMD] fp8-grid: Compare the GEMM to aiter within one bf16 rounding, not bitwise

[Upstream PR](https://github.com/sgl-project/sglang/pull/47054) · state: closed · merged: True

## Original PR description

## Motivation

`test_bitwise_against_aiter_and_separate_fake_quant` asserts that our fused gfx950
fp8-grid GEMM is **bit-for-bit** equal to `aiter...batched_gemm_bf16`. That holds only
while aiter's dispatch for this shape never changes. It has changed: advancing the AITER
pin past the shipped `285579b62` makes this assert fail on gfx950 across all three ROCm
flavors.

**Both kernels are correct.** Against a float64 reference using this file's own bound
(`_assert_within_bf16_of_exact`):

| | plain (SGLang) | ref (aiter) |
|---|---|---|
| within bf16 bound of float64 truth | **True** | **True** |
| max absolute error | 7.769e-03 | 7.769e-03 |
| max relative error | **8.0e-03** | 5.0e-02 |

Only **42 of 131,072** elements differ, by at most 0.0078125 — one bf16 rounding step.
fp32 addition is not associative, so a change in tile size or split-K count reassociates
the sum and moves the last bit. Both results remain equally valid.

The helper already in this file anticipated this; its docstring reads *"One bf16 rounding
... of an fp32 sum whose association **differs from aiter's**"*. It simply was not applied
to the two comparisons that go against aiter.

I think the bitwise check was opportunistic rather than required, and that
outside the determinism tests nothing needs byte-identity.

## Modifications

1. Replace the two `torch.equal(..., _aiter_reference(...))` assertions with
   `_assert_within_bf16_of_exact`, which checks against float64 truth.
2. Key the fp8-grid epilogue check to our own `plain` rather than aiter's `ref`, matching
   what the other two epilogue checks in this file already do.
3. Rename the test and update the file docstring to state the contract accurately.
4. Drop `_aiter_reference`, now unused.

**Eight `torch.equal` assertions are unchanged** — fused vs unfused, split-K vs
single-launch, tile-table equivalence, dequant round-trips. Those are determinism checks
and remain exact.
