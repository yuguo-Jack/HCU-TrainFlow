# [Fix] sgl-model-gateway: Do not abort forwarded requests on reqwest's default 30 s TCP_USER_TIMEOUT

[Upstream PR](https://github.com/sgl-project/sglang/pull/45736) · state: closed · merged: False

## Original PR description

## Motivation

The gateway's forwarding `reqwest` client sets `TCP_USER_TIMEOUT` to 30 s on Linux by default. If an engine stops reading a forwarded request body for over 30 s (e.g. busy with a burst of long prompts), the send is aborted and the router returns 500 regardless of `request_timeout_secs`. Same fix as #45696 for `sgl-router`.

## Modifications

- `sgl-model-gateway/src/app_context.rs`: disable `tcp_user_timeout` on the forwarding client on the targets where reqwest sets it. `request_timeout_secs` still bounds a request.

## Testing

End to end with a worker that reads no POST body for 40 s:

| Router build | Result |
|---|---|
| main | 500 after 30 s |
| this PR | 200 after 40 s |
