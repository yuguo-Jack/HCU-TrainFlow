# [Feat] rust: deepseek-recipe chat encoding for sglang-processor, sgl-router and sglang-server

[Upstream PR](https://github.com/sgl-project/sglang/pull/45715) · state: closed · merged: False

## Original PR description

## What

The Rust hosts' half of `--chat-encoding-backend recipe`: `rust/sglang-processor`, `sgl-router` and `rust/sglang-server` render DeepSeek-V4 / V4.1 chat prompts through deepseek-recipe 0.2.0 under the flag, matching the Python host byte for byte. The router forwards the `input_ids` it renders to the workers, so router and workers must run the same flag; the Rust server renders its own chat prompts.

**Stacked on #45315** (the Python host). Until it merges, this PR's diff also shows that PR's commits; the Rust-only change is the last commit.

## How

- **processor**: `render/models/deepseek_recipe.rs` mirrors `serving_deepseek_recipe.pre_normalize` and, because the Rust hosts get the wire body, the handler steps the Python adapter inherits (the `reasoning` fold, kwargs effort, default kwargs, tool filtering). It calls recipe's `convert`, `render_conversation` and, with the checkpoint's `tokenizer.json`, recipe's own `PromptTokenizer` (special tokens by id, plain BPE between them), since Dynamo's tokenizer backend cannot encode that way. `ChatFormatter::DeepSeekRecipe` plus `render_recipe`; `recipe` is an optional Cargo feature the hosts enable.
- **router**: `--chat-encoding-backend` and `ModelConfig.chat_encoding_backend` (hence one line in each `ModelConfig` literal); `with_recipe_backend` swaps only the DeepSeek-V4 family's formatter and requires `tokenizer.json`, failing startup without it; `encode` returns recipe's ids.
- **server**: `ServerArgs.chat_encoding_backend` via the Python handoff; `load_recipe_formatter` reads the model's `config.json` (other models keep their template, an unreadable config disables chat); the `Recipe` template variant renders text for the server's one-pass encoding.
- **cargo-deny**: BSL-1.0 (xxhash-rust) and MIT-0 (borrow-or-share) from recipe's dependency tree.

Two deliberate differences from the API, listed in `sgl-router/REFERENCE.md`: `tool_choice: required` and a named tool render as `auto` (the workers enforce the choice with their grammar), and the server host applies no recipe sampling defaults.

## Tests

- `tests/fixtures/parity/deepseek-v4.1-flash-1017-recipe.json`: 211 cases generated by `generate_parity.py` through `OpenAIServingChat` with the recipe adapter (`chat_encoding_backend: "recipe"` in the fixture header); `tests/parity.rs` checks prompt text and, with the tokenizer cached, token ids, under the `recipe` feature. The processor CI feature matrix runs `recipe` and `recipe,tokenizer`.
- Unit tests in `deepseek_recipe.rs`, the router's `chat_formatter.rs` and the server's template tests.
