# [Perf] dsv4: dequantize several KV tokens per program in the V4.1 paged dequant

[Upstream PR](https://github.com/sgl-project/sglang/pull/48243) · state: closed · merged: True

## Original PR description

## Motivation

`dequantize_k_cache_paged_v41` (the DeepSeek-V4.1 paged KV dequant used before sparse prefill) launches one 128-thread program per token. On SMs that hold 16 resident blocks and 1024 threads (CC 10.7 / sm_107), the programs are too small to keep enough loads in flight, and the kernel reaches a small fraction of HBM bandwidth. The fp4 kernel also writes each token's 512 bf16 values with two stride-2 stores.

## Modifications

- `_dequantize_k_cache_paged_v41_fp8_kernel` and `_dequantize_k_cache_paged_v41_fp4_kernel` take `num_tokens` and a `TOKENS_PER_PROGRAM` constexpr. Each program dequantizes that many tokens as a `[TOKENS_PER_PROGRAM, 512]` tile and masks the tail.
- The fp4 kernel interleaves the low and high nibbles with `tl.interleave` and writes each token with one contiguous store.
- Every backend launches 8 tokens per program with 2 warps. Only CUDA was measured; on gfx950 the same launch is untested (the dequant test is CUDA-only).

The math per element is unchanged, so outputs are bitwise identical.

## Accuracy Tests

On sm_107 (CC 10.7), at this PR's head:

- `test/registered/kernels/ops/attention/test_dsv4_dequant_k_cache.py`: 3 passed (5 subtests).
- This PR's kernels against main's, bitwise, on random caches with finite scales: V41, V41_NEW, V41_FP4 and V41_FP4_NEW, page size 64 and 256, 1 / 7 / 9 / 16,896 / 262,144 tokens (the small counts exercise the masked tail). All identical.

## Benchmarking and Profiling

sm_107 (CC 10.7), one GPU, kineto median of 20 calls, time relative to main:

| layout | tokens | this PR vs main |
|---|---|---|
| V41 (fp8) | 16,896 | -62% |
| V41 (fp8) | 262,144 | -80% |
| V41_FP4 | 16,896 | -37% |
| V41_FP4 | 262,144 | -69% |

In a DeepSeek-V4.1 prefill step at 16K new tokens per rank, these kernels are about 0.9% of the summed kernel time. The saving depends on how many tokens each call dequantizes. No end-to-end run is claimed.
