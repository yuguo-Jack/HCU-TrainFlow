# [Feat] diffusion: Support dynamic LoRA on GGUF transformers

[Upstream PR](https://github.com/sgl-project/sglang/pull/48159) · state: open · merged: False

## Original PR description

## Motivation

GGUF transformer loading rejects startup LoRA, and runtime LoRA wrapping assumes every base layer has a dense `weight`. This prevents MiniMax-H3 users from combining the GGUF capacity path with a style adapter.

Related to #43313.

## Modifications

- Allow actual diffusion GGUF linears to use the existing dynamic LoRA delta at TP=1. Keep the packed parameter and its offload identity; do not snapshot or materialize a dense base for LoRA.
- Let `auto` select dynamic mode, and reject explicit merging and TP>1 before conversion. Unknown packed formats remain unsupported; the existing one-adapter-per-target restriction remains.
- Cover numerical scaling/bias, packed storage preservation, adapter replacement and disable/reactivation, startup guards, and real layerwise offload with an adapter installed before or after manager initialization.
- Reject full-width AdaLN adapters before installation when a pruned H3 GGUF lacks projection metadata; a failed replacement keeps the active adapter intact.
- Update the H3 cookbook and GGUF constraints.

## Accuracy Tests

182 tests plus 5 subtests passed on H200. Real H3 generation covered startup LoRA, FFN/AdaLN adapters, pruned GGUF, and compile mode; the tested adapter lifecycle transitions restored video/audio latents and MP4 bit-for-bit.

Compile mode has graph breaks and mixes compiled/eager regions; it is **not full-graph compilation** and its output differs from eager. No eager-equivalence or compile-speedup claim is made. These are compatibility/lifecycle checks with one prompt and the listed adapters, not a general perceptual-quality benchmark or coverage of every GGUF variant.

<details>
<summary>Full H3 generation: baseline → LoRA enabled → disabled</summary>

Full H3 validation used one H200, the FL2VA `Q4_K_M` transformer, FA/eager execution, and layerwise offload for DiT and the text encoder. After a two-step warmup, baseline → LoRA enabled → LoRA disabled each ran **50 steps**, seed 1101, 1344×768, 124 frames (5.1667 s), with audio. The adapter was `fal/MiniMax-H3-Realism-People-LoRA/h3-realism-people-t2v-i2v-r2v.safetensors`, strength 0.7, applied to 104 layers.

- Enabling LoRA changed video output and audio latents.
- Disabling it restored the audio latents, raw waveform, all decoded video/audio samples, and final MP4 **bit-for-bit**.
- An earlier run with a cold baseline had a tiny audio difference (max 1.59e-5). A warmed baseline taken **before any LoRA was loaded** exactly matched that run's restored audio. The final run added capture-only probes before encoding to check latent and waveform equality; the LoRA implementation was unchanged.

</details>

<details>
<summary>Extended validation: startup, FFN/AdaLN, pruned GGUF, and compile mode</summary>

Additional real H3 validation used the same H200, prompt, seed, output dimensions, audio, and offload settings:

| GGUF / adapter | Execution | Result |
| --- | --- | --- |
| Full Q4_K_M / Larry Turbo v4 EMA, strength 1.0 | Startup `--lora-path`, 8 steps, eager | 259 modules: 104 attention, 104 FFN, 51 AdaLN. Disable/reactivate changes then exactly restores video/audio latents and MP4. |
| Full Q4_K_M / Larry Turbo v4 EMA, strength 1.0 | Startup `--lora-path`, 8 steps, `torch.compile` enabled | Actual compilation: 53 graphs and 1,490 generated kernels, with LoRA projection shapes in autotuning logs. Same-mode disable/reactivate exactly restores latents and MP4. |
| Unsloth pruned Q4_K / Realism People, strength 0.7 | Startup `--lora-path`, 50 steps, eager | 104 attention modules. Disable/reactivate exactly restores video/audio latents and MP4. |

The pruned test exposed an admission bug: loading a full-width Larry AdaLN adapter returned success despite input width 2688 versus the pruned model's 8. The regression fails on the pre-fix method. With the fix, replacing the active adapter under the **same nickname** is rejected before mutation; a subsequent full 50-step generation exactly matches the previous video/audio latents and MP4. Valid-adapter output also matches the pre-fix run.

</details>
