# [Perf] [AMD] GLM-5.3-Flash: Fewer DSA k-pool indexer launches in MTP verify

[Upstream PR](https://github.com/sgl-project/sglang/pull/44417) · state: open · merged: False

## Original PR description

## Summary

At concurrency 1 on MI355X, the DSA k-pool indexer in GLM-5.3-Flash's 11 sparse-attention layers costs more in small launches than in math: three GEMMs on one input with casts around them, and per-layer metadata rebuilt by index / arange / copy kernels that CUDA already fuses. This PR:

1. Stacks `wk`, the compress gate and `weights_proj` at load time; target verify projects once with an fp32-output `torch.mm`.
2. Enables CUDA's KPool metadata fusion, sibling replay copy and pooled page table on HIP.
3. Unrolls `kpool_topk_transform` row loads ×4 on ROCm.


| Kernel group, per decode step (profiler on) | Base (µs) | This PR (µs) |
| --- | --- | --- |
| Indexer GEMMs: `wk`, compress gate, `weights_proj` | 339.4 | **109.9** |
| Casts around them (`_to_copy`, bf16 ↔ fp32 copies, head-gate scale) | 225.2 | **74.0** |
| Metadata: `index`, `arange`, int elementwise, DtoD copies, `rocprim` | 642.2 | **218.0** |
| `kpool_topk_transform_kernel` | 280.4 | **256.3** |
| k_norm LayerNorm | 50.6 | 51.1 |

## Scope

HIP only; CUDA keeps today's paths. (1) is gfx950 only, for NoPE indexers whose `weights_proj` is bf16-exact; `post_load_weights` refreshes the stack in place after every load. (2) reuses the metadata paths CUDA already runs; the fused replay copy covers every DSA model on HIP, the rest is k-pool only; the pooled page table on HIP is built for target verify only, since draft decode skips the indexer. (3) is `#ifdef USE_ROCM`; CUDA keeps one load per step. The KDA `cache_indices >= 0` mask deferral is left to #43861.
