# [Fix] modelopt-nvfp4: Resolve the automatic MoE runner once so the weight prep matches the kernel path

[Upstream PR](https://github.com/sgl-project/sglang/pull/48107) · state: open · merged: False

## Original PR description

## Motivation

Fixes #48108.

With the default `--moe-runner-backend auto` on Blackwell, `ModelOptNvFp4FusedMoEMethod` prepared its weights for a non-TRT-LLM runner while dispatching to the TRT-LLM kernel: `__init__` derived `enable_flashinfer_trtllm_moe` / `use_flashinfer_trtllm_weight_layout` from the live global (still `auto`), whereas `create_moe_runner` resolved `auto` to `FLASHINFER_TRTLLM` and cached it for `apply`. The layer never got `g1_scale_c`, and the first forward raised `AttributeError: 'FusedMoE' object has no attribute 'g1_scale_c'`. Reproduced with `thinkingmachines/Inkling-Small-NVFP4` at TP2 on B300 and B200 with v0.5.22 defaults (see the issue).


Related: #41765 and #45520 handle the same symptom on SM110/SM120 by routing `auto` in `arg_groups/overrides.py`; this change makes `ModelOptNvFp4FusedMoEMethod` self-consistent so the crash cannot recur on an unrouted SKU or architecture. Happy to switch to, or add, an arg-level SM100/SM103 rule if that is the preferred shape.

## Modifications

- `ModelOptNvFp4FusedMoEMethod.__init__` resolves `auto` once (`_resolve_moe_runner_backend`, the rule `create_moe_runner` used: Marlin on SM80–SM99, FlashInfer TRT-LLM otherwise), caches it in `_moe_runner_backend`, and derives both flags from the resolved backend, so `create_weights`, `process_weights_after_loading` and `apply` agree.
- `create_moe_runner` reuses the same resolution.
- Explicit backends and the Marlin fallback behave as before.

## Accuracy Tests

No kernel or numerics change: under `auto` on Blackwell the layer now takes exactly the path an explicit `--moe-runner-backend flashinfer_trtllm` already takes.

## Speed Tests and Profiling

Not applicable (startup-path fix).

## Tests

- New `test/registered/unit/layers/quantization/test_modelopt_nvfp4_moe_auto_backend.py` (CPU): `auto` on SM100/SM103 → TRT-LLM flags and cached runner agree; `auto` on SM90 → Marlin with flags off; explicit backends kept.
- Existing `test_modelopt_nvfp4_moe_dispatch.py` and `test_modelopt_nvfp4_moe_scales.py` pass.
