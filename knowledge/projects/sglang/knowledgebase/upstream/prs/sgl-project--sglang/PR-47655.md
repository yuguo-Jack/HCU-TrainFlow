# [Fix] [AMD] utils: Cap integrated-device available memory by the device total

[Upstream PR](https://github.com/sgl-project/sglang/pull/47655) · state: open · merged: False

## Original PR description

## Motivation

On integrated/unified-memory devices `get_available_gpu_memory()` reports
`psutil.virtual_memory().available` instead of the device pool, because
`torch.cuda.mem_get_info()` on those devices excludes reclaimable cache.
That value is not bounded by the device capacity: an APU whose GTT cap is
below the host RAM reports more available memory than the device can hold.

Measured on Ryzen AI MAX 395 (Radeon 8060S, gfx1151, ROCm 7.2.4):

| quantity | value |
|---|---|
| `props.total_memory` | 108.0 GiB |
| `psutil.virtual_memory().available` | 122.08 GiB |
| `get_available_gpu_memory("cuda", 0)` | **122.08 GiB** |

The value feeds `pre_model_load_memory` and therefore the KV budget in
`_profile_available_bytes` (`rest ~= mem_fraction_static * pre - weights`).
`mem_fraction_static` is derived from the device capacity (108 GiB) while
`pre` comes from host availability (122 GiB), so the budget is inflated by
`mem_fraction_static * 14 GiB` and the pool request exceeds the device.

Reproduced with `sglang.launch_server` on Qwen3-0.6B with
`--mem-fraction-static 0.95 --attention-backend triton`
(decode/prefill CUDA graph disabled). Unpatched: the KV pool allocation dies
in `memory_pool.py` with
`HIP out of memory. Tried to allocate 2.00 GiB. GPU 0 has a total capacity of
108.00 GiB of which 118.98 MiB is free. Of the allocated memory 107.58 GiB is
allocated by PyTorch`. The budget only stays inside the pool for the default
`mem_fraction_static` because of the slack; it breaks for
`mem_fraction_static >= capacity / host_available` (~0.885 here).

## Modifications

- Bound the integrated CUDA and MUSA branches by `props.total_memory`:
  `min(psutil.virtual_memory().available, props.total_memory)`.
- Keep the host-available metric (the reason it is used at all: `mem_get_info`
  excludes reclaimable cache and would under-report on Jetson-class devices),
  and only add the missing upper bound. When host availability is below the
  device total the returned value is unchanged.
- Cross-checked against the existing MPS precedent in the same function,
  which already bounds by `min(psutil.available, metal_headroom)`.
- Add hardware-free unit tests in `test/registered/unit/utils/test_common.py`
  covering host > total, host < total, and the discrete-device branch.

## Accuracy Tests

Not applicable: the change only affects pool sizing, not model math.

## Speed Tests and Profiling

No speed impact. Same launch config as above with the patch applied:

```
KV Cache is allocated. #tokens: 960570, K size: 51.30 GB, V size: 51.30 GB
Memory pool end. avail mem=14.59 GB
The server is fired up and ready to roll!
```

51.30 + 51.30 = 102.6 GiB = 108 GiB * 0.95, i.e. the budget is now derived
from the device capacity as intended, and the server starts instead of OOMing.
On the probe, `get_available_gpu_memory` returns 108.0 GiB instead of 122.08 GiB.
