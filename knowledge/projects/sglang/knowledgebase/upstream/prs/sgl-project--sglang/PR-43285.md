# [Test] Do not hang scripted-runtime teardown when the server died

[Upstream PR](https://github.com/sgl-project/sglang/pull/43285) · state: closed · merged: True

## Original PR description

## Motivation

When the scripted-runtime server dies in the middle of a test, the test run hangs instead of failing.

- `execute_script` sees that the process died and raises `RuntimeError("server process died before responding ...")`.
- `ScriptedTestCase.tearDownClass` then calls `ScriptedHttpServer.shutdown`, which sends `Shutdown` on the PAIR socket to the scheduler hook.
- A ZMQ PAIR send blocks while no peer is connected. The peer died with the server, so the send never returns and the run waits for an external timeout.

Reproduced on `main` by running `TestScriptedSwaChunkedReqEarlyReturn` with `enable_mixed_chunk=True`. The scheduler dies with a KV OOM in `alloc_for_decode`, and `py-spy` shows the test process stuck in `zmq.Socket.send` <- `sock_send` <- `ScriptedHttpServer.shutdown` <- `tearDownClass`.

## Modifications

- `ScriptedHttpServer.shutdown`: send `Shutdown` with `zmq.NOBLOCK`. When the peer is gone, the send raises `zmq.Again`, which the existing `zmq.ZMQError` handler already ignores. Shutdown then joins and terminates the process and reports the out-of-band error as before. With a live peer the send is queued as before, since the socket's `SNDHWM` is 0.

## Checks

- Same repro on H200 with this branch: the test fails with the server-died error after 226 s and the run exits (exit code 1). On `main` it was still blocked in `shutdown` until it was killed.
