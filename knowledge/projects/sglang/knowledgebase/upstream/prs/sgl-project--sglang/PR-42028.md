# [Bugfix] Preserve PD bootstrap fields in Rust OpenAI endpoints

[Upstream PR](https://github.com/sgl-project/sglang/pull/42028) · state: closed · merged: False

## Original PR description

## Motivation

The Rust OpenAI endpoints drop PD bootstrap fields because the standard OpenAI request types do not include them. The scheduler then loses the metadata needed to connect prefill and decode. Fixes #39412.

## Changes

Keep `bootstrap_host`, `bootstrap_port`, and `bootstrap_room` in both chat and text completions. Preserve scalar and per prompt values, nullable ports, and full width room IDs. Scalar rooms expand in the same order as Python for parallel choices. Invalid list lengths are rejected before any request is submitted.

The updated branch keeps the current HTTP and core layout, the `GenerateRequest` type, and the reasoning code in `sglang_processor`. The bootstrap helper now lives in `api_server/http/openai/routing.rs`.

## Tests

The tests use the real Axum routes and inspect the scheduler intake queue. They cover chat, text and token prompts, streaming, parallel choices, and invalid metadata.

Restoring the current main handlers makes all five new regressions fail, while the eight existing bootstrap tests pass. With the fix, all 54 current OpenAI tests and all 13 bootstrap tests pass.

Strict server library and test Clippy, matching precommit hooks, and formatting pass. The Rust hooks also check the whole workspace, optional multimodal features, and radix tree.

Checks ran on macOS ARM64 with Rust 1.92. No GPU PD integration or complete server test suite was run for this update. AI assistance was used for implementation and validation.
