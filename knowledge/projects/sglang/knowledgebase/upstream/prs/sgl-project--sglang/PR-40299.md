# [Fix] Enforce API key auth for WebSocket routes

[Upstream PR](https://github.com/sgl-project/sglang/pull/40299) · state: open · merged: False

## Original PR description

## Motivation

The API-key middleware currently forwards every non-HTTP ASGI scope before evaluating credentials. SGLang exposes `/v1/realtime` as a WebSocket route, so a client with no credential or an invalid credential can complete the handshake and reach the realtime handler even when `--api-key` is configured.

This conflicts with the existing normal-route policy in `decide_request_auth`, where configuring `api_key` protects all normal endpoints. The equivalent HTTP route correctly rejects the same missing or invalid credentials.

### Reproduction

This model-free reproducer uses SGLang's middleware and the same WebSocket route shape as `/v1/realtime`:

```python
from fastapi import FastAPI, WebSocket
import uvicorn

from sglang.srt.utils.auth import add_api_key_middleware

app = FastAPI()


@app.get("/v1/protected")
async def protected():
    return {"status": "authorized"}


@app.websocket("/v1/realtime")
async def realtime(websocket: WebSocket):
    await websocket.accept()
    await websocket.send_text("REALTIME_HANDLER_REACHED")
    await websocket.close()


add_api_key_middleware(app, api_key="secret", admin_api_key=None)
uvicorn.run(app, host="127.0.0.1", port=8000)
```

With the parent commit, the HTTP control is rejected:

```bash
curl -i http://127.0.0.1:8000/v1/protected
```

```text
HTTP/1.1 401 Unauthorized
{"error":"Unauthorized"}
```

The WebSocket request reaches the handler without an API key:

```python
from websockets.sync.client import connect

with connect("ws://127.0.0.1:8000/v1/realtime") as websocket:
    print(websocket.recv())
```

```text
REALTIME_HANDLER_REACHED
```

On current `main` commit `6e1338dd1eb1546518bdffe3b69d2ea0e011ef28`, the missing-key and invalid-key cases reached the handler in three fresh loopback server processes. The valid key also connected, and the HTTP controls returned 401, 401, and 200 as expected.

After this change, missing and invalid WebSocket credentials are rejected during the handshake with HTTP 403. A valid `Authorization: Bearer secret` header still completes the handshake and reaches the handler. This was repeated in three fresh server processes; every post-test health request returned 200 and every process remained alive.

## Modifications

- Apply the existing route matching and auth decision logic to HTTP and WebSocket scopes.
- Read the WebSocket authorization header directly from the ASGI scope.
- Reject unauthorized WebSocket handshakes with policy-violation close code 1008.
- Add unit coverage for missing, invalid, and valid WebSocket credentials.

Runtime confirmation that this is still exploitable in the latest release, in case it helps this get merged:

Verified on **sglang 0.5.21 from PyPI** (2026-10-02 release) with `--api-key REALTIME-KEY-123 --tokenizer-worker-num 1` (single-tokenizer so the middleware is installed and HTTP is guarded — isolating the bypass to the websocket scope):

- **Attack**: an unauthenticated WebSocket client connecting to `ws://…/v1/realtime` completes the **101 Switching Protocols** handshake, sends a `session.update` frame, and receives an application-layer response frame on the unauthenticated connection (verified both with a websocket client library and with a raw socket HTTP Upgrade request carrying no Authorization header).
- **Controls on the same instance**: unauthenticated `GET /v1/models` and `POST /generate` both return **401**; a Bearer-authenticated websocket connection behaves identically to the unauthenticated one — the endpoint is functional, only the credential check is missing.
- 10/10 assertions passed (exit 0). The installed middleware still reads `if scope["type"] != "http": await self.app(...)` (auth.py:175 in the installed package), matching this PR's motivation.
