# [Fix] model_config: Surface the derived context_length when --context-length is unset

[Upstream PR](https://github.com/sgl-project/sglang/pull/45623) · state: open · merged: False

## Original PR description

## Motivation

When `--context-length` is **not** passed (the default for most users), SGLang silently adopts a context length derived from the model's HF config, with **no log line at all**.

In `_derive_context_length()`:

- If the user **does** pass `--context-length`, SGLang warns — and even raises `ValueError` — when it exceeds the derived value. Well protected.
- If the user **does not** pass it (the default path), `self.context_len = derived_context_len` is assigned with **zero diagnostics**.

The derived value comes from `get_context_length()`, which walks `CONTEXT_LENGTH_KEYS` and, **if none exist, hard-codes `return 2048`** — also silently.

Two silent failure modes result:

1. **Field too small** — fine-tuned models frequently ship a `max_position_embeddings` far below what they actually support (e.g. `4096` while the model really handles `25480`). Long inputs are truncated with no warning, and the user reads it as "the model can't do long context".
2. **Field absent entirely** — `get_context_length()` falls back to a hard-coded **2048**, with no indication the value is a fallback rather than a real capability.

Notably SGLang already documents that the derived value is unreliable — the existing warning says *"the derived context_length may differ from max_position_embeddings in the model's config"* — but that caveat is only surfaced on the **already-safe** path.

Closes #45622

## Modifications

Add diagnostics in the `else` branch of `_derive_context_length()` (`python/sglang/srt/configs/model_config.py`), where `logger` is already available:

- **No context-length field present** → `logger.warning`: none of the fields was found, `context_length` falls back to the built-in default, prompt the user to pass `--context-length`.
- **Value derived from a config field** → `logger.info`: report the value and warn that an inaccurate config (common for fine-tuned models) can truncate long inputs.

Design notes:

- **No signature change** to `get_context_length()`. `CONTEXT_LENGTH_KEYS` is already re-exported via `sglang.srt.utils.hf_transformers.__all__`, so it is imported from the same module that already provides `get_context_length` — no new export is introduced.
- The **explicit-value path is untouched** (still warns / raises as before), which the new test asserts by checking no extra log is emitted there.
- Pure config-derivation + logging: **no GPU, no model loading**.

## Testing

New CPU-only unit tests in `test/srt/test_model_config_context_length.py`:

1. No context-length field → `context_len == 2048` and a **warning** naming the fallback and `--context-length`.
2. `max_position_embeddings=4096` → `context_len == 4096` and an **info** line reporting it.
3. Explicit `--context-length=1024` → `context_len == 1024` with **no** new log output (existing behaviour preserved).

All three drive the config logic directly, so they run without a GPU or model download.
