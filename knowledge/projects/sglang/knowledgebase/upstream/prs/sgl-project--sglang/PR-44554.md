## Motivation

<!-- Describe the purpose and goals of this pull request. -->
This **PR depends on** https://github.com/sgl-project/sglang/pull/44530 

On the Muse Spark NVFP4 MoE path with a static activation scale (no per-token activation scaling), the pre-expert RMSNorm and the NVFP4 quantization of its output run as two separate kernels, writing and re-reading the normalized bf16 activations in between.
The existing fused RMSNorm + NVFP4 kernel only covers the per-token-scale path.

## Modifications

<!-- Detail the changes made in this pull request. -->
- `kernels/jit/csrc/muse_spark_v12/norm_fp4_quant.cuh`: add a static-scale mode to the fused RMSNorm + NVFP4 quantization kernel, using a single fp32 global scale; the quantization matches FlashInfer's CUDA `fp4_quantize`.
- `kernels/ops/muse_spark_v12/norm_fp4_quant.py`: expose it as `fused_norm_fp4_quant_static(x, weight, eps, global_scale) -> (fp4, sf)`.
- `layers/muse_spark_fp4_moe.py`: on the static-scale path, replace the separate pre-expert norm and quantization with the fused op.
