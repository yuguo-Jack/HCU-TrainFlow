## Motivation

<!-- Describe the purpose and goals of this pull request. -->
On the Muse Spark NVFP4 MoE path with a static activation scale (no per-token activation scaling), the pre-expert RMSNorm and the NVFP4 quantization of its output run as two separate kernels, writing and re-reading the normalized bf16 activations in between.
The existing fused RMSNorm + NVFP4 kernel only covers the per-token-scale path.

Rebased onto `main` .

## Modifications

<!-- Detail the changes made in this pull request. -->
- `kernels/jit/csrc/muse_spark/norm_fp4_quant.cuh`: add a static-scale mode to the fused RMSNorm + NVFP4 quantization kernel, using a single fp32 global scale; the quantization matches FlashInfer's CUDA `fp4_quantize`.
- `kernels/ops/layernorm/muse_spark_rmsnorm_nvfp4_quant.py`: expose it as `fused_norm_fp4_quant_static(x, weight, eps, global_scale) -> (fp4, sf)`.
- `layers/muse_spark/muse_spark_fp4_moe.py`: on the static-scale path, replace the separate pre-expert norm and quantization with the fused op.

## Accuracy Tests

<!-- If this pull request affects model outputs (e.g., changes to the kernel or model forward code), provide accuracy test results. -->

Muse Spark Open NVFP4, aggregated TP4/EP4 on 4x GB300 (cookbook GB300 NVFP4 flags, no speculative decoding). Base is upstream `main` `693d333306`; this PR is the same tree plus this change.

Both servers run with:
- `SGLANG_FLASHINFER_NVFP4_PER_TOKEN_ACTIVATION=0` set explicitly, so the MoE input uses the static activation scale, which is the path this PR fuses. The Muse Spark hook turns per-token activation on when the variable is unset.
- `--disable-flashinfer-autotune`, so both sides run identical fixed MoE GEMM tactics.

sgl-eval, xhigh reasoning, T=1.0 / top_p=1.0 / top_k=64:

| | Base | This PR |
|---|---|---|
| GSM8K (64K max tokens) | 97.73% | 97.73% |
| AIME26 x16 (128K max tokens), pass@1 ± SEM | 96.25 ± 0.85% | 96.25 ± 0.60% |
| AIME26 x16, pass@16 | 100% | 100% |
