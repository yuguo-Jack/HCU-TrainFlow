# [NPU] Fix double Mamba ping-pong flip after spec verify

[Upstream PR](https://github.com/sgl-project/sglang/pull/32852) · state: closed · merged: False

## Original PR description

## Motivation

This PR is stacked on and depends on #30451.

#30451 flips `req.mamba_next_track_idx` immediately after committing the
accepted Mamba state in speculative verify. This early flip is required before
overlap can launch the next verify. However, `_mamba_prefix_cache_update`
currently flips the same index again when the result reaches the scheduler.
The two flips restore the original slot, so the next verify can overwrite the
checkpoint that was just committed.

## Modifications

- Keep the scheduler-side ping-pong flip for non-speculative decode.
- Skip that second flip for speculative decode, which already flipped during
  the Mamba state commit.
- Add CPU regression tests for both speculative and non-speculative boundary
  handling.

## Accuracy Tests

The existing Qwen3.6-27B NPU GPQA experiment with #30451, #31659, and this fix
completed five independent TP2 runs with scores:

`0.8687, 0.8586, 0.8636, 0.8788, 0.8737` (mean: `0.8687`).
