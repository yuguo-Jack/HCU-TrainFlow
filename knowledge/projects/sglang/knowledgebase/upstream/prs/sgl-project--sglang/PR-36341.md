# [Test] hicache: cover buffer-only L3 restores across hybrid caches

[Upstream PR](https://github.com/sgl-project/sglang/pull/36341) · state: open · merged: False

## Original PR description

## Motivation

Buffer-only HiCache needs KL guards that prove a storage restore occurred. Device-pool pressure and a nonzero cached-token count can pass using only a resident shared prefix, and files written to L3 prove backup rather than load-back.

Main now supports FULL+SWA+Mamba buffer-only mode through #36345 and already includes a hybrid prefill-from-storage KL test. This PR adds standalone FULL/FULL+SWA coverage and extends that existing hybrid class to restore decode checkpoints across branches.

## Modifications

- Add Qwen3-32B (FULL, KL < 0.0025) and gpt-oss-20b (FULL+SWA, KL < 0.03) buffer-only classes using a temporary file backend. Keep the multi-turn branching tests and FULL GSM8K gate; SWA GSM8K remains skipped because the small device pool is sized for storage pressure.
- For each model, seed a 2048-token prefix, flush the device tree while draining storage writes, then require a 1984–2048-token hit before comparing generated logprobs against recomputation. Both classes explicitly use 64-token pages. This makes storage restore a required condition rather than relying on incidental eviction.
- Extend `TestUnifiedHybridBufferOnlyBitExact` with two groups of two shared-prefix branches. Generate 640 tokens, drain writes and flush, then restore for the next turn. Require checkpoint-aligned hits beyond the original 768-token prompt, and compare the subsequent 640-token generation against recomputation with the existing 1e-9 KL threshold.
- Isolate new test prefixes from other cases because L3 entries survive device-cache flushes. Assert output and logprob lengths before KL comparison.
- Synchronize with main, update the CUDA graph flag and process cleanup, and remove obsolete claims that Mamba is unsupported or that buffer-only has no other KL coverage.
- Move reusable hybrid implementations into non-TestCase mixins and group the CI entrypoints into device-cache strategies, HiCache, and MTP, retaining Python/Rust coverage without duplicate collection. Move FULL/FULL+SWA buffer-only coverage from base to extra.

These tests do not deterministically reproduce the ownership race fixed by #35769. The hybrid extension uses the existing Python TreeCore/extra_buffer configuration; it does not add Rust or lazy-strategy coverage.

When storage writes succeed but the buffer-only prefetch/read path is broken or disabled, evicted requests can fall back to the always-resident 512-token prefix, and this lower bound explicitly accepts that result. The subsequent KL replay also succeeds because the missing suffix is recomputed, so all three helpers can remain green without consuming any data from the file backend—the behavior this module is intended to guard. Track an aggregate storage-read/load-back signal, or require at least one request to restore more than the warm prefix.
