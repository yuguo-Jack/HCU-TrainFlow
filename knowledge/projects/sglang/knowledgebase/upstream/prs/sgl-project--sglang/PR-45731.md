# [Fix] hicache: Size the MLA draft host sidecar in physical rows under DCP

[Upstream PR](https://github.com/sgl-project/sglang/pull/45731) · state: open · merged: False

## Original PR description

## Motivation

Split out of #43599 (asked to be split so HiCache is reviewed on its own). This PR is a single commit on main and can be reviewed and merged independently.

Under DCP a sharded MLA draft (the EAGLE3 MLA draft for Kimi-K3 in #43599) keeps each token's KV at owner row `loc // dcp_size`. The draft's HiCache host copy was built without that rule, so on a DCP + HiCache deployment:

1. **Restores from the host tier land in the wrong rows.** When a prefix is evicted to host and later restored to the GPU, the draft's KV is written back at the undivided `loc`. The draft then reads other tokens' KV while guessing. The output text is still correct, because the target model checks every draft token, but fewer draft tokens are accepted per step: accept length 2.06 -> 1.45.
2. **The host sidecar is 8x too big.** It is sized for the target's full logical token count; on TP8/DCP8 with `--hicache-size 100` that is 27.84 GB of host memory per rank, 7/8 of which can never be written.

## Modifications

- `KVCache.rows_are_dcp_collapsed` (default `False`; `MLATokenToKVPool` returns `dcp_enabled and not dcp_replicated`) names the owner-row layout. #43599 adds the same property for its PD transfer path; whichever lands second drops the duplicate.
- `build_full_draft_pools`: when the draft pool's `rows_are_dcp_collapsed`, build its host sidecar with `dcp_size` / `dcp_rank` and a physical/physical `host_to_device_ratio`, so it translates at the transfer boundary like the target's. Replicated drafts (DSpark, MHA) keep the logical-size sidecar.
- `_build_mha_mla_host_pool` forwards `dcp_size` / `dcp_rank` to the host pool.
- `resolve_hicache_dcp_compatibility` admits EAGLE3 next to DSPARK.
- `test_hybrid_pool_assembler.py`: the sidecar-dispatch fixture declares `rows_are_dcp_collapsed=False`.

## Accuracy Tests

Setup (measured together with #43599, which makes the EAGLE3 MLA draft run under DCP): Kimi-K3 + [lightseekorg/kimi-k3-eagle3.1-mla](https://huggingface.co/lightseekorg/kimi-k3-eagle3.1-mla) on GB300, TP8 / DCP8, HiCache `--hicache-size 100`, EAGLE3 steps 3 / topk 1 / draft tokens 4.

Host sidecar size (per rank, DCP8):

| pool | before | after | change |
|---|---|---|---|
| draft host sidecar | 24,162,816 tokens / 27.84 GB | 3,020,352 tokens / 3.48 GB | 8x smaller, 24 GB host freed per rank |
| target host KV | 3,020,288 tokens / 83.50 GB | same | - |

Does the draft still work after a prefix comes back from the host tier? Same 15k-token document, first served cold, then again with its prefix still on the GPU ("device"), then pushed out to host by 69 other 17.6k prompts (1.2M tokens) and requested again so it is restored from host ("host", 14,848 cached tokens, `cache_source=host` in the metrics):

| | cold accept_length | device recall | host recall |
|---|---|---|---|
| after | 3.08 | 3.00 | **3.00** (same number of verify steps) |
| before (previous base, same kind of probe) | - | 2.06 | **1.45** |

The "before" numbers are from the previous base: on the current base the HiCache + DCP gate rejects EAGLE3 without this change, so "before" cannot boot there. The point is the last column: before, a host restore cost a third of the accept length; after, host recall equals device recall.

DSpark (MHA draft) regression check: draft host sidecar unchanged (55.32 GB per rank).

## Speed Tests and Profiling

No kernel changes. Frees about 24 GB of host memory per rank under DCP8.
