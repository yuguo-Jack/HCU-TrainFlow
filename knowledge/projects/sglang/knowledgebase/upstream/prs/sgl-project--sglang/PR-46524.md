# [Fix] attention: Register the MSA-v1 Q8KV4 kill switch in the env registry

[Upstream PR](https://github.com/sgl-project/sglang/pull/46524) · state: closed · merged: False

## Original PR description

## Motivation

#46141 added the MSA-v1 Q8KV4 decode path with a kill switch, but `SGLANG_DISABLE_MSA_V1_Q8KV4` never got registered in `sglang/srt/environ.py`. `Envs` has no `__getattr__`, so the read in `msa_v1_qmul4_decode_capability` raises:

```
AttributeError: 'Envs' object has no attribute 'SGLANG_DISABLE_MSA_V1_Q8KV4'
```

The probe runs inside `MiniMaxSparseNvfp4AttnBackend.__init__`, and the registry auto-selects that backend for MiniMax sparse models on the M3 NVFP4 native stack, no special flag. Serving MiniMax-M3.1 NVFP4 dies at backend construction, before the FP8 fallback the kill switch is supposed to force can even be picked.

The existing unit test constructs the backend with `__new__` and never runs `__init__`, which is why this did not show up in review.

## Modifications

Register the field next to `SGLANG_DISABLE_MSA`, default False, same shape as the sibling kill switches.

Also a test in `test_environ.py` that walks the sources, collects every `envs.<NAME>` read made through a binding of `sglang.srt.environ.envs` (plain or aliased — multimodal_gen and the trtllm temp registry have their own `envs` and are not counted), and fails if any name has no registration. With the registration removed it flags exactly this name, so the next unregistered reference fails in CPU CI instead of at backend construction.

## Accuracy Tests

No inference-path change; the read now resolves and returns its default. Ran ruff format, the pre-commit ruff selection, and py_compile on both files locally. The scan test is AST-only and deterministic, roughly 7-10 seconds.
