# [Perf] [AMD] dsv4: Gather the compressor kv_score in bf16 under prefill CP

[Upstream PR](https://github.com/sgl-project/sglang/pull/45071) · state: open · merged: False

## Original PR description

## Motivation

Under prefill CP, `Compressor.compute_kv_score` all-gathers `kv_score` across the CP group in every DeepSeek-V4 layer. On the aiter path (#41931) `kv_score` is a bf16 GEMM output, but it is widened to fp32 before the gather, so the gather moves twice the bytes it needs. On MI355X (DeepSeek-V4-Pro, TP4 + prefill CP4, 16K-token chunk) these gathers take 32 ms of a 580 ms chunk.

## Modifications

Widen `kv_score` after the CP gather instead of before it, on the aiter path only. The gather only moves rows, so the result is bit-identical. Other paths are unchanged.

Related: #34624 keeps `kv_score` in bf16 through the compress kernels behind `SGLANG_OPT_KV_SCORE_BF16`.

## Accuracy Tests

Bit-identical. With this commit, the token ids, logprobs and top-5 logprobs of 5 fixed greedy prompts (including uneven CP shards) match before and after across repeated server launches, and an operator-level check of the gathered `kv_score` is bitwise equal. The path is covered by `test/registered/amd/test_deepseek_v4_pro_fp4_cp.py`.

## Speed Tests and Profiling

MI355X x4, `lmsysorg/sglang-rocm:v0.5.22-rocm10-mi35x-20261018`, DeepSeek-V4-Pro-0813, `--tp 4 --enable-prefill-cp --cp-strategy interleave --attn-cp-size 4 --chunked-prefill-size 16384`, dummy weights:

| TTFT (median) | before | after |
|---|---:|---:|
| 16K tokens | 589.7 ms | 574.9 ms (−2.5%) |
| 64K tokens | 2414.3 ms | 2347.6 ms (−2.8%) |

Per layer, the `kv_score` gather drops from 604 to 310 µs (c4 core), 303 to 155 µs (c128 core) and 155 to 83 µs (indexer); GPU time per 16K chunk goes from 581.6 to 566.4 ms. ROCm 7.2.4 (`v0.5.22-rocm724-mi35x-20261017`) shows the same gain: 16K 588.9 → 574.1 ms, 64K 2391 → 2331 ms.
