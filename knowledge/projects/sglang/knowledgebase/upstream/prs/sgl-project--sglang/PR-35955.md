# [Fix] gptq_marlin: Fix BF16 dtype and TP act-order w2 scales in MoE

[Upstream PR](https://github.com/sgl-project/sglang/pull/35955) · state: closed · merged: True

## Original PR description

## Motivation

GPTQ Marlin MoE currently has two correctness issues when serving BF16 models with tensor parallelism.

First, `w13_scales` and `w2_scales` are hardcoded to `torch.half` (`torch.float16`) instead of following `params_dtype`. When the model runs with BF16 activations, this violates the Marlin MoE kernel's requirement that hidden states and scales use the same dtype and causes:

```text
AssertionError: moe_wna16_marlin_gemm assumes hidden_states.dtype
(torch.bfloat16) == w1_scale.dtype (torch.float16)
```

This issue was also reported in [[SGLang #20599](https://github.com/sgl-project/sglang/issues/20599)](https://github.com/sgl-project/sglang/issues/20599), and the same dtype correction was proposed in [[SGLang PR #22121](https://github.com/sgl-project/sglang/pull/22121)](https://github.com/sgl-project/sglang/pull/22121).

Second, the current w2 scale shape condition is reversed for act-order (`desc_act=True`) under tensor parallelism:

- With act-order, every TP rank needs the full w2 scale table.
- Without act-order, every TP rank only needs its local partition.

In addition, although the w2 scale parameter already carries the `load_full_w2` attribute, the current FusedMoE loader does not honor it and shards the tensor again.

As a result, after fixing the dtype mismatch, inference can still produce invalid w2 scales that propagate NaNs into the output logits. The user-visible failure is:

```text
Assertion `probability tensor contains either inf, nan or element < 0` failed.
```

or:

```text
Assertion `NaN detected! sampler: next_token_logits` failed.
```

A diagnostic check placed before the Marlin kernel localized the first invalid tensor to:

```text
NaN detected! Marlin MoE w2_scales
```

The correct act-order loading behavior was previously implemented in [[vLLM PR #12757](https://github.com/vllm-project/vllm/pull/12757)](https://github.com/vllm-project/vllm/pull/12757), which allocates the full w2 scale table and skips TP partitioning when act-order is enabled.

The affected SGLang logic originated during the MoE refactor in [[SGLang PR #9269](https://github.com/sgl-project/sglang/pull/9269)](https://github.com/sgl-project/sglang/pull/9269) and was later moved into the current GPTQ scheme structure by [[SGLang PR #26402](https://github.com/sgl-project/sglang/pull/26402)](https://github.com/sgl-project/sglang/pull/26402).

## Modifications

- Allocate GPTQ Marlin MoE `w13_scales` and `w2_scales` using `params_dtype` instead of hardcoded `torch.half`.
  - BF16 models now use BF16 scales.
  - FP16 models continue to use FP16 scales.
  - This follows the fix proposed in [[SGLang PR #22121](https://github.com/sgl-project/sglang/pull/22121)](https://github.com/sgl-project/sglang/pull/22121).

- Correct the w2 scale shape calculation under tensor parallelism:
  - `desc_act=True`: allocate the full intermediate-size scale table.
  - `desc_act=False`: allocate only the local TP partition.

- Propagate and honor the existing `load_full_w2` parameter metadata in the FusedMoE loader.
  - Skip TP narrowing when full w2 scales are required.
  - Preserve the existing sharded loading behavior for non-act-order models.
  - This follows the loading semantics introduced by [[vLLM PR #12757](https://github.com/vllm-project/vllm/pull/12757)](https://github.com/vllm-project/vllm/pull/12757).

- Add regression tests covering:
  - BF16 and FP16 Marlin MoE scale allocation.
  - w2 scale shapes with and without act-order under TP.
  - Full versus TP-sharded w2 loading behavior.

- ch-wan · comment · 2026-10-15T12:35:50Z · [source](https://github.com/sgl-project/sglang/pull/35955#discussion_r4283012051)

File: `python/sglang/srt/layers/moe/fused_moe_triton/layer.py` · line 966

**[bug]** `if not load_full` now skips TP narrowing for every w2 tensor whose Parameter has `load_full_w2=True`. That attribute was previously a no-op. `GPTQIntelAMXMoEScheme` already sets `load_full_w2=self.quant_config.desc_act` on `w2_scales` / `w2_qzeros` (`python/sglang/srt/layers/quantization/gptq/schemes/gptq_cpu.py:227` and `:252`) but always allocates `w2_scales_size = intermediate_size_per_partition` (`gptq_cpu.py:175`). CPU AMX still allows `desc_act=True` when `true_sequential` and `static_groups` are set (`gptq_cpu.py:33-38`). Compressed-tensors already treats static act-order as *not* needing a full table (`actorder != "static"`). After this change, a CPU GPTQ MoE load with `desc_act=True` and `moe_tp_size > 1` will `copy_` the full checkpoint scale/zero table into a rank-local buffer and raise a size-mismatch error. GPU Marlin is consistent (full table + the flag); this scheme is not.

**Suggestion:** Either stop setting `load_full_w2` on the Intel AMX scheme (matches static-group semantics), or allocate `intermediate_size_per_partition * layer.moe_tp_size` when the flag is true, as Marlin and compressed-tensors already do. Grep the other `load_full_w2` setters before landing the global skip.
