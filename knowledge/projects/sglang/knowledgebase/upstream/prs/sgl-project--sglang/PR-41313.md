# [Fix] function-call: Stream Qwen3 Coder string arguments

[Upstream PR](https://github.com/sgl-project/sglang/pull/41313) · state: open · merged: False

## Original PR description

## Motivation

`Qwen3CoderDetector.parse_streaming_increment()` still buffers an entire open string parameter on upstream main `fb6e6a09ce5e3dc2ebc93ee64d11572a4da4d758` (2026-10-21). Long file-writing arguments can therefore leave an agent client without tool-argument deltas for minutes while decoding continues.

This updates the existing PR against that main commit and addresses the compatibility concerns discussed in https://github.com/sgl-project/sglang/pull/25246#issuecomment-6308754839. It changes parser delivery, not model outputs, decoding, scheduling, or tool execution.

## Changes

- Incrementally emit declared parameters whose existing `_get_param_type()` conversion is string-like. Reuse the upstream helper rather than introducing a conflicting method or a second schema interpretation. This includes nullable/composed string schemas and existing string aliases. Declared untyped parameters use the existing string fallback; undeclared parameters retain the complete-value path.
- Preserve the complete-value path for arrays (including `anyOf` arrays), objects, integers and booleans.
- Preserve case-insensitive literal `null` conversion, one leading/trailing LF removal, JSON escaping, and split parameter/function terminators.
- Retain a bounded suffix rather than the entire open string, and do not synthesize closing syntax for interrupted output.
- Extend the existing Qwen3 Coder tests with composed schemas, non-string conversions, consecutive leading newlines, split terminators, and consecutive tool calls.

## Validation on the updated code

- CPU-only environment, with upstream-pinned `transformers==5.19.0` and `xgrammar==0.2.7`.
- All 23 `TestQwen3CoderDetector` methods pass, including structural-tag checks and 335 parameterized equivalence/typing/terminator subcases across four tests. The isolated class runner executes the unchanged upstream test class with real detector, protocol, schema utilities, and xgrammar; only unrelated package bootstrap/test imports are avoided.
- Negative control: the same tests against the unmodified main detector report 44 failures (including subtest failures), detecting missing incremental delivery and unbounded open-value buffering.
- 20 CPU adapter replays pass: actual detector fragments are serialized with the OpenAI streaming protocol and passed through the current Anthropic stream converter. Long string arguments arrive before the parameter closes; concatenated OpenAI/Anthropic arguments match non-streaming parsing. This uses a synthetic backend stream and replaces only the telemetry-clock import with `time.monotonic`; it is not a live HTTP/GPU test.
- Ruff selected upstream lint rules, Ruff format check, and `git diff --check` pass.

The full test-module import is blocked locally by the CPU environment lacking Triton. Full maintainer CI remains required. This revision has not been deployed to a GPU service and does not claim an inference speedup.

## Historical physical evidence (original September revision, not rerun for this update)

A paired single-request replay used the same model, weights, prompt, tool schema, and generated 15,375-character `content`; only the detector changed:

| Measurement | Existing detector | Original patched detector |
|---|---:|---:|
| SSE events | 8 | 2,108 |
| Longest silence from request start | 300.893 s | 16.058 s |
| Longest gap after streaming began | 300.893 s | 0.421 s |
| Final tool arguments / content SHA-256 | identical | identical |

Request completion was 317.40 s versus 313.04 s; this was not claimed as a speedup. The purpose is progressive delivery with compatible final arguments and bounded parser buffering.

Related: #27005, #25246.
