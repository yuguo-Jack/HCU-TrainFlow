# [sgl-router] Policy reorg 8/N: wire the bucket engine behind --selection-engine reorg

[Upstream PR](https://github.com/sgl-project/sglang/pull/40093) · state: closed · merged: False

## Original PR description

Stacked on the 7/N resolver PR. First PR where the new engine serves requests, opt-in only; the default stays `legacy`.

## Modifications

- `AppContext::enable_bucket_engine()` builds the `BucketResolver` over the already wired load table, KV index / indexer client and metrics, and starts the affinity-store sweeper. `main.rs` calls it when `--selection-engine reorg` is set.
- `chat.rs`: with the engine enabled, the handler prepares the request, builds one `SelectionRequest` (facts plus a per-request `PrefixMemo`), picks the prefill/plain engine and, for a prefill worker, the decode peer, then forwards exactly as before. Selection failures map onto the existing 503 codes and `policy_selection_failures_total` labels.
- `tests/proxy/bucket_routing.rs` now runs on the new engine. All 14 tests pass with no assertion changes: cross-bucket cache winners, global-rebind/preserve session labels, per-bucket pending budgets, the single indexer call, and SLO ordering.

Running the whole proxy suite on the new engine (throwaway experiment, not committed): 105 of 111 pass. The six that differ are the five `shared_prefill_admission` tests whose doubles implement the old proposal trait, plus one test double relying on backup substitution; the removal PR rewrites them against the new boundaries.
