# [Doc] nemotron-3.5-super: update H200 and Spark wizard recipes

[Upstream PR](https://github.com/sgl-project/sglang/pull/44587) · state: closed · merged: True

## Original PR description

## Summary
- Remove the forced Triton MoE runner from both H200 BF16 wizard commands. SGLang auto-selects `flashinfer_cutlass` on H200.
- Update the four H200 GSM8K benchmark rows using the public BF16 checkpoint and `lmsysorg/sglang:nemotron3-5-super` image.
- Set both DGX Spark commands to `--mem-fraction-static 0.75` and limit compile concurrency with `OMP_NUM_THREADS=4`, `MAX_JOBS=1`, and `CMAKE_BUILD_PARALLEL_LEVEL=1`. The prior 0.88 setting failed during startup on Spark.

## Validation
On 8× H200, `sgl-eval==0.1.2` ran 300 GSM8K questions per cell with the public BF16 checkpoint and cookbook image:

| Mamba SSM dtype | Strategy | Correct | Truncated |
| --- | --- | ---: | ---: |
| bfloat16 | High throughput | 294/300 | 4 |
| bfloat16 | Low latency | 294/300 | 4 |
| float32 | High throughput | 289/300 | 5 |
| float32 | Low latency | 291/300 | 5 |

On DGX Spark, the public NVFP4 checkpoint and cookbook image started and completed 30-question GSM8K smoke checks with the updated settings:

| Mamba SSM dtype | Strategy | Correct | Truncated |
| --- | --- | ---: | ---: |
| bfloat16 | High throughput | 28/30 | 1 |
| bfloat16 | Low latency | 29/30 | 0 |
| float32 | High throughput | 28/30 | 1 |
| float32 | Low latency | 29/30 | 0 |

All eight runs had zero request errors. The Spark smoke scores are not added to the wizard's benchmark tab; its float32 cells still require 300-question accuracy runs.

The edited JSX snippets pass `node --input-type=module --check`; `git diff --check` is clean.
