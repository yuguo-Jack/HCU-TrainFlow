# [Fix] gemma4: Refold the router scale when it is reloaded

[Upstream PR](https://github.com/sgl-project/sglang/pull/47111) · state: open · merged: False

## Original PR description

## Motivation

`Gemma4Router` folds `scale * root_size` into `norm.weight` on its first forward and sets `_scale_fused`, and nothing ever clears that flag. So after an online weight update (`update_weights_from_distributed`, `update_weights_from_tensor`, `update_weights_from_disk`) loads a new `scale`, the router keeps routing with the old one, with no error or warning.

We hit this while adding Gemma 4 to the SGLang weight sync in [Halo](https://github.com/whitecircle/halo), which carries a local patch for now. It's the same kind of bug as #35883 (GLM gate).

## Modifications

- `scale` gets its own weight loader that writes the parameter and refolds it into `norm.weight` in place, so CUDA graph replays see the new value too. Only clearing the flag wouldn't fix replays, because a replay doesn't run the `_scale_fused` check in `forward`.
- `fuse_scale` moves `scale` to the buffers' device first. With `--cpu-offload-gb`, `scale` is still on the CPU at load time while `root_size` is on the GPU.
- `forward` keeps its lazy fold for loads that skip `load_weights` (e.g. `--load-format dummy`).
- `Gemma4ForConditionalGeneration` and `gemma4_diffusion.py` load `scale` through the parameter's own loader, so they're fixed too.
- Not covered: `update_weights_from_tensor(load_format="direct")` skips parameter loaders, so the fold still goes stale there, as it does for any parameter with a custom loader.

## Accuracy Tests

The first load folds the same value as before, just at load time instead of on the first forward. Routing only changes after `scale` is reloaded.

New CPU test `test/registered/unit/models/test_gemma4_router_scale.py`: it loads `scale`, runs a forward, loads a new `scale` through `Gemma4ForCausalLM.load_weights`, and checks that `norm.weight` is `new_scale * root_size` and was updated in place. It fails on main, and it also fails if the loader only clears `_scale_fused`.

`test_gemma4_diffusion.py`, `test_gemma4_uniform_lifecycle.py`, `test_gemma4_renoise.py` and `test_gemma4_cuda_graph.py` in `test/registered/unit/dllm/` still pass on CPU.

Not run: an end-to-end online update on GPU, and the `--cpu-offload-gb` path.
