# [Fix] cuda_graph: Release base storage held by empty break inputs

[Upstream PR](https://github.com/sgl-project/sglang/pull/46737) · state: closed · merged: True

## Original PR description

## Motivation

A zero-element accelerator view can still own a large nonempty base allocation. Breakable CUDA graph capture currently keeps these views unchanged in eager-break argument closures. For NoPE attention, empty Q/K RoPE views can therefore pin the projection outputs once per layer and captured bucket.

## Modifications

Replace empty accelerator arguments with zero-storage tensors preserving shape, strides, dtype and device. CPU arguments keep their identity, and nonempty arguments keep the existing weak-reference behavior. Add a regression for nested views and multiple graph buckets with changed-input replay after temporary-storage reuse.

This is independent of KDA, ReplaySSM and MoE optimizations. It does not address the separate nonempty-input lifetime issue in #37448 or change the eager-output ownership fixed in #30584.

## Accuracy Tests

Tested directly on main `def8f93212bd997ec19b1395e0d892b442374552` plus this patch, on one B300 (PyTorch 2.14.1+cu130, FlashInfer 0.7.2, Triton 3.8.0):

- New regression against unmodified main: **2 failed, 1 passed**, exposing retained base storage.
- New regression plus existing BCG capture/replay/copy unit classes: **18 passed**.
- Changed-input replay assertions are bit-exact. CPU empty-argument identity is unchanged.
- Pre-commit and `git diff --check` pass.

**Validation limitation:** isolated model-level validation remains pending. An earlier GLM-5.3-Flash experiment on `d1bbcbdc`, combining this fix with a separate convolution-layout change, scored 1281/1319 on GSM8K versus baseline 1286/1319; both had four truncations, and both passed 12/12 long-context retrieval probes. Long-input teacher-forcing also varied in repeated unchanged-baseline runs. Those results do not establish the cause or a model-quality pass for this individual patch. ROCm/NPU hardware has not been tested.

## Speed Tests and Profiling

The model-free regression uses a shared graph pool with 512/384/256/128-row buckets. The old implementation retains 15 MiB of active projection storage; the patched test requires less than 1 MiB of additional active allocation and verifies replay after input changes.

An earlier isolated memory A/B on 4×B300 used GLM-5.3-Flash, a fixed 1627-slot Mamba pool and the same integration source/configuration in both arms; this empty-view patch was the only difference. Cumulative additional active graph allocation per GPU was:

| Last captured bucket | Before (MiB) | After (MiB) | Released (MiB) |
| ---: | ---: | ---: | ---: |
| 16384 | 2481.26 | 369.26 | 2112 |
| 15872 | 4528.95 | 370.95 | 4158 |
| 15360 | 6509.62 | 371.62 | 6138 |

These are graph-allocation measurements on the earlier integration base, not whole-server VRAM or new-main serving-throughput results. No request-level speedup is claimed.
