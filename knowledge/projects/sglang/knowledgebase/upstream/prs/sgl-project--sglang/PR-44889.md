# [Feat] PD: Support KV-only hybrid decode radix cache with linear EAGLE

[Upstream PR](https://github.com/sgl-project/sglang/pull/44889) · state: open · merged: False

## Original PR description

## Motivation

Enable decode-side prefix KV reuse for hybrid attention models in PD serving, including linear EAGLE/MTP. Requests with a shared prefix can reuse its KV on the decode worker instead of allocating and transferring another copy for every request.

This relieves decode KV capacity pressure and allows more requests to generate concurrently. Recurrent state remains request-local: each request uses the full-prompt state received from prefill, preserving correctness for requests with different suffixes.

## Modifications

- Decouple prefix KV matching from Mamba/KDA checkpoints while keeping recurrent-state ownership and release request-local.
- Use EAGLE bigram keys to prevent incorrect shifted draft-KV reuse when prefixes diverge at a page boundary.
- Account for running and in-flight PD requests when budgeting persistent and speculative state.

Enabled through the existing `--disaggregation-decode-enable-radix-cache` option, using Python TreeCore. Hybrid speculative use currently requires EAGLE with top-k 1, NIXL, and no sliding-window attention; unsupported cache/session combinations are rejected.

## Accuracy Tests

Validated GLM-5.3-Flash on 8 × H200 with TP4/EP4 on both P and D:

- Shared-prefix, isolated-prefix, and concurrent requests returned the expected answers, including requests with different suffixes. D-side prefix hits were confirmed independently of P-side caching.
- With MTP516 and BF16 recurrent state, full GSM8K evaluation (1,314 examples) scored **95.4% / 95.9%**. BF16 validation also includes the independent KDA tracking dtype fix in #44886.
- **104 tests and 80 subtests passed**, covering KV-only matching, state isolation/release, draft-KV boundary keys, and state budgeting. Pre-commit checks passed.

## Speed Tests and Profiling

On a long shared-prefix workload, enabling D-side radix caching improves output throughput by **27.0%** and reduces median TTFT by **64.2%**, relieving the decode KV capacity bottleneck.

**Configuration:** GLM-5.3-Flash, 8 × H200 (P: GPUs 0–3; D: GPUs 4–7), TP4/EP4 on both workers, FP8 KV and BF16 recurrent state. P uses MTP112; D uses MTP516 with ReplaySSM speculative state. Only D-side radix caching changes between OFF and ON; P-side caching stays enabled.

**Workload:** C32, 1K output, GSP input settings of 252K shared prefix + 4K unique suffix (~273K actual input tokens per request). Results below are medians of three runs after warmup; all 512 requests per run succeeded in both configurations.

| Metric | D radix OFF | D radix ON |
| --- | ---: | ---: |
| Output throughput (tok/s) | 2,459.24 | **3,123.84** |
| TTFT P50 (s) | 6.90 | **2.47** |
| Mean TPOT (ms) | 5.80 | 6.98 |
| D running requests (log median) | 15 | **23** |
| D KV utilization (log median) | 98% | **9%** |
| Transfer volume per request (log median, MB) | 21,272 | **485** |

Both configurations have the same **4,745,728-token KV capacity**. Prefix reuse reduces logged per-request transfer volume by **97.7%** and frees KV space for more concurrent decoding. TPOT increases alongside the larger active decode batch, while overall throughput and time to first token improve.
