# [Fix] constrained: Allow uniqueItems false in schema prevalidation

[Upstream PR](https://github.com/sgl-project/sglang/pull/46122) · state: open · merged: False

## Original PR description

## Motivation

Both grammar-backend prevalidators currently reject an integer-array schema containing `"uniqueItems": false`, while accepting the same schema without that keyword. JSON Schema defines these forms as equivalent: false imposes no uniqueness constraint ([specification](https://json-schema.org/draft/2020-12/json-schema-validation#name-uniqueitems)).

This is a narrow follow-up to #37839, similar to the no-op/compatible-schema handling in #39869. It does **not** implement `uniqueItems: true` or reopen #40083.

## Modifications

- Exempt only the boolean value `false` from the unsupported `uniqueItems` check in XGrammar and Outlines prevalidation.
- Keep true, invalid false-like values, and other unsupported constraints rejected; preserve input schemas and sorted error messages.
- Add four CPU regression methods covering absent/false/true, nested properties/items/$defs, input preservation, and other unsupported constraints alongside false.

## Accuracy Tests

No model/kernel computation changes. Local validation was performed on Windows with Python 3.12:

- **Validator assertions:** 16 validator-only test methods pass using an isolated loader. The production validator and test method bodies were unchanged; the CI retry base was replaced with `unittest.TestCase`. The two adapter test methods and the registered CI runner were **not** executed locally. Against the original production source, the same tests reproduced eight false-value rejections and two masked nested-constraint failures.
- **Real backend compilation/matching:** 24 checks pass using XGrammar 0.2.7 and Outlines Core 0.1.26: false and omitted schemas both accept duplicate/nonduplicate integer arrays and reject wrong item types, wrong lengths and incomplete JSON. XGrammar matching checks both acceptance and termination. Two additional controls confirm true remains rejected before compilation.
- The Windows XGrammar smoke check used **TVM-FFI 0.1.14.post1**, because the pinned 0.1.11 Windows DLL lacks C++ symbols required by the XGrammar wheel. Other local versions were PyTorch 2.12.1 and Transformers 5.9.0. **SGLang dependency pins are unchanged**; this is not a full pinned SGLang environment test.
- **Formatting/static checks:** applicable upstream pre-commit hooks pass for both changed files, including isort 7.0.0, Ruff 0.15.1, codespell 2.4.1, AST, private-key and test-registration checks. A private configuration omitted only the C++ formatter, Notebook and manual-link-check repositories after unrelated hook downloads failed; retained hook definitions/options match upstream exactly. The repository configuration is unchanged.

Full HTTP serving, model generation and GPU/token-mask E2E were not run. Please run the registered CPU test through authorized upstream CI.
