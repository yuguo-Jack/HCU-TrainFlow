# [Fix] mem_cache: Match KV budgets to indexer, DCP and replay layouts

[Upstream PR](https://github.com/sgl-project/sglang/pull/46704) · state: closed · merged: False

## Original PR description

## Motivation

Three KV budget paths disagree with the storage they allocate:

- On CUDA, the DeepSeek-V4 FP4 indexer allocates 68 bytes per slot but the planner charges the 132-byte FP8 row (128-dimensional index keys), leaving capacity unused.
- Hybrid MHA/SWA sizing omits DCP replication when counting full-attention KV heads. Ordinary SWA shares those heads; compressed SWA keeps its explicit head count. With TP4/DCP2, the ordinary hybrid example admits approximately twice its byte budget. MXFP8 scales need the same head geometry.
- DeepSeek-V4.1 encoder replay allocates workspace for the largest breakable prefill graph bucket, but its fixed budget only considers the chunk. The request window also has a zero/sink page in addition to the underlying KV pool's padding page.

This complements #41275, which fixes ratio-1/2 compressed KV growth and reserved compressed pages. Those changes are not duplicated here.

## Modifications

- Charge the packed FP4 indexer row on CUDA as well as HIP, preserving the NPU accounting path.
- Match hybrid full/SWA head counts to the pool builder, including MXFP8 scales.
- Share encoder replay workspace row sizing between allocation and budgeting. Preserve the existing scratch allowance while covering larger graph buckets and actual window storage, tags and reserved pages.
- Add three focused regressions to the existing pool-configurator suite.

## Accuracy Tests

All three new regressions fail on the pre-fix source and pass with the patch. CPU allocation/budget validation: **103 tests and 60 subtests passed** across:

```bash
PYTHONPATH=python python3 -m pytest -q \
  test/registered/unit/model_executor/test_pool_configurator.py \
  test/registered/unit/mem_cache/test_dsv4_compressed_pools.py \
  test/registered/unit/mem_cache/test_dsv4_unified_fp8_pool.py \
  test/registered/unit/mem_cache/test_swa_pool_v_head_dim.py
```

The indexer and request-window regressions measure real CPU tensor allocations. The hybrid regression checks admitted capacity against the builder's DCP head geometry for BF16 ordinary SWA and MXFP8 compressed SWA. In the encoder case (chunk 512, graph bucket 65,536), the old fixed reservation is 29,724,672 bytes while target window/tags/workspace alone allocate 69,067,520 bytes.

Model accuracy and GPU model execution were not tested. Focused CI has been dispatched for this head: [CPU allocation tests](https://github.com/sgl-project/sglang/actions/runs/40432209676) and [request-window kernel tests](https://github.com/sgl-project/sglang/actions/runs/40432221620). Both are pending, not reported as passed.

No serving benchmark or throughput claim. This changes capacity budgeting; it does not change quantization, attention kernels or stored KV layouts.
