# [Feature] Enable DeepSeek V4 index cache

[Upstream PR](https://github.com/sgl-project/sglang/pull/26274) · state: open · merged: False

## Original PR description


## Motivation

Enables DeepSeek V4 C4 indexer top-k reuse through an index cache. 
**Input 256K output 100 throughput improved by 17%.**
This pr #25276 is deprecated due to outdated code.

## Modifications

- Add `index_topk_freq` and `index_topk_pattern` to `DeepSeekV4Config`.
- Allow DeepSeek V4 C4 indexer layers to reuse previous raw top-k indices.
- Convert cached raw C4 indices back to sparse page indices before attention.
- Preserve compatibility with indexer top-k capture and HiSparse page translation.
- Handle decoder outputs with cached top-k metadata in DeepSeek V4 NextN.

## Speed Tests and Profiling
Test in H800, TP=4, index_topk_freq=4.
Server start command:
```
python3 -m sglang.launch_server \
  --trust-remote-code \
  --model-path /nas/disk6/DeepSeek-V4-Flash/DeepSeek-V4-Flash/DeepSeek-V4-Flash-FP8 \
  --tp 4 \
  --mem-fraction-static 0.8 \
  --cuda-graph-max-bs 16 \
  --moe-runner-backend marlin \
  --host 0.0.0.0 \
```

I feel passing `prev_topk_indices` across multiple function calling will be invasive and risky.
How about creating a global buffer for storing the previous topk results, and update it when next_skip_topk is True.

For example,
```python
@dataclass
class Dsv4IndexTopkState:
    prev: Optional[torch.Tensor] = None
```
Create it once in DeepseekV4Model.forward, pass topk_state down to DeepseekV4DecoderLayer / MQALayer, and let MQALayer consume/update it internally:
```python
prev = topk_state.prev if self.skip_topk else None

topk = self.indexer(
    ...,
    prev_topk_indices=prev,
    skip_topk=bool(self.skip_topk),
    return_topk_indices=bool(self.next_skip_topk),
)

if self.next_skip_topk is not None:
    topk_state.prev = topk if self.next_skip_topk else None
```
