# [Perf] dsv4: Dequantize each shared sparse-prefill KV source once per forward

[Upstream PR](https://github.com/sgl-project/sglang/pull/45909) · state: closed · merged: True

## Original PR description

- DeepSeek-V4.1's ratio-1/2 layers read the compressed KV of a few kv_source layers, and sparse prefill dequantized that cache into the shared buffer in every one of them. The layers that share a source now reuse its dequant: no later layer of the forward writes that cache, and graph replay keeps the layer order.
- `SparsePrefillWorkspace` is renamed `SparsePrefillKVBuffer` and owns the reuse. `get_with_head` returns the rows and whether the head already holds the given source (source cache, gather ids, row count). A plain `get`, a reallocation, or the start of a new forward forgets the head.

Outputs are unchanged: the skipped dequants would have written the same rows.

Verification:
- Every reused dequant in a DeepSeek-V4.1-Flash DEP4 prefill run matched a fresh dequant of the same rows.
- GPU profiles on B300 and GB300 show the sparse-prefill KV dequant running once per kv_source instead of once per layer, with no other kernel or copy added. Prefill step time drops on both at every batch size tested, with and without the prefill graph.
- No out-of-memory at the recipe memory fraction; GSM8K is unchanged.
