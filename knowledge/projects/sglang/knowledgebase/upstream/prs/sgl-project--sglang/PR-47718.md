# [Perf] [NPU] Release temporary DeepSeek-V4 RoPE tables

[Upstream PR](https://github.com/sgl-project/sglang/pull/47718) · state: open · merged: False

## Original PR description

## Motivation

DeepSeek-V4's NPU RoPE cache retains contiguous FP32 real/imag copies after building the final interleaved cos/sin tables. These copies are only read when building a table; warmed forwards read the final caches.

For two frequency tables with 1,048,576 positions and rotary dimension 64, the unused copies occupy 512 MiB. This is a size calculation, not a whole-model measurement.

## Changes

Keep the real/imag copies local to `ensure_tables` so they can be released after construction. Final caches and the forward path are unchanged. Building another dtype regenerates the temporary copies at initialization.

## Validation

- CPU and Ascend NPU: 144 exact comparisons each, covering FP32/BF16/FP16, owner/no-owner, inverse, 4D, empty/repeated/changed positions.
- Checked cold no-build rejection, warm cache pointer stability and nonpersistent buffers.
- Two NPU graph replays with changed positions matched eager results.
- Applicable formatting/lint checks passed. Two hooks could not launch `python3` on Windows; their scripts passed when run with the available Python interpreter.

With two 262,144-position tables, rotary dimension 64, and FP32/BF16 final caches:

| Active allocated bytes above baseline | Before | After |
| --- | ---: | ---: |
| NPU allocator | 671,095,808 | 536,876,032 |

Reduction: **128 MiB of tensor payload plus 2 KiB of allocator padding**. Measured with torch 2.10.0+cpu and torch_npu 2.10.0.post6. No full-model accuracy or throughput claim.

[Reproducer, source snapshots and results](https://github.com/AkiYangDev/sglang/tree/9101e6fd8792ecffc4ad2a3a420176fdc46f6871) are on a separate evidence branch; this PR contains only the production change.
