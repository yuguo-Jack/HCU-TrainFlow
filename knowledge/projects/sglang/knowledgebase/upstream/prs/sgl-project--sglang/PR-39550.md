# HiCache NIXL Tier-3 Bug Fixes

[Upstream PR](https://github.com/sgl-project/sglang/pull/39550) · state: open · merged: False

## Original PR description

## Motivation

Three bug classes were found in the HiCache NIXL tier-3 (L3) path while
benchmarking the storage tier. The bugs compound in the default configuration.
A fourth gap, missing storage metrics, left the tier with no bandwidth signal
that could have exposed them.

1. **O_DIRECT tier-3 writes failed but were treated as cache hits.** The XPU
   pinned host allocation is page-aligned, but is not `get_user_pages()`-able,
   so NIXL's O_DIRECT path receives `EFAULT`, while buffered I/O using the same
   buffer succeeds. Since O_DIRECT is the default, affected writes created
   zero-length files, while the subsequent cache lookup treated file existence
   as a cache hit. The existing guard only checked page alignment, which is
   insufficient for this allocation type.

2. **Failed transfers were reported using requested bytes.** `_log_xfer_stats`
   derived the logged byte count and bandwidth from the requested buffer sizes
   regardless of transfer outcome. As a result, a batch that wrote no data
   could still be reported as 2.173 GiB at 3.11 GiB/s, which did not represent
   actual storage traffic and could mask the underlying write failure.

3. **NIXL backend configuration was not normalized or validated
   consistently.** JSON boolean values were stringified as `"True"`/`"False"`
   and therefore did not match NIXL's case-sensitive boolean options.
   SGLang-only options such as `use_direct_io` and `l3_cleaner_*` were also
   only read from the top level, so the nested form users commonly write
   silently fell back to defaults. `use_direct_io` was read with `bool()`, so
   `"false"` enabled it. In addition, malformed or incomplete plugin sections
   could raise during backend selection instead of falling back to
   `SGLANG_HICACHE_NIXL_BACKEND_PLUGIN`.

4. **The NIXL tier exported no storage metrics.** `HiCacheNixl.get_stats()`
   returned `None`, so `sglang:prefetch_bandwidth`, `sglang:backup_bandwidth`,
   and the `*_pgs` histograms stayed empty for the NIXL L3 tier even with
   `--enable-storage-metrics`.
5. **Nothing checked that a storage directory was writable at all.** The
   O_DIRECT probe treats `EACCES`/`EPERM` as inconclusive, because those
   errnos say nothing about the buffer, and buffered I/O is its fallback. A
   directory the process cannot write therefore surfaced only as failing
   transfers at runtime.

### 1. Fall back to buffered tier-3 I/O when O_DIRECT rejects the host pool

Probe O_DIRECT usability once per pool registration instead of assuming that
page alignment is sufficient.

The probe opens a temporary file under each configured base directory and
performs a real page-aligned `pwrite` using the pool's own source buffer. If
the probe fails, O_DIRECT and its page-alignment requirement are disabled for
the backend, and the reason is logged. A disk error during the probe (`ENOSPC`,
`EIO`) says nothing about the buffer, so it keeps O_DIRECT; a probe that cannot
run at all falls back to buffered I/O rather than aborting registration.

The probe covers all relevant tier-3 source-buffer types:

- v1 zero-copy `kv_buffer`
- copy-mode bounce buffers
- v2 hybrid mamba/SWA pool buffers
- V4 `LogicalHostPool` marker buffers

Each base directory is probed independently because directories can reside on
different filesystems or mounts.

The probe file never has a directory entry: `O_TMPFILE` where supported, and
otherwise a named file unlinked immediately after `open()`. A probe interrupted
by `SIGKILL` therefore leaves nothing behind, which matters because the L3
cleaner only walks bucket directories and would never reclaim one.

Disabling O_DIRECT drops its page-alignment requirement, so the zero-copy
decision for v2 hybrid pools is gated on an explicit layout check that does not
depend on that requirement. A `layer_first` pool stays on bounce buffers
either way; its per-page slots are not directly addressable, and promoting it
to zero-copy would raise on the first transfer.

The fallback also covers path mode, where O_DIRECT is passed to NIXL as the
`"direct"` token in the file specification.

### 2. Stop reporting requested bytes as transferred for a failed NIXL transfer

Update `_log_xfer_stats` to log the transferred byte count next to the
requested one, and to derive bandwidth from the transferred count. A batch is
one NIXL request that completes all or nothing, so a failed batch now logs
`0 of N bytes transferred` at 0 MB/s.

### 3. Fix NIXL backend configuration normalization and fallback handling

Normalize JSON boolean values to the lowercase strings expected by NIXL:

- `True` -> `"true"`
- `False` -> `"false"`

Literal `"True"`/`"False"` strings are folded with a warning. Other string
values are preserved unchanged.

SGLang-only options such as `use_direct_io` and `l3_cleaner_*` are promoted
from the **selected** plugin's section to the top level with a warning. The
selected section is the one marked `active`, or, when none is, the one named by
`SGLANG_HICACHE_NIXL_BACKEND_PLUGIN` (nothing is promoted for `auto`, which
resolves only at backend creation). SGLang keys under any other plugin are
ignored with a warning, so an inactive `gds` section cannot change the settings
of the `posix` backend that runs. Configuration precedence is:

1. Existing top-level value.
2. The selected plugin's nested value, when the top-level value is absent.
3. Otherwise the `SGLANG_HICACHE_NIXL_*` environment variable or built-in default.

These keys are now parsed strictly. **Behavior change:** a wrongly typed
top-level value (e.g. `"use_direct_io": "false"`, or a boolean watermark) now
raises `ValueError` at startup instead of being coerced; a wrongly typed nested
value is ignored with a warning. Integer `0`/`1` for a boolean key is still
accepted, since it is unambiguous. The README documents these keys as boolean/float.

The `active` plugin selector is consumed by SGLang and is no longer forwarded
to `create_backend`.

Backend selection now handles malformed plugin configuration by falling back
to `SGLANG_HICACHE_NIXL_BACKEND_PLUGIN` instead of raising:

- non-mapping plugin section
- no active plugin
- unusable plugin options

### 4. Add regression tests for the NIXL tier-3 fixes

39 new regression cases were added across two test files.

`test_hicache_nixl_utils.py` adds 24 CPU-gated cases covering:

- NIXL configuration normalization
- nested plugin-option handling, including keys under an unselected plugin
- plugin selector fallback
- malformed configuration
- O_DIRECT probe behavior

`test_hicache_nixl_storage.py` adds 15 GPU-gated cases covering:

- failed-transfer statistics at all four call sites
- v1 registration
- v2 hybrid registration, including layout gating after an O_DIRECT fallback
- logical-anchor registration
- O_DIRECT probe coverage for relevant buffer types

### 5. Report NIXL HiCache storage metrics through get_stats()

Record the page count and bandwidth of every fully successful `batch_get` /
`batch_set` on both the v1 and v2 paths, and drain them in `get_stats()`.

- Bandwidth is recorded in GB/s to match the histogram buckets; the debug log
  line stays in MB/s.
- A failed batch records nothing, since its transferred bytes are unknown.
- `get_stats()` swaps the sample lists out rather than copying and clearing, so
  a sample appended by a worker thread in between is not lost.
- Nothing is recorded when storage metrics are disabled.
- As in the hf3fs backend, each v2 pool transfer is its own NIXL request and
  records its own sample.

5 new GPU-gated cases in `test_hicache_nixl_storage.py`
(`TestNixlStorageMetrics`) cover GB/s units, no sample for a failed batch,
read/write routing to prefetch/backup on all four paths, drain-on-read, and no
accumulation when metrics are disabled.

### 6. Probe NIXL tier-3 storage directories for buffered writes at startup

For every FILE-backend base directory, SGLang now creates, writes and unlinks a
buffered probe file, and checks that each bucket directory is writable (bucket
dirs carry the data files and can predate this process). `EACCES`, `EPERM` and
`EROFS` stop startup with the offending directory in the message, since
buffered I/O is the last fallback; other errors such as `ENOSPC` only warn. The
check runs whether or not `use_direct_io` is set, and the README documents it.

4 new CPU-gated cases in `test_hicache_nixl_utils.py` (`TestNixlBufferedIOProbe`):
writable directories pass and leave nothing behind, a permission/read-only base
directory fails startup, a transient write error only warns, and an unwritable
bucket directory fails startup.


## Accuracy Tests

Bug 1 was reproduced on ext4/NVMe with Qwen2.5-1.5B-Instruct:

| Configuration | Files | Stored data |
| --- | --- | --- |
| O_DIRECT | 2350 | 0 bytes |
| Buffered I/O | 2476 | 0.529 GiB |
| O_DIRECT + probe/fallback | — | 0.529 GiB |

The probe detects that O_DIRECT cannot successfully use the affected XPU host
pool and switches to buffered I/O.

Bug 3 was verified using `strace` with:

```json
{
  "plugin": {
    "posix": {
      "use_uring": true
    }
  }
}
```

Before this change, the POSIX backend issued `io_setup` and selected libaio.
After this change, it issued `io_uring_setup`, confirming that the nested
boolean configuration reaches the intended backend option.

The startup write check of commit 6 was verified against real permissions as a
non-root user: a writable directory passes and leaves nothing behind, a base
directory at `chmod 555` fails startup with `Permission denied (errno 13)`, and
a bucket directory at `chmod 555` fails with the bucket path in the message.

## Performance Impact

No steady-state fast-path overhead is introduced.

- O_DIRECT probing runs once per pool registration.
- One temporary-file probe is performed per base directory.
- The startup write check runs once per base directory, plus an `access()`
  call per bucket directory.
- Statistics only change which byte count is used for the existing log line.
- Configuration normalization runs once during backend creation.
- Metrics recording is two list appends per successful batch, and only when
  storage metrics are enabled.

For affected pools, falling back from O_DIRECT to buffered I/O is a
correctness-over-throughput trade-off. The fallback is selected only when the
probe shows that O_DIRECT cannot successfully write from the pool's source
buffer.
