# [Fix] kt: pass the GPU expert mask that kt-kernel's inference API takes

[Upstream PR](https://github.com/sgl-project/sglang/pull/45183) · state: open · merged: False

## Original PR description

## Motivation

`KTEPWrapperMethod.create_weights` builds `KTMoEWrapper(..., num_gpu_experts=...)`. Since kt-kernel 0.7, the inference wrapper takes `gpu_experts_mask`, a boolean mask of the GPU-resident experts, as a required argument. `num_gpu_experts` is left for the SFT path. With kt-kernel 0.7.2 (the current release on PyPI), every KTransformers launch on main therefore stops at load with a `TypeError` for the missing `gpu_experts_mask`.

From `kt_kernel/experts.py` in the 0.7.2 wheel:

```python
def __new__(cls, layer_idx, num_experts, num_experts_per_tok, hidden_size,
            moe_intermediate_size, gpu_experts_mask: Optional[torch.Tensor],
            cpuinfer_threads, threadpool_count, weight_path, chunked_prefill_size,
            ..., num_gpu_experts: int = 0, ...)
```

#20516 covers this among broader KT changes. This PR is only the minimal call-site fix.

## Modifications

`python/sglang/srt/layers/moe/kt_ep_wrapper.py`: build the mask from `num_gpu_experts` and pass it instead of `num_gpu_experts`. The GPU experts occupy physical ids `0..num_gpu_experts-1`, the same assumption the wrapper already makes when it masks the routing.

## Accuracy Tests

The mask selects the same experts the old argument did, so outputs are unchanged. It runs in our DeepSeek-V4.1-Flash-1017 setup on 2x RTX 5070 Ti with kt-kernel 0.7.0: TP2, 5 GPU experts a layer, the CPU experts on 2x EPYC 7452.

## Speed Tests and Profiling

No change.
