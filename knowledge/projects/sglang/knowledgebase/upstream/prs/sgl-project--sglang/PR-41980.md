# [AMD] Recalibrate test_quark_mxfp4 GSM8K thresholds to observed MI355X noise

[Upstream PR](https://github.com/sgl-project/sglang/pull/41980) · state: open · merged: False

## Original PR description

## Motivation

`test/registered/e2e/quantization/test_quark_mxfp4.py` is the most frequent failure in `stage-b-test-1-gpu-small-amd-mi35x`. It failed on 2026-09-19, 09-23 through 09-28, and 09-30, on every ROCm image. The failures are not regressions: two GSM8K thresholds sit inside the normal run-to-run spread.

GSM8K accuracy collected from 36 scheduled `stage-b-test-1-gpu-small-amd-mi35x` jobs (PR Test AMD + AITER Scout, rocm10/720/724, 2026-09-19 to 09-30; retries included):

| Test | Threshold | min | median | max | attempts ≤ threshold |
|---|---|---|---|---|---|
| `TestNVFP4ToMXFP4MOETP1` | > 0.85 | 0.798 | 0.862 | 0.882 | 17 / 40 |
| `TestFP8ToMXFP4MOETP1` | > 0.92 | 0.900 | 0.922 | 0.940 | 17 / 47 |
| `TestOnlineQuantizationMemoryLoadMOE` | > 0.89 | 0.894 | 0.924 | 0.942 | 0 / 23 |
| `TestFP8ToMXFP4DenseTP1` | > 0.868 | 0.876 | 0.906 | 0.912 | 0 / 36 |
| `TestOnlineQuantizationMemoryLoadDense` | > 0.85 | 0.866 | 0.870 | 0.874 | 0 / 23 |

The 09-30 rocm724 failure, for example: `TestNVFP4ToMXFP4MOETP1` scored 0.814 and then 0.818 on retry (`AssertionError: 0.814 not greater than 0.85`).

## History

Both thresholds have been flaky since the day each test was added. Nothing regressed later.

| Date | PR | Change |
|---|---|---|
| 2026-06-03 | #18005 | Adds the file with the BF16 → MXFP4 `Dense` (> 0.85) and `MOE` (> 0.89) cases, registered in `stage-b-test-1-gpu-small-amd-mi35x` |
| 2026-06-14 | #18182 (reverted the same day by #28213) | First attempt at the FP8 → MXFP4 cases |
| 2026-07-21 | #28291 | Relands FP8 → MXFP4, adding `TestFP8ToMXFP4MOETP1` (> 0.92) |
| 2026-08-14 | #29328 | Adds `TestNVFP4ToMXFP4MOETP1` (> 0.85) |
| 2026-09-26 | #41243 | Moves the file to `test/registered/e2e/quantization/` |

Across all scheduled PR Test (AMD) `stage-b-test-1-gpu-small-amd-mi35x` jobs that ran this file between 2026-07-04 and 2026-10-02 (170 jobs; older logs have expired):

| Test | First failure | Jobs failed | Attempts ≤ threshold | min | median | max |
|---|---|---|---|---|---|---|
| `TestFP8ToMXFP4MOETP1` (> 0.92) | 2026-07-22, the day after it landed: 0.912, then 0.920 on retry | 23 / 138 | 68 / 182 (37%) | 0.900 | 0.924 | 0.946 |
| `TestNVFP4ToMXFP4MOETP1` (> 0.85) | 2026-08-15, its first scheduled run: 0.846, then 0.832 on retry | 16 / 92 | 42 / 104 (40%) | 0.802 | 0.856 | 0.886 |

The distributions did not move when CI switched from the rocm700 image to rocm720/724/10 on 2026-09-15. Medians before and after were 0.922 → 0.924 for FP8 → MXFP4 MoE and 0.860 → 0.856 for NVFP4 → MXFP4 MoE. The BF16 `Dense`/`MOE` and `TestFP8ToMXFP4DenseTP1` cases never dropped to their thresholds.

The file stops at the first failing class. Every job where `TestFP8ToMXFP4MOETP1` failed skipped the NVFP4 and BF16 cases, so NVFP4 has fewer samples, and part of its failure rate was hidden until 2026-09.

## Modifications

Set the two flaky thresholds about 0.02 below the observed minimum and record the observed numbers next to them:

- `TestNVFP4ToMXFP4MOETP1`: 0.85 → 0.78 (the old `~0.88` comment overstated the real median of 0.862).
- `TestFP8ToMXFP4MOETP1`: 0.92 → 0.89, the same value #35477 arrived at from its own MI355X sampling (mean 0.916, min 0.898). That PR still targets the pre-#41243 path `test/registered/quant/` and does not touch the NVFP4 case.

The other three classes have no failures and are unchanged.

Companion to #41973, which fixes the same job's 30-minute timeout.
