# [Perf] [NPU] scheduler: Remove blocking seq_lens D2H from graph replay

[Upstream PR](https://github.com/sgl-project/sglang/pull/45170) · state: open · merged: False

## Original PR description

## Motivation

NPU decode and target-verify graph replay require host-side sequence lengths
to update graph inputs. Reading these lengths through
`forward_batch.seq_lens.cpu()` introduces a blocking device-to-host copy,
even when the batch already provides a CPU mirror.

Reuse the existing CPU mirror to avoid this redundant synchronization and
reduce host-side stalls during graph replay preparation.

## Modifications

- Prefer `forward_batch.seq_lens_cpu` when preparing sequence lengths for
  NPU decode and target-verify graph replay.
- Slice the CPU mirror to the active batch size before adding graph padding.
- Preserve the captured verify-width adjustment for target verification.
- Preserve the existing DFlash metadata path.
- Retain the device-to-host fallback when `seq_lens_cpu` is unavailable.
