# [muse_spark] serve LoRA on the text layers only

[Upstream PR](https://github.com/sgl-project/sglang/pull/47843) · state: open · merged: False

## Original PR description

## Motivation

On the Muse Spark Open branch, enabling LoRA with attention targets crashes the server at startup: the LoRA manager indexes modules by their `layers.N` position and sizes its tables from the language model's layer count, and the vision and audio towers' layers repeat the text projections' names (`q_proj`, `k_proj`, ...), so a tower layer index runs past the table (IndexError).

## Modifications

- `MuseSparkForConditionalGeneration.should_apply_lora`: only the text decoder's `model.layers.N.` modules take LoRA.
- `LoRAManager.init_lora_modules`: honor `should_apply_lora` when the base model defines it, as main already does for the VL models (the gate sits after the embed_tokens / lm_head handling for the same reason).

## Checklist

- Validated with the miles RL trainer (torchtitan backend) streaming rank-32 attention adapters into two engines serving `RadixArk/Muse-Spark-Open-last4-partial`: two rollouts, two adapter syncs, trainer-vs-engine log-prob abs diff 0.017 with routing replay.
