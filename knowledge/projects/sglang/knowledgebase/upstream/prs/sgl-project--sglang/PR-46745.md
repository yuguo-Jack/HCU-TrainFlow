# [Feature] disagg: opt-in Rust wire-codec backend (sglang-disagg crate) for P/D data plane

[Upstream PR](https://github.com/sgl-project/sglang/pull/46745) · state: open · merged: False

## Original PR description

## Summary

First increment of a port of the P/D disaggregation data plane from Python to Rust, motivated by GIL-held stalls in the Python data plane that knock ranks out of collective cadence at high rank counts (observed at 384-rank 2P1D scale: one GIL-stalled rank held 127 peers hostage in a gloo all-gather until timeout).

This PR lands the **safe foundation**: a `sglang-disagg` crate with byte-exact wire codecs for the hottest zmq frame families, golden-vector tested against the Python builders, wired in as an **opt-in** runtime backend (`SGLANG_DISAGG_WIRE_BACKEND=rust`, default `python` — zero behavior change out of the box).

## What's in

- **`rust/sglang-disagg/`** — new crate (rlib + cdylib) in the main workspace:
  - Wire codecs (`status.rs`, `nixl.rs`, `pack.rs`, `json.rs`) byte-exact with the Python builders/parsers for: NIXL receiver registration, NIXL receiver metadata, chunk-ready, kv-status frames.
  - Request-status room state machines (`room.rs`: `StatusTable`, `DecodeRooms`, `PrefillRooms`, `DeferredAbortTracker`).
  - `PeerTable` (`peers.rs`) — NIXL peer bookkeeping mirroring `_add_remote_peer` / `_reload_invalidated_peers` (nixl/conn.py), with the 1.0s reload rate limit and injectable clock; vector-tested via a mock agent.
  - `csrc/nixl_shim.{h,cc}` — 14-call `extern "C"` surface over `nixlAgent` (xfer make/post/status, dlist prep, eager `make_connection`), compile-verified against NIXL v1.5.1 headers (C++20; build gated on `--features nixl` + `NIXL_INCLUDE_DIR`).
  - PyO3 bindings (`py.rs`) for the four codec families; parse functions return dicts keyed by the exact dataclass field names.
- **`python/sglang/srt/disaggregation/rust_wire/`** — source-build loader + registry with logged python fallback; `SGLANG_DISAGG_WIRE_BACKEND` env (default `python`).
- **8 dispatch sites** rewired with rust as a drop-in: `nixl/conn.py` registration build/parse + metadata build/parse; `common/conn.py` kv_status encode/parse (logging split preserved), chunk_ready build/parse.
- **Golden vectors** (`tests/vectors/wire.json`) generated exclusively by the pure-Python path (generator stubs the registry with `rust=None` so generation can never run through Rust — avoids a circular test).
- Bootstrap registry fix: serve `decode_allocation_policy` and `enable_kv_cache_sharding` from the Rust bootstrap registry.

## Verification

- 18/18 `cargo test -p sglang-disagg` green (13 wire + 4 room + 1 peers); clippy clean with and without `python-extension`/`nixl`.
- Regenerated `wire.json` byte-identical.
- Differential run of the **real dispatched methods** under both backends — 13 cases (3 registration incl. staging, 6 metadata incl. 2048-index + dummy/prefix-hit rules, 3 kv_status incl. tagged+reason, 1 chunk_ready): byte-identical frames, identical parse results. Reproduced on a B300 devbox (nixl-cu13 1.5.1).
- NIXL shim compiles + links clean against real NIXL 1.5.1 (`cargo build --features nixl`); two mechanical fixes from that first build are in the last commit.

## Explicitly NOT in this PR (follow-ups)

- The transfer path itself (`makeXferReq`/`postXferReq`/`getXferStatus` under NIXL's STRICT agent mutex) still runs in Python holding the GIL — routing it through the shim with the GIL released, plus eager connect via `PeerTable`, is the load-bearing next increment.
- Room machines and `PeerTable` are not bound over PyO3 (callbacks into the Python agent would recreate the GIL churn they exist to kill).
- Sender-side Transferring/Success transitions; Mooncake frame family.
