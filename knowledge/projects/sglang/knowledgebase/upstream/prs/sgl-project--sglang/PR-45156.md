# [Fix] model_executor: Initialize idle metadata on the active attention backend

[Upstream PR](https://github.com/sgl-project/sglang/pull/45156) · state: open · merged: False

## Original PR description

## Motivation

Eager EAGLE draft steps select a child attention backend through `ForwardContext`. The idle runner currently initializes or clears `model_runner.attn_backend` instead, leaving the backend consumed by that forward with stale metadata. This affects both DP-padded idle batches and zero-batch cleanup.

## Modifications

Resolve the active backend from `ForwardContext` for the idle metadata operation, retaining the default runner backend when called without a context. Input loading and PP argument forwarding remain unchanged.

## Accuracy Tests

- Added 6 registered CPU regression tests covering child-backend overrides, changing batch sizes, zero-batch cleanup, loaded batch views, PP inputs, PDMux, nested child contexts, and default/no-context behavior. They fail against unpatched main and pass with this fix; CPU validation hides the allocated CUDA device.
- Existing DSA eager-idle unit tests: 3 passed.
- NVIDIA H200, PyTorch 2.13.0+cu130: exercised the directly imported idle runner with a controlled DeepGEMM paged-MQA metadata consumer for batch sizes 1, 4, and 2. Unpatched code produces the expected `_batch_size == batch_size` assertion; the fixed path passes all three cases and matches the explicit FP32 reference within `rtol=0.02, atol=1.0` (maximum absolute error 0.02225).

## Speed Tests and Profiling

The GPU check validates the metadata ownership contract through a real CUDA operator; it does not claim a full-model serving failure or an end-to-end performance improvement. The current DSA eager-idle fast path remains unchanged.
