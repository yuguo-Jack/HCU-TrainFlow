## Motivation

Gemma4 on XPU launches normalization and RoPE separately for every attention layer. Shared-KV layers additionally allocate a dummy key tensor just to rotate Q. Fuse these operations while preserving the BF16/FP16 normalization rounding boundary and the existing checkpoint weights.

## Modifications

- Extend the existing Gemma QKV norm/RoPE operator to XPU and query-only shared-KV calls.
- Dispatch eligible XPU Gemma4 layers through the fused operator, including unweighted V normalization for nonshared layers.
- Match native XPU rotary contraction order. Explicitly materialize the FP16 intermediate encoding before rotation to preserve its rounding, including subnormal and nonfinite values.

## Accuracy Tests

Intel Arc Pro B70, `google/gemma-4-E2B-it`, BF16, TP1:

- Official `sgl-eval` GSM8K-200: 163/200 (81.5%), zero errors, two truncated responses. Temperature 1, top_p 0.95, seed 42, max_tokens 2048, concurrency 8, thinking disabled.
- Six greedy model parity cases matched, including 1,016- and 1,814-token prompts.
- All 64 sampled native XPU kernel comparisons matched exactly across BF16/FP16, shared/nonshared KV, geometries, and batch sizes. Graph replay, packed-stride guards, FP16 cancellation, and 8,204 FP16 rounding edge/random inputs passed.
- 123 CPU namespace/dispatch tests passed.
- All four serving capture tests passed (three-step and single-step MTP), in 88.754 seconds.

Expanded 256-token serving comparisons also expose output variation within control repeats. Of three differing prompts replayed on the same GPU/configuration with cache flushed before each repeat, two matched across all four control/candidate runs; one varied in every run. These measurements do not establish bitwise model equivalence on arbitrary prompts. CUDA execution was not available locally; its existing contraction path is preserved.

## Speed Tests and Profiling

Same B70, same serving configuration and unchanged BF16 weights; current stack tip as control. Captured three-step MTP, max_running_requests=32, context_length=8192, max_total_tokens=32768, page_size=64, overlap disabled. Control/candidate/candidate/control sequence, 256 output tokens, 64 requests at c1 and 128 at c8/c32. Each server switch discarded a full 128-request c32 warmup before measurement.

| Concurrency | Control mean TPOT (ms) | Candidate mean TPOT (ms) | Reduction |
| --- | ---: | ---: | ---: |
| 1 | 4.155 | 4.116 | 0.95% |
| 8 | 6.118 | 6.049 | 1.14% |
| 32 | 11.334 | 11.102 | 2.04% |

Both candidate repeats were faster than both control repeats at every measured concurrency. The subset with identical generated text in all four runs showed streaming-interval TPOT reductions of 1.03%, 1.15%, and 1.94%, respectively. These are results on this device/workload, not a claim for all XPU hardware or batch sizes.
