# [Feat] cp: Support FlashInfer prefill context parallelism

[Upstream PR](https://github.com/sgl-project/sglang/pull/33226) · state: open · merged: False

## Original PR description

## Motivation

FlashInfer could not use the existing zigzag prefill CP path for dense MHA/GQA models. This PR adds that backend integration, addressing the FlashInfer coverage task in #21788.

## Modification

Keep queries zigzag-sharded, gather KV into the full paged cache, and execute FlashInfer prefill on each rank's logical queries. Restore physical padding at the strategy boundary.

```text
zigzag token shards
  |-- local K/V --> all-gather --> full paged KV --+
  |-- local Q -----------------------------------+--> FlashInfer prefill
                                                          |
                                                          v
                                                local output + padding
```

Supports eager dense causal MHA/GQA with direct NHD KV. Uses current runtime configuration without deprecated `enable_cp_v2` or model-file changes. CPU coverage checks routing/padding; the registered Qwen3-8B server test uses `GSM8KMixin`.

## Accuracy Result

Qwen3-8B BF16 on 2× H100. Parity compares TP2/CP2 with both cold cache and prefix reuse.

| Validation | Result | Status |
|---|---|---|
| Registered CP2 GSM8K, 200 examples | 191/200 = **95.5%**, above the 90% floor; zero errors/truncations | Pass |
| 2K cold/reuse parity | Identical output token IDs; max absolute logprob delta **1.19e-7 < 0.2** | Pass |
| 8K cold/reuse parity | Identical output token IDs; max absolute logprob delta **0.111686 < 0.2** | Pass |
| 16K cold/reuse parity | Identical output token IDs; max absolute logprob delta **0 < 0.2** | Pass |

The paired GSM8K experiment measured TP2 96.0% versus CP2 95.5% (-0.5 percentage points), so passing the floor does not establish identical accuracy.
