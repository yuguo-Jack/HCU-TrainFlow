# [Fix] io_struct: preserve request flags when slicing requests

[Upstream PR](https://github.com/sgl-project/sglang/pull/27255) · state: open · merged: False

## Original PR description

Fixes #27231.

## Summary

- Preserve the request-level `background`, `use_audio_in_video`, and `routing_key` fields when `GenerateReqInput.__getitem__` creates a sub-request. `require_reasoning` was already forwarded on current main.
- Restate the original patch against the current implementation, which now includes `_sub_obj_cache` and the expanded IPC field set.
- Cover `n > 1` expansion, all four request-level fields, repeated indexed access returning the cached sub-object, and foreground requests remaining `False`.

Without this forwarding, Responses API background jobs can silently revert to foreground disconnect handling after request slicing.

## Test Plan

The new regression fails against the preceding implementation: `test_background_flag_survives_slicing` sees `background=False` in the sub-request. It passes with this change, alongside the foreground control.
