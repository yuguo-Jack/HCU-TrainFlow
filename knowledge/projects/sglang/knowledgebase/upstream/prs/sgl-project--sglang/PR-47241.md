# [Perf] [AMD] dsv4: Speed up the gfx950 swap-AB decode attention

[Upstream PR](https://github.com/sgl-project/sglang/pull/47241) · state: open · merged: False

## Original PR description

## Motivation

On gfx950 (MI355X), DeepSeek-V4 decode with at most 8 query rows runs `swapab_attention`, which takes 12 to 14 µs per call. Its grid has only 2 to 60 programs, so one program's latency sets the call time. This PR cuts that latency and raises the router cap from 8 to 16 rows.

## Kernel architecture

```mermaid
flowchart LR
    A["KV gather"] --> B["KV tile in LDS"] --> C["QK and PV MFMA"] --> D["O per PV tile"] --> E["combine_gfx950"]
```

- P stays in registers. PV runs in 8 tiles, and each tile's O stores right after its MFMAs. VGPR falls from 90 to 60.
- `combine_gfx950` loads `sink` and `pos` as scalars first and skips inverse RoPE on tiles without rope dims.
## What could break

- `_combine` is shared with SM100 and unchanged here. Only the gfx950 wrapper passes `combine_gfx950`. No SM100 GPU was available, so no test ran there. The sm_100 and sm_103 compiles match base.
- The aiter route's split reduce calls `inverse_rope_tail`, whose text and ISA match base.
- The buffer-load gather needs a cache of at most 2**31 - 2 bytes and an even page stride. Other caches keep global loads. A new test covers both edges.
- Rows 9 to 16 on gfx950 move from the aiter route to swap-AB.
