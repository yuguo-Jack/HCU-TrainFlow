# [Fix] lang/runtime: Raise HTTP errors in async generation

[Upstream PR](https://github.com/sgl-project/sglang/pull/44788) · state: open · merged: False

## Original PR description

## Motivation

`Runtime.async_generate` silently returns no output when `/generate` rejects a request with a JSON HTTP error. The client only processes SSE data, so a 400 response looks like a successful empty generation. `add_request` has the same behavior.

## Modifications

Check the HTTP status before consuming the stream. Add a CPU regression test using a local HTTP server, covering both methods and preserving text deltas and error events sent inside HTTP 200 streams.

## Accuracy Tests

```bash
PYTHONPATH=python python test/registered/unit/lang/test_runtime_http_errors.py -v
pre-commit run --all-files --show-diff-on-failure
```

All three tests pass on macOS arm64 with Python 3.12.7 and aiohttp 3.14.5. Against the unmodified base, the six HTTP 400/422/503 cases fail; both HTTP 200 behavior tests pass. The tests use the real HTTP client and server without import stubs or model loading. Pre-commit passes.

No model accuracy evaluation was run; model computation is unchanged. Linux CPU CI is pending.

## Speed Tests and Profiling

Not applicable. This checks the response status once before reading streamed data.
