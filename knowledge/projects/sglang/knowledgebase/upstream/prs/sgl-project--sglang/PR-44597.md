# [CI] glm5.2: Keep EOS in HiSparse needle test output

[Upstream PR](https://github.com/sgl-project/sglang/pull/44597) · state: closed · merged: True

## Original PR description

## Motivation

`test_dsa_glm52_hisparse.py::_test_long_context_spec_swap` fails intermittently, in both greedy and non-greedy runs. The model retrieves the correct code, but the test sends `ignore_eos`, and stripping special tokens removes the EOS between the answer and whatever is generated after it. When that later text starts with a digit, the `(?!\d)` boundary check fails:

- CI (temperature 0): `7393911. What is the name of the language...`
- Local (temperature 0.6): `739391555023\n555023...`

## Modifications

Pass `skip_special_tokens: False` so the EOS token stays in the returned text (e.g. `739391<|user|>1. What...`). All GLM-5.2 stop tokens (`<|endoftext|>`, `<|user|>`, `<|observation|>`) are special tokens in the tokenizer. The check is just as strict as before: a wrong code, or extra digits with no EOS in between, still fails.

## Testing

Checked the decoded output against the `nvidia/GLM-5.2-NVFP4` tokenizer. The full 8xB200 test has not been rerun yet.
