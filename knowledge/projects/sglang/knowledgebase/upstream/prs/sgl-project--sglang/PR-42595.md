# [Fix] Recursively sanitize structural tag containers in xgrammar backend

[Upstream PR](https://github.com/sgl-project/sglang/pull/42595) · state: open · merged: False

## Original PR description

## Motivation
Fix #42144 
`XGrammarGrammarBackend._sanitize_structural_format` is intended to recursively normalize missing or `None` `json_schema` fields to empty schemas `{}`. However, it previously only recursed into `tag`, `sequence`, `or`, `triggered_tags`, and `tags_with_separator`.

When a `json_schema: null` was wrapped in other valid container types (`optional`, `star`, `plus`, `repeat`, `dispatch`, `token_dispatch`, or `token_triggered_tags`), the `null` survived and caused xgrammar compilation to fail.

## Modifications

1. **`python/sglang/srt/constrained/xgrammar_backend.py`**:
   - Extended `_sanitize_structural_format` to recurse into:
     - `content` for single-content containers (`optional`, `star`, `plus`, `repeat`).
     - `rules` (second element `rule[1]`) for dispatch containers (`dispatch`, `token_dispatch`).
     - `tags` for tag-list containers (`token_triggered_tags`).
   - Added safe fallbacks (`or []`) for `elements`, `rules`, and `tags` to avoid `TypeError: 'NoneType' object is not iterable` when container lists are explicitly `None`.
2. **`test/registered/unit/constrained/test_structural_format_sanitizer.py`**:
   - Added comprehensive BDD-aligned unit test suite (`TestStructuralFormatSanitizerBDD`) using `CustomTestCase`.
   - Covers:
     - Scenario 1: Content containers (`optional`, `star`, `plus`, `repeat`).
     - Scenario 2: Dispatch containers (`dispatch`, `token_dispatch`).
     - Scenario 3: Tag list containers (`token_triggered_tags`).
     - Scenario 4: Arbitrary deep recursive nesting.
     - Scenario 5: Resilience against malformed/null fields.
     - Regression check for existing containers (`tag`, `sequence`, `or`, `triggered_tags`, `tags_with_separator`).
   - Registered with `register_cpu_ci(1.0, "base-a-test-cpu")`.
