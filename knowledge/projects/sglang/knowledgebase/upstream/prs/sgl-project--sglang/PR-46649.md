# [Perf] [AMD] Kimi-K3: MLA prefill cat-cache, absorb, prefix no-cat, FP8 prefill

[Upstream PR](https://github.com/sgl-project/sglang/pull/46649) · state: open · merged: False

## Original PR description

## Motivation

K3 MLA prefill paid for a separate rope / cat / KV write, a `torch.cat` of prefix K/V on every extend-with-prefix, and bf16 MHA.

## Modifications

- Fused rope + cat + KV-cache write, with deferred q absorb.
- Extend-with-prefix MHA builds prefix K/V without `torch.cat`.
- FP8 PS-ASM MHA for d192/v128, with host plan metadata shared across a batch's MLA layers.

## Accuracy Tests

- `test_kimi_k3_mla_prefill_fmha.py` and `test_kimi_k3_mla_prefix_nocat.py` pass on MI355.

Full K3 stack on MI355X TP8 (DFlash, prod config) vs B300, McNemar:
- GPQA-D 89.4 vs 87.9 (p=0.55)
- AIME25 96.7 vs 93.3 (p=1.0)
- MATH500 92.2 vs 92.2 (p=1.0)
- MMLU-Pro 89.6 vs 90.0 (p=0.77)
- GSM8K 97.2%

## Speed Tests and Profiling

- Turning it off costs -14.2/-0.3/-1.9% on the agentic replay and -13.4/-4.6% at 90k prefix (mean -6.9%).

Speed numbers: throughput change from turning this feature off on the full stack, agentic replay at C=1/8/32 and 90k-prefix at C=1/8.
