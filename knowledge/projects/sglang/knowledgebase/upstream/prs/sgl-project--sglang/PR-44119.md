# [Perf] DFLASH: build the draft num_token_non_padded scalar with torch.full

[Upstream PR](https://github.com/sgl-project/sglang/pull/44119) · state: closed · merged: True

## Original PR description

## Motivation

The DFLASH draft step builds its `num_token_non_padded` device scalar with `torch.tensor(bs * block_size, dtype=torch.int32, device=device)` on every step. Building a CUDA tensor from a Python int this way is a pageable host-to-device copy, and the host blocks until the stream drains. If GPU work is already queued, the host waits for all of it before it can launch the draft.

## Modifications

Use `torch.full((), bs * block_size, dtype=torch.int32, device=device)` instead. It produces the same 0-dim int32 tensor with the same value, but the fill runs on device and the host does not wait.

## Accuracy Tests

No numerical change: the tensor has the same value, dtype, and shape.

## Speed Tests and Profiling

Host time to produce the 0-dim int32 scalar on B300, torch 2.13.0+cu130, median of 50 calls. The "5 ms queued" column has 5 ms of GPU work already on the stream when the scalar is created.

| variant | GPU idle | 5 ms queued |
|---|---|---|
| `torch.tensor(n, device=cuda)` (before) | 14.8 µs | **4978.5 µs** (waits for the queue) |
| pinned host tensor + `non_blocking=True` | 7.6 µs | 9.4 µs |
| `torch.full((), n, device=cuda)` (this PR) | 6.1 µs | 6.2 µs |
