## Motivation

<!-- Describe the purpose and goals of this pull request. -->

During padded CUDA Graph replay, the variable-length KDA/GDN recurrent kernel leaves padded output rows uninitialized. Stale NaNs in these rows can propagate through downstream operations and corrupt valid-token outputs.

For example, replaying a batch-8 graph with seven active requests writes only seven output rows, leaving the last row unwritten. This fix makes the unused output tail deterministically zero.

## Modifications

<!-- Detail the changes made in this pull request. -->

- Zero the output tail beyond `cu_seqlens[-1]` in the existing kernel, preserving valid-token outputs and recurrent state updates without an additional kernel launch.
- Extend the existing ragged kernel tests to replay the same CUDA Graph with different active-token counts for both KDA and GDN, checking zero padding, valid outputs, and recurrent state preservation.
