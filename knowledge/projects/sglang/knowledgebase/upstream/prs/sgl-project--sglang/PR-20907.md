# Expose Model Parallelism Information

[Upstream PR](https://github.com/sgl-project/sglang/pull/20907) · state: closed · merged: False

## Original PR description

## Motivation

We want to enable model shards to be initialized outside of sglang in a way that's identical to sglang's ModelLoader.  
The external initialization workflow will look something like this: 

```
sglang.srt.server_args._global_server_args = server_args
model_parallelism_info = engine.get_parallelism_config(rank) 
with ParallelismContext(RankParallelismConfig.from_dict(model_parallelism_info)):
   model = get_model(
                model_config=model_config,
                load_config=load_config,
                device_config=device_config,
            )
```

The primary use case of this is to enable train -> inference weight transfer. with [14997](https://github.com/sgl-project/sglang/pull/14997), we already have transfer engine and weight registration, but the transfer can only happen between weights of identical shape. One option is to instantiate the model shards outside, register the weights, and send them to sglang via the existing registrations. 

I will however leave draft_tp for future work. The test currently verifies everything else.


## Modifications
Whenever transfer engine is enabled, we additionally expose the full parallelism configurations of tp/pp/moe_ep/moe_tp/attn_tp/attn_cp/moe_dp information through http API. The info is propagated to the _global_states just like the rdma weight register does at initialization time, so no performance impact. 

A small fix was made to pass dp_parallel_controller's scheduler_infos back to the global  engine instance. This allows remote_weight_info APIs to work with dp>1. 

## Accuracy Tests
`python -m sglang.launch_server --model-path qwen/qwen2.5-0.5b-instruct --remote-instance-weight-loader-start-seed-via-transfer-engine`

the `test_parallelism_context_integration.py` shows the intended use case and that the model parameters match.
