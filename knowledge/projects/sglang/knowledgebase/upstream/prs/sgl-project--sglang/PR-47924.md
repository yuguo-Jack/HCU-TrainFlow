# [Fix] [NPU] attention: Pack valid MLA prefix tokens for mixed batches

[Upstream PR](https://github.com/sgl-project/sglang/pull/47924) · state: closed · merged: True

## Original PR description

## Motivation

Kimi K3's hybrid attention backend processes mixed prefill/decode batches
through the existing extend path. Decode histories may end in partially
filled KV pages.

Gathering whole pages leaves invalid prefix-tail positions between
requests, while prefix FIA uses cumulative logical sequence lengths.
This mismatch can cause attention length errors or incorrect request
boundaries.

## Modifications

- Build valid prefix-token indices and cumulative prefix lengths once per batch.
- Reuse ND/NZ page gathering, then compact latent KV and RoPE before kv_b_proj.
- Update both MLA prefix branches to consume the compacted tensors.
- Preserve the [tokens, 1, head_dim] RoPE shape by removing redundant flattening.
- Reuse the existing extend, FIA, and LSE-merge pipeline.
- Add four regression tests covering partial, empty, and aligned prefixes,
  shared/reordered pages, ND/NZ layouts, and real cache dimensions.

## Accuracy Tests

- Four CPU/NPU cache-layout regression tests passed.
- Four native FIA reference cases passed against independent FP32 full
  attention, including partial pages and zero-length prefixes.
  Maximum absolute error: 0.003689, with atol=0.006 and rtol=0.03.
- Reduced four-layer Kimi K3 serving validation passed with TP4 and graphs
  disabled: 3/3 requests completed, with 14 actual mixed batches per worker.

Model-level accuracy remains unresolved: reduced-model logits comparisons
did not pass the screening thresholds, and off/off repeats also showed
differences. These results do not establish model-level accuracy parity.
Full 93-layer model quality has not been validated.

## Speed Tests and Profiling

A request with 2,048 input tokens and 2,048 output tokens was started
first. After its 64th output token, a second request with 131,072 input
tokens and one output token was submitted.

The comparison used the same revision with mixed chunk disabled/enabled,
a chunk budget of 1,024, page size 128, and non-speculative decoding.
Decode graphs were enabled and prefill graphs disabled. Four measured
runs were collected per setting, excluding warmups.

| Metric | Mixed chunk disabled | Mixed chunk enabled |
|---|---:|---:|
| Maximum observed short-request ITL across all four runs | 9.120 s | 188.7 ms |
| Short requests experiencing a token gap exceeding 1 s | 4/4 | 0/4 |
| Mean short-request TPOT | 9.140 ms | 9.231 ms |
| Mean short-request E2E | 18.894 s | 19.099 s |
| Mean long-request TTFT | 8.995 s | 9.861 s |
<img width="2040" height="1105" alt="image" src="https://github.com/user-attachments/assets/92f97448-f201-4dad-a7e5-3d1f94650cac" />

Each enabled run recorded 129 genuine mixed batches, with each batch
advancing the short request by one decode token alongside the long
request's prefill.

The maximum observed token gap decreased by approximately 98%, and no
second-scale gaps occurred in the four enabled samples. This demonstrates
reduced prefill-induced decode starvation and improved streaming
continuity in this scenario.

Mean TPOT and E2E showed no stable improvement. These results compare
the scheduling configurations on the same revision; they do not isolate
the prefix-packing overhead or establish full-model, P99-latency, or
throughput improvements. No operator profiling was collected for this test.
