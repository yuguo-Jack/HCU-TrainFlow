# [Fix] dsv4.1: capture routed experts on the vision-aware routing path

[Upstream PR](https://github.com/sgl-project/sglang/pull/46671) · state: closed · merged: True

## Original PR description

## Summary

With a vision tower loaded (`vision_n_layers > 0`, no `--language-model-only`), every non-MegaMoE DeepSeek-V4.1 MoE layer routes through `vision_topk` instead of `TopK`. Its non-MegaMoE branch never ran the hooks `select_experts` runs after top-k, so the routed-experts capture buffer kept its zero init: `--enable-return-routed-experts` returned all zeros, and routing replay in RL failed on them. The expert-distribution recorder missed those layers as well.

## Changes

`multimodal/dsv41/vl_routing.py`: the non-MegaMoE branch of `_finish_vision_topk` runs `capture_routed_experts_if_allowed` and the expert-distribution recorder, as `_post_process_topk_ids` does on CUDA.

## Validation

DeepSeek-V4.1-Flash (official FP8 dense + MXFP4 routed experts), one TP8 engine on H200, `--enable-return-routed-experts`, no LoRA:

- Before: every routed-experts value is 0, for prompt and decode tokens alike.
- After: ids span [0, 383] with 6 distinct per token-layer, and match `--language-model-only` (which routes through `TopK`) exactly on the same text prompt: 79 tokens × 40 layers, same output ids.

Not covered: image tokens, which take the alternate bias, were not compared against a reference.

Split out of #45231 per review.
