# [sgl-router] Keep charset=utf-8 on streamed responses

[Upstream PR](https://github.com/sgl-project/sglang/pull/43232) · state: closed · merged: True

## Original PR description

SGLang streams with `Content-Type: text/event-stream; charset=utf-8`. On a successful stream the router replaced that with a bare `text/event-stream`. Clients that decode by the header then read the UTF-8 events as Latin-1. Python `requests`' `Response.text` is one: `°` comes out as `Â°`, and DeepSeek's `<｜DSML｜` tags as `<ï½DSMLï½`.

## Modifications

- `proxy/mod.rs`: a successful stream is sent as `text/event-stream; charset=utf-8`. Error bodies keep the upstream content type, as before.
- The two proxy tests that pinned the bare header now expect the charset.

## Checks

- `cargo clippy --all-targets -D warnings` and `cargo test` in `experimental/sgl-router` pass.
- Live, on DeepSeek-V4.1-Flash behind the router: the stream header matches the engine's, and a 49-case streaming chat matrix decoded with `requests`' `r.text` matches the engine's responses.
