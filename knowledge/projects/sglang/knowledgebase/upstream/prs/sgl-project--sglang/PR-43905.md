# [Fix] scheduler: Abort held decode requests, and read live requests from the lists

[Upstream PR](https://github.com/sgl-project/sglang/pull/43905) · state: closed · merged: True

## Original PR description

With every live request in a list (`Scheduler.request_lists()`), a few places that walk their own subset of queues and batches either miss requests or repeat the list of holders. This makes them read the lists, and lets an abort reach the one list it skipped.

- `abort_request` also aborts a PD decode request held for rebootstrap while generation is paused (`DecodePreallocQueue.held_rebootstrap_reqs`). Such a request holds no KV and no step uses it, so it finishes and is released at once. `DecodePreallocQueue.take_aborted` now removes the retracted and held requests an abort matches; the scheduler only releases them.
- `_has_active_sampling_mask_request` reads every list instead of its own set of batches and queues. It now also sees requests in the PD prefill bootstrap and transfer queues, launched prefills, the dLLM queue, PD decode requests releasing their KV, HiSparse staging and parked uOCR windows.
- `is_fully_idle` reads the request part of each variant (default, health check, `ignore_waiting`) from the lists. Its result is unchanged: the default counts every list except the ones counted elsewhere or deliberately left out (running and launched prefills through the batches, dLLM through its staging check, held decode requests, parked uOCR windows through `blocks_flush`, finished deferred responses); the health check counts chunked, waiting and, unless paused, retracted decode requests, as before.

Behavior changes: the held-request abort, and the sampling-mask check covering more lists.

## Test plan
- A held-request abort during a retract pause finishes only the matching request, and resume enqueues the rest.
- The unit tests this PR touches pass locally with `SGLANG_IS_IN_CI=1`, apart from failures main has too.
