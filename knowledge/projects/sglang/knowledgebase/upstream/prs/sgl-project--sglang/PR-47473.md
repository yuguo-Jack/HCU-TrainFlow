# [Test] diffusion/disaggregation: Cover aligned transfer staging

[Upstream PR](https://github.com/sgl-project/sglang/pull/47473) · state: open · merged: False

## Original PR description

## Motivation

The alignment-aware staging-size fix in #45394 by @mickqian currently has no focused manager/allocator regression. Raw tensor sizes can fit the default 1 MiB buddy block while the aligned writer rejects the second tensor, and list None entries can fail before writing.

This is a tests-only supplement to #45394. It targets `codex/diffusion-stage-deployment` so the diff contains only the new test file. The implementation remains credited to the original PR; these tests can be merged or cherry-picked into it.

## Modifications

Add one CPU-registered `CustomTestCase` file covering nine staging scenarios: the default 1 MiB boundary, alignment edges at 511/512/513 bytes, a single tensor, a zero-length tail, list holes, absent fields, and all-None lists. Assert real tensor round trips, manifest offsets/list indices, and whole-pool reuse after cleanup.

Only pinned-memory allocation, device-event availability, and the unused transfer-engine boundary are mocked. The actual manager, allocator, writer and reader are imported normally and executed. No staging-size algorithm is copied into the tests.

## Accuracy Tests

Python 3.12 / PyTorch 2.14.1+cpu:

```bash
SGLANG_CACHE_DIR=/tmp/sglang-cache PYTHONPATH=python \
  python test/registered/unit/multimodal_gen/test_transfer_staging.py -v
```

- On the #45394 head `ab0c3e671769dc75c18412d6cb05ff54e5a9f959`: 4 test methods covering 9 scenarios pass.
- The same file against main `c8054551012b3df729a0f7c409af95f74286e416` fails in 5 scenarios: 3 existing slot-boundary ValueErrors and 2 None-entry AttributeErrors.
- Repository pre-commit checks on the new file and `git diff --check` pass.

GPU copies/events, RDMA/Mooncake, distributed execution and model-serving accuracy are not validated here.

## Speed Tests and Profiling

No performance claim. The tests use at most a 2 MiB CPU pool per scenario, require no model weights, and register with a 5-second CPU CI estimate.
