# [Perf] cosmos3: optimize v2v preprocess performance

[Upstream PR](https://github.com/sgl-project/sglang/pull/45398) · state: closed · merged: True

## Original PR description

## Motivation

Cosmos3 V2V currently decodes the full source video and repeats CPU preprocessing for temporally padded frames. Reduce this overhead while preserving the original preprocessing and generated outputs bit for bit.

## Modifications

- Use PyAV to load the required first/last conditioning frames without materializing the full video.
- Add batched Triton Lanczos resize with optional crop and normalization, preserving input layout and matching Pillow rounding.
- Preprocess each source frame once, in batches of up to 8. Convert to the VAE dtype before temporal padding, and release pixel tensors after VAE encoding.
- Enable GPU video preprocessing by default; reuse `SGLANG_FORCE_CPU_IMAGE_PREPROCESSING=1` for CPU preprocessing.

## Accuracy Tests

Compared against the original ImageIO + CPU/PIL baseline across **8 configurations**: 480p, 720p, 1080p and 4K inputs, with either fixed 480p output or output resolution following input.

All configurations are **bit-identical** for the FP32 source preprocessing results, the complete 45-frame BF16 VAE input, the final MP4 file, and all decoded RGB frames.

## Speed Tests and Profiling

**Environment:** 1× NVIDIA RTX PRO 6000 Blackwell Server Edition (96 GB); Docker image: `lmsysorg/sglang@sha256:b1259f3ea3275f66237c498ea388919729018bc9f01c3d638391e06e2cf3f469`.

**Workload:** Cosmos3-Edge, official `robot_pouring.mp4`, resized to each input resolution; first 5 conditioning frames, 45 output frames, 24 FPS, 35 steps, CFG 5, seed 42. All offload, torch.compile and guardrails are disabled.

Each configuration uses a separate process with **1 complete warmup + 1 measured request**, using different videos and positive/negative prompts. Every measured request misses the conditioning cache and executes VAE encoding and both text branches. Baseline is the original ImageIO full-video decode + CPU/PIL implementation. Speedup = baseline / optimized.
