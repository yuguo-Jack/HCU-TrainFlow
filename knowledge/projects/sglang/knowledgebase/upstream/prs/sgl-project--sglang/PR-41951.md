# [perf] [multi-lora] remove empty CTAs from fused LoRA expand and add split-K to shrink

[Upstream PR](https://github.com/sgl-project/sglang/pull/41951) · state: closed · merged: True

## Original PR description

## Summary

CSGMV launches empty tiles for smaller packed QKV expand slices and leaves parallelism unused in rank-32 shrink operations. Compact the expand grid using existing CPU slice offsets, and add opt-in split-K shrink with FP32 partials and a separate reduction.

## Changes

- Calls without CPU slice offsets retain the rectangular expand path with early returns for empty tiles.
- `SGLANG_ENABLE_LORA_CSGMV_SPLIT_K=1` enables the existing BF16 rank-32 dispatch policy; it remains off by default. Deterministic inference retains the original shrink accumulation order because split-K changes rounding.
- Treat the partial-buffer row stride as a runtime parameter so different token counts reuse compiled split-K kernels.
- Use `split_k=None` for automatic dispatch, preserve explicit positive values, and reject invalid values before deterministic fallback.
- Keep one kernel benchmark and consolidate regressions into the existing CUDA-graph test script.

## Validation

Validated on H200 at `a7deef700821501c37fd1de266d4f1f42848d23a`:

- Existing CI entry point `python test/registered/kernels/ops/lora/test_chunked_sgmv_cuda_graph.py -f`: **8 tests passed**. Coverage includes FP32 partials, ragged and empty slices, output stride, mixed ranks, CUDA-graph metadata replay, explicit split factors, and deterministic fallback.
- The extended dispatch regression fails on the old argument logic when explicit split 4 is overwritten by 8.
- Eager token counts 7, 8, 9, and 17 pass the FP32 numerical oracle and reuse one compiled producer and reducer each.
- Full `pre-commit run --all-files` passed before both fix commits.

## Performance

The contributor's [corrected serving results](https://github.com/sgl-project/sglang/pull/41951#issuecomment-5925662323) report approximately 9.5–11.6% throughput improvement. These measurements predate the cleanup commits; no new serving or performance measurements are claimed for this head.
