# [Perf] beam_search: Defer token materialization to top-k beams in BeamGroup.finalize()

[Upstream PR](https://github.com/sgl-project/sglang/pull/46480) · state: open · merged: False

## Original PR description

## Motivation

In `BeamGroup.finalize()` (`python/sglang/srt/beam_search/beam_group.py`), `materialize_tokens(beam.leaf)` is currently called for every `CompletedBeam` accumulated in `self.completed` across all decode steps before sorting by `beam_score` and slicing `[: self.beam_width]`.

Because `self.completed` can accumulate up to `beam_width * max_new_tokens` finished candidates over a generation run (each with a `BeamNode` parent chain of length up to `max_new_tokens`), materializing token lists for all completed candidates before selecting the top `beam_width` beams performs $O(|\text{completed}| \cdot T)$ linked-list traversals and reversals when only $O(\text{beam\_width} \cdot T)$ are returned. Since `beam_score` depends solely on `beam.cum_logprob` and `beam.num_tokens`, scoring and sorting first avoids materializing discarded candidates while preserving Python's stable sort order on tied scores.

Additionally, `BeamGroup._pending_steps` acts as a FIFO queue between `advance_frontier` / `advance_final_frontier` and `commit_pending`, so replacing `list` + `.pop(0)` with `collections.deque` + `.popleft()` avoids $O(N)$ list shifts when draining staged steps.

## Modifications

- **`python/sglang/srt/beam_search/beam_group.py`**:
  - In `BeamGroup.finalize()`, compute `(self.beam_score(beam.cum_logprob, beam.num_tokens), beam)` for `self.completed`, sort descending by score (`key=lambda item: item[0]`, preserving stable completion order on ties), and call `materialize_tokens(beam.leaf)` only on the top `self.beam_width` entries.
  - Use `collections.deque` and `.popleft()` for `BeamGroup._pending_steps`.
- **`test/registered/unit/beam_search/test_beam_search_core.py`**:
  - Add `test_finalize_materializes_only_top_k_and_preserves_ties` verifying that only the top `beam_width` beams invoke `materialize_tokens` and that tied scores preserve completion order.
