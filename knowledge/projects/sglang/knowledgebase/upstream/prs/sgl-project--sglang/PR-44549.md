# [Perf] [AMD] mla: One-launch q/k prep, split combine and fused W_vc + gate epilogue for Kimi-K3 decode on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/44549) · state: closed · merged: False

## Original PR description

> Kimi-K3 on gfx950 series (all drafts): #44547 gfx950 verify argmax + tuned rows, #44548 KDA, #44549 MLA decode, #44550 MLA prefill, #44551 → #44552 → #44553 collectives, MoE decode, MoE prefill. The end-to-end numbers in each PR are for all seven together.

## Motivation

Around aiter's head-padded (12 -> 16 heads) asm MLA decode/verify kernel, Kimi-K3 TP8 runs a chain of small ops per
MLA layer and step: q/k concats, the fp8 KV write, the row-0 guard, the query padding, aiter's split reduce, the
absorbed W_vc bmm, the output gate, and the q_a / kv_a RMSNorms ahead of q_b_proj. On gfx950 each is a separate launch.

## Modifications

All new paths are gated on `is_gfx95_supported()`.

- `AttentionBackend.supports_split_mla_qk()` (False by default): the absorbed-MLA forward passes q / k as nope / rope
  parts. The aiter backend says yes for target verify and single-query decode on the zero-padded asm persistent
  kernel with an fp8 KV cache, and `mla_decode_prep` then builds the padded query (a unit-scale fp8 one with
  `SGLANG_AITER_MLA_VERIFY_FP8_Q`, as the qlen > 4 path already does), writes the fp8 KV rows as
  `set_kv_buffer` would and keeps KV row 0 zero, in one launch.
- The backend issues aiter's persistent stage 1 itself and combines the splits over the real heads only
  (`mla_split_reduce`, a drop-in for `aiter.mla_reduce_v1` at up to 16 query rows), or hands the partials to the
  model (`mla_epilogue_handoff`).
- Kimi-K3's absorbed-V epilogue runs the W_vc bmm and the output gate as one kernel (`mla_v_up_gate`) or, with the
  deferred partials, the split combine, W_vc and the gate as one (`mla_decode_epilogue`, 1-64 rows,
  `SGLANG_ROCM_K3_FUSED_MLA_EPILOGUE`).
- The q_a / kv_a RMSNorms and the q_b projection of decode-sized batches run as one launch (`mla_q_norm_proj`,
  <= 16 rows, `SGLANG_ROCM_K3_MLA_Q_NORM_PROJ`), enabled per layer by Kimi-K3 after weight loading.
- `SGLANG_AITER_MLA_MAX_SPLITS_PER_BATCH` caps aiter's planned splits per request (unset: unchanged).

`DeepseekV2AttentionMLA` gains `fused_absorb_v_epilogue()` (returns None) and `fused_q_norm_proj` (False), so other
DeepSeek-family models keep their decode path.

| New env var | Default |
|---|---|
| `SGLANG_AITER_MLA_VERIFY_FP8_Q` | on |
| `SGLANG_ROCM_K3_FUSED_MLA_EPILOGUE` | on |
| `SGLANG_ROCM_K3_MLA_Q_NORM_PROJ` | on |
| `SGLANG_AITER_MLA_MAX_SPLITS_PER_BATCH` | unset |

## Accuracy Tests

**Setup for every number below:** 8x MI350X (gfx950, 1000 W), Kimi-K3 (MXFP4 MoE, bf16 attention) at TP8 with EAGLE3
(topk 1, 3 steps, 4 draft tokens), FP8 KV cache, `SGLANG_USE_AITER=1`, aiter's K3 FlyDSL kernels
(`AITER_SITUV2_A8W4=1 AITER_FLYDSL_FORCE=1 SGLANG_AITER_K3_OPT=1`), CUDA graphs for bs 1/2/4/8/16, and an aiter bf16 GEMM table with K3 rows re-tuned on this pod with HBM-resident weights
(`AITER_CONFIG_GEMM_BF16`; not part of this PR, it belongs in aiter's model configs). EAGLE3 on K3 needs the
aux-capture commit of #43599, applied locally for these runs. Microbenchmarks rotate their weights through HBM.
Per-feature numbers were measured on the integration branch of this series as each piece landed (Oct 13-14,
earlier `main`); the end-to-end numbers are from the integration of all seven PRs rebased on `main` b67785153a,
together with #43599's aux capture, #41867 and #41848.

- GSM8K 400: fp8 verify query 0.9875 / accept 3.612 vs bf16 query 0.985 / 3.616; with the fused epilogue 0.985 /
  3.625; non-speculative decode through the split path 0.99 (200). End-to-end integration: see below.
- `test_mla_decode_gfx950.py` (new): the prep kernel is byte-identical to cat + pad + fp8 KV write (incl. a padding
  token and a NaN row 0); split combine matches `aiter.mla_reduce_v1` (one chunk and > 128 splits); W_vc + gate keeps
  the bmm's and the gate's bf16 rounding; the epilogue matches split combine + W_vc + gate; norm + q_b projection
  matches aiter's rounding.

## Speed Tests and Profiling

- Per verify cycle (C1, 24 MLA layers): prep 7 launches -> 1 (cycle 20.1 -> 19.4 ms); split combine 25.6 -> 15.4 us
  in-server; fp8 query 42.6 -> ~24 us per verify call (cycle 18.35 -> 17.87 ms).
- Non-speculative decode, C1: prep 16 -> 4.5 us, fp8-query asm stage 1 40.1 -> 16.9 us, combine 12.8 -> 7.4 us:
  TPOT 13.21 -> 11.80 ms.
- Epilogue vs split combine + W_vc + gate (24 rotating layers): 1 row 9.73 -> 8.86 us, 4 rows 12.97 -> 11.08,
  16 rows 16.75 -> 14.41, 64 rows 27.61 -> 17.82.
- q_a / kv_a norm + q_b: 1 row 6.73 -> 4.99 us, 4-16 rows -4..-9% vs aiter `fused_qk_rmsnorm` + the tuned GEMM.
