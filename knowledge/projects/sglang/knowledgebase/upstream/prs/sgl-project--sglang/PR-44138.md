# [Fix] moe: gated NVFP4 MoE intermediate alignment for FlashInfer TRTLLM

[Upstream PR](https://github.com/sgl-project/sglang/pull/44138) · state: open · merged: False

## Original PR description

## Summary

Gated NVFP4 experts using FlashInfer TRTLLM currently round each intermediate partition to a multiple of 128 before the quantization method allocates weights. This unnecessarily expands a 192-wide partition to 256. The gated FP4 layout needs 64-aligned intermediate partitions because gate and up are combined.

Let the NVFP4 method select alignment before allocating weights and scales: 64 for gated TRTLLM layout, 128 otherwise. Keep the existing generic TRTLLM alignment for other quantization methods and synchronize the runner configuration with the allocated dimensions. No new base-class API is introduced.

## Memory impact

Measured on 4x B200 with a 48-layer, 512-expert gated NVFP4 MoE model at TP4 (rank-local intermediate 192), FlashInfer TRTLLM MoE, identical launch configuration and `mem_fraction_static` for both runs; only this PR's source differs. Per GPU (all four ranks identical):

| | Before | After | Change |
|---|---|---|---|
| Target model weights after load | 29.14 GB | 22.86 GB | **-6.28 GB** |
| `max_total_num_tokens` | 11,610,688 | 12,311,616 | **+700,928 (+6.0%)** |
| Attention KV cache (K+V) | 66.44 GB | 70.44 GB | +4.00 GB |
| Mamba cache slots | 2082 | 2203 | +121 (+5.8%) |

The weight reduction matches the removed MoE padding (192 -> 256 per rank across 48 layers x 512 experts, 6.33 GiB). Total device usage at startup is unchanged; the freed memory goes to the KV and Mamba caches.

## Validation

- B200: real checkpoint-shard loading, weight processing and TRTLLM forward against the existing independent dequantized reference at intermediate widths 160, 192, 256 and 1024.
- New regression fails on the unchanged baseline for widths 160 and 192 (256 allocated instead of 192).
- Constructor checks preserve 128 alignment for non-gated NVFP4, FP8 and unquantized TRTLLM paths.
- All applicable pre-commit hooks pass (formatting, lint, AST, CI registration and secret checks).
