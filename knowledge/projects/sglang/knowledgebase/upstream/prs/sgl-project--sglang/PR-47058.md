# [Perf] spec: Size DFlash draft KV by Mamba checkpoints

[Upstream PR](https://github.com/sgl-project/sglang/pull/47058) · state: open · merged: False

## Original PR description

## Motivation

Stacked on #47057, so only the last commit is new here.

A DFlash draft gets one KV slot per target token, even when all its layers use sliding-window attention. On a Mamba-hybrid target, a cached prefix resumes from a Mamba checkpoint, so the draft only needs the window before each checkpoint plus what running requests hold. On Qwen3.8-27B the draft pool is 8.60 GB, and most of it holds KV that no cached prefix resumes from.

## Modifications

- `--speculative-draft-kv-bundling` gives a target without SWA layers an SWA side for its all-sliding DFlash or DSpark draft. The target allocator becomes an `SWATokenToKVPoolAllocator` over the target pool, the draft keeps every layer's KV on the SWA side, and draft writes go through the full-to-SWA mapping. The flag also turns on #47057's checkpoint windows for that side (note that the scheduler now sees the stack as hybrid SWA, so its KV usage stats include the draft pool).
- The draft pool holds `M*W' + max(0, C_run(R) - p*R*W', C_run(1) - p*W')` tokens, capped at one slot per target token, and the rest of the budget goes to the target KV cache. Here M is the number of Mamba slots, W' the page-aligned draft window, `C_run(r)` the existing SWA request cap with r running requests, and p the Mamba slots a running request holds outside the tree.
- With HiCache, the draft gets an SWA host pool of one window per host Mamba slot, and auto-sizing accounts for it.
- The TRT-LLM MHA encoder-only verify path reads the SWA page table for SWA layers.
- The flag needs `--speculative-algorithm` DFLASH or DSPARK, a Mamba target without sliding-window layers, an all-sliding MHA draft, chunked prefill, and a CUDA or ROCm device, and can't be combined with unified memory, HiSparse, int8 Mamba checkpoints, PD disaggregation, or DCP.

## Accuracy Tests

Qwen3.8-27B on 1xH200 with the `z-lab/Qwen3.8-27B-DFlash2` draft, 8 running requests, and auto Mamba slots:

| | main | this PR |
|---|---|---|
| Draft pool | 450,496 tokens, 8.60 GB | 152,768 tokens, 2.91 GB |
| Target KV tokens | 450,496 | 542,784 (+20.5%) |
| Mamba slots | 67 | 68 |
| GSM8K | 0.970 | 0.975 |
| Accept length | 5.75 | 5.74 |

With HiCache write-back, a prompt whose checkpoint was evicted from GPU reloads its window from host and matches a resident hit in text and accept length. On a B200, a bidirectional DFlash2 draft on `trtllm_mha` gets the same accept length with and without the flag, with CUDA graphs and without. The encoder-only page table test fails on main.

`test_dflash_draft_kv_bundling.py` passes on 1xH200, and the pool configurator, auto-size, SWA allocator, and TRT-LLM metadata tests pass on CPU (80) and 1xL4 (241).

## Speed Tests and Profiling

Draft writes now look up their slot in the full-to-SWA mapping. Throughput wasn't measured.
