## Motivation

<!-- Describe the purpose and goals of this pull request. -->

The DeepSeek-V4 NPU backend still ran the A5 (Ascend 950) port on a request-bank "CYCLE"
state ABI, while every other path uses the explicit per-token state table. That fork carried
its own table builder, its own state-pool sizing and its own PD transfer component, and the
A5 state bugs tracked back to it.

Fixing the ABI alone is not enough. With explicit per-token addressing the C4 compress state
is addressed by SWA page, and `get_compress_state_ring_size(4, is_speculative)` returns 8
without a draft model and 16 with MTP. A prefill worker without a draft model and a decode
worker with MTP therefore produce different item sizes for the same state payload: the C4 rows
land at the wrong offsets and decode resumes from corrupted state. That failure is silent and
surfaces as a precision drop after a PD handoff, never as an error.

This PR moves A5 onto the shared explicit state ABI and gives the C4 state its own PD
component addressed by logical token position, so the two peers may run different ring sizes.
A3 keeps the payload shape it has been validated with.

## Modifications

<!-- Detail the changes made in this pull request. -->

**Compressor state ABI** — `python/sglang/srt/hardware_backend/npu/attention/ascend_dsv4_backend.py`
- Drop `_build_cycle_state_block_table` and `fm.dsv4_cycle_state_block_table`; always use
  `_build_explicit_state_block_table`, including the CUDA-graph refresh path.
- `compressor_op = torch.ops.npu.compressor` unconditionally; the
  `torch.ops.custom.compressor if is_npu_arch35() else ...` selection is gone.
- The state row for a token slot is the op's own
  `translate_from_swa_loc_to_state_loc(swa_loc)`, i.e.
  `(swa_loc // swa_page_size) * ring_size + (swa_loc % ring_size)`.

**State pool** — `python/sglang/srt/hardware_backend/npu/dsv4/dsv4_memory_pool.py`
- A5 no longer inflates the C4 state pool to `max(state_size, num_req_slots * ring_size)`;
  the explicit page-scoped layout does not need a bank per request slot.
- `get_state_buf_infos()` exports the SWA KV buffers, plus the C4 attention and indexer state
  rows at whole-page granularity on A3 only.
- New `get_c4_state_buf_infos()` exports one physical state row per transfer item on A5.

**PD payload** — `python/sglang/srt/hardware_backend/npu/dsv4/dsv4_common_hooks.py`
- New `_c4_state_rows()` maps the compressor history window (the last `coff * ratio` logical
  positions, 8 for C4) through this peer's own SWA locations into this peer's state rows. The
  window depends only on the compressor geometry, so both peers ship the same number of
  equal-sized rows and only the row numbers differ.
- `dsv4_state_payloads()` emits `DSV4_C128` always and `DSV4_C4_STATE` on A5 only. Its
  signature is unchanged.

**PD wiring** — `python/sglang/srt/disaggregation/ascend/conn.py`,
`python/sglang/srt/disaggregation/utils.py`
- Restore the `AscendStateType.DSV4_C4_STATE` component, its two-group PP slicing in
  `get_mla_kv_ptrs_with_pp`, and the `StateType.SWA` slice that the separate component implies.
- Register that component from `setup_state_kv_args` on A5 only.

**Removed** — `python/sglang/srt/mem_cache/deepseek_v4_compress_state.py`
- `c4_state_transfer_indices()`, whose row formula
  (`req_pool_idx * ring_size + pos % ring_size`) only existed to bridge the removed
  request-bank layout.

**Tests**
- `test/registered/unit/disaggregation/test_disaggregation_wire.py`: the C4 index test now
  asserts that ring-8 and ring-16 peers ship the same item count, different row numbers, and
  that every transferred index is unique. A wider window would alias two positions onto one
  ring row and copy the newer row into the older position's destination row.
- `test/registered/unit/npu/attention/test_npu_ascend_dsv4_backend.py`: payload and SWA-content
  assertions are arch-split. A5 ships `DSV4_C4_STATE` with one row per item; A3 keeps the C4
  rows inside the SWA payload.
