# [GLM-5.3-Flash] Fuse the FFN mHC post into the next layer's attention pre

[Upstream PR](https://github.com/sgl-project/sglang/pull/43069) · state: open · merged: False

## Original PR description

## Summary

At decode batch sizes, GLM-5.3-Flash's mHC boundaries are small, latency-bound launches. The attention -> FFN boundary inside a layer is already fused (`hc_ffn_post_pre`); this does the same for the layer -> layer boundary.

- Each layer's FFN `hc_post` is deferred. Its coefficients stay on the layer's `MHCState` until the next layer's attention read fuses them with that layer's `hc_pre` (`hc_attn_post_pre`).
- It reuses the existing post+pre fusion path and its 16-token cap. Larger batches fall back to the unfused post, then pre.
- The last layer still writes back and contracts the streams itself.
- It is gated by the existing `SGLANG_OPT_FUSE_MHC_POST_PRE`, and off under PP > 1, TBO and `--enable-attn-tp-input-scattered`.
- The rejections of attention-CP and MoE-CP gathers, and of input-scattered attention under CP, now key on any non-plain FFN update, so they also cover the deferred one.
- `hc_ffn_post_pre` and `hc_attn_post_pre` share one helper.
