# [router] Break the SSE pump on client disconnect even while the upstream is pending

[Upstream PR](https://github.com/sgl-project/sglang/pull/30530) · state: closed · merged: False

## Original PR description

## What

The router's SSE forwarding pump (`bytes_stream_to_body`) only noticed a client disconnect via `tx.send()` returning `Err`, i.e. after the next upstream chunk arrived. This races the next chunk against `tx.closed()` in a `tokio::select!`, so the pump stops the instant the client goes away.

## Why

In the common token-streaming case the pump is usually parked on `s.next().await`, waiting for the worker's next token. If the client disconnects while it waits, the old code did not notice until the next token arrived (and, when the upstream was faster than the client, up to the 64-slot channel bound of chunks could be read first). Breaking promptly lets us drop the upstream stream, which closes the worker connection so the worker can abort its own in-flight work: the connection-drop propagation that OpenAI-compatible clients and fronting proxies already expect.

## How

```rust
let chunk = tokio::select! {
    biased;
    _ = tx.closed() => break,          // client dropped: stop now
    maybe = s.next() => match maybe { Some(c) => c, None => break },
};
```

The bounded channel and its backpressure are unchanged, and the existing `tx.send().await.is_err()` break is kept as a backstop.

## Testing

Adds `bytes_stream_to_body_breaks_on_disconnect_while_upstream_pending`: it feeds one chunk, then leaves the upstream `Pending` forever, drops the client, and asserts `on_complete` fires within 500ms. Without the select! branch the pump parks on `s.next()` forever and the test trips its timeout. All existing SSE tests (passthrough, first-byte, panic propagation, backpressure-on-disconnect) are unchanged and pass.
