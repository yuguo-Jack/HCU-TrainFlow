# [Feat] hicache: Enable validated dynamic storage backends with DCP

[Upstream PR](https://github.com/sgl-project/sglang/pull/45763) · state: open · merged: False

## Original PR description

## Motivation

HiCache rejects dynamic storage backends under DCP even when a plugin implements the required MLA shard and page mapping. Allow a plugin to opt in through an explicit, validated contract, including hybrid state and MLA draft pools.

Builds on the merged #41187. Rebased onto `main` at `74c08f3dc5d98dddf052ba03122fc084a31a0269`; the PR contains only the two implementation/documentation commits.

## Modifications

- Validate class-declared capabilities and the complete materialized pool geometry before constructing a dynamic backend. Require shard-aware MLA handling and the appropriate hybrid-state/checkpoint or draft capabilities. Legacy DCP1 plugins keep their existing path.
- Register all initial pools and finalize before starting storage workers; validate late sidecars before publishing them. Preserve the upstream DCP `buffer_only` rejection and logical-token prefetch accounting.
- Retain resources after failed worker shutdown or explicit native-memory cleanup, and reject reattachment until cleanup succeeds. Require a model-process restart after non-transactional partial bookkeeping cleanup. Document these contracts and failure outcomes.

Provider implementations and deployment configuration are outside this PR.
