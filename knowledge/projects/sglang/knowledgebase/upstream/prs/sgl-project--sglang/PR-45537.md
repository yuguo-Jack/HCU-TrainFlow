# [Perf] dcp: Vectorize the per-request reorder in the MHA extend KV gather

[Upstream PR](https://github.com/sgl-project/sglang/pull/45537) · state: open · merged: False

## Original PR description

## Motivation

Fixes #45535.

`all_gather_kv_cache_for_mha_extend` (DCP prefix-hit extend path) rebuilt the query-ordered KV by slicing each request's prefix/extend rows in a Python loop using **0-dim CUDA tensors as slice bounds**. Each bound is a D2H sync: up to `4 * batch_size` syncs per layer per extend step, stalling the CPU and starving the GPU.

## Modifications

Replace the loop with a sync-free scatter: `get_extend_query_order_indices` builds output positions on-device (`repeat_interleave` with `output_size`, two `cumsum`s), rows are written with two `index_put_`. Output ordering and the fp8-prefix -> extend dtype alignment are unchanged. `seq_lens` (only used for `len()`) is dropped from the signature and both callers.

## Accuracy Tests

Order-preserving by construction; CPU unit test pins the index math against the legacy loop (incl. zero-prefix / zero-extend requests), and a 1-GPU test asserts no sync under `set_sync_debug_mode("error")`.

## Speed Tests and Profiling

8x H20, torch 2.13.0+cu130, flashinfer 0.6.18. Baseline = `a8edaff`.

**Micro-bench** (reorder only, 1 GPU, prefix=4096, extend=1024). Legacy syncs on every config, vectorized never; launches `4*bs+19` -> constant 29.

| bs | legacy (us) | vectorized (us) |
|---:|---:|---:|
| 1 | 204 | 299 |
| 16 | 2 163 | 300 |
| 64 | 8 545 | 2 032 |
| 128 | 17 185 | 3 998 |

**Profiler** (DeepSeek-V2-Lite TP2/DCP2, GSP dataset, 3 steps, TP-0): `cudaStreamSynchronize` 1 173 -> 93, `Memcpy DtoH` 1 084 -> 4 (-1 080 = 4 x 27 layers x 10 extend reqs); GPU idle 298.6 -> 199.3 ms (-33%).

**E2E TTFT p50** (same server, `--chunked-prefill-size 8192 --kv-cache-dtype fp8_e4m3`, `--request-rate inf`):

| Scenario | baseline | vectorized | delta |
|---|---:|---:|---|
| gsp 4k, conc 64 | 3 617 ms | 3 425 ms | -5.3% |
| gsp 4k, conc 32 | 796 ms | 708 ms | -11.1% |
| gsp 8k, conc 64 | 5 789 ms | 4 886 ms | -15.6% |
| random 4k, conc 64 (control, no prefix hit) | 867 ms | 883 ms | noise |
| random 8k, conc 64 (control) | 11 119 ms | 11 275 ms | noise |

Throughput and ITL unchanged.
