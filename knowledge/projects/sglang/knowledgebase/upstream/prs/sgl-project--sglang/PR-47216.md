# [Fix] [NPU] dspark: Avoid double-counting verify KV lengths in graph replay

[Upstream PR](https://github.com/sgl-project/sglang/pull/47216) · state: closed · merged: True

## Original PR description

## Motivation

NPU full-graph replay double-counts the verify block when DSPARK supplies a live CPU KV-length mirror. `DsparkTargetVerifier.run_non_compact()` already publishes `prefix_length + verify_width` in `batch.seq_lens_cpu`, but the graph replay fallback adds `captured_req_width` again.

For example, a prefix of 1000 tokens and a verify width of 8 should pass a KV length of 1008 to FIA; replay currently passes 1016. The MLA verify path uses right-aligned causal attention (`sparse_mode=3`), so the incorrect KV length shifts the causal boundary and can expose future candidates and cache positions outside the valid sequence. This corrupts target logits and speculative verification.

The existing metadata-list shortcut only handles `is_dflash()`, so DSPARK reaches this fallback.

## Modifications

Use the live CPU mirror directly for DFlash-family algorithms, including DSPARK, since it already includes the verify block. Other speculative algorithms keep the existing width compensation, and the device-length fallback is unchanged.

This PR changes only the graph replay length calculation; it does not include DCP changes or sampling-kernel changes.

## Accuracy Tests

Previously completed local validation on the `9f6678aa3d6b` baseline, before preparing this PR:

- CPU contract checks using the actual DSpark producer and graph-consumer code: 18 checks passed, including reproduction of the old double-add, CPU int32/int64 mirrors, padded graph batches, the device fallback, and non-DFlash-family compensation.
- Kimi-K3 on 4 Ascend NPU nodes, TP64, attention DP4, DCP1, DSPARK block size 7, attention mode `decode`, full decode graph, temperature 1.0, top-p 0.95: the original run scored 4/20 on a fixed GPQA subset. With only this graph-length fix, 16 of the 17 completed questions were correct before the run was stopped at the user's request. On those same 17 questions, the original run scored 4/17. Both runs retained the same sampling compatibility implementation and other settings.

The fixed run is a partial diagnostic result, not a completed 20-question evaluation or a full GPQA benchmark. No additional tests or NPU service restarts were performed when preparing this PR, and no new test files are included.
