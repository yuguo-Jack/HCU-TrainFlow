# [Test] [NPU] deepseek_v4: Replace 8K perf case with 128K 1P1D case and add L2 host hit-rate checks

[Upstream PR](https://github.com/sgl-project/sglang/pull/48160) · state: closed · merged: True

## Original PR description

## Motivation

Replace 8K perf case with 128K 1P1D case, and adds an L2 host hit-rate assertion to the DSV4-Flash and DSV4-Pro accuracy tests.

## Modifications

- Added `test/registered/npu/performance/deepseek_v4_flash/test_npu_deepseek_v4_flash_w8a8_1p1d_16p_in128k_out1k_prefix90_20ms.py`
  - New nightly perf case `TestNPUDeepSeekV4FlashW8A81P1D16PIn128kOut1k20ms`, registered via `register_npu_ci(est_time=3600, suite="", nightly=True)`.
  - 1P1D PD-separation with 16 NPUs per node: prefill `--tp-size 16 --dp-size 4 --enable-dp-attention --enable-prefill-cp --cp-strategy zigzag`; decode `--tp-size 16 --dp-size 16 --enable-dp-attention`. DeepEP (`normal` on prefill, `low_latency` on decode), `modelslim` W8A8 quantization, `dsv4` attention backend, bf16 KV cache, `--enable-metrics --enable-cache-report` on both nodes.
  - Prefill serving config: `--page-size 128`, `--mem-fraction-static 0.62`, `--max-prefill-tokens 70000`, `--chunked-prefill-size 32768`, `--disable-cuda-graph`, `--optimistic-prefill-attempts 1`, `--load-balance-method round_robin`.
  - Decode serving config: `--page-size 128`, `--mem-fraction-static 0.71`, `--swa-full-tokens-ratio 0.05`, `--cuda-graph-bs-decode 1 2 3 4 6 7 8 10`, `--load-balance-method round_robin`.
  - Both nodes pass `--json-model-override-args '{"use_index_cache":true,"index_topk_freq":2}'` and `--tokenizer-worker-num 16`; prefill additionally sets `--expert-distribution-recorder-mode stat --expert-distribution-recorder-buffer-size 512`; the router uses `--policy cache_aware`.
  - Decode enables DSPARK speculative decoding: `--speculative-algorithm DSPARK`, 6 draft tokens, `--speculative-dspark-block-size 5`; the draft model is the same DSV4-Flash-0731 W8A8 checkpoint (`modelslim` quantization, `ascend` attention backend).
  - Prefill uses `--init-expert-location expert-layout-ais-replicas16.json` together with `--ep-num-redundant-experts 16` and `--ep-dispatch-algorithm dynamic`.
  - Prefill and decode use separate env sets (DeepEP buffer sizes, WAR barrier, multi-stream, etc.).
  - Workload: `generated-shared-prefix`, 90 prompts, `input_len` 131072, `output_len` 1024, `repeat_rate` 0.9, `max_concurrency` 55, `request_rate` 3, `seed` 1, `random_range_ratio` 1, `warmup_requests` 16, `benchmark_tool = BENCHMARK_TOOL_DEFAULT`.
- Added `test/registered/npu/performance/deepseek_v4_flash/expert-layout-ais-replicas16.json`: `physical_to_logical_map` with 43 rows x 272 columns, consumed by `--init-expert-location` and used with 16 redundant expert replicas.
- Updated `.github/workflows/nightly-test-npu.yml`: the DSV4-Flash W8A8 1P1D 16P perf entry is renamed from `deepseek_v4_flash_w8a8_1p1d_16p_in8k_out1k_50ms` to `deepseek_v4_flash_w8a8_1p1d_16p_in128k_out1k_20ms`, and its `test_case` now points to the new `..._in128k_out1k_prefix90_20ms.py`.
- Removed `test/registered/npu/performance/deepseek_v4_flash/test_npu_deepseek_v4_flash_w8a8_1p1d_16p_in8k_out1k_50ms.py`, which is superseded by the long-context case.
- Extended the GPQA PD-separation accuracy jobs with an L2 host cache hit-rate check:
  - `test/registered/npu/accuracy/deepseek_v4_flash/test_npu_deepseek_v4_flash_0731_w8a8_1p1d_16p_gpqa.py` (`test_npu_deepseek_v4_flash_0731_w8a8_1p1d_16p_l2_host_hit_rate`)
  - `test/registered/npu/accuracy/deepseek_v4_pro/test_npu_deepseek_v4_pro_0813_w4a8_1p1d_32p_gpqa.py` (`test_npu_deepseek_v4_pro_0813_w4a8_1p1d_32p_l2_host_hit_rate`)
  - Both reuse the deployment already launched by the accuracy case (`self.host` / `self.port`, model path from `model_config`), so no extra server launch is needed.
  - Each runs a 32K `generated-shared-prefix` bench via `run_bench_serving`: 3 groups x 32 prompts, `input_len` 32000, `output_len` 1024, `max_concurrency` 32, `seed` 100, `warmup_requests` 16, `cache_report=True`.
  - `min_hit_rate_pcts = {"host": 0}` is checked by `assert_metrics`, which asserts strictly greater than 0% and fails if the host tier line is missing (e.g. cache report not enabled).
  - The workload shares a 28800-token system prompt (32K x 0.9) plus a 3200-token question, which exceeds L1 so evictions land in L2.

## Accuracy Tests

The existing GPQA accuracy assertions are unchanged. Both GPQA PD-separation cases now additionally require a non-zero L2 host cache hit rate on the 32K GSP workload described above, so a regression in host-side prefix caching fails the nightly accuracy job.

## Speed Tests and Profiling

The new perf case runs the 128K/1K shared-prefix workload described above. Baselines and the effective assertion bounds applied by `assert_metrics` are:

| Metric | Baseline | Effective bound |
| --- | --- | --- |
| Mean TTFT | 7000 ms | <= 7140 ms (+2%) |
| Mean TPOT | 20 ms | <= 21 ms (20 + 1 ms, since TPOT < 50 ms) |
| Output token throughput | 964.864 tok/s | >= 945.57 tok/s (-2%) |
