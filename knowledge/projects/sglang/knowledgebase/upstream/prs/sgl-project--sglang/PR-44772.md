# [Fix] scheduler: Wait for idle before completing abort-mode pause

[Upstream PR](https://github.com/sgl-project/sglang/pull/44772) · state: open · merged: False

## Original PR description

## Motivation

Fixes #44745.

A streamed client can disconnect and release its tokenizer reader lock while its request is still active in the scheduler. `pause_generation(mode="abort")` previously returned success as soon as that lock was free, although the abort was fire-and-forget and scheduler cleanup was incomplete. An immediate `release_memory_occupation` then hit its idle assertion and killed the scheduler.

## Modifications

- Add an internal scheduler-idle probe using the existing fan-out communicator.
- In abort-mode pause, wait for both the tokenizer reader lock to clear and every scheduler replica to report `is_fully_idle()`.
- Keep scheduler inference enabled during the wait so normal abort cleanup, including overlap results, can drain. Retain the memory-release idle assertion.
- Share the abort drain helper between TokenizerManager and the multi-HTTP-worker override, so both paths wait for scheduler cleanup.
- Shield each in-flight probe from caller cancellation and retain it in the manager task set. The existing communicator FIFO lock stays held until all replies drain, preventing stale replies from satisfying a retry.
- Add seven CPU regression tests covering disconnect cleanup, all-replica idle checks, tokenizer readers, other pause modes, the full-idle predicate, multi-HTTP-worker pause, and cancellation/retry with delayed responses from two scheduler replicas.
