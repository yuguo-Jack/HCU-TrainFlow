# [Perf] [NVIDIA] dflash: Split SWA MLA value columns on GB300

[Upstream PR](https://github.com/sgl-project/sglang/pull/46471) · state: open · merged: False

## Original PR description

## Motivation

Causal DFlash MLA drafts can expose too little parallel work during short-block SWA attention. Split the 512 output value columns across CTAs while retaining the native sequential softmax recurrence.

**Stacked on #44676 at `2c95c09bfa9cb13206f005154d4e9c75ad1c5e28`.** This PR targets `main` because the dependency branch lives in the author's fork. Merge #44676 first, then rebase this PR. The [incremental diff](https://github.com/maocheng23/sglang/compare/2c95c09bfa9cb13206f005154d4e9c75ad1c5e28...f87521086ba6ad92b1217d0e4933acd846d46334) is limited to five files.

## Modifications

- Add a Triton value-column split kernel for BF16 absorbed MLA (`QK=576`, `V=512`), causal window 4096 and draft block 8. Each CTA repeats QK/softmax for its value columns; prefix/current-token loops retain native M16/N64 tiles, BF16 probability conversion and FP32 accumulation. No split-KV reduction or scratch buffer is needed.
- Add `SGLANG_OPT_DFLASH_SWA_MLA_VALUE_SPLIT=1`, **off by default**. Dispatch is restricted to GB300 (SM103), DFlash draft MLA on Triton, DCP1, and these measured `(local heads, batch) -> value partitions`: `(12,1) -> 8`, `(24,1) -> 4`, `(12,4) -> 2`. Other shapes and unsupported attention options retain native dispatch, including deterministic mode, custom masks, sinks and scaling.
- Add CPU dispatch/fallback coverage and GB300 tests for native equality, an independent FP32 reference, ragged/tile/window boundaries, strides, causal masking and CUDA graph metadata changes. Register the GPU suite on the existing `base-c / 2-gpu-gb300` lane.

Enable before server startup:

```bash
export SGLANG_OPT_DFLASH_SWA_MLA_VALUE_SPLIT=1
# Use with the existing DFlash MLA launch arguments:
# --speculative-draft-attention-backend triton
# --speculative-draft-kv-cache-dtype bf16
```

The draft export must already describe causal sliding attention with window 4096 and block 8; the environment flag does not change model semantics.

## Speed Tests and Profiling

The following measurements use the historical GPU-validated revision above. Fixed real-weight five-layer draft backbone, TP4 (24 local heads), BF16, batch 1, prefix 4095, block 8, window 4096:

| Execution | Native ms | Value split ms | Speedup |
| --- | ---: | ---: | ---: |
| CUDA graph | 3.679992 | 3.076570 | 1.196x |
| Eager | 9.110528 | 8.888128 | 1.025x |

Median of three repetitions; each repetition times 20 forwards and uses the maximum rank mean CUDA latency. The graph result is **16.4% lower latency**. Timing includes the five draft layers, current-block cache writes and TP communication. It excludes target execution, context preparation, embedding lookup, logits/selection and scheduling. This is one backbone fixture, not end-to-end serving tokens/s, acceptance length or answer accuracy.

Single-GPU attention shapes at prefix 4095:

| Local heads | Batch | Partitions | Native us | Value split us | Speedup |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 12 | 1 | 8 | 530.454 | 358.986 | 1.478x |
| 24 | 1 | 4 | 535.472 | 373.219 | 1.435x |
| 12 | 4 | 2 | 542.589 | 400.409 | 1.355x |

The 12-head rows are attention shapes, not a distributed TP8 serving benchmark. Both paths use the existing SWA prefix truncation.
