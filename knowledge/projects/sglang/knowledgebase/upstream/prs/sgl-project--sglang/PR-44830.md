# [Perf] [NVIDIA] attention: Add opt-in table-gated CUDA verify for Frozen-KV MTP

[Upstream PR](https://github.com/sgl-project/sglang/pull/44830) · state: open · merged: False

## Original PR description

> Depends on #44466 and #44468, whose commits are the first two here. Please review only the last commit. I'll rebase once they land.

## Motivation

With Frozen-KV MTP (Gemma 4) on CUDA, the Triton backend runs target verify through `extend_attention_fwd`, which walks the whole prefix serially for every few draft tokens. On H20 with Gemma-4-12B at bs 128, that is 5.45 ms of attention per verify round. The split-KV verify kernels already cover this case on gfx95. This PR enables them on CUDA for the shapes I've validated.

## Changes

- New opt-in env var `SGLANG_ENABLE_CUDA_VERIFY_SPLITKV` (default off).
- `TritonAttnBackend` sends a target-verify layer to the new path only when all of these hold: Frozen-KV MTP target, topk=1, causal BF16 without KV scales, and a shape/width/GPU arch that has an entry in the tile table. Everything else stays on `extend_attention_fwd`.
  - full-attention layers with one KV head → `verify_shared_kv_fwd`
  - sliding-window layers → `verify_splitkv_fwd`
- The tile tables in `verify_mla.py` and `verify_splitkv.py` decide eligibility and also supply the launch parameters, so the two can't drift apart. There are entries for SM89 and SM90 only.
- `verify_splitkv` gains sliding-window support (a per-query left bound), and `verify_mla` handles an empty prefix.
- AMD paths are unchanged.

About 210 lines of the diff are code; the rest is tests.

## Results

H20, Gemma-4-12B BF16, TP1, NEXTN (steps 2, topk 1, 3 draft tokens).

Attention time per verify round: **5.45 → 1.75 ms**.

Throughput on C4 prompts with 128 output tokens, three alternating repetitions:

| input | batch | off (tok/s) | on (tok/s) | change |
|---|---|---|---|---|
| 256 | 1 | 137.1 | 177.4 | +29% |
| 256 | 8 | 698.3 | 874.8 | +25% |
| 256 | 128 | 1078.9 | 1481.7 | +37% |
| 4096 | 128 | 128.0 | 147.3 | +15% |

GSM8K, 400 questions, temperature 0: 382 without spec, 383 with the flag off, 384 with it on. Accept length is 2.81 in both cases. Outputs are not bit-identical to the extend kernel, because the reduction order differs.

Kernel tests: 55 pass on H20 (SM90) and RTX 4090D (SM89). They cover FP64 references, paged KV, and CUDA graph replay, including switching between empty and non-empty prefixes. CPU routing tests cover every fallback case.

Tiles: I swept 240 configs of the SWA kernel on H20 and 4090D. The existing `(32, 4)` default was the best or within noise, so I kept it.

## Relation to #39316

#39316 removes the gfx95 gate on the per-head split-KV path for all topk=1 spec, which covers GQA full-attention layers. This PR covers the other two layer types (single-KV-head full attention and SWA), and only for Frozen-KV. The two are complementary. Two things worth aligning:

1. `SGLANG_ENABLE_SPLITKV_VERIFY` and this PR's flag are easy to confuse. I'm happy to rename mine or merge them into one.
2. Split-KV is not bit-identical to the extend kernel, so the "bit-equivalent" comment in that path should change.

## Not covered

Tested on a single H20 and a single 4090D, TP1 only. Other per-rank head layouts fall back to the extend kernel until they get tile entries.
