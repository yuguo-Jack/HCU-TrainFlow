## Motivation

<!-- Describe the purpose and goals of this pull request. -->

Improve the embedding and prefill-only scoring paths by preserving native-dtype embedding outputs, removing avoidable metadata and padding work, and making raw-K/V attention selection agree with the existing no-cache opt-in.

This combines four changes on current OSS `main`. The implementation commits remain separate to make each change reviewable.

Updated to `main` at `20036b7a` (merge commit `dc960f09`). `main` now carries per-request stats in `request_stats`, so `BatchEmbeddingOutput` keeps that field and adds only the PR's `tensor_embeddings`.

## Modifications

<!-- Detail the changes made in this pull request. -->

1. **Native tensor embedding output.** Add optional `encoding_format` after `dimensions` in `Engine.encode()` and `async_encode()`, matching the source port without a keyword-only restriction. For dense outputs, `None` and case-insensitive `"float"` preserve list responses; other format strings retain detached CPU tensors at the model's output dtype. Carry the format through batch slicing, tokenization, scheduler admission, and mixed batches. Keep `_convert_embeddings` and `_convert_embedding_for_response` as separate steps, as in the source port. Use a dedicated typed IPC tensor field compatible with msgspec and preserve it through multi-tokenizer routing and response reconstruction. Do not add request-format normalization or HTTP/sparse-head rejection beyond the source port.
2. **Host-side FlashInfer MIS metadata.** Build relative positions, padding, and per-item maxima on the CPU, where delimiter indices already reside. Transfer each completed metadata tensor to the device once, preserving metadata dtypes, shapes, prefix-cache offsets, and position updates.
3. **Explicit FA raw-K/V gate.** Require `get_schedule().prefill_only_disable_kv_cache` in `fa_skip_kv_cache`, retaining the existing embedding, unchunked-prefill, disabled-radix-cache, and non-MLA conditions. Internal auto-enables such as EmbeddingGemma continue to work.
4. **Skip padded-tail zeroing for unquantized dense CUDA models.** Avoid per-layer tail-zeroing operations only on CUDA, for models with no MoE layers and no quantization (`quant_config` and `model_config.quantization` both unset). Retain zeroing for non-CUDA devices, CUDA MoE (including mixed dense/MoE layer lists), and every quantized model: the eager attention output tail is uninitialized graph-pool memory, and per-tensor dynamic activation quantization reduces its amax over all padded rows. Preserve the separate idle-rank/zero-real-token output-zeroing path.

**Intentional behavior change:** embedding configurations that previously selected raw-K/V attention implicitly now use paged attention unless `--prefill-only-disable-kv-cache` is enabled. Already-opted-in configurations retain their existing path.

**Scope:** unrelated VSA imports, FastAPI telemetry, and HiCache fixes and their tests are excluded. Existing attention and multimodal tests receive only the fixture fields required by the ported code (`moe_layers=[]` and `encoding_format=None`). The GPU tensor-encoding regression comes from the source port; the additional encoding unit-test file and padded-tail test cases are removed.

The tensor format is an in-process API, not a new JSON wire encoding:

```python
# Using an already initialized dense embedding engine:
result = engine.encode("A short document", encoding_format="tensor")
embedding = result["embedding"]  # CPU torch.Tensor, preserving output dtype
```
