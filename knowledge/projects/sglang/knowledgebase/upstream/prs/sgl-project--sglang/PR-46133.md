# [Fix] minimax-m3: Type nested tool-call arguments and count self-opened reasoning

[Upstream PR](https://github.com/sgl-project/sglang/pull/46133) · state: closed · merged: True

## Original PR description

## Summary
Fixes in the MiniMax-M3 tool-call parser and chat serving: type tool-call arguments nested in schema-less containers, and count reasoning tokens when the model opens the reasoning block itself.

## Changes to existing code
These apply to every model:
- `Function.strict` defaults to `None` and is left out of the rendered tool schema when unset; it was `False` and always injected.
- Tool schemas keep the key order the client sent.
- An image `detail` of `"default"` is read as `"auto"`.
- The `root` role is accepted alongside `system` and `developer`.
- A `thinking` request field is accepted; only chat templates that define a thinking mode read it.
- Usage reports reasoning tokens in `completion_tokens_details.reasoning_tokens`, set only when there are some.
- `ModelConfig.self_opened_think_start_ids` defaults to `None`; the scheduler fills it only when a reasoning parser is configured.

MiniMax-M3 only: the request's own `thinking`, `reasoning_effort` and `chat_template_kwargs` settle `thinking_mode` and the effort before `--default-chat-template-kwargs` fill what the request left unset, so a server default never re-enables thinking the request turned off.

## Verification
- test_minimax_m3_detector, test_reasoning_parser, test_serving_chat, test_protocol, test_batch_result_processor_*, test_model_config (reasoning-token fields exist without a reasoning parser)

Cut byte-for-byte from #45925 (MiniMax-M3.1-Flash support) at 10e655aa98.
