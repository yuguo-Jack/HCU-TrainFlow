# [Fix] disaggregation/nixl: Heterogeneous-TP KV slice with heads replicated on both sides

[Upstream PR](https://github.com/sgl-project/sglang/pull/46354) · state: open · merged: False

## Original PR description

## Motivation

Two problems in the NIXL heterogeneous-TP KV slice path (`NixlKVManager._init_hetero_tp_prep_handle`):

1. **Head-group count is 0 when both sides replicate KV heads.** For `prefill_tp < decode_tp` the shared source dlist interleaves one group per unique head slice, counted as `decode_tp // prefill_tp // dst_replication`. When prefill *also* replicates heads, that is 0. Example: 2 KV heads (Qwen3.5-style), prefill TP4 -> decode TP8: `8 // 4 // 4 == 0`, and `assert page_size * num_groups * bytes_per_token_to_send == src_kv_item_len` fires when the decode peer registers.
2. **The slice runs assume token-major (NHD) rows.** The strided runs address `[token][head][dim]` rows. A pool with any other byte layout gets wrong bytes, and nothing reports it. No in-tree pool hits this today: the only pool that declares a PD layout, DeepSeek-V4's, is MLA and never takes this path. Out-of-tree pools can hit it.

## Modifications

- Count the groups from the heads the prefill rank actually holds: `num_groups = src_heads_per_rank // num_heads_to_send`, and `head_group_idx = src_head_start // num_heads_to_send`. When prefill does not replicate this matches the old value, so the non-replicated cases and the existing #31295 regression test are unchanged.
- If the manager's `kv_layout` (from `get_pd_kv_layout`) is not `None`, raise `NotImplementedError` with a clear message instead of building NHD runs. A `None` layout means the default MHA pool, which is NHD. This raises at peer registration, the same place the existing "direct-to-host heterogeneous-TP" refusal raises.
- New CPU test `test/registered/unit/disaggregation/test_nixl_hetero_tp_kv_slice.py`. It replays the prepared dlists (`_expand_stride_descs` + `expand_page_indices_for_slice`, which is what `send_kvcache_slice` posts) against NHD byte buffers. It then checks every decode rank's K/V pages for every shardable (prefill TP, decode TP) pair, for 2 and 8 KV heads and page sizes 1 and 2.

## How it was found

While building an out-of-tree Neuron/Trainium platform plugin, we compared upstream's slice math with a CPU harness across 920 heterogeneous KV cases. Most failures were layout failures, because the Neuron pool is head-major inside a page (see point 2). The 100 assertion errors were the replicate-on-both-sides cases from point 1, and they reproduce on NHD buffers too. The new test reproduces them on upstream `main`: before this change, `TestNixlHeteroTpBothSidesReplicate` and the `heads=2, p_tp=4, d_tp=8` grid cases fail with the geometry `AssertionError`, and the layout test fails because nothing is raised. All other grid cases already passed on `main`.

## Open questions

- Pool layouts other than NHD are refused here. A follow-up could *honor* a declared layout instead. For a head-major-in-page layout (`[page][head][token][dim]`), a head range of a page is one contiguous run, so the dlists actually get simpler. That needs a layout vocabulary (see the companion pool-declared `pd_kv_layout()` PR).
- `prep_handle_slice_src` is built once from the first decode peer and reused for every later peer. If decode servers with *different* attention TP sizes attach to the same prefill, `num_groups` can differ per peer and the shared dlist would be wrong. This is pre-existing and not changed here. Should it be keyed by `num_groups`, or rejected?
- The staging-buffer path (`compute_staging_layout`) was not audited for the replicate-on-both-sides case.
