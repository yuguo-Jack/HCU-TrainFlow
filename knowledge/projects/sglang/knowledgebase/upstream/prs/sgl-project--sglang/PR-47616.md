# [Feat] cache: add concurrent Mooncake linker prefetch control

[Upstream PR](https://github.com/sgl-project/sglang/pull/47616) · state: open · merged: False

## Original PR description

## Motivation

Allow an orchestrator to warm a stored token prefix from Mooncake into a worker's GPU radix tree while that worker continues inference. The caller supplies complete token IDs and optional cache salt; missing KV is not computed. Companion Dynamo API: https://github.com/ai-dynamo/dynamo/pull/17749 (stacked on ai-dynamo/dynamo#17093).

The Dynamo prefetch and pin/unpin PRs supply active KV commands for programmable KV. [Dynamo hint policies #17359](https://github.com/ai-dynamo/dynamo/pull/17359) provide the policy extension point; this PR supplies the SGLang prefetch execution path.

## Modifications

- Add `Engine.prefetch`, `Engine.async_prefetch`, tokenizer control messages and administrative `POST /prefetch`. Validate IDs/context length/salt, drain replies after caller cancellation, and aggregate all-replica success and minimum token counts.
- Reserve private component slots and use the existing Mooncake I/O queue with an independent completion Future. This leaves ordinary inference loads and their forward consumer intact. Poll completion across attention ranks and publish on the scheduler only after the whole job finishes; reconcile prefixes inserted concurrently through normal checkpoint/release.
- Account for the private request's allocations, protect cache reset/memory release and weight changes during transfer, release failed loads, and suppress redundant offload of restored KV. Weight-update guards agree across the full TP group even when DP-attention groups finish at different times.

One explicit prefetch may run per worker, including during inference. Partial/missing prefixes are successful partial hits; `prefetched_tokens` counts newly resident tokens and `cached_tokens` reports the cached prefix after publication. Pages remain evictable. PP, Eagle and Mamba extra buffers are rejected. No new dependencies or model/pool support are added.

```python
result = await engine.async_prefetch(full_token_ids, cache_salt="tenant-a")
if not result.success:
    raise RuntimeError(result.message)
print(result.prefetched_tokens, result.cached_tokens)
```

Equivalent HTTP body: `{"token_ids": [1, 2, 3, 4], "cache_salt": "tenant-a"}`; use the same salt as generation.

Based on upstream main, synchronized through `1f834c19`. Related #44000 and #45600 cover normal inference admission; this is an explicit command with no generation. The existing layer-wise inference load-back path remains in place.

Coverage includes partial/page-aligned prefixes, existing L1 hits, repeats and salt isolation on Python/Rust tree cores; hybrid FULL/SWA/Mamba restoration; a held transfer concurrent with insertion of the same prefix; allocation/state-slot cleanup; actual linker-thread readiness/load failures; preserving ordinary pending loads and consumer state; deferred success/failure replies; cancellation-safe response draining; and remote-pending weight-update guards.

GPU integration: after generating/storing 512 prompt tokens and flushing L1, an explicit 576-token prefix restored 512 tokens. While its real transfer job was held at the transfer-ready gate, another streaming request produced 4 more decode tokens and the prefetch RPC remained pending. Repeating prefetch before target generation returned 0 newly prefetched / 512 cached. Misses and different salts returned zero. Subsequent generation reused 448 device tokens, versus zero in the baseline, with identical 8 output IDs.

Integration used Qwen3-0.6B, real CUDA KV, Mooncake storage/linker and native Dynamo TCP control on one L20Z GPU (page size 64). A **test-only plain-MHA pool mapping** enables this small model because upstream linker support excludes Qwen3; a **test-only transfer-ready gate** makes the pending-transfer assertion deterministic. Neither adapter is in this PR, and neither fakes storage hits or KV data. **Stock supported-model deployment, TP>1 and full disaggregated serving were not validated.**

## Speed Tests and Profiling

Bulk loading runs on the existing I/O thread while the scheduler continues inference. Backend lookup, allocation and tree publication still execute on the scheduler. The shared FIFO load queue means prefetch can delay later inference load-back and contend for transfer bandwidth; no throughput improvement is claimed. The integration proves decode progress while prefetch is pending, not simultaneous network/CUDA bandwidth overlap. No serving throughput benchmark was run.
