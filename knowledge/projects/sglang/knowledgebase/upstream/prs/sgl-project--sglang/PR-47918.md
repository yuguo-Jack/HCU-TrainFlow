# [Fix] qwen2.5-vl: use per-frame cu_seqlens for video full attention

[Upstream PR](https://github.com/sgl-project/sglang/pull/47918) · state: open · merged: False

## Original PR description

## Motivation

Qwen2.5-VL video embeddings are wrong: full-attention `cu_seqlens` treats the whole video as one segment, while  HF and vLLM use one segment per frame (as already fixed for Qwen3-VL in #11458).

## Modifications

`python/sglang/srt/models/qwen2_5_vl.py`:
- `forward`: `cu_seqlens` per temporal step, `repeat_interleave(h*w, t).cumsum()` instead of `(t*h*w).cumsum()`.
- `forward_with_cuda_graph`: same change.
- `forward_with_cuda_graph`: build the `full_layout` graph key per temporal step, so it matches `cu_seqlens`.

Images (t=1) are unaffected.

## Accuracy Tests

Qwen2.5-VL-3B-Instruct, 36 MVBench video clips, bf16, NVIDIA A10, sglang 0.5.22 (vision code identical to main).
Vision embeddings compared with HF transformers' encoder in fp32 on identical pixels (median cosine per clip):

| | min | median | max |
|---|---|---|---|
| HF bf16 (noise floor) | 0.9941 | 0.9991 | 0.9997 |
| before | 0.5929 | 0.8912 | 0.9692 |
| after | 0.9939 | 0.9991 | 0.9997 |

- After the fix, every clip is within HF's own bf16 noise.
- 7/36 answers change; accuracy is 58.3% before and after.
- With `SGLANG_VIT_ENABLE_CUDA_GRAPH=1`, outputs are identical to eager (cosine 1.0000) before and after the change.
- Unrelated to this change: with the ViT CUDA graph, the server ran out of memory after ~30 distinct video shapes on a 24 GB GPU, both before and after.

## Speed Tests and Profiling

Not benchmarked. The change makes the full-attention segments smaller (per temporal step instead of per video), so it does not add attention work.
