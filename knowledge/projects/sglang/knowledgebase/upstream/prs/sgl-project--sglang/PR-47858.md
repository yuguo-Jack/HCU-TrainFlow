# [Fix] graph: Restore XPU logger and Inkling backend mock dtype

[Upstream PR](https://github.com/sgl-project/sglang/pull/47858) · state: closed · merged: True

## Original PR description

## Motivation

After #47173, `EAGLEDraftExtendCudaGraphRunner._cache_loc_dtype()` reads `backend.cache_loc_dtype`. The Inkling checkpoint replay fixture returns a bare `Mock()`, causing real buffer allocation to fail with:

```text
TypeError: ones(): argument 'dtype' must be torch.dtype, not Mock
```

The branch's full-repository Lint also fails because `XPUGraphRunner` references an undefined `logger` when memory saver is enabled ([failure](https://github.com/sgl-project/sglang/actions/runs/41405582938/job/125146727842)).

## Modifications

- Set `cache_loc_dtype=torch.int64` on the fixture's mock decode backend. Preserve the existing production buffer allocation, capture/replay assertions, and parameter combinations.
- Import `logging` and initialize the XPU graph runner's module logger with `logging.getLogger(__name__)`.

#47821 remains the separate empty-TopK NPU fix.

## Validation

- Reproduced the XPU `F821 Undefined name logger` locally before the fix; the repository's configured Ruff checks (`F401,F821,F823,UP037`) pass for both changed files afterward.
