# [Fix] openai: Keep tools for constrained named choices

[Upstream PR](https://github.com/sgl-project/sglang/pull/42207) · state: open · merged: False

## Original PR description

## Motivation

For a named `tool_choice`, the prompt normally includes only the selected tool. Templates that place tools before the conversation then lose the prefix shared with earlier turns. Keeping all tools is safe only when the active grammar backend enforces the named call.

## Modifications

Add the opt-in `SGLANG_ENABLE_NAMED_TOOL_CHOICE_KEEP_TOOLS` switch, off by default. Keep the full tool list only when the generated constraint is supported and will be applied. Legacy structural tags require XGrammar; an unsupported backend or an explicit regex, EBNF, or response-format constraint that replaces the tool grammar keeps the one-tool prompt. Legacy structural tags are restricted to the named function regardless of the switch.

This applies to Python HTTP prompts rendered by Jinja or Inkling. DeepSeek and Kimi K3 encoders already include all request tools; the gRPC gateway and Rust server are unchanged.

## Accuracy Tests

Focused named-tool-choice regressions and scoped formatting pass on the updated branch. An earlier direct llguidance check confirmed that its legacy structural tags do not enforce the named-call requirement. Those tags can still allow another call as free text for some parsers. Strict multi-call enforcement and live model behavior remain unverified.

Run the unit suites with `python -m pytest` and scoped formatting with `pre-commit run --files <changed-files>`.

## Speed Tests and Profiling

An earlier v0.5.20 B200 backport probe with GLM-5.3-Flash preserved a 136K-token cached prefix and produced the first token in 0.25 s; rendering only the named tool lost that prefix and took 2.1 s. Other local patches were present, and the probe did not cover this branch's backend and output-constraint guards. A cold prompt containing every tool can take more prefill.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Keep the one-tool prompt for non-forcing constraints**

When `SGLANG_NAMED_TOOL_CHOICE_KEEPS_TOOLS=1` is used with the llguidance grammar backend and a parser on the legacy-tag path, this non-null check is too weak: `llguidance_backend.dispatch_structural_tag` rebuilds the grammar from only `structures` and `triggers` (`python/sglang/srt/constrained/llguidance_backend.py:300-321`), dropping the tag's `at_least_one=True`, so it does not force a named call. The new branch nevertheless advertises every tool; with a per-tool trigger such as Inkling's, another advertised tool can then pass as unconstrained text and be parsed as a call, violating the named `tool_choice`. Keep the filtered prompt unless the active backend honors the forcing property, or implement `at_least_one` in llguidance.
