# [Fix] openai: Enforce named tool choice in legacy tags, keep tools opt-in

[Upstream PR](https://github.com/sgl-project/sglang/pull/42207) · state: closed · merged: False

## Original PR description

## Motivation

On main, a named `tool_choice` on a legacy structural tag can return another tool. A named turn also renders only that tool, so tools-first templates lose the earlier prefix.

## Modifications

Legacy structural tags now list only the named tool on every named request.

`SGLANG_ENABLE_NAMED_TOOL_CHOICE_KEEP_TOOLS`, off by default, renders every request tool in Jinja and DeepSeek V4 and V4.1 recipe prompts when XGrammar limits the first call to the named tool. With it off, prompts match main.

#40051 has the same filter in `get_legacy_structural_tag` and forces the parameters schema on non-strict named tools. A maintainer offered on 2026-09-23 to merge it once narrowed to the filter, and this PR leaves out the schema change. A comment there asks whether it will be narrowed. If so, this PR drops its filter and keeps only the switch. The switch must not merge before the filter, because with every tool in the prompt and no filter, the grammar would allow any tool.

Limits (new code needs a real input that reaches the case):

- `deepseekv3`, `inkling` and `llama3` can return another tool after the forced call. A post-parse filter is undecided.
- `qwen3_coder`, `step3p5` and `nanbeige` accept a second call inside the forced call's string value, and the parser reads both, as on main. These parsers get no prefix gain.
- `deepseekv4`, `deepseekv41`, strict `glm47` and `flint` keep the switch. Grammar and parser checks (no weights) accept that second call, and the DeepSeek parsers return only the other tool.
- The switch can add token-limit endings.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Keep the one-tool prompt for non-forcing constraints**

When `SGLANG_NAMED_TOOL_CHOICE_KEEPS_TOOLS=1` is used with the llguidance grammar backend and a parser on the legacy-tag path, this non-null check is too weak: `llguidance_backend.dispatch_structural_tag` rebuilds the grammar from only `structures` and `triggers` (`python/sglang/srt/constrained/llguidance_backend.py:300-321`), dropping the tag's `at_least_one=True`, so it does not force a named call. The new branch nevertheless advertises every tool; with a per-tool trigger such as Inkling's, another advertised tool can then pass as unconstrained text and be parsed as a call, violating the named `tool_choice`. Keep the filtered prompt unless the active backend honors the forcing property, or implement `at_least_one` in llguidance.
