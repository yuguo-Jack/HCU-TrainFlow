# [CI] slash-command: Require explicit hardware for Extra CI

[Upstream PR](https://github.com/sgl-project/sglang/pull/47122) · state: closed · merged: True

## Original PR description

## Motivation

The shared `run-ci-extra` label enables both NVIDIA and AMD Extra, so an AMD-only request can consume NVIDIA runners. Replace it with explicit hardware opt-ins and require a hardware argument for Extra and Full commands.

## Modifications

- Register NVIDIA/shared Extra with `run-ci-nv-extra` and AMD Extra with `run-ci-amd-extra`. Both still require `run-ci`; the retired shared label no longer satisfies either gate.
- Add AMD Base selectors and support `/run-extra-ci nv|amd` and `/run-full-ci nv|amd`. Full combines the selected Base and Extra tiers. Existing direct tier aliases also work.
- Reject bare, unknown, or multiple hardware arguments before adding labels or rerunning workflows. Reject legacy `extra` arguments to labeling commands with migration guidance.
- Preserve normal Base CI triggers, path filters, permissions, and scheduled/manual behavior. NVIDIA/shared Extra retains its existing Xeon CPU coverage.
- Migrate the nested Xeon Extra gate and PR status hints, remove the unused shared/alternative gate inputs, and update documentation and registry validation.

Selections target existing runs for the current commit, including successful runs, and leave active runs alone. Missing Base runs are skipped; missing Extra runs are reported. Existing labels are preserved.

## Migration

Use `/run-extra-ci nv` or `/run-extra-ci amd` for Extra, and `/run-full-ci nv` or `/run-full-ci amd` for Base plus Extra. Bare `/run-ci` keeps its existing behavior.

Existing PR branches need these registry, handler, and gate changes plus a fresh push. Rerunning an older workflow retains its original revision and label behavior. The old repository label is not deleted or bulk-replaced; it stops enabling Extra when these updated gates are used. Both dedicated repository labels are available.

## Validation

- Passed 14,160 offline command/gate cases covering hardware selection, permissions, invalid commands, retained labels, current-head runs, and unchanged Base behavior.
- Validated 110 local reusable workflow calls across 123 workflows; registry lint and applicable pre-commit hooks pass.
- Independent review found no correctness issues.

Live GitHub CI has not been validated for this revision. Mintlify validation was unavailable locally. No repository test files were added.
