## Motivation

<!-- Describe the purpose and goals of this pull request. -->

Improve fused MoE performance on H200 for the block-FP8 shape used by GLM-5.3-Flash with TP4/EP4 (`E=72`, `N=2048`, block shape `[128, 128]`). The configurations deliver **1.054×–1.199× speedups** over the default heuristic at the measured token counts.

## Modifications

<!-- Detail the changes made in this pull request. -->

Add two Up/Down GEMM configuration files for Triton 3.8.0, covering 25 input token counts from **M=1 to M=8192**. They load automatically through the existing loader, with no kernel or runtime changes. All configurations use `BLOCK_SIZE_K=128`, matching the quantization group width.

## Accuracy Tests

<!-- If this pull request affects model outputs (e.g., changes to the kernel or model forward code), provide accuracy test results. -->

- All 25 Up/Down configuration pairs passed numerical validation against the default heuristic using nonuniform activation and weight quantization scales (`rtol=0.03`, `atol=0.003`), with held-out routing samples covering multiple layers and all four EP ranks.
- JSON/grid checks and pre-commit passed.

## Speed Tests and Profiling

<!-- If this pull request impacts inference speed, provide benchmarking and profiling results. -->

Fused MoE CUDA Graph microbenchmarks on H200 with Triton 3.8.0, BF16 inputs and block-FP8 weights: hidden size 4096, 72 local experts, intermediate size 2048, top-k 8. Measurements exclude distributed communication.

Speedups over the default heuristic configuration, reported as the median of three paired trials:

| Input tokens (M) | Speedup |
| ---: | ---: |
| 1 | 1.199× |
| 16 | 1.108× |
| 64 | 1.101× |
| 128 | 1.074× |
| 192 | 1.054× |
| 512 | 1.060× |
| 768 | 1.064× |
| 1024 | 1.073× |
| 2048 | 1.102× |
| 4096 | 1.110× |
| 8192 | 1.085× |
