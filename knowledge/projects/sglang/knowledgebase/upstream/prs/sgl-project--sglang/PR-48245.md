# [Perf] dsv4: four chunks per thread in mega MoE pre-dispatch for prefill-sized batches

[Upstream PR](https://github.com/sgl-project/sglang/pull/48245) · state: closed · merged: True

## Original PR description

## Motivation

#47149 made `mega_moe_pre_dispatch` launch 320-thread CTAs with two 16B chunks per thread on SMs that hold 1024 resident threads (CC 10.7 / sm_107), since two 640-thread CTAs do not fit. That PR measured decode-sized batches. At prefill-sized batches (thousands of rows) the kernel is still launch-bound: one CTA per token, three resident per SM.

## Modifications

- `mega_moe_pre_dispatch.cuh`: add a four-chunks-per-thread instantiation (160-thread CTAs for hidden 5120). It is used when the two-chunk launch already applies (1024-thread SMs), `num_chunks` is a multiple of 128, `top_k <= num_chunks / 4`, and `num_tokens >= 6 x SM count`.
- Below that row count, and on 2048-thread SMs, the launch is unchanged. The cutoff comes from the sweep below: four chunks lose 3-16% at 424-1024 rows and win from about 1.3K rows up.

Outputs are bitwise identical (FP8 bytes, scales, shared-SF layout, top-k copies and padding).

## Accuracy Tests
