# [Feat] hicache: Store MXFP8 KV pages in L3 as payload + scales objects

[Upstream PR](https://github.com/sgl-project/sglang/pull/46936) · state: closed · merged: True

## Original PR description

## Motivation

With an MXFP8 KV cache, HiCache L3 does not work at all: `MHATokenToKVPoolMXFP8Host` raises `NotImplementedError` for every storage page, because a page's UE8M0 scales live in their own host buffers, outside `kv_buffer`.

## Modifications

Each page is stored as two multi-buffer objects under the existing keys, so the key schema and every non-MXFP8 pool are unchanged:

| object | buffers (one page, all layers) |
|---|---|
| `{hash}_{rank}_k` | K payload, then K scales |
| `{hash}_{rank}_v` | V payload, then V scales |

`get_page_buffer_meta` returns those pointer/size pairs and `get_hybrid_pool_buffer` exposes both scale buffers for registration. Mooncake already stores nested buffer lists (`batch_put_from_multi_buffers`); flat storage pages stay unsupported.

## Accuracy Tests

| test | before | after |
|---|---|---|
| `test_storage_objects_round_trip_payload_and_scales` (new): pages stored through these pointers and loaded into another pool restore payload and scales; each object is exactly payload + scales | `NotImplementedError` | passes |

`test_mxfp8_mha_pool_host_unit.py`: 5 passed. End to end (PD with decode KV offload and MXFP8 KV, on a fork carrying this change): the prefill restores the KV the decode wrote; every turn's logprobs match a no-cache reference (max drift 4.4e-16).

Not run here: `test_hicache_storage_mooncake_backend.py` with an MXFP8 KV cache.
