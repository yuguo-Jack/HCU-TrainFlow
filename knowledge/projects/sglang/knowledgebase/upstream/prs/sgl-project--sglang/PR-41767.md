# [Fix] strip_thinking_cache: never free KV the radix tree owns after a re-prefill

[Upstream PR](https://github.com/sgl-project/sglang/pull/41767) · state: open · merged: False

## Original PR description

## Motivation

With `--strip-thinking-cache`, `owned_kv_len()` returns the prompt length once a request has reasoning tokens, so `release_kv_cache` frees everything past the prompt as over-allocated. A retracted request is re-prefilled over `prompt + output`, and that prefill's `cache_unfinished_req` puts the output into the tree (`cache_protected_len > prompt`). On finish or a second retraction, the slots in `[prompt, cache_protected_len)` were freed while the tree still owned them. They were freed again on eviction, and could be handed to two requests. Reproduced on main `77091cea68` (after #41281 reworked `release_kv_cache`) and again on `98fce73d5b` and `3c4653b6a3`.

Fixes #41617.

Found while tracing KV-slot ownership across retraction (`cache_protected_len` vs `owned_kv_len`); reported in #41617.

## Modifications

`Req.owned_kv_len()`, strip-thinking branch: `min(committed, max(len(origin_input_ids), cache_protected_len))`. Without a retraction `cache_protected_len <= prompt`, so nothing changes.

## Accuracy tests

`test/registered/unit/mem_cache/test_strip_thinking_after_retraction.py` (new, CPU, `UnifiedRadixCache` with real `cache_unfinished_req`, `release_kv_cache` and `evict`) covers finish after a re-prefill, a second retraction, the no-retraction case (output still stripped), and page_size=4 with an aligned and an unaligned prompt (where the tree-owned page is freed by `insert_req`'s unaligned-tail free instead). After release, no tree-owned slot is in the free list, and after evicting the whole tree the free list has no duplicates and equals the pool. All but the no-retraction test fail on main.
