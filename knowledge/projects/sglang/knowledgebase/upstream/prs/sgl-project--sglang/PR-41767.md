# [Fix] strip_thinking_cache: never free KV the radix tree owns after a re-prefill

[Upstream PR](https://github.com/sgl-project/sglang/pull/41767) · state: open · merged: False

## Original PR description

## Motivation

With `--strip-thinking-cache`, a request that is retracted after it produced reasoning tokens corrupts KV accounting once it is re-prefilled: finishing it trips an assert in the radix cache, and a second retraction frees slots the tree still owns, so one `alloc()` can later hand a slot to two requests. Decode retracts whenever the KV pool runs out, so long reasoning outputs under memory pressure reach this.

Cause: `owned_kv_len()` returns the prompt length once a request has reasoning tokens, so `release_kv_cache` frees everything past the prompt as over-allocated. A retracted request keeps its output and is re-prefilled over `prompt + output`; that re-prefill's `checkpoint_kv_cache` puts the output into the tree (or its match already finds it there), so `cache_protected_len > prompt`. Finishing then trips the `cache_protected_len <= len(new_indices) + page_size - 1` assert in `UnifiedRadixCache.checkpoint_into_tree`, and a second retraction frees `[prompt, cache_protected_len)`; evicting the node frees those slots again.

Fixes #41617.

## Modifications

`Req.owned_kv_len()`, strip-thinking branch: `min(committed, max(len(origin_input_ids), cache_protected_len))`. Without a retraction `cache_protected_len <= prompt`, so nothing changes and the output is still stripped.

Capping the re-prefill's checkpoint at the prompt does not replace this floor: when the match already passes the prompt the capped checkpoint trips the same assert. Keeping a re-prefill's thinking tokens out of the tree is a follow-up on top of this floor.

## Accuracy Tests

`test/registered/unit/mem_cache/test_strip_thinking_after_retraction.py` (new, CPU, real `UnifiedRadixCache`, `checkpoint_kv_cache`, `release_kv_cache` and `evict`, with the flag on for the whole request) covers finish after a re-prefill, a second retraction, the no-retraction case (output still stripped), a chunked re-prefill whose first chunk ends inside the earlier output, a re-prefill whose match already passes the prompt, and page_size=4 with an aligned and an unaligned prompt. After release no tree-owned slot is in the free list (page_size 1), and after evicting the whole tree the free list has no duplicates and equals the pool.

Run on CPU: on main every retraction case fails (2 tests and 8 of 8 subtests; the no-retraction test passes). With the fix: 6 passed, 8 subtests passed.

- sohom-cs · comment · 2026-10-25T02:10:01Z · [source](https://github.com/sgl-project/sglang/pull/41767#issuecomment-6392302414)

The cap is built, as one commit on top of this branch, with a test. With `--strip-thinking-cache` and `reasoning_tokens > 0`, `checkpoint_kv_cache` now stops a re-prefill's checkpoint at the prompt, so the earlier thinking and answer tokens no longer go into the tree:

```python
up_to = req.extend_end
if (
    get_serving().strip_thinking_cache
    and req.reasoning_tokens > 0
    and not tree_cache.supports_mamba()
):
    up_to = min(up_to, max(len(req.origin_input_ids), req.kv.cache_protected_len))
```

The new case re-prefills a retracted request, plain and chunked, and checks that nothing past the prompt is matchable: on this PR's head it fails with `14 != 8`, and with the cap the file gives 7 passed, 10 subtests passed. The floor in `owned_kv_len()` stays: when the re-prefill's match already passes the prompt, the cap can't go below `cache_protected_len`, and with the cap but without the floor that case still trips the assert on finish (`cache_protected_len=12, len(new_indices)=8`) and a second retraction frees tree slots [9..12]. It skips mamba trees, where the live recurrent state is the state after the whole re-prefill: on CPU, a capped checkpoint stores that post-thinking state under the prompt node once the node's own state has been evicted. The branch is `sohom-cs:fix/strip-thinking-cap-reprefill-checkpoint`. I'll open it as a follow-up PR once this one merges, or push it here if you'd rather review both together.
