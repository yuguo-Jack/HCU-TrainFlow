## Motivation

Fixes #41743.

`--enable-return-routed-experts` returned zero-filled IDs with Triton-kernels and FlashInfer from-logits routing.

- esarafian · comment · 2026-11-03T15:45:36Z · [source](https://github.com/sgl-project/sglang/pull/42395#issuecomment-6608309452)

For reference, the zero-filled case from #41743 still reproduces on current main (`8d4e1ce4c7`). This was on GB300 with public `nvidia/Qwen3.8-Flash-Next-NVFP4`, TP1, and `--enable-return-routed-experts`. Main auto-selects `flashinfer_trtllm` for this model, and all 528,000 returned expert ids over 8 requests are 0.

#47524 handles that backend by switching to `flashinfer_trtllm_routed`; the numbers are in our comment there. With that switch the ids are real, outputs change slightly relative to running without capture, and decode TPOT goes from 7.52 to about 8.4 ms. If both PRs move forward, it may help to agree which one owns the flashinfer_trtllm case: reject vs. switch. The Triton `sparse_logits.indx` capture here looks independent of that.

This branch conflicts with main now (`arg_groups/moe_hook.py`, `test_triton_fused_moe.py`), so we did not run its head.
