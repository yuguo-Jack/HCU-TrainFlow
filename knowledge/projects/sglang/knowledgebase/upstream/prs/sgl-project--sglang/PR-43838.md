# [Perf] DeepSeek-V4.1: Run the small-batch decode fusions at TP2

[Upstream PR](https://github.com/sgl-project/sglang/pull/43838) · state: open · merged: False

## Original PR description

## Motivation

DeepSeek-V4.1-Flash small-batch decode fusions (fused all-reduce + mHC epilogues, the fused inverse-RoPE + WO-A + MXFP8 kernel, and SM100 swap-AB decode attention) were gated to TP4 shapes (tp_size == 4, 2 local o_groups, 16 local heads). TP2 decode therefore ran the unfused path at every batch size, although TP2 is the better latency/throughput point for this model on GB300 at mid concurrency.

## Modifications

- Fused all-reduce + mHC: admit tp_size 2 (the all-reduce kernels are already templated on world size).
- Fused WO-A: take the local group count (2 at TP4, 4 at TP2) as a template parameter.
- Swap-AB decode attention: run TP2's 32 local heads as two 16-head groups on the partial kernel's grid z axis.
- Tests: WO-A fused test parametrized over 2 and 4 groups; swap-AB test covers 32 heads.

The gates check shapes (16 or 32 local heads, 2 or 4 local o_groups, tp_size 2 or 4), not TP size alone, so any deployment with those local shapes takes these paths; only DeepSeek-V4.1-Flash TP2 and TP4 have been validated.

## Setup

Both arms use the same image, `lmsysorg/sglang:nightly-dev-cu13-20261012-e6072935`, on GB300 with 2 GPUs. "main" is the image as shipped. "this PR" overlays this branch's changed files onto the same image. Both arms use identical server flags.

Server launch, shown with the c32 flags:

```bash
SGLANG_DEFAULT_THINKING=1 SGLANG_DSV41_REASONING_EFFORT=high \
SGLANG_DSPARK_FOLDED_SAMPLING=2 SGLANG_DSPARK_OPT_MARKOV_W2_BF16=True \
SGLANG_ENABLE_DSV41_ENGRAM_HOST_TABLE=1 SGLANG_DSV41_ENGRAM_HOST_TABLE_LAYOUT=per_rank \
PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True \
python3 -m sglang.launch_server --model-path deepseek-ai/DeepSeek-V4.1-Flash --trust-remote-code \
  --tensor-parallel-size 2 --expert-parallel-size 2 \
  --speculative-algorithm DSPARK --speculative-dspark-block-size 5 \
  --mem-fraction-static 0.8 --chunked-prefill-size 16384 --cuda-graph-max-bs-decode 64 \
  --max-running-requests 64 --prefill-decode-interval 48 \
  --swa-prefix-tails 2048 --enable-decoder-swa-bounded-replay --cuda-graph-backend-prefill disabled \
  --schedule-policy fcfs --tokenizer-worker-num 4 \
  --reasoning-parser auto --tool-call-parser auto --enable-metrics --watchdog-timeout 3600
```

Per-concurrency overrides (all other flags as above):

| conc | max-running-requests | prefill-decode-interval | expert-parallel-size | swa-prefix-tails | bounded replay / prefill graph off / fcfs / 4 tokenizer workers |
|---|---|---|---|---|---|
| 1 | 2 | 16 | 2 | default | no |
| 2 | 4 | 16 | 2 | 128 | no |
| 4 | 8 | 96 | 1 | 256 | no |
| 16 | 32 | 96 | 2 | 1024 | yes, but no fcfs |
| 32 | 64 | 48 | 2 | 2048 | yes |

c4 and c16 also set `SGLANG_NUMA_BIND_V2=0`; c1–c4 do not set `PYTORCH_CUDA_ALLOC_CONF`.

## Accuracy Tests

GSM8K, DeepSeek-V4.1-Flash TP2 on GB300. All 1319 test questions, 5-shot, `max_tokens` 16384, real MTP verification (no simulated acceptance):

```bash
python3 -m sglang.test.run_eval --base-url http://localhost:30000 --eval-name gsm8k \
  --num-examples 1319 --num-shots 5 --max-tokens 16384 --num-threads <1|64>
```

`--num-threads` is the number of concurrent client requests:
- **1 thread** runs against the c1 server flags.
- **64 threads** runs against the c32 server flags (`max-running-requests` 64).

| setting | main | this PR |
|---|---|---|
| 1 thread | 0.968 | 0.967 |
| 64 threads | 0.970 | 0.973 |

## Speed Tests and Profiling

The speed tests use AgentX trace replay from InferenceX (`inferencex-e2e/benchmarks/srt_agentic.sh`, which wraps `aiperf profile --scenario agentx`). The replay:
- uses the `semianalysisai/cc-traces-weka-062126` multi-turn agentic coding traces;
- runs `--concurrency <conc>` concurrent sessions for `--benchmark-duration 3600` (1 h per point), after the scenario's cache-primer warmup;
- uses the chat template and streaming.

```bash
aiperf profile --scenario agentx --url http://localhost:30000 \
  --model deepseek-ai/DeepSeek-V4.1-Flash --tokenizer deepseek-ai/DeepSeek-V4.1-Flash --tokenizer-trust-remote-code \
  --concurrency <conc> --benchmark-duration 3600 --warmup-grace-period 1800 \
  --public-dataset semianalysis_cc_traces_weka_062126 --apply-chat-template
```

As in InferenceX throughput runs, MTP acceptance is pinned to the golden length on both arms with these server environment variables:

```bash
SGLANG_SIMULATE_ACC_LEN=3.51 SGLANG_SIMULATE_ACC_METHOD=match-expected SGLANG_SIMULATE_ACC_TOKEN_MODE=real-draft-token
```

The metrics are computed over requests in the profiling phase:
- **P90 tok/s/user:** the 10th percentile, which is the slow tail, of per-request `1 / TPOT`, where `TPOT = (E2E latency − TTFT) / (output tokens − 1)`.
- **tok/s/GPU:** total input plus output tokens of all requests, divided by the wall-clock span and by 2 GPUs.

Results are P90 tok/s/user @ tok/s/GPU:

|---|---|---|---|---|
| 1 | 431.7 @ 12,443 | 517.7 @ 13,423 | +19.9% | +7.9% |
| 2 | 392.6 @ 12,689 | 439.6 @ 13,865 | +12.0% | +9.3% |
| 4 | 383.5 @ 18,119 | 417.5 @ 18,495 | +8.9% | +2.1% |
