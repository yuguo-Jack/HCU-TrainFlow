## Motivation

The unified memory pool sized its arena from token counts and handled state (Mamba/GDN/KDA recurrent state), request-indexed and fixed payloads in separate, per-model code. This PR makes the KV storage plan declare every payload — state entries, request rows, scratch and derived pages — before allocation, and sizes all of it from one total byte budget, so capacity, resizing and admission read one source.

## Modifications

- Declarations: `mem_cache/kv/decl.py`, `kv/plan.py`, `kv/layout/parts.py`, `kv/memory/fixed.py`, `kv/memory/request_window.py`, `kv/memory/snapshot.py`: state, request, scratch and derived storage are declared parts of the plan; checkpoint and request-reset behavior is preserved through layout views; resume boundaries and tracking effects are carried by the storage.
- Sizing: `mem_cache/kv/sizing.py`, `kv_cache_configurator.py`, `model_executor/pool_configurator.py`: one solve over the total budget sizes FULL, windows and state; every arena band can be resized after capture without changing captured addresses; physical and widened DCP units are accounted separately; request payloads are fitted within the usable budget; runtime sizing includes peak state demand.
- Admission and retraction: `mem_cache/prefill_budget.py`, `managers/schedule_policy.py`, `managers/scheduler_components/batch_result_processor.py`: request state-slot demand is shared between sizing and admission; retraction keeps complete entries.
- Linear-attention state staging: `layers/attention/linear/kernels/state_pool_io.py`, `gdn_backend.py`, `gdn_flashinfer.py`, `kda_backend.py`, `hybrid_linear_attn_backend.py`: with a strided state pool, prefill stages requests' states at rows 1..n and keeps row 0 as the padding row the FlashInfer GDN prefill expects.
- Replay geometry is read only for enabled modes (`fused_recurrent_linear_replayssm.py`, `spec_utils.py`).
- Tests: new declaration, sizing, request-window, state-alignment and staging tests under `test/registered/unit/mem_cache/kv/`, `test/registered/unit/layers/attention/`, plus updates to the existing unified allocator, admission and golden-layout tests.

**Behavior change:** under `--enable-unified-memory`, `--max-total-tokens` sizes the arena (as it sizes separate pools): the arena is the smallest budget whose solve gives that many FULL tokens, with windows and state sized by the same rules. FULL may still grow into the whole arena; the flag is not an allocation cap. Only a pipeline stage's synchronized share caps FULL.

**Known limitation:** with a strided state pool, the GDN prefill path rebuilds its staging indices in every layer. On short-request workloads this costs about 4% (Qwen/Qwen3.8-27B TP2 unified, 2x B200, GSM8K 1000 questions, warm server: 36.0 s vs 33.8–35.4 s on `main`). Computing the indices once per forward removes it; the longer-term fix is kernels that take the state slot stride directly.
