# [Perf] dsv41: Read Engram rows from peer device shards

[Upstream PR](https://github.com/sgl-project/sglang/pull/46180) · state: closed · merged: True

## Original PR description

With per-rank Engram tables and DP attention, every lookup all-gathers all DP ranks' hash ids, gathers the owned rows for all of them into a `[DP x tokens]` bf16 buffer, and reduce-scatters it back. The traffic and the buffer grow with the DP size, so wide-EP decode pays a collective per Engram layer that is larger than the lookup itself.

This adds an opt-in path, `SGLANG_OPT_DSV41_ENGRAM_PEER_SHARDS=1`:

- Each TP rank keeps its row shard in exportable device memory (CUDA VMM) and maps every peer's shard after loading: FABRIC handles across an NVLink domain (MNNVL), POSIX fds within a host.
- `engram_gather_peer`: one Triton kernel reads each of a rank's own tokens' rows straight from the owning shard (owner found by binary search over the shard starts). No id gather, no global buffer, no collective; CUDA-graph safe. Covers the TP, DP and prefill-CP lookups.
- Output is bitwise equal to the current path (-0 is written as +0, as the zero-fill + sum leaves it).
- Takes precedence over the host table (a warning says so when both are set). The shard costs `table_size / tp_size` of HBM per GPU, so it suits wide DEP.
- The VMM handle exchange (export, then FABRIC handles or POSIX fds) moves into `cuda_vmm_utils.exchange_shareable_handles`, shared with the DWDP transport; a group spanning hosts without FABRIC handles now fails there with a clear error. Peers are mapped with the existing `import_and_map_alloc`.

Off by default; nothing changes unless the variable is set.

## Verification

- `test/manual/layers/test_engram_peer_shards.py` at the real table size, bitwise equal to the current lookup, eager and under CUDA graph replay: 8 GB300 ranks over two nodes (FABRIC), and 8 B300 GPUs on one host (POSIX fds).
- DeepSeek-V4.1-Flash decode with DP attention over two GB300 nodes: the ReduceScatter and AllGather are gone from the decode step, greedy outputs and accept lengths match, and the reduced KV pool still fits the tested batch.

Related: #45679 (single-node TP4 peer reads).
