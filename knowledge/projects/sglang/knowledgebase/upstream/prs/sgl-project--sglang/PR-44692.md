# [Perf] Fix watermark redaction walking every token id in request logging

[Upstream PR](https://github.com/sgl-project/sglang/pull/44692) · state: open · merged: False

## Original PR description

## Motivation

#37577 (Aaronson-Gumbel text watermarking) added `redact_watermark_secrets` to the request-log formatters. Both `_dataclass_to_string_truncated` and `_transform_data_for_logging` redact the whole request object **before** truncation and **before** `skip_names` filtering, so every `--log-requests` call walks the full `input_ids` element by element (~0.5us/token). With long prompts this costs tens of ms per log call on the tokenizer-manager event loop, on receive and again on finish, and shows up directly in TTFT.

On main, formatting an 80k-token `GenerateReqInput` at `--log-requests-level 2` costs ~62 ms (text) / ~61 ms (json); with this PR it is ~1 ms.

## Modifications

`python/sglang/srt/utils/request_logger.py`:

- New `_redact_field`: redact by field/key name. Fields named `watermark_key` / `watermark_key_b` / `watermark_config` become `<redacted>`; `watermark` / `sampling_params` / `preferred_sampling_params` are redacted recursively; everything else passes through untouched. `skip_names` fields are dropped before redaction.
- The truncated-list branch of `_transform_data_for_logging` now redacts the printed head/tail halves, matching `_dataclass_to_string_truncated`.

`python/sglang/srt/sampling/watermarking/core.py`:

- The watermark field-name sets are now module-level `WATERMARK_SECRET_FIELD_NAMES` / `WATERMARK_CONTAINER_FIELD_NAMES`, shared by all redact branches and the logger instead of being re-listed in five places.
- New scalar fast-path: a list/tuple with no dict/list/tuple/Struct/dataclass element cannot hold a secret (secrets only sit under dict keys or struct/dataclass fields), so it returns the input unchanged. This bounds every caller — including the `dump_requests` / crash-dump path in `tokenizer_manager.py`, which redacts full request tuples synchronously on the event loop, and batched requests whose `input_ids` is a list-of-lists with a short outer list.

Log output is unchanged at every `--log-requests-level`.

## Accuracy Tests

Logging-only change; no model path touched.

New `test/registered/unit/utils/test_request_logger_redaction.py` (CPU, `base-a-test-cpu`):

- Secrets are redacted in both formatters, for 16 and 100k input ids.
- Truncated lists keep their printed halves redacted.
- The redaction walk is bounded at each level's real `(max_length, skip_names)` — this test fails on main.
- Scalar sequences are returned by identity while containers are still redacted.

Output equivalence vs main was checked with both formatters over 20 payload shapes (levels 0-3 metadata, nested secrets, long secret-bearing lists, batched `input_ids`, finish `out` dicts, tuples, None secrets, unicode text): byte-identical in all 40 runs, no secret string in any output.

## Speed Tests and Profiling

CPU, single thread, one formatter call on an 80k-token request carrying a watermark config:

| case | main (ms) | PR (ms) |
|---|---:|---:|
| level 2, text | 62.5 | 1.1 |
| level 2, json | 61.2 | 1.0 |
| level 1, text | 58.8 | 0.05 |
| level 3, text (prints every id) | 128.1 | 43.3 |
| batched 32x4k `input_ids`, level 2 | 219.7 | 69.4 |
| crash-dump-shaped redact (80k prompt + 20k `output_ids`) | 15.1 | 8.8 |

Level 3 and batched requests remain dominated by `str()` of the ids they print; the redaction walk on top is now a flat scan instead of a full recursion.

Related: #44683 fixes the same logger path with a different split (it skips the walk only for `skip_names` fields and long non-watermark lists). This PR redacts strictly by field name and additionally bounds the other `redact_watermark_secrets` callers via the core fast-path.
