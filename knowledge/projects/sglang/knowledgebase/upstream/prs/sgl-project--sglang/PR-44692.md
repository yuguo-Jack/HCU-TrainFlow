# [Perf] request_logger: skip per-token watermark redaction walk

[Upstream PR](https://github.com/sgl-project/sglang/pull/44692) · state: closed · merged: True

## Original PR description

## Motivation

#37577 (Aaronson-Gumbel text watermarking) added `redact_watermark_secrets` to the request-log formatters. Both `_dataclass_to_string_truncated` and `_transform_data_for_logging` redact the whole request object **before** truncation and **before** `skip_names` filtering, so every `--log-requests` call walks the full `input_ids` element by element (~0.5us/token). With long prompts this costs tens of ms per log call on the tokenizer-manager event loop, on receive and again on finish, and shows up directly in TTFT.

On main, formatting an 80k-token `GenerateReqInput` at `--log-requests-level 2` costs ~62 ms (text) / ~60 ms (json); with this PR it is ~0.3 ms / ~1.1 ms.

## Modifications

`python/sglang/srt/utils/request_logger.py`:

- New `_redact_field`: redact by field/key name. Fields named `watermark_key` / `watermark_key_b` / `watermark_config` become `<redacted>`; `watermark` / `sampling_params` / `preferred_sampling_params` are redacted recursively; everything else passes through untouched. `skip_names` fields are dropped before redaction.
- The `str(...)` fallback in both formatters still redacts first, so a msgspec Struct carrying watermark fields under an ordinary key stays redacted, exactly as on main.
- The truncated-list branch of `_transform_data_for_logging` now transforms each printed item instead of returning raw items, so a truncated list of dataclasses/Structs no longer breaks `json.dumps`.

`python/sglang/srt/sampling/watermarking/core.py`:

- The watermark field-name sets are now module-level `WATERMARK_SECRET_FIELD_NAMES` / `WATERMARK_CONTAINER_FIELD_NAMES`, shared by all redact branches and the logger instead of being re-listed in five places.
- New scalar fast-path: `_SCALAR_TYPES.issuperset(map(type, value))` scans a sequence in C, and a plain-scalar sequence (e.g. token ids) can never hold a secret, since secrets only sit under dict keys or struct/dataclass fields. Mutable lists come back as copies (the crash-dump path pickles the result on a worker thread); immutable tuples may alias. The mixed-container walk skips scalar items inline. This bounds the other `redact_watermark_secrets` callers too — `dump_requests` / crash dump in `tokenizer_manager.py`, server info — and list-of-lists batched `input_ids`.

Log output is byte-identical to main at every `--log-requests-level`, with one intentional exception: Struct/dataclass items inside truncated json lists now print as redacted strings instead of crashing `json.dumps`.

## Accuracy Tests

Logging-only change; no model path touched.

New `test/registered/unit/utils/test_request_logger_redaction.py` (CPU, `base-a-test-cpu`):

- Secrets are redacted in both formatters, for 16 and 100k input ids, including the top-level `GenerateReqInput.watermark` field.
- A msgspec Struct with a `watermark_key` field under an ordinary key stays redacted (regression test for the string fallback).
- Truncated lists keep their printed halves redacted; a truncated json list of Structs stays `json.dumps`-serializable.
- The redaction walk is bounded at each level's real `(max_length, skip_names)` — this test fails on main.
- Scalar sequences skip the walk; mutable lists come back as copies while tuples may alias; containers are still redacted.

Output equivalence vs main was checked with both formatters over 22 payload shapes (levels 0-3 metadata, nested secrets, msgspec Structs under ordinary fields, long secret-bearing lists, batched `input_ids`, finish `out` dicts, tuples, None secrets, unicode text): byte-identical in all 44 runs, no secret string in any output.

## Speed Tests and Profiling

CPU, single thread:

| case | main (ms) | PR (ms) |
|---|---:|---:|
| level 2, text, 80k input_ids | 61.6 | 0.3 |
| level 2, json, 80k input_ids | 59.6 | 1.1 |
| scalar list redact, 100k ids | 74.4 | 2.3 |
| mixed 100k scalars + 1 dict | 74.2 | 5.8 |
| batched 32x4k `input_ids`, level 2 text | 204.6 | 14.0 |
| level 3, text, 80k input_ids (prints every id) | 127.0 | 9.2 |
| crash-dump-shaped redact (80k prompt + 20k `output_ids`) | 14.7 | 0.5 |

Level 3 and batched requests remain dominated by `str()` of the ids they print; the redaction on top is now a C-level scan.

Related: #44683 (closed) fixed the same logger path with a different split (it skipped the walk only for `skip_names` fields and long non-watermark lists). This PR redacts strictly by field name and additionally bounds the other `redact_watermark_secrets` callers via the core fast-path.
