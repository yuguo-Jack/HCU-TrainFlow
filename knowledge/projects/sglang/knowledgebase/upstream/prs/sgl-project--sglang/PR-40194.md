# [Fix] Validate step limits for stage-based profiling

[Upstream PR](https://github.com/sgl-project/sglang/pull/40194) · state: closed · merged: False

## Original PR description

## Motivation

A stage-based profiling request without a step count (or with `num_steps=0`) is accepted, but the next forward callback raises `TypeError` when incrementing an uninitialized stage counter. A negative limit starts and immediately stops stage captures.

For example, `POST /start_profile` with `{"profile_by_stage": true}` currently returns 200 before that later failure. Reject these configurations while constructing the request, before dispatch to workers.

## Modifications

Require positive `num_steps` whenever `profile_by_stage` is enabled. Apply the invariant regardless of the input `req_type`: `/start_profile` overwrites that field, so an input STOP value must not bypass validation.

HTTP returns the existing validation response (400); Python Engine calls raise `ValueError` before invoking the tokenizer manager. Typed msgpack decoding enforces the same invariant. Ordinary manual profiling and its existing step-limit behavior are unchanged. Add the requirement to the field comment and register focused CPU regression tests.
