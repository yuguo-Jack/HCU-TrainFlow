# [Fix] [AMD] aiter: Refuse an MLA draft model under DCP with a clear error

[Upstream PR](https://github.com/sgl-project/sglang/pull/47814) · state: open · merged: False

## Original PR description

## Motivation

- An MLA draft (EAGLE, NEXTN, STANDALONE) on aiter with `--dcp-size > 1` crashes at startup with an opaque `AttributeError: 'NoneType' object has no attribute 'shape'` in `forward_extend`.
- Cause: the draft keeps a replicated KV pool, but the MLA model code still routes its extend through the DCP decode branch without the step's keys. The aiter extend cannot run that.
- Users get no hint that the configuration is unsupported or what to change.

## Modifications

- `AiterAttnBackend._reject_mla_draft_under_dcp` raises a clear `ValueError` when the backend is built, like the other `_reject_*` guards.
- It reads `hf_config` only after the cheap checks, so targets and test fakes without `hf_config` are unaffected.
- The CPU unit test `test/registered/unit/layers/attention/test_aiter_mla_draft_dcp_guard.py` pins the guard.

| Case | Result |
|---|---|
| MLA draft, DCP > 1, KV replicated | `ValueError`: use `--dcp-size 1` or a non-MLA draft |
| ROCm DSA draft (shards KV like the target) | allowed |
| Target model, non-MLA draft (e.g. DSpark MHA), DCP 1 | unaffected |

- Not covered: the check runs after weights load; drafts on another attention backend; real support, which needs the draft at DCP 1 in the model, the backend and the pool.

## Accuracy Tests

DeepSeek-V2-Lite-Chat as its own STANDALONE draft, TP2, fp8 KV, aiter, MI355X. GSM8K: sgl-eval 0.1.3, 200 questions, greedy.

| Setup | Before | After |
|---|---|---|
| DCP2 | `AttributeError` at startup | `ValueError` with the message |
| DCP1 | runs | runs: GSM8K 0.54, accept length 3.75 of 4 |

## Speed Tests and Profiling

- None: this only replaces a crash with an error.
