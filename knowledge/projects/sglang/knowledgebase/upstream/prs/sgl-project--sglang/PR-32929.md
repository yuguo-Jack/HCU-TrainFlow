# [NCCL RAS] Integrate runtime diagnostics into health checks (detection + reporting)

[Upstream PR](https://github.com/sgl-project/sglang/pull/32929) · state: closed · merged: False

## Original PR description

## Motivation

Closes #32928.

SGLang's forward watchdog detects collective hangs via timeout but cannot pinpoint which rank errored, cannot sense cross-node death early, and cannot observe a whole-job crash. NCCL 2.28.7+ exposes exactly that data via a local RAS socket (`STATUS` command → job-wide JSON: per-rank states, `missing_ranks[]` with `unresponsive`/`considered_dead`, per-collective counts). This PR adds a **detection-only** RAS collector that feeds the existing Prometheus + structured-log channels — a supplement, not a replacement, for the forward watchdog.

## What's included

**New `python/sglang/srt/distributed/nccl_ras.py`** (pure Python, no NCCL C-binding — reads the socket text protocol):
- `parse_status` — tolerant parser; caches the parsed timestamp epoch.
- `RasSocketClient` — short-connection `SET FORMAT json` + `STATUS`; skips the `OK\n` ack; refused/timeout/malformed → `None`; bounded recv (16 MB).
- `RasDetector` — state machine `HEALTHY → UNKNOWN → SUSPECT → STUCK → ERROR → DEAD`.
- `RasMonitor` — daemon thread; log-only fallback when metrics are off.

**Detector priority (verified on real NCCL 2.30.7):**
1. poll failure / connection refused → `poll_success=0` (single-node crash signal);
2. per-rank NCCL error states (`async_error`/`abort_flag`/`finalize`/`destroy`) → `ranks_in_error`;
3. (cross-node) dead/unresponsive from `missing_ranks[]` — `unresponsive` ~5s, `considered_dead` ~60s, `peer_dead_transitions_total` counter;
4. (advisory) collective divergence — subgroup lag sustained for `stuck_polls`; all-zero samples dropped; **symmetric whole-collective hangs intentionally do not fire** (left to the forward watchdog — RAS `collective_counts` does not diverge when the whole collective is stuck).

> Note on "detect collective progress divergence" (#32928): implemented as **advisory only**. GPU verification showed RAS `collective_counts` are cached/intermittently-all-zero and do not diverge under symmetric hangs — divergence is reported only for genuine subgroup lag, and the forward watchdog remains the primary hang detector.

**Metrics (`observability/metrics_collector.py`)** — 11 `sglang:nccl_ras_*` series in the existing collector (DI/Ray-inherited), `log_nccl_ras`. Bounded labels: `comm_hash` (+`collective`/`state`); **no `rank` (high cardinality), no `comm_name` (deferred)**.

**Lifecycle (`managers/scheduler.py`)** — `init_nccl_ras_collector`: world-rank-0 election (NOT a dp/tp/pp all-zero predicate, which silently elects zero collectors under plain TP/PP where `dp_rank` is None); two-level gate (loop+logs run when enabled; Prometheus writes gated on `metrics_collector is not None` with a one-time warning); `NCCL_RAS_ENABLE=1` setdefault; stop in `run_scheduler_process` `finally`.

**Communicator `name` passthrough** — `PyNcclCommunicator.name` (srt + multimodal_gen). Groundwork for a future hash↔name registry; not consumed in this PR.

**Env vars** — `SGLANG_NCCL_RAS_{ENABLE,POLL_INTERVAL,STUCK_POLLS,ADDR}` (default-off/inert; no NCCL version bump — torch's pinned `nvidia-nccl-cu13` already satisfies ≥2.28.7; older/absent RAS degrades to `poll_success=0` without crashing).

**Docs** — `environment_variables.mdx` (env vars) + `production_metrics.mdx` (series).

## Tests

`test/registered/unit/distributed/test_nccl_ras.py` — 34 CPU tests, `register_cpu_ci` (`base-a-test-cpu`):
- Parser: golden fixture + `missing_ranks[]` schema + `OK\n` ack + tolerates missing fields + unparseable timestamp.
- Detector: per-rank error states → ERROR; poll None → `poll_success=0`; `missing_ranks` `unresponsive` → SUSPECT; `considered_dead` False→True counted once; all-zero sample drop (no false stuck); **symmetric hang not stuck**; subgroup lag → STUCK; RECOVERED reset; `is_initializing` grace; staleness → UNKNOWN.
- Metrics: series + labels (no `rank`/`comm_name`).
- Election: world-rank-0 starts; non-zero world rank no monitor; metrics-off warning + log-only; bootstrap setdefault.

## Verification

- **CPU unit tests: 34/34 pass.**
- **GPU E2E** (2×RTX 4080 SUPER, NCCL 2.30.7, TP=2, `SGLANG_NCCL_RAS_ENABLE=1 --enable-metrics`): `[TP0] RAS collector elected on world rank 0`; `curl /metrics` shows `nccl_ras_poll_success=1`, `nccl_ras_last_collection_age_sec` advancing (0.025–0.11s), 2 communicators, `nccl_ras_communicator_state{state="HEALTHY"}=1`, all counters 0. Direct `localhost:28028` STATUS confirmed live NCCL 2.30.7 data.
- **Cross-node dead-rank repro** (documented in #32928): captured `unresponsive` ~5s / `considered_dead` ~60s on a 2-rank idle-worker harness — the path a single-node hard-crash cannot show (job tears down before RAS's ~60s).

## Non-goals / follow-ups

- `comm_name` Prometheus label + hash↔name registry (stable communicator names).
- `POST /support_bundle` (env + server_args + ras_json + comm names).
- Inspector/Parameter API data (`ncclParamGet` runtime probe + bundle key; NCCL 2.30+).
- Opt-in `SGLANG_NCCL_RAS_HEALTH_GATE` → `/health` 503-on-DEAD.
- MONITOR event-stream (real-time, edge-triggered) — removes the symmetric-hang blind spot.

## Checklist

- [x] Detection-only — never aborts/removes ranks; forward watchdog untouched.
- [x] Default off; no new NCCL version requirement (degrades gracefully on old/absent RAS).
- [x] Bounded labels (no `rank`/`comm_name`).
- [x] CPU unit tests + CI registration.
- [x] Docs.
- [x] GPU E2E + cross-node repro verified.
