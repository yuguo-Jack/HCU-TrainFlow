# [sglang-miles] Recover disk-delta checkpoints safely across resets and retries

[Upstream PR](https://github.com/sgl-project/sglang/pull/41274) · state: open · merged: False

## Original PR description

## Motivation

@humansand

Make disk-delta checkpoints safe to reuse/retry after a trainer reset or interrupted apply, reject incomplete publications, and remove unnecessary host work. An unchanged publication should not scan every checkpoint header; full model loading should not invoke memory diagnostics that only feed disabled DEBUG logs.

This targets `sglang-miles`, which already includes `/pull_weights`; the refreshed base is `571212b636baca45e10fa3b4da11a289123f3235`. Companion Miles draft: https://github.com/radixark/miles/pull/3711. Existing NVFP4 W4A16 disk reload/postprocessing is reused; this adds no quantization kernel or wire-format change.

## Modifications

- **Reset/retry:** explicit `pull(0)` reseeds a reused directory; stale positive pulls remain no-ops. Invalidate the applied marker before byte mutation so a failed copy/XOR apply reseeds before retry. Callers serialize startup resets before positive pulls; independent streams cannot share the same local checkpoint.
- **Publication:** validate each delta index's shard/tensor mapping before byte mutation, then verify reconstructed tensor checksums during apply. Reject indexless sharded/empty publications; preserve indexed full checkpoints and the standard unindexed single `model.safetensors` layout.
- **Empty versions:** preserve lineage, compression/encoding, and required metadata validation, then atomically advance the marker without tensor-header scans or byte-mutation setup. A failed marker replacement retains the previous valid version.
- **Loader diagnostics:** gate the two before/after GPU memory probes on DEBUG logging, avoiding their default allocator-cache eviction when the messages are disabled. Actual loading and explicit online-quantization synchronization/cache cleanup are unchanged.
- **Compatibility/scope:** companion Miles scalar staging keeps the existing per-name wire payload and checksum rules and needs no additional receiver format handling. No receiver worker batching, persistent header cache, automatic retry/rollback, selective tensor reload, or no-op GPU reload bypass. The state marker describes the materialized disk checkpoint, not active GPU weights.

This isolates the **deferred snapshot-copy worker change**. Regular CPU tensors stand in for completed D2H buffers; no GPU/DMA, actual pinned pool/backpressure, gathering, scalar batching, publication, receiver apply, or reload is measured. Submission/drain, worker allocations, diff/count, snapshot copy, compression, checksum, and queue return are timed. Input preparation, pool creation, verification, and result disposal are outside timing. Process CPU counts all threads in this one process, not four trainer ranks.

Two warmup pairs precede five measured pairs; B→C/C→B order alternates. All **28 samples** passed full snapshot/decode/checksum/count verification, including unchanged old inputs. The unchanged case uses identical canonical bytes. The changed case reconstructs the published synthetic v1→v2 states: **79,500,803 changed bytes**, but only **465,303,040 bytes (2.5993%)** belong to wholly unchanged tensors. Its compressed worker payload is **182,769,068 bytes** for both implementations; this excludes safetensors headers/index and is distinct from the end-to-end shard-byte counter.

These windows are not an exact simultaneous whole-host total.
- **Overhead:** membership refresh and journal flush are outside trainer wall/CPU but inside driver wall; receiver snapshots are outside trainer CPU and inside trainer wall. No estimated cost is subtracted. Flush timing is lagged and the final flush has no later measurement. Other ranks can incur observer-induced synchronization delay.
- **Coverage:** before/after membership checks are non-atomic. Entirely transient or newly born children omitted during concurrent exits may remain unobserved. Receiver source is verified through configured launch/PYTHONPATH, without independent loaded-module attestation. Container CPU quota files may be unavailable; observed affinity/cgroup/thread settings are retained and matched.
- **Meaning:** wire bytes are compressed serialized shards, excluding index JSON and startup checkpoint copy; broadcast byte counters are unavailable, not zero. Checksums, acknowledgements, replay and successful training do not prove active GPU byte equality or learning equivalence. Synthetic balanced reward is an explicit transport workload, not task-quality evidence.
