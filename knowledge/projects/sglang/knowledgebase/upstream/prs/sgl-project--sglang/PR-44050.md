# [WIP] Adds the SGLang kernel and runtime primitives required by UBTree 

[Upstream PR](https://github.com/sgl-project/sglang/pull/44050) · state: open · merged: False

## Original PR description

## Motivation

UBTree verifies a proposal tree rather than a linear draft sequence. For models using KDA linear attention, directly saving a complete recurrent state for every proposal node introduces substantial memory traffic and temporary-state overhead, especially for rejected branches.

This PR adds the SGLang kernel and runtime primitives required by UBTree to:

- share one pre-tree recurrent state across all proposal nodes;
- represent each node using root-to-node factors;
- verify tree nodes without materializing a complete recurrent state per branch;
- restore only the accepted root-to-leaf path after verification;
- capture the fixed-width UBTree decode path with CUDA Graph.


## Modifications

### 1. Factorized KDA tree verification

Added a factorized KDA verification path for UBTree:

```text
fused causal convolution + tree transform
→ factor generation
→ factorized tree verification
→ target logits and speculative acceptance
→ accepted-path fold/commit
```

Instead of storing a complete recurrent state for every tree node, the implementation uses:

- one shared pre-tree recurrent state;
- root-to-node factors describing each node's state update;
- an accepted-path fold to recover the final recurrent state.

This avoids preserving full recurrent states for rejected branches.

### 2. Fused causal convolution and tree transform

Added a fused kernel that combines:

- causal convolution over proposal tokens;
- tree-node input transformation;
- preparation of inputs consumed by factor generation.

This removes an intermediate kernel launch and reduces intermediate tensor traffic.

### 3. Accepted-path state commit

Added tree-aware KDA and convolution-state commit logic.

Only nodes on the accepted path are folded into the persistent recurrent state. States belonging to rejected branches are not committed or replayed.

### 4. CUDA Graph support

Added fixed-width Decode CUDA Graph support for the UBTree path, including:

- stable graph buffers for tree metadata;
- accepted-path commit in the graph tail;
- target KV movement in the graph tail;
- fixed-width proposal and target verification;
- reuse of scheduler and attention metadata during graph replay.

### 5. FA3 tree-verification support

Added FA3 metadata handling for tree verification, including a QLEN-only tree-mask path that avoids rebuilding and transferring a dynamic full attention mask on every decode step.

### 6. Tests

Added tests covering:

- fused causal convolution and tree transform;
- factorized KDA tree verification;
- KDA backend integration;
- FA3 CUDA Graph metadata handling;
- CUDA Graph replay correctness.

## Integration Boundary

This PR provides reusable SGLang kernel and runtime primitives for tree verification.

Proposal-tree construction, draft-model loading and proposal-node selection remain in the external Ling-Spec UBTree plugin. Changes in SGLang core are required for:

- KDA recurrent-state management;
- factorized tree verification;
- accepted-path state commit;
- FA3 tree metadata;
- CUDA Graph capture and replay.

Existing target-only and speculative-decoding paths remain unchanged unless UBTree tree metadata is explicitly supplied.

## Design Notes

A fully monolithic factor-generation and factor-verification kernel was evaluated but is not included because it increased register pressure and did not provide an end-to-end performance improvement.

The current implementation keeps factor generation and verification separate while removing the more expensive full branch-state materialization.

## Known Limitations

- Only BS=1 is covered by the current factorized fast path.
- CUDA Graph capture uses a fixed verification width.
- The initial implementation targets Ling3 KDA models.
- Adaptive tree width and multi-batch scheduling will be addressed separately.
- Proposal-tree construction is provided by the Ling-Spec UBTree plugin and is not part of this PR.
