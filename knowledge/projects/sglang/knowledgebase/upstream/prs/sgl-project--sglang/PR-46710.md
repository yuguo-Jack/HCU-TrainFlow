# [Fix] hicache: Reject host mappings that exceed NUMA capacity

[Upstream PR](https://github.com/sgl-project/sglang/pull/46710) · state: open · merged: False

## Original PR description

## Motivation

HiCache's host-wide budget can accept a buffer that cannot fit in the worker's permitted NUMA nodes. For example, a single rank can pass the global budget check for a 127 GiB buffer while bound to a node with about 126 GiB total RAM.

This adds a physical-capacity check before the built-in mmap and SHM allocators create a new mapping. It catches an impossible pinned-buffer size early, with the requested size and permitted nodes in the error.

Related work:

- #35540 divides the host budget among local ranks. This patch preserves that calculation and checks the allocation's NUMA scope.
- #38208 already notes the NUMA blind spot while addressing hugepage accounting.
- #45516 addresses a related budget overestimate in CPU serving. This patch covers HiCache's built-in host allocators.

## Modifications

- Read the task's memory policy and cpuset allowance. For ordinary strict binding, sum the total RAM of the permitted nodes.
- Keep preferred/interleave fallback valid. Handle static and relative node masks; use only the cpuset bound for unhandled policy flags.
- Check before mapping or prefaulting memory. For SHM, select the backing file first and use only the cpuset ceiling for the `/dev/shm` fallback, whose mount policy can override task binding. Close the descriptor if the check rejects the request.
- Preserve existing behavior if policy/sysfs information is unavailable.
- Add CPU regressions and document the limit.

This is a **per-mapping total-capacity ceiling**, not an available-memory estimate or reservation. Several smaller pools can still exhaust a node. External allocator backends are outside this change.

## Accuracy Tests

No model-forward or output changes.

From a checkout with SGLang's test dependencies:
```bash
python3 test/registered/unit/mem_cache/test_numa_memory.py
python3 test/registered/unit/mem_cache/test_mmap_allocator.py
python3 -m pytest test/registered/unit/mem_cache/test_host_memory.py \
  test/registered/unit/mem_cache/test_mem_pool_host.py::TestHostMemoryBudget -q
```

**35 tests passed locally.** Synthetic topology makes the regressions independent of the machine's NUMA-node count. The new rejection test fails on the base allocator in all six allocator/hugepage combinations; allocation sentinels stop each case before mapping memory.

A separate bounded Linux-policy check reproduced acceptance before the patch and rejection by the new helper under strict binding. It allocated no KV. Full server startup and driver recovery were not tested.

## Speed Tests and Profiling

No inference benchmark: the check runs when creating a host mapping. It adds policy queries and sysfs reads to that path; startup overhead has not been measured.
