# [Fix] Forward scheduler SIGQUIT through the DP controller

[Upstream PR](https://github.com/sgl-project/sglang/pull/40365) · state: closed · merged: False

## Original PR description

## Motivation

Fixes #40364 

When `DataParallelController` is used, DP schedulers are children of the controller rather than direct children of the Engine.

If a scheduler raises an exception, `run_scheduler_process()` sends `SIGQUIT` to its direct parent. In this process topology, that parent is the DP controller. Because the controller has no SIGQUIT handler, the default action terminates it instead of notifying the Engine.

This has two consequences:

1. The Engine does not receive the original scheduler failure notification.
2. The remaining scheduler children are killed by their configured parent-death `SIGKILL` when the controller exits.

The controller may also spend a substantial amount of time generating a core dump before the Engine watchdog observes its exit.

This change complements #35804. That PR detects scheduler exits inside the controller, including failures that cannot send SIGQUIT themselves. Its watchdog sends SIGQUIT to the controller process, so the forwarding handler added here is still required for that notification to reach the Engine.

## Modifications

- Register a SIGQUIT handler in `run_data_parallel_controller_process()` before constructing `DataParallelController` and spawning its schedulers.
- Forward the first SIGQUIT notification to the parent Engine.
- Ignore duplicate SIGQUIT notifications from other ranks in the same distributed failure.
- Keep the controller alive after forwarding so Engine cleanup can still traverse and terminate its scheduler children.
- Add a focused CPU unit test verifying that:
  - the handler is registered before controller construction;
  - two SIGQUIT handler invocations produce exactly one parent notification;
  - the normal controller event-loop and scheduler-join paths remain unchanged.
