# [Perf] Drop unguarded message deepcopies; summarize tools in level-2 request logs

[Upstream PR](https://github.com/sgl-project/sglang/pull/47012) · state: open · merged: False

## Original PR description

## Motivation

Two frontend costs for requests carrying large tool payloads (177 tools in a system message, measured on upstream main with the real `OpenAIServingChat`, medians):

1. **`_apply_jinja_template` deep-copies the dumped messages up to twice per request** — ~15 ms per copy for message-embedded tool payloads: once for the encoder dispatch (`:2049`), again in the dsv32 branch, and again in the ordinary Jinja loop (`:2135`).
2. **Level-2 request logging (the default "partial input") dumps and formats every tool schema in full** — 9.8 ms text / 23.5 ms json for 177 tools, because the 2048 limit counts list *elements*, so a 177-tool list renders completely while the rendered prompt at the same level is cut to 2048 chars.

## Fix

**Removed three deepcopies.** The ownership audit behind it:

- The message dumps share no objects with the request (verified by walking all 227 containers — `model_dump` deep-copies, including `Function.parameters`).
- Every encoder that mutates the dump also handles the request; after a non-None return the dump is dead (media collection re-dumps `request.messages`).
- The ordinary Jinja loop only rewrites `content` keys on the dump itself; `process_content_for_template_format` returns fresh dicts.
- The remaining hazard — a subclass override that mutates `messages` and then returns `None` — is now an explicit contract in the `_encode_messages` docstring.

177 message tools: **34.0 → 4.9 ms** (the remainder is the dump the template path genuinely needs).

**Level 2 logs tool names + count instead of full schemas** (`{"count": N, "names": [...]}`, top-level and message-embedded tools). Level 3 keeps the full payload. Watermark redaction and all other fields unchanged; nothing is cached, per-request metadata stays fresh. Level 2: **9.8 → 0.58 ms** text, **23.5 → 0.63 ms** json.

## Tests / evidence

- New `test_tool_schemas_logged_only_at_level_3`: level 2 logs names without schema text (top-level + message tools, text + json), level 3 keeps full schemas. **Fails on pre-fix**, passes after.
- D1 (copy removal) is behavior-preserving by construction, so instead of a mirror test: a differential probe ran five encoding modes (Jinja string/openai/tool-result-reorder, dsv32, kimi_k3) × request variants (message tools, multimodal, None content, out-of-order tool results, string tool-call args, continue_final_message) through the real `_apply_jinja_template` on baseline and patched trees — **byte-identical across all 40 records**, request objects unmutated.
- `test_serving_chat.py` 173 passed / 255 subtests; full `entrypoints/openai` suite has identical failure sets to clean main (local-env only: missing deepseek_recipe, HF network).
- `pre-commit run --files`: clean.
