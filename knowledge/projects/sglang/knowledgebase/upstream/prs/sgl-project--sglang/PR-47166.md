# [Perf] observability: Send scheduler timing to the tokenizer as typed reports

[Upstream PR](https://github.com/sgl-project/sglang/pull/47166) · state: closed · merged: True

## Original PR description

- Send scheduler time stats to the tokenizer as `time_stats`, a per-row list of `SchedulerOutputTimeStats` msgspec structs, instead of a pickled list of `SchedulerReqTimeStats` objects in `BatchTokenIDOutput` and `BatchStrOutput`. A struct holds only the five values the tokenizer puts in `meta_info` (storage prefetch and staging waits, forward entry, prefill finished, queue time), named and ordered as the `meta_info` keys, with timestamps converted to wall-clock on the scheduler.
- With metrics off, the scheduler builds none and `time_stats` is `None`. Before, every emitted row's stats object went through pickle on every step even though its state was empty.
- `BatchEmbeddingOutput` no longer carries time stats: embedding requests never have a metrics collector, so every row was empty. The tokenizer reads a missing row as empty time stats.
- The detokenizer and the multi-tokenizer split pass the structs through as typed values instead of unwrapping and re-pickling them.
- Remove what only served the old path: `SchedulerReqTimeStats.__getstate__`, `has_timing_data`, `SchedulerReqTimeStats.convert_to_output_meta_info`, and the clock rebasing in `ReqTimeStatsBase.__setstate__`, which no sender uses any more.
- Drop the unused `scheduler_time_stats` argument of `APIServerReqTimeStats.convert_to_output_meta_info`.

No behavior change: `meta_info` and the non-streaming first-token time are the same as before.

## Micro benchmark

One decode step of output on the CPU only: 512 requests, one new token each, built by the real `_GenerationStreamAccumulator`, then pickled and unpickled as the default IPC does. Base and this PR ran interleaved, 6 rounds of 200 steps each; each value is the minimum over rounds (laptop CPU, so absolute numbers are indicative).

| metrics | build (us/step) | pickle (us/step) | unpickle (us/step) | scheduler build + pickle (us/step) | message (KB) |
|---|---|---|---|---|---|
| off, base | 491 | 278 | 250 | 769 | 35.3 |
| off, this PR | 478 | 112 | 133 | 590 (-23%) | 29.6 |
| on, base | 509 | 401 | 585 | 909 | 81.5 |
| on, this PR | 655 | 294 | 267 | 949 (+4%) | 65.0 |

- With metrics off (the default), the scheduler spends 178 us less per step and each receiving process 117 us less.
- With metrics on, receivers spend 54% less on unpickling. The scheduler spends slightly more, because building each row's `SchedulerOutputTimeStats` now happens in the step instead of inside pickle.
