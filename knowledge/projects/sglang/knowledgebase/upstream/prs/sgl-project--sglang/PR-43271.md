# [Fix] DSA/KDA: Handle MoE padding in hybrid MTP verification

## Motivation

<!-- Describe the purpose and goals of this pull request. -->

GLM-5.3-Flash can fail during MTP verification with TP4/EP4 MegaMoE when Decode CUDA Graph is disabled. MoE pads the token tensors, while attention metadata still describes the valid verification sequences. For example, one 6-token verification sequence is padded to 8 rows.

This mismatch causes KDA verification to fail when reshaping QKV. After correcting that path, DSA KPool verification also fails at `assert bn % num_draft_tokens == 0` because it includes the extra padding rows.

## Modifications

<!-- Detail the changes made in this pull request. -->

- Use the logical verification length from attention metadata to trim KDA QKV and gate inputs before convolution and state updates. Restore zero padding in the output to preserve the downstream tensor layout. Keep the ragged verification path unchanged.
- Restrict DSA KPool key, score, and cache-location writes to the token rows covered by the verification write plan.
