## Motivation

This PR addresses the remaining observability gap identified in #35808.

Currently, when a cache read fails, operators cannot distinguish between:
- **"Data not present"** (capacity eviction / cache miss)
- **"Data present but read failed"** (transfer error / corruption)

`UnifiedRadixCache` records some prefetch outcomes internally, but the default collector does not export them. A `batch_exists` hit followed by a failed `batch_get*` is only logged—not exposed as a metric[reference:5]. This makes it difficult to diagnose whether cache hit rate degradation is caused by capacity pressure or underlying transfer failures.

This PR closes this gap by:
1. **Adding Prometheus counters** for cross-tier transfer failures (L1→L2, L2→L3, and reverse), with bounded `op` and `result` labels for low-cardinality classification.
2. **Adding structured logs** containing `rid` (request ID) to trace a single request's KV cache flow across the entire L1 GPU → L2 Host → L3 Storage hierarchy, aligned with the proposal in #35808[reference:6].

These additions transform the KV cache from a "black box" into a fully observable system

- RichardoMrMu · comment · 2026-08-29T07:29:28Z · [source](https://github.com/sgl-project/sglang/pull/36474#discussion_r3885935271)

File: `python/sglang/srt/mem_cache/unified_radix_cache.py` · line None

**[P2] Account timed-out prefetch tails.** can_terminate_prefetch() reports a timeout as a failed prefetch, then check_prefetch_progress() calls terminate_prefetch(), which sets operation.is_terminated(). In _page_transfer(), that stops later storage batches without setting prefetch_read_failed. A multi-batch timeout can therefore reach this block with completed_tokens < expected_tokens, but only l3_actual_read_tokens is incremented. The exported counters then satisfy l1l2_miss_tokens - l3_miss_tokens > l3_actual_read_tokens + l3_read_failed_tokens, so the missing tail is invisible even though the structured log says timeout. Please classify terminated/timeout separately and charge expected_tokens - completed_tokens to that outcome, with a deterministic test that terminates after the first batch.
