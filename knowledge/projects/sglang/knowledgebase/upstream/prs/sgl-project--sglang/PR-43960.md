# [Scheduler] Filter finished requests out of running_batch on the non-mixed-chunk prefill path

[Upstream PR](https://github.com/sgl-project/sglang/pull/43960) · state: closed · merged: False

## Original PR description

## Motivation

`_get_new_batch_prefill_raw()` has two branches: the mixed-chunk branch filters `running_batch` before mixing it into the prefill batch, while the `else` branch leaves `running_batch` untouched. A request that lands in `running_batch` is then only ever removed by `update_running_batch()`, which runs exclusively on the decode path — and under chunked prefill that path is starved, because a chunked prefill is essentially always in progress and `_get_new_batch_prefill_raw` keeps producing prefill batches.

As a result `len(running_batch.reqs)` — logged as `#running-req`, exported as the `num_running_reqs` gauge, consumed by `/v1/loads` — grows monotonically for the whole run and over-reports the worker's load.

This is not limited to any special flag: `is_mixed_chunk = chunked_prefill_size is not None and enable_mixed_chunk`, and `enable_mixed_chunk` defaults to `False`, so the `else` branch is the common path. (The earlier #23895 framed this as `return_logprob=True`-specific; that PR is stale — it calls `filter_batch(v1_spec_info_filtered=True)`, a kwarg that no longer exists.)

## Modifications

Add the missing `running_batch.filter_batch()` to the `else` branch of `_get_new_batch_prefill_raw()` in `python/sglang/srt/managers/scheduler.py`.

```diff
         else:
+            # The mixed-chunk path above filters running_batch before mixing it into
+            # the prefill batch; without it, finished requests are never removed and
+            # #running-req / num_running_reqs grows monotonically for the whole run.
+            running_batch.filter_batch()
             new_batch.decoding_reqs = None

Fixes #43961
