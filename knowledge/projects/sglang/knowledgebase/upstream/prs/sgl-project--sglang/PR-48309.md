# [Perf] memory: Expand single-GPU decode graph coverage

[Upstream PR](https://github.com/sgl-project/sglang/pull/48309) · state: open · merged: False

## Original PR description

## Motivation

Single-GPU decode batches can exceed the default CUDA graph ceiling while ample GPU memory remains. Those batches fall back to eager execution, which is expensive for CPU-bound decode workloads.

## Modifications

- With default graph and memory settings, extend decode coverage to 512 requests above 60 GiB and 256 at 35–60 GiB. Charge the additional graphs to the static memory reserve and preserve the existing running-request limit.
- Respect explicit graph/memory choices and exclude configurations the planner does not model, including multi-GPU, speculative decode, dLLMs, hybrid models, multimodal models, and LoRA.
- Keep post-capture KV sizing opt-in. For that mode, bound the default running batch by captured graph sizes, back off on small KV budgets, and reserve sampling state, decode/prefill tails, and allocator fragmentation.
- Add `SGLANG_ENABLE_DECODE_GRAPH_PLANNER=0` to restore the existing graph tier; document the defaults and opt-in behavior.

Related work: [#43645](https://github.com/sgl-project/sglang/pull/43645) accounts for the request-token table in the pre-capture budget; this changes graph coverage and its reserve. [#45608](https://github.com/sgl-project/sglang/pull/45608) addresses a prefill coverage gap for post-capture sizing; this preserves the existing eligibility gate.

## Accuracy Tests

Added CPU tests for full argument-resolution precedence, supported GPU tiers and exclusion gates, reserve sizing, request-cap backoff, and post-capture headroom.

Local validation against current main on macOS: `PYTHONPATH=python python -m pytest test/registered/unit/mem_cache/test_runtime_reserve.py -q` passed all 5 tests. The full argument-resolution suite cannot complete in this environment: its simulated CUDA platform reaches `cutlass_fp8_supported()` without a CUDA device capability (`None >= 9`), also reproduced on unmodified upstream main. All applicable pinned pre-commit hooks pass, including formatting, Python parsing, and indirect-import validation. Linux/CUDA validation remains required.

`PYTHONPATH=python python -m pytest test/registered/unit/model_executor/test_kv_canary_headroom.py test/registered/unit/model_executor/test_pool_configurator.py -q` also passed **77 tests and 48 subtests** locally.

Historical validation supplied with the patch, against `99fd01047d67bb249641a8e50282a1a5218afc63`: 106 focused tests and 56 subtests passed on an A10G environment. H100 greedy outputs matched 64/64; L40S matched 56/64 when the base used eager decode and the patch used CUDA graphs. This is not a claim of bitwise equivalence across execution modes. Worst-sampling, input-logprob, and overlapped-load gates completed all requests without hard OOMs; allocator retries were reported separately.

## Speed Tests and Profiling

Historical same-host measurements supplied with the patch; these were not rerun during this PR preparation. Each result below has one base and one patch measurement. Both arms use default server flags.

| GPU / model / workload | Base output tok/s | Patch output tok/s | Change |
| --- | ---: | ---: | ---: |
| H100 / Qwen3-30B-A3B-FP8 / 1024-in, 256-out, c384 | 3,478 | 6,767 | +94.6% |
| H100 / Qwen3-8B / 256-in, 256-out, c512 | 11,100 | 13,471 | +21.4% |
| L40S / Qwen3-30B-A3B-FP8 / 1024-in, 256-out, c128 | 798 | 995 | +24.7% |
| L40S / Qwen3-8B / 128-in, 128-out, c1024, non-streaming | 4,722 | 4,695 | -0.6% |

The additional graph reserve reduces KV capacity by roughly 1.1–1.5% on the H100 models and 2.0–5.6% on the L40S models listed above. The last workload had a 38.3% higher median TTFT, despite nearly unchanged throughput. Startup also captures additional graphs. Other model families and GPU tiers need wider validation.

Post-capture sizing remains opt-in: its overlapped stress tests exhibited allocator retries, including on the base implementation, and its tighter running cap can reduce throughput for large resident batches.

To reproduce the primary H100 workload, start the server on the base or patch checkout:

```bash
python -m sglang.launch_server --model-path Qwen/Qwen3-30B-A3B-FP8 --port 30000
```

In a separate terminal, run the same client against each arm, with the planner and post-capture environment overrides unset:

```bash
python -m sglang.benchmark.serving --backend sglang \
  --model Qwen/Qwen3-30B-A3B-FP8 --host 127.0.0.1 --port 30000 \
  --dataset-name random --random-input-len 1024 --random-output-len 256 \
  --random-range-ratio 1.0 --num-prompts 1152 --max-concurrency 384
```
