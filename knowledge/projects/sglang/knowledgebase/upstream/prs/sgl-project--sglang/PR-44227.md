# [Fix] benchmark: Honor chat stream overrides when decoding responses

[Upstream PR](https://github.com/sgl-project/sglang/pull/44227) · state: open · merged: False

## Original PR description

## Motivation

The chat benchmark lets `extra_request_body` override `stream`, but response decoding still follows the CLI default. Setting `stream=false` can report a successful request with empty generated text; the reverse override attempts to decode SSE as JSON and fails.

## Modifications

Use the final payload's `stream` value to select JSON/SSE decoding, and the same override precedence when multi-turn requests default `stream_options.include_usage`. Extend the existing HTTP-backed prompt-length suite to cover both directions, preserve generated text and per-round usage, and check that the caller's body is unchanged.

## Accuracy Tests

No model-forward or inference-engine behavior is changed. CPU tests use a local HTTP server that chooses JSON or SSE from the actual received request.
