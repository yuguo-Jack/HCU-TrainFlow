# [Fix] Kimi-K3: Fix derived weight buffers across CUDA graph reloads

[Upstream PR](https://github.com/sgl-project/sglang/pull/43675) · state: open · merged: False

## Original PR description

## Motivation

Reloading Kimi-K3 weights after CUDA graph capture can leave captured operations reading old derived-weight storage. AttnRes also retains its cached norm/projection product after the underlying weights change, affecting eager execution as well.

## Changes

- Preserve MLA absorbed projection buffers across reloads.
- Reuse merged MoE front and CUDA BFA buffers, restoring parameter views into the merged storage. Preserve the dequantized BFA projection buffer as well.
- Reuse the ROCm fused KDA input-projection buffer across reloads, preserving whole-buffer, BFA-tail, and parameter-view addresses.
- Refresh CUDA KDA fused-decode tensor arguments in place.
- Refresh both BF16 and FP32 AttnRes cached products in place during post-load processing.
- Add repeated-reload regressions and replace dynamic attribute access in the MLA test with direct tensor access.

The reload contract assumes unchanged model configuration, shapes, dtypes, and devices. Native ROCm kernels and all quantized loader variants are not covered by this validation. This is not a claim that every K3 hot-update path has been validated.

## AMD/ROCm follow-up

The Python buffer-lifecycle fix for the ROCm fused KDA input projection is included and regression-tested on H100 by invoking `_merge_kda_inproj_weights_hip()` with an eligible fixture. Native AMD/ROCm graph replay, fused kernels, and token-threshold branches still need validation, tracked in [#47508](https://github.com/sgl-project/sglang/issues/47508). H100 results do not establish ROCm end-to-end hot-update correctness.

## Validation

The original MLA regression failed before its fix and passed after it on one H100, with exact graph/eager projection equality after two successive updates.

The four additional regressions exercise front-weight views, dense/dequantized BFA buffer lifetime, CUDA KDA static buffers, and both AttnRes cache dtypes. Each performs two updates after CUDA graph capture, checks changed values, exact replay/eager buffer equality, and stable addresses. The dequantized BFA branch uses a mocked dequantization boundary returning fresh tensors; it does not validate an FP8 quantizer.

On one H100 80GB using PyTorch `2.14.1+cu130` / CUDA 13.0 and `lmsysorg/sglang:dev` at digest `sha256:78142f9f4b7fb3ee27f59065615dc7bb263f643ed256c9299c3861086ade4d47`:

- All four new cases reproduce failures on the previous PR head `f05814ad4eaa02f28afd6d86c3b1fc8fd049e098`, using the same image and test source.
- The complete registered test file passes **10/10** in **11.659 seconds** with commit `cc5159e`.

```bash
PYTHONPATH=python python test/registered/unit/models/test_kimi_k3_bfa_overlap.py -v
```

Follow-up commit `810b49e2bc3ee7d80ebc3beb520638f77d2a29fb` adds the HIP input-projection storage regression. On one H100 PCIe with PyTorch `2.14.1+cu130` / CUDA 13.0 and image digest `sha256:77ff63ee69fd7ebef20df3a6d036ee4b8a4ffe0734efb0028c3b7643386e3ccf`:

- The same new test fails against parent `58a5db50225e8aad6b3a3ee9652b90e122a4e8ea` (including stale replay values after the second update) and passes after the fix.
- The complete registered test file passes **11/11** in **10.802 seconds** using full SGLang imports.
- The regression captures tensor copies, checks exact replay/current-buffer equality and stable addresses across two reloads, verifies parameter aliases and zero padding, and does not execute AMD fused kernels.

Applicable pre-commit checks pass. Full-model accuracy, real rollout weight synchronization, and performance benchmarking are outside this validation.

[by Claude Code] **Severity: functional | Confidence: Medium**

**Issue**

This keeps `w_kc`/`w_vc` stable, but a K3 weight update after CUDA graph capture can still give wrong output. Later in the same `post_load_weights()`, `_merge_front_weights()` and `_merge_bfa_weights()` build a new merged buffer with `torch.cat` and rebind `_front_w`/`_bfa_w`. `_prepare_fused_decode()` also allocates new `_k3_fused_decode_args`. The graphs still point at the old buffers, which are now freed, so the allocator can reuse that memory. `get_cw()` also keeps its first-load cache, so eager mode is stale too.

**Fix**

Make these buffers reload-safe in the same way (copy into existing storage, clear the `get_cw` cache), or link a tracking issue so K3 hot updates are not treated as fixed.

**Fix** in `_merge_kda_inproj_weights_hip()`:

```python
previous = self._qkvgbfa_layer
merged, sizes = _merge_weights_as_views(
    [self.fused_qkvg_proj, self.f_a_proj, self.b_proj],
