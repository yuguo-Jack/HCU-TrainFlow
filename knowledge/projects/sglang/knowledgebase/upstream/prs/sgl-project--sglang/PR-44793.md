# [Feat] decisions: Support cold shared-prefix prefill with MIS

[Upstream PR](https://github.com/sgl-project/sglang/pull/44793) · state: open · merged: False

## Original PR description

## Motivation

A cold `/v1/decisions` request can prefill the same input once per question. The engine already supports MIS query sharing and Qwen3.5/3.8 GDN state branching from #33922, but the decisions route rejects `--enable-mis` and submits full prompts as separate items.

## Modifications

- Pack the questions' common token prefix as the MIS query and their remaining tokens as independent items. Preserve per-question labels, temperature, raw label mass and caller order. Keep the ordinary path unchanged.
- Check the complete packed prefill budget and reject images and speculative decoding. Keep the existing System One behavior. `usage.prompt_tokens` reports the packed sequence.
- Propagate MIS positions to the mRoPE tensor consumed by Qwen3.5/3.8. Empty-query delimiters receive a valid dummy position, avoiding an invalid fused-RoPE lookup.
- Extend the existing CPU suites and document the opt-in behavior and limits. No new GDN kernels or cache support.

```mermaid
flowchart LR
    A[Render question prompts] --> B[Common prefix + question tails]
    B --> C[Existing MIS score request]
    C --> D[Item-relative positions + mRoPE]
    D --> E[Shared query prefill + independent GDN branches]
    E --> F[Per-question label scores]
```

## Accuracy Tests

Validation covers the serving contract on a fixed synthetic workload:

- `test_serving_decisions.py`: **30 passed**; `test_gdn_mis_metadata.py`: **5 passed**.
- Existing `test_qwen35_gdn_multi_item_scoring.py`, with the pinned **Qwen3.8-27B** checkpoint: **3 passed**, including empty queries, sibling changes/reordering and concurrent requests.
- Negative controls reproduce the original MIS refusal and wrong mRoPE coordinates. Removing the empty-query clamp reproduces the invalid RoPE index; the final long empty-query replay returns 200 with finite scores.
- `/v1/decisions` equals manually packed `/v1/score` exactly. Changing a sibling's contents without changing its shape leaves the other rows bit-identical.
- Additional GPU edge checks cover single/identical questions, concurrency, image and oversized-input refusals, and valid requests after errors. These exercise unchanged no-speculation/nonempty-prefix paths; final-commit API parity, content isolation and the long empty-query replay were executed again.

**Scores are not numerically interchangeable with the original prompts.** All eight top-scoring labels matched on the main workload, but normalized probabilities differed by up to **0.152**; separate single-question probes reached **0.191** because the prefix split changes. Expected numeric scores can therefore change too.

A fixed-query packed-versus-single check measured **0.02236** with the default BF16 readout, failing an initially chosen 0.02 normalized bound. That bound was incorrectly derived from #33922's **unnormalized** score test; it is not presented as passing. BF16 logit steps amplify small layout differences. With the existing FP32 LM-head flag, the measured maximum was **0.01270**. An independent, unchanged SIS reference with an FP32 head moved **0.02500** when only prefill chunking changed. These are measurements, not accuracy or determinism guarantees. No test tolerance was relaxed.

## Speed Tests and Profiling

One NVIDIA GB300, TP=1, Qwen3.8-27B revision `1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0`, BF16 weights/KV and FP32 GDN state. Torch 2.14.1+cu130, Transformers 5.19.0, FlashInfer 0.7.2, sglang-kernel 0.4.10. Eight questions share 3,985 tokens. Both arms disable radix caching, chunked prefill and CUDA graphs; concurrency 1, three kernel warmups, ten measured HTTP round trips, zero errors.

| Mode | Median complete-request latency | Computed tokens | Cached tokens |
| --- | ---: | ---: | ---: |
| SIS, base `456231e251` | 1217.5 ms | 32,155 | 0 |
| MIS, this change | 320.0 ms | 4,269 | 0 |

**3.81× faster on this workload, with 86.7% fewer computed tokens.** The API input is the same; MIS delimiter semantics differ as described above. The final profile records 48 `_forward_extend_mis` calls and 96 `_forward_mis_segments` calls: one query phase and one item phase for each GDN layer.

```bash
CUDA_VISIBLE_DEVICES=0 PYTHONPATH=python python -m sglang.launch_server \

  --served-model-name qwen38-decisions --host 127.0.0.1 --port 31500 \
  --tp 1 --dtype bfloat16 --kv-cache-dtype bfloat16 --mamba-ssm-dtype float32 \
  --attention-backend flashinfer --linear-attn-prefill-backend triton \
  --disable-radix-cache --chunked-prefill-size -1 \
  --cuda-graph-backend-decode disabled --cuda-graph-backend-prefill disabled \
  --context-length 32768 --max-prefill-tokens 32768 \
  --max-running-requests 16 --mem-fraction-static 0.7 \
  --enable-mis
```

```python
import statistics
import time
import requests

state = "\n".join(
    f"[{i:03d}] customer: order #{4400 + i} "
    f"{'was charged twice' if i % 5 == 0 else 'shows as shipped but has not arrived'}; "
    f"agent: we escalated to {'billing' if i % 5 == 0 else 'logistics'} "
    f"and will update within {(i % 4) + 1} business days."
    for i in range(110)
)
questions = [{'id': 'team',
  'type': 'choice',
  'question': 'Which team should own this thread?',
  'options': [{'name': 'billing'}, {'name': 'logistics'}, {'name': 'technical'}]},
 {'id': 'refund', 'type': 'yes_no', 'question': 'Does any customer ask for a refund?'},
 {'id': 'urgency',
  'type': 'score',
  'question': 'How urgent is the thread?',
  'levels': ['low', 'medium', 'high']},
 {'id': 'escalate', 'type': 'yes_no', 'question': 'Should a supervisor review this thread?'},
 {'id': 'sentiment',
  'type': 'score',
  'question': 'Overall customer sentiment',
  'levels': ['angry', 'upset', 'neutral', 'happy']},
 {'id': 'channel',
  'type': 'choice',
  'question': 'Which channel is this?',
  'options': [{'name': 'email'}, {'name': 'chat'}, {'name': 'phone'}]},
 {'id': 'fraud', 'type': 'yes_no', 'question': 'Is there any sign of fraud?'},
 {'id': 'resolved', 'type': 'yes_no', 'question': 'Is every issue in the thread resolved?'}]
payload = {
    "model": "qwen38-decisions", "input": state, "questions": questions,
    "return_prompt_token_ids": False,
}
session = requests.Session()
latencies = []
for i in range(13):
    start = time.perf_counter()
    response = session.post("http://127.0.0.1:31500/v1/decisions", json=payload, timeout=240)
    elapsed_ms = (time.perf_counter() - start) * 1000
    response.raise_for_status()
    if i >= 3:
        latencies.append(elapsed_ms)
print("median ms:", statistics.median(latencies))
print("usage:", response.json()["usage"])
```
