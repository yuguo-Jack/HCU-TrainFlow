# [Perf] diffusion: Keep layerwise offload buffers cached between requests

[Upstream PR](https://github.com/sgl-project/sglang/pull/46438) · state: closed · merged: False

## Original PR description

## Motivation

With DiT layerwise offload, `_empty_cache_after_large_release` calls `torch.cuda.empty_cache()` after every release of a `LayerwiseOffloadStrategy` component. On Qwen-Image-2512 this returns about 3.7 GB of reserved memory to the driver after denoising (reserved 20.4 GB -> 16.7 GB). The VAE decode and the next request then reserve it again, about 46 `cudaMalloc` calls per request.

A host-clock probe (no GPU synchronization) over 12 requests on an RTX 5090 showed:

- Denoising time is the same in every request (spread under 0.1 s); GC, swap, page faults, CPU steal and IO wait are negligible.
- The `empty_cache` call costs 0.42 s in a normal request.
- When the driver free/alloc is slow, that call takes 0.54-0.94 s and the decode right after it goes from 0.014 s to 0.5-1.65 s. This produces the occasional request that is 1.5-3 s slower than the rest.

## Modifications

- Skip `empty_cache` after a layerwise release. Layerwise buffers are re-reserved by the next use of the same component, so the blocks stay in the caching allocator.
- Other residency strategies keep their behavior, and devices that share host memory still empty the cache at `finish_request`.
- Trade-off: the allocator keeps those blocks reserved between requests (about 3.7 GB here). Components in the same process reuse them, and the allocator still frees cached blocks and retries if an allocation cannot be satisfied. Other processes on the same GPU see less free memory.

## Accuracy Tests

No numerical change. In the A/B/A/B run below, all 16 output images (including warmups) have the same SHA-256 with and without this change.

## Speed Tests and Profiling

RTX 5090, Qwen-Image-2512 T2I, 1024x1024, 50 steps, true CFG 4 (100 DiT forwards), DiT layerwise offload, text encoder and VAE resident, measured at `49933325`. Runs went back to back on the same GPU in A/B/A/B order with one warmup plus three formal requests each. The metric is wall time from the generate call to a complete host-side RGB image.

| Run | Formal requests (s) | Mean (s) | Per formal request: `empty_cache` / new `cudaMalloc` |
|---|---|---:|---|
| Before, A | 74.132 / 74.362 / 73.000 | 73.831 | 1 / 46 |
| After, A | 71.919 / 71.917 / 71.918 | 71.918 | 0 / 0-1 |
| Before, B | 71.950 / 71.947 / 73.472 | 72.456 | 1 / 46 |
| After, B | 71.918 / 71.915 / 71.917 | 71.917 | 0 / 0-1 |

With the change, the six formal requests are within 0.004 s of each other and VAE decode takes 0.009-0.010 s. One warmup with the change took 81.16 s (the other took 73.33 s; warmups without the change took 73.36-73.70 s). It is outside the formal samples and not explained yet. Other layerwise-offload models have not been measured.
