# [Perf] paged-experts: fewer host syncs in host-planned steps

[Upstream PR](https://github.com/sgl-project/sglang/pull/46567) · state: closed · merged: True

## Original PR description

# [Perf] paged-experts: fewer host syncs in host-planned steps

## Motivation

This PR aims to decrease TTFT.

Currently, Paged Experts (#42557) plans a step on the host when it routes more entries than the K resident slots: prefill, and decode batches past `K // top_k`. Such a step runs in waves, and each MoE layer syncs with the GPU 6 times plus once per wave (twice on the compacted Marlin path): two reads of the device LRU state, `torch.unique().tolist()`, a blocking upload of each wave's slot map, a `nonzero()` per compacted wave, `step.item()`, and two blocking uploads of the state back.

Profiling Qwen3-30B-A3B-GPTQ-Int4 at K=92 on an RTX 5070 Ti, the GPU sat idle for 24.5 ms of a 79 ms TTFT on a 60-token prompt, inside these MoE layers. The page-in copies themselves already ran at the PCIe ceiling (51.8 GB/s); the idle time was host round trips.


## Modifications

**One host sync per host-planned MoE layer** (`residency.py`, `executor.py`, `runners.py`).
- The step's routed entries per expert are counted on the GPU (`scatter_add_`) and read together with the device LRU state in one copy; all waves are planned from the counts.
- Every wave's slot map goes up in one pinned copy that does not wait for the GPU.
- A Marlin wave is compacted to the entry count the host already has (`nonzero_static`), so it needs no `nonzero()` sync.
- The state goes back in one such copy; the step counter it needs was read with the state.

The device state tensors, the decide kernel of the captured path and the per-expert page-in copies are unchanged.

## Accuracy Tests

**Unit and kernel tests.**
- Multi-wave paged forward on CPU equals the unpaged reference, for both the masked (triton) and the compacted (Marlin) runner contracts; on Marlin, a wrong entry count would drop or duplicate rows.
- The device state round-trips through the host LRU policy and returns the step's counts.

**Paged vs unpaged, 4-layer test models** (E=32, top-4, K=8; prompt and greedy decode logprobs; RTX 5070 Ti; main 2d3de82633 and this PR in one run):

| model | runner | this PR | main |
|---|---|---|---|
| Qwen3-MoE bf16 | triton | identical | identical |
| AWQ int4 | Marlin | decode max 0.014 | decode max 0.014 |
| compressed-tensors NVFP4 | Marlin | median max 0.050, unpaged floor 0.055 | median max 0.050, unpaged floor 0.046 |

Marlin is not run-to-run reproducible, so the Marlin formats are judged against the spread of two unpaged servers (the floor); bf16 on triton is bit-identical. Each check has a negative control that must fail (a perturbed RMSNorm eps on bf16 and AWQ, unnormalized top-k weights on NVFP4), and all three do.

**GSM8K (200 questions), Qwen3-30B-A3B-GPTQ-Int4, K=92:** main 0.945 / 0.945, this PR 0.950.

## Speed Tests and Profiling

Same machine as #42557: RTX 5070 Ti 16 GB (PCIe 5.0 x16, 62 GB RAM), Qwen3-30B-A3B, 10,240 KV tokens and 4 slots, prefix caching off, 16 ShareGPT warm-up requests discarded. Decode tok/s is `1000 / median TPOT` over 8 ShareGPT prompts sent one at a time (256 output tokens each); TTFT and ITL are from the same requests. 4 requests: 16 ShareGPT prompts from 4 clients at once (output tok/s). 2k TTFT: 4 natural ~2,048-token prompts. main (upstream 2d3de82633) is measured first and last in the same run as this PR; both values are shown, and a difference inside their spread is no difference. Prefill is host-planned in every phase; decode with 4 requests stays captured (4 ≤ `K // top_k` = 11, 5 and 10 here).

| config | decode tok/s | TTFT p50 / p99 | ITL p50 / p99 | 4 requests: out tok/s | 2k TTFT p50 / p99 | peak VRAM |
|---|---|---|---|---|---|---|
| int4, K=92: main | 212.3 / 212.7 | 50 / 86, 50 / 82 ms | 4.70 / 5.35, 4.69 / 5.33 ms | 399 / 399 | 239 / 275, 246 / 274 ms | 14.8 GiB |
| int4, K=92: this PR | 212.2 | **40 / 75 ms** | 4.70 / 5.29 ms | 403 | **232 / 262 ms** | 14.9 GiB |
| FP8, K=40: main | 90.3 / 90.3 | 213 / 301, 213 / 300 ms | 10.50 / 20.70, 10.50 / 20.75 ms | 100 / 100 | 427 / 481, 427 / 481 ms | 13.3 GiB |
| FP8, K=40: this PR | 90.2 | **196 / 281 ms** | 10.52 / 20.76 ms | 101 | **410 / 465 ms** | 13.4 GiB |
| NVFP4 (Marlin), K=85: main | 189.6 / 190.6 | 73 / 112, 74 / 118 ms | 5.20 / 6.50, 5.18 / 6.41 ms | 347 / 343 | 257 / 285, 246 / 283 ms | 14.5 GiB |
| NVFP4 (Marlin), K=85: this PR | 189.3 | **62 / 100 ms** | 5.20 / 6.39 ms | 356 | **232 / 272 ms** | 14.5 GiB |

TTFT p50 drops 20% (int4), 8% (FP8) and 16% (NVFP4) for ShareGPT prompts, and 4%, 4% and 8% for a natural 2k prompt, against the mean of the two main runs. Decode, ITL and 4-request throughput are unchanged: captured decode does not take this path.
