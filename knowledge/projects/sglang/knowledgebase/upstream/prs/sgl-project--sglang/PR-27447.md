# feat: add Evo 2 (StripedHyena 2) DNA foundation model with CharLevelTokenizer auto-generation

[Upstream PR](https://github.com/sgl-project/sglang/pull/27447) · state: closed · merged: False

## Original PR description

## Motivation

Evo 2 is a state-of-the-art DNA foundation model trained autoregressively on 9.3 trillion base pairs with up to 1M-token context. It uses the StripedHyena 2 architecture (interleaved attention + Hyena convolutions). This PR adds inference support for Evo 2 checkpoints in SGLang.

Evo 2 uses the Vortex CharLevelTokenizer, which encodes DNA bases as UTF-8 bytes (A=65, C=67, G=71, T=84). The tokenizer is auto-generated on first use since the HuggingFace checkpoint does not include tokenizer files.

## Modifications

- **`python/sglang/srt/models/evo2.py`** — Full StripedHyena 2 model with MHA (RoPE), Hyena-LI/SE/MR convolution layers, gated MLP, and Vortex checkpoint weight loading
- **`python/sglang/srt/utils/hf_transformers/tokenizer.py`** — Auto-detect Evo2 configs (`tokenizer_type: CharLevelTokenizer`) and generate tokenizer.json before HuggingFace loads
- **`python/sglang/srt/parser/code_completion_parser.py`** — Register `evo2` completion template for fill-in-the-middle generation
- **`test/registered/unit/utils/test_evo2_tokenizer.py`** — 16 unit tests for tokenizer generation, encode/decode roundtrip, and auto-detection

Tested with Evo 2 1B (D=1920, 25 layers, 1.1B params, 2.21 GB VRAM) on H100. Supports `/generate` and `/encode` endpoints.

## Accuracy Tests

- **Next-token prediction**: Model correctly predicts DNA bases (A/C/G/T) with tokenizer using UTF-8 byte encoding (A=65, C=67, G=71, T=84). Verified by checking `input_token_logprobs` on known sequences.
- **Generation output**: 100% valid DNA/IUPAC characters over 100-token generation with greedy decoding — no garbage or out-of-vocabulary tokens.
- **Tokenizer roundtrip**: Encode-decode roundtrip verified for DNA sequences of varying length and composition (`ACGT`, `ATGAAACGCATTAGCACC`, `NNNNACGT`, `GATTACA`).
- **Unit tests**: 16 tests covering tokenizer generation, encode/decode correctness, Vortex CharLevelTokenizer byte compatibility, auto-detection, idempotency, and edge cases

This is a critical bug. The Vortex checkpoint stores `mlp.l1.weight` and `mlp.l2.weight` as separate tensors, but they both map to `gate_up_proj.weight` in `_remap_weight_name`. Because `gate_up_proj.weight` is a stacked parameter with twice the size, calling `weight_loader` directly will cause a shape mismatch and completely skip loading these weights, leaving the model with random weights. We must use the defined `stacked_params_mapping` to correctly load each shard with its corresponding `shard_id` so that the parallel linear weight loader can shard and stack them correctly.

```python
    def load_weights(self, weights: Iterable[Tuple[str, torch.Tensor]]):
        """Load weights from a Vortex checkpoint.

        Handles weight name remapping from Vortex format to sglang format.
        """
        stacked_params_mapping = [
            # (param_name, shard_name, shard_id)
            (".qkv_proj", ".q_proj", "q"),
            (".qkv_proj", ".k_proj", "k"),
            (".qkv_proj", ".v_proj", "v"),
            (".gate_up_proj", ".l1", 0),      # gate
            (".gate_up_proj", ".l2", 1),      # up
        ]

        params_dict = dict(self.named_parameters())
        loaded_params: Set[str] = set()

        for name, loaded_weight in weights:
            # Skip non-parameter keys (like _extra_state)
            if name.endswith("._extra_state"):
                continue

            # Remap Vortex weight names to sglang names
            sglang_name = self._remap_weight_name(name)
            if sglang_name is None:
                continue

            if sglang_name not in params_dict:
                logger.warning(f"Parameter {sglang_name} (from {name}) not found in model. Skipping.")
                continue

            param = params_dict[sglang_name]
            weight_loader = getattr(param, "weight_loader", default_weight_loader)

            # Check if the parameter is a stacked parameter
            is_stacked = False
            for param_name, shard_name, shard_id in stacked_params_mapping:
                if shard_name in name:
                    weight_loader(param, loaded_weight, shard_id)
                    loaded_params.add(sglang_name)
                    is_stacked = True
                    break

            if is_stacked:
                continue

            # Handle shape mismatches by reshaping loaded weight to match param
            if param.size() != loaded_weight.size():
                try:
                    loaded_weight = loaded_weight.reshape(param.size())
                except RuntimeError:
                    logger.warning(
                        f"Shape mismatch for {sglang_name}: "
                        f"param={list(param.shape)}, loaded={list(loaded_weight.shape)}. Skipping."
                    )
                    continue

            weight_loader(param, loaded_weight)
            loaded_params.add(sglang_name)

        # Log any unloaded parameters
        unloaded = set(params_dict.keys()) - loaded_params
        if unloaded:
            logger.warning(f"Unloaded parameters: {unloaded}")
```

Writing directly to `tokenizer.json` and `tokenizer_config.json` can cause race conditions and file corruption when multiple processes (e.g., in a tensor parallel setup) try to write to the same shared directory simultaneously. Writing to a temporary file first and then renaming it atomically using `os.replace` prevents this issue.

```python
    os.makedirs(model_path, exist_ok=True)
    temp_tok_path = tok_path + ".tmp"
    temp_cfg_path = cfg_path + ".tmp"
    try:
        with open(temp_tok_path, "w") as f:
            json.dump(tokenizer_json, f, indent=2)
        os.replace(temp_tok_path, tok_path)
        with open(temp_cfg_path, "w") as f:
            json.dump(tokenizer_config, f, indent=2)
        os.replace(temp_cfg_path, cfg_path)
    except Exception as e:
        for p in (temp_tok_path, temp_cfg_path):
            if os.path.exists(p):
                try:
                    os.remove(p)
                except Exception:
                    pass
        raise e
```

Hardcoded indexing like `x[:, :, 0]` assumes the input tensor is exactly 3D. If the input is 2D (which is very common in SGLang during prefill/decode when tokens are flattened), this indexing will slice the wrong dimension or crash. Blocker — forward NaN. On evo2_1b_base with the DNA prompt `ATGAAACGCATTAGCACCACGTACGT`, layer 23 (last HCL/IIR) overflows: hidden_states absmax reaches ~1e15 then `out_filter_dense(inf)` → NaN (weights contain zeros, inf*0=NaN), which `nan_to_num` here masks to 0. The Vortex reference on the same checkpoint + same prompt also reaches 4.6e16 at layer 23 but stays finite and returns the correct next base (T). So this is an implementation gap, not the checkpoint.

Root cause is partly dtype (under `dtype=auto` the generated config allowed fp16, which overflows at layer 23's large pre_norm scale ~5.5 before the IIR FFT) and partly the Hyena filter layout. I prototyped: default `torch_dtype=bfloat16` in configs, run the short/long filter in fp32 with bf16 casts at the boundaries, and align the filter layout to Vortex's channel-first `(B,3D,L)` path. That removes the NaN. Not byte-exact with Vortex yet — see the layer-0 layout note below.

- JustinTong0323 · comment · 2026-06-27T11:18:46Z · [source](https://github.com/sgl-project/sglang/pull/27447#discussion_r3485910125)

File: `python/sglang/srt/models/evo2.py` · line 665

Blocker — decode state missing. Vortex's `HyenaCascade` has `sequential_forward` + `step_fir`/`step_iir` + a `fir_state_dict`/`iir_state_dict` so each decode step only consumes the new token plus a cached short-filter tail / recurrent IIR state. This `forward` runs the short + long filter over the full input length `L`, so in decode (`L=1`) the conv has no history: the IIR collapses to its t=0 impulse sample and the short FIR left-pads with zeros. Attention layers recover history via the KV cache, but the Hyena layers (~80% of layers) keep no state, so autoregressive generation silently loses all temporal context. Serving greedy on the prompt above returns a degenerate repeat. This needs a stateful decode path (cache last `short_filter_length-1` of `x1*v`, recurrent IIR step) — it's a framework-level change, not a one-line fix.

Residual structure. Both `Evo2AttentionLayer` and `Evo2HyenaConvLayer` use sglang's pre-norm fused residual (`RMSNorm(x, residual)` accumulates `residual += x` across all layers).
