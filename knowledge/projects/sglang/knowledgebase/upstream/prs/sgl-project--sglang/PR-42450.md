# [Fix] mimo: Preserve ModelOpt policies for packed projections

[Upstream PR](https://github.com/sgl-project/sglang/pull/42450) · state: open · merged: False

## Original PR description

Reopened from #40675. GitHub closed that PR on 2 October when the fork it came from was deleted; its review history is still there.

MiMo omits `packed_modules_mapping`, so ModelOpt mixed-precision policies for separate checkpoint projections do not reach their fused runtime layers. With NVFP4 experts and block-FP8 dense layers, loading fails at `model.layers.0.mlp.gate_up_proj.weight_scale_inv` because the fused layer never receives its FP8 policy.

Declare the gate/up and split-QKV mappings. The new CPU tests exercise the actual ModelOpt resolver: retained block-FP8 gate/up, split and already-fused QKV, rejection of conflicting fused policies, and an unquantized output projection.

Validation: all five tests pass remotely. Applying the model metadata mapping to SGLang 0f6761b54 also allows the full MiMo-V2.6-Flash-RL NVFP4 checkpoint to load and generate on four RTX PRO 6000 Blackwell cards (TP4/EP4, FlashInfer CUTLASS, Triton attention). An eight-turn conversation returned the expected answers and reused the complete preceding prefix on every later turn. No kernel or activation-precision changes are included.

Duplicate check on 2026-09-22: clean application to upstream b44e2486824e; inspected #37261 and #39080 (DeepEP-v2 dispatch) and #39885 (pipeline/MTP handling). Their MiMo changes do not declare these quantization mappings.
