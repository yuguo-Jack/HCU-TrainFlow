# [Perf] DSA: Share one metadata buffer set across MTP draft steps

[Upstream PR](https://github.com/sgl-project/sglang/pull/44358) · state: open · merged: False

## Original PR description

## Motivation

GLM-5.3-Flash MTP 5/1/6 decode spends about 5% of each step with the GPU outside CUDA graphs. The largest gap is between the draft-extend and draft graphs, where `DeepseekSparseAttnMultiStepBackend` fills each of the 4 draft-step backends separately, though every step ends up holding identical metadata.

## Modifications

- Draft steps 1.. now alias step 0's captured metadata. Replay refreshes step 0 once from the precomputed input, and steps 1.. no longer allocate their own wide `page_table` and seqlen buffers.
- `DeepseekSparseAttnBackend` gets two protected helpers: `_init_cuda_graph_state_shared` sizes only the multi-CTA KV counter, which `_forward_trtllm` reads per backend, and `_share_cuda_graph_metadata` aliases step 0's metadata.
- Sharing does not depend on KPool fusion, so it replaces both the KPool sibling copies and the multi-destination copy block.
- `test_dsa_metadata_replay.py` captures and replays the steps through the wrapper for `index_kpool` 4 (KPool fusion on and off) and 1, and checks that steps share step 0's buffers, only step 0 refreshes, and the result matches the ordinary path.

Sharing is safe because every step consumes the same precomputed input and the draft forward only reads the metadata. All writes to `DSAMetadata` / `KPoolWritePlan` are in the init and replay paths; the one forward-time writer (`dsa_npu_indexer.py`) is prefill-only.

Only GLM-5.3-Flash sets `index_kpool` (4); DeepSeek-V3.2 and GLM-5 through 5.3 use 1. With more than 3 draft steps, those models used the multi-destination copy block, which never refreshed `paged_mqa_schedule_metadata` / `topk_v2_plan` for the first three steps; they now get the full refresh.

Some cleanups this change enables can be done as a follow-up.
