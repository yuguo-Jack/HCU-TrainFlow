# [Perf] deepseek-v4.1: Drop host syncs from encoder-replay folding and tail metadata

[Upstream PR](https://github.com/sgl-project/sglang/pull/45275) · state: closed · merged: True

## Original PR description

- Encoder SWA replay folding and the late-layer tail metadata built small device tensors with copies that block the host until the stream drains: `torch.tensor(..., device=cuda)` (pageable), `.to(device, non_blocking=True)` on pageable host tensors, a 0-dim CUDA tensor used as an index, and `repeat_interleave` without `output_size`. They run once per prefill step with encoder SWA replay on.
- They now go through `async_h2d` or pinned copies, index replay heads with the batch's host pool indices (`req_pool_indices_cpu`), and pass `output_size`. No behavior change: same values, same rows.
- The unit test's fake batch gains `req_pool_indices_cpu`, which `ScheduleBatch` always carries.
- Verification: DeepSeek-V4.1-Flash on GB300, DP2 attention + MegaMoE (EP2), DSpark, encoder and decoder replay on, a multi-turn agentic prefill trace at concurrency 512, 900 s per run.
  - With `torch.cuda.set_sync_debug_mode("warn")` over a full run, no synchronizing call remained on the scheduler's forward path.
  - Throughput is within noise (-0.3% to +1.7% on three nodes): once the request-window reset sync was gone (#45247), the scheduler was no longer blocked on these copies. This keeps the forward path sync-free so a later sync is not hidden behind them.
  - `test_encoder_swa_replay.py` and `test_dsv4_compressed_pools.py` pass.
