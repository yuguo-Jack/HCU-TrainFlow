# [Perf] sampling: JIT softmax and argmax for the sampler and speculative verify

## What this PR does

- Adds a JIT row softmax (`kernels/ops/sampling/softmax_jit.py`, `jit/csrc/sampling/softmax.cuh`): fp32 / bf16 / fp16 logits in, fp32 probs out, per-request temperature fused, in place for fp32. One row per thread-block cluster with the row held in registers (read once, written once). The launch config is chosen per row count from the real occupancy of the compiled candidates. Used on the SM100 family; other platforms keep the existing Triton / Cake / torch paths.
- Adds a JIT row argmax (`kernels/ops/sampling/argmax_jit.py`, `jit/csrc/sampling/argmax.cuh`): int64 output, a tie takes the lowest index.
- `sampling.softmax(logits, temperatures, *, rows_per_request, out)` and a new `sampling.argmax(logits)` dispatch to them (both registered in the kernel registry).
- Sampler: temperature is fused into the softmax and the probs are written in place (no separate `div_` and no copy back); greedy uses the JIT argmax. Deterministic mode is unchanged.
- Speculative decoding: EAGLE verify passes `rows_per_request=draft_token_num` instead of a repeat-interleaved temperature; EAGLE, DFlash, UNO, `fast_sample` and DSpark use the JIT argmax. The DSpark per-model `fused_argmax` opt-in is removed.
- Renames `ops/sampling/temperature_softmax.py` to `softmax_triton.py` and `test_temperature_softmax.py` to `test_softmax.py`.

Behaviour change: the JIT argmax never selects a NaN, while `torch.argmax` returns a NaN's index. The sampler already sanitizes NaN logits; for the speculative verify paths a NaN logit no longer becomes the target token.

Supersedes #44752.

Agreed, this is real. `sanitize_nan_logits` writes `posinf=1e30`, and `fmaf(x, log2_scale, -base)` with `base = round(raw_max * log2_scale)` leaves a residual of about half an ulp of 1.4e30 (~7e22) for the max element. `ex2` then overflows to inf, and the row sum becomes inf/inf = NaN.
