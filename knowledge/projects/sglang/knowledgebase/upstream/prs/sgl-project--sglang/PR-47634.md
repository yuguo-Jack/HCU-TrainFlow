# [Fix] [NPU] attention: Slice MLA latent K after TP all-gather

[Upstream PR](https://github.com/sgl-project/sglang/pull/47634) · state: open · merged: False

## Original PR description

## Motivation

With `SGLANG_USE_AG_AFTER_QLORA=1`, ordinary NPU MLA takes `k_nope` from the local latent cache before all-gather replaces `latent_cache`. The old view still has only this rank's rows, while Q, RoPE K, and KV write locations have the gathered rows. On Ascend 910C, the KV scatter completes without an exception but writes incorrect cache contents.

For example, two ranks with two tokens each produce four Q/RoPE K rows and four write locations, but only two latent K rows per rank.

This affects the non-DSA DeepSeek V3/R1 MLA decode/verify path when MLAPO is disabled and attention receives TP-sharded input, such as after an all-to-all MoE with attention TP > 1. This is not a claim about the separate V3.2 DSA or V4 attention paths.

## Modifications

Slice `k_nope` after the latent-cache all-gather, so both K components use the same gathered token order and row count. Only the existing MLA source file changes; no test files are included.

## Accuracy Tests

Two-rank Ascend 910C function-level validation using real HCCL AllGather, NPU RMSNorm/matmul, and the original `NPUMLATokenToKVPool.set_kv_buffer` against isolated buffers.

| Source | Correct KV caches | Incorrect KV caches | Write exceptions |
| --- | ---: | ---: | ---: |
| Before | 0 / 18 | 18 / 18 | 0 |
| Fixed candidate | 18 / 18 | 0 / 18 | 0 |

Coverage: FP32/FP16/BF16 × 1/2/4 local tokens × 2 ranks. Cache comparison uses `rtol=0.01, atol=0.01`. PyTorch 2.10.0+cpu with torch_npu 2.10.0.post6 and sgl-kernel-npu 2026.9.0.

The hardware candidate inlines the post-gather slice into RMSNorm; this PR expresses the same operation by moving the slice assignment. CPU execution of the actual proposed function also passes TP=1/2/4/8 shape/reference checks. The hardware-tested base is `1f834c19`; the relevant preparation, gather and KV-write sources are unchanged in PR base `ba78bce7`.

Synthetic projection weights are used. Rotary embedding and model scheduling are not exercised; no full-model accuracy evaluation was run.
