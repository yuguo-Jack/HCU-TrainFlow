## Motivation
Support two goals for DeepSeek-V4 DSA attention:

1.cp can cross different node, like DP2CP8EP16
2.save HBM for more kvcahe when using CP, DeepSeekV4 Pro in H200, KV cache capacity 258,816 -> 731,904.

you can use this feature by setting:
export SGLANG_ENABLE_CP_TP = 1

Flow (per layer)
Activation, mHC, q_lora, kv, light-indexer compute along the CP split.
cp all-gather q_lora and kv so each rank holds the full-sequence q_lora/kv.
attention core and w_o compute in TP; all-reduce for the full result.
cp split back into the CP domain; continue to the next layer.



Tests
DSV4 flash PD-disaggregated prefill server verified under TP4, CP4, DP4, DP2, DP2CP2TP2, CP4TP4 — accuracy as expected.

## Code Review

This pull request introduces support for CP-TP (Context Parallelism - Tensor Parallelism) mode in DeepSeek V4, allowing head-parallel Q/O computation within the CP group. It adds environment configuration, validation hooks, and metadata helpers to manage full and local batch metadata during attention computation. Feedback on the changes highlights a critical runtime import error where `get_parallel` is imported from the wrong module, as well as a suggestion to explicitly pass `is_prefill=True` to `init_flashmla_related` for consistency and safety.

File: `python/sglang/srt/layers/dp_attention.py` · line 336

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The function `get_parallel` is defined in `sglang.srt.runtime_context`, not in `sglang.srt.distributed`. Importing it from `sglang.srt.distributed` will result in an `ImportError` at runtime when `is_cp_tp_enabled()` is called.

```suggestion
    from sglang.srt.runtime_context import get_parallel
```
