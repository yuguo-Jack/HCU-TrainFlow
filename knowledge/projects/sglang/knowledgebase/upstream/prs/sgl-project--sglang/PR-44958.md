# [Refactor] platforms: in-tree platforms declare their BaseFusedOp dispatch key

[Upstream PR](https://github.com/sgl-project/sglang/pull/44958) · state: open · merged: False

## Original PR description

## Motivation

`SRTPlatform.get_dispatch_key_name()` is the seam that picks a `BaseFusedOp`'s `forward_<key>()`, but only out-of-tree platforms go through it. In-tree dispatch resolves the key from a separate `is_cuda / is_hip / is_cpu+AMX / is_npu / is_xpu / is_musa` chain in `kernels/fused_op.py`, so two sources answer "which device is this", and they can disagree. For example, with `SGLANG_USE_CPU_ENGINE=1` on a CUDA host, the platform resolves to `CpuSRTPlatform` while op dispatch still keys on `cuda`.

This is the first of a few PRs that route the in-tree platforms through the `SRTPlatform` seams that already exist, so that out-of-tree platforms aren't the only users of those seams.

## Modifications

- Each in-tree platform overrides `get_dispatch_key_name()`:

  | Platform | Key |
  |---|---|
  | CUDA | `cuda` |
  | ROCm | `hip` |
  | MUSA | `musa` |
  | NPU | `npu` (already overridden) |
  | XPU | `xpu` |
  | CPU | `cpu` with AMX, `native` otherwise (the old `is_cpu() and cpu_has_amx_support()` rule) |
  | MPS and the base platform | `native` (default) |

- `fused_op._platform_key()` reads `current_platform.get_dispatch_key_name()` and maps `native` to `""`, which is the plain-native key it already used. The out-of-tree path (`_oot_dispatch_key`) is unchanged.
- `_is_cuda_available()` now also requires `torch.version.cuda`, matching `is_cuda()`. A `torch.cuda` shim over another device no longer resolves to the CUDA platform; torchada's opt-in `TORCHADA_FORCE_CUDA_AVAILABLE` on MUSA is the case that matters. Without that switch, torchada never patches `torch.cuda.is_available()` or `torch.version.cuda`, so default MUSA resolution doesn't change.
- Tests:
  - the per-platform keys, including CPU with and without AMX;
  - `_platform_key()` reading the key from the platform;
  - `_is_cuda_available()` rejecting a non-CUDA build.

Behaviour is unchanged on CUDA, ROCm, NPU, XPU, MUSA, MPS and AMX/non-AMX CPU. The only change is the CPU engine on a CUDA host, which now dispatches CPU paths instead of `forward_cuda`.

## Accuracy Tests

N/A: no kernel or forward change. Dispatch keys are identical on every in-tree platform except the CPU-engine-on-a-CUDA-host case above.
