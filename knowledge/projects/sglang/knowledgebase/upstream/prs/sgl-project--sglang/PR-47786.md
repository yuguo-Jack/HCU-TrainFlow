# [Feat] multimodal: Share CPU preprocessing artifacts across tokenizer workers

[Upstream PR](https://github.com/sgl-project/sglang/pull/47786) · state: open · merged: False

## Original PR description

## Motivation

Repeated images are preprocessed independently by tokenizer processes even when the service-wide cache budget is configured. Add an opt-in, host-local CPU artifact store so workers share one retained copy and one global LRU budget.

## Modifications

- Add `--mm-preprocess-cache-dir`; with this option `--mm-preprocess-cache-size-mb` is a global budget and must be explicitly positive. Default per-worker behavior is retained.
- Reuse `MediaArtifactCacheMixin` and existing typed model artifacts. The shared store uses SQLite indexing/LRU, fixed POSIX lock shards for cross-process single flight, typed JSON metadata, and copy-on-write NumPy mappings of CPU tensors. It adds no dependency.
- Use SHA-256 for lookup and compare actual snapshot bytes plus a complete processor/options witness on hits, including when caller hashes are trusted. This protects the preprocessing store; downstream KV/embedding identity remains its existing contract.
- Remove the Qwen full-prompt template LRU so token IDs and M-RoPE tensors are released with each request. Preserve per-request prompt composition. Flush generations cover work waiting for snapshots, locks and computation. Failed publication returns the computed result; interrupted or damaged artifacts are reclaimed/recomputed.
- Add CPU regressions, documentation and a synthetic streaming benchmark.

Existing work: #34398 supplies the process-local artifact framework reused here; #39335 addresses PIL execution, and #47120 addresses downstream identity. Open model-adapter PRs #45287 and #44181 can use the same common artifact store. Searches found no existing shared-directory preprocessing store.

## Accuracy Tests

- Upstream candidate at base `0f93be7b654d6a208676d060deb995af5df8f7c1`: **125 targeted CPU tests passed** on Linux, including forced content/configuration hash collisions, cross-process single flight, LRU/byte limits, cancellation/process termination, COW, truncated files, and flush races.
- A downstream backport of this same shared backend passed 101 targeted tests; an earlier revision also passed actual-model GPU serving tests. Those GPU checks used that backport in `jpezzulli/sglang-rtxpro6000`; upstream GPU serving with its declared torch 2.14.1/transformers 5.19.0 stack was not separately qualified.
- Real Qwen3-VL and Flash-Next processors, using retained image payloads and complete message/tool histories rendered consistently per processor, produce identical pixel tensors, image grids, raw input IDs, offsets and MRoPE/delta between legacy and artifact paths on cold/hot requests. Artifact-path padded IDs also agree across cold/hot requests; the backported content-based artifact hash changes legacy pad identities by design.
- Actual 3 GiB retention check with 52 insertions of a 68.3 MiB Qwen tensor: 44 retained, 8 evicted, 3005.1 MiB retained, all object files removed by clear, live mapping still usable after eviction.
- Pinned isort, ruff checks/format, codespell and whitespace checks pass. No private requests or media are included.

## Memory retention regression

Qwen previously retained up to 256 complete prompt templates per process, including prompt strings, token tuples and M-RoPE tensors, independently of the image-cache budget. Conversation histories change each turn, so these templates can consume substantial private memory with little reuse. Remove that LRU and keep prompt composition request-local; image artifacts remain cached.

A CPU-only probe used the real Flash-Next processor, a synthetic image and 64 distinct 32,209-32,210-token prompts. Original commit methods retained 64 M-RoPE tensors (49,474,320 bytes); the final implementation retained zero. Private anonymous RSS growth from request 1 to request 64 was 97,208 KiB before and 84 KiB after. All token/position outputs matched by digest. This is a controlled retention regression, not a claim about total serving RSS.

New tests cover prompt-tensor release, processor lifetime and output mutation isolation. Shared-cache capacity still excludes temporary preprocessing, in-progress publications and live mappings after eviction; it is not a total process-memory or tmpfs limit.

The synthetic GPU benchmark remains available at `benchmark/multimodal/bench_shared_preprocess_cache.py`. Earlier GPU A/B measurements included the removed prompt-template LRU and are not presented as final-head performance numbers.
