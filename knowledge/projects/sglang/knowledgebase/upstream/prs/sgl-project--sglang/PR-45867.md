# [Fix] memory_pool: Preserve FP4 MHA block scales during PD and CPU retraction

[Upstream PR](https://github.com/sgl-project/sglang/pull/45867) · state: open · merged: False

## Original PR description

## Motivation

Fixes #45866. With an FP4 KV cache, the block scales aren't sent over PD and aren't backed up on retraction, so decode dequantizes with zero or stale scales.

## Modifications

- Register the per-token scale buffers as `BLOCK_SCALE` for PD (plain `MHATokenToKVPool`), like MXFP8. As with MXFP8, both sides need the same attention TP; the error now says "block-scaled" instead of "MXFP8".
- Include the scales in `get_cpu_copy` / `load_cpu_copy`.
- The default retraction backend (`host_pool`) rejects these scales at startup, so use `cpu_tensor` for this layout.

Only plain MHA pools. MLA FP4 (#44437), PD registration for hybrid pools and draft-model scales aren't covered here; happy to do them next.

## Accuracy Tests

- New CPU test `test/registered/unit/mem_cache/test_fp4_kv_scales.py`: 3 of 5 fail on main, all pass here.
- mem_cache / disaggregation unit tests: no new failures vs main.
- PD e2e, Qwen3-0.6B with fp4_mx_block16: outputs matching non-PD went from 0/8 prompts to 8/8.
