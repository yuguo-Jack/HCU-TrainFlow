# Retry the post-warmup freeze_gc while the listener is still coming up

[Upstream PR](https://github.com/sgl-project/sglang/pull/40653) · state: open · merged: False

## Original PR description

## Motivation

Under `--skip-server-warmup` (and for elastic EP joiners), `_wait_and_warmup` posts `/freeze_gc` without first waiting for the listener. The POST lands before uvicorn accepts connections, fails once, and the GC freeze is silently lost:

```
06:12:13.0719  INFO:     Application startup complete.
06:12:13.0734  post-warmup freeze_gc failed
```

## Modifications

Retry the POST on `ConnectionError` for up to 10 s. Any other error still warns on the first attempt.

## Tests

Three CPU unit tests in `test_http_server_warmup.py`: retried until the listener accepts (fails on the pre-fix code), HTTP errors not retried, retry bounded.

- lauthu · comment · 2026-11-03T03:03:55Z · [source](https://github.com/sgl-project/sglang/pull/40653#issuecomment-6594372193)

Some measurements in support of this fix, from a beam-search benchmark on a fork whose `_wait_and_warmup` matches main's: Qwen3-0.6B, 2,048-token prompts, 256 beams, `--skip-server-warmup`, one RTX PRO 6000 with an AMD EPYC 9124 host.

- Without the freeze, the startup heap stays in GC scope: about 1.0M tracked objects in the tokenizer manager and 1.1M in the scheduler. Each full collection took 0.39 s and 0.48 s, with the process stalled.
- The same server with only the freeze fixed, one round of 600 requests per concurrency, GC logging on:

  | Concurrency | Freeze refused: mean / p99 / max (ms) | Freeze working: mean / p99 / max (ms) |
  | ---: | ---: | ---: |
  | 2 | 54.2 / 109 / 520 | 52.9 / 87 / 124 |
  | 8 | 169.2 / 630 / 635 | 153.9 / 288 / 300 |

One suggestion: report `ServerStatus.Up` only after the freeze. With Up first, clients can start sending requests while the freeze is still pending. In our runs a version with that order had the freeze land on the server's first few requests, adding 40-70 ms to each. Our version waits for the listener with the same `/model_info` poll that the warmup path already uses, then freezes, then sets Up: https://github.com/lauthu/sglang/commit/3ab9a26278a706a7347d4b4ff3a41f69bf4b02a4 (with a test that starts the listener late). Happy to adapt it to this PR, or to leave it as a reference.
