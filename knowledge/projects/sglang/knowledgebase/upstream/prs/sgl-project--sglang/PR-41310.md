# [Fix] diffusion: Tolerate parent exit during process cleanup

[Upstream PR](https://github.com/sgl-project/sglang/pull/41310) · state: open · merged: False

## Original PR description

## Motivation

`kill_process_tree` in the multimodal runtime catches `psutil.NoSuchProcess` when constructing the parent handle, but the parent can exit before `children(recursive=True)`. Return when it disappears during enumeration so teardown does not raise this race. The SRT helper is a separate owner and already guards the same lookup-to-enumeration race.

## Modifications

- Catch the parent disappearing during child enumeration.
- Retain the focused regression in the current process test file, sharing the upstream `unittest.mock` imports.
- Merge main `834bfe4ef0` to resolve the test import conflict. Keep all upstream process reaping and GC-deferral behavior/tests.

## Accuracy Tests

Current merged head: the complete standalone `python/sglang/multimodal_gen/test/unit/test_process.py` passes all nine tests on Linux/Python 3.12.3 with psutil 7.1.3, including real process-tree cleanup, skipped-PID preservation, fork/GC restoration and the parent-exit race. No skips. Replacing only the production module with pinned main makes the parent-exit regression fail with `psutil.NoSuchProcess`; candidate bytes were restored and verified.

```bash
python python/sglang/multimodal_gen/test/unit/test_process.py -v

Windows hooks use a task-local `python3` launcher pointing to native Python; process/fork tests run on the authorized Linux host. This is standalone unittest evidence; full multimodal pytest/conftest and accelerator suites were not run. No model output changes.
