# [Fix] hicache: preserve NVFP4 payload and scales across host transfers

[Upstream PR](https://github.com/sgl-project/sglang/pull/46452) · state: open · merged: False

## Original PR description

## Motivation

NVFP4 host-cache transfers must preserve packed K/V bytes together with their persistent scale buffers. Generic token-scale MHA descriptors and logical-head-width staging do not represent this layout correctly. This is the independent transport companion to the workspace fix in [#43356](https://github.com/sgl-project/sglang/pull/43356).

## Modifications

- Add an explicit NVFP4 buffer descriptor and host-pool dispatch, using byte-width geometry for packed payload transfers.
- Back up and restore page-granular scale buffers with target/draft layer order preserved, and include persistent scales in host allocation accounting.
- Support aligned whole-page L2 transfers with the `kernel` backend and `page_first` layout. Reject invalid descriptors, partial transfers, native-only scale layouts and unsupported relocation/L3 layouts. Token indices retain canonical order within each page.

Descriptors also carry optional native-layout scales when present; this branch has CPU coverage. Native-only configurations remain explicitly unsupported.

## Accuracy Tests

Independent validation of this **6-file patch**, based on `a99c7d050fae`:

- **26 registered CPU tests passed** for descriptors, allocation, transfer selection and rejection checks.
- **96 GPU byte comparisons passed** for page sizes 16/32/64 with permuted source, host and reload pages.
- **32 additional comparisons passed** for a 65-page transfer crossing the 64-page staging capacity.

The GPU cases use two target and two draft layers on RTX 5090/SM120, comparing packed K/V plus token-linear K/V scales. Native scale buffers are disabled/rejected in these GPU cases. They establish byte preservation; native-scale GPU transport, SM100 and RTX PRO 6000 were not validated.

```bash
python -m pytest -q \
  test/registered/unit/mem_cache/test_nvfp4_host_buffer_info.py \
  test/registered/unit/mem_cache/test_nvfp4_mha_pool_host_unit.py
```

The **combined workspace + HiCache candidate**, using Qwen3.8-27B ModelOpt NVFP4 on TP2 RTX 5090, additionally passed **8 L2 Graph/eager request pairs**. Its finite 24-item quality comparison scored **19/24 for both NVFP4 and FP8 with zero new errors**. These combined results are separate from this patch's standalone transport tests and do not establish standalone end-to-end quality or the full reasoning/tool/vision/needle suite.

## Speed Tests and Profiling

No standalone host-transfer throughput claim is made. The complete five-point ABBA and memory/capacity measurements are reported in the [companion core PR](https://github.com/sgl-project/sglang/pull/43356), with HiCache enabled for both paths.

For that **combined candidate**, NVFP4/FP8 paired request-throughput ratios were 1.0573/1.0110/0.8809/0.9012/0.8832 for shared 25K C1/C4/C16, shared 50K C4 and unique 25K C4 respectively. At an equal 196608-token pool, ready-state known KV/scales/workspace storage was 31.99% lower and PyTorch allocated memory 4.97% lower per rank. Separately measured automatic token-pool capacity was 782,592 vs 565,568 (+38.37%). These service and capacity results are not attributed to the HiCache transport patch alone; the core's launch optimization does not change this patch.
