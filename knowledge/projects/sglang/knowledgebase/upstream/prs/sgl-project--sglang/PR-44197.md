# [Fix] [AMD] mamba: Import the causal conv1d kernels for Mamba2 layers on ROCm

[Upstream PR](https://github.com/sgl-project/sglang/pull/44197) · state: open · merged: False

## Original PR description

## Motivation

Mamba2 hybrid models (Granite 4.0-H, Falcon-H1, Nemotron-H) do not start on ROCm. `mamba.py` binds `causal_conv1d_fn`, `causal_conv1d_update` and their Triton variants only in its CUDA, NPU and XPU branches, so on ROCm none of them is defined. The server fails while capturing the decode CUDA graphs:

```
NameError: name 'causal_conv1d_update_triton' is not defined
```

(`causal_conv1d_update` for Falcon-H1). `mamba1.py` imports those names from `mamba.py`, so it cannot be imported on ROCm either ("Ignore import error when loading sglang.srt.models.mamba").

`causal_conv1d.py` already handles ROCm: the compiled kernel is CUDA-only, and it falls back to the Triton kernels there.

## Modifications

- `mamba.py`: take the CUDA import branch on ROCm too (`is_cuda_alike()`).
- No change on CUDA, NPU, XPU or CPU.

## Accuracy Tests

MI350X, `rocm/sgl-dev:v0.5.21-rocm724-mi35x-20261012` with this change applied, `--attention-backend triton`.

| Model | before | after |
| --- | --- | --- |
| `tiiuae/Falcon-H1-7B-Instruct` | NameError at startup | serves; GSM8K (all 1,319 questions, temperature 0, `sgl-eval` 0.1.2): 85.82% |
| `ibm-granite/granite-4.0-h-tiny` | NameError at startup | starts and serves with `--enable-deterministic-inference`; in normal mode it then stops at a separate MoE `torch.compile` error (`moe_sum_reduce_torch_compile`), not addressed here |
| `nvidia/NVIDIA-Nemotron-Nano-9B-v2` | NameError at startup | needs ReLU2 on ROCm as well (#44198) |

## Speed Tests and Profiling

No performance change on other platforms; on ROCm these models did not run before.
