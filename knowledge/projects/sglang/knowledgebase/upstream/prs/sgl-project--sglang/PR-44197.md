# [Fix] [AMD] mamba: Import the causal conv1d kernels for Mamba2 layers on ROCm

[Upstream PR](https://github.com/sgl-project/sglang/pull/44197) · state: closed · merged: True

## Original PR description

## Motivation

Mamba2 hybrid models (Granite 4.0-H, Falcon-H1, Nemotron-H) do not start on ROCm. `mamba.py` binds `causal_conv1d_fn`, `causal_conv1d_update` and their Triton variants only in its CUDA, NPU and XPU branches, so on ROCm none of them is defined. The server fails while capturing the decode CUDA graphs:

```
NameError: name 'causal_conv1d_update_triton' is not defined
```

(`causal_conv1d_update` for Falcon-H1). `mamba1.py` imports those names from `mamba.py`, so it cannot be imported on ROCm either ("Ignore import error when loading sglang.srt.models.mamba").

`causal_conv1d.py` already handles ROCm: the compiled kernel is CUDA-only, and it falls back to the Triton kernels there.

## Modifications

- `mamba.py`: take the CUDA import branch on ROCm too (`is_cuda() or is_hip()`).
- No change on CUDA, NPU, XPU or CPU.

## Accuracy Tests

MI350X, `rocm/sgl-dev:v0.5.22-rocm724-mi35x-20261019` (upstream/main of 2026-10-19) with this change applied, `--attention-backend triton`, `SGLANG_USE_AITER=0`. GSM8K: all 1,319 questions, temperature 0, `sgl-eval` 0.1.2.

| Model | before | after |
| --- | --- | --- |
| `tiiuae/Falcon-H1-7B-Instruct` | `NameError: name 'causal_conv1d_update' is not defined` at startup | serves; GSM8K 85.37% (85.82% on the 2026-10-12 nightly); with `--enable-deterministic-inference` 86.05% |
| `ibm-granite/granite-4.0-h-tiny` | `NameError` at startup | serves; GSM8K 86.20%; with `--enable-deterministic-inference` 86.73% |
| `nvidia/NVIDIA-Nemotron-Nano-9B-v2` | fails at startup | needs ReLU2 on ROCm as well, added by #44198 (merged); with both, starts; with `--enable-deterministic-inference` GSM8K 75.28% (26% of answers hit the 2,048-token limit) |

Not addressed here, for reviewers trying other settings on ROCm:
- With AITER enabled (`SGLANG_USE_AITER=1`, the ROCm image default), Falcon-H1 serves but its output is wrong (GSM8K 0.5%, on the 2026-10-13 to 2026-10-19 nightlies alike) and a 50-sequence prefill batch hit a GPU memory fault. Granite 4.0-H is fine with AITER (GSM8K 86.35% with Triton attention, 72.25% with the default AITER attention).
- `--enable-deterministic-inference` without `--attention-backend` selects FA3, which the ROCm image does not ship; with `--attention-backend triton` these models start.

## Speed Tests and Profiling

No performance change on other platforms; on ROCm these models did not run before.
