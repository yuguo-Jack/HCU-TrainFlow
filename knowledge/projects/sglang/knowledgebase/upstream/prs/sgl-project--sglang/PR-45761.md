# [CI] multimodal_gen: Target thirty-minute CI shards

[Upstream PR](https://github.com/sgl-project/sglang/pull/45761) · state: closed · merged: True

## Original PR description

## Motivation

Multimodal-gen H100 jobs finish substantially below the intended 30-minute shard target. The six two-GPU shards in [run 39719746385](https://github.com/sgl-project/sglang/actions/runs/39719746385) took roughly 15–22 minutes. Always rounding the shard count up favors shorter jobs, while stale full-test runtime estimates create additional shards.

## Modifications

- Select the shard count whose estimated average is closest to 30 minutes, retaining the existing 20–40-minute window and maximum of ten shards.
- Refresh scheduling-only H100 case and standalone estimates using full-process durations from [run 39719746385](https://github.com/sgl-project/sglang/actions/runs/39719746385) and [main run 39590001492](https://github.com/sgl-project/sglang/actions/runs/39590001492). Use medians rounded up to ten seconds where both runs provide successful observations.
- With the current test inventory, reduce H100 single-GPU shards from six to five and two-GPU shards from six to three. Keep every case and standalone file scheduled exactly once.
- Add a regression test for the observed 154-minute suite selecting five approximately 31-minute shards instead of six approximately 26-minute shards.

Only scheduling estimates change in the baseline JSON; inference, consistency, memory, and performance validation thresholds remain unchanged.

## Validation

CI on this branch is pending. The existing runs supply calibration data; their results are not a measurement of the new partition layout. No GPU jobs were rerun for calibration.
