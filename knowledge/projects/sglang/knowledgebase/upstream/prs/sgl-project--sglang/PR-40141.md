# [Feat] [NPU] startup-weight-load: Support overlap mode on NPU

[Upstream PR](https://github.com/sgl-project/sglang/pull/40141) · state: open · merged: False

## Original PR description

## Motivation

`--startup-weight-load-mode=overlap` overlaps checkpoint prefetch with decode CUDA-graph capture to shorten model startup, but it was gated as CUDA-only: the options resolved `is_cuda_platform` and `device == "cuda"`, so NPU was rejected. This enables the overlap path on NPU, where the decode graph is still captured and the prefill graph (`TC_PIECEWISE` by default) is disabled — `tc_piecewise` prefill bakes weights during `torch.compile` and is unsafe for commit-after-capture.

## Modifications

- Add `is_npu` to `StartupWeightLoadOptions` and populate it from `current_platform.is_npu()`.
- Relax the overlap startup validation rule from CUDA-only to CUDA-or-NPU (`is_cuda_platform or is_npu`; `device in ("cuda", "npu")`), updating the message to `"CUDA or NPU only"`.
- Replace the hard-coded `torch.cuda.synchronize()` with the device-agnostic `current_platform.synchronize()`.
- CUDA behavior is unchanged.

## Accuracy Tests

Validated on NPU by the e2e case `test_npu_startup_weight_load_mode.py` (companion test branch): launching Llama-3.2-1B in overlap mode with prefill graph disabled, and asserting the generated text contains "Paris". This proves the sentinel weights baked during capture are replaced by real weights after commit — a baked-sentinel graph would output gibberish.

## Speed Tests and Profiling

N/A. This change enables the overlap startup path on NPU (reduces startup latency); it does not affect per-token throughput, and the CUDA path is untouched.
