# [Fix] minimax-m3: Stream null and empty tool arguments as non-streaming parses them

[Upstream PR](https://github.com/sgl-project/sglang/pull/44132) · state: open · merged: False

## Original PR description

## Motivation

With `--tool-call-parser minimax-m3`, a streamed tool call can carry different arguments from the same output parsed without streaming.

- A string parameter that also allows null, such as `{"type": ["string", "null"]}` (the form OpenAI strict mode uses for optional fields), written by the model as `null` or left empty, is parsed as JSON `null` by `detect_and_parse` (`test_nullable_param_null_becomes_none` pins this). Streaming sends the string `"null"` or `""` instead.
- An empty scalar value whose closing tag arrives in the same chunk as its opening tag streams as `{}`. Chunks hold several tokens with `--stream-interval` above 1 or with speculative decoding. The streaming parser reads the closing tag as the start of a nested child.

So a client that sets `stream=true` gets a different type than one that does not.

## Modifications

All changes are in `MinimaxM3Detector`'s streaming path. `detect_and_parse` is unchanged.

- If a string parameter allows null, its text is held back while it can still become `null`, `Null` or `NULL` (at most four characters). Any other value starts streaming as soon as it stops matching, so long values still stream token by token. If the closing tag arrives first, the held text goes through `_convert_leaf_value`, the same function the non-streaming parse uses.
- The parameter's own closing tag right after its opening tag means an empty scalar value, not a nested child. This is the rule `_parse_parameter` already applies. Any other tag there keeps the existing path, so a mismatched closing tag in the same chunk is rejected as on `main`. If a chunk ends partway through the next tag marker, the parser waits for one more chunk before it decides.

## Accuracy Tests

The decoded model text below went through the real `OpenAIServingChat` (`_generate_chat_stream` and `_handle_non_streaming_request`) with `tool_call_parser="minimax-m3"`. There was no model inference.

```
schema: name {"type": "string"}, nickname {"type": ["string", "null"]}, note {"type": "string"}
model output: <name>Ada</name><nickname>null</nickname><note></note>   (MiniMax-M3 tags)

stream=false                   {"name": "Ada", "nickname": null,   "note": ""}
stream=true, before, per tag   {"name": "Ada", "nickname": "null", "note": ""}
stream=true, before, 1 chunk   {"name": "Ada", "nickname": "null", "note": {}}
stream=true, after, any split  {"name": "Ada", "nickname": null,   "note": ""}
```

Over five `nickname` values (`null`, `NULL`, empty, `Lovelace`, `nullable`), the run tried per-tag chunks, one chunk, one character per chunk, and the full text split at every position. Each chunking ran in both incremental and cumulative output modes. Streamed arguments differed from the non-streamed ones in 2424 of 2488 runs before this change and in 0 after it.

New tests in `test/registered/unit/function_call/test_minimax_m3_detector.py`:
- `test_nullable_param_null_becomes_none_streaming`
- `test_nullable_param_agrees_at_every_split_point`
- `test_empty_value_in_one_chunk_matches_non_streaming`
- `test_nullable_param_text_streams_before_closing_tag`
- `test_mismatched_closing_tag_after_opening_tag_in_one_chunk`

The first three fail on `main` (324 failing subtests) and pass with this change. The fourth checks that non-null values still stream before the closing tag. The fifth checks that a wrong closing tag right after an opening tag is not streamed as the value. `test/registered/unit/function_call` and `test/registered/function_call` pass: 707 tests.

When a model emits a malformed sequence such as `<note></wrong></note>` in one buffered chunk, this predicate treats `</wrong>` as an empty scalar close because it checks only the generic closing-tag prefix. The scalar path then serializes the mismatched tag into `note` and forwards a valid-looking tool call, whereas `detect_and_parse` rejects the mismatched tags and returns no call; compare against `_parameter_end_token(tag)` before selecting scalar mode so malformed output is not forwarded.
