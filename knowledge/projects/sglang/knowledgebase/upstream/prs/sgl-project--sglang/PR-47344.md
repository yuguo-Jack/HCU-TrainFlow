# [Refactor] multimodal: Let token-space strategies declare media decoding and the video device

[Upstream PR](https://github.com/sgl-project/sglang/pull/47344) · state: open · merged: False

## Original PR description

## Motivation

- The video preprocessing device can change decoded and preprocessed pixels, but only the serving wrapper resolved it, so a trainer using the same strategy decoded videos differently from rollout.
- A strategy could not declare CPU image decoding, although nvJPEG and PIL decode JPEGs to different pixels; several legacy processors already set `gpu_image_decode = False`.
- Item hashes scoped feature bytes only by declared layout fields, so a feature laid out by its own shape (e.g. `[3, H, W]` pixels with no grid field) hashed equal for transposed solid images.
- Serving flattened `mm_spans` per modality and relied on the legacy split to regroup offsets by grid fields, so a strategy without grid fields could not get per-media offsets.

## Modifications

- `TokenSpaceProcessStrategy.video_preprocessing_device`: the core resolves `mm_process_config["video_preprocessing_device"]` over it and moves every medium of a video request there; the serving spec field is removed. The user-facing key is unchanged.
- `TokenSpaceProcessStrategy.gpu_image_decode`, set on the core class the media loader reads.
- `_layout_digest` scopes item hashes by the feature shape as well as the declared layout fields.
- After `split_mm_items`, the wrapper sets each media item's offsets from its own `mm_spans` row; a modality the split leaves bundled keeps all its media's offsets.

Qwen output is unchanged except its item hashes, which are not compared with legacy.

## Tests

`test_processor_device_selection.py` (core resolves the video device), `test_mm_token_expansion.py` (shape-scoped hashes, legacy defaults read from the strategy), `test_processor_async_call_sites.py`, `test_qwen_tokenized_media.py`.
