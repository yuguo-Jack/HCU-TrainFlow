# [NPU] HiSparse: support DeepSeek V4 sparse KV offload on Ascend

[Upstream PR](https://github.com/sgl-project/sglang/pull/47635) · state: open · merged: False

## Original PR description

## Motivation

DeepSeek V4 HiSparse (sparse KV staged in host memory) already exists for CUDA, but the code assumes the CUDA platform in several places, so it cannot start on Ascend NPU at all:

```
AssertionError: enable_hisparse is not supported on the NPU DSV4 KV pool
```

and, once that assertion is relaxed, the first request that grows past the sparse staging window dies with

```
NameError: name 'transfer_kv_all_layer_mla' is not defined
```

Short prompts hid the second failure because they take the per-token branch; only the whole-page C4 branch reaches the CUDA-only symbol.

## Changes

| File | Change |
|---|---|
| `managers/hisparse_coordinator.py` | Select `io_backend` per platform: NPU exposes `transfer_kv_dim_exchange` from `sgl_kernel_npu.kvcacheio` and is served by the `kernel_ascend` backend, so the 5 hardcoded `io_backend="kernel"` sites now use `_HISPARSE_IO_BACKEND`. Also build the LRU init table as int32 then cast to int16, because `aclnnArange` has no int16 output on NPU (error 107000). |
| `mem_cache/memory_pool_host.py` | `transfer_cache_dsv4_mla` has no NPU counterpart. The NPU C4 pool uses the PA_ND layout, where one token is one contiguous row, so a torch gather/scatter (`_npu_transfer_dsv4_tokens`) is exact and needs no kernel. |
| `hardware_backend/npu/dsv4/dsv4_memory_pool.py` | Add `NPUHiSparseC4DevicePool`, the NPU counterpart of the CUDA `HiSparseC4DevicePool` (compress_ratio / data_ptrs / full -> compressed -> hisparse-device loc translation), and let it through the pool factory instead of rejecting it. |
| `mem_cache/allocator/hisparse.py` | Accept any pool implementing the C4 interface rather than only the CUDA class; use the native NPU paged allocator (the in-tree triton `alloc_extend_kernel` overflows the Ascend UB at compile time: requires 1902592 bits, available 1572864); forward `req_pool_indices`; unwrap and re-return the `DSV4OutCacheLoc` bundle; release by request. |
| `hardware_backend/npu/sparsity_driven_kv_offload/manager.py` | `req.req_pool_idx` moved to `req.kv.req_pool_idx`. |

## Verification

8x Ascend 910B3 (A2), single node, `DeepSeek-V4-Flash-w8a8` (43 layers), `--tp-size 8 --page-size 128 --kv-cache-dtype bfloat16 --attention-backend ascend --enable-hisparse --disable-radix-cache`, cuda graph disabled, `--mem-fraction-static 0.75`.

**Starts and offloads:**

```
HiSparse c4 host-to-device ratio = 2
Allocating 5.47 GB host memory for V4 paged pool 'dsv4_hisparse_c4'
  (layers=21, pages=7949, item_bytes=32768, layout=layer_first)   # all 8 ranks
```

**Accuracy (GSM8K, 200 questions, 5-shot, greedy, same code, same prompts):**

| HiSparse | Correct | Accuracy |
|---|---|---|
| off | 192/200 | 96.0% |
| **on** | **194/200** | **97.0%** |

Both runs finished with 0 unparseable answers and 0 tracebacks, and the server was still healthy (`/health` 200) afterwards. No accuracy regression.

## Notes for reviewers / users

* `--disable-radix-cache` is required (already enforced by `validate_hisparse`).
* Raise `--watchdog-timeout` (e.g. 9000) and keep client concurrency modest (8 was stable here); at 32 concurrent long prompts the scheduler watchdog can fire during the host staging backpressure.
* `NPUHiSparseC4DevicePool.get_cpu_copy` / `load_cpu_copy` raise `NotImplementedError`, matching what the NPU C4 pool can support today.

This is a draft: happy to split it per-file or drop the `req.kv.req_pool_idx` fix if it should land separately.
