# [Feat] disaggregation: Support Qwen3.8-Flash-Next CPU-buffer PD

[Upstream PR](https://github.com/sgl-project/sglang/pull/46554) · state: open · merged: False

## Original PR description

## Motivation

This PR extends the NIXL CPU-buffer transport in [#45779](https://github.com/sgl-project/sglang/pull/45779) to support Qwen3.8-Flash-Next prefill–decode (PD) disaggregation in Confidential Computing (CC) deployments. This branch includes those prerequisite changes on top of `e1c4b273af`.

Qwen3.8-Flash-Next needs more than attention KV and Gated DeltaNet (GDN) state at the prefill–decode boundary. Its QSA path also maintains pending keys, RoPE state, and compressed index-key pages. The parent PR rejects these additional state components. Decode retraction must preserve them as well, or a resumed request loses the state required for sparse attention.

Tracking issue: #46588

## Modifications

- Transfer QSA pending/RoPE state and compressed index-key pages alongside KV and GDN state. Validate component layouts and carry their types in the versioned CPU-buffer bootstrap extension. Both peers must run the new protocol.
- Preserve QSA state when a decode request saves its state to CPU during retraction. Compute checksums using each component's own indices and wait for outstanding decode work before restoring a reused state slot.
- Keep PLE embeddings on GPU in CPU-buffer mode and reject explicit embedding offload.
- Fix FlashInfer GDN decode indexing for CUDA graph padding: map the `-1` padding sentinel to the reserved dummy slot instead of the last live state slot. A regression test reproduces the overwrite and verifies that padded rows leave live state unchanged.

MTP/speculative decoding, PP/CP, and PLE embedding offload remain unsupported by this CPU-buffer path. The validated model configuration is FP8 TP2/EP2; BF16 and TP4 are not covered by these results.

## Accuracy Tests

Tests use `Qwen/Qwen3.8-Flash-Next-FP8` from ModelScope, revision `47b13b2ed4`, on two H20 hosts running as TDX guests. Unified uses two GPUs; cross-node PD uses two GPUs per role, four in total. Both use TP2/EP2, FlashInfer GDN prefill/decode, BF16 recurrent state, chunked prefill 2,048, and context length 32,768. CUDA graphs and overlap scheduling are enabled. Radix caching is enabled for unified/prefill and disabled for PD decode. MTP is disabled. PD uses NIXL/UCX TCP with a 4 GiB CPU pool per worker and KV/state checksum verification.

GSM8K follows the [upstream Qwen3.8 PD test recipe](https://github.com/sgl-project/sglang/blob/d0a75654368a470d8484e3ea45b06e500fee57af/test/registered/e2e/disaggregation/test_qwen4_exp_pd_prefill_cp.py): `run_sgl_eval`, 200 questions, 32 client threads, thinking enabled, and a 16,384-token output limit. The effective evaluator settings are temperature 0 and top_p 0.95. Both deployments are evaluated against the 94% threshold from that test. The upstream test uses NVIDIA NVFP4; the results below use the FP8 checkpoint for both unified and PD.

| Test | Unified | Cross-node PD |
| --- | --- | --- |
| GSM8K, same 200 questions | 193/200 (96.5%) | 193/200 (96.5%) |
| Responses at output limit | 0 | 1 |
| Long-context needle retrieval, approximately 20k tokens | 3/3 | 3/3 |

The PD response that reached the output limit is counted as incorrect. Both deployments scored 96.5%, though they did not answer exactly the same questions correctly. Needle retrieval was tested at depths of 10%, 50%, and 90% of the prompt.

The PD evaluation recorded no request retries or KV/state checksum mismatches. A cross-node request cancellation was followed by four successful requests and empty request queues. The GSM8K and serving measurements were collected at `3b5db0e3ac`, before the rebase.

The 144-test regression run includes CPU-buffer lifecycle/layout checks, QSA retraction and checksum tests, the GDN padding regression, and real NIXL/UCX transfers with CUDA tensors. Six additional offline tests cover evaluator acceptance (score threshold, request errors, and length-limited responses) and the fault-injection tool itself.

Cross-node fault injection uses the same FP8 TP2/EP2 deployment with checksums enabled. Requests go directly to both workers so router retries cannot mask failures.

| Injected failure | Recovery requests | Resource checks |
| --- | --- | --- |
| Decode receive-buffer allocation | 4/4 passed | Both peers released their pool allocations |
| Prefill send-buffer allocation | 4/4 passed | Both peers released their pool allocations |
| Exception after a real NIXL write submission | 4/4 passed | Send buffers retained until submitted transfers drained |

In each case, both workers returned HTTP 500 for the affected request, then completed four subsequent requests without a restart. All four TP-rank pools returned to zero allocated bytes and pending handles, and both request queues became empty. For the post-submission failure, the trace also confirmed that the sender still owned the buffers when the exception occurred. The fault-injection tool and instructions are in `test/manual/disaggregation/cpu_buffer_fault_injection/`.

After starting the servers, run the evaluator once against the unified endpoint and once against the PD router, using separate output directories:

```bash
python test/manual/disaggregation/eval_qwen38_cpu_buffer_pd.py \
  --url "$ENDPOINT_URL" \
  --model "$MODEL_PATH" \
  --output-dir "$RESULT_DIR"
```

## Speed Tests and Profiling

Performance sanity checks use upstream `sglang.bench_serving` with `random-ids`, a nominal 1,024-token input target, 128 output tokens, range ratio 1, seed 42, and unlimited request rate. Each configuration runs serially once, with 16 warmup requests followed by 80 measured requests. `--flush-cache` clears both PD workers after warmup. The sampler uses its default text mode, so server-side retokenization can change the input length. The benchmark ignores EOS by default.

| Deployment | Total H20 GPUs | Client concurrency | Output tokens/s | Median TTFT (ms) | Median TPOT (ms) |
| --- | --- | --- | --- | --- | --- |
| Unified TP2/EP2 | 2 | 1 | 94.96 | 118.82 | 9.64 |
| Unified TP2/EP2 | 2 | 8 | 227.02 | 3584.71 | 10.87 |
| Cross-node PD, TP2/EP2 per role | 4 | 1 | 87.85 | 235.54 | 9.59 |
| Cross-node PD, TP2/EP2 per role | 4 | 8 | 422.04 | 366.46 | 15.54 |

All 320 measured requests succeeded and generated 128 tokens each. Reviewed serving logs contain no transfer or CUDA errors. Each row is a single measurement on shared hosts, so the results do not establish run-to-run variance.

CUDA graphs and overlap scheduling remain enabled. Radix caching is enabled for unified/prefill and disabled for PD decode; MTP and checksum verification are disabled for timing. The effective running-request limits are 3 for unified/prefill and 8 for PD decode, despite the common requested limit of 8. At client concurrency 8, unified can run only three requests at a time; the rest must wait. PD has four GPUs and can run eight decode requests at a time. These differences prevent attributing the throughput and TTFT gap to CPU-buffer transport alone. The runtime skips unsupported FlashInfer all-reduce fusion in CC mode and uses the default MoE tuning configuration.

PD uses `UCX_TLS=tcp,cuda_copy,self`, `UCX_ACC_DEVICES=''`, and `SGLANG_DISAGGREGATION_NIXL_BACKEND=UCX`, with a 4 GiB CPU pool per worker. Requests go through the mini_lb router, which coordinates prefill and decode. Performance and accuracy tests use the same runtime code. Fault injection is disabled for performance tests.

```bash
python -m sglang.bench_serving \
  --backend sglang --base-url "$ENDPOINT_URL" --model "$MODEL_PATH" \
  --dataset-name random-ids --random-input-len 1024 --random-output-len 128 \
  --random-range-ratio 1 --seed 42 --num-prompts 80 --warmup-requests 16 \
  --flush-cache --max-concurrency "$CONCURRENCY" --output-file "$RESULT_FILE"
```
