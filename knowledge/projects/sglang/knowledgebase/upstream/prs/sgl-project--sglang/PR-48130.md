# [Fix] fp8_utils: Import DeepGEMM lazily in transform_scale_ue8m0

[Upstream PR](https://github.com/sgl-project/sglang/pull/48130) · state: open · merged: False

## Original PR description

## Motivation

`transform_scale_ue8m0` runs `import deep_gemm.utils.layout` on its first line, even when called with `use_torch_impl=True`. The torch impl (`_get_mn_major_tma_aligned_packed_ue8m0_tensor_torch_impl`) also imports `align` and `get_tma_aligned_size` from `deep_gemm.utils`.

`inverse_transform_scale_ue8m0` always calls the torch impl, so it raises `ModuleNotFoundError: No module named 'deep_gemm'` on any platform without DeepGEMM, even though it needs no DeepGEMM kernel. It is called from `dequantization.py`, `weight_checker_comparator.py`, `model_runner.py` and the DeepSeek weight loader.

For the same reason, `TestInverseTransformScaleUe8m0::test_round_trip` cannot run outside CUDA: it hard-codes `device="cuda"` and needs DeepGEMM.

## Modifications

- `fp8_utils.py`
  - `transform_scale_ue8m0`: import `deep_gemm` only when `use_torch_impl=False`.
  - Torch impl: use sglang's existing `get_tma_aligned_size` (`sglang/kernels/ops/moe/ep_moe_kernels.py`, a copy of the DeepGEMM helper) and `ceil_div(k, 4) * 4` in place of `deep_gemm.utils.align`.
  - The DeepGEMM path is unchanged.
- `test_fp8_utils.py` (`TestInverseTransformScaleUe8m0::test_round_trip`)
  - Use `get_device()` instead of `device="cuda"`.
  - Pass `use_torch_impl=not _is_cuda`, so CUDA still tests the DeepGEMM kernel and other devices test the torch impl.

## Accuracy Tests

No change to model outputs: the DeepGEMM path is untouched, and the torch impl computes the same values without DeepGEMM.

Unit tests on Intel Arc Pro B60 (XPU), torch 2.14.0+xpu:

- `test_fp8_utils.py::TestInverseTransformScaleUe8m0::test_round_trip`: passed. Before this change it failed with `Torch not compiled with CUDA enabled`, then `No module named 'deep_gemm'`.
- Full `test_fp8_utils.py`: 3 passed, 5 skipped (CUDA/SM100-only, unchanged).

The CUDA DeepGEMM path relies on existing CI.
