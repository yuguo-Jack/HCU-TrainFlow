# [Feat] HttpServerEngineAdapter: forward memory-release tags and expose pause/continue_generation

[Upstream PR](https://github.com/sgl-project/sglang/pull/47818) · state: open · merged: False

## Original PR description

## Motivation


`Engine.release_memory_occupation` / `resume_memory_occupation` take `tags: Optional[List[str]]`, and the HTTP routes
(`/release_memory_occupation`, `/resume_memory_occupation`, `ReleaseMemoryOccupationReqInput.tags`) accept them. The
`EngineBase` abstract methods and `HttpServerEngineAdapter` do not: their signatures are `(self)`, so a caller that
holds an adapter cannot do the staged release/resume that colocated RL needs (for example free `kv_cache` first,
then `weights`, and resume in the reverse order). `adapter.release_memory_occupation(tags=["kv_cache"])` raises
`TypeError`.

The adapter also has no wrapper for `/pause_generation` and `/continue_generation`, although it already wraps the other
RL control routes (`begin_weight_update`, `end_weight_update`, `update_weights_from_tensor`, `flush_cache`). Those two
calls are server-only by design (see the `PauseGenerationReqInput` docstring), so they are added to the adapter only,
not to `Engine` or `EngineBase`.

I checked open and closed PRs/issues for `HttpServerEngineAdapter`, `EngineBase`, `http_server_engine` and
`ReleaseMemoryOccupationReqInput tags`; none covers this. #40720 (open) also edits `http_server_engine.py`, in
`update_weights_from_tensor` only, so the hunks do not overlap.

## Modifications


- `EngineBase.release_memory_occupation` / `resume_memory_occupation`: add `tags: Optional[List[str]] = None`
  (matches `Engine`).
- `HttpServerEngineAdapter`:
  - `release_memory_occupation(tags=None)` / `resume_memory_occupation(tags=None)` send `{"tags": tags}`.
    `tags=None` keeps the old meaning (everything).
  - New `pause_generation(mode="abort")` and `continue_generation(torch_empty_cache=True)`, thin wrappers over the
    existing routes.
- New CPU unit test `test/registered/unit/entrypoints/test_http_server_engine_adapter.py` (mocks `requests.post`;
  checks endpoint and payload, the default, and that the `release/resume` signatures of `EngineBase` and the adapter
  equal `Engine`'s).

About 25 lines of source and 70 lines of test, no behavior change for existing callers.

## Accuracy Tests


Environment: RTX 4090 24 GB, `lmsysorg/sglang:latest` (0.5.22, commit baa9bef), Qwen3-0.6B,
`enable_memory_saver=True`, `enable_weights_cpu_backup=True`. The patch was applied to a copy of the image's
files and bind-mounted read-only over the originals; the image itself is untouched. The patch applies cleanly to
the 0.5.22 files and was written against `main` as of 2026-11-02. GPU was idle before and after the run (0% util,
15 MiB).

Before the patch (same image): `inspect.signature(HttpServerEngineAdapter.release_memory_occupation)` is `(self)`,
and `hasattr(HttpServerEngineAdapter, "pause_generation")` is `False`.

1. Unit test: `pytest test/registered/unit/entrypoints/test_http_server_engine_adapter.py` -> 4 passed.
2. End-to-end against a real server launched by the adapter (GPU memory from `nvidia-smi`, MiB):

   | step | used |
   |---|---|
   | server up | 13922 |
   | `release_memory_occupation(tags=["kv_cache"])` | 2960 |
   | then `tags=["weights"]` | 1770 |
   | `resume_memory_occupation(tags=["weights"])` | 2984 |
   | then `tags=["kv_cache"]` | 13946 |

   Greedy output after the staged cycle equals the output before it. An untagged `release_memory_occupation()` /
   `resume_memory_occupation()` cycle still releases everything (1770 MiB) and the output is again identical.
3. `pause_generation(mode="in_place")` during a 1500-token generation: the request does not finish within 3 s
   while paused, and after `continue_generation()` it completes with `finish_reason=length`, 1500 tokens.
   `pause_generation(mode="abort")` ends the running request with `finish_reason=abort`.

Not tested: multi-GPU/TP > 1, `--api-key` setups (the adapter's `_make_request` sends no auth header; unchanged here),
other hardware backends.
