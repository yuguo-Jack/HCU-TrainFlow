# [CLI] Route sglang serve dLLM launches to the LLM runtime

[Upstream PR](https://github.com/sgl-project/sglang/pull/40942) · state: open · merged: False

## Original PR description

## Motivation

The DiffusionGemma cookbook command `sglang serve --model-path google/diffusiongemma-26B-A4B-it --dllm-algorithm Gemma4Renoise --trust-remote-code --host 0.0.0.0 --port 30000` exits at startup with `error: unrecognized arguments: --dllm-algorithm Gemma4Renoise`. The checkpoint ships a diffusers `model_index.json` next to its SRT `config.json`, so auto-detection sends it to the diffusion backend, which has no dLLM options.

## Changes

- Make the diffusion detector decline requests that pass `--dllm-algorithm`, a flag only the language model runtime accepts, so auto-detection falls back to it.

## Validation

- On unchanged main, the cookbook command exits with the error above. With the checkpoint path, host, and port changed to local values and `--max-running-requests 8` added, the cookbook command now selects the language model runtime and answers chat and chat-templated generate requests on one H200. Together with the decode graph OOM fix, the same command without `--max-running-requests` also starts and answers them.
- Routing is unchanged for launches without the flag, including a Cosmos3 diffusers checkpoint, and for explicit `--model-type` overrides. The `--dllm-algorithm=...` and positional model path forms also route to the language model runtime.
- `test/registered/unit/cli` passes with the same 12 tests as main. Pre-commit passes.

## Limits

- Without the decode graph OOM fix, the cookbook command still needs `--max-running-requests` to start on one H200.
- A DiffusionGemma launch without `--dllm-algorithm` still routes to the diffusion backend.
- The new check reads only the command line, so a launch that passes the model path on the command line and sets `dllm-algorithm` only in an SRT `--config` file still routes to the diffusion backend as on main and needs `--dllm-algorithm` on the command line or `--model-type llm`.
