# [qwen 3.8 next] Fuse QSA prefill KV gathering and dtype conversion

[Upstream PR](https://github.com/sgl-project/sglang/pull/41933) · state: closed · merged: True

## Original PR description

## Motivation
QSA chunk prefill gathers each request's cached K and V separately, concatenates the results, and converts FP8 values inside attention. This adds small operations and host-side request-index materialization.

## Changes
- Gather K and V together with a Triton kernel using the request-to-token mapping.
- Convert to the query dtype during gathering, including FP8 KV to BF16.
- Preserve main's prefill length metadata, attention interface and attention arithmetic.

This PR is now standalone, directly based on main at `2a3655fea1`. It does not include or depend on #41932 or #41934. It retains the rectangular packing launch grid; highly uneven request lengths can launch masked work.

## Validation
The standalone revision passed the complete QSA test file on both H200 and GB300: **93 passed, 1 skipped**. Coverage includes BF16/FP8 packing, strided inputs, dtype conversion, packing-kernel graph replay with changed request IDs, and attention reference comparisons. Repository-configured Ruff checks and formatting passed. The two metadata/max-query graph tests from #41932 are intentionally not included; the attention interface remains identical to main.

This kernel validation is not an NVFP4 model serving benchmark. No new AIME26 result is claimed for this revision.

## Performance
One complete paired run on **4 GB300 GPUs**, comparing main `2a3655fea1` with this standalone commit `51c2680402`. A planned reverse-order repetition was interrupted by an infrastructure container termination and is excluded. These are single-run measurements, not a statistical confidence interval.

Configuration: `nvidia/Qwen3.8-Flash-Next-NVFP4`, revision `fc694b54fb0174e0913e6adf86691ef85a4ead47`, TP4, FP8 KV, BF16 Mamba state, FlashInfer linear attention, NEXTN with 3 steps/top-k 1/4 draft tokens. Random input/output 8192/1024, range ratio 1, seed 42, warmup 64, flush cache, chunked prefill 16384; 160 requests at C32 and 320 at C64. Both arms use simulated acceptance length 3.3 and identical communication defaults. Prefill graph and plan stream are disabled. Timings exclude profiler overhead.

- Qiaolin-Yu · comment · 2026-10-07T21:29:15Z · [source](https://github.com/sgl-project/sglang/pull/41933#discussion_r4212181788)

File: `python/sglang/srt/layers/attention/qsa/sparse_attn.py` · line None

I reproduced the regression on B200 and added conditional compact packing. We use it when batch_size * max_k > 2 * total_k and the rectangular grid has at least 4096 programs; smaller or more balanced batches retain the rectangular path.
For FP8 KV packing, median timings across three repetitions were:
- Uniform [8192] * 32: 72.04 → 72.03 µs.
- Moderately ragged [8192] + [3584] * 31: 40.52 → 36.60 µs.
- Extremely ragged [131072] + [128] * 127: 2193.80 → 46.04 µs, compared with 1807.47 µs for the original gather/cat path.

These are packing-only microbenchmarks, not end-to-end results. The minimum-grid condition avoids regressions observed for small workloads. Dispatch uses existing host-side metadata without additional device synchronization.
