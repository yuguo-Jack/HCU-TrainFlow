# [cake_kernels] SP all-gather matmul route: torch's default symmetric-memory backend, prepared launcher inside prefill CUDA-graph capture (stacked on #42532)

[Upstream PR](https://github.com/sgl-project/sglang/pull/42707) · state: closed · merged: False

## Original PR description

## Summary

Stacked on #42532 (which is stacked on #42416); only the last four commits (`01f7d5d1b`, `a99b140df`, `2b5a1ab97`, `f70c20423`) belong to this PR.

The opt-in `sp_all_gather_matmul` route (`SGLANG_CAKE_ROUTES=sp_all_gather_matmul` with `--enable-layernorm-sp`) currently forces torch's process-global `NVSHMEM` symmetric-memory backend, because FlashInfer's Cake all-gather matmul refused the default `CUDA` backend. Under `NVSHMEM` the engine's custom all-reduce v2 can only use its group-free allocation form (no multicast) and torch's fused symm-mem SP ops have to be disabled for the process, and the route was refused inside prefill CUDA-graph capture. With the matching FlashInfer change (Cake all-gather matmul served on the process-selected backend, `CUDA` or `NVSHMEM`, and a CUDA-graph-capturable prepared launcher), this PR makes the route:

- **run on torch's default symmetric-memory backend**: no `TORCH_SYMMMEM=NVSHMEM` in the route's process env and no `set_backend` on the first call. `communication.symmetric_memory_backend_support()` asks FlashInfer (`cake_all_gather_matmul.supports_symmetric_memory_backend`) whether the process backend is served; custom all-reduce v2 and the torch fused symm-mem SP ops keep running. An older FlashInfer without that check still gets `NVSHMEM` selected once (previous behaviour), and only then are the fused SP ops turned off (`sp_fused_matmul_eligible`).
- **admit the eagerly prepared launcher inside prefill CUDA-graph capture** (`_cake_sp_captured_call`, route event `taken-captured`): the engine warms every captured shape eagerly first, so a prepared launcher of sufficient capacity exists; when none does, the captured call falls back to the stock path (preparation is a collective and cannot be captured).
- log once per process which backend serves the Cake all-gather matmul and whether the fused SP ops stay on.
- carry the per-call diagnostic `SGLANG_CAKE_SP_CHECK=1` (eager calls only): recompute the stock all-gather + matmul on the same inputs and count calls with elements outside the BF16 tolerance; periodic summary line, optional dumps (`SGLANG_CAKE_SP_DUMP_DIR`).

Requires a FlashInfer release containing the Cake all-gather matmul backend-admission / capture change (FlashInfer PR flashinfer-ai/flashinfer#6104). Until then the branch behaves like today's route on an older FlashInfer.
