# [CI] [AMD] docker: Add a build-only dispatch option to the ROCm nightly image workflows

[Upstream PR](https://github.com/sgl-project/sglang/pull/45882) · state: closed · merged: True

## Original PR description

## What

Add a `push` input (boolean, default `true`) to the ROCm7.2, ROCm 10 and gfx1151 nightly image workflows. When a manual dispatch sets `push=false`, the image is built but every `docker push`, the lmsys retag/push, and the image-tag artifact are skipped.

## Why

Every AMD image workflow ends in `docker push`, and there's no other way to build the ROCm image on the `amd-docker-scale` runners. So a Dockerfile fix can't be checked before merge without publishing the branch build as `rocm/sgl-dev:v<ver>-<rocm>-<arch>-<DATE>` and `lmsysorg/sglang-rocm:<same>`. That is the same tag the nightly uses for that day.

## Notes for the reviewer

- `PUSH_IMAGES` is `github.event_name != 'workflow_dispatch' || inputs.push`, so scheduled runs always push, and so does a dispatch that leaves the input at its default. Nightly behavior doesn't change.
- The Docker Hub logins for pulling are kept, so build-only runs still pull base images authenticated.
- The two Miles workflows aren't touched because they build from `radixark/miles`.

## Test plan

Build-only dispatches from this branch, both with `push=false`, both passed:
- gfx1151: https://github.com/sgl-project/sglang/actions/runs/39841576697
- ROCm7.2, `gfx942-rocm720` only: https://github.com/sgl-project/sglang/actions/runs/39841585351. The full build completed and logged `Build-only run: not pushing rocm/sgl-dev:v0.5.22-rocm720-mi30x-20261022`. The artifact and lmsys login/push steps were skipped.

Neither log has any `docker push` output. ROCm 10 uses the same guard but hasn't been dispatched.
