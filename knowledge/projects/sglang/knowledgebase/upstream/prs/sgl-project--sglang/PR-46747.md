# [Perf] disagg/nixl: Opt-in warm-up transfer to each decode peer at registration

[Upstream PR](https://github.com/sgl-project/sglang/pull/46747) · state: open · merged: False

## Original PR description

## Summary

Adds an opt-in warm-up transfer for the NIXL P/D backend. With `SGLANG_DISAGGREGATION_NIXL_ENABLE_PEER_WARMUP=1`, right after the prefill registers a decode peer in `_add_remote_peer`, it posts one prepped WRITE of **slot 0 of every KV layer** into the decode's slot 0, then waits for it to settle.

**Why a transfer and not `make_connection`.** On LIBFABRIC over EFA, the first transfer to each peer pays a large one-time cost that `make_connection` doesn't remove. Measured on two trn3.48xlarge nodes, nixl 1.3.2, raw NIXL agents, 64 MB DRAM WRITEs, 6 fresh-agent trials:

| Step | Time |
|---|---|
| `add_remote_agent` (the handshake) | ~120 ms |
| `make_connection` | 0.03 ms |
| First WRITE to the peer, no warm-up | ~350 ms |
| First WRITE to the peer, after a 4 KB warm-up WRITE | **0.8 ms** (the warm-up itself took ~345 ms) |
| Warm WRITE | 0.65 ms (~104 GB/s) |

So the cost is per peer, not per byte, and a tiny transfer absorbs all of it.

**Why slot 0 is safe.** It's the allocator's reserved padding slot on both sides (`PagedTokenToKVPoolAllocator.clear` hands out pages from 1; see the "padded slot 0" comments in `memory_pool.py`). The warm-up never touches live KV. The write carries no notification, so decode doesn't see it.

**Details:**
- Runs on the prefill bootstrap thread, not the scheduler; NIXL releases the GIL in these calls.
- The settle wait is bounded by `SGLANG_DISAGGREGATION_ENGINE_INIT_TIMEOUT`.
- Peers without prepped dlists (hetero-TP, DCP relayout) are skipped.
- A failed or unsettled warm-up logs a warning and leaves the peer registered; real transfers then pay the cost as they do today.

**When it helps.** Decode registers with a prefill on its first request to that prefill, so the warm-up runs during that first request. It overlaps the per-peer cost with the prefill forward instead of adding it after the forward, and it removes the cost entirely for peers that register before traffic arrives. Steady-state transfers are unchanged. **Default off.**

  - off by default;
  - writes only slot 0 of every layer on both sides, using each side's slot count;
  - a failed warm-up doesn't raise out of the bootstrap thread and the peer stays registered;
