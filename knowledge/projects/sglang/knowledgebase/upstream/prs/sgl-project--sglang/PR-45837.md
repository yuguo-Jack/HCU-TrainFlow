# [Fix] diffusion: LoRA adapter-state and merge-transition fixes

[Upstream PR](https://github.com/sgl-project/sglang/pull/45837) · state: closed · merged: True

## Original PR description

## Motivation

Follow-up to #44770. Split per review: this PR keeps the adapter-state and merge-transition fixes. Format/scaling and merge-cache changes moved to separate PRs.

## Changes

- Clear existing adapters on the first adapter that covers a layer (not index 0), so adapters no longer stack when adapter 0 misses a layer.
- `set_lora` skips only when every target module already matches.
- Critic offload lookups map `critic` to `fake_score_transformer`.
- `load_lora_adapter` builds into a local dict and swaps at the end, so a failed reload keeps the previous adapter.
- Dynamic reactivation fast path only requires covered layers to hold exactly one entry.
- An explicit `merge_lora_weights(strength=...)` is compared against every adapter's strength and updates `cur_adapter_config`.

## Tests

No new files; extended `test_lora_pipeline.py` and `test_fused_lora_compose.py`. The new tests fail on `main` and pass here.

Modal CPU, targeted LoRA unit files: pass. ruff, isort, codespell clean. No GPU run.
