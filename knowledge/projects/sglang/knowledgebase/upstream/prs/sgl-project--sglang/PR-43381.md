# [ROCm] Support ratio-3 fused GDN qkvzba split on AITER/HIP

[Upstream PR](https://github.com/sgl-project/sglang/pull/43381) · state: closed · merged: False

## Original PR description

> **Status: draft, not ready for review.** We are still investigating the use case for this change. In end-to-end Qwen3.8-27B serving on MI355X, removing it moved throughput by -0.2% / -0.5%, which is within run-to-run noise, so it does not yet have a measured benefit to justify review time.

## Motivation

Qwen3.8-27B (and other dense Qwen3.5-architecture hybrids) use 48 v-heads over 16 k-heads in their GDN layers, a v/k head ratio of 3. #34859 taught `fused_qkvzba_split_reshape_cat_contiguous` to handle non-power-of-two groups through a per-head walk, and enabled ratio 3 on CUDA. The AITER tuple in `qwen3_5.py` was left at `(1, 2, 4, 8)`. On ROCm, every GDN layer of these models therefore still takes the unfused fallback on every forward pass: `torch.split`, two `.contiguous()` copies, and a `torch.cat`.

The kernel itself has no CUDA-specific code on this path, and the existing ratio-3 unit test is already registered for AMD CI.

## Modifications

- `python/sglang/srt/models/qwen3_5.py`: add `3` to `_GDN_FUSED_QKVZBA_RATIOS` when `_use_aiter` is set (`(1, 2, 4, 8)` -> `(1, 2, 3, 4, 8)`), and update the comment. CUDA, CPU and non-AITER HIP are unchanged.

## Accuracy Tests

The fused kernel is pure data movement. `test/registered/attention/test_gdn_fused_split_head_ratios.py` checks it bit-exactly against plain slicing for ratios 1, 2, 3 and 4. On MI355X (ROCm 7.x, torch 2.11.0+rocm, `SGLANG_USE_AITER=1`), with this branch's source:

```
test_ratio_1 PASSED
test_ratio_2 PASSED
test_ratio_3 PASSED
test_ratio_4 PASSED
4 passed in 4.12s
```

In the same environment, `sglang.srt.models.qwen3_5._GDN_FUSED_QKVZBA_RATIOS` resolves to `(1, 2, 3, 4, 8)`.

## Speed Tests and Profiling

This change removes two copies and a concat per GDN layer per forward pass on ROCm for ratio-3 models. That is the same path CUDA already takes for this layout. I have not run an end-to-end benchmark for this one-line routing change.

Related: #31091 generalizes the ratio whitelist for every backend. #43366 (draft) skips the split entirely for batched Triton decode by using strided views. This PR is the minimal fix, so that the ROCm prefill/extend path, and decode outside #43366, matches CUDA.
