# [Fix] spec: Keep mixed-batch grammar masks in step; sample-verify fixes (DFlash)

[Upstream PR](https://github.com/sgl-project/sglang/pull/46657) · state: open · merged: False

## Original PR description

## Motivation

Kimi-K3 with DFlash had three bugs.
1. A mixed chunked-prefill batch samples its decode rows in the target extend, not in `verify()`, so the grammar barrier never ran for them. Under overlap scheduling, the bitmask was built from an FSM that hadn't yet accepted the previous batch's tokens, and the request was aborted mid-stream with "Grammar accept_token failed".
2. The verify step filtered target probs differently from the sampler's top-k/top-p, so sampled verify accepted tokens the sampler would never emit.
3. Under TP, the selector draft could differ across ranks.

## Modifications

- DFlash runs the grammar barrier between the target extend forward and sampling (the `before_sample` hook). Spec workers without the hook take the synchronous path for grammar-carrying mixed batches.
- Verify filters with the sampler's own `top_k_top_p_filter_probs_torch`.
- The selector draft is broadcast from TP rank 0.
- ROCm DFlash uses the Triton chain rejection sampler for sampled verification.

## Accuracy Tests

- `test_mixed_grammar_overlap_sync.py` and `test_eagle_verify_target_probs.py` fail on `main` and pass here, with 19 passing overall.
- End to end, the grammar repro on the full stack gives 91/91 streams, 0 aborts.

Full K3 stack on MI355X TP8 (DFlash, prod config) vs B300, McNemar:
- GPQA-D 89.4 vs 87.9 (p=0.55)
- AIME25 96.7 vs 93.3 (p=1.0)
- MATH500 92.2 vs 92.2 (p=1.0)
- MMLU-Pro 89.6 vs 90.0 (p=0.77)
- GSM8K 97.2%
