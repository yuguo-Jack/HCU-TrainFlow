# [Perf] mem_cache: Free SWA pages with the Triton kernel on Triton-capable out-of-tree platforms

[Upstream PR](https://github.com/sgl-project/sglang/pull/47348) · state: open · merged: False

## Original PR description

## Motivation

`SWATokenToKVPoolAllocator._free_swa_pages` uses the fused Triton kernel `get_and_clear_swa_pages` only when `free_index.is_cuda`. Every other device takes `_free_swa_pages_none_cuda`, which launches about ten small eager ops (gather, floor-divide, page expansion, `index_fill`) on every request finish and radix eviction.

Out-of-tree platforms declare whether Triton kernels can launch on their device through `PlatformCapabilities.supports_triton`. The same allocator already honors that capability: its full and SWA sub-allocators are `PagedTokenToKVPoolAllocator`s, which gate their alloc kernels on it. Only the free path ignores it.

## Modifications

Also take the Triton path on out-of-tree platforms that declare `supports_triton=True`, when the indices are not CPU tensors.

In-tree platforms are unchanged: CUDA and ROCm keep the Triton path through `is_cuda`, and every other in-tree device keeps the eager path.

XPU, MUSA and SAIL also declare `supports_triton=True` and run the paged allocator's Triton kernels, so they could take this path too. I left them out to keep this PR free of in-tree behavior changes; widening the condition is a one-line follow-up if their maintainers want it.

## Accuracy Tests

Both functions resolve and clear the same mappings; the Triton path is the one CUDA already runs. On an out-of-tree Triton-capable platform with a hybrid sliding-window model: outputs match the golden tokens in eager and graph mode, GSM8K is 0.8946 (eager) / 0.8908 (graph) against a 0.8875 +/- 0.0107 baseline, and a SWA cache-effectiveness check passes.

## Speed Tests and Profiling

Each free, timed on an out-of-tree Triton-capable accelerator (page size 16, median of 300 calls, microseconds). Host is the time until the call returns; total is until the device finishes.

| Pages freed | `_free_swa_pages_none_cuda` host / total | `_free_swa_pages_cuda` host / total |
|---|---|---|
| 1 | 250 / 497 | 74 / 116 |
| 8 | 233 / 514 | 76 / 113 |
| 64 | 211 / 506 | 73 / 109 |
| 512 | 184 / 508 | 71 / 108 |

Both return the same pages and leave the same mapping in every case. The eager path is launch-bound, so its cost barely depends on the number of pages.
