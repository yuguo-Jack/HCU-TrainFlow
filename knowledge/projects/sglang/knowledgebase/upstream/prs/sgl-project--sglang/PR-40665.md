# [Spec] Add --speculative-draft-kv-ratio for all-SWA DFlash drafts

[Upstream PR](https://github.com/sgl-project/sglang/pull/40665) · state: open · merged: False

## Original PR description

## Motivation

A DFLASH draft allocates one KV slot per target token, even when every draft layer is sliding-window attention and it can only ever read the last window of what it stores. On Qwen3.8-27B, for example, the draft pool is 8.6 GiB versus the target's 27.5 GiB, which represents a quarter of the KV budget held for rows outside the draft's 2048-token window.

This PR adds a flag to size the draft KV pool as a ratio of the target's capacity for all-SWA DFLASH drafts. On 1xH200 with Qwen3.8-27B and a 5-layer all-SWA draft (draft window 2048, 8 running requests, and 0.8 static memory fraction), a ratio of 0.25 grows the target pool by 21.7%:

| ratio | draft pool | target pool |
|---|---|---|
| 1.0 (default) | 450,060 tokens, 8.6 GiB | 450,060 tokens, 27.5 GiB |
| 0.25 | 136,974 tokens, 2.6 GiB | 547,899 tokens, 33.4 GiB (+21.7%) |

## Modifications

- `--speculative-draft-kv-ratio` sizes the draft pool as a fraction of the target's token capacity. At the default of 1.0 nothing changes.
- Below 1.0 the draft's KV becomes the SWA side of the target allocator, which hands out a draft slot with each target slot and owns the full->SWA mapping.
- The radix cache takes its SWA component from the draft's window, so out-of-window draft slots are freed.
- With `--enable-hierarchical-cache`, the draft pool is backed up as the radix cache's SWA host pool, with one host slot per target host slot, so a prompt evicted by draft-pool pressure is restored from host. Storage backends (`--hicache-storage-backend`) are rejected below 1.0. On MLA targets their keys carry no TP rank, so with TP above 1 every rank would load rank 0's share of the draft.
- With PD disaggregation, prefill and decode register the bounded draft pool as SWA state, so the existing SWA transfer sends the draft's last window, and decode preallocates draft slots only for that window at page sizes above 1.
- Requires DFLASH. The window defaults to the draft's `sliding_window` unless `--speculative-draft-window-size` is set. Drafts with full-attention layers and targets with sliding-window layers are not supported yet. A ratio too small for the running requests is rejected with the smallest usable value.

## Accuracy Tests

`test/registered/spec/dflash/test_dflash_draft_kv_ratio.py` on 1xH200 with Qwen3.8-27B and the `z-lab/Qwen3.8-27B-DFlash2` draft, at ratio 0.15. Page size 1, page size 64 and HiCache: 14 passed and 2 skipped. GSM8K 0.98 with accept length 5.75, and 0.975 with HiCache.

Without HiCache, a prompt evicted by draft-pool pressure is recomputed. With HiCache it reloads 2,368 of 2,370 tokens from host and matches a resident hit in text and accept length.

PD disaggregation was tested on two H200s, using the Mooncake transfer backend and a page size of 64. At ratio 0.15, GSM8K accuracy stays at 0.98 and the accept length is 5.73, compared with 5.74 at ratio 1.

`test_pool_configurator.py`, `test_server_args.py`, `test_hicache_auto_size.py` and `test_hybrid_pool_assembler.py`: 354 passed.
