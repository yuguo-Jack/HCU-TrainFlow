- copilot-pull-request-reviewer · comment · 2026-10-08T02:26:34Z · [source](https://github.com/sgl-project/sglang/pull/40092#discussion_r4213985160)

File: `docs/src/snippets/configs/MiniMaxAI/minimax-h3.jsx` · line 189

Adding Xeon also exposes Docker mode, but `dockerImages` has no Xeon entry. The renderer therefore falls back to `lmsysorg/sglang:dev`, rather than a CPU build with diffusion dependencies. Add a validated CPU image, or add `"xeon"` to the Python-only hardware list in `runModes` at line 1031 until its Docker recipe is validated.

- copilot-pull-request-reviewer · comment · 2026-10-08T02:26:34Z · [source](https://github.com/sgl-project/sglang/pull/40092#discussion_r4213985206)

File: `docs/src/snippets/configs/Qwen/qwen3.8-27b.jsx` · line 394

The Xeon Docker recipe selects the regular CUDA image rather than a CPU build. The CPU installation guide requires CPU kernels and `SGLANG_USE_CPU_ENGINE=1`, provided by `docker/xeon.Dockerfile`; `--device cpu` alone does not supply that setup. Use a validated Xeon image containing this model's support, or disable Docker for Xeon until one is available.

- copilot-pull-request-reviewer · comment · 2026-10-08T02:26:34Z · [source](https://github.com/sgl-project/sglang/pull/40092#discussion_r4213985242)

File: `docs/cookbook/diffusion/Cosmos/Cosmos3.mdx` · line 56

This CPU launch defaults to port 30000, but the page's curl examples and Python `base_url` target 30010. Readers following the CPU deployment and generation steps cannot connect to this server. Specify the matching port here.

- copilot-pull-request-reviewer · comment · 2026-10-08T02:26:35Z · [source](https://github.com/sgl-project/sglang/pull/40092#discussion_r4213985284)

File: `docs/src/snippets/_deployment.jsx` · line 932

The CPU Docker branch is added only to Deploy. Qwen3.8-27B also uses Playground, whose Docker renderer still falls through to `docker run --gpus all` for Xeon (`_playground.jsx:1940–1942`). That command requires NVIDIA device access on a CPU-only host. Mirror the CPU handling in the Playground renderer.

- copilot-pull-request-reviewer · comment · 2026-10-08T02:26:35Z · [source](https://github.com/sgl-project/sglang/pull/40092#discussion_r4213985301)

File: `docs/src/snippets/autoregressive/deepseek-ocr-deployment.jsx` · line 27

The new DP checkbox has no effect: `generateCommand()` handles only TP and EP, so checking DP produces the same command on both Xeon and MI300X. Implement the data-parallel flags with supported parallel sizes, or keep this option unavailable until a recipe exists.

- copilot-pull-request-reviewer · comment · 2026-10-08T02:26:35Z · [source](https://github.com/sgl-project/sglang/pull/40092#discussion_r4213985340)

File: `docs/src/snippets/autoregressive/minimax-m25-deployment.jsx` · line 25

The hardware-change handler never revalidates `gpuCount`. Switching from AMD with `2gpu` to Xeon shows the AMD-only compatibility error; selecting `tp6` on Xeon and switching back to a GPU leaves no count selected and emits no `--tp` flag. In `handleRadioChange`, validate the current count against `options.gpuCount.getDynamicItems(next)` and select an enabled default when it is invalid.

- copilot-pull-request-reviewer · comment · 2026-10-08T02:26:36Z · [source](https://github.com/sgl-project/sglang/pull/40092#discussion_r4213985378)

File: `docs/src/snippets/diffusion/flux-deployment.jsx` · line 43

This Xeon command does not select the CPU platform. Diffusion autodetection tries accelerator backends before the CPU fallback, so on a host with an available GPU it can launch FLUX on that GPU despite the Xeon selection. Prefix the command with `SGLANG_DIFFUSION_PLATFORM_OVERRIDE=cpu`, as the other CPU recipes do.

- copilot-pull-request-reviewer · comment · 2026-10-08T02:26:36Z · [source](https://github.com/sgl-project/sglang/pull/40092#discussion_r4213985417)

File: `docs/src/snippets/diffusion/mova-deployment.jsx` · line 75

The CPU command omits `--port`, so it starts on the default 30000. The request example in `docs/cookbook/diffusion/MOVA/MOVA.mdx:82` targets 30002 and cannot connect to this server. Preserve the page's serving port.

- copilot-pull-request-reviewer · comment · 2026-10-08T02:26:36Z · [source](https://github.com/sgl-project/sglang/pull/40092#discussion_r4213985446)

File: `docs/src/snippets/diffusion/wan21-deployment.jsx` · line 145

Switching to Xeon disables the LoRA controls but retains `selectedLoraPath`, which the CPU command still emits. Wan2.1 selects an adapter by default, so simply choosing Xeon locks that adapter into the command with no way to deselect it. Clear the LoRA selection when entering CPU mode.

- copilot-pull-request-reviewer · comment · 2026-10-08T02:26:37Z · [source](https://github.com/sgl-project/sglang/pull/40092#discussion_r4213985475)

File: `docs/src/snippets/diffusion/wan22-deployment.jsx` · line 115

A LoRA selected on GPU survives switching to Xeon for the same checkpoint. The CPU command still emits `--lora-path`, but the disabled controls prevent removing the adapter. Reset `selectedLoraPath` to `'none'` when entering CPU mode.
