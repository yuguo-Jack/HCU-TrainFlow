# [Fix] spec: sample from the target when the rejection residual is empty in TreeSpeculativeSamplingTargetOnly

[Upstream PR](https://github.com/sgl-project/sglang/pull/42850) · state: open · merged: False

## Original PR description

## Motivation

Fixes #42528.

`TreeSpeculativeSamplingTargetOnly` draws coins from `[0, 1)` and, after rejecting a draft, samples the bonus/replacement token from the residual `relu(target - draft)`. The residual can be **empty**: every token the target gives mass to was a rejected draft (the kernel copies `target` into `draft` for each rejected token, so `q - p == 0` there). The easiest way to hit this in practice is a renormalized one-token nucleus (`top_k` + `top_p`): its probability is `1 - 2^-24`, not `1.0`, and `torch.rand` returns exactly `1 - 2^-24` with probability `2^-24`. The half-open CDF test (`coin < prob_acc`, #35798) then rejects the only token with target mass, `sum(relu(q - p)) == 0`, `u == 0`, no bucket is ever selected and the fallback emits token id `d - 1` — a token with zero target probability.

With MTP on a 248k vocabulary this shows up as a rare garbage token (id `vocab_size - 1`) in the middle of a generation.

## Modifications

- `python/sglang/kernels/jit/include/sgl_kernel/speculative/sampling.cuh` (shared device header, so the CUDA/ROCm JIT launchers and the MUSA AOT build all pick it up): also accumulate `sum(q)` in the first pass; when `sum(relu(q - p))` is not `> 0`, sample from the target distribution itself (`u = coin * sum(q)`, buckets from `q`). The acceptance test is unchanged, so #35798's semantics (half-open CDF, no zero-mass drafts) are preserved.
- `test/registered/kernels/ops/speculative/test_speculative_sampling.py`: add `upper-endpoint-empty-residual` — target `[0, 1 - 2^-24, 0]`, draft token 1, coin `1 - 2^-24`: the draft is rejected (`accept_token_num == 0`) and the emitted token must be `1`, not `2`.

## Accuracy Tests

- `test/registered/kernels/ops/speculative/test_speculative_sampling.py`: `8 passed` with the fix (1-GPU, JIT build). On `main` (`660b17e8dc`) the new `upper-endpoint-empty-residual` case fails (`predicts[0] == 2`, i.e. `vocab_size - 1`) and the other 7, including #35798's `interior-boundary` and both endpoints, pass — so the acceptance semantics are untouched.
- Minimal reproduction from #42528 (248,320-token vocabulary, one-token nucleus renormalized to `0.99999994`, 8 rows, coin `0.99999994`): before, 8/8 rows accept 0 drafts and emit `248319`; after, 8/8 rows still accept 0 drafts (the draft is rejected by the half-open test, as before) and emit the nucleus token `1174`. `coin=0.5` is unchanged (3 drafts accepted per row).
