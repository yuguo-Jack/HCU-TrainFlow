# [AMD] Eliminate remaining gfx95 FP8 scale relayout copies

[Upstream PR](https://github.com/sgl-project/sglang/pull/41030) · state: closed · merged: True

## Original PR description

## Motivation

Six gfx95 block-FP8 producers request row-major scales and then materialize the bpreshuffle layout with an extra GPU copy. This was visible in GLM-5.3 decode as one relayout launch per affected layer. Native `Fp8LinearMethod` checkpoints reach these branches after #39409; block-FP8 implementations exposing `weight_scale` can reach them on current main.

This supersedes #34589 and #24476 with a current-main implementation, based on the approaches from @amd-mvarjoka and @Jacob0226.

## Modifications

Use the existing `emit_transposed_bpreshuffle_scale` gate at the remaining communicator, MLA, and MHA fused-RMS producers. For `M >= 2`, AITER emits the target layout and SGLang applies a zero-copy stride view; `M == 1` keeps the existing materialize path. Extend fused-RMS tests across residual and unquantized-output combinations.

## Accuracy Tests

- Transposed and row-major producer paths are bit-exact for quantized values, scales, residual output, and the DSA bf16 payload.
- GLM-5.3 EAGLE sentinel: 949 samples, mean accept length 3.7189, p50 3.60, with no observed regression.

## Speed Tests and Profiling

GLM-5.3 MXFP4, MI355X, TP8, EAGLE 5 steps, concurrency 6 (`M=36`):

- Decode step: 17.175 ms to 16.943 ms (-1.35%), three runs per arm with disjoint ranges.
- Kernel launches: 2078 to 2000 per step; the 78 removed launches match the affected layer count.
- Trace attribution measured the removed relayout copies at 0.297 ms per step.

Measurement: three alternating runs per arm after graph capture/warmup; 50 replays per op, 20 calls per graph.
