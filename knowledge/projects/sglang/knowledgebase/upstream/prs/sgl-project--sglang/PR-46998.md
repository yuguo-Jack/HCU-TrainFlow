# [Fix] [XPU] spec: Give EAGLE drafts triton attention when intel_xpu lacks their head size

[Upstream PR](https://github.com/sgl-project/sglang/pull/46998) · state: open · merged: False

## Original PR description

## Motivation

An EAGLE draft inherits the target's attention backend unless `--speculative-draft-attention-backend` is set. On XPU the recommended target backend is `intel_xpu`, whose paged prefill and decode kernels only accept head sizes 64, 96, 128, 192, 256 and 512.

A draft with any other head size fails on its first draft forward with `Unsupported head size for paged prefill attention`. For example, `AngelSlim/Qwen3-32B_eagle3` has head_dim 80. Users currently have to know to pass `--speculative-draft-attention-backend triton`.

## Modifications

- `arg_groups/speculative_hook.py`: new `_fall_back_xpu_draft_attention_for_head_size`, run from `_handle_eagle_family`. It applies only when all of these hold:
  - the platform is XPU,
  - no draft backend was given,
  - a draft model path is set,
  - the resolved target prefill backend is `intel_xpu`.
- When it applies, it reads the draft's HF text config (`get_hf_text_config`, so composite configs such as `Qwen3_5Config` work). The head size is `head_dim`, or `hidden_size // num_attention_heads` when the config has no `head_dim`. If that size is not one the paged kernels accept, it declares `speculative_draft_attention_backend="triton"` and logs this.
- An explicit `--speculative-draft-attention-backend` is never overridden.
- The supported-size list mirrors `src/sycl/flash_attention.cpp` in sgl-kernel-xpu. It is the same in 0.4.0 and in 0.5.0, the version pinned now. sgl-kernel-xpu main has since added paged head_dim 80 (sgl-project/sgl-kernel-xpu#565). The list should gain 80 when sglang moves to a release with that change.
- New CPU unit test `test/registered/unit/spec/test_xpu_eagle_draft_attention.py`, covering:
  - head_dim 80 resolves to triton,
  - a draft config without `head_dim` (size derived as 80) resolves to triton,
  - a composite `Qwen3_5Config` draft is read from its `text_config`, for both an unsupported and a supported head size,
  - a supported head size and an explicit draft backend are left untouched.
- Each of these mutations fails at least one case: dropping the head-size check, dropping the explicit-backend check, or making the function a no-op (the pre-fix behavior).

The RoPE crash for the same draft is fixed separately in "[Fix] [XPU] rope: Fall back to native RoPE for head sizes the XPU kernel lacks". That fix is #46997; the two PRs touch different files. Serving `AngelSlim/Qwen3-32B_eagle3` on XPU needs both.

## Accuracy Tests

- The new unit test passes (4 cases), and `test_oot_eagle_hooks.py` still passes (11 cases).
- Drafts whose head size intel_xpu supports, such as Qwen3-30B-A3B's EAGLE3 drafts, resolve exactly as before.

## Speed Tests and Profiling

With both fixes, Qwen3-32B + `AngelSlim/Qwen3-32B_eagle3` starts with no manual flag and reaches 42.4 tok/s at c=1, against 31.5 tok/s without speculative decoding.
- Setup: 4x Arc Pro B70, TP4.
- Workload: ShareGPT prompts, 256 output tokens, greedy.
- Server flags: cookbook BMG flags plus `--attention-backend intel_xpu --page-size 64 --cuda-graph-backend-decode full --cuda-graph-backend-prefill breakable --speculative-algorithm EAGLE3 --speculative-num-steps 3 --speculative-eagle-topk 1 --speculative-num-draft-tokens 4`.

**[P1] Extract the draft text config before reading attention dimensions**

`get_config()` returns the full Hugging Face config, but composite draft configs such as `Qwen3_5Config` store `head_dim`, `hidden_size`, and `num_attention_heads` under `text_config`. With XPU, inherited `intel_xpu` attention, and no explicit draft attention backend, this new check raises before draft initialization—even when the actual text head dimension is supported.

I reproduced this using a locally saved `Qwen3_5Config` and the real `get_config()` loader: the text head dimension is 256, but this expression raises `AttributeError: 'Qwen3_5Config' object has no attribute 'hidden_size'`.

Please extract the text config with `get_hf_text_config()` before calculating the head dimension, and add a composite-config regression test. The current tests only cover flat configs.
