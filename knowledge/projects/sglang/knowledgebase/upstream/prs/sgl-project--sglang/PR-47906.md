# [Perf] [AMD] minimax-sparse: Persist Triton autotune results across server restarts

[Upstream PR](https://github.com/sgl-project/sglang/pull/47906) · state: open · merged: False

## Original PR description

## Motivation

MiniMax-M3's sparse-attention Triton kernels re-run their autotune sweeps on every server start, even with a warm `TRITON_CACHE_DIR`, because none of the 9 `@triton.autotune` decorators under `minimax_sparse/` set `cache_results`; this sets it, so a restart loads the saved winners instead of re-sweeping during CUDA-graph capture.

## Modifications

- Add `**autotune_cache_kwargs` to all 9 autotune decorators in `minimax_sparse/{decode,prefill}/`, reusing the helper the FLA and Mamba SSD kernels already use. Configs and keys are unchanged. `FLA_CACHE_RESULTS=0` turns it off, and it is a no-op on a Triton without `cache_results`.
- Add `test_sparse_autotuners_cache_results` to `test_minimax_sparse_gqa.py`. Run out of tree on CPU, it fails on main (9/9 uncached) and on two partial variants: one that misses the functional-style `_gqa_share_sparse_decode_kernel`, and one that leaves the prefill decorators uncached. It passes with this PR.

Trade-off: the cache freezes the first sweep's pick for each key. At TP8, one cold sweep picked `num_warps=8, num_stages=3` for batch bucket 64, while main picked `num_stages=2` in 4 of 4 sweeps. Every later restart then ran gqa decode 6.8 % / 7.6 % slower at bs 37 / 61, until the cache was cleared or `FLA_CACHE_RESULTS=0` was set. This is the same exposure the FLA and Mamba kernels already have.

## Speed Tests and Profiling

Op-level startup walk: 1 prefill, then the 52 CUDA-graph capture sizes from 512 down to 1, with MiniMax-M3 head layouts. Setup:

- MI355X (gfx950), main@d9521615b7 (these files are unchanged up to b45a36531c), Triton 3.8.0.
- Each arm ran as 4 fresh processes with a per-arm `TRITON_CACHE_DIR`, wiped before run 1.
- Figures are the median of runs 2–4, with [min–max].

| Walk time (s) | main | this PR | Δ |
|---|---|---|---|
| TP1 (64q/4kv), warm restart | 9.19 [9.14–9.39] | 0.89 [0.88–0.99] | −90.3 % |
| TP8 (8q/1kv), warm restart | 8.03 [8.01–8.18] | 0.89 [0.88–1.01] | −88.9 % |
| TP1, first cold start | 89.4 | 93.0 | — |
| TP8, first cold start | 83.1 | 82.9 | — |

There is no gain on the first cold start. Steady-state gqa decode under HIP graph stayed within main's own run-to-run config-selection noise, except for the TP8 bs 37–61 case above. Only MiniMax-M3 / M3.1 (`MiniMaxM3Sparse*`) reach these kernels. On MI355X (TP8, `SGLANG_USE_AITER=1`) the sweeps that run by default are the gqa decode kernel and the two prefill indexer kernels; on NVIDIA, Blackwell uses MSA and Hopper paged decode is pinned, so little of this is reached there.
