# [Docker] Bump DEEPEP_COMMIT past hidden-dim-3072 support (pre-EPv2 tip)

[Upstream PR](https://github.com/sgl-project/sglang/pull/31556) · state: closed · merged: False

## Original PR description

## Motivation

The mainline `DEEPEP_COMMIT` pin (`9af0e0d` = DeepEP v1.2.1, 2025-09-15) predates deepseek-ai/DeepEP#458 (2025-10-17), which added hidden-dim **3072** to the low-latency kernels' `SWITCH_HIDDEN` table. Images built from the current pin abort CUDA-graph capture for hidden=3072 models (e.g. MiniMax-M2 family) when using `--moe-a2a-backend deepep` in low-latency mode:

```
RuntimeError: Failed: Assertion error /sgl-workspace/DeepEP/csrc/kernels/internode_ll.cu:391 'false and "Unsupported hidden"'
```

Context: #24502 (we hit this on 8× B300 in April; offered to submit this bump there).

## Modifications

Two-line pin bump, `9af0e0d` → `567632d`:

- `docker/Dockerfile` — `ARG DEEPEP_COMMIT`
- `scripts/ci/cuda/ci_install_deepep.sh` — matching `git checkout`

**Why `567632d` and not DeepEP main or the #458 merge commit:** `567632d` is the last commit before DeepEP's EPv2 repo reorg (deepseek-ai/DeepEP#605, 2026-04-29), which moved kernels to `csrc/kernels/legacy/` and rewrote `setup.py` — a post-reorg pin breaks this Dockerfile's `csrc/kernels/configs.cuh` sed and build steps. Relative to the #458 merge commit, `567632d` additionally includes the `use_fabric` buffer kwarg (deepseek-ai/DeepEP#217), which sglang passes on CUDA-13 + MNNVL-fabric setups, and NVSHMEM 3.5 runtime fixes (deepseek-ai/DeepEP#564). The `deep_ep` Python API surface between the two pins is strictly additive (diffed `deep_ep/` including `buffer.py` signatures and pybind exports).

One behavioral note: #458 adds `assert self.nvshmem_qp_depth >= (num_max_dispatch_tokens_per_rank + 1) * 2` in low-latency mode — deployments with a small `NVSHMEM_QP_DEPTH` may need to raise it.
