# [NPU][FIX]: make Qwen3.6 radix-cache miss/hit lossless on Ascend A2

[Upstream PR](https://github.com/sgl-project/sglang/pull/33515) · state: closed · merged: False

## Original PR description

## Summary

Fix Qwen3.6-35B-A3B prefix/radix-cache correctness on Ascend A2.

Before this change, a cold cache miss matched the no-cache baseline, while repeated cache hits were deterministic but produced different greedy tokens. The issue was reproducible with MTP, graph, overlap scheduling, and plan stream disabled.

## Root Causes

Qwen3.6 uses:

- Mamba/GDN state chunk size: 64 tokens
- Radix-cache/page checkpoint size: 128 tokens

The old tracking logic used the 128-token cache chunk size to index the 64-token intermediate state array.

For the 29,123-token reproduction prompt, the checkpoint at token 29,056 incorrectly selected `h[99]` instead of `h[198]`.

After fixing the index, a second numerical difference remained:

- Cold miss crossed token 29,056 inside one prefill kernel while retaining FP32 internal state.
- Cache hit restored the BF16 state persisted at token 29,056.

The different FP32/BF16 persistence boundaries were sufficient to change greedy output.

## Changes

### Separate state and cache chunk sizes

- Add `mamba_state_chunk_size` for indexing kernel intermediate states.
- Keep `mamba_cache_chunk_size` for page-aligned radix checkpoints.
- Update scheduler tracking and SSM intermediate-state index calculations.
- Add regression coverage for `state_chunk=64` and `page/cache_chunk=128`.

### Align chunked prefill with radix checkpoints

- Split a cold prefill at the final radix checkpoint before processing an unaligned tail.
- The reproduction prompt now runs as:

  ```text
  cold miss: 16384 + 12672 + 67
  cache hit: cached 29056 + 67
  ```

- Both paths therefore cross the same BF16 persistence boundary.
- The alignment is limited to chunked prefill with Mamba radix cache enabled.

## Validation

- Focused scheduler/index tests: 5 passed
- Full `test_prefill_adder.py` plus index tests: 24 passed
- Greedy radix-only `max_tokens=1`: cold miss and cache hits identical
- Explicitly flushed cold miss plus two 128-token cache hits produced the same SHA256:

  ```text
  02885da7d8e868bc7f70903558081cfb42f62b1f9451aad5bdedc64bcf0493d7
  ```

- No parser, UTF-8, or output-corruption errors
- Layer-0 GDN core mismatch decreased from approximately `0.07/0.16` to `0.00024/0.0039` after correcting the state index; aligning the prefill boundary removed the observable token divergence.

## Performance

In the measured reproduction:

- Cold miss: `24.745 s -> 33.584 s`
- Warm cache hit: approximately `22.2 s`, unchanged

The cold miss performs one additional checkpoint-aligned prefill segment.

## Scope

This PR fixes radix-cache miss/hit consistency for hybrid Mamba/GDN models.

Strict MTP-on/off bitwise identity is a separate issue because target verification and normal decode use different numerical paths.
