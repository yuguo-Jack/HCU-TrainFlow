# [Fix] srt: bound FanOutCommunicator queueing calls with a reply deadline

[Upstream PR](https://github.com/sgl-project/sglang/pull/45522) · state: open · merged: False

## Original PR description

## Motivation

Fixes #45512. `FanOutCommunicator.queueing_call` awaited the all-rank reply
event with no deadline while holding the queueing lock, so a silent scheduler
rank (e.g. SIGSTOP'd) left `/flush_cache` without an HTTP response until the
client timed out, and subsequent calls on the same communicator could not
dispatch until the active call finished.

## Modifications

- New `queueing_timeout` constructor argument (default
  `DEFAULT_QUEUEING_TIMEOUT = 300.0` seconds; `None` disables the deadline and
  restores the legacy unbounded wait). The deadline covers the whole call:
  waiting for the slot behind an earlier call plus waiting for the call's own
  rank replies.
- On expiry the caller gets a new `FanOutTimeoutError` (a `TimeoutError`
  subclass) instead of hanging -- a defined worker-failure outcome rather
  than relying solely on the client's HTTP timeout.
- Response ownership is preserved: a call that times out *after* dispatch
  keeps the slot until its rank replies drain (`handle_recv` releases it once
  the captured reply count is reached). Late replies drain into the orphaned
  collector and can never be consumed by -- or complete -- a later call, and
  partial results are never reported as successful all-rank completion.
  A call that times out *before* dispatch never owned the slot and simply
  reports the timeout without sending.
- External cancellation and send failures keep the previous behavior (slot
  freed immediately). This is complementary to #42694, which addresses
  cancellation ownership; that PR's scope is unchanged by this change.
- `watching_call` is untouched.

## Reproducer (before / after, verbatim)

CPU reproducer loading the real communicator module (fan-out 2, only one
rank reply supplied; the second scenario uses `queueing_timeout=0.5` to keep
the demo short -- the default is 300s):

Before (pre-fix code):
```
timeout param ABSENT (pre-fix code)
first call: STILL PENDING after 2.0s (elapsed=2.15s)
dispatch_count=1 (second caller dispatched: False)
second call done: False
```

After (with the fix):
```
first call: FanOutTimeoutError after 0.50s
  message: FanOutCommunicator queueing call timed out after 0.5 seconds waiting for 2 rank replies
dispatch_count=1 (second caller not yet created)
dispatch_count=1 (late reply not yet drained)
dispatch_count=2 (slot freed after drain, second dispatched)
second call returned: ['rank0-reply-2', 'rank1-reply-2']
```

The timed-out call raises instead of hanging; the later caller cannot
dispatch until the late reply drains; the late reply never leaks into the
later call's results.

## Tests

- New `test/registered/unit/managers/test_fanout_communicator_timeout.py`
  (registered in `base-a-test-cpu`, 5 tests): default-timeout value,
  silent-rank fail-fast + orphan-drain ownership, pre-dispatch timeout never
  sends, success within the deadline, and `queueing_timeout=None` preserving
  the unbounded wait.
- Existing `test/registered/unit/managers/test_fanout_communicator.py`
  (FIFO ordering) still passes: 6/6 green on CPU-only Python 3.12.
- Edge cases verified: external cancellation still raises `CancelledError`
  with the slot freed immediately; send failures propagate with the slot
  freed; `queueing_timeout=0` fails fast; `watching_call` is unaffected; a
  `TimeoutError` raised by `send` itself propagates unchanged (not converted
  to `FanOutTimeoutError`).
- `ruff check --select=F401,F821,F823,UP037` (the repo's pre-commit rule
  set), `ruff format --check`, `isort --check-only`, and `git diff --check`
