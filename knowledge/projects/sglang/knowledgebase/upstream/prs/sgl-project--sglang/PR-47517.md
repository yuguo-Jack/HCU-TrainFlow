## Motivation

In a decode MoE layer two streams run after the attention boundary, and the experts' first GEMM starts when both have finished:

- main stream: the pre-expert projection (pooler) on this rank's column slice, the all-gather of the slices, then the pre-expert RMSNorm + static NVFP4 quant;
- router stream: the router GEMM and the top-8 routing.

This PR fuses the gather, the norm and the quant, so the main stream is one launch and one bf16 round trip shorter. It also takes the pooler gather path on SM107 and up to 1024 tokens at TP4.

**The gain shows only when the main stream gates the experts.** When the router stream finishes last, the experts wait for the router regardless, and this PR does not move them; the saving appears once the router stream is shortened.

## Modifications

- `all_gather_norm_fp4_quant.cuh` (new): multicast push of the local slice on the `CustomAllReduceV2` push plane, Lamport poll of each 16-element block in `norm_fp4_quant`'s thread map, then the RMSNorm and the static-scale NVFP4 quant of `norm_fp4_quant.cuh` on the gathered row in registers. fp4 / scale factors are bitwise those of the all-gather + `fused_norm_fp4_quant_static`.
- `muse_spark_all_gather.py`: the op (`all_gather_norm_fp4_quant`) and its shape check. `gemm_ag_supported(..., pooler=True)` is the pre-expert projection's rule: TP4 / TP8 on SM103 or SM107, up to `POOLER_TP4_MAX_TOKENS = 1024` at TP4 (the 8 MB push slot). The unpooler keeps the SM103-only rule and `MAX_TOKENS`.
- `muse_spark_gemm_ag.py`: `gemm_ag_norm_fp4_quant`, the local slice GEMM followed by the fused kernel.
- `muse_spark.py`: `MuseSpark1xMoE` passes the fused FP4 / scale-factor tuple to the experts as `prepared_input` when the experts take static-scale NVFP4 input through the pre-expert norm.

This PR conflicts with main in `gemm_ag_supported`. #47782 changed the SM103 check in this function to `current_arch().is_sm(10, 3)`. The pooler rule adds two `torch.cuda.get_device_capability(x.device)` checks (here and in the `n in (4096, 8192)` branch). **Fix**

When you rebase, use the `sglang.kernels.arch` helper for both checks, for example:

```python
sm_ok = current_arch().is_sm(10, 3) or (pooler and current_arch().is_sm(10, 7))
```

Then reuse `sm_ok` in both places instead of the `archs` tuple.
