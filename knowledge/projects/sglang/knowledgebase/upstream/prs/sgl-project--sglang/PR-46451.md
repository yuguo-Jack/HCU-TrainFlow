# [Perf] hicache: bound full-hit staging waits

[Upstream PR](https://github.com/sgl-project/sglang/pull/46451) · state: open · merged: False

## Original PR description

## Motivation

Supersedes #40361.

An L3 hit can be available in storage while the host pool temporarily lacks room to stage it. Add an opt-in wait for full staging so short-lived pressure can clear before the request falls back to recomputation.

## Modifications

- Add `--hicache-storage-prefetch-host-capacity-wait-ms` (default `0`). When enabled, retry full-span allocations until the deadline or retry cap is reached. The policy applies to single-engine cache mode.
- Fix cancellation and expiry handling so each pending operation is submitted once, and stale notifications cannot revoke its replacement.
- Let smaller hits proceed while a larger hit waits for capacity.
- Keep partial staging as the default and preserve buffer-only and distributed behavior.

## Accuracy Tests

- `test/registered/unit/mem_cache/test_storage_prefetch_lifecycle.py`: 24 passed, including eight new regressions for cancellation, request reuse, stale notifications, allocation order and timeout cleanup.
- `test/registered/unit/mem_cache/test_hicache_staged_write_back_dispatch.py`: 24 passed, 1 skipped.
- CLI help, changed-file pre-commit and repository Lint passed.
- All 45 benchmark runs matched the reference's 16 generated token IDs and logprobs. No operation obtained staging twice.

## Speed Tests and Profiling

One H20-3e, TP1, Qwen3.5-35B-A3B, Triton attention/MoE, `page_first_direct`, private TCP Mooncake. Replay a stored 16,384-token prefix with one additional input token and 16 output tokens, alongside a concurrent short request.

Host-pool reservations leave 4,096 tokens available for staging. For transient pressure, release the reservation on the first scheduler drain after 25 ms; for sustained pressure, hold it until cleanup. Bounded wait uses 300 ms and eight allocation retries. The immediate-miss control uses zero allocation retries, with the same storage-miss polling.

Long-request TTFT medians from five interleaved repetitions per case after warmup:

| Host capacity | Partial staging (default) | Immediate full-span miss | Bounded full-span wait |
| --- | ---: | ---: | ---: |
| Unconstrained | 247.8 ms | 249.7 ms | 249.6 ms |
| Transient pressure | 1445.6 ms | 1413.7 ms | 304.9 ms |
| Sustained pressure | 1425.4 ms | 1343.1 ms | 1680.6 ms |

Waiting reduces TTFT by 78.9% under transient pressure and increases it by 17.9% under sustained pressure, so it remains opt-in. Concurrent short-request TTFT under transient pressure changes from 232.4 ms to 143.0 ms.

On this hybrid model, partial staging reads 80 MiB without yielding a usable cached prefix; full restore reads 381.4 MiB across KV and Mamba state.

Benchmark runtime: Torch 2.13.0+cu129 and sglang-kernel 0.4.6.post1+cu129, with kernel version checking disabled.
