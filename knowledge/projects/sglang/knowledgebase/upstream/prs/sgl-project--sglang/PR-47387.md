# [Perf] [NVIDIA] dsv41: Balance the SM90 paged decode indexer's tiles across the GPU so one long context no longer sets the step time

[Upstream PR](https://github.com/sgl-project/sglang/pull/47387) · state: closed · merged: True

## Original PR description

## Motivation

On SM90, DeepSeek-V4.1 decode scores each query row against its whole visible compressed context with `fp4_index_logits_paged`. The grid gives every row a fixed `min(cdiv(max_len, 64), cdiv(num_sms * 4, rows))` CTAs, which scan the row's tiles serially, so a single long request sets the kernel time while most SMs are idle. Under DP attention every rank waits for the slowest one, so one long context slows every request on the node.

## Modifications

- `_fp4_index_logits_paged_balanced_kernel`: a persistent grid of `num_sms * 8` programs that splits all rows' tiles into equal contiguous shares. The grid does not depend on lengths, so CUDA graph capture and replay work as before.
- Per tile: queries and head weights are loaded once per row, scales are read as 4 bytes per position, e2m1 is decoded from its bit pattern, and `BLOCK_L` is 128.
- The dot shapes, bf16 rounding points and head sum are unchanged, so the scores are bitwise identical to the per-row kernel.
- `fp4_index_logits_paged` uses it behind `SGLANG_OPT_DSV41_FAST_DECODE_INDEXER` (default on; `0` restores the per-row kernel), for up to 4096 rows.

## Accuracy Tests

The scores are bitwise identical, so outputs do not change. New `test_fp4_paged_logits_balanced_matches_per_row_replay` compares the two kernels bit for bit across CUDA graph replays (32 / 64 heads, ratio 1 / 2, with and without a candidate mask, lengths 0, 1, tile edges and past `max_len`).

## Speed Tests and Profiling

Kernel, H200, one call, 32 heads, 48 query rows:

| Rows | Before | After |
|---|---|---|
| 48 × 3K | 0.055 ms | 0.051 ms |
| 48 rows, 30K-220K | 1.924 ms | 0.713 ms |
| 43 × 3K + one 900K request (5 rows) | 6.172 ms | 0.584 ms |

End to end, DeepSeek-V4.1-Flash on 8×H200 with DP attention and DSpark, 80 concurrent requests, decode tok/s:

| Workload | Before | After |
|---|---|---|
| 80 × 3K | ~11.0K | ~10.8K (within noise) |
| 80 × 30K-200K | 8.8K | 10.2K (+16.5%) |
| 79 × 3K + one 900K | 6.8K | 10.2K (+49%) |
