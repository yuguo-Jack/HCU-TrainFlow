# [Fix] [AMD] w8a8_fp8: Load and run per-channel FP8 DeepSeek-V4 checkpoints on ROCm

[Upstream PR](https://github.com/sgl-project/sglang/pull/47886) · state: open · merged: False

## Original PR description

## Motivation

DeepSeek-V4 checkpoints quantized to per-token-per-channel FP8 (`quant_method: w8a8_fp8`) do not load on ROCm today: `DeepseekV2MoE.__init__` raises `AttributeError: 'W8A8Fp8LinearMethod' object has no attribute 'quant_config'`. Past that, the fused `wqkv_a` would run with uninitialized scales, the routed experts would load saturated on gfx942, and every linear and MoE would run on the unfused fallback path.

## Modifications

- `deepseek_v2.py`: w8a8_fp8 takes the per-channel shared-expert path that compressed-tensors already takes (no `weight_block_size` check).
- `deepseek_v4.py`: with fused `wqkv_a`, the loader also remaps the per-channel `.weight_scale` of `wq_a` / `wkv`. It only carried `.weight_scale_inv`, so `wqkv_a` ran with uninitialized scales.
- `w8a8_fp8.py`:
  - On fnuz hardware the routed experts are allocated as OCP e4m3fn so loading is bit-faithful, then normalized to e4m3fnuz after loading, as the linear method in the same file already does. Copying into e4m3fnuz saturated every value above 240.
  - With `SGLANG_USE_AITER` on HIP, linears run aiter's preshuffled `gemm_a8w8_bpreshuffle` with per-token activations, and the MoE runs aiter's fused MoE with per-token quant.

Not included: per-channel checkpoints whose routed experts stay mxfp4-packed; that needs a separate change once validated.

## Accuracy Tests

Main `def8f93212` with this change, 8x MI308X (gfx942), DeepSeek-V4-Flash FP8 per-channel checkpoint, TP4, `SGLANG_USE_AITER=1`, `--attention-backend dsv4`, `SGLANG_HACK_FLASHMLA_BACKEND=unified_kv_triton`, `SGLANG_DSV4_FP4_EXPERTS=0`.

- Main as is: fails at model init (above).
- With this change, as the token-parallel-off arm of the measurements in #47888: gsm8k 8-shot 1319 questions 0.9401 (200 questions: 0.97), needle in a haystack 8K-60K 12/12.
- With DSpark and #47887: gsm8k 1319 0.9431, accept length 4.6-5.5 at 1024-token outputs.
- Re-checked on this revision, which only drops an unvalidated mxfp4-experts path and tidies comments: gsm8k 200 0.96, needle 12/12.

## Speed Tests and Profiling

Flash TP4, single request, 10 output tokens: TTFT 463 / 1524 / 3523 / 8124 ms at 4K / 14K / 30K / 63K input (mean of three runs). There is no main baseline because main does not load this checkpoint.
