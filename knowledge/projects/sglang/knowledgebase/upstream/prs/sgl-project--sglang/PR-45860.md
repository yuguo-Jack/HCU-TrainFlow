# [Fix] docker: Relax frozen python-dateutil pin so runai-model-streamer[s3] resolves

[Upstream PR](https://github.com/sgl-project/sglang/pull/45860) · state: open · merged: False

## Original PR description

## Problem

The CUDA image build fails at the `framework` stage with:

```
error: No solution found when resolving dependencies
  runai-model-streamer[s3]>=0.15.7 and pandas==3.1.0 are incompatible
```

### Root cause

The `torch_deps` stage freezes the fully-resolved dependency set into `constraints.txt`:

```dockerfile
uv pip freeze | grep -vE "^sglang( |==|@)" > /sgl-workspace/constraints.txt
```

`python-dateutil` has just released **3.0.0**, so it is captured as the latest and frozen as `python-dateutil==3.0.0` (pandas 3.1.0 only requires `python-dateutil>=2.9.0`, so nothing actually needs 3.0.0).

The `framework` stage then runs:

```dockerfile
uv pip install -c /sgl-workspace/constraints.txt ... pandas ... "runai-model-streamer[s3,gcs,azure]>=0.15.7"
```

The `[s3]` extra pulls `runai-model-streamer-s3 -> boto3 -> botocore`, and **botocore requires `python-dateutil<3.0.0,>=2.1`**. The hard `==3.0.0` pin from the freeze collides with that, so the resolution is unsatisfiable.

## Fix

Relax the frozen `python-dateutil` pin to `<3.0.0` right after generating `constraints.txt`, so later stages can resolve a compatible 2.9.x that satisfies both `pandas` (`>=2.9.0`) and the boto3/botocore chain (`<3.0.0`).

## Verification

Reproduced and verified with `uv pip compile` (platform `x86_64-manylinux_2_34`, Python 3.12), using the frozen pins plus a realistic boto3 floor:

| constraints | result |
|---|---|
| `python-dateutil==3.0.0` | `No solution found` (reproduces the failure) |
| `python-dateutil<3.0.0` | **Resolved** → `python-dateutil==2.9.0.post0`, `boto3`/`botocore==1.43.117`, `pandas==3.1.0` |
