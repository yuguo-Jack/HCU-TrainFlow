# [HiCache] Add staged write-back for the page-unified KV cache layout

[Upstream PR](https://github.com/sgl-project/sglang/pull/39606) · state: closed · merged: True

## Original PR description

## Motivation

Add staged write-back support for the `page_unified` KV cache layout, building on the unified storage layout discussed in #33651 and the GPU staging approach introduced in #21631.

The destination layouts are:

- **MHA:** `(page, head_group, layer, 2, page_size, head_in_group, dim)`, where K=0 and V=1.
- **MLA:** `(page, layer, page_size, dim)`, storing one compressed KV tensor per layer.

## Changes

- Add `hicache_page_unified_relayout_kernel` to gather per-layer GPU KV data into contiguous staging pages using 16-byte vectorized loads and stores.
- Support MHA and MLA through compile-time specialization. MLA has no head-group, separate K/V, or head axes.
- Reuse the existing whole-page D2H copy helpers after GPU relayout.
- Support transfers larger than the caller-provided staging buffer by processing chunks on the current CUDA stream.
- Add MHA and MLA Python entry points and correctness tests in existing files.

This PR implements the write-back primitives and tests. Host-pool integration and load-back support are outside its scope.

## Correctness

**160 test cases passed on NVIDIA H20 after merging `sgl/main`: 80 MHA and 80 MLA cases.**

Tests compare the complete host output against an independently constructed CPU reference using exact equality, including untouched destination pages.

Coverage includes:

- Different head-group counts, layer counts, page sizes, and dimensions.
- MLA compressed KV dimensions of 512 and 576.
- BF16, FP16, and uint8 data.
- int32 and int64 source page indices.
- Reordered pages and repeated source pages.
- Empty transfers, staging reuse, and partial final chunks.
- Execution on a non-default CUDA stream.
- Invalid shapes, alignment, staging capacities, and destination indices.

Ruff, clang-format, and diff whitespace checks passed for the implementation changes.

## Performance

The MHA write-back path was benchmarked on one NVIDIA H20 with PCIe Gen5 ×16, PyTorch 2.9.1 / CUDA 12.8, and CPU/memory bound to the GPU's NUMA node.

Configuration:

- BF16
- 61 layers
- 8 KV heads
- Head dimension: 128
- Page size: 64
- 5 warmup iterations and 25 measured iterations
- Median CUDA-event latency

Bandwidth includes **GPU relayout + D2H transfer**. GB/s counts the KV payload once.

| Tokens | Payload | 1 head group | 2 head groups | 4 head groups | 8 head groups |
|---|---:|---:|---:|---:|---:|
| 512 | 122 MiB | 52.32 GB/s | 52.34 GB/s | 52.33 GB/s | 52.33 GB/s |
| 2048 | 488 MiB | 52.53 GB/s | 52.52 GB/s | 52.53 GB/s | 52.52 GB/s |
| 8192 | 1952 MiB | 52.74 GB/s | 52.74 GB/s | 52.74 GB/s | 52.74 GB/s |

The measured contiguous D2H baseline was **55.0–55.2 GB/s**, so staged write-back reached approximately **95%** of that baseline.

Using a 32-page staging buffer for the 8192-token transfer sustained approximately **52.6 GB/s**.

For 2048 tokens, profiling showed approximately **0.34 ms for GPU relayout** and **9.39 ms for D2H**, indicating that PCIe transfer dominated total latency.

These performance measurements were collected before the MLA extension and the subsequent merge of `sgl/main`. MLA correctness was validated; MLA bandwidth has not been measured.
