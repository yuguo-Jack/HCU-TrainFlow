# [Rust] Lock hyper 1.12.0 and want 0.3.2 in the rust workspace

[Upstream PR](https://github.com/sgl-project/sglang/pull/43724) · state: closed · merged: True

## Original PR description

## Motivation

hyper 1.11.0 with want 0.3.1 has a race in the HTTP/1 client connection pool: a request can be queued behind a pooled connection that is still busy even when another pooled connection is about to become idle. Under concurrent load through a single pooled hyper client this shows up as requests waiting a full extra response time for no reason. hyper 1.12.0 and want 0.3.2 fix the race.

## Modifications

A lockfile-only change to `rust/Cargo.lock`: the `hyper` entry moves from 1.11.0 to 1.12.0 and the `want` entry from 0.3.1 to 0.3.2, with their checksums. Nothing else in the lock changes. A plain `cargo update -p hyper` also reshuffles unrelated Windows-only `windows-sys` entries, which this PR deliberately leaves alone.

All workspace `Cargo.toml` constraints already admit these versions, so no manifest changes are needed.

Verified locally in `rust/` with `--locked`, so cargo fails if it wants to rewrite the lock: `cargo tree --locked -i hyper@1.12.0` and `cargo tree --locked -i want` resolve to the new versions, and the lock file is unchanged afterwards. `cargo clippy --locked --workspace --all-targets -- -D warnings` and `cargo test --locked -p sglang-server` pass.
