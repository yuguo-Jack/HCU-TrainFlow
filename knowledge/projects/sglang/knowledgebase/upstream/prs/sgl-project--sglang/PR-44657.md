## Motivation

Decode currently shares a MegaMoEV2 instance sized for prefill. Even with a small decode batch, the large MTPR keeps it on the large-instance dispatch/combine path, preventing it from benefiting from kernel configurations optimized for small token counts.

Introduce a separate, smaller decode instance to enable the small-MTPR execution path while retaining the main instance for prefill.

## Modification

Add `SGLANG_AMD_FLYDSL_MEGA_MOE_DECODE_MTPR` (default: `0`, disabled). When enabled, maintain two cached `MegaMoEV2` instances:

- **Main instance:** uses `SGLANG_AMD_FLYDSL_MEGA_MOE_MTPR` for steps containing prefill.
- **Decode instance:** uses the smaller MTPR `SGLANG_AMD_FLYDSL_MEGA_MOE_DECODE_MTPR` for decode, target verify, and draft extend in decode-only steps. 

Both instances are constructed together in a fixed order across EP ranks before graph capture. They own separate communication buffers and synchronization state while sharing model weights through per-layer rebinding.

Instance selection follows the globally synchronized step type, ensuring all EP ranks use the same instance regardless of local batch size or graph/eager execution. Startup validation checks that the decode MTPR covers the maximum per-rank workload.
