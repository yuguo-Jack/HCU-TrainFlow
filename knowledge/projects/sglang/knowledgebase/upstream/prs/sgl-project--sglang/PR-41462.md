# [Rust server] Add SageMaker-compatible endpoints

[Upstream PR](https://github.com/sgl-project/sglang/pull/41462) · state: closed · merged: False

## Original PR description

## Motivation

The Rust frontend returns HTTP 404 for SageMaker's `/ping` and `/invocations`, while the Python server already exposes both. This implements the basic endpoint-parity portion of #23206, item 25.

## Modifications

- Add `GET /ping` with Python's empty HTTP 200 liveness response, without submitting a generation probe.
- Register `POST /invocations` on the existing chat-completion handler, sharing its request validation and unary/SSE response handling.
- Add three CPU HTTP regression tests, exercise existing chat-validation cases through both routes, and document the endpoints.

## Accuracy Tests

Validated on macOS arm64 using the repository-pinned Rust 1.92.0:

- `cargo test --manifest-path rust/Cargo.toml -p sglang-server --lib --locked --quiet -- --skip multi_modality::shm::tests::into_name_disarms_the_unlink --skip multi_modality::shm::tests::segment_roundtrip_and_drop_unlinks --skip multi_modality::result_store::tests::park_splits_features_by_grid`: **275 passed, 3 filtered**.
- Those three existing tests read Linux `/dev/shm` paths. An unfiltered run failed the same three tests on both this patch and the unchanged base `c311bc9611` (275 vs. 272 passing tests, respectively).
- All three new endpoint tests failed with HTTP 404 before adding the routes and passed afterward. They exercise routing, chat request preparation, typed backend-response fixtures, JSON responses, and SSE completion framing.
- All applicable pre-commit hooks passed, including the workspace Clippy and rustfmt hooks. `git diff --check` passed.

These are CPU HTTP-handler tests. No real-model inference or deployment on AWS SageMaker was run.

## Speed Tests and Profiling

Not applicable: this adds endpoint routing and reuses the existing chat handler; no model-forward or kernel changes.
