# [Feat] [NPU] scheduler: align cross-request ViT batching with CUDA and fix NPU graph buffer ownership

[Upstream PR](https://github.com/sgl-project/sglang/pull/44435) · state: open · merged: False

[**Related issue**: [#25598 — NPU Development Roadmap 2026 H2](https://github.com/sgl-project/sglang/issues/25598)

## Motivation

NPU currently encodes per-image cache misses separately for each request. Enable the existing CUDA cross-request batching path on NPU, so eligible cache misses from multiple requests can be encoded together, without introducing a new environment variable. Retain the existing per-request behavior on HIP/XPU.

Cross-request batching also requires cached embeddings to remain valid after later ViT invocations. The NPU graph runner must preserve caller inputs and returned embeddings across capture, replay, and reuse of the shared graph pool.

## Modifications

1. **Scheduler:** remove NPU from the per-request fallback condition so eligible cache misses follow the existing CUDA batching path. Keep deduplication, cache refill, and request-order assembly. HIP/XPU retain the per-request path. No new environment variable or model capability flag is introduced.
2. **NPU graph ownership:** give captured inputs and returned embeddings independent storage where needed, preventing in-place vision blocks and later graph executions from overwriting caller inputs or retained embeddings.
3. **Regression tests:** cover cross-request merge/split behavior and graph input/output ownership, plus NPU image association, multi-image ordering and embedding-cache reuse. The block/deepstack/merger computation and graph lifecycle retain the main implementation.
