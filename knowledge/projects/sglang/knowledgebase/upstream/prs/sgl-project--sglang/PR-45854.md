# [CI] [Intel] docker/xpu: Tag nightly images with main-whl and main-main kernel variant

[Upstream PR](https://github.com/sgl-project/sglang/pull/45854) · state: closed · merged: True

## Original PR description

## Motivation

The Intel XPU nightly publish job (`release-docker-intel-xpu-nightly.yml`) builds two `intel/sglang-dev` images per run: one with the prebuilt `sglang-kernel-xpu` wheel and one with `sgl-kernel-xpu` main built from source. Today the wheel image's dated tag doesn't say which variant it is, and the source image uses a `-kernel-main-` suffix. This makes the kernel variant explicit in both tags.

## Modifications

Rename only the dated-tag suffix:

| Variant | Before | After |
|---|---|---|
| wheel | `nightly-dev-xpu-bmg-20261020-c2e5742` | `nightly-dev-xpu-bmg-20261020-c2e5742-main-whl` |
| source | `nightly-dev-xpu-bmg-20261020-c2e5742-kernel-main-253c08a` | `nightly-dev-xpu-bmg-20261020-c2e5742-main-main-253c08a` |

- No other tag logic changes. Non-main refs keep their existing slug prefix.
- The rolling `latest` and `latest-kernel-main` tags that CI pulls are unchanged. Nothing in the repo reads the dated tags.
- Build args, kernel pinning, and push steps are unchanged.
