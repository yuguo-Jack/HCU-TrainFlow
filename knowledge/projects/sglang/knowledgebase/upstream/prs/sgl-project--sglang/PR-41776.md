# [Tokenizer] Optionally omit consumed processor input_ids from tokenized multimodal requests

[Upstream PR](https://github.com/sgl-project/sglang/pull/41776) · state: closed · merged: False

## Original PR description

## Motivation

For multimodal requests, `TokenizerManager._create_tokenized_object` copies the processor's expanded `input_ids` into the request's canonical `array("q")`, but the `MultimodalProcessorOutput` it forwards still carries the same list. That list is then serialized to the scheduler a second time. For long multimodal prompts this is a redundant O(prompt) payload on every request.

## Modifications

- New `SGLANG_MM_STRIP_PROCESSOR_INPUT_IDS` (default `False`). When set, and the request IDs were taken from the processor output (`input_ids is mm_inputs.input_ids`), the forwarded output is a `msgspec.structs.replace` copy with `input_ids=None`.
- Outputs with extra attributes (`__dict__`) or weak references are left unchanged, so callbacks or state attached to the producer output keep their lifetime. The producer's own object is never mutated, and padded/modality IDs are kept.
- `test/registered/unit/managers/test_tokenizer_mm_input_ids_reduction.py`: canonical IDs and reuse, embedding expansion, precomputed padding across session prefixes, broadcast materialization on both ranks, unused processor IDs, encoder-output ordering, msgpack wire round-trip, and ownership/finalizer cases.

Split out of the caller token-ID validation PR so it can be reviewed on its own.

## Compatibility

Off by default, so behavior is unchanged unless the env var is set. With it on, scheduler-side consumers that read `mm_inputs.input_ids` instead of the request's `origin_input_ids` would see `None`; the tests cover the in-tree consumers exercised by the tokenizer→scheduler path, but out-of-tree processors that read the field would need to switch.

## Accuracy Tests

CPU: 8 passed, 4 subtests passed. With the `msgspec.structs.replace` line disabled: 4 failed.

## Speed Tests and Profiling

Reduces tokenizer→scheduler payload for multimodal requests when enabled; not separately benchmarked.
