# fix(diffusion): make warmup preload components and headroom configurable

[Upstream PR](https://github.com/sgl-project/sglang/pull/43561) · state: closed · merged: False

## Original PR description

## Motivation

Warmup always preloads every component a pipeline marks `preferred_ready_after_request`, and it always reserves a fixed 1 GiB of free device memory before doing so. On a tight GPU that preload is the difference between a warmup that fits and one that runs out of memory, and there is no way to skip it, narrow it to the components the next request needs, or change the headroom. #41126 asks for both knobs.

`auto` and `1.0` keep today's behavior. An explicit `--component-residency` policy still wins, and the component filter applies only to warmup requests.

Fixes #41126

## Modifications

- `--warmup-preload-components` (default `auto`). `auto` keeps the pipeline hints. `none` skips those preferred preloads and does not unload components already kept by `keep_ready_after_warmup`. Otherwise a comma-separated list of exact module keys or the groups `dit`, `text_encoder`, `image_encoder`, `vae`, and `all`. A group includes numbered suffixes (`text_encoder` matches `text_encoder_2`; `dit` matches `transformer`, `transformer_2`, and the other DiT modules). An exact key matches only that module. Names the pipeline did not mark preferred are not preloaded. A selector that matches no loaded component logs a warning once.
- `--warmup-preload-margin-gib` (default `1.0`). Free device memory left unused when deciding whether a warmup preload fits. `0` leaves no extra headroom. Layerwise offload does not consult this headroom, and the check does not estimate activations or attention workspace.
- The filter runs in `ComponentResidencyManager.finish_request` only when `state.batch_is_warmup`. The margin is stored on `ResidencyState.warmup_preload_margin_bytes` and read by `ComponentOffloadStrategy`.

## Accuracy Tests

No model, kernel, or sampling change. The default `auto` / `1.0` keeps the existing preload set and the historical 1 GiB headroom.

Unit tests cover CLI parsing and validation, warmup-only filtering (`auto`, `none`, `dit`, and group-vs-exact-key matching), explicit residency precedence, `keep_ready_after_warmup`, and a custom margin.

## Speed Tests and Profiling

Not run. The default warmup path is unchanged. `none` or a narrower list only changes which components stay resident after warmup.
