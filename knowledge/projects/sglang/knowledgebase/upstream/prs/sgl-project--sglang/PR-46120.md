# [Fix] diffusion/disaggregation: Isolate malformed request and result messages

[Upstream PR](https://github.com/sgl-project/sglang/pull/46120) · state: closed · merged: True

## Original PR description

## Motivation

Production fault testing around #45919 exposed an independent disaggregation failure: one malformed worker tensor result can terminate the head's routing loop and stall unrelated requests. Invalid scheduler payloads and duplicate active IDs can also leave clients waiting without a reply.

## Changes

- Decode worker tensor frames once at the message boundary. An identifiable decoding error fails its request; unidentifiable frames are logged and discarded without stopping the head.
- Reply to malformed or duplicate scheduler requests without replacing an existing request. Make the existing one-request-per-message contract explicit.
- Treat missing decoder output as an error while preserving audio-only results.
- Return reserved receive slots when a worker reports an error, as well as its scheduling capacity.
- Extend the existing orchestration test across combined/split encoders, dynamic/preallocated buffers, malformed requests/results, duplicate IDs, worker errors, and recovery. No new production module or knob.
- Document the failure boundary and trusted-network requirement.

## Validation

- Remote fault matrix on the base revision: **24 failed, 4 passed**. Fixed related suite: **111 passed, 6 subtests passed**, including 44 orchestration variants.
- Real GLM-Image on 2x H200, PyTorch 2.14.1+cu130 / CUDA 13.0: external AR server, separate DiT/VAE worker and HTTP head; 1024x1024, 30 steps, concurrent `n=1/2` requests.
- A ZMQ relay corrupts the shape of exactly one real output tensor after a successful warmup. Before the fix, the routing loop exits and all four concurrent requests time out after 90 seconds. After the fix, only the affected request returns 500; the other three requests and a subsequent recovery request complete successfully.
- Repeat with in-memory and saved outputs: 12 generation requests, 10 successful responses and two expected failures. Each run returns six valid images; the six saved files match the API's encoded bytes. No worker-side image files remain. Malformed IPC requests return errors, invalid HTTP input returns 422, and subsequent generation succeeds.
- Both baselines include #46104 to avoid the unrelated missing-image transport regression. Its changes are not included here.
- Pre-commit passes. No model computation, GT, tolerance, or performance baseline changes; no speedup claim.

This is request-level isolation for malformed scheduler messages and tensor decoding errors, not general failover. Transfer-control validation, dead/hung-worker supervision, head restart recovery and durable jobs remain separate concerns. The internal pickle transport must remain on a trusted network.
