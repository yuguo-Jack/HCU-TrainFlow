# [AMD] Pass a query-dtype cos_sin_cache to the HIP rotary_embedding fallback

[Upstream PR](https://github.com/sgl-project/sglang/pull/42483) · state: closed · merged: False

## Original PR description

## Motivation

#41282 keeps `RotaryEmbedding.cos_sin_cache` fp32 on HIP so the fused QSA indexer kernel can read it, and stopped casting it to the query dtype in `forward_cuda`. On HIP, though, every rope without a fused KV-cache write goes through the `sgl_kernel.rotary_embedding` fallback, and that kernel reads the cache as `scalar_t` of the query. With a bf16/fp16 query it now fails during CUDA graph capture:

```
File ".../sglang/srt/layers/rotary_embedding/base.py", line 455, in forward_cuda
File ".../sgl_kernel/elementwise.py", line 414, in rotary_embedding
RuntimeError: expected scalar type BFloat16 but found Float
Exception: Capture cuda graph failed: expected scalar type BFloat16 but found Float
```

This takes down `stage-a-test-1-gpu-small-amd` (Llama in `test_basic_sanity.py` / `test_basic_sanity_eagle3.py`), so every AMD stage B/C lane is skipped. Examples: [run 37180583674](https://github.com/sgl-project/sglang/actions/runs/37180583674/job/111372273784), [run 37187809051](https://github.com/sgl-project/sglang/actions/runs/37187809051/job/111393476849) (`expected scalar type Half but found Float`).

## Modifications

`python/sglang/srt/layers/rotary_embedding/base.py`:

- The HIP fallback branch of `forward_cuda` passes `_cos_sin_cache_as(query.dtype)`: a copy of the fp32 buffer cast to the query dtype. It is cast once and reused until the buffer is replaced (moved or extended by `_ensure_cos_sin_cache_length`). The kernel sees the same values as before #41282.
- The registered buffer stays fp32, so the QSA indexer and the other HIP consumers #41282 targets are unchanged. The device move now only reassigns when the device actually differs.

CUDA, XPU and the other platforms are untouched.

`test/registered/unit/layers/test_rope_hip_fallback_cache_dtype.py` (CPU): with `_is_hip` patched on, the fallback gets a query-dtype cache equal to the fp32 buffer cast, the copy is reused across calls, the buffer stays fp32, and an extended buffer produces a fresh copy.
