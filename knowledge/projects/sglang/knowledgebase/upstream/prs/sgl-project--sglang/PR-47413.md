# [Fix] deterministic: Batch-invariant Kimi Delta Attention

[Upstream PR](https://github.com/sgl-project/sglang/pull/47413) · state: open · merged: False

## Original PR description

## Motivation

Kimi-Linear (Kimi Delta Attention + MLA; Kimi K3 uses the same KDA kernels) is not deterministic with `--enable-deterministic-inference`: on MI350X, 2-7 different outputs for 50 identical requests, up to 9 per prompt in the prefix test, and bitwise-identical logprobs in only 10 of 1,275 responses. KDA gives a request different results depending on its batch in three places:
- `fused_recurrent_kda_packed_decode` switches to a row-streaming kernel from 8 requests up, which rounds differently from the Triton kernel;
- `chunk_kda_fwd` fuses the diagonal blocks and the recompute when the batch's total chunk grid is small (`B * NT * H <= 256`): a 59-token sequence alone takes the fused path and inside a batch the unfused one, and the two round differently;
- chunked prefill can split a request off the 64-token chunk grid that `chunk_kda` counts from the sequence start.

## Modifications

- `fla/fused_recurrent.py`: in batch-invariant mode, keep the Triton packed-decode kernel for every batch size.
- `fla/kda.py`: in batch-invariant mode, `chunk_kda_fwd` takes the unfused path for every batch.
- `managers/scheduler.py`: with `--enable-deterministic-inference`, align chunked-prefill splits to 64 tokens for Kimi-Linear models (as already done for Gated DeltaNet models).
- New test `test/registered/amd/test_kda_batch_invariant.py`: a sequence's `chunk_kda` prefill (59, 200 and 1,000 tokens) and a request's packed decode step give the same bits alone and in batches of up to 32.
- Normal mode is unchanged.

## Accuracy Tests

MI350X (gfx950), ROCm 7.2.4, `rocm/sgl-dev:v0.5.22-rocm724-mi35x-20261021`, deterministic mode (`--enable-deterministic-inference`) together with the other open MI350X deterministic-mode changes (the same in every run). Checks: `python3 -m sglang.test.test_deterministic` (`single`, `prefix`, `prefix --return-logprob`, `radix_cache`, 50 trials) plus a bitwise batch-size check (the same prompt in batches of 1 to 50, 1,275 responses, token IDs and logprobs compared exactly with the batch-size-1 response). GSM8K through sgl-eval, 1,319 questions, temperature 0.

- Kimi-Linear-48B-A3B TP1: every check passes on 3 / 3 fresh servers (single 1, prefix 1/1/1/1, prefix logprobs identical, radix cache consistent, bitwise 1,275 / 1,275; long-prompt bitwise 9 / 9). Before: single 2-7, prefix up to 9, bitwise 10 / 1,275. GSM8K 91.89% (normal mode 91.28%).
- TP2: every check passes; GSM8K 91.81%.
- The new test passes on MI350X (4 passed). With batch-invariant mode off, 3 of its cases fail (59- and 200-token prefill, packed decode), as expected; the 1,000-token prefill is above the small-grid bound either way.
- Known: at TP4, Kimi-Linear's prefix test still varies (1/2/3/6) with this PR; the same TP4-only symptom appears on another model and is outside KDA.

## Speed Tests and Profiling

Kimi-Linear TP1, deterministic mode, output throughput 1k / 1k and 8k / 1k: 6,532 / 1,539 -> 6,499 / 1,526 tok/s (-0.5% / -0.8%; normal mode 7,885 / 2,767). Normal mode is unchanged.
