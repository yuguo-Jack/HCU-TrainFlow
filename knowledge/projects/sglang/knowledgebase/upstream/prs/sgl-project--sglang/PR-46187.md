# [Feat] spec: online acceptance estimator for drafts without a confidence head

[Upstream PR](https://github.com/sgl-project/sglang/pull/46187) · state: open · merged: False

Updated onto upstream `main` (6a319e7b). All applicable pre-commit checks passed on this branch. The GPU tests and benchmark results below were run previously on the original source branch; they have not been rerun after this upstream update. Submission preparation used AI assistance.

## Problem

Confidence-scheduled (compact) verification sizes each request's verify window from per-position acceptance probabilities. DSpark drafts get these from a trained confidence head. Draft models without such a head, like DFlash2, have no confidence source, so they cannot use the planner.

## Fix

Add `OnlineAcceptanceEstimator` (python/sglang/srt/speculative/online_acceptance_estimator.py), a logistic model that calibrates itself while serving:

    p_k = sigmoid(slope * x_k + bias_k)

- **Feature.** x_k = logit(q_max) of the temperature-scaled draft distribution at position k. Greedy rows are scored at T = 1, and the value is clamped to +-40. It is computed exactly as -log(sum over the non-max candidates of e^(z - m)), so confident rows are not quantized. The feature scores the draft distribution, not the sampled token, so trimming drafts by it keeps rejection sampling lossless.
- **Model.** One slope is shared by all positions, and each position has its own intercept. They start at 0.5 and -0.2.
- **Learning.** `observe()` labels the accepted drafts and the first rejected one (positions k <= accepted and k < verified) and adds them to the Newton (IRLS) statistics, with weights evaluated at the current coefficients.
- **Refit.** Every 100 calls it solves the arrowhead system (ridge 1e-3) via the Schur complement, damps each update by n / (n + 50), and clears the statistics.
  - A slope step that would make the slope negative is halved until the slope stays positive, at most 8 times, and dropped only if it still crosses zero. The intercepts take their Newton step given the slope step actually taken.
  - This backtracking is its own commit, 874094430, on top of the estimator commit 17ed303ce. 17ed303ce dropped every such step. From an overconfident fit the predictions saturate, the damped step overshoots past zero round after round, and the slope never moved: started at 3.0 on drafts generated with slope 1.0, it stayed at 3.0, and from the default 0.5 on drafts whose feature carries almost no signal it could stay at 0.5. With backtracking, within ten refits the slope reaches 0.96 in the first case and 0 to 0.06 in the second (generating slope 0 or 0.03). Refits whose full step keeps the slope positive are unchanged.
  - Non-finite steps are dropped.

Interface:
- `feature_from_scores(scores [bs, K, n_cand], temperatures) -> x [bs, K]`
- `predict(x) -> p [bs, K]`, with no state change
- `feature_and_predict(scores, temperatures) -> (x, p)`, both in one kernel launch
- `observe(x, num_verified, num_accepted)`
  - num_verified excludes the anchor; num_accepted excludes the bonus token.
  - Padding rows pass num_verified = 0 and are never read.
  - Call it once per real verify step, never from warmup or dummy forwards.

Two Triton kernels in python/sglang/kernels/ops/speculative/acceptance_estimator.py compute the feature (optionally with the prediction) and the accumulate/refit. Both are registered in the kernel inventory. The refit counter is a device tensor, the refit interval is a runtime kernel argument, and the coefficients are updated in place. As a result:
- No call synchronizes with the host, so the estimator works with overlap scheduling.
- The whole step can be captured in a CUDA graph.
- A single program applies each update, backtracking included, so TP ranks that see the same inputs keep bit-identical coefficients.

## Effect

No behavior change on its own: nothing in this PR calls the estimator. Its only caller is https://github.com/sgl-project/sglang/pull/46190, which uses it as the confidence source for confidence-scheduled verification of DFLASH drafts, so the two should be reviewed together. This PR has no end-to-end speed numbers; those are in https://github.com/sgl-project/sglang/pull/46190.

Offline, the estimator was replayed in order over recorded static DFlash2 traces of Qwen3.8-27B (block 8, 1.8M to 2.9M draft positions each). AUC of the predicted survival against acceptance:

| Trace | Estimator | Raw q_max product |
|---|---|---|
| T = 1, c64 | 0.898 | 0.886 |
| T = 1, c128 | 0.898 | 0.886 |
| T = 0, c64 | 0.921 | 0.920 |
| T = 0, c128 | 0.919 | 0.918 |

These AUCs were measured on 17ed303ce, before the backtracking in 874094430.

Cost on GB300, K = 7, 16 candidates, measured on 17ed303ce:

| | bs <= 128 | bs = 512 |
|---|---|---|
| Fused feature + predict, then observe: GPU time in a CUDA graph | 6-8 us | 10 us |
| Separate kernels: GPU time in a CUDA graph | 10 us | 14 us |
| Fused step: host time eager | 55-56 us | 56 us |
| Separate step: host time eager | 85-89 us | 87 us |

The backtracking in 874094430 adds at most 0.1 us of GPU time to `observe()` (bs 1 to 512, K = 7 and 16, refit on every call or every 100 calls).

## Tests

test/registered/kernels/ops/speculative/test_online_acceptance_estimator.py (CUDA, about 30 s; also registered for the ROCm nightly kernel suite) covers:
- the feature kernel against a float64 reference: dtypes, strides, multi-block candidate rows, ties, clamp and greedy rows;
- the fused feature + predict path against the separate calls;
- observation-rule edge cases;
- padding rows, which leave the estimator bit-identical;
- a float64 reference of the full IRLS round over hundreds of steps, with coefficients matching to 1e-4, including batches that span the kernel's request blocks;
- refit interval and statistics reset;
- slope steps that cross zero: backtracked, or dropped when they still cross it after 8 halvings, and a saturated fit started at slope 3.0 that ends within 0.15 of the generating slope 1.0, where dropping the steps leaves it at 3.0;
- empty batches;
- no host synchronization (`torch.cuda.set_sync_debug_mode("error")`);
- CUDA graph replay matching eager bit-for-bit across refits.

compute-sanitizer memcheck, racecheck and initcheck, run on 17ed303ce before the backtracking, report no device-side errors from these kernels. The only memcheck errors are host API errors raised while flashinfer is imported.

## Related upstream work

sgl-project/sglang#44866 (draft) adds an online acceptance estimator for DSpark's confidence-scheduled verification. It uses the same module path (`srt/speculative/online_acceptance_estimator.py`), the same kernel file (`kernels/ops/speculative/acceptance_estimator.py`) and the same class name, `OnlineAcceptanceEstimator`, so the two cannot both land as they are.

How they differ:
- Model: both score `sigmoid(slope * logit(q_max) + intercept[position])`.
- Fit: sgl-project/sglang#44866 bins observations by (position, feature bin, label) with a decayed history and runs several Newton iterations with a batched line search every 100 steps. This PR keeps exact per-observation IRLS statistics for the round and takes one damped Newton step, with the slope backtracking above.
- Wiring: sgl-project/sglang#44866 wires DSPARK (a `--speculative-dspark-confidence-source` argument, with the trained head used when present) and also changes compact padding rows to a point mass. This PR has no caller; DFLASH uses it through https://github.com/sgl-project/sglang/pull/46190.

What to do: if sgl-project/sglang#44866 lands first, drop this PR and move https://github.com/sgl-project/sglang/pull/46190 onto its estimator. The DFLASH wiring needs a feature and a prediction computed inside the draft CUDA graph and one observe call per real verify step, with no host synchronization, so its estimator has to keep that contract.
