# [Feat] wan2.2-s2v: Add Wan2.2-S2V-14B speech-to-video (port of #21609)

[Upstream PR](https://github.com/sgl-project/sglang/pull/43279) · state: open · merged: False

## Original PR description

## Motivation

Adds Wan2.2-S2V-14B (speech-to-video) to sglang-diffusion. This is a port of #21609 by @mickqian (closed) onto a recent main (`1e86143bf0`), with the changes to shared files reduced so that other models keep their behaviour. @mickqian is co-author of the commit.

## Modifications

One commit. The commit message lists every change; in short:

- **New S2V model:** DiT (`dits/wan_s2v.py`), wav2vec2 audio encoder + loader, `WanS2VBeforeDenoisingStage`, pipeline + configs, the `S2V` task type, `--audio-encoder-cpu-offload`.
- **Shared files, kept main-compatible:**
  - `parallel_executor.py`: `MAIN_RANK_ONLY` is unchanged. The S2V stage uses `MAIN_RANK_ONLY_AND_SEND_TO_OTHERS` and opts in (`PipelineStage.relocate_broadcast_batch`, default `False`) to moving the received batch's device tensors and generators, with their state, to the local device.
  - `t5.py`: `RMSNorm` for every T5 model. Only S2V sets the new `T5ArchConfig.reference_layer_norm` (a plain-PyTorch `T5LayerNorm`), because its stage can run T5 on the host. With a layerwise-offloaded T5 the stage feeds the device.
  - Audio mux: main's ffmpeg arguments. `select_output_audio()` no longer cuts a stereo `[N, 2]` / `(2, L)` track to one row.
  - `WanI2V480PConfig` keeps main's VAE flags; no `skip_decode_scale_and_shift` hook.
  - `AutoencoderKLWan._remap_official_state_key` is added for the S2V overlay's materializer, which converts the official `Wan2.1_VAE.pth`.
- The ref/motion/pose latents are normalized `(z - mean) / std`, as in Wan2.2's `WanVAE.encode`.

**Known limitation:** the S2V stage places its text and audio encoders itself (no `component_uses()`), so an explicit offload request for either fails with `ComponentResidencyError`. The default policy, `--component-residency text_encoder=resident` and `--audio-encoder-cpu-offload` work.

**Not in this PR (follow-ups):** taking the last wav2vec2 layer from `last_hidden_state`. On transformers >= 5.17, `hidden_states[-1]` is pre-LayerNorm, which loses lip sync. Also XPU-side speedups (fp32 RoPE, fused segmented modulation, minimal-copy Ulysses exchange).

## Accuracy Tests

Wan2.2-S2V-14B, 704x1024x81, seed 42, image + `talk.wav`, SP=2 Ulysses unless noted:

- **2x A100-40GB (CUDA, torch 2.13.0+cu130), 3 steps:** the stack this commit starts runs 2/2 requests with lip sync r +0.51 (p < 0.001); SP=2 vs SP=1 PSNR at the same-code level. A run of this commit alone is in progress; results will be added here.
- **Shared code on CUDA, no checkpoint:**
  - every changed module imports;
  - default T5 output is bit-identical to main;
  - the 2-GPU NCCL check: main's rank 1 receives the broadcast batch on `cuda:0`, and this PR relocates every tensor and generator to `cuda:1`; a rank-0 error reaches every rank;
  - audio mux on 9 shapes: all non-stereo outputs identical to main, stereo kept 2-channel.
- **2x Intel Arc B60 (XPU):** 40-step runs of earlier revisions of this stack match same-code reruns at their noise floor.

## Speed Tests and Profiling

2x A100, 3 steps, warm request, with the follow-up commits applied: denoise ~99.5 s at SP=2 vs ~188 s at SP=1 (1.89x). Numbers for this commit alone will be added with the run above.
