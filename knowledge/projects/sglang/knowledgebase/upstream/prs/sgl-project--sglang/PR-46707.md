# [Fix] hicache: Restore sidecars to every Mamba destination

[Upstream PR](https://github.com/sgl-project/sglang/pull/46707) · state: closed · merged: False

## Original PR description

## Motivation

A Mamba host-cache hit can restore the same checkpoint into both a radix-cache slot and an active request's preallocated slot. A derived sidecar (`indices_from_pool=MAMBA`) currently follows only the first matching transfer, leaving the active request's side state stale.

For example, host slot 2 contains `30` and must initialize device slots 4 and 7. Before this fix, the sidecar leaves those slots as `[30, -1]`; afterward they are `[30, 30]`.

## Modifications

- Resolve derived sidecars against all matching source transfers, preserving host/device pairs and the single-source path.
- Sum repeated source transfers when accounting for sidecar bytes.
- Add a registered CPU regression using the real `MambaComponent.build_hicache_transfers()` and `HybridCacheController.load()` paths. It simulates the queued data copy on CPU, checks untouched slots, allocation ownership, and byte accounting, and covers either sidecar ordering with and without an active request.

## Accuracy Tests

On unmodified upstream `c43abd6d9e38a14e81bdb77c648a06353e1c10ee`, the new regression reports **2 failed, 2 passed**: both active-request cases fail and both single-destination controls pass. With the fix, all four pass.

After refreshing onto upstream `5008726431`, the regression and existing staged-transfer suite report **33 passed, 1 skipped, 8 subtests passed**. No model weights or GPUs are needed for this repro.

```bash
PYTHONPATH=python python -m pytest -q \
  test/registered/unit/mem_cache/test_hicache_sidecar_restore.py \
  test/registered/unit/mem_cache/test_hicache_staged_write_back_dispatch.py
```

## Speed Tests and Profiling

No performance claim; this fixes missing state copies and transfer-byte accounting.
