# [Fix] diffusion: LoRA merge cache key identity and eviction

[Upstream PR](https://github.com/sgl-project/sglang/pull/45834) · state: closed · merged: True

## Original PR description

## Motivation

Split from #44309 (adapter-state fixes stay there). The LoRA merge cache could serve stale merged weights and mishandle several paths.

## Changes

- Key on the resolved local adapter file (name, resolved name, size, mtime, inode) plus the per-adapter effective alpha and loaded PEFT config, so an alpha change, `use_rslora` or `alpha_pattern` edit, or a different file from the same repo gets its own store. Bare module names no longer resolve against the cwd.
- The cache merge runs once after all adapters are set, so it also covers layers the last adapter skips.
- A failed `put()` removes only its temp file, not the previous entry.
- Admission evicts least recently used stores when disk headroom is short; adopting a store marks it recently used.

## Tests

No new files. Extended `test_lora_merge_cache.py` and `test_lora_pipeline.py` (existing CPU-backed cache test now asserts key identity). The 3 new/extended tests fail on `main` and pass here, plus a deterministic low-space eviction test.

Modal CPU, LoRA unit files: 65 passed in the targeted run. ruff, isort, codespell clean. No GPU run.
