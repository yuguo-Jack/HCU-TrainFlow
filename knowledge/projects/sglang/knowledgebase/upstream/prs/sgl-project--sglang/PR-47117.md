# [Doc] [AMD] glm-5.2: PD disaggregation on MI355X with the Infera router

[Upstream PR](https://github.com/sgl-project/sglang/pull/47117) · state: open · merged: False

## Original PR description

## Motivation

SemiAnalysis InferenceX requires every SGLang submission's production configuration, including the router and the prefill/decode launch commands of a disaggregated deployment, to be documented in the SGLang cookbook before the InferenceX PR merges. This adds that documentation for an AMD MI355X submission, `glm5.2-fp4-mi355x-infera-sglang-agentic-disagg` ([InferenceX #4629](https://github.com/SemiAnalysisAI/InferenceX/pull/4629), draft): `amd/GLM-5.2-MXFP4` served as prefill/decode disaggregation behind [Infera](https://github.com/AMD-AGI/Infera)'s KV-aware router.

The workers are SGLang's own server. Infera's launcher (`python3 -m infera.engine.sglang`) forwards every SGLang flag unchanged and registers the worker in etcd; the router discovers workers there, routes prefill on the cached prefix each worker reports through SGLang's ZMQ KV events, keeps a session on one prefill worker, and balances decode DP ranks. This is the same split as the Dynamo entries on this page (a deployment layer in front of `sglang.launch_server` flags), and it follows the hand-written MI355X PD section of the DeepSeek-V4 page (§3.7) rather than the generated AgentX block, which covers NVIDIA submissions.

**Draft** until:
- Infera 0.3.2 is published with the `infera-router` binary in its wheel, the router's `--decode-request-weight`, and [AMD-AGI/Infera#222](https://github.com/AMD-AGI/Infera/pull/222) (the worker advertises a caller-supplied `--kv-events-config` port);
- the deployment is re-run on the stock image below with these commands;

## Modifications

`docs/cookbook/autoregressive/GLM/GLM-5.2.mdx`: new **§3.6 PD Disaggregation on MI355X with the Infera Router**:
- image (`lmsysorg/sglang-rocm:v0.5.22-rocm720-mi35x-20261018`), RDMA container flags and the Infera install (`--no-deps`, so the image's packages are untouched);
- the three shapes (1P1D with an 8-GPU decode, 1P with a 4-GPU decode, 2P1D), with TP1 × PP4 prefill, write-back HiCache at 250 GB per stage, TP + DP-attention decode and EAGLE 5-1-6 on both roles;
- etcd, shared environment, prefill, decode and router commands in launch order;
- why `--disable-custom-all-reduce`, `--disable-overlap-schedule`, `MC_MAX_MR_SIZE` and the HiCache size matter here;
- a note listing the open SGLang fixes the stock image still needs for this deployment: #21194 / #47184 (PP stages without the embedding), #46830 and #33059 (DP-attention decode on gfx950), #46820 (KV-metrics backpressure).

Excluded as InferenceX-only harness settings: simulated MTP acceptance (`SGLANG_SIMULATE_ACC_*`) and the benchmark client's environment.

## Accuracy Tests

Docs only. The configuration was measured with these flags on an MI355X image that carries the fixes above: GSM8K 0.9666 (strict) / 0.9674 (flexible) on 1P1D with real MTP acceptance. A run on the stock image is pending (see Draft).

## Speed Tests and Profiling

Docs only. On that image, AgentX (3,600 s per point, simulated acceptance 3.61): 1P1D 31,088 tok/s/GPU at C88, 1P + 4-GPU decode 37,310 at C80, 2P1D 38,392 at C176. InferenceX will publish its own measurement.
