# [Doc] cookbook: point NVFP4 checkpoint references at nvidia repos

[Upstream PR](https://github.com/sgl-project/sglang/pull/45724) · state: open · merged: False

## Original PR description

## Summary

The NVFP4 checkpoints for Qwen3.8-2.4T-A95B, Qwen3.8-27B (FP4 head), GLM-5.3 and GLM-5.3-Flash are published under the `nvidia` org on Hugging Face. This updates the cookbook to reference those instead of the RadixArk copies (existence of each `nvidia/*` repo verified via the HF API).

- Qwen3.8 / GLM-5.3 pages and config snippets: single reference points, straight swap to the `nvidia/*` repo ids.
- Qwen3.8-27B: the NVIDIA export is the same W4A4 body as the previous FP4-head entry (identical tensor set, 21.9 GB), so the duplicate `NVFP4-NVIDIA` quant option, its four per-card cells, and the extra model-table row merge into the FP4-head entry, which now points at `nvidia/Qwen3.8-27B-NVFP4`. Surrounding prose and sweep-count wording adjusted to match.
- GLM-5.3-Flash weights cell: deduplicated to list only `nvidia/GLM-5.3-Flash-NVFP4`.

Left unchanged:
- `RadixArk/Qwen3.8-27B-NVFP4-BF16-LMHead` and `RadixArk/Muse-Glimmer-NVFP4` — no `nvidia` counterpart exists.
- The Qwen3.8-Flash-Next and GLM-5.3-Flash RadixArk exports — these are distinct quantization artifacts documented side by side with NVIDIA's (different ModelOpt builds, separately measured benchmark rows), not mirrors.

## Verification

- `node docs/scripts/check_cookbook_configs.mjs` passes.
- Pre-commit passes.
- Grepped all remaining `RadixArk/*NVFP4` references in `docs/`: only the intentional keep-list above remains.
