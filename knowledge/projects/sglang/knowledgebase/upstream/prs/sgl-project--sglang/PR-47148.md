# [Perf] dsv41: Run MegaGate routing in prefill

[Upstream PR](https://github.com/sgl-project/sglang/pull/47148) · state: closed · merged: True

## Original PR description

Runs MegaGate routing in prefill again. #46232 added it and #46242 reverted it, because with MegaGate on extend batches the breakable prefill graph capture failed with `CUDA error: unspecified launch failure`. #46719 records graph breaks at capture without running them, which removes that failure.

- `should_use_mega_gate` also takes extend batches (draft extend keeps the regular router), up to MegaMoE's per-rank token cap `SGLANG_OPT_DEEPGEMM_MEGA_MOE_NUM_MAX_TOKENS_PER_RANK`, the size of the buffer the routing and the Mega-mHC input go to. Decode and target verify use the same cap instead of 2048 rows.
- `test_mega_moe_deepgemm_api.py` covers extend, target verify and draft extend, and the row cap.

Still behind `SGLANG_OPT_DEEPGEMM_MEGA_GATE=1`; without it nothing changes.

## Verification

- DeepSeek-V4.1-Flash on GB300, DP attention 4 with MegaMoE, breakable prefill graphs at 4096 and 8192 tokens, `SGLANG_OPT_DEEPGEMM_MEGA_GATE=1`: with this change on main, all four ranks capture both shapes and the server starts. The same change on the parent of #46719 fails the capture with `unspecified launch failure` (also on B300), and captures with MegaGate off.
- The MegaGate admission tests pass.
- Prefill step time and accuracy with MegaGate on are not measured here.
