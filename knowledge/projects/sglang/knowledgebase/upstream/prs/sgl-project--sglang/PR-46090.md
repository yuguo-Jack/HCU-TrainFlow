# [Perf] moe: Fold the routed scaling factor into the mega MoE pre-dispatch

[Upstream PR](https://github.com/sgl-project/sglang/pull/46090) · state: closed · merged: True

## Original PR description

## Motivation

When `routed_scaling_factor != 1`, `run_mega_routed_experts` scales the top-k weights with a separate elementwise kernel. Right after that, the JIT `mega_moe_pre_dispatch` copies those same weights into the Mega MoE symmetric buffer. That is one extra small launch on the decode critical path for every MoE layer.

## Modifications

- `mega_moe_pre_dispatch` takes `topk_weight_scale`, and the kernel applies it with `__fmul_rn` while copying the weights. It is the same single fp32 multiply, so the result is bitwise identical to the standalone multiply.
- `run_mega_routed_experts` passes `routed_scaling_factor` for the JIT pre-dispatch path. It keeps the explicit multiply for the nvfp4xnvfp4 and mxf4xmxf4 paths, which use DeepGEMM's own pre-dispatch.
- The `routing_in_buffer` path still asserts `routed_scaling_factor == 1.0`, so it is unchanged.
- A new `test_mega_moe_pre_dispatch.py` case checks the scaled copy against the separate multiply bit for bit.

## Validation

- DeepSeek-V4.1-Flash, DEP4, Mega MoE, on a CC 10.7 node: weights bitwise identical, and GSM8K unchanged.
- Small decode throughput gain, measured together with a sibling mHC change, so it is not isolated.
