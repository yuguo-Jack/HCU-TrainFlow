# [Perf] engram: Read host-table rows in address order on GPUs without host page tables

[Upstream PR](https://github.com/sgl-project/sglang/pull/45879) · state: closed · merged: True

## Original PR description

- `engram_gather` takes `sort_ids`: it sorts the ids, reads the rows in address order and stores each row at its original position. Output is bitwise identical.
- `EngramEmbedding` turns it on for host tables only when `CU_DEVICE_ATTRIBUTE_PAGEABLE_MEMORY_ACCESS_USES_HOST_PAGE_TABLES` is 0, i.e. the GPU maps pinned host memory in its own page tables (PCIe hosts). On NVLink-C2C hosts the attribute is 1, reads go through the host page tables, sorting only adds work, and the path is unchanged. Device tables and HIP are unchanged. No new flag.
- Why: random rows spread over a host table far larger than the GPU's address-translation reach miss on nearly every row; the same rows read in address order share pages, which makes the host-table lookup several times faster on PCIe hosts.

No behavior change except the order of host-table reads on GPUs without host page tables.

Verification: bitwise-equal gather output; DeepSeek-V4.1-Flash DEP4 with host Engram tables on a PCIe host is faster in prefill, and on an NVLink-C2C host the path is not taken (throughput unchanged); GSM8K unchanged.
