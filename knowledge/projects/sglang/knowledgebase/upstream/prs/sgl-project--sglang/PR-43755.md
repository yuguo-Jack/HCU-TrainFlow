# [AMD] Reject balancedness reporting with the MegaMoE prefill-only EPLB recorder (fixes prefill hang)

[Upstream PR](https://github.com/sgl-project/sglang/pull/43755) · state: closed · merged: False

## Original PR description

Reject `--expert-balancedness-report-mode` together with the MegaMoE prefill-only EPLB recorder. Today this combination silently hangs prefill on the first request.

## Motivation

On ROCm, `--moe-a2a-backend megamoe` + `SGLANG_AITER_MEGA_EPLB_PREFILL_ONLY=1` + `SGLANG_AITER_MEGA_RANK_SYNC=1` (#35619), combined with `--expert-balancedness-report-mode != off` (#34998), hangs prefill on the first batch that does not reach every DP rank, e.g. the health check.

The prefill-only recorder decides per rank whether to record a pass, and IDLE ranks skip it. Balancedness reporting, however, calls `torch.distributed.reduce` on every recorded pass (`_append_utilization_rate`). Only the ranks that recorded the pass enter the collective, so it never completes. EPLB without reporting is unaffected: it only all-reduces at rebalance time, and that runs in lockstep.

## Modifications

- `check_mega_moe_compat` rejects the combination with a clear error.
- Regression test in `test/registered/unit/eplb/test_megamoe_prefill_recorder.py` (fails on `main`).

Follow-up, not in this PR: make every rank join the per-pass reduce (keyed on `is_extend_in_batch`, contributing zeros), or compute balancedness from the window at `dump()` time. Either would also unblock `--eplb-min-rebalancing-utilization-threshold` with this recorder.
