# [Feat] [CPU] quantization: Add CPU FP8/INT8 quant ops and compressed-tensors support

[Upstream PR](https://github.com/sgl-project/sglang/pull/41329) · state: open · merged: False

## Original PR description

## Motivation

Add CPU (Xeon / AMX) support for the FP8 and INT8 quantization utilities and the compressed-tensors linear schemes that use them, so CPU execution goes through in-tree `sgl_kernel` CPU kernels (or torch-native code where not on the hot path) instead of falling into CUDA/Triton-only paths.

This PR supersedes #41330 (CPU INT8), merged here per review.

## Modifications

### FP8 quant ops (`python/sglang/kernels/aot/csrc/cpu/fp8_quant.cpp`)
New CPU ops, named after their CUDA counterparts (`<cuda_op>_cpu`):

| CPU op | CUDA counterpart | Notes |
|---|---|---|
| `sgl_per_token_group_quant_8bit_cpu(input, group_size, eps)` | `sgl_per_token_group_quant_8bit` | FP8 (e4m3) output, bf16 input |
| `sgl_per_token_quant_fp8_cpu(input)` | `sgl_per_token_quant_fp8` | dynamic per-token |
| `sgl_per_tensor_quant_fp8_cpu(input, scale?)` | `sgl_per_tensor_quant_fp8` | `scale` given → static, otherwise dynamic per-tensor |
| `mxfp8_group_quantize_cpu(input)` | — (Triton on CUDA) | group 32, UE8M0 scales |

- Schemas are functional (return tensors), matching existing CPU ops; outputs never alias inputs.
- Kernel structure: `at::parallel_for` on the outer loop, shared row helpers (`absmax_row` / `quantize_row_fp8`); `#if CPU_CAPABILITY_AVX512` only wraps the 16-wide vector body, and the scalar loop handles the remainder (and is the full fallback without AVX512).
- bf16 / fp16 / fp32 inputs supported for per-token, per-tensor and MXFP8; results are bit-exact with the torch reference `clamp(x / scale).to(fp8)`.
- Fake impls registered in `cpu_graph_runner.py` (`register_cpu_compile_fake`) for CPU graph / torch.compile.

### Python dispatch
- `fp8_kernel.py`: CPU branches for `per_token_group_quant_fp8`, `static_quant_fp8` (ndim >= 2 inputs are flattened and restored), and `scaled_fp8_quant` (`num_token_padding` handled in Python, as in the CUDA path).
- `fp8_utils.py`: CPU branch for `mxfp8_group_quantize`.
- `int8_kernel.py`: CPU `per_token_quant_int8` uses a torch-native implementation (it is not on the CPU hot path, since the AMX GEMMs quantize activations internally), so it has no K-alignment constraint.

### compressed-tensors schemes on CPU
- **W8A16 FP8**: routed to the existing `fp8_per_tensor_scaled_mm_cpu` AMX kernel instead of the Marlin path (`apply_fp8_marlin_linear` depends on GPU/Marlin packing). Per-tensor single-scale weights are supported; fused layers with multiple per-shard scales are rejected explicitly for now.
- **W8A8 FP8**: explicitly raises `NotImplementedError` on CPU (the CPU FP8 GEMM here is W8A16).
- **W8A8 INT8**: per-tensor scales are requantized to a single max scale, per-channel scales are used as-is, weights are packed via `_amx_process_weight_after_loading`, and the linear runs through `int8_scaled_mm_with_quant`. Static input scales, asymmetric activations, and AMX-unpackable weights are rejected explicitly instead of silently changing semantics.

## Tests

`test/registered/cpu/test_quant_ops.py`, registered under `stage-a-test-cpu-intel`:
- FP8 ops: bit-exact vs torch reference over bf16/fp16/fp32 and non-16-aligned K (1x7, 5x129, 33x4096); group quant with a remainder (group 40); MXFP8; static quant with 3D input; `num_token_padding`.
- `torch.library.opcheck` (schema + fake tensor) for all new ops.
- compressed-tensors W8A16 FP8 CPU path, multi-scale rejection, W8A8 FP8 unsupported.
- `per_token_quant_int8` CPU contract (dtype / shape / scale / `cal_sum`, including K=33).
- compressed-tensors W8A8 INT8 AMX path (per-channel and per-tensor scales), plus rejection of unpacked weights, static input, and asymmetric input.
