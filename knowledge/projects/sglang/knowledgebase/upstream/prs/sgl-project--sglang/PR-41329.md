## Motivation

Add CPU support for FP8 quantization utilities used by compressed-tensors FP8 paths. This enables CPU/Xeon execution to use in-tree `sgl_kernel` CPU kernels for FP8 activation/weight quantization instead of falling through unsupported CUDA/Triton-only paths.

## Modifications

- Added CPU AOT kernels for:
  - `per_token_group_quant_fp8_cpu`
  - `scaled_fp8_quant_cpu`
  - `mxfp8_group_quantize_cpu`
- Registered the new CPU ops in `torch_extension_cpu.cpp`.
- Routed CPU dispatch in FP8 quantization helpers:
  - `per_token_group_quant_fp8`
  - `static_quant_fp8`
  - `scaled_fp8_quant`
  - `mxfp8_group_quantize`
- Added CPU handling for compressed-tensors FP8 schemes:
  - W8A16 FP8 supports CPU per-tensor single-scale weights.
  - W8A16 FP8 explicitly rejects fused layers with multiple weight scales for now.
  - W8A8 FP8 explicitly raises `NotImplementedError` on CPU, since the CPU kernels added here are W8A16-only.
  - For W8A16 FP8 compressed-tensors linear on CPU, this PR does not use the Marlin FP8 helper. `apply_fp8_marlin_linear` is a GPU/Marlin execution path and depends on Marlin-specific kernel/packing assumptions. On CPU, the validated backend is the existing `fp8_per_tensor_scaled_mm_cpu` AOT kernel, so the CPU branch routes W8A16 FP8 linear directly to that kernel.
- Added CPU unit tests covering the new quant ops, padding behavior, MXFP8 quantization, W8A16 FP8 CPU path, W8A16 multi-scale rejection, and W8A8 unsupported behavior.
