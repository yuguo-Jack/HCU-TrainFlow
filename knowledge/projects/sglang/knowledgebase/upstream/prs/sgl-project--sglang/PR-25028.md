# [NPU] Support Longcat Flash for NPU

[Upstream PR](https://github.com/sgl-project/sglang/pull/25028) · state: closed · merged: False

## Original PR description

## Motivation

This PR adds Ascend NPU support for `LongCat-Flash` and `LongCat-Flash-NextN`.

## Modifications

- Add explicit NPU interleaved RoPE handling for LongCat attention.
- Add NPU-specific zero-expert handling for LongCat MoE.
- Fix LongCat NPU weight/layout handling for `w_vc`.
- Update scheduler MoE initialization for configs using `moe_topk`.
- Support dp-attention, deepep, and double stream.

### Code review

Found 4 issues:

1. `_DOUBLE_STREAM_EP` is initialized unconditionally in `initialize_model_parallel()` for **all models**, using whatever `group_ranks` was last assigned in the preceding `_MOE_TP`/`_MOE_EP` block — not a topology computed for this group. Additionally, `destroy_model_parallel()` never resets `_DOUBLE_STREAM_EP`, so the `assert _DOUBLE_STREAM_EP is None` assertion will fire on every re-initialization (e.g., in test suites).

https://github.com/sgl-project/sglang/blob/332a59592f8fd43b7ba15a69dfd945067d8f5f4c/python/sglang/srt/distributed/parallel_state.py#L2023-L2031

2. `SGLANG_ENABLE_LONGCAT_DOUBLE_STREAM` is a new private env-var gate in `environ.py`, which the branch CLAUDE.md explicitly prohibits: *"Do not add V4-only staged-rollout env gates. Recent commits explicitly removed `SGLANG_DSV4_NPU_REAL_COMPRESSOR`-style flags; if you need conditional behavior, gate on config/server args, not on private env vars."*

https://github.com/sgl-project/sglang/blob/332a59592f8fd43b7ba15a69dfd945067d8f5f4c/python/sglang/srt/environ.py#L331-L333

3. `longcat_flash_nextn.py` sets `use_explicit_npu_interleaved_rope = True` and the flag on `rotary_emb`, but never calls `sync_explicit_npu_interleaved_cache()`. The corresponding block in `longcat_flash.py` does call it. `update_and_get_cos_sin_cache()` raises `RuntimeError("Explicit NPU interleaved RoPE cache is not initialized")` if `cos_cached_total` is `None`, so the NeXTN model will crash on the first NPU decode step.

https://github.com/sgl-project/sglang/blob/332a59592f8fd43b7ba15a69dfd945067d8f5f4c/python/sglang/srt/models/longcat_flash_nextn.py#L148-L150

4. `mla_preprocess.py` adds a `hasattr(self.q_b_proj, 'weight_scale')` guard for `q_b_proj_weight_scale`, but `preprocess_weights()` unconditionally accesses `self.q_b_proj.deq_scale` and `self.q_b_proj.quant_bias` without equivalent guards. If `weight_scale` is absent (non-quantized LongCat), `deq_scale` is likely also absent, causing an `AttributeError` crash in `preprocess_weights()`.

https://github.com/sgl-project/sglang/blob/332a59592f8fd43b7ba15a69dfd945067d8f5f4c/python/sglang/srt/hardware_backend/npu/attention/mla_preprocess.py#L61-L64

Thanks for catching these issues. Here are the proposed fixes and explanations:Initialization Gate: I will update initialize_model_parallel() so that _DOUBLE_STREAM_EP is gated and only initialized when longcat double stream is explicitly enabled.Config/Server Arg: I will remove the private environment variable SGLANG_ENABLE_LONGCAT_DOUBLE_STREAM and replace it with a proper server argument/config parameter.Sync Cache/Precision: The cache is already initialized in the main model. Re-initializing it in the draft model would cause precision issues. I will ensure the draft model skips re-initialization.Quantization Guard: preprocess_weights() is designed specifically for MLAPO, which is a W8A8-quantization-only feature. I will add a proper check to ensure this function is only executed for quantized configurations.
