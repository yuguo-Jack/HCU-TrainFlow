# [Fix] scheduler: Count retracted output tokens as uncached HRRN work

[Upstream PR](https://github.com/sgl-project/sglang/pull/44867) · state: open · merged: False

## Original PR description

## Motivation

`SchedulePolicy._uncached_len` sizes a waiting request by its uncached tokens, and `_sort_by_hrrn` divides by that value when it builds the response ratio (`ratio_delta = waited_tokens / uncached`). The helper returns:

```python
return max(0, len(r.origin_input_ids) - r.num_matched_prefix_tokens)
```

`r.output_ids` is missing from the minuend, but `num_matched_prefix_tokens` is produced against `origin_input_ids + output_ids`: `_compute_prefix_matches` builds `prefix_ids = r.origin_input_ids + r.output_ids` and matches that, and `match_kv_cache` caps the result with `_compute_max_prefix_len(len(token_ids))`. The two sides of the subtraction therefore measure spans of different length.

For a fresh request `output_ids` is empty and the expression is correct, which is why this only shows up for requests that already generated tokens. It matters when such a request is retracted back into the waiting queue: `reset_for_retract` clears the matched prefix but keeps `output_ids` — it discards them only when `input_embeds is not None` — so those tokens have to be prefilled again. HRRN then underestimates the remaining work by `len(output_ids)`, which makes the response ratio too large and admits the request earlier than its real cost warrants.

The sibling helper `_shortest_prefill_work` in the same file already counts both spans:

```python
return max(1, len(r.origin_input_ids) + len(r.output_ids) - r.num_matched_prefix_tokens)
```

When the underestimation is large enough the clamped result reaches 0, and `_sort_by_hrrn` treats `uncached <= 0` as having no prefill work left (`return (-float("inf"), rid)`), so the request is ordered ahead of the queue.

## Modifications

- `python/sglang/srt/managers/schedule_policy.py`: `_uncached_len` now measures by `r.seqlen`, which is defined as `len(origin_input_ids) + len(output_ids)`. One line changed; no new helper, no signature change, and no difference for requests whose `output_ids` is empty.

- `test/registered/unit/managers/test_schedule_policy.py`: one regression test added to the existing `TestSchedulePolicyHRRN` class. It puts a retracted request (90 output tokens, 90 matched) and a fresh request (same origin length, same matched count) through `_sort_by_hrrn`; the retracted one has more work left and must sort second.
