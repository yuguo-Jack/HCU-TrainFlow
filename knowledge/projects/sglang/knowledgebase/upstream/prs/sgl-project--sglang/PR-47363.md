# [DSV4] Use the shared memory budget for dense prefill

[Upstream PR](https://github.com/sgl-project/sglang/pull/47363) · state: open · merged: False

## Original PR description

Supersedes #40967, which was closed for inactivity.

## Motivation

The V4.1 eager prefill indexer still sizes dense scores against a fixed 2 GiB allowance. The sparse publisher also keeps its preceding logits and block keys alive while allocating the next score tile.

## Changes

- Resolve the existing free-memory-aware workspace allowance lazily, once per forward, and share it across indexer layers and the late-layer tail.
- Include candidate-selection scratch when sizing row-aligned tiles in the current `v41_indexer` implementation.
- Release sparse-publisher logits and block keys before requesting the next tile.
- Keep small forwards free of a synchronizing memory query and use the helper's static allowance during capture.

The index scoring and selection kernels, dtypes and arithmetic are unchanged.

## Validation

The budget resolver and candidate-scratch calculator have identical function ASTs to the original PR. Their call sites are adapted to the current indexer layout. Python syntax and undefined-name checks pass. No full suite or GPU validation was rerun after the upstream merge.
