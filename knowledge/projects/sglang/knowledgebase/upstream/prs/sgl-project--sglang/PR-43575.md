# [diffusion] FLUX: declare regional compile regions

[Upstream PR](https://github.com/sgl-project/sglang/pull/43575) · state: closed · merged: True

## Original PR description

## Motivation

`FluxTransformer2DModel` inherits the empty `_compile_conditions` from `BaseDiT`, so `--enable-torch-compile true --regional-compile true` on FLUX.1 fails at startup:

```
ValueError: regional compile found no matching submodules; check FluxTransformer2DModel._compile_conditions
```

## Modifications

Declare the regions: every `FluxTransformerBlock` (double-stream) and `FluxSingleTransformerBlock` (single-stream), 57 for FLUX.1-dev.

## Accuracy Tests

Same modules, same compile mode as whole-model compile; only the compile granularity changes.

## Speed Tests and Profiling

GB300, FLUX.1-dev 1024², 50 steps, TP2, served. Median of 5 requests after 2 warmups, fresh server per arm, 2 interleaved rounds. NUMA-bound workers (#43565) and compile fixes applied in all arms.

| Arm | Round 1 | Round 2 |
|---|---|---|
| eager | 4.06 s | 3.86 s |
| whole-model compile | 4.03 s | 3.93 s |
| regional compile (this PR; failed to start before) | 3.70 s | 3.90 s |

Startup log: `Enabled regional torch.compile for 57 submodules in FluxTransformer2DModel`. The remaining graph breaks in both compile modes are the TP all-reduce (`Communicator.get_world_size` is not traceable), which is a follow-up.
