# [Fix][VLM] Enable local SHM with skip_tokenizer_init

[Upstream PR](https://github.com/sgl-project/sglang/pull/43828) · state: open · merged: False

## Original PR description

## Motivation

Single-node multimodal requests using `--skip-tokenizer-init` bypass shared-memory feature transport. Both `wrap_shm_features()` and `unwrap_shm_features()` return early based on tokenizer initialization, even though local SHM availability depends on node topology. This causes CPU features and precomputed embeddings to be serialized inline for token-ID-only requests, increasing IPC payloads and host-memory pressure during repeated multimodal requests.

## Modifications

- Remove the `skip_tokenizer_init` condition from both SHM helpers and remove the unused serving-config import.
- Preserve `_get_is_default_transport()`, including its `nnodes > 1` protection.
- Add a registered CPU regression test covering exact Tensor round trips, precomputed hashes, batched requests, SHM cleanup, and both tokenizer settings on single-node and multi-node layouts.
- Remove obsolete serving-config mocks from existing SHM ownership and error-consensus tests.

## Accuracy Tests

The new regression test fails on the unmodified upstream code for both single and batched requests with `skip_tokenizer_init=True`. It passes after the fix.

The following tests passed against the modified upstream checkout: **13 tests and 13 subtests**. The round-trip tests assert exact Tensor values; the existing suite also exercises two-process SHM ownership and failure consensus.

```bash
python -m pytest -q -p no:cacheprovider \
  test/registered/unit/multimodal/test_shm_feature_transport.py \
  test/registered/unit/multimodal/test_tensor_transport_mode.py \
  test/registered/unit/managers/test_mm_shm_error_consensus.py
```

## Speed Tests and Profiling

No end-to-end serving benchmark was run. This change enables the existing SHM path for CPU multimodal tensors when tokenizer initialization is skipped.
