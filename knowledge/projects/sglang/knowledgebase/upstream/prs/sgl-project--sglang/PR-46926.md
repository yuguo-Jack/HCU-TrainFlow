# [Chore] deps: Bump FlashInfer to 0.7.2.post1

[Upstream PR](https://github.com/sgl-project/sglang/pull/46926) · state: open · merged: False

## Original PR description

## Summary

Bump FlashInfer from 0.7.2 to 0.7.2.post1 ([release notes](https://github.com/flashinfer-ai/flashinfer/releases/tag/v0.7.2.post1)): the `flashinfer_python` pin, the `flashinfer-cubin` / `flashinfer-jit-cache` version in both Dockerfiles, and the runtime version check in `engine.py`.

post1 carries Rubin (SM107) MoE, GEMM, GDN and attention support and tuning, the Muse-Spark-Open fused normalization and MoE communication kernels, FP8-output MNNVL all-reduce, StepFun clamped SwiGLU in TRT-LLM-Gen MoE, and the `uniform_q_len` prefill planner hint (flashinfer-ai/flashinfer#6144) that #44115 wires up.

## Compatibility

- No dependency floor changes: FlashInfer's `requirements.txt` is identical between v0.7.2 and v0.7.2.post1.
- Every `from flashinfer... import ...` in sglang resolves the same against both tags. Public exports only gained names, and the changed signatures sglang calls only add keyword arguments.
- `fast_prefill_plan` in `flashinfer_backend.py` calls the native paged-prefill `plan` positionally; that native signature is unchanged (20 arguments, `uniform_q_len` already last). The new wrapper state that `run()` reads is initialized in `__init__`.
- Picked up without code changes: the MNNVL CuTe DSL all-reduce fusion now finds FlashInfer's shipped Kimi K3 profiles (hidden 7168, top_k 16, TP4/TP8) in `DEFAULT_CONFIG`, so `_config_for_shape` uses them instead of re-targeting the GB300 presets.
- Still not in this release: flashinfer-ai/flashinfer#5666 (needed by #39832), #6415/#6416 (#45905) and #5726 (#40539).

## Validation

- `scripts/release/bump_flashinfer_version.py 0.7.2.post1` updates and validates all 4 pin files.
- `uv pip compile python/pyproject.toml` (py3.12, x86_64, cu130 torch index) before and after: the only resolved change is `flashinfer-python` 0.7.2 -> 0.7.2.post1.
- `flashinfer-cubin==0.7.2.post1` and `flashinfer-jit-cache==0.7.2.post1` (cu129 and cu130, x86_64 and aarch64), plus every per-arch jit-cache package, are published on flashinfer.ai/whl.
- Repository pre-commit hooks.

GPU model E2E tests were not run locally; relying on CI.

### Why the jit-kernel shard times out

- **Every runner starts cold.** SGLang's JIT build key includes the installed `flashinfer-python` version (`_VERSIONED_PACKAGES` in `python/sglang/kernels/jit/utils/compile/cache.py`). This bump therefore invalidates every SGLang JIT kernel, including ones that don't use FlashInfer. The cache lives on each runner's disk. The three attempts landed on three different H100 slots, so each one started with an empty cache.
- **The extra time is one MoE case.**
  - `test_compressed_tensors_fp4_numeric.py` took 723–741 s here.
