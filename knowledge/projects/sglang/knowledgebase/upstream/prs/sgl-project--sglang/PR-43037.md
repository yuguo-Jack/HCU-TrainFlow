# [Spec] Allow Qwen3.5 backends to opt into packed target verification

[Upstream PR](https://github.com/sgl-project/sglang/pull/43037) · state: closed · merged: True

## Original PR description

## Motivation

Qwen3.5 passes packed QKVZ and BA projections to the attention backend only during decode. During speculative target verification, the model always unpacks them first, preventing a backend from owning the fused projection-unpack/Conv1D boundary even when it supports that operation.

## Modifications

Allow the active linear-attention backend to opt into packed target-verification inputs with `supports_packed_verify = True`, resolving through `linear_attn_backend` for hybrid backends. The backend receives `(projected_states_qkvz, projected_states_ba)` and must return `(core_attn_out, z)`, following the existing packed-decode contract.

The existing fusion flag and tensor-input guards still apply. Missing or false capability flags retain the unpacked verification path; decode and prefill routing are unchanged. No upstream backend is opted in by this PR.

## Accuracy Tests

Applicable pre-commit hooks passed, including isort and Ruff; `git diff --check` passed. Full-model accuracy was not run.

## Speed Tests and Profiling

No benchmark or speedup claim: this PR exposes the backend capability without adding a packed-verification kernel or enabling one by default.
