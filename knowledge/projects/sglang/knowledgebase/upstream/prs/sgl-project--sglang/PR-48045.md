# feat: port Muse Spark Open support to sglang-miles

[Upstream PR](https://github.com/sgl-project/sglang/pull/48045) · state: open · merged: False

## Original PR description

## Summary
Bring the remaining Muse Spark Open support into `sglang-miles` for Miles RL.

## Motivation
Miles needs the serving-side weight-update and weight-checking support carried on the Muse Spark Open branch. The current `sglang-miles` already contains the base model and kernels, but lacks the remaining integration from that support commit.

## Usage
For a running Muse Spark Open server using the standard expert path, reload a compatible checkpoint through the existing API:
```bash
curl -X POST http://localhost:30000/update_weights_from_disk \
  -H 'Content-Type: application/json' \
  -d '{"model_path":"/checkpoints/updated/Muse-Spark-Open-816B-A42B"}'
```
The update refreshes derived weight state without restarting the server. Optional Helion verify banks reject online updates and require restart.

## Design Notes
- **Mental model:** A weight update reaches the model loader, which preserves checkpoint-layout tensors while refreshing backend-specific repacks and norm caches so subsequent inference uses the new weights.
- **Provenance:** Cherry-pick the remaining changes from [bc1c2ac7dfc52d9e3a61e8967266050bf94de1a6](https://github.com/sgl-project/sglang/commit/bc1c2ac7dfc52d9e3a61e8967266050bf94de1a6), including `MuseSparkTextForCausalLM` weight updates, ParameterMapper, ROCm/AITER integration and opt-in Helion verify kernels.
- **Adaptation:** Port only the residual changes onto current kernel paths while preserving existing multimodal/CPU/scheduling behavior and initializing shared loader metadata for the affected target-branch subclasses.

## Verification
- Static checks at `d5f16a38d5de`: AST parsing of 83 Python files, Ruff `F821,F811,F401` and `git diff --check` passed.
- `test_params_mapping.py`: 42 original mapping vectors passed through a source-level probe; runtime/model imports were excluded.
- Selected pytest files failed collection on missing `orjson` and a partial-import `KeyError`, so no pytest cases executed.
- GPU, CUDA graph, ROCm and serving/training integration remain untested on this head.

## Review Focus
- Weight layout, derived-cache refresh and parameter-address stability across online updates.
- Shared loader metadata compatibility and optional ROCm/Helion backend gates.
