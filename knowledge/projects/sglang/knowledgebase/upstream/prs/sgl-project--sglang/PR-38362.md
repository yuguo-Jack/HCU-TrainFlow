# [Fix] hicache: Isolate Mooncake KV objects by storage dtype via tenant_id

[Upstream PR](https://github.com/sgl-project/sglang/pull/38362) · state: open · merged: False

## Original PR description

## Motivation

Two SGLang instances sharing a Mooncake store with the same model and backend tag can generate identical object keys even when their persisted KV values use different dtypes. A later instance can then load cache bytes in the wrong format.

This change isolates Mooncake objects by the host pool's persisted KV value dtype using `tenant_id`, while preserving the existing object keys and model/backend prefixes.

## Modifications

- Add `get_storage_dtype()` to host pools. Typed host buffers declare their own dtype. Raw-copy FP8 buffers preserve E4M3, E5M2, and E4M3FNUZ even when backed by `uint8`; unified page envelopes report the mirrored stored K/V dtype. Logical anchors with no KV payload declare no value dtype.
- Populate `HiCacheStorageConfig.kv_cache_dtype` from the storage host anchor. The allocation facade does not need a dtype, and the controller does not assume that the device dtype describes the persisted values.
- Compose tenants such as `dtype_bfloat16` and `tenant-a_dtype_float8_e4m3fn`. Reuse the existing setup, tenant compatibility checks, and SSD fallback handling.
- Document the Mooncake client, master quota policy, and matching standalone-client requirements.

The master must enable `--enable_multi_tenants=true` and register the composed tenants in its quota policy. Without this mode, Mooncake uses the default object namespace and does not enforce dtype isolation. An external standalone client must use the matching `--tenant_id`. A client that does not support `tenant_id` fails with an upgrade hint rather than silently dropping isolation.

## Accuracy Tests

Local validation: **40/40 Mooncake CPU unit tests passed** on Python 3.12 / PyTorch 2.14.1. The tests exercise real host dtype methods without allocating GPU buffers, and mock Mooncake clients. Coverage includes host/device dtype differences, raw FP8 encodings, unified page envelopes, logical anchors, tenant composition, unchanged object keys, old-client rejection, SSD fallback, group semantics, and standalone buffers.
