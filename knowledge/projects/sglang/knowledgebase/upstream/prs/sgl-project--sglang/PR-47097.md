# [Fix] dflash: Give the draft a private RoPE module

[Upstream PR](https://github.com/sgl-project/sglang/pull/47097) · state: open · merged: False

## Original PR description

## Motivation

We observed an illegal memory access in speculative serving with a Qwen3.5-family target and a DSpark draft. The underlying issue affects the DFlash/DSpark attention path when target and draft resolve to the same cached RoPE module and the draft replaces its cache after target CUDA Graph capture. Replay can then read stale storage, producing incorrect results or an illegal memory access. This does not imply that every Qwen3.5 + DFlash/DSpark configuration is affected.

`get_rope()` caches `RotaryEmbedding` modules by their arguments. A draft that retains matching partial/M-RoPE configuration from the target can receive the same module in `DFlashAttention`. The complete resolved cache key must match; sharing a `partial_rotary_factor` alone is insufficient. The relevant capture/forward order is:

1. The target's fused QK-norm/RoPE kernel (`fused_qk_gemma_rmsnorm_rope_gate`, Qwen3.5) reads `rotary_emb.cos_sin_cache` (fp32) directly, and that read is captured in the target's CUDA graphs.
2. A subsequent BF16 draft forward takes the CUDA `MRotaryEmbedding` path and calls `_match_cos_sin_cache_dtype()`, replacing `cos_sin_cache` with a bf16 copy. If no other owner retains the old fp32 tensor, its allocation can be released and reused.
3. Target graph replay still uses the captured pointer; it does not re-read the updated Python attribute. Reusing the old allocation can expose incorrect results or an illegal access. Replay may happen to compare equal while the old contents remain intact, which does not make the lifetime safe.

The sequence can occur serially in one process; concurrent requests are not required. The verified trigger is the NVIDIA CUDA BF16 M-RoPE path. Ordinary partial RoPE at head dimension 256 did not replace the cache in our tests; other hardware paths are not assumed to have the same dtype-conversion behavior.

### Model-free repro

The script below builds a random-init `DFlash2DraftModel` with a Qwen3.5-style partial + M-RoPE config, captures the real target kernel in a CUDA graph, runs one bf16 draft RoPE forward, lets the allocator reuse the freed block, then replays. Results on L20, torch 2.14.1+cu130, main @ `9d2dae3`:

The model-free reproducer deliberately encourages reuse of the freed allocation to expose the stale-pointer read; it does not introduce the cache-sharing or cache-replacement behavior. It uses the real draft constructor and target fused kernel without loading target weights or requiring private model artifacts.

| | main | this PR |
| --- | --- | --- |
| draft shares the target's RoPE module | yes (`MRotaryEmbedding`) | no |
| target `cos_sin_cache` replaced by the draft | yes, fp32 → bf16 | no |
| graph replay vs. eager reference | diverges (reads reused memory) | bit-exact |

<details><summary>repro script</summary>

```python
import torch
from transformers import PretrainedConfig

from sglang.kernels.ops.attention.fused_qk_rmsnorm_rope_gate import fused_qk_gemma_rmsnorm_rope_gate
from sglang.srt.models import dflash
from sglang.srt.runtime_context import get_context, get_parallel

HEADS, KV_HEADS, HEAD_DIM, T = 8, 2, 256, 16
config = PretrainedConfig(
    hidden_size=1024, intermediate_size=512, num_hidden_layers=2,
    num_attention_heads=HEADS, num_key_value_heads=KV_HEADS, head_dim=HEAD_DIM,
    vocab_size=64, rms_norm_eps=1e-6, hidden_act="silu", max_position_embeddings=4096,
    rope_theta=1e7, partial_rotary_factor=0.25,
    rope_scaling=dict(rope_type="default", mrope_section=[11, 11, 10], mrope_interleaved=True),
    dflash_config=dict(block_size=4, selector_rank=2, selector_top_k=2, target_layer_ids=[0, 2],
                       conv_kernel_size=2, conv_group_size=2),
)

shared, real_get_rope = [], dflash.get_rope
dflash.get_rope = lambda *a, **k: shared.append(real_get_rope(*a, **k)) or shared[-1]
with get_context().override_server_args(), \
        get_parallel().override(tp_size=1, tp_rank=0, tp_group=None), torch.device("cuda"):
    draft = dflash.DFlash2DraftModel(config)
dflash.get_rope = real_get_rope
target_rope, draft_rope = shared[0], draft.layers[0].self_attn.rotary_emb

q_gate = torch.randn(T, HEADS * 2 * HEAD_DIM, device="cuda", dtype=torch.bfloat16)
k = torch.randn(T, KV_HEADS * HEAD_DIM, device="cuda", dtype=torch.bfloat16)
w = torch.randn(HEAD_DIM, device="cuda", dtype=torch.bfloat16) * 0.1
pos = torch.arange(T, device="cuda") * 37
step = lambda: fused_qk_gemma_rmsnorm_rope_gate(
    q_gate, k, w, w, target_rope.cos_sin_cache, pos, 1e-6,
    HEADS, KV_HEADS, HEAD_DIM, target_rope.rotary_dim, has_gate=True)

ref = [t.clone() for t in step() if t is not None]
s = torch.cuda.Stream(); s.wait_stream(torch.cuda.current_stream())
with torch.cuda.stream(s):
    step()
torch.cuda.current_stream().wait_stream(s)
g = torch.cuda.CUDAGraph()
with torch.cuda.graph(g):
    out = step()

draft_rope(pos, torch.randn(T, HEADS * HEAD_DIM, device="cuda", dtype=torch.bfloat16),
           torch.randn(T, KV_HEADS * HEAD_DIM, device="cuda", dtype=torch.bfloat16))
junk = [torch.full((target_rope.cos_sin_cache.numel(),), float("nan"), device="cuda") for _ in range(8)]
g.replay(); torch.cuda.synchronize()
print("shared:", draft_rope is target_rope, "| target cache dtype:", target_rope.cos_sin_cache.dtype,
      "| replay matches:", all(torch.equal(a, b) for a, b in zip([t for t in out if t is not None], ref)))
```

## Modifications

- `python/sglang/srt/models/dflash.py`: wrap the draft's `get_rope()` result in `_draft_private_rope()`, which deep-copies the shared module. The copy is cached per shared module in a process-wide weak cache: drafts alive at the same time share one copy (isolated from the target, not from each other), and all layers of a draft share that copy.
  - The copy is held through a `weakref.ref` keyed (weakly) by the shared module, so it is freed once its last holder is gone.
  - A cached copy whose buffers were killed by a teardown (moved to meta, or storage freed) is rebuilt, mirroring `get_rope()`'s own cache. Meta-device construction passes keep sharing one meta copy.
- `python/sglang/srt/layers/rotary_embedding/factory.py`: factor the dead-buffer check out of `_get_live_rope_cache_entry()` into `dead_rope_buffer()`, with no behavior change, so both caches use the same rule.
- `test/registered/unit/spec/test_dflash_draft_private_rope.py` (CPU: `base-a-test-cpu`; CUDA: `base-b`, `1-gpu-small`):
  - the draft no longer aliases the target module, and the draft's dtype cast leaves the target's `cos_sin_cache` object and pointer intact;
  - the private copy is released after its last holder is gone;
  - a dead copy is rebuilt (meta / freed storage);
  - a meta-device construction pass shares one copy, and the real build afterwards gets a live one.

## Accuracy Tests

The patch isolates mutable RoPE state without intentionally changing the draft's mathematical operations. Component-level verification used L20, torch 2.14.1+cu130, flashinfer 0.7.2 + cubin 0.7.2, and sglang-kernel 0.4.10. The regression, component-numerics, and repeated-reproducer artifacts were retained:

- Draft RoPE outputs vs. an independent copy of the same module: bit-exact, for plain RoPE and M-RoPE, on CPU (`forward_native`) and on CUDA in bf16 with 1-D and 3-row M-RoPE positions.
- Fixed-input numerics + CUDA graph: 18 configurations on each of baseline and candidate (36 independent process runs total). The target `fused_qk_gemma_rmsnorm_rope_gate` is captured in a graph, followed by one draft bf16 RoPE forward and replay. With the fix, all 18 configurations are bit-exact vs. the eager reference on the pristine fp32 cache, with no NaN/Inf or target cache pointer/dtype changes. The regression tests additionally assert unchanged target cache identity and values.
- Without the fix (baseline), M-RoPE: the target's cache is replaced (fp32 -> bf16) in 12/12 cases, and 9 of them replay differently from the reference (max abs err 3.4-10.4). The remaining 3 also had their cache replaced (eager on the new cache differs from the fp32 reference by 1.6e-2 - 3.1e-2) but happened to compare equal on the reported outputs; they are not counted as passing.
- Plain partial RoPE at head 256 does not hit this path: the default CUDA kernel does not cast the cache, so its 6 cases match the reference on baseline too.
- The model-free reproducer was also repeated in fresh processes: baseline diverged in 5/5 runs (exit 1); candidate matched the reference in 5/5 runs (exit 0).

### Supporting observations from an earlier run

The greedy serving comparison, concurrency-8 serving observations, and memory/timing measurements below were measured in an earlier run. Their raw artifacts were lost during an environment rebuild, and these measurements have not been repeated in the archived validation run. We report them as supporting observations, separately from the retained regression and component-level evidence above.

Serving-level check (a Qwen3.5-family target + DSpark draft, greedy, 8 prompts x 256 tokens, per-token logprobs):

- With this PR, CUDA graph vs. eager: all 2048 generated tokens identical, max logprob difference 0.0.
- Repeatability check: the same server queried twice gave 8/8 identical outputs for this sample.
- Baseline eager vs. candidate eager: 0/8 identical, first divergence at token 6-230, max logprob difference 0.228 on the common prefix. This is consistent with the cache-dtype effect demonstrated by the component check (baseline's eager target output differs from the fp32 reference by 1.6e-2 - 3.1e-2). The component result supports that explanation, but does not by itself establish the sole cause of the full-model sequence differences.

Scope: component-level numerics plus the serving observations above. No GSM8K/MMLU run and no full-logits comparison against a reference implementation; no claim of unchanged whole-model accuracy.

Stability: the original serving reproduction crashed with `illegal memory access` on the first target prefill. The fixed run completed 8/8 requests at concurrency 4 (retained results). The earlier concurrency-8 run reported 64/64 completed requests (raw artifacts lost, as noted above).

## Speed Tests and Profiling

No kernel or scheduling change. The measurements in this section come from the earlier run whose raw artifacts were lost, as noted above.

Memory (L20, `max_position=262144`, 3-layer draft, 3 rounds): construction-time `allocated` goes from 242.1 MiB to 306.1 MiB, i.e. **+64 MiB**, exactly one fp32 `cos_sin_cache` (262144 x 64 x 4 B). At `max_position=4096` the delta is +1 MiB. One copy is shared by all draft layers and by drafts alive at the same time, so the delta is per shared RoPE module, not per draft.

RoPE forward (bf16, T=16 / T=256, CUDA events, 5 x 1000 calls after 50 warmup): recorded medians were ~141-148 us on baseline vs ~139-147 us with this PR. The observed ranges overlap. An unrelated GPU load generator was running on the same device; this is not a controlled estimate of the performance delta and does not establish absence of a regression.

Serving: no throughput A/B was completed. Three of six planned runs completed before the interruption (baseline, candidate, candidate); reported mean acceptance lengths were 4.5234 vs 4.5251 / 4.5575, with no errors. This small sample does not establish acceptance-rate equivalence. No serving throughput or latency numbers are claimed.
