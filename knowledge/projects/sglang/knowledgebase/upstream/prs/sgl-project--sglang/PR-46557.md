# [Feat] logprobs: Allow flat output top logprobs on streaming /generate

[Upstream PR](https://github.com/sgl-project/sglang/pull/46557) · state: open · merged: False

## Original PR description

## Motivation

`return_flat_raw_output_top_logprobs` (#42890) rejects `stream=True`, because the flat arrays are only built on the finished response. Serving frontends that always talk to SGLang over a stream (for example a proxy that forwards native `/generate` requests and needs incremental tokens for routing, cancellation or migration) cannot request the flat format at all, even though the final chunk could carry it.

`return_routed_experts` already works this way: intermediate chunks carry nothing and the final chunk carries the full per-token payload. This PR gives flat output top logprobs the same contract.

## Modifications

- `GenerateReqInput._validate_inputs`: drop the `stream=True` rejection.
- `TokenizerManager.convert_logprob_style` already emits no output top logprobs before the request finishes and the flat fields (covering every output position) on the finished chunk; only the comment changes.
- `_slice_streaming_output_meta_info`: with incremental streaming, do not slice `output_top_logprobs` for flat-output requests. That key appears only on the final chunk, when unrepresentable rows fall back to the nested format, and it then covers every position, so slicing it to the last chunk would drop rows.
- Tests: the rejection test becomes an acceptance test, plus a test for the incremental fallback slicing.

The OpenAI chat path is unchanged: it still requires `return_meta_info`, which streaming chat rejects.
