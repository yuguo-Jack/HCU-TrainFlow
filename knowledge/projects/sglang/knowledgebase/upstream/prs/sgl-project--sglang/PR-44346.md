# [Feat] [AMD] kimi_k3: Add whole-layer fused KDA backend (gfx950 TP8)

[Upstream PR](https://github.com/sgl-project/sglang/pull/44346) · state: open · merged: False

## Original PR description

## Motivation

On MI355X (gfx950, TP8), the entire Kimi-K3 KDA (Kimi Delta Attention) layer can run as a single fused Gluon op. This PR adds an in-tree backend that routes the KDA layer through the aiter fused ops, replacing an out-of-tree monkeypatch plugin with a clean, flag-gated path.

## What this does

New server arg **`--kimi-kda-fused-layer-backend {native, aiter}`** (default `native`, **no behavior change**):

- **`aiter`** — `KimiK3DeltaAttention.forward` routes the whole KDA layer through the aiter fused ops:
  - **Decode:** one kernel does the QKVG/beta-forget-A projections + conv + single-token gated-delta recurrence + gated RMSNorm + **fused O matmul**, and returns the rank-local O **partial** for the decoder-boundary TP reduce — exactly what `self.o_proj(core)[0]` returns in this config.
  - **Prefill:** the fused ragged-batch gated-delta core, then the native `o_proj` (which owns its TP reduction).
- **Fail-closed:** a static layer-config contract + the aiter op's `*_supported()` gate are checked per forward; any arch / shape / reduce-topology miss falls back to the native per-kernel KDA path. Off gfx950 / pre-3.8 Triton / without the aiter op, nothing changes.

Implementation leaves the native KDA path untouched: the fast path + two helpers on `KimiK3DeltaAttention`, two small public accessors on `KDAAttnBackend` (`fused_kda_layer_state`, `track_fused_decode_state`) that reuse the existing mamba caches and `_track_mamba_state_decode`, and the new arg. The fused prefill reuses the native `forward_qkvbfg_fused` projection instead of duplicating it.

## Dependency

Requires the aiter ops `aiter.ops.triton.kimi_delta_attn.kimi_kda_fused_layer_{prefill,decode}` (separate aiter PR). The backend engages when `do_fuse_qkvbfg` is active for the layer.

## Validation (Kimi-K3, TP8, MI355X gfx950)

- **Correctness:** GSM8K (1319-Q, 5-shot) = **0.978**; aiter ops are bit-identical to the reference kernels across all decode/prefill shapes.
- **Perf:** consistent whole-layer speedup over native (+6–9% tok/s across short/mid context; the decode dispatch routes by batch range to the two kernels that dominate an on-device bake-off, which also beats the per-size dispatch by up to ~20% tok/s at higher concurrency).
- **Default off = inert:** `native` reproduces stock numbers.
