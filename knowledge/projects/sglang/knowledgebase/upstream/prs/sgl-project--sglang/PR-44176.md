# [Fix] dsa: Route mixed-chunk batches to the RAGGED top-k transform for bf16-only sparse prefill

[Upstream PR](https://github.com/sgl-project/sglang/pull/44176) · state: open · merged: False

## Original PR description

## Motivation

With an FP8 KV cache, `--enable-mixed-chunk` kills the DSA backend on the first mixed batch when the prefill backend is `flashmla_sparse`, `flashmla_sparse_q8` or `triton_sparse_mla`. The root cause is one routing predicate: `get_topk_transform_method` returns `TopkTransformMethod.RAGGED` for `ForwardMode.EXTEND` only, and a mixed-chunk batch carries `ForwardMode.MIXED`. The rest of the stack already treats such a batch as an extend-shaped batch (its decode rows are one-token extends with a full prefix), which is exactly how the gap surfaces:

- The eager runner runs a mixed batch as EXTEND (`eager_runner.execute` rewrites the mode), so without a prefill CUDA graph the backend never sees MIXED and nothing fails.
- The prefill CUDA graph runner (breakable, the CUDA default) builds the attention metadata from the real MIXED batch and replays the EXTEND-captured graphs, whose in-graph ops see a static batch with mode EXTEND. The metadata is therefore prepared for PAGED and has no `topk_indices_offset`, while the in-graph indexer asks for the RAGGED transform:

  ```
  RuntimeError: RAGGED topk_transform requires topk_indices_offset; expected extend-without-speculative metadata.
  ```

- Runs that hand MIXED straight to `forward_extend` (context parallel, NPU) take the PAGED path and the bf16-only kernel receives the packed FP8 pool:

  ```
  RuntimeError: kv must have dtype torch::kBFloat16          # flashmla_sparse, flashmla_sparse_q8
  TypeError: sparse_mla_prefill needs a bf16 KV cache, got torch.float8_e4m3fn   # triton_sparse_mla
  ```

The gap was pointed out by @ch-wan in the review of #32779 as a pre-existing issue shared with `flashmla_sparse`; this PR fixes it for all three backends.

## Modifications

`get_topk_transform_method` routes `ForwardMode.MIXED` exactly like `ForwardMode.EXTEND` for these three prefill impls (an FP8 pool, or `flashmla_sparse_q8` with any pool since #41790), so the metadata the backend builds from a MIXED batch agrees with what the EXTEND-replaying graph ops, and the eager runner, expect. Nothing else changes: the extend branch of `init_forward_metadata` already builds `page_table_1_flattened` and `topk_indices_offset` for MIXED (it enters through `is_extend()`), and the indexer already runs its ragged top-k for MIXED (`is_extend_without_speculative()`), with the transform method as a parameter. FP8-native impls (`flashmla_kv`, `flashinfer_sparse_mla`, `trtllm`) and bf16 pools keep PAGED in both modes, which is why they never hit this. Born-fp8 q for `flashmla_sparse_q8` stays EXTEND-only; a MIXED batch reaches the q8 helper on the bf16-q hand-off, which casts. The q8 launch validator used to refuse `--enable-mixed-chunk` because a MIXED batch took PAGED; that refusal, its parameter and its test case are removed, and the `forward_extend` message for q8 now names the two shapes that remain unsupported (SPLIT_PREFILL, DLLM_EXTEND).

The alternative, building the replay metadata from the mode-rewritten static batch inside the prefill graph runner, would change every attention backend's replay contract to fix a predicate that only this backend has; the backend-local change keeps `get_topk_transform_method` consistent with the backend's own `is_extend()` branches.

Cost: a RAGGED mixed batch dequantizes the batch's whole ragged KV (`sum(seq_lens)` tokens) per layer, the same work a chunked EXTEND with prefixes already does, now including the decode rows' contexts. That is the price of running a bf16 kernel on an FP8 pool; `flashmla_kv` (main's default for FP8 KV on SM90) is unaffected. Numbers below.

```python
"""Drive a server into MIXED batches and record greedy outputs.

Eight short natural prompts start first (max_tokens 96) so they are decoding
when, half a second later, one long prompt arrives whose chunked prefill then
mixes with them. Outputs go to a JSON file for cross-server comparison.

Usage: mixed_client.py <base_url> <out.json> [long_len]
"""

import asyncio
import json
import random
import sys
import time

import aiohttp

URL = sys.argv[1].rstrip("/")
OUT = sys.argv[2]
LONG_LEN = int(sys.argv[3]) if len(sys.argv) > 3 else 6000

SHORT_PROMPTS = [
    "The capital of France is",
    "Water boils at a temperature of",
    "In computer science, a hash table is",
    "The theory of general relativity was published by",
    "A sonnet is a poem that has",
    "Photosynthesis converts sunlight into",
    "The largest planet in the solar system is",
    "To sort a list in Python you can call",
]


async def gen(session, payload):
    t0 = time.time()
    async with session.post(f"{URL}/generate", json=payload) as r:
        body = await r.json()
    body["_latency"] = time.time() - t0
    return body


async def main():
    rng = random.Random(1234)
    long_ids = [rng.randint(1000, 60000) for _ in range(LONG_LEN)]
    sampling = {"temperature": 0.0, "max_new_tokens": 96}
    async with aiohttp.ClientSession(timeout=aiohttp.ClientTimeout(total=1800)) as s:
        shorts = [
            asyncio.create_task(
                # No return_logprob: the scheduler skips mixing whenever the running
                # batch or the new batch asks for logprobs (scheduler.py, mixed-style
                # chunked prefill condition), which would hide the very path under test.
                gen(s, {"text": p, "sampling_params": sampling})
            )
            for p in SHORT_PROMPTS
        ]
        await asyncio.sleep(0.5)
        long_task = asyncio.create_task(
            gen(s, {"input_ids": long_ids, "sampling_params": {"temperature": 0.0, "max_new_tokens": 32}})
        )
        short_res = await asyncio.gather(*shorts)
        long_res = await long_task
    out = {
        "short": [
            {
                "prompt": p,
                "text": r.get("text"),
                "output_ids": r.get("output_ids") or (r.get("meta_info") or {}).get("output_token_ids"),
                "completion_tokens": (r.get("meta_info") or {}).get("completion_tokens"),
                "latency": r["_latency"],
            }
            for p, r in zip(SHORT_PROMPTS, short_res)
        ],
        "long": {
            "text": long_res.get("text"),
            "prompt_tokens": (long_res.get("meta_info") or {}).get("prompt_tokens"),
            "latency": long_res["_latency"],
        },
    }
    json.dump(out, open(OUT, "w"), indent=1)
    print("short latencies:", [round(x["latency"], 2) for x in out["short"]])
    print("long: prompt_tokens=%s latency=%.2fs text=%r" % (out["long"]["prompt_tokens"], out["long"]["latency"], (out["long"]["text"] or "")[:60]))
    for x in out["short"]:
        print("  %-48r -> %r" % (x["prompt"], (x["text"] or "")[:70]))


asyncio.run(main())
```

Probe (drop this file as `sitecustomize.py` on the server's `PYTHONPATH`; set `PROBE_REFCHECK=1` for the fp32 row check, which writes its tensors to `DUMP_DIR`):

```python
"""sitecustomize for the mixed-chunk probe.

Counts DSA forward_extend calls per (forward_mode, topk transform, impl,
use_mha, in-graph), logs the first mixed batches by shape (the breakable graph
replays a mixed batch with the static batch's mode, EXTEND), and, with
PROBE_REFCHECK=1, recomputes layer-0 attention in fp32 for the decode rows and
the last chunk rows of the first mixed batches from the KV pool and the top-k
the kernel received, logging cosine / max abs against the kernel's output.
Logs every 200 calls because the servers are stopped with docker stop.
"""

import os
from collections import Counter

_TAG = os.environ.get("PROBE_TAG", "probe")
_REFCHECK = os.environ.get("PROBE_REFCHECK", "0") == "1"
_DUMP = os.environ.get("DUMP_DIR", "/dump")


def _refcheck(self, layer, forward_batch, q, kw, out, method, in_bcg):
    import torch

    from sglang.kernels.ops.attention.dsa.dequant_k_cache import (
        dequantize_k_cache_paged,
    )

    if not self.use_fused_topk:
        print("[REFCHECK %s] skipped: unfused topk" % _TAG, flush=True)
        return
    topk_indices = kw.get("topk_indices")
    q_rope = kw.get("q_rope")
    if topk_indices is None:
        print("[REFCHECK %s] skipped: no topk_indices" % _TAG, flush=True)
        return
    h = layer.tp_q_head_num
    T = q.shape[0]
    if q_rope is None:
        q_all = q.reshape(T, h, -1)
    else:
        q_all = torch.cat([q.reshape(T, h, -1), q_rope.reshape(T, h, -1)], dim=-1)
    d_qk = q_all.shape[-1]
    d_v = layer.v_head_dim
    out3 = out.reshape(T, h, -1)[:, :, :d_v]
    ext = list(forward_batch.extend_seq_lens_cpu)
    starts = [0]
    for e in ext[:-1]:
        starts.append(starts[-1] + e)
    decode_rows = [s for s, e in zip(starts, ext) if e == 1]
    ci = max(range(len(ext)), key=lambda i: ext[i])
    chunk_rows = list(range(starts[ci] + ext[ci] - 4, starts[ci] + ext[ci]))
    pool = self.token_to_kv_pool.get_key_buffer(layer.layer_id)
    md = self.forward_metadata
    pt = topk_indices.reshape(T, -1)
    kv_ragged = None
    if method == "RAGGED":
        kv_ragged = dequantize_k_cache_paged(pool, md.page_table_1_flattened).reshape(
            -1, d_qk
        )

    def ref_row(t):
        idx = pt[t]
        idx = idx[idx >= 0].long()
        if kv_ragged is not None:
            K = kv_ragged[idx].float()
        else:
            K = dequantize_k_cache_paged(pool, idx.to(torch.int32)).reshape(-1, d_qk).float()
        p = torch.softmax(q_all[t].float() @ K.T * layer.scaling, dim=-1)
        return p @ K[:, :d_v], int(idx.numel())

    rec = {"rows": [], "out": [], "ref": [], "nvalid": [], "group": []}
    for group, rows in (("decode", decode_rows), ("chunk", chunk_rows)):
        cos_min, mabs_max = 1.0, 0.0
        for t in rows:
            ref, nvalid = ref_row(t)
            o = out3[t].float()
            cos = torch.nn.functional.cosine_similarity(o.flatten(), ref.flatten(), dim=0).item()
            mabs = (o - ref).abs().max().item()
            cos_min, mabs_max = min(cos_min, cos), max(mabs_max, mabs)
            rec["rows"].append(t); rec["out"].append(o.cpu()); rec["ref"].append(ref.cpu())
            rec["nvalid"].append(nvalid); rec["group"].append(group)
        print(
            "[REFCHECK %s] layer=%d %s rows=%d (%s, %s, %s): min cosine %.8f, max abs %.3e, ref |x| max %.3e"
            % (_TAG, layer.layer_id, group, len(rows), method, self.dsa_prefill_impl,
               "bcg" if in_bcg else "eager", cos_min, mabs_max,
               max(r.abs().max().item() for r in rec["ref"][-len(rows):]) if rows else 0.0),
            flush=True,
        )
    torch.save(rec, "%s/%s_refcheck_l%d_%d.pt" % (_DUMP, _TAG, layer.layer_id, os.getpid()))


def _install():
    from sglang.srt.layers.attention.dsa_backend import DeepseekSparseAttnBackend
    from sglang.srt.model_executor.runner_backend_utils.breakable_cuda_graph.context import (
        is_in_breakable_cuda_graph,
    )

    counts = Counter()
    state = {"n": 0, "mixed_logged": 0, "checked": 0}
    orig = DeepseekSparseAttnBackend.forward_extend

    def forward_extend(self, q, k, v, layer, forward_batch, *a, **kw):
        mode = forward_batch.forward_mode.name
        method = self.get_topk_transform_method(forward_batch.forward_mode).name
        in_bcg = is_in_breakable_cuda_graph()
        key = (mode, method, self.dsa_prefill_impl, bool(self.use_mha), "bcg" if in_bcg else "eager")
        counts[key] += 1
        state["n"] += 1
        ext = forward_batch.extend_seq_lens_cpu or []
        looks_mixed = mode == "MIXED" or (len(ext) > 1 and max(ext) > 1 and min(ext) == 1)
        if looks_mixed and state["mixed_logged"] < 3 and layer.layer_id == 0:
            state["mixed_logged"] += 1
            print(
                "[PROBE %s] MIXED batch: mode=%s extend_seq_lens=%s prefix_lens=%s method=%s impl=%s use_mha=%s %s"
                % (_TAG, mode, ext, forward_batch.extend_prefix_lens_cpu, method,
                   self.dsa_prefill_impl, self.use_mha, "bcg" if in_bcg else "eager"),
                flush=True,
            )
        if state["n"] % 200 == 0:
            print("[PROBE %s] counts=%s" % (_TAG, dict(counts)), flush=True)
        out = orig(self, q, k, v, layer, forward_batch, *a, **kw)
        if (
            _REFCHECK and looks_mixed and layer.layer_id == 0
            and state["checked"] < 2 and not self.use_mha
        ):
            state["checked"] += 1
            try:
                _refcheck(self, layer, forward_batch, q, kw, out, method, in_bcg)
            except Exception as exc:  # the check must never take the server down
                print("[REFCHECK %s] failed: %r" % (_TAG, exc), flush=True)
        return out

    DeepseekSparseAttnBackend.forward_extend = forward_extend
    print("[PROBE %s] hook installed (refcheck=%s)" % (_TAG, _REFCHECK), flush=True)


try:
    _install()
except Exception as exc:  # never take the server down
    print("[PROBE %s] hook install failed: %r" % (_TAG, exc), flush=True)
```

The two bf16 kernels land at the same distance from the fp32 recomputation as the FP8-native `flashmla_kv` control, i.e. bf16 output rounding (max error ~0.3% of the largest value); these rows are from the merged tree in the 2026-10-14 image, and the 2026-10-06 tree gave the same figures. `flashmla_sparse_q8` computes attention in FP8 (q and KV cast to e4m3 with identity scales), so its rows sit at that kernel's own precision: on plain extend chunks without mixed chunk, the same check gives the same figures (min cosine 0.99978, max abs 6.7e-04 on the chunk rows, against 0.99999845 / 3.1e-05 for `flashmla_sparse` on the same chunks), so the mixed batch adds nothing to the q8 error. Its decode rows sit lower (0.988) because they attend over a dozen keys, where FP8 rounding of P and V does not average out; note that this is the price of sending decode rows through the q8 prefill kernel, which only `--enable-mixed-chunk` does, and that without this PR the configuration does not start at all. The second mixed batch of each run, which fits a graph bucket and replays in-graph, gives the same figures.

Greedy outputs across servers are not a usable metric for this change: the no-mixed `flashmla_sparse` server reproduces its own eight short continuations exactly on a rerun (8/8), but every mixed server agrees with it on only 0-2 of the 8 (first divergence after 0-9 tokens), including the FP8-native `flashmla_kv` control and the eager-prefill `flashmla_sparse` run, neither of which this PR changes. Merging a 4088-token chunk with the decode rows changes the MoE GEMM shapes those rows run under, and on this FP8 stack that is enough to flip near-tie tokens. The row-level check above is the one that isolates the kernel.

## Speed Tests and Profiling

Latency (the eight short prompts, 96 tokens each / the 12000-token prompt): `flashmla_sparse` mixed 5.04 s / 3.88 s, `triton_sparse_mla` mixed 3.78 s / 2.62 s, `flashmla_kv` mixed 5.07 s / 3.92 s, `flashmla_sparse` without mixed chunk 5.08 s / 3.86 s and 4.89 s / 3.68 s on a rerun. With three chunks the decode rows only gain three tokens during the prefill, so mixing does not move these numbers; the dequant cost described above is inside the noise here.
