# [Fix] deepseek: Write the MLA latent cache through store_mla on out-of-tree platforms

[Upstream PR](https://github.com/sgl-project/sglang/pull/47352) · state: open · merged: False

## Original PR description

## Motivation

On CUDA, `DeepseekMHAForwardMixin._set_mla_kv_buffer` writes the prefill latent cache with the KV layer's `store_mla`, which calls `set_mla_kv_buffer` on the layer's pool or view. Other non-NPU devices take a fallback: they slice-assign `kv_a` and a clone of `k_pe` into `latent_cache`, then call `store`, which goes to `set_kv_buffer`.

Out-of-tree platforms supply their MLA pool through `get_kv_pool_cls(kind="mla")`, as a subclass of `MLATokenToKVPool`. They can override `set_mla_kv_buffer` to own the latent-cache write. The fallback never reaches that method, so such an override is skipped for this path.

## Modifications

Take the `store_mla` branch on out-of-tree platforms too. In-tree platforms are unchanged.

This needs no capability check: the default `set_mla_kv_buffer` already picks the Triton kernel or the torch-native scatter (`set_mla_kv_buffer_naive`) from `capabilities.supports_triton`.

## Accuracy Tests

On an out-of-tree platform, DeepSeek-R1-0528 (TP8) GSM8K (5-shot, flexible-extract) is 0.9651 in graph mode (reference 0.9651 +/- 0.0107). DeepSeek-R1-0528 (TP8) in eager mode and GLM-5.2-FP8 (TP8) in graph mode also pass.
