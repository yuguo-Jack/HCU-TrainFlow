# [Feat] kv-indexer: Add shared DRAM pools for worker prefix matching

[Upstream PR](https://github.com/sgl-project/sglang/pull/46995) · state: open · merged: False

## Original PR description

## Motivation

Several workers can read the same UMBP DRAM pool. Store that residency once under a pool identity and credit it to every member. Companion owner implementation: https://github.com/ROCm/mori/pull/851. Either PR can merge first; enabling shared-pool reporting requires both implementations.

## Modifications


Add optional `dram_pool_id` to mutation requests: with `worker_id` it binds a member; without a worker it identifies the DRAM owner. Queries combine worker HBM and pool DRAM using each worker's FULL/SWA/MAMBA rules. Clear/revoke remain scoped to their sender. Bridges refresh pool membership every 30s so idle workers recover after an Indexer restart. Prefix matching fails closed for all workers whose supplied cache spec omits FULL or contains unknown component bits, including workers outside shared pools. Specs generated by the bridge satisfy these checks.

One pool per worker, one owner per pool, with compatible model/page/key layouts. Private DRAM/SSD is ignored while joined; callers must clear obsolete private snapshots before detaching. No fencing, TTL or HBM replay.

## Validation

132 Indexer tests, Rustfmt and all-target Clippy passed. Joint validation with the simplified MoRI owner passed shared lookup and byte readback for five bridge/client pairs, eviction, clear isolation, reinsertion, partial-component composition and quiet restart recovery. An external probe used 800,000 pages with synthetic residency and the real Indexer; all 347 sampled queries retained shared hits during concurrent registration and repair. Real DeepSeek-V4-Pro-0813 validation passed on one exclusive 8-GPU MI355X node: TP4 offload, shared lookup for five workers, and byte-verified restores on all four DP-attention ranks (8,192 host-cached tokens each). HBM flush, quiet Indexer restart (17.06s recovery), owner clear/reinsert, and 48 requests at concurrency 8 with 8K–32K inputs passed. Uses content-stable `triton` SWA with optional fused inverse-RoPE disabled; request-private `unified_kv_triton` SWA was not covered.

CI: synced with main to include the upstream lint fix in #47078. Router CI requires `run-ci`; AMD Extra additionally requires `run-ci-extra`.
