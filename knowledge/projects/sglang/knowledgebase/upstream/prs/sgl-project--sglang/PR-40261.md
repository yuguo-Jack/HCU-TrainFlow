# [Perf] Accept int64 array input_ids in TokenizerManager without re-copying

[Upstream PR](https://github.com/sgl-project/sglang/pull/40261) · state: closed · merged: False

## Original PR description

## Motivation

`TokenizerManager._create_tokenized_object` always runs `array("q", input_ids)`, which walks the input and allocates a fresh int64 array for every request, even when the caller already holds a typecode-`q` array. Callers that receive token ids from a binary buffer (for example an Engine fed by an external router) currently pay for this second copy on every request.

## Modifications

Pass `input_ids` through unchanged when it is already an `array` with typecode `"q"`. Lists, tuples, and arrays of any other typecode still go through the converting constructor, so existing callers see no change.

## Accuracy Tests

Not applicable: no change to model forward or outputs.

## Speed Tests and Profiling

No benchmark included. The change only skips a redundant copy for callers that already hold an int64 array and is a no-op for all other callers.
