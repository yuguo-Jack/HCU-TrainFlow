# [Fix] [KDA] cookbook: add MoE runner backend to Muse Spark BF16 recipes

[Upstream PR](https://github.com/sgl-project/sglang/pull/45422) · state: closed · merged: True

## Original PR description

## Motivation

This PR is powered by [KDA](https://github.com/NVlabs/kda) team. The Muse Spark BF16 recipes for B300, GB300 and B200 in the cookbook enable `--enable-layernorm-sp --enable-megamoe-for-layernorm-sp` but do not set a MoE runner backend. For Muse Spark, `python/sglang/srt/arg_groups/layernorm_sp_hook.py` requires `--moe-runner-backend flashinfer_trtllm` whenever layer-norm SP is enabled, so these recipes fail at startup:

ValueError: Muse Spark --enable-layernorm-sp requires --moe-runner-backend flashinfer_trtllm.

The NVFP4 recipes already pass the flag.

## Modifications

Add `--moe-runner-backend flashinfer_trtllm` to the three BF16 cells (B300, GB300, B200) of `docs/src/snippets/configs/meta-models/muse-spark.jsx`, in the same position as in the NVFP4 cells. No code changes

## Accuracy Tests

GB300 BF16 recipe (2x GB300, TP8/EP8) with this flag, GSM8K via sgl-eval (1319 questions, temperature 0, reasoning effort xhigh, max tokens 8192, 8 runs): 93.65%.

Without the flag the server does not start, so there is no "before" number.

## Speed Tests and Profiling

Not applicable: this PR only makes the BF16 recipes launch.

Tested on GB300 only: as written, the GB300 BF16 recipe fails at startup; with this flag it starts and serves. B300 and B200 were not tested because we had no access to those GPUs. They go through the same unconditional check in `layernorm_sp_hook.py`, so they should fail the same way without the flag.
