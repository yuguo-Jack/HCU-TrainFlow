# [AMD] Loosen quark MXFP4 MoE gsm8k thresholds to their observed spread

[Upstream PR](https://github.com/sgl-project/sglang/pull/42061) · state: closed · merged: False

## Original PR description

## Motivation

Two GSM8K thresholds in `test_quark_mxfp4.py` sit inside the normal run-to-run spread of the scores they check, so `stage-b-test-1-gpu-small-amd-mi35x` fails on them regularly with no code change. #41793 has failed on this file four times in a row and never reached its own test:

| Attempt | Failing test | Scores (try, retry) | Threshold |
|---|---|---|---|
| [2](https://github.com/sgl-project/sglang/actions/runs/36653184760/attempts/2) | `TestFP8ToMXFP4MOETP1` | 0.904, 0.910 | 0.92 |
| [3](https://github.com/sgl-project/sglang/actions/runs/36653184760/attempts/3) | `TestFP8ToMXFP4MOETP1` | 0.912, 0.918 | 0.92 |
| [4](https://github.com/sgl-project/sglang/actions/runs/36653184760/job/110158770073) | `TestFP8ToMXFP4MOETP1` | 0.912, 0.912 | 0.92 |
| [5](https://github.com/sgl-project/sglang/actions/runs/36653184760/job/110210253573) | `TestNVFP4ToMXFP4MOETP1` | 0.810, 0.822 | 0.85 |

These are not regressions. The PR runs used the same code as a scheduled `main` run that passed. The scores come from the September 2026 PR Test (AMD) scheduled and dispatched runs of this lane, across the rocm700/10/720/724 images. All four images show the same distribution.

| Test | Samples | Mean | Std | Min | Max | First try at or below threshold | Both tries at or below threshold |
|---|---|---|---|---|---|---|---|
| `TestFP8ToMXFP4MOETP1` (0.92) | 101 | 0.924 | 0.009 | 0.900 | 0.946 | 30% | 13% of runs |
| `TestNVFP4ToMXFP4MOETP1` (0.85) | 55 | 0.856 | 0.018 | 0.802 | 0.886 | 31% | 18% of runs |

The retry re-scores on the same server, so it rarely rescues a low first try. Together the two tests fail the lane in about 30% of runs. Because the suite stops at the first failure, every file after this one (19 of 49) is skipped too.

Notes on the original comments:
- The `~0.948` on `TestFP8ToMXFP4MOETP1` is the FP8 checkpoint's own score. Requantizing to MXFP4 costs about 2.5 points, so 0.92 was within one standard deviation of the requantized mean when it was added.
- The `~0.88` on `TestNVFP4ToMXFP4MOETP1` is above what CI measures.

## Modifications

| Test | Threshold before | Threshold after | Distance below mean |
|---|---|---|---|
| `TestFP8ToMXFP4MOETP1` | 0.92 | 0.89 | 3.8 standard deviations |
| `TestNVFP4ToMXFP4MOETP1` | 0.85 | 0.79 | 3.7 standard deviations |

Both new thresholds are below every score observed in September, and the comments now record the observed spread. A real requantization bug still trips them. A broken MXFP4 MoE path lands far below either value, not a few points lower.

Nothing else in the file changes. The other thresholds already have enough margin; for example, the Dense TP1/TP2 tests check 0.868 against observed scores of 0.88-0.908.
