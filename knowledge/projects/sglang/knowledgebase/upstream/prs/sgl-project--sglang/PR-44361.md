# [Fix] [AMD] kimi-k3: Drop symmetric memory under graph capture on ROCm

[Upstream PR](https://github.com/sgl-project/sglang/pull/44361) · state: open · merged: False

## Original PR description

## AITER prerequisites

None. This change does not call an AITER kernel.

## Motivation

On ROCm, Kimi-K3 with `--enable-symm-mem` and graph capture on produces corrupted output. Symmetric-memory buffers are allocated per forward, so a captured graph replays addresses that are neither held nor rank-aligned.

## Modifications

- Add a Kimi-K3 post-process pass that sets `enable_symm_mem=False` on HIP when decode or prefill graph capture is on, and log why and which flags keep symmetric memory.
- Run it after the model-specific adjustments in the resolution pipeline.
- Leave eager runs, other models and CUDA unchanged.
- Extend `test_resolution_declarations.py` with HIP decode capture, HIP prefill-only capture, HIP eager and CUDA cases.

This is a workaround until the symmetric-memory pool pins buffers for captured graphs.

## Accuracy Tests

Correctness fix; no serving-path change when symmetric memory is off. CPU test: `test_resolution_declarations.py`.
