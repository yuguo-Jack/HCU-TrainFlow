### Optimization Opportunity: Avoid Redundant Global Memory Writes and Re-computation

Currently, every block (expert) in the grid writes the entire `cumsum` array of size `num_experts` to global memory (`expert_start_loc`). This results in $O(N^2)$ total global memory writes with severe write-write conflicts/contention across blocks, even though they write the same values.

Additionally, the current implementation re-computes the prefix sum using `tl.sum` over `tokens_per_expert` with a `< cur_expert` mask, even though `cumsum` has already been computed.

### Solution
We can optimize this by:
1. Reusing the already computed `cumsum` to extract `cur_expert_start` via a single-element mask (`offset_cumsum == cur_expert`).
2. Having each block write only its own scalar `cur_expert_start` to `expert_start_loc + cur_expert`. This reduces the total global memory writes from $O(N^2)$ to $O(N)$ and completely eliminates write-write conflicts.

```python
    cur_expert_start = tl.sum(
        tl.where(offset_cumsum == cur_expert, cumsum, 0),
        axis=0,
    )
    tl.store(expert_start_loc + cur_expert, cur_expert_start)
```
