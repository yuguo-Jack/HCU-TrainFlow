# [Refactor] multimodal: Share the CUDA VMM chunk copy and let the transport pick its pool class

[Upstream PR](https://github.com/sgl-project/sglang/pull/47968) · state: open · merged: False

## Original PR description

## Motivation

`CudaVmmMemoryPool.wrap_tensor` and `wrap_tensors` each carry their own copy of the staging sequence that moves feature bytes into a reserved pool chunk: wait for the source streams, zero the chunk's control words, copy the bytes onto the publish stream, and synchronize before publishing. Anyone who wants to change how the bytes reach the chunk (for example a copy that does not go through torch) has to re-implement reservation, proxies, rollback and recycling alongside it, and keep two copies of the sequence in step.

`CudaVmmFeatureTransport` also builds `CudaVmmMemoryPool` by name, so a subclass of the transport cannot choose a different pool class.

## Modifications

- `CudaVmmMemoryPool._copy_into_chunk(control_offset, data_offset, tensors, layouts)`: one method that both `wrap_tensor` and `wrap_tensors` call. It waits on the source streams, zeroes `[control_offset, data_offset)`, copies every tensor to `data_offset` plus its layout's relative offset, and synchronizes the publish stream before returning. The torch ops are the same as before: a single tensor goes through `_prepare_pinned_copy_source`, several tensors are packed into one pinned buffer by `_pack_pinned_copy_sources`. On failure the callers still synchronize the publish stream before releasing the chunk, and still quarantine the pool if that synchronize fails.
- `CudaVmmFeatureTransport.pool_class`: a class attribute read when the transport is built. The default `None` resolves to the module's `CudaVmmMemoryPool` at construction time, so code that replaces that module attribute still takes effect; a subclass can set its own pool class instead.

No behaviour change for the default path.

Not applicable: the bytes written to the pool, the ack words and the proxies are unchanged. `test/registered/unit/multimodal/test_cuda_vmm_transport.py` and `test_gpu_feature_transport.py` cover both wrap paths, the single publish-stream synchronize per publish, and the failed-cleanup quarantine.
