# [RFC][LoRA] Share a generation backbone with multiclass classifier heads

[Upstream PR](https://github.com/sgl-project/sglang/pull/42974) · state: closed · merged: False

## Original PR description

## Motivation

Serve multiple multiclass LoRA classifiers and ordinary generation requests on one causal-LM backbone. Each classifier has its own saved head, labels, and preprocessing; callers select it with `model="base:adapter"` on `/v1/classify`.

**Draft RFC with an implementation.** Please review the artifact contract and execution approach before treating this as merge-ready. This branch includes the small, independently reviewable registry fix in #42971 as its first commit; the classifier implementation is the second commit.

## Modifications

- Load standard PEFT `LORA` / `SEQ_CLS` safetensors containing a linear `score` or `classifier` head. An exporter writes a proposed version-1 `classification_config.json` binding labels, raw-text preprocessing, exact head tensor keys, and checksums of both PEFT artifacts. No private artifact format or service dependency is required.
- Dynamically load an immutable local snapshot and publish its CPU head only after all backend replies succeed. Bind heads and request leases to runtime adapter IDs, retain them through CPU postprocessing, preserve retryable cleanup after partial backend failure, and drain LoRA control operations despite caller cancellation.
- Reuse generation prefill with `max_new_tokens=0` and LAST hidden states, followed by a CPU linear head and FP32 softmax. Clone the tokenizer lazily; offload classifier tokenization, file validation, and head computation from the event loop. Classification uses raw text, explicit special-token handling, and right truncation.
- Add registered CPU tests, a no-download fixture with two real PEFT classifiers plus a generation adapter, a registered real-server CUDA test, documentation, and a classification/generation/mixed-load benchmark harness.

Initial scope: dense Llama/Qwen2/Qwen3 decoders, standard uniform-rank LoRA, local dynamic bundles, one node/tokenizer worker, DP=PP=1, and unchanged vocabulary. Unsupported head/config variants and explicitly padded inputs fail closed. rsLoRA, DoRA, MoE parameter adapters, arbitrary saved modules, speculative decoding, and disaggregated serving are excluded from this prototype. TP>1 and quantized execution have not been validated. The manifest binds adapter artifacts, not the identity of the base weights; the serving base must match training.

### RFC decisions

1. Is a versioned sidecar appropriate for labels/preprocessing/checksums, while leaving PEFT tensor names and files unchanged, or should this metadata use a different config contract?
2. Is tokenizer-process CPU head execution an acceptable first step, or should heads live with the workers/GPU?
3. Should the initial implementation retain the current prefill/hidden-state route or first bypass vocabulary-logit computation? `max_new_tokens=0` avoids decoding, but the current causal-LM logits processor can still run the LM head. Capture and serialization also have costs that require measurement.

## Accuracy Tests

**Passed locally:**

- 51 CPU unittest cases across artifact/export validation, registry cancellation, classifier lifecycle, HTTP handling, and existing LoRA result-merge regression tests.
- Full independent HF/PEFT sequence-classifier forwards versus an independent decoder reconstructed from SGLang-loaded LoRA weights and the production CPU head: Llama/Qwen2/Qwen3 × left/right reference padding. Checks tokens, logits, probabilities, labels, and truncation with `rtol=1e-5`, `atol=1e-6`. These tests do **not** run SGLang GPU kernels.
- ASGI tests run the real protocol, serving handler, TokenizerManager, and registry, replacing token packing/scheduler transport. Lifecycle tests include the real fan-out communicator and late replies after repeated unload cancellation.
- Public synthetic fixture creation and CPU HF/PEFT reference execution; benchmark HTTP/stream/resource-monitor smoke tests.
- Pre-commit, full Mintlify build validation, and the new page's link/anchor check passed (Mintlify 4.2.976).

**Not yet run:** the actual CUDA server test, GPU numerical comparisons, native GPU classification regressions, and TP/quantized validation. The registered CUDA test exercises both saved heads, raw text/token IDs, base/LoRA generation, streaming, reload, and base→classifier→base isolation. Its proposed FP16/FP32 probability tolerance is `atol=rtol=0.003`.

Local CPU environment: Python 3.14.4, PyTorch 2.14.1, Transformers 5.19.0, PEFT 0.21.2. Repository CI environments still need to run these tests.

## Speed Tests and Profiling

**GPU performance measurements are pending.** No throughput or zero-overhead claim is made. `benchmark/lora_classification/bench_serving.py` reports errors, p50/p95/p99 latency, throughput, streaming TTFT/ITL, and optional process-tree CPU/RSS and device VRAM samples. Batched stream chunks are reported separately from per-token intervals.

The documentation specifies a fixed-length/concurrency comparison of generation without capture, generation with capture but no classifier, classifier-only, and mixed traffic, including ordinary generation LoRA and cache settings. Maintainer agreement and measured GPU correctness/performance are prerequisites to moving this RFC out of draft.
