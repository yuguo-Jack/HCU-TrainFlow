# [Fix] Preserve scalar EOS token 0 from generation config

[Upstream PR](https://github.com/sgl-project/sglang/pull/42334) · state: closed · merged: False

## Original PR description

## Motivation

`ModelConfig._get_hf_eos_token_id` ignores `eos_token_id: 0` in `generation_config.json` because it checks the value's truthiness. The equivalent list `[0]` is retained. For example, model-config EOS `2` plus generation-config EOS `0` resolves to `{2}` instead of `{0, 2}`.

The scheduler passes this set to request stop detection. In a tokenizer-free CPU component reproduction, a real `Req` continues after token `0` before the fix and stops after it with the fix.

Related: #8315 fixed the same zero-value issue for the model-config branch; this addresses the remaining generation-config branch.

## Modifications

- Use an explicit `None` check for generation-config EOS IDs.
- Extend the existing registered CPU model-config tests with local-file loading coverage for scalar/list zero, positive IDs, missing/empty IDs and model-config zero.
