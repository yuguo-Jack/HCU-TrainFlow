# [Fix] [NPU] qwen3.5: Fix dense serving on Ascend 950

[Upstream PR](https://github.com/sgl-project/sglang/pull/32745) · state: open · merged: False

## Original PR description

## Summary

Fix Qwen3.5 dense serving on Ascend 950 across Gemma RMSNorm, multimodal rotary positions, and ModelSlim MXFP8 scale loading.

- Route ordinary `GemmaRMSNorm` and `Gemma3RMSNorm` through the stable `sgl_kernel_npu.norm.gemma_rmsnorm.npu_gemma_rms_norm` API. The wheel selects the provider at build time: native Gemma RMSNorm on Ascend 910B/910C, or standard RMSNorm with `1 + weight` on Ascend 950. Preserve the existing `torch_npu` fallback for older Ascend 910 wheels and document the required Ascend 950 package.
- Use `torch_npu.npu_add_rms_norm` with cached `gemma_weight` for the residual path at every hidden size. Reuse the same cached scales in the Qwen3.5 fused NPU prefill path, avoiding repeated `1 + weight` operations.
- Preserve three-axis multimodal positions in NPU prefill and route two-dimensional positions away from the ordinary NPU RoPE operator. Decode keeps its existing fused path.
- Round up ModelSlim MXFP8 scale placeholders, pad odd scale counts for the kernel pair layout, and align unaligned row-parallel shards to checkpoint quantization blocks. For example, `K=4304` requires 135 scales; TP ranks whose shard starts inside a block must share its scale and pad both weights and inputs to the same block boundary.

## Dependency

The ordinary Ascend 950 Gemma path requires a matching target wheel containing sgl-project/sgl-kernel-npu#638, which is merged. Provider selection stays in the wheel build; SGLang adds no runtime SoC detection. The residual path uses the common `torch_npu` API directly.

Vision-tower ModelSlim configuration forwarding in #36426 remains a separate change and is not included here.

## Validation

After merging official main `fea48754de4b73276cad1062d6b5ae013288204d` on 2026-10-19:

- 102 isolated CPU/mock Gemma and kernel-registry tests passed, including 18 residual cases spanning FP16/BF16, FP32-to-BF16 scale conversion, hidden sizes 256/5120/8192, and optional post-residual addition. The tests check cached tensor reuse, argument forwarding, and returned tensor identities.
- 8 MRoPE tests passed through an isolated harness using the checked-in methods, including multimodal positions, prefill/decode routing, and cached Q/K scale forwarding.
- 6 MXFP8 tests passed through an isolated CPU harness, covering partial scale blocks and TP1/2/4/8 scale alignment across all ranks.
- Ruff 0.15.1, isort 7.0.0, codespell 2.4.1, Python AST checks, registered-test validation, pytest entrypoint checks, and whitespace checks passed for the final change.

Four kernel tests requiring the full serving/JIT import environment were deselected. Serving dependencies and NPU hardware are unavailable locally; these checks do not establish current-head NPU model loading, warmup, output accuracy, or performance. Target hardware validation remains required.

With the help of an agent, I've found 2 possible places where this PR could gain performance.
Could you take a look at these points?

Two per-forward allocations in the NPU Gemma-norm paths that can both read a buffer that already holds the value.

**1. `qwen3_5.py`, `forward_prepare_npu_prefill`** — `q_norm`/`k_norm` are `GemmaRMSNorm`, which precomputes `weight + 1.0` into its `gemma_weight` buffer at load time in the same dtype:

```diff
         q, k, v, gate = triton_split_qkv_rmsnorm_mrope(
             qkv=qkv,
-            q_weight=1 + self.q_norm.weight,
-            k_weight=1 + self.k_norm.weight,
+            q_weight=self.q_norm.gemma_weight,
+            k_weight=self.k_norm.gemma_weight,
             cos_sin=cos_sin,
```

`test_qwen35_npu_prefill_mrope_contract` builds `q_norm`/`k_norm` as `SimpleNamespace`, so those need `gemma_weight` (1.25 / 0.75) in place of `weight`.

**2. `layernorm.py`, `GemmaRMSNorm.forward_npu`** — with the paired kernel wheel, `add_gemma_rms_norm` is itself `npu_add_rms_norm(x, residual, 1.0 + weight, eps)`: the same operator as the branch above it, with the addends swapped (commutative, same returned sum) but gamma recomputed per call. So the threshold now picks cached vs. allocated gamma, and the allocating side is the common case:

```diff
             if post_residual_addition is not None:
                 residual = residual + post_residual_addition
-            if x.shape[-1] > _NPU_GEMMA_RMS_NORM_TRITON_MAX_HIDDEN_SIZE:
-                gamma = self.gemma_weight.to(x.dtype)
-                norm_out, _, residual = torch_npu.npu_add_rms_norm(
-                    residual, x, gamma, self.variance_epsilon
-                )
-            else:
-                norm_out, residual = add_gemma_rms_norm(
-                    x, self.weight, residual, self.variance_epsilon
-                )
+            norm_out, _, residual = torch_npu.npu_add_rms_norm(
+                residual, x, self.gemma_weight.to(x.dtype), self.variance_epsilon
+            )
             return norm_out, residual
```

That leaves two dead declarations in this file — the `add_gemma_rms_norm` import and `_NPU_GEMMA_RMS_NORM_TRITON_MAX_HIDDEN_SIZE = 5120`. The wheel symbol itself is still used by `GemmaFusedAddRMSNormOp.forward_sgl_kernel_npu` in `sglang/kernels/ops/layernorm/__init__.py`.

Note change 2 is only equivalent with the new wheel — on an older one the `≤5120` branch is still the Triton kernel.

The ceil on `scale_dim` (`modelslim_mxfp8.py:69-71`) is per partition, but `RowvLLMParameter.load_row_parallel_weight` (`parameter.py:299-301`) shards the scale at `tp_rank * ceil(K/tp/32)` while the weight shards at `tp_rank * K/tp`. Those diverge whenever `K/tp` isn't a multiple of 32 — at tp=2 with K=4304, rank 1's first weight element needs checkpoint block 67 but gets 68.

Unfixed, tp>1 on such a layer loads and computes garbage rather than failing: a one-block E8M0 shift scales weights by a wrong power of two, and the read past the checkpoint's last column is silently zero-padded. Before this change the pair reshape raised instead. The new tests cover tp=1 only.
