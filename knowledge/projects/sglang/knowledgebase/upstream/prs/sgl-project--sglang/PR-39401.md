# [benchmark] Add ascend_bench: config-driven benchmark sweeps with SLA gating for Ascend NPU

[Upstream PR](https://github.com/sgl-project/sglang/pull/39401) · state: open · merged: False

## Original PR description

## Summary

`ascend_bench` is a self-contained sweep tool that automates
launch → warm up → benchmark → verify → rank for SGLang deployments, with
first-class support for Ascend NPU hosts. One YAML file describes the whole
sweep: server argument grid, workload grid, SLA thresholds, and repeat
policy.

It was built to establish reproducible NPU performance baselines and to
support regression verification (hiascend community task
"[SGLang] sglang 自动化基准测试能力建设", issue #1103), but the core is
hardware-agnostic: `asc_bench/` imports neither `torch` nor `sglang`
(enforced by a unit test), and all NPU awareness is isolated in a single
module (`asc_bench/npu.py`).

## What it does

- **Config-driven sweeps** — cartesian product over `server.axes` and
  `workload.axes`; every YAML key is a literal `sglang.launch_server` /
  `sglang.bench_serving` CLI flag. Validation aggregates all errors and
  rejects Ascend-unsafe configs up front (e.g. `--cuda-graph-bs` > 10
  entries → graph-capture stream-conflict crash 507000).
- **Hard HBM gate** — after each cell the server process group is killed
  and `npu-smi info` is polled until per-device HBM is back within a
  budget of the pre-run baseline; stragglers are SIGKILLed and the cell is
  flagged `failed_hbm` instead of poisoning the sweep with phantom OOMs.
- **SLA filtering + variance-gated ranking** — cells violating any
  percentile threshold are eliminated; survivors are ranked by output
  throughput (TPOT p99 tiebreak); repeats report mean ± std and cells with
  CV above `cv_max` are marked unrankable.
- **Accuracy smoke gate** — optional per-cell gsm8k run reusing
  `benchmark/gsm8k/bench_sglang.py`; below-floor accuracy flags perf data
  as untrustworthy.
- **Reports + regression** — `report.md`/`report.json` (rank table, SLA
  matrix, compatibility matrix with server.log tails, recommended commands,
  full provenance); `compare.py` diffs two runs by cell hash.
- **Resume** — append-only `manifest.jsonl`; interrupted sweeps continue
  where they stopped.

## Methodology

Documented in `docs/docs/hardware-platforms/ascend-npus/evaluation/automated_benchmarking.mdx`
(metric definitions and percentile rationale, warmup/repeat/variance
policy, dataset selection, Ascend-specific pitfalls, how to add a model
spec).

## Baseline (Atlas 800I A3, 2 × 910C die, single node, PD co-located)

Measured with the configs in `configs/cookbook/` (random-ids 1024/1024, 3 repeats, gsm8k 200-question gate per cell; full data in each run's `report.json`). SLA gates: p99_tpot ≤ 100 ms passes on **every** cell of both specs; p99_ttft gates fail under saturation (queueing at conc≥8 with 8×concurrency prompts) — by design, see the methodology doc.

**Qwen3-8B BF16 — 24/24 cells done, gsm8k ≥ 0.945 everywhere:**

| concurrency | output tok/s (mean±std) | tok/s/card | p99 TPOT ms | note |
|---|---|---|---|---|
| 1 | 96.2 ± 0.3 | 48.1 | 10.5 | unrankable once: single 9.8 s TTFT spike in 1/3 repeats (variance gate; rerun clean at 111 ms) |
| 8 | 630 ± 2 | 315 | 12.7 | |
| 32 | 1717 ± 6 | 859 | 18.5 | **top-ranked** |
| 64 | 2525 ± 5 | 1262 | 25.5 | |

Throughput is insensitive to `--mem-fraction-static` 0.80 vs 0.85 (< 1%).

**Qwen3.6-35B-A3B BF16 (qwen3_5 GDN+MoE) — 18/18 cells done, gsm8k 0.615–0.655:**

| concurrency | output tok/s (chunked-prefill 4096 → 8192) | tok/s/card | p99 TPOT ms | note |
|---|---|---|---|---|
| 8 | 390.6 → 395.1 | ~196 | 19.6–20.0 | **SLA pass, both ranks** |
| 32 | 939.9 → 967.9 | ~477 | 32.6–33.9 | |
| 64 | 1295.9 → 1362.6 | ~655 | 41.3–43.7 | |

**Stretch (NEXTN speculative decoding): fails to launch on this stack** — sgl-kernel-npu's `mamba_state_update_triton.py` hits a UB-overflow compile error (`requires 2097152 bits while 1572864 bits available`) in the MTP draft path; both cells captured in the compatibility matrix with server.log tails (filed as a separate bug issue against `Ascend/sglang`).

## Notes for reviewers

- Landing path is intentionally self-contained (`benchmark/ascend_bench/`);
  if reviewers prefer NPU-specific tooling to live in `Ascend/sglang`, the
  directory relocates with a single `git mv` — the hardware-agnostic core
  has no sglang/torch imports.
- Load generation and accuracy evaluation reuse the existing
  `sglang.bench_serving` and `benchmark/gsm8k/bench_sglang.py`; no
  benchmarking logic is duplicated.
