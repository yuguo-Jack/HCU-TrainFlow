# [CI] [AMD] pr-test: Run stage-b and diffusion shards in parallel; trim stage-a

[Upstream PR](https://github.com/sgl-project/sglang/pull/46086) · state: open · merged: False

## Original PR description

## What

- Raises `max-parallel` from 1 so these shards run at the same time instead of one after another:
  - `stage-b-test-1-gpu-large-amd`: 3
  - `stage-b-test-2-gpu-large-amd`: 2
  - `multimodal-gen-test-1-gpu-amd`: 2
  - `multimodal-gen-test-2-gpu-amd`: 2
- Trims `stage-a-test-1-gpu-small-amd` to the two server sanity tests, as CUDA's base-a does. The seven AMD kernel/unit tests move to `stage-b-test-1-gpu-small-amd`.

## Why

On PRs the ROCm matrix is only rocm10, so `max-parallel: 1` serializes the shards:
- 1-gpu-large runs 3 × ~35 min back to back, which is most of why `wait-for-stage-b-amd` finishes around minute 117.
- The 2-GPU diffusion job runs 2 × ~2 h back to back.

The cap came in with the ROCm-version matrix consolidation in #38632. Scheduled runs with two ROCm versions will now use up to 2–3 runners at once for these jobs instead of 1.

Every other stage waits on stage-a, so its runtime is on the critical path of every PR. The moved tests are small and unchanged.

Related: #46084, #46085. #46084 cuts 1-gpu-large to 2 shards and 2-gpu-large to 1; the new limits are harmless either way, and the branches merge cleanly.
