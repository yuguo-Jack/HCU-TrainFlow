# [Fix] unified_cache: Restore Inkling MTP draft state in the direct external linker

[Upstream PR](https://github.com/sgl-project/sglang/pull/47293) · state: open · merged: False

## Original PR description

## Motivation

#40223 restores every Inkling MTP draft head's KV and recurrent state on a HiCache hit, but the direct external linker never picked those pools up: the FULL + SWA + MAMBA linker group ignores `mtp_draft_device_pools` and `mtp_draft_mamba_pools` without an error. On an L3 hit the draft heads read whatever the reused pages and slots last held. Target outputs stay correct (verification rejects bad drafts), but the accept length drops.

## Modifications

- Pack draft KV into the linker pages: full-attention drafts and SWA drafts addressed by full-token ids ride the KV entry (a linker page may mix head geometries, so no separate draft sidecar is needed); SWA drafts that share the target's SWA indices ride the SWA entry.
- Pack the separate draft Mamba conv/temporal state into the MAMBA entry, addressed by the target's slot indices.
- Draft buffers attach to each entry's last transfer layer, since drafts read only after the whole target forward.
- Small HiCache refactor in the same area: a sidecar draft with both full and SWA sub-pools now registers a `DRAFT` sidecar for its full sub-pool next to `DRAFT_SWA`, instead of only mirroring the SWA sub-pool (`build_hicache_draft_sidecars`, plus staging sizing in `prepare_hicache_staging`). Covered by `test_hybrid_draft_restores_full_and_swa_layers`.
- Tests: a unit test for the packed layout, and an Inkling MTP e2e that compares an L3-hit second turn against a device-hit one (per-request `spec_verify_ct` and output ids). A filler request between flush and the second turn overwrites the freed pages and slots, otherwise stale rows hide a missing restore.

## Accuracy Tests

Tiny Inkling checkpoint, 1 GPU, deterministic inference, multi-layer EAGLE (2 steps, topk 1, 3 draft tokens), Mooncake linker, 4 multi-turn requests with a 1280-token prefix fully restored from L3:

| | Accept length |
|---|---|
| Device prefix hit (reference) | 2.467 |
| L3 hit, main | 2.156 |
| L3 hit, this PR | 2.467 |

Target output ids are identical in all three. The new e2e fails on main and passes with this PR; the existing Inkling linker KL test still passes.

File: `python/sglang/srt/mem_cache/hybrid_cache/linker_pool_assembler.py` · line 561

🔴 Servers that share a Mooncake store across versions or MTP settings now get failed loads or corrupted Mamba conv state on L3 hits. Packed MTP draft rows change the MAMBA and KV object layouts. The object keys stay the same, and the MAMBA draft rows sit between the temporal rows and conv rows, so conv offsets move. Fix: make every packed-layout change produce different keys, for example by tagging the DevicePoolEntry object suffix with the draft layer count. Mooncake skips puts for keys that already exist, so objects in the old layout are never replaced.

<details>
<summary>Why this was flagged</summary>

Trigger: a Mooncake store that outlives a server upgrade, or is shared by MTP and non-MTP instances serving the same model. Keys are only prefixed with extra_backend_tag and model_name (mooncake_store.py:458-473), and a DevicePoolEntry object is just `_{mla_suffix}_{object_name}` (mooncake_store.py:933-937). On base, the mamba+SWA group ignored drafts, so MTP on and off wrote identical objects. Now, with packed=True, the MAMBA entry's _component_offsets follow the order [temporal target, temporal draft, conv target, conv draft] (linker_pool_assembler.py:550-561). A non-MTP reader of an MTP-written object reads its conv rows at offset T*temporal_size, which holds draft temporal bytes, so target conv state is silently wrong. An MTP reader of an older object reads past its end, both for MAMBA conv/draft rows and for KV draft rows appended at :499-509. load_layer_wise then raises "Mooncake range get failed" and the requests are aborted. _build_pool_buffer_meta (mooncake_store.py:1216-1243) skips pages that already exist, so stale objects keep failing until evicted.

**Verification:** A DevicePoolEntry object key is just `f"_{self.mla_suffix}_{object_name}"` (mooncake_store.py:933-937). `DevicePoolEntry` with packed=True adds offsets up across components (linker_pool_assembler.py:64-73). On base, this group ignored drafts, so MTP on and MTP off produced byte-identical objects under the same keys. The only check is that the transferred byte counts equal `sizes`.

</details>
