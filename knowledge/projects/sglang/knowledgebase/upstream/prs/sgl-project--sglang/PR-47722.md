# [Feat] observability: Add request-level frontend wall-time histograms

[Upstream PR](https://github.com/sgl-project/sglang/pull/47722) · state: open · merged: False

## Original PR description

## Motivation

Process CPU usage is not request latency. Add request-level wall-time histograms to show how much frontend processing occurs before a request is submitted to the Scheduler.

## Modifications

- Add one histogram, `sglang:frontend_request_stage_seconds`, controlled by the existing `--enable-metrics` flag, with `total`, `text`, and `multimodal` stages.
- Measure total time from HTTP route handler entry, before body parsing, until the frontend send returns. Record each logical request only on its first submission; exclude internal parallel-sampling warmups and pre-submission failures.
- Record text/MM only for requests that executed the stage, including genuine zero-duration observations. Their counts and percentiles describe participating requests, while total counts all submitted requests. No extra labels or counters.
- Carry request-local context through Chat conversion, multimodal executors, and dynamic batch tokenization. Shared batch execution is attributed in full to each participating request; encoding queue waits are excluded.
- Merge overlapping intervals within each stage. Text may overlap multimodal processing; fused template-and-encode operations remain in text. Stage durations and marginal quantiles must not be added. Send completion does not prove Scheduler receipt.
- Use `msgspec.Struct` for the new timing state, with independent span maps and locks per request. Timing attributes on internal requests/futures remain optional at existing lifecycle boundaries; metrics-disabled requests do not create timing objects.
