# [CI] diffusion: Add the B200 baseline override for b200-cirrascale2

[Upstream PR](https://github.com/sgl-project/sglang/pull/48256) · state: open · merged: False

## Original PR description

## Motivation

`multimodal-gen-test-4-gpu-b200` fails every attempt on runner `b200-cirrascale2`, whatever the PR changes. `b200.json` picks E2E references by runner-name prefix, and no `runner_overrides` key matches `b200-cirrascale2`, so it uses the default (Verda) references. Two cases fail `E2E Latency` on all 7 attempts (initial run plus 6 retries), as seen in [job 126183089454](https://github.com/sgl-project/sglang/actions/runs/41712145442/job/126183089454) on #46926:

| Case | Default limit (ms) | Measured on `cirrascale2` (ms) |
| --- | ---: | ---: |
| `flux1_modelopt_nvfp4_t2i` | 1045.89 | 1169–1196 |
| `qwen_image_2512_modelopt_nvfp4_t2i` | 12062.58 | 16136–16967 |

Nothing else in that job failed. It's the same gap #42329 fixed for `b200-cirrascale4`.

`cirrascale2` runs at the speed of the other Cirrascale runners. It has the same B200 and driver (580.126.20) as `cirrascale4`, and its per-step denoise times agree with main's scheduled run on `cirrascale4-4567` ([job 125879877166](https://github.com/sgl-project/sglang/actions/runs/41624885463/job/125879877166)):

| Runner | Flux1 E2E (ms) | Flux1 step (ms) | Qwen2512 E2E (ms) | Qwen2512 step (ms) |
| --- | ---: | ---: | ---: | ---: |
| `b200-cirrascale2` (7 attempts) | 1169–1196 | 80.7–82.9 | 16136–16967 | 317.5–334.0 |
| `b200-cirrascale4-4567` | 1194.61 | 82.9 | 17071.79 | 336.1 |

It's one runner over all eight GPUs, with no `-0123`/`-4567` suffix. It seems to be rare: none of main's 59 scheduled B200 diffusion jobs from 10-07 to 11-03 ran on it. Any PR whose B200 job lands there fails.

## Modifications

- `perf_baselines/b200.json`: add a `b200-cirrascale2` key to `runner_overrides`. Under the Cirrascale pool rule in `PERFORMANCE.md`, it reuses the `cirrascale4-4567` references: 1471.19 ms for flux1 and 17346.65 ms for qwen. With the 25% tolerance, the limits become 1838.99 and 21683.31 ms.
- `test_runner_perf_baselines.py`: `b200-cirrascale2` was listed as a runner that keeps the defaults. Move it to the override and E2E-boundary cases.
- `PERFORMANCE.md`: add a Cirrascale 2 section with the measurements above.

Nothing else changes: no other metric, case, tolerance or runner.

## Testing

- I checked locally that `b200-cirrascale2` now matches its own key, and that every other runner name still resolves to the same key as before (`cirrascale1/3/4`, `di01` → `b200-di`, and `fin03` → defaults).
- `test_runner_perf_baselines.py` needs torch, so I haven't run it locally. CI runs it.
- pre-commit passes.
