## Motivation

Part 5/5 of the DeepSeek-V4.1 CP>1 support series, split from the original combined PR [#45954](https://github.com/sgl-project/sglang/pull/45954). Based on the CP replay core in part 3. This PR adds Mooncake Store L3 recovery independently of the P/D extension.

For replay recovery, taking the minimum reported hit length is insufficient when required pools are restorable only at specific endpoints. All peers must adopt a common restorable endpoint. Stored KV also needs a producer namespace: identical model/token keys do not establish numerical compatibility across different CP topologies or compute recipes.

For example, suppose two peers report restorable page endpoints `{1, 3}` and `{1, 2}`. Taking the minimum of their maximum hit lengths yields page 2, which the first peer cannot restore. Intersecting the endpoint sets instead yields page 1. This illustrates endpoint selection, not a new Mooncake/RDMA measurement.

## Modifications

- Propagate backend restorable endpoints and intersect them across peers before adoption, alongside the common hit bound and per-pool results.
- Keep scheduler probes and background prefetch on their respective collective groups. Use matching collective sequences for hits, misses, query failures, and cancellation.
- Add a storage namespace derived from KV layout and the CP producer recipe, including topology, selected compute backends, relevant options, and package versions. Preserve a user-supplied `extra_backend_tag`.
- Require Mooncake Store for this CP replay L3 path, including runtime attachment. Preserve CP1 cache identity.

Changing CP topology or a recorded numerical recipe changes the namespace. Changing pool capacity alone does not. Autotune tactics must still be pinned; rotate `extra_backend_tag` and warm the cache when unrecorded tactic choices change.

Only persistent cache pools are stored. Request windows, draft rings, and hidden state are rebuilt or transferred through their existing paths. P/D still requires part 4; direct L3 linking and `buffer_only` remain outside this scope.

## Accuracy Tests

Archived replay/storage CPU validation for this split head: **55 passed, 0 skipped**. Coverage includes producer tags, runtime attachment, endpoint propagation, and two-rank Gloo restore collectives. Lint passed during split preparation.

The endpoint regression supplies the trailing-pool query plan and mocks hash/transport boundaries. It does not prove automatic plan discovery, production hashing, real Mooncake Store/RDMA, or GPU L3-to-L1 bitwise equivalence. Historical combined H20 results are not standalone acceptance for this head.
