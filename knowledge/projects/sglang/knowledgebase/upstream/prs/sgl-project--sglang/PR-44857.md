# [Fix] deepseek-v4.1: Keep the cached KV of folded encoder replay rows

[Upstream PR](https://github.com/sgl-project/sglang/pull/44857) · state: closed · merged: True

## Original PR description

- Folded encoder SWA replay rows now get the padding slot (`raw_out_loc` 0) as their compressor write location (`_compressor_out_loc`); their main KV, compressed groups and index keys keep what the prefill that cached them wrote
- The fused c1/c2 compressors (SM100+) used to rewrite those rows on every prefix hit: `compress_skip` only reached the c2 ring write-back, while the c1 store, the c2 pooling store and the index-K store ran over every row
- The unfused compressor (e.g. Hopper) used to drop the replay rows from its input but not from its slots, so each new row landed on another row's slot (since #43166); it now takes every row, and the padding slot skips the replay rows
- Drop `compress_skip`, which the padding slot replaces
- Add `test_extend_metadata_puts_replay_rows_on_the_padding_slot` (on main no row gets the padding slot) and `test_unfused_compressor_writes_each_row_at_its_own_slot` (on main 90 of 282 rows reach the compressor)
- Checked on GB300 by snapshotting the replay rows' cached c1/c2 bytes before each prefix-hit prefill and comparing after it: main changed 3308-3712 of 3712 checked rows per hit on the fused path and all 3712 on the unfused path; this PR changes 0 on both

No behavior change outside `--enable-encoder-swa-bounded-replay`, where a prefix hit no longer rewrites the cached KV of its replayed tokens and every new token's KV goes to its own slot.
