# [Fix] rust-server: Deliver scheduler-side aborts to Rust frontend clients

[Upstream PR](https://github.com/sgl-project/sglang/pull/45899) · state: closed · merged: True

## Original PR description

## Motivation

The scheduler ends some requests outside the output stream:

- aborted while queued (`/abort_request`, `SGLANG_REQ_WAITING_TIMEOUT`);
- evicted or rejected by priority scheduling (`--max-queued-requests`, priority disabled);
- aborted on retraction when the KV pool is full;
- aborted while chunked, or in the PD decode retracted queue.

It reports each one as an `AbortReq` on the ZMQ tokenizer socket, and Python's `TokenizerManager` turns that into the request's final frame (`_handle_abort_req`). In Rust mode nothing reads that socket, so these clients never got a terminal frame: a stream hung until the client gave up, and a unary request never received its status.

## Modifications

- `python/sglang/srt/managers/scheduler.py`: the nine abort sites now go through a new `Scheduler.send_abort_output`, the counterpart of `send_control_output`. With a Rust server it calls `rust_server.push_abort`; otherwise it sends the `AbortReq` to the tokenizer socket as before. Python mode is unchanged.
- `python/sglang/srt/rust_server/server.py`: `RustServer.push_abort` pushes a one-request terminal batch to the Rust egress with the abort finish reason (the scheduler's, or Python's `"Abort in waiting queue"` default) and no new tokens. The Rust frontend renders it like any abort finish: a final stream frame, or the finish's status code for a unary request, as Python does. The batch carries the request's own prompt, cached and reasoning token counts, so it does not reset what the stream already reported.
- Tests: `test_rust_server_extension.py` gains `test_scheduler_aborts_reach_the_rust_egress` (in Rust mode the abort becomes the one-row batch with the request's counts; without the Rust server it still goes to the tokenizer socket). Scheduler unit tests that build a scheduler with `Scheduler.__new__` or a `SimpleNamespace` now set `rust_server = None`, which every real scheduler sets in `maybe_init_rust_server`, or fake `send_abort_output` directly (`test_weight_versions.py`).
