# [Fix] diffusion: Harden component loaders: trust_remote_code gating, Ming overrides, meta-init upscaler

[Upstream PR](https://github.com/sgl-project/sglang/pull/47745) · state: open · merged: False

## Original PR description

## Changes

1. `vae_loader.py`: the `auto_map` branch exec'd the checkpoint's custom `.py` without checking `trust_remote_code`. It now raises `ComponentCheckpointUnsupportedError` unless it is set. The module is also registered in `sys.modules` under a unique name (was always `_custom`), so custom VAEs with relative imports work.
2. `text_encoder_loader.py`: `build_model_config` hard-coded `trust_remote_code=True` in `AutoConfig.from_pretrained`. It now passes `server_args.trust_remote_code`, and the call moved inside `if encoder_index == 0:`, the only place the result is used.
3. `ming_image.py`: `MingImageEncoderLoader` accepted weight and quantization overrides via its base class but ignored them. Both resolvers now reject non-None values like the base `ComponentLoader`, and precision comes from `self.component_load_precision(...)`.
4. `latent_upscaler_loader.py` (perf): build under `torch.device("meta")` and `load_state_dict(..., strict=True, assign=True)` instead of fp32 random init on CPU plus copy. Follows `upsampler_loader.py`. The model has no buffers, so nothing stays on meta.

## Tests

Added `test_auto_map_requires_trust_remote_code` and `test_ming_image_encoder_loader_rejects_overrides`. Ran the vae, text encoder, plain state dict and component loader unit tests on CPU: 128 passed, 18 skipped.
