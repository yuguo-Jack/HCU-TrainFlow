# [Chore] [NVIDIA] deps: Bump sgl-deep-gemm to 0.2.5.post3

[Upstream PR](https://github.com/sgl-project/sglang/pull/47894) · state: closed · merged: True

## Original PR description

## Motivation

Move sglang to sgl-deep-gemm 0.2.5.post3 without changing any call site. 0.2.5 changed the MQA logits APIs (sgl-project/DeepGEMM#103); 0.2.5.post3 adds sgl-project/DeepGEMM#128, which keeps 0.2.3.post2's MQA logits code for SM90/SM100/SM120 and routes 0.2.3-style calls to it. The DSA and DSV4 indexers on main keep running exactly the MQA kernels they run with 0.2.3.post2. Moving the indexers to the new API (FP32 vs UE8M0 index-K) stays with #44350.

Release: https://github.com/sgl-project/DeepGEMM/releases/tag/v0.2.5.post3 (PyPI wheels from run 41412536657; the DeepGEMM suite including `test_attention_legacy.py` passed on H200, B200 and GB300).

## Modifications

- `python/pyproject.toml`: `sgl-deep-gemm==0.2.5.post3`.
- `docker/Dockerfile.cu134`: `DEEPGEMM_REF=v0.2.5.post3`, `SGL_DEEP_GEMM_VERSION=0.2.5.post3`.
- `test/registered/e2e/cp/test_cp_decode_attn_tp_server.py`: set `disabled=` on its CI registration. It has failed on every run since #46857 added it, with identical numbers under 0.2.3.post2 (run 41483265706) and 0.2.5.post3 (run 41420105384), and it blocks `pr-test-extra-finish`. The file stays in the tree and still runs directly or with `/rerun-test`.

## Accuracy and speed

4x B300 (TP4), sglang main 38d9e4a3fe, same tree with 0.2.3.post2 vs 0.2.5.post3 (identical wheel contents, built from the release tree). `few_shot_gsm8k` 1319 questions run twice; `bench_serving` random 8192 in / 256 out, 256 prompts, concurrency 32. The DeepGEMM call sites have not changed on main since 38d9e4a3fe.

| Model | sgl-deep-gemm | GSM8K | bench tok/s | TTFT ms | TPOT ms | MQA kernels compiled |
|---|---|---|---|---|---|---|
| DeepSeek-V4-Flash | 0.2.3.post2 | 0.951 / 0.957 | 645.6 | 1712 | 42.45 | `sm100_paged_mqa_logits` |
| DeepSeek-V4-Flash | 0.2.5.post3 | 0.955 / 0.954 | 670.5 | 1643 | 41.27 | `legacy_sm100_paged_mqa_logits` |
| DeepSeek-V3.2 | 0.2.3.post2 | 0.950 / 0.950 | 502.9 | 6486 | 38.41 | `sm100_mqa_logits`, `sm100_paged_mqa_logits_metadata` |
| DeepSeek-V3.2 | 0.2.5.post3 | 0.951 / 0.950 | 503.5 | 6473 | 38.39 | `legacy_sm100_mqa_logits`, `legacy_sm100_paged_mqa_logits_metadata` |

V4-Flash: `flashinfer_mxfp4` MoE, EAGLE 3/1/4, chunked prefill 4096, `SGLANG_DSV4_REASONING_EFFORT=low`. No server errors in any run.

Kernel and unit tests touching DeepGEMM, same results under both wheels on B300:

- `test_deepgemm_paged_mqa_logits` 192 passed
- `test_cute_dsl_fp8_paged_mqa_logits` 192 passed
- `test_fp4_indexer` 95 passed
- `test_dense_prefill_indexer`, `test_dsa_indexer`, `test_dsv41_prefill_sparse_indexer`, `test_dsv4_nonpaged_indexer`, `test_kpool_stream_scheduling`, `test_page_sharded_dsa_attention`, `test_mhc_kernels`, `test_fp8_wo_a`, `test_per_token_group_quant`, `test_mega_moe_deepgemm_api` and `test_fp8_blockwise_linear_backends` all pass.
- `test_paged_mqa_metadata` (14 failures) and `test_dsa` (1 failure) fail identically on 0.2.3.post2.

Not covered: SM90 and SM120 e2e. SM90 is covered at the kernel level by the release workflow's H200 job.
