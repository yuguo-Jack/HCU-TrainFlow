# [CI] [NVIDIA] docker: Publish the CUDA 13.4 nightly image for x86_64 as well as aarch64

[Upstream PR](https://github.com/sgl-project/sglang/pull/47999) · state: open · merged: False

## Original PR description

## Motivation

`lmsysorg/sglang:nightly-cu134` (and every dated `nightly-cu134-*` tag) is published for **arm64 only**: `release-docker-cu134-nightly.yml` builds only on `arm-kernel-build-node` with `--platform linux/arm64`. x86_64 Blackwell and Hopper hosts (B300, B200, H200) have no CUDA 13.4 nightly to pull (`docker pull` fails with `no matching manifest for linux/amd64`). Models whose kernels need a CUDA 13.4 toolkit at runtime, such as MiniMax-M3.1-Flash (the MSA `qmul4` NVFP4 KV dequant compiles with `nvcc` >= 13.4), are left on one-off `dev-*` images on x86.

`docker/Dockerfile.cu134` already handles x86_64 (CUDA target by `uname -m`, sm90-only HPC-Ops and the flash-attn3 cubin download on x86). Only the `MANYLINUX_IMAGE` default is aarch64-specific.

## Modifications

`.github/workflows/release-docker-cu134-nightly.yml`:

- **`meta` job.** Computes the date / commit tag once, so both architectures and the merged tags share it.
- **`build` matrix.** `amd64` on `x64-kernel-build-node` (the runner the kernel and DeepEP wheel releases use for x86_64) with `MANYLINUX_IMAGE=pytorch/manylinux2_28-builder:cuda13.4`, and `arm64` on `arm-kernel-build-node` as before. `fail-fast: false`, so one architecture failing does not cancel the other's multi-hour build. `--builder default` is kept, so each node's BuildKit / ccache stays warm. Each architecture pushes to a rolling single-arch tag (`nightly-cu134-amd64` / `nightly-cu134-arm64`) and uploads the pushed repo digest as an artifact.
- **`merge` job.** `docker buildx imagetools create` writes `nightly-cu134-{date}-{sha}` and `nightly-cu134` from the digests. arm64 is required (current GB200 / GB300 users must not lose it); amd64 is added when it built, otherwise the run publishes arm64 only with a `::warning::`. If arm64 failed, nothing is published and the job fails.
- `build_only` dispatches still build both architectures and skip the push and merge, as before.

The single-arch rolling tags do not match the nightly cleanup pattern `^nightly-cu134-[0-9]`, so only two extra tags ever exist.

## Testing

- `actionlint` is clean apart from the warnings the existing workflow already has (custom self-hosted runner labels, `docker/login-action@v2`).
- **Not run yet:** the x86_64 build itself. Suggested check before merge: dispatch this workflow on this branch with `build_only=true`, or with `image_repo=lmsysorg/sglang-staging`. Then confirm `docker buildx imagetools inspect lmsysorg/sglang-staging:nightly-cu134` lists both `linux/amd64` and `linux/arm64`.
