# [Unified Cache] Support hybrid SWA + Mamba models in the Mooncake direct linker

[Upstream PR](https://github.com/sgl-project/sglang/pull/41343) · state: open · merged: False

## Original PR description

## Motivation

The unified-cache external linker (direct L3, no host tier) supports Full and SWA tree components only. Hybrid SWA + Mamba models such as Inkling are rejected at startup by both the Python wrapper and the Rust tree core, and the Mamba component's linker hooks raise.

## Modifications

**Device pool group for FULL + SWA + MAMBA** (`linker_pool_assembler.py`, `hybrid_pool_assembler.py`)
- `_MambaSwaStrategy.build_direct_linker_pool_group`: the full-attention and SWA MHA pools each pack a layer's K and V into one page object; the Mamba pool is slot-addressed (one row per state slot, the empty temporal state of conv-only models is skipped).
- Rejected at startup with a clear error: `--enable-unified-memory`, int8 Mamba checkpoints, scaled KV caches, and Mamba side states (PLE). Non-dense rows are rejected too.

**Mamba component** (`components/mamba.py`)
- OFFLOAD / LOOKUP / LOAD transfers: one state per checkpoint node, keyed by the node's last page hash under `TRAILING_PAGES`, so a prefix is restorable only where a stored state ends.
- COMMIT copies the loaded node state into the request's own slot. Without this step the KV is restored to length L while the request continues from a shorter prefix's state (or a cleared slot). The forward's COW waits on the linker counter's last Mamba layer before reading the slot.
- When the node already holds a state (`mamba_exist`, e.g. two requests restoring the same prefix in one round), COMMIT frees the loaded slot before the copy, so the copy can reuse it when the Mamba pool is full.
- LOAD allocates through `_alloc_mamba_slot(required=False)` and returns `None` when no slot can be allocated, so the wrapper aborts and recomputes.

**Wrapper** (`unified_cache_linker.py`, `components/base.py`)
- Accept `ComponentType.MAMBA`.
- `TreeComponent.linker_indices_are_paged` (False for Mamba): COMMIT skips adopted-range page slicing for slot-addressed state.
- The Mamba component, not the wrapper, releases the loaded slot when the node already holds a state.

**Mooncake keys** (`mooncake_store.py`)
- A linker `DevicePoolEntry` always maps to one object per page per pool (`_k` for KV, `_{pool}` otherwise). Keys for the existing DeepSeek-V4 / DSA linker pools are unchanged: those groups are rank-replicated and already took the MLA single-object branch.

**Rust tree core**
- Drop the Mamba rejection in `set_enable_external_cache_linker` (now a plain setter) and add `MambaComponent::build_external_linker_offload_transfer`.

**Tests**
- `test_mamba_state_round_trips_only_at_its_checkpoint` (Python and Rust tree cores): OFFLOAD keys, a prefix restorable only at its stored state, LOAD and the COMMIT copy.
- `test_mamba_load_onto_existing_state_reuses_its_slot`: two requests match the same stored prefix before either loads, with exactly three free Mamba slots; the second COMMIT hits `mamba_exist`. Python and Rust tree cores. Negative control: copying before the free fails with `Can not alloc mamba cache` on both cores.

## Accuracy Tests

New `test_unified_cache_linker_kl_inkling.py` (tiny `thinkingmachines/Inkling --revision test`, Mooncake, `--enable-deterministic-inference`). This checkpoint scores every token identically in prefill and decode, so the threshold is a 1e-9 floor, not a tolerance.

`test_load_back_after_flush`: turn 1 offloads, `/flush_cache` drops the device tree, turn 2 restores from Mooncake alone (asserts `cached_tokens_details.host == cached_tokens`). 6/6 requests restore 1152 tokens; avg KL 0.0.

Rerun at the PR head on 1x H200 (Mooncake over RDMA): 6/6 requests restore 1152 tokens from Mooncake, avg KL 0.0.

- Negative control: skipping the Mamba load in COMMIT gives avg KL 5.6e-4, so the test detects a wrong restored state.
- Also checked locally, not added to CI: the same test on the Rust tree core and with `--tp-size 2` (each rank reads and writes its own `tp{rank}` keys), KL 0.0; a 3-turn branching workload with a device pool smaller than one round (13 of 18 requests restored from Mooncake), KL 0.0.
- Regression at the PR head: linker / pool-assembler / Mooncake / Mamba unit tests 99/99; unified radix cache unit suites, Python entry 1313 passed and Rust entry 2866 OK; `cargo test --lib` 921 passed; the existing `test_unified_radix_cache_kl_hybrid_bitexact.py` Python classes 9/9 (KL 0.0, run before rebasing onto the current main).

## Known limitations

- Not covered: FULL + Mamba without SWA, the UMBP (mori) backend, unified memory, scaled KV.
- A Mamba checkpoint attached to a node that is already stored externally (e.g. a split / branching point) is not offloaded again; this loses a hit but does not affect correctness.
- A batch that loads a Mamba state waits for the whole load before its forward starts (no per-layer overlap).
- A request with no Mamba slot needs a second slot for its private copy at COMMIT; if the pool and its evictable states are exhausted there, it asserts like HiCache's `prepare_load_back` instead of aborting.

Related: #39511 (FULL + Mamba on UMBP for Kimi K3); the pool group, UMBP and DCP parts there are complementary to this PR.
