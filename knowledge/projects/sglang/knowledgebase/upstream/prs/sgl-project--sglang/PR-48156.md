## Motivation

<!-- Describe the purpose and goals of this pull request. -->
When `--enable-unified-memory` is used with HiCache, host compaction reclaims fragmented space for reuse across sub-pools.

The GPU-side implementation minimizes movement by filling holes with live pages from the boundary being released. The host-side implementation instead repacks live pages in physical order. A single hole near the start of the packing order can therefore cause almost every remaining live page to be copied, even when most pages could stay in place.

These unnecessary copies increase host allocation latency when compaction is required. This PR brings the same minimal-movement strategy to host compaction

## Modifications

<!-- Detail the changes made in this pull request. -->

* Compute the final packed region from the live page count and growth direction.
* Fill only the holes inside that region, using live pages from the boundary being released.
* Leave live pages already inside the final packed region in place.
* Update logical-to-physical and physical-to-logical mappings in place.

For a final packed region containing H holes, the new implementation moves exactly H pages. Physical page order may change, but logical page identities and payloads are preserved.

For example, for an upward-growing pool:

| | Physical page layout | Pages moved |
|---|---|---:|
| Before compaction | `[A, hole, B, C, D]` | — |
| Previous implementation | `[A, B, C, D, free]` | 3 |
| New implementation | `[A, D, B, C, free]` | 1 |

The previous implementation shifts B, C, and D. The new implementation moves only D into the hole, leaving B and C in place while reclaiming the same amount of space.

Both growth directions are supported. The existing synchronization is unchanged.
