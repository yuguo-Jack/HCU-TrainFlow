# [Perf] [NVIDIA] fp8: Add Triton block-fp8 GEMM configs for RTX PRO 5000

[Upstream PR](https://github.com/sgl-project/sglang/pull/45263) · state: open · merged: False

## Original PR description

## Motivation
SM120 defaults to the Triton w8a8 block-fp8 kernel. RTX PRO 5000 has no tuned configs, so every DeepSeek-V4.1-Flash dense linear falls back to the default config.

## Modifications
Adds 8 tuned configs (`block_shape=[32, 32]`, `NVIDIA_RTX_PRO_5000_72GB_Blackwell`) for the V4.1-Flash dense shapes.

## Accuracy Tests
Configs only. GSM8K 0.899 (default configs) vs 0.905 (tuned configs).

## Speed Tests and Profiling
8x RTX PRO 5000 72GB, DP8 attention + EP8, default Triton FP8 GEMM backend:

| Metric | Default | Tuned | Change |
|---|---|---|---|
| 32K/1K saturation | 0.639 req/s | 0.743 req/s | +16% |
| 3K/100 saturation | 7.64 req/s | 8.89 req/s | +16% |
| Single-request 32K prefill | 7798 tok/s | 10801 tok/s | +38% |
| bs1 TPOT | 57.6 ms | 23.2 ms | 2.5× |

Kernel example, 1792×5120 at M=1: 90.5 → 19.4 us.

### Validation of the combined branches
I validated a clean tree: upstream `a90e9c5d` plus #42371 plus this PR and the three companion SM120 PRs (DeepGEMM metadata, b12x MXFP8, mHC BLOCK_K, RTX PRO 5000 configs). It ran on 8x RTX PRO 5000, DP8 attention + EP8, with `--fp8-gemm-backend flashinfer_cutlass`:
