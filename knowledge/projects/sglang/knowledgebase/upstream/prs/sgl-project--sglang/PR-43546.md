# [Fix] Hard watchdog: log and send SIGQUIT even if diagnostics hang

[Upstream PR](https://github.com/sgl-project/sglang/pull/43546) · state: open · merged: False

## Original PR description

Fixes #43205

## Motivation
On timeout, `WatchdogRaw._watchdog_once()` ran `dump_info()` and `pyspy_dump_schedulers()` before logging the timeout and before sending SIGQUIT to the parent. If a diagnostic blocked (e.g. a CUDA sync / `.tolist()` on a wedged GPU) or raised, the timeout was never logged and the hard watchdog never fired.

## Changes
- Log the watchdog timeout first.
- Run diagnostics in a daemon thread, joined with a bounded timeout (`_DIAGNOSTICS_TIMEOUT_S = 60.0`); exceptions are caught and logged, and a timeout is logged if they don't finish.
- Then send SIGQUIT (hard watchdog) regardless of how diagnostics ended. The existing 5s delay before SIGQUIT is kept as `_SIGQUIT_DELAY_S`.
- New CPU unit test `test/registered/unit/utils/test_watchdog_raw.py`: normal path, diagnostic that blocks forever, diagnostic that raises, and soft watchdog (no SIGQUIT). The parent process is mocked, nothing is actually signaled.

## Testing
```
PYTHONPATH=python python -m pytest -q test/registered/unit/utils/test_watchdog_raw.py test/registered/unit/utils/test_subprocess_watchdog.py
# 10 passed in 8.30s
pre-commit run --files python/sglang/srt/utils/watchdog.py test/registered/unit/utils/test_watchdog_raw.py
# all passed
```
Without the fix, the blocking/raising tests fail.
