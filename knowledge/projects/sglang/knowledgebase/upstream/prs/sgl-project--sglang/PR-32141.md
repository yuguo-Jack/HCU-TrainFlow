# [models] Support --load-format dummy for KimiLinearForCausalLM

[Upstream PR](https://github.com/sgl-project/sglang/pull/32141) · state: closed · merged: False

## Original PR description

## Motivation

`--load-format dummy` crashes for `KimiLinearForCausalLM`. Loaders that bypass `model.load_weights()` — `DummyModelLoader`, sharded-state, remote — run the post-load fixup via `_post_load_weights()` in `model_loader/loader.py`, which only calls `model.post_load_weights()` when that method exists. `KimiLinearForCausalLM` inlined the MLA `w_kc`/`w_vc` extraction at the tail of `load_weights()` and defined no `post_load_weights()`, so under dummy load the extraction never runs and the server crashes at the first MLA forward with `w_kc is None`. Other MLA models (deepseek_v2 family, kimi_k25, ...) already expose `post_load_weights()` for this reason.

## Modifications

- `kimi_linear.py`: move the `w_kc`/`w_vc`/`w_scale` extraction (unchanged) from the tail of `load_weights()` into `KimiLinearForCausalLM.post_load_weights()`; `load_weights()` still calls it. Real checkpoint loading is byte-for-byte identical; dummy / sharded-state / remote loaders pick it up through `_post_load_weights()`. The method is idempotent.
- Add `test/registered/unit/models/test_kimi_linear.py`: parity of the extracted `w_kc`/`w_vc` vs. the previous inline code, idempotence, and that the loader-side `_post_load_weights()` hook reaches the fixup (this test fails on `main`).

## Accuracy Tests

No change to real-checkpoint behavior (extraction code identical, same call site). CPU unit tests pass.
