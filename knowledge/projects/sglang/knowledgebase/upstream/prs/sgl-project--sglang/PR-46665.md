# [Feat] grpc: Add standard health checks to the native server

[Upstream PR](https://github.com/sgl-project/sglang/pull/46665) · state: open · merged: False

## Original PR description

## Motivation

The native Rust `sglang.api.v1` listener has a custom health RPC but does not expose the standard `grpc.health.v1` service used by gRPC health clients. This implements the native health item in #38075; it does not implement that tracker's Shutdown item or modify the Python-backed `runtime.v1` frontend.

## Modifications

- Register standard `Check` and `Watch` beside the existing service, for the empty service name and `sglang.api.v1.SglangService`.
- Share one demand-driven monitor across known-service clients, cache completed results for five seconds, and stop probing when demand disappears. Unknown names do not submit scheduler work.
- Reuse the core's scheduler-activity probe, with an outer timeout covering preparation and admission as well as response activity. Handle client cancellation, monitor closure and listener shutdown without leaving a cached `SERVING` result indefinitely.
- Document the endpoint scope, probe cost, timeout and freshness behavior. The custom `HealthCheck` RPC is unchanged.

Health here means startup readiness plus observed scheduler output activity. A synthetic one-token request is submitted; other requests' output can satisfy the probe. This is listener-local health, not a fleet-wide, capacity or drain guarantee. An established Watch can retain old `SERVING` for five seconds plus the configured timeout, subject to runtime scheduling delay.

## Accuracy Tests

No model/kernel output changes. The complete native gRPC module passes **32 tests**, including **12 new health tests**. These exercise actual tonic clients, `CoreHandle`, Dispatcher acknowledgements, stall/recovery, shared demand, deterministic cache/cadence boundaries, blocked admission, disconnect cancellation, monitor-closure ordering and both listener shutdown paths. Scheduler events are controlled CPU fixtures; this is not a GPU/model-inference validation claim.

Validation also passes workspace formatting, scoped server Clippy including tests, workspace Clippy, `sglang-mm` Python/parallel Clippy, and radix-tree all-targets `tch/doc-only` Clippy. Documentation `mint broken-links` and full `mint validate` pass; the latter used a documented tool-cache-path-only adapter to keep its pinned renderer outside personal state, without altering validation checks.

The unchanged full-repository `pre-commit run --all-files --verbose --show-diff-on-failure` passed: **31 hooks passed, two had no matching files, zero failures**, with no automatic file changes. The guide-pinned Mint 4.2.559 link check also passed with `--check-anchors --check-redirects`.

## Speed Tests and Profiling

No throughput improvement is claimed. The new standard service shares probes and stops submitting them without known-service demand, but each probe has real scheduling cost and can wake an idle scheduler. Hardware/model profiling remains unperformed.
