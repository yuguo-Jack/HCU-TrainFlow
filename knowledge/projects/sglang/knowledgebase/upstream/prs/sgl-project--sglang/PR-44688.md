# [HiCache] Support partial transfer groups for GLM-5.3

[Upstream PR](https://github.com/sgl-project/sglang/pull/44688) · state: open · merged: False

## Original PR description

## Motivation

GLM-5.3 can hit the following warning when HiCache selects the CUDA
register-based transfer kernel:

```text
Unsupported element_size = 576 for JIT HiCache kernel
```

A 576-byte KV row contains four complete 128-byte transfer groups and a
64-byte tail. The current CUDA register-kernel capability check rejects
that tail and falls back to the AOT transfer kernel, even though the row
is aligned to the vector package used by each lane.

This PR makes the register kernel handle the partial final group. It
does not change TMA selection, transfer layouts, or ROCm copy-round
selection. On upstream revisions with TMA transfers enabled, the
existing TMA route remains available; this fix covers the register
route when TMA is disabled or not applicable.

## Modifications

- Copy complete transfer groups with the existing unrolled, branch-free
  loops; predicate only the lanes responsible for the final partial group.
- Allocate local storage for the full groups plus the optional tail, and
  apply the same bounds to both loads and stores.
- Admit CUDA rows divisible by the selected 4-, 8-, or 16-byte vector
  package rather than requiring a multiple of 128 bytes.
- Preserve the existing ROCm narrow-round selection and block quotas.
- Add the 576-byte shape to correctness tests and the benchmark matrix.
  The tests represent it as 288 BF16 values; the transfer kernel copies
  bytes and does not depend on the model's KV quantization format.
- Slice benchmark buffers to the required element count before reshaping,
  so the new 288-element case does not require the backing allocation to
  be divisible by 288.
- Explicitly disable TMA in the register-kernel correctness tests so a
  TMA-capable GPU cannot mask a regression in this path.

## Accuracy Tests

Tests run on one NVIDIA B200 on October 16, 2026, using the upstream
checkout plus this patch:

- CPU copy-round regression: **7 passed**, including **1,945 subtests**.
- HiCache round-trip and staged write-back tests: **56 passed**.
- Dedicated page-first staged write-back tests: **18 passed, 2 skipped**.
  The skipped tests require `get_device_accessible_ptr`, which is absent
  from the installed AOT kernel package. The skips are unrelated to this
  patch and were not weakened or removed.
- `compute-sanitizer --tool memcheck --target-processes all
  --error-exitcode 1` on the 576-byte and staged-only-alignment cases:
  **11 passed; ERROR SUMMARY: 0 errors**.
- The two new 576-byte MLA round-trip cases fail on the unmodified
  upstream baseline and pass with the patch, confirming that the tests
  exercise the actual unsupported-size regression.
- Benchmark outputs are checked against the source tensors with
  `rtol=0, atol=0` for both AOT and JIT providers.

No model-level GLM-5.3 accuracy benchmark was run for this upstream
patch. The change only copies KV bytes; the results above verify
bit-exact transfers, including write-back and load-back.

## Speed Tests and Profiling

**Environment:** one otherwise idle NVIDIA B200, driver 580.82.07,
PyTorch 2.13.0+cu130, CUDA 13.0, Python 3.12; measured October 16, 2026.
Upstream baseline: `81f2b43ab512cbc1e2ca0aef97b93e224d400a69`.

**Method:** 576-byte MLA rows in pinned host memory, layer-first layout,
page size 16, 524,288-token pools, default register-kernel block quota 2.
H2D copies one layer; D2H copies eight layers. Each CUDA graph rotates
through 32 random page-index pairs; timings are the median of 120
CUDA-event samples after 10 warm-up replays. Provider order is balanced
across forward/reverse cyclic permutations. AOT and JIT use the same
buffers and indices. TMA is disabled to isolate the affected path.

| Direction | Tokens | AOT latency (us) | JIT latency (us) | Speedup | JIT payload bandwidth (GB/s) |
| --- | ---: | ---: | ---: | ---: | ---: |
| H2D, one layer | 128 | 9.73 | 4.11 | 2.36x | 17.92 |
| H2D, one layer | 1,024 | 64.63 | 15.83 | 4.08x | 37.27 |
| H2D, one layer | 8,192 | 500.83 | 118.64 | 4.22x | 39.77 |
| D2H, eight layers | 128 | 12.77 | 12.42 | 1.03x | 47.51 |
| D2H, eight layers | 1,024 | 179.75 | 106.04 | 1.70x | 44.50 |
| D2H, eight layers | 8,192 | 1,488.04 | 972.80 | 1.53x | 38.80 |

Bandwidth is transferred payload divided by elapsed time, in decimal
GB/s; it does not count the payload twice as read-plus-write traffic.

**Aligned-size regression check:** the baseline and patched JIT kernels
also run in the same process on identical buffers, with balanced provider
ordering. Across 512- and 1,024-byte rows, both directions, and all three
token counts, patched median latency differs from baseline by **-0.035%
to +0.204%**. For 512-byte MLA rows, all four per-layer/all-layer and
int32/int64-index specializations have identical SASS instruction hashes.
Earlier unbalanced runs showed a large-transfer D2H timing difference;
balancing provider positions removed it. Those exploratory runs are not
used for the reported comparison.

The repository's registered benchmark also completes for both CI shapes,
including the new 288-BF16-element case:

```bash
CUDA_VISIBLE_DEVICES=0 SGLANG_HICACHE_TMA_TRANSFER=0 SGLANG_IS_IN_CI=1 \
  DISABLE_TORCH=1 PAGE_SIZE=16 PYTHONPATH="$PWD/python" \
  python3 test/registered/kernels/benchmark/kvcache/bench_hicache.py
```

That benchmark intentionally invokes its explicit `tma` provider even
when runtime TMA routing is disabled. Its MHA timings are not mixed with
the MLA microbenchmark results above.

These are transfer-kernel microbenchmarks, not end-to-end GLM-5.3
serving throughput claims. Earlier downstream live-load measurements
are intentionally not used here because their request mixes differ.

# GLM-5.3 HiCache partial-transfer-group benchmark

## Scope and revisions

Measured on October 16, 2026. This report accompanies the community port
of downstream commit `8d9011f6d0ea94700e33331ecf59102a44b28122`.

- Community baseline: `81f2b43ab512cbc1e2ca0aef97b93e224d400a69`.
- Final patch: `community.patch`, covering six existing files.
- Authoritative measurement: `balanced-benchmark.json`.
- Benchmark implementation: `bench_hicache_mla_pr.py`.
- Raw timings and correctness assertions: `balanced-benchmark.log`.

The target checkout remains on `main` with uncommitted changes. No commit,
branch, push, PR creation, existing deployment replacement, or model
server launch was performed.

## Environment and methodology

- One NVIDIA B200 on the prefill node; all eight GPUs were idle at setup.
- NVIDIA driver 580.82.07, PyTorch 2.13.0+cu130, CUDA 13.0, Python 3.12.
- Pinned host memory and BF16 tensors; a 288-value row is exactly 576 bytes.
  This models the byte-copy size, not GLM-5.3 model arithmetic.
- Layer-first layout, 524,288-token pools, 16-token pages; GPU 0 only.
- Default register-kernel block quota 2; `SGLANG_HICACHE_TMA_TRANSFER=0`.
- H2D copies one MLA layer; D2H copies eight MLA layers.
- 32 random page-index pairs rotate through each CUDA graph. The providers
  share all buffers and indices; no provider-specific allocations are used.
- 10 warm-up graph replays per provider and 120 measured replays. Each
  graph replay contains 32 transfers. CUDA-event elapsed time is divided
  by 32 to report per-transfer median latency.
- Provider positions are balanced through cyclic rotations of forward
  and reverse orders, rather than always measuring the same provider
  immediately after a particular predecessor.
- Bandwidth is decimal transferred-payload GB/s, not read-plus-write GB/s.
- Every provider is checked against source values with `rtol=0, atol=0`.
- Baseline JIT specializations for aligned sizes are loaded from the
  unmodified upstream header under a distinct module identity, in the
  same process as the patched JIT specializations.

## Aligned-size JIT regression check

The delta is `(patched / baseline - 1) * 100`; positive means slower.
The exact values in JSON are used for deltas, before table rounding.
The full-precision delta range is -0.034739% to +0.203875%.

| Row bytes | Tokens | Direction | Baseline JIT (us) | Patched JIT (us) | Latency delta |
| --- | ---: | --- | ---: | ---: | ---: |
| 512 | 128 | H2D | 3.924 | 3.932 | +0.20% |
| 512 | 128 | D2H | 13.523 | 13.521 | -0.01% |
| 512 | 1,024 | H2D | 12.799 | 12.803 | +0.03% |
| 512 | 1,024 | D2H | 80.074 | 80.122 | +0.06% |
| 512 | 8,192 | H2D | 84.098 | 84.149 | +0.06% |
| 512 | 8,192 | D2H | 756.710 | 756.846 | +0.02% |
| 1,024 | 128 | H2D | 5.283 | 5.288 | +0.09% |
| 1,024 | 128 | D2H | 20.116 | 20.134 | +0.09% |
| 1,024 | 1,024 | H2D | 23.026 | 23.019 | -0.03% |
| 1,024 | 1,024 | D2H | 159.270 | 159.256 | -0.01% |
| 1,024 | 8,192 | H2D | 165.941 | 165.936 | -0.00% |
| 1,024 | 8,192 | D2H | 1,293.250 | 1,293.530 | +0.02% |

For 512-byte MLA rows, the final and baseline SASS instruction hashes
match in all four specializations: per-layer/all-layer and int32/int64
indices. See `sass-comparison.json` and `sass-comparison.log`.

Earlier separate-process or unbalanced-provider measurements exhibited
approximately 7% large-transfer D2H differences despite identical SASS.
The balanced same-buffer comparison removes that difference. The earlier
JSON/logs are retained as exploratory evidence, not presented as final
results: `base-benchmark`, `patched-benchmark`, `base-repeat-benchmark`,
`final-benchmark`, and `shared-buffer-benchmark`.

These measurements support no measurable aligned-size regression in
this microbenchmark; they are not a guarantee for every platform or
workload. Small 512-byte D2H transfers still favor AOT over JIT in this
setup, as they already did before the patch.

## Reproduction

The script supports any checkout containing this patch. To include the
aligned-size comparison, first extract the baseline header from that
checkout's Git history:

```bash
cd /path/to/patched/sglang
git show 81f2b43ab512cbc1e2ca0aef97b93e224d400a69:python/sglang/kernels/jit/csrc/kvcacheio/hicache.cuh \
  > /tmp/hicache-upstream-base.cuh

CUDA_VISIBLE_DEVICES=0 SGLANG_HICACHE_TMA_TRANSFER=0 PYTHONPATH="$PWD/python" \
  python3 /path/to/bench_hicache_mla_pr.py \
  --label balanced \
  --baseline-source /tmp/hicache-upstream-base.cuh \
  --output /tmp/hicache-benchmark.json
```

Optional subsets use `--element-bytes 576` or
`--element-bytes 512 1024 --batch-tokens 8192`.

Run the repository benchmark with the reduced CI matrix:

```bash
CUDA_VISIBLE_DEVICES=0 SGLANG_HICACHE_TMA_TRANSFER=0 SGLANG_IS_IN_CI=1 \
  DISABLE_TORCH=1 PAGE_SIZE=16 PYTHONPATH="$PWD/python" \
  python3 test/registered/kernels/benchmark/kvcache/bench_hicache.py
```

The repository benchmark uses MHA buffers and explicitly invokes its
`tma` provider on SM90+ even when automatic runtime TMA routing is off.
Its numbers are not combined with the MLA table in this report.

The correction to backing-buffer slicing is required by the new
288-element shape: flatten, take the required number of elements, then
reshape. Without it, reshaping the entire 1,024-element backing allocation
as 288-element rows raises an invalid-shape error before any kernel runs.

All remote files are under `/tmp/sglang-hicache-pr-20261016`; the existing
deployment is untouched, and the benchmark processes release GPU 0.
