# [Perf] flashinfer: Add opt-in FP8 KV dequant for eager prefill

[Upstream PR](https://github.com/sgl-project/sglang/pull/46809) · state: open · merged: False

## Original PR description

## Motivation

FlashInfer FA2 paged prefill converts FP8 KV tiles during attention. For long KV and head dimension 256 on an RTX 5090, gathering the referenced KV once into temporary BF16 buffers can be faster, while the persistent pool and decode still use FP8.

This is a standalone, default-off implementation based on main `922e595a`. It does not include the MBO changes in #46771.

**Numerical limitation:** finite FP8 values convert exactly to BF16, but changing the attention kernel does not preserve the original FP8 kernel's rounding. Fresh end-to-end probes differ, including one first-token change. This PR does not claim losslessness or established quality equivalence.

## Changes

- Add a Triton gather/conversion kernel for NHD E4M3/E5M2 KV. It preserves referenced-page order and duplicates, supports non-packed page strides, and ignores the unused tail of an index buffer.
- Plan a BF16 paged wrapper over consecutive temporary page IDs. Use host-known token counts rather than reading a GPU indptr scalar. The twin shares the float workspace; no FlashInfer methods are monkey-patched.
- Gather after the current layer's KV write, then call the BF16 wrapper with the same attention arguments and K/V scales.
- Carry the optional plan in prefill metadata and clear it on fallback batches.
- Leave decode and the FP8 pool unchanged. Restrict the path to BF16 Q, plain FP8 KV, FA2, and a single paged wrapper. Ragged, speculative metadata, custom/multi-item masks, sliding-window/cross-attention wrapper dispatch, deterministic mode, FP4 workspaces and CUDA graph capture retain the existing path. Backend subclasses do not opt in automatically.

### Enable

```bash
SGLANG_PREFILL_KV_DEQUANT=1 SGLANG_FLASHINFER_USE_PAGED=1 \
python -m sglang.launch_server \
  --model-path RadixArk/Qwen3.8-27B-NVFP4 \
  --quantization modelopt_fp4 --tp-size 2 \
  --attention-backend flashinfer --kv-cache-dtype fp8_e4m3 \
  --page-size 256 --chunked-prefill-size 8192 --max-prefill-tokens 8192 \
  --mem-fraction-static 0.80 --context-length 131072 \
  --cuda-graph-backend-prefill disabled
```

The graph flag above selects the eager prefill path measured here; the feature does not redirect graph replay. Defaults:

| Variable | Default |
|---|---:|
| `SGLANG_PREFILL_KV_DEQUANT` | `False` |
| `SGLANG_PREFILL_KV_DEQUANT_MIN_TOKENS` | 1024 |
| `SGLANG_PREFILL_KV_DEQUANT_MIN_KV_TOKENS` | 16384 |
| `SGLANG_PREFILL_KV_DEQUANT_MAX_KV_TOKENS` | 262144 |

KV thresholds count referenced slots across requests, including duplicates. Temporary K+V storage is `slots * KV_heads * head_dim * 4` bytes for equal K/V dimensions: 256 MiB at the maximum for one KV head / dimension 256, plus wrapper workspaces. It consumes runtime headroom even though the persistent pool is unchanged. SGLang's FlashInfer view uses one-token pages, independently of the allocator page size.

## Fresh performance measurement

RTX 5090 / SM120, torch 2.14.1+cu130, sglang-kernel 0.4.9, FlashInfer 0.7.2, Triton 3.8.0. Single full-attention layer, BF16 Q, E4M3 KV, 6 Q heads / 1 KV head / dimension 256, 40,960-token prefix + 4,096 new tokens, FlashInfer page size 1 and shuffled pool locations. Scales: K=0.75, V=1.5.

CUDA events, three warmups, five rounds of ten calls, rotating the order; median round latency:

| Path | ms |
|---|---:|
| Original FP8 paged kernel | 8.936 |
| BF16 pool reference | 6.750 |
| FP8 gather/conversion + BF16 kernel | 6.779 |
| Gather/conversion alone | 0.043 |

The combined path reduced this layer's time by **24.1%**. Its output was bit-identical to the BF16-pool reference and differed from the original FP8 kernel. Temporary K+V buffers were 44 MiB for this shape. This is not an end-to-end throughput claim.

## Correctness and service probes

- New GPU tests: E4M3/E5M2 × page sizes 1/16/256, multiple unequal request lengths, partial last pages, shuffled and duplicated page IDs, oversized index buffers, interleaved K/V storage, and non-unit K/V scales. Gathered tensors, attention output and LSE match a BF16 copy of the same FP8 pool exactly.
- An actual FlashInfer backend fixture verifies routing to the BF16 wrapper, retaining an FP8 pool, and returning to the FP8 wrapper on the following short batch.
- New CPU tests cover thresholds, unsupported masks/dtypes, ragged/speculative/graph fallback, preserving plan options, and reusing the twin without retaining an enabled plan on fallback.
- Existing dense and speculative-verify regressions passed. Total executed: **8 tests / 39 subtests**. Pre-commit and whitespace checks passed.
- TP2 on 2× RTX 5090, public NVFP4 checkpoint above, E4M3 KV, MEM=0.80, 8192-token chunks; both arms used eager prefill and retained 487,936 KV tokens. Each arm completed 12 fixed-16-output-token requests: 1k/8k/16k/32k/64k cold inputs, a 32k prefix with 16k new input, a repeat hit, and c4×16k. Cache counts and output lengths were checked. Neither arm logged allocator-retry warnings or a serving traceback before deliberate shutdown.
