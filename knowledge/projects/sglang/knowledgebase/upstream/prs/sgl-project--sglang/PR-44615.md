## Motivation

<!-- Describe the purpose and goals of this pull request. -->

When prefill attention TP is smaller than decode attention TP (e.g. TEP4 prefill -> TEP8 decode), each decode rank holds only part of a prefill rank's KV heads, so the prefill rank sends each of those decode ranks a head slice of its full-attention KV and SWA state.

Currently, each NIXL descriptor moves one small per-token head-slice region, per layer and per K/V. At high concurrency, posting that many small transfers becomes the bottleneck.

This PR gathers each decode rank's head slices into a contiguous GPU buffer first, so each descriptor moves a whole destination page. The speedup comes from page-sized transfers replacing per-token head-slice transfers.


## Modifications

<!-- Detail the changes made in this pull request. -->
Optional KV packing on prefill (`SGLANG_ENABLE_NIXL_KV_PACKING=1`, default off):

- `disaggregation/nixl/packed.py`: `PackedKVSender` gathers a decode rank's head slice of each page into a registered GPU buffer (`SGLANG_NIXL_KV_PACK_BUFFER_SIZE_MB`, default 64) with the existing staging Triton gather kernel, then posts one transfer request per batch with one page-sized descriptor per tensor and page.
- `disaggregation/nixl/conn.py`: one packer per transfer worker. When prefill attention TP < decode attention TP, full-attention KV and SWA state go through the packer; equal TP and prefill TP > decode TP keep the existing paths. The transfer worker now honors the early-send `wait_event`, as Mooncake does.
- `disaggregation/utils.py`: `kv_packable` marks SWA hybrids whose full and SWA pools are NHD `MHATokenToKVPool`s with equal K/V head dims and the same head count, without draft KV (each pool is gathered with one page size, and both are sliced with the full-attention head count).
- `environ.py`: the two variables.
