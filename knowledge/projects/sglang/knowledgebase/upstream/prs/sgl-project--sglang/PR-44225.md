# [Fix] [XPU] gemma3: Enable bidirectional image attention

[Upstream PR](https://github.com/sgl-project/sglang/pull/44225) · state: closed · merged: True

## Original PR description

…-xpu

Gemma-3 image tokens attend bidirectionally in prefill (text stays causal). On the intel_xpu backend they ran plain-causal, degrading vision tasks (docvqa_val ANLS 59.4 on B60 vs 65.0 on H200). Use the sgl-kernel-xpu bidirectional_block_ids prefill mask (kernel-side) rather than a Python attention fallback:

- gemma3_mm.prepare_attn_masks: for XPUAttentionBackend build a per-token image-block id over whole sequences (image index, -1 for text) and store it on the backend (is_xpu()-guarded lazy import; Triton path unchanged). None when this extend holds fewer than two tokens of any image.
- xpu_backend.forward_extend: when present, run non-causal and pass bidirectional_block_ids to flash_attn_with_kvcache; the kernel re-imposes causal for text and keeps image tokens bidirectional. With a cached prefix (radix hit or a later chunk) pad q to whole sequences so the kernel sees a full prefill, then keep the extend rows. On sliding-window layers drop the window only when it cannot clip a key; longer prompts keep local attention.
- layernorm.forward_xpu: make the input contiguous before gemma_rmsnorm (it requires a contiguous last dim, which a sliced hidden state may not have), so Gemma-3 loads on XPU.
- test/registered/xpu/test_xpu_gemma3_bidirectional_attn.py: sliding-window bound and image-after-cached-prefix against a dense reference.

Requires the companion sgl-kernel-xpu bidirectional_block_ids kernel. docvqa_val (full 5349) 59.4 -> 67.5 on Intel Arc Pro B60, above H200 (65.0).
