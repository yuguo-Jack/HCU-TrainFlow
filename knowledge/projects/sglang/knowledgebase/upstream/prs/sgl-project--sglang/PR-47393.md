# fix(multimodal): preprocess images on the CPU with several tokenizer …

[Upstream PR](https://github.com/sgl-project/sglang/pull/47393) · state: closed · merged: False

## Original PR description

…workers

With --tokenizer-worker-num N > 1 every worker ran the fast image processor on the serving GPU and opened its own CUDA context next to the scheduler's static memory pool. On a 32 GB GPU with 16 workers, concurrent image requests failed with CUDA_ERROR_OUT_OF_MEMORY or CUDA_ERROR_ALREADY_ACQUIRED and HTTP 500. Several workers now leave the fast processor on the CPU, where they are real preprocessing parallelism; a single worker keeps the GPU path

Enabled on NVIDIA GPUs only (is_cuda()), where it was measured; other devices keep the previous behavior.
