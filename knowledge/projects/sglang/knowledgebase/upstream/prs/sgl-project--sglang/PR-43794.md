# [NPU DSV4]Preserve DeepSeek-V4 SWA cap mode with model-default ratios

[Upstream PR](https://github.com/sgl-project/sglang/pull/43794) · state: open · merged: False

## Original PR description

## Motivation

DeepSeek-V4 model overrides populate `swa_full_tokens_ratio=0.1` before cache compatibility handling. The hook currently treats any resolved non-`None` ratio as explicitly supplied by the user. As a result, omitting `--swa-full-tokens-ratio` still disables request-cap sizing, and `--swa-prefix-tails` cannot reserve additional SWA capacity even when the other cap-mode conditions are satisfied.

For example, a paged SWA configuration with `--max-running-requests 4` and chunked prefill should remain eligible for cap mode when the ratio flag is omitted, even though the model supplies a default ratio.

## Modifications

- Determine `_swa_full_tokens_ratio_explicitly_set` from `server_args._raw_input`, preserving the distinction between user input and model defaults.
- Keep explicitly supplied ratios in ratio-sizing mode, including `0.1`, which equals the model default. Continue validating the effective ratio and rejecting negative prefix tails.
- Add CPU regression tests covering CUDA/NPU configuration paths, model defaults and resets, explicit ratios, fallback behavior, runtime publication, serialization, and invalid inputs.

## Accuracy Tests

- Before the fix, 2 of the 8 new regression tests failed because model-default ratios were marked explicit. After the fix, all 18 tests passed across the new test file and the existing fallback/raw-input tests.
- Ruff lint/format checks, isort, and `git diff --check` passed.
- Ascend A3 runtime validation used TP=2, a reduced DeepSeek-V4 configuration (6 layers, 8 experts, dummy weights), and radix caching. With `max-running-requests=4`, `chunked-prefill-size=512`, `max-total-tokens=65536`, and window/page sizes of 128:

| Configuration | SWA token capacity |
| --- | ---: |
| Ratio omitted, prefix tails = 0 | 3200 |
| Ratio omitted, prefix tails = 8 | 5248 |
| Explicit ratio = 0.1, prefix tails = 8 | 6528 |

The cap-mode capacity increase is `2048 = 8 × (window + page)`; explicitly supplying the ratio continues to select ratio sizing.

All 110 inference requests across 50 groups passed, covering cold/hot prefix reuse, branching prefixes, concurrent requests, and cache pressure. Compared output token IDs matched, and compared final-prefill logits had a maximum absolute difference of 0.0. A separate decode full-graph configuration passed with 56 actual graph replays.

Validation limits: CUDA was tested only through configuration logic, and full-checkpoint inference was not tested. Prefill BCG capture failed with `loc=None` in the NPU C4 index-cache write path; the successful inference runs used eager prefill.

## Speed Tests and Profiling

No inference-speed benchmark was performed. Runtime validation measured SWA pool capacity and checked inference consistency.
