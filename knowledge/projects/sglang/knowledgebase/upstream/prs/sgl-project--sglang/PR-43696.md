# [Feat] comfyui: Add SGLDCacheOptions for per-run Cache-DiT

[Upstream PR](https://github.com/sgl-project/sglang/pull/43696) · state: open · merged: False

## Original PR description

Adds an `SGLDCacheOptions` node that turns Cache-DiT on or off for a single run from the graph. It sets the options on a cloned MODEL, so toggling it never restarts the worker. The executor reads them from `transformer_options` and maps them to the per-request `enable_cache_dit` and `cache_dit_params`. The loader option stays as the fallback, and a per-run on/off wins over it.

Only MiniMax-H3 supports it. Other models send one independent step per request, so there is no step history to reuse, and the node rejects them with an error. TeaCache is not exposed because its state resets on timestep 0.

This is meant to line up with slimming `SGLDOptions` down to load-time options. If #43504 lands first I will rebase onto its `model_options` path.

Tested on CPU only (`test_comfyui_adapters.py`, `test_comfyui_generator.py`, 44 passed). GPU unit run is in the comments.

E2E numbers. H100, ComfyUI v0.39.2, Flux.1-dev, 1024x1024, 25 steps, euler/simple, cfg 1, same seed, default DBCache settings (Fn=1 Bn=0 W=4 R=0.24 MC=3). The worker log confirms one context for the whole run: `cache-dit enabled on transformer (steps=25, ...)`.

| | prompt time | PSNR | SSIM |
|---|---|---|---|
| native ComfyUI | 4.62s | | |
| SGLD cache off | 3.64s | 25.37 dB vs native | 0.903 vs native |
| SGLD cache on | 2.01s | 18.08 dB vs cache off | 0.616 vs cache off |

That is 1.81x vs cache off. With these defaults the output drifts noticeably (layout shifts a bit, still a clean image), so the default threshold is on the aggressive side for 25 step Flux. The node exposes the DBCache knobs for a more conservative setting.

- OnePunchMonk · comment · 2026-10-12T16:29:54Z · [source](https://github.com/sgl-project/sglang/pull/43696#issuecomment-6128366975)

Follow-up with gentler DBCache settings, same H100 setup (Flux.1-dev, 1024x1024, 25 steps, same seed), compared against cache off:

- W8 R0.08: 1.37x, 22.5 dB PSNR / 0.81 SSIM
- W8 R0.12: 1.45x, 20.7 dB / 0.74
- W4 R0.12: 1.52x, 19.2 dB / 0.69
- Default W4 R0.24 (from above): 1.81x, 18.1 dB / 0.62

Every setting keeps a clean image, with the layout shifting more as the threshold goes up. To make sure the drift is Cache-DiT itself and not the per-run wiring, I checked that W25 (no caching possible) is bit-identical to cache off, and that a fresh mount and a later run with the same seed are bit-identical too.

The sweep also hit a crash when the knobs change between runs: cache-dit 1.5.1 leaves a class-level flag set after disable_cache on a bare transformer, so the remount asserted. Fixed in 7585fd52d9 with a regression test against the real cache-dit. This affects server requests that change cache_dit_params as well, not just ComfyUI.

Hi @OnePunchMonk, I pushed one commit on top of your branch (814256ec76) so CFG > 1 runs are cached instead of rejected:
