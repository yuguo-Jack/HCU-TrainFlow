# [CI] diffusion: Run the FLUX.2 XPU norm-fusion test on the XPU suite only

[Upstream PR](https://github.com/sgl-project/sglang/pull/46040) · state: closed · merged: True

## Original PR description

## Motivation

#41942 registered `test/registered/kernels/ops/diffusion/test_flux2_xpu_norm_fusions.py` on the CPU suite (`base-a-test-cpu`) as well as the XPU suite. Both of its CPU-runnable paths import `sglang.multimodal_gen.runtime.models.dits.flux_2`, which imports `diffusers`, and the CPU suite installs only `python[dev]`, without the `diffusion` extra. Every `base-a-test-cpu` partition that picks up the file fails with:

```
ModuleNotFoundError: No module named 'diffusers'
```

This now fails CPU CI on unrelated PRs, for example [#40479](https://github.com/sgl-project/sglang/actions/runs/39938364150/job/120363719922) and [#45785](https://github.com/sgl-project/sglang/actions/runs/39937459719).

## Modifications

- Drop the file's `register_cpu_ci` registration; it stays on `stage-b-test-1-gpu-xpu`.
- The Intel-Triton import regression still runs there: its subprocess blocks `triton.language.extra.intel`, so it simulates a host without Intel Triton on the XPU runner.
- The docstring now says why the file is XPU-only.

Skipping the CPU case when `diffusers` is missing would make it skip on every CPU run, and adding `diffusers` to the CPU suite's install would grow every CPU partition for one import check.
