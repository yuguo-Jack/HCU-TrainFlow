# [Fix] models: Fix Phi and Persimmon startup crash under breakable prefill CUDA graph

[Upstream PR](https://github.com/sgl-project/sglang/pull/44327) · state: open · merged: False

## Original PR description

## Motivation

On CUDA, breakable prefill CUDA graph is the default prefill graph backend. During capture, `PrefillCudaGraphRunner._run_forward` calls the decoder body positionally:

```python
output = self.layer_model.forward(input_ids, positions, forward_batch, **kwargs)
```

`PhiModel` and `PersimmonModel` declare `forward(input_ids, forward_batch, positions, inputs_embeds=None)`. Capture therefore passes the positions tensor as `forward_batch` and the `ForwardBatch` as `positions`. On default flags, Phi-1.5, Phi-2 and Persimmon crash during startup on main. Phi-1.5 also crashes the same way on the v0.5.21 release:

```
  File ".../model_executor/runner/prefill_cuda_graph_runner.py", line 850, in _run_forward
  File ".../models/phi.py", line 214, in forward
  ...
AttributeError: 'ForwardBatch' object has no attribute 'size'
```

Phi-2 fails the same way, through the JIT rotary kernel: `rotary_embedding_with_key() Expected a value of type 'Tensor' for argument 'positions' but instead found type 'ForwardBatch'`.

Eager prefill is unaffected, because `PhiForCausalLM` and `PersimmonForCausalLM` pass these arguments by keyword. `microsoft/phi-1_5` and `adept/persimmon-8b-chat` are both in the `test_generation_models.py` model list.

I checked the other decoder bodies under `python/sglang/srt/models` that use a different order. None of them reaches this call:
- `GlmImageTextModel`: its architecture is multimodal and not in `multimodal_breakable_cuda_graph_supported_model_archs`, so breakable prefill graph is disabled for it.
- `Mamba2Model` and `FalconMambaModel` have no attention layers, so prefill graph capture is skipped.
- `GLMTransformer` (ChatGLM) and `HrmTextStack` are not on the `.model` chain the capture setup resolves.

## Modifications

- Reorder `PhiModel.forward` and `PersimmonModel.forward` to `(input_ids, positions, forward_batch, inputs_embeds=None)`, the order the other decoder bodies use. The only callers pass keywords, so no call site changes.
- Add a regression test to `test_prefill_cuda_graph_runner_helpers.py`: both decoder bodies take `input_ids, positions, forward_batch` as their first three parameters, in that order.

## Accuracy Tests

Setup: one RTX 4090, `lmsysorg/sglang:nightly-dev-20261014-684fea8a` (main at `684fea8a`), with and without this patch. Each model ran through `SRTRunner` and `HFRunner` the way `test_generation_models.py` does: fp16, the short `DEFAULT_PROMPTS`, 32 new tokens. I compared this PR on default flags against main with `--disable-prefill-cuda-graph`.

| Model | Main, default flags | This PR vs main with eager prefill |
|---|---|---|
| `microsoft/phi-1_5` | startup crash | same output strings on 3/3 prompts; max prefill and decode top-logprob diff 0.0000 |
| `microsoft/phi-2` (`--attention-backend triton`) | startup crash | same output strings on 3/3 prompts; max diff 0.0000; 3/3 strings match Hugging Face |
| `adept/persimmon-8b-chat` (`mem_fraction_static=0.88`) | startup crash | same output strings on 3/3 prompts; max diff 0.0000 |

Phi-2 has head dim 80, so it also needs a non-FlashInfer attention backend on GPUs that use FlashInfer by default (#44238). On the default backend it fails even with prefill CUDA graph disabled. For Persimmon, `mem_fraction_static=0.88` lets its 18.8 GB of weights fit in 24 GB.

Against Hugging Face, this PR's outputs match main's eager prefill outputs exactly, so the change adds no numerical difference.

The phi-1_5 case of `test_generation_models.py` fails on main for reasons unrelated to this change, even with prefill CUDA graph disabled:
- its long prompt (6402 tokens) exceeds the model's 2048-token context;

That is why the accuracy check above compares directly against main's eager prefill.
