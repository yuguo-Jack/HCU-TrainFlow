# [DP] consistent_hash load-balance method with optional load-aware spill + repin

[Upstream PR](https://github.com/sgl-project/sglang/pull/40473) · state: closed · merged: False

## Original PR description

## Summary

Adds a new DP load-balance method **`consistent_hash`** for data-parallel attention, plus two independent, opt-in behaviors on top — **load-aware spill** (`--enable-dp-spill`) and **re-pin** (`--enable-dp-repin`). Fully gated: with defaults unchanged the DP controller behaves exactly as today.

## Motivation

With dp-attention, a session's turns want to stay on one dp_rank, but a long-prefill request can pile a huge uncached backlog on its home rank and head-of-line-block the short requests queued behind it → a p90–p99 **TTFT tail**. The existing DP methods don't address this: `round_robin` / `total_*` ignore session affinity, and there is no session-consistent method today.

### Why consistent-hash, and not a plain load-balance policy

This targets deployments on the unified external-cache **linker** (`--enable-unified-cache-external-linker`; the `[Unified Cache]` series — cache contract #37091, end-to-end integration #37381, and the **UMBP external linker #37578**). There, the dp_ranks of a DP group **share one node-local standalone KV store**. That shared store exists precisely to **cut cross-dp-rank traffic and stop ranks from evicting each other's KV**: any rank can reach any prefix, so per-rank content-prefix **cache-aware routing is unnecessary** and its migration thrash is actively harmful.

But a *pure* load-balance policy (`round_robin` / `total_*`) would **scatter a session's turns across ranks**, re-introducing exactly what the shared store is meant to avoid — multiple ranks touching the same session's KV → cross-rank traffic + mutual eviction. So the right **base** is a stateless **consistent-hash session→rank pin** (keeps each session's working set coherent on one rank against the shared store); load-awareness is added only as an **opt-in spill on top**, for when a rank is genuinely overloaded — not as the primary routing.

### Scope: an intra-node DP group

The shared standalone store is **node-local**, so the DP group that shares it must live within one node:
- single node: 8 cards (or, in future, 4 cards) → one 8-way (or 4-way) DP group over the node-local store — this method applies here;
- multi-node (e.g. 16 cards / 2 nodes): run **two independent 8-way DP groups (8 + 8)**, each over its own node-local store — **not** one 16-way DP group spanning nodes (that would force cross-node store traffic and defeat the purpose).

So `consistent_hash` + spill/repin is scoped to a per-node DP group. This is enforced in code: `--dp-spill-group-size` (default 8 = cards/node; set 4 for 4-GPU nodes) partitions dp_ranks into node-local groups `[0,size),[size,2*size),…` and a spill only considers ranks in the home rank's own group — so even a (discouraged) cross-node DP will not spill across the shared store.

## What this adds

`--load-balance-method consistent_hash`:
- **pin (always):** `home = blake2b(session_id or rid) % (active dp_ranks)`. Mirrors `follow_bootstrap_room`, but keyed on `session_id` and hashed over the *active* ranks. Stateless; reads no load.
- **`--enable-dp-spill`** (default off): when the home rank's `num_waiting_uncached_tokens` exceeds the least-loaded rank by a **relative** gap (`--dp-spill-gap-pct`, 0.30) + absolute floor (`--dp-spill-abs`, 8192), route to a less-loaded rank (anti-herding pick by hash), **restricted to the home rank's node group** (see `--dp-spill-group-size`) so a spill never crosses the node-local store. Signal = the existing shm `LoadSnapshot.num_waiting_uncached_tokens`.
- **`--enable-dp-repin`** (default on): a spilled session returns to its CH home once the home drains — home is recomputed every request, so the spill is transient and **no per-session migration state is kept (no migration storm)**. If off, the session sticks to the spilled rank (bounded `session→rank` map) until that rank also overloads.

Reuses existing infra only (`LoadSnapshot`, `DPBudget`, `load_snapshot_reader`); `refresh_load_budget_on_dispatch` is enabled for `consistent_hash` only when spill is on. No new subsystems; no load-monitor dependency when spill is off.

## Results

DeepSeek-V4-Pro, TP8+DP8 dp-attention, external-cache linker, conc128 agentic replay (3600 s). **Pure `consistent_hash` (baseline) vs `consistent_hash` + spill + repin:**

**TTFT (ms)** — the whole tail collapses:

| pct | CH baseline | CH + spill + repin | Δ |
|---|---|---|---|
| p50 | 1802 | 1771 | −1.7% |
| p75 | 2622 | 2431 | −7.3% |
| p90 | 5888 | **3625** | **−38.4%** |
| p95 | 10220 | **5925** | **−42.0%** |
| p99 | 26012 | **15949** | **−38.7%** |
| avg | 3385 | 2471 | −27.0% |

**TPOT (ms):** p50 47.1→49.7, p90 57.8→60.3, p99 70.6→82.2 (+16.4%, decode-tail cost).
**Throughput:** 9369→9251 reqs, 275373→270683 tok/s (−1.7%), prefix-hit 0.935→0.934.

Spill+repin cuts the TTFT tail p90/p95/p99 by ~38–42% for a small (~16% p99 TPOT, ~2% throughput) cost. The **repin=on** design keeps this stateless — a content-cache-aware policy with load spill and *no* re-pin stormed in the same setup (CV ~1, p99 ~225 s), the failure mode this design avoids.

## Reproduction & benchmark plan

Only the load-balance flags differ between the two arms; everything else (model, `--tp/--dp`, `--enable-dp-attention`, the external-cache linker, etc.) is identical.

**Baseline — pin only:**
```
python -m sglang.launch_server --model <MODEL> --tp 8 --dp 8 --enable-dp-attention \
  --enable-unified-cache-external-linker <backend> \
  --load-balance-method consistent_hash
```

**Treatment — pin + load-aware spill + repin:**
```
python -m sglang.launch_server --model <MODEL> --tp 8 --dp 8 --enable-dp-attention \
  --enable-unified-cache-external-linker <backend> \
  --load-balance-method consistent_hash \
  --enable-dp-spill --dp-spill-gap-pct 0.30 --dp-spill-abs 8192 --dp-spill-group-size 8
```
(`--enable-dp-repin` defaults on; `--dp-spill-group-size 8` = one 8-GPU node.)

**Workload:** a multi-turn / agentic load where each session sends a stable `session_id` (the consistent-hash key) and the input length is heavy-tailed (a few long-prefill turns among many short ones — the case that produces the HOL tail). Compare TTFT {p50,p90,p95,p99}, TPOT {p50,p90,p99}, output tok/s, and prefix-cache hit at a fixed concurrency.

**Validated point:** DeepSeek-V4-Pro, TP8+DP8, external linker, conc128, 3600 s agentic replay — the table above (TTFT p90/p95/p99 −38 / −42 / −39 %).

**Proposed matrix (for broader validation — happy to run what maintainers prefer):**
- models: one dense + one MoE public model on an 8-GPU dp-attention node;
- concurrency: 64 / 128 / 256;
- workloads: (a) multi-turn ShareGPT-style with per-session ids, (b) synthetic heavy-tailed ISL;
- checks: (1) tail drop with spill on; (2) exact no-op parity with spill off; (3) throughput within a few %; (4) the storm-free property — bounded per-rank running-CV — vs a content-cache-aware + load-spill policy.

## Config surface

| flag | default | meaning |
|---|---|---|
| `--load-balance-method consistent_hash` | — | session→dp_rank consistent-hash pin |
| `--enable-dp-spill` | off | load-aware spill on `num_waiting_uncached_tokens` |
| `--enable-dp-repin` | on | transient spill (return to CH home; no state) vs sticky |
| `--dp-spill-gap-pct` | 0.30 | relative backlog gap that triggers a spill |
| `--dp-spill-abs` | 8192 | absolute waiting-uncached-token floor |
| `--dp-spill-group-size` | 8 | consecutive dp_ranks per node-local store; spill stays within the home rank's group (no cross-node spill) |
