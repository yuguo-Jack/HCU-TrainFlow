# fix: accept pp_proxy_tensors in frozen-kv-mtp, uno, and multi-layer-eagle forward_batch_generation

[Upstream PR](https://github.com/sgl-project/sglang/pull/40355) · state: open · merged: False

## Original PR description

## Description

The scheduler's non-overlap speculative path (`srt/managers/scheduler.py:4514,4527`) always passes `pp_proxy_tensors` to `forward_batch_generation`:

```python
self.model_worker.forward_batch_generation(batch, pp_proxy_tensors=pp_proxy_tensors)
```

Three spec-v2 workers are missing this keyword parameter, causing a `TypeError` crash on the first non-overlap step:

| Worker | Status |
|--------|--------|
| `frozen_kv_mtp_worker_v2.py` | ❌ missing |
| `uno_worker_v2.py` | ❌ missing |
| `multi_layer_eagle_worker_v2.py` | ❌ missing |

Other v2 workers (`eagle_worker_v2.py`, `dflash_worker_v2.py`, `ngram_worker.py`) and `dspark_worker_v2.py` already accept `pp_proxy_tensors`.

## Changes

Add `pp_proxy_tensors=None` to `forward_batch_generation`'s signature in the three workers listed above, matching the pattern established by existing workers.

For `FrozenKVMTPWorkerV2` and `MultiLayerEagleWorkerV2`, also pass the kwarg through to `target_worker.forward_batch_generation()` in the prefill (extend) path, consistent with `EAGLEWorkerV2`'s behaviour.

A follow-up could declare `forward_batch_generation` on `BaseSpecWorker` as an abstract method so the next divergence fails at lint time.

## Related

Fixes #40155.
- #39262 — the DSpark instance of this bug (already fixed on main)
- #29189 — carries the multi-layer EAGLE hunk as part of GigaChat 3.5 support
