# [Fix] deepseekv3: stream tool-call arguments when the closing fence arrives with the name

[Upstream PR](https://github.com/sgl-project/sglang/pull/47305) · state: open · merged: False

## Original PR description

## Motivation

With multi-token chunks (MTP or other speculative decoding), a DeepSeek-V3 tool call can be streamed with empty arguments.

`DeepSeekV3Detector.parse_streaming_increment` only matches a call once the closing ```` ``` ```` of the arguments has arrived. On that first match it sends the tool name and returns, leaving the arguments for the next chunk. If the closing fence and `<｜tool▁call▁end｜><｜tool▁calls▁end｜>` arrive in the same chunk, that chunk is the last one, so the arguments are never sent. `_check_for_unstreamed_tool_args` then fills in the `{}` stored with the name, and the client receives the call with arguments `{}`.

The existing `test_parse_streaming_multiple_tool_calls_with_multi_token_chunk` passes only because its last chunk, `<｜tool▁calls▁end｜>`, arrives on its own. If it is merged into the previous chunk, the second call's arguments are lost.

I found this with a differential check that streams the same text through every parser in `FunctionCallParser.ToolCallParserEnum` under many chunkings and compares the result with `parse_non_stream`. Special tokens are never split, so every chunking can occur in serving.

## Modifications

- `deepseekv3_detector.py`: after sending the name, process the arguments in the same step instead of waiting for another chunk. The pattern only matches once the arguments are complete, so they are always available at that point. The argument and completion logic is unchanged; it is dedented out of the `else` branch.
- `test_function_call_parser.py`: two tests in `TestDeepSeekV3Detector`:
  - a single call whose closing fence and both end tokens arrive in the last chunk;
  - the existing multi-token two-call test with its last two chunks merged.

  Both fail before this change (the arguments are missing) and pass after it.

Tested on CPU at 46008a7: with the new tests and without the fix, `test_function_call_parser.py` runs 263 tests with 2 errors (the new ones). With the fix, all 263 pass.
