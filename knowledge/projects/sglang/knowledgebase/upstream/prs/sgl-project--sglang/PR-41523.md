# [Feat] [Intel] hisparse: Allow the intel_xpu DSA backend on XPU

[Upstream PR](https://github.com/sgl-project/sglang/pull/41523) · state: closed · merged: False

## Original PR description

## Motivation

This PR enables the `intel_xpu` DSA backend path for HiSparse on XPU.

## Modifications

- `hisparse_hook.py`: add `HISPARSE_XPU_DSA_BACKENDS_BY_DTYPE = {"bfloat16": {"intel_xpu"}}` and use it on XPU. fp8 KV is rejected at startup, because the intel_xpu kernels read the raw bf16 MLA layout, not the fp8 scaled layout (656 B/token). `_hisparse_default_backend` returns `intel_xpu` on XPU, so the default stays inside the allow-list.
- `fields/exec_.py`: accept `intel_xpu` as a `--dsa-prefill-backend` / `--dsa-decode-backend` choice.
- `test_server_args.py`: XPU tests (`intel_xpu` accepted with bf16 KV, the XPU default is in the allow-list, fp8 KV rejected, a CUDA backend rejected, `intel_xpu` parses as a CLI choice). The existing CUDA cases now also set `is_xpu=False`; otherwise they take the new XPU branch when run on an XPU host.

CUDA and ROCm behaviour is unchanged.

## Accuracy Tests

- `pytest test/registered/unit/server_args/test_server_args.py -k "HiSparse or intel_xpu_is_a_dsa"`: 18 passed. With the hook or CLI change reverted, the new tests fail.
- End to end on 2x Arc Pro B60 (DeepSeek-V3.2, dummy weights, 3 layers, TP2/DP2, bf16 KV): the server starts with `prefill=intel_xpu, decode=intel_xpu` and HiSparse enabled. Long prompts decode with most of the KV in host memory, and the rows swapped into the device buffer match the host KV exactly. 
- Full-model accuracy is N/A because the model does not fit on BMG.

## Speed Tests and Profiling

### Why only `intel_xpu`

`triton` is also a DSA backend, and ROCm allows it with HiSparse. On XPU the triton sparse-MLA kernels currently crash (`torch.cuda.*` device and stream queries). With those patched locally, the kernels are correct but much slower than `intel_xpu`, so this PR does not allow `triton` on XPU.

HiSparse on, 4k input / 64 output, same model and config:

| Concurrency | Metric | triton | intel_xpu |
|---|---|---|---|
| 1 | Output throughput (tok/s) | 1.74 | 26.6 |
| 1 | Median TTFT (s) | 34.9 | 0.85 |
| 1 | Median TPOT (ms) | 27.7 | 22.8 |
| 4 | Output throughput (tok/s) | 1.65 | 64.8 |
| 4 | Median TTFT (s) | 109.1 | 2.12 |
| 4 | Median TPOT (ms) | 197.9 | 25.8 |

Sparse decode kernel alone (one layer call, 128 heads, top-k 2048, bf16), both matching a torch reference to about 1e-3:

| Batch | triton (ms) | intel_xpu `flash_mla_decode` (ms) |
|---|---|---|
| 1 | 3.92 | 0.50 |
| 4 | 14.57 | 1.29 |
| 16 | 50.82 | 3.87 |
| 32 | 96.60 | 6.15 |
