# [Fix] mem_cache: report the CUDA error when host registration fails

[Upstream PR](https://github.com/sgl-project/sglang/pull/48272) · state: open · merged: False

## Original PR description

## Motivation

`_cuda_host_register` (HiCache host pools, mamba/DSA/MHA host buffers) and `_cuda_host_unregister_ranges` (their teardown) format a failed CUDA call with `cudart.cudaGetErrorString(rc)` after converting the return value to `int`. torch's binding (`torch.cuda.cudart()`) returns `cudaError` values, and its `cudaGetErrorString` accepts only those:

```
TypeError: cudaGetErrorString(): incompatible function arguments. The following argument types are supported:
    1. (arg0: torch._C._cudart.cudaError) -> str
```

So the error path raises a `TypeError` instead of the intended message, and the actual CUDA error (e.g. `part or all of the requested memory range is already mapped`) is lost. In teardown, an unregistration failure that should be logged as a warning raises instead. The existing unit tests use a fake runtime that takes ints, so they could not catch this.

## Modifications

- `mem_cache/pool_host/common.py`: keep the `cudaError` value returned by `cudaHostRegister` / `cudaHostUnregister`, compare `int(err)`, and pass the value itself to `cudaGetErrorString`. Messages, return values and control flow are otherwise unchanged.
- New `test/registered/unit/mem_cache/test_cuda_host_register_errors.py` (`base-b`, `1-gpu-small`, skipped without CUDA). It triggers real CUDA errors through torch's binding:
  - registering the same buffer twice must raise `RuntimeError("cudaHostRegister failed (rc=..., <CUDA error text>) ...")`;
  - unregistering a range that was never registered must be logged as a warning with the CUDA error text, and returned as a failed range.
  - after each forced failure, a torch kernel launch consumes the leftover CUDA error, so later tests in the same process are unaffected.
