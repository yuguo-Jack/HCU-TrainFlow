# [FlashInfer] Add startup autotuning for MegaMoE

[Upstream PR](https://github.com/sgl-project/sglang/pull/43789) · state: closed · merged: True

## Original PR description

## Motivation

@humansand

Add startup autotuning for the existing FlashInfer MegaMoE NVFP4 W4A4 and MXFP8
backends. The generic FlashInfer autotune context does not trigger MegaMoE's
native tuner. Tune representative decode/prefill capacities before CUDA graph
capture, then select a fixed workspace using synchronized DP token counts.

This is the standalone autotune prerequisite for
[#39210](https://github.com/sgl-project/sglang/pull/39210). W4A16 integration stays
in that separate PR. Uses the FlashInfer 0.7.1 dependency already on `main`.

## Modifications

- **Startup:** participate in the existing target-model autotune lifecycle by
  default. Prepare powers-of-two decode capacities plus the exact decode ceiling
  and one prefill ceiling. Decode bounds cover captured graphs, eager request
  limits, and maximum speculative width. Preparing the native prefill profile
  does not enable `SGLANG_FLASHINFER_AUTOTUNE_EXTEND`.
- **Representative inputs:** repeat or slice the startup batch to each capacity;
  synthesize inputs for idle ranks. Native `knobs="auto"` otherwise measures its
  first live input while caching under workspace capacity. Tune temporary owners,
  then destroy them and warm fixed public workspace handles before capture.
- **Runtime selection:** use the largest synchronized DP count to choose the
  smallest covering profile on every EP rank. Retain local expert inputs and
  existing DP bookkeeping; reject capacity overflow. No tuning or cache-file
  access occurs in ordinary forwards.
- **Workspace ownership:** use FlashInfer's reference-counted pool instead of
  assigning private workspaces across layers. Stage existing per-layer NVFP4
  scales on every forward; use the public output-view capability and released
  `enable_in_kernel_fc2_reduce` keyword. The FC2 flag permits atomic candidates;
  the selected tactic can still use external reduction.
- **Persistence:** store native tactic payloads in the existing FlashInfer
  namespaced cache. Stage each geometry/capacity once per startup context and
  retain process-local winners for already-pooled workspaces. Target MegaMoE
  cache filenames include physical GPU UUIDs; engines sharing physical GPUs
  need separate `SGLANG_CACHE_DIR` roots. Cache-disabled runs use unique filenames.
- **Boundaries:** native tuning requires EP to span WORLD because FlashInfer
  0.7.1's tuner uses WORLD collectives. Draft profiles are not added. Existing
  disable, deterministic-mode, and skip-op controls preserve normal forwarding;
  DeepGEMM keeps its existing forward path. No W4A16/SiTU, quantization/loader,
  model-specific, NVSHMEM, Dockerfile, or dependency-pin changes.

Use `--flashinfer-autotune-skip-ops flashinfer_megamoe` to skip just this tuner,
or `--disable-flashinfer-autotune` to disable startup FlashInfer tuning.

**Native W4A4 and MXFP8 autotune/capture validation**

- **Fixture:** EP4/WORLD, synthetic SwiGLU, hidden/intermediate size 256, eight
  experts, top-k 4, two layer owners and separate startup contexts. Both paths
  use their actual SGLang weight preprocessing and the released native kernels.
- **Profiles:** bootstrap 4, decode ceiling 16, prefill ceiling 8; capacities
  `[1, 2, 4, 8, 16]`. Synchronized DP counts are supplied as
  `[0, 1, 1, 2]`, `[0, 1, 2, 7]`, `[8, 8, 8, 8]`, and `[0, 4, 9, 16]`.
  These include unequal and idle ranks; full scheduler behavior is outside
  this fixture.
- **Oracle:** compare against independent fixed-default native MegaMoE sessions
  (`knobs={}`, capacity 16), with immediate clones of pooled output views for
  both owners. This is the same released FlashInfer kernel family, not a BF16
  or PyTorch mathematical oracle. Both results must be finite and bitwise
  equal as BF16; no tolerance is applied.
- **Capture:** two unchanged CUDA graph replays and one replay after mutating
  activations, plus FC1 scales for W4A4, for each count fixture. Assert shared
  workspace identity and reference counts `2 → 1 → 0` during owner teardown.
- **Persistence:** the native AUTO wrapper only counts calls. All candidates,
  kernels, tuning, and dispatch remain unchanged. Cold startup invokes AUTO
  five times per rank; warm restart invokes it zero times. Both owners' eight
  cache files per precision contain identical namespaced records for all five
  capacities.

**W4A4 serving accuracy**

Model: `nvidia/Qwen3-30B-A3B-NVFP4`, pinned Hugging Face revision
`2538ded2a4edb247b4d2b4a8ba24e44bd4c017c3`. TP4 / attention DP4 / EP4;
max running requests 64; decode CUDA graphs up to 64; prefill CUDA graphs
disabled; chunked prefill 4096; static memory fraction 0.7; BF16 combine;
per-token activation quantization and in-kernel FC2 reduction disabled.
Startup FlashInfer tuning remains enabled by default. No speculative decoding.

Full server command (the test helper resolves this public model to the pinned
local snapshot):

```bash
export MODEL_PATH="$(hf download nvidia/Qwen3-30B-A3B-NVFP4 \
  --revision 2538ded2a4edb247b4d2b4a8ba24e44bd4c017c3)"
unset SGLANG_FLASHINFER_MEGAMOE_MAX_TOKENS_PER_RANK FLASHINFER_MOE_EP_KNOB_CACHE
CUDA_VISIBLE_DEVICES=0,1,2,3 \
SGLANG_FLASHINFER_CUTEDSL_NVFP4_W4A16=0 \
SGLANG_FLASHINFER_NVFP4_PER_TOKEN_ACTIVATION=0 \
SGLANG_FLASHINFER_MEGAMOE_IN_KERNEL_FC2_REDUCE=0 \
SGLANG_FLASHINFER_MEGAMOE_COMBINE_DTYPE=bf16 \
SGLANG_ENABLE_JIT_DEEPGEMM=False \
NVSHMEM_REMOTE_TRANSPORT=none \
NVSHMEM_IB_ENABLE_IBGDA=0 \

  --model-path "$MODEL_PATH" \
  --dtype bfloat16 \
  --tp-size 4 --attn-dp-size 4 --ep-size 4 \
  --moe-runner-backend flashinfer_megamoe \
  --moe-a2a-backend flashinfer_megamoe \
  --cuda-graph-backend-prefill disabled \
  --cuda-graph-max-bs-decode 64 \
  --max-running-requests 64 \
  --chunked-prefill-size 4096 \
  --mem-fraction-static 0.7 \
  --device cuda --host 127.0.0.1 --port 31100
```
