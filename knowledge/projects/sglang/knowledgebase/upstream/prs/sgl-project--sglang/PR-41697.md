[Upstream PR](https://github.com/sgl-project/sglang/pull/41697) · state: open · merged: False

## Original PR description

# [AMD] Reuse AITER DSA decode metadata across layers

**Depends on:** #41696

## Motivation

During one decode step, every DSA layer has the same sequence lengths, valid
index counts, `kv_indptr`, and AITER persistent work schedule. Only the selected
KV index values differ by layer.

The existing AITER decode path rebuilds the layer-invariant metadata in every
layer. GLM-5.2 has 78 DSA layers, so the repeated mask, reduction, cumulative
sum, buffer fill, and `get_mla_metadata_v1` work adds substantial fixed latency.

## Modifications

- Use the current `DSAMetadata` object as the decode-forward owner.
- Build `kv_indptr` and AITER persistent work/reduction metadata in the first
  AITER layer of a decode step.
- Reuse that metadata in later layers with the same owner.
- Rebuild the metadata when the owner changes.
- Reset the owner in `on_after_cuda_graph_warmup` so actual graph capture
  records one metadata build after eager warmup.
- Keep `get_valid_kv_indices` per layer because the selected index values are
  layer-specific.
- Keep the BF16-KV path unchanged.

Under CUDA graphs, the metadata generation is recorded once and replayed once
per decode step. Eager execution receives a new metadata owner and rebuilds the
schedule for the new step.

## Accuracy Tests

All registered metadata tests pass, covering reuse within one decode step,
rebuilding for a new owner, active `kv_indptr` refresh, and invalidation after
CUDA graph warmup.

On MI355X TP4 with FP8 KV cache and CUDA-graph decode, a fixed-seed 60k-token
greedy comparison produced exact matching text and exact matching retokenized
output for all 600 generated tokens.

## Speed Tests and Profiling

Hardware: AMD MI355X, TP4, `amd/GLM-5.2-MXFP4`, FP8 KV cache, and seven matched
serving points.

- Output throughput improved by 4.68–13.85%.
- Mean TPOT improved by 5.42–12.79%.
- Mean TTFT ranged from a 1.71% improvement to a 6.01% regression.
- The largest median-TTFT regression was 9.54% at 16k input, concurrency 32.

This change improves AITER decode throughput by 4.68–13.85% relative to the previous AITER path. However, AITER remains slower than ROCm’s default Triton decode backend at the tested points. This PR therefore does not change the recommended backend by itself. It is a prerequisite for #41698, which removes the remaining per-layer AITER preparation overhead.

## Reproduction

Build the parent and candidate revisions separately, then launch both with:

```bash
SGLANG_USE_AITER=1 python3 -m sglang.launch_server \
  --model amd/GLM-5.2-MXFP4 \
  --tp 4 \
  --trust-remote-code \
  --attention-backend dsa \
  --dsa-prefill-backend aiter \
  --dsa-decode-backend aiter \
  --dsa-topk-backend sgl-kernel \
  --kv-cache-dtype fp8_e4m3 \
  --page-size 64 \
  --cuda-graph-max-bs-decode 64 \
  --disable-radix-cache \
  --chunked-prefill-size 32768 \
  --max-prefill-tokens 32768
```

After an unrecorded 8k-input/8-output warmup at concurrency 4 and seed 0, run
1,024 output tokens at 8k input with concurrency 1, 8, 16, 32, and 64, and at
16k input with concurrency 8 and 32. Use the same prompts and seeds for both
revisions.

- Jacob0226 · comment · 2026-10-07T10:44:29Z · [source](https://github.com/sgl-project/sglang/pull/41697#discussion_r4205932625)

File: `python/sglang/srt/layers/attention/dsa_backend.py` · line 3637

`DeepseekSparseAttnMultiStepBackend` doesn't define this hook, so the EAGLE draft runner's `getattr(..., None)` skips it and the per-step backends keep the warmup owner. Draft graph capture then records no `get_mla_metadata_v1`. On MI355X, `run_dsa_eagle_draft_cuda_graph_runner_case` with AITER + FP8 (raw 576 layout): graph draft tokens differ from eager (2/4 and 4/6 mismatched), with 0 metadata builds during capture vs 1 per step on #41696. Forwarding the hook, as `DeepseekV4MultiStepBackend` does, restores the match:

```python
def on_after_cuda_graph_warmup(self):
    for backend in self.attn_backends:
        backend.on_after_cuda_graph_warmup()
```
