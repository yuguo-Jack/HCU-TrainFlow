# [Perf] Add optional K-group unrolling for CUDA block-FP8 matmul

[Upstream PR](https://github.com/sgl-project/sglang/pull/39635) · state: closed · merged: False

## Original PR description

## Motivation

Add optional CUDA K-group unrolling for block-FP8 matmul. A large K tile is split into separately scaled dots, so two 32-element groups with scale products 1 and 8 contribute `32 + 256 = 288`.

Depends on #39630 at `6e5425d2`; the final commit adds this extension. PR1 can merge independently. This PR remains draft pending GPU validation and renewed performance comparisons.

## Modifications

- Port the separate unrolled kernel, regression tests, and benchmark to the current GEMM paths. The unrolled kernel AST matches the previously tested implementation at `086a5079`; all five existing GPU kernel ASTs are unchanged from PR1.
- Select the new kernel only for generic CUDA configs with `group_k` in {32, 64, 128}, larger `BLOCK_SIZE_K` in {64, 128, 256}, whole groups, and FP32 scale storage. Data and scale loads are masked at K tails.
- Keep PR1's validator strict for Hopper and gfx1250. The unrolled path explicitly rejects `SWAP_AB`/`SPLIT_K` config fields, including neutral values; these combinations are not implemented. INT8 and AMD unrolledx4 dispatch are unchanged.
- Extend the CUDA FP8 tuner's search, retaining BK32 candidates for group32. Preserve config selection's insertion-order tie breaking with a traceable loop. Default configs and shipped tuning files are unchanged.

## Speed Tests and Profiling

Final paired rerun against the original kernel (median microseconds, 10 alternating rounds; group32, BF16 output):

| M/N/K | Cache condition | BK32 | BK128 | Latency reduction |
|---|---|---:|---:|---:|
| 16/1152/5120 | Warm | 27.996 | 24.599 | 12.1% |
| 16/1152/5120 | 128 MiB scrub | 37.792 | 36.272 | 4.0% |
| 16/3072/1280 | Warm | 8.147 | 6.644 | 18.4% |
| 16/3072/1280 | 128 MiB scrub | 14.896 | 13.280 | 10.8% |

An unchanged-BK32 control differed by at most 0.03% warm / 0.33% scrubbed in these examples. The standalone script below was also run: warm reductions were 12.5% / 18.1%, scrubbed reductions 5.5% / 10.3%. The first scrubbed example is a small, run-dependent gain.

```bash
python benchmark/kernels/quantization/bench_block_fp8_k_groups.py
```

The script prints configs and all ten alternating measurement rounds. It preallocates outputs, checks exact synthetic results before timing, and uses GPU events with CUDA Graphs. The 128 MiB cache-scrub write is outside the timed interval. Example BK32 configs were selected from a 480-config search per shape, with warm and scrubbed conditions tuned separately; BK128 configs were frozen before that stronger baseline search.

These are selected microbenchmarks. Larger tiles did not improve every shape in the broader sweep; this PR makes no end-to-end model-speed claim. Other GPUs require CI/reviewer validation.
