# [Diffusion][Refactor] Refactor and extract complex RoPE implementation to layers/rotary_embedding for MOVA DiT

[Upstream PR](https://github.com/sgl-project/sglang/pull/31453) · state: closed · merged: True

## Original PR description

## Motivation

SGLang has a dedicated directory (`layers/rotary_embedding`) designed to house unified, high-performance Rotary Positional Embedding implementations. 
 
Was observed that a complex-valued RoPE representation is highly efficient for the `neox_style=False` and `interleaved=True` configurations. However, implementing this complex multiplication logic directly within model-specific code leads to duplication and limits its reusability. 
 
Since this optimized complex RoPE path is generic, mathematically clean, and performant, it is logical to extract the implementation out of the model code and move it into the shared `layers/rotary_embedding/utils.py` utility module. This enables other models within SGLang using interleaved RoPE to easily inherit and reuse this optimization.


## Modifications

Were modified 4 key files to implement this refactoring and optimization:
 
### 1. `sglang/multimodal_gen/runtime/layers/rotary_embedding/utils.py`
- Added the `_apply_rotary_emb_complex` function:
  - **Inputs:** 
    - `x` of shape `[batch, num_tokens, num_heads, head_size]`.
    - `freqs` of shape `[num_tokens, 1, head_size // 2]`.
  - **Outputs:** Evaluated tensor of the same shape and dtype as `x`.
  - **Optimization Details:** It utilizes `view()` transformations to group activation dimensions and cast to `float32`. It then performs a single vectorized complex multiplication kernel. Calling `torch.view_as_real()` on the result natively lays out the real and imaginary elements sequentially in memory, producing the interleaved layout. This excludes the need for `torch.stack()` and `.contiguous()` allocations.
 
### 2. `sglang/multimodal_gen/runtime/layers/rotary_embedding/__init__.py`
- Registered the new `_apply_rotary_emb_complex` utility in the package exports: imported the function from `.utils.py` and added it to the `__all__` list to expose it cleanly to the rest of the codebase.
 
### 3. `sglang/multimodal_gen/runtime/models/dits/mova_video_dit.py` and `mova_audio_dit.py`
Cleaned up the attention blocks and models:
  - Removed custom inline complex RoPE functions.
  - In `SelfAttention.forward`, reshape `q`, `k`, and `v` to `[B, S, H, D]` format using `view()` operations, and apply the `_apply_rotary_emb_complex` directly. This eliminates `rearrange` and `flatten` steps inside the attention loop.

- gemini-code-assist[bot] · comment · 2026-07-16T10:57:52Z · [source](https://github.com/sgl-project/sglang/pull/31453#discussion_r3594818704)

File: `python/sglang/multimodal_gen/runtime/layers/rotary_embedding/utils.py` · line 89

![medium](https://www.gstatic.com/codereviewagent/medium-priority.svg)

To ensure robustness and prevent potential runtime errors when `_apply_rotary_emb_complex` is reused with non-contiguous inputs, it is safer to call `.contiguous()` on the reshaped tensor before passing it to `torch.view_as_complex`. `torch.view_as_complex` requires the input tensor to have a stride of 1 along its last dimension, which is not guaranteed for non-contiguous tensors.

```suggestion
    x_complex = torch.view_as_complex(x.to(dtype_c).reshape(b, s, h, d // 2, 2).contiguous())
```

- gemini-code-assist[bot] · comment · 2026-07-16T10:57:52Z · [source](https://github.com/sgl-project/sglang/pull/31453#discussion_r3594818720)

File: `python/sglang/multimodal_gen/runtime/models/dits/mova_video_dit.py` · line 182

![medium](https://www.gstatic.com/codereviewagent/medium-priority.svg)

Using `.reshape(b, s, -1)` instead of `.view(b, s, -1)` is safer here. The output of the attention block (`self.attn`) might be non-contiguous depending on the underlying attention backend or sequence parallelism communication, which would cause `.view()` to raise a runtime error.

```suggestion
        out = out.reshape(b, s, -1)
```
