# [Feat] cp: Hierarchical cache for padded CP KV layouts

[Upstream PR](https://github.com/sgl-project/sglang/pull/47995) · state: open · merged: False

## Original PR description

## Motivation

Depends on #47988, which adds radix caching for padded CP KV layouts. This PR is stacked on #47988's branch, so its diff shows only this second layer.

#47988 keeps hierarchical caching rejected under a padded layout, because the host and storage tiers still count physical pages. This PR makes the host tier and the generic L3 controller paths handle a padded layout, so hierarchical caching can be enabled with one.

## Modifications

- **Host tier (Python and Rust tree cores).** Backups keep only the rows this rank owns, through the new `get_cp_sharded_padded_owned_indices`. Load-back expands those rows back to cache rows for the tree. Host-value lengths are counted in rank-local rows.
- **Generic L3 controller paths.** Storage page hashes cover logical pages (`cp_size * page_size`), while transfers stay physical. Prefetch accounting, hit lengths, the storage prefetch threshold and the buffer-only pipeline convert between logical tokens and rank-local rows. KV events keep the physical-page chain.
- **Tree-cache gate.** Hierarchical caching is now admitted under a padded layout, except under pipeline parallelism, which stays rejected. Subclasses and other trees, session radix caching, the unified-cache external linker and streaming sessions stay rejected, as in #47988.
- **Storage backends.** Under a padded layout, `HiCacheController.attach_storage_backend` rejects the built-in HiCache storage backends, since none has been validated with one. Host caching without a storage backend is supported. A controller that implements its own CP-aware attach can use the converted L3 paths.
- **Tests.** Existing test fixtures now set the controller's `logical_page_size`, and one unified-radix-cache test covers the backup-capacity failure path.

Every new branch is gated on a padded layout, so behavior without one is unchanged.
