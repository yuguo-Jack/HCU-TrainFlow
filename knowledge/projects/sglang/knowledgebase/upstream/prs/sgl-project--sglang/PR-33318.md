# [XPU] Use SYCL kernels for topk_transform on XPU

[Upstream PR](https://github.com/sgl-project/sglang/pull/33318) · state: closed · merged: True

## Original PR description

## Motivation

Route `topk_transform` , `topk_transform_paged` and `topk_transform_ragged` to the native SYCL
kernels on XPU. The SYCL implementations are added in the `sgl-kernel-xpu` PR (https://github.com/sgl-project/sgl-kernel-xpu/pull/366, https://github.com/sgl-project/sgl-kernel-xpu/pull/452) and exposed as
`torch.ops.sgl_kernel.topk_transform`, `topk_transform_paged` and `topk_transform_ragged` . Without this dispatch, XPU
runs fall through to the JIT CUDA path and fail to load, or drop to a
significantly slower vectorized PyTorch fallback.

## Modifications

- `python/sglang/kernels/ops/attention/dsv4/topk.py`:
  - `topk_transform(...)`: added an `elif scores.device.type == "xpu"`
    branch that calls `torch.ops.sgl_kernel.topk_transform(...)`, before
    the existing generic JIT path.
  - `topk_transform_paged(...)`: added an early-return branch for
    `scores.device.type == "xpu"` that calls
    `torch.ops.sgl_kernel.topk_transform_paged(...)`. On XPU the
    `metadata` argument is accepted for API parity but ignored by the
    kernel.
  - `topk_transform_ragged(...)`: added an `elif scores.device.type == "xpu"`
    branch that calls `torch.ops.sgl_kernel.topk_transform_ragged(...)`, before
    the existing generic JIT path.
