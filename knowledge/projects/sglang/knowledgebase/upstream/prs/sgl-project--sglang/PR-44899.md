# [Fix] disaggregation: Preserve EAGLE/MTP draft KV during CPU retraction

[Upstream PR](https://github.com/sgl-project/sglang/pull/44899) · state: open · merged: False

## Original PR description

## Motivation

Related to #39749, which fixes full DFlash draft KV but explicitly leaves EAGLE/MTP unregistered.

PD decode retraction with `--disaggregation-decode-retraction-backup cpu_tensor` saves the target allocator's KV, but separate EAGLE/MTP pools use the same token slots without being included in that backup. Reusing those slots overwrites draft history before the request resumes. For GLM DSA this includes draft index keys/scales as well as MLA KV.

#34801 covers the host-pool path. It does not fix CPU-tensor backups; #36343 deliberately keeps CPU tensors as the implicit ROCm fallback.

## Changes

- Declare an immutable, per-allocator default for separate CPU-retraction draft pools and deduplicate pool identities, excluding target storage.
- Register all EAGLE/EAGLE3 draft runners after allocation, independently of HiCache. This also covers multi-layer EAGLE rather than only its first runner.
- Save draft snapshots in the existing request-owned `RetractionBackup`, then restore them at the request's newly allocated token indices.
- Delegate layout handling to each pool's existing `get_cpu_copy/load_cpu_copy`: MLA DCP localization and DSA index/scales remain pool-owned.
- Reuse existing CPU-backup discard cleanup. No global snapshot dictionary or inference-time monkeypatch.

This changes retraction only, not normal draft/verify/decode execution or the selected ROCm backup backend.

## Scope

Standard, non-unified-memory EAGLE/EAGLE3/MTP draft KV pools. Fused unified-memory draft storage, Frozen-KV MTP and DFlash are unchanged. This does not claim to fix separate recurrent-state or in-flight overlap checkpoint-boundary problems such as #39743.

Missing draft history can reduce speculative acceptance; target verification still runs. We do not claim this alone proves user-visible output corruption.

## Tests

**10 CPU tests passed:** 8 new regression tests plus the 2 existing Mamba-backup tests.

Coverage:
- Poison old storage, relocate slots and restore target plus one/multiple MLA/DSA draft pools.
- DCP1 and a page-aligned DCP2/rank1 case.
- Exact draft index-key/scale byte preservation.
- Target-only negative control reproduces missing draft history.
- Pool identity deduplication, no-draft behavior, registration with HiCache disabled.
- Request-owned snapshot release on discard; failed restore retains the backup for cleanup.
- Existing target/Mamba CPU-copy behavior.

Tests use real upstream Req/allocator/MLA/DSA/IndexKeyCache copy methods on CPU tensors, with device synchronization mocked. They ran against upstream `4eb606b2aee8a9165e16352fd4c08d998ba37990` plus this patch in an isolated ROCm-image container: no GPU devices, 2 CPUs, 8 GiB, 180-second bound. The test process enabled the CPU engine, cleared `torch.version.hip` and made AITER unavailable to avoid import-time GPU probes. These are test-process accommodations, not source/runtime changes. Tested files match the committed SHA-256s.

Pinned isort 7.0.0, Ruff 0.15.1 formatting/lint and `git diff --check` pass.

## GPU regression — real weights completed

Validated on MI350X, GLM-5.3 MXFP4 **real weights** (`--load-format auto`), TP4/EP4 per role, KV `fp8_e4m3`, EAGLE 3/1/4, HiCache off, decode graphs enabled and KV checksum guards on.

| Gate | Result |
| --- | --- |
| Actual decode-memory retraction | Two concurrent 128000-token prompts requesting 8192 output tokens each, D pool 262144. One request retracts under real memory pressure; both complete all 8192 output tokens. |
| Independent draft-state preservation | Full pre-backup/post-restore draft KV and DSA indexer/scale snapshots are byte-identical on **4/4 decode ranks**, covering 131063 token positions. No rescue hook. |
| Abort while backed up | Wait for all four ranks to hold the request-owned backup and the request to be queued for resume, then abort that RID. **4/4 ranks** clear the backup and release all observed draft CPU tensor objects; the peer completes 8192 tokens. |
| Fresh request after abort | A fresh arithmetic request succeeds on the same workers without restart and answers **4**. Running/retracted queues drain; after explicit cache flush, used KV tokens are zero. |

Completed pressure requests retain exactly 128000 prompt tokens and return 8192 finite selected-token logprobs. Synthetic stress input IDs and one arithmetic smoke are not a broad accuracy gate. Read-only observers add CPU copies/synchronization, so no throughput claim is made.

**Runtime scope:** the committed delta was mechanically applied, with offsets only, to pinned image `sha256:e54f0279d1d538cc43a4cf7087afe9c05d46e95560eebe89cb1f924a4b64d1f2` plus our PD qualification overlay. Normalized ASTs for all four changed methods match this PR's commit exactly. Observation brackets the complete Req backup/restore methods and only reads state; the older allocator monkeypatch/rescue implementation is removed. This is a pinned-image compatibility-port regression, **not** a claim that a whole latest-main image has been GPU-qualified.

**Evidence bookkeeping:** the initial retraction reproduction and rescue control used dummy weights. The real-weight resume subgate passed in a later run whose final arithmetic-probe client then hit a BatchEncoding JSON-serialization error. After CPU-testing the tokenizer adapter, only abort + fresh-follow-up was rerun and passed. An earlier attempt also stopped on an overly strict load-snapshot freshness assertion. Those harness failures are retained as failed/inconclusive whole runs; only passing subgates are reused.

All owned GPU workers were archived and stopped. The local implementation and scoped GPU gates are ready for review; upstream CI remains required.
