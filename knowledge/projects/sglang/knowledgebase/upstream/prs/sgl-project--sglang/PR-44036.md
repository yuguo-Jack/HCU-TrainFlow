# [Feat] FlashInfer: Add NVFP4 W4A16 and SiTU support to MegaMoE

[Upstream PR](https://github.com/sgl-project/sglang/pull/44036) · state: closed · merged: True

## Original PR description

## Motivation

@humansand

Add opt-in NVFP4 W4A16 to FlashInfer MegaMoE for serialized ModelOpt checkpoints
and `nvfp4_online`, reusing `SGLANG_FLASHINFER_CUTEDSL_NVFP4_W4A16=1`. The default
NVFP4 MegaMoE path remains W4A4.

This is the remaining integration from [#39210](https://github.com/sgl-project/sglang/pull/39210)
on top of merged [#43789](https://github.com/sgl-project/sglang/pull/43789).
Startup autotuning, cache ownership, native workspace pooling and DP token-count
synchronization are already upstream and are not changed here. The original PR's
branch and history are preserved.

**Dependency:** the existing FlashInfer 0.7.1 pin includes
[FlashInfer #5019](https://github.com/flashinfer-ai/flashinfer/pull/5019).
No Dockerfile or dependency changes.

## Modifications

- **Precision and preparation:** extend the existing MegaMoE adapter with the
  native W4A16 config/preprocessing. Keep packed NVFP4 weights/block scales,
  per-expert FP32 weight scales, BF16 activations/EP transport/combine and
  post-FC2 routing. Neutralize serialized checkpoint activation scales and
  bypass activation quantization for online W4A16. Retain the existing source
  precision and excluded-layer behavior for online weight conversion.
- **Activation and model wiring:** support gated SiLU/SwiGLU and SiTU for NVFP4
  W4A4/W4A16. Kimi K3 uses standard TopK and local EP/shared-expert handling;
  its GEMM1 alpha/clamp fields map to SiTU beta/linear-beta, separately from
  SwiGLU clamps. MXFP8/DeepGEMM reject unwired SiTU. Nemotron ReLU-squared is
  unsupported. Requirements remain SM100/SM103 and attention-DP=TP=EP;
  W4A16 additionally requires BF16 model dtype and combine.
- **Reload:** restore canonical loading views over the four prepared
  weight/block-scale allocations, then copy newly prepared data into those
  allocations. Share this loader/preparation lifecycle between W4A4 and W4A16. Keep the live
  MegaMoE layer, tuned profiles and workspace owner so CUDA graph pointers remain
  stable; per-expert runtime scales are staged on each forward. FlashInfer 0.7.1
  captures W4A4 input normalization as a scalar: reloading a different input
  scale is rejected and requires a server restart. Weight, weight-scale and
  per-expert FC1-output scale updates remain supported. The registered
  W4A16 serialized reload test covers both cache-flush modes; the existing
  storage regression covers both precisions.
- **Dummy weights:** initialize FP4 global `weight_scale_2` tensors to one,
  preserving ordinary random-weight initialization. Retain the simple
  neutral-scale regression test.
- **FC2 reduction:** default `SGLANG_FLASHINFER_MEGAMOE_IN_KERNEL_FC2_REDUCE=0`
  uses external FP32 accumulation. Setting it to `1` permits nondeterministic
  BF16 atomic candidates; tuning can still select external reduction.
- **Current upstream contracts:** preserve the default non-MegaMoE draft runner
  and A2A behavior. An unset draft A2A backend now resolves to `none` for a
  FlashInfer MegaMoE target, and the NVSHMEM guard accounts for that default.
- **Tests:** extend the existing adapter/storage and architecture cases, plus
  the registered online NVFP4 GSM8K and serialized weight-reload classes.
  No full Kimi K3 E2E or dedicated NVSHMEM environment tests are added.

### Single-node NVSHMEM defaults

For single-node FlashInfer MegaMoE, with no speculative decoding or a default/
explicit `none` draft A2A backend, set these defaults before initialization:

```bash
NVSHMEM_REMOTE_TRANSPORT=none
NVSHMEM_IB_ENABLE_IBGDA=0
NVSHMEM_DISABLE_LOCAL_ONLY_PROXY=1
```

Explicit environment settings are preserved. These defaults apply to all
supported FlashInfer MegaMoE formats and select direct peer memory access,
avoiding the uninitialized proxy global-exit state fixed by
[NVIDIA/nvshmem commit `af9e2391a849`](https://github.com/NVIDIA/nvshmem/commit/af9e2391a849d1a36b4be09c3f6f20d622dada1b).
The closed [NVIDIA/nvshmem#110](https://github.com/NVIDIA/nvshmem/pull/110) has
additional background. Remote IB/UCX transport and proxy-based global-exit/
timeout polling are disabled; bootstrap networking is unaffected. All EP GPUs
must support peer memory access. Multi-node jobs and explicit other draft A2A
backends receive no automatic defaults.

### Example server command

Four Blackwell GPUs, FlashInfer 0.7.1, online expert-weight conversion:

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3 \
SGLANG_FLASHINFER_CUTEDSL_NVFP4_W4A16=1 \
SGLANG_FLASHINFER_MEGAMOE_IN_KERNEL_FC2_REDUCE=0 \
SGLANG_FP4_IGNORED_LAYERS='' \
SGLANG_ENABLE_JIT_DEEPGEMM=False \
python -m sglang.launch_server \
  --model-path Qwen/Qwen3-30B-A3B-Instruct-2507-FP8 \
  --quantization nvfp4_online --dtype bfloat16 \
  --moe-runner-backend flashinfer_megamoe \
  --moe-a2a-backend flashinfer_megamoe \
  --tp-size 4 --attn-dp-size 4 --ep-size 4 \
  --enable-dp-lm-head \
  --cuda-graph-max-bs-decode 64 \
  --cuda-graph-backend-prefill disabled \
  --max-running-requests 64 \
  --chunked-prefill-size 16384 \
  --mem-fraction-static 0.7
```

Convert every routed expert for this example; excluded FP8 expert layers cannot
use the NVFP4 MegaMoE runner. With attention DP4, the 16384-token configured
prefill chunk resolves to 4096 tokens per rank. The existing startup autotuner
therefore prepares a 4096-token per-rank prefill profile.
