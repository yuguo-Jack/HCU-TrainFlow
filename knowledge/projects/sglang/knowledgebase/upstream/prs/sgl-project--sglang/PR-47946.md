# [CI] [AMD] ci: Name and resolve AMD suites and runners as CUDA does

[Upstream PR](https://github.com/sgl-project/sglang/pull/47946) · state: open · merged: False

## Original PR description

## Motivation

CUDA has one source of truth for where a test runs: `register_cuda_ci(stage=..., runner_config=...)` names a key in `scripts/ci/runner_configs.yml`, `pr-test.yml` reads `runs-on` from that file, and `check_registered_tests.py` keeps every registration in that form. `/rerun-test` resolves runners through the same file.

AMD has none of this, and its suite names follow a different scheme:

- `pr-test-amd.yml` and `pr-test-amd-extra.yml` hardcode each job's runner.
- Most AMD tests register with a legacy `suite=` string.
- The names differ from CUDA's: `stage-a/b/c` vs `base-a/b/c`, `jit-kernel-unit-test-amd` vs `base-b-kernel-unit-test-1-gpu-*`, and `runner_config="amd"`, which names no pool.

This PR mirrors CUDA for AMD **without changing what AMD CI runs**. It is the groundwork for `/rerun-test --amd` (#48190) and for registering more CUDA tests on AMD (#48317), which then use the final names.

## Modifications

- **`scripts/ci/runner_configs.yml`** gets an `amd_runner_configs` section with one entry per runner pool:
  - `1-gpu-small-amd`, `1-gpu-large-amd`, `2-gpu-large-amd`, `4-gpu-amd` and `8-gpu-amd` (MI300; `$amd_arch` takes the `runner_arch` input, mi300 or mi325);
  - `1-gpu-small-amd-mi35x`, `8-gpu-amd-mi35x` and `8-gpu-amd-mi35x-fabric`.

  `4-gpu-amd` carries `extra_envs`, the RCCL env the 4-GPU jobs passed inline (the AMD counterpart of `rdma_devices`). The CUDA section is untouched.
- **`scripts/ci/runner_configs.py --amd-map <arch>`** emits `runs_on_map` and `extra_envs_map`. `pr-test-amd.yml` builds them in `check-changes`, and `pr-test-amd-extra.yml` in a new `amd-runner-map` job. Every GPU job reads its `runs-on`, the runner shown in its `name`, `RUNNER_LABELS`, and the 4-GPU env from these maps. **Job names and ids are unchanged**, so `wait-for-jobs`, the AMD job monitor, and job history keep working.
- **Suite names follow CUDA's `{stage}-test-{runner_config}`.** A variant goes into the stage, as in CUDA's `base-b-kernel-unit`. Every per-commit/extra `register_amd_ci` call (399) uses `stage=`/`runner_config=`. Nightly per-model suites keep `suite=`.

  | old suite | new suite |
  |---|---|
  | `stage-a-test-1-gpu-small-amd` | `base-a-test-1-gpu-small-amd` |
  | `stage-b-test-1-gpu-{small,large}-amd`, `stage-b-test-2-gpu-large-amd` | `base-b-test-1-gpu-{small,large}-amd`, `base-b-test-2-gpu-large-amd` |
  | `stage-b-test-1-gpu-small-amd-mi35x` | `base-b-test-1-gpu-small-amd-mi35x` |
  | `stage-b-test-1-gpu-small-amd-nondeterministic` | `base-b-nondeterministic-test-1-gpu-small-amd` |
  | `stage-b-test-large-8-gpu-mi35x-disaggregation-amd` | `base-b-disaggregation-test-8-gpu-amd-mi35x-fabric` |
  | `stage-c-test-4-gpu-amd` | `base-c-test-4-gpu-amd` |
  | `stage-c-test-large-8-gpu-amd`, `...-amd-mi35x` | `base-c-test-8-gpu-amd`, `base-c-test-8-gpu-amd-mi35x` |
  | `jit-kernel-unit-test-amd`, `jit-kernel-benchmark-test-amd` | `base-b-kernel-unit-test-1-gpu-small-amd`, `base-b-kernel-benchmark-test-1-gpu-small-amd` |
  | `sgl-kernel-unit-test-2-gpu-amd` | `base-b-sgl-kernel-unit-test-2-gpu-large-amd` |
  | `extra-*-amd` | unchanged |

  The workflows' `--suite` arguments and `run_suite.py`'s AMD per-commit list are renamed to match.
- **`scripts/lint/check_registered_tests.py`**, for AMD, rejects three things:
  - a `runner_config` missing from `amd_runner_configs`;
  - a `stage=`/`runner_config=` pair whose suite no AMD PR-test job runs, so a stale `stage="stage-b"` cannot silently stop a test from running;
  - a legacy `suite=` of a per-commit/extra AMD suite.

## Verification

Compared against `main` (`58484246d2`):

- **Registrations:** for every file under `test/registered/` (2820), the AMD suites at `main`, mapped through the table above, equal the suites on this branch, with identical `est_time`, `nightly`, and `disabled`. So each new suite selects exactly the files its old suite did.
- **Jobs:** for all 20 AMD GPU jobs, with `runner_arch` both `mi300` and `mi325`, the evaluated `runs-on`, job `name`, `RUNNER_LABELS`, and container `-e` env are identical, and each job's `--suite` is the renamed suite.
- **CUDA:** `runner_configs.py --map` (both b200 tags) and `runner_configs.py <rc>` for every CUDA runner_config print byte-identical output. `run_suite.py` is identical outside the AMD list.
- **Lint:** `check_registered_tests.py` passes, and flags an injected old-stage pair, an old legacy name, an unknown runner_config, and a legacy `suite=` of a current suite.
- **actionlint / format:** no new actionlint findings; three "unknown label" findings for the hardcoded mi35x labels go away. ruff and isort are clean.
- **Live:** a dispatch of `stage-a` and `stage-c 4-GPU` on the previous revision ran on the mapped runners with unchanged job names: https://github.com/sgl-project/sglang/actions/runs/41665317466.
