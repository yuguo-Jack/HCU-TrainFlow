# [Perf] deepseek-v4: DSpark draft stages take the TF32 mHC statistics path from 32 rows on SM100

[Upstream PR](https://github.com/sgl-project/sglang/pull/45260) · state: closed · merged: True

## Original PR description

## Motivation

Under DSpark decode, the three draft stages compute the mixing statistics of their six mHC boundaries with the Triton split-K kernel (`hc_mix_stats_sinkhorn`) at every batch, while the target layers run DeepGEMM's `tf32_hc_prenorm_gemm` from 128 rows. Two reasons: the DSpark model never calls `refresh_mhc_norm_weight_cache`, so its stages have no TF32 weight parts, and `_mix_stats_impl` keeps the DeepGEMM path off under 128 rows on SM100 (SM90 uses it from 32).

Measured on GB300 (DEP16 decode, DeepSeek-V4.1 Flash, 128K contexts, torch profiler, kernel durations):

| Draft rows (= requests per rank) | `_hc_mix_stats_partial_kernel`, 6 launches | `_hc_mix_reduce_sinkhorn_kernel`, 6 launches | Per cycle |
|---:|---:|---:|---:|
| 32 | 6 x 23.8 us | 6 x 9.0 us | 0.197 ms |
| 64 | 6 x 42.2 us | 6 x 9.1 us | 0.307 ms |
| 256 | 6 x 150 us | 6 x 10.5 us | 0.963 ms |

In the same traces the target's unfused boundaries run `sm100_tf32_hc_prenorm_gemm_impl` at 7.4-7.9 us per launch (160 and 320 rows) plus a 16-slice reduce of 7.8 us: about 23 us per boundary against 52 us on the Triton path at 64 rows. The 128-row floor is not a kernel requirement: DeepGEMM's SM100 kernel uses `block_m = 64` with a grid of `num_splits x ceil_div(m, 64)` and no assertion on M.

## Modifications

- `DeepseekV4ForCausalLMDSpark.post_load_weights` calls `refresh_mhc_norm_weight_cache` on each stage, which builds the TF32 parts of the 24 x 20,480 mixing weights (24 MB per GPU for three stages).
- `_mix_stats_impl`: the row floor for the TF32 parts becomes 32 on SM100 as on SM90 (`x_flat.shape[0] >= 32` replaces `>= 128 or hopper_medium`, which already meant 32 on SM90). Batch-invariant mode and rows under 32 are unchanged.

Expected: about 0.17 ms less per decode cycle at 64 requests per rank (22.6 ms cycle), 0.06 ms at 32.

## Accuracy Tests

The draft's statistics move from the Triton tf32x3 kernel to the two-part TF32 split the target already runs at 128 rows and above. Accept length from the A/B decode logs will be posted here; GSM8K at native acceptance on request.

## Speed Tests and Profiling

The A/B at 64 requests per rank (same recipe, base main 49766a74f9 against this branch) is running; the six draft launches and the log cycle will be posted here.
