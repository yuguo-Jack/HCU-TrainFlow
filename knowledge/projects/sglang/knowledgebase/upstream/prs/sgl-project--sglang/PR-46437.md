# [Fix] [CPU] topk: Bound sigmoid vectors for small expert counts

[Upstream PR](https://github.com/sgl-project/sglang/pull/46437) · state: open · merged: False

## Original PR description

## Motivation

Related to #36600. The correction-bias path of `topk_sigmoid_cpu` accepts small expert counts, but its sigmoid helper uses full-width vector loads and stores. For counts below one vector, those operations exceed the input or local score array's logical length.

The prior attempt #37414 was closed by the stale-PR policy on October 6 without being merged. Its issue, discussion, and diff were checked before preparing this PR. The affected source and existing test file are still unchanged on current main (`c00e7e12b64b587da336c4350b1d2484c7dffcd6`). This draft keeps the existing vector loops and expands ordinary numeric coverage to FP16 and both normalization modes.

## Modifications

- Pass compile-time bounded counts to the FP32 and reduced-precision vector loads/stores.
- Omit the second FP32-vector store for FP16/BF16 inputs when the expert count fits in the first float vector.
- Add 72 numeric cases covering FP32/BF16/FP16, 1/2/4/8/16/32 experts, 1/3 tokens, and normalization on/off. Check selected IDs and unbiased sigmoid weights against PyTorch operations.

The supported expert counts are either smaller than a vector or multiples of its width. Full-vector counts therefore remain full-width. No new helper, dispatch option, dependency, or operator API is introduced.

## Accuracy Tests

Local environment: Intel Core i5-14600KF (AVX2), WSL2 Ubuntu, Python 3.12.3, PyTorch 2.14.0+cpu (matching `pyproject_cpu.toml`), GCC 13, two OpenMP threads, `TRITON_DEFAULT_BACKEND=cpu`.

- **10/10 test methods passed** in the complete `test/registered/cpu/test_topk.py`, selected through `test/run_suite.py --hw cpu --suite stage-a-test-cpu-intel --only-file-list ... --fork-worker-batch-size 1 --timeout-per-file 300 --continue-on-error`; `SGLANG_TEST_MAX_RETRY=0`.
- **24 additional numeric cases passed** through the real `fused_topk_cpu` Python entry point and native dispatcher, with literal expected expert IDs/weights, FP32/BF16/FP16 gates, FP32/BF16 bias, top-k 1/2, and normalization on/off.
- The entire production `topk.cpp` translation unit was built as an AVX2 extension with the unchanged top-k registration schemas from `torch_extension_cpu.cpp`. The test loaded the real `sgl_kernel` Python package and those native operators. No simulated kernel, module stub, or replacement reference implementation was used.
- **Compile-only:** the same translation unit also builds with the project's x86 CPU CMake flags (`-O3 -march=x86-64-v4 -mavx512bf16 -mavx512vnni -mamx-tile -mamx-bf16 -mamx-int8 -fopenmp`). This AVX512 binary was not executed on the AVX2 host.
- All applicable pre-commit checks, including clang-format, Ruff, and CPU CI registration checks, passed on byte-identical source copies. `git diff --check` passed.

The first suite attempt failed in the compiled PyTorch reference because Triton selected NVIDIA for the CPU-only PyTorch installation. Explicitly selecting the installed CPU backend resolved that setup issue. The full suite then passed with compilation and assertions enabled.

**Validation still unfinished:** AVX512/Arm64 execution, a full CPU-kernel package build, full model inference, and sanitizer validation of this resumed patch. Existing issue/baseline evidence establishes the original defect; the old fault reproduction was not rerun. The new numeric tests establish routing results, not a claim that fresh sanitizer coverage passed. Keeping this PR in draft with those limits explicit.

<summary>Reproduce the bounded local AVX2 validation build</summary>

From the repository root, with the normal CPU SGLang dependencies installed, save this as a temporary Python script. It compiles the entire production source file and reuses the real dispatcher schemas; it does not implement a substitute kernel.

```python
import pathlib
import shutil
import subprocess
import sys
import sysconfig

import torch
from torch.utils.cpp_extension import include_paths, library_paths

repo = pathlib.Path.cwd()
arch = sys.argv[1] if len(sys.argv) > 1 else 'avx2'
assert arch in ('avx2', 'avx512')
build = pathlib.Path('/tmp/sglang-topk-validation') / ('module' if arch == 'avx2' else 'module-avx512')
build.mkdir(parents=True, exist_ok=True)
source = repo / 'python/sglang/kernels/aot/csrc/cpu'
shutil.copytree(repo / 'python/sglang/kernels/aot/python/sgl_kernel', build / 'sgl_kernel', dirs_exist_ok=True)
registration = (source / 'torch_extension_cpu.cpp').read_text().split('  // topk\n', 1)[1].split('  // decode\n', 1)[0]
driver = build / 'bridge.cpp'
driver.write_text('''#include "topk.cpp"
#include <torch/all.h>
#include <torch/library.h>
#include <Python.h>
TORCH_LIBRARY_FRAGMENT(sgl_kernel, m) {
''' + registration + '''
}
static PyModuleDef module = {PyModuleDef_HEAD_INIT, "common_ops", nullptr, -1, nullptr};
PyMODINIT_FUNC PyInit_common_ops() { return PyModule_Create(&module); }
''')
arch_flags = (['-mavx2', '-mfma', '-mf16c', '-DCPU_CAPABILITY_AVX2'] if arch == 'avx2' else
              ['-march=x86-64-v4', '-mavx512bf16', '-mavx512vnni', '-mamx-tile', '-mamx-bf16', '-mamx-int8'])
cmd = ['g++', '-std=c++20', '-O3' if arch == 'avx512' else '-O2', '-g1', '-shared', '-fPIC', *arch_flags, '-fopenmp',
       f'-D_GLIBCXX_USE_CXX11_ABI={int(torch._C._GLIBCXX_USE_CXX11_ABI)}', str(driver),
       '-o', str(build / 'sgl_kernel/common_ops.so'), '-I' + str(source), '-I' + sysconfig.get_path('include')]
cmd += ['-I' + p for p in include_paths()]
cmd += ['-L' + p for p in library_paths()]
cmd += ['-Wl,-rpath,' + p for p in library_paths()]
cmd += ['-ltorch_cpu', '-ltorch', '-lc10']
print(f'Building production topk operators with original dispatcher schemas: {arch}', flush=True)
subprocess.run(cmd, check=True)
print(build / 'sgl_kernel/common_ops.so', flush=True)
```

Run the script without an argument to build AVX2. It prints the extension path. Then run the existing test file using that extension:

```bash
PYTHONPATH="/tmp/sglang-topk-validation/module:$PWD/python" \
TRITON_DEFAULT_BACKEND=cpu OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 SGLANG_TEST_MAX_RETRY=0 \
python test/registered/cpu/test_topk.py
```

Passing `avx512` to the build script reproduces the compile-only configuration in a separate directory. It does not execute that binary.
