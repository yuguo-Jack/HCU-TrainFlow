# [Auto-Fix] Add XPU rotary-embedding dtype handling for StableLM-2 (fixes dimension mismatch)

[Upstream PR](https://github.com/sgl-project/sglang/pull/41068) · state: closed · merged: False

## Original PR description

## Motivation

`stabilityai/stablelm-2-1_6b` fails on Intel XPU with a rotary-embedding dimension-mismatch error. `StablelmAttention` in `stablelm.py` only special-cases NPU dtype handling around `rotary_emb` (float32 cast-and-back) — there is no equivalent XPU branch, so q/k tensors are routed through the `sgl_kernel.rotary_embedding` fallback path in the wrong dtype on XPU.

## Modifications

Mirror the existing `_is_npu` handling with a new `_is_xpu` check in `StablelmAttention.__init__` and `.forward`, so XPU also gets the float32 cast-and-back around `rotary_emb` that NPU already relies on.

## Accuracy Tests

Validated on real Intel XPU hardware (P1 CI) running `stabilityai/stablelm-2-1_6b` against `hellaswag` via `sglang serve` + `lm_eval`:
- Smoke run (20 examples): acc=0.35, acc_norm=0.55 — model serves and evaluates correctly with the patch applied (previously crashed with a dimension mismatch before any request completed).
