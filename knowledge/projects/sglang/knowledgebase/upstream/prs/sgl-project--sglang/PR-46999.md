# [Fix] [XPU] spec: Sample EAGLE verification on XPU instead of forcing argmax

[Upstream PR](https://github.com/sgl-project/sglang/pull/46999) · state: open · merged: False

## Original PR description

## Motivation

EAGLE verification on XPU always commits the target model's argmax, because XPU has no `tree_speculative_sampling_target_only` kernel (`_verify_uses_greedy` returns True for every XPU batch). With speculative decoding on, sampled requests (temperature, top-p, top-k) are therefore silently decoded greedily, and the output distribution differs from the same request without speculation.

`--speculative-use-rejection-sampling` is not a way out for most EAGLE3 drafts. Rejection sampling needs a draft distribution over the target vocab, and reduced-vocab drafts (e.g. 32000 of 151936 tokens for the Qwen3 EAGLE3 drafts) do not have one.

## Modifications

The fix rests on one observation: a top-1 EAGLE draft is deterministic, so it is a point-mass proposal. Classic speculative sampling against a one-hot proposal is exactly target-only verification: accept the draft token `t` with probability `p(t)`, and on rejection resample from `p` with `t` removed. That needs no draft distribution.

- `kernels/ops/speculative/reject_sampling.py`:
  - A `ONE_HOT_DRAFT` mode of the existing Triton `speculative_sampling_classic_kernel`. In this mode `q` is 1 for the proposed token and the residual removes only the rejected token. `DraftProbs` is never read and no draft distribution is materialized.
  - New `chain_speculative_sampling_target_only_triton`, with the `tree_speculative_sampling_target_only` signature, so it plugs in where CUDA uses the sgl-kernel op.
  - It supports exact verification only, and raises if accept thresholds other than 1.0 are set.
- `kernels/ops/speculative/verify_sampling.py`: XPU's `tree_speculative_sampling_target_only` is that function.
- `speculative/eagle_utils.py`: `_verify_uses_greedy` now takes `tree_topk`.
  - XPU samples for top-1 chains, or for any tree when rejection sampling is on.
  - Tree drafts (topk > 1) without rejection sampling stay greedy on XPU, as before. The Triton kernel walks a chain, not a tree.
  - CUDA, HIP, CPU and NPU are unchanged.
- Renorm: the sampled verify path calls the platform top-k / top-p renorm kernels, which main now routes to sgl-kernel-xpu on XPU. This PR does not change them.
- Tests:
  - `test_block_verification.py::test_target_only_matches_one_hot_draft`: the target-only mode must accept, reject and resample exactly as the classic kernel does when it is handed the one-hot draft explicitly. The cases cover vocab sizes 7, 17 and 131073 and 1 or 3 steps, with both accepts and rejects. Setting the point-mass probability to 0.5 instead of 1 fails all 3 cases.
  - `test_block_verification.py` is now registered for XPU CI as well.
  - `test_eagle_gate_routing.py` covers the XPU top-1 / tree split. It still checks that every other platform reduces to the original predicate.

## Accuracy Tests

GSM8K, sampled, on Qwen3-30B-A3B, TP4 on 4x Arc Pro B70. Settings: sgl-eval, full 1319 questions, temperature 0.7, top-p 0.8, thinking off, max 2048 tokens.

| | GSM8K | accept length |
|---|---|---|
| no speculative decoding | 95.38% | - |
| EAGLE3 (`Tengyunw/qwen3_30b_moe_eagle3`, 3 steps, topk 1), this PR | 95.22% | 2.5-2.9 |

Kernel and unit tests on Arc Pro B70:
- `test_block_verification.py`: 28 passed.
- `test_eagle_gate_routing.py`: 10 passed.

## Speed Tests and Profiling

This is a correctness fix: before it, sampled requests on XPU were not sampled at all. The sampled verify path adds a softmax, the renorm kernels and one Triton launch per verify step. The run below verifies sampled requests end to end on Qwen3-32B-FP8 with EAGLE3. It ran with the Triton renorm kernels, which this PR used on XPU before main switched XPU to sgl-kernel-xpu's; those are 7-13x faster at batch 16-64 on B70, so the TPOT below should not get worse.

**Combined check on main** (`7e142dd9fd` with #46997-#47003 applied, sgl-kernel-xpu 0.5.0, 4x B70, TP4, cookbook BMG flags plus `--attention-backend intel_xpu --page-size 64 --cuda-graph-backend-decode full --cuda-graph-backend-prefill breakable`, EAGLE3 with 3 steps / topk 1 / 4 draft tokens, GSM8K full 1319 sampled at 0.7 / 0.8):

| model | GSM8K | c=1 median TPOT | c=4 median TPOT |
|---|---|---|---|
| Qwen3-30B-A3B bf16 | 94.69% (95.38% in an earlier run without these PRs) | 6.74 ms | 10.68 ms |
| Qwen3-32B-FP8 + EAGLE3 (`AngelSlim/Qwen3-32B_eagle3`, sampled verify) | 95.30% | 11.08 ms (accept length 2.37) | 13.97 ms |
