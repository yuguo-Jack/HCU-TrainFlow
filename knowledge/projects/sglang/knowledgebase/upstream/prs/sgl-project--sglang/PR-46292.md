# [Fix] spark2_5: Honor gate_attn_act_mode instead of hardcoding sigmoid

[Upstream PR](https://github.com/sgl-project/sglang/pull/46292) · state: open · merged: False

## Original PR description

Fixes #37639

## Motivation

`Spark2_5Attention` hardcodes `torch.sigmoid` for the per-head attention
output gate, ignoring the config field `gate_attn_act_mode` that the
reference implementation (`modeling_spark.py`) honors with `sigmoid` and
`silu` branches (and a `ValueError` for anything else). Both released
Spark-X2.5 checkpoints declare `"sigmoid"`, so there is no divergence
today, but any future checkpoint declaring `"silu"` would silently get
the wrong gate activation (bounded, strictly positive `sigmoid` instead
of unbounded `silu`, which goes negative for `x < 0`), with the error
compounding across every attention layer and no error pointing at the
cause.

## Modifications

- `python/sglang/srt/configs/spark2_5.py`: declare `gate_attn_act_mode`
  (default `"sigmoid"`, matching the released checkpoints and preserving
  current behavior for configs that omit the field).
- `python/sglang/srt/models/spark2_5.py`:
  - `Spark2_5Attention` takes `gate_attn_act_mode` (default `"sigmoid"`)
    and validates it at construction, raising `ValueError` for
    unsupported modes when the gate is enabled, so a bad config fails
    fast at load time instead of silently serving wrong activations.
  - `forward` applies `F.silu` when the mode is `"silu"` and keeps the
    existing `torch.sigmoid` path otherwise.
  - `Spark2_5DecoderLayer` forwards `getattr(config,
    "gate_attn_act_mode", "sigmoid")` to the attention module.

## Tests

No GPU and no torch on this machine, so the change could not be run
through a model forward pass here; that verification is left to CI:

- A stub harness executed the actual activation-selection lines
  extracted from `forward` (via AST, not a copy) against a minimal
  fake tensor: the `sigmoid` branch and the `silu` branch both match
  the reference activations exactly on `[-6, -2, -0.5, 0, 0.5, 2, 6]`.
- The same harness checks the `__init__` default (`"sigmoid"`), the
  unsupported-mode `ValueError`, the decoder-layer config forwarding,
  and the config-class field.
- `ruff check --select F401,F821,F823,UP037`, `ruff format --check`,
  `python3 -m py_compile`, and `git diff --check` all pass on both
  touched files. No existing test covers `spark2_5` gate behavior
  (checked the test tree), so no test contradicts the new behavior.
