# [Feat] pp: Add CPU-staged Gloo transport for pipeline parallelism

[Upstream PR](https://github.com/sgl-project/sglang/pull/45790) · state: open · merged: False

## Original PR description

## Motivation

TDX / Confidential Computing (CC) deployments that require host-memory PP communication need a selectable `GPU → CPU → Gloo → CPU → GPU` path while retaining their existing TP backend. The tested upstream baseline (`16eb87c06fca`) does not expose this PP path. This PR adds `--pp-transport gloo`, stages PP payloads through owned CPU buffers and restores received tensors to CUDA. Default transport selection and TP collectives are preserved.

The existing PP tensor send path does not automatically stage CUDA tensors on the CPU for Gloo. In the tested environment, explicitly creating Gloo process groups and sending CUDA tensors directly triggers `gloo::IoException: writev ... Bad address`. This PR adds GPU-to-CPU staging on send and CPU-to-GPU restoration on receive so that PP payloads can travel through Gloo.

A matched end-to-end comparison on two H20 hosts exercised Qwen3.5-35B-A3B with cross-host TP1/PP2, NEXTN and full decode CUDA graphs. The unmodified upstream default NCCL path completed eight serial warmup requests but failed to complete the concurrency-4 warmup block within the common 180-second limit. A second control using the PR implementation at the time with default NCCL also exceeded the limit: its first serial warmup block eventually took 184.01 seconds. Gloo completed all 32 warmup requests and 48 measured requests. Its measured output token sequences matched across repeats and concurrency settings. The same model, runtime, input tokens and serving settings were used, apart from transport selection and the implementation revisions being compared.

Startup and two full-shape warmup rounds were excluded from timing. Populated Triton caches were shared across cases on each host; server logs and cache-artifact timestamps showed no new compilation during the measured blocks or failed NCCL warmup windows.

## Modifications

- Select Gloo for the PP process groups and avoid creating a PP PyNccl communicator when CPU staging is enabled.
- Copy outgoing PP tensors into owned, contiguous CPU buffers; retain asynchronous send buffers until completion. Restore received tensors to their original device before TP all-gather reassembles sharded payloads.
- Cover tensor dictionaries, bidirectional exchanges, tensor broadcasts and raw tensor P2P. Route PP object-list broadcasts through the CPU group; existing scheduler control messages continue to use their Gloo path.
- Add a four-rank Gloo regression with real TP all-gather, configuration/communicator-policy tests, and an eager-versus-CUDA-graph generation test with replay and log-drain assertions.
- Document cross-host deployment and synchronous staging costs.

This option currently requires CUDA and PP > 1; independent DP replicas and elastic rank offsets are rejected. Host staging is synchronous; asynchronous work overlaps Gloo transmission only. Gloo manages its own peer connections, so no fixed PP port range is exposed.

Gloo communication does not add encryption, peer authentication or attestation. Object communication uses pickle and requires trusted peers. Deployments must protect inter-host traffic separately. PD KV transfer remains a separate configuration.

## Accuracy Tests

Isolated Linux CPU validation passed 66 tests and 22 subtests, including configuration validation. The four-rank Gloo test exercises actual PP sends and TP all-gather with noncontiguous, non-divisible, empty, scalar and BF16 payloads; it also checks asynchronous snapshots, bidirectional exchange, broadcasts and tagged object receives. Default communicator-policy tests cover CUDA, NPU, XPU and Mooncake policy without requiring those accelerators.

Cross-host Qwen3.5-35B-A3B validation on H20 completed all eight Gloo configurations: TP1/TP2, PP2, ordinary decoding and NEXTN, each in eager and full decode CUDA graph modes. All four pairs matched 20/20 measured 64-token outputs (80/80 paired comparisons; 160 requests). Replay counts refer only to the four full decode CUDA graph configurations, including warmup. Both PP stages had the same count within each configuration, with no logged decode fallback: 952 each for TP1 ordinary and TP2 ordinary, 337 for TP1 NEXTN, and 336 for TP2 NEXTN. Counts are decode-batch log entries. The 80/80 comparisons pair eager and full execution within each TP configuration; request-level draft acceptance statistics differ between TP1 and TP2. Prefill graphs were disabled.

The updated GPU CI test compares Gloo eager and full decode CUDA graphs, requires replay on both stages and rejects logged decode fallback after shutdown and output capture have completed. The test passed on two H20 GPUs using a hash-verified local copy of Qwen2.5-1.5B-Instruct (1 test, 169.3 seconds).

The two-rank GPU regression uses real Gloo process groups and contiguous CUDA graph outputs, exercising the actual PP tensor-dictionary send/receive methods. Three consecutive graph replays pass data, dtype, receiver-device and asynchronous send-buffer snapshot checks. Disabling only CPU staging reproduces the `Bad address` error described above.

The new contiguous CUDA-payload regression passed on two H20 GPUs (1 test, 22.143 seconds).

## Speed Tests and Profiling

The matched TP1/PP2 + NEXTN comparison used 256 input tokens / 128 output tokens, two unmeasured rounds followed by three measured rounds, each with eight requests at concurrency 1 and 4. Median measured output throughput:

| Transport / source | Warmup outcome | Measured requests | Output tokens/s, c1 / c4 |
| --- | --- | ---: | ---: |
| Default NCCL / unmodified upstream | c4 exceeded 180-second block limit | 0 | N/A |
| Default NCCL / tested PR implementation | first c1 block took 184.01 s; exceeded limit | 0 | N/A |
| Gloo / tested PR implementation | 32/32 completed | 48 | 123.98 / 275.88 |

Gloo logged 1,788 decode graph replays per PP stage, including warmup, with no logged decode fallback. Its c4 repeats ranged from 245.81 to 285.42 output tokens/s. Failed warmup timings are diagnostics, not steady-state performance measurements.

The following broader Gloo-only measurements were collected separately:

Completed on two H20 hosts with full decode CUDA graphs and Gloo PP transport: 256 input tokens / 128 output tokens, concurrency 1/4, three repeats of eight requests per concurrency (48 requests per configuration). Throughput is the median of three runs; TTFT and TPOT are medians over requests. Profiling is excluded from timing.

| Configuration | Output tokens/s, c1 | Output tokens/s, c4 | TTFT ms, c1 / c4 | TPOT ms, c1 / c4 |
| --- | ---: | ---: | ---: | ---: |
| TP1/PP2, ordinary | 86.02 | 246.44 | 198.4 / 400.9 | 10.15 / 13.20 |
| TP1/PP2, NEXTN | 126.93 | 237.51 | 224.0 / 394.6 | 5.99 / 10.40 |

TP2 has lower throughput than TP1 in three of the four comparisons, with NEXTN c4 as the exception. TP2 retains synchronous CPU staging and adds TP collectives and all-gather for PP shard reassembly.

At TP1, NEXTN c4 had lower median throughput than ordinary decoding (237.51 vs 246.44 tokens/s); at TP2, it was higher (285.21 vs 221.21 tokens/s). The two independent TP1 NEXTN c4 measurements had medians of 237.51 and 275.88 tokens/s, with three-repeat ranges of 237.38–284.26 and 245.81–285.42 tokens/s, respectively, showing substantial run-to-run variation.

Within each configuration, full output token sequences matched across repeats and concurrency settings for the same prompts. TP2 NEXTN c4 throughput ranged from 237.43 to 285.99 tokens/s. NCCL did not complete warmup, so no steady-state throughput is available for a speedup calculation.

Process-tree CPU use averaged 0.53–1.60 cores per host across measurement blocks. Peak aggregate process RSS ranged from 3.50 to 7.74 GiB per host; shared pages may be counted more than once. Twelve per-rank CPU traces were collected. CPU receive scopes include synchronization and waiting.

The validation targets Confidential Computing (CC) deployments. Both hosts reported GPU CC State OFF; GPU CC-On and attestation were not tested.

The environment previously rejected GPU CUPTI activities with `CUPTI_ERROR_CONFIDENTIAL_COMPUTING_NOT_SUPPORTED (41)`. The collected traces contain CPU activities only.

```python
"""Same e2e workload, explicit full-shape warmup, atomic progress and timing gates."""

import argparse
import json
import os
import threading
import time
from concurrent.futures import ThreadPoolExecutor
from pathlib import Path

import requests
from transformers import AutoTokenizer

p = argparse.ArgumentParser()
p.add_argument("--url")
p.add_argument("--model")
p.add_argument("--output")
p.add_argument("--node0-log", required=True)
p.add_argument("--node1-log", required=True)
a = p.parse_args()
out = Path(a.output)
assert not out.exists()
lock = threading.RLock()
tok = AutoTokenizer.from_pretrained(a.model, local_files_only=True)
base = tok.encode(
    "Explain pipeline parallelism and CPU communication. " * 80,
    add_special_tokens=False,
)
inputs = [
    (tok.encode(f"Question {i}: ", add_special_tokens=False) + base)[:256]
    for i in range(8)
]
r = dict(
    input_ids=inputs,
    input_tokens=256,
    output_tokens=128,
    status="running",
    warmups=[],
    runs=[],
    phase="initializing",
    phase_status="idle",
    events=[],
)


def save():
    with lock:
        temp = out.with_suffix(".tmp")
        temp.write_text(json.dumps(r, indent=2))
        temp.replace(out)


def log_counts():
    return {
        str(i): sum(
            "took" in l and "compile" in l
            for l in Path([a.node0_log, a.node1_log][i]).read_text().splitlines()
        )
        for i in [0, 1]
    }


def generate(item):
    i, ids = item
    start = time.perf_counter()
    first = None
    final = None
    chunks = []
    with requests.post(
        a.url + "/generate",
        json={
            "input_ids": ids,
            "stream": True,
            "sampling_params": {
                "temperature": 0,
                "max_new_tokens": 128,
                "ignore_eos": True,
            },
        },
        stream=True,
        timeout=200,
    ) as res:
        res.raise_for_status()
        for line in res.iter_lines(chunk_size=1):
            if not line.startswith(b"data: ") or line == b"data: [DONE]":
                continue
            obj = json.loads(line[6:])
            if obj.get("error"):
                raise RuntimeError(obj)
            if obj.get("output_ids"):
                now = time.perf_counter()
                if first is None:
                    first = now
                    with lock:
                        r["events"].append(
                            dict(
                                phase=r["phase"],
                                request=i,
                                event="first_token",
                                time=time.time(),
                            )
                        )
                        save()
                final = obj
                chunks.append([now - start, len(obj["output_ids"])])
    end = time.perf_counter()
    assert final and len(final["output_ids"]) == 128
    result = dict(
        ids=final["output_ids"],
        ttft_s=first - start,
        latency_s=end - start,
        tpot_s=(end - first) / 127,
        chunk_arrivals=chunks,
        meta_info=final["meta_info"],
    )
    with lock:
        r["events"].append(
            dict(phase=r["phase"], request=i, event="complete", time=time.time())
        )
        save()
    return result


save()


def enforce_deadlines():
    start = time.monotonic()
    while True:
        time.sleep(0.2)
        with lock:
            if r["status"] != "running":
                return
            if (
                r.get("phase_status") == "running"
                and time.time() - r["phase_started_at"] > 180
            ) or time.monotonic() - start > 900:
                r["status"] = "failed"
                r["error"] = "Request block exceeded 180 s or client exceeded 900 s"
                save()
                # ThreadPoolExecutor cannot cancel an in-flight HTTP request. Exit only
                # this client; the operator retains control of both model servers.
                os._exit(2)


threading.Thread(target=enforce_deadlines, daemon=True).start()
try:
    for stage, repeats in [("warmup", 2), ("measure", 3)]:
        for repeat in range(repeats):
            for c in [1, 4]:
                requests.get(a.url + "/flush_cache", timeout=30).raise_for_status()
                with lock:
                    r.update(
                        phase=f"{stage}-{repeat}-c{c}",
                        phase_status="running",
                        phase_started_at=time.time(),
                    )
                    save()
                counts = log_counts()
                start = time.perf_counter()
                started_at = time.time()
                with ThreadPoolExecutor(max_workers=c) as pool:
                    rows = list(pool.map(generate, enumerate(inputs)))
                elapsed = time.perf_counter() - start
                new_counts = log_counts()
                entry = dict(
                    repeat=repeat,
                    concurrency=c,
                    started_at=started_at,
                    finished_at=time.time(),
                    elapsed_s=elapsed,
                    output_tokens_per_s=1024 / elapsed,
                    requests=rows,
                    compile_messages_before=counts,
                    compile_messages_after=new_counts,
                )
                with lock:
                    r["warmups" if stage == "warmup" else "runs"].append(entry)
                    r["phase_status"] = "complete"
                    save()
                print(
                    stage,
                    repeat,
                    c,
                    elapsed,
                    "new_compilation",
                    counts != new_counts,
                    flush=True,
                )
                if stage == "measure" and counts != new_counts:
                    raise RuntimeError(
                        "Compilation detected in measured window; do not report this timing"
                    )
    r["status"] = "complete"
    r["benchmark_status"] = "complete"
    save()
except BaseException as exc:
    r["status"] = "failed"
    r["error"] = repr(exc)
    save()
    raise
```
