# [Fix] [AMD] dsv4: Fix the mHC weight orientation across layer boundaries

[Upstream PR](https://github.com/sgl-project/sglang/pull/48065) · state: open · merged: False

## Original PR description

On gfx1250, read the mHC projection weight transposed at the cross-layer boundary (`deepseek_v4_boundary.py`) and in the platform decoder stage (`deepseek_v4_platform_stage.py`), matching how it is stored.

<!-- results -->
### Accuracy
GSM8K (200 questions, greedy), DeepSeek-V4-Pro: TP4 0.965.

### Performance
Setup:
- Model: DeepSeek-V4-Pro, BF16 KV cache, DSPARK speculative decoding (block 6, 1 step)
- Parallelism: TP4 (`--tp 4`, CP prefill + CP decode attention)
- Step time: torch profiler on rank 0, GPU time per step; decode = 8 steps at 4 running requests (VERIFY = target verify, DRAFT = DSPARK draft), prefill = one EXTEND step of an ~8k-token prompt (TP4) / 4k (EP4)
- Comparison: with vs without this PR, same image and node, all earlier PRs of the series applied

Without this PR the server does not start on gfx1250 (the TileLang `mhc_fused_post_pre` fails to build). With it, decode VERIFY 17.77 ms, DRAFT 1.83 ms, prefill 191.9 ms per step.
