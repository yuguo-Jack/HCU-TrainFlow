# [Perf] unified-memory: Bind the SWA tail's new pages without a host sync in alloc_extend_swa_tail

[Upstream PR](https://github.com/sgl-project/sglang/pull/47542) · state: closed · merged: True

## Original PR description

## Motivation

`ChainAllocator.alloc_extend_swa_tail` is the decode-side preallocation path for hybrid full/SWA models under unified memory: the owner band takes virtual pages for the whole sequence, and the window band binds only the pages of the live window tail. The pages to bind were picked on the device, with `torch.unique` over the tail of the extend kernel's output followed by `torch.isin` against the new virtual pages. Both are data-dependent and synchronize the host with the device, so admission in the scheduler stalled behind the in-flight forward.

## Modifications

This change is expressed on the allocator structure introduced in #46976, where `alloc_extend_swa_tail` hands `_allocate` a `tail_pages` closure that selects the window pages to bind.

Pick the tail's new pages on the host instead. The extend kernel hands the j-th new virtual page to sequence page `first_new_page + j`, and `num_swa_pages`, the number of tail pages that are new, is already computed on the host for admission pricing. The tail's new pages are therefore the last `num_swa_pages` entries of the new virtual pages, so `tail_pages` returns that slice (and an empty slice when no new page lies in the tail) with no device round trip. The pages bound, the prefix pages left alone, and the admission price are unchanged.

## Accuracy Tests

No numerics change: the window binds the same pages as before. Ran the unit tests that drive `alloc_extend_swa_tail` against this branch on one GPU; the swa-tail test also passes unchanged on main, as expected for a sync-free rewrite that binds the same pages:
