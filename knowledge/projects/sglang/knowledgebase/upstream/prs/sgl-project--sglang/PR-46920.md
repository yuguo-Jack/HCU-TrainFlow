# [Fix] [NPU] attention: honour sliding window for ENCODER_ONLY layers

[Upstream PR](https://github.com/sgl-project/sglang/pull/46920) · state: open · merged: False

## Original PR description

## Motivation

Fixes sgl-project/sgl-kernel-npu#865. On the Ascend backend, an `ENCODER_ONLY` attention layer that has a valid `sliding_window_size` silently computes **global** attention instead of windowed attention when it goes through the hybrid-SWA FIA path.

Root cause is in `AscendAttentionBackendImpl.forward` (the `is_hybrid_swa` branch): the encoder-only override forces

```python
if layer.attn_type == AttentionType.ENCODER_ONLY:
    mask = None
    sparse_mode = 0
```

`sparse_mode=0` means "no mask", and FIA only applies `pre_tokens`/`next_tokens` in the banded sparse modes. The layer keeps passing `pre_tokens=sliding_window_size`, but the kernel ignores it, so encoder-only layers with SWA attend to the whole sequence and produce wrong outputs.

## Modifications

For the encoder-only case, use the same banded mode (`sparse_mode=4`) that SWA layers already use in this branch, and make the band symmetric:

- `sparse_mode = 4 if is_swa_layer else 0`
- `next_tokens = layer.sliding_window_size if is_swa_layer else FULL_ATTENTION_WINDOW`

The non-encoder path is unchanged (`next_tokens=0` stays causal for decoder SWA). `next_tokens` is now computed next to `sparse_mode` in the `if/else` so both FIA calls below share one value instead of re-deriving it inline.

For non-SWA encoder-only layers both settings stay as before (`sparse_mode=0`, `FULL_ATTENTION_WINDOW`), so this is a no-op for every other configuration.

## Accuracy Tests

None yet: I do not have Ascend hardware, so I could not run the encoder-only SWA model from the issue (reported on 910B and 950 with CANN 9.0). The change is derived from the surrounding code: the same file already expresses "sliding window in FIA" as `sparse_mode=4` + `pre_tokens=window` (+ `next_tokens=0` for causal decoders).

- bupt-lxc · comment · 2026-11-02T09:33:03Z · [source](https://github.com/sgl-project/sglang/pull/46920#issuecomment-6573749280)

Hi @wangbo23,

I have access to Ascend hardware and tested your PR on **Ascend910B2 with CANN 9.0.0**. I confirmed the underlying window-attention issue and found two remaining problems in the current implementation.

I prepared a small follow-up based directly on your current head, `1b5c0c7921b2b2634c69a9d9b3bb4174278fcc14`:

**[[a442cfeae1 — fix(npu): pass MTP band mask and non-hybrid window bounds](https://github.com/bupt-lxc/sglang/commit/a442cfeae1b81296ef614aa6dd74426dcb161f11)](https://github.com/bupt-lxc/sglang/commit/a442cfeae1b81296ef614aa6dd74426dcb161f11)**

The commit changes only `ascend_backend.py`: **9 additions and 1 deletion**. Validation scripts and logs are kept separately. This fix was accomplished by me together with Codex.

**What I found**

1. **Encoder SWA needs a mask when using band mode.**

   Your change correctly selects `sparse_mode=4` and makes the encoder window symmetric. However, the current code still passes `atten_mask=None`. On CANN 9.0.0, the operator rejects this combination with error **561002**:

   ```text
   When attnMask is not provided, sparseMode must be 0
   ```

   The follow-up reuses the existing compressed MTP mask for encoder SWA:

   ```python
   mask = self.mtp_mask if is_swa_layer else None
   ```

   The existing symmetric `pre_tokens=W` and `next_tokens=W` bounds are retained. This does not turn encoder attention into causal attention: the future-token visibility test described below confirms that future tokens inside the window remain visible. Global encoder attention continues to use `mask=None`.

2. **The non-hybrid FIA call also needs explicit window bounds.**

   The V2 call already receives `pre_tokens` and `next_tokens`, but the non-hybrid call omits both. Selecting band mode alone therefore does not establish the intended window.

   The follow-up passes the same bounds to both operators:

   | Attention type | Left bound | Right bound |
   | --- | ---: | ---: |
   | Encoder SWA | `W` | `W` |
   | Decoder SWA | `W` | `0` |

   This also fixes the non-hybrid decoder SWA numerical failure observed during validation.

**Test environment and method**

- Ascend910B2, 64 GB; the regression run was repeated on a second 910B2 card.
- CANN 9.0.0.
- PyTorch/TorchNPU 2.10.0.
- `sgl-kernel-npu` 2026.9.0.
- BF16 inputs, compared against independent CPU float32 masked attention.

The backend tests import and execute the actual `AscendAttnBackend.forward_mtp` method with real NPU tensors, paged KV caches, and real FIA operators. Minimal batch metadata and cache accessors are used to isolate this branch; the attention operators are not mocked.

**Before/after results**

The same test file was run before and after the implementation change:

| Version | Result |
| --- | --- |
| Current PR head | 18 encoder mask-related subtest errors and 1 non-hybrid decoder numerical failure |
| With the follow-up | All 10 test methods / 24 path configurations pass |

The non-hybrid decoder failure before the fix had a greatest absolute difference of approximately **2.663086** from the CPU reference. Global encoder/decoder controls and hybrid decoder SWA passed before the fix.

Coverage includes both hybrid V2 and non-hybrid FIA, with:

- Encoder and decoder local/global attention.
- Cached prefixes with unequal Q/KV lengths and right-aligned positions.
- Ragged batches and non-contiguous physical page mapping.
- Sequence lengths around the window boundary.
- TARGET_VERIFY and list-based graph metadata.

There is also a deterministic boundary test: for query position 64 and window radius 31, keys 33 and 95 must contribute, while key 96 must not. This detects both accidental causal masking and accidental global attention.

General numerical checks use `atol=0.02, rtol=0.02`; the deterministic boundary test uses `atol=0.0002, rtol=0`.

**Checks with real pretrained models**

The original reporter’s model was unknown. I loaded five complete pretrained models and ran 1024-token Hugging Face eager forwards on one NPU. I captured real Q/K/V from their local/global attention layers and replayed them through both repaired FIA paths.

All **16 model/layer/path comparisons** passed independent CPU float32 references with `atol=0.03, rtol=0.03`. The following RMSE values were identical between the hybrid and non-hybrid paths in this run:

| Qwen3 0.6B | Causal global attention | N/A | 0.000175 |
| Qwen3-Embedding 0.6B | Causal global attention | N/A | 0.000184 |
