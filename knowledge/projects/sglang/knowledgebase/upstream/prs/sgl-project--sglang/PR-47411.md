# [Feat] diffusion: Native Gemma-4-Unified text encoder for LTX-2.5

[Upstream PR](https://github.com/sgl-project/sglang/pull/47411) · state: closed · merged: True

## Original PR description

## Motivation

LTX-2.5's text encoder (`Gemma4UnifiedForConditionalGeneration`, 22 GB) has no SGLang implementation. On main it loads through `transformers.AutoModel`:

```
Component: text_encoder doesn't have a customized version yet, using native version
Native component text_encoder: Gemma4UnifiedModel is loaded, performance may be sub-optimal
```

`runtime/models/encoders/gemma_4_unified.py` only class-swaps that transformers module so it can be layerwise-offloaded (#43683).

## Modifications

- `Gemma4UnifiedForConditionalGeneration` in `runtime/models/encoders/gemma_4_unified.py` builds only the text path, because LTX-2.5 reads the embedding output plus all 48 decoder hidden states. The vision and audio embedders in the checkpoint are not loaded.
  - It covers the fused QKV and gate/up GEMMs (`QKVParallelLinear` / `MergedColumnParallelLinear` / `RowParallelLinear`), `k_eq_v` full-attention layers (V loads K's weights), QK/V RMSNorm, per-layer-type RoPE (`default` / `proportional`), and sliding-window plus padding masks.
  - Ops run in the same order and dtypes as the transformers SDPA path. LTX2 already pins this component to torch SDPA.
  - It declares `layer_names` / `host_resident_table_names`, so layerwise offload and the host-resident vocab table keep working.
- The transformers class-swap adapter stays for checkpoints whose format transformers owns.
- `configs/models/encoders/gemma_4_unified.py`: the config now carries the repo's `text_config`. The gate/up shard ids are ints.
- The unit tests in the existing `test_gemma4_unified_layerwise_offload.py` check that a small random model matches transformers, the `k_eq_v` / GQA layers, and the layerwise and host-resident declarations.

## Accuracy

4×B300 (sm_100), `Lightricks/LTX-2.5-Diffusers` revision 4791a110, bf16, torch 2.14.1. Native vs transformers on the same GPU:

| prompts | tokens | connector input (all 49 hidden states) |
|---|---|---|
| 5 single prompts (EN incl. 1-token and 198-token, ZH) | 1–198 | bitwise identical, max abs 0.0 |
| batch of 2 (13 + 38 tokens, padded) | | bitwise identical |

End-to-end `sglang generate` LTX-2.5 (two-stage, 1920×1088×121, same seed): the MP4 md5 is identical (`4abb8c3a…`) with the native encoder and with the transformers one.

## Speed

- Encode B=1 S=1024, median/min: native 47.18 / 47.15 ms, transformers 47.15 / 47.13 ms, i.e. unchanged.
- Load time: native 4.4 s, transformers 4.9 s.

- Serving, `ltx2.5_twostage_t2v_2gpus` (2×B300, Ulysses 2 + breakable CUDA graph, client wall clock, 2 requests per fresh server): this PR 5.093 / 5.086 s, main 1ab008f5 with the transformers encoder 5.113 / 5.101 s. vLLM-Omni 0da1d831 on the same box: 5.962 / 6.032 s.

## Not tested

- TP > 1 for this encoder on GPU. LTX-2.5's serving recipes run it at TP 1.
- AMD / NPU.
