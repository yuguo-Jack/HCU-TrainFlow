# [Bugfix] Warn when ordinary --api-key also unlocks ADMIN_OPTIONAL endpoints

[Upstream PR](https://github.com/sgl-project/sglang/pull/44230) · state: open · merged: False

## Original PR description

## Summary

Fixes #43706 without breaking legacy single-key deployments.

When only `--api-key` is set (no `--admin-api-key`), `AuthLevel.ADMIN_OPTIONAL` management endpoints still accept the ordinary key — intentional compat from #15908. Operators often miss that this makes every client credential a management credential.

This PR keeps that auth behavior, and:
1. Logs a startup **WARNING** when `api_key` is set and `admin_api_key` is unset, naming representative endpoints (`/update_weights_from_disk`, `/load_lora_adapter`, `/start_profile`) and recommending `--admin-api-key`.
2. Documents the single-key exposure in `--api-key` / `--admin-api-key` help text and server-args docs.

No change to `decide_request_auth` fallback when only `api_key` is configured.
