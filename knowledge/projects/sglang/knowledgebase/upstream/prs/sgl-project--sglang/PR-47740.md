# [Perf] [NPU] dsv4: bound decode SWA storage by request slots

[Upstream PR](https://github.com/sgl-project/sglang/pull/47740) · state: open · merged: False

## Original PR description

## Motivation

DeepSeek V4 PD decode currently sizes NPU SWA storage as a fraction of full KV capacity. Long-context capacity therefore reserves many more SWA rows than the live decode window needs.

This adds an opt-in request-owned ring. In the tested DeepSeek-V4-Flash W8A8 / Ascend 910C DSpark configuration, post-request occupied HBM fell from 49.373 to 44.880 GiB per logical NPU, with full KV capacity held at 688,512 tokens. These are snapshots, not peak-memory measurements.

## Modifications

- Reserve 256 SWA rows per request slot, including the existing spare/dummy slots, and size C4 compression state from those pages.
- Map appended full KV locations to `request_slot * 256 + position % 256`; clear those mappings before released full IDs can be reused.
- Reuse the existing request-ring allocator lifecycle and target/draft PD transfer layout checks.

Enable with `SGLANG_DSV4_NPU_DECODE_SWA_RING=1`. The default is off. The initial scope is pre-A5 PD decode, window/page size 128, PP/CP/DCP=1, an explicit request limit, and plain decode or DSpark with at most six verification tokens. Radix reuse, KV offload, HiCache, HiSparse, unified memory and encoder replay are rejected. The tested configuration also requires `--disaggregation-decode-retraction-backup cpu_tensor`; V4 actually resumes by P-side recomputation, not a CPU KV round trip.

## Accuracy Tests

Hardware tests used base `fa5580f6d0e969a3d44c603d215e2139886e8db2`, TP16 / attention DP16, BF16 KV, context 32,768 and temperature 0. DSpark used gamma 5 / verify width 6, `SGLANG_DSPARK_FAST_KERNEL=0`, and the official `sgl-kernel-npu` 2026.9.0.post12 package.

| Check | Result |
|---|---|
| Sequential and page-boundary cases | 5,700 output token IDs match |
| Request-slot reuse | 19,200 token IDs match the saved baseline |
| Prompt lengths 8,191 / 16,383 / 32,447 | 900 token IDs and selected-token logprobs match |
| Fixed-position retraction | 900 token IDs and selected-token logprobs match across base/ring |

For the retraction comparison, identical diagnostic copies allowed a single request to retract once after exactly 64 emitted tokens. Both arms had identical prefixes and repeatable results. Both also diverged from uninterrupted generation at output token 88, so this reproduced difference exists without the ring change. The diagnostic edits and test files are not part of this PR.

**Draft limitation:** mixed 64-request concurrency is not a parity pass. Ring-off repetitions also differ, so those runs do not isolate a ring regression or establish equivalence. General concurrent and memory-pressure retraction coverage remains outstanding.

## Speed Tests and Profiling

| Per logical NPU | Baseline | Ring |
|---|---:|---:|
| Full KV capacity | 688,512 | 688,512 |
| SWA rows, each target/draft pool | 68,736 | 3,328 |
| Target C4 state rows | 8,592 | 416 |
| Post-request occupied HBM (GiB) | 49.373 | 44.880 |

Saving: **4.493 GiB per logical NPU (9.10%)**, relative to the model-default SWA ratio of 0.1. No throughput or latency improvement is claimed.

In the fixed-position test, both arms had identical native speculative counts: control 206/480 correct/proposed drafts, 96 verifications, AL 3.125; each retracted run 203/500, 100 verifications, AL 3.0. Strict acceptance was 42.92% and 40.60%, respectively.
