# [Feat] deepseek-v4.1: the V4.1 KV cache layouts on SM120 / SM121

[Upstream PR](https://github.com/sgl-project/sglang/pull/45851) · state: open · merged: False

## Original PR description

## Motivation

DeepSeek-V4.1 defines two KV cache layouts. The checkpoint's own `inference/model.py` and DeepSeek's DeepInfer (`V41_FORMAT`) agree on both:

- **Window/SWA KV:** all 512 values, RoPE part included, in e4m3 blocks of 32 with UE8M0 scales.
- **Ratio-1/2 compressed KV:** e2m1 blocks of 16 with e4m3 scales.

SGLang already has both layouts as `KVLayout.V41` and `V41_FP4`, and its writers support them. However, `select_dsv4_kv_layout` allows them only on SM100. SM120 / SM121 (RTX 50, RTX PRO Blackwell, DGX Spark) therefore always run the V4 layout, which keeps RoPE in bf16 and uses FP8 blocks of 64.

FlashInfer 0.7.2 already ships SM120 kernels that read both V4.1 caches (`kv_scale_format="ue8m0_g32"`, `extra_kv_fp4`).

## Modifications

- `select_dsv4_kv_layout`: return V41 on SM12x when `SGLANG_DSV4_KV_LAYOUT=v41` and `SGLANG_SM120_FLASHMLA_BACKEND=flashinfer` (the default backend). The default layout stays `v4`, so nothing changes unless the variable is set.
- `flash_mla_with_kvcache_sm120`: a 528-byte main cache goes to FlashInfer's `SparseMLASm120Wrapper`, with:
  - `kv_scale_format="ue8m0_g32"`;
  - `extra_kv_fp4` set for a 288-byte extra cache;
  - one wrapper per (extra format, device).

  The cache is read in place: FlashInfer takes the page size at run time, so the 256 → 64 page split the V4 path needs is skipped.
- `SGLANG_SM120_V41_PRECISION`, default `bf16`, selects FlashInfer's full-BF16 route: bf16 Q and P, exact on-chip dequantization, and fp32 softmax and merge, as the reference computes. `default` selects FlashInfer's MXFP8 route.

## Accuracy Tests

DeepSeek-V4.1-Flash (1017 checkpoint) on 2× RTX 5070 Ti (SM120), TP2.

- **Writers:** the V41 / V41_FP4 writers match the reference's `act_quant` / `fp4_act_quant`. 0 of 2,097,152 values differ in each.
- **Attention, single op:** compared against torch attention over SGLang's own dequantization of the same pages.

  | Route | Error |
  |---|---|
  | full-BF16 | 0.2–0.3% |
  | FlashInfer's default MXFP8 | 3.2–3.9% |

- **Layer 0's attention output** against the reference implementation, run layer by layer: 3.8% off with the V4 layout, 1.0% with V41.
- **Mean NLL** on 24 × 480-token pieces:

  | Run | Mean NLL |
  |---|---|
  | reference | 2.594 |
  | V4 layout | 2.596 |
  | V41 layout | 2.590 |

  The per-piece SE is about 0.007.

## Speed Tests and Profiling

Decode attention per call under a CUDA graph (1 token, 32 heads):

| Inputs | V4 layout (page split) | V41 layout |
|---|---|---|
| 128 window positions | 16.1 µs | 10.0 µs |
| 128 window + 512 FP4 compressed positions | 18.0 µs | 11.3 µs |

A compressed-KV token takes 288 bytes instead of 584. The 35K-token prefill is unchanged.
