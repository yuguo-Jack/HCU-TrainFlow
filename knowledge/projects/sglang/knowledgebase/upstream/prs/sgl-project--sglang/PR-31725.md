# [Fix] Avoid cross-node JIT build races on shared NFS caches

[Upstream PR](https://github.com/sgl-project/sglang/pull/31725) · state: closed · merged: False

## Original PR description

## What this fixes

1. On a multi node cold start with a shared NFS home directory, every rank on every node computes the same tvm-ffi build directory.
2. tvm-ffi serializes builds with a file lock, but that lock is node local on common NFS mounts, and its build compiles and links the shared library in place.
3. Two hosts entering the cold path at the same time therefore rewrite each other's link inputs mid link, and startup aborts with `ld: final link failed: Stale file handle`.
4. Warm caches never hit this, because the existing fast path finds the built library and skips the build entirely.

Fixes #31347.

## The fix

1. A cold compile now runs in a host private staging directory inside the shared cache, so no two hosts ever share a mutable build directory.
2. The finished library is published to the shared path with a hard link, so the first publisher wins and a library another host already loaded is never swapped underneath it. On filesystems without hard links this falls back to an atomic rename.
3. If publishing fails and the staged copy is gone because another rank on the same host already published, the published library is loaded instead of crashing on a missing path.
4. The staging directory is cleaned up on a best effort basis after a successful publish.
5. The warm start path is unchanged. The library lands at exactly the path the existing fast path checks, so a cache warmed by any host is shared across the cluster.
6. `SGLANG_DISABLE_JIT_KERNEL_STAGED_BUILD=1` restores the previous behavior, and a caller supplied build directory is respected as before.
7. If the operating system refuses the host name lookup or returns an empty name, the staging directory falls back to a name unique to that process rather than one shared fallback name, so hosts that cannot report a name still never share a build directory.

I rejected putting the hostname in the final cache path, because it breaks cluster wide cache sharing and container hostnames are ephemeral, so users with a persistent cache volume would recompile on every container start. I also rejected gating the compile on rank 0 with a barrier, because this code runs lazily at first kernel use with no guaranteed process group at that layer.

## Limitations

1. Not validated on a real multi node NFS cluster. I do not have one. Validation is unit tests with the tvm-ffi boundary mocked, plus reasoning checked against the installed tvm-ffi sources.
2. On filesystems without hard link support the fallback rename can still replace a published library with an identical one. Readers never see a partly written file either way.
3. Cleanup empties each staging directory but never removes the directory or its lock file, so a shared cache keeps one `stage__<host>` directory per host per module version for good. The lock file has to stay, because deleting it while another process holds it open would let two later builders build in the same directory at once.
4. Cleanup can delete build outputs a concurrently building rank on the same host was about to reuse. That rank recompiles once. It wastes work but is safe.
5. A tiny window remains where one host loads the library at the same instant another publishes over it on a filesystem without hard links. The existing rebuild on load failure path covers it.
6. The tests build each racer's filesystem state in one process. There is no real multi process or NFS test.

In containerized, sandboxed, or highly restricted environments (e.g., certain Kubernetes or serverless setups), calling `socket.gethostname()` can raise an `OSError` or other network-related exceptions. Wrapping this call in a `try-except` block ensures that SGLang does not crash on startup if the hostname cannot be resolved.

```python
def _host_tag() -> str:
    """Filesystem-safe per-host tag used to keep staging build dirs host-private."""
    try:
        hostname = socket.gethostname()
    except Exception:
        hostname = "unknown-host"
    hostname = hostname or "unknown-host"
    return re.sub(r"[^0-9A-Za-z._-]", "_", hostname)
```

![medium](https://www.gstatic.com/codereviewagent/medium-priority.svg)

If another host has already successfully compiled and published the `.so` file to the shared directory while this host was compiling, we can skip the redundant `os.replace` call. This reduces unnecessary write and metadata operations on the shared NFS filesystem and minimizes the window for potential `ESTALE` errors on other nodes.

```python
def _publish_and_load(built_so: str, target_so: pathlib.Path) -> Module:
    """Atomically publish a staged ``.so`` into the shared cache dir and load it.

    The staging directory lives inside the target's directory, so ``os.replace``
    stays on one filesystem and is atomic: concurrent publishers (other hosts
    racing the same cold start) can only swap in a byte-identical, fully linked
    ``.so`` — readers never observe a partially written file.
    """
    from tvm_ffi import load_module

    load_path = pathlib.Path(built_so)
    if target_so.is_file():
        load_path = target_so
    else:
        try:
            os.replace(load_path, target_so)
            load_path = target_so
        except OSError:
            logger.warning(
                "Failed to publish staged JIT module %s to %s; "
                "loading it from the staging directory instead.",
                built_so,
                target_so,
                exc_info=True,
            )
    return load_module(str(load_path))
```
