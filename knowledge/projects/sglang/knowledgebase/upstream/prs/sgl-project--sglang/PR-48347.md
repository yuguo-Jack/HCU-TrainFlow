# [Fix] offloader: Enforce the CPU offload storage budget

[Upstream PR](https://github.com/sgl-project/sglang/pull/48347) · state: open · merged: False

## Original PR description

## Motivation

`OffloaderV1` checks only the bytes already offloaded before moving the next whole parameter to CPU. The next parameter can therefore exceed `--cpu-offload-gb`. For example, with a 32-byte budget, two FP32 `Linear(2, 2)` layers offload 40 bytes: the first layer uses 24 bytes, then the second 16-byte weight is admitted because 24 < 32. Packed MoE weights can make this overshoot much larger.

Reviewing bounded expert-storage accounting in our TierWeaver experiments prompted this fix. The existing counter also uses `numel() * element_size()`, which undercounts a strided allocation with gaps.

## Modifications

- Use the existing `_empty_strided_like` helper on the meta device to calculate the CPU allocation's storage bytes before allocating or copying it.
- Skip parameters that exceed the remaining budget, continuing to smaller parameters that fit; charge the same storage size after offloading.
- Add CUDA regression coverage for exact/insufficient/zero budgets, budgets shared across modules, pinned and pageable memory, FP16/FP32 contiguous/transposed/gapped layouts, and views with a nonzero source storage offset. Check forward results against the original layers.

This bounds the requested tensor storages, not allocator caching/rounding overhead or total process RSS. Parameters that previously overshot the CPU budget now stay on the accelerator, so affected configurations may need an explicitly larger offload budget.
