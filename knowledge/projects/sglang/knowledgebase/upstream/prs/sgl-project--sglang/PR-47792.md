# [Fix] frontend: Preserve routing keys when slicing generation requests

[Upstream PR](https://github.com/sgl-project/sglang/pull/47792) · state: open · merged: False

## Original PR description

## Motivation

Continues #27199, which was closed by inactivity automation. GitHub rejected reopening the original PR.

Batch slicing still drops `routing_key` on current main (`a52ee805`). This loses the request affinity key for batched and parallel-sampling requests. `require_reasoning` is already forwarded upstream, so the implementation is now limited to the remaining routing-key bug.

## Modifications

Forward `routing_key` when constructing each sliced request. Test ordinary batches and `n=2` sampling with unset, empty and nonempty keys; retain reasoning metadata checks.

## Accuracy Tests

The new regression fails on unmodified main for four subcases. With the fix, the full CPU io_struct suite passes (64 tests, 2 skipped, 16 subtests). No model-forward changes; GPU serving is not validated locally.

## Speed Tests and Profiling

No benchmark claim; one existing request field is forwarded. Upstream CI is pending after reopening.
