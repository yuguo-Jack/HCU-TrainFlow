# [Feat] lora: CuTeDSL BF16 grouped GEMMs and provider (17/21)

[Upstream PR](https://github.com/sgl-project/sglang/pull/42884) · state: closed · merged: False

## Original PR description

Part 17 of 21 of the LoRA runtime stack (branch `lora-stack-16-cutedsl-bf16`, base `lora-stack-15-cutedsl-schedule`). The stack is cut from the development branch of #42284.

## What this part adds

Add the SM90 (WGMMA) and SM100 (tcgen05) BF16 grouped GEMM kernels, the
compile-and-prepare API, the CuTeDSL BF16 providers for both row domains, the
shared tile logic, and the per-geometry GEMM config store. The BF16 grouped
GEMMs are inventoried for SM90+, and CuTeDSL becomes the BF16 default vendor.

Tests: the runner-level numeric oracles (selected pipelines against an FP32
reference and in replayed graphs, B + activation, down-B-into-base), masked
capacity, contiguous row domain, small-preparation paths and blocks, provider
contracts, the GEMM config store.

- `pre-commit` passed on the changed files of every part; `pre-commit run --all-files` passed on the complete stack tree.

The complete 21-part tree equals the development branch of #42284 at `e7b7179a86` (the `6588053ef2` tree with four test-only follow-ups squashed into its dense commit: the admission/snapshot trim, the restored FP8 block-shape admission pin, a second trim that keeps only the tests guarding silent failures and adds pins for four coverage gaps, and restored numerical and packing coverage; production code is unchanged) minus the benchmark tools and the Triton MoE tuning tables, which follow in separate PRs.
