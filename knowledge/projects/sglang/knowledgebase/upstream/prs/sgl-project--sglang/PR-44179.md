# [Perf] diffusion: convrot_int8 comfy_kitchen issues one GEMM per layer by default

[Upstream PR](https://github.com/sgl-project/sglang/pull/44179) · state: open · merged: False

## Original PR description

## Motivation

`convrot_int8`'s comfy_kitchen backend splits tall GEMMs into 8192-row calls (`SGLANG_KITCHEN_INT8_MAX_ROWS`) to keep them off comfy_kitchen's Stream-K schedule. Every extra call also copies its slice of the output, and with comfy-kitchen 0.2.37 whole-model runs are faster unsplit on every GPU we measured.

## Modifications

- Default `SGLANG_KITCHEN_INT8_MAX_ROWS` to `0` (one call per layer). A positive value still splits.
- Update the comment in `convrot_int8_comfy_kitchen.py`, `environment_variables.mdx` and `quantization.mdx`.

## Accuracy Tests

Splitting rows does not change any row's arithmetic. Outputs are bit-identical with and without the split (same-input ablation on all three GPUs).

## Speed Tests and Profiling

MiniMax-H3 pruned INT8 checkpoint, comfy_kitchen backend, SGLD ComfyUI workflow, 4 steps × 3 seeds. Steady model-time gain going from rows 8192 to 0:

| GPU | 480p / 124 frames | 768p / 124 frames | Ref2VA / 4 refs |
|---|---:|---:|---:|
| RTX 4090 | +3.91% | +2.40% | +2.14% |
| RTX 5090 | +2.96% | +1.62% | +1.26% |
| H200 (kitchen forced) | +2.20% | +1.56% | +1.48% |

H200, B200 and RTX 5090 default to the JIT backend, which does not use this setting. RTX 4090 (sm89) always uses comfy_kitchen.
