# [Feat] minimax-h3: Add an opt-in SMD4 release sampling preset

[Upstream PR](https://github.com/sgl-project/sglang/pull/44739) · state: open · merged: False

## Original PR description

## Motivation

Loading an SMD Ref2VA student LoRA does not select its trained sampling grid. This draft adds an explicit `smd-ref2va-4step` release sampling preset: four updates, five sigma boundaries, a final half-sized raw interval, and separate video/audio shifts of 12/3. It does not automatically detect adapter metadata or add an adapter loader.

The student checkpoint source is [SMD-MiniMax-H3-Ref2VA-4step](https://huggingface.co/zjwfufu/SMD-MiniMax-H3-Ref2VA-4step). No new distillation method or speed/quality improvement is claimed here.

## Modifications

- Accept optional `_minimax_h3.sampling_preset: "smd-ref2va-4step"` in an existing native Ref2VA model index. The package owner must supply the matching student transformer or use the existing LoRA loading mechanism. The preset does not download, apply, or identify a LoRA.
- Validate request steps and modality shifts before encoding; reject PDD/DMD stacking and untrained tasks. Warmup uses a prefix of the serving grid, including when a request already contains a cached serving grid.
- Include the preset in timestep dedup identity only when enabled. Default schedules and default dedup keys retain their previous values. The Euler loop, LoRA loading, and default model recipes are unchanged.
- Document the opt-in release declaration and pending GPU/quality validation in the existing H3 cookbook.

Open-PR searches for `SMD`, `MiniMax student`, `H3 distill`, and `consistency H3` found no matching sampling-preset change. The FastH3 AdaLN, LoRA shape-check, and attention PRs returned by the broader searches address other paths.

## Accuracy Tests

Local isolated CPU validation passed the new contract cases: sigma values, serving/warmup step errors, modality-shift errors, release metadata admission, PDD/DMD exclusion, warmup truncation, and dedup identity. The actual time-request, release-metadata, resolved-plan, dedup, and timestep-stage modules ran; unrelated serving-bootstrap/protocol dependencies were substituted, and package `conftest` was disabled.

The default 1/4/50-step grids at shifts 12 and 3 were also compared exactly with the unmodified base commit, as was the default timestep fingerprint.

The normal installed-package test command remains pending:

```bash
python -m pytest python/sglang/multimodal_gen/test/unit/test_minimax_h3_smd.py -q
```

Full pipeline creation, student adapter loading, GPU end-to-end generation, audio/video quality, and CI validation are **pending**. The CPU bootstrap run is not an end-to-end serving result.
