## Motivation

It would be useful to see the the rate of scheudler loop iterations or latency of each iteration.  For example, in #45085, we found reducing latency of each scehduler iteration will affect batching behavior at medium concurrency.  This PR adds a counter to measure this.

## Modifications

Add a counter `scheduler:scheduler_iterations_total`, which is the total number of scheduler iteartions since process starts. Accumulate that counter in `event_loop_normal`, `event_loop_pp`, etc.

## Tests

Tested various kinds of deployment to cover the added code.

Covered:
- `event_loop_overlap`
- `event_loop_normal`
- `event_loop_pp`
- `event_loop_pdmux`
- `event_loop_pp_disagg_prefill`
- `event_loop_overlap_disagg_prefill`
- `event_loop_normal_disagg_prefill`
- `event_loop_overlap_disagg_decode`
- `event_loop_normal_disagg_decode`
- `event_loop_pp_disagg_decode`

- `event_loop_overlap_mlx`
