# [Feat] [CPU] numa: Add support for CPU-less HBM/NUMA node binding

[Upstream PR](https://github.com/sgl-project/sglang/pull/45784) · state: open · merged: False

## Original PR description

## Motivation

This PR adds support for explicit HBM/NUMA node binding in SGLang, specifically targeting systems with **CPU-less (memory-only) HBM nodes**. 

Previously, memory node binding relied entirely on auto-detection via `numa_node_of_cpu(...)` mapped from the assigned OpenMP CPU cores. On hardware architectures featuring CPU-less HBM nodes, this auto-detection fails or cannot target the memory nodes directly because no CPUs are attached to them. 

By introducing the `SGLANG_CPU_MEM_BIND` environment variable, you can now explicitly bind parallel execution ranks and migrate memory pages directly to specific NUMA/HBM nodes regardless of CPU topology.

Examples:

```bash
# All workers allocate from node 8.
export SGLANG_CPU_MEM_BIND=8

# Global worker indices 0–3 allocate from nodes 8–11.
export SGLANG_CPU_MEM_BIND=8,9,10,11
```

## Modifications

- **`numa_utils.cpp`**: 
  - Added the `node_mem_bind` argument to `init_cpu_threads_env`.
  - Updated memory node selection logic: when `node_mem_bind >= 0`, it overrides the automatic `numa_node_of_cpu` lookup, enabling manual targeting of CPU-less HBM nodes for `numa_migrate_pages` and `numa_set_membind`.
- **`bootstrap.py`**: 
  - Implemented parsing for `SGLANG_CPU_MEM_BIND` inside `_init_cpu_threads_env`.
  - Supports single-node strings (binding all ranks to the same node) or comma-separated lists mapping specific TP ranks to HBM nodes (e.g., using `gpu_id`).
  - Passes the resolved `node_mem_bind` integer down to the C++ extension layer.
- **`torch_extension_cpu.cpp`**: 
  - Updated function signatures and PyTorch bindings to accept the new `node_mem_bind` parameter.
