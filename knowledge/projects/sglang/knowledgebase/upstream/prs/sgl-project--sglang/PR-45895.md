## Motivation

<!-- Describe the purpose and goals of this pull request. -->

The unquantized DFLASH draft `fc` projects the concatenated target hidden taps to the draft hidden size. It is replicated on every TP rank, so every rank reads the whole weight once per decode cycle: K = num_context_features x hidden, N = hidden, 2 x K x N bytes of bf16.

## Modifications
Opt-in via `SGLANG_OPT_DFLASH_SPLIT_FC=1` (default off; nothing changes when it is off):

- With the flag on, `DFlashDraftModel.project_target_hidden` computes `fc` with the existing column-parallel GEMM + multicast all-gather helper `gemm_ag` (`layers/communication/muse_spark_gemm_ag.py`):
  - each rank runs the bf16 GEMM dispatch on its `N / TP` row block of the replicated weight, reading 1 / TP of the bytes;
  - one multicast all-gather through `CustomAllReduceV2` then assembles the full output.
- `gemm_ag` needs the same input on every rank of the TP group, so the flag is ignored under attention DP and prefill context parallel, where ranks of the draft's TP group can hold different tokens. Layernorm sequence parallelism is safe: `validate_layernorm_sp` rejects it with speculative decoding unless the target all-gathers the aux hidden states (`sp_exit_gather`) before the draft reads them, so the draft `fc` input is replicated.
- It falls back to `self.fc` whenever `gemm_ag_supported()` rejects the call:
  - TP = 1 or no multicast;
  - non-bf16 data;
  - M > 512, or an M x N bf16 output larger than the push workspace;
  - for M > 8, anything other than SM 10.3 at TP4 / TP8 with N = 4096 or 8192.

  The default `CustomAllReduceV2` push workspace on SM100-class GPUs is 4 MB at TP4 and 2 MB at TP8. So on SM 10.3 a draft with N = 8192 takes the new path up to M = 256 (TP4) / 128 (TP8), and N = 4096 up to M = 512 / 256, with no extra reservation. On other GPUs only M <= 8 does.
- The Laguna draft overrides `project_target_hidden` and does not use the flag.

Why the weight stays replicated instead of a column-parallel `fc` with an output gather:
- the loader stays unchanged;
- `ColumnParallelLinear(gather_output=True)` gathers through NCCL. We measured it at 18.5 us per call at TP4 (~20 us across trays at TP8), against 8.5 us for the multicast gather, plus a reshape copy for the last-dim gather.

Why opt-in: the gain beyond M = 8 needs SM 10.3 at TP4 / TP8, and the slice GEMM is not bitwise equal to the replicated GEMM.

**Issue**

This guard never fires. The DFLASH worker (attention DP or prefill CP) and the DSpark worker (attention DP) build the draft inside `draft_tp_context(owns_attention=True)`, where `patch_tensor_parallel_group` sets `attn_dp_size=1` and `attn_cp_size=1`. So `split_fc` stays on in the modes this comment excludes.

**Example**

Dense DSpark draft (a `DFlashDraftModel` subclass) + `--enable-dp-attention` + the flag. `DSparkKVInjector._inject` calls `project_target_hidden` outside the draft scope, so `_fc_split_gather` uses the full-TP `ca_comm`. DP ranks with different tokens join one gather, and a rank with no tokens skips it. The gather kernel spin-waits for every peer, so this can hang.

**Fix**

Decide eligibility from the target topology before entering the draft scope, for example by having the worker pass the decision in.
