# [Perf] hicache: Reuse the host eviction heap across one write_back eviction walk

[Upstream PR](https://github.com/sgl-project/sglang/pull/47126) · state: open · merged: False

## Original PR description

## Motivation

With `--hicache-write-policy write_back` and a full host pool, every device victim of an eviction walk first frees host space, and each `drive_host_eviction` call rebuilds a heap over all evictable host leaves. A walk therefore costs O(victims x host leaves), which dominates eviction time once the host holds many leaves. See #46952.

## Modifications

- The Full component (Python and Rust TreeCore) keeps its host-leaf heap until the current device-eviction walk ends instead of rebuilding it on every call. No eviction priority changes inside a walk, so every pop matches a fresh rebuild. With `--enable-session-radix-cache` the heap is still rebuilt per call.
- Host leaves that appear while the heap is live are pushed from `_update_evictable_leaf_sets`, which replaces the explicit parent push.
- `drive_host_eviction` returns before building the heap when duplicate reclaim already met the target (from #48209, co-authored by @RuiDingY).

## Benchmark

MiniMax-M3.1-Flash, 4x GB300, TP4, `--hicache-write-policy write_back`, host pool 1.6x the device pool, Python TreeCore. Multi-turn sessions arrive in waves on one server; numbers are means of the waves measured after the host pool is full. Hit rate is identical between the two arms. Measured before #46930; a rerun on current main is in progress.

| Workload | Metric | main | This PR |

| Many short sessions (2000 per wave, 512-token first turn) | Mean eviction time | 164 ms | 47 ms |
