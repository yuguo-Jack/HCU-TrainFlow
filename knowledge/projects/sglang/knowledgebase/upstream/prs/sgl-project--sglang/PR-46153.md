# [Feat] [NVIDIA] modelopt: Load NVFP4 experts with CSF-compressed scales

[Upstream PR](https://github.com/sgl-project/sglang/pull/46153) · state: open · merged: False

## Original PR description

## Motivation

`nvidia/Qwen3.8-Flash-Next-FP4-Local` is a ModelOpt MIXED_PRECISION checkpoint that SGLang cannot load on `main`. Its NVFP4 layers carry `"weight_scale_encoding": "csf"`: each E4M3 block-scale matrix is stored losslessly as a `weight_scale.nvfp4_csf_fixed` / `weight_scale.nvfp4_csf_exceptions` pair instead of one `weight_scale` tensor. The same checkpoint quantizes the Qwen4-Exp vision tower (MXFP8 attention, W4A16_NVFP4 MLP and merger), which SGLang builds in BF16, and its shards sit in a `tensors/` subfolder that the safetensors index names.

This PR decodes the CSF scales to plain E4M3 at load, so every existing NVFP4 MoE backend and TP size runs unchanged. It adds no kernels.

## Modifications

- `nvfp4_csf.py` (new): validate a stream pair and decode it to the plain E4M3 `weight_scale` on the CPU, in the layout FlashInfer's b12x decoder reads.
- `ModelOptMixedPrecisionConfig`: accept `weight_scale_encoding: "csf"` only on `NVFP4` / `W4A16_NVFP4` layers with group size 16, and resolve a layer's encoding with `scale_encoding_of`, walking up from per-expert names.
- `DefaultModelLoader`: for `modelopt_mixed` configs with CSF layers, decode the pairs before `load_weights` and any scale rename.
- Shards in a subfolder that the safetensors index names are found by the loader and by the local snapshot lookup; the top-level glob path is unchanged.
- `dequantize_layers_to_bf16`: Qwen4-Exp's `load_weights` turns the vision tower's MXFP8 and W4A16_NVFP4 linears into BF16 weights, so the tower loads them instead of raw quantized bytes (it failed the shape check).
- Qwen4-Exp's MTP draft declares `checkpoint_weight_name_filter`; the loader then reads only the shards the index places its tensors in (2 of 21 here), instead of re-reading and decoding the whole checkpoint.
- Docs: a paragraph in `quantization.mdx`.
- Tests (CPU): 9 for the CSF decoder and config, 5 for the BF16 step, plus loader and weight-utils cases.

## Dependency on #41624

Serving this checkpoint end to end also needs #41624 (NVFP4 PLE table and MXFP8 layers). The commit here does not import or depend on #41624's code and applies to `main` on its own, so CI on this PR cannot load the model.

Every end-to-end run below used [`test/fp4-local-e2e`](https://github.com/AndreasBis/sglang/tree/test/fp4-local-e2e): `main` at `69f830756e` plus three changes.

| PR | change | needed to serve |
|---|---|---|
| #41624 | NVFP4 PLE table and MXFP8 layers | yes |
| #46153 (this PR) | CSF-compressed scales | yes |
| #46128 | sequential read of each shard before the multi-thread loader maps it | no, load time only |

Without #46128, loading this checkpoint takes about 8 to 13 minutes on this machine (an earlier run, not a back-to-back comparison).
