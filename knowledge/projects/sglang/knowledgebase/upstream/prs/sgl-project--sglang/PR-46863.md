# [Feat] jit: Split a header-only module's kernel instantiations across parallel translation units

[Upstream PR](https://github.com/sgl-project/sglang/pull/46863) · state: closed · merged: True

## Original PR description

## Motivation

A header-only JIT module compiles every kernel it instantiates in the one generated `cuda.cu` unit. Its cold build is therefore serial however many cores the host has: a module that instantiates one kernel template many times pays for all of them on the critical path of its first load, and every added instantiation lengthens that path.

## Modifications

- `load_jit(cuda_units=...)` adds extra device units to a header-only module. Each unit is a list of `NAME=VALUE` macros; the generated `cuda_unit<i>.cu` defines them, includes the module's `cuda_files` and exports nothing, so the sources can guard which instantiations each unit emits behind the macros while the generated wrapper alone exports the entry points. Ninja builds the units in parallel and links their objects beside `cuda_0.o`.
- The option requires a header-only module with `cuda_files` and raises a `ValueError` otherwise.
- `BuildSpec.cuda_units` carries the units, so they enter the build key: two modules that differ only in their units never share a build directory.

For example, `cuda_units=[["UNIT=A(1) A(2)"], ["UNIT=A(3)", "FLAG"]]` generates

```
cuda_unit0.cu:  #define UNIT A(1) A(2)
                #include "<source>"
cuda_unit1.cu:  #define UNIT A(3)
                #define FLAG
                #include "<source>"
```

and the link line becomes `cuda_0.o cuda_unit0_1.o cuda_unit1_2.o`.

Modules that do not pass `cuda_units` build exactly as before: the default is an empty tuple, which generates no extra unit and leaves the build key for existing modules unchanged.

## Accuracy Tests

Not applicable: no kernel changes. Existing modules generate the same translation units and build key as before.

## Benchmarking and Profiling

Not applicable to this change on its own: it adds the option and generates the units; the build-time gain depends on how a module splits its instantiations.
