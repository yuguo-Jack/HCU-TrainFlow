# [1/N][DSv41] Enable DP attention with MegaMoE

[Upstream PR](https://github.com/sgl-project/sglang/pull/43228) · state: closed · merged: True

## Original PR description

## Motivation

DeepSeek-V4.1 checkpoints with `vision_n_layers > 0` reject every MoE A2A backend at initialization, including text-only serving with DP attention and MegaMoE. Simply removing the guard would also route image tokens using the text router bias. Flash additionally fails the old MegaMoE intermediate-size check because its expert intermediate dimension is 2304.

This enables DeepSeek-V4.1-Flash text and image serving with DP attention and CUDA MegaMoE using SGLang's existing `sgl-deep-gemm==0.2.1.post1` pin.

## Modifications

- Admit CUDA MegaMoE for V4.1 vision-capable checkpoints; retain the CP, PP, and unsupported A2A restrictions.
- Route local image/text rows through vision-aware top-k on MegaMoE, preserving EPLB mapping, expert recording, home-rank shared slots, routed scaling, and padded/idle rank handling.
- Require 128-element intermediate alignment for the pinned FP8/FP4 path, allowing Flash's 2304 dimension. Retain the input-scale alignment requirement and the other MMA paths' restrictions.
- Add constructor admission and numerical routing regressions covering image/text bias, shared slots, scaling placement, padding, and idle ranks.
- Skip DSv4 DSPARK attention on idle CUDA ranks during DP speculative prefill coordination. Idle ranks have no local attention metadata or KV rows, while their later FFN still participates in the shared MoE draft.

## Accuracy Tests

- 22 focused unit tests passed: MegaMoE DeepGEMM API and DeepSeek-V4 shared-expert/admission tests. Six existing fused shared-weight scaling tests also passed.
- On 2x GB300 with DeepGEMM 0.2.1.post1: 16 CUDA routing cases passed, covering image/text bias, EPLB remapping, shared slots, scaling placement, and padded rows.
- Two-rank real DeepGEMM dispatch/combine checks passed at Flash's exact hidden/intermediate dimensions (5120/2304), with shared slots, scaling placement, and idle ranks. Six CUDA graph replay cases passed while switching captured inputs between text and image tokens.
- Full `deepseek-ai/DeepSeek-V4.1-Flash` checkpoint (revision `2cba9e42aa026125f3ed06c6d98c1db82f7ca027`) served successfully on 2x GB300 with TP2 / attention DP2 / EP2 / MegaMoE. Four semantic smoke requests returned HTTP 200 and the expected answers: arithmetic `5`, red image `Red`, concurrent capital question `Paris`, and concurrent blue image `Blue`.

- Native DSPARK with coordination enabled on DSv4.1 Flash/MegaMoE passed the registered mixed-rank greedy output comparison on 2x GB300. Fresh ~26.7K-token contexts were prefilled on each rank while both ranks decoded; ongoing and subsequent outputs matched isolated execution. Simulation was disabled. The idle-attention regression fails before the fix and all four coordination unit cases pass after it, including with CUDA hidden.

```bash

  --model-path deepseek-ai/DeepSeek-V4.1-Flash --trust-remote-code \
```

## Speed Tests and Profiling

AgentX cc128 on 2x GB300, TP2 / attention DP2 / EP2 / MegaMoE / TRTLLM sparse attention. Each controlled run used a 900-second admission window after the same 1,422-request warmup, with synthetic DSPARK acceptance 3.51. Results use InferenceX latency/throughput calculations; throughput includes cached prompt tokens. Memory, HiCache, router, chunk size, and graph limits were fixed.

| Prefill/decode interval | DP spec/prefill coordination | p90 interactivity (tok/s) | Total tok/s/chip | Output tok/s/chip | p90 TTFT (s) | Cache hit |
|---|---|---:|---:|---:|---:|---:|
| 0 | Off | 18.70 | 157,336 | 1,465 | 7.03 | 94.18% |
| 8 | Off | 38.75 | 186,951 | 1,822 | 14.95 | 94.48% |
| 0 | On | 20.65 | 160,275 | 1,532 | 8.31 | 94.10% |

All three had zero request errors, OOMs, and memory retractions. Interval 8 improves interactivity and throughput with a TTFT cost. Coordination provides a smaller gain: decode round counts across ranks were nearly unchanged (18,931 vs 18,936), with 2,184 eager rounds replacing part of normal graph replay. Matched common turns confirm the latency gains; raw cache rates also reflect different completed request mixes. Cache parity with the published vLLM result has not been established. The coordination performance run includes the idle-attention fix; native correctness was checked separately with simulation disabled.
