# [CI] [PPU] slash-command: Register PPU with shared opt-in CI tiers

[Upstream PR](https://github.com/sgl-project/sglang/pull/47208) · state: closed · merged: True

## Original PR description

## Motivation

PPU CI already uses the shared `pr-gate.yml` with `run-ci-ppu`, but it is not registered with the opt-in CI tier registry introduced by #45735. As a result, maintainers cannot select and rerun only PPU CI through `/run-ci ppu` or `/run-ppu-ci`.

This follows the MLU registration in #45385.

## Modifications

- Register `ppu` in `scripts/ci/opt_in_ci_tiers.json`, mapping `run-ci-ppu` to `pr-test-ppu.yml`.
- Remove the `labeled` pull-request trigger and the associated `ignored-label-*` compatibility expressions from the PPU workflow.
- Keep the existing `run-ci` + `run-ci-ppu` live-label gate and PPU path filters unchanged.
- Document `/run-ci ppu` and `/run-ppu-ci` in the contribution guide, workflow README, and CI workflow skill.
- Keep existing status-check names, including `pr-test-ppu-finish`.

No change to `slash_command_handler.py` is required: the generic tier handler reads this registry entry, maps `/run-ci ppu` to `/run-ppu-ci`, applies `run-ci` and `run-ci-ppu`, and reruns `pr-test-ppu.yml`.

## Behavior change

After this change, manually adding the `run-ci-ppu` label in the GitHub UI no longer starts a new PPU workflow run, because registered opt-in workflows must not listen for `labeled` events. Use `/run-ppu-ci` (or `/run-ci ppu`) to label and rerun the existing PPU workflow. A new commit also creates a fresh workflow run.

The existing PPU path filters still apply: selecting the PPU tier does not force PPU jobs for a PR outside PPU scope. `workflow_dispatch` with `run_all_tests: true` remains available for that case.

## Validation note for this PR

This PR itself cannot validate `/run-ppu-ci`: slash-command comments are handled by the version of the handler and registry on `main`, where `ppu` is not registered yet. On this PR:

- `/run-ppu-ci` is not recognized by the current `main` handler.
- `/tag-and-rerun-ci ppu` treats `ppu` as an unknown legacy suffix, adds only `run-ci`, and does not add `run-ci-ppu`.

To run PPU CI for this PR, a maintainer must add both `run-ci` and `run-ci-ppu`, then rerun the existing `PR Test (PPU)` workflow (or push a new commit). After merge, `/run-ppu-ci` should be exercised on the next PPU-scoped PR.
