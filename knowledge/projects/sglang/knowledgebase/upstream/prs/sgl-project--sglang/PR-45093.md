# [Feat] volundr: Add Agens Volundr model support

[Upstream PR](https://github.com/sgl-project/sglang/pull/45093) · state: open · merged: False

## Original PR description

## Motivation

Agens Volundr (`Blockway/Agens-Volundr-32B-v1`, `Blockway/Agens-Volundr-32B-v1-INT4` (W4A16)) is a hybrid model that
today only runs from a patched SGLang build (`ghcr.io/blockwayz/agens-sglang:v1-sm89` / `v1-sm90`). This PR adds native support so a stock install serves it.

Architecture, as the runtime sees it:

- **KDA** linear-attention layers (per-channel forget gate), served by the existing `KDAAttnBackend`
  through `RadixLinearAttention`, with grouped value attention (48 value heads over 16 key heads).
- **BCSA** layers: a 4,096-token sliding window plus a 4:1 mean-pooled far field chosen by a learned
  128-wide indexer, merged with the window under one softmax through the window's LSE. The indexer key
  depends on the layer input, so each BCSA layer keeps a per-token side cache indexed by
  `out_cache_loc` like K/V. One `attn` layer is plain dense attention.
- **mHC** (manifold hyper-connections): 4 residual streams with Sinkhorn-normalised mixing around
  every layer.
- **Engram**: hashed n-gram memory on two layers; needs the two previous token ids of every token.
- Optional vision tower: SGLang's qwen3_vl vision model and MRoPE, unchanged.

The layer map comes from `config.mixer_types`; the attention layers do not sit on a fixed interval.

## Modifications

New files

- `srt/models/volundr.py` — `VolundrForCausalLM`, `VolundrForConditionalGeneration`. Weights load
  as shipped (HF names; `gate_up_proj` stacking; blockwise column-parallel loaders for the fused
  `[q|k|v]` projection and conv at tp > 1). Every attention/MLP RMSNorm is the zero-centred
  `GemmaRMSNorm`; mHC and the KDA output norm are plain.
- `srt/configs/volundr.py` — `VolundrTextConfig` (layer map from `mixer_types`, KDA state layout via
  `KimiLinearCacheParams`, BCSA/Engram/mHC fields with defaults), `VolundrConfig` (vision + text);
  registered in `_CONFIG_REGISTRY` and the linear-attention model registry (-> `KDAAttnBackend`).
- `kernels/ops/layernorm/volundr_mhc.py`, `kernels/ops/attention/volundr_bcsa.py` — Triton kernels for
  mHC mix/combine and the BCSA decode block-key write / far branch (~6,000 small launches per decode
  step become a few per layer). Each is bit-exact with the torch reference next to it; the rounding
  rules that make it so (libdevice exp, `div_rn`, fixed reduction order, FMA contraction off) are in
  the module docstrings. Registered for the kernel inventory.
- `srt/function_call/agens_detector.py` — `AgensDetector` (Qwen3-Coder XML body inside
  `<|call|>`/`<|/call|>`).
- `arg_groups/model_overrides/volundr.py` — defaults: `page_size=1` (BCSA pools far-field K/V straight
  from the token-indexed cache), `--attention-backend fa3`.

Edits to shared files (all small)

- `configs/hybrid_arch.py`: an explicit linear-attention registration wins over the `Qwen3Next`
  isinstance chain in `hybrid_gdn_config` (Volundr's config reuses the Qwen3.5 text-config plumbing,
  but its linear layers are KDA, not GDN).
- `configs/model_config.py`: `uses_kda_attention` also recognises registry entries whose backend is
  `KDAAttnBackend` (so the KDA prefill-graph rule applies); multimodal arch lists.
- `layers/attention/linear/kernels/kda_triton.py`: `extend` broadcasts q/k heads when
  `num_v_heads > num_k_heads` (the decode/verify kernels already handle grouped value attention).
- `multimodal/processors/qwen_vl.py`: Volundr uses the Qwen3.5 vision/MRoPE path (`vision_config.model_type`).
- Parsers: `AgensDetector` reasoning detector in `parser/reasoning_parser.py` (`<|think|>…<|/think|>`,
  `<|call|>` closes reasoning implicitly), `agens` in both registries and both name lists.
- `sampling/custom_logit_processor.py`: `AgensThinkingBudgetLogitProcessor` (thinking-token ids
  248068/248069, newline 198), used through the existing `custom_params.thinking_budget`.

Behaviour notes

- Token ids listed in the checkpoint's `generation_config.suppress_tokens` (padding rows of the
  embedding/lm_head past the tokenizer) are masked from next-token logits, as transformers'
  `SuppressTokensLogitsProcessor` does. Input logprobs are untouched.
- No environment variables. No `trust_remote_code` needed (the config class is native; a checkpoint
  `auto_map` is ignored by the registry reload).
- In this PR: tp >= 1 bf16, INT4 (compressed-tensors) at tp 1, fa3 backend (sm90). Prefix caching,
  the FlashInfer backend / sm89 and far/near decode graphs, and speculative decoding follow as
  separate PRs.

## Accuracy Tests

Teacher-forced against the checkpoint's own transformers implementation (one HF forward per passage,
dumped once, every engine compared against the same dump). Passages: license texts and Python
sources, 285 / 4,000 / 6,000 / 12,133 tokens. "Disagree" = top-1 differs; the reference's own
top1–top2 logprob margin at those positions is listed. KL20 = KL(ref || engine) over the reference's
top-20 tokens (approximation; engine logprobs outside its own top-20 floored at its 20th).

| bf16, sm90, fa3 | 285 | 4,000 | 6,000 | 12,133 |
|---|---|---|---|---|
| this PR, tp1: top-1 | 100.00 % | 99.97 % | 99.93 % | 99.88 % |
| this PR, tp1: mean abs. dlogprob(target) | 0.0016 | 0.0020 | 0.0014 | 0.0021 |
| this PR, tp1: KL20 | 3.3e-4 | 1.5e-4 | 1.1e-4 | 1.7e-4 |
| this PR, tp2: top-1 | 100.00 % | 99.97 % | 99.95 % | 99.90 % |
| previous out-of-tree build, tp1: top-1 | 100.00 % | 99.97 % | 99.93 % | 99.93 % |
| previous out-of-tree build: mean abs. dlogprob | 0.0018 | 0.0023 | 0.0018 | 0.0023 |

All disagreements sit at reference margins of 0.0–0.375 (bf16 ties). The 12,133-token passage has
15 / 12,132 disagreements here vs 9 for the previous build; mean dlogprob and KL20 are lower here.
Decode path vs prefill (greedy-decode 256 tokens on 8 prompts of 300–6,000 tokens, several crossing
the 4,096 window, then teacher-force the same tokens): mean abs. difference 0.0051, 4 / 2,048
top-1 flips (previous build 0.0045, 10 / 2,048). Runs are deterministic (repeat = bit-identical).

Fused kernels: bit-exact against the torch references (`test/registered/kernels/ops/...`).

Serving smoke (bf16 tp1 and INT4 tp1, text and vision checkpoints): `--reasoning-parser agens`
splits reasoning/content (thinking on and off); `--tool-call-parser agens` parses 8/8 sampled
tool calls at T=0.6; `thinking_budget=32` caps reasoning at 32 tokens; an image of three coloured
shapes is described correctly (`--enable-multimodal`).

Long context: one 32,768-token passage, top-1 99.81 % (63 / 32,767 disagreements, all at reference
margins <= 0.375), KL20 2.6e-4; the mean dlogprob grows along the sequence (0.0019 in the first 4K,
0.0055 in the last 4K).

Benchmarks (sm90, bf16 tp1, the v1 model-card protocol):
