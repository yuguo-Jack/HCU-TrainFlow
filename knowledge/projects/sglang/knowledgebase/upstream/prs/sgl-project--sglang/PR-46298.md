# [Fix] hunyuan: Skip undefined tools in streaming like detect_and_parse

[Upstream PR](https://github.com/sgl-project/sglang/pull/46298) · state: open · merged: False

## Original PR description

## Motivation

`HunyuanDetector` handles a tool name that is not in `tools` differently in its two paths:

- `detect_and_parse` skips the call. This is covered by `test_unknown_tool_skipped` and `test_mixed_known_and_unknown_tools`.
- The streaming path logs `Model attempted to call undefined function` and then **emits the call anyway**.

As a result, a streaming client receives a call to a tool it never defined, and every later call gets a shifted `tool_index`. Below, the model calls `get_current_date`, then an undefined `nonexistent`, then `search`:

| path | calls (tool_index, name) |
|---|---|
| `detect_and_parse` | `get_current_date`, `search` |
| streaming, `main` | `(0, get_current_date)`, `(1, nonexistent)`, `(2, search)` |
| streaming, this PR | `(0, get_current_date)`, `(1, search)` |

`SGLANG_FORWARD_UNKNOWN_TOOLS=1` is meant to be the only way an undefined tool reaches the client. That is how the non-streaming path behaves.

## Modifications

- In `_continue_streaming`, when the tool name is unknown and `SGLANG_FORWARD_UNKNOWN_TOOLS` is off, wait for the call's `</tool_call>` and drop the whole block. Nothing is emitted for it, and `current_tool_id` is not advanced. The warning is now logged once per skipped call, not on every delta while the call is open.
- With `SGLANG_FORWARD_UNKNOWN_TOOLS=1` the behavior is unchanged: the call is still forwarded.
- Two streaming tests were added next to the existing non-streaming ones:
  - `test_streaming_unknown_tool_skipped`: token-by-token deltas.
  - `test_streaming_mixed_known_and_unknown_tools`: one delta and char-by-char; checks names, arguments and `tool_index` 0, 1.

## Accuracy Tests

The change is parser-only, so model outputs are unchanged.

- `test_hunyuan_detector.py`: the 2 new tests fail on `main` (13b7ef75c5) and pass with this change. 46 passed.
- `pytest test/registered/unit/function_call/`: the same 7 tests fail before and after this change (`test_deepseekv41_detector` grammar and `test_iquest_q1_detector` serving-path cases). They are unrelated to this PR, and my guess is the local xgrammar version. Nothing new fails.
- I checked by hand that Hy4 tokens (`:opensource` suffix, no `<tool_sep>`) give the same result as `detect_and_parse`, for both a single delta and char-by-char.
- Differential fuzzing compares streaming against `detect_and_parse` on every Hunyuan sample in the unit tests (19 samples):
  - Chunkings: whole text, splits that never cut inside special tokens, every 2-way split, and random splits.
  - Before: 1 mismatch (the mixed known/unknown sample). After: 0.
