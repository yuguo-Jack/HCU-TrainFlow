## Motivation and scope

Related to #45367. This proposal retains DCP a2a exchange-buffer storage while allowing NCCL graph registration to remain enabled. It is currently **on hold for correctness investigation**, following the high-load failure above; Plan A / #45371 is the preferred candidate to advance.

The original two-node GB300 TP8/DCP8 12-prompt probes showed corruption with temporary exchange buffers and registration enabled, and small-probe recovery after disabling registration or retaining storage. Those limited observations motivated this proposal, but did not establish correctness under the later high-load R3 conditions.

## Modifications

- Retain one send/receive buffer pair per `(device index, B, N, heads per rank, head dimension, dtype)` in `dcp_a2a_lse_reduce()`.
- Allocate and cache a missing pair outside CUDA stream capture. Subsequent calls with that shape reuse its storage.
- Preserve the explicit `cuda_graph_buffers` path, which bypasses the cache.
- If a shape is first encountered during capture, allocate as before without inserting that allocation into the persistent cache. Uncaptured warmup must populate shapes intended for persistent reuse.
- Preserve the existing packing, byte all-to-all transport, and LSE-combine operations.
- Leave `fi_a2a` unchanged: that backend returns through its existing implementation before the new cache logic.

The tradeoff is retained GPU memory: one send/receive pair per cached shape, with memory usage growing with the exercised shape set. This PR does not change the process-wide registration policy or add the #45371 guard.
