# [Perf] model_executor: Write small forward metadata with fill kernels behind SGLANG_ENABLE_MLP_SYNC_METADATA_FILL

[Upstream PR](https://github.com/sgl-project/sglang/pull/47550) · state: closed · merged: True

## Original PR description

## Motivation

The forward's small per-batch metadata (the DP-attention token counts and their logprob counterpart, the extend sequence and prefix lengths, and the non-padded token count) reaches the device as pinned host-to-device copies. Those copies share the copy engine with bulk host-to-device DMA, so when a large transfer is queued ahead of them, for example a HiCache load-back with the `direct` io backend, the forward waits behind that transfer before it can start, even though the metadata itself is a handful of integers.

## Modifications

Behind `SGLANG_ENABLE_MLP_SYNC_METADATA_FILL` (default off, CUDA only), write that metadata with a Triton kernel that takes the values as kernel arguments instead of copying them, so the write is an ordinary kernel launch on the compute stream and never waits on the copy engine.

- `python/sglang/kernels/ops/memory/small_copy.py`: `write_host_ints(dsts, values)` fills several small contiguous 1-D int32/int64 CUDA tensors in one launch and validates its inputs. The values are encoded as `16 * v + 3` before the launch so Triton's integer specialization (equal to 1, divisible by 16) never splits the kernel cache by value; the kernel decodes with a shift.
- `python/sglang/srt/model_executor/forward_batch_info.py`: `_host_ints_to_device(values, dtype, device)` builds a tensor from a varying-length list by padding to a power of two up to 256 elements, and to whole launches of 256 past that, so the set of compiled kernels stays bounded; the caller receives the leading `len(values)` elements. `init_mlp_sync_metadata`, `init_new` (extend lengths), `_init_num_token_non_padded` and `prepare_mlp_sync_batch` take the kernel path when the flag is on and the device is CUDA, and keep the existing pinned-copy path otherwise.
- `python/sglang/srt/environ.py`: the new `EnvBool`, default off.
- `python/sglang/srt/mem_cache/l2_transfer.py`: `L2TransferEngine` warns once when it is created with the `direct` io backend on CUDA while the flag is off, since that backend moves KV with copy-engine DMA that the metadata copies would queue behind.

With the flag off (the default) nothing changes.

## Accuracy Tests

No numerics are touched: the kernel writes the same integers the pinned copy would have written.

## Checklist

- [x] Upstream pre-commit hooks (isort, ruff, ruff-format, codespell, ast) pass on the four changed files.
- [x] On a single NVIDIA GPU: `write_host_ints` writes the expected int32 and int64 values (including 0, 1, 16 and `2**31 - 1`) into several destinations in one launch; 20 further launches with random values of the same shapes compile no additional kernel; `_host_ints_to_device` round-trips lists of every length from 1 to 69 and 127/128/129/255/256/257/300/600 in both dtypes, returns an empty tensor for an empty list, and the 0-dim `squeeze(0)` form reads back correctly; the validation errors fire on mismatched counts, a float tensor, a CPU tensor and a wrong length.
- [ ] Serving with `SGLANG_ENABLE_MLP_SYNC_METADATA_FILL=1` under DP attention is covered by the CI suites on this PR.
