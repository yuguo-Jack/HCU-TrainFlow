# fix(args): floor the derived mem_fraction_static and validate explicit values

[Upstream PR](https://github.com/sgl-project/sglang/pull/43281) · state: open · merged: False

## Original PR description

## Motivation

`chunked_prefill_size=-1` is the documented way to disable chunked prefill, but it makes the activation reserve in `handle_gpu_memory_settings` scale with `max_prefill_tokens`: `512 + 16384 * 1.5` MiB before the CUDA-graph and DeepEP terms, which exceeds any device under roughly 25 GiB. The derived `mem_fraction_static` comes out negative and the engine dies at memory profiling with

```
ValueError: Loaded weights leave no GPU memory for the KV cache under --mem-fraction-static=-0.05
```

for a flag the user never set (issue reporter measured -0.05 on a 24058 MiB RTX 4090; I reproduce -0.026 at 24576 MiB and -0.539 at 16 GiB). The same path triggers for any config whose estimated reserve exceeds the device, e.g. `chunked_prefill_size=32768` on a 24 GiB card derives -1.026. This locks the whole 16/24 GiB class (T4, L4, A10, 3090/4090/5090) out of a documented configuration.

## Fix

- Floor the *derived* fraction at 0.5 with a warning that names the estimated reserve, the device size, and how to override with `--mem-fraction-static`. The startup profiler already computes a precise minimum viable fraction and raises with a suggested value when the weights genuinely do not fit, so in that case this converts the misleading negative-fraction failure into an accurate, actionable error, and small models (where the model-agnostic 1.5 MiB/token estimate is far above real activations) get a working engine.
- Reject an explicit `--mem-fraction-static` outside (0, 1] in `handle_other_validations`, so a bad explicit value fails at argument parsing instead of deep in the memory profiler.

User-supplied values within range are untouched by the floor.

## Tests

New `TestDerivedMemFractionFloor` in `test/registered/unit/server_args/test_server_args.py`:
- `chunked_prefill_size=-1` on a 24 GiB device derives at the floor (previously -0.026) and logs the warning
- oversized explicit chunk on 16 GiB clamps to the floor
- a healthy derivation is unchanged
- an explicit `mem_fraction_static=0.9` is not rewritten by the floor
- an explicit out-of-range value raises `ValueError` from `handle_other_validations`

Red/green verified by stashing the source fix: the two clamp tests and the validation test fail without it.
