# [TRT-LLM MLA] Run chunked-KV prefill under breakable CUDA graphs

[Upstream PR](https://github.com/sgl-project/sglang/pull/41715) · state: closed · merged: False

## Original PR description

## Motivation

Under a breakable prefill CUDA graph, `handle_attention_trtllm_mla` sends every extend down the MLA path, and `TRTLLMMLABackend` falls back to FlashInfer MLA metadata. That forfeits TRT-LLM's ragged MHA prefill for every model dispatched through `DeepseekV2AttentionMLA` with `trtllm_mla` as the prefill backend.

Chunked-KV MHA could not simply be enabled there. The eager attention break replays with the ForwardBatch captured at graph-capture time, so the cached-prefix metadata it sees is stale.

## Modifications

- One eager region per layer (`forward_mha.py`): under breakable graphs, run suffix and cached-prefix attention together in a single `eager_on_graph` region. The region:
  - reads the live ForwardBatch from the forward context instead of the captured one;
  - trims the bucket padding (`global_num_token_non_padded_cpu`) before attention and zero-pads the output back to the bucket shape;
  - skips attention entirely on an idle replay (zero real tokens);
  - runs its backend calls under `force_eager_attention()`, so RadixAttention does not insert nested breaks.
- Output projection stays captured: the output projection (and optional gate) moves out of `_forward_normal_chunked_kv_attention` and into the caller, so it stays in the captured segment after the break. As a side effect, the fused-prefix path now applies `gate` like the unfused path does. Only Bailing-V3 passes a gate, and only the Triton backend enables fused prefix, so this is a no-op for `trtllm_mla`.
- Dispatch (`attention_backend_handler.py`): the graph fixes the forward method at capture time, but whether a replay has a cached prefix varies. So under breakable graphs:
  - extend-without-speculative uses chunked KV;
  - with `--disable-chunked-prefix-cache`, extend keeps the MLA/FlashInfer fallback (the backend's fallback condition is updated to match);
  - `tokenspeed_mla` stays on MLA, since its prefill kernel has not been validated as an eager region.
- Runner (`prefill_cuda_graph_runner.py`): restore `mha_one_shot=False` and pass copies of the per-request CPU length lists on replay when this path is active.

Scope: the change applies whenever a breakable prefill graph runs with `trtllm_mla` as the prefill backend. By default, `cuda_graph_hook.py` turns breakable prefill graphs off for DeepSeek-V3 on `trtllm_mla` and for KDA hybrids such as Kimi K3. For those models the change takes effect only with an explicit `--cuda-graph-backend-prefill breakable`. Revisiting the DeepSeek-V3 default is left to a follow-up.

## Accuracy Tests

- `test/registered/unit/models/test_deepseek_mha_breakable_prefix.py`: 4/4 pass. They cover the live batch, trimming and padding, skipping idle replays, and projecting after the break.
- `test/registered/unit/models/test_deepseek_mla_dispatch.py`: 9/9 pass, including the new breakable-graph dispatch cases (chunked KV with or without a prefix, and the MLA fallback with `disable_chunked_prefix_cache`).
- On current `main`, the four eager-region tests and the chunked-KV dispatch case fail.

GSM8K eval run through `sglang.test.few_shot_gsm8k` with DeepSeek-V2-Lite-Chat:

| Setup | GSM8K accuracy |
|---|---|
| `main`, breakable prefill graph (MLA fallback) | 0.662 |
| this PR, breakable prefill graph | 0.658 |
| `main`, prefill graph disabled | 0.654 |
