# [Perf] [AMD] qwen3_5: read the GDN in_proj outputs as strided views under the Qwen3.8 prefill prologue

[Upstream PR](https://github.com/sgl-project/sglang/pull/47156) · state: closed · merged: False

## Original PR description

## Motivation

With the fused Qwen3.8 GDN prefill prologue from #39912 on (ROCm gfx950, `SGLANG_QWEN38_GDN_PREFILL_PROLOGUE_FUSION=1`), ROCm prefill still unpacks the GDN `in_proj` outputs into contiguous `mixed_qkv` / `z` / `b` / `a` copies with `fused_qkvzba_split_reshape_cat_contiguous`. The prologue (`x` with unit feature stride, `a`/`b` with unit head stride) and the gated RMSNorm (the 3-D strided `z`, including the MXFP4 epilogue) already read strided views in place, as CUDA does through `qwen3_5_gdn_prefill_projection_views`. On ROCm the copies are therefore extra memory traffic on every prefill chunk.

## Modifications

- `qwen3_5.py`: `use_strided_prefill_z` is now also true on ROCm when the new `Qwen3_5GatedDeltaNet._uses_qwen38_prefill_views` holds. This is a conservative mirror of the prologue's eligibility:
  - prologue enabled (AITER, gfx95, env flag);
  - attention TP 1 with the Qwen3.8-27B GDN head layout (16 QK heads, 48 V heads, head dim 128);
  - extend without speculation, without multi-item scoring and without a mamba track mask;
  - not deterministic inference and not page-major KV layout;
  - no DP padding.
- Every other ROCm batch keeps the contiguous unpack, and CUDA behaviour is unchanged. If the prologue still declines a batch at runtime, the views go to the stride-aware fallbacks: the Triton `causal_conv1d_fn` (channel-last), `fused_gdn_gating` and the gated-norm kernels.
- No new env var.

## Stacking and dependencies

- **Stacked on #39912** (head `65a73b0960`). The diff against `main` therefore includes #39912's commits. **Review only the last commit** (`e27f519c9a`, 2 files: `qwen3_5.py` and the unit test).
- **Needs #43381** (ratio-3 fused qkvzba split on AITER) to take effect. Without it, the Qwen3.8-27B layout (ratio 3) does not reach the fused-unpack branch on ROCm, and this change is a no-op.
- Overlap: #41683 and #47128 switch every ROCm extend to strided views. This PR switches only the batches the Qwen3.8 prologue consumes. If one of those lands with ROCm validation, this PR can be closed.

## Setup

MI355X (gfx950), Qwen3.8-27B MXFP4 (`amd/Qwen3.8-27B-Quark-AWQ-MXFP4`), SGLang TP1 with `--attention-backend aiter`, FP8 KV cache, `--enable-amd-monokernel` and chunked prefill 16384. "With vs without" = the full stack (this PR together with #39912, #43381 and the other Qwen3.8 MI355X PRs) vs the same build without this PR, on the same GPU, averaged over 2 GPUs. Prefill: 1 request at a time, 1 output token, 8 prompts after 1 warm-up, mean per-prompt time-to-first-token ratio. Repeat noise of the full stack on one GPU: TTFT 0.1-0.8%; TPOT 0.1-0.8%, except 2.4% at 16 concurrent requests on one GPU.

## Accuracy Tests

TP1 GSM8K-200 0.930 / 0.945 / 0.940 and needle in a haystack 30/30 with this PR. It reads the same values through views; the math is unchanged.
