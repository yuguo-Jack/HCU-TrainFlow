# [Fix] anthropic: Continue a trailing assistant message as a prefill

[Upstream PR](https://github.com/sgl-project/sglang/pull/47091) · state: open · merged: False

## Original PR description

## Motivation

The Python Anthropic adapter treats a trailing assistant message as a completed turn instead of continuing its text. For example, `[user: "Question?", assistant: "The answer is ("]` reaches the OpenAI chat layer with `continue_final_message=False`, so that layer rewrites the prefix as a user message. Anthropic's [Messages API](https://platform.claude.com/docs/en/api/messages) defines a final assistant message as a prefill.

## Modifications

Set `continue_final_message` for a text-only final assistant turn that follows another message, and concatenate that turn's text blocks without introducing a separator. Tool-use and thinking turns retain their existing behavior. Lone assistant turns, including conversations reduced to one message after empty inline-system filtering, retain their existing behavior because continuation would leave an empty conversation for templates/encoders that cannot handle it. `/v1/messages/count_tokens` uses the same converter.

Add three regression cases for string prefills, multi-block prefills, and the non-prefill/empty-conversation branches. The affected test class now uses `CustomTestCase` as required by the current test guidance.

Known limitations for review:

- Reasoning-on-by-default parsers may classify continued text as thinking unless the client sends `thinking: {"type": "disabled"}`. This follows the existing `continue_final_message` path; the adapter does not change reasoning policy here. No model-server validation was performed in this run.
- Consecutive assistant messages are not merged by the Python adapter. Only the final turn is continued.
- This joins final text blocks with `""`; the Rust router uses `"\n"`. Joining contiguous text blocks without an inserted separator preserves the supplied prefix exactly.
