# [Doc] cookbook: DeepSeek-V4.1 static expert placement from recorded counts

[Upstream PR](https://github.com/sgl-project/sglang/pull/46306) · state: open · merged: False

## Original PR description

## Motivation

Routed experts of DeepSeek-V4.1-Flash are not used evenly. With expert parallelism, the most loaded EP rank sets the pace of every MoE layer. SGLang can already place experts at startup from recorded per-expert counts (`--expert-distribution-recorder-mode stat`, then `--init-expert-location <dump>`). The model's cookbook page doesn't mention it.

## Modifications

Adds "3.7 Static Expert Placement" to the DeepSeek-V4.1 cookbook:
- how to record the counts on real traffic and restart with them;
- what the dump holds;
- what redundant experts add on top.

No code changes.

## Benchmark

GB300, DeepSeek-V4.1-Flash, DP2 TP2 EP2 prefill server, ABBA, 4 runs of 900 s each.

| | prefill throughput (tok/s per rank) |
|---|---|
| trivial placement | 80,876 / 80,858 |
| `--init-expert-location` (counts from the same traffic) | 82,990 / 82,684 (+2.4%) |
| `--init-expert-location` (counts from random token ids) | 80,762 (no gain) |

KV cache capacity is unchanged without redundant experts.
