# [Perf] [ROCM] diffusion: Skip dead math-SDPA work in the MiniMax-H3 VAE decoder on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/47570) · state: closed · merged: True

## Original PR description

## Motivation

gfx950 forces the H3 VAE decoder attention onto aten's math SDPA. That path also masks all-`-inf` rows (`_safe_softmax`: isneginf + all + where) and downcasts the fp32 attention weights it returns; the decoder discards both. On rank 0 this was ~58% of the 2.85 s decode, about 0.5 s of it dead work.

## Modifications

- Replay the math op chain (fp32 upcast, sqrt-scale on q and k, matmul, softmax, matmul) without the dead mask and downcast. Only the gfx950 math-SDPA path is touched.
- Test added to `test_minimax_h3_vae_output.py` (fails on main, passes here).
- The MIOpen workspace warnings in the VAE convolutions are left alone: giving MIOpen more workspace selects different conv algorithms and changes the output bits.

## Accuracy Tests

Output is bit-identical (per-op replay of the same chain): MP4 md5 identical to main on every prompt checked.

## Speed Tests and Profiling

Setup for all numbers below: 4x MI355X, MiniMax-H3 T2VA, 1280x704 (SemiAnalysis "720p"), 124 frames, 49 forwards, Ulysses 4 + aiter, single stream. Each arm is a fresh server (1 warmup + 3 timed requests), ABAB across two rounds, base = main `75a5da7f`.

Decode 2.84 s -> 2.09 s; 720p median -0.68 s.
