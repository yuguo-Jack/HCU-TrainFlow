# [Feat] scheduler: Adapt the UniBoost gamma online from the response-time tail

[Upstream PR](https://github.com/sgl-project/sglang/pull/48077) · state: open · merged: False

## Original PR description

## Motivation

Follow-up to #48076 (the UniBoost policy). The right `gamma` depends on the load: it sets how far a short request may jump a long one, and a fixed value is either too timid at low load or starves large requests under overload. The paper's gamma-Ada estimator (Eq. 9) tracks it online from the response-time tail: `gamma_hat = ln(5) / (t99 - t95)`. This PR adds it as `--uniboost-adaptive-gamma`.

**UniBoost series** (each PR builds on the previous one; review in order):
1. #48076: the policy (`--schedule-policy uniboost`)
2. #48077: adaptive gamma from the response-time tail
3. #48078: bounded waits for requests that share a prefix
4. #48079: decode time-slicing for first-token-starved waiters

All four target `main`, so #48077 to #48079 also carry the commits of the PRs before them; each PR's own change is its last commit.

## Modifications

- `managers/uniboost.py`: `AdaptiveGamma`. It fits `gamma_hat = ln(5) / (t99 - t95)` over the response times (scheduler receive to completion, wall seconds) of the last 128 completed requests, starting after 32. Each fit is folded into an EMA with weight 0.2 and clipped to [1e-3, 15] 1/s. Two additions to the paper's estimator:
  - **Max-jump floor** (`--uniboost-adaptive-max-jump-s`, default 60): `gamma` is floored so that the largest boost, `b_gamma(k / rate)`, stays within J wall seconds; the floor is the root of a monotone function, found by bisection. That bounds how long a newcomer can delay a waiting request regardless of the service rate. A raw `gamma` floor would give a bound that scales with the rate.
  - **Size-aware fit**: when the requests above median work have a fatter tail than those below it, the fit uses the small-work tail. In that case the fat tail is the policy itself starving large requests under overload, and fitting it would drive `gamma` toward 0 and starve them further.
  - The paper's main text derives `ln 5` (`ln(CCDF(t95) / CCDF(t99))`); its Algorithm 1 computes `ln(99/95)`. The main-text form is used.
  - An info log line reports `gamma`, the raw fit and its source, the floor, and the share of updates pinned at the floor.
- `managers/schedule_policy.py`: `record_completed_requests` feeds finished requests to the estimator, and the sort reads the current `gamma`.
- `managers/scheduler.py`: calls `policy.record_completed_requests(batch.reqs)` after each processed batch result.
- `arg_groups/`: `--uniboost-adaptive-gamma` and `--uniboost-adaptive-max-jump-s`. Validation: both require `--schedule-policy uniboost`, the estimator requires `--uniboost-clock wall` (the tail fit is in seconds), and J > 0. `--uniboost-gamma` becomes the initial value.
- Existing scheduler unit tests that build partial schedulers get a `policy` stand-in for the new call.
- `docs/.../server_arguments.mdx`: the two flags.
