# [Fix] Skip cancelled requests in the dynamic batch tokenizer

[Upstream PR](https://github.com/sgl-project/sglang/pull/42043) · state: open · merged: False

## Original PR description

## Motivation

With the dynamic batch tokenizer enabled, cancelling an `encode()` caller leaves its prompt in the queue. The batch worker still tokenizes it and only discards the result afterward. Behind a busy encoder, abandoned prompts consume CPU before live requests; their kwargs can also prevent otherwise compatible live requests from being batched.

## Modifications

Exclude cancelled result futures before checking batch kwargs or submitting encoder work, and return immediately for an all-cancelled batch. Preserve live request ordering, kwargs and results. Already-started tokenization continues as before.

## Accuracy Tests

- Four registered CPU tests use a real in-memory Hugging Face tokenizer and deterministic gates: cancelled entries around live requests, mixed live kwargs, all-cancelled batches, and subsequent live progress. All four fail before the fix and pass afterward.
- The 13 existing manual CPU cases pass. The model-download integration case was deselected; a separate reproduction with a real ByteLevel tokenizer verifies the abandoned prompts are no longer encoded and live results stay identical.
- Touched-file pre-commit checks pass, including registered test validation.

Local tests loaded the actual CPU modules with namespace package paths because this macOS environment cannot run SGLang's GPU package initializer without Triton. The implementation and tokenizer were not replaced; the registered tests use normal imports in CI.

Prepared and independently reviewed with AI assistance (Codex).

## Speed Tests and Profiling

Verified avoided tokenizer invocations for requests cancelled before encoder submission. No GPU or end-to-end throughput benchmark was run; this does not interrupt an active tokenizer call or change model inference.
