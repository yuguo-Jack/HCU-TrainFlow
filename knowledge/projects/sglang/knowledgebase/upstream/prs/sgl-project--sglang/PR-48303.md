# [Perf] [AMD] GLM5.3: Speed up KDA causal-conv and mHC pre prefill on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/48303) · state: open · merged: False

## Original PR description

## Motivation

GLM-5.3-Flash runs its KDA causal convolution on the default 8×256 Triton tile on gfx950 for its 6,144-channel (TP4) and 3,072-channel (TP8) width-4 prefill. Its mHC pre GEMM passes the FP32 `hc_fn` to AITER's `mhc_pre_gemm_sqrsum`, which then computes with FP32 MFMA and is bound by FP32 matrix throughput (68% MFMA utilization at 16K tokens).

This change selects a 32×512 causal-conv tile for the measured GLM-5.3-Flash geometry from the token counts where it beats the default, and packs each `hc_fn` once at weight load into AITER's BF16 hi/lo layout so the pre GEMM runs on BF16 MFMA through AITER's existing `w_preshuffle_bf16` path. No AITER change is required.

## Modifications

- Add a gfx950 GLM-5.3-Flash causal-conv prefill tile (`BLOCK_M=32`, `BLOCK_N=512`) for BF16 width-4 convolution at 6,144 channels from 12,288 tokens and at 3,072 channels from 24,576 tokens.
- Keep the default tile for every other channel count, width, dtype, token count, non-gfx950 device, and block-table launch.
- Pack `hc_attn_fn` and `hc_ffn_fn` once after weight load with AITER `mhc_shuffle_fn` on both the `load_weights` and `post_load_weights` paths; nothing is packed inside a forward, so CUDA-graph capture is unchanged.
- Pass the packed weight with `w_preshuffle_bf16=1` only while the cached entry belongs to the same parameter at the same version. An in-place weight update, any geometry other than the measured FP32 24 × 16,384 weight, or a missing AITER packing API keeps the FP32 GEMM.
- Add CPU dispatch contracts for the causal-conv thresholds and gfx950 tests for packed-weight parity, version invalidation, and the geometry gate.

## Accuracy Tests

Focused validation passed **2 CPU dispatch contracts, 9 gfx950 kernel tests with 38 subtests, and 270 Triton causal-conv layer tests**. Coverage includes the TP4/TP8 tile thresholds and their boundaries, default-tile fallbacks, packed-versus-FP32 mHC mixes and layer input at 1, 64, and 4,096 tokens, weight-version invalidation, the unmeasured-geometry gate, AITER import and runtime fallbacks, and CUDA-graph replay.

Full GLM-5.3-Flash TP8 GSM8K on snapshot `b5688f25491202978c19c4d036eef579f61bbe07`: 1,319 examples, 1,200 evaluator threads, 4,096 maximum output tokens, thinking enabled, temperature 1.0, top-p 0.95, sampling seed unset.

### Causal-convolution prefill latency

Single-sequence GLM-5.3-Flash geometry, BF16, width 4. GPU kernel time compares the default 8×256 tile against the 32×512 GLM tile; outputs are bitwise identical.

| TP | Channels | Tokens | Default tile (ms) | GLM tile (ms) | Delta |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 4 | 6,144 | 12,288 | 0.1442 | 0.1184 | **-17.86%** |
| 4 | 6,144 | 16,384 | 0.1912 | 0.1541 | **-19.44%** |
| 4 | 6,144 | 32,768 | 0.3789 | 0.2927 | **-22.75%** |
| 4 | 6,144 | 65,536 | 0.7425 | 0.5621 | **-24.29%** |
| 4 | 6,144 | 131,072 | 1.5481 | 1.0627 | **-31.35%** |
| 8 | 3,072 | 24,576 | 0.1385 | 0.1170 | **-15.53%** |
| 8 | 3,072 | 32,768 | 0.1882 | 0.1532 | **-18.63%** |
| 8 | 3,072 | 65,536 | 0.3639 | 0.2940 | **-19.21%** |
| 8 | 3,072 | 131,072 | 0.7124 | 0.5523 | **-22.47%** |

Three-sequence ragged batches at the same totals improve by 13.26-25.22%. Every enabled cell beat the default tile; shorter batches, where the GLM tile was slower, keep the default.

### mHC pre GEMM latency

AITER `mhc_pre_gemm_sqrsum` for GLM-5.3-Flash (`hc_mult=4`, hidden 4,096, 24 outputs). `hc_fn` is replicated across TP ranks, so TP4 and TP8 run the same shape. GPU kernel time compares the FP32 weight against the packed BF16 hi/lo weight:

| M | FP32 weight (ms) | Packed BF16 weight (ms) | Delta |
| ---: | ---: | ---: | ---: |
| 1 | 0.0043 | 0.0035 | **-18.15%** |
| 64 | 0.0052 | 0.0045 | **-12.41%** |
| 512 | 0.0107 | 0.0082 | **-22.85%** |
| 2,048 | 0.0250 | 0.0154 | **-38.42%** |
| 4,096 | 0.0447 | 0.0249 | **-44.20%** |
| 8,192 | 0.0863 | 0.0534 | **-38.08%** |
| 16,384 | 0.1794 | 0.1256 | **-30.01%** |

Post and combine mixes match the FP32 GEMM to about 1e-6 relative; the BF16 layer input differs by at most one BF16 rounding step.
