# fix(unified_cache): replay hit-count bump on chunked-prefill request finish (fixes #33714)

[Upstream PR](https://github.com/sgl-project/sglang/pull/44335) · state: closed · merged: False

## Original PR description

## Issue

Fixes #33714 — **unified_cache 长 prompt 备份缺失（chunked long-prompt backup missing in unified_cache）**

For any request whose cold prefill extend exceeds `chunked_prefill_size`, HiCache
write-through was completely skipped. After a server restart, every cold long
prompt had to pay the full prefill cost again.

## Root Cause

Chunked prefill flows through multiple intermediate `checkpoint_kv_cache`
calls before the final `release_kv_cache`. Each call passes
`inserted_len = req.kv.cache_inserted_len`, and `UnifiedTreeCore` skips the
hit-count bump for any node whose `node_end <= inserted_len`:

| Phase | inserted_len | Retained prefix nodes | Hit count bump |
|---|---|---|---|
| Chunk 1 checkpoint | 0 | — (all new) | ✓ hit_count += 1 |
| Chunk 2 checkpoint | chunk_size | chunk 1 nodes | ✗ skipped |
| Chunk 3 checkpoint | 2× chunk_size | chunk 1 + chunk 2 | ✗ skipped |
| **Final release insert** | total_len | **all prior nodes** | **✗ skipped** |

Result: every node on the retained prefix ends with `hit_count = 1`. With
`hicache-write-policy write_through_selective` (threshold = 2), the
write-through backup **never fires** on a cold chunked request.

## Fix

Add `InsertParams.force_bump_hit_count: bool = False`. When set, the tree
walk ignores the `inserted_len` gate and bumps hit counts on every node it
passes — replaying the root-walk effects that a chunked request's intermediate
checkpoints deliberately deferred.

`UnifiedRadixCache.checkpoint_into_tree` sets `force_bump_hit_count=True`
**only** when:

- `is_finished = True` (the final insert, not an intermediate checkpoint), **and**
- `req.kv.cache_inserted_len > 0` (there was at least one prior intermediate checkpoint,
  i.e. the request was chunked).

This gives the retained prefix exactly **one extra hit-count bump at request
finish**, bringing every node from `hit_count=1` to `hit_count=2` — just at
the `write_through_selective` threshold of 2 so HiCache write-through fires.

Non-chunked requests are unaffected (`cache_inserted_len = 0` at finish →
`force_bump_hit_count = False`). The split-leaf insert at the prompt boundary
also explicitly disables it to avoid a double-bump on the structural re-insert.

## Design Notes

- Mirrors Rust-side fix b7e2cd903a which introduced the same "bump only on
  non-chunked continuation" semantic on the Rust UnifiedTreeCore.
- Acknowledges PR #36353 (zumi87, open): this approach is complementary —
  it reuses the existing hit-count->write-through trigger instead of adding a
  new backup path, keeping the change minimal and fully backward-compatible.
- Mamba checkpoint boundary edge case (PR #30850) remains open; it requires
  `effective_cache_len > 0` to enter the insert path at all.

## Verification

- Code compiles clean (`py_compile` on all three touched files).
- Backward-compatible: `force_bump_hit_count` defaults to `False`.
- Simulated scenarios (table above) confirm every chunked-request node crosses
  the `write_through_selective` threshold exactly at request finish.
