# [Perf] hicache: overlap MLA host reloads with forward-layer broadcasts

## Status and dependency

**Draft; depends on #44536.** This branch is based on its current head, `2a97353558a3b505c17fb4aa0da61e8d324e2471`, and targets `main` as a follow-up. The base diff therefore includes the UnifiedRadixCache dedup integration from #44536. The final commit contains the optimization-specific changes; those inherited integration changes are not new work in this PR.

## Motivation

The synchronous dedup path restores and broadcasts all layers on the H2D stream, then drains that stream before returning to forward. This avoids conflicting collective order across the dedup and model-TP communicators, but prevents this batch's compute from overlapping with later H2D copies. Simply removing the drain would not preserve the required collective ordering.

## Optimization increment

[Optimization-only diff](https://github.com/HZY-Wade/sglang/compare/2a97353558a3b505c17fb4aa0da61e8d324e2471...cde7357fac8eb3508241deed3f43753d6a0a646a).

- Add opt-in `SGLANG_MLA_DEDUP_LOAD_MODE=forward`. The default remains `sync`; with host dedup disabled, the existing non-dedup transfer path remains unchanged.
- Keep target/source and rank-local draft H2D on `L2TransferEngine.host_to_device_stream`, preserving the producer and reclaimed-page fences. Record a copy-ready event per layer.
- Submit each layer's broadcast from the model's forward layer boundary, on the current forward stream: wait for that layer's copy, broadcast/scatter, then run the layer. Later H2D can proceed concurrently, while dedup and model collectives are submitted in layer order.
- Bind forward callbacks to a batch's producer slot and generation. Guard collective submission order and prevent reuse of a slot whose GPU work is still in flight.
- Publish the load ACK and allocator transfer-completion event only after the final broadcast/scatter has been submitted. H2D-only completion is not peer-KV readiness.
- Bypass graph replay only for a forward with pending broadcasts. Retain the normal graph path for batches without a pending load.

This is a scheduling/ordering change, not a new KV layout or broadcast kernel. Target KV/Indexer remain deduplicated; draft transfers stay rank-local.

## Current scope

The opt-in path currently supports the DeepSeekV2 forward hook and derived models, with either normal or CPU/GPU-overlap scheduling, PP1, non-disaggregated serving, CPU L2 only, and fixed device pages.

PD, PP>1, movable/unified-memory device pages, TBO, split prefill, and unsupported model hooks are explicitly excluded. Pending broadcasts execute eagerly, outside CUDA graph capture. These restrictions are not removed from the synchronous default path.

Coverage includes source/peer H2D selection, rank-local drafts, producer/load fences, layer waits, idempotent callbacks, no premature ACK, final completion-event ownership, queued-batch ordering, stale handles, GPU-inflight slot reuse, and excluded configurations. Ruff lint/format and diff checks pass.

The same scheduling approach has been exercised in a downstream implementation with overlap scheduling and repeated L2 reloads under live traffic. This community adaptation uses the current `L2TransferEngine` interfaces and still needs its own multi-GPU correctness, graph-regression, and performance validation before leaving draft. No downstream throughput result is claimed for this exact port yet.
