# [Perf] sdar: Share block refresh with next-block denoising

[Upstream PR](https://github.com/sgl-project/sglang/pull/44652) · state: open · merged: False

## Original PR description

## Motivation

SDAR runs a full-model KV refresh after completing each block. The next block then starts with a separate denoising forward.

This opt-in change shares those forwards at batch size one. Each layer refreshes the completed block before next-block attention reads its KV.
The gate/up projection uses both blocks together. QKV, attention-output, and FFN-down projections retain their original row counts on two ordered CUDA streams.

## Scope and behavior

- Dense SDAR, BF16 weights/KV, LowConfidence, FDFO, TP=PP=1, and native FlashInfer ragged attention.
- Enable `SGLANG_SDAR_REFRESH_PAIR=1`. The default is disabled.
- Keep the threshold, token selection, terminal refresh, and model weights unchanged.
- Use native execution for larger batches and unsupported request features. Discard pending predictions before incompatible batch changes or retraction.
- Validate configuration and capture the extra graph before readiness. Compare the first eligible live transition against native graph execution.
- Preserve normal profiler spans and GPU-time accounting. Reject unsupported memory-saving, offloading, debugging, and speculative modes.
- Reject online weight updates while enabled. The session guard checks every selected runner before changing weights.
- Disable sharing after native graph replacement and discard pending predictions before reuse.

The adapter borrows one scratch KV block per paired call and releases it afterward. Scratch slots never enter the scheduler request table.
There is one model weight copy. The extra graph and attention metadata consume additional memory.

[Usage and test commands](https://github.com/vishal1383/sglang/blob/7402129c76586f461a1a7aec58f0c7ea914190f1/benchmark/dllm/sdar_refresh_sharing.md).

## CPU and GB10 validation

- 163 CPU tests passed, including existing diffusion/FDFO and KV-location regressions.
- The registered original-B4 regression passed three additional full-output comparisons on this head's exact source, including repeated-request reuse. Total: 46 comparisons across the two validation runs.
- 43 exact-output comparisons passed: three registered B4, 16 initial B16/B32, and 24 paired timing comparisons. Another 24 main-branch SGLang timing requests matched their initial references.
- Both B16/B32 N1-to-N2 transitions passed: prediction discard, mask restoration, drain, and request-slot reuse.
- B16/B32 numerical qualification reported zero logit differences for both blocks.
- Repository-configured Ruff, isort, CI registration, and whitespace checks passed.

The numerical check requires finite logits, `atol=0.01`, `rtol=0.01`, equal greedy IDs, and equal confidence decisions.
Failure disables sharing and restores native execution. The first-transition check is not a proof of bitwise equality for all inputs.

## Performance

### A100: current PR source

One NVIDIA A100-SXM4-80GB, BF16, concurrency 1, confidence threshold 0.95, FDFO, CUDA Graphs, and native FlashInfer 0.7.2.
Both variants disabled radix caching and scheduler overlap.
Each block size used eight retained ShareGPT prompts and two trials, with variant order reversed between trials.
Each cell used eight full-workload warmup requests before eight timed requests, with identical output caps and native EOS.

| Model / block size | Threshold | Main-branch SGLang mean request latency (ms) | Patched SGLang (ms) | Speedup | Latency reduction |
| --- | ---: | ---: | ---: | ---: | ---: |
| SDAR-8B-Chat, B4 (original) | 0.95 | 4346.4 | 3701.6 | **1.174x** | **14.83%** |
| SDAR B16 | 0.95 | 2879.8 | 2734.8 | 1.053x | 5.03% |
| SDAR B32 | 0.95 | 2113.5 | 2076.8 | 1.018x | 1.74% |

These are warmed full-request latencies, including prefill, generation, scheduling, and HTTP.
For each block size, all 16 timed patched outputs and 16 patched warmup outputs matched the main-branch SGLang reference exactly.
The comparison checked output token IDs, text, and finish reasons.
Each patched server passed numerical qualification before timing. No qualification or fallback occurred during timing.
B4 trial speedups were 1.149x and 1.199x. Seven of eight B4 prompt means improved; the one-token response was 0.37% slower.

The A100 B4 and B32 qualification checks reported zero logit difference for the checked blocks.
B16 had a maximum absolute logit difference of 0.0625, within `atol=0.01, rtol=0.01`, with unchanged greedy IDs and confidence decisions.
These checks do not establish universal bitwise equality.
Device-memory samples increased by 158 MiB for B4, 230 MiB for B16, and 286 MiB for B32.
These nvidia-smi samples measure device memory use; the GB10 table below uses live PyTorch allocations.

Patched source: `7402129c76586f461a1a7aec58f0c7ea914190f1`.
Main-branch SGLang baseline: `773cb938fe9484a8f7e7e46fb1b1fe96412c59ed`.
The small cohort supports an initial comparison at N1 and threshold 0.95.

### GB10

One NVIDIA GB10 (Spark664c), BF16, N1, FDFO, CUDA Graphs, and native FlashInfer 0.7.2. Radix caching and overlap scheduling were disabled for both variants.
Each variant used four fixed ShareGPT prompts, repeated three times, with identical output caps and native EOS.
Memory reads ran outside timing. Transition instrumentation was installed after timing.

| Block | Threshold | Main-branch SGLang mean request latency (ms) | Paired (ms) | Speedup | Extra live PyTorch allocation (MiB) |

| B32 | 0.95 | 5411.8 | 5101.5 | 1.061x | 192.8 |

These observations include loading, compilation, and three-second polling. They do not isolate graph-capture cost.
Extra allocation uses PyTorch allocator snapshots; it excludes allocations outside PyTorch.
