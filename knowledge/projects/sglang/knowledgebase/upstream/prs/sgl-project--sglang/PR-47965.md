# [Feat] spec: add per-request speculative decoding opt-out with mixed-batch support (#47797)

[Upstream PR](https://github.com/sgl-project/sglang/pull/47965) · state: open · merged: False

## Original PR description

## Summary and final contract

Implements per-request speculative-decoding opt-out for EAGLE, EAGLE3, and STANDALONE, including mixed batches. Related RFC: #47797.

`SamplingParams.disable_speculative_decoding=True` means **one target-root token committed per decode iteration**. The opted-out row independently uses the ordinary target sampler; draft proposals are not accepted. Draft prefill, proposal, and extend work **continues**, including when every row opts out, to preserve the configured execution layout and draft KV state.

This is deliberately narrower than the RFC's zero-draft-work request. It is not a target-only performance baseline or a promise of bitwise-identical sequences across separately configured servers. Maintainer agreement on this contract remains necessary.

## Changes

- Propagate opt-out masks and host flags through batch construction, filtering, merging, and empty batches.
- Sample and replace the target-root token, then truncate acceptance counts and index sentinels. Clamping acceptance length alone would not ensure the correct target-root output.
- Preserve draft extend inputs, retained-token/bonus-token bookkeeping, and runtime shapes for mixed and all-opt-out batches.
- Reject opt-out batches from post-verify graph replay; model forward CUDA graphs remain supported. Exclude deliberate zero draft acceptance from adaptive accuracy feedback.
- Reject unsupported algorithms and custom logit processors. Carry the field through the native API schema, protobuf, and generated Python/Rust bindings.
- Add regression tests, CUDA graph checks, model lifecycle diagnostics, and reproducible environment/resume scripts.

### Separate EAGLE3 output-head fix

[`b751b5f3`](https://github.com/sgl-project/sglang/commit/b751b5f3816a43603e85591850e6c70b003f611b) is a **separate commit fixing an existing EAGLE3 reduced-vocabulary head-loading bug**, not the opt-out contract itself. An enabled-only control reproduced the failure.

When a draft checkpoint has a reduced vocabulary and `tie_word_embeddings=True`, its trained `lm_head` must remain separate from target embeddings. The fix preserves that head during checkpoint loading and target-embedding sharing; equal-vocabulary tying is retained. The focused regression failed before the fix (1 failed, 1 passed) and passes after it (2 passed). Reviewers can evaluate or split this commit independently.

## Numerical diagnosis and remaining limits

- Earlier STANDALONE target-only comparisons had **14 exact token-sequence mismatches**; those assertions remain recorded as failures. Same-prefix diagnostics at the two first-divergence sites found BF16 root-logit ties and correct lower-ID argmax/token-logprob agreement. FP16 removed those ties and matched the tested outputs. This supports numerical sensitivity at those sites, not a blanket proof of identical logits or KV across all execution modes.
- One empty CUDA graph warning remains in the model graph-mode warmup, consistent with the separate no-op Mamba-state commit capture for the dense Qwen3 model. It did not indicate an empty target forward/sampling graph; lifecycle checks passed. Unit graph-warning coverage and this model-warmup observation are distinct.
- TP/PP/DP combinations, HiSparse, top-k > 1, broader models/transports, and throughput/latency benchmarks remain unvalidated. Diagnostic probes synchronize execution and are not performance measurements.
- The existing EAGLE-family `return_sampling_mask` limitation remains; ordinary streaming is covered.
- Local/GPU results above are independent evidence, **not upstream CI success**. The pre-transition Base CI run was blocked by the draft gate; repository CI also requires the appropriate `run-ci` authorization. Latest-head CI must be green and maintainer review completed before merge.
