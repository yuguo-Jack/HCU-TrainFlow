# [Feat] [NVIDIA] megakernels: Add --enable-nvidia-megakernel and a layer for NVIDIA megakernel plugins

[Upstream PR](https://github.com/sgl-project/sglang/pull/44945) · state: open · merged: False

## Original PR description

## Motivation

The NVIDIA megakernel for DeepSeek-V4.1-Flash decode on GB300 ships as an out-of-tree package, sgl-project/sgl-nvidia-mega. It runs the decode steps it covers with its own step code over the weights SGLang loaded.

This PR adds the SGLang side such a plugin needs, and nothing else:
- one launch flag and a small framework that checks the setup, replaces the model's forward for the steps the plugin covers, and offers a DSpark draft-proposal entry;
- one binding file through which SGLang hands the plugin's build, forward and draft entries the runtime state they need (the KV pool, the running forward's attention metadata, the Engram tables), as data.

Everything model-specific stays in the plugin. SGLang's own decode flow (the DSpark worker included) is unchanged.

This PR previously also carried DSpark decode hooks and runtime changes; they are no longer part of it.

```text
# with the flag and the NVIDIA megakernel plugin, every rank logs one line per installed model:
NVIDIA megakernel: active (<spec>: <summary>; widths [...]; <numerics> numerics; built in N s, M MiB; wait deadline D s)
# a DSpark draft model with its own spec logs its own line (an "active" line when it covers draft steps)
```

## Modifications

**Flag.** `--enable-nvidia-megakernel` (bool, default off), in the exec argument group. With it off, nothing in the megakernel layer runs.

**`python/sglang/srt/megakernels/`**
- `spec.py`: the contract a plugin implements, plus a lazy per-architecture registry that the plugin's `sglang.srt.plugins` entry point fills. The contract is:
  - `MegakernelSpec`;
  - `Requirements` and `Numerics`, given as data;
  - `BuildContext` (now with `binding`) and `Step` (now with `view`);
  - the `BuiltMegakernel` protocol, with an optional draft-sampler factory.
- `guards.py`: the argument-resolution step `handle_nvidia_megakernel`. It runs before any weight loads. With the flag set, it refuses the launch and lists every reason together:
  - the plugin's entry point is not installed (with an install hint), or `SGLANG_PLUGINS` is set and does not list it;
  - the model has no spec for this GPU;
  - an SGLang feature in use that the spec does not accept (one probe each, on the resolved settings);
  - tensor parallel size, dtype, decode CUDA graph backend, server arguments, HF config fields or environment variables that the spec does not accept;
  - the watchdog's wait deadline;
  - the spec's own configuration checks;
  - another whole-step kernel backend selected at the same time.
- `runtime.py`: `install_megakernel`, the last step of `ModelRunner.initialize`. It runs after every post-load change to the model and before the KV cache is sized. With the flag set:
  1. On every TP rank, it finds the spec and the reasons it cannot serve this model, gathers them, and raises on every rank if any rank has one.
  2. It builds the spec at the covered step widths, handing it this model's binding (below).
  3. It replaces the forward on that model instance only. A step the built object plans runs on the plugin, with the running forward's view; every other step runs the model's own forward. The plan reads host state only, so all ranks agree and a captured graph replays the decision made at capture.
  4. It makes weight updates refuse, and logs one line per rank saying what is active.
  5. It adds a capture check that refuses a runner none of whose decode graphs run the plugin, and checks the binding's sealed sources there.
  6. A target spec that builds no width is refused on every rank. A draft model's spec is checked the same way; it may cover draft steps (its own forward and binding) and/or offer a draft sampler.
- `megakernel_agree` (in `runtime.py`): the one cross-rank check every decision above uses. It gathers a value over the TP CPU group and refuses on every rank, listing each rank's value, when they differ.
- `binding.py` (new): the binding, the one place a megakernel reads SGLang's runtime state (next section).

**The binding (`megakernels/binding.py`).**

- **`MegakernelBinding`**, one per installed model, handed to the spec's build as `BuildContext.binding`. The target model and the DSpark draft model each get their own (each is installed on its own runner).
  - `forward_view()`: the `ForwardView` of the forward running now, read from SGLang's forward context. A draft entry calls it inside the draft step and gets the draft runner's view.
  - `engram_history()`: the model's Engram hash history tensor, or None.
  - `engram_host_table(engram)`: the host table of one of the model's Engram layers, or None.
  - `assert_live()`: raises, naming the source, once a sealed source was reallocated.
- **`ForwardView`**, the running forward's attention data. A covered step gets it as `Step.view`; SGLang builds it only when the plan returned a step, so at capture for a graph step, and its tensors are the ones the graph replays.
  - `metadata`: the attention backend's forward metadata;
  - `kv_pool`: a `KvPoolView`;
  - `trtllm_attn`;
  - the backend's own `attention`, `store_cache`, `swa_out_cache_loc`, `low_ratio_sources` and `core_compressor` calls (tolerated, below).
- **`KvPoolView`**, the running forward's KV pool under the pool's own names: `uniform_fp8`, `request_window`, `get_swa_key_buffer_radix(layer)`, `get_swa_key_page_size()`, `get_swa_key_bytes_per_token()`, `get_extra_key_buffer(layer)`, `get_extra_key_page_size(layer)`, `get_extra_key_bytes_per_token(layer)`, `set_swa_key_buffer_radix_fused_norm_rope` (tolerated), and `pool` (tolerated: only passed back into SGLang's own calls). A pool offers the members of its kind; each is read on access.
- **What crosses besides data**, listed as literal tuples in the file so a plugin's contract test can pin them:

  ```python
  TOLERATED_CALLABLES = (
      "ForwardView.attention",  # the attention backend's own forward
      "ForwardView.store_cache",  # the KV write
      "ForwardView.swa_out_cache_loc",
      "ForwardView.low_ratio_sources",  # compressor / indexer inputs
      "ForwardView.core_compressor",
      "KvPoolView.set_swa_key_buffer_radix_fused_norm_rope",  # the fused SWA key write
      "KvPoolView.pool",  # passed back to SGLang's own draft KV store only
      "sglang.kernels.ops",  # SGLang's kernel ops
      "the replaced model's modules, weights and quant methods",
  )
  TOLERATED_WRITES = (
      "ForwardView.metadata.q_pad_buffer",
      "ForwardView.metadata.low_ratio_req_indices",
      "ForwardView.metadata.low_ratio_pos_i64",
  )
  TOLERATED_READS = (
      "runtime_context getters (get_parallel, get_exec, get_spec, get_platform)",
      "capture-mode queries (get_is_capture_mode, is_in_breakable_cuda_graph)",
      "MegakernelBinding.engram_host_table",  # the per-layer host table object
  )
  ```

- **Lifetime.** The binding is built at install, before the KV pools exist, so it reads lazily. The KV pool and the Engram history are each sealed (data pointer, shape and dtype, or the object) at the first read that finds them. `assert_live` runs in the capture check, once every decode graph of the runner is captured, and raises naming a source that was reallocated since.

**Call sites:**
- the resolution step in `arg_groups/pipeline.py` and `resolution_hooks.py`;
- one call at the end of `ModelRunner.initialize`;
- `maybe_build_draft_sampler`. It passes the draft model's factory, when one is registered, to `DsparkDraftSampler`, which then runs the plugin's step for the batch sizes it serves. Every rank must serve the same batch sizes, checked with `megakernel_agree` before graph capture; the `BuiltMegakernel` docstring states what a step must do (identical tokens on every rank, the buffers it writes, the noise counter).

**Docs:** a row in the server-arguments documentation.

**Images:** `docker/Dockerfile` and `docker/Dockerfile.cu134` install the plugin at a pinned commit (`SGL_NVIDIA_MEGA_COMMIT`, sgl-nvidia-mega main `d47deb3`) and check that its entry point is registered, as `docker/rocm.Dockerfile` does for the AMD plugin. Images with CUDA below 12.9 skip it; opt out with `--build-arg ENABLE_SGL_NVIDIA_MEGA=0`. The plugin does nothing unless a server passes `--enable-nvidia-megakernel`.

### Known limits

- **Re-capture.** `assert_live` runs at the capture check only. A later SGLang re-capture would have to check again; the binding does not support re-capture yet. With the flag set, weight updates already refuse.
- **Tolerated items.** The three lists above are what is still handed over beyond data: the backend's own attention / KV-write / compressor calls, three writes into the forward metadata, and configuration reads. Each can move to data later without changing the plugin's other code.

Could you simplify the tests in this PR, especially the “1 + 1 = 2” style of AI-generated tests that mostly restate the implementation or check names we just defined? Each test should protect a concrete behavior that could regress, with as little test scaffolding as practical.

In particular:

- Please consider removing `test_megakernel_contract.py`. Its AST scan checks whether a name or string appears somewhere in a source file, which does not establish that the runtime object actually provides the required interface. An unrelated occurrence can satisfy it, while moving an implementation between files can break it without changing behavior.
- In the binding tests, the `TOLERATED_CALLABLES` / `hasattr` enumeration seems less useful than the existing checks that the view exposes the actual backend/pool and that replacing a sealed source is detected. Keep those behavioral checks and trim the interface-name bookkeeping.
- Keep the meaningful guard/dispatch coverage: disabled flag, covered-step vs. fallback routing, missing target vs. optional draft spec, rank disagreement, no captured graph using the plugin, and draft-sampler buffer handoff/fallback. These cover distinct failure modes; they do not need a larger matrix of trivial assertions.

The goal is a small, readable suite that catches real regressions, rather than more assertions or elaborate mocks for their own sake.
