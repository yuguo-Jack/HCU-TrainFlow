## Motivation

Enable DeepSeek-V4 breakable prefill graphs on Ascend NPU, including `--cuda-graph-prefill-max-context`.

The NPU path needs request-dependent cache/indexer/compressor work outside captured segments and fixed page-table extents across capture and replay. This PR adds those hooks and preserves the existing CUDA semantics: the context bound applies to each request, while graph buckets remain keyed by aggregate token count. Eligible zero-prefix multi-request prefills can replay a graph; over-limit or unsupported batches fall back to eager.

## Modifications

- Add NPU DSV4 prefill graph eligibility checks for compatible token buckets, zero-prefix batches, valid DSV4 cache locations, and non-speculative/non-CP execution.
- Prepare valid scratch cache locations for synthetic capture batches. Support context-bounded multi-request capture, and size C4/C128 locations per request to preserve compression boundaries.
- Run request-dependent KV cache writes, indexing, and compression at eager boundaries using the live batch. Trim padded token rows before these operations and trim C4 top-k rows to the actual query count.
- Enable the max-context capability and use `max_seq_len_override` to fix full/SWA/C4/C128 page-table extents while preserving actual sequence and extend lengths. Propagate the limit through a shallow batch copy when rebuilding replay metadata, without modifying the original serving batch.
- Preserve DSV4 cache-location bundles in replay batches and disable multi-stream execution for the NPU breakable prefill path.
- Move HCCL prewarm before attention-backend and graph initialization, using the initialized TP group, so the first DSV4 metadata call does not trigger lazy HCCL initialization during capture.
- Add regression coverage for fixed metadata extents, per-request context bounds, compressor boundaries, replay limit propagation, and unchanged eager/decode behavior. Update the existing capture test fixture.

**NPU graph/eager parity:** DeepSeek-V4-Flash configuration with dummy weights, 4 layers, 8 routed experts, TP=2, random seed 42, decode graph disabled, and prefill token buckets `128/256/384/512`.

| Max context | Boundary behavior | Request groups matching eager | Saved logit batches matching eager | Max absolute logit error |
| --- | --- | --- | --- | --- |
| 256 | 256 uses graph; 257 falls back to eager | 20/20 | 25/25, bitwise identical | 0 |
| 384 | 384 uses graph; 385 falls back to eager | 20/20 | 25/25, bitwise identical | 0 |

Across both settings, output token IDs and text matched eager execution for all 40 request groups. All 50 saved prefill logit batches were bitwise identical, with relative L2 error 0 and identical argmax.

Coverage includes batch sizes 1-4, changing live sequence lengths, bucket padding, over-limit fallback, and chunked requests. Both TP ranks captured all four buckets, including the 512-token bucket above the per-request context limit. A `[256, 256]` batch replayed the 512-token graph under both limits. CLI page alignment was also checked: a requested limit of 300 resolves to 384 with page size 128.

These are dummy-weight correctness checks. Full-checkpoint/task accuracy evaluation and DP/CP validation have not been performed.
