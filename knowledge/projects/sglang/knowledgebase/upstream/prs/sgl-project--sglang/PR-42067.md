# [Rust] Skip queued tokenization for disconnected clients

[Upstream PR](https://github.com/sgl-project/sglang/pull/42067) · state: closed · merged: False

## Original PR description

## Motivation

The native tokenizer worker still encodes a queued request's stop strings and prompt after its client disconnects. Intake eventually drops the result, but the cancelled work delays live requests sharing the CPU worker queue.

## Modifications

Check whether the request's response receiver is closed before starting tokenization. Return the request through the existing `Tokenized` event with the expected disconnected error so Intake clears tracking and deregisters it, including when the separate abort event has not arrived yet. Keep running tokenization non-preemptive.

This changes the native `sglang-server` worker. The renderer and Python dynamic tokenizer have separate queues and implementations.

## Accuracy Tests

- Two regressions fail with the exact original worker implementation and pass with the fix.
- A gated actual worker processes one live request, a cancelled queued request and a following live request. The cancelled prompt and stop strings are never encoded, all requests return to Intake, and live work still completes. Threads are released and joined before assertions on both versions.
- Actual worker/Intake lifecycle tests verify cleanup both before and after Intake records the abort: no cancelled request reaches the scheduler, tracking is removed, and deregistration occurs exactly once.
- The full server library suite has 316 passing tests and 13 existing POSIX shared-memory permission failures in this local sandbox. Real socket tests pass. These CPU lifecycle checks do not require model execution or GPU validation.
- The existing special-token test now keeps its response receiver alive, matching the live request that it intends to exercise.

## Speed Tests and Profiling

The regression counts backend encode calls to establish that cancelled queued work is skipped. No throughput or GPU benchmark claim. A disconnect after encoding has started does not interrupt the tokenizer.
