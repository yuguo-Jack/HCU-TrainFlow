# [diffusion] WanVideo TeaCache skipping is off-by-one

[Upstream PR](https://github.com/sgl-project/sglang/pull/24227) · state: open · merged: False

## Original PR description

This PR fixes an off-by-one indexing error in the WanVideo TeaCache implementation.

## The Issue

The `WanTransformer3dModel.cnt` is 0-indexed, while `TeacacheParams.start_skipping` and `TeacacheParams.end_skipping` are treated as 1-indexed step counts. This mismatch caused the model to remain in a "boundary step" (must perform the full calculation) for one extra forward pass, preventing a valid skip.

## The Fix

I aligned the 0-indexed counter with the 1-indexed boundaries by adding and subtracting 1 when appropriate. Specifically, I replaced
```py
is_boundary_step = self.cnt < start_skipping or self.cnt >= end_skipping
```
with
```py
is_boundary_step = self.cnt < start_skipping-1 or self.cnt >= end_skipping+1
```
in `dits/wanvideo.py`.

## The Example

As an example consider the test
```bash
PYTHONPATH=python python3 -m pytest -s -v --tb=short python/sglang/multimodal_gen/test/server/test_server_1_gpu.py -k wan2_1_t2v_1.3b_teacache_enabled
```
Here, WanVideo defaults to `start_skipping=5`. Since CFG is enabled, each denoising timestep requires two forward passes (one positive CFG, one negative CFG). Consequently, `TeaCacheParams.get_skip_boundaries` sets `start_skipping=10`. We are supposed to stop being a boundary step and start being able to skip forward passes
* Forward pass 9 (self.cnt=9), i.e. the 5th forward pass of the positive CFG branch, should have `is_boundary_step=False`
* Forward pass 10 (self.cnt=10), i.e. the 5th forward pass of the negative CFG branch, should have `is_boundary_step=False`

However, I found that the positive CFG branch had `is_boundary_step=True` (incorrect) while the negative CFG branch had `is_boundary_step=False` (correct).

To test this out, I added the print statements
```py
print(f"\ncurrent_timestep={ctx.current_timestep}")
print(f"Teacache step {self.cnt}: {'NEGATIVE' if self.is_cfg_negative else 'POSITIVE'} CFG branch")
print(f"{is_boundary_step=}, start_skipping={start_skipping}, end_skipping={end_skipping}")
```     
to `dits/wanvideo.py::should_skip_forward_for_cached_states` and ran the above test

On `main`
```md
current_timestep=5
Teacache step 9: POSITIVE CFG branch
is_boundary_step=True, start_skipping=10, end_skipping=100

current_timestep=5
Teacache step 10: NEGATIVE CFG branch
is_boundary_step=False, start_skipping=10, end_skipping=100
```
Here we have `is_boundary_step=True` on the positive CFG branch (incorrect) and `is_boundary_step=False` on the negative CFG branch (correct).

On `teacache-cnt` (my branch)
```md
current_timestep=5
Teacache step 9: POSITIVE CFG branch
is_boundary_step=False, start_skipping=10, end_skipping=100

current_timestep=5
Teacache step 10: NEGATIVE CFG branch
is_boundary_step=False, start_skipping=10, end_skipping=100
```
Here we have `is_boundary_step=True` on the both the positive and negative CFG branches, which is overall correct.

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The logic for `is_boundary_step` appears to have a few issues:

1. **`end_skipping + 1`**: This moves the boundary in the wrong direction. To align a 1-indexed step boundary with the 0-indexed `self.cnt`, you should subtract from the boundary value. Adding 1 allows more skipping at the end of the sequence than the configuration specifies (e.g., if `end_skipping=45`, steps 45 and 46 might still be skipped).
2. **CFG Alignment**: Since `self.cnt` tracks individual forward passes and `start_skipping`/`end_skipping` are doubled when CFG is enabled, using an offset of `1` will result in a "split step" where one pass of a denoising step is a boundary step and the other is skippable. To keep whole steps as boundaries, the offset should ideally be `2` when CFG is active, or the logic should be based on the step index (e.g., `self.cnt // 2`). 
3. **Style**: Please add spaces around the arithmetic operators (e.g., `start_skipping - 1`) to adhere to PEP 8.

```suggestion
        is_boundary_step = self.cnt < start_skipping - 1 or self.cnt >= end_skipping - 1
```
