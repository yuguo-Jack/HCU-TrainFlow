# [Feat] weight_cache: Add protocol version checks

[Upstream PR](https://github.com/sgl-project/sglang/pull/46470) · state: open · merged: False

## Original PR description

## Motivation

The weight cache daemon can stay alive across engine restarts. After an engine upgrade, the daemon may still use the old protocol. Today, the engine sends its cache config without a protocol version check.

This PR implements the **protocol version handshake and compatibility policy** item under **Ops & reliability** in #33522:

> `protocol_version` in the handshake with a documented skew policy

The check rejects incompatible peers before config validation or IPC export. A version error does not trigger a disk fallback.

## Modifications

- Exchange protocol versions, then request weights on the same connection.
- Check the version on direct `fetch_state` requests too, so old clients cannot bypass the check.
- Keep `ping` and `query_config` unchanged.
- Add CPU tests and document the compatibility rules and upgrade steps.

The policy requires equal integer protocol versions. A missing, invalid, or different version is rejected, so peers that predate the handshake need an upgrade. SGLang release numbers may differ if the protocol versions and cache configs match.

## Accuracy Tests

The protocol suite passed all 42 tests on macOS with SGLang's native Apple platform, Python 3.12, and PyTorch 2.14.1:

```bash
PYTHONPATH=python python3 test/registered/unit/model_loader/test_weight_cache_protocol.py
```

The tests cover a real Unix socket exchange between the loader and daemon handler, legacy client requests and daemon replies, invalid versions, and no disk fallback after a version error.

Pre-commit checks passed for all five changed files. GPU cache attachment and model accuracy were not tested.

## Speed Tests and Profiling

Not run. The handshake adds one socket round trip before the weight request. The inference path is unchanged.
