# [PDMux] Add GLM single-layer MTP support

[Upstream PR](https://github.com/sgl-project/sglang/pull/42414) · state: closed · merged: False

## Original PR description

## Motivation

GLM's checkpoint MTP/NextN path needs the complete target prefill state before drafting. Under PDMux, that handoff must occur after the final layer slice, and verification must use the decode attention lane while prefill remains in flight. DP padding must also preserve the real-request layout of preplanned KPool writes.

## Changes

- Capture target hidden states across slices and seed the draft once after the final slice, using a separate batch view and the prefill TP placement, including IDLE participants.
- Route verify masks, eager verify/IDLE attention and accepted Mamba states through the selected decode backend.
- Keep draft forwards eager while retaining target per-stream decode/verify graphs; reset GLM/NextN helper streams when returning to prefill.
- Restrict KPool key/score/cache-location writes to real requests in the existing plan. Preserve the padded query/top-k shape and paged-MQA schedule.
- Support the checkpoint's single-layer EAGLE/NEXTN configuration and reject unsupported speculative algorithms and shapes.

The MTP suite covers draft handoff, stream scheduling, verify metadata and DP-padded KPool writes. Its regression case runs production DP8 MAX_LEN padding and KPool planning for one real request: it plans `[1, 1]` write locations, while padded draft keys previously made the writer require `[2, 1]`. The fix passes only real write rows to the kernel while retaining the DP query shape. Cases also cover draft widths 2 and 4, precomputed gates, dual streams and an unpadded control.

CUDA operations are mocked where the CPU tests require a GPU. Target graph replay, GPU multi-rank accuracy, stress and throughput remain unvalidated.

Launch guidance: [GLM MTP runbook](https://github.com/Li-brua/sglang/blob/feat/glm53-pdmux-mtp/GLM53_FLASH_PDMUX_MTP.md).
