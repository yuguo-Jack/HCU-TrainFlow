# [Spec] Don't charge FROZEN_KV_MTP draft layers against the target KV pool

[Upstream PR](https://github.com/sgl-project/sglang/pull/43850) · state: open · merged: False

## Original PR description

## Motivation

A `FROZEN_KV_MTP` draft (the Gemma-4 assistant) reads the target KV pool and owns no per-token KV; its own runner pool is a 64-token placeholder. But `is_eagle()` includes it, so the pool configurators add its layers to the per-token cell size and shrink the target pool for KV nobody allocates.

On Gemma-4-31B (hybrid SWA, 4-layer draft) the full-attention pool is 11.8% smaller than it needs to be at `--swa-full-tokens-ratio 0.2`. Unlike the EAGLE/STANDALONE accounting added in #28219, a frozen draft has no pool of its own to pay for.

## Modifications

- Add `_target_pays_for_draft_kv()` in `pool_configurator.py`. It replaces the duplicated `is_eagle() or is_standalone()` gate in the default and hybrid-SWA configurators and returns False for `FROZEN_KV_MTP`.
- Keep the charge under `--enable-unified-memory`: the draft worker builds a pool over the virtual id space there.
- `is_eagle()` and its FIXME are untouched.
- Add `TestFrozenKvMtpDraftBudget` (4 cases) to `test_pool_configurator.py`.

## Accuracy Tests
