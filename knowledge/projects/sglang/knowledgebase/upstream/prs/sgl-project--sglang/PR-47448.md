# feat(simulator): add AFD support to sglang-simulator

[Upstream PR](https://github.com/sgl-project/sglang/pull/47448) · state: open · merged: False

## Original PR description

## Motivation

Add AFD support to sglang-simulator for evaluating Attention–FFN disaggregation on CPU, using AIC costs and virtual events while retaining the existing Scheduler and HTTP request lifecycle.

Depends on the AFD implementation in #41646; related discussion: #41648. Use the latest implementation checkout. Compatibility is maintained through interface checks and regression tests rather than source hash locks.

## Modifications

- Keep simulator source code separate from the native AFD implementation. Reuse native control flow at runtime through thin adapters.
- Decouple execution adapters, virtual-event scheduling and cost interfaces so they can evolve independently.
- Model computation, communication, dependencies and resource contention as virtual events.
- Integrate per-request completion times with the Simulator Scheduler.
- Support native-style A/F role configuration and both legacy and compiled-core AIC APIs.
- Provide setup commands, public-AIC reproduction and examples in `tools/sglang-simulator/AFD.md`.

## Accuracy Tests

This PR simulates execution timing; it does not validate numerical model outputs.

- Nine focused CPU tests pass, covering both routing adapters, event scheduling and Scheduler integration.
- Both routing CLIs run successfully. Four public-AIC cases reproduce previous results exactly, with matching CLI and Python API outputs.
- Previously validated synthetic HTTP case: 16 requests and 48 output tokens completed through one prefill and two decode iterations.

Conditional SM103 timing comparison: Qwen3-235B, Direct 8A8F/S2, TRTLLM + NCCL Direct + DeepGEMM.

| Cost database | Cases | Throughput MAPE |
| :--- | ---: | ---: |
| Expanded AIC | 4 | 6.79% |
| Public AIC | 4 | 21.39% |

Expanded AIC includes supplementary operator measurements and interpolation. Uncovered components use explicit formulas. No scale or offset was fitted.

These are fixed-step comparisons with partially matched execution conditions, not full HTTP performance validation.

## Speed Tests and Profiling

| Execution | Observed time |
| :--- | ---: |
| Simulator fixed-step CLI | 1.29–6.69 seconds per case |
| Service benchmark: two warmups and one formal run, service ready | 2.3–9.4 minutes per case |

The execution scopes differ, so these times do not establish an end-to-end speedup. Production inference execution is unchanged.
