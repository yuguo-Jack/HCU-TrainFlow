# [Perf] [AMD] dsa: Enable fused k-pool metadata kernels on HIP

[Upstream PR](https://github.com/sgl-project/sglang/pull/42266) · state: open · merged: False

## Original PR description

## Motivation

The fused k-pool decode, target-verify, and draft-extend metadata kernels are disabled on HIP even when the geometry is supported. Enable the existing kernels on HIP to avoid the separate metadata operations.

## Modifications

- Accept HIP alongside CUDA in the platform eligibility check. Retain the geometry checks and the `SGLANG_EXPERIMENTAL_DSA_KPOOL_METADATA_FUSION` opt-out.
- Register the existing target-verify replay regression for AMD MI35x CI.
- Update the branch against main `7d9bc10493275a371989bd03a13147588005f136`.

## Accuracy Tests

Validated commit `4458382cdfd1b749d409034e5c657233b3e493e2` on MI355X/gfx950, PyTorch `2.11.0+rocm7.2`, HIP `7.2.26015`, and Triton `3.7.0`:

| Check | Result |
| --- | --- |
| Direct decode/verify/draft-extend metadata matrix | 85/85 GPU cases passed |
| Graph replays within that matrix | 170 passed |
| Platform/geometry/flag dispatch combinations | 22/22 passed |
| Registered verify replay regression | Passed, including three input updates/replays |

The direct matrix checks exact integer metadata against independent PyTorch references, guarded output buffers, strided inputs/outputs, variable and zero-length draft extension, and actual row offsets above 2^31 elements. It covers pool sizes 2/4/8/16/32/64 and selected batch, context-length, top-k, and speculative-width boundaries. Production kernel and dispatch sources are unchanged in the validation payload. The harness isolates package initialization/test utilities; it does not execute a full serving process.

Registered regression command on MI355X:

```bash
python test/registered/kernels/ops/attention/test_dsa_kpool_metadata_fusion.py
```

Full-model GSM8K has not been rerun in this quick validation. These are metadata correctness results, not a model-accuracy score.

## Speed Tests and Profiling

No verified end-to-end speed result is claimed in this update. A matched serving comparison remains pending; the original approximate decode-step timing is removed because its raw timing records and full configuration were not recovered.
