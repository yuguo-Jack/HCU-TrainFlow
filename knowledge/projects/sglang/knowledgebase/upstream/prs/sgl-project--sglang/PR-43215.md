# [Test] hunyuan3d: fix mesh Chamfer normalization and isolate sampling RNGs

[Upstream PR](https://github.com/sgl-project/sglang/pull/43215) · state: open · merged: False

## Original PR description

## Motivation

Mesh validation compared a sum of squared nearest-neighbor distances with a linear bounding-box length. Because the units don't match, scaling the reference and generated geometry together changed the verdict: a small, badly shifted mesh could pass while a large, slightly shifted one failed. Point sampling also seeded the global NumPy RNG.

## Modifications

- **Scale-invariant score.** The new score is the bidirectional squared-distance sum (`forward_mse + backward_mse`) divided by the squared reference diagonal `D²`. It stays a sum, with no halving and no square root. Neither mesh is independently aligned or rescaled.
- **Threshold.** The default ratio is now `0.003`. On the Hunyuan3D reference (`D ≈ 2.99`), the old limit `sum ≤ 0.01·D` normalizes to `0.0034`, so `0.003` keeps the previous strictness rather than loosening it about 3×.
- **Isolated RNGs.** Surface sampling uses its own seeded RNGs (`42` and `43` by default) and no longer touches global NumPy state.
- **Input validation.** Parameters and mesh geometry are checked before sampling, so empty, degenerate or non-finite meshes and invalid arguments fail with a clear message.
- **Diagnostics.** On failure, the check reports both directional MSEs, `D`, the normalized score and the threshold.
- **Unchanged.** The signature, 4096 samples, the reference URL, reference caching, transformed Scene merging, planar meshes, and the `None` return value on success.
- **Regression test.** Added in `python/sglang/multimodal_gen/test/unit/test_mesh_correctness.py`, following the current unit test layout.

## Accuracy Tests

**Unit test.** `test_mesh_correctness.py` runs 9 tests with 45 subtests on CPU geometry: real files, trimesh sampling and SciPy KD-trees, with only the reference download mocked. All pass with trimesh 5.1.1 and NumPy 2.3.5 in about 9 s. The pre-fix validator fails the scale subcases below.

| Plane scale | Normal offset / D | Old `S ≤ 0.01·D` | New `S / D² ≤ 0.003` | Normalized score |
| --- | --- | --- | --- | --- |
| 0.01 | 0.25 | pass (wrong) | fail | 0.125078 |
| 0.01 | 0.08 | pass (wrong) | fail | 0.012878 |
| 1000 | 0.02 | fail (wrong) | pass | 0.000878 |

The tests also cover:
- generated-only scale and translation errors;
- repeatable diagnostics, and global RNG state left unchanged;
- an inclusive threshold;
- transformed multi-component Scenes;
- invalid arguments;
- empty, degenerate and non-finite geometry.

**Real meshes.** The fixed reference GLB is `c7d02360…`. Each GLB was replayed through `validate_mesh_correctness` as-is, with no conversion, alignment or rescaling:

| Mesh | Normalized score | Threshold | Result |
| --- | --- | --- | --- |
| Reference self-check | 0.000114 | 0.003 | pass |
| Real `hunyuan3d_shape_gen` API output (`tencent/Hunyuan3D-2@9cd649ba`) | 0.000133 | 0.003 | pass |

The real output passes with about 22× margin.
