# [Rust] Reject non-generation models when the Rust server starts

[Upstream PR](https://github.com/sgl-project/sglang/pull/42621) · state: closed · merged: False

## Original PR description

## Motivation

`SGLANG_RUST_SERVER=1` only serves generation models. Embedding, reward and classification outputs go to the Python detokenizer, which Rust mode does not start, and the Rust server has no `/encode` route. Nothing rejects such a model today, so the launch fails later and less clearly:

- On current main, `/model_info` hard-codes `is_generation: true`, so the startup warmup sends a text `/generate` to the embedding model. Locally (gte-Qwen2-1.5B-instruct, triton attention), the scheduler then crashed with `AssertionError: q.shape[0] <= kv_indptr.shape[0] - 1` in the attention backend, and the server went down 219 s after launch.
- Once `/model_info` reports the real `is_generation` (#42622), warmup takes the embedding path and posts to `/encode`, which the Rust server doesn't have. Locally that returned 404, the warmup failed with a bare `AssertionError` (empty message), and the server exited.
- With `--skip-server-warmup`, neither failure happens at startup, so the server would come up unable to serve the model (from reading the code; not run).

## Modifications

- `RustServer.launch` raises a `RuntimeError` for a non-generation model before it loads the extension or binds a port. The error names the unsupported model kinds and tells the user to unset `SGLANG_RUST_SERVER`.
- The check runs where the Rust server starts, after the model worker has loaded weights. That matches the existing multimodal gate, but it does not fail before weight loading.
- Test stubs gain `is_generation=True`, plus a test that a non-generation model is rejected before the extension loads.

This is independent of #42622. With both, the clear error replaces the `/encode` warmup failure.

#36986 proposes OpenAI embedding support for the Rust server. If it lands, this check should let embedding models through and keep rejecting the other kinds.

## Tests

- `python -m pytest -q test/registered/unit/entrypoints/test_rust_server_dp_ports.py test/registered/unit/multimodal/rust/shared/test_rust_server_extension.py`: 17 passed.
- `pre-commit run --from-ref origin/main --to-ref HEAD`: all hooks pass.
- Real launch on one A100, `SGLANG_RUST_SERVER=1 python -m sglang.launch_server --model-path Alibaba-NLP/gte-Qwen2-1.5B-instruct --is-embedding --attention-backend triton --sampling-backend pytorch`:
  - With this change (also merged with #42622): the scheduler raises `RuntimeError: SGLANG_RUST_SERVER=1 does not support non-generation (embedding, reward, or classification) models. ...` about 70 s after weight load, and the server exits 132 s after launch.
  - On main without it: the scheduler crash above (exit at 219 s). With only #42622: the `/encode` 404 warmup failure (exit at 238 s).
- Not run: `--skip-server-warmup` without this change.
