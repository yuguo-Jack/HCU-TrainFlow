# [Doc] [NPU] cookbook: add A3 deployment scenarios to GLM-5.2

[Upstream PR](https://github.com/sgl-project/sglang/pull/39321) · state: closed · merged: False

## Original PR description

> **Status:** the docs and config are complete and pass all local checks. On-hardware verification on A3 Series full nodes is pending (see Accuracy Tests below).

## Motivation

Refs Ascend/sglang#1211.

The GLM-5.2 cookbook has no Ascend NPU option, although the [Ascend NPU GLM-5.2 tutorial](https://docs.sglang.io/docs/hardware-platforms/ascend-npus/model-deployment/tutorials/glm_5_2) documents a single-node PD mixed recipe and a 1P1D PD disaggregation recipe. This PR adds both to the deploy panel, so you can pick **A3 Series** and get a command for each scenario.

## Modifications

### Commit 1: GLM-5.2 A3 data (`glm-5.2.jsx`, `GLM-5.2.mdx`)

| Deploy selection | Scenario | Key flags |
|---|---|---|
| A3 · W8A8 · Balanced · Single Node | 1×A3 PD Mixed (16 dies) | `--tp-size 16`, DeepEP auto, NEXTN 3-1-4 |
| A3 · W8A8 · High-Throughput · **PD Prefill (2 nodes)** | 2×A3 1P1D, prefill node | `--tp-size 16 --attn-dp-size 4`, DeepEP normal, graph capture off, NEXTN 1-1-2 |
| A3 · W8A8 · High-Throughput · **PD Decode (2 nodes)** | 2×A3 1P1D, decode node | `--tp-size 16 --attn-dp-size 16 --ep-size 16`, DeepEP low_latency, NEXTN 3-1-4 |

- Checkpoint: `Eco-Tech/GLM-5.2-w8a8` (msModelSlim W8A8, 774 GB; `--quantization modelslim`). The W8A8 chip appears only on A3. The checkpoint's MTP layer (layer 78) is stored as FLOAT per its `quant_model_description.json`, so every recipe passes `--speculative-draft-model-quantization unquant`.
- The PD roles sit in the **Nodes** row because each role is a single-node server of its own, so neither fits a `multi-2` cell. The router command is in the page text.
- The recipes are transcribed from the tutorial. Three of its spellings have moved on in `main`, so the cells carry the current ones: `--moe-dense-tp` → `--moe-dense-tp-size` (the old name no longer parses), plus two that still parse but are deprecated — `--disable-cuda-graph` → `--cuda-graph-backend-{decode,prefill} disabled` and `--dp-size N --enable-dp-attention` → `--attn-dp-size N` (#41818).
- `dockerImages.a3` is `quay.io/ascend/sglang:v0.5.22-cann9.1.0-a3`, verified on an A3 card to parse all three cells: the tutorial's pinned `cann9.0.0-a3-v0.5.16` predates two of them (`--cuda-graph-backend-*` landed 2026-08-26, `--attn-dp-size` on 2026-09-30), and the `main-cann9.0.0-a3` daily was still serving a 2026-09-23 build as of 2026-10-21, which rejects `--attn-dp-size`. The PD roles use host networking, and the config adds `NETWORK_IFACE` / `PREFILL_IP` placeholders for `HCCL_SOCKET_IFNAME` and `ASCEND_MF_STORE_URL`.
- On A3, the Playground hides the cards that would emit CUDA-only flags (Attention, PD Disagg, HiCache, and the MoE EP degrees) and greys out the EAGLE presets with a reason: the NPU path is NEXTN.
- Page: the install section notes the CANN image, and Configuration Tips gains an Ascend section with a topology table, weights, host preparation, cross-node networking, the router command, and the verification status.
- All three cells are marked `verificationStatus: "in-progress"`, the same as the Kimi-K3 A3 cell in #35508.

### Commit 2: Playground fix (`_playground.jsx`, `authoring-reference.md`)

The A3 PD Prefill / PD Decode cells carry their own `--disaggregation-*` flags. The PD Disagg card is hidden on A3, but `applyAllDeltas` still ran its `apply`, which clears the `--disaggregation-*` family and then re-adds the role picked on the card. On A3 the card's role stays "off", so **the Playground command silently lost `--disaggregation-mode`** and turned the role recipe into a PD mixed one. The Deploy panel was not affected.

The fix skips an axis whose axis-level `showWhen(base)` hides its card, using the same predicate the renderer uses. There is one line of logic; the rest is the comments that state the rule, plus the matching paragraph in `authoring-reference.md`. The change sits outside the `MIRROR` block the two engines keep identical, so `_deployment.jsx` needs no counterpart.

**No existing page changes behavior.** Of the 19 configs on `main` that declare a PD card, only Kimi-K3 and GLM-5.2 have cells carrying `--disaggregation-*` flags. Kimi-K3 gates its card on `pdMode`, the very dimension its PD cells match on, so the card is on screen whenever such a cell is selected and the skip never fires. GLM-5.2 reaches its A3 PD cells through the `nodes` dimension while the card is hidden on A3, which is why it is the only config the skip affects.
