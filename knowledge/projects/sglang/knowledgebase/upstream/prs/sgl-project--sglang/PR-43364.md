# [MoE][gfx950] Pick the fp8_w8a8 default tile by routed rows per expert

[Upstream PR](https://github.com/sgl-project/sglang/pull/43364) · state: open · merged: False

## Original PR description

## Motivation

On MI355X (gfx950) there are no tuned Triton fused-MoE config files, so every fp8_w8a8 per-channel / per-tensor MoE that runs through Triton uses `get_default_config`. That covers `--quantization w8a8_fp8`, Gemma4 FP8, and FP8 MoE with AITER off. The default branches only on `M` vs `E`:

```python
config = {"BLOCK_SIZE_M": 128, "BLOCK_SIZE_N": 256, "BLOCK_SIZE_K": 128, "GROUP_SIZE_M": 32, "num_warps": 8, ...}
if M <= E:
    config = {"BLOCK_SIZE_M": 64, "BLOCK_SIZE_N": 128, "BLOCK_SIZE_K": 128, "GROUP_SIZE_M": 1, "num_warps": 4, ...}
```

`BLOCK_SIZE_M` is also the `moe_align_block_size` alignment: every touched expert is padded to a whole block, and padded blocks still run the full K loop. What matters is therefore the number of rows each expert receives, `M * topk / E`, which this rule never looks at.

## Modifications

On gfx950 only, the fp8_w8a8 (no block quant) default picks the tile by routed rows per expert:

| `M * topk / E` | BLOCK_M | BLOCK_N | BLOCK_K | warps | stages |
|---|---|---|---|---|---|
| < 8 | 16 | 64 | 128 | 4 | 2 |
| 8 – 24 | 32 | 128 | 128 | 4 | 2 |
| 24 – 48 | 64 | 128 | 128 | 4 | 3 |
| ≥ 48 | 128 | 128 | 128 | 8 | 2 |

`BLOCK_SIZE_K` stays 128, as in both branches it replaces, so the K reduction order is unchanged and the output is bit-identical. Other architectures, block-wise fp8, tuned config files and deterministic inference are untouched. No new environment variable.

The tiers were selected from a sweep of 48 tiles (`BLOCK_M` {16, 32, 64, 128} × `BLOCK_N` {64, 128, 256} × warps {4, 8} × stages {2, 3}, `BLOCK_K` = 128) on three MoE shapes × 14 batch sizes, maximizing the worst-case speedup over the current default and then the geometric mean.

## Accuracy Tests

- Outputs are bit-identical to `main` (`torch.equal`) at all 88 shape × batch points below.
- New `test/registered/unit/layers/moe/test_fused_moe_default_config.py` (CPU): tier boundaries, `BLOCK_SIZE_K` = 128 in every tier, and unchanged defaults off gfx950 and for block-wise quant.

## Speed Tests and Profiling

MI355X (gfx950), ROCm 7.2.0, torch 2.9.1, Triton 3.7.0. `fused_moe` with `use_fp8_w8a8=True, per_channel_quant=True`, `triton.testing.do_bench_cudagraph`, minimum of 3; `main` and this PR run in separate processes. This run is independent of the sweep, uses 22 batch sizes (most of them not in the sweep), and adds a shape that was not used to select the tiers.

| Shape (E, top_k, N, K) | Geomean speedup over 22 batch sizes | Worst point |
|---|---|---|
| Gemma4 (128, 8, 704, 2816) | 1.074x | 0.995x (M=96) |
| Qwen3.5-35B-A3B (256, 8, 512, 2048) | 1.050x | 1.000x |
| Qwen3-Next-80B (512, 10, 512, 2048) | 1.049x | 1.011x |
| Qwen3-30B-A3B (128, 8, 768, 2048), not used for selection | 1.056x | 0.993x (M=96) |

Selected points (µs, `main` → this PR):

| M | Gemma4 | Qwen3-30B-A3B (held out) |
|---|---|---|
| 1 | 35.2 → 32.6 (1.08x) | 31.4 → 29.1 (1.08x) |
| 8 | 65.2 → 61.0 (1.07x) | 57.5 → 53.4 (1.08x) |
| 32 | 132.3 → 127.6 (1.04x) | 107.2 → 104.6 (1.03x) |
| 128 | 153.5 → 153.1 (1.00x) | 123.0 → 122.3 (1.01x) |
| 256 | 194.3 → 163.6 (1.19x) | 145.7 → 128.5 (1.13x) |
| 512 | 212.3 → 184.1 (1.15x) | 160.3 → 144.3 (1.11x) |
| 1024 | 243.2 → 225.6 (1.08x) | 190.0 → 182.6 (1.04x) |
| 4096 | 595.6 → 553.6 (1.08x) | 453.2 → 411.6 (1.10x) |

Only gfx950 was measured, so the change is gated to it. Tuned MI355X config files, if added later, still take precedence over this default.
