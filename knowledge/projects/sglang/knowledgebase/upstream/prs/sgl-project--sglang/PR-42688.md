# [Fix] Mask unused ReplaySSM history before checkpoint arithmetic

[Upstream PR](https://github.com/sgl-project/sglang/pull/42688) · state: open · merged: False

## Original PR description

## Motivation

The compact ReplaySSM checkpoint kernel reads the whole history ring, then gives unused entries zero decay. Reused ring storage can contain NaN or infinity, and multiplying those values by zero still contaminates the checkpoint. A tracked checkpoint can also be corrupted by a nonfinite update that belongs to the active history but lies after the tracked prefix.

For example, a ring with four valid updates and a stale NaN in its fifth entry should produce the same checkpoint as clean unused storage. A checkpoint tracking the first three updates should remain finite when only the fourth update is nonfinite.

## Modifications

Mask unused history loads before arithmetic, and mask keys and updates to the tracked prefix before its matrix products. Nonfinite values within the active history still propagate; this prevents unrelated history from contaminating checkpoints rather than sanitizing valid inputs or existing state.

Add synthetic regression tests for all history fields, NaN and positive/negative infinity, ring wraparound, residual modes, shorter tracked prefixes, empty history, and untouched/null slots.

## Accuracy Tests

All 111 regression cases passed on a CUDA GPU (no failures or skips), using `pytest -q test/registered/attention/unittests/gdn/test_gdn_replayssm_compact_commit.py`. File-scoped pre-commit and Python syntax checks also passed.

## Speed Tests and Profiling

Not benchmarked for this revision. The change adds load/operand masks within the existing checkpoint kernel and does not add a kernel launch.

### reviews

- ch-wan · COMMENTED · 2026-10-07T07:10:42Z · [source](https://github.com/sgl-project/sglang/pull/42688#pullrequestreview-5438835179)

Reproduced the issue and checked the fix independently on H200 (torch 2.14.1+cu130, triton 3.8.0), on main f47d89564d with this PR's kernel change applied. The kernel file has not changed on main since this PR's base.

- **Kernel test.** `test_gdn_replayssm_compact_commit.py` against unpatched main: 84 failed, 27 passed. With this PR: 111 passed.
- **End to end.** Qwen3.8-27B (BF16) on one H200 with `--kv-cache-dtype fp8_e4m3 --attention-backend flashinfer`, MTP (`--speculative-algorithm EAGLE --speculative-num-steps 3 --speculative-eagle-topk 1 --speculative-num-draft-tokens 4`) and `--enable-linear-replayssm-spec`. Test-only instrumentation wrote a single NaN into one request's hidden state at one verify step; each run then served 384 chat and shared-prefix requests. Requests with any nonfinite output logprob:

| seed | main | this PR |
| --- | --- | --- |
| 11 | 5 | 1 |
| 12 | 7 | 1 |
| 13 | 5 | 1 |

On main, every extra bad request sits in the same request-pool slot as the injected one, and first turns nonfinite at the first GDN layer after the injection point. The stale ring entries poison each later request that is assigned that slot. With this PR, the NaN stays in the request it was injected into.

So on main, one transient NaN anywhere upstream becomes recurring NaNs for unrelated later requests. That may be worth a line in the description: the fix matters to anyone serving GDN models with `--enable-linear-replayssm-spec`.

The verify kernel and the decode ring kernel already mask their history loads, so the compact commit is the only place that needed this.

LGTM once CI passes.
