# [Perf] [NPU] mimo: fold attention_value_scale into o_proj weights

[Upstream PR](https://github.com/sgl-project/sglang/pull/40890) · state: open · merged: False

## Original PR description

## Motivation

MiMo-V2.5-Pro defines a per-model `attention_value_scale` that the attention forward applies to V before writing the KV cache and before the attention output (`v = v * v_scale`). On NPU this materializes as an extra `aclnnMuls` kernel per layer in every decode/verify step — ~2 ms/layer on MiMo-V2.5-Pro EP6 profiling (~8% of the attention section).

Attention is linear in V:

    softmax(qk) @ (s · V) ≡ s · (softmax(qk) @ V)

so multiplying the layer's `o_proj.weight` by `s` at load time reproduces the runtime `v * v_scale` exactly, and the per-token kernel disappears.

## Modifications

- Add `MiMoV2ForCausalLM._fold_attention_value_scale_into_o_proj`, called at the end of `load_weights`: for each attention layer with a `v_scale`, multiply `o_proj.weight.data` by `attention_value_scale` (when the config defines one) and clear `attn.v_scale` so the runtime multiply is skipped.
- Only floating-point o_proj weights are folded (MiMo FP4 checkpoints keep o_proj in bf16, so this covers the shipped configurations); a quantized o_proj keeps the runtime multiply and logs a warning.
- The KV cache now stores unscaled V. This stays self-consistent because every consumer of V (decode, target-verify, DFlash draft KV materialization) goes through the same layer's (folded) o_proj.
- MTP draft (`mimo_v2_nextn.py`) and DFlash draft (`dflash.py`) have independent weight loading and their own v_scale handling; they are unaffected.

## Speed Tests and Profiling

MiMo-V2.5-Pro, NPU, EP6 decode profiling: the per-layer `aclnnMuls` multiplier is eliminated (~2 ms/layer, ~8% of the attention section in the profiled window). No new kernels are introduced; the fold is a one-time load-time weight transform.
