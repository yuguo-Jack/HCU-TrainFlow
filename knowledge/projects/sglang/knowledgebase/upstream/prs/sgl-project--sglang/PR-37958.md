# [Perf] prefill-cuda-graph: Make prefill shared-read completion explicit and default-on

[Upstream PR](https://github.com/sgl-project/sglang/pull/37958) · state: closed · merged: True

## Original PR description

## Summary

Prefill publishes the shared-read-done event by default. With overlap scheduling, the next step's writes to `req_to_token` and `full_to_swa` then wait only for prefill metadata preparation instead of the whole prefill forward. It is enabled only where the prefill forward reads none of those tables after the event.

## Changes

- `SGLANG_ENABLE_PREFILL_WAR_READ_DONE` defaults to `True`; `0` keeps the whole-forward barrier for prefill.
- `AttentionBackend.resolve_prefill_shared_read_ends` returns a batch's prefill read end, and the runners pass it to `maybe_publish_prefill_shared_read_done`. With `build_snapshot`, a backend first snapshots its late reads in `_prepare_prefill_shared_reads`; full graphs and breakable graphs with captured metadata use the static `shared_read_ends`.
- DeepSeek V4 builds its sparse-prefill chunk cache in that hook instead of in the first layer, and the hook and the forward share one `_use_sparse_prefill` gate. The `prefill_shared_reads_snapshotted` flag is removed.
- `HybridAttnBackend` forwards the hook to its prefill backend.
- `HybridLinearAttnBackend` no longer calls the removed `prepare_prefill_shared_read_snapshot`, which was a no-op for it.

## Where prefill keeps the whole-forward barrier

- DeepSeek V4.1: the low-ratio indexer reads `req_to_token` in every layer.
- DeepSeek V4 with HiSparse: `full_to_hisparse` is translated in every layer.
- DSPARK: the draft KV inject reads the SWA mapping after the target prefill.
- Dots: an eager prefill may rebuild metadata from the live tables when DP padding changes the batch.
- DeepSeek V4 with CP, a request window, or a breakable prefill graph with captured metadata.
- HiCache, a HiCache storage backend, or LMCache: write-through and offload copy a stashed chunk's KV ordered only behind the schedule stream, so they could copy it before the forward writes it.
- EAGLE-family, NGRAM and UNO, as before.

## Behavior for existing users

- On CUDA with overlap scheduling, EXTEND batches with no speculative decoding or with DFLASH now publish the event for:
  - `trtllm_mha`, the default attention backend for MHA models on SM100, directly or through the hybrid and two-batch-overlap wrappers;
  - DeepSeek V4 (not V4.1) without HiSparse, in eager or piecewise prefill.
- Decode, other attention backends and non-CUDA platforms are unchanged.
- With `SGLANG_ENABLE_PREFILL_WAR_READ_DONE=1` set explicitly, DSPARK, DeepSeek V4.1, HiSparse and Dots no longer take the prefill fast path.

## Verification

- Unit: `test_prefill_shared_read_done.py`, `test_prefill_cuda_graph_padding.py`, `test_prefill_cuda_graph_runner.py`, `test_dots_hybrid_backend.py`, `test_deepseek_v4.py`.
- Accuracy: `test_gpt_oss_4gpu_mxfp4.py` (`trtllm_mha`, GPQA), `test_deepseek_v4_flash_fp4_b200.py` and `test_deepseek_v4_flash_fp4_b200_trtllm.py` (GSM8K), `test_basic_sanity_dspark.py`.

[by Claude Code] **Severity: style | Confidence: High**

**Issue**
The `use_sparse_prefill` test above copies the sparse-prefill test in `_forward_attention`, and the two already differ. With `--dsv4-attn-backend trtllm`, `_forward_attention` returns through `_forward_trtllm` first, so nothing reads `sparse_prefill_cache`. This hook still builds it. `SGLANG_OPT_FLASHMLA_SPARSE_PREFILL` defaults to True, so after this PR every trtllm-backend prefill builds an unused cache.

**Why it matters**
Returning `PRE_REPLAY` is safe only while both tests agree. If the forward takes the sparse path after this hook skipped the build, the lazy build in `_forward_prefill_sparse` reads `req_to_token` and `full_to_swa` after the event.

**Fix**
Move the test into one helper used by both sites, and include `not self.trtllm_attn`.

File: `python/sglang/srt/environ.py` · line None

[by Claude Code] **Severity: style | Confidence: High**

**Issue**
The PR deletes `SGLANG_ENABLE_PREFILL_WAR_READ_DONE` without an entry in `_DEPRECATED_ENVS`, so a launch that still sets it gets no warning and the variable silently does nothing. The InferenceX DSV4 AgentX recipes set it to `"1"` today, including the c960 recipe used for this PR's A/B. A user who set it to `0` to keep the coarse barrier now gets the fast path with no notice.

**Fix**
Register it the same way as `SGLANG_ENABLE_UNIFIED_RADIX_TREE`: `"SGLANG_ENABLE_PREFILL_WAR_READ_DONE": _DeprecatedEnv(note="Prefill read-done is on by default; set SGLANG_FORCE_PREFILL_COARSE_WAR_BARRIER=1 to disable it.")`.
