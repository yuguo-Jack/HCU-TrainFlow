# [Feat] moe: support bounded SiTU MXFP4 launches

[Upstream PR](https://github.com/sgl-project/sglang/pull/46083) · state: open · merged: False

## Original PR description

## Motivation

Large mixed-prefill batches can exhaust the workspace of a single SiTU MXFP4 launch. This came up while serving K3 on B300.

## Changes

Add `SGLANG_MXFP4_MOE_MAX_TOKENS_PER_LAUNCH` to bound each launch. Activations, scales, routing and output use the same row slice, including the tail. The default is `0` (disabled); the deferred path keeps its existing behavior.

## Validation

The actual launch function passes CPU mocked-kernel checks for disabled caps, chunk boundaries, tail rows, packed/tuple inputs and BF16 output.

A B30Z GPU follow-up on this commit also passes for MXFP4 weights + MXFP8 activations: caps 32 and 8192 produce `[32,32,1]` and `[8192,1]`, matching the unchunked reference exactly for the seeded fixture. Tail, destination-pointer and row-guard checks pass; peak Torch allocation is ~287 MiB. [Configuration and scope](https://github.com/sgl-project/sglang/pull/46083#issuecomment-6382618709). This exercises the isolated actual function/helper with a real FlashInfer CUDA quantization adapter; SGLang's native quantizer, full-model/distributed behavior and performance remain unverified. The attempted BF16 activation combination has no matching kernel on the tested FlashInfer runtime.
