# fix(bench): honor CUDA decode profiling step limits

[Upstream PR](https://github.com/sgl-project/sglang/pull/30914) · state: open · merged: False

## Original PR description

## Motivation

`benchmark.one_batch` starts `CUDA_PROFILER` with
`cudaProfilerStart()`, but `start_profile()` returned `None`.
The decode loop therefore skipped `stop_profile()` and ignored
`--profile-steps`.

For example, `--profile-start-step 32 --profile-steps 1` captured all
remaining decode steps instead of one step.

## Modifications

- Return a sentinel after `cudaProfilerStart()` succeeds.
- Stop CUDA profiling after the requested decode steps.
- Keep CUDA captures out of the Torch trace export path.
- Add CPU unit tests for CUDA start/stop and Torch trace export.

## Accuracy Tests

N/A. This change only affects profiling control flow.

## Speed Tests and Profiling

Tested on NVIDIA H200 with a 36-layer Qwen2 model:

| Metric | Before | After |
|---|---:|---:|
| `cudaGraphLaunch` calls | 31 | 1 |
| `prepare_varlen_num_blocks_kernel` instances | 31 | 1 |

The result contains one decode step as requested.
