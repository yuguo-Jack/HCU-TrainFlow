# [KVCache] [DSV4] Add Direct INT4 KV cache with 29.27% higher token capacity.

## Motivation

DeepSeek V4 Flash uses persistent KV caches for sliding-window attention (SWA), C4, and C128. The native FP8 layout uses 584 bytes per latent KV row, which limits KV-cache capacity for long-context workloads.

This PR adds an optional 368-byte Direct INT4 KV-cache layout for the target worker. The 448 NoPE dimensions are stored as signed INT4 with group32 E4M3 scales, while the 64 RoPE dimensions remain in BF16. The format does not use a Hadamard transform and is enabled with:

```bash
--kv-cache-dtype int4
```

EAGLE draft workers continue to use FP8 KV cache by default.

 > This work is part of [KVBit](https://github.com/yuyu5333/kvbit), a broader effort to develop reusable low-bit KV-cache formats, reference codecs, and serving-backend integrations. This PR focuses on the DeepSeek V4 SM90 Direct INT4 specialization.

<!-- Describe the purpose and goals of this pull request. -->

## Modifications

- Add `int4` support to `--kv-cache-dtype` for DeepSeek V4 on CUDA SM90.
- Add a 368-byte packed KV row format (a 384-byte aligned variant is selectable via `SGLANG_DSV4_INT4_LAYOUT`):
  - 224 bytes of signed INT4 NoPE values;
  - 14 bytes of group32 E4M3 scales using nearest rounding;
  - 2 padding bytes;
  - 128 bytes of BF16 RoPE values.
- Define the packed layout as a generated ABI shared by Python, C++, and tests: `scripts/kvbit/generate_dsv4_layout.py` emits `kvbit_dsv4_format.json`, `kvbit_dsv4_layout_constants.py`, and `packed_layout.h`, and a pre-commit hook re-runs the generator in check mode.
- Add CPU reference codecs for the packed format in `kvbit_dsv4_codec.py`: encode, decode, repack without requantization, and an attention-equivalence validator.
- Store SWA, C4, and C128 KV directly in the packed format without a native shadow cache or decode scratch buffer.
- Add an SM90 AOT sparse-decode operator for the packed INT4 format, structured as an INT4 producer stage, shared attention math, and a sink-inclusive split-K combine pass.
- Interleave the producer's token stores across shared-memory banks, removing nearly all shared-store bank conflicts in the main decode kernel.
- Harden warpgroup synchronization inside the decode kernel: use unaligned named barriers across DSV4 INT4 warpgroups, and add a two-phase softmax-buffer rendezvous so consumers synchronize before softmax state is reused.
- Accept TP-padded query-head geometry in the INT4 startup validation.
- Add a `SGL_KERNEL_DSV4_INT4_ONLY` CMake option that configures only the FlashMLA dependencies, enabling focused builds of the INT4 extension.
- Keep target and draft KV-cache dtype selection independent.
- Reject unsupported model, hardware, HiSparse, hierarchical-cache, and disaggregation configurations.
- Add unit tests for the packed codec, the generated layout ABI, runtime helpers, memory pools, dtype routing, and sparse attention results.

### KV capacity

| Mode | Persistent row | Maximum tokens |
|---|---:|---:|
| Native FP8 | 584 B | 6,157,312 |
| Direct INT4 | 368 B | 7,959,296 |

Direct INT4 increases KV-cache capacity by 1,801,984 tokens, or 29.27%, under the same static-memory configuration.
