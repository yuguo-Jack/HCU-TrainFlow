# [Perf] [AMD] dsv4: fold the padded-weight zeroing into the fused append kernel

[Upstream PR](https://github.com/sgl-project/sglang/pull/36530) · state: open · merged: False

## Original PR description

## Motivation

On the per-rank fused shared-slot path, `_post_process_topk_ids` ends with a
`_zero_topk_weights_padded_region` launch, once per MoE layer, that exists only
to undo what the append kernel left behind.

`_fused_append_remap_shared_experts_deepep_kernel` already takes
`num_token_non_padded`, but its `HAS_PADDING` branch only fills the routed
**ids** for padded rows — it stores the gate's weights untouched, and writes the
shared slots unconditionally at `scale_factor`. So a padded row leaves the
append with live weights, and a second full pass over `topk_weights` is needed
to zero them.

## Modification

Zero them in the append instead, on both the routed and the shared tile. The row
is already in registers there, so it costs a `tl.where` on each tile, and a
padded row now leaves that kernel fully inert.

The trailing pass is then redundant whenever the fold was active, so it is
skipped in that case. It still runs otherwise, which is required: the append
only receives `num_token_non_padded` when the fold is active, so `HAS_PADDING`
is false on every other path and those rows are still zeroed by the trailing
pass exactly as before.

16 lines across two files.

One kernel launch per MoE layer disappears, along with a read and a write of
`topk_weights` that the preceding kernel does for free.

DeepSeek-V4-Pro, MI355X (gfx950), TP8 + DP8 attention + EP8/MoRI with
`--enforce-shared-experts-fusion`. Rank-0 device kernel time over a profiled
window of 5 decode steps; both arms are the same image and differ only by this
commit:

| kernel | base calls | base us | patch calls | patch us |
| ------ | ---------: | ------: | ----------: | ------: |
| `_fused_append_remap_shared_experts_deepep_kernel` | 290 | 1388.9 | 290 | 1256.4 |
| `_fill_padded_rows_kernel` | 320 | 1348.2 | 30 | 96.3 |
| total | 610 | 2737.1 | 320 | 1352.7 |

The pad-fill count drops by exactly 290, the same as the append count, which is
the fold engaging one-for-one. That is 58 fewer launches and ~250 us per decode
step. The 30 remaining calls are the paths where the fold does not apply, and
they are unchanged.

**This is not a throughput change, and should not be read as one.** The whole
MoE routing stage is ~1% of device kernel time in this configuration, so a
saving of this size is well inside run-to-run noise:

| metric | base | patch |
| ------ | ---- | ----- |
| output throughput | 293.97 tok/s | 295.89 tok/s |
| total throughput | 4997.57 tok/s | 5030.15 tok/s |
| mean TPOT | 115.75 ms | 115.66 ms |

It removes redundant work, not a bottleneck.

## Accuracy

The risk here is a padded row escaping with a live weight, which is wrong output
rather than an error, so accuracy is the check that matters.

GSM8K, 1319 questions, parallel 1319:

| arm | accuracy | invalid |
| --- | -------- | ------- |
| base | 0.948 | 0.000 |
| patch | 0.951 | 0.000 |

The gap is four questions out of 1319, which is inside run-to-run noise for this
benchmark; the point is that the padded rows stayed inert, not that the change
improves accuracy.

#### 1. 🟠 Should fix: Env var SGLANG_MORI_NO_PAD_MASK weight behavior changes on per-rank path
`python/sglang/srt/layers/moe/topk.py:2652`

With `_skip_hip_pad_mask` set, the per-rank path still has `_fold_pad_into_append` true, so the deepep kernel now receives `num_token_non_padded` and zeroes routed/shared weights on padded rows, whereas before they were preserved. #### 2. 🟠 Should fix: Gating change untested for per-rank shared-slot path
`python/sglang/srt/layers/moe/topk.py:2661`

The new gating makes `_fold_pad_weights_into_append` true on the HIP+aiter+per-rank path, dropping the trailing `_zero_topk_weights_padded_region` and relying on the kernel; only the kernel is tested directly, not `_post_process_topk_ids`/`select_experts` with `use_per_rank_shared_slots`. A wiring regression forwarding `num_token_non_padded` would leave live weights on padded shared slots uncaught. Add a test exercising the full path.

 Thanks @peymanr / PR Pundit — good catches, all addressed in 239e0322a7.

  1 (🟠) NO_PAD_MASK weight behavior on the per-rank path — fixed, not just confirmed. You're right that this was an
  unintended change. The per-rank (MoRI/DeepEP) id fold engages even under SGLANG_MORI_NO_PAD_MASK because aiter needs
  in-range ids, so aliasing the weight fold to the id fold silently zeroed padded weights that the flag means to leave
  live. The id fill and the weight zeroing are now decoupled in the deepep kernel via a new ZERO_PAD_WEIGHTS constexpr,
  and the gate is _fold_pad_weights_into_append = _fold_pad_into_append and not _skip_hip_pad_mask. So under NO_PAD_MASK
  the padded ids are still filled but the weights stay live — exact pre-PR semantics on both paths.

  2 (🟠) Per-rank gating untested — added. New test_post_process_per_rank_pad_weight_gating drives the full
  _post_process_topk_ids on the HIP+aiter per-rank path (patched globals + get_parallel) for both NO_PAD_MASK values and
  n_valid in {0, m/2, m}: asserts padded routed/shared weights are zeroed when the flag is off, left live (routed
  passthrough, shared 1.0) when on, and that padded ids are filled in both cases. Verified it fails on the pre-fix
  aliasing and passes on the fix (ran on MI355X; full file 7 passed / 57 subtests).

  3 (🔵) Docstrings — updated. Kernel, wrapper, and test-module docstrings now document the padded-weight contract and
  the ZERO_PAD_WEIGHTS vs. id-fill split; dropped the "fully inert" overstatement (padded rows still carry live ids).

  4 (🔵) Redundant alias — resolved by keeping it meaningful rather than removing it. Collapsing to a single symbol would
  reintroduce finding 1 (the per-rank path needs the id fold on but the weight fold off under NO_PAD_MASK).
  _fold_pad_weights_into_append now genuinely differs from _fold_pad_into_append on exactly that case, and the deepep
  call passes both explicitly (num_token_non_padded for the fill, zero_pad_weights for the zero). Fixed the misleading
  trailing-skip comment to name the real gate.
