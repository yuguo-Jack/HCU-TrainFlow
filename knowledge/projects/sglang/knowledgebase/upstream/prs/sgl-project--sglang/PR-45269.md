# [Feat] [AMD] docker: Release ROCm 10.1 for gfx942 / gfx950 in parallel with ROCm 10.0

[Upstream PR](https://github.com/sgl-project/sglang/pull/45269) · state: closed · merged: False

## Original PR description

## What

Build ROCm 10.1 images for MI30x (gfx942) and MI35x (gfx950) in the nightly ROCm 10 workflow, alongside the ROCm 10.0 ones. This follows #42699, which did the same for gfx1250.

| GPU_ARCH | Tag |
|---|---|
| `gfx942-rocm1010` | `v<version>-rocm101-mi30x-<date>` |
| `gfx950-rocm1010` | `v<version>-rocm101-mi35x-<date>` |

Nothing that pulls `rocm10-*` changes. The MI355X disagg nightly, the only workflow that picks the newest image by tag, matches `-rocm10-mi35x-` exactly, so it keeps picking the 10.0 image.

## Notes for the reviewer

- The new stages build on `rocm1000-base`, which already pins one stack per flavor suffix since #42699 (ROCm 10.1.0, torch 2.12.0, torchvision 0.27.0, torchaudio 2.11.0, the SDK's Triton `3.8.0+git669b31ac`). So `srt_hip_rocm101`, the torch constraint file, amdsmi and the version check already cover `*-rocm1010`. All of those wheels, plus `rocm-sdk-device-gfx942/gfx950==10.1.0` and the matching `amd-torch(vision)-device-*` wheels, are on the stable index for cp312.
- The gfx1250 10.1 image builds with `ENABLE_MORI=0`, but these two keep `ENABLE_MORI=1` like their 10.0 counterparts. The MORI `rocm_sysdeps` path and the NIXL `libabsl-dev` removal were keyed on `rocm1000` only, so this extends both to `rocm1010`.
- The gfx1250 10.1 stage sets `HIPBLASLT_TENSILE_LIBPATH`. I left it out here: the 10.1 gfx942/gfx950 device wheels keep the same `hipblaslt/library/<arch>/` layout as 10.0, and the gfx1250 wheel is the only one that changed (it adds a `gfx1250v0` directory). I have not confirmed on hardware that GEMMs resolve without it.
- They are in the same `publish` matrix as 10.0 rather than in a separate job. `fail-fast: false` already keeps a 10.1 build failure from cancelling the 10.0 images.

## Test plan

- [ ] Smoke test each image on MI300X / MI355X: `torch.cuda` sees the GPUs, a GEMM runs, and GSM8K on a small model matches the `rocm10` image
