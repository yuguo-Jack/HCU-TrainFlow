# [Fix] true-on-policy: Allocate the graph logits buffer in the logits dtype

[Upstream PR](https://github.com/sgl-project/sglang/pull/44517) · state: closed · merged: True

## Original PR description

## Summary

Under a true-on-policy contract (e.g. `qwen3_dense_true_on_policy_v1`), the lm head runs in bf16 and eager forward returns bf16 next-token logits. CUDA-graph decode copies the same logits into the shared `next_token_logits_buffer`, which was always fp32. As a result, decode `log_softmax` and top-k ran in fp32 and stopped matching the trainer bitwise. Prefill, which uses no buffer, matched. In `LogitsProcessor._copy_logits_to_buffer`, the buffer branch came before the force-bf16 branch, so the bf16 cast never ran under CUDA graph.

The fix gives the buffer the dtype the logits processor returns:
- `get_next_token_logits_dtype(config)` in `logits_processor.py` returns bf16 when the contract forces a bf16 lm head, and fp32 otherwise.
- `GraphSharedOutput.get_logits_buffer` takes a required `dtype` and keys its cache by `(vocab_size, dtype)`.
- Every runner that allocates a `next_token_logits_buffer` passes that dtype: decode and prefill CUDA graph, EAGLE and multi-layer EAGLE draft extend, and the base runner's dummy-run buffers.
- `_copy_logits_to_buffer` asserts that the buffer dtype matches, so a mismatched allocation fails loudly instead of converting silently.
- Default serving is unchanged and keeps the fp32 buffer.

An alternative was rejected: checking for force-bf16 before the buffer branch would drop the shared buffer, so each captured batch size would hold its own logits output. With this fix the shared buffer stays, and halves in size under the contract.

Only `sglang-miles` needs this. On `main`, `_copy_logits_to_buffer` upcasts every path to fp32, so prefill and decode already agree.

## Rebased onto the rebuilt sglang-miles (`bff3f6ae7e`)

The rebuilt branch adds a fused cast-and-softcap path in `_copy_logits_to_buffer` that always writes fp32 logits and asserts an fp32 buffer. `get_next_token_logits_dtype` therefore returns fp32 when the config sets `final_logit_softcapping`, and the softcap lookup is shared through `_final_logit_softcapping(config)`. The unit test adds a contract-plus-softcap case. The GPU results below were measured before the rebase; the CPU unit tests were re-run on the new base:
- the new tests: 6 passed (plus 5 subtests);
- `true_on_policy/` and the logprob suites: no new failures. The 10 failures and 1 error also fail on base, from stub subprocesses and missing CUDA.
