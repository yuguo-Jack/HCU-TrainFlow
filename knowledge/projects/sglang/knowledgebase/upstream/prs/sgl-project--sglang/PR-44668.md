- BBuf · comment · 2026-10-19T07:14:15Z · [source](https://github.com/sgl-project/sglang/pull/44668#issuecomment-6261800709)

Hi @Fridge003, thanks for the Helion verify megakernels! A heads-up for the rebase: #45112 regroups `sglang.kernels` by operator, following the existing README rule that model-specific kernels live inside a logical group rather than in a model-named top-level group. As part of that, `python/sglang/kernels/ops/muse_spark/` was dissolved. For this PR:

- `helion_qk_norm.py` → `ops/attention/muse_spark_qk_norm_rope_store_helion.py`
- `helion_runtime.py` → `kernels/jit/utils/helion_runtime.py`
  - `helion_supported(tensor)` no longer takes `op_name`.
  - The public helpers are `base_package_version` and `warn_helion_unsupported`.
- `FinalizePushWorkspace` now lives in `srt/layers/communication/muse_spark_finalize_workspace.py`. The moe modules this PR edits import it from there.
- `helion_megakernels/` and its tests need a home in a logical group. `test_kernels_namespace.py` now checks that the operator groups match the README list, so `ops/muse_spark/` and `test/registered/kernels/ops/muse_spark/` would be rejected. Since these are whole-layer speculative-verify kernels, `ops/speculative/` (e.g. `ops/speculative/muse_spark_helion_verify/`, with tests under `test/registered/kernels/ops/speculative/`) seems like a natural fit, but I'm open to whatever you think reads best.

Kernel code was moved byte-for-byte, so nothing should change functionally. Happy to help with the rebase if that's useful. Thanks!
