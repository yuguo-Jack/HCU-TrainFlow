# [Fix] metrics: Guard scrapes from starving health checks

[Upstream PR](https://github.com/sgl-project/sglang/pull/28163) · state: open · merged: False

## Original PR description

Fixes #28157.

## Motivation

The `/metrics` route mounts the Prometheus ASGI app directly. In multiprocess mode, a scrape can spend seconds collecting and rendering metrics on the request path. In the single-tokenizer prefill topology that shares a process with the bootstrap health endpoint, scrape pressure can make `/health` look dead even though the prefill process is still alive.

## Modifications

- Run the original `make_asgi_app` in a worker thread with a buffered request and response. The serving event loop no longer executes synchronous registry collection, while native OpenMetrics negotiation, gzip compression, `name[]` filtering, headers, and response bodies remain unchanged.
- Keep only one scrape in flight. Concurrent requests return `503` instead of queuing more registry work. The request is read before the occupancy check so two simultaneous callers cannot both pass the check while awaiting their request messages.
- Bound the wait with a timeout and return `504` when it expires. The background scrape remains marked in flight until it actually finishes, so repeated timeouts cannot create an unbounded pile of workers.
- Return `500` if the native app fails. Task exceptions are logged in the completion callback, including failures that happen after the caller has already received a `504`.
- Move the regression test to `test/registered/unit/utils/` and register it for CPU CI.

## Validation

The pre-rework middleware fails the native OpenMetrics regression by returning `text/plain`. The simultaneous-arrival regression was also observed failing with two `200` responses before the request read was moved ahead of the occupancy check.

On final head `50bf308c4f`:

- Six source-bound CPU tests pass with both `prometheus-client==0.26.0` and the minimum supported `0.20.0`. They execute the real helper and middleware functions from `common.py`, the unchanged committed test file, and real `make_asgi_app` instances. Coverage includes plain text, OpenMetrics, gzip, `name[]`, sequential and simultaneous scrapes, `503`, `504`, and exception logging after a timeout.
- Changed-file pre-commit passes, including Ruff, formatting, merge-conflict checks, and registered-test validation.
- `py_compile` and scoped `git diff --check` pass.

The lightweight local lane does not import the complete serving stack or run a model. Full package CI remains authoritative for that integration coverage. No GPU or serving benchmark was run; this change targets failure isolation in the metrics path.

If a metrics scrape times out, the background task `scrape_task` continues to run. If it subsequently fails with an exception, the exception is completely swallowed and never logged because the request has already returned a `504` response.

To prevent silent failures, we can log the exception directly inside `clear_scrape_task` when the task completes with an error. This centralizes the logging and ensures all failures are recorded.

```suggestion
    def clear_scrape_task(done_task: asyncio.Task):
        nonlocal scrape_task
        try:
            exc = done_task.exception()
            if exc is not None:
                logger.error("Failed to generate Prometheus metrics", exc_info=exc)
        except asyncio.CancelledError:
            pass
        if scrape_task is done_task:
            scrape_task = None
```
