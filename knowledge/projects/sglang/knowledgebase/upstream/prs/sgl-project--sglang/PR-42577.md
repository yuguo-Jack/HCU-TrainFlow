# [Fix] minicpm5: Fix quadratic regex scans in the tool-call parser

[Upstream PR](https://github.com/sgl-project/sglang/pull/42577) · state: open · merged: False

## Original PR description

## Motivation

`MiniCPM5Detector` (`minicpm5`) scans model output with patterns that go quadratic when a closing tag never arrives:

1. `detect_and_parse` uses `re.finditer(r"<function.*?</function>")`, which rescans to the end of the text from every `<function`.
2. The regex fallback, taken whenever a block isn't well-formed XML, runs `<param\s+name=...>([\s\S]*?)</param>` over the block. Every `<param name="...">` without a later `</param>` rescans to the end. Streaming re-parses each complete block with `detect_and_parse`, so this also hits a single streaming call.
3. `<param(?![^>]*\bname=)[^>]*>` rescans to the next `>` from every `<param`.

| Input | Before | After |
|---|---|---|
| 100 KB of repeated `<function `, non-stream | 12.4 s | < 1 ms |
| 96 KB block with unclosed `<param name="...">` tags, non-stream | 12.7 s | fast |
| same, **one streaming call** | 13.7 s | fast |
| 112 KB of `<param` with no `>` | 0.4 s | fast |

Tool-call parsing runs synchronously on the tokenizer manager's event loop, so one such response stalls every in-flight request. Found with an Atheris fuzzing harness that records per-input parse time.

## Modifications

- `_iter_delimited`: a linear `str.find` scan returning the same spans as the `finditer`. The unused `func_call_regex` is removed.
- The `<param name=...>` `finditer` is bounded with `endpos` at the end of the last `</param>`. No match can end past it, so the matches are unchanged.
- `_has_param_missing_name`: a linear replacement for `_PARAM_MISSING_NAME_REGEX.search()`. For each `>`, it checks only the last `<param` before it. Every earlier `<param` sharing that `>` has a superset of its attribute text, so if any of them lacks `name=`, the last one does.
- Regression test in `test_minicpm5_detector.py` (fails on `main`, passes here).

## Accuracy Tests

- Differential test of `main` vs patched detector, comparing `detect_and_parse` and every streaming result under random re-chunking: **0 mismatches** over 20k random plus 20k mutated well-formed inputs.
- `_has_param_missing_name` vs the old regex on 200k random strings: identical.
- `test/registered/unit/function_call/`: all pass.
