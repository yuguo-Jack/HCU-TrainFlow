# Allow 128 chat logprob candidates through the model gateway

[Upstream PR](https://github.com/sgl-project/sglang/pull/41373) · state: closed · merged: False

## Original PR description

## Summary

Allow the OpenAI-compatible chat route to forward up to 128 candidate log probabilities per generated token, and preserve the session extensions `input_ids` and `return_meta_info` when forwarding the request to a worker. This enables clients that record candidate probabilities for score centering while using the SGLang router.

The current typed chat request rejects `top_logprobs` above 20 and discards these extensions. The change retains validation of unrelated fields and rejects candidate counts above the backend limit. It vendors the protocol crate so the extended validation and fields can be represented in the router's typed request. I am open to replacing that vendoring with an upstream protocol-crate release if one is available.

## Verification

- Six focused Rust tests passed on the original source revision. They cover the 128-candidate request, bounds and logprobs validation, and preservation of the session fields.
- A live probe through the patched router completed 128 concurrent chat requests successfully, followed by 50 successful health checks. The downstream session data retained 128 candidates per token.
- Rebased the same source changes onto current SGLang `main`; the rebased tree passes `git diff --check`. The Rust suite has not been rerun on this rebased tree.

The larger rollout is a separate workload and is not part of this PR's validation.
