# [Fix] trtllm_mha: Pack a graph-built page table for eager reads

[Upstream PR](https://github.com/sgl-project/sglang/pull/47703) · state: open · merged: False

## Original PR description

## Motivation

With unified memory, every reader in an iteration shares one plan's page table, built by the first reader that asks. A CUDA-graph reader builds it in place in its static buffer as `into[:rows, :width]`. `width` is the pages the batch's host lengths need, usually far narrower than the buffer's `max_num_pages`, so with 2+ rows the table is a strided view. A later eager trtllm_mha read of the same plan asking for no more rows gets that view. XQA and fmha_v2 take a table's row length from its width and ignore its strides, so #42930 added an assert for this case, which "no known configuration produces":

```text
AssertionError: trtllm_mha reads its page tables as packed rows, but the plan's table is a strided view of a wider buffer
```

#46837 (DFlash draft CUDA graph under attention DP) produces it. The draft graph is keyed by the rank-local batch and the target verify by the DP-wide max. In a round where the draft replays but the verify overflows the captured graph and runs eager, the draft builds the table in place and the verify reads the strided view. Under skewed DP load (one heavy rank, 2+ requests on the others) the scheduler dies on the first decode rounds. On main alone the DFlash draft graph is off under DP, so this lands first and #46837 needs no workaround.

The fix belongs in the reader. The other table readers already handle a strided table: FA3 passes the row stride, the gather and CSR readers pass `row_stride`, and the MLA readers copy. Building packed tables in the plan instead would add a copy to nearly every graph replay on every backend.

## Modifications

- trtllm_mha's eager `init_forward_metadata` packs the full and sliding-window page tables with `.contiguous()` instead of asserting they are packed. `.contiguous()` returns a packed table as it is; decode graph capture and replay do not run this path.
- `test_unified_eager_table_must_be_packed`, which pinned the assert, becomes `test_unified_eager_packs_a_table_a_graph_reader_built`, run for the full and the sliding-window table. A captured reader builds that table in place first; the eager read must then give packed tables carrying exactly the ids the graph reader built.
