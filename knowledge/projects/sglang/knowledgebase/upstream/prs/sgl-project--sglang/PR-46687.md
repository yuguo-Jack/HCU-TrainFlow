# [Fix] kimi-k3: Enable SiTU in FlashInfer CuTe DSL MoE

[Upstream PR](https://github.com/sgl-project/sglang/pull/46687) · state: open · merged: False

## Original PR description

## Motivation

@humansand

Kimi K3 uses `activation="situ"`, which SGLang currently rejects with `--moe-runner-backend flashinfer_cutedsl` even though FlashInfer implements it. Forward the model's SiTU parameters to the existing CuTe DSL wrapper for both NVFP4 W4A16 and W4A4.

## Modifications

- **Activation:** admit SiTU on the wrapper-based CuTe DSL path and use `ActivationType.Swiglu` with `situ_beta` / `situ_linear_beta`. K3 supplies these through `gemm1_alpha=4.0` and `gemm1_clamp_limit=25.0`; pass the raw constants without quantization-scale adjustment.
- **Defaults:** use the existing MoE SiTU beta default of `4.0` when unspecified. Only SiTU calls receive the new keyword arguments.
- **Reuse:** preserve the existing weight layout, scale preparation, expert placement, and W4A16 BF16-activation path. The legacy DeepEP masked path remains unsupported for SiTU; no topology or dependency changes.
- **FlashInfer implementations:** [#4394 — GeGLU and SiTU in W4A16](https://github.com/flashinfer-ai/flashinfer/pull/4394), built on [#4048 — BF16 activations in CuTe DSL NVFP4 MoE](https://github.com/flashinfer-ai/flashinfer/pull/4048); [#4009 — CuTe DSL SiTU / GeGLU](https://github.com/flashinfer-ai/flashinfer/pull/4009) provides the W4A4 implementation. All are merged, and the currently pinned FlashInfer `0.7.2` already exposes the required constructor arguments.
