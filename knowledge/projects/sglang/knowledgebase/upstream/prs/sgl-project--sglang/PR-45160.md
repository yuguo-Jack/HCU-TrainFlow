## Motivation

The `--c128-page-size` argument controls the NPU DSV4 C128 KV cache physical
page size. It must be a positive multiple of 16 (required by the Ascend sparse
attention operator), and its value must be wired through to the C128 KV pool's
`kernel_page_size`. These two invariants were previously only exercised
indirectly through e2e inference, with no focused unit coverage, so a regression
backed by a mis-wired or unvalidated page size could slip through CI.

## Modifications

- Add `TestC128PageSize` to `test_npu_ascend_dsv4_backend.py`:
  - `test_configured_page_size_reaches_npu_c128_kv_pool` asserts the configured
    value (16/32) is stored on the pool and forwarded as `kernel_page_size` when
    `_make_kv_pool` builds the C128 pool.
  - `test_invalid_page_size_is_rejected` asserts non-positive and non-16-multiple
    values (0, -16, 1, 24) raise `ValueError`.
- Mock `sgl_kernel_npu.kvcacheio` alongside the other optional NPU modules so the
  test file imports cleanly when that submodule is unavailable.
