# [GLM-5.3] Load checkpoints saved by transformers, and warn on unfilled parameters

[Upstream PR](https://github.com/sgl-project/sglang/pull/38616) · state: closed · merged: False

## Original PR description

## Motivation

Two independent defects on the same loading path, one commit each.

### 1. Checkpoints written by `save_pretrained` load with most weights dropped

transformers renames GLM-5.3-Flash tensors while *reading* the released
checkpoint (`conversion_mapping.py`, entry `"glm5_next"`) and did not reverse
that on *save*. Anything written back by `save_pretrained` — a fine-tune, a
merged adapter, a bf16 re-export — therefore carries transformers module names
rather than the released ones `glm5_next.py` is written against. Those names
miss `params_dict` and the tensors are dropped silently.

| written by `save_pretrained` | expected by `glm5_next.py` |
| --- | --- |
| `attn_hc.{fn,base,scale}` | `hc_attn_{fn,base,scale}` |
| `ffn_hc.{fn,base,scale}` | `hc_ffn_{fn,base,scale}` |
| `self_attn.forget_gate.{f_a_proj,f_b_proj,dt_bias,A_log}` | `self_attn.{f_a_proj,f_b_proj,dt_bias,A_log}` |
| `mlp.experts.gate_up_proj` [E, 2I, H] | `mlp.experts.{i}.{gate,up}_proj.weight` |
| `mlp.experts.down_proj` [E, H, I] | `mlp.experts.{i}.down_proj.weight` |
| `self_attn.conv1d.weight` [3P, 1, K] | `self_attn.{q,k,v}_conv1d.weight` |

On a 45-layer bf16 checkpoint that is **524 of 1609 tensors — 304.4B
parameters, 97% of a 628 GB file**: the packed routed MoE experts, the mHC
`attn_hc` / `ffn_hc` parameters, the KDA forget gate and the packed conv1d. The
released checkpoint is unaffected — it ships the names this loader expects, and
the conversion is a no-op on it — which is why bring-up never saw this.

**On huggingface/transformers#48676.** Since this PR was opened, transformers
made `save_pretrained` preserve the released names for the standalone text
model. That is the right layer for it and thanks @Dovis01 for fixing it there.
It does not retire this half: checkpoints already written by older transformers
are on disk (mine is 628 GB), the fix is not in a release yet (`v5.17.0`
predates the merge), and other tooling can produce the same layout. Mapping the
names on the way in keeps one loading path for both.

### 2. `load_weights` said nothing when it did not fill a parameter

The conversion above fixes the layout this loader knows about. It does not make
the loader honest about a layout it does not. `load_weights` still skips any
checkpoint tensor whose rewritten name misses `params_dict` — right for a
tensor this model does not own, indistinguishable from a checkpoint written
against names nobody here anticipated. In the second case the module keeps its
initialised values and the server starts on a partly-random model: `The server
is fired up and ready to roll!` in the log, 200 on `/health`, noise out of the
sampler.

That is what made #38618 expensive to find rather than hard to fix. The only
tell was the load time.

SGLang already treats this as worth catching, just not consistently:

| model | on unloaded params |
| --- | --- |
| `unlimited_ocr.py` | `raise RuntimeError(...)` |
| `mamba2.py`, `mllama4.py`, `falcon_mamba.py` | `logger.warning(...)` |
| `gemma3_mm.py` | computes the set, then `pass` |
| `glm5_next.py` | no check at all |

## Modifications

Rebased onto current `main` (`91f691c`) — the previous head predated the CI
rebase gate.

**`convert_hf_native_weights`** maps the transformers layout onto the released
one as `load_weights` iterates, with `_split_hf_packed_gate_up`,
`_split_hf_packed_down` and `_split_hf_packed_conv1d` unpacking the three packed
forms. Malformed packed tensors raise rather than load a wrong slice.

**`report_unloaded_params(param_names, loaded_params, *, model_label, optional_params)`** diffs
the declared parameters against the ones actually written, warns naming the
first 12 and counting the rest, and returns the list so a caller or a test can
assert on it. `load_weights` passes the parameters marked `_skip_weight_check`
as optional: the KV-cache scales `BaseKVCacheMethod` creates keep their
defaults when a checkpoint has none, and SGLang's weight checker already skips
them. `load_weights` accumulates `loaded_params` at the four sites that
write a parameter (stacked mapping, expert mapping, the fused `q_a_proj` /
`kv_a_proj_with_mqa` target, and the default loader). The pre-existing
`weight_names` records the *checkpoint* side and so cannot answer "did every
parameter get a value".

Only a full load is checked: a nextn pass reads the speculative layers alone
and `encoder_only` / `language_only` skip a whole tower on purpose, so in those
modes most of `params_dict` is legitimately untouched.

A warning rather than a raise for the second half: it cannot break a deployment
that works today, and naming 524 tensors would already have turned a day of
debugging into seconds. `unlimited_ocr.py` is the in-tree precedent if
maintainers would rather fail closed.

### Unit tests

`test_glm5_next_hf_layout.py` — 7 cases over the conversion: mHC parameters
arrive under released names, the forget-gate submodule is flattened, packed
experts split gate before up, packed `down_proj` splits per expert, packed
`conv1d` splits into q/k/v keeping the singleton dim, the released layout passes
through untouched, and malformed packed tensors raise instead of loading
silently.

`test_glm5_next_unloaded_params.py` — 8 cases over the reporting: a complete
load stays silent, a dropped parameter is named, the count and total appear, a
long list truncates but still counts, recording the fused name does not make
its checkpoint halves look like a gap, the label distinguishes one pass from
another, output is sorted, and a `dict.keys()` view is accepted as well as a
set.

Both files call `register_cpu_ci(est_time=5, suite="base-a-test-cpu")`; the
missing registration on the second one is what failed `lint` on the previous
push.

### On verification

`ruff check --select=F401,F821,UP037`, `ruff format --check` and `isort
--check-only` pass on all three files with the repo's own configuration, and the
10 reporting tests pass.

On this branch I loaded the released GLM-5.3-Flash checkpoint end to end on
8x MI325X at TP8, against its base (`81f2b43ab5`). Both load on all eight ranks.
Before the last commit, the new warning fired on every rank for this correct
checkpoint: 44 of 1551 parameters, all of them the `k_scale` / `v_scale` of
`attn_mha` and `attn_mqa`, which the checkpoint does not carry and which keep
their defaults. With the last commit it stays silent, as base does.

Serving could not be compared on that host. After loading, base and this branch
both stop in CUDA-graph capture, because the DSA decode path needs the FA3,
TileLang or TRTLLM backend (and `fast_hadamard_transform` on ROCm). The GSM8K,
load-time and greedy-probe numbers above are from the original run in #38618,
on gfx950.
