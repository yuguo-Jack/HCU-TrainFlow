# [Feat] [NPU] diffusion: Integrate MindIE-SD quantized attention into Ascend FA

[Upstream PR](https://github.com/sgl-project/sglang/pull/46029) · state: open · merged: False

## Original PR description

## Motivation

Enable MiniMax-H3 on Ascend to use MindIE-SD FP8/MXFP8/MXFP4 attention through the existing `fa` backend.

## Modifications

- Integrate `AscendQuantAttention` into `ascend_fa.py`; remove the separate backend.
- Select SD precision through `attention_backend_config`, independently of linear-weight quantization. Omitting `precision` preserves native FA.
- Support H3 packed inputs, Q/K rotation, and MHA head chunking (default 4; `0` disables it). H3 text encoding defaults to SDPA when SD attention is selected.
- Load the optional MindIE-SD API before NPU initialization when SD is selected.
- MindIE-SD is an optional dependency installed manually; see the [installation and configuration guide](https://github.com/De-cs/sglang/blob/f958ae0e91e4a1da8ccca11089b559b6243dc57b/docs/docs/sglang-diffusion/attention_backends.mdx#ascend-quantized-attention-with-mindie-sd).

```bash
--attention-backend fa \
--attention-backend-config '{"precision":"fp8","fp8_fa_mode":"C8V16_TILING512","head_chunk_size":4}'
```

For MXFP8/MXFP4, change `precision` and omit `fp8_fa_mode`.

## Accuracy Tests

Local CPU adapter, H3 dispatch/startup, and lint checks passed using isolated tests with native operators mocked. NPU numerical/model-quality validation and FP8 C8V16 + CacheDiT + chunk 4 performance remain pending.

## Speed Tests and Profiling

4 × Ascend 950PR; MiniMax-H3 `fl2va/t2va`; 1344×768, 15-second output requested, 50 steps; TP=1/Ulysses=4/Ring=1. All cases use MXFP8 linear weights, SDPA text encoding, and the same prompt/seed (1101). Quantized attention uses Q/K rotation.

End-to-end latency includes decode and excludes startup/warmup. Reductions use each table's BF16 baseline.

<details>
<summary>Benchmark settings and comparison scope</summary>

- CacheDiT 1.3.5: Fn=2, Bn=1, warmup=4, RDT=0.4, MC=4, TaylorSeer order=2; DMD/SCM off. The six original cache-enabled cases used a 50-step warmup, recorded 37/50 cached steps per worker, and disabled VAE parallel tiling. Cache-disabled cases used a 2-step warmup.
- The six original cache-enabled cases and the separate cache-disabled C8V16 run used SDK `3.1.0+fb774c4.c8v16`.
- Results come from benchmark snapshots, not a full rerun of the latest PR revision. The original five cache-disabled cases included a VAE gather workaround and native packed-MXFP8 V-scale fix; the original cache-enabled cases retained the native fix. These fixes are outside this PR. SDK/source/VAE differences prevent attributing cross-table changes solely to CacheDiT.
- All SD measurements are unchunked except the explicitly listed MXFP8 chunk 4 result. SDK MXFP4 can include padded K/V in softmax for unaligned sequences and returns BF16.

</details>
