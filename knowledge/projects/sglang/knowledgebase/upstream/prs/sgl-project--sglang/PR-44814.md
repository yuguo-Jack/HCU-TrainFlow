# [Fix] MiMo-V2: Normalize images with the checkpoint's image_mean/image_std

[Upstream PR](https://github.com/sgl-project/sglang/pull/44814) · state: open · merged: False

## Original PR description

## Motivation

Fixes #44789.

`MiMoProcessor` normalizes images with hard-coded OpenAI-CLIP mean/std. MiMo-V2.6 checkpoints now specify ImageNet stats in `preprocessor_config.json`, so SGLang normalizes V2.6 images differently from HF `Qwen2VLImageProcessor` with the same checkpoint, by up to 0.4941 per channel in the reproduction below.

The CLIP constant matched MiMo-V2.6 when #40888 was merged. The checkpoint config later changed to ImageNet stats in Xiaomi's [`6a7f202e`](https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Pro-MOPD/commit/6a7f202e) ("Align preprocessor config to training values").

Different MiMo-V2 checkpoints now specify different stats:

| Checkpoint (`MiMoV2ForCausalLM`) | Normalization |
|---|---|
| MiMo-V2.6-Pro/Flash, -RL, -MOPD | ImageNet |
| MiMo-V2.5, MiMo-V2.5-Base | CLIP |
| MiMo-V2.5-Pro, -Pro-FP4-DFlash | text-only; multimodal disabled |

So no single hard-coded normalization is correct for all of them.

## Modifications

- `processors/mimo_v2.py`
  - Read `image_mean`/`image_std` from the loaded image processor, with the existing CLIP values as fallback.
  - Key the normalization cache by `(device, mean, std)` instead of only the device, so processors with different stats do not share cached tensors.
- `models/mimo_v2.py`, `disaggregation/encoder/preprocessor.py`
  - Pass the encode server's already-loaded `image_processor` to the MiMo hook through the existing `invoke_encoder_preprocessor` mechanism. The image call already used it; the video and audio calls now do too, so whichever modality arrives first builds the processor with the checkpoint's stats.
  - Log a warning when no image processor is loaded and the encoder falls back to CLIP.
- `test_mimo_v2_image_normalization.py`
  - Regression coverage for CLIP and ImageNet checkpoints sharing one device.
  - Encode-server coverage with a video request arriving first.

Pixel bounds are unchanged: SGLang reads them from `config.json`'s `processor_config`, which already has 8192/8388608 for V2.6. The FA4 vision sliding-window issue mentioned in #44789 (#38871) is separate.

## Accuracy Tests

Compared against HF `Qwen2VLImageProcessor` loaded from each checkpoint's own preprocessor config, with GPU preprocessing (`SGLANG_ENCODER_IMAGE_PROCESSOR_USE_GPU=1`) on both the regular and encode-server paths.

Setup: RTX 4060 Laptop GPU (sm89), PyTorch 2.14.1+cu130, Transformers 5.19.0.

| Checkpoint | Path | main | This PR |
|---|---|---|---|
| MiMo-V2.5 (CLIP) | regular | match | match |
| MiMo-V2.5 (CLIP) | encode server | match | match |
| MiMo-V2.6-Pro-MOPD (ImageNet) | regular | max diff 0.4941 | match |
| MiMo-V2.6-Pro-MOPD (ImageNet) | encode server | max diff 0.4941 | match |

With this PR, the normalization cache holds separate `cuda:0` entries for the CLIP and ImageNet stats.

Unit tests (the new test plus `test_encode_server.py`, `test_kimi_k3_encoder_mode.py`, `test_processor_async_call_sites.py`):
- main: the new ImageNet cases fail, with greatest absolute difference up to 0.4941.
- This PR: 115 passed, 0 failed, with and without `SGLANG_ENCODER_IMAGE_PROCESSOR_USE_GPU=1`.

I did not run a full MiMo-V2.6 serving comparison; the change is isolated to preprocessing and is checked directly against the HF processor.

## Speed Tests and Profiling

Not applicable. Normalization does the same arithmetic as before; the tensors are still cached per device, with the stats added to the cache key.
