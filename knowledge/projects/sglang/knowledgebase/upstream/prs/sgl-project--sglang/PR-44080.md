# (draft) [Fix] [AMD] quark: Load FP8 shared experts into MXFP4 fused MoE weights

[Upstream PR](https://github.com/sgl-project/sglang/pull/44080) · state: open · merged: False

## Original PR description

## Motivation

Mixed Quark checkpoints store routed experts as MXFP4 and shared experts as block FP8. Loading the shared experts failed because Quark never received the MXFP4 flag that FP8 already copy. 
Separately, when shared-expert fusion is disabled and the shared experts stay on the block-FP8 `Linear` path, Quark's block-FP8 weight scale is the raw E8M0 exponent byte, not a float. Left undecoded, every block-FP8 matmul in the shared experts is wrong and the model degenerates into repeating garbage tokens — GSM8K scores 0.

## Modifications

- Set `is_fp4_experts` on Quark only when the checkpoint says its routed experts are MXFP4.
- Requantize those block-FP8 shared experts into the fused MXFP4 buffers.
- Read Quark's uint8 scales as UE8M0 bytes, and use `w2_weight_scale` / `w13_weight_scale` when `*_weight_scale_inv` is absent.
- Default a missing Quark block size to `[1, 32]`.
- Leave FP8 and ModelOpt on `*_weight_scale_inv`. Their scale dtype, block size, and buffer layout are unchanged.
- Thread a new `weight_scale_is_ue8m0` flag through `Fp8Config`, set from `quark.py`'s `_get_block_fp8_config` whenever the checkpoint's weight spec has `scale_type == "float8_e8m0fnu"`.
- Decode `weight_scale_inv = 2^(stored_byte - 127)` once in `Fp8LinearMethod.process_weights_after_loading_block_quant`, gated on that flag, so this only touches Quark block-FP8 layers and leaves plain FP8 / ModelOpt checkpoints untouched.

## How to run 
export HF_TOKEN=<hf-token>
export HIP_VISIBLE_DEVICES=0,1,2,3
export SGLANG_USE_AITER=1
export SGLANG_USE_AITER_MOE_GU_ITLV=0
export NCCL_IB_DISABLE=1
export NCCL_SOCKET_IFNAME=lo
export SGLANG_WARMUP_TIMEOUT=20000

export MODEL=amd/MiniMax-M3.1-preview2-dspark-private-Quark-MXFP4

python3 -m sglang.launch_server \
  --model-path "$MODEL" \
  --tp 4 \
  --trust-remote-code \
  --quantization quark \
  --dtype bfloat16 \
  --disable-shared-experts-fusion \
  --attention-backend aiter \
  --moe-runner-backend aiter \
  --context-length 131072 \
  --page-size 128 \
  --mem-fraction-static 0.85 \
  --reasoning-parser auto \
  --port 8000

GSM8K, 1319 scored questions, 5-shot, thinking disabled, 4096-token cap:

```
python3 -m sglang.test.run_eval \
  --eval-name gsm8k --api chat \

  --num-examples 1319 --num-threads 128 --num-shots 5 \
```

## Accuracy Tests

GSM8K on `amd/MiniMax-M3.1-preview2-dspark-private-Quark-MXFP4`, `--disable-shared-experts-fusion`, otherwise identical server flags:

| Attention backend | E8M0 scale decode | Score |
|---|---|---|
| Triton | Without this PR | 0.000 (every answer runs to the 4096-token cap) |
| Triton | With this PR | 0.915 |
| Aiter | With this PR | 0.909 |

The expected startup log line is still `Loading FP8 shared expert weights into FP4 fused MoE weights` when fusion is enabled; with `--disable-shared-experts-fusion` the shared experts load as block-FP8 `Linear` layers and the new decode applies there instead.

## Speed Tests and Profiling

The decode is a one-time elementwise op on the weight-scale tensor at load time; it does not change the runtime matmul path or tensor layout. No throughput benchmark was run specifically for this change.
