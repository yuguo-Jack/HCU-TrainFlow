# [Perf] Kimi-K3: Index parameters per decoder layer in load_weights

[Upstream PR](https://github.com/sgl-project/sglang/pull/47531) · state: open · merged: False

## Original PR description

Stacked on #47530. Only the last commit is new here; I will rebase onto `main` once #47527 and #47530 are merged.

## Why?

- A Kimi-K3 weight update makes about 770 `load_weights` calls.
- Each call rebuilt `dict(self.named_parameters())`, once for the language model and once more in the multimodal wrapper for vision tensors. It also rebuilt the 896 × 3 expert mapping and its index.
- On GB300 engines (TP16 EP16, W4A16), these rebuilds were about a quarter of each scheduler's weight-update time. The other two slow spots from the same profile are already fixed on `main` (#39264, #38805).

## What?

- `load_weights` indexes parameters one decoder layer at a time: `model.layers.{i}.named_parameters()`, built the first time a call touches that layer. The rest of the model is indexed only when a name outside the layers arrives.
- The multimodal wrapper indexes the whole model at the first vision tensor.
- The indexed expert lookup from #38805 is built once per model instead of once per call.
- A parameter tied across layers still answers only to its first name, as `dict(named_parameters())` did. So loading its second name can't overwrite the first.

## Verification?

```text
Kimi-K3 weight update on GB300 (~770 load_weights calls)

Before: every call → dict(named_parameters()) ×2 + 896×3 mapping + index rebuild
After:  every call → index only the layers it touches; mapping built once per model   (expected)

Internal fork, same model: these rebuilds were ~1/4 of each scheduler's update time (observed there)
```
