# [Perf] [AMD] dsa: Merge indexer wk and weights_proj

[Upstream PR](https://github.com/sgl-project/sglang/pull/34394) · state: open · merged: False

## Original PR description

## Summary

The single-kernel ROCm q/k prep this PR introduced (`indexer_qk_rope_quant_and_cache`, Hadamard dropped) has since landed through #40710, so after merging main this PR is two changes on top of it:

1. **Merged indexer projection on ROCm.** `wk` and `weights_proj` fold into one bf16 `wk_weights_proj` GEMM, previously CUDA-only, and its output feeds #40710's fused writer. Numerically identical to the split projections.
2. **LoRA fix.** `lora_manager.py` imports `_use_dsa_indexer_fusion`, which nothing defines, so an indexer-targeted LoRA adapter raised `ImportError` instead of the intended `ValueError`.

| Decode indexer projection, per layer | us |
| --- | --- |
| `hgemm_16x64x128x3` (wk) + `hgemm_16x64x64x6` (weights_proj) | 6.59 + 5.30 |
| `hgemm_16x64x128x3` (merged `wk_weights_proj`) | 6.50 |

The Test plan was measured before #40710 landed, so its baseline has neither change: of the 29.4 us/layer saved, 5.4 is the merged projection.

## Scope

ROCm enables the merged projection wherever #40710's fused writer is enabled (gfx950, `SGLANG_USE_AITER`, LayerNorm `k_norm`, head_dim 128 / rope_dim 64). `SGLANG_DISABLE_DSA_INDEXER_FUSION=1` restores the separate projections. On FP8 checkpoints the GEMM reads the bf16 passthrough of aiter's `(fp8, scale, bf16)` activation tuple. The k-only store path now skips the Hadamard whenever the q path does. CUDA and NPU are unchanged.

## Test plan

MI355X TP4, GLM-5.2-MXFP4, fp8 KV, `chunked_prefill=16384`, DSA backend triton, i8192 / o1024, one run per point. Baseline is the same AMD GLM-5.2 stack without this PR (#30519, #30575, #30715, #30808, #31323, #31324, #32888, plus ROCm/aiter#4453).

ITL improves −4.2% to −5.5% at every concurrency, matching the 29.4 us/layer the kernel table predicts over the 21 layers that run the indexer (0.62 ms per decode forward). TTFT is flat, which is the check that matters given the kernel is decode-only.

GSM8K (1200 questions): 0.928 baseline, 0.934 this PR. The index-K cache is bit-exact against the unfused path across both `preshuffle` and `scale_fmt`; the q fp8 payload differs by 1 ULP on 0.10% of elements, because aiter multiplies by the reciprocal rather than dividing.
