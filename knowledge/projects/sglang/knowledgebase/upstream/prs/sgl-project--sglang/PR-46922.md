# [Test] cpu: Re-enable the subblock sparse attention test

[Upstream PR](https://github.com/sgl-project/sglang/pull/46922) · state: open · merged: False

## Original PR description

## Motivation

test/registered/cpu/test_subblock_sparse_attention.py has been disabled with `disabled="Xeon import initializes CUDA-only vsa (#43334); until 2026-10-24"`. That deadline has passed, and the import no longer initializes CUDA-only state — `from sglang.multimodal_gen.runtime.platforms.cuda import _SubBlockSparseAttentionBackendResolver` imports cleanly on a CPU-only box on current main.

While the test sat disabled it also drifted: `MiniMaxH3PipelineConfig.validate_server_args` now reads `server_args.performance_mode`, which the fixtures' SimpleNamespace never set, so 7 of the 31 tests raised AttributeError as soon as anything ran them. This fixes the fixtures and removes the expired marker so the Xeon suite (`stage-a-test-cpu-intel`) picks the test back up.

## Modifications

- Removed the expired `disabled=` argument from `register_cpu_ci`.
- Added `performance_mode="speed"` to the two `SimpleNamespace` server_args fixtures that `validate_server_args` reads.

## Accuracy Tests

`pytest test/registered/cpu/test_subblock_sparse_attention.py` — 31 passed, 7 subtests passed, on a CPU-only box against current main. ruff format and the pre-commit ruff selection are clean.
