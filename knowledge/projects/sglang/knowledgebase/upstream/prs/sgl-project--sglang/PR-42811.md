# [Perf] [NVIDIA] custom-all-reduce: Add 2shot_push all-reduce and retune SM100 TP4/TP8

[Upstream PR](https://github.com/sgl-project/sglang/pull/42811) · state: closed · merged: True

## Original PR description

## Motivation

`CustomAllReduceV2` has no good option between about 0.5 MB and 8 MB at TP4 and TP8 on Blackwell: `1shot_push` moves `W` copies of the tensor per rank and runs out of steam, while `2shot_pull` pays two barriers and remote loads. A push-plane two-shot (Lamport markers, no barriers) beats both across that band. This PR adds it as `2shot_push` and retunes the SM100 world 4 / 8 rows from a B300 sweep.

The kernel follows the design in #35192 by @lyppg (rotated per-peer scatter and gather, owner reads its own partial from the input, split reduce and gather loops). The difference is the plane layout: this PR keeps both halves of a chunk in one existing push slot, so the push plane, its workspace and the `PushPlane` constructor are unchanged, and no multicast variant is added. @lyppg is a co-author on the kernel commit.

## Modifications

**Kernel** (`custom_all_reduce.cuh`): `all_reduce_2shot_push_kernel`, next to `all_reduce_1shot_push_kernel`.
- The flat tensor is split into `W` chunks of `ceil(num_vecs / W)` 16 B vectors; rank `c` owns chunk `c`.
- Reduce-scatter: each rank pushes chunk `c` only to its owner. The owner polls its own slots, reduces in rank order, keeps the sum, and pushes it to every other rank. All-gather: each rank drains the peers' sums into its output.
- Same bytes on the wire as `2shot_pull`, but every remote operation is a posted store and every wait is a local poll: no barriers, no remote loads, no staging copies.
- A slot `(dst, src)` holds `[partial of chunk dst | reduced chunk src]`, two `chunk_vecs` halves. The `(r, r)` slot is unused.
- Scatter and gather give each warp one peer, starting at `r + 1`, so every peer's ingress is busy from the first wave and the slot pointer is warp-uniform. The host raises the block size when a small grid has fewer warps than peers.
- Reduction order is rank order on every rank, so all ranks hold identical bits, and `2shot_push` matches `1shot_push` bit for bit.

**Push-plane sizing** (`configs/custom_all_reduce_v2.py`, `custom_all_reduce_v2.py`):
- A 2shot slot needs `2N / W` bytes instead of `N`. `Heuristic.max_push_bytes(world_size)` sizes the slot for both push algorithms; `clip()` caps the 2shot threshold at what the slot fits (`two_shot_push_slot_bytes` and its inverse `two_shot_push_max_bytes`).
- Symmetric memory per rank with the new rows: TP4 24 MB to 32 MB, TP8 12 MB to 32 MB.

**Picker**:
- New `AllReduceAlgo.TWO_SHOT_PUSH`; it is a push algorithm (`is_push()`), needs no graph pointer table, and behaves the same in eager mode and under CUDA-graph capture.
- `Heuristic.two_shot_push_threshold` defaults to 0, so untuned (arch, world size) rows are unchanged. Table rows set it by keyword (`two_shot_push=`).
- Order of preference is now `1shot_push -> 2shot_push -> 1shot_pull -> 2shot_pull mc -> 2shot_pull`.

**SM100 table** (graph and eager use the same thresholds):

| World size | `1shot_push` up to | `2shot_push` up to |
|---|---|---|
| TP4 | 640 KB (was 2.25 MB graph / 3 MB eager) | 8 MB |
| TP8 | 256 KB (was 0.5 MB graph / 0.75 MB eager) | 8 MB |

Multicast `2shot_pull` still takes over above 8 MB at TP8 where it was configured. The rows were swept on B300; B200 and GB200 inherit them as SM100 (see follow-ups).

**Tests** (`test_custom_all_reduce.py`): `TWO_SHOT_PUSH` joins the algorithm matrix, with an odd size (3 MiB + 24 elements, uneven chunks).

## Accuracy Tests

- `test_custom_all_reduce.py` with `SGLANG_JIT_KERNEL_RUN_FULL_TESTS=1`: 264 passed at each of TP2, TP4 and TP8 on the kernel commit; 264 passed again at each of TP2, TP4 and TP8 after merging main. Exact equality against NCCL; fp16, bf16, fp32; eager and CUDA graph; 11 sizes from 16 elements to 4 Mi elements, including sizes that leave chunks empty.
- In the sweeps below (bf16 randn, 64 KB to 16 MB), `2shot_push` matches `1shot_push` bit for bit at every size and world size.

## Speed Tests and Profiling

Setup: 8x B300 (sm_103, 148 SMs), bf16. Each timing is one CUDA-graph replay of 100 back-to-back all-reduces, max over ranks, median of 9 replays. Graph mode captures under `comm.capture()`; eager mode captures the eager dispatch path (staging copies included) without Python launch overhead. **this PR** is the tuned picker end to end; **today** is the upstream picker from an earlier sweep on the same box (`1shot_push` was rerun in both and agrees within 0.97-1.08x). `2shot_pull mc` is forced on at TP4 to show the crossover.
