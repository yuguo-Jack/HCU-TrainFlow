# [Fix] moe: disable deferred finalize under deterministic inference

[Upstream PR](https://github.com/sgl-project/sglang/pull/48236) · state: open · merged: False

## Original PR description

## Motivation

MoE deferred finalize (`SGLANG_ENABLE_MOE_DEFERRED_FINALIZE=1`, `SGLANG_MOE_DEFERRED_FINALIZE_MAX_TOKENS=192`) skips the in-op expert reduction when `num_tokens <= 192` and fuses the weighted expert sum with `shared_output` in `finalize_flashinfer_trtllm_deferred_output`, while batches with `num_tokens > 192` finalize routed experts to BF16 inside the MoE kernel first and add `shared_output` afterward. Because the two paths round BF16 in different orders (~23% BF16 element bit mismatch across `M = 192`), small-batch decode and large-batch prefill produce different hidden states under `--enable-deterministic-inference`.

`handle_environment_variables` previously disabled `SGLANG_FLASHINFER_MOE_FUSED_FINALIZE` under deterministic inference, but left `SGLANG_ENABLE_MOE_DEFERRED_FINALIZE` enabled and left env-independent deferred-finalize variants (`qwen35_fp8_deferred`, `qwen4_bf16_deferred`, `packed_nvfp4_routed_deferred`, and MXFP4 `return_moe_output`) unguarded.

## Modifications

- Set `envs.SGLANG_ENABLE_MOE_DEFERRED_FINALIZE.set("0")` when `cfg.enable_deterministic_inference` is true in `serving_hook.py`.
- Guard `FusedMoE.supports_deferred_finalize`, `FusedMoE.supports_routed_deferred_finalize`, `DeepseekV2MoE`'s `deferred_finalize` check, and `MiMoV2MoE.supports_deferred_finalize` with `not get_exec().deterministic.enable_deterministic_inference`.
- Add hermetic CPU unit tests in `test/registered/unit/moe/test_moe_deferred_finalize_deterministic.py`.
