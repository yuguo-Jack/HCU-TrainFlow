# [Fix] internvl: Load GPT-OSS backbone weights through GptOssForCausalLM.load_weights

[Upstream PR](https://github.com/sgl-project/sglang/pull/45009) · state: open · merged: False

## Original PR description

Fixes #45032

## Motivation

`InternVLChatModel` builds a `GptOssForCausalLM` language model when `llm_config.architectures[0] == "GptOssForCausalLM"`, but `load_weights` has no branch for it. `stacked_params_mapping` is never assigned, so loading fails on the first weight:

```
UnboundLocalError: cannot access local variable 'stacked_params_mapping' where it is not associated with a value
```

This affects the public checkpoint `OpenGVLab/InternVL3_5-GPT-OSS-20B-A4B-Preview` (bf16, `GptOssForCausalLM` backbone, 411 `language_model.*`, 340 `vision_model.*` and 6 `mlp1.*` tensors).

Defining the variable would not be enough. The generic loop also does not do the GPT-OSS specific work in `GptOssForCausalLM.load_weights`: qkv splitting, attention sinks, and the bf16/mxfp4/quark expert layouts.

## Modifications

- In `InternVLChatModel.load_weights`, add a `GptOssForCausalLM` branch. It streams `language_model.*` weights (prefix stripped) to `self.language_model.load_weights`. Vision model and projector weights are collected and loaded by the existing loop. All three GPT-OSS paths (bf16, mxfp4, quark) consume the iterator fully, so nothing is skipped.
- Held-back weights go through `_own_if_runai_streamed`, the same ownership rule GPT-OSS's mxfp4 path uses for tensors it keeps past the streamer.
- Add `test/registered/unit/models/test_internvl_gpt_oss_loader.py` (CPU). It checks that language weights reach the GPT-OSS loader with the prefix stripped, and that vision and projector weights are loaded into the wrapper.

## Accuracy Tests

Not run. This change only affects weight loading for the GPT-OSS backbone, which could not load before. No GPU end-to-end run has been done yet, so serving InternVL3.5-GPT-OSS past weight loading is unverified.
