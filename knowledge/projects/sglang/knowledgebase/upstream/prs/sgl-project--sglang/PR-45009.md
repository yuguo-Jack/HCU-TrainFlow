# [Fix] internvl: Load GPT-OSS backbone weights through GptOssForCausalLM.load_weights

[Upstream PR](https://github.com/sgl-project/sglang/pull/45009) · state: open · merged: False

## Original PR description

Fixes #45032

## Summary

InternVL cannot load checkpoints that use a GPT-OSS language model. Its weight loader handles several language-model architectures directly, but GPT-OSS requires its own loader to process the backbone weights. Without that delegation, loading fails with an `UnboundLocalError` before the model can start.

This affects checkpoints such as `OpenGVLab/InternVL3_5-GPT-OSS-20B-A4B-Preview`.

## Changes

- Route `language_model.*` tensors through `GptOssForCausalLM.load_weights`, stripping the `language_model.` prefix expected by that loader.
- Keep vision-model and projector tensors in InternVL's existing wrapper-level loading path.
- Preserve ownership of tensors retained after streaming, matching the GPT-OSS mxfp4 loading path.
- Add a CPU unit test covering backbone delegation and vision/projector weight loading.

Delegating to the GPT-OSS loader also lets it handle its format-specific weight transformations and expert layouts.

## Validation

- CPU unit test: passed. On the base revision, the test reproduces the `UnboundLocalError`; with this change, it passes.
- Formatting and lint checks listed below: clean.
- No GPU end-to-end run has been performed. This change unblocks weight loading; successful serving of InternVL3.5-GPT-OSS has not been verified.
