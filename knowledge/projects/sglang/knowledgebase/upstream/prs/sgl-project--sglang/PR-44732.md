# [Fix] hicache: Separate storage keys for incompatible host layouts

[Upstream PR](https://github.com/sgl-project/sglang/pull/44732) · state: open · merged: False

## Original PR description

## Motivation

Dense MHA and MLA host pools currently use the same storage keys across host memory layouts. With L3 caching enabled, restarting with `page_first` after writing pages with `layer_first`, while retaining the same model, rank configuration, page size, and storage directory, lets a matching prefix reuse incompatible KV pages. The file backend accepts these pages because their byte counts are equal.

On an NVIDIA L20 with Qwen3-0.6B, three requests each reported a 240-token storage hit after this layout change and produced different token sequences from the cold-cache control. A GPU page round-trip reproduced the incorrect KV values for both MHA and MLA.

## Modifications

- Add layout-specific `storage_format_tag` values to the dense MHA and MLA host pools, using the existing storage model-name tagging path.
- Keep `layer_first` and `page_first_direct` in the same namespace because their flattened page byte order is identical.
- Add file-backend regression tests for compatible and incompatible layout pairs, including MHA `page_head`, and for untagged legacy pages.

Existing untagged MHA/MLA L3 entries will miss after this change, even if the host layout is unchanged. The cache must warm again under the new keys. Existing entries are not deleted or migrated.

## Accuracy Tests

CPU regressions: **65 tests and 37 subtests passed**.

```bash
python -m pytest -q \
  test/registered/unit/mem_cache/test_hicache_storage_format_tag.py \
  test/registered/unit/mem_cache/test_mem_pool_host.py \
  test/registered/unit/mem_cache/test_hicache_file_lru_unit.py \
  test/registered/unit/managers/test_scheduler_hicache_attach.py
```

The new regression cases produce 16 failing subtests on the unmodified base. The storage-format test also passes when executed directly, as in registered CI.

Manual validation on one NVIDIA L20, using the file backend:

- **GPU page round-trip:** actual device-to-host and host-to-device transfers for MHA and MLA. All four incompatible `layer_first`/`page_first` cases now miss. All four same-layout cases restore every element exactly.
- **Qwen3-0.6B:** three 253-token prompts, 16 generated tokens each, TP=1, Triton attention, CUDA graphs disabled, `buffer_only`, `write_through`, and page size 16. After switching layouts, all three requests miss the incompatible entries and match the cold-cache outputs token for token. A subsequent same-layout run hits 240 tokens per request and matches the unmodified same-layout warm-cache control token for token.

GPU transfer validation covers `layer_first` and `page_first`. The `page_first_direct` and `page_head` cases are covered by CPU page-format tests. MLA validation covers GPU page transfers; the full-model run uses Qwen3-0.6B. Other storage backends were not exercised.

Local coverage collection crashed during imports on both the unmodified base and patched source, so no coverage percentage is reported.

## Speed Tests and Profiling

Not measured. This change separates incompatible cache entries; it does not change transfer kernels.
