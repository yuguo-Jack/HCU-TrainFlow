# [AMD][Fix] Exclude added-vocabulary tokens from synthetic multimodal prompts

[Upstream PR](https://github.com/sgl-project/sglang/pull/37732) · state: open · merged: False

## Original PR description

## Motivation

`--dataset-name image` loses a random fraction of its requests to HTTP 400 before they ever reach the model, and still reports the run as successful. On `amd/MiniMax-M3-MXFP4` the rejections read `"No data iterator found for token: ]<]video[>["` — a *video* placeholder, in an image benchmark that attaches no video.

Nothing reports the loss: the benchmark exits 0 and discards the error body. Throughput and latency are then computed over a smaller request set than asked for making those numbers unreliable for multimodal inputs

Prerequisite for trusting any `--dataset-name image` result, including the VL numbers
in the MiniMax-M3 series (#41662, #41663, #41664, #41672). #38035 is the
companion fix, correcting vision-token *accounting* on the same path; different files,
neither depends on the other.

## Modifications

`get_available_multimodal_text_tokens()` additionally excludes
`tokenizer.get_added_vocab().values()`, behind a `callable` guard for tokenizers that
do not implement it. Excluding the added vocabulary covers image, video and audio
placeholders for any model, rather than only the one image id callers can pass in.

Not applicable — synthetic benchmark prompt generation only, not kernels or model
