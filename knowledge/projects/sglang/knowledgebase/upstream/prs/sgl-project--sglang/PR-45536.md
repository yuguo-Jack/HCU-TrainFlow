# [Feat] DSpark: Add opt-in online latency cost correction

[Upstream PR](https://github.com/sgl-project/sglang/pull/45536) · state: open · merged: False

## Original PR description

## Motivation

Feed completed-step latency observations back into DSpark's existing confidence-budget cost estimate when runtime conditions differ from the initial profile, without retraining the model or confidence head.

Refs #45515. Related roadmap: #42170.

## Modifications

- Opt-in `SGLANG_DSPARK_ONLINE_COST_CORRECTION=1`, disabled by default.
- Signed median residuals against the immutable SPS baseline, keyed by `(request count, physical verify tokens)`. Keep 64 recent valid observations; require at least 8 per shape. Unseen/expired shapes retain the baseline.
- Price physical CUDA Graph tiers and synchronize corrections before attention-TP budget selection.
- Admit timings only after three consecutive observations with identical physical geometry and contiguous forward counters, accounting for the two-step overlap timing lag without additional GPU synchronization.
- Initial scope: compact verification with a profiled table, unified serving, CP=PP=1, no DP attention.

Inspired by [DeepInfer's runtime cost feedback](https://github.com/deepseek-ai/DeepInfer/blob/8b16149741a4935e1dec8cea27853f273b374c5b/csrc/engine/mtp_varlen.hpp). This implementation reuses SGLang's whole-service-cycle cost infrastructure. No new training or package dependency.

## Accuracy Tests

- 101 tests and 24 subtests passed, including the overlap-transition regression; independent reviews found no outstanding production issue.
- Controlled same-engine DeepSeek-V4.1-Flash GSM8K comparison: original scheduler, physical-tier pricing, and online feedback each scored 122/128 on a fixed official test subset. Official chat encoding, normal EOS, identical inputs, fixed seeds, and temperature zero.
- This is aggregate subset validation, not a universal or per-example accuracy guarantee; numerical/token variability also occurs in the original scheduler.
- Local compact model experiments apply the separately authored prerequisite #42718. Its code is excluded from this PR.

## Speed Tests and Profiling

**Performance validation is in progress; this PR remains a draft. No general speedup is claimed.**

Expanded experiments target 8K–64K contexts, up to 64 concurrent requests, and changes in context length and offered load. The initial short-context cost table stays fixed so the tests can measure adaptation to real runtime cost drift.

Compare original scheduling, physical-tier pricing without feedback, and online feedback on the same loaded engine. Exploration runs and independent confirmation repeats are recorded separately. Shared-prefix warm-cache decode and request-burst workloads are distinguished from cold-prefill end-to-end serving. Any reported improvement will identify its workload, cache condition, concurrency, and tested limits.

Hardware: **8 x H200**. Complete measurements and raw traces are retained locally while validation continues.
