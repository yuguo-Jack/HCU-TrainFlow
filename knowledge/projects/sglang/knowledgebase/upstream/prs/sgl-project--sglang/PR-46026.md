# [Feat] [NPU] DeepSeek-V4: Adapt Mooncake L3

[Upstream PR](https://github.com/sgl-project/sglang/pull/46026) · state: open · merged: False

## Original PR description

Follow-up to #41642 (already merged). Two NPU-side fixes that are needed to run DeepSeek-V4 with a reduced layer count and with an L3 (HiCache storage) backend, plus MemCache parity for the new V4 pools.

## 1. Load MTP drafts of checkpoints reduced with model overrides

When a DeepSeek-V4/GLM checkpoint is loaded with a reduced `num_hidden_layers`, the MTP/nextn weights are still stored under the *original* layer indices, so the nextn layer name was derived from the reduced count and the weights were not found (the model ended up with `model.decoder0...`-style garbage names and the fused qkv-a-proj quant sidecars were looked up for layers that do not exist).

- add `get_nextn_layer_id()` that derives the nextn layer id from `original_num_hidden_layers`;
- use it for the DSV4/GLM4-MoE nextn layer names and for the `mtp.*` -> `decoder.*` weight remap;
- skip absent quantization sidecars of the fused qkv-a-proj for layers that the checkpoint does not contain.

Verified on Ascend 910 with `DeepSeek-V4-Flash-w8a8-mtp` (43 -> reduced layers) + NEXTN speculative decoding: weights load, draft layers run.

## 2. L3 residency for the DeepSeek-V4 C128 sidecar

On NPU, the C128 compressed-KV pool is an independent radix-tree component (`req_to_c128_sidecar`), not a KV-derived sidecar as on GPU. It therefore never took part in L3 backup/restore, and the C128-side prefix validator kept failing, which dropped the whole prefetched span (`storage_prefetch_hit_tokens=6144` but `cached_tokens=0`).

- give the component a `pool_name`, expose `block_pages / _kernel_page_size / _group_tokens / _block_transfer`;
- implement `prepare_prefetch()` / `alloc_prefetch_staging()` and the `BACKUP_STORAGE` / `PREFETCH` builds, and commit `PREFETCH` transfers in `commit_hicache_transfer()`;
- teach the hybrid cache controller to share prefetch requests and to sync trailing keys for `BLOCK_GROUPS` pools;
- implement `PoolHitPolicy.BLOCK_GROUPS` in the mooncake store (one key per compressed block; the block verdict must not shorten the KV prefix).

After the fix, `DeepSeek-V4-Flash-w8a8-mtp` (TP8) restores 6144 tokens from L3 (`cached_tokens=6144`) and the output matches the cold-preload baseline exactly.

## 3. MemCache L3 store: V4 KV anchor + C128 block groups

DeepSeek-V4 builds the FULL/anchor KV pool as a `LogicalHostPool`: it owns page-aligned token slots but no tensor, and all physical bytes live in the per-component paged pools registered through `register_mem_host_pool_v2()`. The mooncake store already treats that anchor as a no-op KV object; the MemCache store crashed on `kv_buffer is None`.

- skip KV registration/copy/lookup for the logical anchor and report the requested page count as the KV verdict;
- implement `PoolHitPolicy.BLOCK_GROUPS` (same semantics as the mooncake store).

This last part is the MemCache counterpart of change 2; the mooncake path is the one exercised end-to-end above, the MemCache path was validated on the Qwen hybrid model (with a logical-anchor-less pool) and by code inspection only.

## Notes
- No behaviour change on GPU; all new code is under `hardware_backend/npu` or behind the new pool/`BLOCK_GROUPS` types.
- Happy to split this into separate PRs if you prefer.
