# [Perf] dsv4: Vectorize paged KV cache dequantization

[Upstream PR](https://github.com/sgl-project/sglang/pull/42929) · state: closed · merged: True

## Original PR description

## Summary

The V4 paged KV-cache dequant kernel processes one token per program, issuing small loads when gathering a long compressed history. This PR processes four tokens per program while preserving the per-element dequantization arithmetic and BF16 RoPE copy.

Compressed-cache reuse across a `kv_source` group is already provided by upstream. This PR is limited to the V4-layout dequant kernel and its correctness test.

Related issue: https://github.com/sgl-project/sglang/issues/42170

## Implementation

- Vectorize the V4-layout kernel to four tokens per program: a `[4, 8, 64]` FP8 load, a `[4, 8]` scale load, and a `[4, 64]` BF16 RoPE load. Mask the padded scale tile and incomplete token groups.
- Preserve the existing output row stride and 64-bit cache-offset arithmetic.
- Add a registered zero-tolerance dequant test against the Torch reference, covering token tails, both page sizes, an int64 page table, and a shared-workspace output slice.

![V4 dequant kernel: one to four tokens per program](https://github.com/user-attachments/assets/9ac92803-f3b2-4807-8c3b-f751e2a6af06)

## Performance

Previously recorded kernel measurements on an idle B200, page size 256, V4 layout:

| Gathered rows | One token/program | Four tokens/program |
|---|---|---|
| 262K | 0.381 ms | 0.089 ms |
| 524K | 0.754 ms | 0.171 ms |
| 16K | 0.019 ms | 0.020 ms |

These are measurements from before the rebase, not a fresh benchmark of the current head. The long-gather kernel speedup is approximately 4.3–4.4×; the 16K case remains launch-bound. End-to-end TTFT has not been remeasured against the rebased base, which already includes dequant reuse. The vectorization applies to `KVLayout.V4`; V4.1 layouts continue to dispatch to their existing dequant kernels.

## Validation

- The retained kernel test compares against the Torch reference with `atol=0`, `rtol=0`, and `equal_nan=True`.
- The original B200 run recorded three test methods passing in 4.5 s. GPU tests have not been rerun after the rebase and scope reduction.
- Local validation: Python syntax, kernel/reference import symbols, and `git diff --check`. This host has no PyTorch/Triton installation.
