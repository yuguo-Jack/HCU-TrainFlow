# [CI] diffusion: Refresh the LTX-2 two-stage runtime VRAM baseline for the cached prompt K/V

[Upstream PR](https://github.com/sgl-project/sglang/pull/47962) · state: closed · merged: True

## Original PR description

## Motivation

The H100 2-GPU diffusion job fails `ltx_2_two_stage_t2v` on its `Runtime Peak VRAM (allocated)` check (row T15 in #42752):

```
Actual:   55831.6900 MiB
Expected: 54736.0000 MiB
Limit:    55830.7200 MiB (rel_tol: 2.0%, abs_pad: 128.0 MiB)
```

The baseline is stale, not a regression. #46105 (merged 10-24) caches the prompt's cross-attention K/V for the whole denoising loop, which costs exactly the memory that appeared.

**When it moved.** I read the case's summary-table row from `multimodal-gen-test-2-gpu` in main's scheduled `pr-test` runs (188 attempts, 09-28 to 11-02):

| Scheduled runs | Commit | Runtime allocated peak (MiB) |
|---|---|---|
| 09-28 to 10-23 23:09 (46 runs) | ... `855c092deb` | 54657–54729 |
| 10-24 11:08 onward (17 runs) | `3ea7e210d2` ... | 55808.43 or 55831.69 |

The load peak stayed at 43411 MiB throughout.

**Why it moved.** #46105 ("Project LTX-2 prompt K/V once per denoising loop") is in the `855c092deb..3ea7e210d2` window. It writes every block's prompt K/V into persistent per-block buffers. For LTX-2 (48 blocks, 1024 text tokens, bf16, batch 1 per rank under CFG parallel), that's:
- video `attn2`: 48 × (K + V) × 1024 × 4096 × 2 B = 768 MiB
- audio `audio_attn2`: 48 × (K + V) × 1024 × 2048 × 2 B = 384 MiB
- total 1152 MiB, against an observed step of 55808 − 54657 = 1151 MiB.

The trade is intended: the PR reports about 3.6 ms saved per stage-1 step. The two values 24 MiB apart (55832 vs 55808) equal one block's K/V (16 + 8 MiB), most likely a transient per-block buffer that sometimes overlaps the peak. 55832 is 0.97 MiB over the limit and 55808 is under it, so each attempt is a coin flip weighted toward failing (55832 on 46 of 61 post-jump attempts). Main survives on the job's retries most of the time, but it has failed outright: all 7 attempts were 55832 on 10-27 11:05 and 10-28 23:06.

## Modifications

Refresh only `ltx_2_two_stage_t2v` in `perf_baselines/h100.json`, using the file's calibration policy (observed max plus 1% for allocated memory):
- `runtime_peak_allocated_mb`: 54736 → 56390 (55831.69 × 1.01). The limit becomes 57517.8 MiB.
- `runtime_peak_vram_mb` (reserved, reported only when an allocated reference exists): 57528 → 58834, the observed max.
- Load peaks and timings are unchanged. `rel_tol` is unchanged.

Other LTX cases aren't affected: `caches_prompt_kv` is false for LTX-2.3 (`cross_attention_adaln`), and `b200.json` has no `ltx_2_two_stage_t2v` entry.
