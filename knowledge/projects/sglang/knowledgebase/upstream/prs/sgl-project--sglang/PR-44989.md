# [Perf] [AMD] mla: One-launch q_a / kv_a norms and q_b projection for Kimi-K3 decode on gfx950

## Motivation

Ahead of the absorbed MLA decode/verify, Kimi-K3 TP8 runs the q_a / kv_a RMSNorms (aiter `fused_qk_rmsnorm`) and the
q_b projection (the tuned GEMM) as separate launches per MLA layer and step. This is the last and smallest piece of
the series: the kernel is faster, but end to end it is neutral (see below).

## Modifications

Gated on `is_gfx95_supported()`.

- The q_a / kv_a RMSNorms and the q_b projection of decode-sized batches run as one launch (`mla_q_norm_proj`,
  <= 16 rows, `SGLANG_ROCM_K3_MLA_Q_NORM_PROJ`), enabled per layer by Kimi-K3 after weight loading.

`DeepseekV2AttentionMLA` gains `fused_q_norm_proj` (False), so other DeepSeek-family models keep their decode path.

| New env var | Default |
|---|---|
| `SGLANG_ROCM_K3_MLA_Q_NORM_PROJ` | on |

## Accuracy Tests

**Setup for every number below:** 8x MI350X (gfx950, 1000 W), Kimi-K3 (MXFP4 MoE, bf16 attention) at TP8 with EAGLE3
(topk 1, 3 steps, 4 draft tokens), FP8 KV cache, `SGLANG_USE_AITER=1`, aiter's K3 FlyDSL kernels
(`AITER_SITUV2_A8W4=1 AITER_FLYDSL_FORCE=1 SGLANG_AITER_K3_OPT=1`), CUDA graphs for bs 1/2/4/8/16, and an aiter bf16 GEMM table with K3 rows re-tuned on this pod with HBM-resident weights
(`AITER_CONFIG_GEMM_BF16`; not part of this PR, it belongs in aiter's model configs). EAGLE3 on K3 needs the
aux-capture commit of #43599, applied locally for these runs. Microbenchmarks rotate their weights through HBM.
Per-feature numbers were measured on the integration branch of this series as each piece landed (Oct 13-14,
earlier `main`). All branches of the series are on `main` 4eb606b2ae (2026-10-17); the kernel tests below ran on this
branch, and the end-to-end checkpoints on that `main` plus the queue up to each slot.

- `test_mla_decode_gfx950.py` (extended): norm + q_b projection matches aiter's rounding. On MI350X, with #44983's
  and #44984's cases: 5 passed (22 subtests).
- End to end: GSM8K 200 0.990 with and without this PR (slot-11 and slot-12 checkpoints below).

## Speed Tests and Profiling

- q_a / kv_a norm + q_b: 1 row 6.73 -> 4.99 us, 4-16 rows -4..-9% vs aiter `fused_qk_rmsnorm` + the tuned GEMM.
- End to end it is neutral: C1 decode cycle 15.7 ms at slot 11, 15.6 ms with this PR at slot 12. That is why it is
  last in the queue.
