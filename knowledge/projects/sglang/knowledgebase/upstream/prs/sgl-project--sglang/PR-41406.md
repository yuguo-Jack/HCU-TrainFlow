# [XPU] Enable ring attention on XPUAttentionBackend

[Upstream PR](https://github.com/sgl-project/sglang/pull/41406) · state: closed · merged: True

## Original PR description

## Motivation

Ring attention (`--ring-degree > 1`) is rejected on XPU. `XPUAttentionBackend` never overrides `supports_ring_rotation()`, so it inherits `False`, and the admission check in `layers/attention/layer.py` turns ring down before the kernel is called.

## Modifications

1. `XPUAttentionBackend.supports_ring_rotation()` now returns `True`.
2. `XPUAttentionImpl.forward` reshapes the LSE before returning it.

sgl-kernel-xpu's `flash_attn_func` is varlen only. `forward` packs q as `(B * S, H, D)`, so the kernel returns the LSE as a 2D tensor `(H, B * S)`. Both places that call `forward(..., return_softmax_lse=True)` expect `[B, H, S]`:

- **Ring attention** (`ring_attn` in `layers/usp.py`): torch's `_templated_ring_attention` merges each ring step's output using the LSE. With the 2D LSE this fails with a bare `AssertionError` in `_SDPAMerger._merge_one`.
- **Replicated KV under ring** (`_replicated_kv_attention` in `layers/attention/layer.py`, used by the replicated prefix/suffix paths): it merges the ring result with a local pass over the replicated KV using `_merge_attention_partials`, which expects `[B, H, S]`.

`view(H, B, S)` splits the packed token dim back into batch and sequence, and `permute(1, 0, 2)` moves batch to the front.
