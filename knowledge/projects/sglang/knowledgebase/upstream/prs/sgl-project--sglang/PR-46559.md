# [Fix] [CPU] Fix: Qwen3.5-35B-A3B-GPTQ-Int4 quantization rule failure and accuracy degradation

[Upstream PR](https://github.com/sgl-project/sglang/pull/46559) · state: open · merged: False

## Original PR description

## Motivation

- When attempting to load the `Qwen3.5-35B-A3B-GPTQ-Int4` model, we discovered that a projection layer (`in_proj_ba`)—which should have been excluded from quantization—was incorrectly identified by the CPU execution path as being quantized via GPTQ.
- Furthermore, the dequantization process follows an outdated GPTQ convention by erroneously adding 1 to the model's symmetric zero-points, which leads to accuracy issues.

## Modifications

- Modified `gptq.py` at line 238. The original `FusedMoE` branch is preserved, while the selection logic for standard linear layers is delegated to an existing utility function (`get_linear_quant_method`) within the repository.
- Retain the `sym` flag for checkpoints in GPTQ configurations. For the CPU-based GPTQ backend—specifically regarding linearly quantized standard linear layers and fused MoE layers—normalize the packed zero-point value to 7; the existing unpacking logic will then add 1 to this value, yielding the correct result of 8.
