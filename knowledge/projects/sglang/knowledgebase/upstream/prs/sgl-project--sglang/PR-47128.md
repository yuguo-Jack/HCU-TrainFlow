# [Perf] [AMD] gdn: Use strided prefill projection views on ROCm

[Upstream PR](https://github.com/sgl-project/sglang/pull/47128) · state: open · merged: False

## Original PR description

## Motivation

On CUDA, GDN prefill reads q/k/v/z/b/a as strided views of the input projection (`qwen3_5_gdn_prefill_projection_views`). ROCm still copies them into contiguous buffers with `fused_qkvzba_split_reshape_cat_contiguous_kernel.`(conv1d, chunked GDN, gated norm) already take strided inputs, so on ROCm the copy is pure overhead.

## Modifications

- `Qwen3_5GatedDeltaNet.forward`: enable `use_strided_prefill_z` on HIP as well as CUDA (`_is_cuda` -> `_is_cuda or _is_hip`).
- Affected: prefill (extend without speculative decoding) in the GDN linear-attention layers, for models whose v/k head ratio takes the fused-unpack branch.
- It applies to models whose head ratio takes the fused-unpack branch. Qwen3.8-Flash-Next (ratio 3) reaches that branch once #44302 is merged.

## Accuracy Tests

GSM8K, full 1319 questions, 5-shot, real MTP acceptance. MI355X, TP1, `SGLANG_USE_AITER=1`.

| Model | before | after |
|---|---:|---:|
| Qwen3.8-Flash-Next MXFP4 (on top of #44302) | 97.73% | 97.73% |

Qwen3.5-397B-A17B MXFP4 (ratio 4), TP1, cookbook MI355X env, `few_shot_gsm8k` with 400 questions: 92.0% before, 94.8% after.

`test_gdn_prefill_layout.py` and `test_gdn_fused_split_head_ratios.py` pass on MI355X with and without `SGLANG_USE_AITER`. The exception is the compact conv block-table subtests, which cover a CUDA-only feature and fail on HIP with or without this change.

## Speed Tests

Qwen3.8-Flash-Next MXFP4 on top of #44302, MI355X TP1, MTP 3/1/4, random dataset ISL 32768 / OSL 4096, concurrency 16, 48 prompts, 2 runs per arm.

| | before | after | Δ |
|---|---:|---:|---:|
| Mean TTFT (ms) | 8662 | 8440 | **-2.6%** |
| Output throughput (tok/s) | 964.4 | 972.0 | +0.8% |
| Mean TPOT (ms) | 14.48 | 14.40 | -0.6% |

The gain is in prefill. All "after" runs beat all "before" runs on TTFT, in this test and in an earlier one with a different server config (TTFT -2.6% there as well).
