# [Fix] [AMD] mimo-v2.6: Enable MXFP4 on ROCm

## Motivation

  `XiaomiMiMo/MiMo-V2.6-Pro-RL` produced corrupted multilingual output on MI355X despite reaching server-ready state.
  The native MXFP4 loader interleaves gate/up weights by default, but did not record that layout. Because MiMo uses plain SiLU with `swiglu_limit=0`, the AITER quant-info path omitted `GateMode.INTERLEAVE`, causing AITER to interpret interleaved  weights as separated.
  Additionally, the MiMo multimodal processor imported `torchcodec` unconditionally, preventing text-only startup when the optional audio dependency was missing or incompatible

## Modifications

  - Make `torchcodec` optional for MiMo processor initialization.
    - Catch `ImportError` and `OSError`.
    - Audio detection returns unavailable while text/image serving can start.
  - Record the actual AITER gate/up layout after native MXFP4 weight shuffling.
  - Forward `GateMode.INTERLEAVE` or `GateMode.SEPARATED` whenever layout metadata is available, independent of `swiglu_limit`.
  - Add CPU unit regressions for:
    - recording interleaved native MXFP4 layout;
    - forwarding interleaved layout with `swiglu_limit=0`.
  No AITER kernels or attention implementations are changed.

## Accuracy Tests

  Validated on 8× AMD Instinct MI355X with:
  - Model: `XiaomiMiMo/MiMo-V2.6-Pro-RL`
  - TP=8, EP=8
  - AITER MXFP4 MoE
  - Decode CUDA/HIP graphs enabled
  - `AITER_BF16_FP8_MOE_BOUND=0`
  Before this fix, both chat and raw completions returned corrupted multilingual token sequences.
  After this fix:
  - `15% of 240` → `36`
  - `The answer to 2 + 2 is` → coherent completion beginning with `4`
  - GSM8K, 5-shot, 10 samples:
    - flexible exact match: `0.9`
    - strict exact match: `0.9`

  ### Reproduction

  Run on 8× MI355X:
  ```bash
  SGLANG_USE_AITER=1 \
  AITER_BF16_FP8_MOE_BOUND=0 \
  python3 -m sglang.launch_server \
    --model-path XiaomiMiMo/MiMo-V2.6-Pro-RL \
    --served-model-name XiaomiMiMo/MiMo-V2.6-Pro-RL \
    --tp 8 \
    --ep 8 \
    --moe-runner-backend aiter \
    --moe-dense-tp-size 1 \
    --attention-backend triton \
    --mm-attention-backend triton_attn \
    --disable-cuda-graph \
    --trust-remote-code \
    --host 0.0.0.0 \
    --port 30000
  ```
  Then:
  ```bash
  curl http://localhost:30000/v1/chat/completions \
    -H 'Content-Type: application/json' \
    -d '{
      "model": "XiaomiMiMo/MiMo-V2.6-Pro-RL",
      "messages": [{"role": "user", "content": "What is 15% of 240? Give only the number."}],
      "chat_template_kwargs": {"enable_thinking": false},
      "temperature": 0,
      "max_tokens": 64
    }'
  ```
  Before this fix, the request returns garbled multilingual output. After the fix, it returns `36`.

## Speed Tests and Profiling

  There is no meaningful performance comparison against the previous behavior because its output was incorrect.
  The corrected TP8/EP8 configuration completed an 18-point OOB sweep:
  - 1k input, concurrency 256: 8,003 output tok/s
  - 8k input, concurrency 256: 3,115 output tok/s
  - 60k input, concurrency 64: 224 output tok/s
  - DFlash accept length: approximately 7.3–7.6 tokens
