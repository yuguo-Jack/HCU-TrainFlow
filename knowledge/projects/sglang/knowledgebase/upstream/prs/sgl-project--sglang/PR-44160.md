# [Fix] multimodal: Preserve caller hashes and offsets for precomputed inputs

[Upstream PR](https://github.com/sgl-project/sglang/pull/44160) · state: open · merged: False

## Original PR description

## Motivation

Caller-provided `hash` and `offsets` on a `precomputed_embedding` input currently land in `model_specific_data`. The native item therefore has no hash or offsets, so SGLang rediscovers spans and hashes the feature instead of using the supplied identity.

Preserve those fields, matching the existing processor-output metadata handling. This is a small first step toward #44159.

## Modifications

Two production lines move `hash` and `offsets` into the existing `MultimodalDataItem` fields. Inputs without them retain the current defaults. The caller payload and embedding tensor are unchanged.

The hash uses SGLang's existing integer representation and is trusted as the precomputed item identity. Its hash-derived pad IDs participate in prefix-cache keys and downstream KV-event hashes. This is separate from the raw-media `content_hash` trust setting; no new SHA-string field or cache-key format is introduced.

## Accuracy Tests

Added a regression to the existing CPU-CI-registered `test_precomputed_embedding_validation.py` (`base-a-test-cpu`). One small regression exercises native item finalization and checks that the supplied hash and offsets survive.

Six isolated source-extracted CPU checks pass; the new regression fails against the pre-change source. Full-package execution is pending upstream CI: the local lightweight environment could not import the suite because it lacks `psutil`. Ruff formatting/import checks and whitespace checks pass.

## Speed Tests and Profiling

No kernel/model-math changes; no model benchmark run.
