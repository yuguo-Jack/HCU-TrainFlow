# [Fix] function_call: keep a stray closing function tag inert in qwen3_coder streaming

[Upstream PR](https://github.com/sgl-project/sglang/pull/45244) · state: open · merged: False

## Original PR description

## Summary

Fixes #45226.

In the qwen3_coder streaming detector, a model that repeats the closers after a complete call (the `</invoke></function></tool_call>` tail from the issue's shape A) hit the `</function>` branch with no function open (`current_func_name` was cleared when the call closed) and got a second `}` appended into the finished call's arguments — `{"ref": "p9"}}`, invalid JSON. Each stray `</function>` added one more.

The branch now only emits the closing brace when a function is actually open; a stray `</function>` is consumed without output, matching the one-shot `detect_and_parse` behavior the issue measured. The empty-parameters path (`<function=name>` straight into `</function>`) is unchanged — the function is open there, so `{}` is still emitted correctly.

## Test plan

- New regression test `test_streaming_stray_closing_tags_do_not_corrupt_arguments` (the issue's shape A as chunked streaming input): the finished call's arguments stay valid JSON.
- `pytest test/registered/function_call/test_function_call_parser.py -k Qwen3Coder`: 14 passed (CPU, local).
- Mutation check: with the guard removed the new test fails on the invalid JSON (restored green).
- Full file: 139 passed + 7 pre-existing `TestDeepSeekV32Detector` failures that fail identically on unmodified main in this environment (no GPU here), so they are not from this change.
