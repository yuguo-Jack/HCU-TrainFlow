# [Feat] lora: Add plan-driven dense and MoE LoRA engines

[Upstream PR](https://github.com/sgl-project/sglang/pull/45892) · state: closed · merged: True

## Original PR description

## Motivation

Provide a single-PR alternative for merging the complete, currently published 21-part LoRA runtime stack. This is the same implementation and history, not a separate development variant.

The existing stacked PRs remain open and unchanged. Choose one merge route; this PR does not add a 22nd feature layer.

## Modifications

- Plan-driven dense LoRA execution through `triton_v2`, shared routing/workspace management, grouped and per-row shrink/expand kernels, and shipped SM90/SM100 plans.
- LoRA-free decode graphs, absorbed-MLA corrections, and Inkling shared-sink integration.
- Per-expert and shared-outer MoE LoRA execution, with Triton/CuTeDSL BF16 and FP8 providers and the Marlin NVFP4 provider.
- The stack's existing correctness, CUDA-graph, numerical, serving-integration tests and runtime configuration tables.

This branch reuses the final stack commit directly: no squash, rebase, cherry-pick, source edit, or additional commit. Benchmark/tuning tools and the deferred Triton MoE tuning-table changes from the development branch are intentionally excluded, exactly as in the stack.
