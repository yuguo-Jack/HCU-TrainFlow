# [Fix] rust-server: Serve /v1/loads from every listener under multi-node DP attention

[Upstream PR](https://github.com/sgl-project/sglang/pull/47319) · state: closed · merged: True

## Original PR description

## Motivation

Under multi-node DP attention, schedulers publish their load snapshots over ZMQ to a collector on node 0, so no scheduler owns a shared-memory snapshot file. The embedded Rust server (`SGLANG_RUST_SERVER=1`) serves `/v1/loads` from that file, so in this topology every listener on every node answered 503 (`load snapshots are not published to shared memory`), and a router polling the listeners read every rank as idle, both for routing and for autoscaling signals.

The node-0 collector is of no use in Rust mode either: its owner is the TokenizerManager (absent in Rust mode) or a DataParallelController that reads loads only on dispatch, which Rust listeners bypass.

## Modifications

A Rust listener runs in its rank's scheduler process and reads only that rank's slot, so it needs no node-0 collector. `should_use_zmq()` now keeps the shared-memory transport under multi-node DP attention when the Rust server is on: each rank writes its slot of a file on its own node and its own listener reads it. Each listener still reports only its own rank.

Unchanged:

- Python mode (multi-node DP attention still uses the ZMQ transport to node 0);
- single-node deployments;
- the `SGLANG_LOAD_SNAPSHOT_USE_ZMQ` override, which still forces ZMQ, so a listener answers 503 there.

No Rust change: the fix is the three-line condition in `should_use_zmq()`; the rest is the docstring and module doc that describe the transports, the comment in `rust_server/config.py` that explains which writer the listener is given, and tests.

## Testing

- `test_load_snapshot_backends.py`: `should_use_zmq` is tabled over (node count, attention-DP size, Rust mode, forced ZMQ) with six subtests; the multi-node + Rust case is the one that flips.
- `test_rust_server_dp_ports.py`: a listener test builds the server args for the two DP leaders on the last node (single-node, multi-node, forced ZMQ) and checks each listener gets its own slot of a node-local file, or no file at all under forced ZMQ.
- `pytest test/registered/unit/entrypoints/test_rust_server_dp_ports.py test/registered/unit/managers/test_load_snapshot_backends.py`: 72 passed, 6 subtests passed. With the `should_use_zmq()` change reverted, exactly the two new multi-node Rust cases fail.
- pre-commit on the changed files: passed.
