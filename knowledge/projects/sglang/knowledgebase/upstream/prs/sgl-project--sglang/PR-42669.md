# [Bugfix] Disable mixed chunk for PP speculative decoding

[Upstream PR](https://github.com/sgl-project/sglang/pull/42669) · state: open · merged: False

## Original PR description

## Motivation

Pipeline-parallel EAGLE/MTP speculative decoding crashes on the first mixed batch when `SGLANG_ENABLE_PP_SPEC=1` and `--enable-mixed-chunk` are used together. The mixed batch carries `EagleDraftInput`, while the PP verify rebuild path expects `PPSpecRelayInput` and accesses its `rids` field.

Until the PP relay supports mixed batches, turn this unsupported combination into a startup-time configuration downgrade instead of a scheduler crash.

Fixes #42648.

## Modifications

- Disable mixed chunked prefill when aggregate PP speculative decoding is enabled (`pp_size > 1` with `SGLANG_ENABLE_PP_SPEC=1`).
- Emit a targeted warning when the downgrade is applied.
- Preserve mixed chunking for single-stage speculative decoding and PP speculative PD-prefill.
- Move the existing no-server PP-spec gate tests from the multi-GPU E2E file to the server-argument unit suite, and add regression coverage for the downgrade and both preserved configurations.

## Accuracy Tests

Not applicable. This changes startup argument resolution only; model forward code and model outputs are unchanged.

Focused tests:

- `TestPipelineParallelCompat` + `TestPPSpecGate`: 17/17 passed in the official SGLang container without GPU passthrough.
- Controlled resolution check: unpatched `main` keeps `enable_mixed_chunk=True`; this patch logs the warning and resolves it to `False` for aggregate PP spec.
- `pre-commit run --all-files`: passed.

The provided validation VM exposes one A100, so the original `pp_size=2` scheduler reproduction could not be run locally.
