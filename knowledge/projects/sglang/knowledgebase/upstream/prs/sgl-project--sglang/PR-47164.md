# [Perf] lora: Avoid O(tokens) per-token expansion in build_lm_head_pass_segments

[Upstream PR](https://github.com/sgl-project/sglang/pull/47164) · state: open · merged: False

## Original PR description

## Motivation

When chunked input logprobs processing (`SGLANG_ENABLE_LOGPROB_CHUNK=True`, default chunk size `2048`) runs with an `lm_head` LoRA adapter (`LoRABackendLmHeadMixing._get_lm_head_pass_segments`), `build_lm_head_pass_segments(weight_indices, pruned_lens, logprobs_chunk_size)` in `python/sglang/srt/lora/utils.py` previously:
1. Materialized a flat per-token Python list `token_wi` of length `sum(pruned_lens)` via `token_wi.extend([wi] * pl)`.
2. Iterated token-by-token in Python across each chunk pass (`for t in range(start, end):`) to run-length encode consecutive adapter indices.

Because each request already contributes a contiguous run of `pl` tokens assigned to the same adapter index `wi`, expanding to `O(total_pruned_tokens)` and re-scanning token by token in Python is unnecessary and adds ~20 ms of CPU overhead on long-context prefill batches (e.g., 128K pruned tokens).

## Modifications

- Replace the per-token list materialization and inner token-by-token RLE loop in `build_lm_head_pass_segments` with direct sequence-run splitting across `logprobs_chunk_size` pass boundaries in `O(num_seqs + num_passes)` time and `O(1)` auxiliary space (~680x faster on 128K pruned tokens across 8 sequences: `20.6 ms -> 0.03 ms`; ~240x faster across 256 sequences: `19.5 ms -> 0.08 ms`).
- Validate `logprobs_chunk_size > 0` with a clear `ValueError`.
- Add unit and randomized differential equivalence tests in `test/registered/unit/lora/test_lm_head_pruning.py`.

## Acknowledgments

Builds on the chunked input logprob and LoRA `lm_head` segmentation work by @hnyls2002 (#31655), @jybsuper (#45892, #34337), @glenliu21 (#46743), and @Qiaolin-Yu (#20071).
