# [Perf] diffusion: Serve FA4 head sizes on Blackwell instead of falling back to sm80 SDPA

[Upstream PR](https://github.com/sgl-project/sglang/pull/46102) · state: closed · merged: True

## Original PR description

## Motivation

The CUDA platform decides whether FlashAttention can serve a layer with `FlashAttentionBackend.get_supported_head_sizes()`. That is FA3's list: 32, 64, 96, ..., 256. On Blackwell the FA backend is FA4, which also serves every multiple of 8 up to 128. Other head sizes fall back to `torch_sdpa`. The CUDA platform disables cuDNN SDPA for the whole process, so PyTorch then runs its sm80 FlashAttention-2 kernel (`pytorch_flash::flash_fwd_kernel`).

The Qwen-VL vision towers hit this:
- Qwen3-VL has head size 72. It is the encoder of Qwen-Image-2.1 edit and MiniMax-H3 Ref2VA.
- Qwen2.5-VL has head size 80. It is the encoder of Qwen-Image and Qwen-Image-Edit.

It happens both with the default backend and with `--attention-backend fa`. In both cases the server log shows `Attention backends for text_encoder: torch_sdpa, ...`.

Kernel time on one B300, `[1, H, S, 72]` bf16, non-causal:

| H, S | sm80 FA2 (current) | cuDNN SDPA | FA4 |
|---|---|---|---|
| 16, 23808 | 9.64 ms | 2.37 ms | 2.35 ms |
| 8, 23808 | 5.09 ms | 1.27 ms | 1.27 ms |
| 16, 4096 | 0.340 ms | 0.082 ms | 0.106 ms |

## Modifications

`CudaPlatformBase._resolve_flash_attention_backend_cls_str`: on Blackwell, a head size that is a multiple of 8 up to 128 now counts as FA-capable, which matches FA4's own check for sm100.
- Default backend: these layers take the Blackwell default, `dynamic_cudnn_sdpa`. That is cuDNN SDPA, with FA4 as the fallback.
- `--attention-backend fa`: they run FA4, including its packed-varlen path.
- Hopper, SM12x and ROCm are unchanged.

Tests: `test_cuda_attention_backend.py` adds two cases on a mocked platform.
- Blackwell: head sizes 72 and 80 resolve to `dynamic_cudnn_sdpa` by default and to FA4 when FA is requested. Head sizes 68 and 136 still fall back to `torch_sdpa`. On main, the 72 and 80 subtests fail.
- Pre-Blackwell: head size 72 keeps `torch_sdpa`.

## Accuracy Tests

All three kernels take bf16 inputs and accumulate in fp32. Against an fp32 reference on random inputs (H=16, S=23808, D=72), their max abs error is 2.8e-4 (sm80 FA2), 2.7e-4 (cuDNN) and 2.5e-4 (FA4).

The table compares the vision tower's outputs on main and on this PR, with the real checkpoints and the same request inputs. Each value is the relative L2 difference.

| | deepstack (block 8) | deepstack (block 16) | deepstack (block 24) | merger output |
|---|---|---|---|---|
| MiniMax-H3 Ref2VA, 2976x2048 reference, cuDNN | 1.3% | 2.4–2.5% | 3.7–3.8% | 4.7–4.8% |
| Qwen-Image-2.1 edit, `--attention-backend fa` (FA4) | 1.2% | 2.2–2.3% | 3.3–3.6% | 7.1–8.3% |
| Qwen-Image-2.1 edit, default backend (cuDNN) | 1.2% | 2.2–2.3% | 3.4–3.6% | 6.7–7.7% |

The difference grows steadily with depth, which is how bf16 rounding differences add up over 27 blocks. No single layer jumps.

Each kernel against an fp32 reference. The Qwen3-VL vision tower of Qwen-Image-2.1 (27 blocks, head size 72) ran on the benchmark's edit reference (1248x864 after the stage's resize, 4212 patches), once with fp32 weights and math SDPA as the reference, and once in bf16 per attention kernel. Only the attention kernel changes between the bf16 rows. Each value is the relative L2 difference from the fp32 reference, on one B300:

| bf16 attention kernel | deepstack (block 8) | deepstack (block 16) | deepstack (block 24) | merger output |
|---|---|---|---|---|
| sm80 FlashAttention-2 (main on Blackwell) | 2.40% | 5.34% | 7.68% | 15.09% |
| cuDNN SDPA (this PR, default backend) | 2.40% | 5.50% | 7.84% | 13.86% |
| FA4 (this PR, `--attention-backend fa`) | 2.40% | 5.21% | 7.55% | 14.91% |
| memory-efficient SDPA (for scale) | 2.39% | 5.27% | 7.64% | 15.24% |

The new kernels are as close to fp32 as main's kernel. FA4 is closer at every depth. cuDNN is within 0.2 points at the deepstack taps and closer at the output. The 7-8% kernel-to-kernel difference in the earlier table is the size of bf16 rounding over 27 blocks, the same order as each kernel's distance from fp32. (The same check on H200 gives FlashAttention-2 / cuDNN / memory-efficient at 14.39% / 15.28% / 15.20% for the merger output.)

End to end on B300 (Qwen-Image-2.1 edit, B300 `--attention-backend fa` command), this PR ran stacked with four other changes; that stack measured 2.626 / 2.637 s against main's 2.751 / 2.771 s. The changes measured on their own account for all but ~60-67 ms of that difference, which is the stored-PNG change plus this one.

## Speed Tests and Profiling

Server runs on B300 with each case's serving command. Main and this PR ran side by side on separate GPUs, with requests sent one at a time. The vision-tower time is synchronized wall time around the tower's forward, and the kernel times come from `torch.profiler`.

**MiniMax-H3 Ref2VA**, 2 GPUs with Ulysses 2. The encoder is TP-folded to 8 heads per rank. The reference is 2976x2048, which gives 23808 patches over 27 blocks.

| | main | this PR |
|---|---|---|
| attention kernels per tower forward | 137.5 ms (27x `pytorch_flash::flash_fwd_kernel`, sm80) | 34.2 ms (27x `cudnn_generated_fort_native_sdpa_sm100_flash_fprop`) |
| vision tower | 182–188 ms | 84.5–84.7 ms |
| text-encoding stage, two warm requests | | 116 ms and 107 ms shorter |
| end to end, 50 steps | 103.41 s | 102.99 s |

**Qwen-Image-2.1 edit**, 1 GPU. The reference becomes 4212 patches over 27 blocks.

| | main | this PR, `--attention-backend fa` | this PR, default backend |
|---|---|---|---|
| attention kernels per tower forward | 9.4 ms | 2.9 ms (FA4) | 2.3 ms (cuDNN) |
| vision tower | 21.0–21.5 ms | 18.0–20.8 ms | 14.5–16.7 ms |

For this case the vision tower is a small share of the encoding stage. Encoding-stage and end-to-end times stayed within run-to-run noise.

The first request at a new image size pays for building a cuDNN plan once per sequence length, about 45 ms. On the H3 case's first request the tower took 128 ms on this PR, against 182 ms on main. FA4 builds no per-shape plan.
