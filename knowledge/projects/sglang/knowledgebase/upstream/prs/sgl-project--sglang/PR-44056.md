## Motivation

<!-- Describe the purpose and goals of this pull request. -->
Qwen-Image 2.1 already runs on Ascend through `torch_npu`, but two hot paths in the DiT stay on the slow eager implementations: `QwenImage21Attention` forces the native fp32 QK RMSNorm on every platform, and the complex RoPE goes through the complex64 multiply path. This PR routes both to the CANN operators exposed by `torch_npu`:

- `torch_npu.npu_rms_norm` for `norm_q` / `norm_k`.
- `torch_npu.npu_rotary_mul(..., rotary_mode="interleave")` for the complex RoPE, with the cos/sin tables prepared once per layout and cached.

Cos/sin for `npu_rotary_mul` must be expanded with `repeat_interleave(2)`; a plain `cat((c, c), -1)` pairs the wrong frequencies.

The previously attempted Triton fast-path enablement on NPU is **not** part of this change: the QK-norm+RoPE Triton kernel is not bit-exact for sequence lengths ≥ 1024 and is 60–95× slower than the eager chain on Ascend. The three kernel
files touched by that attempt are restored to their pre-enablement state.

The result is full Qwen-Image 2.1 coverage on one A3 chip: text-to-image, single- and multi-reference editing, transparent RGBA output, and local recolor, with NPU CI cases and baselines.

### Reproduction

```bash
# t2i
sglang generate --model-path /path/to/Qwen-Image-2.1 \
  --prompt "Doraemon is eating dorayaki" \
  --num-inference-steps 40 --guidance-scale 1 \
  --height 1024 --width 1024 --seed 42 --num-gpus 1 \
  --generator-device cuda --save-output
```

```bash
# ti2i (2D -> 3D)
sglang generate --model-path /path/to/Qwen-Image-2.1 \
  --image-path TI2I_Qwen_Image_Edit_Input.jpg \
  --prompt "Convert 2D style to 3D style" \
  --num-inference-steps 40 --guidance-scale 1 \
  --height 1536 --width 1024 --seed 42 --num-gpus 1 \
  --generator-device cuda --save-output
```

```bash
# multi-image edit (two references; edit2509_1.jpg / edit2509_2.jpg from the

  -F "seed=42" -F "quality=lossless" -F "response_format=b64_json"
```

```bash
# local recolor (CI case): orange skirt and bow -> deep blue

  -F "seed=42" -F "quality=lossless" -F "response_format=b64_json"
```

### multi-image editing (A+B)

Two reference images (`edit2509_1.jpg` magician bear, `edit2509_2.jpg` alchemist bear, from the Qwen-Image-Edit-2509 test set), sent as two `image` fields to HTTP `/v1/images/edits`; seed 42, 40 steps, guidance 1, 1024×1024, `quality="lossless"`. The server log confirms the request carries both paths.

- **Composition** — with the multi-image CI prompt ("The magician bear is on the left, the alchemist bear is on the right, facing each other in the central park square."), both identities are preserved (hat/robe/book/wand, graduation  cap/cauldron/fan/Qwen shirt) and placed as instructed.
- **Slot binding** — with "the bear from image 1 … image 2 …", uploading  `[ref1, ref2]` puts ref1 on the left and ref2 on the right; uploading  `[ref2, ref1]` swaps them. The second file lands in `<image2>`; it is not silently dropped or merged into the first.
- **Ablation** — one reference at a time produces only that subject.
- **Determinism** — repeating the request, or running it on a different chip,  reproduces a byte-identical PNG.

The CI case uses the two references staged for the NPU runner (the shared TI2I image and `rabbit.jpg`); the bear pair above is the manual slot-binding check.
