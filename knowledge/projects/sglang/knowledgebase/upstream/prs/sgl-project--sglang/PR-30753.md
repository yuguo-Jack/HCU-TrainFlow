## Motivation
Under tensor parallelism, every KimiLinear decoder layer issues **two independent NCCL AllReduces** — one after attention `o_proj`, one after the MoE/MLP — and each is immediately followed by a residual-add + RMSNorm. On small-batch decode this is latency/launch-bound: 2 collectives + several tiny elementwise kernels per layer, with the `[T, H]` activation bounced through HBM 4–5× per layer.
SGLang already has the fix — `LayerCommunicator` + FlashInfer AllReduce fusion — which folds `AllReduce + residual add + RMSNorm` into a single kernel and uses a low-latency one-shot allreduce for small messages. It is already live for DeepSeek, Qwen3-Next (GDN), Nemotron-H, etc., but **KimiLinear never adopted it**: its `KimiDecoderLayer.forward` is hand-written with `reduce_results=True` on every RowParallel projection, and `KimiLinearForCausalLM` is absent from the auto-enable whitelist.
This PR ports the proven Qwen3-Next (hybrid linear-attn) pattern into KimiLinear so that **both** AllReduces get fused:
- attention `o_proj` AllReduce → fused into the same-layer `post_attention_layernorm`
- MoE/MLP AllReduce → fused into the next-layer `input_layernorm`

## Modifications
`python/sglang/srt/models/kimi_linear.py`
- `KimiDeltaAttention` (KDA) and `KimiMLAAttention` (MLA) `o_proj`: set `reduce_results=False` so the partial output is reduced by the communicator instead of self-reducing. `reduce_results=False` is also required-consistent with MLA's empty-batch short-circuit assertion.
- `KimiMoE.forward`: accept `should_allreduce_fusion` / `use_reduce_scatter` and gate the post-experts AllReduce through `should_skip_post_experts_all_reduce` (mirrors `Qwen2MoeSparseMoeBlock`). Dense `LlamaMLP` layers skip their reduce via `use_reduce_scatter`.
- `KimiDecoderLayer.__init__`: build `LayerScatterModes` + `LayerCommunicator`. `is_last_layer` is wired correctly so the final layer's AllReduce feeds `model.norm` rather than being deferred. A shared `_kimi_is_sparse_layer` predicate computes the prev/next-layer sparsity (Kimi-48B: layer 0 dense, 1–26 MoE).
- `KimiDecoderLayer.forward`: rewritten into the three-stage `prepare_attn → prepare_mlp → postprocess_layer` pattern, with the `_sglang_needs_allreduce_fusion` marker driving the MLP-side fusion. `python/sglang/srt/server_args.py`
- Add `KimiLinearForCausalLM` to the FlashInfer AllReduce-fusion auto-enable whitelist (activates on sm90/sm100, TP>1, non-DP, single-node, `moe_a2a_backend == none`).
The change is numerically equivalent — no new kernels, only a re-routing of where the AllReduce happens.

## Accuracy

  GSM8K 5-shot (1319 questions), Kimi-Linear-48B-A3B-Instruct, TP=2:

  | Run      | Accuracy | Invalid |
  |----------|---------:|--------:|
  | baseline | 0.899    | 0.000   |
  | fusion   | 0.898    | 0.000   |

  Δ = −0.001, within run-to-run noise.

  ## Benchmark

  Kimi-Linear-48B-A3B-Instruct, 2× H20-3e (sm90), TP=2, flashinfer 0.6.11, `bench_serving --dataset-name random --random-input-len 256 --random-output-len 512`.
  baseline = `--enforce-disable-flashinfer-allreduce-fusion`, fusion = auto-enabled.

  | conc | metric            | baseline | fusion | Δ       |
  |-----:|-------------------|---------:|-------:|--------:|
  | 1    | median TPOT (ms)  | 3.65     | 3.63   | −0.5%   |
  | 1    | median TTFT (ms)  | 30.17    | 27.22  | −9.8%   |
  | 1    | P99 TTFT (ms)     | 34.33    | 30.21  | −12.0%  |
  | 4    | median TPOT (ms)  | 4.86     | 4.80   | −1.2%   |
  | 4    | P99 TTFT (ms)     | 89.62    | 78.49  | −12.4%  |
  | 16   | median TPOT (ms)  | 8.21     | 8.20   | neutral |
  | 16   | P99 TPOT (ms)     | 8.76     | 8.50   | −3.0%   |
  | 16   | median TTFT (ms)  | 246.13   | 154.25 | −37.3%  |
  | 16   | P99 TTFT (ms)     | 255.99   | 178.91 | −30.1%  |

  Consistent (small) TPOT wins at low concurrency and a large TTFT reduction across the board, with no regression. At batch sizes above the fuse cap the fusion gracefully no-ops back to NCCL.
