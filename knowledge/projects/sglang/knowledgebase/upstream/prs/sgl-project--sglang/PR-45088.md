# [Test] moe: Pin the Waterfill algorithm end to end

[Upstream PR](https://github.com/sgl-project/sglang/pull/45088) · state: open · merged: False

## Original PR description

## Motivation

Waterfill (`--enable-waterfill`, #19290) routes DeepSeek's always-on shared expert as a 9th top-k slot to an EP rank with headroom. It is layered on generic MoE code -- `TopK`, the DeepEP per-rank-slot layout, `DeepseekV2MoE.forward_deepep`'s epilogue -- and refactors of that code have changed Waterfill's behavior without touching `waterfill.py`. The latest instance is the shared slot ending up at 0.4x whenever top-k folds `routed_scaling_factor` (ModelOpt NVFP4 on `flashinfer_cutedsl`, cutlass / trtllm-routed FP8, aiter), which #44901 fixes; GSM8K accuracy did not move while teacher-forced NLL/token went 0.706 -> 0.858 (see [this comment](https://github.com/sgl-project/sglang/pull/44901#issuecomment-6259502252)). Nothing in the test suite pinned the algorithm, so this PR adds a GPU test that does.

**Depends on #44901.** On current `main` the folded cases of contracts 1, 4 and 5 below fail (shared expert at 0.4x); everything else passes. Please merge this after #44901.

## Modifications

New `test/registered/moe/test_waterfill.py` (`register_cuda_ci(est_time=60, stage="base-b", runner_config="1-gpu-large")`, ~14 s on one GPU). It pins:

1. **TopK layout.** With Waterfill the router is asked for the routed experts only (`top_k - num_fused_shared_experts`, `num_fused_shared_experts=0`, STANDARD output) and the balancer appends the shared column afterwards; `forward` before `prepare_moe_topk` raises.
2. **ID remap.** Routed `e -> e + e // (E/W)`, the shared slot of rank `r` is `r*(E/W+1) + E/W`, routed weights are copied unchanged, padded rows get `-1` / weight 0 in the shared column -- identical on the local path (`expand_topk_with_shared_expert`) and the fused Triton path (`materialize_waterfill_dispatch_fused`); `count_local_routed` equals a bincount.
3. **Rank selection.** Static mode samples the shared rank in proportion to headroom below the water level (ranks at or above it get nothing, home rank preferred 11:10; 8192 tokens, every rank within 15% of its expected share); dynamic mode (`allow_all_ranks=False`) only uses the home rank and the ranks the token's routed experts visit; batches below `MIN_BATCH_FOR_BALANCE` keep the shared expert local; a hot home rank spreads evenly over the seven idle ranks (within 10%); the dynamic water-level formula and `allow_all_ranks` decision; the fused kernel is deterministic.
4. **Shared weight.** `1/routed_scaling_factor` when the epilogue scales the MoE output afterwards, `1.0` when top-k already folded the factor, via `prepare_moe_topk`.
5. **End to end.** `DeepseekV2MoE.forward_deepep` under Waterfill -- real `TopK` and router kernels, stub gate, a linear stand-in for the experts whose expert `i` multiplies its input by `scale[i]` -- equals `rsf * sum_i w_i E_i(x) + S(x)` for both scaling modes and for both the local (16 tokens) and the fused (1024 tokens) expansion. The reference takes the routed experts and normalized weights from `biased_grouped_topk_gpu` itself, so near-tied scores cannot make the two sides disagree.

The `DeepseekV2MoE` construction follows the stub pattern of `test_fused_shared_expert_scaling.py` in #44901 (patched `MoEGate`, `get_moe_impl_class`, `get_parallel`, `get_exec`, a2a backend, `ExpertLocationDispatchInfo.init_new`).
