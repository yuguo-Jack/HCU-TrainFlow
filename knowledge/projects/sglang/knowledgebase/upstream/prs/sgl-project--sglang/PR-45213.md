# [Perf] mamba: Copy tracked decode states at HBM bandwidth in one persistent launch

[Upstream PR](https://github.com/sgl-project/sglang/pull/45213) · state: closed · merged: True

## Original PR description

## Motivation

`track_mamba_state_if_needed_kernel` copies a request's conv and ssm state rows from `cache_indices[i]` to `mamba_track_indices[i]` whenever `mamba_track_mask[i]` is set, so the state can be reused across turns. It launched one program per batch row, so a single SM copied one whole state row for one layer: the copy's parallelism was bounded by the number of tracked rows rather than by the amount of data, and a backend that calls the copy once per layer serialized that work once per layer. The copy is pure bandwidth, so it should run on every SM.

## Modifications

- `track_mamba_state_if_needed_kernel` is now persistent. Every program reads the whole track mask, the tracked rows are compacted in-kernel (`cumsum` over the mask), and their (row, layer, 32 KB chunk) work items are strided over a grid of four programs per SM. A step with no tracked row reads one mask vector per program and exits; one tracked row runs at HBM bandwidth on every SM. `batch_size` and `num_layers` are `do_not_specialize`, so the graph-captured launch does not recompile per batch size.
- `track_mamba_states_if_needed` and `track_mamba_states_all_layers` keep their signatures and share one launcher, `_launch_track_mamba_states`; the separate `track_mamba_states_all_layers_kernel` is removed. The per-layer wrapper passes a zero layer stride and `num_layers=1`.
- The copy is bitwise identical to the old kernel, including the freed-slot (`-1`) skip for the unified pool and the int64 index promotion before the row-stride multiply. It stays CUDA-graph safe: the grid depends only on the padded batch size, the layer count and the pool shapes, and the mask is read on the device at replay.
- New `test/registered/unit/layers/test_mamba_track_states_triton.py` (base-b, 1-gpu-small, ~20 s) checks both wrappers against a torch reference over padded batches 1..40, mixed conv/ssm dtypes, freed slots, partial chunks with the persistent loop forced onto one SM, every row tracked, and CUDA-graph replay with a changing mask.

Tests:
- `python -m pytest test/registered/unit/layers/test_mamba_track_states_triton.py`: 6 passed on one B300-class GPU against this branch.
- `pre-commit` on the two changed files is clean (isort, ruff, ruff-format, codespell, registered-test checks).

## Accuracy Tests

Not applicable: the copy is bitwise identical to the old kernel. The new unit test asserts `torch.equal` against a torch reference for both wrappers, and a direct old-vs-new comparison on the benchmark shape below was bitwise equal.

## Speed Tests and Profiling

Measured for this PR with the script below, which runs the kernel file from `main` (saved as `old_mamba_state_scatter_triton.py` next to the script) against this branch under CUDA-graph replay on one B300-class GPU. Shapes: 36 linear-attention layers, padded batch 40, conv state `(8192, 3)` and ssm state `(32, 128, 128)` in bf16 (about 1 MB per row per layer). "per-layer x36" is `track_mamba_states_if_needed` called once per layer; "all-layers" is one `track_mamba_states_all_layers` launch.

| tracked rows | old per-layer x36 | old all-layers | new per-layer x36 | new all-layers |
|---|---|---|---|---|
| 0 | 43 us | 4.2 us | 55 us | 4.2 us |
| 1 | 6621 us | 239 us | 129 us | 12.8 us |
| 4 | 8587 us | 269 us | 158 us | 55 us |
| 40 | 8910 us | 527 us | 592 us | 493 us |

With no tracked row the persistent kernel reads one mask vector per program, so a per-layer call site pays about 0.3 us more per launch than before; every case with a tracked row is faster, most of all the one-row benchmark case, where the old kernel's single program per row left the rest of the GPU idle.

<summary>Benchmark script</summary>

```python
import sys, torch
sys.path.insert(0, ".")
import old_mamba_state_scatter_triton as old  # python/sglang/kernels/ops/mamba/mamba_state_scatter_triton.py from main
from sglang.kernels.ops.mamba import mamba_state_scatter_triton as new

NUM_LAYERS, POOL, BS = 36, 128, 40
CONV_SHAPE, SSM_SHAPE = (8192, 3), (32, 128, 128)
dev = "cuda"
conv = torch.randn((NUM_LAYERS, POOL) + CONV_SHAPE, device=dev).to(torch.bfloat16)
ssm = torch.randn((NUM_LAYERS, POOL) + SSM_SHAPE, device=dev).to(torch.bfloat16)
cache_indices = torch.arange(BS, device=dev)
track_indices = torch.arange(BS, 2 * BS, device=dev)
mask = torch.zeros(BS, dtype=torch.bool, device=dev)

def per_layer(mod):
    for l in range(NUM_LAYERS):
        mod.track_mamba_states_if_needed(conv[l], ssm[l], cache_indices, mask, track_indices, BS)

def all_layers(mod):
    mod.track_mamba_states_all_layers(conv, ssm, cache_indices, mask, track_indices, BS)

def graph_time(fn, iters=50):
    s = torch.cuda.Stream(); s.wait_stream(torch.cuda.current_stream())
    with torch.cuda.stream(s):
        fn(); fn()
    torch.cuda.current_stream().wait_stream(s)
    g = torch.cuda.CUDAGraph()
    with torch.cuda.graph(g):
        fn()
    g.replay(); torch.cuda.synchronize()
    st, en = torch.cuda.Event(enable_timing=True), torch.cuda.Event(enable_timing=True)
    st.record()
    for _ in range(iters):
        g.replay()
    en.record(); torch.cuda.synchronize()
    return st.elapsed_time(en) / iters * 1000  # us

mask.copy_(torch.rand(BS, device=dev) < 0.5)
conv_a, ssm_a = conv.clone(), ssm.clone()
old.track_mamba_states_all_layers(conv_a, ssm_a, cache_indices, mask, track_indices, BS)
conv_b, ssm_b = conv.clone(), ssm.clone()
new.track_mamba_states_all_layers(conv_b, ssm_b, cache_indices, mask, track_indices, BS)
assert torch.equal(conv_a, conv_b) and torch.equal(ssm_a, ssm_b)
del conv_a, ssm_a, conv_b, ssm_b
print("bitwise equal old vs new: ok")
for n in (0, 1, 4, 40):
    mask.zero_(); mask[:n] = True
    print(n, [round(graph_time(f), 1) for f in (
        lambda: per_layer(old), lambda: all_layers(old),
        lambda: per_layer(new), lambda: all_layers(new))])
```
