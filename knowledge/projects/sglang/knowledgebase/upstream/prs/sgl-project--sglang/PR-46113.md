# [Feat] openai: support allowed tool subsets in Chat requests

[Upstream PR](https://github.com/sgl-project/sglang/pull/46113) · state: open · merged: False

## Original PR description

## Motivation

An agent can keep one full tool declaration and choose which tools are available for each turn. For example, a read-only step can expose `search` while leaving `deploy` unavailable. Chat currently rejects the `tool_choice.type=allowed_tools` request needed to express that subset.

Accept a declared function subset with `auto` or `required` mode, including declarations in root/system/developer messages.

Resolve the subset during request validation so encoders, constrained decoding and output parsers see the same selected declarations and mode. Carry the explicit mode into copied template kwargs so null hints and server defaults cannot change it. Generic Jinja templates also receive message-level tool schemas through their `tools` argument; native encoders keep the original message scopes. Historical calls/results and caller inputs are preserved. Reject duplicate/undeclared references, empty required subsets and conflicting template choices.

The Rust gateway has separate handling (#11085); this change covers Python serving. The K3 cookbook documents the request shape.

## Test Plan

- Protocol regressions cover filtering, validation, serialization and input preservation. Focused serving unit tests reproduce the missing message schemas on `e3c61ad` and pass with the fix, alongside named/none/empty-auto, Muse, K3 and DSV controls. Repository Ruff checks and formatting pass.
- Ran complete `e3c61ad` and `8d9a9d0` servers on one NVIDIA B30Z with genuine BF16 Qwen2.5-0.5B-Instruct, Torch 2.14.1+cu130, sglang-kernel 0.4.10 and FlashInfer 0.7.2. Required subsets, excluded-tool prompts, null/default mode hints, empty-auto and root declarations pass through real HTTP/SSE generation. Invalid requests hit the corresponding production validation errors.
- A disclosed test-only zero-output Jinja prefix checks rendered names, schemas and modes. Real tokenizer checks confirm accepted prompts are byte-identical to the stock template, with and without diagnostic kwargs. The baseline exposes the missing root declarations; the fix generates `keep({})`. Temporary servers were cleaned up and all 24 resident GPU PIDs were preserved.

This covers generic Python Chat integration. Full K3 weights/native generation, performance and SLA are outside this run; upstream hardware CI still needs `run-ci`.

Prepared with Codex assistance.
