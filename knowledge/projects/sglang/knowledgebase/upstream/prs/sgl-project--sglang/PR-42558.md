# Revert "Revert "[AMD][ROCm] Keep cos_sin_cache fp32 on HIP for fused QSA indexer kernel (#41282)""

[Upstream PR](https://github.com/sgl-project/sglang/pull/42558) · state: closed · merged: True

## Original PR description

## Motivation

#42541 reverted #41282 because the HIP `sgl_kernel.rotary_embedding` fallback could not read an fp32 `cos_sin_cache`. #42494 had already fixed that kernel to read an fp32 cache, about 12 hours before #42541 merged, and it moved `test_rope_rocm.py` into AMD stage A with a check that the HIP cache stays fp32.

With #41282 reverted, HIP casts the cache to the query dtype again, so that check fails `stage-a-test-1-gpu-small-amd` and every AMD stage B/C job is skipped:

```
File "/sglang-checkout/test/registered/rotary/test_rope_rocm.py", line 62, in _run_case
    self.assertEqual(rope_hip.cos_sin_cache.dtype, torch.float32)
AssertionError: torch.bfloat16 != torch.float32
```

#42541's own stage A run already failed this way ([job](https://github.com/sgl-project/sglang/actions/runs/37250822085/job/111615153216)). Since it merged, 18 of the 19 completed stage A jobs failed the same way, e.g. [run 37272668001](https://github.com/sgl-project/sglang/actions/runs/37272668001/job/111642894134) and [run 37275678823](https://github.com/sgl-project/sglang/actions/runs/37275678823/job/111652177894). The one pass is a stacked PR whose base branch does not contain #42541.

With #41282 and #42494 both on main, stage A passed 9/9, including Llama, EAGLE3 and `test_rope_rocm.py`: #42494's own run ([job](https://github.com/sgl-project/sglang/actions/runs/37210510566/job/111460697051)) and later PRs such as [run 37254377497](https://github.com/sgl-project/sglang/actions/runs/37254377497/job/111588311545) and [run 37265045192](https://github.com/sgl-project/sglang/actions/runs/37265045192/job/111620051932), the last one 12 minutes before #42541 merged.

## Modifications

`git revert 456d533e` (#42541). `base.py` and `mrope.py` go back byte-for-byte to their state after #41282; the patch is identical to f6fcda8827, and nothing else has touched either file since.

This brings back the fp32 `cos_sin_cache` on HIP that `test_rope_rocm.py` checks for, and with it the fused QSA indexer prep on HIP (`_use_fused_prep` requires an fp32 cache; benchmarks in #41282).
