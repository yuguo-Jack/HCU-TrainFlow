# [Perf] deepseek_v4: fuse q_norm with the MXFP8 quantize on the prefill path

[Upstream PR](https://github.com/sgl-project/sglang/pull/44836) · state: closed · merged: False

## Original PR description

## Motivation

Profiling the DEP2 prefill step on GB300 (DeepSeek-V4.1-Flash, MegaAttention + MegaMoE + Mega-mHC, decoder bounded replay, eager prefill): a cold 16,384-token chunk per rank takes 322 ms, of which 215 ms is kernel time and the rest GPU idle between ~1,800 launches (median inter-kernel gap 41 µs, roughly 65 µs of dispatch per launch).

`flashinfer_mxfp8_quantize` is one of the launch multipliers: 5 standalone quantize launches per layer, 210 per step, 4.2 ms of kernel time. The one feeding `wq_b` already has a fused kernel (`rmsnorm_mxfp8`, q_norm with the MXFP8 epilogue), but it was gated to `m <= 8` rows because its scale swizzle addressed a single 128-row tile, so prefill fell back to standalone `rmsnorm` + `mxfp8_quantize`.

## Modifications

- `python/sglang/kernels/ops/layernorm/mxfp8_epilogue.py`: `rmsnorm_mxfp8` takes any row count. The scale buffer is the tile-major 128x4 swizzle `mxfp8_quantize(..., is_sf_swizzled_layout=True)` returns (rows padded to 128, groups to 4, padding zeroed) via `mxfp8_epilogue_tiled` / `mxfp8_sf_offset`; the single-tile `mxfp8_epilogue` used by `hc_combine_norm_mxfp8` is untouched.
- `python/sglang/srt/models/deepseek_v4.py`: `_normalize_q_lora` uses the fused kernel for any positive row count (was `0 < m <= 8`). The other gates (CuTe-DSL backend, bf16, K=1280, not batch-invariant/deterministic) are unchanged.
- `test/registered/kernels/ops/layernorm/test_mxfp8_epilogue.py`: `test_prefill_rows` at 9, 128, 129, 257, 1000, 4096 and 16384 rows and both strides.

## Numerics

- The e4m3 data and the full swizzled scale buffer are bitwise `flashinfer.mxfp8_quantize` of the fused kernel's own BF16 row at every row count tested (padding included).
- The BF16 normalized row, which the indexer also reads, matches `flashinfer.norm.rmsnorm` bitwise at the ≤8-row shapes the kernel served before (0 of 368,640 elements differ over 36 draws). At prefill row counts FlashInfer's rmsnorm takes a different reduction and the two differ by one BF16 ulp on about 3e-6 of elements (31 of 12.2M at 257 rows, 2,251 of 767M at 16,384 rows), with FlashInfer the one farther from the fp32 result in about two thirds of them. The test asserts max 1 ulp at a bounded rate.

## Expected effect

One fewer launch per layer per prefill step (norm and quantize become one kernel): ~40 launches per 16K step, ~0.4 ms of kernel time plus ~2.5 ms of dispatch idle at this launch cost. The two remaining standalone quantizes per layer (before `wq_a`/`wkv` after Mega-mHC, before `wo_b` after the wo_a FP8 einsum) need an MXFP8 epilogue in those DeepGEMM producers and are not in this PR.

## Measured

GB300, DEP2 (TP2 + DP attention, EP2), DeepSeek-V4.1-Flash, MegaMoE, Mega-mHC, decoder bounded replay, eager prefill, 16K-token prefill budget per rank, rank 0. Main (job 3470, `2d3dd3168d`) against this branch (job 3466).

The fused kernel is about 10 µs slower than the two it replaces, so the gain is one launch per layer, about 65 µs of dispatch idle each on this path. The step-time deltas are within run-to-run noise.
