# [Fix] [XPU] dllm: Build extend metadata for DLLM_EXTEND (fix dLLM decode crash)

[Upstream PR](https://github.com/sgl-project/sglang/pull/41773) · state: closed · merged: False

## Original PR description

## Motivation

On Intel XPU, diffusion LMs (e.g. `inclusionAI/LLaDA2.1-mini` served with `--dllm-algorithm`) crash at warmup with `AttributeError: 'NoneType' object has no attribute 'shape'` in `XPUAttentionBackend.init_forward_metadata` (`metadata.page_table.shape[1]`).

`ForwardMode.DLLM_EXTEND` is included in `is_extend()` but **not** in `is_extend_or_draft_extend_or_mixed()`, which guards the XPU backend's extend-metadata branch. On CUDA, `DLLM_EXTEND` runs via CUDA graph (`is_cuda_graph()` includes it), so FlashAttention builds its metadata on the graph path and never reaches this eager branch. On XPU (CUDA graph disabled), `DLLM_EXTEND` goes through eager `init_forward_metadata`, matches none of the branches, and leaves `metadata.page_table = None` — crashing at the `page_size > 1` strided-page step.

## Modifications

Route `DLLM_EXTEND` into the XPU extend-metadata branch (it is a multi-query block forward, so extend-shaped metadata is correct). One-line guard change in `python/sglang/srt/layers/attention/xpu_backend.py`.

## Test

`inclusionAI/LLaDA2.1-mini` on Intel XPU (tp2, `--dllm-algorithm LowConfidence --attention-backend intel_xpu`): the server now warms up and serves. gsm8k `flexible-extract` = 0.8 (5-sample smoke) and mmlu runs to completion — both crash-free, versus the immediate warmup crash before this change.
