# [Feat] nemotron3-embed: Support Nemotron-3-Embed embedding models

[Upstream PR](https://github.com/sgl-project/sglang/pull/45885) · state: closed · merged: True

## Original PR description

## Motivation

Add native support for [`nvidia/Nemotron-3-Embed-1B-BF16`](https://huggingface.co/nvidia/Nemotron-3-Embed-1B-BF16), NVIDIA's text embedding model for retrieval.

The checkpoints are serialized as the bare `Ministral3Model` backbone with `is_causal: false` and `pooling: "avg"`: bidirectional attention over the whole prompt, then normalized mean pooling (2048-dim). SGLang has no native implementation for them today: `ministral3.py` registers only `Ministral3ForCausalLM`, not the bare `Ministral3Model` backbone, and nothing applies the bidirectional attention and mean pooling these checkpoints need. This PR detects them from the checkpoint config, the same way `use_bidirectional_attention` identifies EmbeddingGemma, and serves them with `sglang serve --model-path nvidia/Nemotron-3-Embed-1B-BF16`. `--is-embedding` is not needed.

## Modifications

- **Detection** (`configs/model_config.py`): `is_embedding_nemotron3(config)` matches `Ministral3Model` with `is_causal=False` and `pooling == "avg"`, and `ModelConfig` then renames the architecture to `EmbeddingNemotron3Model`, the same way it already renames a bare `Qwen3_5Model` backbone. From there the model goes through the usual architecture-name paths: `EmbeddingNemotron3Model` is listed with the other embedding architectures in `is_generation_model()`, and the model registry loads the class of that name, with no loader special case. Generative Ministral3 checkpoints are unaffected; unit tests cover checkpoints missing any of the three fields.
- **Capability spec** (`configs/embedding_model_spec.py`): new `embedding_nemotron3` spec, selected by the `EmbeddingNemotron3Model` is: encoder-only, bidirectional, MEAN pooling, normalized, embedding mode auto-enabled. Radix cache and chunked prefill are disabled, because K/V depend on later prompt tokens. Adds a support-matrix row.
  - New spec field `encoder_only_attention` (default False): every attention layer is `AttentionType.ENCODER_ONLY`. The Nemotron-3-Embed spec sets it, together with `safe_disable_kv_cache`; The KV-cache auto-enable below reads these capabilities, so the hook never names a model, and future encoder-only embedding models only declare them in their spec.
- **Model** (`models/nemotron3_embedding.py`, new file; `models/ministral3.py` is unchanged): `EmbeddingNemotron3Model` subclasses `Ministral3ForCausalLM`.
  - Marks every attention layer `AttentionType.ENCODER_ONLY`.
  - Always returns embeddings.
  - Maps the bare-backbone weight names (`layers.*`, `embed_tokens.*`, `norm.*`) to `model.*`.
  - Pools and normalizes in FP32, so embeddings are returned in FP32. Pooling in BF16 is imprecise for this model.
  - The checkpoint ties word embeddings, so the inherited `lm_head` is only an alias of `embed_tokens`.
- **No KV cache on FA3/FA4** (`arg_groups/model_hook.py`): each request is one bidirectional prefill that never reads K/V back. When the spec declares `safe_disable_kv_cache` and `encoder_only_attention` and the prefill backend is FA3 or FA4, the model hook enables the existing `--prefill-only-disable-kv-cache` mode (FA's `fa_skip_kv_cache` path over raw K/V), then runs the existing validator.
  - It runs after CUDA-graph sizing, so prefill graphs keep their default capture sizes.
  - Other prefill backends keep the KV pool, including FlashInfer (Ampere default) and `trtllm_mha` (Blackwell default). FlashInfer support would belong inside `flashinfer_backend.py`, alongside its ragged/paged choice, and is left for a follow-up.
- **ROCm not supported** (`arg_groups/model_overrides/nemotron3_embedding.py`, new file): on HIP, startup fails with "Nemotron-3-Embed is not supported on ROCm." The default ROCm backend (aiter) ignores `AttentionType.ENCODER_ONLY` and always runs causal prefill, which would silently return wrong embeddings, and no ROCm backend has been validated for this model. Generative Ministral3 checkpoints on ROCm are unaffected.
- **Docs** (`docs/docs/supported-models/embedding_models.mdx`): Nemotron-3-Embed section with the launch command, the auto-applied server settings and the `query: ` / `passage: ` prefixes. Also adds a Supported Models table row and notes that ROCm is not supported.
- **Tests:**
  - `test/registered/unit/configs/test_model_config.py`: detection and non-detection.
  - `test/registered/unit/configs/test_embedding_model_spec.py`: spec contract (including `encoder_only_attention`), support matrix, and the model hook enabling no-KV for Nemotron-3-Embed with FA3/FA4 while keeping the KV pool with FlashInfer/Triton.
  - `test/registered/prefill_only/test_nemotron3_embedding.py`: E2E on a tiny random checkpoint with the same config shape, compared with HF `Ministral3Model` + mean pooling. Covers FP32 torch_native (tight tolerance) and BF16 default backend (cos ≥ 0.999), with single and packed batches. Registered for CUDA CI only.
  - `test/registered/unit/test_model_overrides.py`: Nemotron-3-Embed is rejected on ROCm, still resolves on CUDA, and generative Ministral3 on ROCm is not rejected.

## Accuracy Tests

Ran BF16 checkpoint on one RTX A6000. 32 `query:`/`passage:` synthetic texts (7 to 8,894 tokens), sent one per request, as batches in several orders, and concurrently. Each embedding is compared with the FP32 SentenceTransformer reference and the min cosine similarity was 0.99991

[by Claude Code] **Severity: functional | Confidence: High**

**Issue**

On ROCm, the default MHA backend is `aiter` (`model_override_base.py` returns `"aiter"` when `is_hip`). `AiterAttnBackend.forward_extend` never reads `layer.attn_type`; it calls `mha_batch_prefill_func(..., causal=True)`. So this `ENCODER_ONLY` flag has no effect on AMD, and Nemotron-3-Embed silently returns causal embeddings there. `test_nemotron3_embedding.py` also calls `register_amd_ci`, so `test_bf16_default_backend_matches_hf` will run on `aiter` and fail its cosine check.

**Fix**

Add an `EmbeddingNemotron3Model` override in `arg_groups/model_overrides/` that picks `triton` on HIP when no backend is set (like `embedding_gemma2.py`), or reject `aiter` for this model. Add a CPU unit test for the override.

[by Claude Code] **Severity: style | Confidence: High**

**Issue**

`hasattr(layer, "self_attn")` is a defensive check, which SGLang style does not allow. It also hides real errors: if a layer class ever renames `self_attn`, this loop skips that layer, and it silently stays causal.

**Fix**

Loop over the layers this PP rank owns:

```python
for layer in self.model.layers[self.model.start_layer : self.model.end_layer]:
    layer.self_attn.attn.attn_type = AttentionType.ENCODER_ONLY
```

**Issue**

`is_embedding_nemotron3` uses three `getattr(..., default)` calls, which SGLang style does not allow. `architectures` always exists on a `PretrainedConfig`, so that `getattr` only hides errors.

**Fix**

Read `architectures` directly, and read the two checkpoint-only fields from the config dict:

```python
fields = config.to_dict()
return (
    config.architectures == ["Ministral3Model"]
    and fields.get("is_causal") is False
    and fields.get("pooling") == "avg"
)
```

Build the unit-test configs with `PretrainedConfig(...)` instead of `SimpleNamespace`.
