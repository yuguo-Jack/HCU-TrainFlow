# [Fix] [XPU] compressed-tensors: Support W8A8 int8 on XPU and quantize Whisper MLP linears.

[Upstream PR](https://github.com/sgl-project/sglang/pull/48353) · state: open · merged: False

## Original PR description

## Motivation

`RedHatAI/whisper-large-v3-turbo-quantized.w8a8` is a compressed-tensors W8A8 int8 checkpoint: per-channel symmetric int8 weights, dynamic per-token symmetric int8 activations, `targets: [Linear]`, `ignore: []`. It cannot be served on Intel XPU, and once the load is unblocked it produces garbage output. There are four separate issues, and each one hides the next:

1. **The XPU scheme allowlist rejects it.** `CompressedTensorsConfig.get_linear_scheme` admits only `CompressedTensorsW8A8Fp8` and `XPUCompressedTensorsWNA16` on XPU, so the server fails at weight load with
   `RuntimeError: CompressedTensorsW8A8Int8 is not supported on XPU (no XPU kernel implementation).`
2. **XPU has no int8 GEMM.** `CompressedTensorsW8A8Int8` imports `int8_scaled_mm` from `sgl_kernel` only under `_is_cuda`, and sgl-kernel-xpu does not provide that op.
3. **`per_token_quant_int8` does not link on XPU.** On every non-HIP backend the Triton kernel calls `tl.extra.cuda.libdevice.round`, which lowers to `__nv_roundf`. On XPU this fails with `ZE_RESULT_ERROR_INVALID_MODULE_UNLINKED`.
4. **Whisper's MLP linears ignore `quant_config`. This bug is not specific to XPU.** `WhisperEncoderLayer` and `WhisperDecoderLayer` build `fc1`/`fc2` without `quant_config`. As a result 72 of the model's 156 linears (32 encoder + 4 decoder layers × 2) get `UnquantizedLinearMethod`: the checkpoint's int8 weights are loaded into bf16 parameters and `weight_scale` is silently skipped. Output is garbage from the first token (WER 104, table below). The same thing happens on any backend that loads this checkpoint.

## Modifications

- **`compressed_tensors.py`**: `_get_scheme_from_parts` sends dynamic per-token W8A8 int8 to the new `XPUCompressedTensorsW8A8Int8` on XPU, and that scheme is added to the XPU allowlist in `get_linear_scheme`.
- **`schemes/compressed_tensors_w8a8_int8.py`**: adds `XPUCompressedTensorsW8A8Int8(CompressedTensorsW8A8Int8)`. Weight creation and `process_weights_after_loading` (the transposed `[K, N]` int8 weight plus per-channel `weight_scale`) are inherited unchanged. Only `apply_weights` is overridden. It runs Triton `per_token_quant_int8`, then `torch._int_mm` (int8 × int8 → int32, oneDNN on XPU), then the per-token × per-channel rescale in fp32, then the bias add, then a cast back to the activation dtype. Static or asymmetric activation schemes raise `NotImplementedError` in `__init__`, so an unsupported checkpoint fails at load time instead of producing wrong numbers mid-forward.
- **`schemes/__init__.py`**: exports the new scheme.
- **`kernels/ops/quantization/int8_kernel.py`**: renames the `IS_HIP` constexpr to `GENERIC_LIBDEVICE` and sets it to `_is_hip or _is_xpu`, so XPU uses the backend-agnostic `libdevice.round` that ROCm already uses. CUDA codegen is unchanged.
- **`models/whisper.py`**: passes `quant_config` to the encoder and decoder `fc1`/`fc2`, matching the attention projections in the same file. For unquantized checkpoints `quant_config` is `None`, so nothing changes.

Behaviour that does not change:
- The LM head stays unquantized. `load_weights` ties `proj_out` to `embed_tokens`, so the checkpoint's int8 `proj_out` is dropped, exactly as before.
- None of Whisper's linears pass `prefix=`, so a non-empty compressed-tensors `ignore` list cannot match Whisper layer names. This checkpoint's `ignore` list is empty, so it is not affected. Adding prefixes throughout `whisper.py` is left for a follow-up.
