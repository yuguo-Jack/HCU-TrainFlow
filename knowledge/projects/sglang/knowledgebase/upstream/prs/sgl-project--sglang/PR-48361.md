# [Fix] scheduler: Abort embedding requests longer than the KV pool

[Upstream PR](https://github.com/sgl-project/sglang/pull/48361) · state: closed · merged: False

## Original PR description

## Motivation
`_handle_embedding_request` validates the input length but, on failure, queues the request without finishing it. A prompt that fits the context length but not the KV pool is then never scheduled and never answered: the client hangs until its timeout. The generate path already aborts in this case.

## Modifications
- `scheduler.py`: `req.set_finish_with_abort(error_msg)` when `validate_input_length` fails.
- New regression test `test_embedding_length_validation.py` (`--max-total-tokens 1000`, 1500-token input): expects HTTP 400, then a normal request still succeeds.

## Accuracy Tests
No model-output change. New test: 2/2 pass with the fix; without it both fail with `ReadTimeout`. `test_embedding_models::test_prefill_logits` passes.

N/A (error path only).
