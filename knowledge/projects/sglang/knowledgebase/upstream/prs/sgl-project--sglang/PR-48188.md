# [Fix] spec: Keep chain MTP prefill hidden states under DP attention

[Upstream PR](https://github.com/sgl-project/sglang/pull/48188) · state: open · merged: False

## Original PR description

## Motivation

Under DP attention, multi-layer EAGLE with a chain MTP draft (`chain_mtp_hidden_states`: `Step3p5MTP`, `InklingForConditionalGenerationMTP`, `GigaChat35ForCausalLMNextN`) builds the prompt's draft KV for every step after the first from zero hidden states.

In `MultiLayerEagleDraftWorker._draft_extend_for_prefill`, a chain draft captures hidden states with `CaptureHiddenMode.FULL` and passes `output.logits_output.hidden_states`, one row per prompt token, to the next step. Under DP attention, `ModelRunner.forward` then calls `ForwardBatch.post_forward_mlp_sync_batch`, and its `EAGLE_DRAFT_EXTEND` (non-V2) arm slices `hidden_states` to `[:bs]`, the request count. The next step's `_pad_inputs_to_size` pads the missing rows with zeros. So steps 1..K-1 write the prompt's draft KV from the token embedding alone, with no context.

- Step 0 reads the target hidden states and is unaffected.
- Draft KV written during decode goes through the `DRAFT_EXTEND_V2` arm, which keeps `bs * num_tokens_per_req` rows, and is correct.
- Without DP attention, `post_forward_mlp_sync_batch` does not run.

Multi-turn workloads, where most of the context arrives through prefill, lose acceptance from the second draft position on.

## Modifications

- `ForwardBatch.post_forward_mlp_sync_batch`, `EAGLE_DRAFT_EXTEND` arm: when the batch captures FULL, slice `hidden_states` to `_original_num_tokens`, the token count before MLP-sync padding. Every other capture mode keeps the per-request slice, and `next_token_logits` keeps its per-request slice.
- `test_mlp_sync_pad_unpad.py`: a draft-extend batch of 2 requests and 7 tokens, padded to 10, keeps all 7 hidden rows under FULL capture and 2 under LAST. The FULL case fails on main.

#47493 changes the target extend arm of the same function. The two do not overlap in code, but both add a case to this test file.

## Accuracy Tests

On an internal fork serving a 7-step chain MTP draft with DP attention, on a multi-turn workload, with the boundary-KV fix (#48187) in both runs: accept length went from 3.76 to 6.03. The acceptance rate at draft positions 2-7, given the earlier positions were accepted, went from 0.38-0.72 to about 0.90; position 1, which reads the target hidden states, stays around 0.9.

We also dumped each step's draft KV at committed positions and compared it with a fresh prefill of the committed tokens. Before the fix, steps 1-6 on prompt rows had a median relative error of about 1.36, i.e. uncorrelated. After it, every step is at 0.07-0.15 on both prompt and generated rows, which is within the fp8 KV quantization noise.

Local checks, CPU only: `test_mlp_sync_pad_unpad.py`, `test_aux_hidden_state_row_alignment.py`, `test_mlp_sync_hybrid_target_verify.py`, `test_unified_out_cache_loc_rebind.py`, `test_forward_metadata_plan_record.py`, `test_dp_spec_prefill_coordination.py`, `test_tbo_children_dummy_token_mask.py`, `test_mamba_prefill_track_metadata.py` and `test_dp_attn.py` give the same results before and after the change. `test_dp_attn.py`'s gloo exchange case sometimes fails on a fixed port (`EADDRINUSE` on 18005), on main as well.

## Speed Tests and Profiling

Only a slice length changes; decoding gets faster through the higher acceptance above.
