# [Fix] dspark: Keep output sampling exact under folded draft sampling by storing corrected logits in FP32

[Upstream PR](https://github.com/sgl-project/sglang/pull/42710) · state: open · merged: False

## Original PR description

## Motivation

With folded draft sampling (`SGLANG_DSPARK_FOLDED_SAMPLING`, on by default when memory allows), `DsparkDraftSampler` draws each draft token in the draft CUDA graph from the Markov-corrected step logits and copies those logits to `corrected_out`. Sampling acceptance later rebuilds the draft distribution q from `corrected_out`.

`corrected_out` was allocated in the head dtype: `lm_head.weight.dtype` for a floating-point weight, otherwise the dtype of the first Markov-head parameter (BF16 for a BF16 `lm_head`). The DeepSeek-V4 DSpark Markov head adds an FP32 bias, so its corrected logits are FP32. The token was drawn from the FP32 logits, but rejection sampling used q from a BF16-rounded copy. Rejection sampling then compares the target against a distribution that is not the one the draft token came from, which can bias the output distribution. The eager proposal path keeps the FP32 logits, so the folded and eager paths also used different q.

## Modifications

- Allocate `corrected_out` as FP32 and remove `_base_logits_dtype`. FP32 holds BF16/FP16 logits exactly, so heads with BF16 corrected logits get the same values as before.
- The free-memory check that decides whether folded sampling is enabled now counts 4 bytes per element. For heads that previously stored 16-bit logits, the buffer grows by `max_bs * gamma * vocab * 2` bytes, where `max_bs` is the largest decode CUDA-graph batch size. That is about 21 MB at max_bs 16, gamma 5, vocab 129,280, and 83 MB at max_bs 64.

  This can change one decision. For eligible heads in AUTO mode, an initialization-time check enables folded sampling only when available GPU memory is at least 1 GiB plus the `exp_noise` and `corrected_out` buffers; with default TP synchronization, available memory is the group minimum. A deployment whose free memory falls inside the extra margin (about 1.11-1.18 GiB at max_bs 64, gamma 5, vocab 129,280) now gets the existing warning, and its sampling batches take the eager proposal path. That path already keeps FP32 corrected logits. Greedy token selection is unchanged. OFF is unchanged; FORCE still folds, with the larger buffer. Heads for which AUTO never folds sampling (`supports_sharded_greedy`) are unchanged.

## Accuracy Tests

New CPU test `test/registered/spec/dspark/test_dspark_draft_sampler.py` runs the folded sampler with BF16 base logits and an FP32 Markov bias, as in the DeepSeek-V4 draft head:
- sampling rows: `corrected_out` is FP32 and equal (`torch.equal`) to the step logits recomputed from the sampled tokens;
- greedy rows: tokens and `corrected_out` are equal (`torch.equal`) to the eager `sample_draft_block` output.

Both tests fail with the sampler from main (the buffer is BF16) and pass with this change.

## Speed Tests and Profiling

Not benchmarked. For heads that previously stored BF16 logits, `corrected_out` and the copy into it are twice as large. See Modifications for the one case where AUTO now picks the eager proposal path.
