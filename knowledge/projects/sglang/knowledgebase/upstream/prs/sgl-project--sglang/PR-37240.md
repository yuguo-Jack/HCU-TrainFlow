# [NPU] Harden nightly multi-node cleanup and trim nightly single-node jobs

[Upstream PR](https://github.com/sgl-project/sglang/pull/37240) · state: closed · merged: False

## Original PR description

## Why are these changes needed?

Fixes multi-node nightly jobs hanging in the `Clear resources` / `Post process` steps and avoids parallel jobs deleting each other's pods.

- **nightly-test-npu-e2e-multi-node.yml**
  - Add `timeout-minutes` to the `Clear resources` and `Post process` steps.
  - Scope all `kubectl` calls to the job namespace and force-delete pods (`--force --grace-period=0`) with a finalizer cleanup fallback.
  - Replace the unbounded `while true` loop with a bounded retry loop and print matching pods for debuggability.
  - Uniquify `KUBE_JOB_NAME` with `run_id`/`run_attempt` so concurrent jobs no longer interfere with each other's pods.
- **nightly-test-npu.yml**
  - Keep only `nightly-1-npu-a3`, `nightly-4-npu-a3` and `debug-nightly-acc-2-npu-a3` jobs and comment out the rest.
- **test_npu_qwen3_6_27b_1p_gpqa.py**
  - Register the GPQA accuracy case to the `debug-nightly-acc-2-npu-a3` suite.

## Tests

- Verified the registered case is collected and matched by `run_suite.py --hw npu --suite debug-nightly-acc-2-npu-a3 --nightly`.
- Workflows validated with actionlint (no YAML parse errors).
