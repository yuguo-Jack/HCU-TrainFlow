# [Fix] openai: replay gpt-oss reasoning_content as thinking for tool-call turns

[Upstream PR](https://github.com/sgl-project/sglang/pull/45178) · state: open · merged: False

## Original PR description

Closes #44931

### Motivation

With `--reasoning-parser gpt-oss`, SGLang returns gpt-oss's analysis channel
as `message.reasoning_content`. When a client replays that assistant
tool-call turn (assistant tool call → tool result → next request), the
chain-of-thought never reaches the prompt: the stock gpt-oss chat template
reads prior CoT only from the assistant message's `thinking` field, while
`reasoning_content` is passed to the template under a name it ignores.
Measured on the issue's repro: 268 prompt tokens instead of 291, and the
replayed prompt no longer extends the previous prompt plus output, so
prefix-cache reuse stops at the start of that assistant turn.

### Modifications

- `python/sglang/srt/entrypoints/openai/serving_chat.py`
  - New module-level helper `_replay_gpt_oss_reasoning_content_as_thinking()`
    that copies an assistant message's `reasoning_content` into `thinking`
    (never overwriting an explicitly provided `thinking`).
  - Called in `_apply_jinja_template`'s generic Jinja branch only, gated on
    `self.reasoning_parser == "gpt-oss"` (per-model opt-in, so no other
    model's template behavior changes). Custom encoders (dsv4/dsv41/dsv32,
    kimi_k3, inkling) are untouched.
  - Edge case the template itself flags: an assistant tool-call turn with
    non-empty `content` plus `thinking` makes the template raise
    ("Cannot pass both content and thinking in an assistant message with
    tool calls!", surfaced as HTTP 400). Instead of erroring or silently
    dropping the CoT, the preamble is folded into the analysis channel
    (`thinking = reasoning_content + "\n" + content`, generation order)
    and `content` is cleared, so the template always renders.
- `test/registered/unit/entrypoints/openai/test_serving_chat.py`
  - `TestReplayGptOssReasoningContentAsThinking`: 6 unit tests covering the
    copy, the explicit-`thinking` guard, the preamble merge (string and
    parts-list content), non-assistant messages, and the no-op case.

### Tests

- Verified against the real stock `openai/gpt-oss-20b` chat template's
  message loop (transcribed verbatim; only `raise_exception` message
  strings shortened) rendered with Jinja2: without the fix the replayed
  CoT is dropped from the analysis channel (bug reproduced); with the fix
  it renders as `<|start|>assistant<|channel|>analysis<|message|>…<|end|>`
  before the tool call; the preamble edge case renders merged with no
  template error. 17/17 harness checks pass.
- The 6 new unit tests pass against the AST-extracted helper (full
  `test_serving_chat.py` needs torch/GPU, unavailable on this machine).
- `ruff check --select F401,F821,F823,UP037`, `ruff format --check`,
  `python -m py_compile`, and `git diff --check` all pass on both touched
  files; no added line exceeds 88 columns.
- Not verifiable here: an end-to-end run against a live gpt-oss server
  (no GPU on this machine). Requesting CI via the `run-ci` label.
