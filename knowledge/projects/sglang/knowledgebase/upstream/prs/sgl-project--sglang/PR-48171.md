# [Perf] diffusion: Share convrot_int8 input quantization across LTX-2 projections

[Upstream PR](https://github.com/sgl-project/sglang/pull/48171) · state: open · merged: False

## Original PR description

## Motivation

With `--quantization convrot_int8` on the JIT backend, every LTX-2 attention block calls `to_q`, `to_k`, `to_v` (and `to_gate_logits` on LTX-2.5) separately. Each call rotates and INT8-quantizes the same activation again. The FFN also runs GELU as its own kernel before `proj_out`. The JIT backend already provides bit-exact helpers for both cases (`apply_convrot_int8_shared_input` and `apply_convrot_int8_gelu_input`), and Qwen-Image and FLUX use them. LTX-2 did not.

## Modifications

`models/dits/ltx_2.py`:
- `LTX2Attention.forward`:
  - Self-attention projects Q/K/V and the gate logits from one rotated and quantized copy of the hidden states.
  - Cross-attention shares the context between K and V, and the hidden states between Q and the gate.
  - With the cached prompt K/V (`context_kv`), only Q and the gate are projected.
  - `project_context_kv` shares the context between K and V.
- A small `_project_shared` helper adds the gate only when it is eligible too. For example, a gate width that is not a multiple of 8 stays in BF16. When no layer is eligible (BF16, comfy_kitchen backend, LoRA wrappers, deferred bias), it falls back to the per-layer calls.
- `LTX2FeedForward.forward`: when `proj_out` is eligible, GELU(tanh) is folded into its rotate kernel. Eligibility is checked per call because LoRA mounting swaps `proj_out` for a wrapper.

`test/unit/test_ltx2_convrot_shared_input.py` (new): self-attention (with and without the gate), cross-attention, the cached-K/V path and the FFN must all be `torch.equal` to the unfused path. The test also checks that the shared/fused helpers are actually taken.

## Accuracy Tests

The change is bitwise identical end to end. Setup: LTX-2.5 T2V on 1x RTX 5090 (SM120), 960x544, 121 frames, 8 steps, seed 42, three prompts. Flags: `--quantization convrot_int8 --layerwise-offload-components dit text_encoder --dit-layerwise-resident-layers 48 --dit-layerwise-residency-lifetime permanent --vae-tiling false`. Every decoded frame matches the run without this PR (max abs diff 0), and the MP4 md5s are identical.

Unit tests on the same GPU: `test_ltx2_convrot_shared_input.py`, `test_convrot_int8_backends.py` and `test_ltx2_prompt_kv_cache.py` give 35 passed, 1 skipped (the comfy_kitchen-only case).

## Speed Tests and Profiling

Same setup, built on an image at `38d9e4a3f` with this patch applied. Steady-state requests 2 and 3 of each run:

| arm | denoise | per step | end to end |
|---|---|---|---|
| convrot_int8 | 6.14 / 6.20 s | 0.753 s | 11.64 / 11.51 s |
| convrot_int8, this PR | **5.91 / 5.96 s** | **0.723 s** | **11.41 / 11.28 s** |
| convrot_int8 + `fp8_fa_sm120` attention | 5.12 / 5.17 s | 0.628 s | 10.63 / 10.50 s |
| convrot_int8 + `fp8_fa_sm120`, this PR | **4.88 / 4.92 s** | **0.596 s** | **10.37 / 10.25 s** |

That is about 4% less denoise time, or about 0.24 s per video, at the same peak memory (30.3 GB). The `fp8_fa_sm120` rows also need #45239, which fixes that backend's import under a meta-device model build.
