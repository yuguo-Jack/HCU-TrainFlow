# [Fix] scheduler: Cap aborted speculative output at max_new_tokens

[Upstream PR](https://github.com/sgl-project/sglang/pull/44874) · state: open · merged: False

## Original PR description

## Motivation

Fixes #44839. When an abort arrives during a speculative decoding step, the
pending-finish branch of `Req.update_finish_state()` sets `FINISH_ABORT` and
returns before the `max_new_tokens` cap is applied to the accepted run, so a
multi-token acceptance can leave `output_ids_through_stop` equal to the entire
accepted run — tokens beyond the requested budget are returned/detokenized
for aborted requests. The reporter observed 51/78/69 aborted completions
beyond their 3–7 token budgets (Qwen3-0.6B, NGRAM, RTX A5000, three
fresh-server runs); those are the reporter's numbers, reproduced independently
below.

## Modifications

`python/sglang/srt/managers/schedule_batch.py` (4 lines): when honoring a
pending abort, if the committed `output_ids` exceed `max_new_tokens`, set
`finished_len = max_new_tokens`. The abort reason/metadata and the full raw
`output_ids` are preserved (the accepted run remains available to the KV
release path, which checkpoints through `owned_kv_len()` and frees the
overallocated suffix). At/below-budget aborts are unchanged.

Compatibility audit (no code change needed): `output_streamer` emits from
`output_ids_through_stop` (already capped by `finished_len`), and logprob
payloads slice on the same length; `release_kv_cache` already supports
`finished_len` smaller than the committed accepted length.

## Accuracy Tests

Only over-budget aborted outputs change; the model computation and ordinary
decoding paths are unchanged. The non-speculative control below also stays
within the requested cap.

Unit regressions added in
`test/registered/unit/managers/test_finish_length_speculative.py`
(real `Req` + `SamplingParams`): abort-with-overshoot caps output and keeps the
abort reason; abort within budget stays untrimmed; abort overshoot is not
treated as a cache-key length. On pristine main the new tests fail (Linux
normal pytest: 4 failures = 3 max-token subcases + 1 KV-boundary case, 28
passes); with the patch the file and the adjacent speculative finish suites
(length, stop-string, vocab-boundary, grammar-stop) pass: 29 tests + 5
subtests (Linux, Python 3.12, torch 2.14.1, `maybe_stub_sgl_kernel` intact).

End-to-end (NVIDIA A800 80GB PCIe, Qwen3-0.6B official weights,
`--speculative-algorithm NGRAM --speculative-num-draft-tokens 8
--speculative-ngram-max-trie-depth 12`): the reporter's client verbatim, with
a wrapper that adds `return_spec_tokens_details=True` and
`return_token_ids=True`, and records every response. Because the A800
completes the abort window faster than the
reporter's A5000, the abort delay was scaled to 20–60 ms (delay_scale 0.2);
the original 100–300 ms and 10–30 ms attempts (0 overshoot) are retained as
non-reproducing evidence.

| arm | requests | failed | responses over cap | aborted w/ accepted drafts | reporter check | health |
|---|---|---|---|---|---|---|
| main, spec | 508 | 0 | **27** | 239 | exit 1 (overshoot) | 200 |
| patched, spec | 508 | 0 | **0** | 242 (11 with accepted draft count > cap; all returned exactly cap) | exit 0 | 200 |
| main, non-spec control | 508 | 0 | 0 | 0 | exit 0 | 200 |
