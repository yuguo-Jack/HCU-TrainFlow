# [Fix] benchmark: Reject incomplete OpenAI streams

[Upstream PR](https://github.com/sgl-project/sglang/pull/44636) · state: open · merged: False

## Original PR description

## Motivation

HTTP 200 and a clean HTTP EOF do not guarantee that an OpenAI-compatible streaming response completed. Both benchmark clients can currently count an unfinished response as successful, including partial output whose token count falls back to the requested output length.

This complements #43209, which handles explicit SSE error payloads. This PR handles EOF without an error payload or completion marker. The patches have adjacent overlapping hunks and need reconciliation if both land.

## Modifications

- Require `[DONE]` or nonempty `finish_reason` for every requested and observed choice before counting a streaming request as successful.
- Use the final request payload's `stream` and `n` values, including completions with batched prompts.
- Keep completion state monotonic and consume usage trailers, including zero-output and tool-only responses.
- Preserve non-streaming behavior and transport errors; exclude incomplete requests from successful-request and output-token totals.
- Add real loopback HTTP/aiohttp regressions to the existing registered CPU test file.
