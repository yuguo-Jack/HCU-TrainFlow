# [Fix] diffusion/loader: Honor custom weight-loader overrides

[Upstream PR](https://github.com/sgl-project/sglang/pull/46253) · state: closed · merged: True

## Original PR description

## Motivation

The TP=1 linear storage-adoption fast path checks the loader's owner type, but a subclass can override `weight_loader` to transform a checkpoint. Matching shape and dtype do not make that override safe to skip: a square-weight transpose reproducer currently loads the wrong values without an error.

## Modifications

- Check the bound loader implementation before bypassing it.
- Preserve storage adoption for the six existing plain/merged/QKV linear loaders, including subclasses inheriting those implementations. Custom implementations run through their normal loader.
- Add a regression covering CPU checkpoints and explicit direct-GPU loading.

No new options, model allowlists, or changes to the default CPU-to-GPU loading strategy. This only tightens the TP=1 linear fast path; the separate MPS checkpoint-mapping path is unchanged.

## Validation

- Reproduced incorrect weights before the fix; the regression passes after it.
- H200: 310 loader/offload tests passed, 3 skipped, using the existing `single_process_model_parallel` fixture for the wider suite. Two existing test groups omit that fixture and fail identically on main when run alone; their repair is separate in #46254.
- Actual TP1/TP2 process groups: 96 exact weight comparisons per rank across six linear types, FP32/BF16, CPU/CUDA source and destination, and direct loading on/off. Existing storage-aliasing behavior is preserved for the supported implementations.
- Real H200 server requests: Wan1.3B single GPU and Ulysses2 (512x320, 17 frames), and Z-Image Turbo single GPU (512x512), all 4 steps with seed 42. Decoded output hashes match main within each configuration; allocated load/runtime peaks are unchanged. These are correctness smokes, not statistical performance claims.

This is a correctness fix, not a claimed startup speedup. An overridden loader may need its own allocation/copy; skipping that work is only safe when its semantics are known.
