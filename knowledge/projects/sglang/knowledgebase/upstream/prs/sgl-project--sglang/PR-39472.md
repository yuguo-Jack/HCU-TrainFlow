# [feat] update_weights_from_disk: model_loader_extra_config + rebuild_model

[Upstream PR](https://github.com/sgl-project/sglang/pull/39472) · state: closed · merged: False

## Original PR description

## Motivation

`/update_weights_from_disk` rebuilt `LoadConfig` from the load format alone, so a server started with a custom `--model-loader-extra-config` (e.g. fastsafetensors `enable_gds`) silently dropped it on reload and fell back to the wrong loader settings. The request now carries `model_loader_extra_config`; when unset the worker falls back to the runner's startup `load_config` value, preserving prior behavior.

Some quantization paths (e.g. MXFP4 MoE on the flashinfer backend) additionally replace raw parameters with derived ones in `process_weights_after_loading`, so a second in-place `load_weights` cannot reconstruct the checkpoint. The new `rebuild_model` flag instead drops the current model, constructs a fresh one through `load_model_with_memory_saver`, and re-runs the model-dependent tail of `ModelRunner.initialize()`: KV scales, MoE topk, layer indices, post-load transforms, capturers, attention backends and CUDA graph capture.

Stacked on #39470. Next: #39490

## Modifications

- `python/sglang/srt/managers/io_struct.py`: new optional `model_loader_extra_config` field and `rebuild_model` flag on `UpdateWeightFromDiskReqInput`.
- `python/sglang/srt/managers/tokenizer_manager.py`: log both values and record them via `record_config_updates("tokenizer.update_weights", ...)` for provenance alongside `load_format`.
- `python/sglang/srt/managers/tp_worker.py`, `python/sglang/srt/speculative/base_spec_worker.py`: pass the fields through to the weight updater.
- `python/sglang/srt/managers/scheduler_components/weight_updater.py`: reject rebuild while any memory region is paused (`offload_tags`), and force the cache flush since every cached token maps to weights that no longer exist.
- `python/sglang/srt/model_executor/model_runner_components/weight_updater.py`: accept the config parameter, default to the startup `load_config` value, build `LoadConfig` with it, and the rebuild machinery.

Details:
- Old weights are released explicitly (params, buffers and device tensors zeroed) after clearing captured graphs, attention backends, the eager runner and any runner attribute referencing the old modules, so the reload reuses the freed allocations.
- Drop and reload run on the default stream: the caching allocator only reuses blocks on their allocating stream, and the model was loaded on the default stream at startup while the scheduler forwards on its own.
- The KV pool keeps its startup sizing, so a rebuilt model spanning a different layer range fails loudly instead of corrupting the pool.
- Rejected up front for speculative decoding, LoRA and EPLB / elastic EP (post-load state bound to the dropped model or its weights), and at the scheduler level while any memory region is paused.
- `update_model_fields` stamps the runner and records `model_path` / `load_format` through the runtime-context override, matching the in-place path.
- The remote-instance weight transporter's stale memory registration is reset so `maybe_register_and_publish_weight_info` re-registers against the new weights.

## Accuracy Tests

Config passthrough is identical when the field is unset; rebuild reproduces the startup load path for the same architecture, and in-place updates are unchanged when the flag is off.

## Speed Tests and Profiling

Rebuild costs a full model load plus graph recapture, as documented on the flag.
