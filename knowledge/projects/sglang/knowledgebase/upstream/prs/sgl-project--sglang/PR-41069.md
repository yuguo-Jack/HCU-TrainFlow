# [PD] Arm host drain ack tracking before abort notification

[Upstream PR](https://github.com/sgl-project/sglang/pull/41069) · state: open · merged: False

## Original PR description

## Motivation

When a host-staged decode transfer fails, decode sends ABORT and holds its host pages until every prefill rank acknowledges that in-flight writes have drained. Previously, the common receiver sent ABORT before registering the room for drain acks. An immediate ABORT_ACK was discarded, and host pages could remain held indefinitely because host release does not time out.

Host destinations are currently supported only by custom transfer backends; no built-in backend opts in.

## Modifications

- Mark a common receiver when the decode destination is the host pool, and register its drain-ack room before sending ABORT. This also covers timeout-initiated abort notifications.
- Reject host receive at decode startup for common-manager backends unless deferred decode KV release is enabled.
- Document that common-based custom backends require `SGLANG_DISAGGREGATION_DEFERRED_DECODE_KV_RELEASE=1` on both prefill and decode servers. Decode validates only its local setting; it cannot verify the remote prefill configuration.
- Add CPU regression tests for host destination marking and an ack arriving immediately during ABORT notification.
