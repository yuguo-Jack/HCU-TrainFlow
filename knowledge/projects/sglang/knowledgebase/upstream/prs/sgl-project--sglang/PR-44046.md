# [Feature] Opt-in compact readout for PPLX decision checkpoints

[Upstream PR](https://github.com/sgl-project/sglang/pull/44046) · state: open · merged: False

## Original PR description

## Motivation

Closes #44044.

`perplexity-ai/pplx-decider-v1.1-27b` ships a 255-row decision readout (`readout.safetensors`, `[255, 5120]`) instead of an LM head. The current loader scatters those rows into a zero-filled `[248320, 5120]` vocabulary head (≈2.368 GiB in BF16) and projects every scored position onto the full vocabulary. This PR adds an **opt-in** mode that keeps the native readout (≈2.49 MiB) and scores the pooled hidden state directly.

## Modifications

Enabled with:

```bash
--json-model-override-args '{"sglang_pplx_compact_readout":true}'
```

- **`layers/compact_decision_head.py`** (new): `CompactDecisionPooler` — LAST-token pooling of the backbone's final hidden state, then the native `[num_codes, hidden]` readout. No vocabulary head, logits buffer or sampler conversion.
- **`models/qwen3_vl.py`, `models/qwen3_5.py`**: `build_lm_head=False` skips `lm_head`/`LogitsProcessor` construction; the existing readout loader fills the compact head before the scatter branch. Backbone, vision tower and mRoPE are unchanged.
- **`configs/model_config.py`**: parses the flag (must be a JSON boolean), requires a decision checkpoint, rejects combination with a joint schema head, and marks the model non-generative.
- **`arg_groups/model_hook.py`**: TP=PP=1, unquantized native impl only; LoRA, speculative decoding and MIS are rejected. Resolves `is_embedding=True` and disables radix cache / chunked prefill.
- **`managers/tokenizer_manager*.py`, `entrypoints/systemone/serving.py`, `entrypoints/openai/serving_decisions.py`**: route compact checkpoints through the embedding path; generation/chat requests and unsupported pooling/scoring options are rejected before scheduling.
- **Docs**: a Configuration Tips entry on the PPLX-Decider-v1.1-27B cookbook page.
- The trained-protocol functions (`_encoded_decider_questions`, `_decider_question`, `_answer`, `_choice_confidence`, `_score_confidence`) are unchanged. Without the flag, the existing vocabulary-head path is untouched.
- Tests: `test/registered/unit/layers/test_compact_decision_head.py`, `test/registered/unit/entrypoints/systemone/test_compact_decider.py` (new), plus cases in `test/registered/unit/configs/test_model_config.py`.

## Accuracy Tests

**Setup.** 1× H20 96GB, CUDA 13.0, torch 2.14.1+cu130, flashinfer 0.7.1, sglang-kernel 0.4.9, transformers 5.19.0, this branch on `7ff3a112`. Two servers that differ only in the flag: `--attention-backend flashinfer --dtype bfloat16 --tp-size 1 --context-length 8192 --max-total-tokens 8192`, prefill CUDA graphs enabled on both. The same requests were sent to each through `/v1/systemone`.

**Unit tests** (`test_compact_decision_head.py`, `entrypoints/systemone/`, `test_model_config.py`): 34 passed, 20 subtests passed, 0 failed. The existing `test_joint_schema.py` also passes (10 passed, 8 subtests).

**Baseline (flag off) vs compact (flag on)**, max absolute probability difference per request:

| Request | Input tokens | Questions | Max prob diff | Top choice |
|---|---:|---|---:|---|
| req0 | 205 | choice + noul | 2.3e-10 | same |
| mid_short (concurrent) | 179 | noul | 6.9e-09 | — |
| mid_medium (concurrent) | 1393 | choice | 3.6e-12 | same |
| mid_long (concurrent) | 2679 | choice | 3.4e-09 | same |
| mid_mixed (concurrent) | 5346 | choice + noul | 6.5e-09 | same |
| long8k | 7844 | choice | 4.9e-12 | same |

No top-choice flips. The four `mid_*` requests were sent concurrently as one variable-length batch.

Not yet covered: parity against the model's reference (transformers) implementation, image inputs, and the FA3 / TRT-LLM attention backends.

## Speed Tests and Profiling

**Memory** (`Load weight end`, as reported by SGLang):

| | Weight memory |
|---|---:|
| Baseline | 51.05 GB |
| Compact | 48.71 GB |
| Saved | 2.34 GB (expected ≈2.37 GiB) |

`--max-total-tokens` was pinned on both sides so the freed memory is not absorbed into a larger KV pool.

**Latency** (p50 over 100 rounds, ms):

| Request | Baseline | Compact |
|---|---:|---:|
| req0 | 102.8 | 101.8 |
| mid_short | 948.4 | 928.3 |
| mid_medium | 2793.6 | 2800.3 |
| mid_long | 2792.7 | 2799.9 |
| mid_mixed | 3876.6 | 3885.8 |
| long8k | 3275.9 | 3283.6 |

Latency is unchanged within noise: the baseline projects onto the vocabulary only for the last position of each request, which is small next to the backbone, so the benefit is memory, not speed. The concurrent `mid_*` latencies most likely include queueing, because their combined 9,597 tokens exceed the pinned 8,192-token pool.
