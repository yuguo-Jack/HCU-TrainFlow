# [Rust] Warm up every attention-DP listener so each reports healthy

[Upstream PR](https://github.com/sgl-project/sglang/pull/42642) · state: closed · merged: False

## Original PR description

## Motivation

With `SGLANG_RUST_SERVER=1` and attention DP, each DP group's first rank runs its own Rust listener, on the base port plus the group's index within its node. Since #37994, each listener's `/health` stays 503 until a startup warmup request succeeds on that listener. The startup warmup still sends one request to the base port on node 0 only, so:

- On a single node, only the base-port listener reports healthy. The others stay at 503 and a load balancer never routes to them, unless the server runs with `--skip-server-warmup`.
- On other nodes, nothing sends a warmup, so their listeners also stay at 503.

#38010 (closed) warmed the other listeners on the same host; #37994 landed without that part.

## Modifications

- `rust_listener_ports_on_node()` lists the ports of this node's Rust listeners, computed the same way `RustServer.launch` binds them (for elastic EP scale joiners, over their whole local TP group). `node_hosts_rust_server()` now uses it.
- In Rust mode, the startup warmup waits for `/model_info` on each local listener, then sends each one its own single-prompt warmup. The warmups run concurrently. For PD, each listener gets one fake-bootstrap request. The Python frontend's warmup is unchanged.
- Nodes other than node 0 that host Rust listeners now run the same warmup for their own listeners before waiting on the schedulers. Elastic EP scale joiners still skip it there, as they do with the Python frontend.
- Tests:
  - The listener-port helper matches the ports `RustServer.launch` binds, per node.
  - The Rust-mode warmup reaches each listener concurrently.
  - The PD fan-out covers several URLs.

This conflicts with #42639 and #42620 only in the import lines of `test_rust_server_dp_ports.py`; keep both sides.

## Tests

- `python -m pytest -q test/registered/unit/entrypoints/test_http_server_warmup.py test/registered/unit/entrypoints/test_rust_server_dp_ports.py`: 18 passed.
- `pre-commit run --from-ref origin/main --to-ref HEAD`: all hooks pass.
- Real launch on two A100s, Rust mode, warmup on: `--model-path Qwen/Qwen1.5-MoE-A2.7B-Chat --tp 2 --dp 2 --enable-dp-attention --port 32000`.
  - With this PR: each listener (32000 and 32001) answered `/model_info` and one warmup `/generate`, and the two warmups finished 0.2 ms apart. Both listeners reported healthy within a second of each other, and a `/generate` to each returned 200.
  - On current main: the base-port listener reported healthy 129 s after launch. The second listener still returned 503 three minutes later, although a `/generate` sent to it directly returned 200.
- PD prefill with the same parallelism (`--disaggregation-mode prefill`, nixl), warmup on, in the two-A100 PD setup from #42641 (decode `--tp 1`, mini load balancer with each prefill listener as its own URL):
  - With this PR: the prefill log shows `Disaggregation warmup requests completed for 2 DP ranks`, and both listeners reported healthy.
  - With all the related Rust-frontend PRs merged, including #42641: all 40 requests from that PR's run succeeded, with no conflicts and both DP ranks running prefill. That run had needed `--skip-server-warmup` before.
- Triton attention, pytorch sampling and `--cuda-graph-backend-prefill disabled` because of the local environment.
- Not run: multi-node; only one node was available. The per-node port lists for multi-node layouts are covered by the unit test.
