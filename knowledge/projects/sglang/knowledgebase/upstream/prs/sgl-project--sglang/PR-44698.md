# [Fix] hicache: Ignore stale prefetch queries after reissue

[Upstream PR](https://github.com/sgl-project/sglang/pull/44698) · state: open · merged: False

## Original PR description

## Motivation

In `buffer_only` mode, a storage prefetch can be cancelled and reissued with the same `CacheRequestHandle` while the original query is still in flight. The hit-queue drain looks up the current prefetch by handle, so processing the terminated old operation revokes the replacement and removes its prefix context. The same problem occurs when an old hit remains queued for allocation after cancellation.

## Modifications

- Require `info.operation is operation` before updating the current prefetch from a query result or retrying a queued allocation. Storage-belief updates still run when consuming the synchronized query result, before this check.
- Add regressions for late misses, late hits, and queued hits consumed after cancellation and reissue. Check that the replacement and its prefix context survive, and that its own query result is still processed.

## Verification

  python -m pytest -q \

Both hosts: **41 passed, 22 subtests passed**. Running the new regressions with `UnifiedRadixCache` from `dfc89580f1225d2806f7d60ed105761cc5aff067` fails in all three scenarios: the replacement has been removed from `ongoing_prefetch`.

The new tests use fixture-backed cache state and the actual prefetch lifecycle methods. No model inference or accelerator transfer was exercised.
