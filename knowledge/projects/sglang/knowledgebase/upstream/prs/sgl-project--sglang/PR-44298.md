# [Perf] [NVIDIA] dsa: Shard k-pool prefill rows across TP

[Upstream PR](https://github.com/sgl-project/sglang/pull/44298) · state: open · merged: False

## Original PR description

## Motivation

Large CUDA k-pool prefills repeat the indexer logits and top-k work on every attention TP rank. Split the query rows across ranks and gather the selected indices.

## Modifications

Add `SGLANG_OPT_USE_DSA_KPOOL_PREFILL_TP=1`, off by default, for large eager CUDA prefills using the k-pool extend plan. Each rank processes its rows within the existing memory-budget chunks and gathers int32 indices, preserving -1 padding.

Context parallelism, scattered inputs, graph capture/replay, empty key pools, small batches and the unplanned path keep the existing behavior. Every TP rank must select the same path because it adds a collective.

## Accuracy Tests

CPU row-sharding, scheduling and environment suites pass, along with scoped formatting and registration checks. The production-selector check stubs the gather, so it does not validate NCCL or GPU numerics.

An earlier TP4 B200 NCCL check of the row-chunk method matched the replicated result for uneven rows, chunk boundaries, page-table mappings and padding. That check predates this PR head. Earlier full-model measurements combined other changes and do not establish accuracy for this branch.

Run the focused CPU suites with `python -m pytest`. Full-model accuracy on the current PR commit is still required before merge.

## Speed Tests and Profiling

An earlier v0.5.20 backport on TP4 B200, GLM-5.3-Flash FP8 and other serving patches measured a 44K-token prefill behind 60K cached tokens. Interleaved sharded and replicated indexer runs averaged 1.0354 s and 1.0878 s respectively, a 4.8% reduction. Warm-server variation was about 0.3% to 1.1%; restarts moved baseline latency by about 2.5%.

These are backport measurements. Accuracy and speed on this exact PR commit, TP8 and other GPUs remain unvalidated.
