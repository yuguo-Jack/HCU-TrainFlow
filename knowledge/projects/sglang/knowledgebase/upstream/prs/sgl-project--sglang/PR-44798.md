# [Perf] muse-spark: remove o-proj and moe tail from Helion verify megakernels

[Upstream PR](https://github.com/sgl-project/sglang/pull/44798) · state: open · merged: False

## Original PR description

## Motivation
With optimizations to the o-proj and tail kernels, the TP4 verify megakernels' lead over today's default (EP4) on the E07 OpenHands replay shrank from 1.10x to 1.03x TPOT.

We simply remove the helion overrides for tail and o-proj and restore: `dev` o-projection, all-reduce, and attention-boundary norms. This brings us back to **1.08x** output tok/s vs dev EP4 on the OpenHands eval. 

This keeps the performant moe and attention megakernels:

| Megakernel | Default EP4 kernels | Default | Helion | Speedup |
|---|---|---|---|---|
| Attention | QK norm + RoPE (Triton), attention (FlashInfer), norm + gate (CUDA) | 12.3 µs | 10.1 µs | 1.22× |
| Router | pooler (FlashInfer), router GEMM (cuBLASLt), quant + top-8 (CUDA) | 13.4 µs | 12.7 µs | 1.06× |
| MoE | MoE (FlashInfer), finalize + combine (CuTe DSL) | 61.9 µs | 55.6 µs | 1.11× |
| LM head | GEMM + split-K reduce (cuBLASLt) | 137.4 µs | 135.9 µs | 1.01× |

## Modifications
- Restore stock O-projection, all-reduce and attention-boundary norms. Got rid of tail megakernel.
- `attention_boundary_verify_megakernel.py`: drop roots A/B/C; the input is the stock pre-FFN-normed hidden state.  Pooler K block 64 and 8 warps (tuned on GB300).
- `moe_tp4_verify_megakernel.py`: trigger dependents at entry so the stock unpooler GEMM prefetches during R3. The tail megakernel stays in-tree, unused (can go in a follow-up).
- `integration.py` / `megakernel_verify.py`: compose the stock modules around the megakernels.

## Accuracy Tests
Megakernel TP4 on this branch, real outputs (no forced acceptance):
- AIME26 (sgl-eval, thinking, reasoning effort xhigh, temperature 1, top-p 0.95, 400K max tokens, 2 repeats, 4 x
  GB300): **58/60 pass@1 (96.7%)**, pass@2 30/30, 0 truncated, 0 errors (reference 94.6%).
