# [Perf] flashinfer_cutedsl: Use swap-AB MoE on Blackwell

[Upstream PR](https://github.com/sgl-project/sglang/pull/48350) · state: open · merged: False

## Original PR description

## Motivation

@humansand

Use the swap-AB split CuTe DSL MoE added in [FlashInfer #7290](https://github.com/flashinfer-ai/flashinfer/pull/7290) on Blackwell SM100/SM103, with the matching checkpoint weight layout.

**Merge prerequisite:** keep this PR draft until SGLang's upstream FlashInfer dependency bump includes #7290 (merge `338924c2541673cedb6098185690eb54f26a5cde`). Version pins, Docker images, and dependency upgrades are outside this PR.

## Modifications

- **Dispatch:** select `swap_ab=True` for SM100/SM103 using the weight tensor's device; retain the legacy mode on other architectures. The same selector drives preparation and `CuteDslMoEWrapper` construction.
- **Weight preparation:** replace SGLang's local interleave helper with public `flashinfer.fused_moe.interleave_cute_dsl_moe_weights`. Prepare paired packed FC1 weights and row-major block scales before existing swizzle/MMA conversion, using 16-row groups for swap-AB and 64-row groups otherwise. Checkpoint values/global scales are preserved; no requantization.
- **Reuse:** existing ModelOpt and inherited `nvfp4_online` loading, standard/all-to-all wrapper paths, W4A4 scalar/per-token and W4A16 selection, activation handling, and in-place reload updates.
- **Processed-weight caches:** add the selected layout to standard CuTe DSL presharded cache keys. Old caches and opposite-layout caches are rebuilt instead of being reused with incompatible execution. Other backends retain their cache keys.
- **Boundaries:** DeepEP's masked CuTe DSL path, MegaMoE, other MoE backends, and FC2/non-gated weight row layouts retain their existing preparation.

## Speed Tests and Profiling

**Keep FlashInfer autotuning enabled when performance matters.** All performance results below use independently autotuned legacy and swap-AB layouts, with the selected tactics frozen across timing repeats.

- **Workload:** one C3 B300, local TP1/EP1, E32/H7168/I2048/top8, SwiGLU, 16 tokens. Both layouts use identical seeded serialized weights, inputs and routes, and FlashInfer merge `338924c2`.
- **Autotuning:** tune only bucket 16 for each mode/layout before measurement. The reverse-order process loads the same four caches and verifies their SHA-256 hashes and resolved tactics; no runtime cache misses occurred.
- **Timing:** two fresh-process sweeps, legacy→swap then swap→legacy. Each phase uses 10 warmups and 100 untrimmed CUDA-event samples around whole-forward CUDA graph replay with warm L2. Initial activation quantization is included; precomputed route selection, weight preparation, reload, tuning and graph capture are excluded. No clock locking or CUPTI timing.
- **Metrics:** pooled medians include all 200 samples per arm/case, 800 samples total. Speedup = legacy pooled latency / swap pooled latency - 1. Repeat spread = max(phase medians) / min(phase medians) - 1.

| Mode | Tokens | Legacy first µs | Swap second µs | Swap first µs | Legacy second µs | Legacy pooled µs | Swap pooled µs | Speedup | Legacy spread | Swap spread |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| w4a4_scalar | 16 | 146.912 | 132.224 | 131.328 | 147.296 | 147.136 | 131.712 | +11.71% | 0.26% | 0.68% |
| w4a4_per_token | 16 | 160.384 | 138.896 | 138.192 | 160.352 | 160.352 | 138.368 | +15.89% | 0.02% | 0.51% |

All eight measured arms preserved exact initial/reloaded cross-layout outputs and graph replay. These results cover the two autotuned M16 layer cases above; they do not establish performance for other token counts, W4A16, distributed EP8, or full-model serving.
