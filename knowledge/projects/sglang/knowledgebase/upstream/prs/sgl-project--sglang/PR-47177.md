# [Perf] pd: Copy the last chunk's state page indices to the host without a scheduler sync

[Upstream PR](https://github.com/sgl-project/sglang/pull/47177) · state: closed · merged: True

## Original PR description

## Motivation

On a PD prefill worker under the overlap scheduler, `_send_kv_chunk` already hands a sender that declares `supports_host_tensor_indices` its KV page indices as a pinned host tensor plus a CUDA event, so the scheduler thread does not wait on the in-flight forward to send a chunk (#45492). The last chunk's state payloads were left out of that path: the sliding-window and full-KV state page indices still went through `kv_to_page_indices`, a `.cpu()` on the schedule stream. `_apply_war_barrier` fences that stream behind the running forward, so the copy returns only when that forward's reads are done, and the scheduler thread still blocked once per request, in `process_batch_result`, right before the hand-off to the transfer.

## Modifications

- `_send_kv_chunk` decides the host-tensor path once per call: a sender with `supports_host_tensor_indices`, outside the context-parallel transfers that filter indices on the host. The per-segment KV page indices use it as before.
- The last chunk's SWA-window and full-KV state page indices now take the same copy (`async_d2h` into pinned memory), returned as a NumPy view of the host tensor so the sender's consumers keep their types. The state rides the last segment's send, whose `indices_event` is recorded after these copies on the same stream; the Mooncake transfer worker already synchronizes that event before it reads the chunk, and on the scheduler thread the sender only takes their length.
- Senders without host-tensor support keep the synchronous read. The Mamba and DSA state payloads are unchanged; they do not go through `kv_to_page_indices`.

## Accuracy Tests

No numerics change: the same page indices reach the transfer, later. Ran the unit tests that drive `_send_kv_chunk` and the Mooncake chunk queue against this branch:
