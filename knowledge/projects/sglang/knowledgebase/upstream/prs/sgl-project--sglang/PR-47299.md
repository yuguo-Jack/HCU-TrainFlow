# [Perf] [AMD] unquant: backport gfx11 weight-row padding (#46327) to amd_march

[Upstream PR](https://github.com/sgl-project/sglang/pull/47299) · state: open · merged: False

## Original PR description

## Motivation

Backport of #46327 to `amd_march`, since RDNA changes land here first (#31805). The full motivation, root cause and results are in #46327.

On gfx11, a bf16/fp16 weight whose row stride is a multiple of 2 KiB maps the rows a skinny GEMM reads together onto the same L2/MALL channel. This PR gives those unquantized linear and LM-head weights a 128 B row pad at load time. Shapes and values stay the same; only the stride changes. Untied input embeddings, quantized layers, fp32 weights and MoE experts are left alone. `SGLANG_DISABLE_GFX11_WEIGHT_PADDING=1` turns it off.

## Modifications

Same code as #46327, with two differences:
- **Conflicts:** context only (neighbouring lines that `amd_march` doesn't have) in `environ.py`, `unquant.py` and `loader.py`. Only this PR's own lines were kept.
- **Test:** `amd_march` has no `sglang.test.parallel_groups`, so the test calls `runtime_context.publish` directly and installs the TP / attention-TP group stubs itself. Those stubs are what the embedding's forward reads.

## Results

Decode gains with padding on vs `SGLANG_DISABLE_GFX11_WEIGHT_PADDING=1`; prefill and GSM8K unchanged in all three:

| GPU | Model | 1 stream | Batched |
|---|---|---|---|
| gfx1151 (Strix Halo) | Llama-3.1-8B | +27% | +23% (8-way) |
| gfx1151 (Strix Halo) | Qwen2.5-3B | +30% | +33% (8-way) |
| gfx1100 (W7900-class), on `amd_march` (@vivienfanghuagood, #46327) | Qwen3-8B | +20.9% | +18.0% (c=8), +10.4% (c=32) |
