# [Refactor] linker: Use dedicated configuration throughout linker setup

[Upstream PR](https://github.com/sgl-project/sglang/pull/46388) · state: closed · merged: True

## Original PR description

## Motivation

External linkers now consume their own configuration throughout construction and the in-tree launch recipes. This follows #40595, which introduced `--unified-cache-external-linker-config` but left the built-in constructors and existing callers using the HiCache option.

## Modifications

- Warn only when an external linker actually consumes the legacy HiCache configuration at startup. CLI help marks this fallback deprecated; a TODO tied to #46388 schedules removal after one full stable-release deprecation cycle following the first release containing the warning. Ordinary HiCache use of the flag is unchanged.

- Pass the backend and linker config explicitly to the shared factory. Mooncake and MORI consume only their `extra_config` argument.
- Resolve the legacy HiCache option at the startup boundary for backward compatibility, including `@file` input. An explicit linker config, including `{}`, takes precedence. Explicit factory calls never inherit launch defaults.
- Migrate linker KL tests, AgentX deployment recipes, and playground configuration handling to `--unified-cache-external-linker-config`. Ordinary HiCache configuration is unchanged.
- Extend the existing factory tests to cover explicit-config isolation.

## Validation

- Applicable pre-commit hooks and `git diff --check` passed.
- `node docs/scripts/check_cookbook_configs.mjs` passed.
- Six local control-flow checks passed using the production config/factory and extracted legacy parser with mocked backend services. They cover legacy inline/file input, empty override, dynamic selection, private config copies, constructor arguments, and invalid plugin rejection. These are not the full registered suites or GPU validation.
- Full registered CPU suites could not collect in the local macOS environment because runtime dependencies are unavailable/incomplete. GPU E2E was not rerun; CI results are tracked separately.

## Accuracy Tests

No changes to KV transfer or model computation. No new inference accuracy claim.

## Speed Tests and Profiling

- nvpohanh · comment · 2026-10-26T04:37:00Z · [source](https://github.com/sgl-project/sglang/pull/46388#issuecomment-6408341029)

[by Claude Code] Heads-up: #46506 regenerates the cookbook's AgentX data files (`docs/src/snippets/agentx/`), so the Mooncake external-linker workers there show `--hicache-storage-backend-extra-config` again instead of `--unified-cache-external-linker-config`.

Those files are generated: they mirror the launches that SemiAnalysis InferenceX ran and measured, in the image each run used. Those recipes pass `--hicache-storage-backend-extra-config`, and every submission image the page names predates `--unified-cache-external-linker-config` (it reached `main` on 2026-10-25 in f82af9ca17), so the renamed commands would fail to parse in the image shown next to them. This PR keeps the old flag working for external linkers (deprecated), so the mirrored commands still run on current SGLang too.

Your `_agentx.jsx` change is kept: `LINKER_FLAGS` now lists both spellings, so switching a cell's KV tier strips either. Please don't hand-edit the AgentX data files: the next sync overwrites them. If a mirrored launch needs a change, the sync's rules (or the InferenceX recipe) are the place for it.
