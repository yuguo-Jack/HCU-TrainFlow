# [CI] ci: Preload `sglang.test.test_utils` in CPU fork workers

[Upstream PR](https://github.com/sgl-project/sglang/pull/47592) · state: closed · merged: True

## Original PR description

- `fork_test_worker.py` takes `--preload MOD ...` and imports those modules after the common numpy/torch/triton stack, before it forks; a module that fails to import is logged and skipped, so the child imports it itself.
- `run_suite.py --fork-worker-preload` passes the list through `run_unittest_files` to the worker.
- The CPU stage (`_pr-test-stage-cpu.yml`) preloads `sglang.test.test_utils`. About 650 of the ~930 `base-a-test-cpu` files import it, mostly for `CustomTestCase`, and its import chain (`sglang.benchmark.serving` -> `transformers`, `sglang.srt.layers.quantization` -> `sgl_kernel` -> `flashinfer`) costs about 7s per file on 4 cores, while a typical test body runs in about 1s.
- `base-a-test-cpu` in CI, this PR (run 41167919034) against a recent main run (41045755944): the summed `Run test` step drops from 10415s to 3902s, the slowest partition from 607s to 245s, and the median per-file time from 10s to 2s. All 973 files run and pass. A side-by-side full run with and without the preload on one CPU-only machine executed and skipped the same cases (12245 and 152), file by file.

No behavior change outside the CPU stage: the JIT kernel lane keeps using the fork worker with no extra preloads.
