# [Fix] [AMD] moe: Keep the fake EP dispatch's zeroed correction bias on the aiter path

[Upstream PR](https://github.com/sgl-project/sglang/pull/44909) · state: open · merged: False

## Original PR description

## Motivation

Fixes #44897. With `--ep-dispatch-algorithm fake`, `transform_select_experts_inputs` fills the router logits with noise and replaces the correction bias with zeros, so the simulated routing ignores the bias. On ROCm with aiter, `select_experts` then overwrites that zeroed bias with `topk_config.correction_bias_for_dtype(router_logits.dtype)`, a cached cast of the model's real bias. The aiter router picks experts from noise plus the real bias, so the "fake" expert distribution is skewed toward the experts the bias favours. On CUDA the zeroed bias is kept.

## Modifications

- `python/sglang/srt/layers/moe/topk.py`: use the cached cast only while `correction_bias` is still `topk_config.correction_bias`. A bias that `transform_select_experts_inputs` replaced is passed through unchanged; the aiter branch of `biased_grouped_topk_gpu` already handles either dtype per call.
- `test/registered/unit/layers/moe/test_topk_correction_bias_cache.py`: a CPU regression test that runs `select_experts` with `_use_aiter` patched on and the aiter kernel mocked, and records the bias the router receives. With fake dispatch the bias must be all zeros (bf16 and fp32 bias); with no dispatch info and with `static` dispatch it must still be the config's bias, so normal serving is unchanged.

This is independent of #44797, which skips the cast for fp32 biases (#44794). That PR alone keeps the zeroed bias only when it is fp32; a bf16 bias, as DeepSeek checkpoints with fp8, compressed-tensors or quark quantization have on aiter, would still be replaced. Both PRs add a condition to the same `if`, so whichever merges second needs a one-line rebase that keeps both conditions.
