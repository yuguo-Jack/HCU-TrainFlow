# [sglang-miles] Cherry-pick #37740: keep deterministic inference off the Lean path

[Upstream PR](https://github.com/sgl-project/sglang/pull/39581) · state: open · merged: False

## Original PR description

## Why

True on-policy validation for AMD's Q3 milestone
([radixark/miles#2025](https://github.com/radixark/miles/issues/2025)) needs the logprobs
from rollout to match the ones recomputed in training, but on MI355X / gfx950 they differ
even with `--enable-deterministic-inference`. Lean Attention spreads the whole batch's KV
tiles over a fixed grid, so one request's result depends on which other requests share its
batch.

## What

- Use the standard Triton decode path when deterministic inference is on, instead of Lean
  Attention.
- Cherry-pick #37740 (`cf2b485914`) onto `sglang-miles`, which is still exposed because
  that PR has not landed on `main` yet.
- Keep the diff identical to #37740, so a later rebase sees one patch, not two.
- Drop this commit on the first rebase after #37740 lands.

## Result

- On gfx950, `test_deterministic` `single` goes from FAIL `[2]` to PASS `[1]` and `prefix`
  from FAIL `[2, 4, 3, 14]` to PASS `[1, 1, 1, 1]`. `radix_cache` passes either way.
- Running one prompt alone, then as row 0 of a 64-row batch, gives 128/128 bitwise-equal
  logprobs instead of 51/128. Max abs diff drops from 5.43e-5 to 0.0.
- Both runs left `SGLANG_DISABLE_LEAN_ATTENTION` unset, so deterministic mode alone is now
  enough. Tested on Qwen3-0.6B with CUDA graph, radix cache and chunked prefill all on.
- Normal serving is unchanged, and NVIDIA is unaffected because Lean only runs on HIP.
