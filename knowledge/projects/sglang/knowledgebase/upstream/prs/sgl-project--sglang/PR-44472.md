# [Fix] distributed: Detect MNNVL fabric independently of GPU names

[Upstream PR](https://github.com/sgl-project/sglang/pull/44472) · state: open · merged: False

## Original PR description

## Motivation

`is_mnnvl_fabric_device()` currently recognizes only GPU names containing `GB200` or `GB300`. On an OEM-named GB300 system, NCCL can establish cross-node `P2P/MNNVL` while SGLang reports no fabric, skips its multi-node NCCL defaults, and rejects `fi_a2a` for a cross-node DCP group.

Fixes #44470.

## Modifications

- Replace the GPU-name whitelist with the existing NVML-based `is_gpu_fabric_ready()` query for the first visible CUDA device. Require completed fabric initialization and a successful NVML fabric status.
- Resolve the CUDA ordinal through PyTorch's NVML device-index mapping, including reordered and UUID-based `CUDA_VISIBLE_DEVICES`.
- Correct the legacy NVML fabric structure field from `partitionId` to `cliqueId`.
- Add 15 CPU CI tests covering name independence, incomplete/error fabric state, V3/legacy queries, device mapping, unavailable NVML/non-CUDA systems, cleanup, and cross-node versus node-local DCP backend eligibility.

The predicate remains a cached, local-device startup check. It does not establish that all process-group ranks share one fabric domain or that IMEX/remote imports are operational.

## Accuracy Tests

CPU tests on the actual production modules, with CUDA/NVML responses mocked:

```bash
SGLANG_USE_CPU_ENGINE=1 PYTHONPATH=python \
  python -m unittest discover \
  -s test/registered/unit/utils \
  -p test_mnnvl_fabric_detection.py -v
```

Result: **15 tests passed**. The name-independence, unjoined-fabric, and OEM cross-node DCP cases were also run against unmodified main at `f7ad4345b86d147a1c3095a3cebabca9a33ebaa1`, producing the expected five failing assertions/subtests.

`pre-commit run --files` passed for all three changed files, including registered-test validation. Python compilation and `git diff --check` passed.

Hardware observation motivating this change: 2 nodes × 4 GB300 GPUs, TP8/DCP8, with a custom CUDA device name. A temporary local whitelist addition on a v0.5.21-based image removed the backend rejection. **That was not this NVML implementation.** This PR is draft pending GPU validation of this exact implementation, including backend selection, startup, and request completion. No new model-output accuracy result is claimed.

## Speed Tests and Profiling

No performance claim. The reported C128 failure and its cause are outside this PR's scope. A local fabric readiness result or successful backend selection alone does not demonstrate that failure is fixed.
