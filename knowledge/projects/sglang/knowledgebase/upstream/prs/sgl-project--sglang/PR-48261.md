# [Fix] hicache: Carry captured routing rows with KV between device and host

[Upstream PR](https://github.com/sgl-project/sglang/pull/48261) · state: open · merged: False

## Original PR description

## Motivation

  Fixes #26975. The routed-experts and indexer-topk capturers index rows by device KV slot. HiCache load-back moves KV to new slots without recomputing routing, so a host-tier hit returns another
  request's rows.

  ## Modifications

  - New `state_capturer/hicache_carry.py`:
    - copies captured rows to a host-slot-indexed store on every HiCache backup, and back into the new device slots on load;
    - refuses to load rows that were never backed up.
  - Hooks for write-through/back, load-back, and retraction backup/restore, via a new `on_allocated` callback on `HybridCacheController.write` and `load`.
  - A chunk stashed while its forward is still in flight (overlap/pipeline) defers its backup until every capture output in flight is finalized.
  - The capture flags are rejected with `--hicache-storage-backend`, since storage prefetch carries no rows.

  ## Accuracy Tests

  - New CPU tests in `test_hicache_carry.py`, including an overlap-schedule fuzz and a pre-fix control. There are no new failures in `unit/mem_cache`, `unit/state_capturer` or `unit/managers`.
  - The same design runs in our RL stack: on Qwen3-30B-A3B TP8, 4,108 of 4,108 host-restored rows matched, versus 0 with the carry disabled.

  ## Speed Tests and Profiling

  The carry copies CPU rows only on HiCache backup and load. Restoring 4,108 rows took 0.9 ms (median).
