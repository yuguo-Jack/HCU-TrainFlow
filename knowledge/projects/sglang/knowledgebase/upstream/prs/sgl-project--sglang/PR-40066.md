# [Fix] [CPU] memory: Honor cgroup memory.max when sizing CPU memory

[Upstream PR](https://github.com/sgl-project/sglang/pull/40066) · state: closed · merged: True

## Original PR description

## Motivation

Re-submit of #38260.

On CPU, sglang auto-computes mem_fraction_static from total host memory and does not honor container cgroup memory limits. This makes a single server reserve a huge KV-cache pool regardless of the actual model size, and makes it impossible to run multiple sglang containers on one host safely.

## Modifications

Added a `get_instance_memory_status` function which tries to retrieve the cgroup memory limit from /sys/fs/cgroup/memory.max and memory status from /sys/fs/cgroup/memory.current . Existing CPU mem acquisition approach  psutil.virtual_memory().total is used as a fallback.

* This adds parsing and fallback behavior that is used by CPU memory sizing, but the existing `test/registered/unit/utils/test_common.py` has no coverage for this function. Please add focused tests for a byte limit, `max`, malformed content, and `FileNotFoundError`/permission fallback so cgroup environments and non-cgroup hosts cannot silently regress.
```
def get_available_cpu_memory():
    # Try to retrieve CPU memory limit from /sys/fs/cgroup/memory.max
    # If no legal value returned, fallback to querying psutil.virtual_memory().total
    try:
        with open("/sys/fs/cgroup/memory.max", "r") as f:
            content = f.read().strip().lower()
            # Match a number followed optionally by a unit (e.g., "512m", "2gb", "1024", "512b", "1024bytes")
            match = re.fullmatch(r"(\d+)\s*([kmgt]b|[kmgt]|bytes|b)?", content)
            # "max" or other non memory size content will be skipped
            if not match:
                raise ValueError

            value_str, unit = match.groups()
            value = int(value_str)

            # Map units to their respective multiplier (binary/1024-based)
            # If no unit or unit is 'b'/'bytes', the value is already in bytes (multiplier = 1)
            if unit and unit not in ("b", "bytes"):
                multipliers = {
                    "k": 1024,
                    "kb": 1024,
                    "m": 1024**2,
                    "mb": 1024**2,
                    "g": 1024**3,
                    "gb": 1024**3,
                    "t": 1024**4,
                    "tb": 1024**4,
                }
                value *= multipliers[unit]
            return value

    except (PermissionError, FileNotFoundError, ValueError):
        return psutil.virtual_memory().total
```

This repeats the same incorrect accounting: `memory.max` is a cgroup limit, but `psutil.virtual_memory().used` is host-wide rather than the container's current usage. In a constrained container this can report a negative or otherwise unrelated amount of memory during graph capture. Use cgroup-local current usage (with a consistent fallback) before subtracting from the limit.

File: `python/sglang/srt/utils/common.py` · line None

When `/sys/fs/cgroup/memory.max` is set, this subtracts the host-wide `psutil.virtual_memory().used` from a container-local limit. On a busy host that value can exceed the limit (yielding negative available memory), and even when it does not it includes memory used by other containers/processes, so CPU KV-cache sizing is not based on this container's usage. Read the cgroup's current usage (for example `memory.current`) alongside `memory.max`, or preserve the existing `psutil.virtual_memory().available` fallback when the cgroup usage cannot be read.

This issue also appears on line 783 of the same file.
