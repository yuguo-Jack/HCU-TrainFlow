# [Perf] DSv4.1: Enable decoder bounded replay by default

[Upstream PR](https://github.com/sgl-project/sglang/pull/44403) · state: closed · merged: True

## Original PR description

[codex/claude generated]

## Motivation

Enable decoder SWA bounded replay by default for supported standalone CUDA DeepSeek-V4.1 configurations, while preserving an explicit full-prefill opt-out. In our paired accuracy runs, AIME 2026 without an explicit output cap was identical (469/480 each); DeepSWE differed by one solved task and MMMU-Pro by five correct responses. These are finite, stochastic accuracy measurements, not proof of numerical equivalence or a universal speedup.

## Modifications

- Enable decoder replay by default on CUDA DSv4.1 unless `disable_decoder_bounded_replay` is set for eager/breakable prefill, with the existing DP-attention compatibility checks. Keep PD, context parallelism, encoder replay, other platforms, and incompatible configurations out of automatic enablement.
- Preserve explicit `--enable-decoder-swa-bounded-replay`; add `--disable-decoder-bounded-replay` to retain full prefill, including prompt-logprob support. Bounded replay remains numerically different from full prefill and does not support prompt logprobs.
- Include the candidate-table capacity fix needed for speculative verification beyond the 1,048,576-token boundary. Select the existing 16 KiB or expanded 32 KiB bitmap according to page-table capacity; reject unsupported capacities above 2M tokens. This fixes a shared indexer issue, not a replay-only failure, and does not enlarge the model context limit.
- Add default-resolution/CLI coverage and eager/CUDA-graph sorter boundary regressions; update the model cookbook and CLI help.

Base: upstream main `9d68ecce2e811d908551d58a2a8792c75245d181`. Main already includes breakable-prefill replay support; this PR does not reapply the historical #43440 patch wholesale.

### Revision scope and the original MMMU failure

These full benchmark runs predate the PR base above. DeepSWE/AIME ran on main `b60444c62169c7992b98f102cbc4e86d9d117294` plus #43440 head `729c1584e597c915f6dbb6207b89e90a09fcef33`, integrated locally as `b273c67e75a70c1971eb7715910d15c148136883`. Repaired MMMU added local fix `6dc4fa29df069c92668de2fc5ed7766dd49e378b`, transplanted in this PR. The full benchmarks have not been rerun on the new main/default-selection patch.

Both original MMMU arms crashed at the context boundary with `logical_page_idx < block_table_stride`. A minimal sorter reproducer passed at 1M tokens but lost the newest candidate at 1M+1, returning `INT32_MAX`. Original interrupted scores are invalid and excluded from the accuracy table. Both arms were rerun fresh with the same fix; both completed without request errors.

Omitting max_tokens still permits context-limit truncation. Repaired MMMU reached maximum generated lengths of 1,048,271 off and 1,048,285 on. The remaining truncations reflect length stopping, not a recurrence of the server crash.

Historical fix validation also included six sparse-indexer tests, sorter boundaries at 1,048,575 / 1,048,576 / 1,048,577 / 1,048,586 / 2,097,152 tokens in eager and captured execution, and an end-to-end DSPARK request with 1,048,544 input tokens plus 30 output tokens followed by a healthy server. The text-only boundary reproducer shows that images are not necessary to trigger this bug.

### Controlled fixed-token comparison on 4×GB300

Measured October 16, 2026 on the same node, sequentially replay off then on. Identical deterministic synthetic token-ID prompts, temperature=0, `ignore_eos=true`, exact output lengths, and three repetitions per case. Shape-specific warmup and server startup are excluded; the radix cache was flushed before each repetition. All 348 measured requests per arm passed exact prompt/output-length checks with zero cached tokens.

Both arms used DeepSeek-V4.1-Flash, TP4/EP4, attention DP=1, FlashMLA, DSPARK block size 5, breakable prefill, 16,384-token chunks, and a 16,384-token prefill graph context limit. Encoder replay was disabled. Effective server settings matched apart from decoder replay and runtime metadata.

**Single-request time to first token**, with one output token and five requests per repetition. Values are medians of the three per-repetition medians; speedup = off/on. This is client-observed first-token latency, not GPU-kernel-only time.

| Input tokens | Replay off TTFT | Replay on TTFT | Speedup |
|---:|---:|---:|---:|
| 1,024 | 42.89 ms | 42.92 ms | 0.999× |
| 8,192 | 174.50 ms | 172.54 ms | 1.011× |
| 32,768 | 480.92 ms | 346.89 ms | 1.386× |
| 65,536 | 974.77 ms | 700.62 ms | 1.391× |

**End-to-end output throughput**, with concurrency 16, 32 requests per repetition, and exactly 128 output tokens per request. Values are median repetition throughput; speedup = on/off.

| Input tokens | Replay off output tokens/s | Replay on output tokens/s | Speedup |
|---:|---:|---:|---:|
| 1,024 | 2054.97 | 2107.11 | 1.025× |
| 8,192 | 792.69 | 885.98 | 1.118× |
| 32,768 | 256.38 | 337.22 | 1.315× |

Long-prompt first-token latency improved by approximately **1.39× (28% lower latency)** at 32K/64K input; 32K concurrent throughput improved **1.315×**. Short single-request latency was essentially unchanged. Concurrent TTFT did not improve uniformly: at 1K input it was 163 ms off versus 184 ms on.

**Revision and interpretation limits:** these measurements use the retained repaired accuracy-test runtime, not a fresh checkout of current main or this PR head. The installed package reports `0.0.0.dev1+g67eab5705`; that build-version string alone does not identify later local patches. The candidate-table header SHA-256 matches the repaired benchmark (`d7088c2ac6c282ef2ae42cadcf527b21c36b165501add4d449b1c596bbbd16a2`). Synthetic token IDs control input shape but do not represent natural-language quality or every production workload. DSPARK acceptance can differ between modes even with fixed output counts. The sequential order was not counterbalanced, and three repetitions do not establish statistical confidence.
