# [Fix] function_call: Stream Kimi K3 tool-call arguments incrementally

[Upstream PR](https://github.com/sgl-project/sglang/pull/45774) · state: open · merged: False

## Original PR description

## Motivation

With `--tool-call-parser kimi_k3`, a streaming chat completion emits **no chunks while the model is generating a tool call**. The whole call (name + all arguments) is delivered as one `tool_calls` delta after `<|close|>call<|sep|>`. For agentic workloads where a call carries a whole file (`write_file` with thousands of tokens of `content`), the stream is silent for minutes; proxies with a per-chunk idle timeout (300 s in our deployment) kill the request and the generation is wasted. Details and a client-side timeline are in #45697.

Root cause: `KimiK3Detector.parse_streaming_increment` re-runs `_CALL_RE` over the whole buffer on every chunk, and that regex only matches a complete call. Most other detectors (`kimi_k2`, `qwen25`, `deepseekv31`, `glm47`) emit the name early and then stream `arguments` fragments.

## Modifications

`python/sglang/srt/function_call/kimik3_detector.py`, streaming path only:

- Replace the whole-call regex with a state machine over the XTML nesting (tools channel > call > argument value). Each state consumes one marker or a run of text at a time; the buffer is trimmed after every increment, so scanning is incremental.
- Emit a `ToolCallItem` with the name and empty parameters as soon as `<|open|>call tool="x" ...<|sep|>` is complete.
- `type="string"` arguments stream as they arrive: `{"key": "` / `, "key": "` on the open tag, `json.dumps(fragment)[1:-1]` for each text fragment (per-character escaping, so fragments concatenate to the escaped whole), `"` on the close tag. A suffix that could start a close marker is held back via the existing `partial_suffix_len`.
- Non-string arguments are emitted when they close (they need `json.loads`/`json.dumps` normalisation, and are short).
- `}` on `<|close|>call<|sep|>`. The concatenation of all fragments is byte-identical to `detect_and_parse`'s `parameters`, so `prev_tool_call_arr` / `streamed_args_for_tool` keep their contract with `serving_chat._check_for_unstreamed_tool_args` (it finds nothing left to send).
- A call cut off by end of stream or by `<|close|>tools<|sep|>` has its JSON closed (`"` and `}`) instead of being left as a dangling prefix; `detect_and_parse` drops such a call, but streaming has already sent its name. Logged at WARNING.
- Nameless calls are skipped without consuming a tool index, matching `detect_and_parse`.

`detect_and_parse` (non-streaming) is unchanged.

`test/registered/function_call/test_kimik3_detector.py`:

- Existing streaming tests now fold fragments per tool index before asserting.
- New: 300 seeded random-chunking cases asserting streamed output == `detect_and_parse` and the bookkeeping arrays; name + argument fragments arrive before the call closes; partial close marker held back; nameless call skipped; truncated call closed.

## Accuracy Tests

No model forward changes. Parser equivalence, checked offline:

- **Differential fuzz against the model's own renderer** (`encoding_k3.py` from the Kimi-K3 repo renders random OpenAI-style tool calls to XTML; the real K3 tokenizer splits it; chunks of 1 token, whole text, random 1–6 token groups, and single characters are fed through `ReasoningParser("kimi_k3")` → `FunctionCallParser` → the serving layer's completion check; 30 % of cases are truncated inside the tools channel). 4 seeds × 3000 messages = 144,000 streaming replays, 0 failures. Argument values deliberately include quotes, backslashes, control characters, CJK, emoji, `&amp;`/`&quot;`, and partial and complete `<|open|>`/`<|close|>`/`<|sep|>` markers. Per step it also asserts the name is sent once, fragments belong to the current tool, and the streamed prefix is always a JSON prefix.
- 1500 marker-free realistic calls (code in `content`): streamed arguments byte-identical to the renderer input in all 18,000 replays.
- Unit suites touching the parser chain (`test_serving_chat`, `test_serving_responses`, `test_kimik3_reasoning_parser`, `test_kimik3_structural_tag`, `test_kimik2_detector`, `test_function_call_parser`, `test_kimik3_detector`): 959 passed.

Known, intended differences from `detect_and_parse`: a call truncated mid-argument is kept and closed (non-streaming drops it); duplicate keys are all streamed (a JSON decoder keeps the last, as the non-streaming dict does).

## Speed Tests and Profiling

Parser-only, replaying a single `write_file` call in 4-char chunks:

| `content` length | old (µs/chunk) | new (µs/chunk) |
|---|---|---|
| 10k chars | 30 | 2.7 |
| 100k chars | 212 | 8.3 |
| 400k chars | 887 | 14 |

Simulated client timeline for the #45697 repro shape (≈4k tokens at 11 ms/token): first tool-call byte 45.0 s → 0.2 s after the call starts; longest silence 45.0 s → 0.25 s. Not yet verified end-to-end on a GPU server; I will add that before taking this out of draft.
