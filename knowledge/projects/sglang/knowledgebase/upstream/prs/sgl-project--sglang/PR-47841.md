# [Fix] transcription: Serve /v1/audio/transcriptions for Qwen3-Omni and Gemma 4

[Upstream PR](https://github.com/sgl-project/sglang/pull/47841) · state: open · merged: False

## Original PR description

## Motivation

`/v1/audio/transcriptions` returns HTTP 500 on every request for Qwen3-Omni and Gemma 4, so ASR evals through the endpoint score WER 100. The endpoint sends `text=""`, which reaches the multimodal processor as an empty `input_ids` list. Neither processor builds a prompt for a text-less audio request, so `load_mm_data` asserts:

- Qwen3-Omni: `assert isinstance(prompt, str)`
- Gemma 4: `assert len(prompt) and isinstance(prompt[0], int)`

Neither model has a transcription adapter either. `resolve_adapter` would fall back to `WhisperAdapter`, which adds Whisper-only sampling keys that only the Whisper processor removes.

The open ASR PRs #44452 (AudioFlamingo3, generic adapter) and #44473 (Voxtral, MiDashengLM) don't cover these models, and this PR doesn't depend on them.

## Modifications

**Qwen3-Omni**
- `QwenVLImageProcessor._build_omni_transcription_prompt`: for a `qwen3_omni_moe` audio request with no text, render the model card's evaluation prompt through the chat template. The audio comes first, then "Transcribe the \<Language\> audio into text.", with no system turn. For `zh` it uses the card's Chinese prompt; with no language it drops the language name. Caller text or `input_ids` pass through unchanged.
- `Qwen3OmniAdapter` (key `Qwen3OmniMoe`): duration-scaled `max_new_tokens` like the other speech-LM adapters. It forwards `request.language` in `sampling_params` and reports it in `verbose_json`.
- `BaseMultimodalProcessor._pop_transcription_language`: removes that key before `SamplingParams` sees it, the same way the Whisper processor handles its transcription keys.

**Gemma 4**
- `Gemma4SGLangProcessor`: for audio with no text, build the model card's ASR chat prompt, instruction before audio. In an A/B, audio first raised LibriSpeech test-other WER from ~14 to 23–37.
- `Gemma4Adapter` (key `Gemma4`, matches `Gemma4ForConditionalGeneration` and `Gemma4UnifiedForConditionalGeneration`):
  - duration-scaled `max_new_tokens`;
  - a 30 s clip limit, the model's audio maximum, so longer clips are split;
  - a `logit_bias` ban on `<|channel>` (id 100). With thinking off, the template already ends in an empty thought block. Under greedy decoding the model still reopens one on 2–5 % of clips and repeats it until `max_new_tokens`; HF transformers does the same on those clips. On 200 clips the ban takes loops from 10 to 0 and WER from 22.1 to 7.6.
- Cookbook: the Gemma 4 page documents the endpoint.

**Tests**
- `test/registered/unit/entrypoints/openai/test_transcription_adapters.py` covers:
  - adapter resolution for Qwen3-Omni and both Gemma 4 architectures;
  - sampling params, including language forwarding and the `<|channel>` ban;
  - the 30 s clip cap.
- New `test/registered/unit/multimodal/test_qwen3_omni_transcription_prompt.py` covers:
  - prompt text and audio/text order;
  - the `zh` and no-language cases;
  - pass-through of caller text and `input_ids`;
  - `language` being removed from `sampling_params`.

## Accuracy Tests

The harness is lmms-eval `sglang_asr`, which posts each clip to `/v1/audio/transcriptions`. I used it because sgl-eval ships no ASR task. Runs were on the full `openslr_librispeech_other` split (2939 clips), greedy, seed 42, on Intel Arc Pro B70 with `--attention-backend intel_xpu`. The image was `intel/sglang-dev:latest` `dbe08e9f1e24` (main@7fe5b127e4) with this branch on `PYTHONPATH`.

| Model | Before (stock) | After | Reference |
|---|---|---|---|
| Qwen/Qwen3-Omni-30B-A3B-Instruct | WER 100 (20/20 HTTP 500) | **2.41** | 2.48 (Qwen3-Omni tech report) |
| google/gemma-4-12B-it-qat-w4a16-ct | WER 100 (100/100 HTTP 500) | **6.42** | — |

The stock runs used 20/100-clip subsets because every request fails. After the fix, all 2939 requests returned HTTP 200, with no empty predictions and no server tracebacks. Only the Gemma 4 12B QAT checkpoint was measured; E2B/E4B resolve to the same adapter but were not run.

```bash
# Qwen3-Omni: 2x B70 (64 GB) can't hold the ~63.5 GB bf16 thinker, so tp2 + weight offload (same bf16 math)
SGLANG_USE_SGL_XPU=1 sglang serve --model-path Qwen/Qwen3-Omni-30B-A3B-Instruct --device xpu \
  --tp-size 2 --mem-fraction-static 0.85 --trust-remote-code --enable-multimodal \
  --cpu-offload-gb 10 --attention-backend intel_xpu

# Gemma 4
SGLANG_USE_SGL_XPU=1 sglang serve --model-path google/gemma-4-12B-it-qat-w4a16-ct --device xpu \
  --tp-size 1 --mem-fraction-static 0.6 --trust-remote-code --enable-multimodal \
  --json-model-override-args '{"audio_config":{"output_proj_dims":640}}' \
  --reasoning-parser gemma4 --tool-call-parser gemma4 \
  --mm-process-config '{"image":{"max_soft_tokens":560}}' --attention-backend intel_xpu

# Client (num_concurrent/batch_size: 8 for Qwen3-Omni, 16 for Gemma 4)
python -m lmms_eval --model sglang_asr \
  --model_args pretrained=<model>,base_url=http://127.0.0.1:30000/v1,num_concurrent=16 \
  --tasks openslr_librispeech_other --batch_size 16 --seed 42
```
