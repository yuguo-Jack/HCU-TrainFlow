# [Perf] [AMD] kimi-k3: Fused router top-k + MoE route sort and zero-copy MoE output for decode on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/44987) · state: open · merged: False

## Original PR description

> Kimi-K3 on gfx950 merge queue (all drafts; they land one at a time in this order): 1 #44978 verify argmax + tuned bf16 rows · 2 #44979 MLA prefill · 3 #44980 streaming AttnRes · 4 #44981 MoE prefill · 5 #44982 KDA · 6 #44983 MLA decode prep · 7 #44984 MLA decode epilogue · 8 #44985 LL column tail · 9 #44986 fused all-reduce read · 10 #44987 fused route sort · 11 #44988 split MoE front + bank partials · 12 #44989 MLA q-norm + q_b. Replaces #44547-#44553.

## Motivation

A Kimi-K3 MoE layer at decode sizes runs aiter's biased top-k, two moe_sorting phases and the MXFP8 activation quant
before the experts. The routed output is then copied out of aiter's own output into K3's all-reduce buffer, and the
shared-expert down GEMM into that buffer (`torch.mm(out=)`) lands on hipBLASLt.

## Modifications

Gated on gfx950 with aiter (`SGLANG_USE_AITER`).

- `kimi_k3_route_sort` (`route_sort.cuh`, `route_topk.cuh`): the router top-k (sigmoid + bias selection as aiter's
  topk kernel, renormalized pre-bias weights) and aiter's block-padded moe_sorting layout in one launch for decode
  batches (`SGLANG_ROCM_K3_FUSED_ROUTE_SORT_MAX_TOKENS`, 16), with the A8W4 experts' MXFP8 activation quant + scale
  sort folded in up to 8 tokens (`SGLANG_ROCM_K3_FUSED_ROUTE_QUANT`). The routes reach aiter's `fused_moe` through
  `moe_sort_handoff`, which aiter's `moe_sorting` / `fused_dynamic_mxfp8_quant_moe_sort` hooks consume only for the
  exact call they were staged for (aiter's own sort runs otherwise).
- The aiter runner writes the routed output into K3's joint all-reduce buffer (`zero_copy_context`) instead of
  copying it out of its own.
- The shared-expert down GEMM into the all-reduce buffer runs aiter's tuned FlyDSL kernel with `out=` (hipBLASLt
  otherwise).

#44552 also had an opt-in direct route layout (`SGLANG_ROCM_K3_MOE_ROUTE_DIRECT_MAX_TOKENS`, off by
default); it measured slower (C1 cycle 16.6 vs 15.7 ms; aiter's A8W4 kernels are tuned for expert-grouped blocks), so
it is not part of this PR.

| New env var | Default |
|---|---|
| `SGLANG_ROCM_K3_FUSED_ROUTE_SORT_MAX_TOKENS` | 16 |
| `SGLANG_ROCM_K3_FUSED_ROUTE_QUANT` | on |

## Accuracy Tests

**Setup for every number below:** 8x MI350X (gfx950, 1000 W), Kimi-K3 (MXFP4 MoE, bf16 attention) at TP8 with EAGLE3
(topk 1, 3 steps, 4 draft tokens), FP8 KV cache, `SGLANG_USE_AITER=1`, aiter's K3 FlyDSL kernels
(`AITER_SITUV2_A8W4=1 AITER_FLYDSL_FORCE=1 SGLANG_AITER_K3_OPT=1`), CUDA graphs for bs 1/2/4/8/16, and an aiter bf16 GEMM table with K3 rows re-tuned on this pod with HBM-resident weights
(`AITER_CONFIG_GEMM_BF16`; not part of this PR, it belongs in aiter's model configs). EAGLE3 on K3 needs the
aux-capture commit of #43599, applied locally for these runs. Microbenchmarks rotate their weights through HBM.
Per-feature numbers were measured on the integration branch of this series as each piece landed (Oct 13-14,
earlier `main`). All branches of the series are on `main` 4eb606b2ae (2026-10-17); the kernel tests below ran on this
branch, and the end-to-end checkpoints on that `main` plus the queue up to each slot.

- `test_kimi_k3_route_sort.py` (new): top-k ids, sorted rows, expert blocks and valid counts equal aiter's
  `biased_grouped_topk` + `moe_sorting`, the fused MXFP8 rows equal `fused_dynamic_mxfp8_quant_moe_sort`, NaN /
  saturated logit rows still give 16 distinct experts. On MI350X: 1 passed (6 subtests).
- End to end: GSM8K 200 at each checkpoint of the queue, see below.

## Speed Tests and Profiling

- Route sort at 4 tokens: 6.5 us vs 14.8 (aiter top-k + sort); with the quant 11.6 vs 16.9 us in-server.
- Shared-expert down GEMM with `out=`: 7.0 -> 4.5 us.

## Related

- #43126 (closed) fused radix-4 routing, the MoE sort and the MXFP8 quant on the Quark A4W4 decode path, handing the
  sort to aiter's `fused_moe` (now ROCm/aiter#6484); on MI355X it measured 1-2.6% slower TPOT than separate kernels.
  This PR is the A8W4 path of the stock checkpoint, keeps aiter unchanged, and is faster at the sizes it takes
  (route sort 6.5 vs 14.8 us at 4 tokens, with the quant 11.6 vs 16.9 us in-server; see above).
- ROCm/aiter#6263 fuses the same sort + MXFP8 quant inside aiter; here the router top-k is folded in as well.
- #44294 moves the shared down GEMM to aiter through `tgemm.mm(out=)`, which needs ROCm/aiter#6538 (not in the
  pinned aiter); this PR uses the FlyDSL `out=` the pinned aiter already has.
- The measurements above also had #41867 and #41848 applied.
