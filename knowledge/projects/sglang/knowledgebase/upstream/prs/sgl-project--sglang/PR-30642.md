# [Bugfix][DSA] Fix num_splits (b+1) crash with DP-attention + speculative decode

[Upstream PR](https://github.com/sgl-project/sglang/pull/30642) · state: open · merged: False

## Original PR description

Motivation
Fixes [#30296](https://github.com/sgl-project/sglang/issues/30296). Enabling DP-attention (attn_tp_size > 1) together with speculative decode on a DSA model (DeepSeek-V3.2 / GLM-5.x) crashes in the FlashMLA decode kernel with num_splits must have shape (b+1).

Root cause: cal_padded_tokens (which sizes num_splits) only aligns the token count to cp_align_size, missing the attn_tp_size align that prepare_mlp_sync_batch applies to q. On the spec path the DSA metadata is planned pre-pad and not re-planned, so num_splits ends up shorter than the padded q whenever num_draft_tokens * batch_size isn't a multiple of attn_tp_size.
