# fix(sgl-model-gateway): parse prefilled Qwen3 reasoning

[Upstream PR](https://github.com/sgl-project/sglang/pull/35249) · state: closed · merged: False

## Original PR description

## Motivation

Fixes #35148.

When `qwen3` reasoning parsing is configured only in `sgl-model-gateway`, Qwen3.8 responses can contain a prefilled reasoning segment from the chat template. The gateway parser starts in the wrong state, so the reasoning is returned in `content` and `reasoning_content` remains null instead of separating the thinking and final answer.

## Modifications

- Upgrade `reasoning-parser` from `1.0.0` to `1.3.0`.
- Initialize the non-streaming parser per request, including reset and prefilled-thinking state.
- Initialize each streaming parser per choice with the tokenizer's `ThinkingToggle`, `ThinkingKeyName`, and `think_in_prefill` settings.
- Respect explicit `enable_thinking` / `thinking` request overrides.
- Add unit regressions for Qwen3.8 prefilled `</think>` parsing in streaming and non-streaming paths.

## Accuracy Tests

Added parser unit tests covering:

- Qwen3 prefilled reasoning in the non-streaming path.
- Qwen3 prefilled reasoning and closing `</think>` transition in the streaming path.
- Thinking-toggle defaults and request-key resolution.


## Speed Tests and Profiling

Not applicable. This is a reasoning-parser correctness fix and does not change an inference kernel or performance-critical model computation.
