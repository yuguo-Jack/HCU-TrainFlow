# [AMD][MiniMax-M3] Optimize the MXFP8 sparse decode kernel tail on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/39994) · state: open · merged: False

## Original PR description

## Motivation

On MiniMax-M3-MXFP8 (TP4/EP1, MI355X/gfx950), small elementwise, cast and copy kernels cost 1.83 ms per decode step (12.8% of decode kernel time): 433 launch-bound launches of about 4 us each, mostly one or two per sparse layer. Some do nothing (dividing K and V by 1.0); others split one job across launches (two fp8 casts, then a scatter).

This PR removes **228 launches per decode step** (433 → 205, 1.83 → 0.86 ms). The profiled decode step is 7.0% shorter, output throughput is 2.4% to 6.6% higher at concurrency 4–64, and GSM8K stays within run-to-run noise (mean 0.980 → 0.973).

## Modifications

- **A. Skip work with no effect (A1, A2):** −114 launches/step, all from A1; A2 acts only on the Triton MoE runner, which this configuration does not use.
- **B. Fuse or replace kernels (B1, B2):** −114 launches/step, all from B1.

**A1. Skip dividing K/V by a unit scale** (`memory_pool.py`). The MiniMax sparse backend passes `layer.k_scale_float` and `layer.v_scale_float`, which are `1.0` when the checkpoint has no KV scales, so every sparse layer ran `div_(1.0)` on K and V. `_kv_scale_divides()` skips a host `1.0` at all seven scale-divide sites; a device scale still divides, since reading it would break CUDA-graph capture. −114 `MulFunctor<float>` launches. **Bit-exact.**

**A2. Keep the expert-id clamp where it can fire** (`triton.py`, `mxfp8_moe_amd_gfx95.py`). `main` already skips the Triton MXFP8 runner's clamp at EP1 via `_topk_ids_may_be_nonlocal()` ([#36559](https://github.com/sgl-project/sglang/pull/36559)). It now also keeps the clamp when the weights' expert count (`w13.shape[0]`) differs from the config's, and `maybe_detect_oob()` checks the unclamped ids under `SGLANG_ENABLE_ASYNC_ASSERT=1`. The zero-fill in `_grouped_gemm_mxfp8` stays, so a route filtered to `-1` contributes zeros whether or not the sort keeps it. No launches removed.

**B1. Fold the bf16 → fp8 KV cast into the paged write** (`memory_pool.py`, `cache_ops.py`, `hisparse_memory_pool.py`). `store_kv_fused_cast()` casts and scatters K and V in one `reshape_and_cache_flash` launch: −114 `float8_copy_kernel_cuda` launches. `_has_dense_kv_rows()` admits the strided `dim=-1` QKV slices (the kernel takes the token stride) but requires the exact token count; anything else takes the old path. Like `store_cache`, it skips reserved slot 0 (new `reserved_skip_index`, default `-1`) and bounds slots by `size + page_size` (new `size_limit`, default off). Where `store_cache` device-asserts on an out-of-range slot, the fused store skips it, since Triton has no always-on device assert; with `SGLANG_ENABLE_ASYNC_ASSERT=1`, `maybe_detect_oob()` still fails loudly. `HiSparseMHAMainPool` opts out, and its `store_kv_fused_cast()` raises. Bytes match `.to(fp8)` + scatter wherever ATen's cast is finite (|x| ≤ 464 for `float8_e4m3fn`; every bf16 value tested on gfx950, for `float8_e4m3fnuz` too); where ATen overflows to NaN, the fused store may write the saturated maximum instead (±448 for `float8_e4m3fn`).

**B2. Replace the index-K `index_put` with a row scatter** (`cache_move.py`, `memory_pool.py`). `MHATokenToKOnlyPool.set_k_buffer` ended in `k_buffer[loc] = src`; it now always calls `store_k_slots`, a Triton row scatter that skips any slot outside `[0, size + page_size)`. A source that fails `_has_dense_kv_rows()` is made contiguous first; the MiniMax-M3 index-K source is already dense. The two paths differ only on slots a correct caller never passes, since padded rows target slot 0: ATen asserted on a too-large slot and wrapped a negative one, and `store_k_slots` skips both. Same launch count, **4.9 → 4.2 us/layer**.

### Impact on CUDA and on Other AMD Architectures

No change checks the architecture; dispatch conditions decide:

| change | reaches CUDA and gfx942 when |
| --- | --- |
| A1 | a host `1.0` scale is passed (bit-exact) |
| A2 | never: only the gfx95 MXFP8 runner uses it |
| B1 | MiniMax-M3's sparse store casts bf16 K/V into an fp8 cache and passes `can_store_kv_fused_cast()` |
| B2 | a MiniMax-M3 index-K store passes `_has_dense_kv_rows()` |

`can_store_kv_fused_cast()` requires nhd layout, a `uint8`-stored non-quantized `float8_e4m3fn` or `float8_e4m3fnuz` cache, a flat 3-D buffer, `head_dim == v_head_dim`, unit scales and dense, equal-shape K/V; anything else keeps today's path. E5M2 is left out so that an overflow stays infinite, as ATen makes it, instead of saturating. The AITER backend's own `launch_reshape_and_cache_flash()` calls keep the defaults (`reserved_skip_index=-1`, no `size_limit`). For every caller, the kernel now computes destination offsets in int64 and reads `slot_mapping` through its stride; neither changes those calls, which already pass contiguous int64 slots. B1 and B2 have only run on gfx950; on CUDA (`float8_e4m3fn`) and gfx942 (`float8_e4m3fnuz`), B1 swaps ATen's fp8 cast for Triton's. The `float8_e4m3fnuz` byte test does not cover gfx942 either: Triton converts in software on gfx950 and in hardware on gfx942.

# Status after merging `main` (last merged 2026-10-06)

Merging `main` removed much of the tail on its own; this PR's own commits in between add no launches.

| | before merging `main` | after merging `main` |
| --- | --- | --- |
| tail launches/step | 946 → 319 (−627) | 433 → 205 (−228) |
| tail ms/step | 4.05 → 1.39 | 1.83 → 0.86 |
| baseline decode step | 21.55 ms | 14.29 ms |
| output throughput | +8.6% to +11.8% | +2.4% to +6.6% |

- [#36574](https://github.com/sgl-project/sglang/pull/36574) runs this model's MXFP8 MoE on aiter's fused kernels, with the sorting kernel from [#36559](https://github.com/sgl-project/sglang/pull/36559). The Triton MXFP8 runner no longer serves the MoE, so its clamp, zero-fills, combine and copies left the baseline: 570 launches and 2.42 ms/step, including everything A2 and the former A3 removed. [#36559](https://github.com/sgl-project/sglang/pull/36559) also skips the clamp at EP1, so A2 is now a guard. A3 skipped the grouped-GEMM zero-fill when nothing is filtered; it has been dropped, since it saved no launches in this configuration and its safety rested on the router never emitting `-1`.
- [#36549](https://github.com/sgl-project/sglang/pull/36549) stores the index-K cache in fp8 on gfx95, adding the cast behind the 57 remaining `float8_copy_kernel_cuda` launches.

The faster MoE also shrank the step, so the tail's share fell from 18.8% to 12.8%. The server settings changed between the two measurements as well: `--fp8-gemm-backend aiter`, `SGLANG_USE_AITER_MOE_GU_ITLV=0` and `SGLANG_MINIMAX_INDEXCACHE_*` were added, and `ROCM_QUICK_REDUCE_QUANTIZATION=INT4` was dropped. They don't touch the tail rows but do move the step time, so the decode-step and throughput rows compare configurations as well as trees.
