# [release/v0.5.21][HiCache] Back up DSA index keys in the hybrid Mamba host tier (GLM-5.3-Flash)

[Upstream PR](https://github.com/sgl-project/sglang/pull/43998) · state: closed · merged: False

## Original PR description

[by Claude Code]

## Motivation

Fixes #43997 on the v0.5.21 release line.

On v0.5.21, GLM-5.3-Flash with `--enable-hierarchical-cache` returns wrong output whenever a prefix is restored from the host tier. The hybrid KDA + DSA host stack (`_MambaStrategy`) backs up the MLA KV and the KDA state but not the DSA indexer keys, so a restored prefix selects its sparse top-k from the keys of whichever request last owned those device pages. A verbatim-recall probe on 4x B300 (TP4, the GLM-5.3-Flash recipe flags) gets 18 of 20 host restores wrong, while all cold requests and device-pool hits are correct.

`main` already fixed this through #40913 and #40915, which assemble `_MambaStrategy` from `host_pool_decls()` and so pick up the DSA indexer pool. Those PRs are part of a ~1.7k-line host-pool declaration refactor that does not apply to v0.5.21. This PR backports only the behavior, using the same `DSAIndexerPoolHost` sidecar that v0.5.21's pure-DSA stack (`_DsaStrategy`) already attaches. It is not needed on `main`.

## Modifications

- `build_hybrid_mamba_stack`: when the full-attention pool is a `DSATokenToKVPool`, add an `INDEXER` entry backed by `DSAIndexerPoolHost`. The entry uses the KV layer mapping and transfer span, like the pure-DSA stack.
- `_MambaStrategy`: register `SidecarPoolSpec(INDEXER, KV)` when that entry exists, so backup and load-back move the index pages together with their KV pages. The boot line then reads `pools=KV + MAMBA + INDEXER`.
- In this release, `DSAIndexerPoolHost` packs one index buffer per target layer and per MTP draft pool. If any layer or draft pool shares top-k (no index keys), the stack keeps the old `KV + MAMBA` behavior and logs a warning, rather than building a misaligned mirror. GLM-5.3-Flash without speculative decoding has no shared-top-k layers.
- Unit tests in `test_hybrid_pool_assembler.py`:
  - a regression case, which fails on the unpatched release: the `INDEXER` entry rides the KV transfers and its sidecar is registered;
  - the shared-top-k skip case.

## Accuracy Tests

4x B300, TP4, `zai-org/GLM-5.3-Flash` (FP8, rev `04c4e9e`), `--kv-cache-dtype fp8_e4m3 --dsa-prefill-backend trtllm --dsa-decode-backend trtllm --moe-runner-backend flashinfer_trtllm --max-total-tokens 49152 --enable-hierarchical-cache --hicache-ratio 2 --mamba-full-memory-ratio 0.2`, no speculative decoding. The probe and full command are in #43997. Each run is one fresh server launch with 10 cold requests, 10 device hits, and 10 host restores; every host restore is a genuine full-prefix L2->L1 load (`load_back_duration_seconds_count` = 10, `load_back_tokens_total{pool="kv"}` = 37,760 = 10 x 3,776, no dropped host tokens).

## Speed Tests and Profiling

No speed benchmark. The cost is the indexer mirror on the host, 0.14 GB per rank for the 98,368-token host tier above, plus the index pages copied alongside each KV page on backup and load-back.
