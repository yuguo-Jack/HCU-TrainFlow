# [Perf] flux2: Build the single-block output projection without a cat

[Upstream PR](https://github.com/sgl-project/sglang/pull/41943) · state: open · merged: False

## Original PR description

## Motivation

Each of FLUX.2's 48 single-stream blocks built the input to its row-parallel
`to_out` projection with

```python
hidden_states = torch.cat([hidden_states, mlp_hidden_states], dim=-1)
hidden_states, _ = self.to_out(hidden_states)
```

That is a full read and write of the `[tokens, attn + mlp]` buffer immediately
before the GEMM consumes it — pure data movement, 48 times per forward. The FP8
and NVFP4 paths already avoid it (`try_flux2_token_cat_fp8` /
`try_flux2_token_cat_nvfp4` write a packed GEMM input directly); only bf16 still
materialised the cat.

## Modifications

On the bf16 path, preallocate the `[tokens, attn + mlp]` GEMM input, let the
fused SwiGLU write its columns straight into it, and copy only the narrower
attention output:

```python
gemm_input = hidden_states.new_empty((*hidden_states.shape[:-1], attn_dim + mlp_out))
self.mlp_act_fn(mlp_hidden_states, out=gemm_input[..., attn_dim:])
gemm_input[..., :attn_dim].copy_(hidden_states)
hidden_states, _ = self.to_out(gemm_input)
```

- `fused_packed_silu_mul_bitexact(x, out=None)` now accepts a row-strided `out`
  (a column slice of a wider buffer), via a new `out_row_stride` kernel
  argument; an `out` that is not a dense-row column slice raises.
- `_flux2_swiglu` / `Flux2SwiGLU` pass `out` through and copy into it on the
  eager fallback, so the caller always gets its buffer filled.
- FP8 / NVFP4 token-cat paths untouched.

Splitting the GEMM instead (`attn @ W1 + mlp @ W2`) would also remove the cat,
but it changes accumulation order and rounding; this keeps the GEMM input
byte-identical.

## Accuracy Tests

The GEMM input is byte-identical to the old `torch.cat` result, so model output
is unchanged by construction.

- `test_flux2_xpu_norm_fusions.py::test_swiglu_into_out_projection_input_matches_cat`
  (added here): asserts the in-place buffer equals `cat([attn, swiglu(mlp)])`,
  that `out` is written in place (same `data_ptr`), and that the untouched
  columns stay untouched.
- End to end on XPU: no bit-exact fallback warnings; images differ from the
  parent commit only at the level of oneCCL run-to-run noise (see PR 2).

**CUDA accuracy is not yet measured** — see below.

## Speed Tests and Profiling

Micro-benchmark, one card, per-TP4-rank shapes
(`[4608, 1536]` attn + `[4608, 9216]` packed SwiGLU input):

| | time per block |
|---|---|
| `swiglu(mlp)` + `cat` | 0.699 ms |
| in-place build | 0.344 ms |

−0.355 ms per block × 48 blocks ≈ −17 ms per forward expected.

torch.profiler: `CatArrayBatchedCopy_contig` (21.3 ms per forward) disappears;
device-busy time per profiled forward 919.5 → 901.7 ms (−17.8 ms).

End to end (FLUX.2-dev, 1024x1024, 8 steps, bf16, eager, warm, TP4 on 4x
Arc Pro B70), 2 runs per side:

| | denoise (8 steps) | per DiT forward |
|---|---|---|
| parent commit | 6.227 / 6.234 s | 778.8 ms |
| this commit | 6.140 / 6.129 s | **−12 ms (−1.5%)** |

End to end recovers less than the 17.8 ms the profile shows; I did not chase
the difference.
