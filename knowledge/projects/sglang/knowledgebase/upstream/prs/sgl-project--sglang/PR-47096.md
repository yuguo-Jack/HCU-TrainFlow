# [Fix] responses: Merge replayed tool calls into the preceding commentary message

[Upstream PR](https://github.com/sgl-project/sglang/pull/47096) · state: open · merged: False

## Original PR description

## Motivation

When the model writes text before calling tools, `/v1/responses` returns `[reasoning, message(phase="commentary"), function_call, ...]`. Clients such as Codex replay these items as-is. The `function_call` items carry no `phase`, so `_merge_consecutive_assistant_messages` keeps them apart from the commentary message, and one generated turn is rendered as two assistant messages, the second without reasoning. The history then differs from what the model generated, which also breaks prefix-cache reuse of that turn.

## Modifications

- A tool-call-only assistant message without `phase` merges into a preceding `commentary` message.

## Tests

Replaying `[reasoning, message(commentary), function_call x2, function_call_output x2]` now yields one assistant message with `reasoning_content`, `content` and both `tool_calls`. `test/registered/unit/entrypoints/openai/test_serving_responses.py` results are unchanged versus main.
