# [Refactor] scheduler: Hold a launched prefill in one list until its next holder takes it

[Upstream PR](https://github.com/sgl-project/sglang/pull/43903) · state: closed · merged: True

## Original PR description

A request whose last prefill chunk was launched was in no request list until its result was processed, under PD prefill and HiSparse. In those modes `request_lists()` could not see it, and the busy memory check had to read `last_batch` and `running_batch` to find its rows. This adds the list that holds it, for every mode.

- `Scheduler.prefill_launched_reqs` holds a prefill request that left the chunked slot and still has launched steps, until its next holder takes it:
  - the running batch, at the merge (default engine);
  - the PD transfer queue, when its result is processed, or a requeue or retirement on that path;
  - HiSparse staging, in the same call that admits it (`SchedulerBatchResultProcessor.leave_prefill_launched`);
  - finishing, or a pause that retracts it.
- A request enters it when its last chunk is launched, or when a PD optimistic request yields the chunked slot with chunks still in flight. dLLM keeps its requests in its own queue.
- `running` now means the requests merged into a running batch: a launched prefill joins it at the merge instead of at launch. This removes `_prefill_launch_starts_running()`, which made the launch rule depend on the mode, and the matching field in the invariant checker. The running cross-check no longer needs a per-mode exception: it always compares against the running batches and the decode steps.
- `RunningReqs` is split into a generic `RequestList` (join, leave, leave finished requests, in join order) and the running cross-check; `prefill_launched_reqs` is a `RequestList`.
- `request_lists()` lists `prefill_launched`, so every live request is in some list. The busy memory check reads only the lists, and the invariant checker drops its running-batch getter.
- A PD optimistic request that yielded the chunked slot with a chunk in flight is requeued when that chunk is processed, whatever its bootstrap flag says by then. Before, the requeue also required the bootstrap to still be pending; that held only because nothing polls a yielded request's bootstrap.

No behavior change outside the debug checks: `running_reqs` and `prefill_launched_reqs` are read only by the invariant checker and `request_lists()`, and the requeue condition gives the same result on every state main can reach.

## Test plan
- `test_yielded_request_requeues_after_its_chunk_once_bootstrap_completes`: fails on the old requeue condition.
- `test_launch_holds_prefills_until_the_merge`: a launched prefill (alone, and in a mixed step) is held until the merge moves it to running; dLLM holds nothing.
- The unit tests that build a scheduler or an invariant checker pass locally with `SGLANG_IS_IN_CI=1`, apart from the failures main has too.
