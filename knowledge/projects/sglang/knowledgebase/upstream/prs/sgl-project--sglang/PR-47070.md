# [Perf] [NVIDIA] moe: Add H20 block-FP8 Triton configs for Qwen3-30B-A3B

[Upstream PR](https://github.com/sgl-project/sglang/pull/47070) · state: closed · merged: True

## Original PR description

## Motivation

With plain tensor parallelism (no `--ep`), Qwen3-30B-A3B runs its routed experts through the Triton fused MoE kernel. On H20, at `moe_tp_size = 1` (TP1 serving, or one replica per GPU), the serving lookup is `E=128,N=768` with `fp8_w8a8` and `block_shape=[128, 128]`.

The lookup key is derived from the kernel's per-rank shape, not from the model: `N = moe_intermediate_size / moe_tp_size`, and `E` grows by the fused shared expert. So the same model served with `--tp-size 8` looks up `E=128,N=96` and keeps the heuristic — these configs cover the `moe_tp_size = 1` geometry only. Conversely, any model whose expert geometry is `E=128, N=768, fp8_w8a8, block=[128,128]` picks these files up regardless of its name; `top_k` and `hidden_size` are not part of the key.

`triton_3_8_0` has no config for that shape (main pins torch 2.14.1, which ships Triton 3.8.0), so the runner falls back to the `triton_3_3_1` entry — five Triton versions stale — and logs:

```
Config file not found at .../triton_3_8_0/E=128,N=768,device_name=NVIDIA_H20,dtype=fp8_w8a8,block_shape=[128, 128].json.
Fallback to triton version 3.3.1 ... Performance might be sub-optimal!
```

## Modifications

Adds one file, `triton_3_8_0/E=128,N=768,device_name=NVIDIA_H20,dtype=fp8_w8a8,block_shape=[128, 128].json`, covering the 18 default batch sizes.

Tuned with the stock `benchmark/kernels/fused_moe_triton/tuning_fused_moe_triton.py` on 8x H20 96 GB, default 1280-config search space, `--tp-size 1 --dtype fp8_w8a8`, i.e. the `moe_tp_size = 1` geometry described above.

Because the tuner measures each candidate once, its pick was re-verified per batch size against four other candidates — the `triton_3_3_1` fallback, the heuristic default, and three hand-picked shapes — three repetitions each, median kept. That pass changed the winner for several batch sizes, notably M=64/96/128 (BM=16/BN=128 instead of BM=16/BN=64) and M=4096 (the 3.3.1 shape instead of BM=128/BN=64). Each number below is a re-measured median, not a single-shot tuner sample.

The separate down-projection (`_down`, TMA) configs from `tuning_fused_moe_triton_sep.py` are not included; serving keeps reusing the up config for the down GEMM, as it does today.
