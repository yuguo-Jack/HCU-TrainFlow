# [Kernel] Add fused SiLU+clamp+mul+FP8 quant AOT kernel for DeepSeek V4 EP MoE path

[Upstream PR](https://github.com/sgl-project/sglang/pull/32058) · state: closed · merged: False

## Original PR description



## Motivation

In the DeepSeek V4 Expert Parallelism (EP) serving path, the Triton MoE runner performs three separate operations between the gate-up GEMM and down-projection GEMM:

  1. **SwiGLU clamping** (`swiglu_limit=10`, gate to `[-inf, 10]`, up to `[-10, 10]`)
  2. **Activation**: `SiLU(gate) * up`
  3. **FP8 blockwise quantization** (group_size=128)

  Each operation materializes an intermediate bf16 buffer and launches a separate kernel.

  This PR adds a specialized AOT CUDA kernel (`sgl_act_mul_blockwise_quant`) that **fuses all three operations** — clamp + activation + quantization — into a single kernel launch, including expert-filtering (skipping rows for non-local experts).

  ### Difference from PR #31712 (JIT version)

  | | This PR (AOT) | JIT version |
  |---|---|---|
  | **Target** | DeepSeek V4 EP only (swiglu_limit + filter_expert) | General FP8 blockwise MoE |
  | **Fusion depth** | 3 ops: clamp → act+mul → FP8 quant | 2 ops: act+mul → FP8 quant |
  | **Activation** | SiLU only (hardcoded, more optimized) | SiLU + GeLU (parameterized) |
  | **Expert filtering** | Required (built into kernel) | Optional |
  | **Compilation** | AOT (no first-call overhead) | JIT (compiled at runtime) |

  The AOT version achieves higher performance for the DeepSeek V4 EP scenario by fusing the swiglu clamp directly into the kernel and eliminating JIT overhead.

## Modifications

 - **New AOT CUDA kernel**:
    - `sgl-kernel/csrc/moe/act_mul_blockwise_quant.cu` — Host launcher + kernel dispatch
    - `sgl-kernel/csrc/moe/act_mul_blockwise_quant.cuh` — Device utilities
  - **Build registration**: `CMakeLists.txt`, `common_extension.cc`, `sgl_kernel_ops.h`
  - **Python wrapper**: `sgl-kernel/python/sgl_kernel/moe.py` → `sgl_act_mul_blockwise_quant()`
  - **Integration in Triton MoE runner**:
    - `fused_moe.py`: Prioritize AOT kernel in the `swiglu_limit + filter_expert` branch
    - `fused_moe_triton_kernels.py`: Skip redundant quantization when input is already FP8
  - **Tests**: `sgl-kernel/tests/test_act_mul_blockwise_quant.py`
  ### Gating conditions

  The AOT kernel fires when ALL conditions hold:
  1. `SGLANG_OPT_FUSED_ACT_QUANT=1` (default)
  2. CUDA platform
  3. `swiglu_limit is not None` (DeepSeek V4 model)
  4. `filter_expert == True` (Expert Parallelism mode)
  5. FP8 W8A8 + block_shape[1] == 128
