# [Perf] [AMD] aiter: Run the DSpark MHA draft on non-causal unified_attention

[Upstream PR](https://github.com/sgl-project/sglang/pull/47437) · state: open · merged: False

## Original PR description

## Motivation

- On ROCm with `--attention-backend aiter`, the DSpark draft worker never gets aiter: `aiter` is not in `DRAFT_ATTENTION_BACKEND_CHOICES`, so the draft falls back to triton.
- DFlash/DSpark draft layers are `ENCODER_ONLY` (each draft block attends to its prefix and to all of its own tokens). Triton runs that non-causal verify through `extend_attention_fwd`, which has no split-KV, so each draft layer reads a long prefix on a few CUs.
- Cost: for the Kimi-K3 draft at TP8 (8 Q / 2 KV heads, head dim 64, 4 draft tokens) one call takes 11.7 ms at 350K tokens of context.
- Bug: the aiter backend ignored `ENCODER_ONLY` in target verify and always ran causally.
- ROCm/aiter#7244 (stacked on ROCm/aiter#7088) lets AITER's Triton `unified_attention` take `causal=False`. This PR uses it for the DSpark MHA draft and fixes the aiter verify path. With an AITER that lacks it, nothing changes.

## Modifications

- `aiter_backend.py`, target verify:
  - An `ENCODER_ONLY` layer passes `causal=False` to `unified_attention` and to the legacy `extend_attention_fwd`, as triton does.
  - `ENCODER_ONLY` layers stay off `unified_attention_3d_mtp` (causal-only).
  - Under CUDA graphs the legacy path drops the custom mask when `spec_info` has none, as triton does.
  - CUDA-graph verify metadata fills the flat per-token `kv_indices` only for MLA and the legacy verify; unified verify reads the page table.
- `aiter_backend.py`: a DSpark draft runner (non-MLA, non-SHUFFLE-5D pool) uses `unified_attention` when `SGLANG_USE_AITER_UNIFIED_ATTN` is unset.
- `draft_worker_common.py`: `resolve_draft_worker_attention_backend` keeps `aiter` for a DSpark draft only under the conditions below; otherwise it falls back as before.
- `dspark_config.py`: `draft_is_mla()` and `draft_has_sliding_window()` read the (MiniMax-translated) draft config.
- `utils/aiter.py`: `aiter_unified_attention_supports_non_causal()` checks that both Triton `unified_attention` kernels have the `CAUSAL` constexpr from ROCm/aiter#7244.

| Draft stays on `aiter` only when | Otherwise |
|---|---|
| Speculative algorithm is DSpark | fallback (triton) |
| AITER `unified_attention` accepts `causal=False` | fallback |
| Draft is not MLA (aiter MLA verify is causal-only) | fallback |
| Draft has no sliding-window layer (AITER rejects `causal=False` with a window) | fallback |
| `SGLANG_AITER_KV_CACHE_LAYOUT=nhd`, no unified memory | fallback |
| `SGLANG_USE_AITER_UNIFIED_ATTN` not set to `0`, `SGLANG_AITER_UNIFIED_VERIFY` not `0` | fallback |
| Deterministic inference is off (aiter rejects `unified_attention` under it) | fallback |

| Env var | Default | Effect |
|---|---|---|
| `SGLANG_USE_AITER_UNIFIED_ATTN` | unset (was `false`) | Unset: only a DSpark MHA draft on aiter uses `unified_attention`. Set: decides for every runner. |
| `SGLANG_AITER_UNIFIED_VERIFY` | `true` | Now read through `envs`; `0` also keeps the DSpark draft off aiter. |

## Accuracy Tests

Kimi-K3-Quark-MXFP4-AttnFP8, TP8 + DSpark (block 4), 8x MI355X, AgentX c16 with real acceptance. Both trees are identical except for this PR's commits and ROCm/aiter#7244.

| | A: triton draft | B: aiter draft |
|---|---:|---:|
| GSM8K (sgl-eval 0.1.3, 1319 questions) | 94.92% | 95.15% |
| Accept length at 13-16 running requests | 3.572 | 3.569 |

- The unchanged accept length shows the draft attention is still bidirectional; the pre-fix aiter path ran it causally.
