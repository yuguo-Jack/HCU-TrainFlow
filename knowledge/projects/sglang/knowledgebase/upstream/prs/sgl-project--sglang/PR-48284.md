# [Fix] model_loader: Use the local CUDA device in the fastsafetensors loader

[Upstream PR](https://github.com/sgl-project/sglang/pull/48284) · state: open · merged: False

## Original PR description

## Motivation

`fastsafetensors_weights_iterator` builds its device from the process-group rank: `torch.device(f"cuda:{rank}")`. With multi-node tensor parallelism that rank is global. On every node after the first it names a GPU the node does not have (rank 4 on a 4-GPU node asks for `cuda:4`), and `--load-format fastsafetensors` fails on those ranks. The same line can also pick the wrong GPU when `--base-gpu-id` is not 0.

This is the bug reported in #29272. #26597 and #29717 fixed the same line, but the stale bot closed both before review. This PR carries only that one-line fix plus a regression test.

## Modifications

- `python/sglang/srt/model_loader/weight_utils.py`: use the device `ModelRunner` already set for this process (`torch.cuda.current_device()`). The group rank still keys the file map.
- `test/registered/unit/model_loader/test_prefetch_checkpoints.py`: a unit test where the group rank (3) differs from the current device (1). It fails on the old code (`cuda:3`) and passes with the fix.

## Accuracy Tests

2 nodes x 4 GPUs (GB300), TP8, an MXFP4 MoE checkpoint, `--load-format fastsafetensors`:
- ranks 4-7 load with the fix;
- greedy outputs are identical to the default loader's;
- the KV cache size is within 0.14 GiB per rank of the default loader's.

Where the group rank already equals the local GPU index (one TP group on a single node with `--base-gpu-id 0`), nothing changes.

## Speed Tests and Profiling

The fix itself does not change speed. #29272 has load times that others measured once the device was fixed.
