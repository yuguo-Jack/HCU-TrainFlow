# [Perf] [AMD] aiter/spec: Remove two host syncs from extend metadata and spec M-RoPE positions

[Upstream PR](https://github.com/sgl-project/sglang/pull/47432) · state: open · merged: False

## Original PR description


## Motivation

Two lines block the host until the GPU has drained its queue, so the scheduler cannot prepare the next batch while the GPU works:

1. `AiterIndicesUpdaterPrefill` (normal extend) fills the tail of `kv_indices` from `kv_indptr[-1]`, a device scalar: slicing at it is a
   device-to-host read.
2. `ForwardBatch` speculative M-RoPE positions copy the per-request M-RoPE deltas (host tensors) with `torch.stack(...).to(device)`, a
   pageable, synchronizing copy, in every draft/verify cycle that has a multimodal request.

A torch profile (with stacks) of Qwen3.8-27B on MI355X, TP1, MTP 3/1/4, image requests (768x1024 + 1k text / 64 output tokens, 16
concurrent) showed the host blocked 844 ms over 4 prefill batches in (1), paid by the target extend and again by the EAGLE draft extend, and
162 ms over 20 draft/verify cycles in (2). With speculative decoding the image workload ran at 85% of the no-SD throughput, with the GPU
idle about half of the time.

## Modifications

1. The tail fill slices at `paged_kernel_lens_sum` (host int) instead of `kv_indptr[-1]`. Same offset: `kv_indptr[bs]` is the cumsum of
   `paged_kernel_lens`, whose sum is `paged_kernel_lens_sum`, which already sizes the buffer.
2. The M-RoPE deltas are copied with `async_h2d_stack` (pinned staging, non-blocking) instead of `torch.stack(...).to(device)`.

No numeric change by construction. The two commits are independent and can be split if preferred.

## Accuracy Tests

Setup: MI355X, `amd/Qwen3.8-27B-Quark-AWQ-MXFP4`, `--attention-backend aiter --kv-cache-dtype fp8_e4m3`, MTP 3/1/4
(`--speculative-algorithm EAGLE --speculative-num-steps 3 --speculative-eagle-topk 1 --speculative-num-draft-tokens 4`).

- Greedy outputs, upstream main 8080507c3e + #47430 with and without this PR (TP1, 50 ShareGPT prompts, 256 tokens, batch size 1):
  identical, 50/50. (#47430 is used as the base because without it the verify attention fallback makes greedy MTP output vary from
  run to run on this setup.)
- Upstream main 8080507c3e + this PR starts with MTP and serves text and image requests at TP1 (accept length 2.71) and TP2 (2.70).
- GSM8K (5-shot, all 1319 questions, `sglang.test.few_shot_gsm8k`) on the Qwen3.8 build below with this change (and #47430,
  #47431), MTP 3/1/4 + `--enable-linear-replayssm-spec`: 0.930, no invalid answers (no speculative decoding, without this change: 0.933).

## Speed Tests and Profiling

The two changed lines are the same on current main as on the build these numbers come from (a Qwen3.8 build of main: e732f5d41e +
14 open AMD Qwen3.8 PRs, among them #39912, #39998, #43785, #47154). MI355X TP1; SD = MTP 3/1/4 + `--enable-linear-replayssm-spec` with #47430 and #47431 applied;
output tok/s with `python -m sglang.bench_serving` (random / image datasets, range ratio 0.8), all four arms on the same GPU, one after another,
% of the no-SD baseline without this change:

| workload | no SD | no SD + this PR | SD | SD + this PR |
|---|---|---|---|---|
| image 768x1024 + 1k text / 64 out, 16 concurrent | 684.0 | 699.9 (102.3%) | 579.0 (84.6%) | 684.8 (100.1%) |
| image 768x1024 + 1k text / 64 out, 4 concurrent | 394.6 | 395.3 (100.2%) | 383.2 (97.1%) | 443.2 (112.3%) |
| image 768x1024 + 8k text / 64 out, 16 concurrent | 262.4 | 263.6 (100.5%) | 239.7 (91.4%) | 248.9 (94.9%) |
| text 8k / 1k out, 16 concurrent | 1582.1 | 1569.6 (99.2%) | 1780.5 (112.5%) | 1800.8 (113.8%) |
| text 60k / 600 out, 4 concurrent | 236.6 | 236.3 (99.9%) | 257.3 (108.7%) | 260.7 (110.2%) |

Image requests gain the most: with SD each image prefill batch paid the extend sync twice (target and draft) and every draft/verify cycle
paid the M-RoPE copy. Without SD only one extend per prefill batch blocked and the M-RoPE path is not used, so the change is neutral there.
