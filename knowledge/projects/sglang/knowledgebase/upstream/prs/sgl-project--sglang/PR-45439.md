# [Refactor] radix-tree: Reuse the insert walk, component hooks and bindings for custom tree cores

[Upstream PR](https://github.com/sgl-project/sglang/pull/45439) · state: closed · merged: True

## Original PR description

Follows #45238, #45242 and #45241, which this change builds on; it is based on `main` after they landed.

## Motivation

A tree core that wants to own specialised state (for example a FULL component whose device values are not backed one pool row per token, or a core that must do its own bookkeeping between locating an overlapping node and letting components claim its slots) currently has to copy `UnifiedTreeCore`, the component drivers and the whole PyO3 binding, because:

- the insert walk performs the per-node overlap claim inline and cannot be paused between finding the overlapping node and consuming its slots;
- eviction hooks can return freed tensors but cannot emit cache actions, so component-owned work that eviction triggers has nowhere to go except an inline call on the cache;
- the binding is written against `UnifiedTreeCore<K>` by name, reads the core's fields directly, and validates init params inside its constructor;
- several drivers read `node.device_reclaimable_value_len()` directly, so a driver that counts a component's backing differently is bypassed.

## Modifications

Rust crate (`rust/sglang-radix-tree`):

- `TreeComponent` gains two defaulted hooks: `reclaimable_value_len(&Node)` (what the core counts as evictable or protected for this component; every driver and the core now go through `component_reclaimable_value_len_`) and `on_node_removed(NodeId)` (called after a leaf is freed). `update_component_on_insert_overlap` takes `preserve_full_ids`; SWA treats it like a locked FULL and keeps the canonical FULL ids. Every eviction hook (`evict_component`, `evict_device_next_node`, `drive_host_eviction`, `reclaim_coexisting_host_values`, `release_window_lock`, `evict_excess_path_states`) takes `cache_actions: &mut Vec<CacheAction>`.
- The insert walk is split into WALK → OVERLAP → COMMIT → TAIL. `start_insert_walk_`, `advance_insert_walk_(state, pause_at_overlap)`, `insert_overlap_step_(state, InsertOverlapContext)` and `InsertWalkState::finish` let a crate-local caller own the walk; `try_insert` / `try_resume_insert` are thin wrappers over them and behave as before (the ordinary path runs the overlap step inline in the same iteration). `match_prefix` is split the same way: `create_match_validators_` plus `match_prefix_with_validators_` accept borrowed validators.
- `UnifiedTreeCore::new_with_components_` builds a core from caller-supplied drivers; `validate_init_params` moves the binding's init validation into the core; the fields the binding used to read (`is_write_back`, `enable_hicache`, ...) get accessors; `build_backup_kv_action(NodeId)` is exposed; `EvictionStepResult` carries `cache_actions` (and an optional `backup_kv`); `TreeCoreRuntimeError::InvalidInsertOverlap` is added for callers that drive the overlap step themselves.
- `python_bindings.rs`: `TreeCoreBinding<Core>` and the `tree_core_methods!` macro stamp the delegate for any core type that offers the `UnifiedTreeCore` surface; `tree_core_binding!` takes `core = ...;` and a list of pyclasses, each with optional extra methods. For Python callers the stock `RustUnifiedTreeCoreBinding` / `RustBigramUnifiedTreeCoreBinding` change only in that eviction results carry `cache_actions`, `dec_window_lock_only` / `dec_swa_lock_only` return `(device_frees, host_frees, cache_actions)`, and `build_backup_kv_action` is exposed. Most of this file's diff is the re-indent into the macro; `git diff -w` on it is about 170 lines.

Python:

- `BaseEvictionResult.cache_actions`, and `UnifiedRadixCache._apply_eviction_result`, which frees the values and then drains the actions even when freeing raises; every step wrapper uses it. The Python tree core and components thread `cache_actions` through the same hooks as the Rust crate (`C128SidecarComponent` and the test fakes included).
- `RustUnifiedTreeCore`'s binding-to-interface conversions become overridable methods (`_cache_action_from_tagged`, `_insert_step_from_binding`, `_match_result_from_binding`, `_fill_evict_result`); `evict_excess_path_states` takes the `cache_actions` buffer; `build_backup_kv_action` is added.

Tests: Rust unit tests for the new hooks, action forwarding order through leaf, subtree and host eviction, caller-owned walks (pause, abort, parity with the stock insert) and borrowed match validators; Python tests for the drain order under a free failure, an action-only eviction step counting as progress, the sidecar component's hooks, and `build_backup_kv_action` on the Rust backend.
