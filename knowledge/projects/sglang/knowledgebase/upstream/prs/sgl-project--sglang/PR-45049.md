# [Fix] speculative: Refresh shared_read_done_event after post-verify KV cache compaction

[Upstream PR](https://github.com/sgl-project/sglang/pull/45049) · state: open · merged: False

## Original PR description

## Motivation

Fixes #44997

When running speculative decoding (`--speculative-algorithm NEXTN` / `NGRAM`, or `EAGLE` with `topk > 1`) with CUDA graphs enabled and the overlap scheduler active, `DecodeCudaGraphRunner.execute` publishes `model_runner.shared_read_done_event` inside or immediately at the end of the target verify CUDA graph replay (`SharedReadEnds.PRE_REPLAY` for Triton, `SharedReadEnds.IN_REPLAY` for FlashInfer via `in_graph_metadata_prep_done`, or `SharedReadEnds.POST_REPLAY`).

However, after `target_worker.forward_batch_generation(..., is_verify=True)` returns, `NGRAMWorker.forward_batch_generation` (and `run_eagle_verify` when `topk > 1` via `_finalize_accept_tree_path`) launches `move_accept_tokens_to_target_kvcache` on `forward_stream`. `move_accept_tokens_to_target_kvcache` runs `assign_extend_cache_locs`, which reads `batch.req_to_token_pool.req_to_token[batch.req_pool_indices, batch.seq_lens : batch.seq_lens + num_correct_drafts + 1]` into `tgt_cache_loc`, and then copies KV cache entries from `accept_out_cache_loc` into `tgt_cache_loc`.

Because `shared_read_done_event` was not refreshed after `move_accept_tokens_to_target_kvcache`, `scheduler._apply_war_barrier()` only fenced `schedule_stream` behind the target verify graph's early `shared_read_done_event`. When a request finishes on a stop token (or by length when speculative pre-stop is disabled) in `batch_t`, it still participates in `batch_{t+1}`'s verify step before `pop_and_process(batch_t)` runs:
1. While `batch_{t+1}`'s target verify forward is still executing on `forward_stream`, `_apply_war_barrier()` on `schedule_stream` immediately passes (since `PRE_REPLAY` / `IN_REPLAY` already fired).
2. `pop_and_process(batch_t)` calls `release_kv_cache`, freeing the finished request's `req_pool_idx`.
3. The next iteration admits a new request into that same `req_pool_idx` and executes `alloc_for_extend` -> `write_cache_indices` on `schedule_stream`, overwriting `req_to_token[req_pool_idx, :prefix_len + extend_len]` with the new request's radix-cached prefix KV slot indices **before** `batch_{t+1}`'s `move_accept_tokens_to_target_kvcache` executes on `forward_stream`.
4. `batch_{t+1}`'s `move_accept_tokens_to_target_kvcache` then reads `tgt_cache_loc` from the overwritten `req_to_token[req_pool_idx]` (pointing to the shared radix-cached prefix KV slots) while `accept_out_cache_loc` holds the finishing request's old over-allocated draft KV slots, corrupting the shared radix-cached prefix KV cache in-place.

## Modifications

- Add `refresh_shared_read_done_event(model_runner, device_module=None)` in `python/sglang/srt/model_executor/runner_utils/shared_read_event.py` to record and publish a fresh `shared_read_done_event` on `forward_stream` when an earlier event was published during the forward pass.
- Call `refresh_shared_read_done_event(self.model_runner)` in `NGRAMWorker.forward_batch_generation` (`python/sglang/srt/speculative/ngram_worker.py`) after post-verify `move_accept_tokens_to_target_kvcache` (and `compute_spec_logprobs`).
- Call `refresh_shared_read_done_event(target_worker.model_runner)` in `run_eagle_verify` (`python/sglang/srt/speculative/eagle_worker_common.py`) after `_finalize_accept_tree_path` when `finalize_tree_path and not batch.forward_mode.is_idle() and topk > 1`.
- Add unit tests in `test/registered/unit/model_executor/runner/test_prefill_shared_read_done.py` covering `refresh_shared_read_done_event`, `NGRAMWorker` target verify event refresh ordering, and `run_eagle_verify` tree compaction event refresh ordering.

## Accuracy & Unit Tests

- `pytest test/registered/unit/model_executor/runner/test_prefill_shared_read_done.py test/registered/unit/model_executor/runner/test_decode_cuda_graph_shared_read_fence.py` (all 35 tests pass).
