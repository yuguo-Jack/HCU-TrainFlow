# [NPU DSA prefill sharding 1/2] Indexer: shard prefill queries across attention TP

[Upstream PR](https://github.com/sgl-project/sglang/pull/42977) · state: open · merged: False

## Original PR description

## Motivation

On Ascend, the DSA indexer is the most expensive part of long-context prefill, and every attention-TP rank
runs all of it. Each rank scores every query against every key, so the O(n²) work is repeated
`attn_tp_size` times.

On GLM-5.2, Ascend A3, a single 1M-token prefill, the indexer is most of TTFT: about 83%, inferred from
the speed-up below. A single-die probe of the indexer operator alone measured 61%.

Every rank already holds the full index-K. So only the queries need to be split, and the work divides by
`attn_tp_size` with no change to the KV layout and no extra KV memory.

## Modifications

- `dsa_npu_indexer.py`: in prefill, each attention-TP rank scores `1/attn_tp_size` of the indexer queries.
  The top-k indices are then all-gathered over attention TP, so every rank still ends with the top-k
  for every token.
- The rank also projects only its own rows through `wq_b` and the query rotary. A Linear acts on each
  row alone, so this gives the same rows as projecting everything and slicing. Only for neox-style rotary.
- `dsa_token_shard_layout.py` (new): the row plan. Rows are split `ceil(T / attn_tp_size)` per rank, and
  the query tensor may be padded to a multiple of `attn_tp_size`.
- The gate turns it off at attention TP 1, for decode and speculative passes (only plain and mixed extend
  shard), for prefill CP, when the attention input is scattered, and when the query tensor's width is
  outside `[real tokens, rows * attn_tp_size]`.
- `SGLANG_NPU_ENABLE_DSA_INDEXER_QUERY_SHARDING`, **default on**. It reaches NPU DSA users who run
  attention TP > 1 in prefill. The `base-c-test-acc-16-npu-a3` PR gate (GLM-5 tp16 GSM8K) exercises it.
  Set it to `0` to get the old path.
- Docs: the flag is added to the Ascend environment variables reference.

## Accuracy Tests

GLM-5.2 W4A8, Ascend A3, tp16, no DCP, eager, GSM8K all 1,319 questions:

| | accuracy |
|---|---|
| this PR (flag on) | 0.9378 |
| flag off | 0.9424 |

The flag-off run was made on the larger branch this PR is cut from, with this path and its follow-up
(DSA token shard) both off and the same settings otherwise. Paired: 23 questions right only with the flag
off, 17 right only with it on. McNemar p = 0.43, so the difference is within noise. The server logged
"query sharding is active" once per rank (16 times).

## Speed Tests and Profiling

GLM-5.2 W4A8, Ascend A3, 16 dies, chunked prefill 16384. These runs used DCP 16 (from a larger branch that
this PR is cut from). The DCP KV gather was on in both arms, and was measured separately at under 4% of
cold prefill. This branch alone was checked for accuracy, not speed.

| cold-cache TTFT | before | this change | speed-up |
|---|---|---|---|
| 131k tokens | 70.47 s | 51.12 s | 1.38× |
| 524k tokens | 534.79 s | 229.63 s | 2.33× |
| 1M tokens | 2011.30 s | 491.00 s | 4.10× |

AISBench, ~990k-token shared prefix (radix-cached) + 16 concurrent ~10.8k-token tails: 486.2 s → 109.2 s.
