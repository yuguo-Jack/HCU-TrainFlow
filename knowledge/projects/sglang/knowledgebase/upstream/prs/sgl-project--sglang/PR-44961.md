# [Refactor] quantization: ask the platform for its quantization config on every device

[Upstream PR](https://github.com/sgl-project/sglang/pull/44961) · state: open · merged: False

## Original PR description

## Motivation

`SRTPlatform.get_quantization_config()` lets a platform supply its own `QuantizationConfig` class. `layers/quantization.get_quantization_config()` consulted it only when `current_platform.is_out_of_tree()`. In-tree CPU picked its AMX config table with an inline `is_cpu() and cpu_has_amx_support()` branch ahead of the hook.

This PR is part of a small series that routes in-tree platforms through the `SRTPlatform` seams that already exist (#44958, #44960).

## Modifications

- `get_quantization_config()` asks `current_platform.get_quantization_config()` on every platform and falls back to the registry when it returns `None`.
- `CpuSRTPlatform.get_quantization_config()` owns the AMX selection. With AMX, it returns the entry from `CPU_QUANTIZATION_METHODS` or raises for a method that isn't in it; without AMX, it returns `None`.
- Small fix: the CPU error message listed every registered method under "Available methods on CPU". It now lists the CPU table.
- Tests:
  - CPU with and without AMX;
  - an in-tree platform's override being honoured, with registry fallback for methods it doesn't claim.

**Behaviour:** unchanged on every in-tree platform. No in-tree platform other than CPU overrides the hook, and CPU returns exactly what the inline branch did.
