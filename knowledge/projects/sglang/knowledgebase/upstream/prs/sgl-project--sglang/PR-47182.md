# [Fix] Catch OSError when probing torchcodec so broken installs fall back to decord

[Upstream PR](https://github.com/sgl-project/sglang/pull/47182) · state: closed · merged: False

## Original PR description

## Summary

The backend probe in `python/sglang/srt/utils/video_decoder.py` only catches `ImportError` and `RuntimeError` when importing `torchcodec`. A torchcodec wheel that installs cleanly but whose native library fails to load (e.g. an FFmpeg version mismatch) raises `OSError` instead, which escapes the guard and breaks the whole `sglang.srt.utils.common` import chain — on hosts where decord is installed and would work fine.

## Changes

- Add `OSError` to the fallback `except` tuple so the decord fallback also engages for unloadable torchcodec native libraries.

## Testing

- [x] Reproduced on a deployment host with a broken torchcodec native lib: `sglang.launch_server` failed at import time before the change; after it, the decord fallback engaged and the server started normally.
