# [AMD][Perf] moe: Fuse MXFP8 quant into the small MoE sort

[Upstream PR](https://github.com/sgl-project/sglang/pull/42498) · state: open · merged: False

## Original PR description

## Motivation

Main fuses aiter's stage-1 MXFP8 quant (`fused_dynamic_mxfp8_quant_moe_sort`) into the small MoE sort only when `hidden % 2048 == 0`, and its bitonic sort kernel (#44004) runs only without the quant. DeepSeek-V4.1 has hidden 5120, so in decode it runs the sort and the quant as separate launches in every MoE layer.

This PR fuses the quant for hidden sizes that are multiples of 1024, also in the bitonic kernel. For DeepSeek-V4.1 (E 385 = 384 routed + 1 fused shared expert, top 7), the sort and the quant become one launch up to 36 rows.

The stage-1 quant runs only when aiter uses fp8 activations. With aiter's default `AITER_BF16_FP8_MOE_BOUND` (256), decode uses bf16 activations, and this PR changes nothing. The DeepSeek-V4.1 cookbook sets it to 0, as do all results below.

## Modifications

The branch is based on main `a126e8d640`, which has #44004's bitonic sort (merged 2026-10-16; it replaced #41900, which the old head `10b76d8c07` used). The diff is kernel +85/-16 and tests +118/-8.

- `moe_sorting_small.py`: the `fused_moe` gate passes the activations to the sort when `hidden % 1024 == 0` (was 2048). The bitonic kernel gets the quant: extra programs write each token's fp8 row once and the e8m0 scales of its pairs at aiter's swizzled addresses, with aiter's math.
- Above 32 pairs and below 512 experts, the quant path now takes the bitonic kernel. From 512 experts on, it keeps main's kernels: at Qwen3.5's E 513 / top 11, the bitonic kernel with the quant was 4.7 to 5.2 % slower at 3 to 5 rows.
- `test_moe_sorting_small.py`: E 385 / top 7 in the sort test; quant bytes and scales checked bitwise against aiter at hidden 5120; the 36 / 37-row cutoff; and a new `test_fused_moe_a8w4_stage1_matches_aiter`. The new test runs aiter `fused_moe` at DeepSeek-V4.1's TP4 shape (target MoE and DSpark draft MoE). It fails if the quant did not come from the sort, and it compares the stage-1 output bitwise with stock aiter.

Credit: the sort kernel is from #44004. The end-to-end test follows the idea of #43822's test.
