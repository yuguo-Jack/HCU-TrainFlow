# [AMD] Fuse MXFP8 quant into the small MoE sort

[Upstream PR](https://github.com/sgl-project/sglang/pull/42498) · state: open · merged: False

## Original PR description

This draft depends on #41900 by Yanfei Wang. The first commit rebases #41900 onto current main and integrates its test under a distinct class name. The second commit is this change. It lets the small MoE sort emit the stage-1 MXFP8 activation quant for hidden sizes divisible by 1024. For 33 to 256 token-expert pairs, it adds one quant program per token and 1024-column chunk to #41900's one-block sort. It also lets this path run up to 256 pairs when there are fewer than 512 experts; on main, #41982 sends more than 64 pairs at more than 256 experts to aiter's sort and separate quant. Calls with masked or local-token routing still use aiter. For DeepSeek-V4.1 top-7 decode, the path is active at 1 to 36 rows; 64-user decode is unchanged.

Tested on the ROCm 10-06 image (SGLang 679d2851 with #42796), MI355X, TP4. The same source change is rebased on current main but was not run there. Sort outputs, FP8 rows and consumed scale bytes are bit-exact against aiter at hidden 4096, 5120 and 7168, E384 top-6 and E385 top-7, and block 16 and 32. Sort-plus-quant time fell from 4.8-5.4 to 2.3-3.1 us per layer at 1-4 rows and from 10.0-12.5 to 4.5-5.4 us at 10-36 rows, against current main. On the 10-06 image, whose small sort still uses the older distributed kernel at 10-36 rows, two serving repeats showed 2.0-6.0% lower median ITL at every active point and 4.1-5.8% higher throughput at 16 and 32 users. With main's small-sort code (#41982) on the same image, two A/B pairs of this PR against #41982 alone cut median ITL by 2.1-3.5% at 4 to 32 concurrent users (1k to 128k input), every run past the run-to-run floor (at most 0.5%); 64 users is unchanged. On the 10-06 image without #41982, book prompts with the prefix cache on (80-86% hits) showed 1.7-2.3% lower median ITL at 1-4 users and 4.3-4.8% at 16 users, in two A/B runs per arm on each of two GPU sets; at 64 users, where this path is not active, no change repeats. With this change alone, accuracy was GSM8K 0.9734, GPQA 0.8384 and NIAH 64k / 128k 1.0 (base 0.9734, 0.8687 and 1.0).
