# [Refactor] multimodal: [sglang-miles] [MM refactor 5/9] Add a token-space multimodal processor

[Upstream PR](https://github.com/sgl-project/sglang/pull/46729) · state: closed · merged: True

## Original PR description

## Motivation

Port of #46411 ([MM refactor 5/9]) onto `sglang-miles`, stacked on #46699 (4/9).

## Modifications

The twelve commits of #46411, cherry-picked with no conflicts (`git range-diff` against #46411: 11 identical, 1 context only). The first four:

- `feat(mm)`: expand media placeholders in token space (`token_space_mm_process/expansion.py`).
- `feat(mm)`: process media per item with a token-space strategy (`process_strategy.py`, `processor.py` with `TokenSpaceProcessor`); the mixin gains `_worker_thread_initializer` (returns `None`, so legacy processors are unchanged) and `_run_mm_processor`, and `MultimodalProcessorConfig` gains `keep_mm_features_on_device` (default `False`).
- `feat(mm)`: register token-space strategies by architecture (`registry.py`).
- `fix(mm)`: pin a trainer's media IO threads to its CUDA device.

Commit messages only: the last commit drops a co-author trailer and gains the `Signed-off-by` the others carry.

Nothing calls the token-space processor in serving until 6/9; trainers construct `TokenSpaceProcessor` directly.

## Tests

At the stack head (9/9 port), on a 1x H200 box: 716 passed and 2 failed in the stack's unit tests, vs 755 passed on #46415; both failures already fail on `sglang-miles`. `test_qwen_processor_bitwise.py`: 4/4 bitwise identical.

## Next

[MM refactor 6/9] Serve token-space processors behind `--enable-token-space-processor`, stacked on this branch.
