# [Fix] qwen3_coder: Keep non-finite numbers out of number parameters

[Upstream PR](https://github.com/sgl-project/sglang/pull/48143) · state: open · merged: False

## Original PR description

## Motivation

With `--tool-call-parser qwen3_coder`, a `number` parameter whose value is `1e999`, `nan`, `inf` or `-Infinity` is converted with `float()` into a Python `inf`/`nan`. `json.dumps` then writes the arguments as `{"x": Infinity}` or `{"x": NaN}`, which is not valid JSON, so strict clients fail to parse the tool call. This happens in both `detect_and_parse` and streaming.

```
schema: {"x": {"type": "number"}}, value: 1e999
before: {"x": Infinity}
after:  {"x": "1e999"}
```

The detector already has `_parse_finite_float`, added for union-typed parameters (#44124), but the plain `number` branch did not use it.

I did not open an issue for this. I found it while checking sibling parsers after #48040, which fixes the same class of bug in `minimax_m2`. The only open PR touching `qwen3_coder_detector.py` is #41313 (string argument streaming), which does not change number conversion.

## Modifications

- The `number`/`float` branch of `_convert_param_value` calls `self._parse_finite_float` instead of `float`. A non-finite value raises `ValueError`, which the existing `except` handles by keeping the raw string and logging the existing warning, the same as any other value that fails to convert.

Finite values are unchanged: `5` → `5`, `5.0` → `5.0`, `1e3` → `1000.0`, `-0` → `0`.

## Testing

CPU only (ARM Neoverse-N1), Python 3.12. Added `test_number_parameter_nonfinite_values_remain_strings` to `TestQwen3CoderDetector` in `test/registered/unit/function_call/test_function_call_parser.py`. It uses the existing `_check_structured_union_value` helper, so it covers one-shot parsing and streaming at several chunk sizes.

- Without the fix the new test fails with `AssertionError: {'value': inf} != {'value': '1e999'}`.
- With the fix, `pytest test/registered/unit/function_call/test_function_call_parser.py -k TestQwen3CoderDetector` gives 26 passed.
- The whole file gives 253 passed and 9 failed. All 9 are in `TestDeepSeekV32Detector` and fail the same way on `main` in my environment, because `torchvision` is not installed.

`pre-commit run --files` passes on both changed files.
