# [Feat] [MUSA] breakable: Support portable capture status

[Upstream PR](https://github.com/sgl-project/sglang/pull/47034) · state: closed · merged: True

## Original PR description

## Motivation

MUSA exposes the portable
`get_device_module().is_current_stream_capturing()` API, but the breakable CUDA
graph capture-status helper does not include MUSA in that portable branch. MUSA
therefore falls through to the NVIDIA-only cuda-python path and fails even
though the portable capture-status query is available.

## Modifications

- Include MUSA in the portable capture-status branch of
  `_is_stream_capturing()`.
- Keep the original cuda-python path for NVIDIA.
- Add a focused unit test that verifies MUSA calls the portable device API and
  never reaches the CUDA bindings path.

## Related Work

- MUSA roadmap: https://github.com/sgl-project/sglang/issues/16565
- MUSA PCG reference: https://github.com/sgl-project/sglang/pull/20758

The PCG reference is platform context only; this PR fixes breakable graph capture
status and does not depend on the PCG implementation.

## Accuracy Test

Dispatch-level A/B verification with a mocked portable device module:

```text
torch.musa.is_current_stream_capturing callable: True
torch.cuda.is_current_stream_capturing callable: True

stock SGLang: STOCK_USED_CUDA_BINDINGS_PATH
patched SGLang: True
patched portable calls: 1
```

This confirms the issue is dispatch, not missing MUSA capture capability. The
stock branch reaches the NVIDIA cuda-python path; the patched branch calls the
portable MUSA API exactly once.

`pre-commit` passed on both changed files. Python compilation and
`git diff --check` also passed.

The test environment exposes a MUSA device, but no physical MUSA Graph capture
or breakable model run was completed. End-to-end MUSA availability and breakable
prefill performance remain separate validation work.
