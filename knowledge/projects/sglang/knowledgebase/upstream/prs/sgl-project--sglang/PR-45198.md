# [Fix] model_loader: Fix KV scale name remapping and pad_loaded_weight device/integer splitting

[Upstream PR](https://github.com/sgl-project/sglang/pull/45198) · state: open · merged: False

## Original PR description

## Motivation

Fixes three bugs in `python/sglang/srt/model_loader/weight_utils.py`:

1. **`maybe_remap_kv_scale_name` drops already-canonical `.attn.k_scale` / `.attn.v_scale` weights**:
   - Unlike vLLM's `maybe_remap_kv_scale_name` (which begins with `if name in params_dict: return name`), SGLang's implementation did not check whether `name` was already present in `params_dict`.
   - When a checkpoint or weight mapper already uses `.self_attn.attn.k_scale` / `.self_attn.attn.v_scale`, the `.endswith(".k_scale")` branch rewrote it into `.self_attn.attn.attn.k_scale`, failed `if remapped_name not in params_dict:`, and returned `None` (silently dropping the scale tensor).

2. **`maybe_remap_kv_scale_name` Quark scale mapping produces malformed `.prob_scale` names and raises `KeyError` on unmapped scales**:
   - `quark_scale_names` mapped `"self_attn.prob_output_scale": ".attn.prob_scale"`, turning `"model.layers.0.self_attn.prob_output_scale"` into `"model.layers.0..attn.prob_scale"` (with a double dot `..` and missing `self_attn`). Replacing `".prob_output_scale": ".attn.prob_scale"` preserves `self_attn` (`"model.layers.0.self_attn.attn.prob_scale"`).
   - Unlike the `.kv_scale` and `.k_scale`/`.v_scale` branches above it, the `quark_scale_names` branch returned `remapped_name` without checking `if remapped_name not in params_dict:`, causing callers (`param = params_dict[name]`) to fail with `KeyError` when a Quark checkpoint includes `.q_proj.output_scale` or `.prob_output_scale` for a model whose `RadixAttention` only registers `k_scale` and `v_scale`.

3. **`pad_loaded_weight` float truncation and CPU-only padding tensor allocation**:
   - `int(output_size / total_output_size * raw_output_size)` suffers from IEEE-754 float64 truncation (for example, `1 / 49 * 49 == 0.9999999999999999`, so `int(1 / 49 * 49) == 0`), triggering a spurious `AssertionError` even when `output_size * raw_output_size` is cleanly divisible by `total_output_size`. Using `(output_size * raw_output_size) // total_output_size` is exact.
   - `torch.zeros(target_pad_shape).to(loaded_weight.dtype)` allocated an intermediate `float32` CPU tensor and omitted `device=loaded_weight.device`, failing when `loaded_weight` resides on a non-CPU device (e.g., direct-to-GPU weight loaders).

## Modifications

- `python/sglang/srt/model_loader/weight_utils.py`:
  - Add `if name in params_dict: return name` at the start of `maybe_remap_kv_scale_name`.
  - Fix `quark_scale_names` key `".prob_output_scale": ".attn.prob_scale"` and guard `if remapped_name not in params_dict:` with `print_warning_once` + `return None`.
  - Use `(output_size * raw_output_size) // total_output_size` and `torch.zeros(target_pad_shape, dtype=loaded_weight.dtype, device=loaded_weight.device)` in `pad_loaded_weight`.
- `test/registered/unit/model_loader/test_weight_utils.py`:
  - Add `TestMaybeRemapKvScaleName` and `TestPadLoadedWeight` unit tests.
