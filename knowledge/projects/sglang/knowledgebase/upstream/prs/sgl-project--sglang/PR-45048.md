# [Fix] DSv4.1: Support CUDA image requests with encoder bounded replay

[Upstream PR](https://github.com/sgl-project/sglang/pull/45048) · state: closed · merged: True

## Original PR description

[codex/claude generated]

## Motivation

DeepSeek-V4.1 image requests fail with HTTP 400 when `--enable-encoder-swa-bounded-replay` is enabled, preventing MMMU-Pro evaluation with encoder bounded replay and breakable CUDA graphs (BCG). The CUDA folded replay path already preserves the multimodal metadata needed to reconstruct image embeddings, but request and scheduler guards reject images.

## Modifications

- Allow image inputs on the CUDA encoder replay path while retaining restrictions for non-CUDA multimodal replay, video/audio, user-supplied embeddings, positional overrides, and cached prompt logprobs.
- Add a regression covering mixed cache hits/misses and a replay window starting inside an image span, using the real multimodal embedding scatter path.
- Add a registered four-GB300 DeepSeek-V4.1-Flash E2E for encoder bounded replay + BCG + DSPARK, evaluating GSM8K and MMMU-Pro.

## Accuracy Tests

Local validation on 4× NVIDIA GB300, TP4/EP4, DeepSeek-V4.1-Flash:

| Evaluation | Examples | Accuracy | Required |
| --- | --- | --- | --- |
| GSM8K | 200 | 97% | 95% |
| MMMU-Pro | 200 | 78% | 75% |

Both E2E tests passed with no request errors. Nine MMMU-Pro responses reached the existing 32,768-token cap. DSPARK average acceptance lengths were 4.30 and 3.27 respectively.

An additional repeated-image request returned the correct color twice and showed 256 device-cached tokens on the repeat, exercising a replay window inside the image span.

The full GPU evaluation ran on upstream `fe89a7c89` plus this patch. The PR was subsequently rebased onto `670842672`; focused regression and formatting checks were rerun after the rebase. GitHub CI has not yet run.
