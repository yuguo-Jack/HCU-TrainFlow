# [Fix] humming: Honor input quantization ignore aliases

[Upstream PR](https://github.com/sgl-project/sglang/pull/40465) · state: closed · merged: False

## Original PR description

Superseded by merged #46018 (`ca939407423088dffd33304e0ea7d092cba355d2`). The alias-selection fix in this PR is present in current main; the original validation below remains historical.

---

## Motivation

`humming_is_layer_skipped` stops at a missing/empty alias and continues past a populated one. As a result, an exclusion supplied through any one of `ignored_layers`, `ignore`, or `modules_to_not_convert` is lost. `prepare_humming_moe_layer` can then select FP8 input schemas for an excluded layer.

## Modifications

Use the first **present** alias, matching `HummingConfig.is_layer_skipped` / `get_from_keys_or`. Explicit empty or null values keep their existing precedence over later aliases; this does not merge the lists.

Extend the registered CPU schema tests to cover all three aliases, precedence, empty/null values, absent configuration, `lm_head` and dynamic exclusions, and the actual MoE input-schema selection for both `w13` and `w2`.

## Accuracy Tests

The original 8 tests pass on the baseline. The added regressions reproduce 9 failing subcases before the fix; the complete file passes all 14 test methods after it:

```bash
CUDA_VISIBLE_DEVICES=999 PYTHONPATH="$PWD/python" python test/registered/unit/layers/quantization/test_humming_w4afp8_schemas.py
```

Tested on WSL Linux, Python 3.12, PyTorch 2.13.0+cu130, with CUDA hidden. The integration regression calls the production helper and MoE preparation with real Humming input schemas; downstream weight conversion/transforms are mocked. It covers the non-DeepEP schema path, not the separate FP8 DeepEP override. No GPU kernel or full-model accuracy claim.
