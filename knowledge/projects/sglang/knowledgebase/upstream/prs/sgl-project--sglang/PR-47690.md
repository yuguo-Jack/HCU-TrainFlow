# [Feat] [NVIDIA] quant: Enable CompressedTensorsWNA16TritonMoE on Turing sm_75 GPUs

[Upstream PR](https://github.com/sgl-project/sglang/pull/47690) · state: open · merged: False

## Original PR description

## Motivation

In SGLang quantization (`python/sglang/srt/layers/quantization/compressed_tensors/schemes/compressed_tensors_wNa16_moe.py`), `CompressedTensorsWNA16MoE` targets Marlin kernels and therefore enforces:

```python
    @classmethod
    def get_min_capability(cls) -> int:
        # ampere and up
        return 80
```

However, `CompressedTensorsWNA16TritonMoE` subclasses `CompressedTensorsWNA16MoE` while using pure Triton fused MoE kernels rather than Marlin. Because it did not override `get_min_capability()`, it inherited the `min_capability = 80` requirement.

As a result, users running W4A16 MoE models (such as `AtomicChat/Unlimited-OCR-2-W4A16`) on Turing (`sm_75`, e.g. Tesla T10, RTX 2080 Ti, Titan RTX) or Volta GPUs were rejected with:
```
RuntimeError: Quantization scheme is not supported for the current GPU. Min capability: 80. Current capability: 75
```

Since Triton MoE kernels natively run on Turing (`sm_75`) and Volta (`sm_70`), this capability check was unnecessarily restrictive.

## Modifications

1. In `CompressedTensorsWNA16TritonMoE`, override `get_min_capability(cls)`:
```python
    @classmethod
    def get_min_capability(cls) -> int:
        # Triton W4A16 MoE kernels support Turing/Volta (sm_70/sm_75) and up
        return 70
```
2. Allows SGLang to automatically dispatch Triton W4A16 MoE on Turing GPUs without modifying Marlin dense paths.

## Accuracy Tests

- Tested on Tesla T10 (Turing `sm_75`, 15GB):
  - Model weights: `AtomicChat/Unlimited-OCR-2-W4A16` (66 experts, uint8 packed).
  - Cosine Similarity compared to unquantized reference: **1.000000**.
  - Document parsing outputs identical Markdown structure with zero character corruption.

## Speed Tests and Profiling

- Tesla T10 (sm_75, 150W):
  - Decode speed: **63.6 ~ 64.0 token/s**.
  - Static model memory: **3.13 GB** (reduced from 12 GB FP16).
  - KV Cache tokens: **120,352 tokens**.
  - Peak memory: **11.9 GB** with 3.4 GB safety headroom across a 15-page document parsing stress test (17,824 tokens).
