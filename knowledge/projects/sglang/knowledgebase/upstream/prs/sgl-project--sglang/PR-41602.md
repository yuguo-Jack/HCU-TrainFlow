# [AMD] Add GLM-5.3 MI30x and MI35x nightly accuracy tests

[Upstream PR](https://github.com/sgl-project/sglang/pull/41602) · state: closed · merged: True

## Original PR description

## Motivation

GLM-5.3 has no AMD model test. The [Day-0 tracker](https://rocm.github.io/sglang-ci/day0/) lists it as **shared suites only**: its one AMD test is a kernel check, and both required CI cells from the cookbook recipe (MI30x FP8 and MI35x FP8) are missing.

## Modifications

- **New tests**, one per arch, both with `zai-org/GLM-5.3` (FP8):
  - `test/registered/amd/accuracy/mi30x/test_glm53_eval_mi30x.py`, suite `nightly-amd-accuracy-8-gpu-glm53`
  - `test/registered/amd/accuracy/mi35x/test_glm53_eval_mi35x.py`, suite `nightly-amd-8-gpu-mi35x-glm53`
  - Server args are the FP8 / low-latency / single-node cell of `docs/src/snippets/configs/zai-org/glm-5.3.jsx`, which is the same for MI300X, MI325X and MI355X: `--tp 8 --dsa-prefill-backend tilelang --dsa-decode-backend tilelang --chunked-prefill-size 131072 --mem-fraction-static 0.80 --watchdog-timeout 1200`, plus the `glm45` / `glm47` parsers and multithreaded weight loading. No MTP, because the cookbook disables it on AMD.
  - The eval is sgl-eval's zero-shot `gsm8k` through `run_sgl_eval`: full split, 64 threads, 32768 max tokens, temperature 1.0, top_p 0.95, thinking on, seed 42. These are the same parameters as the GLM-5.3-Flash MI35x nightly. The GLM-5.3 chat template forces thinking, so the legacy few-shot scorer that `run_combined_tests` uses for gsm8k would read numbers out of the reasoning trace.
- **New nightly jobs** in `nightly-test-amd.yml` (dropdown options, jobs, `check-all-jobs.needs`):
  - `nightly-8-gpu-glm53` on `linux-mi300-8gpu-sglang`, with an 18000 s per-file cap
  - `nightly-8-gpu-mi35x-glm53` on `linux-mi35x-gpu-8`, with a 9000 s per-file cap
- Both suites are added to `NIGHTLY_SUITES` in `test/run_suite.py`.
- **Retired `nightly-8-gpu-glm51`** (GLM-5.1, MI30x) and **`nightly-8-gpu-mi35x-glm52-fp8`** (GLM-5.2-FP8, MI35x accuracy + perf) from `nightly-test-amd.yml`: its dropdown option, job, and `check-all-jobs.needs` entry. GLM-5.3 takes over both GLM slots. The retired jobs' test files and `run_suite.py` suites stay, so they can still be run by hand.

I gated both arches because they don't run the same code. gfx942 converts the OCP FP8 weights to e4m3fnuz at load time and uses different AITER and tilelang kernels. The retired GLM-5.2-FP8 nightly covered gfx950 only.

## Validation

Dispatched on this branch with `continue_on_error=false`, full GSM8K split (1319 questions), HF snapshot `aca966e4`:

| Job | Image | Result | GSM8K | Wall clock |
|---|---|---|---|---|
| `nightly-8-gpu-glm53` (MI30x) | rocm724 | ✅ [run](https://github.com/sgl-project/sglang/actions/runs/36505808540/job/109206884696) | 0.9735 | 4332 s |
| `nightly-8-gpu-glm53` (MI30x) | rocm720 | ✅ [run](https://github.com/sgl-project/sglang/actions/runs/36505823619/job/109206938922) | 0.9704 | 4565 s |
| `nightly-8-gpu-glm53` (MI30x) | rocm10 | ✅ [run](https://github.com/sgl-project/sglang/actions/runs/36516664130/job/109240398922) (re-run) | 0.9765 | 2176 s |
| `nightly-8-gpu-mi35x-glm53` (MI35x) | rocm724 | ✅ [run](https://github.com/sgl-project/sglang/actions/runs/36523773291/job/109262164893) | 0.9742 | 1370 s |
| `nightly-8-gpu-mi35x-glm53` (MI35x) | rocm10 | ✅ [run](https://github.com/sgl-project/sglang/actions/runs/36541623736/job/109318168515) (re-run) | 0.9712 | 1018 s |
| `nightly-8-gpu-mi35x-glm53` (MI35x) | rocm720 | ✅ [run](https://github.com/sgl-project/sglang/actions/runs/36541643777/job/109318232261) (re-run) | 0.9742 | 1105 s |

- The MI30x scores sit inside the cookbook's CUDA range (97.12–97.73%). Both passing runs spent ~48 min of their load waiting on the first download into the pool's shared HF cache.
- The first MI30x rocm10 attempt failed before reaching the model. The shared cache returned `OSError: [Errno 116] Stale file handle` during the download, and the loader then found 138 of 141 shards missing. The re-run, with the cache warm, passed with a 942 s weight load.
- The MI35x scores match the cookbook's CUDA range: 0.9742 is inside it and 0.9712 is at its lower edge. Weight load took 576 s on rocm724, which did the download, and 106 s / 77 s on rocm10 / rocm720 once the cache was warm.
- The first MI35x attempts on all three images failed with `OSError: [Errno 28] No space left on device`: the pool's shared 15 TB HF cache was full. I freed 2.1 TB (GLM-5.2-FP8, GLM-5.1-FP8, Kimi-K2.6 and Qwen3-235B-A22B-Instruct-2507-mxfp4, none used by an MI35x job other than GLM-5.2-FP8) and re-ran. On that retry, rocm10 and rocm720 hit `FileNotFoundError` on `.incomplete` blobs: all three jobs downloaded into the shared cache at the same time and removed each other's partial files. rocm724 completed the download, and the rocm10 and rocm720 re-runs then passed against the warm cache.

## Status and threshold

- **Threshold 0.92.** It is `measured - 0.05` from the MI30x runs, the convention for sgl-eval gsm8k, and it matches the GLM-5.2-FP8 and GLM-5.3-Flash AMD nightlies. The MI35x runs (0.9742, 0.9712, 0.9742) clear it by the same margin.
- **Retired `nightly-8-gpu-mi35x-glm52-fp8`** the same way as GLM-5.1, now that GLM-5.3 passes on MI35x. GLM-5.3 keeps the GLM-5.2 architecture and FP8 format, so it covers the same gfx950 FP8 DSA path. The GLM-5.2-FP8 accuracy and perf test files and their `run_suite.py` suites stay. Until this merges, main's nightly keeps re-downloading the ~700 GB GLM-5.2-FP8 checkpoint into the MI35x cache.
- A perf step and the BF16 checkpoint (MI325X/MI355X only) are left for follow-ups.

- michaelzhang-ai · comment · 2026-10-15T05:56:57Z · [source](https://github.com/sgl-project/sglang/pull/41602#issuecomment-6185537195)

Follow-up after 16 scheduled nightlies on `main` (2026-09-29 through 2026-10-14, all including this PR):

- `nightly-8-gpu-glm51` and `nightly-8-gpu-mi35x-glm52-fp8` no longer run. Their test files and suites remain for manual dispatch.
- The GLM-5.3 jobs passed 95 of 96 runs on rocm10 / rocm720 / rocm724. Full-split GSM8K scores, against the 0.92 threshold:

| Job | Passed | GSM8K min | GSM8K max | GSM8K mean |
|---|---|---|---|---|
| `nightly-8-gpu-glm53` (MI30x) | 48 / 48 | 0.9689 | 0.9803 | 0.9747 |
| `nightly-8-gpu-mi35x-glm53` (MI35x) | 47 / 48 | 0.9689 | 0.9803 | 0.9744 |

- The one failure was `nightly-8-gpu-mi35x-glm53 (rocm724)` on 2026-10-06 ([job](https://github.com/sgl-project/sglang/actions/runs/37505216954/job/112412038210)). It was not a model or accuracy failure. The server never started, because the `sglang-radix-tree` Rust extension failed to build (`E0463: can't find crate for std`). 41 other test jobs failed in that run too, and the same job passed on rocm724 the next night.

The lowest score sits about 5 points above the threshold, so the gate has comfortable headroom against sampling noise. The GLM-5.3 MI35x perf step that replaces the retired GLM-5.2-FP8 benchmark is in #41669.
