## Code Review

This pull request updates the `forward` method of `DeepseekV2ForCausalLM` to handle cases where `input_ids` and `input_embeds` are `None` on later pipeline parallel (PP) ranks by falling back to `pp_proxy_tensors`. However, the reviewer identified a critical bug where using `pp_proxy_tensors["hidden_states"].shape[0]` as `len_input_ids` on later PP ranks causes a mismatch in Context Parallel (CP) metadata, as it represents the already-split sequence length instead of the unsplit length. The reviewer suggested using `sum(forward_batch.extend_seq_lens_cpu)` to get the correct unsplit sequence length.

### Critical Bug: Context Parallel (CP) Metadata Mismatch across PP Ranks

Using `pp_proxy_tensors["hidden_states"].shape[0]` as `len_input_ids` on later PP ranks introduces a critical bug when Context Parallelism (CP) is enabled:

1. **Split vs. Unsplit Length**: On later PP ranks, `pp_proxy_tensors["hidden_states"]` contains the already-split hidden states from the previous stage. Thus, `shape[0]` represents the **split** sequence length (e.g., `total_seq_lens / cp_size`), not the original **unsplit** sequence length.
2. **CP Threshold Mismatch**: `can_cp_split` and `can_dsa_cp_split` check if `seq_len // (cp_size * 2) != 0`. If `len_input_ids` is the split length, this check can evaluate to `False` on later PP ranks even though it evaluated to `True` on the first PP rank. This leads to CP being silently disabled on later PP ranks, causing a hang or crash.
3. **Metadata Mismatch**: Even if CP remains enabled, `prepare_context_parallel_metadata` uses `len_input_ids` as `kv_len` to calculate padding (`pad_len = kv_len - sum(extend_seqs_len)`). If `kv_len` is the split length, `pad_len` will be negative, leading to incorrect padding calculations and a mismatch in `split_list`, `zigzag_index`, and other metadata tensors between PP ranks. This causes silent data corruption or runtime crashes.

### Solution
Use `sum(forward_batch.extend_seq_lens_cpu)` to obtain the correct unsplit sequence length on later PP ranks during prefill.

```python
        if input_ids is not None:
            len_input_ids = input_ids.shape[0]
        elif input_embeds is not None:
            len_input_ids = input_embeds.shape[0]
        elif forward_batch.extend_seq_lens_cpu is not None:
            len_input_ids = sum(forward_batch.extend_seq_lens_cpu)
        elif pp_proxy_tensors is not None:
            len_input_ids = pp_proxy_tensors["hidden_states"].shape[0]
        else:
            raise RuntimeError(
                "DeepseekV2ForCausalLM.forward requires input_ids, "
                "input_embeds, or pp_proxy_tensors"
            )
```
