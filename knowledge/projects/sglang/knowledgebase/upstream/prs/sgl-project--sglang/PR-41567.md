# [Feat] [NPU] mm-global-cache: Add npu_memcache backend

[Upstream PR](https://github.com/sgl-project/sglang/pull/41567) · state: open · merged: False

## Original PR description

## Motivation

Add Ascend (NPU) support for the global multimodal-embedding cache by extending `--mm-global-cache-backend` with the `npu_memcache` option. Previously the only backend was `mooncake`, which depends on RDMA and is not usable on Ascend; a warning was emitted when `--enable-mm-global-cache` was combined with a non-`npu_memcache` backend on NPU. There was no way to run the global image-embedding cache on Ascend at all. This PR closes that gap by registering an embedding store backed by Ascend MemCache (`memcache_hybrid.DistributedObjectStore`) and by removing several hard-coded CUDA assumptions in the encoder / embedding-cache paths so the feature runs on NPU.

## Modifications

- **`python/sglang/srt/arg_groups/fields/mm.py`** — add `npu_memcache` to the `--mm-global-cache-backend` choices.
- **`python/sglang/srt/arg_groups/serving_hook.py`** — warn when a global cache is requested on NPU without `npu_memcache`; read the mm-global-cache args from the resolving view in the hook.
- **`python/sglang/srt/environ.py`** — add `SGLANG_MM_GLOBAL_CACHE_MEMCACHE_CONFIG_PATH` env var.
- **`python/sglang/srt/mem_cache/embedding_cache_controller.py`** — make the device stream/event/copy helpers device-agnostic and allow NPU tensors in `store_to_pool_async`.
- **`python/sglang/srt/mem_cache/embedding_store.py`** — register `npu_memcache` -> `NpuMemcacheEmbeddingStore`.
- **`python/sglang/srt/mem_cache/storage/npu_memcache/npu_memcache_embedding_store.py`** — new `EmbeddingStore` implementation over Ascend MemCache (`batch_get`/`batch_put`/`batch_is_exist`, multi-buffer variants), connecting to a MetaService/LocalService config.
- **`python/sglang/srt/disaggregation/encoder/server.py`** — make the mm-global-cache assembly syncs and zero-copy `TensorWrapper` staging device-safe (dispatch on `device.type` instead of hard-coded `torch.cuda`, and coerce the device to `torch.device`).

The end-to-end NPU test lives on a companion branch (`feature/npu-mm-global-cache-test`, commit `test(npu): e2e for --mm-global-cache-backend=npu_memcache`), kept separate from this adaptation branch. It is a 3-card EPD topology (encoder + prefill + decode + CPU LB) that self-launches a local Ascend MetaService and asserts cold-miss -> same-image global hit -> different-image isolation semantics.

## Accuracy Tests

This is a functional/connectivity change; it does not alter any model numerics. Correctness is covered by the companion NPU e2e test, which verifies that reusing the same image embedding through `npu_memcache` yields a relevant response (semantic-consistency proxy) with zero GPU recompute on the second request, and that a different image misses. No accuracy benchmark is applicable to this backend-selection/device-adaptation change.

## Speed Tests and Profiling

No throughput regression is expected: this PR only adds a backend option and fixes device-agnosticism in the encoder / embedding-cache staging paths. It does not change any runtime kernel, collective, or the default serving path (when the flag is unset, behavior is unchanged). Performance of the global-cache path on Ascend is a separate track.
