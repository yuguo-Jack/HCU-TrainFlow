# [Fix] [AMD] kda: Reject match_cutedsl_decode on ROCm and skip its parity tests

[Upstream PR](https://github.com/sgl-project/sglang/pull/44089) · state: closed · merged: True

## Original PR description

`match_cutedsl_decode` (#42251) reproduces FlashInfer's CuTe DSL decode kernel, including PTX `ex2.approx` / `lg2.approx` emitted through `inline_asm_elementwise` with `"=f,f"` constraints. AMDGCN rejects that asm (`error: could not allocate output register for constraint 'f'`), but the launch still runs and returns wrong values. So on ROCm both `TestKDAVerifyDecodeParity` tests that set `match_decode=True` fail. CI shows only the first because the suite stops early:

```
FAIL: test_bf16_state_verify_matches_single_token_launches (head_dim=128)
AssertionError: False is not true
```

https://github.com/sgl-project/sglang/actions/runs/38317177892/job/115041491883

No production caller sets `match_cutedsl_decode`; the parity test is its only user. So the wrapper now raises `NotImplementedError` on ROCm instead of returning wrong values. The two parity tests skip on ROCm, and a ROCm-only test checks that the error is raised. The default-path test in the same class keeps running on ROCm.

Everything here is gated on `_is_hip`, so NVIDIA behaviour is unchanged.

The other KDA failure on ROCm (`test_glm_fp32_weights_bit_exact_on_rocm`) has an unrelated cause and is fixed separately in #43991.
