# [Feat] llm-jp: Add llm-jp-harmony reasoning and tool call parsers

[Upstream PR](https://github.com/sgl-project/sglang/pull/44682) · state: open · merged: False

## Original PR description

## Motivation

Adds reasoning and tool call parsers for LLM-jp-4.1 (https://huggingface.co/llm-jp/llm-jp-4.1-8b-thinking, also 32b-a3b and 33b).

The model uses the gpt-oss Harmony format, but the tokenizer decodes a space after every special token, and parallel tool calls are separated by `<|end|>`:

```
<|channel|> analysis<|message|> I need both cities.<|end|>
<|start|> assistant to=functions.get_weather<|channel|> commentary <|constrain|>  json<|message|> {"city": "Tokyo"}<|end|>
<|start|> assistant to=functions.get_weather<|channel|> commentary <|constrain|>  json<|message|> {"city": "Osaka"}<|call|>
```

The `gpt-oss` parsers return no tool calls for this output, also with the changes in #38222.

## Modifications

- `llm-jp-harmony` reasoning and tool call parsers. The tool call parser builds its own grammar for `required`, named, `strict` and `parallel_tool_calls=false`, since the xgrammar `harmony` tag expects no spaces and `<|call|>` after every call.
- `auto` picks `llm-jp-harmony` when the chat template has `chat_format=llm-jp-harmony-v1`.
- Outside the new files: registration and two lines in `_patch_reasoning_skip_special_tokens`.

## Accuracy Tests

No change to model outputs. With `llm-jp/llm-jp-4.1-8b-thinking`, reasoning, single and parallel calls, `required`/named and streaming work, and on 400 BFCL v3 prompts the parsed output matches the reference parser of the LLM-jp vLLM plugin (https://github.com/llm-jp/llm-jp-vllm) for all 400.
