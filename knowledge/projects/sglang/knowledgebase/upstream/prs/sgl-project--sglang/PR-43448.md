# [Bugfix] DeepSeek V4: fix mHC prewarm when chunked prefill is disabled

[Upstream PR](https://github.com/sgl-project/sglang/pull/43448) · state: open · merged: False

## Original PR description

## Motivation

`prewarm_mhc_pre` sizes its token buckets from `chunked_prefill_size`. With `--chunked-prefill-size -1` (chunked prefill disabled) that produces a single bucket of `-1` tokens, so `residual.new_zeros(-1, ...)` raises while weights load. DeepSeek V4 cannot start with chunked prefill disabled.

Servers that capture prefill hidden states turn chunked prefill off, so a request's states arrive in one forward. They hit this on DeepSeek V4.

## Modifications

When chunked prefill is disabled or unset, size the prewarm buckets from `max_prefill_tokens`, which bounds a prefill batch in that case. This is the same rule `pre_capture_activation_reserve_mb` uses.

## Tests

`test/registered/unit/kernels/test_mhc_prewarm.py` (CPU, `mhc_pre` stubbed):
- chunk size 256 → buckets `[64, 128, 192, 256]`;
- chunked prefill `-1` / `0` / `None` → buckets bounded by `max_prefill_tokens`.

The three fallback cases fail without the fix and pass with it.
