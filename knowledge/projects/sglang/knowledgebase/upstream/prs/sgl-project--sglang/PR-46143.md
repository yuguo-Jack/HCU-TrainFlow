# [Fix] frontend: Preserve zero logprobs in choice normalization

[Upstream PR](https://github.com/sgl-project/sglang/pull/46143) · state: open · merged: False

## Original PR description

## Motivation

`RuntimeEndpoint.select` drops valid `0.0` logprobs because normalization filters by truthiness. A nonempty all-zero choice raises `ZeroDivisionError`; `[None, 0.0, -2.0]` is incorrectly averaged as `-2.0`, which can select the wrong choice.

Refs #3509. This addresses the valid-zero residual only; empty/all-`None` ranking is unchanged.

## Modifications

### Summary

```diff
- if x[0]
+ if x[0] is not None
```

Keep zero scores in the average while preserving `None` as the missing-value sentinel. Add registered CPU coverage for all-zero scores, mixed `None`/zero/negative scores, negative-score controls, and `token_length_normalized` ranking.
