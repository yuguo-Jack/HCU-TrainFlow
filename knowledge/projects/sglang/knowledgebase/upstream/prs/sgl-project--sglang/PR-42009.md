# [HiCache] MLA/DSA host dedup with rotating layer owners (opt-in)

[Upstream PR](https://github.com/sgl-project/sglang/pull/42009) · state: open · merged: False

## Original PR description

> **Reworked to reuse the existing code.** Rotating host-layer ownership is now an option of the #36800 primitives (`MLAHostDedupBroadcaster`, `MLAHostDedupContext`, the MLA/DSA host pools). It is switched on through the factory's existing `enabled=` argument and adds no new classes. This PR is now only the host dedup: the chunked D2H backup issue and the idle-sync skip were dropped from it. Rebased on current `main`.

## Motivation

Every attention-TP rank holds the same MLA latent KV and DSA index keys. As a result, HiCache backs up, stores and loads back the same bytes on every rank, and stores each token once per rank. #36800 landed the dedup primitives, but nothing in HiCache uses them yet; today only the Mooncake linker does. #26691 (closed) used a single source rank, which then carried every host copy and every broadcast.

## What is reused

| Need | Existing code |
|---|---|
| Enable switch and dedup state | `maybe_create_mla_host_dedup_context(..., enabled=)`, `MLAHostDedupContext` |
| Eligibility (MLA/DSA, non-FP4, CUDA, more than one rank) | `mla_host_dedup_eligible`, `mla_dedup_rank_and_size` |
| Broadcast group and DP attention | `MLAHostDedupBroadcaster.build` (group from `attn_tp_group`; warm-up unchanged) |
| Per-layer broadcast with the page index computed on device | `_bcast_layer`, `broadcast_loaded_layer`, `prepare_broadcast` |
| Host pools store only their own layers | The MLA host pool's `_is_device_layer_owned` and `_host_layer_index` hooks; the DSA indexer pool's compact `_live_target_layers` |
| Layer-wait hook on the forward stream | `LayerDoneCounter` gets the same `on_layer_ready` callback as the Mooncake linker's counter |
| Config validation | `handle_hicache`, next to the `--enable-linker-mla-dedup` check |

## What is new

- **Rotating owners.** `MLAHostDedupBroadcaster(rotate_owners=True)` broadcasts layer slot `s` (each KV layer, then each layer that holds index keys) from dedup rank `s % size`, using `group_src`. `build()` forwards constructor arguments, and the Mooncake linker passes none, so its behavior is unchanged.
- **Two fixes in the primitives.** Shared-top-k index layers (0-row placeholders) are skipped, where `main` raises in `index_select`. The index-key staging buffer is sized in pages, its row unit.
- **Load-back.** Each rank loads only its own layers. The forward broadcasts each layer from its owner through the layer-wait hook, on the forward stream, right after it waits for that layer's H2D copy. Later layers therefore keep loading while earlier ones compute. The load's ack event is recorded again after the last broadcast, so the ack and the allocator's transfer fence cover the broadcasts.
- **Host capacity.** `MLATokenToKVPoolHost(dedup_rank=, dedup_size=)` stores KV layers `rank`, `rank + size`, and so on. Token capacity is sized by the largest share, so every rank holds the same tokens. Packed MTP draft layers stay on every rank. The DSA indexer pool keeps its share of the index layers.
- **One server argument:** `--enable-mla-hicache-host-dedup`. `handle_hicache` rejects it unless the L2 tier uses direct I/O with `page_first_direct`, on one node and one PP stage, with no storage backend, hisparse, attention CP/DCP or PD decode. Attaching a storage backend at runtime is rejected too.

Off by default: with the flag unset, no context or group is created and every path is unchanged.

## Accuracy and performance

All GPU numbers below were measured on this PR's head (`0f5738164e`), applied to the SGLang nightly at `7224fce1`. Every arm uses the same build; the control simply leaves the flag off.

**Setup**
- **Model and serving:** GLM-5.2 FP8 at TP8 on one node with 8× B300, with EAGLE (3 steps, top-k 1, 4 draft tokens).
- **HiCache L2:** `write_back`, direct I/O, `page_first_direct`.
- **Prefill and memory:** 8192-token chunked prefill; `mem-fraction-static` 0.92; max running requests = 2 × concurrency.
- **Workload:** agentic-coding trace replay, with a 20-minute measurement window per arm. Throughput runs use a fixed synthetic acceptance length; GSM8K uses real acceptance.
- **Noise:** one run per arm, so treat differences under about 5% as noise.

**Performance**

| Arm | p90 tok/s per user | tok/s per GPU | TTFT p50 / p90 (s) | Cache hit | Pinned host memory (node) |
|---|---|---|---|---|---|
| c32, dedup off (control), 270 GB/rank | 27.21 | 10,585 | 2.30 / 26.21 | 93.1% | 2,655 GB (host pool full) |
| c32, dedup on, 270 GB/rank (7.18× host tokens) | **45.77 (+68%)** | **14,859 (+40%)** | 0.60 / 6.80 (−74%) | 95.4% | ≈ 2,595 GB (pool 33% used at peak) |
| c32, dedup on, 38 GB/rank (≈ same host tokens as control) | 31.38 (+15%) | 10,952 (+3.5%) | 1.74 / 20.52 (−22%) | 92.5% | 372 GB (−86%) |
| c32, single owner (rank 0 owns every layer; diagnostic switch, not in this PR), 270 GB/rank | 25.18 | 10,355 | 2.11 / 28.47 | 93.0% | ≈ 361 GB |
| c16, dedup off (control) | 87.39 | 8,438 | 0.28 / 1.73 | 95.8% | 2,655 GB |
| c16, dedup on, 270 GB/rank | 87.33 (−0.1%) | 8,385 (−0.6%) | 0.27 / 1.58 | 95.8% | ≈ 2,595 GB |

Reading the table:
- **Where the c32 gain comes from:** about +15% p90 from cheaper backup and eviction at equal capacity. Eviction drops from 13.9% to 8.3% of the window per rank, and backup from 8.6% to 1.2%, because each rank backs up about 1/8 of the layers. The rest comes from 7.18× host capacity in the same memory.
- **Rotating owners matter:** a single owner puts all backup and eviction on rank 0. It lands 20% behind rotation at equal host tokens on p90, and 7.5% behind the control.
- **c16:** the host path is about 3% of the window with dedup off, so there is little to recover.
- **Cost:** the per-layer broadcasts run on the forward stream and are not overlapped. They took 11.6% of a 283K-token load-back forward and 25–27% of a 107K-token one, mostly waiting on peer ranks. With HiCache on, `main` keeps index keys for all 78 layers on host, although only 21 have their own; that is 13.6% of broadcast bytes. Index-K elision under HiCache (#41057) would remove it.

**Accuracy (GSM8K 5-shot, stress)**

The device KV pool was capped at 131,072 tokens. Pass 1 runs at concurrency 32. Pass 2 runs at concurrency 64 and reloads 96.5% of prompt tokens from host: 1,287,488 tokens loaded back on every rank with dedup on.

| Arm | Pass 1 strict / flexible | Pass 2 strict / flexible |
|---|---|---|
| Dedup off | 0.9674 / 0.9704 | 0.9674 / 0.9689 |
| Dedup on | 0.9682 / 0.9697 | 0.9689 / 0.9712 |

Per-document McNemar, off vs on: p ≥ 0.61 for every pass and filter.

**Engagement**
- Every rank logs the broadcaster setup and warm-up and owns 9–10 of the 78 KV layers. With a single owner, ranks 1–7 own 0.
- A profile shows one broadcast per layer during load-back, issued from the layer-wait hook just before that layer's attention (57/57) or index-key store (21/21).
- No collective or watchdog errors in any arm.

**Unit tests** in `test_mla_host_dedup_primitives.py`:
- per-layer broadcast source, including the placeholder skip;
- index staging size;
- a multi-process gloo restore through the layer-wait hook;
- DP attention over the attention-TP group;
- host-pool layer mapping, including the draft layer;
- capacity sizing.

With the flag off, the existing host-pool, assembler, write-back and server-args suites give the same results as `main`.

## Reproduction

**Hardware and image**
- **Hardware:** one node with 8× B300 and 2.4 TB of host DRAM for the KV host tier.
- **Image:** `lmsysorg/sglang:nightly-dev-cu13-20261013-7224fce1` (`sha256:20d36eeb32df0418a165641b51399fd4dc5239dad57f9b8d1f9974c4c9263ca6`), with this PR applied.

**Server.** Dedup-on arm at concurrency 32; the control arm drops `--enable-mla-hicache-host-dedup`.
```bash
SGLANG_SIMULATE_ACC_LEN=2.99 SGLANG_SIMULATE_ACC_METHOD=match-expected \
SGLANG_SIMULATE_ACC_TOKEN_MODE=real-draft-token SGLANG_TIMEOUT_KEEP_ALIVE=900 \
python3 -m sglang.launch_server --model-path zai-org/GLM-5.2-FP8 \
  --served-model-name zai-org/GLM-5.2-FP8 --trust-remote-code \
  --tp-size 8 --ep-size 1 --quantization fp8 --kv-cache-dtype fp8_e4m3 --bf16-gemm-backend cutedsl \
  --chunked-prefill-size 8192 --max-prefill-tokens 8192 --mem-fraction-static 0.92 \
  --max-running-requests 64 --cuda-graph-max-bs-decode 64 \
  --speculative-algorithm EAGLE --speculative-num-steps 3 --speculative-eagle-topk 1 \
  --speculative-num-draft-tokens 4 \
  --tool-call-parser glm47 --reasoning-parser glm45 \
  --enable-hierarchical-cache --hicache-size 270 --hicache-write-policy write_back \
  --hicache-io-backend direct --hicache-mem-layout page_first_direct \
  --enable-mla-hicache-host-dedup --enable-metrics --watchdog-timeout 1800
```

**Other arms**
- **Equal host tokens:** `--hicache-size 38`.
- **Concurrency 16:** `--max-running-requests 32 --cuda-graph-max-bs-decode 32`.
- **Single owner:** a local diagnostic switch that gives every layer to rank 0. It is not part of this PR.

The three `SGLANG_SIMULATE_ACC_*` variables fix the speculative acceptance length for the throughput runs, following the AgentX synthetic-acceptance rule. GSM8K runs leave them unset and use real verification.

**Benchmark.** InferenceX AgentX replay, `benchmarks/srt_agentic.sh` from [SemiAnalysisAI/InferenceX](https://github.com/SemiAnalysisAI/InferenceX) at `1570a54f`, with its agentic-coding trace set:
```bash
MODEL=zai-org/GLM-5.2-FP8 CONC=32 KV_OFFLOADING=dram TOTAL_CPU_DRAM_GB=2399 \
AIPERF_EXPERIMENTAL_FAST=1 RUN_EVAL=false EVAL_ONLY=false \
bash benchmarks/srt_agentic.sh
```
`AIPERF_EXPERIMENTAL_FAST=1` is the shortened replay, which gives the 20-minute window.

**GSM8K stress.** Same server, without the `SGLANG_SIMULATE_ACC_*` variables and with `--max-total-tokens 131072` to cap the device KV pool. Then run InferenceX's eval path, lm-eval GSM8K 5-shot, at concurrency 32 and then 64:
```bash
MODEL=zai-org/GLM-5.2-FP8 RUN_EVAL=true EVAL_ONLY=true EVAL_CONC="32 64" \
bash benchmarks/srt_agentic.sh
```
