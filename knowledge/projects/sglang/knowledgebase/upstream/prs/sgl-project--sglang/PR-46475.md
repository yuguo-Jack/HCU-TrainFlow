# [Perf] [NVIDIA] kimi-k3: Device-prepared expert-tile routing metadata for the FlashInfer FP4 MoE

[Upstream PR](https://github.com/sgl-project/sglang/pull/46475) · state: open · merged: False

## Original PR description

## Motivation

For Kimi-K3's MXFP4 MoE on the FlashInfer trtllm-gen path, the expert routing metadata is built on the host each call. At small M it is cheaper to build it on device and hand FlashInfer's native FP4 MoE body prepared expert-tile metadata through `TrtllmMoERoutingMetadataSlot`.

## Modifications

- `trtllm_prepared_fp4.py` (new): `prepare_expert_tile_metadata` sorts routes by expert so each distinct expert owns one padded CTA tile; buffer sizes derive from tokens, top-k, experts and tile; `try_prepared_k3_mxfp4` runs the native body with that metadata for the K3 shapes at M = 1 and M = 8 (deferred or finalized) and returns None otherwise.
- `route_quant_metadata.cuh`, `moe_route_quant_fused.py`, `route_quant_handoff.py`: the fused radix routing + per-token-group quantization launch also writes the metadata in-kernel at M <= 8, handed to the runner through the route-quant handoff. Metadata is refreshed every call because the expert kernels may rewrite the expanded-to-permuted map.
- `flashinfer_trtllm.py`: the MXFP4 trtllm-gen path tries the prepared body first and falls back to `trtllm_fp4_block_scale_routed_moe`; pass `moe_op` to the runner constructor.
- Enabled on SM100, SM103 and SM107.
- `test_prepared_mxfp4.py`: the device-built metadata is bit-exact against the Triton reference, and the prepared path matches `trtllm_fp4_block_scale_routed_moe` at M = 1 and M = 8, deferred and finalized, with changing routes and under CUDA-graph replay.

## Accuracy Tests

- `test_prepared_mxfp4.py` passes on GB300 (SM103) with this branch: metadata bit-exact against the Triton reference; prepared path matches `trtllm_fp4_block_scale_routed_moe` at M = 1 and M = 8, deferred and finalized, under CUDA-graph replay.
- `test_route_quant_prerequisites.py` 3 OK on SM107; `test_route_quant_prerequisites.py` and `test_tiny_gemm.py` green on H100 CI for the combined branch this was split from.
- Fork: GSM8K 127/128 on SM107 TP8 with the prepared MXFP4 path.

## Speed Tests and Profiling

B200 (fork measurement, M8, synthetic K3 TP8 MoE shapes, CUDA-graph replay): fused route+quant 2.75 -> 4.80 us with metadata, replacing the 2.15 us Triton prep; route+quant+experts 61.27 us with Triton prep -> 59.39 us fused, vs 67.26 us on FlashInfer's own routing. SM107 TP8, bs=1, 60k/1k, MXFP4: metadata prep 12.48 -> 10.97 us, fused sequence 2.80-3.12 -> 1.92-2.23 us, 149.6 -> 163.8 output tok/s (+9.5%).
