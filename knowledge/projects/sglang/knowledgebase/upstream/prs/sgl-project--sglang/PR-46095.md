# [Fix] diffusion/loader: Preserve checkpoints on read failures

[Upstream PR](https://github.com/sgl-project/sglang/pull/46095) · state: closed · merged: True

## Original PR description

## Summary

Safetensors header validation currently treats every read exception as corruption, then deletes the file. For a symlink, it also deletes the target blob, which may be shared by other snapshots or replicas. Permission and storage I/O errors can therefore destroy otherwise valid checkpoints.

Remove this automatic deletion. Keep validation and duplicate-key rejection, report the original read error, and leave repair or re-download to the operator. Document the behavior in the deployment cookbook. No new option or production module; production code decreases by 22 lines.

## Validation

- Regression tests reproduce deletion on the parent for regular files and shared symlinks under malformed headers, permission errors, and I/O errors.
- Remote loader suites: 52 tests and 12 subtests pass, including retrying a transient read error without re-downloading the checkpoint.
- Real Wan2.1-T2V-1.3B HTTP inference on H200, single GPU and Ulysses2: 8 generations across 4 rejected updates and 2 successful reloads. Source files survive rejection, health remains ready, and weight checksums plus decoded-frame hashes remain unchanged within each configuration.
- Pre-commit passes.

This does not change checkpoint repair tooling, generation kernels, or the normal weight-reading path. TP/FSDP hot updates and hardware-level storage fault injection were not exercised by the GPU smoke test.
