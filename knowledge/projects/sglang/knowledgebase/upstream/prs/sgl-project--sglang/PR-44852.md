# [Perf] [Intel] gemma4: Enable frozen-KV MTP graph capture

[Upstream PR](https://github.com/sgl-project/sglang/pull/44852) · state: open · merged: False

Stack (2/6), merge in order: [#44851](https://github.com/sgl-project/sglang/pull/44851) → [#44852](https://github.com/sgl-project/sglang/pull/44852) → [#44853](https://github.com/sgl-project/sglang/pull/44853) → [#44854](https://github.com/sgl-project/sglang/pull/44854) → [#44863](https://github.com/sgl-project/sglang/pull/44863) → [#44869](https://github.com/sgl-project/sglang/pull/44869)

## Motivation

Frozen-KV MTP on XPU fails under the synchronous scheduler and uses the draft's dummy KV pool when determining sliding-window translation. It also leaves recurrent assistant forwards eager despite the shared graph runner supporting XPU.

## Modifications

- Accept and forward `pp_proxy_tensors` through target prefill and verification.
- Bind frozen draft attention to the target allocator's KV pool and skip write-slot metadata for this read-only draft.
- Enable frozen-KV draft graph capture on XPU, with a serving regression and an E2B/BMG MTP recipe.

Depends on #44851. No CPU-offload changes or weight quantization.

## Accuracy Tests

Five attention backend unit tests pass, including a pool-ownership regression that fails before the fix. The XPU MTP serving fixture checks repeated decode, per-request verification statistics, and nonzero draft capture. Six greedy prompts match ordinary decoding, including 1,016- and 1,814-token prompts crossing the sliding-window boundary.

GSM8K via `sgl-eval==0.1.3`: 82.5%/200, zero errors, two truncated responses. This is a smoke check, not proof of accuracy improvement or equivalence.

## Speed Tests and Profiling

Same physical Intel Arc Pro B70, TP1 BF16, unchanged target weights, context 8,192, KV capacity 32,768, max running requests 8; MTP top-k 1, three draft steps/four verification tokens. OpenAI chat benchmark, fixed 256 output tokens, two repeats; 8 requests at concurrency 1 and 32 at concurrency 8.

| Concurrency | Ordinary TPOT | Corrected eager MTP | Captured MTP |
| --- | ---: | ---: | ---: |
| 1 | 11.168 ms | 7.742 ms | 4.282 ms |
| 8 | 11.774 ms | 9.372 ms | 5.914 ms |

Capture alone improves TPOT by 1.81x/1.58x over corrected eager MTP. The total 2.61x/1.99x over ordinary decoding also includes speculative decoding's benefit.
