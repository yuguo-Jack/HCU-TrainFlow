# [DLLM] Onboard Nemotron-Labs-Diffusion model with FastDiffuser decoding

[Upstream PR](https://github.com/sgl-project/sglang/pull/25803) · state: closed · merged: False

## Original PR description

## Motivation

First PR of the staged Nemotron Labs Diffusion upstreaming stack (tracked in #25802): add the released `nvidia/Nemotron-Labs-Diffusion-8B` model, the shared diffusion-LLM (DLLM) runtime integration it needs, and one working decoder — `FastDiffuser`. This change is independently runnable and does not depend on later planned interfaces.

LinearSpec, LoRA/AR mode, the FA4 attention backend, LearnedSampler, and evaluation helpers are staged as later PRs — see #25802 for the full stack and end-to-end validation.

## Scope

- Add the released Ministral-based `NemotronLabsDiffusionModel` implementation.
- Add causal-context DLLM request, scheduler, schedule-batch/policy, and KV-accounting integration.
- Add FlashInfer and decode/prefill CUDA-graph plumbing for diffusion decoding.
- Add FastDiffuser block denoising with EOS handling and compacted active batches.
- Add the internal `defer_cuda_graph_capture` server arg for algorithms that bake auxiliary weights into CUDA graphs.
- Keep the shared KV write implementation unchanged.

### inline_comments

- hutm · comment · 2026-06-29T15:51:58Z · [source](https://github.com/sgl-project/sglang/pull/25803#discussion_r3492990307)

File: `python/sglang/srt/dllm/attention.py` · line 26

Causal-context models intentionally use two attention regimes here. Prompt-cache population and the final KV refresh are causal, while denoising EXTEND passes are bidirectional. dllm_causal_kv_update marks that refresh explicitly; centralizing this decision keeps the eager and CUDA-graph backends consistent.

- hutm · comment · 2026-06-29T15:51:58Z · [source](https://github.com/sgl-project/sglang/pull/25803#discussion_r3492990319)

File: `python/sglang/srt/dllm/mixin/scheduler.py` · line 167

FastDiffuser returns a block, but EOS or max_tokens may accept only a prefix. The rejected suffix already owns KV slots, so this path frees that tail and rolls back the committed and allocated lengths before normal request release. That prevents tail KV from being retained or inserted into the radix cache.

- hutm · comment · 2026-06-29T15:51:58Z · [source](https://github.com/sgl-project/sglang/pull/25803#discussion_r3492990326)

File: `python/sglang/srt/dllm/mixin/scheduler.py` · line 425

The released causal-context checkpoint needs one regular EXTEND pass before its first denoising block so prompt KV is initialized with causal masking. This intentionally goes through PrefillAdder instead of bypassing scheduler capacity and preemption accounting.

- hutm · comment · 2026-06-29T15:51:58Z · [source](https://github.com/sgl-project/sglang/pull/25803#discussion_r3492990333)

File: `python/sglang/srt/layers/rotary_embedding/yarn.py` · line 96

The released checkpoint provides both mscale and mscale_all_dim. Hugging Face applies their ratio to the attention scale; using the simple fallback here would change RoPE attention magnitudes. This branch is checkpoint compatibility rather than a new tuning choice.

- hutm · comment · 2026-06-29T15:51:58Z · [source](https://github.com/sgl-project/sglang/pull/25803#discussion_r3492990336)

File: `python/sglang/srt/models/nemotron_labs_dllm.py` · line 639

The checkpoint stores encoder.* parameters and separate Q/K/V and gate/up projections, while the SGLang module uses model.* names and fused projections. Keeping this translation in the loader preserves the existing fused runtime path without changing model math.
