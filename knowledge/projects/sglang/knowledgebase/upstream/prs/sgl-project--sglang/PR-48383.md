# [Perf] diffusion: reuse bit-exact RoPE in HiDream-O1-Image

[Upstream PR](https://github.com/sgl-project/sglang/pull/48383) · state: open · merged: False

## Original PR description

## Motivation

HiDream-O1-Image executes rotate-half RoPE separately for Q and K in all 36 transformer layers. At 2048×2048 and 50 CFG steps, the eager elementwise chain launches 57,600 kernels. Reusing the existing BF16-rounded RoPE kernel reduces this to 7,200 launches and lowers saved-request latency by **4.87–4.92%** in two independent paired rounds on B300.

- Main baseline: `4c7c775cf4adcbd2c7419d13b51ec838a17e559e`.
- Final tested PR head: `4b0f75d26a870d2401782545e1a2a4e173f752ee`.
- Before cleanup: `603193d7d31a91ddc7bb0bced66c37030fbd1991`.
- Checkpoint: `HiDream-ai/HiDream-O1-Image@0b0901d99f200389e138c61946af1185f5f49a13`.

## Modifications

- Reuse `fused_rope_rotate_half_bitexact` for contiguous CUDA BF16 Q/K. Its separate BF16 product and sum rounding matches the native eager expression; attention and normalization are unchanged.
- Reuse `BitExactFusionGate` for first-call equality checking, mismatch/exception disabling, and eager fallback. Unsupported layouts/dtypes retain the native path.
- Add four focused dispatch/fallback cases to the existing registered test and document this call site in the kernel README. The source diff contains no new kernel, option, cache or precision policy.
