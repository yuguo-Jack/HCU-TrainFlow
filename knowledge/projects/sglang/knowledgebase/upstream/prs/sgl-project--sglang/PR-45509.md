# [Perf] kda: Remove unused d/k rings from speculative ReplaySSM

[Upstream PR](https://github.com/sgl-project/sglang/pull/45509) · state: open · merged: False

## Original PR description

## Motivation

With `--enable-linear-replayssm-spec`, KDA models allocate and budget the decode ring's `d`/`k` buffers on every Mamba slot, but spec-verify only reads its fold window (raw v, raw k, the gate, and beta). On GLM-5.3-Flash NVFP4 at TP2 with 512 Mamba slots, `d` and `k` take 2.13 GB each per GPU.

## Modifications

- Remove the `d`/`k` rings from the KDA pool under `--enable-linear-replayssm-spec`.
(note that while `forward_decode` routes on `d`, it doesn't run with this flag, so behavior is unchanged)
- Remove the KDA `d`/`k` terms from `replayssm_ring_bytes_per_req`, so the sizer gives that memory to the KV pool.

## Accuracy Tests

GLM-5.3-Flash NVFP4 on 2xB200 (TP2/EP2) with a DFlash2 draft, 512 Mamba slots, and ring length 16:

| | main | this PR |
|---|---|---|
| `d` / `k` per GPU | 2.13 GB each | 0 |
| KV cache tokens | 647,680 | 1,024,256 |
| GSM8K | 0.925 | 0.930 |
| Accept length | 5.07 | 5.07 |

`test_kda_fold` now expects 2,176 bytes per layer and fails on main. A new case checks that a KDA spec pool allocates exactly the accounted ring bytes. The ring accounting, Mamba allocation, KDA dispatcher, and n-gram verify unit tests pass on CPU (38), and `test_mamba_unittest.py` passes on 1xH200.
