# [Fix] rust-server: Report the launched --tokenizer-path from the info endpoints

[Upstream PR](https://github.com/sgl-project/sglang/pull/46879) · state: closed · merged: True

## Original PR description

## Motivation

In Rust frontend mode, `/server_info`, `/model_info` and `/get_model_info` (and gRPC `GetModelInfo` / `GetServerInfo`) report the tokenizer path the Rust server *loads*, not the launched `--tokenizer-path`. The loader path comes from the scheduler's `rust_server_tokenizer_path()` hook, which a model-side override may point at a process-local copy of the tokenizer, for example a temporary directory holding only `tokenizer.json`. That path then leaks out of the info endpoints, and a client that loads the tokenizer from `/server_info` or `/model_info` gets a path that is temporary and may not exist on its side. The Python server reports the launched `--tokenizer-path` (`http_server.py`, `model_info` / `get_model_info`).

## Modifications

- `message/config.rs`: `ServerArgs` gains `public_tokenizer_path`, the launched `--tokenizer-path` as reported by the info endpoints. `tokenizer_path` keeps its meaning (the source this server loads) and its docstring now says why the two differ.
- `core/handle.rs`: `CoreMetadata` takes `tokenizer_path` from `public_tokenizer_path`, so every info surface (HTTP and gRPC) reports the launched path. The tokenizer, detokenizer and chat template still load from `tokenizer_path`; serving behaviour is unchanged, and when both paths are the same the reported value does not change.
- `rust_server/config.py`: passes the launched `--tokenizer-path` as the new required keyword next to the loader path.
- `http/info.rs` tests: the `/model_info` and `/server_info` route tests now give the loader a path that differs from the public one, so they fail without the `CoreMetadata` change.
- `test_rust_server_dp_ports.py`: two new handoff cases check `tokenizer_path` (the scheduler's loader path) and `public_tokenizer_path` (the launched path) separately.

Not applicable: no model forward or kernel code changes; generated tokens are unchanged.
