# [Chore] deepseek-v4.1: Harden the prefill graph capture of the full top-k break

[Upstream PR](https://github.com/sgl-project/sglang/pull/45283) · state: closed · merged: False

## Original PR description

- The breakable prefill graph's capture pass runs each eager break once, on activations that the segments before it only captured and never computed (`eager_on_graph`). The DeepSeek-V4.1 full top-k break (#43733) scores and selects candidate blocks from those values.
- Inside the 16K candidate window the candidate table is the identity whatever the input, so buckets up to 16K tokens are unaffected. Buckets past the window (for example 32K tokens per rank) turn the uncomputed values into block ids for DeepGEMM's schedule. The same selection in the decoder tail graph's capture pass saw activations of 0 and 1.7e38, tripped DeepGEMM's `logical_page_idx < block_table_stride` assert, and got a capture stub in #45107.
- This is hardening: the failure was not reproduced on the prefill graph (a TP4 main run with 32K buckets captured and served normally).

Changes:
- `_bcg_prefill_graph_full_topk` gets a `capture_stub` that selects nothing: the sparse index outputs hold the empty selection (-1), and the candidate source returns an empty table from the new `SparseTableBackend.capture_prefill_graph_table`, in the buffers the buckets share.
- `publish_prefill_graph` now runs only at replay, and its tables are copied into those buffers; its `shared=` argument and `is_capturing` (added by #43733, now unused) are removed.
- The break and the stub build their indexer inputs in one helper, `_prefill_graph_full_topk_inputs`.

No behavior change outside the capture pass: warmup, replay and eager prefill run the same code as before.

Verification, GB300, DeepSeek-V4.1-Flash, TP4, DSpark, chunked prefill 32,768, prefill graph buckets up to 32,768 tokens:
- Capture takes 70 s and 27.69 GB per GPU, on this branch and on main alike; 99 prefill steps replayed with no shape mismatch between the empty table and the published ones.
- First-token top-20 distributions, as total variation distance from the same tree's eager prefill: at most 0.027 on two text needles (134K and 284K tokens), 0.015 on 155,648- and 327,680-token prefixes (cold, and with 256 or 1,024 new tokens), 0.081 on short prompts. Main's graph gives 0.012, 0.015 and 0.076 on the same cases, within the eager run-to-run spread.
- GSM8K (sgl-eval, 200 questions, model preset, 8-shot prefix): 96.0%.
- CPU unit tests: `test_dsv41_late_layer_tail_readers.py`, `test_deepseek_v4.py::TestDSV4BreakableCudaGraphMetadataContract`, `test_eager_on_graph.py`, `test_encoder_swa_replay.py`, `test_prefill_cuda_graph_runner.py`, `test_dsv4_nonpaged_indexer.py`.
