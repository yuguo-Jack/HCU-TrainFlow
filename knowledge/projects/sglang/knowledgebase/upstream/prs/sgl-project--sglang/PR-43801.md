# [Fix] Handle overflowing TopK v2 threshold buckets exactly

[Upstream PR](https://github.com/sgl-project/sglang/pull/43801) · state: open · merged: False

## Original PR description

## Motivation

TopK v2 can silently select incorrect values when more than 2,048 candidates occupy the threshold bucket. FP32 scores in a coarse bucket need not be equal, so selecting from an arbitrary retained subset can discard required high-score members even when all returned indices are valid.

## Modifications

- Preserve the true bucket population while keeping candidate-buffer copies capacity-bounded.
- Recover overflowing buckets from the valid input using four byte-wise radix passes and a final scan, retaining all higher keys and only the required cutoff ties.
- Apply recovery to register, streaming, and cluster selection. Cluster recovery runs in rank 0; no additional kernel launch or host synchronization is introduced.
- Add strict regressions for overflow boundaries, output modes, negative scores, partial ties, infinities, ragged/odd lengths, small K, and changing CUDA Graph inputs. Public APIs and dispatch remain unchanged.

## Accuracy Tests

H20 (78 SMs), CUDA 13.0, PyTorch 2.13.0+cu130:

- **155 strict added regressions passed**, including 55 additional boundary/Graph cases.
- Full test file: **443 passed, 18 ROCm-only skipped**. The strict regressions are included in the 443; existing general tests retain upstream tolerances.
- The same 4,096-candidate negative control fails the selected-value oracle upstream and passes with the fix.
- Memcheck, racecheck, and synccheck each passed the same 55 new cases with zero errors; racecheck also reported zero warnings.
- The historical frozen failure passed eager and CUDA Graph checks with the unchanged CUDA implementation.

GPU validation used `121ea94e0b`. Head `158ffe61a3` only reformats three test expressions; Python AST equivalence and unchanged CUDA were verified. No GPU rerun is claimed for that formatting commit.

Other GPU architectures, sixteen-block cluster execution, ROCm, and the real score dumps from #35257 remain unvalidated.

## Speed Tests and Profiling

**Performance cost remains inconclusive.** The final comparison stopped at the same-code equivalence gate before measuring upstream against the fix. Earlier measurements on a previous revision observed approximately 10% overhead in one cache-scrubbed non-overflow cluster case; this remains a disclosed risk, not an established cost for the current head.

Overflow recovery requires additional scans, and compiled resource changes may also affect non-overflow paths. This PR makes no zero-overhead or inference speedup claim. Performance characterization remains an open review item.
