# [Fix] scoring: Return token_logprobs for setwise CausalLM scoring

[Upstream PR](https://github.com/sgl-project/sglang/pull/47649) · state: open · merged: False

## Original PR description

## Motivation

`/v1/score` accepts `return_token_logprobs=True` together with `score_extraction_token` (setwise scoring) for CausalLM models, but the raw label logprobs are silently dropped:

| Path | `token_logprobs` returned today |
| --- | --- |
| Pointwise | one row per item (correct) |
| Setwise, batched (default) | `[]` |
| Setwise, fused (`--enable-mis`) | `null` |

The scheduler already returns the per-anchor `input_token_ids_logprobs`; only result post-processing loses them:

- `_process_single_item_scoring_results` builds the setwise score matrix and `continue`s before recording the raw logprobs.
- `score_request` never forwards `return_token_logprobs` to `_process_multi_item_extraction_results`, which has no such parameter.

Even if the values were collected, `ScoringResponse.token_logprobs` is typed `List[List[float]]`, so the nested setwise shape would fail response validation.

## Modifications

- `tokenizer_manager_score_mixin.py`
  - New `_score_anchor_rows` helper used by both setwise CausalLM paths. Per anchor it converts label logprobs to scores (unchanged behavior) and, only when requested, also keeps the raw label logprobs, read the same way as the pointwise path.
  - `_process_multi_item_extraction_results` takes `return_token_logprobs`; `score_request` forwards it.
  - `ScoreResult.token_logprobs` is typed like `scores`.
- `protocol.py`: `ScoringResponse.token_logprobs` accepts the pointwise `[num_rows x num_labels]` shape or the setwise `[num_items][Nᵢ x num_labels]` shape, mirroring `scores` and `pooled_hidden_states`.
- Docs: `engine_score_mixin.py` docstring and `native_api.mdx` state that `token_logprobs` is shaped like `scores`.

Output shape follows the existing convention for `pooled_hidden_states` ("parallel to `scores`": flat for pointwise, one matrix per item for setwise). Pointwise responses and setwise responses without `return_token_logprobs` are unchanged.

## Tests

- `test_token_scoring.py::test_http_setwise_token_logprobs_follow_scores`: drives `OpenAIServingScore` → `score_request` → result processing for both batched and `--enable-mis`, with ragged per-item labels and items with 1 and 2 anchors. Only model execution is faked; the fake now returns position-dependent rows for setwise anchors, so misgrouped or reordered rows fail. It checks that each `token_logprobs` row equals the raw logprobs for that anchor and that `scores` equals `softmax(token_logprobs / T)`.
- `test_setwise_score_mixin.py::test_generation_setwise_token_logprobs_grouped_per_item`: both processors, label order differing from row order, and `None` when not requested.

On current `main`, the new tests fail (batched returns `[]`, fused returns `None` / rejects the argument). With the fix:
