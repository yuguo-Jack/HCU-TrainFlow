# [Perf] diffusion: Add each Wan block's FFN residual in the next block's norm1

[Upstream PR](https://github.com/sgl-project/sglang/pull/46245) · state: closed · merged: False

## Original PR description

Stacked on #46244 (fused q/k/v GEMM) and #46228; review the commits after #46244.

## Motivation

A Wan block ends with `MulAdd` (`hidden + ff_output * c_gate`) and the next block starts with `norm1` over that sum: the residual stream is written by one kernel and read straight back by the next. At 720p on 4xB300 (37800 x 5120 per rank) the pair takes ~0.43 ms of every block inside the denoising loop (MulAdd 0.19 ms + norm1 0.23 ms), against ~0.30 ms for the CuTe residual norm that does both (it already serves the self- and cross-attention residuals).

## Modifications

`models/dits/wanvideo.py`:
- `WanTransformerBlock.forward(..., ffn_residual=None, defer_ffn_residual=False)`: with `defer_ffn_residual` the block returns `(hidden_states, (ff_output, c_gate))` instead of adding the residual; with `ffn_residual` its norm1 is `ffn_residual_norm1` (a `ScaleResidualLayerNormScaleShift` without affine), which writes `hidden + gate * ff_output` and the modulated LayerNorm of it in one kernel. `chains_ffn_residual` is true only when MulAdd, norm1 and that norm run their CUDA kernels.
- `WanTransformer3DModel.forward`: chains the blocks when they are all plain `WanTransformerBlock`s in a plain `nn.ModuleList` (no instance-level `forward`, so a cache adapter or another block type keeps the one-block-at-a-time contract); the last block adds its own residual.

The residual the fused norm writes equals MulAdd's output bit for bit (both fuse the multiply-add in fp32 before rounding to bf16), and the norm reads that same bf16 sum, so every block output keeps its bits.

## Accuracy Tests

- `test_model_fast_paths.py::test_wan_chained_blocks_match_blocks_one_by_one` (Wan section): three Wan blocks (5120, 40 heads) chained give the same bits as the blocks run one by one.
- MulAdd vs the CuTe residual output on `[1, 37800, 5120]` bf16 with an fp32 gate: bitwise equal.
- Wan2.2 T2V A14B 720p, 4xB300, 3-step lossless (crf 0) mp4: md5 identical to the base for 3 prompts.

## Speed Tests and Profiling

Wan2.2 T2V A14B 720p, 4xB300, harness single_e2e (fresh server per run, runs interleaved with the other arms): base (fused QKV, #46244) 90.034 / 90.105 / 90.143 s (mean 90.094) -> 90.001 / 90.030 / 89.963 / 90.032 s (mean 90.007), -0.09 s (-0.10%).
