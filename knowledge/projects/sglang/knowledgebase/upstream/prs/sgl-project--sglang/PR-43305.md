# [Feat] [Ascend] glm5: Support GLM-5.3-Flash on Ascend A3/A5

[Upstream PR](https://github.com/sgl-project/sglang/pull/43305) · state: open · merged: False

## Original PR description

> Co-authors: @IceShip423 @stellaxcpeng @cen121212 @WayneLuo-HW @ranjiewen

## Motivation

GLM-5.3-Flash is a Z.ai hybrid-attention MoE VLM that interleaves MLA + DSA
(DeepSeek Sparse Attention) with linear attention and ships a built-in MTP head
for NEXTN speculative decoding. This PR ports the Ascend NPU adaptation
(Atlas A3/A5, developed on an internal fork, commits 1c76e6a01d..47594f8e1)
onto current upstream main (8854857a99), so the model can be served with SGLang
on Ascend clusters with PD disaggregation and speculative decoding.

## Modifications

- DSA attention backend and indexer kernels on NPU
  (`hardware_backend/npu/attention/ascend_dsa_backend.py`,
  `layers/attention/dsa/kpool_index_npu.py`, `kpool_bf16_index.py`,
  `kpool_lightning_indexer.py`, `kpool_decode_prepare_indexer.py`,
  `expand_pool_topk_and_append_tail_batched_npu.py`): Ascend DSA backend,
  lightning indexer, bf16/decompress kpool index kernels, decode-prepare
  indexer, and batched topk-pool tail expansion.
- Compress-tail state in the NPU MLA pool
  (`hardware_backend/npu/memory_pool_npu.py`): per-request DSA compress-tail
  k/score rings in `NPUMLATokenToKVPool`, with global indexer layer ids exposed
  for transfer pairing.
- PD disaggregation for hybrid DSA
  (`disaggregation/utils.py`, `disaggregation/ascend/conn.py`,
  `disaggregation/mooncake/conn.py`): target+draft DSA tail registration and
  merge, PP window slicing of tail pointers, and live-token remap between rings
  with different speculative slot counts.
- NEXTN speculative decoding on NPU
  (`kernels/ops/mamba/causal_conv1d_target_verify.py`,
  `kernels/ops/speculative/spec_tree_npu.py`,
  `kernels/ops/speculative/cache_locs.py`,
  `speculative/draft_utils.py`, `speculative/eagle_utils.py`): target-verify
  conv1d update kernel, NPU spec-tree kernels, and draft runner integration.
- MoE and quantization
  (`hardware_backend/npu/quantization/moe_methods.py`,
  `layers/quantization/modelslim/modelslim.py`, `layers/quantization/fp8.py`,
  `layers/moe/token_dispatcher/deepep.py`): ModelSlim W8A8 serving paths, A5
  (arch 3510) detection, and DeepEP token-dispatcher hooks.
- Multimodal preprocessing on NPU
  (`hardware_backend/npu/modules/glm5_next_processor.py`,
  `hardware_backend/npu/modules/glmga_processor.py`,
  `multimodal/processors/base_processor.py`).
- Portability fixes onto the new upstream layer-boundary architecture
  (`model_executor/model_runner.py`, `managers/scheduler_pp_mixin.py`,
  `kernels/ops/attention/fla/chunk_delta_h.py`): PP proxy scattered-boundary
  queries re-expressed on the new `layer_boundary` declarations (the legacy
  `layers.communicator` module is gone), legacy cfg-flag migration, and a
  triton-ascend workaround for the missing `constexpr and runtime-condition`
  short-circuit in `chunk_delta_h`.
- Tests (`layers/attention/dsa/test/*_npu.py`,
  `test/ascend/test_ascend_memory_registration.py`): unit tests for the kpool
  NPU kernels (assemble-softmax-write-cache, decode compress-and-write-cache,
  MTP flow, tail scatter updates, lightning indexer accuracy).

## Accuracy Tests

Validated end-to-end on a two-node Atlas A3 cluster (32 dies) with
GLM-5.3-Flash-W8A8 (ModelSlim quantized weights):

- Prefill/decode disaggregation with the Ascend transfer backend
  (prefill tp=16, decode tp=16 dp=16, DeepEP normal mode).
- NEXTN speculative decoding on the decode side
  (`--speculative-algorithm NEXTN --speculative-num-steps 3
  --speculative-eagle-topk 1 --speculative-num-draft-tokens 4`), including
  DSA compress-tail state transfer for target + draft layers.
- Server bring-up, generation correctness, and DSA state/kv transfer pairing
  across heterogeneous attention-TP topologies.

A5 (950PR/DT, arch 3510) code paths are included but not yet hardware-validated;
they are guarded by device/arch detection (`is_npu_a5` / `is_npu_arch35`) and
fall back to the A3 path.

- IceShip423 · comment · 2026-10-25T04:05:06Z · [source](https://github.com/sgl-project/sglang/pull/43305#discussion_r4369588503)

File: `python/sglang/srt/models/glm5_next.py` · line None

Delete the error raise checkpoint.

Scope clarification: `visual_seen - visual_matched` detects visual checkpoint entries that were encountered but did not resolve to a model parameter. It does not detect required visual parameters whose weights are entirely absent from the checkpoint, because those names never enter `visual_seen`. Consequently, the error message's claim that parameters would remain randomly initialized is not established by this check alone; an unmatched entry could also be an extra checkpoint key.

This is not a uniform convention across existing vision models: the full-model loaders in `glm4v.py`, `qwen2_5_vl.py`, and `qwen3_vl.py` have paths that silently skip unmatched visual names. Some skipping is intentional for pipeline stages or encoder/language-only configurations. The shared `AutoWeightsLoader` instead raises for unexpected names unless explicitly allowed, but that is also distinct from checking missing checkpoint weights.
