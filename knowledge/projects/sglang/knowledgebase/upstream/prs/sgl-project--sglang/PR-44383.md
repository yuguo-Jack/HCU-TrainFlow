# [CI] runners: Isolate CI runners that share one host

[Upstream PR](https://github.com/sgl-project/sglang/pull/44383) · state: open · merged: False

## Original PR description

## Motivation

The RTX 5090 CI pool (`1-gpu-5090`) is down. The replacement 8x RTX 5090 machines come from vast.ai, and a standard vast.ai instance is itself an unprivileged Docker container, with `CAP_SYS_ADMIN` and `CAP_NET_ADMIN` removed. So we can't run the usual layout of one Docker container per GPU. The fallback is 8 runner processes in one container, each pinned to one GPU with `CUDA_VISIBLE_DEVICES`.

A trial run of that layout failed 52 of 52 jobs, all in Install dependencies, because the runners shared state that is normally private to each container:

- `/root/.rustup`: concurrent toolchain installs left `cargo` missing (18 jobs)
- the dpkg frontend lock (6 jobs)
- the kept venv `/opt/sglang-ci-py3.12`, which concurrent installs `rm -rf` and rebuild (3 jobs)

Two more problems would show up once tests run:
- `killall.py` kills every sglang process in the shared `/proc`, including other runners' test servers.
- The `/dev/shm` sweep unlinks other runners' live `cuda.shm.*` and `nccl-*` segments.

## Modifications

Opt in by setting `SGLANG_CI_SHARED_HOST=true` in each runner's environment. Then:
- Each runner gets its own Rust (`CARGO_HOME`, `RUSTUP_HOME`) and uv-managed Python (`UV_PYTHON_INSTALL_DIR`, `UV_PYTHON_BIN_DIR`) under `/opt/sglang-ci-runners/$RUNNER_NAME`. These are exported to later steps.
- The kept venv moves to `/opt/sglang-ci-runners/$RUNNER_NAME/venv-py3.12`.
- The `/dev/shm` sweep skips the segment families that have no owner PID in their name.

Always on, and uncontended on a single-tenant runner:
- Host-wide installs run under one `flock` (`/tmp/sglang-ci-host.lock`). This covers apt (apt packages, the nvidia-dkms repair, GDRCopy, protoc, zstd), the system pip/uv bootstrap, and the `/usr/local` and `/opt/gdrcopy` installs.
- `killall.py` skips sglang processes whose `RUNNER_NAME` differs from its own. In a per-runner container every process has the same runner name, so nothing changes there.

Caches (uv, Hugging Face, JIT kernels, cargo target) stay shared, as they already are across the per-GPU 5090 containers, which all mount one `/opt/ci-cache`.

**The second commit is temporary.** `[DO NOT MERGE] Route 5090 jobs to the 1-gpu-5090-vast runners` sends this PR's 5090 jobs to the vast.ai runners so the isolation can be checked on real hardware. It will be dropped before merge.
