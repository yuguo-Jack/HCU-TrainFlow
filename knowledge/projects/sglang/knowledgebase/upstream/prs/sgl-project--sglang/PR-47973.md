# [Fix] attention: Use int64 token offsets in layernorm_gated and fused_qk_rmsnorm_rope_gate

[Upstream PR](https://github.com/sgl-project/sglang/pull/47973) · state: open · merged: False

## Original PR description

## Motivation

Two Triton kernels used by Qwen3.5 / Qwen3-Next compute token offsets from an int32 `tl.program_id(0)`. With Qwen3.5-4B layouts, the offset exceeds 2^31 at >= **174,764 tokens** in `_layer_norm_fwd_1pass_kernel`, and at >= **209,717 tokens** in `_fused_qk_rmsnorm_rope_gate_kernel`. Wider models hit it sooner: about 131K tokens for Qwen3.5-27B. Past that, the kernel faults with `an illegal memory access was encountered`, or silently returns wrong values.

Chunked prefill normally hides this. However, for noncausal decision models (e.g. [`pplx-decider-v1.1-27b`](https://lmsysorg.mintlify.app/cookbook/autoregressive/Perplexity/PPLX-Decider-v1.1-27B)), chunked prefill is disabled, so long prompts hit this.

## Modifications

- Cast the program id to int64 in both kernels
- Corresponding unit tests which can reproduce the 2 issues, and pass after the fixes

## Accuracy Tests

Outputs are bitwise identical below the overflow point. On 1xH100:

| | main | this PR |
|---|---|---|
| pplx-decider-v1.1-27b, 125,684 tokens | correct | correct |
| pplx-decider-v1.1-27b, 139,965 tokens | server crashes | correct |

The end-to-end run used `--quantization fp8` so a 140K prefill fits on one H100. Activations and kernel layouts are unchanged.

## Speed Tests and Profiling

1xH100, Qwen3.5-4B layouts, µs:

| T | gated norm main / PR | fused QK main / PR |
|---|---|---|
| 1,024 | 53.9 / 55.0 | 31.9 / 32.0 |
| 8,192 | 86.9 / 87.0 | 204.8 / 205.0 |
| 131,072 | 1,269.8 / 1,269.9 | 3,213.1 / 3,219.3 |

Tested on a v0.5.22 build with main's sources; both kernels are unchanged between v0.5.22 and main.
