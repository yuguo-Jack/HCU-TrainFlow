# [Fix] deepgemm: Handle missing CUDA toolkit during availability checks

[Upstream PR](https://github.com/sgl-project/sglang/pull/48140) · state: open · merged: False

## Original PR description

## Motivation

DeepGEMM raises `AssertionError` during import when `find_cuda_home()` cannot locate a CUDA toolkit. Both availability probes currently let this escape into model imports, leaving the model registry empty even for architectures such as Qwen2 that do not require DeepGEMM.

Refs #48080. This addresses the optional-import failure only; it does not change registry loading or startup performance.

## Modifications

- Treat import-time `AssertionError` as an unavailable optional dependency in both the SM120/121 API probe and the general DeepGEMM probe.
- Add CPU regressions covering the failing import and a working installation, with mocked SM90/100/120/121 detection.

## Accuracy Tests

- **14 targeted CPU tests passed:** the new availability tests, existing DeepGEMM UE8M0 requantization tests, and model-registry tests. The new regression fails on unmodified `40a64e1b` for all four SM cases.
- **H100, `sgl-deep-gemm==0.2.5.post3`:** unsetting CUDA paths, removing `nvcc` from `PATH`, and hiding `/usr/local/cuda` reproduced the actual DeepGEMM assertion. Registry entries changed from **0 before the fix to 231 after**, including Qwen2 (292 with the toolkit available).
- **Separate fallback smoke test:** with the toolkit available for other kernels, injecting a DeepGEMM import assertion still allowed `Qwen/Qwen2.5-0.5B-Instruct` BF16 inference. Two greedy generations matched the normal-installation outputs. Used Triton attention, PyTorch sampling, and the Python radix-tree backend.
- **Positive control:** DeepGEMM remained enabled with a working installation; its BF16 GEMM matched PyTorch on H100.

The fix does not make inference toolkit-free: a cold Qwen2 launch without the toolkit still needs NVCC to compile its RoPE kernel. Models that directly require DeepGEMM also remain subject to that dependency.

## Speed Tests and Profiling

Not applicable: only optional-dependency import error handling changes.
