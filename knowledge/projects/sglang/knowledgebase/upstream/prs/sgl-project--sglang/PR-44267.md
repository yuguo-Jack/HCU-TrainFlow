# [Perf] [AMD] qwen3: Fuse QK-norm + RoPE + KV cache write for dense Qwen3 decode

[Upstream PR](https://github.com/sgl-project/sglang/pull/44267) · state: closed · merged: True

## Original PR description

Follow-up to #44266, which fixed the KV cache write of the same fused path for Qwen3-VL (3D mRoPE).

## Motivation

On ROCm with `SGLANG_USE_AITER=1` (the default in the ROCm images), every decode layer of dense Qwen3 runs QK-norm, RoPE and the KV cache store as four small kernels of about 4.5 µs each. GPU kernel time in one Qwen3-8B decode step at batch 8 on MI355X (36 layers), from a torch profiler trace:

| Kernel | Baseline launches | Baseline time | This PR launches | This PR time |
|---|---|---|---|---|
| `aiter::add_rmsnorm_quant_kernel` (q_norm, k_norm) | 72 | 319 µs | 0 | 0 |
| `rotary_embedding_kernel` | 36 | 165 µs | 0 | 0 |
| `sglang::store_kvcache_kernel` | 36 | 164 µs | 0 | 0 |
| `mrope_utils::fused_mrope_rms_kv_kernel` (1D instantiation) | 0 | 0 | 36 | 156 µs |
| **Total** | **144** | **648 µs** | **36** | **156 µs** |

The fused kernel does the same work in one launch per layer, 0.49 ms less GPU time per step at batch 8. `qwen3.py` already uses it for 3D mRoPE (Qwen3-VL); dense Qwen3 uses 1D RoPE and never reached it, and `apply_qk_norm`'s fused path is CUDA-only.

## Modifications

- `aiter_fused_qk_norm_rope_set_kv` dispatches on the rotary type: `MRotaryEmbedding` keeps `fused_qk_norm_mrope_3d_cache_pts_quant_shuffle`, plain `RotaryEmbedding` uses `fused_qk_norm_rope_cache_pts_quant_shuffle`. Both share the NHD cache views and the cached `cos_sin_cache` cast from #44266.
- `Qwen3Attention.use_fused_qk_norm_rope` enables the 1D kernel only for exactly `RotaryEmbedding` (YaRN / NTK / linear-scaling subclasses keep the unfused path), full-width rotary, head sizes the kernel is instantiated for (64/128/256/512), and a single eps for both norms. The decode-only, NHD-only, activation-dtype-only conditions from #44266 apply unchanged, so prefill, speculative verify, FP8 KV cache and non-NHD layouts keep the unfused path.
- The unit test gains the 1D case: Qwen3-8B head layouts at TP1 and TP4, 1–256 tokens.

Numerics: the unfused HIP RoPE kernel already converts the fp32 `cos_sin_cache` to the activation dtype before rotating (`test/registered/rotary/test_rope_rocm.py` asserts equality with `cos_sin_cache.to(dtype)`), so reading a bf16 table here does not change RoPE precision. The norms are computed in fp32 inside the kernel.

Besides `Qwen3ForCausalLM`, the path is reached by multimodal models whose language model is `Qwen3ForCausalLM` (InternVL, Intern-S1, MiniCPM-V, LightOnOCR, Step3-VL-10B, Qwen3-ASR); those were not benchmarked here.

## Accuracy Tests

MI355X (gfx950), ROCm 7.2.0, torch 2.9.1, Triton 3.7.0, transformers 5.19.0, `SGLANG_USE_AITER=1`, default server args (attention backend resolves to `aiter`, decode CUDA graphs on). Baseline is `3b72b70ef4` with #44266 applied; this PR is measured on top of it.

**Unit test.** `test/registered/amd/test_qwen3_aiter_fused_qk_norm_rope.py`: 3 passed, 16 subtests passed.

**GSM8K**, `python -m sglang.test.run_eval --eval-name gsm8k --num-examples 1319 --max-tokens 4096` (chat API, greedy):

| Model | Baseline | This PR |
|---|---|---|
| Qwen3-8B | 0.944 | 0.946 |
| Qwen3-14B-FP8 | 0.955 | 0.957 |
| Qwen3-0.6B | 0.635 | 0.626 |
| Qwen3-8B, `--kv-cache-dtype fp8_e4m3` (unfused path on both) | 0.947 | 0.948 |

The standard error of one run is about 0.006 for the 8B / 14B rows and 0.013 for 0.6B, so every gap is within one standard error. With `--kv-cache-dtype fp8_e4m3` the decode trace of this PR contains `rotary_embedding_kernel` and no fused kernel, confirming the fallback.
