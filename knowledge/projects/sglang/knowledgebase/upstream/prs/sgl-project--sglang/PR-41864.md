## Original PR description

# [AMD][GLM-5.3-Flash] Allow shared experts fusion on gfx942 (MI308X)

## Motivation

`Glm5NextForConditionalGeneration.shared_experts_fusion_disable_reason` gates the HIP path behind `_use_aiter_gfx95`, so on gfx942 (MI308X / MI325X, CDNA3) the fusion is refused even when `--enforce-shared-experts-fusion` and `SGLANG_USE_AITER=1` are set.

The gate is stricter than the execution path requires. Everything the fused shared-expert slot actually runs through keys off **`_use_aiter` (HIP + AITER), not off the arch**:

- TopK expansion: `layers/moe/topk.py` fuses `num_fused_shared_experts` via `jit_grouped_gate(..., topk + num_fused_shared_experts if _use_aiter else topk, ...)`
- MoE execution: the AITER MoE runner consumes the expanded slot identically on both arches
- The gfx950-only pieces on this path (`_use_aiter_bpreshuffle_gfx95` scale plumbing, smallM gfx950 kernel, gfx95 `gate_mode`) are side optimizations the fused slot does not depend on

So this PR lifts the gate to also admit gfx942 via a new `_use_aiter_gfx942` flag, mirroring how #36576 handled the MiniMax-M3 equivalent on ROCm (that PR covered `minimax_m3*.py` only; the GLM gate is a separate per-model classmethod and was left at gfx950-only).

## Changes

- `python/sglang/srt/models/deepseek_common/utils.py`: define `_use_aiter_gfx942 = _use_aiter and is_gfx942_supported()`
- `python/sglang/srt/models/glm5_next.py`: HIP gate now `(_use_aiter_gfx95 or _use_aiter_gfx942)`; error message updated

Everything else in the gate (TP4/TP8 only, no MoE A2A backend, GLM-5.3-Flash expert geometry E=288/topk=8, clamped SiLU, serialized dynamic 128x128 block-FP8) is kept unchanged — those constraints were all exercised by the validation below.

## Validation

### Environment (identical across both arms)

| Item | Value |
|---|---|
| Hardware | 8x AMD Instinct MI308X (gfx942, CDNA3, 192 GB), TP=4 @ GPU 0-3 |
| Server build | SGLang v0.5.20-rocm720-mi30x nightly `20260927` (commit `a0ba1968b1`), ROCm 7.2.0 |
| Model | ZhipuAI/GLM-5.3-Flash, FP8 weights + `--kv-cache-dtype fp8_e4m3` |
| Common server args | `--tp-size 4 --enforce-shared-experts-fusion --enable-fused-qk-norm-rope --schedule-conservativeness 1.2 --context-length 524288 --kv-cache-dtype fp8_e4m3 --chunked-prefill-size 32768 --mem-fraction-static 0.72 --max-running-requests 128 --disable-radix-cache --moe-runner-backend aiter` + EAGLE 5/1/6 |
| ENV | `SGLANG_USE_AITER=1 SGLANG_USE_AITER_MHC=1 SGLANG_DSA_FUSE_TOPK=true HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1` |
| A/B variable | fusion ON vs OFF is the ONLY difference between arms (`--enforce-shared-experts-fusion` removed on the OFF arm; the rest identical, same host, same image) |

### Benchmark protocol

- Tool: SGLang `bench_serving`, random dataset with **ISL=8192 / OSL=1024 fixed** (`--random-input-len 8192 --random-output-len 1024 --random-range-ratio 1.0`)
- `--num-prompt = concurrency x 10`, `--max-concurrency = {1,2,4,8,16,32,64}`, `--seed 42`, greedy (`temperature 0.0`), radix cache **disabled** on the server so no prefix-hit interference
- Total = input + output aggregate (4-GPU sum); each row is a full fresh-container run of 10..640 requests

### Results (EAGLE 5/1/6 arms, fusion OFF vs ON)

| Concurrency | Total tok/s OFF | Total tok/s ON | Δ |
|---|---|---|---|
| 1 | 984.5 | 1473.0 | **+49.6%** |
| 2 | 1766.7 | 2547.3 | +44.2% |
| 4 | 2830.2 | 3391.0 | +19.8% |
| 8 | 4153.6 | 4869.2 | +17.2% |
| 16 | 4719.4 | 5469.5 | +15.9% |
| 32 | 5874.2 | 5991.3 | +2.0% |
| 64 | 6640.4 | 7132.7 | +7.4% |

- Single-stream TPOT 7.46 → **4.55 ms** (−39%), TTFT statistically unchanged (fusion touches only the MoE path; 1,596 vs 1,726 ms at c1)
- Correctness: needle retrieval at 8K context x 3 depths (greedy) all-hit; CUDA-graph vs eager token-level equality; a follow-up full 7-point sweep with fusion enabled (and a separate non-speculative arm) shows zero regressions vs the pre-fusion baseline
- The fusion gain is orthogonal to speculation: with EAGLE the fused slot amortizes the draft overhead, and the non-speculative arm shows the same directional win at c1 (+2.9% total, +1.47x decode measured earlier on this platform)

No CUDA behavior change (`_is_cuda` branch untouched); no gfx950 behavior change.
