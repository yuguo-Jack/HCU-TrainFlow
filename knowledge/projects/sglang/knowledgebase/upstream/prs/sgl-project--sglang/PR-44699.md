# [AMD] Use aiter pa_prefill_sparse for unified-KV sparse prefill on gfx1250

[Upstream PR](https://github.com/sgl-project/sglang/pull/44699) · state: open · merged: False

## Original PR description

## Motivation

On gfx1250 , the DSV4 unified-KV path (`SGLANG_HACK_FLASHMLA_BACKEND=unified_kv_triton`) already dispatches sparse **decode** to aiter `pa_decode_sparse`, but sparse **prefill** still falls back to SGLang's `_sparse_attn_v4_paged_prefill_triton`, because the aiter OPUS prefill (`_HAS_OPUS`) is gfx950-only. aiter ships a gfx1250 Gluon `pa_prefill_sparse` with exactly the same signature (two sources: prefix + extend, attention sink), so it can be used directly.

## Modifications

- `python/sglang/kernels/ops/attention/dsv4/unified_kv_kernels/paged_prefill.py`:
  - Import `aiter.ops.triton.attention.pa_prefill_sparse.pa_prefill_sparse` when available; enabled only on gfx1250 (`_HAS_AITER_GFX1250`).
  - In `sparse_attn_v4_paged_prefill`, after the OPUS branch, call `pa_prefill_sparse(...)` when `q`, `unified_kv` and `kv` share a bf16/fp16 dtype; otherwise keep the Triton fallback.
  - Opt-out via `SGLANG_DSV4_AITER_SPARSE_PREFILL=0` (default on).

## Accuracy

Kernel-level, DSV4-Pro shapes (H=128, D=512, topk=1024, SWA=128, bf16, 300k-page pool), aiter vs SGLang Triton:

| T | max_abs | max_rel | cosine |
|---|---|---|---|
| 512 | 1.95e-3 | 3.7e-3 | 0.999995 |
| 4096 | 3.91e-3 | 3.8e-3 | 0.999995 |

End-to-end (DeepSeek-V4-Pro, 4x MI455, TP4/DP4/EP4 + DP attention): needle-in-haystack PASS at 19.5k / 65k / 325k tokens.
