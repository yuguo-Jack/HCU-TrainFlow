# [Fix] attention: Migrate FLA Triton kernels off tl.make_block_ptr

[Upstream PR](https://github.com/sgl-project/sglang/pull/47944) · state: closed · merged: True

## Original PR description

Upstream Triton removed `tl.make_block_ptr`/`tl.advance` (triton-lang/triton#10833), breaking the FLA/KDA kernels on Triton builds without block pointers.

Following vllm-project/vllm#60502 (and upstream flash-linear-attention#1062), this replaces every block-pointer use with explicit pointer arithmetic plus masked `tl.load`/`tl.store`:

- 19 kernels / 226 call sites across the CUDA FLA kernels (`cumsum`, `chunk_o`, `l2norm` incl. GDN strided prepare, `wy_fast`, `fused_norm_gate`, `chunk_intra_token_parallel`, `chunk_delta_h`, `chunk_fwd`, `kda`, `chunk_intra`) and the XPU copies.
- Masks reproduce `boundary_check` semantics; offsets are widened to int64 like block-pointer offsets were.
- Deletes the `triton_block_ptr_compat` shim and its imports — no shim is needed once no kernel uses block pointers.

Block pointers lowered to plain vectorized loads (not TMA), so this is behavior-equivalent by construction.

Test: per-kernel A/B against pre-port baselines on H100 (Torch 2.11 + Triton 3.9) — bit-exact for all kernels, both normally and with `tl.make_block_ptr` deleted, incl. partial-chunk, strided, gated, fused/non-fused/safe-gate paths, plus an end-to-end `chunk_kda` smoke test. One exception: `kda` Aqk differs by at most 1 fp16 ulp because the autotuner picks a different `num_warps` for the ported sub-intra kernel (reduction reassociation). XPU kernels are compile-checked only (no XPU in the test env). `ruff check --select=F401,F821,F823,UP037` and `ruff format` pass.

**Issue**

`unlimited_ocr_dash` still uses `tl.make_block_ptr` at 6 sites (`attend.py` L173, L296, L403, L509, L518; `common.py` L71). On Triton 3.9, they compile on main only because this line patches `tl` for the whole process. This PR deletes the patch, so they break.

**Example**

Serve Unlimited-OCR v2 on a Triton 3.9 image such as `nightly-cu134`. On main, `ModelRegistry` imports `qwen3_next.py`, which imports `fla/fused_norm_gate.py`, which imports this shim. With this PR, the first DASH attend or split-K merge kernel fails to compile.

**Fix**

Port those 6 sites here, for example with `tile_ptrs_2d`/`tile_ptrs_3d` from `minimax_sparse/common/tile_ptr.py`. Or keep the shim until they are ported.

[by Claude Code] **Severity: perf | Confidence: Medium**

**Issue**

The port removed the 1-D `m_k = o_k < K` that this `STORE_KG` load used. The load now takes the 2-D `[BT, BK]` `m_k` from line 563. Triton broadcasts the `[BK]` pointer to the mask shape, so `b_gn` becomes a full tile that reloads the same `last_idx` row BT (64) times. Results do not change, but each K block now does a third full-tile load next to `b_k` and `b_gk`.

**Why it matters**

This kernel runs on every KDA prefill with `B * NT * H > 256` (the unfused path in `chunk_kda_fwd`), so long prompts pay for it.

**Fix**

Use `mask=o_k < K` here.
