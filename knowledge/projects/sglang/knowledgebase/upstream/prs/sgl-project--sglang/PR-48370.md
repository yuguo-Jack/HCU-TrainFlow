# [Perf] gemma3: Fuse q_norm and k_norm into gemma_rmsnorm for rank above 2

[Upstream PR](https://github.com/sgl-project/sglang/pull/48370) · state: open · merged: False

## Original PR description

## Motivation

`Gemma3RMSNorm.forward_cuda` fuses only 2D input. q_norm and k_norm get `[tokens, heads, head_dim]` and fall back to the eager chain, 10 kernels per norm. This is the 3D follow-up hnyls2002 suggested on #21962.

## Modifications

Higher-rank input is flattened for `gemma_rmsnorm`, as `Gemma4RMSNorm` does. The gemma3_mm vision embedding norm also takes this path. The new test fails on `main`.

## Accuracy Tests

gemma-3-4b-it, GSM8K 400 questions, RTX 3090: main 0.750, this PR 0.740 (standard error about 2.2 points), invalid 0.000 on both. The fused output matches `forward_native` to one bf16 step.

```
python -m sglang.test.few_shot_gsm8k --num-questions 400 --parallel 64
```

## Speed Tests and Profiling

gemma-3-1b-it decode step, median of 3 alternating rounds, RTX 3090:

```
python -m sglang.benchmark.one_batch --batch-size 1 8 32 --input-len 256 --output-len 128
```

| batch | main ms | this PR ms |
|---|---|---|
| 1 | 5.65 | 4.94 |
| 8 | 5.88 | 5.27 |
| 32 | 6.75 | 6.13 |

gemma-3-4b-it serving, random 128 in and 128 out, median TPOT over 2 runs per arm: 12.70 to 11.85 ms at concurrency 1, 12.88 to 12.08 ms at 8. The q and k norm pair goes from 20 kernels to 4 per layer.
