# [Feat] PD: Publish spec_kv_layout so DSpark/DFlash prefill and decode must match

[Upstream PR](https://github.com/sgl-project/sglang/pull/48375) · state: open · merged: False

## Original PR description

## Summary

- Publish `spec_kv_layout` through the existing bootstrap `PUT /route` for DSpark/DFLASH draft KV carried in main entries: algorithm, `num_draft_entries`, and DSpark/DFlash block size.
- Keep the first non-`None` layout across prefill ranks in both Python and Rust registries, allowing draftless PP stages in either registration order and rejecting conflicting known layouts.
- Let decode opt in with `spec_kv_layout=1` and reject a mismatch only when both peers publish a layout. Older peers without the field retain existing behavior.

## Why

DSpark and DFlash materialize draft context KV during prefill from target hidden states. Decode cannot rebuild those bytes from transferred token metadata alone. Comparing the layout before registering a prefill destination catches target-only peers, different algorithms, different draft entry counts, and different block sizes before incompatible KV is consumed.

Ordinary PD, EAGLE, and NEXTN publish `{}` and gain no new checkpoint, TP, EP, PP, DCP, step-count, or draft-token-budget restrictions. DSV4 drafts carried only in state components retain legacy behavior; the existing DSV4.1 validation is unchanged.

## Validation

- H200 Qwen3-0.6B NIXL prefill/decode pair: **4/4 requests completed with `finish_reason=stop`**; legacy bootstrap responses omitted the field.
- Independent implementation and review passes found no remaining issues within the main-entry draft scope.
