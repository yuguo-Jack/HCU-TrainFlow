# [Perf] [AMD] dsv4: Token-parallel prefill on ROCm (opt-in)

[Upstream PR](https://github.com/sgl-project/sglang/pull/47888) · state: open · merged: False

## Original PR description

## Motivation

Under pure TP, every rank repeats the replicated per-token work of a DeepSeek-V4 layer for all T prefill tokens: the mHC mixing and both norms, the input projections (`wqkv_a`, both compressors' `wkv_gate`, the indexer `weights_proj`), the C4 indexer scoring (O(T x L) per layer), and the router. Only the attention heads and the MoE experts are sharded. In a one-rank profile of DeepSeek-V4-Pro at TP8 on 8x MI308X (gfx942), this repeated work was about 31% of the rank's prefill time for a 63K-token prompt.

Upstream's `attn_tp_input_scattered` does not cover this: it is gated to CUDA / NPU and needs `is_mhc or not is_dsa`, which DSV4 does not satisfy. #43065 shards the mHC boundary for V4.1 on CUDA only.

## Modifications

`SGLANG_DSV4_TOKEN_PARALLEL_PREFILL=1` (default off) keeps 1/tp of an extend batch's tokens on each rank:

- `DeepseekV4Model` scatters the `[T, hc_mult, hidden]` residual before the layer loop and all-gathers it after, so the mHC pre/post and the norms run on local rows.
- `MQALayer` runs `wqkv_a`, both `wkv_gate` and `weights_proj` on the local rows and all-gathers their narrower outputs; the compressors and the indexer take those instead of recomputing on full rows. Attention keeps its TP-sharded heads over all T tokens, and `wo_b` reduce-scatters back to the local rows.
- The C4 indexer builds queries, logits and top-k for this rank's query rows only (keys still cover all tokens), with a top-k v2 plan over those rows, and all-gathers the selected indices.
- The router (replicated) routes the local rows; the per-row top-k is all-gathered and handed to `DeepseekV2MoE.forward_normal(topk_output=...)`. The experts and the shared expert run on all tokens with the post-experts all-reduce left out (`mlp_reduce_scatter`), and the partial sums are reduce-scattered. `forward_normal`'s router moves into `_route()` so both paths share the ROCm fused gate.

`SGLANG_DSV4_TOKEN_PARALLEL_DSPARK=1` (default off; needs `SGLANG_DSV4_TOKEN_PARALLEL_PREFILL=1`) also admits DSpark capture. With DSpark on, every prefill captures the target's aux hidden states, so without this switch the feature never engages on DSpark deployments. Each captured layer's mHC stream mean is computed on the local rows and all-gathered into the draft's `AuxHiddenStatePacker` buffer, so the draft sees every token.

Per layer, two reduce-scatters plus the all-gathers replace the two all-reduces, so the communication volume stays about the same (by design; not profiled separately). The saving is compute.

Scope: anything else keeps today's path.

- ROCm other than gfx95 / gfx1250, which quantize the attention input inside the norm on full rows.
- `attn_tp_size == tp_size` (no DP attention or CP), no PP, no EP / a2a MoE.
- Eager extend batches of at least `SGLANG_DSV4_TOKEN_PARALLEL_MIN_TOKENS` (default 2048) tokens; no TBO, CUDA graphs or SP.
- No DSpark capture unless `SGLANG_DSV4_TOKEN_PARALLEL_DSPARK=1`.
- `model_type == "deepseek_v4"`, fused `wqkv_a`, TP-sharded shared expert.

The code lives in `models/deepseek_common/amd/deepseek_v4_token_parallel.py`; the hooks in `deepseek_v4.py`, `deepseek_v4_platform_stage.py`, `compressor.py`, `indexer.py` and `deepseek_v2.py` are a few lines each. Two commits: the first is the base feature, the second (`e3581f6d31`, 3 files, +20/-4) adds the DSpark switch.

## Setup

- Hardware and stack: 8x MI308X (gfx942), ROCm 10.0, torch 2.12, aiter at main's pin (285579b62), sgl-kernel built from main.
- Model: DeepSeek-V4-Flash with FP8 per-channel (PTPC) weights, TP4 on GPUs 0-3.
- Flags: `--attention-backend dsv4 --page-size 128 --chunked-prefill-size 16384 --max-prefill-tokens 32768 --mem-fraction-static 0.90 --disable-shared-experts-fusion --disable-radix-cache --disable-overlap-schedule`.
- Env: `SGLANG_HACK_FLASHMLA_BACKEND=unified_kv_triton SGLANG_DSV4_FP4_EXPERTS=0 SGLANG_USE_AITER=1`.
- DSpark runs add `--speculative-algorithm DSPARK --speculative-dspark-block-size 5 --speculative-draft-model-path <model> --decrypted-draft-config-file <model>/draft_blockscale_config.json --speculative-moe-runner-backend triton`.
- The same tree serves both arms. Off = token-parallel off; on = `SGLANG_DSV4_TOKEN_PARALLEL_PREFILL=1`, plus `SGLANG_DSV4_TOKEN_PARALLEL_DSPARK=1` in the DSpark runs.
- Tree: main `def8f93212` + this PR + #47886, plus #47887 for DSpark. They are only needed for this setup (without #47886 the checkpoint does not load on gfx942; without #47887 the draft's block-FP8 config is dropped); they share no code with this PR and merge in either order.
- Not yet run on `sgl-project/DeepSeek-V4-Flash-FP8`.

## Accuracy Tests

DSpark off:

| | off | on |
|---|---|---|
| gsm8k 8-shot, 1319 questions (flexible / strict) | 0.9401 / 0.9409 | 0.9447 / 0.9447 |
| gsm8k 8-shot, 200 questions | 0.97 | 0.97 |
| needle in a haystack, 8K-60K (12 cases) | 12/12 | 12/12 |

- Paired over the 1319 questions: 14 right -> wrong, 20 wrong -> right (sign test p = 0.39).

DSpark on (block size 5):

| | off | on |
|---|---|---|
| gsm8k 8-shot, 1319 questions | 0.9431 | 0.9454 |
| gsm8k 8-shot, 200 questions | 0.96 | 0.975 |
| needle in a haystack, 8K-60K (12 cases) | 12/12 | 12/12 |
| accept length, 4K c16, per pair | 5.10 / 5.53 / 4.56 | 5.12 / 5.52 / 4.57 |
| accept length, 30K c8, per pair | 5.22 / 5.54 / 4.69 | 5.24 / 5.53 / 4.69 |

- Paired over the 1319 questions: 13 right -> wrong, 16 wrong -> right (sign test p = 0.71).
- Accept length matches within every pair; it moves between server boots by the same amount in both arms.

Both modes:

- An earlier revision of this PR logged every token-parallel forward. It engaged in every on run (under capture in the DSpark runs) and never in the off runs, with no server errors in either.
- This revision drops that log and the gate checks that other conditions already imply. Re-checked on it (one run per arm without DSpark, one on-arm run with DSpark): gsm8k 200 0.96, needle 12/12, every perf point within 0.3% of the means below, DSpark accept length 5.13 / 5.25.
- Unit test: `test/registered/unit/layers/test_dsv4_token_parallel.py` (CPU, 3 passed) checks the row partition, the scatter / all-gather round trip and the reduce-scatter over an in-process 2-8 rank group.

## Speed Tests and Profiling

`sglang.bench_serving`, random dataset, fixed lengths, 2 warmup requests. Three paired runs per arm in off, on, on, off, off, on order; mean shown. Every point's min-max spread is at most 1.1% of its mean, except the DSpark off arm at 4K c16 (1037 / 1073 / 1071 tok/s, so that gain is +4.8% to +9.0% per pair).
