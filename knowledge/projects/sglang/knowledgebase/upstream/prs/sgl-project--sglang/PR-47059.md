# [Fix] sampling: Preserve a byte-length floor for string-stop matching

[Upstream PR](https://github.com/sgl-project/sglang/pull/47059) · state: closed · merged: False

## Original PR description

## Motivation

String-stop matching can miss a valid generated spelling when its tokenization is longer than the stop's canonical encoding. For example, Qwen3 encodes `AAA` as `[50107]`, while `[32,32,32]` decodes to the same `AAA`. With one accepted token per iteration, a canonical count of 1 plus the existing one-token margin searches only the last 2 tokens and never sees the complete stop.

This was observed with a short STANDALONE request: repeated token 32 output stopped correctly for `AA`, but `AAA` reached its length limit. The affected integration source matched public `5cbf949839b1fc73802d20670943ccbeb805d3f2`. Separately, the regressions below reproduce the missing-stop semantics using normal imports from public main `b85d6a8893d7b81f25ad69eb1c50eee068946d90`; this is not a claim of latest-main GPU service testing.

## Modifications

- Use `max(canonical token count, UTF-8 byte length)` for normalized string-stop lookback.
- Preserve the same byte floor in the Rust tokenizer worker rather than replacing it with a shorter canonical count. Keep a larger canonical count when applicable.
- Add sequential and cross-accept-group stop regressions, UTF-8 byte-fallback coverage, and normalization/no-stop/regex controls. Preserve existing first-match trimming, EOS and length behavior.

The scope is ordinary byte/character decompositions, including the demonstrated case. UTF-8 byte length is **not a universal bound** for arbitrary zero-width/ignored tokens or context-dependent decoder cleanup. No request lifecycle, scheduler, wire format, or regex matching algorithm changes; no full-history decoding is introduced.

## Speed Tests and Profiling

CPU method microbenchmark with the actual Qwen3 tokenizer: a static nonmatching 512-token output tail, `Req.update_finish_state`, median of 3 rounds of 10,000 calls. This measures bounded matching cost, **not server throughput, model generation, or GPU latency**.

| Stop | Original / patched decode tail | Original / patched median |
| --- | --- | --- |
| Disabled | No decode calls in either case | 9.39 / 8.21 ms (timing difference not interpreted) |
| `AAA` | 2 /4 tokens | 58.56 / 60.95 ms |
| 18 ASCII characters | 4 /19 tokens | 60.79 / 83.11 ms |

The longer stop adds about 2.23 µs per method call in this setup. Stop-enabled requests intentionally decode a larger bounded tail; the stop-disabled generation path adds no decode call.
