# [Fix] [AMD] kernels: Import the HIP launch helpers from jit.utils.hipcc in smallm_fp8_blockscale_gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/45676) · state: closed · merged: True

## Original PR description

## What
`smallm_fp8_blockscale_gfx950` imports its HIP build/launch helpers from `sglang.kernels.jit.utils.hipcc` (`check_hip`, `hip_lib`, `hipcc_path`, `HipKernel`) instead of the private names that no longer exist in `smallm_moe_gfx950`.

## Why
#45112 moved `_check`, `_hip_lib`, `_hipcc` and `_Kernel` out of `smallm_moe_gfx950` into `jit/utils/hipcc.py` under the new names. #42229 added this module against the old location and merged a day later, so importing it fails:

```
File ".../kernels/ops/gemm/smallm_fp8_blockscale_gfx950/__init__.py", line 10, in <module>
ImportError: cannot import name '_check' from 'sglang.kernels.ops.moe.smallm_moe_gfx950'
```

`aiter_w8a8_block_fp8_linear` imports it on gfx950, so FP8 block-scale dense linears fail there. Three tests in `stage-b-test-1-gpu-small-amd-mi35x` have failed with this since: `test_smallm_fp8_blockscale_gfx950.py`, `test_dsv4_dense_mxscale_gfx95.py` and `test_fp8_bpreshuffle_dense_linear_mi35x.py`. Example: https://github.com/sgl-project/sglang/actions/runs/39599109770/job/119218874753

The helpers are the same code under the new names; this is the change #45112 made to the sibling `smallm_fp8_gfx950`.
