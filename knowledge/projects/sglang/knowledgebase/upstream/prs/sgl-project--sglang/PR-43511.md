# [Feat] sgl-router: Add --dp-rank-policy round_robin for --dp-aware

[Upstream PR](https://github.com/sgl-project/sglang/pull/43511) · state: closed · merged: True

## Original PR description

## Motivation

With `--dp-aware`, a DP rank that no routing key or cached prefix decides goes to the rank with the fewest requests this router has in flight (#41974); in PD mode that is every decode rank. `sgl-model-gateway` offers `--decode-policy round_robin`, which is what PD deployments moving to `sgl-router` run today. Without a round-robin choice, such a deployment cannot reproduce its baseline, and least-in-flight cannot be A/B tested against round-robin inside the same router.

## Modifications

- `--dp-rank-policy {least_in_flight,round_robin}`, which requires `--dp-aware`. `least_in_flight`, the current behaviour, stays the default.
- It replaces only the last step of `select_dp_rank`: a sticky or session key and the deepest cached prefix still decide first, so a conversation keeps its prefill rank. `round_robin` takes a worker's ranks in turn from a per-worker cursor, over the tied ranks when several share the deepest prefix.
- `ModelConfig::dp_rank_policy`; the other `ModelConfig` literals take the default. README: DP-rank routing.

## Testing

- New `dp_rank_routing::round_robin_gives_decode_ranks_turns`: PD decode ranks come out 0, 1, 2, 3, 0, 1, 2, 3 (in random order without this change).
- Fake 1P1D workers with 8 attention-DP ranks each, `--policy sticky --routing-key-header X-SMG-Routing-Key --dp-aware --dp-rank-policy round_robin`, 256 streaming chats at concurrency 64 over 16 keys: every decode rank got exactly 32 requests, and each key stayed on prefill rank `sha256(key) % 8` with a matching `bootstrap_room % 8`.
- Passing: `cargo +nightly fmt --all -- --check`, `cargo check`, `cargo clippy -- -D warnings`, `cargo test --release --workspace -- --skip parity_matrix`.

## Benchmark (MI355X)

DeepSeek-V4-Pro, 1 prefill + 1 decode engine with 8 DP-attention ranks each, AgentX trace replay with AIPerf (multi-turn agentic sessions, 96% prefix-cache hit), 1 h per concurrency. Router `--policy sticky --routing-key-header X-SMG-Routing-Key --decode-policy power_of_two --dp-aware`, built at 1e86143bf0: `round_robin` with this change, `least_in_flight` without it (its default). Both arms used the same recipe, including prefill `--load-balance-method follow_bootstrap_room` (see #44072), and neither had request errors.

| 384 | 561.4 → 564.0 (+0.5%) | 7.59 → 8.25 | 31.01 → 32.13 | 19.80 → 19.14 (-3.3%) | 22.45 → 21.03 (-6.3%) |
| 512 | 599.8 → 589.9 (-1.7%) | 16.84 → 19.16 | 57.90 → 61.18 | 23.13 → 21.81 (-5.7%) | 25.50 → 24.16 (-5.3%) |

|---|---|---|---|---|
| 192 | 14.71 → 14.05 (-4.5%) | 14.6 → 12.8 | 0.22 → 0.15 | 0.17 → 0.05 |
| 256 | 16.87 → 15.70 (-6.9%) | 19.7 → 17.0 | 0.21 → 0.13 | 0.15 → 0.03 |
| 384 | 19.87 → 19.08 (-4.0%) | 28.3 → 25.8 | 0.17 → 0.13 | 0.10 → 0.02 |
| 512 | 22.77 → 21.45 (-5.8%) | 34.2 → 30.6 | 0.16 → 0.14 | 0.08 → 0.01 |

- `least_in_flight` keeps outstanding requests nearly even across decode ranks, which lowers the busiest rank's batch that every DP-attention decode step waits for. TPOT p50, TPOT p90 and the engine's own TPOT drop 3–8% at every concurrency, so `least_in_flight` stays the default and `round_robin` is for reproducing gateway baselines.
- TTFT is set by prefill queueing, which depends on how the benchmark's routing keys, random per run, hash onto prefill ranks. It varies as much between runs that differ only in decode policy: TTFT p50 at 384 ranges 8.07–9.32 s across four gateway runs.
- At 512 the two runs' prefill differed this way: `round_robin`'s run kept more requests decoding (217 vs 201 running on average), which raised its throughput and its TPOT alike. Per rank, busiest / mean running was 1.25 vs 1.21 (median over seconds).

### Per-rank decode load

Same two runs, from each decode rank's `Decode batch` log lines sampled every second; outstanding = running + waiting on KV transfer (prealloc, retracted and queue stayed 0). Stdevs are across the 8 ranks, p50 over the hour; busiest ÷ mean running excludes the first 5 min of ramp-up. `round_robin` → `least_in_flight`:

| conc | outstanding stdev (req) | waiting-on-KV stdev (req) | running stdev (req) | waiting ÷ outstanding | busiest ÷ mean running, p50 / p90 |
|---|---|---|---|---|---|
| 192 | 2.40 → 0.66 | 1.05 → 1.48 | 2.40 → 1.56 | 27% → 27% | 1.33 / 1.53 → 1.22 / 1.37 |
| 256 | 3.11 → 0.70 | 1.32 → 1.80 | 3.00 → 1.87 | 29% → 31% | 1.32 / 1.50 → 1.19 / 1.33 |
| 384 | 3.84 → 0.71 | 2.40 → 2.71 | 3.76 → 2.74 | 42% → 44% | 1.26 / 1.43 → 1.20 / 1.32 |
| 512 | 4.66 → 0.78 | 3.33 → 3.38 | 4.36 → 3.35 | 53% → 57% | 1.25 / 1.39 → 1.21 / 1.36 |

![Per-rank outstanding, waiting-on-KV and running requests at concurrency 512](https://raw.githubusercontent.com/AMD-yanfeiwang/sglang/pr-assets-sgl-router/sglr-c512-per-rank-outstanding-waiting-running.png)

![round_robin vs least_in_flight over the hour at concurrency 512](https://raw.githubusercontent.com/AMD-yanfeiwang/sglang/pr-assets-sgl-router/sglr-c512-over-the-hour.png)

- `least_in_flight` leaves almost no outstanding spread (stdev 0.66–0.78 requests, the floor for integer counts). But a rank's outstanding requests are either running or waiting for their KV from prefill, and the router cannot see which rank's transfers land first. The waiting share grows from 27% to 53–57% with concurrency, and under `least_in_flight` the running spread equals the waiting spread, so its lead in running CV shrinks from 32% at 192 to 14% at 512.
- No rank stays hot under `least_in_flight`: each rank's mean running batch is within ±3.3% of the 8-rank mean, and each is the busiest in 9–17% of seconds (12.5% if even). Under `round_robin` at 256, DP1 and DP5 were the busiest in 19.5% and 22.1% of seconds, with means 8% above the 8-rank mean.
- Neither policy's imbalance grows over the hour (10-minute medians of busiest ÷ mean stay flat after the ramp). `least_in_flight`'s outstanding CV is below `round_robin`'s in every post-ramp minute at 512, while its busiest ÷ mean is lower in 53 / 53 / 48 / 41 of 56 minutes at 192 / 256 / 384 / 512.
- `sgl-model-gateway`'s p2c on in-flight requests, measured the same way, reaches the same running spread (within 0.2 requests) and busiest-rank batch (within 4%) despite more outstanding spread (1.2–1.4 requests), so evening out in-flight counts further would not flatten the running batch.
