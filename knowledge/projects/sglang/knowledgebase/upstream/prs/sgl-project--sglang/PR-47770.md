# [Perf] DFlash: Use CUDA graphs for draft and idle verify under DP attention

[Upstream PR](https://github.com/sgl-project/sglang/pull/47770) · state: open · merged: False

## Original PR description

## Motivation

With `--attn-dp-size > 1`, DFlash keeps the draft eager on every device, and any DP round with an idle rank falls back to eager target verify on all ranks.

Eager execution drops most of the DFlash speedup. A drafted block of tokens only pays off when draft and verify are cheap per step, and eager launch overhead dominates at small batch sizes, which is where DP ranks go idle. On base main, at concurrency 1 (an idle rank in every round), the 27B DFlash2 pair outputs 24.81 tok/s at 38.96 ms median TPOT; with graphs it outputs 210.43 tok/s at 4.12 ms (see Speed Tests).

Neither fallback is required. The draft runs attn-TP-local (`draft_tp_context`) with no cross-DP collective, so each DP rank can replay its own draft graph keyed by local batch size, as the DSpark dense draft already does. For verify, this PR follows DSpark's idle-rank handling: the idle rank runs a dummy verify padded to the same graph bucket as the active ranks, so all ranks replay the verify graph and the DP-gather offsets agree.

## Modifications

- `DecodeCudaGraphRunner._forward_is_dp_local` returns True for the DFlash draft runner, so draft graphs are keyed by local batch size, as for the DSpark dense draft. Without this, the hand-built draft batch has no `original_global_num_tokens_cpu` and DP replay rejects it.
- `DFlashWorkerV2.init_cuda_graphs`: on CUDA, capture the draft decode graph under DP attention. Non-CUDA devices keep the eager draft.
- Idle DP rank verify: on CUDA, stop forcing eager. The idle rank and the active ranks pick the same padded bucket from the gathered max DP batch, so DP-gather offsets agree. `can_run_cuda_graph` is propagated from the idle verify result.
- The active-rank idle-DP guard (eager verify when any DP rank has 0 tokens) is now NPU-only, matching NPU idle ranks, which still verify eagerly.
- The mixed prefill/verify round guard is unchanged.
- Docs: update the "DFlash and DFlash2 with DP attention" section.
- Unit tests in `test/registered/unit/spec/test_dflash_dp_attention.py` cover the draft graph policy per device, local-batch graph keying, and idle-rank verify graph vs eager per device.

## Speed Tests and Profiling

Tested commit e4283151a6cd7b992756219a5150bf4174823ee1 against base main e2982985110fb432fd8ddba5f0147a5004fd03ab, same server flags and the same machine.

GPU: 4 × NVIDIA B30Z (SM103), `Qwen/Qwen3.8-27B` target with `incoai/Qwen3.8-27B-DFlash2` draft, TP4 / attention DP2. `bench_serving` on ShareGPT, output length 256, seed 42, 2 warmup requests, `num-prompts >= 5 * max-concurrency`:

| 2 | 16 | 190.98 → 386.00 | 2.02x | 7.88 → 4.65 | 283.81 → 145.74 | 3.36 / 3.36 |

At concurrency 1, every DP round has an idle rank. On main, that round runs both the draft and target verify eagerly on all ranks. With this change, both replay CUDA graphs. Accept length is unchanged, so the gain comes from graph replay, not from different drafts. On main, the server logged "Disable DFLASH draft cuda graph because dp attention is enabled" and 32 decode batches with `cuda graph: False`. With this change, the draft graph was captured for bs 1-16 (0.28 GB per rank) and every decode batch logged `cuda graph: True`.
