# [Fix] Track partial weight updates per runner

[Upstream PR](https://github.com/sgl-project/sglang/pull/42561) · state: open · merged: False

## Original PR description

## Motivation

A weight-update session can load only a subset of its runners, or load the target successfully before a draft runner fails. The session currently records one `loaded_weights` flag only after the entire fan-out succeeds. Consequently, `end_weight_update()` can run a completed runner's `post_load_weights()` twice, or skip the fixup for a runner whose load was bypassed. A failed draft load also prevents flushing KV entries computed with the old target, even though the target's weights have already changed.

For example, after `begin_weight_update(selector="all")`, a successful target load followed by a rejected draft load must preserve the target's completed fixup and invalidate its old KV cache, while still finalizing the unloaded draft. The same bookkeeping is needed for independently loaded target/draft roles and multiple draft steps.

## Modifications

- Record successfully loaded roles as an immutable set in the session, accumulating across update calls.
- Finalize each runner according to its own load state.
- Flush the requested cache in `finally` when the target loaded successfully, including a later draft rejection or exception. Preserve success-only weight-version advancement and successful draft-only cache-flush behavior.
- Extend the existing registered CPU tests with observable model-buffer values and cache contents. The fixture uses the real `WeightUpdater.end_weight_update()` and controls the transport/loader boundary.

Related PRs #34495, #35403, and #41359 were inspected; they address draft synchronization/enumeration and backend reload transformations rather than this scheduler session bookkeeping.
