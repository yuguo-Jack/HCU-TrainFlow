# [Fix] function_call: Normalize GLM non-streaming tool names

[Upstream PR](https://github.com/sgl-project/sglang/pull/46053) · state: open · merged: False

## Original PR description

## Motivation

Fixes #45953.

GLM non-streaming tool-call parsing can silently drop a defined tool when the captured function name contains surrounding whitespace. A GLM-4.7/5 response such as `<tool_call>get_weather` followed by a newline and its argument tags is rejected as an unknown function; both `tool_calls` and visible content can be empty. GLM-4.5/4.6 has the same inconsistency for names with leading/trailing spaces, tabs, or CRLF headers. Both streaming paths already normalize function names.

This PR consolidates the GLM-4.7/5 fix from #45962 with the independently reproduced GLM-4.5/4.6 fix.

**Confirmed root cause (parser-level reproduction):** Both non-streaming detectors pass the untrimmed function-name capture into argument-schema lookup and `parse_base_json`. The latter matches registered tool names exactly, so a name such as `get_weather\n` or `get_weather ` is treated as undefined and skipped. The tool-call span has already been consumed from visible content, which explains the empty response. Normalizing the captured identifier before these lookups resolves the reproduced failure while preserving argument-value whitespace.

## Modifications

- Strip surrounding whitespace from function names in both `Glm4MoeDetector` and `Glm47MoeDetector` before argument-schema lookup and tool validation.
- Add GLM4 regression coverage for name whitespace and actual/literal newline separators, asserting that argument-value whitespace is preserved.
- Include the GLM47 newline regression from #45962, which exercises non-streaming and several streaming chunk sizes.
- Use `CustomTestCase` for the two modified regression test classes.
