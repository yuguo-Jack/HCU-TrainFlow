# fix: replace eval() with safe AST-based expression evaluator in dumper filter

[Upstream PR](https://github.com/sgl-project/sglang/pull/44205) · state: closed · merged: False

## Original PR description

## Background

Fixes #44188

## Problem

`_evaluate_filter()` in `dumper.py` used `eval(filter_expr, {"__builtins__": {}}, namespace)` to evaluate caller-supplied filter expressions. Although `__builtins__` was set to an empty dict, the exposed `re.search` and `re.match` function objects (`search` and `match`) retain `__globals__` attributes that lead back to the real builtins mapping.

An attacker with ordinary API key access can chain `search.__globals__[__builtins__][__import__](os).system(...)` to achieve arbitrary code execution in the scheduler process.

## Fix

Replaced `eval()` with a strict AST-based expression evaluator (`_safe_eval_node`) that:

1. Parses with `ast.parse(mode="eval")`
2. Only allows whitelisted node types: `Constant`, `Name`, `Attribute` (blocks dunders), `Subscript`, `Call`, `Compare`, `BoolOp`, `BinOp`, `UnaryOp`, `Tuple`, `List`
3. Blocks all dunder attribute access (prevents `__globals__`, `__class__`, `__subclasses__`, etc.)
4. Wraps `re.search`/`re.match` in `_SafeRegexWrapper` that blocks attribute access entirely (except Python protocol dunders)
5. Blocks all attempts to call whitelisted builtins (`__import__`, `exec`, `eval`, `open`) — they are not in the allowlist

## Security Model

```python
# ATTACK BLOCKED:
search.__globals__["__builtins__"]["__import__"]("os")  # ValueError
__import__("os").system("...")                            # ValueError
exec("import os")                                          # ValueError
search.__class__.__bases__[0].__subclasses__()              # ValueError

# NORMAL USE PRESERVED:
layer_id > 3 and layer_type == "mlp"                       # works
search(r"test", "some_string")                            # works
missing_tag is None                                         # works (resolves to None)
```
