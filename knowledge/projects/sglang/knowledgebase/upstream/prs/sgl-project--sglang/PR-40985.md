# [Sampling] Reject an invalid stop_regex with a 400 instead of a 500

[Upstream PR](https://github.com/sgl-project/sglang/pull/40985) · state: open · merged: False

## Original PR description

## Motivation

A malformed `stop_regex` makes the server answer 500 instead of 400. `SamplingParams.normalize()` bounds every `stop_regex` with `get_max_seq_length()`, which parses the pattern with `re._parser`. A bad pattern raises `re.error` there, and `re.error` is not a `ValueError`, so `/generate` (`http_server.py` catches `ValueError` only) and the OpenAI endpoints (`serving_base.py` maps `ValueError` to 400 and everything else to 500) both let it out as an internal error with a traceback in the server log. Every other bad sampling value in the same function, including the `stop` and `stop_regex` limits from #37029, comes back as a 400 with a message.

Repro against a server on current `main`:

```
python -m sglang.launch_server --model-path Qwen/Qwen2.5-0.5B-Instruct --port 30000
curl -s -w '\n%{http_code}\n' http://127.0.0.1:30000/generate -H 'Content-Type: application/json' \
  -d '{"text": "Paris is", "sampling_params": {"max_new_tokens": 8, "stop_regex": "("}}'
```

Output on main and on this branch (same server, same requests, log excerpts):

```
# main
== /generate, stop_regex '('
Internal Server Error
HTTP 500
== /v1/completions, stop_regex '[a-'
{"object":"error","message":"Internal server error: unterminated character set at position 0","type":"InternalServerError","param":null,"code":500}
HTTP 500

# this branch
== /generate, stop_regex '('
{"error":{"message":"stop_regex '(' is not a valid regular expression: missing ), unterminated subpattern at position 0"}}
HTTP 400
== /v1/completions, stop_regex '[a-'
{"object":"error","message":"stop_regex '[a-' is not a valid regular expression: unterminated character set at position 0","type":"BadRequestError","param":null,"code":400}
HTTP 400
```

`main` answers `Internal Server Error` with status 500 and logs `re.error: missing ), unterminated subpattern at position 0`. `"stop_regex": "[a-"` on `/v1/completions` gives `{"object":"error","message":"Internal server error: unterminated character set at position 0","type":"InternalServerError","param":null,"code":500}`. Without a model:

```python
from unittest.mock import MagicMock
from sglang.srt.sampling.sampling_params import SamplingParams

tok = MagicMock(); tok.encode.return_value = [1]
SamplingParams(stop_regex="(").normalize(tok)   # main: re.error, not ValueError
```

## Modifications

In the `stop_regex` loop of `normalize()`, `get_max_seq_length(stop_regex)` is wrapped in `try/except re.error` and re-raised as `ValueError("stop_regex '(' is not a valid regular expression: missing ), unterminated subpattern at position 0")` (`from e`), the same shape and place as the limits added in #37029, so the existing HTTP mapping turns it into a 400. `import re` is added; `re._parser` was already imported as `sre_parse`. Valid patterns are unaffected.

With the patch the `/generate` request above answers 400 with `{"error":{"message":"stop_regex '(' is not a valid regular expression: missing ), unterminated subpattern at position 0"}}`, and the OpenAI endpoints answer 400 `BadRequestError` with the same message.

Test: `test_invalid_stop_regex_raises_value_error` in `test/registered/unit/sampling/test_sampling_params.py` covers `(`, `[a-`, `*abc` and `(?P<x>a)(?P=y)`, checks that the message names the field and the pattern and that the cause is the `re.error`, and checks that a valid pattern in the same list still normalizes. It fails on `main` (the four patterns raise `re.error`) and passes with this change.

The only test file touched is `test/registered/unit/sampling/test_sampling_params.py`; a selective CI run is `/rerun-test test/registered/unit/sampling/test_sampling_params.py`.

Checked end to end on a g5 instance (A10G) with `Qwen/Qwen2.5-0.5B-Instruct`, unmodified `main` and then this patch: the three invalid requests move from 500 to 400 with the message above on `/generate`, `/v1/completions` and `/v1/chat/completions`; a valid `stop_regex` (`Par[a-z]s`) still stops with `"finish_reason": {"type": "stop", "matched": "Par[a-z]s"}`; the request without `stop_regex` is unchanged; no traceback in the server log.
