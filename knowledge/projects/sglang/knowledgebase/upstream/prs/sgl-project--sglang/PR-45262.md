# [Perf] [NVIDIA] fp8: Use FlashInfer b12x for block-fp8-as-MXFP8 linears on SM12x

[Upstream PR](https://github.com/sgl-project/sglang/pull/45262) · state: open · merged: False

## Original PR description

## Motivation
With `--fp8-gemm-backend flashinfer_cutlass`, block-fp8 weights served as MXFP8 always use FlashInfer's CUTLASS MXFP8 GEMM. On SM120/SM121, FlashInfer 0.7.2 also ships the b12x warp-MMA backend. It has small-M tiles and is faster at every M. FlashInfer's own `backend="auto"` already prefers it on SM12x.

## Modifications
`dispatch_block_fp8_mxfp8_linear`: when FlashInfer reports `b12x` as supported for the device, use b12x when K % 128 == 0 and CUTLASS otherwise. Non-SM12x devices are unchanged.

## Accuracy Tests
- Kernel level: the output error is identical across the Triton block, CUTLASS and b12x paths (rel ≈ 2.67e-2, which comes from activation quantization).
- GSM8K 5-shot, DeepSeek-V4.1-Flash: 0.913 (b12x) vs 0.904 (CUTLASS); SE ≈ 0.8pt.

## Speed Tests and Profiling
8x RTX PRO 5000 72GB, DeepSeek-V4.1-Flash, DP8 attention + EP8, MXFP4 MoE.

Kernel latency (us, CUDA graph):

| N×K | M | CUTLASS | b12x |
|---|---|---|---|
| 1792×5120 | 1 | 33.5 | 7.6 |
| 25600×6144 | 1 | 420 | 142 |
| 25600×6144 | 8192 | 9906 | 7207 |

End to end, CUTLASS → b12x:

| Metric | CUTLASS | b12x | Change |
