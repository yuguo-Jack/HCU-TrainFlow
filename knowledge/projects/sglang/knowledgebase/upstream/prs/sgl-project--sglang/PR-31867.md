# [NPU] Update non-vit vision part for cumulative seqlen

## Motivation

`torch_npu.npu_fused_infer_attention_score` with `input_layout="TND"` requires `actual_seq_lengths` / `actual_seq_lengths_kv` to be **cumulative** sequence lengths (same semantics as FlashAttention `cu_seqlens[1:]`). The last element must equal `query.shape[0]` (packed token count `T`).

[#25768](https://github.com/sgl-project/sglang/pull/25768) aligned the eager Ascend path with that contract. [#31701](https://github.com/sgl-project/sglang/pull/31701) fixed the ViT NPU graph runner, which still cached per-sequence lengths from the older `_npu_flash_attention_unpad` API.

A third path remained broken: after [#24013](https://github.com/sgl-project/sglang/pull/24013), eager ViT encoding prefers `VisionAttentionMetadata`, and `VisionAscendAttention` passed `forward_metadata.seq_lens` (per-sequence deltas) into TND. That still works for a single image (`last == T` by accident) but fails when multiple images are packed into one ViT forward — e.g. Ascend MMMU accuracy cases without `SGLANG_VIT_ENABLE_CUDA_GRAPH`, with errors such as `queryT(1000) must be equal to the last element of actualSequenceLengthQ(264)`.

## Modifications

- In `VisionAscendAttention`, when `forward_metadata` is present, build TND `actual_seq_lengths` from `forward_metadata.cu_seqlens[1:]` (moved to CPU) instead of `forward_metadata.seq_lens`.
- Leave `prepare_vision_attention_metadata` / `seq_lens` unchanged so other backends that still consume per-sequence lengths are unaffected.
- Graph and non-metadata eager branches are unchanged (already cumulative / covered by [#31701](https://github.com/sgl-project/sglang/pull/31701)).
