# [Fix] offloader: Restore forward wrappers after exceptions

[Upstream PR](https://github.com/sgl-project/sglang/pull/45354) · state: open · merged: False

## Original PR description

## Motivation

Both CPU-offload forward wrappers temporarily replace `module.forward` with the original implementation to avoid recursively calling themselves through `torch.func.functional_call`. They restore the wrapper only on a successful return.

If device-state preparation or the wrapped forward raises, the module is permanently left with its original forward. In the V2 helper, an exception in `on_forward_end` has the same effect. A subsequent call bypasses the offloader's parameter substitution and hooks. This patch preserves the installed wrapper even when a call fails; it does not make an arbitrary failed engine safe to resume.

Found while reviewing the CPU-offload path at `78185f4b3f565cbe0fec20d71bb5deb372428e80`. This is separate from the cached-weight residency changes in #44139.

## Modifications

- Restore `module.forward` in `finally` in `OffloaderV1` and `_hook_module_forward_raw`.
- Preserve the original exception. Keep `on_forward_end` after a successful `functional_call`, as before; do not invoke it after a preparation or forward failure.
- Add regression coverage for preparation, forward, and end-hook failures; repeated successful calls; parameter restoration; and positional/keyword argument forwarding. Add a CUDA test for V1's actual CPU/device transfers.
