# [Fix] Match KPool draft-extend writes to precomputed plans

[Upstream PR](https://github.com/sgl-project/sglang/pull/37588) · state: open · merged: False

## Original PR description

## Motivation

**Stacked on #37587**, at `27a790d6b285d189306a6aaaaa211c6f969866a0`. The base is `codex/fix-hybrid-linear-eagle-padding`; merge #37587 first, then retarget/rebase this PR onto main.

#37587 keeps complete request groups for hybrid target verify. KPool's existing kernel already skips dummy groups whose first `out_cache_loc` is zero, so those physical groups and their request plan should remain intact.

Eager draft extend instead prepares its attention metadata before TP padding and deliberately skips replanning. Three requests with six draft tokens can become 24 physical token rows while the KPool plan still has three requests. The writer then fails its token-divisibility or write-plan batch-size assertion.

## Modifications

Bound the writer's key, score and cache-location inputs by `plan.req.shape[0] * plan.num_draft_tokens`, and reject a plan larger than the physical input. Keep all request-plan tensors intact. This trims surplus draft-extend inputs while retaining the complete target-verify and graph buckets.

The net diff relative to #37587 is one production method (+12/-3) and two test files. Decode, paged-reader and schedule changes have been removed. In a controlled C38 serving run, restoring the original decode method while retaining only the draft-extend fix still completed 76/76 requests; that experiment does not justify a separate decode fix in this PR.
