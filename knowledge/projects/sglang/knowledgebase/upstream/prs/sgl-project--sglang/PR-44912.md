# [Refactor] moe: Split the two meanings of num_fused_shared_experts

## Motivation

`num_fused_shared_experts` carries two meanings: shared experts executed by the fused MoE layer, and shared id/weight slots emitted by ordinary TopK. Waterfill needs fused computation while appending the shared slots after ordinary routing. Conflating these quantities makes TopK and HashTopK rewrite their constructor arguments for Waterfill.

## Modifications

- Keep `num_fused_shared_experts` for the experts-layer layout and use `num_shared_topk_slots` for shared output positions emitted by ordinary routing, before Waterfill expansion.
- Derive ordinary routing slots once in `shared_topk_slots`: the fused count normally, zero when Waterfill writes the slots later. Construct TopK/HashTopK from these meanings directly.
- Update router consumers and layout helpers; retain existing kernel interfaces.
- Guard the single-writer invariant: the router or Waterfill emits the shared slots exactly once, including unfused and empty-output cases.

#44913 places both quantities in one immutable model-owned configuration and exposes it through `get_model().shared_experts`.
