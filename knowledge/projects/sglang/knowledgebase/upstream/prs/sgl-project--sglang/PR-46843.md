# [Feat] [NPU] sampling: Add DSpark Triton operators

[Upstream PR](https://github.com/sgl-project/sglang/pull/46843) · state: closed · merged: False

## Original PR description

## Motivation

DSpark sampling and greedy verification on Ascend NPU require efficient
implementations of token selection and output-token assembly.

This PR adds four Triton operators to the `sgl-kernel-npu` operator framework:

- `row_argmax`: select the maximum logit index for each row.
- `markov_greedy`: combine the Markov projection with base logits and select
  the next token.
- `build_out_tokens`: assemble draft tokens and the bonus token.
- `markov_sample`: perform a Markov sampling step, including greedy and
  temperature-based sampling.

## Modifications

- Add Triton implementations under `implementation/triton/sample`.
- Register the four public operators under `sgl_kernel_npu.operators.sample`,
  with `auto`, `triton`, and `torch_native` implementations.
- Add Torch Native implementations for accuracy comparison.
- Add public-operator framework tests and dedicated tests for edge cases,
  Philox sampling, precomputed noise, sharding, and NPU graph replay.

## Accuracy Tests

### Operator tests

On the tested Ascend A3 environment:

- Public operator framework tests: **21 passed**.
- Dedicated operator tests: **39 passed**:
  - `row_argmax`: 4 passed.
  - `build_out_tokens`: 5 passed.
  - `markov_greedy`: 10 passed.
  - `markov_sample`: 20 passed.

The tests cover exact token/index agreement against Torch references, including
ties, NaNs, padding, strides, mixed greedy and sampled rows, FP32/FP16/BF16
rounding, Philox and precomputed noise, sharding simulations, kept logits, and
NPU graph replay.

### End-to-end accuracy

The SGLang integration was evaluated on two A3 environments with matching
runtime versions and aligned effective model configuration. Generation used
temperature 1, top-p 1, seed 1, thinking/high, and `max_tokens=125000`.

For the matched **197-example** cohort:

| Result | Examples |
| --- | ---: |
| Correct in both baseline and integration | 175 |
| Correct only in baseline | 5 |
| Correct only in integration | 3 |
| Incorrect in both | 14 |

Neither completed cohort contained API errors. One long-running baseline
example was externally terminated and excluded from both variants; this is not
a completed 198-example run.

The `markov_sample` Torch baseline uses the same Philox random-number

The generic `build_out_tokens` kernel failed during BiShengIR lowering because
of an `i1`/`i8` operand type mismatch. The generic Markov sampling path
encountered unsupported Philox operations, including `uint32` to `float32`
conversion. Therefore, no generic-Triton speedup is reported for those cases.

### End-to-end serving performance

Both variants ran in the same container on the same A3 host with
`DeepSeek-V4-Flash-0731-w8a8` and ModelSlim W8A8 quantization. The workload
used 128 input tokens, 1024 output tokens, and concurrency 128. NPU graphs
were enabled; the DSpark draft block size was 6 and verification length was 7.

The compatible baseline routes Markov sampling to the precision-fixed NPU
Philox implementation, without precomputed noise or the other dedicated
operator integrations. Unmodified main could not capture the graph on the
tested stack because of unsupported `uint32` to `float32` lowering.

The following table reports the second, warmed run:

| Temperature | Output throughput, tokens/s | Mean TPOT, ms | Draft acceptance rate | Acceptance length, including bonus |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 4671.52 → 4929.38 (+5.52%) | 18.60 → 18.94 (+1.86%) | 53.58% → 54.28% | 4.2093 → 4.2501 |
| 1 | 3610.44 → 4286.05 (+18.71%) | 25.86 → 21.94 (−15.16%) | 44.02% → 44.70% | 3.6378 → 3.6779 |

At temperature 1, P99 TPOT decreased from **33.20 ms to 28.23 ms**.

These end-to-end measurements are for the corresponding SGLang integration,
which includes related sampling-path changes; they should not be attributed
solely to the four operators in this PR.
