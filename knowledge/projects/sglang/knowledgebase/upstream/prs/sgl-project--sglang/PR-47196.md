# [Feat] unlimited-ocr-v2: Add Unlimited-OCR v2 model support

[Upstream PR](https://github.com/sgl-project/sglang/pull/47196) · state: closed · merged: True

## Original PR description

## Motivation

Unlimited-OCR v1 (#29186) serves single images and short documents with a prefill-aware sliding window. [Unlimited-OCR-2](https://huggingface.co/baidu/Unlimited-OCR-2) (`UnlimitedOCRV2ForCausalLM`) targets long multi-page documents (hundreds of pages in one request). It replaces the sliding window with DASH sparse attention (a learned per-page router plus a per-page 2D position frame), so serving it needs a new attention backend, model, and processor, plus serving-side support for splitting a long document into page windows that reuse each other's KV cache.

## Modifications

**Model and attention**
- `models/unlimited_ocr_v2.py`, `multimodal/processors/unlimited_ocr_v2.py`; v2-only processor options in `configs/unlimited_ocr.py` (`v2_layout=True`; v1 keeps its upstream tile cap and crop layout).
- `layers/attention/unlimited_ocr_v2_backend.py`: DASH sparse attention (learned per-page entmax router, sparse prefill/decode attend, page-local 2D RoPE). Full prefill and decode CUDA graphs supported; eager decode also supported.
- Triton kernels in `kernels/ops/attention/unlimited_ocr_dash/` with `KernelSpec` registrations; runtime state (page/coord state, router math) stays in `srt/layers/attention/unlimited_dash_ops/`.
- `arg_groups/model_overrides/unlimited_ocr_v2.py`: selects the `unlimited_ocr_v2` backend, sets `page_size` to the sparse block size, disables the radix cache, and rejects unsupported modes (see below).
- `UnlimitedOCRV2KVPool` (K + router-index K) in `mem_cache/memory_pool.py`, sized in `kv_cache_configurator.py` / `pool_configurator.py`.

**SAM vision encoder (shared with DeepSeek-OCR / Unlimited-OCR v1)**
- Two JIT kernels, `elementwise.sam_rel_pos_bias` and `elementwise.window_unpartition_add`, used only when their contract holds (CUDA non-ROCm, bf16, shape/stride/alignment); otherwise the eager path runs. Query-chunked relative-position bias capped at 64 MiB.

**Long-document serving (v2 only)**

Serving, retained-window KV state, prefetch, scheduler hooks, and decode/crop helpers are owned by Unlimited-OCR v2 under `models/unlimited_ocr_v2_support/`. The serving loop owns window progress and a single prefetched successor; plans are validated once in `document_split.py`. The retained KV-row holder is `RetainedWindow`.
- `models/unlimited_ocr_v2_support/chat.py` + `models/unlimited_ocr_v2_support/document_split.py`: with `--uocr-doc-split`, a multi-page chat request is split into page windows (with lookahead pages) and answered as one response / one stream. Windowing with KV splicing is approximate and opt-in; the default serves the whole document. `serving_chat.py` only gets a `None`-checked hook. If a window is rejected for exceeding context while other windows succeed, the non-streaming response preserves their text and usage, reports an incomplete document with `finish_reason="length"`, and includes the rejected window in its diagnostic metadata. The cookbook client checks `doc_split_complete` before using the text as a complete document.
- `models/unlimited_ocr_v2_support/document_reuse.py` (`DocReuse`), `models/unlimited_ocr_v2_support/retained_window.py`: a finished window's KV tail is retained and copied into the next window instead of re-encoding and re-prefilling the overlap page.
- `models/unlimited_ocr_v2_support/document_prefetch.py` (`DocPrefetch`, `EarlyEmbeddings`): the next window is sent while the current one decodes and its pages are vision-encoded early on a side stream.
- Per-page output cap (`--uocr-max-page-tokens`) through the built-in page guard, without enabling external custom logit processors. External serialized processors still require `--enable-custom-logit-processor`. The processor collects its per-row bans / forced tokens and applies them with one non-blocking index upload, so it never blocks the host on the forward.
- With doc split, the request pool has `2 * max_running_requests` rows: each in-flight document may hold a retained window row next to its running row (the running cap is unchanged). Without this, retained windows were evicted near the running cap and the follow-up window lost its predecessor's context.

**Scheduler / runtime (created only for Unlimited-OCR v2; `None` otherwise)**
- `models/unlimited_ocr_v2_support/scheduler_hooks.py` owns all per-scheduler document state (no module globals) and is reset by `flush_cache`.
- `models/unlimited_ocr_v2_support/async_shm.py`, `models/unlimited_ocr_v2_support/overlap_release.py`, `models/unlimited_ocr_v2_support/crop_transfer.py`: SHM materialization off the scheduler thread, deferred overlap release, pinned crop prefetch.
- `models/unlimited_ocr_v2_support/greedy_graph.py`, `models/unlimited_ocr_v2_support/decode_graph_io.py`: greedy argmax recorded in the decode graph and decode inputs relayed through it.
- `Scheduler` / `ModelRunner` only construct, wire and delegate; request-side state is declared on `Req` (`uocr_doc`, `page_guard_state`).

**Unsupported with Unlimited-OCR v2 (rejected at launch with a clear error)**
- speculative decoding, `--pp-size > 1`, PD disaggregation;
- `--dp-size > 1` / DP attention while doc split is on (omit `--uocr-doc-split`).

**New server arguments**

| Flag | Default | Meaning |
|---|---|---|
| `--uocr-doc-split` | off | Opt into approximate page-window processing with KV reuse |
| `--uocr-doc-page-window` | 1 | Maximum transcribed pages per window, across all image modes |
| `--uocr-max-page-tokens` | 0 | Per-page output token cap (0 = off); enforced by the built-in page guard |

The model-owned `UocrDocumentConfig` declares and validates these CLI arguments. Advanced request settings use typed `doc_split_options`: `max_batch_pages` (may tighten the server window), `overlap_pages` (default 0), `lookahead_pages` (default 1), and `max_page_tokens` (may tighten the server cap). A larger lookahead can require an explicit `--context-length`. Window settings require `--uocr-doc-split`; per-page limits can also be used with whole-document serving.

**Internal environment overrides** (expert kill-switches / resource thresholds; not semantic model settings): `SGLANG_ENABLE_UOCR_DOC_PREFETCH`, `SGLANG_UOCR_DOC_PREFETCH_MAX_MB`, `SGLANG_ENABLE_UOCR_CROP_PREFETCH`, `SGLANG_UOCR_CROP_PREFETCH_MAX_MB`, `SGLANG_ENABLE_UOCR_ASYNC_SHM_MATERIALIZATION`, `SGLANG_UOCR_ASYNC_SHM_MAX_MB`, `SGLANG_ENABLE_UOCR_SHM_WRAP_MODEL_DATA`.

**Changes visible to other models**
- Custom logit processors: when every row of the batch uses the same processor, it is applied to the full logits in place (bit-exact; saves two full-logits copies per step).
- SAM encoder JIT kernels (above) for DeepSeek-OCR / OCR2 / Unlimited-OCR v1 on bf16 CUDA; a kernel bug for strided `rel_w` inputs is rejected instead of producing a wrong bias.
- `DeepseekOCRNoRepeatNGramLogitProcessor`: new opt-in params; with default params output is identical (3000 random cases). Out-of-vocab banned ids are ignored instead of raising.
- Fastokens: unchanged for every tokenizer that loaded before. A tokenizer whose `tokenizer.json` pre-tokenizer disagrees with its declared class (v2 declares `LlamaTokenizerFast` with a ByteLevel pre-tokenizer) used to fail under `--tokenizer-backend fastokens`; it now loads through Hugging Face with the v5 component fix and wraps the repaired backend.
- Unlimited-OCR v1 prompt building, processor and serving behave exactly as before.

**Tests and docs**
- Document planning and split-response tests: `test/registered/unit/models/unlimited_ocr_v2/test_document_split.py`.
- Unit tests under `test/registered/unit/{session,managers,mem_cache,sampling,entrypoints,server_args,models,layers/attention}`; kernel tests and benchmarks under `test/registered/kernels/{ops,benchmark}/{attention,elementwise}`; e2e server test `test/registered/vlm/test_unlimited_ocr_v2_server.py` (single page + multi-page with splitting and KV reuse).
- Cookbook page `Baidu/Unlimited-OCR-2.mdx` with its config; new flags in `server_arguments.mdx`.

## How to reproduce

Server (1x NVIDIA L20 48 GB). The command below uses the current CLI names. The benchmark results below are carried over from the original PR description at `f15f2d1aa007e7df0e79495285eb2f50f8389a90`, before the configuration cleanup. The original recipe used equivalent one-page windows; these results have not been remeasured on the current head. Only `--uocr-max-page-tokens` differs per benchmark:

```bash
SGLANG_VLM_CACHE_SIZE_MB=0 PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True \
python -m sglang.launch_server \
  --model-path baidu/Unlimited-OCR-2 \
  --served-model-name Unlimited-OCR-v2 \
  --host 0.0.0.0 --port 30000 \
  --tokenizer-worker-num 8 \
  --tokenizer-backend fastokens \
  --chat-template unlimited-ocr \
  --mem-fraction-static 0.7 \
  --max-running-requests 64 \
  --max-prefill-tokens 2048 \
  --random-seed 20260918 \
  --uocr-doc-split \
  --uocr-max-page-tokens 20000 \
  --enable-custom-logit-processor \
  --enable-streaming-session \
  --allow-auto-truncate \
  --disable-radix-cache \
  --mm-preprocess-cache-size-mb 0 \
  --cuda-graph-backend-decode full \
  --cuda-graph-max-bs-decode 64 \
  --cuda-graph-backend-prefill full \
  --cuda-graph-max-bs-prefill 16384 \
  --cuda-graph-bs-prefill 1024 2048 \
  --cuda-graph-config '{"prefill": {"backend": "full", "full_prefill_max_req": 64}}'
```

`--uocr-max-page-tokens` is 8000 for MPDocBench and 20000 for MarathonDocBench. MPDocBench sends multi-page documents with `images_config.image_mode="base"` and single pages in the default `gundam` mode; MarathonDocBench uses `gundam`.

Request: one chat request per document, all pages in one message; the server splits it into page windows and returns one answer.

```python
from openai import OpenAI
from sglang.srt.sampling.custom_logit_processor import DeepseekOCRNoRepeatNGramLogitProcessor

client = OpenAI(base_url="http://127.0.0.1:30000/v1", api_key="EMPTY")
pages = [...]  # data URLs or http(s) URLs, in page order
content = [{"type": "image_url", "image_url": {"url": u}} for u in pages]
content.append({"type": "text", "text": "<PAGE><image>" * len(pages) + "Multi page parsing."})
resp = client.chat.completions.create(
    model="Unlimited-OCR-v2",
    messages=[{"role": "user", "content": content}],
    temperature=0,
    max_tokens=20000 * len(pages),
    extra_body={
        "skip_special_tokens": False,
        "images_config": {"image_mode": "gundam"},
        "custom_logit_processor": DeepseekOCRNoRepeatNGramLogitProcessor.to_str(),
        "custom_params": {"ngram_size": 35, "window_size": 1024 if len(pages) > 1 else 128},
    },
)
```
