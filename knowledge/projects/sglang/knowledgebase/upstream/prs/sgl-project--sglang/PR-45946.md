# [Feat] sail: support sail fa3 and flashmla [3/N]

[Upstream PR](https://github.com/sgl-project/sglang/pull/45946) · state: closed · merged: True

## Original PR description

## Motivation

Refs #37519 

T-HEAD SAIL exposes a CUDA-compatible torch backend (`SailSRTPlatform` already exists in `platforms/sail.py`), but its attention kernels are not the ones `sgl_kernel` ships:

- `sgl_kernel` imports its compiled `flash_ops` (FA3) at import time, so the import fails on SAIL.
- SAIL provides its own FA3 interface (`flash_attn_interface`) and FlashMLA library, with different metadata semantics: a lazily-initialized scheduler-metadata object, a 320 `sm_parts` cap, and no `qv` / `only_qv` support.
- The FA3 backend's capability assert rejects MLA on SM 8.x, which is the capability SAIL reports.
- Channel-wise FP8 `kv_b_proj` weights go through `channel_quant_to_tensor_quant` + FP8 BMM, which SAIL does not support.

This PR lets MLA models (DeepSeek / GLM family) run on SAIL with `--attention-backend fa3` and `flashmla`, including MTP / EAGLE speculative decoding and CUDA graph. It keeps the existing backends unchanged: SAIL-specific behavior is injected via `@plugin_hook` and only loaded when SAIL hardware is detected.

## Modifications

### New: `python/sglang/srt/hardware_backend/sail/attention/`

| File | Purpose |
| --- | --- |
| `flash_attention.py` | Wraps SAIL's `flash_attn_interface`: `flash_attn_with_kvcache`, `flash_attn_varlen_func`, `get_scheduler_metadata`, with the same signatures as `sgl_kernel.flash_attn`. FA4 (`ver=4`) and `only_qv=True` raise `NotImplementedError` with a clear message. |
| `flash_mla.py` | Wraps SAIL's FlashMLA library: `get_mla_metadata`, `flash_mla_with_kvcache`, `flash_mla_sparse_fwd`. |
| `sail_fa3_hooks.py` | Hooks `flashattention_backend.flash_attn_varlen_func` / `flash_attn_with_kvcache` (REPLACE) and `FlashAttentionBackend.__init__` (AROUND), so the FA3 backend calls the SAIL ops. |
| `sail_flashmla_hooks.py` | Hooks for `sgl_kernel.flash_mla.*` (REPLACE) and `FlashMLABackend`: caps the CUDA graph metadata buffer at 320 `sm_parts`, and replaces `_apply_decode_target_verify_metadata` (SAIL metadata object, DRAFT_EXTEND_V2 seq_lens) and `init_forward_metadata_in_graph`, so lazy metadata init runs inside graph capture. |
| `sail_dsa_hooks.py` | Hooks for `DSAFlashMLAMetadata.copy_` / `.slice` and `DeepseekSparseAttnBackend` graph-metadata init/replay, so the cached SAIL metadata is never overwritten during replay. |

### Platform detection and hook loading

- `platforms/sail.py`: adds `is_sail_available()` (cached; true when the CUDA device name contains `ZW`). When it returns true, imports the three hook modules to register them. They are applied by the existing `load_plugins()` → `HookRegistry.apply_hooks()` path.
- `runtime_context.py`: adds `"is_sail"` to `_PLATFORM_PROBES`, so `get_platform().is_sail` is available.
- `sgl_kernel/utils.py`: adds `is_sail()`. `sgl_kernel/flash_attn.py`: skips the `flash_ops` import on SAIL, so `import sgl_kernel.flash_attn` no longer fails there.

### Attention backend / model changes

- `attention_registry.py`: the FA3 capability assert also accepts `major == 8` with MLA when `_is_sail`.
- `flashmla_backend.py`: `forward_decode` / `forward_extend` accept optional `q_rope` / `k_rope`.
  - When `k_rope` is given, the KV cache is written with `set_mla_kv_buffer`.
  - When `q_rope` is given, the backend builds the 576-dim query with `concat_mla_absorb_q_general`.
  - The `ForwardMode.EXTEND` branch forwards them to `FlashInferMLAAttnBackend.forward_extend`.
- `deepseek_common/utils.py`: adds `"flashmla"` to `FORWARD_ABSORB_CORE_ATTENTION_BACKENDS`, so the model passes `q_rope` / `k_rope` separately and does not pre-concatenate. Adds `_is_sail`.
- `forward_mla.py`:
  - Uses `concat_mla_absorb_q_general` in place of `torch.cat` for the non-absorb-core `q` / `k` concat.
  - On SAIL, skips the FP8 `w_kc` / `w_vc` BMM branches; the weights are BF16 there (see below).
- `deepseek_weight_loader.py`: on SAIL, dequantizes channel-wise FP8 `kv_b_proj` to BF16 (`w * weight_scale`) instead of `channel_quant_to_tensor_quant`.

- `python/pyproject_other.toml`: adds `flash-attention-for-sail`, `flashinfer-for-sail` and `flashmla-for-sail` to `srt_sail` (no version pins).

- `python/sglang/srt/layers/moe/topk.py`: requires `get_device_sm() >= 89` before selecting the FlashInfer biased grouped topk kernel.

### Server-arg resolution

- `model_override_base.py`: on SAIL, MHA models default to `fa3`, under the same `is_no_spec_infer_or_topk_one` condition as Hopper.
- `model_hook.py`: on SAIL with an MLA backend, sets the prefill phase of `cuda_graph_config` to `DISABLED`. A captured prefill graph pins MLA to the absorbed path, which passes `qv` to FA3, and the SAIL FA3 interface rejects `qv`.

### Impact on non-SAIL platforms

- All `_is_sail` / `is_sail()` / `get_platform().is_sail` branches are false on non-SAIL devices, and no hook module is imported.
- **One shared behavior change:** with `"flashmla"` in `FORWARD_ABSORB_CORE_ATTENTION_BACKENDS`, CUDA FlashMLA now receives `q_rope` / `k_rope` and does the concat and `set_mla_kv_buffer` inside the backend. This replaces the concat in the model plus `set_kv_buffer`. It needs CUDA (Hopper) validation before going upstream.

### Known limitations

- SAIL FA3 does not support `qv` / `only_qv`. DSA + `fa3` (`DeepseekSparseAttnBackend._forward_fa3` always passes `qv`) is therefore not usable on SAIL; use `flashmla_kv` for DSA decode.
- Prefill CUDA graph is disabled for MLA on SAIL (see above).

File: `python/sglang/srt/arg_groups/platform_hook.py` · line None

For a dense MLA model such as DeepSeek-V3, --attention-backend fa3 resolves to FA3 for both prefill and decode. The new compatibility check immediately returns because it only handles the pair ("fa3", "flashmla"). Meanwhile, the changed registry explicitly permits FA3 with MLA on SAIL and constructs SailFlashAttentionBackend. [Registry dispatch](https://github.com/sgl-project/sglang/blob/30df2e680c07aa5de518113f670238d1a2013e84/python/sglang/srt/layers/attention/attention_registry.py#L254-L269)
That subclass inherits the standard MLA decode implementation, which always calls attention with qv=q_nope. The SAIL wrapper forwards this argument, but the vendor kernel requires params.arch == 90 whenever q_v is supplied. On SAIL’s reported SM8.x device, this reaches:
```
q_v is only supported for Hopper GPUs
```
The failure follows directly from the [inherited decode call](https://github.com/sgl-project/sglang/blob/30df2e680c07aa5de518113f670238d1a2013e84/python/sglang/srt/layers/attention/flashattention_backend.py#L2356-L2360), the [SAIL wrapper](https://github.com/sgl-project/sglang/blob/30df2e680c07aa5de518113f670238d1a2013e84/python/sglang/srt/hardware_backend/sail/attention/flash_attention.py#L124-L130), and the [vendor’s architecture assertion](https://github.com/t-head/flash-attention-for-sail/blob/3c77a993ad20334a7b6f3cd2d9f79a58eb4e347d/hopper/flash_api.cpp#L1458-L1462).
