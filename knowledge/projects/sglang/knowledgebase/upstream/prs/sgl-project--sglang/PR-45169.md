# [CI] check-pr-test-health: Retry transient GitHub API errors

[Upstream PR](https://github.com/sgl-project/sglang/pull/45169) · state: closed · merged: False

## Original PR description

## Motivation

A transient GitHub API 500/502 can fail `check-pr-test-health` before any tests run. These failures are tracked in #42752 (I11, I14, I17, I31, I33, I34 and I36) and are still recurring: I17, I31, I33, I34 and I36 were all last seen on 2026-10-20, across `1-gpu-h100`, `2-gpu-h100`, `4-gpu-b200`, `8-gpu-b300` and `8-gpu-h20` runners.

## Modifications

Set `actions/github-script`'s `retries` to 2, as `check-maintenance` already does. This retries individual API requests; real lint and sibling-job failures still fail the health check.

This covers `check-pr-test-health`. #42806 changes the separate `wait-for-jobs` action.

## Accuracy Tests

- `node --test .github/actions/check-pr-test-health/action.test.cjs`: 5 tests pass.
- Local HTTP fault injection with the current action script and the real `github-script@v8` bundle: 11 cases pass. Without retries, an injected 500 fails immediately. With retries, transient 500/502 responses recover in lint, label lookup and paginated job lookup. Persistent lint/job-list API errors and real lint/job failures still fail; bypass labels still work.
- Scoped pre-commit checks pass.

## Speed Tests and Profiling

No inference code changes. Successful requests need no extra calls; a failing request can make up to two additional attempts.
