# feat: reject empty/whitespace-only assistant content in chat validation

[Upstream PR](https://github.com/sgl-project/sglang/pull/30267) · state: closed · merged: False

## Original PR description

When a request contains an assistant message with empty or whitespace-only content (and no tool_calls), the chat template produces a malformed prompt that can cause garbled model output.

Add a validation check in _validate_request that rejects such messages with a 400 error before they reach the model. Assistant messages carrying tool_calls are exempt since null content is expected in that case.

Tests cover:
- Empty string content is rejected
- Whitespace-only content is rejected
- Tool_calls with null content passes
- Non-empty content passes

If an assistant message has `content` set to `None` (or an empty list `[]`) and does not contain any `tool_calls`, it will bypass this validation check because `isinstance(content, str)` is `False`. However, during template processing (e.g., in `_apply_jinja_template` or the DeepSeek encoders), `None` content is normalized to an empty string `""`. This means `None` content without tool calls will still result in a malformed prompt and garbled output.\n\nWe should update the check to reject `None` content and empty lists when no tool calls are present.

```python
            if (\n                not getattr(message, "tool_calls", None)\n                and (\n                    content is None\n                    or (isinstance(content, str) and not content.strip())\n                    or (isinstance(content, list) and not content)\n                )\n            ):
```
