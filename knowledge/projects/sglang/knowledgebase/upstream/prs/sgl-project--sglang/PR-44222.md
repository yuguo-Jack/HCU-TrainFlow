# [Fix] speculative: Validate QSA top-k before loading weights

[Upstream PR](https://github.com/sgl-project/sglang/pull/44222) · state: open · merged: False

## Original PR description

## Motivation

QSA currently supports only chain speculation (`speculative_eagle_topk=1`). With an EAGLE-family algorithm and `--speculative-eagle-topk 2`, argument resolution can succeed and startup fails in the QSA backend after model weights have been loaded. Reject this unsupported combination during argument resolution with a clear error.

Partially addresses #44099. Draft-window width validation is outside this PR's scope; #40143 is expanding the pending index-key ring capacity.

## Modifications

- Detect QSA using the existing `is_qwen_qsa()` config parser.
- Validate the effective top-k in `_handle_eagle_family()` after automatic/adaptive parameter resolution, preserving valid defaults and non-QSA behavior.
- Register 10 CPU regression tests covering QSA rejection, chain speculation, nested/flat configs, non-QSA configs, default resolution, NEXTN aliasing, single-step speculation, adaptive fallback, and existing draft-token normalization.

## Accuracy Tests

CPU argument-handling tests were run on Linux with no visible CUDA devices, without loading model weights. The pre-fix regression on main `684fea8a` reproduced the missing validation (`ValueError not raised`). The patch was synchronized to main `6f646563`, and the focused regression tests below passed again on that base.

```bash
PYTHONPATH=python CUDA_VISIBLE_DEVICES=99 OMP_NUM_THREADS=1 python -m pytest \

  test/registered/unit/spec/test_block_verification_args.py \
  test/registered/unit/spec/test_adaptive_spec_params.py -q
```

Result: **47 passed, 25 subtests passed**.

The expanded run on the updated base, including `test/registered/unit/server_args`, produced **458 passed, 2 failed**. Both failures had also reproduced on the original unmodified main `684fea8a` with the same existing-test selection (**448 passed, 2 failed**):

- `test_default_transport_is_cpu_for_unsupported_multinode_model`: an existing cross-test environment-variable leak changes the expected log message.
- `test_start_server_call_site_matches_native_signature`: the reused test environment lacks `soundfile`.

Ruff checks, Ruff formatting, isort, and `git diff --check` passed.
