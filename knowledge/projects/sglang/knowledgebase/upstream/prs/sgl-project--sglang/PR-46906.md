# [Feat] dflash: Support Bolt E4B NVFP4 DFlash checkpoints

[Upstream PR](https://github.com/sgl-project/sglang/pull/46906) · state: open · merged: False

## Original PR description

## Motivation

Enable speculative decoding for Bolt E4B with `nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-BF16-DFlash-NVFP4`. This drafter provides its own NVFP4 output head, which the existing DFlash path does not load correctly.

This PR supports the BF16 target with the NVFP4 drafter. Support for the GGUF drafter (https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-4GB-DFlash), intended to be used with the GGUF target, will be added in a separate PR.

## Modifications

- Load and use the drafter's head when `has_own_lm_head` is explicitly enabled, including NVFP4 weights.
- Select the sampling head once during worker setup.
- Reject malformed head flags, missing head weights, and unsupported selector/Domino combinations.
- Honor explicitly enabled DFlash sliding-window metadata when Transformers clears the top-level window. Preserve existing top-level precedence and other draft behavior.
- Add regression tests and update model/sampler documentation.

## Accuracy Tests

The NVFP4 drafter currently requires TP1 due to an existing limitation in SGLang’s quantized-head sampler.

Accuracy tests based on commit `1d605b7e`. Tested in Docker on one H100, with unchanged published checkpoint configs. BF16 used this PR branch alone.

GSM8K used `sgl-eval` 0.1.3, 200 examples, zero shots, temperature 0, four workers, a 1,024-token output limit, and thinking disabled.

| Target / mode | GSM8K |
| --- | ---: |
| BF16, target only | 152/200 (76%) |
| BF16 + NVFP4 drafter | 149/200 (74.5%) |

Both BF16 evaluations completed without API errors; each had one response reach the output limit.

On H100, both BF16 configurations passed eight image checks (colors, positions, counting, OCR, and two-image ordering) and two text checks. Additional serving smoke checks passed on GB10 and B200: BF16 passed all ten text/image checks both with and without the drafter on each GPU.

Target attention used defaults for each tested GPU arch: Triton on H100 and GB10, and `trtllm_mha` on B200. BF16 prefill graphs remained disabled by default. Target verification used CUDA graphs. Draft token selection ran eagerly because SGLang’s existing graph sampler does not support quantized output heads.

```bash
bf16=nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-BF16

# BF16 target:
target_args=(--model-path "$bf16" --revision "$bf16_revision")

python3 -m sglang.launch_server \
  "${target_args[@]}" --served-model-name bolt-e4b \
  --context-length 8192 --max-running-requests 4 --max-total-tokens 8192 \
  --mem-fraction-static 0.7 --host 127.0.0.1 --port 30001 \
  --reasoning-parser gemma4 --random-seed 42 --watchdog-timeout 900 \
  --speculative-algorithm DFLASH --speculative-draft-model-path "$draft" \
  --speculative-draft-model-revision "$draft_revision" \
  --speculative-draft-load-format safetensors \
  --speculative-dflash-block-size 8 --speculative-draft-attention-backend triton
```

For target-only runs, omit all six `--speculative-*` options. Run evaluation against the active server, using a separate output directory for each configuration:

```bash
sgl-eval run gsm8k \
  --base-url http://127.0.0.1:30001/v1 --model bolt-e4b \
  --num-examples 200 --num-threads 4 --max-tokens 1024 --temperature 0 \
  --chat-template-kwarg enable_thinking=false --out-dir ./gsm8k-results
```

## Speed Tests and Profiling

Tested on one H100, with the same reviewed source and server settings as the accuracy runs. Used intact ShareGPT prompts through the chat endpoint, thinking disabled, a 512-token maximum, and normal EOS stopping. All configurations used the same prompts: 20 requests at concurrency 1 and 40 at concurrency 4, two warmups, cache flushed, seed 42, temperature 0.

| Target / mode | C1 output tokens/s | C4 output tokens/s | Mean output tokens (C1 / C4) |
| --- | ---: | ---: | ---: |
| BF16, target only | 136.0 | 467.4 | 481.2 / 463.6 |
| BF16 + NVFP4 drafter | 224.9 | 691.9 | 481.5 / 465.3 |

The NVFP4 drafter improved BF16 throughput by 65% at concurrency 1 and 48% at concurrency 4. All 120 measured requests completed without API errors. Saved outputs were screened for repeated phrases and lines, with no extended repetition detected; representative responses were also inspected. 86/120 responses reached the 512-token cap, so this does not establish behavior beyond that limit. Throughput uses actual streamed completion-token counts.

File: `python/sglang/srt/models/dflash.py` · line 1202

[by Claude Code] **Severity: functional | Confidence: Medium**

**Issue**

`load_weights` is also the online weight-update entry point. `update_weights_from_tensor` and `update_weights_from_distributed` call it once per bucket on the draft runner (with `selector="draft"` or the default `"all"`). This check fails every bucket that has no `lm_head.*` tensor. So a bucketed draft update for a drafter with its own head always fails, and leaves the draft partly updated. The Domino check below has the same limit.

**Fix**

Run this completeness check only for the initial checkpoint load, for example from the loader path or behind a flag set after the first full load. A CPU test that calls `load_weights` a second time without head weights would cover it.
