# [Refactor] kernels: Regroup operators by computation and dissolve ops/muse_spark

[Upstream PR](https://github.com/sgl-project/sglang/pull/45112) · state: open · merged: False

## Original PR description

## Motivation

`python/sglang/kernels/README.md` says to classify kernels by the computation they perform, not by the model that first used them, and never to add a model bundle as a top-level group. An audit of current main found that this had drifted:

- `ops/muse_spark/` (#44665) was a model-named top-level group. It contained 22 files mixing norms, routing, GEMMs, collectives and reductions, with no KernelSpecs and no kernel tests. It had been added to `_GROUPS`, which is the only thing the guard test checked, so the test did not catch it.
- `attention/dsv4/` and `attention/dsa/` had collected quantization kernels, KV-cache stores and copies, a split-K GEMV, collective attention-residual kernels, runtime controllers and config predicates, and test oracles.
- Elsewhere, ops sat in the wrong group: GEMMs in `quantization`, RMSNorms in `elementwise`, attention metadata in `kvcache`, a forwarding shim in `attention/utils.py`, and the same computation implemented in two or three groups.

This PR fixes all of it in one pass. It writes the classification rules into the README and the `kernel-organization` skill, and makes the guard test enforce the README.

## Classification rules (README + skill)

- RoPE, including standalone RoPE and position ids, stays in `attention`.
- **Producer + output quantization belongs to the producer's group:**
  - norm + quant → `layernorm`
  - activation + quant → `activation`
  - a GEMM with a quant epilogue → `gemm`
  - MoE dispatch + quant → `moe`
  - `quantization` holds only pure format conversion: quant, dequant, scale layout, repack.
- **Any kernel that performs a cross-rank collective, or reads or writes peer memory, → `communication`**, whatever compute it fuses. Workspaces, symmetric buffers and process groups stay in `srt/layers/communication/`.
- **`kvcache` owns ops that read or write KV-cache contents:** store, gather, copy, quantize-into-cache, clear rows.
- **`attention` owns the index, shape and schedule tables attention kernels consume:** page tables, cu_seqlens, kv_indices, schedule metadata.
- A fused compute+store op stays with its compute group.
- `kda_kernels/` and `cake_kernels/` are documented as the agent-generated kernel backends. They are deliberately left in place, and new agent kernels keep landing there.

**Guard test** (`test_kernels_namespace.py`):
- The README group list must equal `_GROUPS`.
- The README Layout must list exactly the packages under `sglang/kernels/`.

Both checks fail on main.

## Modifications

All relocations are `git mv` plus import updates. Every moved function, class and constant was checked to be byte-identical apart from import paths, either by AST comparison or by a normalized diff. Relocation commits are kept apart from semantic commits. No forwarding shims remain: 94 old module paths have zero references anywhere.

## Bugs fixed along the way
- **CuTeDSL GDN/KDA prefill was selected on SM120 and crashed.** `_is_blackwell()` returned `major >= 10`, but the kernels need tcgen05. The first extend failed with an NVVM `unsupported operation` on sm_120a. They are now gated to SM10x, and SM120 falls back to Triton; B200 still selects CuTeDSL.
- **Muse Spark RMSNorm+NVFP4 quant had no native reference.** `forward_native` raised `NotImplementedError`, which BaseFusedOp does not allow. It is now implemented and checked against the JIT kernel.
- **MiniMax sparse attention tests never ran:** they sat inside the srt package with stale imports. They are fixed and registered.
- **FlashInfer KDA comments wrongly said "SM100-only".** SM120 runs the generic CuTeDSL path, verified on an RTX PRO 6000. Comment fix only.
