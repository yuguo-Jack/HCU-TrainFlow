# [Feat] lora: Grouped and per-row LoRA shrink and expand kernels (03/21)

[Upstream PR](https://github.com/sgl-project/sglang/pull/42870) · state: closed · merged: False

## Original PR description

Part 03 of 21 of the LoRA runtime stack (branch `lora-stack-02-dense-kernels`, base `lora-stack-01-route-primitives`). The stack is cut from the development branch of #42284.

## What this part adds

Add the shared A/B Triton kernels: grouped and per-row shrink (serial split-K
with acquire/release counters, planes, windowed), grouped and per-row expand
with slice geometry tables cached per (rows, columns, tile width, device), and
the embedding LoRA-A lookup. Register them in the lora kernel inventory.

Tests: geometry caching and alignment. The 47-case bitwise kernel fixture
drives the kernels through the runner bridge and lands with the dense runner.

## Verification

- GB300 run r45: the tree of upstream main `c1c287a429` plus parts 01–03 imports every module this part changes and passes this part's tests together with every earlier part's unit tests: **9 passed, 20 warnings in 21.45s**.
- `pre-commit` passed on the changed files of every part; `pre-commit run --all-files` passed on the complete stack tree.

The complete 21-part tree equals the development branch of #42284 at `e7b7179a86` (the `6588053ef2` tree with four test-only follow-ups squashed into its dense commit: the admission/snapshot trim, the restored FP8 block-shape admission pin, a second trim that keeps only the tests guarding silent failures and adds pins for four coverage gaps, and restored numerical and packing coverage; production code is unchanged) minus the benchmark tools and the Triton MoE tuning tables, which follow in separate PRs.
