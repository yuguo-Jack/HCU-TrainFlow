# [Perf] [AMD] gdn: Optimize Qwen3.5 prefill preparation and Triton recurrence

[Upstream PR](https://github.com/sgl-project/sglang/pull/38806) · state: open · merged: False

## Original PR description

## Motivation

[#36267](https://github.com/sgl-project/sglang/pull/36267) removed Qwen3.5 GDN prefill projection unpack copies on CUDA by keeping Q/K/V/Z/B/A as strided views. ROCm still materialized those tensors despite already having stride-aware consumers. ROCm also split QKV and then launched `l2norm_fwd` twice per GDN layer.

This PR ports the view path to ROCm and folds Q/K normalization plus GDN gating into the QKV split. Profiling then showed that the recurrent `chunk_h`/`chunk_o` kernels dominated the remaining GDN time. Their fixed launch geometry under-filled MI355X, while NVIDIA can route GDN prefill through specialized FlashInfer/CuTeDSL backends. This PR therefore adds gfx95-aware Triton launch selection while preserving the original configuration for other platforms, KDA, and unsupported shapes.

The norm fusion differs from [#33290](https://github.com/sgl-project/sglang/pull/33290) and closed [#28361](https://github.com/sgl-project/sglang/pull/28361): those reduce two norm launches to one; this PR reduces them to zero by normalizing while Q/K are already in registers. [#37113](https://github.com/sgl-project/sglang/pull/37113) is the complementary decode projection/Conv1D fusion; its decode branch is mutually exclusive with this prefill path.

## Modifications

- Enable Qwen3.5's strided projection views on ROCm for non-speculative extend. Speculative extend/verify retain the existing unpack path.
- Add `fused_gdn_prefill_prepare`, which in one launch:
  - splits strided post-conv Q/K/V,
  - L2-normalizes Q/K in fp32,
  - passes V through unchanged,
  - computes fp32 GDN `g`/`beta` from strided A/B views.
- Surface `chunk_gated_delta_rule`'s existing `use_qk_l2norm_in_kernel` switch through `TritonGDNKernel.extend`.
- Harden non-power-of-two TP-local Q/K head counts by padding both reduction axes and masking padded loads/stores.
- Select AMD GDN `chunk_h` BV from launch-grid coverage and use deeper pipelining for long per-sequence recurrences. Explicit env overrides remain available; non-AMD and KDA retain prior defaults.
- For AMD GDN `K=V=128`, tune `chunk_o` to `BK=64`, `BV=128`, two warps, and three stages. Replace its zero-filled output allocation with `empty_like`, since every valid output element is overwritten.
- Register the existing chunk launch overrides in `environ.py`. No new user-facing option.

## Accuracy Tests

On MI355X, `test_gdn_prefill_layout.py` passes **7 tests / 10 subtests**, covering:

- BF16 and FP16,
- Qwen3.5 TP2 dimensions,
- non-power-of-two Q/K heads,
- empty batches,
- transposed post-conv and strided A/B layouts,
- exact V/g/beta parity,
- Q/K agreement with `l2norm_fwd`,
- GDN-only `chunk_h`/`chunk_o` selector contracts and fallback behavior.

GSM8K, full 1,319-question split, 5-shot, greedy, TP2, two runs per arm:

| Arm | Run 1 | Run 2 | Pooled |
|---|---:|---:|---:|
| Baseline (pre-PR) | 0.928 | 0.922 | 0.9249 |
| This PR | 0.917 | 0.922 | 0.9196 |

The 0.53pp pooled gap is 0.72σ and does not resolve an accuracy difference. After the new recurrence tuning, a separate no-thinking chat-mode confirmation scores 0.974.
