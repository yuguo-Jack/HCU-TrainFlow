# [Refactor] scheduler: Hold the waiting queue and the chunked slot in request lists

[Upstream PR](https://github.com/sgl-project/sglang/pull/43910) · state: closed · merged: True

## Original PR description

The waiting queue and the chunked slot become request lists like the others, so every list in `Scheduler.request_lists()` is a `ReqList`, each one carries its own abort, and `abort_request` calls them all without type checks. Queues go back to list storage, which is how they were written before the request lists and costs one entry per join.

- The request list classes are renamed: the interface is `ReqList`, with two implementations named by storage.
  - `IndexedReqList`, the default, holds items in a list: read by index and slice, joined at the back or front, reordered through `replace`, and dropped from in batches. An owner that wraps each request (a `DecodeRequest`, a release record, a HiSparse action, a deferred response) passes `req_of`. Every queue uses it: waiting, grammar, chunked, PD bootstrap / sending / prealloc / retracted / held / receiving / releasing, HiSparse staging, deferred responses, uOCR parked / released, dLLM waiting.
  - `KeyedReqList` holds requests in a dict changed in place, for the lists asked `in` often: running and prefill-launched.
- The previous dict-backed list copied its dict on every `join` and `leave`, linear in the queue length per request (quadratic for a burst into a long PD queue); both implementations now change in place.
- The waiting queue's operations follow the waiting events of a scheduler core: `join`, `prepend`, `replace`, `leave`, `take`. Every write to `Scheduler.waiting_queue` goes through them; the uOCR insert at a queue position and the PD prealloc priority reorder are `replace`s.
- `SchedulePolicy.calc_priority` returns the admission order instead of sorting the caller's list, and each caller writes it back with one `replace`.
- The chunked request lives in a single-slot list (`Scheduler.chunked_reqs`) behind the existing `chunked_req` property, so its reads and assignments are unchanged.
- The waiting abort moves from `Scheduler.abort_request` into `Scheduler._abort_waiting`, and the chunked abort mark into `Scheduler._abort_chunked`; `abort_request` keeps the encoder-embedding abort and the abort of requests in flight.

Behavior change: an abort that names several waiting requests handles them in queue order instead of reverse order.
