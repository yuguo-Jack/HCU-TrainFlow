# [SMG] Forward decode streams while prefill is still running

[Upstream PR](https://github.com/sgl-project/sglang/pull/42728) · state: open · merged: False

## Original PR description

## Motivation

PD routing waits for the entire prefill response body before forwarding the decode stream. If prefill is still running, decode can already be sending SSE keep-alives, but the client sees silence until prefill finishes.

## Modifications

After both workers return successful headers, drain the prefill body while forwarding decode chunks. The drain belongs to the decode stream, so completion or client disconnect drops unfinished upstream bodies. Requests that need prefill logprobs still wait for that body before merging them.

## Tests

The new regression holds the prefill body open and sends a decode heartbeat. It times out on the base commit and passes with this change. It also checks upstream cleanup on `[DONE]`, EOF, and client disconnect.

29 tests passed: 13 HTTP-router unit tests, 9 PD routing tests, and 7 PD reliability tests. Pre-commit passed twice. `cargo clippy --all-targets --all-features -- -D warnings` passed.
