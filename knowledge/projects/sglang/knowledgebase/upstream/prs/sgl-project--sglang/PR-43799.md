- **GLM-5.2 NVFP4 B300 ([InferenceX #3890](https://github.com/SemiAnalysisAI/InferenceX/pull/3890)).** c1/c4/c8/c20 now use 5 EAGLE steps (6 draft tokens) and become their own deployment, "Agg TP8 · MTP 5-1-6". c12–c48 keep 3 steps ("Agg TP8 · MTP 3-1-4").
- **DeepSeek-V4.1 GB300 SGLang ([InferenceX #3859](https://github.com/SemiAnalysisAI/InferenceX/pull/3859)).** All of this lane's deployments move to the `nightly-dev-cu13-20261012-e6072935` image. The new `SGLANG_NUMA_BIND_V2=0` env var (TP2 c8/c16, DEP2) is mirrored as submitted.
- **DeepSeek-V4.1 GB300 Dynamo disaggregated ([InferenceX #3860](https://github.com/SemiAnalysisAI/InferenceX/pull/3860)).** Adds five shapes (1P3D, 2P2D, 2P3D, 2P4D, 2P5D). Every worker gets `SGLANG_DSPARK_FOLDED_SAMPLING=2`. 2P1D's router session-affinity TTL goes from 1 s to 3600 s and its `--mem-fraction-static` from 0.85 to 0.8. The lane shows as in progress until [InferenceX #3860](https://github.com/SemiAnalysisAI/InferenceX/pull/3860) has a measured run.

- Verified at their `/use` runs: DeepSeek-V4 GB200 disaggregated ([InferenceX #3701](https://github.com/SemiAnalysisAI/InferenceX/pull/3701)) and GLM-5.2 FP8 B300 c12 ([InferenceX #3836](https://github.com/SemiAnalysisAI/InferenceX/pull/3836)).

**HiCache donor for DeepSeek-V4.1.** Every DeepSeek-V4.1 deployment's derived HiCache variant borrows its flags from `dsv41flash-fp4-gb300-dynamo-sglang-agentic-disagg`. Only measured lanes donate KV settings, and [InferenceX #3860](https://github.com/SemiAnalysisAI/InferenceX/pull/3860)'s revision of that lane has no measured run yet. So the lane's measured `main` version ([InferenceX #3598](https://github.com/SemiAnalysisAI/InferenceX/pull/3598)'s run) keeps donating, used only as a fallback where no displayed measured lane can donate. Every derived HiCache command on the page stays byte-identical to `main`; the per-deployment note now reads "...launch on InferenceX main".

**Component (`_agentx.jsx`), three small changes:**

- A point's own measured KV tier is always selectable. Before, the KV row enabled only the tiers the deployment could derive, so a point measured with a tier that had no donor showed its "as measured" chip disabled. This sync hit that case before the donor fallback above was added; no point on the current pages is affected.
- A disabled KV chip's sub-label reads "not available"; the tooltip still gives the reason. It used to say "not available for this image", which was wrong for HiCache disabled for lack of a verified donor (Qwen3.8-Flash-Next B300, B200 and H200).
- The derived-HiCache note adds "on InferenceX main" when the donor is the measured `main` version of a lane that an open PR replaces.

## How the commands are produced

The pipeline and rules are the same as in #42726 / #43083. Each lane is rendered at the exact commit of the run that produced its dashboard data or, for an open PR, the run named by its authorized `/use` comment (the PR head when there is none). SA-only settings are removed: the benchmark harness, cluster paths and caches, telemetry, and InferenceX's synthetic speculative acceptance (disclosed per deployment). Placeholders replace IPs, ports and NICs. Router and KV-offload variants that were not run are derived and labeled "Derived — not run".

- **Recipe-only overlays.** [InferenceX #3890](https://github.com/SemiAnalysisAI/InferenceX/pull/3890) changes only the lane's srt recipe; its config entry is unchanged apart from comments. An open PR now also claims a lane whose recipe file it changes.
- **Not mirrored.** `qwen3.5-fp8-h100-sglang-agentic` (H100 without MTP) has never produced dashboard data, so there is no run to pin it to.
- **Images.** [InferenceX #3859](https://github.com/SemiAnalysisAI/InferenceX/pull/3859) pins `lmsysorg/sglang:nightly-dev-cu13-20261012-e6072935@sha256:b5c48869…` (multi-arch). Pruned nightly tags are flagged on the page as before.

The data files are generated; please review the component changes rather than the JSON.
