# [Feat] dwdp: Support DWDP for DeepSeek-V4

[Upstream PR](https://github.com/sgl-project/sglang/pull/39802) · state: open · merged: False

## Original PR description

## Motivation

Three things break when the DWDP MoE path is used with DeepSeek-V4 (`dwdp_size > 1`). They are independent, but all of them only show up under DWDP.

## Modifications

- `python/sglang/srt/layers/moe/dwdp/dwdp_manager.py`: `_allgather_small_params` passed the raw tensor to `dist.all_gather`, but DeepGEMM's `transform_sf_into_required_layout` returns mn-major expert scales (logical `(E, n, sk)`, storage `(E, sk, n)`) and NCCL rejects a non-contiguous input. Added `_memory_major_permutation`, which gathers on the memory-contiguous view and restores the logical dim order before `replace_expert_tensor`.
- `python/sglang/srt/models/deepseek_v2.py`: under DWDP every rank holds a full replica of the shared expert (`moe_dense_tp_size=1`, no cross-rank reduce), so `_shared_expert_use_tp1` must also be true when `dwdp_size > 1`. Without it the shared weight is sharded but never all-reduced, which silently corrupts the output.
- `python/sglang/srt/models/deepseek_v4.py`: skip the DP-attn gather/scatter around the MoE when DWDP is on. DWDP keeps every token on-rank, and under `SGLANG_SCHEDULER_SKIP_ALL_GATHER` the global DP buffer and `global_num_tokens_gpu` are never populated, so gathering there reads a `None` cumsum or an unsized buffer.

## Accuracy Tests

DeepSeek-V4-Flash on 4 GPUs, `--disaggregation-mode null`. The two runs differ only in the DWDP switch.

```bash
# DWDP
python -m sglang.launch_server --trust-remote-code \
  --model-path <DeepSeek-V4-Flash> \
  --tp 4 --dwdp-size 4 --disaggregation-mode null \
  --moe-runner-backend deep_gemm --fp8-gemm-backend deep_gemm \
  --context-length 65536 --max-running-requests 8 --mem-fraction-static 0.8 \
  --skip-server-warmup --allow-auto-truncate --enable-deepseek-v4-fp4-indexer \
  --json-model-override-args '{"index_topk_pattern": "FSSSSSFFSSSFSSSSSSSFF"}' \
  --tool-call-parser deepseekv4 --reasoning-parser deepseek-v4

# baseline: same command, with
#   --tp 4 --dp 4 --ep 4 --enable-dp-attention --moe-a2a-backend none
#   (no --dwdp-size)

sgl-eval run gsm8k  --base-url http://HOST:30000/v1 \
  --num-examples 50 --max-tokens 2048 --num-threads 8
sgl-eval run aime26 --base-url http://HOST:30000/v1 \
  --num-examples 12 --n-repeats 1 --temperature 0.0 --no-thinking \
  --max-tokens 2048 --num-threads 8 --seed 0
```

| benchmark | DWDP | baseline |
|---|---|---|
| GSM8K (n=50) | **98.00%** (49/50) | **98.00%** (49/50) |
| AIME26, no thinking (n=12) | 70.0% (7/10) | 75.0% (9/12) |

On the 10 AIME26 problems both runs completed they agree on 8; the two differences are near misses (366 vs 396, 958 vs 896). The AIME26 sample is small, so it bounds systematic loss rather than proving per-problem equality; GSM8K at n=50 is the stronger signal.

Independent confirmation of the `deepseek_v2.py` hunk on a second model family and on Hopper, including the PD-disaggregated prefill setup that you mentioned wasn't available to you.

**Setup:** GLM-5.3-Flash (built on `DeepseekV2MoE`), FP8, 8x H20 (SM90), `--tp 8 --dwdp-size 8`. I ran a v0.5.21 backport of the same condition.

**Colocated** (`--disaggregation-mode null`). The A/B toggles the same predicate via `SGLANG_SHARED_EXPERT_TP1`.
- Shared expert TP-sharded (without this condition): consistency fails on every prompt, and GSM8K is 0.20 (n=20).
- Shared expert replicated (with it): consistency passes, and GSM8K is 0.98 (n=100).

**PD.** P is DWDP8 with this condition. D is TP8 on a second node. KV goes over mooncake/RoCE, and requests go through the router.
- GSM8K-200: 0.955 with default prefill flags, and 0.945 with `--chunked-prefill-size 65536 --load-balance-method total_tokens`. A TP8 prefill gives 0.940.
- 64k needle-in-a-haystack (48 prompts, 48k-66k tokens): 42/48 for both DWDP-P and TP8-P.

**Regression test.** Since the checklist has no unit test for this predicate yet, I wrote a small CPU one.
- It moves the predicate into a module-level `shared_experts_use_tp1()`. The comment and the conditions are byte-for-byte unchanged.
- It checks two cases: DWDP gives a replicated shared expert, and plain TP keeps it sharded.

Against this PR's head (`4784d80`):
- The patch applies cleanly with `git apply`.
- The DWDP case fails if `get_parallel().dwdp_size > 1` is removed, and passes with it.
- isort, ruff (check and format) and codespell are clean.

Happy to open it as a PR against your branch, or as a follow-up once this merges, whichever you prefer.
