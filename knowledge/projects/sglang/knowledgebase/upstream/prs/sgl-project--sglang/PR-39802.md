# [Feat] dwdp: Support DWDP for DeepSeek-V4

[Upstream PR](https://github.com/sgl-project/sglang/pull/39802) · state: open · merged: False

## Original PR description

## Motivation

Three things break when the DWDP MoE path is used with DeepSeek-V4 (`dwdp_size > 1`). They are independent, but all of them only show up under DWDP.

## Modifications

## Modifications

- `python/sglang/srt/layers/moe/dwdp/dwdp_manager.py`: `_allgather_small_params` passed the raw tensor to `dist.all_gather`, but DeepGEMM's `transform_sf_into_required_layout` returns mn-major expert scales (logical `(E, n, sk)`, storage `(E, sk, n)`) and NCCL rejects a non-contiguous input. Added `_memory_major_permutation`, which gathers on the memory-contiguous view and restores the logical dim order before `replace_expert_tensor`.

- `python/sglang/srt/models/deepseek_v2.py`: under DWDP every rank holds a full replica of the shared expert (`moe_dense_tp_size=1`, no cross-rank reduce), so `shared_experts_use_tp1()` must also be true when `dwdp_size > 1`. Without it the shared weight is sharded but never all-reduced, which silently corrupts the output.

- `python/sglang/srt/models/deepseek_v4.py`: skip the DP-attn gather of the global token ids around the MoE when DWDP is on. DWDP keeps every token on-rank, and under `SGLANG_SCHEDULER_SKIP_ALL_GATHER` the global DP buffer and `global_num_tokens_gpu` are never populated, so gathering there reads a `None` cumsum.

- `python/sglang/srt/models/deepseek_v4_boundary.py`, `python/sglang/srt/models/deepseek_common/moe_transport.py`: the same gate for the MoE hidden-state gather. The stage-boundary refactor moved it out of `deepseek_v4.py`, and the rebuilt path lost the guard:
  - `deepseek_v4_boundary.py` passes `moe_gather=...` explicitly, so `MoeRowTransport` takes the `moe_gather is not None` branch — a guard in `moe_transport.py` alone is unreachable from this call site.
  - `moe_transport.py` derives `_use_tp_moe_gather` from `attn_dp_size` alone; DWDP forces `attn_dp_size == dwdp_size`, so it selects the gather.

  Both now require `get_parallel().dwdp_size <= 1`. Without this, the first request on any DeepSeek-V4 DWDP server aborts with `TypeError: object of type 'NoneType' has no len()` at `dp_attention.py:83` (`dp_slot_in`), for every checkpoint.
## Accuracy Tests

**Unit**: `test/manual/layers/moe/test_dwdp_allgather_permutation.py`, 7/7 on an idle GPU (gather layout + permutation helper, `dist.all_gather` mocked). It does not cover an end-to-end DWDP run.

**End to end**: 4 GPUs, `sgl-eval` 0.1.2, greedy (temperature 0), no truncation. The two runs differ only in the DWDP switch — DWDP is `--tp 4 --dwdp-size 4 --disaggregation-mode null`; the baseline is `--tp 4 --dp 4 --ep 4 --enable-dp-attention --moe-a2a-backend none` (no `--dwdp-size`). Everything else is identical.

Both checkpoints are DeepSeek-V4-Flash W4 builds, covering the two quant layouts this path has to handle:

| Checkpoint | routed experts | attention | `wo_a` | extra flag |
|---|---|---|---|---|
| `DeepSeek-V4-Flash` | MXFP4 (I8 + E8M0) | FP8 | FP8 | — |
| `DeepSeek-V4-Flash-FP8` | FP8 (E4M3) | FP8 | **BF16** | `SGLANG_OPT_FP8_WO_A_GEMM=0` |

Commands:

```bash
# DeepSeek-V4-Flash (MXFP4 experts + FP8 attention + FP8 wo_a)

# DWDP
python -m sglang.launch_server --trust-remote-code \
  --model-path <DeepSeek-V4-Flash> \
  --tp 4 --dwdp-size 4 --disaggregation-mode null \
  --moe-runner-backend deep_gemm --fp8-gemm-backend deep_gemm \
  --context-length 65536 --max-running-requests 8 --mem-fraction-static 0.8 \
  --skip-server-warmup --allow-auto-truncate \
  --tool-call-parser deepseekv4 --reasoning-parser deepseek-v4

# baseline
python -m sglang.launch_server --trust-remote-code \
  --model-path <DeepSeek-V4-Flash> \
  --tp 4 --dp 4 --ep 4 --enable-dp-attention --moe-a2a-backend none \
  --disaggregation-mode null \
  --moe-runner-backend deep_gemm --fp8-gemm-backend deep_gemm \
  --context-length 65536 --max-running-requests 8 --mem-fraction-static 0.8 \
  --skip-server-warmup --allow-auto-truncate \
  --tool-call-parser deepseekv4 --reasoning-parser deepseek-v4


# DeepSeek-V4-Flash-FP8 (FP8 experts + FP8 attention + BF16 wo_a)
# wo_a is BF16: keep it off the fp8 path, or weight loading rejects it with
# "SGLANG_OPT_FP8_WO_A_GEMM is enabled but ...wo_a.weight has dtype BF16".

# DWDP
SGLANG_OPT_FP8_WO_A_GEMM=0 \
python -m sglang.launch_server --trust-remote-code \
  --model-path <DeepSeek-V4-Flash-FP8> \
  --tp 4 --dwdp-size 4 --disaggregation-mode null \
  --moe-runner-backend deep_gemm --fp8-gemm-backend deep_gemm \
  --context-length 65536 --max-running-requests 8 --mem-fraction-static 0.8 \
  --skip-server-warmup --allow-auto-truncate \
  --tool-call-parser deepseekv4 --reasoning-parser deepseek-v4

# baseline
SGLANG_OPT_FP8_WO_A_GEMM=0 \
python -m sglang.launch_server --trust-remote-code \
  --model-path <DeepSeek-V4-Flash-FP8> \
  --tp 4 --dp 4 --ep 4 --enable-dp-attention --moe-a2a-backend none \
  --disaggregation-mode null \
  --moe-runner-backend deep_gemm --fp8-gemm-backend deep_gemm \
  --context-length 65536 --max-running-requests 8 --mem-fraction-static 0.8 \
  --skip-server-warmup --allow-auto-truncate \
  --tool-call-parser deepseekv4 --reasoning-parser deepseek-v4


# Accuracy (same server, once up on port 30000)
sgl-eval run gsm8k  --base-url http://127.0.0.1:30000/v1 \
  --num-examples 50 --max-tokens 2048 --num-threads 8
sgl-eval run aime26 --base-url http://127.0.0.1:30000/v1 \
  --num-examples 12 --n-repeats 1 --temperature 0.0 --no-thinking \
  --max-tokens 8192 --num-threads 8 --seed 0
```

|---|---|---|---|---|
| GSM8K (n=50) | 98.00% (49/50) | 98.00% (49/50) | 98.00% (49/50) | 100.00% (50/50) |
| AIME26, no thinking (n=12, max-tokens 8192) | 75.00% (9/12) | 66.67% (8/12) | 58.33% (7/12) | 66.67% (8/12) |

Per-item diffs — no cell differs by more than one item, and the differences go in both directions:

- **Flash / GSM8K**: identical item by item.
- **Flash / AIME26**: 3 items differ. `aime26-3` (70) and `aime26-10` (896) are correct only under DWDP; `aime26-2` (79) is correct only under baseline. Net +1 for DWDP.
- **Flash-FP8 / GSM8K**: one item (`gsm8k-8`). DWDP's first step reads `3 x 60 = 120` where the baseline reads `180`; the rest of the reasoning follows the same steps, so it finishes at 15 instead of 45. That is a single argmax flip on one token under the small numeric difference of the exchanged-weights path, not a different plan.
- **Flash-FP8 / AIME26**: one item (`aime26-1`, expected 62): DWDP answers 61, the baseline answers 62.
