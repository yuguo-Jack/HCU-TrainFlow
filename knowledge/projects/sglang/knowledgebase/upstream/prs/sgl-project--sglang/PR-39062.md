## Motivation

<!-- Describe the purpose and goals of this pull request. -->
Plain tensor parallelism scales prefill poorly on this model. Measured on 8x B200 (main 480b14edad, prefill only): TP8 is only 1.12-1.14x faster than TP4 above 8K tokens and slower below, and about 76% of the per-token time does not shrink with the TP degree. The reasons are structural: the hyper-connection mixes (20% of TP8 GPU time), the QSA indexer (6%, quadratic in prompt length), the PLE projections and the router are computed on every rank for every token; the two all-reduces per layer move the same bytes at any TP; and the QSA sparse-attention Triton kernel pads the per-rank GQA group of 3 heads to BLOCK_M=16, so its issued work is nearly TP-invariant. Adding TP ranks therefore buys ~13% per doubling.

Hi, thank you for reaching out. I have already considered this approach before and I also implemented a fused CP hidden state update kernel for both GDN and KDA. I do not make this choice because I have a few concern. I hope that you can answer some of them for me. 

1. How do you manage the storage of mamba state? The CP of linear attention does not mean that we partition each sequence into cp segments. It will partition the concatenated sequence where each rank might have different mamba states for different requests. This requires another alltoallv. Otherwise, it's hard to do prefix matching in unifiedRadixTree. 
2. As far as I know, there is no fully fused kernel for CP, but there is fully fused intra parallel kernel for TP. Do you have the SOTA performance benchmark toward them?
3. Do you mean that we will only use your optimization for small CP size? Because, as for low latency area, I believe that we will still use TP for MoE instead of EP. Does it mean that we will use allgather instead of allreduce? The gain will be the performance diff between allgather and allreduce. Is it correct?
