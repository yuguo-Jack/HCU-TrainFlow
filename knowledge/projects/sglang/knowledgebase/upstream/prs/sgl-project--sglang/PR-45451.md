# [Perf] [NVIDIA] minimax-m3: Score EAGLE verify rows in one pass over the index K

[Upstream PR](https://github.com/sgl-project/sglang/pull/45451) · state: open · merged: False

## Original PR description

Depends on #43804; only commits after it are new.

## Motivation

With 4 EAGLE3 draft tokens, MiniMax-M3's sparse layers score each verify token as its own decode row (#41497, #43804), reading a request's index K 4 times. At AgentX c16 on GB300, `_decode_score_kernel` is 15.0 ms of a 36.1 ms verify step (nsys, one rank).

## Modifications

- New `_decode_score_packed_kernel`: a request's `packed_queries` rows share one 16-row dot tile, so each K tile loads once; each row keeps its own length mask, and both kernels run the same 16-row MMA, so max scores equal the per-row kernel's.
- `flash_decode_with_topk_idx` packs on CUDA for score-only layers, whole groups and `packed_queries × gqa ≤ 16`; `minimax_sparse_decode` forwards `packed_queries` (from #42614). SM90 keeps its paged (#46135) and per-row kernels, ROCm the per-row kernel.
- The packed kernel runs one fixed config (BLOCK_SIZE_N 128, 4 warps, 2 stages; within 13 % of a sweep's best): autotune would tune on the 1-token CUDA-graph warm-up rows and differ per rank.
- A second kernel rather than a `PACK` option on `_decode_score_kernel`, so the per-row kernel keeps its CUDA autotune and ROCm heuristics; its chunk-count rule moves unchanged into `_num_kv_chunks`, which #46135's paged launch also calls with its cap of 1024.

Prior art: AMD draft #39466 (needs local_blocks > 0), merged #45251 (DeepSeek-V4.1 indexer).

## Accuracy Tests

GSM8K (sgl-eval 0.1.3 cookbook + `--max-tokens 32768`), MiniMax-M3-NVFP4, 4× GB300 TP4, EAGLE3 at real acceptance, `SGLANG_DISABLE_MSA=1`:

| GSM8K | #43804 | + this PR |
|---|---|---|
| 1,319 q | 96.74 % | 97.12 % |
| 100 q, one at a time | 98 % | 98 % |

- New `test_minimax_sparse_decode_packed_score.py` (22 passed, GB300; B200 CI, skipped on SM90): packed = per-row scores and selected-block scores (max; lse via the Triton top-k), incl. local_blocks 0, fp8 K and graph replay.
- `test_minimax_linear_verify.py` now asserts one packed launch per score-only verify forward (none on SM90) and also runs on B200; it and the decode top-k (160), page-table top-k (38) and sparse kernel (54) tests pass on GB300 after merging main.

[by Claude Code] **Severity: functional | Confidence: Medium**

**Issue**

The PR body says this test relies on #45174, which is still open. On this branch, the CUDA radix top-k in `minimax_decode_topk.cuh` still places final-round ties with `atomicAdd(&smem->counter_final, 1)`. Rows with more than 128 blocks use that path: the `long` and `clamped` cases and `test_graph_replay_at_longer_context`. When two blocks tie at the top-k boundary, the packed and per-row runs can pick different ids, so `torch.equal(got, want)` can fail from run to run.

**Fix**

Land #45174 first and say so in the PR body. Or make the check tie-invariant: `_assert_rows_equal` already proves the scores match, so for block ids compare the sorted `want_score` values at `got` and at `want`.
