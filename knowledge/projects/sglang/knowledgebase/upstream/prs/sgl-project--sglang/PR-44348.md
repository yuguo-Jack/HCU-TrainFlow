# [Fix] hicache: Flush the cache without dying when a storage worker cannot be stopped

[Upstream PR](https://github.com/sgl-project/sglang/pull/44348) · state: open · merged: False

## Original PR description

> **Stacked on #44342 (`hicache/recoverable-storage-sync`, head 74a0e6ba9a) and #44343 (`hicache/bounded-storage-calls`, commits b379b595ab + 4908f3a3dd).** Review only this PR's own commits (the first `Flush the cache without dying ...` commit and the revision-2 commit on top): they build on #44342's rank-agreed storage health bit and on #44343's host-slot quarantine. Draft until both land.
>
> **Revision 2 (additional commit, after a second internal review).** `Scheduler.flush_cache` keeps returning `bool` (the registered flush-cache tests pass unchanged) and reports the wedge by raising `HiCacheStorageWedgedError` once the pools are flushed; the wrapper turns it into the `Cache flushed, but ...` response. Abandoned layout leases on the unified page-envelope pool are keyed by per-acquire tokens instead of thread idents, which Python recycles. A returning abandoned worker can no longer clear the live worker's in-flight slot, issues no further backend call once it learns it is dead, and the PP ticket thread checks its generation right after the broadcast. The two-rank test drives the production `check_hicache_events` round. Message and docs state the `raise`-policy, second-flush and never-returning-worker outcomes.

## Motivation

`/flush_cache` is the operator's remediation for a wedged HiCache storage pipeline, and today it is the one thing that is guaranteed to kill the server: `UnifiedRadixCache.reset()` -> `cache_controller.reset()` joins the storage worker threads for 10 s and raises `Failed to stop HiCache storage threads cleanly`, which escapes `Scheduler.flush_cache` and exits the scheduler on every rank (reproduced 9/9 on a TP2 lane with one hung backend call, both on main and with #43550). #44343 bounds the backend calls so a hung call no longer wedges a worker, but a worker can still be unjoinable when the bound is disabled, when it is stuck in a rank-sync collective whose peer is gone, or when a backend ignores its deadline. Restarting new workers over a live one is not safe either: the stuck worker still owns the host rows of its operation, and when it finally returns it would publish a stale ack into the live queues (one extra ack on one rank misaligns the peers' MIN sequence) and release pages the flush already handed out.

## Modifications

1. **`reset()` never raises; a stuck worker is abandoned, not restarted over.** `HiCacheController.reset()` joins the workers (10 s each) and leaves the ones still alive on a *dead generation*: every worker loop and every publication site checks the generation it was started in, so an abandoned worker neither consumes from nor publishes into the live queues, drops its host releases, and issues no collective once it returns (`_enter_storage_worker` / `_storage_worker_is_live` / `_publish`). The operations the transfer and backup workers were inside (`_inflight_prefetch_op` / `_inflight_backup_op`) get their host spans quarantined through #44343's `HostSlotQuarantine`; the stuck worker releases them in its `finally` when it returns. Fresh workers start on every rank, so no peer is left waiting on a rank without workers, and `reset()` returns the degradation message. `UnifiedRadixCache._reset_full` finishes the tree reset (the host pool is cleared through `clear_host_pool()`, after the quarantine), then raises `HiCacheStorageWedgedError` (defined in `hicache_storage.py`); `Scheduler.flush_cache` catches it, still flushes the device pools, and re-raises it at the end instead of dying, keeping its `bool` return for the ordinary outcomes. `SchedulerFlushWrapper` turns it into `FlushCacheReqOutput(success=False, message="Cache flushed, but HiCache storage worker(s) [...] did not stop within 10s ...")`, the weight updater logs it and lets the update stand (the cache is flushed), and the PD role switch catches it and continues the flip with L3 off. An abandoned worker that returns cannot clear the live worker's in-flight slot (compare-and-clear), issues no further backend call for the rest of its operation (so it never takes a guard lane the live worker needs), and the PP ticket thread re-checks its generation right after `broadcast_pyobj` and skips `task_done()` on the queue a reset replaced.

2. **The degradation is rank-agreed.** The wedged rank sets `storage_wedged_reason`, which `storage_workers_healthy()` (#44342) folds into the MIN-reduced health bit; at the next drain every rank flips `storage_unavailable` together under `storage_failure_policy=disable` (or fails loudly under `raise`). `enable_storage` is never touched rank-locally, so `_sync_hicache_ready_counts` keeps one tensor length on every rank. `detach_storage_backend` refuses while an abandoned worker is still alive (its sync groups and backend are in use) with a message naming the thread; detach and re-attach is the recovery once it has returned.

3. **Unified page-envelope (mori) host pool.** An orphaned or abandoned call holds a layout lease. Leases are per-acquire tokens (`_layout_holders[token] = thread ident`); before the clear, `clear_host_pool()` converts the controller's orphaned and wedged thread idents into the tokens they hold at that moment (`abandon_leases_of`), so a thread ident recycled after the abandoned thread exits can never exempt a later lease. Compaction and `clear()` do not wait for abandoned tokens; the pages those calls may still write are immovable for compaction and survive `clear()` in place, unallocatable until their quarantine is released. After a flush this also removes the scheduler-thread wait on that call in the allocation-path compaction; an orphan created after the last flush is still waited for there, as on main.

4. The two controller extra-config pops (#44342's sync knobs, #44343's call deadlines) are merged into `_apply_storage_extra_config`, validated before any side effect.

Operator story (message and `hicache_best_practices.mdx`): under `storage_failure_policy=disable` L3 is degraded on every rank until the backend is detached and re-attached, which needs the abandoned worker to return (detach is refused while it is alive; if it never returns, the recovery is a restart). A later `/flush_cache` returns 200 but L3 stays disabled until the re-attach. Under `storage_failure_policy=raise` the flush is followed by the scheduler failure at the next HiCache drain on every rank, as that policy asks.

## Speed Tests and Profiling

No hot-path change: one thread-local read per worker publication; the generation check runs only on the worker threads. Not benchmarked at scale.

Unit tests (CPU, `test/registered/unit/mem_cache/test_hicache_flush_wedged_storage.py`, 6 cases, ~20 s): a flush with the bound disabled and a worker stuck in the backend returns the reason instead of raising, restarts a new generation, keeps the stuck operation's host memory quarantined across the pool clear, refuses detach while the worker lives, serves new backups meanwhile, the returning worker publishes nothing into the live queues and releases its quarantine, a reset with nothing in flight stays healthy and a later clean reset does not lift the degrade; an abandoned transfer worker's late acks and host releases are dropped; a two-rank gloo run where only rank 1 wedges at reset ends with `storage_unavailable` on both ranks after one production `check_hicache_events` round and `enable_storage` untouched; the unified page-envelope backing's `clear()` does not wait for an abandoned lease holder and keeps the pinned page mapped in place; compaction leaves a pinned page where it is; abandonment marks the leases held at marking time, so a lease taken afterwards under the same (recycled) thread ident is waited for and `_begin_compaction` still refuses. `test/registered/unit/managers/test_scheduler_flush_cache.py` (8, one new: the wedge message reaches `FlushCacheReqOutput`) and `test_scheduler_flush_cache_after_retract.py` (7, one new: the pools are cleared before the error surfaces) pass with `flush_cache` returning `bool`. Existing suites on this tree: test_storage_call_guard (14), test_hicache_storage_sync_recovery (the knob test also checks the deadline keys), test_pp_prefetch_ticket, test_hybrid_pool_assembler, test_buffer_mode_sidecar, test_hicache_pp_sync_drain, test_storage_prefetch_lifecycle, test_hicache_staged_write_back_dispatch, test_mem_pool_host, test_hicache_host_register, test_unified_hicache_transfer_lifecycle, test_unified_hicache_regressions, test_hicache_file_lru_unit, test_hicache_storage_format_tag, test_dsv4_hicache_l2, test_decode_hicache_tree_core, test_decode_queue_cleanup (205 passed / 3 skipped); test_unified_radix_cache_unittest `-k "prefetch or storage or backup"` (201 passed / 220 skipped) and test_mamba_unittest (12) on one GPU.
