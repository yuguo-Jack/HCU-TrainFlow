# [Feat] [NPU] GLM-4.1V: Add ModelSlim W8A8S support with multimodal serving optimizations

[Upstream PR](https://github.com/sgl-project/sglang/pull/44442) · state: closed · merged: True

## Original PR description

## Motivation

Make GLM-4.1V-9B-Thinking servable on Ascend NPUs with ModelSlim W8A8S quantized weights, and fix the largest remaining vision-prefill gaps found by CANN profiling of the running server: every ViT block re-issued a `cu_seqlens` NPU→CPU transfer (plus a `seq_lens.max().item()` sync) per forward pass, serializing the host behind 27 blocks per image batch and stalling the scheduler under concurrent prefill; and the patch downsampling step ran Conv2D with unfold/permute layout copies (plus internal TransData on non-contiguous inputs) per image batch.

This contributes to the Ascend multimodal workstream in the NPU roadmap #43519.

## Modifications

**Uncompressed ModelSlim W8A8S weights** 
- New `ModelSlimW8A8SInt8` scheme for uncompressed W8A8S exports: dense INT8 weights with encoded INT64 `deq_scale` (requires `--dtype float16`; the encoding is only meaningful for FP16 output), plus per-tensor `input_scale` / `input_offset` / `quant_bias` described by `quant_model_description.json`.
- `NPUW8A8Int8LinearMethod` skips the unused `weight_scale`/`weight_offset` fields that W8A8S exports omit, and creates `aclnn_input_scale` / `aclnn_input_scale_reciprocal` / `aclnn_input_offset` in the expanded per-channel layout the aclnn ops expect.

**CPU sequence-length metadata reuse across ViT blocks** (`32092d1599`)
- `Glm4vVisionModel.forward` (NPU branch) prepares the attention metadata's CPU cumulative sequence endpoints (`actual_seq_lengths_cpu`) and max seqlen once per forward pass, merging the two per-forward D2H transfers and removing the `seq_lens.max().item()` sync point.
- `VisionAscendAttention.forward` consumes the prepared CPU list for every ViT block instead of re-issuing a `cu_seqlens.to("cpu")` round-trip per block, and `seq_len_arg.tolist()` runs only for tensor inputs.

**GEMM-based patch downsampling without layout copies** (`7982403c61`)
- On NPU, the spatial-merge downsampling after the ViT blocks runs as a plain `F.linear` over the natural NHWC layout: the `[N, 2, 2, C]` post-layernorm output is reshaped directly to `[N, K*K*C]`, and the `[O, K*K*C]` GEMM weight is derived once from the already-loaded conv weight and cached — no unfold/permute/reshape copies and no Conv2D TransData on non-contiguous inputs.
- Non-NPU platforms keep the original `nn.Conv2d` path; parameter names, weight shapes/dtypes and checkpoint loading are unchanged. An intermediate variant that enabled `Conv2dLayer(disable_linear=False)` was evaluated and rejected: its unfold/permute copies offset the GEMM gain (±2% on microbenchmarks).

## Usage

Single-card launch (validated configuration, 64GB Ascend NPU):

```
python3 -m sglang.launch_server --model-path GLM-4.1V-9B-Thinking-w8a8s \
  --device npu --attention-backend ascend --tp-size 1 --dtype float16 \
  --context-length 32768 --mem-fraction-static 0.65 --max-running-requests 16
```

`--dtype float16` is required for this export (INT64 `deq_scale` encoding). The vision-path optimizations activate automatically on the NPU GLM-4V path; nothing needs to be configured. BF16 original weights benefit from them the same way.

## Accuracy Tests

Full MMBench DEV EN v1.1 (4876 rotated samples, 1292 CircularEval groups), deterministic answer extraction, greedy decoding, single Ascend NPU, same W8A8S weights as this PR ships:

| Metric | BF16 | W8A8S (this PR) |
| --- | --- | --- |
| CircularEval (GLM extraction) | 87.31% | 86.30% |
| Strict boxed exact-match CircularEval | 87.15% | 86.30% |
| Per-sample accuracy | 90.83% | 90.28% |

The vision-path optimizations are numerically equivalent to the baseline chain: CPU sequence-length metadata is bit-identical (prompt_tokens identical to baseline on all multi-image behavior cases), and the downsample GEMM matches Conv2D to 1.6e-5 relative error (±1 LSB FP16 rounding, same magnitude as quantization noise). Each optimization individually and the combination on this branch pass GSM8K official test first 10 (10/10 after granting the one over-long chain-of-thought a 3072-token budget, invalid=0) plus 3 image QA smoke cases, with greedy outputs semantically identical to the baseline (only benign wording forks inside thinking segments).

## Performance

Fixed-length streaming benchmark, single NPU, same card, three configs run back-to-back in the same order, 4 trials per cell with trial 0 discarded as warmup, per-request P50 over the steady trials; 1024 requests per config, 0 errors, all outputs at requested length. The three columns change one variable at a time: BF16 weights → W8A8S weights (same code) → W8A8S weights + this PR's vision-prefill optimizations:

| Workload | c | TTFT P50 (ms) BF16 / W8A8S / +opt | TPOT P50 (ms) BF16 / W8A8S / +opt |
| --- | --- | --- | --- |
| image_normal (896px, 1024 img tokens) | 1 | 318.5 / 292.8 / **275.8** | 18.6 / 14.8 / **14.9** |
| image_normal | 16 | 2757.6 / 2695.7 / **2273.2** | 23.9 / 18.8 / **19.1** |
| image_large (1792px, 4096 img tokens) | 1 | 1318.8 / 1217.0 / **1182.6** | 19.4 / 15.5 / **15.5** |
| image_large | 16 | 12111.1 / 11319.0 / **10513.1** | 45.3 / 38.3 / **37.5** |
| image_long | 1 | 313.5 / 291.4 / **269.6** | 19.0 / 15.2 / **15.3** |
| image_long | 16 | 2785.1 / 2620.4 / **2289.7** | 23.2 / 18.6 / **18.8** |
| text4096 | 16 | 3761.2 / 2984.7 / **2974.9** | 35.3 / 28.3 / **28.4** |
| text512 | 1 | 78.2 / 72.1 / **73.1** | 17.6 / 13.8 / **13.9** |

Headline numbers:

- **W8A8S vs BF16** (same code): TTFT `−2~−21%` (text4096 c16 −20.6%), TPOT `−15~−22%`. Quantization is a latency win across every workload, not only a memory one.
- **This PR on top of W8A8S**: TTFT image_normal c1 −5.8%, c16 −15.7%, image_large c1 −2.8%, c16 −7.1%, image_long c1 −7.5%, c16 −12.6%; text workloads flat (text4096 c16 −0.3%, text512 c1 +1.0ms/+1.3%, within run-to-run noise for that 72ms cell). No vision scenario regresses.
- TPOT is unchanged by the vision-prefill changes (decode path untouched): every c1 cell moves by <0.1 ms, image_large c16 −2.1%.
- Known follow-up (not in this PR): `down_proj` and the vision tower remain FP16 in the current export; quantizing `down_proj` is the next-largest decode win (est. ~32% of the decode step).
