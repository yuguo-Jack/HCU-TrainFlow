# [NPU] GLM-4.1V ModelSlim W8A8S support with multimodal serving optimizations on Ascend

[Upstream PR](https://github.com/sgl-project/sglang/pull/44442) · state: open · merged: False

## Original PR description

## Motivation

Make GLM-4.1V-9B-Thinking servable on Ascend NPUs with ModelSlim W8A8S quantized weights, and fix the two largest performance gaps found by CANN profiling of the running server:

1. **Multimodal TTFT**: the mm embedding path serialized ViT encoding one image at a time and staged features with a full-device `torch.npu.current_stream().synchronize()`, and NPU was excluded from the cross-request vision batching fast path.
2. **Decode TPOT**: every W8A8S projection launched a separate `AscendQuantV2` activation-quant kernel (121 launches per decode step at bs=1); GLM's residual RMSNorm + bias is the natural fusion point for the consumer projection's activation quant.

This contributes to the Ascend multimodal workstream in the NPU roadmap #43519.

## Modifications

**Uncompressed ModelSlim W8A8S weights** 
- New `ModelSlimW8A8SInt8` scheme for uncompressed W8A8S exports: dense INT8 weights with encoded INT64 `deq_scale` (requires `--dtype float16`; the encoding is only meaningful for FP16 output), plus per-tensor `input_scale` / `input_offset` / `quant_bias` described by `quant_model_description.json`.
- `NPUW8A8Int8LinearMethod` skips the unused `weight_scale`/`weight_offset` fields that W8A8S exports omit, and creates `aclnn_input_scale` / `aclnn_input_scale_reciprocal` / `aclnn_input_offset` in the expanded per-channel layout the aclnn ops expect.

**Vision batching and single-buffer feature staging** 
- NPU is no longer excluded from the cross-request ViT batching fast path in `mm_schedule.py` (the old `_is_npu` guard predates working NPU support).
- Removed the full-device `torch.npu.current_stream().synchronize()` from `get_embedding_and_mask`.
- GLM-4V registers in `_can_skip_pre_embed_feature_move` and uses `materialize_multimodal_features` (one pre-allocated target buffer + per-item `copy_`) instead of `torch.cat(...).type()` in `get_image_feature` / `get_video_feature`, eliminating a redundant device copy of the whole feature batch.

**Fused RMSNorm + activation quant** 
- GLM-4 decoder layers register `input_layernorm.fuse_input_quant(qkv_proj)` and `post_attention_layernorm.fuse_input_quant(gate_up_proj)`.
- The NPU RMSNorm wrapper calls the aclnn fused op `torch_npu.npu_add_rms_norm_quant(x, residual, gamma, scale_f32, offset_i32, beta, epsilon)`, producing the INT8 input for the quantized GEMM and the residual stream in one kernel. The Triton `add_rmsnorm_bias` quant branch was evaluated and rejected: its quantization shows a systematic truncation bias vs the fp32 golden (51.85% exact match), while the aclnn path matches at 99.2% with bit-equal residuals.
- The linear method publishes `aclnn_input_scale_f32` / `aclnn_input_offset_i32` after loading (only when the exported `input_offset` is integral; non-integral offsets keep the separate quant launch), and `apply` passes pre-quantized INT8 input straight to `npu_quant_matmul`.
- The fusion parameters are resolved from `layer.scheme` (where `ModelSlimConfig.get_quant_method` attaches the resolved scheme), not from the quant method object.

## Usage

Single-card launch (validated configuration, 64GB Ascend NPU):

```
python3 -m sglang.launch_server --model-path GLM-4.1V-9B-Thinking-w8a8s \
  --device npu --attention-backend ascend --tp-size 1 --dtype float16 \
  --context-length 32768 --mem-fraction-static 0.65 --max-running-requests 16
```

`--dtype float16` is required for this export (INT64 `deq_scale` encoding). The fused RMSNorm path activates automatically for static W8A8S layers with integral input offsets and falls back to the unfused chain otherwise; it also applies to other ModelSlim W8A8S models whose decoder layers register `fuse_input_quant`. BF16 original weights are unaffected by the fusion (it only applies to quantized layers) but still benefit from the vision batching.

## Accuracy Tests

Full MMBench DEV EN v1.1 (4876 rotated samples, 1292 CircularEval groups), deterministic answer extraction, greedy decoding, single Ascend NPU, same W8A8S weights as this PR ships:

| Metric | BF16 | W8A8S (this PR) |
| --- | --- | --- |
| CircularEval (GLM extraction) | 87.31% | 86.30% |
| Strict boxed exact-match CircularEval | 87.15% | 86.30% |
| Per-sample accuracy | 90.83% | 90.28% |

The fused kernel's fp32-scale rounding shifts INT8 inputs by ±1 LSB vs the original fp16-reciprocal chain, which flips some temperature-0 argmax tokens: 113/4876 samples flip (58 wrong→right, 55 right→wrong), with per-category churn within ±4 and no systematic direction. CircularEval moves by one question in opposite directions on the two scoring variants (main vs strict), i.e. within quantization noise.

## Performance

Fixed-length streaming benchmark, single NPU, 5 workloads (text512/text4096/image_normal(896px,1024 img tokens)/image_large(1792px,4096 img tokens)/image_long) × concurrency {1,4,16} × 3 trials = 876 requests, 0 errors, all outputs at requested length. Baseline → +vision batching → +fused quant:

| Workload | c | TTFT P50 (ms) | TPOT P50 (ms) |
| --- | --- | --- | --- |
| image_normal | 1 | 342 / 281 / **280** | 15.2 / 14.9 / **14.7** |
| image_normal | 16 | 2848 / 2208 / **2347** | 20.7 / 19.7 / **18.3** |
| image_large | 1 | 1276 / 1194 / **1176** | 17.3 / 15.7 / **15.4** |
| image_large | 16 | 11768 / 9806 / **9734** | 36.3 / 33.3 / **32.7** |
| image_long | 1 | 298 / 288 / **284** | 16.6 / 15.3 / **15.0** |
| image_long | 16 | 2754 / 2206 / **2319** | 20.0 / 18.9 / **18.7** |
| text4096 | 16 | 2985 / 2994 / **2993** | 28.8 / 28.3 / **27.6** |
| text512 | 1 | 111 / 77 / **127** | 14.9 / 13.9 / **13.6** |

Headline numbers:

- Image TTFT −18~−23% (P95 up to −59%) from vision batching; TTFT P95 6.5s → 2.7s at image_normal c16.
- TPOT improves another 0.3~1.4ms across all 14 workload/concurrency combinations from the fused kernel (AscendQuantV2 launches per decode step: 121 → 41; the standalone fused op is 6× faster than the unfused chain, 0.029 vs 0.183ms).
- text512 c1 TTFT regresses +9ms (78→87ms, confirmed by same-night A/B on the same card; still 22% below baseline). The aclnn op's host dispatch cost is visible only in small-batch eager prefill; bs≥4096 prefill and graph-captured decode are unaffected. A `num_tokens` gate on the fused path would remove this if it matters, not included here.
- Known follow-up (not in this PR): `down_proj` and the vision tower remain FP16 in the current export; quantizing `down_proj` is the next-largest decode win (est. ~32% of the decode step).
