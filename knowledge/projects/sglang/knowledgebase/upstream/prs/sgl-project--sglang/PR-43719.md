# [PD] Poison the deferred abort ack when a Mooncake send fails

[Upstream PR](https://github.com/sgl-project/sglang/pull/43719) · state: closed · merged: True

## Original PR description

## Motivation

With `SGLANG_DISAGGREGATION_DEFERRED_DECODE_KV_RELEASE` on (the default), decode holds an aborted request's KV pages and metadata slot until every prefill rank acks that its transfer drained, or until the release timeout.

In the Mooncake transfer worker, a submitted send that returns non-zero (`send_kvcache`, `maybe_send_extra`, `send_aux`) concludes the room as Failed and then falls through to the outstanding decrement and `_maybe_ack_drained_abort`. The ack fires as soon as decode's ABORT is registered. But a -1 from Mooncake's `batchTransferSync` does not mean the writes stopped. It returns with the batch still running on two paths:

- Wall-clock timeout: `Transport::freeBatchID` refuses a busy batch (`BatchBusy`), the binding drops the handle, and the slices keep retrying in the worker pool.
- Failed batch: `MultiTransport::getBatchTransferStatus` reports FAILED as soon as any one task fails, while the batch's other tasks may still be in flight. The binding ignores the `BatchBusy` from `freeBatchID` and re-submits every entry as a new batch, up to its retry limit; the last failed attempt returns -1.

Decode receives the drained ack, frees the pages, and the leaked writes can land on pages already reused by another request. The caller cannot tell from the -1 whether anything is still writing.

Decode takes this deferred path on a prefill-reported failure too (`ensure_abort_notified(force_arm=True)` in `decode.py`), so both ABORT orderings reach the bug: ABORT mid-send, or ABORT only after the Failed status.

## Modifications

- Add `MooncakeKVManager._poison_unsettled_send`, which calls the existing `poison_deferred_ack_room` (the same helper NIXL uses for an unsettled handle) when the feature is on.
- Call it at the three sites where a submitted transfer returned non-zero:
  - the KV chunk send;
  - the state send, before the Failed-status check (an ABORT during the send also marks the room Failed, which would otherwise skip the poison);
  - each aux send, per decode rank, right after it fails. The aux write targets decode's metadata slot, which the deferred release also frees. Poisoning only at the all-ranks aggregate misses the case where a later rank stops the room first.
- `CommonKVManager._maybe_ack_drained_abort` drops the targets of a poisoned room. `register_deferred_ack_target` checks the poison and then stores without a lock, so a target registered concurrently with the poison could otherwise still ack. This also covers NIXL's existing poison path.
- Decode then falls back to its release timeout (`SGLANG_DISAGGREGATION_DEFERRED_DECODE_KV_RELEASE_TIMEOUT`, 30s) for that room. A new lifecycle of the same `bootstrap_room` clears the poison as before.

Not changed: the failed-session early exit. Nothing has been submitted for that chunk, and an earlier failed chunk in the room already poisoned it. The KV-chunk site also poisons the `-1` returns where nothing was posted (staging ring too small, stride mismatch); the cost is a 30s hold on decode for a request that already failed.

The complete fix is upstream in Mooncake: expose "failed, writes may still be in flight" on the batch path (the ticket API already distinguishes `FAILED_DRAINED` from `COMPLETION_UNKNOWN`), so sglang can ack a drained failure immediately. Out of scope here.

## Test

Regression tests. Each drives `transfer_worker` (or the ACK helpers) and asserts that no ABORT_ACK is sent:

- `test_failed_send_never_acks_drained`: the KV send fails, with the ABORT arriving either mid-send or after; the ACK returns once the room starts a new lifecycle. Fails on main.
- `test_abort_during_failed_state_send_never_acks`: an ABORT lands during a state send that then fails.
- `test_failed_aux_to_one_decode_rank_never_acks`: two decode ranks. Rank 0's aux send fails, then rank 1 stops the room before its own aux send, either because of an ABORT during the aux send or because rank 1's session is already dead.
- `test_target_registered_during_poison_never_acks` (common): the poison lands between `register_deferred_ack_target`'s check and its store.

The last three fail on the PR's first commit (`d369d92178`) and pass now. The `test_disaggregation_wire.py` fixture gains `_deferred_ack_poisoned_rooms`.
