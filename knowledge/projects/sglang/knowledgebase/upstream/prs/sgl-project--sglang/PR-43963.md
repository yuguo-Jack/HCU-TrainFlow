# [Refactor] multimodal: [MM refactor 5/6] Add a token-space strategy for Qwen VL models

[Upstream PR](https://github.com/sgl-project/sglang/pull/43963) · state: closed · merged: False

## Original PR description

## Motivation

Qwen VL models (Qwen2-VL through Qwen3.5, Qwen3-Omni) are the first token-space models: their placeholders are single special tokens, so expansion can run on the caller's input_ids.

## Modifications

- Move the Qwen media helpers into `multimodal/qwen_vl_media_processing.py`, shared by the legacy processor and the strategy.
- Move the Qwen output assembly (M-RoPE, grids, CUDA IPC marking) into `QwenVLMultimodalProcessorOutputBuilder` (`processors/qwen_vl_token_space.py`). The legacy processor holds one and calls it; its outputs are unchanged.
- Add `QwenTokenSpaceProcessStrategy` (same HF calls and options as the legacy path) and `QwenVLTokenSpaceProcessor`, registered in the token-space mapping.

Serving is unchanged until PR6 selects it. `refactor(move)` commits have reproducible proofs.

Known legacy bug, left for a separate fix: Qwen2.5-VL video passes no metadata, so `second_per_grid_ts` is 0.0833 instead of 1.0; the token-space path gives 1.0, like qwen-vl-utils.

## Tests

- `test_processor_trainer_import.py`: the trainer host runs the Qwen strategy without serving modules.
- `test_qwen3_vl_feature_materialization.py`: CUDA IPC marking goes through the builder.
