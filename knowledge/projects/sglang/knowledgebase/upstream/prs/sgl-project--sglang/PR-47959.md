# [Chore] sgl-router: decouple preprocessing from app state

[Upstream PR](https://github.com/sgl-project/sglang/pull/47959) · state: open · merged: False

## Original PR description

**refactor only - no new logic**

`AppContext` mixes tokenizers and preprocessing configuration with routing policies, KV state, and P/D coordination. 

Passing this entire context into request preparation couples frontend processing to the routing runtime, making it harder to use preprocessing independently or introduce selective feature builds.

This pr introduce an owned `Preprocessor` for stable preparation resources. Pass engine settings and token requirements explicitly, and record preparation outcomes in the serving layer.

This preserves serving behavior and establishes a narrower dependency boundary. Direct submission and feature gating remain follow-up work.
