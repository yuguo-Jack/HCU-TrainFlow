# [DSv4.1][SM90] Fuse inverse RoPE into a single-launch WO-A kernel for decode

[Upstream PR](https://github.com/sgl-project/sglang/pull/44190) · state: open · merged: False

## Original PR description

## Motivation

#42170 (fp8 rope + wo_a fusion). The fused inverse-RoPE + WO-A kernel exists only for SM100. On SM90, DSv4.1 decode runs `fused_rope_inplace(inverse=True)` and then `torch.einsum`.

## Modifications

- `wo_a_bf16_fused_inv_rope`: a single-launch Triton kernel, split-K by head.
  - Inverse RoPE is applied to the last 64-wide K step.
  - The last head to arrive reduces the eight partials.
- `MQALayer` calls it behind `SGLANG_OPT_DSV41_FUSED_WO_A_SM90`, off by default. It runs on SM90 with bf16 wo_a, 1–2 local groups and at most 16 tokens.
- KernelSpec, kernel tests and a manual benchmark.

## Accuracy Tests

- Relative error against an fp64 reference matches cuBLAS einsum (~1.7e-3).
- A dummy-weight 4-layer V4.1 model gives identical greedy outputs with the flag on and off.
- compute-sanitizer racecheck reports 0 hazards.

## Speed Tests and Profiling

Measured on H100 NVL with cold L2, replayed from a CUDA graph. Unfused / fused, in µs:

| T | G=1 | G=2 |
|---|---|---|
| 1 | 8.62 / 7.27 | 11.54 / 9.77 |
| 4 | 9.14 / 7.70 | 11.49 / 10.18 |
| 8 | 8.94 / 7.85 | 11.55 / 10.60 |
| 16 | 9.16 / 8.23 | 11.72 / 11.04 |

Could anyone with 8×H200 run GSM8K and ITL with the flag on vs off before it defaults on?
