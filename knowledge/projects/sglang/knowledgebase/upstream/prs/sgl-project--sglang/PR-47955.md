# [Perf] srt: Record per request whether an extend row completes its prompt

[Upstream PR](https://github.com/sgl-project/sglang/pull/47955) · state: closed · merged: True

## Original PR description

## Motivation

#45487 gave `ForwardBatch` a host-side `contains_last_prefill_chunk`: one `bool` saying whether *any* request in a non-speculative extend batch finishes its prompt on this forward. That is enough to gate batch-wide work, but model code that acts per request on the forward that finishes that request's prompt (a head that reads the prompt's last token for some rows and not others, an output row published once per request) still has no host-side way to tell *which* rows those are. The device-side alternative is the same one the batch-level flag removed: compare `extend_prefix_lens + extend_seq_lens` with `orig_seq_lens` and sync, once per extend forward.

## Modifications

- `ForwardBatch.extend_is_final_cpu: Optional[List[bool]]`, snapshotted by `init_new` for non-speculative extend batches, one entry per `batch.reqs` row in order. A row is final when its extend ends at `len(full_untruncated_fill_ids)` (so resumed and retracted prompts are handled the same way as fresh ones), or when it is a running decode request mixed into the extend batch, since that row also produces a token on this forward. Decode batches and synthetic capture or replay batches leave it `None`.
- `contains_last_prefill_chunk` is now derived from the same list, ignoring the mixed-in decode rows as before, so the two fields cannot disagree.
- `TboForwardBatchPreparer.filter_batch` slices the new list per child batch, alongside the other per-request CPU lists (`extend_seq_lens_cpu`, `extend_logprob_start_lens_cpu`, ...), instead of inheriting the parent's whole list.

No reader inside this repository consumes the list yet; the batch-level flag keeps its meaning and its readers.

## Accuracy Tests

Not applicable: no numerics change. The field is a new host-side list derived from request bookkeeping that `init_new` already reads.

## Benchmarking and Profiling

Not run: the change replaces one Python generator over `batch.reqs` per extend forward with a list of the same length plus one `zip` over it; no device work is added.

## Checklist

- `test/registered/unit/managers/test_schedule_batch_out_of_place.py::TestForwardBatchPrefillCompletion` now also checks `extend_is_final_cpu` across `NONE`/`EAGLE`/`EAGLE3`, mixed and zero-token requests: the mixed-in decode row is final, the incoming request follows its chunk, a later change to `req.extend_end` does not move the snapshot, and `dataclasses.replace` preserves it.
- `test/registered/unit/batch_overlap/test_tbo_filter_batch_marker.py::test_filter_batch_slices_extend_completion_per_request` checks that `filter_batch` hands each child its own slice and leaves the parent untouched.
- Both test files on CPU: red on current `main` (`AttributeError: 'ForwardBatch' object has no attribute 'extend_is_final_cpu'`, 31 failed), green on this branch (17 passed, 40 subtests passed).
- `pre-commit run --files` on the four changed files passes.
