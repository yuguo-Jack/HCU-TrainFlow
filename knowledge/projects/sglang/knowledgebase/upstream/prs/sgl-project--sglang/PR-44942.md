# [Fix] openai: Fix multi-turn reasoning history replay for empty reasoning (#44932) and gpt-oss thinking templates (#44931)

[Upstream PR](https://github.com/sgl-project/sglang/pull/44942) · state: open · merged: False

## Original PR description

## Motivation

Fixes #44931 and #44932.

1. **Multi-turn tool-call replay fails with HTTP 400 when a reasoning model emits empty thinking (`#44932`)**:
   - When a reasoning model (e.g. DeepSeek-V3.2 / Kimi-K2.5 / Qwen3) emits an empty reasoning block (`<think></think>`) before a tool call, `ReasoningParser.parse_non_stream` returns `reasoning_text == ""`.
   - For non-K2 parsers, `serving_chat.py` normalizes `""` to `reasoning_content: null` in the `ChatCompletionResponse`.
   - When standard OpenAI-compatible SDKs/agents replay that assistant message verbatim in the next turn (`{"role": "assistant", "reasoning_content": null, "tool_calls": [...]}`), `_validate_MultiTurn_reasoning_support()` could not distinguish an explicitly replayed `reasoning_content: null` from a client that omitted the reasoning field entirely, rejecting the request with HTTP 400.

2. **Multi-turn thinking blocks are silently dropped for `gpt-oss` and other templates reading `message.thinking` (`#44931`)**:
   - In `process_content_for_template_format()`, assistant `reasoning_content` is populated on the template message dict, but templates like `openai/gpt-oss-120b` check `message.thinking` in Jinja (`{%- if "thinking" in message %}`).
   - As a result, multi-turn thinking blocks passed via `/v1/messages` (Anthropic API) or `/v1/chat/completions` (OpenAI API) were silently omitted from the rendered prompt for `gpt-oss` models.

## Modifications

- **`protocol.py` / `serving_chat.py` / `chat_encoding.py`**:
  - Track whether `reasoning_content` or `thinking` was explicitly provided on `ChatCompletionMessage` via `has_explicit_reasoning_field()`, allowing explicitly replayed `reasoning_content: null` to pass multi-turn validation and normalize to `""` for template/encoding rendering while still rejecting assistant tool-call turns where the reasoning field was omitted entirely.
- **`jinja_template_utils.py`**:
  - Synchronize `reasoning_content` and `thinking` in `process_content_for_template_format()` so Jinja chat templates inspecting either `message.reasoning_content` or `message.thinking` (such as `gpt-oss`) receive the assistant reasoning text.
- **Unit Tests**:
  - Added tests in `test/registered/unit/entrypoints/openai/test_serving_chat.py` and `test/registered/unit/entrypoints/anthropic/test_serving.py` verifying empty reasoning replay, omitted reasoning rejection, and `gpt-oss` multi-turn thinking template rendering.
