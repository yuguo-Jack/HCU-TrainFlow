# [Fix] step5: Register Step5 HiCache pool names in the Rust tree core

[Upstream PR](https://github.com/sgl-project/sglang/pull/44511) · state: closed · merged: True

## Original PR description

`_reduce_prefetch_ack` passes every Python `PoolName` member to the Rust tree core, but `parse_pool_name` does not know the three Step5 pools. The first L3 prefetch commit then crashes every scheduler with `ValueError: unknown pool name: step5_fp8_k_scale` (BF16 KV included). This adds `step5_compressed_index_key`, `step5_fp8_k_scale` and `step5_fp8_v_scale` to the Rust `PoolName`.

Verified on Step-5-Preview, 4x GB300 TP4, BF16 KV, HiCache + Mooncake L3: greedy outputs on storage hits match device hits bit for bit (8/8), and no scheduler crash. Before the fix it crashed on the first storage prefetch.
