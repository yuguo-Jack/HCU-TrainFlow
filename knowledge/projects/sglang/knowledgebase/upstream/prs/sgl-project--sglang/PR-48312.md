# [Perf] logprobs: Pack readback and cache cumulative stream encoding

[Upstream PR](https://github.com/sgl-project/sglang/pull/48312) · state: open · merged: False

## Original PR description

## Motivation

Top-k and token-ID logprobs currently incur one device-to-host transfer per row. Native cumulative `/generate` streams then encode the entire logprob history for every chunk. This PR combines batch-packed readback and cached cumulative JSON encoding while preserving response values and bytes.

## Modifications

- Keep next-token top-k matrices and requested token-ID logprobs packed through readback, then reconstruct per-request host lists. Mixed K, empty probe lists and speculative multi-position rows retain their ordering.
- Build large token-ID gather indices with NumPy in pinned host memory; keep the cheaper list path for up to 128 IDs.
- Preserve packed results across pipeline-parallel metadata instead of pickling every row's shared backing storage. MLX and existing per-row results retain their fallback.
- Cache encoded prefixes only for append-only cumulative lists in native logprob streams. A cold, already-finished response uses the ordinary encoder directly. Document the append-only invariant and `SGLANG_ENABLE_CACHED_STREAM_ENCODING` escape hatch; older orjson versions retain ordinary encoding.

Related work: [#48208](https://github.com/sgl-project/sglang/pull/48208) batches only speculative top-k rows when every request has the same K. This change covers ordinary decode, heterogeneous K, token-ID probes, pipeline transport and cumulative HTTP encoding. [#46557](https://github.com/sgl-project/sglang/pull/46557) enables a final-only flat output format on streams; this PR preserves the existing cumulative nested response format.

## Accuracy Tests

```bash
PYTHONPATH=python .venv/bin/python -m pytest -q \
  test/registered/unit/layers/test_logprob_chunk_stitching.py \
  test/registered/unit/utils/test_json_response.py \

```

These exercise packed/per-row value equality, mixed and large probe sets, speculative chain/tree layouts, pipeline pickle round-trips, cumulative chunk byte equality through TokenizerManager, and the HTTP route's gating. CUDA variants and multi-rank pipeline execution were not run on this host.

The pipeline payload-size regression was reproduced on the original supplied patch, then fixed. The same test asserts both finalized values and sub-quadratic payload growth:

```bash
PYTHONPATH=python .venv/bin/python -m pytest -q \
  test/registered/unit/layers/test_logprob_chunk_stitching.py::TestNextTokenLogprobReadback::test_pp_payload_size_scales_linearly_with_requested_logprobs
```

Before the repair: **failed**, `2398992 not less than 1535532.5`; 32/64 rows produced 614,213/2,398,992-byte payloads. After the repair: **passed**, 20,783/39,345 bytes. Each row requests 128 token IDs and top-5 logprobs. The repair keeps one storage per packed tensor rather than one copy of that storage per row.

The supplied archive separately reports deterministic-inference probes matching base versus packed readback (8/8 mixed-batch and 4/4 single requests), and stream byte-identity checks passing. At default non-batch-invariant kernels it records a first-position logprob shift of about 5e-5 in some runs, with unchanged tokens and batch-formation differences. These GPU results are historical and have not been rerun on this branch.

## Speed Tests and Profiling

Historical results from the supplied archive, SGLang `99fd010`, Qwen3-8B, one H100 80 GB, native cumulative `/generate`, random input/output lengths 512/128, total concurrency 256, four benchmark clients, one measured run per arm:

| Request | Baseline output tok/s | Packed readback + encoder | Change |
|---|---:|---:|---:|
| Top-5 logprobs | 3,634 | 4,948 | +36.2% |
| Sampled logprob only | 5,987 | 6,131 | +2.4% |
| No logprobs | 6,289 | 6,293 | +0.1% |

The encoder-only run reports top-5 main-process CPU dropping from 190 to 112 microseconds/token. Packed readback alone improves server decode throughput while native streaming remains bottlenecked downstream; that server decode number should not be mistaken for end-to-end throughput. These single-pair measurements do not establish variance, and current-branch GPU benchmarks remain pending.

Reproduction shape: launch `python -m sglang.launch_server --model-path Qwen/Qwen3-8B --cuda-graph-max-bs-decode 512` on each revision. Run four simultaneous `python -m sglang.benchmark.serving` clients, each with `--backend sglang --dataset-name random --random-input-len 512 --random-output-len 128 --random-range-ratio 1.0 --num-prompts 512 --max-concurrency 64 --return-logprob --top-logprobs-num 5`. Repeat without `--top-logprobs-num 5`, and with both logprob options omitted; aggregate completed output tokens over the shared elapsed interval.

The encoder retains one encoded copy of each active request's cached lists and releases it on the final chunk. Incremental streams and OpenAI endpoints do not use it. Pipeline transport still follows the existing nested-metadata pickle path, now with one packed storage; multi-rank GPU validation remains necessary.
