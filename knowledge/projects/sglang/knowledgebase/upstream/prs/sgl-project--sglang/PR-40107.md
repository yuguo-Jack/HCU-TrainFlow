# [Fix] Preserve sampler customized_info across PD disaggregation

[Upstream PR](https://github.com/sgl-project/sglang/pull/40107) · state: open · merged: False

## Original PR description

## Why is this change needed?

Prefill samples the first output token, but its sampler-provided `customized_info` does not reach decode. For a sampler that copies each generated token into metadata, output tokens `[101, 102, 103]` currently produce:

```diff
- "sampled_token_ids_copy": [102, 103]
+ "sampled_token_ids_copy": [101, 102, 103]
```

Transfer the first token's metadata through the existing PD buffers using MessagePack and the existing NumPy/tensor codecs. Tensors are restored on CPU instead of inheriting the sender's GPU ordinal.

The per-request buffer defaults to 4 KiB, configurable with `SGLANG_DISAGG_CUSTOMIZED_INFO_MAX_BYTES`. Oversized or unencodable payloads fail only the affected request. NIXL and Mooncake reject missing or incompatible per-slot sizes before writing to that peer, without killing the transfer worker. Both sides must use matching upgraded builds and capacity settings; there is no capacity negotiation.

## Test Plan

- Reuse the existing sampler probe in the unified-memory PD parity tests, checking scalar and array metadata against every output token, including the first.
- Test layout variants once in the shared validator, with one incompatible-then-healthy request regression per backend. Both backend regressions failed against the pre-fix revision because the incompatible request incorrectly succeeded.
- CPU validation: 552 tests and 185 subtests passed; 17 skipped. Covers the disaggregation unit directory plus auxiliary-output, speculative-grammar, and MessagePack IPC suites, including payload roundtrips, capacity settings, and request-local cleanup.
- Changed-file pre-commit checks passed. GPU CI for this revision is pending; no local cross-node RDMA or performance benchmark.

This strict check will break decode-only spec decoding. If prefill runs without spec and decode runs EAGLE, `disagg_hidden_size` is decided per side (`scheduler.py:1495`, 16 x fp32 on P vs the draft hidden size on D), so the `output_hidden_states` item len is different and every request will be rejected here. I think we only need to check the buffer count and the two customized_info buffers here. Also please add a unit test for P w/o spec + D with EAGLE, none of our PD spec CI tests cover this case.

QQ: what if the sampler uses non-str keys? e.g. `{1: [...]}` encodes fine here, but `get_customized_info` decodes with `dict[str, list[object]]`, so decode raises `msgspec.ValidationError` in `_commit_transfer_to_req`. Maybe decode the payload once here with the same type and raise `CustomizedInfoError` if it fails, then it goes through the request-level abort path you already have.
