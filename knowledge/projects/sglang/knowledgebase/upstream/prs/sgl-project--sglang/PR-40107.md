# [Fix] disaggregation: Preserve sampler customized_info across PD

[Upstream PR](https://github.com/sgl-project/sglang/pull/40107) · state: open · merged: False

## Original PR description

## Why is this change needed?

Prefill samples the first output token, but its sampler-provided `customized_info` does not reach decode. For a sampler that copies each generated token into metadata, output tokens `[101, 102, 103]` currently produce:

```diff
- "sampled_token_ids_copy": [102, 103]
+ "sampled_token_ids_copy": [101, 102, 103]
```

Transfer the first token's metadata through the existing PD buffers using MessagePack and the existing NumPy/tensor codecs. Tensors are restored on CPU instead of inheriting the sender's GPU ordinal.

The per-request buffer defaults to 4 KiB, configurable with `SGLANG_DISAGG_CUSTOMIZED_INFO_MAX_BYTES`. Oversized, unencodable, or schema-invalid payloads fail only the affected request. NIXL and Mooncake validate buffer counts and the two customized-info slot sizes before writing to a peer, without killing the transfer worker. Hidden-state widths may differ when only decode uses speculative decoding. Both sides must use matching upgraded builds and capacity settings; there is no capacity negotiation.

## Test Plan

- Reuse the existing sampler probe in the unified-memory PD parity tests, checking scalar and array metadata against every output token, including the first.
- Test layout variants in the shared validator, including non-speculative prefill with EAGLE-sized decode hidden states, plus one incompatible-then-healthy request regression per backend.
- Extend the existing request-local cleanup test with non-string sampler keys. Both new review regressions fail before their fixes and pass afterward.
- CPU validation: 769 tests and 407 subtests passed; 20 skipped. Covers the disaggregation unit directory, auxiliary-output, speculative-grammar, MessagePack IPC, NVFP4 dispatch, and CP strategy suites.
- Changed-file pre-commit checks passed. GPU CI for this revision is pending; no local cross-node RDMA or performance benchmark.

This strict check will break decode-only spec decoding. If prefill runs without spec and decode runs EAGLE, `disagg_hidden_size` is decided per side (`scheduler.py:1495`, 16 x fp32 on P vs the draft hidden size on D), so the `output_hidden_states` item len is different and every request will be rejected here. This setup works on main now, see `common/conn.py:1518`, and #30222 already hit the same issue on the NIXL KV side.

I think we only need to check the buffer count and the two customized_info buffers here. Also please add a unit test for P w/o spec + D with EAGLE, none of our PD spec CI tests cover this case.

QQ: what if the sampler uses non-str keys? e.g. `{1: [...]}` encodes fine here, but `get_customized_info` decodes with `dict[str, list[object]]`, so decode raises `msgspec.ValidationError` in `_commit_transfer_to_req`.
