# [Fix] ollama: Normalize chat inputs and bound default output tokens

[Upstream PR](https://github.com/sgl-project/sglang/pull/44426) · state: open · merged: False

## Original PR description

Continues #37730. GitHub currently rejects reopening the original closed PR; this uses the same updated branch and retains the original discussion as context.

## Motivation

Fixes #37711.

The Python Ollama chat route can pass a mapping returned by apply_chat_template into input_ids, causing request normalization to fail. Its fixed 2048-token completion default can also exceed the remaining model context. Request flat token IDs and bound only the implicit completion default by the available context.

## Modifications

- Request return_dict=False from the chat template and use the prompt length for context-aware defaults in both routes.
- Preserve explicit num_predict and the 2048-token cap; subtract reserved tokens and support model-config context metadata.
- Exercise real GenerateReqInput normalization in the fake manager, cover streaming chat input, context exhaustion, fallback metadata, and explicit limits. Streaming-output fixes in #42151 remain separate.
