# [Fix] [NPU] memory-saver: Drain device before sleep unmap and preserve runtime tensor attrs

[Upstream PR](https://github.com/sgl-project/sglang/pull/48289) · state: open · merged: False

## Original PR description

## Motivation

In RL-colocated serving (slime / verl), the rollout engine loops `release_memory_occupation -> training -> resume_memory_occupation -> update_weights_from_disk` on every iteration. On Ascend NPU (910B A3) with `--enable-memory-saver`, this loop deterministically corrupted the model: after `sleep -> resume -> update_weights_from_disk(correct weights)` the engine emitted stable garbage outputs for **every** request, and further weight updates never recovered it.

Two independent defects combine here:

1. `release_memory_occupation` synchronized the device only **after** all unmaps, so the TMS unmap raced in-flight async work (kernels, D2H copies), corrupting pages behind stable virtual addresses that captured graphs happily replay.
2. Plain tensor attributes (neither parameters nor buffers) held by modules or by non-Module helper objects (MoE dispatchers, quant methods) are not covered by `_export/_import_static_state` — anything they carry across sleep is silently lost (the "virtual address stability ≠ value preservation" failure class of vLLM RFC #53343; vllm-ascend #13352 fixed the same class case-by-case).

## Modifications

- `weight_updater.py`: synchronize the device **before** the first pause (covers every unmap, including `kv_cache`) and again after the weights export D2H copies, before unmapping `weights`.
- new `utils/sleep_state_utils.py`: generically export/restore every persistent device tensor reachable as a plain module attribute (containers and non-Module helper objects included; CPU snapshots so the export does not inflate device memory). Gated by `SGLANG_SLEEP_STATE_RESTORE` (default on).
- content audit across release → resume over parameters + buffers + runtime tensors, gated by `SGLANG_SLEEP_STATE_AUDIT=1` — reports any state the restore paths still miss; this is what localized the root cause on hardware.

## Validation (Ascend 910B A3, Qwen3-30B-A3B bf16, TP=2 EP=2, deepep)

Deterministic 5-prompt greedy comparison around the full RL cycle, three independent runs (two on 2026-11-02, one on 2026-11-04), all consistent:

| experiment | before | after |
|---|---|---|
| sleep → resume → update_weights_from_disk(same weights) | stable garbage 5/5, never recovers | == no-sleep update reference, SAME 0/5 |
| second sleep → update cycle | same garbage | SAME 0/5 |
| update modified weights | garbage changes | takes effect |
| audit diff across release → resume | — | only parameters change (level-2 discard by design); buffers/runtime 0 |
