# [Feat] [NPU] qwen4: Support Qwen3.8-Flash-Next W8A8 inference with QSA on Ascend A2

[Upstream PR](https://github.com/sgl-project/sglang/pull/43102) · state: open · merged: False

## Original PR description

## Motivation

Enable Qwen3.8-Flash-Next W8A8 text inference on Ascend A2, including the QSA indexer and sparse attention beyond the checkpoint's 2048-token selection budget. The goal is to support chunked prefill, decode, prefix-cache reuse and decode-graph execution through SGLang's existing model and serving interfaces.

The model architecture is already upstream. This PR adds NPU execution paths and connects the QSA kernels to the model, cache layout and graph metadata.

## Modifications

- **Model execution:** Add NPU sigmoid-gated normalization with FP32 computation and support for gating before or after normalization. Use actual tensor devices to keep PLE, GatedResidual and attention-gate operations from entering CUDA-only paths through torch-npu compatibility aliases.
- **QSA indexer:** Reuse the shared indexer forward logic on NPU, dispatching packed MQA for prefill, paged MQA for decode, Top-K selection and index expansion to the NPU kernel implementations.
- **Sparse attention and cache layout:** Connect NPU sparse prefill/decode to the attention backend and expose the rank-4 NPU KV cache as storage-sharing rank-3 views without copying the cache.
- **Decode graphs:** Read live request IDs and request-to-token mappings during QSA replay, skip diagnostic assertions that trigger a synchronizing CPU fallback on NPU, and preserve FIA replay input updates for dense fallback. Expose `SGLANG_NPU_ALLOW_INTERNAL_FORMAT` with a targeted troubleshooting hint for unsupported aclop capture. On the previously tested CANN 9.0.0 stack, the Conv2D internal-format path uses an aclop operator that cannot be captured in an NPU graph.
- **Bounded fallback:** Add an explicit dense-attention option for contexts within `indexer_budget` and reject larger resolved contexts. Propagate the active-QSA state through model construction, attention selection, cache allocation and memory accounting, and speculative-worker setup; skip unused indexer weights and cache allocation in this mode.
- **Regression tests and documentation:** Add focused coverage for normalization, device dispatch, fallback configuration, NPU QSA routing and graph mappings; document the fallback and internal-format environment variables.

The QSA integration builds on [#37570](https://github.com/sgl-project/sglang/pull/37570) and [sgl-kernel-npu #807](https://github.com/sgl-project/sgl-kernel-npu/pull/807), with contributor attribution in the commits. `a5364f440a` is our QSA integration commit, adapted from #37570.

W8A8 loading uses the existing ModelSlim implementation.

## Accuracy Tests

### Long-context retrieval and concurrency

These tests retrieve random record values. The tests cover two types of cases:

- Single-record cases retrieve a value inserted near the 10%, 50% or 90% position in a repeated background document.
- Two-record cases retrieve values from both the 10% and 90% positions in the requested order.

An excerpt of a 32K two-record case is:

```text
Read the reference records and answer the question at the end.
Background record: ordinary weather observations were archived for this period.
Background record: ordinary weather observations were archived for this period.
Background record: ordinary weather observations were archived for this period.
...
The value for record_3_0 is Q8b0ee4f2299df23a.
[The same background records are repeated]
The value for record_3_1 is Q737b515056dafeac.
[The same background records are repeated]
Return the values for record_3_0, record_3_1 in that order, separated by commas. Output only the values; no explanation.
```

> Expected answer: `Q8b0ee4f2299df23a, Q737b515056dafeac`.

The background sentence is repeated until the entire tokenized prompt contains 32,768–32,831 tokens. Generation uses greedy decoding with a maximum of 96 output tokens.

### GSM8K

We evaluated the first 128 GSM8K test questions in their original order using sgl-eval 0.1.3 and dataset revision `3101c7d507`. Evaluation settings were zero-shot prompting, temperature 0, top_p 1, seed 42, thinking disabled, client concurrency 2, and an output limit of 1800 tokens.

| Accuracy | Length-limited | Transport errors |

| 125/128, 97.65625% | 2 | 0 |

The requests in this run therefore **do not cross** the 2048-token sparse-selection budget.

## Speed Tests and Profiling

The performance tests used the same TP8 deployment. The client concurrency was set to 1, 2, 4 or 8. At each concurrency setting, we ran 12 warmup requests, flushed the prefix cache, and then **measured 48 requests** with **4096 input** tokens and **128 output** tokens each. Input prompts were constructed by repeating and truncating tokenized GSM8K question text to 4096 tokens. Generation used temperature 0 and `ignore_eos=true`.

All four concurrency settings reported 0% prefix-cache reuse.
