# Enrich chat_parsing streaming events

[Upstream PR](https://github.com/sgl-project/sglang/pull/40478) · state: open · merged: False

## Original PR description

Extend `chat_parsing` streaming events with just enough context for serving adapters, while keeping parsing results unchanged.

## Context

Transformers [response templates](https://huggingface.co/docs/transformers/main/en/chat_response_parsing) describe how generated text is split into structured message fields. The core parser can already parse those fields, but its original events are intentionally minimal.

A serving adapter needs a little more: where each delimiter sits in the parser input, the tool name captured by an opener before the region body exists, and a way to recover when one region fails to parse. Without that, every serving library has to reconstruct parser state on its own.

## Event contract

| Event | Keys added by this PR | Meaning |
| --- | --- | --- |
| `region_open` | `start`, `end`, `captures` | Span of the opening delimiter in `input_text` (empty for implicit opens). Explicit opens also carry the opener's named groups. |
| `region_chunk` | none | `text` is raw region text. `dirty=False` only for untransformed `text` fields; whitespace trimming still happens at close. |
| `region_close` | `start`, `end` | Span of the closing delimiter (empty at implicit boundaries and end of stream), alongside the parsed `value`. |
| `region_malformed` | new event | Replaces `region_close` when a region's value fails to parse or transform. Carries `start`, `end`, and the original `error`. |

- `ResponseParser.input_text` exposes the raw input after start-anchor truncation. Before the first `feed()` it is exactly the truncated prefix, so its length marks where generated text begins.
- Prompt bytes held back at the end of the prefix as a possible delimiter are not re-emitted as generated `region_chunk` text.
- Named opener captures let an adapter resolve a tool name as soon as the opener matches, then wait for the close event before emitting parsed arguments.

## Malformed output

- **Streaming:** a region that fails to parse ends with `region_malformed` and parsing continues, so later content and valid calls still parse.
- **Non-streaming:** `parse_response()` re-raises the original exception from the first malformed region, even when required fields are also missing.

## Scope

The grammar, transforms, and tool-argument coercion are unchanged. This PR only enriches the event and recovery contract consumed by the adapters in the next layer.

Stacked on [Port chat_parsing core](https://github.com/sgl-project/sglang/pull/40477).
