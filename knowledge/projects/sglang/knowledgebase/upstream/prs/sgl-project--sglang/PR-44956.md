# [Fix] openai: Align DeepSeek DSML streaming unknown-tool filtering and tag prefix guards (#44941)

[Upstream PR](https://github.com/sgl-project/sglang/pull/44956) · state: open · merged: False

## Original PR description

## Motivation

Fixes #44941.

Cross-pollinates `BaseFormatDetector` / vLLM unknown-tool validation and exact partial-token suffix matching into `DeepSeekV32Detector` (shared by `DeepSeekV3.2`, `DeepSeekV4`, and `DeepSeekV4.1`):

1. **Streaming vs. Non-Streaming Disagreement on Unknown Tool Calls**:
   - `DeepSeekV32Detector.detect_and_parse()` delegates to `self.parse_base_json()`, which drops tool calls whose function name is not in `self._get_tool_indices(tools)` unless `SGLANG_FORWARD_UNKNOWN_TOOLS` is set.
   - `DeepSeekV32Detector.parse_streaming_increment()` bypassed `parse_base_json()` and constructed `ToolCallItem` directly without checking `_get_tool_indices(tools)` or `SGLANG_FORWARD_UNKNOWN_TOOLS`, causing streaming responses to emit undefined tool calls that one-shot responses reject.

2. **Non-DSML Fullwidth-Bar Tags (`<｜end｜>`) Stall Streaming Indefinitely**:
   - `parse_streaming_increment()` buffered whenever `current_text` contained `f"<{bar}"` (`<｜`), which matches any fullwidth-bar special token in prose (e.g., `<｜end｜>`), holding all subsequent normal text in `self._buffer` until `finish()`.

3. **Bare `｜DSML｜` Mention in Prose Truncates Text at Stream End**:
   - Both `potentially_dsml` and `_text_before_dsml()` matched bare `self.dsml_token` (`｜DSML｜`) even without a leading `<` or `</`. When a response mentioned `｜DSML｜` in plain prose (e.g., `"The tag ｜DSML｜ marks tool calls."`), streaming stalled and `finish()` truncated everything from `｜DSML｜` onward.

## Modifications

- **`python/sglang/srt/function_call/deepseekv32_detector.py`**:
  - Check `func_name in tool_indices` in `parse_streaming_increment()` after initial preamble/state setup and skip unknown tools (logging a warning) unless `envs.SGLANG_FORWARD_UNKNOWN_TOOLS.get()` is enabled, preserving `tool_index` numbering for subsequent valid calls and withholding trailing `</｜DSML｜...>` tags on `finish()`.
  - Replace the overly broad `<｜` and bare `｜DSML｜` substring checks with `_has_dsml_tag()` and `_has_partial_dsml_tag_suffix()` (using `BaseFormatDetector._ends_with_partial_token()`), and anchor `_text_before_dsml()` on actual DSML tool-call tags (`bot_token` / `invoke_start_token`) or their trailing partial prefixes.
- **`test/registered/unit/function_call/test_deepseekv4_detector.py`**:
  - Added unit tests covering streaming vs. non-streaming unknown-tool filtering (both default and with `SGLANG_FORWARD_UNKNOWN_TOOLS=True`), unknown-only invoke `finish()` cleanup, `<｜end｜>` streaming without stalling, and literal `｜DSML｜` in plain prose across chunk widths.

Items 1–3 are fixed: unknown tools are dropped the same way in both paths (indices stay contiguous, `SGLANG_FORWARD_UNKNOWN_TOOLS` still forwards), and the `<｜…` / bare `｜DSML｜` cases stream promptly and agree with `detect_and_parse`. Valid DSML split at every character boundary behaves exactly as on main.

One regression: the new partial-suffix fallback in `_text_before_dsml` (L134-138) is only reached from `finish()`, where a partial tag can no longer complete, so a reply ending on `<`, `<｜` … `<｜DSML` now loses that tail (and a preceding `\n\n`):
```
stream ["for (int i = 0; i ", "<"] -> "for (int i = 0; i "
parse_non_stream                   -> "for (int i = 0; i <"
```
Main keeps it. Deleting that fallback, so it cuts only at a full `bot_token` / `invoke_start_token`, fixes it (the streaming hold already uses `_has_partial_dsml_tag_suffix`); with that change all 40k fuzz cases agree with `parse_non_stream` and your tests still pass. A test like streaming `["for (i ", "<"]` then expecting `"for (i <"` would pin it.

Smaller, out-of-spec input only: after an invoke, stray fragments that aren't one of the four full tags (e.g. `</｜DSML｜parameter>` between invokes, or a V3.2 `</｜DSML｜function_calls>` under the V4 parser) now stream as content where main held them; and the bare-invoke path of `detect_and_parse` now keeps a foreign wrapper like `<｜DSML｜function_calls>` in `normal_text`.

On tests: reverting the `_text_before_dsml` anchoring, or re-adding bare `｜DSML｜` to `_has_dsml_tag`, still passes the suite, and the unknown-tool tests cover V4 with one chunk. Your comment mentions 18 tests and a parameter-value close-tag holdback; the pushed head has 4 new tests and doesn't touch parameter parsing. Is there a commit still to push?
