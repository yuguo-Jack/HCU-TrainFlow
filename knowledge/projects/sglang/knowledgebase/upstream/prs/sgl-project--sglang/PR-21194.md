# [Fix] [AMD] deepseek-v2/v3: Fix PPMissingLayer AttributeError in aiter_gfx95 code path

## Motivation

When running DeepSeek-V2/V3 with Pipeline Parallelism (PP) on AMD gfx950 GPUs (MI300/MI350), the server crashes during model initialization with: `AttributeError: 'PPMissingLayer' object has no attribute 'embedding_dim'`.
This is because the `_use_aiter_gfx95` code block in `DeepseekV2Model.__init__` directly accesses `self.embed_tokens.embedding_dim` and `self.layers[i].mlp`, which are `PPMissingLayer` placeholders on non-owning PP ranks. 

## Modifications

Replace 4 bare attribute accesses inside the `_use_aiter_gfx95` block with safe `getattr` calls

We hit the same crash serving GLM-5.2 with a pipeline-parallel prefill on MI355X, and this PR is the fix we need.

Every PP stage that does not own the embedding fails during model construction with an `AttributeError` on `self.embed_tokens.embedding_dim`: there `embed_tokens` is a `PPMissingLayer`, and the `_use_aiter_gfx95 and config.n_routed_experts == 256 and ...` condition reaches the attribute because GLM-5.2 also has 256 routed experts. Only stage 0 comes up.

**Still on main.** At `5ac32ada54` the same reads are at [deepseek_v2.py#L3029](https://github.com/sgl-project/sglang/blob/5ac32ada54371cf24525dfeeb814b3e432df6eb9/python/sglang/srt/models/deepseek_v2.py#L3029) and [#L3064](https://github.com/sgl-project/sglang/blob/5ac32ada54371cf24525dfeeb814b3e432df6eb9/python/sglang/srt/models/deepseek_v2.py#L3064). **Validation with an equivalent change.** We have run with a local fix that reads `config.hidden_size` where this PR uses `getattr(self.embed_tokens, "embedding_dim", ...)`. For GLM-5.2 (6144, not 7168) both skip this allocator branch on every stage. With it, the TP1 x PP4 prefill starts on all four stages and has served our PD runs since Oct 21: GSM8K 0.9666 (strict) / 0.9674 (flexible) on 1P1D with real MTP acceptance, and the 3,600-second AgentX points for 1P1D, 1P + 4-GPU decode and 2P1D.

The calculation of `num_moe_layers` can be made more concise and efficient. Using a generator expression with `sum()` is more Pythonic and avoids creating an intermediate list. Note that `isinstance()` returns a boolean, which `sum()` will treat as `1` or `0`.

```python
            num_moe_layers = sum(
                isinstance(getattr(layer, "mlp", None), DeepseekV2MoE)
                for layer in self.layers
            )
```
