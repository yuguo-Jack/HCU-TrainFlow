# [Doc] cookbook: Add Muse Spark Open GB300 Dynamo + SGLang deployments measured with AA AgentPerf

[Upstream PR](https://github.com/sgl-project/sglang/pull/45629) · state: closed · merged: True

## Original PR description

## Motivation

The Muse Spark Open cookbook page has launch commands for single deployments but none tuned along the latency/throughput curve for agentic serving on GB300. This PR adds five Dynamo + SGLang deployments on GB300, measured with the [Artificial Analysis AgentPerf](https://github.com/ArtificialAnalysis/agentperf-client) coding-agent workload. Together they cover the curve from the lowest per-user latency (concurrency 1) to the highest throughput per GPU (concurrency 160). Of the 43 points on the measured SGLang Pareto frontier, these five keep both ends and cover 81% of its area.

## Source

All five start from the Artificial Analysis SGLang submission for this model (`lmsysorg/sglang:dev-muse-spark-open@sha256:8cfc5a72…`, TP4·EP4, DFlash2 with 8 draft tokens, FP8 KV cache). They add the Dynamo frontend (KV-aware router with session affinity) and change only flags, environment variables and parallelism. There are no source or image changes beyond the Dynamo wheels (`ai-dynamo` / `ai-dynamo-runtime` `1.6.0.dev20261019` from PyPI).

Changes from that submission:

- **Agg TP8·EP8 (2 nodes), lowest latency:** TP8·EP8 over 2 nodes, layernorm SP and MegaMoE-for-SP off, `NCCL_MNNVL_ENABLE=1`, `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`.
- **Agg TP8·EP8 (2 nodes), low latency:** same as c1.
- **Agg TP4·EP4, balanced:** `--prefill-decode-interval 64`.
- **Agg TP4·EP4, high throughput:** `--prefill-decode-interval 24`, `--max-running-requests 64`, `--cuda-graph-max-bs-decode 64`, `--swa-full-tokens-ratio 0.15`, `SGLANG_OPT_UNIFIED_CACHE_FREE_OUT_OF_WINDOW_SLOTS=1`.
- **Agg TP4·EP4 + HiCache, max throughput:** HiCache (`--hicache-size 120`), `--prefill-decode-interval 6`, `--max-running-requests 176`, `--cuda-graph-max-bs-decode 176`, `--mem-fraction-static 0.9`, `--swa-full-tokens-ratio 0.15`, `SGLANG_OPT_UNIFIED_CACHE_FREE_OUT_OF_WINDOW_SLOTS=1`.

## What this PR does

Adds a subsection, **GB300 deployments measured with Artificial Analysis AgentPerf**, to the Agentic Long-Context Deployment section of `docs/cookbook/autoregressive/Meta/MuseSparkOpen.mdx`. It holds one collapsible entry per deployment, ordered from low latency to high throughput. Each entry has tabs in launch order: Env Vars (placeholders), etcd, the Dynamo frontend, then the SGLang worker. A two-node worker uses one command with `$NODE_RANK`. The page has no performance numbers, and nothing else on the page changes.

## How the commands are produced

- **Workers:** the exact `dynamo.sglang` command and environment each run launched, taken from its launcher log. For the two-node deployments, both nodes' commands normalize to the same text.
- **Frontend and etcd:** rebuilt from the run's recipe with the same launcher (`dynamo.frontend` gets the recipe's router arguments and environment as given).
- **Cleanup:** the same keep / remove / rewrite rules as the earlier cookbook syncs (#42726, #43083). Removed: cluster paths, the benchmark client, telemetry and log switches, and per-run ports. Rewritten: weights and draft to Hugging Face ids, IPs to placeholders, ports to the cookbook defaults. Anything those rules do not classify is listed explicitly: `--dyn-reasoning-parser`, `--dyn-tool-call-parser`, `DYN_TOKENIZER*` and `DYN_ROUTER_QUEUE_THRESHOLD` are kept, and `HF_HUB_OFFLINE` is removed.
