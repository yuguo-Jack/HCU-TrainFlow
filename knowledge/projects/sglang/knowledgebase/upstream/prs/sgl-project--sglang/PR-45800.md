# [Fix] GLM: Preserve NextN PTPC quantization for excluded experts

[Upstream PR](https://github.com/sgl-project/sglang/pull/45800) · state: closed · merged: True

## Original PR description

## Motivation

With `SGLANG_GLM_NEXTN_MOE_PTPC=1`, GLM NextN adds a per-channel FP8 scheme for routed experts, but also maps checkpoint per-expert excludes into runtime names. Quark treats those leaf exclusions as excluding the fused expert module, so its quantization method is never selected even though the loader converts the expert weights to FP8.

## Modifications

Skip mapped routed-expert leaf exclusions when the existing PTPC predicate is enabled. Preserve checkpoint exclusions for loading, other runtime exclusions, flag-off behavior, and the shared-expert fusion guard. Add a regression using Quark's actual ignore predicate.

## Accuracy Tests

Using the same test file on base and patched trees:

- Existing registered PTPC suite: base reproduces the new assertion; patched passes all 12 tests without skips.
- CPU component check with real QuarkConfig and FusedMoE types: base selects no quant method with PTPC enabled; patched selects QuarkFusedMoEMethod and the per-channel FP8 scheme. The real parameter loader correctly places both experts' gate/up/down weights and scales. Flag-off and shared-expert BF16 behavior are preserved.

## Speed Tests and Profiling

Not measured; this fixes quantization configuration selection and makes no performance claim.
