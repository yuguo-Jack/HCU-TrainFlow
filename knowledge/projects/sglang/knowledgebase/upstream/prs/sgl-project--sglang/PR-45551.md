# [Observability] Support standard Prometheus metric names with configurable style (#45418)

[Upstream PR](https://github.com/sgl-project/sglang/pull/45551) · state: open · merged: False

## Original PR description

## Description

Closes #45418.

### Problem
Prometheus best practices and downstream telemetry scrapers (such as Google Cloud Managed Prometheus, Datadog, OpenTelemetry Prometheus receivers, and certain Grafana / Prometheus alerting rules) restrict metric names:
- Prometheus metric names should follow `[a-zA-Z_:][a-zA-Z0-9_:]*`, but colons (`:`) are historically reserved for user-defined recording rules.
- Scrapers like GCP Cloud Monitoring reject or mangle metric names containing colons, throwing errors or dropping SGLang metrics.

### Solution
This PR introduces configurable metric naming style for SGLang Prometheus metrics:
1. Adds `--prometheus-metric-style` CLI flag and `SGLANG_PROMETHEUS_METRIC_STYLE` environment variable with choices:
   - `"colon"` (default): Preserves existing behavior (`sglang:...`) for 100% backward compatibility.
   - `"underscore"`: Uses standard Prometheus naming convention (`sglang_...`).
2. Introduces `format_metric_name(name)` in `python/sglang/srt/observability/metrics_collector.py` and transparently normalizes metric registration in `_StatLoggerDIMixin` without requiring manual repetitive refactoring of ~160 metric definitions.
3. Updates `http_request_metrics.py`, `cpu_monitor.py`, and `disaggregation/encoder/runtime.py` to use the dynamic metric formatter.
4. Adds comprehensive unit tests verifying both colon and underscore modes, Prometheus `_total` counter normalization, and CLI / env var overrides.
