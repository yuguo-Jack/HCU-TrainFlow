## Motivation

This PR adds CPU INT8 quantization support for two serving paths:

- `per_token_quant_int8` Python dispatch on CPU
- compressed-tensors W8A8 INT8 linear layers on the Intel AMX backend

The goal is to make the CPU INT8 path usable through the same Python-facing APIs as other devices while keeping the AMX kernel’s internal packed/offset format contained inside the CPU implementation.

## Changes

- Add CPU dispatch in `per_token_quant_int8`.
  - Calls `sgl_kernel.per_token_quant_int8_cpu` on a flattened 2D view.
  - Converts the CPU kernel’s internal `uint8 + 128` result back to public `torch.int8`.
  - Reshapes scales back to the public `[..., 1]` contract.
  - Preserves `cal_sum=True` behavior.

- Update CPU INT8 kernel implementation details.
  - Use explicit `Aq` and `As` tensors in `int8_scaled_mm_with_quant`.
  - Extend BF16 row quantization to support non-32-aligned K with scalar/tail handling.

- Add compressed-tensors W8A8 INT8 CPU support.
  - Process per-tensor and per-channel weight scales for CPU.
  - Pack weights through the Intel AMX helper.
  - Route supported AMX-packed weights to `sgl_kernel.int8_scaled_mm_with_quant`.
  - Explicitly reject unsupported/unpacked CPU weights instead of silently using the packed-kernel contract incorrectly.

- Add CPU registered tests for:
  - public `per_token_quant_int8` CPU dtype/shape/scale contract
  - compressed-tensors W8A8 INT8 AMX path
  - unsupported unpacked-weight rejection
