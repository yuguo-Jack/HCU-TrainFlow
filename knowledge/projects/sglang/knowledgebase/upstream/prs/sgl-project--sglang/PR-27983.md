# [Fix] hf_transformers: Apply rope overrides to text_config for VLM-format models

[Upstream PR](https://github.com/sgl-project/sglang/pull/27983) · state: open · merged: False

## Original PR description

## Motivation

For composite (VLM or omni) configs such as Qwen3.5 and Qwen3-VL, the language model reads its RoPE settings from a sub-config (`text_config`), and two `--json-model-override-args` forms go wrong on main `03a27e2a17`:

1. A flat `{"rope_parameters": {...}}` or `{"rope_scaling": {...}}` updates only the parent config, so the language model never sees it.
2. A nested `{"text_config": {"rope_parameters": {"rope_theta": 20000.0}}}` is applied with a shallow `update`, which replaces the whole RoPE dict and drops checkpoint keys such as `rope_type` and `partial_rotary_factor`.

Fixes #27974 (closed by the stale bot; both cases still reproduce on main).

## Modifications

`get_config` now applies overrides through `apply_model_override_args`:

1. A dict override for a key whose current value is a `PretrainedConfig` (or a dict-valued `thinker_config`, `llm_config`, `language_config` or `text_config`) is applied recursively, in place, so the sub-config object is kept.
2. Partial `rope_scaling` and `rope_parameters` dicts are merged over the existing ones instead of replacing them, one key at a time, since transformers v5 backs both with one dict. When an override names the scaling type with `rope_type` or the legacy `type`, the merge sets the other alias to the same value, so the checkpoint's old type does not win.
3. A flat RoPE dict override is also merged into the language sub-config, picked in `get_hf_text_config`'s order: `thinker_config`'s `text_config`, then `llm_config`, `language_config` and `text_config`.

Other flat overrides are applied as before.

Limits:

- A merge keeps the checkpoint keys an override does not set, so switching the scaling type keeps the old type's extra keys (for example `low_freq_factor` when switching from `llama3`). Set those keys in the override to change them.
- Only the two RoPE keys are mirrored. A flat `rope_theta` or `max_position_embeddings` still updates the parent only, as on main.
- A non-dict RoPE value such as `null` reaches the parent as on main and is not mirrored, since it would replace the sub-config's whole RoPE dict, `rope_theta` included.
- For `Llava*ForCausalLM`, `get_hf_text_config` returns the parent config, so the mirrored copy lands on a `text_config` that is not used.
