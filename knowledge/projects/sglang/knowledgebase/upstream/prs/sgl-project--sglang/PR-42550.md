# [Fix] Reject removal of an external corpus while its load is pending

[Upstream PR](https://github.com/sgl-project/sglang/pull/42550) · state: closed · merged: False

## Original PR description

## Motivation

Removing an external NGRAM corpus during an asynchronous load currently returns success, but the background load can subsequently publish that corpus. Reject the removal until the scheduler completes the load instead of acknowledging an operation that did not take effect.

Closes #36500.

## Modifications

- Reject same-ID removal while a load is pending, including when the worker thread has finished but the scheduler has not committed its bookkeeping.
- Preserve removal of other corpora and removal after the pending load completes.
- Extend the existing CPU corpus suite with deterministic thread barriers and the real JIT-compiled `NgramCorpus`, checking deferred completion, corpus visibility, and token-budget recovery.

## Accuracy Tests

On macOS arm64, Python 3.12.9, Torch 2.14.1, Transformers 5.17.0, and apache-tvm-ffi 0.1.14.post1 (the repository pins 0.1.11):

```bash
PYTHONPATH=python python test/registered/unit/spec/test_ngram_corpus.py -v
```

**39 tests and 2 subtests passed; 5 existing HTTP tests skipped** because their server import requires unavailable CUDA dependencies. The new regression uses real request records, threads and CPU corpus operations; only the model worker is replaced by an adapter to those corpus methods.

Both new regression subcases fail against the unchanged implementation and pass with this fix. An independent rerun of the regression also passed. Applicable pre-commit hooks and `git diff --check` passed. Changed executable-line coverage is **100% (2/2)**, exceeding the repository's 60% threshold.

No model weights, GPU inference, or full HTTP serving validation was used.
