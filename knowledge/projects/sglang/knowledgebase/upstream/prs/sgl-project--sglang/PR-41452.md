# [MemCache] refactor: require an anchored lock receipt for non-root releases

[Upstream PR](https://github.com/sgl-project/sglang/pull/41452) · state: closed · merged: True

## Original PR description

## Motivation

The unified tree core checks a release receipt with `params.node_id is None or params.node_id == node.id`, so a receipt that never came from an acquire (`DecLockRefParams()`) passes on any node. Such a release is not harmless: FULL walks to the root and SWA walks to the root when its uuid is `None`, so it silently drops locks other holders own. That is how #41261's bug (a resumed PD request releasing a lock it never took) stole another request's prefix lock instead of failing.

The only legitimate unanchored release is a root pin (`_bind_root_prefix`), and releasing the root is a no-op.

## Modifications

- Python and Rust cores: a receipt must be anchored on the node it releases; an unanchored receipt is accepted only on the root.
- Tests that released non-root nodes with hand-built unanchored receipts now pass the node id (or the acquire's receipt), so they still exercise the path they were written for. No test logic changes.

## Accuracy Tests

- Rust `cargo test --lib`: 867 passed, same as main. Before the test updates 23 tests tripped the new assert, which is the point: each released a non-root node with an unanchored receipt.
- `test/registered/unit/{mem_cache,disaggregation,managers}` and the Rust-core run of the shared suite (`test_rust_unified_radix_cache_unittest.py`): same results as main.
- PD e2e smoke (decode radix + HiCache + file L3 on Qwen3-8B, and decode radix on the Mamba hybrid Qwen3.5-2B): healthy, the new assert never fired.
