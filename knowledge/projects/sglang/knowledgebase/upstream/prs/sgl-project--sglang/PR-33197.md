# [Bugfix] Pad DSA topk_indices_offset under prefill CP

## Motivation

Follow-up to #30992 (GLM-5.2 MTP index sharing with prefill CP).

That PR padded `topk_indices` to match the query token length after CP sharding / reordering, but left `topk_indices_offset` unpadded. When the two tensors have different row counts, adding offset into top-k indices fails with a broadcast mismatch (or silently misaligns rows).

The error message is as follows:
```text
File ".../sglang/srt/layers/attention/dsa_backend.py", line 1962, in forward_extend
    mask, topk_indices + topk_indices_offset, topk_indices
          ~~~~~~~~~~~~~^~~~~~~~~~~~~~~~~~~~~
RuntimeError: The size of tensor a (8) must match the size of tensor b (2) at non-singleton dimension 0
```

This bug is triggered in the **PD disaggregation** path (`--disaggregation-mode prefill`) with prefill CP + EAGLE, and based on sglang v0.5.16. Repro launch command:

```bash
python3 -m sglang.launch_server \
  --model-path zai-org/GLM-5.2-FP8 \
  --port 8001 \
  --host 0.0.0.0 \
  --chunked-prefill-size 32768 \
  --attn-cp-size 8 \
  --enable-prefill-cp \
  --cp-strategy interleave \
  --dsa-prefill-backend flashmla_sparse_q8 \
  --page-size 64 \
  --ep-size 8 \
  --moe-a2a-backend deepep \
  --deepep-mode normal \
  --disaggregation-mode prefill \
  --mem-fraction-static 0.83 \
  --tp 8 \
  --watchdog-timeout "1000000" \
  --trust-remote-code \
  --max-running-requests 32 \
  --enable-cache-report \
  --enable-metrics \
  --dist-init-addr $LWS_LEADER_ADDRESS:20102 \
  --nnodes $LWS_GROUP_SIZE \
  --node-rank $LWS_WORKER_INDEX \
  --collect-tokens-histogram \
  --tool-call-parser glm47 \
  --reasoning-parser glm45 \
  --speculative-algorithm EAGLE \
  --speculative-num-steps 3 \
  --speculative-eagle-topk 1 \
  --speculative-num-draft-tokens 4 \
  --disable-piecewise-cuda-graph \
  --disable-overlap-schedule \
  --kv-cache-dtype fp8_e4m3
```
