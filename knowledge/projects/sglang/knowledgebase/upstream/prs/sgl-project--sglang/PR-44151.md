# [Perf] Reduce GPU->CPU syncs in multi-item scoring and token-id logprob paths

## Motivation

Consolidates two small perf PRs that both remove GPU→CPU synchronization from the scoring / logprob output path and both touch `python/sglang/srt/managers/utils.py`. Reviewing them together is easier than reviewing them separately. This PR supersedes #37176 and #39642.

## Modifications

One commit per original PR, so the changes can be reviewed one at a time:

1. **Batch the GPU→CPU copy for multi-item scoring embeddings** (was #37176)
   - Adds `_can_batch_d2h` / `_batched_async_d2h` in `managers/utils.py`. A list of uniform-shape tensors is copied in one async D2H transfer with one sync, instead of N `.tolist()` syncs. Ragged or non-batchable inputs fall back to the per-tensor path.
   - Adds `test/registered/unit/managers/test_batched_async_d2h.py` (CPU unit tests).
2. **Remove per-request CUDA syncs from the token-id logprob path** (was #39642)
   - `get_token_ids_logprobs_batch_optimized` (`layers/logprob_processor.py`) builds its index arithmetic on the host, so it no longer syncs per request.
   - `batch_result_processor.py` converts the per-request logprob tensors with one batched `batch_convert_tensors_to_lists` call (`managers/utils.py`).

## Accuracy Tests

No numerical change. Both changes produce identical outputs by construction:
- (1) Same tensors in the same order; only the transfer is batched. Checked for exact equality against the per-tensor `.tolist()` reference on uniform batches, single-tensor batches, zero-row tensors, ragged column counts (fallback path), empty input, and fp16.
- (2) Differential test against the original `get_token_ids_logprobs_batch_optimized`. Values and indices are exactly equal on the docstring example, all-empty input, `None` mixed with populated/empty entries, a single request, and duplicate token ids.

## Speed Tests and Profiling

- (1) Removes N-1 D2H syncs per prefill batch in the MIS embedding path. The gain grows with batch size; batch size 1 is unchanged.
- (2) From the internal report, HTTP scoring with RPS=40, item_count=50, concurrency=16: 2825 requests in 60 s, 2342 items/sec, P99 442 ms. Workloads that never set `token_ids_logprob` are unaffected.
