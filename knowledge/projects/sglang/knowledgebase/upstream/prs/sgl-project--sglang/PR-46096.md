# [Fix] api: reject malformed tool arguments in Responses and Messages

[Upstream PR](https://github.com/sgl-project/sglang/pull/46096) · state: open · merged: False

## Original PR description

## Motivation

Responses history currently rewrites invalid function arguments to `{}`. Messages does the same for malformed model output, or leaks a validation exception for valid JSON that is not an object. Clients can mistake an invented empty input for a real tool call.

## Changes

Reject invalid/non-object function arguments in Responses history. Return a Messages `502 api_error` when model tool arguments cannot be represented, rather than emitting a fabricated tool input. Valid JSON objects, including `{}`, keep working.

## Validation

Recorded focused CPU regressions reproduce both failures using the actual normalization and Messages non-streaming handlers, and cover malformed JSON, arrays, null/scalars and valid empty/dict inputs. The fixture isolates model/startup imports; this is not a full-package, HTTP-service or GPU run. Model inference is unchanged.

The current head is `5f53f4aa`. GitHub lint passes; its [Base gate](https://github.com/sgl-project/sglang/actions/runs/40077865950/job/120825117228) stops before the suites because `run-ci` is missing. The normal-package regressions still need CI:

```bash
PYTHONPATH=python python -m pytest -q \
  test/registered/unit/entrypoints/anthropic/test_serving.py \
  test/registered/unit/entrypoints/openai/test_serving_responses.py \
  -k 'ToolArgumentIntegrity or function_call_rejects_invalid_or_non_object_arguments or function_call_preserves_valid_empty_and_dict_arguments'
```
