# [Feat] spec: Support EAGLE3 under pipeline parallelism by relaying au…

[Upstream PR](https://github.com/sgl-project/sglang/pull/46320) · state: open · merged: False

## Original PR description

## Motivation

Part of #39634 (P2: "EAGLE3 / DFLASH: ship aux hidden states across stages") and the PP roadmap #43885.

PP and speculative decoding are converging: PP x EAGLE/MTP already works, both on the PD prefill role and with `SGLANG_ENABLE_PP_SPEC`. EAGLE3 is still rejected under PP, which leaves out the EAGLE3 drafts of Llama, gpt-oss and Kimi-K2.5.

The reason is more than the gate. An EAGLE3 draft does not read only the target's last hidden state. It reads aux hidden states from three target layers (by default `[2, n/2, n-3]`), concatenates them to `3 * hidden_size`, and projects them back with `fc`. Under PP these layers usually sit on different stages, but:

1. `set_eagle3_layers_to_capture` returns early on non-last stages, so earlier stages never capture.
2. `to_pp` only carries `hidden_states` / `residual`, so nothing could be relayed anyway.

The last stage therefore only sees the capture layers it owns. With Llama-3.1-8B (32 layers, default layers `[2, 16, 29]`):

- **PP2:** the last stage owns layers 16 and 29. The 8192-wide feature crashes the draft `fc` (`mat1 and mat2 shapes cannot be multiplied (7x8192 and 12288x4096)`).
- **PP4:** the last stage owns only layer 29. The feature is exactly `hidden_size` wide, and `LlamaForCausalLMEagle3` applies `fc` only when the width differs from `hidden_size`, so it **silently skips `fc`**. Outputs stay correct because the bonus token is always accepted, but accept length collapses to ~1.0, so speculation is effectively off and nothing reports an error.

The gate in `check_pipeline_parallel_compat` hides this today, but it is an assert, so `PYTHONOPTIMIZE=1` (which some PP recipes use) bypasses it. Lifting the gate safely needs the aux states relayed across stages.

## Modifications

- Rename the DSpark-only PP proxy key `dspark_hidden_states` to the generic `aux_hidden_states`, and `get_pp_proxy_dspark_hidden_size` to `get_pp_proxy_aux_hidden_size`. Kimi already relays DSpark aux states this way, and the transport and CUDA graph buffers handle the extra key generically, so EAGLE3 reuses the path. This is mechanical and touches kimi_linear / kimi_k3.
- Llama and Qwen3: every stage captures its own layers and relays the aux states it has accumulated to the next stage, through two shared helpers in `layers/aux_hidden_states.py`.
- Allocate the aux key in the dummy-run and chunk-sizer proxy buffers too.
- Allow EAGLE3 in the PP gate. A target without the relay now fails at load time instead of degrading silently. DFLASH and DSpark are unchanged.

Qwen3's DFLASH capture also runs on every stage now, so DFLASH under PP (#45756) gets the same relay on these targets. Other EAGLE3 targets, including the MoE ones, can adopt the helpers in later PRs.

## Accuracy Tests

Setup:
- Llama-3.1-8B-Instruct + `lmsys/sglang-EAGLE3-LLaMA3.1-Instruct-8B`, fp16.
- Qwen3-8B + `Tengyunw/qwen3_8b_eagle3`, bf16, thinking off.
- Cookbook EAGLE3 flags (steps 3, topk 1, draft tokens 4).
- `SGLANG_ENABLE_PP_SPEC=1`, `--disable-overlap-schedule`.
- sgl-eval gsm8k, 200 examples, temperature 0 (greedy instead of Qwen3's recommended sampling, to keep the PP comparison deterministic).

Runs on main used `PYTHONOPTIMIZE=1` to bypass the gate.

Llama-3.1-8B:

| Run | GSM8K | Accept length |
|---|---|---|
| pp=1, main | 82.5% | 2.91 |
| PP2, main | crash | - |
| PP2, this PR | 82.0% | 2.87 |
| PP4, main | 82.0% | **1.00** |
| PP4, this PR | 82.0% | 2.88 |

Qwen3-8B:

| Run | GSM8K | Accept length |
|---|---|---|
| pp=1 | 95.5% | 2.76 |
| PP2, main | crash | - |
| PP2, this PR | 96.0% | 2.76 |
| PP4, main | 95.0% | **1.00** |
| PP4, this PR | 96.0% | 2.76 |

Tests:
- New CPU unit test `test_pp_aux_hidden_relay.py`:
  - For Llama and Qwen3, 3-stage aux is bit-identical to 1-stage, and the width each stage receives matches its CUDA graph buffer size.
  - A target without the relay is rejected under PP.
  - Fails if the relay is removed.
- New `TestPPSpecEagle3Consistency` in `test_pp_spec.py` (PP2 vs pp=1).
- Updated the PP gate cases in `test_server_args.py`.
