# [Fix] Keep cancelled control calls from consuming later replies

[Upstream PR](https://github.com/sgl-project/sglang/pull/42694) · state: open · merged: False

## Original PR description

## Motivation

Cancelling a dispatched `FanOutCommunicator` call releases its queueing lock while rank replies are still in flight. The next caller resets the shared collector, so a delayed reply from A can complete B with mixed results. This affects the uncorrelated control-call path used by adapter and weight updates, among other operations.

With two ranks, the baseline reproduces: send A → receive A0 → cancel A → send B → receive A1 and B0. B returns `[A1, B0]`.

## Modifications

Keep the slot owned by a cancelled, dispatched call until its captured number of rank replies has drained. Cancellation still reaches the caller immediately. A request cancelled while waiting for the lock is never sent, and send failures release the slot.

The six CPU tests cover fan-out values 1/2/4, queued cancellation, cancellation after the final reply, send failure, a fan-out change during draining, and watching mode.

The cancellation concern was also discussed in #30022, which closed unmerged. This builds on the FIFO lock in #30606. #39834 adds optional correlation IDs for elastic-scaling calls; this change protects existing calls that have no IDs.

## Validation

- Baseline: four failing assertions across the cancellation/draining cases.
- Patched: all six new test methods pass on Python 3.12.
- Existing FIFO-ordering test passes.
- A separate in-process ZeroMQ check confirms B receives only its own two replies after A is cancelled.
- Ruff 0.15.1, isort 7.0.0 and `git diff --check` pass.

Local tests imported the actual communicator and CI registration modules while bypassing SGLang package startup; no GPU or full-server run was performed. The new file is registered in `base-a-test-cpu`.

Without response IDs, safely admitting another call still requires all dispatched ranks to reply. This does not add worker-failure recovery or a drain timeout.

## Accuracy Tests

No model or kernel changes. Full model accuracy testing was not run.

## Speed Tests and Profiling

No inference benchmark was run; this changes the control-call lifecycle.
