# [Perf] [AMD] lfm2-vl: Batch image encodes across requests on ROCm

[Upstream PR](https://github.com/sgl-project/sglang/pull/33751) · state: open · merged: False

## Original PR description

## Motivation

On HIP every per-image LFM2-VL request takes the per-request encoder path. A run at concurrency 32 admitted 771 requests over 188 prefill batches and ran the vision encoder 771 times. CUDA already batches per-image cache misses across requests. On HIP, the check that allows this batching excludes every model.

## Modifications

1. `python/sglang/srt/managers/mm_schedule.py`: the per-request fallback decision moves into `_use_per_request_encode_fallback`. NPU and XPU always take the fallback. HIP takes it unless the encoder's model is in `_HIP_CROSS_REQUEST_ENCODE_ARCHS`, which lists LFM2-VL. CUDA always batches, as on main.
2. `mm_schedule.py`: add `Lfm2VlForConditionalGeneration` to `_can_skip_pre_embed_feature_move`. On every platform the scheduler leaves LFM2-VL features where they are and the model uploads them in one copy.
3. `python/sglang/srt/models/lfm2_vl.py`: build the pixel tensor with `materialize_multimodal_features` (one destination buffer, per-item `copy_`) instead of per-item `.to()` plus `torch.cat`.
4. `test/registered/chunked_prefill/test_mm_chunked_embedding_unit.py` (CPU suite): sends two single-image requests through `_get_chunked_prefill_embedding` and checks that they take one encoder call on HIP for LFM2-VL, two on HIP for another model, and one on CUDA. The HIP LFM2-VL case fails on main.

## Accuracy Tests

HIP was not re-run for this revision. No AMD GPU was available. The MI325X numbers below are from the first revision of this branch (2026-08-05).

On MI325X (Torch 2.9.1 + ROCm 7.2, BF16), VLMEvalKit CountBenchQA scores 417/487 with zero inference or judge failures. The multi-resolution and 7,819-token long-image diagnostics against HF pass. The worst max delta is 0.2275 in prefill and 0.1360 in decode.

## Speed Tests and Profiling

MI325X BF16, one 512 px image per request, 268 input + 32 output tokens, 128 prompts per run, 1 warmup + 3 measured runs. These numbers are from the first revision of this branch (2026-08-05) and were not re-measured:

| Path | C=16 | C=32 |
|---|---:|---:|
| Per-request encoder | 1,320 ± 3.6 tok/s | 1,429 ± 86.9 tok/s |
| Cross-request encoder | 1,477 ± 9.5 tok/s | 1,665 ± 87.2 tok/s |
| Change | +11.9% | +16.5% |

± is the standard deviation over the 3 measured runs. A rerun on MI325X against this head is still needed.
