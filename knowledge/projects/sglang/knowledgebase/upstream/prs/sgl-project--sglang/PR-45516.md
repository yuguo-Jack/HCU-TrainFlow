## Motivation

<!-- Describe the purpose and goals of this pull request. -->

In #40066, empty CPU lists were filtered out via `if cpus` in `get_cpu_ids_by_node()`. However, after per-rank thread/NUMA core binding (e.g., running with `TP=6`), `get_cpu_ids_by_node()` only returns the CPUs within the current rank's bound NUMA node, reducing `n_numa_node` from the total number of NUMA nodes (e.g., 6) to `1`.

Meanwhile, `get_free_cpu_memory()` queries the **system-wide (or cgroup-constrained) available memory** via `psutil.virtual_memory().available` and `/sys/fs/cgroup/memory.*`, rather than the available memory of the bound NUMA node. Dividing the global free memory by `n_numa_node = 1` instead of total NUMA nodes significantly overestimates the per-rank KV cache memory budget, while actual memory allocation remains strictly restricted by NUMA binding, leading to OOM errors (e.g., when running Grok-2 with TP=6).

## Modifications

<!-- Detail the changes made in this pull request. -->
Cache get_cpu_ids_by_node results to ensure consistent NUMA node detection across binders.
