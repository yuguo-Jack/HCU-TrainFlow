# [Perf] [AMD] GLM5: Add opt-in PTPC FP8 projections on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/33602) · state: open · merged: False

## Original PR description

## Motivation

The `amd/GLM-5.2-MXFP4` checkpoint keeps the q_a, kv_a, q_b, and o attention projections in BF16. They are represented by three modules: `fused_qkv_a_proj_with_mqa`, `q_b_proj`, and `o_proj`.

This PR adds a default-off PTPC FP8 path on gfx950 using per-token activation scales and per-channel weight scales. BF16 remains the default and fallback.

## Modifications

- Add `SGLANG_DSA_FP8_PROJ_GEMM` as the single opt-in switch; the path also requires Aiter, gfx950, and the GLM DSA model type.
- Cache bpreshuffled FP8 weights while retaining the original BF16 parameters for fallback, so enabled projections hold both copies.
- Fold q_b input quantization into the existing q/k RMSNorm in the active ROCm MHA/MLA forward paths. o_proj uses a standalone per-token quantization of the ROCm MLA attention output.
- Keep `fused_qkv_a_proj_with_mqa` on tuned Aiter BF16 for M≤512 and use PTPC FP8 for M>512; the threshold was selected empirically on MI355X. q_b_proj and o_proj use FP8 whenever the flag is enabled.
- Fall back to Triton quantization helpers on Aiter builds without the HIP fused per-token RMSNorm kernel.
- Add CPU unit coverage for the enablement gate, default-off BF16 behavior, weight repacking, PTPC dispatch, rollback, the M=512/513 boundary, and ROCm MHA/MLA routing.
