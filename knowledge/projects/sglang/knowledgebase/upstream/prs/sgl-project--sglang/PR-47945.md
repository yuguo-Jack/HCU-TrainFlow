# [Test] Add CPU unit coverage for MTP weight filtering

[Upstream PR](https://github.com/sgl-project/sglang/pull/47945) · state: open · merged: False

## Original PR description

## Motivation

`DefaultModelLoader` filters MTP checkpoint weights when `draft_model_idx` is set (`_filter_mtp_weights` in `python/sglang/srt/model_loader/loader.py`): it keeps only the requested MTP layer, remaps it to layer 0, preserves non-MTP weights, and yields lazily so the upstream buffered iterator's sliding window bounds CPU memory. None of that behavior had CPU unit-test coverage, so a regression in the filter (wrong layer kept, wrong remap, eager materialization re-introducing the page-reclaim hangs on large MoE checkpoints) would go unnoticed until a real MTP load.

Fixes #47594.

## Modifications

- `test/registered/unit/model_loader/test_default_model_loader.py`: three new tests in `TestDefaultModelLoader` (already registered for CPU CI):
  - `test_filter_mtp_weights_keeps_requested_layer_and_remaps_to_zero`: non-MTP weights pass through unchanged (with prefix), only the requested MTP layer is kept and remapped to `model.mtp.layers.0.*`, other MTP layers are dropped; yielded tensors are the same objects (no copy).
  - `test_filter_mtp_weights_keeps_layer_zero_and_multi_digit_indices`: multi-digit layer indices (e.g. `layers.10`) are parsed and remapped correctly.
  - `test_filter_mtp_weights_yields_lazily`: building the filtered iterator pulls nothing upstream; each `next()` pulls only what it needs to produce the next kept weight (a dropped MTP layer is consumed only while advancing past it).

Test-only change; loader behavior is unchanged.

## Tests

- Verified the real `_filter_mtp_weights` (AST-extracted from `loader.py`) against the exact scenarios the new tests assert, with a stub harness (no torch/GPU on this machine): 11/11 checks pass, covering name filtering, prefix handling, tensor identity, multi-digit indices, and laziness (pull counts at each step).
- The new tests themselves could not be executed here (this machine has no torch install, and the test file imports torch plus the full loader module), so please let CI run `test/registered/unit/model_loader/test_default_model_loader.py`.
