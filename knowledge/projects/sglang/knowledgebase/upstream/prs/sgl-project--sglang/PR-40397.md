# Fix AttributeError on humming quantization in DeepSeek post_load_weights

[Upstream PR](https://github.com/sgl-project/sglang/pull/40397) · state: open · merged: False

## Original PR description

## Motivation

v0.5.20 cannot load any DeepSeek/GLM MLA checkpoint served with `--quantization humming`. Every TP rank fails at the end of weight loading:

```
File "sglang/srt/models/deepseek_common/deepseek_weight_loader.py", line 632, in post_load_weights
    weight_scale.format_ue8m0 and weight_scale.dtype == torch.uint8
AttributeError: 'BlockQuantScaleParameter' object has no attribute 'format_ue8m0'
```

#38446 hoisted the attribute read out of a short-circuit expression:

- before: `if should_deepgemm_weight_requant_ue8m0(...) and weight_scale.format_ue8m0:` — for humming the first operand is `False`, so `format_ue8m0` was never read.
- after: `is_ue8m0_uint8 = (weight_scale.format_ue8m0 and weight_scale.dtype == torch.uint8)` — evaluated unconditionally.

`format_ue8m0` is stamped only by particular quant methods and MoE runners (`layers/quantization/fp8.py`, `moe/moe_runner/flashinfer_trtllm.py`, `moe/mega_moe.py`, the NPU methods). `layers/quantization/humming.py` never stamps it (`grep -c format_ue8m0` → 0), so on the humming path the attribute genuinely does not exist on the `kv_b_proj` scale parameter.

Reported in #40393, where the full deployment context is recorded: a PD-disaggregated GLM-5.3-W4AFP8 deployment (1 prefill on 8x H100 + 2 decode on 8x H20, mooncake transfer backend) — all three nodes crash-restart-loop on v0.5.20, while the same command works on v0.5.19, and v0.5.20 with `--quantization w4afp8` works on the same checkpoint and machines.

## Modifications

Read the attribute with a default, exactly as `models/qwen3_5.py:528` and `layers/quantization/fp8_utils.py:1562` already do. Behaviour is unchanged for every path that does stamp the attribute; the humming path returns to its pre-#38446 behaviour (`is_ue8m0_uint8` is `False`, so neither the `<< 23` reinterpretation nor the fnuz normalization skip applies).

The second read in the same block (inside the `elif`) is still guarded by `should_deepgemm_weight_requant_ue8m0(...)`, which short-circuits for humming, so it is left untouched to keep the diff minimal — happy to switch it to `getattr` as well if reviewers prefer the defensive form in both places.

## Accuracy Test

No numerical change: the patched expression evaluates identically wherever `format_ue8m0` exists, and restores the v0.5.19 code path where it does not.

## Benchmarking and Profiling

Not applicable — load-time only, no change to any forward path.
