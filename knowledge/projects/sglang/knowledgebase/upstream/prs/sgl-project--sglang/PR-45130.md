# [Fix] openai: Return errors in the format OpenAI clients expect

[Upstream PR](https://github.com/sgl-project/sglang/pull/45130) · state: open · merged: False

## Original PR description

## Motivation

OpenAI returns errors as `{"error": {"message", "type", "param", "code"}}`, where `code` is a string or null (`ErrorResponse`). SGLang's OpenAI routes return a flat body with class-style types (`"BadRequestError"`) and the HTTP status as an integer `code`, so OpenAI clients lose the message or fail to parse the error. The open #33534 changes only the non-streamed body.

## Modifications

- **Scope:** the routes that serve the OpenAI API (`/v1/chat/completions`, `/v1/completions`, `/v1/embeddings`, `/v1/audio/transcriptions`, `/v1/models`, and SageMaker's `/invocations`, which shares the chat serving) now return the envelope:
  - from their servings, including stream error frames;
  - from the `HTTPException` and validation handlers and the API-key middleware.
- SGLang's own routes (`/generate`, score, tokenize, rerank, classify, decisions, systemone) keep their shapes. `/v1/responses` and the Anthropic routes keep theirs.
- **Fields:**
  - `error.type` follows the HTTP status: `authentication_error`, `permission_error`, `rate_limit_error`, `service_unavailable_error`, `server_error`, otherwise `invalid_request_error`.
  - `code` is null except the models 404's `"model_not_found"`.
  - `message` is always a string.
  - HTTP statuses are unchanged.
- **Server errors:** the `serving_base` catch-all 500 no longer includes exception text, on every serving route. An `HTTPException` keeps its detail.
- **gRPC:** errors returned by the chat, completions and embedding servings use the envelope. The bridge's own errors (request parsing, its catch-all) are unchanged; for streamed requests they are gRPC statuses.
- **Anthropic adapter:** it maps upstream stream errors by `error.type`.
- **Rust:** `sglang-processor` and `sglang-server` emit the same envelope; the processor's parity fixtures are updated.

**Breaking change for the OpenAI routes:**
- The flat body's top-level `object`, `message`, `type` and `code` are gone. Clients read `body["error"]["message"]` and the response status.
- `error.type` values change from class-style names to the types above.
- The API-key middleware's `{"error": "Unauthorized"}` becomes an object.
- A stream error frame no longer carries the numeric status, only `error.type`.
