# [Fix] moe: add uses_expert_location to MegaMoE test fixtures

[Upstream PR](https://github.com/sgl-project/sglang/pull/45350) · state: closed · merged: True

## Original PR description

## Motivation

#45299 made `mega_moe.py` and `mega_moe_flydsl.py` read `moe.experts.uses_expert_location`, but several `SimpleNamespace` fixtures don't define the attribute. Since PR CI tests the merge ref, every PR branched before #45299 hits this once its CI runs against current main.

Failing CI with the `AttributeError`:

- [base-a-test-cpu (7)](https://github.com/sgl-project/sglang/actions/runs/39379173942/job/118484313383) / [(9)](https://github.com/sgl-project/sglang/actions/runs/39379173942/job/118484313439) on #45147 — `test_mega_moe_deepgemm_api.py`
- [base-a-test-cpu (13)](https://github.com/sgl-project/sglang/actions/runs/39387327249/job/118510471280) on this PR's first run — `test_mega_moe_decode_capacity.py`, same root cause one file over

## Modifications

Set `uses_expert_location=False` in the affected fixtures (`test_mega_moe_deepgemm_api.py` ×2, `test_mega_moe_decode_capacity.py` ×1), preserving the pre-#45299 code path the mocks were written against.

## Verification

`python -m pytest test/registered/unit/layers/moe/test_mega_moe_deepgemm_api.py test/registered/unit/layers/moe/test_mega_moe_decode_capacity.py -q` on main: 29 failed → with this change: **54 passed, 13 subtests passed, 1 xfailed**.
