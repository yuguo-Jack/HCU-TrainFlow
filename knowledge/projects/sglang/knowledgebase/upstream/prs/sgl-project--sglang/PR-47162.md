# [CI] [AMD] ci: Spread out tests and prefer today's images

[Upstream PR](https://github.com/sgl-project/sglang/pull/47162) · state: closed · merged: True

## Original PR description

## What

Give rocm10 earlier scheduled slots, spread AMD CI work out of the 17:30 UTC queue spike, and prefer current-day images over older runner caches. The schedule aims to reduce overlap with the 02:00–11:00 UTC PR peak; it does not enforce execution or completion order.

- **Image builds move one hour earlier.** They keep their one-hour stagger.
- **rocm10 is scheduled first, every day.** The PR test runs every 12 hours, at 13:00 UTC first. The nightly runs at 16:00 UTC as its own rocm10-only run.
- **ROCm 7.2 is scheduled later, one image flavor per day.** rocm724 runs on even UTC days of the month and rocm720 on odd days. Both its scheduled PR test and nightly select that flavor on the same day; they still resolve images and source commits independently.
- **MILES has the last scheduled nightly slot.**
- **Prefer the newest date for the requested image base tag.** `amd_ci_start_container.sh` checks today locally and remotely before considering yesterday, continuing through the previous six dates. An older local cache no longer wins over a newer remote dated tag.

D is the UTC day the images are built. Beijing is UTC+8. PT is PDT (UTC−7); every PT time moves one hour earlier when PST starts on Nov 1.

| # | Run | Before (UTC) | After (UTC) | Beijing | PT |
|---|---|---|---|---|---|
| 1 | Nightly images: rocm10, rocm7.2, MILES | 10:00, 11:00, 12:00 | **D 09:00, 10:00, 11:00** | D 17:00, 18:00, 19:00 | D 02:00, 03:00, 04:00 |
| 2 | `pr-test-amd.yml`, rocm10 | 00:00, 12:00 | **D 13:00, D+1 01:00** | D 21:00, D+1 09:00 | D 06:00, D 18:00 |
| 3 | `nightly-test-amd.yml`, rocm10 | 17:30, with 7.2 | **D 16:00, every day** | D+1 00:00 | D 09:00 |
| 4 | `pr-test-amd.yml`, rocm724 / rocm720 | 17:30, both daily | **D 19:00**, rocm724 even days / rocm720 odd days | D+1 03:00 | D 12:00 |
| 5 | `nightly-test-amd.yml`, rocm724 / rocm720 | 17:30, both daily | **D 21:00**, rocm724 even days / rocm720 odd days | D+1 05:00 | D 14:00 |
| 6 | MILES nightlies, MI35x and MI30x | 17:30, 21:00 | **D 22:00** | D+1 06:00 | D 15:00 |

AITER Scout (Saturday 20:00 UTC) is not touched.

## Why

- **The midday scheduled rocm10 PR test used the previous day's image.** The 12:00 UTC run starts at 12:16–12:23, while the image has recently finished at 13:06–13:10. An [Oct 28 job](https://github.com/sgl-project/sglang/actions/runs/40686510947/job/122810254338) selected the cached `20261027` tag at 12:17 UTC. Moving the build an hour earlier and the test to 13:00 is expected to leave about 50 minutes of margin. This concerns the scheduled `PR Test (AMD)` run on `main`.
- **Retiming alone did not fix stale cache selection.** Previously, the helper searched all seven local dates before checking any remote date, so yesterday's cache could still win after today's image was published. It now checks local and remote availability for each date before moving to an older date.

  The expected finish times below are the Oct 23–28 times moved one hour earlier; they are not measured yet.

  | Image | Finished, UTC (Oct 23–28) | Expected after this PR, UTC | Beijing | PT |
  |---|---|---|---|---|
  | rocm10 | 13:06–13:10 | 12:06–12:10 | 20:06–20:10 | 05:06–05:10 |
  | rocm7.2 | 14:16–14:20 | 13:16–13:20 | 21:16–21:20 | 06:16–06:20 |
  | MILES | 12:48–13:11 | 11:48–12:11 | 19:48–20:11 | 04:48–05:11 |

- **17:30 UTC had three workflows on the same runners.** The MILES MI35x nightly took 5 `linux-mi35x-gpu-8` runners at 17:33 for about 2 h. The nightly's 8-GPU MI35x jobs and the 7.2 PR test queued behind it.
  - Over Oct 20–27, at 18:00 UTC on weekdays, about 67 scheduled jobs were waiting on `linux-mi35x-gpu-8`, against about 13 PR jobs.
  - The nightly's own jobs waited a median of 43–157 min per run ([Oct 26](https://github.com/sgl-project/sglang/actions/runs/40370684139), [Oct 27](https://github.com/sgl-project/sglang/actions/runs/40552118021)).
- **The nightly tested three image flavors every day.** In the sampled runs, rocm10 used about 146 GPU-hours, rocm724 about 164 and rocm720 about 156. Testing rocm10 plus one 7.2 flavor per day is expected to remove about a third of the scheduled nightly test load. Docker images are still built daily, so this does not reduce image-build frequency or all AMD CI costs by a third.
- **Give rocm10 an earlier opportunity to acquire runners.** Previously the nightly created rocm10 and 7.2 jobs together, alongside the 7.2 PR test. The rocm10 PR test and nightly are now scheduled about three hours before the following workflow. Delays can still cause overlap; there is no runner reservation or cross-workflow completion dependency.

## Notes for the reviewer

- **Image builds.**
  - The three builds move together, so the stagger from #45848 is unchanged. (The MILES rocm724 build was removed in #47194.)
  - `release-docker-amd-gfx1151-nightly.yml` (14:00 UTC, also on `amd-docker-scale`) is not touched and still starts after them.
  - Tags use the UTC date, so 09:00–11:00 still tags the same day.
- **Workflow ROCm flavor selection.**
  - `pr-test-amd.yml`: `github.event.schedule` maps `0 19 2-30/2 * *` to rocm724 and `0 19 1-31/2 * *` to rocm720. Explicit `rocm_version` inputs keep precedence; other triggers without a version input default to rocm10.
  - `nightly-test-amd.yml` has three crons:
    - `0 16 * * *` runs rocm10.
    - `0 21 2-30/2 * *` runs rocm724.
    - `0 21 1-31/2 * *` runs rocm720.

    Each of the 46 per-job matrix expressions maps them, placed before the three-image default.
  - Dispatch with `rocm_version`, the `version.py` push trigger, and the `workflow_call` callers (AITER Scout, version bump, release branch cut) keep their current behaviour.
  - actionlint reports the same findings on both workflows before and after.
- **Dated image resolution.**
  - For the requested ROCm/architecture/base tag, search today and the previous six dates. For each date, check the local cache first, then the remote manifest. Only then consider an older date.
  - Example: with local `20261028` and remote `20261029`, select and pull `20261029`. Today's local cache still avoids an unnecessary manifest probe.
  - If a dated tag cannot be resolved, continue through the existing fallbacks. A failed remote probe can also reflect a registry, authentication, or network problem. Existing versioned-image and hard-coded fallback paths are unchanged.
  - This shared helper change also applies to ordinary AMD PR CI jobs that use automatic image selection. Explicit custom images keep their current behavior. It does not pin a common image digest or source SHA across independent runs.
- **Month boundaries and coverage.** Each 7.2 flavor changes from daily scheduled coverage to usually once every 48 hours, including the delegated AMD Extra coverage. Day-of-month steps restart each month: after a 31st, rocm720 runs two days in a row and rocm724 has a 72-hour gap (for example, Oct 30 to Nov 2).
- **Monitoring is unchanged.** `scripts/ci_monitor/ci_failures_analysis.py` still reads the latest six scheduled nightly runs. With two AMD runs per day, this is about three days of history: typically three rocm10 observations and one or two per 7.2 flavor. This can affect consecutive-failure classification; absent flavors are not counted as successful tests. No monitoring-script changes are included in this PR.
- **Expected effect.** This comes from a FIFO replay of the Oct 20–27 jobs, with per-pool capacity fitted to the observed waits and the runs moved to the new times. It is an estimate, not a measurement.
  - Total PR queue time falls by about 11%.
  - Mean PR wait on `linux-mi35x-gpu-8` falls from about 67 to 27 min, and on `linux-mi300-8gpu-sglang` from about 9.5 to 6.8 min.
  - The rocm10 PR test and nightly finish before the 7.2 runs start on every replayed day. This does not count `linux-mi35x-gpu-1` jobs: that pool is saturated by PR jobs at every hour, so its jobs wait regardless of schedule.

## Validation

Completed locally:

- Executed the actual Bash `find_latest_image` function in a temporary regression harness with mocked Docker, registry, and date commands: **14/14 cases passed**. The previous implementation failed the three targeted stale-cache cases.
- Covered newer remote tags taking precedence over older local caches on MI30x/MI35x, current-day local cache hits, older-date fallback, existing versioned-image/hard-coded fallback paths, and error paths.
- `bash -n scripts/ci/amd/amd_ci_start_container.sh` and `git diff --check` passed.
- Reviewed all 46 nightly ROCm matrix expressions for consistent schedule selection.

The function-level checks do not validate live Docker/GPU execution or scheduled trigger timing. After merge, verify on the scheduled runs that:

- the image builds finish earlier and the 13:00 UTC rocm10 PR test selects the current-day tag when it is available;
- the 16:00 UTC nightly creates only rocm10 jobs;
- the 19:00 UTC PR test and 21:00 UTC nightly select rocm724 on even UTC dates and rocm720 on odd dates;
- MILES starts in the 22:00 UTC scheduled slot;
- `linux-mi35x-gpu-8` queue times and workflow completion times improve over the first week. The replay estimates above are not post-merge measurements.
