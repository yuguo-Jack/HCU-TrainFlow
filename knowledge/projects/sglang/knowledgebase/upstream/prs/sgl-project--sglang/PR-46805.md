# [Perf] [NPU] dsv4: drop host-syncing ops from the decode scheduler chain (aclnnNonzeroV2 + D2H)

[Upstream PR](https://github.com/sgl-project/sglang/pull/46805) · state: closed · merged: True

## Original PR description

# Motivation

DSV4-NPU decode schedules everything on a single host thread. Three ops on that chain synchronized with the device mid-chain, pinning the scheduler thread until the in-flight forward drained and leaving the NPU idle:

1. The verify bundle built the ratio-4 compressed loc table with a boolean index (`x[mask]` → aclnnNonzeroV2; output shape depends on device data, so the count must be read back to host) — ~3.9 ms/round on the spec path.
2. The same boolean index in `_derive_c4_loc_from_full` on the alloc path — 32.5 ms/round on the non-spec path (it inherited the whole queue-drain wait once the mirror D2H was disabled).
3. `maybe_write_dsv4_decode` read `batch.req_pool_indices` back to host (31.4 ms/round, same inheritance).

## Modifications

- New `_compact_c4_loc` helper (dsv4_common_hooks.py): compacts the group-closing slots fully on device via `cumsum → masked_fill → scatter` (a trash slot absorbs invalid rows, sliced away after). All shapes are host-known, so nothing syncs. Output is zero-padded to a fixed upper bound — byte-identical to what the consumers already build from the compact tensor (eager `zeros(bs)` prefix copy / graph-replay zero-tail), so no consumer changed.
- Call sites pass a constructively-safe bound only where it holds: the verify bundle uses `min(t, t//4 + bs)` (the padding width the backend already applies); plain decode passes `t` (one new slot per request bounds the count unconditionally). Multi-slot (spec reserve) and extend shapes keep the original boolean index.
- `maybe_write_dsv4_decode` takes the batch's `req_pool_indices_cpu` host mirror (the extend hook's existing contract) instead of D2H-syncing the device tensor.

All changes are behind NPU/DSV4 gates; CUDA paths are untouched.

## Speed Tests and Profiling

Steady-state decode profiling, 16×NPU TP16+DP16, bs=2:

| Path | Round | Device-idle (Free) |
|---|---|---|
| DSPARK spec, before | 68.3 ms | 16.3 ms |
| DSPARK spec, after fix 1 | 64.0 ms (-6.3%) | — |
| non-spec (env=0), before | 50.2 ms | 12.8 ms |
| non-spec (env=0), after both | **39.2 ms (-22%)** | **1.7 ms (-87%)** |

Device Computing unchanged in both — the gain is pure bubble removal; no sync op >1 ms remains on the chain.

End-to-end (256 reqs, 16k in / 1k out, unlimited stream):

| Path | Duration | Throughput | Mean TPOT |
|---|---|---|---|
| spec, fix 1 | 564 → 489 s | 7715 → 8900 tok/s (+15.4%) | 128.9 → 111.9 ms |
| non-spec, fix 2 | 261 → 238 s | 8322 → 9126 tok/s (+9.7%) | 52.4 → 46.7 ms |

TTFT unchanged (decode-scheduler path only). Each commit's e2e gain is attributable in isolation: fix 1 only runs under dspark, fix 2 only affects the non-spec decode alloc chain.
