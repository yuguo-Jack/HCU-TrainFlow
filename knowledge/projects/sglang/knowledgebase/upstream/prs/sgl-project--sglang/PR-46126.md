# [CI] disaggregation: Run the SWA decode radix cache test on Mooncake

[Upstream PR](https://github.com/sgl-project/sglang/pull/46126) · state: closed · merged: True

## Original PR description

## Motivation

`test_disaggregation_decode_radix_cache_swa.py` fails in `setUpClass` on the slower 8xH200 runners before any test runs:

```
RuntimeError: NIXL create_backend('UCX', {'num_threads': '8'}) did not return within 60s on radixark-wk03
RuntimeError: Server process exited with code -9
```

Example: https://github.com/sgl-project/sglang/actions/runs/39977798414/job/120497020607. The three Mooncake tests in the same partition passed on the same runner.

This is not a hang. The prefill worker asks NIXL for 8 progress threads and NIXL opens one UCX worker per thread; each worker builds receive memory pools for every RDMA transport on every listed device, so init time grows linearly with the thread count. Measured inside the `h200-gmi-wk03` runner container (NIXL 1.3.0, idle): 3.7 s at 0 threads, 49.5 s at 8 threads; under a real CI job the prefill side took 46.2 s and crossed 60 s. Mooncake's engine init on the same hosts takes well under 10 s.

## Modifications

- Run `TestDisaggregationDecodeRadixCacheSWA` on Mooncake instead of NIXL, matching the other decode radix cache tests. Decode-side radix cache is orthogonal to the transfer backend (#39544 dropped the plain NIXL variant for that reason), NIXL keeps its own coverage in `test_disaggregation_nixl.py`, and #27770 validated this path on both backends.
- No server args or thresholds change.

Supersedes #46121, which raised `SGLANG_DISAGGREGATION_ENGINE_INIT_TIMEOUT` instead.
