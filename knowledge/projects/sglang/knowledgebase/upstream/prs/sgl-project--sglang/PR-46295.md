# [Fix] minimax-m2: Scope streamed parameters to the current invoke

[Upstream PR](https://github.com/sgl-project/sglang/pull/46295) · state: open · merged: False

## Original PR description

## Motivation

Fixes #46293. When one streaming delta closes an invoke and also carries the next invoke's parameters, `MinimaxM2Detector.parse_streaming_increment` merges those parameters into the closing call. The client then receives, for example, `get_weather(Paris)` twice instead of `get_weather(Tokyo)` and `get_weather(Paris)`. Deltas this large happen when `TokenizerManager` coalesces queued outputs under load, with `--stream-interval > 1`, or with speculative decoding.

## Modifications

- `minimax_m2.py`: find `</invoke>` first, then pass only the text before it to `_parse_and_stream_parameters`. Before, the whole buffer was passed. The completion check reuses the same `end_pos`. Nothing else changes.
- New `test/registered/unit/function_call/test_minimax_m2_detector.py` (CPU, `base-a-test-cpu`). This detector had no unit tests before. The three tests are:
  - both calls in one delta;
  - a delta that starts inside call 0 and ends inside call 1;
  - a no-argument call followed by a call with arguments.

## Accuracy Tests
