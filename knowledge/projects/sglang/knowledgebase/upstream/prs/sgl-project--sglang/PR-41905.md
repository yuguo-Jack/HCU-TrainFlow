# [AMD][DSV4] fp8 verify: write the SWA ring in the fused norm/rope kernel

[Upstream PR](https://github.com/sgl-project/sglang/pull/41905) · state: open · merged: False

## Original PR description

## Motivation

With fp8 unified_kv (`SGLANG_DSV4_UNIFIED_KV_FP8=1`), DSpark target verify writes the SWA ring the slow way. `_forward_prepare` copies the strided `kv` (`kv.contiguous()`, 61 copies per step). The fused kernel then packs an fp8 pair, and the backend scatters it into the ring with `store_swa_into_unified` (2 `_swa_scatter` launches per layer, 122 per step). In a profiled DSpark b6 step, these took 0.28 ms and 0.55 ms.

Decode already writes its ring rows inside `fused_qk_norm_rope_group_quant`. The backend also builds a per-token `swa_loc` for verify, so verify can use the same path.

## Modifications

`models/deepseek_v4.py`, `MQALayer._forward_prepare` only:
- fp8 target verify now uses the decode store arm. The kernel writes each draft token's ring row through `get_unified_swa_loc` (the per-token verify `swa_loc`) before attention, reading the strided `kv` directly.
- `kv` is returned as `None`, so the backend skips `store_swa_into_unified`. The `kv.contiguous()` copy and the packed `k_nope_out`/`k_rope_out` pair are no longer used on this path.
- bf16 verify, decode and prefill are unchanged.

This PR does not depend on sgl-project/sglang#41383. It applies cleanly to main and to the image's sglang, and does not touch the attention reader.

## Accuracy Tests

DeepSeek-V4-Pro-0813, TP8 MI355X, DSpark block 6 (7 draft tokens), fp8 unified_kv, image `lmsysorg/sglang-rocm:v0.5.20-rocm724-mi35x-20260927` with only this patch applied (stock asm fp8 decode). gsm8k, 200 questions:

| | accuracy | accept length |
|---|---|---|
| image | 0.975 | 3.99 |
| image + this PR | 0.970 | 4.02 |

The difference is 1 question out of 200. On the FlyDSL stack below, gsm8k with all 1319 questions over 2 boots gave 0.946 / 0.943 before and 0.950 / 0.945 after.

Unit tests `test_deepseek_v4_unified_fp8_q_pair.py` and `test_dsv4_unified_fp8_scatter.py` pass (22/22).

## Speed Tests and Profiling

Removed per verify step: 61 `direct_copy` launches (0.28 ms) and 122 `_swa_scatter` launches (0.55 ms), from the profiled DSpark b6 step.

E2E: DeepSeek-V4-Pro fp8, TP8 MI355X, 8k in / 1k out, DSpark b6, same image. The pairs were measured on our DSv4 decode stack, sgl-project/sglang#41383 + ROCm/aiter#5882 (FlyDSL fused decode). Before = that stack; after = stack + this PR. 2 boots x 3 reps, alternating order:

| cell | verify step before -> after (ms) | delta mean [min, max] | steady decode tok/s |
|---|---|---|---|
| DSpark b6 c16 | 26.94 -> 26.38 | **-2.09%** [-0.771, -0.448 ms] | 3608 -> 3711 (+2.8%) |
| DSpark b6 c64 | 45.94 -> 45.33 | **-1.33%** [-0.787, -0.504 ms] | 8391 -> 8532 (+1.7%) |

All 12 pairs are faster. Accept length is unchanged (6.07 / 6.12 at c16, 6.12 / 6.14 at c64). Plain decode is not affected.
