# [diffusion] Z-Image: replace padded rows without a host sync

[Upstream PR](https://github.com/sgl-project/sglang/pull/44069) · state: closed · merged: True

## Original PR description

## Motivation

`ZImageTransformer2DModel._replace_padding_with_token` runs on every forward, for the image tokens and, without a caption mask, for the caption tokens. It writes the pad token through a boolean mask, `tensor[pad_mask] = pad`, which runs `nonzero` and blocks the host until the GPU catches up. It also builds the lengths with `torch.tensor(list, device=...)`, which is another blocking copy. Each forward therefore starts by draining the GPU queue, and the host loses the lead it needs to hide launch overhead.

## Modifications

- When the lengths are a Python list, write each padded row by slice (`tensor[row, length:] = pad`); there is no mask and no host-to-device copy.
- When the lengths are a tensor, select with `torch.where`, as the masked variant `_replace_padding_with_token_mask` in the same file already does.

Values are unchanged, since the change is a selection or copy with no arithmetic.

## Accuracy Tests

`python/sglang/multimodal_gen/test/unit/test_zimage_padding_no_sync.py` compares the result with the previous mask-assignment implementation, for list and tensor lengths. It runs under `torch.cuda.set_sync_debug_mode("error")`, so any synchronizing CUDA call fails the test. On main, these tests fail with `called a synchronizing CUDA operation` at `zimage.py:1469`. The existing `test_zimage_pipeline_config` and `test_zimage_qknorm_fusion` pass. Z-Image-Turbo output md5 matches main at 512² and 1024².
