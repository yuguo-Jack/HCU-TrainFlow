# [Fix] attention: Mask empty splits in verify_splitkv stage2 combine

[Upstream PR](https://github.com/sgl-project/sglang/pull/45387) · state: open · merged: False

## Original PR description

## Motivation

`_verify_combine_stage2` merges the prefix splits with weights `exp(lse - max)`. A split whose KV range is empty skips the stage1 store of `Att_Out` and only writes the `-inf` lse sentinel, so its weight is 0. Stage2 still loads that split's `Att_Out` row, which holds whatever the reused scratch buffer (`VerifySplitKV.att_out`, cached per shape in `_VK_CACHE`) last contained, and computes `ao * 0`. If that stale memory is nan or inf, `0 * nan = nan` and the whole draft row of the output becomes nan.

Empty splits are routine, not a corner case. A split covers whole 32-key blocks, so:

- with 4 splits, any prefix of 96 keys or fewer leaves at least one split empty;
- with 16 splits (chosen from the batch-average prefix, so a long request in the batch selects it), a short request in the same batch leaves most of its splits empty. For example, a 100-key prefix fills 4 of 16.

The cached buffer is allocated with `torch.empty`, so its first contents come from the caching allocator and are not guaranteed finite. Raising the split cap, as proposed in #35521, makes empty splits more frequent.

## Modifications

- `verify_splitkv.py`: in stage2, load `Att_Out` only where the split is valid (`lse > -inf`), with `other=0.0`. Valid splits are unchanged, so results on inputs that were already finite are bit-identical.
- `test_verify_splitkv.py`: add `test_empty_splits_ignore_stale_scratch`. It fills the cached `att_out` with nan, then runs the existing parity check against `extend_attention_fwd` for prefixes `[64]` (4 splits, 2 empty) and `[16384, 100]` (16 splits, 12 empty for the short request).
