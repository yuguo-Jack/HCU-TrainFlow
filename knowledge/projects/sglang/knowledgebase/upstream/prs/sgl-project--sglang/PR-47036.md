# [Perf] [AMD] kda: Run gfx950 KDA prefill extend on AITER Gluon chunk_kda

[Upstream PR](https://github.com/sgl-project/sglang/pull/47036) · state: open · merged: False

## Original PR description

## Motivation

- On gfx950, KDA prefill extend with a bf16 SSM state pool (`--mamba-ssm-dtype bfloat16`, used by the Kimi-K3 MI355X recipe) runs on Triton `chunk_kda`.
- The HIP gfx950 prefill kernel from #45710 only takes an fp32 state pool, so it does not cover this case.
- AITER ships a Gluon `chunk_kda` for gfx950 (ROCm/aiter#5866, `aiter.ops.triton.attention.chunk_kda`). In the kernel microbenchmark below it is 1.3x to 2.3x faster than the Triton path.
- `forward_extend` also asked every kernel for per-chunk states `h` on every tracked batch, even when only aligned boundaries were tracked and `h` was never read. That kept final-state-only kernels off those batches.

## Modifications

- New `python/sglang/kernels/ops/attention/linear/kda_aiter_prefill.py`: `extend()` runs AITER Gluon `chunk_kda`, or returns None when it does not cover the batch (same pattern as `kda_gfx950_prefill.extend()`).
  - Gathers the `cache_indices` rows of the state pool (bf16 or fp32) into an fp32 initial state, then scatters the final state back in place.
  - Padded (negative) slots start from zeros and leave the pool unchanged.
  - Caches the chunk metadata per `cu_seqlens` tensor (like the Triton path's `tensor_cache`), so its host sync runs once per forward, not once per KDA layer.
  - Registered in the kernel inventory as `attention.kda_aiter_prefill` (AITER backend, HIP).
- `TritonKDAKernel.extend` on ROCm tries the HIP kernel (fp32 pools) first, then AITER Gluon, then Triton `chunk_kda`. Batches the HIP kernel already covers do not change.
- `KDAAttnBackend.forward_extend` sets `return_intermediate_states` only when an interior chunk boundary is tracked (`track_ssm_h_src` non-empty).
  - FlashKDA and CuteDSL no longer fall back or raise on aligned-only tracked batches. Their fast paths now return a bare output tensor, matching the "tuple only when `h` is requested" contract.

| Batch | Path |
|---|---|
| gfx950, fp32 pool, covered by the HIP kernel | HIP kernel (#45710), unchanged |
| gfx950, AITER Gluon `chunk_kda` present, covered (e.g. bf16 pool) | AITER Gluon |
| not gfx950, or AITER without Gluon `chunk_kda` | Triton `chunk_kda` |
| `SGLANG_OPT_HIP_KDA_AITER_PREFILL=0` | Triton `chunk_kda` |
| per-chunk `h` or an fp32 `track_state` snapshot requested | Triton `chunk_kda` |
| draft-extend (`is_spec_decode`) | Triton `chunk_kda` (same as the HIP kernel) |
| padded chunk tables from breakable prefill CUDA graphs | Triton `chunk_kda` |
| non-raw beta, `lower_bound` missing or outside `[-5.5, 0)`, head dim != 128, non-bf16 q/k/v/g | Triton `chunk_kda` |
| `cache_indices` length != number of sequences | Triton `chunk_kda` |

| New env var | Default | Effect |
|---|---|---|
| `SGLANG_OPT_HIP_KDA_AITER_PREFILL` | `true` | `0` keeps gfx950 KDA prefill extend off AITER Gluon `chunk_kda` |

- Tests: `test/registered/kernels/ops/attention/test_kda_aiter_prefill.py` (MI35x, `stage-b-test-1-gpu-small-amd-mi35x`):
  - On a bf16 pool, `TritonKDAKernel.extend` takes the Gluon route and does not fall back to Triton.
  - Output and written state rows match Triton `chunk_kda` (RMS ratio < 1e-2) for bf16 and fp32 pools across 4 length mixes; untouched pool rows stay bitwise unchanged.
  - A padded (negative) cache index starts from zeros and writes no pool row.
  - Each uncovered input in the table above, and the env opt-out, return None.

## Accuracy Tests

Kernel level, against Triton `chunk_kda` on the same inputs. RMS ratio = `||aiter - triton|| / ||triton||`. One MI355X, image AITER `285579b62`, H=12, D=128, random inputs, one run:

| State pool | Lengths | Output RMS ratio | Final state RMS ratio |
|---|---|---:|---:|
| bf16 | 64, 96 | 5.69e-3 | 4.44e-3 |
| bf16 | 8192 | 5.91e-3 | 4.46e-3 |
| bf16 | 17, 4096, 333 | 5.88e-3 | 4.40e-3 |
| fp32 | 64, 96 | 5.69e-3 | 3.94e-3 |
| fp32 | 8192 | 5.91e-3 | 3.98e-3 |
| fp32 | 17, 4096, 333 | 5.88e-3 | 3.92e-3 |

End to end, GSM8K with sgl-eval 0.1.3, all 1319 questions, `--load-preset-from-model-id moonshotai/Kimi-K3` (temperature 1.0, top_p 0.95, thinking on):

| Prefill extend | GSM8K | Runs | Accept length |
|---|---|---:|---:|
| Triton `chunk_kda` (route reverted) | 96.89% | 1 | 3.11 |
| AITER Gluon `chunk_kda` | 97.19 / 97.42 / 97.12, avg 97.24% | 3 | 3.18 |

- Setup: 8x MI355X, Kimi-K3-Quark-MXFP4-AttnFP8, TP8, DCP1, DSpark block 3 with real acceptance, `--mamba-ssm-dtype bfloat16`, ROCm 7.2.4.
- That build carries this route as its original commit: the same kernel route plus the `forward_extend` change, without the metadata cache, the env switch and the draft-extend exclusion. The baseline is the same build with only that commit reverted.

## Speed Tests and Profiling

Kernel microbenchmark, one MI355X, H=12, D=128. A 1 GiB buffer is zeroed before every call to flush L2 and the 256 MB Infinity Cache. Median of 30 event-timed calls, one run. Times include the wrapper's gather and scatter. Triton is the path these bf16-pool batches take on main today.

| Lengths | Triton, bf16 pool | AITER Gluon, bf16 pool | Triton, fp32 pool | AITER Gluon, fp32 pool | HIP #45710, fp32 pool |
|---|---:|---:|---:|---:|---:|
| 8192 | 0.480 ms | 0.213 ms | 0.487 ms | 0.202 ms | 0.170 ms |
| 4 x 2048 | 0.301 ms | 0.209 ms | 0.306 ms | 0.197 ms | 0.137 ms |
| 16 x 512 | 0.274 ms | 0.214 ms | 0.279 ms | 0.208 ms | 0.092 ms |

- On fp32 pools the HIP kernel is faster, so it stays first in the dispatch order.

End to end, same setup and A/B as the GSM8K runs. `bench_serving` generated-shared-prefix, 32 groups x 8 prompts, 16K shared prefix, 1K question, 256 output tokens, concurrency 16. One unrecorded warm-up pass, then 3 passes with the cache flushed.

| Prefill extend | Mean TTFT |
|---|---:|
| Triton `chunk_kda` (route reverted) | 1,334 ms |
| AITER Gluon `chunk_kda` | 1,324 ms (-0.8%) |

- Two servers running identical code differ by up to about 2.5% in mean TTFT on this workload, so -0.8% is within noise. No end-to-end TTFT gain is claimed.
