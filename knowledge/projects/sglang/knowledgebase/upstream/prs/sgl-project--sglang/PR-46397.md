# [Fix] [AMD] deterministic: Batch-invariant MiniMax sparse-attention decode

[Upstream PR](https://github.com/sgl-project/sglang/pull/46397) · state: open · merged: False

## Original PR description

## Motivation

With `--enable-deterministic-inference`, MiniMax-M3 on MI350X gives a long prompt different tokens depending on how many requests share its decode batch: a 4k-token prompt matches its batch-size-1 output in batches of 2-8 requests and differs from 16 requests up, whatever the other requests are. The sparse-attention decode kernels choose their split-K chunk counts from the batch size (`flash_decode_with_topk_idx`: `NUM_KV_CHUNKS` from `4096 // (batch_size * num_kv_heads)`; `flash_decode_with_gqa_share_sparse`: `NUM_TOPK_CHUNKS` from `256 // (batch_size * num_kv_heads)`), and on gfx950 the decode score kernel uses a 512-token tile for batches of up to 4 requests and 128 above. Each choice changes the order in which a request's partial results are combined, so its output depends on its batch mates. This PR sizes them for a fixed batch size (16) in deterministic mode. Normal mode is unchanged.

## Modifications

- `minimax_sparse/common/utils.py`: `grid_batch_size(batch_size)` returns 16 when deterministic inference is on (read once from the runtime config) and `batch_size` otherwise.
- `decode/flash_with_topk_idx.py`: the KV chunk count and the gfx950 score-tile choice use `grid_batch_size(batch_size)`.
- `decode/topk_sparse.py`: the top-k chunk count uses `grid_batch_size(batch_size)`.
- New test `test/registered/amd/test_minimax_sparse_decode_batch_invariant.py` (`stage-b-test-1-gpu-small-amd-mi35x`): in deterministic mode, a request decoded alone and among 1-63 other requests (random lengths 2k-8k tokens, random position) gives bitwise identical results with MiniMax-M3's head layouts: the indexer's top-k blocks (score-only, as MiniMax-M3's sparse layers run it) and the sparse attention output; plus the grid-size helper.
- Unchanged: normal mode, other models.

16 is the count of a mid-size batch: at batch size 1 the kernels would launch many more CTAs than needed for large batches (the batch-size-1 counts cost 5.8% decode throughput at 1k in / 1k out, against 3.4% for 16).

## Accuracy Tests

MI350X, ROCm 7.2.4, `rocm/sgl-dev:v0.5.22-rocm724-mi35x-20261021`, MiniMax-M3 (MXFP4), TP2, deterministic mode, together with a deterministic MXFP4 MoE path (not part of this PR; the model's MoE is otherwise not deterministic on this image) and the fp32 router gate (`SGLANG_OPT_USE_BF16_ROUTER_GEMM=0`).

`python3 -m sglang.test.test_deterministic` (`single`, `prefix`, `prefix --return-logprob`, `radix_cache`, 50 trials) plus a bitwise batch-size check (the same prompt in batches of 1 to 50, 1,275 responses, token IDs and logprobs compared exactly with the batch-size-1 response):

| | before | this PR |
| --- | --- | --- |
| `single` | 1 output | 1 output |
| `prefix` (4 prompts, outputs per prompt) | 1 / 2 / 3 / 4 | 1 / 1 / 1 / 1 |
| `prefix --return-logprob` | logprobs differ | identical |
| bitwise batch-size check | 1,275 / 1,275 | 1,275 / 1,275 |
| 4k-token prompt in batches of 2-50 (25 cases) | differs from 16 requests up | 25 / 25 identical |

With this branch's files the checks above pass on 2 / 2 fresh servers (the table's "this PR" column was measured with the same logic behind an experiment-only switch, on 3 / 3 more fresh servers). GSM8K (sgl-eval 0.1.2, temperature 0, 1,319 questions): 95.60%. The new test passes on MI350X (`7 passed`); with deterministic mode off it fails (4 of 7: the sparse attention output at every layout and the grid-size check; the top-k selection matches either way, since the max block scores do not depend on the split).

Scope: these results are at TP2. At TP4 MiniMax-M3 shows a separate difference through the prefix cache (a cached prefix vs a fresh prefill), which this PR does not change.

## Speed Tests and Profiling

Deterministic mode, MiniMax-M3 TP2, `python3 -m sglang.benchmark.serving --backend sglang --dataset-name random --random-range-ratio 1.0 --request-rate inf`, output throughput:

| workload | before | this PR | change |
| --- | --- | --- | --- |
| 1k in / 1k out, 256 prompts | 2,383 tok/s | 2,302 tok/s | -3.4% |
| 8k in / 1k out, 128 prompts | 588.2 tok/s | 582.2 tok/s | -1.0% |

Normal mode is unchanged.
