# [diffusion] comfyui: video-to-video, audio-video node, prompt enhancement, checkpoint sweep, LoRA stack, request logging

[Upstream PR](https://github.com/sgl-project/sglang/pull/43673) · state: open · merged: False

## Original PR description

## Summary

Six small additions to the ComfyUI server-mode nodes, one commit each. All of them use server endpoints and request fields that already exist; there are no server changes.

1. **Video-to-video**: the generic video node gets an optional `VIDEO` input, sent as `video_path`.
2. **Generic audio-video node**: one node for any model that muxes audio into its MP4 (H3, LTX-2, MOVA, Kandinsky-6). Returns `VIDEO`, `AUDIO` (decoded with PyAV, which ComfyUI already ships) and the file path. Model-specific request fields go in an `extra_request_json` input, so a new model needs no new node.
3. **Prompt enhancement**: `enhance_prompt` toggle on the image, video and audio-video nodes, plus a trailing `revised_prompt` `STRING` output. Without enhancement it is the original prompt. Server error details now show up in node errors, so a missing `--prompt-enhancer-config` says so instead of "400 Bad Request".
4. **Checkpoint sweep**: renders one prompt and seed across checkpoints (`checkpoint-{step}`, default 500 to 5000) using `/update_weights_from_disk`, and tiles them into a grid. The original weights are restored at the end, including when a step fails.
5. **LoRA browser and stacking**: `List LoRAs` node, a `LoRA Stack` node (4 slots, per-LoRA strength, one merge mode and target), and `strength` / `merge_mode` on the existing `Set LoRA` node. Slot dropdowns list the adapters loaded on the server last connected to.
6. **Workflow to API recipe**: reads the workflow graph (hidden `PROMPT` input) and renders the image / video / audio-video node as a `curl` command, Python snippet, or `sglang generate` command. The API key is never written out; snippets read `$SGLANG_API_KEY`.

## Behavior notes and limits

- **No denoise-strength control.** `/v1/videos` has no such field, so a slider would be silently ignored. Left out until the server supports it.
- **No `AUDIO` input.** The server has no audio-conditioning field on `/v1/videos` either. Output side only for now.
- Existing graphs keep working: new outputs are appended after the old ones, new inputs are optional, and the old `Set LoRA` payload only gains `strength: 1.0`.
- Stacking several LoRAs on one target needs `merge_mode` `merge` (or `auto`). The server's `dynamic` mode takes one adapter per target, so the node rejects that combination up front.
- The checkpoint sweep is for image models, and each checkpoint directory must be readable by the server and laid out like the served model.
- The recipe follows inputs that come from primitive or text nodes. Anything else falls back to the node default and is flagged in a comment, as are reference files you need to replace.

## Testing

CPU only, no GPU run. The ComfyUI modules are stubbed and only HTTP is mocked, so the real nodes and the real client run together.

- 76 new tests in `ComfyUI_SGLDiffusion/test/`, passing after every commit (5, 12, 19, 38, 53, 76).
- The audio test builds a real MP4 with an AAC track and decodes it.
- A parity test runs the real nodes and checks the recipe sends the same payload.
- Checked that the sweep tests fail when the restore or the fixed seed is broken.
- `ruff` (the pre-commit selection), `ruff format` and `isort` are clean.

`test_h3_request.py` already fails to collect on `main`: its `folder_paths` stub has no `folder_names_and_paths`, which the gguf helper reads at import. I did not touch it. The new tests use their own harness (`test/harness.py`).
