# [Fix] hicache: Defer query beliefs until the rank-synchronized hit drain

[Upstream PR](https://github.com/sgl-project/sglang/pull/43108) · state: closed · merged: True

## Original PR description

In `buffer_only` mode, revoking a storage prefetch can update storage-existence beliefs from rank-local query results before their reduction. TP ranks can then disagree about whether a prefix is already stored and make different backup decisions. Cancellation can also cause a rank to skip the query; that lack of query evidence must not be treated as a storage miss.

This change updates beliefs only when consuming the rank-synchronized `prefetch_hit_queue`:

- Remove query-driven belief updates from `revoke_pending_prefetch`.
- Apply query evidence at the start of each hit-queue drain iteration, before handling removed requests, terminated operations, or below-threshold hits.
- Skip belief updates when the reduced result has no KV verdict, indicating that a rank did not query storage. An explicit zero-page KV verdict remains a real miss and can invalidate existing beliefs.

The added sidecar unit test uses the actual query and synchronization methods with a stub storage backend and simulated MIN reduction. It checks that cancellation preserves existing KV beliefs when the peer skipped the query (`-1`), but invalidates them when the peer reports a miss (`0`). The terminated-query lifecycle fixture also gains `all_hash_values=None` for the belief-update path now reached during draining.

Belief updates reuse the existing synchronized drain and add no collective.
