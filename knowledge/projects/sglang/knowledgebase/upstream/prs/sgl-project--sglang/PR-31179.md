# feat(anthropic): support document content block in /v1/messages

[Upstream PR](https://github.com/sgl-project/sglang/pull/31179) · state: closed · merged: False

## Original PR description

## Motivation

The Anthropic Messages API (`/v1/messages`) supports a `"document"` content
block type (introduced mid-2024) for native PDF / plain-text document ingestion.
SGLang's Anthropic-compatible endpoint previously raised a validation error or
silently dropped such blocks, breaking clients that send document content
(e.g., Claude SDK users passing PDF files).

This PR adds first-class support for the `document` block type so that
SGLang no longer rejects these requests.

## Modifications

**`python/sglang/srt/entrypoints/anthropic/protocol.py`**
- Added `DocumentBlockSource` model supporting `base64`, `text`, and `url`
  source types (matching the Anthropic API schema).
- Added `DocumentBlock` model with optional `title`, `context`, `citations`
  and `source` fields.
- Registered `DocumentBlock` in the `AnthropicContentBlock` discriminated
  union so Pydantic can parse it correctly.

**`python/sglang/srt/entrypoints/anthropic/serving.py`**
- Added handling for `block.type == "document"` in the message conversion
  pipeline with a best-effort text fallback strategy:
  - `text` source → content is passed through directly as a `text` part.
  - `base64` source → emits a notice that binary content cannot be decoded by
    local models.
  - `url` source → emits the URL so the model has context about the document.
  - `title` / `context` fields are prepended when present.

> **Note:** Local models cannot natively parse binary PDFs, so this
> implementation intentionally falls back to text representation rather than
> attempting PDF decoding.

## Accuracy Tests

No model-output changes for standard text / image requests — the new code
path is only triggered when `"type": "document"` blocks are present.

Manual verification:

```bash
# text source — content passed through
curl -X POST http://localhost:30000/v1/messages \
  -H "Content-Type: application/json" \
  -d '{
    "model": "...",
    "max_tokens": 64,
    "messages": [{
      "role": "user",
      "content": [{
        "type": "document",
        "source": {"type": "text", "text": "Hello from a document."},
        "title": "Test Doc"
      }]
    }]
  }'
