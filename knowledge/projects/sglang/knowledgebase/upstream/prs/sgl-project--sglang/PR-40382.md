# [Bugfix] Discover profile traces written with a profile_prefix

[Upstream PR](https://github.com/sgl-project/sglang/pull/40382) · state: closed · merged: False

## Original PR description

### What this fixes

`ProfileMerger._discover_trace_files()` globs only `<profile_id>*.trace.json.gz`. But when a `profile_prefix` is set, `SchedulerProfilerManager._stop_profile()` writes files named:

```
<profile_prefix>-<profile_id>-TP-<rank>[-DP-...][-PP-...][-EP-...]<stage>.trace.json.gz
```

So the trace files start with the prefix, discovery finds nothing, and `merge_profiles=True` combined with a `profile_prefix` fails with `No trace files found for profile_id`.

### Fix

Add an additional `<prefix>-<profile_id>` pattern while keeping the existing one, so prefixed traces are discovered. The merged output (`merged-<profile_id>.trace.json.gz`) is still excluded by the existing filter. No API change.

### Reproduction / test

Added `test_discover_trace_files_with_profile_prefix` in `test/registered/unit/utils/test_profile_merger.py`: creates `DECODE-<id>-TP-0/-TP-1` traces plus the merged output and asserts only the prefixed traces are discovered. CPU-only, no GPU needed.

Local check of the discovery logic against the new patterns (stdlib-only harness): prefixed + non-prefixed traces are found, the merged file and other profile ids are excluded.

### Related / duplicate check

- #20933 (same bug) was auto-closed for inactivity, and #21092 attempted it but was closed for inactivity — this revives the fix with a regression test.
- #38914 is open and touches `_discover_trace_files`, but only to `glob.escape` literal paths; it does not add prefix discovery. This change only adds an extra pattern, so it is orthogonal.

### AI assistance

AI assistance was used. The change is small and self-contained, and was validated with a CPU-only unit test.
