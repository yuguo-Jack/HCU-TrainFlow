# [Fix] [AMD] KDA: Guard NVIDIA-only decode parity on HIP

[Upstream PR](https://github.com/sgl-project/sglang/pull/44463) · state: open · merged: False

## Original PR description

## Motivation

`test_kda_kernels.py` is registered for AMD CI, but `TestKDAVerifyDecodeParity` only checks `torch.cuda.is_available()`. That check is also true on ROCm, so AMD runs enter `match_cutedsl_decode`, which uses NVIDIA `ex2.approx.ftz.f32` / `lg2.approx.ftz.f32` inline assembly.

The public `fused_sigmoid_gating_delta_rule_update` entry point also lacks a platform check for this option.

## Modifications

- Skip only `TestKDAVerifyDecodeParity` on HIP. Keep the other KDA tests enabled in AMD CI.
- Reject `match_cutedsl_decode=True` on HIP with a clear `ValueError`, before tensor access or kernel compilation.
- Add a platform-guard regression test that can run without a GPU.

## Tests

CPU execution on Linux with Python 3.12 and PyTorch 2.11.0+cu128 (GPUs hidden).

```bash
CUDA_VISIBLE_DEVICES=999 SGLANG_RUST_BUILD_MODE=never SGLANG_BUILD_RUST_EXTS=none \
  PYTHONPATH=python python -m pytest -q \
  test/registered/attention/test_kda_kernels.py::TestKDADecodeParityPlatformGuard
```

**1 passed.** The same test fails against the unmodified entry point from `f7ad4345b8` because it accesses the tensors instead of rejecting HIP.

Also evaluated the test class decorators with CUDA availability true: HIP skips only the decode-parity class; NVIDIA skips none of the classes. No ROCm GPU compilation run was performed.

## Accuracy Tests

The supported kernel paths are unchanged. No numerical accuracy run was performed.

## Speed Tests and Profiling

Not applicable; this adds a guard for an unsupported option and adjusts test selection.
