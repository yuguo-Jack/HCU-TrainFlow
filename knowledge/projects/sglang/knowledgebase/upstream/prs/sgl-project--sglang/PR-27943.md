# Fix DLLM rollout sampling diversity and expose decoding step maps

## Motivation

`LowConfidence` and `JointThreshold` previously selected dLLM block tokens with greedy argmax, so rollout generation ignored sampling parameters such as `temperature`, `top_p`, `top_k`, and `min_p`. This can collapse an RL rollout group to identical samples.

Trajectory-replay algorithms also need to know the decoder step at which each response token was first unmasked. That information already exists inside the dLLM decoder, so this PR exposes it as generic, opt-in decoding metadata instead of adding an algorithm-specific field.

The issues were observed while using SGLang as the rollout backend for [DARE](https://github.com/yjyddq/DARE) with SDAR and LLaDA2.x. Related discussion: https://github.com/yjyddq/DARE/issues/20

## Modifications

- Add a shared dLLM block-token sampling helper.
- Respect per-request `temperature`, `top_k`, `top_p`, and `min_p` in `LowConfidence` and `JointThreshold`.
- Preserve greedy behavior for deterministic sampling, such as `temperature=0` or `top_k<=1`.
- Add an opt-in `return_step_maps` argument to `Engine.generate` and `Engine.async_generate`; the default response contract is unchanged.
- Return `meta_info["step_maps"]` as positive, 1-based decoder-step IDs aligned one-to-one with returned response token IDs.
- Support `LowConfidence` in synchronous and first-done-first-out modes, including per-request flags in mixed batches and prompt-partial blocks.
- Carry step-map state across FDFO rounds and reuse SGLang's existing customized-info transport for streaming and non-streaming responses.
- Fail fast when step maps are requested from an algorithm whose token-edit semantics cannot provide an exact first-unmask trace.
- Propagate the option through normal, disaggregated, and session request construction.

DARE converts the returned 1-based values to its 0-based local unmask-step representation for SDAR/LLaDA2 CJ-GRPO actor replay.

## Tests

Current-main validation:

- Pure CPU sampling contract: greedy preservation and `top_k` support.
- LowConfidence contract: 1-based/token-aligned maps, mixed opt-in batch, synchronous and FDFO state carry.
- Request-propagation/static contract across Engine, request normalization, tokenizer manager, scheduler, and session construction.
- `py_compile`, Black, isort, and `git diff --check` pass for all 16 changed Python files.
- Full upstream CI is running on this PR.

The original rollout-diversity smoke tests used `temperature=0.8`, `top_p=0.95`, `top_k=50`, and `max_new_token=4096`:

- `LowConfidence`: SDAR-8B-Chat, LLaDA2.0-mini, and LLaDA2.1-mini produced diverse rollout groups.
- `JointThreshold`: all seven LLaDA2.1-mini prompt groups produced `unique_count=8/8`.

This change only records step maps when explicitly requested. The default path does not allocate or transport step-map state.
