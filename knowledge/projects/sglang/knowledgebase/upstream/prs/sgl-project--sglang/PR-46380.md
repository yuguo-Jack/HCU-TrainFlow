# [Feat] unified-memory: Admit DSPARK on trtllm_mha

[Upstream PR](https://github.com/sgl-project/sglang/pull/46380) · state: closed · merged: False

## Original PR description

> **Superseded by #46978; closing.** #46978 removed the DSPARK verify allow-list this PR extended (`arg_groups/kv_cache_hook.py`). On unmodified main (`76d5b3ce02`, SM90), Nemotron-3.5-Lightning with its DSPARK draft on trtllm_mha boots under `--enable-unified-memory`, fuses the draft, and matches the default pool on GSM8K (all 1314 questions, greedy, paired by question) and accept length; so does the run without speculative decoding. This PR's gate test passes on main unchanged.
>
> The original description follows for reference.

---

## Motivation

Under `--enable-unified-memory` a DSPARK target was refused at boot on trtllm_mha, the backend a Nemotron-H DSPARK deployment resolves to on SM100. Yet trtllm_mha's target verify already reads the unified pool through the KV-index translator: it is the same verify EAGLE and DFLASH run on trtllm_mha, and its unified page table is refilled from the iteration plan on capture and on every replay. A DSPARK draft on trtllm_mha already fuses into the target's pages.

## Modifications

- DSPARK's verify allow-list (`arg_groups/kv_cache_hook.py`) now includes trtllm_mha.

Test (CPU), `test/registered/unit/server_args/test_unified_memory_spec_gate.py`: the case that admits DSPARK on trtllm_mha (target, and a trtllm_mha draft) fails before this change and passes after; a backend outside every unified set stays refused.

## Accuracy Tests

SM90, `nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16`, TP 1, `--attention-backend trtllm_mha`, `--mamba-ssm-dtype float16`, `--speculative-algorithm DSPARK --speculative-draft-model-path nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-NVFP4-DSpark --speculative-dspark-block-size 3 --speculative-draft-attention-backend trtllm_mha`, radix cache, overlap scheduler, CUDA graphs on. GSM8K (all 1314 test questions, 5-shot, greedy, `python -m sglang.test.run_eval`), paired by question between the pools; median accept length from the scheduler logs. The unified-memory server ran with `SGLANG_DEBUG_POISON_POOL=1`.

| speculative | GSM8K (default / unified) | one pool only right (default / unified), p | accept length (default / unified) |
|---|---|---|---|
| DSPARK | 0.865 / 0.868 | 15 / 20, p = 0.50 | 3.47 / 3.48 |
| off | 0.869 / 0.869 | 8 / 8, p = 1.00 | - |

These runs keep CUDA graphs on throughout. Serving that mixes graph replay with eager trtllm_mha forwards also needs #45667 (open), which fixes the eager metadata path after a graph-built table.
