# [Perf] diffusion: Nomas camera attention reads each frame's value directly when camera_chunk_size is 1

[Upstream PR](https://github.com/sgl-project/sglang/pull/47686) · state: closed · merged: True

## Original PR description

## Summary

When `camera_chunk_size == 1` (the value in the released Hy-Nomas `transformer/config.json`), each camera chunk is one latent frame, so the softmax in `NomasCameraAttention` runs over a single key and equals 1.0. The output for every token is just the value vector of its frame, independent of q and k.

This PR takes that path directly: it skips the `img_attn_q` GEMM, the q/k RMSNorm + RoPE and the per-frame SDPA launches, and gathers `v` by frame index (with `token_offset` for sequence-parallel slices). Other chunk sizes use the old code unchanged. The change is 7 lines in `nomas.py` (`git diff -w`); the rest of the diff is re-indentation of the old path into the `else`.

Scope: this only runs for requests that carry camera poses (`norm_extrinsics`). Requests without a camera never reach this module.

## Evidence

Real Hy-Nomas DiT weights loaded from the assembled checkpoint (0 missing / 0 unexpected keys), H100, 352x640, one 10-latent segment of 8 steps, DiT only, random text embeddings, median of several runs:

| | original | this PR | bitwise equal |
|---|---|---|---|
| hist 0 | 1341 ms | 1237 ms (-8%) | yes |
| hist 3 | 1460 ms | 1271 ms (-13%) | yes |
| hist 8 | 1543 ms | 1322 ms (-14%) | yes |

A second container (slower host CPU) showed larger gains for the same comparison: 1858 -> 1370 ms (-26%) at hist 0, 1920 -> 1438 ms (-25%) at hist 3, 2299 -> 1814 ms (-21%) at hist 3 with action windows. The forward issues about 8k kernel launches and the GPU is idle roughly half the time, so the gain scales with how launch-bound the host is. Absolute numbers differ between containers; only compare within a table.

## Tests

`test_camera_chunk_of_one_reads_each_frames_value_without_attention` in `test_nomas.py`: builds the expected output with real SDPA over random q/k (one key per frame), checks the module matches it, checks a slice that starts mid-frame, and fails if `img_attn_q` is called.

- main: fails (`a one-key softmax needs no query`), Modal CPU.
- This PR: **not run on the final tree** (CPU or CUDA unit tests). Bitwise equality was checked on real weights in the benchmark above.

## Review

An independent review pass found no correctness issue. Optional follow-ups it suggested: a `has_camera` tensor case in the test, and a comment that the shortcut relies on `chunk_size == 1`.

## Not checked

- No end-to-end camera request, only the DiT.
- Fixed-tree CPU and CUDA unit tests not run (see above).
- TP/SP multi-rank run not done; the slice test covers the `token_offset` path on one rank.
