## Motivation

Builds uTLX (standalone TLX, for sglang's TLX kernels) into the ROCm 10 images for MI355X (`gfx950-rocm1000`) 

## Modifications

1. **Opt-in switch.** `--build-arg BUILD_UTLX=1` (default `0`) builds uTLX on `gfx950-rocm1000` and `gfx1250-rocm1000`, the two stages that set `UTLX_TRITON_PATCH`. Any other flavor fails at the start of the final stage rather than after the full build. Without it every flavor builds as before, and gfx950 keeps the SDK's Triton.
2. **Triton with plugin support.** With `BUILD_UTLX=1`, the Triton step builds the flavor's Triton from source into `/sgl-workspace/triton-custom` with `TRITON_EXT_ENABLED=ON`, plus a patch from `docker/patches/` that keeps libtriton's LLVM apart from the SDK's `libLLVM.so` (otherwise `import torch; import triton` segfaults):
   - gfx950: ROCm/triton `4cff872c`, the commit the SDK's wheel comes from, with ROCm/triton#983, which replaces ROCm/triton#978. The version stays `3.8.0+git4cff872c.rocm10.0.0`, which torch pins.
3. **uTLX.** Built from triton-ext `9592ce6` (triton-lang/triton-ext#179) against that Triton; `UTLX_TRITON_ROCM=1` on gfx950 selects its Triton release/3.8 code paths. Waiting this fix to be merged https://github.com/triton-lang/triton-ext/pull/183
4. **Kept in the image.** Triton's source, build tree and LLVM, and triton-ext (`/sgl-workspace/triton-ext`), stay in the image for in-place rebuilds. uTLX's tests and examples are in `/sgl-workspace/utlx`.
With `BUILD_UTLX=1`, gfx950 grows by about 15 GB (Triton's build tree and LLVM) and gets `triton_kernels`; on gfx1250, uTLX adds about 28 MB.

#### 1. 🟠 Should fix: Released rocm10-mi35x images ship without uTLX: this PR adds BUILD_UTLX=0 opt-in unwired into CI
`docker/rocm.Dockerfile:424`

`BUILD_UTLX` defaults to `0`, and no workflow under `.github` passes `--build-arg BUILD_UTLX=1`. So the published `rocm10-mi35x` images built by `release-docker-amd-rocm10.yml` and `release-docker-amd.yml` do not contain uTLX, despite the PR title saying it is built into the gfx950 rocm10 images. The opt-in is deliberate and documented in the Dockerfile header ("Off by default"). Still, nothing in CI exercises the new path: the Triton cherry-pick, the plugin-enabled Triton source build and the uTLX build. Consider rewording the title as opt-in, or adding a matrix entry that builds it.

**Who is affected:** Users of the published gfx950-rocm1000 (rocm10-mi35x) images who expect uTLX to be included; also maintainers relying on CI to catch breakage in the opt-in uTLX build path.

#### 2. 🟠 Should fix: uTLX build fails at cherry-pick if ROCm/triton#983 SHA becomes unreachable: this PR hard-codes it
`docker/rocm.Dockerfile:1220`

The `ROCm/triton#983` cherry-pick (`89c3a46`) is a hard-coded SHA inside the Triton `RUN`, not an `ARG`/`ENV` like `TRITON_REVERT_COMMITS`, so it cannot be overridden without editing the Dockerfile. Today it is the head of `release/internal/3.8.x` and a plain `git clone` fetches it. If that branch is rewritten, the `git cherry-pick` step (not `git clone`) fails and the opt-in build stops. That the patched Triton keeps the SDK's version (`3.8.0+git4cff872c.rocm10.0.0`) is intentional, so torch's pin stays satisfied (stated in the PR comments). Consider exposing the SHA as a build arg.

**Who is affected:** Only image builds with `BUILD_UTLX=1` on `GPU_ARCH=gfx950-rocm1000`, and only if ROCm rewrites `release/internal/3.8.x`.

_Checked against the code by an independent pass._

**Related past reviews:** [#23263](https://github.com/sgl-project/sglang/pull/23263) on `docker/rocm.Dockerfile`

#### 3. 🟠 Should fix: uTLX plugin/Triton mismatch surfaces only at kernel compile time: this PR's uTLX step lacks a smoke test
`docker/rocm.Dockerfile:1278`

The uTLX step installs the plugin without a post-install check (e.g. `python3 -c 'import triton'` with the `utlx` `.pth` loaded, compiling a trivial kernel). The Triton step has such a check at its end. A plugin/Triton mismatch or a plugin load failure would therefore only show when the image is used, not when it is built. Consider adding an import smoke test after the `pip install ./extensions/utlx`.

**Who is affected:** Image builders using `BUILD_UTLX=1` with `GPU_ARCH=gfx950-rocm1000`; the step is off by default.

_Checked against the code by an independent pass._
