# [Feat] deepseek-v4.1: Run encoder SWA bounded replay on PD prefill workers

[Upstream PR](https://github.com/sgl-project/sglang/pull/44952) · state: closed · merged: True

## Original PR description

- Lift the encoder SWA bounded replay rejection for PD prefill workers on CUDA. PD decode and PD prefill on ROCm still reject it. Decode never replays: the prefill sends it the last SWA window, so decode keeps its paged SWA.
- Send the target's SWA from the request window. `RequestWindow.page_indices` returns the window pages holding `[window_start, seq_len)`; `capacity` is whole pages, so each page keeps a paged pool's row offsets and pairs one for one with decode's paged SWA pages. `get_state_buf_infos` registers the window's buffers in place of the paged SWA pool, with the same item length.
- In `_swa_payload`, read the window size from the pool under encoder replay, where the scheduler is not hybrid SWA and keeps none.
- Round the DSpark draft SWA ring up to whole pages, so it holds the same rows per slot as the target window and both components share one page list. PD state registration checks that the two match.
- `RequestWindow.row_loc` owns the `slot * capacity + position % capacity` row formula; the two existing copies call it.

Behavior change, encoder replay only: the DSpark draft ring takes `ceil(window + draft tokens, page)` rows per request slot instead of `window + draft tokens` (256 instead of 134 at page 256), about 55 MB more per rank. Nothing changes without encoder replay.

Known limit: after a prefix hit that adds fewer than 128 tokens, decode's paged draft SWA receives rows below the cached prefix that the prefill's draft ring never wrote (the ring starts at the cached prefix). This can lower acceptance on the first decode steps of such requests; outputs are unchanged, since the target verifies every draft token.

Verification, DeepSeek-V4.1-Flash: one DEP2 prefill and one DEP2 decode on two GB300 nodes, 2 GPUs each; DSpark block 5, MegaAttention, MegaMoE, Mooncake, decoder bounded replay on both roles, HiCache on prefill, prefill CUDA graph off. GSM8K with sgl-eval, 1,319 examples, greedy, thinking off. The shared-prefix runs prepend the same eight worked training problems to every question so that prefill hits its prefix cache; pass 2 repeats pass 1.
