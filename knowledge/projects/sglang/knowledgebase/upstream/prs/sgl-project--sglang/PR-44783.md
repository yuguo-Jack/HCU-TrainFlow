# [Perf] DSv4.1: Skip discarded KV rows during window commit

[Upstream PR](https://github.com/sgl-project/sglang/pull/44783) · state: closed · merged: True

## Original PR description

[codex/claude generated]

## Motivation

Request-window commit copies every input KV row, routing discarded rows to a shared sink even though only the final window survives. Long prefills therefore move KV bytes that will never be read.

## Modifications

Add a Triton commit kernel that skips KV loads and stores for discarded rows, computes retained ring destinations, and writes position tags in the same launch. Keep history validation and the existing window retention policy unchanged. The launch grid still covers all input rows; this change removes discarded-row memory traffic rather than bounding the grid.

## Accuracy Tests

The tested patch passed 22 local tests on GB300: 4 packed-copy/commit GPU tests, 5 encoder replay CPU tests, and 13 compressed-pool CPU tests. Added byte-exact coverage for both KV layouts, ragged and 16K-token input, ring wrap, padded strides, untouched discarded destinations, layer isolation, and CUDA graph metadata refresh. These checks do not establish full-model semantic accuracy.

Transplanted onto main at 456231e25: all three changed files are byte-identical to the tested candidate, their baseline versions are unchanged, and syntax/diff checks pass. GPU results below were measured on base 30ca1dffc, not rerun on the new main revision. Pre-commit passed on the tested patch; CI on this PR is pending.

## Speed Tests and Profiling

On 4x GB300, TP4/EP4 with encoder bounded replay, the unchanged high-concurrency replay subset had median E2E latency of 3561.52 ms before this change and 3299.75 / 3315.78 ms in two candidate runs (6.9–7.4% lower). All 816 request/usage maps and cached-token totals matched. One baseline and two candidate runs were measured; DSPARK used simulated acceptance 5.4.

A 16K-token eager commit microbenchmark decreased from 142.24 us to 14.79 us. This includes destination calculation and tag updates and is not an end-to-end speedup. Later direct-packed and sparse-prefill experiments are excluded from this PR and these measurements.
