# [CI] [AMD] workflows: Report AMD Extra in PR states and the monitor; bound the stage-B wait

[Upstream PR](https://github.com/sgl-project/sglang/pull/47179) · state: open · merged: False

## Original PR description

## Motivation

AMD Extra (`pr-test-amd-extra.yml`, label `run-ci-amd-extra`) results are only visible in the checks list: the CI States block in the PR body has rows for Base, Extra (NV) and AMD base, and the AMD job monitor never reads label-triggered AMD Extra runs. Separately, the AMD stage-B gate asks a GitHub-hosted job to wait longer than such a job may run, and the large / multimodal-gen lanes run their shards one at a time.

## Modifications

- `pr-states.yml`: subscribe to `PR Test Extra (AMD)` and add a `Latest PR Test Extra (AMD)` row, gated on `run-ci` + `run-ci-amd-extra` the way the NV Extra row is gated on `run-ci-nv-extra`. New `.github/scripts/pr-states.test.cjs`, run in `lint.yml` next to the PR title test.
- `amd-ci-job-monitor.yml`: query `pr-test-amd-extra.yml` too, add a `PR Extra - <job>` report per Extra job, and count Extra jobs in the runner-fleet report.
- `pr-test-amd.yml`:
  - `wait-for-stage-b-amd`: `max-wait-minutes` 480 -> 350 (GitHub-hosted jobs stop at 6h) and `fail-on-timeout: 'false'`, so a slow stage-B releases stage-C; `pr-test-amd-finish` still needs and checks every stage-B job.
  - `max-parallel` 1 -> 2 on `stage-b-test-1-gpu-large-amd`, `stage-b-test-2-gpu-large-amd`, `multimodal-gen-test-1-gpu-amd`, `multimodal-gen-test-2-gpu-amd`. Shard counts are unchanged. On PR runs (one ROCm version) multimodal-gen 1-GPU (4 x ~31 min) and 2-GPU (2 x ~52 min) finish in about half the wall clock.

This PR used to also fix two never-run test registrations and add AMD suite-name validation to `run_suite.py`. The registrations moved to #48135; suite validation will be revisited after #47946.

## Verification

- `node --test .github/scripts/pr-states.test.cjs`: 5/5 pass (Node 20).
- All four changed workflow files parse as YAML.
- In 256 `pr-test-amd.yml` runs on 2026-10-29, `wait-for-stage-b-amd` took at most 102 min, so the 350 min bound does not cut normal runs.

- michaelzhang-ai · COMMENTED · 2026-11-04T04:32:46Z · [source](https://github.com/sgl-project/sglang/pull/47179#pullrequestreview-5763260611)

The new CI States row matches the NV Extra row's logic. `fail-on-timeout: 'false'` with a 350 min bound keeps the stage-B wait under the 6h limit, and `pr-test-amd-finish` still checks every stage-B job. Raising `max-parallel` to 2 has no effect on the one-shard 2-GPU large job, which is harmless.

One small thing: the AMD Extra job list in `amd-ci-job-monitor.yml` excludes only `call-gate` and `pr-test-amd-extra-finish`. #47946 adds an `amd-runner-map` job to `pr-test-amd-extra.yml` that runs on `ubuntu-latest`. The snapshot keeps only self-hosted jobs, so once both PRs are in, the monitor would show an empty `PR Extra - amd-runner-map` report. Could `amd-runner-map` be added to the exclude list here (`^(call-gate|amd-runner-map|pr-test-amd-extra-finish)$`)? Otherwise #47946 can add it when it rebases.
