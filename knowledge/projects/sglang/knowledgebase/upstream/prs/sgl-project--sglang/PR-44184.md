# [Fix] nemotron_vl: Preserve tokenized prompts during media expansion

[Upstream PR](https://github.com/sgl-project/sglang/pull/44184) · state: open · merged: False

## Original PR description

## Motivation

Nemotron VL image requests fail when callers supply a tokenized prompt through `generate(input_ids=...)`: the processor assumes a string and calls `.replace()` on the list.

## Modifications

- Accept tokenized prompts and expand media placeholders directly in token IDs, without re-tokenizing surrounding text.
- Use the original text IDs for image budgeting and validate image/video placeholder counts before loading.
- Preserve text unknown IDs when normalizing generated video markers.

The existing string-prompt path remains supported. This replaces the original decode/re-encode implementation with the token-preserving processor fix previously included in #44581; it does not change the vision encoder or weights.

## Why expand token IDs directly?

The immediate 500 occurs because `generate(input_ids=..., image_data=...)` passes a list to a processor that assumes a string and calls `.replace()`. Decoding that list to text would avoid the exception, but a decode/re-encode round trip can change the surrounding text IDs.

`_media_token_ids` identifies placeholders represented by a single token; `_splice_media` expands those placeholders directly in the ID list and leaves surrounding text IDs unchanged. These helpers are not required merely to avoid `.replace()` on a list; they make tokenized-prompt support preserve the caller's text IDs.

## Accuracy Tests

All **5 CPU tests** in the existing `test_nano_nemotron_vl_processor.py` pass, covering tokenized image expansion/budgeting, invalid image counts, text unknown-ID preservation, and the existing tubelet/EVS cases. Project isort/ruff checks pass.

GPU/serving validation has not been rerun for this split.

## Related PR

**Merge first in the stack:** #44581 adds offset-based image padding to prevent literal `<img>` / `</img>` text from being mistaken for image boundaries. That follow-up is a separate fix.
