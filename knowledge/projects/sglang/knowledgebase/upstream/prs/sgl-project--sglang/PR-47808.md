# [Feat] deepseek-recipe: [sglang-miles] Expose convert and encode_conversation on DeepSeekRecipe

[Upstream PR](https://github.com/sgl-project/sglang/pull/47808) · state: open · merged: False

## Original PR description

## Summary
Expose `DeepSeekRecipe.convert` and `encode_conversation` to encode a conversation prefix.

## Motivation
Cherry-pick of #47810 onto `sglang-miles`, which Miles runs: its three commits, unchanged (`git range-diff` against #47810: 3/3 identical, no conflicts).

Miles tokenizes a session turn by turn and is moving its DeepSeek-V4 / V4.1 rendering from a vendored copy of the removed `encoding_dsv4` / `encoding_dsv41` encoders to deepseek-recipe through `DeepSeekRecipe`, so its prompts match this server's chat endpoint. Each turn also renders the stored history on its own, and that history often ends with an assistant turn whose tool results have not arrived yet; recipe's request validation rejects it. `encode` converts and encodes in one call, so a caller cannot render that prefix.

## Usage
```python
recipe = DeepSeekRecipe.from_hf_tokenizer("dsv41", tokenizer)
conversation = recipe.convert(body_with_tool_results, effort_budget=30)
history = deepseek_recipe.Conversation(
    conversation.messages[:n],
    thinking_mode=conversation.thinking_mode,
    tools=conversation.tools,
    reasoning_effort=conversation.reasoning_effort,
)
ids = recipe.encode_conversation(history, effort_budget=30)  # prefix of encode(body), then the generation header
```

## Design Notes
- **Mental model:** a chat request goes through `pre_normalize` and recipe's request conversion (`convert`) to a recipe `Conversation`, then through recipe's prompt encoding plus the integer effort-budget rewrite (`encode_conversation`) to prompt ids.
- **The server path keeps its ids:** `encode` runs both steps, then attaches images and tasks; the chat endpoint still calls only `encode`.
- **Effort budget spans both steps:** `convert` renders the budget tier's effort line and `encode_conversation` rewrites it, so a caller passes the same `effort_budget` to both. The rewrite now keys on `conversation.thinking_mode`, which `convert` sets from `body["thinking"]`.

## Verification
- `test/registered/unit/parser/test_deepseek_recipe_renderer.py`: 9 passed locally with the V4.1 tokenizer, importing the SGLang leaf modules without torch.
- Its new case: with an effort budget, `encode_conversation(convert(body))` equals `encode(body)`, and a conversation cut after an assistant turn with pending tool calls encodes as a prefix of the full prompt.
- Miles' renders on top of this branch equal the chat endpoint's `encode_messages` ids for 62 V4 / V4.1 requests: thinking on or off, tools, tool results, parallel calls, developer or mid-conversation system turns.
- ruff, ruff-format, isort and codespell pass on the changed files.

## Review Focus
- `DeepSeekRecipe.encode`: the same ids as before for every input, including `image_urls` and `task`.
- `encode_conversation`: the budget rewrite keys on `conversation.thinking_mode` instead of `body["thinking"]`.
