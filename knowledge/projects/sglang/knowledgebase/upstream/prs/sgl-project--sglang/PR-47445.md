# [Fix] ipc: Make multimodal payloads, hidden states and weight-update dtypes round-trip under msgpack IPC

[Upstream PR](https://github.com/sgl-project/sglang/pull/47445) · state: closed · merged: True

## Original PR description

Fixes for messages that do not survive the opt-in msgpack IPC (`SGLANG_USE_PICKLE_IPC=0`). The default codec is unchanged.

- **Object-typed multimodal fields.** `MultimodalDataItem.feature`, `precomputed_embeddings`, `model_specific_data` values and `PositionalEmbeds.embeds` are typed `object`, and msgspec encodes tuples as lists and dataclasses as dicts without calling `enc_hook`. Values msgpack would not decode back unchanged (tuples, `torch.Size`, `torch.dtype`, dataclasses such as Kimi-K3's `KimiK3DeferredPreprocessing`, PIL images, numpy scalars, dicts with non-str keys, transport proxies) are now pickled into one ext (code 6) per request, through one pickler, so objects shared between values stay shared. Tensors, ndarrays, arrays and plain containers of them still go as before, with no pickling.
- **CUDA IPC / VMM transport proxies.** Their msgpack ext (code 5) read `sync_data_meta`, which the proxy no longer has, and dropped state and the concrete subclass on decode. It is removed; proxies take the pickled path above, which carries exactly what pickle carries and keeps one `_packed_owner` shared by the packed VMM proxies of a request.
- **`OutputHiddenStates`** allows a row to be one vector, which `return_hidden_states="last"` produces; msgpack decode rejected it.
- **`Engine.update_weights_from_distributed`** sends dtype names (`"bfloat16"`), so `torch.dtype` arguments encode under msgpack; both receivers already parse names with `getattr(torch, name)`.
- **Scripted runtime**: `ScriptedTokenizerRecvProxy.recv` returns msgpack bytes instead of raising.
- **Tests**: the data-parallel controller tests pin pickle IPC (they send `SimpleNamespace` requests), the rid-cleanup test asserts no call on the socket under either codec, and two `test_io_struct.py` tests cover the shared packed owner and the object-field round trip.

Behavior under pickle IPC is unchanged, except that `update_weights_from_distributed` passes dtype names instead of `torch.dtype` objects, which load the same weights.
