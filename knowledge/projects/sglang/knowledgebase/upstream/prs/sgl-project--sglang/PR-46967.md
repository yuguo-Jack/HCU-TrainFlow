# [Fix] scheduler: backport no_grad CUDA graph capture (#43854) to amd_march

[Upstream PR](https://github.com/sgl-project/sglang/pull/46967) · state: open · merged: False

## Original PR description

## Motivation

On `amd_march`, `Scheduler.init_all_cuda_graphs` runs without `torch.no_grad()`, so tensors made during CUDA graph capture carry autograd state. This bites the ROCm MoE path without aiter. There, `fused_experts` reduces with `moe_sum_reduce_torch_compile`, which is `torch.sum(..., out=...)` under `torch.compile`, and that op refuses out= when an argument requires grad. Decode CUDA graph capture of any MoE model then fails and the scheduler dies:

```
torch._dynamo.exc.TorchRuntimeError: RuntimeError when making fake tensor call
... got RuntimeError("sum(): functions with out=... arguments don't support automatic differentiation, but one of the arguments requires grad.")
  File ".../moe_runner/triton_utils/fused_moe.py", line 372, in moe_sum_reduce_torch_compile
  File ".../runner/decode_cuda_graph_runner.py", line 492, in __init__
```

`main` already fixed this in #43854 (`@torch.no_grad()` on `init_all_cuda_graphs`). This PR is a clean `git cherry-pick -x` of it, with authorship kept. Found while validating RDNA on `amd_march` (#46900).

## Modifications

Cherry-pick of b60444c621 (#43854): `python/sglang/srt/managers/scheduler.py`, +3 lines.

## Accuracy Tests

allenai/OLMoE-1B-7B-0125-Instruct on a Radeon AI PRO R9700 (gfx1201), TP1. Environment: no aiter; vLLM not importable, so RMSNorm uses `forward_native`. Applied on top of #46914, which is needed to import without aiter. Accuracy: `sgl-eval==0.1.2` gsm8k, 200 examples, temperature 0.7, top_p 0.8.

| config | result |
|---|---|
| `amd_march` + #46914, default (decode CUDA graph) | scheduler dies during graph capture (trace above) |
| `amd_march` + #46914, `--disable-cuda-graph` | serves; gsm8k 0.585 |
| `amd_march` + #46914 + this PR, default | decode graph captured in 4.8 s; gsm8k 0.605 |

On a Radeon PRO W7900D (gfx1100), vLLM 0.31 / torch 2.13, with #46914 + #46915 + this PR at default flags, the same model serves with the decode CUDA graph captured: gsm8k 0.545 on the same harness.

I only exercised MoE on RDNA. The change itself is the one `main` already carries for all platforms.
