# [Feat] platform: Let a graph runner that owns prefill be built on PD prefill servers

[Upstream PR](https://github.com/sgl-project/sglang/pull/46361) · state: open · merged: False

## Original PR description

## Motivation

On a PD prefill server, `apply_cuda_graph_disaggregation_roles` resolves the decode graph phase to `Backend.DISABLED`. `capture_decode_graph` then returns before it constructs `current_platform.get_graph_runner_cls()`. For CUDA graphs that is correct, since a prefill server never replays decode graphs.

Some out-of-tree platforms use the graph runner as *the* compiled-execution owner. Their runner builds and serves the compiled prefill buckets as well as decode. On a PD prefill server such a platform ends up with no compiled prefill, or has to monkeypatch `ModelRunner.init_cuda_graphs` to build the runner anyway.

## Modifications

- New `PlatformCapabilities.graph_runner_owns_prefill: bool = False`. It means the platform's graph runner also builds and serves the compiled prefill path, so it must exist on a PD prefill server.
- `apply_cuda_graph_disaggregation_roles`: for `disaggregation_mode == "prefill"`, the decode phase is no longer forced to `DISABLED` when the capability is set. An explicit `--cuda-graph-backend-decode` still wins, as before.

In-tree platforms are unaffected: the capability defaults to False.

Users can already work around this per launch with `--cuda-graph-backend-decode full` on the prefill server. The capability makes it the platform's default, so a bare PD launch is correct.

## How it was found

Found while building an out-of-tree Neuron/Trainium platform plugin. Its graph runner warms and serves the compiled (NEFF) prefill and decode buckets. On PD prefill servers no runner was built, so the plugin now wraps `ModelRunner.init_cuda_graphs` to construct it after the fact. This capability would replace that wrapper.

## Open questions

- Naming and placement: is a capability flag right, or should this be a platform method (e.g. `graph_runner_roles(disaggregation_mode)`)? Should it also stop the decode role from disabling the *prefill* phase, for symmetry? A runner that owns prefill should arguably not be told to skip it on decode servers either. I kept the change to the case I hit.
- `capture_decode_graph` also skips the target-verify graph on spec-decode PD prefill servers. That path is left unchanged.
