# [XPU] Fix int4 dense test to set TP size on the layer's tp_group

[Upstream PR](https://github.com/sgl-project/sglang/pull/43306) · state: closed · merged: False

## Original PR description

## Motivation

#42588 changed `GPTQXPULinearKernel.process_weights_after_loading` to read `tp_size` from `layer.tp_group.world_size` instead of `get_parallel().tp_size`. `test/registered/xpu/test_xpu_int4_dense.py` still fakes TP with `get_parallel().override(tp_size=...)`. Its bare `LinearBase` has no `tp_group`, so it falls back to the class default `None`, which means `tp_size=1`. As a result:

- `test_gptq_act_order_rejects_split_group_shard` fails: the `tp_size=2` subtest no longer gets the `--tp-size 1` hint. Example failure: https://github.com/sgl-project/sglang/actions/runs/37879819194/job/113656790497
- `test_gptq_group_aligned_shard_allows_tensor_parallel` still passes, but it now runs at TP=1 instead of TP=2.

#42588 didn't catch this because its XPU job was skipped (no `run-ci` label). The `main` push runs that would have tested it were cancelled by later pushes.

## Modifications

Set `layer.tp_group = SimpleNamespace(world_size=tp_size)` in both places and remove the unused `get_parallel` import. Test-only; no kernel change. The kernel's new lookup is correct for real layers, since every `tp_group` type exposes `world_size`.

## Notes

#34355 carries the same fix for the first spot only. This PR fixes both so it can land on its own and unblock other XPU PRs (e.g. #42048).
