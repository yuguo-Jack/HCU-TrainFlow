# [NPU] Fix TypeError in the DFlash graph replay: pass global_num_tokens_cpu

[Upstream PR](https://github.com/sgl-project/sglang/pull/41369) · state: closed · merged: False

## Original PR description

## Motivation

#36389 (merged 2026-09-25) added a required `global_num_tokens_cpu` parameter to `build_replay_fb_view` and updated the CUDA decode runner's call. `NPUGraphRunner.execute` builds the same view on its DFlash replay path (added in #37565 for MiMo-V2.5-Pro) and was not updated. Since #36389, replaying a captured graph with DFlash on Ascend fails before the graph runs:

```
TypeError: build_replay_fb_view() missing 1 required positional argument: 'global_num_tokens_cpu'
```

## Modifications

- `NPUGraphRunner` subclasses `DecodeCudaGraphRunner`, so pass what the CUDA runner passes: `self._global_num_tokens_for_graph(...)` of the padded token count. That is the same helper the capture path uses. #36389 added this field to the replay view for LoRA with DP attention, and nothing under `hardware_backend/npu` reads it, so the NPU replay is unchanged apart from the TypeError going away.
- No CPU or CUDA test reaches the Ascend replay, so I added `test/registered/unit/model_executor/runner/test_build_replay_fb_view_callers.py` (CPU suite), in the style of `test_plugin_hook_signatures.py`. It parses every `build_replay_fb_view(...)` call in `sglang.srt` and binds it to the function's signature. On `main` it fails at `npu_graph_runner.py:358` (`missing a required argument: 'global_num_tokens_cpu'`); with this PR both calls bind. If a parameter is added later and a caller is missed, the test will catch it on CPU.

```
python test/registered/unit/model_executor/runner/test_build_replay_fb_view_callers.py   # main: FAILED (errors=1), this PR: OK
pre-commit run --files <both files>                                                     # all hooks pass
```

I don't have Ascend hardware, so I could not run the DFlash replay end to end. The change only adds the missing argument.
