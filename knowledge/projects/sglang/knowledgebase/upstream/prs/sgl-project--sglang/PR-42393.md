# [Fix] grok: Fix per-layer quantization exclusions

[Upstream PR](https://github.com/sgl-project/sglang/pull/42393) · state: open · merged: False

## Original PR description

## Motivation

Related to #37848 (Grok call sites only).

Grok silently ignores qualified per-layer FP8 exclusions. For example, constructing a real two-layer Grok model with `ignored_layers=["model.layers.0.block_sparse_moe.experts"]` still selects `Fp8MoEMethod` for layer 0. Qualified attention and residual MLP exclusions also fail.

The decoder constructor receives no layer prefix, the MoE experts and residual MLP receive no module prefix, and the attention prefix uses `attn` instead of its checkpoint/module namespace `self_attn`.

## Modifications

- Propagate `model.layers.{i}` into each decoder.
- Pass the existing MoE prefix plus `experts` to `FusedMoE`.
- Use the `self_attn` namespace and pass `mlp` to the residual MLP.
- Add CI-registered CUDA regression tests using real `Grok1Model` and `Fp8Config`, without mocked constructors or quantization methods. Assert both the selected unquantized method and unchanged FP8 selection in the neighboring layer; also cover an empty exclusion list.

## Accuracy Tests

```bash
python -m pytest test/registered/unit/models/test_grok_quantization_prefix.py -q
```

Baseline official main `5b5d72123935dc2a3fb341790796ec1a987d31ce`: **3 failed, 1 passed**. After the fix: **4 passed** (15 dependency deprecation warnings), including the final explicit unquantized-method assertions.

Environment: WSL Ubuntu 24.04, Python 3.12, NVIDIA RTX 4060 Laptop GPU, PyTorch `2.13.0+cu130`, single-device runtime context. The tests construct a small two-layer model on CUDA; no checkpoint downloads are required.

These are quantization-selection regressions, not full-checkpoint inference or end-to-end accuracy results. Two additional existing tests could not collect locally because the shared GPU environment lacks `datasets`; no pass is claimed for them.
