# [Fix] Kimi-K3: Rebuild derived weights in place on weight updates

[Upstream PR](https://github.com/sgl-project/sglang/pull/47527) · state: open · merged: False

## Original PR description

## Why?

- After loading, Kimi-K3 derives tensors from its weights: MLA's absorbed `w_kc`/`w_vc`, the merged MoE-front and KDA `[f_a | b]` buffers, the fused KDA decode arguments, and the attention-residual norm×proj products (`get_cw`).
- CUDA graphs captured at startup hold these tensors. An RL weight update streams the model over many `load_weights` calls (about 769 buckets for full K3). Each call built new derived tensors, or kept the cached first-load values.
- So after an update, graph replays read the old weights. An engine started from dummy weights, as RL engines are, kept dummy products.
- `_bfa_f_b_w` and MLA's `w_scale` held a `Parameter`. Assigning a Parameter to a module attribute registers it, and the deduplicated `named_parameters()` then lists it only under the new name. So every weight update silently skipped each KDA layer's `f_b_proj.weight`, and `kv_b_proj.weight_scale`.

## What?

- Rebuild every derived tensor in place with `bind_or_assign`, so captured graphs see the new values.
- Keep the merged buffers as they are. Module weights are views into them, so the weight loaders write through.
- `_bfa_f_b_w` and `w_scale` hold `.data`, a plain tensor.
- `post_load_weights(weight_names)` rebuilds only the layers a call loaded, like deepseek_v2. `None` still means every layer. The output attention-residual products refresh when their own names load.
- The KDA prefill kernel precompiles only once.
- This covers what `sglang-miles` #41925 fixes: `_bfa_f_b_w` via `.data`, stable `_front_w` / `_bfa_w` / ROCm in-proj buffers, and in-place block-FP8 `_bfa_w`. `sglang-miles` can drop #41925 when it rebases onto `main`. One difference: #41925 copies a moved module weight back into the merged buffer, while this PR keeps the views and returns early. cc @XinyuJiangCMU

## Verification?

```text
Kimi-K3 engine started from dummy weights, CUDA graphs on, then an RL weight update

Before: post-load builds new w_kc / w_vc / cw / fused-decode tensors
        → captured graphs keep reading the dummy ones → rollout logprobs ≠ trainer
        f_b_proj.weight hidden under _bfa_f_b_w → the update skips it
After:  derived tensors rewritten in place → graphs read the updated weights
        f_b_proj.weight listed and updated                                   (expected)
```

## Test?

- New `test/registered/e2e/rl/test_kimi_k3_weight_update.py::test_bucketed_update_refreshes_derived_tensors_in_place`. It builds a tiny real K3, starts from dummy weights, and streams a checkpoint over several `load_weights` calls. It checks that every derived tensor gets the new values in the same tensors and that no tensor is dropped. Registered on `1-gpu-large`. **Pending CI** (not run locally: no GPU here).
