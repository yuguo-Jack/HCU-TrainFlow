# make infllm maxpool lookup fast

[Upstream PR](https://github.com/sgl-project/sglang/pull/30385) · state: closed · merged: False

## Original PR description

## Summary

Replace the per-query linear batch scan in InfLLM-V2  max pooling with a binary search over `cu_seqlens_q`.

The old kernel walked batches from the front for every `(query, head)` block.The new path keeps the same behavior while reducing that lookup from O(batch_size) to O(log(batch_size)).

also added `__restrict__` on vars where applicable

![security-high](https://www.gstatic.com/codereviewagent/security-high-priority.svg) ![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

To prevent potential out-of-bounds memory access in the binary search and subsequent array lookups, we should add an early exit guard. If `bidq_global` is greater than or equal to the total number of queries (`cu_seqlens_q[batch_size]`), the thread block should return early. This is especially important if the grid size `grid_q` is launched with a value larger than the actual sequence length, or if `batch_size` is 0.

```
  const int total_q_all_bound = cu_seqlens_q[batch_size];
  if (bidq_global >= total_q_all_bound) return;

  int lo = 0;
  int hi = batch_size;
  while (lo < hi) {
    const int mid = (lo + hi) >> 1;
    if (bidq_global >= cu_seqlens_q[mid + 1]) {
      lo = mid + 1;
    } else {
      hi = mid;
    }
  }
  const int batch_idx = lo;

  const int q_start = cu_seqlens_q[batch_idx];
  const int bidq_local = bidq_global - q_start;
  const int seqlen_q = cu_seqlens_q[batch_idx + 1] - q_start;
  const int seqlen_k = cu_seqlens_k[batch_idx + 1] - cu_seqlens_k[batch_idx];
  if (bidq_local >= seqlen_q) return;
```

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Guard padded query rows before indexing batch+1**

When `grid_q` includes padded query rows (for example, the wrapper receives `input.shape[1] > cu_seqlens_q[-1]`, or a direct op caller passes a larger `total_q`), the new binary search returns `batch_idx == batch_size`. This line then reads `cu_seqlens_q[batch_size + 1]` and `cu_seqlens_k[batch_size + 1]`; the old linear scan reached the `bidq_local >= seqlen_q` return without indexing past the metadata, leaving those inactive rows zero-filled. This can turn previously tolerated padded inputs into an OOB device read or crash.
