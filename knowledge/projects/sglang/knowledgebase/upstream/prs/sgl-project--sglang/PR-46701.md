# [Fix] FlashInfer: Tune one prefill shape during MoE startup

[Upstream PR](https://github.com/sgl-project/sglang/pull/46701) · state: closed · merged: False

## Original PR description

## Motivation

@humansand

Prepare FlashInfer TRTLLM and CuTe DSL MoE decode profiles **plus exactly one prefill shape at startup**, following our [MegaMoE autotune design in #43789](https://github.com/sgl-project/sglang/pull/43789). Decode-shaped warmup currently misses larger prefill inputs.

## Modifications

- **Profile set:** preserve native decode buckets through the graph/eager decode ceiling D, then add the exact prefill capacity P. Resolve P from the chunk buffer or scheduler limit and apply the actual DP gather width to both limits. No intermediate prefill sweep or rounding P up.
- **Lifecycle:** FlashInfer profiles the selected shapes during startup without enlarging the model dummy. The runner/layer retains the round-up mapping for serving; existing cache reuse and tactic synchronization remain in place.

**Example: D=32, P=5000**, with autotuning enabled. Startup prepares `[1, 2, 4, 8, 16, 32, 5000]`. For the same kernel configuration, a **4000-token batch hits the 5000 profile and reuses its tuned tactic**. M is the MoE input token count after applicable DP gathering.

| MoE input tokens M | Serving selection |
| --- | --- |
| 1–32 | Native decode profile, including for a small prefill batch |
| 33–5000 | The single 5000-token profile; all inputs in this range reuse that tactic |
| Above 5000 | Native lookup or heuristic fallback |

**None of these serving paths enables autotuning.**

- **Controls:** honor `--disable-flashinfer-autotune`, deterministic inference, and `--flashinfer-autotune-skip-ops`. Preserve `SGLANG_FLASHINFER_AUTOTUNE_CACHE` and `SGLANG_CACHE_DIR`; disabling cache reuse still permits startup tuning. `SGLANG_FLASHINFER_AUTOTUNE_EXTEND` controls only the extra full-model forward, so its default false value does not suppress this kernel-level prefill profile. A padded EXTEND dummy keeps the same profile set. Skipped ops retain heuristic fallback during startup and serving.
- **Scope:** regular TRTLLM/CuTe wrappers, standalone MXFP4/MXINT4, and Muse BF16. Draft and PD-decode workers retain their existing policy. MegaMoE, CUTLASS, and experimental LoRA policies are unchanged. Prefill-only precision/dispatch/finalization variants still need their applicable model hook or opt-in EXTEND pass.

## Accuracy Tests

- **Tested commit:** `287a1538bb1d6dd7fbac6841abead45e5a0616e6`, on C3 B300 with FlashInfer 0.7.2.
- **Existing suite:** `12 passed, 20 warnings, 8 subtests passed in 93.12s`. Scoped pre-commit, `git diff --check`, and eight CPU contract probes also passed. Only existing test fixtures/assertions were updated.
- **Native kernels:** both backends produced the exact seven-profile set. Serving and cache reload added no profiles; M=5001 used native fallback. The table reports the measured runtime inputs and output differences from the same-input heuristic.
- **Control checks:** disable/deterministic gates and skipped ops produced zero profiles; skipped serving performed no tactic-cache lookup. Padded startup M=5001 retained seven profiles and matched the heuristic. Existing tests cover cache reuse and the opt-in EXTEND gate.

Closing this after tracing the existing behavior. `SGLANG_FLASHINFER_AUTOTUNE_EXTEND=1` already provides opt-in prefill tuning for supported TRTLLM and CuTe DSL configurations. [MegaMoE (#43789)](https://github.com/sgl-project/sglang/pull/43789) retains per-capacity workspaces; the audited TRTLLM/CuTe paths do not retain a separate full GPU workspace per autotune profile, so that memory rationale does not carry over.

This PR adds kernel-level prefill tuning without the extra full-model EXTEND pass and replaces that sweep's intermediate prefill profiles with one prefill profile per kernel configuration. That trades shape-specific tactics for fewer profiling shapes than the EXTEND sweep, but we have not established a net performance or memory benefit to justify changing the existing policy.
