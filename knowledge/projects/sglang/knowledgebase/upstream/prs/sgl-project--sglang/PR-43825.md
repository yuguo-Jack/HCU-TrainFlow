# [Fix] [NPU] Correct MurmurHash values used by seeded sampling

[Upstream PR](https://github.com/sgl-project/sglang/pull/43825) · state: open · merged: False

## Original PR description

## Motivation

This PR restores the intended integer computation used by seeded sampling on NPU. The sampler hashes the request seed, generation position, and candidate column to produce the pseudorandom values used to select the next token. On the evaluated NPU Triton path, these hashes differ from the algorithm's unsigned 32-bit reference, changing the sampling inputs for the same seed and position.

The error occurs in `rotl32`, the shared MurmurHash rotation helper. It widens the input to `uint64` before combining left and right shifts. In the observed NPU execution, the widened value contains extra high bits; the right shift moves them into the low 32 bits. The existing output mask cannot remove those bits once they have entered the result.

## Modifications

In `python/sglang/kernels/ops/sampling/murmur_hash.py`, mask the widened input before either shift so that only the intended 32 bits participate in the rotation:

```diff
- x = x.to(tl.uint64)
+ x = x.to(tl.uint64) & 0xFFFFFFFF
  return ((x << r) | (x >> (32 - r))) & 0xFFFFFFFF
```

This restores the existing MurmurHash computation at the point where the incorrect values originate. The helper is shared by the Triton device path, so the change also applies to GPU callers.

Add an NPU regression test comparing 16 candidate-column hashes against fixed values from an independent unsigned 32-bit reference. The inputs exercise the high-bit case that exposes the rotation error.

## Validation

Existing NPU validation compared eight seed/position pairs across 16 columns, including seeds with nonzero upper 32 bits:

| Implementation | Hash mismatches against the independent reference |
| --- | ---: |
| Original | 72/128 |
| With the input mask | 0/128 |

The [saved comparison](https://github.com/celestial-micha/sglang/blob/ebcec6e4a5416066688e6a5eb71af7476cf21ed7/test/manual/murmur_uint32/murmur_vector_results.json) records the inputs, reference values, and both device outputs.

Replay of 27 captured speech-generation sampling steps also produced reference-matching hashes after the fix. With candidate ordering and filtered weights held equal, the selected speech tokens matched the reference in **27/27 steps**. This verifies that the corrected hashes feed the existing sampling calculation as intended.

These measurements used the `release/v0.5.20` candidate; the product file and submitted 16-column test remain unchanged from that candidate. The test requires an NPU and skips when one is unavailable.

GPU comparison against the same integer reference and representative model quality regression remain pending. Correcting the hashes can change generated token sequences; the recorded checks establish arithmetic correctness, while end-to-end speech/text consistency remains tracked in [sglang-omni#2738](https://github.com/sgl-project/sglang-omni/issues/2738).

The PR is now based on main. The measured hash implementation and submitted regression test are unchanged; upstream device validation on the rebased commit remains pending. The NPU workflow requires a maintainer to add the `run-ci` label.
