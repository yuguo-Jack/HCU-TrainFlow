# [Fix] rust-server: Reject whitespace inside a stop_regex repeat count

[Upstream PR](https://github.com/sgl-project/sglang/pull/46346) · state: open · merged: False

## Original PR description

## Motivation

The Rust server checks every `stop_regex` with `regex-syntax` before it reaches the scheduler, and sends the scheduler a length bound for the match window (`stop_regex_max_len`). An admitted pattern's bound must be at least CPython's max match width, or the window cannot hold a match.

`regex-syntax` accepts whitespace inside a counted repeat. It reads `a{2 }`, `a{ 2}` and `\d{1, 3}` as repeats. CPython reads them as literal text. So `\d{1, 3}` gets a bound of 3 while CPython needs 7 characters, the stop never fires, and the request runs to `max_new_tokens`. The Python server stops on the same request. A space after the comma is an easy typo to make in a hand-written stop pattern.

### Reproduction

The new corpus rows fail on current main:

```
ADMITTED but must be rejected: "a{2 }" (bound 2, worst re.search 0.01 ms)
ADMITTED but must be rejected: "a{ 2}" (bound 2, worst re.search 0.01 ms)
ADMITTED but must be rejected: "\\d{1, 3}" (bound 3, worst re.search 0.01 ms)
```

Effect on the scheduler. This drives the real `Req._check_str_based_finish` with a tokenizer that emits one character per token, fed one token at a time as decode does.

```
pattern='\\d{1, 3}' text='The answer is 5{1, 3} and then more text follows here.'
  python bound 7: fires=True  (FINISHED_MATCHED_REGEX)
  rust   bound 3: fires=False
```

## Modifications

- `spaced_repetition_operator` rejects a repetition operator whose source text holds whitespace. The request gets a 400. The check only rejects, so the bound of every pattern still admitted is unchanged. Spacing outside a repeat, such as `a {2}` and `[ ]{2}`, stays admitted.
- A new unit test runs CPython's `re` on every pattern the tests expect Rust to admit. It checks that each one compiles and that the Rust bound is at least CPython's `sre_parse` max width. It is skipped when no `python3` can be started (`PYTHON` overrides the interpreter).

## Tests

- 3 `MustReject` corpus rows, with `py_max_len` from SGLang's `get_max_seq_length` and `worst_ms` from timed `re.search` runs.
- `whitespace_outside_a_repeat_operator_is_still_admitted` guards against over-rejection.
- `admitted_patterns_compile_in_cpython_within_their_bound` passes. With the new check disabled it fails with `"\\d{1, 3}" rust bound 3 < CPython max width 7`.
- `cargo test -p sglang-server --lib utils::regex`: 14 passed.
- `cargo fmt -p sglang-server --check` and `cargo clippy -p sglang-server --all-targets -- -D warnings` are clean.
