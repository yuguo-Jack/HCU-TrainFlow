# [Fix] [AMD] diffusion: Default to torch_sdpa and keep NCDHW VAE convs on Radeon (RDNA)

[Upstream PR](https://github.com/sgl-project/sglang/pull/45937) · state: open · merged: False

## Original PR description

## Motivation

On AMD Radeon (RDNA) GPUs, two ROCm defaults in the diffusion runtime break or stall generation. Measured on a Radeon PRO W7900 (gfx1100, ROCm 7.2, torch 2.10).

1. **Default attention backend.** With no `--attention-backend`, `_set_default_attention_backend` always picks `aiter` on ROCm. AITER's CK attention kernels are only generated for CDNA (gfx9/gfx950) and gfx1250, so on gfx1100 every request fails at the first denoising step:
   ```
   [DenoisingStage] Error during execution after 240.6214 ms: invalid argument for fmha_fwd
   ```
   (FLUX.1-schnell and Wan2.1-T2V-1.3B with default flags.)

2. **channels_last_3d VAE weights.** `_should_use_channels_last_3d` converts the Wan / Qwen-Image / LTX-2 / Cosmos3 VAE Conv3d weights to `channels_last_3d` on ROCm. MIOpen has no fast NDHWC Conv3d kernels on RDNA. A single Wan decoder conv (192 channels, 3x240x416, bf16) takes 51.3 s in NDHWC vs 12.1 ms in NCDHW on the W7900 (warm, plain `torch.nn.Conv3d`). In practice, the Wan VAE decode of a 9-frame 832x480 clip had not finished after 30 minutes.

Related: #30599 (Radeon RDNA support tracking, mostly the LLM side).

## Modifications

- `ServerArgs._set_default_attention_backend`: on ROCm, keep `aiter` for gfx9* and gfx125*, and use `torch_sdpa` for other archs (Radeon RDNA2/3/3.5/4). An explicit `--attention-backend` is unchanged.
- `vae_loader._should_use_channels_last_3d`: on ROCm, only use `channels_last_3d` on gfx9*. `SGLANG_DIFFUSION_VAE_CHANNELS_LAST_3D` still overrides in both directions.
- Docs:
  - `attention_backends.mdx` (ROCm notes): the per-arch default.
  - `installation.mdx` (AMD section): the RDNA defaults, and that Wan-family VAE decoding on RDNA is much faster with the existing `SGLANG_USE_ROCM_VAE_CONV2D_BF16=1`.
- Tests:
  - New `test_rocm_default_attention_backend.py`: default per arch.
  - `test_vae_loader.py`: ROCm `channels_last_3d` default for gfx942 (on) and gfx1100 (off).

Instinct (CDNA) behavior is unchanged.

## Accuracy Tests

No numerics change on any arch that already worked. On RDNA, outputs now come from `torch_sdpa`, the backend users already had to pass by hand.

**Radeon PRO W7900 (gfx1100).** `sglang generate`, no `--attention-backend` unless noted.

| Run | `main` | this PR |
|---|---|---|
| FLUX.1-schnell 512x512, 4 steps | fails: `invalid argument for fmha_fwd` | `torch_sdpa`, image in 3.51 s (cold) |
| Wan2.1-T2V-1.3B 832x480, 9 frames, 4 steps | fails: `invalid argument for fmha_fwd` | `torch_sdpa`, video in 153 s (cold); VAE decode stays NCDHW |
| Same Wan run, `--attention-backend torch_sdpa` | denoise 1.02 s/step; VAE decode with `channels_last_3d` **not finished after 30 min** (killed) | — |
| Same Wan run + `SGLANG_USE_ROCM_VAE_CONV2D_BF16=1` | — | video in 10.5 s, VAE decode 3.4 s |

Times are single cold requests, including MIOpen kernel compilation; I'm citing them for the order of magnitude only. `compare_perf.py` isn't applicable here because the `main` runs don't complete.

**Instinct MI300X (gfx942).** Functional check of this branch in `lmsysorg/sglang:v0.5.19-rocm10-mi30x`, no timing claims:
- FLUX.1-schnell, default flags: logs `Using 'aiter' by default on ROCm`; image generated.
- Wan2.1-T2V-1.3B, default flags: `aiter` selected and `VAE: converted 35 Conv3d weights to channels_last_3d` as before; video generated.

Unit tests: `test_rocm_default_attention_backend.py` and `test_vae_loader.py` pass on both GPUs (38 passed).

- vivienfanghuagood · comment · 2026-10-29T17:18:10Z · [source](https://github.com/sgl-project/sglang/pull/45937#issuecomment-6503514533)

I tested this on RDNA4 (gfx1201) with `Wan-AI/Wan2.1-T2V-1.3B-Diffusers` (17 frames, 832x480, 10 steps, `sglang generate`, default flags), in the `rocm/pytorch` ROCm 7.2.3 image without aiter. Base: main plus #43679 (sgl-kernel build on gfx1201), #47254 and a local optional-aiter import guard.

- `test_rocm_default_attention_backend.py` passes: 1 passed, 6 subtests.
- On current main, the diffusion runtime never reaches this code in that image. Without amdsmi's Python bindings, `multimodal_gen` resolves the platform to CPU. I opened #47296 for that.
- With that detection fix alone, ROCm is detected and the default attention backend becomes AITer, which fails without aiter: `AttributeError: module '...attention.backends' has no attribute 'aiter'`.
- With the detection fix plus this PR, it picks `torch_sdpa` ("Attention backend not specified. Using 'torch_sdpa' by default on ROCm") and generates the video. Denoise takes 1.22 s/step (15.5 s for 10 steps).

So on RDNA without aiter, this PR is what makes diffusion run at all, once platform detection works.

One more observation, not caused by this PR: the first VAE decode of a cold MIOpen cache takes 444 s with the default Conv3d path on this card. Most of that is MIOpen's cold-cache find. Numbers are in #46289.
