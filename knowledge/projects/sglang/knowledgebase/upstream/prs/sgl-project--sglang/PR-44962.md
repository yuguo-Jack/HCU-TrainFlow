# [Fix] srt: cap finished_len at max_new_tokens on request abort with speculative decoding

[Upstream PR](https://github.com/sgl-project/sglang/pull/44962) · state: open · merged: False

## Original PR description

## Motivation

in speculative decoding, multiple draft tokens get committed to output_ids before finish checks run. when a request gets aborted mid-run via to_finish, update_finish_state sets finished_reason and returns early without setting finished_len or checking length boundaries. because finished_len stayed none, output_ids_through_stop returned the raw output_ids including the overshot speculative tokens, so completion_tokens exceeded max_new_tokens on aborted requests (issue #44839).

## Modifications

clamps finished_len to max_new_tokens inside the to_finish handler when output_ids meets or exceeds the cap, and ensures output_ids_through_stop and the output streamer never emit past max_new_tokens. added unit tests covering speculative aborts both over and under the token cap in test_finish_length_speculative.py.
