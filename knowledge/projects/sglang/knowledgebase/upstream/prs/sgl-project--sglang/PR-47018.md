# [Perf] Cache the serialized tool-call constraint across requests

[Upstream PR](https://github.com/sgl-project/sglang/pull/47018) · state: open · merged: False

## Original PR description

## Motivation

For constrained tool requests (strict tools, `SGLANG_TOOL_STRICT_LEVEL`, required or named `tool_choice`), the frontend builds the structural tag fresh on every request: tool `model_dump` 4.8 ms + xgrammar tag build 1.5 ms + exclusion strip 2.7 ms + tag dump 2.7 ms + `json.dumps` 3.6 ms ≈ **16.3 ms** for 177 tools — and the result is byte-identical on every agent turn. The scheduler's grammar cache only engages *after* that string exists, so it saves nothing here.

## Fix

Per-serving-instance LRU of the **final serialized constraint string**, in new `entrypoints/openai/tool_call_constraint_cache.py`:

- **Key**: `marshal`-encoded tuple of every input the build reads — tool parser name, all `Tool`/`Function` fields (including post-normalization `parameters` content), strict level, `tool_choice`, `parallel_tool_calls`, thinking mode, and the exclusion tokens stripped for the reasoning parser. `marshal` is exact-typed: NaN/±inf stay distinct from `null` (orjson would collide them), `1`/`True`/`1.0` and tuple/list are distinct, and non-builtin types raise → the request goes uncached. A unit test enumerates `Tool.model_fields`/`Function.model_fields` so adding a field without keying it turns the test red.
- **Value**: the post-strip `(kind, str)` exactly as `to_sampling_params` would serialize it — immutable strings, nothing request-mutable shared. `ChatCompletionRequest.to_sampling_params` now passes a pre-serialized `str` structural tag through.
- **Bounds**: 256 entries + 64 MiB (a 177-tool strict entry ≈ 1 MiB); oversized entries are returned but not stored. Lock around get/put (conversion runs in an executor pool); builds happen outside the lock.
- **Not cached (unchanged)**: unconstrained `auto` (never pays for a key), response-template parsers, GLM `full_assistant_ebnf`, `None` results.

Also included: `strip_structural_tag_excludes` reads pydantic fields from `__dict__` instead of `hasattr`/`getattr` probes (each absent-attr probe raises+catches) — **2.74 → 0.16 ms**, byte-identical output. The orjson serialization swap was evaluated and rejected (changes bytes and NaN semantics for a miss-only gain).

## Numbers (177 tools, medians)

| Case | before | after (hit) |
|---|---:|---:|
| constraint stage (strict auto + reasoning parser) | 16.26 ms | **0.98 ms** |
| `_process_messages + to_sampling_params`, strict auto + strip | 21.64 ms | **6.97 ms** |
| strict named | 6.47 ms | **1.24 ms** |
| non-strict auto (uncached common case) | 5.07 ms | 5.20 ms (noise) |

A miss without a reasoning parser costs ~1 ms more than today (key + store); with a reasoning parser the faster walker makes a miss cheaper than today.

## Tests / evidence

- **6,480-case cross-tree matrix** (54 tool parsers × reasoning on/off × strict level 0/1/2 × tool strictness × tool_choice × parallel flag): **0 byte differences** vs upstream main, **0 hit/miss mismatches** (each case run twice).
- thinking_mode and in-place parameter mutation: 324 cached-vs-fresh comparisons, 0 mismatches; thinking on/off changes output in 48 configs (key field load-bearing).
- New unit tests: cache bounds/LRU/oversized-entry; full rebuild-on-any-input-change (each Tool/Function field, tool_choice, parallel flag, strict level, reasoning detector) — fails on unpatched main.
- Suites (`entrypoints/openai`, `entrypoints/anthropic`, `function_call`, `parser`): failure sets identical to clean main (all local-env gaps); one existing assertion updated because `json_schema` constraints are now serialized (no production code indexes the value).
- `pre-commit run --files`: clean.

Pre-existing side findings (not fixed here): legacy-tag `triggers` list built from a `set` is cross-process nondeterministic for multi-trigger detectors; builtin vs legacy tags treat omitted `strict` differently.
