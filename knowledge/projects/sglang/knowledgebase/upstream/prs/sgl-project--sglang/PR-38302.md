## Motivation

This PR adds the first, deliberately scoped SGLang integration point for SparDA: a reusable cross-layer Forecast selector runtime, with MiniCPM4.1 as the first model adapter.

The feature is opt-in and disabled by default. It does not include host KV-cache offload or asynchronous prefetch, so this PR does not claim to be the complete SparDA runtime or to provide an inference-speedup result.

## Modifications

- Add a `ForecastState` owned by each `ForwardBatch` for per-request/per-layer forecast handoff, including first-layer current-query fallback, reset, and batch isolation.
- Add `--enable-sparda` and `--sparda-indexer-path`, with startup validation for model type, pipeline parallelism, path existence, checkpoint keys, and tensor shapes.
- Add the MiniCPM4.1 (`model_type=minicpm`) adapter with the official `q_future_proj` layout, RoPE handling, GQA/KV-head slicing, and TP-compatible loading.
- Map the official indexer checkpoint layout, including nested state-dict formats and `module.` prefixes. The official `q_curr_proj` entry is accepted as an extra checkpoint key; PR1 intentionally uses the current-query fallback for the first layer.
- Thread the optional forecast selector through `RadixAttention` and the MiniCPM sparse-attention backend. The existing current-query selector, DSA, MiniCPM-SALA, and default attention paths remain unchanged when the flag is disabled.
- Keep the forecast selector on the reference compressed-attention selection path; no host KV residency, copy stream, event synchronization, eviction, or prefetch logic is included.
- Add documentation and registered unit tests. No model checkpoint or training data is committed.

## Speed Tests and Profiling

The following are warm-run measurements with deterministic inputs and 16 generated tokens per request. The 32K and 64K cases use 32768 and 65504 input tokens respectively, so the latter stays within the 65536-token context limit. `TTFT / decode tok/s` is reported in seconds and aggregate generated tokens per second.

| Context | Batch | Default path TTFT / decode tok/s | `--enable-sparda` TTFT / decode tok/s | Output tokens |
| --- | ---: | ---: | ---: | ---: |
| 32K | 1 | 4.08 / 33.21 | 5.62 / 15.89 | 16 |
| 64K | 1 | 11.12 / 34.72 | 11.68 / 15.12 | 16 |
| 32K | 4 | 19.96 / 138.04 | 23.00 / 63.49 | 64 |
| 64K | 4 | 45.04 / 138.87 | 47.82 / 60.89 | 64 |

The default column is the normal non-SparDA dense path. The enabled column uses MiniCPM sparse defaults and a synthetic Forecast checkpoint. These are selection-only measurements: there is no host KV prefetch/offload, so no end-to-end SparDA speedup is claimed. GPU-memory and isolated selector-overhead measurements are omitted because the validation environment is shared; they will be measured with the independent KV-prefetch PR.
