# [Fix] metrics: Handle CPU monitor clock resets after restore

[Upstream PR](https://github.com/sgl-project/sglang/pull/44494) · state: open · merged: False

## Original PR description


## Motivation

CRIU restore can reset process CPU time below the monitor’s saved baseline. The resulting negative delta causes the Prometheus counter to raise ValueError, terminating the monitoring thread and leaving CPU metrics stale.

## Modifications

Count the current CPU reading as time since restore when the delta is negative, then update the baseline for subsequent samples.

Add a regression using a real Prometheus counter covering repeated resets and normal increments after each reset.

## Accuracy Tests

Model outputs are unaffected.

Both mocked CPU-monitor tests pass directly without GPU dependencies or stubs. The new regression reproduces the negative-counter failure against the original implementation.

Full-file execution encounters existing interference from the smoke test’s background thread. Real CRIU restore validation remains outstanding.
