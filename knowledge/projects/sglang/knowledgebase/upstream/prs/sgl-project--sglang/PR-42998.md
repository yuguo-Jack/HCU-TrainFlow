# [sgl-router] Serve /v1/chat/completions through /generate, with reasoning parsing

[Upstream PR](https://github.com/sgl-project/sglang/pull/42998) · state: closed · merged: True

## Original PR description

Adds **`/v1/chat/completions`** to the router's `/generate` path, on #42997's shared OpenAI layer. Unlike completions, chat needs the prompt **rendered** and the output **parsed** for reasoning. Stacked on #42997.

## What this PR adds

**Chat lowering (`openai/chat.rs`)**
- Lowers the request to the `GenerateReqInput` `serving_chat.py` builds, around the prompt ids the router renders from `messages` (`render/`).
- Covers `generation_config.json` sampling defaults, `max_completion_tokens`, `reasoning_effort`/`reasoning`/`thinking` with `require_reasoning`, and `continue_final_message`.

**Chat response**
- Builds the response and SSE chunks as `_build_chat_response` and `_generate_chat_stream` do.
- Reasoning is split into `reasoning_content` and `content`, honoring `separate_reasoning` and `stream_reasoning`.

**Reasoning parsing in `sglang-processor/parser`**
- New `parser/models/` lists the parser names SGLang ports from Python, because Dynamo's parsers split them differently; every other name stays on Dynamo. It mirrors `render/models/`, so porting Kimi or GLM later means one `models/<model>.rs` plus its names.
- `deepseek-v4` is a configuration of `parser/think.rs`, a port of SGLang's `BaseReasoningFormatDetector`. Dynamo's `deepseek_v4` parser split about half the recorded edge cases differently, for example stripping `</think>` from content when thinking is off.
- `ReasoningStreamSplitter` and `split_reasoning` take `ReasoningOptions`.

**Gate:** chat goes through `/generate` only when:
- the model's renderer is verified against SGLang (`AllText` scope; DeepSeek-V4 here);
- router `--default-chat-template-kwargs` equal the workers';
- the request has no tools or media.

Everything else keeps going to the engine's own route.

**Shared with completions:** request types and helpers move to `openai/request.rs`; usage, stream state and the unary reply move to `openai/wire.rs`. This is why #42997's `completions.rs` shrinks here.

## Behavior change outside the router

sglang-server and sglang-renderer use the same parser, so DeepSeek-V4 reasoning there now splits as Python does. The server's unary path also starts in reasoning when the prompt prefilled `<think>`.

## Left to later PRs

- Tool calls: #42999.
- DeepSeek-V4.1: #43000.

## Checks

- DeepSeek-V4-Flash-0731 chat fixtures (thinking, effort, continuation, logprobs, `n`, streaming options) match Python exactly.
- `tests/reasoning_parity.rs` checks the split against SGLang's `ReasoningParser`.
- **Live check:** on DeepSeek-V4-Flash-0731, the engine logs an identical `GenerateReqInput` for every chat case, including the router-rendered `input_ids`.
- Router, processor, server and renderer suites pass, and clippy and fmt are clean.
