# [NPU] Enable MXFP8 low-latency DeepEP dispatch for Fp8MoEMethod FP4 experts

[Upstream PR](https://github.com/sgl-project/sglang/pull/40519) · state: open · merged: False

## Original PR description

## Motivation

On NPU, FP4-expert models routed through Fp8MoEMethod ( is_fp4_expert=True , e.g. MiMo-V2.5-Pro with modelopt_fp4) delegate execution to NPUW4A8MXFP4MoEMethod kernels via the ASCEND MoE runner. However, process_weights_after_loading only runs Fp8MoEMethod 's own body, so the DeepEP dispatcher quant config was never set — dispatch fell back to BF16 and a separate DynamicMxQuant kernel ran before every grouped matmul (~15ms/layer at 16K-token prefill).

The native FP4 path ( NPUW4A8MXFP4FusedMoEMethod , DSV4) already sets the same dispatcher config; the Fp8MoEMethod path was simply missing it.

## Modifications

- Declare the dispatch wire format as a DISPATCHER_QUANT_CONFIG class attribute on NPUW4A8MXFP4MoEMethod ( low_latency=mxfp8 ; normal stays BF16 since A5 MXFP8 normal dispatch is intranode-only). The kernel that consumes the activations now owns the declaration, instead of each caller hand-writing platform-specific if/else patches.
- In Fp8MoEMethod.process_weights_after_loading , pick the config up from the attached layer.w13_kernel when it declares one; otherwise keep the original checkpoint-dtype config. No _is_npu / is_fp4_expert branching — the attached kernel already encodes both.
- Reuse the same declaration in NPUW4A8MXFP4FusedMoEMethod , replacing its hand-written copy.
With this, A5 low-latency dispatch quantizes activations to MXFP8 in-kernel (with E8M0 block scales) and the GMMs consume them directly; the three previously duplicated config dicts collapse into a single kernel-owned declaration.

## Speed Tests and Profiling

MiMo-V2.5-Pro-FP4 (DFlash), single-node A5, DeepEP low-latency, prefill with 16K-token random inputs.

Per-layer kernel profile (avg ms, before → after):

| Kernel | Before | After |
|---|---|---|
| DynamicMxQuant (post-dispatch) | 15.14 | **eliminated** |
| MoeLowLatencyDispatchV2 | 33.16 | 30.63 |
| GroupedMatmulSwigluQuantV2 | 30.37 | 27.60 |
| Layer total | 238.6 | 222.7 (**-6.7%**) |
