# fix: account for DFlash draft KV in HybridSWAPoolConfigurator cell_size

[Upstream PR](https://github.com/sgl-project/sglang/pull/32508) · state: closed · merged: False

## Original PR description

## Motivation

`HybridSWAPoolConfigurator` already budgets EAGLE/STANDALONE draft KV via
`_draft_full_layers_num` / `_draft_swa_full_layers_num`, but it does **not**
account for DFlash/DSPARK draft KV. When a hybrid SWA model (e.g. Gemma4,
GPT-OSS) runs with DFlash, the target's `cell_size` omits the draft KV pool
cost, causing `max_total_num_tokens` to be overestimated by roughly
`draft_layers / total_layers` (~6% for typical configs). This can lead to
draft KV pool OOM at runtime.

The existing Gemma4 DFlash test (`test_gemma4_dflash_31b_extra.py`) masks
this by setting `--max-total-tokens 32768` explicitly, which bypasses the
`cell_size` calculation entirely.
