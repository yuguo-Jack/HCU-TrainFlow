# [Bench] Fix bench_serving sglang-oai output_len silently stuck at requested max_tokens

[Upstream PR](https://github.com/sgl-project/sglang/pull/24255) · state: closed · merged: False

## Original PR description

## Motivation

Fixes #24254.

`async_request_openai_completions` updates `output_len` from the trailing
`usage` chunk inside `if data["choices"][0]["text"]:`. sglang streams the
final `completion_tokens` in a chunk whose text is empty, so the guard is
False and the update is skipped. `output_len` stays at the requested
`max_tokens` — silently breaking TPOT / output throughput / retokenized length
whenever generation stops before `max_tokens` (EOS, length stop, abort).

Chat path was already fixed by #23954; this mirrors the same shape for the
completions path.

## Modifications

`python/sglang/bench_serving.py`:

- Move the `output_len = data.usage.completion_tokens` update out of the
  content guard, matching the chat-completions path.
- Add `choices = data.get("choices") or []; if not choices: continue` so the
  usage-only chunks emitted by vLLM's `include_usage=true` (reported in #5451)
  no longer raise `IndexError`.
- Normalize `choices[0].get("text") or ""` so a `null` text field cannot crash
  or drop content.

Net diff: +18 / -11 on one function, no behavior change on the happy path.

## Tests

New `test/registered/bench_fn/test_bench_serving_oai_completions_stream.py`
(5 tests, `stage-a-test-cpu` CI suite, ~3s total):

- `test_output_len_from_trailing_usage_chunk_with_empty_text` — primary
  regression for #24254.
- `test_output_len_from_trailing_usage_chunk_with_empty_choices` — #5451 shape.
- `test_null_text_field_does_not_break`
- `test_content_only_stream_unchanged` — happy-path non-regression.
- `test_no_usage_reported_keeps_request_output_len` — fallback behavior.

All five pass with this PR; four of them fail on `main` without it (the
empty-text test fires `AssertionError: 64 != 3`, the empty-choices test
raises `IndexError`).
