# [Perf] diffusion: Write uncompressed PNG responses without Pillow's row filters

[Upstream PR](https://github.com/sgl-project/sglang/pull/46099) · state: closed · merged: True

## Original PR description

## Motivation

Image responses are encoded as PNG with zlib level 0 by default since #45987. Pillow still runs its adaptive row filter at that level: for every row it tries the PNG filters and keeps the one with the smallest sum (the encoded files use filters 1 and 2). At level 0 the deflate stream is stored, not compressed, so the filter cannot make the file smaller. It only costs time, and the time is on the output rank between the end of the forward and the reply:

| frame | Pillow, `compress_level=0` | unfiltered rows in stored blocks |
|---|---|---|
| 1024x1024 RGBA (Qwen-Image-2.1) | 74.9 ms | 4.3 ms |
| 1280x720 RGB (Cosmos3 T2I) | 60.9 ms | 2.8 ms |

(One core of a Xeon Platinum 8558P, `Pillow` 13.0.0, zlib 1.3.2. OpenCV's level-0 encoder takes 37.0 / 26.5 ms.)

## Modifications

`entrypoints/utils.py`: `_encode_image_frame` writes a uint8 frame with `compress_level == 0` itself: unfiltered rows (filter byte 0) in one `zlib.compress(rows, 0)` IDAT, behind the same IHDR Pillow writes. Any other level, and non-uint8 frames, still go through Pillow.

The PNG is the same image:
- The IHDR is byte-identical. Pillow writes no other chunks on this path (no gAMA, sRGB, pHYs or text), so the only difference is how the IDAT data is filtered and split: one IDAT chunk instead of Pillow's 64 KiB chunks.
- Decoded pixels, mode and `info` are equal for gray, gray + alpha, RGB and RGBA frames.
- The file is slightly smaller (1024x1024 RGBA: 4,195,716 bytes instead of 4,196,804).

Tests:
- `test_output_saving.py`: levels None, 0 and 75 no longer call Pillow's save, level 100 still saves through Pillow at `compress_level=9`, and every saved file decodes to the source frame. On main the uncompressed cases call Pillow and fail.
- `test_image_response_bytes.py`: the returned-bytes test also covers two-channel (gray + alpha) frames.

## Accuracy Tests

The decoded pixels are identical to the frame the pipeline produced, so the served image does not change.

## Speed Tests and Profiling

Client latency (median of 5 after warmup), main vs this PR, a fresh server per arm, distinct inputs per request; the Qwen arms ran in pairs on two GPUs and swapped GPUs between rounds.
