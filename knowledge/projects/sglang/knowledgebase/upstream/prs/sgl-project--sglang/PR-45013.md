# [CI] [Intel] xpu: Disable L0 copy offload to fix first-H2D-copy hang

[Upstream PR](https://github.com/sgl-project/sglang/pull/45013) · state: closed · merged: True

## Original PR description

## Motivation

The Intel nightly wheel job (`nightly-xpu-kernel-wheel-1-gpu`) has lost 2h on each of the last two nights to a silent hang:

- 10-17 [run 39052685301](https://github.com/sgl-project/sglang/actions/runs/39052685301/job/117454286197): `test_xpu_embedding.py (timeout after 7200s)`, the only failure (8/9 passed).
- 10-16 run 38937883788: the same hang in `test_xpu_classification.py`.

Both stop right after the HF reference model loads, with no error output. When the per-file timeout kills the test, the kernel logs `Schedule disable failed to respond` and a GT reset from `xe_guc_exec_queue_lr_cleanup`.

**Root cause (reproduced on the CI runner, same image `d2e04cc7` and commit `4eb606b2a`, GPU 0):**
This looks like a driver-stack issue (the GuC/xe interaction with copy offload in the L0 v2 adapter), not an sglang bug. The runner's GuC firmware is 70.45.2, while xe asks for 70.49.4.

## Modifications

- In `scripts/ci/xpu/xpu_ci_start_container.sh`, set `UR_L0_V2_FORCE_DISABLE_COPY_OFFLOAD=1` in the CI container. In-order queues then keep copies on the compute engine instead of offloading them to `bcs`.
- The nightly and PR XPU workflows both start their container with this script, so both get the change.

## Accuracy Tests

Validated on the CI runner (same image digest and commit as the failing run, GPU 0):

| | Runs | Hangs | Time per run | `bcs` engine resets in dmesg |
|---|---|---|---|---|
| `test_xpu_embedding` loop, default | 10 | 2 | ~85s | on almost every teardown |
| `test_xpu_embedding` loop, flag on | 20 | **0** | ~87s | **none** |

Full replay of the `nightly-xpu-kernel-wheel-1-gpu` job steps with the flag on:

- stage-a + stage-b 1-GPU XPU suites: **40/40 passed** (CI 10-17: 40/40).
- `nightly-xpu-kernel-wheel-1-gpu` suite: **9/9 passed**, with embedding in 94s (CI 10-17: 8/9, embedding timed out at 7200s).
- No xe errors in dmesg for the whole run. DeepSeek-OCR-2 olmbench accuracy was 0.887 (threshold 0.80).

## Speed Tests and Profiling

- Per-file run times stayed within normal run-to-run variation.
- `test_xpu_kv_canary` was the largest outlier in the replay, so I ran it on its own on the same setup: 359s without the flag vs 369s with it, which is noise.
