## Motivation

<!-- Describe the purpose and goals of this pull request. -->

DeepSeek-V4.1-Flash's dense gemm use fp8 with 32x32 blocks. On the current AMD code path (`--fp8-gemm-backend aiter`), these layers (wq_b, wo_b, wqkv_a, indexer wq_b, engram) run aiter's triton mxfp8 gemm (`gemm_a8w8_blockscale`).
With tp2 and a 16k chunk size, these kernels take ~31 ms, ~10% of prefill.
This PR adds an in-tree  mxfp8 dense gemm written in flydsl and uses it in place of aiter's gemm for prefill-sized inputs (M >= 2048).

## Modifications

<!-- Detail the changes made in this pull request. -->

`python/sglang/kernels/ops/quantization/mxfp8_flydsl_gfx95.py`
- Computes `C[M, N] = A[M, K] @ B[N, K]^T` (C: bf16; A, B: fp8_e4m3 with one ue8m0 scale per 32 elements along K).
- Each workgroup computes a 256x256 tile of C (128x256 when M is small) with 8 waves (512 threads). The pipeline is similar to aiter's 8-wave fp8 gemm:
  ```
  C tile 256 x 256, waves w0-w3 (row 0) and w4-w7 (row 1)
  
                     B0 (cols 0-127)          B1 (cols 128-255)
  A0 rows   0-63     w0  w1  w2  w3           w0  w1  w2  w3
  A0 rows  64-127    w4  w5  w6  w7           w4  w5  w6  w7
  A1 rows 128-191    w0  w1  w2  w3           w0  w1  w2  w3
  A1 rows 192-255    w4  w5  w6  w7           w4  w5  w6  w7
  
  each cell: 64 x 32 = 4 x 2 MFMA tiles of 16 x 16
  per K step (128): (A0,B0) -> (A0,B1) -> (A1,B0) -> (A1,B1)
  ```
- A and B are split into halves, giving four quadrants. Each K step computes them in turn, reading each half from LDS once and reusing it for two quadrants.
- Each half has two LDS buffers, so the global -> LDS copy (DMA) of later K steps overlaps the MFMAs. The two wave rows run one barrier apart, so one row's MFMAs overlap the other row's LDS reads.
  ```
  time ->  | t0       | t1       | t2       | t3       | t4       | t5       | t6       | t7       | t8 ...
  row 0:   | ld A0,B0 | mfma 00  | ld B1    | mfma 01  | ld A1    | mfma 10  | wait     | mfma 11  | ld A0,B0 ...
  row 1:   | (extra)  | ld A0,B0 | mfma 00  | ld B1    | mfma 01  | ld A1    | mfma 10  | wait     | mfma 11  ...
  ```
- The C tile is staged through LDS and written back as full rows.
- `mxfp8_scale_layout()`: a small Triton kernel that rearranges ue8m0 scales into the layout the kernel reads.

`python/sglang/srt/layers/quantization/fp8_hip.py`
- `_prepare_flydsl_mxfp8()`: at weight loading, converts the weight scales into the kernel's layout.
- `apply_dense()`: on the aiter route, calls `_apply_flydsl_mxfp8()` when M >= 2048. Smaller M, including decode, stays on aiter.

`python/sglang/kernels/ops/quantization/mxfp8_amd_gfx95.py`
- Add a `mxfp8_operand()` helper to avoid repeated code.

`python/sglang/srt/environ.py`
- Add `SGLANG_OPT_HIP_FLYDSL_MXFP8` (off by default).

This affects gfx950 with fp8 weights that use a 32-element ue8m0 scale (DeepSeek-V4.1-Flash).
Only be triggered when `SGLANG_OPT_HIP_FLYDSL_MXFP8=1`. With the flag off, the code path is same.

## Speed Tests and Profiling

<!-- If this pull request impacts inference speed, provide benchmarking and profiling results. -->

| gemm (N x K, TP2) | M=4096: aiter -> flydsl | M=16384: aiter -> flydsl |

| wq_b (16384 x 1280) | 113.3 -> 87.5 us (1.29x) | 476.5 -> 338.1 us (1.41x) |
| wo_b (5120 x 4096) | 125.5 -> 90.0 us (1.39x) | 459.7 -> 282.3 us (1.63x) |
| wqkv_a (1792 x 5120) | 56.2 -> 40.6 us (1.38x) | 212.3 -> 130.8 us (1.62x) |
| indexer wq_b (4096 x 1280) | 34.1 -> 27.8 us (1.23x) | 127.4 -> 87.4 us (1.46x) |
| engram (25600 x 6144) | 851.6 -> 526.0 us (1.62x) | 3634.6 -> 1865.6 us (1.95x) |
