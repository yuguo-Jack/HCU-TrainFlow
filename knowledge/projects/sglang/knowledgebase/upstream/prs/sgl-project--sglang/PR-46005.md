## Motivation

The cookbook's **Agentic Long-Context Deployment** sections (#42726, #43083, #43799, #43983, #44065, #44228, #44654, #44712, #45039, #45111, #45311, #45513, #45749) mirror SemiAnalysis InferenceX AgentX submissions as raw launch commands, each linked to the run that measured it. The configurations are mirrored from SemiAnalysis submissions. This PR:

1. **Syncs to InferenceX `main`** (`39b1aab8`). Since #45749, `main` merged [InferenceX #4303](https://github.com/SemiAnalysisAI/InferenceX/pull/4303) (DeepSeek-V4.1-Flash GB300 Dynamo+SGLang), [InferenceX #4394](https://github.com/SemiAnalysisAI/InferenceX/pull/4394) (GLM-5.2 FP4 B200 SGLang image `v0.5.22-cu130`), [InferenceX #4389](https://github.com/SemiAnalysisAI/InferenceX/pull/4389) (GLM-5.2 FP8 B200) and [InferenceX #3930](https://github.com/SemiAnalysisAI/InferenceX/pull/3930) (GLM-5.3 B300). All four are now measured on `main`.
2. **Overlays seven open InferenceX PRs** (table below).
3. **Gives colocated workers their own GPUs and ports.** Some deployments run several workers on one node. The page showed them with the same `--port` / bootstrap / KV-event ports, so they could not run as written. #45495 fixed the DeepSeek-V4.1 GB300 cell by hand; this PR makes the generator do it for every such cell (details below).

**Colocated workers**

Some deployments start several workers on one node:
- DeepSeek-V4.1 GB300 disagg: two DEP2 prefill workers per 4-GPU node.
- GLM-5.2 B200 disagg: two TP4 decode workers per 8-GPU node.
- Qwen3.5 GB300 / B200 / B300 disagg: prefill and decode on one node, or two decode workers per node.

SemiAnalysis's launches gave each of them its own GPUs and ports. The page now does too:
- **Several colocated workers in one role.** The worker tab starts with a `LOCAL_WORKER_RANK` preamble. It sets `CUDA_VISIBLE_DEVICES`, `PORT` (+32 per rank, srt-slurm's spacing: SGLang derives further ports from `--port`), `BOOTSTRAP_PORT` (+1) and the KV-event endpoint. The note under the tab lists each worker's rank.
- **KV-event endpoint stride.** The endpoint is offset by the attention-DP size per rank, because a publisher binds endpoint + DP rank. srt-slurm's +1 spacing would overlap for DEP2; #45495 used the same fix.
- **A single colocated worker** (e.g. the decode worker of a one-node 1P1D) shows its offset ports directly, e.g. `--port 30032`.
- **SGLang router URLs** in the derived variant use the same per-worker ports.
- **Placement note.** These cells carry a note that the GPU count covers the GPUs the workers use, so whole nodes should be reserved.

**Relation to #45495.** That PR hand-edited the DeepSeek-V4.1 GB300 disagg cell. This sync replaces the edit with generated data:
- **Kept:** the per-worker GPU pinning, distinct ports, the 2-port KV-event stride and a Placement note.
- **Changed:** the cell again offers the derived no-offload / HiCache tiers next to the measured Mooncake tier, labeled "derived", like every other cell.
- **Removed by existing rules:** `--enable-metrics`, `DYN_SYSTEM_PORT`, `PYTHONUNBUFFERED` and `MC_STORE_CLIENT_METRIC_INTERVAL`. The Dynamo system server is off by default, so dropping `DYN_SYSTEM_PORT` cannot make colocated workers collide.

`_agentx.jsx` changes only text: the worker note for blocks with `local_ranks`, and the `LOCAL_WORKER_RANK` placeholder description (no longer prefill-only).

**Flag rules added:** `--no-speculative-enable-w4a4-mxfp4-megamoe` (keep, kernel selection) and `UCX_CUDA_IPC_ENABLE_MNNVL` (keep, UCX CUDA IPC over multi-node NVLink for NIXL, [InferenceX #4398](https://github.com/SemiAnalysisAI/InferenceX/pull/4398)).
