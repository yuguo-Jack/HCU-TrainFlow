# [Perf] [AMD] attention: Use aiter Gluon MLA decode in the triton backend on gfx1250

[Upstream PR](https://github.com/sgl-project/sglang/pull/44458) · state: open · merged: False

## Original PR description

## Motivation

On gfx1250 the ASM MLA decode kernels only take FP8 Q and FP8 KV, so a model with a bf16 KV cache decodes MLA with the triton backend's `decode_attention_fwd`. aiter ships a paged Gluon `mla_decode_fwd` for gfx1250 that is several times faster at small batch.

## Modifications

With `SGLANG_USE_AITER=1` on gfx1250, MLA decode in the triton backend calls aiter's paged Gluon `mla_decode_fwd`. It is used only for:

- a paged KV pool with a power-of-two page size of at least 16;
- plain causal MLA: no speculative decoding, sinks, score_mod, logit soft cap, sliding window or DCP.

Everything else keeps `decode_attention_fwd`. The page table and sequence lengths are built at the first layer of each forward from the same graph-static batch tensors the Triton path reads, so CUDA graph replay stays valid. `num_kv_splits` is 0, so the kernel picks its split from a fixed estimate that holds for any sequence length during replay.

#41682 adds the same aiter kernel to the aiter attention backend behind an opt-in flag. This PR covers the triton backend and does not change the aiter backend; the two do not conflict.

### Dependency on aiter

Needs ROCm/aiter#5935, which the ROCm Docker images carry since #44379 (aiter 2bb549102). Without it the kernel writes its segment softmax state over the output whenever a batch runs one segment per sequence (batch 97 and above on 96 CUs), which gives wrong results without an error. The wrapper checks the installed aiter for that change and keeps the Triton decode when it is missing.

A CPU unit test (`test/registered/unit/layers/attention/test_triton_gluon_mla_decode_probe.py`) checks that an aiter without #5935 keeps the Triton decode.

## Setup

Kimi-K2-Thinking-MXFP4, TP8, MI455X (gfx1250), image `rocm/sgl-dev:v0.5.21-rocm10-mi45x-20261011`; aiter is the image's plus ROCm/aiter#5935, #5501, #5043 and #5402 (all in aiter 2bb549102). The Kimi-K2 cookbook targets MI300X; flags used here beyond it: `--attention-backend aiter --prefill-attention-backend aiter --decode-attention-backend triton --page-size 64 --disable-radix-cache --disable-custom-all-reduce --chunked-prefill-size 8192 --cuda-graph-max-bs-decode 128`, with `SGLANG_USE_AITER=1`, `SGLANG_ROCM_FUSED_DECODE_MLA=0` and `AITER_FORCE_A8W4=1`. Before and after differ only by this PR.

## Accuracy Tests

GSM8K with `few_shot_gsm8k` (8-shot, 1319 questions, `max_new_tokens` 512, the settings of sglang's AMD Kimi accuracy tests; 1319 parallel requests, so batches above 96 are covered): before and after to be added. Single GPU, batch 4 at 8k context: cosine similarity to the Triton decode >= 0.9999.
