## Motivation

Cosmos3 reuses the Wan VAE, but Cosmos3Config was excluded from the Conv3d channels_last_3d transform that Wan-T2V-480P / LTX2 / Qwen-Image already use.


- BBuf · comment · 2026-08-27T06:49:26Z · [source](https://github.com/sgl-project/sglang/pull/28021#issuecomment-5435403034)

RTX PRO 6000 Blackwell (SM120, 96 GB) validation on commit bede6bc37c5d9638099ebb948d93b9e2a7799f10, PyTorch 2.13.0+cu130, CUDA 13, Cosmos3-Nano T2V 832x480x9f, 4 steps, bf16, seed 42. I held the DiT/VAE resident in both arms so this isolates SGLANG_DIFFUSION_VAE_CHANNELS_LAST_3D=1.

Two warmed request runs:

- default: VAE decode 288.677 / 288.703 ms; E2E 765.578 / 770.076 ms; peak reserved 37008 MB
- channels_last_3d: VAE decode 256.423 / 256.463 ms; E2E 740.212 / 735.459 ms; peak reserved 35260 MB

Averages: decode 288.690 -> 256.443 ms (-11.17%); E2E 767.827 -> 737.836 ms (-3.91%). Denoise was neutral within run variance.

Numerics: the two channels_last runs were mutually deterministic, but decoded frames were not bitwise-identical to the default layout. ffmpeg comparison over all 9 decoded frames gave PSNR 50.498 dB and SSIM 0.996193. So this looks like a useful SM120 speed/memory win, but it should retain the documented numerical-parity tolerance rather than claim bitwise equivalence.
