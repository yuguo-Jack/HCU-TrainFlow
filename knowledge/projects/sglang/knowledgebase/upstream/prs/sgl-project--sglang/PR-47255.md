# [Fix] disaggregation: Bind NIXL transfer workers to the rank's device

[Upstream PR](https://github.com/sgl-project/sglang/pull/47255) · state: closed · merged: True

## Original PR description

- Start NIXL transfer worker threads through `run_on_device(gpu_id, ...)`, as #45678 does for Mooncake and Mori.
- An unbound worker's current device is 0. The DCP pack (`try_pack_dcp_src`) switches to a gather stream on the rank's device; leaving that stream context restores device 0, which creates a CUDA context there in every prefill rank.
- Revert the per-call `set_device` in `dcp_pack.py` that this PR first added: with the thread bound, it is not needed.

Only NIXL prefill workers change: their current device becomes the rank's GPU instead of 0. Mooncake and Mori are unchanged.

Verified with a model-free check that packs DCP rows from a thread while the buffer is on `cuda:1`: a thread started like the old NIXL worker leaves 612 MiB on device 0; a thread started through `run_on_device` leaves none, and the packed rows match in both.
