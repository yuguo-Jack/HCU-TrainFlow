# [Perf] minimax-m3: Cache CPU image preprocessing artifacts

[Upstream PR](https://github.com/sgl-project/sglang/pull/44181) · state: open · merged: False

## Original PR description

## Motivation
Repeated image requests to MiniMax M3 rerun image preprocessing even when the preprocessing cache is enabled. Implements the MiniMax M3 follow-up in #39532.

## Modifications
- Cache prompt-independent per-image CPU features and `grid_thw` via `MediaArtifactCacheMixin`.
- On hits, expand image placeholders from cached grids (mirrors HF `replace_image_token`) and tokenize directly; the image processor is not called. Cached items carry their feature hash, so the downstream pad-value hashing is skipped too.
- Image-processor config is part of the cache fingerprint; RGB conversion matches the legacy loader.
- Only image-only requests with canonical placeholders take the cached path; video/audio, aliases, preprocessed/tokenized inputs and GPU decoding keep the existing path. Default (cache disabled) behavior is unchanged.
- Per-image features are cloned only when they share storage with other images in the batch, so eviction frees memory independently without copying single-image misses.

## Tests
- `test_minimax_m3_artifacts.py` (CPU CI): parity test against the legacy path using the Transformers MiniMax M3 image processor with the processor worker pool enabled (identical input_ids, offsets, features, grids on cold and hot requests), plus regressions for partial hits, ordering, per-image storage ownership, fingerprinting and fallbacks.
- Local check with the real `MiniMaxAI/MiniMax-M3` tokenizer, chat template and remote-code processor (no weights): cached and legacy outputs are identical for 1, 2 and 3 images of mixed sizes (56x56 to 1600x1200), cold and hot.

## Benchmark
Apple M3 CPU, real M3 tokenizer/processor, base64 JPEG inputs. Time covers `process_mm_data_async` plus the tokenizer manager's pad-value hashing. Median of 40 requests, averaged over 3 runs.

| Image | Cache off | Cache miss (new image) | Cache hit (repeated image) |
|---|---|---|---|
| 448x448 | 8.9 ms | 9.4 ms | 1.4 ms |
| 1600x1200 | 36.1 ms | 37.9 ms | 2.5 ms |

The cache is opt-in. Misses cost ~0.3–2 ms extra (content digest and cache bookkeeping); hits are ~6–15x faster. Not an end-to-end serving benchmark.
