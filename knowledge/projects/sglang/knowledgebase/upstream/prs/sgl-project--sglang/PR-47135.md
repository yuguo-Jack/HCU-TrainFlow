# [Feat] lora: upsert on /load_lora_adapter

[Upstream PR](https://github.com/sgl-project/sglang/pull/47135) · state: closed · merged: True

## Original PR description

## Motivation

A same-name `/load_lora_adapter` of a PEFT directory fails with "already loaded", so a trainer that republishes an adapter every step has to unload and reload it. That leaves the name unregistered while in-flight requests drain and deadlocks under a retract pause, which rules it out for fully-async RL. The registry and `LoRAManager` already refresh an adapter in place for streamed weights (`register_lora_adapter`, `apply_streamed_adapter`); this exposes the same thing on the path route.

Miles side: radixark/miles#3690 (http-lora transport). Its tensors mode already streams through the weight-update session and needs nothing here; this is for its path mode (adapter on shared storage, engine loads the directory) under `--fully-async`.

## Modifications

- `LoadLoRAAdapterReqInput.upsert: bool = False`.
- `TokenizerControlMixin.load_lora_adapter`: with `upsert`, resolve `lora_name` through `register_or_reuse` so a held name keeps its `lora_id`, and `refresh` the registry entry only after the backend succeeded. A fresh name loads as before; a plain load of a held name is still rejected.
- `LoRAManager.load_lora_adapter(upsert=)`: a loaded id rereads the PEFT directory and installs it through `_load_lora_adapter_from_tensors(upsert=True)`, so a failed read or install leaves the old weights serving (same rollback as the streamed path).
- `ModelRunner` / `TpModelWorker`: pass-through.
- Cached prefixes are keyed by `lora_id`, so the caller pauses and flushes around the swap, same as for `end_weight_update`; miles under fully-async uses its namespaced radix cache instead. Noted on the field.

Source: 5 files, +68/-12.

## Accuracy Tests

- `test/registered/unit/lora/test_lora_upsert.py`: 6 new cases (manager path upsert incl. failed-read rollback; route-level id reuse, registry untouched on failure, held name still rejected without upsert). 32/32 pass. Also sets `attn_dp_enabled` on the stub manager, which 16 existing cases needed.
- End to end on an H200 with Qwen3-0.6B and two adapters, greedy decoding: fresh load v1, plain reload rejected, upsert v2, upsert v1; each upsert's output matches a fresh load of the same adapter. Same adapters installed through the weight-update session match too.
- Miles RL run on MI300X (`rocm/sgl-dev:miles-rocm10-mi30x`, this patch mounted): Qwen3-4B Megatron LoRA on 2 GPUs, two external engines on 2 GPUs, `train_async.py --fully-async --pause-generation-mode in_place`, http-lora path mode. 7 syncs, every one an in-place upsert under the same `lora_id` with 12 requests in flight per engine, zero unloads, generation never stopped, job succeeded.
