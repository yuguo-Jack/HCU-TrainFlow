# [Perf] [AMD] mla: FP8 prefix K/V pack and absorbed short cached extends for Kimi-K3 prefill on gfx950

Replaces #44547-#44553.

## Motivation

Agentic Kimi-K3 traffic is mostly extends over long cached prefixes (50K tokens here). On the aiter FP8 MLA prefill
path each such extend re-expands the whole cached latent prefix per MLA layer through index_select, two casts, a
contiguous copy, kv_b_proj, the rope cat, head padding and two fp8 casts; for a short extend that expansion costs far
more than the new tokens' attention.

## Modifications

Both paths are gated on gfx950 and an FP8 latent cache.

- `_expand_prefix_kv_fp8`: the prefix K/V for the FP8 prefill come from two launches around kv_b_proj
  (`gather_prefix_latent`, then `pack_prefix_kv_fp8`: rope cat, head tiling to the kernel's 16 heads, fp8 casts),
  byte-identical to the chain they replace; `mla_fp8_prefill_attn` skips re-padding them.
- `uses_absorbed_cached_extend()`: an extend whose requests each add at most
  `SGLANG_ROCM_MLA_ABSORBED_EXTEND_MAX_TOKENS` (64) tokens after a cached prefix takes the absorbed MLA path
  (`handle_attention_aiter`), and the aiter backend attends the latent cache directly with absorbed queries
  (`mla_absorbed_extend`: 4 queries x 16 heads per program over one KV split, fp8 QK, LSE combine), planned once
  per batch in the extend metadata.

| New env var | Default |
|---|---|
| `SGLANG_ROCM_MLA_ABSORBED_EXTEND_MAX_TOKENS` | 64 |

## Accuracy Tests

**Setup for every number below:** 8x MI350X (gfx950, 1000 W), Kimi-K3 (MXFP4 MoE, bf16 attention) at TP8 with EAGLE3
(topk 1, 3 steps, 4 draft tokens), FP8 KV cache, `SGLANG_USE_AITER=1`, aiter's K3 FlyDSL kernels
(`AITER_SITUV2_A8W4=1 AITER_FLYDSL_FORCE=1 SGLANG_AITER_K3_OPT=1`), CUDA graphs for bs 1/2/4/8/16, and an aiter bf16 GEMM table with K3 rows re-tuned on this pod with HBM-resident weights
(`AITER_CONFIG_GEMM_BF16`; not part of this PR, it belongs in aiter's model configs). EAGLE3 on K3 needs the
aux-capture commit of #43599, applied locally for these runs. Microbenchmarks rotate their weights through HBM.
Per-feature numbers were measured on the integration branch of this series as each piece landed (Oct 13-14,
earlier `main`). All branches of the series are on `main` 4eb606b2ae (2026-10-17); the kernel tests below ran on this
branch, and the end-to-end checkpoints on that `main` plus the queue up to each slot.

- GSM8K 400 with the absorbed extend on: 0.985 / accept 3.622; short questions after the 50K context answer
  correctly. End to end: see below.
- `test_mla_prefill_gfx950.py` (new): ragged absorbed extends with and without a prefix against a reference attention
  (cosine > 0.9995); the prefix pack is byte-identical to the unfused expansion for 1 / 37 / 3000 rows. On MI350X:
  2 passed (6 subtests).

## Speed Tests and Profiling

- Prefix expansion per MLA layer at a 50K prefix: 1645 -> 401 us (~30 ms per agentic turn over 24 layers).
- Absorbed extend per layer at a 50K prefix: 101 / 202 / 351 / 667 / 1279 us for 8 / 32 / 64 / 128 / 256 new tokens
  vs ~420-500 us for the expansion path (both scale with the prefix), hence the 64-token default.
- In-server turn TTFT, 50K cached prefix + 62 new tokens: 265 / 261 / 243 ms -> 249 / 246 / 249 ms.
