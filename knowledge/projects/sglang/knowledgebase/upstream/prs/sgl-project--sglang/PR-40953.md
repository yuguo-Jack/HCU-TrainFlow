# [PD] Transfer EAGLE draft probabilities for rejection sampling

[Upstream PR](https://github.com/sgl-project/sglang/pull/40953) · state: closed · merged: False

## Original PR description

## Motivation

The disaggregated EAGLE handoff needs the initial full draft proposal distribution when rejection sampling is enabled. Top-k candidates alone do not provide the proposal probabilities needed by the verifier.

## Modifications

- Transfer the FP32 draft distribution through prefill/decode metadata and reconstruct it in the decode draft input.
- Validate the peers' rejection-sampling settings before transfer setup. Mixed/unknown prefill rank settings remain unknown rather than adopting a later rank's layout. Upgrade both peers together.
- Restrict this handoff to single-layer EAGLE-family speculation; retain the disabled metadata layout.
- Initialize fake-transfer warmup proposals consistently, without mutating reusable metadata slots.
- Report metadata allocation size and document per-rank memory cost.
- Preserve current upstream sampling-mask, DSA-seed, and optional KV-checksum fields.

## Accuracy Tests

- Passed: 7 source-isolated CPU tensor tests (plus 7 subtests), exercising proposal roundtrip, disabled layout, DSA/checksum ordering, missing/invalid proposals, and decode reconstruction.
- Passed: changed Python files compile; focused Ruff checks; `git diff --check`.
- Added bootstrap compatibility and Rust roundtrip/mixed-registration regressions.
- Full SGLang unit-test collection is blocked on the local macOS environment by missing Triton. Rust tests were not run because the Rust toolchain is unavailable.
- GPU PD transport, overlap/CUDA graphs, stochastic sampling quality and model accuracy have **not** been validated on this upstream port. This PR is Draft.
