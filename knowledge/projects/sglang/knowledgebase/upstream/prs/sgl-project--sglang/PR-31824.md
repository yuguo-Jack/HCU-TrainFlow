## Motivation

EAGLE draft-extend-v2 processes a uniform window of `speculative_num_draft_tokens` for every request. Before draft-extend CUDA graph replay, the current path constructs its metadata through six serialized device launches: subtract and clamp the prefix lengths, cast them to int32, fill the uniform extend lengths, generate flattened positions and start offsets with `compute_position_triton`, and advance the sequence lengths.

The generic position kernel supports ragged extend lengths and recomputes the sum of preceding lengths for each request. Draft-extend-v2 does not need that generality: for a fixed window, request `i` always starts at `i * window_size`. The extra kernels and launch gaps are visible in the decode profile and add latency before useful draft-model work begins.

The CUDA DSA metadata path has the same static-width invariant, but it still materializes an `extend_seq_lens = [qo_len] * batch_size` tensor with `torch.full` and passes it to a kernel that retains generic variable-width indexing logic. No production caller uses the variable-width branch for draft-extend-v2, so the fill launch, tensor load, and scan-capable interface are unnecessary.

## Modifications

- Add `fused_draft_extend_prolog`, a Triton kernel that constructs prefix lengths, uniform extend lengths, flattened positions, per-request start offsets, and post-extend sequence lengths in one launch. It supports int32 and int64 sequence lengths, boundary-window `front_offset`, and caller-supplied positions.
- Enable the fused prolog only on CUDA. Pass positions and start offsets together as a `PrecomputedExtendLayout`; `ForwardBatch` either adopts both tensors or computes both through the existing fallback. Keep `ScheduleBatch.seq_lens` unchanged while exposing the post-write lengths only through `ForwardBatch`.
- Specialize `fused_dsa_draft_extend_metadata` for draft-extend-v2's uniform query width. Replace the device `extend_seq_lens` argument and `STATIC_EXTEND_LEN` mode with a compile-time scalar `qo_len`.
- Simplify DSA row mapping to `req_row = offset // qo_len`, `local_offset = offset % qo_len`, and `row_prefix = req_row * qo_len`; derive `total_len = batch_size * qo_len` and size the Triton launch from the exact production shape.
- Remove the CUDA fused-path `torch.full` used only to communicate the constant query width. Non-fused platform and backend fallbacks retain the existing eager construction.
- Add focused prolog correctness coverage for both sequence-length dtypes, generated and caller-owned positions, front-offset clamping, empty batches, and the full `prepare_for_draft_extend` to `ForwardBatch` handoff. Register this new prolog coverage only in NVIDIA CUDA CI; it is not registered in AMD CI.
- Update `test_dsa_metadata.py` to validate the static-width DSA contract against the eager reference, including padded-length clamping, real page tables, empty batches, large sequence lengths, and large batches. Remove the defensive variable-width and partial-capacity cases tied to the deleted, unused API.
- Add a no-CUDA-graph microbenchmark comparing the previous PyTorch plus `compute_position_triton` metadata pipeline with the fused prolog across batch sizes.
