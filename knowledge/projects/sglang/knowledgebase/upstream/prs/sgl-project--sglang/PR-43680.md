# fix(openai): reject out-of-vocabulary embedding token IDs

[Upstream PR](https://github.com/sgl-project/sglang/pull/43680) · state: open · merged: False

## Original PR description

## Motivation

A flat token-ID input to `/v1/embeddings` is checked for negative IDs but not for IDs outside the model vocabulary. With `BAAI/bge-small-en`, sending ID 30528 triggers a CUDA indexing assertion, terminates the scheduler, and prevents subsequent valid requests from completing.

This requires an invalid client-supplied token ID. It was not observed with ordinary text input.

## Modifications

Reject ordinary IDs at or above `model_config.vocab_size` in the existing OpenAI request validation loop. Preserve the existing exception for a matching `embed_override_token_id` when `embed_overrides` is supplied.

This changes invalid flat token-ID requests to HTTP 400. It does not change native `/encode`, multimodal inputs, embedding override resolution, or model kernels.

```python
import json
import sys
from pathlib import Path
import requests
from transformers import AutoTokenizer

model = "BAAI/bge-small-en"
tokenizer = AutoTokenizer.from_pretrained(
    model, revision="2275a7bdee235e9b4f01fa73aa60d3311983cfea"
)
text = "A short embedding test."
ids = tokenizer(text)["input_ids"]
client = requests.Session()
client.trust_env = False
records = []
for value in (text, ids, [ids[0], 30528, ids[-1]], text, ids):
    try:
        response = client.post(
            "http://127.0.0.1:31248/v1/embeddings",
            json={"model": model, "input": value, "encoding_format": "float"},
            timeout=60,
        )
        records.append({"status": response.status_code, "body": response.json()})
        print(response.status_code)
        if response.status_code != 200:
            print(response.text)
    except requests.RequestException as error:
        records.append({"error": str(error)})
        print(type(error).__name__, str(error))
Path(sys.argv[1]).write_text(json.dumps(records, indent=2))
```

On main and after reverting the validation, the first two requests return 200, the invalid request disconnects after the CUDA assertion, and subsequent requests cannot connect. With the fix, the statuses are `200, 200, 400, 200, 200`. The valid response `data` fields are exactly equal across the main controls and fixed controls.

ID -1 was already rejected with 400 on main. ID 30522 is outside the model vocabulary but still inside the padded embedding table, so it did not crash main; the new validation rejects it consistently rather than relying on padding.
