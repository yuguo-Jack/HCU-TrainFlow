# [Fix] [NVIDIA] minimax-m3: Enable EAGLE3 verification on CUDA

[Upstream PR](https://github.com/sgl-project/sglang/pull/43804) · state: open · merged: False

## Original PR description

## Motivation

MiniMax-M3 with an EAGLE3 draft does not start on CUDA: TARGET_VERIFY reaches the sparse layers' `forward_extend`, which needs the `extend_seq_lens` that verify batches lack, so the warm-up fails with `AttributeError: 'NoneType' object has no attribute 'device'`. #41497 fixed ROCm by verifying a linear draft chain with the sparse decode kernels, one causal row per draft token, but every gate it added is `is_hip`. This PR covers TP, not DP attention.

## Modifications

- Run the #41497 linear-verify path on every non-NPU GPU: `forward_extend` hands verify to `forward_decode` on a shallow copy, one row per draft token, so the dense layers keep their per-request metadata and the draft KV is stored once. `_init_rocm_linear_verify_metadata` becomes `_init_linear_verify_metadata`; the ROCm test only follows the rename.
- On CUDA, accept only EAGLE chains (`topk == 1`) via the existing `draft_is_chain_layout`; tree drafts and other algorithms raise `NotImplementedError` at startup. ROCm keeps its rule: any draft with `topk == 1`.
- Refuse HiSparse with speculative decoding at startup: its swap-in keeps one device buffer and one LRU slot set per request, while verify scores `bs × ndt` rows.
- Bound verify capture by the context length on every platform (CUDA capture took the bound from the 1-token dummy lengths, a one-column score buffer that `_decode_score_kernel` overruns at replay); the eager bound counts the draft rows.
- Clamp rows past the context length to it, which keeps the verify bound at the context length instead of `context + ndt`: those rows predict positions that are never committed (the scheduler caps `max_new_tokens` below the context length and trims over-accepted drafts), and at 1M context the decode top-k stays in its 8192 register bucket.
- Keep verify rows on Triton when MSA decode is on, since its plan covers decode batches only; MSA with the decode graph and speculative decoding is still refused at startup.

## Accuracy Tests

MiniMax-M3-NVFP4, 4x GB300, TP4, 1M context, thinking enabled, `SGLANG_DISABLE_MSA=1`, `lmsysorg/sglang:nightly-dev-cu13-20261012-e6072935` + this patch; EAGLE3 `Inferact/MiniMax-M3-EAGLE3-GQA` (3 steps, topk 1, 4 draft tokens, unquantized draft), real verification.

| same build, one tray each | no spec | EAGLE3 |
|---|---|---|
| GSM8K 1319 q (5-shot) | 0.861 | **0.864** |
| GSM8K 40 q at `--parallel 1` (bs=1 decode graph) | 0.800 | 0.875 |
| passkey at 131K / 524K / 990K tokens | pass | pass |
| mean acceptance length (GSM8K / long context) | – | 2.81 / 2.90 |

- New `test_minimax_linear_verify.py` (CUDA, H100 and B200 CI; MSA decode on, so verify must stay on Triton) compares verify rows with the same rows decoded alone: eager at prefixes 1000 and 5118 (crosses a block boundary) is bit-exact; a graph captured on 1-token dummies, replayed with one request two tokens short of a 64K context, matches inside the context and clamps rows past it.
- On GB300, dropping the eager draft-token term fails the eager cases and dropping the clamp fails the replay cases.

[by Claude Code] **Severity: functional | Confidence: Medium**

**Issue**

This line turns on linear verify for CUDA, where the M3 cookbook documents HiSparse. `validate_hisparse` allows HiSparse with `--speculative-eagle-topk 1`, so HiSparse + EAGLE3 now starts. Verify then calls `swap_in_selected_blocks` with `bs * ndt` rows. But `num_real_reqs` holds `batch_size`, and `load_cache_to_device_buffer_kernel` writes `-1` for every row at or past it.

**Example**

With bs=2 and ndt=4, rows 2-7 get no KV slots. The `ndt` rows of one request also update the same `lru_slots[rid]` at the same time. And `top_k_device_locs_buffer` has only one row per request slot.

**Fix**

Raise `NotImplementedError` here when `self.hisparse_coordinator is not None` and speculative decoding is on, until the swap-in handles verify rows.
