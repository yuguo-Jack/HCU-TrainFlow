# fix(sampler): skip identity all-reduce when tp_sync_group has a single rank

[Upstream PR](https://github.com/sgl-project/sglang/pull/43302) · state: open · merged: False

## Original PR description

## Problem

In `Sampler._sync_token_ids_across_tp`, the final-token-id `all_reduce` is gated only on `SYNC_TOKEN_IDS_ACROSS_TP` (env, default off) or non-empty `sampling_info.grammars`. It does not check the size of the sync group.

Under `tp=1` PP-only prefill, the TP group is a **single rank**, so the `MIN` all-reduce is a semantic no-op. However, issuing it still **lazily initializes the NCCL communicator**, which allocates device buffers. Under memory pressure that allocation can fail (observed: `Failed to CUDA calloc 536870912 bytes`), raising an unhandled NCCL error that crashes the scheduler (SIGQUIT) — even though the reduce itself was pointless.

This is the same class of issue as our earlier indexer OOM: a hidden over-allocation that only surfaces when headroom is tiny.

## Fix

Skip the all-reduce when the actual sync group has a single rank:

```python
if (
    SYNC_TOKEN_IDS_ACROSS_TP or sampling_info.grammars
) and dist.get_world_size(self.tp_sync_group) > 1:
    torch.distributed.all_reduce(...)
```

The guard reads the real process-group size (not static tp config), so:
- single-rank group → no-op skipped (no communicator init, no allocation);
- multi-rank group → identical behavior to today.

## Notes

- `self.tp_sync_group` is created at init from `get_tp_group()` (or `attn_tp_group` under DP-attention), so its size is fixed for the process lifetime.
- No correctness impact: a one-rank MIN reduce is the identity.

## Test

- `python -m py_compile` on the file passes.
- Local path (pp=8, tp=1) no longer hits the NCCL lazy-init allocation when grammars are present.
