# [Fix] [AMD] mori: Look up elided DSA state entries by the paired dst index

[Upstream PR](https://github.com/sgl-project/sglang/pull/44412) · state: closed · merged: True

## Original PR description

## Motivation

#41769 added `is_elided_entry(src_len, dst_lens, dst_index)` to mori's `_send_swa_dsa_state`, and #37358 changed the same loop to `for i, j in pairs`. The merged loop still passes `i`, but `dst_state_item_lens` is in decode entry order, like `dst_state_mem_descs[j]`.

When a prefill PP stage pairs with decode entries at different positions (`i != j`), the check reads the wrong decode entry. It either skips an entry that must be sent (decode never gets that layer's index-K), or sends to an elided entry whose descriptor is `None`. PP-equal setups and runs without index-K elision are not affected.

`i != j` needs per-layer ids for the DSA state entries. `append_state_component(..., StateType.DSA, ...)` does not register them today, so PP-mismatched DSA state currently stops earlier with "PP-heterogeneous transfer requires layer ids on both peers" (seen with GLM-5.2-MXFP4, prefill PP2 to decode TP). This change is therefore not reachable yet; it keeps the loop correct for when layer ids are registered.

nixl and mooncake already index by the paired dst entry.

## Modifications

- mori: pass `j` to `is_elided_entry`.
- Two unit tests for a PP prefill stage against full-model decode, with the elided decode entry before and after the paired one.

## Testing
