# [Fix] mistral: do not strip closing brackets from ordinary text in streaming

[Upstream PR](https://github.com/sgl-project/sglang/pull/44245) · state: closed · merged: False

## Original PR description

## Background
In Mistral function call streaming detector, when no [TOOL_CALLS marker was present, the code still ran text.replace("]", "") which corrupted any bracket characters in user normal text.

## Problem
Streaming responses like The item at items[0] has value [guide](url) would have all closing brackets stripped.

## Solution
Removed the erroneous bracket-stripping logic. When there is no tool call marker, parse_streaming_increment should return text unchanged.

## Testing
- Reproduced the issue with the example from bug report
- Verified items[0] and [guide](url) are now preserved correctly

Fixes #44219
