# [Feat] moe: Let models opt out of the partial-block quantized MoE shard check

[Upstream PR](https://github.com/sgl-project/sglang/pull/45985) · state: open · merged: False

## Original PR description

## Motivation

`check_quantized_moe_compatibility` requires, for block-quantized MoE checkpoints, that each rank's expert intermediate shard (`moe_intermediate_size / moe_tp_size`) is a multiple of the checkpoint's `weight_block_size[0]`. That is the right default for models that load the FP8 blocks as-is, but some model implementations do not depend on checkpoint block boundaries.

Concrete case: GLM-5.2-FP8 served at TP64 by an out-of-tree platform plugin (AWS Neuron). Per rank, `moe_intermediate_size` is 2048 / 64 = 32, below the 128 block, so the check rejects the config. That plugin's model dequantizes the checkpoint blocks with each shard's offsets during loading and requantizes the experts per row, so partial-block shards are fine. Today the plugin has to monkeypatch `check_quantized_moe_compatibility` to get past this.

## Modifications

- `model_loader/utils.py`: add `supports_quantized_moe_partial_block_shards(model_config)`, which resolves the model class via `get_model_architecture` (so OOT registry overrides are honored) and reads a `supports_quantized_moe_partial_block_shards` class attribute (default `False`). Same pattern as the existing `supports_cuda_vmm_feature_transport`.
- `moe_ep_setup.check_quantized_moe_compatibility`: skip only the block-alignment error when the model class opts in. The `moe_intermediate_size % moe_tp_size` divisibility check is unchanged. The class is resolved only when the alignment check would otherwise fail, so passing configs and models that don't opt in behave exactly as before.
- New CPU unit test `test/registered/unit/model_executor/model_runner_components/test_moe_ep_setup.py`:
  - misaligned shards (2048 at TP64, 128 block) still raise for a model without the attribute
  - the same config passes when the registered class opts in
  - the divisibility check still applies to opted-in models
  - aligned configs pass without resolving the model class
