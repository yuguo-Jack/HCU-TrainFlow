# [Refactor] sgl-router: Rename --max-in-flight to --max-inflight-requests

[Upstream PR](https://github.com/sgl-project/sglang/pull/44950) · state: closed · merged: True

## Original PR description

## Motivation

Every reorg admission flag mirrors its bucket-file key exactly (`--max-waiting-requests` / `max_waiting_requests`, `--max-pending-prefill-tokens` / `max_pending_prefill_tokens`, `--max-running-usage`, `--max-kv-usage`), except the router-local in-flight cap: the flag is `--max-in-flight` while the group key is `max_inflight_requests`. Follow-up to the docs rewrite in #43592, where this came up as the one exception that had to be called out.

## Modifications

- `src/config/cli.rs`: the flag is now `--max-inflight-requests`; `--max-in-flight` stays a `visible_alias`, so existing launch commands keep working and `--help` lists both. Startup error messages name the new flag. Tests spell the new flag and one new assertion covers the alias.
- `src/config/types.rs`, `src/policies_reorg/factory.rs`: doc comments.
- `README.md`, `ARCHITECTURE.md`: the key-flags row, the admission table, the in-flight sentence and Example A.

Internal field names (`EligibilityConfig::max_in_flight`, the legacy `overloaded` filter) are unchanged; this only renames the CLI surface. Rebased on main after #43592 (docs rewrite) and #44951 (router compile fix) merged.
