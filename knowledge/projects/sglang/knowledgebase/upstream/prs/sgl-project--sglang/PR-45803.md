# [Fix] parser: Fix reasoning/tool-call grammar handoff and GLM-4.5 argument parsing

[Upstream PR](https://github.com/sgl-project/sglang/pull/45803) · state: open · merged: False

## Original PR description

## Motivation

Split out from the Ling-3.1-flash day-0 support effort.

Three correctness fixes on the serving/parser path, all validated on public models:

1. **Implicit end of thinking drops tool-call constraints.** When a model's reasoning ends not with an explicit think-end token but directly with a tool-call marker, the inner grammar was never engaged, so tool arguments after the marker were unconstrained free text. On Qwen3-30B-Thinking with a schema forcing `priority ∈ {1,2,3}` and `</think>` suppressed, base produces a schema-invalid call 9/10 times; with this PR 10/10 are schema-valid, and logprobs show the grammar's begin-sequence taking over right after the marker token.
2. **Nullable string arguments are stringified.** The GLM-4.5 detector converts a bare `null` argument into the strings `"None"` (non-streaming) or `'null'` (streaming), violating schemas that declare `type: ["string", "null"]`, `anyOf`, or `nullable: true`.
3. **Pathological regex backtracking on unclosed tool calls.** A tail of N repeated `<tool_call>` openers costs quadratic time in the GLM detector's split/stream/detail regexes — measured server-side at 13.1 s for N=16000, executed inside the HTTP event loop. This PR makes the scan linear (0.007 s at N=16000) with identical outputs on 4,000 generated inputs.

## Modifications

- `ReasonerGrammarObject` probes a complete tool-start marker during thinking via a new atomic `try_accept_tokens` on the grammar backends (XGrammar, llguidance, Outlines), replays it into the inner grammar, and rolls the replay back across the boundary on rollback. Only complete, non-line-anchored markers accepted by the inner grammar trigger the transition; answer-framed dispatch and request-specific terminators (#44716) are preserved.
- The GLM-4.5 detector resolves local `$ref` against the containing parameters schema and decides null-permission with three-valued composition logic; whenever the full constraint cannot be established (root-level composition/`enum`/`const`, nested `$id` resources, unresolvable references), it conservatively keeps the previous string behavior. Validated against `jsonschema.Draft202012Validator` on 2×20,000 generated schemas with zero false-null emissions.
- The GLM regexes stop retrying every opener in an unclosed tail.

## Accuracy Tests

- GB300 4x, Qwen3-30B-A3B-Thinking-2507, full GSM8K (1319 questions, temp 1.0, top_p 0.95): PR **96.29%** vs base 96.51% (single-run sampling noise); **stop rate 100% both**, zero request errors.
- API regression (streaming + non-streaming): `tool_choice=required` and named tools produce schema-valid JSON arguments (52/54 identical to base; the 2 mismatches are the pre-existing named-tool legacy structural-tag behavior, identical on base). Nullable `["string","null"]` argument yields JSON `null` 12/12 on the Qwen detector (unchanged) and on the GLM-4.5 detector (was `"None"`). Plain requests: 6/6 normal `stop`.
- CPU: 797 passed in `test/registered/unit/{constrained,function_call}` with pinned XGrammar 0.2.7; the two new null-preservation regressions fail on base and pass here; composed-schema and ordinary-string probes show no output change outside the intended nullable cases.

## Speed Tests and Profiling

Not a performance PR. The regex fix removes a quadratic worst case (13.1 s → 0.007 s at N=16000 repeated openers); ordinary tool-call parsing cost is unchanged.
