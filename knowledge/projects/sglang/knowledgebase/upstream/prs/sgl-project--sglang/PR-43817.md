# [Fix] hicache: Key MLA Mamba state per TP rank in the HF3FS backend

[Upstream PR](https://github.com/sgl-project/sglang/pull/43817) · state: closed · merged: True

## Original PR description

## Motivation

MLA shares KV storage keys across TP ranks, but Mamba checkpoints are sharded. On MLA models all HF3FS ranks use rank 0's file and metadata, so Mamba pages from different ranks used the same key. Give Mamba keys a TP rank/size suffix so one rank cannot overwrite another rank's checkpoint. Keep existing keys for other pools. Same fix as #43594 for NIXL.

Old unranked Mamba entries are not reused because their owning rank is ambiguous.

Validation: the new two-rank Mamba round-trip test fails before and passes after.
