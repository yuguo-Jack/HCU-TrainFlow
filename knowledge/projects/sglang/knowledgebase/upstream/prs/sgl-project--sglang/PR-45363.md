# [Fix] eplb: Load all local replicas of each expert

[Upstream PR](https://github.com/sgl-project/sglang/pull/45363) · state: closed · merged: True

## Original PR description

## Motivation

With an a2a backend (for example `--moe-a2a-backend deepep`), a server started with `--init-expert-location` set to a `physical_to_logical_map` in which one EP rank holds two replicas of the same logical expert never loads the second replica. A rank that holds no replica of that expert can still dispatch tokens to that slot, so those tokens go through an expert whose weights were never written. There is no error; the outputs just change. Reloading the weights through the same loader (for example with `update_weights_from_disk`) skips the same slots.

Such layouts come out of EPLB: the packing step can put two replicas of a hot expert on one GPU (deepseek-ai/EPLB#22), and SGLang's copy of the algorithm does too. Passing a saved, rebalanced layout back through `--init-expert-location` therefore hits this. In two layouts that we saved from Qwen3-30B-A3B servers (EP2, 2 redundant experts) after online rebalancing, 16 and 23 of the 48 layers had such a pair.

Where it happens (main @ 78185f4b):

1. [`_compute_logical_to_all_physical_map`](https://github.com/sgl-project/sglang/blob/78185f4b3f565cbe0fec20d71bb5deb372428e80/python/sglang/srt/eplb/expert_location.py#L557-L591): with an a2a backend, each rank replaces every logical expert's candidate list with [`_find_nearest_expert`](https://github.com/sgl-project/sglang/blob/78185f4b3f565cbe0fec20d71bb5deb372428e80/python/sglang/srt/eplb/expert_location.py#L699-L737) (#10874). A rank that holds replicas keeps only its first local one. A rank that holds none keeps the full list (on one node).
2. [`FusedMoE.weight_loader`](https://github.com/sgl-project/sglang/blob/78185f4b3f565cbe0fec20d71bb5deb372428e80/python/sglang/srt/layers/moe/fused_moe_triton/layer.py#L1099-L1104) writes a checkpoint expert into the slots that `logical_to_all_physical()` returns, which is this narrowed list, and [`_weight_loader_physical`](https://github.com/sgl-project/sglang/blob/78185f4b3f565cbe0fec20d71bb5deb372428e80/python/sglang/srt/layers/moe/fused_moe_triton/layer.py#L1124-L1127) keeps the local ones. The rank that holds both replicas writes only the first. For unquantized weights the second one stays [`torch.empty`](https://github.com/sgl-project/sglang/blob/78185f4b3f565cbe0fec20d71bb5deb372428e80/python/sglang/srt/layers/quantization/unquant.py#L787-L789).
3. [The static dispatch table](https://github.com/sgl-project/sglang/blob/78185f4b3f565cbe0fec20d71bb5deb372428e80/python/sglang/srt/eplb/expert_location.py#L612-L672) gives a rank without a local replica a [`_fair_choices`](https://github.com/sgl-project/sglang/blob/78185f4b3f565cbe0fec20d71bb5deb372428e80/python/sglang/srt/eplb/expert_location.py#L662-L667) pick among all replicas, which can be the unloaded one. `static` is [the default with an a2a backend](https://github.com/sgl-project/sglang/blob/78185f4b3f565cbe0fec20d71bb5deb372428e80/python/sglang/srt/arg_groups/parallel_hook.py#L751-L764); with `--ep-dispatch-algorithm dynamic`, [the same list is sampled per token](https://github.com/sgl-project/sglang/blob/78185f4b3f565cbe0fec20d71bb5deb372428e80/python/sglang/srt/eplb/expert_location_dispatch.py#L114-L153).

The narrowing has left rows unloaded before: #12866 removed it to fix NaN NVFP4 input scales, and #13162 / #13484 restored it with a separate path for those global scale parameters (`require_global_experts`). That relies on the other unloaded rows never being dispatched to, and a second replica on the same rank breaks it. #32962 skipped the narrowing when there is no a2a backend; the a2a path is unchanged.

## Modifications

- `ExpertLocationMetadata.logical_to_all_physical()` (`eplb/expert_location.py`): for a routed expert, it now returns every physical slot that `physical_to_logical_map` assigns to the expert, on all ranks, instead of reading the per-rank dispatch list `logical_to_all_physical_map`.
  - The draft-layer fallback and the `require_global_experts` branch are unchanged. They only read the map's shape, and `logical_to_all_physical_map` is padded to the number of physical slots, so both maps give the same values.
  - For a layer in the map and without `require_global_experts`, the lookup rejects out-of-range logical expert ids with `IndexError`, including negative ids, which used to index from the end. The draft-layer and global-scale branches keep their existing conventions.
  - The dispatch fields (`logical_to_all_physical_map`, `logical_to_rank_dispatch_physical_map`) are not touched, so the nearest-replica dispatch from #10874 stays as it is.
- `FusedMoE._local_routed_expert_ids()` (`layers/moe/fused_moe_triton/layer.py`, new) keeps the slots in this rank's routed range. `FusedMoE.weight_loader` applies it to a routed expert's slots (not with `require_global_experts`) before `_weight_loader_physical` maps them to local ids.
  - This is needed because the list now also holds other ranks' slots. After an elastic EP scale-up, a new rank's routed slot can lie past the `_num_global_routed` that an existing rank's layer set at startup, and `_map_global_expert_id_to_local_expert_id` maps such a slot onto that rank's fused shared expert.
  - From reading the code and a CPU test with a stand-in layer, this already happens on main for a rank that holds no replica of the expert, because its narrowed list is the full list. The filter covers that case too.
- `moe_wna16._local_expert_ids` (`layers/quantization/moe_wna16.py`) writes qzeros outside the layer's loader, so it applies the same filter to routed experts. A fused shared expert's id, which the draft-layer fallback returns, is not filtered.
- The third caller, `elastic_ep/expert_backup_client.py`, already keeps only its own range and is unchanged.
- New CPU test file `test/registered/unit/eplb/test_expert_location_weight_loading.py` (`base-a-test-cpu`, 8 tests). It is a new file because it drives the real `FusedMoE` and `moe_wna16` loaders through a stand-in layer, unlike the existing dispatch-table tests. The tests check that:
  - the lookup returns exactly each expert's slots: a same-rank pair, a two-node layout where a rank narrows to a same-node replica, random EP4 layouts, with and without an a2a backend;
  - the real `FusedMoE.weight_loader` and `_weight_loader_physical` fill every local slot with its own expert (the same layouts, random EP2 and EP4); the stand-in layer records the writes instead of copying tensors;
  - every entry of each rank's static dispatch table points at a slot that holds that expert;
  - after an EP 2 -> 4 scale-up, loading routed experts on the existing ranks keeps their fused shared slot;
  - a param with `_sglang_require_global_experts` still gets every slot, on every rank (the new filter does not apply to it);
  - `moe_wna16` picks the right qzeros slots: a second replica, scale-up on ranks 0 and 1, a draft layer with a fused shared expert;
  - the dispatch candidates are unchanged;
  - the draft-layer fallback and the global-scale branch keep their conventions, and out-of-range and negative ids raise.

Alternatives considered:

- Keep every local replica when narrowing. This fixes loading but changes dispatch: `dynamic` gets more candidates, and the static table draws its random picks in a different order.
- Change only dispatch, so that no rank picks an unloaded replica. After an online rebalance the lists are full again, and a slot that keeps the same expert is not copied (`update_expert_weights_single_layer` treats it as unchanged), so a never-written slot can still be picked.
- Copy the first local replica into the others after loading. That has to cover every load path and every parameter, including quantization scales.

## Accuracy Tests

**CPU repro** (script and full output below). EP2, 4 logical experts + 2 redundant, rank 1 holds both replicas of expert 3 (slots 3 and 4), rank 0 holds none.

- On main @ 78185f4b, rank 1 never writes slot 4. Rank 0's static table sends expert 3 to slot 4 in 1 of 8 layers, and with `dynamic`, 4047 of rank 0's 8000 tokens for expert 3 go there.
- With this PR, rank 1 writes slots 3, 4 and 5. Both ranks' static picks for expert 3 are the same as on main, layer by layer; this PR does not touch the dispatch tables.

## Speed Tests and Profiling

Not measured. Only weight loading changes: the lookup compares one row of `physical_to_logical_map` per call instead of indexing the per-rank list, and a rank that holds two replicas of an expert now writes that expert twice. Dispatch and forward passes are unchanged.

```python
"""CPU-only repro: with an a2a backend (e.g. --moe-a2a-backend deepep) and an
--init-expert-location physical_to_logical_map that puts two replicas of one
logical expert on the same EP rank, the second replica is never loaded, while
another rank's static dispatch table can still route tokens to it.

It calls the real SGLang code; no GPU, model or server is needed:
  compute_initial_expert_location_metadata    what each rank builds from --init-expert-location
  ExpertLocationMetadata.logical_to_all_physical  the slots FusedMoE.weight_loader writes
  topk_ids_logical_to_physical                the physical slot a token is dispatched to

Usage: PYTHONPATH=<sglang checkout>/python python repro_same_rank_replica.py [--layers N]
Exit code: 1 if a rank dispatches to a slot its owner never loads, else 0.
"""

import argparse
import json
import sys
from unittest import mock

import torch

from sglang.srt.eplb import expert_location as el
from sglang.srt.eplb.expert_location_dispatch import (
    ExpertLocationDispatchInfo,
    topk_ids_logical_to_physical,
)
from sglang.srt.runtime_context import get_context

EP_SIZE = 2
NUM_LOGICAL = 4
NUM_REDUNDANT = 2
NUM_PHYSICAL = NUM_LOGICAL + NUM_REDUNDANT  # 6 slots: rank 0 = 0..2, rank 1 = 3..5
SLOTS_PER_RANK = NUM_PHYSICAL // EP_SIZE
NUM_LAYERS = 8  # --layers
HOT = 3
# Same row in every layer: logical expert 3 has two replicas, both on rank 1
# (slots 3 and 4); rank 0 has no replica of it.
ROW = [0, 1, 2, 3, 3, 0]


def owner(slot):
    return slot // SLOTS_PER_RANK


def build_rank(rank, a2a_backend, dispatch_algorithm, num_tokens=1):
    """Return what one EP rank loads and where it dispatches, per layer."""
    shape = el.ModelConfigForExpertLocation(
        num_layers=NUM_LAYERS, num_logical_experts=NUM_LOGICAL
    )
    overrides = dict(
        device="cpu",
        ep_size=EP_SIZE,
        nnodes=1,
        moe_a2a_backend=a2a_backend,
        ep_dispatch_algorithm=dispatch_algorithm,
        ep_num_redundant_experts=NUM_REDUNDANT,
        init_expert_location=json.dumps(
            {"physical_to_logical_map": [ROW] * NUM_LAYERS}
        ),
    )
    # No model is loaded, so only the layer / expert counts come from the patch.
    with get_context().override_server_args(**overrides), mock.patch.object(
        el.ModelConfigForExpertLocation,
        "from_model_config",
        staticmethod(lambda model_config: shape),
    ):
        # ModelRunner.maybe_init_expert_location_metadata does this on every rank
        # before load_model(). With static dispatch it also builds this rank's
        # logical_to_rank_dispatch_physical_map (a seeded random pick, seed 42).
        metadata = el.compute_initial_expert_location_metadata(
            model_config=None, moe_ep_rank=rank
        )
        el.set_global_expert_location_metadata(metadata, allow_overwrite=True)
        loaded, dispatch = [], []
        for layer in range(NUM_LAYERS):
            # FusedMoE.weight_loader: for checkpoint expert e, write every slot in
            # logical_to_all_physical(layer, e) that lives on this rank.
            loaded.append(
                sorted(
                    slot
                    for e in range(NUM_LOGICAL)
                    for slot in metadata.logical_to_all_physical(layer, e)
                    if owner(slot) == rank
                )
            )
            info = ExpertLocationDispatchInfo.init_new(layer_id=layer)
            topk_ids = torch.full((num_tokens, 1), HOT, dtype=torch.int64)
            dispatch.append(topk_ids_logical_to_physical(topk_ids, info).view(-1))
        candidates = metadata.logical_to_all_physical(0, HOT)
    return loaded, dispatch, candidates


def run(a2a_backend, dispatch_algorithm, num_tokens=1):
    ranks = [
        build_rank(r, a2a_backend, dispatch_algorithm, num_tokens)
        for r in range(EP_SIZE)
    ]
    print(
        f"\n== --moe-a2a-backend {a2a_backend} "
        f"--ep-dispatch-algorithm {dispatch_algorithm} =="
    )
    for r, (loaded, _, candidates) in enumerate(ranks):
        never = sorted(
            set(range(r * SLOTS_PER_RANK, (r + 1) * SLOTS_PER_RANK)) - set(loaded[0])
        )
        print(
            f"rank {r}: weight loader writes slots {loaded[0]}, never writes {never}; "
            f"logical_to_all_physical(layer, {HOT}) = {candidates}"
        )
    bad_layers = set()
    for r, (_, dispatch, _) in enumerate(ranks):
        hits = {}  # layer -> tokens sent to a slot its owner never loaded
        for layer, slots in enumerate(dispatch):
            missing = [
                int(s) for s in slots if int(s) not in ranks[owner(int(s))][0][layer]
            ]
            if missing:
                hits[layer] = missing
        bad_layers |= set(hits)
        slots_hit = sorted({s for m in hits.values() for s in m})
        if num_tokens == 1:
            picks = [int(d[0]) for d in dispatch]
            print(
                f"rank {r}: logical {HOT} is dispatched to slot, per layer: {picks}"
                + (
                    f"\n        -> never-loaded slot {slots_hit} in layers {sorted(hits)}"
                    if hits
                    else ""
                )
            )
        else:
            n = sum(len(m) for m in hits.values())
            print(
                f"rank {r}: {n}/{num_tokens * NUM_LAYERS} tokens of logical {HOT} go to "
                f"never-loaded slot(s) {slots_hit} ({len(hits)}/{NUM_LAYERS} layers)"
            )
    return len(bad_layers)


def main():
    global NUM_LAYERS
    parser = argparse.ArgumentParser(description=__doc__.splitlines()[0])
    parser.add_argument("--layers", type=int, default=NUM_LAYERS)
    NUM_LAYERS = parser.parse_args().layers
    print(
        f"EP size {EP_SIZE}, {NUM_LOGICAL} logical experts + {NUM_REDUNDANT} redundant = "
        f"{NUM_PHYSICAL} slots ({SLOTS_PER_RANK} per rank), {NUM_LAYERS} layers"
    )
    print(
        f"--init-expert-location row in every layer: rank 0 slots 0-2 = {ROW[:3]}, "
        f"rank 1 slots 3-5 = {ROW[3:]}"
    )
    bad_static = run("deepep", "static")
    torch.manual_seed(0)
    bad_dynamic = run("deepep", "dynamic", num_tokens=1000)
    bad_control = run("none", "dynamic", num_tokens=1000)
    print()
    print(f"layers that route to a never-loaded slot (of {NUM_LAYERS}):")
    print(f"  deepep + static (default with an a2a backend): {bad_static}")
    print(f"  deepep + dynamic: {bad_dynamic}")
    print(f"  control, no a2a backend: {bad_control}")
    reproduced = bad_static > 0 or bad_dynamic > 0
    print("RESULT:", "REPRODUCED" if reproduced else "NOT_REPRODUCED")
    return 1 if reproduced else 0


if __name__ == "__main__":
    sys.exit(main())
```

2. Get approvals from [CODEOWNERS](https://github.com/sgl-project/sglang/blob/main/.github/CODEOWNERS) and other reviewers.
3. Trigger CI tests with [comments](https://docs.sglang.io/developer_guide/contribution_guide.html#how-to-trigger-ci-tests) or contact authorized users to do so.
   - Common commands include `/tag-and-rerun-ci`, `/tag-run-ci-label`, `/rerun-failed-ci`
4. After green CI and required approvals, ask Merge Oncalls or people with Write permission to merge the PR.
