# [Fix] diffusion: Refuse CUDA JIT builds below SM80

[Upstream PR](https://github.com/sgl-project/sglang/pull/45060) · state: open · merged: False

## Original PR description

## Motivation

Fixes #38516.

SGLang's fused diffusion JIT kernels need an NVIDIA GPU of the Ampere generation or newer (SM80+: RTX 30-series / A100 and up). On older cards — Turing and before, like the issue reporter's RTX 2080 Ti — image generation still works through the Triton/torch fallback paths, but the code never checked the GPU generation up front: each kernel launched a full nvcc compile that could not succeed, waited for it to fail, and only then fell back. On the reporter's FLUX run that cost ~49 seconds on the first denoise step, and the failed-compile output (pages of `rsqrt` header-conflict errors) made it look like something was broken when the fallback had actually worked fine.

This PR adds the up-front check, so unsupported GPUs skip straight to the fallback with a one-line log message. The `rsqrt` header conflict itself is an NVIDIA-headers-vs-glibc bug; the sglang-side mitigation is tracked separately in #45066.

## Modifications

- New `kernels/ops/diffusion/common/jit_arch.py` with `require_sm80()`: checks the detected GPU generation and raises before any compiler work when it is below SM80. AMD (HIP) and Moore Threads (MUSA) pass through, since their capability numbers are not on NVIDIA's SM scale.
- Called as the first step of the 16 diffusion JIT kernel builders that had no generation check (14 under `kernels/ops/diffusion/`, 2 under `kernels/kda_kernels/`), copying the pattern already used in `vdn_delta_factors_jit`. The raise is caught by each kernel's existing build-failure fallback, so behavior on unsupported GPUs is unchanged — the fallback just engages instantly instead of after a doomed compile. Kernels already gated at SM90/SM100 are untouched.
- Docs: a Troubleshooting entry in `docs/docs/references/faq.mdx` covering the glibc 2.42 `rsqrt` compile failure (workarounds, link to the distro patch) and the SM80 floor (the issue's third suggested fix).
- Regression test `test/registered/kernels/ops/diffusion/test_jit_sm80_floor.py` (CPU suite, no GPU needed): simulates an older GPU via `override_jit_cuda_arch(7, 5)` and asserts the compiler is never invoked, and pins the cutoff at exactly 8.0. Both cases fail on the pre-fix code and pass with the fix.

## Accuracy Tests

No kernel arithmetic changes. Verified on an L40 (sm_89):

```bash
PYTHONPATH=python python3 -m pytest -q test/registered/kernels/ops/diffusion/test_qknorm_rope_out_of_place.py
# 13 passed in 207.92s (cold cache; ~24 JIT modules compiled through the new gate)
PYTHONPATH=python python3 -m pytest -q test/registered/kernels/ops/diffusion/test_jit_sm80_floor.py
# 2 passed
```

With the GPU generation overridden to sm75 on real CUDA tensors, `residual_gate_add2` falls back immediately with `diffusion CUDA JIT kernels need SM80 or later; detected sm_75`, and the fallback output matches the plain PyTorch path bit for bit.

## Speed Tests and Profiling

On pre-SM80 GPUs, the fallback now engages in milliseconds instead of after serial failed nvcc builds (~49 s on the issue reporter's setup; not re-measured here — no Turing hardware available, and the fix removes the compile attempts entirely rather than speeding them up). On SM80+ the check is one cached capability read per kernel builder, evaluated once per process — effectively free.
