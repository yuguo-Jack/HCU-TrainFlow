# [Feat] [Apple] mlx: Support Unlimited-OCR v2

[Upstream PR](https://github.com/sgl-project/sglang/pull/47921) · state: open · merged: False

## Original PR description

## Motivation

Unlimited-OCR v2 (#47196) runs on CUDA only. This PR serves it on Apple Silicon with the MLX backend (`SGLANG_USE_MLX=1`). It covers the whole model (SAM + CLIP vision encoders, DASH sparse attention, page2d RoPE), the built-in page guard and n-gram processor, and `--uocr-doc-split` with KV tail reuse between page windows. It loads the BF16 checkpoint `baidu/Unlimited-OCR-2` and the mlx-community exports `mlx-community/Unlimited-OCR-2-{4,6,8}bit`.

## Modifications

**MLX model** (`hardware_backend/mlx/models/unlimited_ocr_v2_*.py`, new)
- `unlimited_ocr_v2_mlx.py`: language tower (MoE, DASH attention with entmax routing, page2d RoPE, per-request DASH cache), plus a loader for three checkpoint layouts: BF16 HF, MLX pre-quantized, and mlx-vlm exports (`language_model.` keys, unfused Q/K/V, quantized projector, OHWI convs).
- `unlimited_ocr_v2_kernels.py`: Metal kernels for DASH route and attend. One launch per layer serves up to 12 decode requests, each reading its own cache buffers.
- `unlimited_ocr_v2_sam.py`, `unlimited_ocr_v2_clip.py`, `unlimited_ocr_v2_vision.py`: vision encoders.
- `unlimited_ocr_v2_preprocess.py`: page resize, crop grid and tiling on Metal.
- Decode speed: quantized MoE layers sort (token, expert) pairs at every batch size (mlx-lm sorts only from 64 pairs), so `gather_qmm` reads each touched expert once. Prefill DASH attention runs SDPA in fp16, about 3x faster than fp32 on M5; fp16 keeps the router bias 8x finer than bf16. On the 8-bit model this cut the 8-document MPDocBench smoke run from 337 s to 296 s (162.6 to 185.2 tok/s) at the same score.

**Runner and backend wiring** (only taken for Unlimited-OCR v2)
- `uocr_v2_runner.py` (new): `MlxUocrV2ModelRunner(MlxModelRunner)`. It keeps one DASH cache per request and merges the image features into prefill. The page guard and n-gram processor run inside the decode graph, so decode steps keep chaining.
- `tp_worker.py`: picks the runner when `is_unlimited_ocr_v2`. Skips the CPU custom-logits hook when the runner handles the processors itself. Builds the scheduler's `UocrSchedulerRuntime` (`create_uocr_runtime`).
- `scheduler_mixin.py`: a batch with a custom processor chains when the runner handles it. Calls `uocr_runtime.after_forward` in the MLX overlap loop, at the same point as `Scheduler.run_batch`.
- `model_runner.py`: `supports_native_custom_logit_processor()` returns False on the base runner.
- `scheduler.py`: `maybe_init_uocr_runtime` delegates to the MLX worker on MLX (6 lines).

**Document windows** (`uocr_v2_doc_reuse.py`, new)
- `MlxDocReuse(DocReuse)` copies a finished window's tail rows out of its MLX cache and seeds the follow-up's cache with them. The overlap text is spliced in after prefill.
- `document_reuse.py` gains small override hooks: `_committed_len`, `_keep_tails`, `_reusable`, `_covers`, plus `backend_for`, which moves here from `scheduler_runtime._v2_backend`. Their defaults keep the CUDA path as it was. `_page_base` becomes `page_base`.
- `scheduler_runtime.py`: takes `doc_reuse_cls`, default `DocReuse`.

**Shared paths**
- `cuda_graph_hook.py`: skips the Unlimited-OCR v2 decode-graph default on MLX. The MLX runner never captures CUDA graphs, so `--disable-cuda-graph` is not needed and the "decode CUDA graphs are opt-in" warning no longer prints on a Mac.
- `model_overrides/unlimited_ocr_v2.py`: on MLX, `page_size` and `attention_backend` are not pinned. The radix cache is still disabled and the same serving modes are rejected.
- `multimodal/processors/unlimited_ocr_v2.py`: on MLX, pages go out as raw `uint8` and are encoded in the tokenizer process on one vision thread. The features ship as `precomputed_embeddings`, so a window's vision encode does not stall the scheduler's decode. The scheduler encodes as a fallback.
- `layers/quantization/mlx.py`, `choices.py`, `quantization/__init__.py`: add an `mlx_q6` preset so 6-bit mlx-community repos load. Before this, they failed with "Unknown quantization method". This affects every MLX model.
- `managers/mm_utils.py`: `ShmPointerMMData` reads exactly its payload. macOS rounds shared memory up to a page, so the old code read past the payload.

**Docs**: an Apple Metal section (including a concurrency note: throughput stops growing at about 8 concurrent documents on a 16 GB M5), and a Mac option for each of the four checkpoints in the Unlimited-OCR-2 cookbook.

No new environment variables or server arguments, apart from the `mlx_q6` choice.

## How to reproduce

```bash
SGLANG_USE_MLX=1 python -m sglang.launch_server \
  --model-path mlx-community/Unlimited-OCR-2-8bit \
  --chat-template unlimited-ocr \
  --enable-custom-logit-processor \
  --uocr-doc-split \
  --enable-streaming-session \
  --uocr-max-page-tokens 8000 \
  --host 127.0.0.1 --port 30000
```

The request is the one in the cookbook: `"<PAGE><image>" * pages + "Multi page parsing."`, with `temperature=0` and `skip_special_tokens=false`. The accuracy runs also send the n-gram processor `DeepseekOCRNoRepeatNGramLogitProcessor` as `custom_logit_processor` (`ngram_size=35`, `window_size=128` for one page and 1024 for several pages), which is why the command has `--enable-custom-logit-processor`. Without that processor the flag is not needed: the built-in page guard runs on its own.

## Speed Tests and Profiling

Environment as above. One request at a time after the server's startup warm-up, temperature 0. TTFT and total are measured on the client from a streamed `/v1/chat/completions` request. Input is real document pages, 1 page in gundam mode and 3 pages in base mode.

All rows use `--uocr-doc-split`. `tok/s` is output tokens after the first one divided by the time after TTFT: `(out tok - 1) / (total - TTFT)`, so it includes the prefill of later windows.

| Weights | 1 page: TTFT | total | out tok | tok/s | 3 pages: TTFT | total | out tok | tok/s |
|---|---|---|---|---|---|---|---|---|
| BF16 | 3.10 s | 11.8 s | 647 | 75 | 0.98 s | 27.5 s | 2073 | 78 |
| 8-bit | 1.32 s | 6.6 s | 647 | 122 | 0.41 s | 17.2 s | 2041 | 122 |
| 6-bit | 0.88 s | 5.6 s | 647 | 136 | 0.43 s | 15.5 s | 2056 | 136 |
| 4-bit | 0.97 s | 4.9 s | 646 | 163 | 0.42 s | 13.6 s | 2074 | 157 |

Full MPDocBench runs (the accuracy runs above, 420 documents, concurrency 8):

| Weights | Wall | Output tokens | tok/s |
|---|---|---|---|
| BF16 | 6.4 h (395 documents, resumed run) | 2,640,970 (all 420) | 115 |
| 8-bit | 3.2 h | 2,618,435 | 227 |
| 6-bit | 3.7 h | 2,622,796 | 196 |
| 4-bit | 2.7 h | 2,622,985 | 266 |

BF16 on 16 GB is memory-bound: the KV budget filled up (requests were retracted) and the system swapped, so fewer requests ran at once. The quantized runs peaked at about 40% of the KV budget.

## Notes for reviewers

- **Generic MLX multimodal input.** The runner merges image embeddings inside `MlxUocrV2ModelRunner`; the generic runner's interface is unchanged. Happy to lift this into `MlxModelRunner` in a follow-up if you prefer.
- **Known follow-ups.**
  - `MlxUocrV2ModelRunner.__init__` does not call `super().__init__`: the base sets up a shared KV pool and `mlx_lm` loading this model does not use.
  - Some SAM/CLIP position tables are built with torch interpolation at load time.
  - The tokenizer-side vision tower is not counted in the MLX token budget.
- On a 16 GB machine the runner caps the MLX buffer cache at 1 GB unless `SGLANG_MLX_CACHE_LIMIT_GB` is set.
