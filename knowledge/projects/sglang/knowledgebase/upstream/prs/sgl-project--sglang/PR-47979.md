# [Fix] disaggregation: Protect non-final KV sends from checkpoint deduplication

[Upstream PR](https://github.com/sgl-project/sglang/pull/47979) · state: closed · merged: False

## Original PR description

## Motivation

During chunked prefill with a shared sliding-window cache, a checkpoint can stop at an SWA branch while the KV sender advances to the computed end. If another request caches the same remaining prefix, the next checkpoint can deduplicate and free pages that the transfer is still reading.

## Modifications

Cap non-final sends at `cache_protected_len` before page and staging-grid alignment, when prefix sharing and request insertion are enabled. The shared `clamp_kv_send_end` helper also lets alternate send implementations apply the same ownership boundary before mapping their transfer layouts. Checkpoints keep running to reclaim SWA memory, and the final send carries any remainder.

Add CPU regressions using the real Python and Rust cache backends: sibling-prefix deduplication must preserve in-flight pages, and a long branched request must keep releasing SWA slots. Also cover explicit send limits, decode prefixes, disabled sharing, skipped insertion, final sends, and staging alignment. Update the host-index and MiniMax transfer test fixtures with cache ownership state.

## Accuracy Tests

- On baseline `251eb36da0`, the sibling-prefix regression reproduces eight in-flight pages freed by the next checkpoint in both cache backends.
- With this change, the new regression and existing prefill result-polling, transfer-packing, KV-checksum, prefill abort-cleanup, and MiniMax cache-transfer tests pass: **98 tests and 81 subtests**.
- Pre-commit checks pass on all changed files.

GPU/RDMA end-to-end serving and model accuracy evaluations were not run. The CPU regression uses real cache ownership and allocation with controlled transfer completion.

## Speed Tests and Profiling

Not run. A suffix beyond the protected prefix can be transferred on a later chunk; the final send remains unrestricted.
