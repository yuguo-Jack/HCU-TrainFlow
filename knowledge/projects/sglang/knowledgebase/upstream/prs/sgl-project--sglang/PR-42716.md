# [HiCache] Serve host-tier prefix hits for DeepSeek-V4 with encoder SWA bounded replay

[Upstream PR](https://github.com/sgl-project/sglang/pull/42716) · state: open · merged: False

## Original PR description

## Motivation

DeepSeek-V4.1 with DSpark and `--enable-encoder-swa-bounded-replay` keeps the target's SWA state in a per-request window (`DeepSeekV4TokenToKVPool.request_window`). Replay rebuilds that window on admission. The paged SWA allocator remains, because the DSpark draft layers use it, so the unified radix tree still has an SWA component. `SWAComponent.create_match_validator` and the Rust tree core's validator skip the SWA gate only for the per-request SWA ring (`is_swa_req_ring`). Other layouts require device SWA state, or host SWA state for host-inclusive matching. With HiCache on and no SWA host pool, every host-only node fails that check. `host_hit_length` stays 0 and `load_back` never runs: the host tier fills up but never serves a hit. Device nodes whose SWA was evicted are rejected the same way, although replay rebuilds the window in both cases.

Measured on DeepSeek-V4.1-Flash, TP4 on 4x RTX PRO 6000 Blackwell (SM120), DSpark, encoder SWA replay, HiCache ratio 2: send a 54K-token prompt, then about 2.74M tokens of unrelated prompts to evict it from the 2.64M-token device pool, then the same prompt again. I measured this with an earlier revision of this fix, on an older upstream base; this exact diff was not benchmarked.

| | host-hit tokens | TTFT after eviction (cold) |
|---|---|---|
| before | 0 | 4.98 s (7.43 s) |
| after | 53,760 | 0.72 s (7.30 s) |

Both runs recovered the passkey from the prompt.

#42446 changes the same Python gate for HiCache without an SWA host pool. This PR also covers the Rust tree core and request windows with HiCache off, and keeps the SWA match gate for paged allocators without a request window.

## Modifications

- `swa_kept_out_of_tree(allocator)` in `mem_cache/allocator/swa.py` returns true for the per-request SWA ring and for an SWA allocator whose KV pool has a non-`None` `request_window`.
- The Python validator uses it, and `RustUnifiedTreeCore` passes it to the Rust core's existing `swa_req_ring` gate flag. No Rust change.
- `test_rust_tree_core_integration.py`, parameterized over both tree cores with stand-in request windows:
  - `test_swa_match_ignores_tombstones_with_a_request_window`, with and without HiCache: an SWA tombstone no longer truncates the reusable device prefix.
  - `test_swa_host_only_prefix_matches_with_a_request_window`: a backed-up prefix demoted to host, with no SWA host pool, is a host hit (`host_hit_length == 8`) with a request window and still a miss with paged SWA.
  - All request-window cases pass with this change.

Note for reviewers: without an SWA host pool, host load-back does not restore the DSpark draft's paged SWA history. Encoder replay rebuilds the target window; ordinary prefill injects draft state for uncached tokens. Whether the missing draft history lowers initial acceptance is unmeasured. Draft tokens are verified against the target logits.
