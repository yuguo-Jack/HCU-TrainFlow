# [Feat] lora: serve DeepSeek-V4/V4.1 attention and shared-expert adapters

[Upstream PR](https://github.com/sgl-project/sglang/pull/45231) · state: closed · merged: True

## Original PR description

## Summary
Serve LoRA adapters on DeepSeek-V4 / V4.1's attention projections, including the grouped `wo_a`, and on the shared expert. The grouped `wo_a` semantics and the `wq_b` disambiguation follow #36579 / #36578 (both open against `main`), rewritten for current sglang-miles and V4.1.

## Changes
- `lora/utils.py`: `wq_a` / `wkv` (replicated), `wq_b` / `wo_a` / `wo_b` (attention-TP; `wo_b` row-parallel) are known LoRA targets. A `wq_b` under another parent (`attn.wq_b`) is the attention's own projection; a bare `wq_b` keeps meaning the DSA indexer's, as before.
- `lora/layers.py`, `lora/backend/triton_backend.py`: `wo_a` multiplies each head group by its own row block of the weight, so `apply_grouped_lora` does too: one `A` for every group, `B` split by group (`delta_g = B_g @ A @ x_g`). The triton backend routes the group-major rows with grouped segments. Backends declare `supports_grouped_lora` and the model lists `grouped_lora_modules`, so a `wo_a` adapter on another backend fails in `init_lora_modules` at startup, not on the first request.
- `lora/mem_pool.py`: no 4D expert buffers for experts a model keeps out of LoRA (`should_apply_lora`); they are never wrapped.
- `models/deepseek_v4.py`:
  - `should_apply_lora` wraps only the five attention projections and the shared expert: the indexer, compressor and engram reuse the leaves `wq_b` / `wkv`, and routed experts are not adapted.
  - `get_lora_target_module_name` maps the shared expert's `w1` / `w3` / `w2` to `gate_proj` / `up_proj` / `down_proj`; `get_hidden_dim` sizes every target (all layers are MoE, so `gate_up_proj` / `down_proj` are the shared expert's).
  - Under LoRA, `wq_a` / `wkv` stay unfused, and `wo_a` takes no fused inverse RoPE, which would leave the adapter without its input. A LoRA-wrapped `wq_b` is checked with `isinstance(..., BaseLayerWithLoRA)` and takes the unquantized normalized row on every platform; `wo_b`'s `use_decode_attn_tp` reads through the wrapper. With an adapter on `wo_a`, `wo_a` emits unquantized bf16 (no fused MXFP8 quant, no gfx950 fp8-grid / MXFP8 epilogue), so the delta joins before `wo_b` quantizes its input; this path is not exercised on H200.
  - Under attention DP without an MoE all-to-all, the layer gathers the MLP input rows from every attention-DP rank; the MLP and the TBO MoE op now run under `LoRABatchLayout.TP_GLOBAL`, as deepseek_v2 and the layer-boundary path do (#36389). Before, the shared-expert adapter applied the local rank's batch info to the gathered rows.
- The vision-aware routing capture fix that briefly rode here is in #46671.

## Validation
radixark/miles#4205 (native LoRA), DeepSeek-V4.1 4-layer slice, 8×H200, colocated, TP4/EP8 trainer, one TP8 engine, R3, lr 2e-3, 5 rollouts:
- adapter served: `train/train_rollout_logprob_abs_diff` 0.0571 / 0.0529 / 0.0011 / 0.0010 / 0.0006 (the slice collapses to near-deterministic output from rollout 2; rollout log-probs match the trainer's to 1e-4)
- same run with the adapter not served (`--lora-train-only`): 0.0575 / 1.05 / 0.92 / 2.70 / 5.23
- 64 adapter tensors per sync with `--check-lora-weight-equal`, no mismatch
- the step-0 gap is the same with and without LoRA serving, so the unfused paths leave the base unchanged

Attention DP, same slice and settings, one TP8 engine with `--sglang-attn-dp-size 8` and `--rm-type deterministic_random`; A′ is D2's code without attention DP. `train/train_rollout_logprob_abs_diff`:

| rollout | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| D1, attention DP, before the layout fix | 0.0566 | 0.1266 | 0.1383 | 0.1355 | 0.3824 |
| D2, attention DP, with it | 0.0567 | 0.0549 | 0.0154 | 0.0169 | 0.0063 |
| A′, no attention DP, D2's code | 0.0573 | 0.0527 | 0.0277 | 0.0045 | 0.0208 |

D1 leaves the others from rollout 1; D2 stays at A′'s level. These three runs also carry a cherry-pick of the engram hasher's idle-batch handling (7e74b31b26, not in this PR): under attention DP an idle rank otherwise hits the hasher's forward-mode assert.

Full 40-layer DeepSeek-V4.1-Flash through radixark/miles#4205, 2×8 H200, colocated, official FP8 checkpoint (FP8 dense, MXFP4 routed experts) on two TP8 engines with `--language-model-only`, decode CUDA graphs on (bs up to 64), adapters on all five attention projections (grouped `wo_a` included) and the shared expert, DAPO-Math-17k, 100 rollouts at lr 5e-5: `train_rollout_logprob_abs_diff` 0.020–0.032 with no trend as the adapter grows (mean 0.026), `rollout/raw_reward` 0.745 over rollouts 0–19 and 0.856 over 80–99.

Not executed: the full model under attention DP with the layout fix; context-parallel decode with LoRA (rejected at startup: `--enable-cp-decode-attn-tp` slices the raw attention linears, not the LoRA wrapper or its A/B); the Blackwell / gfx950 `wo_a` fast paths with an adapter.
