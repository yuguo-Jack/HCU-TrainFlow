# [diffusion] BCG: warn instead of disabling on unvalidated models

[Upstream PR](https://github.com/sgl-project/sglang/pull/43568) · state: closed · merged: True

## Original PR description

## Motivation

`--enable-breakable-cuda-graph` is checked against a model list and a pipeline-config list. Those lists record which checkpoints were *validated*, not which ones can capture, but an explicit request on any other model was silently switched off. FLUX.2-dev, for example, captures fine through the generic denoising stage, and the user simply never got BCG.

The list cannot be dropped outright, though. Some pipelines have their own denoising stage that never calls the BCG runner (e.g. `Cosmos3DenoisingStage`). For those, an enabled flag would claim BCG while the server runs eager. That is how an earlier "BCG == eager, bit-exact" parity check on Cosmos3 turned out to compare eager with eager.

## Modifications

- `server_args`: off the validated lists, BCG stays enabled with a warning that names the model and the validated set (it used to disable). The default warmup resolution is seeded in both cases.
- `breakable_cuda_graph/runner.py`: `BaseBreakableCudaGraphRunner.num_captures` counts graphs captured in this process (a class attribute; scheduler and workers share the process).
- `server_warmup.py`: BCG captures during the startup warmup. After the first successful warmup batch, if BCG was requested and nothing was captured, the scheduler warns once that the model runs eager (its denoising stage does not capture, or capture was rejected).
- `api/cli.mdx`: documents both warnings.

## Accuracy Tests

GB300, `sglang generate`, eager vs `--enable-breakable-cuda-graph`, same seed:

| Model | BCG log | Output vs eager |
|---|---|---|
| FLUX.1-dev TP2 (validated) | `captured 58 segment(s)` x2 ranks, no warning | max_abs 0 |
| FLUX.2-dev TP2 (**not** validated; disabled before this PR) | `not validated for Flux2PipelineConfig` + `captured 57 segment(s)` x2 ranks | max_abs 0 |
| Cosmos3-Nano T2I, CFG-parallel 2 GPUs (own denoising stage) | `not validated for Cosmos3Config` + `warmup captured no breakable CUDA graphs` | max_abs 0 (eager both ways) |

## Speed Tests and Profiling

No change for validated models. On the GB300 runs above, BCG on FLUX.1-dev TP2 served at 1.88 s vs 6.4 s eager (host-bound at 1024², 50 steps).
