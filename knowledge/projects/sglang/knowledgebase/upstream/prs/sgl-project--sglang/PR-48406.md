# [Perf] [AMD] qwen3: Let the fused QK-norm + RoPE + KV write serve the vectorized_5d layout

[Upstream PR](https://github.com/sgl-project/sglang/pull/48406) · state: open · merged: False

## Original PR description

## Motivation

Qwen3's decode path fuses QK-norm, RoPE and the KV-cache write into one aiter kernel (#44267), but only for the NHD layout: with the `vectorized_5d` KV-cache layout (`SGLANG_AITER_KV_CACHE_LAYOUT=vectorized_5d`) it falls back to the unfused path. The kernel already writes aiter's shuffle layout, which `vectorized_5d` is, when it is given `use_shuffle_layout` and the cache's `block_size` and `x`.

## Modifications

- `python/sglang/srt/models/qwen3.py`: `aiter_fused_qk_norm_rope_set_kv` passes a 5D cache as it is, with `use_shuffle_layout=True` and the cache's `block_size` and `x`; an NHD cache is passed as before. `Qwen3Attention` takes the fused path for either layout, in the activation dtype or fp8.
- `test/registered/amd/test_qwen3_aiter_fused_qk_norm_rope.py`: checks the 5D write, bf16 and fp8, for RoPE and mRoPE, reading the cache back through `gather_shuffle_5d_to_linear`.

## Accuracy Tests

GSM8K, all 1319 questions (`python -m sglang.test.few_shot_gsm8k --num-questions 1319 --parallel 128`), one MI355X (gfx950), TP 1, `SGLANG_USE_AITER=1 SGLANG_AITER_KV_CACHE_LAYOUT=vectorized_5d`:

|---|---|---:|---:|
| Qwen/Qwen3-8B | bf16 | 0.903 | 0.901 |

`test_qwen3_aiter_fused_qk_norm_rope.py` passes on main and, with the new 5D cases, on this branch, on the same image.
