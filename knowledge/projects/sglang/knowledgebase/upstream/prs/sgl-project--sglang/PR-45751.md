# [Feat] moe: Integrate EvenMoE and retire native Waterfill/LPLB

[Upstream PR](https://github.com/sgl-project/sglang/pull/45751) · state: open · merged: False

## Original PR description

## Motivation

[EvenMoE](https://github.com/ai-dynamo/evenmoe) (formerly "MoE Load Balancer", now open-sourced under ai-dynamo, Apache-2.0) is a framework-neutral MoE load balancer: L1 expert placement (DeepSeek EPLB variants, UltraEP) and L2 replica routing for redundant experts (static, LPLB, Waterfill, UltraEP, and compositions such as `lplb+waterfill`). The algorithms live in that package; SGLang only needs a thin, opt-in integration so EP deployments can pick an algorithm with one flag:

```bash
python -m sglang.launch_server --model-path deepseek-ai/DeepSeek-V3 \
  --tp 8 --dp 8 --ep 8 --enable-dp-attention --moe-a2a-backend deepep --deepep-mode auto \
  --init-expert-location /path/to/logical_count.pt --ep-num-redundant-experts 32 --eplb-algorithm auto \
  --moe-load-balancer-algorithm lplb+waterfill      # or static | lplb | waterfill | ultraep | ultraep+waterfill
```

Design rule: SGLang stays the authority over the committed expert placement, the weight moves and the collectives; EvenMoE plans placements and chooses physical replicas for the router's logical TopK (precision-neutral: the logical experts never change). `--moe-load-balancer-algorithm` is strictly opt-in — without it nothing changes and `evenmoe` is never imported (verified by running the unit suites with `evenmoe` hidden).

The `sglang-moe-lb-waterfill-dev` fork has carried this integration since July; this PR rebases it on current `main` (post #44913 / #44994 TopK refactors) and upstreams it.

## Dependency

No new dependency. `evenmoe` is **not** added to `pyproject.toml`; every import of it is lazy and sits behind `--moe-load-balancer-algorithm` (11 sites, all inside functions that only run when the flag is set). The native EPLB stack is left as is and does not depend on EvenMoE: `--enable-eplb`, `eplb_algorithms/`, `--ep-dispatch-algorithm {static,dynamic,fake,lp}`, `lplb_solver.py` and `--enable-waterfill` are untouched and remain the default. Verified by running the `unit/eplb`, `unit/server_args` and `unit/layers/moe` suites with `sys.modules["evenmoe"] = None` (398 passed / 13 skipped) and by the native-path e2e row below. Setting the flag without the package raises `ImportError: --moe-load-balancer-algorithm requires the evenmoe package`.

## Modifications

- `arg_groups`: `--moe-load-balancer-algorithm` (resolvable; appended at the end of `POSITIONAL_FIELD_ORDER`), `handle_moe_load_balancer` (validates the pipeline, rejects combining with `--ep-dispatch-algorithm` / `--enable-waterfill`, coupled-placement constraints), fusion override when the pipeline routes the shared expert, DeepEP requirement.
- `eplb/moe_load_balancer_glue.py` (new): pipeline parsing, TopK output → routing request → `StandardTopKOutput`, stage from `ForwardContext.forward_mode` (new field populated from the active batch).
- `TopK` / `HashTopK`: when the pipeline routes after top-k, `select_experts` takes the pipeline's input transform and defers recording; `_apply_moe_load_balancer` replaces `_apply_waterfill` at the end of every backend path; EvenMoE records the physical ids for EPLB statistics and routed-experts capture. Draft layers keep the native path. NPU `fused_topk_npu` threads `defer_expert_recording` through `_finalize_topk_npu`.
- `SharedExpertsConfig.routed_by_load_balancer`: the router emits routed experts only when EvenMoE appends the fused shared-expert slot (same mechanism as `use_waterfill`).
- `ExpertLocationMetadata.init_by_eplb` / `EPLBManager`: plan placement through EvenMoE when selected, publish per-layer routing metadata, commit after the weight move (`commit_placement`), coupled per-layer refresh (UltraEP) via `ExpertLocationUpdater.update_layer`.
- Expert distribution recorder: gatherer for `--deepep-mode auto`, exclude the fused shared slot from DeepEP local counts, per-source-rank statistics when placement is coupled.
- `ModelRunner`: builds the shared `MoELoadBalancer` from the runtime context and attaches it to every target TopK before the first forward.
- Docs: `server_arguments.mdx` row. Tests: `test/registered/unit/eplb/test_evenmoe_*.py` (skip without `evenmoe`), `test_deepep_auto_distribution_gatherer.py`, server-args cases including "no flag ⇒ no import" and "flag without package ⇒ clear ImportError"; manual two-rank pipeline smoke under `test/manual/ep/`.

## Accuracy Tests

8×H20, DeepSeek-V3 FP8, TP8/EP8/DP8 attention, DeepEP `auto`, CUDA graph on (except UltraEP), this branch + EvenMoE `main`. Teacher-forced NLL on GSM8K answer tails (13,252 tokens; the fused-shared-expert bug fixed in #44901 shows up as 0.86 here) and `sglang.test.few_shot_gsm8k` on all 1319 questions:

| `--moe-load-balancer-algorithm` | redundant experts | NLL / token | GSM8K | decode TPOT @64 (ms) |
|---|---:|---:|---:|---:|
| *(none, native path)* | 0 | 0.7019 | 0.941 | 54.7 |
| `static` | 32 | 0.7038 | 0.935 | 56.7 |
| `lplb+waterfill` | 32 | 0.7056 | 0.938 / 0.942 | 83.4 |
| `ultraep` (`--enable-eplb`, online per-layer re-placement, no CUDA graph) | 32 | 0.7061 | 0.939 | 170.0 |

GSM8K noise band on this setup is 0.933–0.942; no `Traceback` in any server log. CPU unit suites (`unit/eplb`, `unit/server_args`, `unit/layers/moe/test_topk_*`, `test_fused_shared_expert_scaling`): 427 passed with `evenmoe`, 398 passed / 13 skipped with `evenmoe` hidden.

## Speed Tests and Profiling

No change on the native path (the flag is off by default). EvenMoE prefill numbers on DeepSeek-V3 EP8 are in the [EvenMoE README](https://github.com/ai-dynamo/evenmoe#performance) (EPLB + Waterfill + LPLB vs. plain EP: +13–15 % input throughput on GSM8K/MMLU).
