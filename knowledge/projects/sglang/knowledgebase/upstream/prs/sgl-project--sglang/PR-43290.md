# [Scheduler] Hold back decode rows on a mixed step when they do not fit the KV pool

[Upstream PR](https://github.com/sgl-project/sglang/pull/43290) · state: closed · merged: True

## Original PR description

## Motivation

With `--enable-mixed-chunk`, a mixed step can run the running decode rows out of the KV pool and kill the server.

- The mixed-chunk branch at the end of `Scheduler._get_new_batch_prefill_raw` calls `prepare_for_decode` and `mix_with_running` on the running rows. It does not run the decode KV check (`check_decode_mem`) that a decode step runs in `update_running_batch`.
- When the prefill admitted in the same step fills the pool, `alloc_for_decode` fails with `RuntimeError: Out of memory` and the scheduler dies.
- Reproduced on `main` with a small hybrid SWA pool (gpt-oss-20b, `max_total_tokens=4096`, `swa_full_tokens_ratio=0.1`, `chunked_prefill_size=64`): `_get_new_batch_prefill_raw` -> `prepare_for_decode` -> `alloc_for_decode` -> `alloc_token_slots` raises.

## Modifications

- `Scheduler._get_new_batch_prefill_raw`: before mixing, check that the decode rows fit with `running_batch.check_decode_mem()`.
- **Behavior change, only under KV pressure on a mixed step:** when the decode rows do not fit, they are not mixed in. They sit out this step, which runs extend-only, and they decode on the next decode step, which fits them the same way as without mixed chunk (retracting if needed).
- When the rows fit, the mixed step is unchanged. A mixed step still never retracts running rows for the prefill it has just admitted, and it does not change the new token ratio.
- `check_decode_mem` may evict reclaimable radix-cache entries to make room, as it does on a decode step.
- `test/registered/chunked_prefill/test_scripted_swa_1gpu.py`: add `TestScriptedSwaMixedChunkDecodeFit`. It runs decoders next to chunked prefills on the same small SWA pool with mixed chunk on. Every request must finish, and at least one step must run a prefill while running decode rows sit out. `est_time` is raised to cover the second server launch.

## Checks

All on H200.

- `TestScriptedSwaMixedChunkDecodeFit` on `main`: the server died with the OOM above in 2 of 3 runs; 1 run passed.
- The existing `TestScriptedSwaChunkedReqEarlyReturn` with `enable_mixed_chunk=True` (local variant, not committed) on `main`: the server died with the same OOM in 1 of 1 run.
- With this PR:
  - `test/registered/chunked_prefill/test_scripted_swa_1gpu.py`: 2 passed. `TestScriptedSwaMixedChunkDecodeFit` passed in 3 of 3 runs.
  - The mixed-chunk variant of `TestScriptedSwaChunkedReqEarlyReturn`: passed.
  - `test/registered/scheduler/test_mixed_chunked_prefill.py`: 2 passed.
  - `test/registered/spec/test_spec_mixed_chunk.py -k Eagle3`: 5 passed. The DFlash and DSpark classes were not run (no weights on the test machine).
  - `test/registered/scripted_runtime/test_scripted_runtime_core.py` and `test/registered/chunked_prefill/test_scripted_core_1gpu.py`: 49 passed.
