# [Fix] qwen3_next: dequantize GGUF weight for shared embedding/head

[Upstream PR](https://github.com/sgl-project/sglang/pull/45081) · state: open · merged: False

## Original PR description

## Motivation

GGUF-quantized `embed_tokens` / `lm_head` modules keep the packed `qweight` and expose no `.weight`. When a GGUF target is paired with a draft model, speculative decoding hands the target embedding and output head to the draft through `Qwen3NextForCausalLM.get_embed` / `get_embed_and_head` (used by EAGLE3 / NEXTN workers). Those getters dereferenced `.weight`, so with a GGUF target they raised `AttributeError` and the draft could not start.

## Modifications

- Add `get_gguf_dequantized_weight(module, dtype)` to `python/sglang/srt/layers/quantization/gguf.py`: returns `.weight` as-is for an unquantized module, otherwise dequantizes the packed `qweight` once into `dtype` and caches the dense tensor on the module.
- Route `Qwen3NextForCausalLM.get_embed` and `get_embed_and_head` through the helper (local import, matching the existing gguf import sites in `qwen3_moe.py` / `deepseek_v4.py`). The unquantized path keeps its exact previous behaviour via the `hasattr(module, "weight")` short-circuit.
- Add a CPU-only unit test (`test/registered/unit/layers/quantization/test_gguf_shared_weight.py`) covering the dense pass-through, the dequantize call/args, the per-module cache, and the two getters.

## Accuracy Tests

- New unit test: 4 passed (CPU-only, no accelerator).
- A100 end-to-end (Qwen3-Next-80B-A3B Q4_K_M GGUF target + NEXTN MTP draft): the draft starts (previously failed with AttributeError), accept length ~ 3.2 / accept rate ~ 0.73; GSM8K-100 = 98.0 == non-speculative baseline (two A100 runs gave 97/98; the 1-question spread is MTP-on run-to-run nondeterminism, not caused by this change).

## Speed Tests and Profiling

Bug fix; no change to any kernel or forward path. Dequantization happens once per shared module and is cached, so there is no per-step overhead.

Checklist: isort / ruff / ruff-format clean; unit test added under test/registered/unit/; no docs change needed.
