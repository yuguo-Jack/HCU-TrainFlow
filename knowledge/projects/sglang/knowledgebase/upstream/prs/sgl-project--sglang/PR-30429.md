# feat: Clean up shared memory and CUDA host registrations in HostSharedMemoryManager on shutdown

[Upstream PR](https://github.com/sgl-project/sglang/pull/30429) · state: closed · merged: False

## Original PR description

## Motivation

Closes #30428.

When the SGLang inference server runs with parameter offloading enabled, it uses `HostSharedMemoryManager` to allocate shared memory blocks and registers them with CUDA. However, `HostSharedMemoryManager` lacks a teardown implementation, leaving CUDA host pointer registrations leaked and POSIX shared memory segments dangling in `/dev/shm` after the server terminates.

This PR implements the missing teardown lifecycle logic to ensure resources are cleanly reclaimed.

## Modifications

1. **`HostSharedMemoryManager` dispose logic**:
   - Implemented `dispose()` method in `HostSharedMemoryManager` inside `python/sglang/srt/utils/host_shared_memory.py`.
   - Iterates through allocated shared memory records to unregister them via `cudaHostUnregister` and close/unlink (`shm.unlink()` on rank 0) the shared memory segments.
   - Added global `dispose_host_shared_memory_manager()` helper.
2. **Teardown integration**:
   - Modified `release_host_resources()` in `Scheduler` inside `python/sglang/srt/managers/scheduler.py` to invoke `dispose_host_shared_memory_manager()`.
