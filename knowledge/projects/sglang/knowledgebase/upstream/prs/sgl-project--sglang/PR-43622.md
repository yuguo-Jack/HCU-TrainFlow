# [DSpark] Draft the eager markov block through `MarkovSampleStep`

[Upstream PR](https://github.com/sgl-project/sglang/pull/43622) · state: closed · merged: True

## Original PR description

Stacks on #43621.

- The eager draft runs `draft_markov_block`: per step the head gives its bias (`step_bias`), and the draft module adds it and picks the token with the op; the step logits land request-major in one `[bs, gamma, vocab]` buffer, which the sampling accept reads directly.
- A markov head now gives only facts: its bias, the dtype of its step add (`step_logits_dtype`), and where its TP vocab shard starts with the gather over its group (`vocab_shard`). Which gather a step uses and how wide the kept logits are is decided in the draft module.
- The draft noise key is derived from the server's random seed, so a seeded server drafts reproducibly per process.
- On a TP-sharded DeepSeek-V4 head, kept step logits are gathered inside the op, one gather per step; the separate per-step vocab gather after the block is gone.
- Removes the multinomial draft sampling and `SGLANG_DSPARK_FAST_SAMPLING` (registered as deprecated; draft sampling always uses Gumbel-max).

Behavior changes:
- Sampled draft tokens come from a different random stream (Philox instead of the torch generator). The draft distribution is the same.
- DeepSeek-V4 step logits are FP32 in every configuration (the add already ran in FP32 for the sharded head).

## Verification

- `test/registered/unit/spec/test_dspark_draft_block.py` (CPU) passes; GPU tests of the draft path run on the layers above.
- The draft proposal of the full stack on DeepSeek-V4.1, TP4 on GB300, is cheaper per decode step than main at temperature 0 and 1, concurrency 1 and 16 (sampling part -2% to -16%); TPOT, accept length and GSM8K match main.
