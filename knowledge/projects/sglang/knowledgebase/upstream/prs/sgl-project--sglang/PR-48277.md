# [Docs] Muse Spark Open cookbook: add TPU v7

[Upstream PR](https://github.com/sgl-project/sglang/pull/48277) · state: open · merged: False

## Original PR description

## Summary

Adds **TPU v7** to the Muse Spark Open cookbook. TPU v7 runs one host (4 chips, 8 TensorCores, `--tp-size 8`) serving the NVFP4 checkpoint with [SGLang-TorchTPU](https://github.com/sgl-project/sglang-torchtpu).

TPU v7 support is on the SGLang-TorchTPU branch [`haolin/ms-v11`](https://github.com/sgl-project/sglang-torchtpu/tree/haolin/ms-v11) and is not merged yet. The page says so wherever it introduces TPU v7.

**Deploy panel.** A TPU v7 entry with two general commands:
- **Low Latency** keeps DFlash, at 2 running requests.
- **High Throughput** runs 64 requests without speculative decoding.
- Both keep only what the server needs to run well on TPU v7: the decode megakernel over fp8 KV in the SEQ_ALONG_LANE layout (batched-RPA attention, 256-token pages), host-side prefill padding, and the compiled batch and prefill buckets.
- Low Latency serves the published draft, `RadixArk/Muse-Spark-Open-DFlash2`. On `haolin/ms-v11` the engine reads the draft's sliding windows from its own config, so no draft preparation step is needed.

**"TPU v7 deployment measured with SemiAnalysis InferenceX".** A hand-written section next to the MI355X one, with the AgentX deployment at concurrency 1, 7, 9, 10, 16 and 22.
- It is hand-written because the AgentX explorer above it is generated by the cookbook sync from public InferenceX data only, and this run is not public yet.
- The commands are the submission's server settings ([`agentx.py`](https://github.com/sgl-project/sglang-torchtpu/blob/haolin/ms-v11/benchmark/tpu/recipe/configs/muse_spark/agentx.py)), minus logging, diagnostics and telemetry settings and values equal to the engine defaults. Every performance setting stays: HiCache, sessions, intervals, adaptive verify, the megakernel and fused-RS settings, `LIBTPU_INIT_ARGS`.
- Concurrency 1 and 16 are shown in full, and 7, 9, 10 and 22 as exact changes.
- A check outside this repo reads the six commands back from the page, parses them with SGLang-TorchTPU's server arguments (defaults filled), fills in env defaults, and finds no differences from the submission's configuration.
- The commands serve the published draft, `RadixArk/Muse-Spark-Open-DFlash2`.
- The section also lists the image placeholder, the host memory, and the golden acceptance length used in the measurement, which is not part of the commands.

Only `MuseSparkOpen.mdx` and `muse-spark.jsx` change. The generated AgentX data and its component are untouched. The repo's config checker passes.

## Why this is a draft

1. **Public image.** The image is `<public sglang-torchtpu image: TBD>`. torch-tpu installs from a private package server, the image used so far is in a private registry, and Docker Hub has no current SGLang TPU image. Until one exists, the Deploy panel's Docker tab shows the placeholder, and its run flags are the generic GPU ones.
2. **Verification link.** The runs behind these settings are in a private InferenceX repository, and the public InferenceX data has no TPU rows for this model yet. The panel cells are marked "in progress" and the section has no run link until a public one exists.

Before leaving draft, also boot the commands as written on the public image. The Deploy panel's High Throughput settings have so far been run at an 8K context, not at the model's native context.

## 概要

在 Muse Spark Open cookbook 中加入 **TPU v7**：单机（4 芯片、8 个 TensorCore，`--tp-size 8`），以 [SGLang-TorchTPU](https://github.com/sgl-project/sglang-torchtpu) 运行 NVFP4 checkpoint。

TPU v7 支持位于 SGLang-TorchTPU 的 [`haolin/ms-v11`](https://github.com/sgl-project/sglang-torchtpu/tree/haolin/ms-v11) 分支，尚未合并；页面在每处介绍 TPU v7 的地方都注明了这一点。

**Deploy 面板。** 新增 TPU v7 条目，两条通用命令：
- **Low Latency** 以 2 个并发请求保留 DFlash。
- **High Throughput** 以 64 个请求运行，不使用投机解码。
- 两者只保留在 TPU v7 上高效运行所需的设置：fp8 SEQ_ALONG_LANE KV 布局上的 decode megakernel（batched-RPA attention、256-token 页）、主机侧 prefill padding，以及编译的 batch 与 prefill 桶。
- Low Latency 直接使用已发布的 draft `RadixArk/Muse-Spark-Open-DFlash2`；在 `haolin/ms-v11` 上，引擎从 draft 自身的配置读取滑动窗口，无需预处理 draft。

**“TPU v7 deployment measured with SemiAnalysis InferenceX”。** 在 MI355X 一节旁新增手写章节，给出并发 1、7、9、10、16、22 下的 AgentX 部署命令。
- 采用手写章节，是因为上方的 AgentX 浏览器由 cookbook 同步脚本只从公开的 InferenceX 数据生成，而这次运行尚未公开。
- 命令即提交时的服务器设置（`agentx.py`），仅去掉日志、诊断与遥测设置以及与引擎默认值相同的取值；所有性能设置均保留：HiCache、会话、间隔、自适应 verify、megakernel 与 fused-RS 设置、`LIBTPU_INIT_ARGS`。
- 并发 1 与 16 给出完整命令，7、9、10、22 给出确切的改动。
- 一个仓库外的检查脚本从页面读回这六条命令，用 SGLang-TorchTPU 的服务器参数解析（补全默认值），并补全环境变量默认值，与提交时的配置相比没有差异。
- 命令直接使用已发布的 draft `RadixArk/Muse-Spark-Open-DFlash2`。
- 章节还列出镜像占位符、主机内存，以及测量所用的 golden 接受长度（不属于这些命令）。

仅修改 `MuseSparkOpen.mdx` 和 `muse-spark.jsx`；生成的 AgentX 数据及其组件未改动；仓库的 config checker 通过。

## 为何是草稿

1. **公开镜像。** 镜像为 `<public sglang-torchtpu image: TBD>`：torch-tpu 从私有包服务器安装，目前使用的镜像位于私有仓库，Docker Hub 上也没有当前的 SGLang TPU 镜像。在公开镜像发布前，Deploy 面板的 Docker 标签页显示占位符，其运行参数为通用的 GPU 参数。
2. **验证链接。** 这些设置所依据的运行位于私有的 InferenceX 仓库，公开的 InferenceX 数据中尚无该模型的 TPU 结果。在有公开链接之前，面板单元格标记为“进行中”，章节也不附运行链接。
