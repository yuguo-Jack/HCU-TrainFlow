# [Feat] moe: B12x W4A16 E4M3 K/32 route with EP support for ModelOpt mixed checkpoints

[Upstream PR](https://github.com/sgl-project/sglang/pull/45298) · state: open · merged: False

## Original PR description

## Motivation

GLM-5.3-Flash ships as a ModelOpt MIXED_PRECISION checkpoint: NVFP4 W4A16 expert weights (E2M1, per-32-block E4M3 scales) with BF16 activations. On SM120 no serving path handled that combination: W4A16 layers fell through to the A4 activation-quant kernel route, and the K/32 scale cadence had no packed-weight preparation. This PR ports the SM12x W4A16 serving route onto the flashinfer_cutlass MoE runner with expert-parallel support, plus the serving-stack fixes the port surfaced.

Requires flashinfer #6824 (the E4M3 K/32 W4A16 route; unreleased at the time of writing — flashinfer lands first). Source-built flashinfer installs need a real CUTLASS tree: the JIT resolver now validates probe results and honors `$CUTLASS_HOME`.

## Modifications

- **moe_runner/flashinfer_cutlass**: new `w4a16_e4m3_k32` quant type dispatching to FlashInfer's `launch_sm120_moe` W4A16 arm. EP callers pass an explicit global-id `expert_map` instead of the silent rank-0 prefix fallback; EP>1 zeros the scatter output so the layer all-reduce sums clean partials; `precompile_w4a16_prefill_routes` warms the route pack for the model precompile hook.
- **modelopt_quant**: one-time load-time in-place preparation through FlashInfer's `reuse_input_storage` — the prepared layout overwrites checkpoint bytes, so no checkpoint-layout copy survives. Load-path fixes riding the route: `ModelOptMixedPrecisionConfig.from_config` now derives `is_w4a16` (the flag stayed False and W4A16_NVFP4 layers took the A4 kernel route), and `linear_fp8_config` for deepseek_weight_loader MLA requantization of mixed checkpoints.
- **models/glm5_next**: precompile hook warms the route-pack Triton modules across the seven prefill shape regimes (256..8192 tokens) before KV pools and CUDA graphs claim device memory; gated on the b12x W4A16 route being active.
- **attention**: enable flashinfer_sparse_mla for GLM-5.3-Next DSA on SM120 — arch-validator gate, kpool tail-token backend guard, and GLM NoPE candidate padding to flashinfer's 2,176-wide prefill contract.
- **kernels/jit**: CUTLASS probe results are validated against sentinel headers (a source-built flashinfer with no `data/cutlass` passed a non-empty include list with no real CUTLASS in it, and nvcc died on the first `cutlass/util` include); adds a `$CUTLASS_HOME` override, a tilelang vendored-tree probe, and a hard failure naming every probed path.
- **cuda_graph,dsa**: keep captured CUDA-graph state valid across `flush_cache` resets. `flush_cache` released pooled state while captured decode/verify CUDA graphs kept replaying through raw device pointers — the first verify after a reset (and the first decode after boot) read buffers the allocator had already recycled. Three coordinated fixes: capture-owner retention of graph-referenced scratch tensors, stale-reset-state clamps in the kpool chain, and a graph-liveness counter gating the serving-reachable `empty_cache` sites (scheduler `flush_cache`/`continue_generation`, IdleSleeper). A hardening batch rides with it: the remaining serving-reachable `empty_cache` sites are gated (elastic-drop, runner pool measure, hot-reload set_embed sites; LoRA resize refuses while graphs are live), liveness bookkeeping is idempotent, `SGLANG_DSA_GRAPH_BUFFER_LIFETIME` is wired through environ, and the W4A16 route hardens its quant-config handling (per-algo group-size scan that raises on disagreement, loud asserts for bf16 activations and divisible EP splits, shared gate/up scale guard).

## Accuracy Tests

- New unit tests: `test_dsa_capture_owner_cuda.py`, `test_dsa_logits_gate_owner_cuda.py` (kernels/ops/attention), `test_dsa_capture_owner.py`, `test_dsa_graph_buffer_lifetime.py` (layers/attention).
- Stability on the served stack (GLM-5.3-Flash W4A16 TP2-EP2, 2× RTX PRO 6000): with the flush-path `empty_cache` active in graph mode the stack crashed 7/7 on the reset trigger; with the graph-liveness gate it survives the same trigger and a post-fix stress loop passes 8/8 with the gate engaging on every flush and no illegal-memory-access exits.
- The flashinfer companion (#6824) adds a positive numeric GPU test comparing the E4M3 K/32 wrapper arm against the bf16 reference.

## Speed Tests and Profiling

Decode steps/s, same model and host (2× RTX PRO 6000, PCIe, C4 prompts, 8k/64k/250k, medians):

| config | 8k | 64k | 250k |
|---|---:|---:|---:|
| EP2 route, window 1 | 39.30 | 35.04 | 39.61 |
| EP2 route, window 2 | 39.05 | 38.98 | 38.99 |
| routed experts (no EP), record | 45.3 | 41.7 | 42.7 |

EP2 decode trades 6.5–13.8% vs the routed-experts record (window-dependent; both windows disclosed; the ~15% same-boot C4 swing floor bounds the comparison). Prefill is a wash at 64k/250k (C4 ttft_med ≈ 54 s in all measurements) and faster at 8k (1.81 s vs 4.93 s).
