# [Perf] [AMD] mimo-v2.6: Fuse small-M QKV projection on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/44271) · state: open · merged: False

## Original PR description

## Motivation

MiMo-V2.6-Pro-RL TP8 decode spends about 2.1 ms/step in the block-FP8 fused QKV projection (`M<=16, N=3392, K=6144`). The existing gfx950 path launches per-1x128 activation quantization followed by an untuned CK blockscale GEMM.

Tracks [SILOTIGER-1248](https://amd.atlassian.net/browse/SILOTIGER-1248).

## Changes

- Add a gfx950 small-M HIP kernel specialized for MiMo TP8.
- Fuse BF16 per-1x128 activation quantization with the block-FP8 GEMM.
- Consume AITER's existing `(16,16)`-preshuffled weight and FP32 128x128 scales.
- Accumulate scaled `16x16x128` MFMAs in FP32 and emit BF16 QKV.
- Add guarded dispatch behind `SGLANG_ROCM_MIMO_FUSED_QKV=1`.
- Fall back unchanged for every other shape, dtype, bias, or batch size.

This PR is independent of the RoPE/KV-cache fusion PR.

## Correctness

- M = 1, 2, 4, 8, 16 versus AITER CK.
- Cosine approximately 1.0; maximum absolute difference 0.007812 at M=16.
- CUDA graph replay matches eager execution.
- Registered MI35X GPU tests: 3 tests and 5 parameterized subtests.
- MiMo GSM8K exact match: 0.98.

MiMo's native MXFP4 layout correctness fix is tracked separately by #41573.

## Performance

8x MI355X, TP8/EP8, no speculative decoding:

| Workload | Baseline output tok/s | Fused QKV output tok/s | Change | Mean ITL change |
|---|---:|---:|---:|---:|
| 60k/c16 | 282.60 | 291.53 | +3.16% | -1.446 ms |
| 128k/c4 | 141.87 | 149.72 | +5.54% | -1.234 ms |
