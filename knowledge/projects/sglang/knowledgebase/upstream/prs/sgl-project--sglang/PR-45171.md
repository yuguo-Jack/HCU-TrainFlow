# [Fix] benchmark/mmmu: Forward extra request body through the SDK

[Upstream PR](https://github.com/sgl-project/sglang/pull/45171) · state: open · merged: False

## Original PR description

## Motivation

MMMU evaluation fails before sending a request when `--extra-request-body` contains SGLang extensions, for example:

```text
--extra-request-body '{"top_k":5,"min_p":0.1,"ignore_eos":true}'
TypeError: AsyncCompletions.create() got an unexpected keyword argument 'top_k'
```

`get_sampling_params` returns flat request-body fields, but `process_sample` expands them as OpenAI SDK keyword arguments.

## Modifications

- Forward request-body fields through the SDK's `extra_body`, preserving standard CLI sampling overrides and LoRA/reasoning options.
- Preserve existing nested `extra_body` precedence and SDK request controls (`extra_headers`, `extra_query`, `timeout`), without mutating the shared sampling dictionary.
- Add eight registered CPU regression tests using the real benchmark helpers, OpenAI SDK and `httpx.MockTransport` to check the serialized request and response.

The shared sampling helper, HF benchmark, image processing and answer scoring are unchanged.

## Accuracy Tests

On upstream `0025f9394421451aa09ec192a4a6e7928e14736b`, the final eight regression cases produce **2 SDK errors / 6 passes** with the original implementation and **8 passes** with the patch. Coverage includes extension fields, defaults, CLI/nested overrides, LoRA, reasoning effort, SDK controls and input preservation.

Local environment: Windows, Python 3.11, OpenAI SDK 2.21.0, httpx 0.28.1. The local compatibility launcher isolates the Unix-only SGLang package bootstrap, test base and unused CLI helper; the benchmark, evaluation helpers, SDK and transport remain real.
