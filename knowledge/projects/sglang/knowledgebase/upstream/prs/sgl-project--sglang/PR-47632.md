# [Perf] [AMD] attention: Forward decode graph variants through wrapper backends

[Upstream PR](https://github.com/sgl-project/sglang/pull/47632) · state: open · merged: False

## Original PR description


## Motivation

Follow-up to #47042, which added `AttentionBackend.get_decode_graph_variants` (default None) and the aiter decode partition buckets. Two non-blocking follow-ups from its review:

- Wrapper backends inherit the default None, so aiter partition buckets silently turn off under `HybridAttnBackend` (e.g. `--decode-attention-backend aiter`), `TboAttnBackend` and `HybridLinearAttnBackend`. Output stays correct; only the speedup is lost.
- The bucket tests checked capture metadata and eager output but did not capture and replay real decode graphs.

## Modifications

- `HybridAttnBackend.get_decode_graph_variants`: ask the backend that `_select_backend(capture_forward_mode)` routes to, the same routing its metadata and graph-state calls use. `SailHybridAttnBackend` inherits it.
- `HybridLinearAttnBackend`: ask `full_attn_backend`; linear-attention metadata does not depend on the variant label, so the same linear graph state is captured under each label. `ShortConvHybridAttnBackend` and the other subclasses inherit it.
- `TboAttnBackend`: ask `primary`. During capture the children read the same global variant label, and the label is chosen from the whole batch's longest request, which bounds every child's.
- Not forwarded: the Dots wrappers (MLA / FlashAttention / DSA children, one decode graph) and `MiniMaxHybridAttnBackend` (dense side not verified with buckets on ROCm).
- Tests:
  - `test_kv_translate_ownership.py` (CPU): every wrapper found by `_derive_wrapper_names()` must be listed, and each must return its decode child's variants, or None when that child returns None while another child returns variants. Fails for Hybrid, HybridLinear, ShortConv and TBO without this change.
  - `test_aiter_decode_partition_buckets.py` (AMD): `test_bucket_graphs_replay_like_eager` captures one real decode CUDA graph per bucket (p16 / p128 / p512) through `init_forward_metadata_out_graph(in_capture=True)` and `forward_decode`, checks the captured partition counts, then replays at max lengths 4096 / 4097 / 32768 / 32769 and requires bit-identical output to eager decode at `max_num_partitions`; a 4097-token batch replayed in the p16 graph must differ.

## Accuracy Tests

MI355X (gfx950): `test_aiter_decode_partition_buckets.py`, `test_kv_translate_ownership.py` and `test_aiter_fp8_kv_scales_paths.py` pass (15 tests). The wrapper changes only decide which graphs are captured; each graph's output is covered by the replay test above.

## Speed Tests and Profiling

Not measured. Under the three wrappers decode now gets the same buckets #47042 measured for a plain aiter backend.
