# [Perf] [AMD] monokernels: Let a plugin skip per-step attention metadata

[Upstream PR](https://github.com/sgl-project/sglang/pull/44601) · state: closed · merged: True

## Original PR description

## Motivation

A monokernel forward may never read some of the attention metadata a backend builds every step. sgl-amd-mono's DeepSeek-V4.1 forward scores every index source with K2i, so on each step it runs, the HIP radix backend builds the aiter decode schedule of each low ratio and nothing reads it. The build is recorded in the decode CUDA graph, so it runs on every replay.

Co-authored with @kkHuang-amd: this is kevin-mii/sglang#19 with the plugin contract stated as data.

## Modifications

- `monokernels/spec.py`: a `StepMetadata` enum and `MonoSpec.unread_metadata`, the per-step metadata a spec's forward never reads. It defaults to empty, so existing plugins are unchanged and the API version stays 1.
- `monokernels/runtime.py`: `is_metadata_unread(model, forward_batch, metadata)`, true only on a step the forward switch routes, for metadata the spec lists.
- `deepseek_v4_backend_hip_radix.py`: the low-ratio decode schedule build skips a ratio when `is_metadata_unread`, next to the identity-rows filter. Without `--monokernel-backend`, every schedule is built as before.
- CPU test `test_only_routed_steps_skip_the_metadata_a_spec_never_reads`.

- `pyproject_other.toml`: the plugin pin moves into one `monokernels_hip` extra that `srt_hip` and `srt_hip_rocm724` both include, at sgl-amd-mono e07665c (sgl-project/sgl-amd-mono#5), whose DeepSeek-V4.1 spec declares the schedule unread. A bump is one line, and the two extras cannot disagree. #5 merged first; until this PR merges, plugin main's DeepSeek-V4.1 spec needs it (it imports `StepMetadata`).
- `docker/rocm.Dockerfile`: the plugin install step from #44621 checks out the commit pip installed through `monokernels_hip`, read from the plugin's `direct_url.json`, instead of its own pin; `SGL_AMD_MONO_COMMIT` stays as an optional override, and the step skips SGLang versions that do not install the plugin. The image and pip then install the same commit. The step's text, run with git and `pip install` stubbed but the real `pip show` and metadata read, covers the installed, not-installed, override, gfx942 and opt-out cases; the image itself was not built.
