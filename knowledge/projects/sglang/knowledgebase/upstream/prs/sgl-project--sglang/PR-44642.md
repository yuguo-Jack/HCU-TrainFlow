# [Perf] distributed: Cache the eager launch of custom all-reduce v2 per size

[Upstream PR](https://github.com/sgl-project/sglang/pull/44642) · state: closed · merged: True

## Original PR description

## Motivation

An eager TP all-reduce through `CustomAllReduceV2` spends about 3.8 µs in Python on top of the 5.2 µs launch, measured on H200 (x86) with #44251 applied. The cost is split across these layers:

| layer | µs |
|---|---|
| kernel wrapper (`get_all_reduce_module` lookup, `comm.world_size`, result check) | 1.18 |
| `CustomAllReduceV2.custom_all_reduce` (byte count, `_pick_config` again) | 1.04 |
| `should_custom_ar` (`_pick_config`) | 0.62 |
| coordinator and `tensor_model_parallel_all_reduce` | 0.8 |

Every eager call of a given size and dtype resolves to the same algorithm and module, so the repeated work is redundant.

## Modifications

All changes are in `custom_all_reduce_v2.py`:
- Eager calls without `override_algo` resolve `(module, algorithm name, multicast)` once per `(nbytes, dtype)`. Both `should_custom_ar` and `custom_all_reduce` read that entry, and `custom_all_reduce` launches the module directly. A tvm-ffi Tensor result is still converted with `from_dlpack`.
- The cache is tied to the `config` object it was built from, so `uncap_pull_thresholds()` or any replaced config rebuilds it.
- Graph capture (`_graph_mode_allowed`), `override_algo` and kernel API logging keep the full path.

Callers, srt and diffusion alike, are unchanged. No memory is involved.

## Accuracy Tests

`test_custom_all_reduce.py --num-gpu 2` on 2xH200: 211 passed. Every existing case sets `override_algo`, so the tuned path had no coverage. Two tests are added:
- `test_custom_all_reduce_tuned_eager`: without an override, `should_custom_ar` matches `_pick_config` at every test size and dtype, and two passes (the second from the cache) equal NCCL exactly.
- `test_custom_all_reduce_eager_plan_follows_config`: replacing the config flips the verdict, restoring it flips it back, and the result equals NCCL.

## Speed Tests and Profiling

Base `c15edf314d` + #44251, torch 2.14.1, 2xH200 (Xeon 8558P), with processes pinned to the GPUs' NUMA node.

**Host time per call** (µs, bf16 [1, 4096, 3072]; the GPU is kept busy so only submission is timed):

| | before | after |
|---|---|---|
| `tensor_model_parallel_all_reduce` | 9.04 | 6.74 |
| `CustomAllReduceV2.custom_all_reduce` | 7.46 | 5.49 |
| `should_custom_ar` | 0.62 | 0.50 |
| bare module launch, for reference | 5.24 | 4.96 |

**End to end**, TP2 eager, client wall-clock median. Two identical co-resident servers differed by 3.5% in an A/A test on this box, so both paths were built into one server and chosen per request. Requests rotated through the arms in the same process, and an extra base arm measures in-process noise.

| | vs base (#44251 applied) | faster than base in | in-process A/A |
|---|---|---|---|
| FLUX.1-dev 512² | −2.43% | 11/12 | +0.33% |
| Qwen-Image-2.1 512² | −0.23% | 13/16 | 0.00% |
| both at 1024² (GPU-bound) | +0.1% | — | +0.0% |

Output images are unchanged: the same kernel runs with the same arguments.

On a base without #44251, the bypassed kernel wrapper also drops its DLPack re-wrap. Against plain main, this change measured −14.4% (Qwen-Image-2.1) and −15.2% (FLUX.1) at 512², 10/10 and 8/8. Most of that is the re-wrap that #44251 removes for every caller. The two PRs touch different files and combine cleanly.
