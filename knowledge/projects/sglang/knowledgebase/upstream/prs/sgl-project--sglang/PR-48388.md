# [Feat] sampling: --sampling-banned-token-ids masks token ids for the target and EAGLE draft

## Motivation

Some deployments must never sample a fixed set of token ids: multimodal placeholder tokens, or padded vocabulary rows past the tokenizer. Sampling and every returned logprob then have to be normalized over the remaining ids, for example to match a downstream consumer that masks the same ids.

Today the only server-side tool is a per-request custom logit processor (`DisallowedTokensLogitsProcessor`). It needs `--enable-custom-logit-processor`, runs per request, and does not reach speculative decoding: the draft keeps proposing banned tokens and the verify step does not see the mask.

## Modifications

- New server arg `--sampling-banned-token-ids <id> [<id> ...]` (`ExecFeatures.sampling_banned_token_ids`), documented in `server_arguments.mdx`. Off by default. `validate_sampling_banned_token_ids` rejects negative ids at startup; ids past the model's vocabulary are ignored with a warning.
- `LogitsProcessor.set_banned_token_ids` records the logits columns of the banned ids (optionally through a column -> token id map). `_get_logits` sets those columns to the dtype's lowest finite value on both of its return paths, with `index_fill_` on a static index, so CUDA graphs capture it. Every consumer reads these logits: sampling, the speculative verify (a drafted banned token gets target probability 0, so it is rejected and never resampled), draft proposals, and every returned logprob, which is normalized over the remaining ids. The fill is finite, so a banned id inside a prompt or used as a scoring label gets the lowest finite logprob rather than `-inf`.
- Target: `ModelRunner.maybe_set_banned_token_ids` masks every `LogitsProcessor` of the target model after load.
- Drafts: `EagleDraftWorkerBase.set_banned_token_ids` masks the draft after its head is set up. It is called by the EAGLE / EAGLE3 / NEXTN draft worker (columns mapped through the hot-token map: EAGLE3 `d2t` or `--speculative-token-map`), the STANDALONE draft worker and the multi-layer EAGLE draft worker. Other drafts (frozen-KV MTP, DFLASH, DSPARK, n-gram) are not masked; their banned proposals are still always rejected by the masked target.
- `DFlashWorkerV2` does not defer its target-verify TP gather while a ban is set, since a vocabulary shard cannot be masked (not run on GPU).
- Tests:
  - `test/registered/unit/layers/test_logits_banned_token_ids.py` (CPU): column selection for full and hot-token-mapped heads; `_get_logits` masks on both its regular and fused-gather return paths.
  - `test/registered/sampling/test_banned_token_ids.py` (`extra-a`, `1-gpu-small`): a positive control on its own server (without the flag, each prompt's greedy continuation starts with a banned id), then no banned id in the output or the top-20 logprobs, greedy and sampled.
  - `test/registered/sampling/test_banned_token_ids_eagle3.py` (`extra-a`, `1-gpu-small`): the same checks with EAGLE3.

## Accuracy Tests

1x GB300, `Qwen/Qwen3-30B-A3B` + EAGLE3 draft `Tengyunw/qwen3_30b_moe_eagle3` (steps 3, topk 1, draft tokens 4), same GPU and container as the baseline.

| Check | Result |
|---|---|
| Flag unset, `--enable-deterministic-inference`: 24 requests (top-k 5 / 20 / mixed, temperature + seed): output ids, token logprobs, top-20 logprobs | byte-identical to main `8d4e1ce4c7` |
| `--sampling-banned-token-ids 151935` (a padded id that is never sampled), same 24 requests | byte-identical to the flag-unset run, logprobs included |
| `--sampling-banned-token-ids 4236 6303 8697 12095` (" Paris", " five", " blue", " Blue"), prompts whose greedy continuation starts with one of them, greedy and T=1.0, top-20 logprobs, without and with EAGLE3 | 0 banned ids in output ids and in any top-20 row (12 requests); all logprobs finite |
| Columns masked (server log) | target 4 of 151,936; EAGLE3 draft 4 of 32,000 (via `d2t`) |
