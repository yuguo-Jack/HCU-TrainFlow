# [Fix] hicache: Resolve derived sidecars over every source transfer

[Upstream PR](https://github.com/sgl-project/sglang/pull/43110) · state: closed · merged: True

## Original PR description

## Motivation

A derived sidecar must follow every independent transfer of its source pool. Taking only the first transfer loses data when a component stages a pool in multiple segments, or when a Mamba host checkpoint is restored to both a radix-cache slot and a request-owned slot.

For split D2H backups, the sidecar can copy only the first segment while storage persists keys for the entire span, leaving stale tail pages. For H2D restores, host slot 2 may need to initialize device slots 4 and 7, but the sidecar previously followed only slot 4.

This fixes the generic multi-transfer sidecar contract introduced by #42633. Mamba load-back can emit two source transfers; the CPU regression explicitly registers a Mamba-derived sidecar. Default packed Mamba draft buffers use a separate dispatch path, so this is not a claim of model-level validation for that path.

## Modifications

- Add `merge_source_transfers` and use it in D2H allocation, H2D allocation, non-KV storage-side resolution, and sidecar descriptor construction. Preserve transfer order, repeated host indices, explicit sidecar device indices, and the single-source tensor aliases.
- Resolve sidecar sources by pool name across component transfers, including component-owned pools outside the fixed SWA/Mamba mapping. Only independent source transfers own their allocations.
- Sum repeated source transfers for byte accounting while retaining current rank-local `transferred_tokens` filtering.
- Move the split-pool CUDA/file-storage regression into the current `unified_radix_cache/test_unified_radix_cache_storage.py` suite and adapt its fixture to the explicit host-pool geometry API.
- Incorporate the six CPU restore/sharding regression cases from #46707. Sam Shleifer is credited with `Co-authored-by: Sam Shleifer <sshleifer@gmail.com>` in the integration commit.
