# [Fix] Preserve retained stop tokens in renderer incremental frames

[Upstream PR](https://github.com/sgl-project/sglang/pull/42040) · state: closed · merged: False

## Original PR description

## Motivation

With an engine configured for incremental streaming output, `no_stop_trim=true` can lose the final stop token and its logprob in the renderer. After one emitted token, a final frame containing one retained stop ID and a cumulative completion count of two is mistaken for cumulative output: normalization assumes a missing trimmed stop, then removes the retained ID as an already-emitted prefix. For example, `h!` becomes `h` when `!` is the stop token.

## Modifications

Pass the request's `no_stop_trim` setting into engine frame normalization. Only allow missing stop IDs when trimming is enabled. This preserves retained token IDs and logprobs while keeping default trimming and cumulative-frame handling unchanged.

## Accuracy Tests

- The new token/logprob regression fails before the fix and passes afterward; all 10 engine protocol tests pass.
- An HTTP engine transport regression covers cumulative/incremental frames and retained/trimmed stops, including decoded text, completion counts and finish reason.
- Complete renderer suite: 129 library tests and 1 CLI integration test pass with Rust 1.92.
- A standalone renderer HTTP reproduction with a real tokenizer passes all 8 combinations of engine streaming mode, stop retention and unary/SSE frontend responses; the two incremental retained-stop cases fail before the fix.
- Strict Clippy for the workspace, renderer test targets, multimodal features and radix-tree, formatting and touched-file pre-commit checks pass.
