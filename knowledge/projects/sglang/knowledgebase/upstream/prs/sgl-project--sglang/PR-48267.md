# [Fix] deps: Use oss-harmony for offline GPT-OSS serving

[Upstream PR](https://github.com/sgl-project/sglang/pull/48267) · state: open · merged: False

## Original PR description

## Motivation

Replace `openai-harmony==0.0.4` with `oss-harmony==0.0.12` so GPT-OSS Python serving can load its vocabulary offline ([openai/harmony#101](https://github.com/openai/harmony/issues/101)).

Tool history now uses native oss-harmony rendering. Commentary recipient placement and explicit `<|constrain|>` content-type markers are intentional [upstream changes](https://github.com/oss-harmony/harmony/commit/c16672a4613d3e2550758ad3630e5ed79da8301b); rewriting them would undo those changes. This follows the shim removal in the still-open [vLLM #59387](https://github.com/vllm-project/vllm/pull/59387). Its separate parser recovery changes are outside this PR.

## Modifications

- Switch all six Python/AMD dependency manifests to `oss-harmony==0.0.12`.
- Use the library's native rendering without a compatibility helper. **The final diff contains no Python runtime-source changes.**
- Add an empty-cache offline regression and four native-header/body subcases to the existing Responses tests. The header test passes with native rendering and fails with the removed shim.

Fresh GPU checks ran on one initially idle **GB300** from an existing Colossus lease, using GPT-OSS 20B MXFP4 at revision `6cee5e81ee83917806bbde320786a8fb61efebee`. Both phases used the ARM64 `lmsysorg/sglang:v0.5.23-cu130` image with the tested source overlaid through `PYTHONPATH`; other runtime dependencies were held fixed. The GPU was freed afterward.

The 16 cases cover text generation, function calls, tool-result replay, Chat Completions, and a third tool call/result after two prior tool turns, each streaming and non-streaming. All returned HTTP 200 and passed their semantic assertions.

**Identical generations are not claimed.** Four of eleven prompt fixtures intentionally differ from 0.0.4. Two GPU replay answers changed wording while retaining the supplied 21°C/sunny facts; four multi-turn cases retained the correct Rome call/result but differed in reasoning or usage. The text count includes empty text on tool-call-only cases, whose names and JSON arguments are checked separately. Normalization excludes generated IDs, timestamps, and cache-hit counters. Raw JSON/SSE captures and comparison details are in the evidence.
