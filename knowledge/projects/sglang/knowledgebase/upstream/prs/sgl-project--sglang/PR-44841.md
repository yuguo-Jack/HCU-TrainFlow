# [Feat] diffusion: Add worker-side ComfyUI compatibility patches

[Upstream PR](https://github.com/sgl-project/sglang/pull/44841) · state: closed · merged: True

## Original PR description

## Motivation

ComfyUI and SGLang Diffusion can produce different H3 outputs with the same BF16 checkpoint, conditioning, noise, and sampler because their floating-point operation order differs. Patching only the ComfyUI process does not reach the spawned diffusion worker.

Add an `alignment_mode` option to the existing **SGLDiffusion Options** node: `default` retains normal SGLang behavior; `comfyui` selects the initial H3 compatibility implementation. The workflow remains `Options → Model Loader`, with no extra node.

## Modifications

- Append the alignment selector to preserve existing workflow widget positions. In ComfyUI mode, `auto` attention resolves to `torch_sdpa`; explicit incompatible backends are preserved and rejected by validation.

- Keep the shared worker-patch entry point small: a fixed name-to-module mapping, startup configuration transport, and synchronous installation after the worker loads its pipeline. No separate wheel, entry-point registration, or multi-profile composition framework.
- Preserve the normal bootstrap/platform/plugin initialization order. Install in the child process, propagate installation failures, and restore the parent's launch target after startup.
- Include the selected versioned profile name in generator reuse and reload state so changing profiles rebuilds the worker.
- Keep H3-specific validation and all five numerical adjustments in one module: timestep embedding cast order, RMSNorm/AdaLN fusion, residual addcmul, QK/RoPE, and output-head projection row selection. Bind changes to model instances without editing the H3 runtime implementation.
- Add tests for spawn propagation, failure handling, default startup restoration, unsupported settings, dynamic LoRA rejection, and instance isolation.

**Draft scope:** the H3 profile is currently restricted to single-GPU Hopper, resident BF16 base H3, eager execution, and `torch_sdpa`, without quantization, caching, or LoRA. It pins the reviewed H3 source hash and `comfy-kitchen==0.2.36`. These are deliberate prototype constraints to review before broadening support; multi-GPU and Ref2VA parity are not claimed. User-facing cookbook documentation remains a follow-up before marking this ready.

## Accuracy Tests

21 automated tests passed (including Options defaults, auto/explicit attention handling, invalid mode rejection, and legacy widget order):

```bash
PYTHONPATH=python python -m pytest -q \
  python/sglang/multimodal_gen/apps/comfyui_worker_patches/tests/test_worker_profiles.py
```

Manual H200 tests used the actual ComfyUI node Python APIs and spawned SGLang workers, with matching conditioning, seed 123456, input noise, and Euler sigmas. These were not HTTP-queued UI tests.

| Case | Result |
|---|---|
| BF16 T2AV, 384×256, 22 frames, 8 steps | Final video and audio latents bitwise equal to native ComfyUI |
| BF16 T2AV, 768×768, 124 frames, 50 steps | Final video and audio latents bitwise equal to native ComfyUI |
| Same parent, live worker retained: default → compatibility → default | Both profile changes rebuilt the worker; both default results matched the original SGLang baseline bitwise; compatibility matched native ComfyUI bitwise |
| Repeated load with unchanged options | Reused the model/worker and preserved the reload configuration |

After moving selection into Options, the 384×256 live-worker sequence was rerun through `SGLDOptions.create_options`, with `auto` attention in ComfyUI mode. The 768×768 result predates this UI-only change; worker installation and H3 arithmetic are unchanged.

All integration runs omitted the previous experimental addon installation. The shared ComfyUI installation and existing UI service were unchanged. The direct-node harness still emits an existing `ModelPatcher.__del__ / ON_DETACH` warning at interpreter teardown, after result saving and worker shutdown; runs exit successfully.

## Speed Tests and Profiling

The 768×768 / 124-frame / 50-step compatibility run took 167.17 seconds for sampling, including the client/worker path. This is one functional-validation run, not a repeated performance benchmark; no speedup claim is made. The change keeps the existing default execution path and uses an explicit compatibility opt-in. Sage/FA3 performance experiments are outside this PR.
