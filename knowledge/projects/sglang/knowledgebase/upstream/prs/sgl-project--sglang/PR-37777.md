## Original PR description

# perf(hisparse): resolve MTP KV on demand inside FlashMLA

## Summary

This PR adds an opt-in, request-local HBM read-through cache for HiSparse MTP target verification. Instead of materializing every selected historical KV row before attention, FlashMLA resolves each TopK row while consuming it: current speculative rows come from the device overlay, cache hits come from the Demand Buffer, and misses read the authoritative pinned-Host row while filling HBM for later reuse. MTP sampling and accepted-token ownership remain unchanged.

```text
HiSparse MTP without Demand

4 x TopK rows -> pre-attention Host-to-HBM materialization -> page tables -> FlashMLA

HiSparse MTP with Demand

4 x TopK rows -----------------------------------------------> FlashMLA
                                                                  |
                       current row -> device overlay               |
                    historical hit -> Demand HBM <-----------------+
                   historical miss -> pinned Host -> fill HBM
```

This PR is stacked on #26445, which owns HiSparse MTP allocation, request lifecycle, and accepted-token finalization.

## Motivation

MTP target verification evaluates four ordered query rows per request. With `top_k=2048`, eagerly materializing each row can place up to 8192 historical-KV occurrences on the verification critical path and reserve `num_draft_tokens * top_k` staging rows per active request.

Demand moves historical-KV source selection into the FlashMLA producer. It removes the separate multi-row staging pass while preserving pinned Host memory as the source of truth.

## Design

```text
logical TopK position
        |
        +-- current MTP window ------------> existing device overlay
        |
        +-- committed history
                 |
                 +-- matching READY tag ---> request-local HBM row
                 |
                 +-- miss -----------------> pinned Host row
                                                   |
                                                   +-- consume now
                                                   +-- fill and publish HBM row
```

- HiSparse remains the owner of the Host KV pool and request lifecycle.
- Each request reserves 4096 HBM Demand rows per local attention layer.
- Each historical row has two independently hashed candidate slots.
- Tags encode the Host row, a lazy generation, and `FILLING` or `READY` state.
- The first producer that claims a miss fills and publishes the slot with release ordering.
- A concurrent consumer performs bounded observations of `FILLING`, then falls back to the authoritative Host row rather than waiting or reading partial data.
- Entries survive adjacent decode calls and are replaced lazily.
- Current speculative rows continue to use #26445's existing extra-page device slots.
- Accepted rows are committed only after draft-extend has finished consuming the verify overlay.

The feature adds no planner, prefetch pass, periodic clear, or additional CUDA stream.

## Performance

Validated on 8x NVIDIA H20 with GLM-5.2 W4AFP8, TP8/DP8, full 78-layer execution, CUDA Graph, 128K input, 1K output, and fixed 69.76% acceptance. All variants used the same candidate commit, seed, input hash, DP placement, 323 verify steps, and no retractions.

These measurements were collected at pre-rebase commit `92e993902`. The final community-main rebase contains API adaptation and formatting changes; its repository pre-commit gate passes, while a post-rebase H20 rerun remains pending.

| Variant | TTFT | TPOT | Verify-step wall time | Output throughput |
| --- | ---: | ---: | ---: | ---: |
| MTP, all KV in HBM | 244.562 s | 22.785 ms | 70.470 ms | 3.741 tok/s |
| HiSparse MTP + Demand | 251.813 s | 24.173 ms | 74.765 ms | 3.624 tok/s |
| HiSparse MTP union | 251.917 s | 26.501 ms | 81.965 ms | 3.592 tok/s |

- Demand is **8.79% faster** than the current union path in TPOT.
- Demand is **6.09% slower** than the all-HBM path in TPOT.
- `mtp_demand_buffer=false` currently selects the union path for this production shape; the benchmark launcher's historical `native` spelling refers to that union variant.
- B8/B16 current-HEAD serving results were not rerun in this validation and are not claimed here.

## Modifications

- Parse and fail-close the `mtp_demand_buffer` HiSparse option.
- Allocate, bind, reset, and release request-local Demand rows and tags.
- Emit logical TopK positions and physical Host rows from fused TopK-v2.
- Pass one typed HiSparse Demand adapter through the FlashMLA wrapper.
- Resolve overlay, HBM-hit, and Host-miss sources inside the FlashMLA producer.
- Fill and publish Demand rows without blocking concurrent consumers.
- Persist accepted MTP rows through the existing HiSparse lifecycle.
- Keep the speculative draft worker's KV device-resident; only the target worker owns the HiSparse Host pool.

## Supported configuration

The optimization is disabled by default and fail-closes to the existing HiSparse MTP path unless all of the following hold:

- CUDA SM90;
- GLM-5.2 MLA DSA with FP8 KV and `flashmla_kv`;
- fused SGLang TopK-v2 with `dsa_topk_backend=sgl-kernel`;
- `top_k=2048`, device buffer size 4096, page size 64;
- EAGLE MTP with `num_steps=3`, `topk=1`, `num_draft_tokens=4`;
- TP8/DP8 with DP attention, PP1, CP1;
- integrated serving, or PD decode with `index_share_for_mtp_iteration=false`.

```bash
--enable-hisparse \
--hisparse-config '{"top_k":2048,"device_buffer_size":4096,"mtp_demand_buffer":true}'
```

For the 78-layer GLM-5.2 target, the buffer reserves 199.875 MiB per active request and DP rank. Allocation failure is reported instead of silently changing execution semantics.

## Accuracy tests

- `PASS`: 31 Demand/adapter tests plus 25 subtests.
- `PASS`: 42 HiSparse allocator/request-lifecycle tests plus 25 subtests; 2 unsupported-platform cases skipped.
- `PASS`: 11 production-shape union/JIT tests.
- Byte-exact FlashMLA output and LSE parity against HBM for B1 and B8.
- Same-generation hit test corrupts the corresponding Host rows after fill, proving resident rows are consumed from HBM.
- Epoch retention, replacement, request reset, and 24-bit generation-wrap coverage.
- No `FILLING` tag remains after kernel completion.
- Multi-step page-table lifetime regression verifies that later MTP rows cannot overwrite earlier returned mappings.
- Full-model HBM and Demand natural smoke produced the same output hash and zero retractions.

## Profiling

- Demand folds Host fallback, cache fill, and tag publication into the FlashMLA producer.
- It does not add a planner or a separate staging kernel to the verify critical path.
- The release claim in this PR is based on the current full-model B1 result above; no earlier WIP trace is used as current evidence.
