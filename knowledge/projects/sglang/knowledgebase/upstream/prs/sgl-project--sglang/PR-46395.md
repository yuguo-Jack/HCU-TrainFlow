# [Feat] disagg: Write PD decode KV to the linker and skip pages the prefill already stored

[Upstream PR](https://github.com/sgl-project/sglang/pull/46395) · state: closed · merged: True

## Original PR description

## Motivation

With PD disaggregation, nothing writes the decode-side KV to the external store, so the next turn's prefill restores only the previous prompt and recomputes the previous output every turn. The decode radix cache can write those pages through the linker, but it then re-uploads the prompt pages whose storage is delegated to prefill.

## Modifications

- Prefill reports `stores_to_linker` in its bootstrap info (Python and Rust bootstrap servers). Decode sets `req.linker_offload_skip_prefix_len` at each preallocation, including rebootstrap: the prefill-filled prefix length in raw tokens when the peer enables the linker, otherwise 0. The `getattr` fallback preserves compatibility with receivers such as `FakeKVReceiver` that have no `prefill_info`.
- `UnifiedRadixCache._linker_offload_skip_prefix` converts this generic request boundary to page-aligned radix-key units, including bigram conversion where applicable. It wraps the local tree insert in `UnifiedCacheLinkerWrapper.skip_offload_prefix(len)`; PD-specific policy stays in decode.
- The linker trims the corresponding transfer prefix while preserving local radix-tree insertion. A fully skipped node is marked stored locally to suppress duplicate uploads. This delegates storage responsibility to prefill; it does not wait for a persistence ACK. External storage is best-effort, so a failed prefill write can require recomputation on a later turn.
- `process_decode_queue` polls linker offload completion while tree offloads are pending, so their node locks are released.

The change is model-agnostic (Full / SWA / Mamba pools).

## Tests

- Unit (`test_unified_cache_linker.py`, Python and Rust tree cores): `test_offload_skips_prefix_stored_by_prefill`, `test_node_inside_skip_offload_prefix_is_marked_stored`. Both fail with the skip disabled.
- New e2e `test_disaggregation_decode_radix_linker.py` on Kimi Linear (MLA + KDA), 1P1D, Mooncake store, decode radix cache, linker on both roles. Across four turns, with both device caches flushed between turns, prefill `cached_tokens` covers the previous turn's prompt and output. It fails with only the prefill linker (1472 < 2048).

## Results

DeepSeek-V4.1-Flash, 1P1D DEP2, 16 concurrent multi-turn sessions:

| | decode radix + linker, no skip | with skip | prefill-only linker |
|---|---|---|---|
| Mooncake put items / key count | 1.49 | 1.005 | 1.005 |
| Turn 1-3 prefill hit rate | 0.94 / 0.95 / 0.96 | 0.94 / 0.95 / 0.95 | 0.84 / 0.86 / 0.88 |

### Agentic replay follow-up

Harness: local `agentic-cache` extension of #46006's `benchmark/engine_steps/bench_engine_steps.py` (`543a2804d5c8`), 8 SWE-smith trajectories × 6 turns. No device-cache flush; actual generated token IDs carried forward; only the decode external linker toggled.

| Model | Continuation Prefill hit rate, off → on | Extra reused tokens |
|---|---|---|
| Kimi Linear | 70.951% → 71.595% (**+0.644 pp**) | 1,280 / 198,807 input tokens |
| DSv4.1-Flash | 68.692% → 69.728% (**+1.036 pp**) | 2,304 / 222,488 input tokens |

DSv4.1 used #45556 (`60bc8f6fdcc3`) stacked on this PR (`99058868c7c8`): 1P1D, TP2/EP2 per role, attention DP1, native paged KV, decode radix + decoder bounded replay enabled. All 96 requests per model succeeded. DSv4.1's 12 rounds agree across Prefill metrics, scheduler logs, and input counts; Kimi was audited against Prefill logs. Response `cached_tokens` also includes decode-local reuse and masks the benefit.

Tool observations and output lengths are replayed; generated outputs are not bit-identical across arms. This measures cache reuse, not agent task success or E2E speedup.
