# [AMD][DSV4] fp8 unified_kv decode/verify via aiter FlyDSL v4 nm decode

## Motivation

On gfx950, DSv4 fp8 unified_kv decode and target verify run the asm `mla_a8w8_qh64_qseqlen1_gqaratio64_nm` kernel, then a stage-2 split merge, then a separate inverse-RoPE + wo_a mxfp8 quant. This PR moves all three into one launch of aiter's FlyDSL v4 nm decode (ROCm/aiter#5882). On the current image it cuts the 8K/1K step time by 1.1–3.9%.

## Modifications

- `decode_fp8_2buff` calls `aiter.ops.flydsl.flydsl_mla_decode_fwd_v4_nm` when the installed aiter has it. The kernel picks its own split plan from the stream kind (CSA / HCA / SWA-only).
- fp8 wo_a: the same launch also does the inverse RoPE and the wo_a mxfp8 quant, so `MQALayer` runs only the a8w8 GEMM.
- DSpark target verify: HCA and SWA-only layers read one stream per request (per-draft `q_kv_bounds`) where aiter's `flydsl_mla_v4_grouped_pays` says it pays. CSA stays per-token. The output matches per-token verify.
- On by default; `SGLANG_DSV4_FLYDSL_DECODE=0` keeps the asm path.
- **Without ROCm/aiter#5882** (e.g. current aiter main): `aiter.ops.flydsl` has no `flydsl_mla_v4_decode_supported`, so `_flydsl_v4_decode()` catches the `AttributeError` (or `ImportError` if FlyDSL is missing) and returns None. Then decode/verify call the asm `mla_decode_fwd_v4_nm` with the same split policy as today, wo_a keeps its current path, and no grouped-verify metadata is built. Behaviour is the same as main; there is just no speedup. The FlyDSL cases in the test skip.
- Test: `test/registered/e2e/dsv4/test_dsv4_unified_fp8_decode.py` checks decode, fused wo_a (incl. H128) and grouped verify against asm and a reference.

## Speed Tests and Profiling

DSv4-Pro, 8x MI355X, `lmsysorg/sglang-rocm:v0.5.20-rocm724-mi35x-20260927`, 8K in / 1K out, TP8, fp8 KV (`SGLANG_DSV4_UNIFIED_KV_FP8=1 SGLANG_OPT_FP8_WO_A_FUSED_INVROPE=1`), CUDA graphs.
- **stock asm** = the image as shipped: asm v4 nm `.co` (sgl-project/sglang#41120) per-token + stage-2 merge + inverse-RoPE quant. This is the production path.
- **this PR** = the same image + this PR (identical diff on current main) + ROCm/aiter#5882 + flydsl 0.3.4.1, with the asm `.co` deleted. No other change.
- 2 boots per arm, interleaved, 3 reps each; deltas are paired by (boot, rep), n = 6. Step time = median ITL (plain / DP) or median full-accept verify step (DSpark 6).

| Config | stock asm (ms) | this PR (ms) | Δ step, paired [min, max] | decode tok/s |
|---|---|---|---|---|
| TP8, c8 | 13.28 | 12.75 | **-3.9%** [-0.55, -0.49 ms] | +4.1% |
| TP8, c32 | 17.13 | 16.61 | **-3.1%** [-0.56, -0.48 ms] | +3.2% |
| TP8 + DSpark 6, c16 | 27.45 | 26.95 | **-1.8%** [-0.62, -0.38 ms] | +2.7% |
| TP8 + DSpark 6, c64 | 46.91 | 46.03 | **-1.9%** [-1.06, -0.61 ms] | +2.5% |
| DP8 attention, c64 | 21.24 | 21.01 | **-1.1%** [-0.26, -0.20 ms] | +1.1% |

All 30 paired differences are negative. The DSpark rows are the total gain vs the production asm path. In the earlier 20260922-image numbers, about 0.18 ms/step of the DSpark gain came from that asm baseline (ROCm/aiter#5195 `.co` + ROCm/aiter#5776 merge) building `split_indptr` in every layer; the stock asm wrapper here caches it, so none of the gain above comes from that.

Attention per step, in-graph kineto (µs), stock asm read + merge + inv-RoPE quant → one FlyDSL launch:

| | TP8 c8 | TP8 c32 | DSpark c16 | DSpark c64 |
|---|---|---|---|---|
| stock asm | 1199 | 1275 | 1633 | 3231 |
| this PR | 584 | 673 | 1111 | 2247 |
| graph nodes | -122 | -122 | -122 | -59 |

The rest of the step is unchanged within 1–2%.

Kernel microbench (details in ROCm/aiter#5882), FlyDSL / best asm split + merge: 179 decode cells (H 16–128, msq 1–4, B 1–1024, L 128–16K) median 0.86, max 0.997; DSpark verify, 80 cells, median 0.86; 61-layer decode step 0.77–0.93x.
