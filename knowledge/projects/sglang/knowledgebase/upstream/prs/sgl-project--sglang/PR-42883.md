# [Feat] lora: Packed MoE schedules for the CuTeDSL GEMMs (16/21)

[Upstream PR](https://github.com/sgl-project/sglang/pull/42883) · state: closed · merged: False

## Original PR description

Part 16 of 21 of the LoRA runtime stack (branch `lora-stack-15-cutedsl-schedule`, base `lora-stack-14-moe-runner`). The stack is cut from the development branch of #42284.

## What this part adds

Add the dual-stage schedule builder (one int64 per tile) and the persistent
tile scheduler the CuTeDSL grouped GEMMs consume, plus the small masked
preparation that builds them in one launch.

Tests: schedule packing and builder boundaries. The small masked preparation
is exercised by the CuTeDSL BF16 part's tests.

## Verification

- GB300 run r45: the tree of upstream main `c1c287a429` plus parts 01–16 imports every module this part changes and passes this part's tests together with every earlier part's unit tests: **385 passed, 20 warnings, 160 subtests passed in 25.90s** (excluding the tests that fail identically on the untouched base tree in that environment).
- `pre-commit` passed on the changed files of every part; `pre-commit run --all-files` passed on the complete stack tree.

The complete 21-part tree equals the development branch of #42284 at `e7b7179a86` (the `6588053ef2` tree with four test-only follow-ups squashed into its dense commit: the admission/snapshot trim, the restored FP8 block-shape admission pin, a second trim that keeps only the tests guarding silent failures and adds pins for four coverage gaps, and restored numerical and packing coverage; production code is unchanged) minus the benchmark tools and the Triton MoE tuning tables, which follow in separate PRs.
