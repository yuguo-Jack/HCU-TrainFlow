# [Feat] scheduler: Bound UniBoost waits of requests that share a prefix

[Upstream PR](https://github.com/sgl-project/sglang/pull/48078) · state: open · merged: False

## Original PR description

## Motivation

Follow-up to #48077. Agentic traffic sends many requests that share a long prefix: turns of one session, or sessions forked from one system prompt. Two interactions with prefix sharing break UniBoost's wait bound, and this PR fixes both.

1. **Dedup followers have no bound.** In-batch prefix dedup marks a waiting request whose prefix another queued request will insert (its *leader*) as a follower, and the cache-aware policies sort followers last. A follower behind the whole queue also sits behind every later arrival, so its wait is unbounded under sustained load.
2. **Admitting just before a sibling's commit recomputes it.** When an earlier extender (the in-flight chunked prefill, or a waiting request that sorts first) is about to commit tokens past a request's matched prefix, admitting that request in the same pass prefills those tokens uncached, and the sibling's commit lands a moment later. On agentic contexts of 100k tokens or more, that duplicates the prefill of the whole shared span.

**UniBoost series** (each PR builds on the previous one; review in order):
1. #48076: the policy (`--schedule-policy uniboost`)
2. #48077: adaptive gamma from the response-time tail
3. #48078: bounded waits for requests that share a prefix
4. #48079: decode time-slicing for first-token-starved waiters

All four target `main`, so #48077 to #48079 also carry the commits of the PRs before them; each PR's own change is its last commit.

## Modifications

- **Leader-relative followers**: `_compute_prefix_matches` can report each follower's leader. The simulated tree stores, per inserted prefix, the index of the request that inserted it, so the deepest matched node names the leader.
  - A follower sorts just behind its leader (at `phi(leader) + eps`) instead of last, so it inherits the leader's bound.
  - A follower whose leader has left the queue goes last, as before. Followers of one leader keep arrival order.
- **Commit gate** (`uniboost.mark_commit_holds`, run after the sort): a request is held out of the current admission pass when an earlier extender will extend its matched prefix by at least one 256-token frontier. The extender is the in-flight chunked prefill, or a waiting request that sorts before it.
  - The hold ends when that extender commits; the cumulative hold of one request is capped at 120 s.
  - The admission loop skips held requests for this pass only.
- uniboost shares `shortest-prefill-first`'s chunk handling: the chunked-prefill chunk limit (a chunk leaves budget for shorter waiting requests) and the one-unfinished-chunk rule in `PrefillAdder`.
- `managers/schedule_batch.py`: two `Req` fields for the commit gate.
- Existing scheduler unit tests with stand-in requests get `uniboost_commit_hold = False`.
