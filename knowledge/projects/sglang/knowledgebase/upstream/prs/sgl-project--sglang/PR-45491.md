# [Fix] spec: Take post-verify KV move targets from the verify window

[Upstream PR](https://github.com/sgl-project/sglang/pull/45491) · state: closed · merged: True

## Original PR description

- `move_accept_tokens_to_target_kvcache` takes each request's move targets from the front of its verify window in `out_cache_loc`, instead of rereading `req_to_token` after the verify forward
- The reread raced with the overlap scheduler: the target verify publishes its shared-read-done event inside the graph replay, before the move runs, so a request that finished by EOS or a stop condition in the previous step can have its row handed to a new request while the move is still queued. The move then copied KV into the new owner's slots, including radix-cached prefix slots, and later hits on that prefix read the corrupted KV
- Affects NGRAM and UNO tree verify (`--speculative-eagle-topk > 1`) on CUDA; EAGLE tree verify calls the same function but keeps the whole-forward barrier
- Add `test/registered/unit/spec/test_move_accept_tokens_targets.py`: rewrites the rows after the verify window is built and checks the move targets and sources for chain and tree layouts

No behavior change when no row is reused: the targets equal the rows' entries at verify time.

Verification with Qwen3-8B, NGRAM, FA3, page size 1, one H200 per server. A 4000-token prefix is cached, then for 120 s short requests that stop early run next to requests that reuse the prefix. Afterwards, bs=1 prefill logprobs over the cached prefix are compared with a server using the whole-forward barrier (`SGLANG_FORCE_COARSE_WAR_BARRIER=1`); both servers match bitwise before the load.
