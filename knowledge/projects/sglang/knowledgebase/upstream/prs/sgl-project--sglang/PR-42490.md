# [Fix] hicache: Carry Mamba slot side states through zero-copy storage backends (Qwen3.8-Flash-Next on Mooncake/NIXL)

[Upstream PR](https://github.com/sgl-project/sglang/pull/42490) · state: open · merged: False

## Original PR description

## Motivation

#39862 made `MambaPoolHost` carry registered slot side states (Qwen4-Exp / Qwen3.8-Flash-Next PLE short-conv window and N-gram history) through the host tier, and made `get_page_buffer_meta()` raise `NotImplementedError` whenever such states exist. Mooncake only uses zero-copy for hybrid pools, and NIXL uses it whenever O_DIRECT is off, so on main every Qwen3.8-Flash-Next L3 backup through those backends hits that raise:

```
File ".../hybrid_cache_controller.py", line 1370, in _page_backup_with_stable_layout
    self.storage_backend.batch_set_v2(transfers, extra_info=extra_info)
File ".../mooncake_store.py", line 942, in _batch_io_v2
    ptr_list, element_size_list = host_pool.get_page_buffer_meta(host_indices)
NotImplementedError: Mamba storage zero-copy does not carry registered slot side states; use a whole-page storage backend.
```

The backup thread dies on the first backup (the warmup request), so L3 is silently never written, the server keeps serving, and `/flush_cache` returns 400 from then on because writes stay pending.

Mooncake, NIXL, Ascend MemCache and UMBP also each hard-coded their own copy of the Mamba per-page object list (`temporal` + `conv_i`) that has to line up with the pointer order of `get_page_buffer_meta()`.

## Modifications

- `MambaPoolHost.get_page_component_names()`: the storage object names of one page, in `get_page_buffer_meta()` pointer order: `temporal` (dropped for conv-only models), `conv_i`, then one entry per registered side state, named from its transfer entry (`ple_short_conv_0`, `ple_ngram_0`).
- `MambaPoolHost.get_page_buffer_meta()` emits the side-state rows after `conv_n` instead of raising.
- Mooncake, NIXL, Ascend MemCache and UMBP build their Mamba component keys from `get_page_component_names()`. Keys for models without side states are unchanged (`_temporal`, `_conv_i`), so existing L3 objects stay readable. The Ascend MemCache and UMBP edits are the same one-line substitution and are not exercised by the tests below (no Ascend / `mori` environment).
- The NIXL L3 cleaner groups the new component files with their logical page.

## Accuracy Tests

Unit tests (CPU):
- `test_hicache_mamba_slot_side_states.py`: zero-copy meta carries the side-state rows at the right addresses; models without side states are unchanged.
- `test_mooncake_group_semantics.py`, `test_hicache_nixl_storage.py`: Mamba keys follow the host pool's component names and stay zipped with the matching pointers.
- `test_hicache_nixl_cleaner.py`: side-state files share the page's cleanup group.

With the source changes reverted, all new tests fail (6 failures, including 2 cleaner subtests).

End to end, `nvidia/Qwen3.8-Flash-Next-NVFP4`, 1x B200, TP1, ~12.5K-token prompts carrying five random codes, `--page-size 64 --mamba-radix-cache-strategy extra_buffer --hicache-size 24 --hicache-write-policy write_through --hicache-mem-layout page_first --hicache-io-backend direct --hicache-storage-prefetch-policy wait_complete`. Each restore leg must hit the asserted tier in full, recall 5/5 codes and match the device-hit leg's output tokens. Three samples per leg.

| Backend | main | this PR |
|---|---|---|
| Mooncake: host restore / L3 restore after `/flush_cache` | host OK; L3 never written (raise above), `/flush_cache` 400 | all legs pass |
| Mooncake + NEXTN (3 steps, topk 1, 4 draft tokens) | not run | all legs pass, accept length equal across tiers |
| NIXL POSIX, `SGLANG_HICACHE_NIXL_USE_DIRECT_IO=0`: host / L3 / L3 after restart | raise above | all legs pass |
| NIXL POSIX + NEXTN | not run | all legs pass |
| File (regression) | pass | pass |

NIXL with O_DIRECT (the default) is not covered here: on main its hybrid bounce-buffer path writes and reads the wrong bytes for Mamba pages. That is fixed separately in #42491.

## Speed Tests and Profiling

No change to the transfer path for models without side states. With side states, each Mamba page adds one storage object per registered state (184 KB per checkpoint on Qwen3.8-Flash-Next, 0.3% of the page).
