# [Perf] [XPU] distributed: Default oneCCL to its Arc all-reduce on Arc GPUs

[Upstream PR](https://github.com/sgl-project/sglang/pull/47000) · state: open · merged: False

## Original PR description

## Motivation

At small batch, decode issues one tensor-parallel all-reduce per attention block and one per MLP/MoE block: 129 per step for Qwen3-32B and 94 for Qwen3-30B-A3B at TP4. Their latency is a fixed part of every step. On Arc Pro B70 (4 cards over PCIe), oneCCL's default SYCL all-reduce takes 17-26 us per call at decode sizes. Its Arc-specific algorithm (`CCL_SYCL_ALLREDUCE_ARC=1`) takes 15-16 us, and it is equally fast at prefill sizes.

## Modifications

- `distributed/bootstrap.py`: new `_set_xpu_ccl_defaults()`, called in `init_parallel_runtime` on XPU before the first communicator is created.
  - When the device name contains `Arc`, it does `os.environ.setdefault("CCL_SYCL_ALLREDUCE_ARC", "1")`, so a value the user sets still wins.
  - Other Intel GPUs are left alone.
- Setting the variable in-process takes effect: oneCCL reads it when the first communicator is created, and the per-call latency drops as shown below.

## Accuracy Tests

Only the all-reduce algorithm changes. Like any switch of all-reduce algorithm, the summation order can change, so outputs are not bit-identical across the two settings. oneCCL runs are not bit-reproducible on this setup to begin with.

No accuracy change is expected; the combined check below runs GSM8K with this PR applied.

**Combined check on main** (`7e142dd9fd` with #46997-#47003 applied, sgl-kernel-xpu 0.5.0, 4x B70, TP4, the server flags listed under Speed Tests, GSM8K full 1319 sampled at 0.7 / 0.8):

| model | GSM8K | c=1 median TPOT | c=4 median TPOT |
|---|---|---|---|
| Qwen3-30B-A3B bf16 | 94.69% (95.38% in an earlier run without these PRs) | 6.74 ms | 10.68 ms |
| Qwen3-32B-FP8 + EAGLE3 (`AngelSlim/Qwen3-32B_eagle3`, sampled verify) | 95.30% | 11.08 ms (accept length 2.37) | 13.97 ms |

## Speed Tests and Profiling

**Setup:**
- 4x Arc Pro B70, TP4 on cards with no shared PCIe switch, torch 2.14.0+xpu.
- compute-runtime 26.31, oneAPI 2026.0.

All-reduce latency per call, measured inside an XPU graph (bf16, 4 ranks):

| message | default | `CCL_SYCL_ALLREDUCE_ARC=1` |
|---|---|---|
| 2048 x 1 | 18.5 us | 14.7 us |
| 2048 x 4 | 26.4 | 14.7 |
| 2048 x 16 | 24.9 | 15.2 |
| 5120 x 1 | 16.6 | 14.6 |
| 5120 x 32 | 22.9 | 20.6 |
| 5120 x 4096 (prefill) | 2041 | 2041 |

oneCCL's low-latency variant (`CCL_SYCL_ALLREDUCE_LL=1`) is as fast in graphs, but it is 2x slower in eager mode (63-75 us vs 33-42 us), so it was not used.

End to end, `bench_serving` random 512 in / 256 out, TPOT in ms, ABBA order:
- A: this branch with `CCL_SYCL_ALLREDUCE_ARC=0`.
- B: this branch's default.
- Server flags: the cookbook BMG command (`--device xpu --tp 4`) plus `--attention-backend intel_xpu --page-size 64 --cuda-graph-backend-decode full --cuda-graph-backend-prefill breakable`.

| model | c=1 A / B | c=4 A / B | c=16 A / B |
|---|---|---|---|
| Qwen3-30B-A3B | 6.85, 6.84 / 6.73, 6.72 (-1.8%) | 11.00, 10.98 / 10.73, 10.72 (-2.4%) | 20.38, 20.45 / 20.15, 20.15 (-1.3%) |
| Qwen3-32B | 31.58, 31.59 / 31.18, 31.18 (-1.3%) | 32.52, 32.56 / 32.17, 32.17 (-1.1%) | 34.93, 34.93 / 34.64, 34.52 (-1.0%) |
