# [MemCache] Serve disabled full-attention models with `UnifiedRadixCache`

[Upstream PR](https://github.com/sgl-project/sglang/pull/43199) · state: closed · merged: True

## Original PR description

- `--disable-radix-cache` on full-attention layouts (MHA / MLA) builds `UnifiedRadixCache(disable=True)` instead of `ChunkCache`
- This changes the default PD decode cache for MHA / MLA (`cpu_tensor` retraction backup), and also moves DSA HiSparse (GLM-5/5.2, DeepSeek-V3.2, MiniMax-M3), embedding models with `safe_disable_radix_cache`, Whisper, `--enable-mis`, and deterministic inference on non-radix backends
- Multimodal on the transformers backend with lmcache / flexkv / external linker and radix disabled now gets plain `UnifiedRadixCache(disable=True)`
- Validated: retract MMLU, MHA and MLA PD GSM8K, strict busy memory check

## Other observable differences
Found by a base-vs-head equivalence check; KV slots, generated tokens and pool usage are unchanged.
- `--enable-session-radix-cache` or `--radix-eviction-policy tlru` with `--disable-radix-cache` used to fail at startup (the check required `UnifiedRadixCache`); they now start and have no effect
- The OOM error text from `available_and_evictable_str` reads `Available full tokens: ...` instead of `Available tokens: ...`, and the OOM path prints the (empty) tree via `pretty_print`
- `--enable-metrics` registers a `RadixCacheMetricsCollector` that never records a sample
- KV events (`AllBlocksCleared` on construction and flush) and startup validation of `--radix-eviction-policy-config` are removed again by #43253
