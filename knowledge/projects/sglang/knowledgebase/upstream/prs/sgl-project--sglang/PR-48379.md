# [Perf] qsa: copy only the context rows a prefill reads under the QSA K/V offload

## Motivation

With the QSA K/V host offload (`--enable-qsa-kv-offload`, PR 1/N and 2/N), a prefill on a cached prefix copies the whole context of every request in the batch from host memory, for every QSA layer, before the sparse chunk prefill runs. The sparse prefill then loads K/V only at the top-k positions each query row selects. A long cached prefix with a short extend, such as a multi-turn follow-up, pays a host-to-device copy of the full prefix per layer for a few thousand rows it actually reads.

**Series.** Stacked on PR 2/N (`qsa-kv-host-offload-fused`) and must merge after it. It needs only the offload's extend path; it sits on 2/N because 2/N adds `qsa_kv_offload_kernels.py`, where the new Triton kernels live. No new flag: outputs are bit-identical by construction (below).

## Modifications

- **`mem_cache/qsa_kv_offload_kernels.py`:**
  - `mark_context_rows(indices, cu_seqlens_k, extend_seq_lens, total)`: one Triton kernel that flags, in the packed context, every row some query row's top-k references (`cu_seqlens_k[r] + j` for `j >= 0`). Indices with a group dimension are flattened per row.
  - `gather_selected_rows(...)`: copies only the flagged rows from the pinned host store, through their UVA addresses; other rows of the output are left unwritten.
- **`mem_cache/qsa_kv_offload.py`:** `QSAKVHostOffload.gather_context(..., selected=None)` uses the selected-row copy on CUDA (not ROCm) and keeps the full copy otherwise.
- **`layers/attention/qsa/kv_offload_attention.py`, `qwen_sparse_attn_backend.py`:** `gather_offloaded_context` (the backend passes it the extend's `topk_indices`) marks the rows from the extend's `topk_indices` and gathers only those. In debug verify mode (`SGLANG_DEBUG_QSA_KV_OFFLOAD_VERIFY`), it rebuilds the read set with torch from the query rows' owners, checks the mark against it, and compares the gathered context with the full pool's on that set.
- **Tests:** `test_qsa_kv_offload.py` (GPU, BF16 and FP8 K/V): a two-request chunk prefill on cached prefixes. The mark must equal a read set built independently in the test (also with a grouped index layout), the copied rows must equal the host rows, and the sparse prefill output must be bit-identical to the full-context output when every unmarked row holds NaN. A mark that missed a row the prefill reads turns the last check red.

Why it is exact: `_sparse_gqa_chunk_prefill` loads K/V only at column positions `token >= 0` of a row's top-k (masked loads, `other=0`), relative to `cu_k[batch]`. Every such row is marked, so unmarked rows are never read.

## Accuracy Tests

Bit-exact by construction; no output change.

- **Unit test** (above): bit-identical prefill output with NaN in every unmarked context row, BF16 and FP8, on RTX PRO 6000 Blackwell and H100. `test_qsa_kv_offload.py` with the series' `test_qsa_kv_offload_backend.py` 17 passed, `test_qsa_kv_offload_unit.py` 16/16, and the upstream `test_qsa_fused_kv_prepare.py` with `test_qsa.py` 474 passed (1 skipped).
- **End to end, verify mode** (`SGLANG_DEBUG_QSA_KV_OFFLOAD_VERIFY=1`), the 24-request mix of PR 1/N (long prompts up to 29K tokens, multi-turn radix hits, a shared 20K prefix, concurrent batches), decode CUDA graphs on: on RTX PRO 6000 Blackwell Server Edition at TP1 with every decode batch size captured (`--cuda-graph-bs-decode 1 2 3 4 5 6 7 8`): all 24 requests served, **30,180 bit-exact checks, 0 mismatches**. Inside the server on 8x H100 (FP8, TP8/EP8), the sparse prefill output from the selected rows equals the output from the full-pool context in 5,088 of 5,088 extend attention calls.

## Speed Tests and Profiling

Public `nvidia/Qwen3.8-Flash-Next-NVFP4`, one RTX PRO 6000 Blackwell Server Edition (600 W), one job, the two trees swapped in A-B-B-A order on the same GPU (A: PR 2/N; B: this change before the review fixes, which do not alter the copy path). Server: `--tp 1 --quantization modelopt_fp4 --mem-fraction-static 0.93 --max-running-requests 32 --chunked-prefill-size 4096 --disable-prefill-cuda-graph --context-length 65536 --enable-qsa-kv-offload --qsa-kv-offload-host-size 60 --qsa-kv-offload-hot-blocks 1024`. Load: `python -m sglang.benchmark.serving --dataset-name generated-shared-prefix --gsp-num-groups 4 --gsp-prompts-per-group 6 --gsp-system-prompt-len 60000 --gsp-question-len 256 --gsp-output-len 8 --max-concurrency 1` (24 requests: a 60K cached prefix plus a 256-token question), 2 repeats per arm.
