# [Fix] [AMD] diffusion: Accept residual and skip_bias in the ROCm Conv3d-to-Conv2d VAE patch

[Upstream PR](https://github.com/sgl-project/sglang/pull/44672) · state: closed · merged: True

## Original PR description

## Motivation

**What goes wrong**
Wan VAE decode on ROCm fails with `TypeError: RocmPlatform._replace_conv3d_with_conv2d.<locals>._patched_forward() got an unexpected keyword argument 'residual'`. #38650 made the Wan VAE decoder call `WanCausalConv3d` with `residual=` and `skip_bias=` (the fused conv-bias epilogue). The ROCm Conv3d-to-Conv2d replacement installs its own `forward` that only takes `(x, cache_x)`, so the decoder's first patched conv call raises.

**Where it shows up**
Any ROCm device that enables the patch (`SGLANG_USE_ROCM_VAE_CONV2D=1` or `SGLANG_USE_ROCM_VAE_CONV2D_BF16=1`) and decodes with the Wan VAE through the non-fused cache path. Reproduced with Wan2.2-T2V-A14B on gfx1250: denoising completes, then DecodingStage fails.

**How to fix**
Accept `residual` and `skip_bias` in the patched forward with the same contract as `WanCausalConv3d.forward`: drop the bias when `skip_bias` is set, add `residual` to the conv output.

## Modifications

- `runtime/platforms/rocm.py`: `_patched_forward` takes `residual=None, skip_bias=False`, passes `None` as bias when `skip_bias`, and adds `residual` to the output.
- `test/unit/test_rocm_conv3d_patch.py`: regression test that the patched conv matches the original `WanCausalConv3d` with `residual` and with `skip_bias`. It fails on the pre-fix code with the same `TypeError` and passes with the fix.
