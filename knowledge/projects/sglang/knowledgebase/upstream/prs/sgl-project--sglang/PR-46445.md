# [Feat] KVShard: opt-in Rust tree backend with rotation-phase support

[Upstream PR](https://github.com/sgl-project/sglang/pull/46445) · state: open · merged: False

## Original PR description

## Motivation

KV-sharded prefill requires a tree core that preserves page rotation. The Rust core tracks rotation bases but is rejected by the launch gate and lacks the rotation-phase query used for owner-matched HiCache backups.

Allow explicit Rust selection while preserving Python as the default for sharded launches:

```bash
SGLANG_UNIFIED_RADIX_TREE_CORE_BACKEND=rust
```

Non-sharded launches keep their existing default. Explicit Rust selection retains the normal supported-platform/toolchain fallback policy.

## Changes

- Add `rotation_phase_of` to the Rust core, production/inspection PyO3 bindings and Python adapter. The result is the chain rotation base plus the ancestor prefix length in pages; root and unrotated nodes return `None`.
- Permit explicit Python/Rust selections in the sharding gate and reject unsupported backends.
- Reuse the existing rotation-phase test class for both Python and Rust, including the host-backup consumer's handling of owner zero and unsharded nodes.
- Extend native tests to page sizes 1, 4 and 64, rotation bases zero and two, multiple ancestor splits, and unsharded nodes.
- Document explicit Rust opt-in for KV-sharded prefill.

Updated onto main `46caa54562a97e71d9b937c62875c90b39274b0d`. #42973 is merged; the Python rotation-phase interface and sharding default are now upstream, so they are no longer duplicated in this PR's diff. The remaining increment spans eight files.
