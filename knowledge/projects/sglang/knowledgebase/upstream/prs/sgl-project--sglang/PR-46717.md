# [Feat] weight-sync: Add update_weights_from_colocated_param_bytes

[Upstream PR](https://github.com/sgl-project/sglang/pull/46717) · state: open · merged: False

## Original PR description

Stacked on #46716.

A colocated trainer process prepares each engine rank's param bytes in that rank's own layout (its replica ran this engine's loader). Inside a `sync_base` weight-update session, each TP rank pulls them from the trainer's CUDA-IPC transfer buffers over a node-local ZMQ socket and copies each byte range into its published weight locations: the bytes a P2P transfer-engine write covers, so `end_weight_update` finalizes them the same way. torch_memory_saver weights cannot be mapped by another process, hence a pull.

- A rank that publishes rank info describes its weight locations even without a Mooncake engine.
- `UpdateWeightsFromColocatedParamBytesReqInput{socket_paths_by_device_uuid, timeout_s}` through io_struct, HTTP, tokenizer and scheduler dispatch; each rank picks its socket by its GPU UUID.
- `weight_sync/colocated_param_bytes.py`: the wire messages (Hello / Shared / Write / Ack / End / Closed) and the copy loop. It checks sent vs published nbytes per param, and that every param the loader writes got bytes.
- Errors are acked to the trainer and all-gathered over the TP group, never raised; a silent trainer fails the sync after `timeout_s`.

Tests:
- `test/registered/unit/weight_sync/test_colocated_param_bytes.py` (1 GPU, 2 processes): bytes land; a size mismatch is acked and writes nothing; an unwritten loader param fails the sync.
- `test_scheduler_weight_version_tracking.py`: refused outside a `sync_base` session.
- End to end with the miles colocated p2p protocol on 8 × H200: `--check-weight-update-equal` with real weights passes on GLM-4.7-Flash bf16 and fp8.
