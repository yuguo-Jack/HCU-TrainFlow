# [Fix] moe: Gate expert location per FusedMoE for every draft layer

[Upstream PR](https://github.com/sgl-project/sglang/pull/45322) · state: open · merged: False

## Original PR description

## Motivation

Follow-up to #45299. That PR opted DeepSeek-V4 draft MoE layers out of the target's expert placement with a per-layer flag, but the flag was read in one place (the MegaMoE paths) while the other `DeepseekV2MoE` forwards still gated on `enable_eplb and not is_nextn` or `not is_nextn`, and the opt-out was keyed on DeepSeek-V4 only, so a DeepSeek-V3 / GLM NextN draft on MegaMoE with EPLB still routed its tokens through the live target map for layer 0.

## Modifications

- `DeepseekV2MoE` sets `uses_expert_location = not is_nextn`: every draft layer opts out, and gets no redundant expert slots.
- `FusedMoE.expert_location_dispatch_info()` is the single gate. The MegaMoE paths (CUDA and AMD FlyDSL) and all four `DeepseekV2MoE` forward paths call it; the per-site predicates are gone. `ExpertLocationDispatchInfo.init_new` returns None before touching the metadata when no dispatch algorithm is set.
- `FusedMoE.weight_loader` runs the opted-out case through the same physical-slot path as the metadata case, so a global-sized param (modelopt NVFP4 input scales) places its fused shared expert on each rank's shared slot under per-rank layouts instead of on slot `num_routed`.
- `DeepseekV4ModelNextN.forward` wraps the decoder in `disable_this_region()`, as `deepseek_nextn.py` and the DSpark model already do; without it the EPLB stat recorder sees the draft's topk with no layer index and fails during draft CUDA graph capture.
- `get_current_pass_count_buffer` returns None inside a disabled region, so the ROCm fused map+record path cannot add draft counts to a target layer's buffer.
- DSpark stores `stage_config` at construction instead of re-deriving it in `load_weights`.

With redundant experts, any NextN draft on MegaMoE now has its own expert count and so its own MegaMoE symm buffer, as #45299 already noted for DeepSeek-V4.

## Tests

- `test_megamoe_prefill_recorder.py`: a disabled region hands out no count buffer.

Not run on GPU. DeepSeek-V4 NextN MTP with `--enable-eplb` is the configuration the recorder change targets and still needs a GPU run.
