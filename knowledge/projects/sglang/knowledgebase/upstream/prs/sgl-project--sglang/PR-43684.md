# [diffusion] split and batch LTX-2.3 one-stage guidance passes under CFG parallel

[Upstream PR](https://github.com/sgl-project/sglang/pull/43684) · state: closed · merged: True

## Original PR description


## Motivation

LTX-2.3 one-stage uses multi-guidance (video/audio CFG + STG + modality), so each denoise step runs **4 DiT passes**: cond, neg, perturbed, modality.

`LTX2Pipeline` on LTX-2.3 takes the legacy one-stage path (`_should_use_ltx23_legacy_one_stage`), which had two problems:

- It excluded itself from CFG parallel: `stage1_cfg_parallel = enable_cfg_parallel and not use_ltx23_legacy_one_stage`.
- It ran the four passes as sequential batch-1 forwards.

The stage still declared `CFG_PARALLEL`, so the executor ran it on both ranks. With `--enable-cfg-parallel --cfg-parallel-size 2`, each rank computed all four passes, and 2 GPUs ran at the 1-GPU speed: **5.24 vs 5.23 s/step, 175.7 s per video**. 

Separately, multi-rank LTX-2 runs showed a **0–32 s gap between POST and "Sampling params"**. py-spy showed the cause:
- rank 1 was in the diffusers numpy `postprocess_video`, whose result is discarded on non-output ranks;
- rank 0 was meanwhile waiting in `broadcast_pyobj` for rank 1.

## Modifications

Three commits:

1. **Split the legacy one-stage guidance passes across CFG-parallel ranks.**
   - The legacy path now builds the same four `LTX2GuidancePassSpec` entries as the shared guidance code.
   - Pass `i` goes to rank `i % world_size`.
   - The per-branch x0 is combined with `_ltx2_combine_guided_x0_parallel_av`, which applies the same guider formula and order as the single-GPU path.
   - Passes still run one per forward in this commit, so 1-GPU output is bit-identical to before.
   - The old 4-forward block is removed. Most of the remaining diff is re-indentation.
2. **Batch each rank's guidance passes into one forward** with per-item `perturbation_configs`.
   - Perturbation masks are exact per item, so only GEMM/attention rounding moves. That is the `lossless` quality tier, which is the request default.
   - With DiT layerwise offload, this streams the weights once per step instead of once per pass.
   - `quality="exact"` keeps one pass per forward and stays bit-identical to the old schedule; it is still rank-split.
3. **Skip the LTX-2 video postprocess on non-output ranks.** Only replica rank 0 runs `postprocess_video`; other ranks return `video=None`.

New unit test `test_ltx2_cfg_parallel_guidance.py`: the rank-split combine is bitwise equal to the single-GPU combine at world sizes 2 and 4.

## Accuracy Tests

Setup: 768x512x121f, 30 steps, seed 42.

| Comparison | PSNR |
|---|---|
| `quality="exact"`, after vs before, 1 GPU and 2 GPU | identical (bit-exact) |
| Default quality, 2 GPU after vs old 1 GPU | 31.0 dB |
| Default quality, 1 GPU after vs old 1 GPU | 32.4 dB |
| Old code, own 1 GPU vs 2 GPU (reference) | 33.6 dB |

The middle frames have the same composition.

**Note:** with the default `lossless` quality, LTX-2.3 one-stage now takes the batched path on a single GPU as well, so default numerics move by rounding. If keeping the legacy default is preferred, commit 2 can be made opt-in. Commit 1 alone already gives the 2-GPU split.

## Speed Tests and Profiling

Setup: RTX 5090 32 GB (SM120, PCIe, no P2P), `--dit-layerwise-offload true --layerwise-offload-components dit text_encoder` (Gemma-3 already supports layerwise offload). Client wall-clock median of 3 runs after 1 warmup run.

| Config | Before | After |
|---|---:|---:|
| 2 GPUs, `--enable-cfg-parallel --cfg-parallel-size 2` | 175.7 s (5.24 s/step) | **73.4 s** (2.30 s/step) |
| 1 GPU | 161.7 s (5.23 s/step) | **146.3 s** (4.70 s/step) |
| 2 GPUs, gap between POST and pipeline start | 0–32 s | 0 s |

Batching 4 passes on 1 GPU did not raise peak memory here, because the peak comes from the text encoder, not denoising.

## Known issues not addressed here (shared code)

- The CFG_PARALLEL executor pickles CUDA tensors to rank 1, which opens an extra ~622 MB context on GPU 0.
- With 2 GPUs, `num_frames=33` is silently adjusted to 41 even when only CFG parallel is used.
