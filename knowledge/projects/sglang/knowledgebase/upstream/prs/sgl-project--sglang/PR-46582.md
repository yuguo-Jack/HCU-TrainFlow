# [Fix] [NPU] graph: Fix PP tensor handling in speculative replay

[Upstream PR](https://github.com/sgl-project/sglang/pull/46582) · state: open · merged: False

## Original PR description

## Motivation

GLM-5.2 produces garbled/repetitive output and low MTP acceptance with TP=2, PP=4, NEXTN, and NPU Graph enabled on Ascend 910B4.

The NPU graph replay path has two PP tensor handling issues:
- Preplanned verification does not refresh incoming PP tensors in the graph-bound buffers before replay.
- PP outputs are sliced by request count, truncating token rows when speculative verification uses multiple tokens per request.

Fixes #46581

## Modifications

- Copy incoming PP tensors into the existing graph-bound buffers before preplanned replay, preserving buffer addresses and avoiding attention metadata reinitialization.
- Skip transport markers that do not correspond to graph input buffers.
- Slice PP outputs to `bs * captured_req_width` to preserve all token rows in the selected graph batch.
- Add regression tests for repeated replay, in-place buffer updates, transport markers, padded batches, and token widths of 1, 2, and 4.
