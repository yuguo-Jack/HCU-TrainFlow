# [Feat] lora: MoE base-GEMM providers and the Triton BF16 vendor (14/21)

[Upstream PR](https://github.com/sgl-project/sglang/pull/42881) · state: closed · merged: False

## Original PR description

Part 14 of 21 of the LoRA runtime stack (branch `lora-stack-13-moe-providers`, base `lora-stack-12-moe-stages`). The stack is cut from the development branch of #42284.

## What this part adds

Add the provider contract (MoeBaseProvider, prepare/gateup/act/down over a
row domain), the masked and contiguous row domains, input alignment, the
BF16 quant info, and the Triton BF16 vendor. Vendors are selected per weight
family.

Tests: provider contracts and fused dispatch numerics.

## Verification

- GB300 run r45: the tree of upstream main `c1c287a429` plus parts 01–14 imports every module this part changes and passes this part's tests together with every earlier part's unit tests: **395 passed, 20 warnings, 152 subtests passed in 27.17s** (excluding the tests that fail identically on the untouched base tree in that environment).
- `pre-commit` passed on the changed files of every part; `pre-commit run --all-files` passed on the complete stack tree.

The complete 21-part tree equals the development branch of #42284 at `e7b7179a86` (the `6588053ef2` tree with four test-only follow-ups squashed into its dense commit: the admission/snapshot trim, the restored FP8 block-shape admission pin, a second trim that keeps only the tests guarding silent failures and adds pins for four coverage gaps, and restored numerical and packing coverage; production code is unchanged) minus the benchmark tools and the Triton MoE tuning tables, which follow in separate PRs.
