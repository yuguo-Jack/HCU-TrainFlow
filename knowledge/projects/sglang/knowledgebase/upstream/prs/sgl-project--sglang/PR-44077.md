# [Fix] sgl-router: Retry a send once when a pooled connection was closed

[Upstream PR](https://github.com/sgl-project/sglang/pull/44077) · state: closed · merged: False

## Original PR description

## Motivation

sgl-router keeps idle upstream connections pooled for reqwest's default 90 s, while SGLang's HTTP server closes idle keep-alive connections after 5 s (`SGLANG_TIMEOUT_KEEP_ALIVE`, uvicorn's default). A request sent on a pooled connection just as the engine closes it fails before any response (`Connection reset by peer`, `connection closed before message completed`). hyper retries only requests it had not started writing, and `--retry-max-attempts` only moves to a worker not yet tried, so with one worker for the role the client gets a 502; with more, the request pays a retry and its backoff. Any connection left idle for about 5 s can hit this, at any load.

## Modifications

- Idle pooled connections expire after 3 s, under the engines' default 5 s keep-alive, so the router stops reusing a connection before the engine closes it.
- Plain, PD prefill and PD decode forwards (`forward_json_to` / `forward_streaming_to`) resend once, immediately, to the same worker when an HTTP/1.1 send fails with a reset, broken pipe or EOF before any response, which also covers engines with a shorter keep-alive. Connect errors, timeouts and failures after the response head are not resent; `--retry-max-attempts` is unchanged.
- The resend cannot run a request twice, PD pairs included: an HTTP/1.1 connection carries one request at a time, and an engine that closes an idle connection never reads the request that meets the close. h2c is excluded, since one connection carries many requests.
- `hyper` becomes a direct dependency for `Error::is_incomplete_message` (`Cargo.lock` unchanged). README: Retries.

## Testing

- New `proxy::tests::closed_connection_is_retried_once`, against a raw HTTP/1.1 worker: a reset or EOF on the first connection is resent and returns 200 (502 after one connection without this change); a worker that closes every connection returns 502 after exactly two; one that never answers returns 504 after one.
- Passing: `cargo +nightly fmt --all -- --check`, `cargo check`, `cargo clippy -- -D warnings`, `cargo test --release --workspace -- --skip parity_matrix`.

## Benchmark (MI355X)

Same setup as #44072: DeepSeek-V4-Pro, 1 prefill + 1 decode engine with 8 DP-attention ranks each, AgentX trace replay with AIPerf, 1 h per concurrency, sgl-router built at 1e86143bf0, engines at the default 5 s keep-alive.

The runs predate this patch. The after runs remove the race from the engine side instead, with `SGLANG_TIMEOUT_KEEP_ALIVE=300` (longer than the router's 90 s pool); this PR's 3 s pool timeout removes it from the router side.

Failed requests per 1 h run (AIPerf), before → after:

| conc | round-robin decode ranks | least-in-flight decode ranks |
|---|---|---|
| 192 | 8 → 0 | 2 → 0 |
| 256 | 10 → 0 | 11 → 0 |
| 384 | 7 → 0 | run aborted in warmup, twice → 0 |
| 512 | 9 → 0 | run aborted in warmup; rerun 4 → 0 |

- Every before run hit the race: 2–11 failed requests per hour (≤0.04% of requests), all 502s except two 503s from the breaker the resets opened in one run (#44075). The sends failed with `Connection reset by peer`, plus a few `connection closed before message completed` and broken pipes, on both prefill and decode, always before any response.
- AIPerf aborts a run on any failure during warmup, which cost three runs.
- `sgl-model-gateway` hit the same race on the same cluster in 54 of 88 PD runs and hid it by retrying, on the same worker when there is one per role; sgl-router's `--retry-max-attempts` only moves to workers not yet tried.
- Throughput and latency of these runs are in #44072; they did not change beyond run-to-run noise.
