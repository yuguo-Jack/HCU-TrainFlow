# [Perf] [NVIDIA] dsv41: Engram DP lookup as an id push plus an MXFP8 row push

[Upstream PR](https://github.com/sgl-project/sglang/pull/45666) · state: closed · merged: False

## Motivation

Under DP attention, `EngramEmbedding._dp_sharded_lookup` all-gathers every rank's hash ids, looks up the rows each rank owns for all ranks' tokens into a `[DP x tokens, 24, 256]` BF16 buffer, reduce-scatters it, and then `wkv` quantizes the result to MXFP8. The all-gather and the reduce-scatter grow with the DP size and dominate the lookup at decode sizes.

## Modifications

`SGLANG_OPT_DSV41_MEGA_ENGRAM=1` (off by default) replaces that path with two kernels and no collective (`python/sglang/kernels/jit/csrc/deepseek_v4/engram/mega.cuh`), launched by one host call:

- `engram_id_push_kernel`: each rank sends each of its `[T, 24]` hash ids to the rank that owns the row, as 8 B packets `{t * 24 + col, row}` into the owner's receive buffer. The owner is computed from the id, matching `engram.shard_range`: by hash column when `24 % R == 0`, else the equal-row split through an exact multiply-high (the magic and its exactness are checked on the host at load).
- `engram_scatter_kernel`: after a per-block cross-rank barrier (multicast above 2 ranks), each owner reads the requested FP8 rows and E8M0 scales from its own shard (device or per-rank host table) and writes them straight into the requester's wkv input in FlashInfer's 128x4 swizzled layout, so `wkv` takes it as `Mxfp8SwizzledInput` without a separate quantize. Work is dealt as (source, tile) items over a grid coprime with R.
- Both kernels support PDL.

Python: `kernels/ops/communication/mega_engram.py` (`mega_engram_lookup`) and `srt/layers/communication/mega_engram.py` (`MegaEngramWorkspace`, one per process, with one `attach` per Engram table). `Engram.prepare_mega_engram` binds the table after loading when the lookup runs under DP attention on per-rank shards; `Engram.forward` uses it when `wkv` takes 128x4 MXFP8 input and the step's largest DP rank fits `SGLANG_OPT_DSV41_MEGA_ENGRAM_NUM_MAX_TOKENS_PER_RANK` (default: one rank's largest prefill chunk), else it keeps the old path. Every rank takes the same path every step.

Other: `kMaxWorldSize` 16 -> 64 in `sgl_kernel/distributed/communicator.cuh`; `custom_all_reduce_v2._allocate_symmetric_memory` is now public.
