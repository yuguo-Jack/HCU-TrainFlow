# Honor OOT attention defaults for Gemma4

[Upstream PR](https://github.com/sgl-project/sglang/pull/41293) · state: open · merged: False

## Original PR description

## Motivation

SGLang's generic attention-backend resolution lets an out-of-tree platform provide its default through `SRTPlatform.get_default_attention_backend()`. Gemma4 bypasses that contract: its model-specific override resolves the backend earlier to a built-in `triton` or `trtllm_mha` default, and its subsequent static allowlist rejects a platform-provided backend.

As a result, an out-of-tree platform cannot use its registered attention backend as the Gemma4 default even though the same platform API works for other MHA models.

## Modifications

- Use the active out-of-tree platform's declared default for non-diffusion Gemma4 models when no attention backend was explicitly selected.
- Accept that same platform-owned default in Gemma4's backend validation.
- Preserve the existing built-in CUDA/SM100 defaults, the DiffusionGemma `triton` default, and explicit common or split backend selections.
- Add focused unit coverage for out-of-tree defaulting, explicit selection, split prefill/decode selection, validation, and DiffusionGemma behavior.

## Accuracy Tests

This change only affects startup-time backend resolution and does not modify model math.

- Added a fake out-of-tree platform regression test in `test/registered/unit/test_model_overrides.py`.
- Isolated behavior checks passed for unset, explicit common, split prefill, split decode, validation allowlist, and DiffusionGemma cases.
- Full registered unit tests have not yet been run locally because the current development environment does not contain the SGLang test dependencies.

## Speed Tests and Profiling

Not applicable. The new checks run only during server-argument resolution and do not affect the inference hot path.
