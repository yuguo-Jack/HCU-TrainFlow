# [Refactor] bcg: Delete capture leftovers and rename `capture_stub` to `on_capture`

[Upstream PR](https://github.com/sgl-project/sglang/pull/46792) · state: closed · merged: True

## Original PR description

Since #46719 the capture pass records each graph break without running it. This removes what that left with no effect.

- Delete the capture stubs that only filled outputs: DeepEP MoE a2a, paged experts, radix linear attention, pooled-indexer prefill, and the CP interleave indexer. Nothing reads those outputs at capture.
- Delete `barrier_fn` from `BreakableCUDAGraphCapture` and its two callers. It synced ranks before break bodies with rank-coupled collectives, and none run at capture now.
- Delete the capture-var hiding in the DeepSeek V4 decoder tail break. The body never runs while the outer graph captures.
- Rename `capture_stub` to `on_capture`. It now adds host setup at capture instead of replacing the body. The remaining users are the DeepSeek V4 tail enter and exit, the tail source KV layer id, and the Nemotron-H shared-expert side graph.
- Tests: drop the `_barrier_fn` mocks and follow the rename.

No behavior change at replay. At capture, ranks no longer barrier at each break, and the deleted stubs no longer write their output buffers.

Known issue on HIP, pre-existing and not changed here: under the breakable prefill graph, the decoder SWA bounded-replay tail is switched in only at capture, not at replay.
- The HIP backend builds no graph tail metadata at capture (`init_forward_metadata_for_breakable_cuda_graph_capture` in `deepseek_v4_backend_hip_radix.py`) and refreshes none at replay, so `LateLayerTail.scatter_indices` is None and `tail_in_graph` is False.
- `deepseek_v4.py` then takes the eager branch, `attn_backend.enter_late_layer_tail(...)`, which is segment code: it runs while the graph captures and never at replay. Replays reuse the capture batch's tail rows and metadata, and `tail_source_kv_layer_id`, which the source KV break sets at every replay, is never cleared.
- CUDA runs this switch as a graph break since #43736; the HIP path (#37810, #41308) has no counterpart. Not reproduced on AMD hardware.
- Possible fixes: give the HIP backend the CUDA graph-tail path, or turn decoder SWA bounded replay off on HIP while the breakable prefill graph is on.

Tests run at this head on B300 and GB300 pass:
- the BCG, eager-on-graph, radix attention, radix linear attention, paged experts and CP strategy unit tests;
- `test_breakable_cuda_graph.py`, `test_bcg_with_speculative_decoding.py`, `test_dp_attention_bcg_kl.py`, `test_bcg_with_lora.py`, `test_lora_moe_prefill_cuda_graph.py` and `test_mamba_cache_kl.py`;
- the DeepSeek V4 Flash FP4 tests (TP 4);
- the DeepSeek V4.1 Flash bounded-tail and encoder BCG tests;
- the multimodal BCG unit tests and the Z-Image Turbo BCG tests (single GPU and TP 2).

Two tests fail the same way on main: the `test_paged_experts.py` GPTQ class and one `test_deepseek_v41_bcg_multimodal.py` case.
