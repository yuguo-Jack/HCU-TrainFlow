# [Test] [AMD] debug-utils: Opt TestCrashDump into expect_server_exit

[Upstream PR](https://github.com/sgl-project/sglang/pull/45408) · state: closed · merged: True

## Original PR description

## What

Set `expect_server_exit = True` on `TestCrashDump` in `test/registered/debug_utils/test_crash_dump.py`.

## Why

#45053 added a fail-fast watcher to `CustomTestCase._callTestMethod` that calls `os._exit` as soon as the class's server process exits non-zero. `TestCrashDump` sets `SGLANG_TEST_CRASH_AFTER_STREAM_OUTPUTS` so the server crashes on purpose, and then checks that a crash dump was written. The watcher fires first (`[FIXTURE FAIL-FAST] server ... exited rc=-9; aborting.`), so the file exits 137 before the assertions run.

#45172 added the `expect_server_exit` opt-out, which skips both the watcher and the retry, but only applied it to `test_self_e2e_perturb_raise.py`. This applies it to the other test that crashes its own server.

Failing nightly jobs (all three ROCm lanes of the AMD nightly 1-GPU unit suite):
- https://github.com/sgl-project/sglang/actions/runs/39295902328/job/118208221369
- https://github.com/sgl-project/sglang/actions/runs/39295902328/job/118208221470
- https://github.com/sgl-project/sglang/actions/runs/39295902328/job/118208221787

The same file is also registered for the CUDA nightly, which goes through the same `CustomTestCase` path.

## Test plan

- `python -m py_compile` on the changed file passes.
- Passed on MI300 (rocm10) in a dispatched `nightly-test-1-gpu-unit` run on this commit: https://github.com/sgl-project/sglang/actions/runs/39461778070/job/118762845063 (`test_crash_dump.py` passed, no `[FIXTURE FAIL-FAST]` abort).
