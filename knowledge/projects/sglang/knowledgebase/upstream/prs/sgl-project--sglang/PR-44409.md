# [CI] [AMD] ci/slurm: Add a Mooncake KV-transfer test to the MI355X disaggregation nightly

[Upstream PR](https://github.com/sgl-project/sglang/pull/44409) · state: closed · merged: True

## Original PR description

## What
Add a Mooncake KV-transfer test to the MI355X disaggregation nightly: DeepSeek-V4-Flash FP4, 1 prefill + 1 decode node, same settings as the MORI one.

- `launch_mi355x.sh`: when a recipe sets `kv_transfer_backend: mooncake`, pass `MC_GID_INDEX=1` (the routable RoCEv2 GID on this network). A recipe can also set `mc_disable_hip: 1`. MORI recipes are unchanged.
- New recipe `1p1d-mooncake.yaml` and its entry in `nightly-configs.yaml`.

## Depends on
#44404 (Mooncake bump in the ROCm image). Until the nightly image has it, this test fails on the first request.

## Validation
Ran on two MI355X nodes with the ROCm 10 image rebuilt with Mooncake v0.3.14-rc1: all 7 concurrencies (1 to 256) completed, GSM8K 0.926 (gate 0.91), no transfer errors.
