# [Diffusion] Cache static text conditioning per request (Krea2 first)

[Upstream PR](https://github.com/sgl-project/sglang/pull/46873) · state: open · merged: False

## Original PR description

## Motivation

Text conditioning in several multimodal_gen DiTs is recomputed on every denoising step even though it only depends on the prompt and the weights. Helios already caches this per request on `forward_batch.extra`. This PR lifts that into a shared helper on `BaseDiT` and applies it to the other models that have the same pattern.

## Modifications

Shared helper (`dits/base.py`)
- `_request_cache` / `_tensor_key` moved from Helios into `BaseDiT`. Helios behavior is unchanged.
- `cached_per_request(name, inputs, compute)` (also `BaseDiT._cached_per_request`): runs `compute()` once per request for the same input tensors.
  - Key is tensor identity (data_ptr, shape, stride, dtype, device). Non-tensors fall back to `id()`.
  - Lives in `Req.extra`, so it is dropped with the request. Weight and LoRA updates happen between requests.
  - The entry holds its inputs so their data_ptr cannot be reused within the request.
  - Disabled with no forward context or with grad enabled.
  - At most 4 entries per name, so inputs that change every step cannot pile up.

Call sites
- Krea2: `text_fusion` + `txt_in`.
- SANA, SANA-Video, SANA-WM: caption projection / `y_embedder` once per request, and every block's cross-attn K/V projected once per request at the model level. This is done outside the compiled blocks so torch.compile sees no cache lookups. Under layerwise offload the block weights are not resident up front, so blocks project inline as before.
- Z-Image, Ming: caption embedder + context refiner once per request.
- LLaDA: T2I caption embedder + context refiner once per request. Editing stays uncached (its sequences are built with the source latents).
- Hunyuan3D-Paint: reference-attention K/V projected once per request from the stored reference. `StableDiffusionAttention` gets `project_kv` and an optional `context_kv`.
- LTX-2: left as is. It already projects prompt K/V once per denoising loop into persistent buffers that are reused across requests, which the shared helper would not improve.

Tests
- New `test_dit_request_cache.py`: reuse within a request, isolation across requests, no caching without context or with grad, cache bound, SANA model-level K/V once per request and inline fallback under offload.
- `test_krea2_fp8.py`: Krea2 reuse, pos/neg CFG separation, per-request isolation.

### Krea2 on GPU

1x H100 80GB (Modal), `lmsysorg/sglang:dev`. main = `de26bb16a9`, this PR = `dbd0f701de`. Same checkpoint, prompt ("A red fox sitting in fresh snow, golden hour, photorealistic."), seed 42, 1024x1024, Python `DiffGenerator` with default server args.

| | Krea-2-Turbo (8 steps, guidance 1.0) | Krea-2-Raw (50 steps, guidance 4.5) |
|---|---|---|
| Output vs main | bit-identical (max pixel diff 0) | bit-identical (max pixel diff 0) |
| `text_fusion` calls per request | 8 -> 1 | 100 -> 2 |

main vs main across two loads was also bit-identical, so the comparison is deterministic. The call count comes from a forward hook on `text_fusion` in the worker process.

Not covered: the ragged prompt batch (masked varlen path). `DiffGenerator` sends each prompt as its own request, so it needs a batching server to exercise.

### Other models on GPU

main = `de26bb16a9`, this PR = `dbd0f701de` (`ba949388d6` for Hunyuan3D-Paint), `lmsysorg/sglang:dev` on Modal, Python `DiffGenerator` with default server args, seed 42. One model load per side (main once, this PR once), each with 1 correctness run + 2 timed runs. Call counts are forward hooks on the text-path modules in the worker process, counted over the first request.

| Z-Image Turbo | L40S | 1024x1024, 9 steps | bit-identical | `cap_embedder` 9 -> 1 |
| Ming-Image-0.1-Design | H100 | 1024x1024, 12 steps | bit-identical | `cap_embedder` 12 -> 1 |
| LLaDA-Image-Turbo | H100 | 1024x1024, 4 steps | bit-identical | `cap_embedder` 4 -> 1 |
| Hunyuan3D-2 (shape + paint) | H100 | `assets/demo.png`, default steps | mesh identical; texture within main's run-to-run noise | paint `attn_refview.to_k` 480 -> 16 |

Video settings are reduced from the defaults to keep GPU cost down. SANA-WM runs with `SGLANG_SANA_WM_SKIP_REFINER=1`, so only the Stage-1 DiT this PR touches is measured.

- Hunyuan3D-Paint: the first run showed no cache hits, because the paint denoise loop set a forward context without `forward_batch`, which disables the per-request cache. Fixed in `ba949388d6` by passing the request through. Its texture is not deterministic run to run even on main: main vs main gives PSNR 51.4 dB (max pixel diff 225), and main vs this PR gives 51.3 to 52.0 dB, so this PR is within that noise. Mesh vertices match exactly. This one ran two loads per side to get that baseline.
- LLaDA-Image-Turbo needs `trust_remote_code=True` to load its text encoder.

## Benchmarking and Profiling

Krea2 only, same setup as above. main and this PR alternated over two rounds (separate model loads); each round ran 1 warmup + 3 timed runs, so 6 timed runs per side.

| | main median (range) | this PR median (range) | delta |
|---|---|---|---|
| Turbo end-to-end | 1.587 s (1.549-1.754) | 1.557 s (1.545-1.571) | within noise (see note) |
| Raw end-to-end | 18.21 s (18.19-18.24) | 18.14 s (18.10-18.23) | about -0.4% |
| Peak reserved memory | 37958 MB | 37958 MB | none |

Turbo note: main's second load ran slower (1.62-1.75 s) than its first (1.55 s), which moves the median. Round one alone is 1.552 s vs 1.547 s, so I would not read a gain into Turbo.

Text conditioning is a small part of a Krea2 step, so the gain there is small.

Other models, same runs as the table above. Only 2 timed runs per side from a single load each, so treat these as rough.

| Model | GPU | main | this PR | delta | Peak reserved memory |
|---|---|---|---|---|---|
| SANA 1.6B | L40S | 1.55, 1.38 s | 1.21, 1.20 s | about -13 to -20% | 14128 -> 14144 MB (+16) |
| SANA-Video 2B | L40S | 21.51, 21.54 s | 21.24, 21.33 s | about -1% | 20768 -> 20926 MB (+158) |
| SANA-WM Stage 1 | H100 | 2.50, 2.77 s | 2.44, 2.34 s | about -8% | 13830-13864 -> 14072-14232 MB (+240 to +370) |
| Z-Image Turbo | L40S | 2.73, 2.74 s | 2.78, 2.77 s | none (about +1.5%, noise) | 22138 -> 22140 MB |
| Ming-Image-0.1-Design | H100 | 2.10, 2.10 s | 2.08, 2.08 s | about -1% | 21808 MB, no change |
| LLaDA-Image-Turbo | H100 | 0.62, 0.62 s | 0.65, 0.62 s | none | 50282 MB, no change |
| Hunyuan3D-2 (shape + paint) | H100 | 27.45, 27.60 / 33.18, 33.42 s | 33.63, 33.33 / 33.21, 32.53 s | none clear (main's two loads differ by 6 s) | 8790-9218 -> 9464-10618 MB (+0.7 to +1.4 GB) |

The SANA family gains the most, since every block's cross-attn K/V is cached; the extra memory is that cached K/V. Hunyuan3D-Paint pays the most memory for its cached reference K/V with no clear latency gain, so it may be better left out. SANA and SANA-WM need more timed runs before quoting a number, as main's two runs differ noticeably.
