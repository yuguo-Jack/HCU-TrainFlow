# [Test] KVShard: Extend HiCache E2E with GLM accuracy coverage

[Upstream PR](https://github.com/sgl-project/sglang/pull/46789) · state: closed · merged: True

## Original PR description

## Motivation

Follow up on [the accuracy-test request in #42973](https://github.com/sgl-project/sglang/pull/42973#issuecomment-6436606158). Extend the existing `test_dsa_glm52_pd_kv_shard_hicache.py` with GSM8K accuracy coverage for KV sharding and CPU HiCache together.

## Modifications

- Use a single `base-c / 4-gpu-gb300` registration for the existing reload regression and both accuracy cases. All use P2/D2 with prefill CP2; decode uses GPUs 2–3. Retain the known GB300 fabric transport and exportable allocator: `MC_FORCE_MNNVL=true`, `SGLANG_MOONCAKE_CUSTOM_MEM_POOL=NVLINK`, staging disabled.
- Preserve the original cold/device-hit/host-reload assertions. Reuse its request and cache-counter helpers.
- Retain the layer-split scoring settings: 1319-question cap, 20 shots, 48 evaluation threads and a **0.935** accuracy floor. The evaluator excludes the 20 demonstrations, leaving 1299 held-out questions. The 32-question Mixed-MoE smoke retains its **0.8** floor and uses target DeepEP with D-side DP2/EP2 plus a TP-only draft.
- Seed the evaluator prefix into write-through HiCache and wait for its D2H backup. Two independent 12,288-token prompts exceed CP2's 16,384 logical GPU slots while fitting in the 4× host cache. Score without flushing the host copy and require H2D growth during evaluation.
- Bound the accuracy fixture's context length to 16,384, decode pool to 65,536 tokens and ordinary decode concurrency/graph size to 48; Mixed-MoE retains an eight-request limit. Disable decode prefix reuse and check decode-side MTP activity.
- Add the standalone [KV sharing guide](https://github.com/HZY-Wade/sglang/blob/codex/glm-sharded-hicache-accuracy/docs/docs/advanced_features/kv_cache_sharing.mdx), its navigation entry and updated argument reference. Remove only the duplicated GLM KV sharing section from the P/D overview. The guide distinguishes its deployment recipe from the four-GPU CI fixtures.

## Accuracy Tests

Local validation using the project `.venv`:

- Exactly one CI registration and three active tests with four visible GPUs; hardware tests skip when fewer than four are available.
- All six P/D launch configurations parse, including DP2/EP2 for Mixed-MoE; both sides retain the GB300 transport environment.
- The original reload test body and both accuracy floors remain unchanged.
- Eight mocked control-flow cases pass: success and expected failures for missing H2D reload, insufficient accuracy and missing MTP activity, for both accuracy cases.
- Applicable pre-commit checks and documentation build/link validation pass.

On head `e19de3aef0`, the [four-GB300 hardware job](https://github.com/sgl-project/sglang/actions/runs/40650131890/job/122688169704) passed the reload regression and the full GSM8K test, scoring **0.9438029253271748 >= 0.935**, including its H2D and MTP assertions. Mixed-MoE failed during decode setup: target + draft weights required a static-memory fraction above approximately 0.870, exceeding the inherited 0.85 budget. This change overrides **only Mixed-MoE decode to 0.90**, retaining the 65,536-token KV cap and accuracy floors; parser checks and pre-commit pass. **The corrected Mixed-MoE case still needs hardware verification.** The CI time estimate remains 600 seconds.
