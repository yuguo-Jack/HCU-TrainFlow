# [Fix] [AMD] docker: Repair the AITER build step after the 2bb549102 pin bump

[Upstream PR](https://github.com/sgl-project/sglang/pull/44534) · state: closed · merged: True

## Original PR description

## What

Fix two leftovers from the AITER pin bump in #44379 that break the AITER build step in `docker/rocm.Dockerfile`:

1. Drop the trailing `\` after `pip install -r requirements.txt`. #44379 removed the gfx1250 `git revert` block that followed it but kept the continuation. Dockerfile continuations skip blank and comment lines, so the next `COPY --from=local_src ...` got appended to the `pip install` command (`no such option: --from`).
2. Remove the gfx942/gfx950 AITER patch block (the ROCm/aiter#6042 cherry-pick, the ROCm/aiter#5967 CSV diff, and the ROCm/aiter#6007 `other=127` sed). ROCm/aiter#5967 and ROCm/aiter#6007 are in the new pin `2bb549102`. The cherry-pick conflicts in `pa_decode_sparse.py`.

**Correction:** ROCm/aiter#6042 is *not* in the pin; it merged after it. #44539 restores that patch using its squash-merge commit.

## Why

Today's scheduled nightlies failed on every flavor: gfx1250 on (1), and gfx942/gfx950 on (2).

- ROCm 10.0: https://github.com/sgl-project/sglang/actions/runs/38734502837
- ROCm 7.2 / 7.2.4: https://github.com/sgl-project/sglang/actions/runs/38733045567

## Test plan

- `release-docker-amd-rocm10.yml` dispatched for gfx942-rocm1000 with only fix (1): https://github.com/sgl-project/sglang/actions/runs/38781603589. The AITER step no longer swallowed the `COPY`, then failed on the ROCm/aiter#6042 cherry-pick conflict, which is what surfaced (2).
- After merge, `release-docker-amd-rocm10.yml` on main passed for all four images (gfx942, gfx950, gfx1250, gfx1250-rocm101): https://github.com/sgl-project/sglang/actions/runs/38784940437. ROCm 7.2 with #44539 on top: https://github.com/sgl-project/sglang/actions/runs/38803779443.
