# [Fix] diffusion: Log LoRA merge decisions only on first evaluation

[Upstream PR](https://github.com/sgl-project/sglang/pull/44376) · state: closed · merged: True

## Original PR description

## Motivation

Automatic LoRA merging caches the rounding-loss estimate, but currently repeats the same INFO message whenever a cached adapter configuration is evaluated again. Reactivating adapters can therefore emit identical explanations without a new decision.

## Modifications

- Emit the existing rank-zero diagnostic only when populating the rounding-loss cache.
- Preserve the first explanation for each newly evaluated configuration, including changed adapter strengths.
- Add parametrized coverage for cache hits, configuration changes, both ranks, and high, low, or unavailable loss estimates.

This does not change the merge threshold, adapter weights, or inference kernels, and introduces no additional deduplication state.

## Accuracy Tests

No model-output change is intended. Regression coverage is in `test_lora_auto_merge_rounding.py`.

## Speed Tests and Profiling

No inference speedup is claimed; this is a log-hygiene change.
