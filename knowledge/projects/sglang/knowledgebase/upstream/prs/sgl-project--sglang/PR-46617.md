# [Fix] function_call: Preserve valid DeepSeek calls when a sibling is malformed

[Upstream PR](https://github.com/sgl-project/sglang/pull/46617) · state: open · merged: False

## Original PR description

## Motivation

Part of #31915: one malformed tool call currently discards every valid sibling in DeepSeek V3/V3.1 non-streaming responses. For example, a valid weather call followed by invalid JSON returns no calls and exposes the raw tool-call markup as text.

Related previous fix: #32027, closed without merging.

## Modifications

- Handle parsing errors per call in both detectors, preserving valid calls in response order and the existing preamble.
- Handle a missing function-detail match explicitly.
- Preserve the original full-text fallback when parsing errors leave no usable calls. Unknown-tool filtering and empty sections retain their existing behavior.
- Add a CPU test file registered in the base-a CPU suite, covering malformed JSON or call structure before, between and after valid calls, multiple errors, all-invalid input, valid calls, plain text and unknown tools.

## Accuracy Tests

- 16 CPU test methods pass. On the unmodified base, the same suite reports 32 failures, including subtests.
- Tests use the real source protocol, detectors, environment and parser helpers. Only top-level package startup was bypassed locally to avoid unrelated serving dependencies; no detector or protocol code was mocked.
- Changed-file pre-commit checks and `git diff --check` pass.
- No model inference or accelerator tests were run.

## Speed Tests and Profiling

Not run. This change isolates errors in non-streaming tool-call parsing; no performance claim.
