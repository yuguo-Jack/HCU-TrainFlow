# [Perf] quantization: Speed up Hopper group32 FP8 quantization with FP32 scales

[Upstream PR](https://github.com/sgl-project/sglang/pull/48165) · state: open · merged: False

## Original PR description

## Motivation

The row-major FP32 power-of-two scale path uses `per_token_group_quant_8bit_v2` on the baseline. This PR routes the matching contiguous BF16 group32 case on Hopper to the existing trait-driven kernel. Both kernels use two lanes per group. For `[8192, 5120]`, the launch changes from 32 threads and 16 groups per CTA to 256 threads and 128 groups per CTA, reducing the observed grid from 81,920 to 10,240 CTAs. The trait-driven kernel also uses packed BF16 pairs for the local absmax and power-of-two scaling.

Six interleaved baseline/candidate H200 server restarts show median **8K TTFT falling 2.21% at c1 and 2.31% at c2**; the constructed real-text workload improves 2.86%. The cold-L2 kernel measurement is **100.257 → 31.761 μs (3.16×)**. The serving results include the complete dispatch and validation path. This builds on #26766's fused rounding; it does not remove another scale-rounding launch. Related #46838 targets column-major FP32 scales for DeepGEMM, whereas this change targets row-major group32.

## Changes and review fixes

- Separate power-of-two rounding (`kUe8m0`) from packed storage (`kPackedScale`). Preserve existing packed, sorted, masked and fused-activation specializations, including the external fused route+quant trait consumer.
- Accept supplied contiguous FP32 scale buffers only for flat 2D BF16 → FP8 E4M3 group32, without fused activation. The cached factory rejects unsupported combinations. Automatic packed-scale allocation is unchanged.
- Validate shape, dtype, device, contiguity, alignment and non-overlap before either launcher. This fixes the 16B-offset fallback previously bypassing output-buffer checks.
- Query the input device inside the existing opaque custom op. This removes import-time CUDA/NVML architecture detection and keeps pointers/device queries outside Dynamo tracing. Other architectures and 16B-but-not-32B-aligned views use v2.
- Match v2's NaN → −448 behavior for the FP32 specialization; retain NaN preservation for existing packed BF16 kernels. FP16 and other production combinations retain their existing dispatch.
- Fix the omitted template argument in `route_quant_fused.cuh`. The registered test now fails on compilation errors instead of converting them into skips.

Eight files; no model changes, production dependency, or server flag.
