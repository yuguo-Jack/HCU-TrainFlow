# [Perf] MOSS-Image: Fuse joint-block QKV projections in high quality

[Upstream PR](https://github.com/sgl-project/sglang/pull/46641) · state: closed · merged: True

## Original PR description

## Motivation

MOSS-Image joint blocks run three separate Q/K/V GEMMs for every conditional and unconditional denoising pass. This PR packs those projections for `quality=high` and lets the existing ordered RMSNorm+RoPE kernel read their strided Q/K views directly. The latter avoids copying Q and K back to contiguous storage after each packed GEMM.

The measured scope is MOSS-Image-Base, 1024×1024, 50 steps, batch 1 / concurrency 1 on one RTX PRO 6000 Blackwell Server Edition. Four repeated temporal pairs give a geometric-mean E2E speedup of **1.0141× over main** (1.386% lower latency) and **1.0222× over native Omni**; every pair is faster. The primary timed input is the fixed short product-photograph prompt; the long and Chinese prompts are quality checks. This is an eager optimization; it does not add or claim BCG coverage.

- Frozen main baseline: `af21e2b989e482cfdce39689126562f2209d53ac`.
- Tested PR head: `d752066eaa6f5091fa4c8daa2ba1d5d43a3928cd`.
- Native vLLM-Omni comparator: `817d4c17feb702289a2d2b2cbacfd594c262b7a7`.
- Common checkpoint: `OpenMOSS/MOSS-Image-Base@85975793d8b3d432f1b6e27f352abaa4c2a4c0d3`; all downloaded files were verified against the pinned file hashes.

## Modifications

- Reuse the existing checkpoint name mapping to merge Q/K/V in that order into one weight. There is no duplicate model weight or persistent view cache.
- Pass the quality choice through the request's denoising branch. `high` uses one packed GEMM; `exact/lossless` use three separate `F.linear` calls with fresh slices of the packed weight. A later request can change quality without reloading weights or mutating a module-wide mode.
- Extend the existing ordered norm+RoPE kernel to accept contiguous heads with a regular token stride. Reduction order and BF16 rounding in this kernel are unchanged; its result remains contiguous. Other layouts keep the existing fallback.
- Extend existing loading-order, quality-dispatch, offload/stream and numerical/stride tests; document the quality policy in the existing MOSS cookbook.

The protocol runs two symmetric main / PR / Omni / Omni / PR / main cycles on the same physical GPU: four fresh processes and 16 measured requests per arm. Each process first passes the three-prompt and repeated-short quality gate, then runs eight thermal warmups and four timed requests. All rows, including failed configuration screens, are retained. GPU0 UUID and owned PIDs are checked in archived NVML samples; GPU1 remains idle. No Torch/Nsight profiler runs during these timings.

HTTP E2E covers submission through receipt of all response bytes; client PNG decoding/writing is outside the timer. Startup and warmups are reported separately. Launch-to-ready uses each framework's native readiness boundary: SGL includes its configured 50-step built-in warmup, while Omni's health readiness precedes the qualification requests. This is not a same-work cold-start comparison. Both then receive the same quality sequence and eight extra thermal warmups. SGL native stage timing is enabled equally for main and PR. Its denoise stage includes the scheduler. † Omni denoise-core p50 is **14.417836 s** across four separately instrumented requests. Its default profiler did not time the actual MOSS full-forward loop, so an isolated diagnostic checkout adds four lines configuring the existing native profiler targets: `predict_noise_with_slg`, `scheduler_step_maybe_with_cfg`, encoder and VAE. Logs verify exactly 50 prediction and 50 Euler calls per request, and their sums agree with response metrics. This boundary excludes the surrounding Python loop/setup, unlike the SGL denoise stage. The primary Omni checkout and all primary E2E timing rows are unchanged. No cross-framework denoise speedup is inferred from these different boundaries.

Both SGL arms use the faster qualified explicit transformer cuDNN configuration. Omni's native Blackwell default already selects `CUDNN_ATTN`; it keeps regional compilation enabled with `TORCHINDUCTOR_EMULATE_PRECISION_CASTS=1`. The default compile configuration without cast emulation failed the restart quality gate (PSNR 27.449 < 28), so its timing is not used as a qualified comparison. SGL MOSS rejects torch.compile in this pinned source.

Strided norm+RoPE is **slower** than contiguous norm+RoPE, but removes the extra copies a packed-only implementation would require. The earlier packed-only prototype's Torch-flash trace added 166 BF16 copies per step (~5.75 ms total copy time); the final implementation preserves main's nine small copies. The model-level paired result above is the net benefit. These independent traces are diagnostic, not latency benchmarks. Whole-trace kernel sums contain different work outside the matched annotations and are not compared as E2E time. Both final traces have zero CUDA-graph launches.

### Reproduction

Use separate source checkouts at the exact baseline/head SHAs, installed into the same SGL environment. Put the verified checkpoint at `/task/cache/common/MOSS-Image-Base` and use the public `moss-workloads.json` unchanged.

```bash
CUDA_VISIBLE_DEVICES=0 HF_HUB_OFFLINE=1 FLASHINFER_DISABLE_VERSION_CHECK=1 \
SGLANG_DIFFUSION_SYNC_STAGE_PROFILING=1 OMP_NUM_THREADS=8 \
sglang serve --model-path /task/cache/common/MOSS-Image-Base \
  --backend sglang --num-gpus 1 --tp-size 1 --ulysses-degree 1 --ring-degree 1 \
  --performance-mode speed --disable-autocast true \
  --component-attention-backends transformer=torch_cudnn_sdpa \
  --enable-torch-compile false --enable-breakable-cuda-graph false \
  --warmup-resolutions 1024x1024 --warmup-steps 50 --host 127.0.0.1 --port 31030

# In the pinned Omni environment, after stopping the SGL server:
CUDA_VISIBLE_DEVICES=0 HF_HUB_OFFLINE=1 FLASHINFER_DISABLE_VERSION_CHECK=1 \
TORCHINDUCTOR_EMULATE_PRECISION_CASTS=1 VLLM_WORKER_MULTIPROC_METHOD=spawn \
OMP_NUM_THREADS=8 vllm serve /task/cache/common/MOSS-Image-Base \
  --omni --num-gpus 1 --host 127.0.0.1 --port 31031
```

Limits: this PR establishes the measured Base single-GPU eager high cell. It does not establish SFT, multicard, concurrent serving, other resolutions, quantization, or BCG gains. Lossless/exact retain separate projections; no new quality guarantee across attention backends is implied.
