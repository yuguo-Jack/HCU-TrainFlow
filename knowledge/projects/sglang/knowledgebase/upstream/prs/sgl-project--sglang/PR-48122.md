# [Perf] diffusion: Cache MiniMax-H3 reference and keyframe rows per image

[Upstream PR](https://github.com/sgl-project/sglang/pull/48122) · state: open · merged: False

## Original PR description

## Motivation

MiniMax-H3 reference images (Ref2VA) and keyframes (FL2VA) are encoded again on every request, even when a request reuses the same images, for example the same character references with a new prompt.

The shared conditioning cache (#40470) cannot hold them:

- **More than one GPU:** `cached_vae_encode` bypasses the cache whenever `world_size > 1`.
- **One GPU:** H3's `tiled_encode` calls the cached `encode` once per 256px tile. A reference resized to a 2048px short edge has 132–209 tiles, more than the cache's 128 entries. Each reference therefore evicts its own earlier tiles, and a repeat never hits. Instrumented runs showed 0 hits and 400 misses over two identical requests. Every tile also pays a device-to-host copy plus a SHA-256 hash.

## Modifications

- Add `cached_vae_call` to `runtime/cache/conditioning.py`. It caches a deterministic result derived from a VAE, keyed on the same numeric VAE settings as `cached_vae_encode`, which now shares that settings helper. Its optional `group` makes the ranks that run the computation agree on hit or miss.
- `minimax_h3_encode_keyframe_cond_rows` caches the packed condition rows per image. The encode seed is fixed, so the rows depend only on the image, and a hit returns the same bytes. The key covers the prepared image's pixels, the seed, and the latent normalization.
  - With parallel tiling, every replica rank encodes and all-gathers tiles. The replica group votes, so no rank skips the all-gather alone.
  - Otherwise only rank 0 encodes and broadcasts the rows as before, and it decides alone.
- Rows are stored as host tensors under the existing 512 MiB budget, LRU eviction, and weight-update invalidation. Nine 2048px references take about 23 MB of rows, compared with about 3 GB of tile posteriors. No device memory is used.

## Accuracy Tests

The H3 output is deterministic: the same request run twice without a cache produces a byte-identical MP4. With this change, every cache hit produced an MP4 byte-identical to the uncached output:

| Topology | References | Same prompt | New prompt |
|---|---|---|---|
| 2×H200, Ulysses 2 | 9 | identical | identical |
| 1×H200 | 3 | identical | identical |

## Speed Tests and Profiling

MiniMax-H3 Ref2VA. Settings: `reference_resize_mode=diffusers`, 768p, 16:9, 5 s, 2 denoising steps. Stage timings use `SGLANG_DIFFUSION_SYNC_STAGE_PROFILING=1`.

| | First request (miss) | Same references, same prompt | Same references, new prompt |
|---|---|---|---|
| 2×H200 · 9 references · `MiniMaxH3VisualEncodingStage` | 6.13 s (main: 6.7 s) | **0.19 s** | **0.19 s** |
| 1×H200 · 3 references · `MiniMaxH3VisualEncodingStage` | 4.35 s | **0.07 s** | **0.07 s** |

The miss also gets faster because per-tile hashing no longer runs inside the encode. The text encoder is unchanged, since its joint image and prompt input depends on the prompt.
