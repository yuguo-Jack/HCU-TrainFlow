# Fix zero-residual fallback in CUDA speculative sampling

[Upstream PR](https://github.com/sgl-project/sglang/pull/42534) · state: open · merged: False

## Original PR description

## Motivation

Fixes #42528.

A single-token nucleus can renormalize to `0.9999999403953552`. When the verification coin equals that value, the draft is rejected and removing its mass leaves an empty residual. The CUDA target-only sampler then emits the last vocabulary token, even though it has zero target probability.

Using the issue's FlashInfer top-k/top-p reproduction (vocabulary size 248320, eight rows):

| Verification coin | Before: first emitted token | After: first emitted token | Accepted drafts, before/after |
| --- | --- | --- | --- |
| `0.5` | 1174 | 1174 | 3 / 3 |
| `0.99999994` | 248319 (zero mass) | 1174 (nucleus token) | 0 / 0 |

## Modifications

Remember the last rejected candidate with positive target mass at the current tree node. Use it when residual sampling has no positive entry. Reset the remembered candidate after accepting a draft. The strict CDF comparison and acceptance bookkeeping stay unchanged.

Add regression cases for a rounded CDF equality, a coin above the rounded CDF, and siblings that exhaust the target support.

## Accuracy Tests

- Native registered sampling file through the CUDA JIT path: 10 passed. The three new cases fail against upstream. A `<=` comparison alone changes the existing interior CDF boundary (emits token 1 instead of 3 at coin 0.25) and still emits a zero-mass token in the shortfall and sibling cases.
- The issue's actual FlashInfer renormalization and CUDA sampling reproduction produces the table above.
- Fixed-seed differential: acceptance indices, counts and emitted tokens match upstream on 1024 seeded rows at each of two threshold settings (2048 rows total).
- Boundary checks pass for vector widths 1, 2 and 4 in deterministic and non-deterministic modes.

Run on an NVIDIA L40S with CUDA 13.0, Python 3.12.11, Torch 2.14.1 and FlashInfer 0.7.0.post1.

## Speed Tests and Profiling

CUDA graph replay of the sampler plus draft-buffer reset, median microseconds over five batches of 100 replays:

| Batch / draft width / vocabulary | Deterministic | Before | After |
| --- | --- | --- | --- |
| 1024 / 4 / 64 | yes | 27.32 | 27.14 |
| 1024 / 4 / 64 | no | 27.36 | 27.30 |
| 8 / 4 / 248320 | yes | 125.29 | 125.34 |

Observed medians differ by at most 0.86% in this one run per arm.

- clayboby · comment · 2026-10-08T09:33:40Z · [source](https://github.com/sgl-project/sglang/pull/42534#issuecomment-6056967267)

Hi @bIackr0se, thanks for picking up #42528 (I filed that issue). FYI there is a second PR for the same bug, #42850, which takes a different route, so the maintainers may want to look at both together.

Difference in approach:
- #42534 (this PR): remember the last rejected candidate with positive target mass at the node and emit it when the residual is empty.
- #42850: when the residual `(p - q)+` is empty, fall back to sampling from the target distribution `p` itself.

My reasoning for the target-sampling fallback: the empty residual can only arise from float rounding (in exact arithmetic the residual always has mass when the draft is rejected), so the fallback should keep the emitted token distributed like the target. Sampling from `p` does that for any shape of `p`; returning one remembered candidate is equivalent in the single-token-nucleus case from the issue, but when several candidates carry mass it deterministically favours one of them, and it needs extra per-node state in the kernel. #42850 also keeps the kernel change small and includes the reproduction from #42528 as a unit test.

Happy to fold your coin-table test into #42850 (or the other way round) — whichever the maintainers prefer. Both PRs are currently waiting on the `run-ci` label.

- bIackr0se · comment · 2026-10-19T10:11:28Z · [source](https://github.com/sgl-project/sglang/pull/42534#issuecomment-6264812262)

Thanks @clayboby, I agree that the empty residual comes from rounding and both fixes prevent the zero-probability token, with the difference confined to an event of roughly 2^-24 per node. The sibling loop uses one coin against cumulative target mass and copies each rejected sibling's mass into `draft_probs`, so an empty residual means that coin reached or exceeded the rounded total. My reason for retaining the last positive-mass candidate is that this coin falls in its interval in exact arithmetic: #42534 returns the token the CDF test would have selected without rounding. Your fallback in #42850 samples from `p` using the final-sampling coin, giving a target-distributed draw that can differ from the token selected by the original coin. The cost trade-off is one extra variable and no extra pass in #42534 versus a vocabulary-wide block reduction only on the rare empty path in #42850. I'm happy with whichever approach the maintainers prefer, and glad to fold my three coin-table cases (rounded-CDF equality, shortfall, and siblings exhausting support) into whichever lands.
