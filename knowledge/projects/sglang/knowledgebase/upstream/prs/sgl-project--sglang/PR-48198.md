# [Fix] tokenizer: Isolate per-request failures and skip cancelled requests in AsyncDynamicBatchTokenizer

[Upstream PR](https://github.com/sgl-project/sglang/pull/48198) · state: open · merged: False

## Original PR description

## Motivation

While auditing `AsyncDynamicBatchTokenizer` in `python/sglang/srt/managers/async_dynamic_batch_tokenizer.py`, we identified three reliability and overhead edge cases in the dynamic batching loop (`_batch_tokenize_loop`):

1. **All-or-nothing batch failure propagation**: When `batch_encode` raises an exception on a batch of `(prompt, future)` requests (for example, due to a single malformed input in the batch), the `except Exception as e` block previously set that exception on **every** future in the batch, causing all healthy concurrent requests in the same batch to fail.
2. **Cancelled caller futures in flight**: If a caller cancels or times out its `await tokenizer.encode(...)` future while queued in `self._queue`, `_batch_tokenize_loop` still included the cancelled prompt in the `batch_encode` call and then called `fut.set_result(...)` / `fut.set_exception(...)`. Although `if not fut.done():` guarded `InvalidStateError` on completion, tokenizing already-cancelled prompts wastes batch slots and CPU tokenization work.
3. **Unnecessary timer task creation when the queue already holds a full batch**: `_batch_tokenize_loop` created an `asyncio.create_task(asyncio.sleep(self.max_batch_wait_s))` timer before checking whether additional items were already available in `self._queue`.

## Modifications

- **Skip cancelled futures before tokenization**: Filter out `(prompt, fut)` entries where `fut.done()` is already true before running tokenization. If all futures in the collected batch were cancelled, skip the `run_in_executor` call entirely.
- **Drain immediately available queue items via `get_nowait()`**: Pull any already-queued items up to `max_batch_size` before creating the `asyncio.sleep(self.max_batch_wait_s)` task, avoiding timer allocation and cancellation overhead when a full batch is already waiting.
- **Per-request fallback isolation (`_encode_individually`)**: When `batch_encode` fails on a multi-item batch, fall back to encoding each active prompt individually via `_encode_individually` in the executor and resolve each future with its own result or exception so a single bad input never fails healthy concurrent requests in the batch.
- **Unit tests**: Added 3 unit tests in `test/manual/test_async_dynamic_batch_tokenizer.py` covering per-request fault isolation on batch failure, skipping pre-cancelled futures, and handling an all-cancelled batch without invoking the executor.
