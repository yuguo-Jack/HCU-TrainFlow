# [Feat] [NVIDIA] weight-sync: Add GPU-delta in-place weight updates

[Upstream PR](https://github.com/sgl-project/sglang/pull/47981) · state: open · merged: False

## Original PR description

## Motivation

@humansand

Apply canonical Miles deltas directly to live SGLang weights, including HF-base recovery on fresh engines. This targets upstream `main`; the `sglang-miles` counterpart is [SGLang #42210](https://github.com/sgl-project/sglang/pull/42210), paired with [Miles #3894](https://github.com/radixark/miles/pull/3894).

## Modifications

- **Lifecycle/API:** `/get_gpu_delta_info`, `/update_weights_from_gpu_delta`, `/get_gpu_delta_status` and `/clear_gpu_delta_state` serve the Miles client. One update carries the negotiated participants/session and publication descriptor, then owns preparation, pause/fence/apply, all-rank acknowledgement and resume. Failed preparation is released; uncertain XOR application is never replayed. Model labels become visible before generation resumes.
- **Preparation:** validate manifests, read/hash into shared tmpfs, decode/copy into private rank HOST_NUMA arenas, and prepare byte descriptors and three fixed access-family kernels. Bulk byte copies release the GIL. Private scalar patches use empty storage for full replacement or a clone for partial replacement, with batched copies. Cache one decode-status kernel per device. Live weight writes wait for pause; concurrent-serving impact has not been measured. `GPU_DELTA_HOST_CACHE_DIR` must name host-shared tmpfs when overridden.
- **Apply/storage:** one hardware-DE stream, one Triton stream and exactly two decoded slots, ordered by decode-ready/apply-finished events. Sticky status guards subsequent mutation. DE-facing allocations own their CUDA storage; streams drain before release on failure/cancellation. No pipeline-depth tuning, runtime autotuning or encoded-HBM ring.
- **Integrity/recovery:** `validate_payload_hash=True` is the sole receiver hash-policy input; disabling it skips payload SHA passes only. Manifest/file/native checks remain. Ordinary updates use consecutive transport versions; fresh engines can accept HF base→current. State stays cached unless cleared explicitly or via `release_state=True` after successful resume. Cleanup does not change weights/version/pause timing; caller-owned pauses are preserved.
- **Observability:** retain rank/engine phase metrics for Miles/W&B without added collective, polling or device synchronization. Standard `SGLANG_ENABLE_NVTX_OPERATIONS=1` marks host preparation, scheduler and worker/enqueue ranges; the benchmark controls capture. Disabled tracing leaves callables unchanged.

### Compatibility

Blackwell hardware DE; no software-decompression fallback or weight requantization. Admission maps existing FlashInfer packed buffers into canonical affine byte views; padding is excluded, aliases receive one XOR, and independently owned consumer images each receive it. There is no update-time weight/mask permutation.

| Weight format | FlashInfer TRTLLM family | CuTe DSL | MegaMoE |
|---|---|---|---|
| BF16 | Yes | — | — |
| FP8 128×128, UE8M0 scales | Yes | — | — |
| MXFP8 | Yes | — | Yes |
| MXFP4 × MXFP8 activation | Yes | — | Yes |
| NVFP4 | W4A4 | W4A4 / W4A16 | W4A4 / W4A16 |

These are admitted byte layouts, not full-serving qualification of every combination. Backend/model reachability follows upstream main; this change does not enable combinations absent from its native loader. Compact UE8M0 scales expand losslessly for the FP32 API image; arbitrary FP32 scales and conversion fallbacks are rejected. CuTe wrappers/derived buffers must already exist. Supported architectures are `DeepseekV2ForCausalLM`, `DeepseekV3ForCausalLM`, `DeepseekV32ForCausalLM` and `GlmMoeDsaForCausalLM`. Attention TP/CP/DCP=1, PP=1, expert TP=1, fixed expert topology and the Python server with one tokenizer worker are required; no LoRA, disaggregation, EPLB, redundant experts or elastic joins.

For TRTLLM NVFP4 with clamped activation, gate/up global scales must remain tied. Admission rejects an untied starting image, and preparation rejects an update that would require block-scale requantization; this path never requantizes weights. Physical weight and block-scale row order follows the ordinary loader, while global scalar halves retain canonical gate/up order.

For MXFP4 on upstream main, TRTLLM and MegaMoE use the transformed live images in `w13_weight_scale_inv` / `w2_weight_scale_inv`; the TRTLLM clamp tensor belongs to the quantization method. GPU-delta binds and tracks those existing consumers. Layout preparation remains separate from the unchanged DE/Triton apply path, with no update-time weight conversion.
