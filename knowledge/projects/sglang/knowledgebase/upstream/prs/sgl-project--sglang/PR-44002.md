# [Disagg] Return prompt routed experts from the PD prefill server

[Upstream PR](https://github.com/sgl-project/sglang/pull/44002) · state: closed · merged: True

## Original PR description

## Motivation

**Original source:** ported from #22916 by @zyzshishui ("R3 Support on PD Disaggregation (mini_lb)"), which was merged into the `sglang-miles` branch, not `main`. This PR brings over only its `prefill.py` change (as it exists on `sglang-miles` today, commit 01957d9104). The `mini_lb` merge from that PR is not included; frontends combine the two responses themselves (see below).

R3 (`--enable-return-routed-experts`) is broken under PD disaggregation on `main`:

- The decode server never runs the prompt through the model, so the prompt rows it returns in `routed_experts` are whatever stale data sits in its host cache at those KV slots (~1% match vs. a non-PD baseline in the test below).
- The prefill server does capture the prompt routing, and #23885 made it finalize the host cache, but nothing on `main` ever reads it back into the prefill response, so prefill returns no `routed_experts` at all.

## Modifications

In `process_disagg_prefill_inflight_queue`, for requests with `return_routed_experts` set, collect the routed experts when the KV transfer succeeds, before `release_kv_cache` frees the slots. Other requests are untouched.

The prefill response now contains rows `[routed_experts_start_len, prompt_len)`. A frontend that sends `routed_experts_start_len=prompt_len` to decode gets `[prompt_len, seqlen - 1)` from decode, and `concat(prefill, decode)` equals the non-PD result. Decode also skips gathering and serializing its stale prompt rows.

## Accuracy Tests

Qwen3-30B-A3B, B200, TP1 per server: non-PD baseline + Mooncake prefill + decode, `--enable-deterministic-inference --moe-runner-backend triton`. A client stands in for the frontend: it sends each request to P and D with a shared `bootstrap_room` and compares against the baseline. 16 concurrent prompts (4 to 201 tokens), 32 output tokens.

| Run | Prefill rows | Result vs. baseline |
|---|---|---|
| Unpatched, overlap on | none | 0/16 |
| Patched, overlap on, join `prefill + decode[prompt_len:]` | `prompt_len`, 100% match | 16/16 exact |
| Patched, `--disable-overlap-schedule` | `prompt_len`, 100% match | 16/16 exact |
| Patched, P `start_len=S`, D `start_len=prompt_len`, plain concat (S in {0, 3}) | `prompt_len - S` | 32/32 exact vs. baseline with `start_len=S` |

Output text matched in every case. No row-count mismatch warnings in the server logs.

Note: with the default `flashinfer_trtllm` MoE runner on Blackwell, routed experts come back all zeros even without PD, because routing happens inside the fused kernel and is never captured. That is separate from this fix, which is why the test uses `--moe-runner-backend triton`.
