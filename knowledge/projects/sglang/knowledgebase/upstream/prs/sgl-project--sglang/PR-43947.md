# [sglang-miles] Return routed experts as a compressed, self-describing payload

[Upstream PR](https://github.com/sgl-project/sglang/pull/43947) · state: open · merged: False

## Original PR description

## Motivation

Routing replay (R3) returned each request's routing as base64 of an int32 `[tokens, layers, topk]` buffer: 72 MB for a 35k-token request on Qwen3-30B-A3B. Most of the cost came before encoding: the scheduler gathered full int32 rows and pickled them as torch tensors to the detokenizer. On a single-turn GRPO batch, R3 added 7.7% to rollout wall time.

## Modifications

- **Capture:** each row is sorted on the GPU, and the pinned host cache uses the narrowest dtype that fits (`uint8` up to 256 logical experts, else `int16`/`int32`). Replay only needs each row's expert set, so this is lossless, and every later copy moves 4× fewer bytes.
  - The bound is the logical expert count: capture records logical ids, so EPLB's redundant physical slots don't widen the dtype, and elastic-EP scale-up can't outgrow it.
  - The NPU topk path now also captures logical ids, before the logical-to-physical mapping, matching CUDA.
- **Wire format:** `routed_experts` is base64 of a 16-byte header (magic `SGRE`, version, dtype, shape) followed by one zstd frame of the rows laid out `[layers, tokens, topk]`. There is one format, with no flag.
- **Codec** (`state_capturer/routed_experts_codec.py`): `RoutedExpertsEncoder` is built once per process; `decode_routed_experts` returns `[tokens, layers, topk]` and raises `ValueError` on malformed input.
- **IPC:** the scheduler hands rows to the detokenizer as numpy, which pickles more cheaply than torch.

## Breaking change

- **Readers must switch decoders.** Code that read `np.frombuffer(b64decode(...), np.int32)` must call `decode_routed_experts`, or `extract_routed_experts_from_meta_info` for flat int32.
- **Row order changes.** Rows are sorted ascending instead of in router rank order.
- **miles counterpart:** radixark/miles#4035.

## Accuracy Tests

- **Unit tests:** exact round trips for every dtype; every malformed payload raises `ValueError`; captured rows come out sorted and exactly narrowed; the overlap-path output never aliases the device cache.
- **GPU tests (H200, at this head):** `rl/test_return_routed_experts.py`, `ep/test_routed_experts_dp_readback.py` and `unit/state_capturer/`: 27 passed, 1 skipped (a DeepEP variant missing from the image).
- **End to end:** replaying 96 Terminal-Bench agent trajectories through miles, every trajectory's accumulated routing equals a full re-fetch, with or without `routed_experts_start_len`.

Two requests before this lands:

1. Put the new format behind a flag, off by default. The first commit (8d11e2e531) had `--routed-experts-encoding {base64_int32,zstd}` with `base64_int32` as the default; please bring it back. With the flag off, behavior should match the base branch exactly: no row sort, int32 host cache, raw int32 base64. The row order and dtype are visible to consumers, so the sort and narrowing belong behind the flag too. No `routed_experts_encoding` echo field is needed: the `SGRE` magic already identifies the format, and a legacy payload cannot start with it (its first int32 would be 1163019091, which is not an expert id). Consumers can dispatch on the magic, and Miles can turn the format on with `--sglang-routed-experts-encoding zstd`.

2. [P1] The PD routers must understand the new payload. `mini_lb._merge_routed_experts` (sgl-model-gateway/bindings/python/src/sglang_router/mini_lb.py:38) and `merge_routed_experts_in_json` in radixark/sgl-router-for-miles (src/routers/http/pd_router.rs) both splice `prefill_bytes + decode_bytes[len(prefill_bytes):]`. That works only because every legacy row has a fixed byte width. With a header plus a zstd frame, the byte offset no longer marks a row boundary. The decoder reads the prefill header, decompresses only the first frame, and ignores the trailing bytes, so a PD + R3 response silently carries prompt rows only. With this head's codec and mini_lb's merge logic, 6 prompt + 5 generated tokens gave 6 rows instead of 10. Please:
   - add `merge_routed_experts(prefill, decode)` to `routed_experts_codec.py`. The body is layer-major, so the merge is per layer: `prefill[l, :P] + decode[l, P:N]`, which is not a flat concat. Keep the current behavior when decode has no payload or fewer rows;
   - have mini_lb call it when the payload starts with `SGRE` and keep the byte splice otherwise. Import the codec lazily, since `sglang_router` does not depend on sglang, numpy or zstandard. Add a unit test that covers both formats;
   - land the same row-level merge in sgl-router-for-miles, tested against golden payloads produced by this encoder. Miles should enable the format for PD only after that router build is in its image.

3. [P2] `decode_routed_experts` accepts trailing data after the frame, contrary to its docstring, and that is why the case above passes silently. Passing `allow_extra_data=False` to `ZstdDecompressor().decompress` rejects it (checked with zstandard 0.25.0). Please also add a trailing-bytes case to `test_malformed_payloads_raise_value_error`.
