# [Fix] row_transport: Ensure MoeDeferredFinalize properly declares completion group

[Upstream PR](https://github.com/sgl-project/sglang/pull/46391) · state: open · merged: False

## Original PR description

## Summary of Changes
Fixed a bug where `MoeDeferredFinalize` objects were being created without properly declaring their completion group, causing a validation error during CUDA graph capture. The issue occurred when using DeepSeek-V4-Flash NVFP4 with flashinfer_megamoe and dp-attention.

## Motivation & Context
Closes #46316

The bug was in the `MoeDeferredFinalize` class in `cutedsl.py`. This class inherits from `DeferredFinalize` but doesn't properly initialize the `completion_group` attribute, which is required by the transport layer's validation logic. When `TransportExit.finish()` checks if `output.completion_group` is in the declared groups, it fails because `MoeDeferredFinalize` instances don't have this attribute set.

## Verification
This fix ensures that:
1. `MoeDeferredFinalize` properly initializes with a `completion_group` attribute
2. The transport layer's validation passes during CUDA graph capture
3. The server can start successfully with the specified configuration

The fix is minimal and focused, only adding the necessary initialization to maintain compatibility with the existing transport layer interface.
