# [Perf] diffusion: Remove per-step host syncs and uploads in video models

[Upstream PR](https://github.com/sgl-project/sglang/pull/46047) · state: closed · merged: True

## Original PR description

Depends on #46045 (host-sync guards in `test/unit/host_sync_guard.py`); this branch is stacked on it.

## Motivation

Video pipelines run long denoising loops where every blocking host read or pageable upload stalls the host on the previous step's kernels, and several of them rebuilt request-constant RoPE tables or masks on every forward. This PR removes those per-step costs model by model. Outputs are bitwise unchanged.

## Modifications

- **MOVA** (`model_specific_stages/mova.py`, `bridges/mova_dual_tower.py`): the loop uploaded both timesteps every step and `step_from_to` read them back with `float()`, four syncs per step. The paired schedule is uploaded once and the scheduler steps on the host values. Every forward re-uploaded both towers' CPU complex128 RoPE tables (six blocking copies, ~17 MB for audio) and redid the full-sequence concats, and every bridge layer rebuilt its fp32 cos/sin caches (30 layers x 2 directions); tables and bridge caches are built once per request and freed when the loop ends.
- **MiniMax-H3 / FastH3** (`dits/minimax_h3.py`, `minimax_h3_adaln_cache.py`): FastH3 PDD heads copied that step's weight and bias from the host stacks, four blocking copies per step; the stacks are uploaded once per (device, dtype) and indexed by step. The AdaLN online cache indexed its slabs with a 0-dim device slot (a host read, two per step); it now gathers with `index_select` and keeps the old strides.
- **HunyuanVideo** (`dits/hunyuanvideo.py`): the forward built the RoPE cos/sin on the host and copied both to the device every forward (~59 MB per step at 720p x 125 frames). The uploaded tables are kept per request in an underscore `Req.extra` key, which the disaggregation transport skips.
- **Helios** (`helios_denoising.py`, `dits/helios.py`): frame indices were built on the host and uploaded by each of four RoPE embeddings per forward (eight syncs per CFG step); they are built on the latent device. Every block cast the full-sequence [B, L, 6, D] modulation to fp32 (~1.4 GB per block at 384x640); the compact rows are cast once before the expand/concat.
- **Wan family** (`dits/causal_wanvideo.py`, `dits/wanvideo.py`): causal Wan (LongLive2) copied its host RoPE tables to the device every forward; they are uploaded once per request and chunk position. Wan and causal Wan blocks each cast the batch-wide modulation to fp32; the forward casts it once (the per-token TI2V table keeps its fused bf16 path).
- **LTX-2** (`dits/ltx_2.py`, `ltx_2/denoising.py`; paths not touched by #45966): `prepare_video_coords` uploaded two constant tensors per call (every forward on the LTX-2.3 one-stage path, every step for JoyEcho memory coords); they are uploaded once per device. HQ res2s: the SDE coefficient NaN replacement went through a 0-dim boolean index (nonzero on get and set, four calls per step) and is now a `torch.where`; the 100-iteration bongmath refinement hoists its fp64 casts and `h * a21`; the stage-1 step size starts from the step's host sigmas instead of `.cpu()` reads.
- **JoyEcho** (`joy_echo/denoising.py`): every DMD step read sigma and sigma_next with `.item()`; the loop takes fp32 host and device copies of the schedule once. With the memory bank (shot >= 2) the shot-constant cross masks, audio block mask and memory RoPE coords are built once per loop instead of every step.
- **SANA-WM / SANA-Video2** (`sana_wm*.py`, `sana_wm/streaming*.py`, `sana_video2.py`): the cache-type flag was uploaded in every block's clean pass and read back by the next chunk (20 uploads + 20 reads per chunk) and is now a host tensor; self-forcing steps read their timestep once per chunk; `forward_long` windows camera/Plucker inputs once per chunk so the UCPE and Plucker caches hit; the UCPE invalid-ray fix is a `torch.where`; the chunked refiner reads its sigmas from a host copy and builds each block's RoPE once on the device. SANA-Video2 builds its RoPE tables once per latent shape instead of uploading complex128 tables twice per forward.
- **Cosmos3 world models** (`dits/cosmos_dreams.py`, `dits/cosmos3_sim_auto.py`, `cosmos3_simulation/sim_auto.py`): Dreams zeroed null-action V slots by indexing with a Python list in each of 36 layers (a blocking upload each); the slots are per-frame slices. Sim-Auto's scatter/gather indexes, mRoPE frame ids and generated-frame masks are built once per chunk on the device. The default Cosmos3 T2V/I2V loop is untouched (#45967 covers its CFG window).

Tests:
- `test_mova_denoising.py`: steps never upload or read device timesteps (`SyncOnRead` schedule, one upload); RoPE tables built once per request; outputs bitwise equal.
- `test_minimax_h3_pdd_offline.py`, `test_minimax_h3_adaln_cache.py`: heads uploaded once; slab gathers run under `forbid_host_syncs` with the old values and strides.
- `test_hunyuanvideo_rope_upload.py`, `test_wan_step_host_overhead.py`: RoPE tables uploaded once per request (per chunk position for causal Wan), identical tables; blocks receive fp32 modulation.
- `test_helios_step_host_overhead.py`: frame indices live on the latent device; blocks receive fp32 modulation.
- `test_ltx2_step_host_overhead.py`: video-coord constants uploaded once; SDE coefficients under `forbid_host_syncs`; the refinement casts once.
- `test_joy_echo_denoising_host_overhead.py`: host/device sigma copies, steps never read device sigmas, the memory prefix is built once.
- `sana_wm/test_host_overhead.py`, `test_sana_video2.py`, `test_cosmos3_simulation_host_overhead.py`, `test_cosmos_dreams.py`, `test_cosmos3_sim_auto.py`: the SANA-WM, SANA-Video2 and Cosmos3 world-model paths above.

No hunk overlaps #45942, #45943, #45944, #45948, #45965, #45966, #45967, #45977, #45978, #45979 or #45987; each of them still applies on top of this branch.

- MOVA: the denoising stage went from 44.67 s to 44.22 s (-1.0%) in both rounds, from the 16 per-step syncs and the per-forward RoPE rebuilds going away.
- HunyuanVideo at this shape is GPU-bound (about 1.4 s per step), so the four removed syncs per step do not show in the latency; the saving is the per-step 2 x RoPE upload, which grows with resolution and frame count.
- Wan2.2-T2V-A14B and MiniMax-H3 T2VA have no per-step syncs on main in these commands (table above), so no latency change is expected there; their A/B did not complete (the benchmark machine was released mid-run, after one MiniMax-H3 main run at 138.38 s). This needs a rerun before the speed claim covers them.
