## Motivation

#33182 added the text-to-image `BooguImagePipeline`. The same Boogu-Image checkpoint
also serves **reference-image editing** (TI2I / I2I). This PR extends that one pipeline
to serve both: a single pipeline + config (`task_type=TI2I`) handles text-only and
reference-conditioned requests, matching the one-pipeline house pattern (`GlmImage`,
`Flux2`). With no reference image it degrades to the existing T2I behavior, so base T2I
output is unchanged.

## Modifications

The edit path reuses the DiT, VAE, Qwen3-VL encoder, and scheduler unchanged. A
reference image is routed to **both** the Qwen3-VL encoder (image-aware instruction
embeddings) and the VAE (reference latents threaded through the DiT via
`ref_image_hidden_states`). With no reference image the pipeline degrades to T2I.

- `configs/pipeline_configs/boogu_image.py` — `BooguImagePipelineConfig` gains
  `task_type=TI2I` and `BooguImageCFGPolicy`: dual text+image CFG (1/2/3 branches),
  collapsing to standard CFG `c + (s-1)(c-u)` when there is no reference.
- `configs/sample/boogu_image.py` — adds `guidance_scale_2` (image guidance, default
  `1.0` = off, so a text-only request runs exactly two CFG branches).
- `runtime/pipelines/boogu_image_pipeline.py` — builds the reference-aware
  `BooguImageEncodingStage`, so the single pipeline serves both paths; no
  `--pipeline-class-name` and no separate edit pipeline.
- `.../stages/model_specific_stages/boogu_image.py` — dual-resolution reference
  preprocessing (384 px VLM copy, 2048 px VAE copy), VAE-encode `(sample - shift) * scale`,
  TI2I system prompt with image-before-text ordering; falls back to the plain T2I encode
  when no reference is present.
- `.../stages/model_specific_stages/boogu_image_processor.py` — native port of the
  reference downscale-only, alignment-aware preprocessing (drops the external `boogu` dep).
- `runtime/warmup_request_builder.py` — opts out of the synthetic warmup image so the
  server warms at the real 1024×1024, following the `GlmImagePipelineConfig` precedent.
- `runtime/pipelines_core/schedule_batch.py` — additive `ref_image_hidden_states` field.

Boogu's `head_dim` is 120, which is not an FA-supported size, so q/k/v are zero-padded to
128 and the output sliced back. The softmax scale stays `head_dim**-0.5` = 1/sqrt(120):
zero columns leave `q·k` unchanged, so the padded dim must not enter the temperature. It
is passed explicitly because `Attention.__init__` defaults to `head_size**-0.5`, and
`head_size` there is the padded 128. (This lives in the base T2I DiT from #33182; it is
not part of this PR's diff.)

## Accuracy Tests

CPU-only unit tests: `test_boogu_image.py` **14 passed**. They pin the dual-CFG branch
construction and combine formula, the T2I-unchanged path (reference-free build → 2
branches, combine → `c + (s-1)(c-u)`), `task_type=TI2I`, VAE-encode shift-then-scale
order, `guidance_scale_2` defaulting off, and image-before-text message building.

Same weights and conditioning across all three stacks: 1024×1024, 50 steps, seed 42,
text guidance 4.0, image guidance 1.0, empty negative prompt, bf16.

sglang's edit output reproduces the reference sample at **36.8 dB** vs diffusers; the
residual is bf16 / kernel drift, and `torch.compile` does not change it. Base T2I is
unaffected — **34.7 dB** vs diffusers, and folding the edit path into the shared pipeline
left the T2I output identical to the pre-merge run (**42.3 dB** pairwise, within bf16
run-to-run noise). vllm-omni's edit is a *different valid sample* rather than a degraded
one — lower horizon, brighter ocean — while its T2I matches, so that difference is
specific to its reference-image conditioning path.

## Speed Tests and Profiling

Full-pipeline wall time per image (text encode + 50 steps + VAE decode), 1024×1024,
concurrency 1, warmup excluded, H20. All four sglang arms are from the single merged
build.

| | diffusers | vllm-omni<br>eager | vllm-omni<br>compile | sglang<br>eager | sglang<br>compile |
|---|---|---|---|---|---|
| **TI2I** edit | 159.84 s | 136.76 s | 130.71 s | 143.97 s | **124.81 s (1.28×)** |
| **T2I** base | 68.21 s | 61.03 s | 58.10 s | 64.67 s | **54.77 s (1.25×)** |

sglang compile is fastest on both paths; eager-vs-eager it trails vllm-omni by ~5 %,
because compile buys sglang −13.3 %/−15.3 % vs vllm-omni's −4.4 %/−4.8 % (vllm-omni's
`_repeated_blocks` excludes its double-stream and refiner layers).

Head-dim padding is what makes FA usable here, and it is worth **−12.6 %** on TI2I
(SDPA 164.76 s → padded FA 144.02 s) and **−7.4 %** on T2I (69.84 s → 64.67 s), eager.

Nearly all the time is the denoise loop — TI2I e2e 143.97 s against a 143.39 s denoise
sum, so the edit path's extra VAE encode + image-fused VLM forward is ~0.6 s.

**Caveats:** every GPU on this host carries a foreign tenant at ~79–81 % utilization, so
absolute seconds are contended. diffusers and sglang ran on the same card (ratios are
apples-to-apples); vllm-omni ran on a second card, so its column is cross-card. The T2I
image cell and the T2I latency come from different runs, because vllm-omni's timed T2I
arm uses `dataset: random`, which substitutes its own prompt and injects a synthetic
negative prompt.
