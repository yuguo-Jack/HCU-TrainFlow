## Motivation

PR #41364 adds `topk_page_transform`, which combines DeepSelect Top-K selection with the page-table transform in its epilogue.

DeepSeek V4.1 on Hopper still uses:

```text
torch.topk
  -> sort raw indices
  -> gather physical KV slots
```

This PR connects the new DeepSelect operator to that runtime path.

<!-- Describe the purpose and goals of this pull request. -->

## Modifications

- Use `topk_page_transform` for the SM90 full-topk decode path.
- Write transformed int32 KV slots directly into the existing output buffer.
- Preserve raw-index ordering with `sorted_index=True`.
- Keep the existing Torch path when raw indices are also required.
- Keep SM100 and newer architectures on the existing DeepGEMM path.
- Add CPU dispatch/fallback tests and an H20 runtime integration test.

## Speed Tests and Profiling


The replaced region was benchmarked on NVIDIA H20 with CUDA 13.0 and PyTorch 2.13. Each complete run used 20 warmup iterations followed by 5 groups of 100 measurements. The table reports the mean of the medians from two complete runs.

The measured regions were:

```text
Before:
torch.topk -> raw-index sort -> slot gather -> output copy

After:
DeepSelect top-k -> sorted-index epilogue -> page-table transform
```

| Rows | Width | Top-K | Before | After | Speedup |
|---:|---:|---:|---:|---:|---:|
| 1 | 32K | 512 | 163.264 us | 31.744 us | 5.14x |
| 8 | 32K | 512 | 163.992 us | 31.592 us | 5.19x |
| 32 | 32K | 512 | 163.664 us | 31.456 us | 5.20x |
| 1 | 128K | 1024 | 162.864 us | 31.760 us | 5.13x |
| 8 | 128K | 1024 | 164.960 us | 32.480 us | 5.08x |

This is a microbenchmark of the replaced Top-K and transform region, not an end-to-end serving throughput claim.

- yuyu5333 · comment · 2026-09-29T08:08:19Z · [source](https://github.com/sgl-project/sglang/pull/41561#discussion_r4131091156)

`sorted_index=True` preserves the existing decode behavior. The previous `write_decode()` path explicitly call `sidx.sort(dim=-1)` , and `Selection.page_indices` is documented as ascending. This sorts logical indices, not values, before the page-table transform. The sort is fused into the DeepSelect kernel rather than adding another PyTorch kernel launch. 

- yuyu5333 · comment · 2026-09-29T08:13:26Z · [source](https://github.com/sgl-project/sglang/pull/41561#discussion_r4131133708)

File: `python/sglang/srt/layers/attention/dsv4/v41_indexer/full_topk.py` · line None

Setting `sorted_index=False` does not change the Top-K set, and FlashMLA does not require indices to be ordered. However, it would alter the existing output-ordering contract and change the floating-point accumulation order inside FlashMLA, so the attention outputs would no longer be bitwise identical. With the default `index_topk=512`, removing the sort saves at most about `0.29 us` inside the DeepSelect kernel; when the subsequent FlashMLA dual-cache decode is included in the measurement, no stable benefit is observed. The gain does not justify the contract change and the loss of determinism, so `full_topk.py` should be left unchanged.
