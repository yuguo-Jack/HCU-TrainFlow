## Motivation

An FFN's exit recomputed on every forward of every layer whether it may leave its sum to the next input, whether a reduce-scatter completes it, which sum an input-scattered batch's next input completes, whether the attention-DP return is the reduce-scatterv, and whether the post-expert sum is one all-reduce; a mixer's exit recomputed whether it carries its sum. All of these depend only on the parallel configuration, the declarations and the bound path. Separately, `--enable-layernorm-sp` with pipeline parallelism failed on the first prefill in three ways at the handoff.

## Modifications

- **Decide at construction what an exit decides from fixed facts.** Each bound path carries `ExitFacts` with those decisions, computed when the plan is built in the order the exit used to evaluate them; the docstring states that they are read under the scope the stage is built in (a speculative draft's own MoE settings while it builds) and why they hold for every forward. The exit keeps deciding per batch only what depends on the batch: its padding, whether the attention-DP reduce-scatter is usable (elastic EP can change the DP group), whether it has tokens, and whether a fused consumer takes the sum. The forced completion of an operation-scheduled exit is unchanged.
- **Look up a stage's path once per prepare call** (it was selected up to three times).
- **Reject `--enable-layernorm-sp` with pipeline parallelism.** Behavior change: under PP only the first rank starts the sequence-sharded region, and the handoff failed on the first prefill (an all-gather into a buffer sized for another batch, a missing residual on the wire, and an odd-length prompt's padding row crossing to a rank that does not pad). Startup now rejects the combination, as it does attention DP and speculative decoding.

## Accuracy Tests

How the stack is checked:
- **Unit tests**: the 39 layer-boundary test files pass at the head of every PR in the stack, apart from the two AMD-only `test_aiter_allreduce_fusion_amd` cases that fail on NVIDIA on main too; the test files that changed most recently pass on every commit. The full `test/registered/unit` suite (926 files, one process per file) shows no failure on the stack's head that main does not have.
- **Plan comparison**: an out-of-tree harness binds every stage plan for seven stack shapes (decoder layers with and without an output transform, MHC, Nemotron-H patterns, Kimi K3, Qwen4-exp, NemotronNAS-style attention-only layers, single-stage appends) over 23 parallel configurations, four boundary reductions and one or two pipeline ranks (3,928 scenarios), and compares each bound plan leaf by leaf with the parent commit's.
- **GPU**: dummy weights are seeded per TP rank and scaled (0.05, norms 1.0), so that a sum taken twice or a mixture of rank partials changes the output; the default dummy weights give every rank the same shard and would hide both.
- GPU results below were measured on these commits as based on main `516fd1c1b5` unless marked as on the merge candidate; rebasing onto current main had no conflicts, and the CPU checks were run again after it.
- **On the merge candidate** (head of this stack against main `961bcf481d`, H200, asymmetric dummy weights unless noted): DeepSeek-V2-Lite input-scattered PP2 is bit-identical to PP1 (main crashes on it); Nemotron-H cut between a mixer and its FFN differs from PP1 only at the rounding level of the FFN-to-mixer cuts (main: 0.93 and 2.21); Llama, Qwen3-MoE, GPT-OSS and DeepSeek-V2-Lite are bit-identical to main at PP1 and PP2; GSM8K (real DeepSeek-V2-Lite weights, 250 questions, TP4 with attention DP2 and the dense FFN fully data-parallel) gives 0.360 at PP2, 0.364 at PP1 and 0.368 on main at PP1, medians of three runs whose run-to-run spread is 0.012–0.016. The last revision of the stack changed only comments, docstrings, an equivalent condition and explicitly set attributes after these runs; its bound plans are identical.

For this PR: on the same fixtures, the plan comparison shows no difference, and a decision comparison records, for every bound variant of 3,512 constructed scenarios and an eight-point grid of the per-batch inputs, what each exit does (how it completes, what it finalizes, what sum it leaves, whether a mixer defers): no difference from the parent. Tests that patched these predicates for a forward now set them when the plan is built. On B300 (Kimi K3, see #43460) the K3 SP collective path, whose exits use these facts, is bit-identical to main with CUDA graph decode.

The fixed exit decisions no longer run per layer per forward; device work is unchanged. Not separately benchmarked.
