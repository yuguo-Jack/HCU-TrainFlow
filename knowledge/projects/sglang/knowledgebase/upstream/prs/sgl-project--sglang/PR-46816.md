# [Fix] [Intel] gemma4: Bidirectional image attention on the intel_xpu backend

[Upstream PR](https://github.com/sgl-project/sglang/pull/46816) · state: closed · merged: True

## Original PR description

## Motivation 

Same as #44225 for Gemma4.

On `--attention-backend intel_xpu`, Gemma 4 image tokens get causal attention instead of bidirectional attention. `Gemma4ForConditionalGeneration.prepare_attn_masks` handles only Triton and FA4. On any other backend it logs `Bidirectional attention for image tokens requires TritonAttnBackend. Falling back to causal attention` and returns. Text is unaffected, so the only symptom is poor vision accuracy: `google/gemma-4-12B-it-qat-w4a16-ct` scores docvqa_val ANLS 0.349 on an Arc Pro B70.

## Modifications

- `gemma4_mm.prepare_attn_masks`: on XPU, hand `XPUAttentionBackend` the per-token image-block ids that Gemma 3 already builds (`Gemma3ForConditionalGeneration._build_xpu_image_block_ids`). The sgl-kernel-xpu FMHA prefill turns them into bidirectional image attention.
- Cookbook (Gemma4 "Configuration Tips"): document that the sgl-kernel-xpu mask has no sliding-window variant, so on intel_xpu a prompt longer than the 1024-token window loses it on the sliding layers. `max_soft_tokens` 560 fits; 1120 does not.
- Test: `test/registered/xpu/test_xpu_gemma3_bidirectional_attn.py` checks that Gemma 4 sets the same block ids as Gemma 3. It fails on the unpatched code (block ids left `None`).
