# [DSA] Fix decode context parallelism for RoPE sparse attention on Blackwell

[Upstream PR](https://github.com/sgl-project/sglang/pull/42536) · state: open · merged: False

## Original PR description

## Motivation

- Fixes #41926. With `--dcp-size > 1`, GLM-5.3, GLM-5.2 and DeepSeek-V3.2 crash. These models use RoPE sparse attention (DSA) with the `trtllm` backend. There are three causes:
  - `forward_mla.py` expects the attention backend to return `(attn_output, lse)`, but the DSA backend only returns the output.
  - `multi_ctas_kv_counter_buffer` is sized for the heads of one rank, but with DCP each rank runs the heads of the whole DCP group.
  - The EAGLE draft pool asserts `page_size == 64`, and DCP uses a larger page size.
- This makes a documented flag work. It does not make DCP the fastest option: TP alone is still fastest when the load fits in memory, and attention DP is still faster at high concurrency.

## Modifications

- **Index remap**: a new Triton kernel takes the global top-k slots, keeps the ones this rank owns, converts them to local slot ids, moves them to the front of the row, and returns the count per row.
- **Backend**: sparse attention is called with `return_lse=True`. Rows that have no local KV are fixed up, and the partial results are merged with the existing `ag_rs` / `a2a` / `fi_a2a` code. The fused top-k path stays on.
- **Memory**: the target model's KV is split across the DCP group. The index keys are kept in full on every rank. KV sizing now reserves room for the DCP workspace, the counters, the merge buffers and the replicated Q weights.
- **Decode latency**:
  - Layers that share the previous layer's top-k reuse its remapped table. This cuts the remaps from 78 to 21 per step.
  - With `a2a` / `fi_a2a`, every rank keeps the full Q projection weights by default, so there is no Q all-gather per layer. `--no-dcp-replicate-q-proj` turns this off.
- **EAGLE/MTP**: works with the checkpoint's own draft as a single chain. The draft KV is kept in full on every rank.
- **Launch validation**: flag combinations that are not supported raise an error at startup.
- **Fixes in shared code**:
  - The LSE combine returns zero when every shard is empty.
  - Eager autotuning no longer allocates a logits buffer that it never uses.
- **FlashInfer workaround**: in 0.7.0.post1, the sparse RoPE kernel with `return_lse` returns wrong values for short-KV FP8 rows when there are more than 32 heads. To stay within 32, the heads are split into groups and each group runs as extra batch rows. I have a reproducer and will file the upstream issue.

### Not in this PR

- PD disaggregation.
- Prefill CP together with DCP.

Both raise an error at launch.

### Follow-ups, most important first

1. **A fused merge kernel.** Today each layer runs three kernels to merge the partial results: pack, exchange and LSE combine. That is 234 launches per step. Doing all three inside the FlashInfer all-to-all is the biggest remaining latency item.
2. **Splitting the index cache across ranks.**
   - Today every rank keeps all index keys: 2,772 bytes per token on every rank, next to 44,928 bytes per token of KV that is split.
   - This costs 5.8% of capacity at DCP2, 17% at DCP4 and 41% at DCP8.
   - Splitting the index cache gets that back, but each indexer layer then needs one more collective (21 per step) to merge the local top-k candidates.
   - It is worth doing for DCP8, but not for DCP2 or DCP4.
3. HiSparse and HiCache / L3.
4. Unified memory.
5. LoRA with replicated Q. It works today with `--no-dcp-replicate-q-proj`.
6. Hopper (`flashmla_kv`).
7. DCP groups that span several nodes.

These also raise an error at launch: sparse backends other than `trtllm`, KV dtypes other than FP8 E4M3 or BF16, and DCP groups that span more than one attention-TP group. EAGLE needs the checkpoint's own draft, top-k 1, and draft tokens = steps + 1.

## Accuracy Tests

- 4x B300 (SM103), FlashInfer 0.7.0.post1. The tables were measured with torch 2.13 cu130 and sglang-kernel 0.4.8.
- Rerun on the current head (torch 2.14.1, sglang-kernel 0.4.9):
  - Unit and GPU test suites: 143 passed.
  - GSM8K: DCP2 and DCP4 both score 198 of 200. TPOT at C1 is 7.63 ms for DCP2 and 8.05 ms for DCP4.
  - Registered test (MTP fixture, completion API, 20-shot, 500 questions): TP4 + DCP2 scores 0.904 and TP4 without DCP scores 0.914. The accept length is 4.05 in both.
- Rerun after merging main at `0f5bc4af4b`: the same test suites give 146 passed. TP4 + DCP2 scores 198 of 200 on GSM8K, and TPOT at C1 with 32K input is 7.67 ms.
- Rerun after merging main at `e6072935bf`: the same test suites give 148 passed. TP4 + DCP2 scores 198 of 200 on GSM8K, and TPOT at C1 with 32K input is 7.66 ms.
- Model: `nvidia/GLM-5.3-NVFP4`, FP8 KV, temperature 0.
