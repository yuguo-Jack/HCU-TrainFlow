# [CI] cp: Disable the CP8 TP-decode B300 server test while it fails

[Upstream PR](https://github.com/sgl-project/sglang/pull/47798) · state: open · merged: False

## Original PR description

## Motivation

`test/registered/e2e/cp/test_cp_decode_attn_tp_server.py` was added in #46857 and has failed on every run so far: both targeted `/rerun-test` runs on that PR ([1](https://github.com/sgl-project/sglang/actions/runs/41056533933), [2](https://github.com/sgl-project/sglang/actions/runs/41094611156)), and every scheduled run since it merged:

- [Oct 31, 4am PDT](https://github.com/sgl-project/sglang/actions/runs/41195425101/job/124520624208)
- [Oct 31, 4pm PDT](https://github.com/sgl-project/sglang/actions/runs/41251070653/job/124684625363)
- [Nov 1, 3am PST](https://github.com/sgl-project/sglang/actions/runs/41300331378/job/124829869452)

The failure is identical each time: the first case (the fallback server with `--enforce-disable-flashinfer-allreduce-fusion`, 1-token prompt) fails the VERIFY versus teacher-forced CP prefill check with `Mismatched elements: 19 / 32`, max absolute difference `0.50715888` against `atol=0.02`. The greedy tokens match. Each failure also fails `extra-b-test-8-gpu-b300`, which hides the results of the other files in that shard.

## Modifications

Set `disabled=` on the file's `register_cuda_ci` call. `run_suite.py` skips disabled registrations, so the test stays in the tree and can still be run directly or with `/rerun-test`. Remove the `disabled=` argument to re-enable it once the mismatch is understood.
