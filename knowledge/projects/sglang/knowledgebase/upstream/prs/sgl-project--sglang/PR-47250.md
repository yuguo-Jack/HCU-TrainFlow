## Motivation

A prefill cancellation can release source KV after the GPU forward ends while an asynchronous transfer still reads it. Transfer failure state is not itself a source-quiescence acknowledgement.

Four unmodified runs released pages while an asynchronous transfer was still reading them; two also reallocated a page before the source read completed. A matched source-retention control completed normally. All expected client completions, sentinels and health checks passed; client-visible disclosure or overwrite was not established.

## Modifications

Keep a failed sender in `Transferring` while its outstanding count is positive, and avoid caching terminal failure immediately in `abort`. Move affected chunked/waiting prefill aborts to the existing inflight queue so its normal terminal cleanup can release their KV after the source drains. A drained failed room does not wait for the success-only zero-entry cleanup rule.

The fix uses the existing worker-outstanding boundary: a failed room remains nonterminal until every dequeued staging worker has left the transfer call and decremented that count. Aborts then reuse the established inflight-queue cleanup instead of adding a blocking scheduler wait. This deliberately scopes the change to backends that participate in that existing counter contract.

## Accuracy Tests

The new normal-import regressions exercise both ownership boundaries. A failed sender with one outstanding worker remains `Transferring` with no cached terminal state, then becomes `Failed` only after the count reaches zero. A chunked-prefill abort with that sender is placed on the inflight queue; the immediate request cleanup and KV release functions are both verified not to run.

The broader sender-lifecycle, prefill-abort, result-polling and chunked-abort suites pass 21 tests and 36 subtests in 12.05 seconds. They cover success/failure polling, PP consensus, late chunk results, retry, retraction and terminal cleanup.

The matched source-retention serving control at the same release boundary completed all 20 submissions, six disconnect/replacement cycles, the tenant sentinel and the health check with zero lifetime reports.
This patch changes cancellation cleanup only and does not alter logits or sampling.

## Speed Tests and Profiling

The normal terminal-success sender poll was timed for nine rounds of 500,000 calls.

-  The baseline measured a 0.289 microsecond median per poll (0.286-0.293 microseconds).
-  The patched branch measured 0.306 microseconds (0.298-0.307 microseconds).
    - added 0.017 microseconds per uncached terminal poll.

The scheduler adds one extra poll only on an abort.
Ordinary request scheduling, forward execution and transfer payloads are unchanged.
The source is retained longer only when a failed transfer still has an outstanding worker, which is the required behavior for correctness.
