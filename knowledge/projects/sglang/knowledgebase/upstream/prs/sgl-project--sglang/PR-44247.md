# [Fix] zimage: Expand text conditioning for multiple outputs per prompt

[Upstream PR](https://github.com/sgl-project/sglang/pull/44247) · state: open · merged: False

## Original PR description

## Motivation

A single-prompt Z-Image request with `n=3` creates three image latents but supplies only one caption embedding, raising `Z-Image expects one caption embedding per image, got 3 images and 1 captions`.

This fixes the server-side Z-Image multi-output bug documented in #44088 and explicitly excluded from that PR's ComfyUI scope.

## Modifications

- Return `TextConditioningOutput` with an explicit batch dimension for both single and multiple prompts.
- Expand positive and negative embeddings, attention masks, embedding masks, and valid lengths with `PromptToSampleBatchExpander`, preserving prompt order and idempotence.
- Reject invalid embedding ranks for multi-output requests while retaining the existing 2D getter support for single-output inputs.
- Add CPU regression coverage through the real postprocess, expansion, getters, conditioning kwargs, and weight-free `patchify_and_embed` path.

## Accuracy Tests

### Unit tests (CPU)

The single-prompt, three-output regression reproduces the caption/image count mismatch before the fix. After the fix, the complete configuration test file passes: **17 tests and 38 subtests**.

```bash
PYTHONPATH=python CUDA_VISIBLE_DEVICES='' SGLANG_DIFFUSION_PLATFORM_OVERRIDE=cpu SGLANG_USE_CPU_ENGINE=0 \
  python -m pytest python/sglang/multimodal_gen/test/unit/test_zimage_pipeline_config.py -q
```

Coverage includes single-output compatibility, unequal positive/negative lengths, two unequal-length prompts with two outputs each, ordering, idempotence, invalid dimensions, mask/length mismatches, dtype preservation, and RoPE consistency.

This run used Linux CPU, Python 3.12.14, and PyTorch 2.13.0+cu129.

### End-to-end server test (GPU)

On a single NVIDIA H20 with the full `Tongyi-MAI/Z-Image-Turbo` weights and the cookbook command `sglang serve --model-path <Z-Image-Turbo>` (default flags), I compared the parent commit (`72730d63`) with this PR (`d251216c`). The two runs differ only in `zimage.py`. Requests go to `POST /v1/images/generations` with the same prompt, `size=512x512` and `seed=42`.

| `n` | Base (`72730d63`) | This PR (`d251216c`) |
|---|---|---|
| 1 | 1 image | 1 image, byte-identical to base |
| 2 | HTTP 500: `got 2 images and 1 captions` | 2 distinct images |
| 3 | HTTP 500: `got 3 images and 1 captions` | 3 distinct images |

All returned images are coherent and match the prompt, and peak GPU memory was about 17 GB. The unit test file above also passes in this GPU environment.

This run used Python 3.12.3, PyTorch 2.14.0+cu130, CUDA 13.0, diffusers 0.37.0, and driver 595.

**Not tested:** the pinned PyTorch 2.14.1, multi-GPU or parallel configs, and other Z-Image variants (base and fp8 transformer). Batched and single-image outputs are not pixel-equivalent for the same seed. I believe this comes from batched latent sampling rather than from this change, but I have not confirmed it.
