# [Perf] diffusion: Remove per-step and per-request host syncs in Cosmos3 and Qwen-Image-2.1

[Upstream PR](https://github.com/sgl-project/sglang/pull/45967) · state: closed · merged: True

## Original PR description

## Motivation

Two blocking device reads sit on the host's critical path:

1. **Cosmos3, every step.** The denoising loop checked the CFG window, and the Transfer control-CFG window, with `t.item()` on the device timestep. So the host waited for each step's kernels to finish before it launched the next step.
2. **Qwen-Image-2.1 edit, every request.** The edit path built the VAE latent mean/std with `new_tensor` right after launching the condition-image VAE encode. That pageable upload made the host wait for the encode before it could start the prompt's image preprocessing.

## Modifications

- `cosmos3.py`: the loop takes one host copy of the timestep schedule (`timesteps.tolist()`), and `_cfg_active_at` reads the window from those floats. The per-step decisions and kernels are unchanged.
- `qwen_image21.py`: `QwenImage21EncodingStage` uploads the latent mean/std once per `(dtype, device)` and reuses them, so the preprocessing overlaps the encode. The normalization is bit-identical.

Tests:
- `test_cosmos3_rollout.py::test_cfg_window_check_reads_host_timesteps`: runs the denoising loop with a `[400, 1000]` CFG window over timesteps whose `item()` / `float()` / `bool()` raise. The window must still choose batched CFG at 999, 700 and 400, and the cond branch alone at 399 and 100. It fails on main.
- `test_qwen_image21.py::test_condition_latents_reuse_uploaded_latent_stats`: two edit requests must produce the reference-normalized condition latents bitwise, and the second request must reuse the first one's mean/std tensors (checked by identity).

No files are shared with #45942, #45943, #45944 or #45948.
