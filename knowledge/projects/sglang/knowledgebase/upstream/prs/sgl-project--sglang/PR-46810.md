# [Fix] Resolve dangling $defs refs in tool-call grammar schemas

[Upstream PR](https://github.com/sgl-project/sglang/pull/46810) · state: open · merged: False

## Original PR description

## Motivation

A request whose tool JSON Schema uses `$defs` can fail with HTTP 400:

```
Failed to compile structural_tag grammar: .../json_schema_converter.cc:
Cannot find field $defs in #/$defs/<Name>
```

xgrammar resolves `$ref` against the schema document root. Two paths hand it a schema where the root has no `$defs`, so the grammar compile fails and the whole request aborts:

1. **Client schema with misplaced definitions.** A tool's `parameters` contains `$ref: "#/$defs/...`" while the `$defs`/`definitions` map sits in a nested subschema — the classic shape produced by embedding a Pydantic sub-model's `model_json_schema()` as a property value. Reproduced byte-identically with the pinned xgrammar 0.2.7:

```python
params = {"type": "object", "properties": {"w": {"$ref": "#/$defs/WaitFor", "$defs": {"WaitFor": {"type": "object"}}}}}
# compile_structural_tag -> json_schema_converter.cc: Cannot find field $defs in #/$defs/WaitFor
```

Any placement with `$defs` at the `parameters` root compiles fine (property/items/anyOf/allOf/prefixItems refs, recursive, chained), so the grammar path itself is sound — the schema just needs its definitions at the root.

2. **Named `tool_choice` drops root definitions** (the gap previously attempted in #31692, which went stale; this PR covers it). `get_json_schema_constraint`'s `ToolChoice` branch wraps the tool's `parameters` under `items/properties/parameters` without hoisting its root `$defs`, unlike the `"required"` branch right below it. A named-tool request whose parameters use `$defs` — standard for nested/Pydantic args — produces a constraint with dangling refs.

## Fix

- New `hoist_json_schema_defs` in `function_call/utils.py`, called from `OpenAIServingChat._validate_request` next to `normalize_json_schema_types`: walks the `parameters` tree and deep-copies nested `$defs`/`definitions` maps to the root, only when the root lacks that map and no name conflicts exist. Conflicting, `$id`-scoped, or already valid schemas pass through byte-identical — behavior for valid requests is unchanged, and unrepairable schemas fail exactly as before.
- The named `ToolChoice` branch of `get_json_schema_constraint` now mirrors the `required` branch and attaches the selected tool's definitions to the outer array schema.

## Tests

- `TestHoistJsonSchemaDefs`: embedded definitions resolve for both `$defs` and `definitions` spellings (including a ref to the original nested location); existing root maps and conflicting nested maps stay untouched.
- `TestJsonSchemaConstraint::test_specific_tool_choice_resolves_defs`: named tool_choice with chained `$defs` refs, plus a conflicting definition in an unselected tool that must not leak in.
- Each new test validates instances through `jsonschema` (so internal refs must resolve) and fails on the pre-fix code with `PointerToNowhere`.

Verified with xgrammar 0.2.7: the nested-defs schema compiles after repair; conflicts and missing defs keep the original compile error; per-tool repair is independent. `pre-commit run --files` passes on all changed files.
