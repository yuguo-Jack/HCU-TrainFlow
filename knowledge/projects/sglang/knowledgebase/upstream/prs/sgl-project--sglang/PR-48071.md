# [Fix] [NPU] lora: Handle constexpr tuple offsets on older Triton

[Upstream PR](https://github.com/sgl-project/sglang/pull/48071) · state: open · merged: False

## Original PR description

## Motivation

Fix LoRA server startup on older Triton versions. With `triton-ascend 3.2.2` (Triton module version `3.2.0`), decode graph capture fails while compiling the ragged cSGMV expand kernel:

```text
tiles = (SLICE_OFFSETS[s + 1] - SLICE_OFFSETS[s] + BLOCK_N - 1) // BLOCK_N
TypeError("'constexpr' object is not subscriptable")
```

This blocks both LoRA update tests before their assertions in [the failing NPU CI job](https://github.com/Ascend/sglang/actions/runs/41192732188/job/124512664305). The older `tl.constexpr` wrapper does not implement tuple subscription, and its compiler evaluates the subscript directly.

## Modifications

Read each slice boundary from the wrapped tuple's `.value`, then wrap the scalar with `tl.constexpr` for compile-time arithmetic. Reuse the two boundaries for tile sizing and slice selection. The ragged grid, fallback path, cache key, and launch configuration remain unchanged; no device copies or kernel launches are added.

## Accuracy Tests

Validated on Ascend A3 / CANN 9.1.0, Torch `2.10.0+cpu`, torch_npu `2.10.0.post6`, and triton-ascend `3.2.2`, using runtime commit `93f4f1a87dbf356833e5d2ec777ee4b006b631fd`. The original expand kernel is byte-for-byte identical to the kernel at this PR's upstream base, `c8704818d4f04fa9249a4144f14882670b4d37ae`.

The complete fresh upstream checkout was not run on NPU. The original CI's Llama 3.1 8B and four real adapters were unavailable, so the original full test matrix was not rerun. CUDA GPU execution was not tested.

## Speed Tests and Profiling

A same-stack operator comparison used the working rectangular fallback as a reference, with rank 16, 16 tokens, 10 warmups, and 30 measurements of 20 calls per path. Median rectangular / patched-ragged times in microseconds were: unequal QKV `193.00 / 180.83`, equal QKV `207.59 / 208.78`, two-slice MLP `202.24 / 200.21`, and single slice `152.76 / 153.07`.

Event timings include host launch gaps, and paths were measured in a fixed order. This is not a before/after comparison with the original ragged path, which cannot compile on this stack. No serving throughput benchmark or profiling was run, and no end-to-end performance improvement is claimed.
