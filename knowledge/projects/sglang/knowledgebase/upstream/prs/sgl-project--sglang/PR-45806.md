# [Feat] ultravox: Add Ultravox speech LLM support

[Upstream PR](https://github.com/sgl-project/sglang/pull/45806) · state: open · merged: False

## Original PR description

## Motivation

fixie-ai/ultravox-v0_5-llama-3_2-1b (Whisper encoder + stacking projector
    + Llama-3.2 decoder) had no implementation. An unregistered architecture
    resolves to the Transformers fallback backend rather than erroring, which
    then failed during weight loading with
    `Parameter.__new__() got an unexpected keyword argument '_is_hf_initialized'`.
    
## Modifications

Model (`models/ultravox.py`):
    - The audio tower is an unmodified HF Whisper encoder, so it reuses
      `VoxtralWhisperEncoder` (plain SDPA, no KV cache, HF weight names).
    - `UltravoxProjector` stacks `stack_factor` encoder frames into the channel
      dim, then RMSNorm -> Linear -> SwiGLU -> RMSNorm -> Linear. The SwiGLU
      chunk order (`x, gate = chunk(2); silu(gate) * x`) matches HF/vLLM.
    - The checkpoint carries only `audio_tower.*` and `multi_modal_projector.*`;
      the frozen text backbone lives in the separate repo named by
      `config.text_model_id` and is fetched in `load_weights`.
    - `config.hidden_size` is the projector width, not the text width; the
      text config is taken from `config.text_config`.
    - The processor right-pads every mel chunk to the 30s window, so each chunk
      is trimmed to `audio_lens` before encoding; padding frames would otherwise
      become extra audio tokens.
    - Whisper omits the k_proj bias that the fused QKVParallelLinear allocates,
      so a zero bias is synthesised.
    
Processor (`multimodal/processors/ultravox.py`):
    - HF's UltravoxProcessor substitutes EOT for the `<|audio|>` placeholder
      and locates spans by start index; SGLang locates them by placeholder id,
      so `audio_token_replacement` is redirected to keep `<|audio|>`.
    - It takes a single text string and sets its own audio padding, so the base
      class's `text=[...], padding=True` call is overridden.
    - Its mel is named `audio_values` with true frame counts in `audio_lens`;
      both are registered in the modality attribute table.

Chat template (`examples/chat_template/audio_template_ultravox.jinja`):
    The stock Llama-3 template takes only string content, so SGLang detects
    the "string" content format and drops audio parts. This template iterates
    content parts and emits `<|audio|>`, which routes audio_url parts through
    to the multimodal processor on /v1/chat/completions. Text-only serving does
    not need it.

- siju-samuel · comment · 2026-10-28T12:14:23Z · [source](https://github.com/sgl-project/sglang/pull/45806#discussion_r4400397817)

File: `python/sglang/srt/multimodal/processors/ultravox.py` · line 37

UltravoxProcessor tokenizes with `add_special_tokens=False` and leaves BOS to the caller, so this prompt reaches the model without `<|begin_of_text|>` and without the system turn the stock template always writes. Rendering a string `<|audio|>` user turn via `tokenizer.apply_chat_template`, as the HF pipeline does, fixes both.
