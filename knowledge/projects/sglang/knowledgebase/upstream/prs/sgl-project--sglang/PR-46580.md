# [Feat] diffusion/model: add the BRIA Fibo 2.0 transformer and text conditioning

[Upstream PR](https://github.com/sgl-project/sglang/pull/46580) · state: closed · merged: True

## Original PR description

> Split out of the original (4456-line) PR as asked in https://github.com/sgl-project/sglang/pull/46580#issuecomment-6568379129 — this PR is the transformer and text conditioning, **2126 lines**. The pipeline, serving, mask plumbing and cookbook follow in #47831, stacked on this one.

## Motivation

Add the model side of [BRIA Fibo 2.0](https://huggingface.co/briaai/Fibo-2.0-edit-turbo) to SGLang Diffusion. Fibo 2.0 is an 8B flow-matching model that both generates and edits images in the FLUX.2 VAE latent space: Qwen3-VL-4B encodes structured JSON captions, a two-layer Perceiver resamples those features into 256-512 "gist" tokens, and five transformer blocks additionally cross-attend to Qwen3-VL's internal layers.

The weights are released under CC BY-NC 4.0 and require accepting BRIA's license on Hugging Face.

## Modifications

**Model**
- `runtime/models/dits/bria_fibo2.py`: the Fibo 2.0 transformer. It keeps the Z-Image single-stream block and adds a Perceiver resampler, five injection blocks with gated cross-attention, per-token noisy/clean modulation, three-axis RoPE over the gist, image and context-image planes, and patchify/unpatchify around the FLUX.2 latent layout.
- `configs/models/encoders/bria_fibo2.py`: builds the six text bundles from fifteen Qwen3-VL hidden states, each normalized to unit RMS per token before concatenation. The in-tree text tower returns one hidden state per decoder layer, one fewer than the reference, so the reference layer indices are shifted and the tuple length is asserted, which turns a future collection change into an error instead of silently wrong conditioning.
- `configs/models/dits/bria_fibo2.py`: the architecture config, including the checkpoint's own parameter names and the three-axis RoPE geometry.
- Parameter names match the checkpoint one to one (`param_names_mapping` stays empty). q/k/v stay unfused: an injection block reads a 7680-wide text bundle through a 3584-wide query.

**Tests**
- `test/unit/test_bria_fibo2.py` (30 tests): gist-count interpolation, token layout and RoPE planes, per-token modulation, patchify round trips, and the checkpoint key/shape mapping against the released index.
- `test/unit/test_bria_fibo2_encoder.py` (17): the six-bundle construction, the layer shift and its guard, and the architecture fields flattened from the real `text_config` / `vision_config`.
- `test/unit/test_bria_fibo2_parity.py` (3): the transformer against the diffusers implementation at a tiny configuration, for generation, editing and the no-context path.

- liquanfeng · comment · 2026-10-30T15:20:49Z · [source](https://github.com/sgl-project/sglang/pull/46580#discussion_r4425252974)

File: `python/sglang/multimodal_gen/configs/pipeline_configs/bria_fibo2.py` · line None

Good catch — the mask was dead code, and the root cause is exactly what you describe: `InputValidationStage` calls `preprocess_condition_image` per image without the batch, so `getattr(batch, "mask", None)` could never see a request.

Fixed in the two commits on top. `preprocess_vae_image` is the hook that does receive the batch, and `InputValidationStage` runs it *before* the crop loop, so the greying now happens on the original image in the order training used:

- `[Feat] diffusion: plumb an optional repaint mask through the image edits API` — `POST /v1/images/edits` declared `mask` and dropped it; it is now saved and forwarded as `SamplingParams.mask_path` (per-request, like `image_path`), so a masked edit no longer silently degrades to a plain edit.
- `[Fix] diffusion/bria_fibo2: apply the request mask to the source image` — the greying moved to `preprocess_vae_image`; `preprocess_condition_image` is crop-only again. A mask with several reference images, or one whose size differs from its image, raises instead of being composited wrong. One detail only the real run surfaced: the hook has to leave `condition_image` as a list, because the stage iterates it immediately afterwards.

Verified on an H100 with the same inputs as the reference run (suitcase + mask, 4 steps, guidance 1.0): mean absolute change is **0.254 inside the mask vs 0.008 outside**, against the reference's 0.248 / 0.008 — the edit stays in the marked region and the rest is preserved. Locally: `184 passed, 3 skipped` across the five new test files plus the sampling-params / image-API suites, and `node --test docs/scripts/tests/*.test.mjs` 52/52.
