## Motivation

<!-- Describe the purpose and goals of this pull request. -->
This PR speeds up the Qwen3.8 QSA prefill indexer when a batch contains many requests with long cached prefixes.
Previously, each query row’s score buffer had space for all compressed keys in the batch. The PR stores scores in request-relative columns, reducing the buffer width to the longest request’s compressed-key count.

## Modifications

<!-- Detail the changes made in this pull request. -->
The implementation:
- Removes batch-wide zero-fill and masking; top-k reads only each row’s valid scores.
- Fits more query rows into the same workspace budget, reducing scoring chunks and kernel launches.
- Derives buffer width from CPU sequence lengths to avoid an additional GPU synchronization.
- Splits key ranges across GPU blocks to improve parallelism.
