# [Fix] diffusion/server: Clean up rejected and cancelled video requests

[Upstream PR](https://github.com/sgl-project/sglang/pull/46057) · state: closed · merged: True

## Original PR description

## Summary

Fix request-owned resource leaks in `POST /v1/videos` before background dispatch:

- Share the existing temporary-directory helper with the image API, using an async exit stack to transfer cleanup ownership from the request to the background job.
- Clean up rejected JSON/multipart requests and preparation failures, without deleting configured persistent input/output directories.
- Wait for CPU preparation to finish before cleaning up a cancelled request. Cancelling an await does not stop its thread.
- Let newly created background jobs enter their cleanup scope before shutdown cancels them.

No new flags or resource-management framework. Production code decreases by 13 lines; most diff churn is indentation around the cleanup scope. This fixes existing behavior on main, independently of #45919.

## Validation

- Regression tests fail before the fix for malformed JSON, invalid multipart fields, cancellation during CPU preparation, and immediate shutdown.
- 139 related tests pass on the fix; 161 pass when integrated with #45919 and #46025.
- Real H200 / Wan2.1-1.3B HTTP comparison: four bursts of 100 rejected requests at concurrency 8. Old code accumulates 400 temporary directories and returns 500 for invalid multipart fields. Fixed code leaves zero and returns 400.
- Each version completes eight valid video jobs, including one after every rejection burst. Decoded frames match between versions; persistent output files remain available.
- Combined real-server validation with #45919/#46025 passes concurrent progress polling, multi-output generation, malformed progress IPC, and deletion without late-update resurrection.
- Pre-commit passes.

This does not implement GPU job cancellation, durable job storage, or bounded cancellation of arbitrary blocking preprocessing.
