# [Perf] Qwen3.8: Allow breakable prefill CUDA graphs for image batches

[Upstream PR](https://github.com/sgl-project/sglang/pull/46329) · state: open · merged: False

## Original PR description

## Motivation

With `--cuda-graph-backend-prefill breakable`, the prefill runner refuses graph replay for every Qwen3.8-Flash-Next (Qwen4-Exp) batch that carries multimodal inputs, so image prefills always run eager.

**Scope:** this enables graph replay for image prefills in deployments without speculative decoding. With speculative decoding enabled (any algorithm, including NGRAM), behavior is unchanged.

- The refusal came with #41729, which added breakable prefill graphs for this model with text-only scope.
- Multimodal `input_embeds` already replay under breakable graphs (#31391): the eager outer forward builds the merged text and vision embeddings, and replay copies them into the captured static slot, as for text batches.
- With speculative decoding, the draft runner still refuses image batches, and the target must refuse with it: under DP attention the replay vote consults only the target runner and the draft follows it, so a draft-only refusal could split ranks between replay and eager.

This PR keys the refusal on whether speculative decoding is enabled, a launch-time property identical on every rank. Without speculative decoding, image batches become replay-eligible; with any speculative algorithm (including NGRAM), behavior is unchanged. No new flag, environment variable or API.

## Modifications

- `python/sglang/srt/model_executor/runner/prefill_cuda_graph_runner.py` (+8/-4): replace `_qwen_bcg_mtp_draft` (no other reader) with `_qwen_bcg_multimodal_eager = qwen_bcg and model_runner.spec_algorithm.is_speculative()`, and gate multimodal batches on it.
- `test/registered/unit/model_executor/test_prefill_cuda_graph_runner.py`: flag derivation for no speculative decoding, EAGLE and NGRAM.
- `test/registered/unit/managers/scheduler_components/test_dp_attn.py`: DP vote with one image rank and one text rank, refusal on and off.
- `test/registered/unit/configs/test_multimodal_piecewise_cuda_graph.py`: forward-time gate for image and text batches.
- `test/registered/unit/model_executor/test_prefill_cuda_graph_runner_helpers.py`: drop fixture lines for the removed flag.

The breakable prefill backend is the default on CUDA, so there this applies by default to Qwen3.8-Flash-Next without speculative decoding. On ROCm it is opt-in.

## Speed Tests and Profiling

**Setup**
- Image: `lmsysorg/sglang-rocm:v0.5.22-rocm724-mi35x-20261024`, SGLang tree `13b7ef75c5` with this commit applied (`prefill_cuda_graph_runner.py` is unchanged between that tree and this PR's base), torch 2.11.0+rocm7.2.
- Hardware: 2x MI355X (gfx950).
- Model: `amd/Qwen3.8-Flash-Next-Quark-MXFP4` (revision `b2091c38`), MTP off.
- Server (all arms): TP2 + EP2, `--attention-backend aiter --linear-attn-backend triton --context-length 8192 --max-running-requests 128 --disable-radix-cache --mm-enable-dp-encoder`.
