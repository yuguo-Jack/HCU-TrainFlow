# [Perf] [AMD] mimo-v2.6: Fuse RoPE and KV-cache insertion on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/44272) · state: open · merged: False

## Original PR description

## Motivation

MiMo-V2.6-Pro-RL runs separate decode kernels for partial RoPE, semantic V scaling, and asymmetric K=192/V=128 KV-cache insertion. The generic fused SGLang path assumes equal power-of-two Q/K/V dimensions and cannot serve this geometry.

Tracks [SILOTIGER-1251](https://amd.atlassian.net/browse/SILOTIGER-1251).

## Changes

- Add a MiMo-specific gfx950 Triton kernel for decode batches up to 16 tokens.
- Apply NeoX RoPE to the 64 rotary dimensions of Q/K head size 192.
- Apply MiMo's semantic V scale.
- Write rotated K and scaled V directly into BF16 KV cache.
- Support 4D NHD and vectorized 5D cache layouts, including SWA slot mappings.
- Skip the ordinary KV write when fusion succeeds.
- Add guarded dispatch behind `SGLANG_ROCM_MIMO_FUSED_FRONT=1`.

This PR consumes ordinary Q/K/V from `qkv_proj` and is independent of the fused-QKV PR.

## Correctness

- Standalone 4D and 5D cache-layout tests at M=1, 4, and 16.
- Device scalar K/V cache scales.
- CUDA graph capture and replay.
- Registered MI35X GPU tests: 2 tests and 6 shape/layout subtests.
- MiMo GSM8K exact match: 0.98.

MiMo's native MXFP4 layout correctness fix is tracked separately by #41573.

## Performance

|---|---:|---:|
| 60k/c16 | +1.03% | -0.463 ms |
| 128k/c4 | +3.15% | -0.927 ms |
