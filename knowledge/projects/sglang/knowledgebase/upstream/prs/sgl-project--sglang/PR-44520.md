# [Fix] weight_checker: Preserve rotary embedding axis_map buffer during reset

[Upstream PR](https://github.com/sgl-project/sglang/pull/44520) · state: open · merged: False

## Original PR description

### Summary

When `WeightChecker._reset_tensors` executes, it resets model parameters and non-whitelisted buffers. In M-RoPE models (e.g. Qwen3.5-VL), `MRotaryEmbedding` registers `axis_map` as a non-persistent `int64` buffer indicating temporal/height/width rotary lane indexing.

Because `axis_map` was omitted from `_NON_PERSISTENT_BUFFER_PATTERNS`, `reset_tensors` overwrites the buffer with random `int64` values. Subsequent weight update checks or kernel executions using `axis_map` fail or encounter memory corruption as lane indices diverge outside `{0, 1, 2}`.

### Changes

1. **`python/sglang/srt/utils/weight_checker.py`**:
   - Added `"axis_map"` to `_NON_PERSISTENT_BUFFER_PATTERNS` so `_is_non_persistent_buffer_name()` preserves the buffer across resets and excludes it from parameter checksum mismatches.
2. **`test/registered/unit/utils/test_weight_checker.py`**:
   - Registered `rotary_emb_axis_map` in `_TinyModel`.
   - Added `test_skips_axis_map` in `TestResetTensors` verifying the buffer is untouched during `_reset_tensors()`.
   - Added `test_matches_axis_map_substring` in `TestIsNonPersistentBufferName`.
   - Verified snapshot capturing and non-persistent checksum filtering.

Fixes #44501
