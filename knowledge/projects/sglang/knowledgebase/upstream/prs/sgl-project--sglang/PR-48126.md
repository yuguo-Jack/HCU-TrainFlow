# [Feat] [NPU] attention: Support Modelslim GQA mxfp8 kvcache for 950 NPU

[Upstream PR](https://github.com/sgl-project/sglang/pull/48126) · state: open · merged: False

## Original PR description

## Motivation
- Extend the ModelSlim KV-cache infrastructure introduced by the MLA C8 PR to support GQA MXFP8 KV cache on Ascend A5. This enables Qwen models, including models with head dimension 256, to consume QK_MXFP8_DYNAMIC_V_MXFP8_PER_CHANNEL checkpoints and reduce KV-cache memory usage.
- To integrate QFA op with no new bubble  between steps, support in-graph metadata prepare. To avoid accuracy risks caused by the scheduler modifying req_pool_indices (and other info) of the current batch before they are read, while preparing the next batch.read-done signal for npu.

## Modification
- Add a dedicated ModelSlim MXFP8 scheme with dynamic grouped Q/K quantization, static per-channel V quantization, and TP-aware scale loading and replication.
  - Q (query) and K (key) use dynamic MXFP8 quantization, with one scale computed for each group of 32 consecutive channels within each token and attention head.
  - V (value) uses static per-channel quantization, with one checkpoint-provided scale for each KV head and channel, shared across all tokens.
- Extend the NPU MHA memory pool with paged MXFP8 K/V storage, scale buffers, quantized cache writes, and memory accounting for scales.
- Integrate QFA through sgl_kernel_npu.operators.attention for prefill, prefix/chunked prefill, eager decode, graph decode, and MTP execution.
- Since QFA supports device-side metadata preparation, move sequence-length updates, page-table construction, and scheduling-metadata generation into the captured graph through the existing metadata hooks to reduce host dispatch overhead and small ops execution gaps. This requires an in-graph preparation path and bypassing FIA-specific host sequence-length updates during QFA graph replay.  To protect information (like  req_pool_indices) be modified by scheduler too early, also support read-done signal though aclrtRecordEventWithFlag for NPU.
<img width="663" height="444" alt="image" src="https://github.com/user-attachments/assets/4c2b8092-92ff-40d8-bec7-594ecdc5d58a" />

- Wire scheme initialization and FA parameter loading into Qwen3 dense/MoE and Qwen3.5/3.6 models, including Qwen3.5 MTP. Share initialization through ModelSlimConfig.init_kv_cache(), with the existing MLA initializer delegating to the same entry point.
- Support PD disaggregation by reusing the existing KV cache transfer path and transferring dynamic K scales through the BLOCK_SCALE mechanism, while initializing static V scales locally on each worker.
- Fix flat packed-module mapping resolution so ModelSlim-quantized GDN fused projections select the correct Linear scheme and register their weight scales.
Enable this path with:
--quantization modelslim --kv-cache-dtype fp8_e4m3
Requires CANN 9.2 and an sgl-kernel-npu package exposing the QFA and QFA metadata interfaces. HiCache is outside this PR’s scope.
