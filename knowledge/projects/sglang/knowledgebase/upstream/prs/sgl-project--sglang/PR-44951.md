# [Fix] sgl-router: Fill the media fields when converting TextGenerate to Generate

[Upstream PR](https://github.com/sgl-project/sglang/pull/44951) · state: closed · merged: True

## Original PR description

## Motivation

`experimental/sgl-router` does not compile on main since #42833 (3acfa2efcc5):

```
error[E0063]: missing fields `audio_data`, `image_data` and `video_data` in initializer of `sglang_api_types::runtime::v1::GenerateRequest`
   --> src/proxy/grpc.rs:371:5
```

#42833 added `image_data` / `video_data` / `audio_data` to `runtime.v1.GenerateRequest`. Its branch forked main on 2026-10-10, before #42681 added the router's `TextGenerate` → `Generate` conversion that builds a `GenerateRequest` literal, so both sides compiled on their own and the merge broke the router. The router workflow did not run on #42833's head, and pushes to main only run the gate, so every router PR is now red at `tier-1 — lint` (`cargo check`), e.g. #43592.

## Modifications

`src/proxy/grpc.rs`: the `TextGenerate` route carries no media, so the conversion sets the three new fields to empty vectors. Fields are listed explicitly rather than `..Default::default()` so the next proto addition fails loudly here again.

## Accuracy Tests

N/A (compile fix; the text route still forwards no media).

Local in `experimental/sgl-router`: `cargo fmt --check`, `cargo clippy --all-targets --all-features -- -D warnings` and `cargo test --lib proxy::grpc` pass on main plus this change.
