# [Feat] lora: Inkling shared-sink LoRA on the dense engine (09/21)

[Upstream PR](https://github.com/sgl-project/sglang/pull/42876) · state: closed · merged: False

## Original PR description

Part 09 of 21 of the LoRA runtime stack (branch `lora-stack-08-inkling-sink`, base `lora-stack-07-mla-correction`). The stack is cut from the development branch of #42284.

## What this part adds

Add InklingBatchDenseMLPWithLoRAV2, which runs the shared sink on the pool
buffers through the dense runner, and keep the legacy wrapper for the other
backends. The model factory picks the class by backend; LoRAManager binds only the sinks an adapter targets.

Tests: sink numerics, linearized-LoRA units, routed/sink overlap gate.

## Verification

- GB300 run r45: the tree of upstream main `c1c287a429` plus parts 01–09 imports every module this part changes and passes this part's tests together with every earlier part's unit tests: **417 passed, 20 warnings, 152 subtests passed in 29.32s** (excluding the tests that fail identically on the untouched base tree in that environment).
- `pre-commit` passed on the changed files of every part; `pre-commit run --all-files` passed on the complete stack tree.

The complete 21-part tree equals the development branch of #42284 at `e7b7179a86` (the `6588053ef2` tree with four test-only follow-ups squashed into its dense commit: the admission/snapshot trim, the restored FP8 block-shape admission pin, a second trim that keeps only the tests guarding silent failures and adds pins for four coverage gaps, and restored numerical and packing coverage; production code is unchanged) minus the benchmark tools and the Triton MoE tuning tables, which follow in separate PRs.
