# [Feat] disaggregation: Gate Mooncake session recovery on one real transfer trial

[Upstream PR](https://github.com/sgl-project/sglang/pull/48120) · state: open · merged: False

## Original PR description

## Motivation

The existing failed-session probe loop can remove a session from the blacklist after a successful control probe or idle timeout. A responding peer can still fail KV, state or auxiliary writes. Add an opt-in mode in which metadata refresh and probe success authorize one room to try real transfer; they do not immediately restore traffic.

Depends on [Mooncake #5194](https://github.com/kvcache-ai/Mooncake/pull/5194), which adds the strict `refresh_session` API. The optional mode requires a Mooncake build containing that API; it remains disabled by default.

## Modifications

- Add `SGLANG_ENABLE_FAILED_SESSION_REPAIR`, default false. When enabled it also enables the existing probe thread, reusing upstream exponential backoff. Prefill startup rejects an engine without the native refresh method.
- Reuse the existing contribution's refresh/probe gate, per-session trial grant and failure accounting. Only one bootstrap room can use the grant. KV, required state and auxiliary completion, with a real nonempty final KV write, permit readmission. Empty/dummy writes and control probes alone do not.
- Refresh/probe failures can retry on the existing schedule. A failed real trial consumes the grant and remains isolated; success clears incident state so a later independent failure may receive a new trial. A cancelled room can release its binding without another refresh after outstanding writes finish.
- Disable idle unblacklisting and registration-driven unblacklisting in repair mode. Continue to validate peer state layouts. Keep default-off auxiliary-failure blacklist behavior unchanged.
- Adapt cleanup to the current sender clear, abort and transfer-worker lifecycle. Do not import separate housekeeping, private metrics, routing, deployment or recovery-controller code.

The mode intentionally retains failed-session state for the manager lifetime rather than using idle expiry to bypass a failed trial. The new Mooncake API refreshes cached peers only: uncached or already-evicted entries do not receive a trial from this implementation. A transfer whose final chunk has no KV does not establish recovery, even if an earlier chunk carried KV. These are conservative limits of this initial feature, not complete recovery of every session fault. TENT's existing probe remains supported by upstream, but this new repair mode requires the classic refresh backend.

Upstream work inspected on 2026-11-03: merged #45338 supplies the probe/backoff/idle loop reused here; #35823 explores TTL readmission, #46911 changes failure thresholds, and #47025 adapts TENT probes. This feature differs by requiring actual transfer success. It adds no new P/D status-500 metadata, which already exists upstream.
