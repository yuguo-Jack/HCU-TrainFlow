# [Perf] function_call: Avoid O(N^2) buffer rescanning in KimiK3Detector streaming parser

[Upstream PR](https://github.com/sgl-project/sglang/pull/45125) · state: open · merged: False

## Original PR description

## Motivation

In `KimiK3Detector.parse_streaming_increment` (`python/sglang/srt/function_call/kimik3_detector.py`), every streaming chunk previously:
1. Re-searched `self._buffer` from index `0` for `<|open|>tools<|sep|>`,
2. Sliced the entire `tools` section (`section = self._buffer[open_idx + len(self.bot_token) :]`) and ran `_CALL_RE.finditer(section)` from the beginning of `section`, stepping the lazy `(?P<body>.*?)` quantifier across the entire unclosed call body on every chunk even when no new `<|close|>call<|sep|>` delimiter had arrived, and
3. Re-matched and re-decoded (`_decode_call`, `_ARG_RE.finditer`, `json.loads`, `json.dumps`) all previously emitted tool calls `0 .. self.current_tool_id` on every subsequent chunk before slicing `parsed[self.current_tool_id + 1 :]`.

When streaming large tool call payloads (such as code execution / file edits) or multi-tool turns, per-chunk latency grows linearly with the accumulated `tools` buffer size (`O(N)` per chunk, `O(N^2)` across the stream).

## Modifications

- Track `self._scan_pos` and `self._close_search_pos` across streaming increments in `KimiK3Detector`:
  - Before `<|open|>tools<|sep|>` arrives, search `self._buffer.find(self.bot_token, self._sent_normal_idx)` starting at `_sent_normal_idx` rather than index `0`.
  - Once inside the `tools` channel, check `self._buffer.find(CALL_CLOSE, self._close_search_pos)`. When no new `<|close|>call<|sep|>` delimiter has arrived, advance `_close_search_pos = max(self._scan_pos, len(self._buffer) - len(CALL_CLOSE) + 1)` and return immediately (`O(len(new_text))`) without slicing or invoking `_CALL_RE`.
  - When one or more `<|close|>call<|sep|>` delimiters arrive, run `_CALL_RE.finditer(self._buffer, self._scan_pos, last_close_end)` directly on the newly completed span `[self._scan_pos, last_close_end)` and advance `self._scan_pos = last_close_end`, so previously emitted calls are never re-matched or re-decoded and trailing unclosed call bodies are not scanned.
  - Skip redundant `_parse_calls` in `finish()` when at least one tool call has already been emitted (`self.current_tool_id >= 0`).
- Add `test_streaming_decodes_each_call_once` to `test/registered/function_call/test_kimik3_detector.py`.

## Benchmark (16-char streaming chunks)

| Workload | Before | After | Speedup |
|---|---:|---:|---:|
| Single 66 KB tool call (4,140 chunks) | 2,295.0 ms | 27.4 ms | **83.8x** |
| 8 sequential 8.4 KB tool calls (4,240 chunks) | 5,516.2 ms | 28.6 ms | **192.9x** |
