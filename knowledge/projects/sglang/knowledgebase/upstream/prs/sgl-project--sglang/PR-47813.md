# [Fix] [AMD] aiter: Decode DCP over a non-fp8 KV cache on Gluon instead of the asm kernel

[Upstream PR](https://github.com/sgl-project/sglang/pull/47813) · state: open · merged: False

## Original PR description

## Motivation

- With `--dcp-size > 1`, the aiter MLA DCP decode defaults to the asm kernel (`SGLANG_AITER_MLA_DECODE_BACKEND=asm`). It is a8w8: it casts Q to fp8 and passes the KV cache's fp8 scale.
- A bf16 KV cache, the default, has no scale. aiter raises `fp8 Q requires q_scale and kv_scale`, and the server fails during CUDA graph capture.
- So any MLA model with DCP and the default KV dtype cannot start on aiter.

## Modifications

- The asm DCP decode now also requires an fp8 KV cache (`_mla_dcp_asm_selected`). Other caches use the existing Gluon DCP decode; fp8 caches are unchanged.
- When `asm` was requested but the cache rules it out, the backend logs it once.
- `mla_gluon_supports_dcp_decode` (in `aiter_mla_gluon.py`) checks what aiter's `mla_gluon` asserts at run time. If the DCP decode falls to Gluon and Gluon cannot run it, startup fails with a clear `ValueError` instead of crashing at the first decode. The check runs only when this backend runs MLA decode.

| KV cache | `SGLANG_AITER_MLA_DECODE_BACKEND` | DCP decode kernel |
|---|---|---|
| fp8 | `asm` (default) | asm (unchanged) |
| fp8 | `gluon` | Gluon (unchanged) |
| bf16 | `asm` (default) | Gluon (was: crash) |
| bf16 | `gluon` | Gluon (unchanged) |

| Gluon requirement (else startup `ValueError`) | Source |
|---|---|
| Gluon importable, Triton >= 3.7, `SGLANG_AITER_MLA_GLUON=1` | `_gluon_fn` probe |
| gfx950 | `mla_gluon` arch assert |
| 1-96 gathered heads, not 64 | bh16 regimes; bh64 (64/128 heads) needs batch % 64 == 0 |
| bf16 or fp8 e4m3fn KV | bh16 KV dtype assert |

- Tests: `TestMlaDcpDecodeRoute` pins the route (its bf16 case fails before the fix); `TestMlaGluonSupportsDcpDecode` pins the Gluon limits.

## Accuracy Tests

DeepSeek-V2-Lite-Chat, TP2, aiter, MI355X. GSM8K: sgl-eval 0.1.3, 200 questions, greedy, max_tokens 1024.

| Setup | Before | After |
|---|---|---|
| bf16 KV, DCP2 | fails at startup | 0.550 |
| bf16 KV, DCP1 (reference) | 0.535 | unchanged |

- The scores count `\boxed{}` answers only. This model often writes "The answer is: N", which they miss; lenient scoring gives 0.67-0.71.
- End to end on our ROCm tree with this commit applied. The unit tests run on main.

## Speed Tests and Profiling

- None: bf16 KV with DCP did not start before.
