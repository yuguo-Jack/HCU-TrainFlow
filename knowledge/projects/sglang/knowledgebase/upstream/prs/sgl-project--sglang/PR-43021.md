# [Build][CI] Drop Python 3.10: require Python 3.11+ and run CUDA CI on Python 3.12

[Upstream PR](https://github.com/sgl-project/sglang/pull/43021) · state: closed · merged: True

## Original PR description

## Motivation

Python 3.10 reaches end of life in October 2026. This PR raises sglang's minimum Python to 3.11 and moves the CUDA CI stages onto uv-managed Python 3.12, the interpreter the `lmsysorg/sglang` image has used since #42612, where GPU CI previously tested the runners' system Python 3.10. It also unblocks dependencies that ship only 3.11+ wheels, e.g. `tml-renderers` (`cp311-abi3`); the code already uses unguarded 3.11-only APIs (`BaseException.add_note`, `tomllib`, `asyncio.TaskGroup`).

## Release note

**sglang now requires Python >= 3.11.** On Python 3.10, `pip install sglang` does not fail. Instead it resolves to the last release that still supported 3.10. Users on Python 3.10, such as the Ubuntu 22.04 system Python, need to move to 3.11+ to get new releases. Python 3.11 is a transitional floor: it will be dropped later with advance notice, around its October 2027 end of life or earlier if a core dependency such as torch drops it.

## Modifications

**CI runs on Python 3.12**

- `scripts/ci/cuda/ci_install_dependency.sh` installs into a uv-managed venv at `/opt/sglang-ci-py${SGLANG_TEST_CI_PYTHON}` (default `3.12`) on every runner, whatever Python its image ships.
  - Every job upgrades uv with pip and puts it first on `PATH`. It downloads a managed Python only when none is installed or the installed build lacks `os.memfd_create`, since the download comes from github.com, which some runner pools reach slowly enough to time out the install step.
  - The venv persists across jobs. The install writes a completion marker when it finishes, and a venv without one (a job cancelled mid-install) is recreated.
  - It is wired through the existing `VIRTUAL_ENV` / `GITHUB_PATH` / `BASH_ENV` mechanism.
  - A runner without fast github.com access can set uv's `UV_PYTHON_INSTALL_MIRROR` for that download; no CI runner sets it today.
- Rust extensions are built for cp312 only (`rust-ext-*-cp312` artifacts and cache keys). The CPU stages, the simulator stage and `rerun-test` pin setup-python 3.12 to match.
- `diffusion-ci-gt-gen.yml` installs its extra LTX dependencies into the active interpreter instead of the system Python.
- The unit-test coverage job (`ci-coverage-overview.yml`) installs into a throwaway venv under `$RUNNER_TEMP` and no longer touches the persistent venv.
- `pyarrow<26` is pinned wherever CI installs a package that pins numpy 1.26.4: next to `lmms_eval==0.5.0` in the CUDA install and in the simulator's `aic` extra (`aiconfigurator`); the NPU install already pins `pyarrow==23.0.1` on main (#43308). pyarrow 26 requires NumPy 2 at import without declaring it, so a fresh resolve would otherwise break `import datasets`.

**Minimum Python 3.11**

Python 3.10 reaches end of life in October 2026. CI and the production image run Python 3.12; 3.11 stays installable as a transitional floor until it is dropped with advance notice.

- `requires-python = ">=3.11"` in:
  - `python/pyproject.toml`, `pyproject_cpu.toml`, `pyproject_npu.toml`, `pyproject_xpu.toml`
  - `rust/sglang-{grpc,mm,server}/pyproject.toml`
- The `tomli ; python_version < '3.11'` dependency is removed.
- `release-pypi.yml` builds wheels for 3.11, 3.12 and 3.13; the sglang wheel bundles a version-specific native gRPC extension, so the floor needs its own wheel. Nightly and PR wheels are built on 3.12.
- The install docs, `bench_serving` and backend-plugin guides, and the MiniMax-M3 cookbook now state Python 3.11+. The Laguna-XS.2 cookbook's Python 3.10 note now refers only to its pinned cp310 nightly, since nightlies are built on 3.12.

**`memfd_create` on uv-managed Python**

python-build-standalone builds before 20260718, which uv older than 0.11.30 installs, have no `os.memfd_create`; on them the MiniMax H3 reference-video decode and the shared engram host table raise `AttributeError`. The install script replaces such a build with the latest one, which keeps CI off them, and users on one should upgrade uv and run `uv python upgrade 3.12`. The call sites are unchanged from main; the streamed-encode tests no longer skip when `os.memfd_create` is missing.

**FastAPI native telemetry**

FastAPI 0.142 traces every request once a global tracer provider exists, and sglang's tracing init sets one, so HTTP spans were exported even at trace level 0. Fresh installs, including new images, get 0.142+, while the runners' existing environments (0.136.1) hid it. Every sglang FastAPI app that can share a process with tracing init now passes `telemetry={"tracing": False, "metrics": False, "logs": False}`. FastAPI before 0.142 has no native telemetry and takes the keyword through `**extra`, so the dependency needs no version floor.

**Test fix for Python 3.12**

`test_vit_npu_graph_runner.py` patched a module that `patch.dict(sys.modules)` had already dropped; on 3.12, `mock` re-imports it through `pkgutil.resolve_name` without its `torch_npu` stub. The test now patches the module object.

**Unchanged**

- `python/pyproject_other.toml` (ROCm, MUSA, HPU, MPS), `kernels/aot/pyproject_rocm.toml` and `pyproject_musa.toml` keep `>=3.10`: the ROCm 7.2.0 images and MUSA still run on Python 3.10.
- `sglang-kernel-cpu` (`kernels/aot/pyproject_cpu.toml`) keeps `>=3.10`.
- `sglang-kernel` (`kernels/aot/pyproject.toml`) keeps `>=3.10`. It is built on 3.10 as a `cp310-abi3` wheel, which installs unchanged on 3.11+.
- `sgl-model-gateway` keeps its own interpreter range.

## Notes for hardware maintainers

- **AMD**: the ROCm 7.2.0 flavor uses `rocm/pytorch:rocm7.2_ubuntu22.04_py3.10_pytorch_release_2.9.1` (`docker/rocm.Dockerfile`) and `3rdparty/amd/wheel/sglang` pins cp310 ROCm wheels. Those still work because `pyproject_other.toml` keeps 3.10, but they need a 3.11+ base before ROCm can follow. rocm724 and rocm10 are already on Python 3.12.
- **Moore Threads**: `srt_musa` pins the `torch 2.11.0.post1` series (torch, torch_musa, torchaudio, torchvision, deep_ep), which has only cp310 wheels on the MTHREADS index. The `.post2` series has cp312 wheels. `docker/musa.Dockerfile` uses the ubuntu:22.04 system Python, and `scripts/ci/musa/musa_install_dependency.sh` pins the cp310 Triton wheel by sha256. Moving MUSA to 3.12 means repinning those, which needs MUSA hardware to validate.
- **Ascend**: `pyproject_npu.toml` now requires 3.11. Both component sets in the install guide satisfy it: CANN 9.0.0 (`python==3.11`, the set the prebuilt SGLang NPU images use) and CANN 9.1.0 (Python 3.12, the set NPU CI runs).

## Accuracy Tests

No model forward or kernel changes.

## Verification

This PR's own GPU CI is the end-to-end check: every CUDA stage installs into the 3.12 venv and runs against the unchanged `cp310-abi3` sgl-kernel wheel and the cp312 Rust extensions. On `efd68ddc523`, before the install script stopped downloading Python on every job, PR Test [Base](https://github.com/sgl-project/sglang/actions/runs/38139972257) and [Extra](https://github.com/sgl-project/sglang/actions/runs/38139971932) pass. On `0defd83f2d3` (run [37784357976](https://github.com/sgl-project/sglang/actions/runs/37784357976/attempts/1)), runners whose image ships Python 3.10 recreated `/opt/sglang-ci-py3.12` in a 48–323 s cold install, and later jobs on the same runner took about 35 s.

- memfd: `multimodal-gen-unit-test` in run [37704464694](https://github.com/sgl-project/sglang/actions/runs/37704464694/job/113077362818) ran on a pre-20260718 3.12.13 build, and 6 of its failures came from the missing `os.memfd_create` (4 in `test_minimax_h3_media`, 2 in `test_layerwise_offload`).
- Locally, with `os.memfd_create` deleted to simulate that build, main fails the same 6 tests; with the function present, all 205 pass.
- `test_tracing.py::test_trace_level_0` fails on main with FastAPI 0.143 (5 FastAPI spans exported) and passes with this PR.
- Local checks: `bash -n` and YAML load of changed scripts and workflows, `pre-commit`, `scripts/ci/test_diffusion_rust_gate.py`, and `configure_environment` against real `uv` (venv creation, marker-gated reuse, exported environment).
