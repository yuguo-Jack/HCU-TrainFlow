# [Rust] Reject full tokenizer queues without blocking intake

[Upstream PR](https://github.com/sgl-project/sglang/pull/42066) · state: open · merged: False

## Original PR description

## Motivation

The native server uses bounded queues in both directions between Intake and its tokenizer workers. If workers are waiting to return completed requests to a full Intake inbox, a blocking Intake send to the full tokenizer queue creates a deadlock.

## Modifications

Use `try_send` for tokenizer admission, matching multimodal admission. A full queue returns the existing overload error and deregisters the rejected request; a disconnected pool retains its internal-error response. Only successfully queued requests enter state tracking.

## Accuracy Tests

Two deterministic CPU regressions fail before the fix and pass afterward. They cover rejection, terminal response, deregistration, preserved queued work, tracking and recovery, plus the bounded return-queue cycle with the actual `Intake` and `TokenizerWorker`. Test teardown joins all worker threads even on the failing baseline. The disconnected-pool control is strengthened as well.

The full server library suite has 316 passing tests and 13 pre-existing POSIX shared-memory failures under local sandbox permissions. Local socket tests pass. These are queue/lifecycle tests; no model-output change or GPU accuracy claim.

## Speed Tests and Profiling

This resolves a blocked admission path. No throughput benchmark or GPU performance claim.
