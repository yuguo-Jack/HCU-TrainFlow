# [Doc] diffusion: Document IMAGEIO_FFMPEG_EXE for faster MP4 encoding

[Upstream PR](https://github.com/sgl-project/sglang/pull/48200) · state: open · merged: False

## Original PR description

## Motivation

#37662 pinned MP4 encoding to the static ffmpeg bundled with `imageio-ffmpeg`, so outputs stay reproducible. That makes sense as the default. On some CPUs, though, the bundled build (ffmpeg 4.2.2) is much slower than a recent ffmpeg, and the docs do not say how to opt out.

On an aarch64 host (8x RTX 5090, LTX-2.5 T2V, 960x544, 121 frames, `--x264-preset fast`), the two binaries took this long per video with the same arguments:

| ffmpeg | encode time per video |
|---|---|
| bundled 4.2.2 | 1.21 s |
| bundled 4.2.2, `ultrafast` preset | 1.10 s |
| distribution 6.1.1 (`IMAGEIO_FFMPEG_EXE=/usr/bin/ffmpeg`) | 0.42 s |

End to end, that is about 0.6 s per video, or roughly 6% of a 9.9 s request. Grace-based systems (GH200, GB200) are aarch64 too.

## Modifications

Docs only. `performance-optimization.mdx` gets a short "FFmpeg binary for MP4 encoding" section. It explains why the bundled binary is pinned, shows how to point `imageio-ffmpeg` at another binary with `IMAGEIO_FFMPEG_EXE`, and states the tradeoff. The default behavior does not change.

## Accuracy Tests

No code change. In the run above, only the MP4 encode differs: decoded frames are identical, the PSNR between the two encodes is 42 dB or higher, and the file sizes are the same.
