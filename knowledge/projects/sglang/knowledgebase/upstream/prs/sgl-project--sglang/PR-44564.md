# [Fix] dsa-eagle-topk: Copy token keys and scales when relocating index cache

[Upstream PR](https://github.com/sgl-project/sglang/pull/44564) · state: closed · merged: True

## Original PR description

Fix for dsa with speculative_eagle_topk=2


## Motivation

`DSATokenToKVPool.move_kv_cache` passes token-slot IDs to `IndexKeyCache.move`, but that method indexes its page buffer with them. With 64-token pages, slot 319 is page 4, offset 63; treating it as page 319 can access out of bounds. Small IDs that fit in the page dimension silently copy entire pages and overwrite unrelated keys.

This matters when speculative decoding relocates accepted tree tokens. The ordinary single-chain (`speculative_eagle_topk=1`) path skips that compaction.

## Modifications

Move each selected token's FP8 index key and scale within the physical-page view used by the cache writers and readers. Advanced-index gathering before assignment preserves overlapping swaps. Layers that reuse another layer's indexer remain skipped.

Nonempty moves with pooled index keys (`index_kpool > 1`) now fail explicitly: relocating individual tokens would require rebuilding their pooled keys.

## Accuracy Tests

On upstream main `87211088c98ae4f5b60625eebcce007db36aa6af`, the new small-ID regression fails: swapping slots 1 and 2 corrupts neighboring keys without a CUDA error. With this patch, all three GPU cases pass on one GB300:

- Small token IDs that previously selected whole pages.
- Cross-page overlapping swaps, including the final allocated slot.
- Empty moves.

The tests use a real DSA pool and its production key/scale writers and readers, checking exact key bytes, scales, unchanged neighbors, latent KV, and a layer that reuses another layer's indexer.

```bash
python -m pytest -q test/registered/kernels/ops/kvcache/test_dsa_index_cache_move.py
# 3 passed
```

These are cache correctness tests; no full-model branching-speculation accuracy run was performed for this PR.

Consequently this view makes each apparent token row contain pieces from multiple real tokens, so a branching speculative relocation silently copies mixed key bytes while copying one token's scale; use layout-aware offsets (or gather and re-store) for this path.
