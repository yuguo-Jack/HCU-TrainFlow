## Motivation

Parallel sampling gives its common-prefix seed and children distinct request IDs but the same bootstrap room in the [Python tokenizer path](https://github.com/sgl-project/sglang/blob/6cac4dc3fe9a4bf15009f300132c3c7a1853c210/python/sglang/srt/managers/tokenizer_manager.py#L2136-L2195). NIXL indexes in-flight transfer state by room, so the collision can fail transfer. [PR #43863](https://github.com/sgl-project/sglang/pull/43863) fixes the Rust frontend, not this path; related [#26486](https://github.com/sgl-project/sglang/pull/26486) and [#24223](https://github.com/sgl-project/sglang/pull/24223) closed without merging.

## Modifications

Give the seed and each child a deterministic, distinct 63-bit room while preserving its data-parallel routing. Single-sample requests stay unchanged; explicit per-child rooms remain supported. No user-facing documentation changes are needed.

## Accuracy Tests

- Historical NIXL P/D requests with 2–4 samples hit a transfer-worker assertion before the fix; `2/2` matched fixed runs completed.
- On main `2e7c9d851c`, the tokenizer-manager suite passed `52/52` with a `datasets` stub. A current-main NIXL P/D serving replay on the fix branch completed public requests with 2, 3, and 4 samples (all HTTP 200); the router, prefill, and decode workers and the post-run probe stayed healthy. The prefill log did emit one nonfatal NIXL descriptor-shape error, so this is a limited smoke test. It used Triton/eager execution because the local `sglang-kernel` 0.4.5 is incompatible with main's FA3 CUDA-graph path; it is not a matched FA3 performance result.

## Speed Tests and Profiling

RTX A6000, NIXL P/D, dummy Llama-4, Triton/eager: two warmed 30-request rounds at concurrency 3. Single-sample control throughput was 359–381 vs. 365–369 output tok/s (baseline vs. fix). With 2–4 samples, baseline failed all six warmups; the fix completed 60/60 measured requests at 388–396 tok/s. A speed ratio is therefore not meaningful; FA3/CUDA graphs were not benchmarked.
