# [Fix] routed-experts: reset routed_experts_start_len when a request is rejected at intake

[Upstream PR](https://github.com/sgl-project/sglang/pull/48207) · state: open · merged: False

## Original PR description

## Motivation

Any client can stop the scheduler today with one request. The routed-experts check, which rejects a negative `routed_experts_start_len`, runs after the other intake checks. A request rejected by an earlier check (an out-of-range `logprob_start_len`, a prompt longer than the limit, a multimodal prompt that grows past it) keeps its negative start, runs its one-token abort prefill, and `get_topk` raises `ValueError: start_len=-5 must be non-negative` in the scheduler. The server exits and every in-flight request is lost.

Reproduced on upstream main with `Qwen/Qwen3-30B-A3B`, `--enable-return-routed-experts`, on H100 and GB300: `{"return_routed_experts": true, "routed_experts_start_len": -5, "return_logprob": true, "logprob_start_len": 1000000}`.

## Modifications

- `Req.set_finish_with_abort` resets `routed_experts_start_len` to 0, next to the existing `logprob_start_len` reset. Every intake rejection goes through it.
- The now-duplicate reset in the scheduler's routed-experts check is removed.
- Tests:
  - `test/registered/unit/managers/test_req_finish_state.py` (CPU): `set_finish_with_abort` resets both start lengths. Fails on main.
  - `test/registered/rl/test_return_routed_experts.py::TestRoutedExpertsStartLen::test_negative_start_len_survives_intake_abort`: the request above is aborted on its own and the server keeps serving. On main the server dies.

## Accuracy Tests

No output change on any request that is not rejected. Same GPU, same container, `--enable-deterministic-inference`: 1x GB300, `Qwen/Qwen3-30B-A3B`, `--enable-return-routed-experts --enable-deterministic-inference --moe-runner-backend triton` (the default GB300 MoE backend does not capture routed-experts rows yet; see #47524), baseline `8d4e1ce4c7` and this PR in one container on one GPU.

| Check | upstream main | this PR |
|---|---|---|
| 12 requests (6 prompts x 24 greedy tokens, single and batched): output ids and routed-experts rows | reference | byte-identical |
| Request above (`routed_experts_start_len=-5`, rejected by `logprob_start_len`) | scheduler `ValueError`, server gone | HTTP 400, server keeps serving |

`TestRoutedExpertsStartLen` on one GB300 node (TP2, as registered): the new test passes. `test_start_len_with_cache_hit` fails on main and on this PR alike on this setup (`--enable-deterministic-inference` disables the radix cache there).

## Speed Tests and Profiling

No speed impact: one assignment on the rejection path.
