# trace: split decoder bootstrap and KV allocation wait

[Upstream PR](https://github.com/sgl-project/sglang/pull/36374) · state: open · merged: False

## Original PR description

## Motivation

The existing `decode_bootstrap` trace slice covers two operationally different phases:

1. bootstrap handshake; and
2. waiting for decoder KV allocation.

The metrics path already separates these as `kv_transfer_bootstrap_ms` and `kv_transfer_alloc_ms`, but traces expose only the combined span. Under decoder pressure this makes a long KV-allocation wait look like slow bootstrap or transfer.

## Modifications

- Keep the existing `decode_bootstrap` span for backward compatibility.
- Add `decode_bootstrap_handshake` from decode preallocation entry to bootstrap completion.
- Add `decode_kv_allocation_wait` from bootstrap completion to transfer-queue entry.
- Add a unit test that verifies all three trace boundaries.

## Accuracy Tests

Not applicable. This changes trace emission only and does not affect model execution or outputs.

## Speed Tests and Profiling

Not benchmarked. Scheduling, allocation, and transfer behavior are unchanged. The patch emits two additional trace slices when request tracing is enabled.

Thanks @sufeng-buaa. These are not redundant, they run in separate processes.

`compute_and_observe_kv_transfer_metrics` has a single caller, in the prefill worker's inflight queue ([prefill.py:920](https://github.com/sgl-project/sglang/blob/8ad7641/python/sglang/srt/disaggregation/prefill.py#L920)). `set_decode_transfer_queue_entry_time` has a single caller, in the decode worker's preallocate path ([decode.py:1523](https://github.com/sgl-project/sglang/blob/8ad7641/python/sglang/srt/disaggregation/decode.py#L1523)). `DecodePreallocQueue` is constructed only under `if disaggregation_mode == DECODE` ([scheduler.py:1423](https://github.com/sgl-project/sglang/blob/8ad7641/python/sglang/srt/managers/scheduler.py#L1423)), with the prefill branch in a separate `elif`.

In P/D disaggregation prefill and decode are separate processes, each with its own `metrics_collector` labeled by `engine_type`. So the two `observe_kv_transfer_bootstrap` sites ([req_time_stats.py:972](https://github.com/sgl-project/sglang/blob/8ad7641/python/sglang/srt/observability/req_time_stats.py#L972) and [:1029](https://github.com/sgl-project/sglang/blob/8ad7641/python/sglang/srt/observability/req_time_stats.py#L1029)) never touch the same collector instance. "Guaranteed to be executed" holds only on the prefill worker; the decode worker cannot reach `compute_and_observe_kv_transfer_metrics`. No double-count.

Scope kept to trace emission only. Happy to follow up on broader observability refactor in a separate PR if useful.

The PR diff adds only `observe_per_stage_req_latency` + `trace_slice` for the two new stages, and adds no new `observe_kv_transfer_bootstrap` emission. The single decode-side `observe_kv_transfer_bootstrap` call is pre-existing, just routed through a wrapper. So splitting the stage does not duplicate the `kv_transfer_*_ms` histograms.
