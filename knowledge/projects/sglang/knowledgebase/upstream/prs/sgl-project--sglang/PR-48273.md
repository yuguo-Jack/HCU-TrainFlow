# [Fix] models: Pass HF sliding windows to RadixAttention without the query

[Upstream PR](https://github.com/sgl-project/sglang/pull/48273) · state: open · merged: False

## Original PR description

## Motivation

`RadixAttention.sliding_window_size` is the number of keys a query may see before itself: fa3 uses `window_size=(sliding_window_size, 0)`, and the triton extend and torch_native masks keep `k_pos >= q_pos - sliding_window_size`. An HF config's `sliding_window` counts the query too (`kv_idx > q_idx - sliding_window` in `transformers.masking_utils`), which is why Gemma 2/3, EXAONE 4, OLMo 2 and gpt-oss pass `config.sliding_window - 1`.

These layers pass the HF value through unchanged:

- `commandr.py` (Cohere2: Command R7B, Command A)
- `cohere2_moe.py`
- `exaone_moe.py` (K-EXAONE, window 128)
- `gemma3n_causal.py` (its `get_attention_sliding_window_size` already returns `sliding_window - 1`, so its layers also disagree with the window the runner and SWA pool use)
- `step3p5.py` (Step-3.5-Flash, window 512)
- `transformers.py` (the Transformers fallback backend, so every HF model with sliding layers served through it)

The reference modeling code of all of these builds its mask with `create_sliding_window_causal_mask(config.sliding_window)`. In SGLang their sliding layers attend to one key more than the checkpoint's window on every backend that applies the per-layer window (triton extend, fa3, trtllm_mha), so outputs drift from the reference once a sequence passes the window.

MiMo-V2 (`mimo_v2.py`, `mimo_v2_nextn.py`) has the same off-by-one. #43678 already fixes it there, so it is left out of this PR.

Minimal repro: a tiny random-weight Cohere2 with `sliding_window=16`, scored teacher-forced in SGLang (triton backend) and in HF (eager, fp32). Run on an RTX 2060 SUPER (sm_75, fp16), torch 2.14.1.

```python
import random, sys, tempfile

import torch
import transformers


def hf_logprobs(path, ids, window):
    cfg = transformers.AutoConfig.from_pretrained(path)
    cfg.sliding_window = window
    model = transformers.AutoModelForCausalLM.from_pretrained(
        path, config=cfg, dtype=torch.float32, attn_implementation="eager"
    ).cuda()
    with torch.no_grad():
        lp = torch.log_softmax(model(torch.tensor([ids], device="cuda")).logits[0], -1)
    return [lp[i - 1, ids[i]].item() for i in range(1, len(ids))]


def main(impl):
    import sglang as sgl

    path = tempfile.mkdtemp()
    cfg = transformers.Cohere2Config(
        vocab_size=1024, hidden_size=256, intermediate_size=512, num_hidden_layers=4,
        num_attention_heads=4, num_key_value_heads=2, sliding_window=16,
        layer_types=["sliding_attention"] * 3 + ["full_attention"], logit_scale=1.0,
        initializer_range=0.1, bos_token_id=1, eos_token_id=2, pad_token_id=0,
    )
    torch.manual_seed(0)
    transformers.Cohere2ForCausalLM(cfg).to(torch.float16).save_pretrained(path)
    random.seed(0)
    ids = [random.randrange(3, 1024) for _ in range(96)]

    engine = sgl.Engine(model_path=path, skip_tokenizer_init=True, attention_backend="triton",
                        model_impl=impl, mem_fraction_static=0.5)
    out = engine.generate(input_ids=ids, sampling_params={"max_new_tokens": 1},
                          return_logprob=True, logprob_start_len=0)
    engine.shutdown()
    sgl_lp = [x[0] for x in out["meta_info"]["input_token_logprobs"][1:]]
    for window in (16, 17):
        gap = max(abs(a - b) for a, b in zip(sgl_lp, hf_logprobs(path, ids, window)))
        print(f"model_impl={impl}: max |logprob(SGLang) - logprob(HF, sliding_window={window})| = {gap:.4f}")


if __name__ == "__main__":
    main(sys.argv[1] if len(sys.argv) > 1 else "sglang")
```

## Modifications

- Pass `sliding_window - 1` to `RadixAttention` in the six places above. Gemma 3n reuses its existing `get_attention_sliding_window_size(config)`.
- Add a regression test to `test/registered/unit/model_executor/test_resolve_sliding_window_size.py` that builds each affected layer from a small config and checks its window. On main all six subtests fail with `8 != 7`; with this change the file passes (the existing Inkling cases pass either way).

Out of scope: models without `get_attention_sliding_window_size` still give the runner the raw config window, which FlashInfer decode and triton decode read instead of the layer's window. This is the same situation Granite and Laguna are in today and is unchanged here, so FlashInfer decode for these models still reads one extra key.

## Accuracy Tests

Teacher-forced logprobs against HF (eager, fp32) on the tiny random Cohere2 above, triton backend, served through `sglang.launch_server`. Prefill: max gap over three sequences of 64 to 100 tokens. Decode: max gap over 64 greedy steps from an 8-token prefix, rescored by HF.

| Path | prefill vs HF, before | prefill vs HF, after | decode vs HF, before | decode vs HF, after |
|---|---:|---:|---:|---:|
| native Cohere2 | 1.9136 | 0.0075 | 0.0079 | 0.0079 |
| `--model-impl transformers` | 1.9156 | 0.0082 | 0.0102 | 0.0102 |

Before the change, triton prefill and decode also disagreed with each other: prefill matched a 17-key window while decode matched 16. No affected checkpoint fits on the 8 GB GPU I used, so there is no GSM8K-style run on a real model.
