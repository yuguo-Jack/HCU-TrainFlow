# [NPU] support --enable-int8-mamba-checkpoint

[Upstream PR](https://github.com/sgl-project/sglang/pull/40140) · state: open · merged: False

## Original PR description

## Motivation

`--enable-int8-mamba-checkpoint` stores Mamba temporal states as int8 in the checkpoint pool to roughly double cache capacity, but it was not usable on Ascend NPU. The active pool's conv state layout on NPU is `[layers, pool, window, channels]` (required by the `causal_conv1d` CANN op), while the checkpoint pool follows the upstream `[channels, window]` convention. Copying conv snapshots between the two without alignment corrupts the cached conv windows, so the parameter fails on NPU.

## Modifications

- Import `is_npu` and cache it as `_is_npu` in `mamba_checkpoint_pool.py`.
- In `store_from_active` and `load_to_active`, apply `transpose(2, 3)` to the conv source when running on NPU, bridging the `[window, channels]` (NPU active pool) and `[channels, window]` (checkpoint pool) layouts.
- CUDA behavior is unchanged; only the `_is_npu` branch is new.

## Accuracy Tests

N/A for CUDA (path unchanged). On NPU, validated by the e2e reuse test (`test_npu_int8_mamba_checkpoint_reuse.py`)https://github.com/sgl-project/sglang/pull/43072, which passes: enabling int8 checkpoint doubles the effective capacity (the reuse collapse point moves from 256 to 1024 with int8 enabled), confirming conv/temporal snapshots round-trip correctly.

## Speed Tests and Profiling

N/A. This is an NPU portability fix — the added `transpose` only touches the small conv window tensors during cache store/hit, with negligible end-to-end impact; the CUDA path is untouched.

- qybnb · comment · 2026-10-08T06:33:23Z · [source](https://github.com/sgl-project/sglang/pull/40140#discussion_r4215669238)

File: `python/sglang/srt/mem_cache/mamba_checkpoint_pool.py` · line 279

The unconditional _is_npu transpose assumes that checkpoint conv_shapes are always [channels, window], but they come from the model configuration. KimiLinearStateShape already uses [window, channels], and _init_npu_conv_state preserves that order when is_kda=True. NPU KDA therefore has matching [L, slots, W, C] layouts in both pools before this change. transpose(2, 3) turns the source into [L, batch, C, W], so the store assignment fails when W != C; load_to_active has the same issue. Please select the conversion using explicit source/target layout or model metadata, preserve the KDA [W,C] path, and add an NPU KDA store/load regression case with a non-square conv shape.

- qybnb · comment · 2026-10-08T06:34:35Z · [source](https://github.com/sgl-project/sglang/pull/40140#discussion_r4215678962)

File: `python/sglang/srt/mem_cache/mamba_checkpoint_pool.py` · line None

 The transpose fixes the NPU GDN axis order but does not handle the extended conv window used by speculative decoding. _init_npu_conv_state allocates an active window of W + speculative_num_draft_tokens - 1, while the checkpoint still uses the model conv_shapes, [C,W]. For W=3, C=5 and draft_tokens=4, the transposed source is [L,batch,5,6] but the destination is [L,batch,5,3], so cache store still fails,please check it
