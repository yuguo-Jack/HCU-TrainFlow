## Motivation

When a request finishes before its first Mamba tracking interval, the [int8-checkpoint path](https://github.com/sgl-project/sglang/blob/6cac4dc3fe9a4bf15009f300132c3c7a1853c210/python/sglang/srt/mem_cache/unified_cache/components/mamba.py#L609-L627) reads an unwritten ping-pong state slot, then discards the zero-length checkpoint. The read is unnecessary; no output corruption was observed. Related [PR #44718](https://github.com/sgl-project/sglang/pull/44718) and [PR #39209](https://github.com/sgl-project/sglang/pull/39209) address different checkpoint cases.

## Modifications

Skip the state read when tracked length is zero; nonempty checkpoints are unchanged. No user-facing documentation changes are needed.

## Accuracy Tests

- Historical Qwen3.5-0.8B-Base HTTP warmup: the unwritten-state read disappeared after the fix.
- On main `2e7c9d851c`, the focused checkpoint suite passed `2/2` with CPU-device and `datasets` stubs. On the fix branch, Qwen3.5-0.8B-Base served 21/21 HTTP requests on an RTX A6000 with int8 Mamba checkpoints enabled. This was a functional smoke test, not a KVGuard-instrumented read check; the local kernel-version guard was bypassed because `sglang-kernel` 0.4.5 is older than main requires.

## Speed Tests and Profiling

RTX A6000, Qwen3.5-0.8B-Base, int8 checkpoints: two warmed baseline/fix pairs of 80-request rounds at concurrency 8. Output throughput ranges (baseline vs. fix) overlapped for short requests (571–650 vs. 616–647 tok/s) and longer requests (492–526 vs. 454–524 tok/s); no consistent change was observed. An unrelated GPU job overlapped later rounds, so small differences need an exclusive-GPU rerun.
