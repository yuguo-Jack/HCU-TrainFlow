# [Feat] diffusion/disaggregation: Add declarative stage deployments

[Upstream PR](https://github.com/sgl-project/sglang/pull/45394) · state: open · merged: False

## Original PR description

## Motivation

Roles should describe where pipeline stages run, rather than require a new hardcoded role and payload for each split. This adds an experimental, opt-in stage deployment path on top of the existing generation API and Mooncake transport.

Targets `main`; the prerequisite #45309 has landed. Main has been merged, not rebased.

## Modifications

- Declare stage groups, worker endpoints, replicas, node placement, and per-role server arguments in a deployment file. Select stages by registered name or zero-based index.
- Transfer the complete request context automatically between consecutive stage groups, including nested tensors, scheduler state, and consumed RNG state. Tensor data uses the tensor transport; tracing, metrics, and model modules remain process-local.
- Retain explicit-field contracts for parallel encoder branches and fan-out/join graphs. Automatic context transfer does not infer parallel branches.
- Load only the selected role's components and construct its stages through factories. Separate standard decoder postprocessing into a stage while retaining monolithic result handling.
- Add local node launch, bounded admission/result leases, cancellation cleanup, scalar-tensor transport support, and explicit remote error propagation.
- Support directly targeted encoder pools with `EncodingClient.encode(..., role=...)`, independent checkpoint/configuration per role, and independently sized replica pools. Same-model roles preserve explicit settings while recalculating automatic defaults for their GPU count.
- Add scoped, bounded, input-ordered client prefetch. Receive copies use a dedicated CUDA stream and do not block the event loop while completing; cancellation waits for the copy before recycling the receive slot.
- Update the generic disaggregation guide, CLI reference, and model integration guidance. Add focused unit coverage and a reusable manual cross-model E2E matrix.

## Speed Tests and Profiling

No latency, throughput, or peak-memory improvement is claimed. Full-context transfer prioritizes correctness and can transfer/retain more data than an explicit-field graph. Representative coordinator warmup and workload-specific benchmarking are still required before production rollout.

## Current Limits

- Automatic mode requires complete placement in original sequential order, with consecutive stages per role. Pipelines still need accurate stage/component manifests and compatible factories/loaders.
- Workers must be trusted and run matching source versions: control metadata uses Python serialization. Do not expose internal RPC to untrusted clients.
- Arbitrary runtime objects, hidden stage-local state, overlapping storage views, and arbitrary cross-role sharded layouts are not universally supported.
- Each worker executes one request at a time; replicas provide concurrency. Node launch starts local processes, not remote provisioning or cluster scheduling. Failed work is not durably replayed.
