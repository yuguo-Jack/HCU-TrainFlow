# [CI] install: Let a runner place the kept venv with SGLANG_CI_KEPT_VENV_DIR

[Upstream PR](https://github.com/sgl-project/sglang/pull/46341) · state: closed · merged: False

## Original PR description

## Motivation

The kept CI venv lives at `/opt/sglang-ci-py3.12`, inside the runner's own filesystem. The sourcem 5090 runners are now k3s pods, and a pod's filesystem lives in k3s's containerd store on the node's **root drive**. Two of those nodes have budget consumer root drives (Kingston NV3, WD Blue SN5000), and copying several GB of packages into the venv there took minutes instead of under a second. "Install dependencies" timed out at 20 minutes, and uv's shared-cache lock timed out after 300 s for the runners queued behind it.

For the same install step, `Installed 27 packages` took **0.36 s** on sourcem-node-4, whose runners keep their filesystem on the `/data` RAID, and **2 min 05 s** on sourcem-node-2, a k3s pod on a Kingston NV3 root drive.

## Modifications

- `ci_install_dependency.sh` uses `SGLANG_CI_KEPT_VENV_DIR` for the kept venv when it's set, and creates its parent directory. **Unset keeps today's `/opt/sglang-ci-py3.12`**, so every other runner is unaffected.
- The variable is deliberately not `SGLANG_CI_VENV_PATH`: `ci_cleanup_venv.sh` deletes that path after every job.

The runner side, mounting a per-runner `/data` directory and setting this variable on the sourcem pods, is a separate change in the platform repo. Until it lands, nothing sets the variable.

## Testing

- `bash -n` passes.
- Checked the path resolution with the variable unset (`/opt/sglang-ci-py3.12`) and set (the given directory).
