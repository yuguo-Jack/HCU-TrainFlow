## Motivation

A context-parallel KV layout that keeps each rank's KV sharded and padded (`--cp-kv-layout` with a strategy that sets `cp_kv_sharded`) sizes and indexes KV per rank. The unified memory pool's placement and PD transfers do not model that layout, so the combination could only fail later, at allocation or transfer time.

## Modifications

- `arg_groups/parallel_hook.py::handle_context_parallelism`: right after the CP strategy is bound, a sharded-padded strategy together with `--enable-unified-memory` is refused with a clear error. Static pools keep the sharded-padded accounting.
- `test/registered/unit/server_args/test_server_args.py`: with a sharded-padded strategy bound, unified memory is refused and the static pool is accepted.

**Behavior change:** `--enable-unified-memory` with a sharded-padded `--cp-kv-layout` now fails at startup instead of later.
