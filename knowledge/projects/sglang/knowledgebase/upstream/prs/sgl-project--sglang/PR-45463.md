## Motivation

On HIP the DSpark draft still reads its SWA through the target's paged full-to-SWA mapping, so with encoder SWA bounded replay the radix tree keeps an SWA component and cannot hit mid-prefix or across conversations.

## Modifications

- `uses_draft_swa_ring()` is true on HIP too (except unified_kv triton), and the pool keeps `swa_valid_from` for that ring.
- The HIP radix backend writes the draft block's SWA rows into the ring and skips the full-to-SWA translation; init asserts the ring is used only with the V4.1 DSpark block window.

## Accuracy Tests

GSM8K 5-shot, 1319 questions, same setup: main 0.889 -> 0.897 with the series.

## Speed Tests and Profiling

Measured with the full series (1/3-3/3) on 2x MI355X, TP2, DeepSeek-V4.1-Flash, DSpark, `--enable-encoder-swa-bounded-replay`, AgentX trace replay c64 PDI 8: TTT/GPU 157,543 -> 174,697 (+10.9%), TPOT p50 13.95 -> 11.84 ms, P90 interactivity 57.3 -> 65.5.
