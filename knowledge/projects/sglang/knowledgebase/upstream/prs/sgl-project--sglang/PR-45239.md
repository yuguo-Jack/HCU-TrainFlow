# [Fix] diffusion: Import fp8_fa_sm120 under a meta-device model build

[Upstream PR](https://github.com/sgl-project/sglang/pull/45239) · state: open · merged: False

## Original PR description

## Motivation

The `fp8_fa_sm120` attention backend cannot load a model whose transformer is built on the meta device. `fused_prep.py` computes a constant at import time:

```python
INVERSE_FP8_MAX = (torch.ones((), dtype=torch.float32) / 448.0).item()
```

The attention resolver imports the backend lazily, from `USPAttention.__init__`, and the transformer loader constructs the DiT under `torch.device("meta")` (`fsdp_load.initialize_model`). The first import of the backend therefore happens inside that context: `torch.ones` returns a meta tensor and `.item()` raises.

```text
File ".../fp8_fa_sm120/fused_prep.py", line 91, in <module>
    INVERSE_FP8_MAX = (torch.ones((), dtype=torch.float32) / 448.0).item()
RuntimeError: Tensor.item() cannot be called on meta tensors
Error while loading customized transformer, falling back to native version
ValueError: `low_cpu_mem_usage` cannot be False when `keep_in_fp32_modules` is True.
```

The transformer loader catches the first error and retries through its Diffusers path, which fails with the unrelated second error, so the request never starts. Reproduced with `Wan-AI/Wan2.1-T2V-1.3B-Diffusers` and `--attention-backend fp8_fa_sm120`. The existing unit tests miss it because they call the kernel directly instead of loading a model.

## Modifications

- `kernels/ops/attention/fp8_fa_sm120/fused_prep.py`: create the constant with an explicit `device="cpu"`. An explicit device overrides the default-device context, and the value is unchanged: outside a meta context the tensor was already created on CPU, so the FP32 reciprocal that keeps the scales bit-equal stays the same.
- `test_fp8_fa_sm120_attn.py`: `test_kernel_package_imports_under_meta_device` reloads `fused_prep` under `torch.device("meta")` and checks the constant is unchanged. It fails with the error above without the fix.

## Accuracy Tests

No numerical change: `INVERSE_FP8_MAX` has the same FP32 value as before. The full `test_fp8_fa_sm120_attn.py` suite passes, including the new test; the new test fails without the fix. These runs were on SM89 GPUs (RTX 4090, L40S) with the backend's SM120 gate lifted locally, since I do not have an SM120 card; the code path is architecture-independent. @emre570, could you run the suite on your RTX 5080?

With the fix, MiniMax-H3 (`t2va`, 50 steps) loads and generates end to end with `fp8_fa_sm120` on an L40S.

- syang-genai · comment · 2026-11-03T15:00:30Z · [source](https://github.com/sgl-project/sglang/pull/45239#issuecomment-6607197536)

Confirming this fix on an RTX 5090 (SM120) with LTX-2.5 T2V.

Without the fix, `--attention-backend fp8_fa_sm120` fails while the DiT is built, so the backend cannot be used at all:

```
  File ".../sglang/kernels/ops/attention/fp8_fa_sm120/fused_prep.py", line 91, in <module>
RuntimeError: Tensor.item() cannot be called on meta tensors
RuntimeError: Failed to load customized transformer; native fallback is disabled for this component configuration.
```

With this one-line change applied on top of `38d9e4a3f`, the backend loads and runs. Setup: 1x RTX 5090, 960x544, 121 frames, 8 steps, seed 42, three prompts. Flags: `--quantization convrot_int8 --layerwise-offload-components dit text_encoder --dit-layerwise-resident-layers 48 --dit-layerwise-residency-lifetime permanent --vae-tiling false`. Steady-state requests 2 and 3:

| attention | denoise | per step | end to end |
|---|---|---|---|
| default (cuDNN SDPA) | 6.14 / 6.20 s | 0.753 s | 11.64 / 11.51 s |
| `fp8_fa_sm120` (with this fix) | **5.12 / 5.17 s** | **0.628 s** | **10.63 / 10.50 s** |

That is about 17% less denoise time, or about 1 s per video, at the same peak memory (30.3 GB). The audio-branch attention (head_dim 64) falls back to cuDNN as documented. Output quality looks equivalent to the cuDNN BF16 run on all three prompts. PSNR against it is 19–25 dB, about the same gap as INT8 vs BF16 on this model, so the FP8 run is a different sample rather than a degraded one.
