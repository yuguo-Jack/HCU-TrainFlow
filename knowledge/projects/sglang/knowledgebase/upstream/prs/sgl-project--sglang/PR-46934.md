# [Fix] hicache: Restore sub-window SWA L3 hits under a mid-tree anchor

[Upstream PR](https://github.com/sgl-project/sglang/pull/46934) · state: open · merged: False

## Original PR description

## Motivation

An L3 hit shorter than one sliding window, under a mid-tree anchor, is dropped in both host-memory modes. It is the usual hit when a reader holds a prefix on device and another writer stored its continuation, e.g. a PD decode offloading its output KV.

End to end (PD with decode KV offload, hybrid SWA + Mamba model, window 512, page 128; a 512-token prompt whose decode wrote KV up to 768), the next turn's prefill reuse:

| prefill host memory | before | after |
|---|---|---|
| `cache` (`write_back`) | 512 (its own prompt; the 256 stored tokens are dropped) | 768 |
| `buffer_only` | 512 (the lookup is declined) | 768 |

Every turn's logprobs match a no-cache reference (max drift 4.4e-16). Run on a fork carrying this change.

## Modifications

- **Cache mode** (Python and Rust tree cores): `SWAComponent.prepare_prefetch` stages `min(span, window)` pages at any anchor, and the SWA prefetch commit no longer drops a short window under a non-root anchor. The window head is the anchor path's own SWA; the match validator (`create_match_validator`) accepts a boundary only after a full contiguous SWA window, so a short window whose head is gone never matches.
- **Buffer mode**: remove the full-window lookup minimum (`resolve_prefetch_threshold`). A staged hold pins FULL, not SWA, so the head of a staged short window can be evicted while it waits (the concern behind #39283); admission now refetches when this pass's joint match no longer reaches the window's start.
