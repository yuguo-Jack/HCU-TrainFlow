# [Perf] lightonocr: remap multimodal item offsets via bisect without dict/sort

[Upstream PR](https://github.com/sgl-project/sglang/pull/48365) · state: open · merged: False

## Original PR description

## Motivation

In `LightOnOCRProcessor.process_mm_data_async` (`python/sglang/srt/multimodal/processors/lightonocr.py`), removing Pixtral row-break and image-end tokens previously:
1. Allocated an $O(L)$ Python dictionary `old_to_new` mapping every surviving token position `old_idx -> new_idx`.
2. For each multimodal item, iterated over **every individual token index** `idx in range(start, end + 1)` across all `(start, end)` row spans in `mm_item.offsets`, looked up `old_to_new[idx]`, materialized the full list of thousands of remapped token indices, and called `sorted(...)` just to read `(new_indices[0], new_indices[-1])`.
3. Left stale un-remapped `mm_item.offsets` in place if all tokens inside `mm_item.offsets` were removed (`new_indices` empty).

For multi-page OCR workloads (e.g., 8 pages at $64 \times 64$ patches = 33,291 tokens), this dictionary construction + per-token expansion + sort adds unnecessary CPU overhead on every multimodal request.

## Modifications

- Replace the `old_to_new` dictionary with a contiguous `surviving_old_indices` list of surviving token indices (which is naturally strictly increasing).
- Use `bisect_left(surviving_old_indices, start)` and `bisect_right(surviving_old_indices, end) - 1` on each `(start, end)` span endpoint in `mm_item.offsets` to find the remapped `[min_new_idx, max_new_idx]` bounds in $O(R \log L)$ time without iterating over or sorting individual patch token indices.
- Clear `mm_item.offsets = []` when all tokens in `mm_item.offsets` are removed.
- Add unit tests in `test/registered/unit/multimodal/test_lightonocr_processor.py`.

### Micro-benchmark (8-page $64 \times 64$ document, 33,291 tokens)
- **Before**: `10.67 ms`
- **After**: `3.52 ms` (**3.03x speedup**)
