# [Fix] [NVIDIA] qwen: Bound serving allocations and handle empty and grayscale inputs

[Upstream PR](https://github.com/sgl-project/sglang/pull/47895) · state: open · merged: False

## Original PR description

## Motivation

Qwen3.8-Flash-Next deployment on H20 exposed three allocation/correctness failures: an idle attention-DP rank launched a zero-block grouped Gemma RMSNorm kernel; grayscale GPU JPEG decoding produced one-channel tensors; and large PLE host tables or many-image GPU preprocessing exceeded allocation limits.

The full optimization report, matched throughput comparisons, failed-candidate analysis, and public per-request exports are in [the fork issue](https://github.com/leviking98z-rgb/sglang/issues/2). This PR contains the runtime fixes and regression coverage. It is based on main `1ced9a9eb0224e5c12c9ed236b188868a635cd5c`.

## Modifications

- Return after validation for a zero-block grouped Gemma RMSNorm grid. Nonempty CUDA kernel code is unchanged.
- Request RGB explicitly in the torchvision GPU JPEG decode path, matching the existing PIL RGB conversion.
- Add opt-in Qwen GPU image preprocessing chunks with CPU feature transport. Reject incompatible transport modes; preserve the original path for CPU inputs and small batches.
- Add opt-in bounded CUDA host registrations for one contiguous PLE mapping, including storage/view lifetime ownership, partial-registration rollback, and retention on failed unregistration.
- Add focused CPU/CUDA regressions and document both optional environment settings. Their defaults remain zero; this PR does not change MTP, layout, concurrency, or transport defaults.

## Accuracy Tests

The original H20 qualification passed 33 RMSNorm tests including BF16/FP16 comparisons to an FP64 reference, empty/nonempty input, supplied outputs, and CUDA Graph replay. The 24/47-page and mixed-shape image fixtures preserved pixels, grids, shape, dtype, stride, and order bit for bit. PLE qualification checked boundary rows, TP masks, CUDA Graph replay, parameter-view lifetime, partial-registration rollback, and cleanup, including production-size tables on all 32 ranks.

Current-main patch qualification on one allocated H20: **52 passed, 0 failed, 0 skipped in 92.22 s** with pytest 8.4.2. The four test files cover the new RMSNorm, PLE, image-chunk and JPEG cases plus existing utility regressions. The source package was isolated from the running service environment; test dependencies were installed into a separate test-only directory. All changed files passed repository pre-commit checks.

## Speed Tests and Profiling

The image change is a memory tradeoff, not a speedup: for 47 synthetic pages, peak PyTorch GPU allocation dropped from **6.43 GiB to 0.80 GiB (-87.5%)**, while preprocessing time increased **0.790→1.184 s**. Measurements and output hashes are linked from the issue. PLE registrations and empty-grid/JPEG fixes have no standalone serving-throughput claim.

Separate tuning experiments on pinned measured commits achieved 11768/8879 output tokens/s for 1024/256 and 8192/1024 on 32 H20 (+47.7%/+54.9% vs matched TP8 baseline). On the final deployed service, raising HTTP concurrency 16→64 achieved 2553→4427 output tokens/s at 16K+1K and 1969→2934 at 32K+1K, with increased TTFT/TPOT. These are configuration/admission measurements, **not gains attributed to this code patch**. The issue retains source/model revisions, repetitions, latency, sample counts and workload limits.
