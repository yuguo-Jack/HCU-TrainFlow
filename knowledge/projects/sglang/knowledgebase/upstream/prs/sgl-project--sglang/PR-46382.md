Stacked on #46381 ([Feat] unified-memory: Fuse MLA drafts into MLA hosts); only the last commit is new here. Please merge after #46375, which makes these backends plan each draft step's own tokens.

## Motivation

flashmla, trtllm_mla and cutedsl_mla build their decode, target-verify and draft-extend page tables from the KV-index translator's plan, both eagerly and under CUDA graphs, and hand prefill to the FlashInfer MLA path. So an MLA draft fused into an MLA host reads its latent rows through them just as it does on fa3, flashinfer and triton. On an MLA host, though, the EAGLE draft-backend gate admitted only the MHA backends, which among the MLA backends are just those three.

## Modifications

- The EAGLE draft-backend gate (`arg_groups/kv_cache_hook.py`) also admits the unified pool's MLA backends on an MLA host, adding flashmla, trtllm_mla and cutedsl_mla.
- The fusion decision (#46381) already checks an MLA draft against that set and an MHA draft against the MHA backends, so an MHA draft that inherits one of them still does not fuse.

Tests (CPU), `test/registered/unit/server_args/test_unified_memory_spec_gate.py` and `test/registered/unit/mem_cache/test_fused_draft_placement.py`: the EAGLE draft gate admits flashmla, trtllm_mla and cutedsl_mla on an MLA host, named or inherited, and an MHA draft that inherits trtllm_mla there does not fuse; the gate case fails before this change and passes after.

## Accuracy Tests

SM90, `inclusionAI/Ling-3.1-flash`, TP 8, EP 8, `--attention-backend flashmla`, `--mamba-radix-cache-strategy extra_buffer`, `--speculative-algorithm NEXTN --speculative-num-steps 3 --speculative-eagle-topk 1 --speculative-num-draft-tokens 4`, radix cache, normal scheduler, with #46375 applied. GSM8K (all 1314 test questions, 5-shot, greedy, `python -m sglang.test.run_eval`), paired by question between the pools; median accept length from the scheduler logs. The unified-memory servers ran with `SGLANG_DEBUG_POISON_POOL=1`.

| CUDA graphs | GSM8K (default / unified) | one pool only right (default / unified), p | accept length (default / unified) |
|---|---|---|---|
| on | 0.902 / 0.902 | 12 / 12, p = 1.00 | 2.60 / 2.60 |
| on (earlier run) | 0.903 / 0.890 | 65 / 47, p = 0.11 | 2.61 / 2.61 |
| off (earlier run) | 0.896 / 0.917 | 46 / 73, p = 0.02 | 2.61 / 2.61 |

The earlier runs differ from the default pool in both directions; pooled over the three, neither pool is ahead.

**SM100 validation is pending.** trtllm_mla and cutedsl_mla need SM100 and have not run with a fused MLA draft yet; their table building is the TRT-LLM MLA code that #46375 tests on metadata only. Results will be added here before this is ready to merge.
