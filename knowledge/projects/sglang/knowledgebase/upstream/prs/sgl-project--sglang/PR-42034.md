# fix: skip cancelled queued renderer tokenization

[Upstream PR](https://github.com/sgl-project/sglang/pull/42034) · state: closed · merged: False

## Original PR description

## Motivation

When renderer batch preparation fails, `try_join_all` drops the remaining tokenization futures. For example, a completion batch with a later overlong request ID can fail after earlier prompts enter the tokenizer queue. The queued jobs still encode those prompts even though their reply receivers have been dropped, occupying tokenizer workers and delaying live requests. Cancelling a pending `tokenize_prompt` call has the same effect.

## Modifications

Skip dequeued tokenizer jobs whose reply receiver is already cancelled before encoding starts. Already-running tokenization is not interrupted; successful request ordering is unchanged.

## Accuracy Tests

- Two regressions fail before the fix and pass afterward, covering a dropped queued caller and queued siblings of a rejected batch. Both use the real renderer service and worker queue, and verify active and live requests still complete.
- Complete renderer suite: 129 library tests and 1 CLI integration test pass with Rust 1.92.
- Strict Clippy for the workspace, renderer test targets, multimodal features and radix-tree, formatting and touched-file pre-commit checks pass.

Prepared and independently reviewed with AI assistance (Codex).

## Speed Tests and Profiling

A local CPU backlog reproduction using `DynamoTokenizer` and a ByteLevel `tokenizer.json` fixture queued 16 cancelled prompts of 550KB each behind an active job. Actual encoding calls fell from 18 to 2 (the active and live requests). This demonstrates avoided queued CPU work; it is not a model inference or serving-throughput benchmark.
