# [Doc] [NPU] cookbook: add Qwen3 Ascend recipes and measured A3/A2 results

[Upstream PR](https://github.com/sgl-project/sglang/pull/40677) · state: open · merged: False

## Original PR description

## Motivation and scope

Add Ascend deployment recipes and measured results to the Qwen3 cookbook. Related task: https://github.com/Ascend/sglang/issues/1216.

Following the explicit hardware and validation boundaries in merged PR #40120, this contribution reports A3 measurements for 8B/30B and A2 measurements for 32B/235B. Multi-card A3 resources were unavailable; A2 results do not establish A3 performance equivalence. This documentation stage does not close the full hardware-validation task.

## Changes

- Add seven single-node, PD co-located recipes, with editable model paths, interfaces, service settings, and reproduction commands. Physical cards and logical NPU devices are labelled separately.
- Record complete accuracy and performance measurements for six recipes: A3 8B TP1/TP2, A3 30B low-latency/high-throughput, and A2 32B BF16/W8A8.
- Record A2 eight-device 235B W8A8 startup and 200-question GSM8K accuracy, while retaining its unverified status because the performance workload did not complete. The subset has its own accuracy label, with no fabricated speed metrics.
- Retain historical GPQA context-limit failures separately from the corrected 38000-token reruns. No answers or scores are spliced across attempts.
- Add six command-generator regression tests under docs/scripts/tests/, covering logical device counts, draft requirements, editable paths containing spaces, partial verification, stale selections, and the unchanged GPU default. The cookbook CI step executes that test directory, matching the convention accepted in #40120.

## Accuracy evidence

| Actual hardware / recipe | Protocol | Correct / scored | Result | Successful requests |
| --- | --- | --- | --- | --- |
| A3 8B W8A8 TP2 | GSM8K, 5-shot, temperature 0, output 512 | 1157/1314 | 88.05% | 1314/1314 |
| A3 8B W8A8 TP1 | GPQA Diamond, temperature 1, output 38000 | 112/198 | 56.57% | 198/198 |
| A3 30B-A3B W8A8 TP2 | AIME 2025, temperature 1, output 32768 | 23/30 | 76.67% | 30/30 |
| A2 32B BF16 TP4 | GSM8K, 5-shot, temperature 0, output 512 | 1139/1314 | 86.68% | 1314/1314 |
| A2 32B W8A8 TP4 | GPQA Diamond, temperature 1, output 38000 | 132/198 | 66.67% | 198/198 |
| A2 235B W8A8 TP8 | GSM8K fixed 200-question subset, 5-shot, temperature 0, output 512 | 192/200 | 96.0% | 200/200 |

The two 30B workload recipes share one accuracy run. The 32B BF16 result includes all 178 output-budget stops; AIME includes all three output-budget stops. The corrected A3 8B TP1 and A2 32B GPQA runs both completed with 198 natural stops. Historical 40000-token attempts are retained with the context-limit rejection included in the denominator; they do not validate the revised protocol.

The 235B run uses dataset rows 0–4 as demonstrations and rows 5–204 for evaluation, plain completion prompts without a chat template, top-p 1, 128 client threads, and a server limit of eight requests. All 200 responses finished with stop, with no recorded API errors or missing responses. Independent rescoring agrees. This is neither full GSM8K nor the registered A3 test, and it does not validate the A3 TP16/DP16 reference.

BF16 235B is not offered as a tested recipe and remains deferred pending storage and compute resources.
