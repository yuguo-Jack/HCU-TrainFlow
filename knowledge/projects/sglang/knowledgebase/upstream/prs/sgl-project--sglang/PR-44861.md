# [Fix] [NVIDIA] modelopt: Keep SM12x FP8 batch-invariant in deterministic mode

[Upstream PR](https://github.com/sgl-project/sglang/pull/44861) · state: open · merged: False

## Original PR description

## Motivation

On SM12x, ModelOpt static-FP8 linears can change reduction schedules between cold prefill and a shorter prefix-cache-hit batch despite deterministic inference being enabled. The same input sequence then receives different scores.

Related to #41351's ModelOpt path. Credit to `furedericca-lab` for the [diagnosis and initial fallback](https://github.com/sgl-project/sglang/issues/41351#issuecomment-5847506820), and `twu3202` for [identifying the small-M gap](https://github.com/sgl-project/sglang/issues/41351#issuecomment-5853051517). This does not claim to resolve every hybrid/GDN issue in that thread.


## Modifications

- In **SM12x deterministic mode only**, reuse Triton scaled MM with fixed N=64/K=128 reduction tiles and M-only tiles 16/32/128. Normal-mode and forced-Marlin dispatch remain unchanged.
- Zero masked A/B loads for partial K tiles.
- Extend the existing registered SM120 test file with 12 cached-suffix comparisons and two CUDA Graph replay cases covering bias, strided 3D inputs, BF16/FP16 and a K=80 tail.
- The 2026-10-22 refinement changes only the deterministic GEMM's pipeline from two stages to **three**, retaining the same tiles, warps 4, quantization, arithmetic and scaling. It overlaps loads while preserving the reduction schedule.

## Accuracy Tests

Complete source files are installed before each process starts; normal package imports are used, with no function/AST injection. This is official-nightly validation, not a latest-main rebuild or upstream CI.

## Speed Tests and Profiling

The isolated probe identifies GEMM as the main component cost in these cases; increasing pipeline depth is faster for several projection shapes while all 64 explored cases remain exact. These cache-evicted microbenchmarks are diagnostic; the end-to-end results below determine the performance claim.

32 forced output tokens per request, one warmup and five measured samples per cell per boot, cache flushed before requests, passive cooling to<=55C outside timing. PR-arm Graph boot order is **A(two stages), B(three stages), B, A**. Table medians pool ten samples per PR arm; per-boot medians, ranges and every sample are retained. The upstream Graph reference and each eager arm have one boot/five samples. Graph capture covers decode 1/2/4 and prefill 4/128/256/1024/2048/4096/8192; unsupported partial prefills may fall back to eager.

| Prefix / batch | Graph two stages → three | Wall-time reduction | Upstream Graph reference | Eager two stages → three |
|---|---:|---:|---:|---:|
| 128 / 1 | 0.3119s → 0.2796s | 10.3% | 0.2684s | 1.4868s → 1.4839s |
| 128 / 4 | 0.3539s → 0.3251s | 8.1% | 0.3322s | 1.5320s → 1.5275s |
| 2048 / 1 | 0.5314s → 0.5143s | 3.2% | 0.4766s | 1.5629s → 1.5642s |
| 2048 / 4 | 0.8900s → 0.8688s | 2.4% | 0.7953s | 2.0843s → 2.0747s |

The stage-only update reduces this Graph matrix's pooled median wall times by **2.4–10.3%**, most consistently on the short prompts. The 2048/1 cell varies between boots: current medians0.5285/0.5895s, candidate0.4982/0.5434s. Eager differences are within about 0.5%, so no meaningful eager speedup is claimed.

Against the single fresh upstream Graph reference, the three-stage path ranges from 2.1% lower to9.2% higher wall time. This does not eliminate the determinism/cost tradeoff or establish a general speedup. Earlier 5.7–25.8% nightly and 5–20% mixed-runtime Graph costs describe the prior two-stage measurements and remain in their historical evidence. All ten successful jobs stayed below 72 C, peaking at **66C** with the 400W limit unchanged.

[Full samples, boot medians and measurement limits](https://github.com/yibol9768-alt/sglang/blob/ef2c6cde610839e88a830f7a7cbcbb06c551e3d4/validation/rtx5090-20261017/round4/summary.json).

Duplicate check: inspected #34429 (small-M dispatch), #42865 (block/MXFP8), #38921 (SM89 prequantized inputs) and #44076 (GDN chunk alignment); these do not implement this static per-tensor deterministic path. [Original pinned diff audit](https://github.com/yibol9768-alt/sglang/blob/ca72d5212b33ab079f838144467a870de749e859/validation/rtx5090-20261017/evidence/final-diff-audit.json).

Validated on a hybrid GDN model, which the description leaves out of scope: it fixes this case.

**Setup.** One RTX PRO 6000 (SM120), TP=1. Image `lmsysorg/sglang:nightly-dev-cu13-20261101-cda284e4` with the PR head `6a7695ddc4` merged on top (no conflicts), bind-mounted over the installed package. Model [`ukisai/Swift-1.5-Qwen3.8-27b-NVFP4`](https://huggingface.co/ukisai/Swift-1.5-Qwen3.8-27b-NVFP4) @ `25482027`, a ModelOpt mixed checkpoint of a Qwen3.8-27B fine-tune: the GDN `in_proj_qkv` / `in_proj_z` / `out_proj` and the full-attention `q/k/v/o_proj` are static per-tensor FP8, the MLPs are NVFP4. Flags: `--enable-deterministic-inference --attention-backend triton --kv-cache-dtype auto --mamba-ssm-dtype bfloat16 --mamba-radix-cache-strategy extra_buffer_lazy --chunked-prefill-size 2048 --page-size 64 --enable-hierarchical-cache --hicache-size 64 --hicache-write-policy write_through --schedule-policy lpm --enable-session-radix-cache --mem-fraction-static 0.41 --max-running-requests 4`.

**Result**, `python3 -m sglang.test.test_deterministic --test-mode radix_cache`, cached vs uncached prefill:

| | cached | uncached | |
|---|---|---|---|
| nightly `cda284e4` | -5.0687 | -4.8716 | FAIL |
| + this PR, prefill CUDA graph on | -3.7109196186 | -3.7109196186 | PASS |
| + this PR, eager prefill | -3.7109196186 | -3.7109196186 | PASS |

A prefill-only probe (cold, prefix hit with a 37-token suffix, cold again; 101 tokens) gives -6.1011090279 all three times with the PR.

**Where the difference came from on this model** (diagnosed independently before finding this PR, by dumping per-layer tensors for the hit tokens, cold vs hit):
- The first tensor that differs is layer 0's GDN `out_proj` output (1.2e-4, from bit-equal inputs). It accumulates in the residual stream and reaches layer 3's norm input as 1.3e-3. NVFP4 MLP outputs stay bit-equal.
- These FP8 projections go through `ModelOptFp8LinearMethod.apply` → `apply_fp8_linear_bmm_flashinfer` → flashinfer `bmm_fp8` (`use_flashinfer_bmm=True`); `try_sm120_fp8_linear` returns None for these shapes.
- Standalone, on the real layer-0 `out_proj` weight (K=6144, N=5120), rows computed in a call of M rows vs the same rows inside a 101-row call: `bmm_fp8` differs by 0.0039 at M = 8, 16, 37, 64; `torch._scaled_mm` and `sgl_kernel.fp8_scaled_mm` are exact at M = 1, 8, 16, 37, 64, 100.
- With the PR, all 128 FP8 linear calls per forward (M=101 cold and M=37 hit) take the new `use_sm120_fp8 and deterministic` branch into `apply_fp8_linear_deterministic`, which sits before the `bmm_fp8` branch, so `bmm_fp8` is never reached.

Not measured: throughput of the deterministic Triton path on this model.
