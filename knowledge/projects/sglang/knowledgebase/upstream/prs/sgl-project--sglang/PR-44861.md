# [Fix] [NVIDIA] modelopt: Keep SM12x FP8 batch-invariant in deterministic mode

[Upstream PR](https://github.com/sgl-project/sglang/pull/44861) · state: open · merged: False

## Original PR description

## Motivation

On SM12x, ModelOpt static-FP8 linears can change reduction schedules between cold prefill and a shorter prefix-cache-hit batch despite deterministic inference being enabled. The same input sequence then receives different scores.

Related to #41351's ModelOpt path. Credit to `furedericca-lab` for the [diagnosis and initial fallback](https://github.com/sgl-project/sglang/issues/41351#issuecomment-5847506820), and `twu3202` for [identifying the small-M gap](https://github.com/sgl-project/sglang/issues/41351#issuecomment-5853051517). This does not claim to resolve every hybrid/GDN issue in that thread.

## Modifications

- In **SM12x deterministic mode only**, reuse Triton scaled MM with fixed N=64/K=128 reduction tiles. M-only tiles 16/32/128 reduce decode waste and improve long-prefill occupancy while retaining exact per-row results. Normal-mode and forced-Marlin dispatch remain unchanged.
- Zero masked A/B loads for partial K tiles.
- Extend the existing SM120 test file with 12 cold/cache row comparisons and two CUDA Graph replay cases covering strided 3D input, bias, BF16/FP16 output and a K=80 tail.

## Accuracy Tests

RTX 5090, 400W, TP=1, `nvidia/Qwen3-8B-FP8` at `2cebc4c89e25abc17668c81b01dceaf3d8b914d5`, BF16 output, Triton attention, deterministic mode.

| Check | Baseline | Candidate |
|---|---|---|
| 12 cold/cache native-method cases | 4 failed / 8 passed | 12 passed |
| Complete current SM120 test file | — | **137 passed**, including two new Graph cases |
| Prefixes 128/1024/4096, batches 1/4/2, two repetitions, eager and Graph | selected-score deltas up to 2.500 | **0 in all 12 comparisons**; warm repeats also 0 |
| Disjoint GSM8K rows 32–159, zero-shot greedy, thinking disabled, cap 512 | 119/128 | 117/128 |
| No parseable numeric final answer in that sample | 1 | 2 |

The row-tile optimization is bit-exact against the initial fixed-M=32 candidate in 120 isolated comparisons and produces **identical complete text on all 128 real-model evaluation questions**. The evaluation contains different reasoning errors and answer-format/truncation effects between baseline and candidate; it establishes neither a general accuracy gain nor statistical equivalence.

## Speed Tests and Profiling

Four workloads below use 32 forced output tokens per request, one warmup and five measured repetitions. Values are end-to-end medians; cooling to ≤55°C occurs outside each measurement. Graph runs capture decode batches 1/2/4 and prefill token sizes 4/128/256/1024/2048/4096/8192; unsupported partial prefills may fall back to eager.

| Prefix tokens / batch | Eager baseline → candidate | Graph baseline → candidate |
|---|---:|---:|
| 128 / 1 | 1.626s → 1.778s | 0.284s → 0.336s |
| 128 / 4 | 2.423s → 1.776s | 0.404s → 0.426s |
| 2048 / 1 | 1.666s → 1.784s | 0.500s → 0.597s |
| 2048 / 4 | 2.791s → 2.284s | 0.857s → 0.993s |

Graph wall time remains about **5–20% higher** on this measured matrix. This is an opt-in determinism fix with a measured cost, not a general speedup claim. Full samples and ranges are in the [benchmark records](https://github.com/yibol9768-alt/sglang/blob/fd948aa99130c601e1f35b50b260edf15d79c11e/validation/rtx5090-20261017/round2/README.md).

Duplicate check: inspected #34429 (small-M dispatch), #42865 (block/MXFP8), #38921 (SM89 prequantized inputs) and #44076 (GDN chunk alignment); these do not implement this static per-tensor deterministic path. [Original pinned diff audit](https://github.com/yibol9768-alt/sglang/blob/ca72d5212b33ab079f838144467a870de749e859/validation/rtx5090-20261017/evidence/final-diff-audit.json).
