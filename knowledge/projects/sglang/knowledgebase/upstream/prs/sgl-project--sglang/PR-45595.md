# [Fix] docker: Bump sgl-nvidia-mega to 3333e4c so the megakernel runs on main

[Upstream PR](https://github.com/sgl-project/sglang/pull/45595) · state: closed · merged: False

## Original PR description

## Motivation

The CUDA images pin `sgl-nvidia-mega` at `d47deb3`, and that commit no longer runs on main. It imports SGLang modules that main has since moved or changed:

- `kernels/ops/attention/dsv4/unified_kv_kernels/env_gate.py`, `kernels/ops/layernorm/mxfp8_epilogue.py`, and `hc_combine` in `kernels/ops/layernorm/mhc.py`, all moved by #45112.
- `TopKConfig.num_fused_shared_experts`, split by #44912 / #44913.

With the pinned plugin, `--enable-nvidia-megakernel` fails to build the megakernel on main with `ModuleNotFoundError: No module named 'sglang.kernels.ops.attention.dsv4.unified_kv_kernels.env_gate'`.

sgl-nvidia-mega `main` already follows these changes: sgl-project/sgl-nvidia-mega#15, sgl-project/sgl-nvidia-mega#16 and sgl-project/sgl-nvidia-mega#18. Its operators resolve at their current locations, falling back to the old ones.

## Modifications

Bump `SGL_NVIDIA_MEGA_COMMIT` from `d47deb3` to `3333e4c` (sgl-nvidia-mega `main`) in `docker/Dockerfile` and `docker/Dockerfile.cu134`.

## Accuracy Tests

Tested on 4x GB300 with `lmsysorg/sglang:dev-cu13`, SGLang main `a175e39b84`, and sgl-nvidia-mega `3333e4c` on `PYTHONPATH`. DeepSeek-V4.1-Flash was served with the plugin README's command: TP4, DSpark block 5, `--enable-nvidia-megakernel` and the three required env vars.

- The megakernel builds and runs:
  - `NVIDIA megakernel: active` appears for the target and the DSpark draft spec on all 4 ranks (8 lines).
  - `draft proposal engaged` appears 108 times during graph capture.
  - The server log has no errors.
- GSM8K (sgl-eval 0.1.3, 200 examples, temperature 1.0, top_p 0.95, no thinking, seed 0): 0.975, with error rate 0 and truncated rate 0.
- bs=1 serving (random-ids 1024/512, 8 prompts): 491.8 tok/s, accept length 3.88.
- The plugin's own `test/unit` on this SGLang: 148 passed.

With `d47deb3`, the same server fails at the megakernel build with the `ModuleNotFoundError` above.
