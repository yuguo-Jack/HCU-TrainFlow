## Headline

End-to-end AgentX numbers on GB300 will be added here.

**When to expect a gain.** The gain appears when idle sessions outnumber the windows the SWA pool can keep:
long contexts, multi-minute think gaps, and pools sized close to the running requests (default 4 x
`--max-running-requests`). Models without SWA (GLM-5.x, Qwen3.5, ...) are not affected.

## Motivation

**Background: what makes a cached prefix reusable for an SWA model.** DeepSeek-V4/V4.1 mixes full-attention layers with
sliding-window attention (SWA) layers. The radix cache keeps two kinds of KV:
- Full KV, which lives long in a large pool.
- SWA KV, in a much smaller pool.

A cached prefix can be reused only if the SWA KV for the last window before the match point (128 tokens for DSv4) is
still on the GPU. If that window is evicted, the full KV under it is still cached, but no request can use it.

**What agentic follow-up turns need.** In multi-turn agent traffic (AgentX), a follow-up prompt is the previous prompt
plus new messages: the assistant reply as the client renders it, plus the tool output. The next turn therefore reuses
the cache exactly up to the **end of the previous prompt**.
- In AgentX trace replays, most follow-up turns land exactly there, and none land inside the previous output.
- The same holds in real serving whenever the client re-renders the history (dropped thinking, reformatted tool
  calls).
- So the one SWA window that matters for an idle session is the one at its previous prompt end.

**What goes wrong on main.** Main evicts SWA windows in one strict LRU.
- While a session waits (AgentX think time is up to 300 s), its prompt-end window becomes the oldest and is evicted.
- The next turn then recomputes its whole context, often 175K to 465K tokens.

**What #42840 fixes, and what it does not.** #42840 adds a two-pass eviction walk that spares windows within one
window of a leaf or a fork, which fixes many long-idle misses. But it spares the wrong window for this traffic:
- It spares each finished request's **output-end leaf**, which no follow-up turn ever matches.
- It does not spare the **prompt-end window**: between turns that window has one child (the generated output) and
  sits more than one window above its end.
- So under agentic load, #42840's first pass evicts the *recent* prompt-end windows before the *old* spared leaves.
- As a result, with #42840 more follow-up turns miss part of their reusable prefix than on main, and reuse after a
  short (< 60 s) gap drops.

## Modifications

The fix: protect the window the next turn will match, i.e. the one at the prompt end.

- New env var **`SGLANG_OPT_SWA_PROTECT_PROMPT_TAIL`** (default off).
  - With it off, nothing is marked and eviction is exactly #42840's.
  - Enable it with `SGLANG_OPT_SWA_PROTECT_PROMPT_TAIL=1` in the server environment, on every node of a multi-node
    deployment.
- **Mark.** When a running (unfinished) request's checkpoint inserts a key that ends at the prompt's last full page,
  the SWA window there gets a `prompt_tail` mark.
  - That checkpoint is normally the post-prefill one. When the last prefill chunk is shorter than a page, it is the
    chunk before it.
  - If the window already exists in the tree (for example, another request built it), the existing node is marked.
  - The equality test also means a retracted request's re-prefill marks at most that one window.
- **Evict last.** #42840's first eviction pass skips marked windows the same way it skips branch tails. Marked
  windows are reclaimed in LRU order only when nothing else is left, so protection never blocks an allocation.
- **Mark lifecycle.**
  - A node split keeps the mark on both halves, so the protected span does not change.
  - Tombstoning a window's SWA clears its mark; evicting a leaf deletes the node.
  - Windows rebuilt by host load-back or unevict start unmarked.
- **Both tree cores.**
  - Python: `unified_radix_cache.py` (the mark condition in `checkpoint_into_tree`) and
    `unified_cache/components/swa.py`.
  - Rust: `rust/sglang-radix-tree` (`Node.swa_prompt_tail`, `InsertParams.swa_prompt_tail`, the
    `InsertParamsBinding` kwarg) and the adapter.
- **Docs.** A new row in the environment-variable reference, and one sentence in the unified-cache components README.
- **Tests.**
  - `test_unified_radix_cache_core.py`: 4 new tests, 30 config cases. They run on the Python core and, through
    `test_unified_radix_cache_rust`, on the Rust core.
    - prompt-end window evicted last, flag on vs off;
    - last chunk under one page;
    - retraction re-prefill marks only the prompt end;
    - prompt ending on another request's live window.
  - `rust/sglang-radix-tree/src/tests/components/swa.rs`: 4 new tests: eviction order, second-pass reclaim and mark
    clear, split, and marking an existing node.
  - Each new test fails against a targeted mutation of the fix.

```python
#!/usr/bin/env python3
"""Metrics in the #45430 tables, from AgentX (aiperf) output dirs: agentx_swa_metrics.py <artifact_dir>... [--gpus 4]

Each <artifact_dir> is the harness's --output-artifact-dir (profile_export_aiperf.json + profile_export.jsonl).
Only the measured phase (benchmark_phase == "profiling") is counted.
- tok/s/GPU: total (input incl. cached + output) token throughput / GPUs (SA tput_per_gpu).
- 1000/p90 ITL: 1000 / p90 inter-token latency in ms (SA p90 interactivity).
- E2E-norm.: 1000 / p90 over requests of (request latency ms / output tokens) (InferenceX north star).
- Follow-up misses: turns of the same conversation (conversation_id, source_kind, root_correlation_id) whose prompt is at
  least as long as the previous turn's, but whose cached tokens fall short of the previous prompt rounded down to a
  256-token page.
- Reuse tokens lost: the shortfall summed over those turns (previous prompt, page-rounded, minus cached tokens).
- TTFT p90 / p99: nearest-rank percentiles over measured requests.
- Reuse after < 60 s idle / long-idle reuse (>= 280 s idle): a turn reuses if uncached <= new tokens since the previous
  prompt + 1024.
- Recompute vs ideal: (100 - realized prompt-cache %) / (100 - aiperf's theoretical prefix-hit %).
"""
import argparse
import collections
import json
import pathlib

PAGE = 256


def pct(xs, p):
    xs = sorted(xs)
    return xs[min(len(xs) - 1, int(p / 100 * len(xs)))] if xs else float("nan")


def turns(path):
    rows = []
    for line in open(path):
        d = json.loads(line)
        m, x = d["metadata"], d["metrics"]
        v = lambda k: (x.get(k) or {}).get("value")
        rows.append(dict(key=(m["conversation_id"], m.get("source_kind"), m.get("root_correlation_id")),
                         phase=m.get("benchmark_phase"), start=m["request_start_ns"], end=m.get("request_end_ns") or 0,
                         isl=int(v("input_sequence_length") or 0), osl=int(v("output_sequence_length") or 0),
                         cached=int(v("usage_prompt_cache_read_tokens") or 0), ttft=v("time_to_first_token"),
                         lat=v("request_latency")))
    rows.sort(key=lambda r: r["start"])
    prev = {}
    for r in rows:
        r["prev"] = prev.get(r["key"])
        prev[r["key"]] = r
    return [r for r in rows if r["phase"] == "profiling"]


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("dirs", nargs="+")
    ap.add_argument("--gpus", type=int, default=4)
    a = ap.parse_args()
    cols = ("tok/s/GPU", "1000/p90ITL", "E2E-norm", "TTFTp90_s", "TTFTp99_s", "misses", "lost_tok", "reuse<60s", "longidle",
            "xs")
    print(f"{'run':44s} " + " ".join(f"{c:>11s}" for c in cols))
    for d in a.dirs:
        d = pathlib.Path(d)
        agg = json.loads((d / "profile_export_aiperf.json").read_text())
        g = lambda k, s="avg": (agg.get(k) or {}).get(s)
        cache, theo = g("overall_usage_prompt_cache_read_pct"), g("theoretical_prefix_cache_hit")
        rows = turns(d / "profile_export.jsonl")
        done = [r for r in rows if r["ttft"] is not None and r["lat"] is not None and r["osl"]]
        e2e = pct([r["lat"] / r["osl"] for r in done], 90)
        ttft = [r["ttft"] for r in done]
        misses = lost = short = short_ok = long_n = long_ok = 0
        for r in rows:
            p = r["prev"]
            if p is None or r["isl"] < p["isl"]:
                continue
            shortfall = max(0, p["isl"] // PAGE * PAGE - r["cached"])
            misses, lost = misses + (shortfall > 0), lost + shortfall
            if not p["end"]:
                continue
            gap = (r["start"] - p["end"]) / 1e9
            ok = r["isl"] - r["cached"] <= r["isl"] - p["isl"] + 1024
            if gap < 60:
                short, short_ok = short + 1, short_ok + ok
            elif gap >= 280:
                long_n, long_ok = long_n + 1, long_ok + ok
        vals = (f"{(g('total_token_throughput') or 0) / a.gpus:,.0f}", f"{1000 / g('inter_token_latency', 'p90'):.1f}",
                f"{1000 / e2e:.1f}", f"{pct(ttft, 90) / 1e3:.2f}", f"{pct(ttft, 99) / 1e3:.1f}", str(misses),
                f"{lost:,}",
                f"{100 * short_ok / max(short, 1):.1f}%", f"{long_ok}/{long_n}", f"{(100 - cache) / (100 - theo):.2f}x")
        print(f"{str(d)[-44:]:44s} " + " ".join(f"{x:>11s}" for x in vals))


if __name__ == "__main__":
    main()
```

**Costs**
- *CPU.* Each SWA evict call's first pass walks past the spared nodes. Most of this cost comes from #42840's walk.
- *Memory.* No new memory. The mark changes only eviction order.
- *Protected windows.* Each idle session keeps about one more protected window (one 256-token page on DSv4).

**Limits**
- **The turn after a miss lags by one prompt.** This is already the case on main and with #42840.
  - After a miss, the match sets `swa_branching_seqlen`. When that branch point falls in the last prefill chunk, the
    post-prefill checkpoint stops at it. The new prompt end is then inserted only at finish, after decode has freed
    its SWA window, so there is nothing to mark.
  - The next turn reuses one prompt less than it could.
  - A fix is designed and checked on a scratch copy but not included here: re-checkpoint the remainder in the same
    call, about 8 lines. It changes behavior with the flag off too, so it will be a separate PR.
- **Page smaller than the window.** Only the node ending at the prompt's last full page is marked. When the page size
  is below the sliding window, part of the window can sit in an older, unmarked node. DSv4 (page 256 >= window 128) is
  not affected.
- **Opt-in for now.** It could become the default if reviewers agree it is strictly better.
