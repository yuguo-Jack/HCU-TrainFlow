# [Feat] metrics: Count KV bootstrap and transfer timeout observations

[Upstream PR](https://github.com/sgl-project/sglang/pull/42516) · state: open · merged: False

## Original PR description

## Motivation

The existing bootstrap and transfer failure counters do not distinguish deadline expiry from other failure causes. Repeated polling and warning-once logs also make log counts unsuitable for counting timeout observations.

This is reproducible without a model: give a sender or receiver a 10-second deadline, set its existing start time to 20 seconds before the current time, and call the shared timeout helper repeatedly. The request becomes Failed, but current main records no classified timeout observation. The initial regression suite on main `ab9d8f029c12cda8167f51d46664d643c8771a6e` failed eight count assertions across the two paths.

## Modifications

- Add `sglang:kv_transfer_timeouts_total{stage="bootstrap"|"transfer"}` with two zero-initialized stages.
- Observe expiry in the existing shared bootstrap and waiting-timeout helpers, once per sender/receiver object. Preserve the original deadline clocks, failure recording, terminal status, cache invalidation, and abort delivery.
- Create the counter only for metrics-enabled KV managers. Import Prometheus lazily after launcher initialization and reuse the counter across manager lifecycles within one process.
- Add CPU tests for repeated polling, deadline boundaries, deferred bootstrap timing, cancellation, terminal polling, disabled metrics, room reuse, and existing failure records. Add real Prometheus subprocess export and fresh-directory tests.
- Document that these are rank-local observer events, not unique failed requests or a failure-rate numerator.

This does not introduce new deadlines or count transport errors, session recovery, cancellation, or stalled transfers outside the existing shared timeout helpers. Existing phase failure metrics are preserved.

Related work: [#41140](https://github.com/sgl-project/sglang/pull/41140) is an open lifecycle consolidation that touches the same helpers but does not add classified timeout counters. [#34132](https://github.com/sgl-project/sglang/pull/34132) adds request outcomes and broad disaggregation abort reasons; it measures a different unit. [#34692](https://github.com/sgl-project/sglang/pull/34692) already added the missing NIXL bootstrap timeout. This patch instruments that existing behavior.

## Production deployment and results

The downstream instrumentation is deployed in our production disaggregated inference service. On 2026-10-04, read-only inspection confirmed it in all six engine containers. All 54 event series were initialized, and the oldest source sample was 16.5 seconds old.

The observed counters distinguished 5 bootstrap-timeout events from 23 abort events, with 0 transfer-timeout events. This separation is useful operationally: cancellations must not be counted as deadline expiry.

This PR extracts bootstrap and transfer timeout observations from that broader deployed implementation. It uses `sglang:kv_transfer_timeouts_total{stage}` instead of the downstream `sglang:kv_failure_events_total{event}`. Counts are rank-local observations, not unique failed requests. The production sample contains no transfer timeout; regression tests cover that path and the upstream collector adaptation.
