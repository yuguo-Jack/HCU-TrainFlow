# [Observability] Support custom OTLP service names

[Upstream PR](https://github.com/sgl-project/sglang/pull/35730) · state: closed · merged: False

## Original PR description

## Motivation

Fixes #35691.

SGLang hardcodes the OpenTelemetry `service.name` as `sglang`, so separate deployments appear as one service in tracing backends. This change lets deployments select a name with `--otlp-service-name`, falling back to `OTEL_SERVICE_NAME` and then `sglang`.

## Modifications

- Declare the optional CLI field in the current `Observability` namespace; retain the existing positional `ServerArgs` constructor order.
- Read the published observability setting in the HTTP server, Engine, Scheduler, DP Controller, and disaggregated Encoder tracing initialization paths.
- Resolve the service name once before constructing the OpenTelemetry resource and pass that same name to the async exporter.
- Document the option and its precedence in the server argument reference and tracing guide.
- Cover CLI parsing, namespace projection, environment fallback, and actual SDK span resources. The exporter test checks all four precedence/fallback cases with async tracing both enabled and disabled, without sending telemetry over the network.
