## Motivation

On gfx950 the aiter MXFP8 dense route runs the Triton group32 GEMM on the plain weight. aiter's FlyDSL MXFP8 GEMM
(ROCm/aiter#5896, already in the pinned aiter) is faster when the weight is kept (16, 16)-preshuffled.

## Modifications

- `SGLANG_ROCM_MXFP8_AITER_PRESHUFFLE` (default off): at load time shuffle the aiter-route dense weights in place
  (one copy, no extra memory) and call `gemm_a8w8_blockscale(..., isBpreshuffled=True)`.
- Preshuffled layers skip the in-tree FlyDSL MXFP8 prefill path (`SGLANG_OPT_HIP_FLYDSL_MXFP8`), which needs the plain
  weight; the aiter kernel serves prefill as well.
- DSpark draft: the fused wkv projection passes the preshuffle flag through.
- Test: the aiter-route test also runs with preshuffle on (M 1 to 2049), within one bf16 ulp of the bf16 route.

## Accuracy Tests

GSM8K (DeepSeek-V4.1-Flash, TP2): 0.898 -> 0.901 with this on (same tree otherwise).

## Speed Tests and Profiling

DeepSeek-V4.1-Flash TP2 on MI355X, flag off -> on: decode step bs 16 18.03 -> 17.17 ms (-4.8%), bs 64 36.51 -> 35.67 ms
(-2.3%); idle prefill 4k / 16k new tokens over a 32k cached prefix 0.123 -> 0.110 s / 0.303 -> 0.291 s.
AgentX c64: 169,008 -> 170,633 tok/s/GPU.
