# [Fix] dflash: Stage the draft sampler only for batches its buffers hold

[Upstream PR](https://github.com/sgl-project/sglang/pull/47644) · state: open · merged: False

## Original PR description

## Motivation

With a DFlash2 draft (candidate selector) or a LiLiCorr head, the draft sampler is folded into the draft CUDA graph. Its static buffers are sized to the largest captured decode bucket, but every decode step staged its sampling params into them. When a decode batch is larger than `--cuda-graph-max-bs-decode`, the scheduler crashes:

```text
File ".../speculative/dflash_worker_v2.py", line 293, in stage_sampling_params
    self.greedy_mask[:bs].copy_(
RuntimeError: The size of tensor a (4) must match the size of tensor b (8) at non-singleton dimension 0
```

That step's draft cannot replay (no captured bucket covers the batch). It runs the eager head, which reads none of the sampler's buffers, so the staging is not needed.

Our default Beam launch did not hit this: it ran 12 requests per rank and captured graphs up to 12. It happens when `--max-running-requests` exceeds the graph max or `--cuda-graph-max-bs-decode` is lowered. Under attention DP with #46837, it also happens when one rank's batch exceeds the graph max.

## Modifications

- `DFlashWorkerV2._stage_draft_sampler` stages the folded sampler only when the batch fits its buffers (`bs <= max_bs`).
- `_SelectorDraftSampler` records its `max_bs`; `LiLiCorrDraftSampler` already does.

## Accuracy Tests

Beam-1.0-501B-A23B-NVFP4 + Beam-1.0-501B-A23B-DFlash2 (block 8), 4x GB300, TP4, `trtllm_mha`, page 64, unified memory, `--cuda-graph-max-bs-decode 4`, 8 concurrent ShareGPT requests (512 output tokens, temperature 0):

| | Result |
|---|---|
| main | Scheduler crash (the traceback above) |
| this PR | 48/48 requests; accept length 3.45; no errors |

Under attention DP (TP4 / attention DP4 / EP4 FlashInfer MegaMoE) with #46837 applied, at the same graph max and about 4.5 requests per rank: crash without this change, 108/108 requests with it.

The GPU runs used main at `1f834c19` plus the MegaMoE autotune fix from #46213, which this image needs at startup. The change is the same as on this branch.

- `test/registered/unit/spec/test_dflash*.py`: 62 passed, the same as on main.

## Speed Tests and Profiling

Not affected: this only skips host-side staging for steps whose draft cannot replay.
