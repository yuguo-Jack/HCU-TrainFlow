# [Core] Keep request priority within the signed 64-bit range in radix caches

[Upstream PR](https://github.com/sgl-project/sglang/pull/43920) · state: closed · merged: True

## Original PR description

## Motivation

A `/generate` request with `"priority": 9223372036854775807` (INT64_MAX) terminates the scheduler once the request finishes. When a finished request's KV is cached, the radix cache re-inserts the prompt one priority above the request so that eviction drops the output KV before the prompt. With the Rust tree core (the default), `InsertParams.priority` is an `i64`, so the re-insert at `priority + 1` raises `OverflowError: Python int too large to convert to C long` inside the scheduler loop. The legacy Python cache does not crash but stores a value outside the signed 64-bit range.

Nothing validates the request priority on the way in, so a client (or a misconfigured default priority) can bring the engine down with one request.

## Modifications

- `RadixCache` and `UnifiedRadixCache`: the prompt priority boost is `min(priority + 1, INT64_MAX)`. The request's own priority is unchanged; only the boosted prompt copy saturates.
- `TokenizerManager._set_default_priority`: after applying the configured default, a priority outside `[-2**63, 2**63 - 1]` raises `ValueError` before `_init_req_state`, so the request is rejected at the API layer instead of failing inside the scheduler. The check applies whether or not priority scheduling is enabled, since the priority still reaches the cache either way.

Tests (each fails on the pre-fix code and passes with it):

- `test_rust_tree_core_integration.py`: a real CPU `UnifiedRadixCache` on the Rust core releases a finished request at `INT64_MAX - 1` and `INT64_MAX`; the recorded insert priorities are `[priority, INT64_MAX]` (no overflow, no over-clamp) and the full sequence is still matchable.
- `test_radix_cache_unit.py`: the existing prompt/output split fixture is shared with a new case asserting both nodes hold `INT64_MAX` after a request at `INT64_MAX`.
- `test_tokenizer_manager_rid_cleanup.py`: the INT64 boundary values pass through `_set_default_priority` unchanged; `INT64_MIN - 1` and `INT64_MAX + 1` from the body or from the configured default raise `ValueError` from `generate_request` before `_init_req_state` is called, with priority scheduling on and off.
