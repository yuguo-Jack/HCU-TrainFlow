## Motivation

Gemma4 text serving currently loads vision/audio encoders that it never uses. Enable `--language-model-only` while preserving the processor's tokenizer configuration, including BOS handling.

## Modifications

- Omit media towers and skip their checkpoint weights for text-only launches.
- Reuse Gemma4's processor tokenizer so identical text retains identical token IDs; preserve the existing tokenizer loader for other architectures.
- Add text-only XPU coverage for generation, token-ID parity, and media rejection, plus an E2B/BMG cookbook recipe.

This is encoder omission, not CPU offload. The existing CPU-offload work in #44139 is excluded from this branch.

## Accuracy Tests

On an Intel Arc Pro B70 with the original `google/gemma-4-E2B-it` weights: full-model and text-only generation tests, processor-tokenizer parity, and media rejection pass. Prior 200-example GSM8K smoke runs scored 78.5% for both modes; this is not a statistical quality-equivalence claim.

## Speed Tests and Profiling

At TP1 and `--mem-fraction-static 0.70`, reported weight allocation decreases from 9.94 to 9.04 GB. Full-attention KV capacity increases from 353,920 to 382,528 tokens (8.1%). No weight quantization is involved.
