# Revert "[AMD][ROCm] Keep cos_sin_cache fp32 on HIP for fused QSA indexer kernel (#41282)"

[Upstream PR](https://github.com/sgl-project/sglang/pull/42541) · state: closed · merged: True

## Original PR description

## Motivation

#41282 keeps `RotaryEmbedding.cos_sin_cache` fp32 on HIP. On HIP, every rope without a fused KV-cache write goes through the `sgl_kernel.rotary_embedding` fallback, which reads the cache as the query dtype, so CUDA graph capture now fails:

```
File ".../sglang/srt/layers/rotary_embedding/base.py", line 455, in forward_cuda
File ".../sgl_kernel/elementwise.py", line 414, in rotary_embedding
RuntimeError: expected scalar type BFloat16 but found Float
Exception: Capture cuda graph failed: expected scalar type BFloat16 but found Float
```

This fails `stage-a-test-1-gpu-small-amd` (`test_basic_sanity.py` / `test_basic_sanity_eagle3.py`) on every AMD PR, so all AMD stage B/C lanes are skipped. Examples: [run 37180583674](https://github.com/sgl-project/sglang/actions/runs/37180583674/job/111372273784), [run 37187809051](https://github.com/sgl-project/sglang/actions/runs/37187809051/job/111393476849). #41282's own PR Test (AMD) runs stopped at the label gate, so stage-a never ran on it.

Reverting unblocks AMD CI now. The forward fix that keeps the fp32 cache for the QSA indexer is #42483; it can re-land on top of this.

## Modifications

`git revert f6fcda8827`: `base.py` and `mrope.py` are byte-identical to before #41282. Nothing has touched either file since.

Effect on the QSA indexer: `_use_fused_prep` already requires `cos_sin_cache.dtype == torch.float32`, so on HIP it goes back to the unfused prep path it used before #41282. No functional break, only the fused prep on HIP is lost until #42483 lands.
