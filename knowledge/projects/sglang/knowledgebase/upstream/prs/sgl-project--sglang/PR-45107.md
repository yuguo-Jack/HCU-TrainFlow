# [Perf] deepseek-v4.1: Run decoder replay tail graphs in prefill-graph steps and under DP attention

[Upstream PR](https://github.com/sgl-project/sglang/pull/45107) · state: open · merged: False

## Original PR description

- Follow-up to #45059, which runs the decoder-replay tail layers from row-bucket CUDA graphs on eager prefill steps with attention DP size 1. This PR extends those graphs to prefill-graph steps and to DP attention.
- Prefill-graph steps: a captured shape of at least `SGLANG_DSV4_DECODER_TAIL_GRAPH_MIN_PREFILL_TOKENS` tokens (default 2048) no longer captures the tail over its padded block.
  - At the tail switch, one eager break of the prefill graph switches onto exact-row tail metadata of the live batch (`_enter_eager_tail_in_prefill_graph`, `_unpadded_batch` in `deepseek_v4_replay_tail.py`).
  - It replays the tail graphs, or runs the tail layers eagerly past the largest bucket, and writes the tail rows into bridge buffers that the later captured segments read.
  - Smaller shapes keep the tail in their own capture, where the break would cost more than it saves.
- DP attention: every rank captures and replays the bucket of the largest rank's tail, and an idle rank takes part with no rows of its own.
  - TP MoE: the tail runs in a rank-uniform DP layout. Row counts come from the pre-forward exchange (`ForwardBatch.global_late_layer_num_tokens_cpu`). Each rank's padded tail IDs are gathered when the MoE routes on IDs.
  - MegaMoE: each rank sees only its local bucket, and the ranks agree on it through a host gather of their counts. This path needs the prefill graph disabled, since MegaMoE ranks may pick a prefill graph or eager independently.
- `RowBucketGraphRunner` gains `batch_scope`, `bucket_from` and `out_rows`, so the DeepSeek-V4.1 side can lay out the DP batch and replay a shared bucket.
- Behavior change, on by default whenever decoder replay is on:
  - prefill-graph shapes of 2048 tokens or more run the tail outside the captured block;
  - DP attention with a TP MoE, or MegaMoE on eager prefill, runs the tail from graphs.
  - Still off: encoder replay inside a prefill-graph step, context parallel, unified-KV Triton, and other all-to-all backends under DP. `SGLANG_DSV4_DECODER_TAIL_GRAPH_MAX_ROWS=0` turns the tail graphs off.
- Verification: DeepSeek-V4.1-Flash on GB300 with DSpark. Baseline is main before #45059 (`58ad0748a6`). Each pair ran on one node; GSM8K is sgl-eval, 1319 examples, no thinking.
  - TP4, breakable prefill graph (max 8K tokens): cold 8K TTFT 146.4 -> 100.4 ms; 64K cached prefix + 2048 TTFT 178.0 -> 121.4 ms; saturated 8K-input prefill at concurrency 64, 59.9K -> 82.1K tok/s (+37%); GSM8K 96.97% vs 96.74%. Shapes under 2048 tokens are unchanged (cold 128: 33.8 vs 32.2 ms).
  - DP4 attention + TP MoE, eager: cold 8K TTFT 368.3 -> 233.7 ms; saturated prefill 93.7K -> 140.9K tok/s (+50%); GSM8K 96.89% vs 96.97%.
  - DP4 attention + TP MoE, breakable prefill graph: cold 8K TTFT 335.7 -> 287.8 ms; 64K cached + 2048 TTFT 201.8 -> 139.8 ms; saturated prefill 100.2K -> 112.6K tok/s (+12%); GSM8K 96.82% vs 96.66%.
  - DP2 attention + MegaMoE (EP2), eager, encoder replay on: cold 8K TTFT 208.4 -> 166.2 ms; 64K cached + 1K TTFT 153.8 -> 116.0 ms; 48 sessions with a 32K cached prefix each adding 2048 / 8192 new tokens, 81.2K / 108.9K -> 97.1K / 133.4K fresh tok/s; GSM8K 96.29% vs 96.89%.
  - The same MegaMoE setup with the breakable prefill graph captures no tail graphs and serves normally (GSM8K 96.89%).
