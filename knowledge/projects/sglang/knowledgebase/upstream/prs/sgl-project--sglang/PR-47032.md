# [Fix] disaggregation: Preserve bootstrap receiver and scope disconnect cleanup

[Upstream PR](https://github.com/sgl-project/sglang/pull/47032) · state: open · merged: False

## Original PR description

## Motivation

An invalid Mooncake bootstrap metadata frame can raise an uncaught parsing exception in Prefill's sole receiver thread. Later valid metadata is then never consumed, leaving requests waiting for bootstrap timeout while other engine components remain alive.

A separate cleanup race can compound failures: a closed streaming response waits two seconds before cancelling by RID. If a new request reuses that RID, the old response can cancel the new owner.

## Reproduction

These regressions use CPU-only stand-ins for receive queues and request state. They invoke the actual implementation methods, without starting a model, accessing a serving endpoint, or sending network application frames.

### Bootstrap receiver

`test_receiver_continues_after_bad_message` starts the real `MooncakeKVManager.start_prefill_thread` using a queue-backed receive function. It delivers `[b"\xd7"]`, followed by valid transfer metadata.

Before the fix:

```text
frames[0].decode("ascii")
  -> UnicodeDecodeError
  -> receiver thread exits
  -> the valid follow-up is never handled
  -> the request cannot leave Bootstrapping
```

After the fix, the malformed message is rejected and the same receiver processes the valid follow-up, advancing it to `WaitingForInput`.

### RID reuse during delayed cleanup

The ownership regressions replace `rid_to_state[rid]` with a new request object either before the old cleanup task starts or while its delay runs. The old implementation calls `abort_request(rid)` against the new owner. The fixed implementation compares the state's request object with the object owned by the closed response.

Positive tests retain cancellation of the original request and cancellation of owned items in a batch.

## Modifications

- Extract Prefill metadata handling and isolate expected wire-format errors per message. Log only the exception type and frame count.
- Parse complete transfer metadata before publishing room state. Reject invalid room/destination counts and staging control when staging is unavailable. Keep legacy optional fields, registration, watermark, staging and abort handling.
- Keep socket failures and errors applying parsed transfer/registration state outside the format-error guard.
- Track the bootstrap receiver and check it at the scheduler input boundary. Unexpected exit reaches the existing scheduler fatal-error path; intentional role teardown is exempt. This does not automatically restart a receiver with potentially inconsistent state.
- Apply the existing `SGLANG_ZMQ_ALLOWED_PEERS` mechanism to the common KV metadata socket. An unset allowlist preserves existing behavior; an explicitly configured list must include all legitimate peers. No bind-address or firewall defaults are changed.
- Limit delayed disconnect cleanup to the request object owned by that response.
