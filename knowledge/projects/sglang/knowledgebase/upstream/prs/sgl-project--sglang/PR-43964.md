# [Refactor] multimodal: [MM refactor 6/6] Enable token-space processing at startup with parity tests

[Upstream PR](https://github.com/sgl-project/sglang/pull/43964) · state: closed · merged: False

## Original PR description

## Motivation

Turn `--enable-token-space-processor` on and test token-space Qwen against HF and the legacy path.

## Modifications

- `get_mm_processor_cls`: with the option on, an architecture with a registered token-space processor that supports the config gets it; everything else stays legacy. The tokenizer manager and the scheduler both use this function.
- The tokenizer manager rejects `mm_token_expansion_start_len` on a legacy processor. The token-space processor prefers tokenized input, so it receives the request's input_ids.

## Tests

- `test_mm_process_config.py`, `test_processor_async_call_sites.py`: routing, the partial-expansion check, request media forwarding.
- `test_qwen_tokenized_media.py`: byte-for-byte match with the HF processors (image, video, audio), startup selection and fallbacks.
- `test_qwen_token_space_token_ids.py` (e2e): request token IDs survive a token-space server.
- `test_qwen_processor_bitwise.py` (CUDA): legacy and token-space outputs are bitwise identical on multi-turn samples for Qwen3.5, Qwen2.5-VL, Qwen3-VL and Qwen3-Omni.
