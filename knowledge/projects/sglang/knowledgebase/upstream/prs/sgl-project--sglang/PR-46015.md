# [CI] [AMD] stage-b: Run the scheduled mi35x 1-GPU small suite on the 8-GPU pool

[Upstream PR](https://github.com/sgl-project/sglang/pull/46015) · state: open · merged: False

## Original PR description

## What
Scheduled runs of `PR Test (AMD)` now run `stage-b-test-1-gpu-small-amd-mi35x` on `linux-mi35x-gpu-8` instead of `linux-mi35x-gpu-1`. PR runs are unchanged.

## Why
The `linux-mi35x-gpu-1` pool has 4 runners. Each PR run needs 2 partitions of about 24 minutes, so the pool can handle about 5 PR runs an hour, and recently about 10 runs an hour have needed it. The queue stays hours long, and scheduled main runs wait behind it: in every scheduled run over the last 3 days, these two jobs started 4-7 hours after the run began, long after every other stage had finished. In https://github.com/sgl-project/sglang/actions/runs/39879522486, stage-c was done by 02:22 UTC while both mi35x partitions were still queued at 05:45.

`linux-mi35x-gpu-8` is the pool stage-c's mi35x jobs already use. Its stage-c jobs haven't been queuing, and scheduled runs add only 2-4 jobs per run (rocm10 twice a day, rocm724/rocm720 once).

## Notes for the reviewer
The tests in this suite are single-GPU and run on device 0, so an 8-GPU runner only changes which runner picks them up. The PR backlog itself needs more `linux-mi35x-gpu-1` capacity; moving PR runs to the 8-GPU pool would add more load than it has spare.

## Test plan
- [x] Ran the suite on `linux-mi35x-gpu-8` with a `workflow_dispatch` from a temporary branch that also sends dispatch runs to gpu-8: https://github.com/sgl-project/sglang/actions/runs/39925806744. Both partitions started within a few minutes on 8-GPU runners. [Part 0](https://github.com/sgl-project/sglang/actions/runs/39925806744/job/120321885282) passed. [Part 1](https://github.com/sgl-project/sglang/actions/runs/39925806744/job/120321885300) passed every file except `test_v41_kv_store.py`, which fails to compile on ROCm (`__shfl_xor_sync` with a 32-bit mask, from #45934 on main). That is a compile error, so it does not depend on the runner.
