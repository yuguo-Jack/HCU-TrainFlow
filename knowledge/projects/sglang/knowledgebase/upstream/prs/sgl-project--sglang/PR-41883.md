# [MLX] Release finished request state between prefill-only batches

[Upstream PR](https://github.com/sgl-project/sglang/pull/41883) · state: open · merged: False

## Original PR description

## Motivation

Repeated `/v1/decisions` requests retain per-request state in the native MLX runner. These requests use `max_new_tokens=0` and finish during prefill. The scheduler releases their KV resources, but does not notify the worker. The existing decode-only cleanup never runs if subsequent batches are also prefill-only.

A similar cleanup was proposed in [#32446](https://github.com/sgl-project/sglang/pull/32446). It was briefly cherry-picked onto the [#30578 branch](https://github.com/sgl-project/sglang/pull/30578#issuecomment-5099972233), then reverted as scope creep and hard to review ([revert note](https://github.com/sgl-project/sglang/pull/30578#issuecomment-5233089096)); it was not merged.

## Modifications

Call the existing optional worker release hook when a request finishes during prefill. The MLX worker records the finished request IDs and removes their state before the next fresh non-idle launch, including EXTEND.

Removal is deferred because an already-launched overlap decode may still need the state during finalization. The fresh-launch boundary lets that work finish before cleanup and removes old state before routing new requests, including requests that reuse the same ID.

This does not address idle-tail retention or abort/retraction cleanup. The tracking stays in the native MLX worker and can be removed with that backend as part of #32321 / #36164.

## Accuracy Tests

The targeted routing and result-processor suites pass: 36 tests and 4 subtests.

Coverage includes zero-token completion, immediate request-ID reuse, pending chained-decode finalization before cleanup, live and chunked requests, and workers without the optional hook.

The overlap test runs the real event loop with mocked model execution and KV allocation/release. It checks lifecycle ordering, not physical pool-reuse or Metal correctness. No model-quality benchmark was run.

<summary>Environment details and measurement limits</summary>

- **Machine:** Mac16,8, 48 GiB unified memory, macOS 26.5.2. Python 3.11.12, Torch 2.13.0, Transformers 5.12.1, MLX 0.32.3.
- **Model:** `Qwen/Qwen3-0.6B-MLX-4bit`, snapshot `173234aa840d113125e9f2271100ddbaf16c9620` for both runs.
- **Flags:** `SGLANG_USE_MLX=1`, `SGLANG_MLX_CACHE_LIMIT_GB=2`, `--mlx-enable-sampling`, `--context-length 512`, `--max-running-requests 1`, `--disable-radix-cache`; overlap enabled.
- **Workload:** three client warmups per run, followed by sequential one-question binary-choice requests with 216 prompt tokens each. The first 20 measured inputs matched; the fixed run continued through request 40.
- **Measurement:** identical worker hooks recorded `_req_caches` and `mx.get_active_memory()` after prefill; HTTP access logs confirmed responses. System-available memory is plotted where retained. Base request 20 returned HTTP 200 and its worker counters are recorded, but its latency and system-available-memory sample were not retained.
- **Limits:** automatic token pools differed (149,630 base; 168,005 fix). This is not a capacity or speed comparison. The baseline was stopped after request 20; the operator reported the configured safety guard fired, but its console output was not retained. The run was not continued to OOM. The result covers one model, concurrency one, and radix caching disabled.
