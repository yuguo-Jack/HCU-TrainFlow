# [Perf] [AMD] GLM5: Fuse KPool Hadamard and FP8 quant on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/44661) · state: open · merged: False

## Original PR description

## Motivation

GLM-5.3-Flash uses `IndexerKPool`, so the non-pooled indexer optimization in #30715 does not apply to it. Its query path separately launches Hadamard rotation and FP8 quantization in every DSA layer; dual-stream decode also launches two elementwise operations to apply the head-gate scale.

This ports that fusion to `IndexerKPool`. The intended benefit is fewer kernel launches and one fewer BF16 intermediate round-trip, not an end-to-end throughput claim.

Component launch profile on MI355X/gfx950:

| path | fusion off | fusion on |
|---|---:|---:|
| prefill | 2 launches | 1 launch |
| dual-stream decode | 4 launches | 1 launch |

## Modifications

- Add `fused_hadamard_act_quant`, a Triton kernel combining the query-side Walsh-Hadamard transform and block FP8 quantization.
- Preserve the production BF16 materialization boundary inside the fused kernel so `ue8m0` scales match the two-pass path exactly.
- Fold `weights * q_scale * softmax_scale` into the fused kernel when dual-stream decode has precomputed head-gate weights.
- Wire the kernel only into `IndexerKPool`; the non-pooled `Indexer` remains unchanged.
- Keep the existing path as the default and fallback. The fused path requires `SGLANG_DSA_FUSE_HADAMARD_QUANT=1`, ROCm gfx950, a power-of-two head dimension, and `head_dim == block_size`.
- Add gfx950 tests covering GLM-5.3-Flash geometry `(M, 32, 128)`, `M={1,64,4096,16384}`, two seeds, `ue8m0` and unrounded scales, production two-pass parity, folded weights, finite outputs, and CUDA graph replay.
