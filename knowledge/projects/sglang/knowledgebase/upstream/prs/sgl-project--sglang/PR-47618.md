# [Fix] pd: Agree on PP prefill release and abort-vs-error outcome via PP0 decision

[Upstream PR](https://github.com/sgl-project/sglang/pull/47618) · state: open · merged: False

## Original PR description

## Motivation

With a pipeline-parallel prefill server in PD disaggregation, every PP stage must release an inflight request at the same step and in the same way. Main does this with a ring consensus over the PP group (#47045 made the concluded outcome agree across stages). #45085 (WIP, @stepinto) replaces the ring with a simpler scheme: PP0 reads every stage's transfer status through `PPConsensusStore` and forwards its decision.

One gap remains in both versions: the *classification* of a failed transfer is still decided locally. When a request is aborted (client `AbortReq` or a decode-side abort), only the rank that saw the abort records an abort reason. A stage that finished its own transfer has no failure reason, so it concludes the same request as a transfer error and returns a 500 for a request the client aborted, while other stages finish it as an abort.

This PR builds on #45085 (its commit is included with authorship preserved; happy to rebase onto it if it lands first) and adds an agreed abort-vs-error classification.

## Modifications

- Commit 1 (from #45085, rebased onto current main): PP0 polls every stage's status via `PPConsensusStore` and forwards the decision, replacing the ring consensus for releasing inflight requests. A transfer that failed on any stage stays Failed (min over stages), which keeps the behavior of #47045. Separate P2P tags for the bootstrap and inflight PP syncs.
- Commit 2:
  - `disaggregation/common/conn.py`: `record_failure` replicates whether a stage's failure was a requested abort to PP0 under a separate key, before the Failed status on the same ordered channel; keys are cleaned up with the room.
  - `disaggregation/utils.py`: `TransferOutcome` and `poll_transfer_outcomes_{prefill_pp,attn_cp_tp_group}`. PP0 forwards polls together with the terminal outcome: an error on any rank outranks an abort on another, and an abort is only reported if every failed rank recorded one. The same classification is applied across attention TP/CP ranks without PP.
  - `disaggregation/prefill.py`: `handle_inflight_transfer_failure` uses the agreed classification (abort → abort finish, error → 500) instead of the local exception.
  - `disaggregation/mooncake/conn.py`: record the decode-side abort reason, as NIXL already does.
- Commit 3: test stub update for the new `request_status` read in `record_failure`.
- Tests: `test/registered/unit/disaggregation/test_pp_prefill_release_consensus.py` covers PP0 decisions, error-over-abort precedence, abort agreement across stages and TP ranks, and key cleanup.

## Accuracy Tests

Qwen3-30B-A3B-Instruct-2507-FP8, B300, Mooncake over RoCE, mini-LB; prefill `--tp 1 --pp-size 2`, decode `--tp 1`. GSM8K 5-shot greedy, 400 examples:

| | GSM8K |
|---|---|
| main | 0.9625 |
| this PR | 0.960 |

Abort stress on the same deployment: 3 rounds × 96 concurrent requests (ISL 200/2000/6000, OSL 8/128/512), one third cancelled by the client mid-flight, one third aborted through `/abort_request`, one third run to completion. Afterwards 32 normal requests and health checks:

| | main | this PR |
|---|---|---|
| hang / stuck stage | no | no |
| completed requests OK | 96/96 | 96/96 |
| post-stress requests OK | 32/32 | 32/32 |
| prefill tracebacks | 0 | 0 |

Both main (44) and this PR (45) return 500 for the `/abort_request` requests whose abort lands while the request is still bootstrapping: decode only learns about it through its waiting timeout. That path is unchanged here (bootstrap-phase abort propagation to decode; related: #47250).

Unit tests: `python -m pytest test/registered/unit/disaggregation/` plus the affected `test/registered/unit/managers/` tests (489 passed).

## Speed Tests and Profiling

The PP release path issues one PP0 → stage forward per step instead of a ring pass; the extra abort flag is an int per failed room on the existing channel. No measurable change in GSM8K throughput.
