# [Feat] http_server: Make the multi-worker ASGI app path configurable

[Upstream PR](https://github.com/sgl-project/sglang/pull/44583) · state: closed · merged: True

## Original PR description

## Motivation

With more than one tokenizer worker (`--tokenizer-worker-num > 1`), both the Uvicorn and the Granian launch paths hand the server a fixed import string, `sglang.srt.entrypoints.http_server:app`, and every worker process re-imports that module-level app. A package that embeds SGLang and registers extra routes on the app in the parent process never sees those routes in the workers, because each worker loads the bare SGLang app. There is currently no way to point the workers at an extended app without forking the launch code.

## Modifications

- Add `SGLANG_HTTP_SERVER_APP_PATH` to the `Envs` registry (HTTP server section), defaulting to `sglang.srt.entrypoints.http_server:app`.
- Read it at both multi-worker launch sites in `http_server.py`: the Granian `target` and the `uvicorn.run(...)` import string.
- Document it next to the other HTTP-server variables in `docs/docs/references/environment_variables.mdx`.
- The single-worker path is unchanged and still passes the in-process `app` object; with the variable unset, behaviour is byte-for-byte the same as before.

Example: a package `my_pkg.server` that does `from sglang.srt.entrypoints.http_server import app` and adds its own routes can now run `SGLANG_HTTP_SERVER_APP_PATH=my_pkg.server:app` with multiple tokenizer workers, and every worker serves the extended app.
