# [AMD] Run MiniMax-M3 decode layers as mono kernels on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/44319) · state: open · merged: False

## Original PR description

## Motivation

At small batch sizes, MiniMax-M3 decode on MI355X is bound by kernel launches and the two TP all-reduces in every layer. This PR adds `--layer-backend mono`. With it, on gfx950 at TP4, each sparse MoE layer of a decode or EAGLE verify step (up to 16 tokens) runs as one persistent FlyDSL launch, both all-reduces included. Other steps and layers keep the normal path. It is off by default.

## Modifications

- `--layer-backend {module,mono}` and a small runtime in `srt/layers/mono`. A model declares a spec, which supplies:
  - startup refusal that lists every unsupported setting;
  - per-step routing from the CUDA-graph key;
  - kernel builds agreed across TP ranks;
  - peer memory for the in-kernel all-reduces;
  - a check mode (`SGLANG_MONO_CHECK=1`) that compares each routed layer with the normal path.
- MiniMax-M3 kernels in `kernels/ops/mono/gfx950/minimax_m3` and the M3 spec in `srt/models/minimax_m3_mono`. M3's decoder layer routes through the runtime.
- Prerequisites that the kernels read:
  - AITER FP8 block selection, the change in #41708 (included here until that PR merges);
  - page16 SHUFFLE K/V with AITER sparse attention.
- On ROCm, EAGLE greedy verify uses aiter `greedy_sample` instead of `torch.argmax`.

Requires `SGLANG_MINIMAX_M3_INDEX_TOPK_FREQ=1`.

## Accuracy Tests

`amd/MiniMax-M3-MXFP4`, TP4, full 5-shot GSM8K (1,319 questions), temperature 0.

| Configuration | Strict-match | Flexible-extract |
|---|---:|---:|
| `--layer-backend module` | 93.86% | 93.86% |
| `--layer-backend mono` | 94.09% | 94.09% |

Thanks for this! The monokernel framework has landed in SGLang (#44353): `--monokernel-backend amd` loads per-model specs from the plugin repo sgl-project/sgl-amd-mono, so model kernels now live there rather than in SGLang. Could you port the M3 monokernels over? sgl-project/sgl-amd-mono#6 (GLM-5.3-Flash) is the template, and `sgl_amd_mono/deepseek_v41` is a second worked example.

- `srt/models/minimax_m3_mono` and `kernels/ops/mono/gfx950/minimax_m3` become `sgl_amd_mono/minimax_m3/spec.py` and `sgl_amd_mono/minimax_m3/gfx950/`, registered in `sgl_amd_mono/__init__.py`.
- `--layer-backend mono` and `srt/layers/mono` go away: the framework routes steps by shape, checks graph-capture coverage, refuses unsupported setups at startup and keeps the ranks in agreement. The shared HIP runtime is `sgl_amd_mono/common`.
- Constraints go in the spec as data, e.g. the `SGLANG_MINIMAX_M3_INDEX_TOPK_FREQ=1` requirement in `Requirements.env`, and widths and TP sizes in `DeviceLimits`.
- The commits that change SGLang's normal path (AITER FP8 block selection, page16 SHUFFLE K/V sparse attention, EAGLE greedy verify through aiter) stay in SGLang as their own PRs.

#44686 (TP2) builds on this, so the two can port together. Happy to review.
