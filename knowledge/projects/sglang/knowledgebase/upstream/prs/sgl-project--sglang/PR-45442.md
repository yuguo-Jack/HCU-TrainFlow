# [Fix] [AMD] moe: Support SiLU-gated MXFP8 MoE on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/45442) · state: open · merged: False

## Original PR description

## Motivation

On gfx950 (MI350X/MI355X), the native MXFP8 MoE `fused_experts_mxfp8` (`tl.dot_scaled` grouped GEMM) only
implements the MiniMax-M3 SwiGLU-OAI activation. A standard SiLU-gated MoE model in MXFP8 (1x32 blocks, UE8M0
scales), such as Qwen3-30B-A3B, cannot be served at all. With `--moe-runner-backend triton` (the gfx950 MXFP8
default when `--quantization mxfp8` is given), the first forward raises:

```
NotImplementedError: native MXFP8 MoE expects uninterleaved (split) gate/up layout.
```

The check fires because Qwen3-MoE leaves `gate_up_interleaved` at its default `True`. That flag only describes
SwiGLU weights, though: for plain SiLU, `FusedMoE` loads w13 as `[gate; up]`, the split layout the kernel's
GEMMs already read. Only the activation between the two GEMMs is M3-specific.

## Modifications

- `fused_experts_mxfp8`: when neither `gemm1_alpha` nor `gemm1_limit` is set, select plain `silu(gate) * up`
  and skip the interleave check. DeepSeek-V4's `swiglu_limit` clamp is not implemented here, so it is rejected
  instead of being dropped silently.
- `fused_moe_mxfp8_native`: `alpha=None` applies `silu_and_mul` to the GEMM1 output, then the same MXFP8
  quantization as before GEMM2.
- The SwiGLU-OAI path (MiniMax-M3 passes `gemm1_alpha=config.swiglu_alpha`) is unchanged: on identical inputs,
  `fused_experts_mxfp8` with SwiGLU-OAI arguments returns bitwise-identical outputs to `main` in 120/120 cases:
  5 shapes, 6 argument sets (M3 with and without the clamp, default alpha with the clamp, `no_combine`,
  `expert_map`, `routed_scaling_factor`), and all 4 combinations of `SGLANG_MINIMAX_M3_FUSED_SWIGLU_MXFP8` and
  `SGLANG_MINIMAX_M3_FUSED_MOE_COMBINE`.
- Test: `test_mxfp8_native_moe_plain_silu` calls `fused_experts_mxfp8` with the Qwen3-MoE runner defaults and
  compares against a dequantized BF16 reference.

Not in scope:
- With `SGLANG_USE_AITER=1` (the ROCm image default) and neither `--quantization mxfp8` nor
  `--moe-runner-backend triton`, the `auto` runner still resolves to aiter, whose MXFP8 MoE only supports
  SwiGLU-OAI (`NotImplementedError: AITER MXFP8 MoE only supports swiglu-oai alpha=1.702, got gemm1_alpha=None.`).
  Pass one of the two flags.
- The native kernel still needs the per-rank MoE intermediate size to be a multiple of 128. For Qwen3-30B-A3B
  (768) that means TP1 or TP2, or TP4 with `--ep-size 4`.

## Accuracy Tests

Qwen3-30B-A3B converted to MXFP8, and to 128x128 block FP8 for comparison. Tested on MI350X with
`rocm/sgl-dev:miles-rocm10-mi35x-20261019` and this branch's Python sources. Offline `sgl.Engine`; MXFP8 runs
use `moe_runner_backend="triton"`, the others use the default runner.

GSM8K, first 250 test questions, greedy, non-thinking chat template, 768 new tokens:

| Model | Accuracy |
|---|---|
| BF16, TP1 | 92.4% |
| Block FP8, TP1 | 94.0% |
| MXFP8, TP1 | 94.4% (`main`: NotImplementedError) |
| MXFP8, TP2 | 94.8% |
| MXFP8, TP4 + EP4 | 94.8% |

BF16 and block FP8 do not reach the changed code; they were run on this branch.

Log-prob agreement with BF16 (TP1). 16 fixed prompts with 128-token BF16 greedy completions (1748 tokens),
each re-scored by prefill on every model:

| Model | mean abs dlogprob | p99 abs dlogprob | argmax == BF16 greedy token |
|---|---|---|---|
| BF16 (reference) | 0 | 0 | 99.1% |
| Block FP8 | 0.023 | 0.30 | 97.6% |
| MXFP8 (this PR) | 0.025 | 0.34 | 97.8% |

For BF16, the argmax column compares its prefill argmax with its own greedy decode; its prefill and decode log-probs differ by 0.011 mean / 0.14 p99 abs.

Kernel tests, `python -m pytest test/registered/kernels/ops/moe/test_minimax_m3_mxfp8.py` on MI350X: 2 failed
and 16 passed before the change (the new cases hit the `NotImplementedError` above), 18 passed after.

## Speed Tests and Profiling

Decode throughput, TP1, 512 random input tokens, 256 output tokens with `ignore_eos`, output tok/s:

| Model / MoE runner | bs 1 | bs 8 | bs 32 | bs 128 |
|---|---|---|---|---|
| BF16 / aiter (default) | 199 | 1065 | 3247 | 8116 |
| Block FP8 / aiter (default) | 181 | 1081 | 3702 | 9705 |
| Block FP8 / triton | 149 | 887 | 2862 | 8553 |
| MXFP8 / triton (this PR) | 118 | 758 | 2584 | 7610 |
| MXFP8 MoE / triton, dense layers converted to block FP8 (`SGLANG_FORCE_MXFP8_BLOCK_CONVERT_DENSE=1`) | 149 | 852 | 3115 | 8787 |

The MXFP8 MoE runs at the speed of the Triton block-FP8 MoE. The extra gap at small batch comes from the dense
MXFP8 linears, which this PR does not touch.
