# [Refactor] diffusion: Write MiniMax-H3 and Qwen-Image 2.1 break outputs into caller-allocated buffers

[Upstream PR](https://github.com/sgl-project/sglang/pull/46660) · state: closed · merged: True

## Original PR description

- Four graph breaks in the diffusion breakable CUDA graph now write into outputs the caller allocates right before the break and return nothing: the MiniMax-H3 attention core, the VDN-H3 hybrid attention core, `MiniMaxH3DiTModel._embed`, and Qwen-Image 2.1's `attend_past_prefix_pad`. The captured segment after each break reads those outputs. Before, each break returned fresh tensors on every replay and the graph wrapper copied them into the ones it had captured.
- The caller sizes each output from inputs it already has. The attention outputs take q's shape with v's head dim. The VDN linear readout covers the video rows on a single rank, all local rows under Ulysses, and is absent when the window covers the whole sequence. `forward` allocates the embeddings and the timestep embedding it passes to `_embed`. Each break asserts that its result has the predicted shape and dtype before it copies, since `copy_` would broadcast or cast a misprediction silently.
- The two attention cores go through their breaks only while a breakable graph is being captured; eager runs call the core directly, as before.
- Declared differences:
  - `_embed` takes `embeddings` and `t_emb` and returns `None`. The ComfyUI worker patch in `apps/comfyui_worker_patches/h3.py` still unpacks the old return, but its source-hash check already rejects the current `minimax_h3.py`, so the patch does not install today.
  - `_embed` copies the timestep embedding (`[M, time_embed_dim]`, fp32) into `t_emb` on every forward.
  - A Qwen-Image 2.1 forward that carries a prefix pad but runs eager (the warmups before capture, or a signature without a graph) copies the target attention output once more per layer.
  - VDN-H3 and VSA-H3 reject the breakable graph at startup, so their paths through these breaks run only for direct model callers.
- A unit test captures the Qwen-Image 2.1 prefix-pad break and checks that a replay with a new pad writes the captured output.
