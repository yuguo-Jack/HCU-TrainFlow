# [CI] proto: Publish protobuf module to Buf Schema Registry

[Upstream PR](https://github.com/sgl-project/sglang/pull/48216) · state: open · merged: False

## Original PR description

## Motivation

Downstream consumers written in Go, Python, and other languages (such as `llm-d/llm-d-router` for `sglang.api.v1.SglangService`) currently have to copy `.proto` files out of `sgl-project/sglang` and maintain local `protoc` pipelines to generate client/message bindings.

Publishing `proto/` as `buf.build/sgl-project/sglang` on the Buf Schema Registry (BSR) lets downstream projects import versioned generated SDKs directly (for example `go get buf.build/gen/go/sgl-project/sglang/protocolbuffers/go` and `buf.build/gen/go/sgl-project/sglang/grpc/go` via BSR Managed Mode) without adding language-specific options like `option go_package` to the `.proto` sources, while enforcing `buf build`, `buf lint`, and `buf breaking` checks on `.proto` changes in CI.

## Modifications

- Add `proto/buf.yaml` (Buf v2) declaring module `buf.build/sgl-project/sglang` with `STANDARD` lint rules (excluding the four naming rules that conflict with existing `sglang.api.v1`, `sglang.json.v1`, and `sglang.runtime.v1` wire contracts) and `FILE` breaking-change detection.
- Add `proto/README.md`, rendered by the BSR as the module documentation: generated SDK usage, version labels, a warning that the SDKs target the gRPC wire format (the HTTP JSON form follows the `sglang.json.v1` options, not canonical proto3 JSON), and the schema change process.
- Add `.github/workflows/buf.yml` (Buf CLI pinned to 1.75.0):
  - On pull requests touching `proto/**`: `buf build`, `buf lint`, and `buf breaking` against the PR's base commit. A maintainer can approve an intentional breaking change with the `buf skip breaking` label, which re-triggers the check.
  - On `main` pushes, `v*` release tag pushes, published GitHub releases, and manual dispatch on `main`: publish `proto/` to the BSR, labeled with the commit SHA and the branch or tag name.
  - Before publishing from `main`, re-run `buf breaking` against the previous `main` commit unless the merged PR carries `buf skip breaking`. The PR check is not a required status check, so this keeps an unapproved breaking change out of the registry.
  - Publishing is opt-in via `vars.BSR_PUBLISH_ENABLED`, so this can merge before the registry is set up. Once enabled, a missing `BUF_TOKEN` fails the job instead of silently skipping.

## Maintainer setup (after merge)

1. Create the `sgl-project` organization on buf.build (`buf push --create` creates the module, not the organization).
2. Create a BSR token for a bot or service account in that organization and add it as the `BUF_TOKEN` repository secret.
3. Set the `BSR_PUBLISH_ENABLED` repository variable to `true`.
4. Run the "Buf Protobuf" workflow manually on `main` once for the first publish.
5. Create the `buf skip breaking` label.
