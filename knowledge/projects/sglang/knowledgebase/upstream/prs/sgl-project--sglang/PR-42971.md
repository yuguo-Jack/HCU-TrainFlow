# [LoRA] Fix cancellation and unload races during reference acquisition

[Upstream PR](https://github.com/sgl-project/sglang/pull/42971) · state: closed · merged: False

## Original PR description

## Motivation

Cancelling a batched `LoRARegistry.acquire()` after one counter has incremented can leak the acquired reference and block adapter unload indefinitely. Lookup and increment also ran outside a common registry lock, allowing unregister/unload to remove a counter in between.

## Modifications

Resolve the whole batch and increment its counters under the registry writer lock. On an exception or cancellation, roll back only completed increments and finish that rollback even if the caller is cancelled again. The existing single-name/list return types and duplicate-name reference counts are preserved.

## Accuracy Tests

Eight CPU regression tests passed against the production registry, including cancellation after partial acquisition, repeated cancellation during rollback, and the unregister race. The two regressions for leaked counters and the unregister race fail on the unmodified base. No GPU/model computation changes.

## Speed Tests and Profiling

Not applicable to model execution; this changes asynchronous reference bookkeeping. No performance benchmark claimed.
