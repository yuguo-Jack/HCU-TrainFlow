I re-reviewed after the latest commit and found no new bugs. All three earlier points are fixed. The paths touched have CODEOWNERS (`python/sglang/srt/managers`, `rust/sglang-server`), so a maintainer should still take a look.

What was reviewed:
- Missing `names` now raise a ValueError that names the runner and lists every missing name, instead of a bare KeyError.
- Rust `CheckWeightsBody`, `CoreHandle::check_weights` and the msgpack `CheckWeightsReqInput` now carry `names` as the 8th element, matching the Python field order. The tests now expect 8 elements.
- The hash lookup now uses `_model_state()` with non-persistent buffers filtered out, so `layer_scalar` is hashed and `cos_sin_cache` is not. The new CPU tests cover both cases.

The PR adds a `raw_checksum` action to the weight-checking pipeline, plus an optional `names` field passed through the Rust HTTP server, the msgpack control message, the Python scheduler, ModelRunner and WeightChecker. It touches no auth, crypto or injection surface. The newest commit fixes all three issues raised in the previous review. I deferred instead of approving because CODEOWNERS covers the changed paths in `python/sglang/srt/managers` and `rust/sglang-server`, and the change alters a positional wire format shared by two languages.
