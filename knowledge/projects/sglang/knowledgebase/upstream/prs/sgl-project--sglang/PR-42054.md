# [Fix] function_call: Flush buffered text at stream end in Mistral, Hermes and GigaChat3 detectors

[Upstream PR](https://github.com/sgl-project/sglang/pull/42054) · state: open · merged: False

## Original PR description

## Motivation

Same loss pattern as #41909 / #41914 / #41962 / #41963 / #42007 / #42053:
`MistralDetector`, `HermesDetector` and `GigaChat3Detector` hold text back
in `self._buffer` while waiting for the closing marker, and
`BaseFormatDetector.finish()` returns an empty result by default. When the
stream ends with an incomplete tool call still buffered, the held-back text
is silently dropped.

## Changes

Add a `finish()` override to each detector that flushes `_buffer` as normal
text:

- `MistralDetector` / `HermesDetector`: a partial JSON block is flushed;
  a fully closed call (trailing `eot_token`) is not re-emitted.
- `GigaChat3Detector`: a partial function-call block is flushed; a complete
  JSON payload (validated via `REGEX_FUNCTION_CALL` + `json.loads`) is not
  re-emitted. Non-tool text kept in the buffer is flushed rather than
  dropped.

Normal streams are unaffected: `finish()` stays a no-op when `_buffer` is
empty (for Mistral/Hermes).

## Tests

Offline unit tests (no server, no model loading) for each detector cover:
- partial tool call at stream end: `finish()` releases the buffered text;
- plain/clean stream behavior;
- complete-call behavior: the closed call is not duplicated.

All pass locally (`pytest test/registered/unit/function_call/test_{mistral,hermes,gigachat3}_detector_finish.py`), ruff clean.
