# [Perf] [NVIDIA] kimi-k3: Route draft/dense bf16 GEMMs to TGV and narrow the MLA output gate vector

[Upstream PR](https://github.com/sgl-project/sglang/pull/46468) · state: closed · merged: True

## Original PR description

## Motivation

A per-kernel comparison of Kimi-K3 NVFP4 target verify (bs=1, 8 tokens, TP8 per-rank shapes) found three small-M bf16 GEMMs still on cuBLAS where TGV is faster, and an MLA output gate launch with too few CTAs for its `[8, 12, 128]` tile.

## Modifications

- `cutedsl_bf16_gemm.py`: add `(7168, 1792)` DSpark draft down, `(7168, 512)` draft o_proj and `(8448, 7168)` dense gate_up to `_K3_TGV_WIN_SHAPES`. The table only applies at M <= 8, so this affects decode and verify.
- `mla_output_gate.cuh`: 4 bf16 per thread instead of 8, doubling the CTA count. Output is bit-exact.

## Accuracy Tests

- `mla_output_gate`: bit-exact against the torch reference for T in {1, 2, 5, 8, 16, 128, 1024}.
- TGV vs cuBLAS on the three shapes: identical output (max abs diff 0.0).
- On this branch: `test_mla_output_gate.py` OK and `test_cutedsl_bf16_gemm.py` 462 passed on both SM107 and GB300 (SM103).

## Speed Tests and Profiling

CUDA-graph us per call with cold weights (rotated past L2). M=7 for the draft shapes, M=8 otherwise.

| op | SM100 before | SM100 after | SM107 before | SM107 after |
|---|---:|---:|---:|---:|
| draft down_proj 7168x1792 | 5.64 | 4.77 | 6.23 | 3.90 |
| draft o_proj 7168x512 | 3.07 | 2.53 | 3.00 | 1.92 |
| dense gate_up 8448x7168 | 19.47 | 18.95 | 14.07 | 13.70 |
| mla_output_gate | 1.29 | 1.07 | 1.28 | 1.02 |

About 25 us per decode step in total; end to end it is within run-to-run noise (SM107 TP8, bs=1, 8k in / 1k out: 645.6 vs 647.7 / 651.7 tok/s single runs), with the trace confirming the new kernel selection.
