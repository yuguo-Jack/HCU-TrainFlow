# [Perf] dsv41: Mega-mHC and the wo_a einsum write MXFP8 for wqkv_a and wo_b

[Upstream PR](https://github.com/sgl-project/sglang/pull/45632) · state: closed · merged: True

## Original PR description

## Motivation

In DeepSeek-V4.1 Mega attention decode, wqkv_a and wo_b quantize their bf16 input in a separate kernel before the MXFP8 GEMM. The producers of those inputs (Mega-mHC and the wo_a `fp8_einsum`) can write the MXFP8 input directly.

## Modifications

- `LinearBase.deepgemm_mxfp8_input`: `MQALayer` sets it on wqkv_a and wo_b before load; `Fp8LinearMethod.process_weights_after_loading` packs a DeepGEMM weight scale beside the FlashInfer one and keeps the flag only when it did. A DeepGEMM-packed activation pair is a plain `(fp8, int32 scale)` tuple, which `apply` routes to the existing `deepgemm_w8a8_mxfp8_linear_with_fallback`.
- `mhc_mega_boundary` takes `y_fp8` / `y_gemm_sf` out-buffers; the Mega-mHC post fills them for the next layer's wqkv_a.
- The Mega wo_a `fp8_einsum` writes its FP8 output pair for wo_b.
- On whenever the layer can be prepared (Blackwell, DeepGEMM UE8M0, FlashInfer dense backend, aligned shapes); decode/verify only (no extend, no SP), at most 2048 rows. Every other linear is unchanged.
