# [Perf] diffusion: Wan-Animate-2 decode clamp, LTX-2 Bongmath closed form, rollout log-prob/CPU-copy, validators NaN gate, in-place decode normalize

[Upstream PR](https://github.com/sgl-project/sglang/pull/46277) · state: closed · merged: True

## Original PR description

Six independent, small fixes found while reviewing the diffusion denoising/rollout/decode path. Each is its own commit; no commit depends on another.

## 1. `[Fix]` Wan-Animate-2: clamp decoded frames before uint8 cast
`WanAnimate2DenoisingStage`'s per-clip decode calls `clip_decoder.decode_raw(...)`, which does not clamp its fp32 output to `[-1, 1]`. The frame-to-uint8 conversion then did `((decoded_frames + 1) * 127.5).to(torch.uint8)` with no clamp: a value a little outside `[-1, 1]` (e.g. `-1.02`) pushes the scaled value outside `[0, 255]`, and the cast wraps around instead of saturating, producing a bright/dark speckle instead of a clean pixel. Fix: extract the conversion into a named helper and add `.clamp(-1, 1)` before scaling, matching the existing pattern in `decoding.py`'s `_to_unit_range`.

Test: `test_clip_decoded_frames_past_unit_range_saturate_instead_of_wrapping` — values straddling the boundary, asserts saturation instead of wraparound. Fails on the pre-fix formula, passes post-fix.

## 2. `[Perf]` LTX-2: replace Bongmath's 100-iteration fp64 loop with a closed form
The Bongmath anchor-refinement loop (`anchor = x_mid - h*a21*eps1; eps1 = denoised - anchor`, run 100 times, both video and audio, at two call sites) is an affine contraction in `eps1` with ratio `c = h*a21` (`|c| <= 0.22` in practice), so it converges to a fixed point `eps1* = (denoised - x_mid) / (1 - c)`. Solving directly replaces ~800 full-size fp64 kernel launches per step with a handful of elementwise ops.

Verified: closed form matches the 100-iteration loop to ~1e-16 relative error across the full valid `h` range, independent of the loop's starting point (tested numerically with real torch/einops, not just by inspection).

## 3. `[Perf]` rollout_hooks: skip the CPU copy init discards
`init_rollout_env_if_enabled` copied `pos_cond_kwargs`/`neg_cond_kwargs` to CPU (a host sync) on every rollout request that returns the denoising environment, but `finalize_rollout_if_enabled` always overwrites both with its own SP-gathered CPU copy before anything reads them. The initial copy was pure waste.

Test: `test_pos_neg_cond_kwargs_are_kept_as_is_not_copied_to_cpu` asserts the stored values are the exact same (GPU) tensor objects, not a copy.

## 4. `[Perf]` validators: gate the NaN scan behind an env flag (opt-in)
`StageValidators.is_tensor`/`tensor_with_dims`/`list_of_tensors`/etc. each run a `torch.isnan(x).any().item()` scan (full-size kernel + host sync) on every field they check, on every request — roughly 6+ of these fire per request on the standard path (text-encoding output, latent-prep input, timestep-prep output, denoising input). Shape/type checks stay on regardless; `SGLANG_DIFFUSION_DISABLE_STAGE_NAN_CHECK=1` skips only the NaN scan, for callers on few-step/distilled models who want to cut per-request sync overhead and already trust their pipeline.

Test: `test_stage_validators_nan_gate.py` — default still rejects NaN, the flag accepts it while keeping shape checks, clean tensors pass either way.

## 5. `[Perf]` flow_rollout_controller: simplify SDE/CPS log-prob to one reduction
`-((full_variance_noise*noise_std_dev)**2) / (2*noise_std_dev**2)` is exactly `-0.5*full_variance_noise**2` (`noise_std_dev`, a scalar here, cancels algebraically), and `-log(noise_std_dev) - C` is the same scalar at every spatial position, so summed over the reduce dims it is just `local_elem_count * that scalar`. Moving both out of the per-element sum turns a full-size divide plus two full-size broadcast-subtracts into a single reduction plus a cheap per-batch-row correction. Also stopped allocating and summing a full-size zero tensor on ODE steps (`p_ode` is always exactly zero), and stopped allocating the ODE debug noise tensor when debug mode is off.

Verified against the existing `test_scheduler_rollout_unit.py` FlowGRPO bit-for-bit reference check (`atol=1e-6`, covering both the full log-prob and no-const branches) and a 200-trial numeric comparison against the original formula (max abs error 3.6e-7 on `log_prob_mean`).

## 6. `[Perf]` decoding: normalize decoded frames to `[0,1]` in place (memory, not speed)
`decode()`'s final `_to_unit_range(image)` call created a second full-size copy of the decode output (900MB+ for a typical video decode) just to rescale and clamp it. `image` is `decode_raw`'s fresh output with no other live reference to its pre-normalization values (`decode`/`decode_raw` both run under `@torch.no_grad()`), so it's safe to rescale/clamp in place. The streaming `on_frames` callback path keeps the out-of-place default, since those frames come from the VAE's own per-tile buffer.

Test: `_to_unit_range(..., in_place=True)` matches the out-of-place formula and mutates its input; the default stays out-of-place.

## GPU benchmark (base vs head)
Microbenchmarks on an NVIDIA A10: each changed code path, base (`main`) vs head, on synthetic tensors at realistic shapes, median of 20 runs. Not a full end-to-end model run.

| Change | Shape | Base | Head | Gain |
|---|---|---|---|---|
| LTX-2 Bongmath (video + audio) | `[1,128,16,32,48]` | 43.5 ms | 0.55 ms | 79x, rel err ~2e-16 |
| LTX-2 Bongmath (video + audio) | `[1,128,16,16,24]` | 11.0 ms | 0.14 ms | 81x |
| Rollout init CPU copy | pos + neg `[1,512,4096]` bf16 | 0.80 ms | 0.008 ms | one host sync removed |
| Validator NaN scan (flag on) | per field | 0.062 ms | 0.008 ms | ~0.05 ms per field, 6+ fields per request |
| Log-prob, SDE | `[4,16,21,60,104]` | 0.95 ms | 0.25 ms | 3.9x, rel err 1.4e-7 |
| Log-prob, ODE | `[4,16,21,60,104]` | 0.15 ms | 0.02 ms | 7.8x |
| Decode normalize in place | `[1,3,121,720,1280]` | 16.9 ms | 16.7 ms | same speed, 2.5 GiB less peak memory (740 MiB less at 480p) |

Notes:
- The decode change saves memory, not time.
- The validator change only applies with `SGLANG_DIFFUSION_DISABLE_STAGE_NAN_CHECK=1`; default behavior is unchanged.
- The Bongmath saving is per refinement call; a full LTX-2 generation was not measured.

## Test plan
- Each fix has a focused regression test (see above), reusing existing fixtures/test files where one fit.
- All 6 fixes were run against the real package (not just unit-test logic) in a GPU-image CPU container on Modal, head vs base where base has a meaningful comparison:
  - Wan-Animate-2 clamp: head 129 passed / base 128 passed
  - LTX-2 Bongmath: 2 passed (head only; closed form verified separately against the loop)
  - rollout_hooks: 3 passed (head only)
  - validators NaN gate: 3 passed (head only)
  - flow_rollout log-prob: head 10 passed/1 skipped, base 10 passed/1 skipped — **identical pass count on both branches**, confirming no regression against the FlowGRPO reference
  - decoding in-place: head 12 passed / base 9 passed

## Known limitations / deferred (not in this PR)
- CFG batching (combining cond/uncond into one forward pass) is not included — it needs per-model measurement, not just a correctness check, and the models that don't already do it (most besides Cosmos3/LTX-2) would need individual handling of text lengths, masks, and RoPE.
- Minor per-step CPU overhead (`_build_attn_metadata` re-deriving the builder class every step, NVTX label string formatting) is not included — caching the builder class at construction looked tempting but I couldn't confirm `self.attn_backend` never changes mid-run across all models without a deeper audit, and the review that flagged it called this the lowest-priority item ("only matters with CUDA graphs or very small models").
