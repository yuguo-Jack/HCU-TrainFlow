# [Perf] deepseek-v4: Reuse synchronized prefill tail counts

[Upstream PR](https://github.com/sgl-project/sglang/pull/45811) · state: open · merged: False

## Original PR description

## Motivation

Remove a redundant host collective from eligible eager decoder replay tails by reusing DP token counts already exchanged during synchronized DSPARK prefill.

## Modifications

- Add count reuse for CUDA MegaMoE + DSPARK with speculative prefill coordination disabled, attention TP=CP=1, and complete early/late count vectors.
- Preserve existing eligibility checks and the collective fallback for all other configurations or incomplete metadata.
- Change one Python helper; graph-owned count buffers remain unchanged.

## Accuracy Tests

- Reported local eligibility/fallback checks and pre-commit passed. Observation-only prefill/idle probes found no count mismatches.
- GSM8K (200 examples, baseline/reuse/reuse/baseline): **197/195/197/197** correct.
- First tokens matched across ten directed inputs. Top-20 logprobs varied even between baseline restarts, so numerical equivalence remains unestablished.

## Speed Tests and Profiling

Reported fixed-batch prefill measurements with the Rust TreeCore backend used `benchmark/engine_steps/bench_engine_steps.py` from #46006 at `ede3f52b3ffe5bd1ec13eaa848ba0e570fa24742`. ABBA means:

| Baseline (ms/step) | Reuse (ms/step) | Throughput change (%) |
|---:|---:|---:|
| 359.435 | 359.607 | -0.048 |

All harness and engine-log checks passed. The difference is within the baseline variation of 0.168%; no stable engine-step gain or regression was established.

Historical prefill-serving screens used a different harness and the Python TreeCore fallback:

| Screen | Total-token throughput change (%) |
|---|---:|
| 1 | +10.16 |
| 2 | +7.32 |

These historical results are not #46006 measurements. They include cached input tokens and changing request/cache mixes, and do not establish benefit with the default Rust backend or application E2E performance. Stronger numerical qualification remains outstanding.
