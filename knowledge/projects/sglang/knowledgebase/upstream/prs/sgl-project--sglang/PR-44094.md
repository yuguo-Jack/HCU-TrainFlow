# fix(serving): pin cuBLAS/cuDNN to deterministic modes for batch-shape invariance

[Upstream PR](https://github.com/sgl-project/sglang/pull/44094) · state: closed · merged: False

## Original PR description

## Summary

Fixes numerical drift across batch shapes reported in **#43956**: Qwen3.8-27B scores change enough to flip borderline decisions (FP8 / BF16) when the same token IDs are placed into different batch sizes.

## Root cause

The reporter isolated the first projection drift to a pure-PyTorch `torch.nn.functional.linear` (BF16 x BF16 → BF16) in `model.language_model.layers.0.linear_attn.in_proj_ba`. A BF16 intermediate dot product was near the rounding boundary and cuBLAS chose a different reduction order for different M/N/K shapes — this crossed the boundary and the difference propagated through the network. With FP8 checkpoints and the default BF16 LM head the drift reached **12.2 percentage points** on a 0.5 P(positive) tie.

`torch.backends.cuda.matmul.allow_bf16_reduced_precision_reduction = False` alone does not help because the problem is *reduction order*, not reduced-precision reduction.

## Fix

Wire cuBLAS and cuDNN determinism into the existing `--enable-deterministic-inference` code path in the argument-resolution pipeline:

1. **`CUBLAS_WORKSPACE_CONFIG=:4096:8`** — forces cuBLAS to pick the deterministic algorithm variant for every GEMM call, regardless of M/N/K shape. This is the primary fix and is set before any cuBLAS lazy initialisation.
2. **`CUDNN_DETERMINISTIC=1` / `CUDNN_BENCHMARK=0`** plus the equivalent `torch.backends.cudnn` attributes.
3. **`torch.use_deterministic_algorithms(True, warn_only=True)`** with flash-/mem-efficient-SDP disabled and `allow_bf16_reduced_precision_reduction=False` so remaining PyTorch ops with shape-dependent behaviour are pinned to deterministic code paths.

All three env vars are applied:
- First in `handle_deterministic_inference` (pipeline step 228 of 351) — the earliest deterministic hook, well before model load or any GEMM.
- Then again via `setdefault` in `handle_environment_variables` (step 318) as a belt-and-braces guard for code paths that might initialise cuBLAS between the two steps. `setdefault` preserves the earlier hook’s values.

## Testing

I don’t have access to the reported H20 environment, so verification will need to come from the reporter’s existing reproduction script. The fix is additive to the existing `--enable-deterministic-inference` flag and a no-op when that flag is not set.
