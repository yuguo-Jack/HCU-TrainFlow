# [Feat] [AMD] sgl-kernel: accept gfx1101, gfx1102 and gfx1200 in the ROCm AOT build

[Upstream PR](https://github.com/sgl-project/sglang/pull/46909) · state: open · merged: False

## Original PR description

## Motivation

On `amd_march`, the ROCm AOT build accepts `gfx1100` and `gfx1201` but not the other RDNA3 / RDNA4 discrete parts:

- gfx1101 (Navi 32, e.g. RX 7800 XT / W7800)
- gfx1102 (Navi 33, e.g. RX 7600)
- gfx1200 (Navi 44, e.g. RX 9060 XT)

For those, the build stops immediately:

```
$ AMDGPU_TARGET=gfx1101 python setup_rocm.py build_ext --inplace
Error: Unsupported GPU architecture 'gfx1101'. Expected one of: ['gfx942', 'gfx950', 'gfx1100', 'gfx1151', 'gfx1201', 'gfx1250']
```

They are the same ISA families as gfx1100 / gfx1201: wave32, and `is_rdna_supported()` already matches `gfx11*` / `gfx120*`. They need no code change beyond the allowlist. This is the smallest piece of the RDNA plan in #46900.

## Modifications

Add `gfx1101`, `gfx1102` and `gfx1200` to `supported_archs` in `python/sglang/kernels/aot/setup_rocm.py`. Nothing else changes, and the build is unchanged for every target that was already accepted.

## Accuracy Tests

**Build.** `rocm/pytorch:rocm7.2.3_ubuntu24.04_py3.12_pytorch_release_2.10.0`, no GPU in the container, so `AMDGPU_TARGET` is used as given. Offload bundles were read back from `common_ops*.so` with `llvm-objdump --offloading`, run on a copy.

| `AMDGPU_TARGET` | before | this PR | bundles |
|---|---|---|---|
| `gfx1101` | `Error: Unsupported GPU architecture` | rc=0 | gfx1101 |
| `gfx1102` | same error | rc=0 | gfx1102 |
| `gfx1200` | same error | rc=0 | gfx1200 |
| `gfx1100;gfx1101;gfx1102;gfx1200;gfx1201` | same error | rc=0 | all five |

**Runtime.** I don't have gfx1101/1102/1200 hardware. The five-arch fat binary above was installed and the AOT kernel tests were run on the two RDNA GPUs I do have, one pytest per file:

| test | gfx1100 (W7900D) | gfx1201 (R9700) |
|---|---|---|

| test_moe_topk_softmax | 744 passed | 744 passed |

`test_topk` fails the same way on unmodified `amd_march` on both GPUs: 157 failed / 5 passed. It is not related to this change. The cause is that `include/hip/dsa_topk_coop.cuh` hard-codes `kWaveSize = 64`. `main` fixed that in #41687, and I'll open a separate backport of it to `amd_march`.
