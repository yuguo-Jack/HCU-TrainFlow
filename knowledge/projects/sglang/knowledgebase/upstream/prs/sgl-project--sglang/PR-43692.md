# [Fix] convert_otel_2_perfetto: handle whitespace-prefixed arrays and SMG spans

[Upstream PR](https://github.com/sgl-project/sglang/pull/43692) · state: closed · merged: False

## Original PR description

## Motivation

Fixes #43540.

`scripts/convert_otel_2_perfetto.py` rejects two supported trace inputs:

1. A JSON array with insignificant leading whitespace is misdetected as JSONL. The format sniff only inspects the very first character, so a compact array is parsed as JSONL and later crashes with `TypeError: list indices must be integers or slices, not str`, while a pretty-printed array crashes with `JSONDecodeError` on the first line.
2. A normal OTLP span from `service.name=smg` crashes with `KeyError: 'child'`. `build_otel_span_tree` initializes the internal `child` field for engine spans only, but the shared perfetto converters (`__convert_to_perfetto_span`, `__convert_to_perfetto_events`) also expect it on SMG spans.

## Modifications

- `load_otel_data`: detect the input format from the first *non-whitespace* character (`content.lstrip().startswith("[")`), so a whitespace-prefixed JSON array is no longer mistaken for JSONL. The JSONL path is unchanged.
- `main`: initialize the internal `child` field (`span.setdefault("child", [])`) for SMG spans after tree building, so an OTLP exporter never has to provide the converter's internal field. `setdefault` keeps any exporter-provided value intact.
- Removed four provably unused imports (`collections.defaultdict`, `typing.Iterable/List/Tuple`) that were already flagged by `ruff check --select F401` before this change.

## Tests

- Ran the exact reproduction from the issue (stdlib only): plain array, space-prefixed compact array, and newline-prefixed pretty-printed array of an SMG span. Before: all three exited 1 (`KeyError: 'child'`, `TypeError`, `JSONDecodeError` respectively). After: all three exit 0 and produce byte-identical Perfetto output containing the complete SMG span.
- Regression: a JSONL input and a mixed engine+SMG input convert unchanged; the JSONL and whitespace-prefixed-array forms of the same trace produce identical output.
- Audit: `ruff check --select F401,F821,F823,UP037` and `ruff format --check` pass on the file, `python3 -m py_compile` passes, `git diff --check` is clean, no added line exceeds 88 cols. No existing tests reference this script.
- Honest caveat: this machine has no GPU and the converter needs none (standard library only), so verification was limited to the CLI-level reproduction above; CI is needed for any broader integration signal.
