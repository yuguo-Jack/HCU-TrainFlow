# Fix MiMo vision sink semantics and text sliding-window boundaries

[Upstream PR](https://github.com/sgl-project/sglang/pull/43678) · state: open · merged: False

## Original PR description

## Motivation

Align MiMo attention behavior with the released reference implementation:

- **Vision sink semantics:** each head's sink biases the first real key in each packed segment, whose value participates in the output. This differs from a virtual sink that only contributes to the softmax denominator.
- **Vision window handling:** the existing FA4 path omits the window and sink arguments.
- **Text SWA boundary:** the configured window includes the current token. A window of 128 therefore requires an inclusive left extent of 127, rather than 128.

## Modifications

- Add an explicit first-key sink mode for MiMo vision attention, preserving the default behavior for other models.
- Implement FA3/FA4 correction using ordinary windowed attention output and its log-sum-exp:
  - `beta = expm1(sink) * exp(q @ k0 * scale - lse)`
  - `output = (output + beta * v0) / (1 + beta)`
- Apply the correction with a small Triton kernel only to queries that can attend to the first key. Support packed segments, GQA, strided tensors, and CUDA graph replay.
- Add segmented SDPA support for the first-key bias and window mask. Fall back to SDPA when a selected backend does not support first-key sinks.
- Convert MiMo text window sizes consistently across target attention, MTP attention, and runner/KV-cache metadata.
- Add CPU and CUDA regression tests.

Text virtual-sink semantics and the vision window's existing boundary convention are unchanged.

## Accuracy Tests

Local regression results:

- **59 tests and 22 subtests passed**, including existing vision attention and MiMo QKV-loading tests.
- CPU-only run: **9 tests and 11 subtests passed**.
- Pre-commit checks passed for all changed files.

Coverage includes:

- Real FA4 and SDPA outputs against an independent FP64 attention reference.
- Window boundaries, unequal packed segments, GQA, strided QKV, zero sinks, and queries that cannot see the first key.
- CUDA graph replay with updated segment boundaries.
- Text SWA packed prefill, paged decode, and chunked prefill.
- An adversarial boundary case showing that a key incorrectly included by the old text window no longer contributes.
- Target/MTP attention configuration and runner window metadata.

A complete vision-tower comparison also used model weights, fixed synthetic patch inputs, and the released reference implementation. Inputs covered non-square grids, multiple frames, and row/column window ordering.

| Implementation | Final-output RMSE | Cosine similarity |
| --- | ---: | ---: |
| Existing BF16 FA4 path | 0.0158040 | 0.957329 |
| Corrected BF16 FA4 path | 0.00287397 | 0.998459 |
| Corrected FP32 SDPA diagnostic | 1.80941e-7 | 1.0 |

The FP32 diagnostic used native RMSNorm and disabled both matmul and cuDNN TF32 on both sides. It passed `assert_close(atol=2e-5, rtol=2e-3)`, with maximum absolute error `1.26362e-5`.

The BF16 comparison measures improvement over the existing path, which omits both the vision window and sink; it does not establish bitwise equivalence. The FP32 result is an SDPA diagnostic, not an FA4 measurement.

Real FA3 kernel execution and long-sequence end-to-end generation were not tested in this PR's validation run.

## Speed Tests and Profiling

Attention-only microbenchmark on a Blackwell GPU:

- BF16, 8 packed segments, 32 query heads, 8 KV heads, head dimension 64.
- Strided QKV tensors.
- CUDA-event timings, median of three groups of 30 eager calls.

| Tokens per segment | Existing FA4 path, without window/sink | Corrected window + first-key sink |
| --- | ---: | ---: |
| 128 | 0.055863 ms | 0.095062 ms |
| 512 | 0.056475 ms | 0.093005 ms |
| 2048 | 0.292283 ms | 0.114314 ms |

For the shorter shapes, the corrected path adds approximately 37–39 µs per attention call. The longer shape benefits from restoring windowed attention.

These paths implement different attention semantics, so the table describes the cost of the correctness change rather than an equivalent-operation speedup. Eager measurements include launch gaps and do not represent end-to-end serving throughput.
