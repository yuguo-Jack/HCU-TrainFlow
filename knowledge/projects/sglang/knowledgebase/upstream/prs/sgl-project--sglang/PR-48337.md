# [Fix] dsv32: Keep developer messages when dropping earlier reasoning

[Upstream PR](https://github.com/sgl-project/sglang/pull/48337) · state: open · merged: False

## Original PR description

## Motivation

With the DeepSeek-V3.2 encoder (`chat_encoding_spec == "dsv32"`), a thinking-mode request fails with HTTP 400 when it has a `developer` message before its last user turn:

```
DS32EncodingError: Index 2 out of range for messages list of length 2
```

In thinking mode, `encode_messages` first calls `drop_thinking_messages`, which rebuilds the message list without earlier `reasoning_content`. It keeps `user`, `system` and `tool` messages and strips `assistant` ones, but a `developer` message before the last user turn matches neither branch and is dropped. `encode_messages` then loops over the original number of messages, and `render_message` indexes past the end of the shorter list.

The rest of the encoder already treats `developer` as a user turn (`find_last_user_index`, `render_message`), and `serving_chat` passes `developer` messages to this encoder unchanged. Two inputs that hit it:

- an OpenAI-style request with a `developer` instruction followed by a `user` message;
- DeepSeek's multi-turn search-agent format, where each turn is a `developer` message and an assistant reply sits between them.

Chat mode doesn't drop messages and was not affected. DeepSeek's reference `encoding/encoding_dsv32.py` on Hugging Face has the same `["user", "system", "tool"]` list, so the copy here inherited it.

## Modifications

- `drop_thinking_messages` keeps `developer` messages, like `user` messages.
- New `test/registered/unit/entrypoints/openai/test_encoding_dsv32.py` (CPU suite `base-a-test-cpu`). The encoder had no unit tests, and this case needs no serving fixtures.
  - The test encodes both conversations above in thinking mode and checks that every developer message is rendered and the prompt ends with `<｜Assistant｜><think>`.
  - It fails on `main` with `DS32EncodingError` and passes with the change.
