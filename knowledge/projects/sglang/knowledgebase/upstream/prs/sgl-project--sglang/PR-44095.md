# [Bug] Fix bench_serving --dataset-name openai always reports prompt_len=2

[Upstream PR](https://github.com/sgl-project/sglang/pull/44095) · state: closed · merged: False

## Original PR description

## Summary

Closes #43929

`bench_serving --dataset-name openai` records every request's prompt length as **2 tokens** regardless of actual prompt size.

### Root Cause

In transformers >= 5.0, `tokenizer.apply_chat_template(messages, tokenize=True, add_generation_prompt=True)` returns a `BatchEncoding` dict (`{"input_ids": [...], "attention_mask": [...]}`) by default. The code calls `len()` on that dict, which gives the number of keys (2), not the token count.

When the loader was added (#17219, first released in v0.5.9), SGLang pinned transformers 4.57.1 where `apply_chat_template(tokenize=True)` returned a plain list of token IDs. Transformers 5 changed the default behavior to return a dict.

### Fix

Pass `return_dict=False` to get a plain list of token IDs so `len()` returns the actual token count:

```python
# Before (broken on transformers >= 5.0):
prompt_len = len(tokenizer.apply_chat_template(messages, tokenize=True, add_generation_prompt=True))

# After:
prompt_len = len(tokenizer.apply_chat_template(messages, tokenize=True, add_generation_prompt=True, return_dict=False))
```

### Impact

This fix restores correct reporting of:
- `Total input tokens`
- `Input token throughput`
- `Total token throughput`

In both console report and JSON output from `bench_serving` with `--dataset-name openai`.

### Verification

Manual logic verification confirmed:
- Old code with transformers 5: `len()` returns `2` (dict keys) ❌
- New code with transformers 5: `len()` returns actual token count ✅

### Additional finding
During investigation, I found a **similar latent bug** in `python/sglang/srt/multimodal/processors/voxtral.py:166` where `tokenizer.apply_chat_template(messages, tokenize=True)` is called without `return_dict=False`, and the result is iterated with `enumerate()`. On transformers >= 5.0 this would iterate dict keys instead of token IDs. Scope of this PR is limited to the benchmark loader as requested by issue #43929.

Searched for PRs addressing this specific transformers 5 compatibility issue in the benchmark loader — none found.
