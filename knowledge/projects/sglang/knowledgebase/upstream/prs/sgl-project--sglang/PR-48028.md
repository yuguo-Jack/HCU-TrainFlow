# [Fix] batch-invariant: restore torch.bmm when set_batch_invariant_mode exits

[Upstream PR](https://github.com/sgl-project/sglang/pull/48028) · state: closed · merged: True

## Original PR description

## Motivation

`enable_batch_invariant_mode()` replaces `torch.bmm` with `bmm_batch_invariant`, but the `set_batch_invariant_mode()` context manager only restored `_batch_invariant_MODE` and the aten library when it exited. After the first `with set_batch_invariant_mode(): ...` in a process, every later `torch.bmm` call kept going through the batch-invariant Triton kernel.

A caller that runs after the context (for example a test computing an fp32 reference with `torch.bmm`) then silently uses a different kernel than it expects and gets different numerics, and the outcome depends on which code ran earlier in the same process.

## Modifications

- `set_batch_invariant_mode()` saves `_original_torch_bmm` and `torch.bmm` together with the mode and library on entry, and restores all of them on exit.
- The restore moved into a `finally` block, so an exception raised inside the context also leaves `torch.bmm` as it was found.

Behaviour inside the context is unchanged.

## Accuracy Tests

Checked directly on a GPU host:

```python
import torch
from sglang.srt.batch_invariant_ops import set_batch_invariant_mode

bmm = torch.bmm
with set_batch_invariant_mode():
    assert torch.bmm is not bmm          # replaced inside
assert torch.bmm is bmm                  # restored on exit (fails before this change)
try:
    with set_batch_invariant_mode():
        raise RuntimeError("boom")
except RuntimeError:
    pass
assert torch.bmm is bmm                  # restored after an exception too
```

Before this change the second assertion fails: `torch.bmm` is still `bmm_batch_invariant` after the context exits. The existing `test/registered/unit/batch_invariant_ops/test_batch_invariant_ops.py` calls `torch.bmm` only inside the context, so its expectations are unchanged.
