# [Fix] request_logger: Redact client watermark keys in request logs when watermarking is off

[Upstream PR](https://github.com/sgl-project/sglang/pull/47545) · state: closed · merged: True

## Original PR description

## Motivation

A client can send a watermark config that carries its key to a server launched without `--enable-watermark`. The received-request log runs before validation rejects such a request, so the key was written to the request log in plain text, at every `--log-requests-level` and in both the text and JSON formats. The request-metrics exporter had the same gap. The crash dump's `server_args` snapshot had a related one: the Python API (`ServerArgs` / `Engine(watermark_key=...)`) accepts a server key without `--enable-watermark`, and the dump then pickled the raw `ServerArgs`.

## Modifications

- `request_logger.py`: with watermarking off, `_has_client_watermark` looks only where a client can put a watermark config: `GenerateReqInput.watermark` (a single value or the per-request list), `sampling_params["watermark"]` (a dict, a list of dicts, or `None`; `EmbeddingReqInput` included), and the OpenAI request's top-level `watermark` after `model_dump`. `_redact_client_watermark` returns the request unchanged when none of those is set, or when watermarking is on (the formatters already redact then). Otherwise it redacts; for the OpenAI request dict it redacts only the watermark config on a shallow copy instead of walking the dict and its prompt. It is applied in `log_received_request`, `log_openai_received_request` and `log_finished_request`. A request without a watermark field is logged exactly as before, with no copy and no walk over its token-id lists.
- `request_metrics_exporter.py`: redact the watermark container fields of the exported request parameters.
- `tokenizer_manager.py`: `_server_args_for_dump` always writes the redacted resolved dict, as watermarking-on servers already did (that dict also loads under `safe_pickle_load`, which blocks the `ServerArgs` object). If the snapshot raises, the dump is written without `server_args`, as for the config snapshot.
- `sampling/watermarking/README.md`: request logs redact watermark keys whether or not `--enable-watermark` is set, and without it only those fields are checked.

## Accuracy Tests

Not applicable: request-log, metrics-export and crash-dump redaction only; no change to model outputs.

## Speed Tests and Profiling

Not run here. Per logged request the added check reads at most two fields; a request without a watermark field takes the same path as before, and `redact_watermark_secrets` is never called for it (asserted by the new test).
