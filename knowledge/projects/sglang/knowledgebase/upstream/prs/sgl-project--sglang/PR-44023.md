# [Perf] Bind scheduler CPUs to the GPU's NUMA node when memory policy is not permitted

[Upstream PR](https://github.com/sgl-project/sglang/pull/44023) · state: closed · merged: True

## Original PR description

## Motivation

Without NUMA binding, scheduler processes can drift across sockets, losing their CPU caches and touching host memory on the remote node, which adds per-step overhead and makes tail latency noisy. In a container without `SYS_NICE`, LLM serving skips binding entirely and logs `User lacks permission to set NUMA affinity, skipping NUMA node configuration for GPU`.

Only the memory-policy syscalls (`get_mempolicy` / `set_mempolicy`) are denied there; `sched_setaffinity` needs no privilege, so each rank can still be pinned to its GPU's NUMA node, and the default first-touch policy places its host memory there too. #43756 added this CPU-only fallback for the diffusion worker only; the LLM paths never opted in.

## Modifications

- `_is_numa_available()` no longer requires memory-policy permission, so a host where only CPU affinity can be set still gets bound. The `cpu_only_ok` / `require_mempolicy` opt-in is removed, so every caller gets the fallback.
- `configure_subprocess` strips the `--membind` segment before the numactl probe when memory policy is not permitted, so each rank does not log two expected rejections first.
- The `binding CPUs only` INFO line is logged where memory binding is actually skipped (the strip above, and `numa_bind_to_node`), so it also covers an explicit `--numa-node`.
- The diffusion worker call site drops the now-removed kwarg; the unit test that asserted the old skip is replaced, and the strip wiring gets a test. The diffusion CLI and env-var docs note that only CPU affinity is set without `CAP_SYS_NICE`.

Checked on 8x B300 without `SYS_NICE`: with this PR, TP0-3 are pinned to `0-85,172-257` (node 0) and TP4-7 to `86-171,258-343` (node 1); with `SGLANG_AUTO_NUMA_BIND=0` (the same no-bind path the old code took here), all ranks have affinity `0-343`. Memory placement is not enforced; `--cap-add SYS_NICE` is still needed for `--membind`.

Behavior change: with `SGLANG_CRASH_ON_NUMA_BIND_FAILURE=1`, an unprivileged pod whose allowed CPUs don't overlap the GPU's node used to start unbound (binding was skipped earlier); it now fails at launch, as the flag intends.

## Speed Tests and Profiling

`sglang serve --model-path Qwen/Qwen3-0.6B --tp-size 8` on 8x B300 without `SYS_NICE`, bound (this PR) vs unbound (`SGLANG_AUTO_NUMA_BIND=0`). `python -m sglang.benchmark.serving`, random-ids, 256 in / 256 out, `--max-concurrency 64`, 1024 prompts, 256 warmup requests, `--flush-cache`. Mean ± stdev over 3 alternating rounds:

| metric | bound | unbound | delta |
|---|---|---|---|
| output tok/s | 23,584 ± 222 | 22,915 ± 528 | +2.9% |
| TPOT p50 (ms) | 2.35 ± 0.02 | 2.42 ± 0.06 | -2.9% |
| TPOT p99 (ms) | 2.72 ± 0.03 | 3.03 ± 0.27 | -10% |

Bound was ahead on all three metrics in each of the three rounds, and the runs were more repeatable: run-to-run spread was 2.4x lower for throughput (±222 vs ±528 tok/s) and 9x lower for TPOT p99 (±0.03 vs ±0.27 ms).
