# [Feat][GPU] cosmos3: support gpu preprocess fo v2v

[Upstream PR](https://github.com/sgl-project/sglang/pull/44182) · state: open · merged: False

## Original PR description

## Motivation

Cosmos3 V2V currently loads the full source video through ImageIO and preprocesses conditioning frames on the CPU. This PR adds targeted ACCV-Lab decoding and GPU preprocessing to reduce that overhead.

## Modifications


- Add `SGLANG_USE_COSMOS3_ACCVLAB_GPU_PREPROCESS`, disabled by default.
- Reuse the ACCV-Lab reader and request the conditioning source frames, supporting first/last selection and short-video padding.
- Consume each decoded GPU RGB buffer directly. Decoding and preprocessing remain separate functions; synchronize after processing each frame before the SDK reuses its buffer.
- Add a two-pass Triton Lanczos operator that combines resize, center crop, normalization and HWC-to-CHW conversion while matching Pillow rounding.
- Process each source frame once, then reuse the processed last frame for temporal padding.

Install the optional [ACCV-Lab video decoder](https://github.com/NVIDIA/ACCV-Lab/tree/main/packages/on_demand_video_decoder) and enable:

```bash
export SGLANG_USE_COSMOS3_ACCVLAB_GPU_PREPROCESS=1
```

## Accuracy Tests

- Passed 140 Cosmos3 unit tests, CUDA kernel tests covering 36 geometry/pattern combinations, and 9 actual-video preprocessing cases.
- GPU preprocessing matches CPU/PIL exactly for the same decoded input. The decoder-only and full GPU variants produced byte-identical videos across all 8 requests.
- ACCV-Lab and ImageIO have decoder differences; generated output PSNR against ImageIO was 29.65 dB.

## Speed Tests and Profiling

**Environment:** one H200 NVL, Intel Xeon Gold 6444Y; Python 3.12.3, Torch 2.13.0+cu130, CUDA 13.0, Triton 3.7.1. Profiling used Nsight Systems.

**Workload:** Cosmos3-Edge, official `robot_pouring.mp4` (93 frames, 1280×704). Condition on the first 5 frames; generate 45 frames at 832×480, 24 FPS, 35 steps, CFG 5, seed 42.

All offload is disabled. Each variant runs in a separate process with **1 complete warmup + 3 measured requests**, using the default conditioning cache. Guardrails are disabled. Speedups are relative to the **unoptimized ImageIO/PIL baseline**; times are means.

| Version | Video decode/load (ms) | Load speedup | Preprocess (ms) | End-to-end (s) | E2E speedup |
| --- | ---: | ---: | ---: | ---: | ---: |
| ImageIO + CPU/PIL | 378.154 | 1.000× | 940.626 | 4.410 | 1.000× |
| ACCV-Lab decode only + CPU/PIL | 11.801 | **32.045×** | 566.893 | 4.028 | **1.095×** |
| ACCV-Lab + GPU preprocessing | 7.638 | **49.509×** | 8.480 | 3.457 | **1.275×** |

The decoder-only row is an experimental ablation that retains CPU/PIL preprocessing. Its loading time includes GPU-to-CPU/PIL conversion; the full GPU path keeps frames on GPU. ImageIO loads all 93 frames before selecting the conditioning frames, while ACCV-Lab requests the 5 target frames.

Preprocess timing includes actual GPU completion and padding. End-to-end timing includes MP4 saving. The full GPU path eliminates preprocessing D2H transfers. All three runs recorded zero thermal-slowdown increments.

### GPU memory overhead

Same workload and 1-warmup/3-request protocol; values are MiB. PyTorch peaks use exact allocator counters; total device memory includes ACCV-Lab allocations and is sampled through NVML with a 5 ms target interval.

| Metric | ImageIO baseline | GPU preprocessing | Increase |
| --- | ---: | ---: | ---: |
| PyTorch allocated peak | 10768.9 | 11179.3 | +410.4 |
| PyTorch reserved peak | 12152.0 | 12358.0 | +206.0 |
| Total device peak (NVML) | 14506.9 | 14768.3 | +261.4 |

Total device peak increases by **261.4 MiB (1.8%)**: 206 MiB more PyTorch reserved memory plus approximately 55.4 MiB for ACCV-Lab. Each 45-frame float32 conditioning tensor occupies 205.66 MiB; weak-reference tracking confirmed that previous and current request tensors coexist, explaining the larger active-allocation peak.
