# [Feat] [NPU] dwdp: support DWDP on Ascend NPU

[Upstream PR](https://github.com/sgl-project/sglang/pull/40998) · state: open · merged: False

## Original PR description

## Motivation

Support `--dwdp-size` on Ascend NPU using the existing GPU DWDP algorithm: keep each rank's tokens local and prefetch peer expert weights into two reusable local buffer slots.

GPU implementation reference: https://github.com/sgl-project/sglang/pull/29778

## Modifications

- Add an ACL VMM backend with resident local expert shards, preferring FABRIC handles and falling back to ACL IPC only for a confirmed single-host launch. All ranks agree on the route; PID authorization remains enabled. ACL forbids re-exporting one physical allocation, so route detection uses a disposable probe, not the real weights.
- Reuse the original CUDA layer collector, page layout, fixed-size `PagePool`, prefix/local/suffix mapping, per-expert parameter gathering, remote expert-slice copy loop and double-buffer stream/event protocol. Keep CUDA's search scope, support predicates and operation ordering unchanged.
- Keep only platform-specific allocation, ND migration, handle export/import, raw-pointer Tensor construction and resource release in the NPU backend. Every forward copies all remote expert slices, including boundary bytes; resident local experts are not recopied.
- Accept loaded BF16/FP16 unquantized and W8A8 INT8 NPU MoE kernel/layout families. Gather per-expert scales, offsets and biases during initialization.
- Select the backend lazily, without importing CUDA transport on NPU. Preserve existing user/model shared-expert settings, common offload/memory-saver policies and graph configuration precedence. No model-specific, Attention, ordinary EP, DeepEP or FuseEP changes are included.
- Keep this PR production-only: remove both newly added test files from the final diff. Preserve the existing upstream GPU DWDP tests unchanged. The removed suite is retained locally for validation, not committed or registered in CI by this PR.
- Build each layer's peer ranges and remote slices in the existing binding pass, avoiding a separate traversal and duplicate range construction. Keep the runtime copy/event/slot protocol unchanged.
- Preserve stepwise imported-memory release bookkeeping so retries do not repeat successful unmap/address-release operations.

- FABRIC requires supported hardware, driver and topology. CANN 9.1 documents the ACL FABRIC option for Atlas A3; this PR does not claim A5 cross-host support. Same-host ACL IPC is the validated device path; real FABRIC import/map/copy and cross-host operation are still unverified.
- Existing DWDP topology restrictions remain: DWDP=TP=EP, attention DP=DWDP, MoE TP1, PP1, divisible routed-expert count. NPU supports the kernel/layout families listed above, not blanket MXFP8/MXFP4/W4/GGUF parity.
- NPU rejects LoRA and PDMux. Existing common restrictions on EPLB, speculative decoding and two-batch overlap remain unchanged. No generic shared-expert adaptation is added.
- Offload/memory-saver flags and explicit graph selectors retain their existing common policy; acceptance is **not** proof of weight pause/resume or graph capture/replay correctness. Graphs remain disabled by default.
- Imported-memory cleanup retries are tested locally. Distributed recovery after rank failure or independently retried collective cleanup is not provided.
- No Markdown, generated artifacts, model implementation or Attention backend changes are committed.
