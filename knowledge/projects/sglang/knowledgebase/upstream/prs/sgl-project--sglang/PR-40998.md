# [Feat] [NPU] Add independent Ascend DWDP with composite VMM weights

[Upstream PR](https://github.com/sgl-project/sglang/pull/40998) · state: open · merged: False

## Original PR description

## Motivation

Enable Ascend DWDP with composite VMM expert weights. Tokens stay local; each rank directly maps its resident expert shard and prefetches peer shards into two reusable local page slots.

## Implementation

- Keep an independent `NpuDwdpManager` with NPU setup, auxiliary-parameter all-gather, layer selection, copy/compute stream events and ordered teardown. There is no GPU-manager inheritance or NPU weight-manager wrapper class.
- Reuse the unchanged `PageAlignedLayout`. Composite ND tensors alias resident local pages and alternating remote-only page slots. Native ACL copies fetch remote shards on the NPU copy stream and skip the local rank; ready/consumed events protect slot reuse and batch state identifies current prefetches.
- Keep ACL allocation/mapping, V2 FABRIC metadata exchange and non-owning NPU tensor construction under `hardware_backend/npu/dwdp`. Remove composite mappings before releasing imported/source allocations.
- Keep the reduced setup checks for graphs, DCP and the VMM weight data contract. Repeated topology/feature gates, kernel allowlists, whole-model TP scans, extra layer checks and cross-rank signature checks remain removed.

## Public-code scope

Only `layers/moe/dwdp/__init__.py` changes in the public DWDP path: +10/-1 lines to select the NPU manager. Both public manager implementations are restored to main; GPU VMM, buffer, transport and page-pool implementations are unchanged.

Against main `960e30769e8af4618ca0f7a6f1d85464176d881b`: 4 files, +666/-1, net +665 lines. No test files are included.

## Validation

PR head: `8850cab2e17fcbe2e078276fdae52d5d2c0a6a0f`. The real-device test ran on `705a535688a3d82b1a540d7de2e494ab532d5cf5`. The only change between the tested commit and this head is the DWDP module docstring.

Two Ascend A3 devices on one host, CANN 9.2.0, driver 25.5.1, PyTorch 2.13.0 and torch_npu 2.13.0. The external two-rank FusedMoE test passed all six BF16/FP16/ModelSlim W8A8 INT8 × ND/NZ source cases with exact output parity against full-expert references. It checked the resident expert slice, reuse of the same slot across layers of different widths, unequal forward counts between ranks, and asserted that every prefetch read came from a peer rank.

The first launch failed to import pyACL after the test launcher replaced PYTHONPATH. Preserving the container's CANN paths resolved the issue and the full rerun passed.

The implementation requires graphs disabled, DCP1 and uniform divisible expert counts with local three-dimensional BF16/FP16/INT8 shards. A5, cross-host operation, full-model serving and throughput for this VMM revision remain untested. The performance table below reports the earlier full-buffer revision.
