# [Fix] mini-lb: Fail /health and /health_generate while a backend is down

[Upstream PR](https://github.com/sgl-project/sglang/pull/45747) · state: open · merged: False

## Original PR description

## Motivation

The PD mini load balancer's `/health` returns 200 without contacting any server. A health check on the LB therefore stays green while every prefill and decode engine is down. `/health_generate` is also blind. It returns 200 when an engine answers 503, and a bare 500 when an engine refuses the connection.

This first appeared in sglang-torchtpu (sgl-project/sglang-torchtpu#1274) and was fixed there in sgl-project/sglang-torchtpu#1576. The code is the same here. The TPU P/D recipes install `sglang-router` from PyPI, so they only get the fix once it lands in this repo.

## Modifications

- `/health` and `/health_generate` now probe every registered prefill and decode server in parallel.
  - They return 200 only if every server answers 200.
  - Otherwise they return 503 with `{"unhealthy": [{role, url, status, error}]}`.
  - A role with no registered server also returns 503. A runtime role switch can cause this briefly.
  - Probes time out after 30 s. That is above the engine's own `SGLANG_HEALTH_CHECK_TIMEOUT` (20 s by default), after which the engine answers 503 itself.
- The check is strict on purpose. MiniLB picks a backend at random and does not track health, so one dead server already fails part of the traffic. The Rust gateway's `/readiness` (any healthy prefill AND any healthy decode) fits the Rust gateway, because it skips unhealthy workers.
- New `/liveness` endpoint. It returns 200 while the LB process is up, which is the old `/health` behavior.

**Callers in this repo.** The disaggregation test fixtures (`disaggregation_fixture.py`, the Ascend/NPU PD tests, `test_mori_transfer_engine_e2e.py`, `test_tracing_disaggregation.py`) wait for every engine's `/health` before they poll the LB's `/health`. The stricter check only adds probe latency for them.

## Validation

- New `tests/test_mini_lb_health.py`. It serves real aiohttp backends that answer 200 or 503/500, refuse connections, or hang. It also covers a role with no registered server, `/liveness`, and route registration.
- `pytest tests` with `--cov-fail-under=80`: the coverage gate passes at 87.75%. `mini_lb.py` is omitted from coverage by `.coveragerc`.
  - I used this tree's Python sources with the Rust extension from the PyPI 0.3.2 wheel. That mismatch fails 13 `test_pyo3_binding.py` cases, both with and without this change.
  - In sglang-torchtpu CI, where the wheel is built from source, the same suite gave 128 passed.
- End to end through `python -m sglang_router.launch_router --pd-disaggregation --mini-lb`, with stand-in prefill and decode servers in separate processes:

| Scenario | Endpoint | Before | After |
|---|---|---|---|
| all up | `/health`, `/health_generate`, `/generate` | 200 | 200 |
| decode answers 503 | `/health` / `/health_generate` | 200 / 200 | 503 / 503, decode listed |
| decode killed | `/health` / `/health_generate` | 200 / 500 | 503 / 503, decode listed |
| both killed | `/health` / `/health_generate` | 200 / 500 | 503 / 503, both listed |
| any | `/liveness` | 404 | 200 |
