# [AMD] Use the preallocated EAGLE topk=1 draft chain on HIP

[Upstream PR](https://github.com/sgl-project/sglang/pull/43640) · state: closed · merged: True

## Original PR description

## Motivation

`EagleDraftWorker.draft_forward` writes the topk=1 draft chain straight into the preallocated parents/indices buffers only when `_is_cuda`. HIP already runs the Triton `draft_topk1_postprocess` kernel that fills those columns (#35872), but the gate still sends it through the token-list path: the eager `_select_top_k_tokens_first` (with `repeat_interleave`) on step 0, the compiled `_select_top_k_tokens_later` on each later step, and a final `cat`.

## Modifications

- Take the preallocated chain on `_is_cuda or _is_hip`. The other conditions (topk 1, batch fits the buffers, no `hot_token_id`, no draft probs) are unchanged, so EAGLE3 token maps and non-greedy batches under rejection sampling keep the token-list path.

## Accuracy Tests

Bit-exact: the same Triton argmax runs per step and the chain buffers hold what the `cat` path builds. On MI355X, `test_eagle_worker_v2_topk1_fastpath.py` passes 11 tests and 7 subtests, and `test_spec_topk1.py` passes 6 tests and 12 subtests. A draft-forward probe at GLM-5.3 shapes (vocab 154880, hidden 6144, 5 steps) gives `torch.equal` outputs at bs 1-64.

## Speed Tests and Profiling

Same probe with the draft model stubbed out, so only the draft glue is measured. Kernels per draft cycle drop from 27 to 9 at every batch size. HIP-graph replay per cycle (min of 5 x 200 replays):

| bs | main (us) | this PR (us) |
|---|---|---|
| 1 | 53.4 | 24.5 |
| 4 | 58.2 | 23.5 |
| 8 | 57.8 | 26.0 |
| 32 | 72.5 | 36.9 |
| 64 | 86.5 | 47.7 |

That is about 0.25-0.3% of a GLM-5.3 TP4 decode cycle (~12 ms), too small to resolve end to end.
