# fix: sanitize profiler filename components to prevent path traversal

[Upstream PR](https://github.com/sgl-project/sglang/pull/44201) · state: closed · merged: False

## Original PR description

## Background

Fixes #44189

## Problem

The `/start_profile` endpoint accepts caller-controlled `profile_prefix` and `profile_id`. These were used directly to construct trace filenames without sanitizing path separators. A relative `profile_prefix` containing `..` or an absolute `profile_prefix` could let the caller escape the requested `output_dir`.

## Fix

Added `_sanitize_filename_component()` helper that:
- Uses `os.path.basename()` to strip any directory component
- Replaces path separators and `..` sequences with underscores
- Filters out other potentially dangerous characters

Applied sanitization to both `profile_prefix` and `profile_id` in:
- `profiler_manager.py` (V1 profiler / `SchedulerProfilerManager._init_profile`)
- `profile_utils.py` (V2 profiler / `ProfileManager.configure`)

## Test

```python
sanitize("../escaped")           # -> "escaped"
sanitize("/etc/passwd/escaped")  # -> "escaped"  
sanitize("../../etc/malicious")   # -> "malicious"
sanitize("my-profile-id")         # -> "my-profile-id"  (normal case preserved)
```
