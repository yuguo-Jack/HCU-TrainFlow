# [Performance] Cap SWA windows per radix path with --swa-max-states-per-path

[Upstream PR](https://github.com/sgl-project/sglang/pull/39694) · state: open · merged: False

## Original PR description

## Summary

For hybrid SWA models such as DeepSeek-V4 served with the Mooncake unified-cache external linker, **cap SWA windows per radix path** with a new `--swa-max-states-per-path`, the SWA counterpart of `--mamba-max-states-per-path`. Every prefill chunk boundary leaves a live sliding window in the radix tree, and the linker persists all of them on write-through, so most stored SWA bytes are never matched again. With the cap, the shallowest interior windows beyond it are tombstoned after each insert (tail, fork, locked and pending-write nodes are kept; full KV is untouched), so the external store receives only the surviving windows. It reuses the Mamba per-path cap walk and runs on the Python TreeCore, which a positive cap selects through the existing Rust fallback policy. Default `-1` is unchanged.

## Validation

- pre-commit passes; the mem_cache unit suites pass, plus new tests for the SWA window cap.
- DeepSeek-V4 Pro, GB300, prefill 8x DEP8 / decode 4x DEP16, Mooncake external cache, agentic trace replay at concurrency 1920, a cap of 1 on prefill:

| | total tok/s/GPU | Mooncake bytes / key | evictions | prefix hit |
|---|---|---|---|---|
| main | 123,012 / 123,061 | 0.64 MB | 10.5M | 95.2% |
| this PR | 130,044 / 128,832 / 130,835 (+5.8%) | 0.43 MB | 7.1M | 95.8% |

These runs also carried a Mooncake load-reservation change that has since been split out of this PR; it does not touch which windows are written.

## History

An earlier revision retained sparse SWA checkpoints by rewriting the linker's offload path (checkpoint range selection, mid-prefill checkpoint writes, supplementary window writes, replay-boundary plumbing). It measured best, 131,354 tok/s/GPU (+6.8%) on the same setup, but touched 11 files and only worked on the Python TreeCore, so it is reverted in this PR in favour of the per-path cap above, which keeps most of the gain with a fraction of the code. The revision before that bundled six changes; ablation on this workload showed no measurable gain from per-request chunk caps, deferred partial transfers, pipelined lookups or batched puts, so they were dropped. Decode capacity moved to #40153 and batched puts remain in #39696.

[by Claude Code] **Severity: perf | Confidence: Medium**

**Issue**

The cap counts SWA nodes, not windows. A tail shorter than `sliding_window_size` needs SWA from its parent. If the inserting request has no lock on that parent, this walk tombstones it. The tail's window is then incomplete, so `match_prefix` cannot stop anywhere on the path.

**Example**

CPU run, page_size=1, window=4, cap=1: insert [0, 12) (evicted seqlen 8), then insert [0, 14) (evicted seqlen 10) with no lock, as when both requests run in one batch. `match_prefix([0, 14))` returns 0 tokens. With cap=-1 it returns 14. DeepSeek-V4 is not affected because its 256-token page covers a window.

**Fix**

Skip nodes within `sliding_window_size` tokens of the tail in this walk, and add this case as a test.

- nvpohanh · comment · 2026-10-12T08:05:34Z · [source](https://github.com/sgl-project/sglang/pull/39694#discussion_r4245843783)

File: `python/sglang/srt/mem_cache/unified_cache/components/swa.py` · line None

[by Claude Code] **Severity: perf | Confidence: Medium**

**Issue**

This guard keeps nodes within `sliding_window_size` tokens of the tail end. The scheduler matches at most `input_len - 1` tokens, page-aligned down, so an exact repeat of a cached input stops one page before the tail end. That match needs SWA from `sliding_window_size + page_size` tokens back. The cap can tombstone it, so the repeat matches 0 tokens.

**Example**

page_size=1, window=4, cap=1: insert [0, 10) with evicted seqlen 4, then match [0, 9). Both TreeCores return 0 tokens; cap=-1 returns 9. page_size=4, window=2 fails the same way for a page-aligned input. Parallel sampling (n > 1) sends such repeats.

**Fix**

Protect `sliding_window_size + page_size` tokens (the span `_inc_session_coverage` uses) here and in `swa.rs`, and add this case as a test.
