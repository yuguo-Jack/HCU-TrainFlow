# [Fix] megamoe: Count the DP-attention chunk once in the token budget check

[Upstream PR](https://github.com/sgl-project/sglang/pull/46198) · state: closed · merged: False

## Original PR description

Under DP attention, `validate_mega_moe_token_budget` divides `chunked_prefill_size` by `attn_dp_size`, but by the time it runs `handle_data_parallelism` has already turned it into the per-rank chunk. The check therefore sees a chunk `attn_dp_size` times too small: with DP 4, `--chunked-prefill-size 131072` (32,768 tokens per rank) passes a 16,384 cap at startup, and the first long prefill then falls back to the Triton fused MoE, which cannot run the repacked MegaMoE experts and asserts in `invoke_fused_moe_kernel`.

- `mega_moe_hook.py`: under DP attention, use the per-rank chunk as is. Such configurations now fail at startup with the existing message naming the required `SGLANG_OPT_DEEPGEMM_MEGA_MOE_NUM_MAX_TOKENS_PER_RANK`. The CP and pure-TP branches are unchanged.
- `test_server_args.py`: runs `handle_data_parallelism` then the check (TP 4, attention DP 4, chunk 131072): a 16,384 cap raises with `required_per_rank=32768`, a 32,768 cap passes. It fails without the fix.

## Verification

- DeepSeek-V4.1-Flash DEP4 on GB300 with MegaMoE: before, a 40K-token prompt crashed every rank at the first 32,768-token chunk; after, the same launch stops at startup with the token-budget error, and with the cap raised to 32,768 the prompt runs through MegaMoE. A configuration that already fit (chunk 65536, cap 16384) starts as before and scores the same on GSM8K.
