# Keep code fences in streamed DeepSeek-V3 answers when tools are set

[Upstream PR](https://github.com/sgl-project/sglang/pull/43393) · state: open · merged: False

## Original PR description

## Motivation

With `--tool-call-parser deepseekv3` and `tools` in the request, a streamed answer loses every ``` in its normal content, while the same answer without streaming keeps them. Code blocks in DeepSeek-V3, V3-0324 and R1-0528 answers arrive at the client as bare text: `json\n{...}\n` instead of a fenced block. Clients that send tools and stream, as most coding agents do, hit this on every answer that contains code. `--tool-call-parser auto` also picks `deepseekv3` for these templates.

`DeepSeekV3Detector.parse_streaming_increment` strips `"```"` from any text that has no tool-call marker (`deepseekv3_detector.py:104`). `detect_and_parse` (non-streaming) does not strip it, and `DeepSeekV31Detector` leaves fences alone in the same branch.

Repro (one token per delta, the default `--stream-interval 1`):

```
non-stream: 'Here is an example:\n```json\n{"a": 1, "b": [2]}\n```\nDone.'
stream    : 'Here is an example:\njson\n{"a": 1, "b": [2]}\n\nDone.'
```

## Modifications

- `deepseekv3_detector.py`: stop removing `"```"` from normal text in `parse_streaming_increment`. The EOS and `<｜tool▁call▁end｜>` tokens are still removed.
- Why the strip existed: `"```"` was added in #5592, when the partial call regex did not require the closing fence and the buffer was cleared before the fence arrived. #7562 made the regex require the closing fence, so since then the strip has only removed fences from user answers.
- The fences around tool-call arguments never reach this branch: the call regex needs the closing fence before it matches, and the completed call is then cut from the buffer. This change does not alter tool-call output; the only difference from main is the restored fences in prose.
- Three unit tests in `TestDeepSeekV3Detector`:
  - a fenced prose answer streamed token by token matches the non-streaming result;
  - a fenced answer followed by a tool call keeps the fence and still parses the call and its arguments;
  - a multi-token delta carrying the closing fence and `<｜tool▁call▁end｜>` (as with MTP or `--stream-interval` above 1) adds no normal text.
