# [Feat] diffusion/disaggregation: Split FLUX.3 prompt and image encoders

[Upstream PR](https://github.com/sgl-project/sglang/pull/45309) · state: closed · merged: True

## Original PR description

## Motivation

Deploy FLUX.3 Image's prompt encoder, reference-image encoder, DiT, and decoder independently, with a separate worker pool for each role, while keeping the existing image API and transfer protocol.

## Modifications

- Add `prompt_encoder` and `image_encoder` roles and head URL flags. T2I bypasses image encoding; image edits traverse all four pools.
- Load only the components owned by each worker. Preserve the combined `encoder` topology and monolithic pipeline.
- Transfer nested FLUX.3 conditioning tensors through the existing codec, preserving model-specific sampling parameters, explicit dimensions, and crop metadata.
- Track transfer ownership explicitly, reclaim scheduling slots, ignore duplicate transfer notifications, and avoid sending encoding payloads to the decoder.
- Inline head-local uploads for remote image workers and redact inline media in request logs.
- Update the deployment guide, CLI reference, and FLUX.3 cookbook, including ports, pool sizing, request examples, and validation limits.

## Accuracy Tests

Remote validation with the official BF16 FLUX.3 Image Klein package on 3 H200 GPUs, same-node multi-process Mooncake RDMA, `quality=exact`:

- Four-role topology on the PR head: concurrent fixed-seed 1024x1024 / 16-step T2I and multipart image editing; returned image pixels match the monolithic API exactly. Edits retain the 247x239 reference size.
- Combined three-role topology: 1024x1024 / 16-step T2I and reference-size-preserving editing also match monolithic outputs exactly.
- Relevant unit tests: 113 passed and 17 subtests passed, covering nested tensor transport, sampling semantics, real ZMQ orchestration, slot reuse, duplicate messages, and error propagation.

Pre-commit passes. The three changed MDX pages compile. Full-site Mintlify validation is blocked by an unchanged syntax error in `docs/src/snippets/configs/popular-models.jsx`, also present on main.

## Speed Tests and Profiling

No latency or throughput speedup is claimed. Separation adds transfer hops and enables independent placement and scaling. Cross-node execution has not been validated. This PR does not add a standalone training encoder API.
