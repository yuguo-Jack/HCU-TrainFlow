# [Fix] openai: Reject unk_token_id and colliding IDs in serving_rerank._get_yes_no_token_ids

[Upstream PR](https://github.com/sgl-project/sglang/pull/47427) · state: open · merged: False

## Original PR description

## Motivation

In `python/sglang/srt/entrypoints/openai/serving_rerank.py`, `_get_yes_no_token_ids(tokenizer)` dynamically resolves the token IDs for `"yes"` and `"no"` via:
1. `tokenizer.encode("yes", add_special_tokens=False)` / `tokenizer.encode("no", add_special_tokens=False)`, checking only `len(yes_tokens) == 1 and len(no_tokens) == 1`.
2. `tokenizer.convert_tokens_to_ids("yes")` / `tokenizer.convert_tokens_to_ids("no")`, checking only `yes_id is not None and no_id is not None`.

In HuggingFace tokenizers (`PreTrainedTokenizerBase`), `convert_tokens_to_ids(token)` returns `tokenizer.unk_token_id` (an `int`, not `None`) when a token is not in the vocabulary (for example when word-initial tokens are stored as `"Ġyes"` / `"▁yes"`), and `encode(..., add_special_tokens=False)` can likewise return `[unk_token_id]`.

Accepting `unk_token_id` or colliding IDs (`yes_id == no_id`) skips the warning and `(9693, 2152)` fallback, causing:
- `_handle_text_reranker_request` to pass `label_token_ids=[unk_id, unk_id]` to `score_prompts`, yielding `p_yes == p_no` (`score = 0.5`) for every document.
- `_extract_score_from_logprobs` to never populate `p_no` because `elif token_id == self._no_token_id:` is unreachable when `self._yes_token_id == self._no_token_id`.

## Modifications

- Validate in `_get_yes_no_token_ids` that resolved `(yes_id, no_id)` are distinct non-negative `int`s and neither equals `tokenizer.unk_token_id` before returning them from either `encode()` or `convert_tokens_to_ids()`.
- Add unit tests in `test/registered/prefill_only/test_serving_rerank.py` (`test_helper_get_yes_no_token_ids_rejects_unk_and_duplicates`).
