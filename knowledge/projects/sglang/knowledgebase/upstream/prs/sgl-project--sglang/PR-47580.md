# Fix #47213: Prevent decode checkpoint reuse in deterministic mode

[Upstream PR](https://github.com/sgl-project/sglang/pull/47580) · state: open · merged: False

## Original PR description

## Summary

Fix non-deterministic logprobs when prefix cache is reused across requests in deterministic inference mode with mamba extra buffer.

## Problem

With deterministic inference enabled, Qwen3.5-9B (and other GDN/SSM models) returned different logprobs for identical requests depending on whether an earlier request had populated the prefix cache. The issue:

1. Decode-produced recurrent states were being saved to the cache
2. These states were reused by subsequent requests
3. However, decode-produced states are **not numerically identical** to prefill-produced states for the same token prefix
4. This caused different logprobs even though the generated tokens were identical

The root cause is that floating-point computations in decode mode (one token at a time) differ from prefill mode (chunked processing), making their states incompatible for deterministic reuse.

## Solution

In deterministic inference mode with mamba extra buffer enabled, prevent Decode from overwriting or advancing the reusable Prefill checkpoint by:

1. Disabling tracking masks (`mamba_track_mask_cpu` and `mamba_track_mask_next_cpu`)
2. Disabling lazy checkpoint preallocation at boundaries

This ensures that only prefill-produced checkpoints are reused, maintaining deterministic logprobs across requests.

**Key changes in `prepare_for_decode` method:**
- Check `enable_deterministic_inference` flag
- When True: set tracking masks to all-False, skip lazy preallocation
- When False: preserve original behavior (normal cache reuse)

## Testing

- Syntax validation passed
- Normal generation continues unaffected
- Only cache reuse behavior changes in deterministic mode
- Prefill-produced checkpoints remain reusable
- Note: Full validation requires GPU with mamba extra buffer support

## Impact

- Fixes non-deterministic logprobs in deterministic inference mode
- Minimal performance impact (only affects cache behavior)
- No breaking changes to API
- Normal (non-deterministic) mode unchanged

- duerwuyi · comment · 2026-10-31T15:45:08Z · [source](https://github.com/sgl-project/sglang/pull/47580#issuecomment-6545582362)

Thanks for working on #47213. The checkpoint policy matches the intended fix, but I noticed two implementation issues in `prepare_for_decode` at `03be2f3`.

### 1. `track_mask_cpu` must remain a Tensor

Both branches now assign a Python list to the local variable:

```python
if deterministic_mode:
    track_mask_cpu = [False] * len(self.seq_lens_cpu)
else:
    track_remainders_cpu = self.seq_lens_cpu % mamba_track_interval
    track_mask_cpu = (track_remainders_cpu == 0).tolist()
```

However, the unchanged code below still does:

```python
self.mamba_track_mask = track_mask_cpu.pin_memory().to(
    device=self.device, non_blocking=True
)
```

This raises:

```text
AttributeError: 'list' object has no attribute 'pin_memory'
```

when this extra-buffer Decode path is reached. **It affects both deterministic and ordinary mode**, because both branches produce a list.

The original code intentionally kept two representations: the local `track_mask_cpu` was a CPU boolean Tensor for the device transfer, while `self.mamba_track_mask_cpu` was its Python-list representation. Syntax validation alone will not catch this regression.

### 2. Keep `mamba_track_mask_next_cpu=None` when overlap is disabled

The new nested conditional effectively groups as:

```python
false_list if deterministic_mode else (
    boundary_list if self.enable_overlap else None
)
```

Consequently, `deterministic_mode=True` and `enable_overlap=False` produces an all-False list instead of the previous `None`.

This is separate from the blocking type error above: it changes the existing field convention, but I am not claiming an independently demonstrated inference failure from this difference alone.

### Suggested adjustment

Keep the mask computation tensor-valued, and apply the overlap condition to the entire next-mask expression:

```python
track_decode = not deterministic_mode
track_remainders_cpu = self.seq_lens_cpu % mamba_track_interval

track_mask_cpu = (track_remainders_cpu == 0) & track_decode
self.mamba_track_mask_cpu = track_mask_cpu.tolist()

self.mamba_track_mask_next_cpu = (
    (
        (track_remainders_cpu == mamba_track_interval - 1)
        & track_decode
    ).tolist()
    if self.enable_overlap
    else None
)
```

The existing change to skip lazy checkpoint preallocation in deterministic mode can remain. The later `track_mask_cpu.pin_memory().to(...)` then continues to receive a Tensor.

Could you also add regression coverage for deterministic on/off, overlap on/off, and lazy preallocation on/off? In particular, it should check that the local mask remains a boolean Tensor, non-overlap keeps the next mask as `None`, deterministic Decode does not advance the reusable checkpoint, and ordinary-mode tracking remains unchanged.

After those changes, the two-request reproducer in #47213 and the ordinary Prefill cache-reuse control should be rerun on this PR head. The earlier GPU results in the Issue validate the attached candidate implementation; they should not be treated as validation of this rewritten version.
