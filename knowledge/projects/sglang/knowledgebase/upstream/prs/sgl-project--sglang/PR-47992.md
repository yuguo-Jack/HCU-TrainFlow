# [CI] lint: Reject importing a name through a module that only re-imports it

[Upstream PR](https://github.com/sgl-project/sglang/pull/47992) · state: closed · merged: True

## Original PR description

- Add `scripts/lint/check_indirect_imports.py` as the `check-indirect-imports` pre-commit hook. It rejects `from sglang.a import f` when `sglang/a.py` does not define `f` but only imports it, and names the module that `sglang.a` imports `f` from.
- A module still exports an imported name when it says so: the name is in its literal `__all__`, it imports it as `f as f`, it is a package `__init__.py`, or it binds the name inside an `if` / `try` (the module that picks an implementation per platform or as a fallback). Relative imports are resolved and checked like absolute ones, not rejected.
- The hook checks the changed files on each commit and the whole tree under `pre-commit run --all-files`, which the lint workflow runs.
- Fix the ten imports the check flags on main: choice lists read through `server_args` now come from `sglang.srt.arg_groups.choices` (`server_args` keeps its public block for plugins), and two tests take `get_tokenizer` from `sglang.benchmark.utils`.

No behavior change.
