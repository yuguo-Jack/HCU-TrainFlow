# [Fix] [AMD] dsv4.1: Fix the V4.1 k-norm-rope store build on ROCm 10

[Upstream PR](https://github.com/sgl-project/sglang/pull/46236) · state: closed · merged: True

## Original PR description

## Motivation

sgl-project/sglang#45934 added a warp-per-token V4.1 kernel to `main_norm_rope.cuh` whose two reductions shuffle with `__shfl_xor_sync(0xffffffffu, ...)`. ROCm 10's HIP headers `static_assert` a 64-bit mask (wave64), so the V4.1 fused k-norm-rope store (`fused_k_norm_rope_flashmla`, V41 layout) no longer builds on gfx950.

Every PR's `stage-b-test-1-gpu-small-amd-mi35x` shard 1 has failed on `test_v41_kv_store.py` since then, for example [on sgl-project/sglang#46151](https://github.com/sgl-project/sglang/actions/runs/40030122510/job/120684541903). #45934's own AMD run was cancelled before that stage ran.

```
main_norm_rope.cuh:513:18: note: in instantiation of function template specialization '__shfl_xor_sync<unsigned int, float>' requested here
amd_warp_sync_functions.h:307:62: error: static assertion failed due to requirement 'sizeof(unsigned int) == 8': The mask must be a 64-bit integer.
RuntimeError: Failed to build JIT module sgl_kernel_jit_dpsk_v4_main_k_norm_rope_flashmla_bf16_t_512_64_256_V41_false
```

A 64-bit full mask builds but is wrong:
- HIP's `__shfl_xor_sync` traps unless every lane its mask names is active.
- This kernel returns per 32-lane warp, so an odd token count leaves half of the last wave64 idle.
- With that mask, 2049, 4097 and 4099 tokens crash with `HSA_STATUS_ERROR_EXCEPTION`.

## Modifications

- The two reductions call `shfl_xor_in_warp`, a forced-inline helper.
  - On CUDA it is main's `__shfl_xor_sync(0xffffffffu, v, mask)`, so CUDA compiles the same code as main.
  - On HIP it is the mask-free `__shfl_xor`, as `warp::reduce` already uses on HIP.
  - The loops and the reduction tree are unchanged. `kWarpThreads` is 32 on HIP too, so each 32-lane half of a wave64 holds one token, and every xor mask (2, 1, 16, 8, 4) stays inside it.
- `test_v41_kv_store.py`'s warp-per-token case takes 4097 tokens instead of 4096, so the last wave64 runs half idle.

## Accuracy Tests

MI350X (gfx950), ROCm 10.0.0, this branch on main 3c6a6c80:

- `test/registered/kernels/ops/attention/dsv4/test_v41_kv_store.py`: 8 passed.
  - On main it fails to build with the error above.
  - With a 64-bit full mask instead, its 4097-token case traps.
- The fused k-norm-rope store check at 2049, 4097, 4099 and 4100 tokens: bitwise equal to the unfused kernel chain.
- The other AMD-registered tests that build `main_norm_rope.cuh`:
  - `test_hip_flash_mla_aiter_sparse.py`: 7 passed;
  - `test_swapab_attention.py`: 5 passed, 2 skipped;
  - `test_dsv4_q_rope_store.py`: 4 passed;
  - `test_minimax_m3_qk_norm_rope.py`: 24 passed.

Not executed:
- CUDA: no CUDA toolchain here. Instead, expanding the helper's CUDA branch at its two call sites and dropping the helper reproduces main's `main_norm_rope.cuh` byte for byte.
- pre-commit: its hooks are not cached on this box. Every changed line is under the 120-column clang-format limit.
