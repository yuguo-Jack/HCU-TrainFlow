# [Chore] deps: Add nvidia-cuda-tileiras for the optional cuTile router

[Upstream PR](https://github.com/sgl-project/sglang/pull/45290) · state: open · merged: False

## Original PR description

## Motivation

#45361 makes the cuTile BF16x3 router GEMM Beam's default router on Hopper and SM10x Blackwell. `cuda-tile` comes in through `flashinfer-python` (`cuda-tile>=1.4.0`), but it compiles its kernels with the `tileiras` compiler. The CUDA 13.0 toolkit in the release image doesn't ship `tileiras`, and no current dependency installs it. Without it, a Beam server fails during prefill CUDA-graph capture on every TP rank with `FileNotFoundError: 'tileiras' compiler not found`.

Split out of #44747 so the dependency can be reviewed on its own. Merge it right before #45361, and only if #45361 lands.

## Modifications

Adds `nvidia-cuda-tileiras==13.4.92` to `python/pyproject.toml`. Validation used `tileiras`, `nvidia-cuda-nvcc` and `nvidia-nvvm` 13.4.92, which must share their major.minor.

## Validation

- Synced with main: the branches fast-forward from their previous heads and merge into main `b57b5e2286` without conflicts (#45257 merges that main, which includes #40478; the others are on `6efdd33d07`).
- No upstream code is copied into the stack any more. The cherry-picks of #42930, #43168 and #43170 (merged), #43169 (closed) and #43216 (open) are reverted, and #40479 and #43941 come in as merges of those PRs in #45257 (#40478 has since merged into main).
- On 4×GB300 with the public `reflection/Beam-1.0-501B-A23B-NVFP4` checkpoint and the cookbook GB300 NVFP4 low-latency recipe, serving main `6efdd33d07` + #43216, #40478, #43941 and #40479 + this stack:
  - With #45290 and #45361: GSM8K 96.44–96.59% over three server runs (sgl-eval 0.1.3, 1,319 questions, temperature 0), with zero request errors. Chat reasoning, streaming, a chat tool call, Responses text, a Responses function call, a full Responses shell round trip and `/tokenize` all pass. A profiler trace shows the cuTile router kernel running.
  - Without #45290 and #45361: GSM8K 96.51% in both of two server runs, with zero request errors, and the same checks pass.
- The Beam E2E test in #45257 passes on two 4×GB300 nodes (prefill TP4 on one, decode TP4 on the other, Mooncake over multi-node NVLink, in place of the test's single-node 8-GPU layout): GSM8K 96.51–96.89% at temperature 0.7 over three runs, decode accept length 4.53–4.55, and single-request accept length 4.92 at about 750 tok/s.
- Main's existing GPU tests for the code the stack changes pass unedited on GB300: TRT-LLM MHA (dense, graph metadata, encoder-only, stride parity), SWA FlashInfer, tiny GEMM, collectives, Triton MoE and the DFlash buffer and kernel tests. pre-commit passes.
- Earlier #44747 validation showed the startup failure with this dependency removed, on both 4×GB300 (BF16, TP4) and 8×H200 (FP8, TP8); that removal experiment was not repeated in this sync.

## Merge order

Each part is based on the one before it, so its diff shows only its own changes. Merge bottom-up; after each part merges, the next part is retargeted to `main` and `main` is merged into it. #44747 stays open, unchanged, as the full reference. Merge in this order:

1. #45253 — Beam CUDA Docker image (merged)
2. #45291 — OpenAI SDK 2.8.0, needed by the Responses shell tools in #45257 (merged)
3. #45254 — Kernels
4. #45256 — Attention, memory and DFlash DP support, and the Beam model (#45255 folded in; also after #43216)
5. #45257 — Beam reasoning, tool calls, response templates and the Beam E2E test (also after #43941 and #40479; #40478 is merged)
6. #45290 — `nvidia-cuda-tileiras`, needed by #45361
7. #45361 — cuTile BF16x3 router GEMM (optional: without it Beam uses the cuBLAS router)

#45292 (Dynamo and `grpcio-tools` pins for the Beam image) is not in the merge order for now.
