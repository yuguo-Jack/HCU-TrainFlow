# [Perf] function_call: Avoid O(N^2) regex backtracking and buffer reslicing in GLM4/Ling3 streaming parsers

[Upstream PR](https://github.com/sgl-project/sglang/pull/45127) · state: open · merged: False

## Original PR description

## Motivation

In `Glm4MoeDetector` (`glm4_moe_detector.py`), `Ling3Detector` (`ling3_detector.py`), and `Glm47MoeDetector` (`glm47_moe_detector.py`), `parse_streaming_increment` previously incurred `O(N)` work per streaming chunk (`O(N^2)` across a tool-call stream):

1. Every chunk executed a full-buffer `re.DOTALL` regex from index `0` (`_STREAMING_PARTIAL_PATTERN.search(current_text)` in `Glm4MoeDetector` / `Ling3Detector`, and `re.search(r"<tool_call>(.*?)(?:(<arg_key.*?))?(?:(</tool_call>)|$)", current_text, re.DOTALL)` in `Glm47MoeDetector`), causing the lazy `(.*?)` quantifier before `(</tool_call>|$)` to step character-by-character across the entire accumulated tool call body while `</tool_call>` was not yet present.
2. Every chunk extracted and `.strip()`-copied the full `func_args_raw` string from the beginning of the argument block before slicing `func_args_raw[self._streamed_raw_length :]`.
3. Inside `_process_xml_to_json_streaming`, `StreamState.IN_VALUE` iterated character-by-character and invoked `json.dumps(content, ensure_ascii=False)[1:-1]` on every single character even when the incoming chunk contained no `<` character.

When streaming a single 65 KB tool call (such as code generation or file writing) in 16-char chunks, `Glm4MoeDetector` spent **4,854.5 ms** and `Glm47MoeDetector` spent **7,881.2 ms** in CPU parsing on the serving loop.

## Modifications

- Cache the parsed function name (`_cached_func_name`) and argument start offset (`_args_start_pos` / `_arg_key_idx`) once the header delimiter arrives for the active tool call.
- Track `_eot_search_pos` across streaming chunks so `current_text.find(self.eot_token, ...)` only scans newly arrived bytes (`O(len(new_text))`).
- Compute the stripped argument bounds `[content_start, content_end)` in place without copying `current_text[args_start:args_end]`, slicing only the newly arrived `raw_increment = current_text[content_start + self._streamed_raw_length : content_end]` on each chunk and materializing `func_args_raw` once when `</tool_call>` completes the call.
- Add a chunk-level fast path at the top of `_process_xml_to_json_streaming` when `self._stream_state == StreamState.IN_VALUE`, `not self._xml_tag_buffer`, and `"<" not in raw_increment`.
- Add streaming regression tests to `TestGlm4MoeDetector` and `TestGlm47MoeDetector` in `test/registered/unit/function_call/test_function_call_parser.py`.
