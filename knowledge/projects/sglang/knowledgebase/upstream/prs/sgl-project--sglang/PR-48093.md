# [Perf] [AMD] dsv4: Cut HIP prefill and verify host overhead

[Upstream PR](https://github.com/sgl-project/sglang/pull/48093) · state: open · merged: False

## Original PR description

On gfx1250:
- build the unified-KV prefill metadata once per forward instead of per layer
- reuse the interleave CP gather index and skip the pad copy
- store the verify kv from the strided `qkv_a` slice without a copy

<!-- results -->
### Accuracy
GSM8K (200 questions, greedy), DeepSeek-V4-Pro: TP4 0.975.

### Performance
Setup:
- Model: DeepSeek-V4-Pro, BF16 KV cache, DSPARK speculative decoding (block 6, 1 step)
- Parallelism: TP4 (`--tp 4`, CP prefill + CP decode attention)
- Step time: torch profiler on rank 0, GPU time per step; decode = 8 steps at 4 running requests (VERIFY = target verify, DRAFT = DSPARK draft), prefill = one EXTEND step of an ~8k-token prompt (TP4) / 4k (EP4)
- Comparison: with vs without this PR, same image and node, all earlier PRs of the series applied

Profiler step time (without -> with):

| step | without | with | change |
|---|---|---|---|
| decode VERIFY | 15.65 ms | 15.71 ms | +0.4% |
| decode DRAFT | 1.82 ms | 1.83 ms | +0.3% |
| prefill EXTEND | 183.0 ms | 160.7 ms | -12.2% |

Serving (`python -m sglang.bench_serving --backend sglang --dataset-name random --random-range-ratio 1`, fresh random prompts):

| input/output, concurrency, prompts | output tok/s | mean TTFT (ms) | mean TPOT (ms) |
|---|---|---|---|
