# [Fix] dsv4.1: Route image tokens with the VL bias on all-to-all MoE backends

[Upstream PR](https://github.com/sgl-project/sglang/pull/47079) · state: closed · merged: False

## Original PR description

## Motivation

DeepSeek-V4.1 routes tokens inside an image span with a second correction bias. The reference `Gate` selects experts on `sqrtsoftplus(logits) + bias_vl` for those tokens and on `sqrtsoftplus(logits) + bias` for text. Weights come from the unbiased scores in both cases. In SGLang this is `DeepseekV2Gate.e_score_correction_bias_vl` plus `vision_topk` (`multimodal/dsv41/vl_routing.py`).

`DeepseekV2MoE.forward` computes `use_vision_topk` (`deepseek_v2.py:1075`) and passes it to `forward_normal` and `forward_normal_dual_stream`. It does not pass it to `forward_deepep` (`deepseek_v2.py:1128`). `forward_deepep` always routes with `self.topk(...)` (`deepseek_v2.py:1567`), which applies only the text bias. The MegaMoE fallback calls `vision_topk` itself (`mega_moe.py:373`), so MegaMoE is not affected.

`forward_deepep` serves every backend in `_enable_a2a_moe`: `deepep`, `deepep_v2`, `mooncake`, `nixl`, `mori`, `ascend_fuseep`, `flashinfer` and `ascend_ops`.

**Impact**

- DeepSeek-V4.1 with images and one of the a2a backends above: every image token picks its experts with the text bias. Text tokens are not affected.
- The documented V4.1 recipes use `--moe-a2a-backend none` or `megamoe`, and the V4.1 e2e tests in CI use `none`, so no CI job covers this path.
- I did not measure the effect on the real checkpoint. V4.1 does not fit on the 16 GB GPU used here, and the size of the change depends on how far `bias_vl` is from `bias` in each layer.

## Modifications

- `DeepseekV2MoE.forward`: pass `use_vision_topk` to `forward_deepep`, as it already does for `forward_normal`. That covers the HIP `batch_has_images` check too, since the flag is computed before the branch.
- `forward_deepep`: when `use_vision_topk` is set, route with `vision_topk(self, router_logits, input_ids_global)`. This is the same call as in `forward_normal`. `input_ids_global` is the row-aligned id tensor the hash layers already use on this path. `vision_topk` resolves `num_token_non_padded` and the EPLB dispatch info from the forward context, like `TopK.forward_*`.
- `vision_topk`: apply `moe.topk._apply_waterfill(...)` to its output. Every `TopK.forward_*` ends with this call (`topk.py:859,953,978,1061`), and it appends the shared-expert column when `--enable-waterfill` is on. Waterfill requires `deepep` or `megamoe` (`arg_groups/overrides.py:1609`). Without this step, the a2a vision path would drop the fused shared expert, and in dynamic mode its collectives would not match the text and empty-batch paths. The routing body moves unchanged into `_select_vision_experts`.
  - Side effect, read from the code and not run: under `megamoe` with Waterfill, the MegaMoE fallback and `forward_normal` now also append the shared expert for image batches, as their text paths already did.
- TBO (`op_select_experts`) is not changed: DeepSeek-V4.1 rejects two-batch overlap at startup (`arg_groups/deepseek_v4_hook.py:426`).

The code, the test and this description were drafted with an AI coding agent (Claude Code).

## Accuracy Tests

**GPU repro** (`repro_a2a_vision_routing.py`, attached)

The script drives `DeepseekV2MoE.forward` with `_enable_a2a_moe=True` and the real CUDA routers: `TopK.forward_cuda` for text, and `vision_topk` -> `moe_fused_gate` for images. It uses V4.1 shapes: 384 experts, top-6, `sqrtsoftplus`, `route_scale` 1.5, `image_token_id` 129264. The logits and the two biases (std 0.5) are synthetic. 512 tokens, every second one an image token. It records the `TopKOutput` that would be dispatched and compares it with the reference `Gate`.

| | text rows: expert set = reference | image rows: expert set = reference | image rows: expert set = text-bias selection |
|---|---|---|---|
| main | 256/256 | 0/256 | 256/256 |
| this PR | 256/256 | 256/256 | 0/256 |

With this PR, the largest weight difference from the reference over all rows is 8.9e-08.

Environment: torch 2.14.1+cu130, flashinfer 0.7.1, sglang-kernel 0.4.9, RTX 5070 Ti (sm_120). I first ran the repro and the tests on main at 5bb7ecc, then again on 5cc9c933, the base of this PR, with the same results.

**Unit test**

`test_a2a_vision_router_selects_image_rows_with_vl_bias` is added to `test/registered/unit/layers/moe/test_topk_routing_inputs.py` (CPU suite). It runs `DeepseekV2MoE.forward` on the a2a branch with the existing EPLB placement fixture and Waterfill enabled. The experts are replaced by a hook that records the dispatched `topk_ids`.

- On main it fails: image rows get the text experts, `[[2, 0, 4], [2, 0, 4], [2, 0, 4], [2, 0, 4]]` instead of `[[2, 0, 4], [3, 1, 4], [2, 0, 4], [3, 1, 4]]`.
- With the fix, all 26 tests in the file pass.
- With the fix but without the Waterfill call in `vision_topk`, the test fails (`[[2, 0], [3, 1], [2, 0], [3, 1]]`), so the test also covers the shared-expert column.

These related unit tests give the same result before and after the change:

`test_deepseek_v41_bcg_multimodal.py` errors on main as well: its `SimpleNamespace` layer has no `boundary_mhc_fusions`. This PR does not touch it.

**Not run**

- A multi-GPU DeepEP / Mooncake / FlashInfer-a2a server with images. The repro calls the MoE block directly on one GPU.
- MMMU-Pro or another end-to-end accuracy benchmark. V4.1 does not fit on the 16 GB GPU used here.

## Speed Tests and Profiling

Not benchmarked. On the a2a path, image batches now take `vision_topk` (one `moe_fused_gate` call) instead of `TopK.forward_cuda`. This is the router `forward_normal` already uses for the same batches. Text-only batches and models without `bias_vl` are unchanged.
