# [Perf] diffusion: Remove per-step host syncs and uploads in image models

[Upstream PR](https://github.com/sgl-project/sglang/pull/46046) · state: closed · merged: True

## Original PR description

Depends on #46045 (host-sync guards in `test/unit/host_sync_guard.py`); this branch is stacked on it.

## Motivation

Several image pipelines read device values on the host or upload constants with pageable copies inside the denoising loop, or redo request-constant work in every forward. Each such read blocks the host until the stream drains, so it cannot queue the next step while the GPU runs this one. This PR removes them model by model. All values are unchanged.

## Modifications

- **Qwen-Image** (`dits/qwen_image.py`, `pipeline_configs/qwen_image.py`, `qwen_image21.py`, `vaes/base.py`, `qwen_image_layered.py`):
  - Layered built `additional_t_cond` with a pageable `torch.tensor([0])` per CFG branch. The branches got different objects, so the DiT's modulation cache never hit on the negative branch and every step recomputed 60 blocks x 2 modulation GEMMs. Both branches now share one device tensor.
  - Batched prompts of different lengths rebuilt their varlen metadata every forward, uploading the lengths from pageable memory (a sync per step and branch). The metadata is cached by its lengths; each forward gets a fresh dict, since attention may memoize into it.
  - Layered's condition-image encode, the channel-wise VAE stats helper (Qwen-Image edit encode/decode, Krea-2, JoyImage) and Qwen-Image-2.1 decode uploaded latent mean/std per request; they are uploaded once per (device, dtype).
- **FLUX.3 Action** (`flux3_action.py`): `cosmos_unipc` called `float(tick)` on each device tick, a sync per step. The ticks are copied to the host once per request; each step still gets the same device tick.
- **Ideogram-4** (`dits/ideogram.py`, `model_specific_stages/ideogram.py`, `progressive_resolution/ideogram.py`): every forward cast the (B, T+I, 53248) fp32 LLM features to bf16, masked them and ran the RMSNorm and the 53248 -> 4608 projection (plus its TP all-gather) on inputs that never change within a request. The stage projects each branch's conditioning on its first step, inside that step's forward context, and passes it to later steps as `llm_cond`. BCG replays still pass the raw features, which their prompt padder pads; the progressive stage drops the projection when the sequence grows. Decode uploads its latent scale/shift once per (device, dtype).
- **GLM-Image** (`dits/glm_image.py`, `pipeline_configs/glm_image.py`): the eager forward dropped the unconditional branch's prior tokens with `prior_embedding[prior_token_drop] *= 0.0`, two nonzero syncs per forward. It now selects `prior_embedding * 0.0` with `torch.where` (same values, signed zeros included). Decode stats are uploaded once.
- **Krea-2** (`pipeline_configs/krea2.py`): without SP the DiT always got a key mask and ran `bool(mask.all())` every forward. The config decides once per request and passes `mask=None` for unpadded prompts, the maskless path the DiT took before.
- **HunyuanImage-3** (`hunyuan_image3_utils.py`, `hunyuan_image3/ar_stage.py`): per step, a pageable timestep upload, host-built `timestep_embedding` frequencies uploaded on every call (five calls per CFG step), `masked_select` on the request-constant image mask for the scatter and the gather, and per-step condition-timestep uploads on the edit path. Positions, device timesteps and condition timesteps are taken once per request, predictions are gathered by position, and the frequencies are uploaded once per device.
- **SenseNova-U1** (`modeling_neo_chat.py`, `modeling_fm_modules.py`): the CFG-window check compared the device timestep in Python (two syncs per step); the window is computed for the whole schedule with the same fp32 comparisons and read once. The timestep embedder's frequencies are uploaded once per device.
- **SANA** (`dits/sana.py`): every block cast the int64 prompt mask to bool; the forward casts it once.

Tests:
- `test_qwen_image_rope.py`: batched prompts of different lengths build their varlen metadata once, and the second forward matches the first bitwise.
- `test_qwen_image_layered.py`: both CFG branches share `additional_t_cond`; VAE and condition-latent stats are uploaded once.
- `test_qwen_image21.py`, `test_glm_image_dit.py`, `test_ideogram4.py`: decode stats/constants are uploaded once and reused bitwise.
- `test_flux3_action.py`: `cosmos_unipc` with `SyncOnRead` ticks matches the plain run bitwise.
- `test_ideogram4.py`: the LLM projection runs once per branch and every step matches the unprojected forward bitwise; BCG replays get the raw features. `progressive_resolution/test_progressive.py`: a resolution change drops the projection.
- `test_glm_image_dit.py`: the prior-token drop runs under `forbid_host_syncs` and equals the graph path's `masked_fill`.
- `test_krea2_pipeline_config.py`: only ragged prompts carry a key mask.
- `test_hunyuan_image3_denoise_step.py`: timestep frequencies are built once; the image-token scatter/gather runs under `forbid_host_syncs` through the precomputed positions.
- `test_sensenova_u1.py`: timestep frequencies are built once per device.
- `test_sana_dit.py`: the prompt mask is cast once per forward, output unchanged.

The model tests run their tiny DiTs on CUDA when the runner has one (the diffusion unit suite runs on an H100).

No hunk overlaps #45942, #45943, #45944, #45948, #45965, #45966, #45967, #45977, #45978, #45979 or #45987; each of them still applies on top of this branch. #45967 also uploads Qwen-Image-2.1 latent stats once, in the encoding stage; this PR covers decode, a different function.

- Ideogram-4: the denoising stage went from 3.38 s to 3.29 s; the gain is the LLM projection (and its TP all-gather) no longer running in each of the 40 forwards (20 steps x 2 CFG branches). Each run's 5 requests spread under 0.5%.
- Qwen-Image-2.1 had no per-step syncs on main, so only the per-request decode-stats upload goes away; the change is within noise.
- The per-step sync removals for GLM-Image, HunyuanImage-3, Krea-2, SenseNova-U1, Qwen-Image-Layered/batched prompts, FLUX.3 Action and SANA were not benchmarked on GPU here; their unit tests cover them.
