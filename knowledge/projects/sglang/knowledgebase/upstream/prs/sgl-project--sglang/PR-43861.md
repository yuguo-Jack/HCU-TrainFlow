# [Perf] [AMD] linear-attn: Skip the unused PP-spec compare on the GDN and KDA verify path

## Motivation

On Qwen3.5-397B-A17B-FP8 (TP4, EAGLE, MI355X), decode in the 20261008 image is 1–3% slower than the 20260929 image at batch 8 to 64. The gap is a fixed cost of about 0.4–0.6 ms per cycle, so it is largest at small batches. A 30-step profile at batch 8 shows a `compare_scalar` kernel that the old image does not have: 45 launches per cycle, about 0.34 ms, between `fused_qkvzba_split_reshape_cat` and `causal_conv1d_update`.

#### Root cause

#40001 added `select_verify_intermediate_state_indices()` for pipeline-parallel speculative decoding. The helper returns the default indices immediately unless `SGLANG_ENABLE_PP_SPEC` is on. The GDN and KDA verify paths still pass `cache_indices[: query_start_loc.shape[0] - 1] >= 0` as an argument, so Python builds that mask before the helper can discard it. Each linear-attention layer launches one compare kernel per speculative verify step, and the result is thrown away. Qwen3.5 has 45 of these layers. This recipe does not enable PP x speculative decoding.

This PR does not change the indices. It stops building the mask unless the flag is on.

## Modifications

- `gdn_backend.py`: in `GDNAttnBackend` target verify, keep `verify_intermediate_state_indices` unless `pp_spec_stable_rows_enabled()`. Only then call `select_verify_intermediate_state_indices()` with the compare. With the flag on, the call and its arguments are unchanged.
- `kda_backend.py`: the same guard. KDA is not on the Qwen3.5 path; the call site has the same eager compare.
- `qwen4_exp.py` still builds its mask before the same helper. That path is not used by Qwen3.5 and is not changed here.

## Accuracy Tests

No output change on the default path. With `SGLANG_ENABLE_PP_SPEC` unset, the helper returns `verify_intermediate_state_indices` without reading the mask, and the patched code uses that tensor directly. With the flag set, the helper is called with the same arguments as before.

No separate GSM8K run was collected for this guard.

- chuyeh · comment · 2026-10-19T05:07:53Z · [source](https://github.com/sgl-project/sglang/pull/43861#discussion_r4310498397)

File: `python/sglang/srt/layers/attention/linear/gdn_backend.py` · line 996

`self.verify_intermediate_state_indices` isn't a flag. It's just the default index table. The actual flag is `SGLANG_ENABLE_PP_SPEC` (off by default). 

Previously, we always built a mask (`cache_indices[...] >= 0`) and passed it to `select_verify_intermediate_state_indices()`. But when `SGLANG_ENABLE_PP_SPEC` is off, that function ignores the mask and just returns the default table, so the mask was a wasted GPU kernel across 45 layers per decode cycle on Qwen3.5. 

Now we only build the mask when `SGLANG_ENABLE_PP_SPEC` is on. When it's off, we use the default table directly, which is the same result as before.

And yes, it's hardware agnostic. It's just a Python-side check, nothing vendor-specific.
