# [Fix] attention: Skip the MSA-v1 QMUL4 prefill case when QMUL4 is unavailable

[Upstream PR](https://github.com/sgl-project/sglang/pull/47286) · state: closed · merged: True

## Original PR description

## Motivation

`test_minimax_m31_page_row_views.py::test_prefill_indexer_and_attention_match[True]`, added by [#46141](https://github.com/sgl-project/sglang/pull/46141) (`4991bd33ae`, the only commit on that file), fails on every PR that reaches `base-b-kernel-unit` on a runner whose CUDA Toolkit predates 13.4:

```
RuntimeError: Q8KV4 prefill attention with QMUL4 requires CUDA Toolkit 13.4 or newer; selected /usr/local/cuda-13.0 reports 13.0
```

The failure is in the test, not in serving. `MiniMaxSparseNvfp4AttnBackend.__init__` feeds `prefer_qmul4` for both the decode and the prefill plan from `msa_v1_qmul4_decode_capability()`, which already rejects a toolkit below 13.4, so the QMUL4 wrapper is only reached once that probe passes. The test hardcodes `prefer_qmul4=True` instead. The decode cases survive because their plans record `qmul4_fallback_reason` and drop to the FP8 path; the prefill wrapper JIT-builds on
first use and raises.

## Modifications

One file, +8 lines. `test_prefill_indexer_and_attention_match` calls `msa_v1_qmul4_decode_capability()` for the `prefer_qmul4=True` case and skips with the reason the probe returns. The `prefer_qmul4=False` case and both decode tests are untouched.

## Accuracy Tests

No model or kernel code changes, so no accuracy impact. On a runner with CUDA 13.4 or newer the probe passes and the case runs exactly as before; below that it now skips with `QMUL4 is unavailable: QMUL4 requires CUDA compiler >=13.4, got 13.0` instead of failing the suite. The file's fixture already skips everything off SM100/SM103.

## Speed Tests and Profiling

Not applicable.
