# [Perf] radix_cache: page-stride prefix matching and bigram boundary preservation

[Upstream PR](https://github.com/sgl-project/sglang/pull/47914) · state: open · merged: False

## Original PR description


## Motivation

In `sglang/srt/mem_cache/radix_cache.py`, `RadixKey.match_at` computes the longest common prefix between token sequences during prefix caching.

When `page_size > 1`, searching individual tokens inside fractional pages is redundant because prefix caching discards partial pages (`(matched // page_size) * page_size`).
Scanning pages linearly in Python can introduce loop overhead on long sequences.
Additionally, converting raw tokens to bigrams requires exact boundary token preservation across page boundaries.

This pull request introduces page-level exponential galloping and binary search across whole-page windows for `page_size > 1`, and preserves bigram boundaries cleanly in pure Python.

---

## Modifications

1. **Page-Level Galloping in `RadixKey.match_at`:**
   - When `page_size > 1`, gallop over doubling page windows (`step = 1, 2, 4, 8, ...` pages) and binary-search page boundaries.
   - For a 16,384-token context with `page_size = 64` (256 pages), page galloping reduces slice comparisons to ~15 checks instead of 256 Python loop iterations.
   - For `is_bigram = True`, compare `page_size + 1` tokens per page to preserve the shared boundary token.
   - For `page_size == 1`, retain the token-level exponential galloping search.
2. **Pure Python Implementation:**
   - 100% self-contained in `radix_cache.py`.
   - Zero external dynamic libraries, zero `ctypes` overhead, and full portability across all platforms.
3. **Formal Invariant Verification:**
   - Verified the correctness of page-aligned stride matching and bigram token boundaries in Lean 4 (zero `sorry`).

  - Warm Prefix Cache Hit Speed: 152.71 tokens/sec.
  - Live GPU prefill throughput speedup: **1.86x faster**.
