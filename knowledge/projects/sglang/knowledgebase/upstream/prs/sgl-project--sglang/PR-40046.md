# [MLX] Fix cache accounting during chained decode

[Upstream PR](https://github.com/sgl-project/sglang/pull/40046) · state: closed · merged: False

## Original PR description

## Motivation

Chained MLX decode skipped cache slots and length updates. A 40-token continuation reused only 9 cached tokens instead of 39.

Related #32833; this fixes the chained decode part of the RFC.

## Modifications

Allocate each decode step normally, publish completed cache data before freeing request slots, and discard old state when a request is restarted or released. Rebased on current main.

## Accuracy Tests

- 62 related unit tests and 2 subtests pass; all 7 new regressions fail without the fixes.
- Real Qwen3-0.6B serving: cached tokens increase from 9 to 39, and cached/fresh outputs match.
- With a 128-token pool, one request is retracted and resumed; both requests finish with 80 output tokens.

Serving checks temporarily applied the separate startup fix from #41314, which current main still needs. That fix is not included here.

## Speed Tests and Profiling

Apple M4, Qwen3-0.6B-4bit, radix cache disabled: all five 128-token greedy outputs match current main. Median latency: 0.5373s → 0.5377s (+0.08%). This is a small local comparison.
