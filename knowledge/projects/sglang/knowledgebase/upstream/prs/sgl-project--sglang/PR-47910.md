# [Perf] [AMD] aiter: Split the fused-QKV q slice into heads without a copy in batch prefill

[Upstream PR](https://github.com/sgl-project/sglang/pull/47910) · state: open · merged: False

## Original PR description

## Motivation

The non-MLA NHD batch-prefill path in the aiter backend copies the whole of q on every layer (`q.contiguous().view(...)`) although `mha_batch_prefill_func` does not need it to be contiguous; splitting q into heads as a view removes that copy. For a model without QK-norm and with bf16 KV, q is the leading column slice of the fused QKV output: each row is strided over the K/V columns but its last dim is dense. aiter's `_mha_batch_prefill` passes q through `maybe_contiguous`, which copies only when `stride(-1) != 1`, and the CK kernel takes the row and head strides as arguments.

## Modifications

- `aiter_backend.py`: new `_prefill_q_heads` returns `q.unflatten(-1, (num_heads, head_dim))` when q is 2-D with a unit last-dim stride. Any other layout still goes through `contiguous().view(...)`. The batch-prefill call in `forward_extend` uses it. The kernel output is the same as before, element for element.
- `test_aiter_asm_prefill_gather.py`: `TestPrefillQHeads` checks that a fused-QKV column slice comes back as a view of the QKV buffer with equal values, and that a q with a strided last dim is still copied. The test fails on main (the helper does not exist there). It also fails on two plausible-but-wrong variants: unflatten without the stride guard fails the strided case, and a guard on `is_contiguous()` fails the slice case. It passes here (CPU).

Who benefits: this is the default ROCm path for bf16 Llama-3.x / Mistral / Mixtral / Qwen2.5-class models. Current flagship checkpoints do not benefit. DeepSeek-V4, GLM-5.x, Kimi, MiniMax-M3 and Qwen3.8-Flash-Next take other backends or the MLA branch. gpt-oss and gemma-4 take `_forward_extend_unified`, and MiniMax-M2.7 and the Qwen3.5/3-Next family arrive with q already contiguous (QK-norm), so for them this is a no-op. With fp8 KV, q is quantized into a fresh contiguous tensor first, so nothing changes there either. #47822 (draft) makes the same change at the `_forward_extend_unified` call site. The two compose, and they could share one helper.

## Speed Tests and Profiling

Microbench of the reshape plus `mha_batch_prefill_func` (page size 1, bf16, causal, no prefix) on MI355X (gfx950), torch 2.11.0+rocm10.0.0, aiter 0.1.26.dev144+g285579b62, at main `d9521615b7`. The L2 cache was not flushed between calls: in serving, q is read right after the QKV GEMM writes it, but the KV reads also stay warm here, so the percentages at short lengths are an upper bound and the absolute saving is the copy time below. Each arm ran as a block of 4 fresh processes; the first run was dropped and the table reports the median of runs 2-4. The blocks ran in the order base then PR, then repeated as PR then base; the table is the first round, and every shape in the second round is within 2.5 points of it. Times are in µs per call.

| Heads q/kv/dim | Batch x seq | Base | This PR | Speedup |
|---|---|---|---|---|
| 32/8/128 (Llama-3.1-8B) | 1 x 509 | 27.9 | 22.8 | +22.2% |
| 32/8/128 | 3 x 1021 | 61.2 | 51.8 | +18.0% |
| 32/8/128 | 2 x 3067 | 227.2 | 210.3 | +8.0% |
| 32/8/128 | 6 x 4093 | 1220.4 | 1143.6 | +6.7% |
| 32/8/128 | 1 x 8191 | 682.6 | 660.9 | +3.3% |
| 28/4/128 (Qwen2.5-7B) | 3 x 1021 | 56.2 | 45.7 | +22.9% |
| 64/8/128 (Llama-3-70B TP1) | 2 x 3067 | 461.9 | 423.9 | +9.0% |
| 8/1/128 (Llama-3-70B TP8) | 2 x 3067 | 106.9 | 99.7 | +7.3% |

- Over 15 strided shapes the median speedup is +12.5% (+12.6% in the reverse-order round). 14 of the 15 shapes are at or above +5%.
- The saving is exactly the copy (9.9 / 16.9 / 72-73 µs at 3x1021 / 2x3067 / 6x4093). The kernel itself runs at the same speed on strided and contiguous q (within 2%), so the relative gain shrinks as the sequence gets longer.
- The control is an already-contiguous q (the QK-norm case), which goes through the unchanged branch: -1.1% to +1.7%.
- The outputs match `torch.equal` against the copied-q reference for every shape in all 16 runs.
