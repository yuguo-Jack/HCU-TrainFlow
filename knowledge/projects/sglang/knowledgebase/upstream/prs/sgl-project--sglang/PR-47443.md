# [Fix] diffusion: Honor the requested profiler step count

[Upstream PR](https://github.com/sgl-project/sglang/pull/47443) · state: open · merged: False

## Original PR description

## Motivation

A diffusion request with `num_profiled_timesteps=1` writes a trace labeled `1_steps` but records two active denoising steps. Warmup was included in both the schedule's warmup and active counts, and the early-stop counter also ran past the requested window.

## Modifications

Separate warmup from the recorded step count and stop after the last requested step. Keep one warmup step when the request has enough steps; recording every step, including `-1`, retains the first denoising step.

Start denoising-only profiling at the shared executor's denoising stage, and stop when that stage exits. An explicit stage capability selects step profiling independently of deployment roles, including Cosmos3's existing encoder affinity. This keeps preprocessing and decoding out of the trace even without warmup or when the denoiser returns early. Cancellation before denoising safely leaves no trace. Full-stage profiling keeps its existing coverage.

Update the CLI help and add CPU regressions that read actual exported Chrome traces. The existing diffusion unit suite discovers the new file automatically.

## Accuracy Tests

The focused regressions pass on CPU with PyTorch 2.14.0. They exercise `profile_execution` and the shared stage entry, then read exported trace payloads for one and two requested steps, short/all-step requests, an early request end, cancellation before denoising, repeated stop notifications and full-stage profiling. The original implementation reproduces the extra active step in real CPU traces.

The earlier focused run imported the complete profiler and executor modules with unrelated startup imports isolated and a residency-manager fixture. Its Cosmos3 case uses the actual step callback and source class metadata without loading the model; those executor/Cosmos results retain that isolated scope.

A later check on `7773a163` imported the public `SGLDiffusionProfiler` class normally from the complete source package, using the existing CPU environment with PyTorch 2.14.1. Actual exported Chrome traces contained the expected synthetic CPU payload markers for one and two requested steps, all steps (`-1`), an early exit from the public denoising-stage context and full-stage profiling. This run used the complete profiler module without startup stubs, source extraction or `sys.modules` replacements. It newly checks the public profiler API; it does not newly qualify shared-executor wiring, Cosmos3 or full SGLang startup.

The original pytest invocation was attempted in that environment. After adding only task-private `addict` and repository-pinned `imageio`, collection stops in the unit conftest on missing `diffusers`, before any test runs. The direct API traces above are not a passing pytest result:

```bash
python -m pytest -q python/sglang/multimodal_gen/test/unit/test_diffusion_profiler.py
```

## Speed Tests and Profiling

This changes profiling coverage, not model computation. No CUDA, model-quality or inference-speed result is claimed. Changed-file pre-commit checks pass.
