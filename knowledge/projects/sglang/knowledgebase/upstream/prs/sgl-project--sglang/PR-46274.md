# [Fix] diffusion: Keep each request's rollout trajectory and conditioning under dynamic batching

[Upstream PR](https://github.com/sgl-project/sglang/pull/46274) · state: closed · merged: True

## Original PR description

## Summary

Dynamic batching silently breaks RL rollout requests in two ways:

1. `Scheduler._split_batched_output` builds each per-request `OutputBatch` from an explicit field list that omits `rollout_trajectory_data`. Any rollout request batched with another compatible request (same sampling params, different prompt — exactly what `--batching-max-size > 1` is for) gets `rollout_trajectory_data=None` back, which fails the assert in `rollout_api.py`.
2. Fixing that exposes a second bug: `concat_rollout_trajectory_data` keeps only the first output's `denoising_env` for the whole merged batch. A trainer replaying request k's DiT forward then gets request 0's prompt conditioning, with no error raised — silently wrong importance ratios.

## Fix

- `rl_dataclasses.py`: generalize the existing single-index slice helper into `_slice_dim(start, end)`, add small recursive tree cat/slice helpers for conditioning dicts (mirroring `rollout_hooks._kwargs_to_cpu`'s shape), and introduce `slice_rollout_trajectory_range(data, start, end)` as the one range-slicing implementation. `select_output_rollout_trajectory` now delegates to it. `concat_rollout_trajectory_data` now concatenates `denoising_env` across outputs instead of keeping only the first.
- `managers/scheduler.py`: `_split_batched_output` now slices `rollout_trajectory_data` through `slice_rollout_trajectory_range` like every other per-request field.

## Tests

- `test_multi_output_rollout_trajectory.py`: extended the existing per-output fixture with an optional conditioning env, added two tests asserting concat/select no longer collapse or drop per-output conditioning.
- `test_image_response_bytes.py`: added a sibling to the existing `test_dynamic_batch_split_keeps_each_requests_image_bytes` asserting the scheduler split keeps each request's own rollout trajectory.

Verified both new dataclass-level tests fail against the pre-fix code and pass against the fix (CPU-only harness, pure torch, no GPU). The scheduler-wiring test matches the existing style of `test_dynamic_batch_split_keeps_each_requests_image_bytes` in the same file but wasn't executed locally — the full `sglang` package import graph pulls GPU-only dependencies that aren't installable in a CPU-only environment; reviewed by static trace of `_split_batched_output` instead.

## Risks / remaining

- Scheduler-level test not executed (see above); static review only.
