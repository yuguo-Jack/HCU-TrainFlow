# [Feat] rust-server: Serve /start_profile and /stop_profile

[Upstream PR](https://github.com/sgl-project/sglang/pull/46968) · state: closed · merged: True

## Original PR description

## Motivation

The Rust frontend (`rust/sglang-server`, `SGLANG_RUST_SERVER=1`) does not serve `/start_profile` and `/stop_profile`, so a profiling workflow that works against the Python HTTP server returns 404 against the Rust one. The scheduler already handles `ProfileReq`; only the frontend relay was missing.

## Modifications

- `message/io_struct.rs`: add `ProfileReq` to the `control_messages!` block, positionally matching Python's `ProfileReq` (15 fields after the `BaseReq` header), plus `ProfileOptions`, the client-settable subset deserialized from the `/start_profile` body. `start_step` / `num_steps` accept a numeric string, as Python's request validation does. `ProfileReq::start` / `ProfileReq::stop` are the only constructors.
- `api_server/handlers/control.rs`: `CoreHandle::start_profile` / `stop_profile` fan the control request out to every DP rank like `flush_cache` does, decode each scheduler's `ProfileReqOutput` (`success`, `message`) and merge them with `fanout::merge_status`, so the call succeeds only if every rank did. `start_profile` resolves the body the way `TokenizerManager.start_profile` does: `with_stack` / `record_shapes` default to `SGLANG_PROFILE_WITH_STACK` / `SGLANG_PROFILE_RECORD_SHAPES` (read with `get_bool_env_var` semantics, default true) unless the body says `false`, and a missing or empty `profile_id` becomes `str(time.time())`.
- `utils/environ.rs`: add `get_bool_env_var`, a copy of Python's `utils.get_bool_env_var` (only `true` / `1` are true; any other set value is false rather than the default), distinct from the existing `env_bool` (`EnvBool` semantics).
- `api_server/http/info.rs`: mount `GET|POST /start_profile` and `GET|POST /stop_profile`. Responses match Python's: plain-text 200 (`Start profiling.\n` / `Stop profiling. This will take some time.\n`) with no content type; a scheduler refusal (already profiling, nothing to stop) is Python's bare 500 `Internal Server Error` with the reason logged; a malformed body is a 400 before anything reaches the scheduler; `req_type` is accepted only as `1` or `2` and then ignored (the route decides).
- `test/registered/unit/managers/test_io_struct.py`: generalize the Rust/Python lockstep check from `TokenizedGenerateReqInput` alone to every message in the `control_messages!` block, so each Rust control message must be a prefix of its Python namesake and Python must default every field Rust omits. The set of names is pinned so adding a message means extending the test.
- `test/registered/profiling/test_start_profile.py`: run the existing suite a second time against the Rust frontend (`TestStartProfileRustServer`, skipped when the extension is not built), and add `test_start_profile_4_refusals` covering the refused stop / deferred start paths and the exact response bodies. `est_time` is raised to cover the second server launch.

Under attention DP each rank's listener receives the request through the control fan-out, and each scheduler broadcasts it from its TP rank 0, so every rank starts (or stops) its profiler.
