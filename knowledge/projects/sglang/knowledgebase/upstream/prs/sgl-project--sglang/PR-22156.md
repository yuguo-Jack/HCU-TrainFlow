## Motivation

<!-- Describe the purpose and goals of this pull request. -->
Huge thanks to @Hills-code, the author of Fast-dLLM v2, for the support and guidance throughout this integration.

Support [NVIDIA Fast-dLLM-v2](https://huggingface.co/Efficient-Large-Model/Fast_dLLM_v2_7B) with HierarchyBlock algorithm.

This PR continues the original work by @baonudesifeizhai (AR init for Fast-dllm-V2 in https://github.com/sgl-project/sglang/pull/15013) and @Monstertail (parallel decoding / HierarchyBlock algorithm in https://github.com/sgl-project/sglang/pull/17577). All of their commits are preserved with original authorship. I took over, rebased onto latest `main`, fixed a scheduler return-contract bug that blocked end-to-end runs, switched the tests to use the tokenizer chat template so the model sees the same input a production client would send, and re-validated the results.

We would like to make the Fast-dLLM-v2 the standard for integrating new dLLMs and their corresponding algorithms, especially to show:
- How do we implement the algorithms without aggressively changing the systems?
- How do we test the models and decoding algorithms?

## Modifications

<!-- Detail the changes made in this pull request. -->
- Init NVIDIA Fast-dLLM-v2 with full logits.
- Init HierarchyBlock algorithm for parallel generation.
- Add a GSM8k integration test for Fast-dLLM-v2 that applies the tokenizer chat template to every prompt.
- [Todo] support batching when rebase with the newest version after this PR: https://github.com/sgl-project/sglang/pull/14883

Next steps:
- Support batching for the HierarchyBlock algorithm. Token shifts will be challenging in batching because we need to map token from the last block with the dLLM requests in a batch, without breaking the schedule batch abstraction. CC @ClawSeven

## Speedup vs Standard AR Baseline (Qwen2.5-7B-Instruct)

To quantify the speedup from the HierarchyBlock algorithm, we benchmarked the standard autoregressive model **Qwen2.5-7B-Instruct** under identical server settings (`--mem-fraction-static 0.7`, `--max-running-requests 1`, `--attention-backend flashinfer`, chat template applied, A100 80GB).

**Qwen2.5-7B-Instruct Baseline Results**

| TP | Accuracy | Invalid | Latency (s) | Output Throughput (token/s) |
|----|----------|---------|------------:|----------------------------:|
| 1  | 0.825    | 0.000   | 401.554     | 96.358                      |
| 2  | 0.850    | 0.000   | 247.619     | 156.858                     |
| 4  | 0.830    | 0.000   | 155.042     | 248.495                     |

**Throughput Comparison: Fast-dLLM v2 vs Qwen2.5-7B-Instruct (AR baseline)**

| TP | AR Baseline Acc | Fast-dLLM v2 Acc | AR Baseline (token/s) | Fast-dLLM v2 (token/s) | Speedup |
|----|----------------:|-----------------:|----------------------:|-----------------------:|--------:|
| 1  | 0.825           | 0.805            | 96.358                | 169.903                | **1.76x** |
| 2  | 0.850           | 0.770            | 156.858               | 244.444                | **1.56x** |
| 4  | 0.830           | 0.780            | 248.495               | 314.043                | **1.26x** |

Fast-dLLM v2 with HierarchyBlock achieves **1.26x–1.76x** output throughput compared to standard autoregressive decoding, while maintaining comparable accuracy. The speedup is most pronounced at TP1 where the HierarchyBlock parallel decoding compensates most effectively for the single-GPU compute bottleneck.

To run the baseline test, check: `test/srt/dllm/test_qwen2_5_7b_instruct.py`.

This logic for handling tied weights in Pipeline Parallelism (PP) is problematic. Using `next(filter(..., weights))` consumes the `weights` iterator, which will cause the outer loop to skip weights or fail if the desired weight was already yielded. Furthermore, `lm_head.weight` might not even be present in the checkpoint if it is tied to `embed_tokens`. A more robust approach is to detect `model.embed_tokens.weight` directly and load it into `lm_head.weight` on the last rank.

```python
            if self.config.tie_word_embeddings and name == "model.embed_tokens.weight":
                if self.pp_group.world_size > 1 and self.pp_group.is_last_rank:
                    param = self.lm_head.weight
                    weight_loader = getattr(param, "weight_loader", default_weight_loader)
                    weight_loader(param, loaded_weight)
                    # Do not continue here, as rank 0 still needs to load it into embed_tokens
```
