# [Kernel] Use Cake softmax for qualified SM103 sampling workloads

[Upstream PR](https://github.com/sgl-project/sglang/pull/42004) · state: closed · merged: True

## Original PR description

## Motivation

Large-vocabulary, small-batch stochastic sampling spends about 64 us per BS1
decode step in Torch softmax on the measured GB300. Route the qualified domain
through FlashInfer's Cake Blackwell softmax while keeping sampling/filtering in
SGLang. On Qwen3.5-4B, the final same-GPU comparison improves output throughput
by 2.48% at concurrency1 and 1.09% at concurrency64.

**Dependency limitation:** SGLang currently pins FlashInfer0.7.0.post1, which
does not contain this kernel. This draft keeps the dependency pin and detects
the Cake module before enabling the path. The released wheel retains Torch;
the results below require FlashInfer `be92cab02e2818ac1a54e7181d15595a61342a20`
in both the baseline and candidate. This is not an out-of-box gain on the pinned
wheel. Submitting as a draft for integration/dependency review.

## Modifications

- Add a lazy `sglang.kernels.cake_kernels` ownership directory and a thin
  forwarding adapter to the public `flashinfer.sampling.softmax` API, following
  the namespace separation used by `kda_kernels`.
- Register `sampling.softmax` with the existing FlashInfer backend; enable it
  for CUDA SM103, contiguous FP32 `[B,V]`, B1–64, V128256–262144 divisible by8,
  and an installed Cake softmax module. Keep Torch elsewhere, including
  deterministic inference. No new environment variables or dependency changes.
- Preserve temperature scaling, the probability buffer copy, joint top-k/top-p
  filtering, RNG and the existing logprob paths. Cake's combined sampler has
  different filtering semantics and is not used here.

## Accuracy Tests

SGLang base: `3b6d37a56e8dfacc14a5f412886c2f1adb0ca523`; GB300 SM103/152SM,
PyTorch2.13.0+cu130, CUDA13, TP1. Research harnesses remain outside the repository;
no repository test files are added or modified.

- Existing `test/registered/unit/kernels/test_kernels_namespace.py`: 59 passed.
- 34 operator configurations across two matrices (32 unique
  shapes): B1/2/4/7/16/31/63/64, vocab32000/128256/151936/201088/248320/262144.
  Each configuration checks normal, wide, masked, one-valid-token and equal
  logits against FP64 softmax: finite, top1 equality and atol1e-7/rtol1e-5 all
  pass. The 32K timing regression is excluded by the runtime guard.
- Qwen3.5-4B: teacher-forced probabilities on 520 identical histories at BS1/64
  preserve top1 sets and pass logprob comparisons (maximum absolute difference
  3.82e-6). Checks include top128, 512 fixed vocabulary IDs and selected tokens.
  This exercises the changed stochastic branch. Independently sampled histories
  are not treated as deterministic accuracy references.
- Greedy sanity: 65/65 continuations and logprobs identical; 20-example GSM8K,
  thinking disabled, 18/20 for both arms. Greedy bypasses the changed branch,
  so these checks supplement rather than replace probability validation.
- Real released FlashInfer0.7.0.post1 and current-main guard probes pass,
  including CPU, unsupported dtype/shape and noncontiguous inputs; fallback
  outputs are bitwise Torch-equivalent. Ruff0.15.1, isort and diff checks pass.

## Speed Tests and Profiling

Qwen3.5-4B revision `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`;
same physical GPU, same FI revision, only sampler dispatch differs.
`sglang.bench_serving`, random-ids, nominal1024 input / exactly256 output,
temperature0.8, top_p0.9, fixed seed, cache flushed between windows.
Concurrency1 uses8 requests/window; concurrency64 uses128. Five measured windows
per arm after one warmup for each concurrency. Every request completes, output
lengths are256, and server-reported input-length vectors match between arms.
Random token IDs are decoded to text by this benchmark's default, so actual
server input lengths differ from the nominal1024. The reported metric is output
token throughput, not input throughput inferred from nominal lengths.

| Concurrency | Torch output tok/s | Cake output tok/s | Change | Median TPOT ms, Torch -> Cake |
|---|---:|---:|---:|---:|
| 1 | 386.49 | 396.06 | +2.48% | 2.430 -> 2.368 |
| 64 | 7700.98 | 7784.64 | +1.09% | 5.349 -> 5.296 |

Final per-window output throughput ranges: concurrency1 Torch384.46–386.99,
Cake395.12–396.28; concurrency64 Torch7678.77–7736.34,
Cake7777.49–7799.73. Earlier same-GPU A1/B1/B2/A2 blocks are retained locally:
A1 was slower than A2/A3 and is not pooled into the headline. The final guarded
B3/A3 comparison above agrees with the earlier A2/B arms. This is a measured
single-model result, not a universal gain or a cross-device confidence claim.

```bash
python -m sglang.launch_server \
  --model-path Qwen/Qwen3.5-4B --tp 1 --random-seed 123 \
  --mem-fraction-static 0.50 --context-length 32768 \
  --chunked-prefill-size 8192 --max-running-requests 64 \
  --cuda-graph-max-bs-decode 64 --mamba-radix-cache-strategy extra_buffer

python -m sglang.bench_serving --backend sglang \
  --host 127.0.0.1 --port 30000 --model Qwen/Qwen3.5-4B \
  --dataset-name random-ids --random-input-len 1024 --random-output-len 256 \
  --random-range-ratio 1 --max-concurrency 1 --num-prompts 8 \
  --seed 123 --temperature 0.8 --top-p 0.9 --flush-cache \
  --warmup-requests 0 --disable-tqdm --output-details --output-file result.jsonl
# For concurrency64, use --max-concurrency 64 --num-prompts 128.
```

Separate decode profiles show eight softmax launches per capture:

| Batch | Torch softmax mean | Cake softmax mean |
|---|---:|---:|
| 1 | 64.352us | 4.620us |
| 64 | 75.900us | 31.664us |

The candidate kernel is `kernel_flashinfer_blackwell_softmax_cached_c16_t8`.
Profiles use short prompts to verify dispatch; kernel durations exclude the
output copy and are not used as E2E timing. Unprofiled microbenchmarks include
the copy in both arms. Unsupported model/attention/Cake families are outside
this PR.
