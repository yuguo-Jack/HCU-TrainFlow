# fix(io_struct): forward per-sample session_params in GenerateReqInput.__getitem__

[Upstream PR](https://github.com/sgl-project/sglang/pull/28796) · state: closed · merged: False

## Original PR description

## Summary

Batched generation with per-prompt `session_params` currently forwards the entire list to each request, where the tokenizer manager expects one dictionary. Normalize the metadata against the original batch before parallel sampling, then give each prompt its own session dictionary. Its `n > 1` children retain that same dictionary.

Scalar dictionaries remain shared metadata; singleton lists for scalar requests normalize to a dictionary. Empty or malformed lists and wrong batch cardinality fail before fan-out. Empty-token session continuation preserves the same behavior for a dictionary and its singleton-list equivalent.

Builds on #27257 and the validation-boundary analysis from [he-yufeng](https://github.com/he-yufeng) and [chengcuiping](https://github.com/chengcuiping). Fixes #27218.

Request-normalization tests also cover invalid lists and empty-token continuation. No GPU runtime claim is made.

If parallel sampling is used (e.g., `n > 1`), the batch is expanded to a larger size `num = batch_size * parallel_sample_num`. However, `self.session_params` is not expanded in `_normalize_batch_inputs`. As a result, accessing `self.session_params[i]` for `i >= batch_size` will raise an `IndexError`.

Using modulo indexing `i % len(self.session_params)` safely maps the expanded sub-request back to its corresponding original session parameter, preventing the `IndexError` and correctly supporting parallel sampling.

```suggestion
            session_params=(
                self.session_params[i % len(self.session_params)]
                if isinstance(self.session_params, list) and self.session_params
                else self.session_params
            ),
```

    def test_getitem_session_params_per_sample(self):
