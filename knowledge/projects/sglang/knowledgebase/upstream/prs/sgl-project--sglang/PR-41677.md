# [Perf] [AMD] qwen3_5: enable GDN fused decode projection+Conv1D on HIP

[Upstream PR](https://github.com/sgl-project/sglang/pull/41677) · state: open · merged: False

## Original PR description

## Motivation

The GDN fused decode projection + Conv1D path is gated on `_is_cuda`, so ROCm never takes it — although every prerequisite is already satisfied on HIP:

- `TritonGDNKernel.supports_packed_decode` is `not is_cpu() and not is_npu()`, i.e. true on HIP. At runtime the dispatcher reports `packed_decode=True` on gfx950.
- The kernels in `kernels/ops/attention/triton_gdn_fused_proj.py` are Triton, and the eligibility guard tests `tensor.is_cuda`, true for ROCm tensors.
- `SGLANG_ENABLE_GDN_DECODE_FUSED_PROJ_CONV` already defaults to `True`.

The backend advertises the capability and the model layer declines to use it. The sibling KDA Triton kernel makes the opposite call (`supports_packed_decode` excludes only cpu/npu/xpu).

Without the fusion, ROCm decode runs `fused_qkvzba_split_reshape_cat_contiguous` and then a separate `_causal_conv1d_update`. With it, both collapse into one kernel.

## Modifications

```diff
 _gdn_decode_fused_proj_conv = (
-    _is_cuda and envs.SGLANG_ENABLE_GDN_DECODE_FUSED_PROJ_CONV.get()
-)
+    _is_cuda or _is_hip
+) and envs.SGLANG_ENABLE_GDN_DECODE_FUSED_PROJ_CONV.get()
```

No new kernels or flags. `SGLANG_ENABLE_GDN_DECODE_FUSED_PROJ_CONV=0` remains the kill switch.

## Accuracy Tests

GSM8K, full 1319-question test set, `--thinking-mode qwen-3`, temperature 0, 2 runs per arm (2638 samples each), on 8x MI355X:

| arm | score |
|---|---:|
| stock | 0.9708 |
| #41677 (decode fused proj+conv) | 0.9666 |
| #41683 (prefill strided z) | 0.9663 |
| both | 0.9723 |

No significant difference against stock (two-proportion z-test: p = 0.38 / 0.34 / 0.74). Spread across arms is 0.61 pp against a 0.48 pp binomial standard error for a single run, and the both-patches arm scores highest — inconsistent with any additive degradation.

## Speed Tests and Profiling

8x MI355X (gfx950), TP=8, `amd/Qwen3.8-2.4T-A95B-Quark-MXFP4` (ships as `Qwen3_5MoeForCausalLM`; 69 of 92 layers are GDN), SGLang `v0.5.20-rocm10-mi35x`, decode 128/1024 @ concurrency 32, 4 runs per arm:

| metric | baseline | patched | delta |
|---|---:|---:|---:|
| mean ITL (ms) | 24.98 | 24.67 | **−1.22%** |
| output throughput (tok/s) | 1260.1 | 1275.8 | +1.25% |

Kernels on the GDN decode path (torch profiler, TP-0):

| baseline | patched |
|---|---|
| `fused_qkvzba_split_reshape_cat_contiguous_kernel` | `_fused_qkvzba_causal_conv1d_update_contiguous_kernel` |
| `_causal_conv1d_update_kernel` | |

Two kernels per GDN layer become one — 69 fewer launches per decode step.
