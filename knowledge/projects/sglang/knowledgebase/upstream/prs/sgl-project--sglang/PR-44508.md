# [Test] diffusion: Batch performance failure-policy runner scenarios

[Upstream PR](https://github.com/sgl-project/sglang/pull/44508) · state: closed · merged: True

## Original PR description

## Motivation

The performance failure-policy regression test starts a fresh pytest runner for each of nine failure scenarios. With the initial attempt and six retries, this launches 63 nested pytest processes and repeatedly imports the same diffusion test stack.

## Modifications

Parameterize the generated child test over all nine scenarios and exercise them in one runner session. This reduces nested pytest processes from 63 to 7 while retaining all seven real attempts, per-scenario request/LoRA/retained-metric checks, and a final failed report for every scenario. Production retry behavior and performance thresholds remain unchanged.

## Accuracy Tests

- Full `test_performance_failure_policy.py`: **26 passed** on the source commit `2eecf0a3` in an isolated development environment.
- Cherry-picked only that commit onto current main; retained main's updated `_validate_and_record` call signature. Pre-commit passed on the final branch.
- The post-cherry-pick runtime rerun could not start because development-machine access failed its tailnet challenge. CI validation is pending.

## Speed Tests and Profiling

In the same development environment, the original single `regression` scenario took 102.23 seconds; the batched nine-scenario matrix took 109.03 seconds (112.34 seconds for the complete 26-test file). These are different workloads; no full-matrix speedup factor was measured.
