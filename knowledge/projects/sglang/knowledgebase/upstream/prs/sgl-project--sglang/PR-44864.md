# [Perf] DSv4.1: Enable encoder bounded replay with shared BCG metadata

## Motivation

Encoder SWA bounded replay currently rejects breakable prefill CUDA graphs. Supporting the combination also needs correct live-row metadata at eager graph boundaries and bounded metadata allocation across capture buckets.

## Modifications

- Enable encoder bounded replay with CUDA breakable prefill graphs; keep unsupported graph backends and hardware rejected.
- Refresh request-window metadata and keep dynamic KV stores and low-ratio compression at eager boundaries. Slice bucket-sized locations to live rows and size the request-window workspace for capture buckets as well as scheduled chunks.
- Preserve idle DP ranks when entering the decoder tail by clamping the CPU live-row count consistently with its GPU counterpart.
- Share page-table and c1/c2 index backing storage across prefill buckets, with independent full/tail buffers and stable captured addresses. Release inactive buckets' eager candidate tables without changing captured decode metadata ownership.
- Add focused CPU regressions for replay metadata refresh, idle tails, shared-storage isolation and candidate lifetime.

## Accuracy Tests

Local GB300 validation on the development base (`4fc86f73c`):

- 15 encoder replay CPU tests, 4 packed-KV CUDA tests, and a standalone graph probe passed. The probe checks shared addresses, exact integer outputs across bucket switches and tail isolation.
- Shared and unshared DEP4 servers each passed three 44-response smoke suites covering four DP ranks, 6–8192 input tokens and 1024/4096-token prefix-cache extensions. Both use the same idle-row fix.
- All compared first-token IDs and request/cache usage match. Complete generated sequences are not strictly identical: each version's two consecutive repetitions match on 38/44 sequences under the existing DSPARK configuration. These smoke tests do **not** establish strict numerical equivalence or model-quality accuracy.
- The shared 2048 capture limit also passed the same 44-response suite, including inputs exceeding the capture limit.

On the PR base (`14c4dda24`), the simplified 11-test encoder replay CPU suite passed. The 16 compressed-pool CPU tests and 4 packed-KV CUDA tests also passed before this test-only simplification; production code is unchanged. This also covers pool construction without a configured CUDA graph. The full-model memory/smoke measurements above used the earlier development base; they were not rerun on this newer base. No GitHub CI results are claimed.

## Speed Tests and Profiling

On four GB300 GPUs with attention-DP4/EP4, encoder and decoder bounded replay, `flashmla_mega`, DSPARK block size 5, memory fraction 0.7 and unchanged context limit:

| Prefill capture limit | Unshared | Shared |
| --- | ---: | ---: |
| 8192 | 22.67 GiB/GPU | 12.58 GiB/GPU |
| 2048 | ~8 GiB/GPU (memory-only reference) | 5.17 GiB/GPU |

The unshared 2048 capture measured 8.05 GiB/GPU (rounded to ~8 GiB above), but that run subsequently failed startup validation; it is a memory-only reference, not a passing serving baseline.

These are **incremental prefill BCG capture memory** measurements, not total server memory or peak startup allocation. The 8192 shared result repeated across two server startups and all four ranks. No throughput improvement is claimed; sustained workload benchmarking and broader accuracy validation remain outstanding.
