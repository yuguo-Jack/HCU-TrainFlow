# [Fix] speculative: FR-Spec (--speculative-token-map) with a quantized (FP8) target lm_head

[Upstream PR](https://github.com/sgl-project/sglang/pull/44277) · state: open · merged: False

## Original PR description

## Motivation

`--speculative-token-map` (FR-Spec) fails at startup when the **target lm_head is quantized**. With a compressed-tensors W8A8 FP8 (per-channel) lm_head, SGLang keeps the weight transposed (`[K, V]`), so `head.data = head.data[self.hot_token_id]` in `EagleDraftWorker.init_lm_head` slices the K axis instead of the vocab: on Qwen3.8-27B (vocab 248,320, hidden 5,120) a 40,960-id map asks for a `[40960, 248320]` tensor and OOMs (9.47 GiB). The per-row `weight_scale` would also stay full size.

## Modifications

- `spec_utils.prune_quantized_lm_head(lm_head, hot_token_id)`: for a quantized lm_head, returns a shallow copy whose `weight` / `weight_scale` / `weight_scale_inv` / `bias` keep only the hot vocab rows, in the original dtype and layout (handles `[V, ...]` and the transposed `[K, V]` view). Per-tensor scales are shared. Returns `None` for unquantized heads, so the existing path is unchanged. Raises a clear error for layouts it cannot slice per row (block-wise scales, sharded/packed vocab) or for ids outside the vocab, instead of producing garbage. The target lm_head is never modified.
- `EagleDraftWorker.init_lm_head`: when the pruned head is available, hand it to the draft via `set_lm_head_from_target` (with a clear error if the draft model can't take a target head).
- `test/registered/unit/speculative/test_frspec_quantized_lm_head.py`: CPU tests (shape/stride/dtype, logits equal to the hot rows of the full head, target untouched, unquantized → old path, block scales and out-of-range ids refused).

## Accuracy Tests

Real Qwen3.8-27B FP8 lm_head (248,320 × 5,120, `ThinkingCap-Qwen3.8-27B-NVFP4A4-AWQ`, compressed-tensors): pruned logits == the corresponding rows of the full head (max |diff| = 0, top-1/top-4 identical) at M = 1/4/8/16. End to end with MTP (EAGLE 3/1/4) and a 40,000-id map: reasoning 48/48 (3 runs × 16, same as baseline), tool calls 24/24, needle 4/4; accept length ~3.0 vs ~3.1.

## Speed Tests and Profiling

RTX PRO 6000 (SM120), SGLang 0.5.21 (same code as this branch for these two files): draft lm_head 0.97–1.17 ms → 0.17–0.20 ms per call (3 calls per step). Single stream: +3.6 % at 45k context, +11.5 % at 141k; 4 concurrent: +8 %. Combined with other SM120 kernel changes (published separately, not part of this PR: https://github.com/AppNetDeveloper/sglang-sm120-fast-decode) it reached +22–38 % tokens/s on production traffic.
