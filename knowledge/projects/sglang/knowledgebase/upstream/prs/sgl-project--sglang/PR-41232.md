# [dLLM] Add DiffusionGemma output logprobs (stack 1/3)

[Upstream PR](https://github.com/sgl-project/sglang/pull/41232) · state: open · merged: False

## Original PR description

## Summary

**Let DiffusionGemma return output token scores through `/generate`.**

- **Stack 1/3.** Merge order: this PR → #43752 → #43767.
- **Follow-up:** #43767 tracks the TweetEval prefix failures and is marked **[WIP]**.
- **Scope:** token scores. #43752 uses them to answer decision questions.

## Changes

- Return scores for emitted tokens and requested candidate tokens.
- Keep each request's final scores when a shared logits buffer is reused.
- Preserve score rows through batching and streaming.
- Clear unfinished canvas state after retraction. Keep tokens and scores already returned.
- Reject unsupported prompt logprobs.

Scores come from the denoiser. They are not causal sequence likelihoods or calibrated confidence.

## Validation

- **Standalone PR1:** 48 tests and 45 subtests passed.
- **GPU checks:** six text/image cases passed. Batch, streaming, token order and score alignment checks passed.
- **Generation:** enabling scores preserves the output tokens.
- **Style checks:** repository pre-commit hooks passed.
- **Shared coverage:** a focused full-stack run passed 85 CPU tests and 14 subtests. Six CPU smoke runs also passed across `LowConfidence`, `JointThreshold` and `JointThresholdInDel`. [Coverage details](https://github.com/Hangzhi/sglang/tree/273838caccd07a03f17eb6065fca3877c23f6692/validation/diffusiongemma-2026-10-12/tweeteval-diagnosis).

**Why `gemma4_*`?** SGLang calls the DiffusionGemma algorithm `Gemma4Renoise`. These files test that implementation. The GPU validation uses DiffusionGemma weights. Other algorithms have CPU coverage.
