# [Feat] [NPU] disaggregation: Support PD role switching on Ascend

[Upstream PR](https://github.com/sgl-project/sglang/pull/43477) · state: open · merged: False

## Original PR description

## Motivation

Adapt lifecycle, decode graph state, and backup selection for Ascend prefill/decode role switching. The existing role-switch framework already dispatches to `AscendKVManager`, which inherits Mooncake teardown. That teardown calls `batch_unregister_memory`, an API unavailable in MemFabric, and does not explicitly destroy the manager's role-bound MemFabric session. Memory registration failures are also logged without reaching the caller.

Startup decode graph capture does not publish the graph state used by role switching, and automatic decode retraction backup selects the generic host pool, which does not support the tested Ascend blocked KV buffer layout.

Official MemFabric 1.3.0 also performs cleanup in its native object destructor, so an unavailable deregistration API alone does not prove that switching fails. A controlled Qwen3-32B TP2 comparison now reproduces two failures in unpatched base `37678784c6377267e5ef3cf56570d3cba441dab0`: automatic host-pool selection fails during decode startup, and explicit `cpu_tensor` permits the first role exchange but a subsequent generation fails with a KV-transfer HTTP 500. Applying this PR's production changes to the same base passes both configurations. The existing framework and Ascend dispatch predate this PR; these changes fix the tested Ascend serving path.

## Modifications

- Add a transfer-engine teardown hook. Ascend destroys its own role-bound MemFabric session and clears cached connections; Mooncake keeps its existing buffer deregistration behavior.
- Propagate Ascend memory registration failures to the caller. Keep the existing shared transfer-worker stop/join policy.
- Publish decode graph state consistently after startup and on-switch capture, excluding eager runners. Already captured graphs can then be reported and reused across role changes.
- Default Ascend decode retraction backup to `cpu_tensor`, leaving the generic host pool opt-in.
- Add three manual tests under `test/manual/ascend/`: transfer lifecycle, graph/retraction state, and a real two-service PD role-switch regression. These tests are not registered in CI.

## Accuracy Tests

Manually validated on a single Ascend A3 server with Qwen3-0.6B, BF16, Ascend attention/transfer backends, CANN 9.1, and driver 25.5.1.

| Scenario | Effective role changes | PD generations | Result |
| --- | ---: | ---: | --- |
| Fixed P/D, role-switch flag disabled | 0 | 6 | Pass |
| TP1 prefill + TP1 decode, role switching enabled | 8 | 18 | Pass |
| TP2 prefill + TP2 decode, role switching enabled | 8 | 18 | Pass |

Additional controlled comparison on the same A3 server, Qwen3-32B BF16, P/D TP2, and the same unmodified official MemFabric 1.3.0:

| Code | Decode retraction backup | Result |
| --- | --- | --- |
| Unpatched base `37678784` | Automatic | Decode startup fails in `pool_host/mha.py`: `Boolean value of Tensor with more than one value is ambiguous` |
| Same base + all PR production changes | Automatic | Pass: 8 effective role changes, 18 PD generations |
| Unpatched base `37678784` | Explicit `cpu_tensor` | Initial 6 fixed-role generations pass; first paired exchange and its 16-token input pass; the following 129-token input fails with KV-transfer HTTP 500 |
| Same base + all PR production changes | Explicit `cpu_tensor` | Pass: 8 effective role changes, 18 PD generations |

Both comparison variants use identical source except for the five production files changed by this PR; no runtime lifecycle hooks or monkeypatches are used. Both receive explicit graph batch sizes `[1, 2]` and a 4.0 GiB graph-headroom hint on switching. The old startup graph metadata is recorded without requiring the new behavior, and graph-capture counts are recorded rather than used to reject the old version. The failing old-code generation reports `Failed to get kvcache from prefill instance`; native store shutdown/uninitialization occurs before the test sends SIGTERM. This comparison demonstrates a real failure in the tested environment, but does not isolate the necessity of each individual change.

Each switching scenario performs four paired role exchanges in the same service processes. Inputs contain 16, 129, and 513 tokens, covering the 128-token page and 512-token chunked-prefill boundaries. With `temperature=0` and 16 generated tokens, repeated requests and every post-switch output match that scenario's initial token IDs exactly. Both servers' caches are flushed before each request.

The tests also verify:

- HTTP success and the actual role/decode graph state after each exchange.
- Decode graph replay in each request's new logs and one decode graph capture per rank/instance across repeated switches.
- Rejection when the flag is disabled, the role is invalid, or decode graph memory information is missing/insufficient; switching to the current role is a no-op.
- 50 CPU regression tests passed. The 10 new CPU cases were rerun after relocation to `test/manual/ascend/` and passed.

**MemFabric prerequisite:** service validation used unmodified official MemFabric 1.3.0 from GitCode at commit `4bad3e24285bf83524a365ff09c2c2db34d862ef`. Its imported-address cleanup allows engine destruction/recreation without stale GVA mappings. The tested older image's MemFabric 1.2.1 (`106f783df905fe8d8e40446375faf615cf9b74fb`) still fails the first P→D change with `address overlap`; that environment needs a compatible MemFabric fix/upgrade. This PR contains only SGLang changes and tests.

Coverage is limited to single-node SDMA and pure TP1/TP2. PLE offload, hybrid/Mamba, multi-node RDMA, long-running resource stress, GPU serving, and byte-level KV checksum comparison were not validated.
