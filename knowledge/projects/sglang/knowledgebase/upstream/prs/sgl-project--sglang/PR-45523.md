# [sglang-miles] [Diffusion] Return the negative cond from a rollout that runs no CFG

[Upstream PR](https://github.com/sgl-project/sglang/pull/45523) · state: open · merged: False

## Original PR description

## Motivation

DMD2 distillation in miles-diffusion (radixark/miles_diffusion#333) scores the student's samples with the teacher under CFG, inside the trainer. The trainer has no text encoders, so it replays the cond that the rollout returns in `denoising_env`. The student samples unguided (guidance 1), and then the engine never encodes the negative prompt: `neg_cond_kwargs` comes back empty and the teacher can't run CFG.

## Modifications

- `RolloutRequest` / `SamplingParams`: new `rollout_return_neg_cond_kwargs`, default `False` (no behavior change).
- `Req.needs_negative_cond` is true under CFG or for a rollout that sets the field. The stages that produce the negative cond read it instead of `do_classifier_free_guidance`:
  - `TextEncodingStage` encodes, appends and checks the negative prompt. Its dedup fingerprint uses the same flag, so a grouped request without the field never hands its empty negative cond to one with it.
  - `SD3ConditioningStage` merges the negative embeddings.
  - `DenoisingStage` builds `neg_cond_kwargs`, which the rollout hook already copies into `denoising_env`.
- Sampling still reads `do_classifier_free_guidance`. `CFGPolicy.build` adds the unconditional branch only under CFG, so such a request still runs one DiT forward per step.
- Pipelines with their own text-encoding stages keep their gates and return no negative cond for such a request; the trainer rejects a missing one explicitly.

The flag is independent of #45230, and the two branches merge without conflicts.

## Accuracy Tests

FLUX.2-klein-base-4B, 1×B200, 512², 4 steps, `cps` / noise level 1.0, negative prompt `"blurry, low quality"`, same seed for every request:

| request | `neg_cond_kwargs` in `denoising_env` | vs the guidance-1 request without the field |
|---|---|---|
| guidance 1 | `None` (the gap) | - |
| guidance 1 + `rollout_return_neg_cond_kwargs` | present; bitwise equal to the guidance-4 request's | `pos_cond_kwargs`, trajectory latents and per-step model outputs bitwise equal; 4 DiT forwards |
| guidance 4 (CFG) | present | - |

## Speed Tests and Profiling

Same setup, median of 6 requests after warmup:

| request | engine time (`inference_time_s`) | response size |
|---|---|---|
| guidance 1 | 0.052 s | 18.3 MiB |
| guidance 1 + `rollout_return_neg_cond_kwargs` | 0.053 s | 26.5 MiB |

After the first request the negative embedding comes from the conditioning cache, so the extra cost is the negative cond in the response.
