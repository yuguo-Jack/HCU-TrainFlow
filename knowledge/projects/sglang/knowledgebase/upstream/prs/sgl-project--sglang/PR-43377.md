# [Fix] Keep Hermes streaming text in order around tool calls

[Upstream PR](https://github.com/sgl-project/sglang/pull/43377) · state: open · merged: False

## Original PR description

## Motivation

Fixes #43148

When `<tool_call>` starts mid-chunk, `HermesDetector.parse_streaming_increment` returns the text before it directly. Every other normal-text path goes through `_clean_normal_text`, which drains `_normal_text_buffer`, so text held back as a possible `</tool_call>` comes out after the tool call. The same branch leaks `</tool_call>` into the content when one parallel call ends and the next starts in one delta:

```
                 before                              after
issue repro      ['a', 'b', '', '', '</done']        ['a', '</b', '', '', 'done']
parallel calls   ['', '', '', '</tool_call>\n', '']   ['', '', '', '\n', '']
```

## Modifications

- Route that branch through `_clean_normal_text`, as suggested in the issue.
- Two streaming tests in `test_hermes_detector.py`, one per symptom. Both fail on `main`.
