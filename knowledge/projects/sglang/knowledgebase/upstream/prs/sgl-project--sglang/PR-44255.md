# [Fix] security: sanitize profiler filename to prevent path traversal

[Upstream PR](https://github.com/sgl-project/sglang/pull/44255) · state: closed · merged: False

## Original PR description

## Background
The profiler's `/start_profile` endpoint accepted user-supplied `profile_prefix` and `profile_id` parameters without path sanitization.

## Problem
An attacker could supply values like `profile_prefix="../../../etc"` to write profiler trace files outside the configured output directory via `os.path.join()` resolution.

## Solution
Added a `_sanitize_filename_component()` helper that:
- Rejects path separators (`/`, `\\`, `os.path.sep`)
- Rejects `..` traversal components
- Rejects absolute paths (Unix and Windows styles)
- Rejects null bytes
- Validates against a strict `[a-zA-Z0-9._-]` allow-list

Applied to both `profile_prefix` and `profile_id` parameters at the entry point of `_init_profile()`, so both the V1 and V2 profiler paths are covered with a single check. Malicious inputs now return a clear error message in `ProfileReqOutput`.

## Testing
- Added unit tests for: absolute path, `..` traversal, path separators, null bytes, disallowed characters, and valid inputs
- All malicious inputs raise `ValueError` with a field-specific message; valid inputs pass through unchanged

Security fix for issue #44189 (CWE-22).
