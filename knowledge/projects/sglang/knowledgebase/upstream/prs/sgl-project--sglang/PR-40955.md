# [PD] Bootstrap EAGLE draft state on decode after target-only prefill

[Upstream PR](https://github.com/sgl-project/sglang/pull/40955) · state: closed · merged: False

## Original PR description

## Motivation

Target-only prefill does not initialize the draft model's prefix KV or proposal state. Decode-side EAGLE therefore needs real initialization rather than accepting absent metadata or synthesizing probabilities.

## Dependency

Depends on https://github.com/sgl-project/sglang/pull/40953.

This stacked PR targets `main`, so its full diff includes that prerequisite. Review the decode-bootstrap increment separately; it will need rebasing after the prerequisite merges. It does not depend on the workload-routing PR.

## Modifications

- Add default-off `--disaggregation-decode-draft-bootstrap` and an explicit prefix-token budget.
- Advertise draft-state capability in Python and Rust bootstrap registries. Validate the actual handoff capabilities, not merely whether a rejection-sampling flag is set.
- Select a target-only receive layout before metadata registration. Do not mix seeded and target-only peers on one listener.
- Replay the committed prefix on decode through target and draft models while preserving the already sampled handoff token. Reuse allocated KV slots and drain overlap before replay.
- Publish draft state only after successful initialization; reject unsupported/oversized requests without silently truncating them.
- Expose additional target replay work as `pd_draft_bootstrap_tokens`, without altering prefill cache-hit accounting.

This is an **experimental correctness fallback, not a throughput optimization**: it repeats full-prefix target and draft compute. Supported scope is single-layer EAGLE, TP-only decode, supported DeepSeek/GLM MoE text architectures, Mooncake, and Python egress. Decode prefix caching, HiCache, offload, HiSparse, constrained decoding, embeddings and multimodal requests are excluded. Rust egress is rejected for this mode because it does not expose replay accounting.
