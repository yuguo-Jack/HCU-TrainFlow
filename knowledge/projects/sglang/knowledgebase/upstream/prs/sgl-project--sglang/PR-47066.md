# [Fix] kernels: Hash tensors over 8 GiB in gpu_tensor_hash

[Upstream PR](https://github.com/sgl-project/sglang/pull/47066) · state: closed · merged: True

## Original PR description

## Motivation

`gpu_tensor_hash` computes each tile's offset as `pid * TILE` in int32. For a tensor over 8 GiB (2**31 words), the offset wraps negative and the kernel reads before the buffer: `CUDA error: an illegal memory access`.

`/weights_checker` with `action=checksum` hashes every weight with this kernel, so it crashes the engine on any model with a tensor over 8 GiB per rank. We hit it on DeepSeek-V4.1-Flash at TP 8, where each rank's engram table slice is 12.3 GB.

## Modifications

- Compute the offset in int64. Tensors under 8 GiB hash to the same values as before.
- Add a test that hashes a tensor just over 8 GiB (it fails without the fix), and one that pins the hash of a small tensor.

## Accuracy Tests

The change affects hashing only, not model outputs. On DeepSeek-V4.1-Flash (8×B300, TP 8, EP 8), the `/weights_checker` checksum failed before the fix. With the fix, it succeeds in 6.9 s and the engine stays healthy.

## Speed Tests and Profiling

Hashing a 4 GiB tensor on a B300 takes 2.94 ms before and 2.99 ms after (about 1.7% slower). The kernel isn't on the forward path.
