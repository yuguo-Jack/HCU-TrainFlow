# [Perf] SM90 W8A16 small-M fused MoE for 128x128 block-FP8 experts

[Upstream PR](https://github.com/sgl-project/sglang/pull/43913) · state: open · merged: False

## Original PR description

## Motivation

Closes #43912.

At decode with 1-4 tokens, the Triton fused MoE for 128x128 block-FP8 experts spends most of its time outside weight reads. That time goes to align/sort, two activation quantizations, a grouped GEMM tiled for M >= 16, and a separate top-k sum.

## Modifications

- `python/sglang/kernels/ops/moe/small_m_block_fp8_moe.py` adds two Triton launches over bf16 activations; the activation is never quantized.
  - **Up:** each CTA owns BLOCK_N gate rows and the matching up rows of one (token, slot) over the full K, and writes silu(gate) * up in fp32.
  - **Down:** each CTA owns BLOCK_N output rows of one token and reduces all top-k slots in a fixed order, so the result is deterministic. It then applies the router weights and `routed_scaling_factor`.
  - Per-block scales are applied to the activation, and any scale strides work.
  - Per-M block sizes come from an H100 cold-L2 sweep.
- `moe_runner/triton.py`: `fused_experts_none_to_triton` takes this path only when all of these hold:
  - `TritonMoeQuantInfo.small_m_w8a16` is set;
  - M <= 4 and the weights are fp8 with fp32 block scales;
  - the expert is a plain SiLU-gated MLP: no bias, no gemm1 alpha/limit, no swiglu limit, no interleaved gate/up;
  - the router weight is not applied on the input, and `no_combine` is off;
  - there is no EP filtering.

  `inplace` writes into the hidden states, the same as the existing path.
- `Fp8MoEMethod`: sets `use_small_m_w8a16_moe` once at construction. It requires SM90, `SGLANG_OPT_HOPPER_SMALL_M_FP8_MOE=1`, block size [128, 128], and excludes MXFP8 and FP4 experts.
- `environ.py`: adds `SGLANG_OPT_HOPPER_SMALL_M_FP8_MOE` (default off).
- Unit test: checks against an fp32 dequantized reference.
  - Cases: shared-expert slot repeated across tokens, I=768 and H=7168, NaN-padded strided scales, `routed_scaling_factor`, and the `out` buffer.
  - Negative branches of both the kernel predicate and the runner gate.

## Accuracy Tests

- Kernel relative error vs fp32 dequant: 1.7e-3, against 4.4e-2 for the W8A8 Triton path.
- Qwen3.6-35B-A3B-FP8, GSM8K across 10 runs: this PR 0.960-0.965 vs stock 0.958-0.964.

## Speed Tests

Setup:
- One H100 SXM, image `lmsysorg/sglang:nightly-dev-cu13-20261012-e6072935` with this PR's files mounted.
- Stock uses the Triton runner (auto). No tuned config ships for E=257, N=512 on H100, so stock runs its default config.
- End-to-end runs were sequential on the same GPU, one server at a time, with the arm order alternated each round.
