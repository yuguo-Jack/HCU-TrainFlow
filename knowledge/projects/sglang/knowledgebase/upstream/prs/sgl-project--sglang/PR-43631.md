# [diffusion] torch.compile: serve whole graphs after offload-during-compile

[Upstream PR](https://github.com/sgl-project/sglang/pull/43631) · state: closed · merged: True

## Original PR description

## Motivation

`--offload-during-compile` (#29862, on by default) layerwise-offloads the DiT for the torch.compile warmup, so max-autotune compiles each layer with only that layer resident. Residency is restored on the first non-warmup request. That is the real-path prewarm, which still runs during startup.

The restore does not bring back whole-graph compile. The warmup traces the offload hooks, and their `torch.compiler.disable` calls graph-break inside the block loop. Dynamo then skips the DiT frame, and it applies that skip to the code object for every later call: `ConvertFrameReturn` defaults to `FrameExecStrategy(SKIP, DEFAULT)` with `apply_to_code=True`. Removing the hooks changes nothing, so every request keeps running the per-block graphs the warmup left behind.

A toy reproduction is in the new test. It is a 3-block loop with a disabled pre-hook, compiled with `CompileCounter`. After the hooks are removed, serving compiles 0 frames. With this PR it compiles one frame with all 6 ops.

## Modifications

`DenoisingStage._offload_for_torch_compile_warmup` calls `torch._dynamo.reset()` right after `disable_offload()`. The next request compiles whole graphs from the autotune results the warmup already cached, so the compile peak that #29862 caps stays capped. That request is the real-path prewarm, at startup.

## Accuracy Tests

No numerical change beyond graph partitioning: the same kernels, fused across block boundaries instead of within each block.
