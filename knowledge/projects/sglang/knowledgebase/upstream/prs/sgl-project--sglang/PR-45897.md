# [Feat] platforms: Let out-of-tree platforms bind group devices and custom ops

[Upstream PR](https://github.com/sgl-project/sglang/pull/45897) · state: closed · merged: True

## Original PR description

## Motivation

On an out-of-tree platform (here AWS Trainium via the Neuron plugin), SGLang's distributed setup can't run device collectives without these:

1. `GroupCoordinator` picks its device from a fixed cuda/npu/xpu/musa list and falls back to `cpu`.
2. `init_model_parallel_group` enables PyNccl for any device that isn't NPU or XPU, so PyNccl is created on that CPU device and fails (`ValueError: Expected a cuda device, but got: cpu`).
3. `direct_register_custom_op` registers SGLang's custom ops only for CUDA/NPU/XPU/MUSA, so `inplace_all_reduce` has no kernel for the out-of-tree device's tensors.

Today a plugin has to monkeypatch `GroupCoordinator.__init__` and `init_model_parallel_group` to work around 1 and 2.

## Modifications

- `SRTPlatform.get_group_coordinator_device(local_rank)`: consulted only when `current_platform.is_out_of_tree()`. The default is `cpu`, unchanged from today.
- `SRTPlatform.use_pynccl_by_default()`: consulted only for out-of-tree platforms, and only when the caller leaves `use_pynccl` unset. The default is `True`, unchanged from today.
- `direct_register_custom_op`: out-of-tree platforms register under `PrivateUse1`, as NPU already does. That's the dispatch key torch reserves for out-of-tree backends.
- Device selection moved into `_group_coordinator_device()` so it can be tested. In-tree branches are unchanged.
- `plugin.mdx`: documented both methods and the dispatch key.

In-tree platforms behave exactly as before. Out-of-tree platforms that don't override the new methods also behave as before, apart from the custom-op key: their ops previously registered under `CUDA`, which an out-of-tree tensor can't reach.

## Accuracy Tests

No change to model forward code.

**Unit tests (CPU).** `test/registered/unit/distributed/test_oot_group_coordinator_hooks.py` (new, 10 tests) covers:
- device selection for out-of-tree vs in-tree platforms;
- the base defaults;
- the PyNccl default matrix, including an explicit `use_pynccl` winning;
- the custom-op dispatch key for out-of-tree vs in-tree.

`test_parallel_state.py` and `test_platform_interface.py` still pass: 116 passed in total.

**Hardware (AWS trn3, 2 NeuronCores).** I ran `init_distributed_environment` plus `init_model_parallel_group` and an all-reduce on device tensors, with a minimal out-of-tree platform using the `neuron` torch.distributed backend:

| platform overrides | result |
|---|---|
| the two new methods | ranks bind `neuron:0` / `neuron:1`, no PyNccl, all-reduce of 1+2 = **3.0 on both ranks** |
| none (previous behavior) | both ranks fail at group creation: `ValueError: Expected a cuda device, but got: cpu` |

Without the `PrivateUse1` registration, the all-reduce fails with `Could not run 'sglang::inplace_all_reduce' with arguments from the 'CPU' backend`.
