# [CI] runners: Move H100 tests with no H100-specific dependency to 1-gpu-small

[Upstream PR](https://github.com/sgl-project/sglang/pull/48053) · state: open · merged: False

## Original PR description

## Summary

The H100 pool (`1-gpu-h100`) is saturated:
- **Before Nov 2:** in the 24h to 2026-11-02 it ran 993 runner-hours on 40 runners, and per-commit base-b H100 jobs waited 33 min at the median and 394 min at p90.
- **Now:** on Nov 2 the pool lost 24 of those runners and is down to 16. Its queue peaked at 412 jobs on the evening of Nov 2. At about 3pm PST on Nov 3, 286 jobs were queued, with a 5.2h median wait and the oldest waiting 16.9h.

The 5090 pool (`1-gpu-5090`) ran 525 runner-hours on 48 online runners in the 24h to Nov 2.

This PR moves 386 test files from 1-gpu-large (H100) to 1-gpu-small (RTX 5090). The only change in each test file is the `runner_config` value of its `register_cuda_ci` calls. Whole files move: a file moves only if every one of its 1-gpu-large registrations qualifies, and no file is split.

A file stays on H100 if its code (comments and docstrings excluded) shows any of:
- **Hopper-only code:** FA3, FlashMLA, DeepGEMM, HPC-Ops, exact SM90 or SM90/SM100 gates, `int8_scaled_mm`
- **A model over 26 GB,** sized from the checkpoint's weight files on the Hub
- **`lmms_eval`,** which is not installed on the Blackwell runners

This first pass also holds back anything that needs a judgment call:
- throughput or latency floors
- more than one server launch
- "SM90+" gates
- models whose size could not be determined
- combined model sizes over 26 GB

| Suite (est_time) | main | this PR |
|---|---|---|
| base-b 1-gpu-large | 118 files / 118.3 min | 62 / 93.5 min |
| base-b-kernel-unit 1-gpu-large | 289 / 199.2 min | 59 / 71.5 min |
| base-b-kernel-benchmark 1-gpu-large | 78 / 31.4 min | 16 / 12.6 min |
| extra-a 1-gpu-large | 28 / 137.6 min | 15 / 97.7 min |
| nightly 1-gpu-large | 67 / 160.9 min | 28 / 92.5 min |

Counts are from main as of 2026-11-03. Files added to main since the selection was made are left on H100 for now.

Weekly H100 tests are left alone: the weekly workflow has no 1-gpu-small job, and they add almost no H100 load.

## Workflow change

base-b, extra-a and nightly partitions are sized from est_time by `compute_partitions.py`. The JIT-kernel lanes have hard-coded shards, so `pr-test-jit-kernel.yml` changes:
- kernel-unit on 1-gpu-large goes from 2 shards to 1.
- kernel-unit on 1-gpu-small goes from 1 shard to 3.
- A new `benchmark-test-1-gpu-small` job runs the kernel benchmarks that move.
