# [Fix] diffusion/cli: Preserve explicit argv and registered aliases

[Upstream PR](https://github.com/sgl-project/sglang/pull/46155) · state: closed · merged: True

## Original PR description

## Motivation

`prepare_server_args(argv)` parses its argument list, but `get_provided_args()` then checks `sys.argv` to decide which values were explicit. Embedded launchers can lose their model path or flags, or accidentally treat unrelated process flags as user overrides.

Separately, the hand-maintained alias table misses `--pipeline`, so a parsed pipeline selection can be silently dropped.

## Modifications

- Pass explicit `argv` through argument provenance tracking; retain the process-argv fallback for existing CLI callers.
- Resolve aliases from argparse's registered destinations instead of a second alias table.
- Add focused regression coverage in the existing server-args tests, including explicit `false` and omitted defaults.

No new flags, modules, inference behavior, or default placement changes. Production code: +21/-16 lines; tests: +44 lines.

## Validation

- Both reported bugs reproduced before the fix; the same tests pass afterward.
- Remote Linux/H200: server args, sampling params, CLI helpers, and auto residency: **308 passed, 150 subtests passed**.
- One existing LTX placement expectation was deselected after reproducing the same failure on the unfixed base. The initial cold-import failure came from a read-only HF cache; it passes with a writable cache.
- Real Wan2.1-T2V-1.3B server with `--pipeline WanPipeline --mode manual --dit-cpu-offload false`: explicit Python argv preserved without modifying `sys.argv`; two consecutive 512x320, 17-frame, 4-step requests succeeded with identical raw-frame hashes. Health/liveness passed; graceful shutdown left no live children.
- Pre-commit passed. This is a configuration correctness fix, not an inference speedup claim.
