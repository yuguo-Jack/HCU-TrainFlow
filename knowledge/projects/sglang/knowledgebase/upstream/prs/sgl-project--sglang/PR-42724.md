# [Fix] parser: Llama3 Nemotron Parser

[Upstream PR](https://github.com/sgl-project/sglang/pull/42724) · state: open · merged: False

## Original PR description

## Motivation

With `--reasoning-parser auto`, `nvidia/Llama-3_3-Nemotron-Super-49B-v1` (and
`Llama-3_1-Nemotron-Ultra-253B-v1`) resolve to `deepseek-r1`, which always forces
reasoning. These models only think when the system prompt says
`"detailed thinking on"`. Their chat template mentions `</think>` only to strip
it from earlier turns and never opens `<think>`. With thinking off, the whole
answer ended up in `reasoning_content` and `content` came back **empty**.

## Modifications

- `template_detection.py`: new rule `llama_nemotron_optional_think`, keyed on
  Llama-3 headers + the `split('</think>')` idiom + no `<think>`. It sits after
  `deepseek_r1_force`, so templates that prefill `<think>` keep their parser.
- `reasoning_parser.py`: new `llama_nemotron` detector, a `Nemotron3Detector`
  subclass with `reasoning_default="explicit_enable_thinking"`, so a request
  without template kwargs does not force reasoning. Reusing `nemotron_3`
  still forced it.

DeepSeek-R1-0528 has the same `</think>`-only template shape but no Llama-3
headers, so it still resolves to `deepseek-r1`. Unchanged: DeepSeek-R1,
R1-0528, QwQ-32B, Qwen3, Nemotron-Super-v1_5.

## Testing
- 3 new unit tests: Nemotron detection, an R1-0528 negative guard, and the
  serving default. The detection test fails before the fix and passes after.
- `test/registered/unit/parser/`, `test_serving_chat.py`, and
  `test_serving_decisions.py`: 687 passed.
- End-to-end on 4x Intel Arc Pro B70 (TP4):
  - thinking off: answer is in `content`
  - thinking on: reasoning goes to `reasoning_content`
  - GSM8K 0.939, minerva_math (math_verify) 0.759
