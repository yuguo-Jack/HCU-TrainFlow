## Motivation

A monokernel plugin's forward may never read some of the attention metadata the backend builds every step. The DeepSeek-V4.1 plugin (sgl-amd-mono) scores every index source itself, so on each routed decode step the HIP radix backend builds the aiter low-ratio decode schedule and nothing reads it.

## Modifications

- `BuiltMonokernels` gets an optional `skips_metadata(name, forward_batch, key, source)`. A plugin without it gets every metadata built, as before.
- `monokernels.runtime.skips_metadata(model, ...)` returns True only on a step the plugin's forward actually runs (its graph key is served) and when the plugin opts out; `_install_forward` keeps `(built, served)` on the model.
- The HIP radix backend asks it per ratio before building the low-ratio decode schedule (`"low_ratio_decode_schedule"`). No new env knob; nothing changes without `--monokernel-backend`.
- Unit test: the skip applies only on routed steps.

## Accuracy Tests

GSM8K (1319 questions), DeepSeek-V4.1-Flash, TP4 MI355X, `--monokernel-backend amd`: 0.903 (previous mono integration: 0.899). Measured on #44353 + #44405 + this change.

## Speed Tests and Profiling

Decode TPOT (TP4, c1, median of 3), on #44353 + #44405 + this change vs the previous mono integration: 8k input 1.440 -> 1.413 ms, 128k input 1.490 -> 1.436 ms. The schedule build this skips is about 1-3% of c1 TPOT.
