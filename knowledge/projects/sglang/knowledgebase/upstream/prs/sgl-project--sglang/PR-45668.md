# [Fix] triton: Size a captured draft extend by the runner's width

[Upstream PR](https://github.com/sgl-project/sglang/pull/45668) · state: open · merged: False

## Original PR description

## Motivation

The multi-layer EAGLE draft-extend CUDA graph (`--enable-multi-layer-eagle`) lays out each request's draft tokens plus its boundary-KV front rows (`speculative_num_steps - 1` plus the conv warmup rows; 4 + 5 = 9 rows per request for Inkling-Small at 3 steps) and stamps that width on `spec_info.num_tokens_per_req`. The Triton attention backend's captured draft extend ignored it: `_update_draft_extend_buffers` strided `qo_indptr` by `num_draft_tokens`, and the captured metadata took the same number as `max_extend_len`, so every request after the first was read at the wrong rows.

The output stays correct, because verification rejects the bad drafts, but the drafts degrade: with CUDA graphs on, an Inkling-Small MTP head on Triton accepts 1.51 tokens per step instead of about 2.92, on both the default and the unified-memory pool. With CUDA graphs off, and on the FlashAttention backends, the width is read from the batch and is right.

## Modifications

- New `TritonAttnBackend._draft_extend_num_tokens_per_req`: the stamped `spec_info.num_tokens_per_req` when it is set (positive), else the previous rule (`num_draft_tokens` for the V2 draft extend, `speculative_num_steps + 1` otherwise), as the target-verify width already does.
- `_update_draft_extend_buffers` (the `qo_indptr` filled before replay) and the captured draft-extend metadata (`max_extend_len`) both take the width from it.
- A graph replays only when the batch's stamped width equals its captured one, and the plain EAGLE draft-extend graph captures exactly `num_draft_tokens`, so nothing else changes.

Test (CPU), `test/registered/unit/layers/attention/test_triton_verify_metadata.py`: `test_graph_draft_extend_uses_the_runner_width` captures and replays a draft extend with a stamped width of 9 and `num_draft_tokens` 4, and checks `qo_indptr` and `max_extend_len`; unset widths (None, -1, 0) keep 4. On main the width-9 case fails (`qo_indptr` [0, 4, 8], expected [0, 9, 18]).

## Accuracy Tests

SM90, main `76d5b3ce02`, thinkingmachines/Inkling-Small, TP 8, `--attention-backend triton`, `--speculative-algorithm NEXTN --speculative-draft-model-path thinkingmachines/Inkling-Small --enable-multi-layer-eagle --speculative-num-steps 3 --speculative-eagle-topk 1 --speculative-num-draft-tokens 4`, radix cache, overlap scheduler. Median accept length from the scheduler logs; sgl-eval GSM8K, all 1314 test questions, `--temperature 0 --max-tokens 2048`. The unified-memory servers ran with `SGLANG_DEBUG_POISON_POOL=1`, so a read of a never-written pool row shows up as a wrong answer.
