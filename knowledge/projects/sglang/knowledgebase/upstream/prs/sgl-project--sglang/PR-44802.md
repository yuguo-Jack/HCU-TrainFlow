# [Feat] tracing: Stable span names, full rid, and configured request headers on root spans

[Upstream PR](https://github.com/sgl-project/sglang/pull/44802) · state: open · merged: False

## Original PR description

## Motivation

A request's trace is hard to find and hard to group:

- Root spans are named `Req <first 8 chars of rid>`, and thread spans `Scheduler [TP 0] (host:<id> | pid:<pid>)`. With a per-request or per-process ID in the name, every span gets a unique name, which breaks grouping and aggregation by span name in tracing backends. The IDs are already recorded as attributes.
- The `rid` attribute is the rid split on `_`, to drop a worker-ID prefix that multi-tokenizer added to rids (#8964; the split came with #9962). #11295 removed that prefix, so the split now only truncates rids that contain `_`: `req_abc_123` is recorded as `123`, so a request can't be found by its rid.
- A root span carries only SGLang's own `rid`. Clients, gateways and load balancers know a request by their own IDs (`x-request-id`, a correlation ID, ...), so finding its trace means correlating timestamps across systems.

## Modifications

1. **Create root spans in one function.** `start_root_span` replaces the identical root-span code in `TraceReqContext` and `TraceReqContextAsync`, so the changes below apply to both sync and async tracing. Pure refactor, no behavior change.
2. **Stable span names; `rid` recorded as is.**
   - Root spans are named `Req`, or `prefill Req` / `decode Req` under PD disaggregation.
   - Thread spans are named `<label> [TP n] [PP n] [DP n]`; `host_id` and `pid` stay attributes.
   - The `rid` attribute is the full rid.
3. **Record configured request headers on root spans.** `SGLANG_TRACE_REQUEST_HEADERS` (comma-separated, case-insensitive) names the request headers to record. Each one present on a request is set on its root span as `http.request.header.<name>`, the OpenTelemetry semantic-convention attribute for request headers.
   - Values are cut to 1024 characters, a fixed limit rather than a setting: request IDs and hashes (UUID 36, SHA-256 hex 64, SHA-512 hex 128) are far shorter, and the limit only exists so a caller can't attach unbounded data to spans.
   - Headers are recorded exactly as listed, with no filtering, as `SGLANG_LOG_REQUEST_HEADERS` already does for request logs. The operator chooses what goes on spans.
   - `extract_trace_headers` picks these headers up alongside `traceparent`/`tracestate`, so the Engine API and gRPC paths that pass `external_trace_header` record them too.

Docs: new "Finding a Request's Trace" and "Span Names" sections in `production_request_trace.mdx`, and `SGLANG_TRACE_REQUEST_HEADERS` in `environment_variables.mdx`.

### Behavior changes for existing tracing users

| What | Before | After |
| --- | --- | --- |
| Root span name | `Req 6f97ea7f`, `decode Req 6f97ea7f` | `Req`, `decode Req` |
| Thread span name | `Scheduler [TP 0] (host:1a2b3c4d \| pid:123)` | `Scheduler [TP 0]` (`host_id`, `pid` still attributes) |
| `rid` attribute | last `_`-separated part of the rid | the full rid |
| Request headers | not recorded | recorded when listed in `SGLANG_TRACE_REQUEST_HEADERS` (unset by default) |

Queries or dashboards that match span names by prefix (`Req <id>`) or by the host/pid suffix need updating.

## Tests

- `test_trace.py::TestTraceReqContextEnabled::test_span_names_leave_out_request_and_process_ids`: root and thread span names for unified and decode roles, and the rid `req_abc_123` recorded whole.
- `test_trace.py::TestTraceFunctions::test_extract_trace_headers_adds_configured_headers`
- `test_trace.py::TestTraceReqContextEnabled::test_root_span_records_configured_headers_up_to_1024_chars`: a value longer than 1024 characters is cut, and an empty header isn't recorded.
- End to end on 2× L4 (Qwen2.5-0.5B-Instruct, spans exported to Jaeger), with a regular server at TP=2 and with PD disaggregation (NIXL):
  - Root spans are `Req` (regular) and `prefill Req` / `decode Req` (PD); thread spans are `Scheduler [TP 0] [PP 0]`, `Prefill Scheduler [TP 0] [PP 0]` and `Decode Scheduler [TP 0] [PP 0]`.
  - The rid `e2e_rid_abc_123` was recorded whole.
  - Root spans recorded the listed `x-request-id` and a second custom header, and a 2000-character `x-request-id` was recorded as its first 1024 characters.
- `test/registered/unit/observability`, `managers` and `disaggregation` fail the same tests as `main` and no others.
