# [Feat] tracing: Stable span names, record rid as is, and don't trace health checks

[Upstream PR](https://github.com/sgl-project/sglang/pull/44802) · state: open · merged: False

## Original PR description

## Motivation

- Root spans are named `Req <first 8 chars of rid>`, and thread spans `Scheduler [TP 0] (host:<id> | pid:<pid>)`. With a per-request or per-process ID in the name, every span gets a unique name, which breaks grouping and aggregation by span name in tracing backends. The IDs are already recorded as attributes.
- The `rid` attribute is the rid split on `_`, to drop a MultiTokenizer worker prefix that rids no longer carry. It truncates any rid containing `_`: `req_abc_123` is recorded as `123`, so a request can't be found by its rid.
- `/health` and `/health_generate` submit a one-token generation request (rid `HEALTH_CHECK_<uuid>`), and the tokenizer traces it like any other. With tracing on, every probe of every server adds a trace, burying user requests in trace search and sampling.

## Modifications

1. **Create root spans in one function.** `start_root_span` replaces the identical root-span code in `TraceReqContext` and `TraceReqContextAsync`, so the changes below apply to both sync and async tracing.
2. **Stable span names; `rid` recorded as is.**
   - Root spans are named `Req`, or `prefill Req` / `decode Req` under PD disaggregation.
   - Thread spans are named `<label> [TP n] [PP n] [DP n]`; `host_id` and `pid` stay attributes.
   - The `rid` attribute is the full rid.
3. **Don't trace health checks.** `init_trace_ctx` gives `HEALTH_CHECK_*` rids a null trace context, in both sync and async tracing. `request_metrics_exporter` already skips these rids for the same reason.

Docs: new "Span Names" section in `production_request_trace.mdx`.

### Behavior changes for existing tracing users

| What | Before | After |
| --- | --- | --- |
| Root span name | `Req 6f97ea7f`, `decode Req 6f97ea7f` | `Req`, `decode Req` |
| Thread span name | `Scheduler [TP 0] (host:1a2b3c4d \| pid:123)` | `Scheduler [TP 0]` (`host_id`, `pid` still attributes) |
| `rid` attribute | last `_`-separated part of the rid | the full rid |
| Health checks | traced | not traced |

Queries or dashboards that match span names by prefix (`Req <id>`) or by the host/pid suffix need updating.

## Tests

- `test_trace.py::TestTraceReqContextEnabled::test_span_names_leave_out_request_and_process_ids`: root and thread span names for unified and decode roles, and the rid `req_abc_123` recorded whole.
- `test_req_time_stats.py::TestInitTraceCtx::test_health_checks_are_not_traced`
- End to end on 2× L4 (Qwen2.5-0.5B-Instruct, spans exported to Jaeger):
  - Regular server, TP=2: the root span is `Req` and the thread span is `Scheduler [TP 0] [PP 0]`.
  - PD disaggregation (NIXL): roots are `prefill Req` and `decode Req`, thread spans are `Prefill Scheduler [TP 0] [PP 0]` and `Decode Scheduler [TP 0] [PP 0]`.
  - The rid `e2e_rid_abc_123` was recorded whole, and repeated `/health_generate` probes produced no traces.
- `test/registered/unit/observability`, `managers` and `disaggregation` fail the same tests as `main` and no others.
