# [Fix] dLLM: Reject unknown algorithm config keys

[Upstream PR](https://github.com/sgl-project/sglang/pull/44385) · state: open · merged: False

## Original PR description

## Motivation

A typo in `--dllm-algorithm-config` can pass unnoticed. For example, LowConfidence accepts `threshhold: 0.8` but still uses the default `threshold` of `0.95`. This PR rejects unknown keys at startup and reports the algorithm and key name.

Related to #39499, Phase 1: reject unknown algorithm configuration keys.

## Modifications

- Check config keys at startup for all four built-in dLLM algorithms.
- Also check keys in Gemma4Renoise's nested config sections.
- Keep existing valid options and defaults. For Gemma4Renoise, a nested value still takes priority when the same option is set at the top level.
- Add CPU regression tests and update the docs.

## Accuracy Tests

The following tests passed in a Linux ARM64 Docker container with Python 3.12.14 and PyTorch 2.13.0+cpu: **52 tests and 62 subtests**, with no skips.

For comparison, the new `test/registered/unit/dllm/test_config.py` was run against the unchanged Python source from base commit `0cf683ea`. All 14 rejection subcases failed because no `ValueError` was raised; all 23 valid-config and default-value subtests passed.

Pre-commit passed for all changed files. `mint validate` also passed.
