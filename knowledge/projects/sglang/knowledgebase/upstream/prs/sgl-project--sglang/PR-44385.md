# [Fix] dLLM: Reject unknown algorithm config keys

[Upstream PR](https://github.com/sgl-project/sglang/pull/44385) · state: open · merged: False

## Original PR description

## Motivation

A typo in `--dllm-algorithm-config` can pass unnoticed. For example, LowConfidence accepts `threshhold: 0.8` but still uses the default `threshold` of `0.95`. This PR rejects unknown keys at startup. The error names the algorithm and lists the supported keys.

Related to #39499, Phase 1: reject unknown algorithm configuration keys.

## Modifications

- Check config keys at startup for all four built-in dLLM algorithms.
- Also check keys in Gemma4Renoise's nested config sections.
- Accept `capture_input_preparation` only for algorithms that support it.
- Keep existing defaults. For Gemma4Renoise, a nested value still takes priority when the same option is set at the top level.
- Add CPU regression tests and update the docs.
