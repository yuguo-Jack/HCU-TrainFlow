# [DSv4.1] Prefill indexer: raw selection, row-pair schedule ids, no host syncs

[Upstream PR](https://github.com/sgl-project/sglang/pull/41659) · state: closed · merged: True

## Original PR description

> (auto generated by Claude)

Part of #41589 (DeepSeek-V4.1 prefill optimizations, split into smaller PRs).

## Motivation

The low-ratio (ratio 1/2) prefill indexer ran many small kernels per layer, sorted and remapped its selection before attention, had a schedule that is quadratic in a request's rows, and synchronized with the host several times per step.

## Modifications

- **Fused index-Q kernel in the prefill indexer**: prefill query and head-weight prep goes through `index_q_rope_pack_weights` (`_index_q_and_weights`), shared with decode.
- **Prefill top-k written straight into the raw selection**: the DeepGEMM prefill top-k emits request-local compressed positions directly into the buffer sparse prefill reads. Pool slots (`page_indices`) are only derived when this forward's attention reads them (trtllm, non-sparse extend, sm120, late-layer tail, request window, or `SGLANG_OPT_FLASHMLA_SPARSE_PREFILL` off). `Selection` is removed; the output buffers are fields of `PrefillInputs` / `DecodeInputs` / `CapturedPrefillInputs`. `write_selection` keeps only the CP dense-blocks path and no longer sorts.
- **Row-pair request ids for the paged sparse indexer schedule**: DeepGEMM's paged sparse-logits metadata walks back over equal request ids once per row. Ids unique per consecutive row pair of a request (never spanning two requests) bound the walk to one step; logits are unchanged.
- **No host syncs in the prefill forward**:
  - `get_deep_gemm_prefill_data` builds the flattened-K layout for the whole batch from host lengths instead of a per-request loop indexing with device scalars.
  - New `async_h2d` in `srt/utils/common.py` (pinned, non-blocking; the counterpart of `async_d2h`), used for the request starts, row-pair ids, CP rows, tail rows, and the engram history.
  - Engram's `repeat_interleave` takes `output_size` from `extend_seq_lens_cpu`.
- **No `record_stream` on the mHC stats input**: the stats kernels read the residual on the side stream, and every consumer joins that stream on the main stream while the residual is still referenced, so `record_stream` only delayed the reuse of each freed residual. Without the host syncs the host runs further ahead, and those delayed frees piled up to several full residuals and exhausted the allocator.
- **Tests**: `test_dense_prefill_indexer.py` and `test_dsv4_nonpaged_indexer.py` follow the new interfaces.

**Operator checks and caveats**

Operator measurements used `a318be682f333b342f3d87e562af9debc270b09a`. The updated head only changes mHC `record_stream` handling; the measured indexer/kernel files are byte-identical. Model tests above use the updated head, and relevant unit tests were rerun on it.

For 16,384 rows, Q/layout preparation excluding projection GEMMs changed from **571.77 to 228.16 µs** for one request, and **3,435.20 to 246.61 µs** for 64 requests. These are eager wall timings including synchronization.

With context 40,000 and 2,048 candidate blocks, row-pair schedule preparation changed from **12,624.04 to 360.34 µs** at 16,384 rows (**865.74 to 94.25 µs** at 4,096 rows). Actual DeepGEMM valid sparse logits were bitwise equal with identical packed inputs; unused output tails were excluded.

There are two numerical qualifications:

- Fused Q preparation is not universally bitwise identical. A synthetic `1×1×128` replay changes one FP4 packed byte, while scales and head weights agree. The boundary behavior is consistent with a changed RoPE FMA ordering; it is not proof of the exact emitted instruction sequence. On affected synthetic rows, subsequent actual sparse-logits Top-512 intersections were **505–511/512**. `repro_q_boundary.py` plus `q-boundary-input.json` is a small standalone replay. This is distinct from the model-level quality results above.
- Removing selection sorting changes attention accumulation order. For identical KV sets in the sparse-attention replay, base/head relative L2 was about **0.0027**; both were about **0.0021** versus an FP64 reference on sampled rows. This is not bitwise attention equivalence.

The measured schedule benefit is independent of those Q-preparation/order changes.
