# [CI] Rebuild local Rust packages in the shared Cargo cache

[Upstream PR](https://github.com/sgl-project/sglang/pull/43879) · state: open · merged: False

## Original PR description

## Problem

CI runners on the same host share one Cargo target dir. Cargo treats our own crates as up to date if their source files are older than the cached build, and it doesn't check where that build came from. So a job can pick up crates another PR built and compile against that PR's code.

This broke [PR #43625's tier-3 job](https://github.com/sgl-project/sglang/actions/runs/38209190912/job/114680754874?pr=43625): `sglang-api-types` was reported `Fresh` with fields from another PR (`GenerateResponse.text`, `OpenAiStreamChunk.status_code`), and `sglang-grpc` failed with E0063. Neither field exists on main. The same thing can also happen silently, shipping another PR's code in an extension with no compile error.

## Fix

Before building the Rust extensions, while holding the existing cache lock, run `cargo clean --release` on our own crates: the `rust/` workspace plus `sglang-radix-tree`, which `setup.py` builds from its own workspace. Third-party crates stay cached.

`cargo clean` has to be told where the builds are: it defaults to the dev profile and the host target, so the cleanup passes `--release`, plus `--target` when `CARGO_BUILD_TARGET` is set (setuptools-rust then builds into `<target>/release`).

**Cost:** jobs that build Rust from source now always rebuild our own crates. Jobs using prebuilt extensions, and diffusion jobs, are unaffected. The added time will show up in this PR's first CI run.

## Validation (Rust 1.92, the CI pin)

- Reproduced the failure with the real crates and the installer's own `setup_cargo_cache`. Without `--release`: `Removed 0 files`, stale `sglang-api-types` is `Fresh`, same E0063. With this PR: our crates rebuild and compile, and third-party crates stay `Fresh`.
- Confirmed the `sglang-radix-tree` artifacts are removed too.
- With `CARGO_BUILD_TARGET` set: without `--target` the cleanup removes 0 files and the stale crate stays `Fresh`; with it, the crate rebuilds.
- `python -m unittest scripts.ci.test_diffusion_rust_gate`, `bash -n`, and pre-commit pass.
