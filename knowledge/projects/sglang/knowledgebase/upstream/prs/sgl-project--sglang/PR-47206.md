# [Fix] parser: Resolve reasoning end markers to their token ids

[Upstream PR](https://github.com/sgl-project/sglang/pull/47206) · state: open · merged: False

## Original PR description

Fixes #47205

## Motivation

Reasoning detectors build `think_end_ids` by encoding the end marker's text, and `ReasonerGrammarObject` keeps a request's grammar off until the generated ids match that sequence. When the tokenizer does not parse special tokens out of text (`split_special_tokens=True`), a special added marker such as gpt-oss's `<|end|>` encodes to ordinary ids the model never generates. The gate never opens, so `require_reasoning` requests (structured output, forced tool calls) run without their grammar and nothing reports it. Resolving the marker by id in the shared detector path fixes this for every detector instead of one override at a time.

## Effect

`get_think_end_token_ids` with `split_special_tokens=True`:

| Model | Marker | Before | After |
|---|---|---|---|
| gpt-oss-20b | `<\|end\|>` | `[27, 91, 419, 91, 29]` | `[200007]` |
| gpt-oss-120b | `<\|end\|>` | `[27, 91, 419, 91, 29]` | `[200007]` |

Default loading is unchanged, and so are markers that are added tokens not marked special.

## Modifications

- New `marker_token_ids` helper resolves a single special or added-token marker by id.
- Other markers, including unknown ones, keep text encoding.
- Base and response-template reasoning detectors use the helper.

## Accuracy Tests

Not applicable: tokenizers that parse special tokens from text get the same ids as before.

## Speed Tests and Profiling

Not applicable: the ids are computed once at scheduler start-up.
