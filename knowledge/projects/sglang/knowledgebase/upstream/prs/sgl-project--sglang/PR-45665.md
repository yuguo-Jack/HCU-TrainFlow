# [Perf] [AMD] KDA: Fuse gfx950 prefill state and output

[Upstream PR](https://github.com/sgl-project/sglang/pull/45665) · state: closed · merged: False

## Original PR description

## Motivation

KDA chunked prefill currently materializes the recurrent state for every 64-token chunk and the corrected value tensor in `chunk_gated_delta_rule_fwd_h`, then reads both back in `chunk_gla_fwd_o_gk`. For GLM-5.3-Flash prefill on gfx950 this creates an avoidable HBM round trip between the state recurrence and output calculation.

This change adds an opt-in gfx950 chain kernel that keeps each FP32 `[BV, K]` recurrent-state slice on chip while walking all chunks and produces the output in the same launch.

## Modifications

- Add a gfx950 Triton KDA chain kernel for BF16 Q/K/V/W/A, FP32 per-channel gates, `K=V=128`, and varlen batches.
- Keep recurrent state in FP32 across the chunk walk; write only the output, optional FP32 tracking snapshot, and final state.
- Preserve `-1` state-index semantics, envelope-strided state pools, partial tail chunks, deterministic accumulation, and CUDA-graph replay.
- Add the default-off `SGLANG_OPT_KDA_CHAIN_PREFILL` selector.
- Restrict dispatch to measured 16,384-token cells:
  - TP4 geometry: 16 local heads and 3 sequences.
  - TP8 geometry: 8 local heads and 2, 3, or 4 sequences.
- Preserve the existing state/output path for every unsupported or unmeasured dtype, shape, layout, hardware, tracking contract, and selector state.
- Add registered gfx950 correctness tests and a multi-sequence benchmark.

Enable with:

```bash
SGLANG_OPT_KDA_CHAIN_PREFILL=1
```

## Accuracy Tests

On MI355X/gfx950, 22 focused tests passed. Coverage includes TP4/TP8 head geometries, ragged boundaries at 1/63/64/65/127 tokens, long 4×4,096-token inputs, multiple sequences, `-1` state indices, envelope-strided state storage, zero/nonzero state evolution, FP32 tracking snapshots, finite outputs, deterministic replay, CUDA-graph replay, and dispatch fallbacks.

The fused output matches the existing two-kernel path within one BF16 output quantum (`atol=6.2e-5`, `rtol=8e-3`); final BF16 recurrent state is bit-exact. Tracking snapshots retain the FP32 accumulator and round bit-exactly to the existing BF16 chunk-boundary state.
