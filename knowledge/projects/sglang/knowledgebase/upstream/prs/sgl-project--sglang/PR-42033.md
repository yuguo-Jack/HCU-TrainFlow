# fix: include Rust health probe admission in timeout

[Upstream PR](https://github.com/sgl-project/sglang/pull/42033) · state: open · merged: False

## Original PR description

## Motivation

A full intake queue can leave the Rust health probe waiting past its timeout. It can also hide healthy activity from requests that are already running.

## Changes

Watch one deadline and the scheduler heartbeat while the probe waits for admission. Return `Stalled` when the deadline expires, or `Healthy` when existing work produces output. Dropping the pending submission cancels it through the existing guard. An admitted probe stays alive until the health decision and is then cleaned up.

The updated branch keeps the move from the frontend into `api_server/core/handle.rs`. The health endpoints and public settings stay the same.

## Tests

Both new regressions use the real core handle and a blocked intake channel. They check the timeout, healthy activity, and cleanup without leftover intake or abort work.

Restoring the current main health method makes each new regression fail. With the fix, all 16 core handle tests and all six tests selected by the health filter pass.

Strict server library and test Clippy, matching precommit hooks, and formatting pass. The Rust hooks also check the whole workspace, optional multimodal features, and radix tree.

Checks ran on macOS ARM64 with Rust 1.92. No GPU inference or complete server test suite was run for this update. AI assistance was used for implementation and validation.
