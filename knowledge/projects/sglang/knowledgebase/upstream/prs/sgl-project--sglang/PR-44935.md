# [Refactor] dspark: Let a megakernel plugin run the DSpark draft proposal

[Upstream PR](https://github.com/sgl-project/sglang/pull/44935) · state: closed · merged: False

## Original PR description

## Motivation

SGLang loads an out-of-tree kernel plugin through `--monokernel-backend` (`sglang.srt.monokernels`). The NVIDIA megakernel plugin for DeepSeek-V4.1-Flash on GB300 (sgl-project/sgl-nvidia-mega#1) runs covered decode steps through the framework's existing forward entry, with its own step code over SGLang's loaded weights, so it needs no change to SGLang's model code.

One part of a DSpark step sits outside the model's forward: the draft proposal (`compute_base_logits` + `draft_markov_block` in the DSpark draft sampler). The plugin runs that proposal as one vocabulary-sharded kernel per rank. This PR adds the single framework entry point that needs.

## Modifications

1. `monokernels/runtime.py`: `install_monokernel_forward` keeps the object the spec built on the model, readable with `built_monokernels(model)`.
2. `monokernels/spec.py`: `BuiltMonokernels` documents an optional `draft_sampler` factory.
3. `speculative/dspark_components/dspark_draft_sampler.py`: `maybe_build_draft_sampler` calls the factory once with (gamma, max_bs, greedy_draft, noise, draft_tokens, step_logits, step_temperatures). The factory returns a function of the batch size. At each size, that function returns either the step that replaces `compute_base_logits` + `draft_markov_block`, or `None` to keep SGLang's proposal. When the factory is set, a sampled draft's `step_logits` are allocated zeroed up front. The factory is not gated on the draft spec's served keys.

Without a monokernel backend, or without the factory, the proposal runs exactly as today. There are no new server arguments or environment variables.

## Accuracy Tests

CPU unit tests:
- `TestMonokernelDraftSampler` (`test/registered/unit/spec/test_dspark_draft_block.py`): a plugin step replaces only the base logits and the Markov block, and its outputs land in SGLang's buffers; without a plugin step, the stock proposal runs with the same arguments.
- `test/registered/unit/monokernels/test_mono_framework.py`: the runtime keeps the built object on the model, and `built_monokernels` returns `None` without one.

End-to-end results with the plugin's draft proposal will be added.

## Speed Tests and Profiling

No change without a plugin that sets the factory.
