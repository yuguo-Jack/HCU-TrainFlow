# [Perf] [NVIDIA] dsv41: Use the fused low-ratio compressor on Hopper

[Upstream PR](https://github.com/sgl-project/sglang/pull/41294) · state: open · merged: False

## Original PR description

## Motivation

Hopper still runs the split DSv4.1 low-ratio compressor: two projection GEMMs, then pooling, RMSNorm, the index-K store and the FlashMLA cache store as separate launches. Hopper uses the V4 cache layout, which the fused c1/c2 and index-K kernels already write on SM100 and gfx950, and those kernels build and pass on SM90.

## Modifications

- `fused_low_ratio_compress_supported()` also returns True on SM90, so Hopper loads the packed `wkv_gate` weight and takes the same fused decode/verify path as SM100 (like #41308 did for gfx950).
- Run `test_dsv41_fused_compress.py` on the H100 runner and drop its three HIP-only skips. All four cases pass on H100.
- Since #41660 the same gate also sends eager extend through `c2_prefill_norm_rope_store`, so `test_c2_prefill_ring.py` now runs on SM90 and on the H100 runner too. It passes on H100.

## Accuracy Tests

As on SM100, the fused path is not bit-identical to the split path. DeepSeek-V4.1-Flash on 8xH200, TP8/EP8, no speculative decoding, each arm started twice:

| | GSM8K, 200 questions, 5-shot | greedy outputs identical to baseline (32 LongBench prompts x 512 tokens) |
|---|---|---|
| main | 179, 177 | 32/32 between the two runs |
| this PR | 175, 177 | 29/32 |

McNemar p >= 0.29 for every pair. Mean prefill/decode k3 on the sampled tokens: 0.00584 vs 0.00592.

With DSpark (`--speculative-dspark-block-size 5`), target verify takes the fused path with `draft_len=6` on every rank. Full GSM8K test split (1314 questions after the 5 shots), each arm started twice:

| | correct / 1314 | tokens per verify |
|---|---|---|
| main | 1172, 1170 | 3.45, 3.45 |
| this PR | 1181, 1185 | 3.44, 3.44 |

McNemar p is between 0.10 and 0.34 for every main/PR pair.

## Speed Tests and Profiling

One compressor layer on H100, including the projection GEMMs, CUDA graph, cold L2 (16 rotated weight sets, 160 MiB):

| | bs 1 | bs 64 |
|---|---|---|
| ratio 2, main -> this PR | 35.0 -> 14.3 us | 39.1 -> 20.0 us |
| ratio 1, main -> this PR | 27.4 -> 14.1 us | 30.6 -> 17.7 us |

Only the four kv_source layers (three ratio 2, one ratio 1) run a compressor, so that is about 75 us per decode step. End to end it is small but visible; median ITL from `bench_serving` (random ids, 1024 in / 512 out) on the 8xH200 setup above:

| concurrency | main (2 runs), ms | this PR (2 runs), ms |
|---|---|---|
| 1 | 12.40 / 12.26 | 12.19 / 12.19 |
| 8 | 17.26 / 17.27 | 17.19 / 17.19 |
| 32 | 20.47 / 20.47 | 20.34 / 20.35 |

The per-layer table and both tests are from main at 4ae54e9 on 1x H100. The accuracy and ITL tables are from 4dfc0ac. On a34cba3 (after #41660) I reran the full model: GSM8K is 1178 vs 1182 / 1314 without speculative decoding, and decode and eager extend take the fused kernels on all 8 ranks. I have not rerun the full model on anything newer.
