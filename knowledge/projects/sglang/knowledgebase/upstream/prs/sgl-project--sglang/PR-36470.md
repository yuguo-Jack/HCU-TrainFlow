- BBuf · comment · 2026-08-27T03:28:40Z · [source](https://github.com/sgl-project/sglang/pull/36470#issuecomment-5433990845)

I rebased this PR onto `bede6bc37c5d9638099ebb948d93b9e2a7799f10` (`8ec2101b49` locally) and validated the native `flux2-klein` preset on one NVIDIA RTX PRO 6000 Blackwell Server Edition 96 GB (SM120), PyTorch `2.13.0+cu130`, CUDA 13, Triton 3.7.1.

The functionality works: the warmup captured 26 BCG segments with five tensor inputs, and both lossless and high-quality outputs were byte-identical to eager (`SSIM=1`, `PSNR=inf`). Focused tests also passed (208 tests + 48 subtests).

For the registered 1024x1024, four-step workload, however, the performance is neutral on this GPU:

| Path | Denoise A / B | Mean | E2E mean | Peak reserved |
|---|---:|---:|---:|---:|
| main eager | 419.392 / 419.005 ms | 419.199 ms | 658.513 ms | 13,712 MB |
| this PR, BCG | 418.407 / 418.780 ms | 418.593 ms | 659.987 ms | 14,754 MB |

That is a 0.14% denoise change (within run-to-run noise), a 0.22% E2E regression, and +1,042 MB peak reserved memory. The high-quality BCG run was 423.677 ms denoise versus 419.981 ms eager. Main correctly logs that BCG is disabled for `Flux2KleinPipelineConfig`, so I did not count its flag-ignored run as BCG evidence.

In short: capture/replay correctness is validated, but I would present this as a capability extension rather than an RTX PRO 6000 speedup for the default four-step Klein workload.

I temporarily added the Base 4B/9B model IDs and `Flux2KleinBasePipelineConfig` to this PR's allowlists. Capture succeeds with 26 segments and 6 tensor inputs, and both lossless runs plus the high-quality run are byte-exact against eager output.

| path | denoise (two-run mean) | peak reserved |

| eager | 10.4463 s | 13,734 MB |

So Base BCG is 0.98% slower and uses 1,042 MB more peak reserved memory. The high-quality BCG run is also slower (10.5721 s vs 10.4642 s eager). This matches the distilled 4B result above: capture/correctness work, but there is no performance case for expanding the allowlist to Base on SM120.
