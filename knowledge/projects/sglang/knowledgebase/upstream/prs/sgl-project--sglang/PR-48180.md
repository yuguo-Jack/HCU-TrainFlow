# [Fix] openai: Keep one BOS on text-only multimodal prompts

[Upstream PR](https://github.com/sgl-project/sglang/pull/48180) · state: open · merged: False

## Original PR description

## Motivation

SGLang gives `LiquidAI/LFM2.5-VL-450M` two BOS tokens on text-only chat, Responses and Anthropic messages requests. This fix changes its prompt ids from `[1, 1, 6, ...]` to `[1, 6, ...]`, matching `/v1/tokenize`. Two other LFM2 VL models, Gemma 3 with `--enable-multimodal`, Llama 3.2 Vision and Nemotron Nano VL behave the same, and Gemma 4 joins them once #41204 lands.

The measured cost is one extra input token per text-only request and a prompt that differs from the chat template output. Some text-only answers also changed, but run variation was not ruled out. GSM8K on `LiquidAI/LFM2.5-VL-1.6B` shows no regression or improvement, because scores on one tree vary by up to 2.5 points.

Merged #26505 fixed this doubling only for media requests. Open PR #30876 (not run) would also remove it, but it conflicts with main and has been idle since July.

On a multimodal model, `_engine_prompt` sends decoded text, and `TokenizerManager` re-encodes it with default specials, so an auto-adding tokenizer doubles the chat template's BOS.

## Modifications

`_engine_prompt` sends the encoded ids when a request has no media, the tokenizer auto-adds specials, and the ids start with the BOS. Prompts without a leading BOS keep the text path and the tokenizer's BOS. Raw `/generate` text does not change.

## Accuracy Tests

These results are from before I squashed this branch onto main `7b88f09239`. The squash kept the same diff, and I did not repeat these runs on it. On the squashed commit, only pre-commit and `test_chat_prompt_round_trip.py` ran, on CPU, and the test file found no failure.

GSM8K ran with sgl-eval 0.1.3 on `LiquidAI/LFM2.5-VL-1.6B` with the cookbook backends, `--mem-fraction-static 0.5`, 200 examples, max tokens 512 and seed 0.

- Temperature 0: 68.00%, 69.00%, 66.50% before and 69.50%, 68.50%, 69.50% after. Only the first pair set the IPC env vars.
- Temperature 0.1 (cookbook value), with both env vars: 67.00% before and 68.00% after.

sgl-eval has no flags for `min_p` and `repetition_penalty`.

Image prompt ids stay identical. Image answers matched, except the last tokens in one Nemotron and one LFM2.5-VL-450M run.

The new server and unit tests fail before the fix. With it, they and `TestLfm2VlServer` pass on the cookbook backends.

Not checked: `TestLfm2VlServer` on H100, text models (traced only), PD or EPD disaggregation, the Rust frontend, any server on main after `cbfc0932e3`, and the cause of the variation.
