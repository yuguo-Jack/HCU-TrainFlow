# [Diffusion] Fuse FLUX3 SwiGLU with rowwise FP8 quantization

[Upstream PR](https://github.com/sgl-project/sglang/pull/42758) · state: open · merged: False

## Original PR description

## Motivation

FLUX3 FP8r MLP output projections materialize a BF16 SwiGLU activation, then launch a separate rowwise FP8 quantization kernel. Fuse these producers to remove the intermediate activation write/read and one kernel launch while preserving the existing quantized linear output.

## Modifications

- Add `fused_packed_swiglu_fp8_rowwise`: packed/row-strided BF16 `[B,T,2*K]` → padded E4M3 activations and FP32 per-row scales. Preserve both BF16 rounding boundaries, the scale floor, FP8 conversion and padding semantics.
- Integrate the fusion into FLUX3 FP8r MLP output projections on NVIDIA SM89+ for supported layouts and widths. Unsupported inputs and compilation retain the existing path. The downstream GEMM remains `torch._scaled_mm`.
- Use nine 1024-element tiles for SM89 `K=9216`, avoiding a masked 16384-element row. Other supported widths/devices retain the full-row implementation.
- Add lazy kernel registration, numerical and model integration tests, operator documentation, and a standalone microbenchmark.

## Accuracy Tests

Local GPU validation: RTX 4090 D (SM89), PyTorch 2.13.0+cu130, Triton 3.7.1.
For both `fp8r` and `sd-fp8r`, final action arrays are **byte-identical** before and after fusion on two synthetic observations (seeds 0 and 42) and one real DROID observation (seed 0):

- Maximum absolute difference: **0**
- Output shape: `(32, 8)`
- All output values are finite

## Speed Tests and Profiling

### Standalone fused kernel

Measured on one **RTX 4090 D**, using synthetic BF16 packed slices with row stride `3*K`.

- **Before:** existing fused packed SwiGLU kernel followed by the existing rowwise FP8 quantizer.
- **After:** the new single fused SwiGLU + FP8 producer.

GEMM is excluded from this table. Measurements use 10 warmup calls per path, five alternating-order rounds of 100 ms, and median GPU time. The microbenchmark uses `triton.testing.do_bench_cudagraph` to exclude Python launch overhead.

| Rows M | Width K | Before (µs) | After (µs) | Latency reduction | Speedup |
|---:|---:|---:|---:|---:|---:|
| 1 | 9216 | 9\.38 | 4\.27 | 54\.40% | 2\.19× |
| 32 | 9216 | 7\.25 | 2\.71 | 62\.63% | 2\.68× |
| 340 | 9216 | 20\.19 | 8\.76 | 56\.63% | 2\.31× |
| 2720 | 9216 | 223\.98 | 136\.75 | 38\.95% | 1\.64× |
| 3173 | 9216 | 264\.62 | 159\.22 | 39\.83% | 1\.66× |
| 3173 | 3072 | 31\.04 | 26\.84 | 13\.53% | 1\.16× |

### End-to-end model

Measured with local `flux-3-action-droid` checkpoints on one **RTX 4090 D**, using default eager serving settings, concurrency 1, and a warm caption cache.

Each configuration runs three rounds of 20 measured requests, with 10 initial warmups and two warmups before subsequent rounds. Results are the median of the three server-side inference latency medians, excluding network and client serialization. Only SwiGLU + FP8 fusion changes between the baseline and this PR.

| Variant | Before (ms) | After (ms) | Latency reduction |
|---|---:|---:|---:|
| fp8r | 1164\.04 | 1144\.74 | **1\.66%** |
| sd-fp8r | 209\.68 | 204\.84 | **2\.31%** |

Denoising latency also decreases:

| Variant | Before (ms) | After (ms) |
|---|---:|---:|
| fp8r | 1110\.23 | 1090\.08 |
| sd-fp8r | 153\.71 | 150\.10 |
