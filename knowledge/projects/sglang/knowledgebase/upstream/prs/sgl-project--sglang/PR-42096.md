# Return the existing error for missing weight-export groups

[Upstream PR](https://github.com/sgl-project/sglang/pull/42096) · state: closed · merged: False

## Original PR description

## Motivation

Fixes #42073. Sending weights with an uninitialized group, or repeating a send after its group was consumed, raises `KeyError` before the existing failure response can run. This exception escapes the scheduler's control handler.

## Modifications

Look up the resolved rank-specific group with `dict.get`, allowing the existing failure message to reach the HTTP layer as a 400. Registered groups retain their existing broadcast and destruction behavior.

## Accuracy Tests

- Four permanent CPU tests pass; the original source fails two. Cover missing/other-rank and explicit `None` entries, successful send followed by repeated send, and broadcast-error cleanup.
- An actual-source HTTP → tokenizer control → scheduler → TP worker → exporter probe returns 400/200/400 for missing/registered/consumed groups (original: 500/200/500). The IPC transport and GPU/distributed boundaries are doubled; this does not launch a scheduler process or execute NCCL. The local test harness excludes eager GPU package initialization.
- All applicable pre-commit hooks pass.
