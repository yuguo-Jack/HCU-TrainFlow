# [Fix] [AMD] disaggregation: Pair MoRI DSA state across PP prefill stages

[Upstream PR](https://github.com/sgl-project/sglang/pull/48382) · state: open · merged: False

## Original PR description

## Motivation

PD over MoRI breaks as soon as the prefill server runs a DSA model with PP > 1. MoRI registers the DSA indexer state without layer ids, and `build_transfer_entry_pairs` only falls back to positional pairing at PP = 1. A prefill stage has only its own layers while decode has all of them, so every state send fails with `PP-heterogeneous transfer requires layer ids on both peers`.

Seen with GLM-5.2 on MI355X (prefill TP1 PP4, decode TP4).

## Modifications

- `MoriKVManager._send_swa_dsa_state`: when DSA state has no layer ids and PP > 1, map each prefill stage onto the decode entries starting at its first layer via `get_mla_kv_ptrs_with_pp`, same as Mooncake. Raise before writing if decode doesn't have enough entries.
- Skip this for hybrid linear+DSA pools (e.g. GLM-5-Next). Their DSA entries only cover full-attention layers, so slicing by model layer would pair the wrong layers.
- Nothing else changes. The new path only runs in cases that used to raise.
- Added `TestMoriPpDsaStatePairing`: checks the GLM-5.2 PP4 stage pairing, and that SWA without layer ids, a decode overrun and a hybrid pool all raise before any write.

## Accuracy Tests

GLM-5.2 MXFP4, MoRI PD on MI355X: prefill TP1 PP4, decode TP4 + DP attention, MTP, HiCache.
GSM8K with lm-eval 0.4.9.2, full test set (1319), 5-shot, greedy:

| | exact_match |
|---|---|
| strict-match | 0.9697 ± 0.0047 |
| flexible-extract | 0.9719 ± 0.0045 |

No before/after comparison since this setup didn't run at all before the fix. Measured on a v0.5.22 ROCm image with #28827 and the same pairing logic patched in.
