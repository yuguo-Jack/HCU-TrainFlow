# Fix Responses API additional_tools input handling

[Upstream PR](https://github.com/sgl-project/sglang/pull/41178) · state: open · merged: False

## Original PR description

## Motivation

`/v1/responses` still rejects `additional_tools` before inference. Tool definitions added during a conversation must remain available for validation, parsing and continuation without moving their declaration earlier in the prompt.

## Changes

- Accept inline function, custom and namespace tools; reject unsupported definitions and duplicate qualified names.
- Preserve declaration order, namespace identities, named tool choices, streaming and stored continuations.
- Retain upstream Muse namespace metadata, Beam tool translation, raw input preservation and the current output adapters.
- Preserve inline tool messages through the current DeepSeek recipe encoder, which otherwise drops message-level tool schemas during Chat Completions conversion. Harmony retains flat function support.

## Validation

The effective-inventory collector has the same function AST as the original PR. The original regression scenarios are retained with their retired encoder fixture adapted to the current reference renderer. Python syntax and undefined-name checks pass; a direct reference-renderer check preserves the order of user text, tool declaration and later user text. No full suite or GPU validation was rerun after the upstream merge.
