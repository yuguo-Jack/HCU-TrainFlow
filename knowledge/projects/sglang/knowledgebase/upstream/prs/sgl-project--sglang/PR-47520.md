# [Doc] [AMD] cookbook: Add Qwen3.8-Flash-Next MI355X AgentX recipe

[Upstream PR](https://github.com/sgl-project/sglang/pull/47520) · state: closed · merged: True

## Original PR description

## Motivation

[InferenceX #4680](https://github.com/SemiAnalysisAI/InferenceX/pull/4680) adds the MI355X AgentX lane `qwen3.8next-fp4-mi355x-sglang-agentic-mtp`. InferenceX requires its production serving settings on a merged SGLang cookbook page before the PR merges. The Qwen3.8-Flash-Next page has no command for this lane: the Deploy panel's MI355X cells serve the BF16 and FP8 checkpoints at TP8 without MTP, and the generated AgentX explorer has no AMD lanes.

## Modifications

- `docs/cookbook/autoregressive/Qwen/Qwen3.8-Flash-Next.mdx`: under Agentic Long-Context Deployment, after the `<AgentX>` explorer, add an MI355X subsection in the form of the GLM-5.3 (#46825) and Muse Spark Open (#45689) ones. It names the pinned image with its digest and gives one `sglang serve` command for `amd/Qwen3.8-Flash-Next-Quark-MXFP4-AttnFP8-PLEFP8` at TP1 with NEXTN 3/1/4, plus bullets for the settings a reader would otherwise have to guess: the PLE table offload and the FP8 dtype override it requires, `SGLANG_AITER_HONOR_EXPLICIT_MEM_FRACTION=1`, the batch limits per concurrency, and the non-thinking chat default.
- Not changed: the Deploy panel config, the engines, and the generated `docs/src/snippets/agentx/Qwen/qwen3.8-flash-next.jsx`. The sa-infx-cookbook sync generates that file, and none of the generated AgentX files carries an AMD lane yet.

## Where the supplied selector lands

The published Deploy selection `hw=mi355x&variant=default&quant=bf16&strategy=balanced&nodes=single&pleOffload=auto` is a different lane. It renders `Qwen/Qwen3.8-Flash-Next` (BF16) at `--tp-size 8` and `--page-size 32` without MTP, on `lmsysorg/sglang-rocm:qwen38flashnext`. The PLE Offload row is hidden on AMD, so `pleOffload=auto` adds no flag there. #4680 serves the AMD MXFP4 checkpoint at TP1 for an AgentX workload, so this PR adds it to the Agentic Long-Context section and leaves that cell alone.

The Deploy panel has no MXFP4 option for this model. #36919 (open, last updated 2026-09-12) would add one for a different checkpoint (`amd/Qwen3.8-Flash-Next-Quark-MXFP4`, TP8·EP8) in the Deploy panel. It does not cover #4680's lane. On this page it edits the install notes and the precision table of an older revision, not the Agentic Long-Context section this PR adds to.

## Intentionally excluded

- `--enable-metrics` and `--enable-cache-report`: telemetry that the benchmark client reads (`AIPERF_REQUIRED_SERVER_METRIC_PREFIX`). The AgentX sync drops both from the NVIDIA Qwen3.8 lanes as well.
- `SGLANG_TIMEOUT_KEEP_ALIVE=1800`: the recipe's own comment says it outlasts AIPerf's 300 s client connection pool.
- `PYTHONNOUSERSITE=1`: container hygiene.
- `benchmark.env` (`AIPERF_APPLY_CHAT_TEMPLATE`, `AIPERF_REQUIRED_SERVER_METRIC_PREFIX`), the per-point `CONC` and `KV_OFFLOADING`, and `dram-utilization: 0.80`, which has no effect with `kv-offloading: none`.
- Synthetic acceptance: the harness injects the golden acceptance length (`SGLANG_SIMULATE_ACC_LEN`); the recipe does not set it, so it is not part of the command.
