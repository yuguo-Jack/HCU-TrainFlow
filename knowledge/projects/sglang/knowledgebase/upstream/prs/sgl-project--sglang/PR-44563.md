# [Feat] modelopt: Support packed GGML mixed-precision weights

[Upstream PR](https://github.com/sgl-project/sglang/pull/44563) · state: open · merged: False

## Original PR description

## Motivation

Support loading `nvidia/NVIDIA-Nemotron-3.5-Bolt-74B-A9B-24GB`, whose packed weights currently fall back to dense loading. Builds on #44487.

## Modifications

Reuse existing GGUF kernels for ModelOpt `Q8_0`/`IQ2_XXS` linear weights and `IQ2_XXS` experts, including ungated ReLU². Fix fused NVFP4A16 scalar-scale loading. The NVFP4A16 loader fix initializes every logical scale slot in a fused projection. Previously, loading a scalar could leave another slot uninitialized: the regression reproduced `[0.25, NaN]` instead of `[0.25, 0.25]`.


Expert loading supports TP; EP/EPLB are unsupported. LiLiCorr GGUF support is tracked in #45229. No new dependencies.

## Accuracy Tests

The original commit `fedc956` passed chat tests on a GB10 with expected outputs. The same code passed 25 CPU tests and GPU numerical checks. Eight image-input checks also passed: colors/positions, counting, OCR, a natural photo, two-image ordering, and base64/HTTPS inputs.

The routing and large-prefill fixes passed 11 CPU tests and 3 GPU numerical tests on H100. The 7,282-token/top-k 9 regression fails before the fix and passes afterward against independently decoded weights. 

A BF16 vs ModelOpt mixed-precision comparison at commit `749bcc8` on one B300 scored 175/200 (87.5%) for BF16 and 173/200 (86.5%) for the 24GB mixed-precision quantized checkpoint. Both used TP1, zero-shot GSM8K, temperature 0, one worker, a 512-token output limit, and thinking disabled.

## Speed Tests and Profiling

Server launch command for speed test on single GB10, TP1, no speculative decoding:

```bash
python3 -m sglang.launch_server \
  --model-path nvidia/NVIDIA-Nemotron-3.5-Bolt-74B-A9B-24GB \
  --revision 5165e12246e823a578bc2d483958439c38d9d6bd \
  --trust-remote-code --context-length 4096 \
  --max-running-requests 4 --max-total-tokens 8192 \
  --max-mamba-cache-size 32 --mem-fraction-static 0.6
```

SGLang serving benchmark with 256-token inputs and 128-token outputs, two warmup requests per run, cache flushed after warmup:

```bash
bolt_model=nvidia/NVIDIA-Nemotron-3.5-Bolt-74B-A9B-24GB
for concurrency in 1 4; do
  requests=10
  if [ "$concurrency" = 4 ]; then requests=20; fi
  python3 -m sglang.benchmark.serving \
    --backend sglang --host 127.0.0.1 --port 30000 \
    --model "$bolt_model" --tokenizer "$bolt_model" \
    --served-model-name "$bolt_model" --dataset-name random \
    --random-input-len 256 --random-output-len 128 --random-range-ratio 1.0 \
    --num-prompts "$requests" --max-concurrency "$concurrency" \
    --warmup-requests 2 --flush-cache --tokenize-prompt
done
```

**Issue**

`apply` assumes standard TopK output. On SM100/SM103 (B200, B300), `_nemotron_h_overrides` in `arg_groups/model_overrides/nemotron_h.py` sets `moe_runner_backend=flashinfer_trtllm` for `modelopt_mixed` unless the experts are `W4A16_NVFP4`. TopK then returns a 5-field `BypassedTopKOutput`, and this line raises `ValueError: too many values to unpack (expected 3)`.

**Example**

`nvidia/NVIDIA-Nemotron-3.5-Bolt-74B-A9B-24GB` has only IQ2_XXS experts, so a default launch on one B200 fails on the first forward.

**Fix**

In `_nemotron_h_overrides`, detect GGML experts as `has_w4a16_moe_layers` does, and pick a runner with standard TopK output (for example `triton`). Also make `create_moe_runner` reject backends that bypass TopK, with a clear error.

[by Claude Code] **Severity: functional | Confidence: High**

**Issue**

IQ2_XXS has no MMQ kernel, so `fused_moe_gguf` always uses `ggml_moe_a8_vec`. Its launcher `moe_vec_iq2_xxs_q8_1_cuda` (`moe_vec.cuh`) sets `gridDim.z = tokens * top_k`, but CUDA allows at most 65535. With top_k=9, any batch over 7281 tokens fails with `invalid configuration argument`.

**Example**

The Bolt checkpoint uses top_k=9. The default `chunked_prefill_size` is 8192 on GB10 and H100, so one 8k-token prompt gives z = 73728.

**Fix**

In `apply`, run `fused_moe_gguf` on token chunks of at most `65535 // top_k`, or loop over z in the launcher as `quantize_row_q8_1_cuda` already does. Add a GPU test with `tokens * top_k > 65535`.
