# [Feat] modelopt: Support packed GGML mixed-precision weights

[Upstream PR](https://github.com/sgl-project/sglang/pull/44563) · state: open · merged: False

## Original PR description

## Motivation

Support loading `nvidia/NVIDIA-Nemotron-3.5-Bolt-74B-A9B-24GB`, whose packed weights currently fall back to dense loading. Builds on #44487.

## Modifications

Reuse existing GGUF kernels for ModelOpt `Q8_0`/`IQ2_XXS` linear weights and `IQ2_XXS` experts, including ungated ReLU². Fix fused NVFP4A16 scalar-scale loading.

Expert loading supports TP; EP/EPLB are unsupported. LiLiCorr integration for LiLiCorr variant will be addressed and validated in separate PR. No new dependencies.

## Accuracy Tests

The final commit passed chat tests on a GB10 with expected outputs. The same code passed 25 CPU tests and GPU numerical checks. Eight image-input checks also passed: colors/positions, counting, OCR, a natural photo, two-image ordering, and base64/HTTPS inputs.

GSM8K scored 174/200 (87%) before final loader refinements: zero-shot prompts, thinking disabled, 512-token cap. Sanity check only; no reference-runtime comparison.

## Speed Tests and Profiling

Single GB10, TP1, no speculative decoding. SGLang serving benchmark with 256-token inputs and 128-token outputs, two warmup requests per run, cache flushed after warmup:

| Concurrency | Requests | Output tokens/s | Mean time per output token |
| --- | --- | --- | --- |
| 1 | 10 | 30.7 | 26.4 ms |
| 4 | 20 | 55.3 | 52.1 ms |

All requests completed. Small synthetic baseline. No profiling performed.

[by Claude Code] **Severity: functional | Confidence: High**

**Issue**

`apply` assumes standard TopK output. On SM100/SM103 (B200, B300), `_nemotron_h_overrides` in `arg_groups/model_overrides/nemotron_h.py` sets `moe_runner_backend=flashinfer_trtllm` for `modelopt_mixed` unless the experts are `W4A16_NVFP4`. TopK then returns a 5-field `BypassedTopKOutput`, and this line raises `ValueError: too many values to unpack (expected 3)`.

**Example**

`nvidia/NVIDIA-Nemotron-3.5-Bolt-74B-A9B-24GB` has only IQ2_XXS experts, so a default launch on one B200 fails on the first forward.

**Fix**

In `_nemotron_h_overrides`, detect GGML experts as `has_w4a16_moe_layers` does, and pick a runner with standard TopK output (for example `triton`). Also make `create_moe_runner` reject backends that bypass TopK, with a clear error.

- nvpohanh · comment · 2026-10-16T04:11:09Z · [source](https://github.com/sgl-project/sglang/pull/44563#discussion_r4290846622)

File: `python/sglang/srt/layers/quantization/modelopt_ggml.py` · line 265

[by Claude Code] **Severity: functional | Confidence: High**

**Issue**

IQ2_XXS has no MMQ kernel, so `fused_moe_gguf` always uses `ggml_moe_a8_vec`. Its launcher `moe_vec_iq2_xxs_q8_1_cuda` (`moe_vec.cuh`) sets `gridDim.z = tokens * top_k`, but CUDA allows at most 65535. With top_k=9, any batch over 7281 tokens fails with `invalid configuration argument`.

**Example**

The Bolt checkpoint uses top_k=9. The default `chunked_prefill_size` is 8192 on GB10 and H100, so one 8k-token prompt gives z = 73728.

**Fix**

In `apply`, run `fused_moe_gguf` on token chunks of at most `65535 // top_k`, or loop over z in the launcher as `quantize_row_q8_1_cuda` already does. Add a GPU test with `tokens * top_k > 65535`.

File: `python/sglang/srt/layers/quantization/modelopt_ggml.py` · line 249

[by Claude Code] **Severity: style | Confidence: High**

**Issue**

`getattr(moe_runner_config, name)` reads fields that `MoeRunnerConfig` always defines. The dynamic lookup hides typos and defeats type checking (see `.claude/rules/no-getattr-defensive.md`). `test_modelopt_ggml_gpu.py` line 31 also uses `getattr(gguf.GGMLQuantizationType, algo)`.

**Fix**

Read the fields directly, for example build `{"gemm1_alpha": moe_runner_config.gemm1_alpha, ...}` and report the names whose values are not `None`. In the test, use `gguf.GGMLQuantizationType[algo]`, as `ggml_block_layout` already does.
