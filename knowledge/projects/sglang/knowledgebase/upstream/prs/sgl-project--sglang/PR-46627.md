# [Test] minimax-m3.1: Add nightly e2e tests on H200 and B300

[Upstream PR](https://github.com/sgl-project/sglang/pull/46627) · state: closed · merged: True

## Original PR description

## Motivation

MiniMax-M3.1-Flash has unit and kernel tests but no end-to-end test, so a change to a shared path can break the served model without turning any test red. This adds two nightly tests on the cookbook recipes, and installs the MSA kernels on Blackwell CI runners, which the model imports at startup there.

## Modifications

- `test_minimax_m31_flash_h200.py` (nightly, 8-gpu-h200): the H200 balanced recipe (TP8; Marlin W4A16 experts, no MSA) with DSpark and block verification. It checks GSM8K and the DSpark accept length.
- `test_minimax_m31_flash_gb300.py` (nightly, 4-gpu-gb300): the B300 balanced recipe (TP4; TRT-LLM NVFP4 MoE, MSA, DSpark) with HiCache write-through to the file storage backend. It checks GSM8K and the DSpark accept length, then reloads a long prefix from storage after `/flush_cache` and checks that the greedy output matches the GPU-cached one.
- `ci_install_dependency.sh`: on Blackwell, install MSA at the `MSA_COMMIT` of `docker/Dockerfile.cu134`, editable and with its submodules as the Dockerfile does, cached per commit under `~/.cache/sglang-ci/minimax-msa` behind a `flock`, since runner containers on one host share `~/.cache`.

## Verification

Both tests run against `MiniMaxAI/MiniMax-M3.1-Flash` at main 316ff4dce2; sgl-eval GSM8K, 1319 examples, temperature 1.0, top_p 0.95, max_tokens 8192.

| Test | Hardware | GSM8K | Accept length |
|---|---|---|---|
| H200 | 8x H200 | 0.9575, 0.9591 | 3.87, 4.19 |
| GB300 | 4x B300, MSA 1e7bf76 | 0.961, 0.961, 0.955 | 4.22, 4.18, 4.15 |

The thresholds are 0.93 (both) and an accept length of 3.4 (H200) and 3.8 (GB300). The first H200 number was measured with the same flags on main with https://github.com/sgl-project/sglang/pull/46868 applied, before it merged; the second is this PR's CI run (https://github.com/sgl-project/sglang/actions/runs/40914892470).

On the B300 node, MSA was installed by the same steps as the new `install_msa`; the script itself first runs on this PR's Blackwell CI jobs. Runs of the storage-reload case on three prompts, with and without DSpark, matched the GPU-cached output every time, and the full test including it passed (the third row). On a GB300 CI runner the Blackwell test passed with GSM8K 0.9560 and accept length 4.13 (https://github.com/sgl-project/sglang/actions/runs/40910557761).
