# [Perf] mrope: Upload M-RoPE decode deltas without blocking the host

[Upstream PR](https://github.com/sgl-project/sglang/pull/46332) · state: open · merged: False

## Original PR description

## Motivation

`ForwardBatch._compute_mrope_positions_decode` uploads the per-request M-RoPE deltas with `torch.tensor(..., device=...)` from pageable host memory. It runs in `ForwardBatch.init_new` on every decode step that has a multimodal request.

- A pageable host-to-device copy can make the host wait for GPU work already queued on the stream. On MI355X, a standalone check on unpatched code queues a long `torch.cuda._sleep` and calls the function: it returns only after the queued work finishes.
- Other per-step uploads already use the `async_h2d` helper (#41659). It stages the list in pinned memory where the platform provides it and enqueues the copy on the current stream.

This PR uses `async_h2d` at the decode site. Uploaded values, shape and dtype (int64) are unchanged. `compute_spec_mrope_positions` is untouched. No new flag, environment variable or API.

Scope: the change is model-independent and applies to every model that uses M-RoPE (for example the Qwen2-VL, Qwen2.5-VL, Qwen3-VL, Qwen3.5 and GLM-4V families). The speed results below are from one model.

## Modifications

- `python/sglang/srt/model_executor/forward_batch_info.py` (+2/-2): import `async_h2d`, and replace `torch.tensor(deltas_list, dtype=torch.int64, device=...)` with `async_h2d(deltas_list, dtype=torch.int64, device=...)`. Where `is_pin_memory_available` returns False (CPU platforms, NVIDIA confidential compute), the helper is the old pageable copy.
- `test/registered/unit/model_executor/test_forward_batch_mrope_positions.py` (new, +69): one GPU test, registered for CUDA and AMD CI.
  - It calls the function once to warm up, then again under `torch.cuda.set_sync_debug_mode("error")`, the pattern of `test_swa_unittest.py` and `test_decode_prealloc_no_host_sync.py`. Like those tests, it skips where that mode does not flag a pageable host-to-device copy.
  - It checks the decode positions of a mixed batch (image requests with negative, zero and positive deltas, and a text-only request) for exact equality.

The function runs on the host inside `ForwardBatch.init_new`. It adds no allocation or synchronization inside a captured CUDA graph region.

## Accuracy Tests

- The uploaded values are unchanged. The test checks the resulting positions for exact equality.
- End-to-end, a greedy-output probe (16 image+text requests, 32 tokens each) completed in every server launch of the speed run below; its outputs are not used as an accuracy comparison.

## Speed Tests and Profiling

**Setup**
- Image: `lmsysorg/sglang-rocm:v0.5.22-rocm724-mi35x-20261024` (SGLang source tree at `13b7ef75c5`, AITER `285579b6`, torch 2.11.0+rocm7.2). `forward_batch_info.py` is unchanged between that tree and this PR's base.
- Hardware: 2x MI355X (gfx950).
- Model: `amd/Qwen3.8-Flash-Next-Quark-MXFP4` (revision `b2091c38`), no speculative decoding.
- Server (both arms): TP2 + EP2,
  ```
  --attention-backend aiter --linear-attn-backend triton --context-length 8192 --max-running-requests 128 --disable-radix-cache --enable-multimodal --mm-enable-dp-encoder
  ```

- Patched: the +2/-2 runtime change of this PR; no flag or environment change.
- Benchmark: `sglang.bench_serving`, one 512x512 image per request, 1024 input / 128 output tokens (range ratio 0.8), prompts = 10x concurrency; 2 measured runs per row after a warm-up pass. Server launches in the order baseline, patched, patched, baseline.
