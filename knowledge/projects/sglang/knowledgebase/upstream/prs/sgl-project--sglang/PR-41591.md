# [DCP + L3 3/N] Support hybrid MLA/KDA DCP with file and Mooncake HiCache L3

[Upstream PR](https://github.com/sgl-project/sglang/pull/41591) · state: closed · merged: True

## Original PR description

## Why?

- MLA + DCP + L3 still rejects models with KDA state, including Kimi-Linear.
- Stack: #41187 (file) → #41265 (Mooncake) → #41591 (hybrid MLA/KDA).

## What?

- Allow materialized MLA KV plus KDA state with file and Mooncake. Keep the existing layout restrictions.
- Share MLA objects across replicas; keep each TP rank's KDA state distinct. File eviction tracks only objects owned by that rank, using one byte budget. Ambiguous legacy KDA files miss.

```text
TP=4 / DCP=2:
MLA: 2 shards per page
KDA: 4 state bundles per checkpoint
```

- Restore the longest checkpoint present on every rank:

```text
rank 0: 512, 1024
rank 1: 512,  768
shared: 512
```

## Tests?

- Three focused regressions in the existing file-storage CI test file; **zero new test files**.
- CPU: **85 passed / 54 subtests**. Existing storage/release regressions: **90 passed, 143 skipped**.
- **Observed on H200 with pinned Kimi-Linear, BF16:** file and Mooncake restored 1,024 peer-prefix tokens and 1,280 tokens including generated output. Missing MLA/KDA data fell back to 512 tokens. Fresh readers and concurrent requests passed.
- TP=4/DCP=2: **16 MLA objects + 4 KDA bundles**. File stores 20 objects; Mooncake stores 24 because each state bundle has temporal and convolution objects.
- **4 H200 tests / 23 restore checks passed**, with matching cold/warm output IDs and KDA reads on every rank. Formatting, imports, syntax, registered-test and whitespace checks passed; no new lint findings.
- [Reproduction scripts, results, and preserved benchmark evidence](https://gist.github.com/ByronHsu/6ad91c20cd7a82fcd43acec2a31cc7aa). GB300 and performance were not rerun for this cleanup; historical K3 results use dummy weights.
- GitHub CI pending.
