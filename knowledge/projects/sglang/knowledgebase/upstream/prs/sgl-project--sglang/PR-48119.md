# [Refactor] tokenizer: Fold `TokenizerWorker` into `TokenizerManager`

[Upstream PR](https://github.com/sgl-project/sglang/pull/48119) · state: closed · merged: True

## Original PR description

- `TokenizerWorker` is folded into `TokenizerManager`. A manager behind `MultiTokenizerRouter` (`tokenizer_ipc_name` is set) registers with the router, sends pause/continue through it and applies the `PauseContinueBroadcastReq` the router sends to every tokenizer process; it does not start the PD bootstrap service, which the router runs. This replaces the `start_pd_bootstrap_service` argument of `TokenizerManager.__init__`.
- `ServerArgs.get_tokenizer_worker_class()` stays the hook for the class used in multi-tokenizer mode. It now returns `TokenizerManager`, and a custom class subclasses `TokenizerManager` instead of `TokenizerWorker`.
- The process title and `torch.set_num_threads(1)` move to the HTTP worker's `init_multi_tokenizer`.
- `_handle_output_by_index` builds the single-row output from the struct fields, as `_handle_output_by_indices` does, instead of listing every field per output type.

No behavior change, except that:
- a single-row split now carries `prompt_tokens`, `cached_tokens`, `image_tokens`, `audio_tokens` and `video_tokens` (set only by the Rust server) instead of dropping them;
- a parent `Engine` with `tokenizer_worker_num > 1` no longer renames its process or sets its torch thread count to 1.
