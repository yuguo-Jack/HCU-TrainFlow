# [Perf] diffusion: Avoid full GC per tensor update

[Upstream PR](https://github.com/sgl-project/sglang/pull/45832) · state: open · merged: False

## Original PR description

## Motivation

Bucketed RL weight synchronization calls `update_weights_from_tensor()` once per bucket. Each call currently forces a full Python garbage collection before returning, adding repeated pauses to the synchronization path. A downstream Nsight Systems capture measured 16.49–17.16 seconds inside these GC ranges per engine across 32 buckets.

## Modifications

Remove `gc.collect()` from the ordinary, non-LoRA tensor update path. Automatic GC, `torch.cuda.empty_cache()`, weight loading, and cache invalidation remain unchanged.

Disk and LoRA cleanup policies remain unchanged because this PR's measurements and validation cover only ordinary tensor updates.

## Accuracy Tests

- Existing CPU regression: `TestWeightsUpdaterFusedParams` — 2 passed.
- CPU check with the actual `WeightsUpdater` and `FlattenedTensorBucket`: 32 consecutive updates produced correct values, preserved destination storage identities, and released source tensors after caller references were removed. Only CUDA cache cleanup was mocked.
- A downstream eight-GPU run completed a full RL cycle, with all eight engines reporting the updated weight version and healthy status.
- Applicable pre-commit checks passed for the changed file.

## Speed Tests and Profiling

Measured in a downstream SGLang v0.5.21 integration with eight colocated training/inference GPUs, 512 MiB buckets, and 32 buckets per engine. Each timing run covered one RL cycle with profiling disabled.

| Measurement | Before | After |
| --- | ---: | ---: |
| Weight bucket loop | 22.8 s | 2.7 s |
| Transport/wait portion of that loop | 21.8 s | 2.0 s |
| Complete RL cycle | 153.97 s | 130.50 s |
| Sampled peak GPU memory per device | 53.93 GiB | 53.90 GiB |

Complete RL cycle time decreased by 15.24%.

Before the change: repeated GC pauses during bucketed weight updates. The `engine.weight_bucket_gc` NVTX range was added for profiling and directly wraps `gc.collect()` inside update_weights_from_tensor(). Across 32 buckets, these GC ranges total 17.16 seconds for this engine.
