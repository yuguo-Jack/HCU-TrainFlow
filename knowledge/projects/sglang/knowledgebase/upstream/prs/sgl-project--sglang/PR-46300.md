# [Fix] scheduler: Keep arrival order for requests outside the running routing keys

[Upstream PR](https://github.com/sgl-project/sglang/pull/46300) · state: open · merged: False

## Original PR description

## Motivation

`--schedule-policy routing-key` moves waiting requests whose routing key is in the running batch to the front. The remaining requests should keep their arrival order, but `_sort_by_routing_key` sorts them by `(1, 0, key or "")`, which orders them by the key string. A request with key `"zebra"` is overtaken by every later request with key `"apple"`, and key-less requests overtake both. Whether a request waits then depends on how its key sorts alphabetically, not on when it arrived.

Example: the running batch holds keys `hot`, `hot` and `warm`, and the queue in arrival order is `zebra`, `apple`, `warm`, (no key), `hot`.

- `main`: `hot, warm, no-key, apple, zebra`
- this PR: `hot, warm, zebra, apple, no-key`

## Modifications

- The sort key for requests outside the running keys is now a constant, so the stable sort keeps their arrival order. The requests whose key is running are ordered as before: by count, then by key, so requests with the same key stay together.
- New test `TestRoutingKeyPolicy.test_requests_outside_the_running_keys_keep_arrival_order` in `test/registered/unit/managers/test_schedule_policy.py`. It fails on `main` with the order shown above.

Not changed here: like before, this policy ignores `--enable-priority-scheduling`, whereas `fcfs` and `lof` order by priority. I left that alone because it is a policy decision.
