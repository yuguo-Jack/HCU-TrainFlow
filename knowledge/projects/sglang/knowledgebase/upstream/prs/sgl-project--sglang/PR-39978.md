# [Perf] Optimize SM120 FP8 blockwise decode GEMM

[Upstream PR](https://github.com/sgl-project/sglang/pull/39978) · state: closed · merged: False

## Original PR description

## Motivation

Optimize small-M FP8 blockwise decode GEMMs on SM120 for #33629, preserving the public API and quantization layout.

## Modifications

- Use streaming weight TMA loads (`EVICT_FIRST`), a warp FP8 MMA path with FP32 split-K reduction, and shape-dependent tile selection. Retain existing fallback paths.
- Keep implementation in the existing SM120 header and extend the existing kernel tests. No files added.

## Speed Tests and Profiling

RTX PRO 6000 Blackwell Server Edition, 96 GB; PyTorch 2.13.0+cu130, FlashInfer 0.6.18. Baseline: `3ce7e2a`; candidate: `19789d4`.

### Isolated GEMM

All 75 issue-shape combinations (`M=4,8,...,60`) measured with `flashinfer.testing.utils.bench_gpu_time_with_cupti`, CUDA graphs, cold L2, 1,000 warmup and 200 measured iterations. Two repetitions, each bracketed by baseline measurements; split-K reduction is included.

Representative latency in **µs, baseline → candidate**:

| Projection | M=4 | M=16 | M=60 |
|---|---:|---:|---:|
| `gate_up_proj` | 173.250 → 147.590 | 173.186 → 148.575 | 173.562 → 156.510 |
| `down_proj` | 91.895 → 88.319 | 92.531 → 89.743 | 96.891 → 89.847 |
| `in_proj_qkvz` | 83.995 → 83.623 | 83.687 → 83.623 | 87.143 → 85.271 |
| `out_proj/o_proj` | 40.736 → 35.823 | 40.371 → 36.864 | 38.735 → 38.752 |
| `qkv_proj` | 75.871 → 75.887 | 75.619 → 75.711 | 79.731 → 77.488 |

Layer-weighted isolated GEMM time falls **6.60–8.88%** at M=4/16/32/60. This is not end-to-end throughput.

### Model serving

Qwen3.8-27B-FP8 (same projection shapes as Qwen3.6), TP=1, CUTLASS, MTP with 3 steps / top-k 1 / 4 draft tokens, CUDA graphs, and capacity for 16 active requests. Same runtime; only the GEMM binary changes.

Official HTTP serving benchmark, wall-clock timing; fixed-length ShareGPT prompts, temperature 0, seed 42, EOS ignored, closed-loop concurrency. Two measured runs per case after warmup, with zero prefix-cache hits: **768/768 requests succeeded**.

Throughput uses total tokens / total time; accepted length averages the two server-reported values. Greedy outputs and MTP acceptance change, so serving gains cannot all be attributed to GEMM speed. These finite-batch measurements with unlocked clocks do not establish peak capacity.

## Accuracy Tests

- **608 tests passed** after header consolidation, covering FP16/BF16, dispatch boundaries, unequal K partitions, and mutable-input CUDA graph replay. All 20 device kernels retain their pre-consolidation instruction encodings; all 10 original baseline kernels remain unchanged.
- Six graph memcheck cases passed with zero errors; racecheck of the new warp/reduction kernels reported zero hazards.
- **Unresolved:** full CUTLASS graph racecheck reports shared-memory Write/Write hazards on both baseline and candidate. Full model accuracy evaluation remains pending; arithmetic smoke tests are the current model-level correctness evidence.
