# [Fix] qwen4-exp: Honor FP8 exclusions for PLE tables

[Upstream PR](https://github.com/sgl-project/sglang/pull/48073) · state: open · merged: False

## Original PR description

## Motivation

Qwen4-Exp currently allocates an FP8 PLE table whenever the checkpoint uses `Fp8Config`, even when `ignored_layers` / `modules_to_not_convert` excludes that table or all its serialized `shard_N` modules. Loading BF16 shards then silently loses precision apart from a warning (for example, `1.0078125` becomes `1.0`).

## Modifications

Reuse `is_layer_skipped` with the PLE shard mapping when choosing the table dtype. Whole-table and all-shard exclusions preserve BF16; partially excluded shards raise the existing mixed-precision error because they share one table. An explicit `ple_embedding_dtype="float8_e4m3fn"` keeps its existing precedence.

Extend the existing PLE offload test and its single-rank fixture to cover device and pinned-host tables, normalized checkpoint names, partial exclusions, an unrelated shard, and explicit FP8. No new test file or CI job.

## Accuracy Tests

Tested on NVIDIA H20-3e with PyTorch 2.14.1+cu130 and FlashInfer 0.7.2, based on `c8704818d4f04fa9249a4144f14882670b4d37ae`.

```bash
python -m pytest -q -ra test/registered/kernels/ops/embeddings/test_qwen4_ple_offload.py
```

- Before the fix, the new test has **6 failures and 4 passes**: both storage modes fail whole-table/all-shard exclusions and fail to reject partial exclusions.
- After the fix, the full file has **21 passes, 3 skips**. The three existing file-backed-table cases require host page-table support unavailable on this H20.
- Excluded BF16 tables retain a value that FP8 cannot represent exactly through the production weight loader.
- These are small synthetic table tests; no full-model accuracy claim.

Not applicable: this corrects initialization-time dtype selection and does not change forward kernels.
