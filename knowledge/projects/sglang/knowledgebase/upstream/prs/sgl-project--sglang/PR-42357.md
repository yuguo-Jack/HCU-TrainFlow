# [MUSA] Add direct AOT RoPE and fused mul-add tests

[Upstream PR](https://github.com/sgl-project/sglang/pull/42357) · state: open · merged: False

## Original PR description

## Motivation

MUSA `sgl-kernel` CI currently runs speculative-decoding tests and `test_torch_defaults_reset.py`, but it has no direct numerical coverage for MUSA-specific AOT operators. This leaves Python exports, torch dispatcher registrations, and `.mu` kernel behavior vulnerable to silent drift, such as the fused MoE GEMV registration mismatch fixed previously.

## Modifications

- Add registration smoke coverage for MUSA-specific Python exports and torch dispatcher ops.
- Compare ordinary and batched MUSA AOT RoPE against independent PyTorch references across FP16/BF16, NeoX/GPT-J layouts, and partial rotary dimensions.
- Compare MUSA AOT fused mul-add against a PyTorch reference across FP16/BF16/FP32, multiple scales, and aligned multi-block shapes.
- Retain coverage for the `accurate=False` in-place Python fallback semantics.
- Run `test_musa_ops.py` in `sgl-kernel-unit-test-musa` and trigger that job when MUSA kernel sources or this focused test file change.
