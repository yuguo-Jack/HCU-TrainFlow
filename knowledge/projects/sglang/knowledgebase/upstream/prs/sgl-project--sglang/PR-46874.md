# [Feat] gguf: Support Bolt E4B Q4_K_M checkpoints

[Upstream PR](https://github.com/sgl-project/sglang/pull/46874) · state: open · merged: False

## Original PR description

## Motivation

Enable the Bolt E4B Q4_K_M target, `nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-4GB`, through the existing GGUF loader. Its Gemma4 configuration, packed embeddings, and dense BF16 tensors need handling that the current path does not provide.

Depends on #46663 for default prefill graph startup. This branch includes that prerequisite and should be rebased onto main after it merges.

## Modifications

- Preserve shared-KV and layer-specific configuration when reading GGUF.
- Keep tensor-name discovery separate from the runtime configuration.
- Load packed embeddings and decode dense BF16 tensors correctly.
- Preserve chat channel delimiters for the `gemma4_text` code path.
- Add regression tests. No new runtime dependencies.

## Accuracy Tests

On one B300 PCIe (SM103), the reviewed GGUF changes plus #46663 scored 158/200 (79%) on GSM8K with default `trtllm_mha` attention and default breakable prefill graphs. This run used the public revisions in the launch command below, `sgl_eval` 0.1.3, zero shots, temperature 0, four workers, a 1,024-token output limit, and thinking disabled. No API errors; one response reached the output limit. The arithmetic smoke check also passed. This is a sanity check; the older H100 result below used earlier snapshots and is not a controlled hardware comparison.

One H100, TP1: the Bolt E4B Q4_K_M target scored 147/200 (73.5%) on GSM8K using `sgl_eval` 0.1.3, zero shots, temperature 0, four workers, max output 1024, and thinking disabled.

The earlier live H100 test run used the combined target/graph fixes and the separate dense-drafter loader branch, with no speculative options enabled. Five of six smoke checks passed; pencil counting returned 87 instead of 77. The export correctly rejects image inputs (the GGUF variant is text only).

BF16 execution and chat special-token setting regression tests fail without their fixes and pass with them. The chat unit test checks the request setting, not decoded delimiters. The weight test checks GGUF decoding and the existing linear/embedding helpers; Gemma4 embedding scaling and tied-head behavior are covered by live serving checks, without a dedicated numerical unit test.

Server launch command:

```bash
bf16=nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-BF16
quant=nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-4GB
tokenizer_dir=$(hf download "$bf16" \
  --revision 49843eed8db1f1c616c47af75cfd36e07aec0667 \
  --include '*.json' '*.model' '*.jinja')
target_file=$(hf download "$quant" Nemotron-3.5-Bolt-E4B-Q4_K_M.gguf \
  --revision fc2c9fed2eaabca56d44a5be74a448b14d4bc183)

python3 -m sglang.launch_server \
  --model-path "$target_file" --tokenizer-path "$tokenizer_dir" \
  --load-format gguf --quantization gguf \
  --served-model-name bolt-e4b --context-length 8192 \
  --max-running-requests 4 --max-total-tokens 8192 \
  --mem-fraction-static 0.7 --host 127.0.0.1 --port 30001 \
  --tool-call-parser gemma4 --reasoning-parser gemma4 --watchdog-timeout 900
```
