# [Fix] deepseek_v2: keep q_b_proj on one GEMM under deterministic inference

[Upstream PR](https://github.com/sgl-project/sglang/pull/48234) · state: open · merged: False

## Original PR description

## Motivation

`DeepseekV2AttentionMLA.q_b_proj_forward` routes `1 <= M <= 16` rows to the min-latency `dsv3_fused_a_gemm` kernel for verified `q_b_proj` shapes (`(2048, 2048)` and `(4096, 2048)`) and `M > 16` rows to `self.q_b_proj` (regular linear). Because the two kernels round differently (observed 1-ULP BF16 differences across `M = 16`), a token's `q` projection and output logprobs depend on how many tokens share the forward pass (decode at `bs <= 16` vs. `bs > 16`, or decode vs. prefill). `prepare_qkv_latent` already disables its min-latency fused QKV-A GEMM under `--enable-deterministic-inference`; `q_b_proj_forward` was missing the same guard.

## Modifications

- Guard `self._use_min_latency_q_b_gemm` in `DeepseekV2AttentionMLA.q_b_proj_forward` with `not get_exec().deterministic.enable_deterministic_inference`.
- Add hermetic CPU unit tests in `test/registered/unit/models/test_deepseek_q_b_proj_deterministic.py`.
