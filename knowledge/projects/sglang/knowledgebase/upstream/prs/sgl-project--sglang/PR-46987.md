## Motivation

KV allocation and buffer layout currently share ownership of page movement and ID translation. Separate those responsibilities so storage layouts can use the same allocation machinery.

## Changes

- Introduce a shared byte arena for layout-aware page movement and zeroing.
- Separate allocation bands and virtual-to-physical ID spaces from layout views.
- Update KV storage construction and its runtime consumers to use those boundaries.

## Validation

Historical validation at `a2070bc811` / `17935efc49` (8× H200, PyTorch 2.14.1):
- Four allocator chains, each **153 runs / 43,368 operations: 0 divergences**.
- Admission: **4,608 unchanged decisions**, with and without sync-debug.
- GSM8K-200 with unified HiCache: gpt-oss-120b **97.0%**, Qwen3.8-27B **96.5%**, within the recorded baseline spread.

Separate CPU review passed allocation, exhaustion and ownership-preservation cases. Per-run kernel versions were incompletely recorded; GPU allocation/serving was not rerun after the latest rebase.
