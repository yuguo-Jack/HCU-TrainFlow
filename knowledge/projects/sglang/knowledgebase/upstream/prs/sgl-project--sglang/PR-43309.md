# [Fix] Adapt NPU Qwen-VL processor patch to transformers 5.19 resize() signature change

[Upstream PR](https://github.com/sgl-project/sglang/pull/43309) · state: closed · merged: True

## Motivation

Running Qwen2.5-VL / Qwen3-VL on NPU with transformers >= 5.19 crashes with: TypeError: Qwen2VLImageProcessor.resize() missing 2 required positional arguments: 'images' and 'factor' Transformers 5.19 refactored Qwen2VLImageProcessor.resize() and Qwen3VLVideoProcessor.resize():

- Old (<= 5.15): resize(image, size, resample) — the caller computed smart_resize() itself and passed the target SizeDict(height, width).
- New (5.19): resize(images, size, resample, factor[, temporal_factor]) -- smart_resize() moved inside resize(), which now takes the original size (shortest_edge/longest_edge) and the patch factor.

The NPU _preprocess patch in sglang/srt/hardware_backend/npu/modules/qwen_vl_processor.py still called resize() with the old signature: image= was swallowed by **kwargs while the required images/factor params were missing.

## Modifications

1. Image path: drop the manual smart_resize() call and invoke self.resize(images=..., size=size, resample=resample, factor=patch_size * merge_size), matching the upstream 5.19 _preprocess implementation.
2. Video path: drop the manual smart_resize() call and the 5D->4D fold/unfold around resize; call self.resize(videos=..., size=size, resample=resample, factor=..., temporal_factor=...) directly, since the new resize() handles the (B, T, C, H, W) tensor natively.
3. Remove the now-unused smart_resize / smart_resize (video) imports. The NPU-specific flattening logic (transform_patches_to_flatten, avoiding tensors > 8 dims on Ascend) is unchanged.
