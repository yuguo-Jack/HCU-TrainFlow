# [Fix] [NVIDIA] docker: Build sgl-deep-gemm 0.2.3 for cu134 to match the sglang pin

[Upstream PR](https://github.com/sgl-project/sglang/pull/45521) · state: closed · merged: True

## Original PR description

## Motivation

`python/pyproject.toml` pins `sgl-deep-gemm==0.2.3`, but `docker/Dockerfile.cu134` builds DeepGEMM `v0.2.1.post1` and installs it with the pin removed. So the `nightly-cu134-*` images ship `sgl-deep-gemm 0.2.1.post1`.

Muse Spark's MegaMoE path (`muse_spark_megamoe.py`, `forward_megamoe`) passes `post_expert_norm*` arguments that only exist in sgl-deep-gemm 0.2.3+. With `--enable-megamoe-for-layernorm-sp`, the server fails at the first prefill CUDA-graph capture:

```
TypeError: bf16_mega_moe() got an unexpected keyword argument 'post_expert_norm'
```

Reproduce (no GPU needed):

```
docker run --rm lmsysorg/sglang:nightly-cu134-20261020-306ccf6 python3 -c "import importlib.metadata as m, inspect, deep_gemm; print(m.version('sgl-deep-gemm'), [r for r in m.requires('sglang') if 'deep-gemm' in r]); print('post_expert_norm' in inspect.signature(deep_gemm.bf16_mega_moe).parameters)"
# -> 0.2.1.post1+cu134 ['sgl-deep-gemm==0.2.3']
# -> False
```

## Modifications

- Set `DEEPGEMM_REF=v0.2.3` and `SGL_DEEP_GEMM_VERSION=0.2.3` in `docker/Dockerfile.cu134`, matching the pyproject pin and `docker/muse_spark/muse-spark.Dockerfile`, which already builds 0.2.3.
- Add a `check-dockerfile-wheel-pins` pre-commit hook (`scripts/lint/check_dockerfile_wheel_pins.py`). It fails if any Dockerfile under `docker/` sets `DEEPGEMM_REF`, `SGL_DEEP_GEMM_VERSION` or `SGL_DEEP_EP_VERSION` to a value other than the `python/pyproject.toml` pin. These wheels are installed with the pin stripped and `--no-deps`, so a mismatch is otherwise silent. Dockerfiles are found by these ARGs rather than by name, so a renamed or new CUDA Dockerfile stays covered, and the check fails if no Dockerfile sets them. On `main` it reports the current `v0.2.1.post1` mismatch.
