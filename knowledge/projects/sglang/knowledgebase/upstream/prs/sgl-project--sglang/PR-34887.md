# [Fix] [AMD] hunyuan_v3: Fix MoE accuracy with MoRI a2a backend

[Upstream PR](https://github.com/sgl-project/sglang/pull/34887) · state: open · merged: False

## Original PR description

## Motivation

This PR fixes a bug where MoE models served with `--moe-a2a-backend mori` produce garbage output (0/10 on known-answer accuracy), while the exact same model/config with `--moe-a2a-backend none` is correct (10/10). This reproduces on:

- Qwen3-30B-A3B (128 experts, top-8)
- Hy3-preview / Hunyuan (`HYV3ForCausalLM`, 192 experts, top-8, with shared experts)

It reproduces at single node (where MoRI runs its IntraNode kernel) and at multi-node (InterNode/RDMA kernel), so it is not tied to a specific transport.

### Root Cause

After the experts run, `Qwen3MoeSparseMoeBlock` / `HYV3MoEFused` apply a post-experts all-reduce (`moe_expert_parallel_all_reduce` / `moe_tensor_model_parallel_all_reduce`), gated by `should_skip_post_experts_all_reduce(...)`. That all-reduce is correct for backends whose experts return a partial result per rank.

But MoRI's `combine` already all-to-all-reduces each token's expert outputs back to the source rank — the routed output is already complete and replicated across the group, exactly like the `flashinfer` and `pplx` dispatchers, which are already excluded from the post-experts all-reduce. Because `mori` was not in the skip list, the extra all-reduce re-reduces an already-complete result, summing it `ep_size`/`tp_size`× and destroying the output.

We confirmed this directly by dumping per-rank MoE tensors on the failing server: the routed MoE output is identical across all ranks (already reduced by MoRI combine), and the post-experts `final_out` equals `Σ_ranks(routed)` (i.e. `ep_size × routed`), the fingerprint of the erroneous re-reduce.

A reference-trajectory comparison against a correct HuggingFace forward on the same prompt showed layer-0 attention matching (cosine ≈ 1.0) but the trajectory diverging starting at the first MoE layer's output — isolating the defect to the post-experts reduce, not to MoRI's dispatch/GEMM/combine (which produce numerically correct values).

### Specific to Hunyuan 3

`HYV3MoEFused` adds a shared expert (`shared_mlp`, built with `reduce_results=False`) to the routed output before the all-reduce. Under MoRI, the routed output is already full/replicated (must not be reduced again), but the shared output is still a TP/EP partial (still needs reducing).

So simply skipping the blanket all-reduce fixes the routed part but leaves `shared` at a fraction (`1/group_size`), which still corrupts the sum. The fix reduces only the shared partial over the same group(s) the blanket reduce would have used, then adds it to the already-full routed output. Qwen3 has no shared experts, so it needs only the skip.

## Modifications

- `python/sglang/srt/layers/moe/utils.py` — `should_skip_post_experts_all_reduce(...)`: add an `is_mori()` skip alongside the existing `is_flashinfer()` / `is_pplx()` skips (same "combine already reduces to source rank" rationale). This alone fully fixes models without shared experts (e.g. Qwen3).
- `python/sglang/srt/models/hunyuan_v3.py` — in both `_forward_single_stream` and `_forward_dual_stream`, for the MoRI path only, reduce the shared-expert partial over the EP/TP group before adding it to the already-full routed output; plus the `get_moe_a2a_backend` import. Required for Hunyuan/Hy3 and any MoRI model with shared experts.

Both changes are gated on `get_moe_a2a_backend().is_mori()`, so `none`, `flashinfer`, `deepep`, and `pplx` behavior is unchanged.

## Accuracy Tests

Accuracy = greedy known-answer probe (10 factual prompts, temperature 0). Baseline `mori` is the unpatched image; `none` is the reference-correct control.

### Probe Test
| Model | Nodes | Geometry | Backend | Before Fix | After Fix |
|-------|:-----:|----------|---------|:--------:|:--------:|
| Qwen3-30B-A3B | 1 | TP/EP=8  | mori | 0/10 | 10/10 PASS |
| Qwen3-30B-A3B | 2 | TP/EP=16 | mori | 0/10 | 10/10 PASS |
| Qwen3-30B-A3B | 4 | TP/EP=32 | mori | 0/10 | 10/10 PASS |
| Hy3-preview   | 1 | TP/EP=8  | mori | 0/10 | 10/10 PASS |
| Hy3-preview   | 2 | TP/EP=16 | mori | 0/10 | 10/10 PASS |
| Hy3-preview   | 4 | TP/EP=32 | mori | 0/10 | 10/10 PASS |

- Qwen3: clean PASS at 1/2/4 nodes (0/10 degenerate).
- Hy3: all answers correct at 1/2/4 nodes. At multi-node the probe's separate degenerate-tail heuristic flags 3–4/10 (the base model repeats after answering), but the correct `none` reference shows the same 2–4/10 — i.e. it's a base-model/prompt artifact, not a regression from this fix.
- Controls: `--moe-a2a-backend none` remains 10/10 (unchanged), confirming the fix is scoped to MoRI.

Both single-node (MoRI IntraNode) and multi-node (MoRI InterNode/RDMA) paths verified.

|-------|:-----:|----------|:--------------:|:-----------------:|:----------------:|

| Hy3-preview   | 1 | TP/EP=8  | 77.5% (31/40) | 2.5% (1/40) | 77.5% (31/40) |
| Hy3-preview   | 2 | TP/EP=16 | 80.0% (32/40) | 2.5% (1/40) | 77.5% (31/40) |
| Hy3-preview   | 4 | TP/EP=32 | 80.0% (32/40) | 0.0% (0/40) | 80.0% (32/40) |

- Before the fix, mori is broken at every scale (Qwen3 0%, Hy3 0–2.5%), consistent with the garbage output on the known-answer probe.
- After the fix, mori tracks the none reference at every scale: Qwen3 lands at or slightly above none (within noise at N=40), and Hy3 matches the reference closely (exactly equal at 1 and 4 nodes: 31/40 and 32/40).
- The absolute score reflects each base model's own capability (Hy3-preview is a preview model, so its ceiling is lower); the fix restores reference-equivalent accuracy on the MoRI path rather than changing model quality.
- Single-node exercises MoRI's IntraNode kernel; 2-node and 4-node exercise MoRI's InterNode (RDMA) kernel. Scored offline against the staged GSM8K test split via final-integer exact-match.

### Test Environment

- Image: `rocm/sgl-dev:v0.5.16-rocm700-mi30x-20260728` (SGLang upstream `main` @ `84cdfde`, version `0.5.16.dev20260728`), 8× MI300 per node, pure TP (`tp==ep`), `--disable-custom-all-reduce`.
- Hy3 runs also apply an orthogonal, environment-specific workaround for AITER's `biased_grouped_topk` on ROCm (falls back to the reference impl when `apply_routed_scaling_factor_on_output=True`); this is unrelated to the all-reduce fix.
