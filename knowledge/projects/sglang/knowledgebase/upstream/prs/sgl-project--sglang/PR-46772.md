# [Fix] disaggregation: align DSA tail seq_len with decode on last chunk

[Upstream PR](https://github.com/sgl-project/sglang/pull/46772) · state: open · merged: False

## Original PR description

## Motivation

Mooncake PD disaggregation raises `ValueError: DSA tail slot index missing: src=[], dst=[...]` when Prefill and Decode disagree on whether a DSA tail slot exists.

Prefill's last chunk indexed `DSA_TAIL` with `min(extend_end, len(origin_input_ids))`. Decode registers `len(origin_input_ids)` (`_rebootstrap_prefill_len`). Empty vs non-empty is only `seq_len % pool_size` (usually 4). When `extend_end` sits on a pool boundary and the prompt length is one past it, Prefill emits `[]` and Decode emits a live 6-tuple such as `[req_pool_idx, 0, 1, 0, 0, 12]` (`tail_extra_slots=8`). C128 already uses `transfer_input_len` for this request-scoped contract. KV page indices are unchanged.

Fixes #46763

## Modifications

- Last-chunk `DSA_TAIL` now uses `transfer_input_len` (`len(origin_input_ids)`), matching Decode and C128.
- Token-pool payloads still use the materialized range `min(extend_end, transfer_input_len)`.
- CPU unit test covers the pool-boundary mismatch (old index empty + transfer raises; new index transfers), a sampled token past origin, and a pool-aligned prompt that stays empty on both sides.

## Accuracy Tests

No model-forward change. `test/registered/unit/disaggregation/test_dsa_tail_transfer.py` fails on the previous index and passes after this change.
