## Motivation

Request-row ownership and KV allocation lifecycle are spread across pool-specific helpers. A common request table and storage lifecycle make those operations consistent across unified storage layouts.

## Changes

- Add a request table that tracks rows, row generations, token IDs and optional recurrent-state slots.
- Move request allocation, release and rollback through KV storage.
- Migrate scheduler and disaggregated decode consumers to the shared lifecycle.

Remove two tests that only check empty construction or class names; retain request ownership and lifecycle coverage.

## Validation

The cleanup removes only the two construction/name-only checks. Tests were not rerun after the rebase.

Historical validation at `10c16dc289`:
- Storage-versus-direct lifecycle: **9/9 cases matched**; a planted extra allocation failed all nine.
- Four-chain replay: **0 divergences**; admission: **4,608 unchanged decisions**.
- On H200, GSM8K-200 unified HiCache scored **96.5% / 97.0%** for gpt-oss-120b / Qwen3.8-27B. PyTorch 2.14.1 was recorded; full kernel versions were not.

Later CPU review passed **400 allocation/free transitions** and verifier-cache invalidation checks. GPU lifecycle and serving were not rerun on the published head.
