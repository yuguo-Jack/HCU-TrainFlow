# [Fix] humming: Free replaced MoE weights after each sublayer transform

[Upstream PR](https://github.com/sgl-project/sglang/pull/45200) · state: closed · merged: True

## Original PR description

## Motivation

`--moe-runner-backend humming` replaces every MoE sublayer tensor with a padded, repacked copy of a different size while loading. The originals stay referenced until the next sublayer, and later allocations split their cached blocks, so much of that memory is never returned. On 8× H20-3e (141 GB), DeepSeek-V4.1-Flash with TP-sharded experts holds 100.6 GB per GPU after loading at TP4 (81.8–82.2 GB with this PR) and 57.1 GB at TP8 (50.0 GB). At TP4, with or without DSpark, the server fails to start with the default `--mem-fraction-static 0.8` (TP4 + DSpark shown):

```
RuntimeError: The DSV4 SWA pool cap (707840 tokens, 15.81 GB) leaves no room for the full KV pool within the available 9.62 GB. ...
```

## Modifications

- After each sublayer transform, drop every reference to the replaced tensors (including the loop variables) and call `torch.cuda.empty_cache()`, in both Humming MoE paths. Padding, kernels and the forward pass are unchanged.
- CPU unit test `test_humming_moe_release_replaced.py`: no replaced tensor is still referenced when the cache is emptied, for both paths. It fails on main.

## Speed Tests and Profiling

8× H20-3e, `lmsysorg/sglang:nightly-dev-20261019-3c560089`, the DeepSeek-V4.1-Flash H200 low-latency cookbook recipe with `--moe-runner-backend humming --ep-size 1`, `SGLANG_HUMMING_INPUT_QUANT_CONFIG='{"dtype": "float8e4m3"}'` and `SGLANG_ENABLE_DSV41_ENGRAM_HOST_TABLE=1`. Decode: `python -m sglang.bench_serving --dataset-name random-ids --random-input-len 1024 --random-output-len 512`; TP8 is the mean of 3 alternating runs on one node.

| | main | this PR |
|---|---|---|
| TP4: weights per GPU | 100.6 GB, fails to start | 81.8–82.2 GB, KV 10.18M tokens |
| TP4 + DSpark | fails to start | KV 6.92–7.02M tokens |

With #45083 (TP4 + CP4 + DSpark), KV grows from 4.88M to 10.88M tokens. Loading is not slower. With Humming's generic SM90 heuristics (the ones H100/H200 select) forced on the same machine, the memory numbers are the same and TP4 + DSpark starts.
