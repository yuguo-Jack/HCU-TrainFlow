# [Multimodal] Keep Pillow's decompression-bomb guard in NanoNemotron processor

[Upstream PR](https://github.com/sgl-project/sglang/pull/43713) · state: open · merged: False

## Original PR description

Fixes #43707

## Motivation

`NanoNemotronVLImageProcessor.__init__` set `Image.MAX_IMAGE_PIXELS = None`. That is process-global Pillow state, so once a NanoNemotron model was loaded, Pillow's decompression-bomb guard was off for every later image decode in the process (including the generic `Image.open(...).load()` path in `utils/common.py`), not just NanoNemotron requests.

## Modifications

- Remove the global `Image.MAX_IMAGE_PIXELS = None` assignment. It came in with the original model port (#12277) and nothing in the processor relies on it; Pillow's default limit (warning above ~89M pixels, error above ~179M) is far above the image sizes the processor tiles.
- Add `test/registered/unit/multimodal/test_nano_nemotron_vl_processor.py` (CPU suite), which constructs the processor with stubbed dependencies and checks `Image.MAX_IMAGE_PIXELS` is unchanged. It fails on `main` (`None != 89478485`) and passes with this change.

@abhishekacharya200 no changes needed from my side. Nothing in the processor needs the unlimited setting, and vLLM's port of the same model (`vllm/model_executor/models/nano_nemotron_vl.py`) never sets it either.

The new test fails when the line comes back, so it covers the change:

```
$ PYTHONPATH=python python -m pytest -q test/registered/unit/multimodal/test_nano_nemotron_vl_processor.py
1 passed, 3 warnings in 11.46s          # head 6353660
# with `Image.MAX_IMAGE_PIXELS = None` restored in __init__:
AssertionError: None != 89478485
1 failed, 3 warnings in 11.35s
```

non-blocking: once the guard is back, a NanoNemotron request with an image over 178,956,970 pixels gets a 500, not a 400. `DecompressionBombError` subclasses `Exception`, not `OSError`, so `_load_single_item` wraps it in `RuntimeError`. On main `279f1fa`, with every other model:

```
$ PYTHONPATH=python python bomb.py   # 15000 x 15000 1-bit PNG, 27385 bytes
RuntimeError <- DecompressionBombError: ... Image size (225000000 pixels) exceeds limit of 178956970 pixels, could be decompression bomb DOS attack.
```

That predates this PR and doesn't block it. The fix is one more entry in `CLIENT_MEDIA_EXCEPTIONS`, and it belongs in a separate PR so this one stays a single-line revert.
