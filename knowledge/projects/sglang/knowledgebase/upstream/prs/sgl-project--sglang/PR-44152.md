## Motivation

This PR adds features and fixes for serving embedding and scoring models. Each item is a separate commit and can be reviewed on its own.

| # | Added | Gap it fills |
|---|-------|--------------|
| 1 | `--disable-normalize-embedding` | No way to get the raw (un-normalized) pooled vector |
| 2 | Embed-override validation when a request arrives | A malformed override crashes the scheduler and aborts every request in the batch |
| 3 | Zero-padded sub-rids and reserved rid prefixes | Aborting `x_1` also aborts `x_10`–`x_19` |
| 4 | `rid` on score requests | A score call can't be traced across processes |
| 5 | `PID<n>` in the scheduler log prefix | Can't tell which OS process wrote a scheduler log line |
| 6 | `--log-schedule-decisions` | Logs don't say why queued requests weren't admitted |
| 7 | Bias-free Qwen2/Qwen3 classification head | Scores include a random, unseeded bias that HF doesn't have |
| 8 | `input_ids` on `Engine.encode` / `async_encode` | Embeddings fail when the engine is launched with `skip_tokenizer_init=True` |

Where each item applies along a score/embedding request:

```
 Engine.score / /v1/score            Engine.encode / async_encode
   rid="abc"  (4)                      input_ids=[...]  (8)
        │                                    │
        ▼                                    ▼
 ┌──────────────────────── TokenizerManager ────────────────────────┐
 │ io_struct: expand_base_rid("abc", n)                        (3)  │
 │   n=12 → abc_00, abc_01, …, abc_11 (not abc_0 … abc_11)          │
 │   rejects "" and "HEALTH_CHECK…"                                 │
 │ validate_positional_embed_overrides(…, hidden_size)         (2)  │
 │   wrong type / not 2-D / hidden-dim mismatch → ValueError (400)  │
 └──────────────────────────────┬───────────────────────────────────┘
                                ▼
 ┌──────── Scheduler  [… TP0 EP0 PID12345]  (5) ────────────────────┐
 │ prefill pass ──► "Schedule prefill: #picked=…, #left-in-queue=…, │
 │                   #running=…, #preempted=…, kv-free-tokens=…,    │
 │                   kv-evictable-tokens=…, picked-rids=[…]"   (6)  │
 │ abort by rid prefix: "abc_01" is not a prefix of "abc_10"   (3)  │
 └──────────────────────────────┬───────────────────────────────────┘
                                ▼
 ┌──────────────────────── Model forward ───────────────────────────┐
 │ Pooler: normalize = normalize and not --disable-normalize… (1)   │
 │ Qwen2/3 *ForSequenceClassification: score = Linear(bias=False)(7)│
 └──────────────────────────────────────────────────────────────────┘
```

## Modifications

1. **`--disable-normalize-embedding`** (`Model` arg group). When set, a `Pooler` built with `normalize=True` returns the raw pooled vector. Custom poolers (cross-encoder, BERT, vision) are unaffected. The flag is read once in `Pooler.__init__`, and before the config is published it behaves as off. The default behavior is unchanged.
2. **Embed-override validation** with `validate_positional_embed_overrides(value, *, hidden_size)` in `managers/embed_types.py`. It is a plain function, called from `TokenizerManager` on both the generate and embedding paths. It rejects:
   - values that are not `PositionalEmbeds` (e.g. raw JSON);
   - embeds that are not 2-D `[N, hidden_dim]` or are empty;
   - a last dim that differs from the model's `hidden_size`.
3. **`expand_base_rid(rid, num)`** in the new `utils/rid_utils.py`. `GenerateReqInput` and `EmbeddingReqInput` (new) use it to expand a string rid on a batch into `<rid>_<i>`, with `i` zero-padded to a common width. It rejects empty base rids and the internal `HEALTH_CHECK` prefix. This check covers only batch base rids that get expanded; single rids and explicit rid lists are validated as before.
4. **`rid: Optional[str]`** on `Engine.score` / `async_score`, `TokenizerManager.score_request` and `ScoringRequest` (`/v1/score`). It is the base rid that (3) expands for each item.
5. **Scheduler log prefix** now ends with ` PID<pid>`, filled in by `logging` (`%(process)d`) so it stays correct in child processes. `debug_utils/log_parser.py` accepts it, and its rank-group order now matches what `configure_scheduler_process` emits (`DP PP ATTN_CP MOE_DP TP EP`).
6. **`--log-schedule-decisions`** (`Observability`, off by default). `Scheduler._maybe_log_schedule_decision` logs one line for each prefill pass that evaluates the waiting queue, including passes that pick nothing. It logs on attention TP/CP rank 0 only, prints at most 16 picked rids (`(+N more)`), and logs a pass that picks nothing only when its counters differ from the previous empty pass. Passes that return early (e.g. running batch full) are not logged.
7. **Qwen2/Qwen3 `*ForSequenceClassification`** build the score head as `nn.Linear(..., bias=False)`, matching HF. A checkpoint that contains `score.bias` now fails to load with a clear error. Before this PR such a bias **was** loaded; only checkpoints without one got a randomly initialized bias. HF `*ForSequenceClassification` cannot load such checkpoints either.
8. **`Engine.encode` / `async_encode`** take `input_ids`, appended as the last parameter, and `prompt` is now optional.

### Behavior changes

- (3) With 11 or more sub-requests, sub-rids are zero-padded (`x_00` instead of `x_0`). Batch base rids that are empty or start with `HEALTH_CHECK` raise `ValueError` (single rids and rid lists are unchanged).
- (5) Every scheduler log line now ends its prefix with ` PID<pid>`.
- (7) Qwen2/Qwen3 classification scores change to match HF. Checkpoints that ship `score.bias` used to load and score with that bias; they now fail to load.

File: `python/sglang/srt/managers/scheduler.py` · line None

A few things make this line noisier than it needs to be, even for an opt-in debug flag:

1. **Every TP rank logs it.** The other per-batch scheduler logs are gated on `get_parallel().attn_tp_rank == 0`, so at TP=8 each decision would print 8 times. Suggest the same gate (plus `attn_cp_rank == 0`).
2. **`picked-rids` has no limit.** A score call with hundreds of items, or a long chunked prefill, produces a very long line per pass. Maybe cap it, e.g. the first ~16 rids plus `(+N more)`.
3. **Empty passes can repeat every loop.** After `NO_TOKEN`, `batch_is_full` makes later passes return early, so that case is fine. But a queue blocked for a reason that doesn't set `batch_is_full` (e.g. HiCache staging not ready, which `continue`s) logs `#picked=0` on every scheduler iteration. Logging an empty pass only when its counters change from the previous one would keep the head-of-line-blocking signal without the spam.
