# [Feat] score/embedding: Add normalize flag, score rid tracing, embed-override validation, Qwen cls head fix, and scheduler observability

## Motivation

This PR fixes several gaps in SGLang's embedding and scoring serving path:

- Embedding models always L2-normalize their output, with no way to get the raw pooled vector.
- Malformed embed overrides fail inside the scheduler and abort every request in the same batch.
- Score requests can't be traced across processes.
- Aborting one sub-request of a large batch can abort its siblings.
- Scheduler logs don't show why queued requests are not admitted.
- The Qwen2/Qwen3 sequence-classification head has a randomly initialized bias that HF does not have.
- `Engine.encode` can't take token ids.

Each change is a separate commit and can be reviewed on its own.

## Modifications

1. **`--disable-normalize-embedding` server arg.** Embedding models return the pooled vector without L2 normalization. The flag is read once in `Pooler.__init__`, and the default behavior is unchanged. Documented in `server_arguments.mdx`.
2. **Validate `positional_embed_overrides` when a request comes in.** `TokenizerManager` returns a `ValueError` (HTTP 400) for overrides that are empty, are not 2-D `[N, hidden_dim]`, or whose last dim differs from `hidden_size`. Today such a request fails during the scheduler's embedding scatter and aborts every co-batched request. The rank and length checks only apply to tensors, so CUDA-IPC proxies are not checked.
3. **Zero-padded sub-rids and reserved rid prefixes.** When a batched or `n>1` request has a string rid, it is expanded to `<rid>_<i>`. The scheduler aborts by rid prefix, so aborting `x_1` also aborted `x_10`–`x_19`. Sub-rids are now zero-padded to a common width (`x_00`…`x_11`).
   - A base rid must be non-empty and must not start with an internal prefix (`HEALTH_CHECK`, `draft:`).
   - The helper lives in the new `utils/rid_utils.py`. `DRAFT_RID_PREFIX` moves to `constants.py`, so `decoupled_spec_io.py` and the check share one definition.
4. **Caller-supplied `rid` on score requests.** `Engine.score` / `async_score`, `TokenizerManager.score_request` and `/v1/score` (`ScoringRequest.rid`) accept an optional base rid.
   - Each sub-request is sent as `<rid>_<i>`, so one score call can be traced through the tokenizer, scheduler and detokenizer logs.
   - `EmbeddingReqInput` now expands a string rid on a batch the same way `GenerateReqInput` does, so this works for both generation and classification models.
5. **PID in the scheduler log prefix.** When several schedulers run on one host, the rank prefix alone doesn't say which OS process wrote a line, e.g. when matching logs to py-spy dumps. Scheduler log prefixes now end with ` PID<pid>`.
   - `debug_utils/log_parser.py` accepts the suffix.
   - Its rank groups now follow the order `configure_scheduler_process` emits (`DP PP ATTN_CP MOE_DP TP EP`), so lines with `PP` parse again.
6. **`--log-schedule-decisions`.** Opt-in and off by default. Logs one line for each prefill pass that evaluates the waiting queue:
   - picked vs. left in queue;
   - running and preempted counts;
   - KV free and evictable tokens;
   - the picked rids.

   Passes that admit nothing are logged too, since they show head-of-line blocking. Passes that return early (e.g. running batch full) are not logged. Documented in `server_arguments.mdx`.
7. **Qwen2/Qwen3 sequence-classification score head without bias.** HF builds this head with `nn.Linear(..., bias=False)`. SGLang used the default `bias=True`, and no checkpoint supplies that bias, so it kept its random initial value. As a result it shifted every logit, changed on each launch, and wasn't controlled by `--random-seed`. The head is now bias-free. A checkpoint that does contain `score.bias` fails to load with a clear error instead of having the bias silently skipped.
8. **`input_ids` in `Engine.encode` / `Engine.async_encode`.** `EmbeddingReqInput` already accepts `input_ids`, but these entrypoints only forwarded text, so an engine started with `skip_tokenizer_init=True` (e.g. Ray Data batch inference) couldn't produce embeddings. `prompt` is now optional, and `input_ids` is added as the last parameter so existing positional callers keep working.

### Behavior changes

- (3) With 11 or more sub-requests, returned ids change from `x_0` to `x_00`. A client that aborts a single sub-request by id must use the padded form.
- (3) Base rids that are empty or start with `HEALTH_CHECK` / `draft:` are rejected with `ValueError`.
- (5) Every scheduler log line's prefix ends with ` PID<pid>`.
- (7) Qwen2/Qwen3 `*ForSequenceClassification` scores change; they now match HF. Checkpoints that contain `score.bias` are rejected.

## Accuracy Tests

- Only (7) changes model outputs. It removes a random bias term so Qwen2/Qwen3 classification scores match HF.
- With `--disable-normalize-embedding`, (1) returns the pooled vector. Normalizing it on the client reproduces the default output.
- The other changes don't touch model math.

## Speed Tests and Profiling

Not applicable: none of these changes touch the forward pass.
- (2) adds a shape check per request, and only when overrides are present.
- (6) adds one boolean check per prefill pass when the flag is off.
