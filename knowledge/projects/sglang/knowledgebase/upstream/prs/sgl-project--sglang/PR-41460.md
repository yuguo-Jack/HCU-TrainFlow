# Fix reasoning token usage past speculative finish boundaries

[Upstream PR](https://github.com/sgl-project/sglang/pull/41460) · state: closed · merged: False

## Original PR description

Speculative decoding can accept a block that extends past EOS or `max_new_tokens`. The decode result processor updated reasoning usage before applying that boundary, so a four-token completion could report six reasoning tokens and consume a reasoning terminator that was never emitted. This was also observed in GLM-5.3 MTP responses ending at the output limit.

Update reasoning accounting after finish-state calculation, using only the retained prefix of the current block. The generated tokens, sampling, stop decision, and native draft-acceptance counters are unchanged.

Validation:
- The new actual-module CPU regression fails on unchanged upstream main for both EOS and length boundaries (`6 != 4`), and passes with this change. It exercises real speculative result normalization, request finish handling, and the reasoning matcher; cache release, metrics and output transport are stubbed.
- 37 tests plus four subtests pass across speculative grammar/reasoning, hidden-state output, length, string-stop and grammar-stop suites. The tests also preserve an end marker spanning two decode steps and exclude answer tokens from reasoning usage.
- On GLM-5.3 FP8/BF16-KV, ROCm 7.2.4, MI355X P4+D4 with three-step native MTP, the unpatched model control reproduces `reasoning_tokens=4` with `completion_tokens=2`. The patched candidate passes all 16 chat responses, including 2/3/4/7-token reasoning boundaries repeated twice. All boundaries report reasoning usage equal to completion usage; native counters, protocol, PDD handoff and cancellation pass. Raw streams and request hashes are replayed by the [bench audit producer](https://github.com/MarloweAI/marlowe-bench/pull/116).
- The pinned downstream image also passes all 37 actual-module tests. Its metadata tuple differs from current upstream, so a test-only 17-field fixture adaptation was mounted read-only; the production fix is unchanged and hash-verified. This is accounting validation, not a sampling-equivalence claim.
- Ruff lint/format and `git diff --check` pass. Hosted CI currently stops at the draft-PR gate; the model-serving and unit results above are separately executed validation.
