# [Fix] quantization: Check tensor dtypes in E8M0 parameter copy guard

[Upstream PR](https://github.com/sgl-project/sglang/pull/40464) · state: open · merged: False

## Original PR description

## Motivation

`copy_with_check` compares `loaded_rank` (an integer) with `torch.float8_e8m0fnu`, so its E8M0-specific destination check never runs. For example, E8M0 scales containing `2**20` and `2**-30` are silently copied to FP16 as `inf` and `0`.

## Modifications

Compare the source and destination tensor dtypes instead. This restores the existing E8M0/FP32 allow-list without changing the ordinary rank-based downcasting policy.

Add registered CPU tests for allowed destinations, rejection before target mutation (including with the downcasting override), ordinary dtype behavior, and the real `BlockQuantScaleParameter.load_column_parallel_weight` path.

## Accuracy Tests

On the unchanged baseline, the new tests reproduce 15 failing subcases. With the fix, all 4 test methods pass, with no skips:

```bash
CUDA_VISIBLE_DEVICES=999 PYTHONPATH="$PWD/python" python test/registered/unit/layers/test_parameter.py
```

Tested on WSL Linux, Python 3.12, PyTorch 2.13.0+cu130, with CUDA hidden. These use real CPU tensors and the production loading code. No full-model accuracy run was performed.
