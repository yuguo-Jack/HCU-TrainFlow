# Lazily initialize NCCL2 process groups

## Original PR description

Signed-off-by: Tushar Jain <tushar00jain@users.noreply.github.com>

### Summary

#### NCCL2

We recently rolled out a new version of the NCCL communications backend in PyTorch. More details here -  https://pytorch.org/blog/pytorch-2-14-release-blog. The changes in this pull request are needed to adapt the new back end. Particularly,

- Make sure that pipeline parallel communications can overlap
- Don't initialize process groups that we never call to save memory

#### Pipeline-parallel groups

On the NCCL2 path, pipeline-parallel groups use `nccl-lazy` for independently initialized per-peer communicators, allowing communication with different pipeline peers to overlap.

#### Lazy NCCL2 process groups

Create NCCL2 groups with `lazy_init` when their normal communication path uses a custom backend.

Singleton groups and the default group are also initialized lazily. This avoids registering GPU memory for NCCL2 communicators that may never be used, while preserving correctness for groups that are used later. Legacy NCCL behavior is unchanged.
