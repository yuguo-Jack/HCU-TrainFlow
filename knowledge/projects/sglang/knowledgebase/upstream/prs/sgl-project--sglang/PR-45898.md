# [Fix] granitemoe: Declare packed_modules_mapping so per-projection quant targets match qkv_proj

[Upstream PR](https://github.com/sgl-project/sglang/pull/45898) · state: open · merged: False

## Original PR description

## Motivation

`GraniteMoeForCausalLM` fuses `q_proj`/`k_proj`/`v_proj` into `qkv_proj` but declares no `packed_modules_mapping` (unlike `GraniteMoeHybridForCausalLM`, and vLLM's `GraniteMoeForCausalLM`). The model loader hands that mapping to the quant config, which uses it to match a fused layer to per-projection targets. Without it, a compressed-tensors checkpoint that gives attention its own scheme fails to load. For example, FP8 attention alongside 4-bit experts, with targets `re:.*self_attn\.(q|k|v|o)_proj$`:

```
ValueError: Unable to find matching target for model.layers.0.self_attn.qkv_proj in the compressed-tensors config
```

Single-scheme checkpoints (`targets: [Linear]`) are unaffected, which is why this hasn't surfaced before.

## Modifications

- `python/sglang/srt/models/granitemoe.py`: declare `packed_modules_mapping` on `GraniteMoeForCausalLM`.
  - `qkv_proj` ← `q_proj`, `k_proj`, `v_proj`.
  - `input_linear` ← `input_linear`: `GraniteMoeShared`'s shared-expert gate+up, which is stored fused (as in `GraniteMoeHybrid`).
  - `GraniteMoeSharedForCausalLM` and `GraniteMoeSWAForCausalLM` inherit it.
- `test/registered/unit/models/test_granitemoe_packed_modules.py` (new, CPU), using a mixed-precision compressed-tensors config (FP8 attention, NVFP4 experts):
  - `qkv_proj` resolves to the attention scheme;
  - `o_proj` still matches;
  - without the mapping, the lookup raises the error above;
  - the two subclasses inherit the mapping.

## Accuracy Tests

On H200 (SM90), with this change applied to an earlier SGLang build: GraniteMoE checkpoints with FP8 attention plus NVFP4A16 or MXFP4A16 experts now load. Before, they failed with the error above. Their teacher-forced KL against bf16, on a fixed chat prompt set, matches vLLM's on the same checkpoints to within noise, with thinking both off and on.

The unit test passes on this branch's base (current main); lint (ruff, isort, codespell at the pre-commit versions) is clean.
