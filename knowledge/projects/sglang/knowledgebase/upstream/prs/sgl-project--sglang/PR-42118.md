# [Feat] rust/grpc: Add ListModels, Detokenize, and Abort to api.v1

[Upstream PR](https://github.com/sgl-project/sglang/pull/42118) · state: closed · merged: True

## Original PR description

## Summary

Complete the native Rust gRPC surface on the shared `sglang.api.v1` contract, specifically targeting core LLM functionality.

## Changes
 
### gRPC service

- **RPCs:** add `ListModels`, `Detokenize`, and `Abort` alongside the existing `Generate`, `HealthCheck`, `GetModelInfo`, and `GetServerInfo`.
- **Generation fields:** LoRA adapter, routing key, KV hints, and other fields forwarded to the scheduler. 
- **Discovery:** `GetServerInfo` returns typed deployment info (parallelism, DP rank, disaggregation, KV-event sources).
- **Attention DP:** with the Rust server, each DP rank's listener now handles its own control requests (aborts, server info).
- Regenerated Rust and Python bindings; extended tests.

## Abort contract

- `rid` selects a native `/generate` or gRPC `Generate` ID; `abort_all=true` cancels all active frontend generations.
- `success` means an active match was found and cancellation was requested, not scheduler acknowledgement.

### Live GPU validation

Validated end to end on GPUs, driving the Rust server's `sglang.api.v1` gRPC listeners directly with a standalone client.

- **Hardware/model:** NVIDIA B200, (1×4 and 2×4 GPUs, Qwen3-30B-A3B).
- Ran with and without KV events enabled.
- Single node agg: TP1, TP2, attention-DP2, attention-DP4.
- Single node disagg: TP1 prefill + TP1 decode, TP2 prefill + TP2 decode, attention-DP2 prefill + attention-DP2 decode.
- Multi-node agg: TP8 spanning both nodes, attention-DP8 (4 listeners per node).
- Multi-node disagg: attention-DP4 prefill on node A + attention-DP4 decode on node B.
