# [Fix] marlin: Prevent scale underflow in NVFP4 fallback on SM80-SM90 (#44998)

[Upstream PR](https://github.com/sgl-project/sglang/pull/45031) · state: open · merged: False

## Original PR description

fixes #44998

when running nvfp4 on pre-blackwell gpus with marlin, checkpoints that have small block scales (like weight_scale_2 = 1.0 from modelopt, probec, or llm-compressor) underflow during bf16 dequantization. the marlin packing does `(scales * 2^7).view(int16) << 1` which assumes `scales * 2^7 >= 2`. with small scales, the top bit is unset and bf16 exponent widening causes the weights to dequantize to zero, corrupting output.

ported the fix from vllm #34577:
- added `_nvfp4_compute_scale_factor` to upscale small block scales by a power of 2 so `scales * 2^7 >= 2`
- clamped subnormals (`scales < 2`) to zero to prevent bit corruptions
- compensated by dividing `weight_global_scale` by `scale_factor`
- unified the scale factor across experts in `prepare_moe_nvfp4_layer_for_marlin`
- added unit tests covering scale factor computation, dense/moe scale adjustment, and underflow prevention
