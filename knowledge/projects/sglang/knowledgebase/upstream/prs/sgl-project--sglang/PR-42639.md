# [Rust] Accept zstd-compressed requests in the Rust frontend

[Upstream PR](https://github.com/sgl-project/sglang/pull/42639) · state: closed · merged: False

## Original PR description

## Motivation

With `SGLANG_ENABLE_REQUEST_DECOMPRESSION` set, the Python server decompresses request bodies sent with `x-body-compressed: zstd`. The Rust frontend ignores the header and hands the compressed bytes to the handlers, so the same client fails against a Rust-mode server.

## Modifications

- A Rust middleware follows the Python contract: the body is decompressed before routing, the header is removed, `Content-Length` is rewritten, and unsupported methods or corrupt bodies get the same 400 responses.
- Unlike the Python middleware, it caps the decompressed body at 512 MiB (sgl-model-gateway's default request limit) and answers 413 beyond that, since a few KB of zstd can expand to gigabytes.
- The Python launcher forwards the env flag to the Rust server config. It stays off by default.
- Tests:
  - Rust: a body compressed by Python's `zstandard` is rewritten for POST and PUT; the size cap; invalid compression errors before streaming; pass-through when disabled or without the header.
  - Python: the flag is forwarded into the typed config.

## Tests

- `python -m pytest -q test/registered/unit/entrypoints/test_rust_server_dp_ports.py`: 17 passed.
- In `rust/`: `cargo test -p sglang-server` (338 passed), `cargo clippy -p sglang-server --all-targets -- -D warnings` and `cargo fmt --all -- --check` are clean.
- `pre-commit run --from-ref origin/main --to-ref HEAD`: all hooks pass.
- Real server on one A100 (Llama-3.2-1B-Instruct, `SGLANG_RUST_SERVER=1 SGLANG_ENABLE_REQUEST_DECOMPRESSION=1`), together with the related Rust-frontend PRs:
  - A zstd-compressed `/generate` returns 200 with the expected completion.
  - `x-body-compressed: gzip` returns 400 `unsupported x-body-compressed 'gzip'; supported: ['zstd']`.
  - A corrupt body returns 400 `decompress failed`.
