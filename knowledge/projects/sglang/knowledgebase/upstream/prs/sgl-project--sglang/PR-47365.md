## Motivation

The NPU coverage baseline was only refreshed by a manual `workflow_dispatch`,
which made it easy to forget and let the baseline drift from the test suite as
it kept growing. Downstream precise-test selection and coverage comparisons
therefore worked against a stale map.

The publish gate was also too loose: `MIN_NPU_COVERAGE=10` let a mostly-broken
coverage run still pass the check and overwrite the good baseline on the shared
disk / OBS, silently degrading later comparisons.

## Modifications

- [.github/workflows/coverage-collection-npu.yml](<file:///m:/PyCharm/WorkSpace/Ascend/sglang/.github/workflows/coverage-collection-npu.yml#L18-L21>)
  - Add a `schedule` trigger with `cron: "0 21 */2 * *"` (05:00 Asia/Shanghai,
    every 2 days), so the baseline is rebuilt automatically instead of relying
    on manual dispatch.
  - Update the header comment to reflect that the pipeline is triggered by both
    `workflow_dispatch` and `schedule`.
- [.github/workflows/pr-test-npu.yml](<file:///m:/PyCharm/WorkSpace/Ascend/sglang/.github/workflows/pr-test-npu.yml#L1184>)
  - Raise `MIN_NPU_COVERAGE` from `10` to `40`, so a coverage run that collected
    far less than expected fails closed instead of being published as the new
    baseline.

No product code is changed; this is CI/coverage infrastructure only.
