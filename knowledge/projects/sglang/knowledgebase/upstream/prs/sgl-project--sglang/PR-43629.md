# [Fix] kda: Preserve prefill fallback for packed one-token batches

[Upstream PR](https://github.com/sgl-project/sglang/pull/43629) · state: open · merged: False

## Original PR description

## Motivation

Fixes #43615, reported by @StarDuster.

FlashInfer's ordinary packed prefill requires `total_tokens > num_sequences`. SGLang currently checks only `total_tokens > 1`, so `[1, 1]` and similar EXTEND batches reach FlashInfer's recurrent path with the prefill adapter's 2-D bias and possibly FP32 state. That path rejects the bias stride; flattening it then exposes the unsupported FP32 state copy.

## Modifications

- Pass the sequence count from `query_start_loc.shape[0] - 1` into the existing fallback decision. No GPU offset read or synchronization.
- Use Triton when the packed token count cannot enter ordinary FlashInfer prefill. Preserve the existing single-token guard and safe-gate fallback.
- Apply the same decision to the tracked-state capability check. Do not flatten bias, downcast state, or disable FP32 ordinary prefill.
- Add host dispatch regressions and extend the existing backend test with packed one-token, padded and mixed-prefill cases.

## Accuracy Tests

On one B300, FlashInfer 0.7.0.post1 / CUTLASS DSL 4.8.0, PyTorch 2.11.0+cu130 / Triton 3.6.0:

- Ten fresh-process component comparisons: lengths `[1,1]`, `[1,1,1,1]`, `[2,0]`, `[2]`, `[1,2]`, each with FP32 and BF16 state.
- The six affected baseline cases raised the reported stride error; all ten fixed cases passed output/final-state comparisons against an independent FP32 sequential recurrence. Maximum relative L2 error: output 0.005904, state 0.002118. An unused state slot remained bit-identical.
- The four ordinary-prefill controls passed in both arms, including FP32 state.
- Four host routing tests passed; the unchanged dispatch failed the actual `extend` routing regression.

Scope: these ran the real, unmodified SGLang leaf adapters and native kernels. Package entrypoints were namespace-isolated, and the two dispatcher methods were loaded without the model-runner import graph. The host test used `unittest.TestCase` instead of the heavyweight project test base. This is **not** a full installed-package/backend/server run. The available runtime also differs from current main's full dependency set. The committed registered CPU and full-backend GPU tests have **not** been executed via their official entrypoints and still need upstream CI:

```bash
python test/registered/unit/layers/attention/test_kda_prefill_dispatcher.py
python test/registered/attention/test_kda_prefill_flashinfer.py
```

Applicable formatting/lint hooks passed. Three local hooks could not launch the Windows `python3` alias; the same three lint scripts passed when invoked directly with native Python 3.12. `git diff --check` passed.

## Speed Tests and Profiling

Correctness fix only; no performance or whole-model claim. Ordinary multi-token dispatch is unchanged.
