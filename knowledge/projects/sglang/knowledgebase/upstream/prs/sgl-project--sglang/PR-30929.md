# [Feat] [AMD] disagg: Support DSV4 decode radix cache on ROCm unified KV (bf16/fp8, DSpark)

[Upstream PR](https://github.com/sgl-project/sglang/pull/30929) · state: closed · merged: True

## Original PR description

## Motivation

`--disaggregation-decode-enable-radix-cache` rejects DeepSeek-V4 when the KV cache is built, which also blocks DSpark decode even though the server-args check already admits DSPARK (#40263). On the ROCm unified KV layout (bf16, or fp8 with `SGLANG_DSV4_UNIFIED_KV_FP8=1`), the SWA rings and the c128 state are request-scoped and always transferred whole, so the decode tree only needs to share the page-indexed compressed full-attention KV.

## Modifications

- `kv_cache_builder.py`: move the decode radix checks into `validate_decode_radix_cache()`; admit DeepSeek-V4 on the unified KV layout (bf16 or fp8) and keep rejecting the paged layout. The other rules are unchanged.
- Help text and `server_arguments.mdx`: only speculative decoding other than DSPARK is incompatible.
- Tests: `test_decode_radix_cache_validation.py` (CPU).

## Accuracy Tests

DeepSeek-V4-Pro-0813 + DSpark, 1P1D on one MI355X node, MoRI. Flags and env follow the InferenceY AgentX recipe `disagg-umbp-dspark.yaml` (without UMBP and MegaMoE), prefill radix cache on.

| Config | Prefill / decode | DSpark block size |
|---|---|---|
| bf16 unified KV (recipe c4) | TP4 / TP4 | 6 |
| fp8 unified KV (recipe c192+) | TP4 + DP4 attention / TP4 + DP4 attention | 3 |

Workload: multi-turn GSM8K, greedy, concurrency 16. Each turn resends the previous prompt + output + a new question, so from turn 2 the reused prefix includes KV generated by decode under DSpark. Short: 8-shot prefix, 48 sessions x 5 turns. Long: 120-shot prefix (~18K tokens), 32 sessions x 4 turns.

| Config | Workload | GSM8K off / on | Accept length off / on | Same answer, off vs on | Errors |
|---|---|---|---|---|---|
| bf16 | short | 0.967 / 0.971 | 4.40 / 4.38 | 235/240 | 0 |
| bf16 | long | 0.922 / 0.938 | 4.41 / 4.43 | 126/128 | 0 |
| fp8 | short | 0.963 / 0.971 | 3.38 / 3.38 | 235/240 | 0 |
| fp8 | long | 0.930 / 0.914 | 3.40 / 3.38 | 124/128 | 0 |

Also run on DeepSeek-V4-Flash + DSpark, about 5,000 requests with radix on (concurrency 56, a 65,536-token decode pool, `SGLANG_ENABLE_TREE_CACHE_SANITY_CHECK=1`): 0 errors, GSM8K 0.928 vs 0.929 with radix off.

## Speed Tests and Profiling

Same runs; payload counted per request and decode rank from the transfer indices.

| Config | Workload | Prompt tokens sent, on vs off | Payload off → on |
|---|---|---|---|
| bf16 | short | 23% | 44.7 → 34.7 MiB (-22%) |
| bf16 | long | 13% | 190.5 → 52.7 MiB (-72%) |
| fp8 | short | 23% | 37.1 → 30.6 MiB (-18%) |
| fp8 | long | 13% | 131.3 → 42.2 MiB (-68%) |

28-31 MiB per request is request-scoped state that is always sent whole, so the saving grows with context length. `sglang:kv_transfer_total_mb` over-counts state bytes until #33806.

Note: under DP attention, decode only hits when the router keeps a session on one decode DP rank.

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

In the read-only traversal loop, if `matched < len(child.key)`, it means we only partially matched the child node's key. Since we did not fully match the node's key, we cannot proceed to its children (as any descendants must share the full key of this node as their prefix). Continuing the loop in this case is incorrect and could lead to traversing down an unrelated branch if there is a key collision, or at least performing redundant iterations. We should append the partially matched value, update `full_last_node`, and immediately `break` the loop.

```suggestion
        if len(remaining_key) > 0:
            child_key = remaining_key.child_key(self.page_size)
            while len(remaining_key) > 0 and child_key in walk_node.children:
                child = walk_node.children[child_key]
                full_data = child.component_data[BASE_COMPONENT_TYPE]
                if full_data.value is None:
                    break
                matched = child.key.match(remaining_key, page_size=self.page_size)
                value = full_data.value
                if matched < len(child.key):
                    full_values.append(value[:matched])
                    full_last_node = child
                    break
                full_values.append(value)
                full_last_node = child
                walk_node = child
                remaining_key = remaining_key[matched:]
                if len(remaining_key) == 0:
                    break
                child_key = remaining_key.child_key(self.page_size)
```
