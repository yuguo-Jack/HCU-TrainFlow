## Motivation

- Generate block-level kv_indices directly in create_flashmla_kv_indices_triton
  by passing PAGED_SIZE=page_size, eliminating the per-step
  _transform_table_1_to_real overhead (tensor alloc + gather + div + copy)
- Use launch_reshape_and_cache_flash for non-SWA models to fuse K/V cache
  writes into a single Triton kernel instead of two separate scatter ops

## Code Review

This pull request introduces optimizations for unified attention on AMD GPUs, specifically for non-SWA (Sliding Window Attention) models. The changes are well-implemented and focus on two main areas:

1.  **Optimized index generation**: For non-SWA models, the code now directly generates block-level `kv_indices` instead of creating token-level indices and then transforming them. This is achieved by modifying the call to the `create_flashmla_kv_indices_triton` kernel. This optimization is consistently applied across `init_forward_metadata`, `init_forward_metadata_capture_cuda_graph`, and `init_forward_metadata_replay_cuda_graph` functions.
2.  **Optimized KV cache write**: The `launch_reshape_and_cache_flash` function is now utilized for non-SWA models, extending its use beyond just SWA models. The SWA-specific logic is correctly guarded, ensuring that non-SWA paths do not execute SWA-related code. This change is applied in both `forward_extend` and `forward_decode` methods.

Additionally, the pull request includes a minor but effective optimization by moving the creation of `page_indices` into the conditional block where it is used, avoiding unnecessary computation.

The changes are clear, consistent, and appear to correctly implement the intended optimizations. I have not found any issues or bugs in the implementation.
