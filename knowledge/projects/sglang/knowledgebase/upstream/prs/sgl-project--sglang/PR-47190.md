# [Fix] [AMD] dsv41: Refuse PD peers that differ in the page-8 index-K layout

[Upstream PR](https://github.com/sgl-project/sglang/pull/47190) · state: open · merged: False

## Original PR description

## Motivation

`SGLANG_HIP_DSV41_INDEX_K_PAGE8` stores the ratio-1 index-K pool in AITER's row-group page-8 order. The page size and shapes match page-64; only the bytes differ, so PD peers must agree (the pool's own comment says so). Nothing enforces this today:

- `pd_kv_layout()` covers only the main and compressed KV layouts.
- The transfer compares item lengths, which are the same in both layouts.

A page-8 prefill paired with a page-64 decode, or the reverse, therefore passes the handshake. The decode reads the transferred index keys in the wrong order, its top-k picks the wrong blocks, and no error is raised. The same pair is also formed when both peers set the env but one peer's AITER lacks the row-group kernel and falls back to page-64. Monokernels are not involved; any DeepSeek-V4.1 PD pair can hit this.

## Modifications

- `DeepSeekV4TokenToKVPool.pd_kv_layout()` appends `idx{ratio}:page8` for each index-K pool in the page-8 layout, after the fallback is resolved. The existing `KV layout mismatch` check in `CommonKVManager` then refuses such a pair. With page-8 off the name is unchanged, so a default-config pair still pairs whether or not each peer has this change.
- The mismatch error now names `SGLANG_HIP_DSV41_INDEX_K_PAGE8` beside `SGLANG_DSV4_KV_LAYOUT`.
- A unit test in `test_dsv4_compressed_pools.py` checks the page-8 name.

## Accuracy Tests

DeepSeek-V4.1-Flash + DSpark, 1P1D on one MI355X node over MoRI, TP4 each, no monokernels, `lmsysorg/sglang-rocm:v0.5.22-rocm10-mi35x-20261028` running this branch. Its AITER has the row-group kernel, so page-8 is in effect where set. GSM8K is `sglang.test.few_shot_gsm8k` with 1319 questions, sent through the PD router.

| SGLang | prefill PAGE8 | decode PAGE8 | result |
|---|---|---|---|
| this PR | 1 | 0 | refused at the first transfer: `KV layout mismatch: prefill server has kv_layout=v4,c1:v4,c2:v4,idx1:page8, but decode server has kv_layout=v4,c1:v4,c2:v4. ...` |
| this PR | 1 | 1 | serves; GSM8K 0.911 at parallel 64, 0.894 at parallel 8 |

On main, the mismatched pair loses 7 to 9 points against matched pairs (0.889 to 0.911 at parallel 64 on this setup) and raises no error. This PR refuses the same pair at its first transfer.

`test_dsv4_compressed_pools.py` on GPU: the new test passes. Five `TestDSparkDraftRingWithEncoderReplay` cases fail on both main and this branch in this image, so they are not from this change.
| main | 1 | 0 | serves with no error; GSM8K 0.823 at parallel 64, 0.835 at parallel 8 |
