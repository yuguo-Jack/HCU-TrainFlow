[Upstream PR](https://github.com/sgl-project/sglang/pull/32057) · state: closed · merged: False

## Original PR description

# [Fix] Preserve caller-owned hidden_states in DeepGemm standard pre-permute

## Motivation

Fixes #32056.

`pre_permute_standard_to_deep_gemm` unconditionally calls
`dispose_tensor(hidden_states_ref)` after repacking tokens into the
expert-major DeepGEMM buffers. `dispose_tensor` shrinks the storage in
place, so the caller's `hidden_states` reference is destroyed even when the
runner was invoked with `inplace=False`.

Models that re-use `hidden_states` after the routed experts return break:
Qwen3.5 / Qwen2-MoE-style shared-expert blocks compute the shared-expert
branch and its sigmoid gate from the same tensor
(`fused_gate_sigmoid_mul_add` in `qwen2_moe.py`) and crash on the first MoE
layer with `--moe-runner-backend deep_gemm`.

## Modifications

Gate the disposal on `runner_config.inplace`, which is the existing
ownership contract (`inplace=True` = runner may consume the input):

```python
    if runner_config.inplace:
        dispose_tensor(hidden_states_ref)
```

- `inplace=True` (default; models without a shared expert): behavior
  unchanged, the activation is still released early to save memory.
- `inplace=False` (shared-expert models such as Qwen3.5): the caller's
  tensor stays intact and the shared-expert gate works.

The DeepEP pre-permute path is untouched — it owns its dispatched tensor and
may keep disposing unconditionally.

## Accuracy / performance

- Verified end-to-end on Qwen3.5-397B-A17B-FP8 (TP8/EP8,
  `--moe-runner-backend deep_gemm`): previously crashed with
  `ValueError` in the shared-expert gate on the first MoE layer, now runs
  correctly with outputs matching the triton runner baseline.
- No behavior change for `inplace=True` callers; the early disposal (memory
  optimization) is preserved on that path.
