# [Doc] install: Document CUDA Toolkit, compiler, and Rust prerequisites

[Upstream PR](https://github.com/sgl-project/sglang/pull/45121) · state: open · merged: False

## Original PR description

## Motivation

The pip / uv and from-source instructions in `docs/docs/get-started/install.mdx` do not list several requirements that a fresh Linux machine needs before `sglang serve` works. The CI bootstrap (`scripts/ci/cuda/ci_install_dependency.sh`) and the Dockerfile already provide all of them, so the gap only shows up outside those environments, one failure at a time.

On a fresh WSL2 Ubuntu 24.04 machine with only the NVIDIA driver installed, following the current page hit these in sequence:

| Missing | Symptom |
| --- | --- |
| Rust toolchain (from source) | `RuntimeError: cargo is required to discover the Rust extension modules ...` |
| C compiler | `UserWarning: Triton is not supported on current platform, roll back to CPU.`, then `Failed to find C compiler` during CUDA graph capture |
| Python headers (system Python venv) | `driver.c: fatal error: Python.h: No such file or directory` |
| CUDA Toolkit / `nvcc` | `Failed to build JIT module sgl_kernel_jit_fused_rope_...` with `/usr/local/cuda/bin/nvcc: not found` (also with `flashinfer-jit-cache` installed, since SGLang's own JIT kernels need `nvcc`) |

I reproduced each one on `main` by hiding the corresponding tool inside a single process, and confirmed that a setup following the CI script starts the server on the first try.

Related:
- #29279 proposed similar docs for the old `docs_new/` tree and was closed by the stale bot without review. Its `protoc` step is no longer needed: protobuf bindings are checked in since #41726, and no crate in `rust/` has a `build.rs` or a build-time protoc dependency.
- #20076 reports the `nvcc: not found` JIT failure in runtime containers.
- #18644 added `python3-dev` to CI for the same Triton `Python.h` failure.

## Modifications

`docs/docs/get-started/install.mdx` only:

- **pip / uv tab**: list the CUDA Toolkit 13 (`nvcc`), C compiler, and Python header requirements, including the toolkit lookup order from `python/sglang/kernels/jit/utils/compile/toolchain.py` (`CUDA_HOME`/`CUDA_PATH`, then `nvcc` on `PATH`, then `/usr/local/cuda`).
- **pip / uv tab**: create the venv with `--python-preference only-managed`, as the CI script does, so uv uses a Python build that ships `Python.h` even when a system Python 3.12 exists.
- **From source tab**: add the rustup step (the toolchain version comes from `rust/rust-toolchain.toml`) and an accordion for `SGLANG_BUILD_RUST_EXTS=none`, noting that Rust-backed features such as the gRPC server build their extension on first use.
- **Troubleshooting**: add entries for `nvcc not found`, the misleading Triton CPU fallback warning, and `cargo is required`, so the error strings are searchable.

The `git clone -b v0.5.21 ...` line that `scripts/release/bump_docs_install_version.py` rewrites is unchanged, and all existing anchors are kept.
