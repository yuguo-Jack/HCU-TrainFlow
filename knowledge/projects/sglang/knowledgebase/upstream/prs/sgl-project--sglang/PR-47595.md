# [Fix] eplb: Exclude draft statistics and reuse compatible TP groups

[Upstream PR](https://github.com/sgl-project/sglang/pull/47595) · state: open · merged: False

## Original PR description

## Summary

Keep speculative draft execution out of the target's EPLB statistics, and reuse an existing TP device group for EPLB communication when it has the same ranks and backend as WORLD.

Rebased onto `main` at `c04bae2b`, including merged #47574. Ascend weight staging and valid-route statistics come from that merged implementation; this PR keeps the two changes below in separate commits.

## 1. Exclude draft execution from target statistics

Target and draft runners share a recorder. A model-level hook guard can stop draft counts from being written, but the outer recorder still resets the buffer and appends an empty record. Those records consume space in the target's rolling window.

`ModelRunner.forward` now passes `is_draft_worker` to the recorder context. Draft execution disables recording hooks and skips buffer reset, collection, and append. Real target passes with zero routes remain in the window. The runner role identifies draft execution even when its forward mode is `TARGET_VERIFY`.

Prefill and decode graph capture call the model directly, bypassing this forward context. Their entry points use the same disable context so models without an internal draft guard do not capture writes to the target counter. DSpark already guards its model body; its empty-record issue is fixed by skipping the outer recorder lifecycle. The existing `_hook_enabled()` check handles both hooks and direct count-buffer access.

## 2. Reuse compatible TP communication

EPLB statistics and weight migration currently use default WORLD. They now use the existing TP device group when its ranks equal WORLD in the same order, its backend matches, and elastic EP is disabled. Other configurations retain WORLD. This keeps collective roots and P2P peer IDs consistent with the existing expert layout.

`communication.py` supplies the group to both statistics and migration. It creates no group and inherits TP's configuration. With EPLB enabled, startup warms the selected TP group's collective and all-peer P2P channels once, before forward or graph capture. All ranks participate at startup so an idle rank can safely skip a later migration. This adds startup communication and can initialize backend resources; group reuse does not mean zero allocation.

## Validation

CPU checks rerun on `c04bae2b` plus these two commits:

- 200 target records retained with interleaved draft passes; valid target-zero records, nested contexts, exceptions, and 16 capture cases pass.
- 40 group-selection cases and a 16-rank P2P startup simulation pass. The shared migration check passes 400 configurations with both TP and WORLD paths, checking peer matching, tensor values, and original storage addresses.
- With #47574 now in main: 400 NPU staging/migration configurations and 24 focused staging cases pass using CPU storage/transport doubles. Every candidate P2P operation uses the selected TP group. The merged NPU implementation is unchanged; its callback reaches the shared migration function and uses the same group selector as statistics. The device-aware utilization tensor and explicit broadcast group are both retained.
- Formatting, isort, syntax, and whitespace checks pass. Ruff reports no new diagnostics relative to `c04bae2b`; the prefill graph file has 15 existing upstream import diagnostics.

Earlier device validation at `798bd8c2` used two Ascend NPU ranks: collectives and four migration cases per rank passed, including graph replay after migration; 16 graph-counter cases per rank excluded draft writes and retained target writes. The edited EPLB/capture functions retain that implementation; this update reruns CPU checks and does not add a new device result.

- AndyLi429 · comment · 2026-11-01T09:06:22Z · [source](https://github.com/sgl-project/sglang/pull/47595#discussion_r4434855300)

File: `python/sglang/srt/eplb/communication.py` · line 56

The warmup posts an isend/irecv to every peer on every rank. NCCL establishes P2P connections lazily per peer, so this moves an O(N) connection setup per rank (O(N²) globally) into startup for every deployment with enable_eplb, including ones that may never migrate. At large EP sizes this can add noticeable startup time and per-peer NCCL buffer memory. The PR description acknowledges “group reuse does not mean zero allocation”, but the commit is labeled perf and there are no numbers. Could you share startup time and GPU memory delta before and after, e.g. at 8, 16, and 64+ ranks? If the overhead is significant, consider gating the warmup (for example, only when a rebalance is actually triggered) or warming up only the peers the first migration can touch.

- AndyLi429 · comment · 2026-11-01T09:06:41Z · [source](https://github.com/sgl-project/sglang/pull/47595#discussion_r4434855914)

File: `python/sglang/srt/eplb/communication.py` · line 60

rank = dist.get_rank() returns the global rank, but peer iterates over range(world_size) where world_size = dist.get_world_size(group), so it is a group-rank range. This is only correct because get_eplb_group() (L34) guarantees the TP group is an identity mapping of WORLD. The same assumption underlies dst=0/src=0 in expert_distribution.py. Please use dist.get_rank(group) here, and add a short comment or assert stating the identity-mapping invariant, so a future relaxation of the L34 check doesn’t silently break peer matching.

- AndyLi429 · comment · 2026-11-01T09:06:55Z · [source](https://github.com/sgl-project/sglang/pull/47595#discussion_r4434856546)

File: `python/sglang/srt/eplb/communication.py` · line 24

The accumulator resolves the group once in __init__ (expert_distribution.py L775), while update_expert_weights_single_layer calls get_eplb_group() again on every call (L199). If the two resolutions ever differ, e.g. get_parallel().tp_group is None when the accumulator is constructed but set later, then statistics fall back to WORLD while migration uses the TP group. That group was never warmed up, which defeats the “first batch_isend_irecv includes every rank” guarantee. Please resolve once and cache (module-level or on the accumulator), and have both call sites use the cached value. This also avoids rebuilding list(range(dist.get_world_size())) (L34) on every per-layer call.
