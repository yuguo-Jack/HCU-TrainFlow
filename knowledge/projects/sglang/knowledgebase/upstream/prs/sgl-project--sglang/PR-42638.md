# [Rust] Serve HTTP/2 and reject TLS flags in the Rust frontend

[Upstream PR](https://github.com/sgl-project/sglang/pull/42638) · state: closed · merged: False

## Original PR description

## Motivation

The Rust frontend serves only HTTP/1.1. With `SGLANG_RUST_SERVER=1`:

- `--enable-http2` has no effect, yet the launcher still requires granian, which only the Python server's HTTP/2 uses.
- The TLS flags (`--ssl-keyfile`, `--ssl-certfile`, ...) are silently ignored, so a launch that asks for TLS serves cleartext.

## Modifications

- With `--enable-http2`, the listener (hyper-util's auto builder) also serves cleartext HTTP/2 (prior knowledge). It uses the Python server's `http2_max_concurrent_streams` and `http2_initial_connection_window_size`, validated at startup. `/server_info` reports them, as Python does.
- Rust mode rejects every TLS flag at launch instead of serving cleartext.
- The granian requirement for `--enable-http2` now applies only to the Python frontend.
- Tests:
  - Rust: protocol, stream-limit, peer-address and shutdown behaviour match the configuration; invalid HTTP/2 settings fail before startup.
  - Python: every TLS flag is rejected; granian is required only for the Python frontend.

## Tests

- `python -m pytest -q test/registered/unit/server_args/test_server_args.py`: 283 passed.
- In `rust/`: `cargo test -p sglang-server` (336 passed), `cargo clippy -p sglang-server --all-targets -- -D warnings` and `cargo fmt --all -- --check` are clean.
- `pre-commit run --from-ref origin/main --to-ref HEAD`: all hooks pass.
- Real server on one A100 (Llama-3.2-1B-Instruct, `SGLANG_RUST_SERVER=1 ... --enable-http2`), checked together with the related Rust-frontend PRs:
  - `curl --http2-prior-knowledge` gets `HTTP/2 200` from `/health` and `/generate`.
  - `/server_info` reports `enable_http2: true`, `http2_max_concurrent_streams: 200` and `http2_initial_connection_window_size: 1048576`.
