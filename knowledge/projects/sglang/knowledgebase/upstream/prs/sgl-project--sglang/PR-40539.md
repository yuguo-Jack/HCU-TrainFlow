# [DCP] Run fi_a2a on FlashInfer's fused all-to-all + LSE reduce

[Upstream PR](https://github.com/sgl-project/sglang/pull/40539) · state: closed · merged: False

## Original PR description

## Motivation

`--dcp-comm-backend fi_a2a` (the Blackwell default for MLA decode context parallelism) runs three kernels per MLA layer per
decode step:
1. `dcp_pack_a2a_send` packs the attention output;
2. FlashInfer's MNNVL `helixAllToAllKernel` exchanges it;
3. the Triton `_dcp_lse_combine_kernel` merges it.

FlashInfer's `decode_cp_a2a_lse_reduce` does the exchange and the LSE-weighted merge in **one kernel**:
- flashinfer-ai/flashinfer#4929 added it;
- flashinfer-ai/flashinfer#5726 rewrites its protocol (LL128: no fence or grid barrier on the critical path) and makes it run
  on whichever torch symmetric-memory backend the process uses.

This PR makes `fi_a2a` use that op, and only it.
- The kernel reads the attention output in place (a strided view), so the pack kernel is gone too: three kernels per layer
  become one.
- The workspace lives on torch's default (CUDA) symmetric-memory backend, which it shares with `CustomAllReduceV2`. Nothing
  else in the process changes: no backend switch, custom all-reduce v2 stays on, no `NCCL_CUMEM_ENABLE` change.

**Dependency.** This needs a flashinfer-python release that contains flashinfer-ai/flashinfer#5726. sglang currently pins
0.7.0.post1, which has no fused op; the release candidates so far (0.7.1rc1–rc5, 0.7.2rc1) have #4929's version, which
forces the NCCL backend. This PR stays draft until the FlashInfer bump lands. Until then:
- an unset `--dcp-comm-backend` resolves to `a2a` and logs why;
- an explicit `fi_a2a` is rejected at argument resolution;
- a FlashInfer whose op still switches the backend fails at startup with a message naming the fix.

## Modifications

- **`fi_a2a` = the fused kernel, exclusively.** The MNNVL exchange + Triton merge path is removed.
- **Startup, before CUDA-graph capture** (`init_fi_a2a_workspace`):
  - creates two workspaces, one for graph capture and replay and one for eager calls, because a workspace serves one ordered
    CUDA stream;
  - sizes them for the widest decode CUDA-graph batch (`--cuda-graph-max-bs-decode`, times the tokens each request verifies
    under speculative decoding), also with `--disable-decode-cuda-graph`;
  - logs `DCP fi_a2a: fused all-to-all + LSE reduce ready (backend=..., capacity ..., 2 workspaces x ... MiB)` once.
- **Per call** (`fi_a2a_lse_reduce`, a registered custom op, so `torch.compile` sees one opaque collective):
  - views the `[B, H, D]` attention output as `[B, H/cp, cp, D]` and its LSE as `[B, H/cp, cp]` (no copy); head `h` goes to
    peer `h // (H/cp)`, exactly as the pack kernel sent it;
  - picks `lse_mode` from the attention backend;
  - runs eager batches wider than the workspace as several calls, in the same order on every DCP rank.
- **Resolution.**
  - `fi_a2a_platform_blocker`: Blackwell, the DCP group inside one NVLink domain (GB200/GB300 fabric or one node), and a
    FlashInfer that provides the op. It never imports FlashInfer.
  - `fi_a2a_blocker` adds an MLA model, no `--enable-pdmux`, and no PP DeepGEMM warmup stream at `--pp-size > 1`.
  - Unset resolves to `fi_a2a` only where it can run, else `a2a`, and logs the reason. An explicit `fi_a2a` names the blocker.
- **Docs.** `dcp.mdx`, `server_arguments.mdx`, the `--dcp-comm-backend` help, and the Kimi-K3 cookbook note.

## Accuracy Tests

- **New GPU test** `test/registered/kernels/ops/communication/test_dcp_fi_a2a_reduce.py`, at 2 / 4 / 8 × B200: 10 passed,
  0 skipped at each size. It checks:
  - equivalence with the all-gather + Triton merge, base-2 and base-e, at 16 heads × 3 tokens, 16 × 7 (several calls per
    batch) and 2 × 49;
  - FlashMLA's `[B, H, 1]` LSE;
  - CUDA-graph replays interleaved with eager calls;
  - a third CUDA stream is rejected before the collective;
  - custom all-reduce v2 stays exact around fused calls on the same symmetric memory.
- **2 × 4 GB300, the DCP group across two trays of one NVL72:** the test passes on all 8 ranks (9 passed; the all-reduce case
  is skipped because sglang does not build custom all-reduce v2 for that group). DeepSeek-V2-Lite TP 8 = DCP 8: GSM8K 0.640
  for both `fi_a2a` and `a2a`, and TPOT at concurrency 1 is 2.3% lower with `fi_a2a`.
- **GSM8K** (5-shot, 50 questions, `--parallel 1`) on every serving arm below: main 0.80 and this PR 0.76 in every run
  (2 of 50 questions; greedy decoding repeats exactly). The full question set is below.
- **Greedy canary:** four prompts give token-identical outputs on main and this PR: 8 of 8 cross-path run pairs.
- **Coverage of the narrow-graph and eager paths** (GSM8K, 1319 questions, `--parallel 32`):
  - `--cuda-graph-max-bs-decode 4`: this PR 0.772, main 0.766;
  - this PR without decode CUDA graphs (eager decode, several calls per batch): 0.767.

- **The three measurements agree.** Per decode step at batch 1:
  - the microbenchmark predicts −93 µs (L2 hot) to −141 µs (L2 flushed);

  both arms). `dcp.mdx` documents the size.
