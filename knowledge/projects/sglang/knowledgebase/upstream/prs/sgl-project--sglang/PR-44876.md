# [CI] base-b: Move server tests that pass on the 5090 to 1-gpu-small

[Upstream PR](https://github.com/sgl-project/sglang/pull/44876) · state: open · merged: False

## Original PR description

## Summary

First of a series that splits #41231 into reviewable PRs, one CI lane each. This one moves 54 base-b server-style test files (attention, cuda_graph, e2e, lora, openai_server, sessions, spec, vlm) from 1-gpu-large (H100) to 1-gpu-small (RTX 5090). Every change is the `runner_config` of one `register_cuda_ci` line, with `est_time` set to the measured 5090 duration where the estimate was more than 1.5x low.

Rule for a file to move: it passes on the 5090 (SM120, 32 GB) with the CI install and env, every test it skips on the 5090 also skips on H100, and where it launches a server, any architecture-dependent default it picks up (e.g. FA3 on H100 vs FlashInfer on SM120) is not what the test is about, or that H100 path stays covered by a test that remains on H100. No coverage is lost.

| base-b per-commit est_time | main | this PR |
|---|---|---|
| 1-gpu-large | 130 files / 169.5 min | 76 / 99.4 min |
| 1-gpu-small | 142 files / 190.1 min | 196 / 279.0 min |

Partitions are sized from est_time by `compute_partitions.py`, so no workflow change is needed.

## Validation

All 56 candidate files were rerun on the 1-gpu-5090 runners at `43b9b6852e` with `/rerun-test -c` ([run 39021157332](https://github.com/sgl-project/sglang/actions/runs/39021157332)) and compared with the same files on H100 in main's scheduled run:

- 55 passed with the same test and skip counts as on H100 (`test_trtllm_mha` skips 5 cases on both; the two rust_server files skip only their fixture base class).
- `test_gdn_replayssm_spec_fold` stays on 1-gpu-large: two bf16 cases (snapshot-baseline fold, long-chain bound) exceed the fp32 tolerance on SM120, in CI and locally; all 5 pass on H100.
- `test_modelopt_fp8` stays on 1-gpu-large: `ModelOptFp8LinearMethod` takes an SM120-only FP8 linear branch on the 5090, and no other test serves a ModelOpt FP8 checkpoint on Hopper.
- 18 of the server tests get FlashInfer (Triton for SWA, `triton_attn` for the vision tower) instead of FA3 on the 5090. They test the API, sessions, LoRA updates, multimodal transport, AWQ (Marlin, same kernel on both) or model support, not the attention kernel. For the two breakable-CUDA-graph files, FA3's breakable path stays covered on H100 by `attention/unittests/dense/test_fa3.py` (bcg runner-mode cases) and `test_bcg_with_speculative_decoding` (2-gpu-large).

## Follow-ups

base-b light tests, extra-a, the round-4 class splits, the jit-kernel unit / benchmark lanes and diffusion follow as separate PRs; #41231 tracks them.
