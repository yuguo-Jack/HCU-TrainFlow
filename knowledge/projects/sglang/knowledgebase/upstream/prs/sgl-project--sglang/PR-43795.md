# [HiCache] Register layer-first host pools as whole-layer ranges

## Motivation

HiCache pins its host KV buffers with `cudaHostRegister`. When registration-granularity support landed, only the `page_first` / `page_first_direct` layouts were given an explicit `registration_granularity_bytes`; the `layer_first` layout was left at `None`, so its host buffers were pinned with default fixed-size chunking that is not aligned to layer boundaries.

The coalesced host<->device direct-copy path assumes each layer occupies one contiguous, layer-aligned pinned range. With `layer_first` registered at arbitrary chunk boundaries, a single layer can be split across multiple registered ranges, breaking that assumption — and the failure path itself warns that a host buffer that is not correctly pinned can make "device transfers ... silently return stale data".

Separately, the register/unregister error paths coerced the CUDA return code with `int(...)` before passing it to `cudart.cudaGetErrorString(rc)`. That API expects the typed `cudaError_t`, so the coercion degraded diagnostics: a registration failure — or a rollback during unregister — reported a generic/incorrect error string instead of the real CUDA error, making such failures hard to triage.

This PR closes both gaps: register `layer_first` host pools (MHA, MHA-K-only, MLA KV, and the DSA indexer) in whole-layer, layer-aligned ranges so the direct-copy assumption holds, and preserve the typed CUDA error code so failures and rollback produce accurate, actionable messages. Non-`layer_first` layouts are unchanged, and both behaviors are locked in by unit tests.

## Modifications

This PR fixes two related defects in how HiCache pins host KV buffers via `cudaHostRegister`, specifically for `layer_first` host pools.

**1. Register `layer_first` host pools in whole-layer ranges** (`pool_host/mha.py`, `pool_host/mla.py`, `pool_host/dsa.py`)

Host pools with `layout == "layer_first"` passed `registration_granularity_bytes=None`, so `_cuda_host_register` fell back to default fixed-size chunking that is not aligned to layer boundaries. The coalesced direct-copy path assumes each layer sits in one contiguous, layer-aligned pinned range; default chunking can split a layer across registered ranges and break that assumption.

The `layer_first` branch now passes a whole-layer granularity:
- MHA KV (`MHATokenToKVPoolHost`), MHA K-only (`MHATokenToKOnlyPoolHost`), and MLA KV (`MLATokenToKVPoolHost`): `self.size * self.token_stride_size`.
- DSA indexer (`DSAIndexerPoolHost`): `indexer_page_num * indexer_page_stride_size * indexer_dtype.itemsize` (one whole indexer layer).

`page_first` / `page_first_direct` keep their existing `page_size * layout_dim` granularity and all other layouts keep `None`, so non-`layer_first` behavior is unchanged.

**2. Preserve the typed CUDA error code on the register/unregister error paths** (`pool_host/common.py`)
> Note: this is the same fix as the currently-open #38509. If #38509 merges first, this section (and its test) can be dropped from this PR.

`_cuda_host_register` and `_cuda_host_unregister_ranges` coerced the return code with `int(...)` up front and then passed that plain int to `cudart.cudaGetErrorString(rc)`. `cudaGetErrorString` needs the typed `cudaError_t` to return the real error string, so the coercion degraded both the failure diagnostic and the rollback warning. The typed `rc` is now kept; `int(rc)` is used only for the `!= 0` success check and the numeric field in the message, while `cudaGetErrorString(rc)` receives the typed enum.

**3. Unit tests** (`test/registered/unit/mem_cache/test_hicache_host_register.py`)

Migrated to `CustomTestCase` and registered for CPU CI. Added:
- `test_layer_first_kv_registration_keeps_coalesced_layers_intact` — every registered range starts on a layer boundary and spans whole layers (within the 1 GiB cap).
- `test_dsa_layer_first_registration_uses_whole_indexer_layer` — DSA indexer granularity equals one whole indexer layer.
- `test_cuda_error_type_is_preserved_for_diagnostics_and_rollback` — the raised error carries the typed CUDA error string and the rollback path unregisters the pinned ranges.

N/A — no effect on model outputs. The change only affects (a) the granularity passed to `cudaHostRegister` for `layer_first` host pools and (b) CUDA error-code handling in the register/unregister error paths. No kernel or model-forward code is touched and the stored KV contents are unchanged. Correctness of the new behavior is covered by the added unit tests.

## Speed Tests and Profiling

N/A — no hot-path impact. `registration_granularity_bytes` only influences how host buffers are pinned at pool initialization (a one-time setup cost), not the per-decode-step copy or attention path.
