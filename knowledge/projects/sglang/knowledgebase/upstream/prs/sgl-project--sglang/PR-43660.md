## Motivation

SGLang Diffusion has no native Stable Diffusion XL support; `stabilityai/stable-diffusion-xl-base-1.0` only runs through the generic `--backend diffusers` path. This PR adds a native SDXL text-to-image pipeline, validated on Intel Arc Pro B60 (XPU) and NVIDIA A100 (CUDA).

The implementation reuses existing SGLang components rather than adding a standalone UNet: the native SD UNet already used by Hunyuan3D, the CLIP encoders and CLIP handling from SD3, `AutoencoderKL` with the existing `StableDiffusionVAEConfig`, and the standard timestep / latent / denoising / decoding stages. No new pipeline stage is added.

## Modifications

- **Shared UNet** (`dits/stable_diffusion.py`): `StableDiffusionUNet2DConditionModel` gains a per-level transformer depth (`transformer_layers_per_block`, e.g. `[1, 2, 10]`) and the SDXL `text_time` add-embedding (pooled text embeds + size/crop ids). Defaults are unchanged, so Hunyuan3D's module tree and state dict are identical; its validation is untouched apart from an early return for the SDXL block layout.
- **SDXL denoiser** (`dits/stable_diffusion_xl.py`, new): a thin `CachableDiT` holding the shared UNet (same composition as `Hunyuan3DPaintUNet`). `_aliases = ["UNet2DConditionModel"]` maps the checkpoint's `unet/config.json` class to it; a `unet.` prefix rule maps Diffusers weight names.
- **Scheduler** (`scheduling_euler_discrete.py`, new): `EulerDiscreteScheduler` wrapper delegating to Diffusers, following the existing DPM-Solver wrapper.
- **Configs**: SDXL DiT, sampling, and pipeline configs. The pipeline config subclasses the SD3 config to reuse its CLIP tokenization and penultimate-layer features. It concatenates the two encoders' embeddings (768 + 1280 = 2048), takes the pooled output from `text_encoder_2`, builds `time_ids`, and zeroes negative embeddings for an empty negative prompt (Diffusers' `force_zeros_for_empty_prompt`).
- **Pipeline** (`pipelines/stable_diffusion_xl.py`, new): standard stages only, with the denoiser under the `unet` key.
- **Loader**: `TransformerLoader` accepts the `unet` component.
- **CI**: an XPU-only server case `sdxl_base_image_t2i` in `gpu_cases.py` (added to `ONE_GPU_XPU_CASE_IDS`) plus its `xpu_b60.json` perf baseline. It is registered only on XPU because no CUDA baseline or consistency GT exists for it; consistency and component-accuracy checks are off, with UNet parity covered by the unit test below.
- **Docs**: SDXL cookbook page (B60 and A100 recipes and benchmarks), supported-model catalog entry, sidebar entry, and a Stability AI card on the diffusion overview (logo from Stability AI's Hugging Face org avatar).

## Accuracy Tests

**Unit test** (CPU): a tiny SDXL-layout config with `text_time` and per-level depths `(1, 2, 3)`, run through the new denoiser's `forward`, matches Diffusers' `UNet2DConditionModel` at `rtol=atol=1e-5` with a strict state-dict load. The existing Hunyuan3D SD2.1 parity and paint tests still pass.

**End-to-end on XPU** (1x Arc Pro B60 and 1x A100): 1024x1024, 30 steps, guidance 7.5, seed 42, prompt "a beautiful sunset over the ocean, photorealistic". SGLang and the reference start from identical latents. The reference is Diffusers' `StableDiffusionXLPipeline` in full fp32; the VAE is fp32 in all runs.

| UNet | Text encoders | B60 PSNR / SSIM | A100 PSNR / SSIM |
|---|---|---|---|
| fp32 | fp32 | 51.14 dB / 0.9974 | 46.25 dB / 0.9928 |
| bf16 (default) | fp16 (default) | 37.92 dB / 0.9648 | 27.02 dB / 0.8571 |
| bf16 | fp32 | 37.53 dB / 0.9630 | 23.50 dB / 0.7842 |
| bf16 | bf16 | 36.10 dB / 0.9528 | 35.33 dB / 0.9523 |

- The fp32 rows show SGLang reproduces Diffusers on both platforms.
- The lower bf16 scores on the A100 are bf16 drift, not an SGLang difference: Diffusers' own bf16 UNet with fp32 text encoders scores **23.49 dB / 0.7843** against the same fp32 reference, matching SGLang's 23.50 dB / 0.7842. Re-running the A100 bf16 configs with `--allow-cudnn-tf32 false --allow-bf16-reduced-precision-reduction false` gave identical scores.
- With one prompt and seed, which bf16 configuration lands closest to fp32 varies, so the bf16 rows should not be ranked against each other.

## Speed Tests and Profiling

Single cold `sglang generate` requests at 1024x1024 with `--num-inference-steps 30 --guidance-scale 7.5 --seed 42` (fresh process per run, so end-to-end includes one-time costs), same workload as above:

| Config | B60 per step | B60 end-to-end | A100 per step | A100 end-to-end |
|---|---|---|---|---|
| fp32 UNet / fp32 text encoders | 1.623 s | 53.15 s | 0.377 s | 28.93 s |
| bf16 UNet / fp16 text encoders (default) | 0.157 s | 14.14 s | 0.145 s | 6.41 s |
| Diffusers fp32 reference | - | 50.96 s | - | 7.93 s |

Hardware/software: Intel Arc Pro B60 24GB, PyTorch 2.13 XPU, Diffusers 0.38.0; NVIDIA A100-SXM4-40GB, PyTorch 2.14.1 CUDA 13.0, Diffusers 0.37.0.

XPU CI case `sdxl_base_image_t2i` (50 steps, `SGLANG_DIFFUSION_SYNC_STAGE_PROFILING=1`, as for the existing XPU baselines, measured after one 1024x1024 server warmup request): 309.8 ms per step, 16.9 s end to end; it passes against the new baseline.

This PR is about functional support; performance work is planned as follow-ups:
- Attention calls `F.scaled_dot_product_attention` directly; routing it through SGLang's attention layer (XPU flash attention) and adding TP linears comes next.
- Cold single-request `sglang generate` runs (no warmup) report large VAE decode times in some configurations (about 6.5 s on the B60 with a bf16 UNet, 13.6 s on the A100 with an fp32 UNet). The XPU CI request decodes in 1.3 s, but it runs after a 1024x1024 server warmup request and with `SGLANG_DIFFUSION_SYNC_STAGE_PROFILING=1`, so the gap is likely one-time first-request cost, possibly plus unsynchronized GPU work attributed to decode. Steady-state, stage-synchronized measurement on both platforms will confirm whether any per-request decode cost remains.

Reproduce:

```bash
sglang generate --model-path stabilityai/stable-diffusion-xl-base-1.0 \
  --prompt "a beautiful sunset over the ocean, photorealistic" \
  --height 1024 --width 1024 --num-inference-steps 30 --guidance-scale 7.5 --seed 42 \
  --save-output
```

Notes for reviewers:
- On a cold HF cache the XPU CI case downloads 62 GB, because the default download filter only skips `*.onnx` / `*.msgpack` and the SDXL repo also ships OpenVINO exports, ONNX weight data, and single-file checkpoints. A per-model download filter is left for a follow-up.
- CUDA CI coverage is left for a follow-up: the case is XPU-only, and enabling it on CUDA needs an H100-measured `h100.json` entry (A100 numbers would not be comparable) plus a consistency GT image or `run_consistency_check=False`.
- Not in this PR: LoRA (the LoRA pipeline targets `transformer`), the refiner (`stabilityai/stable-diffusion-xl-refiner-1.0`), image-to-image with these weights (Diffusers' `StableDiffusionXLImg2ImgPipeline`), and multi-GPU parallelism.
