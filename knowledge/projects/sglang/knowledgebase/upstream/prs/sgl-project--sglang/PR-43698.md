# [diffusion] comfyui: apply ControlNet residuals in Flux integrated mode

[Upstream PR](https://github.com/sgl-project/sglang/pull/43698) · state: open · merged: False

## Original PR description

ComfyUI computes ControlNet residuals in its own process and passes them to the diffusion model as the `control` kwarg. `FluxAdapter` now rejects that kwarg, so Flux ControlNet workflows can't run in integrated mode. This applies the residuals instead.

The adapter validates them and sends them in `req.extra`. The Flux pipeline config turns them into two DiT kwargs, moves them to the worker device and compute dtype, and shards them with the latents under SP. `FluxTransformer2DModel` adds each residual to the image stream after its double or single block. With no residuals the only cost is one `is not None` check per block. Residuals change every step, so they are excluded from the session cache. Adapters that don't declare `control` in `applied_conditioning` still reject it.

I rebased onto the per-row batching, patch-size padding and the `control` rejection from #43495, so the residuals are sliced per row and checked against the padded sequence length.

Checked before the rebase against ComfyUI's Flux with the same weights on CPU: the output matched to 2.4e-7 with residuals that change the output by up to 1.66. The parity test passes again on the rebased code on a GPU; details are in the comments. Untested: SP > 1, `torch.compile`, and cache-dit wrapped blocks (those raise a clear error).

Full details of the GPU run, so it can be reproduced.

**Environment**
- Modal, 1x NVIDIA L4 (sm_89)
- Image: `nvidia/cuda:13.0.1-devel-ubuntu22.04`, Python 3.11
- `pip install 'sglang[diffusion]'` (0.5.21) for the dependencies, which brought in torch 2.13. This branch is cloned and put first on `PYTHONPATH`, so the PR code is what runs.
- ComfyUI master cloned to `/comfy` and added to `PYTHONPATH`, so the tests that need `comfy` run instead of skipping.

**Command** (from `python/`)
```
PYTHONPATH=/comfy:. python -m pytest \
  sglang/multimodal_gen/test/unit/test_comfyui_*.py \
  sglang/multimodal_gen/test/unit/test_ipc_cuda.py -q -rfs
```
Baseline: plain `sgl-project/sglang` main on the same image gives 117 passed, 1 skipped, 3 xfailed.

**Result on this branch:** 126 passed, 1 skipped, 3 xfailed. The one skip needs a tiny H3 checkpoint.

**What the GPU run found along the way**
1. `test_dit_residual_hook_matches_block_output_hooks` and `test_dit_matches_comfyui_with_control` failed with `Tensor match failed ... device=cpu` in `timestep_embedding.cuh`. On a CUDA machine `Timesteps` picks the CUDA kernel, which rejects the CPU tensors these tests use. They now set `visual_embedding._is_cuda = False` through a fixture.
2. The new CUDA test failed in fp32 inside `apply_rope_pos_ids_cos_sin_cache` ("failed to dispatch data type"). That kernel has no fp32 path, so the test is bf16 only.
3. After 1 and 2 the ComfyUI parity test runs and passes, and the bf16 CUDA test passes.

**Not covered:** SP > 1, `torch.compile`, and real Flux ControlNet weights end to end.
