# [Feat] tracing: Attribute prefix checkpoint CPU time to requests

[Upstream PR](https://github.com/sgl-project/sglang/pull/47450) · state: open · merged: False

## Original PR description

## Motivation

A request may spend CPU time publishing its prefix cache after prefill and before output is streamed. Backend insertion work and blocking waits inside `checkpoint()` are not described by a CUDA copy event's DMA duration. Existing request traces do not identify that call, so a post-prefill gap cannot be separated from cache maintenance using the request timeline alone.

## Modifications

- Add the level-1 `cache_checkpoint_cpu` stage through the existing `ReqTimeStatsBase` and request trace APIs.
- Instrument prefix checkpoint calls through the scheduler's `checkpoint_kv_cache` and `release_kv_cache` helpers, covering ongoing requests and final KV-row release. Direct backend calls outside these helpers are not included. Keep skipped insertions and the tracing-disabled path unchanged; do not change cache admission, copying, scheduling, fences or metrics.
- Attach the phase, requested token boundary and normal-return status to the request's span. Capture monotonic timestamps immediately around the backend call and emit a completed span afterwards, so span construction/export is outside the measured interval.
- Keep tracing failures from skipping a checkpoint or replacing the backend's exception. Preserve the request's existing position/error behavior.
- Document that this is CPU call time. It can include shared backend waits and is not a count of copied tokens, GPU DMA time, Host/Store recovery proof or a cache-on/off end-to-end latency estimate. No device event or synchronization is introduced.

This complements, rather than replaces, transfer metrics and the outcome/structured-log work in #36474. It does not introduce another tracing exporter or request-ID Prometheus labels.
