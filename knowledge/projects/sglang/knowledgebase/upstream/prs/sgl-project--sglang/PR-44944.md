# [Fix] [NVIDIA] modelopt: Allow ModelOpt FP8 dense models on Ampere via Marlin

[Upstream PR](https://github.com/sgl-project/sglang/pull/44944) · state: open · merged: False

## Original PR description

## Motivation

#31340 added an FP8 Marlin fallback to `ModelOptFp8LinearMethod` for SM80-SM88. But `ModelOptFp8Config.get_min_capability()` still returns 89. The loader checks it before building any layer, so ModelOpt FP8 checkpoints never reach the fallback on A100 / A40 / A6000:

```
$ python -m sglang.launch_server --model-path nvidia/Llama-3.1-8B-Instruct-FP8   # A40, sm_86
ValueError: The quantization method modelopt_fp8 is not supported for the current GPU. Minimum capability: 89. Current capability: 86.
```

## Modifications

- `ModelOptFp8Config.get_min_capability()`: 89 -> 80, matching `Fp8Config`.
- `ModelOptFp8MoEMethod`: raise a clear error on SM80-SM88. Marlin covers linear layers only, and no FP8 MoE backend supports these GPUs:
  - Triton can't compile FP8 (`fp8e4nv`) here.
  - FlashInfer CUTLASS has no SM8x build.

  Without this check, an FP8 MoE model such as `nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B-FP8` would crash during CUDA graph capture, about 9 minutes into startup. FP8 MoE on Ampere needs an FP8 Marlin MoE kernel, which is left for a follow-up.
- Docs: the compatibility table listed `modelopt_fp8` as SM90+. It now says SM80-SM88 via Marlin for dense models only, and native FP8 on SM89+.
- `test_modelopt_loader.py`: two regression tests.
  - One checks that ModelOpt FP8 loads on SM80/SM86 and is still rejected on SM75. Its SM80 and SM86 cases fail on `main`.
  - One checks that the FP8 MoE quant method raises on SM86. It fails without the new check.

## Accuracy Tests

1x A40, `sgl-eval run gsm8k --n-repeats 3 --temperature 0.6 --top-p 0.9 --max-tokens 4096` (full set, 3 repeats). The server was launched with default flags.

| Model | GSM8K |
|---|---|
| `unsloth/Llama-3.1-8B-Instruct` (BF16 reference) | 81.75% ± 0.90 |
| `nvidia/Llama-3.1-8B-Instruct-FP8`, main | fails to start |
| `nvidia/Llama-3.1-8B-Instruct-FP8`, this PR (Marlin + FP8 KV cache) | 81.65% ± 0.20 |

## Speed Tests and Profiling

1x A40, `bench_serving --dataset-name random-ids --random-input-len 1024 --random-output-len 256 --num-prompts 200 --max-concurrency 16`, server with `--disable-radix-cache`, median of 3 runs:

| | Output tok/s | Median TPOT | Median TTFT |
|---|---|---|---|
| BF16 | 351.7 | 34.6 ms | 2447 ms |
| ModelOpt FP8, this PR | 417.4 | 18.4 ms | 4874 ms |

Decode is 1.9x faster. Prefill is slower because Marlin is weight-only and dequantizes to BF16 for the matmul.
