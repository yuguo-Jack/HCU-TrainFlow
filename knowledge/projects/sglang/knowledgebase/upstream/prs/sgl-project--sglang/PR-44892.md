# [Fix] [H200] ci: Split GLM-5.3-Flash serving recipes into separate tests

[Upstream PR](https://github.com/sgl-project/sglang/pull/44892) · state: closed · merged: True

## Original PR description

## Motivation

The GLM-5.3-Flash H200 test runs High Throughput and Low Latency recipes in one process, sharing the default 1200-second per-file CI budget. In [this failure on #44220](https://github.com/sgl-project/sglang/actions/runs/38998797308/job/117297505340), High Throughput completed GSM8K with 97.12% accuracy, but the file timed out during the Low Latency evaluation.

## Modifications

Split the recipes into independently registered test files, each with an estimated duration of 1200 seconds. Each gets its own existing per-file timeout and can be partitioned separately. Move the unchanged server setup and cleanup into a shared helper. Preserve all model arguments, accuracy thresholds, speculative acceptance checks, and decode performance checks.

## Validation

- AST comparison confirms every original class, function, and constant is preserved exactly once.
- The CI collector discovers both executable CUDA tests in `extra-b-test-8-gpu-h200`; partitioning treats them independently.
- Python syntax, isort, Ruff lint, Ruff formatting, and whitespace checks pass. All commit-time pre-commit hooks pass.
- [H200 validation](https://github.com/sgl-project/sglang/actions/runs/39032680509/job/117396243462) passed on commit `66fcf904f261d2ece679de80c3fdb2d8b95b7ca6`, triggered with `/rerun-test` without adding CI labels. Both files finished below the ordinary suite's 1200-second per-file budget:

| Recipe | File wall time (including setup/cleanup) | GSM8K | Result |
| --- | ---: | ---: | --- |
| High Throughput | 569 s | 97.19% | Passed |
| Low Latency | 314 s | 97.12% | Passed |

The files ran sequentially in one rerun job (883 s total). The rerun workflow does not enforce the ordinary suite's per-file timeout, so the measured file wall times were checked explicitly. This is one successful run on an 8-H200 runner; it does not establish a worst-case cold-start bound.

## Accuracy Tests

Both recipes passed the unchanged full 1319-example GSM8K check and 0.96 accuracy threshold (results above).

## Speed Tests and Profiling

Low Latency passed `test_bs_1_speed` on its first attempt: acceptance length 4.478 > 4.0 and speed 343.75 token/s > 200. All three unittest methods across the two files passed.
