# [Perf] [Intel] kv-canary: Add an on-device XPU fallback for plan/verify/write

[Upstream PR](https://github.com/sgl-project/sglang/pull/48373) · state: open · merged: False

## Original PR description

## Motivation
Off CUDA, the kv-canary plan/verify/write ops run the Python references (`*_ref.py`), which loop per token on the host. On XPU, decode with the canary on drops to 2-3 tok/s and the kv_canary e2e tests time out.

## Modifications
- `kv_canary/_tensor_fallback.py` (new): on-device tensor versions of plan entries, verify and write, byte-equal to the references. Plan reuses the existing Triton offsets kernel. The write chain hash is sequential, so it is folded on the host from one bulk copy per launch.
- `plan/api.py`, `verify.py`, `write.py`: use it when `device.type == "xpu"`. CUDA keeps the JIT kernels and other devices keep the references.
- `test_tensor_fallback.py` (new, XPU CI): 120 seeded differential tests against the references (MHA/SWA, every real-KV hash mode, duplicate slots, in-launch seeds, ring overflow).

## Accuracy Tests
- `test_tensor_fallback`: 120/120 byte-equal on Intel Arc Pro B60.
- kv_canary e2e: 11/11 pass on B60. The perturbation tests still report their expected violations. They also need `--attention-backend intel_xpu`, which comes in #48374.

## Speed Tests and Profiling
Qwen3-0.6B, 8 requests, canary on, B60. Before: 2-3 tok/s. After: about 220 tok/s. The reference ops took about 99% of each decode step. This figure was measured on the pre-rebase branch.
