# [HiCache] Clamp the Mamba host pool to the available host memory budget instead of aborting startup

[Upstream PR](https://github.com/sgl-project/sglang/pull/44185) · state: closed · merged: False

## Original PR description

## Motivation

Hybrid Mamba models build their HiCache host pool by ratio (`--hicache-ratio`) or by an explicit `--hicache-size` split, and unlike the KV host pools they do not go through `auto_size_hicache` (#40135). When the computed pool does not fit the available host memory, `MambaPoolHost.__init__` aborts engine startup:

```
ValueError: Not enough host memory available. Requesting 168.02 GB but
only have 108.93 GB free. Please reduce the size of the hierarchical cache.
```

Attention-only models degrade gracefully via auto-size; hybrid models crash. In containers, the cgroup limit minus the weight load's page cache can leave less headroom than the requested pool.

## Modifications

- `MambaPoolHost` now clamps its pool to the available host-memory budget (page-aligned) and logs a warning, mirroring the graceful degradation auto-sized KV pools already get. It still raises when not even one page fits, with a clearer message.
- The clamped size is re-synced across PP stages via `sync_fixed_hicache_size` and booked against the shared host budget.
- New unit tests: clamp math (page alignment, sub-page budget), no-clamp when the pool fits, clamp-with-warning, raise only when not even one page fits, and booking against `host_memory_budget_scope`.

`mha.py` and `dsa.py` raise on the same condition; left as-is since those pools are covered by `auto_size_hicache`, but the same clamp may be worth applying for symmetry.
