# [CI] slash-command: Write the /run-cpu-ci result back to its reply comment

[Upstream PR](https://github.com/sgl-project/sglang/pull/47246) · state: closed · merged: True

## Original PR description

## Motivation

`/rerun-test` and `/rerun-group` edit their reply comment as the run progresses (⏳ → 🔄 → ✅/❌), so the PR conversation shows whether the tests passed. `/run-cpu-ci` (#45501) only posts a one-time `🚀 Running base-a-test-cpu …` comment and never updates it. Its run is a `workflow_dispatch` on `main`, so it doesn't appear in the PR's checks either. The only way to see the result is to open the run link (example: #47063).

## Modifications

- `slash_command_handler.py` (`handle_run_cpu_ci`): post the reply comment **before** dispatching, then pass `reply_comment_id` and `reply_marker` (`<!--rrt:0-->`) as dispatch inputs. Afterwards, edit that same comment to show the run link, with `⏳` and the marker at the end of the line. A dispatch failure is written into the same comment.
- `run-cpu-ci.yml`: add the two inputs and a `write-back-result` job (`needs: base-a-test-cpu`, `if: always()`). It runs the existing `update_rerun_test_status.py` to set ✅ when the stage succeeds and ❌ otherwise, mirroring `rerun-test.yml`.
- Security model unchanged: the workflow-level token stays read-only, so the stage running PR code still has no write access. Only the separate writeback job gets `issues`/`pull-requests: write`, and it checks out `main` (the dispatch ref), not the PR.
- Docs: one line each in `contribution_guide.mdx` and the `ci-workflow-guide` skill.

There's no 🔄 "runner picked up" beacon: adding it would mean editing `_pr-test-stage-cpu.yml`, which PR CI shares. The comment goes straight from ⏳ to ✅/❌. A run cancelled by a re-dispatch on the same SHA is marked ❌. The new dispatch has its own comment.

## Testing

- Mock run of `handle_run_cpu_ci` with run-URL lookup both succeeding and failing. Checked the dispatch inputs and the comment body, then fed that body through `update_rerun_test_status.main()` for both success and failure: the line flips to ✅/❌ and the marker becomes `<!--rrt:0:done-->`.
- `ruff format --check` (0.15.1) passes. The YAML parses (jobs `check-changes`, `base-a-test-cpu`, `write-back-result`).
- Not yet exercised end to end: the slash-command handler and `run-cpu-ci.yml` both run from `main`, so this takes effect only after merge. Verify with a `/run-cpu-ci` on any PR then.
