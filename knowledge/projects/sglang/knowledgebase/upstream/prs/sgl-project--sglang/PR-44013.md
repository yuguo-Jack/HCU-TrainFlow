# [AMD][DSV4.1][CP] Support interleave prefill CP with breakable CUDA graphs on ROCm

[Upstream PR](https://github.com/sgl-project/sglang/pull/44013) · state: open · merged: False

## Original PR description

## Motivation

This extends ROCm interleave prefill CP + breakable CUDA graphs (BCG) to DeepSeek-V4.1-Flash. On HIP, V4.1 uses the low-ratio (C1/C2) layout, and its breakable prefill graph path rejects attention CP.

**Stacked PR. Please review only the last commit.**
- Depends on #43465 (HIP prefill CP for DeepSeek-V4.1). It is cherry-picked here as `5d062ce956` and will be dropped once #43465 merges.
- Depends on #43819 (ROCm CP + BCG for DeepSeek-V4 / V4-Flash), commit `7d7e991957`.

## Modifications (last commit)

- `deepseek_v4_backend_hip_radix.py`
  - Allows attention CP in the low-ratio breakable prefill graph path.
  - On CP replays, builds the low-ratio write metadata from the live rows of the bucket-padded `out_cache_loc`.
- `deepseek_v4.py`
  - `_forward_low_ratio_sources_cp` uses the live logical token count. Under CP BCG, `total_seq_lens` is the capture bucket.
  - Engram hashing in the CP branch runs at an eager break under BCG, as in the non-CP BCG path.
- `layers/cp/bcg.py`: on HIP, CP BCG capture buckets start at `cp_size * 16`, the HIP minimum CP tokens per rank from #43465. This ensures every captured bucket is CP-active.
- Tests: `test_dsv4_prefill_cp_bcg.py` and `test_cp_strategy_unit.py` (38 passed; 14 of the new tests fail without this commit).

## Accuracy Tests

**Setup:**
- DeepSeek-V4.1-Flash, TP4 on MI355X, DSpark block 5
- Image: `lmsysorg/sglang-rocm:v0.5.21-rocm724-mi35x-20261011`
- GSM8K: 5-shot, 1319 questions, greedy

**Arms:**
- **BCG**: stock image, `--cuda-graph-backend-prefill breakable`
- **CP (#43465)**: `--enable-prefill-cp --cp-strategy interleave --cuda-graph-backend-prefill disabled`
- **CP + BCG (this PR)**: CP flags plus `--cuda-graph-backend-prefill breakable`

The CP arms need `--language-model-only`, because V4.1 vision does not support CP. The stock image rejects this flag, so the BCG arm runs without it. A control run of this branch, BCG with the flag, matches stock BCG within 1%.

| | BCG | CP (#43465) | CP + BCG (this PR) |
|---|---|---|---|
| GSM8K | 0.895 | 0.896 | 0.896 |
| DSpark accept length (GSM8K) | 3.39 | 3.40 | 3.40 |

## Speed Tests (preliminary)

Prefill TTFT p50 (ms), ISL as listed, OSL 1, measured with `bench_serving` random. This is preliminary data: InferenceX-recipe and client results (fixed-seq 1k/1k, 8k/1k) will be added.

| ISL | conc | BCG | CP (#43465) | **CP + BCG** | vs BCG | vs CP |
|---|---|---|---|---|---|---|
| 2048 | 1 | 68 | 88 | **62** | 1.10x | 1.42x |
| 2048 | 4 | 217 | 218 | **191** | 1.14x | 1.14x |
| 2048 | 16 | 760 | 612 | 609 | 1.25x | 1.00x |
| 8192 | 1 | 216 | 173 | 179 | 1.21x | 0.97x |
| 8192 | 4 | 752 | 583 | 596 | 1.26x | 0.98x |
| 8192 | 16 | 2867 | 2264 | 2276 | 1.26x | 0.99x |
| 32768 | 1 | 730 | 572 | 605 | 1.21x | 0.95x |
| 32768 | 4 | 2852 | 2222 | 2233 | 1.28x | 1.00x |
| 32768 | 16 | 11852 | 9274 | 9424 | 1.26x | 0.98x |

Serving 8k/1k: TTFT, TPOT and throughput are within ±5% across arms. Decode already uses graphs in all of them.

**Takeaways:**
- CP + BCG improves prefill TTFT over BCG at every point measured, by 1.10–1.28x.
- It is 1.14–1.42x faster than eager CP for small prefills.
- From ISL 8k up, it is within 2–5% of eager CP. The largest gap is ISL 32k / conc 1, which is under investigation with profiler traces.
