## Motivation

Flashinfer has deprecated and removed the API we currently use for `--moe-a2a-backend=flashinfer`: https://github.com/flashinfer-ai/flashinfer/pull/6621 https://github.com/flashinfer-ai/flashinfer/pull/6047
If we don't update it, it will become unusable the next time we update flashinfer.


## Modifications

Update the code to use the new `moe-ep` api instead. All changes outside of unit tests are contained to `python/sglang/srt/layers/moe/token_dispatcher/flashinfer.py` so there should be no side affects on other code paths.


## Accuracy Tests

GSM8K 
```
 python3 -m sglang.launch_server \
    --model-path nvidia/DeepSeek-R1-0528-FP4-V2 \
    --trust-remote-code \
    --tp 4 --ep 4 --attn-dp-size 4 \
    --moe-a2a-backend flashinfer \
    --moe-runner-backend flashinfer_trtllm_routed \
    --quantization modelopt_fp4 \
    --disable-flashinfer-autotune \
    --model-loader-extra-config '{"enable_multithread_load": true}' \
    --reasoning-parser deepseek-r1 \
    --host 127.0.0.1 --port 30000

 sgl-eval run gsm8k --base-url http://127.0.0.1:30000/v1 \
    --model nvidia/DeepSeek-R1-0528-FP4-V2 \
    --temperature 0.6 --top-p 0.95 --max-tokens 16384 --seed 0 --num-threads 128
```

Result without this PR: **94.92%**
Result with this PR: **95.30%**

- bobboli · comment · 2026-10-28T08:53:26Z · [source](https://github.com/sgl-project/sglang/pull/46885#issuecomment-6464741046)

Suggestion on naming: now that this dispatcher goes through `flashinfer.moe_ep`, `--moe-a2a-backend flashinfer` is ambiguous. `flashinfer.moe_ep` has several all-to-all backends (NVLink one-sided, NVLink two-sided, Cake, NCCL-EP and NIXL-EP), and SGLang already uses `flashinfer_megamoe` for the Mega mode. This dispatcher only uses `NVLinkOneSidedAlltoAll`.

Could we name it `flashinfer_nvlink_one_sided`, and keep `flashinfer` as a deprecated alias for compatibility? That matches vLLM's `--all2all-backend flashinfer_nvlink_one_sided` / `flashinfer_nvlink_two_sided`. It also leaves room to wire up another FlashInfer backend later without overloading `flashinfer`.

[by Claude Code] **Severity: style | Confidence: High**

**Issue**

This works with FlashInfer 0.7.2, which SGLang pins today. Heads-up for the next upgrade: FlashInfer main renamed this keyword to `runtime_max_tokens_per_rank` in flashinfer-ai/flashinfer#7099 and removed the old name. That change is not released yet. It will ship in the same release as flashinfer-ai/flashinfer#6047 and flashinfer-ai/flashinfer#6621, which remove `MoeAlltoAll`. On that release, `max_tokens_per_rank=` here raises `TypeError`, because `NVLinkOneSidedAlltoAll.dispatch()` has no `**kwargs`.

**Fix**

No change is needed for 0.7.2. When SGLang upgrades FlashInfer past 0.7.2, rename this keyword to `runtime_max_tokens_per_rank=` in that upgrade PR. The CPU test fakes take `**_kwargs`, so they will not catch this.
