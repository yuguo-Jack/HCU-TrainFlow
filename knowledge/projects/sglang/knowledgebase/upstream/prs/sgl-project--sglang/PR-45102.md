# [Feat] sgl-router: Add --pd-stream-after-prefill

[Upstream PR](https://github.com/sgl-project/sglang/pull/45102) · state: closed · merged: True

## Original PR description

## Motivation

We compared sgl-router with results measured through sgl-model-gateway in PD mode, and the two start a streamed response at different points:

- sgl-router returns decode's response as soon as decode answers.
- sgl-model-gateway polls both requests and returns decode's response only once the prefill request has completed (`pd_router.rs`); if prefill fails it returns prefill's error and drops decode.

Decode can generate tokens before the prefill request completes, and through sgl-model-gateway those tokens reach the client together with the first one. TTFT and ITL measured through the two routers therefore differ for the same engines. This flag lets sgl-router reproduce sgl-model-gateway's behavior for like-for-like comparisons.

## Modifications

`--pd-stream-after-prefill`, off by default (no change without it). Decode is still dispatched at once; its response is held until prefill completes. If prefill fails, its error is returned and blamed on the prefill worker, and decode is dropped.

## Speed Tests and Profiling

DeepSeek-V4-Pro, agentic coding traces, 192 concurrent sessions, flag on: on average 0.7 to 0.9 s of decode output per request arrived together with the first token, i.e. counted in TTFT instead of ITL.
