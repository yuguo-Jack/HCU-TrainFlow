## Motivation

<!-- Describe the purpose and goals of this pull request. -->

Padded eager prefill can fail with the `tilelang` and `triton` DSA sub-backends. Their sparse kernels return `[1, N, H, Dv]`, but attention padding restoration identifies token rows on dimension 0. The extra batch axis can prevent output padding from being restored, causing a subsequent TP reduce-scatter shape error.

## Modifications

<!-- Detail the changes made in this pull request. -->

- Remove the internal singleton batch axis at the `tilelang` and `triton` adapter exits, preserving token-first outputs across prefill and decode. Raw kernel interfaces and numerical computation remain unchanged.
- Extend the existing padding regression to cover both backends, including single-query and non-TP-aligned inputs.

## Accuracy Tests

<!-- If this pull request affects model outputs (e.g., changes to the kernel or model forward code), provide accuracy test results. -->

- CPU regressions: **12 passed**, with **17 subtests passed**. The four added subcases fail before the fix and pass afterward; the standard CI entry point also passes.
- `triton` standalone checks on H200, with BF16/FP8 KV and 1/34/36 queries: valid outputs are bitwise unchanged, padding rows are zero, and prefill CUDA Graph replay matches eager execution.
- GLM-5.3-Flash, TileLang, 4 × H200: GSM8K, **1,314 examples × 2 runs: 96.0%, 95.9%**. End-to-end validation includes #46225 to address an independent KDA/GDN padding issue; this DSA layout fix does not depend on that change.
