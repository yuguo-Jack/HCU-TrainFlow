# [Perf] [AMD] qwen3.5: Fuse activation quant into small-M FP8 block-scale GEMM on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/42229) · state: open · merged: False

## Original PR description

## Motivation

On MI355X, Qwen3.5-397B-A17B-FP8 decode at low concurrency runs two latency-bound kernels for each dense FP8 projection: AITER's 1x128 activation quant (about 4 µs) and the block-scale GEMM (about 9 µs). EAGLE with four draft tokens runs these projections at 4 to 32 tokens per rank for concurrency 1 to 8.

This PR fuses them into one HIP kernel for M ≤ 32 at the TP4 and TP8 shapes; larger inputs and other shapes keep the AITER path. With the InferenceX recipe, interactivity improves by 5 to 10% at TP8 and about 3% at TP4.

## Modifications

- New `python/sglang/kernels/ops/gemm/smallm_fp8_blockscale_gfx950/`: one HIP kernel that quantizes bf16 activations to fp8 in registers (1x128 groups, bit-exact with `aiter_per1x128_quant`) and runs the block-scale GEMM on the existing AITER-preshuffled weight and `weight_scale_inv`, so weight loading is untouched. It is built with `hipcc` on first use through the `smallm_moe_gfx950` helpers (#40204), with no build or wheel change.
- `SHAPES` covers the Qwen3.5-397B-A17B dense FP8 projections up to M = 32:

  | (N, K) | TP | Layer |
  |---|---|---|
  | (5120, 4096) | 4 | GDN `in_proj_qkvz` |
  | (4608, 4096) | 4 | attention `qkv_proj` |
  | (4096, 2048) | 4 | GDN `out_proj`, attention `o_proj` |
  | (2560, 4096) | 8 | GDN `in_proj_qkvz`, attention `qkv_proj` |
  | (4096, 1024) | 8 | GDN `out_proj`, attention `o_proj` |

- `fp8_utils.py`: `aiter_w8a8_block_fp8_linear` calls `try_smallm_fp8_bs_linear` on the gfx950 bpreshuffle path when the input is not pre-quantized and there is no bias (+8 lines). It returns `None`, and AITER runs, for any shape, M, dtype, or layout it does not support. `SGLANG_ROCM_SMALLM_FP8_BS=0` turns it off.
- Tests (MI35x suite): `test_smallm_fp8_blockscale_gfx950.py` matches AITER at M = 1 to 32 on all five shapes, checks the quant is bit-exact, covers the fallback cases (M = 33, fp16, unaligned rows, unshuffled weight, off switch), and checks graph replay against eager.

With `--enable-aiter-allreduce-fusion`, the fused all-reduce + RMSNorm already quantizes the input of `in_proj_qkvz` and `qkv_proj` to FP8, so those layers keep the AITER GEMM. The kernel runs on `out_proj` / `o_proj` in every layer, the first layer's `in_proj_qkvz`, and the MTP layer's `qkv_proj`. At TP8 those projections are a larger share of each decode step, so the gain is larger than at TP4. Each EAGLE verify pass sends 4 tokens per running request through every projection, so the kernel covers running batches of 8 or fewer. The kernel does not run in prefill.
