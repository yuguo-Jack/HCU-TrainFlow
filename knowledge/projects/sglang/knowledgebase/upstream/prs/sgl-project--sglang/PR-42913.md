# [Perf] Improve BF16 Qwen3-VL GEMMs, mixed attention and cache writes on Blackwell

[Upstream PR](https://github.com/sgl-project/sglang/pull/42913) · state: closed · merged: False

## Original PR description

## Independent PRs

The first three independent changes are split into draft PRs, each based directly on main:

- #43236 — small-batch BF16 SiLU launch tuning on SM103.
- #43237 — BF16 writes to native HND KV cache storage.
- #43238 — mixed-batch BF16 decode-tail routing.

These PRs do not depend on one another. This aggregate PR still contains their changes and the remaining work; the split PRs are the focused review units for those three changes.

## Motivation

Qwen3-VL-4B's small-batch BF16 projections and separate QK normalization/rotation kernels add decode overhead on Blackwell. Mixed prefill batches also send one-token decode tails through context attention. At concurrency 128 in the measured workload, that routing reduces throughput from 3765 to 3201 output tokens/s when mixed chunking is enabled.

## Modifications

- Tune the SM103 BF16 SiLU-and-multiply launch for hidden width 9728 and 1–128 tokens. Use 128 threads with four elements per thread through 32 tokens and eight thereafter, preserving precise arithmetic, BF16 rounding, PDL and existing fallbacks.

- Fuse the batch-one, batch-two, batch-four and batch-eight BF16 QKV GEMM epilogue with Q/K RMSNorm, multimodal RoPE and HND page-32 cache writes on SM103. Preserve the original GEMM BF16 round, norm/rotation rounding and PDL dependency behavior. The shared GEMM hook is optional; other shapes, execution modes and existing epilogues retain their paths.

- Autotune the batch-four and batch-eight BF16 vocabulary projections for the tied Qwen3-VL weight on SM103 at TP1. Use the public FlashInfer cuBLASLt API at startup, verify cached tactics before dispatch, retain existing fallbacks and preserve downstream logits processing. Readiness now includes the row count so existing M128 projections remain separate.

- Pack cached-prefix and fresh BF16 K/V for eligible SM103 prefill batches and run FA4 with a per-call CLC scheduler override. Reuse the existing pack kernel, retain TRT decode tails, bound scratch space to 128 MiB, and fall back for unsupported shapes, streams, graph capture and execution modes. Default FA4 scheduler behavior remains unchanged.

- Use the existing BF16 direct GEMM for the measured single-row gate/up projection on SM103 (M1/N19456/K2560). Guard shape, backend, dtype, layout and inference mode, preserve output buffers and fallbacks, and warm the kernel before graph capture.
- Autotune the M128 BF16 gate/up and down projections on SM103 through the public FlashInfer cuBLASLt API. Verify cached tactics before enabling dispatch, preserve BF16 input/output and caller-owned output buffers, and retain existing fallbacks.
- Add 13 measured BF16 split-K tactics: QKV, output and down projections at batches 1/2/4/8, plus the batch-16 down projection.
- Initialize the BF16 backend in `sglang.benchmark.one_batch`. This runner bypasses the scheduler's initialization; without these two lines it benchmarks a different GEMM path from serving.
- Route trailing one-token requests in ordinary BF16 causal prefill batches through decode attention, retaining context attention for the prefill prefix and preserving output-buffer reuse.
- Fuse BF16 QK RMSNorm and full-width NeoX multimodal RoPE for batches up to 128 tokens on Blackwell using the existing QK normalization warp kernel and an optional rotary/cache epilogue. Keep the original normalization path as the default; remove the separate standalone CUDA kernel and Python wrapper. Preserve the BF16 rounding between normalization and rotation and retain existing fallbacks for unsupported configurations.
- Fuse the existing QK normalization/rotation with BF16 HND cache writes during ordinary decode. Restrict this path to the tested page-32 TRT backend and plain cache pool; preserve physical-slot checks and cache-transfer synchronization.
- Support native HND strides in the fused cache writer. The existing opt-in HND layout uses it for BF16 CUDA writes; other dtypes and compiled execution retain their previous writer.

Weights, KV cache and attention queries remain BF16 in the evaluated configuration. Serving defaults and the default cache layout are unchanged. The optional deployment recipe is in #42914.
