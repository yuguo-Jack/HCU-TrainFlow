# [Fix] internlm: Fix quadratic regex scan in the tool-call parser

[Upstream PR](https://github.com/sgl-project/sglang/pull/42581) · state: open · merged: False

## Original PR description

## Motivation

`InternlmDetector.detect_and_parse` (`interns1`) finds tool calls with

```python
re.findall(rf"{re.escape(bot)}\s*(.*?){re.escape(eot)}", text, re.DOTALL)
```

When the end marker never arrives, each opening tag rescans to the end of the text, and `\s*(.*?)` retries the lazy scan from every split of a whitespace run:

| Input | Before | After |
|---|---|---|
| 224 KB of repeated `<|action_start|><|plugin|>` | 48.3 s | < 1 ms |
| one opening tag + 40,000 newlines | 12.0 s | < 1 ms |

Tool-call parsing runs synchronously on the tokenizer manager's event loop, so one such response stalls every in-flight request. Found with an Atheris fuzzing harness that records per-input parse time.

## Modifications

- `_iter_tool_call_bodies`: a linear `str.find` scan over complete blocks. Each body is already `.strip()`ed before `json.loads`, so dropping the regex's leading `\s*` changes nothing. The now-unused `import re` is removed.
- New `TestInternlmDetector` with a bug-regression test (there were no InternLM detector unit tests): 22.3 s on `main`, fast here.

## Accuracy Tests

- Differential test of `main` vs patched detector, comparing `detect_and_parse` and every streaming result under random re-chunking: **0 mismatches** over 20k random plus 20k mutated well-formed inputs (13k produced parsed calls).
- `test/registered/unit/function_call/`: 630 passed.
