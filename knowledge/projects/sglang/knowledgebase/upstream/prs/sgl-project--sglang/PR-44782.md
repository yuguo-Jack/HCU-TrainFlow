# [Fix] dumper: harden filter evaluation against scheduler RCE

[Upstream PR](https://github.com/sgl-project/sglang/pull/44782) · state: open · merged: False

## Original PR description

## Motivation

Fixes #44188.

`/dumper/configure` accepts a `filter` string that was evaluated with `eval()` while exposing `re.search` / `re.match`. Those function objects keep `__globals__`, so a client with an ordinary API key can import modules and run arbitrary Python in the scheduler process when `DUMPER_SERVER_PORT=reuse`.

A previous attempt at this fix was closed with the author's other open PRs; the `eval()` path is still on `main`.

## Changes

- Replace `eval()` with a restricted AST walker that only allows constants, names, comparisons, boolean/arithmetic ops, lists/tuples, subscripting, and calls to an allowlisted set of helpers (`search`, `match`, `len`, `abs`, `min`, `max`, `sum`, `any`, `all`).
- Block attribute access in filter expressions entirely, and wrap the regex helpers so attribute access cannot reach `__globals__` even if that restriction is relaxed later.
- Keep `SyntaxError` behavior for invalid expressions so existing tests stay green.
- Add regression tests for the known escape payloads from #44188.

Legitimate filters used in tests and docs (`layer_id == 0`, `'keep' in name`, `search(r'attn|mlp', name)`, etc.) continue to work.

## Test plan

- [x] Local assertions covering allowlisted expressions and the RCE payloads from #44188
- [ ] CI: `test/registered/debug_utils/test_dumper.py` filter cases
