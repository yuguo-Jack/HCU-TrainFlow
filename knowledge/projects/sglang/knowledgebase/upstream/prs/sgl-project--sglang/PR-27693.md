# [Bugfix] Keep dataset-specific benchmark result args accurate

[Upstream PR](https://github.com/sgl-project/sglang/pull/27693) · state: open · merged: False

## Original PR description

## Motivation

`bench_serving` result payloads were mixing in unrelated dataset defaults, which made saved benchmark metadata misleading. For example, `generated-shared-prefix` runs could still report `random_*` fields that were not part of the active workload shape.

This change aligns reported result args with the active `dataset_name` and hardens the helper for programmatic/manual namespaces where some fields may be absent.

## Modifications

- Add a dataset-specific result-arg selection path so benchmark output only includes args relevant to the active dataset.
- Expand dataset coverage so `sharegpt_output_len` is reported for `sharegpt`-like datasets (`sharegpt`, `custom`, `autobench`, `openai`, `longbench_v2`) and `random_output_len` is reported for `mmmu`.
- Include `generated-shared-prefix` distribution knobs (`gsp_group_distribution`, `gsp_zipf_alpha`) in result metadata.
- Make `_dataset_specific_args()` tolerant to partial/manual namespaces by using defensive attribute reads and returning `None` for missing dataset-relevant fields instead of raising `AttributeError`.
- Move dataset-to-result-arg metadata close to dataset declarations via `DATASET_RESULT_ARG_KEYS` in `python/sglang/benchmark/datasets/__init__.py`, while keeping rendering logic in `bench_serving`.
- Extend `TestDatasetSpecificResultArgs` with manual-namespace cases to verify defensive behavior and keep coverage for existing dataset branches.
