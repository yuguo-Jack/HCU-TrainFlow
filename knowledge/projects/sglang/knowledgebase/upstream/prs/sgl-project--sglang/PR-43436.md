# [Bug] PPLX MoE A2A padded tokens with topk_ids = -1

## Motivation

<!-- Describe the purpose and goals of this pull request. -->

pplx-kernels a2a is a symmetric collective, meaning every EP rank must dispatch the same number of tokens. Otherwise, the device-side handshake deadlocks (idle DP ranks with 0 tokens never signal their peers). We must therefore force MAX_LEN so all ranks are padded to equal token counts.

TopKRouter assigns `topk_ids = -1` for padded tokens. Unlike DeepEP, pplx-kernels has no skip for topk_ids = -1. When passing `topk_ids.to(torch.uint32)`, -1 becomes 2^32 - 1, leading to **CUDA illegal memory access**.

## Modifications

<!-- Detail the changes made in this pull request. -->

Pass the number of real tokens on each rank to `bound_m`. Now, only real tokens involve in a2a communication and MoE runner. Padded tokens never involve.
