Hi @Fridge003, thanks for the ROCm bring-up! A heads-up so this doesn't surprise you at rebase time: #45112 regroups `sglang.kernels` by operator, following the existing README rule that model-specific kernels live inside a logical group rather than in a model-named top-level group. As part of that, `python/sglang/kernels/ops/muse_spark/` was dissolved. The files this PR touches now live at:

| old `ops/muse_spark/…` | new |
|---|---|
| `fused_muse_spark_routing.py` | `ops/moe/muse_spark_routing.py` |
| `fused_norm_gate.py` | `ops/layernorm/muse_spark_norm_gate.py` |
| `fused_norm_residual.py` | `ops/layernorm/muse_spark_norm_residual.py` |
| `fused_op_tuning.py` | `ops/layernorm/_muse_spark_tuning.py` (configs under `ops/layernorm/configs/muse_spark/`) |
| `fused_qk_norm.py` | `ops/attention/muse_spark_qk_norm_rope_store.py` |

Things that changed beyond the paths:
- `FusedPostNormResidualPreNorm` now takes `post_norm_is_input_scale` and `use_residual_gate` instead of importing the srt layer classes. `forward_with_ag` is gone; the model calls `communication.muse_spark_all_gather_norm_residual(..., **op.jit_kernel_kwargs())` directly.
- `FinalizePushWorkspace` moved to `srt/layers/communication/muse_spark_finalize_workspace.py`.

Kernel code itself was moved byte-for-byte, so the behaviour your PR relies on is unchanged. One optional suggestion: the kernels under `srt/rocm_muse_spark/` (e.g. `triton_sum`, the fused norm/routing variants) could sit next to their CUDA versions as HIP backends of the same ops in `sglang.kernels.ops.<group>`, so both platforms share one entry point. Happy to help with the rebase if that's useful. Thanks!
