# [Perf] [AMD] GLM5: Row-streaming KDA packed decode on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/44659) · state: open · merged: False

## Original PR description

## Motivation

GLM-5.3-Flash's KDA layers use the safe gate (`lower_bound`), so on ROCm their decode skips the packed decode path. It runs `fused_sigmoid_gating_delta_rule_update`, which holds a `[BV, K]` FP32 state tile per program. The recurrent state update is bandwidth-bound on that FP32 state, and this kernel reaches only about 5 TB/s of in-place state traffic on MI355X at decode batch sizes.

This change adds a gfx950 Triton kernel that streams the FP32 state in row chunks per (request, head, row group), and routes GLM-5.3's safe-gate layers to the packed decode path on gfx950. CUDA already uses its own row-streaming kernel in this dispatcher; other HIP targets keep their current path.

## Modifications

- Add `kda_packed_decode_rowstream`, a gfx950 Triton row-streaming KDA decode kernel. It fuses QK L2 norm, the per-K gate with the optional safe-gate `lower_bound`, the sigmoid beta, the delta-rule state update, and the output. It uses one static launch configuration per decode batch bucket.
- In `fused_recurrent_kda_packed_decode`, dispatch to the row-streaming kernel when `covered()` holds: gfx950, `K=V=128`, BF16 packed qkv, contiguous FP32 `[slots, HV, V, K]` state, and contiguous output and indices. Everything else keeps the existing CUDA and Triton paths.
- Set `TritonKDAKernel.supports_packed_decode_safe_gate` on gfx950 only, so safe-gate layers reach the packed path there.
- Padded `-1` slots write zero output and leave the state pool untouched.
- Add a gfx950 suite comparing output and final state against `fused_sigmoid_gating_delta_rule_update`. It covers every batch bucket, TP4 and TP8 head counts, safe gate on and off, padded slots, untouched pool slots, and 16 consecutive decode steps.

## Accuracy Tests

Focused validation passed **3 gfx950 row-streaming tests (29 subtests)** and the KDA Triton unit suite (5 passed, 1 skipped). Coverage includes batch buckets 1-64, 16 and 8 heads, safe gate on and off, padded `-1` slots, untouched pool slots, state over 16 decode steps (atol/rtol `1e-5`), output (atol/rtol `2e-2`), and finite outputs. CUDA-graph replay is exercised by the CUDA-graph E2E runs below.

Full GLM-5.3-Flash MXFP4 TP4 GSM8K on snapshot `b5688f25491202978c19c4d036eef579f61bbe07`: 1,319 examples, 64 evaluator threads, 32,768 maximum output tokens, thinking enabled, temperature 1.0, top-p 0.95, sampling seed unset.
