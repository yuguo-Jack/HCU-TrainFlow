# [Refactor] rust-server: name the literal arguments on the tokenize/detokenize paths

[Upstream PR](https://github.com/sgl-project/sglang/pull/44829) · state: closed · merged: True

## Original PR description

Stacked on #44767 (base branch `oss-sync-f54680cc5b`); it should merge after that one. The diff shown here is only this follow-up.

## Motivation

The `/v1/tokenize` and `/v1/detokenize` routes added in #44767, and their tests, pass several bare `true`/`false`/`None` arguments whose meaning is only visible in the callee, for example `detokenize(token_ids, true)` or `load_chat_formatter(None, None, None, Some("chatml"))`. A reader has to open the callee to know what each literal selects.

## Modifications

Each such literal now carries an inline comment naming the parameter or binding it fills (`true /* add_special_tokens */`), using the callee's real parameter or binding name:

- the `/v1/completions` echo decode: `detokenize(token_ids, true /* skip_special_tokens */)`;
- the chat-template branch of `/v1/tokenize`: `false /* add_special_tokens */`;
- the `(decode_logprob_text, no_stop_trim)` tuple for tokenize, detokenize and control requests in `register_detok`;
- the `registered` flag in `push_tokenize_to_pool`'s `fail` call;
- in tests: the `CoreHandle::tokenize`/`detokenize` calls, `decode_once`/`handle_decode`, the tokenizer worker's `run(text, add_special_tokens)` helper, `load_chat_formatter(None, None, None, Some("chatml"))`, and the `test_mm(_, true /* enabled */)` call.

Literals that are already named (struct fields, well-named locals, assert expectations) and code #44767 does not add are left as they are. In multi-line argument lists rustfmt places the comma before the comment (`true, /* skip_special_tokens */`) and rewrapped a few calls. Comments only; no behavior change.
