## Motivation

DeepEP 2.5 (deepseek-ai/DeepEP#763) removes the V1 `Buffer` API and NVSHMEM, and replaces `ElasticBuffer` with `EPBuffer`, `EngramBuffer`, `PPBuffer`, and `BucketBuffer`. SGLang still needs V1 for the `deepep` backend, so it cannot replace the existing `sgl-deep-ep` package (V1 + DeepEP 2.1, built from `sgl-project/DeepEP@sgl-deepep`).

DeepEP 2.5 is instead packaged separately as `sgl-deep-ep-v25`, built from the new [`sgl-project/DeepEP@sgl-deepep-v25`](https://github.com/sgl-project/DeepEP/tree/sgl-deepep-v25) branch: upstream DeepEP 2.5, plus the manylinux `pidfd` fix and an `sgl_deep_ep_v25/` packaging directory. That wheel installs the Python package `deep_ep_v25`, and its host extension is compiled with the C++ `deep_ep` namespace renamed. As a result, `deep_ep` and `deep_ep_v25` can be installed in, and imported into, the same process. This PR adds the release pipeline for it; the `sgl-deep-ep` release is unchanged.

## Modifications

- `.github/workflows/release-whl-deepep-v25.yml`: a manual release workflow modeled on `release-whl-deepep.yml`.
  - Same Python (3.11/3.12/3.13) x architecture (x86_64/aarch64) matrix; it builds `sgl-deepep-v25` by default.
  - Builds with the CUDA 13.4 manylinux builder, because DeepEP 2.5 needs a CUDA 13.1+ toolkit to build and to JIT-compile kernels at runtime. PyTorch 2.14.1 comes from the cu130 index, matching the SGLang runtime; the extension needs only CUDA 13.
  - Uploads wheels to the `sgl-project/whl` release `sgl-deep-ep-v25-v<version>`. The prefix keeps them out of the `v0.1.x` releases that other packages share.
  - Updates the `cu134/sgl-deep-ep-v25` index.
  - Publishes to PyPI with a new `SGL_DEEP_EP_V25_PYPI_TOKEN` secret.
- `docker/sgl-deep-ep-v25.Dockerfile`:
  - Installs `nvidia-nccl-cu13==2.32.3` with `--no-deps`, because DeepEP 2.5 needs NCCL 2.32.3+ and PyTorch pins an older version.
  - Adds the elfutils headers, which DeepJIT includes. `libdw` is only `dlopen`ed at runtime, if it is present.
  - Drops the NVSHMEM and RDMA build dependencies.
- `scripts/build_sgl_deepep_v25.sh`:
  - Builds in that image and runs `auditwheel repair` without the NVSHMEM/gdrcopy excludes.
  - Writes PyPI wheels that drop the local CUDA version.
- `scripts/update_deepep_whl_index.py`: adds `--package` and `--release-tag-prefix`. The defaults keep the current `sgl-deep-ep` behavior.

SGLang runtime code is unchanged; this PR adds no dependency or import. Switching `deepep_v2` to `deep_ep_v25` will be a follow-up, after the first release.

## Speed Tests and Profiling

Not applicable. The package itself was validated with a wheel built from `sgl-deepep-v25` with the same packaging script, outside this workflow, on 4x GB300 (aarch64). The environment was CUDA 13.1 toolkit, PyTorch 2.14.1 cu130, and NCCL 2.32.3:

- `import deep_ep_v25` works, and the wheel contains only `deep_ep_v25`. With only nvcc 13.0 available, the import fails with a clear prerequisite error.
- `deep_ep` (`sgl-deep-ep`, DeepEP 2.1) and `deep_ep_v25` import into one process in either order, with distinct pybind11 types.
- `tests/ep/test_ep.py` on 4 GPUs, NVLink only (`EP_DISABLE_GIN=1`): all 36 correctness cases pass; dispatch/combine run at ~840 GB/s.
- RDMA was not validated. Gin setup failed on that host with an IB-level `IBV_WC_RETRY_EXC_ERR` before any DeepEP kernel ran.

Release tooling checks:

- Both `cuda13.4` builder images put GCC 13 on `PATH`. DeepJIT needs `<format>`, so this matters.
- The shell scripts, including the in-container script, pass `bash -n`, and the workflow YAML parses.
- `update_deepep_whl_index.py` produces the same `sgl-deep-ep` index as before. In a run with both packages' wheels, each index lists only its own package. `ruff`, `ruff format`, and `isort` are clean.
- The builder image and the workflow have not run end to end yet. The first dispatch should use an rc version.

Before the first release:

- Add the `SGL_DEEP_EP_V25_PYPI_TOKEN` repository secret. The `sgl-deep-ep-v25` name is still unregistered on PyPI, so the first upload needs an account-scoped token, or a pending trusted publisher with a matching workflow change.
