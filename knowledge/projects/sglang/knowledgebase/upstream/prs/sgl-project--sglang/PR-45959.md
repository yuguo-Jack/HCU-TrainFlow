# [Doc] developer_guide: Use sglang.benchmark.serving in the benchmark guides

[Upstream PR](https://github.com/sgl-project/sglang/pull/45959) · state: closed · merged: False

## Original PR description

## Motivation

`python -m sglang.bench_serving` has been a deprecated shim since #28997. The module itself says so:

```python
warnings.warn(
    "`sglang.bench_serving` is deprecated and will be removed in a future "
    "release; use `sglang.benchmark.serving` instead "
    "(e.g. `python -m sglang.benchmark.serving`).",
    FutureWarning,
    stacklevel=1,
)
```

and its docstring ends with "Update references to the new path". The developer guide and the production-metrics reference never got that update: every benchmark command on those pages still used the old path, so a reader following the docs got a `FutureWarning` on their first run.

## Modifications

- `docs/docs/developer_guide/bench_serving.mdx` — 22 commands
- `docs/docs/developer_guide/benchmark_and_profiling.mdx` — 11 commands + 1 heading
- `docs/docs/developer_guide/evaluating_new_models.mdx` — 2 commands
- `docs/docs/references/production_metrics.mdx` — 2 commands

`python[3] -m sglang.bench_serving` → `python[3] -m sglang.benchmark.serving`, and `sglang.bench_one_batch_server` → `sglang.benchmark.one_batch_server` (3 commands). One sentence on the benchmark page records that the old path still works but is deprecated.

No flag, default, or behavior changes. Page titles and slugs are unchanged, so no links move.

## Verification

- `python/sglang/benchmark/serving.py` and `python/sglang/benchmark/one_batch_server.py` both end with `if __name__ == "__main__": cli_main()`, so both new paths work as `-m` targets (checked on current `main`).
- `grep -rn "sglang\.bench_serving" docs/docs/developer_guide/ docs/docs/references/production_metrics.mdx` returns only the new deprecation note.

## Scope

`docs/docs/hardware-platforms/**` and `docs/cookbook/**` have ~370 more occurrences of the same string. I left them out of this PR to keep the diff reviewable — happy to send a mechanical follow-up if you would rather have them in one sweep.
