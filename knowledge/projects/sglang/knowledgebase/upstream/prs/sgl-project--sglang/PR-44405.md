## Motivation

DSpark / spec-v2 decode on HIP waits on the host every step to read the accept lengths. This removes that sync so the next step can be scheduled while the GPU is still busy. HIP only; other platforms are unchanged. Independent of the monokernel PRs that follow (part 1 of 4).

## Modifications

- Skip the per-step host read of the accept lengths in the overlap scheduler when no attention backend needs CPU sequence lengths (HIP only).
- Fold the simulated accept / bonus into the verify epilogue so it stays inside the graph (`SGLANG_DSPARK_SIMULATE_FOLD`, default on; HIP only, and only with `SGLANG_SIMULATE_ACC_LEN` set).

## Accuracy Tests

GSM8K 1319: DeepSeek-V4.1-Flash TP4 DSpark 0.906; DeepSeek-V4-Pro TP8 EAGLE 0.951 before / 0.948 after.

## Speed Tests and Profiling

DeepSeek-V4.1-Flash TP4 DSpark decode, c1 TPOT: -6.8% without the per-step sync, a further -1% to -3% with the fold.
DeepSeek-V4-Pro TP8 EAGLE, 8k TPOT c1 / c4: -0.8% / -1.2% (within run-to-run noise; no regression).
