# [Bugfix] Preserve both SWA KV pools on decode OOM

[Upstream PR](https://github.com/sgl-project/sglang/pull/42389) · state: closed · merged: False

## Original PR description

## Motivation

Paged SWA decode allocates from the full-attention and sliding-window pools sequentially. If either pool is exhausted, the other allocation can consume a page before the composite returns `None`, stranding unmapped KV capacity. Repeated rejected decodes can drain the healthy pool.

## Modifications

Check the exact decode page demand against both pools before either allocation. Preserve partial-page reuse and the full-only per-request ring path.

Add a CPU regression using real paged allocator bookkeeping and GPU regressions covering both exhaustion directions, retry after freeing a page, staged releases, and decoding with no free pages.

Related #30892 and #34400 change the individual paged allocator's kernel admission; this fixes the separate composite allocation leak.

## Accuracy Tests

The CPU regression fails on main in both exhaustion directions because the healthy pool's free-page list changes.
