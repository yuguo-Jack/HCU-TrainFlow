# Add SGLANG_TRTLLM_WORKSPACE_MB env for trtllm_mla workspace sizing

[Upstream PR](https://github.com/sgl-project/sglang/pull/43783) · state: open · merged: False

## Original PR description

## Motivation

The trtllm_mla backend allocates its workspace once at startup from a
hardcoded `DEFAULT_WORKSPACE_SIZE_MB = 150`. flashinfer's trtllm-gen
kernel carves the prefill softmax stats out of this workspace only when
LSE is requested, sized
`8 B (float2) x num_qo_heads x batch_size x round_up(max_q_len, 256) + 1 MB guard`
(see `trtllm_fmha_kernel_launcher.cu`). The demand therefore grows with
the prefill batch shape: a 64K-token chunked-prefill batch needs
**183,795,712 B (~175 MB)** and the scheduler process aborts with:

```
RuntimeError: flashinfer allocator.h:71 Buffer overflow
  allocating trtllm_gen_softmax_workspace with size 183795712
```

At the common 16K chunk size the demand is ~44 MB
(8 B x heads x small batch x round_up(16384, 256)), so the fixed size
never surfaced before. This affects any trtllm_mla deployment with a
large chunked-prefill-size — PD disaggregation is not required.

## Modifications

- **Register `SGLANG_TRTLLM_WORKSPACE_MB`** (environ.py, next to
  `SGLANG_FLASHINFER_WORKSPACE_SIZE`) and read it at allocation time;
  unset keeps the 150 MB default, so existing deployments are unchanged.
- **Document the variable** in `docs/references/environment_variables.mdx`
  with the sizing guidance.

The default intentionally stays at 150 MB: raising it for everyone would
add a few hundred MB of permanently-allocated memory per GPU for users
who never hit the ceiling, while large-chunk deployments get an explicit,
documented knob. Deployments running chunked-prefill-size >= 32768 should
set e.g. `SGLANG_TRTLLM_WORKSPACE_MB=512`.

Note on decode: recent main work lets decode also request LSE, but decode
demand stays tiny (max_q_len = 1 per request — a few KB per batch), so
the 150 MB default covers it with orders of magnitude of headroom.

## Accuracy Tests

The change only resizes a scratch buffer at startup; kernel inputs and
outputs are untouched. Production validation: full-model (93-layer
Kimi-K3) PD+DCP rounds at chunk 65536 (2x 30-min, c32, 2,436 requests, 0
errors, 0 transfer failures) ran with the workspace raised via this env
to 512 MB — the configuration that previously died on the first
64K-token batch — plus a 12-question gsm8k probe afterwards (acc=1.000,
invalid=0.000). The env plumbing was verified end to end: the variable is
registered in environ.py and the running server reports the configured
value.

## Speed Tests and Profiling

No runtime path added: the allocation happens once at startup. Decode and
small-prefill deployments keep the exact upstream behavior.
