# [Feat] sgl-router: Add an opt-in fips feature backed by aws-lc-rs

[Upstream PR](https://github.com/sgl-project/sglang/pull/48066) · state: open · merged: False

## Original PR description

## Motivation

Deployments under FIPS 140 requirements (for example FedRAMP High) need TLS performed by a FIPS-validated cryptographic module. sgl-router's TLS clients (reqwest for workers, kube-client for Kubernetes discovery) currently run on rustls with ring, which is not validated. This adds an opt-in `fips` cargo feature so those deployments can build the router with the aws-lc-rs FIPS module, without changing default builds.

## Modifications

- `Cargo.toml`: optional `aws-lc-rs` (`fips`) and `rustls` (`fips`) dependencies behind a new `fips` feature. Default builds compile neither.
- `src/main.rs`: under `cfg(feature = "fips")`, install `rustls::crypto::default_fips_provider()` as the process-wide provider at startup (reqwest and kube-client use the installed default) and refuse to start unless `aws_lc_rs::try_fips_mode()` succeeds and the provider reports FIPS.
- `src/tokenizer/adapter.rs`: in FIPS builds, refuse HuggingFace Hub tokenizer downloads with a clear error asking for `--tokenizer-path` (or `--no-tokenizer`). The hf-hub / tokenizer download path uses ureq 2 with a hardcoded ring provider that cannot be redirected to the FIPS module.
- `docker/sgl-router.Dockerfile`: `CARGO_FEATURES` build arg (the aws-lc-fips-sys toolchain — cmake, Go, clang — is installed only when `fips` is requested) and a `RUNTIME_BASE_IMAGE` build arg so the runtime base can be swapped for a FIPS-mode OS image.
- `README.md`: a "FIPS builds" section (how to build, what changes, the tokenizer restriction).
- `.github/workflows/pr-test-sgl-router.yml`: one `cargo clippy --features fips -- -D warnings` step in the tier-1 lint job, so the cfg-gated FIPS code is compiled on every router PR. aws-lc-fips-sys needs cmake, Go and clang, which the GitHub-hosted Ubuntu image already has; the step adds the FIPS module build to that job (a few minutes cold, cached by rust-cache afterwards). Happy to move it to a nightly job instead if you prefer.
- `deny.toml`: allow the `OpenSSL` license used by aws-lc-fips-sys (`deny.toml` checks all features).
- `Cargo.lock`: aws-lc entries.

ring remains in the dependency graph (kube-client and the ureq-based tokenizer download pull it in) but is not used for TLS in FIPS builds.

## Testing

- Default and FIPS builds: `cargo fmt --check`, `cargo check --all-targets`, `cargo check --features fips --all-targets`, clippy.
- `cargo test --test proxy`: 224/224 pass on both the default and the `fips` build.
- `tests/e2e/k8s_integration` (kind): 24/24 pass using a FIPS router image (discovery over the FIPS TLS client to the API server, lifecycle, reconciliation, shutdown drain).
- FIPS images (linux/amd64 and arm64) start with `FIPS mode: aws-lc-rs FIPS module is the rustls crypto provider` and refuse a HuggingFace repo id for the tokenizer with the new error.
- End to end on 8×B200: the FIPS router in front of SGLang engines (Inkling-Small-NVFP4 and a GLM-based model) — chat, streaming, tool calls, reasoning effort and concurrent load return the same responses as the engine directly.
- `cargo deny --all-features check`: licenses/bans/sources pass. advisories currently fail on `main` independently of this PR (RUSTSEC-2026-0433, `pulldown-cmark` 0.13.5, a build dependency of prost-build; fixed in 0.13.6).
