# [Spec] Fix NGRAM over-sampling token 0 from padded draft siblings

[Upstream PR](https://github.com/sgl-project/sglang/pull/43742) · state: open · merged: False

## Original PR description

## Motivation

Fixes #43725.

`fillResult` pads the NGRAM draft tree to `draft_token_num` with token-0 nodes whose parent is the root. When the corpus returns fewer than `draft_token_num - 1` candidates, the pads become duplicate root siblings. `TreeSpeculativeSamplingTargetOnly` adds `target_probs[0]` to `prob_acc` for each of them, but the residual removes it only once, so at temperature > 0 token 0 is accepted with probability up to `m * p(0)` for `m` pads.

## Modifications

- `ngram_corpus/result.cpp`: give pads no parent, so their mask rows keep only the self bit. `reconstruct_indices_from_tree_mask` (CUDA, CPU, Triton) and `_derive_tree_links` already leave a parentless node out of every child and sibling link, so verify never reaches the pads.
- `test_ngram_corpus.py`: update the golden masks for the pad rows.
- `test_ngram_utils.py`: add a request with parentless pad rows to the `reconstruct_indices_from_tree_mask` test.

The draft tree can now have parentless rows besides the root. EAGLE and DFlash build their trees without `fillResult` and are unaffected.

## Accuracy Tests

The repro from #43725 on one L4 (`lmsysorg/sglang:nightly-dev-20261012-e6072935`), 2000 requests per row. P(`!`, id 0) at output positions 1-6; the target model gives .0485 at every position.

| | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| no speculation | .0390 | .0505 | .0525 | .0450 | .0525 | .0580 |
| NGRAM, main | .0470 | .5305 | .2885 | .3710 | .2610 | .2625 |
| NGRAM, this PR | .0505 | .0455 | .0465 | .0495 | .0465 | .0555 |

- Mean accept length at temperature 1 drops from 1.79 to 1.39 here, since pads are no longer accepted. Greedy output on the same model is unchanged. On main, greedy could accept a pad when the target's top token is id 0; this PR doesn't, so acceptance can drop slightly in that case.
- `test/registered/unit/spec/test_ngram_corpus.py`: `42 passed`. On main, the updated goldens fail `TestNgramCorpusBFS::test_masks` and `TestNgramCorpusProb::test_masks`.
- `test/registered/kernels/ops/speculative/test_ngram_utils.py`: `1 passed`. With main's pad rows (root bit set), the new case fails on `retrive_next_sibling`.
