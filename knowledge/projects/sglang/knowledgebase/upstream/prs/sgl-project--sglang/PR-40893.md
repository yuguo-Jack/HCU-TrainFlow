# Support a reduced draft vocabulary in rejection sampling

[Upstream PR](https://github.com/sgl-project/sglang/pull/40893) · state: open · merged: False

## Original PR description

## Motivation

`--speculative-use-rejection-sampling` with EAGLE3 and a reduced draft vocabulary (e.g. `draft_vocab_size=32000`, `target_vocab_size=201216`) currently refuses to start:

```
ValueError: --speculative-use-rejection-sampling requires the draft and target to
share one vocab, but the draft vocab (32000) != target vocab (201216).
```

The FIXME at `eagle_worker_v2.py:328` says *"support reduced (hot) draft vocab by scattering draft probs into the target vocab via the d2t map before the sampling kernel"*. This PR implements exactly that.

### Why it matters for correctness

Without this, EAGLE3 with `--speculative-use-rejection-sampling` falls through to the official tree verifier (`rejected_probs=zeros`), which never consumes the actual draft distribution `q`. On a 201K-vocab model with a 32K hot-vocab EAGLE3 draft (TP=8, H800):

| Setting | Old path (`rejected_probs=zeros`) | New path (classic + scatter) | Delta |
|---|---|---|---|
| target T=1, draft T=1, mean accept length over 11 benchmarks | 2.841 | 3.583 | **+26.1%** |
| target greedy, draft T=1, mean accept length over 12 benchmarks | 4.535 | 3.509 | -22.6% (see note) |

Note on the -22.6%: it is expected, and it shows the old number was mislabeled. Under `rejected_probs=zeros` the draft is always argmax regardless of draft temperature, so "draft T=1" was really measuring greedy-greedy. The new path samples from `q` with the real temperature, and acceptance drops because a sampled token now has to match the greedy target. That is the correct behavior for this configuration.

A four-arm distributional test (two-sample G-test on token-frequency histograms, 10K samples per prompt, positions 2-4, 8 prompts, T=1/top_k=-1/top_p=1) confirms unbiasedness:

```
                     G/2N (nats/token)   relative to cross-launch floor
ref_a_vs_ref_b       1.429e-03           (within-arm floor)
ref_vs_ref2          2.059e-03           1.00  (cross-launch floor)
ref_vs_new           2.035e-03           0.99  <- indistinguishable from floor
ref_vs_old           2.494e-03           1.21  <- biased, pooled p = 3.2e-26
```

`ref2` is a second independent non-speculative launch. It is required as the baseline because this model is not batch-invariant (bs=1 vs bs=20 greedy decoding already diverges on 7/20 prompts), so a within-arm floor understates the noise and misattributes cross-process numerics to the verifier.

## Modifications

`spec_utils.py` - add `scatter_draft_probs_to_target_vocab()`:
- `index_copy_` the hot-vocab `q` into a target-vocab-width zero tensor. This is exact, not an approximation: the draft can only ever propose a hot token, so `q(x) = 0` off the hot set is the true proposal mass, and `relu(p - q)` keeps the full `p` there.
- Force fp32 so the eager and CUDA-graph paths hand the kernel the same dtype.
- No buffer reuse: the returned tensor outlives the call under overlap scheduling, so a cached buffer would alias across iterations.

`eagle_worker_v2.py`:
- Replace the FIXME `raise ValueError` with an info log.
- Add `_build_verify_draft_probs()`, which stacks the per-step `q` and scatters once at the kernel boundary rather than in each producer.
- Under `SGLANG_ENABLE_ASYNC_ASSERT`, assert `q > 0` at every proposed token. A misaligned or mis-scattered `q` reads back as `q == 0`, which makes the `coin * q < p` accept test vacuously true: accept length pins to `num_steps` while the text silently degrades. The gather is gated so it never runs in production.
- Initialize `draft_probs_list = None` outside the rejection-sampling branch, since the new call sites would otherwise raise `NameError` when rejection sampling is off.

`arg_groups/speculative_hook.py` - `_should_auto_enable_hip_rejection_sampling` carried the same FIXME in its docstring ("rejection sampling still cannot consume a reduced / hot draft vocab"). Updated to reflect that the scatter now exists. The conservative behavior is kept: ROCm still does not auto-enable rejection sampling for EAGLE3 or for an EAGLE run with a token map, because this path has not been validated on ROCm. Passing the flag explicitly works.

`docs/docs/advanced_features/speculative_decoding.mdx` - `--speculative-use-rejection-sampling` had no row in the speculative parameter table, only a passing mention under the UNO limitations. Added one, documenting the default, the `--speculative-eagle-topk 1` requirement, the EAGLE/EAGLE3-only restriction, the incompatibility with the accept thresholds and deterministic inference, and the new reduced-vocabulary support. All of it verified against `arg_groups/speculative_hook.py` rather than assumed.

`test/registered/unit/spec/test_draft_probs_reduced_vocab.py` - 7 unit tests: hot columns land on their target ids, non-hot mass is exactly zero, total mass preserved, output is fp32 for any input dtype, no buffer aliasing across calls, width satisfies the `eagle_utils` guard, and a 400K-sample Monte Carlo showing chain rejection sampling with a truncated `q` reproduces `p` (max deviation within 4 standard errors).

## Accuracy Tests

See the four-arm G-test table above. The classic chain verifier with scattered `q` sits on the cross-launch noise floor; the `rejected_probs=zeros` path is 21% above it with pooled p = 3.2e-26.

## Speed Tests and Profiling

Per-benchmark accept-length gain at target T=1 / draft T=1, same model and hardware as above:

| Benchmark | Accept delta |
|---|---|
| mt-bench | +40.2% |
| alpaca | +34.5% |
| arena-hard | +29.8% |
| aime25 | +28.9% |
| livecodebench | +28.0% |
| summarization | +28.0% |
| math500 | +27.3% |
| gsm8k | +27.1% |
| mbpp | +20.5% |
| humaneval | +16.4% |
| translation | +14.6% |

Gains correlate with task entropy: higher-entropy tasks benefit more from the `relu(p - q)` residual resampling that the classic verifier provides and the tree verifier does not.

The added work is a single `index_copy_` per verify step on a `(bs, num_steps, target_vocab)` tensor. This path was previously unreachable for reduced-vocab drafts, so there is no prior behavior to regress.

The accept-length and distributional numbers were measured on a fork of this branch carrying the ERNIE-5 model support, since that is where a 201K-vocab target with a 32K-hot-vocab EAGLE3 draft exists. The scatter code under review is identical.

**Additional motivation: upstream now reaches this error without the flag**

Since this PR branched, `--speculative-use-block-verification` landed, and `handle_speculative_decoding` auto-enables rejection sampling for the EAGLE family:

```python
if (
    cfg.speculative_algorithm in ("EAGLE", "EAGLE3")
    and not cfg.speculative_use_rejection_sampling
):
    declare_resolution(
        server_args,
        "handle_speculative_decoding",
        speculative_use_rejection_sampling=True,
    )
```

So an EAGLE3 draft with a reduced (hot) vocabulary -- e.g. `draft_vocab_size=32000` against `target_vocab_size=201216` -- now hits the `ValueError` this PR removes without the user ever passing `--speculative-use-rejection-sampling`: enabling block verification is enough. What used to be an opt-in limitation is now a hard failure on a supported flag combination.

**Rebased** onto current main and force-pushed. The only conflict was in `eagle_worker_v2.py`, against the new all-greedy `needs_draft_probs` skip. The resolution keeps that gate and changes `_build_verify_draft_probs` to return early when `draft_probs_list is None`, which now covers both "rejection sampling off" and "all-greedy batch verified by argmax" -- the guard this PR originally shipped would have called `torch.stack(None)` on an all-greedy batch. `ruff`, `ruff-format` and `isort` are clean, and the 7 unit tests in `test/registered/unit/spec/test_draft_probs_reduced_vocab.py` still pass.
