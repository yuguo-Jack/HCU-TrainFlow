# [Fix] [AMD] quark: Preserve W4A4 MXFP4 MoE storage across reloads

[Upstream PR](https://github.com/sgl-project/sglang/pull/46673) · state: open · merged: False

## Original PR description

## Motivation

When Quark W4A4 MXFP4 MoE weights are reloaded, for example by an RL weight update, postprocessing replaces the weight and scale buffers with new tensors. Captured graphs still point to the old buffers, so after the update, graph replay keeps reading the old weights.

## Modifications

Use the existing `copy_or_rebind_param` helper when writing back the shuffled weights and E8M0 scales, so a same-shaped reload keeps the buffers that the graphs read.

This covers the separated-layout path of `QuarkW4A4MXFp4MoE`. The gfx1250 branch, the GU-interleaved SiTU branch and `QuarkW4A8MXFp4MoE` still rebind these buffers and are left for follow-ups.

## Accuracy Tests

On MI350X with `rocm/sgl-dev:v0.5.22-rocm10-mi35x-20261018`: capture a graph, reload different weights, then compare graph replay with a freshly loaded layer. Before this change the two outputs differ; after it they match.
