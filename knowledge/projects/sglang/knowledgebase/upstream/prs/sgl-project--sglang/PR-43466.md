# [Fix] hicache: Preserve device coverage for admission-time prefetch recovery

[Upstream PR](https://github.com/sgl-project/sglang/pull/43466) · state: open · merged: False

## Original PR description

A buffer-mode L3 prefetch can become redundant when another request populates the device prefix, either when the L3 hit is committed or when a staged hit is released at admission. If that device prefix is evicted while the request waits, the loss check can still use the original, shorter lookup match and skip the L3 re-query, causing unnecessary recomputation.

This change preserves the device coverage used to discard the prefetch:

- At hit commit, `StoragePrefetchRetries.record_device_covered_len` records the device-covered prefix length per request. Before checking for device-hit loss, the scheduler pops it with `pop_device_covered_len` and raises `storage_prefetch_last_match_len` to at least that length.
- When releasing a device-covered staged hit, the pipeline raises `storage_prefetch_last_match_len` to at least the current joint device prefix length, so a later admission pass can detect its eviction.
- Cancellation and reset clear the recorded coverage. Recovery uses the existing bounded retry path; retry limits are unchanged.

The added lifecycle regression test covers both hit-commit and staged-admission paths, including an original lookup match of zero followed by device-prefix eviction. It verifies that the loss-detection boundary is retained and that cancel/reset remove pending coverage. This is unit coverage of boundary tracking, not an end-to-end L3 recovery test.

Misses after retry exhaustion and the TP cancellation-consensus issue in #43108 remain outside this change.
