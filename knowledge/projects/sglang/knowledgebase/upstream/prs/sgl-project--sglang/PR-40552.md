# [Perf] qwen3.8-flash: Improve HyperConnection performance on SM100

[Upstream PR](https://github.com/sgl-project/sglang/pull/40552) · state: open · merged: False

## Original PR description

## Motivation

Reduce HyperConnection (HC) kernel launches and intermediate memory traffic
in Qwen-3.8-Flash around attention/MLP, without changing the core computation.
Fuse Down and Inject, and reuse residual statistics across HC blocks instead of
materializing a normalized residual at each block.

This patch targets `main` and contains the HC optimization, its necessary
framework integration and registered regression tests. The previously merged
model support is not part of this patch.

## Modifications

- **Fuse Down + Inject.** Fold the learned RMS scale into shared packed weights.
  Small T uses the custom GEMM epilogue to emit Down/SiLU and FP32 alpha;
  large T uses branch-batched GEMM with aligned output padding, followed by
  fused branch reduction, normalization, SiLU and sigmoid.
- **Reuse cross-block RMS statistics.** Carry the raw residual and FP32 square
  sums in `HCSumState`. Down and Up/Mix reconstruct inverse RMS where needed.
  Apply fuses the residual update with square-sum accumulation; Up/Mix resets
  the next sum buffer, avoiding separate normalization and reset kernels in
  steady state. Initial or invalidated state still requires bootstrap statistics.
- **Tune the remaining kernels.** Use register-only alpha output, configuration-
  sized shared memory, finer Up tiles, warp-shuffle post-processing and
  vectorized Apply. Runtime branch stride avoids exact-T JIT specialization;
  global address products use wide indexing.
- **Integrate with the framework and loaders.** Preserve the Tensor ABI for
  non-opted-in callers. The opted-in model carries `HCSumState` between blocks;
  packed HC uses a context object between `mix` and `combine`. Both token paths
  share GPU-native packed Down+Inject and RMS parameter storage, without
  canonical CPU copies or an additional original GPU copy. Original checkpoint
  inputs remain supported through loader mappings; native `state_dict`/export
  uses the packed representation. Retained hooks prepare/rebind HC execution
  views and validate grouped updates. CPU-specific NCCL/IPC/RDMA adaptations
  and the unrelated generic weight-cache transport/daemon changes are removed.

The dispatch boundary remains `T=24`. The optimized BF16/FP16 route validates
device/layout constraints and uses `C=4`; hidden size remains shape-derived.
Attention/MLP is not bypassed in production. Down and Inject may arrive in
separate buckets within an update session; preparation is deferred until
finalization. RMS changes require matching Down/Inject, or matching folded
Down+Inject for native updates. Incomplete groups remain dirty and cannot run.
Outside a session, each `load_state_dict` call must satisfy the HC dependencies
of the weights it updates. Ordinary in-place updates preserve captured HC buffers.
Updates must remain serialized with inference. Replacing parameter storage or
changing device/dtype requires CUDA Graph recapture.

This is tolerance-validated, not bitwise-equivalent to the original: statistics
use the FP32 residual update before its BF16/FP16 store, and folding RMS weights
changes rounding. Final alpha and carried statistics remain FP32; large-T
logits retain their activation-dtype rounding before the nonlinear operations.

### Deterministic-mode scope

With `--enable-deterministic-inference`, Apply writes per-warp partial sums and
uses a separate fixed-order reduction instead of FP32 atomics. Large-T Down uses
the framework's deterministic BMM with caller-owned FP32 output. The default
mode retains the atomic fast path without the additional reduction kernel.

Fixed-T repeatability is covered by tests. The existing T-dependent GEMM and
rounding paths are not unified here; full cross-batch or whole-model determinism
is not claimed.

## Accuracy Tests

At `9c19f9e8e1`, the registered HC GPU suite on GB300 and focused framework
regressions passed. They cover BF16/FP16 HC math, shared storage, state handoff,
grouped weight loading, same-storage CUDA Graph replay and mapped-HC IPC restoration.
The mapped-loader test is not a full daemon or multi-client transport test.

### Historical model and module validation

The following results compare HC commit `40d1499abe` with unmodified `main` at
`630b1ef322`. These are historical results, not a new full-model evaluation of
`9c19f9e8e1`. The performance tables below retain their original measurement
revisions and have not been re-measured at `9c19f9e8e1`.

- HC module validation: 32 BF16/FP16 numerical cases and 160
  changed-input CUDA Graph replays per implementation, including the 24/25 and
  32/33 boundaries and alternative shapes. Maximum relative-RMS drift versus
  unmodified main was 0.002847 for BF16 and 0.000357 for FP16, below unchanged
  limits of 0.008 and 0.0015.
- Full-model GSM8K: unmodified main **1283/1319 (97.2707%)**, optimized
  **1282/1319 (97.1948%)**, a difference of one question (-0.0758 percentage
  points). Both had zero request errors and zero truncations. Paired results:
  1279 both correct, 4 baseline-only correct, 3 optimized-only correct, 33 both
  incorrect. This single run is not a statistical non-inferiority proof.

GSM8K used the same model checkpoint and complete dataset on four GB300 GPUs,
BF16, TP4/EP2, temperature 0, top-p 0.95, no-thinking, maximum 10240 generated
tokens and concurrency 32. Speculative decoding and service CUDA Graphs were
disabled; both runs used the same QSA Torch / vendored FA4 backend selection.
This does not validate the default backend combination.

Registered regressions are included in this PR; standalone benchmark and
full-model evaluation harnesses are separate. Full-service Graph/NEXTN testing
below covers simulated-acceptance performance, not accuracy under natural
speculative decoding. Current targeted regressions do not establish cross-node
RDMA or the full daemon/multi-client lifecycle. Earlier process-level IPC testing
reported an exit-time reference-count warning; no new full-daemon validation is
claimed here.

### Why the end-to-end gain is about 2%, rather than the HC-only gain

A separate concurrency-1 Nsight Systems capture confirmed the optimized HC
path on both TP ranks. HC, including its generically named Down/Up GEMMs,
accounts for approximately **16% of baseline summed decode kernel duration**;
this is not a serial wall-clock fraction. MoE, attention, other projections,
communication and framework overhead are outside this PR's optimization scope.

The baseline Gate also uses programmatic dependent launch (PDL): it can start
before the preceding AllReduce completes and then wait for its dependency.
About **63–65% of its recorded duration overlaps that AllReduce** in this trace,
so removing the Gate does not remove an equal amount of critical-path time.
The observed interval from AllReduce completion to Apply completion decreases
from approximately **2.92 to 1.67 µs**, rather than saving the whole roughly
4.5 µs Gate interval. The overlap is not an instruction-level wait measurement.
These observations explain why HC-only improvements translate into a smaller,
but measurable, full-model gain; they are not an exact E2E cost decomposition.

The single-request node traces are diagnostic only, separate from both the NCU
table and the unprofiled HTTP results. Both had shutdown flush warnings, but
every decode Graph kernel node was verified across all 284 replays on both
TP ranks. They are not used to derive the reported E2E speedups.
