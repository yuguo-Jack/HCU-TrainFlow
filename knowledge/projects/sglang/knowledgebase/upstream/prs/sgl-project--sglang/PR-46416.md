# [Doc] tool-parser: Document every registered tool-call parser and test the table

[Upstream PR](https://github.com/sgl-project/sglang/pull/46416) · state: open · merged: False

## Original PR description

## Motivation

The "Currently supported parsers" table in `docs/docs/advanced_features/tool_parser.mdx` listed 14 names, while `TOOL_CALL_PARSER_NAMES` (the `--tool-call-parser` choices) registers 43. Thirty registered parsers had no row, including `deepseekv4`, `glm47`, `gemma4`, `kimi_k3`, `minimax-m2` and `hermes`.

One listed name, `llama4`, is not registered, so a user who copies it gets an argparse error. Llama 4 uses `pythonic`, which the table already lists. #10151 and #35790 removed that row before, but both were closed unmerged, and nothing stops the table from drifting again.

The "How to support a new model?" section also pointed at `TOOLS_TAG_LIST`, `MultiFormatParser` and `sglang/srt/function_call_parser.py`, none of which exist now.

## Modifications

- `tool_parser.mdx`
  - Add rows for the 30 undocumented parsers. Each example model id comes from the repo's cookbook pages, cookbook configs or tests. Format notes come from the detector docstrings. Where neither exists (for example `cohere_command4`, `spark25`, `nanbeige`), the row names the model family only.
  - List the deprecated aliases `glm45` and `qwen25` in the `glm` and `qwen` rows (`serving_hook.py` maps them).
  - Drop the `llama4` row. The `pythonic` row now carries the Llama 4 example and says there is no separate `llama4` parser.
  - Add one line above the table about `--tool-call-parser auto`.
  - Rewrite "How to support a new model?" for the current layout: detector file, `ToolCallParserEnum`, `TOOL_CALL_PARSER_NAMES`, a table row, unit tests.
- New `test/registered/unit/function_call/test_tool_parser_docs_coverage.py`, modeled on `unit/server_args/test_server_args_docs_coverage.py`. It reads the table and checks three things: every row has 3 cells; every registered name appears in a row's first cell (aliases may share a row); every name in a first cell is registered. It imports only the dependency-free `parser_names` module, not the detectors. `register_cpu_ci(est_time=5, suite="base-a-test-cpu")`.
- `_pr-test-check-changes.yml`: add `tool_parser.mdx` to the `server_args_docs` path filter, so a docs-only edit runs the CPU stage. This is the same mechanism `server_arguments.mdx` uses. I reused the key instead of renaming it; happy to rename it (for example to `docs_coverage`) if you prefer.

The test is a separate file, not part of `test_function_call_parser.py`, because it needs none of that file's xgrammar and tokenizer imports. If you would rather fold it in next to the existing `TOOL_CALL_PARSER_NAMES` check, I can move it.
