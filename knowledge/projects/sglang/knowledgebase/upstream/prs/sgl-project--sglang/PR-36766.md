# Support SM100 and SM103 TP8 FlashInfer sequence parallelism for Llama 3.1 70B

[Upstream PR](https://github.com/sgl-project/sglang/pull/36766) · state: open · merged: False

## Original PR description

**Status note (2026-10-08 13:25Z):** the greedy-parity gate below is failed by legitimate native configurations as well (NCCL vs custom all-reduce, TP4 vs TP8); the routed kernel is bitwise identical to all-gather + matmul in-server on every call, and the remaining deviation is the sequence-parallel decomposition. Root cause, calibration bands and a replacement gate proposal: https://github.com/sgl-project/sglang/pull/36766#issuecomment-6060889128. The September parity receipts referenced in this description are retained only as hashes and are not replayable.

This PR adds an opt-in true sequence-parallel route for unquantized BF16 Llama-3.1-70B-Instruct through FlashInfer's public `prepare_all_gather_matmul` API. `--enable-flashinfer-agmm-true-sp` supports TP8 on SM100/B200 and SM103/B300, and retains TP4 on SM103. Prepared packed-QKV launchers are cached per model weight and local row count. Decode and other row counts use the native Llama route.

The supported configuration is PP1/DP1/CP1 with exactly 4096 total extend rows (512 local rows at TP8,1024 at TP4). It uses FlashInfer attention, `--disable-cuda-graph`, `--disable-overlap-schedule`, `--disable-radix-cache`, `--chunked-prefill-size 4096`, and `--max-running-requests 1`. Serving adds no explicit device synchronization. The implementation and focused coverage are in the Llama adapter, its model integration, parallel CLI fields and `test/registered/unit/models/test_llama_flashinfer_agmm.py`.

The compatible dependency change is [flashinfer-ai/flashinfer#5116](https://github.com/flashinfer-ai/flashinfer/pull/5116). End-to-end throughput is reported for every measurement; it has no minimum speedup requirement. True-SP routing, native isolation and synchronization settings are acceptance gates. Correctness is gated by the calibrated gate **G0–G5** defined in the section *Correctness acceptance gate (revised 2026-10-08)* below; the September token-identity gate quoted in the sealed results further down is the historical gate of those runs and no longer the acceptance gate for this head; where the published-candidate paragraph and the sealed sections below say correctness was verified or PASS, that is the September gate on its own request set (section 3 of the [linked comment](https://github.com/sgl-project/sglang/pull/36766#issuecomment-6060889128)).

**Published integration candidate:** `827dbfbf2883c1ab507b2309d0824d94f5ae57e1` is the published PR head. Its real-model true-SP TP8 exact routes, native isolation and synchronization settings were verified on both SM100/B200 and SM103/B300 with the official FlashInfer wheel below, and it passed the September token-identity gate 96/96 on both architectures (the historical gate of those runs; the acceptance gate for this head is G0–G5 below, measured so far only on the current head). That September request set and scoring harness survive only as the hashes recorded below — the pipeline's data roots are gone — so the 96/96 cannot be replayed and stays unreproduced on this head and on 827dbfbf ([comment](https://github.com/sgl-project/sglang/pull/36766#issuecomment-6060889128), section 3). The B300 final result was sealed after a separate CPU timestamp-parser recovery. The SG6dc results below remain evidence for their original identities as recorded.

**Status on the current head (2026-10-08, aa1ffc762c = 827dbfbf merged with `main` at 0b635266 plus the follow-up fixes):** the route's accept/fallback routing (every 4096-row extend routed, every decode batch native, by a harness-side per-forward counter) is re-verified end to end on 8 × B200 and 8 × B300 (TP8) and 4 × B300 (TP4) with FlashInfer `main` b5e50c20, and the flag lowers median TTFT by 3-5 % (TP8) and 2 % (TP4) against native, a quantity the runs below did not report (the per-rank binding count, the native-isolation artifact check and the synchronization settings were not re-collected on this head). The September token-identity gate, however, is **not met** on this head: 19/32 (B200), 22/32 (B300) and 24/32 (B300 TP4) greedy sequences match native, with a maximum chosen-token logprob delta of 0.12-0.13 over the identical prefixes (0.05 required; the gate's all-position maximum, which includes post-divergence tokens, is 6.5), while the native arms remain exactly reproducible (32/32, delta 0). The FlashInfer revision plays no part in this: the flagged output is token-for-token identical at f0378145, f2794d589 and b5e50c20, and native output is identical across both heads and across f0378145 and b5e50c20. On the published head 827dbfbf itself (FlashInfer f0378145, this harness and prompt set) the gate is not met either: against a native server running the same all-reduce (under the NVSHMEM backend, where that head's custom all-reduce fails to set up, both servers fell back to NCCL), 18/32 sequences are identical, with a maximum prefix delta of 0.20 (6.5 over all positions), while the all-reduce implementation alone moves native output by 9/32 sequences and 0.13. So the difference to the 96/96 below lies between the description's parity workload and harness and this one, not in the merge with `main`, the follow-up fixes or the FlashInfer revision. The SG827 results below describe the published candidate 827dbfbf with the official FlashInfer f0378145 wheel; the SG6dc (6dc8c944) and historical (9c2f2fcb, FlashInfer a059801b) results describe the earlier revisions they name; all remain as recorded, and were measured with a request set and harness that are not part of this PR. The flag stays opt-in and off by default; I am not asking for a merge on this evidence. Details, tables and the published-head runs: [TP8 results on this head](https://github.com/sgl-project/sglang/pull/36766#issuecomment-6053083031) and [TP4, FlashInfer-revision and published-head runs](https://github.com/sgl-project/sglang/pull/36766#issuecomment-6053083370).

**Correctness acceptance gate (revised 2026-10-08)**

Why the gate changed: the September gate (identical greedy token ids on 32 random-id prompts plus identical-prefix max |Δlogprob| ≤ 0.05) is failed on this head by legitimate native configurations exactly as it is failed by the route — a native server with the NCCL all-reduce (`--disable-custom-all-reduce`) matches the native reference on 18/32 (B200) and 23/32 (B300) sequences, native TP4 on 23/32, native B300 vs native B200 on 21/32, all with identical-prefix maxima of 0.10–0.29 — so it has no threshold that a legitimate native variant passes while a defect would still be caught. The FlashInfer all-gather-matmul kernel itself is bitwise exact: an in-server compare of every routed packed-QKV call against `all_gather_into_tensor` + `torch.matmul` shows 0 differing elements (B200 TP8 and B300 TP8: 8 ranks × 80 layers, 1.07·10¹¹ / 1.34·10¹¹ elements per rank; B300 TP4: 4 ranks, 1.34·10¹¹ per rank). The route's deviation from native is the reduction order of the sequence-parallel decomposition. Full data and method: [comment](https://github.com/sgl-project/sglang/pull/36766#issuecomment-6060889128).

The gate is teacher-forced over two pre-registered request sets — (R) random-id prompts, (T) real text — plus (P) repetitive text, a control added after the data (almost every position near-certain), and two regions (the routed 4096-row chunk; the native continuation), against mandatory native-vs-native calibration bands on the same head: in the continuation region, native with NCCL all-reduce vs the native reference (the pre-registered band); in the chunk region, native TP4 vs native TP8, substituted after the data because the pre-registered NCCL band is identically zero there (both native servers already reduce the 64 MiB prefill through NCCL). On B200 the TP4 arm ran in the same run as the route; on B300 the TP4-vs-TP8 band is a between-run comparison on the same node and is bitwise identical to the B200 band. The criteria:

* **G0 harness sanity** — a second native launch reproduces the native reference exactly (32/32 sequences, |Δ| = 0 on every set); route counters show every 4096-row extend routed and every decode batch native.
* **G1 scale** — route mean |Δlogprob| of the reference-chosen token ≤ 2 × the band's mean and ≤ 0.05, per set and region.
* **G2 argmax stability** — route top-1 flip rate ≤ 2 × band and ≤ 5 %.
* **G3 tail** — route p99 |Δ| ≤ 2 × band and ≤ 0.3.
* **G4 defect detector** — max |Δ| at near-certain tokens (reference logprob > −0.1) ≤ 0.5 and max top-20 KL ≤ 1.0 on every set and region (pre-registered cap 0.10, revised to 0.5 because the NCCL native itself reaches 0.134; cells with no near-certain tokens are "no data" for the |Δ| prong and only the KL cap applies).
* **G5 downstream** — many-shot GSM8K (prompts > 4096 tokens so the first chunk is routed), ≥ 200 questions, greedy: the route's paired verdict-flip asymmetry vs the native reference must not differ from the NCCL native's beyond binomial noise (two-sided Fisher exact test on the two (a, b) pairs, p < 0.05 fails), and |Δacc| must not exceed the largest |Δacc| of the native variants (as pre-registered and as scored below; a zero-net-change native band makes this clause unpassable, so a floor analogous to the ratio criteria is proposed for adoption but was not pre-registered and is not applied to the results below).

Greedy identity counts and identical-prefix maxima stay in the reports for continuity but are not gated. Proposed for adoption, not pre-registered and not applied below: the ratio criteria would apply only where the band statistic is well above zero (band mean ≥ 0.001; otherwise only the absolute cap applies) — on (P) they compare noise with noise (continuation region: band means ≤ 0.0004, e.g. 1.9× on a mean of 0.0002). In the chunk region (P) has no nonzero band at all — the NCCL band is identically zero there and the TP4-vs-TP8 chunk band was measured for (R) and (T) only — so the G1–G3 ratios are not read for that cell and only the absolute caps apply to it (route mean ≤ 0.00004, p99 ≤ 0.0004, 0 top-1 flips). Calibration arms are part of the gate: a run without a native-vs-native band cannot be read.

### 5. Proposed gate

The current gate (greedy identity on random-id prompts + 0.05 over identical prefixes) has no threshold that legitimate native configurations pass and that still detects a defect, so it should be replaced for this route by a calibrated, teacher-forced gate. Thresholds below were fixed before the B300/TP4/GSM8K numbers were read (multipliers 2×, absolute caps); one absolute cap was violated by a *calibration arm* and is revised with the data shown (G4). Two things changed after the data: the written proposal named the NCCL native as the sole band for both regions — it is identically zero in the chunk region, so native TP4 vs TP8, the only other same-head native variant, is the chunk band — and (P) was added to the two pre-registered sets.

* **G0 harness sanity** — native second launch == native reference exactly (32/32, |Δ| = 0 on every set); route counters show every 4096-row extend routed and every decode batch native. *Measured: holds on every run that included the second launch (B200 run 1, B300 TP8, B300 TP4, GSM8K B200 and B300: 32/32 and |Δ| = 0, or 250/250 and 200/200 identical answers).*
* **G1 scale** — route mean |Δlogprob| of the reference-chosen token ≤ 2 × the band's mean, and ≤ 0.05, per set and region. *Measured: ratios 0.96–1.04 (continuation vs NCCL native, (R)/(T)), 0.93–0.98 (chunk vs TP4 native); on (P) 0.86–1.93 at means ≤ 0.0004; absolute ≤ 0.024.*
* **G2 argmax stability** — route top-1 flip rate ≤ 2 × band, and ≤ 5 %. *Measured: ratios 0.68–1.35 (minimum: route at TP4 vs native TP4, chunk region, (T), 21 vs 31 flips of 2016); absolute ≤ 2.9 %.*
* **G3 tail** — route p99 |Δ| ≤ 2 × band, and ≤ 0.3. *Measured: ratios 0.89–1.10 on (R)/(T), 0.58–1.11 on (P); absolute ≤ 0.251.*
* **G4 defect detector** — max |Δ| at near-certain tokens (reference logprob > −0.1) ≤ 0.5 and max top-20 KL ≤ 1.0, on every set and region. Pre-registered cap was 0.10; the NCCL native itself reaches 0.134 (B300, continuation), so 0.10 would fail a legitimate native server. A gross corruption reaching the scored rows would be expected to move confident tokens by nats (an expectation, not demonstrated by fault injection here), so 0.5 keeps the detector while leaving the legitimate band a 3.7× margin. Where a cell has no near-certain tokens — the (R) chunk region, 0 of 2048 — the |Δ| prong is "no data", not a pass, and only the KL cap applies there (route 0.17–0.20 vs TP4-native band 0.14). *Measured route maxima: 0.079 and KL 0.49 (NCCL native: 0.134 and 0.47; TP4 native: 0.042 and 0.48).*
* **G5 downstream** — many-shot GSM8K (prompts > 4096 tokens), ≥ 200 questions, greedy: the route's paired flip asymmetry vs the native reference must not differ from the NCCL native's beyond binomial noise (two-sided Fisher exact test on the two (a, b) pairs, p < 0.05 fails), and |Δacc| must not exceed the largest |Δacc| of the native variants. *Measured, B200: route a = 2, b = 1 vs NCCL native a = 0, b = 2, Fisher p = 0.40; |Δacc| 0.4 pt vs native maximum 0.8 pt → pass (no detectable effect at n = 250). At this n the clause resolves only gross effects: against the observed (0, 2) band it fails only ≥ 5 one-directional route flips (an exact McNemar on the route alone needs ≥ 6, two-sided), and the accuracy clause fails any net verdict change larger than the band's (here 2 questions = 0.8 pt); the route changed 3 verdicts and the NCCL native 2. The between-arm test's sensitivity is set by the band arm's own flips, so a ~1-pt one-sided bound would need N of order 1000 — noted for adoption, not applied. B300: route a = 4, b = 0 vs NCCL a = 1, b = 1, Fisher p = 0.33 (flip clause passes); |Δacc| 2.0 pt vs native maximum 0.0 pt → the accuracy clause fails as written (a zero-net-change band makes it unpassable; it needs the same floor as the ratio criteria). G5 verdict: not passed — no detectable effect at n = 450, but a one-directional lean (6 vs 1 pooled) that only a larger N can settle.*

Greedy identity counts and the identical-prefix max |Δ| stay in the report for continuity but are not gated.
