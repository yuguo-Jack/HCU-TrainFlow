# [FlashInfer v0.7.1] Add opt-in NVFP4 W4A16 support to FlashInfer MegaMoE

[Upstream PR](https://github.com/sgl-project/sglang/pull/39210) · state: open · merged: False

## Original PR description

## Motivation

@humansand

Add NVFP4 W4A16 to the existing FlashInfer MegaMoE backend for serialized ModelOpt
checkpoints and `nvfp4_online`. Reuse `SGLANG_FLASHINFER_CUTEDSL_NVFP4_W4A16=1`
from [#35120](https://github.com/sgl-project/sglang/pull/35120); the default NVFP4
MegaMoE path remains W4A4.

**Dependency:** uses upstream's released FlashInfer
[0.7.1](https://github.com/flashinfer-ai/flashinfer/releases/tag/v0.7.1) pin from
[#43494](https://github.com/sgl-project/sglang/pull/43494), including
[FlashInfer #5019](https://github.com/flashinfer-ai/flashinfer/pull/5019).
This PR does not change Dockerfiles or dependency pins.

## Modifications

- **Backend and precision:** extend the existing MegaMoE preparation/forward path
  and use FlashInfer's native config, preprocessing and pooled workspace APIs.
  W4A16 uses packed NVFP4 weights/block scales, per-expert FP32 weight scales,
  BF16 expert activations/EP transport/combine and post-FC2 routing. Checkpoint
  activation scales are neutralized; online quantization retains its source
  precision and excluded-layer semantics. No new opt-in or quantization interface.
- **Topology and models:** SM100/SM103 with attention-DP=TP=EP. GLM DSA/MTP keeps
  synchronized DP token counts and graph buckets while expert inputs remain local.
  Resolve the EP process group through the active runtime context.
  Kimi K3 NVFP4 W4A4/W4A16 uses standard TopK and local EP/shared-expert handling;
  SiTU maps GEMM1 alpha/clamp fields to beta/linear-beta, separately from SwiGLU
  clamps. MXFP8/DeepGEMM reject unwired SiTU; Nemotron ReLU-squared is unsupported.
- **Reduction and output:** default `SGLANG_FLASHINFER_MEGAMOE_IN_KERNEL_FC2_REDUCE=0`
  uses external FP32 accumulation. Setting it to `1` permits nondeterministic
  BF16 atomic candidates; tuning may still select external reduction. Use native
  `supports_output_view` to distinguish W4A4's borrowed output from W4A16's owned output.
- **Reload and dummy weights:** restore canonical W4A16 loading views and copy
  prepared weights into existing buffers. Retain the live layer, workspace owner
  and captured addresses; stage runtime scales on every forward. Initialize dummy
  `weight_scale_2` to one while preserving ordinary random-weight initialization.
  Serialized W4A16 reload is covered; W4A4 reload and online RL reload are outside scope.

### Startup tuning and cache ownership

- Tune once per geometry and capacity before graph capture and prepare pooled
  workspaces: powers-of-two decode profiles cover captured, eager and adaptive-MTP
  bounds, plus the per-rank prefill ceiling from the shared runtime helper.
  All ranks choose the smallest capacity covering synchronized DP counts,
  including empty ranks; reject overflow.
- Tune representative capacity-sized inputs, then install fixed workspaces.
  Native first-forward AUTO alone would tune the first live input while caching
  under workspace capacity. FlashInfer owns namespaced persistence; stage each
  profile once across layers and preserve session winners for pooled workspaces.
- Scope the target rank-cache filename by physical GPU UUID so engines on disjoint
  GPUs do not overwrite each other's records. Same-GPU engines need separate
  `SGLANG_CACHE_DIR` roots. Cache-disabled runs use unique output filenames.
  Cache naming adds no forward-path work.
- Use the existing target startup autotune lifecycle; do not enable
  `SGLANG_FLASHINFER_AUTOTUNE_EXTEND` implicitly. Skipped/disabled tuning retains
  the default native path. Native tuning requires EP=WORLD; draft MegaMoE profiles
  and new deterministic-mode behavior are outside scope.

### Single-node NVSHMEM defaults

For supported single-node FlashInfer MegaMoE formats with no speculative decoding
or draft A2A `none`, set these defaults before NVSHMEM initialization, preserving
explicit environment overrides:

```bash
NVSHMEM_REMOTE_TRANSPORT=none
NVSHMEM_IB_ENABLE_IBGDA=0
NVSHMEM_DISABLE_LOCAL_ONLY_PROXY=1
```

These select the direct-P2P path and avoid the uninitialized proxy global-exit
state corrected by [NVIDIA/nvshmem commit `af9e2391a849`](https://github.com/NVIDIA/nvshmem/commit/af9e2391a849d1a36b4be09c3f6f20d622dada1b).
[NVIDIA/nvshmem#110](https://github.com/NVIDIA/nvshmem/pull/110) is closed; its
description and discussion provide additional background.
All EP GPUs must support peer memory access. Proxy-based global exit/timeout
polling and remote IB/UCX transport are disabled; NCCL/UID bootstrap networking
is unaffected. Multi-node jobs and drafts using other A2A backends receive no
automatic defaults. No dedicated environment-variable behavior tests are added.

Example on four Blackwell GPUs with FlashInfer 0.7.1:

```bash
SGLANG_FLASHINFER_CUTEDSL_NVFP4_W4A16=1 python -m sglang.launch_server \
  --model-path Qwen/Qwen3-30B-A3B-Instruct-2507-FP8 \
  --quantization nvfp4_online --dtype bfloat16 \
  --moe-runner-backend flashinfer_megamoe \
  --moe-a2a-backend flashinfer_megamoe \
  --tp-size 4 --attn-dp-size 4 --ep-size 4 \
  --cuda-graph-backend-prefill disabled
```
