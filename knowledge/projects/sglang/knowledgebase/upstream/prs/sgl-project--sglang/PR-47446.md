# [Fix] logging: Bound token-ID decoding in partial request logs

[Upstream PR](https://github.com/sgl-project/sglang/pull/47446) · state: open · merged: False

## Original PR description

## Motivation

With `--log-requests-level 2`, native token-ID requests still decode every input token after formatting the received record. Batched requests decode every row. The result is then assigned to the real request's `text`, so enabling logging changes the object later used by tokenization and multimodal processing. Formatting a short log does not bound that decoding work.

## Modifications

- Build decoded text on a shallow dataclass replacement used only for logging, for both received and finished records. Pass the tokenizer to the finished logger instead of relying on the earlier mutation.
- At partial level, decode at most 2048 input tokens per record, shared across a bounded selection of batch members. Show head/tail previews and an omission marker; preserve full decoding at explicit level 3.
- Keep metadata levels, supplied text and requests without a tokenizer on their existing paths. Document the preview budget in the existing server-arguments reference.

## Accuracy Tests

Ran the existing registered CPU test file using normal SGLang imports, actual `GenerateReqInput`/`RequestLogger`, a local `PreTrainedTokenizerFast` and actual text/JSON file sinks:

```bash
PYTHONPATH=python .venv/bin/python test/registered/unit/utils/test_request_logger_redaction.py
```

The file passes, including existing redaction checks. New cases cover long single and batched inputs, a batch larger than the preview budget, Unicode, received/finished records, explicit full logging, and request immutability. The partial-preview regression fails on the base revision for both formats: the long single input decodes 8192 IDs and the three-row batch decodes 24576 IDs instead of staying within 2048.

This does not change kernels or claim pretrained-model/GPU accuracy validation. The normal inference request is kept intact rather than populated with a logging preview.

## Speed Tests and Profiling

Validated the bound on actual tokenizer decode inputs rather than inferring work from final log length. Partial-level decoding is limited to 2048 IDs per record independently of input length and batch size; full level 3 remains intentionally unbounded. No end-to-end TTFT or GPU throughput improvement is claimed.

Changed-file pre-commit checks pass. From the documentation directory, `mint validate` passes with existing documentation warnings and `mint broken-links` reports no broken links.
