# [DSpark] Run the same markov block in the draft graph tail; drop `SGLANG_DSPARK_FOLDED_SAMPLING`

[Upstream PR](https://github.com/sgl-project/sglang/pull/43668) · state: closed · merged: True

## Original PR description

Stacks on #43622.

- The draft graph tail (`DsparkDraftSampler`) calls the same `draft_markov_block` as the eager path, over the graph's hidden states, so graph and eager compute the same tokens and logits.
- The tail always keeps the step logits in a static `[max_bs, gamma, vocab]` buffer and serves greedy and sampling rows in one capture; temperatures and greedy rows are staged once per replay.
- Deletes `StepSampler`, `run_markov_block`, `sample_block`, `sample_block_greedy_fused`, and the `SampleStepTokens` and `BuildStepLocal` kernels.
- Removes `SGLANG_DSPARK_FOLDED_SAMPLING`, its free-memory probe, and the greedy-only tail that sent sampling batches back to the eager path. Removes `SGLANG_DSPARK_OPT_FUSED_GREEDY_MARKOV`. Both are registered as deprecated.
- Drops the redundant `SGLANG_DSPARK_FOLDED_SAMPLING=0` from the Kimi-K3 NPU recipes and test; they already set `SGLANG_DSPARK_FOLDED_PROPOSAL=0`.
- Tests: a captured block replays the eager block (tokens, logits, noise offset), and the captured sampler matches the eager draft of the same batch.

Behavior changes:
- The step-logits buffer `[max_bs, gamma, vocab]` is always allocated when the proposal is folded (FP32 on DeepSeek-V4: about 165 MB per rank at `--cuda-graph-max-bs-decode 64` and gamma 5, about 2 GB at max_bs 256 and gamma 15). It is no longer skipped on a low free-memory reading; a deployment that relied on that fallback can now fail at startup instead.
- The greedy-only tail is gone in this PR, and its replacement, `SGLANG_DSPARK_USE_GREEDY_DRAFT=1`, lands two PRs up the stack. In between, a deployment that set `SGLANG_DSPARK_FOLDED_SAMPLING=0` or `SGLANG_DSPARK_OPT_FUSED_GREEDY_MARKOV=1` runs the sampling tail for temperature-0 batches, which is slower (step logits are written and, on a TP-sharded V4 head, gathered whole each step). This PR and the greedy-draft PR are meant to land together.
- `SGLANG_DSPARK_OPT_FUSED_GREEDY_MARKOV` no longer has an effect; the fused one-row kernel serves the greedy draft.

## Verification

DeepSeek-V4.1-Flash on 4x GB300 with the recommended low-latency deployment (TP4, EP4, block size 5, `--cuda-graph-max-bs-decode 64`, custom allreduce on), random 2048-in / 1024-out. The stack column is the top of this stack with the greedy draft off, which runs this layer's tail; main and stack ran back to back.
