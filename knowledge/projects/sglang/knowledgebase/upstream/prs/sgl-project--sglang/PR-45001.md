# [Fix] multimodal: Convert non-RGB images to RGB in decode_media_snapshot

[Upstream PR](https://github.com/sgl-project/sglang/pull/45001) · state: open · merged: False

## Original PR description

## Motivation

Fixes #44748.

A multimodal request carrying a single grayscale JPEG crashes in the HF image processor's normalize step with:

```
RuntimeError: output with shape [1, 1, 1760, 1248] doesn't match the broadcast shape [1, 3, 1760, 1248]
```

Root cause: on the preprocess-cache path, `MediaArtifactCacheMixin.decode_media_snapshot` (`python/sglang/srt/multimodal/media_artifacts/base.py`) decodes the raw source into a PIL image but returns it untouched — a grayscale image stays mode `"L"` and reaches the HF processor as 1-channel, which the 3-channel mean/std broadcast rejects. The legacy (non-cache) path never had this problem: `BaseMultimodalProcessor._load_multimodal_inputs` defaults `discard_alpha_channel=True`, converting every non-RGB image via `smart_to_rgb`/`convert("RGB")` before the processor ever sees it.

## Modifications

- `python/sglang/srt/multimodal/media_artifacts/base.py`
  - `decode_media_snapshot` now normalizes every decoded PIL image through a new `_ensure_rgb_image` helper (both the direct-PIL-input branch and the `load_image` branch).
  - `_ensure_rgb_image` mirrors the legacy path exactly: RGB images are returned as-is (identity, no copy); non-RGB images go through `smart_to_rgb` when the processor class opts into `smart_rgb_conversion` (e.g. GLM-4V), otherwise plain `Image.convert("RGB")`. The attribute is read via `getattr` so the bare mixin (as used in unit tests) keeps working.
  - Tensor/ndarray paths are untouched, matching the legacy behavior for GPU-decoded tensors.
  - Conversion happens after decode, so snapshot identity (content digest, artifact key) computed from the raw source is unchanged.

## Tests

- Wrote a stub harness (`/tmp/verify_44748.py`) that executes the **real** `decode_media_snapshot`/`_ensure_rgb_image` from the edited file (torch, `Modality`, cache helpers, and `load_image` stubbed; real PIL/numpy and the real `smart_to_rgb` extracted from `utils/common.py`). 12/12 pass:
  - Issue repro: grayscale JPEG (`Image.new("L", ...)` saved as JPEG, as in the issue) decodes to mode `"RGB"`; an emulated torchvision normalize broadcast with 3-channel mean/std no longer raises; pixel content is preserved across all three channels (all 128).
  - RGB JPEG passthrough keeps mode `"RGB"` with no conversion.
  - RGBA without `smart_rgb_conversion` converts via plain `convert("RGB")` (same as legacy).
  - RGBA with `smart_rgb_conversion=True` composites the alpha onto a background (transparent pixel renders white, not the black-drop of plain convert).
  - Direct PIL `"L"` and palette `"P"` inputs convert to `"RGB"`; ndarray/tensor inputs pass through untouched; non-image modality still raises `NotImplementedError`; malformed image bytes still raise `ValueError` (preserves the contract asserted by `test_media_artifact_processor.py::test_default_image_decoder_rejects_lazy_pil_failure`).
- Not verifiable here: an end-to-end server run with Qwen3.5-VL requires a GPU and the model weights; the actual HF `Qwen2VLImageProcessor._preprocess` normalize call cannot run on this machine.
- Pre-push audit (mandatory): `ruff check --select F401,F821,F823,UP037` clean, `ruff format --check` clean, `python3 -m py_compile` clean, `git diff --check` clean, no added line over 88 cols.
