# [Perf] [NVIDIA] mhc: Split post-combine for small batches

[Upstream PR](https://github.com/sgl-project/sglang/pull/44169) · state: open · merged: False

## Original PR description

## Motivation

The existing mHC post-combine kernel launches one CTA per token across all channels. GLM-5.3-Flash EAGLE verification uses 5 to 80 tokens, leaving much of a B200 idle. This adds a split kernel for small batches and keeps the existing kernel for larger inputs.

## Modifications

The split TileLang kernel divides the hidden dimension into 512-channel blocks and preserves the existing operation order. GLM's `hc_post` dispatch uses it through 256 tokens and falls back above that. Direct `mhc_post` callers and the default implementation stay unchanged.

## Accuracy Tests

Focused split-kernel checks match the existing kernel bit for bit on the updated branch on an RTX 5070 Ti (SM120). Earlier checks also covered the GLM dispatch boundary and direct callers. Earlier B200 kernel and server checks used a port on the main nightly. Decode/prefill comparisons had mean absolute log-prob differences of 0.0228 to 0.0240 with the split kernel and 0.0212 to 0.0232 on main; argmax agreement was 0.9834 to 0.9840 and 0.9845, respectively. These results were within baseline variation.

Run the layernorm kernel suites with `python -m pytest` in a compatible CUDA environment or through the registered CI runner.

## Speed Tests and Profiling

The server comparison used a GLM-5.3-Flash FP8 model with EAGLE 4/1/5 on TP4 B200. It ran the split-kernel port on nightly commit 7224fce1b5e4. This result predates the latest base update and has not been repeated on the updated branch. Time per verify step:

| Streams | Existing kernel | Split kernel | Change |
| --- | ---: | ---: | ---: |
| 1 | 8.414 ms | 8.342 ms | 72 us (0.9%) |
| 4 | 12.085 ms | 11.748 ms | 337 us (2.8%) |
| 16 | 18.349 ms | 18.003 ms | 346 us (1.9%) |

The two servers per arm varied by up to 0.4%. A separate kernel microbenchmark favored the split through 1,024 tokens and showed it slower at 2,048, so dispatch remains capped at 256. The first call compiled the new kernel in 1.65 s. Server results cover verify batches through 80 tokens; TP8, other GPUs, prefill workloads and other models remain unvalidated.
