# Bound encoder health checks while waiting for dispatch

[Upstream PR](https://github.com/sgl-project/sglang/pull/42088) · state: closed · merged: False

## Original PR description

## Motivation

Encoder `/health` and `/health_generate` wait for the shared TP dispatch lock before starting their timeout. If another encode holds that lock, the health request can wait indefinitely instead of returning 503 within `HEALTH_CHECK_TIMEOUT`.

## Modifications

Bound lock acquisition with the existing timeout and subtract that wait from the remaining probe budget. Keep the lock ownership handoff to the shielded drain task: timing out before acquisition leaves the current owner untouched, while timing out after dispatch still lets the collective finish before releasing its lock.

Add regressions for lock-wait timeout and recovery, cancellation before ownership, and the remaining timeout budget.

## Accuracy Tests

- Entire encoder health test module: 8 tests pass. Original source fails the two new deadline regressions; the other 6 tests pass.
- Actual FastAPI ASGI health endpoint with the dispatch lock held: before, no response after ten times the configured deadline; after, 503 while the original lock stays held and no probe is dispatched. The next health request returns 200 after the original owner releases the lock.
- All applicable pre-commit hooks pass.
- Local tests execute the actual endpoint/drain definitions and permanent tests with GPU package initialization excluded and the encoder/transport boundaries doubled. No GPU or distributed-collective execution claim is made.
