# [Doc] [NPU] cookbook: add tested A2 deployment and A3 reference for MiniMax-M2.5

[Upstream PR](https://github.com/sgl-project/sglang/pull/40120) · state: closed · merged: True

## Original PR description

## Motivation

Add Ascend deployment choices to the MiniMax-M2.5 cookbook: a tested A2 eight-device configuration and a separately labelled A3 reference. Related task: https://github.com/Ascend/sglang/issues/1215

HiDevLab supplied A2 multi-card resources; A3 multi-card resources are unavailable for this contribution. The contributor is proceeding with A2 measurements plus the A3 reference. Hardware/performance equivalence and an A3 benchmark pass are not implied; acceptance of the adjusted scope remains subject to maintainer review.

## Changes

- Add an A2 selector for 8 x Ascend 910B4 / 32 GiB, TP8, ModelSlim W8A8 main weights, BF16, one request at a time, and no EAGLE3 draft model. Model/tokenizer paths are editable and shell-quoted.
- Use the verified selector settings `--mem-fraction-static 0.96 --max-total-tokens 4096`, context 4096, chunked prefill 128, and graph/radix cache disabled.
- Keep the A3 8-card / 16-die W8A8 + EAGLE3 recipe separately labelled as an unvalidated reference.
- Add measured A2 performance results and reproduction commands in section 5.5, using a separate configuration supporting concurrency up to 8.
- Preserve earlier capacity failures and corrected results.
- Add 13 command-generator regression tests covering the A2 preset, existing platforms, and platform transitions.

## A2 hardware results

The selector configuration allocated 4096 KV tokens on every rank. Six simple answer checks passed with natural stops, and six serial native probes with exact inputs of 64, 128, 256, 1024, 2048, and 3500 tokens each produced the requested 128 output tokens. Post-test health was HTTP 200. These are functional checks, not GPQA accuracy.

The separate performance configuration used static memory fraction 0.97, a measured 16384-token KV pool, context 8192, and up to eight requests. The installed official SGLang benchmark completed all 10 planned runs: **76/76 measured requests succeeded**, with exact input-token lengths and 128 output tokens each. Every post-run health check returned HTTP 200.

Repeated groups use seeds 17, 29, and 43. The guide includes mean/min/max throughput and latency, workload generation, commands, and interpretation limits. Inputs are locally authored synthetic text in ShareGPT-compatible format, not the ShareGPT dataset. These short measurements differ from the A3 3500/1500-token reference and do not establish its 50 ms TPOT target or sustained stability.

Runtime: SGLang 0.5.14.dev172+gf308abc05, Torch 2.10.0+cpu, TorchNPU 2.10.0, Transformers 5.8.1, kernel 2026.5.1, CANN 9.0.0, driver 25.5.2. The supplied source tree had packaging-file modifications. An image digest and immutable model revision were not captured.

## Accuracy status and remaining work

The full GPQA Diamond evaluation is incomplete. Its bounded A2 protocol retains all 198 original questions, the pinned SGLang simple-evals prompt/answer parser, temperature 1, and a 6144-token output cap. All 198 tokenization prechecks passed at context 9216; the earlier 8192-context precheck rejected one oversized prompt before generating any answers. No question was cropped or omitted.

A first-four pilot completed with four correct answers, natural stops, and no capped outputs or protocol errors. Completion lengths were 2033, 5689, 1392, and 1205 tokens in original question order. These records are preserved; they are not a full-dataset accuracy result. No normal-accuracy conclusion is claimed.

On September 24, the additional 200 HiDevLab card-hours became available. The concurrency-8 continuation passed service identity/input-length checks but stopped admitting requests after KV pressure and retraction led to 1800-second HTTP timeouts. It retained 18 terminal records: 12 correct, 5 transport timeouts, and no output-cap terminations. This is an incomplete run, not a full-dataset score. All answers, timeout streams, logs, and cleanup evidence were preserved and backed up.

An independent concurrency-2 GPQA run was then launched with the same prompt, parser, temperature, seeds, output cap and request deadline. It was deliberately stopped on September 24 after repeated output-cap terminations and a review of the compute cost. New admissions stopped through the controlled pause mechanism, and both in-flight requests were retained before cleanup. The final incomplete run contains **26 terminal records: 16 correct, 9 output-cap terminations and no transport/protocol errors**. No C8 answer was imported or selected against a C2 answer. The full-198 accuracy remains unavailable; these are diagnostic records, not a full-dataset score or a normal-accuracy claim. All raw records, streams, logs and cleanup evidence were backed up with verified hashes.

The issue requires accuracy validation but does not prescribe GPQA or 198 questions. The bounded GPQA protocol differs from the A3 EvalScope reference and remains incomplete. A separate predeclared GSM8K deployment-regression protocol now uses five training examples, three independent pilot test items, and 50 frozen disjoint test items. The three pilot items all ended naturally and scored correctly, with 1060, 496 and 1603 output tokens; this establishes feasibility only. The frozen 50-item run completed on September 24: **49/50 correct (98% on this fixed subset), 50 natural stops, zero output-cap terminations and zero request errors**, in 9444.6 seconds of client runtime. All 50 unique terminal records and tokenizer prechecks were verified; independent final-content rescoring agreed with the summary. The complete archive and all 172 manifest hashes were verified locally, all eight NPUs had no remaining processes, and the instance was shut down. It uses client concurrency 1, temperature 1, a 6144-token output cap and context 9216, with no retries or replacement items, and a six-hour total instance window. The three pilot answers are excluded from the 50-item score. Even a completed subset is not full GSM8K or GPQA accuracy.

The independent reference-length A2 benchmark completed all 6 measured requests: 3 seeds (1, 17, 29), 2 requests each at client concurrency 2, exact 3500 input / 1500 output tokens. Three 32-token warmup requests are excluded. Inputs are locally authored synthetic text in ShareGPT-compatible format. The eager TP8/ModelSlim/BF16 service used context 9216, KV 16384, memory fraction 0.97, chunked prefill 128, and max-running-requests 8. Across the three run-level measurements, mean output throughput was 8.004 tokens/s (range 7.896–8.065), mean TPOT 243.163 ms (range 241.222–246.570), mean TTFT 10.317 s, and mean end-to-end latency 374.818 s. These means/ranges describe run-level aggregates, not individual-request extrema. The full archive and all 46 evidence hashes were independently verified; owned processes were cleared and the performance instance window was shut down. An earlier missing-file preflight failure occurred before model startup or benchmark requests and is retained in the archive. These A2 low-concurrency measurements do not establish the A3 C320 / 50 ms target. Cookbook sections 5.6 and 5.7 now include these measured results, reproduction commands and the frozen regression protocol. This PR is ready for review. Maintainer review is requested for the documented A2 measurements plus A3 reference and the explicitly bounded validation scope.

A bounded eager-versus-decode-graph diagnostic was completed on September 24 with unchanged TP8/ModelSlim/BF16, context 9216, KV 16384 and static memory fraction 0.97. The eager group completed all 9 measured synthetic 128-input/128-output requests (3 at C1, 6 at C2), plus 3 excluded warmup requests. Mean client-observed TPOT estimates were 236.98 ms at C1 and 241.54 ms at C2. NPU graph capture for batches 1/2 completed, but subsequent startup warmup / graph-input update raised torch.OutOfMemoryError (507033 / Memory_Allocation_Failure); health remained unavailable and no graph measurement requests ran. The operator stopped the supervisor through its cleanup handler after the observed failure; no memory retuning or retry was performed. The complete archive and 93 evidence-file hashes were verified, owned processes were cleared, and the instance was shut down. This diagnoses only the frozen configuration: it establishes neither graph speedup nor general A2 graph incompatibility, accuracy, or A3 parity.
