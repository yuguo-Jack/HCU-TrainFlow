# [MLX] Fix SchedulerProfilerManager MPS capture mocks

[Upstream PR](https://github.com/sgl-project/sglang/pull/30886) · state: closed · merged: False

## Original PR description

## Motivation

The two `SchedulerProfilerManager` MPS tests mock
`mx.metal.start_capture`/`stop_capture`, but the patched profiler takes the MPS
path and calls `torch.mps.profiler.metal_capture`. The success test can
therefore start a real Metal capture and fail unless `MTL_CAPTURE_ENABLED` is
set, while the failure test can pass for the wrong reason.

Fixes #30550.

## Modifications

- Force both manager tests to select the MPS path even when the MLX CI lane
  exports `SGLANG_USE_MLX=1`.
- Mock the actual `torch.mps.profiler.metal_capture` call.
- Verify that the successful capture context is entered and exited.

- now-ing · comment · 2026-07-27T12:59:51Z · [source](https://github.com/sgl-project/sglang/pull/30886#issuecomment-5091599703)

Thanks for the fix — I confirmed the root cause and verified it on real Apple Silicon (the PR notes it couldn't be run locally).

**Environment:** M2 Max 64GB, macOS, mlx 0.32.0, mlx-lm 0.31.3, torch 2.11.0, transformers 5.12.1.

**Root cause (code-level).** `SchedulerProfilerManager._start_profile` (`profiler_manager.py:166`) maps the default `activities=["CPU","GPU"]` to `[ProfilerActivity.CPU, ProfilerActivity.CUDA]`. With `SGLANG_USE_MLX` unset, `use_mlx()` is `False`, so the patched `torch.profiler.profile` (`profiler.py:163`) takes the MPS branch → `MetalCaptureProfiler.start_mps` → `torch.mps.profiler.metal_capture`. The original test mocked `mx.metal.start_capture` (the MLX-path object), which is never called on this path, so the success case hit a real Metal capture failing without `MTL_CAPTURE_ENABLED`, and the failure case passed for the wrong reason. Mocking `torch.mps.profiler.metal_capture` and pinning `use_mlx`→`False` as this PR does is exactly right.

**Verification (current main `db9143e` → this PR applied):**
- Before: `TestSchedulerProfilerManagerMPS::test_start_profile_success_with_mock_capture` FAILED (`AssertionError: False is not true`); the other 9 in the file pass.
- After: `10 passed in 4.72s`.

The remaining CI jobs are the call-gate / `-finish` jobs rather than a test failure. Happy to help with a rebase onto current main or anything else to move this forward.
