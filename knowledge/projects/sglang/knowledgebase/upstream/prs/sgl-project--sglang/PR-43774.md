# [Feat] glm5.3flash: Support padded CP BCG and prefix replay with PD/DFlash2

[Upstream PR](https://github.com/sgl-project/sglang/pull/43774) · state: closed · merged: True

## Original PR description

## Motivation

Enable GLM-5.3 Flash prefill with CP and breakable CUDA graphs together with Mooncake PD disaggregation and DFlash2. Padded inputs and cached prefixes now replay instead of requiring an exact capture-bucket match and an empty prefix.

Supported topology: TP2/CP2 prefill on two GB300 GPUs → TP2 decode on two GB300 GPUs. Physical P/D TP widths must match, prefill CP=TP, and DP=PP=EP=1.

## Changes

- Preserve the existing Mooncake/DFLASH CP support, draft TP scope restoration, and fixed physical P/D layout checks.
- Separate live token counts from captured capacity. Refresh address-stable per-rank MoE counts, retain global cache positions, and use static capacity only for graph-shaped KDA reorders.
- Trim attention queries to each CP rank's valid rows while preserving the global KV/cache extent and matching TRT-LLM sequence metadata. Clear invalid local output rows to prevent padded NaNs from entering later layers.
- Allow padded and prefix-cache-hit replay with live KDA checkpoint metadata. Add capture buckets from 2 through 8192 tokens and regression coverage for odd lengths, bucket reuse, poisoned padding, prefix hits, and long chunks.
- Stage DFlash prefill length metadata asynchronously to avoid a host wait on outstanding target GPU work.
- Keep eager fallback when CP2 cannot activate for a one-token suffix, and for unsupported inputs such as multimodal batches.

## DFlash prefill synchronization follow-up at `09e2c19f8665be8b1e5bfbfb5126f846ba93820e`

The two CPU-list-to-CUDA `torch.tensor(..., device=device)` constructors for prefill lengths waited for the target prefill's queued GPU work before submitting the draft KV materialization. Use the existing `async_h2d` helper for pinned, nonblocking staging on the same stream. This keeps stream ordering and the helper's platform fallback.

A/B validation used `8fd66c1123620061c91ae49abd1a525261aca068` versus the final follow-up source (SHA256 verified), the same pinned models and PR reproduction topology on 4×GB300 (2 prefill + 2 decode), CP2/interleave, BCG, Mooncake PD and DFlash2. Chunked prefill remained **8192**. KV sharding and HiCache were disabled. The workload was BS1, ISL4096, OSL20, with identical inputs and zero cached tokens; each arm had 3 warmups, 3×20 unprofiled requests, and a separate 20-step CPU/GPU profile.

| Metric | Before | After |
| --- | ---: | ---: |
| DFlash length-copy synchronizations, per TP rank / 20 steps | 40 | 0 |
| TP0 DFlash forward CPU mean, profiled | 133.41 ms | 81.79 ms |
| Mean TTFT, 60 unprofiled requests per arm | 147.47 ms | 146.56 ms |

Both TP ranks retained 20 `EXTEND bs=1 toks=4096` steps, 460 graph launches and 47300 GPU kernels. The long early synchronization is removed, but most GPU completion wait moves to the existing PD `copy_done.synchronize()`: TP0 accumulated 962.47 ms there across 20 steps. The observed unprofiled TTFT reduction is approximately **0.62%**; the shorter CPU forward scope is not an equivalent end-to-end speedup.

## Reproduction

Use pinned local model snapshots or the matching revisions. Common options:

```bash
COMMON=(
  --model-path zai-org/GLM-5.3-Flash
  --revision eb9eb208eb0d988989d07a6a12d0fdeb5f52574a
  --tp-size 2
  --dsa-prefill-backend trtllm --dsa-decode-backend trtllm
  --kv-cache-dtype fp8_e4m3 --moe-runner-backend flashinfer_trtllm
  --speculative-algorithm DFLASH
  --speculative-draft-model-path incoai/GLM-5.3-Flash-DFlash2
  --speculative-draft-model-revision bf582e4eacc1810f76656d1811693ff6c6737d2a
  --speculative-draft-attention-backend fa4
  --reasoning-parser auto --tool-call-parser auto
  --max-running-requests 16 --cuda-graph-max-bs-decode 16
  --chunked-prefill-size 8192 --mem-fraction-static 0.9
  --enable-metrics --random-seed 42 --host 0.0.0.0
)

# Configure Mooncake/RDMA for your environment.

# Prefill worker, GPUs 0–1.
CUDA_VISIBLE_DEVICES=0,1,2,3 sglang serve "${COMMON[@]}" --trust-remote-code --base-gpu-id 0 \
  --port 21100 --nccl-port 21300 \
  --attn-cp-size 2 --enable-prefill-cp --cp-strategy interleave \
  --cuda-graph-backend-prefill breakable \
  --cuda-graph-bs-prefill 2 4 8 16 32 64 128 256 512 1024 2048 4096 8192 \
  --disaggregation-mode prefill --disaggregation-transfer-backend mooncake \
  --disaggregation-bootstrap-port 21500

# Decode worker, GPUs 2–3, in a separate shell with the same exports.
CUDA_VISIBLE_DEVICES=0,1,2,3 sglang serve "${COMMON[@]}" --trust-remote-code --base-gpu-id 2 \
  --port 21200 --nccl-port 21400 \
  --disaggregation-mode decode --disaggregation-transfer-backend mooncake \
  --disaggregation-bootstrap-port 21500

# Router: sglang-router 0.3.2. Wait for /readiness before evaluation.
python -m sglang_router.launch_router \
  --pd-disaggregation --prefill http://127.0.0.1:21100 21500 \
  --decode http://127.0.0.1:21200 --host 127.0.0.1 --port 21000 \
  --request-timeout-secs 7200 --worker-startup-timeout-secs 7200 \
  --retry-max-retries 1 --health-check-timeout-secs 60

# Optional integrated TP2 baseline; skipped in the latest PR-only validation.
# Stop candidate workers before using this historical comparison command.
CUDA_VISIBLE_DEVICES=2,3 sglang serve "${COMMON[@]}" \
  --port 31000 --nccl-port 31200
```
