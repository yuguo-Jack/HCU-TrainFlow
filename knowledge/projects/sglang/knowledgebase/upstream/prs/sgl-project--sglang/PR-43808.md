# [HiCache] Back up Mamba and SWA states on write_back eviction when full KV is already on host

[Upstream PR](https://github.com/sgl-project/sglang/pull/43808) · state: open · merged: False

## Original PR description

## Motivation

With `--hicache-write-policy write_back`, Mamba states and SWA windows reach host when their node is evicted from device. Eviction skips that backup when the node's full KV is already on host, so such a leaf is demoted, and such an internal node is tombstoned, without its Mamba state or SWA window.

Such nodes are common: a request that ends inside a host-only node splits it and checkpoints the prefix on device only. After the next eviction the prefix's KV is on host but its checkpoint is gone, and later requests recompute it. #41374 covers the internal-node case. This PR also covers leaf eviction.

## Modifications

- Leaf eviction (`evict_device_leaf`, Python and Rust tree cores): a leaf whose full KV is already on host but whose Mamba state or SWA window is not gets that state backed up before it's demoted.
- During this backup the leaf's full KV host copy is locked, so host eviction cannot remove it before the demote.
- Internal eviction: the Mamba and SWA `write_back` paths also back up nodes whose full KV is already on host.
- `_execute_and_commit_kv_backup` returns `None` on failure and `0` for a backup that writes only Mamba or SWA state.

## Accuracy Tests

No change to model forward. New tests cover leaf and internal Mamba eviction, a failed state-only backup, and host eviction during a state-only backup in the unified radix cache suite, and internal SWA eviction in the Rust tree core. On main, the leaf and internal tests fail in every Mamba configuration, as does the Rust SWA test.

On an L4, the unified radix cache suite passes on both tree cores (Python 1,352, Rust 2,967), the Rust crate passes (932), and `test/registered/unit/mem_cache` adds no failures over main.

## Speed Tests and Profiling

One extra host copy of the missing state per such eviction.
