# [HiCache] Back up component state of backed-up nodes on write-back eviction

[Upstream PR](https://github.com/sgl-project/sglang/pull/43808) · state: open · merged: False

## Original PR description

## Motivation

With `--hicache-write-policy write_back`, Mamba states and SWA windows reach host when their node is evicted from device. Eviction skips that backup when the node's Full KV is already on host, so a backed-up leaf is demoted, and a backed-up internal node is tombstoned, without its Mamba state or SWA window.

Such nodes are common: a request that ends inside a host-only node splits it and checkpoints the prefix on device only. After the next eviction the prefix's KV is on host but its checkpoint is gone, and later requests recompute it. #41374 covers the internal-node case; this PR also covers leaves and both tree cores.

## Modifications

- Device leaf eviction returns a `BackupKV` when an auxiliary component holds device state that host lacks, in both tree cores.
- The internal Mamba and SWA write-back eviction paths back up backed-up nodes too.
- `_execute_and_commit_kv_backup` returns `None` when nothing reached host and `0` for a component-only backup, which callers previously counted as a failure.
- Tests: three shared-suite cases, and the guard tests that expected the drop now expect a backup.

## Accuracy Tests

No change to model forward. On an L4, the unified radix cache suite passes on both tree cores (Python 1,348, Rust 2,948), the Rust crate passes (931), and `test/registered/unit/mem_cache` adds no failures over main. With only this PR's tests on main, the new backup tests fail in every Mamba configuration.

## Speed Tests and Profiling

One extra host copy of the missing state per such eviction.
