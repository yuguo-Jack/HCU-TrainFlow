# [Perf] deepseek-v4.1: Stage late-layer DP row counts through pinned memory

[Upstream PR](https://github.com/sgl-project/sglang/pull/45062) · state: closed · merged: True

## Original PR description

## Motivation

With decoder SWA bounded replay and DP attention, `enter_late_layer_dp` installs every DP rank's late-layer row counts on the device in the middle of the model forward. When the counts differ across ranks it did so with `gpu.new_tensor(counts)`, a pageable host-to-device copy. That copy synchronizes the stream: the host waits until all early layers have finished on the GPU, and only then launches the late layers, so the GPU idles while they are launched.

Torch-profiler trace of DeepSeek-V4.1-Flash DEP2 prefill (DP attention 2, EP 2, MegaMoE, DSpark, 32K tokens per rank per step) on GB300, rank 0, 15 steps:

| | Before | After |
|---|---:|---:|
| `enter_late_layer_dp` host time per step | 241 ms | 0.16 ms |
| Kernel time / step span | ~75% | ~97% |
| Step span | 500-680 ms | 425-500 ms |

## Modifications

- Non-uniform counts go through `async_h2d` (pinned staging, copy enqueued on the current stream), the helper the DSv4 backend already uses for host lists. Rank-uniform counts keep `full_like`, the only branch a graph capture takes.

## Accuracy Tests

Not affected: the device receives the same values on the same stream; only the host no longer blocks on the copy. Checked on GB300 under `torch.cuda.set_sync_debug_mode("error")`: entering the late layers with uneven counts raises on main and runs clean with this change, with identical int32 counts installed.

## Speed Tests and Profiling

GB300, DeepSeek-V4.1-Flash, PD disaggregation with 6 DEP2 prefill workers and one DEP16 decode worker, agentic multi-turn workload at concurrency 2884 (prefill-bound), 60-minute measurement window:

| | Before | After |
|---|---:|---:|
| Prefill GPU utilization (nvidia-smi, 3 nodes) | 75-79% | 91-93% |
| Input throughput per GPU (incl. prefix-cache hits) | 475.2k tok/s | 535.8k tok/s (+12.7%) |
| Output throughput per GPU | 3.55k tok/s | 3.94k tok/s (+11.0%) |
| Requests / s | 96.2 | 106.8 (+11.0%) |
| TTFT p50 / p90 | 9.5 / 20.3 s | 5.5 / 13.3 s |

At concurrency 1228 (decode-bound, 4 prefill workers) TTFT p90 drops from 3.4 s to 2.3 s and input throughput moves +1.8%.
