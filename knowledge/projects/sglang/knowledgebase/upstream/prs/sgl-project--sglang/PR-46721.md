# [Test] cuda-graph: Add a standalone CUDA-graph lifetime validation tool and its skill

[Upstream PR](https://github.com/sgl-project/sglang/pull/46721) · state: closed · merged: True

## Original PR description

## Motivation

Follow-up to #46720 (merged). The bug fixed there was found because the LoRA dual graph made the runners capture two graphs per batch size, and nothing short of a corrupted output could reveal that the second capture had freed the first graph's buffers. This adds a tool that inspects captured graphs directly, and a thin project skill that drives it. It is also why the dual graph is opt-in in #46720: the fixes cover today's backends, but a new component can reintroduce the same class of bug, so a deployment that wants the optimization first runs this check on its own serving command (model, backends, parallelism, graph settings) and turns the knob on only when lifetime and coverage pass for that configuration; the skill is the operator's interface to that check.

## Modifications

- `python/sglang/test/cuda_graph_lifetime/`: a tracer injected through a `sitecustomize` on `PYTHONPATH` (no production hooks) wraps `torch.cuda.CUDAGraph` and the SGLang graph backends and runners, reads each captured graph's kernel operands and classifies every device-memory operand against the PyTorch allocator history, and fails the serving process on an operand freed while its graph lives. The harness (`python -m sglang.test.cuda_graph_lifetime --serving-cmd ...`) launches a serving command three times (eager reference, as given, instrumented), drives identical traffic, and writes one ledger with three verdicts kept apart: lifetime, numerical (token-aligned logprobs against eager within 1.0 nat, fail-closed), coverage (the promised graph paths replayed on every worker). `--recompute` re-judges an archived run from digest-verified outputs.
- Tests: one CPU test in `base-a-test-cpu` with twelve independent subtests of the fail-closed contracts (complete evidence passes; drift, truncated responses, a missing worker, a stale flush, a missing graph variant, a crash with saved outputs, a digest mismatch, an unusable or mismatched control never do; the archived ledger is never modified), and one model-free GPU known-good/known-bad control in the label-gated `extra-a-test-1-gpu-small` lane (an optional diagnostic over private allocator and CUDA inspection APIs; edge-case coverage intentionally kept to these core contracts).
- `.agents/skills/sglang-multi-graph-check/`: a thin operator skill for the CLI (new execution versus archive inspection or recomputation, an execution-path preflight, the boundaries every report states).

## Accuracy Tests

- GB300 and H200: the CPU contract test and the GPU control pass (the fuller 35-test and 13-test suites they replace passed there too); on Qwen1.5-MoE with a LoRA adapter and the dual decode graphs (TP1 and TP2) the tool reports lifetime PASS with verified worker identity on the fixed tree and FAIL with three dangling flashinfer wrappers on the base commit; negative controls on saved evidence fail as designed.
- The `extra-a-test-1-gpu-small` lane (RTX 5090) has not run this suite yet; all GPU evidence is GB300 and H200.
