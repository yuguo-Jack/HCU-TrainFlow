# [Perf] speculative: Parallelize EAGLE spec-decode KV index building over token blocks (flashinfer draft decode; verify/draft-extend for flashinfer, flashinfer_mla, aiter)

[Upstream PR](https://github.com/sgl-project/sglang/pull/42803) · state: open · merged: False

## Original PR description

## Motivation

With EAGLE speculative decoding, every decode step rebuilds the paged KV index arrays for the draft and verify passes by copying live rows of `req_to_token`. The Triton kernels that do this launch one program per request and walk the row serially, so at long context (90k-170k KV tokens per request) they cost 0.3-0.6 ms of a ~22 ms decode step while moving only a few hundred KB.

#37659 already added token-block-parallel versions of both kernels (`NUM_STEPS` on `generate_draft_decode_kv_indices`, `TOKEN_BLOCK_PARALLEL` on `create_flashinfer_kv_indices_triton`, plus `kv_indices_num_token_blocks`) but wired them only into the aiter backend's own launch sites. This PR enables them at the remaining EAGLE launch sites: the flashinfer draft-decode launch, and the shared verify / draft-extend builders in `eagle_info.py`, which serve the flashinfer, flashinfer_mla and aiter backends. Enablement only: no kernel change, no FlashInfer change, outputs bit-identical by construction (int32 index copy).

## Modifications

- `sglang/kernels/ops/kvcache/kv_indices.py`: one threshold and one sizing helper next to `kv_indices_num_token_blocks`: `SPEC_KV_INDEX_BLOCKS_MIN_CONTEXT = 32768` and `spec_kv_index_token_blocks(table_width, kv_lens_sum, batch_size, base_programs=None, length_cap=None)` (re-exported from `sglang.kernels.ops.attention.utils`). It returns 1 below the context gate; otherwise it sizes the block count from the batch's mean live KV length when the length sum is a host int (optionally capped), and from the table width when the sum lives on the device or is not passed (the sync-free bound). `eagle_info.py`, `flashinfer_backend.py` and `aiter_backend.py` import it; the private copies and duplicated constants are gone. AITER passes no length sum and its own `max_context_len` as the gate, so its block counts are unchanged (checked against the previous formulas on a 2025-case sweep: 0 mismatches).
- `eagle_info.py`: `EagleVerifyInput` and `EagleDraftExtendInput.generate_attn_arg_prefill` launch `create_flashinfer_kv_indices_triton` on `(bs, nb)` with `TOKEN_BLOCK_PARALLEL = nb > 1`. These two methods are shared by the flashinfer, flashinfer_mla and aiter backends, so all three get the token-block grid at the verify and draft-extend sites (aiter already uses these kernels token-block parallel at its own sites).
- `flashinfer_backend.py`, `FlashInferMultiStepDraftBackend.common_template` (draft decode): same helper, with `base_programs = steps * num_seqs * topk`, sized from `forward_batch.seq_lens_sum` (a host int here, also at CUDA-graph replay) and capped by `draft_window_size + draft_sink_size` when a draft window is set. Launch `(steps * nb, num_seqs, topk)` with `NUM_STEPS = steps` when `nb > 1`; `nb == 1` compiles to the historical 128-wide kernel. With a 256K table, steps 3, bs 4 and 512 live tokens this is the historical `(3, 4, 1)` grid rather than 396 programs; at 4 x 169k it is 21 blocks. Any block count is correct because the kernel strides its blocks over the row; the launch runs outside the captured draft graph, so the grid may change per step.
- Tests (GPU): `test_draft_decode_window.py` gains `test_token_block_grid_matches_window_oracle`: `NUM_STEPS > 0` with 2 / 3 / 33 token blocks against the closed-form `kv_indptr` oracle and the `[sink + recent] + tree` slot oracle (windowed, pure-recent, cap > seq_len, tree, paged tree, 262145 / 1029306-token rows), plus bit-for-bit equality with the one-block grid. `test_spec_kv_indices_grid.py::test_draft_grid_equivalence` now runs every case with and without a 4032 + 64 draft window.

Scope: only servers with `context_len >= 32768`, and only the EAGLE draft-decode, verify and draft-extend index builders (flashinfer draft decode; verify / draft extend for flashinfer, flashinfer_mla and aiter). Non-speculative prefill/decode builders, the wave backend and aiter's own draft launch are untouched. No environment switch.

```python
"""Microbenchmark: serial vs token-block grids for the EAGLE KV-index kernels.

Times generate_draft_decode_kv_indices (draft decode) and
create_flashinfer_kv_indices_triton (verify twin) on one GPU for a few
(running requests x KV tokens per request) points, CUDA-event medians over
`iters` launches with an L2 flush before each, and checks byte-equality of the
outputs between the two grids.  Standalone: only needs sglang's kernel ops.

    python bench_spec_kv_indices.py --table 262144 --steps 3 --iters 200
"""
import argparse, statistics
import torch
from sglang.kernels.ops.attention.utils import (
    create_flashinfer_kv_indices_triton,
    kv_indices_num_token_blocks,
)
from sglang.kernels.ops.speculative.cache_locs import generate_draft_decode_kv_indices
from sglang.srt.utils import next_power_of_2

def timed(fn, iters, flush):
    ts = []
    for _ in range(iters):
        flush.zero_()
        s, e = torch.cuda.Event(enable_timing=True), torch.cuda.Event(enable_timing=True)
        s.record(); fn(); e.record(); torch.cuda.synchronize()
        ts.append(s.elapsed_time(e) * 1000)
    return statistics.median(ts)

def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--table", type=int, default=262_144)
    ap.add_argument("--steps", type=int, default=3)
    ap.add_argument("--topk", type=int, default=1)
    ap.add_argument("--iters", type=int, default=200)
    ap.add_argument("--points", default="2x87609,4x169336,4x146494,4x512")
    a = ap.parse_args()
    dev = torch.device("cuda")
    flush = torch.empty(256 << 20, dtype=torch.uint8, device=dev)
    print(f"{'R x KV/req':>12} | {'draft serial':>12} {'draft blocks':>12} {'nb':>3} | "
          f"{'verify serial':>13} {'verify blocks':>13} {'nb':>3} | equal")
    for pt in a.points.split(","):
        R, L = map(int, pt.split("x"))
        bs = R * a.topk
        r2t = torch.randint(0, 6_000_000, (R + 1, a.table), dtype=torch.int32, device=dev)
        req_pool = torch.arange(R, dtype=torch.int64, device=dev)
        seq_lens = torch.full((R,), L, dtype=torch.int64, device=dev)
        positions = torch.repeat_interleave(seq_lens, a.topk)
        width = a.topk * (L + a.steps) + 64
        kv_i = torch.zeros((a.steps, bs * width), dtype=torch.int64, device=dev)
        kv_p = torch.zeros((a.steps, bs + 1), dtype=torch.int64, device=dev)
        def draft(nb):
            generate_draft_decode_kv_indices[(a.steps * nb, R, a.topk)](
                req_pool, r2t, seq_lens, kv_i, kv_p, positions, a.table,
                kv_i.shape[1], kv_p.shape[1], next_power_of_2(R),
                next_power_of_2(a.steps), next_power_of_2(bs), 1, 0, 0,
                NUM_STEPS=a.steps if nb > 1 else 0)
        # verify twin: one program per request over the live prefix
        kv_indptr = torch.zeros(R + 1, dtype=torch.int32, device=dev)
        kv_indptr[1:] = torch.cumsum(seq_lens, 0)
        out = torch.zeros(int(kv_indptr[-1]), dtype=torch.int32, device=dev)
        def verify(nb):
            create_flashinfer_kv_indices_triton[(R, nb)](
                r2t, req_pool, seq_lens, kv_indptr, None, out, a.table,
                TOKEN_BLOCK_PARALLEL=nb > 1)
        # mean-live-length sizing, as in the PR
        nb_d = kv_indices_num_token_blocks(L, a.steps * R * a.topk)
        nb_v = kv_indices_num_token_blocks(L, R)
        draft(1); ref_i, ref_p = kv_i.clone(), kv_p.clone(); draft(nb_d)
        verify(1); ref_o = out.clone(); verify(nb_v)
        eq = torch.equal(ref_i, kv_i) and torch.equal(ref_p, kv_p) and torch.equal(ref_o, out)
        d1, dn = timed(lambda: draft(1), a.iters, flush), timed(lambda: draft(nb_d), a.iters, flush)
        v1, vn = timed(lambda: verify(1), a.iters, flush), timed(lambda: verify(nb_v), a.iters, flush)
        print(f"{R:>5} x {L:<6}| {d1:>9.1f} us {dn:>9.1f} us {nb_d:>3} | {v1:>10.1f} us {vn:>10.1f} us {nb_v:>3} | {eq}")

if __name__ == "__main__":
    main()
```
