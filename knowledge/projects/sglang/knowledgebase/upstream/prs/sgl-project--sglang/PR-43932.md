# [HiCache] Buffer-only L3 for an auxiliary SWA window; load back only missing window rows

[Upstream PR](https://github.com/sgl-project/sglang/pull/43932) · state: closed · merged: True

## Original PR description

Builds on #43870 (now merged); rebased onto main so this PR carries only its own commit.

## Motivation

`--hicache-host-memory-mode buffer_only` restores a sliding-window span from L3 by staging the trailing window in a host bounce and copying the whole window into fresh device rows; rows that turn out to be resident already are mapped aside and released after the H2D ack, and an allocator-residency cross-check reconciles the tree and allocator views. Two limits follow from that shape:

- Only `ComponentType.SWA` can take part. A unified tree that also carries an `AUXILIARY_SWA` component (an already-registered component type) is refused by the buffer-only fence, so such models get no L3 prefix reuse in buffer-only mode.
- The complete window is copied even when most of it is still resident, which costs redundant device rows, an extra mapping rebuild and the release bookkeeping at ack.

## Changes

- `PoolName.AUXILIARY_SWA` (Python and the Rust tree binding) and `SWAComponent.pool_name`, so a second window component stages, backs up and loads back through its own host pool with the existing SWA component code. The buffer-only fence, `validate_buffer_only_stack`, the shared-arena load reserve, `_aux_loads_margin` and `resolve_prefetch_threshold` now cover every window component; the pipeline holds the components rather than a single page count.
- The staged plan carries a per-window `WindowLoadBackPlan` (logical coverage plus the missing subranges) instead of one token count. H2D copies only the missing rows: tombstoned ranges inside the resident FULL prefix are repaired through `attach_swa_window(component_type=...)` and the tail is appended, then the FULL-to-window mapping is registered through `SWAComponent.restore_buffer_mapping`. The allocator cross-check and the SWA redundant-slot release disappear; the Mamba load-context release path is unchanged.
- Admission: `Req.auxiliary_swa_host_hit_length` is derived from the staged plan and flows into `needs_host_load_back` and `prepare_prefill`. When an idle adder rejects a staged request for capacity before `init_load_back` runs (prefill budget or load-back budget), the hold now goes through the existing bounded `defer_staged_admission` instead of being retried without limit.
- The Rust tree core keeps one SWA window: the adapter raises `NotImplementedError` when `swa_tombstone_ranges` / `attach_swa_window` are asked for another component type.
