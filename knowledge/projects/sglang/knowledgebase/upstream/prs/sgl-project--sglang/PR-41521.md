# [Perf] [Intel] dp: Routes all_gather_into_tensor and reduce_scatter_tensor to shm kernels

[Upstream PR](https://github.com/sgl-project/sglang/pull/41521) · state: open · merged: False

## Original PR description

## Motivation

#13397 added the CPU shm kernels `shm_allgather_into_tensor` and `shm_reduce_scatter_tensor` to sgl-kernel. #12961 routed CPU through `GroupCoordinator._all_gather_into_tensor` / `_reduce_scatter_tensor`, but left `TODO: add optimized ... kernel for cpu` and never called those kernels. So on CPU, the DP attention gather/scatter still went through `torch.distributed` (gloo).

This PR routes `all_gather_into_tensor` and `reduce_scatter_tensor` to shm kernels.

## Modifications

- `distributed/parallel_state.py`
  - `_all_gather_into_tensor`: on CPU, call `sgl_kernel.shm_allgather_into_tensor` when `is_shm_available(dtype, world_size, local_size)` holds.
  - `_reduce_scatter_tensor`: on CPU, call `sgl_kernel.shm_reduce_scatter_tensor(..., REDUCE_OP_SUM)` under the same condition.
  - Remove the two TODOs left by #12961.
  - If the condition does not hold (no AMX or arm64, dtype outside bf16/fp16/fp32, or multi-node), fall back to gloo as before.
- `model_executor/cpu_graph_runner.py`: register fake impls for both ops. They mutate `output` in place and return nothing, like `shm_allreduce`, so `--enable-torch-compile` works on CPU.

- ch-wan · comment · 2026-09-30T03:48:02Z · [source](https://github.com/sgl-project/sglang/pull/41521#discussion_r4140624621)

File: `python/sglang/srt/distributed/parallel_state.py` · line 1153

**[bug]** This new call site has no size guard, but `shm_reduce_scatter_tensor` is not safe for tensors larger than the SHM workspace. In `python/sglang/kernels/aot/csrc/cpu/shm.cpp`, `MAX_BUF_SIZE` is 32 MiB and `reduce_scatter_outer_loop` walks the **input** byte range with that stride while advancing `output.data_ptr()` by the same offset. Output is `input.numel() / world_size`, so a second chunk writes past the end of `output` and slices the wrong ranks. That is a copy of the in-place allreduce loop, which is valid only because allreduce input and output are the same buffer. `shm_allgather_into_tensor` chunks correctly (rank `i` lands at `i * input_nbytes`); reduce-scatter does not. `test/registered/cpu/test_comm.py` only uses `(world_size * 4, 10)`, so it cannot catch this. CPU DP-attention decode stays under 32 MiB, but prefill reduce-scatter of the gathered hidden states does not: e.g. 8k tokens, hidden 4096, bf16, tp=4 is 256 MiB of input.

**Suggestion:** Do not call the kernel until `reduce_scatter_outer_loop` chunks by the per-rank output (or by `world_size`-aligned input slices) instead of treating `output` as input-sized. Until that lands, fall back to `reduce_scatter_single` when `input.numel() * input.element_size() > 32 * 1024 * 1024`. Add a `test_comm.py` case with input nbytes `> MAX_BUF_SIZE` compared against `dist.reduce_scatter_tensor`.
