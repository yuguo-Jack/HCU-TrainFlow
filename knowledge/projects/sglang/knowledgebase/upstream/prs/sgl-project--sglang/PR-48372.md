# [Fix] scheduler, multimodal: Fix embedding over-length hang, cap CPU pool, fix ST6 reference

[Upstream PR](https://github.com/sgl-project/sglang/pull/48372) · state: open · merged: False

## Original PR description

## Motivation
Three backend-independent bugs found while fixing test timeouts:
1. An embedding prompt that fits the context length but not the KV pool fails validation but is never finished, so the request hangs until the client times out.
2. The multimodal CPU preprocess pool defaults to `os.cpu_count()` fork workers, all started on the first request. On a 512-core host that request overruns its timeout.
3. With sentence-transformers 6, the HF reference in `test_embedding_models` is wrong: plain text goes through the chat template, and the non-ST branch is not causal (the kwarg was renamed).

## Modifications
- `scheduler.py`: `set_finish_with_abort` when embedding length validation fails, as the generate path does.
- `base_processor.py`: default pool size `min(os.cpu_count(), 16)`. `SGLANG_CPU_WORKERS` still overrides it. Changes the default only on hosts with more than 16 cores.
- `test/runners.py`: on sentence-transformers >= 6, drop the chat-template modality and pass `is_causal` under the new kwarg name. No-op below v6.
- New tests: `test_embedding_length_validation.py` (regression for 1) and `test_base_processor_cpu_pool.py` (CPU unit test for 2).

## Accuracy Tests
No model-output change. Tested on Intel Arc Pro B60 (no CUDA run yet):
- `test_embedding_length_validation`: passes; without the fix it fails with `ReadTimeout`.
- `test_base_processor_cpu_pool`: passes; fails without the fix.
- `test_embedding_models` (`test_prefill_logits`, `test_embedding_encoding_format`, sentence-transformers 6.0.1): pass.
- LLaVA `test_vision_openai_server_a` (video_images, multi_images): pass.
