# [Refactor] moe: Scope shared-expert configuration to each model

## Motivation

Shared-expert fusion determines expert weights, router widths and capture buffers for the lifetime of a loaded model. Resolving the count in each MoE block and passing it through intermediate constructors duplicates that decision; storing target/draft copies in process flags adds a separate restoration protocol.

Resolve the layout once, keep its related quantities together, and expose the active model's configuration during construction and execution.

## Modifications

- Add frozen `SharedExpertsConfig`, owned by the loader-created model. It contains the resolved fusion decision, fused expert count and Waterfill policy. Its `num_shared_topk_slots` property is zero when Waterfill writes the shared slots later, otherwise the fused count.
- Expose that object through the runtime-only `get_model().shared_experts` leaf. The loader scopes construction; runner boundaries scope eager execution, warmup, capture and replay, including direct draft graph paths. Existing bag overrides restore nested and exceptional exits. Model replacement reads the replacement model's configuration.
- TopKConfig and HashTopK retain the same immutable object. Selecting another model cannot resize existing layers or graphs. Remove the fusion/count active/speculative flags and their manual save/restore.
- Resolve fusion only when an entry class declares both its veto and `num_fusable_shared_experts` capability. Model families and wrapper entry classes supply the appropriate hooks. MoE blocks and weight loaders read the resolved count at construction.
- Size routed-experts capture from the supplied model's configuration, including wrapper entry models, independently of the ambient binding.
- Retain `FusedMoE`'s count argument with its shape inputs. Qwen-family gated shared-expert fusion remains block-local.
- Update the runtime-context skill and behavior tests for target/draft alternation, nesting, failures, model replacement, direct capture and compiled reads.

### API changes

`TopK.top_k` counts routed experts only and its `num_fused_shared_experts` argument is removed. HashTopK parameters after `num_experts` are keyword-only. Model integrations declare `num_fusable_shared_experts` alongside their fusion veto instead of overriding `determine_num_fused_shared_experts`. TopKConfig receives `shared_experts`, with the ordinary slot count exposed as a read-only property.
