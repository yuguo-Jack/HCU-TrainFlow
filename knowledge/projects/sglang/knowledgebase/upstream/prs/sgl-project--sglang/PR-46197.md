## Motivation

<!-- Describe the purpose and goals of this pull request. -->
The SM107 custom all-reduce table (#36397) was tuned before `2shot_push` existed. #42811 added `2shot_push` later but retuned only the SM100 rows, so SM107 never enables it. Above the 1shot_push ceiling, SM107 sizes fall through to `2shot_pull` (TP4 graph) or multicast `2shot_pull` (TP4 eager, TP8, TP16).

On SM107, a per-algorithm sweep shows `2shot_push` is the fastest custom algorithm from about 1 MB (TP4), 384 KB (TP8) and 256 KB (TP16) up to 16 MB. Every other threshold in the #36397 table lines up with the sweep to within one size step.

## Modifications

<!-- Detail the changes made in this pull request. -->
`_sm107_configs` (`configs/custom_all_reduce_v2.py`) only:

- `config()` takes an optional `two_shot_push=` threshold, the same keyword the SM100 table uses. It defaults to 0 (disabled), so worlds that don't set it are unchanged.
- **TP4**: 1shot ceiling 6.938 MB (graph) / 9.812 MB (eager) becomes 1 MB, then `2shot_push` up to 16 MB. The eager multicast range is untouched; it is only reached above 16 MB.
- **TP8**: 1shot ceiling 2.438 MB becomes 384 KB, then `2shot_push` up to 16 MB.
- **TP16**: 1shot ceiling 832 KB becomes 256 KB, then `2shot_push` up to 16 MB.
- **TP2** is unchanged: `2shot_push` never wins there. TP3/5/6/7 are not tuned and keep their #36397 rows.

`test_custom_all_reduce.py::test_custom_all_reduce_eager_plan_follows_config` zeroes every threshold to force the NCCL path. It now also zeroes `two_shot_push_threshold`; otherwise the size still routes to `2shot_push` on any arch whose table enables it.

## Speed Tests and Profiling

<!-- If this pull request impacts inference speed, provide benchmarking and profiling results. -->

The method follows #42811:
- bf16 input.
- One CUDA graph of 100 back-to-back all-reduces; median of 9 replays; max over ranks.
- Eager mode is the eager dispatch path captured without `comm.capture()`, so staging copies are included and Python launch overhead is not.
- Ranks are aligned on the GPU (a tiny NCCL all-reduce) right before each timed replay.
- Per-algorithm columns are forced through `override_algo`; multicast `2shot_pull` is forced with a temporary heuristic.
- "today" and "this PR" are the tuned tables run end to end (`auto`).

TP4: 1 node. TP8 / TP16: 2 / 4 nodes on one NVLink domain (MNNVL). µs per call.
