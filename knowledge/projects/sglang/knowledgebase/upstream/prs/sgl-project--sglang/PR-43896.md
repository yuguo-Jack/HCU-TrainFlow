# [Scheduler] Answer request-holder questions through named queries

[Upstream PR](https://github.com/sgl-project/sglang/pull/43896) · state: open · merged: False

## Original PR description

Stacks on #43895

- New `scheduler_components/request_queries.py`: one accessor per request holder (waiting, running, chunked, grammar, PD queues, PP micro-batches, dLLM, HiSparse staging) and named queries composed from them: `is_idle`, `is_idle_for_health_check`, `is_idle_for_flush`, `inflight_reqs`, `weight_version_reqs`, `retract_on_pause_reqs`, `owning_row_reqs`, `sampling_mask_reqs`.
- `Scheduler.is_fully_idle(for_health_check, ignore_waiting)` and `collect_inflight_reqs` are removed; each caller uses the query with its existing scope, so no flag selects a scope.
- `SGLANG_DEBUG_REQUEST_MEMBERSHIP=1` (off by default) asserts at the top of each iteration that no request sits in two membership containers.

No behavior change.
