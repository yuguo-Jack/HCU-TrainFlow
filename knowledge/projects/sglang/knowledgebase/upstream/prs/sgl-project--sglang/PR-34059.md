# [KDA] End-to-end context-parallel prefill for hybrid linear models (contiguous strategy)

[Upstream PR](https://github.com/sgl-project/sglang/pull/34059) · state: open · merged: False

## Original PR description

This PR makes prefill CP work end to end for KDA hybrid linear models (Kimi-Linear / Kimi-K3 family) via a new `--cp-strategy contiguous`:

- **KDA state hand-off (op layer)**: FLA KCP's two-pass parallel scan ported to serving semantics — pool-slot seeding, chunked-prefill continuation, zero-communication global final state — plus a conv-halo exchange for the short conv. Serial scan depth per layer drops from `T/64` to `T/(64 W)`.
- **Serving integration**: `ContiguousCPStrategy` (one contiguous block per rank — the layout linear layers need), the KDA backend CP branch, and the `LayerCommunicator` port of `KimiDecoderLayer`.
- **Two upgrades to the shared MLA-CP machinery found necessary along the way**: `attn_tp x cp` generality (any `attn_cp` dividing `tp`), and a dispatch fix routing CP prefill through **MHA one-shot instead of absorbed MLA** — a 3.4x-flops formulation mismatch that dominated CP TTFT (cut ~2x by the fix; DeepSeek-family models under the contiguous strategy share the code). The target deployment is **cross-node CP** — TP intra-node, CP across the fabric, where the KDA hand-off's length-independent ~4 MiB/layer collective shines (see "Where the payoff lands").
- **Validation**: kernel-level bitwise vs the sequential shard chain, real-NCCL 2-GPU check, E2E server compare at `attn_tp1 x cp4` and `attn_tp2 x cp2`, GSM8K accuracy-neutral (0.903 vs 0.896 baseline), non-CP serving byte-identical.

## Motivation

KDA linear-attention layers are the remaining gap in prefill context parallelism for hybrid models (Kimi-Linear-48B: 3:1 KDA:MLA; Kimi-K3: 69 KDA + 24 MLA layers, 1M context). Prefill CP already covers the dense side (MLA #23292, SWA, MHA/GQA — roadmap #21788), but the KDA layers have no sequence-dimension parallelism at all: their recurrent state is one fixed-size matrix per request with no position axis to shard.

The pain is concrete:

- The inter-chunk state recurrence (`chunk_gated_delta_rule_fwd_h`) is a serial per-CTA loop over `T/64` chunks with only `(V/BV) x num_seqs x H/TP` CTAs of parallelism — Kimi-Linear at TP8 puts **16 CTAs on a 132-SM GPU**, and a 1M-token prompt walks **16384 serial chunk steps per layer**. Adding TP makes per-rank occupancy *worse* while the serial depth stays constant.
- Enabling `--enable-prefill-cp` on a hybrid linear model today does not fail — the CP-v2 runner would hand each rank a token shard and the recurrent state would be **silently corrupted**.

This PR ports flash-linear-attention's KCP design to sglang's serving semantics, as the foundation for hybrid prefill CP. A survey of the available implementations shows KCP is the only production reference for *distributed* linear-attention CP — the other candidates solve different problems:

| | distributed (multi-GPU) CP | intra-GPU chunk-parallel | serving state semantics |
|---|---|---|---|
| **flash-linear-attention** (`fla/ops/cp`, KCP, fla-org #691/#733/#740) | ✅ two-pass parallel scan | ✅ intracard CP (off by default) | ❌ `initial_state` / `output_final_state` assert-rejected (training-only) |
| **flashinfer** | ❌ (`parallel_attention/` Ulysses+Ring is softmax-attention-only) | ✅ `cp_delta_rule_dsl_sm90/120` ("CP" in name, single-GPU, zero NCCL calls) | ✅ KDA decode kernel has initial/final state + varlen |
| **FlashKDA** (MoonshotAI) | ❌ | ❌ | ✅ initial/final state + varlen (forward-only CUTLASS) |

So the math comes from KCP, and the serving-semantics gap (the ❌ in the last column of row 1) is exactly what this PR adds. CP divides the serial depth by the CP world size at the cost of **one all-gather of a sequence-length-independent buffer** per layer (~4 MiB fp32 per rank per layer at H=32, K=V=128; /TP with head sharding — Kimi-K3's 69 KDA layers total ~34 MiB per prefill step at TP8, microseconds on NVLink, negligible next to the dense layers' KV gather).

## Design

<img width="1824" height="1007" alt="image" src="https://github.com/user-attachments/assets/d730090e-8469-459a-8dfd-25812480d875" />

The inter-chunk recurrence of the chunked KDA forward,

```math
S_{c+1} \;=\; \big(\mathrm{Diag}(\gamma_c) - k^{g\top}_c w_c\big)\, S_c \;+\; k^{g\top}_c u_c \;=\; M_c\, S_c + S^{ext}_c,
\qquad M_c \in \mathbb{R}^{K\times K},\;\; \gamma_c = \exp_2\!\big(g_{c,\mathrm{last}}\big)
```

is **affine in $S$** ($\gamma_c$ is the per-K-channel gate at the chunk boundary; $k^g, w, u$ are the WY-transform tensors the main kernel already consumes). Affine maps compose, so each rank's whole contiguous shard collapses to ONE affine map

```math
S_{out}^{(r)} \;=\; M^{(r)} S_{in}^{(r)} + S^{ext,(r)},
\qquad M^{(r)} = \prod_{c=NT_r}^{1} M^{(r)}_c,
```

and the cross-rank serial dependency dissolves into three fully parallel phases (no ring, no rank-to-rank pipeline):

1. **Local pre-scan** (`cp_pre_scan_fwd_kernel`): each rank scans its shard with $S_0 = 0$, emitting the fused fp32 buffer $hm = [\,S^{ext} \mid M\,]$.
2. **One all-gather** of `hm` (`[N, HV, K, K+V]` per rank).
3. **Local merge** (`cp_merge_fwd_kernel`): each rank replays the tiny fp32 affine chain (each step is a $K{\times}K$ @ $K{\times}V$ matmul — cheap, redundant per rank by design); the prefix $h_0^{(r)} = \prod_{j<r} \mathrm{affine}_j(S_{seed})$ is this rank's entry state, then the existing chunked forward runs unchanged on the shard. The serial depth per layer drops from $T/64$ to $T/(64\,W)$ chunk steps.

<img width="1779" height="868" alt="image" src="https://github.com/user-attachments/assets/ae8642d6-46f1-4a09-a572-64a540162dc2" />

An empty shard (a sequence shorter than the CP world size) degenerates to the identity affine map $(0, I)$ — no special-casing in the merge.

### Serving-semantics extensions

<img width="1824" height="1039" alt="image" src="https://github.com/user-attachments/assets/8ddb0925-001b-462f-934e-bdc5e1988421" />


Three extensions over the FLA original (which asserts `initial_state is None` and `output_final_state=False` — training-only, incompatible with sglang's chunked prefill where the state lives in a mamba pool slot that seeds each scheduler step and receives the final state in place):

- **Pool-slot seeding**: the merge chain starts from the mamba pool slot, so CP composes with chunked prefill's carried state.
- **Full-chain merge => zero-communication final state**: after the all-gather every rank holds all $(M^{(j)}, S^{ext,(j)})$; replaying the chain over **all** $W$ ranks yields the global final state $S_{final} = \prod_{j<W} \mathrm{affine}_j(S_{seed})$, which every rank writes back to its own pool replica (CP ranks within a head shard all need it for decode). No broadcast, no last-rank special case.
- **Scratch h0 handoff**: the main kernel's `INPLACE_UPDATE` epilogue would clobber the pool state the merge just wrote, so the merge hands the main kernel a scratch `[N, HV, V, K]` tensor plus index mapping instead of the pool. Zero changes to the frozen main kernel.

Two hardening fixes found during bring-up (both inherited hazards, not present in FLA's tests because they only bite on busy GPUs / empty shards):

- **No `[K, K]` register-tile materialization**: FLA's stage-2 computes the transition product via a full `kg^T w` `[K, K]` intermediate held in registers (64 KiB fp32 per CTA at K=128), which spills to CUDA local memory; local memory is reserved for the max-resident thread count, so the launch demands GBs and **OOMs on GPUs with a few GB free**. Regrouped by associativity as $\mathrm{Diag}(\gamma)\,M - k^{g\top} (w\, M)$ — never materializes the $[K, K]$ intermediate, fewer FLOPs, same fp32 chain (pinned with `input_precision="ieee"` so tf32 cannot degrade the per-chunk product chain).
- **Empty-shard compaction contract**: `prepare_chunk_indices` attributes chunks to sequences by counting chunk-index resets, so a zero-length sequence in `cu_seqlens` silently shifts all following chunks onto the empty sequence — the intra kernels then early-return and `kg/w/u` stay **uninitialized memory**. `build_cp_shard_layout` therefore drops empty local shards and returns a `local_seq_ids` global mapping; absent sequences contribute the identity affine `(0, I)` to the all-gather and still receive their final-state writeback everywhere.

## Modifications

- `python/sglang/kernels/ops/attention/fla/chunk_delta_h_cp.py` (new): `LinearAttnCPContext`, `build_cp_shard_layout`, the pre-scan and merge Triton kernels, pure wrappers (`cp_local_transition` / `cp_merge_states`) and the `chunk_gated_delta_rule_fwd_h_cp_pre_process` orchestrator. Shares the `USE_G`/`USE_GK` constexpr split with the main kernel, so the same machinery covers GDN later.
- `python/sglang/kernels/ops/attention/fla/kda.py`: `chunk_kda` / `chunk_kda_fwd` accept `cp_context`; the pre-process runs between `chunk_kda_fwd_intra` and `chunk_gated_delta_rule_fwd_h`, receiving exactly the tensors the main kernel receives (kg/w/u and the log2-domain cumulative gate — the #1 correctness invariant from FLA's CP README).
- `python/sglang/srt/layers/attention/attention_registry.py`: hybrid linear models **reject** prefill CP at backend init with a clear error instead of silently corrupting state; the serving-stack wiring below then admits exactly the supported combination (KDA-backend models + contiguous strategy).
- `test/registered/attention/test_kda_cp_state.py` (new): single-GPU simulation of W CP ranks — `all_gather_into_tensor` is mocked with a record/replay double so the real end-to-end path runs per simulated rank, each with its own pool replica. Cases: CP4 fresh prefill, CP4 chunked-prefill continuation (non-zero seed), CP8 with empty shards, CP1 bit-exact passthrough, untouched-slot isolation.
- `test/manual/kda_cp_standalone_check.py` (new): dependency-light mirror of the CI test (imports only `sglang.kernels.*`) for boxes where the `sglang.test` import chain is unavailable; `test/manual/kda_cp_diag.py`: the CP fault localizer (`--mode cp`: per-rank h0 vs true boundary state, output shard vs reference slice) and the input-conditioning study that established the reference methodology and CI tolerances (`--mode numerics`).
- `python/sglang/srt/layers/attention/linear/kda_cp.py` (new, backend helpers): `KDACPPrefillMetadata` / `build_kda_cp_prefill_metadata` (compacted local cu_seqlens, global sequence mapping, and every rank's shard-length table — pure functions of the global extend lengths, so all ranks derive identical tables with no communication) and `exchange_kda_conv_halo` — the causal-conv counterpart of the SSM state hand-off: one all-gather of only the last `conv_width - 1` tokens of each shard per sequence, from which every rank locally assembles (a) its halo window (spanning as many earlier ranks / the carried pool window as needed) fed to `causal_conv1d_fn` as scratch conv states, and (b) the global tail window it writes into its own pool replica. Zero extra communication, mirroring the full-chain SSM merge.
- `python/sglang/srt/layers/attention/linear/kernels/kda_triton.py`: `TritonKDAKernel.extend` threads `cp_context` through to `chunk_kda` (the Triton path is the only CP-capable prefill kernel backend for now).
- `test/registered/unit/test_kda_cp_backend_helpers.py` (new): pins the window-assembly math (multi-rank reach-back when shards are shorter than the window, empty-shard compaction, zero-padding for fresh sequences, prior-window chaining, cross-rank global-tail agreement) against a direct full-token-stream reference.

## Op-layer validation

Verified on H20-3e (sm90). The correct reference is the **sequential shard chain** (running the shards one-by-one through the pool slot — exactly chunked-prefill semantics with the same per-shard chunk grids as CP); a monolithic single run differs from *any* re-chunked computation by a bf16 rounding baseline (~4e-3 with well-scaled inputs, measured independently of CP).

| case | CP vs sequential chain | CP vs monolithic |
|---|---|---|
| CP4 fresh prefill (lens 1000/704) | **bitwise identical (0)** | 3.3e-03 |
| CP4 continuation (non-zero seed) | 1.15e-06 | 2.6e-03 |
| CP8 with empty shards (lens 5/640) | 4.44e-04 | 3.1e-03 |
| CP1 passthrough | bitwise identical | — |

i.e. CP introduces **no error beyond what chunked prefill already has**, and every rank's pool replica lands the identical global final state.

## Serving-stack wiring

- `python/sglang/srt/layers/cp/contiguous.py` (new): `ContiguousCPStrategy` / `--cp-strategy contiguous` — one contiguous block per rank per sequence, built on zigzag's index-list-driven collectives with single-call attention geometry. This is the layout hybrid linear models need (zero relayout around the linear layers); dense/MLA layers keep the all-gather-KV attention path, trading zigzag's causal load balance for no relayout — the right trade when most layers are linear (69/93 on K3). Block boundaries match the KDA op layer's `build_cp_shard_layout`, so the backend derives its shard geometry independently with no communication.
- `KDAAttnBackend.forward_extend` CP branch (+ `ForwardMetadata.kda_cp` built in `MambaAttnBackendBase._forward_metadata`): shard-local compacted `query_start_loc`, conv seeded from halo windows exchanged across CP ranks into scratch conv states (the kernel's in-place writeback stays off the pool), the globally-assembled tail window written to every pool replica, and `cp_context` handed to the Triton chunk kernel for the SSM state merge. Mamba radix tracking and padded CP batches are rejected loudly for now.
- `kimi_linear.py`: KDA head sharding, projections, `dt_bias`/`A_log`, `qkv_conv1d` and `o_proj` move from `tp_size` to the attention-TP group (`kimi_k3`'s pattern; `o_proj` reduces within the attn-TP group via `use_dp_attention_reduce`); the fused qkvbfg path requires `attn_tp == tp` and falls back to the unfused projections under CP. Baseline serving of Kimi-Linear-48B at `attn_tp == tp` (tp4, H20-3e) regressed clean after the resharding.
- The registry guard now admits KDA-backend models (Kimi-Linear, Kimi-K3, and future registrations) with the contiguous strategy, and keeps rejecting every other hybrid linear combination.
- `test/manual/kda_cp_dist_check.py` (new): **real-NCCL verification on 2x H20-3e** — CP output bitwise-identical to the sequential chunked-prefill chain (fresh + continuation), final states 4.4e-08 norm ratio, conv halo bitwise against a full-stream reference.

## End-to-end serving

`KimiDecoderLayer` moves from hand-rolled norm/residual sequencing to the **LayerCommunicator** pattern (`DSACPLayerCommunicator` under prefill CP: the whole layer stays in the CP-scattered token layout and gathers only around the full-TP MLP region). Attention returns TP-partial outputs (`reduce_results=False` on the MLA layer and the KDA `o_proj`), and the decoder publishes `mlp_reduce_scatter` so `RowParallelLinear` / the fused MoE skip their own all-reduce — the CP postprocess **reduce-scatter** completes the TP reduction while scattering tokens back. (Getting this wrong is a subtle failure mode worth documenting: with the MLP still self-reducing, the reduce-scatter sums W identical complete copies — a per-layer W-fold amplification that produces *coherent but wrong* short generations and degenerate long ones.) Plus the serving-stack gaps found during bring-up: the CP hidden-state gather buffer is now sized unconditionally in `prepare_cp_forward` (previously skipped at `dp_size == 1`), the legacy CP mode aliasing accepts `contiguous`, and `KimiLinearModel.forward` takes the CP-v2 runner's `input_embeds` keyword. Both E2E harnesses ship as manual tests: `test/manual/kda_cp_server_compare.py` (greedy agreement + prompt-logprob deltas between a baseline and a CP server) and `test/manual/kda_cp_ttft_bench.py` (single-request TTFT, fresh random ids per run, warmup + median of 3).

**End-to-end verification** (Kimi-Linear-48B on 4x H20-3e, baseline `tp4` vs `tp4 + attn_cp4` contiguous):

| case | result |
|---|---|
| 5-token prompt, greedy 24 tokens | **24/24 identical tokens**, prompt-logprob mean delta 0.054 (1-2-token shards, boundary noise) |
| 4151-token prompt, greedy 48 tokens | prompt-logprob mean delta **1.5e-3** (the re-chunking bf16 noise level), identical generation up to a greedy near-tie at token 26 |
| non-CP regression | baseline generates **byte-identical** outputs pre/post the LayerCommunicator port |
| **GSM8K** (few-shot, 1319 questions, parallel 128) | baseline **0.896** vs CP **0.898** (invalid 0.000 both; matches the historical 0.898 baseline) — accuracy-neutral end to end |
| **MHA-under-CP re-validation** (post-dispatch-fix, see TTFT section) | `attn_tp1 x cp4` and `attn_tp2 x cp2`: 24/24 identical short greedy, 4151-token logprob mean delta 1.4e-3 / 1.2e-3; GSM8K **0.903** (invalid 0.000) |

GSM8K throughput under CP (1125 vs 2410 tok/s) is expected and out of scope for this comparison: the workload is short-prompt/decode-heavy (CP targets long-context prefill TTFT), `--disable-overlap-schedule` is currently required, and at `attn_cp == tp` the attention weights are replicated (no TP speedup on attention).

### attn_tp x cp generality

The MLA prefill-CP machinery originally required `attn_tp == 1` (attention weights fully replicated across CP ranks). This PR lifts it: `attn_cp` now carves any divisor of `tp`, with `attn_tp = tp / attn_cp` sharding attention heads inside each CP rank. The `DSACPLayerCommunicator` generalizes accordingly — an attn-TP all-reduce completes the partial attention outputs before the pre-MLP fused add-layernorm, and the post-MLP scatter becomes a full-TP all-reduce plus a `tensor_split(cp_size)` slice when `attn_tp > 1` (the `attn_tp == 1` fast path keeps the dedicated reduce-scatter). `attn_tp2 x cp2` is end-to-end verified in the table above alongside `attn_tp1 x cp4`.

### TTFT: finding and fixing the dominant CP overhead

With the state hand-off correct, the first TTFT measurements (absorbed-MLA CP path, default `chunked-prefill-size 8192`) showed CP **losing** to the TP baseline:

| prompt len | baseline tp4 | CP tp4 / attn_cp4 (absorbed) | ratio |
|---|---|---|---|
| 8k | 0.142 s | 0.273 s | 1.92x |
| 32k | 0.670 s | 1.464 s | 2.18x |
| 64k | 1.643 s | 4.032 s | 2.45x |
| 128k | 4.486 s | 12.559 s | 2.80x |

Controlled ablations ruled out the launch flags, chunk-count sensitivity, and projection/MoE FLOPs (provably identical per rank across configs); a per-kernel torch-profiler comparison of one 32k prefill (rank-0 GPU time: base 0.190 s vs cp2 0.463 s) attributed the gap:

| kernel group | base | cp2 | delta |
|---|---|---|---|
| FlashAttention MLA prefill | 63 ms | **207 ms** | **+145 ms (53%)** |
| NCCL all-gather (CP hidden/KV) | ~0 | 66 ms | +66 ms (24%) |
| KDA CP pre-scan + merge | 0 | 47 ms | +47 ms (17%) |
| KDA serial scan | 5.2 ms | 2.7 ms | −2.5 ms (the intended win) |
| MoE + projections | ~81 ms | ~87 ms | ≈0 (FLOPs parity confirmed) |

**Root cause — a formulation mismatch, not a kernel problem.** The trace's CPU-op records show the two paths were not running the same attention formulation at all: the baseline prefill runs **MHA one-shot** (`q [T, H, 192]` against materialized ragged `k [KV, H, 192] / v [KV, H, 128]`), while the CP path was forced onto **absorbed MLA** (`q_rope [T, H, 64] + qv [T, H, 512]` against the paged latent pool) by an explicit gate in `attention_backend_handler.py` ("MLA prefill CP forces absorbed MLA"). Absorbed attention works in the `(kv_lora_rank + rope) = 576/512` latent space — **2176 flops per query-key pair vs MHA's 640, a 3.4x ratio**. Both invocations actually run at ~130 TFLOPS (~88% of H20-3e bf16 peak): 9.0 ms/layer baseline vs 29.6 ms/layer CP is exactly the flops ratio at ~0.93x the pairs, with zero kernel-time overlap from NCCL (verified against the trace timeline). The same forced-absorbed gate applies to the existing zigzag/DeepSeek CP flavor.

**The fix (this PR): MHA one-shot under contiguous CP.** Queries are already rank-local, and the latent pool is fully populated by the same `materialize_full_mla_kv` all-gather the absorbed path runs — so each rank can up-project its causal window `[0, prefix + blocks <= rank)` from the pool and call the identical one-shot varlen kernel, with geometry straight from the strategy metadata (`cu_seqlens_q_prev` / `cu_seqlens_kv_prev`; `causal=True` bottom-right aligns each rank's query block to its window end). The dispatch gate now returns `MHA_ONE_SHOT` for contiguous-strategy fa3 prefill CP whenever the full window fits `SGLANG_MAX_KV_CHUNK_CAPACITY` (uniform across ranks); zigzag and other backends keep absorbed MLA (zigzag's per-rank queries are two disjoint blocks — porting it is a follow-up that would hand the same win to DeepSeek CP deployments). Touched: the dispatch gate (`attention_backend_handler.py` + `cp_utils.mla_prefill_cp_use_mha_one_shot`), the CP branch in `forward_mha.py::forward_normal_prepare` (latent gather + windowed fetch), `ForwardBatch.fetch_mha_one_shot_kv_indices_cp`, and the contiguous-CP one-shot call in `flashattention_backend.py`. Since `KimiMLAAttention` *is* `DeepseekV2AttentionMLA`, the same code serves DeepSeek-family models under the contiguous strategy.

Result (`chunked-prefill-size 32768` everywhere; same bench):

| prompt len | baseline tp4 | CP absorbed (cp2) | **CP MHA (cp2)** | **CP MHA (cp4)** |
|---|---|---|---|---|
| 64k | 1.489 s | 3.944 s (2.65x) | **2.036 s (1.37x)** | **1.980 s (1.33x)** |
| 128k | 4.091 s | 12.155 s (2.97x) | **5.309 s (1.30x)** | **5.155 s (1.26x)** |

The dispatch fix alone cuts CP TTFT by **1.9x (64k) to 2.3x (128k)**.

The dominant term is gone; the remaining ~30% gap is the CP collectives (all-gathering latent KV + hidden states each layer), the KDA pre-scan/merge (which at small W cancels its own scan saving by construction), and the per-rank KV up-projection (each rank up-projects its window at its local head count — inherent to converting TP ranks into CP ranks). **Follow-ups in priority order**: (1) fuse/batch the CP collectives (RS+AG instead of AR+slice, batch the per-layer `hm` gathers), (2) fuse the KDA pre-scan into the main chunk kernel, (3) port MHA-under-CP to the zigzag strategy (benefits DeepSeek CP), (4) a chunked-KV variant for windows beyond the one-shot capacity (>128k tokens per rank window today falls back to absorbed). This PR's scope — the state hand-off machinery, `attn_tp x cp` generality, the MHA-under-CP dispatch, accuracy-neutral end-to-end serving — is the foundation those optimizations build on.

### Where the payoff lands: cross-node CP

<img width="2577" height="1167" alt="image" src="https://github.com/user-attachments/assets/5a37b2a7-e82c-4cd2-959c-b4dacb88a06c" />


The single-node numbers above are deliberately CP's **hardest** comparison: converting NVLink TP ranks into CP ranks trades away GEMM sharding at equal GPU count, and every CP collective is priced at NVLink bandwidth the TP baseline also enjoys. The deployment this PR is built for is scaling long-context prefill **across nodes**, where each term of that trade flips:

- **TP stops scaling at the node boundary; CP is the axis that adds nodes.** Cross-node TP puts a T-proportional, blocking activation all-reduce per layer on a link ~10x slower than NVLink. With `attn_tp = tp / cp`, the CP group boundary can be drawn exactly at the node boundary (`tp16 = attn_tp8 x cp2` on 2x8 GPUs): all TP collectives stay on NVLink, and only the CP collectives cross the slow link — this is precisely what the `attn_tp x cp` generality above buys.
- **The KDA hand-off is tailor-made for slow links.** Its only communication is the per-layer `hm` all-gather, whose size is **independent of sequence length** — ~4 MiB fp32 per rank per layer (H=32, K=V=128, /TP with head sharding), the same at 1M tokens as at 8k; Kimi-K3's 69 KDA layers total ~34 MiB per prefill step across the link. The dense layers' latent-KV gather does scale with T, but it is a one-shot per-layer gather (7 of 27 layers on Kimi-Linear), not a per-layer blocking all-reduce of full activations.
- **The serial scan is the axis TP cannot divide at any size.** A 1M-token prompt is 16384 serial chunk steps per KDA layer whether tp is 8 or 16 — more TP only lowers per-rank occupancy of the scan kernel. CP is the only parallelism that divides the depth (T/(64W)), and it divides every other per-rank T term with it: attention pairs, MoE/projection tokens, activation and KV memory — including contexts that simply do not fit a single node.

So the honest reading of the TTFT table is: at equal GPUs on one node, CP costs ~1.3x; across nodes, the alternative to CP is not `tp4` — it is a T-proportional all-reduce over the inter-node fabric, or not serving the context at all. Cross-node measurement (2x8 H20/H800, `attn_tp8 x cp2`, 256k-1M prompts) is the next validation milestone.


## Limitations / follow-ups

- `attn_tp x cp` combinations are supported (`attn_tp = tp / attn_cp`), except `attn_tp > 1` with a SCATTERED-layout MLP, which raises `NotImplementedError` (no model hits it today).
- MHA-under-CP applies to the **contiguous strategy on fa3** with the rank's full KV window within `SGLANG_MAX_KV_CHUNK_CAPACITY`; beyond that (or on zigzag / other backends) prefill CP falls back to absorbed MLA. The zigzag port and a chunked-KV variant are follow-ups.
- Mamba radix tracking under CP is rejected loudly (`--mamba-radix-cache-strategy no_buffer` required, which in turn requires `--disable-overlap-schedule`).
- `KimiLinearForCausalLM` is not yet in `CP_V2_DEFAULT_MODEL_CLASSES` (CP-v2 is enabled via `SGLANG_ENABLE_CP_V2=1`); auto-enablement plus a multi-GPU CI test and GSM8K accuracy runs are the graduation criteria.
- The merge kernel holds a full `[K, K]` transition tile (K <= 128 asserted; K=V=128 covers Kimi-Linear/K3 and GDN models).
- Backward is out of scope (inference-only port).
