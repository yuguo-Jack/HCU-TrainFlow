# [CI] slash-command: Add /run-cpu-ci to run only the CPU unit suite

[Upstream PR](https://github.com/sgl-project/sglang/pull/45501) · state: closed · merged: True

## Original PR description

## Motivation

Small PRs often only need the CPU unit suite plus the tests of the module they touch. Today the CPU suite only runs as part of a full `run-ci` round, and `/rerun-group unit` is not a substitute: it expands to all ~1000 files under `test/registered/unit/`, dispatches the ~110 CUDA-registered ones to GPU runners, and its reply comment (~79 KB of commands) exceeds GitHub's 65,536-character comment limit.

## Modifications

- New `/run-cpu-ci` slash command (alias `/rerun-cpu-ci`). It dispatches a new `run-cpu-ci.yml`, which reuses `_pr-test-check-changes.yml` and `_pr-test-stage-cpu.yml`, so `base-a-test-cpu` is partitioned and run exactly as in PR CI (13 shards today, continue-on-error), with no `run-ci` label and no GPU stage. Intended usage for a small PR: `/run-cpu-ci` + `/rerun-group <module>`.
- The workflow is always dispatched on `main` with the PR head SHA as an input (fork and in-repo PRs alike), so the workflow definition is main's and only the code under test comes from the PR. That code runs on hosted runners with a read-only token and no inherited secrets, the same exposure as `/rerun-test` cpu mode. Gated the same way as `/rerun-test` (`cooldown_interval_minutes: 0` or write permission), plus the MIN_BASE_SHA pre-dispatch check.
- `_pr-test-stage-cpu.yml` gets a `skip_cache_save` caller input. A run on main's ref that executes PR code would otherwise save the HF / Rust caches under main's scope, where main and every PR restore them. `pr-test.yml` and `weekly-test-cpu.yml` don't pass it, so their behavior is unchanged.
- No prebuilt Rust extension artifact: its compile job runs on a self-hosted build node, so the stage falls back to its cache (about 7 min per shard on a cold cache).
- Docs: contribution guide, `ci-workflow-guide` skill, `.github/FOLDER_README.md`.

## Checks

- `py_compile`, pinned `isort` 7.0.0 / `ruff format` 0.15.1 / `codespell` clean; `actionlint` clean on the three changed workflows (it validates the `with:` keys against the local reusable workflows).
- Handler exercised against mocked GitHub objects: dispatch for write and cooldown-0 users (`ref: main`, `git_ref: <head sha>`), refusal for read-only users, the rebase gate, and a non-2xx dispatch; `/run-cpu-cl` gets a "did you mean `/run-cpu-ci`" hint.
- `compute_partitions.py --pr-test-yml .github/workflows/pr-test.yml` yields `base-a-test-cpu` with 13 shards, which the new workflow consumes.
- Not exercised: a real dispatch. `workflow_dispatch` needs the file on the default branch, so the first live run is a `/run-cpu-ci` comment after merge.
