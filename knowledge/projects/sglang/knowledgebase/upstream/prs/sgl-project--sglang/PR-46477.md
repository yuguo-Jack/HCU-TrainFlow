# [Fix] attention: Use draft forward width for DSpark FA backend

[Upstream PR](https://github.com/sgl-project/sglang/pull/46477) · state: open · merged: False

## Original PR description

## Motivation

For DSpark draft checkpoints with `sample_from_anchor=False`, the draft forwards γ + 1 rows per request (anchor + γ draft positions), but `FlashAttentionBackend` sized its per-request query width with the generic target-verify helper, which returns `num_draft_tokens - 1` for DSpark draft workers. That under-sized `cu_seqlens_q` whenever batch size > 1 (γ = 7, batch 2: `[0, 7, 14]` instead of `[0, 8, 16]`), silently degrading draft acceptance as batch size grew. The issue reports (from the reporters' H100/FA3 measurements, not re-measured here) tokens/verify falling from 3.01 at batch 1 to 1.27 at batch 64 before the fix, versus a flat 3.03 after it.

Fixes #46476.

## Modifications

- `python/sglang/srt/layers/attention/flashattention_backend.py`: the draft-worker branch now takes its width from `ModelRunner.decode_num_tokens_per_req()` instead of independently deriving a target-verify width. That is the shared source of truth the Triton backend already uses for its `target_verify_num_tokens_per_req`: it returns `num_draft_tokens` for DSpark drafts with `sample_from_anchor=False` and falls back to the target-verify width otherwise, so target workers and non-DSpark algorithms are unaffected. FA3 and FA4 share this backend class, so both are covered. The now-unused `SpeculativeAlgorithm` / `resolve_num_tokens_per_req` imports are removed.
- `test/registered/unit/layers/attention/test_flashattention_dspark_draft_width.py` (new, CPU): covers the width contract — DSpark draft widths for `sample_from_anchor=False` (γ + 1) and `True` (γ), target workers and EAGLE unchanged, the backend constructor wiring, and `cu_seqlens_q` for batches 2 and 8 against the flattened query length. The CUDA-graph metadata builds its `cu_seqlens_q` from the same `speculative_num_draft_tokens` field, so it inherits the corrected width.

## Accuracy Tests

New CPU unit tests (6 tests): `test_flashattention_dspark_draft_width.py` — all pass. Existing neighboring tests re-run clean: `test_model_runner_decode_rows.py` and `test_flashattention_graph_metadata.py` (6 tests, 1 pre-existing CUDA-gated skip). No GPU was available in this environment, so FA3/FA4 kernel-level verification is left to CI; the eager metadata assertions above are pure shape arithmetic on the same field the kernels consume.

## Speed Tests and Profiling

No benchmark re-run here (no GPU in this environment); the throughput figures quoted in Motivation are the issue reporters' measurements. This change only corrects metadata shapes and is not expected to change kernel performance characteristics.
