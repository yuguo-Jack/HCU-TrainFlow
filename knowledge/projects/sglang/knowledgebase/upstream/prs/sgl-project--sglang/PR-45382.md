## Motivation

DLite predicts a linear block of draft tokens from the target model's current
multi-layer hidden states without maintaining a draft KV cache. This PR adds
native SGLang inference support for the released Qwen3-4B `dlite_v1` and
Qwen3-8B `dlite_v2` checkpoints.

The initial scope is NVIDIA CUDA, Qwen3 targets, and greedy decoding. It
supports tensor parallelism, ordinary overlap scheduling, and target verify
CUDA Graphs.

The original repository is: https://github.com/SJTU-DAI-Sys/DLite.

<!-- Describe the purpose and goals of this pull request. -->

## Modifications

- Register the `DLITE` speculative algorithm and add startup validation and
  default argument resolution.
- Add the DLite draft model, checkpoint parser, v1/v2 compatibility handling,
  and released-checkpoint role aliases.
- Capture the configured target-layer hidden states and relay them to a
  history-free DLite draft worker.
- Implement linear-block drafting, greedy target verification, accepted-token
  commit, target KV-cache rollback, and overlap-scheduler state relay.
- Support the released v2 query-position offset and checkpoint-defined
  `block_size`.
- Integrate DLite with tensor parallel execution, target verify CUDA Graphs,
  attention backend setup, and auxiliary hidden-state capture.
- Reject unsupported request modes before model execution. Stochastic requests
  and `return_hidden_states` return HTTP 400 without terminating the scheduler.
- Reject unsupported server configurations such as PDMux, pipeline
  parallelism, DP attention, context parallelism, disaggregated serving,
  two-batch overlap, adaptive drafting, mixed chunked prefill, and quantized
  draft checkpoints.
- Add focused model, worker, utility, registry, and request-admission tests.
- Document the deployment command, supported checkpoints, and current
  limitations.

Example deployment:

```bash
python3 -m sglang.launch_server \
  --model Qwen/Qwen3-8B \
  --speculative-algorithm DLITE \
  --speculative-draft-model-path SJTU-DAI-Sys/Qwen3-8B-DLite
```

## Accuracy Tests


Validation was performed on NVIDIA H20 using the existing environment without
upgrading Torch or other system packages:

- Python 3.12.3
- PyTorch 2.13.0+cu130
- Transformers 5.12.1
- sgl-kernel 0.4.9

| Test | Result |
|---|---:|
| Focused DLite unit suite | 84 passed, 26 subtests passed |
| Qwen3-4B DLite v1 eager | PASS |
| Qwen3-4B overlap + target verify CUDA Graphs (BS 1-8) | PASS |
| Qwen3-4B concurrency test | 20/20 requests passed |
| Qwen3-4B TP=2 eager | PASS |
| Qwen3-8B DLite v2 eager | PASS |
| Invalid-request isolation | HTTP 200 / 400 / 400 / 200; health remained 200 |

For the Qwen3-8B v2 equivalence survey, DLite and target-only greedy decoding
were exactly equal for 16 of 20 prompts over 48 output tokens. Each of the four
first divergences occurred at an exact BF16 top-logit tie in at least one
execution path; no clear-margin first-token divergence was observed.

The request-admission regression tests also verify that unsupported DLite
requests are returned directly to the client and never enter the generation
queue.

## Speed Tests and Profiling


The controlled benchmark used one NVIDIA H20, greedy decoding, 256 generated
tokens per request, ordinary overlap scheduling, target CUDA Graph decode
shapes through batch size 8, disabled radix caching, and three complete runs
per configuration.

| Model | Concurrency | Target-only tok/s | DLite tok/s | Throughput speedup | E2E speedup |
|---|---:|---:|---:|---:|---:|
| Qwen3-4B | 1 | 279.80 | 355.00 | 1.269x | 1.269x |
| Qwen3-4B | 2 | 548.04 | 679.49 | 1.240x | 1.264x |
| Qwen3-4B | 4 | 1,055.79 | 1,315.48 | 1.246x | 1.269x |
| Qwen3-4B | 8 | 2,009.47 | 1,906.43 | 0.949x | 0.994x |
| Qwen3-8B | 1 | 176.94 | 336.25 | 1.900x | 1.902x |
| Qwen3-8B | 2 | 347.88 | 611.68 | 1.758x | 1.807x |
| Qwen3-8B | 4 | 678.43 | 1,034.24 | 1.524x | 1.589x |
| Qwen3-8B | 8 | 1,321.92 | 1,407.54 | 1.065x | 1.113x |

DLite primarily improves low-to-medium-concurrency decode. The Qwen3-4B
configuration regresses by 5.1% at concurrency 8 because target-only batching
already amortizes weight reads while the eager draft path and block
bookkeeping remain visible overhead.

At concurrency 1, TTFT increased from 11.94 ms to 19.65 ms for Qwen3-4B and
from 12.47 ms to 22.29 ms for Qwen3-8B. The end-to-end gain comes from
multi-token decode and is best amortized by sufficiently long responses.
