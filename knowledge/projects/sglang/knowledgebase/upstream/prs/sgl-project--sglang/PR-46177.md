# [Fix] jit: Fix permanent cache misses behind a symlinked cache dir

[Upstream PR](https://github.com/sgl-project/sglang/pull/46177) · state: open · merged: False

## Original PR description

## Motivation

When the JIT cache dir or one of its parents is a symlink, the build cache never hits for header-only modules (the `load_jit` default): every new process compiles them again. Found with the cache on a Modal volume, which Modal mounts behind a symlink.

`_to_entries` resolves each dependency but checks it against the unresolved `build_dir`, so the generated `cuda.cu` or `main.cpp` in `.staging-<uuid>/` is recorded in `sgl_deps.json` instead of dropped. `_publish` then renames the staging dir to the leaf, the recorded file is gone, and `find_prebuilt` skips the leaf. A relative `SGLANG_JIT_CACHE_DIR` has the same problem.

## Modifications

- `cache.py`: `_to_entries` resolves `build_dir` before comparing. For an absolute cache dir without symlinks this is the same path, so existing caches keep hitting.
- `test_jit_cache.py`: a CPU regression test that reaches the build dir through a symlink in `tmp_path` and passes the generated unit as the relative `cuda.cu` the depfile records. `python3 test/registered/unit/kernels/test_jit_cache.py` gives 1 failed, 42 passed on `main` and 43 passed with this change.

## Accuracy Tests

Not applicable: no kernel or model output changes.

## Speed Tests and Profiling

On Modal, the first Marlin MoE call took 226 to 317 s in every container, and about 1 s with the cache dir passed through `os.path.realpath`.

On CPU (macOS), loading a header-only C++ module in three processes with the cache dir behind a symlink compiled it three times on `main`, with each later load logging `Rebuilding JIT module ...: abs:.../.staging-<uuid>/main.cpp changed` under `SGLANG_JIT_CACHE_DEBUG=1`. With this change it compiled once and the next two loads hit.
