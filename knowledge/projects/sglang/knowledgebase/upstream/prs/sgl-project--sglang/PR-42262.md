# [Fix] deepseek-v3.1: Parse coalesced streaming tool calls

[Upstream PR](https://github.com/sgl-project/sglang/pull/42262) · state: open · merged: False

## Original PR description

## Motivation

DeepSeek V3.1 streaming tool calls depend on how the output is chunked. With two complete calls in one increment, the greedy name match spans both calls. With the first header delivered separately, the second call's arguments can instead be attached to the first tool. A complete single call can lose its arguments as well.

For example, `weather({"city":"Tokyo"})` followed by `search({"query":"cafes"})` parses correctly when headers and arguments arrive separately, but not when the calls share one increment. The serving layer's final argument flush does not recover the lost/wrongly attributed arguments.

The first-chunk argument issue was previously reported in the closed, unmerged #18236; credit to @momaek. This change also fixes the coalesced multi-call case and adds regressions.

## Modifications

- Bound the function name at the first tool separator.
- Process arguments in the same increment that emits the name.
- Drain completed calls in order; retain a JSON-complete call until its end marker arrives so the next call cannot inherit its state.
- Add nine CPU-registered tests covering coalesced calls, partial arguments, repeated names, delayed end markers, empty arguments, and existing sequential/non-streaming behavior.

## Accuracy Tests

Local native Windows CPU component validation:

- Nine added regression tests pass, including every internal split of the second call's argument JSON. The unchanged detector fails this test set.
- Five source-bound wrapper/final-SSE-flush probes pass after the fix; only the sequential control passes before it.
- Ruff 0.15.1 checks/format, isort 7.0.0 with black profile, and `git diff --check` pass. Upstream `collect_tests` accepts the CPU registration/main entry.

The local harness imports the complete detector/base/utils/protocol modules, bypasses package initializers, and executes unchanged extracted test helpers and wrapper/flush methods. This is **not** a full installed-package CI or live server run. The committed test can run normally in the project's CPU CI:

```bash

```
