# [Fix] [AMD] quantization: Avoid unsupported AITER FP8 bpreshuffle GEMM on gfx1200/gfx1201

[Upstream PR](https://github.com/sgl-project/sglang/pull/43529) · state: open · merged: False

## Original PR description

## Motivation

With `SGLANG_USE_AITER=1`, dense per-channel FP8 linears can select AITER's CK `gemm_a8w8_bpreshuffle` on RDNA4. On a Radeon AI PRO R9700 (`gfx1201`, AITER 0.1.23), a model projection with `M=32, N=8192, K=2048` fails with `This GEMM is not supported!`, even after the module JIT-builds for the selected GPU.

Turning AITER off globally avoids that GEMM but also disables working quantization and activation kernels. Keep those operators available and use the existing unshuffled-weight/torch rowwise FP8 path for `gfx1200` and `gfx1201`. The selection is architecture-based, with no model-name or model-architecture restriction.

## Modifications

- Add a cached selected-device check for exactly `gfx1200` and `gfx1201`, including architecture strings with feature suffixes.
- Extend the existing `use_aiter_bpreshuffle_gemm` predicate with the RDNA4 exclusion. Generic FP8 and Quark linears already use this predicate for their load-time shuffle and runtime GEMM selection.
- Make compressed-tensors channel-FP8 linears use the same predicate at both sites. Runtime dispatch uses the channel-scale count for N because the physical weight axes differ between the shuffled `(N, K)` and plain `(K, N)` layouts. This also applies the existing output-width guard to that path.
- Normalize rowwise torch GEMM weight scales to `(1, N)`. Online `Fp8LinearMethod` stores scales in that orientation already, while compressed-tensors/Quark use `(N, 1)`. Unconditionally transposing the online scales caused `Invalid scaling configuration` after selecting the fallback. The real-GPU test covers this path too.
- Keep `SGLANG_USE_AITER` enabled rather than replacing module globals or maintaining a model-specific shim. Supported AITER quantization and opt-in SiLU remain available.
- Add CPU regression coverage and a checkpoint-free real-GPU test for compressed-tensors, Quark, and online FP8 linears.

The affected scope is dense per-token/per-channel FP8 GEMM dispatch. This builds on the weight-layout/runtime-selection invariant in #37564. AITER's merged ROCm/aiter#3343 handles a separate block-scale family.

## Accuracy Tests

Tested source is based on upstream main `ff19159e162595f26e6d01eabcbbd4638b3bd228` (2026-10-10). The test environment uses ROCm 7.2.3, PyTorch `2.13.0+git733fca1`, Triton `3.8.0+git669b31ac`, AITER 0.1.23, compressed-tensors 0.18.0, and a locally built gfx1201 sgl-kernel 0.4.7.

- New CPU-only regression suite: 4 tests passed with AITER enabled and disabled. Covers both target architecture strings, feature suffixes, non-HIP behavior, retained non-RDNA output-width policy, compressed-tensors shuffle/dispatch agreement, and both `(N, 1)`/`(1, N)` rowwise scale layouts, bias, and 3D output handling.
- Existing neighboring Quark W8A8 FP8 suite: 5 tests passed.
- Real R9700 GPU validation: 45 regular forward cases (3 schemes x 3 `(N,K)` shapes x 5 batch sizes), plus 15 pre-quantized compressed-tensors forward cases passed. Batches are 1/4/8/16/32; `(N,K)` are `(8192,2048)`, `(1536,1024)`, and `(32,512)`. Checks unshuffled FP8 weight bytes, finite outputs, bias, and the FP32 matmul reference built from each path's actual quantized operands (`rtol=0.02, atol=0.01`).
- Runtime dispatch confirms AITER remains enabled in FP8 utilities and quantization, bpreshuffle GEMM is excluded, and `SGLANG_OPT_USE_AITER_SILU_MUL=1` selects `forward_aiter`.
- All applicable repository pre-commit hooks passed.

Reproduction commands from the repository root:

```bash
PYTHONPATH=python python test/registered/unit/layers/quantization/test_aiter_bpreshuffle_dispatch.py -v
SGLANG_USE_AITER=1 PYTHONPATH=python python test/manual/quantization/test_rdna4_aiter_fp8.py -v
```

Hardware validation was performed on **gfx1201 only**. gfx1200 is included in the fallback policy and tested with mocked device detection; no gfx1200 hardware correctness or performance claim is made. CDNA policy preservation is unit-tested, not hardware-tested in this run. The manual GPU test skips without a target GPU and AITER enabled; the CPU suite is registered with CPU CI.

## Speed Tests and Profiling

Before preparing this PR, the equivalent selection policy was evaluated using a two-module initialization shim on **SGLang 0.5.21**, with `IndexTeam/Index-Translate-2B-FP8` on R9700. These are historical measurements of that shim, not a new full-model benchmark of this main-based PR branch. The model is an example used for validation, not a restriction on the change.

For input 512/output 256, FP8 weights and FP8 KV, 5 warmup waves followed by 1 measured wave, aggregate decode throughput excluding prefill:

| Batch | AITER globally disabled (tokens/s) | Selective AITER (tokens/s) | Change |
| ---: | ---: | ---: | ---: |
| 1 | 77.6 | 106.9 | +37.8% |
| 4 | 299.5 | 412.2 | +37.6% |
| 8 | 567.0 | 789.2 | +39.2% |
| 16 | 1037.0 | 1472.8 | +42.0% |
| 32 | 1931.2 | 2566.6 | +32.9% |

The shim configuration also completed the separate fixed-length and translation API suite. These fixed-batch numbers should not be interpreted as HTTP serving throughput or performance on other models/GPUs. No profiler was enabled for timing. The PR-branch validation above exercises real GPU linear operations without downloading a model.
