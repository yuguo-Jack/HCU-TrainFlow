# [Feat] sgl-router: skip engines at an admission cap in power-of-two; forward x-sglext headers

[Upstream PR](https://github.com/sgl-project/sglang/pull/44218) · state: closed · merged: True

## Original PR description

`power_of_two` sampled two engines, checked admission only on the one it picked, and returned the rejection without trying another engine. So a request got a 503 whenever that pick was at a cap (for example `--max-in-flight`), even while other engines had room. Router retries do not help: they only follow dispatch failures, and selection failures return immediately. `cache_aware` (no cache hit) and `session_aware` (new session) reach the same path through their power-of-two fallback.

The router's header allowlist also dropped `x-sglext-*`, so `x-sglext-return-input-ids` never reached the engine on chats the router passes through (the engine-route path).

## Modifications

- `admission.rs`: add `partition_admitted`, which splits candidates into admitted engines and rejections using one load snapshot.
- `power_of_two.rs`: sample only among admitted engines; return `NoAdmissibleEngine` (with every rejection) only when none is admitted.
- `cache_aware.rs`, `session_aware.rs`: filter the fallback candidates with the same helper. This also removes the now-redundant check on the fallback's pick.
- `header_utils.rs`: forward the `x-sglext-` prefix.
- `POLICY_DESIGN.md`, `README.md`: describe the new behavior.
- Tests: update the component tests that pinned "check only the selected engine" (error variant and admission call counts), and add a test that a rejected engine is skipped even when it is the less loaded one.
