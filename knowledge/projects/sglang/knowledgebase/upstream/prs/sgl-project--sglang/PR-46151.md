# [Fix] [AMD] dsv4.1: Fix decode graph capture with quantized low-ratio activations

[Upstream PR](https://github.com/sgl-project/sglang/pull/46151) · state: closed · merged: True

## Original PR description

## Motivation

sgl-project/sglang#45407 made `forward_low_ratio_sources` cut `x` and `q_lora` to the hoisted rows on every step (`x[:n]`, `q_lora[:n]`); before, it cut them only when DP attention padded an eager extend. On ROCm, `q_lora` (and on some routes `x`) reaches it quantized, as an `Mxfp8Activation` (q and scale) or an `Fp8GridActivation`: structs that refuse a slice. Since #45407, a DeepSeek-V4.1 server on MI35x fails while capturing its decode graphs (seen with `--monokernel-backend amd`; the failing call is SGLang's own forward, which every decode step of a plain server runs):

```
File ".../layers/attention/deepseek_v4_backend.py", line 3402, in forward_low_ratio_sources
    q_lora = q_lora[:n]
TypeError: 'Mxfp8Activation' object is not subscriptable
```

## Modifications

- `forward_low_ratio_sources` cuts `x`, `positions` and `q_lora` only when DP padding left rows past the hoisted ones, as before #45407. Decode and verify steps, where every row is live, pass them on uncut.
- That cut goes through `_first_rows`, which cuts a quantized struct field by field (`msgspec.structs.replace`) and a tensor with `[:n]`. On CUDA both are tensors here, so CUDA takes the same cut as on main.

- `test/registered/kernels/ops/attention/dsv4/test_dsv41_decode_glue_hip.py`: 6 passed.
- sgl-amd-mono's `test/e2e/test_deepseek_v41_server.py` (`--monokernel-backend amd`): 9 passed. GSM8K: 0.930 (DSpark verify server), 0.905 (decode server). Both servers step past the monokernels' widths onto this path.
- SGLang alone, without the monokernels, the same two servers, GSM8K (200 questions, 8 shots): 0.895 (DSpark verify), 0.905 (decode).
- sgl-amd-mono's `test/kernels/test_deepseek_v41_kernels.py` against this SGLang (K1, K2 and the FFN launch bit for bit, with and without aiter's preshuffle, every width the spec builds): 6 passed, on 048555d92f.

The other GPU runs used e62ad22f6a. The commits after it change only docstrings and the unit test.
