# [Fix] dsv4: Let the DSpark draft prep run without host lengths on every device

[Upstream PR](https://github.com/sgl-project/sglang/pull/46897) · state: closed · merged: True

## Original PR description

- `ExpandPrefillCausally`'s torch path, used on devices without the Triton kernel such as XPU, derives `extend_start_loc` from the device extend lengths when the host lists are absent. The DSpark draft block has passed no host sequence lengths since #46891, so the DeepSeek-V4 draft prep asserted there. A parity case covers this input.
- The draft and target-verify metadata glue graphs, which the backend declares capturable, raise on a capture failure when `SGLANG_IS_IN_CI` is set. Outside CI they still log and fall back to eager. The generic glue (`SGLANG_ENABLE_METADATA_GLUE_GRAPH`) is unchanged.
- `DeepseekV4AttnBackend.init_forward_metadata_out_graph` no longer forces host sequence lengths for the DSpark draft and follows `needs_cpu_seq_lens`, so capture and replay pass the draft prep the same inputs.
- The DSpark draft batch drops its `nxt_kv_lens_cpu` fallback. It was unreachable, because a draft backend that needs host lengths makes the scheduler publish them, and it carried allocation lengths rather than sequence lengths.

No behavior change on CUDA or HIP outside CI, except that capturing the DeepSeek-V4 DSpark draft graph no longer copies the sequence lengths to the host.
