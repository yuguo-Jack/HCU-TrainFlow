# [Bugfix][Anthropic] Pass prior-turn thinking as reasoning_content when the template reads it

[Upstream PR](https://github.com/sgl-project/sglang/pull/40968) · state: open · merged: False

## Original PR description

Fixes #40959.

## Motivation

Claude Code over `/v1/messages` echoes prior assistant `thinking` blocks on every turn. For HF/Jinja-template models the adapter re-wraps them with the reasoning detector's markers and splices the result into content. Templates that render `reasoning_content` themselves then produce two reasoning blocks per turn: their own empty one plus the spliced one. Qwen3.8 dropped the inline `'</think>' in content` fallback older Qwen templates had, so the doubled pattern is now visible to the model, which learns to emit a stray `</think>` in visible text (the issue measured 14 of 212 assistant blocks in one long Claude Code session).

## Modifications

- `chat_encoding.template_reads_reasoning_content()` answers whether the Jinja template (string or named-template dict) references the `reasoning_content` field.
- `ServingChat.template_reads_reasoning_content()` exposes it next to `supports_native_reasoning_history()`.
- The Anthropic adapter's `_convert_assistant_thinking_blocks` maps prior thinking to `reasoning_content` when either the encoder owns reasoning history or the template renders the field. Templates without the field keep the detector-marker splice, so nothing changes for them.

The discriminator is the template itself, not a model list, so any future template that consumes the field gets the faithful path automatically.

## Accuracy Tests

Rendering-level, no GPU: with the byte-identical official Qwen3.8 `chat_template.jinja`, the spliced shape renders `<think>` empty block + spliced block + text (the doubled pattern from the issue), while the field shape renders exactly one `<think>` holding the prior reasoning, then the text. `preserve_thinking` undefined (the serving default) renders the field for prior turns, so nothing is dropped.

Unit tests in `test_serving.py`: prior thinking maps to `reasoning_content` when the template references the field (and content carries no think markers), and keeps the splice when it does not. The mapping test fails on the unfixed discriminator; the splice test pins the unchanged fallback. `test_serving.py` 63/63 green on CPU. The five `test_serving_chat.py` failures in this environment are a missing `uvloop` wheel on macOS, unrelated to this diff.
