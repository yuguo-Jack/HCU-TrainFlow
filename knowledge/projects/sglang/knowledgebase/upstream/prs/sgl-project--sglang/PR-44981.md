# [Perf] [AMD] kimi-k3: Prefill on gfx950: MXFP4 MoE activations, SiTU front epilogue, row-sharded tails and streaming AttnRes read

[Upstream PR](https://github.com/sgl-project/sglang/pull/44981) · state: open · merged: False

## Original PR description

> Kimi-K3 on gfx950, grouped into larger drafts: prefill #44981 (now includes #44980) · TP8 LL collectives #44985 (with #44986) · decode routing #44987 (with #44978's argmax) · KDA verify #44982 · then #44988. Closed as superseded on main: #44979, #44983, #44984, #44989.

## Motivation

Kimi-K3 prefill on gfx950 leaves four costs on the table:
- the A8W4 experts quantize activations to MXFP8 even where aiter's MXFP4 x MXFP4 kernels are faster;
- the merged MoE front GEMM is followed by a separate SiTU kernel for the shared experts;
- every rank runs the latent tail (norm, up-projection, adds) and the FFN-side attention-residual read on all rows of 4K-8K-token chunks;
- the attention-residual read keeps the whole bank in one register-bound CTA per row.

This PR now also carries #44980 (streaming attention-residual read), so the Kimi-K3 prefill changes land together.

## Modifications

Gated on gfx950.

- **MXFP4 activations:** SiTU MXFP4 MoE calls of at least `SGLANG_ROCM_K3_PREFILL_MOE_A4W4_MIN_TOKENS` (1025) tokens quantize activations to MXFP4 and run aiter's a4w4 kernels on the gate/up-interleaved a8w4 weights (`gate_mode=INTERLEAVE`). This only happens for padded sizes whose aiter config resolves to the mxmoe stage 1, the one stage 1 that honors that layout; `mxfp4.py` records the interleaving on the quant info.
- **SiTU front epilogue (`kimi_k3_front_situ`):** at the prefill sizes where it beats the tuned GEMM + SiTU pair (129-160, 193-320, 1152-1280 tokens), the merged front runs as one Triton GEMM whose gated tiles pair gate row j with up row 768 + j and write SiTU(gate) * up (`SGLANG_ROCM_K3_FRONT_SITU`).
- **Row-sharded tails:** batches of at least `SGLANG_ROCM_K3_ROW_SHARDED_TAIL_MIN_TOKENS` (4096) tokens reduce-scatter the MoE's [latent | shared] partials by rows, run norm + up-projection + shared + residual add on this rank's 1/8 of the rows, and all-gather the stream. With `SGLANG_ROCM_K3_ROW_SHARDED_ATTN_READ`, the attention output's sum and the FFN read also run on the shard (`AttnBankState.ffn_row_shards`). Below ~4K tokens RCCL's fixed cost outweighs it, hence the default.
- **Streaming attention-residual read (was #44980):** from 64 rows with a bank tile of at least 8, `attn_res_hip` reads the bank two rows at a time with an online softmax (`_agg_stream_kernel`), so many CTAs share a CU; smaller batches keep the register-tile kernel.

| New env var | Default |
|---|---|
| `SGLANG_ROCM_K3_PREFILL_MOE_A4W4_MIN_TOKENS` | 1025 |
| `SGLANG_ROCM_K3_FRONT_SITU` | on |
| `SGLANG_ROCM_K3_ROW_SHARDED_TAIL_MIN_TOKENS` | 4096 |

## Accuracy Tests

Setup: 8x MI350X, Kimi-K3 TP8 with EAGLE3 (`lightseekorg/kimi-k3-eagle3.1-mla`; topk 1, 3 steps, 4 draft tokens), FP8 KV, `SGLANG_USE_AITER=1 AITER_SITUV2_A8W4=1 AITER_FLYDSL_FORCE=1 SGLANG_AITER_K3_OPT=1`, on `main` 3a01d4cc8c (2026-10-29) with #43599's aux capture applied locally.

- GSM8K 200: 98.0 with the streaming read, 98.5 with this whole PR (base 98.5; temperature-1.0 runs vary by about 1 point).
