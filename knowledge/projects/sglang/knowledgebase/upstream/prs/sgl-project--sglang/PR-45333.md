# [Fix] [NPU] Correct ModelSlim W4A8 MoE scale-bias TP sharding

[Upstream PR](https://github.com/sgl-project/sglang/pull/45333) · state: open · merged: False

## Original PR description

## Motivation

ModelSlim integer W4A8 MoE loads the W2 matrix as a TP-local K shard, but currently allocates and loads all 16 checkpoint `scale_bias` columns on every TP rank. The post-load reduction therefore applies a full-K quantization compensation to a partial-K matrix product. On GLM-5.2 W4A8 with A3 TP16/EP1 and MoE A2A `none`, the unmodified baseline produces garbled text and scores 0/50 on a local 24-shot subset with 46 invalid answers, even with offload and MTP disabled.

This defect applies when MoE-local TP is greater than one. DeepEP with TP16/EP16 derives MoE-local TP1 and avoids this mismatch. A separate real-model check of unmodified baseline `ce329c85fa` with DeepEP `auto`, TP16/EP16, and NPU decode graph scores 46/50 on the same custom subset, with zero invalid answers and request errors, without this patch. This fix is not a prerequisite for that DeepEP deployment.

## Modifications

- Allocate W2 scale bias from `layer.moe_tp_size`, retaining only this rank's `16 / moe_tp_size` K-block columns. Reject TP sizes that cannot partition the checkpoint's 16 blocks.
- Mark only `scale_bias` as `GROUP` so the existing FusedMoE loader shards it with the matching K range. Keep ordinary per-channel scales and offsets unchanged.
- Add regression coverage for MoE TP 1/2/4/8/16, MoE TP1 with EP16, W13 loading, and invalid TP sizes.

The implementation follows the existing vLLM-Ascend `scale_bias` grouped-parameter convention. It does not change the generic loader, NPU kernels, compact index cache, Copy-SFA, or LIM. It targets integer W4A8, not MXFP4 or W8A8.

## Accuracy Tests

- Ruff, Ruff format, isort and `git diff --check` pass.
- Four regression methods pass on an A3 NPU with tensors allocated on `npu:0`, with zero failures/errors/skips. The same tests pass with the ordinary and compact index-cache source trees.
- Real GLM-5.2 W4A8 serving on A3, TP16/EP1, ModelSlim, BF16 KV, NPU decode graph, with offload/MTP disabled: the same local 24-shot/50-question subset improves from 0/50 (46 invalid) to 47/50 (0 invalid). All 50 requests complete without errors and evaluator/controller/wrapper exits are 0. This is a custom subset, not a standard GSM8K score.
- The independent compact-index-cache variant with the same quantization fix scores 48/50 (0 invalid). Raw text matches for 48/50 questions and extracted answers for 49/50; the small score difference does not establish an accuracy improvement. Three fixed prompts repeated three times have identical text within and across the two variants.

For provenance, model validation preserves ordinary source `ce329c85fa` and compact source `abcdd9982a`, overlaying the exact same corrected production file on both. The quantization and shared loader files are unchanged between the original baseline and this PR's newer main base `553836c164`. NPU unit and raw model results were independently audited.

Only A3 has runtime coverage. A5 uses the same integer W4A8 source path; GPU W4AFP8 is a different quantization format. Neither A5 nor GPU runtime validation is claimed.
