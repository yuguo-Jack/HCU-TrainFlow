# [Refactor] multimodal: [sglang-miles] [MM refactor 3/9] Extract a shared multimodal processor mixin

## Original PR description

## Motivation

Port of #46409 ([MM refactor 3/9]) onto `sglang-miles`, stacked on #46681 (2/9).

## ⚠️ Conflict resolved: `load_video` in `_load_single_item` (behavior change)

Commit `refactor(mm): move decorated loader helpers into the processor mixin` moves `_load_single_item` into `MultimodalProcessorMixin`. `sglang-miles` and `main` disagree on one line of it:

```python
# sglang-miles (removed)
return load_video(data, frame_count_limit)
# main, taken into the mixin
return load_video(data, use_gpu=cls.video_preprocessing_device != "cpu")
```

`load_video(video_file, use_gpu=True)`: the `sglang-miles` line passed the frame limit into `use_gpu`, so legacy video decoding ran on **CPU** whenever no frame limit was set. The mixin takes `main`'s line, so later rebases of `sglang-miles` onto `main` stay clean.

**Behavior change on `sglang-miles`:** legacy video decoding now runs on **GPU** (bare `"cuda"`) unless the processor sets `video_preprocessing_device = "cpu"` (as GLM-4V and MiniMax-M3-VL do). With several engines in one process tree that see all GPUs (e.g. Miles colocate), every engine decodes on `cuda:0`.

## Modifications

The ten commits of #46409. `git range-diff` against #46409: 6 identical, 4 different (two more are context only, next to `main`'s `retry_on_cpu_after_gpu_oom`):

- `refactor(mm): move decorated loader helpers into the processor mixin`: the conflict above.
- `refactor(move): extract shared multimodal processor methods`: context only (`sglang-miles` imports `is_true_on_policy_enabled` next to the moved imports); the moved code is identical.

The resulting `multimodal_processor_mixin.py` is byte-identical to #46409's.
