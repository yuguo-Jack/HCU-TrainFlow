## Motivation

`inference-optimization/Kimi-K3-0.40B`, a small Kimi K3 checkpoint, fails on `main` at two places that the full-size model never reaches:

1. `KimiK3DeltaAttention` takes its value head size from `config.v_head_dim`, which is the MLA layers' value head size. The KDA layers use `linear_attn_config["head_dim"]` for keys and values alike, as the reference modeling code and the KDA state cache do. When the two sizes differ (32 vs 64 here), the value projection and the decode output do not match the state cache, and the first packed decode fails:
   ```
   ValueError: `out` must have shape (512, 1, 4, 32) (got out.shape=(512, 1, 4, 64)).
   ```
2. `situ_and_mul` passes a row-strided 2D input straight to the kernel, which reads each row in vectors of up to 32 bytes and rejects a stride that is not a whole number of them. Kimi K3's fused MoE front hands it the shared experts' `gate_up` as a slice of `[gate_up | router logits | latent]`. With few experts, that slice's stride is not a vector multiple.

## Modifications

- Size the KDA values by `linear_attn_config["head_dim"]`.
- `situ_and_mul` takes the dense copy for a row stride that is not a whole number of the kernel's 32-byte vectors of the wider dtype, as it already does for any other input the kernel cannot read in place.

## Accuracy Tests

- With the full-size Kimi K3 dimensions, neither path changes: the KDA head size equals the MLA value head size (128), and with 896 experts the slice's stride is aligned.
- Kimi-K3-0.40B now gets past both failures. On B200, serving it end to end still needs an MLA backend that accepts its `kv_lora_rank=128` and `qk_rope_head_dim=32`; `trtllm_mla` rejects those, and the triton backend does not compile them.

## Speed Tests and Profiling

Not applicable: the copy is taken only for misaligned strides, which the full-size model does not produce.
