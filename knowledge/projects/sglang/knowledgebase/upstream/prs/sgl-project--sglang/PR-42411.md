# [PDMux] Support GLM-5.3-Flash with layerwise prefill and overlap

[Upstream PR](https://github.com/sgl-project/sglang/pull/42411) · state: closed · merged: False

## Original PR description

## Motivation

GLM-5.3-Flash needs a resumable forward to interleave prefill with decode. Under high prefix-cache hit rates, a token budget alone can submit many prefill layers before the next decode launch. This PR adds the model path and a configurable layer cap to bound that submission window.

## Changes

- Resume GLM prefill across layer intervals while preserving residual, allocator, top-k and auxiliary capture state. Compute multimodal embeddings on the first interval.
- Integrate split-prefill scheduling, chunk completion and HiCache event polling.
- Support capped-prefill/full-device-decode overlap and select matching stream groups and eligible decode helper streams.
- Size intervals from the busiest DP rank using `max(scheduler_global_num_tokens)`; apply `max_split_forward_layers` when configured. A zero layer cap retains token-budget behavior.

This is the first step in the [GLM PDMux rollout (#41861)](https://github.com/sgl-project/sglang/pull/41861). Mamba/HiCache, DP/EP and MTP support follow in the dependent PRs. Speculative decoding is gated at this stage.
