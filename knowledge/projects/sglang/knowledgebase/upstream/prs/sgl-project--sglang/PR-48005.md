## Motivation

A speculative draft fused into the unified pool used to be placed by its layer kind; draft layers whose retention differed from the target's either got a private draft pool or were forced into a band that does not match their lifetime. This PR places draft KV by retention lifetime: a draft layer shares the target sub-pool with the same lifetime, and gets its own band otherwise. It also makes window reclamation independent per window and derives the draft's KV coordinates from its attention execution (DCP width, backend).

## Modifications

- Placement: `mem_cache/layout/fused_draft.py`, `kv_cache_configurator.py`, `kv/plan.py`, `kv/alloc/runner_ids.py`, `kv/alloc/id_space.py`, `unified_draft_pool.py`: draft bands are planned by retention lifetime; fused draft views share the target's storage arena.
- Allocation: `kv/alloc/{chain,band,pricing,interim}.py`, `kv/storage.py`, `prefill_budget.py`: independent windows are reclaimed for cleanup and admission; physical reservation scopes and takes cover every chain band.
- Execution: `configs/attention_execution.py`, `layers/attention/{flashinfer_mla_backend,triton_backend}.py`, `kv/layout/{mha,mla,page}.py`, `layout/token_major.py`, `models/dflash.py`, `speculative/multi_layer_eagle_worker_v2.py`: draft KV coordinates come from the attention execution (replicated vs DCP-sharded).
- HiCache: `managers/cache_controller.py`, `hybrid_cache/hybrid_cache_controller.py`, `kv/memory/host_backing.py`, `hicache_storage.py`, `storage/umbp/umbp_store.py`: storage rank replication is decided per view; the `"file"` storage backend uses the page-envelope host pool (it reads and writes whole pages); a single-pool envelope host is sized from that pool's capacity under `--hicache-ratio` rather than from the whole region.
- Tests: draft placement, DCP capacity, HiCache DCP/identity, multiwindow placement, tri-pool and radix-cache tests under `test/registered/unit/`.

**Behavior changes:**
- Under `--enable-unified-memory`, a draft whose fusion into the unified pool is declined now fails at startup with the reason (`invalid unified draft storage declaration: ...`) instead of falling back to a private draft pool. Examples: a Triton draft attention backend with `--dcp-size > 1` (select a replicated draft backend or disable unified memory); recurrent draft layers without a target recurrent-state band; draft prefill and decode backends with different DCP widths. Some DSPARK/DFLASH configurations that started on `main` this way are refused; a fix is planned in a follow-up.
- HiCache with `--hicache-storage-backend file` uses the page-envelope host layout under unified memory.
