# [Fix] [Apple] overlap: Match device when stashing relay payloads

[Upstream PR](https://github.com/sgl-project/sglang/pull/43099) · state: open · merged: False

## Original PR description

  ## Motivation

  Running the MLX backend with `--disable-overlap-schedule` crashes the scheduler on any concurrent decode batch (n >= 2):

  RuntimeError: Expected all tensors to be on the same device, but found at least two devices, mps:0 and cpu!

  Stack: `run_batch` (scheduler.py) → `_relay_forward_payload` → `FutureMap.stash()` (overlap_utils.py).

  Root cause: with overlap disabled, the scheduler still relays decode inputs through `FutureMap.stash()`. On MLX the relay buffers live on the Metal device (`mps`) while the stub worker materializes sampled tokens on CPU (`mlx/tp_worker.py` builds `next_token_ids` with `device="cpu"`). `stash()` only converted the dtype, and for batched scatters (n >= 2) `index_put_` requires the value and the buffer on the same device.

  Two reasons this stayed latent since #29124 (2026-06-24):
  - Single-request runs (n == 1) go through `index_put_`'s single-element fast path, which silently moves the device — the crash needs a concurrent batch.
  - On CUDA the relay buffers and model outputs always share the same device, so `.to(dtype)` is correct there.

  ## Modifications

  `python/sglang/srt/managers/overlap_utils.py` — in `FutureMap.stash()`, match both device and dtype for the four relay assignments (`bonus_tokens` / `topk_p` / `topk_index` / `hidden_states`). On CUDA the device already agrees, so the added `device=` argument is a no-op.

  ## Accuracy Tests

  No model-output impact (scheduler-side relay only). Functional verification on Mac M5 Pro (48GB), `mlx-community/Qwen3-8B-4bit`, MLX 0.32.3:

  - Unpatched + 4 concurrent requests: scheduler crashes with the error above.
  - Patched + 5 rounds × 4 concurrent requests: 20/20 succeed, no crash.
  - New regression test
    `test/registered/unit/hardware_backend/mlx/test_overlap_stash_device.py` scatters a CPU payload into an mps relay buf with batched indices (the exact MLX non-overlap combination): fails on main, passes with this fix.
  - Full MLX unit suite: 223 passed + 23 subtests.

  ## Speed Tests and Profiling

  Not performance-sensitive: the fix adds a `device=` argument to the existing `.to()` call, which is a no-op when devices already match (CUDA), and a single device copy on MLX that was previously implicit in the (crashing) path.

Four PRs fix the same FutureMap.stash device mismatch: #36200, #39222, #39281, #43099. Measured on an M4 Pro: copying the payload to MPS per stash (#43099, #36200) blocks 25 ms when MLX work is in flight.
