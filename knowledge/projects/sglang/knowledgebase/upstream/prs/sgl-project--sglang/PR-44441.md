# [Test] wan2.2-s2v: Add the 2-GPU server accuracy case

[Upstream PR](https://github.com/sgl-project/sglang/pull/44441) · state: open · merged: False

## Original PR description

Adds `wan2_2_s2v_14b_2gpu` to `TWO_GPU_CASES`, with two checks the existing t2v/i2v gates cannot express.

## The two checks
- **Audio sensitivity (differential).** Generate twice at a fixed prompt, seed and conditioning image, swapping **only the audio**, then require the mouth region to change far more than a static background region. The differential is the point: an absolute motion threshold is satisfied by a model that animates nothing at all, since the existing gates compare a single output against a bound rather than two outputs against each other.
- **Reference fidelity.** PSNR/SSIM of the key frames against the conditioning image, so a drifting or collapsed identity fails rather than scoring well on motion alone.

## Why it is XPU-gated
The region boxes and bounds exist only in `intel_xpu_b60.json`. `get_audio_sensitivity_thresholds()` **refuses to guess them** for another platform instead of silently running a check nobody calibrated — an uncalibrated region box would pass or fail for reasons unrelated to the model.

## Measured
2 × B60, ulysses 2, `dit=layerwise-offload`, 4 steps:

| metric | measured | bound |
|---|---|---|
| mouth region | 24.66 dB | — |
| background region | 39.80 dB | — |
| **separation** | **15.14 dB** | ≥ 6.0 dB |
| reference PSNR | 18+ | ≥ 18 |
| reference SSIM | 0.60+ | ≥ 0.60 |

The separation clears its bound by 9.1 dB, so the gate is not sitting on its threshold.
