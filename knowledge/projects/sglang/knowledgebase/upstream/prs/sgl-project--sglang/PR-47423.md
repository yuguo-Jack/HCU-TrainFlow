# [Feat] dflash: Serve SpecForge KDA drafts through the target KDA layer

[Upstream PR](https://github.com/sgl-project/sglang/pull/47423) · state: open · merged: False

## Original PR description

Serve SpecForge DFlash drafts that contain Kimi Delta Attention layers (`dflash_config.attention_modes` with `"kda"`, plus SpecForge's `linear_attn_config`) on the target's KDA implementation. SpecForge exports KDA with Kimi-Linear's parameter names and math: separate `q/k/v_proj`, depthwise `q/k/v_conv1d`, a low-rank decay gate `f_a/f_b`, an output gate that is low-rank (`g_a/g_b`) or full-rank (`g_proj`, `use_full_rank_gate`), `b_proj`, `A_log`, `dt_bias`, a sigmoid-gated `o_norm`, and the optional safe gate `gate_lower_bound`. The draft layer is therefore a thin `KimiDeltaAttention` subclass. It runs the target's fused projections, TP sharding, gated norm and `o_proj`, and the KDA math runs on the target's Triton KDA kernels. KDA layers can share a draft with GQA/MHA layers or with MLA layers.

Only the DFlash-specific parts are new:

- `KimiDeltaAttention` takes `linear_attention_cls`. The default (`RadixLinearAttention`) is unchanged.
- `DFlashKDAAttention`:
  - loads SpecForge's split checkpoint into the target's fused `fused_qkvbfg_a_proj` / `fused_fg_b_proj` / `qkv_conv1d` layout. `A_log` (`[H]`) and the 2-D conv weights (`[C, K]`) are reshaped by the layer's own loaders;
  - with a full-rank output gate, takes the target's no-LoRA layout (`fused_qkvbfg_proj`, as Ling-V3 uses), which fuses a full-rank decay gate too. SpecForge's low-rank `f_a_proj` / `f_b_proj` load into small staging projections, and `post_load_weights` writes `f_b_proj @ f_a_proj` into the fused weight on every load path. The product is exact up to rounding, since nothing nonlinear sits between the two projections;
  - passes `DFlashKDALinearAttention` as its `self.attn`, so the target forward runs unchanged and only the recurrence call is redirected;
  - advances the per-request state for the worker (`write_context_state`).
- `DFlashKDALinearAttention` (`speculative/dflash_kda.py`) replaces the attention-backend call for the draft. The draft runner has a full-attention backend and no Mamba pool, so the layer keeps its own state in the target KDA pool layout: conv `[slots, K-1, conv_dim]` and SSM `[slots, H, V, K]` FP32, indexed by `req_pool_indices` (row 0 is the CUDA-graph padding row). It calls the same `TritonKDAKernel` and `causal_conv1d_*` entry points as `KDAAttnBackend`:
  - **Prefill commit**: the target's extend path, `causal_conv1d_fn` with `has_initial_state = prefix_lens > 0` plus `chunk_kda` with `beta_is_raw=True`. A request with no prefix is a new occupant of its slot, so its state is zeroed first. Chunked prefill continues the state.
  - **Verify commit**: the recurrent (decode) kernel over dense `[bs, block_size]` verify rows. Each request's first `commit_lens` rows form a varlen segment on its slot; the rest form a segment on slot `-1`, which the kernel neither reads nor writes. The conv tail is rolled by a gather. Nothing syncs with the host, so the overlap scheduler keeps running ahead.
  - **Proposal**: the verify kernel (`disable_state_update=True`) with the conv tail from a gathered copy. It reads the committed state and never writes it, so speculative tokens need no rollback. Block-local layers (`context_state="reset"`) pass no state and start every block at zero.
- KDA layers own no KV, so they mix with GQA/MHA layers or with MLA layers. A KDA + MLA draft keeps the MLA KV pool and backends of sgl-project/sglang#44676 for its MLA layers, including their sliding-window and causal options.
- `DFlashDraftConfig` parses the attention modes once (`attention_modes`, `kda`). The DFlash worker allocates the state with the memory pools, before CUDA graph capture, and routes the KDA layers to `write_context_state` in its prefill and verify context writes. The fused GQA KV materializer is disabled for KDA drafts.
- The scan state lives per request slot, outside the prefix cache. A prefix hit would start drafting from a state that never read the cached rows, so scan drafts resolve `--disable-radix-cache` at launch, and the worker refuses to allocate the state while radix cache is on.

The following are rejected at load or launch:

- stacks of only KDA layers (SpecForge also requires a GQA/MHA/MLA layer to read the target context);
- `context_state` other than `reset` / `scan`, and a non-negative `gate_lower_bound`;
- quantized draft weights;
- KDA layers in DSpark drafts;
- `--enable-hierarchical-cache` with a scan draft.

A scan draft needs no extra flags: radix cache is turned off with a warning.

### Relation to sgl-project/sglang#38383

sgl-project/sglang#38383 serves the same checkpoints with a self-contained KDA module in `dflash.py` (`nn.Linear` projections, replicated KDA weights under TP, host-synced commits). This PR replaces that module with the target layer and kernels:

- KDA heads are TP-sharded like the target's, so the `parallel_mode: replicated` config key is no longer needed.
- Verify commits have no `.tolist()` / host copies.
- The slot-reuse bug found on #38383's branch (a new request inheriting the previous occupant's state through a prefix hit) cannot happen: slots reset on `prefix_lens == 0`, and radix cache is off for scan drafts.

### Validation

Both commits were tested on main `a63ea5442b`, on one B300 (TP1, BF16), with torch 2.14.1+cu130, Triton 3.8.0, sglang-kernel 0.4.10 and Transformers 5.19.0 (the `lmsysorg/sglang:dev` image's pins):

- **Draft KDA kernels:** `test_dflash_kda_kernels.py`, 4 passed. It runs the real Triton kernels against independent FP32 SpecForge math. That oracle matches SpecForge's `reference_kda`, short conv and gating exactly (max error 0.0).
  - Coverage: softplus and safe gates; a full-rank output gate; two new requests plus a chunked-prefill continuation; a verify commit with `commit_lens` of 3 and of a full block; unchanged state across proposals; untouched unrelated and padding slots; CUDA graph replay of a proposal after the state changes; and block-local layers.
  - Measured error: outputs within 0.73% relative L2 and FP32 states within 1.24%, against the test's 2% bound. A context-blind result, used as a negative control, is 70.7% away.
- **Real Engine smokes:** a `Qwen3-0.6B` target with random scan drafts exported by SpecForge's own `DFlashDraftModel.save_pretrained`, so each checkpoint keeps SpecForge's split names and shapes.
  - Drafts: `[kda, gqa, kda]` with a low-rank output gate; and `[kda, mla, kda]` with a full-rank output gate and a causal sliding-window (256) MLA layer with low-rank Q, on the `triton` draft backend.
  - Settings: safe gate, CUDA graphs on, `chunked_prefill_size=64`, greedy decoding.
  - Each ran batch sizes 1, 2 and 3, with a prompt of roughly 400 tokens spanning several prefill chunks.
  - Radix cache was turned off automatically, and the per-request state was allocated before graph capture.
  - In both, all 6 outputs are identical to a target-only run. Accepted length is 1.03, as expected from random draft weights.
  - This validates integration, not acceptance quality.
- **Regressions:** the existing DFlash tests (`test_dflash_mla.py`, `test_dflash_extra_buffer_lazy.py`, `test_dflash_overlap_hostsync.py`, `test_dflash_mla_backends.py`) pass on the GPU box.
- **CPU:** `test_dflash_kda.py`, 5 passed, 7 subtests. It covers:
  - attention-mode validation, including KDA + MLA and the DSpark rejection;
  - SpecForge-layout loading into both fused target layouts, including the folded decay gate, with the GQA layer's q/k/v still landing in its own `qkv_proj`;
  - a KDA + MLA draft whose layers each load their own `q_proj`;
  - the varlen segment and conv-tail math of verify commits;
  - the radix-cache resolution.

  The existing DFlash / DSpark / hook CPU tests pass: 104 passed, 7 CUDA-only skips. ruff, isort and codespell are clean.

Not yet validated: TP > 1, HIP, and acceptance with trained checkpoints.

Known cold-start cost: the first prefill commits compile `chunk_kda`'s Triton kernels at serving time, about 5 s per specialization and 6 of them in a smoke run. The target's KDA layers share these kernels.

State memory per slot is `layers x (H x D x D x 4 + (K-1) x 3HD x 2)` bytes. With 16 heads of 128 and 4 KDA layers that is about 4.1 MiB per slot, or about 200 MiB for DFlash's default 48 running requests. It is allocated after KV-pool sizing and is not counted in the KV budget. A full-rank output gate makes the fused projection `H x D` columns wider, because the decay gate is served full-rank.
