# [Feat] dflash: Support Nemotron Bolt E4B BF16 GGUF drafters

[Upstream PR](https://github.com/sgl-project/sglang/pull/47279) · state: open · merged: False

## Original PR description

## Motivation

Enable speculative decoding for the Bolt E4B Q4_K_M GGUF target, `nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-4GB`, with its companion BF16 GGUF drafter, `nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-4GB-DFlash`. Add native configuration support for plain DFlash checkpoints stored in GGUF, reading their configuration directly from GGUF metadata and loading their weights through the existing DFlash runtime.

## Modifications

- Read DFlash config and tensor mappings from GGUF metadata.
- Load dense weights through GGUFModelLoader without packed quantization parameters.
- Translate capture indices and preserve sliding-window metadata.
- Exclude LiLiCorr and packed drafts; reject missing or unexpected tensors.

Serving this pairing also requires [#46874](https://github.com/sgl-project/sglang/pull/46874) (GGUF target support), which includes [#46663](https://github.com/sgl-project/sglang/pull/46663) (shared-KV prefill graph fixes). Validation combined those changes with this PR. They are not included in this branch.

## Accuracy Tests

On H100 at TP1, serving smoke checks passed 5/6 with the Q4_K_M target, both with and without the BF16 GGUF drafter. Both returned 87 instead of 77 on a pencil counting arithmetic check but responded appropriately, albeit incorrectly; the other five checks passed.

On GB10 Spark and B200, the same checks passed 6/6 with and without the drafter at TP1.

These are the six checks:

| Check | Expected response |
| --- | --- |
| Arithmetic: 17 × 23 | 391 |
| Capital of France | Paris |
| Pencils: 12 boxes × 8, minus 19 sold | 77 |
| JSON instruction | A JSON object equal to `{"city":"Paris","count":3}` |
| Arithmetic with thinking enabled | Final answer containing 391 |
| Tool calling | `get_weather` with `city` set to `Paris` |

The **Server launch and smoke-check commands** section below uses the latest Hub revisions and includes the complete smoke-check script. Results may change as checkpoints are updated. Run it against the Q4_K_M target with and without drafting. The script may report the pencil-task failure and exit nonzero; it is not counted as a pass. The separate GSM8K command is under **GSM8K evaluation command** below.

One H100, TP1, `sgl_eval` 0.1.3, 200 zero-shot GSM8K examples, temperature 0, four workers, max output 1024, thinking disabled:

| Target | Target only | BF16 GGUF draft |
| --- | ---: | ---: |
| Q4_K_M | 147/200 (73.5%) | 149/200 (74.5%) |

TP2 was tested on two H100 NVLs: the Q4_K_M target alone passed all six smoke checks. With the drafter, both models loaded and graphs captured, but the first warmup forward failed with `DFLASH with a quantized target lm_head is only supported at tp=1, got tp_size=2.` This is an existing SGLang restriction in the shared quantized-head sampler, unchanged by this PR. This drafter/target pairing currently requires TP1.

Q4_K_M target with the BF16 GGUF drafter, with the prerequisite PRs applied. The BF16 repository below supplies tokenizer files only; its model weights are not downloaded or served.

SGLang downloads the GGUF files and tokenizer automatically. Keep `--tokenizer-path`: omitting it raises an existing GGUF tokenizer fallback bug. When local tokenizer metadata is missing, the fallback passes a directory `Path` to Hugging Face Hub, which rejects it with `HFValidationError`. This code is unchanged by this PR or its prerequisites; the bug should be addressed in a separate PR.

```bash
python3 -m sglang.launch_server \

  --tokenizer-path nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-BF16 \
  --load-format gguf --quantization gguf \
  --served-model-name bolt-e4b --context-length 8192 \
  --max-running-requests 4 --max-total-tokens 8192 \
  --mem-fraction-static 0.7 --host 127.0.0.1 --port 30001 \
```

## Speed Tests and Profiling

One H100 NVL, using intact ShareGPT prompts through the chat endpoint, thinking disabled, a 512-token maximum, and normal EOS stopping. Each configuration used the same prompts: 20 requests at concurrency 1 and 40 at concurrency 4, two warmups, cache flushed, seed 42, temperature 0. Throughput uses actual streamed completion-token counts.

| Target / mode | C1 output tokens/s | C4 output tokens/s | Mean output tokens (C1 / C4) |
| --- | ---: | ---: | ---: |
| Q4_K_M, target only | 144.0 | 303.2 | 463.1 / 460.7 |
| Q4_K_M + BF16 GGUF draft, block 8 | 97.8 | 241.8 | 471.8 / 457.5 |
| Q4_K_M + BF16 GGUF draft, block 2 | 130.8 | 171.0 | 469.4 / 458.4 |

Speculative decoding was slower than target-only decoding in these tests. A controlled experiment confirmed that existing GGUF kernel selection during target verification contributes substantially to the slowdown. Using vector kernels for selected projection shapes improved throughput by 44% at concurrency 1 and 9% at concurrency 4 compared with speculative decoding using the existing kernel selection. This change falls outside the scope of this PR and would need broader hardware and accuracy testing.

Separate concurrency-1 profiles measured block-8 target verification at about 23.8 ms per step, compared with 6.8 ms for normal decoding. The drafter network took about 0.9 ms, excluding head sampling. GGUF matrix kernels and attention accounted for most verification time, with a mean acceptance length of 2.53 tokens. Block 2 reduced verification time to 11.7 ms but remained slower than target-only decoding. 

These runs used target revision `fc2c9fed2eaabca56d44a5be74a448b14d4bc183`, drafter `0949a2eb7152ec6fda1a91ff9302aecbcd464fbf`, and tokenizer `49843eed8db1f1c616c47af75cfd36e07aec0667`.

[by Claude Code] **Severity: functional | Confidence: High**

**Issue**

`build_plain_dflash_gguf_config` stores `dflash.attention.causal` as `dflash_config["causal"]`, but SGLang never reads that key. `_get_dflash_attention_type` in `models/dflash.py` reads `config.is_causal`. When `is_causal` is unset, every `sliding_attention` layer falls back to causal `AttentionType.DECODER`.

**Example**

The published `Nemotron-3.5-Bolt-E4B-DFlash-BF16.gguf` has `sliding_window_pattern = [True] * 5` and `causal = False`, and llama.cpp honors that flag. With this config, `_get_dflash_layer_attention_params(config, 0)` returns `DECODER`, so all 5 draft layers use a causal mask inside the block. This can lower the acceptance length (2.53 at block 8 in the PR).

**Fix**

Pass `is_causal=bool(field("attention.causal"))` to `Qwen3Config` and drop the unused `"causal"` key. In `test_dense_config_preserves_capture_indices_and_window`, assert that `_get_dflash_layer_attention_params(config, 0)[1]` is `AttentionType.ENCODER_ONLY`.

- nvpohanh · comment · 2026-11-04T11:56:27Z · [source](https://github.com/sgl-project/sglang/pull/47279#discussion_r4467117331)

File: `python/sglang/srt/utils/hf_transformers/gguf_reader.py` · line 19

[by Claude Code] **Severity: perf | Confidence: High**

**Issue**

`get_gguf_reader` keeps up to four parsed `GGUFReader` objects alive for the life of the process. Each one holds a numpy view per tokenizer string, so it is large. `read_gguf_architecture` now uses this cache, so non-DFlash target GGUFs are kept too. On main, that reader is freed after the check.

**Example**

A CPU test GGUF with the Bolt E4B tokenizer size (262,144 tokens, 514,906 merges) keeps about 990 MiB more RSS after `has_native_gguf_support(path)` returns, versus about 78 MiB on main. The target and the drafter each pay this in every process that calls `get_config`.

**Fix**

Cache only the small metadata you need, not the reader. Open a fresh reader in `plain_dflash_gguf_weights`, keep `read_gguf_architecture` as on main, and update `test_config_and_weights_parse_the_gguf_once`.
