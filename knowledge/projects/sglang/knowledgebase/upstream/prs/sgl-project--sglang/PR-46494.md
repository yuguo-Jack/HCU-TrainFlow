# Fix issue #46447: Kimi-K3 AR fusion buffer capacity with attention-DP

[Upstream PR](https://github.com/sgl-project/sglang/pull/46494) · state: open · merged: False

## Original PR description

## Summary

Fix Kimi-K3 AR fusion prefill buffer overflow when attention data parallelism (DP) is enabled.

## Root Cause

`_max_buffer_rows()` in `k3_ar_fusion.py` computed the buffer capacity from the per-chunk prefill size (or `max_prefill_tokens`) without accounting for attention data parallelism. When attention-DP is enabled, multiple DP ranks can be batched together, so the runtime token count can exceed the per-chunk limit. This caused the pre-allocated buffer to be too small, leading to out-of-bounds writes or incorrect AR fusion results during prefill.

## Fix

Scale the base buffer rows by `attn_dp_size` when it is greater than 1. The buffer capacity is now `base_rows * attn_dp_size`, ensuring sufficient space for the combined token count across all DP ranks.

**File changed:** `python/sglang/srt/layers/communication/k3_ar_fusion.py`

## Testing

- Verified Kimi-K3 AR fusion prefill works correctly with attention-DP enabled (multi-rank batching).
- When `attn_dp_size == 1` (default), the behavior is unchanged.

Closes #46447
