# [Fix] disaggregation: Poison the deferred abort ack when a NIXL or Mori write fails

[Upstream PR](https://github.com/sgl-project/sglang/pull/45973) · state: closed · merged: True

## Original PR description

## Motivation

With `SGLANG_DISAGGREGATION_DEFERRED_DECODE_KV_RELEASE` on (the default), decode holds an aborted request's KV pages and metadata slot until every prefill rank acks that its transfer drained, or until the release timeout.

Mooncake withholds that ack after a failed send (`poison_deferred_ack_room`, #43719). NIXL and Mori still send it after a failed transfer, although both engines can report the failure while writes of that transfer are still on the wire (see Engine code references below). The deferred-release ADR (#44186, Rule 2) rules this out.

- NIXL: the Python API raises on a failed post. The raised post never reaches `handles`, so once the other handles settle, the worker concludes the room and calls `_maybe_ack_drained_abort`. A failed poll is already safe: it leaves the batch unsettled, and that branch poisons.
- Mori: `_mark_transfer_quiescent` acks once the room's outstanding count reaches zero without looking at the statuses, and both the transfer worker and the drainer reach it with a `Failed()` status. `_arm_abort_ack` also acks directly when the count is zero, bypassing any poison.

Decode receives the drained ack, frees the pages, and a write that is still running can land on pages already reused by another request. Decode takes this path on a prefill-reported failure too (`ensure_abort_notified(force_arm=True)`), so both ABORT orderings reach the bug: mid-transfer, or after the Failed status.

## Modifications

NIXL:
- Add `_post_xfer`, used by all 11 `agent.transfer` sites. It raises `_NixlPostError` when NIXL raises or returns `"ERR"`, chaining the NIXL exception as `__cause__`.
- In the worker's failure path, poison the room on `_NixlPostError`, then conclude the failure, uncount the chunk and fall through to `_maybe_ack_drained_abort`, which drops a poisoned room's targets. This is the same order as the Mooncake failed-send path in #43719.
- The failure log also checks `__cause__`, so a NIXL transport error is still logged as a warning.

Mori:
- Add `_poison_failed_transfer`, which poisons the room under `_abort_ack_lock` when any status of the chunk reports `Failed()`. Call it where a chunk becomes quiescent: in `_process_transfer_chunk` (before concluding the failure) and in `_drain_transfer_statuses` (after `status.Wait()`).
- `_mark_transfer_quiescent` does not pop a poisoned room's targets, and `_arm_abort_ack` returns early for a poisoned room. Mori sends ACKs from these two places itself, not through `_maybe_ack_drained_abort`.

Decode then falls back to its release timeout (`SGLANG_DISAGGREGATION_DEFERRED_DECODE_KV_RELEASE_TIMEOUT`, 30s) for that room. A new lifecycle of the same `bootstrap_room` clears the poison as before.

Cost: a NIXL post that raises, or a Mori status that reports `Failed()`, is poisoned even when nothing was posted for it (on Mori, e.g. a full send queue before the first WR), so decode holds those pages for 30s.

## Accuracy Tests

N/A, failure-path bookkeeping only. Regression tests, each driving the transfer worker and asserting that no ABORT_ACK is sent:

- `test_rejected_post_never_acks` (NIXL): only the NIXL agent is mocked. Two decode peers: the first post is `DONE`, the second raises a NIXL transport error. The ABORT arrives mid-transfer and again after the worker finishes. Fails on main.
- `test_failed_status_never_acks` (Mori): a `Failed()` status on the worker path and on the drainer path. Fails on main.
- Two existing Mori cases now pin `status.Failed.return_value = False`, since a bare `MagicMock` is truthy.

Results on one H200 node (`lmsysorg/sglang:dev`, `nixl-cu13` 1.5.0), at `e241c252e8`:

- The new cases fail on main (`8d8916815b`), each because an ABORT_ACK is sent. On this branch, the deferred-release, Mooncake, NIXL and wire unit files pass (122 tests, 106 subtests).
- NIXL 1P1D fault injection (a one-off script, not part of this PR): for one request, prefill's `nixl_agent.transfer` does the real post and then raises `nixlBackendError`; the release timeout is 10s. Decode reports `decode_deferred_kv_release_total{outcome="drained"} 1` on main and `outcome="timeout"` 1 on this branch. A follow-up request returns 200 in both.
- Mori: CPU unit tests only; no AMD machine was available.

## Engine code references

- NIXL (UCX backend, `v1.5.0` and `c28061f9`):
  - `postXferReq` and `getXferStatus` call `throw_nixl_exception`, which raises for every status other than `NIXL_SUCCESS` / `NIXL_IN_PROG`; the `"ERR"` return in `_api.py` is unreachable.
  - With prefill's `num_threads = 8`, a request is split into chunks on separate threads and endpoints. When one chunk fails, the others cancel and free their UCX requests without waiting for them (`nixlUcxBackendReqH::release`).
- Mori (RDMA backend, `f39fa765` and current main):
  - With sglang's defaults, one `TransferStatus` spans 4 QPs. The first error CQE or post failure fails the status while WRs on the other QPs keep running, and `TransferStatus::WaitFor` returns as soon as the status is not `IN_PROGRESS`.
