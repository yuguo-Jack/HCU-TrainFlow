# [Feat] lmcache: Enable external KV reuse on PD prefill servers

[Upstream PR](https://github.com/sgl-project/sglang/pull/47507) · state: open · merged: False

## Original PR description

## Motivation

Allow disaggregated prefill servers to reuse KV cached in LMCache.

## Modifications

Enable LMCache on prefill servers and wait for asynchronous KV loads before sending cached prefixes to decode, including when overlap is disabled. Decode-side LMCache remains unsupported.

Add an engine-driven shared-memory (SHM) configuration, a reuse benchmark, and configuration/lifecycle/end-to-end tests. Includes the store-ordering fix in #47558.

## Accuracy Tests

On MI355X / ROCm 10, Qwen3-8B TP=2 and two-node Qwen3-0.6B TP=1 passed strict 16-token comparisons against a no-LMCache baseline, covering cold requests, external hits, cache-salt isolation and both-server restarts. Warm and restarted cross-node requests reused 1024 external tokens with zero device hits. Tests used SHM and Mooncake TCP (`MC_FORCE_TCP=1`).

Combined integration a1477798 passed 459 tests and 262 subtests. Default Mooncake HIP TP=2 and LMCache-driven IPC TP=2 remain unresolved on this stack. Hosted CI is pending.

## Speed Tests and Profiling

At a5b77ce1, Qwen3-0.6B TP=1, input/output 3073/64, concurrency 8: inline versus SHM measured 83.82 versus 610.47 output tokens/s over 512 requests with exact output equality. Both used non-lazy 16 GiB L1 pools; throughput excludes cache priming and flushes.
