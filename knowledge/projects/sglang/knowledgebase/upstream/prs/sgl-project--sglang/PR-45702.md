# [Refactor] radix-tree: Move insert overlap handling into a resumable OVERLAP phase

[Upstream PR](https://github.com/sgl-project/sglang/pull/45702) · state: closed · merged: True

## Original PR description

## Motivation

The resumable insert walk in `UnifiedTreeCore` handles an overlapping node inline inside `_insert_walk_step`: the component overlap hooks (`update_component_on_insert_overlap`), the duplicate-slot frees and the hit-count backup check all run in the same step that matched the node. The walk can suspend at a barrier only between steps, and the only phase a suspended walk can resume into is `WALK`.

That leaves no place for a tree core that has to wait on a resource barrier before it may take ownership of the overlapping slots. Such a core would have to return from the walk step before the overlap hooks run, and the resume would then match the same node again and repeat the pre-barrier work (touch, split, priority), with the overlap still unclaimed.

## Modifications

- `_InsertPhase` gains `OVERLAP` between `WALK` and `COMMIT`; `_InsertWalkState` gains `overlap_node` and `overlap_prefix_len`, and `_advance_insert` dispatches `OVERLAP` to the new `_insert_overlap_step`.
- `_insert_walk_step` keeps the matching, split, priority and unevict handling. For a live node it now records the node and prefix length in the state, switches to `OVERLAP` and calls `_insert_overlap_step` immediately, so an ordinary overlap still completes within one step and emits the same actions as before.
- `_insert_overlap_step` holds the moved overlap body: the component overlap hooks and the duplicate-slot frees (including the split below the SWA eviction floor). A subclass that overrides it can append a non-deferrable action and return while the state stays in `OVERLAP`; `_advance_insert` suspends as usual and the next `resume_insert` lands back in the overlap step for the same node.
- `_finish_insert_walk_node` holds the bookkeeping both the unevict path and the overlap path share: the hit-count backup check, advancing `key` / `value` / `total_prefix_length`, clearing the overlap fields and resetting the phase to `WALK`.
- `components/README.md`: the hook table and the algorithm note name `_insert_overlap_step` as the caller of `update_component_on_insert_overlap`.

No behaviour change for the built-in Full / SWA / Mamba components: the actions emitted per step, and the points at which the walk suspends, are the same as before. The test inspector's `advance_insert_walk_once` precondition (phase is `WALK` between steps) still holds, since an inline overlap returns to `WALK` before the step ends.
