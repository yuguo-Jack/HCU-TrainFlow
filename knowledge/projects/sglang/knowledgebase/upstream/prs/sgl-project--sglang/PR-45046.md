# DeepSeek-V4: skip the MHC prewarm when params are meta

[Upstream PR](https://github.com/sgl-project/sglang/pull/45046) · state: closed · merged: True

## Original PR description

`DeepseekV4ForCausalLM.load_weights` ends with `_prewarm_mhc_kernels()`, which runs the MHC kernels on the model's params. miles' p2p weight update builds a replica of each rollout engine rank and loads it into meta params, to learn which checkpoint tensors write which bytes. On DeepSeek-V4 that load fails in the prewarm (`RuntimeError: Cannot pack tensors on meta` from `tf32_hc_prenorm_gemm`).

The prewarm now returns early when the params are meta. It still marks itself done first, so the replica's later loads into real buffers don't prewarm or barrier in the trainer process. Engines never load into meta, so their behavior is unchanged.

Tested on 16×H200 with `sgl-project/DeepSeek-V4-Flash-FP8` and colocated p2p (4 engines × TP4). Without the fix, the first sync fails while mapping the replica; with it, the run completes, at 5.7 s per sync against 12.3 s for cuda_ipc.
