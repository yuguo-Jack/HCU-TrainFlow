# [Metrics] Add request-level TPOT histogram (sglang:request_time_per_output_token_seconds)

[Upstream PR](https://github.com/sgl-project/sglang/pull/40228) · state: closed · merged: False

## Original PR description

## Motivation

SGLang has no Prometheus metric for **per-request decode speed**. `sglang:inter_token_latency_seconds` is token-weighted (one sample per token), so it cannot answer "how fast did each request decode" or back a per-request TPOT SLO. vLLM exposes this as `vllm:request_time_per_output_token_seconds`, recorded once per finished request; `bench_serving` reports the same per-request TPOT. SGLang already computes the value into `meta_info["decode_throughput"]` when `--enable-metrics` is on, but never exports it.

This is the TPOT histogram from #39706 by @chromecast56, extracted so it can land independently of the PD counter fixes there. An earlier attempt at the same gap (#15184) proposed the tokens/s form; per the review discussion there, seconds-per-token (the reciprocal) is the more conventional unit and matches vLLM, so that is what this PR exports. Supersedes #40224.

## Modifications

- New tokenizer-side histogram `sglang:request_time_per_output_token_seconds`:
  `(finished_time - first_token_time) / (completion_tokens - 1)`, i.e. `1 / meta_info["decode_throughput"]`. One observation per successfully finished request, labelled with `is_streaming` like `sglang:e2e_request_latency_seconds`, reusing the `--bucket-inter-token-latency` buckets (same unit, no new flag).
- Only observed for requests that ran to completion (finish reason `stop`/`length`; aborts leave a truncated decode period) and not on PD prefill workers.
- Factor the formula into `APIServerReqTimeStats.get_time_per_output_token()`; `get_decode_throughput()` is its reciprocal and now feeds `meta_info["decode_throughput"]`. Both return `None` when undefined: <= 1 output token, first token never stamped, or the request finished in the same output batch that carried its first token. The unstamped-first-token guard also hardens the existing `meta_info` path.
- Docs (`production_metrics.mdx`): describe the metric, request- vs token-weighting relative to ITL, PromQL for percentiles and mean, and the TPS-reciprocal caveats (percentile order reverses; mean TPOT does not invert to mean TPS). Also replace the stale sample block for `sglang:time_per_output_token_seconds`, a metric removed in #4914 that the page still listed.
- Tests: metric asserted in `test/registered/observability/test_metrics.py`; unit tests for the formula (`test_req_time_stats.py`) and for the collector observation / `is_streaming` label (`test_stat_loggers_di.py`).
