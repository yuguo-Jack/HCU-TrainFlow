# [Fix] deepseek-v4: End reasoning only on the </think> token

[Upstream PR](https://github.com/sgl-project/sglang/pull/45458) · state: closed · merged: False

## Original PR description

## Motivation

The DeepSeek-V4 / V4.1 reasoning detectors end thinking at the text `</think>`. In the V4.1 tokenizer `</think>` is a single token (128822), but the model can also spell the same text with ordinary tokens, for example when it reasons about parsing its own output. Then reasoning ends early and the real `</think>` leaks into the content.

Repro with the DeepSeek-V4.1-Flash-1017 tokenizer, thinking mode, `--reasoning-parser deepseek-v41`:

```
ids = enc("I will split the raw output on the string '")
    + [1718, 37947, 32]          # "</think>" spelled with ordinary tokens
    + enc("' and keep the tail.")
    + [128822]                   # the </think> token
    + enc("Final answer.")
```

Before, streaming and non-streaming give the same wrong split:

- reasoning: `I will split the raw output on the string '`
- content: `' and keep the tail.</think>Final answer.`

DeepSeek's reference output parser ([deepseek-recipe](https://github.com/deepseek-ai/deepseek-recipe)) matches `</think>` by token id, so only the token ends reasoning.

## Modifications

- `DeepSeekV4Detector` (and the V4.1 subclass) take the tokenizer and look up the `</think>` id. When output ids are available, the detector finds that id, counts the spelled-out `</think>` in the text before it, and ends reasoning at the matching occurrence in the text.
- `ReasoningParser.parse_non_stream` takes optional `output_ids`. `ReasoningParser.observe_stream_output_ids` passes each stream chunk's ids to the detector before its text, for incremental or cumulative streaming output.
- Chat and Responses pass the ids they already have (`output_ids` is in every tokenizer-manager output), for non-streaming and streaming.
- Without ids, or with a tokenizer that has no single `</think>` token, parsing stays text-based as before. Other detectors are unchanged.

## Accuracy Tests

With the real DeepSeek-V4.1-Flash-1017 tokenizer, the input above, token-by-token streaming:

| path | reasoning | content |
|---|---|---|
| before (no ids), stream and non-stream | `I will split the raw output on the string '` | `' and keep the tail.</think>Final answer.` |
| after, non-stream | `I will split the raw output on the string '</think>' and keep the tail.` | `Final answer.` |
| after, stream | `I will split the raw output on the string '</think>' and keep the tail.` | `Final answer.` |

New unit tests cover V4 and V4.1, non-streaming, streaming with incremental and cumulative ids, `stream_reasoning` on and off, and the `</think>` token arriving before its text when the detokenizer holds text back. They use a byte-level tokenizer built in memory. `test_reasoning_parser.py`, `test_serving_chat.py`, `test_serving_responses.py` and `test_serving_responses_stream.py` pass locally (393 passed).

## Speed Tests and Profiling

Not measured. The detector stops looking at ids once the `</think>` token is seen, and decodes the ids before it once.
