# [Perf] [NVIDIA] qwen3: Reuse fused QK-norm/RoPE kernel for decode

[Upstream PR](https://github.com/sgl-project/sglang/pull/46908) · state: closed · merged: True

## Original PR description

## Motivation

Qwen3's native CUDA decode path launches QK normalization and RoPE separately. Reuse the existing table-based QK-norm/RoPE kernel to perform both operations in place, eliminating one launch per layer and the intervening Q/K write/read without introducing a new kernel.

On Qwen3-8B, this removes 36 launches per decode step. Eight paired B200 runs before merging main measured ~1.76% lower decode latency at concurrency 1 and ~0.81% at concurrency 32. 


## Modifications

- Add an opt-in `match_cuda` mode to `table_qk_norm_rope_`. It reproduces the separate CUDA kernels' reduction order, reciprocal square root, intermediate BF16 rounding, and RoPE multiply/FMA ordering. The existing default mode remains unchanged for existing callers.
- Route eligible Qwen3 native CUDA decode through this mode under the existing `--enable-fused-qk-norm-rope` flag. Supported inputs are BF16 QKV and norm weights, head dimensions 64/128/256, equal Q/K epsilon, and standard full-head NeoX rotary embeddings. The launcher validates layouts and devices before accessing pointers.
- Preserve the separate normalization/RoPE path for prefill, target verification, unsupported head dimensions/dtypes/rotary configurations, deterministic/on-policy configurations, and the prefill Inductor configuration. V and KV-cache writes are unchanged. No Q FP8 quantization is added.
- Add focused kernel and real-constructor/model-dispatch tests, including changing-input CUDA-graph replay. Two production files: +96/-15 lines; two test files: 259 lines.

## Speed Tests and Profiling

**Historical, pre-merge measurements.** Baseline: `e22a53085994a68aaecbd7a109c8de6da32baeda`; fused production code matches feature commit `d79827f79cce6c110950c8265278031d5eec74b2`. The timings and profiles below have not been rerun on post-merge head `9a11fd65f8`. The 121-test post-merge pass above establishes focused correctness coverage, not a new performance result.

Same model revision, environment, flags, request shapes, and seed for the two measured variants:

- NVIDIA B200, TP1, `Qwen/Qwen3-8B-FP8@220b46e3b2180893580a4454f21f22d3ebb187d3`.
- FP8 weights with DeepGEMM; **BF16 activations and KV cache**; TRTLLM MHA.
- Decode CUDA graphs enabled; prefill CUDA graphs disabled.
- Eight fixed AB/BA pairs (16 fresh servers); 1,024 input / 512 output tokens at concurrency 1 and 32. Separate prefill requests used 1,024 input / 1 output token.
- Decode metric: window median first-to-last-token latency divided by 511. Reported latencies are geometric means of window medians; confidence intervals use paired log ratios across the eight pairs, not individual requests as independent repetitions.
- Quality evaluation and profiling were outside timing windows. No trials were dropped. All 10,752 measured requests completed without errors or prefix-cache hits.

Positive reduction means faster:

Results on PR commit `0492f96df9` versus baseline `4517a5ff1b`, using Qwen3-8B-FP8 on B200. Positive latency reduction means faster.

| Workload | Baseline | Fused | Latency reduction | Paired 95% interval |
| --- | ---: | ---: | ---: | ---: |
| Decode C1 TPOT | 2.94040 ms | 2.88819 ms | 1.776% | [1.769%, 1.782%] |
| Decode C32 TPOT | 4.29953 ms | 4.26854 ms | 0.721% | [0.556%, 0.885%] |
| Prefill C1 TTFT — controlled follow-up | 35.82999 ms | 35.66697 ms | 0.455% | [-0.085%, 0.992%] |
| Prefill C32 TTFT | 323.04991 ms | 322.70180 ms | 0.108% | [-0.502%, 0.714%] |

Decode and prefill C32 results use eight AB/BA pairs. Prefill C1 comes from a separate, CPU-affinity-controlled follow-up: 24 AB/BA pairs, 48 fresh servers, and 49,152 measured requests. Both experiments tested the same commits; results were not pooled. Statistics use paired server-window medians, not individual requests as independent repetitions.

Decode improved in all eight pairs at both concurrency levels.

Prefill C32 and the controlled C1 follow-up meet the 1% non-regression threshold. The C1 follow-up’s upper 95% slowdown bound is +0.085%. A supplementary same-resident A/A/B test covered 34,560 forwards across three sessions; all passed, with a worst upper 95% slowdown bound of +0.173%.

The follow-up completed with zero request errors, zero cached prompt tokens, and matching paired outputs. The earlier unpinned C1 result remained inconclusive; these controlled results do not establish neutrality for every deployment or prove that the earlier variation was entirely noise. No prefill speedup is claimed.



Profiler engagement checks:

- Prefill: both variants launch 288 separate QK-norm and 288 separate RoPE kernels, no combined kernels, and 4,968 total kernel events.
- One initial prefill plus eight decode steps: baseline has 324 norm + 324 RoPE launches; this change has 36 norm + 36 RoPE launches for prefill and 288 combined decode launches. Total kernel events fall from 4,813 to 4,525: **36 fewer launches per decode step**. KV writes remain separate.

Server configuration used in both variants:

```bash
CUDA_VISIBLE_DEVICES=0 PYTHONPATH="$PWD/python" \
python -m sglang.launch_server \
  --model-path Qwen/Qwen3-8B-FP8 \
  --revision 220b46e3b2180893580a4454f21f22d3ebb187d3 \
  --dtype bfloat16 --tp-size 1 \
  --fp8-gemm-backend deep_gemm --attention-backend trtllm_mha \
  --mem-fraction-static 0.3 --random-seed 42 \
  --host 127.0.0.1 --port 30119 \
  --enable-fused-qk-norm-rope \
  --cuda-graph-bs-decode 1 2 4 8 16 32 \
  --cuda-graph-backend-prefill disabled
```
