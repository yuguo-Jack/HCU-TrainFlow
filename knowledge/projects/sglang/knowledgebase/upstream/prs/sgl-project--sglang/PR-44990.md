# [Refactor] memory-pool: Describe DeepSeek V4 device pools with buffer info

[Upstream PR](https://github.com/sgl-project/sglang/pull/44990) · state: closed · merged: True

## Original PR description

## Motivation

Followup of #40917. `DeepSeekV4TokenToKVPool` now implements `get_device_pool_infos()` like the other pools. It returns one `DevicePoolInfo` per physical region (SWA, C1/C2/C4/C128 KV, C4/C128 RoPE, indexer key and scale, C4 compressor checkpoints), each with its pool name, index source and model layer ids. Shared C1/C2 owner stores are listed once. The HiCache stack and the direct external linker build their entries from this list instead of reading the pool's private buffers and layer mappings. Physical layout, host capacity, transfer kernels and the L3 page format are unchanged.

Packed MTP draft SWA is still backed up only when the target has paged SWA, so a DSpark draft SWA ring under encoder replay stays out of host cache as on main.

One behavior change: the trtllm uniform FP8 pool keeps `kv_layout` V4 for its attention backend but stores 512-byte rows, so its description is labeled `uniform_fp8` and HiCache moves it in whole pages only. On main it was treated as V4, which sends partial pages through the token-granular V4 copy (576-byte value plus 8-byte scale per token) and misreads these rows.

## Accuracy

DeepSeek-V4-Flash, tp 2, EAGLE MTP, HiCache layer_first with kernel IO. Multi-turn KL against main with the same commands. Seeds are evicted from device so that every cache-hit sample is served from host. The assembled host pools and the H2D transfer sequence are identical to main (the SWA host pool holds 43 target layers plus 1 packed draft layer), and decode-hit KL is identical.

main:

prefill_kl: 0.007491   host-served samples: 8/8 (768 tokens each)
decode_kl: 0.008166    host-served samples: 8/8 (1024 tokens each)
