# [Bug] Don't size mamba state pool from speculative auto-default max-running-requests

[Upstream PR](https://github.com/sgl-project/sglang/pull/44375) · state: open · merged: False

## Original PR description

Thanks for the detailed report and root-cause analysis, @rystewart-nvidia — the write-up made this straightforward to confirm and fix.

## Root cause

With speculative decoding, `--max-running-requests` auto-resolves to 48 when omitted (all five `speculative_hook` handlers do this). In `KVCacheConfigurator._handle_max_mamba_cache`, the `--disable-radix-cache` branch treated *any* non-`None` value as a user-chosen limit and sized the mamba state pool around it: 48 slots plus the per-draft-token verify snapshots (`stage_per_req * (slots + 1) * draft_tokens`).

On hybrid models where the target and draft weights fit but leave little memory, that reservation exceeds the remaining memory, so `_profile_available_bytes` raises `ValueError: Loaded weights leave no GPU memory for the KV cache` — even though the weights themselves fit. The radix-enabled and target-only paths don't have this problem because they auto-fit the state pool to the available memory.

## Fix

The radix-disabled branch now only sizes the pool from `--max-running-requests` when the operator **explicitly** passed it. Explicitness is read from the pre-resolution `_raw_input` snapshot (`run_resolution_pipeline` records exactly the flags the operator passed; the speculative auto-default is applied later via `declare_resolution` and never touches it). An auto-resolved default (the speculative 48, or a model hook's default) falls through to the existing ratio-based auto-fit, which sizes the state pool to the available memory and leaves room for the attention KV cache — the same behavior as the radix-enabled speculative path.

Invariant preserved: an explicitly passed `--max-running-requests` (including the `--max-running-requests 10` workaround from the issue) still sizes the pool directly, and `--max-mamba-cache-size` / radix-enabled / non-speculative paths are untouched.

## Reproducer (CPU-only, no GPU needed)

Calls the sizing function directly with mocked memory figures — 4 MiB of mamba state per request slot, 6 draft tokens, 1.0 GiB left after weights load:

```python
import sys
from types import SimpleNamespace
import types as _types
sys.path.insert(0, "python")  # repo checkout

from sglang.srt import runtime_context as rc
from sglang.srt.mem_cache.kv_cache_configurator import KVCacheConfigurator
from sglang.srt.runtime_context import get_schedule

def run_case(label, raw_input, resolved):
    fake = SimpleNamespace(
        mambaish_config=SimpleNamespace(
            mamba2_cache_params=SimpleNamespace(
                layers=[0, 1, 2, 3], mamba_cache_per_req=4 << 20)),
        spec_algorithm=SimpleNamespace(is_none=lambda: False),
        attn_dp_size=1, pp_size=1,
        hybrid_gdn_config=None, hybrid_kda_config=None,
        model_config=SimpleNamespace(num_hidden_layers=4),
        server_args=SimpleNamespace(_raw_input=raw_input),
    )
    fake._calculate_mamba_ratio = _types.MethodType(
        KVCacheConfigurator._calculate_mamba_ratio, fake)
    with rc.get_context().override_server_args(
        disable_radix_cache=True, max_mamba_cache_size=None,
        max_running_requests=resolved, mamba_full_memory_ratio=0.5,
        enable_linear_replayssm_spec=False, speculative_num_draft_tokens=6,
    ):
        remaining = KVCacheConfigurator._handle_max_mamba_cache(fake, 1.0)
        print(f"{label}: slots={get_schedule().max_mamba_cache_size}, "
              f"KV memory left={remaining:.3f} GiB"
              + ("  <-- startup ValueError" if remaining <= 0 else "  OK"))

# flag omitted -> speculative auto-default 48 (the reported failure)
run_case("auto default (flag omitted)", {}, 48)
# explicit flag (the issue's workaround)
run_case("explicit --max-running-requests 10", {"max_running_requests": 10}, 10)
```

Before the fix:

```
auto default (flag omitted): slots=48, KV memory left=-0.340 GiB  <-- startup ValueError
explicit --max-running-requests 10: slots=10, KV memory left=0.699 GiB  OK
```

After the fix:

```
auto default (flag omitted): slots=11, KV memory left=0.672 GiB  OK
explicit --max-running-requests 10: slots=10, KV memory left=0.699 GiB  OK
```

## Tests

New regression test `TestSpecDecodeAutoDefaultRadixDisabled` in `test/registered/unit/mem_cache/test_mamba_donated_alloc_ratio.py` covers both cases (auto default auto-fits to 11 slots with 688 MiB left for the KV cache; explicit 8 and explicit 48 still size the pool directly).

```
python -m pytest test/registered/unit/mem_cache/test_mamba_donated_alloc_ratio.py -q
```

The new tests plus the neighboring `TestPPMambaPoolSizing` tests (radix-enabled auto-fit path, must be unaffected) pass: 4 passed. The full file is registered for CPU CI (`register_cpu_ci`, suite `base-a-test-cpu`); I verified the new test bodies verbatim via a standalone harness since this container lacks the GPU dependency stack.

Fixes #44355.
