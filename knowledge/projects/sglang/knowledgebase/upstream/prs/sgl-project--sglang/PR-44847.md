# [Fix] megamoe: Support EPLB rebalance on SM100

[Upstream PR](https://github.com/sgl-project/sglang/pull/44847) · state: closed · merged: True

## Original PR description

- Register the SM100 MegaMoE per-expert tensors that are copies of the expert parameters as parameters of the experts module: the UTCCP-transposed L1/L2 scales in `build_mega_moe_experts_weights`, and the NVFP4 `mega_l1_alphas`, `mega_l2_alphas` and `mega_l2_act_scales` in `ModelOptNvFp4FusedMoEMethod._build_mega_moe_weights`. EPLB moves each expert's slice of every routed-expert parameter (`get_moe_weights`), so a rebalance now moves these copies with the weights they come from; before, moved experts kept the previous experts' scales
- SM90 and ROCm MegaMoE already read the parameters EPLB rewrites; unchanged

No behavior change without `--enable-eplb`, except that these tensors now appear in `named_parameters()`.

DeepSeek-V4.1-Flash, DEP2 on 2 x GB300 (`--tp 2 --dp 2 --ep-size 2 --enable-dp-attention --moe-a2a-backend megamoe`, `--eplb-rebalance-num-iterations 32` when EPLB is on), GSM8K with sgl-eval, 200 examples, greedy, thinking off:

| Code | EPLB | Rebalances | GSM8K (%) | Avg output (tokens) |
|---|---|---:|---:|---:|
| main | on | 142 | 72.50 | 465.4 |
| this PR | on | 35 | 97.00 | 127.2 |
| this PR | off | 0 | 97.50 | 127.6 |

The main run rebalanced more often because its longer outputs kept the eval running longer.
