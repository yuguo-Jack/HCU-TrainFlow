# [Fix] targeted aborts matching unrelated request IDs

[Upstream PR](https://github.com/sgl-project/sglang/pull/41505) · state: open · merged: False

## Original PR description

Aborting `job-1` could also abort independent requests such as `job-10` or `job-1_0`. Match complete RIDs consistently across scheduler, grammar, PD, EPD, and dLLM queues, while preserving `abort_all` and existing cleanup paths.

Batch cancellation already tracks actual child RIDs, including regenerated UUIDs for parallel sampling. Keep that mechanism and explicit session/beam relationships; do not infer ownership from underscores or introduce a new parent-RID API.

Validation:
- The issue's Qwen3-0.6B reproduction fails before the fix and passes afterward on RTX 3070 with Triton attention.
- Queue regressions reproduce 23 failing subcases on the unchanged baseline; the final focused/related suite passes 198 tests and 94 subtests.
- Seven live-server checks pass, covering independent prefixes, underscore IDs, running/waiting cancellation, `abort_all`, unknown/completed IDs, and parallel-sampling disconnect cleanup. Check finish reasons, token counts, cache flush, and subsequent generation.
- Ruff, isort, and `git diff --check` pass.

PD/EPD/dLLM, grammar-waiting, and mid-chunk cancellation have unit coverage, not dedicated end-to-end validation. This intentionally removes implicit prefix cancellation; it does not add parent-string cancellation for batched requests.

Related PR: #41481.
Refs #41474.
