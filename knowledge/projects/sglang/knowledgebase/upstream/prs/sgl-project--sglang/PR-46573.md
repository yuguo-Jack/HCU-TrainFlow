# [Fix] [AMD] dsv4: Skip retired splits in the HIP sparse decode split reduce

[Upstream PR](https://github.com/sgl-project/sglang/pull/46573) · state: open · merged: False

## Original PR description

## Motivation

On gfx950, DeepSeek-V4 sparse decode runs aiter's `pa_decode_sparse(skip_reduce=True)` and then SGLang's own `gfx_sparse_split_reduce`. Since aiter [#4919](https://github.com/ROCm/aiter/pull/4919), a split past a row's own tiles retires. It writes `m = -inf` and `l = 0` and leaves `part_acc` unwritten. aiter's own reduce masks those splits. `_gfx_sparse_decode_reduce_kernel` does not. It computes `fma(0, part_acc[s], acc)` for every split, so a NaN or inf left in that memory turns the whole output row into NaN.

With `kv_splits` pinned to 4 (what `hip_attn_kv_splits()` returns under deterministic inference), an SWA-only layer has 2 tiles, so splits 2 and 3 retire. When the caching allocator held stale NaN, 655360 of 655360 outputs were non-finite. The aiter that the v0.5.21 image bundles (`acf8fdf930`) does not have #4919 and is not affected. Every aiter version from #4919 on is affected.

A separate aiter PR will make retired splits write zeros to `part_acc` under `skip_reduce`. This PR makes SGLang correct with any aiter version, and it masks the same splits that aiter's own reduce masks.

## Modifications

- `sparse_decode_reduce_hip.py`: load `part_acc` with `mask=m_s > -inf, other=0`. The live splits are unchanged, bit for bit.
- New `test/registered/kernels/ops/attention/test_sparse_decode_reduce_hip.py`: retired splits filled with NaN must leave the output equal to the reduce over the live splits only.

## How to reproduce and verify

You need a gfx950 GPU (MI350X or MI355X).

The unit test needs no aiter. It fails on main and passes with this PR:

```bash
python -m pytest -q test/registered/kernels/ops/attention/test_sparse_decode_reduce_hip.py
```

## Accuracy tests

I ran these on an MI355X (gfx950) in the `lmsysorg/sglang:v0.5.21-rocm720-mi35x` image.

| aiter | SGLang | aiter `pa_decode_sparse` → SGLang reduce: non-finite outputs | Unit test |
|---|---|---|---|
| main `a1e5a46168` | main | 32256 of 32768 | failed |
| main `a1e5a46168` | this PR | 0 of 32768 | passed |

A full repro through `aiter_sparse_decode_fwd` with aiter main, SWA and sparse layers, and batch size 4 went from 655360 non-finite outputs to 0.

## Speed tests

I did not measure speed. The change masks the load of splits that have zero weight.
