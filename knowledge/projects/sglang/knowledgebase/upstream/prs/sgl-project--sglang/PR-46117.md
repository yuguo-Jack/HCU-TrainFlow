# [Fix] diffusion: NDRotaryEmbedding theta_rescale_factor and repeat_interleave_real grid path

[Upstream PR](https://github.com/sgl-project/sglang/pull/46117) · state: open · merged: False

## Original PR description

## Motivation

Two bugs in `NDRotaryEmbedding` / `OneDRotaryEmbedding` (`multimodal_gen/runtime/layers/rotary_embedding/mrope.py`):

1. `OneDRotaryEmbedding` ignores `theta_rescale_factor`. `build_freqs_outer` rescales a local `theta`, but `build_freqs` reads `self.theta`, so NTK rescaling never happens. With `theta_rescale_factor=4` the output is the same as with 1, and it does not match `get_1d_rotary_pos_embed` in the same file. This also affects `get_rotary_pos_embed(theta_rescale_factor=...)`.
2. `NDRotaryEmbedding.forward_from_grid` crashes with `use_real=True, repeat_interleave_real=True`. The grid path allocates `sum(dims) // 2` columns while the 1D generator returns full-width slices:
   `RuntimeError: The expanded size of the tensor (2) must match the existing size (4)`. `forward_uncached` handles this case already.

No in-tree caller hits either path today, so current models are unaffected.

## Modifications

- `build_freqs` takes the rescaled `theta` from its caller.
- `_forward_cached_from_grid` sizes outputs the same way `forward_uncached` does and takes each column width from the generator output.
- Tests added to the existing `test_rope_complex_freqs_preconditions.py`: compare against `get_1d_rotary_pos_embed`, and check `forward_from_grid` matches `forward_uncached` on explicit positions.

## Testing

CPU, torch 2.14.1:
- before the fix: the two new cases fail (`theta_rescale_factor=4.0`, `repeat_interleave_real=True`)
- after: `5 passed, 4 subtests passed`
