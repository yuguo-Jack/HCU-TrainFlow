# [Fix] [NVIDIA] moe: keep DeepGEMM standard MoE layout on compact under deterministic inference

[Upstream PR](https://github.com/sgl-project/sglang/pull/48238) · state: open · merged: False

## Original PR description

## Motivation

In `SGLANG_DEEPGEMM_STANDARD_LAYOUT=auto` (default), `_should_use_masked_standard_layout` selects `masked` layout when the estimated workspace fits inside `_masked_standard_layout_memory_budget_bytes` (small-batch decode / CUDA graph) and falls back to `compact` layout on larger prefill batches (or when `SGLANG_OPT_DG_COMPACT_EAGER=1`).

The two layouts round the post-GEMM1 activation differently: `masked` layout fuses `SiLU * mul` with FP8 quantization in FP32 (`silu_and_mul_masked_post_quant`), whereas `compact` layout materializes `SiLU * mul` in BF16 before `sglang_per_token_group_quant_fp8` (~71% BF16 element bit mismatch between `masked` decode and `compact` prefill on SM100). Switching between `masked` and `compact` across batch sizes breaks batch invariance and prefill-vs-decode equivalence under `--enable-deterministic-inference`.

## Modifications

- Return `False` (`compact` layout) in `_should_use_masked_standard_layout` when `SGLANG_DEEPGEMM_STANDARD_LAYOUT=auto` and `get_exec().deterministic.enable_deterministic_inference` is enabled, keeping CUDA-graph decode, eager decode, and large-batch prefill on a single batch-invariant layout while still honoring explicit `SGLANG_DEEPGEMM_STANDARD_LAYOUT={masked,compact}` overrides.
- Add hermetic CPU unit tests in `test/registered/unit/moe/test_deepgemm_moe_standard_layout_deterministic.py`.
