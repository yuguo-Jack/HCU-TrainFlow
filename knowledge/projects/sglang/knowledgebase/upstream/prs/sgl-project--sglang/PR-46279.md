# [Refactor] [NPU] Delete EAGLEDraftNpuGraphRunner, sink device handling to backend

[Upstream PR](https://github.com/sgl-project/sglang/pull/46279) · state: closed · merged: False

## Original PR description

## Summary

Follow-up to #45XXX-adjacent NPU graph refactor (`4e1ef559`, "NPU Graph refactor: delete npu_graph_runner"), applying the same pattern to the EAGLE draft-decode runner. Deletes `EAGLEDraftNpuGraphRunner` (107 lines) entirely; device-specific handling moves from the NPU subclass into the backend / base class:

- **`EAGLEDraftCudaGraphRunner.__init__`**: resolve `self.backend` before static buffer allocation (mirrors `DecodeCudaGraphRunner`), read `out_cache_loc` dtype from `backend.cache_loc_dtype` (NPU already declares int32), and bind itself via `backend.bind_decode_runner(self)` (no-op for non-NPU backends).
- **`NPUCudaGraphBackend.replay()`**: gains the EAGLE draft branch — rebuilds the per-draft-step KV-length `cpu_update_input` lists (previously the NPU subclass's `_replay_graph` override) and funnels both the draft and decode paths through a single `replay_with_input_update` call. DSA/DSV4 still bypass the update.
- **DP seed readiness vote moves from the NPU subclass into the base `can_run_graph`**: the graph/eager decision must be uniform across TP/EP ranks on every device (a diverged rank hangs the collectives), not just NPU where the hang was first observed (`db9143ee08`). Behavior change for CUDA/XPU/MUSA under PD-disagg DSA + attention-DP: one extra CPU `all_reduce(MIN)` per draft round, correctness strictly better.
- **`eagle_worker_v2.py`**: drop the `Device2DraftCudaGraphRunner` dispatch table, construct `EAGLEDraftCudaGraphRunner` directly.
- Dead code dropped with the file: `_init_arch_map` / `_get_update_attr_*` (MHA branch unreachable, `attr_type` had no callers).

Design doc: kyrotiko/sglang-docs `FE/RemoveEAGLEDraftNpuGraphRunner设计方案`.
