# [Feat] embedding: Support BERT and XLM-R masked-LM checkpoints

[Upstream PR](https://github.com/sgl-project/sglang/pull/41846) · state: open · merged: False

## Original PR description

## Motivation

`FacebookAI/xlm-roberta-large` and `google-bert/bert-base-uncased` cannot be
served as embedding models today. Both ship as masked-LM exports and declare
`architectures: ["XLMRobertaForMaskedLM"]` / `["BertForMaskedLM"]`, but
`roberta.py` and `bert.py` only register the bare encoder classes
(`XLMRobertaModel`, `BertModel`, ...).

An unregistered architecture does not raise at registry lookup; it silently
resolves to the Transformers fallback backend. The failure therefore surfaces
much later and far from its cause, during weight loading:

```
ValueError: No module or parameter named 'model.roberta' in TransformersEmbeddingModel.
```

The encoders themselves are already fully implemented and correct — only the
checkpoint layout of a masked-LM export differs from the bare-encoder export.
Registering the two `*ForMaskedLM` names and normalising that layout is enough
to serve both, and makes the family behave consistently: an XLM-R or BERT
checkpoint now loads whether it was exported as an encoder or as a masked LM.

## Modifications

Purely additive. No existing class, `load_weights`, or forward path is modified,
so no currently-working embedding model can change behaviour.

**`python/sglang/srt/models/roberta.py`** — add `XLMRobertaForMaskedLM(XLMRobertaModel)`
and register it in `EntryClass`. Its `load_weights` normalises the checkpoint and
delegates to the parent:

- strips the `roberta.` prefix from encoder weights
- drops the unused `lm_head.*` MLM head

`roberta.pooler.*` needs no handling: after the prefix strip it becomes
`pooler.*`, which `XLMRobertaBaseModel.load_weights` already skips because its
own pooler is `None`.

**`python/sglang/srt/models/bert.py`** — add `BertForMaskedLM(BertModel)` and
register it in `EntryClass`. BERT needs one transform more than RoBERTa:

- strips the `bert.` prefix
- drops `cls.*` — this covers both the MLM head and the next-sentence-prediction
  head, and note BERT uses the `cls.` prefix rather than RoBERTa's `lm_head.`
- renames `LayerNorm.gamma` -> `LayerNorm.weight` and `LayerNorm.beta` ->
  `LayerNorm.bias`

The rename is required, not cosmetic: the original TF-converted
`bert-base-uncased` export stores all 52 LayerNorm scale/offset tensors under the
legacy `gamma`/`beta` names and none under `weight`/`bias`. Without it every
LayerNorm silently stays at its initialised value and the server still returns
plausible-looking vectors, which is why the accuracy check below compares against
an HF reference numerically rather than only smoke-testing the endpoint.
