# [Fix] diffusion: Resolve cached named weights without the Hub API

[Upstream PR](https://github.com/sgl-project/sglang/pull/46679) · state: closed · merged: True

## Original PR description

## Motivation

`resolve_weight()` in `multimodal_gen/runtime/weights/source.py` lists every Hugging Face source with `HfApi().model_info()`, even when the requested file is already in the local cache. That call counts against the Hub's **`api`** rate limit, which is far lower than the download limit and is shared by every process using the same token. When a scheduled PR Test run starts ~100 jobs at once, the quota runs out and diffusion servers fail at startup:

- Failed job: [`multimodal-gen-test-2-gpu (2)`](https://github.com/sgl-project/sglang/actions/runs/40417752787/job/121904415106) — case `wan2_2_t2v_a14b_lora_2gpu`
- `maybe_download_lora` → `resolve_weight` → `resolve_weight_inventory` → `HfApi().model_info("Cseti/wan2.2-14B-Arcane_Jinx-lora-v1")`
- `429 Too Many Requests: you have reached your 'api' rate limit. Retry after 94 seconds (0/3000 requests remaining in current 300s window).`
- The test's retry 12 minutes later hit the same limit, so the file failed.

The LoRA download right after this already checks the cache first (`maybe_download_model` with `local_files_only=True`); only the inventory step went to the network.

## Modifications

- **Cache first for named files.** `resolve_weight()` now checks the cached snapshot for the requested revision (`snapshot_download(..., local_files_only=True)`) when the caller names an exact file (a file reference, or `weight_name`). If that exact path is cached, it builds the inventory from the snapshot and pins the snapshot's commit, with no network call. This also lets the path work with `HF_HUB_OFFLINE=1`.
- **Same behaviour otherwise.** It falls back to `model_info()` when the revision isn't cached, the file is missing, only a basename match is cached, or no file is named. A cached snapshot holds only the files downloaded so far, so it is never used to choose among candidates.
- **Unpinned revisions use the cached commit.** When no revision is pinned and the file is cached, the cached commit is used without asking the Hub for the latest, so a repo updated upstream isn't picked up on a machine that already has it cached. `maybe_download_model` already behaves this way; this makes the inventory step match it.

No retry on 429: the Hub API quota is shared by every process using the same token, and the test harness already retries a failed server start, so an in-process retry would add requests while the quota is exhausted. On a cache miss this path still makes exactly one `model_info()` call, as before. `resolve_safetensors_weight_set()` is unchanged; I've kept this PR narrow.

## Tests

- `pytest test/unit/test_weight_source.py`: the existing 18 tests pass with huggingface_hub 1.33.0 and 2.3.0.
- Locally against a real HF cache layout: a cached named file resolves with no Hub API call and pins the cached commit; not cached, file missing from the snapshot, a basename-only match, or no file named all fall back to `model_info()`.
- The multimodal-gen GPU suite (`wan2_2_t2v_a14b_lora_2gpu` resolves its LoRA through this path) is the end-to-end check.
