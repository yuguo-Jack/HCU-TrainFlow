## Motivation

DSpark proposes a block of γ draft tokens in one parallel forward. It then corrects them with a serial Markov walk. At step k:

```
logits_k = base_k + W2 · W1[x_{k-1}]    (rank 256, full vocabulary)
x_k      = argmax or sample of logits_k
```

The folded draft graph runs this walk as γ separate steps. Each step is a bf16 GEMM that re-reads all of W2 from HBM (78 MB at Qwen3's 151,936-token vocabulary), followed by `MarkovSampleStep`. On an H100 at γ = 7 the walk costs 269 µs per round at bs = 1 and 453 µs at bs = 64; at γ = 16 and bs = 1 it costs 608 µs.

This PR adds an opt-in replacement for that walk, for every draft graph bucket up to bs = 64:

- one persistent cooperative launch runs all γ steps;
- an int8 copy of W2 is spread over the SMs: each keeps most of its share in shared memory and streams the rest from L2;
- the bias is computed with exact int32 tensor-core dot products;
- each step's tokens are chosen across all SMs with one atomic `{key, count}` exchange per request.

Results:

- The walk alone runs 3.3-6.5x faster than the default walk (table below).
- End to end, client output throughput rises by 1.2-9.0% on six real target / drafter pairs (table below).
- Greedy outputs are unchanged. Sampled outputs are exact up to the draft noise approximations, a total variation of about 1e-5 per draft token (see Accuracy Tests).

## Modifications

### Kernel

One JIT kernel, sm_90a only, in `python/sglang/kernels/jit/csrc/speculative/dspark_markov_walk.cuh`, for every bs from 1 to 64:

- **Tensor cores:** `wgmma` m64n64k32 s8, with the W1 rows of the requests' previous tokens as the register A operand and W2 as the shared-memory B operand. 32 requests per block, two blocks over the 4 warpgroups.
- **W2 layout:** 64-row tiles, max(18, ceil(V / (#SMs x 64))) of them per CTA and at most 32. Each CTA keeps 11 tiles resident in shared memory and streams the others from L2 through a 2-slot TMA ring. On an H100 SXM, 18 tiles per CTA cover 152,064 rows (Qwen3's 151,936); Qwen3.6's 248,320 takes 30.
- **Greedy:** argmax of the bf16-rounded logits.
- **T > 0:** a sample from the same bf16 logits the kernel writes to `corrected_out`; only rows with T > 0 are written. The kernel picks an 8-row item by Gumbel-max over its mass and the row inside it by inverse CDF. The noise uses MUFU log / exp approximations.

Graph buckets above 64 keep the default walk: the kernel maps two 32-request blocks onto its 4 warpgroups, and its exchange polls two requests per lane of one warp.

### Python and launch support

- **`LaunchKernel::enable_cooperative()`** in `jit/include/sgl_kernel/utils.cuh` sets the cooperative launch attribute. The driver rejects the launch if the grid cannot be co-resident.
- **`kernels/ops/speculative/dspark/markov_walk.py`** adds `MarkovWalker`. It:
  - quantizes W1 and W2 once, with per-row scales, in chunks;
  - lays out the W1 rows and W2 tiles for the SM count;
  - loads the JIT module;
  - warms the kernel up before CUDA graph capture.
- One `KernelSpec` is registered, with capability sm_90 only.

### Integration

Changes are in `dspark_draft_sampler.py`, behind `SGLANG_DSPARK_OPT_INT8_MARKOV_WALK=1` (the walker is passed to `DsparkDraftSampler` as the NVIDIA megakernel's draft sampler is):

- The folded draft graph calls the walker for the graph buckets up to bs = 64. Larger buckets keep the default walk.
- The kernel reads the staged step temperatures (0 on argmax rows), so one captured graph serves greedy and sampled requests. With the default sampling draft it writes the step logits that the sampling accept reads; with `SGLANG_DSPARK_USE_GREEDY_DRAFT=1` it only takes the argmax.
- Staging writes the first bs rows of a padded bucket; when bs shrinks, the stale step temperatures of the rows past it are reset to 0, so the kernel walks padding rows greedily.
- The noise is keyed by the draft noise key (`DraftNoise.key`).
- At TP > 1 every rank runs the whole walk, as the default walk does: the draft already gathers the base logits over the vocabulary on every rank. Rank 0's draft tokens are broadcast once per round under `SGLANG_SPEC_TP_SYNC` (the default walk broadcasts after every step).
- With the walker on, online weight updates are refused with a reason (`_derived_weight_cache_error`).

With the flag set, the server fails at startup with the reason in any of these cases:

- the GPU is not sm_90;
- `markov_w2` is vocab-sharded over the TP ranks (`SGLANG_DSPARK_OPT_MARKOV_W2_TP_SHARD`);
- the NVIDIA megakernel plugin provides the draft sampler;
- the block-accept estimator is enabled;
- the markov head's bias is not exactly the `markov_w2` GEMV of `W1[prev]`, i.e. its `greedy_w2_weight()` is None, as for the gated, RNN, Nemotron and DeepSeek-V4 heads;
- the markov rank is not 256;
- the markov vocab differs from the lm_head vocab, or the lm_head vocab is padded;
- the lm_head is not bf16;
- γ is above 256 (the Philox counters give the step 8 bits);
- the vocabulary needs more than 32 tiles per CTA, or is not a multiple of 8;
- the JIT build or the warmup fails.

Without a folded draft graph (e.g. `--disable-cuda-graph`) the flag has no effect, as for the other DSpark draft-graph options. When the walker is built, tp_rank 0 logs `Build DSpark int8 markov walk end. max_bs=..., elapsed=... s, mem usage=... GB.`

Other changes:

- `dspark_block_accept_estimator.py` factors out `block_accept_estimate_enabled()`, so the startup check and the recorder use the same condition.
- Tests and a benchmark, described below.
- No new CLI flag, and no change to the verifier or to rejection sampling.

## Accuracy Tests

### Why outputs are unchanged

- **Greedy:** verification compares the draft tokens with the target's argmax (`AcceptGreedy`). The draft tokens can only change how many tokens get accepted.
- **Sampling:** the sampling accept rebuilds the draft probabilities as q = `SoftmaxTemp(step logits, draft temperature)`, and the kernel draws from exactly the bf16 logits it writes there. The noise is approximate: the Gumbel variable of the item draw, computed with MUFU logs, has a maximum error of 1.3e-5 in log2 units (9.0e-6 in nats). That puts each item's draw probability within a factor exp(+-1.8e-5) of its mass under q, a total variation of at most about 1e-5 per draft token. The `ex2.approx` / `lg2.approx` item masses and the 2^-23 inverse-CDF grid inside an 8-row item are of a smaller order. The accepted output is biased by at most that much.
- **Drafts are not bit-identical to the default walk's.** W2 is int8 (0.58% relative error on `deepseek-ai/dspark_qwen3_4b_block7`), so near-ties can flip.

### Kernel unit tests

`test/registered/kernels/ops/speculative/test_dspark_markov_walk.py` uses synthetic weights at 18 tiles per CTA (151,936 rows on 132 SMs) and at 30 (248,320 rows), with one and two 32-request blocks. It checks:

- greedy replay against the kernel's int8 arithmetic, bit for bit;
- greedy against a float64 dequantized reference (mismatches only at near-ties);
- bit-exact corrected logits on T > 0 rows of a mixed batch, with greedy rows left untouched;
- a χ² test of the sampled tokens (8,000 draws per case, p > 1e-4). At 90% power it detects a deviation of about 6-10% relative in the binned probabilities, e.g. a wrong temperature, a broken transform, or noise reused across requests or launches. The ~1e-5 of the noise approximations is far below what it can see; the bound above covers it;
- rows containing NaN or inf;
- fresh noise on every CUDA graph replay;
- γ = 40 over three consecutive rounds (the exchange state is sized by γ);
- host-side argument checks.

Result: 17 passed.

### E2E test

`test/registered/spec/dspark/test_dspark_int8_markov_walk.py` (Qwen3-4B with `deepseek-ai/dspark_qwen3_4b_block7`, `--enable-deterministic-inference`) is registered in the extra tier (`extra-a`, two server launches, about 200 s), to run with `/rerun-test` when this code changes. It checks that:

- the walker attaches to the folded graph;
- greedy output, as a batch of 32 and as 8 single requests, is identical to the default walk's;
- the sampling acceptance length of a concurrent batch of 16 is within 10% of the default walk's; the batch passes through smaller buckets as its requests finish.

Result: 3 passed (acceptance length 4.691 default, 4.675 int8 walk). Run locally with `--tp-size 2` appended, it also passes (4.662 / 4.571).
