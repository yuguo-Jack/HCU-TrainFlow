# [Fix] spec: Build DFlash draft layers under their checkpoint names and refuse tensors the draft would drop

[Upstream PR](https://github.com/sgl-project/sglang/pull/40884) · state: open · merged: False

## Original PR description

## Motivation

A quantized DFlash draft is built from its quantization config by module name and loaded by tensor name, and the two did not see the same names. `DFlashDraftModel` gave every decoder layer an empty prefix unless the checkpoint was a Nemotron 3.5 draft, so quantization matching saw a bare `qkv_proj`, `o_proj`, `gate_up_proj`, `down_proj` for all layers. Name-based `ignore` entries such as `re:.*self_attn\.q_proj$` never applied, the attention projections were built as quantized layers, and `load_weights` then dropped the checkpoint's BF16 `q_proj`/`k_proj`/`v_proj` tensors without a word because the fused module had no `.weight` to put them in. The packed weight went into attention uninitialized. With the W8A16 draft from the recipe below, built from the official `z-lab/Qwen3.8-27B-DFlash2`, main hits a device-side assert (`srcIndex < srcSelectDimSize` in `indexSelectSmallIndex`) on the server's own warm-up request, after a startup that only logged `DFLASH fused KV materialization disabled: quantized qkv_proj is not supported for this path`.

The second half of the same problem is `fc`: outside the Nemotron path it was a plain `nn.Linear`, so a checkpoint that quantizes `fc` (`fc.weight_packed` / `weight_scale` / `weight_shape`, or FP8 `fc.weight` + `weight_scale_inv`) had those tensors dropped the same way and `fc` kept its random init, so the draft would propose from a random projection of the target's hidden states. Several of the quantized DFlash2 drafts published on the Hub for Qwen3.8-27B quantize `fc` as well.

## Modifications

`python/sglang/srt/models/dflash.py` only:

- A draft whose own checkpoint is quantized, meaning its `config.json` carries a `quantization_config`, builds every decoder layer with `layers.{i}` (or `{prefix}.layers.{i}`), as Nemotron drafts and drafts whose class sets `supports_quantization` (LiLiCorr, #42057) already do. A quantization config then matches the same names the checkpoint uses.
- `packed_modules_mapping` on the draft model class, which the loader already injects into the quant config, so an `ignore` list that names `q_proj`/`k_proj`/`v_proj` or `gate_proj`/`up_proj` applies to the fused module. llm-compressor writes the shard names it was given, as in the recipe below. As for every other model with such a mapping, an ignore list that names a single shard now fails with the fused-layer scheme mismatch error instead of matching nothing.
- The same drafts build `fc` as a `ReplicatedLinear` with the quant config, as those drafts already do. Any other draft is built as on main, with empty layer prefixes and a dense `nn.Linear` `fc`. That includes an unquantized draft that inherits the target's `--quantization`: with `--quantization fp8` its other linears are already quantized online on main, and a quantizable `fc` would have become FP8 as well. The check reads `config.json` only, so a draft described only by `hf_quant_config.json` is also built as on main, and a quantized `fc` tensor in it is now refused, as described below, instead of being dropped.
- The `fc.weight` shape check keeps the packed-aware form and `encoder.fc.*` vendor names alias to `fc.*`. `load_weights` refuses a checkpoint that fills the decoder layers but never `fc`: a quantizable `fc` starts uninitialized, and a dense one left at its random init gave unusable drafts before as well. A projector-only load, as Domino does, is unaffected.
- `load_weights` refuses a checkpoint tensor whose module the draft has, under a parameter name that module does not have (a dense tensor for a packed layer, or a packed tensor for a dense layer, under the draft's own or the vendor `encoder.` name), with the module's actual parameter names in the message. Tensors for modules the draft does not have are still ignored, and so are the ones that have no draft parameter by design: `.bias`, the `.inv_freq` / `.cos_cached` / `.sin_cached` rotary caches, and the `.input_scale` / `.output_scale` / `.k_scale` / `.v_scale` / `.kv_scale` activation and KV-cache scales.
- New CPU test `test/registered/unit/spec/test_dflash_quantized_draft_layout.py`: the layer names through the real decoder layer, the shard-only ignore list reaching the fused projection, `fc` quantized / ignored / dense, an unquantized draft under an inherited online FP8 config keeping main's names and dense `fc`, packed and dense `fc` loading (own and vendor name), the two refusals, and the tensors that must still be ignored. On main 8 of the 13 cases fail.

## Accuracy Tests

Unit tests (CPU): `test_dflash_quantized_draft_layout.py` 13 passed (8 fail on main); `test_dflash_logits.py`, `test_dflash_domino.py`, `test_oot_dflash_hooks.py`, `test_dflash_extra_buffer_lazy.py`, `test_dflash_overlap_hostsync.py`, `model_runner_components/test_spec_aux_hidden_state.py` 51 passed. The branch is rebased onto 26a1377, after #42057, and these CPU tests were re-run there.

The quantized draft is built from the official `z-lab/Qwen3.8-27B-DFlash2` with llm-compressor's model-free PTQ: INT8 weight-only for the MLP, `o_proj` and `fc`, with q/k/v, the candidate selector and the convolution kernels left BF16:

```python
# llmcompressor==0.14.0, data-free round-to-nearest, runs on CPU
from llmcompressor import model_free_ptq

model_free_ptq(
    model_stub="z-lab/Qwen3.8-27B-DFlash2",
    save_directory="Qwen3.8-27B-DFlash2-W8A16",
    scheme="W8A16",
    ignore=["re:.*self_attn\\.(q|k|v)_proj$", "re:.*candidate_selector.*",
            "re:.*kernel_projection$", "re:.*norm.*"],
)
```

The target is `Qwen/Qwen3.8-27B` with a W4A16 body from the same tool and its `lm_head` left BF16, so that this change is tested on its own.

<details>
<summary>Target recipe</summary>

```python
# llmcompressor==0.14.0, data-free round-to-nearest, runs on CPU
from compressed_tensors.quantization import QuantizationConfig, QuantizationScheme
from compressed_tensors.quantization.quant_scheme import W4A16
from llmcompressor import model_free_ptq

model_free_ptq(
    model_stub="Qwen/Qwen3.8-27B",
    save_directory="Qwen3.8-27B-W4A16",
    config=QuantizationConfig(config_groups={
        "body": QuantizationScheme(targets=["Linear"], **W4A16),
    }),
    ignore=["lm_head", "re:.*visual.*", "re:.*mtp.*", "re:.*in_proj_(a|b)$", "re:.*conv1d.*",
            "re:.*norm.*", "re:.*embed_tokens.*"],
)
```
</details>
