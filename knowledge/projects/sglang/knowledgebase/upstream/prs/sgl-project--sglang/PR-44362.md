# [Fix] [AMD] kimi-k3: Load the fused KDA decode when the FlyDSL source is aiter

[Upstream PR](https://github.com/sgl-project/sglang/pull/44362) · state: open · merged: False

## Original PR description

## AITER prerequisites

- [ROCm/aiter#6026](https://github.com/ROCm/aiter/pull/6026) — fused KDA decode on gfx950, exported as `flydsl_kda_decode_with_f_b` and `is_flydsl_kda_decode_supported`.

This stays off the measured hot path, which compiles the vendored SGLang kernel (`SGLANG_OPT_HIP_K3_FLYDSL_SOURCE=sglang`).

## Motivation

With `SGLANG_K3_FLYDSL_SOURCE=aiter`, the Kimi-K3 fused KDA decode loads `aiter.ops.flydsl.kimi_k3_kda_decode`, which no AITER release ships. ROCm/aiter#6026 exports the same kernels from `aiter.ops.flydsl` as `flydsl_kda_decode_with_f_b` and `is_flydsl_kda_decode_supported`, so the fused path silently stays off on AITER.

## Modifications

- Resolve the decode and its support predicate by the vendored names first, then by the names ROCm/aiter#6026 exports.
- Import `aiter.ops.flydsl` for the `aiter` source.
- Read the fused-backend switch as `SGLANG_OPT_HIP_K3_KDA_FUSED_BACKEND`. `SGLANG_ROCM_K3_KDA_FUSED_BACKEND` remains a deprecated alias.
- Keep the backend off when AITER predates #6026 instead of failing on a missing attribute.
- Test the name resolution, and that the vendored and #6026 kernels agree on output, recurrent state and conv state at batch 1, 8 and 16.

## Accuracy Tests

`test/registered/kernels/ops/attention/kda_flydsl/test_kimi_k3_kda_decode.py` on MI355X with ROCm/aiter `main` plus #6026: 20 passed, none skipped. Relative RMSE between the vendored and #6026 kernels is below 1e-3; conv state matches exactly. No default changes, so no speed claim.
