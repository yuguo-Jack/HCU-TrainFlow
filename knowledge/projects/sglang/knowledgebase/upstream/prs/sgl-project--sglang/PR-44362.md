# [Perf] [AMD] kimi-k3: Run the Quark FP8 KDA in-proj and MLA absorb on FP8 kernels

[Upstream PR](https://github.com/sgl-project/sglang/pull/44362) · state: open · merged: False

## Original PR description

## Motivation

- Kimi-K3 decode on MI355X is latency-bound, and with the Quark `AttnFP8` checkpoint the KDA input projection is a large part of each step.
- Today the Quark per-channel FP8 KDA in-proj runs as one wide `[q,k,v,g]` GEMM plus separate small GEMMs for `f_a` and `b`. The BF16 in-proj merge (`SGLANG_ROCM_K3_FUSE_KDA_INPROJ`) does not apply, because a raw row concat would drop the FP8 channel scales.
- The MLA absorb dequantizes the per-channel FP8 `kv_b_proj` to BF16, so on gfx950 it runs a BF16 BMM even though AITER has an a8w8 BMM for it.
- The KDA switch names do not follow the `SGLANG_OPT_HIP_*` env var convention.

## Modifications

- **KDA input projection (Quark FP8):** `fused_qkvg_proj` reserves `[f_a | b | pad]` rows at init (192 rows per rank at TP8, so N % 64 == 0 keeps AITER's preshuffled FP8 GEMM). After load, those rows and their channel scales are filled in place, so every batch size runs one FP8 GEMM. Filling in place avoids a post-load realloc that would fragment about 1 GB per GPU.
- **MLA absorb:** on gfx950 with AITER, `kv_b_proj` is requantized to per-tensor FP8 so the absorb BMMs run AITER's a8w8 kernel. Other ROCm targets keep the BF16 dequant.
- **Env rename:** the KDA switches move from `SGLANG_ROCM_K3_*` to `SGLANG_OPT_HIP_K3_*`. The old names still work as deprecated aliases, and the new name wins when both are set.
- **Weight updates:** online weight updates are rejected while the Quark FP8 merge is active.

| Env var | Default | Effect |
|---|---|---|
| `SGLANG_OPT_HIP_K3_FUSE_KDA_INPROJ` (alias `SGLANG_ROCM_K3_FUSE_KDA_INPROJ`) | `true` | Merge the KDA in-proj: BF16 below the token limit, Quark FP8 at every batch size |
| `SGLANG_OPT_HIP_K3_FUSE_KDA_INPROJ_MAX_TOKENS` (alias `SGLANG_ROCM_K3_FUSE_KDA_INPROJ_MAX_TOKENS`) | `256` | Token limit for the BF16 merge; ignored for Quark FP8 |
| `SGLANG_OPT_HIP_K3_MLA_ABSORB_FP8` | `true` | `false` keeps the BF16 `kv_b` dequant (about 0.12% vs 2.3% weight error, at BF16 BMM speed) |

| Condition | KDA in-proj path |
|---|---|
| `q,k,v,g`, `f_a`, `b`, `f_b` all Quark per-channel FP8 with dynamic activations | Merged FP8 GEMM at every batch size |
| `[q,k,v,g]` resolves to a different quant method (e.g. excluded) | Split projections, as before |
| Unquantized BF16/FP16 weights | BF16 merge at <= `_MAX_TOKENS` tokens, as before |
| `SGLANG_OPT_HIP_K3_FUSE_KDA_INPROJ=0` | Split projections |
| Already-processed restore (ShardedStateLoader) with the merged tail | Keeps the tail; `f_b` runs on `f_b_proj` |
| Restored state that was saved without the tail | Load fails with an error that asks for the same env setting at save and load |

## Accuracy Tests

- Setup: sgl-eval 0.1.3, Kimi-K3 preset, K3 integration build, TP8, DSpark block 3. "Off" and "on" toggle both switches together.

| Eval | Both off | Both on |
|---|---:|---:|
| GSM8K, 1,319 questions, mean of 3 runs | 97.24% | 97.24% |
| MMLU-Pro, first 1,000 questions, 1 run | 87.6% | 88.6% |
| Mean acceptance length (max 4) | 3.16 | 3.18 |

- Numerics: merged `q,k,v,g` and `f_a` match the separate projections bit for bit. Beta error goes from 0.2-0.3% to about 2.7%; forget-gate error goes from about 3.7% to about 2.7%. The MLA requant adds about 2.3% weight error vs BF16.
- Unit tests: `test/registered/unit/models/test_kimi_k3_rocm_quant.py`, `test/registered/unit/test_environ.py`, and `test/registered/amd/test_kimi_k3_kda_inproj_fusion.py` (MI355X): 48 passed.

## Speed Tests and Profiling

- Setup: 8x MI355X, TP8, `Kimi-K3-Quark-MXFP4-AttnFP8`, random 8,192 input / 1,024 output tokens, radix cache off, 4x concurrency requests.
- Sampling: 3 runs with both on, 1 run for every other column. Run-to-run spread is about 1%.

| Concurrency | Baseline TPOT (ms) | KDA only (ms) | MLA only (ms) | Both on (ms) |
|---:|---:|---:|---:|---:|
| 4 | 16.40 | 15.42 (-6.0%) | 16.23 (-1.0%) | 15.25 (-7.0%) |
| 8 | 19.25 | 18.15 (-5.7%) | 19.07 (-0.9%) | 18.00 (-6.5%) |
| 16 | 24.86 | 23.68 (-4.7%) | 24.65 (-0.8%) | 23.54 (-5.3%) |
| 32 | 32.77 | 31.62 (-3.5%) | 32.58 (-0.6%) | 31.51 (-3.8%) |
| 64 | 47.05 | 46.05 (-2.1%) | 46.90 (-0.3%) | 45.92 (-2.4%) |

- TPOT drops 2.4-7.0%, mostly from the KDA merge. MLA alone is within noise.
