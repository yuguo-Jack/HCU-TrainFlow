# [Fix] kt: run with zero GPU experts (--kt-num-gpu-experts 0)

[Upstream PR](https://github.com/sgl-project/sglang/pull/45188) · state: open · merged: False

## Original PR description

## Motivation

`--kt-num-gpu-experts 0` keeps every routed expert on the CPU. `KTEPWrapperMethod.apply` still calls the GPU method with the masked dispatch, which then holds zero experts. For DeepSeek-V4 / V4.1 (MXFP4 experts, FlashInfer runner), that call fails: the runner refuses a zero-expert workspace. Even where it succeeds, it launches a MoE over no experts on every layer for an all-zero result.

## Modifications

`python/sglang/srt/layers/moe/kt_ep_wrapper.py`: with `num_gpu_experts == 0`, skip the GPU method and start from `torch.zeros_like(x)`. The CPU result is added to it as before (tp rank 0), so the output is the CPU experts' sum.

## Accuracy Tests

DeepSeek-V4.1-Flash-1017 on 2x RTX 5070 Ti, TP2, `--kt-num-gpu-experts 0`. The CPU experts run on 2x EPYC 7452 with kt-kernel 0.7.0. The server loads (`GPU experts per layer: 0`) and answers a chat request coherently. The non-zero path is unchanged.

## Speed Tests and Profiling

Only the zero-expert configuration changes: one MoE launch less per layer.
