# [MemCache] Count reclaimable tokens in the unified tree ledgers

[Upstream PR](https://github.com/sgl-project/sglang/pull/43185) · state: closed · merged: True

## Original PR description

## Motivation

The unified radix tree's evictable and protected ledgers are consumed in the allocator's units: prefill admission adds the evictable ledger to the allocator's free space, and the device eviction walk counts what each node frees toward its request. The ledgers were kept in value length (`len(cd.value)`), which is only right when a component's device value is backed one-to-one by pool rows.

A component plugged in through `component_registry_override` whose values are not (for example one that lists several entries per pool row, or that hands rows of a resident node back to the allocator while the value stays on device) over-promises free space and under-counts eviction progress: the tree claims more than an eviction can give back, and there was no way for the component to say otherwise.

## Modifications

- `TreeComponent.reclaimable_tokens(node)`: pool tokens the allocator gets back when the node's device value is evicted. Defaults to `value_len(node)`, so the built-in components behave exactly as before.
- Every ledger site of the Python tree core and the FULL component reads it instead of the value length: new-node creation, re-materialization of an evicted value, `set_component_device_value`, segment lock acquire and release, device eviction progress, and the recount in `sanity_check`.
- `UnifiedTreeCore.adjust_component_ledger(node, component_type, delta)`: when a component's figure for a resident node changes in place (no lock transition), it moves whichever ledger the node is on by `delta`; a tombstoned value is on neither.
- Test: `TestUnifiedRadixComponentLedgerUnits` registers a FULL subclass that reports half its value length and checks the ledgers against the `sanity_check` recount through insert, lock, an in-place change, release and eviction. On main it fails at the first assertion (ledger 8, expected 4).

Scope: the SWA and Mamba components keep their own `len(value)` arithmetic, which is what their default reports. The Rust TreeCore is unaffected; it already rejects `component_registry_override`.

## Accuracy Tests

Not applicable: no change to model outputs. The default `reclaimable_tokens` is the value length, so built-in components take the same code path with the same numbers.

## Speed Tests and Profiling

Not applicable: one extra method call per ledger update on the Python tree core.
