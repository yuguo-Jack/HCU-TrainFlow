# [Fix] [AMD] deterministic: Bypass AITER GEMM and MoE in deterministic mode on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/43788) · state: closed · merged: True

## Original PR description

## Motivation

This PR makes `--enable-deterministic-inference` deterministic on MI350X/MI355X (gfx950) with AITER enabled, the default in the ROCm images. In deterministic mode it keeps unquantized linear and MoE layers off AITER's GEMM and fused-MoE kernels, which pick a different kernel depending on the batch size. Those layers use SGLang's batch-invariant matmul and Triton MoE runner instead, as the CUDA path already does.

**Which models this affects.** Every unquantized (bf16) linear or MoE layer on gfx950 in deterministic mode, so not only bf16 checkpoints but also the bf16 layers inside quantized ones:

- **gpt-oss** (20b, 120b): the attention projections and the router are bf16 (the experts are MXFP4 and go through ROCm/aiter#6583). Without this PR, gpt-oss-20b and -120b in deterministic mode give 50 and 47 different outputs for 50 identical requests; with it, one (below).
- **Qwen3.8 / Qwen3.5** (bf16 checkpoints): every linear, including the Gated DeltaNet projections. With the GDN fixes (#44076, #44194, #44195) Qwen3.8-27B is deterministic with this PR and not without it (table below).
- **MiniMax-M3**: its unquantized layers (for example the router); MiniMax-M3 passes every exact check at TP2/TP4 with this PR, ROCm/aiter#6583 and #46397/#46786.
- **DeepSeek-V4.x, GLM-5.3**: their unquantized layers take the same path, but these models are not deterministic yet for other reasons (FP8 block-scale and MXFP4 GEMMs), so this PR is one prerequisite there.

The numbers below use gpt-oss-20b/-120b and Qwen3.8-27B, plus Qwen3-8B, the model AMD CI's deterministic test runs.

Today, unquantized linear layers call AITER's GEMM directly, and unquantized MoE layers use AITER's CK fused-MoE. Both choose the kernel, tile and split-K from the number of tokens, and neither goes through the batch-invariant `aten::mm`. So a request's log-probabilities change with whatever else is in its batch. For example, Qwen3-8B's QKV projection runs four different kernels at M = 1, 60, 32 and 1920.

This is the ROCm counterpart of an existing rule in the same file. On Blackwell, deterministic mode resolves `--bf16-gemm-backend auto` to `torch` instead of `cutedsl`, and rejects an explicit `cutedsl` as batch-size dependent (#33945). AITER's GEMM and fused MoE are batch-size dependent in the same way, by design: they are tuned per token count. ROCm had no equivalent rule, and AMD CI runs the deterministic test with AITER on only on MI300, so this went unnoticed.

If AITER later offers a batch-invariant mode for these kernels (as ROCm/aiter#6583 does for the MXFP4 MoE), deterministic mode can call AITER with it instead of skipping it; the check added here is where that switch would go.

## Modifications

- `unquant.py`: in deterministic mode on gfx95, unquantized linear and MoE layers skip AITER and use the batch-invariant matmul and the Triton MoE runner. The decision is made once per layer and applies to the GEMM branch, the expert-weight shuffle and the MoE runner selection.
- An explicit `--moe-runner-backend aiter` with deterministic mode on gfx95 now raises a clear error, like the existing `cutedsl` check.
- `test_deterministic.py`: also registered on the MI35x per-PR suite (`stage-b-test-1-gpu-small-amd-mi35x`) as the regression test.
- Unchanged: serving without the flag, other GPUs (including MI300), quantized layers and all other AITER kernels.

With tensor parallelism, determinism also needs the all-reduce fix in #34543.

## Accuracy Tests

1x MI350X (gfx950), newest nightly `rocm/sgl-dev:v0.5.21-rocm724-mi35x-20261011`, comparing the image's `unquant.py` (before) with this PR's (after). TP1, `--attention-backend triton --enable-deterministic-inference`, `SGLANG_USE_AITER=1`. Checks: `python3 -m sglang.test.test_deterministic --test-mode prefix --return-logprob` and `--test-mode radix_cache` (50 trials), plus a bitwise comparison of 1,275 responses (batch sizes 1-50) against batch size 1.

| Model | Before | After (this PR) |
| --- | --- | --- |
| Qwen3-8B | 107/1275 bitwise-identical; prefix and radix_cache fail | 1275/1275; all pass |
| Qwen3-30B-A3B | 1/1275 bitwise-identical; prefix and radix_cache fail | 1275/1275; all pass |
| gpt-oss-20b (with ROCm/aiter#6583 and #44868; see below) | 1/1275 bitwise-identical; `single` 50 distinct outputs of 50; prefix, prefix logprobs and radix_cache fail | 1275/1275; all pass |
| gpt-oss-120b (same setup) | 2/1275 bitwise-identical; `single` 47 distinct outputs of 50; prefix, prefix logprobs and radix_cache fail | 1275/1275; all pass |
| Qwen3.8-27B (with #44076, #44194, #44195) | logprobs identical in 9/1275 (token IDs 1123/1275); `single` 3 distinct outputs; prefix, prefix logprobs and radix_cache fail | 1275/1275; all pass |

- **Regression test:** `test/registered/attention/test_deterministic.py` (`TestTritonDeterministic`), run with AMD CI's environment (`SGLANG_USE_AITER=1`) on MI350X. Before: both tests fail (`single` gives 7 different outputs for 20 identical requests; `prefix` log-probabilities differ). After: `OK`.
- **AITER dispatch:** with the flag, the Qwen3-8B server no longer calls AITER's tuned GEMM (847 calls logged before, 0 after). Without the flag, the same 116 calls before and after.
- **Explicit backend:** `--moe-runner-backend aiter` with the flag now stops at startup with `ValueError: --moe-runner-backend aiter is batch-size dependent and cannot be combined with --enable-deterministic-inference on gfx95`.
- **gpt-oss and Qwen3.8 runs:** MI350X, `rocm/sgl-dev:v0.5.22-rocm724-mi35x-20261021`, TP1, `--enable-deterministic-inference`; gpt-oss also with ROCm/aiter#6583's deterministic MXFP4 MoE and `--disable-hybrid-swa-memory` (#44868), Qwen3.8 with the GDN fixes; our other open deterministic-mode changes applied in both runs, so the only difference is this PR's `unquant.py`. GSM8K before / after: gpt-oss-20b 95.22% / 94.54%, gpt-oss-120b 95.68% / 96.13%, Qwen3.8-27B 96.21% / 96.13% (within noise).
- **GSM8K** (1,319 questions, greedy, thinking off): Qwen3-8B 93.48 -> 93.56. Qwen3-30B-A3B 94.47 -> 94.77, from earlier runs on the 20261006 image. Within noise.

## Speed Tests and Profiling

1x MI350X, `rocm/sgl-dev:v0.5.21-rocm724-mi35x-20261006`, before and after on the same node. Deterministic mode only, ISL/OSL 1024/1024, 256 prompts, concurrency 256, median of 3 interleaved runs (output tok/s):
