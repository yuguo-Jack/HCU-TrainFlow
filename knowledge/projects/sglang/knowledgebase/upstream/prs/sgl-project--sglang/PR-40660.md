# [AMD] diffusion: expect the residual-gate fast path to be off on ROCm in test_modulate

[Upstream PR](https://github.com/sgl-project/sglang/pull/40660) · state: closed · merged: True

## Original PR description

## What

Update `test_modulate.py` so its residual-gate tests expect the CUDA fast path to be unavailable on ROCm.

## Why

#42391 made `can_use_residual_gate_add_cuda` return False under HIP. Several cases in `test_modulate.py` still assert that the fast path is selected, or call `residual_gate_add_cuda` directly. The file is registered in `nightly-amd-kernel-1-gpu`, so on ROCm those cases now assert the opposite of what the code does.

On ROCm:
- `test_residual_gate_add_matches_torch` and `test_residual_gate_add_guards_and_eager_fallback` assert that the fast path is rejected, and still check that `residual_gate_add` matches the eager expression.
- The dtype, transposed-layout, storage-offset, `torch.compile` and CUDA-graph cases that exercise the CUDA kernel directly are skipped.

NVIDIA behavior is unchanged.

This PR originally also gated the residual-gate path in `residual_gate_add_jit.py` and relaxed a LoRA comparison in `test_qwen_image21_cuda.py`. #42391 covered both: it added the HIP check itself and skips that test file off NVIDIA. After merging main, those two files no longer differ from main.

## Test plan

ROCm, MI300, rocm10, at `9578a6ed`: [nightly-test-1-gpu-kernel](https://github.com/sgl-project/sglang/actions/runs/38520223601/job/115707994833).
- `test_residual_gate_add_matches_torch` (12) and `test_residual_gate_add_guards_and_eager_fallback` (1) pass. Both fail on main before this PR ([scheduled nightly](https://github.com/sgl-project/sglang/actions/runs/38440667473)).
- The 22 cases that call the CUDA kernel directly are skipped.
- The job is still red from other cases in this file that also fail on main and aren't touched here (`test_timestep_embedding_matches_diffusers`, `test_residual_gate_add_batched_rows`, `test_modulate_scale_shift_*`, `test_scaled_residual_add_is_bit_exact`). The file goes from 139 failing cases to 104; the rest will be fixed in a follow-up.
