# [Perf] Cache schema type normalization and defer the template tool dump

[Upstream PR](https://github.com/sgl-project/sglang/pull/47010) · state: open · merged: False

## Original PR description

## Motivation

Two per-request costs in the chat serving path scale with tool count and repeat identically every turn (177 medium tool schemas, Xeon 8124M, medians):

1. **`normalize_json_schema_types` re-walks every tool schema on every request** — 6.9 ms even when every type is already standard, 11.6 ms when aliases apply. It runs synchronously in `_validate_request` on the event loop, including for `tool_choice="none"`.
2. **The template-only `Tool.model_dump()` runs even when no Jinja render will consume it** — 5.3 ms for requests that supply `input_ids` or use a conversation template, and on the muse path where the dump is discarded.

## Fix

**Normalization: rewrite-plan cache.** `normalize_json_schema_types` now keys on the exact pre-mutation schema bytes (orjson, insertion order — exactness, not canonicalization) and replays a cached plan of `(path, new_type)` rewrites onto the request's own objects:

- Standard schemas: 6.9 → **0.66 ms** warm (cost floor is the 0.67 ms key itself); alias schemas: 11.6 → **2.1 ms**.
- The in-place mutation contract is preserved exactly — callers holding `tool.function.parameters` see the rewrite, and no decoded 450 KB blob changes hands. Cached plans are tuples of paths + bytes; every applied value is freshly decoded, so nothing mutable is shared across requests.
- Inputs orjson cannot serialize (non-str keys, lone surrogates, >64-bit ints, cycles) and schemas over 64 KiB fall back to the plain walk; cycles still surface as `RecursionError` into the existing 400 path. `lru_cache(1024)` with the 64 KiB key cap bounds retained keys at ~64 MiB/worker.

**Template dump: deferred.** The template-tool computation moves into `_jinja_template_tools()`, called only in the `chat_template_name is None` branch. Selection semantics unchanged (named choice → subset, muse → `_template_tools`); equivalence verified on 132 request shapes.

## Tests

- New `test_repeated_schema_rewrites_each_fresh_object`: a resent schema is rewritten from the cache onto that request's own objects; mutating the first request's rewritten list does not leak into the second request. Fails pre-fix (symbol missing) and against two broken variants (shared mutable values, skipped replay).
- Correctness corpus: old walk vs new, deep-equal AND byte-equal (key order) on miss and hit across 177 standard + 177 alias schemas (varchar/enum/int/dedup/decimal-in-anyOf/nested `$defs`) + 13 edge shapes (boolean subschemas, non-str `type`, top-level list) + fallbacks.
- `test_serving_chat.py`: 173 passed / 255 subtests. Broader `entrypoints/openai` + `function_call` suites: identical failure sets to clean main (all local-env: missing deepseek_recipe/torchaudio, old xgrammar in venv).
- `pre-commit run --files`: clean.

Not in scope: combining this with the `check_json_schema` cache (#46818) behind one serialization (needs a non-finite-float guard on the validation side; noted as follow-up), and sharing the xgrammar-bound tool dump (different strict/subset flavors; workstream on the constraint path covers it).
