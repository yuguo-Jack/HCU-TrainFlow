# [Fix] sgl-router: Receive kv-indexer-bridge event batches outside tokio's coop budget

[Upstream PR](https://github.com/sgl-project/sglang/pull/44305) · state: closed · merged: True

## Original PR description

## Motivation

`kv-indexer-bridge` never finishes a ZMQ batch over about 1 MiB: it spins at 100% CPU, events back up in the socket, and the router silently loses cache affinity. Such batches come from long contexts with large pages, since every `BlockStored` carries its `token_ids` (e.g. 1,800 events with 256 tokens each is ~1.4 MB).

zeromq's fair queue re-polls a woken stream within the same poll. Once tokio's cooperative budget runs out mid-message, each read returns `Pending` and wakes itself at once, so the task never yields and the budget never resets.

## Modifications

- Receive batches with `tokio::task::unconstrained`.

## Speed Tests

One bridge and one indexer, 54,000 events (30 batches of 1,800) published by pyzmq:

| | with 256 token ids (40 MB) | without token ids (4.9 MB) |
|---|---|---|
| main | not indexed after 600 s | 0.11 s |
| this PR | 0.22 s | 0.11 s |
