# [Fix] [AMD] GLM5: Fix MTP layer_quant_config in-place mutation and add nextn Quark-exclude unit test

[Upstream PR](https://github.com/sgl-project/sglang/pull/30565) · state: open · merged: False

## Original PR description

## Motivation

Follow-up to #30265 / #29781 (supersedes #30379). #30265 merged with two gaps flagged in its own review:

1. The GLM-5.2 Quark-MXFP4 MTP path has **no PR-CI coverage** — the only AMD GLM-MXFP4 test is `nightly=True` and does not enable MTP; the GLM MTP e2e test is CUDA-only + FP8, not Quark MXFP4.
2. `GlmMoeDsaForCausalLMNextN._resolve_nextn_quant_config` remaps `layer_quant_config` keys by **mutating the shared `quant_config` in place**, which can corrupt the main model's per-layer scheme selection (gemini-code-assist review on #30265).

The fix and the CPU test here originate from #30379 (@fanxingran, co-authored).

## Modifications

- `python/sglang/srt/models/glm4_moe.py`: `_resolve_nextn_quant_config` `copy.copy`s `quant_config` (and its nested dict) **before** any remap, and only copies when a remap/exclude is actually needed — no shared-state mutation.
- `python/sglang/srt/models/deepseek_nextn.py`: docstring on the base `_resolve_nextn_quant_config` documenting the subclass override contract.
- `test/registered/unit/models/test_nextn_quark_exclude.py` (new, CPU CI `base-a-test-cpu`): base `DeepseekV3ForCausalLMNextN` passthrough (non-quark / `None`), GLM-5.2 MTP `exclude_layers` + `layer_quant_config` remap, coarse fused-expert prefix, and the no-mutation guarantee.
- `test/registered/amd/accuracy/mi35x/test_glm52_mxfp4_mtp_eval_mi35x.py` (new, nightly `nightly-amd-8-gpu-mi35x-glm52-mxfp4-mtp`): 8-GPU GLM-5.2-MXFP4 EAGLE-MTP GSM8K eval — GPU coverage that the bf16 nextn layer loads under Quark MXFP4 and MTP accepts drafts. Wired into `nightly-test-amd.yml` and `nightly-test-amd-rocm720.yml`.
