# [Perf] qwen: Add experimental L2 weight prefetching around TP AllReduce

[Upstream PR](https://github.com/sgl-project/sglang/pull/47259) · state: open · merged: False

## Original PR description

## Motivation

Explore whether prefetching upcoming GEMM weights into GPU L2 during TP AllReduce can hide part of the later memory access cost for small decode/verification steps.

This PR provides the original opt-in experiment for review and reproduction with **qwen3.8-27b-nvfp4**. Historical service tests used SGLang 0.5.22. End-to-end serving smoke validation also passed on upstream main commit `5007cbd6a57515bf5e008ff2fd2bdb834356b53c`.

## Modifications

- Add the research patch under `benchmark/experimental/decode_l2_prefetch/`, activated explicitly through PYTHONPATH and `SGLANG_DECODE_L2PF=1`.
- Preserve the original **16/32 MiB budgets and lazy join**. Model hooks register upcoming weights, a side CUDA stream issues prefetches around AllReduce, and joins are deferred until the next collective or forward exit.
- Include bulk-prefetch and load-based kernels, reproduction instructions, and manual GPU checks.
- Default serving behavior is unchanged. The executable algorithm matches the original experiment; only comments and formatting changed.
- Document cache-hint semantics, possible GEMM contention, and the row-count gate, which can also admit small prefill inputs.

## Accuracy Tests

Passed on RTX 5090 in the SGLang 0.5.22 CUDA 13 environment:

- Bulk and load-based prefetch in eager execution and CUDA Graph capture/replay, with unchanged weight buffers.
- Weight-plan budget and duplicate-pointer handling, plus exclusion of non-contiguous, small, and CPU buffers.
- Disabled startup without importing the patch or torch.
- Repository pre-commit checks for all four files.

Current-main serving validation used qwen3.8-27b-nvfp4, TP=2, two RTX 5090 GPUs, NVFP4 weights, FP8 KV cache, DFlash, FlashInfer 0.7.2, and sglang-kernel 0.4.10. Native and original-patch runs each completed 8 requests at concurrency 1/4/8 with 128 output tokens per request: **48/48 requests passed, and all 24 paired output-token sequences matched**. All 6,144 output-token log probabilities were finite. Both target workers armed 128 AllReduce sites and recorded `pf=3200, skip=0` during graph capture; decode logs confirmed CUDA Graph execution.

This validates serving compatibility and token agreement for the eight short prompts tested. Full-set answer-quality and repeated native-control measurements are reported below.
