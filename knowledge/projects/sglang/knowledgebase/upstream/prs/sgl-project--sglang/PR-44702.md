# [Feat] model-loader: Reuse model-owned MTP rules for shard selection

[Upstream PR](https://github.com/sgl-project/sglang/pull/44702) · state: open · merged: False

## Original PR description

## Motivation

Closes #43196.

A main model and its MTP draft can share a checkpoint while requiring different weights. Existing model implementations usually filter unused tensors inside `load_weights`, after the Default Loader iterator or prefetcher has started processing files. On whole-file paths, an unnecessary shard may already have been read into memory before the model discards its tensors.

Following [vLLM #60152](https://github.com/vllm-project/vllm/pull/60152), this PR extracts existing model-owned selection rules into a reusable interface and excludes wholly unused shards before weight-payload reads and prefetch. This avoids unnecessary reads, memory copies, and tensor iteration.

The same need arose in [ModelExpress #805](https://github.com/ai-dynamo/modelexpress/issues/805). Keeping the rules in SGLang lets native loaders and downstream integrations share one implementation, instead of requiring MX to duplicate architecture-specific checkpoint naming rules and keep them synchronized with upstream changes.

## Modifications

1. **Model-owned weight selection.** Add an optional `is_unused_checkpoint_weight(name)` hook. It receives a raw checkpoint tensor name and returns `True` when the model does not use that weight. Pre-read selection and `load_weights` share the same rule, preserving shared weights and pipeline-parallel embedding requirements.
2. **Select files before Default Loader reads.** Pass the rule through `Source.is_unused_weight`, inspect safetensors headers, and retain a shard whenever it contains at least one required tensor. Apply selection before weight iteration and prefetch, preserving the original file order.
3. **Keep actual weight loading unchanged.** Renaming, quantization, fusion, parallel sharding, and parameter assignment remain in the existing model code. The generic loader has no model allowlist and does not assume an `mtp.` prefix.
4. **Preserve compatibility.** Models without the hook, non-safetensors formats, and name transformations that cannot safely map to raw checkpoint names keep their existing loading behavior. If selection rejects every shard, retain the original list so the model's existing missing-weight validation still runs.

Selection is at whole-shard granularity, not tensor-range granularity. Mixed shards containing both main and draft weights can still be selected by both roles.

## Speed Tests and Profiling

The measurements below were collected before this rebase and have not been rerun on the current head.

### Default Loader: whole-file reads

H20×8, TP=8, with checkpoints prepared locally. Each model completed one baseline/modified comparison pair with identical launch arguments on both sides, `--weight-loader-disable-mmap`, and two reader threads.

| Model | Load phase | Shards: baseline → this PR | TP0 load time: baseline → this PR |
| --- | --- | ---: | ---: |
| Qwen3.5 MTP 122B | Main | 49 → 49 | 72.44s → 67.74s |
| Qwen3.5 MTP 122B | Draft | 49 → 1 | **64.32s → 9.58s** |
| GLM-5.3 | Main | 141 → 140 | 353.49s → 350.51s |
| GLM-5.3 | Draft | 141 → 3 | **379.45s → 12.99s** |

In these comparison pairs, draft-load time decreased by **85.1%** for Qwen and **96.6%** for GLM. TP0 logical reads during draft loading decreased from **121.00 GiB to 8.38 GiB** and from **703.75 GiB to 15.00 GiB**, respectively.

Both configurations of both models completed main/draft loading on all eight ranks, passed HTTP health checks, and completed two 32-token generation requests each.

Logical read counts come from process `rchar`, not physical disk or OSS traffic. Host page cache was not cleared for these pairs. These results describe the local whole-file path and should not be interpreted as the benefit of the default mmap path.

### Default Loader: mmap

Qwen3.5 MTP 122B completed **five interleaved comparison pairs** with mmap enabled and checkpoint prefetch disabled. Before each engine launch, only the test-private checkpoint files were evicted from page cache, and `mincore` confirmed zero resident pages. Normal cache reuse between the main and draft loads was preserved.

| Metric | Baseline | This PR |
| --- | ---: | ---: |
| Draft shards | 49 | 1 |
| TP0 draft-load median | 2.34s | **0.99s** |
| TP0 draft-load range | 2.32–2.38s | 0.95–1.03s |
| Slowest-rank draft-load median | 2.68s | **1.34s** |
| Slowest-rank draft-load range | 2.64–2.73s | 1.30–1.37s |

All ten launches passed health checks and completed two fixed generation requests each. The draft-stage reduction was repeatable; main loading still selected all 49 shards.

Median engine-start-to-HTTP-health time was **265.06s → 268.07s**, so these runs do not establish an overall startup improvement. This interval includes initialization, compilation, and warmup, but excludes checkpoint preparation.

### Regression coverage

Regression coverage includes real safetensors files, selection before iterator/prefetch construction, mixed shards, shared weights, pipeline-parallel embeddings, layer-selection rules, and fallback for incompatible name transformations. Generation requests are serving-function checks, not model-accuracy evaluations.

## Scope and downstream reuse

This PR provides the model-selection interface and Default Loader integration. A companion PR applies the same interface to the separate RunAI ModelStreamer path. The reference vLLM #60152 does not cover RunAI; the corresponding vLLM RunAI integration is [#60759](https://github.com/vllm-project/vllm/pull/60759).

This PR does not change model execution, scheduling, RunAI internals, or MX P2P. It also does not change Hugging Face downloads that happen before local file resolution. MX can reuse this optimization through a framework loader entry point that passes the actual model and its selection rule, without maintaining separate checkpoint-naming rules.

## Accuracy Tests
