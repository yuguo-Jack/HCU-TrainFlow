# [Perf] disaggregation: Avoid O(N^2) watermark maintenance in StagingAllocator.free

[Upstream PR](https://github.com/sgl-project/sglang/pull/48115) · state: open · merged: False

## Original PR description

## Motivation

In `StagingAllocator` (`python/sglang/srt/disaggregation/common/staging_buffer.py`), `self.alloc_order: List[int]` was maintained alongside `self.allocations: dict` to track the oldest un-freed allocation for watermark updates:

```python
while self.alloc_order and self.alloc_order[0] not in self.allocations:
    self.alloc_order.pop(0)
```

Because `assign()` assigns strictly monotonic `alloc_id`s once at the tail of `self.allocations` and `free()` only deletes entries via `self.allocations.pop(alloc_id)`, Python's insertion-ordered `dict` already preserves the exact chronological order of all live allocations:
1. With `self.alloc_order: List[int]`, every in-order `free()` performed an $O(N)$ `list.pop(0)` shift while holding `self.lock`.
2. Worse, when disaggregated KV transfers completed out of order while an older allocation remained in flight, freed `alloc_id` tombstones stayed inside `self.alloc_order` until the head allocation finished, at which point `free()` executed a tight loop of $K$ consecutive `list.pop(0)` shifts ($O(K^2)$ time under `self.lock`).

## Modifications

- Remove the redundant `self.alloc_order` list in `StagingAllocator`.
- Read the oldest live allocation directly via `next(iter(self.allocations.values()))` in $O(1)$ worst-case time and $O(\text{active allocations})$ space.
- Add `test_out_of_order_frees_advance_watermark_to_oldest_live_allocation` in `test/registered/unit/disaggregation/test_disaggregation_wire.py`.
