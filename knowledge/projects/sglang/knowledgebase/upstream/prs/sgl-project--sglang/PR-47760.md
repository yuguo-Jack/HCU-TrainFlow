# [Fix] Log: Skip leaked user input fields (e.g. video_config._question) via nested field skip support

[Upstream PR](https://github.com/sgl-project/sglang/pull/47760) · state: open · merged: False

## Original PR description

## Motivation

Fixes #47759

At `--log-requests-level` 0/1, the request log is supposed to exclude input/output (`text`, `input_ids`, ...). However, some fields still carry it into the log:

- `video_config._question` — the OpenAI chat entrypoint copies the user's video-paired question text into it (`_build_video_config` in `serving_chat.py`, introduced by #33829); the DotsNote-Omni processor consumes it. This is triggered in the majority of video scenarios.
- `images_config.prefix` — Unlimited-OCR convention where the user's task prompt is sent inside `images_config` in the request body; the processor appends it after the image tokens

The skip-name mechanism only matches top-level field names, so nested fields cannot be skipped directly — this requires multi-level skip logic. Without it, user input data leaked into logs even at the "metadata only" level 0.

There are some other fields populated only for specific inputs may also carry input/output (e.g Output side (`meta_info`): `logprobs` (`return_logprob`=True), `prompt_token_ids` (`return_prompt_token_ids`=True)). They are **out of scope** for this PR.

## Modifications

- `skip_names` now supports dotted entries (`"parent.child"`, any depth) that skip nested fields.
- New `_child_skip_names()`: strips the current key's prefix from the skip set when recursing into a child, so skipping propagates down the tree in both serializers.
- Level 0 and level 1 skip sets add `video_config._question` and `images_config.prefix`.

Compatibility:
- Levels 2/3: unchanged (no skip names).
- OpenAI raw payload logging: unchanged (gated at level >= 2).

No docs change needed: the per-level description of `--log-requests-level` stays accurate.
