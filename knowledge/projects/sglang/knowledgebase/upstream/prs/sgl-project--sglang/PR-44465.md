## Motivation

<!-- Describe the purpose and goals of this pull request. -->

On DSV4.1 with TP only, the draft's head are split by vocab. Each GPU computes logits for its own slice, and picking a draft token never needs the whole vocab.

But verify runs rejection sampling over the whole vocab, so the draft all-gathers its logits at every step, once per draft token.

This PR keeps the draft logits on their shards and adds a support to sharded rejection sampling, so verify only exchanges a few statistics per row instead of the whole-vocab logits.

## Modifications

<!-- Detail the changes made in this pull request. -->

**Gating**
- Add `SGLANG_DSPARK_SHARDED_ACCEPT`, on by default on HIP.
- With the flag off, nothing changes.

**Draft side**
- With the sharded accept on, the draft keeps each step's logits on its own vocab shard instead of all-gathering them.

  ```python
  # python/sglang/srt/speculative/dspark_components/dspark_worker_v2.py, L328
  # Use the sharded accept only when the vocab is sharded and logits are kept.
  self._sharded_accept = (
      envs.SGLANG_DSPARK_SHARDED_ACCEPT.get()
      and not self._greedy_draft
      and markov_head is not None
      and markov_head.vocab_shard is not None
  )

  # python/sglang/srt/speculative/dspark_components/dspark_draft.py, L224
  sharded = (
      {}
      if shard is None
      else dict(
          vocab_start=shard.start,
          gather=shard.gather.gather_stacked,
          gather_logits=None if sharded_accept else shard.gather,  # skip the all-gather
      )
  )
  ```

- Pass the draft's noise to the verify, so every rank reaches the same accept decision and bonus token.

**Verify side**
- Add `sharded_accept_hip.py` with two triton kernels:
  - `_stats_kernel`: each gpu reduces its vocab shard to a few stats per row (max logit, sum-exp, the drafted token's logit).
  - `_accept_kernel`: each gpu merges the stats into p(x) and q(x) and runs the accept test. The bonus is a Gumbel-max race on each shard. The gpus exchange their candidates, and the draft's existing finish kernel picks the token.
- `accept_draft_tokens`: temperature-only batches use the sharded accept. Top-k, top-p, or block verification gather the logits once and fall back to `AcceptSampling`, matching main.

**Other**
- `dspark_block_accept_estimator.py`, `dspark_observability.py`: the block accept estimator (a diagnostic tool, off by default) skips sharded logits instead of computing on half the vocab.
