# [LoRA] Add dense and MoE execution engines with tuned plans

[Upstream PR](https://github.com/sgl-project/sglang/pull/42284) · state: open · merged: False

## Original PR description

## Motivation

Add explicit, architecture-aware LoRA execution plans for dense and routed-MoE layers, sharing routing preparation between eager execution and CUDA graphs.

## Modifications

- Add the BF16 MoE engine, FP8/NVFP4 providers, and per-expert/shared-outer adapter execution.
- Add the opt-in dense `triton_v2` backend, specialized kernels, and SM90/SM100 execution-plan tables.
- Select MoE providers with `--moe-runner-backend lora_cutedsl`, `lora_triton`, or `lora_marlin`, subject to weight-family compatibility checks; select dense execution with `--lora-backend triton_v2`.
- Consolidate behavioral tests and replace exploratory benchmarks with bounded tuning workflows, retaining invalid/failed candidates and independently validating finalists.

The branch contains three commits: BF16 MoE, quantized MoE providers, and dense execution plus the reviewed maintenance cleanup. The separate DeepSeek NVFP4 fusion fixes (#42203), Marlin determinism fix, and rejected small-finalize plan proposal are excluded.

## Accuracy Tests

- Full `pre-commit run --all-files` passed immediately before the final squash; the final tree is identical to the verified maintenance tip.
- Maintenance validation on that tree: 467 CPU tests and 545 subtests passed; bounded GB300 GPU regression suite: 233 tests and 10 subtests passed.
- Dense eager/changed-input graph-replay smoke and eight BF16/FP8 MoE tuner smoke cases passed.
- Post-maintenance model A/B compares the pre-maintenance LoRA tree `0113836115` against the current file tree, **not upstream/no-LoRA against the new engines**. At the latest reconciled checkpoint (October 2, 21:44 UTC), all 15 non-Inkling numerical witnesses passed; timing was complete for 14/15 jobs, with a final H200 shared-outer FP8 timing receipt still unconfirmed.
- Inkling is excluded from those totals. The strict bit-exact long-generation gate also fails in true-no-LoRA A/A on the branch's upstream base `6a14b801`; this does not establish a maintenance-only regression or resolve all LoRA numerical questions.

## Speed Tests and Profiling

The 14 completed maintenance A/B jobs report 255 PASS, 39 INCONCLUSIVE, and zero LOSS across 294 per-cell/metric verdicts on H200, B200, and GB300. These are maintenance regression results, not new-engine speedups versus upstream or universal non-regression acceptance.

Historical tuning evidence is documented in the dense/MoE plan READMEs and remains scoped to its architectures, source revisions, and workloads. Existing losses and inconclusive measurements are retained. Kernel/tuner smoke timings are not promoted to model-TPS gains.
