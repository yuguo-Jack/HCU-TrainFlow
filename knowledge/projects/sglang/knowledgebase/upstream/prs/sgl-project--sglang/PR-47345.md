# [Refactor] multimodal: Register token-space strategies through an explicit registry function

[Upstream PR](https://github.com/sgl-project/sglang/pull/47345) · state: closed · merged: False

## Original PR description

## Motivation

Trainers look up token-space strategies with `strategy_for`, but only `import_processors` registered them, and it lives in `managers/multimodal_processor.py`, which imports the serving stack (`BaseMultimodalProcessor`, the token-space wrapper, `ServerArgs`). A trainer therefore found no strategy for any architecture.

## Modifications

- `registry.register_token_space_models()`: imports every `token_space_mm_process.models` module and registers its strategies and serving specs; a module that fails to import is skipped with a warning. `registry.py` still imports no model module itself.
- The four multimodal serving entry points (tokenizer manager, scheduler, encoder receiver, Rust server) call it instead of `import_processors` on the models package, behind their existing multimodal checks; `import_processors` registers only legacy processors again.

## Tests

- `test_processor_trainer_import.py`: a fresh process that forbids serving imports registers strategies and gets the Qwen strategy from `strategy_for`.
- `test_token_space_registry.py`: importing the manager still loads no strategy module; a broken model module is skipped.

## Stack

Based on #47344, as a follow-up to the MM refactor stack (#43420, #46408 - #46415).
