# [Fix] test-utils: Allow expected server exits in canary tests

[Upstream PR](https://github.com/sgl-project/sglang/pull/45172) · state: open · merged: False

## Original PR description

## Motivation

The fail-fast watcher added in #45053 aborts `TestPerturbRaiseMha` when its intentionally corrupted KV cache makes the server exit. The canary correctly reports `verify_real_kv_hash`, but the watcher exits the test runner before it can assert the captured violation. This caused [this CI failure](https://github.com/sgl-project/sglang/actions/runs/39220756454/job/117959479275) on #44623.

## Modifications

- Add `CustomTestCase.expect_server_exit`, defaulting to false. Opted-in tests run their assertions without a fail-fast watcher or retries against a terminated server.
- Opt in only the canary raise-mode fault-injection test; preserve its violation assertions.

## Validation

- Pre-commit checks passed for the changed Python files.
- Use the existing `test/registered/kv_canary/test_self_e2e_perturb_raise.py` as the regression test: it must complete its `verify_real_kv_hash` violation assertions after the intentional server exit. It remains registered for CUDA and AMD CI.
- Targeted GPU rerun passed on `1-gpu-5090` at commit `f5333ca417c`: [workflow run](https://github.com/sgl-project/sglang/actions/runs/39257555152). The existing canary test triggered the expected `verify_real_kv_hash` violation and completed successfully: `Ran 1 test in 51.741s`, `OK`.

No model execution or inference performance changes.
