# [Feat] speculative: Wire STANDALONE PD draft seeds without hidden states

[Upstream PR](https://github.com/sgl-project/sglang/pull/47751) · state: open · merged: False

## Original PR description

This draft implements the built-in STANDALONE + PD seed handoff discussed in [the Q4 PD roadmap](https://github.com/sgl-project/sglang/issues/43699#issuecomment-6474788871), with focused CPU coverage and reproducible native GPU regressions. Maintainer feedback on the intended support contract is welcome while this remains Draft.

STANDALONE produces a draft top-k seed after prefill, but PD previously adopted that seed only for EAGLE, serialized it only with target hidden states, and had no STANDALONE decode-input factory. Returning the first prefill token alone does not establish that nonterminal speculative decoding can continue on D.

## Implementation

- Retain the draft's real top-k probabilities and indices through `need_topk()`, independently of the hidden-state contract in `carries_draft_hidden_states()`.
- Serialize top-k without requiring hidden states. Clear reused speculative rows while preserving the existing metadata layout and final bootstrap-room publication.
- Rebuild a nonempty `EagleDraftInput` with `hidden_states=None` and `CaptureHiddenMode.NULL`. Synchronous execution consumes it directly; overlap follows the existing FutureMap publish/stash interface.
- Contain P seed-pair/shape/capacity failures with `DraftSeedMetadataError` and the existing request/sender abort and pending-chunk cleanup, before final-chunk send.
- Share seed validation between the D factory and transfer commit. Invalid or unwritten seeds raise `StandaloneDraftSeedError` before committing a handoff token or local HiCache restoration. The completed-transfer abort path excludes that request from admission, clears its receiver, and releases its real request/KV/metadata capacity. Unrelated exceptions still propagate. Metadata teardown clears readiness; the next producer clears and replaces the seed row.

This builds on the optional-hidden-state contract in #25037 and algorithm-specific PD factory interface in #26195. The EAGLE work in #41783 has a different hidden-state/proposal contract.

## Initial support scope

Both P and D enable STANDALONE. P/D use matching target assets and matching draft assets, with equal target/draft vocabulary mappings and compatible KV layouts. The validated serving configuration is one P and D, TP1/PP1/DP1, greedy top-k1, three speculative steps/four draft tokens, BF16/FA3/page1, Mooncake TCP, overlap and CUDA graphs disabled. The target/draft pair is Qwen3-4B/Qwen3-0.6B, with separate P/D processes sharing one H20.

A non-speculative P paired with STANDALONE D is outside this scope. No transport-format optimization is claimed; the fixed hidden-state metadata region remains in the layout.

The test-only forward-hook entry changes only the selected producer row. D transport polling, validation, allocation and release retain their original calls and results. ## Remaining before Ready

GPU recovery is limited to one malformed producer seed transferred successfully, followed by serial good requests on TP1/PP1. It does not exercise random transport damage, partial-transfer resource release, simultaneous bad/good GPU requests, or distributed error consensus. The D guard remains local; rank-local corruption can require TP/PP consensus work. Valid terminal handoffs are CPU-covered; missing/malformed seeds get no terminal exemption, and seedless terminal requests are outside the support claim.

Real GPU overlap/FutureMap event-gather execution, multi-rank and cross-host/RDMA behavior, HiCache/host/staging recovery, ordinary-PD/EAGLE full serving regressions, direct KV-byte/position comparisons, and performance remain open. The CPU overlap test observes the interface, not GPU scheduling. This PR remains Draft for review of the limited support contract and remaining coverage.
