# fix(kv_cache): drop fp8 scales when using nvfp4 kv cache

[Upstream PR](https://github.com/sgl-project/sglang/pull/42419) · state: open · merged: False

## Original PR description

fixes #42369. drops fp8 kv scales at load time if runtime dtype is nvfp4. without this they get systematically mis-scaled (e.g. amax/448 vs amax/6). falling back to dynamic scales works correctly.

- waynehacking8 · comment · 2026-10-17T16:35:24Z · [source](https://github.com/sgl-project/sglang/pull/42419#issuecomment-6236755085)

End to end on SM120 (RTX PRO 6000 Blackwell Max-Q, TP1, the report's checkpoint and attention flags, main `4fc86f73c` with and without this head), this fixes NVFP4 KV: the needle test at 8K to 96K goes from 6/36 to 36/36, GSM8K strict from 0.640 to 0.964, and the NLL of the last 2K tokens of 32K windows from 3.46 to 1.82, level with the default FP8 launch. Two gaps against chengye75-star's invariant: the filter runs outside the mismatch check, so the FP8 launch also gets scales of 1.0 with no warning (harmless on this model); and main also breaks BF16 KV (needle 2/18) because the FlashInfer prefill backend passes `k_scale`/`v_scale` for any KV dtype, which the PR fixes (18/18) only through that unconditional filter, so BF16 should count as a mismatch once the filter moves inside the check.
