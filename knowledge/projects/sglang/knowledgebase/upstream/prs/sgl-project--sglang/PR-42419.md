# [Fix] kv_cache: Drop fp8 scales when using nvfp4 KV cache

[Upstream PR](https://github.com/sgl-project/sglang/pull/42419) · state: open · merged: False

## Original PR description

fixes #42369. drops fp8 kv scales at load time if runtime dtype is nvfp4. without this they get systematically mis-scaled (e.g. amax/448 vs amax/6). falling back to dynamic scales works correctly.

End to end on SM120 this fixes NVFP4 KV: the needle test at 8K to 96K goes from 6/36 to 36/36, level with the default FP8 launch.
Setup: RTX PRO 6000 Blackwell Max-Q, TP1, the report's checkpoint (`unsloth/Qwen3.8-27B-NVFP4`) and attention flags, main `4fc86f73c` with and without this head; sglang-kernel 0.4.10, FlashInfer 0.7.2, torch 2.14.1.

| KV dtype | Tree | Needle 8K to 96K | GSM8K strict | NLL, last 2K tokens of 32K windows |
| --- | --- | --- | --- | --- |
| NVFP4 | main | 6/36 | 0.640 | 3.46 |
| NVFP4 | this PR | 36/36 | 0.964 | 1.82 |
| FP8 (default launch) | main | 18/18 | 0.968 | 1.82 |
| FP8 (default launch) | this PR | 18/18 | 0.972 | 1.82 |
| BF16 | main | 2/18 | 0.668 | 3.47 |
| BF16 | this PR | 18/18 | 0.960 | 1.82 |

With this PR NVFP4 is level with the default FP8 launch on all three measures, and main's BF16 row shows the same breakage.

Two gaps against chengye75-star's invariant:

1. FP8 launch: the filter runs outside the mismatch check, so the FP8 launch also gets scales of 1.0 with no warning. That is harmless on this model (the FP8 rows above).
2. BF16 KV: main also breaks BF16 KV (needle 2/18) because the FlashInfer prefill backend passes `k_scale`/`v_scale` for any KV dtype (`flashinfer_backend.py:1397`, `:1459`, `:1532` on `4fc86f73c`). The PR fixes it (18/18) only through that unconditional filter, so BF16 should count as a mismatch once the filter moves inside the check.

With the default `--kv-cache-dtype auto` this drops the scales: `expected_bits` stays None for `"auto"`, but `configure_kv_cache_dtype` later resolves `auto` to `fp8_e4m3` for compressed-tensors checkpoints with a supported `kv_cache_scheme`, so the FP8 pool runs with scale 1.0. A probe of the filter shows the scales kept on base `eb4b167d27`, dropped on this head, and kept again with the change below (bfloat16 still drops them): https://gist.github.com/waynehacking8/0685c4403346f321f0896860aa882f42. A `(8, "auto", False)` case with `kv_cache_quant_algo="FP8"` in the new test would cover it.

```suggestion
                if runtime_kv_dtype == "auto":
                    # configure_kv_cache_dtype resolves auto to an FP8 pool here.
                    algo = getattr(quant_config, "kv_cache_quant_algo", None)
                    if isinstance(algo, str) and algo.upper() == "FP8":
                        expected_bits = 8
                elif runtime_kv_dtype:
```
