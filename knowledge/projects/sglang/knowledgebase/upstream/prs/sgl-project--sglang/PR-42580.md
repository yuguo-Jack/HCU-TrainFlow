# [Fix] poolside-v1: Fix quadratic regex scans in the tool-call parser

[Upstream PR](https://github.com/sgl-project/sglang/pull/42580) · state: open · merged: False

## Original PR description

## Motivation

`PoolsideV1Detector.detect_and_parse` (`poolside_v1`) runs two lazy `findall` scans that go quadratic when a closing tag never arrives. Each failed match scans to the end of the input again from the next opening tag:

| Input | Before | After |
|---|---|---|
| 234 KB of repeated `<tool_call> ` (`<tool_call>(.*?)</tool_call>`) | 36.3 s | 0.37 ms |
| one call with 8,000 unclosed `<arg_value>` tags, 281 KB (`arg_pair_regex`) | 19.4 s | 4.9 ms |

Tool-call parsing runs synchronously on the tokenizer manager's event loop, so one such response stalls every in-flight request. Found with an Atheris fuzzing harness that records per-input parse time.

## Modifications

- Both `findall` calls are bounded with `endpos` at the end of the last closing tag (`</tool_call>`, `</arg_value>` respectively). No match can end past it, and every opening tag before it finds its closer, so the matches are unchanged. With no closing tag at all, the bound is shorter than any possible match, so the result is still empty.
- The streaming path was already linear (about 0.05 ms per chunk) and is untouched.
- Regression test `test_unclosed_tags_parse_in_linear_time` in `test_poolside_v1_detector.py`: 54.7 s on `main`, fast here.

## Accuracy Tests

- Differential test of `main` vs patched detector, comparing `detect_and_parse` and every streaming result under random re-chunking: **0 mismatches** over 20k random plus 20k mutated well-formed inputs (14.8k produced parsed calls).
- `test/registered/unit/function_call/`: 630 passed.
