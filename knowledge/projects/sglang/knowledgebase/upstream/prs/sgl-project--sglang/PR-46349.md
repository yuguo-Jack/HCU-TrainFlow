# [Perf] fa4: Use SplitKV for MTP target-verify and forward max_seqlen_k

[Upstream PR](https://github.com/sgl-project/sglang/pull/46349) · state: open · merged: False

## Original PR description

## Summary

On SM12x the FA4 runtime policy plans SplitKV only for decode (`num_splits=1` for extend). MTP target-verify runs through `forward_extend`, so each full-attention layer ran one CTA per request over the whole context. Verify cost grew linearly with context: 10.4 ms per layer at 428K tokens on an RTX PRO 6000, about 90% of a verify step.

```diff
 forward_extend (final else branch)
+  verify_split_kv = static-bound decode policy and target_verify and not SWA and not cascade
+  if verify_split_kv: kwargs["max_seqlen_k"] = self.max_context_len
   flash_attn_with_kvcache(...,
-    num_splits=self.num_splits,
+    num_splits=self.decode_num_splits if verify_split_kv else self.num_splits,

 flash_attention_v4.flash_attn_with_kvcache
+  max_seqlen_k: Optional[int] = None      # was swallowed by **_
   flash_attn_varlen_func(...,
+    max_seqlen_k=max_seqlen_k,
```

The second change also matters for decode. `flash_attention_v4.flash_attn_with_kvcache` dropped `max_seqlen_k`, so the static bound never reached the planner. Plans fell back to the KV pool size (about 3M tokens here), and most splits were empty.

## Evidence

MiMo-V2.6-Flash NVFP4, TP4 on 4x RTX PRO 6000 Blackwell, EAGLE multi-layer MTP (3 steps, 4 draft tokens), single stream:

| context | before | after |
|---|---|---|
| 94K | 99 tok/s | 244 tok/s |
| 239K | 47 tok/s | 267 tok/s |

Needle retrieval passes up to 400K with the change. The CUDA-graph replay at long context (graph captured at short context) matches eager output.

## Merge Danger

**Door:** two-way

**Blast Radius:** narrow

Only `FlashAttentionBackend` on runtimes with `decode_uses_static_max_seqlen_k` (FA4 SM12x) changes, and only for target-verify on non-SWA, non-cascade layers. Other paths pass `max_seqlen_k=None` as before.
