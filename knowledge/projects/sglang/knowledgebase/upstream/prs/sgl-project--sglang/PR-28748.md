# Add hard AIME25 subset tool

[Upstream PR](https://github.com/sgl-project/sglang/pull/28748) · state: closed · merged: False

## Original PR description

## Summary
- add a reusable AIME25 hard-subset helper with DeepSeek-V4 Flash presets
- add a CI script that emits sgl-eval-compatible `--from-dataset` JSONL
- let the manual DeepSeek-V4 sgl-eval fixture opt into the hard subset via `DSV4_AIME25_HARD_ONLY=1` or a custom `DSV4_AIME25_FROM_DATASET`
- add CPU unit coverage for id parsing, row selection, and JSONL writing

## Validation
- devbox: `python3 test/registered/unit/test_aime25_hard_subset.py`
- devbox: `python3 scripts/ci/build_aime25_hard_subset.py --source-jsonl <tmp>/source.jsonl --out <tmp>/out.jsonl --problem-ids aime25-29,aime25-13`
- devbox: `python3 -m py_compile python/sglang/test/aime25_hard_subset.py scripts/ci/build_aime25_hard_subset.py test/manual/dsv4/_common.py test/registered/unit/test_aime25_hard_subset.py`
- local pre-commit during commit: check-ast, executable shebang, isort, ruff, black-jupyter, registered-test validation, and related hooks passed

## Notes
The default hard preset is `aime25-13,aime25-14,aime25-27,aime25-29`, with `dsv4-flash-bisect` preserving the 12-sample bisect subset (`13,14,29`). Hard-only mode uses `DSV4_AIME25_HARD_SCORE_THRESHOLD=0.70` by default so it catches the severe no-answer regression without applying the full-AIME threshold to intentionally hard rows.

## Code Review

This pull request introduces utilities, a CI script, and test integrations to build and evaluate a small, hard subset of the AIME25 dataset for faster DeepSeek-V4 accuracy probes. The review feedback highlights several key improvements: aligning the Hugging Face loader's 0-based indexing with sgl-eval's 1-based indexing to prevent ID mismatches, allowing preset names to be resolved directly within the problem ID parser (along with adding a corresponding unit test), and correcting the threshold logic in the test runner so that the hard score threshold is only applied when the hard-only subset is explicitly enabled.

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

The Hugging Face loader currently generates 0-based IDs (e.g., `aime25-0` to `aime25-29`), whereas `sgl-eval` uses 1-based IDs (e.g., `aime25-1` to `aime25-30`). This 1-off discrepancy causes the preset IDs (like `aime25-13`) to map to different questions depending on which loader is used.

Using `enumerate(rows, start=1)` aligns the Hugging Face IDs with the 1-based indexing of `sgl-eval`.

```suggestion
        for idx, row in enumerate(rows, start=1)
```

- gemini-code-assist[bot] · comment · 2026-06-19T22:53:06Z · [source](https://github.com/sgl-project/sglang/pull/28748#discussion_r3444845672)

File: `test/manual/dsv4/_common.py` · line 246

![medium](https://www.gstatic.com/codereviewagent/medium-priority.svg)

Currently, if `AIME25_HARD_ONLY` is `False` but a custom dataset is provided via `DSV4_AIME25_FROM_DATASET`, the threshold is automatically downgraded to `AIME25_HARD_SCORE_THRESHOLD` (0.70) instead of using `self.SCORE_THRESHOLD` (0.93/0.95).

We should only use the hard score threshold if `AIME25_HARD_ONLY` is explicitly enabled, ensuring that custom full datasets or other custom evaluations don't have their thresholds unexpectedly lowered.

```suggestion
        threshold = (
            AIME25_SCORE_THRESHOLD
            if AIME25_SCORE_THRESHOLD > 0
            else AIME25_HARD_SCORE_THRESHOLD if AIME25_HARD_ONLY else self.SCORE_THRESHOLD
        )
```
