# [Feat] mem_cache: defer prefill for pending external linker lookups

[Upstream PR](https://github.com/sgl-project/sglang/pull/44873) · state: open · merged: False

## Original PR description

## Motivation

External linker lookups cannot currently report pending separately from a completed miss. This lets an asynchronous lookup fall through to recomputation unless a backend blocks or patches private admission internals.

Refs https://github.com/sgl-project/sglang/issues/44872.

## Modifications

- Accept `None` for pending lookup and propagate `cache_lookup_pending` through the actual match result and request. Skip pending requests before PrefillAdder capacity checks, budgets, locks and loads; ready siblings remain eligible.
- Reuse slot zero of the existing sparse-boundary MIN mask for readiness. Every rank participates before deciding pending versus a terminal result; no additional collective. Cancel a miss only after all ranks are ready.
- Add a default no-op lookup-only cancellation callback for synchronous backends. Retire superseded queries/markers at native abort, session/disabled bypass, full HBM and unusable tails. Cancellation errors still preserve the existing queued/started-load cleanup responsibility.
- Update the native Scheduler LoRA set only for actually appended requests. A deferred adapter cannot block a ready sibling when max_loras_per_batch=1; an admitted adapter still occupies its slot.
- Require stable terminal results and an original finite deadline across rematches. Keep timeout/input validation and stale callback fencing in the async backend. No new payload-transfer lifecycle or default backend change.
