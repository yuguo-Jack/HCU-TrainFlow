# [Renderer] Fail fast on concurrent choice errors

[Upstream PR](https://github.com/sgl-project/sglang/pull/42031) · state: closed · merged: False

## Original PR description

## Motivation

A later renderer choice can fail while an earlier choice is still waiting for response headers or completion tokens. Ordered submission buffering and sequential unary-completion collection hide the ready error, delaying the OpenAI error response and retaining sibling generation work.

## Modifications

Observe submission results as they complete, keeping the existing concurrency limit of 32. Collect established unary-completion streams concurrently with `FuturesUnordered`. Propagate failures and release sibling futures/streams, then restore choice order on success. Preserve echo text, finish metadata, and per-prompt usage accounting. Chat and streaming response aggregation already read established streams concurrently.

## Accuracy Tests

- Submission regression verifies a later failure releases pending and accepted-but-unpolled siblings; successful submissions retain input order.
- Two additional unary-completion regressions fail on the original implementation and pass with the change. They cover later errors and premature EOF with 2 and 64 choices, dropped sibling streams, out-of-order success, echo, stop metadata, and usage across prompts. All 8 focused completion tests pass.
- Real renderer HTTP reproduction with a recording engine verifies that a later HTTP 503 reaches the frontend while the first choice still waits for response headers.
- Real renderer HTTP reproduction with the actual Python `/generate` handler, `StreamingResponse`, background abort task, and abort dispatch methods: text and token-ID completions previously waited for the blocked first stream before returning a later stream's 503. Chat provides an existing concurrent control. The model generator and scheduler-send boundary are CPU doubles; GPU-facing module initialization is excluded. The control exercises Python's actual concurrent batch collector as well.
- The complete renderer suite passes 131 unit tests and one real CLI/HTTP integration test. Full applicable pre-commit hooks, including Rust workspace Clippy and formatting, pass. The final live HTTP reproduction returns the error before releasing the first choice, closes its engine stream, and observes the real background abort dispatch for both text and token-ID completions; the chat control remains correct.

Prepared and independently reviewed with AI assistance (Codex). No GPU model execution is claimed.

## Speed Tests and Profiling

No throughput claim; this removes waiting behind an earlier choice after another choice has already failed.
