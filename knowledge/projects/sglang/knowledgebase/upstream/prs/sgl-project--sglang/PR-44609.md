# [Fix] profiler: Prevent profiler filename components from escaping output_dir (#44189)

[Upstream PR](https://github.com/sgl-project/sglang/pull/44609) · state: open · merged: False

## Original PR description

## Motivation
Fixes #44189

\/start_profile\ accepts caller-controlled \output_dir\, \profile_prefix\, \profile_id\, and \profile_stages\. Previously, final trace filenames were constructed by directly concatenating \profile_prefix\ and \profile_id\ without validating path separators or ensuring the target path remained within \output_dir\. Consequently, a relative prefix containing \..\ or an absolute prefix could escape the configured output directory and write traces outside the intended directory.

## Modification
1. Added \alidate_filename_component\ in \sglang.srt.utils.field_validators\ to ensure filename components (\profile_id\, \profile_prefix\, \profile_stages\) cannot contain directory traversal sequences (\..\), path separators (\/\, \\\\), or null bytes (\\0\).
2. Added \get_contained_path\ in \sglang.srt.utils.field_validators\ to safely join paths and enforce that the resolved output path remains strictly contained within the base output directory via \
elative_to()\.
3. Added \__post_init__\ validation to \ProfileReq\ in \io_struct.py\ so invalid components are rejected at request decoding time.
4. Enforced validation and safe containment in \SchedulerProfilerManager\ (\profiler_manager.py\), \ProfileManager\ (\profile_utils.py\), and \ProfileMerger\ (\profile_merger.py\).
5. Added comprehensive unit tests in \	est_field_validators.py\ and \	est_profile_merger.py\.
