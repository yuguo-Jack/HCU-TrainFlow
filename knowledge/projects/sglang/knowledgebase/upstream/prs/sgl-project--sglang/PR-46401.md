# [Perf] beam: Add the SM103 single-token BF16 MoE GEMV follow-up

[Upstream PR](https://github.com/sgl-project/sglang/pull/46401) · state: open · merged: False

## Original PR description

Move the opt-in SM103 single-token BF16 MoE GEMV out of #45254 so the Day-0 kernels can land independently. This draft keeps the GEMV, its shared SiLU helper and focused checks together. NVFP4 end-to-end validation does not exercise this BF16 path.

The operator uses Beam's TP4 expert shape (`256` experts, hidden size `5120`, intermediate size `640`, top-k `8`) and returns weighted per-expert BF16 outputs. The caller owns expert reduction, routed scaling and TP communication. Default model dispatch is unchanged here.

Validation:

- The existing focused correctness run passed on GB300/SM103 (`torch 2.14.1+cu130`, Triton `3.8.0`): `1 passed, 2 warnings in 1.24s`. It checks an independent FP64 reference with BF16 rounding points, int32/int64 expert IDs, and five graph replays with changed inputs. The kernel, helper and test bytes match the tested source.
- The standalone benchmark compares GEMV plus expert reduction with the existing Triton MoE using the same summed output. It warms both CUDA graphs, flushes L2 before timing and repeats ABBA ordering. Its GPU run and performance results are pending; there is no speedup claim yet.
- Syntax, diff and pre-commit checks pass.

See the [run instructions](https://github.com/sgl-project/sglang/blob/5808f6a5616e69a50a519c7dd77914021dfa9a49/test/manual/kernels/moe/beam_decode_gemv_probes/README.md) and [focused correctness test](https://github.com/sgl-project/sglang/blob/5808f6a5616e69a50a519c7dd77914021dfa9a49/test/manual/kernels/moe/test_beam_decode_gemv.py).

Base: #45254 (`beam-stack-02-kernels`); retarget to `main` after that parent lands. The existing opt-in dispatch flag in #45256 needs coordination when the model stack is restacked. This draft does not depend on #45361.
