# [Perf] [NVIDIA] fp8: Tiny block-FP8 GEMM with fused UE8M0 activation quantization on SM10x

[Upstream PR](https://github.com/sgl-project/sglang/pull/46467) · state: open · merged: False

## Original PR description

## Motivation

Small-M block-FP8 projections on SM10x pay two launches: the per-token-group activation quantization and the DeepGEMM GEMM. For 1 to 16 rows the GEMM is weight-bandwidth bound and the extra launch is a large share of the time.

## Modifications

- `kernels/ops/gemm/tiny_gemm_fp8_blockwise.py` (new): one Triton kernel for 1 to 16 BF16 rows against a 128x128 block-FP8 weight with packed UE8M0 scales. It quantizes the rows to FP8 with UE8M0 scales in registers per 128-wide K group (matching `sglang_per_token_group_quant_fp8(scale_ue8m0=True)`), runs a swap-AB tensor-core GEMM (weight rows on the MMA M side, tokens padded to 16 on the N side; TMA loads, `tcgen05.mma`), and split-K reduces in the last-arriving CTA in split order, so results are deterministic and a row's result does not depend on M. Launched under PDL. Gated to a shape table (Kimi-K3's five TP8 projection shapes) and M <= 16; above that DeepGEMM wins.
- `fp8_utils.py`: `deepgemm_w8a8_block_fp8_linear_with_fallback` dispatches to it when the gate passes (UE8M0 DeepGEMM, 128x128 blocks), honoring the caller-owned `output` from #46466.
- Test: `test_tiny_gemm_fp8_blockwise.py` compares against the two-launch DeepGEMM path for every shape at M = 1..16, checks bitwise-deterministic reruns, M-independence of each row, the caller-owned output, and the gate.

Stacked on #46466.

## Accuracy Tests

GB300 (SM103): `test_tiny_gemm_fp8_blockwise.py` 3 tests OK (all five shapes at M = 1..16 within 1e-2 of the two-launch DeepGEMM path, bitwise-deterministic reruns, M-independent rows, caller-owned output); `test_fp8_blockwise_linear_backends.py` 23 tests OK, unchanged from main. The same tests pass on an SM107 node (3 OK, backends suite 23 OK), so the B200-tuned configs run correctly there too; SM107 timings are not yet measured.
