# [Fix] logits: Preserve lm_head precision with shared buffers

[Upstream PR](https://github.com/sgl-project/sglang/pull/45855) · state: closed · merged: True

## Original PR description

A matching FP32 logits buffer currently makes the ordinary FP16/BF16 lm_head produce FP32 GEMM output even when FP32 lm_head is disabled. Introduced by #45631, this skips the rounding used by the unbuffered prefill-scoring path and LoRA-wrapped heads.

Restrict the direct FP32 buffer write to heads that explicitly enable FP32. Default heads again compute in their original dtype before copying into the shared buffer. Explicit FP32 and MuseSpark's existing FP32 override retain direct buffer writes.

Add buffered/unbuffered equality coverage for FP16 and BF16, check direct writes for explicit FP32, and exercise CUDA graph replay with FP32 enabled and disabled. Low-precision test references now use the normal dtype GEMM instead of an FP64 result rounded afterward, which can differ by one output ULP. Existing tolerances are unchanged.

Related: #45846. This is intended to address the DSpark decode/prefill logprob mismatch and the contemporaneous LoRA/UNO parity failures; end-to-end confirmation is pending.

Validation:
- Changed-file Ruff, Ruff format, isort, Python compilation, and `git diff --check` pass.
- A local CPU control-flow check with emulated CUDA FP32 output reproduces the buffer-dependent rounding change before the fix and removes it afterward. This does not validate CUDA kernels or graph replay.
- GPU validation submitted for `9a9c369051`: [lm_head / RTX 5090](https://github.com/sgl-project/sglang/actions/runs/39822486281) and [DSpark logprob, dynamic LoRA update, UNO parity / H100](https://github.com/sgl-project/sglang/actions/runs/39822512516). Results pending; keeping this PR as a draft.
