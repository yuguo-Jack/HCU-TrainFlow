# [Fix] gateway: Track in-flight requests for every policy in regular HTTP routing

[Upstream PR](https://github.com/sgl-project/sglang/pull/47871) · state: open · merged: False

## Original PR description

## Motivation

Fixes #47868. In regular HTTP routing (`http-regular`), `Router::route_typed_request_once` created a `WorkerLoadGuard` only when the policy was `cache_aware` or `manual`. `power_of_two` compares `worker.load()`: it is the primary signal for `SGLANG_ROUTER_P2C_LOAD_METRIC=requests`/`least_requests` and the fallback for `tokens`. Without a guard that counter stayed at 0 on this route, so P2C selection there ignored in-flight requests. The PD router and the gRPC router already create the guard for every request.

## Modifications

- `sgl-model-gateway/src/routers/http/router.rs`: always create the `WorkerLoadGuard` for the selected worker, and make `send_typed_request` take it as `WorkerLoadGuard` instead of `Option`. The guard keeps its existing lifecycle: it is dropped after a non-streaming body is read, or attached to a streaming body with `AttachedBody`.
- `sgl-model-gateway/tests/routing/power_of_two_test.rs`: add `test_power_of_two_tracks_in_flight_requests`. It sends a `/generate` request to two slow mock workers under `power_of_two`, checks that the total worker load is 1 while the request is in flight, and checks that it returns to 0 afterwards.

`random` and `round_robin` now count load on this route too. This matches PD/gRPC routing and only costs an atomic increment and decrement per request.
