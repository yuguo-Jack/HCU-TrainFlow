# [diffusion] comfyui: fix resend conditioning after an SGLD worker rebuild mid-run

[Upstream PR](https://github.com/sgl-project/sglang/pull/43403) · state: closed · merged: False

## Original PR description

## Summary
Fixes #43189. When `SGLDiffusionGenerator.ensure_executor` rebuilds a dead SGLD worker mid ComfyUI sampler run, the executor's `_sent_conds` still held cond keys from the old worker, so `_mark_and_maybe_drop` dropped `prompt_embeds` on the next step. The new worker's session cache (`_SESSIONS` in `comfyui_mode.py`) starts empty in that fresh process, so nothing restored the embeddings and `verify_input` failed.

Fix: `ensure_executor` now calls `executor.begin_sampler_run()` right after a successful rebuild, starting a fresh cache lifetime so the next step resends its conditioning.

## Test plan
- Added `python/sglang/multimodal_gen/apps/ComfyUI_SGLDiffusion/test/test_worker_rebuild_conditioning.py`, a CPU-only regression test using the real executor bookkeeping, `FluxAdapter`, session cache, and `ComfyUILatentPreparationStage.verify_input`. Only worker liveness and `load_model` are stubbed.
- Verified the test fails without the fix (conditioning not resent, `verify_input` fails) and passes with it.
