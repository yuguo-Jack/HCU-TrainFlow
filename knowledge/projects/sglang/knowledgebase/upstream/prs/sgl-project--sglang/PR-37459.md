# [weight_cache] Key daemon paths by config digest

[Upstream PR](https://github.com/sgl-project/sglang/pull/37459) · state: open · merged: False

## Original PR description

## Motivation

Weight-cache daemon paths are keyed only by physical GPU UUID (#36101), so only one cache per GPU is addressable. Per @liusy58 on #33522, a GPU should be able to host multiple independent caches for different model configurations.

## Change

`compute_config_digest()` hashes resolved cache-relevant model/parallel inputs plus TP/PP rank. The digest is appended to generated socket and ready-file paths, allowing different cache configurations to coexist on one GPU.

The daemon, launchers, and IPC client use the same helper. Cleanup and `--force` are scoped to one GPU/config pair.

Existing `{device_uuid}` templates continue to work, with the digest appended before the extension. An explicit `--weight-cache-socket` still bypasses generated-path discovery. Generated socket paths are length-checked at derivation, so an over-long custom template fails at launch rather than after the daemon has loaded the model.

The standalone launcher now resolves `ServerArgs` before deriving paths so it agrees with client-side resolution.

`CacheConfig.matches()` remains the post-connect compatibility check. EP/DP shard identity remains separate work under #33522.

## Scope

Generated path selection only. No `CacheConfig`/wire-protocol or serving hot-path changes, and no new operator-facing configuration.

## Validation

Focused weight-cache protocol tests pass. The registered GPU E2E has been updated to derive the new paths.
