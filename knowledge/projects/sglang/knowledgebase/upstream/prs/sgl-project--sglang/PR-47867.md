# [Feat] [AMD] hicache: Add --hicache-mamba-size-gb to pin the HiCache Mamba host pool size

[Upstream PR](https://github.com/sgl-project/sglang/pull/47867) · state: open · merged: False

## Original PR description

## Motivation

- A host KV hit on a hybrid (Mamba/KDA) model is only usable if that request's Mamba checkpoint is also on host.
- Today `--hicache-size` is split across host pools by device pool bytes, so the Mamba host pool can be too small for the KV it backs: host KV hits then miss their checkpoint and are recomputed.
- Kimi-K3 TP8, `--hicache-size 240`: KV gets ~186 GB/rank, Mamba ~53 GB/rank.
- There is no way to change that split without changing device pool sizes; this PR adds one.

## Modifications

- New server flag (memory group, float GB, appended to `POSITIONAL_FIELD_ORDER`):

| Flag | Default | Effect |
|---|---|---|
| `--hicache-mamba-size-gb` | unset | Mamba host pool gets this many GB of `--hicache-size`; the KV host pools (and any indexer / draft host pools inside the KV share) split the rest |

| Value / condition | Result |
|---|---|
| Unset | Unchanged: split by device pool bytes |
| `0 < N < --hicache-size` | Mamba `N` GB, KV pools split `--hicache-size - N` |
| `N <= 0` or `N >= --hicache-size` | Rejected at startup |
| No `--enable-hierarchical-cache`, or no explicit `--hicache-size` | Rejected at startup |
| `--enable-unified-memory` | Rejected at startup (unified stack splits by sub-pool size) |
| Model without a Mamba pool | Ignored |

- `hybrid_pool_assembler.py`: `_split_hicache_size_with_mamba` is used by `build_hybrid_mamba_stack` and `build_hybrid_mamba_swa_stack`.
- `hicache_hook.py`: `validate_hicache_mamba_size` runs as its own resolution hook, before the dummy-model early return.
- Docs: `server_arguments.mdx` row added.
- Same name and meaning as the explicit mode of #42443; close this if #42443 lands first.
- Related PRs:
  - #47040 changes the Mamba weight used by the unset (proportional) split; the pinned split is unaffected.
  - #47584 books all explicitly sized host pools, including the pinned Mamba pool, against one host-memory snapshot; the total stays `--hicache-size`.

## Choosing the value

A host KV hit needs one Mamba checkpoint, so balance the two host pools per cached checkpoint:

```
--hicache-mamba-size-gb ~= hicache_size * E / (E + T)
E = state_bytes_per_slot / kv_bytes_per_token   (KV tokens one checkpoint costs)
T = average cached tokens per host checkpoint
```

- Read `E` from one boot log: `(conv_state + ssm_state) / max_mamba_cache_size` over `KV size / #tokens`.
- Kimi-K3 TP8 DCP8 (fp8 KV, bf16 ssm): `(0.34 + 4.88) GiB / 192` ~= 27 MiB per checkpoint, `16.71 GiB / 1,298,048` ~= 13.5 KiB per token, so `E` ~= 2,064.

| `T` (tokens per checkpoint) | Mamba GB of `--hicache-size 240` |
|---|---|
| 2K | ~120 |
| 4K | ~80 |
| 8K | ~48 (about the default split's 53) |
| 16K | ~27 |

- The default split only fits when each checkpoint covers about 7K or more cached tokens; multi-turn agentic workloads usually cache fewer per checkpoint.
