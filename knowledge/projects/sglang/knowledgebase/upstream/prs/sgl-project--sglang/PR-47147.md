# [Fix] layernorm: Keep weightless RMSNorm's weight as a buffer so it survives memory release

[Upstream PR](https://github.com/sgl-project/sglang/pull/47147) · state: open · merged: False

## Original PR description

## Motivation

`RMSNorm(has_weight=False)` stores its all-ones weight as a plain tensor attribute:

```python
self.weight = torch.ones(hidden_size, dtype=weight_dtype)
```

It is neither a parameter nor a buffer, but it is allocated in the weights memory region. `release_memory_occupation` with the `weights` tag frees that region, and `resume_memory_occupation` restores only what it knows about: weight updates refill the parameters, and `_export_static_state` / `_import_static_state` refill the buffers. This tensor is neither, so after a release and resume it comes back as zeros.

For a model that normalizes its token embeddings with a weightless `RMSNorm`, the hidden states are then multiplied by zero, and every logit is equal: generation returns a uniform distribution over the vocabulary and sampling fails with `Sampling support exceeds --sampling-mask-max-tokens`. We hit this with Muse Glimmer (`embed_norm` and the per-layer `qk_norm` both use `has_weight=False`) when offloading the rollout engine between RL steps. A standalone SGLang server on one GPU reproduces it: greedy output before `release_memory_occupation(tags=["weights"])` / `resume_memory_occupation(tags=["weights"])` is correct; after, every top log-probability is exactly `-log(vocab_size)`. Releasing only the KV cache does not trigger it, and `--enable-weights-cpu-backup` hides it.

## Modifications

Register the weightless weight as a non-persistent buffer instead of a plain attribute. It then takes part in the existing buffer snapshot across release and resume, still follows `.to()` dtype and device moves, and stays out of `state_dict()`, so checkpoint loading is unchanged.

Adds `test/registered/unit/layers/test_rmsnorm_weightless_buffer.py`, which fails without the change.

## Accuracy Tests

No change to model outputs in normal serving: the buffer holds the same ones. With the change, outputs after a weights release and resume match the outputs before it.

## Speed Tests and Profiling

No impact: the same tensor, registered differently.
