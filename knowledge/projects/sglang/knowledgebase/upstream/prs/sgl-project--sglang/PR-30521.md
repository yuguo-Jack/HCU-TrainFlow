# [fix] Prefill delayer: make queue-timeout release deterministic across ranks

[Upstream PR](https://github.com/sgl-project/sglang/pull/30521) · state: closed · merged: False

## Original PR description

## Motivation

The adaptive queue-based prefill-delayer trigger (#23189) caps a delay episode with `--prefill-delayer-max-delay-ms`. That timeout is evaluated from a **rank-local wall clock** after the negotiation all-gather:

```python
if queue_condition and prev_state is not None:
    elapsed_ms = (time.perf_counter() - prev_state.start_time) * 1000.0
    if elapsed_ms >= self._max_delay_ms:
        queue_condition = False
```

Every other negotiation input rides the all-gather and is read from TP0's view (`tp0_info = buffer[:, 0, :]`), which is what keeps the replicated schedulers in lockstep. The elapsed-time check is the single non-uniform input: when the `max_delay_ms` boundary falls inside the inter-rank jitter window (µs–ms after the collective), one rank flips `queue_condition` off and releases prefill while its peers keep delaying. The schedulers then build different batches and desync (collective shape mismatch / hang). Low probability per delay episode, but long-running serving with the queue trigger enabled will eventually hit it.

## Modifications

- Evaluate the rank-local timeout before the existing all-gather and pack the result as a sixth `int` field.
- Release on the gathered maximum so every rank makes the same batch decision.
- Evaluate the gathered timeout lazily, only when the queue condition is active, avoiding an unconditional device-to-host `.item()` synchronization.
- Add an enabled four-rank Gloo regression in `base-a-test-cpu` with rank-local state ages on opposite sides of the timeout boundary.

## Verification

- Previous implementation: the regression fails because rank 0 releases while ranks 1–3 continue delaying.
- Updated implementation: `test_queue_timeout_rank_skew_stays_lockstep` passes with four Gloo ranks.
- Pre-commit checks pass for all changed files.

## Code Review

This pull request updates the prefill delayer to synchronize the queue-delay timeout status across ranks using the all-gather tensor, preventing rank-skewed wall clocks from splitting batch decisions. It also adds a corresponding test case to verify this behavior. The review feedback suggests optimizing performance by lazily evaluating the global queue timeout status to avoid unnecessary GPU-to-CPU synchronization (`.item()`) when the queue condition is false.
