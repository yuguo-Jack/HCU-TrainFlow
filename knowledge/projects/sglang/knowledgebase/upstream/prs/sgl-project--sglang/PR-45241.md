# [Feat] radix-tree: Report each path node's child count in collect_path_info

[Upstream PR](https://github.com/sgl-project/sglang/pull/45241) · state: closed · merged: True

## Original PR description

## Motivation

`collect_path_info` hands a caller the root-to-node chain for each requested end node as `TreePathNodeInfo` records (node id, parent id, path span, FULL value length). A caller that reads tree paths by node id, for example a background writer that must decide whether a node is a branch point or the middle of a straight chain before publishing it, had no way to tell the two apart from the record and needed a second trip into the tree.

## Modifications

- `TreePathNodeInfo` gains `num_children`, the node's immediate child count at the time of the snapshot, in the Rust core (`unified_tree_core.rs`), the Python reference core (`unified_tree_core.py` / `unified_tree_core_interface.py`) and the bindings tuple (`python_bindings.rs`). The Python adapter already builds the record positionally from the tuple, so it picks the field up unchanged.
- Like the rest of the record it is a snapshot: a later split or eviction changes the tree, not a record already handed out.
- Rust unit test `assert_path_info`: build the two-node path with a split so the head node has a real child, add a second branch and check both chains report the branch point, then evict the branch and check the earlier snapshot was not mutated.
- Python integration test: check the new field through the bindings on both backends, including after a split that turns a chain node into a branch point.

## Accuracy Tests

No model behaviour changes; this adds a read-only field to a tree inspection record.

## Benchmarking and Profiling

Not applicable: one extra `usize` per path record on an inspection path.
