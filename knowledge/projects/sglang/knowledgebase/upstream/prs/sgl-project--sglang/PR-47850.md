# [Fix] mem_cache: broadcast packed draft layers in the MLA dedup linker

[Upstream PR](https://github.com/sgl-project/sglang/pull/47850) · state: open · merged: False

## Original PR description

## Motivation

With the unified cache external linker and MTP/EAGLE/DSpark draft KV (packed draft mapping from #37914), the first KV load that needs a cross-rank broadcast kills the whole TP group:

```
TypeError: list indices must be integers or slices, not tuple
```

`_with_packed_draft_mapping()` in `linker_pool_assembler.py` maps one transfer layer to `(target_layer, draft_layer)` once draft layers are packed into the same transfer layer, so `pool.layer_mapping[layer_id]` can be a tuple. `LinkerMLADedupBroadcaster.broadcast_loaded_layer()` still uses that value as an int index into the per-layer buffer list, so the very first broadcast raises and every rank in the group exits. The surrounding log hints point at CUDA graph capture or `--mem-fraction-static`, so it reads like an out-of-memory problem while memory is untouched.

Reproduced on a TP deployment running the external linker with MTP: KV restore aborts on the first cross-rank load, no request is ever served.

## Modifications

- `python/sglang/srt/mem_cache/unified_cache/linker_mla_dedup.py`: unwrap the mapping exactly the way `get_prepared_layer_range_meta()` in `linker_pool_assembler.py` already does (`[mapped] if isinstance(mapped, int) else list(mapped)`) and broadcast every packed physical layer, keeping the mapping order and using each physical layer's own row width.
- `test/registered/unit/mem_cache/test_linker_mla_dedup_broadcast.py`: the test file is now a CPU-registered regression test (`register_cpu_ci(est_time=5, suite="base-a-test-cpu")`), formatted per the repo's ruff and isort rules. Coverage goes from 4 to 12 cases: int mapping, packed tuple mapping, sequence mapping, physical layer zero, sparse mapping, unmapped layer, pool missing from `prepared`, multiple buffer components, DSA dual-pool preparation and dispatch, packed and unpacked data round trips, and empty indices.
- The data round-trip cases build a real DSA pool group, broadcaster, index preparation and `_bcast_layer`, mocking only rank discovery and the communication primitive. Source and receiver use different physical slots, and the assertions check target KV, draft KV, indexer and non-selected rows across repeated reuse of the shared staging buffer.

Broadcasting the packed draft layer is not optional here: in dedup mode the non-source ranks never read the store themselves, so dropping the draft row raises nothing and leaves stale draft KV on those ranks, which decodes to silently wrong tokens.

## Speed Tests and Profiling

N/A, and no speed claim is made.

- No new GPU staging buffer: the existing `kv_staging` and its chunking primitives are reused, and per-layer sizes still come from each layer's own element width.
- Mapping normalization does allocate a small Python list per broadcast layer, so this is not a "zero allocation" change.
- For int mappings the sequence of `_bcast_layer` calls is unchanged; packed mappings now also broadcast the draft layer that was previously dropped. No performance measurement was taken on the restore path.
