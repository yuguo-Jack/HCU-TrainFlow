# [Fix] prefill-graph: Keep every DP rank eager when the replay tail captures behind rank barriers

[Upstream PR](https://github.com/sgl-project/sglang/pull/45881) · state: closed · merged: True

## Original PR description

- With DP attention and MegaMoE, `PrefillCudaGraphRunner._has_inactive_dp_rank` lets a rank replay the prefill graph while ranks with no tokens run an eager idle forward, when `prefill_graph_tolerates_sum_len()` holds. That is safe only if nothing in the captured graph's breaks waits on other ranks.
- The DeepSeek-V4.1 decoder replay tail captures its row-bucket graphs on first use, behind TP-group barriers. In a step where only some ranks have tokens (for example the first step after start, or lone requests), the replaying rank blocks in that barrier, the idle ranks return to the scheduler, and their MegaMoE kernels wait for it: the server stops making progress (DeepGEMM grid sync timeout, then the scheduler watchdog).
- The per_rank Engram host-table layout never hit this because its lookup records a DP gather at capture, which already forces every rank to eager in such steps; the shared layout (the default) has no collective, so it did.
- Fix: while the prefill graphs capture, the replay tail calls `note_rank_barrier_in_prefill_graph()`, which latches `DpFlags.prefill_graph_has_rank_barrier` the way the DP gather helpers latch `prefill_graph_has_dp_gather`. `_has_inactive_dp_rank` keeps tolerating an idle rank only when it is unset. The decision reads `global_num_tokens_cpu`, which is the same on every DP rank, so all ranks take the same path. No new server flag.

No behavior change for steps where every DP rank has tokens, or for configs whose prefill graph has no such break.

Verification: DeepSeek-V4.1-Flash DEP4 with the shared Engram host table and the breakable prefill graph hung before the first prefill on unmodified main and serves with this change (lone requests and GSM8K pass); throughput of the per_rank layout and of steps with every rank active is unchanged; `test_prefill_cuda_graph_padding.py` passes.
