# [AMD] MiniMax-M3: grouped-head shared-KV Triton verify and draft extend, plus Lean draft decode

[Upstream PR](https://github.com/sgl-project/sglang/pull/43020) · state: open · merged: False

## Original PR description

## Motivation

At TP4, MiniMax-M3's dense layers (64 q / 4 KV heads, head_dim 128) and its EAGLE3 draft
(`LlamaForCausalLMEagle3`, same shape, 1 layer) put **16 query heads on one TP-local KV head**. Main already has a
grouped-head split-KV kernel for that shape (`verify_shared_kv_fwd`, #34517), but
`_should_use_verify_shared_kv` enables it only for Kimi-K3, dspark and Qwen3.5. On main, M3 runs per-head
kernels that read the prefix KV once per query head:

| call (M3 TP4 + EAGLE3, topk 1) | main | this PR |
|---|---|---|
| target verify (dense layers 0-2) | `verify_splitkv_fwd` (per-head) | `verify_shared_kv_fwd` |
| draft extend (`DRAFT_EXTEND_V2`) | `extend_attention_fwd` | `verify_shared_kv_fwd` |
| draft decode | `decode_attention_fwd`, standard kernel | `decode_attention_fwd`, Lean kernel (main's) |

Enabling the gate alone fixes only target verify, and with the default 4-head block config the kernel is still
1.94 ms vs 0.45 ms at 24 x 195K. So the PR also routes the draft's extend, adds the head_dim-128 block config,
and turns on main's existing Lean decode for M3 speculative decoding on ROCm.

## Modifications

"Shared KV" here is main's grouped-head kernel: the 16 query heads that share one TP-local KV head are
processed in one block, so each K/V tile is read once instead of once per query head.

- **Gate** (`_should_use_verify_shared_kv`): the GQA allowlist becomes
  `is_qwen3_5 or is_minimax_sparse or is_llama_eagle3_draft`, keyed on the runner's own config, the same way
  main keys dspark on `is_dspark_draft`. `is_llama_eagle3_draft` sits next to `is_dspark_draft` in
  `configs/model_config.py`. The existing conditions still apply (gfx95, topk 1, exactly one TP-local KV head,
  `SGLANG_ENABLE_SPLITKV_VERIFY`), and `can_handle` falls back for anything the kernel does not cover.
  Scope: this also turns on for other Llama EAGLE3 drafts with one TP-local KV head on gfx95 at topk 1; results
  stay exact there, but only M3's draft shape is benchmarked.
- **Draft extend**: the existing verify fast path in `forward_extend` also takes `DRAFT_EXTEND_V2` for a Llama
  EAGLE3 draft (same constant-length chain over a prefix-only `kv_indices`; ragged eager batches fail
  `can_handle` and fall back).
- **Draft decode**: no new kernel. M3's model override sets `enable_lean_attention=True` on HIP when
  speculative decoding is on and the user left the flag unset (`enable_lean_attention` becomes
  `resolvable=True`). Without it the draft's 16-q / 1-KV layer always replays the standard decode kernel, because
  Lean's capture policy never bakes a layer with fewer than 4 head tiles.
- **Kernel** (`verify_mla.py`):
  - `_BLOCK_CONFIG[128] = (16, 128, 4)`: one 16-head block per KV head. This carries the speedup.
  - Empty-prefix guards in stage 1 and the stage-2 merge: weight 0 instead of NaN. Padded draft-extend graph
    rows have `kv_lens == 0`.

Without speculation the gate is off and nothing changes. The target's 57 sparse layers use the MiniMax sparse
backend and are untouched; this PR covers the three dense layers in target verify and the EAGLE3 draft.

## Accuracy Tests

`test/registered/attention/test_verify_shared_kv.py` gains M3 verify parity against `extend_attention_fwd`
(bf16 with prefixes 0, 1, 77, 4,099, 70,001 and 199,999, so a padded empty-prefix row is covered; and fp8 with
k/v scales over 24 requests) and gate assertions for M3 and its EAGLE3 draft. `test_model_overrides.py` gains
`test_m3_rocm_speculative_decode_uses_lean`. Removing either empty-prefix guard fails the M3 parity test.

On gfx950 (MI355X), merged with main `f6c848c882`:

```
pytest test/registered/attention/test_verify_shared_kv.py test/registered/attention/test_verify_splitkv.py \
  test/registered/unit/layers/attention/test_triton_verify_metadata.py \
  test/registered/unit/spec/test_eagle_worker_v2_topk1_fastpath.py test/registered/unit/test_model_overrides.py
145 passed, 2 skipped, 6 failed
```

The 6 failures are `TestGoldenModelOverrides` cases (deepseek_v4, dllm, minimax_m2 sm10x, moe_runner_quant, ...)
that fail identically on main alone in this ROCm image.

Draft-decode numerics (M3 draft shape, fp8 KV, 24 requests up to 195K), mean abs error against an fp32
reference: Lean matches main's standard decode to bf16 rounding (max abs difference 1.3e-2) at every context
length. Draft decode only changes what the draft proposes; target verify decides the output and is the same
kernel either way.

Lean has a fixed cost of about 0.05-0.09 ms, so below about 8K it is slower than the standard kernel; there are
two draft-decode calls per spec step. A dedicated grouped-head decode would be about 20% faster than Lean at
195K; end to end it measured no different (below), so this PR uses main's kernel.

kernel, whose outputs match main's standard decode to bf16 rounding; GSM8K moves about +-3 points between
server instances of the same build.

## Risks

- The draft gate keys on the draft's own architecture, so it also applies to other Llama EAGLE3 drafts with
  one TP-local KV head on gfx95 at topk 1. `can_handle` keeps results exact; only M3's draft is benchmarked.
- The Lean default applies only to M3 with speculative decoding on ROCm, and only when the user did not set
  `--enable-lean-attention`.
- No new env var: verify and draft extend stay behind main's `SGLANG_ENABLE_SPLITKV_VERIFY`.
