# [Fix] trtllm_mla: Keep the fused fp8 KV write off a DCP-resolved loc

[Upstream PR](https://github.com/sgl-project/sglang/pull/46744) · state: open · merged: False

## Original PR description

## Motivation

Kimi-K3 at TP8 + DCP8 with FP8 KV fails on its first decode under `--enable-unified-memory`:

```
AssertionError: fused fp8 KV write reached with a DCP-resolved loc
```

This is the Kimi-K3 cookbook's B300 1x8 Balanced recipe (`--tp-size 8 --dcp-size 8`) with its FP8 (E4M3) KV cache precision option (`--kv-cache-dtype fp8_e4m3`), plus `--enable-unified-memory`. The existing unified + DCP coverage, `test/registered/e2e/models/test_kimi_linear_unified_memory_dcp_blackwell.py`, runs Kimi-Linear without `--kv-cache-dtype`, so its KV stays bf16 and it never reaches the fused fp8 write.

Under the unified pool with `--dcp-size > 1`, the write loc that reaches the trtllm_mla family is already DCP-resolved (`translate_write_loc`): owned rows are physical ids and non-owned rows are on the padding sink 0. The fused fp8 quantize + KV write + q concat kernel (`set_mla_kv_concat_q_fp8`) only understands widened ids (it writes row `loc // dcp_size` iff `loc % dcp_size == dcp_rank`) and has no sink skip. Its gate in `TRTLLMMLABackend.__init__` never excluded this combination, so the helper's tripwire fires. Without the tripwire the kernel would drop most owned rows and store every non-owned token into slot 0.

`TestFusedFp8WriteGate` already expects the clause, but `_gate` asserts a re-typed copy of the expression instead of the gate `__init__` builds, so CI never saw that the backend lacked it.

## Modifications

- Move the fp8 gate into `_use_fused_set_kv_concat_q_fp8` and add the missing `not (get_parallel().dcp_enabled and kv_index_translator.is_translating)` clause.
- Unified + DCP + fp8 now writes through the pool's `set_mla_kv_buffer`, which picks the identity-addressed writer for a resolved loc and skips the sink. This is the path bf16 KV already takes. The static pool (with or without DCP) and non-DCP unified runs keep the fused write.
- `TestFusedFp8WriteGate._gate` calls the production function, so a missing clause turns the test red.
- The assertion in `_set_kv_and_concat_q_fp8_fused` stays as a tripwire.

## Accuracy Tests

On v0.5.22 (`baa9befa`) with the same change, on 8x B300 (Kimi-K3, TP8 + DCP8, FP8 KV, `--enable-unified-memory`):
- Before: the engine starts, and the first decode raises the assertion above.
- After: decode runs.

CPU checks against the real `__init__` of `TRTLLMMLABackend` and `CuteDslMLABackend` (collaborators stubbed):
- The gate is off only for unified + DCP.
- A resolved loc reaches `set_mla_kv_buffer` unchanged.
- The static-pool DCP decode keeps the fused writer with the widened loc.

An address model of the write over 8 DCP ranks:
- The static fused path and the repaired unified path both place every token on its owner (8/8 ranks).
- The unfixed unified fused path matches 2/8 and writes six non-owned tokens into the sink.

## Speed Tests and Profiling

Unified + DCP + fp8 now costs quantize plus scatter instead of one fused launch. Other configurations are unchanged. Before this change that configuration could not decode at all, so there is no baseline to compare against.
