# [Fix] unified_cache: Resize test allocator before allocating backed pages

[Upstream PR](https://github.com/sgl-project/sglang/pull/44843) · state: closed · merged: True

## Original PR description

## Motivation

The `resize with live allocations` subtest in `test_unified_post_capture_sizing.py` finalizes a 64 MiB reservation to 16 MiB, then allocates before resizing the allocator. The full-attention allocator still grows down from the old 64 MiB frontier, so allocation-time `_zero_pages_kernel` writes into the unbacked tail instead of reaching the intended `non-empty` assertion.

Observed in [this CI failure](https://github.com/sgl-project/sglang/actions/runs/38988923342/job/117270212489): `CUDBG_EXCEPTION_WARP_MMU_FAULT` in `_zero_pages_kernel`, process exit code -6. The affected test and allocator code are also present on main; this is independent of #43387.

## Modifications

Resize the empty allocator immediately after finalizing backing, before creating the live allocation. The subsequent resize still verifies that a non-empty allocator is rejected. This matches the production startup ordering and changes only the test setup.
