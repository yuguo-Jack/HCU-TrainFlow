# [Fix] glm5.2: Align HiSparse warmup backends and move test to nightly

[Upstream PR](https://github.com/sgl-project/sglang/pull/44303) · state: closed · merged: True

## Original PR description

## Motivation

The GLM-5.2 PD + HiSparse + MTP test fails during prefill-worker startup after #44256. FlashInfer autotune runs a dummy DECODE forward on the prefill target worker, but only its prefill backend is set to `flashmla_kv`. Its default `trtllm` decode backend rejects the packed KV cache: `Expected head dim 576 for query and kv_cache, got 576 and 656`.

Failure: https://github.com/sgl-project/sglang/actions/runs/38575536780/job/115891733288

## Modifications

- Set the prefill worker's DSA decode backend to `flashmla_kv` as well, so startup autotune consumes the same KV layout as prefill and PD transfer.
- Move the full test from `extra-b` to `nightly`, using the existing 8-GPU B200 suite and retaining TP4 prefill + TP4/DP4 decode, 500-question GSM8K evaluation, speculative acceptance threshold, and both long-context cases.
- Reuse the existing B200 nightly workflow and suite; no workflow changes are needed. Preserve scheduled coverage while reducing per-PR contention for B300 capacity.
