# [Fix] diffusion: stabilize FLUX.3 serving and reuse static conditioning

[Upstream PR](https://github.com/sgl-project/sglang/pull/44493) · state: closed · merged: True

## Original PR description

Follow-up to #44418, now merged. Latest `origin/main` (`09b7383624c1`) is merged into this branch; the PR now contains only the serving fixes, hoisting, tests and cookbook updates.

## Changes
- Stabilize reference SDPA priority across requests. A preceding DiT forward could otherwise switch the text encoder from cuDNN to memory-efficient attention, changing an identical request's output.
- Hoist invariant text/reference embeddings, modulations and positional preparation into request-owned state, extending the existing mode-block reuse. No model-global conditioning cache or new public knob.
- Check exact repeatability both before and after grouped requests and multi-output generation, without loosening assertions.
- Update measured deployment recipes and document TP/SP, streaming, consumer GPU and numerical-validation boundaries. Keep untested resource shapes explicitly unverified.

## Validation
- H200 after merging current main: **81 tests and 21 subtests passed** across native DiT, quantized loading, served configuration, stages, VAE, SDPA priority and normalization dispatch.
- Fresh H200 server: real Base T2I/I2I, concurrent requests, `n=2`, immediate/final repeated requests, and mixed-size multi-reference edits pass.
- Pre-commit, cookbook config validation and 64 generated command combinations pass.

### Hoisting A/B

Same H200, Base BF16 checkpoint `d8acde427a698bdb98b5c1c941c60fa4c97e9f28`, Torch 2.14.1+cu130, Transformers 5.19.0, Torch SDPA, eager, all components resident. Both arms include the SDPA-priority fix. Batch 1, 1024x1024 output/reference, 50 steps, CFG 3.5, exact-quality PNG; two prompts/seeds and two timed repetitions after warmup. Local HTTP submission through client PNG decoding; loading and warmup excluded.

| Workload | Existing partial hoist | Full hoist | Runtime peak allocated, before / after |
| --- | ---: | ---: | ---: |
| T2I | 7.2853 s | 7.2844 s | 22265.63 / 22263.13 MiB |
| I2I | 15.2640 s | 15.0395 s | 22267.76 / 22265.26 MiB |

T2I is effectively unchanged; I2I latency is 1.47% lower in this small sample. These are allocator peaks, not node-wide NVML totals. Both arms repeat exactly internally; cross-arm outputs are **not bit-exact** (SSIM 0.9957-0.9989, MAD 0.158-0.373 / 255 across four PNGs). Component tests cover the unchanged function, not official full-checkpoint accuracy.

### FlashInfer version A/B

Single GB300, same code `78f3ef2182a`, Torch 2.14.1+cu130, Transformers 5.19.0, FA4, eager, all components resident, batch 1, exact quality, PNG. Base revision `17333191c36bae1b61b0a247e33ba284f1df07fa`; distilled revision `875076bf83d4364b68dccdbf8307f4f01475f68d`. Base: 50 steps/CFG 3.5; distilled: 16 steps/no CFG. 1024x1024 output and reference; two prompts/seeds, two timed repeats after warming each request shape. HTTP submission through client PNG decoding, excluding loading/warmup/JIT. Only one server generates at a time. FlashInfer Python and cubin versions match in each environment; no version-check suppression or jit-cache package.

| Checkpoint / precision | T2I 0.7.1 / 0.7.2rc3 | I2I 0.7.1 / 0.7.2rc3 |
| --- | ---: | ---: |
| Base BF16 | 3.200 / 3.208 s | 6.261 / 6.280 s |
| Base FP8R | 2.156 / 2.172 s | 4.424 / 4.448 s |
| Base NVFP4 | 2.120 / 1.932 s | 4.255 / 3.921 s |
| Distilled BF16 | 0.688 / 0.688 s | 1.298 / 1.302 s |
| Distilled FP8R | 0.676 / 0.665 s | 1.012 / 1.015 s |
| Distilled NVFP4 | 0.615 / 0.640 s | 0.974 / 0.918 s |

All 24 version-paired PNGs match pixel-for-pixel, each arm repeats exactly, and per-server runtime peak allocated memory is unchanged in all 12 workload rows. This does not make FP8R/NVFP4 lossless relative to BF16. Base NVFP4 improves by 8.88% T2I / 7.84% I2I; distilled NVFP4 T2I instead regresses by 4.05% in this sample. BF16 and FP8R show no consistent material gain. Keep the stable dependency pin rather than requiring an RC globally for this model-specific benefit.

Both performance experiments leave cuDNN TF32 and BF16 reduced-precision reduction at their enabled runtime defaults. They are matched SGLang-path comparisons, not a strict FP32 or official-reference accuracy claim.

### Cookbook command verification

Completed 15 matched eager/BCG workload pairs across RTX 5090, single/dual H200 and GB300. Resident weights, batch 1, 1024x1024, default `quality=lossless`; Base 50 steps/CFG 3.5, distilled 16 steps/no CFG. Warmed localhost HTTP through JPEG decoding, ABBA order, two prompts/seeds and four timed samples per arm. Loading and capture excluded. Torch 2.14.1+cu130, Transformers 5.19.0, FlashInfer 0.7.1; each comparison keeps its checkpoint, packages and backend fixed.

| Workload | Eager | BCG | Picker default |
| --- | ---: | ---: | --- |
| GB300, distilled NVFP4, FA4, T2I | 0.563 s | 0.436 s | BCG |
| GB300, Base BF16, FA4, I2I | 6.236 s | 6.733 s | Eager |
| H200, Base BF16, FA3, I2I | 14.183 s | 15.252 s | Eager |
| 2x H200, Base BF16, FA3, TP2 T2I | 4.000 s | 4.199 s | Eager |
| RTX 5090, distilled NVFP4, SDPA, T2I | 1.676 s | 1.678 s | Eager |

All 15 fixed-backend pairs repeat exactly and have pixel-identical eager/BCG PNGs on both prompts. The GB300 FA4 win is 22.5%; peak allocated rises 16.63 → 17.46 GiB and peak reserved 18.75 → 19.96 GiB. These are output-rank allocator peaks over warmup/runtime, not loading, all-rank or whole-device measurements.

SDPA + BCG on GB300 distilled NVFP4 T2I measures 0.424 s versus 0.589 s SDPA eager. It remains selectable, not an automatic backend change: SDPA versus FA4 samples have SSIM 0.978–0.987 and MAD 1.74–1.75/255; neither has established official-reference superiority.

The picker now selects graph execution only for a measured win, supplies matching quality/resolution warmup, and exposes a server-local edit warmup reference. Other hardware/topologies stay explicitly unverified. Two small runtime fixes preserve configured BCG references and initialize synthetic edit canvas metadata; otherwise valid edit graph commands captured T2I or failed startup.

Validation: 76 focused tests + 6 subtests, pre-commit, cookbook config checker, 2,880 generated selection combinations and Mintlify build validation pass. Official Diffusers parity remains deferred. CI is triggered; not waiting for the full run.
