## Motivation

This fixes a CPU decode throughput regression observed on Qwen/Qwen3.8-27B with torch compile enabled, between 65ef55e2a8 and b0d7254fbc.

Three issues accumulated on the decode hot path:

1. Deprecated parallel-state getter wrappers entered the compiled graph. Communication code still calls helpers such as get_tp_group() and get_attn_tp_group(). After these helpers were wrapped with deprecation warning logic, Dynamo traced the warning/frame-inspection path during CPU decode capture.

2. The layer-boundary FFN exit policy deferred ordinary single-sum outputs too broadly. For Qwen3.8 CPU decode, this changed the previous fused-only reduction behavior and moved the model onto a slower completion path.

3. Runtime layer-boundary containers were constructed as msgspec.Struct objects inside the compiled decode path. Dynamo reported graph breaks such as: "Unsupported `object.__new__` user-defined class construction" for these runtime objects.



## Modifications
Fix the regression by:
- bypassing deprecated getter warning wrappers while torch.compiler is tracing;
- disabling ordinary single-sum deferral unless the intended fused-consumer path applies;
- replacing hot-path runtime msgspec.Struct containers with Dynamo-friendly containers: NamedTuple for immutable handles/decisions and a small `__slots__` class for the mutable Contribution object.
