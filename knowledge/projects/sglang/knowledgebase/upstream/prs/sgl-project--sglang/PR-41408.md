# Fix ROCm MHA FP8 projection after prefix KV restoration

[Upstream PR](https://github.com/sgl-project/sglang/pull/41408) · state: open · merged: False

## Original PR description

## Motivation

On gfx95 with block-scaled FP8 `kv_b_proj`, ROCm MHA preparation normalizes and quantizes only the newly appended tokens. MHA one-shot prefix restoration then replaces `kv_a` and `k_pe` with the complete cached-prefix-plus-suffix tensors, but projection still consumes the old suffix-only quantized tuple. K/V consequently have fewer rows than the restored RoPE keys and the attention metadata; the key concatenation raises a shape mismatch.

This applies to projections recognized by `_is_block_scale_fp8` (FP8 weights with a multi-column `weight_scale`), with restored BF16 KV as well as the FP8-dequantization and DCP gathering branches. Serialized FP8 projections exposing only `weight_scale_inv` do not take this fused path and are covered as unchanged controls. FP8 weight precision is independent of KV-cache precision.

## Modifications

Invalidate the precomputed quantized tuple when restoring a prefix, then project the full, already normalized KV through the linear layer's ordinary input quantization. Keep the fused tuple for requests without a restored prefix. Cached KV is not RMS-normalized a second time.

Add a CPU regression using the actual prepare method with mocked GPU kernel/cache boundaries. It checks complete K/V values and row order against a full-prefill reference for mixed prefix lengths, BF16/FP8 cache restoration, DCP, block-scale/serialized-FP8/BF16 weights and the no-prefix fast path. The test uses the real `_is_block_scale_fp8` predicate, including its `weight_scale_inv` fallback.

These tests import the actual engine module and use CPU tensors with mocked GPU kernels; real GPU kernels and model output accuracy have not yet been validated for this change. The PR remains draft pending that validation.

Not measured. The no-prefix fused projection is retained. Prefix restoration uses the existing linear-layer input-quantization path; this PR makes no performance claim.
