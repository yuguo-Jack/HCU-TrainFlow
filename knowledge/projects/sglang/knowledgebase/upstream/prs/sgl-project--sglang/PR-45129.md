# [Fix] Anthropic: accept thinking.display="updates"

[Upstream PR](https://github.com/sgl-project/sglang/pull/45129) · state: open · merged: False

## Original PR description

## Motivation

Claude Code sends `thinking: {"type": "adaptive", "display": "updates"}` on its `/v1/messages?beta=true` requests. `AnthropicThinkingParam.display` only accepts `"summarized"` and `"omitted"`, so the first request of every Claude Code session against sglang fails with:

```
400 invalid_request_error: thinking.display: Input should be 'summarized' or 'omitted'
```

Claude Code then retries without the field, so sessions work, but each one starts with a rejected request.

`"updates"` is a documented Anthropic value, not a client quirk. The anthropic Python SDK defines it on the beta thinking configs:

- `BetaThinkingConfigAdaptiveParam.display: Literal["summarized", "omitted", "updates"]`
- `BetaThinkingConfigEnabledParam.display: Literal["summarized", "omitted", "updates"]`

The non-beta configs list only `"summarized"` and `"omitted"`. The [thinking docs](https://platform.claude.com/docs/en/build-with-claude/thinking#controlling-thinking-display) describe `"updates"` (beta header `thinking-display-updates-2026-08-18`) as: reasoning blocks come back with an empty `thinking` field, as with `"omitted"`, and only short progress updates between tool calls carry text.

## Modifications

- `entrypoints/anthropic/protocol.py`: `AnthropicThinkingParam.display` accepts `"updates"`. Other values are still rejected, and `display` with `type="disabled"` is still a 400.
- `entrypoints/anthropic/serving.py`: `"updates"` is served like `"omitted"`. Reasoning stays on and its text is still emitted, because the OpenAI-side pipeline cannot blank reasoning blocks or produce progress-update blocks. A warning names the requested value.

Nothing else in Claude Code's opening request needs a change. Replaying the captured request through `AnthropicMessagesRequest` with only `display` adjusted passes validation: `output_config.effort="high"` is already accepted, and `context_management` (`clear_thinking_20251015`) is ignored as an undeclared field.

## Accuracy Tests

Request validation only; generation is unchanged.

Unit tests (`test/registered/unit/entrypoints/anthropic/test_serving.py`):

- `test_request_claude_code_display_updates_is_accepted` uses Claude Code's opening-request shape: adaptive + `display="updates"` + `output_config` + `context_management` + `metadata`. It fails before this change and passes after.
- `test_request_thinking_unknown_display_is_rejected` checks that a value outside the SDK set still fails validation.
- 70 passed.

Live: Claude Code 2.1.296 (`claude -p` with `ANTHROPIC_BASE_URL` pointing at an sglang server built from this branch, serving `thinkingmachines/Inkling-NVFP4` on 8x H200):
- Both `/v1/messages?beta=true` requests carried `thinking={"type": "adaptive", "display": "updates"}`, and both returned 200. The server log shows 2x 200 and no 400.
- The session completed its tool call and ended with `end_turn`.
- Before this change, the same CLI's first request returned the 400 above.
