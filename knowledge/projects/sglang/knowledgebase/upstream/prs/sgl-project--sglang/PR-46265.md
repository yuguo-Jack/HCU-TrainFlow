# [Fix] [NPU] modelslim: Pass group_size/tp_size to W4A8 MoE and fix group-scale layout

[Upstream PR](https://github.com/sgl-project/sglang/pull/46265) · state: closed · merged: False

## Original PR description

## Motivation

**What goes wrong without this patch.** DeepSeek-R1-0528 ModelSlim W4A8 ([Modelers_Park/DeepSeek-R1-0528-w4a8](https://modelers.cn/Modelers_Park/DeepSeek-R1-0528-w4a8), `group_size=256`) loads and starts on Ascend A3, but it does not produce a usable answer:

- Setup: one A3 server, the DeepSeek-R1 Cookbook recipe, SGLang `d9ce511`.
- Request: a plain chat prompt, `What is 2+3? Give only the number.`
- Result: `content` is empty and `finish_reason` is `length` (at 1024 completion tokens). `reasoning_content` contains repetitive text, and the model never gives a final answer.

With this patch, the same setup answers `5` with `finish_reason: "stop"` and passes all 10 functional checks (plain, streaming, sequential, multi-turn and concurrent requests). The full GSM8K results are below.

**Why.** Two independent defects in the grouped W4A8 MoE path:

1. `ModelSlimConfig.get_moe_scheme` instantiates every MoE scheme with `cls(self, weight_group)`. `ModelSlimW4A8Int8MoE` therefore never receives the checkpoint's `group_size` or the layer's `moe_tp_size`, so it falls back to per-channel handling (`group_size` 0) for weights that are quantized in groups of 256.
2. `NPUW4A8Int8MoEMethod._process_scale` unpacks `group_num, k, n = weight.shape` and doubles `n`, but at this point the weight is still `[E, packed_out, in]`. The doubled dimension is the input size, so the group scales are reshaped with the wrong width.

The affected lines are identical in `d9ce511`, `8e3e2980d` (the SGLang inside `quay.io/ascend/sglang:main-cann9.1.0-a3`) and `bb72b47`, so `main` (checked at `a99eaf9a`, 2026-10-24) and the image (digest `sha256:9e653832d34f058a0035b5009fe8efcd61358c72fec5cf7412df7a236ff544ae`) contain the same code. The empty-answer symptom was reproduced end to end on `d9ce511`; for the other revisions the affected lines were verified by source comparison.

Related Cookbook task: Ascend/sglang#1206.

## Modifications

- `modelslim.py`: for `ModelSlimW4A8Int8MoE`, pass `group_size` from the quantization description and `tp_size=layer.moe_tp_size`.
- `moe_methods.py`: take `n` from the packed output dimension (`group_num, n, _ = weight.shape`).
- `test_npu_modelslim_grouped_w4a8.py`: three unit tests covering group-size passthrough, TP-size passthrough and the scale shape/packed values. All three fail on `bb72b47` without the fix (two assertion failures and one error: `group_size` is `0` instead of `256`, `tp_size` is `1` instead of `4`, and the scale step raises `RuntimeError: The size of tensor a (32) must match the size of tensor b (128)`), and all three pass with it.
