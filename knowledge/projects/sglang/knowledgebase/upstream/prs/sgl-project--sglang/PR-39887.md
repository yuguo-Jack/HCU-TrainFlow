# [Fix] openai: Keep chat stream IDs consistent

[Upstream PR](https://github.com/sgl-project/sglang/pull/39887) · state: open · merged: False

## Original PR description

## Motivation

With `n > 1`, the Python chat server uses a different engine ID for each candidate. As a result, chunks from one response can have different `id` values. OpenAI clients expect one ID for the whole response.

Main already keeps `created` constant after #43026. This PR fixes the remaining ID mismatch in #39864.

Fixes #39864.

## Modifications

Use the ID from the first engine result for every response chunk. Each candidate keeps its own `choices[].index`.

Normalize the ID before the result reaches the response helpers. This covers text, tool calls, encoded output, usage, hidden states, and `sglext` events. Copy the result only if its ID differs, so the original engine data stays intact.

## Accuracy Tests

The change affects response metadata only.

- All **161 tests and 167 subtests** in `test/registered/unit/entrypoints/openai/test_serving_chat.py` passed in a Linux CPU container.
- The three regression tests cover either candidate first, plain and named `sglext` events, tool arguments, and encoded output. All three detect inconsistent IDs with the current main code.
- Pre-commit checks passed for both changed files.

The tests use mock engine output. No live GPU server or model accuracy test was run.

The full-repo pre-commit run did not pass locally. Two workflow checks lack PyYAML, the gateway formatter cannot find `rustup`, and Clippy fails in unchanged Rust code. These files are outside this PR's two-file diff.
