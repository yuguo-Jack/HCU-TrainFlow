# [Perf] dsv41: Speed up encoder SWA bounded-replay prefill by checking the request-window history once per layout

[Upstream PR](https://github.com/sgl-project/sglang/pull/42921) · state: open · merged: False

## Original PR description

Stacked on #42715 (request-window copy kernels), which this PR modifies. This branch carries #42715's two commits exactly as they are on #42715 (head a3db1d2df7, on current main); the diff to review is the last commit, "[DSv4.1] Check the request-window history once per layout, without a host sync". I will rebase this PR once #42715 lands.

## Motivation

With `--enable-encoder-swa-bounded-replay`, `RequestWindow.buffer` verifies before each attention layer that the window history it is about to gather is present. It does this with `torch.equal` on a boolean-mask gather (`tags[layer, src][valid]`). That is a host synchronization once per layer. In an eager prefill chunk the CPU then waits for the GPU 43 times (DeepSeek-V4.1-Flash), so kernel launch cannot run ahead of execution.

Profile of one 51,872-token prefill on 4x RTX PRO 6000 Blackwell (SM120), TP4, rank 0, before this change:
- `aten::nonzero` from this check: 560 calls, 2,142 ms of host time;
- the GPU was busy 80% of the 5.26 s window.

## Modifications

- A layer's history tags change only in that layer's own commit. A layer's required history is therefore unchanged until its first gather. Checking every layer at the layout's first gather is equivalent to checking each layer before its own gather, and stricter for layers not used yet.
- `buffer` now runs that all-layer check once per eager layout activation, as `torch._assert_async` on the device. The host does not wait for the GPU. A decoder bounded-replay tail layout is activated separately, so it is checked again.
- A flag records that the check ran. It is cleared by `activate`, `reset` and `initialize_dummy_history`, and on capture-phase calls, so eager calls after a capture check again.
- Failure mode: a missing history used to raise `RuntimeError` before any state was written. It now fails as a device-side assert at the next synchronizing call, and the worker must restart.

## Accuracy Tests

The check only validates state; it does not change what is gathered or committed. `test/registered/kernels/ops/attention/dsv4/test_request_window_copy.py`, new `TestRequestWindowHistoryCheck` (CUDA):
- a valid window is checked once for all layers (one assert, condition true);
- a missing history row in the last layer makes the first layer's check false;
- a new layout is checked again;
- the commits of every layer run under `torch.cuda.set_sync_debug_mode("error")`;
- in a child process, a missing history row fails with a device-side assert.

The first three fail on the per-layer check, and the sync-debug test fails on any host-side check. The existing copy tests from #42715 pass. On RTX PRO 6000 Blackwell (SM120), torch 2.14.1+cu130, Triton 3.8.0, `test_request_window_copy.py` passes at this branch (8 tests: 3 copy tests and 5 history-check tests); with this commit's production change reverted, the 5 history-check tests fail.

## Speed Tests and Profiling

DeepSeek-V4.1-Flash, 4x RTX PRO 6000 Blackwell (SM120, PCIe, 250 W power limit), TP4, EP2, DSpark speculative decoding, `--enable-encoder-swa-bounded-replay`, `--chunked-prefill-size 8192`. Cold prefill (no cached prefix), throughput = prompt tokens / client-observed TTFT, median of 3 repetitions of 30 s each. Same build and configuration with and without an earlier revision of this change, which already checked once per layout but still with a blocking `torch.equal`:

| Prompt | per-layer check | once per layout (blocking) |
|---|---|---|
| 8k | 8,654 tok/s | 9,109 tok/s (+5.3%) |
| 32k | 10,761 tok/s | 11,163 tok/s (+3.7%) |
| 128k | 11,138 tok/s | 11,638 tok/s (+4.5%) |

This PR also makes the remaining check asynchronous. That step was measured only together with other host-sync removals that main has since made separately (#41659), so I have no isolated number for it.
