## Motivation

With `--enable-unified-memory`, a DFLASH or DSPARK draft can be fused into the target's unified KV pool, so its layers are routed: a full-attention draft layer writes the pool's FULL id space and a sliding-window draft layer writes its window's id space. The draft's context-KV writes (the target hidden states materialized into draft KV) still wrote through the pool-wide `set_kv_buffer_prefix_valid` / a single location vector, so a routed window layer received FULL ids and wrote the wrong rows.

## Modifications

- `mem_cache/kv/router.py::KVLayer.store_prefix`: commits each request's live prefix through the layer's own route and physical ids, as `KVLayer.store` already does for plain writes.
- `speculative/dflash_worker_v2.py`: context appends (sequential, fused, and prefix-valid paths) take the window cache locations next to the FULL ones (`swa_cache_loc`, `_draft_write_ids(plan, kind=)`) and write through the layer route; mismatched FULL/window shapes are rejected.
- `models/dspark.py`, `speculative/dspark_components/dspark_kv_inject.py`, `dspark_verify.py`: the DSPARK context injector passes both id spaces; the fused single-location kernel is used only when every draft layer is owned by FULL, otherwise the per-layer path runs.
- Tests (`test/registered/unit/mem_cache/test_dense_fused_draft_geometry.py`, `test_runner_ids_draft_disposition.py`): layer stores keep the FULL and window id spaces; DFLASH normal and prefix writes route per layer; the DSPARK injector uses both plan id spaces; single-location fusion declines window layers.

No change without unified memory or without a fused routed draft.
