# :construction: [WIP][llm][npu][quant] Fix offline W8A8 MXFP8 quantization for Qwen3.5 on Ascend NPU

[Upstream PR](https://github.com/sgl-project/sglang/pull/32266) · state: closed · merged: False

## Original PR description

# Summary

Fixes Qwen3.5-specific ModelSlim loading issues for offline W8A8 MXFP8 checkpoints on Ascend NPU, covering the language-model GDN projections and the Qwen3-VL visual tower.

> **Offline scope:** Online MXFP8 (`--quantization mxfp8`) already loads BF16/FP16 weights and runs through the existing Ascend MoE implementation from #30768. This PR does not add or modify the online quantization path.

> **Merge dependency:** This PR must be merged only after #32745.
>
> **Merge order:** #32745 → #32266. This branch already contains the current #32745 head, so its Gemma RMSNorm changes are inherited here.

**Inherited Ascend Gemma RMSNorm support**

- The complete Ascend 950 Gemma RMSNorm implementation and its `sgl-kernel-npu` dependency are owned by #32745.
- This PR inherits that branch and adds only the Qwen3.5 offline ModelSlim and visual-tower deltas on top; it does not duplicate the Gemma RMSNorm implementation.

**Qwen3.5 offline ModelSlim packed-module resolution**

- Qwen3.5 exposes the GDN packed mappings `in_proj_qkvz -> [in_proj_qkv, in_proj_z]` and `in_proj_ba -> [in_proj_b, in_proj_a]` at the top level.
- The NPU ModelSlim loader also adds scoped `model` / `visual` mappings. Previously, selecting only the scoped mapping dropped the Qwen3.5 mappings, so those projections silently fell back to unquantized Linear and their checkpoint `weight_scale` tensors were ignored.
- The resolver now preserves top-level list mappings first, then overlays the matching scoped mapping.

**Qwen3-VL offline visual-tower quantization**

- `Qwen3VLForConditionalGeneration` now passes the checkpoint `quant_config` into `Qwen3VLMoeVisionModel` instead of hard-coding `None`.
- This lets visual attention QKV/projection, MLP FC1/FC2, and merger layers register their offline ModelSlim MXFP8 weights and scales rather than skipping the checkpoint's `visual.*.weight_scale` parameters.

**Offline partial MXFP8 block-scale layout**

- ModelSlim exports one scale per 32 input elements. The placeholder now uses `ceil(K / 32)` so a final partial block is retained.
- Qwen3-VL contains visual FC2 projections with `K=4304`: the checkpoint has 135 scales, while the previous floor division allocated 134 and caused the row-parallel loader to truncate the final scale.
- The NPU matmul consumes pair-split scales. An odd scale count is zero-padded before reshape, so `135 -> 136 -> 68` pairs, matching the kernel requirement `ceil(4304 / 64)=68` and the vllm-ascend implementation.

# Implementation Notes

## Offline-only scope

These changes are exercised when SGLang detects `quant_model_description.json` and loads a pre-quantized ModelSlim checkpoint. The online `--quantization mxfp8` path continues to use the existing implementation from #30768 and is unchanged.

## Dependency on #32745

The Gemma RMSNorm support required for Ascend 950 is inherited from #32745. To keep that implementation single-sourced and preserve the intended branch history, merge #32745 first and then merge this PR.

## Packed mapping precedence

Top-level list-valued mappings are model-specific and remain valid alongside the generic scoped mappings added by the NPU loader. The resolver merges the two levels instead of choosing one and discarding the other; a scoped entry wins only when the same packed-module key exists at both levels.

## Offline scale padding

The zero padding is applied only to the synthetic partner of the final partial 32-element block. It does not replace or alter any checkpoint scale. After transpose, the kernel-facing layout is `[ceil(K / 64), out, 2]`.
