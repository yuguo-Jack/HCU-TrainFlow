# [Feat] tracing: Trace only the first rank of each attention TP/CP group by default

[Upstream PR](https://github.com/sgl-project/sglang/pull/44799) · state: closed · merged: False

## Original PR description

## Motivation

Every scheduler process initializes tracing, so with TP 8 each request gets eight sets of scheduler spans. The ranks of an attention TP/CP group run the same requests in lockstep, so the copies describe the same batches. They multiply span volume (export cost, collector load, storage) by the group size and crowd the trace view, without adding information for request-level debugging.

This changes a default, so it is kept to one small PR, with an environment variable to restore the previous behavior.

## Modifications

- `should_trace_rank()` in `trace.py` returns true when the process's attention TP rank and attention CP rank are both 0, read from `get_parallel()` (published before `run_scheduler_process` sets up tracing).
- `run_scheduler_process` initializes tracing only when `should_trace_rank()` returns true.
- `SGLANG_TRACE_ALL_RANKS=1` traces every rank, as before, e.g. to debug a rank that diverges.

With DP attention, each DP group keeps its own tracing rank (attention TP rank 0 of the group), and each PP stage keeps one too. A trace context sent to a rank that does not trace arrives disabled, as it already does for any process without tracing (`TraceReqContext.__setstate__`, `TraceReqContextAsync.__setstate__`).

Docs: `SGLANG_TRACE_ALL_RANKS` in `environment_variables.mdx`, and a note under the span-structure diagram in `production_request_trace.mdx`.

### Behavior changes for existing tracing users

- By default only scheduler processes with attention TP rank 0 and attention CP rank 0 export spans; `Scheduler [TP n]` spans for other ranks no longer appear.
- The Mooncake KV transfer worker spans of those other ranks no longer appear either, since they run in the same scheduler process.
- `SGLANG_TRACE_ALL_RANKS=1` restores the previous behavior.

## Accuracy Tests

Not applicable: tracing only, no change to model outputs.

## Speed Tests and Profiling

Not benchmarked. With tracing on, scheduler span volume drops by the attention TP × CP group size; with tracing off nothing changes.

## Tests

- New: `test_trace.py::TestShouldTraceRank::test_only_the_first_rank_of_each_attention_group_traces` covers TP rank 1, CP rank 1, and the `SGLANG_TRACE_ALL_RANKS` override.
