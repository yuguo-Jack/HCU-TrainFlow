# [Fix] deepseek-v3: Fix quadratic regex scans in the tool-call parser

[Upstream PR](https://github.com/sgl-project/sglang/pull/42592) · state: open · merged: False

## Original PR description

## Motivation

`DeepSeekV3Detector` (`deepseekv3`) scans model output with patterns that go quadratic when the closing tokens never arrive:

1. `parse_streaming_increment` runs ``re.search(r"<｜tool▁call▁begin｜>(.*)<｜tool▁sep｜>(.*)\n```json\n(.*)\n```.*")`` over the **whole buffer on every chunk**. With repeated `<｜tool▁call▁begin｜>` / `<｜tool▁sep｜>` tokens and no JSON fence, each call backtracks over every begin/sep pair.
2. `detect_and_parse` uses `re.findall(begin.*?end)`, rescanning to the end from every begin token, then the same greedy detail pattern on each block.

| Input | Before | After |
|---|---|---|
| 130 KB, one streaming call | 8.3 – 9.4 s | ~0 |
| 31 KB stream in 64-char (multi-token / MTP) chunks | 0.65 s worst chunk, **85 s total** | 0.01 s total |
| 130 KB, non-stream | 5.7 s | ~0 |

Tool-call parsing runs synchronously on the tokenizer manager's event loop, so one such response stalls every in-flight request. Found with an Atheris fuzzing harness that records per-input parse time.

## Modifications

- `_iter_call_blocks`: a linear `str.find` scan for `begin ... end` blocks. It is used in `detect_and_parse` and when trimming the completed block from the stream buffer.
- `_greedy_chain_search(text, a, b, c, d)`: computes the same groups as `re.search(a(.*)b(.*)c(.*)d, DOTALL)` for literal tokens from a few `find` / `rfind` calls. A match can only start at the first `a`, and the greedy groups take the last `d`, then the last `c` ending before it, then the last `b` ending before that. It replaces both greedy patterns. The unused `func_call_regex` / `func_detail_regex` attributes and `import re` are removed.
- Regression test in `TestDeepSeekV3Detector` (fails on `main`, passes here).

## Accuracy Tests

- `_greedy_chain_search` vs both original patterns on 300k random token strings: identical.
- Differential test of `main` vs patched detector (20k random + 20k mutated well-formed inputs, streaming under random re-chunking and non-streaming): **0 mismatches** (11.5k produced parsed calls).
- `test/registered/unit/function_call/`: 630 passed.
