# [Feat] profiler: Expose detailed step annotations in bench_one_batch_server and fall back to device seq_lens

[Upstream PR](https://github.com/sgl-project/sglang/pull/45446) · state: closed · merged: False

## Original PR description

## Motivation

Detailed step annotations (the `detailed_annotations` option of `/start_profile`, added in #24911) fold per-step KV and query aggregates (`g_sq`, `g_sk`, ...) into the `step[...]` trace span. Two gaps keep them out of the most common way of capturing a trace:

- `sglang.bench_one_batch_server` and `sglang.profiler.run_profile` have no way to request them, so a benchmark-driven profile never carries the aggregates.
- Speculative target-verify batches under overlap scheduling do not carry a `seq_lens_cpu` mirror. `build_detailed_annotation_suffix` returns an empty suffix for them, so even with annotations enabled the `VERIFY` steps emit the bare label and the trace loses the KV lengths for exactly the steps a roofline-style analysis needs.

## Modifications

- `python/sglang/benchmark/one_batch_server.py`: new `--profile-detailed-annotations` flag on `BenchArgs`, passed through `run_one_case` to `run_profile`.
- `python/sglang/profiler.py`: `run_profile` gains `detailed_annotations: bool = False` and forwards it in the `/start_profile` request body. The default is unchanged.
- `python/sglang/srt/model_executor/step_span_utils.py`: a `_decode_seq_lens_cpu` helper returns `seq_lens_cpu` when present and otherwise copies the device `seq_lens` to the host. The copy is skipped when the tensor is on CUDA and the current stream is capturing, so a graph capture under an active profile is unaffected, and nothing here runs while detailed annotations are off.
- `test/registered/unit/managers/test_detailed_annotations.py`: the fixture gains `seq_lens`; two new cases check that a `VERIFY` batch without the CPU mirror emits aggregates from `seq_lens`, and that the CPU mirror takes precedence when both are present. The existing "no mirror -> base label" cases still pass with the fixture default `seq_lens=None`.

## Accuracy Tests

Not applicable: no change to model outputs. Only the profiler request body and the trace span label change, and only when detailed annotations are requested.

## Speed Tests and Profiling

Not applicable off the profile path. With detailed annotations on and no CPU mirror, each decode-family step does one device-to-host copy of `seq_lens` (a batch-size-long integer tensor), only while a profile is active.

`test/registered/unit/managers/test_detailed_annotations.py` run locally on this head (CPU, `pytest`): 19 passed.
