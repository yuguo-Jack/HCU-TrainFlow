## Motivation

Currently, when consensus checker enabled, in a deployement of PP prefill and TP decode, the prefill process fails **during warmup**.

The failure messages are: (keyword `max_new_tokens`)
```
[2026-10-26 06:47:04 PP0] Found rank divergence for 4 events(s)! local hash: 8c66d3efda24c238276585a94f94721e8ac1ce3e, events = ["match_prefix called params=params=MatchPrefixParams(... req=Req(... max_new_tokens=8 ...
[2026-10-26 06:47:04 PP1] Found rank divergence for 4 events(s)! local hash: 927c295b9e06d16c3aabbb6a8927fe60e3705aef, events = ["match_prefix called params=params=MatchPrefixParams(... req=Req(... max_new_tokens=1 ...
[2026-10-26 06:47:04 PP2] Found rank divergence for 4 events(s)! local hash: 927c295b9e06d16c3aabbb6a8927fe60e3705aef, events = ["match_prefix called params=params=MatchPrefixParams(... req=Req(... max_new_tokens=1 ...
[2026-10-26 06:47:04 PP3] Found rank divergence for 4 events(s)! local hash: 927c295b9e06d16c3aabbb6a8927fe60e3705aef, events = ["match_prefix called params=params=MatchPrefixParams(... req=Req(... max_new_tokens=1 ...
```

When calling `UnifiedRadixCache.match_prefix`, PP0 passes `Req` with `max_new_tokens=8`, and other PP ranks passes `max_new_tokens=1`.

Timeline:
1. **PP0** receives a warmup request with `max_new_tokens=8`.
2. **PP1** calls `UnifiedRadixCache.match_prefix`, passing `max_new_tokens=8`.
3. **PP0** sets `max_new_tokens=1` in `Scheduler._add_request_to_queue -> ._prefetch_kvcache -> PrefillBootstrapQueue.add -> .create_sender -> ._process_req`.
4. **PP0** sends the request to **PP1**, with `max_new_tokens=1`.
5. **PP1** receives the warmup request, with `max_new_tokens=1`.
6. **PP1** calls `UnifiedRadixCache.match_prefix`, passing `max_new_tokens=1`.  **Divergence detected!**

For now, it is not harmful to `match_prefix` with `max_new_tokens` difference, as it does nothing on that parameter.  However, it would be nice to fix the root cause to prevent it from harming the future code.


## Modifications

1. Move `max_new_tokens=1` to `Scheduler.init_req_max_new_tokens`, which is called for every request at very early stage.
2. Enable consensus checker for PD tests.
