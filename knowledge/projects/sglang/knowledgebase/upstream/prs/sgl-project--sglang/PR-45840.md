# [Fix] spark25: Preserve nullable tool argument types

[Upstream PR](https://github.com/sgl-project/sglang/pull/45840) · state: open · merged: False

## Original PR description

## Motivation

Spark2_5 tool calls with nullable parameter schemas produce incorrectly typed arguments. For example, Pydantic `count: int | None` generates an `anyOf` schema, and an XML value of `42` currently becomes `{"count":"42"}`. Nullable booleans, arrays and objects have the same problem in both streaming and non-streaming parsing.

## Modifications

Reuse `infer_type_from_json_schema` when selecting the Spark2_5 argument conversion type, with string precedence for mixed `type` arrays. Add a CPU regression covering Pydantic-generated nullable schemas, JSON Schema type arrays, null values, mixed string unions in both orders, and one-character/seven-character streaming chunks.

## Validation

- Before the fix: the six non-null nullable-schema regression subtests fail with JSON Schema validation errors.
- Mixed string-union regression: 45 subtests fail on the initial PR commit when integer conversion or JSON decoding changes the XML text. With string precedence, 43 tests and 102 subtests pass across the regression file, JSON-schema constraint tests, and schema-normalization tests.
- These are Windows CPU replays using the real detector, protocol and schema helper modules. The replay bypasses the package's Linux-only bootstrap and substitutes `unittest.TestCase` for the server-oriented `CustomTestCase`. Full Linux test-harness validation is pending CI.
- Changed-file pre-commit checks, Python compilation, and `git diff --check` pass.

## Accuracy Tests / Speed Tests

This change operates on generated tool-call text. Model inference and performance benchmarks were untested.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Preserve string alternatives in mixed type arrays**

When a valid schema expresses a mixed union as `{"type":["integer","string"]}` rather than the equivalent `anyOf` form, this now calls a helper that returns the first non-null type. For an XML value such as `2.5`, integer conversion fails and `_convert_value` then JSON-decodes it to float `2.5`, which matches neither allowed type; before this change the list-valued `type` fell back to string and produced valid `"2.5"`. Limit coercion to arrays with exactly one non-null type, or give a string member the same precedence already used for `anyOf`.
