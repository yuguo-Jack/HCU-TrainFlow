# [Fix] hicache: Disable the NIXL L3 cleaner in the NIXL storage tests

[Upstream PR](https://github.com/sgl-project/sglang/pull/47123) · state: open · merged: False

## Original PR description

## Motivation

`test/registered/unit/mem_cache/test_hicache_nixl_storage.py` fails intermittently in `base-b-test-1-gpu-small`. Example failing jobs: [#46780](https://github.com/sgl-project/sglang/actions/runs/40713563072/job/122922742593) and `cc-fixes-rebased` (job 122948256119), both on 2026-10-28:

```
POSIX path-mode open failed: nixl::FileFd("/tmp/test_nixl_unified/72/same_prefix_False_test_model_0_2_mamba"): No such file or directory
FAIL: test_mla_mamba_round_trip_keeps_each_tp_rank (zero_copy=False)
AssertionError: Lists differ: [False] != [True]
```

**Cause:** `HiCacheNixl` starts `HiCacheL3Cleaner` on TP rank 0 by default (`l3_cleaner_enabled=True`, high watermark 80%). The cleaner thread runs its first tick immediately. If the filesystem holding the storage directory is at or above the watermark, it unlinks the oldest files. This test writes the rank-0 checkpoint first and then reads it back, so on a runner whose `/tmp` disk is near 80% full, the cleaner deletes that file before the read.

## Modifications

Set `"l3_cleaner_enabled": False` in the two file-backed configs that write from TP rank 0: `TestNixlUnified.setUp`, which the failing test inherits via `replace(...)`, and `_make_direct_io_hicache`. The cleaner keeps its own coverage in `test_hicache_nixl_cleaner.py`.

## Checks

These were run on a B200 devbox (nixl 1.5.1) with this file run 10 times per row. To simulate a full disk, a wrapper lowers the cleaner's watermark to 0.1% and keeps the config's `enabled` flag:
