## Motivation
After PR #24013 landed, Ascend NPU VLM serving (ViT CUDA/NPU graph + ascend_attn) regressed on high-concurrency 1080p workloads (e.g. Qwen3.6-27B performance cases that previously passed on TP2).

Two separate issues showed up:

1. TND seqlen mismatch on the ViT NPU graph path
<img width="1300" height="400" alt="image" src="https://github.com/user-attachments/assets/873279c0-cc06-4716-98b9-077fe499d991" />
npu_fused_infer_attention_score with input_layout="TND" requires actual_seq_lengths to be cumulative (same semantics as cu_seqlens[1:]), and the last element must equal query.shape[0].
ViTNpuGraphRunner still stored per-sequence lengths (cu_seqlens[1:] - cu_seqlens[:-1]), which matched the old _npu_flash_attention_unpad API but not TND.
This often passed for a single image (last length == T by accident) and failed after #24013 packed many images into one ViT call (e.g. queryT=89760 vs last=8160).

2. Unbounded cross-request ViT batching OOM on NPU
#24013 batches all per-image cache misses across requests into one ViT forward. HIP already falls back to the per-request path because large cross-request batches regressed on ROCm CI; NPU followed the CUDA batching path with no cap.
On large images + high concurrency this spikes peak memory (even when LLM prefill batching of many seqs is fine). This risk was also raised in review (discussion) with a suggested VIT_ENCODE_MAX_TOKENS split, but that was not implemented for CUDA/NPU.

## Modifications

vit_npu_graph_runner.py
Cache cu_seqlens[1:] (cumulative) for graph capture instead of per-sequence deltas, so TND actual_seq_lengths matches queryT under multi-image ViT batches.

<img width="1347" height="368" alt="image" src="https://github.com/user-attachments/assets/ccaf9e46-3be4-4dc0-9251-eb8999b09b99" />

mm_utils.py
<img width="467" height="102" alt="image" src="https://github.com/user-attachments/assets/549b79ca-fe2f-422c-a891-ebc28c7b5314" />

Treat NPU like HIP for per-image embedding: use _get_chunked_embedding_by_item (per-request ViT) instead of _batch_encode_per_image_misses (cross-request batch), via if _is_hip or _is_npu to avoid OOM when making vit call for too much images at once.
