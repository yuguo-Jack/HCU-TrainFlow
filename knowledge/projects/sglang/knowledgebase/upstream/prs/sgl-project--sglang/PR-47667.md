# [Perf] minimax-m3: Overlap the MegaMoE shared expert with the routed launch

[Upstream PR](https://github.com/sgl-project/sglang/pull/47667) · state: open · merged: False

## Original PR description

## Motivation

With `--moe-a2a-backend megamoe`, MiniMax-M3's MoE block runs its shared expert (two MXFP8 GEMMs plus the SwiGLU-OAI activation) on the main stream before the routed MegaMoE kernel, one after the other. In a DEP4 decode step on GB300 (MiniMax-M3.1-Flash, attention DP 4 + EP 4, DSpark block 7, 8 requests per DP rank at ~64k context) those two GEMMs are 2 of the 4 MXFP8 GEMMs per MoE layer, about 1.2 ms of an 18.6 ms step.

## Modifications

- `MiniMaxM3MoE.forward_mega_moe`: in captured graphs with an alt stream, launch the router, top-k and routed MegaMoE on the alt stream first, then the shared MLP on the main stream, and join before adding the two outputs. Same kernels and arithmetic; eager steps and the FlashInfer TRT-LLM decode path are unchanged.
- The routed half moves into `_mega_moe_topk` and `_mega_moe_routed` so both paths share it.
- `SGLANG_OPT_MINIMAX_M3_MEGA_MOE_SHARED_OVERLAP` (default on) turns it off.

## Accuracy Tests

GB300 DEP4 (`--tp 4 --attn-dp-size 4 --enable-dp-lm-head --ep 4 --moe-a2a-backend megamoe`, DSpark block 7, FP8 draft KV), image `lmsysorg/sglang:nightly-cu134-20261030-e371881` with this change applied:

| | chat GSM8K, 40 q one at a time | chat GSM8K, 1,319 q at 32 threads | acceptance length coding / GSM8K | passkey 128k / 512k |
|---|---|---|---|---|
| this PR | 0.950 | 0.962 | 4.05 / 4.38 | pass / pass |
| same flags, without it | 0.975 | 0.963 | 4.05 / 4.38 | pass / pass |

## Speed Tests and Profiling

Decode step from nsys (one wave of requests, every prefill done), GB300 DEP4 as above:

| requests per DP rank | main | this PR |
|---|---|---|
| 8 (~64k context) | 18.62 ms | 17.80 ms (−4.4 %) |
| 32 (~8k context) | 23.87 ms | 23.27 ms (−2.5 %) |

The main and PR captures ran the same day on different nodes; the serving A/B below is the same-window comparison. Exclusive dense-GEMM time per step falls 3.47 → 3.09 ms at 8 per rank: the shared expert now runs beside MegaMoE. Raising `SGLANG_OPT_DEEPGEMM_MEGA_MOE_RESERVED_SMS` from 2 to 16 or 32 did not change the step (17.80 / 17.86 ms).

Serving, untraced, same cluster and window, two fresh boots per arm in the order main / PR / PR / main, `sglang.benchmark.serving` random 65,536 in / 1,024 out (`--random-range-ratio 1.0 --flush-cache`), one unmeasured warm-up cell first:

| cell | main: output tok/s, median TPOT | this PR | change |
|---|---|---|---|
| 32 concurrent, 64 prompts | 1,256 / 1,232, 11.42 / 11.38 ms | 1,286 / 1,291, 11.08 / 11.13 ms | +3.6 % tok/s, −2.6 % TPOT |
| 64 concurrent, 128 prompts | 1,292 / 1,297, 11.48 / 11.44 ms | 1,329 / 1,327, 11.13 / 11.17 ms | +2.6 %, −2.8 % |
| 32 concurrent, one wave, 16,384 out | 5,001 / 5,034, 5.08 / 5.05 ms | 5,212 / 5,214, 4.82 / 4.83 ms | +3.9 %, −4.7 % |

At 16 concurrent requests the cell is prefill-bound and the two arms are within boot spread.
