# [VLM][MM refactor 2/6] Initialize multimodal processors from a processor config

[Upstream PR](https://github.com/sgl-project/sglang/pull/43421) · state: open · merged: False

## Original PR description

## Motivation

`BaseMultimodalProcessor.__init__` reads its settings from `get_mm()`, which exists only inside a running server, so a trainer cannot construct one.

## Modifications

- Add `MultimodalProcessorConfig` (`processors/processor_config.py`), a frozen `msgspec.Struct` with the settings a processor reads at init: image processor backend and options, `mm_process_config`, worker counts and start method, media URL policy.
- `BaseMultimodalProcessor` fills it from `get_mm()` and initializes from it. Effective attributes are unchanged.

No serving behavior change: the CPU worker start method, `SGLANG_CPU_WORKERS` and the media URL arguments are resolved as before.

## Tests

- Existing multimodal tests pass on every commit; `test_llava_processor_pool.py` sets the two CPU pool attributes directly.
