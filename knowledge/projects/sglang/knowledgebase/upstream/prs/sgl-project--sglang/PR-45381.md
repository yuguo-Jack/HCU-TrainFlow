# [Fix] [NVIDIA] deepseek_v4: Build the DeepGEMM schedule for the low-ratio prefill-graph indexer on SM12x

[Upstream PR](https://github.com/sgl-project/sglang/pull/45381) · state: open · merged: False

## Original PR description

## Motivation

On SM120, `--cuda-graph-backend-prefill breakable` cannot start DeepSeek-V4.1, the 1017 variant included: the prefill CUDA graph capture fails in the ratio-1/2 indexer. Both `DeepSeek-V4.1-Flash` and `DeepSeek-V4.1-Flash-1017` declare the same 20 ratio-1 and 18 ratio-2 layers; reproduced with the 1017.

The model hook forces `SGLANG_FP8_PAGED_MQA_LOGITS_TORCH` on SM120, so `PagedIndexerMetadata.__post_init__` sets `deep_gemm_metadata = None` unless `force_deep_gemm_metadata` is set. `_low_ratio_prefill_indexer_metadata`, which builds the c1/c2 indexer metadata for the prefill graph, never sets it. The captured low-ratio indexer has no Torch path: `_deep_gemm_prefill_captured` always calls `deep_gemm_fp4_paged_mqa_logits` with the plan from `row_chunks()`, which is then `None`:

```
File "sglang/srt/layers/attention/deepseek_v4_backend.py", line 3275, in forward_low_ratio_sources
File "sglang/srt/layers/attention/deepseek_v4_backend.py", line 3745, in _low_ratio_index_topk_captured
File "sglang/srt/layers/attention/dsv4/v41_indexer/full_topk.py", line 65, in topk_prefill_captured
File "sglang/srt/layers/attention/dsv4/v41_indexer/full_topk.py", line 180, in _deep_gemm_prefill_captured
File "sglang/kernels/ops/attention/dsv4/index_logits.py", line 108, in deep_gemm_fp4_paged_mqa_logits
File "deep_gemm/__init__.py", line 164, in fp8_fp4_paged_mqa_logits
RuntimeError: Assertion error (/deepgemm/csrc/apis/../jit_kernels/impls/../heuristics/../../utils/layout.hpp:45): t.is_cuda()
```

This complements #45261, which fixes the same missing schedule on the decode path (`init_forward_metadata_indexer`); without that one, V4.1 does not start on SM120 at all. The two PRs touch different functions and do not conflict.

## Modifications

`_low_ratio_prefill_indexer_metadata` passes `force_deep_gemm_metadata=get_platform().is_sm120`, the condition #45261 applies to the low-ratio decode metadata. On SM120 the prefill-graph indexer then gets its DeepGEMM schedule (per row chunk when `row_chunk > 0`). Other platforms are unchanged: there the flag stays `False` as before.

## Accuracy Tests

One of our GPU servers, 4x RTX PRO 6000 Blackwell (SM120), TP4 / EP4, DeepSeek-V4.1-Flash-1017 with DSpark, `--enable-encoder-swa-bounded-replay`, FP8 KV cache, `--chunked-prefill-size 2048`, context 1M. Tree: `main` @ `ed0b8f43`, FlashInfer 0.7.2, with three other open SM120 fixes that V4.1 needs here: #42371 (without it `make_candidate_indexer` refuses SM120 at backend start, issue #42364), a local equivalent of #45261 (the decode-path fix above) and a local equivalent of #42714. We hit the last one ourselves: without it, 64 running requests × 1M context (also 32 × 1M and 64 × 800K) failed at the first decode with an illegal memory access that a CUDA coredump placed in `_page_split_kernel`; with it, that configuration ran.

- Without this change, with `--cuda-graph-backend-prefill breakable`: the capture fails as above, on every rank.
- With it: the prefill graph is captured (34 s, 1.77 GB on rank 0) and prefill batches report `cuda graph: True`.

| | prefill graph off | breakable prefill graph, with this change |
|---|---|---|
| GSM8K 5-shot, 1319 questions (`few_shot_gsm8k`, parallel 64) | 0.923 / 0.899 (two runs) | 0.911 |
| Code planted at a random depth of a ~14K-token prompt, greedy recall | 6/6 | 6/6 |

The two runs without the graph show the run-to-run spread; the result with the graph falls inside it. The ~14K-token prompts fit under the graph's 16 384-token replay limit, so they prefill through the captured graph, where the ratio-1/2 indexers must pick the planted block.

## Speed Tests and Profiling

No speed change is intended; this is a crash fix. For reference, on this machine the breakable prefill graph was slower than eager prefill above ~500 prompt tokens (median TTFT, prefix cache defeated, one request at a time):

| Prompt tokens | 126 | 518 | 1 980 | 7 860 | 15 677 |
|---|---|---|---|---|---|
| prefill graph off | 0.094 s | 0.104 s | 0.184 s | 0.645 s | 1.263 s |
| breakable prefill graph | 0.070 s | 0.117 s | 0.281 s | 1.015 s | 2.007 s |
