# [sgl-router] Policy reorg 5/N: cache-aware policy with a local/remote prefix source

[Upstream PR](https://github.com/sgl-project/sglang/pull/40088) · state: closed · merged: False

## Original PR description

Stacked on the 4/N affinity PR. Still built beside the current path.

## Modifications

- `policy_reorg/cache_aware.rs`: `CacheAwarePolicy::pick()` owns what today spans `cache_aware.rs`, `admission.rs::resolve_cache_candidates` and the cache rung of `selection.rs`: minimum-hit gate, bounded candidates (over the supplied set), queue gate before admission, fleet-saturation re-admit, saturation pin, switch margin + pressure guard, and the power-of-two miss fallback (queue-gate-admitted tier first). Hard acceptance goes through the attached `Admission` with per-candidate uncached work. Decision labels, admission/pressure-guard counters and the sampled operator logs are kept.
- `CacheSource` normalizes the router-local KV-event index and the remote indexer into `PrefixLookup`; an unavailable backend reads as a miss, a rejected query becomes `PickError::InvalidSignal`. `PrefixMemo` runs the lookup once per request across buckets and lets a size bucket skip the tournament the affinity group already ran, so counters are booked once.
- `state/`: `PrefixLookup`/`PrefixMatch`, `BlockSizeOracle::block_hashes`, `KvEventIndex::match_prefix` (the radix-tree provider's lookup), `LoadView::from_snapshot`.
- `HitRequired` returns `NoCandidates` on a miss and `NoAdmissibleEngine` when every gate survivor failed admission, which is how a rejected global winner falls back to its size bucket.
