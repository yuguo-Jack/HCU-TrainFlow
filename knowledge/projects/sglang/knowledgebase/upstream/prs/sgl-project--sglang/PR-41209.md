# [MLX] Cap the MLX buffer cache by default

[Upstream PR](https://github.com/sgl-project/sglang/pull/41209) · state: open · merged: False

## Original PR description

## Motivation

Related to #21443. MLX's default cache limit equals its memory limit (15.2 GB of 16 GB on an M2) and the runner pins allocations with `set_wired_limit`, so the buffer cache grows until the host swaps. `SGLANG_MLX_CACHE_LIMIT_GB` exists but is opt-in and undocumented.

## Modifications

- When `SGLANG_MLX_CACHE_LIMIT_GB` is unset, cap at `max(1 GiB, 10% of max_recommended_working_set_size)`. Explicit values still win; `0` disables the cache. Resolution moved to `_apply_cache_limit()`.
- Document the variable in `apple_metal.mdx` and `environ.py`.
- `test_mlx_cache_limit.py`: default formula and env resolution, with `mx.set_cache_limit` / `mx.device_info` patched (`stage-a-unit-test-mlx`).

The 10% / 1 GiB constants are a heuristic; a measured cap like vllm-metal's `profile_run` can follow if preferred.

## Accuracy Tests

No change to outputs. Unit tests pass.

## Speed Tests and Profiling

M2 16 GB, `main` @ 6103a8c, `Qwen2.5-0.5B-Instruct`, 30 s Poisson load at 1.5 req/s (256-token prompts, 64 output tokens), system wired memory sampled at 4 Hz, two interleaved repeats:

| condition | wired idle → peak (GB) | available min (GB) | TTFT p50/p90 (ms) | TPOT p50 (ms) |
|---|---|---:|---|---:|
| uncapped | 4.36 → 8.89 / 4.39 → 8.81 | 1.35 / 1.37 | 180/265 / 180/254 | 34.3 / 34.3 |
| `SGLANG_MLX_CACHE_LIMIT_GB=1` | 4.37 → 6.39 / 4.33 → 6.42 | 3.59 / 3.54 | 181/256 / 179/253 | 34.5 / 34.5 |
| this PR, no env var | 4.33 → 6.46 | 3.37 | 181/270 | 34.1 |

`Qwen2.5-1.5B-Instruct`, same load: uncapped 6.49 → 13.82 GB (available min 0.34), default cap 6.53 → 12.46 GB (0.62); TTFT p90 1270 → 1192 ms. The cap bounds the recycled cache, not the live working set, so the 1.5B stays memory-bound on 16 GB either way.
