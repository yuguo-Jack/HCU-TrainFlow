# [Fix] [AMD] moe/topk: Preserve fp32 bias across aiter routing paths

[Upstream PR](https://github.com/sgl-project/sglang/pull/44797) · state: closed · merged: True

## Original PR description

## Motivation

Fixes #44794. `select_experts` rounded an fp32 correction bias to bf16 before the AITER grouped router could select its existing fp32 path. This loses bias distinctions and can change the selected experts.

## Changes

Preserve fp32 correction biases in `select_experts`. In the AITER branch, choose one logits/bias dtype pair before dispatching to either radix4 or AITER: an fp32 bias keeps fp32 routing, while other biases keep the existing logits-dtype conversion. Both dispatches now receive the same precision across the radix4 1024-token cutoff, and the fp32 path avoids an unused bias downcast.

Consolidate the CPU regressions into the existing correction-bias cache test file. They exercise `select_experts` through the actual grouped-router dispatch, mocking only native calls. Add eight native integration cases to the existing AMD radix4 test file; their offset fp32 bias has unique winners that collapse under bf16 rounding.

## Affected configurations

This changes AITER routing when the gate supplies an fp32 correction bias alongside lower-precision logits: `GlmMoeDsaForCausalLM`, Kimi-K3, DeepSeek-family configurations that retain an fp32 bias, and `ExaoneMoeForCausalLM`. Non-fp32 bias conversion, the JIT router, dynamic-bias handling, and non-AITER paths retain their existing behavior.

The fix preserves the supplied bias precision. It does not recover precision already lost when producing bf16 gate logits; router-GEMM precision is tracked separately in #34857.

## Validation

The results below were executed at `d7a09baf8b3f` against base `3927a73a3407`, before rebasing onto `main` at `7e142dd9fdc4`. Tests were not rerun for this merge.

- CPU: all five correction-bias cache/dispatch tests and all five GLM gate-bias tests passed. The fp32 dispatch regressions fail on unpatched main.
- One AMD Instinct MI355X: all 55 tests in `test_moe_route_radix4.py` passed, including GLM-5.3 and DeepSeek-V3 routing shapes, K3 batches of 1024/1025 tokens, and radix4 enabled/disabled. All eight new integration cases fail on unpatched main `3927a73a3407`.
- Native environment: Torch `2.9.0a0+git7bcbafe`, HIP `7.0.51831-a3e329ad8`, AITER `285579b6211b0da30f35b91a890c29c823597cd1`, Triton `3.6.0`, FlyDSL `0.4.0`.
- Pre-commit checks passed for all changed files.

Full-model GSM8K and decode-throughput comparisons for GLM-5.3, Kimi-K3 (radix4 on/off), and an fp32-bias DeepSeek-V3 configuration have not been run. The native results above cover router kernels and dispatch, not model accuracy or serving throughput.
