# [Fix] [NPU] eagle3: 修复 MLA 草稿的张量并行特征汇聚

[Upstream PR](https://github.com/sgl-project/sglang/pull/43957) · state: open · merged: False

## Original PR description

## Motivation

MLA EAGLE3 草稿的 FC 投影无条件初始化 CUDA 对称内存通信器，导致 Ascend 构造进入 CUDA 专用路径。本 PR 修复设备分支，使 NPU 张量并行恢复完整的 FC 输出。

关联任务：[Ascend/sglang#1094](https://github.com/Ascend/sglang/issues/1094)。本 PR 覆盖 FC 汇聚修复与回归测试。完整 Kimi 联合精度验收仍待完成。

## Modifications

- `python/sglang/srt/models/kimi_k25_eagle3.py`：非 CUDA、TP>1 使用 `ColumnParallelLinear(gather_output=True)`，Ascend 通过原生 HCCL 通信器汇聚；TP=1 跳过汇聚；CUDA、TP>1 按需导入并保留 `MultimemAllGatherer`。
- `test/registered/unit/models/test_kimi_eagle3_mla.py`：CPU 契约回归，覆盖辅助特征归一化、权重融合、输出和词表映射。
- `test/registered/e2e/models/test_kimi_eagle3_mla_npu.py`：NPU 注册回归，覆盖权重分片与 FC 投影，以及小型模型的接受、拒绝、缓存推进和图执行。

已合并上游 `main` 的 `d3a157a2f21f120ed727911da2f79ef5ae7a0a5a`，保留上游新增的 `DraftParallelSpec` 配置。相对该基线仍只修改上述三个文件。

## Accuracy Tests

**本次合并后验证：**1×Ascend 910B3（64GiB），CANN 9.1.0，Torch 2.10.0，TorchNPU 2.10.0.post6。

- CPU：5/5 通过。
- NPU TP=1：权重加载与 FC 投影通过；覆盖 0、1、5、17、129 个 token，BF16 容差 `rtol=0.01, atol=0.01`。
- NPU TP=1：dummy 主模型与草稿联合生成的 12 个 token 与主模型基线一致。
- NPU TP=1：固定小型权重的接受与拒绝回归通过，普通执行与图执行均覆盖 batch=1/2 和跨128-token缓存页；每个请求的24个生成 token 与主模型基线一致。
- 三个 PR 文件的全部适用 pre-commit 检查、测试注册检查和相对上游的 `git diff --check` 通过。

**此前已发布提交 `229174d7` 的验证：**4×Ascend 910B4（A2），每卡32GiB，CANN 9.1.0；CPU 5项、NPU 3项通过。覆盖 TP=1/2/4 的权重与 FC 投影，以及 TP=1/4 的联合生成、接受与拒绝、缓存推进和图执行。本次单卡环境没有重跑多卡用例。

完整注册回归的复现命令（NPU 用例需要四卡环境）：

```bash
python test/registered/unit/models/test_kimi_eagle3_mla.py -v
python test/registered/e2e/models/test_kimi_eagle3_mla_npu.py -v
```

注册回归使用测试生成的小型权重，无需下载预训练主模型。本轮单卡验证调用上述 NPU 文件中的测试函数，并仅运行 TP=1 配置。

## Limitations / Notes

- 此前真实 `lightseekorg/kimi-k2.6-eagle3.1-mla` 草稿已完成单卡、四卡独立运行；主模型辅助特征使用合成输入。BF16 跨 TP 隐藏状态比较仍有超限记录，不声明跨 TP 数值完全一致。
- 匹配 Kimi 主模型的正式评测、官方基线偏差≤1%、实际接受率和量化兼容性尚待验证。
