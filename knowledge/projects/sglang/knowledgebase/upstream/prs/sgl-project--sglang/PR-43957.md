# [NPU] 修复 MLA EAGLE3 的张量并行特征汇聚

[Upstream PR](https://github.com/sgl-project/sglang/pull/43957) · state: open · merged: False

## Original PR description

## Motivation

MLA EAGLE3 草稿的 FC 投影无条件初始化 CUDA 对称内存通信器，导致 Ascend 构造进入 CUDA 专用路径。
本 PR 修复设备分支，使 NPU 张量并行恢复完整的 FC 输出。

关联任务：[Ascend/sglang#1094](https://github.com/Ascend/sglang/issues/1094)。本 PR 覆盖 FC 汇聚修复与回归测试。完整 Kimi 联合精度验收仍待完成。

## Modifications

- 非 CUDA、TP>1：使用 `ColumnParallelLinear(gather_output=True)`。Ascend 通过原生 HCCL 通信器汇聚。
- TP=1：跳过汇聚。CUDA、TP>1：按需导入并保留 `MultimemAllGatherer`。
- 添加 CPU 契约测试和 NPU 注册回归。覆盖权重融合与分片、辅助特征归一化、接受与拒绝、缓存推进和图执行。

## Accuracy Tests

环境：4×Ascend 910B4（A2），每卡32GiB，CANN 9.1.0。

- CPU：5项通过。
- NPU：3项通过。TP=1/2/4 核对全部20个合成权重张量，并将 FC 输出与完整线性投影对照。
- 小型主模型与草稿联合回归：TP=1/4，普通执行与图执行均覆盖接受、拒绝和跨128-token缓存页。生成 token 与主模型基线一致。
- 格式与静态检查：全部适用的 pre-commit hook 通过；`git diff --check` 通过。

复现命令（已配置 SGLang、TorchNPU 和 CANN 的环境）：

```bash
python test/registered/unit/models/test_kimi_eagle3_mla.py -v
python test/registered/e2e/models/test_kimi_eagle3_mla_npu.py -v
```

以上注册回归使用测试生成的小型权重，无需下载预训练主模型。
此前真实 `lightseekorg/kimi-k2.6-eagle3.1-mla` 草稿已完成单卡、四卡独立运行；主模型辅助特征使用合成输入。
真实草稿的 BF16 跨 TP 隐藏状态比较仍有超限记录，因此不声明跨 TP 数值完全一致。

匹配 Kimi 主模型的正式评测、官方基线偏差≤1%、实际接受率和量化兼容性尚待验证。
A3 和 CUDA 多卡也尚待真机验证。正式模型支持列表留待联合验收后更新。
