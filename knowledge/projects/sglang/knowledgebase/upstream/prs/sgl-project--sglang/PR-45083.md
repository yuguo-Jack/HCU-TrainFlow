# [Fix] [NVIDIA] deepseek-v4.1: Fix prefill CP (interleave) crashes on SM90/SM100/SM120

## Original PR description

# [Fix] [NVIDIA] deepseek-v4.1: Fix prefill CP (interleave) crashes on SM90/SM100/SM120

## Motivation

Prefill context parallelism (`--enable-prefill-cp --cp-strategy interleave`) for DeepSeek V4.1 fails to start or crashes on SM90, SM100 and SM120. This PR fixes those runtime bugs and adds no performance changes.

| # | Error | Trigger |
|---|---|---|
| 1 | `Interleave CP gather received an unexpected local token count` on the first prefill | CP + `--enable-decoder-swa-bounded-replay` + DSPARK |
| 2 | `shape '[192, 4096]' is invalid ...` during decode CUDA graph capture | SM90 + `--enable-cp-decode-attn-tp` + dense FP8 not on DeepGEMM (e.g. `--fp8-gemm-backend triton`) |
| 3 | `b_descale shape mismatch for swizzled layout` at startup | Blackwell (FlashInfer MXFP8 dense GEMM) + `--enable-cp-decode-attn-tp` |
| 4 | `the torch indexer needs the batch's rows` on prefill | SM90 (torch prefill indexer) + CP |

## Modifications

- `models/deepseek_v4.py` (bug 1): under CP with DSPARK, scatter the bounded-replay tail rows (hidden states, `pre_hc_head`, DSpark aux) back into the rank's extend rows before `cp_gather_after_forward`. Rows outside the tail are zero-filled.
- `layers/cp/cp_decode_attn_tp.py`:
  - Bug 2: also slice the Hopper BF16 weight cache `_block_fp8_bf16_weight`.
  - Bug 3: slice `weight_scale_inv_swizzled` along whole 128x4 SF tiles.
  - Linears without these attributes are sliced as before, so other models' CP decode attention TP is unchanged.
- `layers/attention/deepseek_v4_backend.py` (bug 4): pass the rank-local `req_rows` (`repeat_interleave(req_pool_indices, q_lens_cpu)`) to the indexer instead of `None`.
- `dsv4/v41_indexer/types.py`: comment update only.
- New unit tests: `test/registered/unit/cp/test_cp_decode_attn_tp_unit.py` and `test_dsv4_prefill_cp_rows_unit.py`.
