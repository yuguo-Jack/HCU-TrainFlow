# [Fix] metrics: Handle missing decode seq_lens_cpu in FPM

[Upstream PR](https://github.com/sgl-project/sglang/pull/39537) · state: open · merged: False

## Original PR description

## Motivation

Fixes #31309.

Forward Pass Metrics (FPM) can crash the scheduler when a merged decode batch has `seq_lens_cpu=None`. `ScheduleBatch.merge_batch()` may legitimately drop this optional CPU mirror, but FPM iterated it unconditionally and raised `TypeError`.

Follow-up to #31319, which identified the original fix direction. This PR implements that fix on current main.

## Modifications

- Preserve the existing decode metric path when `seq_lens_cpu` is available.
- Fall back to per-request `req.seqlen` when the CPU mirror is absent, matching  the existing `_decode_total_seq_lens()` and mixed-batch metrics semantics.

This is a metrics-only safety fix. It does not copy GPU tensors to CPU, add a device synchronization, or change request scheduling behavior. The final diff changes only `metrics_reporter.py`; existing test files are unchanged.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Snapshot decode lengths before processing results**

When `seq_lens_cpu` is absent and the decode produces tokens, this fallback does not preserve the normal metric semantics: `Scheduler.process_batch_result()` invokes `process_batch_result_decode()` first, which extends each request's `output_ids`, and only afterward emits FPM. Consequently `req.seqlen` is the post-result length, whereas the `seq_lens_cpu` branch reports the sequence length used by that forward pass. This inflates `sum_decode_kv_tokens` by every accepted token (potentially several per request under speculative decoding) and makes the telemetry backend-dependent; snapshot the request lengths before result processing or derive the pre-result lengths from the result.

Accurate observation, but intentional. This fallback matches the existing post-result `req.seqlen` semantics of the `is_mixed()` branch above and `_decode_total_seq_lens()`; the drift is bounded by one accepted step per request, and this path was a scheduler crash before this change.
