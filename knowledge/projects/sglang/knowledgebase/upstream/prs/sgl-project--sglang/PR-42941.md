# [diffusion] model: support Wan-Animate-2

[Upstream PR](https://github.com/sgl-project/sglang/pull/42941) · state: closed · merged: True

## Original PR description

## Motivation

Add native support for [Wan-Animate-2](https://huggingface.co/Wan-AI/Wan2.2-Animate-2-14B-Diffusers) (`Wan-AI/Wan2.2-Animate-2-14B-Diffusers`), the 14B character-animation model of the Wan2.2 family. It takes a **reference image** and a **reference video** and produces a clip of the reference subject performing the reference video's motion.

Wan-Animate-2 is an in-context video model: the reference video is encoded once per clip into a K/V cache by a separate reference pass, each clip is denoised against that cache with the previous clip's last frame as conditioning, and the clips are assembled into one video. Diffusers serves it as a modular pipeline; this PR implements the model natively (`WanAnimate2Pipeline`, selected automatically from the checkpoint's `model_index.json`) and loads the same checkpoint. There is no diffusers fallback.

## Modifications

### New
- `runtime/models/dits/wan_animate_2.py`, `wan_animate_2_block.py`, `wan_animate_2_clip_conditioning.py`: the in-context DiT on top of `WanTransformer3DModel`. The block runs the padded `[generation | reference-video]` layout through `torch.compile`d `flex_attention` with a per-geometry `BlockMask`; the reference K/V is computed once per clip (keys cached after RoPE) and owned by the request, the text/image context projection is computed once per clip and CFG branch, and the geometry caches hold at most four RoPE tables and two block masks.
- `runtime/pipelines/wan_animate_2_pipeline.py` and `runtime/pipelines_core/stages/model_specific_stages/wan_animate_2/` (`preprocess`, `before_denoising`, `denoising`, `encoder_adapters`, `audio`): reference-video decoding (a local path, or an HTTP(S) / `data:` URL fetched through the shared media loader) and letterboxing, the three text prompts (tokenization and truncation to the DiT `text_len` live in the pipeline config), CLIP and VAE conditioning, the clip schedule, the per-clip denoise-and-decode loop, and the output stage.
- `configs/models/dits/wan_animate_2.py`, `configs/pipeline_configs/wan.py` (`Wan_Animate_2_14B_Config`), `configs/sample/wan.py` (`Wan_Animate_2_14B_SamplingParam`): architecture config read from the checkpoint's `transformer/config.json` (including `text_len`, which sizes the padded prompt embedding), pipeline config with the prompt tokenization hooks and the startup validations listed below, and the model-specific sampling fields.
- Cookbook page [`docs/cookbook/diffusion/Wan/Wan-Animate-2.mdx`](https://github.com/ankitdhall/sglang/blob/diffusion/wan-animate-2/docs/cookbook/diffusion/Wan/Wan-Animate-2.mdx) (serving presets, parameter reference, benchmark table), catalog entry, `docs.json`, and a note in the OpenAI API reference on the Wan-Animate-2 `size`, `seconds` and `enable_audio` semantics.
- Unit tests `test/unit/test_wan_animate_2_config.py` and `test_wan_animate_2_parallelism.py`; two GPU CI cases (`wan2_2_animate_2_14b_ref2v`, 1 GPU, and `wan2_2_animate_2_14b_ref2v_cfg_parallel_2gpu`) with consistency thresholds and H100 perf scenarios (the cases run on the H100 CI lanes).

### Shared code touched
- `DPMSolverMultistepScheduler.set_timesteps` accepts an explicit sigma grid (the official Wan sigma schedule is passed explicitly).
- `TransformerLoader` gains a `strict_checkpoint_keys` hook; this pipeline turns it on so a checkpoint tensor that maps to no parameter fails the load (the full 1303-key mapping is pinned by a unit test).
- `WanTransformer3DModel` builds its blocks through a `_make_block` factory, which the Wan-Animate-2 DiT overrides instead of rebuilding the block list.
- `WanTransformerBlock` exposes its QKV projection and cross-attention/FFN tail as `_qkv` / `_cross_and_ffn`, and `WanTransformer3DModel` its output head as `_unpatchify` (method identity is pinned by a unit test).
- `DenoisingStage` factors its step loop into `_run_denoising_loop` (with a `progress_step_interval` extra); `DecodingStage.decode` is split into `decode_raw` (raw `[-1, 1]` pixels) plus the `[0, 1]` normalisation. Other pipelines keep their behaviour.
- The auto-residency probe fit (`gpu_worker.py`) stops when lightening a probe does not shrink it, with a regression test in `test_warmup_probe_degradation.py`: a model whose sampling params pin the frame count otherwise makes the fit loop forever on cards where the full-shape probe does not fit.

### Supported features
- Server warmup (`--warmup-mode server`, and therefore `--enable-torch-compile`) with a synthetic reference image and a synthetic reference video at the default clip length, written through the shared video writer.
- CFG parallelism: the conditional and unconditional branches run on separate ranks (all-gathered in branch order) and are combined with the serial `uncond + g * (cond - uncond)` arithmetic, without the shared CFG post-process; enabled automatically on 2 GPUs (the framework default, which this model keeps), forced with `--enable-cfg-parallel`, disabled with `--cfg-parallel-size 1`. With `--encoder-parallel replicate --vae-config.use-parallel-decode false` and `SGLANG_DIFFUSION_VAE_CHANNELS_LAST_3D=1` the 2-GPU output is bit-identical to the 1-GPU output.
- Ulysses sequence parallelism: `--ulysses-degree N` splits attention heads across ranks with a per-block all-to-all around the compiled flex attention. `N` must divide the 40 heads.
- Tensor parallelism: `--tp-size N` uses the inherited column/row-parallel layers (40 attention heads split). Recommended when the GPU has less VRAM: about 30 GiB torch peak per GPU at `--tp-size 2` (37 GiB nvidia-smi) versus 66 GiB (70 GiB) on 1 GPU. Combinable with Ulysses (`--tp-size 2 --ulysses-degree 2` on 4 GPUs; both degrees must divide the 40 heads, Ulysses the TP-local count).
- Text-encoder CPU offload: `--text-encoder-cpu-offload` keeps the fp32 UMT5 encoder on the host and moves it in for each request's text encoding. Recommended when the GPU has less VRAM.
- Precision: the DiT runs in bf16, the UMT5 text encoder and the CLIP image encoder in fp32; the Wan VAE encodes and decodes in fp32 with autocast off (the stage-local adapter and the clip decode pin the dtype; the configured VAE decode precision is not consulted).
- DiT layerwise offload: `--dit-layerwise-offload --layerwise-offload-components transformer` streams the 40 blocks from pinned host memory with async prefetch. 1-GPU torch peak drops from 66 GiB to 37 GiB at the same end-to-end time (996 s vs 993 s in the table below).
- Per-request audio: the reference video's audio track is read with the shared audio reader and carried on `OutputBatch.audio` by default, as in the official pipeline; the shared MP4 writer encodes it next to the video, as for LTX-2 and MOVA. `enable_audio=false` on a request gives a silent output. A reference video without an audio track, or one the reader cannot decode, yields a silent output with one log line per process.

### Notes on model-specific parameters
- `clip_len`: the video is denoised in chunks and this is the chunk length. Must be of the form 4k+1 (VAE temporal stride 4); other values are rounded to 4k+1 with the same k and the rounding is logged (40 becomes 41, 38 and 39 become 37); values below 5 are rejected. Default: 37.
- `fps`: the reference video is resampled to this rate and the output MP4 is written at this rate; duration is preserved. Default: 16.
- `prompt_ref`: text for the reference-video branch; defaults to the official demo phrase "人物动作的参考视频". Recommended to leave unchanged.
- `width x height` (the API's `size`): a pixel-area budget, not the output dimensions. The frame keeps the reference image's aspect ratio, rounded to multiples of 16; the letterbox bars are cropped from the output. With the default 640x800 a 9:16 reference gives a 528x944 canvas, a 1:1 reference 704x704.
- `num_frames` and the API's `seconds` are not length controls: the output has as many frames as the (resampled) reference video. A supplied value is ignored and the server logs that it was.
- `video_path` (or `video_url`): the reference video, a path or URL the server can read, passed as a form field or in `extra_body`; the reference image rides `input_reference`.

### Rejected at startup or request admission
- `--ring-degree` greater than 1, `--use-fsdp-inference`, and TP or Ulysses degrees that do not divide the 40 attention heads (Ulysses divides the TP-local count).
- An explicit `--attention-backend` (or `--component-attention-backends transformer=...`): the in-context self-attention runs on `flex_attention` only. The text encoder still accepts its own backend.
- `SGLANG_DIFFUSION_ENABLE_MXFP8_ATTENTION`: this model does not apply the offline Q/K rotation.
- `enable_teacache` / `enable_spectrum` request fields: every block runs at every step.
- A checkpoint `transformer/config.json` with `use_img_emb=false`: the model always builds the image-embedding cross-attention, so such a checkpoint is a different model.
- Any disaggregated `--disagg-role`: the per-request state crosses stages as GPU tensors and a `torch.Generator`, which the disaggregation transport cannot carry.

### Native reuse and model-specific boundaries
- Text encoding uses `TextEncodingStage`; each clip uses the shared `DenoisingStage` loop, CFG utilities, profiling and component-release hooks.
- QKV projections, cross-attention, FFN and output reconstruction are inherited from Wan. Ulysses uses the shared packed-QKV exchange and inverse exchange.
- Clip decoding uses `DecodingStage.decode_raw`, including tiling, compile-cache management and OOM diagnostics, without converting overlap conditioning to and from [0, 1]. Thin CLIP/VAE adapters preserve the existing preprocessing and latent-scaling arithmetic; native modules remain exposed to component and layerwise-offload management.
- The sequential clip schedule, reference K/V pass, in-context FlexAttention mask, branch-specific block skip and overlap-frame conditioning remain model-specific. The checkpoint scheduler uses the official explicit sigma grid per clip. Cache-dit, breakable CUDA graphs, LoRA and disaggregated serving remain unsupported; this refactor does not enable them.

Speedups: 4 GPUs are 3.5x over 1 GPU (283 s vs 993 s) and 3.5x over diffusers, which has no multi-GPU path for this model; 2 GPUs are 1.9x with CFG-parallel and 1.8x with Ulysses, 1.6x with TP2. Among 4-GPU layouts the framework default and the explicit CFG2 x Ulysses2 exchange run at the same speed (283 s); CFG2 x TP2 and Ulysses4 are both about 12 percent slower at 18 and 8 GB less torch peak; TP4 is 34 percent slower for the lowest footprint (22 GB torch, 27 GB nvidia-smi). TP2 x Ulysses2 is the memory-leaning layout after TP4 (25 GB torch, 33 GB nvidia-smi), about 13 percent slower than CFG2 x TP2 and 27 percent slower than the default.

CI perf scenarios (8 steps, one 29-frame clip, 576x1024, layerwise DiT, warmup active) on the H100 80 GB lanes: 98.4 s end-to-end on 1 GPU and 64.0 s on 2 GPUs CFG-parallel, average denoising step 10.8 s and 6.4 s, peak 35.5 GiB (36,322 MiB) on both. Both cases run with the per-step and VRAM perf validation enabled (`run_perf_check=True`).

### Recommended parallelism config

It is recommended to use `--text-encoder-cpu-offload`.

**1 GPU**
- 96 GB or more: defaults (DiT resident, 66 GiB torch peak, 70 GiB nvidia-smi).
- 80 GB: add `--dit-layerwise-offload --layerwise-offload-components transformer` (37 GiB torch peak, 40 GiB nvidia-smi, same end-to-end time).

**2 GPUs**
- `--enable-cfg-parallel --encoder-parallel replicate --vae-config.use-parallel-decode false` with `SGLANG_DIFFUSION_VAE_CHANNELS_LAST_3D=1`: the 2-GPU recipe whose output is bit-identical to 1 GPU: 515 s, 59 GiB torch peak (71 GiB nvidia-smi) per GPU, the same speed as plain CFG-parallel (513 s).
- 80 GB or less per GPU: the same CFG-parallel recipe with `--dit-layerwise-offload --layerwise-offload-components transformer` (512 s, 30 GiB torch peak, 43 GiB nvidia-smi, still bit-identical), or `--tp-size 2` (613 s, 30 GiB torch peak, 37 GiB nvidia-smi).

**4 GPUs**
- `--enable-cfg-parallel --ulysses-degree 2`: 3.5x over 1 GPU (283 s), 48 GiB torch peak per GPU (58 GiB nvidia-smi). Ulysses shards the attention sequence, so no 4-GPU layout is bit-identical to a single GPU; they match the single-GPU video to about 30 dB mean PSNR, with or without `--encoder-parallel replicate --vae-config.use-parallel-decode false` (287 s, 53 GiB torch peak). The 4-GPU framework default (CFG2 x SP2 with the KV-gather exchange) runs at the same speed and produces the same output, but pass `--enable-cfg-parallel --ulysses-degree 2` explicitly: it pins the layout the 80 GB row was measured on.
- 80 GB or less per GPU: the same CFG-parallel x Ulysses recipe with `--dit-layerwise-offload --layerwise-offload-components transformer` (291 s, 22 GiB torch peak, 35 GiB nvidia-smi), or `--enable-cfg-parallel --tp-size 2` (318 s, 30 GiB torch peak, 37 GiB nvidia-smi).
- Memory-leaning: `--tp-size 2 --ulysses-degree 2` (361 s, 25 GiB torch peak, 33 GiB nvidia-smi), the lowest 4-GPU peak after `--tp-size 4`, about 13 percent slower than CFG2 x TP2 and 27 percent slower than CFG2 x Ulysses2; use the default for speed and this layout for memory.

The two extra flags `--encoder-parallel replicate --vae-config.use-parallel-decode false` keep the encoders whole on every rank and decode the VAE on one rank.

## Known limitations and follow-ups
- The distilled checkpoint (`Wan-AI/Wan2.2-Animate-2-14B-Distilled-Diffusers`, 10 steps, no CFG) is not supported in this PR (a follow-up PR adds it). The DiT reads `log_scale` from the checkpoint's `transformer/config.json`; the released base config has no such key and the attention score modifier is an exact identity at 0.
- Ring attention is not implemented: the in-context block mask needs the full K/V on one rank.
- Quantization, TeaCache / cache-dit and LoRA are not supported: the MXFP8 attention path and the `enable_teacache` / `enable_spectrum` request fields are rejected as listed above, and no LoRA or other quantized path is wired for this pipeline. Disaggregated serving is rejected.


### Resolved known limitations
- [x] `--tp-size` combined with `--ulysses-degree` was rejected because of an upstream Wan VAE encoder issue; the fix landed in #41917, so the rejection is lifted and the TP2 x Ulysses2 layout is benchmarked in the table above and in the cookbook.
- [x] The two CI cases read their inputs and ground-truth frames from sgl-project/ci-data-diffusion at the `main` commit pinned by `SGL_TEST_FILES_CI_DATA_REVISION`; the H100 frames are the ones the CI run generated and the maintainer committed from it.
