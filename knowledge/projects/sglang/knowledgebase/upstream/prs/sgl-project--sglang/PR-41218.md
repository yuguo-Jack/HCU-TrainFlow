# [Bugfix] Support LogitsProcessorOutput in the breakable CUDA graph output buffers

[Upstream PR](https://github.com/sgl-project/sglang/pull/41218) · state: open · merged: False

## Original PR description

`--cuda-graph-backend-decode breakable` aborts at decode-graph capture for any model whose decode forward returns a `LogitsProcessorOutput`. GLM-5.3-Flash on the DSA path is one:

```
File ".../runner_backend/breakable_cuda_graph_backend.py", line 197, in _alloc_full_buffer
    raise TypeError(f"Unsupported BCG output type: {type(output)}")
TypeError: Unsupported BCG output type: <class 'sglang.srt.layers.logits_processor.LogitsProcessorOutput'>
```

The three structure-walkers that manage the shared output buffer (`_alloc_full_buffer`, `_slice_output`, `_copy_output_to_buffer`) only handle tensors, `PPProxyTensors`, tuples and lists, so the `LogitsProcessorOutput` dataclass the decode path returns falls through to the `raise`. `full` and `tc_piecewise` reach a serving state on the same command, only `breakable` trips here.

The fix walks the dataclass tensor fields (`next_token_logits`, `hidden_states`, and any other tensor field) and leaves the rest untouched through `dataclasses.replace`. Thats the same set of fields the full decode runner slices in `_process_output_after_replay`; the non-tensor fields are filled later by the sampler, so preserving them is correct.

Validated on GLM-5.3-Flash (DSA, tilelang backends, TP4): with `--cuda-graph-backend-decode breakable` capture now succeeds, decode runs through the graph, and GSM8K matches the non-breakable baseline (24/25 either way). The change is additive (new branches before the existing raise) and device-agnostic, so the default full path and the CUDA path are unchanged.
