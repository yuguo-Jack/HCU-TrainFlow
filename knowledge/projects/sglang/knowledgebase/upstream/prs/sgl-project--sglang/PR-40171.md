# [Fix] diffusion/lora: revalidate FLUX.2 FP8/NVFP4 fast paths after LoRA attach

[Upstream PR](https://github.com/sgl-project/sglang/pull/40171) · state: closed · merged: True

## Original PR description

Fix a crash when attaching a LoRA adapter at runtime to a FLUX.2 (multimodal_gen) model loaded from an FP8-quantized checkpoint (ModelOpt FP8).

## Motivation

`Flux2ParallelSelfAttention.__init__` decides the fused fast-path flags
`_enable_fp8_token_cat` / `_enable_nvfp4_token_cat` by inspecting
`self.to_out.quant_method` on the raw quantized `RowParallelLinear`. When a
LoRA adapter is attached, the LoRA pipeline replaces those quantized linears
with wrapper modules that do not expose `quant_method` / `input_scale`. The
init-time flags then go stale, and `forward()` reads those attributes off the
wrapper, crashing instead of falling back to the unfused path.

Reproduced on an L20 GPU (SM89) with the official FLUX.2-klein-9b-fp8
checkpoint and a runtime-attached LoRA adapter (locally trained, cannot be
shared): the model crashes on the first forward pass after the adapter is
mounted.

Related: #35970 (diffusion LoRA + FP8 crash on static merge) — the merge-policy
half is handled by the `can_merge_base_weight` dynamic fallback; this PR fixes
the stale fast-path flags on the dynamic path.

## Modifications

- Add `Flux2Transformer2DModel.revalidate_fp8_fast_paths()` which also re-runs

No behavior change when no LoRA is attached — the revalidation hook only runs

## Accuracy Tests

End-to-end A/B on a single L20 GPU (SM89) with the official
FLUX.2-klein-9b-fp8 checkpoint and a runtime-attached LoRA adapter (locally
trained, cannot be shared), built on this PR branch (latest main):

- Without the patch: non-LoRA generation succeeds; after `POST /v1/set_lora`
  (merge_mode=dynamic), the first LoRA generation fails immediately with
  `AttributeError: 'ColumnParallelLinearWithLoRA' object has no attribute
  'input_scale'` inside `Flux2Transformer2DModel.forward`.
- With the patch: the same request completes normally and produces valid
  1024x1024 output; no errors in the server log.
- Non-LoRA inference is untouched: same prompt/seed before and after the
  patch yields bit-identical output images.
- ruff / ruff-format / isort pass per pre-commit rules.
