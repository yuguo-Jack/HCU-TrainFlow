# [Fix] trinity: Keep think tags inside tool-call arguments

[Upstream PR](https://github.com/sgl-project/sglang/pull/44240) · state: open · merged: False

## Original PR description

## Motivation

Fixes #42140. `TrinityDetector` stripped every `<think>` / `</think>` from the raw output before parsing, so tool arguments containing those strings were silently altered — `"Qwen emits <think> and </think> tags"` came back as `"Qwen emits  and  tags"`. In streaming the same happens whenever a tag arrives as its own delta inside the arguments.

## Modifications

- `trinity_detector.py`: parse the original text and strip think tags only from the returned `normal_text`, in both `detect_and_parse` and `parse_streaming_increment` (same post-processing pattern as `HermesDetector`). Tool-call JSON is left untouched; normal-text output is unchanged.
- Dropped the `has_tool_call` override so detection and parsing see the same text.
- New `test/registered/unit/function_call/test_trinity_detector.py` (CPU, `base-a-test-cpu`): tags inside arguments preserved, tags outside the call stripped, a tool call inside a think section, no-tool-call text, and streaming with tags arriving as whole tokens inside and outside the call.

Tags split across stream chunks (#30990) are out of scope and behave as before.

## Accuracy Tests

Parser-only change; no model outputs affected. The new tests fail on main with the issue's exact symptom and pass with this change; `TestQwen25Detector` still passes.

    python3 test/registered/unit/function_call/test_trinity_detector.py
