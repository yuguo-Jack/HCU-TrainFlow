# [Fix] [XPU] spec: Start NEXTN/MTP drafts on XPU and stop silent greedy verify

[Upstream PR](https://github.com/sgl-project/sglang/pull/46740) · state: open · merged: False

## Original PR description

## Motivation

On Intel XPU, EAGLE-family speculative decoding (EAGLE / EAGLE3 / NEXTN, i.e. MTP) has two problems:

- **Most NextN/MTP drafts crash at startup.** `set_embed_and_head` / `set_embed` call `torch.cuda.synchronize()`, which raises `Torch not compiled with CUDA enabled` on torch+xpu. Affected: DeepSeek-V3/R1, GLM-4.x/5, Qwen3-Next, MiMo-V2, Nemotron-H, LongCat, Kimi-K2.5 EAGLE3 and others.
- **Sampling is silently dropped.** XPU verify is always greedy, with no warning, and `--speculative-use-rejection-sampling` is accepted but does nothing.

## Modifications

- **models:** use `current_platform.empty_cache()` / `synchronize()` in `set_embed_and_head` / `set_embed`. This is mechanical: 75 sites in 33 files. CUDA/ROCm/MUSA behaviour is unchanged.
- **`eagle_utils.py`:** warn once when EAGLE-path verify falls back to greedy on a sampled batch (XPU, CPU, and ROCm without rejection sampling), as DFLASH already does. It uses the same branch as #42828.
- **`speculative_hook.py`:** reject `--speculative-use-rejection-sampling` on XPU for every algorithm, next to the block-verification device check.
- **docs:**
  - mark XPU spec topk=1 as supported in the attention-backend matrix;
  - add an XPU spec section with its limits to `xpu.mdx`;
  - note the XPU limit in the block-verification paragraph of `speculative_decoding.mdx`.
- **tests (CPU CI):**
  - XPU rejection-sampling cases (EAGLE, NGRAM) in `test_block_verification_args.py`;
  - `test_set_embed_device_neutral.py` scans `models/` for direct `torch.cuda.*()` calls in `set_embed*`;
  - `test_spec_registry.py`: add `speculative_use_rejection_sampling` to the hand-built args stub, which the hook now reads.

## Accuracy Tests

Arc Pro B60, `main` vs this PR:

| Scenario | `main` | This PR |
|---|---|---|
| NEXTN, `glm-moe-dsa-tiny-random` | crash at draft init | draft initializes, server starts |
| EAGLE Llama-2-7B, `intel_xpu`, 5/1/6, greedy + `temperature=0.7` requests | accept length 1.78 | identical output and accept length; warning logged once |

Unit tests: `test/registered/unit/spec` + `unit/server_args` give 753 passed with this PR vs 752 on `main` (+1 test, +2 subtests), with identical pre-existing failures.

DSA models (V3.2 / GLM-5) still hit a separate CUDA-only assert in DSA verify (`pad.py`). That is a follow-up.
