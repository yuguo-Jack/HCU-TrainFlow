# [Fix] [AMD] diffusion: Import the block-scaled scaled_mm API lazily in mxfp8_online

[Upstream PR](https://github.com/sgl-project/sglang/pull/45853) · state: closed · merged: False

## Original PR description

## What

`python/sglang/multimodal_gen/runtime/layers/quantization/mxfp8_online.py` imports `ScalingType`, `SwizzleType` and `scaled_mm` from `torch.nn.functional` at module level. This change moves that import into `mxfp8_scaled_mm`, the only function that uses them. `srt/layers/quantization/fp8_utils.py` already reads `ScalingType` at call time in the same way.

## Why

Torch builds without the block-scaled `scaled_mm` API, such as the one in the ROCm 7.2 CI images, cannot import the module at all. `MXFP8Config.get_quant_method` imports it for every online-MXFP8 linear, so these layers never reach the per-channel fp8 fallback that `process_weights_after_loading` picks on pre-Blackwell GPUs. The three fallback tests in `python/sglang/multimodal_gen/test/unit/test_mxfp8_online_gemm.py` fail with `ImportError: cannot import name 'ScalingType' from 'torch.nn.functional'` on the rocm720 lane (rocm10 and rocm724 pass).

Failing job (rocm720, partition 0): https://github.com/sgl-project/sglang/actions/runs/39645674470/job/119380614726

The block-scaled MXFP8 path only runs on compute capability 10 or higher, and its behavior does not change.

## Test plan

- `python -m py_compile` on the changed file passes, and `black --check` is clean.
- No GPU run locally.
- Passed on MI300 (rocm720) in a dispatched `multimodal-gen-test-1-gpu-amd` run on this commit: https://github.com/sgl-project/sglang/actions/runs/39819280455/job/119966168563 (the three fallback tests in `test_mxfp8_online_gemm.py` passed; the Blackwell-only test skipped as expected). The same shard still fails on `test_qwen3_5_encoder.py` at length 17, which fails on main too and is unrelated.
