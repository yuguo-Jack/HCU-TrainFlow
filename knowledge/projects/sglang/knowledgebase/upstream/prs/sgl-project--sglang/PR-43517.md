# [Feat] [NPU] sampling: Add sampling-mask support for Ascend

[Upstream PR](https://github.com/sgl-project/sglang/pull/43517) · state: open · merged: False

## Original PR description

## Motivation

Requests with `return_sampling_mask=true` are currently rejected by the Ascend sampling backend. This prevents NPU RL callers from retrieving the sampling support and behavior logprobs through the existing API.

The Ascend sampler already computes the filtered probabilities used to draw the next token. This PR exports those weights and connects them to the shared sampling-mask output pipeline, so the reported support describes the distribution used for sampling.

## Modifications

- Add opt-in `return_filtered_probs` to `top_k_top_p_min_p_sampling_from_logits_ascend`. The fused path exports its post-top-k/top-p/min-p weights; the torch fallback scatters its filtered weights back into vocabulary order. Calls without the flag retain the tensor-only return contract.
- Pass the exported weights through `_SamplingMaskCapture` and the existing device packing and host materialization pipeline. Capture only opted-in batch rows and support both `support` and `selected` logprob modes. Support comes from positive exported weights, without replaying the filters or rewriting the sampled column.
- Remove the scheduler's Ascend-specific rejection while retaining the existing finite-top-k validation and support-cap/overflow handling. Fused cutoff ties can produce more than `top_k` candidates.
- Fix fused min-p threshold computation to use `max(dim=-1).values`.
- Add mocked fused/fallback unit coverage and an NPU HTTP test registered in `base-b-test-1-npu-a3` and `nightly-1-npu-a3`. Cover vocabulary ordering, partial-batch capture, opt-in behavior, min-p, cutoff ties, seeded mask-on/off draws, greedy sampling, restricted top-p, real fallback, and mixed output modes.
