# [Feat] [NPU] sampling: Add sampling-mask support for Ascend

[Upstream PR](https://github.com/sgl-project/sglang/pull/43517) · state: open · merged: False

## Original PR description

## Motivation

Requests with `return_sampling_mask=true` are currently rejected by the Ascend sampling backend. This prevents NPU RL callers from retrieving sampling support and behavior logprobs through the existing API.

This PR exports the Ascend sampler's actual post-filter weights through the shared sampling-mask response pipeline, supporting both `support` and `selected` logprob modes.

## Modifications

- Export actual post-filter weights from the fused Ascend top-k/top-p path and its torch fallback, without replaying filters or modifying the sampled token's weight. The Ascend helper consistently returns `(token_ids, filtered_probs)`, with `filtered_probs=None` when mask capture is disabled; callers unpack the same tuple in both cases.
- Capture only opted-in rows and reuse the shared packing and host-materialization pipeline. Remove the Ascend-specific request rejection while retaining finite-top-k validation and support overflow handling, including fused cutoff ties.
- Reuse the fallback softmax buffer with `probs.scatter_`. Exported weights retain the logits dtype; returned logprobs are computed in FP32. The vocabulary-ordered export and the packer's full-vocabulary `topk` remain.
- Separate tests by resource requirements and integration layer. CPU-only mock coverage runs in the CPU suite, real backend coverage uses one NPU, and model E2E uses only GLM-5.2 on two NPUs. Keep the independent CPU reference in the shared test package.

```text
python/sglang/test/ascend/
└── sampling_mask_reference.py

test/registered/
├── unit/sampling/
│   └── test_ascend_sampler.py
└── npu/
    ├── basic_function/backends/
    │   └── test_npu_sampling_mask_backend.py
    └── rl/sampling_mask/
        └── test_npu_sampling_mask.py
```

## Accuracy Tests

### Coverage

- **CPU/mock:** five focused methods covering dispatch, the consistent tuple return contract and opt-in weight capture, FP32/BF16 export dtype and fallback buffer reuse, seeded mask-on/off draw preservation with a fixed hash source, requested-row compaction, and disabled capture. These tests use CPU tensors and mocked Ascend operators; filtering numerics and scheduler materialization are checked by the real NPU backend suite.
- **Real NPU backend:** one test method with 24 parameter combinations covering FP32/FP16/BF16, fused top-k/top-p, fallback top-k/top-p/min-p, cutoff ties, mixed output modes, packing and materialization, with support sets and logprobs checked against an independent CPU reference.
- **GLM-5.2 E2E:** two methods using a six-layer BF16 model with dummy weights, TP=2, attention DP=2, DP LM head enabled, and full decode graphs. Cover greedy, unbiased top-k, exact top-k, top-p, top-k 1025 fallback, both logprob modes and mixed opt-in batches. All 10 single-request combinations and the mixed-batch method execute. Exact-filter cases compare token sets and logprobs with the reference; unbiased and mixed batches check output properties. The fixture starts and gracefully stops its own server.

### How to test

Run from the repository root. For NPU tests, source the installed CANN/ATB environment scripts first and select idle devices. Configure `GLOO_SOCKET_IFNAME`, `HCCL_SOCKET_IFNAME` and an available `HCCL_NPU_SOCKET_PORT_RANGE` for two-device E2E as required by the host.

```bash
export PYTHONPATH="$PWD/python${PYTHONPATH:+:$PYTHONPATH}"
export PYTORCH_NPU_ALLOC_CONF=expandable_segments:False
export NO_PROXY="127.0.0.1,localhost${NO_PROXY:+,$NO_PROXY}"

# Registration checks; no accelerator required.
python scripts/lint/check_registered_tests.py
python scripts/lint/check_no_registered_tests_in_package.py

# CPU tensors and mocked Ascend operators.
python -m pytest test/registered/unit/sampling/test_ascend_sampler.py -v

# One available NPU.
python -m pytest test/registered/npu/basic_function/backends/test_npu_sampling_mask_backend.py -v -s

# Two available NPUs and GLM-5.2 config/tokenizer metadata.
python -m pytest test/registered/npu/rl/sampling_mask/test_npu_sampling_mask.py -v -s
```

The model metadata must exist at `GLM_5_2_BF16_MODEL_PATH` in `sglang.test.ascend.test_ascend_utils`, currently `/root/.cache/modelscope/hub/models/ZhipuAI/GLM-5.2`. The fixture applies the six-layer override and `--dtype bfloat16 --load-format dummy`; pretrained weights are not loaded. A missing `config.json` skips the model tests, so confirm metadata is present before interpreting a successful command as E2E validation.

CPU tests register in `base-a-test-cpu`. Backend tests register in `base-b-test-1-npu-a3` / `nightly-1-npu-a3`; GLM E2E registers in `base-b-test-2-npu-a3` / `nightly-2-npu-a3`.
