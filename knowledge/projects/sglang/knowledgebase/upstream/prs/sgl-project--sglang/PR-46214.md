# [Fix] flashinfer: Apply the sliding window in ragged prefill for hybrid-SWA models

[Upstream PR](https://github.com/sgl-project/sglang/pull/46214) · state: open · merged: False

## Original PR description

## Motivation

On `--attention-backend flashinfer`, a hybrid sliding-window/full model's sliding layers attend past their window during ragged prefill.

FlashInfer selects the kernel module at plan time: `window_left >= 0` picks the variant with the sliding mask compiled in, and a `window_left` passed only to `forward` has no effect on a module planned without it. Main plans one ragged wrapper, shared by sliding and full layers, without the window. On SM100 there is a second cause: for the head dims it serves, that wrapper uses CUTLASS, whose ragged attention ignores the window even when it is planned.

A ragged wrapper planned with `window_left=511` on B300 (FlashInfer 0.7.2, lengths [1500, 700], 12 q heads, 2 KV heads, head dim 128, bf16), max absolute error against an fp32 reference:

| Backend | vs windowed reference | vs full-attention reference |
|---|---:|---:|
| CUTLASS | 0.390 | 0.0081 |
| FA2 | 0.0084 | 0.466 |

This was found while adding Beam (#44747) and is split out of #45256 at review. It affects every hybrid-SWA model that takes ragged prefill on this backend, not only Beam. Multimodal models, multi-item scoring, deterministic inference and `SGLANG_FLASHINFER_USE_PAGED` use the paged path instead.

## Modifications

Merged with main, where a sliding-window read is a `WindowRead`.

- Each wrapper (sliding/full, or decoder/cross-attention) gets its own ragged prefill plan in `prefill_wrappers_ragged`, built with the other prefill wrappers, so `skip_prefill` backends allocate none. Backends with two wrappers gain one more FlashInfer ragged wrapper and its workspace.
- The sliding wrapper's ragged plan takes `window.window`. `window.window_left` is -1 on this read because it belongs to the paged pass, which main keeps to the window with its custom prefix mask.
- The no-prefix ragged forward now passes the layer's `sliding_window_size`, as the prefix path already does.
- On SM100 the sliding ragged wrapper uses `fa2` where `cutlass` was selected, the same fallback the constructor uses for shapes CUTLASS does not serve. The override applies only to sliding wrappers otherwise assigned CUTLASS; other backend-selection rules are unchanged.
- The earlier paged-plan change in this PR is gone: on main, a ragged read already leaves the paged plan without the window.
- `test_flashinfer_window_verify.py` and `test_fused_draft_window_metadata.py` each change one line. They build the backend or updater with `__new__` and stub the single ragged wrapper, so they now set the list.

#34093 is open and overlaps this. It plans one shared ragged wrapper with the window, also passes `logits_soft_cap` at plan time, and leaves SM100 on CUTLASS. Both PRs change the same plan call.

## Accuracy Tests

Measured on B300 (SM103) with FlashInfer 0.7.2 and torch 2.14.1+cu130. "main" is 3a345c0743.

**Existing tests.** On this branch, `test/registered/attention/unittests/swa/` passes (23 passed, 49 subtests). Neighbouring planner tests give the same counts on main and this branch (35 passed, 68 subtests; 232 passed, 58 subtests), including `test_flashinfer_window_verify`, `test_fused_draft_window_metadata` and `test_flashinfer_host_plan`.

Static trace: target verify, graph-replayed draft extend and full-graph extend use paged plans; eager draft extend can take the corrected ragged path. Non-SWA DLLM extend and cross-attention keep their existing masking arguments.

**Beam prompt logprobs.** `reflection/Beam-1.0-501B-A23B-NVFP4` (c5621fc926), TP4 on 4x B300, `--chunked-prefill-size 1024 --disable-radix-cache --mem-fraction-static 0.85`, token-id prompts of 700, 1800, 2600 and 3000 tokens. Mean absolute logprob difference (max) against `--attention-backend trtllm_mha` on main, by query position, with the ratio to the in-window row:

| Query position | Path | main `flashinfer` | this branch `flashinfer` |
|---|---|---:|---:|
| up to 511 (n=2048) | no-prefix, in window | 0.0824 (2.55) | 0.0898 (2.78) |
| 512 to 1023 (n=1723) | no-prefix, past window | 0.6627 (11.20), 8.04x | 0.0747 (3.54), 0.83x |
| 1024 and up (n=4325) | ragged + paged merge | 0.3419 (15.51), 4.15x | 0.0594 (2.24), 0.66x |

- In-window positions move with the kernel change: this branch differs from main's `flashinfer` by a mean of 0.0847 (max 2.33), about the same as either differs from `trtllm_mha`.
- Adding the cookbook's `--page-size 64 --context-length 1048576 --enable-unified-memory` gives the same numbers on both branches.
- A probe in all 4 TP processes shows main planning only CUTLASS with `window_left=-1`, and this branch planning FA2 with `window_left=511` for sliding layers and CUTLASS with -1 for full layers.
- `trtllm_mha` on this branch returns identical logprob values to main (8096 compared, max difference 0.0).

**Speculative decoding.** These check the draft side of the change. They are not accuracy results.

- Windowed draft: a draft model with a sliding window takes the same ragged path in its prefill. `meta-llama/Llama-3.1-8B-Instruct` with `lmsys/sglang-EAGLE3-LLaMA3.1-Instruct-8B`, EAGLE3 steps 3, topk 1, draft tokens 4, `--speculative-draft-window-size 512`, `--dtype float16`, 8 prompts of 600 to 3300 tokens, greedy, 256 new tokens: overall accept length 2.151 on main and 2.160 here. Target outputs are identical on all 8 prompts, and 4 prompts change by one verify step.
- Hybrid target: Beam's prefill output on `flashinfer` changes, and the drafter conditions on it. Overall accept length with `reflection/Beam-1.0-501B-A23B-DFlash2` (163b276be7), block size 8, cookbook flags, greedy, 256 new tokens:

| Prompts | `trtllm_mha` | main `flashinfer` | this branch `flashinfer` |
|---|---:|---:|---:|
| 16 x 480 tokens (prefill inside the window) | 3.531 | 3.371 | 3.451 |
| 16 x 2048 tokens | 4.577 | not run | 4.271 |
| the 4 prompts above | 3.368 | 3.821 | 3.200 |

Inside the window this branch matches main within noise (1.02x; per-prompt mean +0.05, sd 0.30), and both `flashinfer` arms sit below `trtllm_mha`. Past the window this branch is 0.93x `trtllm_mha` on 16 prompts (higher on 5) and 0.84x main on 4; main's target logprobs are wrong there (table above), so its number is not a correct-output baseline, and why it is higher was not investigated. On the 2 prompts whose 256 tokens match `trtllm_mha`, accept length is 7.529 vs 7.314 and 7.529 vs 7.529 (this branch first). Each arm's draft ran on its target's backend (logged), so the comparison does not hold the draft backend fixed.

These are acceptance measurements, not accuracy or parity results.

Beam's cookbook recipes use `trtllm_mha` or `fa3`, not `flashinfer`. `trtllm_mha`'s target logprobs are unchanged here.

**Not covered.**
- Validated on B300 only. Windowed ragged plans on Hopper, where `auto` may resolve to FA3, were not run.
- This covers hybrid-SWA dispatch only. A layer with a window on a model that does not expose it to the runner still plans without it, as on main.
- No unit test checks the window in ragged prefill.
- No GSM8K or other trained-accuracy eval was run; the logprob comparison above is the accuracy evidence.

## Speed Tests and Profiling

Sliding layers' ragged prefill on SM100 moves from CUTLASS to FA2 where CUTLASS was selected. Full layers stay on CUTLASS. Main's numbers below are unwindowed, wrong attention, so these show the cost of the fix, not a speedup.

Kernel time: ragged `forward` with SGLang's plan and forward arguments, 12 q heads, 2 KV heads, head dim 128, bf16, inputs rotated over at least 256 MiB, 10 warmup and 60 timed runs, median in microseconds:

| Request lengths | main (CUTLASS, no window) | this branch (FA2, window 511) | Change |
|---|---:|---:|---:|
| 512 | 36.6 | 44.9 | +23% |
| 1024 | 40.5 | 65.0 | +60% |
| 2048 | 52.1 | 52.1 | 0% |
| 8192 | 225.0 | 106.5 | -53% |
| 16384 | 726.9 | 184.6 | -75% |
| 32768 | 2500.6 | 349.6 | -86% |
| 8 x 2048 | 173.7 | 171.3 | -1% |
| 4 x 8192 | 675.0 | 329.5 | -51% |

`forward_return_lse`, which the prefix path uses, shows the same pattern. One plan takes 124 to 1506 us on CUTLASS and 69 to 163 us on FA2 at these shapes.

End to end: Beam TP4 on `flashinfer`, radix cache off, `/generate` with `max_new_tokens=1`, median of 5 runs after 1 warmup, in milliseconds. The two groups use different server flags, so compare within a group only:

| Prompt tokens | Server | main | this branch | Change |
|---|---|---:|---:|---:|
| 512 | chunk 1024, cookbook flags | 24.54 | 24.59 | +0.2% |
| 1024 | chunk 1024, cookbook flags | 29.43 | 30.58 | +3.9% |
| 1536 | chunk 1024, cookbook flags | 52.18 | 53.32 | +2.2% |
| 2048 | default chunk (16384) | 43.89 | 43.50 | -0.9% |
| 8192 | default chunk (16384) | 110.39 | 103.12 | -6.6% |
| 16384 | default chunk (16384) | 213.30 | 186.54 | -12.5% |
| 32000 | default chunk (16384) | 460.39 | 415.04 | -9.9% |

Prompts of about 1000 to 1500 tokens cost 2 to 4% more; the +0.2% at 512 is within run-to-run spread. The window limits the keys each sliding-layer query reads, which is the likely reason long prompts take less time, but this was not profiled. Both arms in the first group ran with the dispatch probe loaded.
