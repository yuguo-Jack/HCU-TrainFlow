## Motivation

A request's per-window eviction cursors, a match's window host hits, eviction counts and the prefix tree's window slots were keyed by the tree's slot ids, so every reader outside the tree (the scheduler's eviction trigger, row frees, pool accounting, leak checks, decode preallocation, the prefill budget) had to know tree ids, and a unified pool's single window had two names depending on how many windows the plan held. This PR keys all of them by the window sub-pool's name, the key storage, demands and metrics already use, and leaves tree ids inside the tree.

## Modifications

- Window cursors: `ReqKvInfo.window_evicted_seqlens` replaces `component_evicted_seqlens`; `get_evicted_seqlen` / `set_evicted_seqlen`, `window_lengths()`, `window_retention()` and `KVStorage.advance(window_sub_pool=)` take sub-pool names; pool stats, leak checks and decode's pending-transfer charge key windows by sub-pool.
- Tree slots: every slot is numbered by its own name, a single window's too. Each boundary that keeps one window maps the tree's window slot to its own id there: the Rust tree adapter translates ids at every crossing of the binding (`NATIVE_FAMILY_IDS`); LMCache reads the window it publishes from the tree's window slot. Static pools keep their window slot named `SWA`, so their ids are unchanged.
- External cache linker (`mem_cache/unified_cache/unified_cache_linker.py`): keeps every window slot of the tree as its own pool and adds each window's host hit under its name; a window whose pages the store lacks is left out of offloads and its restored tails are tombstoned.
- Retained lengths: the tree's window lengths come from the storage's `retained_window_lengths` (`KVStorage.tree_slots`), the single source PD, the checksum and admission already read; the target window's retained length for static and unified pools is one rule (`retained_target_window`).
- Host hits by name: `UnifiedRadixCache` converts `MatchResult.window_host_hit_lengths` to sub-pool names before the external linker; `Req.window_host_hit_lengths` and `StagedPrefetchPlan.window_sub_pools` follow; the prefill budget no longer maps tree slots.
- Load-back sizing: `UnifiedRadixCache.full_load_back_tokens` answers how many token rows a load-back copies.
- Host pool names are plain strings (`host_pool_name`); a `PoolName` member still names the well-known pools.
- Tests: `test/registered/unit/mem_cache/test_unified_window_slot_trace.py` with a stored record (`unified_window_slot_trace.json`) of inserts, matches, locks, evictions, decode retirements, linker attachment and host-stack wiring over one and two windows on the Python and native tree cores, recorded by name; test helpers in `python/sglang/test/tree_slots.py`; existing tests moved to names.

**Behavior changes (unified memory only):**
- The external cache linker accepts a tree with several window slots (it refused one before).
- The leak check passed a window's tree slot where a sub-pool name was expected, so a window's protected tokens were not counted; it now counts them.

Otherwise no behavior change: the recorded results equal those recorded before the renaming.
