# [Fix] [AMD] quantization: make aiter optional for the quark schemes imported by every model

[Upstream PR](https://github.com/sgl-project/sglang/pull/46914) · state: open · merged: False

## Original PR description

## Motivation

On ROCm, three quark modules import aiter at module scope under a bare `if _is_hip:`:

- `quark/schemes/quark_w4a4_mxfp4.py`
- `quark/schemes/quark_w4a4_mxfp4_moe.py`
- `quark_int4fp8_moe.py`

All three are reached from `layers/quantization/__init__.py`, which every model imports. So on a ROCm install without aiter, `import sglang.srt.layers.quantization` fails, and the model registry ends up empty:

```
File ".../quark/schemes/quark_w4a4_mxfp4.py", line 86, in <module>
ModuleNotFoundError: No module named 'aiter'
```

This is the normal setup on RDNA, where aiter's compiled kernels are CDNA-only. The `amd_march` gfx1151 Dockerfile works around it by building aiter anyway. Its comment says: "aiter is not optional on ROCm despite being CDNA-oriented: ... imports quark, which imports aiter.ops.triton at module scope". A partial or older aiter install fails the same way (`No module named 'aiter.ops.triton.gemm'`).

These modules only need aiter when an MXFP4 or int4-fp8 MoE layer is actually built. Part of the RDNA plan in #46900.

## Modifications

- `quark_w4a4_mxfp4.py`:
  - Import the four aiter Triton kernels inside `try/except ImportError`, and register the wrapper custom ops only when the import succeeded.
  - `QuarkW4A4MXFP4.__init__` raises a clear `ImportError`, chained to the original one, if an MXFP4 linear layer is built without them.
- `quark_w4a4_mxfp4_moe.py`: `dynamic_mxfp4_quant` stays `None` when aiter is missing. That is already its value off ROCm, and the existing `if dynamic_mxfp4_quant is None` check handles it.
- `quark_int4fp8_moe.py`: import `aiter.ops.shuffle.shuffle_weight` inside `process_weights_after_loading`, its only user.

With aiter installed (CDNA), the same symbols are imported and the same custom ops are registered. Verified on an MI355X with aiter:

- `_aiter_mxfp4_import_error is None`
- all four wrappers are defined
- `dynamic_mxfp4_quant` resolves to aiter's function
- `shuffle_weight` imports

## Accuracy Tests

The ROCm environments below have no aiter installed (vLLM ROCm images, torch 2.13, Triton 3.7.1).

| | gfx1100 (W7900D) | gfx1201 (R9700) |
|---|---|---|
| `amd_march`: `import sglang.srt.layers.quantization` | `ModuleNotFoundError: No module named 'aiter'` | same |
| `amd_march`: registered model architectures | 0 | 0 |
| this PR: import | OK | OK |
| this PR: registered model architectures | 270 | 270 |

**End to end on gfx1100.** Qwen/Qwen3-8B, bf16, TP1, default server args (Triton attention, decode CUDA graph captured), no aiter. This PR plus the vLLM `fused_add_rms_norm` arity fix (separate PR, because vLLM is installed in this environment). `sgl-eval==0.1.2` gsm8k, 200 examples, `enable_thinking=false`, temperature 0.7, top_p 0.8, max_tokens 2048: **score 0.955**.

**End to end on gfx1201.** Same model, harness and settings, with this PR and vLLM absent from the environment, so RMSNorm uses `forward_native`: **score 0.935**. Server came up in 55 s, and the decode CUDA graph was captured in 8.2 s.
