# [Fix] hunyuan: Escape streamed string arguments like json.dumps

[Upstream PR](https://github.com/sgl-project/sglang/pull/46217) · state: open · merged: False

## Original PR description

## Motivation

Fixes #42139.

`HunyuanDetector._stream_args` escapes a partial string value by hand (`\\`, `"`, `\n`, `\r`, `\t` only), but the final delta is diffed against `json.dumps(self._completed_args)`. Any other control character (`\x00`-`\x1f`, e.g. `\b`, `\f`, `\x1f`) is streamed raw, and the final delta then appends the rest of its `\u00XX` escape, so the concatenated `arguments` are not valid JSON. The issue's repro on current main:

```
detect_and_parse : {"a": "\^_"}
streamed         : '{"a": "\x1fu001f"}'    # json.loads: Invalid control character
```

## Modifications

- Build the partial value with `json.dumps(safe_value, ensure_ascii=False)[:-1]`, the same encoder as the final arguments minus the closing quote. `json.dumps` escapes each character on its own, so the escaping of a prefix is a prefix of the final escaping, and the streamed deltas concatenate to exactly the one-shot arguments.
- Regression case: a string argument containing `\x00 \b \f \x1f " \ \n`, streamed character by character, must equal the `detect_and_parse` arguments and decode back to the original value.

Note for #45258 (open, O(N) streaming rewrite of this detector): its new incremental path keeps the same hand-written escaping, so it needs the same change.
