# [Core] Add an out-of-tree Mamba pool extension point

[Upstream PR](https://github.com/sgl-project/sglang/pull/40415) · state: closed · merged: False

## Original PR description

## Motivation

Out-of-tree platforms may need platform-specific Mamba state storage operations. Overriding the public lifecycle methods duplicates SGLang's ReplaySSM and sibling-state handling and makes those implementations drift as the lifecycle evolves.

## Modifications

- Split the state writes in clear, copy, and CPU restore into protected methods while retaining lifecycle coordination in `MambaPool`.
- Let an out-of-tree platform provide a `MambaPool` subclass, with the built-in pool as the default.
- Document the extension point and cover its conservative default.

## Accuracy Tests

The default implementation contains the same state writes in the same lifecycle order. The staged integration passed the focused Mamba state, GDN, and KDA tests.

## Speed Tests and Profiling

This changes request-state lifecycle dispatch only and does not add work to the per-token path. Existing platforms keep the built-in implementation.
