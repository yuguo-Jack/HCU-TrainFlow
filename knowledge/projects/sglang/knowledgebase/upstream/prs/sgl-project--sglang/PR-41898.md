# [Fix] dsa: Reject unsupported k-pool backends early

[Upstream PR](https://github.com/sgl-project/sglang/pull/41898) · state: open · merged: False

## Original PR description

## Motivation

On Hopper, pooled DSA with an FP8 KV cache can resolve to `flashmla_kv`, which cannot handle pooled tail tokens. The server loads weights before failing during CUDA graph capture.

Report unsupported configurations during argument resolution and keep that check consistent with runtime backend support.

## Modifications

Startup and runtime use one capability definition, including BF16 `flashmla_auto` prefill and the hardware-dependent remapping of `flashmla_sparse`. Errors list supported prefill and decode backends separately.

Preserve BF16 Q8 prefill added by #41790. FP8 auto prefill, auto decode, Q8 decode and packed-FP8 pooled-tail combinations remain rejected; non-pooled models, ROCm and existing early-return paths keep their behavior.

Native FlashInfer support in #38430 is still pending. When it lands, its implementation should add `flashinfer_sparse_mla` to the shared capability tuple. The guard edits overlap, so the PR that lands second must preserve the shared guard. This branch continues to reject that runtime path until it is supported.

## Accuracy Tests

Model-override, Q8-routing and stream-scheduling CPU suites pass on the updated branch, along with scoped formatting. The BF16 auto-prefill regression fails before the fix and passes afterward on simulated Hopper and Blackwell. Unsupported Hopper FP8 still fails early.

Combined CPU checks with #38430's native patch passed after resolving the guard through the shared tuple; these also predate the latest base update. No native FlashInfer GPU execution or new Hopper model-server run is claimed.

Run unit suites with `python -m pytest` and formatting with `pre-commit run --files <changed-files>`.

Not applicable. This changes startup validation and uses the existing runtime capability rules.

- ormandj · comment · 2026-10-13T08:58:44Z · [source](https://github.com/sgl-project/sglang/pull/41898#issuecomment-6142022311)

This interacts with #38430, which adds `flashinfer_sparse_mla` (FlashInfer's native sparse MLA path for GLM-5.3-Flash on SM120) to `_check_kpool_tail_backend`; that backend handles the pooled tail tokens. With the allowlist here, an explicit `--dsa-prefill-backend` / `--dsa-decode-backend flashinfer_sparse_mla` would be rejected at startup even after #38430 merges, so `_DSA_KPOOL_TAIL_BACKENDS` needs `flashinfer_sparse_mla` whichever PR lands first.

Building the allowlist and the error text from the set `_check_kpool_tail_backend` accepts, plus the remapped `flashmla_sparse`, would keep them aligned; the "Supported backends: fa3, tilelang, trtllm" text already omits `flashmla_sparse`.
