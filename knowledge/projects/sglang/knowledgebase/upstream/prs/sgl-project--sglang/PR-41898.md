# [Fix] dsa: Reject unsupported k-pool backends early

[Upstream PR](https://github.com/sgl-project/sglang/pull/41898) · state: open · merged: False

## Original PR description

## Motivation

GLM-5.3-Flash fails after load when the KV dtype, DSA backend and GPU cannot read pooled rows (`index_kpool > 1`). Users report it with FP8 KV on H20 (#36830), and on SM120 with default backends and BF16 KV (#37105) or with explicit backends (#39302). On one B200 with a reduced config and dummy weights, main exits after 36 to 45 s and this PR after 12 to 18 s. Real weights were not measured.

This PR rejects these configurations at startup and lists the allowed backends. Rejected pairs still do not serve.

#47237 refuses `trtllm` outside SM100, SM103 and SM107, which catches the SM120 defaults but not `flashmla_kv`, `fa3` or `flashmla_sparse`.

## Modifications

Startup and the runtime guard share one capability table. A PD node checks only its starting role.

This PR also corrects the cookbook note on FP8 KV with TileLang DSA, because the new error lists that pair.

Recipes (TPU7x not traced) and ROCm startup do not change.

Startup skips learnable-sink, SM12x FP8 `GlmMoeDsaForCausalLM` and HiSparse. A prefill node with an unsupported decode backend, and SM102 with `trtllm` (by code reading), pass startup and can fail after load.

Whichever merges later adapts: #38430 or #45298 (SM12x backend), #44217 (SM90 Q8 prefill, cookbook sentence), #47237 (table rows).
