# [Perf] Fuse BF16 QK normalization and multimodal rotary on Blackwell

[Upstream PR](https://github.com/sgl-project/sglang/pull/43425) · state: open · merged: False

## Original PR description

## Motivation

Qwen3 multimodal decode currently launches Q/K normalization and MRoPE separately. This change combines them for BF16 tensors with 128-element heads, full-width NeoX rotation, and 1–128 tokens on Blackwell. Unsupported model configurations retain the existing path.

## Modifications

The implementation reuses the existing normalization kernel's load, reduction and store, adding a rotation epilogue in the existing fused RoPE source. It preserves the BF16 rounding between normalization and rotation, supports strided Q/K and position rows, and uses the selected direct per-head scheduling for this fusion. The normal kernel keeps its persistent scheduling. The new CUDA import stays at module scope under the existing platform guard.

Based directly on upstream main `2f1acef3d8`; no dependency on GEMM tuning or cache-writer changes.

## Accuracy Tests and Prior Measurements

Prior validation of the shared implementation passed all 560 existing normalization tests. A prior standalone screen using 36 actual layer weights, batches 1/16/128 and changed-input graph replay matched bitwise. The no-cache B128 screen measured 3.20846 µs for the earlier standalone implementation and 3.24509 µs for shared reuse; this is not a serving-throughput result. These checks predate this upstream-based extraction and support the reused arithmetic/scheduling, but do not validate this exact branch. Cache-write and projection fusion are excluded from this change.

## Validation on This Branch

Validation on this branch: pre-commit, Python AST and static dependency/registry checks. CPU namespace/dispatch tests could not collect because the local Python environment lacks PyTorch. No fresh GPU or server validation was run, and no serving TPS improvement is claimed.
