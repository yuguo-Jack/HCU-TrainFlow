# [Fix] observability: Snapshot STANDALONE metrics before settlement

[Upstream PR](https://github.com/sgl-project/sglang/pull/47060) · state: open · merged: False

## Original PR description

## Motivation

Follow up on #38711 by including STANDALONE in the existing speculative forward-pass metrics snapshot path.

STANDALONE uses the V2 host settlement path, but is absent from `_SPEC_DECODE_SNAPSHOT_ALGORITHMS`. Its result therefore does not retain the scheduled cached-context lengths before accepted tokens mutate the requests. With overlap scheduling, merging a batch whose optional `seq_lens_cpu` mirror is absent also leaves that mirror absent; the later metrics builder then raises `TypeError` instead of using a result snapshot.

The generic absent-mirror issue and emission-time fallbacks are already discussed in #31309, #31319, #39537, and #36387. This change only connects STANDALONE to the pre-settlement mechanism already introduced by #38711; it does not add another generic fallback or claim to cover the other paths in those reports.

## Modifications

- Add STANDALONE to the existing snapshot algorithm list.
- Extend the snapshot timing/retraction test to STANDALONE.
- Add a CPU regression using real request, batch/sampling/spec merge, and decode-result settlement methods, with the optional CPU mirror both present and absent. It checks that the cached-context sum stays at the pre-settlement value 39 even after the request lengths advance to a sum of 46.

The regression uses named no-resource boundaries for streaming, allocator grouping, finish handling, and the worker callback. It does not claim to test GPU execution, physical KV release, or a full scheduler service.

## Accuracy Tests

Tested the public source at `73fbf5ccd3be7c04cedccfac9bec5c2e7ae12df4` in a temporary package copy, with the changed registered unit test imported normally.

```sh
python test/registered/unit/observability/test_forward_pass_metrics.py -v
```

- Original reporter + new lifecycle regression: one method, two subtests. The absent-mirror case raises the real `TypeError`; the mirror-present control reports 39 but has no retained result snapshot.
- Patched reporter: **all 34 test methods pass**, including STANDALONE timing/retraction and both real lifecycle subtests.
- Both phases verify imported module paths and source hashes; the independent process has `torch.cuda.device_count() == 0`.
- Environment: Python 3.12.3, PyTorch 2.14.1+cu130, Transformers 5.19.0, msgspec 0.22.0, sglang-kernel 0.4.9. This exercises Python CPU behavior; main declares kernel 0.4.10, so it is not a matching-kernel GPU validation.

No model loading, service requests, or installed-package changes were involved.

## Speed Tests and Profiling

Not benchmarked. This reuses the existing CPU snapshot calculation for one additional algorithm. It adds no GPU synchronization and changes no scheduling or model execution. Its extra host snapshot cost has not been measured.
