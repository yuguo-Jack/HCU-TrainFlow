## What

The tiny GEMM (`x[m, k] @ w[n, k].T` for MoE router gates and other skinny projections) becomes one kernel family with two templates under `kernels/jit/csrc/gemm/tiny_gemm/`, replacing `tiny_gemm.cuh` and `small_gemm_bf16.cuh`:

- SIMT (`simt.cuh`, CUDA and ROCm, bf16 or fp32 weights): K / 16 lanes cover a row of w and reduce it with shuffles (and shared memory past one warp); a CTA owns a few rows of w, loaded before the PDL wait. Larger batches copy each weight tile into the fewest CTAs along `blockIdx.y`, rows spread evenly.
- MMA (`mma.cuh`, sm90+, bf16 weights): `mma.sync m16n8k16`, K split over a thread-block cluster and its warps (any cluster size from 1 to 8 with an even split), partial sums reduced over the warps in shared memory and reduce-scattered over the cluster with `st.async`. Batches are tiled over CTA rows sized by the driver's cluster occupancy.

`tiny_gemm_bf16` picks the template per batch size: m = 1 always takes SIMT, larger m takes MMA from `M* = max(2, round(1 + 300 / (K * (4 + N_TILE) / 128)))`, a B200 cost model (SIMT pays an L2 re-read of x plus `N_TILE * K` FMAs per extra row, MMA a fixed ~300-cycle DSMEM reduction), with measured exceptions for K <= 512. FP32 weights always take SIMT (exact fp32 products); ROCm and other archs only have SIMT. Any m is served; callers keep their own cuBLAS cutover.

Also:
- `small_gemm_bf16` is removed: the DeepSeek-V4.1 indexer (`wk` 128x512, `weights_proj` 32x5120) calls `tiny_gemm_bf16` directly, under the same gate.
- `max_m` / `n_split` are removed from `tiny_gemm_bf16` / `can_use_tiny_gemm` (no longer used by the kernels); callers are updated.
- The cluster occupancy probe (`csrc/occupancy/cluster_probe.cuh`) sets its function attributes once per device instead of on every query, so concurrent queries (e.g. from `parallel_compile` threads) no longer race.
- The test and benchmark cover more router shapes (DeepSeek-V3/V4/V4.1, Kimi-K2/K3, GLM-5, Qwen3/3.5, dots3, gpt-oss, Kimi-K3 KDA, DeepSeek-V4.1 indexer) and build every module in parallel before running.

## Performance

21 shapes (above) x m = 1, 2, 4, 8, 16, bf16 output, CUDA graph, median. PDL: behind a producer that releases its dependents early (weights prefetched before the wait); cold: L2 flushed, no PDL. Geomean of time ratio (this PR / baseline, lower is better):

| GPU | vs main (PDL / cold) | vs FlashInfer tinygemm_bf16 | vs FlashInfer router GEMM (5 shapes) | vs cuBLAS |
|---|---|---|---|---|
| B200 | 0.73 / 0.88 | 0.52 / 0.69 | 0.35 / 0.69 | 0.28 / 0.58 |
| H200 | 0.72 / 0.89 | 0.52 / 0.71 | 0.38 / 0.81 | 0.20 / 0.53 |

Examples, us, PDL (main -> this PR; cuBLAS in brackets):

|---|---|---|---|
| DeepSeek-V3 router 256x7168 | B200 | 1.28 -> 1.28 (4.83) | 4.38 -> 1.79 (5.50) |
| Kimi-K3 router 896x7168 | B200 | 1.73 -> 1.76 (7.74) | 9.41 -> 2.27 (7.33) |
| DeepSeek-V4.1-Flash router 384x5120 | B200 | 1.41 -> 1.38 (5.34) | 4.54 -> 1.57 (5.60) |

m = 1 matches main (both SIMT); the gain grows with m.
