# [Fix] kimi_k3: stream tool-call arguments instead of buffering until <|close|>call

[Upstream PR](https://github.com/sgl-project/sglang/pull/45716) · state: open · merged: False

## Original PR description

## Motivation

Fixes #45697.

The Kimi K3 tool-call parser (`kimi_k3`) does not stream tool-call arguments: the whole call is buffered until `<|close|>call`, so clients see one giant blob at the end instead of incremental argument deltas.

## Modifications

- Rewrote `KimiK3Detector.parse_streaming_increment` in `python/sglang/srt/function_call/kimik3_detector.py` as an event-driven scan over the tools section: emits a `ToolCallItem` with the tool name as soon as an `<|open|>call` tag completes, then streams parameters as incremental JSON deltas.
- String argument values stream per fragment (JSON-escaped, holding back partial-marker suffixes via `kimik3_format.partial_suffix_len` so a chunk boundary can never emit text that becomes a marker); non-string values stay buffered until their close tag and are JSON-decoded as before.
- Concatenated deltas are byte-identical to the non-streaming `json.dumps(arguments, ensure_ascii=False)` output (verified), and `prev_tool_call_arr` / `streamed_args_for_tool` stay in sync for `serving_chat`'s end-of-stream flush logic.
- `detect_and_parse` is unchanged.
- Updated `test/registered/function_call/test_kimik3_detector.py` streaming tests to the delta contract and added 6 new tests: name-at-open, deltas-before-close, byte-identity with tricky content (quotes/unicode/partial-marker-like text, chunk sizes 1/7/23), non-string buffering, zero-arg call.

## Accuracy Tests

- Full sglang suite unrunnable in this env (no GPU; xgrammar/torch unavailable).
- Ran the repo's `test/registered/function_call/test_kimik3_detector.py` (23 tests incl. 6 new streaming tests) against the REAL detector code via a lightweight stub harness (stubs only for xgrammar, protocol models, base_format_detector, FunctionCallParser, ci_register): 23/23 pass.
- 180-seed random-chunking fuzz (chunk sizes 1..64) over multi-call streams with tricky content: every run reassembled byte-identical to `json.dumps` and to `detect_and_parse` output, and final serving-layer bookkeeping (`streamed == json.dumps(decoded)`) held exactly.
- Edge cases verified: mid-argument truncation (finish warns, no crash, no bogus flush), empty tool-name call skipped, orphan call-open abandoned without hang, zero-arg call emits `{}`, plain-text streaming unchanged.

## Speed Tests and Profiling

- Perf: 20KB argument stream processed in ~11ms with 558 incremental deltas (previously 1 buffered blob).
