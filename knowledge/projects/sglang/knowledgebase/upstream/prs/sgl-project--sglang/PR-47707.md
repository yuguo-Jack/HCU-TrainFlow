# [Doc] docs: Fix commands that the CLI rejects

[Upstream PR](https://github.com/sgl-project/sglang/pull/47707) · state: open · merged: False

## Original PR description

## Motivation

Some documented commands fail when copied. I ran the LLM server and benchmark commands in `docs/`, `README.md`, and `examples/` through the real argument parsers (about 800 server commands and 380 benchmark commands) and fixed the ones the CLI rejects.

| Page | Problem | Result on `main` |
| --- | --- | --- |
| `cookbook/autoregressive/Meta/Llama3.1.mdx` (6 commands) | The benchmark commands call `sglang serve` with benchmark flags | `sglang serve` does not accept `--backend`, `--dataset-name`, and similar flags |
| Same page | Five of those commands pass `--model-path` | The benchmark parser does not accept it and leaves `--model` unset |
| `ascend-npus/.../mimo_v2_5_pro.mdx` | `--cuda-graph-bs` | `ambiguous option: --cuda-graph-bs could match --cuda-graph-bs-decode, --cuda-graph-bs-prefill` |
| `advanced_features/cuda_graph_for_multi_modal_encoder.mdx` | `--cuda-graph-tc-compiler eager` | The flag no longer exists, because `tc_compiler` was removed with `tc_piecewise` |
| `developer_guide/bench_serving.mdx` | Mooncake example | `agent` is not a valid `--mooncake-workload` value, an unquoted `\|` is a shell pipe, the line has no continuation, and `--use-trace-timestamps` takes no value |

## Modifications

- Point the Llama3.1 benchmark commands at `python3 -m sglang.benchmark.serving`, the non-deprecated entry point, and use `--model`. All other flag values are unchanged. This also adds the space missing before one line continuation.
- Use `--cuda-graph-bs-decode` in the MiMo-V2.5-Pro recipe, which is the decode instance's command.
- Drop `--cuda-graph-tc-compiler` from the ViT CUDA graph example. It was set to `eager`, which was the default.
- Make the Mooncake example a single runnable command, and list the four valid `--mooncake-workload` values below it.

Docs only.

## Verification

All of this ran on CPU. These commands were parsed, not executed, so no model was served and no benchmark was run:

- All 6 Llama3.1 commands parse with the `sglang.benchmark.serving` parser, and their parsed values match the original commands.
- The Mooncake, ViT, and MiMo-V2.5-Pro commands parse with their real parsers.
- No documented benchmark command fails to parse now.
- The remaining server parser errors are false positives from my check. They come from placeholders such as `<other option>` or `$((8998+1))`, `--config` and `sglang serve <model>` commands, `--model-type`, diffusion flags, and one JSON value in `lora.mdx` that my script's shell splitting broke.
- `test_server_args_docs_coverage.py` and `pre-commit run --files` pass.

I did not check diffusion commands: many of their flags are registered per pipeline, so a static parser check would be unreliable.
