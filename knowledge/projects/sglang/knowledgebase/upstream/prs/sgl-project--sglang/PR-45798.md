# [Fix] llava: Load LLaVA-1.5 CLIP tower

[Upstream PR](https://github.com/sgl-project/sglang/pull/45798) · state: open · merged: False

## Original PR description

## Motivation

llava-hf/llava-1.5-7b-hf fails at model init on every backend (reproduced on Intel XPU; the P1 accuracy matrix shows the same failure on H200):

AttributeError: 'Conv2d' object has no attribute 'num_embeddings'   (models/transformers.py)

LlavaForConditionalGeneration resolves its vision tower by arch name (CLIPVisionConfig → "CLIPVisionModel"), but clip.py only registered CLIPModel. ModelRegistry.resolve_model_cls does not raise for an unregistered arch — it silently falls back to the generic TransformersForCausalLM, which eagerly reads get_input_embeddings().num_embeddings; a CLIP tower's input embedding is a Conv2d. Fixing the registration exposed three further bugs on the llava-1.5 path that had never been reached.

## Modifications

models/clip.py
- Register CLIPVisionModel (EntryClass = [CLIPModel, CLIPVisionModel]) and give it the llava tower contract, mirroring PixtralVisionModel: forward(pixel_values, image_sizes=None, output_hidden_states=False) returning an HF-shaped CLIPVisionOutput when hidden states are requested (llava-1.5 uses vision_feature_layer=-2), self.config, and load_weights.
- CLIPVisionTransformer.forward gains output_hidden_states; the default path is unchanged.
- Move CLIPModel.load_weights body verbatim into a shared load_clip_weights().
- monkey_patch_weight_loader: add the allow_patterns_overrides parameter so the override matches DefaultModelLoader._prepare_weights — serving CLIPModel as an embedding model was crashing with a TypeError on every backend.

models/llava.py (each was masked by the previous one)
- load_weights: accept vision_feature_select_strategy == "default" (HF's spelling of "patch"; get_image_feature already treated it that way).
- _infer_image_aspect_ratio: a processor-recorded None means a plain square resize → "square", instead of falling through to "anyres" and padding to a grid the tower never produces.
- pad_input_ids: set per-item item.offsets (inclusive spans), required by general_mm_embed_routine; the legacy LlavaLlama/Qwen/Mistral classes use their own forward and were unaffected.
- get_image_feature: convert numpy pixel values from LlavaImageProcessor to a tensor before the native tower.

No device-specific branches; all changes are additive or behavior-preserving for other models.
