# [perf] Sample next tokens from temperature-scaled logits without materializing full-vocab probs

[Upstream PR](https://github.com/sgl-project/sglang/pull/36103) · state: closed · merged: False

## Original PR description

## Motivation

On the default CUDA (flashinfer) sampling path, every non-greedy decode step runs an explicit full-vocab softmax plus an in-place copy-back (`logits[:] = torch.softmax(logits, dim=-1)`), then samples from the materialized probs. The filter-free (temperature-only) case additionally uses `torch.multinomial`, whose cost explodes with batch size.

The fused flashinfer samplers can consume temperature-scaled logits directly, and the repo already ships an alignment test (`python/sglang/kernels/aot/tests/test_sampling.py`) showing `top_k_top_p_sampling_from_logits` draws **RNG-for-RNG identical tokens** to `softmax` + `top_k_top_p_sampling_from_probs` (both `joint` and `top_k_first` orders). This is the output-side sibling of the input-logprob fast path from #31958.

## Modifications

- `Sampler._should_sample_from_scaled_logits`: the fast path engages only when nothing downstream needs the probs tensor — it is skipped for probs-derived logprobs (`return_logprob`), RL sampling-mask capture, per-request `sampling_seed`, deterministic inference mode, `min_p`, and non-flashinfer backends. Existing fallback routes are retained.
- `Sampler._sample_from_scaled_logits`: `top_k_top_p_sampling_from_logits(..., filter_apply_order="joint")` for the top-k/top-p case, `sampling_from_logits` for the filter-free case.
- `environ.py`: `SGLANG_DISABLE_SAMPLING_FROM_LOGITS` (`EnvBool(False)`) escape hatch, placed next to its input-side sibling `SGLANG_ENABLE_FAST_INPUT_LOGPROBS`.
- New CUDA kernel test `test/registered/kernel/sampling/test_sampler_from_logits.py` (gate truth table, bitwise parity vs the probs path under a shared RNG state, distribution parity vs `torch.multinomial`), registered in the dispatched `base-b-kernel-unit-test-1-gpu-large` suite.

## September 14 CPU-only update

Rebased onto `7465e42b7a`, including the current CI baseline. Adapted the fallback to the current `_sample_from_probs` return value `(token_ids, sampling_mask_capture)`, retaining the new opt-in-row sampling-mask handling and `sampling_mask_max_tokens` initialization.

Added `test_sampler_from_logits_dispatch.py` to CPU CI. Its five tests passed in a dependency-isolated harness using the checked-out Sampler definition, real CPU tensors, and mocked sampling/distributed boundaries: fast dispatch, sampling-mask capture, escape hatch, logprob fallback, and unavailable logits kernels. Ruff/isort and whitespace checks passed.

The full SGLang import stack, CUDA parity, and serving benchmarks have not been rerun on this head. GPU results below describe earlier revisions.

## Accuracy Tests (historical)

- Unit tests 5/5 on L40S, including sampler-level bitwise parity: with the same RNG state, the fused top-k/top-p path returns tokens identical to `softmax + top_k_top_p_sampling_from_probs` (bs=64, vocab 32k).
- Filter-free path: empirical distribution over 200k draws, L1(new, true)=0.0072 vs L1(torch.multinomial, true)=0.0085 (vocab 64) — at least as faithful as the current path.
- E2E A/B (env flag on/off, same build): greedy outputs byte-identical; `return_logprob` and seeded requests fall back to the existing pipeline and return unchanged results.

## Speed Tests and Profiling (historical)

Kernel-level (L40S, vocab=151936, fp32 logits; old = softmax + copy-back + sample-from-probs, per step):

| bs | config | old (us) | new (us) | saved |
|---|---|---|---|---|
| 1–32 | temperature-only | ~168 | ~61 | ~107 us (2.8x) |
| 128 | temperature-only | 988 | 61 | 927 us (16.3x) |
| 128 | top_p=0.95, top_k=ALL | 577 | 382 | 195 us |
| 128 | top_p=0.95, top_k=50 | 675 | 485 | 190 us |
| 32 | top_p=0.95, top_k=ALL | 108 | 101 | 7 us |

E2E (qwen3-0.6b, 1x L40S, `bench_serving` random 256/256, concurrency 128, ABAB design across 4 server restarts):

| sampling | baseline median TPOT | fast median TPOT | delta |
|---|---|---|---|
| temperature=1.0 | 20.52 / 20.94 ms | 19.89 / 20.22 / 20.22 ms | **~3–4% faster**, output throughput +3.5–6% |
| + top_p=0.95 | 20.30–20.78 ms (4 reps) | 20.14–20.97 ms (4 reps) | within restart noise (kernel saving ~1% of step) |

The temperature-only saving is a fixed per-step cost (vocab- and batch-dependent, model-size independent), so the relative gain is largest for small/fast models and large running batches.

## Historical L20 Revalidation

These earlier measurements used base `a7ee399904` and tested revision `3d7b5d5932`; they are not measurements of the September 14 head.

- Repository lint/format: Ruff, isort, and Black passed on all changed Python files.
- CUDA parity/regression: `155 passed, 3 skipped, 6 subtests passed` across the new sampler tests and the existing FlashInfer AOT sampling alignment matrix.
- E2E A/B: Qwen3.5-9B on one NVIDIA L20, FlashInfer sampling, 64 requests at concurrency 64, random-id 32/128, `temperature=1`, `top_p=1`, `top_k=ALL`, CUDA graphs disabled.

| Mode | Output throughput (tok/s) | Mean TPOT (ms) |
|---|---:|---:|
| Existing probs path (`SGLANG_DISABLE_SAMPLING_FROM_LOGITS=1`) | 1744.75 / 1721.91 | 34.38 / 34.29 |
| Fused logits path | 1744.84 / 1770.43 | 33.75 / 33.72 |

Across the two steady-state runs, the fused path improved mean output throughput by about 1.4% and reduced mean TPOT by about 1.75%. The first server run was excluded because it incurred one-time batch-64 Triton compilation (visible as a much higher TTFT).

- Greedy + `return_logprob` fallback produced byte-identical token IDs and logprobs with the fast path enabled versus disabled (same SHA256: `903aeea2ca02456f7ad67ffee8c06f57b05ade3bf421e53cb69dd34a88887f1d`).
