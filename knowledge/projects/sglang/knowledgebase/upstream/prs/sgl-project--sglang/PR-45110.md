# [Fix] kimi-k3: Avoid vision attention child-name collisions

[Upstream PR](https://github.com/sgl-project/sglang/pull/45110) · state: closed · merged: True

## Original PR description

## Motivation

Kimi-K3 stores vision-attention implementations in an `nn.ModuleDict`.
Previously, attention implementation labels were used directly as PyTorch
child-module names.

These labels are selection identifiers and are not guaranteed to be safe
`nn.Module` attribute names. For example, an implementation registered with
the label `"cuda"` conflicts with the existing `nn.Module.cuda()` method.
PyTorch rejects the child registration with:

```text
KeyError: "attribute 'cuda' already exists"
```
This failure occurs during model construction, before any attention
implementation is invoked.

Kimi-K3's current CUDA auto-selection path uses implementation labels such as
`"triton_attn"` and `"fa4"`. Those labels do not conflict with `nn.Module`
attributes, so the issue is not observed in the current CUDA path.

The failure surfaces when a custom or externally registered attention
implementation uses a colliding label (for e.g. `platform_arch` from PyTorch). 
Its registry lookup can succeed, but model construction still fails before the 
implementation or any attention kernel is invoked.

This is therefore a child-module naming issue, not a missing backend,
unsupported device, or attention-kernel failure.


## Modifications

- Separate vision-attention implementation labels from private PyTorch child
  names in Kimi-K3.
- Register implementations under namespaced names of the form
  `qkv_impl_<label>`.
- Add centralized helpers for implementation membership and retrieval.
- Update the Kimi-K3 forward and FA4 precompile paths to use these helpers.
- Add CPU-only regression coverage that:
  - reproduces an `nn.Module` namespace collision using the injected label
    "cuda";
  - verifies an ordinary "triton_attn" implementation label;
  - verifies child-module and state-dict registration;
  - invokes the selected implementation;
  - covers FA4 membership and precompile lookup.

The attention registry, implementation selection, tensor operations, kernels,
weights, and precision are unchanged.

The private named_modules() paths change from raw implementation labels to
attention_backend_impls.qkv_impl_<label>. Current vision-attention
implementations do not contribute learned checkpoint parameters.
