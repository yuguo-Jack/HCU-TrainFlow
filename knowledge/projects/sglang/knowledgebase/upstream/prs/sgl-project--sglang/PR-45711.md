# [Feat] GLM-5.2: Support NVFP4 KV cache with DSA layer split

[Upstream PR](https://github.com/sgl-project/sglang/pull/45711) · state: open · merged: False

## Original PR description

## Motivation

Add SM100 NVFP4 KV cache support for GLM-5.2 DSA. Allow the existing layer-split flag to store target KV layers on their owning interleave-CP ranks. Support PD prefill and unified prefill/decode serving with EAGLE/MTP.

This is a draft. Local correctness checks and a long-context capacity run are complete. Dataset accuracy and a controlled, repeated throughput/latency comparison remain open.

## Modifications

- Add the SM100 FlashMLA NVFP4 specialization and DSA codec. Main-cache rows use 416 packed bytes. The indexer uses 132 bytes per row.
- Initialize per-layer FP32 global scales in the shared MLA pool path. Preserve scale values and addresses when buffers are rebuilt. Return raw packed bytes from layer-split getters.
- Support NVFP4 with interleave CP and PD prefill layer splitting. Preserve layer mapping, byte widths, and full draft caches.
- Add unified serving with TP=CP>1, DP=1, and PP=1. Prefill transfers the active physical pages, including cached prefixes. Layer owners compute decode/target-verification attention and broadcast the results. Decode and target verification support CUDA Graphs.
- Account for local layers, remote scratch, indexer buffers, scales, and prefill staging. Use 64-bit cache address arithmetic. Assemble paged DSA logits one chunk at a time to reduce peak allocation.
- Add regression tests, benchmark drivers, and launch examples. Reuse the existing CLI flags. The NVFP4 path requires page size 64, `flashmla_sparse` prefill, and `flashmla_kv` decode. PD layer splitting still requires Mooncake.

## Accuracy Tests

Validation uses commit `9221ec3618b2aba7390711982a766312c9f2e858`.

- 97 test cases passed across the first 11 local validation stages. Coverage includes CP=2/4, nonuniform layer ownership and scales, packed-byte cache operations, prefetch/write behavior, prefix/chunked prefill, owner routing and CUDA Graphs, large index-cache offsets, and FP8 regression.
- The initial paged-logit validator failed on exact top-k index equality at tied boundary scores. A follow-up GPU regression passed all 6 cases in eager execution and two CUDA Graph replays. Valid logits are exactly equal (`rtol=0, atol=0`). Different selected indices occur only at exactly equal boundary scores; selected score multisets match full `torch.topk`. Numerical tolerances were not widened.
- The unified long-context run completed all 1,280 requests with zero retractions. This checks request completion, not model accuracy.
- Dataset accuracy has **not** been evaluated. A full GSM8K test and acceptance runner are included but are not reported as passed.

## Speed Tests and Profiling

Local paged-logit regression collected 84 timing samples. For the large draft case (batch 512), peak temporary allocation fell from 10.56 GiB to 5.54 GiB; median GPU time rose by 1.3%. For native target verification at batch 512, allocation fell from 10.55 GiB to 6.84 GiB; median GPU time fell by 3.45%. These results apply only to those local cases.

The full-model capacity run used 8 GB300 GPUs in one NVLink domain, unified TP=CP=8, DP=1, NVFP4 KV, and EAGLE steps=5/topk=1/draft tokens=6. The KV allocation ceiling was 152 GiB per GPU, including target, indexer, remote scratch, complete draft cache, scales, and staging. The workload used 640 two-turn sessions, about 64K mean input tokens, up to 450,560 input tokens, and about 400 mean output tokens.

| Metric | Layer split ON, client concurrency 256 |
| --- | ---: |
| Successful requests | 1,280 / 1,280 |
| Output throughput | 405.03 tokens/s |
| TTFT p50 / p95 | 4.77 / 175.53 s |
| TPOT p50 / p95 | 643.69 / 4,257.78 ms |
| Mean running requests, middle 20–80% window | 251.02 |
| Mean / peak active KV occupancy | 56.91% / 64.66% |

All ranks stayed within the KV allocation ceiling. Uneven layer ownership leaves different per-rank allocations. Six CUDA allocator allocation-failure/retry warnings occurred; the run then completed all requests.

Historical OFF results at the same per-GPU KV ceiling reached 392.19 tokens/s at concurrency 64 and 315.36 tokens/s at concurrency 128, with lower tail latency. Those runs used different physical GPUs, source revisions, and request manifests. They are not a controlled comparison. This single ON run does not establish a repeatable throughput/latency benefit, and active KV capacity was not saturated.
