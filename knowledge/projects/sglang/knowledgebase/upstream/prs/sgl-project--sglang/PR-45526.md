# [Fix] sgl-router: Bump rustls-webpki and webpki-roots for emSign advisories

[Upstream PR](https://github.com/sgl-project/sglang/pull/45526) · state: closed · merged: True

## Original PR description

## Motivation

The router's tier-1 `cargo deny check` now fails on every PR that touches `sgl-router/` (e.g. [#45502](https://github.com/sgl-project/sglang/pull/45502), [job](https://github.com/sgl-project/sglang/actions/runs/39540580437/job/119065828194)). Three advisories published today hit our lockfile:

- [RUSTSEC-2026-0382](https://rustsec.org/advisories/RUSTSEC-2026-0382): `rustls-webpki 0.103.15` may accept certificate paths through the distrusted emSign intermediates. Fixed in 0.103.16.
- [RUSTSEC-2026-0381](https://rustsec.org/advisories/RUSTSEC-2026-0381): `webpki-roots 1.0.9` and `0.26.11` bundle the `emSign ECC Root CA - G3` root. Fixed in 1.0.10.

Main's own router runs skip tier-1 when no router files change, which is why main still looks green.

## Modifications

- `sgl-router/Cargo.lock`: `rustls-webpki` 0.103.15 → 0.103.16, `webpki-roots` 1.0.9 → 1.0.10 (`cargo update --precise`). No other lockfile changes.
- `sgl-router/deny.toml`: ignore RUSTSEC-2026-0381, with a reason, for `webpki-roots 0.26.11` only. `ureq 2` (via `fastokens` ← `dynamo-tokenizers`) pins it. 0.26.11 is a shim that re-exports `webpki-roots 1.x`, which is now the fixed 1.0.10, and it bundles no roots of its own. Drop the ignore once `ureq 2` leaves the tree.

## Verification

In `sgl-router/` on main + this PR, with cargo-deny 0.19.6 (the CI version):

- `cargo deny check licenses bans sources advisories`: `advisories ok, bans ok, licenses ok, sources ok`
- `cargo metadata --locked` ok
- `cargo check --locked --all-targets` ok

Only sgl-router runs cargo deny in CI; `rust/Cargo.lock` is not checked and is left as is.
