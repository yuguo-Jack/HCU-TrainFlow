# [Perf] [NVIDIA] serving: LayerNorm SP min tokens, DFLASH overlap, small-batch reject sampling, HiCache host sizing, NVFP4 hybrid SWA KV fix

[Upstream PR](https://github.com/sgl-project/sglang/pull/47807) · state: open · merged: False

## Original PR description

## Motivation

Six changes from tuning a TP4 NVFP4 deployment that serves a hybrid full + sliding-window attention model with DFLASH speculative decoding, LayerNorm sequence parallelism (`--enable-layernorm-sp`) and HiCache. Two are bug fixes the configuration hits at startup; three make existing paths cheaper; one sizes the HiCache host tiers for sliding-window prefix hits. The NVIDIA megakernel plugin's prefill and extend support, first part of this PR, is now #47930.

Every behavior change sits behind a new flag that defaults to today's behavior, or is numerically identical to the stock path (bit for bit where tested).

## Modifications

- **Hybrid SWA pool with an NVFP4 KV cache (fix).** `--kv-cache-dtype nvfp4` on a hybrid sliding-window model never got an FP4 KV quant method: the `is_hybrid_swa` branch of `_build_token_to_kv_pool` built none, so both sub-pools fell back to `UnquantizedKVCacheMethod` over a `float4_e2m1fn_x2` dtype and the first KV write failed. The branch now builds the method (with the plain branch's page-major assertion) and `SWAKVPool` passes it to both sub-pools. That exposed a silent second bug: `SWAKVPool.set_kv_buffer` passed `layer=None`, so a quantized sub-pool read the per-layer KV scale of the global layer that shares the local index, which is the wrong layer for every write but the first with interleaved layers. It now passes the layer.
- **HiCache host pools against one free-memory snapshot (fix).** Each host pool re-sampled free host memory as it was built and divided it by the local rank count. Ranks build concurrently, so a rank that sampled after its peers had pinned their pools saw a fraction of its share, and a large `--hicache-size` failed on some ranks ("Not enough host memory available") or came up with different pool sizes per rank. `build_kv_cache` now takes one snapshot between two barriers (the world group's CPU group) and books every pool against it with the existing `host_memory_budget_scope`, as auto-sizing already does. Pool sizes are unchanged; with hierarchical caching off the path is untouched.
- **`--hicache-swa-host-ratio` (default 0: unchanged).** For a full + sliding-window model the host tiers follow the device ratio (`--swa-full-tokens-ratio`). A prefix hit needs the trailing sliding window of the match point on the device or on the host, so a host sliding-window tier sized by the device ratio limits prefix hits while the host has room. The flag sizes the host tiers as if the device pool had used that ratio; the host total stays `--hicache-size` and every device pool is unchanged. Ignored when the pools carry an explicit `host_capacity_bytes` or the device already holds at least that much sliding window.
- **`--layernorm-sp-min-tokens` (default 0: unchanged).** With `--enable-layernorm-sp` every extend runs sequence-parallel, and the SP collectives cost about the same per layer whatever the pass size, so small extends (short follow-up turns, small chunks, prefix-cache hits) can be slower than the replicated path decode already uses. A pass runs SP only above the threshold. `layernorm_sp.runs_sp(forward_mode, num_tokens)` now requires the pass's token count and every caller passes it (model entry, layer-boundary entry, DFLASH aux-tap gather, the input-embeds exit and `maybe_exit_gather`), so the entry and every exit take the same decision; the threshold is read from the parallel config bag. Resolution accepts only a threshold that is a captured prefill CUDA graph bucket or at/above the largest one, because a replayed graph decides on its bucket size while the exit gather outside the graph sees the real count; with prefill graphs off any value is accepted, and the flag without `--enable-layernorm-sp` is refused.
- **Reject sampling at small batch (automatic).** `speculative_sampling_classic_kernel` runs one program per request and scans the whole vocabulary twice, so at small batch the device is mostly idle. Below the multiprocessor count (block verification off, more than one vocabulary tile) a split path runs the same arithmetic over (requests x vocabulary tiles) and reproduces the stock outputs bit for bit; the stock kernel is unchanged. CUDA-graph safe: scratch growth is skipped during capture and falls back to stock.
- **`--speculative-overlap-ctx-projection` (DFLASH, default off).** Projects the verify hidden states into the draft's context features on a side stream as soon as the verify forward returns, overlapping accept and sampling. Same call on the same tensor; joined where the result is first used; capture, empty batches and any side-stream failure take the inline path.

New server arguments, all documented in `server_arguments.mdx`:

| flag | default | effect at the default |
|--|--|--|
| `--hicache-swa-host-ratio` | `0.0` | stock host split |
| `--layernorm-sp-min-tokens` | `0` | every extend runs SP, as today |
| `--speculative-overlap-ctx-projection` | `False` | inline projection, as today |

Reviewer notes:

- `layernorm_sp.runs_sp` now requires `num_tokens`; all in-tree callers pass it. Out-of-tree code that calls it (kernel plugins) must pass the pass's row count.
- When HiCache auto-sizing runs inside the build, its own `host_memory_budget_scope` nests inside the new one and books against the auto-size budget; the new log line then reports what the outer scope saw.
- The reject-sampling split helpers keep the stock kernel's local names (`last_accepted_global_idx`, `all_drafts_accepted`) so the two read side by side; the speculative naming rules would rename both, which is left to a separate change.
- The snapshot's barriers run on the world group's CPU group, which every rank reaches once per KV cache build (only the node-local ranks need to agree; a node-local group would be enough).

## Accuracy Tests

- Reject-sampling split: `test/registered/kernels/ops/speculative/test_reject_sampling_split.py` compares every output buffer bit for bit with the stock kernel across batch, chain depth and vocabulary size (incl. 129280): 50 passed on GPU.
- Ctx-projection overlap: same call on the same tensor; `test/registered/unit/spec/test_dflash_ctx_projection_overlap.py` 4 passed on GPU.
- `--layernorm-sp-min-tokens`: every pass computes exactly one of the two existing paths (SP or replicated); `test_layernorm_sp.py` checks that the entry and every exit take the same decision.
- NVFP4 hybrid SWA KV: `test_swa_pool_global_layer_id.py` pins the per-layer dispatch on an interleaved layout, where the local index and the global layer id differ for every layer but the first.
- End to end: with all flags on, the deployment these changes were tuned for reproduces the throughput, latency and speculative acceptance length of the out-of-tree implementation of the same changes, within run-to-run noise, at three concurrencies.
- GPU unit tests (run before the rebase onto current main and before the megakernel change moved to #47930), this branch vs main on one 4-GPU node, 21 files (the new and changed tests plus the existing unit tests of the touched modules: block verification, HiCache kernels, hybrid pool assembler, DFLASH logits / host sync / graph eligibility / OOT hooks, megakernel binding, CUDA graph setup, decode retraction, unified KV storage): every file passes, and the files present on both trees give the same counts.

## Speed Tests and Profiling

- The three new flags default to today's behavior. With them off, the only change on the serving path is the reject-sampling split at small batch.
- Reject-sampling split, stock vs split kernel time at small batch: not measured yet; it will be added to this PR.
- End to end with all flags on: parity with the out-of-tree implementation (see Accuracy Tests). The thresholds are deployment specific; `--layernorm-sp-min-tokens` should be the captured bucket nearest the measured SP / replicated crossover.
