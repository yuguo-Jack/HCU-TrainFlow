# [ROCm] Add DeepSeek-V4 DSpark speculative decoding support for  AMD GPU(MI350X / MI355X, gfx950)

[Upstream PR](https://github.com/sgl-project/sglang/pull/31026) · state: closed · merged: False

## Original PR description

## Summary
This PR is now a small follow-up on top of the DSpark implementation that already landed in `main` via #30261. It keeps the ROCm/AMD DeepSeek V4 DSpark fixes that were still missing after rebasing the branch onto current `main`.

- Fix DeepSeek V4 HIP target-verify metadata to use the active DSpark draft token count instead of the static configured speculative token count.
- Prepare DSpark KV-injection prefill position metadata before the target prefill forward so the correct cache locations and hidden states are used.
- Stage DSpark prefill `extend_lens` / `prefix_lens` through pinned CPU tensors before non-blocking transfer to the AMD GPU device, avoiding extra synchronization in the prefill path.

The earlier large DSpark implementation commit was dropped from this PR because the equivalent newer implementation is already present on `main`.

Calling `.min()` and `.sum()` on `layout.verify_lens` (which is a GPU tensor) and casting them to `int` triggers synchronous device-to-host transfers, causing a CPU-GPU sync bottleneck during the hot forward path. Since `layout.verify_lens_cpu` is already available as a CPU list, you can perform these assertions entirely on the CPU to avoid any overhead.

```suggestion
        if layout.verify_lens_cpu is not None:
            assert min(layout.verify_lens_cpu) >= 1
            assert layout.total_verify_tokens == sum(layout.verify_lens_cpu)
```

- gemini-code-assist[bot] · comment · 2026-07-13T12:33:38Z · [source](https://github.com/sgl-project/sglang/pull/31026#discussion_r3570643317)

File: `python/sglang/srt/speculative/dspark_components/kernels/causal_swa_page_indices.py` · line None

![high](https://www.gstatic.com/codereviewagent/high-priority.svg)

On AMD/ROCm, the LLVM backend can be highly sensitive to out-of-bounds pointer arithmetic, even when the memory access is masked out. Since `full_loc` is loaded with `other=-1` when `valid` is False, `full_to_swa_ptr + full_loc` results in `full_to_swa_ptr - 1`, which is an out-of-bounds pointer. To prevent potential GPU page faults or undefined behavior, clamp the offset to a valid index (e.g., `0`) when `valid` is False.

```suggestion
        swa = tl.load(full_to_swa_ptr + tl.where(valid, full_loc, 0), mask=valid, other=-1).to(tl.int32)
```
