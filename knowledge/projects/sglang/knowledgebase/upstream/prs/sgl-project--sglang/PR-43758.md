# [RL] Return a failed weight update when the cache flush is refused

[Upstream PR](https://github.com/sgl-project/sglang/pull/43758) · state: closed · merged: True

## Original PR description

## Motivation

After loading new weights, every `update_weights_*` path flushes the cache and asserts that the flush succeeded. The flush is refused while requests are running or queued, which is the normal state after `pause_generation(mode="in_place")`, or after a retract pause that left requests behind. The assert then kills the scheduler, and with it the whole server.

## Modifications

- `SchedulerWeightUpdaterManager.flush_cache_after_weight_update` returns a failed result with a message when the flush is refused, instead of asserting. The disk, distributed, tensor and IPC paths pass it through as `success=False`.
- The new weights stay loaded and their version is recorded, as before; only the result changes from a crash to a failed call that says to retract or finish the requests and call `/flush_cache`.

## Checks

- Qwen3-0.6B, one request running, `pause_generation(mode="in_place")`, then `update_weights_from_disk`:
  - main: the scheduler exits on `Cache flush failed after updating weights` and the server is gone.
  - This PR: the update returns 400 with the message; `continue_generation` and `/health` succeed.
- Unit tests under `test/registered/unit/managers/scheduler_components/` and `managers/`: same results as main.
