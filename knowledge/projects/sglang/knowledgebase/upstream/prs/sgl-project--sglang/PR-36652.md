## Motivation

`--dsv4-attn-backend trtllm` runs DeepSeek-V4 / V4.1 sparse attention through FlashInfer's trtllm-gen sparse MLA kernel (added in #30805). This PR makes that backend accurate with every feature DeepSeek-V4.1 serving uses (DSpark speculative decoding, DP attention, decoder and encoder SWA bounded replay, CUDA graphs) and removes the work SGLang did around each kernel call, so the backend is faster end to end, not only per call.

- **Metadata in the kernel's own form**, as TRT-LLM integrates it: one persistent table per step holds every token's sliding-window and sparse KV slots, and decode, verify, draft-extend and prefill all pass one query row per token.
- **KV cache in the uniform FP8 layout the kernel reads**, written by SGLang's fused norm-RoPE kernels, which also emit the FP8 query directly.
- **Little glue around each call:** a persistent counter buffer instead of a zero-fill before every call, the DSpark draft step's metadata inside its CUDA graph, KV stores that read strided inputs instead of copies, and an indexer that writes its top-k straight into the shared table.

**Impact**

- **Accuracy: unchanged vs FlashMLA.** GPQA-Diamond 0.907 vs 0.909; paired difference -0.25 points, 95% CI [-1.39, +0.76]; DSpark accept length 3.23 vs 3.26 (DeepSeek-V4.1-Flash, GB300 TP4, sgl-eval, 198 questions x 4, real acceptance). The registered GB300 e2e tests pass.
- **Performance: faster than FlashMLA at aggregated TP, and faster than main's trtllm-gen at every point measured.** Per-request decode time on published InferenceX AgentX recipes, DeepSeek-V4.1-Flash with DSpark (negative = this PR is faster):

  | Point | vs FlashMLA | vs main's trtllm-gen |
  |---|---|---|
  | GB300 TP4 c1 | -0.95% | |
  | GB300 TP4 c16 | -0.8% to -1.3% | |
  | B300 TP2 c48 | -1.7% | -2.2% |
  | GB200 TP4 c32 | -2.2% | -5.1% |
  | B300 DEP2 c64 | | -2.5% |

  Against FlashMLA Mega, the published backend at the DEP points: ahead at GB300 DEP2 c64 (output tok/s +2.5% to +4.6%), behind at B300 DEP2 c64 (p90 interactivity -2.3%, output tok/s tie).

## Modifications

**+874 / −506 runtime code (20 files), +895 / −113 tests (7 files), +6 docs (1 file).** Kernel changes are edits to existing SGLang JIT kernels (fused norm-RoPE and KV store, top-k, metadata); no new kernels.

- **trtllm backend** (`deepseek_v4_trtllm_backend.py`): the persistent table pool, refreshed per step (the indexed tail only on index-source layers); dense per-token calls; a persistent multi-CTA counter buffer; PDL off only for an attention launch right after a tail refresh (the kernel reads lengths before `griddepcontrol.wait`); decode tables sized for the adaptive-spec max draft width; `--dsv4-trtllm-flashinfer-backend {trtllm-gen,auto}` (default `trtllm-gen`; `auto` lets FlashInfer pick and logs the result at startup).
- **Shared DeepSeek-V4 metadata** (`deepseek_v4_backend.py`, `dsv4/metadata.py`, `metadata_kernel.py`): trtllm tables for speculative decoding and DP attention built inside the captured metadata graphs, the DSpark draft step included; late-layer tail tables for decoder SWA bounded replay; encoder SWA bounded replay; the low-ratio metadata kernel writes trtllm's lengths; no per-step padding or refills of table rows the kernel never reads; no self-copies of pool-backed tables.
- **KV store and query** (`fused_norm_rope_v2.cuh`, `main_norm_rope.cuh`, `norm_rope.py`, `compress.py`, `compressor_v2.py`, `deepseek_v4.py`): a uniform-FP8 store variant of the fused norm-RoPE and compressor kernels, replacing the separate `compressor_trtllm.py` path; FP8 queries from the fused query norm-RoPE kernel; no FlashMLA query-head padding on the trtllm path.
- **KV pools** (`deepseek_v4_memory_pool.py`, `dsv41_request_window.py`, `dsv4_request_window_copy.py`): uniform-FP8 pools, including the encoder-replay request window.
- **Indexer and DSpark** (`topk_v2.cuh`, `deepseek_v4_dspark.py`): the top-k kernel takes a row stride so it writes the shared table in place; the DSpark commit-KV store reads the stacked projection's strided slices.
- **Tests:** counter buffer and the PDL edge in a captured graph, bitwise metadata and in-place-tail checks, the uniform-FP8 fused store, and a GB300 encoder-replay e2e test; each fails on a mutant of the code it covers. The stale manual VarSeq prefill test is removed.

**Issue**
`trtllm_seq_lens_req` is the last token's causal length. The draft-extend CUDA graph fills unused request slots with `seq_len = 1` (`get_cuda_graph_seq_len_fill_value`), so padded requests enter varlen mode with `seq_lens = 1` and `max_q_len = num_tokens_per_req`. FlashInfer requires `seq_lens >= q_len` to derive the SWA window. With `FLASHINFER_VALIDATE_INPUTS=1` it raises `ValueError`; otherwise the kernel runs outside its contract.

**Example**
A draft-extend graph captured at bs=8 replays 5 live requests with q_len=4. The 3 pad requests pass `seq_lens=1`.

**Fix**
Clamp here: `self.seq_lens_casual[q_len - 1 :: q_len].clamp(min=q_len).contiguous()`. Live requests already satisfy it because draft extend adds `num_draft_tokens` to `seq_lens`, so only pad rows change.
