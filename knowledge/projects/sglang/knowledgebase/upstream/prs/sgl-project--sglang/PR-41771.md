# [Fix] dp-controller: Keep one input_embeds request from killing a DP server under total_tokens

[Upstream PR](https://github.com/sgl-project/sglang/pull/41771) · state: closed · merged: True

## Original PR description

## Motivation

With `--dp-size > 1` and `--load-balance-method total_tokens`, a single `/generate` request that passes `input_embeds` takes the whole server down. Such a request carries `input_ids=None`, so `len(req.input_ids)` in `total_tokens_scheduler` raises `TypeError`. The exception escapes the DP controller's `event_loop`, `run_data_parallel_controller_process` sends SIGQUIT to the parent, and every in-flight request is lost. `input_embeds` is a documented `/generate` field, so an ordinary client can hit this.

## Modifications

`total_tokens_scheduler` sizes an `input_embeds` request by its number of embedding rows, which is how the scheduler sizes it too.

An earlier version of this PR also dispatched PD requests without `bootstrap_room` round-robin instead of asserting. Reaching that path needs a client that bypasses the router, so I dropped it and kept the assert. Other exceptions in the controller still take the server down; a general reject path would need a socket back to every frontend, so this PR fixes only this trigger.
