# [Router] Respect cache_salt in KV-aware routing

[Upstream PR](https://github.com/sgl-project/sglang/pull/42247) · state: closed · merged: False

## Original PR description

## Motivation

SGLang workers include `cache_salt` in KV-event block hashes, but the experimental router hashes requests without that namespace. With identical prompt tokens cached under different salts, a salted request can select a worker holding the unsalted prefix instead of the worker holding its matching prefix.

This fixes request-side routing against the existing event-hash contract introduced by #30827. Related to #39991; the event schema and the broader RFC are outside this change. The earlier #28931 used the old `extra_key` semantics and was closed in favor of #30827, leaving router gaps for focused follow-ups.

## Modifications

- Seed salted unigram and bigram hash chains with the engine's existing `sglang-cache-salt-v1` digest. Preserve unsalted hashes and treat missing, null, and empty salts consistently with the engine.
- Carry the request namespace through legacy and reorg routing, local radix-tree and remote indexer lookups, prefix-cache scoring/filtering, and local DP-rank selection.
- Recognize single-element salt arrays used by parallel sampling (`n > 1`). Preserve prompt tokens for length checks and forward the original salt value to the engine.
- Add routing regressions, bucket-boundary coverage, hash parity fixtures, and a short README description. Embedding lookups retain the engine's unsalted behavior.

```bash
cargo test --locked --lib --test component --test proxy -- --skip parity_matrix
cargo fmt --all -- --check

```

- **1,033 unit tests, 127 component tests, and 183 proxy tests passed.** The filter follows the router CPU CI command and excludes two tokenizer parity tests requiring model tokenizer snapshots unavailable in this environment.
- Regression tests failed before the fixes and passed afterward. Namespace coverage includes 320 HTTP request combinations across local/remote prefix sources, legacy/reorg routing, and unigram/bigram models.
- Fixture regeneration, Python Ruff/isort checks, and `git diff --check` passed.
- Additional CPU audit checked 23 fixture cases, 200 randomized cases, and 96 segmented radix chains against the unchanged engine Python hashing functions and compiled native C++ implementation. The Python functions were loaded in isolation to avoid GPU-dependent imports; this was not a full engine launch.
- Temporary audit cases also verified PD forwarding to both workers and single-element array salts in DP-rank selection.
