# [Perf] DSv4.1: Fused low-latency TP4 decode chain on SM100

## Summary

Adds a fused low-latency decode chain for DeepSeek-V4.1-Flash at TP4 on SM100 (B200/B300), taking each layer's attention sublayer from the query to the MoE input in four PDL-chained kernels:

- `decode_attention`: sparse decode attention over the V4.1 fp8 SWA cache plus the fp8/fp4 indexed cache, inverse RoPE fused into the epilogue, output in FlashMLA MegaAttention's mega-fp8 format (replaces `flash_mla_mega_decode` and its `pack_query`).
- `wo_a_fp8`: the wo_a GEMM on that output with the same `quantize_wo_a` weights `fp8_einsum` uses, emitting the MXFP8 input of wo_b (replaces DeepGEMM `fp8_einsum` + the activation quant). It prefetches its weight before `griddepcontrol.wait`.
- `wo_b_fp8` + `all_reduce_mhc`: wo_b (FlashInfer MXFP8 weight layout, `weight_scale_inv_swizzled`) pushes its rows straight into the CustomAllReduceV2 push plane (unicast or multicast); the consumer drains it with the mHC post, the pre-collapse and the RMSNorm, with the arithmetic of `all_reduce_mhc_post_combine_norm` (replaces wo_b + `all_reduce_mhc_post_combine_norm`).

New pieces:
- Kernels under `kernels/jit/csrc/deepseek_v4/low_latency/`, Python ops under `kernels/ops/attention/dsv4/low_latency/`.
- `include/sgl_kernel/tcgen05.cuh`: tcgen05 wrappers and UMMA descriptors, `TCGen05Common` plus `TCGen05<kCtaGroup>` for cta_group 1/2.
- `srt/models/deepseek_v4_low_latency.py`: `LowLatencyChain`, built once per layer after weight loading when every static precondition holds (SM100, DSv4.1, mega attention, TP4 with attn TP == TP and no attn DP/CP, FlashInfer MXFP8 wo_b, a registered push plane, JIT nvcc >= 13.2); used for decode / target-verify batches of at most 64 tokens, otherwise the existing path runs.
- `SGLANG_OPT_DSV41_LOW_LATENCY_DECODE` (default on) to opt out.

## Validation

4x B300 (TP4, DSpark, cookbook low-latency config): sgl-eval GSM8K unchanged vs the existing path; kernel-level correctness checked against the replaced kernels on B200/B300.
