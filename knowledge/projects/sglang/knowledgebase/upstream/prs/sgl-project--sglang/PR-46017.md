# [Doc] cookbook: Qwen3.5 MI355X FP8 agentic uses HiCache write_through on the v0.5.22 image

[Upstream PR](https://github.com/sgl-project/sglang/pull/46017) · state: closed · merged: True

## Original PR description

## Motivation

The MI355X Qwen3.5-397B-A17B-FP8 AgentX run in InferenceX was updated in [SemiAnalysisAI/InferenceX#4374](https://github.com/SemiAnalysisAI/InferenceX/pull/4374): HiCache write policy `write_through_selective` -> `write_through`, on a newer image. At concurrency 80 the AgentX cache hit rate moves from 51% to about 95%. This follows up on #41849 so the cookbook matches the official run.

## Modifications

`docs/src/snippets/autoregressive/qwen35-deployment.jsx`

- 397B + MI355X + FP8 + HiCache now emits `--hicache-write-policy write_through` instead of `write_through_selective`. All other flags are unchanged.

`docs/cookbook/autoregressive/Qwen/Qwen3.5.mdx`

- MI355X `docker pull`: `v0.5.20-rocm720-mi35x-20260927` -> `v0.5.22-rocm720-mi35x-20261020` (the tag used in #4374).
- MI300X / MI325X `docker pull`: `v0.5.15.post1-rocm720-mi30x-20260715` -> `v0.5.22-rocm720-mi30x-20261020` (same date as MI355X).
- Update the "KV cache offloading (397B FP8 on MI355X)" bullet to the new write policy.

The generated command for every other hardware, precision and toggle combination is unchanged.

## Accuracy Tests

Documentation-only; no runtime code path is touched.

## Benchmarking and Profiling

No change in this PR. Numbers come from the InferenceX run in #4374 (TP4 HiCache, concurrency 80):

| Image | hicache-write-policy | Cache hit rate |
|---|---|---|
| `v0.5.20-rocm720-mi35x-20260929` | `write_through_selective` | 51% |
| `v0.5.22-rocm720-mi35x-20261020` | `write_through` | ~95% |
