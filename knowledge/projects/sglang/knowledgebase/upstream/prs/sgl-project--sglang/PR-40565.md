# [Fix] hicache: Fail fast on a null pointer from the Mooncake host allocator

[Upstream PR](https://github.com/sgl-project/sglang/pull/40565) · state: open · merged: False

## Original PR description

Fixes #40564

## Motivation

`MooncakeHostTensorAllocator.allocate` feeds the raw return value of
`MooncakeHostMemAllocator.alloc(size)` into `ctypes.from_address` and
`torch.frombuffer` without checking it. When the underlying allocator cannot map the
host segment it returns a null pointer, and both of those happily accept address 0, so
`allocate()` returns a normal-looking tensor whose `data_ptr()` is `0`.

Nothing fails where the allocation actually failed. The error surfaces much later and
far from its cause: pinning the host pool calls `cudaHostRegister` on address 0 and
gets `cudaErrorInvalidValue`, or the process segfaults on the first access to the
buffer. Neither message mentions host memory, so in a prefill deployment we spent a
long detour on the CUDA side before identifying the host memory shortage as the real
problem.

## Modifications

- `python/sglang/srt/mem_cache/storage/mooncake_store/mooncake_store.py`: check
  `ptr_int` right after `self.allocator.alloc(size)` and raise a `RuntimeError` naming
  the requested size in both bytes and GB, pointing at host memory availability and
  the mooncake allocator logs. Nothing else in the allocation path changes; a
  successful allocation behaves exactly as before.
- `test/registered/unit/mem_cache/test_mooncake_host_allocator.py`: new CPU unit test.

## Accuracy Tests

Not applicable — this is a pure error path, and a successful allocation is untouched,
so no model output changes.

A CPU unit test covers the new behaviour. It bypasses `__init__` with `__new__` (so it
needs neither a mooncake install nor a mappable host segment) and mocks the underlying
allocator into returning `0` and `None`, asserting that `allocate()` raises a
`RuntimeError` whose message carries the requested size:

```
$ python -m pytest test/registered/unit/mem_cache/test_mooncake_host_allocator.py -q
1 passed, 2 subtests passed in 4.36s
```

The existing mooncake unit tests in `test/registered/unit/mem_cache/`
(`test_mooncake_ssd_offload_path.py`, `test_mooncake_store_config.py`,
`test_mooncake_tenant_config.py`, `test_mooncake_group_semantics.py`,
`test_mooncake_standalone_dummy_mamba.py`) still pass: 32 passed before the change,
33 passed with the new test added.

## Speed Tests and Profiling

Not applicable. The added check is a single truthiness test on an integer that runs
once per host pool allocation, and it only changes behaviour on the failure path.
