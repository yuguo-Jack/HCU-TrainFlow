## Motivation

The HIP mHC boundary first launch (Triton, #41021) uses one 16-row tile for every row count; at decode batch sizes
(M = bs x 6, 96-1023 rows) a wider tile is faster.

## Modifications

- 32-row tile (4 warps, 2 stages, kpack 2, 16x16 MFMA) from 192 rows, or from 96 when M is a multiple of 32.
- Each copy's weight tile is loaded where it is used instead of prefetching all four.
- Both tiles compile with FMA contraction off, so outputs are bitwise identical to before and to the gfx950 HIP kernel.
- `SGLANG_HIP_MHC_BOUNDARY_WIDE_TILE` (default on) to fall back to the 16-row tile.

## Accuracy Tests

Bitwise identical to main at M 8-1023 (post+combine and stats-only); test_hc_boundary_hip passes.

## Speed Tests and Profiling

MI355X, graph-replayed, post+combine: M 96 8.5 -> 7.8 us, 384 21.6 -> 19.2 us, 512 26.7 -> 22.3 us, 1023 44.3 -> 39.4 us
(M <= 48 unchanged; the stats-only form is -3..-12% except M 240 / 336, +9% / +4%). DeepSeek-V4.1-Flash TP2 decode bs 64: boundary 23.0 -> 20.6 us per call, -0.19 ms per step.
