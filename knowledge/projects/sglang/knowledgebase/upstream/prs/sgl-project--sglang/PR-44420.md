# [Refactor] scheduler: Check the prefill budget at the admission loop head; drop a redundant PD gate

[Upstream PR](https://github.com/sgl-project/sglang/pull/44420) · state: closed · merged: True

## Original PR description

Admission-loop hygiene in `Scheduler._get_new_batch_prefill_raw`; no change in which requests are admitted.

- Check the pass budget at the head of the waiting-queue loop: when `adder.budget_state()` is `OTHER`, stop before examining another candidate. The loop already stopped on the `OTHER` verdict that `add_one_req` returns after each admission; a resumed chunk or the mixed-chunk reservation for running decode rows could spend the budget before the first candidate, which then ran `init_next_round_input`, the storage-prefetch pop, and buffer staging only to be rejected with `extend_len <= 0`. That work was harmless (each side effect is undone on rejection or repeated next pass), and since #39283 the rejection comes before any host load-back, which was the cost #35642 reported. `NO_TOKEN` still runs the loop, so no new place sets `batch_is_full`.
- Drop the PD-prefill gate `len(can_run_list) - num_held_rows >= req_to_token_pool.available_size()`. It was added in #6507 when `get_num_allocatable_reqs` counted pool rows only under PP; since #24359 the pool term applies in every mode, and `min(pp_budget, max(available + held - pending, 0)) <= available + held`, so the main gate is full whenever this one is.
- In `get_num_allocatable_reqs`, compute the pool term once as `row_budget = max(available_size() + num_held_rows - pending_member_rows, 0)` instead of reassigning `available`, which read as the pool's free rows after #44401 added the held rows to it; the value is unchanged.
- Condense the comment on the chunked-request exemption from the allocatable check into three lines with the same claims.
- Give the fake adder in `test_scheduler_held_row_admission.py` the `budget_state` the loop now reads.

Related: #35642 and #35645, both closed; the cost #35642 reported was removed by #39283, and this keeps only the loop rule.
