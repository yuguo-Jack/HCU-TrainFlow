# [NPU] Pin CPU-offloaded weights for host-to-device copies

[Upstream PR](https://github.com/sgl-project/sglang/pull/43824) · state: open · merged: False

## Original PR description

## Problem and change

OffloaderV1 allocates pageable host storage on the evaluated NPU stack because the platform pinned-memory predicate returns false. A real Qwen3-ASR offloaded norm weight (BF16, 128 elements, 256 bytes) then fails its CPU-to-NPU copy during graph capture.

Request pinned host storage when the original parameter device is NPU. This is a **one-line product change** in the existing offloader. It preserves the existing non-NPU policy, parameter layout, dtype, budget granularity and weight-copy/forward logic. No model code, attention backend, state_dict implementation, operator registration or mathematical kernel is changed.

The PR is now deliberately narrowed to basic CPU-offload adaptation. The former compiler/FIA/metadata changes have been removed from its current diff; their commits and evidence remain in history. The companion kernel PR is no longer required for this delivery.

## Ownership and scope

This is an NPU adaptation in the shared OffloaderV1 allocation path. Qwen3-ASR is the reproducing and evaluated model, not the owner of a model-specific defect. Other NPU models using this path receive the same allocation policy; the recorded single-model validation is not all-model acceptance. `enable_torch_compile=false` is an explicit launch configuration, not a behavior changed by this patch. Weights return to the NPU for computation.

## Validation and supported conditions

- The submitted file matches the historical pin-only candidate SHA256 9013301d64d73f1c1a3ac04797bd3744f15792b4d9d5d5302d2b54e7380d1f7b, based on release/v0.5.20 at 94602c9c2b7cbdb8efd5c52802dac6a1c180089e.
- Historical Qwen3-ASR-0.6B, torch/torch_npu 2.10 and CANN 9.0: graph-disabled offload 0/4 each completed 20 requests; prefill/decode graphs enabled with **enable_torch_compile=false** also completed 20 requests per arm. Both graph-enabled arms returned identical response bytes on the same 20 input WAVs, each with 2/216 word edits. These are existing measurements, not reruns for this revision.
- Graph-enabled weight-loading memory: 1.63 GB at offload 0 and 0.78 GB at offload 4. This is a loading snapshot, not peak memory or exactly 4 GB of weights.
- Four portable policy regressions execute the actual OffloaderV1 source with recording allocation boundaries: original version fails the NPU pinning test (3 pass, 1 fail); this exact candidate passes all four. Non-NPU behavior, layout/copy selection, budget granularity, zero budget and CPU-resident modules are covered. These tests do not replace the real NPU graph evidence.

## Known limitation

Default torch.compile plus decode graph capture still fails in the evaluated stack, including with offload 0. That independent compatibility work is tracked in https://github.com/sgl-project/sglang/issues/43958. Do not claim that this one-line PR fixes the compiled attention/launcher path, or reuse later broad-candidate compile-enabled performance as measurements of this revision.

This is a scoped draft against the measured release. It does not claim all-model acceptance, current-main integration, full upstream CI or performance optimization. No NPU/model experiments were started for this scope reduction.
