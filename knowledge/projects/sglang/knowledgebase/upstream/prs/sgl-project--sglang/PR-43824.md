# [Fix] [NPU] Support CPU weight offload with pinned host memory

[Upstream PR](https://github.com/sgl-project/sglang/pull/43824) · state: open · merged: False

## Original PR description

## Motivation

`cpu_offload_gb` reduces device memory usage by keeping part of the model weights in CPU memory and copying them back to the device for computation. This PR enables that path for NPU inference with graph capture by allocating pinned CPU storage for the offloaded weights.

`OffloaderV1` currently chooses pinned storage solely through `is_pin_memory_available()`, which returns `False` on the evaluated NPU stack. The resulting pageable CPU storage causes the weight copy back to NPU to fail during graph capture. Requesting pinned storage at allocation time allows the existing CPU-to-NPU transfer to run in the tested graph path.

## Modifications

In `OffloaderV1.maybe_offload_to_cpu`, request pinned CPU storage when the parameter's original device is NPU:

```diff
- pin_memory = is_pin_memory_available()
+ pin_memory = is_pin_memory_available() or device.type == "npu"
```

This applies the allocation policy in the shared offloader, where the CPU storage is created. Weights are still copied back to NPU by the existing forward wrapper. Other devices continue to use the platform's pinned-memory decision.

Add three policy tests covering NPU pinning, the existing non-NPU policy, and the zero-budget/CPU-resident cases. They execute the actual `OffloaderV1` class with mocked allocations, so they can run without an NPU.

## Validation

On main at `d0a75654368a`, the policy tests pass with the patch (**3 passed**). Against the unpatched main implementation, the NPU pinning case fails because the allocation receives `pin_memory=False`.

Existing device validation used Qwen3-ASR-0.6B (BF16), SGLang `release/v0.5.20` at `94602c9c2b7c`, PyTorch/torch_npu 2.10, and CANN 9.0. The release implementation with this pinned-storage change is preserved in [the evaluated implementation](https://github.com/celestial-micha/sglang/commit/aab8724636639d109827536de241cab3d9de3c3b). Each configuration processed the same 20 audio inputs:

| Configuration | `cpu_offload_gb=0` | `cpu_offload_gb=4` | Paired transcriptions |
| --- | --- | --- | --- |
| Graphs disabled | 20/20 completed | 20/20 completed | 20/20 identical |
| Prefill/decode graphs enabled, `enable_torch_compile=False` | 20/20 completed | 20/20 completed | 20/20 identical |

The graph-enabled runs recorded successful graph replay. In that pair, weight-loading NPU memory decreased from **1.63 GB to 0.78 GB**, while median request latency increased from **0.171 s to 0.412 s**. The result demonstrates the intended memory saving and its transfer cost; the memory values are loading snapshots.

The graph-enabled validation explicitly disabled `torch.compile`. Compile-enabled decode graph capture still fails in this stack, including without offload, and is tracked in [#43958](https://github.com/sgl-project/sglang/issues/43958).

The device measurements above apply to the earlier release implementation. Main has since changed weight-residency and transfer handling in the offloader; this PR preserves those changes, and NPU device regression on the rebased implementation remains pending. The policy tests were rerun on the main-based patch. Upstream CI is pending; the NPU workflow requires a maintainer to add the `run-ci` label.
