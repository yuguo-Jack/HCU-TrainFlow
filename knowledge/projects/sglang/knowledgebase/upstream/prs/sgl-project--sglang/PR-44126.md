# Skip empty scheduler time stats in streamed outputs

[Upstream PR](https://github.com/sgl-project/sglang/pull/44126) · state: open · merged: False

## Original PR description

## Motivation
`SchedulerReqTimeStats.__getstate__` returns `{}` unless metrics are enabled or the object carries timing data. Every `BatchTokenIDOutput` still ships one per request anyway. The detokenizer and the `TokenizerManager` then rebuild each of those empty objects through Python `__setstate__`, once per request per step. With metrics off (the default), that is per-token work on the tokenizer manager's event loop.

## Modifications
- `_GenerationStreamAccumulator` records whether any accepted request's time stats carry data, and sends `time_stats=None` otherwise. Every consumer already handles `None`: the tokenizer manager's metrics and first-token paths, the detokenizer passthrough, and the multi-tokenizer router.
- `SchedulerReqTimeStats.has_wire_state()` is now the single condition used by both `__getstate__` and the accumulator.

When metrics are on, nothing changes.

## Accuracy Tests
N/A. Model outputs are unchanged.

## Speed Tests and Profiling
Setup:
- `sgl.Engine` with default flags (detokenizer on, metrics off).
- The scheduler process is replaced by a GPU-free stand-in that emits real `BatchTokenIDOutput` messages. The `TokenizerManager` and detokenizer are unmodified.
- Grace CPU (GB200 node), Python 3.12, 128 input / 1024 output tokens, one token per 8 ms per request, 1024 concurrent streams.
