# [Fix] deepseek-v3.1: Fix quadratic regex scans in the tool-call parser

[Upstream PR](https://github.com/sgl-project/sglang/pull/42593) · state: open · merged: False

## Original PR description

## Motivation

`DeepSeekV31Detector` (`deepseekv31`) scans model output with patterns that go quadratic when `<｜tool▁call▁end｜>` never arrives:

1. `parse_streaming_increment` runs `re.search(r"<｜tool▁call▁begin｜>(.*)<｜tool▁sep｜>(.*?)(<｜tool▁call▁end｜>|$)")` over the **whole buffer on every chunk**. With repeated `<｜tool▁call▁begin｜>` tokens and no separator, each call retries the greedy scan from every begin token.
2. `detect_and_parse` uses `re.findall(begin.*?end)`, rescanning to the end from every begin token, then a greedy detail pattern per block.

| Input | Before | After |
|---|---|---|
| 130 KB, one streaming call | 9.9 s | ~0 |
| 30 KB stream in 64-char (multi-token / MTP) chunks | 0.66 s worst chunk, **84 s total** | 0.1 ms worst chunk |
| 130 KB, non-stream | 9.4 s | ~0 |

Tool-call parsing runs synchronously on the tokenizer manager's event loop, so one such response stalls every in-flight request. Found with an Atheris fuzzing harness that records per-input parse time.

## Modifications

The three patterns are replaced with linear `find` / `rfind` helpers that return the same groups:
- `_iter_call_blocks`: `begin.*?end` spans.
- `_search_complete_call`: `begin(.*)sep(.*)end`. The match starts at the first begin, and the greedy groups end at the last end token and at the last separator before it.
- `_search_partial_call`: `begin(.*)sep(.*?)(end|$)`. The name group ends at the last separator. The lazy argument group stops at the first end token, else at `$`, which, as in `re`, is end of text or just before a trailing newline.

The unused regex attributes and `import re` are removed. A new `TestDeepSeekV31Detector` regression test fails on `main` and passes here (there was no V3.1 test class).

## Accuracy Tests

- Helpers vs the original patterns on 300k random token strings: identical.
- Differential test of `main` vs patched detector (20k random + 20k mutated well-formed inputs, streaming under random re-chunking and non-streaming): **0 mismatches** (11.4k produced parsed calls).
- `test/registered/unit/function_call/`: 630 passed.
