# [diffusion] comfyui: resolve Flux guidance_embeds from checkpoint keys instead of assuming True

[Upstream PR](https://github.com/sgl-project/sglang/pull/43394) · state: closed · merged: False

## Original PR description

Fixes #43395

## Summary

ComfyUI-mode Flux loading always set `guidance_embeds=True`, assuming every checkpoint has `guidance_in.*` weights. FLUX.1-schnell checkpoints don't have these, so the model gets a guidance embedder that never gets populated, and strict loading fails:

```
ValueError: New parameter 'time_text_embed.guidance_embedder.linear_1.weight' is not supported...
```

Now `guidance_embeds` is set based on whether the checkpoint actually has `guidance_in.in_layer.weight`, same as ComfyUI does. The skip logic in `_convert_weights` was already there for this but was never reachable until now.

## Test plan

- [x] Reproduced the error with a synthetic schnell-shaped checkpoint (no `guidance_in.*`) on CPU before the fix.
- [x] Added `test_comfyui_flux_guidance_embeds_follows_checkpoint_keys` and `test_comfyui_flux_schnell_checkpoint_loads_without_guidance_embedder` to `test_comfyui_profile.py` — fail on old code, pass with the fix.
- [x] Ran `test_comfyui_profile.py` and sibling `test_comfyui_*` tests, all green.
- [x] Loaded the real `black-forest-labs/FLUX.1-schnell` checkpoint through `FluxPipeline(comfyui_mode=True)` on an A100 — loads cleanly (11.89B params), no guidance embedder created.
