# [Feat] afd: add the attention-FFN disaggregation framework

[Upstream PR](https://github.com/sgl-project/sglang/pull/45958) · state: open · merged: False

## Original PR description


## Motivation

Attention-FFN disaggregation (AFD) places attention and routed experts on separate GPU groups. This PR adds the execution framework for independently sized attention (A) and FFN (F) groups, including worker startup, model loading, request coordination, token dispatch, and output combination. One attention instance serves requests through the existing SGLang APIs while an FFN instance executes its routed experts.

This is the first integration step proposed in [RFC #45568](https://github.com/sgl-project/sglang/issues/45568), extracted from the complete implementation in [#45562](https://github.com/sgl-project/sglang/pull/45562).

## Modifications

- Add A/F roles, a typed startup handshake, and forward coordination. Validate model and layout compatibility and derive F's dispatch capacity from A's admission limits and rank mapping, preserving the native DeepEP capacity floor.
- Support FULL and SCATTERED layouts with unequal A/F rank counts. FULL sends complete expert inputs to the assigned F ranks and combines their partial outputs; SCATTERED forwards attention shards to F and uses native DeepEP for expert dispatch. Empty F ranks still participate in the required collectives.
- Keep request scheduling, KV cache, attention, routing, shared experts, and sampling on A. F executes routed experts through the existing MoE runners without an attention forward or KV cache. A skips loading target routed-expert weights.
- Integrate the Qwen2/3 MoE and DeepSeek V2/V4 model paths, preserving routed scaling and shared-expert output reduction. Add role/configuration validation and document the AFD server arguments.
- Provide NCCL point-to-point communication as the initial A/F transport, using a joint communicator separate from each instance's native process groups.

### Scope and usage

Configure A with `--afd-role attn --afd-ffn-addr <ffn-host>:<port>` and F with `--afd-role ffn`. Send generation requests to A. The A/F transport defaults to NCCL and does not require an AFD-specific component wheel. F uses the existing `none` or `deepep` MoE backend; A declares the same backend for layout agreement. Native DeepEP uses `auto` or `normal` mode. For BF16 DeepEP, select the `deep_gemm` runner explicitly.

This PR uses eager execution, fixed membership, and one A instance per F instance. Attention TP is one within each attention DP group. CUDA Graphs, microbatch overlap, multiple A instances, additional transports, Direct backends, and speculative decoding follow in separate PRs as outlined in the RFC.

## Accuracy Tests

Output consistency was checked on SM100 with Qwen3-30B-A3B BF16, using this PR's changes on upstream `6393e66b8649b4e6e22f2d94a933e69059192900`. Each configuration ran three serial prompts covering short and longer prefill, followed by 16 greedy decode tokens per prompt.

| AFD configuration | Colocated reference | Matching generated token IDs | Maximum absolute output-logprob difference |
| --- | --- | --- | --- |
| FULL A1/F2, Triton MoE | TP2, attention DP2, Triton MoE | 48 / 48 | 0 |
| SCATTERED A1/F2, native DeepEP | TP2/EP2, attention DP2, native DeepEP | 48 / 48 | 0 |

The FULL pair used deterministic inference and DP LM head. The SCATTERED pair used DeepEP `auto` with the `deep_gemm` runner. Logprob differences above were computed from the recorded responses.

### Regression coverage

CPU tests cover asymmetric dispatch and combination, scaling, empty-rank participation, capacity calculation, wire-protocol errors, and role-specific loading and startup. The end-to-end regression launches real A/F workers, checks readiness, and compares FULL A1/F2 token IDs against the colocated reference. It is registered in the additional four-GPU CI suite.

```bash
python test/registered/e2e/afd/test_afd_nccl.py
```

## Speed Tests and Profiling

This PR establishes the eager AFD execution framework. Performance optimizations and their measurements follow with CUDA Graphs, microbatch overlap, and Direct backends. The full-system measurements in #45562 remain tied to their recorded revisions.
