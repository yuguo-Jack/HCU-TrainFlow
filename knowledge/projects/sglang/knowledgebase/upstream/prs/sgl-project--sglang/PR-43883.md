# [Fix] docker: Install numactl in runtime images - needed for SGLANG_NUMA_BIND_V2

[Upstream PR](https://github.com/sgl-project/sglang/pull/43883) · state: closed · merged: True

## Original PR description

<!-- Thank you for your contribution! Please follow these guidelines to enhance your pull request. If anything is unclear, submit your PR and reach out to maintainers for assistance. Join our Slack community at https://slack.sglang.io to discuss further. -->

## Motivation

Sglang is configured to automatically bind worker process to their corresponding numa node when possible. With `SGLANG_NUMA_BIND_V2` (defailt on), this is done by launching the worker under `numactl`. The slim `-runtime` images do not have numactl installed, so this was silently failing and no numa binding was occuring.

Current behavior with `--log-level debug`:
```
[2026-10-12 11:10:26] numactl command not found, skipping NUMA node configuration for GPU. Install numactl (e.g., apt-get install numactl) to enable automatic NUMA binding.
```

With fix
```
[2026-10-12 11:11:40] mp.set_executable /opt/sglang/bin/python3 -> /tmp/sglang_temp_file_1791828700.5555336_4200524.sh (script='#!/bin/sh\nexec numactl --cpunodebind=0 --membind=0 /opt/sglang/bin/python3 "$@"', logical_gpu_id=0, physical_gpu_id=0, CUDA_VISIBLE_DEVICES=)
```

## Modifications

Install `numactl` in `runtime` images.
