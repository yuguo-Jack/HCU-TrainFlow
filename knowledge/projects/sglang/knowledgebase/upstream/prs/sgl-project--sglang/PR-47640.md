# [Refactor] [Ascend] dsa: Align index K cache and scale layout with GPU

[Upstream PR](https://github.com/sgl-project/sglang/pull/47640) · state: open · merged: False

## Original PR description

## Motivation

Align the NPU DSA index K cache and K scale storage layout with the GPU implementation while preserving inference performance and model accuracy.

Previously, the NPU implementation stored quantized index keys and their scales in separate buffers. This PR adopts the same packed page layout as GPU, storing FP8 keys and FP32 scales in a single allocation and writing them together.

## Modifications

- Align the NPU index cache with the GPU packed page layout: each page stores the FP8 index keys followed by their FP32 scales.
- Reuse the existing Triton cache writer to write already-quantized keys and scales together.
- Update the NPU DSA indexer to consume the packed cache through the registered packed quantized lightning indexer operator.
- Update HiCache host allocation and memory accounting to use the index buffer's actual dtype and element size.
- Add Ascend correctness tests covering cache layout, page boundaries, overwrites, padding slots, NPU graph replay, and packed reader/indexer integration.

## Accuracy Tests

- All applicable pre-commit checks passed.
- Added correctness tests:
  - `test/manual/ascend/test_dsa_index_k_cache.py`
  - `test/manual/ascend/test_dsa_packed_integration.py`
- The tests include comparisons between the packed reader and the existing NPU quantized lightning indexer.
- Ascend hardware test results and end-to-end model accuracy comparisons: pending.

## Speed Tests and Profiling

The cache writer combines key and scale writes into one Triton kernel launch. The packed indexer is invoked through the registered Torch operator with device-side sequence metadata.

The goal is to align the cache layout without introducing a performance regression.
