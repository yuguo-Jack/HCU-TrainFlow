# [Fix] [AMD] inkling: Initialize Inkling safely on ROCm

[Upstream PR](https://github.com/sgl-project/sglang/pull/41928) · state: open · merged: False

## Original PR description

## Motivation

On ROCm, where `cutlass` is not installed, Inkling fails to start on main because `models/inkling_common/attn.py` imports `is_batch_invariant` from the CuTe flash-attention package at module level, outside the file's existing optional-CuTe `try`. Importing that package runs its `__init__`, which pulls in the FA4 interface and `cutlass`, so the module fails to import. The model registry only logs `Ignore import error when loading sglang.srt.models.inkling: No module named 'cutlass'` and skips the model, so startup later fails with an error that does not point at the cause.

The fix comes from sgl-project/sglang#37294, which is merged into the `sglang-miles` branch. That PR also fixed `SWAKVPool.get_v_head_dim()` for pools without full-attention layers; main has since fixed that independently, so after merging main this PR carries only the `attn.py` change.

## Modifications

- `attn.py`: move the `is_batch_invariant` import into the existing optional-CuTe `try`, set it to `None` when CuTe is unavailable, and guard its only use (the FA4 sheared-bias fast path) with `is not None`. With `cutlass` installed the same function is imported and the guard is always true, so the CUDA path is unchanged.

## Accuracy Tests

No change to model outputs; this only decides whether Inkling can start on ROCm.

Validated on MI355X (gfx950) with the `rocm/sgl-dev:miles-rocm10-mi35x-20260929` image, whose SGLang is the `sglang-miles` commit this fix was based on. The `attn.py` lines there are identical to this PR; that image also carries #37294's own fix for the SWA issue, which main now handles independently.

- `import sglang.srt.models.inkling`: fails with `No module named 'cutlass'` before, succeeds after.
- After merging current main, on CPU without `cutlass`: importing Inkling fails with `No module named 'cutlass'` before and succeeds after. Pre-commit passes.
- Miles' `test_inkling_small_4layer_ci.py` (4 x MI355X, Triton attention), the Inkling test registered in Miles' AMD CI, passes with the fix: 2 rollouts and 8 train steps complete and the Ray job succeeds. Without it, this test currently times out at 2400 s in Miles' scheduled AMD CI.

Not run on NVIDIA GPUs.

#### 1. 🟠 Should fix: FA4 forward raises chained CUTE ImportError instead of clear backend error: this PR guards the batch_invariance import
`python/sglang/srt/models/inkling_common/attn.py:934`

On ROCm the `fa4` path is false, so the new guards don't change behavior there; the model override pins Inkling to triton off sm90/sm100. The defect appears only when `fa4` is selected while the cute/cutlass import fails: the first forward raises a chained `ImportError` about the vendored FA4 CUTE interface (via `get_inkling_relative_attention_score_mod` or `flash_attention_v4.flash_attn_varlen_func`) instead of FA4's own unavailability error, though it fails either way. This PR moved the `batch_invariance` import into the guarded cutlass `try` and sets `is_batch_invariant = None` with a `None` check that drops to the `score_mod` branch. Add an init-time check on `_cute_import_error` when `fa4` is selected to surface a clearer error.

**Who is affected:** Only users who force `--attention-backend fa4` in an environment where cutlass/cute cannot be imported; that run fails anyway.

_Checked against the code by an independent pass._

#### 2. 🟠 Should fix: CI won't catch regression of ROCm Inkling import failure: this PR adds no test for importing without cutlass
`python/sglang/srt/models/inkling_common/attn.py:42`

No test checks that `inkling_common.attn` imports when `cutlass` is unavailable, which is the failure this PR fixes. The existing CPU-CI tests that import the module (`test_custom_projection_parallel_groups`, `test_inkling_linear_loader_layout`, `test_split_attention_backend_decisions`) do not cover this, because CPU CI installs `python[dev]`, which pins `nvidia-cutlass-dsl`. A small test could set `sys.modules['cutlass'] = None`, import the module, and assert `is_batch_invariant is None` and that the sheared-bias branch is skipped.

**Who is affected:** Maintainers only: a future unguarded FA4 import could reintroduce the ROCm import failure without CI catching it.

_Checked against the code by an independent pass._
