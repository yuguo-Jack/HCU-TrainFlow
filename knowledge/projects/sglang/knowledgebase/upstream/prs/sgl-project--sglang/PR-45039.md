## How the commands are produced

The pipeline and rules are the same as in #44712, with these changes. None of them alters an existing deployment: GB300, B300 and B200 come out byte-identical to `main`.

- **Composed recipes.** [InferenceX #4272](https://github.com/SemiAnalysisAI/InferenceX/pull/4272) is the first Qwen3.8-Flash-Next lane in InferenceX's composed-recipe layout.
  - The recipe is a fragment: InferenceX binds the master config's model, image, precision and point values at launch, then picks one `override_tp{N}_c{M}` variant per point.
  - The pipeline now does that binding with InferenceX's own selector (`infx.srt_slurm.single_node.select_recipe`) at the pinned commit. Each point therefore renders the variant the sweep ran.
- **Rules.** Removed as telemetry:
  - srt-slurm's job-local OTLP collector (`otelcol-contrib`);
  - the variables it injects (`DYN_LIFECYCLE_TRACE_ENABLED`, `OTEL_EXPORT_ENABLED`, `OTEL_EXPORTER_OTLP_ENDPOINT`, `OTEL_SERVICE_NAME`).
- **GPU count and cluster environment** follow #44228.
  - H200 TP2·EP2 shows 2 GPUs and TP4·EP4 shows 4.
  - The H200 cluster does not export `NCCL_CUMEM_ENABLE`, so the H200 commands carry no cluster variable.

Each lane is still rendered at the exact commit of the run that produced its dashboard data.
- **Removed (SA-only settings):** the benchmark harness, cluster paths and caches, telemetry, and InferenceX's synthetic speculative acceptance (disclosed per deployment).
- **Replaced with placeholders:** IPs, ports and NICs.
- **Derived variants:** router and KV-offload variants that were not run are derived and labeled "Derived — not run".

The data file is generated, so there is no hand-written change to review.
