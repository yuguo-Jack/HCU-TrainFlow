# [Perf] DFLASH: Keep an all-sliding-window draft's KV on the target's SWA slots (opt-in)

[Upstream PR](https://github.com/sgl-project/sglang/pull/46116) · state: open · merged: False

## Original PR description

## Motivation

A DFLASH draft allocates one KV row per target token, even when every draft layer is sliding-window and can read only its last window. On a hybrid sliding-window target, that pool is sized like the target's full-attention pool. Most of it holds rows the draft can no longer read, and HiCache mirrors it on the host.

With this PR, such a draft's KV lives on the target allocator's SWA slots:

- one draft row per target SWA slot;
- the target's budget charges the draft per SWA token, and the bytes saved become target KV;
- HiCache backs it up as a DRAFT_SWA sidecar of the SWA host pool.

The draft window must not exceed the target's, so the target's SWA eviction keeps every slot the draft reads. #40665 covers full-attention targets; this PR covers hybrid sliding-window targets.

Related: #36995 and #37180 bound an all-sliding-window draft's KV with a request-private compact layout for PD serving, with radix cache and HiCache off; this PR keeps the draft on the target's SWA slots, with radix cache and HiCache on.

## How to enable

```bash
SGLANG_OPT_DFLASH_DRAFT_KV_ON_SWA=1   # default off
```

Requires:
- `--speculative-algorithm DFLASH` with an all-`sliding_attention` draft;
- a hybrid sliding-window target;
- `--speculative-draft-attention-backend trtllm_mha`.

It refuses `--speculative-draft-window-size`, `--enable-unified-memory`, DP attention, CP, DCP and PD disaggregation.

## Performance

Muse-Spark-Open NVFP4, 4x GB300, TP4/EP4, FP8 KV cache, DFLASH with an all-sliding-window draft (8 draft tokens) on `trtllm_mha`, HiCache (write-back). Multi-turn long-context sessions. Each row toggles `SGLANG_OPT_DFLASH_DRAFT_KV_ON_SWA` on the same build; only the host cache size also differs, as noted below.

| Concurrency | Throughput per GPU (tok/s), baseline | Throughput per GPU (tok/s), this PR | Per-user decode speed, P90 (tok/s/user), baseline | Per-user decode speed, P90 (tok/s/user), this PR | TTFT P90 (s), baseline | TTFT P90 (s), this PR |
|---|---|---|---|---|---|---|
| 64 (at most 44 running) | 69,457 | 72,189 (+3.9%) | 48.14 | 49.96 (+3.8%) | 6.54 | 4.30 |
| 48 (at most 32 running), equal host memory | 57,728 | 58,361 (+1.1%) | 58.91 | 61.28 (+4.0%) | 2.90 | 2.72 |

- At concurrency 64, both arms also run the KV split of #46082 and the session prompt-end refs of #46114. The baseline uses `--hicache-size 158` instead of 170: without this PR the draft's host pool holds one row per target token, and 170 does not fit in host memory.
- At concurrency 48, neither arm runs #46082 or #46114. The host cache is sized so both arms use about the same host memory.
- Why it helps: without this PR the target's device KV pool is 17.5% smaller. With it, more turns hit on device instead of reloading from host.

Throughput per GPU counts input and output tokens. Per-user decode speed excludes time to first token; P90 is the speed 90% of requests reach.

## Tests

New CPU cases:
- `test/registered/unit/mem_cache/test_kv_index_translator_draft_disposition.py`: both target-hidden writers put each draft token at the target's SWA id. Prefill writes every token, and the post-verify commit writes only the committed rows. The pool refuses a write without SWA ids.
- `test/registered/unit/model_executor/test_pool_configurator.py`: the draft is charged per SWA token. A draft with a full-attention layer keeps its per-full-token charge.
- `test/registered/unit/configs/test_model_config_shapes.py`: only an all-sliding-window DFLASH draft is reclassified; never a target, a DSPARK draft or a draft with a full-attention layer, and nothing with the flag off.

In GPU-registered files (they also run on CPU):
- `test/registered/attention/test_trtllm_mha_graph_metadata.py`: the expanded ENCODER_ONLY verify rows read `swa_page_table` on such a draft and `page_table` otherwise, on the eager path and in the recorded graph refresh.
- `test/registered/unit/spec/test_resolve_swa_kv_pool.py`: only a draft on SWA slots reads the SWA page table; a mixed layout is refused.

Accuracy, GSM8K strict match with this PR: 0.9750.

**Issue**

The PR description does not show that the draft still reads the right KV rows with the flag on. The only accuracy result is "GSM8K strict match with this PR: 0.9750". It does not name the model and GPU, and does not say whether `SGLANG_OPT_DFLASH_DRAFT_KV_ON_SWA=1` was set. GSM8K also cannot catch this kind of bug: the target verifies every token, so a draft that reads a wrong SWA row only accepts fewer tokens. The output stays correct.

**Fix**

Name the model and GPU for the GSM8K result, and say that the flag was on. Also add the average accept length with the flag off and on, on the same model and GPU. The accept length from the server log is enough.
