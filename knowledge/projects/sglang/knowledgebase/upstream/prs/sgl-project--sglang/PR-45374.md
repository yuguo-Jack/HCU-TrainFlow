## Motivation

The NPU precise-test (coverage-based test selection) pipeline needs better run-page
observability and a quieter, faster teardown:

- **Opaque selection results.** The bucketing step only emitted machine-readable
  `GITHUB_OUTPUT` values, so on the run page there was no way to see which tests
  coverage recommended, which suites were skipped vs. ran a subset, and which
  recommended files matched no suite pool.
- **Broken NPU-only coverage view.** The NPU-only report relied on a separate rcfile
  with `[run] source`, but `source` does not filter at report time — the "NPU-only"
  view was identical to the full report, so the per-tree NPU coverage number was
  meaningless.
- **No per-run artifacts.** precise-test outputs (`outputs.tar.gz`,
  `test_case_map.json`) only lived on the shared publish disk under fixed names that
  race with concurrent runs; nothing was attached to the run itself for debugging.
- **Benign log noise masking real failures:**
  - coverage 7.8: multiprocessing workers that receive the teardown SIGTERM after
    their coverage already stopped die on `assert self._collectors`, printing a
    scary multi-process traceback per worker (tests still pass).
  - CANN `tbe` repository-manager queue-client threads flood the log with ~15-line
    `EOFError`/`ConnectionResetError` tracebacks per process during graceful
    teardown — vendor-inherent and benign.
  - The tbe atexit `rm -rf` of the shared `kernel_meta` compile-cache races with
    sibling ranks still writing `kernel_meta_temp_*` dirs, printing one `rm` error
    line per directory.
- **Slow teardown.** The 20s graceful-kill timeout adds dead time to every test
  run; teardown reliably completes well within 5s.

## Modifications

- **`.github/workflows/pr-test-npu.yml`**
  - Pass `--github-summary "$GITHUB_STEP_SUMMARY"` to the bucketing step.
  - Fix the NPU-only coverage view: copy the combined data to `.coverage-npu`,
    `touch_file()` every unexecuted `.py` under `sglang/srt/hardware_backend/npu`
    (`os.walk`, so the PEP 420 namespace tree with no `__init__.py` counts fully),
    then filter with `--include`, which does apply at report time; same for the
    summary totals line.
  - Upload a `precise-test-outputs` artifact (`outputs.tar.gz` +
    `test_case_map.json`, ~300MB, 14-day retention, `continue-on-error`) before the
    publish step moves the files into the fixed `PUBLISH_DIR`.
- **`scripts/ci/npu/precise-test/bucket_recommended_tests.py`**
  - New `--github-summary` option / `write_github_summary()`: appends a markdown
    section with the precision-mode state, recommended case count, a per-suite
    table (registered / bucketed / action), and collapsible lists of recommended
    cases, files matching no suite pool, and per-suite buckets.
  - Keep raw case-level entries (with `::case` suffix) for the summary; write job
    outputs before the summary so a summary failure can never cost downstream jobs
    their bucket outputs.
- **`scripts/ci/npu/precise-test/run_tests_with_coverage.sh`**
  - Replace the one-line `.pth` with a `sglang_ci_cov_guard.py` guard module
    (inert unless `COVERAGE_PROCESS_START` is set): makes `Collector.stop`
    idempotent, patches `Coverage._on_sigterm` to flush via the stock atexit path
    and then die quietly via `SIG_DFL`, and installs a structural
    `threading.excepthook` that swallows only the known tbe queue-client teardown
    shape — any traceback with foreign frames still prints in full.
  - Filter benign `rm` errors on `kernel_meta` paths from pytest output
    (`grep -vE`; `PIPESTATUS[0]` preserves the pytest exit code).
  - Default graceful timeout 20s → 5s.
- **`scripts/ci/npu/precise-test/precise_test_coverage_plugin.py`**
  - Graceful timeout default 20s → 5s, kept in sync with the shell script.
