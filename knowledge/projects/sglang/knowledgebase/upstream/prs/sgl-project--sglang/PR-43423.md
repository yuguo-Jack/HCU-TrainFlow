# [VLM][MM refactor 4/6] Add token-space multimodal processing

[Upstream PR](https://github.com/sgl-project/sglang/pull/43423) · state: open · merged: False

## Original PR description

## Motivation

Today the multimodal processor turns text into a prompt string, lets the HF processor expand
media placeholders in that string, and tokenizes the result. RL rollouts and multi-turn sessions
already hold the exact token IDs of the conversation; re-tokenizing them from text can change
those IDs. Token-space processing keeps the caller's input_ids and expands media placeholders
directly in token space.

## Modifications

- `mm_token_expansion_start_len` on `GenerateReqInput` and `ChatCompletionRequest`: the length of
  an input_ids prefix to leave untouched (for example earlier turns whose media are already
  expanded). Validated and normalized per batch item.
- `--enable-token-space-processor` server option (off by default). Nothing reads it yet; startup
  wiring comes in a later PR. It is rejected with `--encoder-only` / `--language-only` for now:
  the EPD receiver still expands placeholders with each processor's `get_mm_data`, which does
  not honor `mm_token_expansion_start_len`.
- `expand_token_placeholders`: replaces each placeholder pattern after the start length with its
  media fragment, keeping the prefix and never rescanning inserted tokens.
- `TokenSpaceProcessStrategy`: per-model hooks that process one media item at a time
  (`process_image` / `process_video` / `process_audio`) and assemble the per-item fields
  (`merge_*_features`), plus `expand_media_tokens`, which tokenizes when no input_ids are given
  and expands placeholders with the model's expansion spec, and `build_processor_output`, which
  returns the same `BatchFeature` keys as the HF processor (`input_ids`, `attention_mask`, the
  media features, and `mm_token_type_ids` when the processor defaults ask for it).
- The mixin gains `load_and_process_token_space_async`, the token-space counterpart of
  `processor(text, media)`: it loads media with the shared loader, processes one task per item
  on the processor workers, expands placeholders and returns that `BatchFeature`. Training and
  serving both call it. `TokenSpaceMMProcessor` is a trainer-side host that needs no server.
- The per-item CUDA memory pool, the move of features to CPU and the device rule now live in the
  mixin, so a trainer that passes a CUDA device gets the same handling as serving. The first two
  commits move the defaults and the two transfer helpers from the base processor (the second is
  a mechanical move with a proof). Serving keeps only its own default device
  (`_fast_image_processor_device`) and derives `keep_mm_features_on_device` from its feature
  transport; a trainer sets it through `MultimodalProcessorConfig`.
- `BaseMultimodalProcessor.process_token_space_mm_data_async`: the serving entry. It calls
  `load_and_process_token_space_async`, then `sglang_post_process` collects the items, binds them
  with the existing `_bind_and_finalize_mm_items`, and each model builds the final
  `MultimodalProcessorOutput` in `_build_mm_output`. Models opt in through
  `token_space_process_strategy_class`; none does in this PR.
- Media URL policy: a `MultimodalProcessorConfig` that leaves the domain list or the size limit
  unset keeps that part of the process-wide policy (`preserve_allowed_domains`, and
  `max_file_size_mb=None` in `configure_media_url_security`), so a trainer host never resets
  limits it did not set. Existing callers pass both values and are unchanged.

No serving behavior changes: no model sets a strategy and the option is not read yet.

Follow-up: `get_mm_data` / `build_input_ids` is a second hand-written copy of the HF expansion rules
on the EPD receiver. The strategy only needs grids and timestamps, so the receiver can reuse it in a
later PR, which also lifts the EPD restriction above.

## Tests

- test_mm_token_expansion_start_len.py: request field validation and batch normalization.
- test_server_args.py: the option is rejected with --encoder-only and --language-only.
- test_mm_token_expansion.py: expansion rules (prefix kept, counts checked, no rescan) and the
  serving path with a fake processor (offsets, source configs, decoder cleanup).
- test_media_url_security.py: a trainer host keeps or overrides the process policy as configured.
- test_processor_device_selection.py, test_mm_utils_split.py: device choice and item split for
  the token-space path.
