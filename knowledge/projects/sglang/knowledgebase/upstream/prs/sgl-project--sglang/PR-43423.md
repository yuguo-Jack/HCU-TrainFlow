# [VLM][MM refactor 4/6] Add token-space multimodal processing

[Upstream PR](https://github.com/sgl-project/sglang/pull/43423) · state: open · merged: False

## Original PR description

## Motivation

The multimodal processor expands media placeholders in a prompt string and re-tokenizes it. RL rollouts and multi-turn sessions already hold the exact token IDs, and re-tokenizing can change them. Token-space processing keeps the caller's input_ids and expands placeholders in token space.

## Modifications

- `mm_token_expansion_start_len` on generate and chat requests: an input_ids prefix left untouched (for example earlier turns already expanded).
- `--enable-token-space-processor` (off, not read until PR6; rejected with EPD for now, since the EPD receiver does not honor the start length).
- `expand_token_placeholders`: expands placeholders after the start length without rescanning inserted tokens.
- `TokenSpaceProcessStrategy`: per-model hooks that process one media item at a time, merge the items, expand placeholders in the caller's input_ids, and build the same `BatchFeature` as the HF processor.
- Mixin `load_and_process_token_space_async`: loads media, processes items on the worker pools, expands and returns that `BatchFeature`. It takes input_ids only. Training (`TokenSpaceMMProcessor`) and serving both call it. The CUDA pool, CPU move and device rule move into the mixin so both get the same handling.
- `TokenSpaceMultimodalProcessor` (`processors/token_space_processor.py`): the serving processor a model subclasses with its strategy and, if needed, its own `MultimodalProcessorOutputBuilder`. Registered in a separate `TOKEN_SPACE_PROCESSOR_MAPPING`; `BaseMultimodalProcessor` gains no token-space members.
- A trainer config that leaves the media URL domains or size limit unset keeps the process-wide value.

No serving behavior change: nothing is registered and the option is not read yet.

## Tests

- `test_mm_token_expansion.py`: expansion rules, and the serving entry with a fake processor.
- `test_mm_token_expansion_start_len.py`, `test_server_args.py`: request field and option validation.
- `test_media_url_security.py`, `test_processor_device_selection.py`, `test_mm_utils_split.py`: trainer URL policy, device choice and item split.
