# Fuse MiMo verification RoPE and KV cache writes

[Upstream PR](https://github.com/sgl-project/sglang/pull/43106) · state: closed · merged: True

## Original PR description

## Motivation

Reduce KV preparation overhead during MiMo DFlash target verification.

## Modifications

- Fuse BF16 RoPE, V scaling, and KV-cache writes into one kernel while preserving the existing BF16 operation order.
- Reuse attention-backend KV buffers and SWA slot mapping in the MiMo verification path.
- Use the existing tensor matcher and typed launch helpers to define the dtype and layout contract.

## Performance

MiMo-V2.6-Pro-RL + DFlash on 8×B300, TP8, FA4/page128, MNNVL, KV capacity 32768, concurrency 1. Both arms use the same frozen random-topic essay inputs: 8000 input tokens, 1024 output tokens, `ignore_eos=True`, 3 warmups followed by 96 measured requests. One fresh service per arm; timing without a profiler.

| Metric | Baseline | This PR | Improvement |
|---|---:|---:|---:|
| Decode throughput | 302.70 tok/s | 318.04 tok/s | **5.07%** |
| E2E throughput | 285.60 tok/s | 298.77 tok/s | **4.61%** |

E2E includes prefill. Decode timing starts after the first token emission. Baseline: `6e7beace14`; measured candidate: `cdc52f549e`.

## Validation

- All 96 measured output token sequences and speculative acceptance/proposal/verification counters and histograms match the baseline.
- All measured requests have real draft rejection; acceptance is 21.38% in both arms.
- GPU checks cover int32/int64 KV-slot indices, int64 positions, V scaling, KV padding, and CUDA Graph replay with updated positions and slots.

Reproduction commands, pinned model/draft and dependency versions, benchmark scripts, and the existing GPU check: https://gist.github.com/leonardHONG/b55f9d6d4045db6fa8e4fd939b88bf67.

**Optional performance: avoid the intermediate Q/K stores**

Could we compute each rotated Q/K pair from qkv and store the final values directly? This needs a focused before/after measurement; it is not a correctness blocker.
