# [Refactor] platforms: in-tree platforms provide their graph runner and piecewise backend

[Upstream PR](https://github.com/sgl-project/sglang/pull/44960) · state: open · merged: False

## Original PR description

## Motivation

`SRTPlatform.get_graph_runner_cls()` and `get_piecewise_backend_cls()` are the seams for choosing the decode graph runner and the piecewise compilation backend. Only out-of-tree platforms go through them; in-tree devices are still picked in core:

- `capture_decode_graph()` uses a `defaultdict` keyed on `model_runner.device` (`cpu` → `CPUGraphRunner`, `npu` → `NPUGraphRunner`, `xpu` → `XPUGraphRunner`).
- `make_backend()` uses an `is_xpu()` / `is_npu()` chain.

The base-class docstrings describe exactly that: "None means the in-tree device-keyed selection". This PR moves those choices into the platforms, so the factories are the only path and core no longer names platform classes. It is part of a small series that routes in-tree platforms through the `SRTPlatform` seams that already exist (see #44958 for the `BaseFusedOp` dispatch key).

## Modifications

- `NPUSRTPlatform` returns `NPUGraphRunner` and `NPUPiecewiseBackend`.
- `XpuSRTPlatform` returns `XPUGraphRunner` and `XPUPiecewiseBackend`.
- `CpuSRTPlatform` returns `CPUGraphRunner`.
- The imports are lazy, inside each platform method, so importing a platform module stays cheap.
- `None` now means:
  - for `get_graph_runner_cls()`: the model runner's own `_decode_cuda_graph_runner_cls()`, including the UNO override;
  - for `get_piecewise_backend_cls()`: `CUDAPiecewiseBackend`.

  That is what CUDA, ROCm, MUSA and MPS already got.
- `cuda_graph_setup.py` and `compilation/backend.py` drop their imports of the NPU, XPU and CPU classes.
- Out-of-tree platforms still go through `require_out_of_tree_impl` when they return `None`.
- Test: each in-tree platform's factories return the expected class. It uses stub modules because the real piecewise backends can't be imported on a CPU-only host (`weak_ref_tensor` raises at import).

**Behaviour:** unchanged for every supported configuration. The selection now follows the resolved platform rather than `model_runner.device`. These two agree whenever the CPU engine is enabled the documented way (`SGLANG_USE_CPU_ENGINE=1` together with `--device cpu`).

**Not in this PR:**
- The full graph backends in `runner_backend/utils.py`. NPU ignores the requested decode mode there and XPU rejects non-full modes, so moving them is a behaviour decision rather than a mechanical move.
- `ModelRunner.decode_graph_gather_requirements()`, which still asks the CUDA runner class on every platform.
