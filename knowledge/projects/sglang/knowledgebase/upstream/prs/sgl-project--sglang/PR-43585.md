# [diffusion] fix: OpenAI API hardening and runtime utils/pipeline bug fixes

[Upstream PR](https://github.com/sgl-project/sglang/pull/43585) · state: open · merged: False

## Original PR description

**Note: behavior change in item 25. LingBot-World camera poses and intrinsics are now built in float32, and the Plucker rays are computed in float32 before the final cast. Plucker values will differ slightly from before. The effect on generated video was not checked, so a maintainer with a GPU may want to compare LingBot-World output.**

CPU check (16 frames at 832x480, synthetic forward-walk with yaw sweep, float64 as ground truth): the old bf16 path differs from truth in 74% of the conditioning values (mean error 0.0045, max 0.032); the new path matches the float64 result exactly after the final bf16 cast. The effect on generated video was not measured.

## Summary
Hardens the diffusion HTTP API (items 1-7) and fixes a set of bugs found in an audit of `multimodal_gen/runtime/utils` and `runtime/pipelines` (items 8-33). One commit per item.

1. Invalid `output_quality` returned 500; it now returns 400 (`adjust_output_quality` raised outside the try block).
2. `response_format="url"` with no cloud storage and no `output_path` ran the whole generation before returning 400. It is now rejected up front. Unsupported `response_format` values are also rejected before generation.
3. A cloud-upload failure (storage enabled but upload failed) returned a misleading 400 "requires cloud storage". It now returns 502, and the generated file is kept on the server. Behavior change: clients that matched on the old 400 will see 502.
4. URL image inputs were read fully into memory. Downloads are now streamed with a 50 MiB cap, enforced on Content-Length and on bytes received (chunked bodies).
5. `upscaling_model_path` / `frame_interpolation_model_path` accepted any URL and the server fetched it. Network entry points (OpenAI, realtime, Vertex, rollout) now reject URLs with 400; local paths and HF repo ids still work, and the CLI and Python API are unchanged.
6. The upscaler and RIFE model caches (and the resolved-path cache) grew without bound with client-chosen paths. They are now small LRU caches.
7. `frame_interpolation_scale` (0.25-4.0) and `upscaling_scale` (1-8) are range-checked in `SamplingParams._validate` (finite, non-bool). The bounds are chosen, not derived; they match the shipped RIFE scale values and Real-ESRGAN x2/x4/x8 weights. `frame_interpolation_exp` is bounded separately in #43014, which merges cleanly with this PR.
8. `load_video` never deleted the video it downloaded from a URL, so `/tmp` filled up over time. It now cleans up (also on failure) and the download has a timeout.
9. Line-wrapped base64 images were silently cut at the first line. The data URL regex now matches across newlines.
10. An unreachable Hub was treated as "this repo has no model_index.json", so the cache fallback never ran. It now falls back to the cached copy.
11. The same condition sent `maybe_download_model_index` down the single-model path with a misleading "-Diffusers" error. It now reports the download failure.
12. A local cache dir of `ltx-2.3-distilled` matched the `ltx-2.3` overlay by substring. Cache dirs are now matched by path component.
13. An overlay repo resolved by Hub id downloaded only its manifest, so `model_index.json` was missing on a fresh cache. It now downloads the full overlay metadata.
14. `scheduler` anywhere in a component's path made every component read `scheduler_config.json`. Only the component dir name counts now.
15. Normalizing a ModelOpt `config.json` wrote through the HF cache symlink and changed the shared blob. The file is now replaced instead.
16. The ModelScope LoRA path raised a `TypeError` when no weights were found. It now raises a `FileNotFoundError` that says so.
17. Corrected a comment claiming CI validation failures after download are retried (they are not).
18. `temporary_module_dtype` restored the whole module to the first parameter's dtype, undoing mixed precision (bf16 weights with fp32 norms). Each tensor keeps its own dtype now.
19. All `RequestMetrics` instances compared equal. They compare by identity now.
20. `log_request_summary` ignored its `tag` argument. It is honored now, with the previously written value as the default.
21. `get_git_commit_hash` ran `git rev-parse` in the current directory. It now runs in the sglang install dir.
22. The "log on every rank at DEBUG" rule read the log level when the logger was created, before `configure_logger`. It reads it at log time now.
23. Enabling the NVTX hooks between a module's pre- and post-hook popped a range that was never pushed. Push and pop stay balanced across toggles.
24. `get_bool_env_var` warned once per bad value instead of once per variable. It is keyed by name now.
25. Plucker rays were built in bf16 when poses were bf16, so pixel columns above 256 shared a ray. They are computed in float32 now (LingBot-World poses too).
26. The blank default texture and the bake buffers used `(width, height)` where `(height, width)` is needed, which breaks non-square textures.
27. `ImageProcessorV2.load_image` raised `UnboundLocalError` for an ndarray or tensor. ndarrays work and other types raise a `TypeError`.
28. `DiffusersPipeline` output layout: NumPy videos were permuted twice, PIL lists were read as a batch, and several images from an image pipeline were stacked as video frames.
29. `DiffusersPipeline.add_stage` took its arguments in the reverse order of the base class.
30. SANA-Video always encoded the negative prompt at 300 tokens. It uses `max_sequence_length` now.
31. ErnieImage treated a `[null, null]` `pe` entry as a real prompt-enhancement model. It is treated as absent.
32. HunyuanImage3 ignored `--revision` when downloading weights.
33. Hunyuan3D picked an arbitrary checkpoint when several matched the fallback glob. It picks the first by name now.

## Tests
- New unit tests for each item; each was run first against the unpatched code and failed.
- Items 8-33: the new and touched tests (`test_runtime_utils_regressions.py`, `test_hf_diffusers_utils.py`, `test_model_overlay.py`, `test_logging_utils.py`, `test_nvtx_pytorch_hooks.py`, `test_performance_metrics.py`, `test_precision_consistency.py`) were run on a CPU-only Linux box with the diffusion extras: 150 pass, 1 fails. The one failure, `test_worker_releases_the_probe_pool_before_the_next_request`, fails the same way without these changes. With the source changes reversed, all 24 new tests fail.
- `test_openai_security.py`, `test_postprocess_model_cache.py`, `test_postprocess_param_validation.py`: pass.
- No GPU run: the changes are CPU-testable utility and request-handling fixes.

## Notes
- 50 MiB download cap and LRU sizes (4 models, 256 paths) are arbitrary constants.
- Local file paths for model weights are still accepted over HTTP (loaded with weights_only=True).
- Behavior change in item 20: none for existing callers, the default tag keeps the value that was written before.
- Audit findings that were checked but not fixed here (argparse, torch_compile, and a few unproven ones) are in OnePunchMonk/sglang#6.
