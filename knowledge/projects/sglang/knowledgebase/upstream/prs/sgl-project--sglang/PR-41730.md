# [Fix] [XPU] ernie45_vl/dllm: Build the visual-token mask only for image or video prefill, and fix dLLM serving

[Upstream PR](https://github.com/sgl-project/sglang/pull/41730) · state: closed · merged: False

## Original PR description

This PR has two Intel XPU fixes: the ERNIE-4.5-VL visual-token mask, and dLLM serving on `intel_xpu`, which moved here from #41773.

## Motivation

### 1. ERNIE-4.5-VL: visual-token mask on every decode step

On Intel XPU, `baidu/ERNIE-4.5-VL-28B-A3B-PT` crashes during docvqa after a few dozen documents:

```
RuntimeError: level_zero backend failed with error: 40 (UR_RESULT_ERROR_OUT_OF_RESOURCES)
```

`Ernie4_5_VLMoeForConditionalGeneration.forward` calls `_set_visual_token_mask` on every forward, including every decode step. Each call allocates small device tensors (`_visual_token_ids_tensor_cache.to(device)`, `torch.as_tensor(pad_values, device=...)`, `torch.cat`, `torch.isin`). The level_zero backend does not reclaim them, so one prefill plus N decode steps per document adds up until device memory runs out.

The mask only decides which tokens go to the vision experts (`ernie45_moe_vl.py`). A `None` mask and an all-False mask take the same text-experts path, which is also the path CUDA-graph capture uses. Decode tokens are generated text, so the per-step mask is always all-False.

### 2. dLLM serving on intel_xpu

Diffusion LMs (`--dllm-algorithm`) on `--attention-backend intel_xpu` hit two XPU bugs:

1. **Crash at warmup** (`inclusionAI/LLaDA2.1-mini`, `JetLM/SDAR-8B-Chat`): `AttributeError: 'NoneType' object has no attribute 'shape'` in `XPUAttentionBackend.init_forward_metadata`. `ForwardMode.DLLM_EXTEND` is in `is_extend()` but not in `is_extend_or_draft_extend_or_mixed()`, which guards the XPU extend-metadata branch. On CUDA, `DLLM_EXTEND` runs via CUDA graph and never reaches this eager branch; on XPU it matches no branch and leaves `metadata.page_table = None`.
2. **Blank output** (`JetLM/SDAR-8B-Chat`): `_dllm_page_size` sets `page_size` to the dLLM block size (4 for SDAR, 32 for LLaDA2), overriding the intel_xpu 64/128 page constraint. The sgl-kernel-xpu paged kernels are exact at page 1/64/128. At page 2/4/8/16, a query block whose KV spans more than one page returns wrong output (max abs err 1.4 to 3.9 at page 4), and SDAR generates `\n\n\n...`.

## Modifications

### 1. ERNIE-4.5-VL

- In `python/sglang/srt/models/ernie45_vl.py`, build the mask only for non-decode batches that contain image or video inputs; otherwise set `visual_token_mask = None`.
- Image and video prefill/extend batches still build the mask, so vision routing is unchanged. Decode and text-only batches take the text-experts path, as before.

### 2. dLLM

`python/sglang/srt/layers/attention/xpu_backend.py`:

- Route `DLLM_EXTEND` into the extend-metadata branch (a multi-query block forward, so extend-shaped metadata is correct).
- For non-MLA attention without DCP, index KV per token (`page_size = 1`) when the page size is not 1/64/128. This reuses the existing page-1 path; the KV pool layout is unchanged.

Both dLLM changes are in the XPU attention backend only.

#42627 carries earlier versions of both fixes, without the video-only mask fix and the page-size fallback.

## Accuracy Tests

### 1. ERNIE-4.5-VL

Intel Arc Pro B60, tp-size 4, `--attention-backend intel_xpu`, lmms_eval `docvqa_val`:

| Run | Docs | Result |
| --- | --- | --- |
| Before, serialized (`num_concurrent=1`, `--max-running-requests 1`) | ~44 | crash, error 40 |
| After, same settings | 80/80 | 368,682 tokens, no error 40 |
| After, `num_concurrent=8`, `--mem-fraction-static 0.70`, no serialization flags | 150/150 | anls 0.9137, no error 40 |

The anls run sets `enable_thinking=false` in the chat template. ERNIE-4.5-VL opens a `<think>` block by default, and docvqa's short generation budget cuts it off before the answer.

Reproduce (serialized run):

```bash
SGLANG_USE_SGL_XPU=1 python3 -m sglang.launch_server --model-path baidu/ERNIE-4.5-VL-28B-A3B-PT \
  --device xpu --tp-size 4 --mem-fraction-static 0.85 --trust-remote-code --port 30000 \
  --context-length 8192 --disable-radix-cache --disable-overlap-schedule --max-running-requests 1 \
  --enable-multimodal --attention-backend intel_xpu

python3 -m lmms_eval --model openai_compatible \
  --model_args model_version=baidu/ERNIE-4.5-VL-28B-A3B-PT,num_concurrent=1 \
  --tasks docvqa_val --batch_size 16 --limit 80
```

### 2. dLLM

Intel Arc Pro B60, `--dllm-algorithm LowConfidence --attention-backend intel_xpu`, gsm8k 5-shot chat.

`JetLM/SDAR-8B-Chat`, tp1:

| | docs | `\boxed{}` answer correct |
|---|---|---|
| crash fix only | 10 | 0/10 (blank output) |
| this PR | 10 | 7/10 (triton backend: 7/10) |
| this PR | 1319 | **0.8635** (1139/1319) |

Counting answers written as `The answer is: $N$` without `\boxed{}` (last number in the response): 0.9189. Paper: 88.4. lm_eval flexible-extract reads 0.0804 on this model because its regex takes the trailing `$.` from `$\boxed{N}$.` (1176 of 1319 docs).

`inclusionAI/LLaDA2.1-mini`, tp2 (page 32), limit 10: flexible / strict 0.8 / 0.5, same before and after the page-size change.

```
python -m sglang.launch_server --model-path JetLM/SDAR-8B-Chat --trust-remote-code \
  --attention-backend intel_xpu --dllm-algorithm LowConfidence --tp-size 1
```

## Speed Tests and Profiling

- ERNIE-4.5-VL: no speed measurement. Each decode step now skips one `isin` and a few small allocations; image and video prefill are unchanged.
- dLLM: the per-token fallback applies only when the page size is outside 1/64/128. `inclusionAI/LLaDA2.1-mini` (page 32) ran about 20% slower in the 10-question check.
