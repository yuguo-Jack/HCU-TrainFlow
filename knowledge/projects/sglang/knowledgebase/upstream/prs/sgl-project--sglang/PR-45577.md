# [Perf] dsv4: Gather V4.1 index-K slots once per forward and cache the prefill index plan

[Upstream PR](https://github.com/sgl-project/sglang/pull/45577) · state: closed · merged: True

## Original PR description

- DeepSeek V4.1's low-ratio indexer no longer gathers its index-K pool slots from `req_to_token` in every layer: `_snapshot_low_ratio_k_slots` gathers them once per ratio at metadata init (`scoring.prefill_k_slots`), shares them with the late-layer tail metadata, and passes them as `PrefillInputs.k_slots`. The indexer backends stop taking `req_to_token` for prefill.
- The batch-only part of the prefill data (request starts, per-request lengths, compressed lengths) is built by the first layer of each ratio and cached per metadata (`PrefillIndexPlan`, `low_ratio_index_plans`), instead of rebuilt by every layer.
- The eager extend also fills `low_ratio_req_indices` and `low_ratio_pos_i64` once at metadata init, as the tail and the prefill graph already do.
- Captured prefill graphs carry no snapshot and keep the per-layer gather.
- DeepSeek V4.1 Flash on GB300, DEP4, 131,072-token context with 4,096 new tokens per request, one run per arm: at 4K tokens per rank the step goes from 106-110 to 98.3 ms, measured together with a request-window change that is not in this PR (the slot snapshot alone was not measured); 8K and 32K move under 1%.

No behavior change; host work moves from every indexer layer to metadata init.
