# [Perf] [AMD] mla: Fuse RoPE, concat and KV-cache write for triton MLA decode on gfx1250

[Upstream PR](https://github.com/sgl-project/sglang/pull/44459) · state: open · merged: False

## Original PR description

## Motivation

On gfx950, aiter MLA decode skips the standalone RoPE and runs RoPE, the q/k concat and the KV-cache write in one `fused_qk_rope_cat_and_cache_mla` kernel. On gfx1250 with the triton backend none of that is fused: native RoPE, two `torch.cat` and `set_kv_buffer` are more than a dozen elementwise kernels per layer.

## Modifications

- `_fuse_rope_for_gfx1250_triton_mla()`: with `SGLANG_USE_AITER=1` on gfx1250, triton-backend decode takes the same fused branch as gfx95 aiter MLA. Limited to plain `RotaryEmbedding` / `DeepseekScalingRotaryEmbedding` whose rotary dim and cos/sin table cover the whole rope head, without DSA or DCP.
- sglang's rope keeps cos and sin in one `cos_sin_cache`; on this path the kernel gets the two halves as views. gfx95 keeps aiter's rope module (`cos_cache` / `sin_cache`), which does not build on gfx1250.
- The fused kernel emits a bf16 q for the triton backend, which takes bf16 q whatever the KV-cache dtype.
- `_skip_rope_for_aiter_fused_mla()` is unchanged; gfx95 behaviour is unchanged.

A CPU unit test (`test/registered/unit/models/test_rocm_mla_gfx1250_fused_rope_gate.py`) pins down each term of the gate and the cos/sin order of the tables.

### Dependency on aiter

Requires ROCm/aiter#5501, which the ROCm Docker images carry since #44379 (aiter 2bb549102). Before it, the gfx1250 Gluon launch of `fused_qk_rope_cat_and_cache_mla` passes an extra `MAX_EMBD_POS` argument and fails.

## Setup

Kimi-K2-Thinking-MXFP4, TP8, MI455X (gfx1250), image `rocm/sgl-dev:v0.5.21-rocm10-mi45x-20261011`; aiter is the image's plus ROCm/aiter#5935, #5501, #5043 and #5402 (all in aiter 2bb549102). The image's sglang predates #43735, so the measured build reads the DCP state through `get_parallel().dcp_enabled` instead of `self.dcp_size`. The Kimi-K2 cookbook targets MI300X; flags used here beyond it: `--attention-backend aiter --prefill-attention-backend aiter --decode-attention-backend triton --page-size 64 --disable-radix-cache --disable-custom-all-reduce --chunked-prefill-size 8192 --cuda-graph-max-bs-decode 128`, with `SGLANG_USE_AITER=1`, `SGLANG_ROCM_FUSED_DECODE_MLA=0` and `AITER_FORCE_A8W4=1`. Before and after differ only by this PR.

## Accuracy Tests

GSM8K with `few_shot_gsm8k` (8-shot, 1319 questions, `max_new_tokens` 512, the settings of sglang's AMD Kimi accuracy tests): before and after to be added.

The fused kernel matches the unfused path (q, the written KV rows, untouched rows) for bf16 and fp8 KV, batch 1 to 128.

## Speed Tests and Profiling

RoPE + concat + KV write per layer, Kimi-K2 TP8 shapes, MI455X, CUDA-graph replay:
