# [Fix] openai: Track usage for streaming Harmony Responses

[Upstream PR](https://github.com/sgl-project/sglang/pull/45187) · state: open · merged: False

## Original PR description

[Fix] openai: Track usage for streaming Harmony Responses

## Motivation

Streaming gpt-oss `/v1/responses` requests report zero terminal usage despite generated content. Populate the streaming context counters used by the final response so clients receive prompt, cache, completion, and total usage.

Related: #41989 covers the non-streaming prompt-token guard; this PR covers the streaming context.

Fixes #45186

## Modifications

- Read the latest available prompt and cached token counts from streaming engine metadata.
- Count completion metadata as a running total within each generation, preserving earlier generations across builtin-tool results.
- Restart the token cursor after a builtin-tool result so the next generation keeps its first tokens in both cumulative and incremental streaming modes.

Production changes are confined to `StreamingHarmonyContext`; buffered Harmony handling and Responses usage assembly remain unchanged. Prompt and cached counts retain the latest-generation convention; the reasoning-token breakdown remains zero.
