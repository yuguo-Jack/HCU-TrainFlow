# [Router] Add the cache-locality rows to the Grafana dashboard (3/3)

## Motivation

> **3 of 3** in the cache-locality stack, on top of **#39326**, which adds the
> series these panels read; **#39325** is under that. Merge in order — on its
> own this row renders "No data".

The board has a storage-tier row and no way at all to see prefix reuse. Seven
panels over the new series, plus the `monitoring/README.md` section that says
how to read them.

## Modifications

**Cache & Load** gains four panels:

- **Router cache locality** — `selected/query` against `matched/query` per
  model. The two lines are the point: the first is what the chosen worker holds
  and is the only one comparable to the engine's
  `cached_tokens_total / prompt_tokens_total`; the second is the fleet-wide
  ceiling and reads structurally high. The gap between them is locality the
  routing decision gave up.
- **Cache-aware decisions** — evaluations/s by terminal decision, in the
  `cache_hit` / `cache_miss` / `cache_worker_queued` / `all_queued`
  vocabulary of `sgl_router_cache_aware_decisions_total`.
- **Locality by decision** — `selected/query` split by decision, which says
  WHICH bucket is losing the locality. Low under `cache_worker_queued` is the
  queue gate trading prefix for a shorter wait; low under `cache_hit` means
  the winner held little to begin with.
- **Zero-match attribution** — `in_tree` (carried but unreachable from the
  root: router-side linkage) against `absent` (no worker holds it anywhere in
  the tree). `absent` is not an engine fault by itself — a resident block is
  never re-announced — so read it against the tree's coverage first.

Plus **Lookup availability — fleet vs worst replica**, sharing a row with
Zero-match attribution (the input_ids forwarding panel already on `main` holds
the slot beside the active-load panels). Every router replica keeps its own
block-size oracle, so one pod can lose the lookup entirely while the fleet
aggregate stays flat; the worst-replica line is the only place that shows.
Coverage is `sgl_router_overlap_blocks_count` over
`sgl_router_cache_aware_decisions_total` — both booked at the same site for the
same selections, and only a selection that had a lookup observes the
histogram. The numerator supplies an explicit zero so a replica that never
looked anything up reads 0 instead of dropping off; the denominator is
filtered to `> 0` so a replica or model with no traffic in the window drops
out instead of reading 0.

The storage-tier row gains the two panels its series were missing: **Cache hits
by tier served from** (`device` / `host` / `disk` / `external`, plus `none` and
`unknown`, in the same vocabulary as `sgl_router_kv_tree_blocks`) and
**Affinity routes served by load-back** (`host / (device + host)`) — what the
tier work buys, stated as a number. Before the tree honoured tiers, every one
of those was a cold prefill on a random worker.

Two conventions the panels hold to, both learned the hard way on the fork this
comes from:

- Per-decision series are **not** stacked and **not** in `ops`. They are
  evaluations, not requests, and an `ops` axis reads as a request rate.
  `suffix:evals/s` with a table legend, and deliberately no Total column —
  Grafana's Total sums per-point `rate()` samples, which is not an evaluation
  count.
- Fleet aggregates collapse `model_id` only for **rates**. Ratios are not
  additive across models, so every locality and coverage panel keeps it.

## Tests

Before the rebase, every expression on the board was posted to the prod
Prometheus query API with `$vars` widened and `$__rate_interval` at 5m, and
all parsed and returned series. After the rebase onto `main`'s decision
vocabulary, the two **Lookup availability** expressions were rewritten and
have **not** been run against a live Prometheus; the rest are unchanged. The
file re-serialises to valid JSON with unique panel ids and no overlapping
`gridPos` cells.

One caution recorded while validating, for whoever reads these panels against
the live fork: Grafana Cloud adaptive metrics has stripped `instance`/`pod`
from `sgl_router_matched_overlap_blocks_total` and **only** that one of the
three, so a naive `sum by (...)` over the fork's current series compares
different series populations and can make `selected/query` read above
`matched/query`. Querying the bare metric name returns HTTP 422 naming the
stripped labels.
