# [Perf] kda: Capture the GLM-5.3-Flash FlashInfer KDA prefill in breakable prefill CUDA graphs

[Upstream PR](https://github.com/sgl-project/sglang/pull/45369) · state: open · merged: False

## Original PR description

## Motivation

Breakable prefill CUDA graphs capture the Triton KDA extend but not the FlashInfer one, the default KDA prefill on SM100/SM103. With FlashInfer, every KDA layer breaks the graph, runs eagerly and syncs the host.

## Modifications

- Capture the FlashInfer KDA prefill in breakable prefill graphs: each bucket keeps one `RecurrentKDAPrefillWrapper` per layer, re-planned on device before each replay, plus row-indexed tables for the prefix-cache checkpoints.
- Padded rows: padded state slots point at the reserved slot 0, and the q/k/v rows that FlashInfer's last 16-token tile reads past the batch are zeroed before the call, so no NaN reaches the output or the cached SSM state.
- A bucket holds at most `min(bucket - 1, sm_count // (2 * heads))` sequences (9 at TP8 on B300): FlashInfer needs more tokens than sequences, and past that count it leaves its faster sequence-decomposition route. Larger batches replay a second, eager-metadata graph per bucket, in which only the KDA layers break.
- All wrappers share one planner scratch buffer (about 27 MB) instead of one each; this is a workaround until flashinfer-ai/flashinfer#5069.

## Tests

- `test/registered/kernels/ops/attention/test_kda_prefill_graph.py`: new FlashInfer case (SM100/SM103, registered on B200). Graph replays match eager FlashInfer bit for bit on output, conv and SSM pools (including prefix-cache track slots), with NaN in the post-conv q/k/v, `a` and `b` rows past the batch. Fails with the tail zeroing removed. Also pins the tile size to FlashInfer's `_CHUNK_SIZE`.
- `test/registered/unit/managers/scheduler_components/test_dp_attn.py`: with an eager-metadata variant, a batch over the captured-metadata bound votes for the graph and replays that variant.
