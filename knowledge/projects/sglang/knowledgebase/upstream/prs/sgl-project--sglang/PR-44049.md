## AITER prerequisites

None. This densifies the Quark MXFP4 shared experts to BF16 before the fused front, so it does not call an MXFP4 MoE kernel. The tuned BF16 GEMM for that front is #44360, which depends on [ROCm/aiter#6411](https://github.com/ROCm/aiter/pull/6411) (Kimi-K3 BF16 tuned rows).

## Motivation

Quark keeps Kimi-K3's shared experts in MXFP4, so the merged MoE front can only fuse the router and latent projections; the shared gate-up runs separately.

## Modifications

**`569b6448ea` let Quark MXFP4 shared experts join the fused ROCm MoE front**
- Add QuarkW4A4MXFP4.dequantize_to_bf16 and skip the loader's post-processing for a linear already densified.
- Densify Kimi-K3's Quark MXFP4 shared experts before the MoE front merge, so the full fused front covers them.
- Gate it behind SGLANG_OPT_HIP_K3_QUARK_SHARED_FULL_FRONT, off by default; other Quark MXFP4 models are unchanged.
- Add a regression test for the double dequantization and document the switch.

Switch: `SGLANG_OPT_HIP_K3_QUARK_SHARED_FULL_FRONT`. Everything is ROCm only; CUDA and other checkpoints keep the existing path.
