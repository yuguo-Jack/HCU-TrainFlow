# [CP] Support zigzag prefill for DeepSeek sparse attention

[Upstream PR](https://github.com/sgl-project/sglang/pull/43277) · state: open · merged: False

## Original PR description

## Motivation

Enable zigzag prefill context parallelism for DeepSeek V3.2 sparse attention. Zigzag orders all requests' early query blocks before their late blocks; interleave-only metadata incorrectly treats those queries as one contiguous segment per request.

## Modifications

Build sparse metadata from strategy query indices and preserve repeated request segments across Q/K cumulative lengths, causal bounds, page tables, and top-k offsets. Materialize matching segmented RAGGED keys for both cached-prefix and no-prefix prefill. Strip physical padding from gathered indexer/FP8 payloads while preserving dense MLA's cache-writing contract.

Match routing token IDs to rank-major FFN communication and mask padded rows from MoE dispatch. Admit V3.2 zigzag without forcing DeepEP, while retaining the existing attention-TP1/full-CP-width policy. Pooled indexers (`index_kpool > 1`) are explicitly rejected.

This is an independent main-based PR and has no dependency on the dense interleave or V4 changes. The small rank-major input-ID helper overlaps the V4 PR because each must work standalone.

## Accuracy Tests

Exact head `47389f71f7` passes 9 new regression methods, 2 configuration tests, 24 existing CP tests and 5 existing DSA padding tests through normal package imports on H200. Coverage includes segmented causal metadata at CP2/CP4, PAGED/RAGGED coordinates, prefix/no-prefix paths, physical padding, FP8 byte preservation with a mocked collective, MLA contracts and MoE routing layouts.

Public DeepSeek-V3.2 on 8x H200, TP8/CP8, `flashmla_sparse` prefill, `fa3` decode, BF16 KV cache, MoE A2A `none`; 200 GSM8K examples per strategy:

| CP off | Zigzag | Interleave |
| ---: | ---: | ---: |
| 94.0% | 96.0% | 95.5% |

All runs have zero request errors, truncation and invalid answers. Native-chat multi-request smoke crosses the 2,048-token sparse top-k window and the configured 4,096-token chunk budget. Every strategy has actual prefix-cache hits of 320/3,136/3,200 tokens and completes cold replay plus continued decode.

Across 6,719 teacher-forced input tokens, mean absolute logprob differences are 0.00282 (zigzag/off), 0.00304 (interleave/off), and 0.00281 (zigzag/interleave); maxima are 1.625/1.750/1.747, respectively, with the largest outliers on low-probability chat delimiters and early content tokens. Cached/cold output wording can differ. These measurements do not claim bitwise or statistical accuracy equivalence.

Independent source review found no outstanding confirmed defects. Native q8 and deferred TRTLLM FP8 collective paths retain unit-only qualification here.

## Speed Tests and Profiling

No performance claim. Repeating K request segments for early/late query blocks can roughly double indexer logits width and RAGGED key materialization. A future optimization can separate unique-K indexing metadata from segmented attention metadata.

Initial scope is CUDA DeepSeek V3.2 with `index_kpool=1`, attention TP1/full CP width. This does not qualify pooled DSA, HIP, or every sparse backend configuration.
