# [Bugfix] Stop Kimi-K3 free-text string arguments at their own close marker

[Upstream PR](https://github.com/sgl-project/sglang/pull/43119) · state: open · merged: False

## Original PR description

## Motivation

Fixes #43118.

In the Kimi-K3 strict tool grammar an unconstrained string argument (`{"type": "string"}` without `pattern`/`enum`/length keywords) compiles to `JSONSchemaFormat(style="qwen_xml")`. That string grammar may contain the argument close marker `<|close|>argument<|sep|>`, so the model can end the value early and continue with `<|open|>argument ...` tags that the grammar still treats as part of the string. `KimiK3Detector._ARG_RE` splits at the first close marker, so those tags come back as real arguments: with `additionalProperties: False` an undeclared key is accepted, and a declared `integer` property is accepted as a `string`, whenever a free-text argument precedes them.

Verified at token level with the real `moonshotai/Kimi-K3` tokenizer (`<|close|>` is an ordinary id there, not an xgrammar special token): both smuggled calls were accepted by `GrammarMatcher`.

## Modifications

`kimik3_structural_tag.py`: `_value_format` emits `AnyTextFormat()` for strings whose schema constrains nothing about the text (no `pattern`, `format`, `minLength`, `maxLength`, `enum`, `const`, `$ref`, `allOf`/`anyOf`/`oneOf`/`not`). xgrammar stops `AnyTextFormat` at the enclosing tag's end marker, which is what non-strict tools already rely on. Constrained strings keep the qwen_xml schema, since it is what enforces their constraints.

Tests in `test_kimik3_structural_tag.py`: the smuggled calls and a value containing the close marker are rejected at byte and token level while lone `<`, `|`, `>` characters stay allowed; an enum/pattern tool keeps rejecting out-of-schema values.

## Accuracy Tests

No model code changes. On `main` the regression case fails (the smuggled calls are accepted); with the fix the whole `test_kimik3_structural_tag.py` passes (37 tests). With the real Kimi-K3 tokenizer the smuggled calls are now rejected at the first token of the injected key / type. CPU only, Python 3.12.

## Speed Tests and Profiling

Not applicable: the string branch of the grammar changes from a JSON-schema string to `AnyTextFormat`.

### Relation to xgrammar 0.2.8

xgrammar 0.2.8 added `JSONSchemaFormat.excludes` (mlc-ai/xgrammar#912; its built-in Kimi-K3 tag uses it in mlc-ai/xgrammar#915), which forbids the control markers inside string values directly. SGLang pins `xgrammar==0.2.7`, which has no `excludes`, so this PR uses `AnyTextFormat` for free-text strings instead. Once the pin moves to 0.2.8+, the same strings can switch to `excludes=[OPEN, CLOSE, SEP]` with no change for callers.
