# [diffusion] Keep the overlay probe from stalling cached startup

[Upstream PR](https://github.com/sgl-project/sglang/pull/43590) · state: closed · merged: True

## Original PR description

## Motivation

Every diffusion launch checks whether the model id is a direct overlay repo by downloading `_overlay/overlay_manifest.json` with `hf_hub_download` (#21600). Each process that resolves the model runs this check, including the server warmup after `Application startup complete`. Most repos never had that file, so `huggingface_hub` has no cached copy to fall back to, and a HEAD that gets HTTP 429 is retried after each `Retry-After`, up to five times.

```
HTTP Error 429 thrown while requesting HEAD https://huggingface.co/<model>/resolve/main/_overlay/overlay_manifest.json
Rate limited. Waiting 161.0s before retry [Retry 1/5].
```

On a host whose unauthenticated Hub requests were rate limited, 8 of 9 launches of a fully cached checkpoint waited 132 s to 334 s in this probe, and the one launch without a 429 was ready in 90 s. The warmup builds its requests on the HTTP event loop, so `/health` and `/liveness` did not answer during the wait. A 429 on `model_index.json` does not stall, because that file is cached and `huggingface_hub` returns the cached copy at once. `HF_HUB_OFFLINE=1` avoids the wait today, but a default launch of a cached checkpoint should not depend on the Hub for an optional probe.

## Modifications

`maybe_download_model_index` and `maybe_download_model` now pass `_download_overlay_manifest` to the overlay helpers in place of `hf_hub_download`. It skips the Hub when the cached snapshot of the repo is a complete diffusers checkpoint and holds no overlay manifest. That is the same `_verify_diffusers_model_complete` check `maybe_download_model` uses to serve a snapshot from the cache. Overlay repos hold only metadata, so such a snapshot is a regular checkpoint at the cached revision, which `maybe_download_model` then serves from the cache as before.

A cached overlay manifest, a partial or metadata-only snapshot, a repo with nothing cached, `HF_HUB_OFFLINE=1`, and ModelScope all keep the previous path.

## Validation

- `python/sglang/multimodal_gen/test/unit/test_hf_diffusers_utils.py::test_complete_cached_checkpoint_skips_overlay_probe` covers a complete cached snapshot, one with a cached manifest, and a metadata-only one. The complete case fails before this change, because the manifest is fetched through `hf_hub_download`, and passes after. The other two cases pass on both and fail if the manifest check or the completeness check is dropped. `test_hf_diffusers_utils.py` and `test_model_overlay.py` pass (38 tests), also with `HF_HUB_OFFLINE=1` set.
- A reproduction used a synthetic Hugging Face cache and a mocked Hub that answers every request with 429 and `Retry-After: 2`. The table below shows the main cases.

  | Case | Before | After |
  | --- | --- | --- |
  | `maybe_download_model_index`, complete cached checkpoint | 15.0 s, 7 manifest HEADs, 5 rate limit waits | 0.002 s, no manifest request |
  | `maybe_download_model(..., force_diffusers_model=True)`, same cache | 15.0 s, 5 waits | 0.001 s, no Hub request |
  | `SamplingParams.from_pretrained` (the warmup path), `Qwen/Qwen-Image` | 18.7 s, 5 waits | 3.7 s (imports), no wait |

  Across 21 cases of cache state (complete, cached overlay, metadata-only, nothing cached), Hub behavior (reachable, 429, offline), and caller, the resolved pipeline or model path is the same before and after, and no case sends more Hub requests or waits longer.
- `pre-commit run` on the changed files passes.

## Speed Tests and Profiling

No performance claim. The change removes the rate-limit wait from the overlay probe of a complete cached checkpoint, which was the bug. For a cached direct overlay repo, the probe now does one cache lookup before its usual Hub request. I timed the model-resolution call against a zero-latency mock of the Hub, on one pinned CPU, with 8 pairs of fresh processes and 30 calls each. The added lookup cost about 0.1 ms per call there, 16 to 20 percent of the mocked call. Offline and uncached cases showed no measurable change.

## Limits

The probe and the `model_index.json` lookup still resolve `main` rather than `--revision`, because `get_model_info` takes no revision. Repos cached without `model_index.json`, and partial snapshots, keep the old probe.
