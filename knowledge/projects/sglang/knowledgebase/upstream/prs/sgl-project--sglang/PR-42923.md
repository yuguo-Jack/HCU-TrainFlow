# [MemCache] Return only the matched length from `match_prefix`; read KV indices off the node path

[Upstream PR](https://github.com/sgl-project/sglang/pull/42923) · state: closed · merged: True

## Original PR description

- `MatchResult` carries `device_prefix_len` instead of the concatenated `device_indices`; radix, unified (Python and Rust tree core), FlexKV, LMCache and session matches no longer concatenate per-node values
- Probe matches (priority sort, cache-aware policy, in-batch prefix check, admission) were discarding that concatenation; the indices are now read only where needed, through `BasePrefixCache.path_device_indices(node)` (checkpoint rematch, PD decode prealloc / rematch, LMCache publish / store, buffer-mode ownership check) and `prefix_device_indices(req)` at allocation
- Rust binding no longer moves a tensor to Python per match; tree cores expose `empty_device_indices` for empty placeholders
