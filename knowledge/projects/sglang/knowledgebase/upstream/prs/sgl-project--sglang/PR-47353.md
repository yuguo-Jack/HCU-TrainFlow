# [Feat] fpm: Retain captured intervals and support multiple FpmTiming listeners

[Upstream PR](https://github.com/sgl-project/sglang/pull/47353) · state: closed · merged: True

## Original PR description

## Motivation

`FpmTiming` is the observer that `DeviceTimer.capture()` attaches to a forward pass so Forward Pass Metrics (FPM) can publish the first-start to last-end GPU span once every captured interval has completed. It kept a single `when_ready` callback and discarded the intervals after counting them, so a second consumer that wants per-segment GPU durations for the same forward (for example a diagnostic that sums the individual prefill/decode segment times) either overwrites FPM's listener or needs a second capture mechanism alongside the existing one.

## Modifications

Keep the existing ownership path (pending-interval counting, sealing after CPU submission, attachment to the batch result) and extend the observer instead of adding a parallel one:

- `when_ready` now accumulates listeners. All of them are invoked once, with the same span value, when the group completes; a listener registered after completion is still invoked immediately, as before.
- `FpmTiming.segments` exposes the captured intervals as a tuple of `TimingSegment(elapsed_seconds, metadata)` in submission order. It is built lazily on first read, so a span-only consumer never queries per-interval `elapsed_time()` or copies metadata. Reading it before the group is ready raises `RuntimeError`. Each segment is a frozen, slotted dataclass whose metadata is a read-only copy, so a consumer cannot mutate the timer's intervals.
- `wrap_forward_with_fpm` docstring now describes what the wrapper does rather than who installs it.

FPM's span semantics are unchanged: the enclosing span still includes gaps between segments, an empty group still reports `0.0`, and a multi-stream group still reports `None`. `DeviceTimer`, `GapTimer`, and the aggregate reporter interface and metadata are untouched; reporters registered between interval end and drain still receive pending samples.
