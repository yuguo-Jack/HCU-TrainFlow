# [Feat] runtime: Support tokenized multimodal generation

[Upstream PR](https://github.com/sgl-project/sglang/pull/42833) · state: closed · merged: True

## Original PR description

## Motivation

The native runtime gRPC listener (`SGLANG_ENABLE_GRPC` in `rust/sglang-grpc`) accepts pre-tokenized requests: clients send `input_ids` instead of text. Its `GenerateRequest` has no media fields, so a client can't send the images, video, or audio that go with those tokens. The engine's `GenerateReqInput` already accepts `image_data`, `video_data`, and `audio_data`; this listener just doesn't pass them through.

This PR adds that passthrough. It doesn't add model support: each model's existing multimodal processor still decides which modalities it accepts.

## Modifications

- `proto/sglang/runtime/v1/sglang.proto`: add `image_data = 18`, `video_data = 19`, and `audio_data = 20` to `GenerateRequest`. Each is a repeated string (URL, path, or base64), ordered to match its placeholders in `input_ids`.
- `rust/sglang-grpc/src/utils/request_utils.rs`: copy each non-empty list into the matching `GenerateReqInput` field. Requests with no media are unchanged.
- Regenerate the checked-in proto bindings (`rust/sglang-api-types/src/generated/sglang.runtime.v1.rs`).

Media items with per-item options (`ImageData`/`VideoData` objects) aren't covered; these fields carry source strings only.

## Accuracy Tests

Model-output accuracy tests have not been run. The tests below verify request forwarding, not whether each model processes the media correctly:

- `tokenized_multimodal_request_preserves_generation_params`: image, video, and audio sources arrive in order, along with sampling params and bootstrap host/port/room.
- `tokenized_request_omits_empty_media_data`: requests without media don't get media keys.
- `cargo test --locked --manifest-path rust/sglang-grpc/Cargo.toml`: 18 passed, 0 failed.
- `cargo check --locked --workspace --all-targets` in `rust/`: passes.
