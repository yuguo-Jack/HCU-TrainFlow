# [Perf] diffusion: Walk several row chunks per warp in the CuTe-DSL norm kernels

[Upstream PR](https://github.com/sgl-project/sglang/pull/46227) · state: closed · merged: True

## Original PR description

Branch: mick/diffusion-cutedsl-norm-chunked-warps (on main 1e894eb92d), commit 60d5f1e9ee

## Motivation

`fused_norm_scale_shift` and `fused_scale_residual_norm_scale_shift` (CuTe-DSL) launch one CTA of `D // 256` warps per row, each warp owning one 256-column chunk. At Wan's `D = 5120` that is a 640-thread CTA per row, so an SM holds only two or three rows at a time and every row waits out its loads, two block reductions and its scale/shift loads back to back. On Wan2.2 A14B 720p (`[1, 37800, 5120]` per rank on 4xB300) the three calls per block (norm1, the self-attention residual norm, the cross-attention residual norm) moved 0.77-1.55 GB each at 2.4-4.2 TB/s and took 1.16 ms of every 55 ms block inside the denoising loop, where the GPUs run at their power cap (~1300 MHz).

## Modifications

- `norm/cutedsl_common/norm_fusion.py`, `norm/cutedsl_common/reduce.py`: `tensor_slice_for_bsfd` slices one 256-column chunk of a row; `apply_norm_cta` becomes `row_norm_stats` (mean and 1/std of a row held as per-warp chunk lists) + `normalize_chunk`; `cta_reduce_sum` takes one partial sum per chunk.
- `norm/scale_residual_norm_cutedsl.py`: a warp walks `chunks_per_warp` consecutive chunks with the same lane mapping (8 consecutive elements per lane), keeps one partial sum per chunk and runs the same shuffle-down tree on each; the cross-chunk sum reads `acc[chunk]` in chunk order. The reduction order therefore depends on `D` only, so every output is bit-identical to one chunk per warp (the old kernel), whatever `chunks_per_warp` is. `_chunks_per_warp` picks about five warps per row, ten when the row also streams a gate and an affine weight (their registers cap occupancy); measured on B300 at `D = 5120`.

## Accuracy Tests

- `test_norm.py::test_cutedsl_norm_chunks_per_warp_keep_bits`: 1, 2, 4 and 5 chunks per warp give the same bits (layer/RMS, with and without residual).
- Old vs new kernel, 36 cases (`D` 1536-5120, B 1-2, norm1 / RMS + affine / gated affine residual / gate 1 / 4-D frame gate / per-token scale): every output bitwise equal.
- Wan2.2 T2V A14B 720p, 4xB300, 3-step requests, lossless (crf 0) mp4: md5 identical to the base for 3 prompts.
- `test_norm.py -k cutedsl`: 150 passed.
