# [Perf] dsv4: Use the fused MXFP8 producers in eager prefill

[Upstream PR](https://github.com/sgl-project/sglang/pull/45903) · state: closed · merged: True

## Original PR description

- `fused_mxfp8_rows` in `deepseek_v4_mhc.py` decides when the mHC post and RMSNorm steps write MXFP8 activations directly for the next DeepGEMM consumer instead of writing bf16 and quantizing in a separate kernel.
- It previously returned `False` for every extend batch, so eager prefill always paid the separate quantize pass.
- Extend batches now take the fused path, except inside a breakable prefill graph, where the captured buffers stay bf16. Decode and verify keep the existing row cap, and sequence-parallel batches stay excluded.

No change to the computed values: the fused producer emits the same MXFP8 tensor the separate quantize kernel produced.

Verification: DeepSeek-V4.1-Flash DEP4 eager prefill is faster at large batches; the breakable-graph prefill path is unchanged; GSM8K is unchanged.
