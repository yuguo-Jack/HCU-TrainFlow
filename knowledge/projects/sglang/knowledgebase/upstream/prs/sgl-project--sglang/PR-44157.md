## Original PR description

# [AMD] DSA: allow breakable prefill CUDA graph on HIP

## What
Two CUDA-only checks in the DSA prefill graph path now also accept HIP:
- `pcg_dsa_indexer_prefill_split`: `assert _is_cuda` -> `assert _is_cuda or _is_hip`
- `is_dsa_prefill_cp_interleave`: `is_cuda()` -> `(is_cuda() or is_hip())`

This makes `--cuda-graph-backend-prefill breakable` usable for DSA models
(GLM-5.2, DeepSeek-V3.2) on ROCm. The default backend is unchanged.

## Why
Eager prefill on MI355X is launch-bound for short and medium prompts. The DSA
indexer split already works under HIP graphs; only the platform guards blocked it.

## E2E
MI355X TP4, GLM-5.2-MXFP4, EAGLE MTP (3 steps, 4 draft tokens), OSL 1024,
max running 48, `--cuda-graph-backend-prefill breakable` vs eager prefill.

| ISL | conc | TTFT ms | TPOT ms |
|---|---|---|---|
| 1024 | 4 | 138 -> 102 (-26%) | 4.22 -> 4.08 (-3.3%) |
| 1024 | 64 | 3247 -> 3194 (-2%) | 13.18 -> 13.09 (-0.7%) |
| 8192 | 4 | 340 -> 346 (+2%) | 4.85 -> 4.88 (+0.7%) |
| 8192 | 64 | 7040 -> 7088 (+1%) | 24.38 -> 24.74 (+1.5%) |

Geomean over these 4 points: TTFT -7.3%, TPOT -0.5%, throughput flat.
Full 10-point sweep together with the non-fused decode AR change: TTFT -12% to -27%
at 1k c4..c32 and -27% at 8k c16; c64 TTFT is queueing-dominated and unchanged.
gsm8k unchanged (0.93).

## Notes
- No change on CUDA. On HIP the feature stays opt-in.
