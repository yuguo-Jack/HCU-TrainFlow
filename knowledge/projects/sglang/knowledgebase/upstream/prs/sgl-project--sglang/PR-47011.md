# [Fix] disaggregation: Drop a decode's cached bootstrap infos when its prefill re-registers

[Upstream PR](https://github.com/sgl-project/sglang/pull/47011) · state: open · merged: False

## Original PR description

## Motivation

A runtime role switch (#28403) rebuilds the prefill KV manager behind the same bootstrap server. Decode workers cache each prefill's bootstrap infos and register their kv_args with it only once per bootstrap key. After a prefill -> decode -> prefill round trip, they keep using infos the rebuilt manager does not know, and every request routed to that prefill waits in `Bootstrapping` / `WaitingForInput` until the 300 s transfer timeout. The bootstrap server survives the switch, so the heartbeat never fails and nothing refreshes the cache.

## Modifications

- **Bootstrap server:** counts rank re-registrations (a (dp, cp, tp, pp) rank registering again, which is what a rebuilt KV manager does) and returns the count on `/health` as `X-Bootstrap-Epoch`.
- **Decode heartbeat:** when a prefill's epoch differs from the last one it saw, it calls the existing `_handle_node_failure` for that prefill: the cached bootstrap infos are dropped, and requests still bound to the old manager fail now instead of at the timeout. The next request fetches the infos and registers its kv_args again. Nothing happens on the first heartbeat, when the epoch is unchanged, or when the header is missing (an older bootstrap server). The check runs outside the probe's try block, so it never counts as a missed heartbeat.
- **mini_lb `/pd_role_switch`:** optional `settle_secs` (default 0, so nothing changes unless set). After a switch to prefill it waits that long before routing to the server, so decode workers see the new epoch first. Set it a little above `SGLANG_DISAGGREGATION_HEARTBEAT_INTERVAL`.

This reuses the heartbeat that already polls `/health` and the existing node-failure path, and changes nothing for deployments without role switching, where the epoch never moves. Decode workers log the switch as a lost connection to that prefill, since its old KV manager is gone. Re-registering only after a failed transfer would still wait for the timeout, and the prefill cannot push an invalidation because it does not know which decode workers cached it.

## Accuracy Tests

Not a model change.

End to end on 8x MI308X (gfx942), DeepSeek-V4-Flash, four TP2 servers, MoRI connector with the XGMI data plane (#46733), DSpark off, mini_lb, heartbeat interval 2 s, `settle_secs` 5. This ran on a v0.5.19-based tree with #28403 and #43760 backported and an earlier version of this change: the same epoch on `/health` and `settle_secs`, but the decode side dropped only the cached infos instead of calling `_handle_node_failure`. The decode cache, register-once logic and bootstrap server lifetime are unchanged on main.

| | Before | After |
|---|---|---|
| Requests to the server after its prefill -> decode -> prefill round trip that timed out | all (49 timeout log lines across its two TP ranks) | 0 |
| bench_serving 4096/1024, c32, 192 requests, with role switches under load | 629 s | 174 s, 192/192 |
| Decode -> prefill switch under load (drain + settle) | 285 s | 22 s |
| GSM8K 200 after the round trip | requests hung | 0.945 |
| Needle in a haystack, 8K-60K | not run | 12/12 |

The same functional test with this PR's commit on main (45252c64ca), plus #46733 and a gfx942 PTPC checkpoint loading patch that is not on main yet:

- GSM8K 200: 0.95 in 2P2D, 0.95 in 3P1D after a decode -> prefill switch, 0.97 in 1P3D after a prefill -> decode switch.
- After the prefill -> decode -> prefill round trip: GSM8K 0.97, needle 12/12, 0 transfer timeouts. Each decode worker logged the lost connection to that prefill once per TP rank, with 0 requests affected.
- bench_serving 4096/1024, c32, 192 requests, with a decode -> prefill -> decode switch under load: 192/192 in 180 s, mean TPOT 26.2 ms. The decode -> prefill switch took 24.7 s, including the 5 s settle.

Follow-up runs with the change: calibration plus two rounds of shifting traffic with role switches at phase boundaries, 0 transfer timeouts.

Unit tests:

- `test_pd_role_switch.py::TestBootstrapEpochAcrossRoleSwitch`: a rank registering again changes the `/health` epoch, and a first registration does not. The decode side runs the node-failure path for a prefill only when its epoch changes.
- `test_mini_lb_role_switch.py::test_switch_to_prefill_waits_settle_secs_before_routing`: the server is not routable as a prefill server during the wait.
- All three fail without the change.
- `test_nixl_backend_basic.py`: the fake heartbeat response now carries `headers`, as a `requests.Response` does.

`test/registered/unit/disaggregation/` plus the mini_lb tests: 409 passed. The one failure, `test_mori_deferred_kv_release.py::TestMoriAbortAck::test_failed_status_never_acks (via_drainer=False)`, fails the same way on unmodified main in our environment (`amd_mori` 1.2.3.post1). ruff, ruff-format, isort and codespell pass on the changed files.
