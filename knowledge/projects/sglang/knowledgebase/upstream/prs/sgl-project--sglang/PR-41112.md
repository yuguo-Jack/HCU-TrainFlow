# Add tuned fused-MoE Triton config for E=128,N=768 bf16 on B300 SXM6 PC

[Upstream PR](https://github.com/sgl-project/sglang/pull/41112) · state: closed · merged: False

## Original PR description

Tune the Triton fused MoE kernel configuration for NVIDIA B300 for `E=128, N=768` with BF16. The tuned configuration improves the measured fused MoE kernel latency by **14.21%** over the default heuristic on B300.

## Motivation

The default Triton fused MoE configuration is selected by a heuristic. For the B300 target and the `E=128, N=768` workload, a dedicated tuned configuration provides lower kernel latency.

This workload is used by Qwen3-30B-A3B (TP1) and Qwen3-235B-A22B (TP2).

## Modifications

- Add a Triton 3.7.1 MoE kernel configuration for:
  - Device: NVIDIA B300 SXM6 PC
  - `E=128`
  - `N=768`
  - BF16
- The configuration was tuned directly on the B300 lane.
- The existing down-projection fallback reuses the up-projection configuration, so no separate `_down` configuration is added.
- No kernel or runtime code changes.

## Accuracy Tests

Verified the candidate configuration against the existing `torch_naive_moe` reference across the standard M grid:

`M = {1, 2, 4, 8, 16, 24, 32, 48, 64, 96, 128, 256, 512, 1024, 1536, 2048, 3072, 4096}`

Configuration lookup was also verified to select the new B300 configuration in the candidate arm and fall back to the default heuristic in the baseline arm.

`test/registered/moe/test_fused_moe.py` passes with the existing BF16 accuracy tolerances.

## Speed Tests and Profiling

Measured `fused_moe_grid_us`, defined as the sum of the per-M median kernel latency across the standard M grid, using CUDA events on NVIDIA B300 SXM6 PC x1.

8 trials per arm after 2 warmup trials, interleaved ABBA. Lower is better.

| Arm | n | Median |
| --- | ---: | ---: |
| Baseline | 8 | 1301.70 us |
| Candidate | 8 | 1116.77 us |

This corresponds to a **14.21% reduction** in measured fused MoE kernel latency (`0.8579x` baseline).

The benchmark was performed on:

`E=128, N=768, topk=8, hidden=2048, BF16`

The search used a pruned configuration space covering block sizes, group size, warp count, and pipeline stages. The final configuration was selected from measurements performed directly on the B300 lane.

This is a kernel-level benchmark; no end-to-end model throughput claim is made.
