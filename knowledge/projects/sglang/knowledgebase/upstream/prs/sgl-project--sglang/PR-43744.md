# [Spec] Add aux hidden-state capture for Granite and GraniteMoe targets

[Upstream PR](https://github.com/sgl-project/sglang/pull/43744) · state: open · merged: False

## Original PR description

## Motivation

Granite targets (`GraniteForCausalLM`, and `GraniteMoeForCausalLM` with its `GraniteMoeShared` / `GraniteMoeSWA` subclasses) do not expose aux hidden-state capture, so they cannot serve as targets for aux-hidden-state speculative decoding (EAGLE3, DFLASH, DSPARK). With DSPARK, startup fails with `Model GraniteForCausalLM implements neither set_dspark_layers_to_capture nor set_dflash_layers_to_capture`.

This PR adds the capture hooks, as #31041 did for LFM2. The vLLM counterparts are vllm-project/vllm#60855 (dense Granite) and vllm-project/vllm#61110 (Granite MoE).

## Modifications

`python/sglang/srt/models/granite.py` and `python/sglang/srt/models/granitemoe.py`:

- The inner models record the hidden state before each layer in `layers_to_capture` (and after the last layer when requested) with `AuxHiddenStateList`, and return it with the final hidden states.
- Captures are snapshots. The dense model captures `hidden_states + residual` (a fresh tensor) or a clone of the embeddings at layer 0, because fused add-RMSNorm updates the residual in place. The MoE model clones each layer input, since routed experts may consume their input buffer.
- `GraniteForCausalLM` and `GraniteMoeForCausalLM` gain `set_eagle3_layers_to_capture` and `set_dflash_layers_to_capture`, with the same semantics as Llama / Qwen3 (the state after target layer `k` is captured before layer `k + 1`), and pass the aux hidden states to the logits processor.
- Both expose `get_input_embeddings()` returning the embedding module, which the DSpark worker uses to share the target embedding with the draft. `GraniteMoeModel.get_input_embeddings(input_ids)` is unchanged.
- No behavior change when no capture layers are set.
- New CPU unit test `test/registered/unit/models/test_granite_aux_hidden_capture.py`: capture positions and snapshot semantics for both models, the layer-id mapping of both hooks, and the hand-off to the logits processor.

## Accuracy Tests

- JustinTong0323 · COMMENTED · 2026-10-13T02:27:51Z · [source](https://github.com/sgl-project/sglang/pull/43744#pullrequestreview-5498096818)

Thanks for the PR — this looks correct to me. I checked the implementation against the existing capture hooks on main:

- Hook semantics match `llama.py` exactly: the `val + 1` mapping (state after target layer `k` is captured before layer `k + 1`), the EAGLE3 default `[2, num_layers // 2, num_layers - 3]`, and DFLASH requiring explicit layer ids.
- DSPARK's fallback in `configure_aux_hidden_state_capture` (`set_dspark_layers_to_capture` if present, else `set_dflash_layers_to_capture`) means these two hooks resolve the quoted startup error on their own.
- The snapshot handling fits both layer contracts: dense captures the fresh `hidden_states + residual`, and clones at layer 0 where the residual aliases the embeddings; MoE clones every capture since experts may reuse the input buffer. The `residual is None` layer-0 case is handled more robustly than llama's, which would crash if layer 0 were ever requested.
- Capture after the last layer (`len(self.layers) in layers_to_capture`) matches the LFM2 precedent (#31041).
- `GraniteSWA` / `GraniteMoeShared` / `GraniteMoeSWA` are `pass` subclasses, so they inherit the hooks; `GraniteMoeHybrid` is a standalone class with its own existing capture and is unaffected. Granite has no pipeline-parallel support, so the absence of llama's `is_last_rank` guard is fine.
- The CPU unit test is registered the same way as the sibling granitemoe test, and the snapshot-semantics / layer-mapping cases pin real invariants.

Two non-blocking nits:

- `GraniteMoeForCausalLM.get_input_embeddings()` (returns the module, no args) vs the pre-existing inner `GraniteMoeModel.get_input_embeddings(input_ids)` (returns a tensor) share a name with different contracts. It's what the DFlash worker needs on the outer model, so fine as-is — just a readability wrinkle.
- `test_forward_passes_aux_hidden_states_to_logits_processor` mostly asserts argument pass-through on lambda mocks; the snapshot-semantics and layer-id-mapping tests are the real guards. Consider trimming it, but not required.
