# [Feat] model-loader: Enable model-aware Qwen MTP loading in RunAI ModelStreamer

[Upstream PR](https://github.com/sgl-project/sglang/pull/44703) · state: open · merged: False

## Original PR description

## Motivation

Closes #43196. Depends on the model-selection interface introduced in #44702.

Both PRs target `main`. This single-commit branch includes the shared model hooks and Default Loader changes from that companion PR, plus the RunAI-specific integration and tests. After the companion lands, this branch can be rebased to leave only the RunAI-specific changes.

In two-pass MTP loading, main and draft can share a checkpoint while the draft needs only a small subset of its weights. If RunAI ModelStreamer receives the full file list before model-level filtering, it can read many main-model shards whose tensors the draft will discard, increasing object-storage reads, data processing, and startup cost.

Default Loader and RunAI use different weight iterators, so Default-loader selection does not automatically apply to ModelStreamer. [vLLM #60152](https://github.com/vllm-project/vllm/pull/60152) provides model-owned Default shard selection but does not cover RunAI; the corresponding vLLM RunAI integration is [#60759](https://github.com/vllm-project/vllm/pull/60759).

This PR reuses model-owned rules before RunAI starts weight reads. It also provides a shared entry point for cold loading and storage fallback in [ModelExpress #805](https://github.com/ai-dynamo/modelexpress/issues/805), avoiding a second set of model-naming rules in MX or the generic Streamer loader.

## Modifications

1. **Reuse the model-selection interface.** Pass the actual model's `is_unused_checkpoint_weight(name)` into RunAI weight preparation, sharing the rule with `load_weights`. This PR adds no model-adapter table.
2. **Select files before constructing the Streamer iterator.** Local checkpoints reuse safetensors-header selection. Object-storage checkpoints use the prepared `model.safetensors.index.json` to map required tensor names to shard URIs, then pass the selected list to `runai_safetensors_weights_iterator`. Selection does not require staging the full checkpoint locally.
3. **Preserve compatibility.** Keep mixed shards, extra files retained by existing weight preparation but not described by the index, and original ordering. Missing hooks, missing or unusable optional metadata, unsupported name transformations, or an empty selection retain the original file list. Errors from the model rule or weight reading still propagate.
4. **Coordinate distributed selection.** When ranks have identical original ordered file lists, use the existing WORLD CPU communication group to take the union of required files. If any rank requires the full list, keep the full list for the group. If original lists differ, each rank keeps its own list rather than substituting another node's local paths.

The model adapters in this PR cover Qwen3-MoE, Qwen3-Next, Qwen3.5 (dense/MoE, including the text implementation), and Qwen4-Exp main/MTP loading. Qwen3.5 MTP selection preserves shared embedding weights.

Other architectures can opt in by extracting their existing `load_weights` skip rules into `is_unused_checkpoint_weight(name)`, while preserving required shared weights and quantization metadata. The same rule can then be reused by Default Loader and RunAI ModelStreamer without adding architecture-specific branches to the generic loaders.

This is whole-file selection, not tensor-range reading. Mixed shards may still be read by both main and draft. Weight mapping, quantization, and parameter loading continue to use the existing model logic.

## Speed Tests and Profiling

Qwen benchmark record: 2026-10-09. The measurements below describe the tested configurations and loading paths.

### Object-storage RunAI loading

Qwen3.5 MTP 122B, H20×8, TP=8. The baseline and modified configurations used the same node, checkpoint, BF16 compute setting, launch arguments, and resource requests, with `torch.compile`, CUDA Graph, and warmup enabled on both sides. Main and draft loaded object-storage weights through RunAI ModelStreamer.

| Metric | Baseline | This PR |
| --- | ---: | ---: |
| Main shards | 49 | 49 |
| Draft shards | 49 | **1** |
| Main iterator items | 75,881 | 75,881 |
| Draft iterator items | 75,881 | **1,121** |
| TP0 main load | 116.51s | 106.62s |
| TP0 draft load | 130.73s | **9.09s** |
| Engine-reported combined weight load | 247.26s | **115.75s** |
| Engine-container start to Kubernetes Ready | 484s | **351s** |

In this comparison pair, draft loading decreased by **121.64s, approximately 93.0%**, and observed engine startup decreased by **133s**.

Both configurations reached Kubernetes Ready and completed four fixed generation requests, producing 256 completion tokens per configuration.

These are observations from one comparison pair; cache state and object-storage load were not controlled. Shard and iterator-item counts are not measured OSS bytes. Weight-load intervals are included in startup time and should not be added to it. Generation requests are serving-function checks, not accuracy or acceptance-rate evaluations.

### Automated and distributed validation

Regression coverage includes:

- Applying the model rule before constructing the Streamer.
- Selecting shards from local safetensors headers and object-storage indexes.
- Mixed shards, extra files, missing metadata, and no-hook fallback.
- Two-process Gloo coordination of file selection and fallback.
- Real RunAI reads against a local S3 emulator, checking the requested shard files and returned tensor values.

Synthetic-checkpoint I/O and rule-integration tests are reported separately from real-model GPU performance measurements.

## Relationship to Default Loader and MX

#44702 provides the shared model rules and Default Loader integration; this PR applies the same rules to RunAI ModelStreamer.

MX can reuse framework-owned checkpoint selection by calling a SGLang loader entry point that receives the actual main/draft model. Main/draft P2P pairing, NIXL resource management, shared-tensor handling, and publication lifecycle remain MX responsibilities and are outside this PR's scope.
