# [Fix] Discover the SiMM process NUMA node beyond node zero

[Upstream PR](https://github.com/sgl-project/sglang/pull/42102) · state: closed · merged: False

## Original PR description

## Motivation

SiMM's NUMA-aware NIC selection only checks a CPU's `node0` link. On a worker running on another NUMA node, discovery returns `-1` and skips the local NIC selection even when matching RDMA devices are present. Splitting all of `/proc/self/stat` on whitespace also reads the wrong processor field when the process name contains spaces.

Linux documents CPU links such as [`cpu42/node2`](https://github.com/torvalds/linux/blob/master/Documentation/ABI/testing/sysfs-devices-system-cpu); [`proc_pid_stat(5)`](https://man7.org/linux/man-pages/man5/proc_pid_stat.5.html) places the processor at field 39 after the parenthesized command name.

## Modifications

- Inspect the CPU directory's `nodeN` symlinks instead of hardcoding node zero.
- Parse the processor field after the final closing parenthesis, preserving spaces and parentheses in the command name.
- Keep the existing `-1` fallback when topology information cannot be read.

## Accuracy Tests

Six CPU unit tests cover node zero/nonzero/multidigit nodes, command names, missing or malformed files, unrelated directory entries, and actual constructor NIC selection. The original source fails five assertions; the corrected source passes all six test methods.

Local validation executes the actual helpers and constructor against temporary Linux-shaped proc/sysfs files and real symlinks. Native SiMM storage initialization and warmup are doubled; GPU-facing package initialization is excluded by the local source harness. No RDMA or GPU execution is claimed.
