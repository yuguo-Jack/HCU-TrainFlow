# [Fix] [AMD] kernels: Import the shared HIP helpers in the small-M FP8 block-scale GEMM

[Upstream PR](https://github.com/sgl-project/sglang/pull/45818) · state: closed · merged: False

## Original PR description

## Motivation

On gfx950 with ROCm >= 7.2, every FP8 block-scale linear (`aiter_w8a8_block_fp8_linear`) imports `sglang.kernels.ops.gemm.smallm_fp8_blockscale_gfx950` on first use, and that import fails:

```
ImportError: cannot import name '_check' from 'sglang.kernels.ops.moe.smallm_moe_gfx950'
```

Two changes crossed: #42229 added the small-M FP8 block-scale GEMM, importing the private helpers `_check`, `_hip_lib`, `_hipcc` and `_Kernel` from `smallm_moe_gfx950`; #45112 moved those helpers to `sglang.kernels.jit.utils.hipcc` as `check_hip`, `hip_lib`, `hipcc_path` and `HipKernel`. As a result, models with FP8 block-scale layers fail to start on MI350X/MI355X: for example GLM-5.3-Flash (Quark MXFP4) and DeepSeek-V4-Flash crash during startup on the 2026-10-21 nightly.

## Modifications

- `kernels/ops/gemm/smallm_fp8_blockscale_gfx950/__init__.py`: import `check_hip`, `hip_lib`, `hipcc_path` and `HipKernel` from `sglang.kernels.jit.utils.hipcc`, the shared helpers `smallm_moe_gfx950` itself now uses. Same behaviour; no other change.

## Accuracy Tests

Not applicable (import fix). On MI350X, `rocm/sgl-dev:v0.5.22-rocm724-mi35x-20261021`:

