# [Fix] [CPU] runtime: Defer optional AOT imports for torch_native serving

[Upstream PR](https://github.com/sgl-project/sglang/pull/44064) · state: open · merged: False

## Original PR description

## Motivation

CPU-only `--device cpu --attention-backend torch_native` serving currently fails
at startup when `sgl_kernel` is absent: memory-pool and speculative-worker imports
load CPU AOT operators before those features are used. This prevents the existing
PyTorch fallback from serving ordinary dense FP32 models on an AVX2 host without
AVX-512 or AMX.

## Modifications

Use the existing `LazyImport` helper for CPU-only AOT bindings in nine modules.
The ordinary serving path can then start without the extension. Invoking an
AOT-only feature still loads its original operator and still requires the
extension. No new CLI flag, kernel implementation or ISA build option is added;
this restores the existing `torch_native` option rather than adding AVX2 versions
of AMX kernels.

Related #41727 addresses CPU operator registration for the simulator. This fix
targets real serving startup and installs no simulator stand-ins.

Reproduction (CPU-only Torch environment, locally downloaded model):

```bash
export SGLANG_USE_CPU_ENGINE=1 CUDA_VISIBLE_DEVICES=""
export OMP_NUM_THREADS=4 MKL_NUM_THREADS=4
export SGLANG_CPU_OMP_THREADS_BIND=0,2,4,6
taskset -c 0,2,4,6 python -m sglang.launch_server \
  --model-path /path/to/Qwen2.5-Coder-1.5B-Instruct \
  --device cpu --dtype float32 --attention-backend torch_native \
  --disable-overlap-schedule --disable-cuda-graph --tp 1 \
  --max-running-requests 1 --max-total-tokens 4096 --context-length 2048 \
  --enable-cache-report
```

Before: `ModuleNotFoundError: No module named 'sgl_kernel'` from
`kernels/ops/kvcache/cache_move.py` during startup.
After: the server completes full generation requests with radix cache on/off.
