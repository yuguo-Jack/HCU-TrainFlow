# [Perf] tokenizer_manager: Optionally wrap SHM features off the event loop

[Upstream PR](https://github.com/sgl-project/sglang/pull/46797) · state: open · merged: False

## Original PR description

## Motivation

With the shared-memory feature transport, `TokenizerManager._send_one_request` calls `wrap_shm_features` on the event loop. That call creates a shared-memory segment per multimodal feature and copies the tensor into it. Large features take a long time: a 16K-token video request carries about 200 MB of BF16 pixels, which takes about 106 ms. During that time the tokenizer manager accepts and processes no other request, so concurrent multimodal requests queue behind each other.

## Modifications

- `SGLANG_SHM_WRAP_OFF_LOOP` (default off) and `SGLANG_SHM_WRAP_THREADS` (default 4) in `environ.py`.
- `tokenizer_manager.py`: with the variable on, `_send_one_request` awaits `_wrap_shm_features_off_loop`, which runs `wrap_shm_features` on a dedicated, lazily created thread pool.
  - If the request is cancelled while the copy runs (client disconnect), the request is never dispatched. Its segments are released with `discard_shm_features` once the copy finishes.
  - With the variable off, the call stays inline as today.
- Ordering: with the variable on, two requests can reach the scheduler in a different order than they finished tokenization, if the later one has smaller features. Requests are independent, so this only changes arrival order.
- Test: `test/registered/unit/managers/test_tokenizer_manager_shm_wrap.py` (CPU). It checks that:
  - the wrap runs on a pool thread;
  - a cancelled caller releases the wrapped features;
  - `_send_one_request` wraps inline by default and off the loop with the variable on.

  It is a new file next to the existing tokenizer-manager unit tests. Reviewers may prefer it merged into an existing file under `test/registered/unit/managers/`; that is fine with me.

## Accuracy Tests

The output does not change: the same tensors are copied into the same segments.

From a clean checkout (CPU):

```bash
python3 test/registered/unit/managers/test_tokenizer_manager_shm_wrap.py   # 4 tests OK
```

This passed on a downstream fork whose `python/` and `test/` trees match this repository's layout. The patch applies cleanly to this repository's main.

On an earlier version of this change, with an internal multimodal model, greedy outputs with the variable on and off were identical on 8/8 multimodal requests.

## Speed Tests and Profiling

Measured on an earlier version of this change, with the same model:

- The change removes about 106 ms of event-loop work per 16K-token video chat request.
- Measured together with the prompt re-encode change (separate PR) and processor-side changes:
  - first-wave TTFT P50 went from 8.2 s to 4.1 s;
  - tokenizer-process CPU went from 4.5 to 1.1 cores per serving instance;
  - throughput did not change, because the workload is device-bound.
