# [Feat] [Intel] Model-enabling: Enable MiMo-V2-Flash and MiMo-V2.5 on Xeon CPU

[Upstream PR](https://github.com/sgl-project/sglang/pull/46919) · state: open · merged: False

## Original PR description

## Motivation

Enable `XiaomiMiMo/MiMo-V2-Flash` & `XiaomiMiMo/MiMo-V2.5` models on Xeon CPUs.

## Modifications

- Config dtype conversion: `MiMoV2Config` loads and stores its config items in a Dict rather than normal config object. An on-the-fly conversion is added to align the format.
- Loosen RoPE Q/K Headnum check: MiMo-V2.5 uses grouped-query attention in the vision tower, the inference was blocked by a over-strict Q/K head_num check in `rope.cpp`.
- Adaptive device orientation: In `mimo_audio.py` this was hard-coded as CUDA device.
- Fix for `req_to_token` index overflow: `req_pool_id` was stored as an int32, models that support long context input like `XiaomiMiMo/MiMo-V2.5` would cause an overflow for default service launching parameters: (max_context_len = 1,048,580, req_pool_id can reach 2048, 2048 * 1,048,580 = 2,147,491,840 > INT32_MAX). Casting `req_pool_id` to int64_t to avoid this. (was covered in #44665 )

## Accuracy Tests

Service launching commands:

```
sglang serve --model-path XiaomiMiMo/MiMo-V2-Flash --device cpu --trust-remote-code --disable-overlap-schedule --tp 4 --reasoning-parser mimo --tool-call-parser mimo --host 0.0.0.0 --port 30000

sglang serve --model-path XiaomiMiMo/MiMo-V2.5 --device cpu --trust-remote-code --disable-overlap-schedule --tp 4 --reasoning-parser mimo --tool-call-parser mimo --host 0.0.0.0 --port 30000
```

Tested with [example request](https://docs.sglang.io/cookbook/autoregressive/Xiaomi/MiMo-V2.5#4-2-reasoning-output), output makes sense (pasting MiMo-V2.5 output as example):

```
====== Reasoning ======
9.11 vs 9.9

Let me compare these two decimal numbers carefully.

9.9 = 9.90
9.11 = 9.11

9.90 > 9.11

So 9.9 is larger.
====== Answer ======
## Comparing 9.11 and 9.9

To compare these properly, I'll align the decimal places:

- **9.11** = 9.11
- **9.90** = 9.90

Looking at the tenths place: **9 > 1**

**9.9 is larger.**
```
