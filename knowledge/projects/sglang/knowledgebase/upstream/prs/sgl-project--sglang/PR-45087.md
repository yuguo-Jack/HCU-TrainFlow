# [Fix] constrained: bound the compiled-grammar cache (LRU) to stop host-memory growth with per-request schemas

[Upstream PR](https://github.com/sgl-project/sglang/pull/45087) · state: open · merged: False

## Original PR description

## Motivation

`BaseGrammarBackend.cache` is a plain `dict` that is never evicted. Each compiled grammar (xgrammar / outlines / llguidance) holds per-vocabulary token tables; with a 150k-token vocabulary we measured **+250–380 MB of scheduler RSS per previously-unseen `json_schema`**. Agent frameworks commonly embed per-call values (enums, defaults, descriptions) inside the schema, so every request is a cache miss and the scheduler grows until the host runs out of RAM.

In production (Qwen3.6-35B-A3B-FP8, `--dp-size 4`, 4× H100 NVL, 128 GB RAM + 61 GB swap, SGLang 0.5.10.post1) one client with ~1,250 distinct schemas/day drove each scheduler from 3.5 GB to 35 GB in 11 days; RAM and swap filled and the server stalled for 25 minutes. `/flush_cache` clears the cache but is refused unless the server is fully idle, so it is not a mitigation under load. The cache code is unchanged on `main`.

Fixes #45077.

## Changes

- `BaseGrammarBackend.cache` becomes an `OrderedDict` used as an LRU: a hit moves the key to the MRU end, `set_cache` evicts from the LRU end while `len(cache) > cache_max_entries`.
- Bound is `DEFAULT_CACHE_MAX_ENTRIES = 64`, overridable by constructor argument or `SGLANG_GRAMMAR_CACHE_MAX_ENTRIES`; `<= 0` restores the previous unbounded behaviour.
- Eviction is safe for in-flight requests: `get_cached_or_future_value` already hands out `value.copy()`, so a request never references the cached instance.
- `reset()` unchanged.

Why 64: enough for every realistic set of *reused* schemas (the common case is a handful per client), while capping worst-case memory at tens of GB instead of unbounded. With this change our 4-rank deployment plateaus at 12–21 GB total after 17 h instead of growing without limit; single-stream throughput is unchanged (334 → 333 tok/s).

## Follow-ups (separate PRs)

1. Pass `cache_limit_bytes` to xgrammar's `GrammarCompiler` (its internal cache is also unbounded by default).
2. Optionally skip caching grammars whose key exceeds a size threshold (a single 60 KB schema compiles to several GB and is almost never reused).
3. Expose these knobs as server arguments.

## Tests

`test/registered/unit/srt/constrained/test_grammar_cache.py` (CPU-only, ~1 s): default/env/constructor bound, LRU eviction order, hit refreshes recency, copies returned on hit, eviction does not affect in-flight copies, miss-after-eviction recompiles, `<= 0` disables bound, `reset()`, repeated same-key insert.
