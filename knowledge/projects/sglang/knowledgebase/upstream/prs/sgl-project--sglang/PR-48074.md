# [Feat] [Intel] video_decoder: Decode video on the XPU media engine via torchcodec-xpu

[Upstream PR](https://github.com/sgl-project/sglang/pull/48074) · state: open · merged: False

## Original PR description

## Motivation

On Intel XPU, video inputs are decoded on the host CPU; this decodes them on the GPU media engine through the torchcodec-xpu plugin, as CUDA already does with NVDEC.

## Usage

`SGLANG_ENABLE_XPU_VIDEO_HW_DECODE=1` (default `0`, opt-in): on XPU, with torchcodec-xpu installed, video inputs decode on the media engine and the frames stay on the XPU. Decoded frames need memory headroom on the card, so pick a `--mem-fraction-static` that leaves room. Without it, or on other platforms, decode stays on the CPU as before.

## Accuracy Tests

Decoded frames match CPU decode within colour-conversion rounding (max 2 levels, XPU hardware test). The Qwen3-VL video e2e test passes on XPU.

## Speed Tests and Profiling

Intel Arc Pro B60, torch 2.14.0+xpu, torchcodec-xpu 0.17.0.

| Workload | Hardware decode off | On |
|---|---|---|
| Decode 60 frames of 720p, standalone | 482 ms, 9.8 CPU-s | 471 ms, 0.1 CPU-s |
| Qwen3-VL-2B, 32 video requests, conc 8: server CPU per request | 22.8 s | 7.8 s |
| Qwen3-VL-2B, conc 8: requests/s | 0.27 | 0.24 (no gain; run-to-run noise 14%) |
| Gemma-4 E2B, conc 8: requests/s | 1.25 | 1.63 |
| Gemma-4 E2B, conc 8: TTFT p50 | 4.20 s | 2.33 s |
| Qwen3-Omni-30B-A3B, TP 4, conc 1: tokenizer CPU per request | 19.0 s | 4.0 s |
| Qwen3-Omni-30B-A3B, TP 4, conc 1: requests/s | 0.07 | 0.07 |

Prefill-bound models (Qwen3-VL, Qwen3-Omni) gain host CPU, not throughput; models with a short prefill (Gemma-4) gain end to end. Decoded frames use device memory outside `--mem-fraction-static`, so the docs advise headroom on the decoding card.

Related: #42627 (open) also adds torchcodec-xpu, pinned to 0.15.0 for torch 2.13; main needs 0.17.0. #44966 (open) moves device calls onto `current_platform`, which `_parallel_decode` follows here.
