## Motivation

With fused shared experts in per-rank slots (`--enforce-shared-experts-fusion` with a DeepEP-class or `megamoe` a2a backend), every MoE layer renormalized its routed weights over one routed expert too many on CUDA, so the routed experts it kept summed to about 0.85-0.97 instead of 1.0.

How it happened:

1. On the per-rank slot path `select_experts` gives the router no shared slot (`num_fused_shared_experts=0`), because `_post_process_topk_ids` appends the shared column afterwards. On aiter it also gives the router the routed count, `top_k - num_fused_shared_experts`. Off aiter every router call kept `top_k` (`num_routed_topk if _use_aiter else top_k`), which counts the shared slot.
2. So the router selected `top_k` routed experts, one more than the model's `num_experts_per_tok`, and renormalized their weights to sum to 1.
3. `remap_topk_for_per_rank_shared_slots` then overwrote the last column with the home-rank shared expert.
4. The routed experts kept sum to `sum(top K) / sum(top K+1)`, per token, in every layer. The CUDA routers return their top-k sorted by score, so the kept experts are the right ones; only their weights shrink.

#36515 (non-grouped routers) and #40943 (grouped routers) gave the router 0 shared slots on this path. That fixed aiter, where the router already gets the routed count, and left CUDA in the state above. Before them, CUDA gave the router `top_k` with the shared slot, which selects the routed count and renormalizes over it.

Kept routed weight sum per token, one H200, 64 tokens of random logits, EP8, rank 3, one shared expert:

| Router path | Before | After |
|---|---|---|
| grouped sigmoid + bias, 256 experts, top-8 (DeepSeek-V3 shape; FlashInfer router after the fix, Triton fallback before) | 0.873-0.913 | 1.0000 |
| grouped sigmoid + bias, 384 experts in 8 groups, top-8 | 0.873-0.914 | 1.0000 |
| grouped, one group, sigmoid + bias, 384 experts, top-8 (Kimi-K2 shape) | 0.873-0.919 | 1.0000 |
| grouped softmax, no bias, 64 experts, top-6 | 0.886-0.967 | 1.0000 |
| ungrouped sqrtsoftplus + bias, 256 experts, top-6 (DeepSeek-V4) | 0.850-0.885 | 1.0000 |
| ungrouped sigmoid + bias, 256 experts, top-8 | 0.877-0.912 | 1.0000 |
| ungrouped softmax, 128 experts, top-8 | 0.909-0.949 | 1.0000 |
| `HashTopK` (DeepSeek-V4 hash layers), torch and fused kernel | 1.0000 | 1.0000 |
| DeepSeek-V4.1 vision routing on MegaMoE | 1.0000 | 1.0000 |

In every row the routed experts equal routing without fusion (64/64 rows) before and after; the shared column is the home-rank slot with weight `1/routed_scaling_factor`.

Affected: CUDA, and other platforms without aiter, with shared-experts fusion on a per-rank backend (`deepep`, `mooncake`, `mori`, `pplx`, `megamoe`); for the DeepSeek family that takes `--enforce-shared-experts-fusion`. The original per-rank normalization bug does not affect aiter, Waterfill, the global fused slot (no a2a backend), runs without fusion, `HashTopK` and the DeepSeek-V4.1 vision routing, whose routers already select the routed experts alone.

Two related problems on the same path are fixed here too:

- **FlashInfer's DeepSeek router ignores `renormalize`.** `fused_topk_deepseek` always normalizes the selected weights, and its ninth parameter is `launch_with_pdl`, which sglang's wrapper called `renormalize`. With routed-only sizing the per-rank top-8 path now fits that router (top-9 did not), so a `renormalize=False` configuration would have been normalized. Configurations without fusion or with the global slot already were, within that router's shapes. Grouped sigmoid routing with a bias, 256 experts in 8 groups, top-8, `renormalize=False`, zero logits (each raw weight is sigmoid(0) = 0.5): before this PR 0.125 per expert without fusion and 0.5 with a per-rank slot; with this PR's first version 0.125 for both; now 0.5 for both.
- **Padded rows on the per-rank path.** The append shifted a padded row's `-1` to `-1 - num_fused_shared_experts` and gave it a live home-rank shared slot, so padded rows did not leave top-k as `-1`. `HashTopK` and the vision routing already mask after their append.

The `renormalize=False` guard also exposes the Triton global shared-slot path. That path previously wrote `sum(selected routed scores) / rsf` before normalization, so disabling normalization made the shared output depend on the routed-score sum (4x for eight zero-logit sigmoid selections). It now writes a shared weight of 1 when rsf is folded, otherwise 1/rsf, after processing the routed weights. The dynamic-bias torch route receives the corresponding repair from #44901.

## Modifications

- `select_experts` decides once, for every router, what the router is asked for: where `_post_process_topk_ids` appends the shared columns (aiter, per-rank slots), the routed count with no shared slot; otherwise `top_k` with the shared slots, as before. The values are unchanged on aiter, on the global slot and without fusion.
- `remap_topk_for_per_rank_shared_slots` takes the routed columns and appends the shared ones, the contract `fused_append_remap_shared_experts_deepep` already has on aiter. Routers that still write shared placeholders (the per-token-bias router, the DeepSeek-V4.1 vision routing, `HashTopK`) have them dropped before the append. On CUDA the EPLB remap splits off shared columns only when the router wrote them, and padded rows are masked again after the append.
- `biased_grouped_topk_gpu` takes the FlashInfer branch only when renormalizing; otherwise the Triton router, which honors `renormalize`, serves the call. The wrapper's last parameter is renamed `launch_with_pdl`, and the global shared columns that branch appends take `fused_shared_expert_weight(...)`.
- `RoutedExpertsCapturer.capture` pads routed-only ids (the device width minus the fused shared experts) to its device width and raises on any other width; the host side already keeps only `num_experts_per_tok` columns. The per-rank path now captures routed-only ids, and without the pad `--enable-return-routed-experts` would fail with a shape mismatch.
- The fused aiter kernel's docstrings name its eager twin.
