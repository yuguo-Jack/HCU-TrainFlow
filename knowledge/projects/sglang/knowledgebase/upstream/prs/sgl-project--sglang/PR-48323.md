# [CI] [AMD] miles: Skip MI30x tests whose kernels exceed gfx942 LDS

[Upstream PR](https://github.com/sgl-project/sglang/pull/48323) · state: closed · merged: True

## Original PR description

## Motivation

Three Miles tests in the MI30X nightly fail on every run that reaches them, because a kernel asks for more LDS per block than gfx942 has (64 KiB). They pass on MI35X.

| Test | Job | Error |
|---|---|---|
| `tests/fast-gpu/kernels/attention/dsa/test_dsa_indexer.py` | 2-GPU | tilelang `indexer_fwd_kernel_kernel`: `Requested dynamic shared memory 98304-102400 exceeds device limit 65536` |
| `tests/fast-gpu/kernels/attention/dsa/test_dsa_sparse_attention.py` | 2-GPU | tilelang `main_kernel`: 81920-157696 bytes requested, same limit |
| `tests/e2e/megatron/model_scripts/test_qwen3_8_next_4layer_ci.py` | 8-GPU | Triton `OutOfResources: out of resource: shared memory, Required: 73728, Hardware limit: 65536` during training |

The two DSA tests first ran on MI30X on 11-02, when the 2-GPU job stopped timing out, and failed then and on [11-03](https://github.com/sgl-project/sglang/actions/runs/41728316389). `test_qwen3_8_next_4layer_ci` hit the Triton error on [11-01](https://github.com/sgl-project/sglang/actions/runs/41355713231) and 11-03; on 11-02 it failed earlier with an unrelated error.

## Modifications

Add them to `skip_tests` in `nightly-test-amd-miles-rocm10-mi30x.yml`, next to `test_glm5_2_744b_a40b_5layer_ci`, which is skipped for the same reason. `test_qwen3_8_next_4layer_ci` goes on both 8-GPU parts: files are removed before `run_suite.py` partitions the suite, so both parts must remove the same files to split the same list.

## Test plan

- [x] All three paths exist in miles `main`; the matrix parses with the new `skip_tests`.
- [ ] Next MI30X Miles nightly: the skip step removes the files and the remaining tests run.
