# [Fix] moe: Avoid stale prefix reads in ep_scatter

[Upstream PR](https://github.com/sgl-project/sglang/pull/44974) · state: closed · merged: True

## Original PR description

We hit an illegal memory access while running GLM-5.3-Flash + DFlash2 with TP8 on H20. We traced it to `_fwd_kernel_ep_scatter_1`.

In this kernel, every program writes the full expert offset table, then reads its own offset back from global memory. The writes and reads are not properly synchronized, so the read can return a stale value.

This PR follows the approach in #31930: compute the current offset directly from the expert token counts, and have each program write only its own entry. This avoids the stale read and removes the repeated full-table writes.

## Testing

- All 4 regression tests passed on H20, covering empty experts, tile boundaries, CUDA Graph replay, and BF16/FP8 scatter.
- Compute Sanitizer reported no memory errors.
- With the fix and CUDA Graphs enabled, the serving setup that originally failed completed the 32-request benchmark at concurrency 1 and 32.

To run the tests:

```bash
PYTHONPATH=python python test/registered/kernels/ops/moe/test_ep_scatter.py -v
```

The kernel was faster in isolated tests than the approach in #31930. We did not see a noticeable end-to-end speedup over our earlier correctness-only patch. Full model accuracy evaluation has not been run.

Related: #31929, #31930.


The multimodal padding values can exceed the int32 range, while this history copy uses `torch.int32`. Both are already present in the base commit (`4ec19ca27`); this PR does not change them. The server then exits, causing the remaining MMMU-Pro requests to fail.
