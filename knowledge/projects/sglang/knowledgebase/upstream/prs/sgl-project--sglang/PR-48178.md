# [Fix] kimi-k3: Verify DFLASH on cutedsl_mla under DCP

[Upstream PR](https://github.com/sgl-project/sglang/pull/48178) · state: open · merged: False

## Original PR description

## Motivation

The published Kimi-K3 DFLASH recipes with DCP, such as TP8 DCP8 on B300, stop at CUDA graph capture on main, so the server does not start.

This hits DFLASH users on all 13 cookbook DCP cells that offer it (B300, GB300, GB200, and B200 Decode).

The published DFLASH flags fail this way at TP4 DCP4 on 4 B200 GPUs with a reduced K3 config and dummy weights. At TP8 and TP16, only the resolver ran: `prefill` on main, `decode` with this change.

Under DCP, the K3 override sets `speculative_attention_mode` to `decode` only for DSPARK. DFLASH stays on `prefill`, so target verify runs on `trtllm_mla`, which refuses this path:

```
trtllm_mla cannot forward a global causal bound to its decode kernel, which is required for DCP with q_len > 1 (speculative target-verify / draft-extend); select cutedsl_mla for a DCP speculative run
```

Explicit `--speculative-attention-mode decode` avoids this, but no published command sets it.

We found no open PR that fixes this: #43599 covers EAGLE3 only, and #47142 reports DFLASH at TP8 DCP8 on GB300 without changing this override or showing a mode flag.

## Modifications

On the K3 DCP override's `cutedsl_mla` path, DFLASH now resolves the mode to `decode`, as DSPARK does. Recipe flags, AITER, and NPU paths do not change.

An explicit `--speculative-attention-mode prefill` now becomes `decode` with no log line, as for DSPARK. Lower-case `dflash` still fails at capture.

## Accuracy Tests

Servers used the Motivation setup, so accuracy and acceptance were not measured.

- The PD decode role (fake transfer backend) failed the same way on main. With the fix, it and the published flags run verify. Published-flag tokens and logprobs match main with explicit `decode`.
- With a local patch that drafts the NOSPEC continuation, logprobs over the matching token prefix stayed within 0.002 of NOSPEC at dummy range +/-0.05. A verify causal bound smaller by one raised that to 0.023. Near-uniform logits make tokens diverge after that prefix.

Not checked: B300, GB200, GB300, multi-node runs, a real PD transfer, HiCache, AITER, NPU, `--enable-unified-memory`, and a server run on current main.

## Speed Tests and Profiling

Not measured. A PD prefill role with `--dcp-size` above 1 also moves to `decode`. It does not verify, and a fake-transfer check kept its first token and logprob.
