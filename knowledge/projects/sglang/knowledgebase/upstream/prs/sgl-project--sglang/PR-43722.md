# [MemCache] Add shared component size and path APIs to the tree core interface

[Upstream PR](https://github.com/sgl-project/sglang/pull/43722) · state: closed · merged: True

## Original PR description

## Motivation

`UnifiedTreeCore.adjust_component_ledger` lets a component whose per-node
reclaimable figure (`TreeComponent.reclaimable_tokens`) changes in place move
the evictable/protected ledgers without a lock transition, but it exists only
on the Python core and takes a concrete Python node. The Rust core, now the
default backend, has no equivalent, so a caller written against
`UnifiedTreeCoreInterface` cannot do this accounting portably. Callers that
read a root-to-node path likewise have no backend-neutral way to get node
spans without walking Python node objects.

## Modifications

- Add `adjust_component_size(node_id, component_type, delta)` to
  `UnifiedTreeCoreInterface`. It resolves the node id, validates the
  component, and moves the ledger the node is on by `delta`. Roots and nodes
  without a device value are no-ops; a missing handle raises `KeyError` and a
  disabled component raises `ValueError`. The Rust core also rejects a delta
  that would underflow or overflow the ledger, and leaves both ledgers
  untouched on every error.
- Add `collect_path_info(end_node_ids)`, which returns, per input id, the
  root-to-node path (root excluded) as frozen `TreePathNodeInfo` records:
  `node_id`, `parent_id`, half-open root-relative `path_start`/`path_end`
  offsets (bigram atoms for bigram trees), and `full_value_len` (`None` when
  the FULL value is absent). The Rust binding copies each batch under one
  tree lock.
- Implement both on the Python core (renaming `adjust_component_ledger` to
  the new signature) and on the Rust core and PyO3 bindings, and update the
  existing unit test that called the old name.
- Tests: Rust unit tests for ledger movement across lock transitions and
  eviction, error paths that leave both ledgers intact, root/tombstone no-ops,
  and path offsets for plain and bigram keys; shared Python tests run the
  same contract against both backends.
