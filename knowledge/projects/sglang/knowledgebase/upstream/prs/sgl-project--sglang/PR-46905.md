# [Perf] Hunyuan3D: Speed up shape export with GPU-side grid generation

[Upstream PR](https://github.com/sgl-project/sglang/pull/46905) · state: closed · merged: True

## Original PR description

## Summary

- Construct the Hunyuan3D `VanillaVolumeDecoder` dense coordinate grid on the GPU instead of building the full grid with NumPy and copying it from CPU.
- Preserve the original `np.linspace(..., dtype=np.float32)` values for the three axes, then transfer those axes and use `torch.meshgrid(indexing="ij")` and `torch.stack` on the latent device. This keeps the previous coordinate rounding and ordering.
- Leave geo-decoder chunking, marching cubes, other volume decoders, and output formats unchanged. No new runtime flag or dependency.

## Motivation

For Hunyuan3D-2 shape-only generation at 384 octree resolution, the original dense-grid path constructs approximately 57 million query points on CPU before transferring them to GPU. Synchronized diagnostic profiling attributed approximately 420 ms to NumPy grid generation and 51 ms to grid transfer/layout within a roughly 6.2 s Shape Export stage.

## H200 benchmark

Single NVIDIA H200; `tencent/Hunyuan3D-2`, shape only, `lossless`, eager (`torch.compile=false`), 32k geo-decoder chunks, 50 denoising steps, guidance 5.0, seed 42, and a fixed input image. Baseline and candidate used separate worktrees, fresh processes, the same request warmup, and native SGLang perf dumps without extra per-stage synchronization. Eight visits in `A-B-B-A-A-B-B-A` order (four per arm).

| Metric (median) | Native | GPU grid | Latency reduction |
| --- | ---: | ---: | ---: |
| End-to-end | 8,854.62 ms | 8,387.93 ms | **5.27%** (466.70 ms) |
| Shape Export | 6,172.60 ms | 5,703.72 ms | **7.60%** (468.88 ms) |

All four neighboring pairs improved E2E latency (4.56%, 5.19%, 6.58%, and 5.05%). These are measured single-request H200 results, not a general cross-GPU or serving-throughput claim.

## Correctness and tests

- **Full-grid exactness:** all **57,066,625 coordinates** of the `385³` production grid matched the original NumPy reference bit-for-bit when captured at the geo-decoder input.
- **Mesh parity:** all **8/8** production runs saved byte-identical OBJ files (SHA256 `74c2a1318c394fbfe2e3dfc93253cc6ac513bf8b1d0d6ac435603e8e3f18315f`).
- **Targeted unit test:** `test_hunyuan3d_gpu_grid.py` passed on H200 (`1 passed`, `4 subtests passed`, 9.83 s), covering CPU/CUDA and float32/float16 query-coordinate parity against the original NumPy reference. Pytest reported 20 warnings.

Investigation history and the separate experimental screen: [Hunyuan3D H200 investigation log](https://github.com/charliechenye/sglang/issues/2).

### Additional H200 validation: TorchCompile enabled

We also validated the GPU-side grid optimization with `torch.compile=true` (`max-autotune-no-cudagraphs`).

Setup: single NVIDIA H200, Hunyuan3D-2 shape-only, lossless quality, 32k geo-decoder chunks, 50 inference steps, fixed image and seed.

Eight fresh-process visits were run in ABBA order (four per arm).

| Metric (median) | Native | GPU Grid | Improvement |
| --- | ---: | ---: | ---: |
| End-to-end | 11,301.64 ms | 10,846.93 ms | **4.02%** |
| Shape Export | 6,156.11 ms | 5,700.87 ms | **7.39%** |

All four adjacent pairs showed positive E2E improvements.

**Correctness:** All eight runs produced byte-identical OBJ files (SHA256 `db670bd7ddbe78a3e2f1b497e0ee2e903bf60f826680f3fd255bcf802149d867`).

The absolute E2E reduction (~455 ms) closely matches the Shape Export reduction (~455 ms), consistent with the optimization being isolated to grid generation.

The compiled and eager configurations were evaluated separately; cross-configuration mesh identity is not claimed.

Together with the eager-mode results, this confirms a consistent GPU Grid benefit in both tested execution modes.
