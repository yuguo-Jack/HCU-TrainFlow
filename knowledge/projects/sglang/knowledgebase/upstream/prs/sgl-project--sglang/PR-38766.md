# [diffusion] Enable rank-local TP checkpoint loading for MiniMax-H3

[Upstream PR](https://github.com/sgl-project/sglang/pull/38766) · state: open · merged: False

## Original PR description

## Motivation

Native MiniMax-H3 uses a custom grouped-QKV weight loader, which prevents the existing rank-local TP checkpoint fast path from accepting the model. The ordinary path copies each full parameter to the GPU before invoking its TP weight loader, even though the final parameters are already sharded.

This PR enables rank-local checkpoint loading for native, unquantized H3. It also replaces the fused-only `MergedColumnParallelLinear` slicing added in #35990 with validated per-parameter read plans, so packed layouts are checked at admission, before any payload is read, and fall back as a whole instead of failing mid-read.

## Modifications

- Extend the existing `rank_local_checkpoint.py` path with validated per-parameter read plans; reuse its safetensors inventory, source mapping, `LocalTPShard`, and existing materialization code.
- Let H3 explicitly opt in to reading this rank's contiguous grouped heads, then reorder only the local CPU slice into Q/K/V layout before device loading. Keep the ordinary weight loader and FSDP's global-reorder-before-slice transform unchanged.
- Replace #35990's `output_sizes` slicing with a `packed_sizes` read plan: each logical matrix of a fused weight/bias is still sharded independently, and separately stored sources are validated against `output_sizes`. The upstream fused merged-column unit test is kept and adapted to the new argument.
- Keep conservative, all-or-nothing admission before payload reads. Unsupported custom/quantized loaders, parameter subclasses, metadata and incompatible layouts fall back; invalid opted-in transforms fail explicitly.
- Add deterministic TP2/TP4 slicing and fallback tests, plus a manual complete-checkpoint TP parity checker.

No new CLI flags, model-forward changes, or weight-cache/IPC infrastructure. TP1 and FSDP loading behavior is unchanged.


**Complete native-checkpoint parity on two H200s:** all 535 tensors on each TP2 rank match the ordinary production loader exactly with `torch.equal`. Shapes, BF16/FP32 dtypes, devices, and parameter/buffer registration also match. The checker asserts that both ranks use the fast path:

```bash
PYTHONPATH=python torchrun --standalone --nproc-per-node=2 \
  python/sglang/multimodal_gen/test/unit/manual/check_minimax_h3_tp_loading.py \
  --transformer /path/to/FL2VA/transformer
```

**Full output parity against the unmodified base commit:** two T2VA requests through the real HTTP video API, with the native FL2VA checkpoint, TP2, identical prompts/seeds/request order, and no loader or inference hooks. Both use `num_inference_steps=50` (the full native schedule: 49 denoiser updates), not the shortened startup warmup.

## Speed Tests and Profiling

Compared base `2092f6df05` with `9b04d4442f` on **2×H200**, using the original unquantized `MiniMaxAI/MiniMax-H3` FL2VA checkpoint (snapshot `42ed227ee7df40d41602854ae760620d6eb651fe`). No weight-cache service or checkpoint conversion is involved.

**NVMe, TP2: three paired starts per cache condition**, alternating baseline/candidate order. Values below are medians; transformer loading uses the slower rank, and HTTP health is measured from process launch through server readiness/warmup.

| Local page cache | Transformer: base → PR | Reduction | HTTP health: base → PR | Reduction |
|---|---:|---:|---:|---:|
| Cold | 25.98 → 15.88 s | 38.9% | 84.41 → 76.08 s | 9.9% |
| Warm | 14.20 → 7.26 s | 48.9% | 65.07 → 58.35 s | 10.3% |

Every NVMe pair improved both metrics. Cold/warm local file-page residency was verified as 0%/100%. Startup measurements include server warmup with `--warmup-resolutions 1344x768 --warmup-num-frames 96 --warmup-steps 2`; the full-schedule output tests above are separate.

Additional **single-pair boundary checks**, not replicated performance claims:

- GPFS, TP2, cold local page cache: transformer **101.17 → 33.74 s**, health **232.00 → 164.82 s**. GPFS server-side cache was not controlled.
- NVMe, SP2, warm local page cache: transformer **14.24 → 14.07 s**, health **65.68 → 65.56 s**—effectively unchanged, as expected for the TP1 transformer path.

All **16 server starts/warmups passed**, with 192 successful component-load spans verified across both ranks.

The logical H3 checkpoint payload per TP2 rank drops from **61.73 GiB to 30.86 GiB** before device loading; final parameter shapes are unchanged. This is not a measurement of physical disk or PCIe traffic. CPU slicing/repacking increases host CPU work: the test host has 192 logical CPUs and uses the existing 16-intra-op-thread budget per worker. NVMe-cold process high-water RSS sampled at transformer-load completion decreased from **66.17 to 59.64 GiB**. CPU-constrained and unified-memory hosts were not benchmarked.
