# [Fix] disaggregation: bound staging requests by destination pages

[Upstream PR](https://github.com/sgl-project/sglang/pull/46150) · state: open · merged: False

## Original PR description

## Motivation

Fixes #39764. Decode currently grows `chunk_staging_infos` to the chunk index in a `STAGING_REQ`, even when that index is outside the destination pages allocated for the request. The allocation-failure branch grows the same list. Negative indices can also index the wrong slot or raise `IndexError`.

Credit to the page-count approach in #39792 by gokay-ai, which was closed without merging. This change requires the locally published page count instead of using a fallback cap, also bounds the requested page count, and prevents rejected requests from registering a watermark subscriber.

## Modifications

- Mooncake and NIXL receivers record the destination suffix page count before publishing their staging room.
- The shared request handler rejects negative/out-of-range chunk indices and nonpositive/oversized page counts before touching allocator or receiver state. It reports whether a request was accepted so the caller only subscribes accepted requests to watermarks.
- Extend the existing CPU wire tests with both metadata publishers, boundary rejection on both allocator outcomes, subsequent valid requests, out-of-order/duplicate chunks, and permanent allocation-failure replies. Keep the existing PP response-routing test.

The bound is the destination page count, not a chunk count inferred from decode's configuration: prefill chooses its own chunk size, and one-page chunks must remain valid.
