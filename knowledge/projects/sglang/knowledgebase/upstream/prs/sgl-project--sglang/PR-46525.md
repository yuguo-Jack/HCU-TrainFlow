# [Fix] gdn: Keep a mixed batch's decode tail on the decode kernels under deterministic inference

[Upstream PR](https://github.com/sgl-project/sglang/pull/46525) · state: open · merged: False

## Original PR description

## Motivation

Fixes #46446. With `--enable-deterministic-inference` and `--enable-mixed-chunk`, Qwen3.5-9B's greedy output for a request changes when another request's prefill is mixed into one of its decode steps.

`EagerRunner.execute` runs a MIXED batch as EXTEND, so the GDN layers process each running request's decode token as a 1-token sequence through the chunked prefill kernel (`chunk_gated_delta_rule`). Without mixed chunk, the same token goes through the recurrent decode kernel. The two are mathematically equal but not bitwise equal, and the difference stays in the recurrent state. In the issue's repro only one step is mixed (the 255-token intruder plus the target's 1-token tail at prefix 4120), and that step is enough to flip the target's greedy token about 100 tokens later. The full-attention layers (Triton, deterministic) do not need a change: with only the GDN layers fixed, the outputs match exactly.

## Modifications

- `ForwardBatch.num_mixed_decode_reqs`: the number of running requests that `mix_with_running` appended to a MIXED batch, set in `init_new` from `mix_running_indices_cpu`. This is needed because the eager runner relabels the batch as EXTEND before the attention backends see it. TBO children set it to `None`.
- `GDNAttnBackend`: under deterministic inference, `init_forward_metadata` cuts a mixed batch once per forward into its prefill rows and its decode tail (`build_gdn_mixed_decode_split`). `forward_extend` then runs the prefill rows through the unchanged extend path and the tail through `forward_decode`, the same path a decode step takes. The tails are untracked in a mixed step (as in `mix_with_running`), so no state tracking changes.
- The split is skipped, and behavior is unchanged, when deterministic inference is off, with MIS, with ReplaySSM (its decode path needs per-row ring metadata that a mixed batch does not build), and when the batch no longer ends in 1-token rows.

```python
"""sgl-project/sglang#46446: greedy outputs at client concurrency 1 vs 8.

Same engine settings as the issue's repro.py. 32 prompts of 300-3000 tokens cut
from different offsets of the repro's long prompt, 64 new tokens each.
Usage: python conc.py <model> <pair_T3.jsonl> <port> <out.json>
CONC_MIXED=0 disables mixed chunk, CONC_RADIX=0 disables the radix cache.
"""

import asyncio
import json
import os
import sys

import sglang as sgl

model, pair_path, port, out_path = sys.argv[1], sys.argv[2], int(sys.argv[3]), sys.argv[4]
base = json.loads(open(pair_path).readline())["target"]["prompt_token_ids"]
prompts = []
for i in range(32):
    length = 300 + (i * 977) % 2700
    start = (i * 131) % max(1, len(base) - length)
    prompts.append((base * 2)[start : start + length])


async def run(engine, concurrency):
    sem = asyncio.Semaphore(concurrency)

    async def one(ids):
        async with sem:
            out = await engine.async_generate(
                input_ids=ids,
                sampling_params=dict(temperature=0, max_new_tokens=64, ignore_eos=True),
            )
            return out["output_ids"]

    return await asyncio.gather(*(one(p) for p in prompts))


if __name__ == "__main__":
    results = {}
    for concurrency in (1, 8):
        engine = sgl.Engine(
            model_path=model,
            dtype="bfloat16",
            tp_size=1,
            context_length=32768,
            mem_fraction_static=0.65,
            max_running_requests=16,
            chunked_prefill_size=2048,
            enable_mixed_chunk=os.environ.get("CONC_MIXED", "1") == "1",
            disable_radix_cache=os.environ.get("CONC_RADIX", "1") == "0",
            mamba_radix_cache_strategy="extra_buffer",
            max_mamba_cache_size=128,
            attention_backend="triton",
            linear_attn_backend="triton",
            cuda_graph_backend_decode="disabled",
            cuda_graph_backend_prefill="disabled",
            skip_tokenizer_init=True,
            enable_fp32_lm_head=True,
            random_seed=42,
            enable_deterministic_inference=True,
            port=port,
            log_level="warning",
        )
        try:
            results[concurrency] = asyncio.run(run(engine, concurrency))
        finally:
            engine.shutdown()
    diff = [i for i, (a, b) in enumerate(zip(results[1], results[8])) if a != b]
    json.dump(dict(results={str(k): v for k, v in results.items()}, different=diff), open(out_path, "w"))
    print(f"DIFFERENT {len(diff)}/32 {diff}")
```

## Speed Tests and Profiling

The default path is unchanged: the split only runs under `--enable-deterministic-inference`, and only for a mixed batch. There it adds two shallow `ForwardBatch` copies and two metadata copies per forward (shared by all GDN layers), and splits each GDN layer's call into one extend launch for the prefill rows and one decode launch for the tail.
