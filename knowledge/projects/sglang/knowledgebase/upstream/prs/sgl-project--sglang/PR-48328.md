# [Fix] mamba: Give a lazy boundary snapshot its own slot instead of overwriting the keep slot

[Upstream PR](https://github.com/sgl-project/sglang/pull/48328) · state: open · merged: False

## Original PR description

With the lazy Mamba extra buffer, a request at a tracking boundary takes a second state slot for the new snapshot. When no slot was free, the forward wrote the new state into the keep slot, the slot that holds the last checkpoint and may be handed to the radix tree at finish. One slot then meant both "the checkpoint at `mamba_last_track_seqlen`" and "this step's write destination". The scheduler covered this by dropping the checkpoint at launch (`mamba_last_track_seqlen = None`) and, at finish, predicting whether an in-flight step would still write the keep slot, with a mixed-forward exception on top.

Now the keep slot is never a write destination:
- The boundaries of a batch get their second slots through `alloc_tracking_slots` (`mem_cache/allocation.py`), which evicts the shortfall from the tree once, as `ensure_mamba_capacity` does for request slots (locked nodes are never evicted), then allocates.
- Only if that also fails does the boundary skip its snapshot: decode clears the row's track-mask bit, speculative verify plans position -1 (the scatter skips it and the result path does not promote it), and the keep slot keeps its checkpoint.
- A verify step whose row has no track destination (-1, from a skip or from a freed row) commits no snapshot even when it crosses a boundary, so no backend sees a crossing with nowhere to write. Before, the Ascend hybrid linear attention verify update wrote the pool's last row for such a row.
- Removed: the launch-time `mamba_last_track_seqlen = None`, the finish-time predictions of an in-flight write to the keep slot (decode and verify), the `mamba_untracked_decode_batch_idx` field that fed one of them, and the failed-prealloc branch of the mixed-forward undo.
- Kept: the verify finish check for a keep slot this step's scatter wrote (a just-promoted keep written by the next overlapped crossing), which is known exactly when the result is processed.

## Measurements
Qwen3-Next-80B-A3B-Instruct, TP2 on GB300, `--mamba-radix-cache-strategy extra_buffer_lazy --page-size 64`, multi-turn `generated-shared-prefix` benchmark (2048 requests, 4 turns, each turn resends the earlier answers, 64 concurrent). "Skip only" is this PR without the eviction. The eviction arm was measured with one eviction per failing row; the PR now evicts the batch shortfall at once, which frees the same number of states.

| config | arm | turn >= 2 hit rate (%) | uncached tokens per turn >= 2 (tokens) | output throughput (tok/s) | boundary slot failures (%) |
|---|---|---|---|---|---|
| `--max-mamba-cache-size 512` | main | 84.8 / 84.9 | 386 / 382 | 6597 / 6791 | 88 / 91 |
| | skip only | 74.2 / 74.2 | 653 / 653 | 6735 / 6667 | 90 / 90 |
| | this PR | 84.3 / 84.9 | 397 / 381 | 6726 / 6819 | 5 / 5 |
| same + NEXTN (3 steps, 4 draft tokens) | main | 83.7 | 413 | 3342 | 96 |
| | skip only | 74.2 | 653 | 3297 | 96 |
| | this PR | 84.4 | 396 | 3401 | 28 |
| default Mamba cache size | main | 84.8 | 385 | 6775 | 46 |

- Once the tree fills the state pool, most boundaries find no free slot (46% even at the default pool size), so the fallback path is the common one under lazy tracking. Skipping alone loses about 10 points of turn >= 2 hit rate; with the eviction the hit rate and throughput match main.
- Failures for this PR count attempts that still failed after the eviction. Repeat noise is about 0.1-0.4 points of hit rate and 100-200 tok/s.

## Test plan
- New unit tests: a failed decode prealloc clears the mask bit and keeps the checkpoint length; a failed verify plan gives -1 and no promote; a -1 position maps to track index -1; a crossing row with no destination commits no snapshot; the eviction frees a slot before the boundary would skip (decode and verify).
- The unit tests of the changed sites pass locally.
- To run on GPU: `test_mamba_cache_kl.py`, the lazy allocation-failure classes in `test_qwen3_next_models_extra.py`, and `TestQwen3NextMTPLazyV2` in `test_qwen3_next_models_mtp.py`.
