# Normalize the deprecated nsa attention backend alias to dsa

[Upstream PR](https://github.com/sgl-project/sglang/pull/34232) · state: open · merged: False

## Original PR description

`nsa` is declared in `ATTENTION_BACKEND_CHOICES` as a deprecated alias for `dsa`, but unlike the `compressed` -> `dsv4` alias it was never normalized.

On current `main` (after the `server_args` split into `arg_groups`), the effect is worse than before: `CPAttentionBackendKind.from_string` in `layers/cp/base.py` recognizes only `dsa`, so `--attention-backend nsa` with context parallel **raises** `Unsupported attention_backend='nsa' for CP strategy` at CP dispatch. The attention registry still resolves `nsa` to the DSA backend, so it only breaks on the CP path.

**Fix:** normalize the alias once, in the existing deprecated attention-backend alias loop in `handle_deprecated_args` (`arg_groups/serving_hook.py`), via `declare_resolution`, the same way `compressed` is handled. Every downstream consumer then sees `dsa`. Patching `from_string` alone would leave the same trap for the next consumer.

**Also fixed on the same line:** `from_string` tested `value in ("dsa")`, which is a substring check on the string `"dsa"` (a tuple needs a trailing comma), so `"a"`, `"s"`, `"ds"` or `""` would select the DSA branch. It's now an exact comparison.

Other consumers checked: `forward_mla.py` / `forward_mla_rocm.py` test `current_attention_backend in ("dsa", "nsa")`, which still matches; `attention_registry.py` keeps its `nsa` registration; Dots3 derives its internal `"nsa"` label from the backend class, not from server args, so it's unaffected.

**Tests:** new `test/registered/unit/server_args/test_deprecated_attention_backend_aliases.py` (CPU suite) covers nsa -> dsa on the base/prefill/decode fields, compressed -> dsv4 still working, the normalized value selecting `CPAttentionBackendKind.DSA`, and substring inputs being rejected. I couldn't run it locally (no torch/GPU runtime on this machine); isort, black and ruff pass on all changed files.

Rebased and re-ported onto `b2800461`, since the original change targeted the pre-split `server_args.py`.
