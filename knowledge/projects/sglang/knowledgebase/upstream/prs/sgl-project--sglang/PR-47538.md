# [Feat] http_server: Dispatch SageMaker /invocations to completions and embeddings by request body

[Upstream PR](https://github.com/sgl-project/sglang/pull/47538) · state: open · merged: False

## Original PR description

## Motivation

SageMaker only sends inference requests to `POST /invocations`, and ours only handles chat completions. So you can't serve an embedding model, or use the completions API, on SageMaker today. (#3740 mentioned this might be worth doing.)

## Modifications

`/invocations` now looks at the request body and forwards it to the existing route:

- `messages` → `/v1/chat/completions`
- `prompt` → `/v1/completions`
- `input` → `/v1/embeddings`

`messages` is checked first, so anything that worked before still goes to chat the same way.

I went with matching on keys instead of trying each request model until one validates (what vLLM does). Here `ScoringRequest` accepts any body and `input` fits three different models, so the result would depend on the order of the list.

A few other changes:
- A body that isn't a JSON object (e.g. an array or `text/plain`) now returns 400 instead of 500.
- A body without any of the three keys returns 400 listing the keys we accept.
- The SageMaker docs page lists the keys.

Things that change as a side effect: the OpenAPI schema for `/invocations` is now a plain object, and the HTTP metrics count all three request types under `/invocations`.

Rerank, score and classify aren't covered here. I can do them in a follow-up.

## Accuracy Tests

Ran on one L4. Qwen2.5-0.5B-Instruct for chat/completions (`temperature=0`), gte-Qwen2-1.5B-instruct with `--is-embedding` for embeddings. `/invocations` gives the same output as the native routes:

```
PASS  chat: /invocations == /v1/chat/completions
PASS  completions: /invocations == /v1/completions
PASS  completions stream: same SSE text
PASS  chat stream: same SSE text
PASS  embedding body on a generation server: 400 (asks for --is-embedding)
PASS  unknown body: 400
PASS  embeddings: matches /v1/embeddings (min cosine 0.999999)
```

Embeddings are compared by cosine: two `/v1/embeddings` calls in a row already differ by about 4e-4 in bf16.
