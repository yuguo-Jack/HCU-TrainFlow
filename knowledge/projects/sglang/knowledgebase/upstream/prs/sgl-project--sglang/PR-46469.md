# [Fix] serving: Return 400 for malformed requests instead of 200/500

[Upstream PR](https://github.com/sgl-project/sglang/pull/46469) · state: open · merged: False

## Original PR description

## Motivation

Malformed requests either ran the model or got a 5xx with internal error text back. This was found on sglang-torchtpu (sgl-project/sglang-torchtpu#1266) and fixed there in sgl-project/sglang-torchtpu#1651. The code is shared and hardware-agnostic, and sglang `main` has the same gaps, so this ports the fix to keep the fork and upstream in sync.

## Modifications

| Case | Root cause | Fix |
|---|---|---|
| `/generate` with out-of-vocab or non-integer `input_ids` returned 200 and ran the model | `TokenizerManager._validate_one_request` range-checks `token_ids_logprob` but never the prompt `input_ids` | New `_validate_input_ids_in_vocab`: every client-supplied id must be an int (not bool) in `[0, vocab_size)`, otherwise 400 |
| `max_new_tokens: "ten"` returned a bare 500 | `max_new_tokens + input_token_num` runs before `SamplingParams.verify`, so a string raises `TypeError` | Type check before that arithmetic: a non-int gets a 400 |
| chat/completions `n: 0` returned a 400 that leaked `range() arg 3 must not be zero` | `n` had no bound on `ChatCompletionRequest` or `CompletionRequest` | `n: int = Field(default=1, ge=1)` |
| Unreachable `image_url` on the media-artifact path (Qwen-VL, Kimi-K3) returned 500 with urllib3 internals | A `requests.RequestException` from `snapshot_media_source` escaped to the generic 500 handler | Catch it there and raise a 400 `Failed to fetch media URL <url>: <timed out / connection failed / HTTP n / ...>` |

The id check skips:
- `input_embeds` requests
- `positional_embed_overrides` requests
- empty ids
- ids produced by the tokenizer or the multimodal processor

Unknown `model` names are still accepted on chat/completions, as before.

## Validation

- New `test/registered/unit/managers/test_generate_request_validation.py`, plus cases in `test_protocol.py` (`n >= 1`) and `test_media_artifact_processor.py` (connection refused, HTTP 404, timeout; real sockets).
- Upstream `main` with the new tests: 18 failed. With this PR: 26 passed, 28 subtests passed. Both runs on CPU, py3.13, torch 2.11.0+cpu.
- The same change in sgl-project/sglang-torchtpu#1651 was verified end to end on a TPU v7x Qwen3-VL-8B server:

| Request | Before | After |
|---|---|---|
| out-of-vocab `input_ids` | 200 | 400 |
| `max_new_tokens: "ten"` | 500 | 400 |
| `n: 0` | leaked `range()` error | 400 on `body.n` |
| unreachable `image_url` | 500 with urllib3 internals | 400 naming the URL |
