# [Fix] diffusion: fix 11 quantization-layer correctness bugs (MXFP4, FP8, KitchenW4A4, Nunchaku)

[Upstream PR](https://github.com/sgl-project/sglang/pull/46319) · state: open · merged: False

## Original PR description

Fixes #46314.

11 correctness bugs in `python/sglang/multimodal_gen/runtime/layers/quantization/`, found by code review. Each is independently minimal; no new abstractions or refactors.

## Fixes

1. **ModelSlim dual-scale MXFP4 `AttributeError`** (`modelslim_mxfp4_scheme.py`): `self.is_dual_scale_key` was never set; the attribute is `dual_scale_key`. Crashed on every `W4A4_MXFP4_DUALSCALE` layer.
2. **ModelSlim MXFP4 smooth-quant scale never loads** (`modelslim_mxfp4_scheme.py`): `has_mul_scale` required both `.div.mul_scale` and `.mul_scale` keys with `and`, but `tools/wan_repack.py` renames the first into the second, so a repacked checkpoint never has both. Switched to `or`.
3. **Rowwise FP8 skipped fnuz normalization on ROCm** (`fp8.py`): the `per_channel_serialized` path only transposed the weight; added the same `normalize_e4m3fn_to_e4m3fnuz` call the `block_quant` path in this file already makes. (The aiter bpreshuffle half of this is left for a maintainer with ROCm+aiter hardware to validate — flagged, not guessed at.)
4. **gfx1250 FP8 fallback passed the wrong layout to `torch._scaled_mm`** (`fp8.py`): when the Triton tile declines, the weight stored row-major `[K,N]` for that tile went straight into `torch._scaled_mm`, which requires column-major `mat2`. Added a cheap transpose-twice copy on the fallback path only.
5. **MXFP4 (ROCm) silently corrupted pre-quantized checkpoints** (`mxfp4.py`): `create_weights` always allocated bf16 weights, ignoring `is_checkpoint_mxfp4_serialized`. Now raises `NotImplementedError` at init instead of loading packed bytes into bf16 params.
6. **MXFP4 (ROCm) only flattened 3-D input** (`mxfp4.py`): a 4-D video input reached the GEMM unflattened. `dim()==3` -> `dim()>2`, `.view` -> `.reshape`.
7. **Non-contiguous activations reached `.view()` unguarded** (`modelopt_quant.py`, `modelopt_fp8.py`, `weight_only_fp8.py`): added the same `.contiguous()` guard `fp8.py` already has for diffusion backbones that pass permuted views.
8. **KitchenW4A4 dropped INT8 embedding companions** (`kitchen_w4a4_config.py`): `get_quant_method` returned `None` for any non-`LinearBase` layer. Copied the `VocabParallelEmbedding` -> `ComfyInt8EmbeddingMethod` branch (and `quantizes_embedding`) from the sibling W4A8/NVFP4 configs.
9. **Nunchaku config** (`nunchaku_config.py`): three issues —
   - skip rule returned `None` for a `LinearBase`, which trips `assert self.quant_method is not None`; now returns `UnquantizedLinearMethod()`.
   - skip-pattern matching was case-insensitive (`prefix.lower()`) while AWQ/SVDQ matching is case-sensitive; made skip consistent.
   - `_patch_nunchaku_scales` silently skipped multi-shard checkpoints even though NVFP4 correctness depends on the patch; now merges all shards.
10. **ModelSlim `str.replace` corrupted prefixes** (`modelslim.py`): replaced every occurrence of the projection name in the prefix string, not just the leaf component, so a prefix where an earlier path segment happened to match `proj_name` got corrupted. Switched to `rpartition` on the last `.`-segment.
11. **`verify_prims_ts_coverage` double-reported QKV** (`flux3_prims_ts.py`): when a `to_qkv` projection had no planned PrimsTS role, it was appended to the `missing` list twice (once plain, once with the QKV suffix).

## Deferred / out of scope

- The aiter bpreshuffle weight-shuffle step for rowwise FP8 on gfx942/gfx950 (part of bug 3) needs ROCm+aiter hardware to validate; only the fnuz-normalize half, which is hardware-independent, is fixed here.
- A GGUF embedding padded-vocab-size check (`gguf.py:141`) needs more tracing of `VocabParallelEmbedding`'s padding contract before it's safe to change; left alone rather than risk a subtler regression.
- A couple of purely cosmetic items from the original review (a dead `pass` branch, a log message that assumes a 2-byte source dtype) have no functional effect and were left out to keep this diff minimal.

## Testing

All changed files: `py_compile` clean, `ruff check` clean, `isort --check-only` clean.

### New regression tests

Added 5 small test files (11 cases) covering 9 of the 11 bugs directly, in the same style as the existing suite:

```
test_modelslim_prefix_mapping.py       (bug 10: both str.replace call sites)
test_modelslim_mxfp4_scheme.py         (bugs 1, 2)
test_kitchen_w4a4_config_embedding.py  (bug 8)
test_nunchaku_config_skip.py           (bug 9: skip->Unquantized, case sensitivity)
test_flux3_prims_ts_coverage.py        (bug 11)
```

Verified each one **fails against the pre-fix source (`HEAD~1`) and passes against the fix**, on a Modal CPU container:

- Pre-fix: `9 failed, 2 passed` — failures reproduce the exact bug (e.g. `AttributeError: ... no attribute 'is_dual_scale_key'`, QKV counted `2 != 1`, `None is not an instance of ComfyInt8EmbeddingMethod`). The 2 that pass either way are companion checks for behavior the fix doesn't touch (an unmarked embedding staying `None`, and a differently-cased prefix correctly not matching either way).
- Post-fix (current HEAD): `11 passed`.

Bugs 3, 4, 5, 6, and 7 aren't covered by new tests: 3-6 are ROCm/NPU-hardware-gated at import or init time (no CPU-safe way to exercise the actual kernel path), and 7 is a one-line guard matching an existing pattern already covered by the existing FP8 test suite below.

### Existing tests (regression check)

