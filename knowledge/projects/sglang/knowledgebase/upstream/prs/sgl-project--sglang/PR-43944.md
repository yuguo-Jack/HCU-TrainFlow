# [AMD][DI][CI] dsv4pro-fp8 2p1d-ep16-mtp: raise prefill mem fraction for MORI EP v2 memory

[Upstream PR](https://github.com/sgl-project/sglang/pull/43944) · state: closed · merged: True

## Original PR description

## What
In `dsv4pro/1k1k/2p1d-ep16-mtp.yaml`, raise `prefill_mem_fraction_static` from 0.85 to 0.88. MORI EP v2 stays on.

#40666 made MORI EP v2 the default. It reserves 4 GiB per GPU for its symmetric arena, which together with the MTP draft model leaves the prefill KV budget at 1.86 GB. The fixed KV state alone needs about 5 GB, so the prefill servers stop at start-up with `Not enough memory. Please try to increase --mem-fraction-static`. This test failed in the 2026-10-12 nightly and passed before #40666.

Each 0.01 of the fraction adds about 2.9 GB per GPU. At 0.88 the budget is 10.17 GB.

## Validation
On pit2 (4 nodes), main `6a7abcf`, same image as the nightly. EP v2 active in every run.
- 0.85 (unchanged): fails, KV budget 1.86 GB.
- 0.87: passes, budget 7.40 GB, GSM8K 0.951.
- 0.88: passes, budget 10.17 GB, GSM8K 0.947 (gate 0.91), 7 of 7 result files, no out-of-memory in prefill.

0.87 clears the roughly 7.2 GB needed by only 0.2 GB, so 0.88 is proposed.
