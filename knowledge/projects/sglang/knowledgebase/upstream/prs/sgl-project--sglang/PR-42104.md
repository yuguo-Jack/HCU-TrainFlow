# [BugFix] Drain pending NGRAM inserts before resetting the online cache

[Upstream PR](https://github.com/sgl-project/sglang/pull/42104) · state: closed · merged: False

## Original PR description

## Motivation

A NGRAM cache flush can be undone by already queued inserts. The final verification step submits corpus updates asynchronously; `clear_cache_pool()` calls `reset()` without first synchronizing those updates. The reset clears the online trie, but the insertion worker can then repopulate it with pre-flush sequences.

An unchanged native corpus returned the old continuation after enqueue → reset → synchronize in 25/25 runs. The actual Python → TVM FFI path reproduced the same behavior in 10/10 runs.

## Modifications

Wait for the existing pending-insert counter to reach zero before resetting the trie and match state. The condition-variable wait releases the existing mutex so the insertion worker can finish; reset retains the mutex from observing zero through clearing. External corpora remain loaded, and inserts admitted after reset can populate the fresh online cache.

## Accuracy Tests

- Two new regression methods cover pending inserts with BFS/PROB matching, subsequent new inserts, and preservation of an external corpus. The original source fails three assertions; the corrected source passes.
- Complete existing NGRAM corpus suite: 40 test methods passed and one class-level skip; the existing HTTP mock test class is skipped because importing http_server requires unavailable CUDA libraries.
- Matching pre-commit hooks and `git diff --check` pass.

Local tests compile all five actual native/FFI source files and execute the original Python wrappers on CPU. The harness substitutes CPU build discovery for GPU-target discovery and excludes test-only GPU-idle/retry services. No GPU generation or model-output accuracy run is claimed. The backlog reproduction is repeated observed evidence, not a forced thread schedule.

## Speed Tests and Profiling

No inference-speed claim. The change only waits during reset; steady-state insertion and matching paths are unchanged. A flush may now wait for already admitted insertions before clearing them.
