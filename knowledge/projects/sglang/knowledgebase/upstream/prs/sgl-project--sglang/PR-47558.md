# [Fix] lmcache: Order stores after forward-stream KV writes

[Upstream PR](https://github.com/sgl-project/sglang/pull/47558) · state: open · merged: False

## Original PR description

## Motivation

LMCache can start reading KV before the model finishes writing it when stores are submitted on a different GPU stream. Concurrent SHM reuse reproduced an incorrect first output token on MI355X.

## Modifications

Wait for the caller stream, then prepare store indices and submit the store on the model's forward stream. The completion event now covers KV writes and index preparation. Select the stream API from the producer device backend and preserve asynchronous transfer and lock cleanup.

## Accuracy Tests

On MI355X / ROCm 10, both 3073-token SHM reuse runs failed before the fix; no-LMCache controls passed. After the fix, all eight cases passed: 512 measured requests, concurrency 8/output 64, alternating input lengths 257/3073, exact output equality and expected cache hits.

Four mocked CUDA/XPU regression cases cover stream ordering, restoration and failed-store lock release. Combined integration a1477798 passed 459 tests and 262 subtests. XPU hardware was not tested. Hosted CI is pending.
