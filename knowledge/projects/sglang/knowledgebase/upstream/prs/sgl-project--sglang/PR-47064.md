# [Perf] [AMD] kda: Narrow the Kimi-K3 TP8 KDA recurrent tile for small batches on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/47064) · state: closed · merged: True

## Original PR description

## Motivation

Kimi-K3 at TP8 has 12 KDA heads per GPU. The recurrent KDA update (`fused_sigmoid_gating_delta_rule_update`) uses a value tile of 32 with one warp, which gives only 48 workgroups for a small batch, too few to fill an MI355X. With speculative decoding and ReplaySSM, this kernel runs on every verify step, and plain decode uses it when the fused KDA decode kernel is not armed.

## Modifications

- On gfx950, for KDA with 12 heads, head dim 128 and at most 4 requests, use a value tile of 8 with one warp. Everything else keeps the current launch.
- One warp keeps the same reduction order, so outputs, the recurrent state and the ReplaySSM rings are bit-identical to the default launch.
- New test `test/registered/kernels/ops/attention/test_kda_recurrent_launch_gfx950.py` (MI35x suite): checks which batches take the narrow tile, and that verify (with ReplaySSM rings) and decode (with state update) are bitwise equal to the default launch. 7 passed.

## Accuracy Tests

Outputs are bit-identical to the default launch (checked by the new test for verify and decode, n = 1 and 4), so model accuracy cannot change.

## Speed Tests and Profiling

Kernel, one MI355X, bf16 state, cold L2 (a 1 GiB buffer is written before each call), median of 200 calls, two alternating passes per config, measured on two GPUs (they agree within 4 points):

| Mode | Requests | Tokens per request | Default (us) | Narrow tile (us) | Change |
|---|---:|---:|---:|---:|---:|
| verify | 1 | 4 | 12.7 | 10.2 | -20% |
| verify | 1 | 8 | 19.9 | 15.2 | -24% |
| verify | 4 | 4 | 13.0 | 11.1 | -15% |
| verify | 4 | 8 | 20.4 | 17.2 | -16% |
| decode | 1 | 1 | 7.9 | 6.4 | -19% |
| decode | 4 | 1 | 8.0 | 6.9 | -10% to -14% |

End to end: 8x MI355X, `Kimi-K3-Quark-MXFP4-AttnFP8`, TP8, DSpark block 3 with ReplaySSM, real acceptance, Kimi-K3 integration build (A/B toggles only this change). Random 8192 in / 1024 out, 16 prompts per concurrency level with warm-up, 3 servers per side, alternating. Median TPOT:

| Concurrency | Default | Narrow tile | Change |
|---:|---:|---:|---:|
| 1 | 4.37 ms | 4.30 ms | -1.6% |
| 4 | 6.90 ms | 6.86 ms | -0.6% |
