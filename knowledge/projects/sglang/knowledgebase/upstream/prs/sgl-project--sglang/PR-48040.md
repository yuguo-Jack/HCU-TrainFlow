# [Fix] minimax-m2: Keep values of nullable parameters and survive non-finite numbers

[Upstream PR](https://github.com/sgl-project/sglang/pull/48040) · state: open · merged: False

## Original PR description

## Motivation

Two bugs in how `--tool-call-parser minimax-m2` converts parameter values. Both show up in `detect_and_parse` and in streaming.

**Nullable parameters lose their value.** `_convert_param_value_with_types` returns `None` whenever the schema's types include `null`, whatever the model sent. Tools generated from Pydantic `Optional[...]` fields or from `{"type": ["integer", "null"]}` are affected:

```
schema: {"limit": {"type": ["integer", "null"]}}, value: 5
before: {"limit": null}
after:  {"limit": 5}

schema: {"tag": {"anyOf": [{"type": "string"}, {"type": "null"}]}}, value: abc
before: {"tag": null}
after:  {"tag": "abc"}
```

**Non-finite numbers crash the parser or produce invalid JSON.** For a `number` parameter, `1e999` makes `int(float("inf"))` raise `OverflowError`, which is not caught, so the request fails. `NaN`, and non-finite values inside an object or array parameter, reach `json.loads`, which accepts them, and `json.dumps` then emits tokens such as `Infinity` that strict JSON clients reject.

I did not open an issue for this. I found it while checking sibling parsers after #48034. #31511 fixes the same overflow in `minimax_m3`, and no open PR touches this code in `minimax_m2`. I checked #46295, #36691, #42007, #42594 and #35625.

## Modifications

- Only a null-only schema or a null literal (`null`, `none`, `nil`) now maps to `None`.
- `OverflowError` is caught in the `number` branch.
- JSON parsing in this converter goes through `_loads_finite_json`, which rejects non-finite numbers at any depth. Such values are returned as the raw string, the same as other text that fails to parse.

Behavior left unchanged: for a nullable string parameter, the literal text `none` still becomes `None`.

## Testing

CPU only, Python 3.12. Added `test/registered/unit/function_call/test_minimax_m2_detector.py`, covering both parsing paths. The nullable and non-finite cases fail without the fix, the first with `{'limit': None} != {'limit': 5}` and the second with `OverflowError`.

The new tests pass.
