# [AMD][Kimi-K3] Use public FlyDSL APIs in KDA decode kernels

## Motivation

The Kimi-K3 KDA FlyDSL decode kernels import a private helper from aiter (`_to_raw`) and build raw MLIR ops by hand. Both break easily when aiter or FlyDSL change, and the private import already broke here once. This PR moves the kernels to the public FlyDSL API.

## Modifications

- Remove the `_to_raw` import from aiter's `tensor_shim`.
- Replace raw `gpu.ShuffleOp`, `vector.ReductionOp` / `FMAOp` / `BroadcastOp` / `extract` / `from_elements` and `ArithValue` with `fx.gpu.shuffle_xor/idx`, `fx.Vector(...).reduce`, `fx.fma`, `fx.full`, `fx.Vector` indexing and `fx.Float32`.
- Replace `scf.IfOp` + `ir.InsertionPoint` with Python `if` over local closures.
- The `llvm.amdgcn.fdot2.f32.bf16` call has no FlyDSL wrapper yet, so it stays raw, isolated in `_fdot2_f32_bf16`. No env knobs or defaults change.

## Accuracy Tests

Kimi-K3 GSM8K (1319, 5-shot), 8x MI355X TP8/DCP8 with `SGLANG_ROCM_K3_KDA_FUSED_BACKEND=aiter`: 0.951 before -> 0.954 after. `test_kimi_k3_kda_decode.py` passes 16/16, and generated ISA is identical (ignoring `.loc`) for all compiled specializations.

## Speed Tests and Profiling

The ISA is identical, so kernel performance does not change.
