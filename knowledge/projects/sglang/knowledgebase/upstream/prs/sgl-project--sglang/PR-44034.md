# [Feature] --moe-replicate-tp: replicated MoE with prefill sequence parallelism (Qwen3.5 MoE)

[Upstream PR](https://github.com/sgl-project/sglang/pull/44034) · state: open · merged: False

## Original PR description

## Motivation

Implements the design in #43820 (revised).

For long-prompt prefill on a small TP group, TP pays two costs that grow with the prompt and do not shrink with the TP size:
- the all-reduce of the attention / linear-attention output;
- the all-reduce of the MoE output.

Sequence parallelism alone does not remove them: with TP-sharded experts, the MoE still needs an all-gather plus a reduce-scatter, which moves the same bytes. Replicating the experts does remove them. Each rank keeps its own tokens through the MoE, so the MoE needs no collective at all, and only the attention side keeps one all-gather / reduce-scatter pair.

For Qwen3.5-35B-A3B on 2 GPUs, full BF16 experts fit in memory (~63 GB per GPU), and the MoE all-reduce was ~half of the prefill communication.

## Modifications

New flag `--moe-replicate-tp` (Qwen3.5 MoE only). It resolves `moe_dp_size = tp_size` (no attention CP or EP) and disables the prefill CUDA graph.

- **`arg_groups/moe_replicate_tp_hook.py`** (new) and **`parallel_hook.py`**: architecture allowlist and rejection of incompatible flags (EP, attention CP / DP, PP, DWDP, a2a MoE, layernorm SP, input-scattered attention, TBO). It also allows `moe_dp_size == tp_size` without CP.
- **`layers/moe/utils.py`**: `moe_replicated_over_tp()`. The MoE output is complete, so its all-reduce and the fused all-reduce with the next layer are skipped.
- **`models/qwen2_moe.py`**: the shared expert is replicated too (`parallel_group="replicated"`). Without this, `moe_dp_size == tp_size` would leave the shared expert's TP partial sum unreduced.
- **`layers/layer_boundary/`**: new `BatchVariant.REPLICATED_MOE_SP`, bound when the MoE is replicated and selected for extend batches (not target-verify) at the stack's entry. It reuses the existing "FFN on the rank's own rows" path (as for a2a MoE):
  - reduce-scatter the attention output onto each rank's attention-TP slice, then add + norm there;
  - run the MoE on that slice;
  - at the next attention's entry, norm and then all-gather;
  - after the last layer, gather back.

  The batch is not padded, so linear attention never sees padding tokens. Instead, the slices of a batch whose rows do not divide over TP are padded with zero rows, and the gathers drop those rows again. The fused reduce-scatter + norm kernels are skipped for this variant. Decode batches keep the ordinary TP path.
- **Docs**: `server_arguments.mdx` row.

## Accuracy Tests

GSM8K (200 examples, `GSM8KMixin`), Qwen3.5-35B-A3B, TP2, 2×B200, main @ d8f8522:

| | score |
|---|---|
| TP2 | 0.860 |
| TP2 `--moe-replicate-tp` | 0.895 |

The difference is within noise (standard error ~0.023). Greedy outputs on 60K-token prompts match TP2 for the first 32 tokens on 2 of 3 prompts; the third diverges at a near-tie, as EP2 does on the same prompt (the MoE summation order changes). New e2e test: `test/registered/e2e/models/test_moe_replicate_tp.py`.

## Speed Tests and Profiling

Qwen3.5-35B-A3B, TP2, 2×B200, 3 prompts of ~60K tokens, `--chunked-prefill-size 32768`, trtllm_mha attention, FlashInfer GDN, bf16 SSM state. TTFT is from HTTP `/generate` with `max_new_tokens=1`: per prompt, the median of 3 runs; then the mean over prompts. Arms are interleaved.

| | TTFT | TPOT (bs=1) |
|---|---|---|
| TP2 (breakable prefill CUDA graph) | 419.8 / 419.9 ms | ~2.45 ms |
| TP2 `--moe-replicate-tp` | **383.8 / 383.1 ms (−8.6%)** | ~2.55 ms |
| TP2 + DFlash (block 8) | 425.0 ms | 1.255 ms |
| TP2 + DFlash `--moe-replicate-tp` | **394.0 ms (−7.3%)** | 1.366 ms (+9%) |

**Decode cost.** Every rank reads all experts in decode:
- bs=1 TPOT is +4% (no speculative decoding) and +9% (DFlash verify);
- GSM8K output throughput is roughly halved (2738 vs 5561 tok/s).

The flag is therefore aimed at **prefill instances** (PD disaggregation) and prefill-heavy, low-concurrency long-prompt workloads, as the help text states. A standalone emulation with the same kernels attributes the TTFT gain to removing the MoE all-reduce (~26 ms of transfer at 60K) plus faster full-width experts on half the rows (~10 ms); details in #43820.
