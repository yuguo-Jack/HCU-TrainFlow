# [Feat] Step5: Port preview support and LoRA to sglang-miles

[Upstream PR](https://github.com/sgl-project/sglang/pull/44917) · state: open · merged: False

## Original PR description

Ports Step 5 Preview support from #44356 onto `sglang-miles`, preserving request-budget and weight-update synchronization behavior. Adds LoRA for attention, dense MLPs, shared experts, and explicitly targeted routed experts; unsupported expert execution backends fail at startup.

Follow-up fixes cover repeated/streamed weight updates, config-derived KV pools, cache flushing, stage-owned dense/MoE reductions, and single synchronized KV-memory release. Ordinary stage producers leave tensor-parallel partials for the boundary to sum; attention-DP retains its separate reduction path. The FA4 dedicated Blackwell head-dimension-256 call now matches its kernel signature. Changes remain separate commits.

Validation at `ba328f88d`:
- Focused CPU suite: 29 passed, 17 subtests passed. The MoE regression fails on the previous runtime at TP2/4/8 and passes after removing the redundant producer sum. Scoped pre-commit passes.
- H200 five-layer slice [0, 3, 4, 88, 91], FA3/Triton: same-checkpoint TP4/EP4 versus TP8/EP8 comparison. Mean absolute input-logprob difference improves from 2.30850 to 0.105357; maximum improves from 8.56990 to 0.534933. Generated token IDs now match. Residual numerical differences remain unresolved; this is not bitwise parity.
- Zero-B LoRA adapter versus base: all 127 input logprobs match exactly and output IDs match. Base results also match exactly between LoRA-enabled and LoRA-disabled servers.
- Two complete memory-release/resume cycles with memory saver, CPU weight backup, and LoRA: base and nonzero-adapter output IDs and input logprobs remain identical after both cycles. Sequence includes full release, flush while offloaded, weights-only resume, then KV/graph resume.
- All 296 changed files staged for GPU testing match this commit by SHA-256.
- Earlier serving smoke passed decode graph capture, 5,000-token prefill, deterministic repeats, disk reload equality, and nonzero adapter effects. These checks alone did not detect the subsequently corrected MoE double reduction; the TP comparison and zero-adapter controls above provide additional coverage.
- Broad Linux CPU regression on the earlier runtime cleanup: 946 passed, 751 subtests passed, 1 skipped; the two remaining failures reproduce on the base. CPU LoRA suite: 221 passed, 39 subtests passed; all 20 failing test/subtest IDs also fail on the base.

Runtime uses Torch 2.13.0+cu130 with locally built sglang-kernel 0.4.9+torch213.sm90 (common90 + FA3); the published wheel has an ABI mismatch with this image. The Python radix-tree backend is selected because the source-overlay environment lacks matching Rust extensions. No dependency guard is bypassed. The slice adapter targets attention, dense MLPs and shared experts; routed experts are frozen in this GPU smoke.

This remains a draft. Full-model validation passed on Miles `3383800fc` with SGLang `ba328f88d`: three steps, 96 samples, driver exit 0, nonzero gradients on every step, adapter equality checks passed. Train/rollout mean absolute logprob gaps were 0.0187147 / 0.0193659 / 0.0167071; KL was 0.000631824 / 0.00065094 / 0.000551634. This is a bounded correctness test, not a convergence study. Blackwell head-dimension-256 runtime validation is still required. The repository-wide test gate rejects the requested `sglang-miles` base because it requires a newer `main` ancestor; no gate bypass is applied. Final-head [GitHub lint passes](https://github.com/sgl-project/sglang/actions/runs/39060174001), including Rust and documentation checks.
