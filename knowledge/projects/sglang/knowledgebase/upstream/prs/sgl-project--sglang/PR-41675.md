# [CI] [NPU] tests: Reduce HiCache sizes and enable expandable pinned memory in focused tests

[Upstream PR](https://github.com/sgl-project/sglang/pull/41675) · state: closed · merged: True

## Original PR description

## Motivation

Several Ascend NPU CI tests have intermittently failed while allocating pinned host memory. Large HiCache host pools increase the allocation pressure, and the Indexer/GSM8K tests also allocate pinned host buffers.

This change reduces HiCache capacity where appropriate and enables the expandable pinned allocator in nine focused NPU tests. It is a mitigation for these allocation failures, not a claim that their underlying cause is fully resolved.

## Modifications

- Follow the existing MLA sizing policy from #43308: change the MHA test from 30 GB per rank to `1 if _is_pr_pipeline else 10`, and set both Prefill HiCache and Decode KV offload in the PD test to `2 if _is_pr_pipeline else 10`. MLA already has this sizing policy in the base branch.
- Set `PYTORCH_NPU_ALLOC_CONF=expandable_segments:True,pin_memory_expandable_segments:True` in the server subprocess environments for:
  - HiCache MHA and MLA.
  - PD disaggregation, on both Prefill and Decode.
  - DeepSeek-V4 and GLM-5.2 Indexer replay.
  - GLM-5 top64-pruned BF16 GSM8K.
  - Qwen3.6-35B-A3B AIME26 with 64K input and prefix reuse.
  - Expert distribution recorder modes.
  - EPLB minimum rebalancing utilization thresholds, in both server launch environments.
- Keep the changes in these nine NPU test files. There are no shared runtime/helper, workflow, or diagnostic logging changes.

The size selection follows `GITHUB_EVENT_NAME == "pull_request"`: PR-triggered runs use 1 GB per rank for MHA/MLA and 2 GB per rank for PD Prefill/Decode; other invocations use 10 GB per rank. This is a logical HiCache pool size, not a cap on all pinned allocations.
