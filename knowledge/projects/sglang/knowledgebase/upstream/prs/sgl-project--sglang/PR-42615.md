# [Spec] Accept draft probabilities that round slightly above 1 in chain verify

[Upstream PR](https://github.com/sgl-project/sglang/pull/42615) · state: closed · merged: False

## Original PR description

## Motivation

Fixes #42568.

#37134 made the chain verifier (`speculative_sampling_classic_kernel`) reject any draft whose `q(X)` is outside `(0, 1]`, so a corrupt draft row can never be accepted unconditionally. But fp32 softmax can round a peaked row's top probability slightly *above* 1. With FlashInfer 0.7.0.post1 (the version main pins) on H100, `flashinfer.sampling.softmax(logits, temperature=t)` returns values up to `1 + 6.4e-6`. Over 60 settings (vocab 32000/129280/151936, temperature 0.3-1.0, top-logit margin 5-40, 64 rows each), 27 settings had 7-45 rows above 1.0 (all at temperature <= 0.7); `torch.softmax` never exceeded 1.0. DSpark builds both its draft and target probabilities with that softmax (`SoftmaxTemp.flashinfer` in `dspark_accept.py`), so its most confident drafts were rejected, and the bonus token was resampled from `p` instead of `(p - q)+` because the residual passes also zeroed such a `q`. Greedy requests are unaffected (they do not run this kernel).

@dg1kjd reported this on V100 and proposed the tolerance; this PR applies it and adds H100 evidence and regression coverage.

## Modifications

- `reject_sampling.py`: accept `q <= 1 + 1e-3` as a probability and clamp it to 1, in the token-verification accept test, in the block-verification prefix ratio added by #42297 (where such a q zeroed the prefix probability for that step and every later one), and in both residual passes. `0`, negative, `NaN`, `+-inf` and clearly invalid values such as `2.0` are still rejected exactly as before.
- `test_speculative_sampling.py`: four regression cases for `chain_speculative_sampling_triton`, each run with `block_verification` off and on:
  - `q = 1 + 2^-23` and `1 + 5e-4` are accepted (with `coin = 1 - 2^-24`, which also pins the clamp);
  - `q in {0, nan, -inf, inf, 2.0}` is still rejected (the #37134 contract);
  - after a rejected draft with `q = 1 + 8e-6`, the bonus token comes from `(p - q)+`, not `p`;
  - FlashInfer softmax probabilities used as both `p` and `q` accept every draft.

## Accuracy Tests

Kernel tests on 1x H100 (`lmsysorg/sglang` nightly-dev-20261005 image, FlashInfer 0.7.0.post1), `test_speculative_sampling.py` plus the existing `test_block_verification.py`, same files against both trees:

| tree | result |
|---|---|
| main `730f1f3e5b` (after #42297) | 8 failed, 40 passed: the three acceptance/residual cases fail in both modes, and with `p == q` from FlashInfer softmax the chains accept `[0, 0, 2, 1, 1, 0, ...]` of 3 drafts in both modes |
| this PR | 48 passed |

The E2E numbers below were measured before #42297 landed, on the token-verification path (block verification is opt-in).

E2E, 1x H100, `Qwen/Qwen3-14B` + `deepseek-ai/dspark_qwen3_14b_block7`, the Hopper configuration of `test_basic_sanity_dspark.py` (fa3/fa3, `SGLANG_RAGGED_VERIFY_MODE=compact`, page size 1) with decode CUDA graphs up to bs 32; GSM8K 200 questions, temperature 0.7, top-p 0.95, 32 threads:

| temperature | tree | runs | GSM8K | avg_spec_accept_length | output throughput (tok/s) |
|---|---|---|---|---|---|
| 0.7 | main | 2 | 0.940, 0.950 | 3.973, 3.983 | 3656, 3420 |
| 0.7 | this PR | 2 | 0.955, 0.950 | 4.110, 4.139 | 3820, 3773 |
| 0.3 | main | 1 | 0.950 | 3.935 | 3527 |
| 0.3 | this PR | 1 | 0.960 | 4.179 | 4064 |

GSM8K is unchanged within run-to-run noise. Each run is a fresh server, and `avg_spec_accept_length` is read from `/server_info` after the eval.

## Speed Tests and Profiling

On this pair, mean acceptance length rises by about 3.8% at temperature 0.7 and 6.2% at 0.3. The effect grows with sharper distributions, consistent with the mechanism. Throughput moves the same way, but `run_eval` throughput is noisy (see the two main runs above), so I would not quote a throughput number from it. The issue reports a much larger drop on DeepSeek-V4.1-Flash (V100); I did not test that model. The kernel change adds one compare and one `min` per loaded `q`.
