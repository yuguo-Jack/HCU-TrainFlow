# [Docs] Use rope_parameters for the YaRN overrides in the Qwen3-Next and Ling cookbooks

[Upstream PR](https://github.com/sgl-project/sglang/pull/44155) · state: open · merged: False

## Original PR description

## Motivation

SGLang pins transformers v5, where `rope_scaling` is only an alias property of `rope_parameters`: assigning it replaces the whole dict, and huggingface/transformers#49515 deprecates the setter (a `FutureWarning` now, a `ValueError` when `rope_theta` is missing). Two cookbook recipes still override through the old key:

- Qwen3-Next (1M context) passes `{"rope_scaling": {"rope_type": "yarn", ...}}` without `rope_theta`, so it would start raising on the next transformers release.
- Ling-2.6 / Ling-3.0-flash-VL carry the full dict (`rope_theta`, `partial_rotary_factor`) but under the deprecated key.

This is the cookbook follow-up discussed on huggingface/transformers#49515; the engine side (`--json-model-override-args` merging the base parameters) is #43067.

## Modifications

- `docs/cookbook/autoregressive/Qwen/Qwen3-Next.mdx`: both 1M commands pass the complete `rope_parameters` dict; `rope_theta: 10000000` and `partial_rotary_factor: 0.25` come from the model's `config.json`.
- `docs/cookbook/autoregressive/InclusionAI/Ling-2.6.mdx`, `Ling-3.0-flash-VL.mdx`: prose updated to the new key.
- `docs/src/snippets/autoregressive/ling-26-flash-deployment.jsx`, `docs/src/snippets/configs/inclusionAI/ling-3.0-flash-vl.jsx`: the generated commands switch `rope_scaling` → `rope_parameters`, values unchanged.

## Verification

Loaded the Qwen3-Next config through `sglang.srt.utils.hf_transformers.config.get_config` with the new override (transformers 5.19.0, CPU):

| override | `rope_parameters` after loading | `rope_theta` attribute |
| --- | --- | --- |
| none | `None` | 10000000 |
| old `rope_scaling` | `{rope_type: yarn, factor: 4.0, original_max_position_embeddings: 262144}` | 10000000 |
| new `rope_parameters` | `{rope_type: yarn, factor: 4.0, original_max_position_embeddings: 262144, rope_theta: 10000000, partial_rotary_factor: 0.25}` | 10000000 |

`get_rope`'s YaRN branch reads its keys with `.get`, and SGLang's native v5 configs already pass full `rope_parameters` dicts (with `rope_theta` and `partial_rotary_factor` inside) through the same path, so the extra keys change nothing for the rotary embedding. No `rope_scaling` reference is left under `docs/`.
