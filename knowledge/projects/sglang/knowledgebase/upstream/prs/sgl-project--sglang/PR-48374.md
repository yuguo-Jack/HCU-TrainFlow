# [Fix] [Intel] xpu: Fix int8 rounding, static Triton launcher crash and XPU test settings

[Upstream PR](https://github.com/sgl-project/sglang/pull/48374) · state: open · merged: False

## Original PR description

## Motivation
XPU-only failures in the per-commit tests:
1. `per_token_quant_int8` calls the CUDA libdevice round (`__nv_roundf`) on every non-HIP backend, and XPU Triton cannot link it (`ZE_RESULT_ERROR_INVALID_MODULE_UNLINKED`).
2. The torch XPU inductor static Triton launcher segfaults loading the compiled repetition penalty, which kills the LLaVA server.
3. On XPU, kv_canary e2e (default Triton attention, too slow for the ~7k-token workload) and `test_embedding_models` (an 8B model on a 24 GB card) time out with their current settings.

## Modifications
- `int8_kernel.py`: use the CUDA libdevice round only on CUDA and the backend-agnostic `libdevice.round` elsewhere (already the ROCm path). New `test_per_token_quant_int8.py` (CUDA and XPU CI).
- `engine.py`: on XPU, `setdefault TORCHINDUCTOR_USE_STATIC_CUDA_LAUNCHER=0` before workers spawn.
- Tests: `kv_canary/e2e_base.py` uses `--attention-backend intel_xpu` on XPU; `test_embedding_models` uses `mem_fraction_static=0.85` on XPU.

Everything is gated on XPU except the int8 rounding change, which is unchanged on CUDA and ROCm.

## Accuracy Tests
On Intel Arc Pro B60:
- `test_per_token_quant_int8`: passes; without the fix it fails with `ZE_RESULT_ERROR_INVALID_MODULE_UNLINKED`.
- LLaVA `test_vision_openai_server_a` ×2: pass.
- kv_canary e2e: 11/11 pass (with #48373).
- `test_embedding_models`: passes (with #48372).

## Speed Tests and Profiling
N/A for kernels: same kernel with a different round intrinsic, and only off CUDA.
