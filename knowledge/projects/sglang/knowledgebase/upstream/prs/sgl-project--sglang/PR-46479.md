# [Feat] [NVIDIA] megakernels: Expose fixed-width Kimi K3 DSpark verification state

[Upstream PR](https://github.com/sgl-project/sglang/pull/46479) · state: closed · merged: False

## Original PR description

This extends Kimi K3's typed megakernel binding for fixed-width DSpark target verification: request-local KDA checkpoint buffers, MLA query-width metadata, and auxiliary hidden-state buffers with capture-lifetime checks. SGLang retains ownership of acceptance, recurrent-state commit, and stock draft-model execution. This is restacked on [#45406](https://github.com/sgl-project/sglang/pull/45406) using the new NVIDIA kernel-plugin paths; the [DSpark-only delta](https://github.com/leejnau/sglang/compare/d8543baa113fc623429dfc787cbf2a1a3856ac53...feat/kimi-k3-dspark) does not include the parent API change. The relocation does not change kernel arithmetic.

The focused configuration is GB300, TP8, five draft proposals plus one anchor (q6), DCP off, and an 8,192-token context limit. Uniform q4–q8 metadata support is retained with fail-closed layout and ownership checks. The matching implementation is [sgl-nvidia-mega #25](https://github.com/sgl-project/sgl-nvidia-mega/pull/25). Specialized draft execution, DCP expansion, and long-context validation are outside this scope.

Historical full-model measurements apply specifically to **SGLang `02406d4ef05680cbf3d77287354d887b039141d9` + sgl-nvidia-mega `194d693d15a51f74a727889531fd6d9cd01bf355`**, not the rebased pair: GSM8K was 1,283/1,314 specialized versus 1,284/1,314 stock, with 3.7966 versus 3.8264 accepted draft tokens per verification, excluding the bonus token. Matched end-to-end output throughput was 1.43–2.09x stock for B1/B4 and 128/6,144-token inputs; see the [measurements and limitations](https://github.com/sgl-project/sgl-nvidia-mega/pull/25#issuecomment-6408017781). The known numerical canary remains **FAIL**, separately from quality and timing; these results do not establish general numerical equivalence.

Native old/new-layout compatibility checks passed on GB300, covering ordinary decode and DSpark in 34 isolated test-file runs with no failures or skips. The native-tested DSpark pair is SGLang `0e9e2aa` / plugin `e64e4d0`; the subsequent `d3d6d8c` commit only applies CI-requested import formatting in one test, with identical AST and no production changes. Real module/type identities and audited wheel payloads passed, with identical wheels across layouts and unchanged kernel payload bytes. These are focused compatibility checks, not a new full-model pass or performance result on the rebased pair.
