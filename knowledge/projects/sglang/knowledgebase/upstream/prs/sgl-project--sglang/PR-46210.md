# [Feat] [NVIDIA] megakernels: DSA / MLA binding view, EAGLE draft capture checks, early draft embedding sharing

[Upstream PR](https://github.com/sgl-project/sglang/pull/46210) · state: open · merged: False

## Original PR description

## Motivation

Two gaps in the megakernel layer (#44945) keep a plugin from serving a DSA (sparse MLA) model with an MTP draft model;
under embedding replication the KV cache is sized while the EAGLE v2 draft still holds memory it is about to free; and
a spec that needs embedding replication is not served by the flag alone:

- A megakernel that replaces the decode or verify step of a DSA model reads the DSA backend's layout and decode buffers
  and writes the MLA and index-K rows of its KV pool. Today the binding offers neither, so a plugin would read private
  backend attributes. This PR offers them through the binding, sealed and checked like the existing views. The DSA
  backend serves GLM-5 and DeepSeek-V3.2, so the view is not tied to one model.
- The decode graph runner calls the model runner's capture tail hooks after each captured forward, which is where the
  megakernel layer runs a spec's capture check (`assert_live`, and a refusal when no captured graph runs the spec). The
  EAGLE draft-decode and draft-extend graph runners do not call them, so a megakernel spec installed on a draft model is
  never checked after capture. This PR adds the call to both runners and a capability marker a draft spec can require.
- With `SGLANG_ENABLE_EMBED_REPLICATION`, the NextN draft loads its own full embedding table on every rank, and the
  EAGLE v2 draft worker replaces it with the target's only after the scheduler has sized the KV pool. The draft's copy
  and its lm_head shard therefore still count against the KV cache; they are freed only after it is sized. This PR
  binds the target's embedding and lm_head at the end of the draft worker's construction, so the KV cache gets that
  memory. The change is in the draft worker, so it applies with or without a megakernel.
- A spec can require an SGLang environment variable (`Requirements.env`), and the startup check refuses a server where
  it has another value. A spec that needs embedding replication therefore refuses `--enable-nvidia-megakernel` unless
  the user also sets `SGLANG_ENABLE_EMBED_REPLICATION=1`. SGLang reads that variable only when a model is built, after
  argument resolution, so resolution can set it. This PR has the flag set it when the served spec requires it and the
  user left it unset.

The GLM-5.3 specs of sgl-nvidia-mega (https://github.com/sgl-project/sgl-nvidia-mega/pull/24) code against the binding view and the capture
check and refuse at startup without them. Their draft spec needs embedding replication: the flag now turns it on for
them, and a GLM-5.3 server also gains the memory of the third change.

## Modifications

DSA / MLA binding view, `python/sglang/srt/kernel_plugins/nvidia/binding.py`:

- `KvPoolView` gains `get_key_buffer(layer_id)`, `get_index_k_with_scale_buffer(layer_id)`, `index_page_size` and
  `set_mla_kv_buffer` (the pool's own names; MLA / DSA pools offer them).
- `ForwardView.dsa` returns a `DsaView` of the running DSA backend (`None` on any other backend, detected by the
  backend's DSA decode implementation): the MLA dimensions, the decode implementation, the KV dtype, the top-k and DCP
  settings, the decode workspace and the multi-CTA KV counter buffer (both offered as data, sealed at the first read
  and checked by `assert_live` like the KV pool), and `indexer_metadata` (the backend's public `get_indexer_metadata`).
- `TOLERATED_DSA_CALLABLES` (2: the MLA key write and the indexer metadata) and `TOLERATED_DSA_WRITES` (2: the MLA key
  rows and the index-K rows at the step's `out_cache_loc`) list what a megakernel still calls or writes; the comments in
  `binding.py` say how long each stays tolerated (a call until it is offered as data, a write until SGLang owns it). The existing `TOLERATED_*` lists are unchanged, so existing plugins' contract pins keep
  passing.

EAGLE draft-graph capture checks:

- `eagle_draft_cuda_graph_runner.py`, `eagle_draft_extend_cuda_graph_runner.py`: both runners call the capture tail
  hooks through one method, `_run_capture_tail_hooks`, at the end of their captured function, with the batch size and
  token count they captured. The draft-decode runner runs the hooks under its first per-step attention backend: the
  draft steps ran under the per-step backends, and a hook that reads the running backend (the capture check reads its KV
  pool) sees the first. This rests on every per-step backend sharing the draft's KV pool, which the method checks when a
  hook exists. The same wrap is what any other hook registered on an EAGLE draft model runner sees; today only a
  megakernel draft spec registers one there.
- `python/sglang/kernels/plugin_kernels/nvidia/spec.py`: `EAGLE_DRAFT_CAPTURE_CHECK` marks an SGLang whose EAGLE draft runners run a draft model's
  capture check; `Step` documents the draft modes (`"draft_decode"`, `"draft_extend"`), that a draft spec's rows may be
  off its width grid, and that a draft model's capture check runs once, at the first draft runner that has captured
  every batch size.

EAGLE draft embedding, `python/sglang/srt/speculative/eagle_worker_v2.py`:

- Under `SGLANG_ENABLE_EMBED_REPLICATION`, `EagleDraftWorker` runs `init_token_map` and `init_lm_head` (which binds the
  target's embedding and lm_head) at the end of its construction instead of in `alloc_memory_pool`, which the
  scheduler calls after it has sized the KV pool. The draft's own copies are therefore freed before the pool is sized
  (GLM-5.3 with an MTP draft at TP 8: about 1.99 GiB per GPU, about 44 k more KV tokens). The same calls run in the
  same order, and a flag keeps `alloc_memory_pool` from running them again.
- Without replication the calls stay in `alloc_memory_pool`, where they were.

Environment the flag sets, `python/sglang/kernels/plugin_kernels/nvidia/spec.py` and
`python/sglang/srt/kernel_plugins/nvidia/binding.py`:

- `FLAG_SETS_ENV` lists the variables of `Requirements.env` the flag may set: only `SGLANG_ENABLE_EMBED_REPLICATION`.
  SGLang reads it only when a model is built (the input embedding's vocab-parallel layout and the EAGLE v2 draft
  worker's construction), in the model processes, which start after argument resolution.
- `handle_nvidia_megakernel` sets each of them that the served spec requires and the user left unset to the spec's
  value, before its checks, and logs it (`--enable-nvidia-megakernel: set SGLANG_ENABLE_EMBED_REPLICATION=True for
  <spec>`). The model processes inherit the value, so every rank sees it. Main's early return for a model that the
  MSA plugin serves (sgl-project/sglang#46625) comes before this step, so the flag leaves no variable set for such a
  model.
- A value the user set is kept and checked as before: `1` passes, and `0` is still refused, naming the variable. A
  refused setup leaves the environment as it was. Every other variable of `Requirements.env` is only checked: some are
  read at import or earlier in argument resolution, where a value set here would come too late.

Tests (CPU):

- `test/registered/unit/kernel_plugins/nvidia/test_megakernel_binding.py` (existing), new class
  `TestMegakernelBindingDsa`: the DSA view is the running DSA backend and its pool; a backend without DSA has none; the
  pool view offers the MLA and index-K buffers; a replaced DSA buffer fails `assert_live`.
- `test/registered/unit/kernel_plugins/nvidia/test_megakernel_draft_capture.py`: a draft runner's capture is checked; a draft
  runner with no routed graph is refused; the decode runner uses its first per-step backend; per-step backends on
  different pools are refused; without hooks nothing is read; the extend runner fires the hooks; each runner's captured
  function ends with the call. Its fake built object has the four members of megakernel API version 2 (`None`), as
  main's fake does.
- `test/registered/unit/spec/test_eagle_draft_embed_share.py`: under replication the draft binds the target's
  embedding and lm_head before the KV pool is sized, and only once; without replication it binds them after the draft
  pool is allocated, as before; the draft worker's construction ends with the early share.
- `test/registered/unit/kernel_plugins/nvidia/test_megakernel_guards.py`, new class `TestFlagSetsEnv`: with the flag, an unset
  variable the spec requires is set and logged; a set value is kept and checked (`1` passes, `0` is refused); without
  the flag, or for a spec that does not require it, nothing is set; a refused setup leaves the environment as it was;
  `FLAG_SETS_ENV` holds only the replication variable.

## Speed Tests and Profiling

No per-step change: nothing changes on a path that does not request the view, the hooks run once per captured batch
size at startup, the draft embedding change moves two startup calls, and the flag's environment step runs once, at
argument resolution. Under embedding replication the draft
embedding change gives the KV cache the memory the draft's own table held. Logged KV pool size on the setup above
(GLM-5.3 NVFP4, TP 8, MTP), dummy weights:

| server | KV pool (tokens) |
|---|---|
| the GLM-5.3 specs, replication on, before -> after | 3,174,720 -> 3,241,152 (+66,432, +2.1 %) for this change together with the companion plugin PR's change that no longer builds an NCCL communicator before the KV cache is sized; about 44 k of it (about 1.99 GiB per GPU) is this change, derived from the sizes of the two parts |
| SGLang main + this PR, replication off | 3,722,432 (this path is unchanged) |
| SGLang main + this PR, replication on | 3,697,920; without this change about 44 k fewer (derived, not run) |

All three were logged at `--max-running-requests` 32. The first row ran an earlier revision of the
GLM-5.3 plugin PR, so its absolute pool sizes are from that build; what the row reports
is the difference in pool size.
