# [Perf] [AMD] kimi-k3: TP8 LL column-parallel latent tail fused with the next attention read on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/44985) · state: open · merged: False

## Original PR description

> Kimi-K3 on gfx950 merge queue (all drafts; they land one at a time in this order): 1 #44978 verify argmax + tuned bf16 rows · 2 #44979 MLA prefill · 3 #44980 streaming AttnRes · 4 #44981 MoE prefill · 5 #44982 KDA · 6 #44983 MLA decode prep · 7 #44984 MLA decode epilogue · 8 #44985 LL column tail · 9 #44986 fused all-reduce read · 10 #44987 fused route sort · 11 #44988 split MoE front + bank partials · 12 #44989 MLA q-norm + q_b. Replaces #44547-#44553.

## Motivation

At Kimi-K3 decode sizes the latent-MoE tail after the MoE all-reduce (norm + 3584 -> 7168 up-projection + shared +
residual add) and the next layer's attention-side attention-residual (AttnRes) read are separate small launches per
layer, and each rank computes the whole replicated tail GEMM.

## Modifications

Gated on gfx950 TP8 (`layers/communication/k3_ll_comm_hip.get_comm()`).

- `comm/ll_hip.cuh`: a low-latency push protocol over a dedicated aiter CustomAllreduce's IPC meta buffer: senders
  write 16-byte lines of 8 payload bytes + an epoch flag into the receiver's scratch, receivers poll their own;
  no barrier (a line is rewritten two epochs later).
- The column-parallel latent tail, fused with the AttnRes read (softmax over the bank rows and the stream, RMSNorm;
  `attn_res/read_hip.cuh` + `k3_attn_res_read_hip.py`): each rank runs the tail GEMM on 1/8 of the replicated up_proj
  rows as split-K fp32 partials (`k3_latent_tail_partials`), and the all-gather kernel finishes its slice (/rms, +
  shared [+ residual]), gathers the stream and runs the next layer's attention read on it (optionally writing the
  bank row), staged in `AttnResidual` for that read (`SGLANG_ROCM_K3_COLUMN_TAIL`, <= 64 tokens).
- Batches the column tail does not take run norm + up-projection + shared + residual add as one kernel
  (`k3_latent_tail`, <= 32 tokens, `SGLANG_ROCM_K3_FUSED_LATENT_TAIL`).

#44986 (the attention output's all-reduce read) and #44988 (the column-parallel MoE front) build on the same LL
communicator.

| New env var | Default |
|---|---|
| `SGLANG_ROCM_K3_FUSED_LATENT_TAIL` | on |
| `SGLANG_ROCM_K3_COLUMN_TAIL` | on |

## Accuracy Tests

**Setup for every number below:** 8x MI350X (gfx950, 1000 W), Kimi-K3 (MXFP4 MoE, bf16 attention) at TP8 with EAGLE3
(topk 1, 3 steps, 4 draft tokens), FP8 KV cache, `SGLANG_USE_AITER=1`, aiter's K3 FlyDSL kernels
(`AITER_SITUV2_A8W4=1 AITER_FLYDSL_FORCE=1 SGLANG_AITER_K3_OPT=1`), CUDA graphs for bs 1/2/4/8/16, and an aiter bf16 GEMM table with K3 rows re-tuned on this pod with HBM-resident weights
(`AITER_CONFIG_GEMM_BF16`; not part of this PR, it belongs in aiter's model configs). EAGLE3 on K3 needs the
aux-capture commit of #43599, applied locally for these runs. Microbenchmarks rotate their weights through HBM.
Per-feature numbers were measured on the integration branch of this series as each piece landed (Oct 13-14,
earlier `main`). All branches of the series are on `main` 4eb606b2ae (2026-10-17); the kernel tests below ran on this
branch, and the end-to-end checkpoints on that `main` plus the queue up to each slot.

- GSM8K 400 with the column tail: 0.99 / accept 3.62. End to end: see below.
- `test_k3_ll_collectives.py` (new, 8 GPUs): the gather read (1 / 4 / 64 rows, with and without the prefix and the
  bank write) against torch.distributed. On MI350X: 1 passed.
- `test_kimi_k3_latent_tail_hip.py` (new): the fused tail against norm + GEMM + add; the partials finish to the same
  projection. On MI350X: 2 passed (9 subtests).

## Speed Tests and Profiling

- Column tail + fused next read: C1 decode cycle 17.95 -> 17.25 ms; tail partials ~4 us vs 11.5-13 us replicated.
- Fused latent tail: 13.5 vs 19.5 us (norm + up + add3); -21..-36% over 2-32 rows.
