# [Perf] [AMD] mla: Use aiter bf16 batched GEMM for the absorb BMMs on gfx1250 decode

[Upstream PR](https://github.com/sgl-project/sglang/pull/44456) · state: open · merged: False

## Original PR description

## Motivation

On gfx950 the absorbed MLA weights are converted to MXFP4 and run on aiter. On gfx1250 they stay bf16 and the two absorb BMMs per layer (`q_nope @ w_kc`, `attn_output @ w_vc`) go through `torch.bmm`, which lands on hipBLASLt.

## Modifications

With `SGLANG_USE_AITER=1` on gfx1250, both absorb BMMs use aiter `batched_gemm_bf16` when both operands are bf16, `w_scale` is 1.0 and the batch has at most 256 rows (the same limit as the gfx95 fp8 path):

- q: the Gluon backend up to 4 rows, Triton above (faster at larger batches);
- v: the Gluon backend, writing into the existing `(batch, heads, dim)` buffer through `YQ`, so the flatten stays a view.

Prefill-sized batches, quantized weights and the piecewise CUDA graph path keep `torch.bmm`.

### Dependency on aiter

None beyond the aiter in the gfx1250 Docker image (`batched_gemm_bf16` with `backend=` and `YQ=`). Shape-specific gfx1250 configs for these BMMs are proposed in ROCm/aiter#6573; without them aiter uses its default config.

## Setup

Kimi-K2-Thinking-MXFP4, TP8, MI455X (gfx1250), image `rocm/sgl-dev:v0.5.21-rocm10-mi45x-20261011`; aiter is the image's plus ROCm/aiter#5935, #5501, #5043 and #5402 (all in aiter 2bb549102). The Kimi-K2 cookbook targets MI300X; flags used here beyond it: `--attention-backend aiter --prefill-attention-backend aiter --decode-attention-backend triton --page-size 64 --disable-radix-cache --disable-custom-all-reduce --chunked-prefill-size 8192 --cuda-graph-max-bs-decode 128`, with `SGLANG_USE_AITER=1`, `SGLANG_ROCM_FUSED_DECODE_MLA=0` and `AITER_FORCE_A8W4=1`. Before and after differ only by this PR.

## Accuracy Tests

GSM8K with `few_shot_gsm8k` (8-shot, 1319 questions, `max_new_tokens` 512, the settings of sglang's AMD Kimi accuracy tests): before and after to be added.

Both BMM outputs are bit-identical to `torch.bmm` at batch sizes 1, 4, 32 and 128.

## Speed Tests and Profiling
