# [Perf] sampling: Draw final samples in vocabulary blocks

[Upstream PR](https://github.com/sgl-project/sglang/pull/44116) · state: open · merged: False

## Original PR description

## Motivation

The rejection sampler draws the final token in the same program as the acceptance decision. With a large vocabulary and few requests, this leaves much of the GPU idle. This change splits the residual draw across vocabulary blocks.

## Modifications

Keep acceptance decisions in the existing kernel, then compute residual masses for 4,096-token vocabulary blocks, select a block and draw the final token. Token-wise and block verification use the same implementation; the sampler API is unchanged. FP32 summation order changes, so a draw can differ near a CDF rounding boundary while representing the same distribution.

PR #42615 changes the draft-probability range check in the same code. Whichever lands second must preserve that update.

## Accuracy Tests

A focused block-verification reference check passes on the updated branch on an RTX 5070 Ti (SM120), both on CUDA and under the Triton interpreter. Earlier GPU validation covered both verification modes, distribution behavior and CUDA graph replay. Acceptance decisions matched the base; final-token differences were limited to FP32 CDF boundaries and remained within reference tolerance. That full matrix has not been repeated on this commit.

Earlier B200 validation used branch revision 5e9bfa815b over a main nightly, before the latest base update. Accept lengths matched the base, and the few final-token differences were at float32 CDF boundaries. The SM120 AOT wheel mismatch prevented DSpark runtime integration checks there. Full model accuracy remains unverified.

Run the speculative kernel suites with `python -m pytest` in a compatible CUDA environment or through the registered CI runner.

## Speed Tests and Profiling

The earlier B200 validation used a GLM-5.3-Flash FP8 model with EAGLE 4/1/5 and a 154,880-token vocabulary. In an isolated CUDA-graph sampler benchmark, the block draw was 4.7x to 8.8x faster across the measured request counts and acceptance patterns. The server A/B switched the kernel in process and measured time per verify step:

| Streams | Main | This change | Reduction |
| --- | ---: | ---: | ---: |
| 1 | 8.414 ms | 8.378 ms | 36 us (0.43%) |
| 4 | 12.091 ms | 12.048 ms | 44 us (0.36%) |
| 16 | 18.334 ms | 18.273 ms | 60 us (0.33%) |

These measurements used revision 5e9bfa815b and predate the latest base update. They have not been rerun on the updated branch. The server comparison used one server with interleaved passes; main server runs varied by up to about 0.33% at higher concurrency, so the end-to-end changes are modest. Block verification in a server, TP8, other GPUs and full model accuracy remain unvalidated.
