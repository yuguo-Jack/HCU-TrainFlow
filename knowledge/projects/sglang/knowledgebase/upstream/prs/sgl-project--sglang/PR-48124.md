# [Test] attention: Guard Muse Spark fused KV store writes

[Upstream PR](https://github.com/sgl-project/sglang/pull/48124) · state: open · merged: False

## Original PR description

## Motivation

The Muse Spark fused QK norm/RoPE/KV-store test compares the cache with a numerical tolerance and randomly selects slots. That is useful for reduction/RoPE accuracy, but does not explicitly guard repeated padding slot 0, both ends of the writable pool, all-padding calls, or bitwise preservation of untouched storage. A small stray write can fit inside the current 2e-2 / 0.125 tolerance.

## Modifications

Add eight cases to the existing CI-registered `test_muse_spark_qk_norm_rope_store.py`: RoPE on/off × BF16/E4M3 cache × mixed/all-padding slots.

- Deliberately use slots `[0, capacity - 1, 1, 0, 9]`, or all zeros.
- Require untouched K/V cache rows (including slot 0) and the entire strided QKV source allocation, including row padding, to remain byte-identical.
- Check live K against the returned BF16 K from the same call, converted to the cache dtype. Keep the existing tolerant comparison with the independent torch norm/RoPE implementation.
- Check live V against its raw input, including signed zeros, E4M3 halfway values and ±448/±512 saturation cases. The API requires unity cache scales; no foreign scaling/rounding convention is imposed.

No production code changes, no claimed kernel bug or speedup. This strengthens the fused operation's store contract; the standalone `store_cache` tests exercise a different kernel.

Overlap review: FlashInfer #7957 already covers paged append output preservation and #4992 covers window/split attention against an FP32 oracle, so those were not duplicated. SGLang's fused implementation already has BF16 rounding before RoPE and FP8 cache conversion, so no rounding patch was ported.
