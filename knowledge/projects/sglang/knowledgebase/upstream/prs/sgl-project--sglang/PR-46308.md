# [Perf] diffusion: Hide the pipelined Ulysses own-row copies behind the exchange

[Upstream PR](https://github.com/sgl-project/sglang/pull/46308) · state: closed · merged: True

## Original PR description

Stacked on #46247 (Wan's normed q/k written straight into the Ulysses exchange, which adds `fill_all`); also needs #46145 (`attend_into`, carried in that stack). The end-of-block part only engages where `attend_into` runs, which on B300 also needs #46146 (FA4 for long self-attention). Review the last commit.

## Motivation

On Wan2.2 T2V A14B 720p (4xB300, CFG 2 x Ulysses 2), the four GPUs differ by ~2% in speed at the 1100 W cap. Every block syncs a Ulysses pair twice and every step syncs all four ranks, so the slowest GPU sets the pace. A 2-step profile of every rank shows:
- the fastest rank idles ~1.5 ms per block, waiting for its peer;
- the slowest rank is busy except for two pipeline waits per block: ~117 us before the first head group attends (the peer's group-0 q/k in flight) and ~82 us before the output gather (the last group's output blocks in flight).

Two same-device copies (~60 us each) ran right next to those waits, on the slowest rank's critical path:
- v's own rows, copied into this rank's slots before the q/k fill;
- the gather of the peers' output blocks, after every group had arrived.

## Modifications

`distributed/device_communicators/ipc_a2a_multi.py`, `pipelined_attention`:
- `fill_all(blocks, part)` fills q (part 0), then k (part 1). q's blocks go out on the copy engine while the SMs fill k.
- v's own rows are copied after the fill, while k's blocks are in flight.
- With `attend_into`, the peers' blocks of every group before the last are gathered as soon as the last group has attended, while that group's blocks are still on the copy engines. The last group's blocks are gathered once they land.

`models/dits/wanvideo.py`: Wan's `fill_all` takes the part (one fused norm-RoPE pass for q, one for k, as before).

The same kernels copy the same bytes, so outputs are bit-identical.

## Accuracy Tests

- `test_usp_pipelined_attention_multi_gpu.py` (2 and 4 ranks):
  - the q/k-filled exchange (`forward_qk_filled` with a copying `fill_all`) matches the sequential exchange bitwise;
  - with FA4 in place of cuDNN in the dynamic SDPA backend, the zero-copy output path (`attend_into`) matches the sequential exchange for dense and filled calls;
  - a wrong gather offset fails it.
- Wan2.2 T2V A14B 720p, 4xB300, 3-step lossless (crf 0, x264 medium) mp4: md5 identical to the base for 3 prompts.

## Speed Tests and Profiling

Wan2.2 T2V A14B 720p, 4xB300, 2-step profile of every rank, median per DiT block:

| rank | before: SM idle | before: block | after: SM idle | after: block |
|---|---|---|---|---|
| 3 (slowest) | 0.205 ms | 54.565 ms | 0.046 ms | 54.472 ms |
| 0 (fastest) | 1.48 ms | 54.644 ms | 0.75 ms | 54.143 ms |

Rank 3's two waits (117 us + 82 us) and both copies leave its critical path: -93 us per block, ~0.15 s over the 1600 block calls of a 40-step request.

Ten head groups instead of the automatic five were slower: 55.1 ms per block.

E2E, harness single_e2e (fresh server per run, MP4 x264 medium / CRF 23), one 4xB300 box, runs interleaved: base (#46247 stack) 88.441 / 88.465 s (mean 88.453) -> this PR 88.394 / 88.346 / 88.444 s (mean 88.395), -0.06 s; TRT-LLM 1.4.0rc1 in the same rotation 93.118 / 93.173 s.
