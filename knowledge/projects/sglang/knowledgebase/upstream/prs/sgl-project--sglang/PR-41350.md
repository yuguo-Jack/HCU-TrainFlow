# [Fix] kt: read num_hidden_layers from text_config for multimodal checkpoints

[Upstream PR](https://github.com/sgl-project/sglang/pull/41350) · state: open · merged: False

## Original PR description

## Motivation

`create_kt_config_from_server_args` reads `num_hidden_layers` from the top-level `hf_config` only. Multimodal `*ForConditionalGeneration` checkpoints keep the language model's layer count under `text_config`:

| checkpoint | top-level `num_hidden_layers` | `text_config.num_hidden_layers` |
|---|---|---|
| Qwen/Qwen3.5-35B-A3B (`Qwen3_5MoeForConditionalGeneration`) | missing | 40 |
| a Qwen3.8-Flash-Next checkpoint (`Qwen4ExpForConditionalGeneration`) | missing | 48 |

So `KTConfig.num_layers` is `None` for these models, and the guard in `KTEPWrapperMethod.create_weights` that sets `max_deferred_experts_per_token` to 0 on the last MoE layer never fires when `--kt-max-deferred-experts-per-token` is set. We noticed it because a hook of ours keyed on the last layer never ran on a Qwen3.8-Flash-Next checkpoint.

## Modifications

Fall back to `text_config.num_hidden_layers` when the top-level value is missing. Configs that have a top-level value are unchanged.

## Accuracy Tests

No change for configs with a top-level `num_hidden_layers`. For the multimodal checkpoints above, the only effect is that the existing last-layer guard now applies.
