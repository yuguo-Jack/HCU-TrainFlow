# [Fix] benchmark: Count actual overlaps for peak concurrency

[Upstream PR](https://github.com/sgl-project/sglang/pull/44276) · state: open · merged: False

## Original PR description

## Motivation

Fixes #44278.

`Peak concurrent requests` currently counts requests that touch the same one-second bucket, even when their lifetimes do not overlap. For example, five sequential subsecond requests report a peak of 5 instead of 1. The benchmark output in #14165 already shows the discrepancy: `--max-concurrency 1` reports `Peak concurrent requests: 2`.

Compute the scalar peak from actual request overlap in both the Python and Rust clients. This is separate from #33193, which corrects peak output-token throughput.

## Modifications

- Sweep successful requests' half-open `[start, end)` intervals. Simultaneous departures and arrivals do not create extra overlap, and zero-duration intervals contribute no concurrency, consistent with the existing steady-state benchmark.
- Preserve the Python per-second plot data and rename its title to `Requests active during each second`: a bucket counts requests active at any point during that second, while the scalar reports the maximum simultaneously active count.
- Add registered CPU regression coverage and Rust tests for sequential subsecond requests, boundary handoffs, genuine overlap, unordered outputs, empty intervals, and failed requests. Keep token-throughput and average-concurrency calculations unchanged.
