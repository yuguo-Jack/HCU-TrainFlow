# [NPU] Add complete-group C128 Mooncake prefetch

[Upstream PR](https://github.com/sgl-project/sglang/pull/40407) · state: open · merged: False

## Original PR description

## Motivation

DeepSeek-V4 NPU exposes C128 cache pages to UnifiedRadixCache only at complete compression-group boundaries.

The existing C128 HiCache integration supports device-to-host backup and host-to-device load-back, but it cannot restore C128 groups from Mooncake storage. As a result, a storage KV hit cannot reconstruct the C128 sidecar state required at complete-group endpoints.

This PR adds complete-group C128 Mooncake prefetch support without introducing partial-tail restoration or changing SWA behavior.

## Modifications

- Add C128 prefetch sizing based on complete compression-group boundaries.
- Allocate C128 prefetch staging through the existing host-pool reclaim callback.
- Add C128 host-to-storage and storage-to-host transfer descriptors.
- Generate sparse Mooncake keys from C128 group endpoint hashes.
- Preserve `RadixKey` namespace, cache salt, and EAGLE bigram hash semantics.
- Trim C128 endpoint keys and staging when the actual KV hit is shorter than the requested span.
- Commit successfully loaded C128 groups to their radix endpoint nodes.
- Release failed, duplicate, and unused C128 host staging through component actions.
- Restrict Mooncake restorable prefixes to consecutive complete C128 group endpoints.

For a radix page size of 128 and a C128 physical page size of 16, one C128 storage object represents 2048 tokens, or 16 radix pages. For an 8064-token prefix, the valid C128 endpoints are radix pages 16, 32, and 48; the remaining partial tail is not restored.

## Accuracy Tests

The change does not modify model computation or kernel numerics.

Verified on DeepSeek-V4 NPU with Mooncake:

- C128 objects were successfully prefetched from Mooncake.
- Complete-group endpoint restoration succeeded.
- Mooncake/ADXL transfer completed successfully.
- Generated results matched the non-prefetch path.
