# [Feat] unified_cache: Support FULL + MAMBA MLA models (Kimi-K3) in the direct external linker

[Upstream PR](https://github.com/sgl-project/sglang/pull/44977) · state: open · merged: False

## Original PR description

## Motivation

The direct external linker rejects FULL + MAMBA models with MLA full attention, such as Kimi-K3 (MLA + KDA): `_MambaStrategy` has no linker pool group, and non-packed draft KV (DSPARK) raises at startup.

## Modifications

- `_MambaStrategy` builds a linker pool group: the MLA KV (paged) plus the existing Mamba slot entry. It is not `rank_replicated`, since the Mamba state is TP-sharded.
- DSPARK draft KV shares the target KV slots, so it is a `DRAFT` entry indexed from the KV transfer, the layout HiCache already uses for sidecar drafts. Sidecar pools reach the linker through `CacheInitParams.sidecar_draft_device_pools`. A model whose linker group has no `DRAFT` entry fails at startup instead of dropping the draft KV.
- Rejected at startup: non-plain-MLA full-attention pools, `--dcp-size > 1`, packed draft KV, and more than one sidecar draft pool.

## Accuracy Tests

Oracle: the same request served from a device hit, then after `/flush_cache` from a Mooncake host hit at the same prefix. Output ids, logprobs and `spec_verify_ct` must be equal. Negative controls (box-only probe) fill the destination rows with 0xA5, then skip one pool's load.

| setup | normal load | load skipped |
|---|---|---|
| CI: `kimi-linear-tiny-random`, 1 GPU | 4/4 exact | MAMBA or KV skipped: fails |
| Kimi-K3, 8x B300 TP8 (cookbook Low-Latency) | 24/24 exact | MAMBA: 1/8 ids equal; KV: 0/8 |
| Kimi-K3 + DSPARK (block 7) | 32/32 exact, same accept length | DRAFT: logprobs 0/8, `spec_verify_ct` 3/8 |

Kimi-K3 TP8 is bit-deterministic run to run, but GPU work from another thread shifts its output even on a pure device hit, so a poisoned *normal* load is not bit-exact there. The loaded bytes were checked directly instead: they equal the stored bytes and are intact when the forward reads them.

## Known limitations

- Each TP rank stores its own copy of the MLA KV.
- With DSPARK, a lookup needs the `DRAFT` objects, so prefixes written without speculation do not hit.
