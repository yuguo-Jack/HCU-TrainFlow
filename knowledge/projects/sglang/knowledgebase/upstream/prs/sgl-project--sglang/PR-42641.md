# [PD] Let Rust-server prefill with multiple DP ranks register its DP rank

[Upstream PR](https://github.com/sgl-project/sglang/pull/42641) · state: closed · merged: False

## Original PR description

## Motivation

With `SGLANG_RUST_SERVER=1`, a PD prefill server opens one listener per DP rank, and the router picks the listener, so the bootstrap room can't choose the rank. Two things break:

1. The PD prefill default `--load-balance-method auto` still resolves to `follow_bootstrap_room`. Decode then expects rank `bootstrap_room % num_dp_ranks`, and prefill fails every request the router sent to another rank with a `follow_bootstrap_room conflict`.
2. With `round_robin` set explicitly, prefill registers each request's DP rank at the server's base bootstrap port. Each Rust-server DP listener serves its own registry on its own port, so decode, which queries the request's `bootstrap_port`, never finds a rank registered behind another listener, and the request stays pending on decode.

The Python frontend is unaffected: its DP controller dispatches by room.

## Modifications

- For a Rust-server PD prefill with more than one DP rank, `auto` resolves to `round_robin`, and an explicit `follow_bootstrap_room` is rejected at launch. Prefill then registers each request's DP rank for decode to look up.
- The DP rank is registered at the request's bootstrap address (`bootstrap_host:bootstrap_port`), where decode looks it up, instead of at the server's base bootstrap port. The `bootstrap_port` argument of `PrefillBootstrapQueue` is removed.
- Tests: a Rust multi-rank PD prefill can't follow the bootstrap room; the prefill sender registers at the request's bootstrap port.

A one-docstring conflict with #42620 resolves by taking that PR's deletion of `_alias_bootstrap_port_to_api_port`.

## Tests

- `python -m pytest -q test/registered/unit/disaggregation/test_register_to_bootstrap.py test/registered/unit/server_args/test_server_args.py`: 296 passed.
- `pre-commit run --from-ref origin/main --to-ref HEAD`: all hooks pass.
- Real PD launch in Rust mode on two A100s (Qwen1.5-MoE-A2.7B-Chat, nixl transfer): prefill `--tp 2 --dp 2 --enable-dp-attention`, decode `--tp 1`, behind the mini load balancer with each prefill DP listener as its own prefill URL and bootstrap port; 40 greedy `/generate` requests from 8 threads, 16 new tokens each.
  - On current main (`auto` resolves to `follow_bootstrap_room`): 21 succeeded. Prefill failed the other 19 with a `follow_bootstrap_room conflict`, decode waited until its 300 s transfer timeout, and the client gave up at 120 s.
  - With this PR (`auto` resolves to `round_robin`): all 40 succeeded with no conflicts, and both DP ranks ran prefill batches. Same result on a tree with all the related Rust-frontend PRs merged.
  - Prefill ran with `--skip-server-warmup`: on current main the startup warmup reaches only the base-port listener, so the second DP listener never reports healthy. #42642 fixes that separately; with both PRs, the same run passes 40/40 with warmup on. Triton attention, pytorch sampling and `--cuda-graph-backend-prefill disabled` because of the local environment.
