# [Refactor] bcg: Write the debug-mode forward's output buffer inside its eager break

[Upstream PR](https://github.com/sgl-project/sglang/pull/46553) · state: closed · merged: True

## Original PR description

- Under `--debug-cuda-graph`, the breakable backend runs the whole forward as one eager break (`forward_into_buffer` in `BreakableCudaGraphBackend.capture_one`). The break now copies the forward's output into the backend's shared output buffer, which it takes as its last argument, and returns nothing. Before, the break returned the output; at every replay the graph wrapper copied it into the output from capture, and a captured copy after the break moved that into the shared buffer.
- The break no longer returns an output, so the row count comes from the warmup's output; the warmup runs the same forward on the same inputs. The path without `--debug-cuda-graph` is unchanged.
- One behavior change, under `--debug-cuda-graph` with pipeline parallelism on a rank other than the last, where the forward returns `PPProxyTensors`: replay now returns that replay's tensors. Before, the wrapper's copy replaced the captured object's `tensors` dict instead of writing into its tensors, so the captured copy after the break read the tensors from capture.
- No test is added; the debug-mode cases in `test_graph_routing_context.py` run the new break on CPU.
