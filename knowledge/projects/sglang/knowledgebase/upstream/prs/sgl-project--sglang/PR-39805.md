# [XPU] Support Gemma-3 bidirectional image attention in XPUAttentionBackend

[Upstream PR](https://github.com/sgl-project/sglang/pull/39805) · state: closed · merged: True

## Original PR description

## Motivation

Gemma-3 multimodal uses **bidirectional attention among image tokens** during prefill (text stays causal). In SGLang this is realized by `Gemma3ForConditionalGeneration.prepare_attn_masks()` building a dense per-sequence mask — but that path is gated to `TritonAttnBackend` only (see the note in `gemma3_mm.py`: *"only the TritonAttnBackend supports bidirectional attention; other backends have not yet implemented this"*).

On the Intel XPU attention backend the mask was never applied, so image tokens ran plain **causal** attention, degrading vision-heavy tasks while leaving text unaffected.

On Intel Arc Pro B60 (`--attention-backend intel_xpu`, tp1), `docvqa_val` ANLS:

| backend | ANLS |
|---|---|
| intel_xpu (before) | 59.4 |
| triton (same HW) | 64.1 |
| H200 (ref) | 65.0 |
| **intel_xpu (this PR, sgl-kernel-xpu native)** | **67.46** |

Text-only `gsm8k_cot` is unchanged between intel_xpu and triton, consistent with the gap being image-specific.

## Modifications

This does the bidirectional masking **in the kernel** (via sgl-project/sgl-kernel-xpu#495), keeping the sglang path a normal flash-attn call — no attention fallback in the model runner.

- `models/gemma3_mm.py::prepare_attn_masks`: for `XPUAttentionBackend`, build a per-token block id over whole sequences (image index, `-1` for text) and store it on the backend (`is_xpu()`-guarded lazy import; the Triton path is unchanged). None when this extend holds fewer than two tokens of any image.
- `layers/attention/xpu_backend.py::forward_extend`: when present, run non-causal and pass `bidirectional_block_ids` to `flash_attn_with_kvcache`; the kernel re-imposes causal for block-less tokens and keeps same-block (image) tokens bidirectional. With a cached prefix (radix hit or a later chunk), q is padded to whole sequences so the kernel sees a full prefill, and only the extend rows are kept. On sliding-window layers the window is dropped only when it cannot clip a key; longer prompts keep local attention.
- `layers/layernorm.py::forward_xpu`: make the input contiguous before `gemma_rmsnorm` (it requires a contiguous last dim, which a sliced hidden state may not have) so Gemma-3 loads on XPU.
- `test/registered/xpu/test_xpu_gemma3_bidirectional_attn.py`: sliding-window bound and image-after-cached-prefix against a dense reference.

Depends on the companion kernel PR sgl-project/sgl-kernel-xpu#495 (`bidirectional_block_ids`).

## Accuracy

`docvqa_val` (lmms-eval, ANLS), Intel Arc Pro B60, tp1, `--enable-multimodal --attention-backend intel_xpu` with default radix cache and chunked prefill: **59.4 → 67.46** over the full 5349-sample val set (67.48 with full prefill and radix off), above the H200 reference (65.0). `gsm8k_cot` (text) unchanged. The kernel is unit-tested against an fp32 reference on the companion PR.
