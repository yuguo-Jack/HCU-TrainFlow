# [Fix] disaggregation: fix HiSparse spec PD transfer on PP>1 prefill

[Upstream PR](https://github.com/sgl-project/sglang/pull/47840) · state: open · merged: False

## Original PR description

## Bug

HiSparse + speculative decoding + PD disaggregation on a `--pp-size > 1` prefill fails on the first request: every non-last pipeline stage raises

```
ValueError: HiSparse spec PD transfer requires an appended device-only draft KV buffer
```

inside `send_kvcache` (mooncake), killing that stage's transfer thread. All subsequent PD requests hang at 0 completions while `/health` stays 200.

## When it happens

Mooncake PD with a spec-decoding decode engine and hisparse. Only the last prefill PP stage owns a draft runner, so non-last stages register `num_draft_entries = 0`; `send_kvcache` derives the host-backed vs device-only boundary in the receiver's `dst_kv_ptrs` from the local stage count and raises when it is 0. Any model whose weights exceed one node's HBM at the target TP forces PP>1 on the prefill (GLM-5.3 FP8 at TP8: 88.5 GB/GPU > 80 GB HBM), so production-shaped topologies hit this on the first request. The current CI does not reach this path (the hisparse PD test runs PP=1 with a dense prefill and no spec), and this is the destination-side boundary suggested during #37771 review.

## Fix

The decode receiver ships its registered draft-entry count over the mooncake registration wire (one field appended after `kv_item_lens`; absent for peers that predate it), and `send_kvcache` takes the host-backed/device-only boundary from the destination's registration, falling back to the local count when the field is absent. Old peers keep the current behavior exactly.

## Verification

- Unit tests (`test_disaggregation_wire.py`): a non-last PP stage takes the boundary from the destination registration and transfers only its target span; a pre-field peer still raises the loud error; the registration round-trips the count and parses `None` when the field is absent. All pass on this branch; the new tests fail on current main (`AttributeError` / `TypeError`), i.e. they detect the bug.
- E2E (v0.5.22-based tree carrying the same diff; GLM-5.3 FP8 on 4x H100; prefill TP8xPP2+CP8, decode TP16+DP16+EAGLE 3/1/4, hisparse): the hang reproduced before the fix (the raise appears on the non-last stage only, first request); with the fix the stack serves — 128k-context needle retrieval 5/5, no raise on any stage.
