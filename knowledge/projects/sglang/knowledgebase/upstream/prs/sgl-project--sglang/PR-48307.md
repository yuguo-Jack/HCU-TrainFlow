# [Feature] multimodal: Write each item feature cache key once

[Upstream PR](https://github.com/sgl-project/sglang/pull/48307) · state: open · merged: False

## Original PR description

## Motivation

Concurrent misses on one key, e.g. the eight samples of a prompt that arrive together, each serialized and wrote the same features: 2.7 writes per key on video items, 407 writes for 153 files in the TimeLens run below. The file was written once, by whoever renamed first, but every writer paid for the serialization and the disk.

## Modifications

- The temporary file has a fixed name and is created exclusively, so it is the claim on the key: a writer that finds it, like one that finds the file, leaves the key to whoever holds it. Between processes as within one, through the filesystem.
- A failed write removes its temporary file, so the next writer takes the key.
- Opening the directory removes the temporary files a killed process left; a key whose claim stayed would otherwise never be written. A process that opens the directory while another is writing interrupts that write, which fails and is logged.

## Tests

`test_preprocess_cache.py`: the second of two concurrent writers calls `torch.save` zero times and the file holds the first writer's value with no temporary file left; after a failed write the next write succeeds; a stale temporary file is gone once the directory is opened.

Run on the H200 devbox: `test_mm_token_expansion.py`, `test_preprocess_cache.py`, `test_model_overrides.py` pass.

End to end with radixark/miles, Qwen3.5-9B on 400 TimeLens Charades prompts (2 fps, up to 448 frames, CPU decode), 4 H200 colocated, TP 4, 16 prompts x 8 samples, 10 steps, means over steps 1+:

| arm | step time (s) | trainer media wait (s) | trainer log-prob pass (s) | rollout (s) | logprob abs diff | reward |
|---|---|---|---|---|---|---|
| no cache | 151.1 ± 15.9 | 8.6 | 38.5 | 27.2 | 0.0089 | 0.43 |
| disk cache, #48285 + #48286 | 146.2 ± 12.6 | 1.0 | 32.5 | 28.4 | 0.0084 | 0.43 |
| disk cache, with #48304 and this | 138.5 ± 13.0 | 0.7 | 29.7 | 24.1 | 0.0091 | 0.43 |

With this change 153 files took 153 writes (407 before), no temporary file was left, no write failed, and the 12 sampled hit checks all matched. Every trainer lookup hit. The trainer's log-prob pass is faster with the cache because it no longer competes with the media rebuild threads for the CPU; rollout is faster than without the cache because a prompt's later samples hit what its first sample wrote.

## Stack

After #48306. The main port of #48305; the patch is byte-identical to it. The tests and the end-to-end run were done on the sglang-miles stack, not re-run here.
