# [Fix] openai: Report aborted requests as an error or a stop

[Upstream PR](https://github.com/sgl-project/sglang/pull/45132) · state: open · merged: False

## Original PR description

Based on #45130; only the last commit is new.

## Motivation

OpenAI's `finish_reason` has no `"abort"` value: chat allows stop, length, tool_calls, content_filter and function_call, and completions stop, length and content_filter. SGLang returns `"abort"`, which clients with a closed enum fail to parse. Separately, a streamed abort with an error status became an error frame only when the status was an `HTTPStatus`; after IPC it is an int, so the client got `"abort"` instead.

## Modifications

- **Chat and completions:**
  - An abort with an error status returns that error, as an HTTP error or a stream error frame. Examples are a timeout, out of memory, and EPD's 404/408/502/504.
  - With `n > 1`, one failed choice fails the request.
  - Both `int` and `HTTPStatus` statuses count.
- **Aborts without a status** (`/abort_request`, `pause_generation(mode="abort")`, session replacement):
  - they report `"stop"` with `matched_stop: null`;
  - they are not promoted to `"tool_calls"`;
  - their partial output and any parsed tool calls are returned unchanged.
- **Grammar:**
  - A token rejected by the grammar aborts with 500, as the PD paths do.
  - A request aborted in the grammar queue gets the same status as a running one: none, or 503 for a timeout.
- **Rust:**
  - `sglang-processor` matches.
  - The native `sglang-server` reports a statusless abort as `"stop"` on completions, and promotes to `"tool_calls"` only after a natural stop, streamed and not.

**Not covered:** after a statusless abort, the native `sglang-server` stream still flushes normal or reasoning text buffered by its parsers, which Python does not. This predates the PR.

**Merge note:** this and #45131 both add an import to `sglang-server`'s completions test module; keep both.

**Breaking changes:**
- Clients cannot tell a deliberate abort from a natural stop by `finish_reason`.
- An abort with an error status, such as EPD's, now fails the request instead of returning 200 with partial output, including through the Anthropic `/v1/messages` adapter.
- With `n > 1`, one such choice fails the whole request.
