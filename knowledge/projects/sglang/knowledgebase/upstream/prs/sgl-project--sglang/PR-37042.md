# [comm] Rebuild the custom all-reduce v2 dispatch layer

[Upstream PR](https://github.com/sgl-project/sglang/pull/37042) · state: closed · merged: False

## Original PR description

> Generated by Claude.

## Motivation

Picking a kernel for one all-reduce depended on five places that had to agree: the tuned crossover table, a five-layer precedence pile in `__init__`, a post-rendezvous patch that nulled `num_mc_blocks` once multicast turned out to be unavailable, a post-construction threshold mutation used by the benchmark, and the ordered if-chain in `_pick_config`. The chain's meaning lived in the order of its branches, in a different file from the numbers it read, and the thresholds were both the routing input and the source for workspace sizing -- a circular dependency laundered through repeated `_replace`.

## Modifications

The tuned crossovers become a private source format under `device_communicators/config/`. A communicator compiles them **once**, against its own workspace capacity and multicast availability, into a sorted band table that the hot path scans:

```
config/__init__.py                  wiring; the public surface
config/..._v2_dispatch.py           Dispatch / Band / Tuning, the runtime table
config/..._v2_tuning.py             per-arch crossovers + the compile policy
```

`_RawTuning.compile` is the only place that knows the priority order.

- **Multicast is probed up front**, on a small symmetric-memory allocation, so availability is an input to the table instead of a retroactive patch.
- **Sizing, grid widths and plane allocation are pure functions**; `__init__` orchestrates and unpacks them.
- **Test hooks replace the table instead of mutating thresholds**: `force_algo(algo, use_multicast)` installs a single-algo table; `uncap_pull` is a constructor flag that runs the fallback up to workspace capacity. It is never implied by passing an explicit `max_pull_size` -- a sizing argument no longer changes routing.
- **`PullPlaneObj` accepts an all-empty plane.** A push-only communicator (`max_pull_size=0, num_pull_blocks=0`) holds one as a placeholder, and each half already fails with its own message when a kernel needs it (`"slice escapes the 0-byte pull workspace"`, `"This pull plane has no semaphores to barrier on"`), so the ctor check was only refusing a legal state earlier.
- **New tuning aid**: `test/manual/kernels/tune_custom_all_reduce.py` times every algo our kernel can run, plus NCCL, at each message size. Latency only -- a crossover is a latency question. Columns are the *forced* dispatch, so every algo is measured at every size, including sizes where the current table hands back to NCCL.

No tuned number changes in this PR.

## Accuracy Test

Dispatch decisions are unchanged. An offline sweep replays the pre-refactor `_pick_config` chain against the new table over the whole default construction path (workspace sizing -> clip -> select), fed the same tuned tuples so a tuning edit cannot be mistaken for a regression:

| check | coverage | result |
| --- | --- | --- |
| default construction path | SM90 / SM100 / SM107, every world size, multicast on+off, eager+graph | 10420 sizes, **0 dispatch mismatches** |
| band compilation | same axes, unclipped | 10160 sizes, **0 mismatches** |

The one behavioral difference is a workspace size, not a route: SM107 world 2 is the only entry whose three crossovers are all equal, so it compiles to a single push band and no longer allocates a 16 MB pull buffer that nothing could reach. Routing there is identical (push covers the whole clipped range).

Correctness on 8x B200:

| test | result |
| --- | --- |
| `test_custom_all_reduce.py`, world 2-8 incl. odd sizes | 180 x 7 = 1260 passed |
| `test_tp_qknorm.py` (push-only instance) | 42 x 3 passed |
| `kimi_k3/test_ar_fusion.py` | 58 passed |
| `kimi_k3/test_collectives.py` | 4 passed / 1 skipped, 5 passed |
| `unit/distributed/` + module-state / global-config / legacy-global / server-args ratchets | 23 + 5 passed |

## Benchmarking and Profiling

`bench_custom_all_reduce.py` over world 2-8: no regression, 154 rows with no missing cells. 8x B200, 64 MB: 575 GB/s (JIT graph) vs 395 GB/s (NCCL). `bench_tp_qknorm.py`: 2072 GB/s at 16384 tokens.

The new sweep confirms the SM100 table on this machine. Every crossover the tables encode for world 2 / 4 / 8 falls in the right sampling interval, e.g. world 8 graph `1shot_push -> 2shot_pull` at 0.5 MB:

| size | 1shot_push | 2shot_pull.g |
| --- | --- | --- |
| 512 KB | **9.30 us** | 10.68 us |
| 640 KB | 10.99 us | **10.91 us** |

Two observations left for a follow-up, both within noise and not touched here: world 8 graph's multicast range `(8 MB, UNTUNED_MAX)` is generous -- multicast leads only to 32 MB, and plain `2shot_pull.g` is 0.5-1.7% faster at 64/128 MB; and `UNTUNED_MAX = 128 MB` cedes 256/512 MB to NCCL on world 2/4 graph where our path is still 5-20% faster.
