# [AMD][CI] Fix ROCm kernel wheel sources: drop eagle_utils, add DSV4 kernels

[Upstream PR](https://github.com/sgl-project/sglang/pull/42461) · state: closed · merged: True

## Original PR description

## What

Bring the ROCm kernel wheel's source lists (`3rdparty/amd/wheel/sgl-kernel/CMakeLists_rocm.txt` and `rocm_hipify.py`) back in line with `setup_rocm.py` and `common_extension_rocm.cc`:

- Remove `csrc/speculative/eagle_utils`.
- Add `csrc/elementwise/deepseek_v4_topk` and `csrc/elementwise/dsv4_norm_rope`.

## Why

The release workflow does not build with `setup_rocm.py`. `build-rocm-matrix` copies `3rdparty/amd/wheel/sgl-kernel/*` into the AOT directory, and `build_rocm.sh` builds with `CMakeLists_rocm.txt`. Those lists have drifted, which causes two problems.

**The build fails (0.4.8, 0.4.9).** #40033 moved the EAGLE tree kernels to JIT. It reduced `eagle_utils.cu` to an include of `python/sglang/kernels/jit/include/sgl_kernel/speculative/eagle.cuh`, and dropped the file from `setup_rocm.py` and its op registrations from `common_extension_rocm.cc`. The wheel lists still compiled it, and the JIT include directory is neither on that include path nor mounted into the build container:

```
/sgl-kernel/csrc/speculative/eagle_utils.hip:28:10: fatal error: 'sgl_kernel/speculative/eagle.cuh' file not found
```

- 0.4.9: https://github.com/sgl-project/sglang/actions/runs/37155260604/job/111315213887
- 0.4.8: https://github.com/sgl-project/sglang/actions/runs/36649756025/job/109710303032

No ROCm wheels were published for either version.

**The published wheels fail at import.** `common_extension_rocm.cc` registers `deepseek_v4_topk_transform_512` and the three `dsv4_fused_*` ops, and `setup_rocm.py` compiles their sources, but the wheel lists never included them. In the published `0.4.6.post1+rocm720`, `0.4.7+rocm720` and `0.4.7+rocm1000` wheels, `common_ops.abi3.so` has all four as undefined `R_X86_64_GLOB_DAT` relocations. Those are resolved at load time, so loading the library fails. The ROCm Docker images build with `setup_rocm.py` and are not affected.

## Test plan

Built both ROCm wheel legs with `release-whl-kernel.yml` at version 0.4.9 on a test branch, with all publish steps disabled: https://github.com/sgl-project/sglang/actions/runs/37189886891

| Leg | Result |
|---|---|
| `build-rocm-matrix (3.10, 720)` | pass, `sglang_kernel-0.4.9+rocm720` built |
| `build-rocm-matrix (3.10, 1000)` | pass, `sglang_kernel-0.4.9+rocm1000` built |

- All 16 sources compile for gfx942 and gfx950 together, so both `HIP_FP8_TYPE_FNUZ` and `HIP_FP8_TYPE_E4M3` are defined. The DSV4 files had previously only been built single-arch through `setup_rocm.py`.
- A build-only step ran `nm -D --undefined-only` on `common_ops.abi3.so` in each wheel. No sgl_kernel op is left unresolved; the only undefined symbols are from Python and torch.
- The wheels were not imported or run on a GPU.
