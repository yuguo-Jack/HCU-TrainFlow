# [Feat] model-runner: Add an opt-in step-shape log

[Upstream PR](https://github.com/sgl-project/sglang/pull/46589) · state: open · merged: False

## Original PR description

## Motivation

A full-workload run needs the batch size and KV-length distribution of every `ModelRunner.forward`, separate from the profiler span. Formatting a `logger.info` line on that path takes the logging lock and writes stdout, which can stall the forward thread. The lengths themselves are small enough to keep until the process exits.

## Modifications

- Add `SGLANG_LOG_STEP_SHAPES=off|summary|vector` (default `off`) and `SGLANG_LOG_STEP_SHAPES_PATH`.
- On `tp_rank == 0` and `attn_cp_rank == 0`, copy per-request N_Q and KV lengths into an in-memory buffer. `summary` and `vector` store the same bytes. The env var is read once.
- The scheduler writes one `SGLSTEP1` file at process exit (`atexit` as well). Median and CSV text are produced offline by `python -m sglang.srt.model_executor.step_shape_log`.
- Paths that replay a CUDA graph without calling `ModelRunner.forward` are not recorded.
- Unit tests cover the binary round trip, including draft steps and a step with no lengths.

## Accuracy Tests

Recording reads CPU-side batch metadata only. Model outputs are unchanged, and the flag defaults to off.

## Speed Tests and Profiling

Default `off` does not allocate the buffer. When enabled, the forward thread copies the length arrays and does not call `logger.info`. The file is written once, after the event loop returns.
