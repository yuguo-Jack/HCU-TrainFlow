# [Refactor] dsv41: Write the candidate table into caller-held prefill graph buffers

[Upstream PR](https://github.com/sgl-project/sglang/pull/46399) · state: closed · merged: True

## Original PR description

- The candidate source's full top-k break in the prefill graph writes its sparse table (block ids, DeepGEMM schedule, physical blocks, valid lengths) into the layer's table buffers and returns nothing; the captured consumers bind those same buffers. Before, the break returned a fresh table on every replay and the graph wrapper copied it into the one it had captured.
- The caller looks the buffers up with `prefill_graph_table` and passes them to the break. On the first run, a warmup, there are none, and the break allocates them from the real table. Buckets share each layer's newest buffers; older ones stay alive for the graphs captured on them.
- Capture and replay take the same path through the break, so the `shared=is_capturing()` switch, `_shared_graph_table`, and the now unused `is_capturing` are removed.
- No behavior change intended. The changed path runs only on SM100 and newer with the breakable prefill graph; GPU runs pending.
