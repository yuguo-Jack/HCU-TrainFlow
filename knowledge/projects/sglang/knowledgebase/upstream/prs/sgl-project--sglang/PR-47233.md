# [Fix] mem-cache: Use indexed operations for Mamba state slots

[Upstream PR](https://github.com/sgl-project/sglang/pull/47233) · state: closed · merged: False

## Original PR description

## Motivation

Use explicit Torch indexing primitives for Mamba slot copies and CPU restores, so these operations do not require multidimensional advanced-index assignment on every backend.

## Modifications

- Use `index_select` and `index_copy_` for selected state rows, with non-NPU indices normalized to `int64`.
- Apply the same change to the current `StateView` API: copies still move whole arena entries, while CPU restores write the existing conv and temporal views.
- Preserve NPU assignment paths, fused CUDA conv copying, sibling state operations, and ReplaySSM destination-cursor resets. Skip empty temporal buffers.
- Require unique copy destinations, checked only in debug mode. Existing `index_fill_` clearing is unchanged.

This refresh replaces closed #38761 after the KV-pool refactor; it does not restore the removed `UnifiedMambaPool` class.

## Accuracy Tests

CPU-tensor validation on Python 3.14 / Torch 2.16, with the compiled CPU engine disabled:

20 passed, 4 GPU-only tests skipped. Unchanged `main`: 16 passed, the same 4 skipped.

Additional local checks covered overlapping source/destination rows, strided and contiguous tensors, FP32/BF16, and ReplaySSM cursor resets. The NPU assignment branch was exercised with CPU tensors, not NPU hardware.
