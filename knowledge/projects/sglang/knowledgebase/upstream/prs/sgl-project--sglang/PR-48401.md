# [Test] [Intel] jit: Stub tvm_ffi paths in test_jit_cache when tvm_ffi is absent

[Upstream PR](https://github.com/sgl-project/sglang/pull/48401) · state: open · merged: False

## Original PR description

## Motivation

`test/registered/unit/kernels/test_jit_cache.py` fails on Intel XPU (BMG) with `ModuleNotFoundError: No module named 'tvm_ffi'` for every case that builds a ninja file, e.g. `test_build_key_separates_every_build_input[ldflags]`.

`ninja.generate()` calls `toolchain.base_include_paths()` / `base_link_flags()`, which import `tvm_ffi` through `tvm_ffi_paths()`. `apache-tvm-ffi` is a core dependency in `pyproject.toml` but is not in `pyproject_xpu.toml`, so it is absent on XPU images.

## Modifications

Test-only change: an autouse fixture replaces `toolchain.tvm_ffi_paths` with fixed fake paths **only when `tvm_ffi` cannot be found**. These tests check build-key and ninja-text invariants, so only the paths' text matters.

No library code changes and no new dependency. CUDA/ROCm/MUSA/CPU lanes have `tvm_ffi` installed, so the stub never turns on there and their behavior is unchanged.

## Testing

| With `apache-tvm-ffi==0.1.11`, with this PR | 44 passed |
