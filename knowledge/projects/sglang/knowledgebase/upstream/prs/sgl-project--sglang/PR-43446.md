# Fix Mistral-native format detection when the Hub is unreachable

[Upstream PR](https://github.com/sgl-project/sglang/pull/43446) · state: closed · merged: True

## Original PR description

`is_mistral_native_format` decides from the Hub file listing for a repo id and returns False if that call fails. When CI launches offline (on hosts whose cache passes validation) or the Hub returns 429, Mistral-Small-4 loads its HF-format weights into the Mistral-native model, skips all 2970 weights, and crashes at CUDA graph capture on `w_kc.dtype`.

Since 9/25, every offline launch of `test_ministral4_models` crashed this way (8/8). CI's online retry usually hid it. The test fails when that retry also hits HF 429 (2/49 runs):
- https://github.com/sgl-project/sglang/actions/runs/37922198403/job/113792765425
- https://github.com/sgl-project/sglang/actions/runs/37612296419/job/112762467951

Fall back to the local snapshot when the Hub call fails. Verified on 2x H200: the offline launch loads with 0 unrecognized weights, and `test_ministral4_models` passes in CI mode (MMMU 0.50, offline, no retry).

- ch-wan · comment · 2026-10-10T01:37:57Z · [source](https://github.com/sgl-project/sglang/pull/43446#discussion_r4235862841)

File: `python/sglang/srt/arg_groups/model_path_hook.py` · line 356

**[suggestion]** The new fallback passes `cfg.revision` into `find_local_repo_dir`, but that helper only resolves a revision when it is falsy (`None` → read `refs/main`) or when `snapshots/<revision>` already exists as a directory (commit SHA). A branch or tag string such as `"main"` or `"v1.0"` is truthy, so the helper looks for `snapshots/main` (which HF cache does not create) and returns `None`, and the fallback silently returns `False` — same broken offline behavior the PR is fixing. Default `revision=None` (the CI case) is fine; explicit `--revision main` / tag while Hub is unreachable is not.

**Suggestion:** Before treating a miss as fatal, resolve non-SHA revisions through the cache refs (e.g. try `refs/<revision>` / `refs/main` then `snapshots/<sha>`), or call an HF helper that already does that (`snapshot_download(..., local_files_only=True)` / equivalent). Alternatively, if you only intend to support the default-revision offline path, pass `revision=None` here and note that branch/tag offline detection remains best-effort.
