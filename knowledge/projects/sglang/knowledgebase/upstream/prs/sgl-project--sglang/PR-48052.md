# [HiCache] Storage touch hook and prompt_cache_options.ttl retention hint

[Upstream PR](https://github.com/sgl-project/sglang/pull/48052) · state: open · merged: False

## Original PR description

## Motivation

HiCache storage backends only see the L3 traffic they serve. Prefix hits served from device or host memory never reach storage, so a backend cannot tell that a stored prefix is still hot, and a backend that offers a minimum retention time (e.g. to back a prompt-cache TTL) has no way to receive the per-request TTL.

## Modifications

- `HiCacheStorage.batch_touch(keys, extra_info=None)`: new optional hook, **default no-op**. Called once per finished request with the request's whole page-hash chain (from the sequence start), so a backend can renew retention of pages served from memory or start retention for new ones. Pages may still be in the backup queue when it runs; backends handle that themselves.
- `HiCacheController.touch_storage(hash_values, ttl_s)`: runs the hook on a dedicated single-thread executor (never on the scheduler thread); skipped on non-writer ranks and when storage is disabled. Failures only log.
- `UnifiedRadixCache.checkpoint_into_tree`: on request finish, touches `get_prefix_hash_values(last_node)`.
- Request field `prompt_cache_options: {"ttl": "90s" | "5m" | "1h"}` on `/v1/completions` and `/v1/chat/completions` (validated `^[1-9][0-9]*(s|m|h)$`) → `GenerateReqInput.cache_retention_ttl_s` → `Req.cache_retention_ttl_s` → `extra_info.extra_info["retain_ttl_s"]` of the touch. Backends without retention ignore it.
- `HiCacheStorageFailureInjector` forwards `batch_touch`.

No change to cache keys, scheduling, or any existing backend's behaviour.

## Accuracy Tests

Not applicable (no model-side change). Outputs at temperature 0 were compared before/after an L1/L2 flush with a storage backend that implements the hook; identical.

## Benchmarking and Profiling

The hook runs off the scheduler thread; the default backend is a no-op.
