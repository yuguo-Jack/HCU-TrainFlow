# [Bugfix] Preserve fp32 MoE router precision across model gates

[Upstream PR](https://github.com/sgl-project/sglang/pull/38719) · state: open · merged: False

## Original PR description

## Motivation

Addresses the independent model fixes called out in #38695.

Several MoE models still discard router precision at model-specific boundaries:

- MiMo-V2, Ernie4, and Kimi Linear can construct the checkpoint correction bias in bf16, even though expert selection consumes it in fp32-sensitive score arithmetic.
- Bailing MoE and Bailing MoE Linear compute with fp32 router weights when configured, then cast the logits back to the hidden-state dtype before top-k.

These paths either collapse checkpoint bias values or throw away the fp32 router output immediately before expert selection.

LLaDA2 originally had the same router-output downcast, but #31768 fixed that path independently. The current PR therefore leaves LLaDA2 untouched.

## Modifications

- Keep `e_score_correction_bias` parameters in fp32 for MiMo-V2, Ernie4, and Kimi Linear.
- Return the gate GEMM output at the router-weight dtype for Bailing MoE and Bailing MoE Linear.

The patch is limited to five model files. It does not introduce a shared `RouterGate`, add a kernel, or change expert computation.

## Accuracy Tests

No new unit test is included, following the maintainer guidance in #38695 that these model-file fixes do not require one. The changes only preserve the dtype already selected for the correction bias or router GEMM output.

## Speed Tests and Profiling

Not applicable. No kernel is added. The Bailing paths remove a dtype-conversion operation when the router is configured for fp32.
