# [sglang-miles] Add NVFP4 MoE weight checker support

[Upstream PR](https://github.com/sgl-project/sglang/pull/42283) · state: open · merged: False

## Original PR description

NVFP4 MoE weights currently either compare raw storage (TRTLLM) or reject weight checking (CuteDSL). This makes equivalent scale encodings fail comparison and prevents checking the CuteDSL standard path after a weight update.

Decode TRTLLM and CuteDSL standard NVFP4 expert layouts into comparable values using the packed FP4 weights, block scales, and global scales. Check execution alphas and separately stored swizzled/MMA scales alongside their weights so stale derived parameters are detected. Existing quantization-error tolerance remains opt-in.

Validation:
- `pre-commit run --all-files`: passed.
- `test/registered/e2e/rl/test_weight_checker_nvfp4.py`: 5 tests passed on one B200 with PyTorch 2.13.0+cu130 and FlashInfer 0.6.18. Covers real backend layouts, equivalent scale encodings, corruption, CPU snapshots/chunking, and separate padded scales.
- Existing `test_weight_checker.py` and `test_weight_checker_comparator.py`: 75 tests passed on the same B200.
- [CPU regressions](https://github.com/sgl-project/sglang/actions/runs/37076133862): all 192 tests across four files passed against `e159d0251060f9d476d2c4b0e17984cea8b95167`; includes NVFP4 configuration, MoE dispatch/scales, and runtime context.
- Targeted TE 4over6 probe on the B200: quantized the same seeded BF16 tensor (2 x 256 x 256) with regular NVFP4 and 4over6 using E4M3 maxima 448 and 256. QDQ strict equality failed as expected (max absolute differences 0.78125 and 1.0), while both had zero elements beyond combined ULP tolerance. Injected sign-bit corruption exceeded tolerance at 857 and 867 elements respectively. This is a small numerical probe, not model-level training/update validation.

This change does not provide per-update transport checksum verification or enable the Miles recipe checker flags. Quantization tolerance intentionally permits some byte differences; transport integrity requires a separate checksum over the transmitted representation.

The 4over6 probe does not establish a universal error bound. In particular, blockscale underflow to zero also makes this checker's per-side tolerance zero, so the current bound need not cover all valid cross-quantizer differences. Such boundary cases have not been validated on GPU.

The ordinary PR Base/Extra workflows are blocked by the upstream maintenance ancestry check (`Required base commit: 8854857a991e` on `main`). This PR intentionally targets `sglang-miles`; the CPU workflow above tests the exact PR head independently.

Scope: NVFP4 MoE TRTLLM and CuteDSL standard. NVFP4 Linear and other unsupported backends remain unsupported.
