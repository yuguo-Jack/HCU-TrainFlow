# [Fix] diffusion: Server warmup reaches every data-parallel replica

[Upstream PR](https://github.com/sgl-project/sglang/pull/47571) · state: closed · merged: True

## Original PR description

## Motivation

With `--dp-size > 1`, `--warmup-mode server` warms only one replica. The warmup requests go through `forward`, which routes with the round-robin `_select_replica`, so one warmup request lands on replica 0 only and every other replica serves its first real request cold.

Observed on MiniMax-H3 fl2va, `--num-gpus 2 --dp-size 2 --performance-mode speed --warmup-mode server`: the log shows `Warmup requests 1/1`, and replica 1's first real request took 121.9 s against about 116.6 s warm. Its MP4 also differed from the warm output (video bit-identical, audio SNR 52.8 dB). A 1-GPU server with `--warmup-mode off` reproduces the same cold-first-request output, so that difference is a cold-path effect, not a DP bug; warming every replica removes it from the served traffic.

## Modifications

- `SchedulerClient.forward` / `AsyncSchedulerClient.forward`: new keyword-only `replica` argument that pins an ordinary request to one replica and bypasses `_select_replica`, so `_replica_counter` only advances for real traffic. Control requests still fan out to all replicas.
- `run_async_client_warmup` / `run_sync_client_warmup`: build the warmup list once and send the full list to every endpoint in `server_args.scheduler_endpoints`, replicas in parallel (asyncio tasks / a thread pool) and each replica's list in order. Every replica sees the same list, so `warmup_total` stays correct per replica, and OOM degradation retries independently per replica. All replicas finish before the first error is raised, so a failure does not leave siblings warming in the background of live traffic.
- With `dp_size == 1` behavior is unchanged: the single request still goes to `endpoints[0]` and the counter was never advanced in that case.
- Tests: `test_server_warmup_reaches_every_replica_without_skewing_round_robin` in `test_scheduler_client.py` (sync and async) asserts that with two endpoints both receive the whole warmup list with `warmup_total == 2`, and that real traffic then still starts at replica 0. It fails on `main` and passes here. `test_cfg_parallel_warmup.py` only gains the `scheduler_endpoints` its mock `server_args` now needs.

## Accuracy Tests

No model-output change: only which replica receives each warmup request changes.
