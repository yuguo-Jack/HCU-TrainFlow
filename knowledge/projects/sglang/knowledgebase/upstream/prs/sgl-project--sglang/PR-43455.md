## Motivation

The residual read and update protocols carried several capabilities that binding relies on but nothing enforced: whether an update writes the next stream itself was decided by identity against one `ReplaceAtExit` instance; whether a sum may run quantized was folded into "is a plain add"; whether a read needs every row of the attention was optional with a default of `False`, so a read that needed every row but did not say so silently read only this rank's slice. Nothing checked that a read or update sets what binding reads, or that the combinations it sets are ones binding handles.

Two defects sat behind the same looseness:
- On an input-scattered batch, the step that gathers an attention's rows before the projection was chosen only for an update other than a plain add, standing in for "this attention has no QKV hook". GLM-5-Next's KDA layers have no hook, so with a plain update and `--enable-attn-tp-input-scattered` they projected half the rows and the first prefill failed at the next stage with a size mismatch.
- On an input-scattered batch, an FFN whose compute completes its sum (`output_complete`) or that writes the next stream itself still carried its sum group and reduce-scatter permission, so a complete output would have been summed again. No model reaches this today (input-scattered attention runs for the DeepSeek-V2 family and GLM-5-Next, whose FFN outputs owe their sum; Kimi K3 turns the option off; Gemma 4 binds the variant but never selects it).

## Modifications

- **Say on the residual update whether it writes the next stream itself** (`ResidualUpdate.writes_stream`, set on every update).
- **Keep whether a sum may run quantized apart from being a plain add** (`ResidualUpdate.quantized_sum`, set on every update and checked when a stage is declared; only `PlainAdd` sets it to True, so the same sums run quantized as before).
- **Require every residual read to say whether it needs the attention's rows** (`reads_after_attn_tp_gather` is required; the final read gets a `FinalRead` protocol documenting its optional members).
- **Check a stage's residual read and update when it is declared.** A `StageDeclaration` names any required member a read or update lacks, and rejects an update that writes the next stream without being applied at its exit, or that lets its sum run quantized without being a plain add; binding a stack's last stage rejects an update the final read cannot apply. No model declares any of these.
- **Gather an input-scattered attention's rows when no QKV hook does.** Every attention on an input-scattered batch takes the step that gathers before the projection exactly when there is no hook or the attention is DSA.
- **Owe no sum for a complete FFN output on an input-scattered batch.** The input-scattered output contract uses the same completeness test as every other variant. The next attention keeps the entry it already binds for an input whose sum is done, which keeps the residual on this rank's slice.
- **Read a residual read's kernels directly and say MHC's rules plainly; say where each residual read applies a post-residual addition.** Every read sets `completing_fusions` and `gathering_reads`, empty when it offers none (the two attention-residual bank reads each supply one, over empty defaults on their base); a stage's declaration checks that its read sets both, and binding reads them directly instead of through `getattr` with a default; documentation. No read changes what it does.

## Accuracy Tests

How the stack is checked:
- **Unit tests**: the 39 layer-boundary test files pass at the head of every PR in the stack, apart from the two AMD-only `test_aiter_allreduce_fusion_amd` cases that fail on NVIDIA on main too; the test files that changed most recently pass on every commit. The full `test/registered/unit` suite (926 files, one process per file) shows no failure on the stack's head that main does not have.
- **Plan comparison**: an out-of-tree harness binds every stage plan for seven stack shapes (decoder layers with and without an output transform, MHC, Nemotron-H patterns, Kimi K3, Qwen4-exp, NemotronNAS-style attention-only layers, single-stage appends) over 23 parallel configurations, four boundary reductions and one or two pipeline ranks (3,928 scenarios), and compares each bound plan leaf by leaf with the parent commit's.
- **GPU**: dummy weights are seeded per TP rank and scaled (0.05, norms 1.0), so that a sum taken twice or a mixture of rank partials changes the output; the default dummy weights give every rank the same shard and would hide both.
- GPU results below were measured on these commits as based on main `516fd1c1b5` unless marked as on the merge candidate; rebasing onto current main had no conflicts, and the CPU checks were run again after it.
- **On the merge candidate** (head of this stack against main `961bcf481d`, H200, asymmetric dummy weights unless noted): DeepSeek-V2-Lite input-scattered PP2 is bit-identical to PP1 (main crashes on it); Nemotron-H cut between a mixer and its FFN differs from PP1 only at the rounding level of the FFN-to-mixer cuts (main: 0.93 and 2.21); Llama, Qwen3-MoE, GPT-OSS and DeepSeek-V2-Lite are bit-identical to main at PP1 and PP2; GSM8K (real DeepSeek-V2-Lite weights, 250 questions, TP4 with attention DP2 and the dense FFN fully data-parallel) gives 0.360 at PP2, 0.364 at PP1 and 0.368 on main at PP1, medians of three runs whose run-to-run spread is 0.012–0.016. The last revision of the stack changed only comments, docstrings, an equivalent condition and explicitly set attributes after these runs; its bound plans are identical.

For this PR:
- GLM-5-Next (synthetic non-MHC config with KDA layers, H200, TP2, input-scattered on): main fails on the first prefill; with this PR every KDA layer's input and output are bit-identical to the run with input-scattered attention off, over five prompt lengths. The MHC variant and a DeepSeek-V2-Lite synthetic model are bit-identical to main.
- The complete-output fix: a test runs attention, an FFN with a complete output and the next attention on simulated attention-TP ranks with input-scattered attention, with and without a QKV hook. On the parent the eight complete-output cases fail with the FFN term summed twice; the partial-output controls pass on both. The output-contract test now enables the input-scattered variant and asserts it is bound.
- The plan comparison differs from the parent only in the input-scattered attention adapter and, for the complete-output fix, in 16 Kimi K3 input-scattered scenarios (the MoE output's sum group becomes none), which the K3 argument checks never reach.

## Speed Tests and Profiling
