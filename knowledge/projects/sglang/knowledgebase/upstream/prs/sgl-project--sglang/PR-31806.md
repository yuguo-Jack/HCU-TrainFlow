# qwen3_5: fix multimodal mrope positions being collapsed by the CUDA fused rope kernel

[Upstream PR](https://github.com/sgl-project/sglang/pull/31806) · state: closed · merged: False

## Original PR description

## Motivation

On CUDA, `Qwen3_5AttentionDecoderLayer.self_attention` always takes `forward_prepare_cuda_fused` when `attn_output_gate` is set. Its `fused_qk_gemma_rmsnorm_rope_gate` kernel indexes `positions` as a flat `[T]` tensor, but multimodal requests on Qwen3.5/Qwen3.6 (`Qwen3_5ForConditionalGeneration`) pass mrope positions shaped `(3, T)` — the kernel silently applies only the temporal position row across the whole rotary dim, so image-conditioned outputs are corrupted with no error raised.

## Modifications

Route 2-D positions to `forward_prepare_fused_gate` instead (2-line change): its Triton norm+gate kernel runs fine on CUDA and its `rotary_emb` call dispatches to the fused Triton mrope kernel. Text-only requests (1-D positions) keep the existing CUDA fused path.

## Accuracy Tests

Validated serving Qwen3.6-27B-FP8 on 8xB200 with screenshot-heavy multimodal traffic: without this change the model consistently misreads image content; with it, image-conditioned responses are correct. Text-only outputs are unaffected (that path is untouched).

## Speed Tests and Profiling

No change to the text-only hot path. Multimodal batches move from the (incorrect for mrope) CUDA fused kernel to the Triton fused-gate path — correctness fix.

"performance unchanged" claim holds at the dispatch level.

Routing to `forward_prepare_fused_gate` rather than fully native looks right to me since
it keeps the QK-norm + gate fusion and only defers rope. Also worth noting
`fused_qk_gemma_rmsnorm_with_gate` is pure Triton and imported unconditionally, so
sending CUDA into that branch is safe.

**One gap:** this guards the dispatch, but `fused_qk_gemma_rmsnorm_rope_gate` still

<summary>Standalone repro (no weights, no images). The kernel drops rows 1 and 2</summary>

```python
import torch
from sglang.srt.runtime_context import get_context
from sglang.srt.server_args import ServerArgs

get_context().set_server_args(ServerArgs(model_path="dummy"))

from sglang.kernels.ops.attention.fused_qk_rmsnorm_rope_gate import (
    fused_qk_gemma_rmsnorm_rope_gate,
)
from sglang.srt.layers.rotary_embedding.mrope import MRotaryEmbedding

torch.manual_seed(0)
DEV, DTYPE = "cuda", torch.bfloat16
T, NQ, NKV, HD, RD = 8, 4, 2, 128, 128
MROPE_SECTION = [24, 20, 20]          # real Qwen3-VL split, per the comment in mrope.py

temporal = torch.arange(T, device=DEV, dtype=torch.int64)
zeros = torch.zeros(T, device=DEV, dtype=torch.int64)
pos_a = torch.stack([temporal, zeros, zeros])
pos_b = torch.stack([temporal,
                     torch.arange(100, 100 + T, device=DEV, dtype=torch.int64),
                     torch.arange(200, 200 + T, device=DEV, dtype=torch.int64)])

q_gate = torch.randn(T, NQ * 2 * HD, device=DEV, dtype=DTYPE)
k = torch.randn(T, NKV * HD, device=DEV, dtype=DTYPE)
qw = torch.randn(HD, device=DEV, dtype=DTYPE)
kw = torch.randn(HD, device=DEV, dtype=DTYPE)

rope = MRotaryEmbedding(head_size=HD, rotary_dim=RD, max_position_embeddings=4096,
                        base=10000, is_neox_style=True, dtype=DTYPE,
                        mrope_section=MROPE_SECTION, mrope_interleaved=True)
cache = rope.cos_sin_cache.to(device=DEV, dtype=DTYPE)

def fused(p):
    q, k_, _ = fused_qk_gemma_rmsnorm_rope_gate(
        q_gate, k, qw, kw, cache, p, 1e-6, NQ, NKV, HD, RD, has_gate=True)
    return q.clone(), k_.clone()

qa, ka = fused(pos_a)
qb, kb = fused(pos_b)
q1, k1 = fused(temporal.contiguous())     # temporal row alone, as rank-1

print("changing H/W rows changes output:", not (torch.equal(qa, qb) and torch.equal(ka, kb)))
print("[3,T] == row 0 alone:            ", torch.equal(qb, q1) and torch.equal(kb, k1))
```

On unpatched `main`:
```
changing H/W rows changes output: False
[3,T] == row 0 alone:             True
```

The second line is the tightest statement of the defect: passing the full `[3, T]`
tensor is bit-identical to passing only the temporal row, so height and width are
provably never read. The kernel also accepted a rank-2 tensor without raising.
</details>
