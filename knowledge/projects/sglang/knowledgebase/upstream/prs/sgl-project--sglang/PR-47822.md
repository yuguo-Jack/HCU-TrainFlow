# [Perf] [AMD] aiter: Skip q.contiguous() in unified extend when the per-token layout is dense

[Upstream PR](https://github.com/sgl-project/sglang/pull/47822) · state: closed · merged: True

## Original PR description

## Summary

Q tensor was always forced to do `q.contiguous().view(-1, H, D)`  before `unified_attention` (**extend/prefill** path), which isn't necessary when applying fused RoPE + KV write because q is already a **column slice**.  That is unnecessary copy.

This PR replaces the unconditional copy with a small layout helper `_unified_extend_q`. It returns a zero-copy
`view(-1, H, D)` **only when** the result already has unit dim stride and head stride = `head_dim` (what
`unified_attention` / the gfx1250 gluon 2D TDM Q descriptor need). Any other layout still takes the old
`.contiguous().view(...)` path. The fp8-KV extend path is unchanged (its q quantization already materializes a
fresh contiguous tensor).

## Motivation

Call chain (gpt-oss-120b + aiter, `use_triton_unified_attention`):

1. QKV GEMM writes a fused buffer of width `3 · H · D` (TP1: 5120 = 64·64 + K + V; TP2: 2560).
2. Fused RoPE + KV cache write runs with `q_out` pointing at the Q columns of that buffer, so after RoPE, `q` is
   still a **non-contiguous column slice**: shape `(T, H·D)`, token stride 5120 (TP1) or 2560 (TP2), but
   **within each token** the `H × D` elements are dense (dim stride 1, head stride `D`).
3. `_forward_extend_unified` must hand `unified_attention` a 3-D q `(T, H, D)`. Old code always did
   `q.contiguous().view(...)`, which copies even when a view would already be dense per token.
4. AITER's `unified_attention` (and the gfx1250 gluon 2D kernel) address q with `query_stride_0` between tokens and
   require only that heads × head_dim be contiguous inside a token (`stride(2)==1`, `stride(1)==head_dim`). The
   QKV-slice layout already satisfies that; the copy was pure waste.

Trace role: ATen bf16 direct-copy in the prefill attention-prep path (~56 / 119 µs at 8k / 16k per full layer;
~2.0 / 4.3 ms per step over 36 layers). Microbench of `q.contiguous()` alone: 58.8 µs @ 7,500 tokens, 121.8 µs @
16,384.

## Modifications

One helper + one call-site change in `python/sglang/srt/layers/attention/aiter_backend.py`:

```python
def _unified_extend_q(q, num_heads, head_dim):
    try:
        q_v = q.view(-1, num_heads, head_dim)
        if q_v.stride(2) == 1 and q_v.stride(1) == head_dim:
            return q_v          # zero-copy when per-token layout is already dense
    except RuntimeError:
        pass
    return q.contiguous().view(-1, num_heads, head_dim)  # old behavior
```

`_forward_extend_unified` now uses `_unified_extend_q(q, layer.tp_q_head_num, layer.qk_head_dim)` instead of
`q.contiguous().view(...)`. No other extend/decode arm is touched.

## Accuracy Tests

Offline gfx1250 probe (`check_p6b_strided_q.py` / `probe_strided_q.py`); **no new in-tree SGLang unit test**. These
checks are what the title must match: the helper is a **guard**, not an unconditional “always strided, never copy”.

**1. Layout selection** (`_unified_extend_q` vs old `q.contiguous().view`):

| Input layout | Expect | Result strides (H=64, D=64) |
|---|---|---|
| gpt-oss QKV column slice, TP1 (token stride 5120) | **zero-copy view** | (5120, 64, 1) |
| gpt-oss QKV column slice, TP2 (token stride 2560) | **zero-copy view** | (2560, 64, 1) |
| already-contiguous q | view of itself | (4096, 64, 1) |
| `view()` OK but dim stride 2 (`q[:, ::2]`) | **copy** (guard rejects) | (4096, 64, 1) |
| transposed q (`view()` OK, inner stride ≠ 1) | **copy** (guard rejects) | (4096, 64, 1) |

Values always equal the old contiguous reshape; wrong layouts still copy.

**2. Attention equality** — gfx1250 gluon unified-attention **2D extend**, bf16 KV, sinks on:
- Heads: TP1 64/8 and TP2 32/4; full attention and window-128.
- Batches: 4-seq prefill/prefix (7,548 query tokens) and 2-seq chunked-with-prefix (8,192 query tokens).
- Output with `_unified_extend_q(q_slice)` vs old contiguous q: **bitwise equal**, all finite (8/8 cases).

**3. CUDA-graph replay** — capture 10 calls into 10 outputs, replay 20×: **0 mismatches** (200 calls per case).

**4. End-to-end sanity** — gpt-oss-120b W4A8 on gfx1250, controlled A-B-A (A = contiguous path, B = this change):
8192/1024 c64 **1.007**, 70000/300 c4 **1.007**; GSM8K strict **0.9598**.

Not covered here: an in-repo `test/registered/...` unit test (layout guard is pure PyTorch; attention equality needs
gfx1250 + aiter gluon). Closest existing sibling is `test_aiter_fp8_q_unified_attention.py` (decode / fp8-q routing),
which this PR does not change.

## Speed Tests and Profiling

Whole op = old (`q.contiguous()` + attention) vs new (attention on the view), CUDA-graph median, µs:

| Case | old | new | new/old |
|---|---|---|---|
| TP1 7,548 tok, full | 527.5 | 475.2 | 0.90 |
