## Motivation

Kimi-K3 is a hybrid linear-attention (KDA) + MLA MoE model whose 1M-token context makes prefill KV/activation memory the dominant bottleneck on a single accelerator. GPU support for full-sequence context parallel (CP) prefill landed in PR #38344, but the Ascend NPU backend had no CP path.

This PR ports PR #38344 to NPU.

## Modifications

Layer-level dataflow of the NPU CP + SP-residual path:

<img width="1124" height="1179" alt="image" src="https://github.com/user-attachments/assets/503dcf81-876e-42e3-9786-e0a3af45ea4a" />


Shared code changes from PR #38344 are carried in this branch until that PR merges; the only new logic is below.

**NPU backend (all confined to NPU branches/files):**
- `hardware_backend/npu/attention/ascend_backend.py`: `do_cp_mla_attn_fia` — two-segment TND attention over zigzag [prev|next] blocks; radix prefix support by accumulating causal starts over prefix + extend lengths (removed the old explicit `raise`).
- `hardware_backend/npu/modules/deepseek_v2_attention_mla_npu.py`: CP latent materialization — all-gather the rank-local latent shard, write the full-sequence latent into the KV pool, and prepend each sequence's prefix latent from the pool (`_prepend_cp_prefix_latent`) for radix hits; pure local assembly, zero extra communication.
- `hardware_backend/npu/attention/ascend_kda_backend.py`: KDA layers consume full-sequence inputs under CP (no intra-layer sequence comm).

## Accuracy Tests

On Ascend 910B with the layer-truncated K3 proxy model (`num_hidden_layers=5`, covering both KDA and MLA layer types; MLA CP exercises the full zigzag path in layer 4):

**End-to-end regression, 9 configs, radix cache ON** (tp2/tp4/tp8 base, tp2_cp2, tp4_cp2, tp8_cp8, and 3 configs with
`SGLANG_K3_CP_SP_RESIDUAL=1`), each compared against a same-code radix-OFF baseline:
- No-prefix prompts: input logprob diff is exactly zero in all 9 pairs.
- Prefix-hit prompts (`prefix+*`): in_max diff 0.08–1.70, the inherent cache-restore-vs-recompute band, far below the 4–6 cross-run noise floor.
- Decode outputs: identical for all tp2-series pairs; tp4/tp8 greedy divergence traced to decode batch scheduling sensitivity (diverge-at-1 pattern with all-zero input diffs), not to this change.
- Gated negative cases (CP ≠ TP with the SP-residual env set): zero diff, confirming the env gate short-circuits correctly.
- Radix reuse: second identical request reports `cached_tokens > 0`; CP + prefix-hit runs complete through the previously unimplemented code path.
- Decode CUDA graph enabled for all CP configs (capture bs multiple of attn_cp_size) with no numerical regression.
