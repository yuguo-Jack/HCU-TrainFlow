# [Fix] rust-server: Refuse a relayed control request meant for another DP rank

[Upstream PR](https://github.com/sgl-project/sglang/pull/47519) · state: open · merged: False

## Original PR description

## Motivation

Fixes #47511

When rust-server fans a control request out to other DP ranks, each relay to `POST /internal/peer` carries no target rank, and the receiving listener serves it on its own scheduler regardless. If the endpoint table points a rank at another rank's listener (a loopback entry as in #47509, stale or swapped ports, a duplicate entry), `fan_out` records one rank's reply under another rank's id. `/flush_cache` then reports every rank flushed, `/weights_checker` returns one rank's hashes under two ids, and profiling runs on one rank twice, all with a success response.

## Modifications

- `core/peer.rs`: `Peer::forward` sends the target rank in an `x-sglang-dp-rank` header. A peer's `421` maps to `CoreError::Internal`, so the fan-out fails that rank (`dp rank 2: relayed to dp rank 0's listener`, HTTP 500) instead of recording a success.
- `http/info.rs`: `/internal/peer` compares the header with the local `dp_rank` before anything reaches the scheduler: another rank gets `421 Misdirected Request` and a `warn` log naming both ranks; a missing or unparsable header gets `400`. A matching request is served as before.
- `handlers/handle.rs`: a `dp_rank()` accessor on `CoreHandle`.

Only the listener-to-listener route changes; nothing outside `sglang-server` calls it. Requiring the header assumes every listener in a deployment runs the same binary, which holds since they are launched together.

Out of scope: auth on the route (`TODO(auth)`), and the table itself (#47505, #47509). Two listeners that both believe they are rank N, or a table missing a rank, agree with the header, so checking that ranks are unique and complete belongs with the table construction.

## Speed Tests and Profiling

Not a performance change. The relay carries admin control requests only (`/flush_cache`, `/weights_checker`, `/start_profile`, `/server_info`, ...), never `/generate`. Measured anyway: sequential relays over real HTTP, `Peer` -> `/internal/peer` -> core -> a scheduler stub that answers at once, so the numbers are the relay's own overhead. Base and head test binaries were built once each and run alternately, 5 rounds of 20,000 relays each after 1,000 warmup; medians of the 5 rounds.

| Per relay | Base `734aa5503e` | This PR | Delta |
|---|---|---|---|
| p50 | 70.2 µs | 75.0 µs | +4.8 µs |
| p99 | 120.8 µs | 130.7 µs | +9.9 µs |
| mean | 74.6 µs | 83.3 µs | +8.7 µs |
| relays/s | 13,337 | 11,937 | -10% |

Rounds varied by up to 45 µs (base p50 ranged 67.2–111.9 µs), so the delta is single-digit µs per relay. Against a real control request, which waits on the scheduler (a cache flush or a weight hash takes milliseconds or more), it is not measurable. Not profiled.

#[tokio::test(flavor = "multi_thread", worker_threads = 4)]
#[ignore]
async fn bench_forward_control_round_trip() {
    use crate::api_server::core::fanout::ControlTarget;
    use crate::message::config::{DeploymentInfo, RustServerEndpoint};
    use std::future::IntoFuture;
    use std::time::Instant;

    let (state, intake_rx, _abort_rx) = test_state(ServerArgs::default());
    tokio::spawn(async move {
        while let Ok(event) = intake_rx.recv_async().await {
            if let TmEvent::Intake { request, admission } = event {
                assert!(admission.try_accept());
                let _ = request.sink.try_send(ResponseItem::Control(Bytes::from_static(b"ok")));
            }
        }
    });
    let listener = tokio::net::TcpListener::bind("127.0.0.1:0").await.unwrap();
    let url = format!("http://{}", listener.local_addr().unwrap());
    tokio::spawn(axum::serve(listener, routes().with_state(state)).into_future());
    let info = DeploymentInfo {
        rust_server_endpoints: vec![RustServerEndpoint { dp_rank: 0, endpoint: url }],
        ..Default::default()
    };
    let peers = crate::api_server::core::peer_endpoints(&info, 1).unwrap();
    let peer = &peers[0];
    let build = || {
        crate::message::io_struct::ControlRequest::FlushCacheReqInput(
            crate::message::io_struct::FlushCacheReqInput::new(Rid::new().to_string(), Some(1.0)),
        )
    };
    let iters: usize = std::env::var("BENCH_ITERS").ok().and_then(|v| v.parse().ok()).unwrap_or(20_000);
    for _ in 0..1_000 {
        assert!(peer.control(&build).await[0].outcome.is_ok());
    }
    let mut lat_us = Vec::with_capacity(iters);
    let start = Instant::now();
    for _ in 0..iters {
        let t = Instant::now();
        let replies = peer.control(&build).await;
        lat_us.push(t.elapsed().as_secs_f64() * 1e6);
        assert!(replies[0].outcome.is_ok(), "{:?}", replies[0].outcome);
    }
    let total = start.elapsed().as_secs_f64();
    lat_us.sort_by(|a, b| a.partial_cmp(b).unwrap());
    let pct = |p: f64| lat_us[((lat_us.len() as f64 - 1.0) * p).round() as usize];
    println!(
        "BENCH iters={iters} mean_us={:.1} p50_us={:.1} p90_us={:.1} p99_us={:.1} rps={:.0}",
        lat_us.iter().sum::<f64>() / iters as f64, pct(0.50), pct(0.90), pct(0.99), iters as f64 / total,
    );
}
