# [Feat] pd: Defer single-layer NEXTN draft prefill to decode workers

[Upstream PR](https://github.com/sgl-project/sglang/pull/45636) · state: closed · merged: False

## Original PR description

## Motivation

In PD serving with single-layer DSA NEXTN, removing speculative decoding from the prefill worker leaves the decode worker without a complete draft prefix. Keeping ordinary draft prefill on P also consumes prefill capacity.

This opt-in path runs only the target on P, transfers the full prompt's target hidden states alongside the existing target KV/recurrent state, and initializes only the draft prefix on D before normal speculative decode. D does not replay or advance the target model.

Submitted as a draft for protocol/lifecycle review and broader accuracy validation; exact greedy/numerical equivalence has not been established.

## Modifications

- Add `--disaggregation-defer-draft-prefill`, required on both roles while retaining NEXTN arguments. The default path remains unchanged.
- Capture chunked prompt hidden states on the last P pipeline stage; negotiate version/width/dtype and transfer them through Python Mooncake.
- Initialize the full draft prefix on D with local destination indices and TP-consistent admission. Protect hidden/metadata ownership with request generation, PP retirement consensus, and CUDA-consumer fences; quarantine uncertain ownership.
- Integrate final-chunk ownership with the shared sender while preserving asynchronous host-index events and TP-consistent deferred KV release. Reject KV checksum with hidden staging until it supports the separate index domain.
- Reject unsupported configurations early and abort retraction/rebootstrap with error status 503. Streaming HTTP headers may already be 200, so clients must inspect the finish reason.
- Document the supported layout and add seven core cases across three test files, reusing the existing Mooncake test helpers. Cover chunked hidden capture, draft-only initialization, local DSA indices, real two-rank Gloo transport, and safe source retirement.

Initial scope: single-layer DSA NEXTN with unexpanded hidden states, P TP1, D PP1, DP/CP/EP1, Python Mooncake, no prefix cache/offload/role switching/KV checksum. D's max-prefill budget must cover the full input. Full restrictions are in the docs and argument guards.

## Accuracy Tests

- Current source (`82f03091`, based on main `fd5c5258`): **102 CPU cases passed**, using Python 3.11 / PyTorch 2.14.1+cpu. This comprises seven core feature cases and 95 existing sender, deferred-release, wire, and decode-cleanup regressions. Pinned Ruff/isort/format checks, the Mintlify site build, and link/anchor checks for both edited documentation pages pass.
- GPU smoke and quality results below are from the original frozen implementation before the rebase and code simplification.
- Production GPU smoke: 80 requests at CC8, 8192 input / 32 output, plus SSE 8192/128; complete token IDs, no retractions or cache hits, and repeated hidden-slot reuse.
- Upstream `sglang.test.run_eval`, GSM8K, 5-shot, fixed examples 5–204, temperature 0, max output 1024, threads 8, original grader:

| Ordinary P/D MTP | Deferred P draft / D MTP |
|---|---|
| 178/200 (89%) | 184/200 (92%) |

All 200 responses per arm succeeded on the first HTTP attempt, with no empty/truncated/unknown terminal responses. Paired counts: both correct 174, OFF-only correct 4, ON-only correct 10, both wrong 12; exact two-sided McNemar p=0.17956543. Both arms have positive speculative verify/proposal metadata.

These are fixed, nonrandom 200 short prompts (696–805 tokens), one run per arm, with no prespecified equivalence margin. They do **not** establish accuracy equivalence or 8K accuracy. Earlier exact-output diagnostics found ON/OFF differences, as well as same-mode repeat differences; this PR does not claim bitwise equivalence or a proven root cause.

## Speed Tests and Profiling

Official NVIDIA `nvidia/GLM-5.3-Flash-NVFP4` revision `09b04e5e74bca08ca8549fc736d4cdd8624bfde3`; 8 RTX 6000D GPUs on one model-serving node: P=PP4/TP1 (4 GPUs), D=TP4 (4 GPUs). D NEXTN H4/topk1/Q5, FlashInfer PCIe allreduce, full CUDA graph through batch128; P chunk2048, microbatch2, async depth0. CPU router/client run separately.

The GPU accuracy and performance results here were measured on the original frozen implementation based on `6cac4dc3`, with the same settings and initial cache seeds for both arms and only the deferred flag changed. That environment includes existing SM120 sparse-MLA compatibility associated with #38430; those five hardware files are **excluded** from this PR.

The current source is based on main `fd5c5258` and uses its draft parallel placement, shared asynchronous sender, and TP-consistent deferred KV release. Hidden staging and source retirement live in one feature module; PP votes use the existing transport. It has the CPU validation listed above; the historical GPU accuracy/performance measurements have **not** been rerun on this source.

8192 input / cache0 / 1024 output, smooth constant arrivals, global CC256, each row **512 requests × 3 independent waves**. TPS includes full ramp/drain; ± is sample SD across waves. TTFT is measured from offered arrival; mean TTFT and mean TPOT are the gates, P99 is diagnostic.

| Configuration | Offered RPS | Output TPS ± SD | Mean TTFT | Mean TPOT |
|---|---:|---:|---:|---:|
| OFF, 1.5s point | 1.275 | 1266.49 ± 4.80 | 1496.23ms | 15.39ms |
| OFF, 3s point | 1.850 | 1779.68 ± 2.92 | 1711.31ms | 20.80ms |
| ON, suggested point for both tiers | 2.200 | 2060.57 ± 4.71 | 1480.65ms | 26.02ms |

The ON point gains **62.70%** against OFF's tested 1.5s point and **15.78%** against OFF's tested 3s point (257.57 output TPS/serving GPU). These compare each arm's selected rates, not a fixed-rate throughput effect. All pass mean TPOT30/50ms; none pass mean TPOT15ms. ON P99 TTFT is 1571–1576ms and P99 TPOT51.47–51.88ms, so this is not a P99 SLO claim.

A higher ON rate2.25 also passes the finite-wave mean3s gate (2079.51±7.41TPS, TTFT2864.32ms), but TTFT rises consistently across each wave and P99 reaches4.18–4.62s. It is excluded from the suggested capacity point. Bounded tests do not establish indefinitely sustainable capacity or a global optimum.
