# docs(cookbook): DeepSeek-V4 Pro Official (0813) variant with DSpark recipes

[Upstream PR](https://github.com/sgl-project/sglang/pull/34762) · state: closed · merged: False

## Original PR description

## Summary

Adds a **Pro Official (0813)** variant to the DeepSeek-V4 cookbook, building on #34809 (which seeded the variant and the GB300 numbers).

`deepseek-ai/DeepSeek-V4-Pro-0813` bundles a DSpark draft head (config carries `dspark_block_size=5`, `dspark_noise_token_id`, `dspark_target_layer_ids`, `dspark_markov_rank` — same shape as Flash-0731, so SGLang reads the spec shape from the checkpoint). The Pro Official low-latency recipes therefore use `--speculative-algorithm DSPARK`, drop the EAGLE `--speculative-num-steps / -eagle-topk / -num-draft-tokens` flags, and take no `--speculative-draft-model-path`.

What this PR adds on top of #34809:

- **B200 low-latency cell verified end-to-end** (8×B200, TP=8, flashinfer_mxfp4, DSpark) — the only cell flipped to `verified: true` so far
- **Full accuracy set for `pro-official`** (`defaultAccuracy` entry so every cell renders the accuracy card) plus the matching `gpqa` / `aime25` sgl-eval reproduce commands
- A `b200` entry in `deepseek-v4-benchmarks.jsx` (alongside the GB300 entries from #34809)
- Playground polish: EAGLE presets hidden on `pro-official`, DSpark hidden on AMD hardware (CUDA-only), TP/DP-Attn/EP 1,2 hides extended to `pro-official`, DSpark block-size slider covers both official variants

Verified on 8×B200 (sglang v0.5.17 image, full splits, thinking where applicable) against the Pro EAGLE baselines in the same cookbook:

| Eval | Pro Official DSpark (B200) | Pro EAGLE default | Δ |
|---|---|---|---|
| GSM8K (full 1319) | **96.13** — stop-rate 100%, 0 truncated, 0 error | 96.13 | ±0 |
| AIME25 (16 repeats, thinking) | **98.1** pass@1 (maj@16 1.0, stop 100%) | 97.5 | +0.6 |
| GPQA Diamond (16 repeats, thinking) | **89.7** pass@1 (maj@16 91.67, stop 100%) | 90.1 | −0.4 |

Serve log confirms the bundled DSpark head is picked up end-to-end: `Draft checkpoint bundles a DSpark head; loading draft arch DeepseekV4ForCausalLMDSpark`, with `speculative_num_draft_tokens=6` (5 proposed + 1) read from the checkpoint.

## Remaining

- B300 / GB300 / H200 cells: same recipe, different parallelism — flip each to verified after its own hardware run
- Speed (TTFT/TPOT/TPS) rows for the B200 cell: pending B200 devbox availability; will land as a follow-up (GB300 cells already carry speed entries from #34809)
