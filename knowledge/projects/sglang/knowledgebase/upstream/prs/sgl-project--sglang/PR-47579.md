# Fix #47399: Correct next_tokens parameter in NPU graph decode mode

[Upstream PR](https://github.com/sgl-project/sglang/pull/47579) · state: open · merged: False

## Original PR description

## Summary

Fix incorrect `next_tokens` parameter in NPU graph decode mode that was causing wrong attention computation for sliding-window attention layers.

## Problem

In `forward_decode_graph` method of `ascend_backend.py`, the `next_tokens` parameter logic was inverted:
- SWA layers incorrectly received `FULL_ATTENTION_WINDOW` (2147483647) instead of 0
- This caused incorrect attention computation in graph decode mode
- The non-graph decode path correctly uses `next_tokens=0` for all cases

## Solution

Changed `next_tokens` parameter to always be 0 in graph decode mode, matching the non-graph decode path behavior.

**Before:**
```python
next_tokens=(
    0 if layer.sliding_window_size == -1 else FULL_ATTENTION_WINDOW
),
```

**After:**
```python
next_tokens=0,
```

## Testing

- Existing unit test at `test/registered/unit/npu/attention/test_npu_ascend_backend.py:584` already validates `assert kwargs["next_tokens"] == 0`
- Syntax validation passed
- Note: Full validation requires NPU hardware

## Impact

- Fixes incorrect attention computation for SWA models in NPU graph decode mode
- Minimal change (1 line modified, 3 lines removed)
- No breaking changes to API or behavior

Fixes #47399
