# [Fix] model-loader: Honor explicit weight loaders for object-store models and drafts

[Upstream PR](https://github.com/sgl-project/sglang/pull/47436) · state: open · merged: False

## Original PR description

## Motivation

An object-store `--model-path` currently forces `runai_streamer`, overriding an explicitly selected weight loader. For example, `--model-path s3://... --load-format remote_instance --remote-instance-weight-loader-backend modelexpress` never reaches ModelExpress. An object-store draft with no explicit draft format is also forced to streamer instead of inheriting the target's loader.

Fixes #47428. Context: [ModelExpress #925](https://github.com/ai-dynamo/modelexpress/issues/925#issuecomment-6508299458).

## Modifications

- Keep object-store metadata preparation through the existing `handle_model_source_paths()` / `ObjectStorageModel` flow, including the original URI used for weights.
- Use `runai_streamer` as the object-store default only when the resolved weight format is `auto`. Preserve explicit formats, including valid `remote_instance` configurations for NCCL, TransferEngine, and ModelExpress; the object-store branch has no backend-specific exception.
- Resolve invalid remote-instance configurations before applying URI defaults, so their existing fallback to `auto` still selects streamer for an object-store path.
- Let an unspecified draft format inherit the target's resolved loader. An explicit draft format remains authoritative; an effective `auto` format with an object-store draft selects streamer. Other remote-connector URI handling is unchanged.

Coverage includes S3/GCS/Azure and URI case handling; automatic and explicit weight formats; configured NCCL, TransferEngine, and MX backends; incomplete remote configuration and unavailable TransferEngine fallback; draft inheritance and explicit overrides; local/remote-connector behavior; and metadata deduplication. External metadata download and package availability are mocked where needed; these CPU tests do not establish GPU loading for every backend.

Normal pre-commit checks and `git diff --check` passed. Broader server-args and repository-wide pytest collection were attempted but blocked by missing local dependencies (`compressed_tensors` and `prometheus_client`, respectively); those suites are not counted as passed.
