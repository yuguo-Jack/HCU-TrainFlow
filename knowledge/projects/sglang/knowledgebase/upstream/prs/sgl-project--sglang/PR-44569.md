# [Muse Spark] Accept top_k=0 as disabled top-k filtering

[Upstream PR](https://github.com/sgl-project/sglang/pull/44569) · state: open · merged: False

## Original PR description

## Motivation

A local Muse Spark `generation_config.json` with `do_sample: true` and `top_k: 0` produces HTTP 400 in the Python serving path. Interpret the Transformers zero sentinel as disabled top-k filtering for Muse Spark.

## Modifications

Keep the policy in `model_overrides/muse_spark.py`. Resolve its providers once when the tokenizer manager initializes, then apply the alias after sampling parameters are merged and before `SamplingParams` is constructed. Positive top-k values, request precedence, greedy sampling and other models retain their behavior. No test files are added or modified in the final diff.

## Accuracy Tests

- **Real-checkpoint GSM8K smoke on 4 GB300 GPUs:** the unmodified base returned the exact top-k-zero HTTP 400. With the patch, all **16/16 requests returned HTTP 200**, with no retries or truncations and real speculative counters on every response. The numeric answer check matched **15/16** references; this is a bounded serving sanity check, not a full accuracy evaluation.
- Both live phases used identical commands, weights, runtime, prompts and a separate model view with literal `top_k: 0`, `do_sample: true`, temperature 1 and top-p 1. Requests omitted all four sampling fields. DFLASH8, block verification, xhigh reasoning and `--sampling-defaults model` were enabled; no simulated acceptance. The original checkpoint config still has top-k 64 and was not modified.
- **34 private regression probes passed**; the same probe reproduces eight Muse-zero validation failures on the pristine base. Relevant existing CPU tests: **409 passed plus 331 subtests**, one skipped. One pre-existing whitelist assertion about `mm_enable_dp_encoder` fails identically on the base and is left untouched.
- Scoped pinned isort, Ruff check/format and codespell checks passed. Source/model identity checks and owned-process cleanup passed; no OOM events or resource-limit violations.
