# [Feature] Validate empty and non-mapping diffusion config files

[Upstream PR](https://github.com/sgl-project/sglang/pull/45323) · state: open · merged: False

## Original PR description

## Motivation

When loading diffusion configuration files via `ServerArgs.load_config_file()` or `FlexibleArgumentParser._load_config_file()`, empty or comment-only YAML files load as `None`, while YAML lists / JSON arrays load as sequences. The downstream CLI merge logic assumes a mapping and crashes with `TypeError: 'NoneType' object is not iterable` or `TypeError: 'list' object is not a mapping`.

This PR adds root-level type validation to ensure configuration files contain a mapping at the root level, consistent with the existing SRT config merger.

## Changes

1. In `ServerArgs.load_config_file()`:
   - Normalize `None` results (empty or comments-only YAML/JSON) to `{}`.
   - Reject scalar and list/sequence root elements with a clear `ValueError` requiring a mapping/dictionary.
2. In `FlexibleArgumentParser._load_config_file()`:
   - Apply the same normalization (`None` -> `{}`) and dictionary validation.
3. Added focused CPU unit tests in `test/registered/unit/multimodal_gen/test_diffusion_config_validation.py` covering:
   - Valid YAML & JSON mappings
   - Empty YAML
   - Comments-only YAML
   - `null` JSON
   - YAML lists and JSON arrays (rejects with `ValueError`)
   - Scalar roots (rejects with `ValueError`)
   - Unsupported file extensions

Fixes #45182
