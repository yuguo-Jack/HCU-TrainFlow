# [Fix] PD: Skip the cached-prefix early send in batches that start a HiCache load-back

[Upstream PR](https://github.com/sgl-project/sglang/pull/44081) · state: open · merged: False

## Original PR description

## Motivation

Fixes #44070. On a PD prefill server with HiCache, a request re-matched after another request's load-back in the same batch build counts the not-yet-loaded pages as device prefix. `maybe_send_cached_prefix_chunk` then hands those pages to the KV transfer before the H2D copy writes them, so decode silently gets stale KV.

## Modifications

- `Scheduler.run_batch`: if this batch's build submitted a load-back (`batch.hicache_consumer_index >= 0`), skip the early send for its requests. The post-forward send covers the range after the forward has waited for every load layer.
- `maybe_send_cached_prefix_chunk`: new `allow_send` argument. It returns before sending, after the staging snapshot.
- Unit test: no early send when the batch started a load-back; the early send still happens when it didn't.

## Accuracy Tests

The #44070 repro (1P1D, NIXL, HiCache `write_back`, `--disaggregation-enable-kv-checksum` on both roles) on the 2026-10-13 SGLang nightly image, with only this PR's two source files overlaid. The image's copies of those files are identical to this PR's base.

| `--hicache-io-backend` | Trials | KV checksum mismatches, before | After |
|---|---|---|---|
| `direct` | 30 | 29 | **0** |
| `kernel` | 30 | not run | **0** |

With the fix, both concurrent requests' greedy outputs match a fresh run (30/30 each). Batches without a load-back still early-send (every device-hit request did).

## Speed Tests and Profiling

Batches whose build starts a load-back lose the early-send overlap: their KV goes out after the forward. In the repro this was about 54 ms later for a 100K-token prefix. Other batches are unchanged.

Follow-up: keep the overlap by handing the load's completion event to the sender and waiting on it before the read. That needs every connector to honor a wait event; see #43299 for NIXL.
