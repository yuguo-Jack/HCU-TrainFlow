# [Fix] diffusion: Fix VMoBA chunk selection bugs

[Upstream PR](https://github.com/sgl-project/sglang/pull/44286) · state: closed · merged: True

## Original PR description

## Summary
Fixes several selection bugs in `vmoba_attn/vmoba/vmoba.py`, each reproduced on main first.

- `topk` + `head_global` never applied `valid_gate_mask`, so topk could pick -inf entries from other sequences in the batch.
- The "select everything" fallback used `full_like(any_cond, C-1)`, which is bool, so the cutoff became 1 (`query_head`, `block`). Now `torch.full(..., dtype=torch.long)`.
- `threshold` + `overall` raised `IndexError` (argmax on empty tensor) when every sequence fits in one chunk. Now returns the self-chunk mask early.
- When nothing was selected, the code ran dense attention over the whole sequence. It now attends within the self chunk (`cu_chunk`).
- Threshold mode always added one extra chunk even when the self chunk already met the threshold. Cutoff is now -1 in that case (all four modes).
- Zero-length sequences corrupted the chunk layout. The caller drops them, `calc_chunks` raises on them.
- Removed `lru_cache` on `calc_chunks` (tensor-identity key, stale on in-place updates). Fixed the topk/threshold error messages.

Not included: the `kernel.attn.vmoba_attn` import path (needs a packaging decision) and host-sync cleanup.

## Tests
New `tests/test_vmoba_selection.py`, CPU only, fakes only the flash-attn kernel. 13 of 16 fail on main, 16 pass with this change. `black` clean. Independent review found no blocking issues.

## Limitations
No GPU end-to-end run, so flash-attn kernel integration is untested.
