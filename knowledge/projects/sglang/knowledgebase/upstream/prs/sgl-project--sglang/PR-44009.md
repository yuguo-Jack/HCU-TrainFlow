# [AMD] Small MoE sort: support the EP expert mask (stacked on #42498)

## Motivation

#41900 and #42498 replace AITER's MoE sort and the stage-1 MXFP8 quant with one small Triton launch, but `_small_sort_supported` turns the path off whenever `expert_mask` is set. Under expert parallelism the mask is always set, so EP deployments never get the fused path. MiMo-V2.6-Pro-RL at TP8/EP8 on MI355X is one such case: the 384 experts are split 48 per rank, and every decode step pays AITER's masked sort plus a separate quant in each of its 69 MoE layers.

## Modifications

- `_localize_experts`: maps global expert ids to local ids, the number of local experts below each one, which is the numbering AITER's masked `moe_sorting` emits. Pairs routed to another rank become the kernel's sentinel and drop out of the sort.
- `_moe_sorting_small_kernel` (P <= 64) and `_moe_sorting_small_kernel_sorted` (32 < P <= 256) take a `HAS_MASK` constexpr and localize the ids in-kernel. The fused MXFP8 quant still writes every token's fp8 row and writes scale bytes only for local pairs, as AITER does.
- `_small_sort_supported` admits a masked batch only when it fits one of those two kernels and the mask is a contiguous int32 tensor of length `num_experts`. The distributed variant does not localize, so masked batches never reach it. Calls with `num_local_tokens` still go to AITER.
- `moe_buf` is always allocated zeroed under a mask, because EP stage 2 accumulates only the local experts.
- A one-time `logger.info` when the path first serves a masked batch, so a deployment can confirm it is active.
- Tests: `TestMoeSortingSmallExpertMask` checks sort outputs, the shared-expert layout and the fused quant against AITER's masked `moe_sorting`, for MiMo's 384 experts with top-8 and DeepSeek-V4.1's 385 with top-7. It also checks that the gate keeps unsupported masked shapes on AITER.

82 lines in `moe_sorting_small.py` (+78/−4) and 151 lines of tests.

## Accuracy Tests

- Unit tests on MI355X: the whole of `test/registered/amd/test_moe_sorting_small.py` passes, 9 tests and 192 subtests, including the 4 new masked tests. Masked outputs are compared exactly against stock AITER.
- MiMo-V2.6-Pro-RL MXFP4, TP8/EP8, same node, same seeds: GPQA-diamond 0.722 with this PR against 0.732 without. That is within run-to-run noise for 198 questions; B200 reference runs score 0.717–0.732.
- NIAH has not completed yet. The first attempt ended in a cluster node failure, not in this code; a rerun is queued.
