# [Perf] [AMD] moe: Support the EP expert mask in the small MoE sort

[Upstream PR](https://github.com/sgl-project/sglang/pull/44009) · state: open · merged: False

## Original PR description

## Motivation

Under expert parallelism, every decode step hands the MoE sort and the stage-1 MXFP8 quant back to aiter, because the small MoE sort turns itself off whenever aiter passes an expert mask, and EP always passes one. This PR lets the small sort take the mask, which lowers MiMo-V2.6-Pro-RL's median decode time per token by 2.0 to 3.3 % at 4 to 32 users with 8k input (TP8/EP8, MI355X).

In detail: #44004 and #42498 replace aiter's MoE sort and the separate stage-1 MXFP8 quant with one small Triton launch, but `_small_sort_supported` returns False when `expert_mask` is set. MiMo-V2.6-Pro-RL at EP8 splits its 384 experts 48 per rank, so each of its 69 MoE layers pays aiter's masked sort plus a separate quant in every decode step. With this PR the sort maps global expert ids to this rank's local ids in-kernel, drops pairs routed to other ranks, and matches aiter's masked `moe_sorting` bitwise.

Related PRs: this PR requires #42498 (open) and nothing else; #42498 itself applies on main. The sort kernels are from #44004 (originally #41900 by @AMD-yanfeiwang) and the fused quant from #42498 by @amd-pedghazi.

## Modifications

- `moe_sorting_small.py`:
  - `_localize_experts` maps a global expert id to its local id, the number of this rank's experts below it, which is the numbering aiter's masked `moe_sorting` emits. Pairs routed to another rank become the kernel's sentinel and drop out of the sort.
  - The compact kernel (up to 64 pairs) and the bitonic kernel (33 to 256 pairs) take a `HAS_MASK` constexpr. With the fused quant they still write every token's fp8 row, and write scale bytes only for local pairs, as aiter does.
  - `_small_sort_supported` names each kernel's condition once and admits a masked batch only when the mask is a contiguous int32 tensor with one flag per expert. The distributed kernel (used only at block sizes below 16) does not localize, so masked batches never reach it. Calls with `num_local_tokens` still go to aiter. Without a mask the gate decides as before (checked equal over 341,550 argument combinations).
  - `moe_buf` is always allocated under a mask, because EP stage 2 accumulates only the local experts.
  - `print_info_once` logs when the path first serves a masked batch, so a deployment can confirm it is active.
- `test_moe_sorting_small.py`: `TestMoeSortingSmallExpertMask` checks the sort outputs, the shared-expert layout and the fused quant bitwise against aiter's masked `moe_sorting`, for MiMo's 384 experts with top 8 and DeepSeek-V4.1's 385 with top 7, and checks that the gate keeps unsupported masked batches on aiter.

Scope: the path covers up to 256 pairs, as without a mask: 32 users at top 8, or 4 requests in a speculative-decoding verify step with 8 tokens per request. *Larger batches go to aiter*. The 256 pairs limit comes from [#36559](https://github.com/sgl-project/sglang/pull/36559); raising it deserves a new PR. (1024 pairs would allow conc=16 with DFLASH speculative decoding; 4096 pairs conc=64).

## Accuracy Tests

Unit tests on one MI355X (image `rocm/sgl-dev:v0.5.22-rocm10-mi35x-20261025`, Triton 3.8.0, torch 2.11.0+rocm10.0.0), with this PR's `python/` ahead of the image's sglang: the whole of `test/registered/amd/test_moe_sorting_small.py` passes at this head (`600348c7`), 10 tests with none skipped, including the 4 masked tests. In the same image, #42498's head alone passes its 6 tests.

Serving, MiMo-V2.6-Pro-RL MXFP4, TP8/EP8, one MI355X node, one run per arm (versions as in the speed tests). GPQA Diamond uses `python -m sglang.test.run_eval`.

| Benchmark | Stock | This PR |
|---|---|---|
| GPQA Diamond (198 questions) | 143 (0.722) | 139 (0.702) |
| NIAH, 64k | 0.854 | 0.878 |
| NIAH, 128k | 0.796 | 0.826 |

The sort and quant outputs are bitwise equal to aiter's, so these runs only check the integration; the GPQA gap is 4 of 198 questions, and B200 reference runs of this model score 0.717 to 0.732.

## Speed Tests and Profiling

Kernels on one MI355X: MiMo's shape (384 experts, top 8) with EP8 rank 0's mask, block 32, CUDA-graph replay. Times are the sort plus the stage-1 MXFP8 quant per MoE layer; aiter is the masked sort followed by the separate quant, which is what these calls run on #42498 alone.

| 2 | 11.61 | 2.95 |

| 8 | 11.85 | 4.37 |
| 16 | 12.81 | 4.76 |

Serving setup: MiMo-V2.6-Pro-RL MXFP4, TP8/EP8, `lmsysorg/sglang-rocm:v0.5.21-rocm10-mi35x-20261011` with MiMo-specific tuning patches, against the same image with this PR's change. Random dataset, both arms on the same node with identical prompts and seeds, one sweep per arm. The path is active up to 32 users; 64 users and above is the control. In an earlier run of the same image, all 8 ranks logged that the path served masked batches with the quant fused.
