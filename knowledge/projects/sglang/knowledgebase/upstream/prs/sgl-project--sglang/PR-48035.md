# [Perf] mem_cache: Fuse INT8 Mamba checkpoint quantization and restore

[Upstream PR](https://github.com/sgl-project/sglang/pull/48035) · state: open · merged: False

## Original PR description

## Motivation

#28185 reduces persistent recurrent-state memory through INT8 checkpoint storage, but the eager conversion path still allocates substantial temporary tensors. Indexed gathers, dtype conversions, reductions, and elementwise operations materialize full-state intermediates, including FP32 tensors, eroding the practical memory benefit of INT8.

For the tested GDN configuration (48 layers × 24 heads × 128×128 BF16 per TP rank), saving one checkpoint requires **252.84 MiB** of temporary allocations and restoring it requires **162.84 MiB**, in addition to the existing pools.

This PR fuses quantization and restore into direct pool-to-pool kernels, eliminating these full-state global intermediates and reducing kernel launches while retaining FP32 arithmetic and the existing INT8 format.

## Modifications

- Add fused Triton kernels in `sglang.kernels.ops.kvcache.int8_mamba_checkpoint` and dispatch from `Int8CheckpointStore.store_from_pool()` / `copy_to_pool()`.
- Preserve scale rounding, round-to-nearest-even, clamping, and NaN semantics. Support FP16/BF16/FP32, strided pools, int32/int64 indices, 64-bit offsets, and value dimensions 1–256; retain eager fallback for unsupported inputs.
- Add lazy CUDA-only registration and codec, integration, graph-replay, and fallback tests.
- Add `SGLANG_EXPERIMENTAL_FUSED_INT8_CHECKPOINT` and `SGLANG_DEBUG_VERIFY_FUSED_INT8_CHECKPOINT`, both **disabled by default**.

The change is confined to the shared checkpoint codec. HiCache integration, cache policy, prefill-graph extensions, AWQ compatibility changes, and the independent sampling/JIT test fix are outside this PR.

## Accuracy Tests

Validation on main `62f9f3f785f8`:

- **75 new tests passed**, covering exact eager-reference agreement (`rtol=0, atol=0, equal_nan=True`), layouts, indices, rounding/exceptional values, large offsets, CUDA Graph replay, commit integration, and fallback.
- Related regressions passed: **98 codec/integration tests** (including the 75 new tests), **163 cache tests**, **21 environment tests**, and **48 native Mamba TreeCore tests**. Targeted CPU/GPU CI runners and applicable pre-commit hooks passed.
- Main TP2 GDN service check: **24/24** matching output-token and cached-token pairs. Separate model-state verification also matched the eager INT8 reference exactly for all checked fused calls, including seven-slot restores.

On the performance snapshot, long-window KDA outputs matched in **39917/39917 common input-index pairs**. Concurrent GDN outputs were not fully identical: C=8 hot-hit/16-token comparisons matched **262/320** with prefill graphs off and **290/320** with graphs on. The unfused baseline also exhibits output variability; not every difference has been isolated. KDA logprobs were not bitwise identical (maximum observed absolute difference ≈0.00507).

Exact codec agreement does not establish lossless INT8 versus BF16 or task-level accuracy. The expanded unit/kernel suite reports **247 passed, 1 skipped**, but an isolated sampling test class still reports the same three failures on patched and clean main; its aggregate result is order-dependent. The separate sampling/JIT test fix is excluded. Full remote CI remains pending. GPU validation covers RTX 5090.

## Speed Tests and Profiling

Measured on **2× RTX 5090, TP2**, using Qwen3.8-27B-NVFP4 (GDN) and Kimi-Linear-48B-A3B-Instruct-AWQ-4bit (KDA). Performance uses frozen v0.5.22 `baa9befa3815` plus this codec change; repeated performance tests have **not been rerun on main**. Both KDA arms share compatibility adjustments outside this PR.

### Temporary memory and codec time

Single checkpoint, per TP rank; GPU times sum attributed kernel durations after warmup:

| Operation | Temporary allocation peak, eager → fused | GPU time, eager → fused | Speedup |
|---|---:|---:|---:|
| GDN save | 252.84 → 0 MiB | 498.18 → 26.78 μs | **18.60×** |
| GDN restore | 162.84 → 0 MiB | 255.82 → 12.80 μs | **19.99×** |
| KDA save | 70.23 → 0 MiB | 93.94 → 10.02 μs | **9.38×** |
| KDA restore | 45.23 → 0 MiB | 57.02 → 4.19 μs | **13.60×** |

**0 MiB refers to additional PyTorch global intermediate tensors.** Existing pools and FP32 arithmetic remain. Save launches decrease **14→1** and restore launches **7→1**.

With active/checkpoint capacities fixed at 32/16, runtime NVML peak reductions were **1392–1440 MiB/GPU for GDN** and **206 MiB/GPU for KDA**. These configuration-dependent service peaks include C=2/C=8 workloads; they are distinct from per-conversion allocations. Saved memory was not used to expand cache capacity.

### End-to-end throughput

Median paired changes over **five independent restart pairs**, with 95% bootstrap intervals; C=8, hot prefix hits:

| Configuration | Throughput change |
|---|---:|
| GDN, existing prefill graph, 1 output token | **+5.60% [+3.85%, +7.02%]** |
| GDN, existing prefill graph, 16 output tokens | **+2.36% [+2.21%, +3.29%]** |
| KDA, prefill graph off, 16 output tokens, 65-second windows | **+0.73% [−1.58%, +1.69%]** |

GDN without prefill graphs did not show a clear hot-hit throughput improvement. KDA's earlier short-window −2.55% did not reproduce as a consistent long-window regression, but **no stable end-to-end KDA speedup is established**.

Whole-service Nsight traces confirm faster codec execution and fewer launches. The estimated reduction in GPU work is only about **1.42–1.44 ms/rank per eight-request group**, versus a roughly 200 ms group cycle; substantial prefill host work and other model operations remain. Profiling perturbs timing, so tracing tails are not treated as the cause of unprofiled throughput variation.

Full methodology, complete result tables, output comparisons, regression details, and profiling analysis are provided in the [benchmark supplement](https://github.com/sll-coder/sglang/blob/6bbcc99f4d7c4ff75b2d4be89143c70b8b9f9610/benchmark/fused_int8_checkpoint/RESULTS.md) and [local validation record](https://github.com/sll-coder/sglang/blob/6bbcc99f4d7c4ff75b2d4be89143c70b8b9f9610/benchmark/fused_int8_checkpoint/validation.json).
