# [Fix] config: Keep --decrypted-draft-config-file across the config registry reload

[Upstream PR](https://github.com/sgl-project/sglang/pull/47887) · state: open · merged: False

## Original PR description

## Motivation

`--decrypted-draft-config-file` reaches `get_config` as `_configuration_file`, and `AutoConfig.from_pretrained` applies it. For model types in `_CONFIG_REGISTRY` (DeepSeek-V4 among them), the config is then reloaded from the checkpoint without that kwarg, so the override is silently dropped. A DSpark draft whose quantization differs from the target's, for example a block-FP8 draft next to a per-channel FP8 target, then loads with the target's config.

## Modifications

`HfModelConfigParser.parse` passes `_configuration_file` through the registry reload (5 lines in `utils/hf_transformers/config.py`).

## Accuracy Tests

On main `def8f93212` with this change and #47886 (which this target needs to load on gfx942), DeepSeek-V4-Flash FP8 per-channel target with its block-FP8 draft config, DSpark block size 5, TP4 on MI308X: the draft config is honored, accept length is 4.6-5.5 at 1024-token outputs, and gsm8k 8-shot on all 1319 questions scores 0.9431. Not A/B'd on main without the fix; on an older SGLang tree without it, the draft fell back to the target's config and accept length dropped to about 1.0.

## Speed Tests and Profiling

Not applicable: config loading only.
