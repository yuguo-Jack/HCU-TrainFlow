# [Perf] Hunyuan3D: Reduce redundant QEM quadric accumulation

[Upstream PR](https://github.com/sgl-project/sglang/pull/48075) · state: open · merged: False

## Original PR description

## Summary

Hunyuan3D's Paint remeshing computes a symmetric 4×4 quadric-error metric (QEM) matrix for each vertex. The existing implementation independently accumulates all 16 matrix entries using `np.bincount`, although only 10 entries are unique.

This PR:

- Computes the **10 unique upper triangular entries** and mirrors them into the lower triangle, eliminating six redundant `np.bincount` calls.
- Preserves the original vertex/face indexing, weight accumulation order, `float64` dtype, and downstream mesh simplification behavior.
- Adds one focused regression test comparing the optimized implementation against an independent 16 entry reference on closed and open boundary meshes.

The change is limited to QEM quadric accumulation. It does not modify edge collapse logic, UV unwrapping, texture generation, or model inference.

Note: shape only requests do not execute this Paint remeshing path.

## Correctness

Validation was performed at three levels:

1. **Frozen OBJ and synthetic CPU inputs:** bitwise parity passed against the original implementation.
2. **Captured live Paint mesh (P4D):** raw NumPy vertices and faces were captured immediately before `mesh_simplify()` on a 568,580 face mesh. Replaying the identical input through the original and optimized implementations produced bitwise identical initial quadrics and matched the recorded live QEM output fingerprint.
3. **Paint+GLB inference:** generated GLBs were successfully loaded and checked for geometry and UVs.

The regression test uses an independent 16 entry reference and compares quadric arrays through `view(np.uint64)` to enforce exact bit pattern equality.

Cross request GLB SHA256 values were not used as parity evidence, since independently generated outputs can differ even with the same seed.

## Performance

We evaluated the optimization on one H200 using an eight-visit
A-B-B-A-A-B-B-A comparison (four measured visits per arm).

- Control: pristine Core `bde43d6c132ecd726ffdd68702bdb66900cae303`
- Candidate: only the symmetric-QEM accumulation change
- Same input image, seed, inference settings, and request warmup
- Paint enabled with `paint_use_remesh=true`
- Native SGLang performance measurements

| Metric | Control | Candidate | Reduction |
| --- | ---: | ---: | ---: |
| Paint Preprocess | 9,197.01 ms | 8,694.76 ms | **5.46%** |
| Native E2E | 22,642.59 ms | 22,079.16 ms | **2.49%** |

All four adjacent A/B pairs showed positive Paint Preprocess and native E2E improvements.

An earlier exploratory cohort showed substantial timing instability and was excluded from the primary performance summary. Both cohorts are documented in the investigation log.

Paint Preprocess includes QEM, UV unwrapping, and rendering, so its improvement is not attributable exclusively to QEM.

### Same-live-input CPU QEM replay (P4D)

To isolate QEM more directly, captured live Paint mesh arrays were replayed through both implementations using identical input bytes.

| Captured input | Original QEM | Optimized QEM | Reduction |
| --- | ---: | ---: | ---: |
| v00-control | 7,033.75 ms | 6,692.41 ms | **4.85%** |
| v01-candidate | 7,300.26 ms | 6,732.47 ms | **7.78%** |

Both inputs passed exact QEM output parity.

These measurements characterize CPU QEM replay performance and should not be interpreted as native Paint E2E improvements. The instrumented live capture timings are diagnostic only.

## Scope and limitations

- Only two files are changed: the QEM implementation and its existing unit test file.
- Performance was measured on one H200 with a fixed request configuration.
- Correctness was verified on synthetic, frozen, and captured live Paint inputs; this does not establish parity for every possible mesh.
- Native SGLang E2E stage timing does not represent user-perceived network latency.
- The optimization does not affect Shape only inference.

Detailed experiment reports and investigation history are recorded in charliechenye/sglang#2.
