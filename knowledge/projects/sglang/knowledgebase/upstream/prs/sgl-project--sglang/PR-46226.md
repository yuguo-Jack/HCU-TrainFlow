# [Fix] sgl-router: Run the chat render parity generator through deepseek-recipe

[Upstream PR](https://github.com/sgl-project/sglang/pull/46226) · state: closed · merged: False

## Original PR description

`sgl-router/tests/scripts/generate_chat_render_parity.py` no longer imports:

```python
from sglang.srt.entrypoints.openai import encoding_dsv4
from sglang.srt.entrypoints.openai.chat_encoding import (
    resolve_dsv4_reasoning_effort_profile,
)
```

e22a530859 ("openai: Render DeepSeek-V4/V4.1 chat prompts with deepseek-recipe") deleted `encoding_dsv4.py` and `encoding_dsv41.py` and dropped `resolve_dsv4_reasoning_effort_profile` from `chat_encoding.py`. The same commit updated `rust/sglang-processor/tests/scripts/generate_parity.py`, which is the other copy of this generator, but the sgl-router copy kept the removed imports, so it now raises `ImportError` before rendering anything:

```
$ python tests/scripts/generate_chat_render_parity.py
ImportError: cannot import name 'encoding_dsv4' from 'sglang.srt.entrypoints.openai'
```

That is the documented way to refresh `sgl-router/tests/fixtures/chat_render_parity/`, which `tests/component/tokenizer/render_parity.rs` checks against.

The `dsv4` branch now asks the serving adapter that the engine itself uses for the prompt, mirroring `_apply_jinja_template`, instead of re-deriving the renderer call inline. This also drops the local message normalisation the old branch duplicated (`pre_normalize` handles developer roles and object tool arguments, as the serving path does), and pins the adapter once per model rather than per case.

The Jinja models are untouched. I did not regenerate `deepseek-v4-flash.json` here because it needs the pinned checkpoint tokenizer; if the recipe render differs from the deleted encoder, that fixture will need a refresh too.

Checked on a checkout of `main` (`25ba24e9a`): `ruff check` and `ruff format --check` pass on the file, and both imports resolve (`DeepSeekRecipeChatEncodingAdapter.__init__` and `encode_messages` take exactly the arguments passed here).
