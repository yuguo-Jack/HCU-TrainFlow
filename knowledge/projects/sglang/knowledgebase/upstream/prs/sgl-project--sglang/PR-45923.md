# [Fix] scheduler: Make a Req's "__req__" self-reference weak

[Upstream PR](https://github.com/sgl-project/sglang/pull/45923) · state: closed · merged: True

## Original PR description

## Motivation

https://github.com/sgl-project/sglang/pull/43181 stopped injecting `"__req__"` into `custom_params` for requests that have no custom logit processor. A request that does have one, such as a thinking-budget, DeepSeek-OCR no-repeat-ngram, LocateAnything box-grammar or user-supplied processor, still stores a strong reference to itself in its own `custom_params`:

```
req -> sampling_params -> custom_params["__req__"] -> req
```

Refcounting never frees such a request after it finishes. It stays alive, with its input and output token lists, until the cyclic garbage collector reaches it, and it adds work to every collection until then. On servers that tune or freeze the collector, these requests can build up.

## Modifications

- `Req.__init__` stores `weakref.proxy(self)` under `"__req__"`. The in-tree processors read `"__req__"` only while the request is running, and never hash, pickle or keep it, so they see the same attributes as before.
- Tests in `test_req_custom_params_ref.py` (CPU, `base-a-test-cpu`):
  - With `gc` disabled, a `Req` that has a custom logit processor is freed when its last reference is dropped. This test fails on main.
  - `Qwen3ThinkingBudgetLogitProcessor` reads the request through the proxy and forces the newline once the budget is spent.

## Accuracy Tests

Not applicable: processors receive the same values, and model outputs do not change.

## Speed Tests and Profiling

Not applicable: the only hot-path change is one `weakref.proxy` call per request that has a custom logit processor.
