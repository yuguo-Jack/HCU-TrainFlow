# [Perf] disaggregation: Vectorize staging gather/scatter for aligned KV buffers

[Upstream PR](https://github.com/sgl-project/sglang/pull/39236) · state: open · merged: False

## Original PR description

## Motivation

The staging gather/scatter kernels read KV buffer addresses from a pointer table on the device. Triton cannot infer alignment from a loaded pointer, so the KV side is lowered to scalar loads and stores. In the PTX for the current kernels, the payload moves one element at a time, and scatter also uses 8 KB of shared memory that the vectorized version does not need.

The KV buffers are 16-byte aligned in practice. The kernel just has no way to know.

## Modifications

- Add an `ALIGNED_16` specialization to the gather and scatter kernels. When it is on, the row bases get a `tl.multiple_of(..., 16)` hint and Triton emits vector loads and stores.
- Check the KV buffers once when Mooncake or NIXL registers them (`kv_buffers_preserve_16_byte_alignment`, called from `build_staging_kv_buffer_info`). The result is stored with the buffer info, so transfers do not rescan the buffer list.
- On each transfer, only the staging buffer address is checked (`_can_use_aligned_staging_copy`), because it can start at any ring offset. The strides and head offsets come from the buffer shape, so the registration check covers them. If any check fails, the transfer uses the generic kernel, same as today.

Nothing changes when staging is disabled, and nothing changes for buffers that fail the checks.

## Test

New test file: `test/registered/kernels/ops/kvcache/test_disaggregation_staging_buffer.py`

- Gather and scatter give bit-exact results on both the aligned path and the generic path, for 1, 2, and 4-byte element sizes.
- Misaligned KV buffers, a misaligned staging offset, and an odd head size stay on the generic path and are still bit-exact.

Ran the test file on an H100 with torch 2.14.1 and Triton 3.8.0: all 6 tests pass.

I also compiled both kernels offline with Triton 3.8.0 for SM90 and SM103 and all three element sizes, 36 combinations in total. The generic version generates the same PTX as upstream. The aligned version uses vector accesses, and scatter shared memory goes from 8192 to 0 bytes.

After the rebase onto current main, I reran the new test file on H100: all 6 tests pass. The related disaggregation suites also pass: `test_disaggregation_wire.py` (73 tests), `test_staging_draft_kv_slots.py` (2 tests), `test_nixl_backend_basic.py` (27 tests), and `test_mooncake_transfer_batching.py` (20 tests).

## Benchmark

Measured on GB300 (one host, four ranks): BF16, 80 layers, 1024 tokens from a 4096-token pool, page size 1, 8 KV heads with head dim 128, prefill TP4 to decode TP1. Baseline and aligned use the same inputs, grids, and warmups. Only `ALIGNED_16` differs.

"Kernel" is CUDA graph replay. "Host-inclusive" adds the per-transfer alignment check to the candidate side. Neither includes RDMA or request handling, so these are not end-to-end numbers.

| Operation | Baseline | Aligned | Change |
| --- | ---: | ---: | ---: |
| Gather, kernel | 37.29 us | 34.86 us | -6.5% |
| Gather, host-inclusive | 37.29 us | 35.65 us | -4.4% |
| Scatter, kernel | 151.90 us | 105.00 us | -30.9% |
| Scatter, host-inclusive | 151.90 us | 105.93 us | -30.3% |

The output was bit-exact in these runs too.

One limitation: RDMA time and end-to-end request latency were not measured here.

The benchmark ran on an earlier version of this branch. The kernel code has not changed since then. After the rebase onto current main, I reran the H100 tests above instead of rerunning the full benchmark.
