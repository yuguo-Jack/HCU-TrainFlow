# [Perf] Hunyuan3D: Skip redundant OBJ exports when generating GLB

[Upstream PR](https://github.com/sgl-project/sglang/pull/46956) · state: closed · merged: True

## Original PR description

## Summary

Avoid two intermediate OBJ exports in the Hunyuan3D-2 **Shape + Paint → GLB** path:

- **Shape Save:** skip exporting the untextured Shape OBJ when Paint and GLB output are both enabled. Paint consumes the in-memory `shape_meshes`, not the saved OBJ.
- **Paint Postprocess:** export the final textured GLB directly, without first writing a textured OBJ and its auxiliary files.

Shape-only OBJ and Paint+OBJ output behavior remain unchanged. This is a two-file change with no new flags, dependencies, or helpers.

## H200 performance

One NVIDIA H200, eager (`torch.compile` off), lossless quality, 50 Shape / 50 Delight / 30 Paint steps, 32k geometry chunks, fixed input image and seed. Each comparison used an eight-visit ABBA sequence with fresh processes and native SGLang stage timings.

| Experiment | Comparison | E2E median | Stage-local improvement |
| --- | --- | --- | --- |
| P2: skip textured OBJ | Native → P2 | **25,038.80 → 23,733.69 ms (+5.21%)** | Paint Postprocess: **4,184.28 → 2,892.93 ms (−30.86%)** |
| P3: skip Shape OBJ | P2 → P2+P3 | **23,780.26 → 22,794.05 ms (+4.15%)** | Shape Save: **~958.81 → ~0.07 ms** |

These are **separate, sequential A/B comparisons**. The percentages should not be added, and no single combined Native → P2+P3 speedup is claimed.

## Correctness

- **P2, same live textured mesh:** direct GLB, OBJ-first-then-GLB, and repeated direct GLB exports from deep copies had matching GLB bytes and matching geometry, normals, UVs, texture pixels, bounds, and material properties for the tested mesh.
- **P3, live Shape mesh:** the original Shape OBJ export did not change the vertices or faces consumed by the pinned Paint remesh/UV path (bitwise equality for the tested mesh).
- **Output contracts:** H200 smoke tests passed for Shape-only OBJ, Paint+OBJ/MTL/PNG, and Paint+GLB. The candidate's GLB remained loadable with geometry and UVs.

GLB hashes across **independent model runs** varied even in the native baseline, so cross-run byte equality is not used as a correctness gate. Same-mesh parity and output-contract checks are the relevant evidence here.

## Scope and compatibility

- `hunyuan3d/shape.py`: make the Shape OBJ export conditional on whether Paint+GLB needs it.
- `hunyuan3d/paint.py`: export either the final GLB **or** textured OBJ, rather than both.
- Preserve existing output path metadata and artifact cleanup.

**Tradeoff:** Paint+GLB no longer leaves an intermediate Shape OBJ when Paint subsequently fails. The pinned pipeline has no supported resume-from-that-OBJ flow; this is an intentional change to intermediate artifacts, not the requested final output.

Experiments: [P2 direct-GLB ABBA](https://github.com/charliechenye/sglang-scripts/tree/exp/hunyuan3d-paint-obj-export-p2/experiments/hunyuan3d_paint_obj_export_p2) · [P3 ABBA, smoke, and live-mesh parity](https://github.com/charliechenye/sglang-scripts/tree/exp/hunyuan3d-shape-obj-skip-p3/experiments/hunyuan3d_shape_obj_skip_p3)
