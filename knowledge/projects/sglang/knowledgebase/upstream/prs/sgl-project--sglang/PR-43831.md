# [Unified Cache] Skip write-through of pages the external linker just loaded

[Upstream PR](https://github.com/sgl-project/sglang/pull/43831) · state: open · merged: False

## Original PR description

Stacked on #40896; only the last commit (`e06f0efe64`) belongs to this PR. It will be rebased onto main once #40896 merges.

## Motivation

#40896 keeps a linker-loaded tail private to the request and inserts it like computed KV once the load lands. That removed the old `mark_external_cache_stored_path` call, so the inserted node is offered to write-through again. The loaded pages usually share a node with the newly computed tokens, so every such offload re-sends the whole loaded prefix to the store's existence check. Measured on an agentic workload (DeepSeek-V4-Flash-FP8, TP4, Mooncake, 48 SWE-bench Pro tasks at 24 concurrent, 25 min each):

| | main | #40896 | this PR |
|---|---|---|---|
| Offload calls | 6200 | 6600 | 6000 |
| Keys sent to the store | 59,523 | 733,305 | 57,378 |
| ...of which already stored | 0 | 675,747 (92%) | 786 (1.4%) |
| Calls with every page already stored | 0 | 746 | 131 |

No data is rewritten (Mooncake skips keys that exist), but the existence queries grow ~12x and nodes stay locked until their larger offloads are acknowledged.

## Modifications

- The linker records the page hashes of each tail whose load landed in a `PoolExistenceBeliefs` (the buffer-mode existence LRU).
- Before an offload, the leading KV pages it holds are dropped from the KV transfer; the pools indexed by the KV transfer follow. A node with nothing left is published as stored without a write. Non-KV transfers (an SWA window) are never trimmed.
- A lookup forgets the pages past its rank-agreed hit, so a page the store lost is written again on recompute.
- The beliefs change only at rank-agreed points (the reduced load verdict, the intersected lookup hit, reset) and are read only on the lockstep offload path, so all TP ranks keep identical copies.

## Tests

- `test_unified_cache_linker.py`, Python and Rust tree cores: a fully loaded node is published without a write; a node mixing loaded and computed pages offloads only the computed pages; a lookup shortfall makes the dropped pages offload again. Without the fix all three fail on both cores; removing only the lookup invalidation fails the last one.
- `test/registered/unit/mem_cache`, file by file: identical to #40896 except the three new tests.
- The measurement above, with no load failures or HTTP errors.
