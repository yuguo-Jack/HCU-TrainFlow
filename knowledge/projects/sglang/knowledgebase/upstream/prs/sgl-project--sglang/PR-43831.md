# [Perf] unified_cache: Skip write-through of pages the external linker just loaded

[Upstream PR](https://github.com/sgl-project/sglang/pull/43831) · state: open · merged: False

## Original PR description

## Motivation

#40896 keeps a linker-loaded tail private to the request and inserts it like computed KV once the load lands. That removed the old `mark_external_cache_stored_path` call, so the inserted node is offered to write-through again. The loaded pages usually share a node with the newly computed tokens, so every such offload re-sends the whole loaded prefix to the store's existence check. Measured on an agentic workload (DeepSeek-V4-Flash-FP8, TP4, Mooncake, 48 SWE-bench Pro tasks at 24 concurrent, 25 min each):

| | before #40896 | #40896 |
|---|---|---|
| Offload calls | 6200 | 6600 |
| Keys sent to the store | 59,523 | 733,305 |
| ...of which already stored | 0 | 675,747 (92%) |
| Calls with every page already stored | 0 | 746 |

No data is rewritten (Mooncake skips keys that exist), but the existence queries grow ~12x and nodes stay locked until their larger offloads are acknowledged.

## Modifications

- Once the reduced load verdict says a tail landed, the linker keeps its page hashes until the request's insert covers the tail, or the request is released or aborted.
- Before an offload, the leading KV pages such a tail loaded are dropped from the KV transfer; the pools indexed by the KV transfer follow. A node with nothing left is published as stored without a write. Non-KV transfers (an SWA window) are never trimmed.
- The record does not outlive the insert, so nothing tracks what the store loses later: a node recomputed after eviction is offloaded in full, as before #40896.
- The record changes only at rank-agreed points (the reduced load verdict, `checkpoint`, `on_release`, `release_aborted_request`, reset) and is read only by the offloads an insert triggers, so all TP ranks keep identical copies.

## Tests

- `test_unified_cache_linker.py`, Python and Rust tree cores: a fully loaded node is published without a write and its record is dropped; a node mixing loaded and computed pages offloads only the computed pages; a peer rank's failed load leaves no record.
- `test/registered/unit/mem_cache` and `test/registered/unit/managers`, file by file: identical to main except the new tests. `test_unified_radix_lock_ref.py`'s hand-built cache now sets `linker = None`, which `on_release` reads.
- E2E with a 4-layer GLM-5 checkpoint (DSA), TP4, Mooncake direct linker, rank consensus checker on: 64 concurrent requests loaded and then extended past the loaded prefix, the linker KL suite with forced eviction, and the L3 prefix-hit test all pass. Keys sent to the store drop from 4,811 to 3,454 and from 2,334 to 1,646 versus main; the keys still found stored are recomputed pages, not loaded ones. Every rank issued identical offloads (same count, keys and key-sequence digest), and the checker reported no divergence.
- Not rerun on this change: the DeepSeek-V4-Flash agentic workload above, and the DSV4 SWA path.
