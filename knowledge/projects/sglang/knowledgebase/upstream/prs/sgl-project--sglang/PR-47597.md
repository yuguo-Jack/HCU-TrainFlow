# [DeepSeek V4.1] Support DP attention with prefill CP and bounded replay

[Upstream PR](https://github.com/sgl-project/sglang/pull/47597) · state: closed · merged: False

## Original PR description

DeepSeek-V4.1 rejected attention DP whenever prefill CP was on. The two
features are compatible once the MoE operand layout, the late-layer
hand-off and the decode/draft collectives agree on what one DP slot holds.

A DP slot carries this rank's complete CP rank-major buffer, padding
included, because the hash-routing IDs and the MoE output rows travel
through the same slots:

- MoeRowTransport fits the CP gather to the slot width taken from the
  batch (cp_fit_slot_rows) before the DP gather, and takes this rank's CP
  block back out of the scattered result (cp_take_slot_rows). Fitting per
  CP block is required: a head-truncating memcpy would drop whole CP
  blocks.
- prepare_mlp_sync_batch sizes global_num_tokens to that slot on every
  rank, including idle DP peers, before any model collective. The
  predicates are config-level: a batch-level is_cp_active would make the
  padding rank-dependent and desync every later DP collective.
- late_layer_dp_counts publishes the padded slot size, not the logical
  tail rows, and gathers over the whole TP group, since CP and
  attention-TP partners replicate a DP slot. It also carries a refresh
  bit so idle peers enter SUM_LEN with their busy partners. The
  prefill-time exchange in prepare_mlp_sync_batch is skipped under CP,
  where the slot width is not known yet.
- The late-layer tail rebuilds the MoE's token IDs through the
  hidden-state gather's own interleave map (LateLayerTail now keeps the
  tail's global indices for that), while Engram's image gate keeps this
  rank's own rows.
- RowParallelLinear sums decode attention-TP output over the CP group,
  Humming prepares an independent rank-local decode shard from canonical
  (pre-packing) tensors, and DSpark synchronizes sampled tokens over the
  effective decode TP group.
- Engram: a sharded table's lookup exchanges rows over the TP group, and
  under CP the layer picks between the CP all-gather and the DP exchange
  from the batch, so an idle attention-DP peer would enter the DP
  exchange alone. --engram-config now requires a collective-free lookup
  ('peer_read', or placement 'cpu' with replication 'per_node') when DP
  attention and CP are combined.

Validation: DeepSeek-V4.1-Flash-1017 on 8x H20-3e, gsm8k 1319 questions,
no-think, no speculative decoding. The target serving configuration is
humming W4A8:

    SGLANG_HUMMING_INPUT_QUANT_CONFIG='{"dtype": "float8e4m3"}' \
    sglang serve --model-path /models/DeepSeek-V4.1-Flash-1017 \
        --trust-remote-code --tp 8 --ep-size 4 \
        --attention-backend dsv4 \
        --quantization humming --moe-runner-backend humming \
        --mem-fraction-static 0.6 --disable-radix-cache \
        --enable-decoder-swa-bounded-replay --cuda-graph-max-bs-decode 64 \
        --enable-prefill-cp --cp-strategy interleave --attn-cp-size 2 \
        --enable-cp-decode-attn-tp \
        --dp 4 --enable-dp-attention --enable-dp-lm-head \
        --chunked-prefill-size 262144 --max-prefill-tokens 262144 \
        --engram-config '{"placement":"cpu","replication":"per_node"}' \
        --host 0.0.0.0 --port 30000

and the same command without --dp / --enable-dp-attention /
--enable-dp-lm-head, with --attn-cp-size 8 and the prefill budget back to
65536, for the DP-off control. The budget is 262144 under DP because it is
split across the 4 attention-DP groups. The shared per-node Engram table
is what the new --engram-config check requires.

    humming W4A8   DP attention 4 / CP 2   97.2%
    humming W4A8   DP off / CP 8           97.0%

plus ifeval 93.1% prompt-strict / 95.4% inst-strict under DP4/CP2. Those
runs predate the port, on the tree this change was developed on.

Re-measured on this branch, with the marlin MoE runner substituted for
humming (the pinned humming build predates humming.config.InputQuantizationMode,
which 0.5.23 imports) and --language-model-only added (vision prefill CP
is not in tree yet; a text evaluation does not use the vision tower):

    marlin         DP attention 4 / CP 2   97.1%   no watchdog timeout
    marlin         DP off / CP 8           97.4%   no watchdog timeout
