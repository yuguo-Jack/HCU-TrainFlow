# [Fix] Publish Mamba prefill cache updates before preparing the next batch

[Upstream PR](https://github.com/sgl-project/sglang/pull/39765) · state: open · merged: False

## Original PR description

## Motivation

With Mamba `extra_buffer` caching and overlap scheduling, the next decode/verify batch can capture `req_to_token` before the previous prefill result publishes its cache insertion. That insertion can replace freshly computed KV slots with the tree's canonical slots and free the duplicates. The first dependent step then uses a different prefix mapping from later steps.

Processing the result after `get_next_batch_to_run()` is too late: batch preparation has already captured the mapping.

Related to #38140, which addresses the same ordering issue for plain radix caches and explicitly leaves Mamba cache timing unchanged. This patch covers tracked Mamba prefills.

## Modifications

- Process a pending tracked Mamba prefill result before selecting/preparing the next batch.
- Consume each result once and retain the opportunistic unified-memory flush at the synchronization boundary.
- Keep overlap for untracked prefills, disabled caches, and decode requests in mixed batches.
- Leave DP/MLP-sync scheduling unchanged; that path needs a collective decision and is outside this patch's scope.

**27 passed, 16 subtests passed.** All applicable pre-commit hooks and `git diff --check` pass.
