# [Fix] nemotron: Correct weight-export failures and GEMV dispatch

[Upstream PR](https://github.com/sgl-project/sglang/pull/45082) · state: closed · merged: True

## Original PR description

## Motivation

Follow-up fixes to #44518, now rebased onto `main`. Handle unsupported NVFP4 weight exports safely and correct the BF16/FP8 GEMV dispatch paths without losing the measured fast cases.

## Modifications

- Return failed control responses for blocked weight exports and reject phase layout before remote weight storage is published.
- Keep unsupported strides/alignment on the existing cuBLAS path. On SM90, use cuBLAS for the measured `K=5120, N<=512` regime. Restore two rows per warp for SM120 FP8 GEMV at `N=8192`.
- Complete lazy kernel registrations using the current `KernelSpec` schema, move layout-cycle ownership into SRT, and remove unused state/arguments.
- Rename the four PR-only toggles to `SGLANG_OPT_SM120_NVFP4_PHASE_LAYOUT`, `SGLANG_OPT_SM120_MTP_ROUTER_TOP22`, `SGLANG_OPT_FLASHINFER_DRAFT_HOST_INDPTR`, and `SGLANG_OPT_FLASHINFER_VERIFY_HOST_PLAN`, without old-name aliases.
- Shorten four comments and retain pinned public CUTLASS references.

No test files or cases are added, deleted or moved. The only test edits are eight required flag-name substitutions in two existing files; assertions, subcases and CI registration remain unchanged.

## Accuracy Tests

- Rebase validation: **372 passed, 2 expected skips on RTX PRO 6000 (SM120)**; **7 tests and 7 subtests passed on H200 (SM90)**. This covers MoE routing, FlashInfer host planning/masks, FP8 linear, BF16 GEMV/addend, kernel namespace, environment and MoE placement checks.
- All applicable pre-commit hooks passed. Both existing test files are byte-identical to `main` after normalizing the renamed flags; the shortened comments leave executable ASTs unchanged.
- The rebase initially exposed an obsolete `KernelSpec.description` argument that prevented imports. Removing that single unsupported argument cleared the failure with the same existing suites.
- Tests ran at `6a978546`; the final refresh onto `04c8c970` adds only two upstream Docker lines. Every runtime, kernel and test file is byte-identical to the tested candidate.

Earlier full GSM8K runs at pre-rebase `180be914` used the official checkpoints: **NVFP4 TP1/MTP4: 1,250/1,319 (94.77%)**; **BF16 TP4: 1,264/1,319 (95.83%)**. Thinking was disabled; neither run had request errors or truncations. These full-model evaluations were not repeated after the rebase.

Validation used Torch 2.14.1/CUDA 13, FlashInfer 0.7.2 and released `sglang-kernel 0.4.10`.

## Speed Tests and Profiling

Earlier matched cold-L2 measurements: H200 BF16 `(N,K)=(96,5120)` ordinary-linear median **11.200 → 10.272 us**; RTX PRO 6000 FP8 `(8192,5120)` operator median **54.272 → 50.176 us**. The rebase preserves those kernel implementations; performance was not remeasured.
