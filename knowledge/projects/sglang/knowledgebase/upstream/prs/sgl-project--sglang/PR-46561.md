## Motivation

<!-- Describe the purpose and goals of this pull request. -->

While auditing the NPU nightly registrations we found several tests request far more cards than they actually occupy. A test inherits the card count of the suite it registers to (the suite name maps to a runner label), so over-requesting both wastes runner capacity and adds queueing time to the nightly pipeline.

Actual usage was derived from each test's launch arguments (`--tp-size` and `--base-gpu-id`; `--attn-dp-size` does not add devices because attention DP runs inside the TP group):

| Test | Cards actually used | Registered suite before | Registered suite after |
| --- | --- | --- | --- |
| `test_npu_pd_disaggregation.py` | 4 (prefill tp2 on cards 0-1, decode tp2 on cards 2-3) | `nightly-16-npu-a3` | `nightly-4-npu-a3` |
| `test_npu_load_balance_method_pd_disaggregation.py` | 4 (prefill tp2 on cards 0-1, decode tp2 on cards 2-3, after this fix) | `nightly-16-npu-a3` | `nightly-4-npu-a3` |
| `test_npu_qwen3_6_27b_2p_in64k_out1k_prefix90_50ms.py` | 2 (`--tp-size 2`) | `nightly-perf-4-npu-a3` | `nightly-perf-2-npu-a3` |
| `test_npu_qwen3_6_27b_w8a8_1p_in64k_out1k_50ms.py` | 2 (`--tp-size 2`) | `nightly-perf-4-npu-a3` | `nightly-perf-2-npu-a3` |

The load balance test could not simply be moved: its prefill server ran with `--base-gpu-id 4` and `--tp-size 2`, i.e. cards 4-5, so the two servers together needed at least 6 visible cards even though only 4 were in use.

## Modifications

<!-- Detail the changes made in this pull request. -->

- `test_npu_load_balance_method_pd_disaggregation.py`: change the prefill server's `--base-gpu-id` from 4 to 0, so prefill uses cards 0-1 and decode (already `--base-gpu-id 2`) uses cards 2-3. The test now fits a 4-card runner, matching `test_npu_pd_disaggregation`.
- Registration changes (nightly suites only):
  - `test_npu_pd_disaggregation.py` and `test_npu_load_balance_method_pd_disaggregation.py`: `nightly-16-npu-a3` -> `nightly-4-npu-a3`.
  - Both `qwen3_6_27b` performance tests: `nightly-perf-4-npu-a3` -> `nightly-perf-2-npu-a3`.
- `test_npu_pd_disaggregation.py` per-commit registration: `base-b-test-16-npu-a3` -> `base-b-test-4-npu-a3`. The test occupies 4 cards and the 4-card job already runs on the `linux-aarch64-a3-4-` runner, so the PR pipeline no longer needs a 16-card machine for it.

Not applicable: no model, kernel or runtime code is changed. The one behavioral change (device placement) was validated on real hardware with the temporary pipelines in #46531:

- [Run 40283190258](https://github.com/sgl-project/sglang/actions/runs/40283190258): the four tests pass on runners sized 4, 8 and 2 cards.
