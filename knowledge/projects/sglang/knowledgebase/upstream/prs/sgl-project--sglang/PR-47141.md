# [Fix] tokenizer: Use the model revision pin in post-load fixes

[Upstream PR](https://github.com/sgl-project/sglang/pull/47141) · state: open · merged: False

## Original PR description

## Summary

`get_tokenizer(..., revision=<sha>)` loaded the tokenizer at that pin, then ran the post-load fixes with `tokenizer_revision=None`. The fixes looked up `tokenizer.json` / `tokenizer_config.json` at the default revision and bailed out when the cache had only the pinned snapshot.

The pin is now `tokenizer_revision` when that argument is set, otherwise the `revision` keyword. An explicit `tokenizer_revision` still wins.

Fixes #47125

## Test

`python3 -m pytest test/registered/unit/tokenizer/test_post_load_revision.py -q`

The post-load revision was `None` for `revision="abc123"` before this change and `abc123` after it. No Hub download.
