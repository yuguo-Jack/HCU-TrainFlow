# [diffusion] fix: share the IPC all-to-all transport between AllToAll4D and USP

[Upstream PR](https://github.com/sgl-project/sglang/pull/43269) · state: closed · merged: True

## Original PR description

## Motivation

`test_ipc_a2a_2_gpu.py` fails on main (reported on 2×H200, reproduced on 2×B200 NVLink at f6569bce4d9):

```
rank0 MISMATCH: ['AllToAll4D never took the IPC path (exchange count stayed at 6)']
IPC_A2A_PARITY FAIL (staged keys=3)
```

AllToAll4D does still reach the IPC transport. None of the steps on that path changed after #31854 (checked with `git log -L` on `sequence_model_parallel_all_to_all_4D`, then `GroupCoordinator.all_to_all_4D`, `DeviceCommunicatorBase.all_to_all_4D`, `AllToAll4D.forward` and `_ipc_all_to_all_4d`). The other recent commits under `runtime/distributed/` (#37547, #39293, #41284, #40069) don't change it either.

The regression is #33317 (f829fb3ff7c). It made `ipc_a2a_ready` reset the transport whenever the caller passes a different ProcessGroup *object*, and the two entry points pass different objects for the same two ranks:

- USP (`_ipc_ready_group`) passes `get_sp_group().ulysses_group`, which `set_seq_parallel_pg_by_sp_groups` creates.
- AllToAll4D passes the SP coordinator's own `device_group`.

So every switch between the two entry points tears the transport down and rebuilds it. Lifecycle trace of the test on main, identical on both ranks:

```
INIT(ulysses_pg) | 6 exchanges | RESET(calls=6) | INIT(sp.device_group) | 6 exchanges | RESET(calls=6) | INIT(ulysses_pg) | 3 exchanges
```

The reset sets `calls` back to 0. The 6 AllToAll4D exchanges then bring it back to exactly 6, which the test reports as "never took the IPC path". The second reset also puts `max_buffers` back to its default, so the eviction check in the test has not been testing eviction. If you remove only #33317's two-line reset from main, the test passes.

**Impact.** Since #33923, wan-VSA (`UlyssesAttention_VSA`) is the only production model that calls AllToAll4D, and it never uses USP in the same process. So the models we ship today did not hit these resets (see the e2e below). A model that uses both entry points would rebuild the transport twice per layer, about 6.3 ms per switch on B200 (benchmark below). Each rebuild also drops staging buffers that kernels captured earlier in a CUDA graph may still point to.

**Why CI missed it.** This file is listed in `STANDALONE_FILES["2-gpu"]`, but the NVIDIA 2-GPU partition plans contain no standalone files (scheduled run 37768448360 has `standalone_files=[]` in all three partitions), and AMD skips the test because it needs CUDA. I'll follow up on that separately.

## Modifications

- `ipc_a2a.py`: the peer mappings depend on which two ranks are paired, not on which group object is passed. Store the pair's global ranks in `init`. In `ipc_a2a_ready`, reset only when a group over a *different* pair arrives; passing the same object still skips the check. `destroy_model_parallel()` still resets explicitly, so the topology-switch case #33317 fixed is unaffected.
- `test_ipc_a2a_lifecycle.py`: parametrize the replaced-group test. `different_pair` must still reinitialize. `same_pair` must reuse the transport; it fails on main.
- `test_ipc_a2a_2_gpu.py`: before reading the exchange count, check that the transport was not re-initialized (`IPC_A2A.flag` identity), so this failure now names its cause. Also update the comment: zimage and hunyuanvideo moved to USPAttention in #33923, and wan-VSA is the only AllToAll4D user left.
