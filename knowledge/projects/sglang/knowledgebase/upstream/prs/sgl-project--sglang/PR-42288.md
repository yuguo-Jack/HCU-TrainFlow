# [Refactor] TCPCG: Consolidate attention eager regions and isolate Inkling policy (4/9)

[Upstream PR](https://github.com/sgl-project/sglang/pull/42288) · state: closed · merged: True

## Original PR description

This is **step 4/9**, split from [the original TCPCG removal PR #41634](https://github.com/sgl-project/sglang/pull/41634).

**Steps 1–3 are merged.** Rebased onto upstream `main` (`58cb1a2be6`); the PR contains only step 4. Review the [step-4 files](https://github.com/sgl-project/sglang/pull/42288/files).

Replace attention's TCPCG split-op adapters and layer-registry lookups with class-owned eager methods. On BCG replay, these methods read the live prepared batch through `get_forward_batch()` from step 2's runner-owned scope. The eager decorator and replay callbacks do not capture or rebind a batch argument.

## Series

1. Relocate shared graph tensor and DSA head-gate helpers — #42285 (merged).
2. Simplify BCG eager replay and publish the live batch in runner utilities — #42286 (merged).
3. Retire TCPCG backend selection, configuration, documentation, and tests — #42287 (merged).
4. **Consolidate attention eager regions and isolate Inkling policy — this PR.**
5. Migrate DSA and DeepSeek eager regions — #42289.
6. Migrate MoE and Mamba eager regions — #42290.
7. Migrate diffusion eager wrappers and standardize names — #42291; depends only on step 2.
8. Remove obsolete runtime contexts, layer registries, split-op plumbing, and temporary compatibility after caller migration — #42292.
9. Simplify quantization paths separately because of their torch.compile implications — #42293.

## Changes

- Consolidate dense attention, optional LSE, sparse handling, and extra keyword arguments in `RadixAttention._eager_attention`. Preserve main’s sparse-BCG fix: sparse attention also runs in an eager region and reads the live batch during replay.
- Share output allocation, token slicing, temporary batch-state restoration, and padded-tail zeroing through `attention/graph_utils.py`. Preserve the newer eager padded-extend handling, including independent query/KV extents and tuple outputs.
- Migrate linear attention, HPC RoPE/store-KV, and MLA BMM attention to class-owned eager methods. Preserve the newer linear-attention path that stays inside BCG when the backend supports it.
- Keep Inkling's attention bypass and token handling in the model, without making the eager decorator nesting-aware.
- Keep Cheng's `ForwardContext` unchanged. Publish the full-prefill flag and raw token count in a separate runner-owned `prefill_graph_scope`, with restoration on exit.

The legacy TCPCG context and layer registries remain temporarily for unmigrated callers until step 8. This changes attention dispatch and eager replay, while preserving backend computation and graph-owned output buffers.

## Review fix: prefill scope

Require the runner-owned prefill scope before entering the migrated eager methods. Decode BCG also handles TARGET_VERIFY and DLLM_EXTEND, which count as extend but do not publish a prefill batch. These modes retain their original backend path. Apply the scope boundary to Radix, linear, HPC, MLA fusion eligibility, and Inkling eager/fusion gates. Add CPU regressions for decode BCG without a batch scope.

## Review fixes: compiler compatibility and BCG test coverage

- Skip the runner-only prefill ContextVar lookups while compiling. BCG/full prefill is uncompiled; compiled decode/target verification retains the ordinary backend path.
- The shared BCG attention test runner now publishes both the live batch and prefill scope, and spies on migrated Radix/linear eager methods to prevent silent fallback coverage.
- Compile the actual RadixAttention.forward entry for decode and target verification, both with the real absent scope and a sentinel that rejects context reads.
- Isolated macOS PyTorch 2.10 CPU validation: the four compile regressions fail with the previous helpers and pass with the fix; all 34 Radix tests pass. Accelerator imports are shimmed; no NPU inference was run.
- Current local CPU suite: 83 tests plus 27 subtests pass. A CPU harness executing the shared runner function with fixture dependencies isolated confirms padded eager dispatch and that removing the scope trips the new assertion. GPU backend suites remain unrun.
