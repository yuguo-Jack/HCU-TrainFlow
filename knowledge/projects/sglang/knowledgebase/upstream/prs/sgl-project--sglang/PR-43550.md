# [HiCache] Keep storage workers alive on backend exceptions

[Upstream PR](https://github.com/sgl-project/sglang/pull/43550) · state: closed · merged: True

## Original PR description

## Motivation

Outside unified memory, the HiCache storage workers re-raise any backend exception (`IOError` on a short `HiCacheFile` read, a `ValueError` from Mooncake, ...). The raise escapes the worker loop and the thread dies:

- prefetch IO thread: every later prefetch on that rank waits forever, and peers block in the per-batch completion all-reduce;
- backup thread: acks stop, so host pages stay locked (and buffer-mode staging freezes on every rank, since the drain is MIN-reduced).

#39479 already treats these failures as misses under unified memory. This PR applies that to all configs.

Smaller alternative to #41106 / #38427: no circuit breaker, no new env vars or operation fields.

## Modifications

- Drop the `if not enable_unified_memory: raise` in the prefetch query, KV transfer and sidecar transfer paths.
- Backup loops (base and hybrid) log a failed `_page_backup` and still ack it.

## Verification

Single-rank file backend on H200:

| Case | main | this PR |
| --- | --- | --- |
| truncated L3 object, then a healthy prefetch | IO thread dead, healthy prefetch never completes | miss, healthy prefetch completes |
| backend `set` raises | backup thread dead, 4 backups never acked | acked, thread alive |

HiCache / storage unit tests under `test/registered/unit/mem_cache` show no change versus `main`.
