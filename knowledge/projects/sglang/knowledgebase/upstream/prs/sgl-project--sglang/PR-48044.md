# [Perf] [AMD] qwen3-next: Fuse the full-attention Q/K GemmaRMSNorm and partial RoPE into one Triton kernel on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/48044) · state: open · merged: False

## Original PR description

## Motivation

In Qwen3-Next's full-attention layers (every fourth layer), the prologue between `qkv_proj` and attention runs on HIP as split/chunk copies, a GemmaRMSNorm launch for q and one for k, and `rotary_embedding`. On gfx950 the aiter fused prologue (`fused_attention_qk_norm_rope`) is called when the installed aiter provides it; current aiter does not (ROCm/aiter#6835 is open), so the unfused path runs.

## Modifications

- New Triton kernel `kernels/ops/attention/qk_gemma_norm_rope.py`: splits `[q||gate]`, k and v from the gated-attention qkv projection, applies GemmaRMSNorm to q and k per head and neox partial RoPE with the fp32 cos/sin cache, in one launch. It keeps the unfused path's bf16 rounding points (normalized value, cos/sin and each product of the rotation).
- `models/qwen3_next.py`: `Qwen3HybridAttentionDecoderLayer` takes the kernel on gfx95 when the rope is the neox `RotaryEmbedding` on its fallback kernel with an fp32 cache and the head sizes are powers of two. It is not taken under `--rl-on-policy-target`, where RoPE forces its native path to match the trainer bitwise. The aiter fused prologue keeps priority.
- `qkv_proj` is computed once in `self_attention` and passed to the prologue in use, so an aiter prologue that reports a shape as unsupported falls back without running the projection a second time (on main the fallback recomputes it).
- New test `test/registered/kernels/ops/attention/test_qwen3_next_fused_qk_prologue.py` (`jit-kernel-unit`, AMD) compares the kernel with the native prologue for the per-rank head counts of Qwen3-Next-80B-A3B at TP1/2/4 and 1 to 8192 tokens, plus an empty batch, and checks that `--rl-on-policy-target` keeps the native prologue.

## Accuracy Tests

MI355X (gfx950), image `lmsysorg/sglang-rocm:v0.5.22-rocm10-mi35x-20261025` (torch 2.11.0+rocm10, aiter `285579b6`), `SGLANG_USE_AITER=1`, Qwen3-Next-80B-A3B-Instruct-FP8, TP2.

**Kernel output.** v and gate are identical to the native prologue. q and k are identical except where the RMSNorm reduction, summed in a different order than the native GemmaRMSNorm, moves a normalized value to the neighboring bf16 and RoPE carries that difference: over the test shapes and four seeds, at most 7e-5 of the q/k elements differ, by at most 2 bf16 ulp of the rotated pair's magnitude. The test bounds both (1e-3 of the elements, 3 ulp) and requires v and gate to match exactly.

**GSM8K** (`python -m sglang.test.run_eval --eval-name gsm8k --num-examples 1319 --max-tokens 4096`, chat, greedy, 3 runs each, main `1ced9a9eb0`):

| | main | This PR |
|---|---|---|
| Accuracy | 0.9619 / 0.9612 / 0.9589 (mean 0.9607) | 0.9635 / 0.9665 / 0.9627 (mean 0.9642) |
