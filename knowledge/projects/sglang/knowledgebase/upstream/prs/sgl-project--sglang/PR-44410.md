# [CI] pr-test: Let stage wait jobs reach their max-wait budget

[Upstream PR](https://github.com/sgl-project/sglang/pull/44410) · state: closed · merged: True

## Original PR description

## Problem

`wait-for-base-a` / `wait-for-base-b` in `pr-test.yml` pass `max-wait-minutes: 240/480` to the `wait-for-jobs` action, but both jobs run on `ubuntu-latest`, where GitHub hard-caps every job at 6h, so the cap fires before base-b's 480-min budget.

Observed on a real PR run ([run 38556047170](https://github.com/sgl-project/sglang/actions/runs/38556047170)): on a slow queue day, base-b took ~7.5h to drain. The wait step's log ends at `attempt 351/480` (73% of budget) with `The operation was canceled.` exactly 360 min after step start — killed by the 6h cap (`The job has exceeded the maximum execution time of 6h0m0s`), not by the action.

The fallout is worse than the cancellation itself:

- `base-c-test` has `if: ${{ !failure() && !cancelled() }}`. A cancelled need is neither `failure()` (cancelled ≠ failure) nor `cancelled()` (which only fires when the whole run is cancelled), so base-c dispatched anyway and every test job passed.
- `pr-test-finish` treats any `cancelled` need as a failure, so the run went red and the PR was blocked despite all 48 test jobs being green.

## Fix

`timeout-minutes` cannot raise the 6h cap, so instead:

- `wait-for-jobs` waits against a wall-clock deadline, not a poll count (API time per poll made 480 polls take ~492 min).
- base-b's budget drops to 350 min, under the cap.
- base-b and base-c skip when a stage wait is `cancelled`.
- base-b's wait passes `fail-on-timeout: 'false'`, so a timeout lets base-c start and `pr-test-finish` judges the run by the test results.

`pr-test-amd.yml`'s `wait-for-stage-b-amd` (480 min, `ubuntu-latest`) has the same 6h problem; out of scope here.

## Testing

- `pre-commit run --files .github/workflows/pr-test.yml` passes
- YAML parses (python yaml.safe_load)
- actionlint passes on `pr-test.yml`; the action script was run under Node with a simulated clock (timeout, success, fail-fast, `fail-on-timeout` values)
