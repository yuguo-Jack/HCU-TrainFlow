# [Fix] dp-attention: Trim MLP-sync pad rows from extend outputs before the draft extend

[Upstream PR](https://github.com/sgl-project/sglang/pull/47493) · state: open · merged: False

## Original PR description

## Motivation

Fixes #47490.

With DP attention + EAGLE, `--moe-a2a-backend flashinfer` on the target and a DeepEP draft (`--speculative-moe-a2a-backend deepep`), the prefill CUDA graph pads each prefill to the DP-wide bucket of the largest rank, while the draft pads only to its own bucket. The extend arm of `post_forward_mlp_sync_batch` trims the target outputs to `seq_lens_sum`, which also counts the cached prefix, so after the first prefill chunk the hidden states keep the pad rows. The draft extend then pads them to its smaller width and `_pad_inputs_to_size` fails with `RuntimeError: Trying to create tensor with negative dimension`.

## Modifications

- `ForwardBatch.post_forward_mlp_sync_batch`, extend arm: trim `next_token_logits`, `hidden_states` and `mm_input_embeds` to `_original_num_tokens` (the token count before MLP-sync padding), falling back to `seq_lens_sum` when the batch was not padded. The draft re-pads the real rows to its own bucket. This covers all spec-v2 workers, which pass the target hidden states to the draft extend unchanged.
- `test_mlp_sync_pad_unpad.py`: a regression case (29-token chunk after a 640-token prefix, padded to a 48-token bucket, must return 29 hidden rows). It fails on main and passes with the fix.

## Accuracy Tests

GLM-5.2 NVFP4 on GB300 with the 2026-10-28 SGLang nightly image plus this patch, EAGLE 3/1/4, prefill CUDA graph on, GSM8K (`few_shot_gsm8k`, 200 questions):

| Topology | MoE A2A (target / draft) | GSM8K | accept len |
|---|---|---|---|
| DEP4 | flashinfer / deepep | 0.960 | 3.29 |
| DEP4 | deepep / deepep (reference) | 0.920 | 3.35 |
| DEP8 | flashinfer / deepep | 0.950 | 3.25 |
| DEP8 | deepep / deepep (reference) | 0.905 | 3.33 |

Without the patch the flashinfer arm crashes at the first mixed-count prefill step. Re-checked on current main (`51d5502aff`, Python overlay on the same image), DEP4, GSM8K 20 questions: main crashes (`negative dimension -48` and `-32`), main + this PR passes (0.90, no errors).
