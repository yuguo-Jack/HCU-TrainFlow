# [Perf] mhc: Parallelize small-batch post across hidden tiles

[Upstream PR](https://github.com/sgl-project/sglang/pull/44906) · state: closed · merged: True

## Original PR description

## Motivation

`mhc_post_tilelang` currently launches one CTA per token and iterates over hidden-dimension tiles inside that CTA. For the GLM-5.3-Flash verification shape `M=24, H=4096, hc=4`, this launches only 24 CTAs.

This change distributes hidden tiles across CTAs for small batches. The same shape now launches 96 CTAs, improving parallelism while preserving the per-element accumulation order and BF16 writeback.

## Modifications

- Add `num_h_blocks=1` to `mhc_post_tilelang`.
- Launch a two-dimensional grid over tokens and hidden blocks.
- Map each iteration to `i_h_iter * num_h_blocks + i_h_block`.
- For `M <= 256`, split the hidden dimension using the existing 1024-element tile size and GCD adjustment.
- For larger batches, retain one hidden block per token.
- Keep scheduling, sampling, and the existing mHC fusion threshold unchanged.

## Accuracy Tests

- Eager and CUDA Graph kernel checks cover multiple batch sizes, hidden sizes, and hc configurations, with bitwise-equal outputs.
- Integrated core checks cover real M24 input, synthetic M6/M24/M48/M256/M512/M8192, and H3072.
- Graph checks update inputs before replay.
- Ruff lint, Ruff formatting, and repository-configured isort passed.
- The final formatting-only revision is AST-equivalent to the GPU-tested source.
- Three service A/B responses still differ in their initial text prefix; the cause has not been established.

## Speed Tests and Profiling

Measured on **4 x B300 / SM103, TP4**, using:

- GLM-5.3-Flash, checkpoint revision prefix `46a050bec130`
- SGLang base `f7ad4345b86d147a1c3095a3cebabca9a33ebaa1`
- Torch 2.14.1, FlashInfer 0.7.1, Transformers 5.19
- FP8 KV cache, MTP with five speculative steps and six draft-token slots
- Simulated average acceptance length 3.5
- Pinned sgl-bench commit `a9da34ad1f997ca05878d858d3d01970e4a49af9`

One baseline/candidate pair was measured without profiling. Each arm ran C1/C4/C8 with 30/40/80 measured requests, respectively, after 64 warmup requests per concurrency. Warmup output length was 32 tokens; measured output length was 1024 tokens. Inputs used the same seeded random ShareGPT workload with nominal 8K input length and chat templating.
