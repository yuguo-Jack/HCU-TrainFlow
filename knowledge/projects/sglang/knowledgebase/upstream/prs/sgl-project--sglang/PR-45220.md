# [Perf] [NVIDIA] muse-spark: Fuse the o_proj all-reduce into the attention boundary

[Upstream PR](https://github.com/sgl-project/sglang/pull/45220) · state: open · merged: False

## Original PR description

Rebased on main after #45112.

cc @Fridge003 @BBuf

## Motivation

- At decode and DFlash verify, each Muse Spark layer runs the o_proj all-reduce and the attention-boundary kernel (post-norm, gated residual, pre-norm) as two kernels.
- For at most 16 rows on B300 TP4, this PR does the all-reduce inside the boundary kernel. It saves about 1 us per layer, over 62 layers per step.

## Modifications

1. `o_proj` skips its all-reduce when the fusion applies.
2. The boundary kernel stores each rank's bf16 partial into every rank's push workspace with unicast stores. It then sums the four partials in fp32 in rank order, the same order as the 1shot push all-reduce, so the result is bit-exact.
3. The reduce reuses the cluster path of `muse_spark_all_gather_norm_residual` and adds an optional fp32 router output. New op `communication.muse_spark_all_reduce_norm_residual`, with a KernelSpec. The model calls it with the boundary's `jit_kernel_kwargs()`, like the FFN all-gather.
4. The fusion runs for bf16, TP4 with attention TP equal to TP, SM103, at most 16 rows, the JIT boundary backend, and room in the push workspace. 16 rows is where the fused kernel stops winning on B300 (table below).

## Accuracy Tests

- New 4-GPU kernel test, 10 passed on B300:
  - The reduce is bit-exact against `custom_all_reduce` + `fused_norm_residual` for 1, 3, 8 and 16 rows, on both halves of the push workspace.
  - The existing FFN all-gather is bit-exact against `fused_norm_residual` on the full branch for 3 and 128 rows. This covers both the cluster kernel and the row kernel, since the push code is now shared.
  ```bash
  python test/registered/kernels/ops/communication/test_muse_spark_all_reduce_norm_residual.py
  ```
- Greedy outputs are identical to main for 8 of 8 prompts: 4 at bs=1 and 2 pairs at bs=2, 384 tokens each.
- AIME26 with sgl-eval 0.1.3, B300 TP4/EP4 with DFlash. Concurrency 2 keeps every verify step at 16 rows, so the fused kernel runs throughout.

<summary>Client</summary>

```python
import json, statistics, threading, time, urllib.request

TOPICS = ["numerical linear algebra", "the history of compilers", "GPU memory hierarchies",
          "speculative decoding", "the Roman road network", "protein folding",
          "sorting algorithms", "TCP congestion control", "the French revolution",
          "photosynthesis", "black holes", "the history of chess", "jazz harmony",
          "volcanoes", "cryptographic hash functions", "the printing press"]


def gen(i, results):
    body = {"text": f"Write a long, detailed essay about {TOPICS[i]}. Essay {i}:",
            "sampling_params": {"max_new_tokens": 512, "min_new_tokens": 512, "temperature": 0}}
    req = urllib.request.Request("http://127.0.0.1:30000/generate", data=json.dumps(body).encode(),
                                 headers={"Content-Type": "application/json"})
    results[i] = json.loads(urllib.request.urlopen(req).read())["meta_info"]["completion_tokens"]


for bs, reps in ((1, 5), (2, 5)):
    vals = []
    for _ in range(reps):
        results = [0] * bs
        threads = [threading.Thread(target=gen, args=(i, results)) for i in range(bs)]
        start = time.time()
        [t.start() for t in threads]
        [t.join() for t in threads]
        vals.append(sum(results) / (time.time() - start))
    print(f"bs={bs} out_tok/s median={statistics.median(vals):.1f}")
```
