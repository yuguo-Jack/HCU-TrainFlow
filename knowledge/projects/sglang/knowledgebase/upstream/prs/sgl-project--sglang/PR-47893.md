# [Perf] [NVIDIA] glm5_next: Run the fused KDA decode kernel at 8 and 16 heads per rank

[Upstream PR](https://github.com/sgl-project/sglang/pull/47893) · state: open · merged: False

## Original PR description

## Motivation

GLM-5.3-Flash has 34 KDA layers. On CUDA each of them runs three kernels per decode step: `causal_conv1d_update`, the recurrence, and the gated RMSNorm. Kimi-K3 runs the same step as one kernel (`kda_fused_decode`): its layers have the same head dim 128, conv width 4 and gate lower bound, but the kernel is only built for 3/6/12 heads per rank. GLM-5.3-Flash has 8 heads per rank at TP8 and 16 at TP4, which is what the cookbook's NVIDIA High Throughput recipes run (H100/H200/B200/B300 TP8, GB300 TP4, spec decode off).

Also, safe-gate layers never take packed decode on CUDA, because `TritonKDAKernel` doesn't declare `supports_packed_decode_safe_gate`, so the recurrence is the unpacked kernel.

Roadmap: #42473 (Kernels), GLM-5.3-Flash Hopper tracker #45373.

## Modifications

- `kda_fused_decode.cuh`: instantiate the fused decode kernel for 8 and 16 local heads, one CTA per (token, head). The arithmetic is unchanged; the only other kernel change is the SM90 state cache hints below.
- `kda_fused_decode.py`: `SUPPORTED_HEADS = {3, 6, 8, 12, 16}`. Kimi-K3 reads this set since #47526, so K3 at 8/16 heads per rank (TP12, TP6) also takes the fused kernel; it matches the unfused chain there with no lower bound on 1x H200.
- `glm5_next.py`: `Glm5NextLinearAttention._prepare_fused_decode()` runs from both `load_weights` and `post_load_weights` (dummy and other loaders call only the latter). It stashes the kernel's static inputs (per-segment fp32 conv taps, zero conv bias, fp32 o_norm weight) and rebuilds them in place on later loads, since captured graphs hold them. In decode, `forward()` hands the o_norm gate to the KDA backend the same way Kimi-K3 does; if the backend doesn't take it, the layer applies o_norm as before.
- The fused path is offered on SM9x and SM10x only (the kernel stages the state with TMA). On Hopper it is used below `2048 // local_heads` tokens per step. From 2048 (token, head) blocks the unfused packed chain streams the fp32 state faster on H200. B200 has no cap.
- `TritonKDAKernel.supports_packed_decode_safe_gate = is_cuda()`, and safe-gate layers stay on the Triton packed kernel instead of the CUDA row kernel, which is slower at 8-32 heads per rank. This is the fallback for Hopper large batches and for TP1/TP2 (64/32 heads).
- On SM90 at 8/16 heads and up to 1024 (token, head) blocks, the kernel loads the state with an L2 evict-first hint and stores it with streaming stores (bit-identical outputs).
- `weight_updater.py`: a module can set `_direct_weight_update_error`, which rejects `update_weights_from_tensor(load_format="direct")` before any write. The direct format skips `load_weights` and `post_load_weights`, so GLM sets it once the fused decode inputs are published. The default format and the disk and distributed updates go through `load_weights` and refresh the buffers in place.
- Tests: GLM-5.3-Flash kernel cases (TP8 H=8, TP4 H=16, lower bound -5, both staging paths) in `test_kda_fused_decode.py`, plus one weight-loading test on a small real `Glm5NextForConditionalGeneration` (both hooks at SM80/90/100/120: SM9x and SM10x publish the inputs and a reload rewrites the graph-held buffers in place, the others prepare nothing), a safe-gate dispatch test in `test_kda_kernels.py`, and a CPU test that the direct format is rejected while the default one still loads. Commits after `6911d48513`, where the GSM8K and H200 kernel numbers below ran, only change tests and merge main.

**BV=8 for the Triton packed kernel on SM90.** `fused_recurrent_kda_packed_decode` launches with BV=32. BV only sets how many V rows one program updates, so BV=8 is bit-identical (output and state); it launches 4x the programs and keeps more state rows in flight. On H20 it takes 6-22% less time than BV=32 per layer (median 17%; 8, 16 and 64 heads, batch 1-256, cold L2). That is the last column above. It also moves the fused/packed crossover on H20.
