# [Fix] dsv41: Warm up the image path under encoder SWA bounded replay

[Upstream PR](https://github.com/sgl-project/sglang/pull/43241) · state: open · merged: False

## Original PR description

## Motivation

The server warmup sends a text request instead of an image request whenever encoder SWA bounded replay is enabled, because replay used to reject images. #45048 serves image requests under replay on CUDA, so a VLM served with replay starts without warming its image path.

## Modifications

- The warmup choice moves into `_warmup_with_image`.
- Under encoder SWA bounded replay, the non-disaggregated warmup now sends the image request on CUDA. Off CUDA, where replay still rejects images (`tokenizer_manager.py`), it keeps the text request. PD warmup is unchanged and sends text.

## Accuracy Tests

Not applicable: startup warmup only.

## Speed Tests and Profiling

Not applicable.

## Validation

A new `TestWarmupWithImage` in `test_http_server_warmup.py` covers replay on and off CUDA, without replay, and a model without image understanding. It fails before the change (partly because `http_server` did not import `get_platform`) and passes after.
