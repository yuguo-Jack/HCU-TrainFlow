# [VLM][MM refactor 3/6] Extract a shared media processor mixin

[Upstream PR](https://github.com/sgl-project/sglang/pull/43422) · state: open · merged: False

## Original PR description

## Motivation

Media loading and the resources behind it (IO / processor / CPU executors, image decoding
options, media URL policy) live in `BaseMultimodalProcessor`, next to serving-only state such
as the preprocess cache, the hash executor and the feature transport. A host that only loads
and preprocesses media, such as a trainer, cannot reuse them without the serving parts.

## Modifications

- Add `MultimodalProcessorMixin` in a new module `sglang/srt/multimodal/media_processor.py`.
  It owns media loading (`_load_single_item`, `_submit_mm_data_loading_tasks_simple`,
  `fast_load_mm_data`, `_load_media_lists`), the executors and their shutdown.
  `_initialize_processor(hf_config, processor, processor_config=...)` sets them up from a
  `MultimodalProcessorConfig`.
- `BaseMultimodalProcessor` inherits from the mixin and keeps its serving-only state:
  preprocess cache, hash executor, feature transport and `skip_tokenizer_init`.
- Extract `_bind_and_finalize_mm_items` and `_move_processor_output_to_cpu` from the serving
  paths so later PRs can reuse them.

No behavior change. Most of the diff is moved code.

## Review guide

- Commits titled `refactor(move): ...` are mechanical and come with reproducible proofs:
  replaying the recorded primitives on the parent commit gives the commit's tree exactly.
- `move decorated loader helpers into the processor mixin` is a hand-made cut/paste because
  the proof tool drops `@staticmethod` / `@classmethod`. Removed and added lines match except
  for the owner of `_is_preprocessed_input` and `_validate_one_modality`.

## Tests

- Existing multimodal unit tests pass on every commit except the move commit, where two tests
  in `test_base_processor_image_decode.py` still patch `load_image` at its old module (a string
  path the move cannot rewrite). The next commit points them at `media_processor`.
