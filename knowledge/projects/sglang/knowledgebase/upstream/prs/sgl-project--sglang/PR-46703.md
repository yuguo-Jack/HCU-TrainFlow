# [CI] [AMD] install: Cache the AOT kernel wheel and stop wiping venv bytecode

[Upstream PR](https://github.com/sgl-project/sglang/pull/46703) · state: closed · merged: True

## Original PR description

## What

Two cuts to the setup that every AMD CI job runs in `amd_ci_install_dependency.sh` before its first test:

| Change | Per job | Expected per week |
|---|---|---|
| Cache the AOT kernel (`sglang-kernel`) wheel on the runner's persistent `/sgl-data` volume | ~30 s build → wheel install on a cache hit | ~350 runner-h (~830 GPU-h) |
| Stop deleting every `.pyc` under `/opt/venv` | ~6 s | ~70 runner-h |

"Per week" assumes the ~41,900 AMD GPU jobs measured in the week of Oct 19–26 and a high hit rate. The real hit rate depends on how often `kernels/aot` and the CI image change. It will be measured after merge.

## Why

The install step takes ~2.3 of the ~2.5 min of per-job setup:
- 30 s of it compiles `python/sglang/kernels/aot` from source with `setup_rocm.py install`, in every job, although that tree rarely changes.
- Another ~6 s is `find /opt/venv -name "*.pyc" -delete` and the `__pycache__` cleanup. The `pip uninstall` calls just before it already remove the old sglang files, so the walk only throws away torch's bytecode, which every job then recompiles on first import.

## Notes for the reviewer

- **Cache key:** the git tree hash of `python/sglang/kernels/aot`, the container's image ID, and the image's GPU arch. Those are the only inputs to the build: `setup_rocm.py` reads nothing outside that directory, and the image fixes torch, HIP and Python.
  - A dirty tree, as in local runs, or a missing key builds without caching.
  - A host without the `/sgl-data` mount gets a container-local cache, so it just misses every time, same as today.
- **Build method:** the build switches from `setup_rocm.py install` (an egg plus `easy-install.pth`) to `setup_rocm.py bdist_wheel` and `pip install --no-deps --force-reinstall`, so a cached build and a fresh one install the same way. Nothing else in the AMD scripts reads the egg or `kernels/aot/dist`.
- **Concurrency and cleanup:** jobs on one host can build the same key at once, so each builds into a temp dir and publishes with `mv -T`; the loser drops its copy. Entries not used for 7 days are pruned, and a hit refreshes the entry's mtime.
- **Bytecode:** clearing `__pycache__` in the checkout is kept.

## Test plan

- [x] `pr-test-amd.yml` dispatch on rocm10 ([run 40430315918](https://github.com/sgl-project/sglang/actions/runs/40430315918)):
  - The install step took 128–133 s on a cache miss, against ~136 s before this change; that difference is the bytecode wipe. On a cache hit it took **97–99 s**. 4 of the 8 MI300 small shards hit; the 5 first-wave jobs started together, so each built its own copy.
  - `sgl-kernel-unit-test-amd` passes against the wheel install.
  - The gfx950 build works: `stage-b-test-1-gpu-small-amd-mi35x (0)` passes.
  - One small shard failed in `test_openai_server.py` (`cannot import name 'ResponseFunctionShellToolCall'`). That's the OpenAI SDK bump from #45291, fixed on main by #46774, not this change.
