## Motivation

<!-- Describe the purpose and goals of this pull request. -->
With DCP enabled, `HybridCacheController._transfer_num_bytes()` multiplies a logical token count by the bytes per physical KV row. Each rank transfers only its share of those tokens, so `sglang:hicache_backup_bytes_total` and `sglang:load_back_bytes_total` over-report the sharded KV payload by `dcp_size`.

## Modifications
- Convert page-aligned logical slot counts to physical row counts using each host pool's own `dcp_size`, for both the anchor and additional pools. Pools without DCP keep their existing byte count.
- Keep token counters and the slot counts used to resolve derived sidecars logical. Non-sharded recurrent-state payloads must not be divided by the anchor's DCP size.

### MLA GPU reproduction

NVIDIA A10, PyTorch `2.14.1+cu130`, CUDA 13.0. A real MLA device pool and pinned host pool use BF16, 2 layers, a 512-dimensional latent plus 64-dimensional RoPE component, and 16 physical rows per page. Each operation contains 256 logical tokens; each physical row costs 2,304 bytes across the two layers.

A single GPU executes each rank's transfer independently for DCP1/2/4, covering every rank with both `page_first/kernel` and `page_first_direct/direct`: **14 round trips**. All D2H/H2D payloads matched exactly. The upstream accounting method was extracted directly from the upstream Git revision and evaluated on the same operation and pools; the MLA transfer files match upstream.

The table applies to each rank and to either transfer direction; KiB = 1,024 bytes.

| DCP size | Physical rows per rank | Observed KV payload | Upstream reports | Fixed reports |
| --- | ---: | ---: | ---: | ---: |
| 1 | 256 | 576 KiB | 576 KiB | 576 KiB |
| 2 | 128 | 288 KiB | 576 KiB | 288 KiB |
| 4 | 64 | 144 KiB | 576 KiB | 144 KiB |

Payload size was checked against the changed nonzero elements in initially zeroed destination buffers and the expected tensor sizes. It measures transferred KV payload, not PCIe protocol overhead. An additional accounting check adds 128 bytes of non-sharded state and confirms those bytes remain unchanged at every DCP size.

This is pool-level transfer and accounting validation; it does not require model weights or a new model-accuracy evaluation.
