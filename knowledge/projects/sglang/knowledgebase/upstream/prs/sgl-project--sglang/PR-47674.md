# [Feat] multimodal: GLM-5.3 token-space strategy for images (sglang-miles)

[Upstream PR](https://github.com/sgl-project/sglang/pull/47674) · state: open · merged: False

## Original PR description

## What

GLM-5.3 support for the token-space multimodal processor (`--enable-token-space-processor`). Images only: one `<|image|>` per image between `<|begin_of_image|>` and `<|end_of_image|>`, expanded to one `<|image|>` per merged patch. Videos stay on the legacy processor. New file `token_space_mm_process/models/glm5_next.py` plus a 2-line registry hook and tests.

Used by miles' token-space session server (radixark/miles#4586) to train GLM-5.3 on screenshots.

## Verified

- CPU parity with SGLang's existing GLM processor: bitwise equal `input_ids`, `mm_token_type_ids`, `pixel_values`, `image_grid_thw` and rotary positions for 1 and 3 images, and for a 2-turn chat with `mm_token_expansion_start_len`.
- GPU, GLM-5.3 on 6 nodes of 8x B300 with miles' session server (computer-use episodes, up to 256 turns): rollouts with 32 graded episodes and 180 samples, 0 prompt-ID mismatches. The routed-expert replay rate on image tokens equals the non-token-space path (0.659% vs 0.638%). The 3-step run on this path completed: 3 train steps and checkpoints, train/rollout KL 2.45e-3 / 3.06e-3 / 1.69e-3, KL to the reference exactly 0 at step 0 with replay on.
