# [Fix] [NPU] moe: honor simple TopK scoring and routing scale

[Upstream PR](https://github.com/sgl-project/sglang/pull/47629) · state: open · merged: False

## Original PR description

## Motivation

Ungrouped routing without a correction bias always enters the NPU softmax fast path, even when `scoring_func="sigmoid"`. That path also omits `routed_scaling_factor` when `apply_routed_scaling_factor_on_output=True`.

For logits whose leading entries are `[0, 1, 2]` (remaining experts at -20), top-2 normalized sigmoid weights should be approximately `[0.546449, 0.453551]`; the current path returns `[0.731059, 0.268941]`. With normalized softmax and an enabled scale of 2.5, the current weights sum to 1 instead of 2.5.

## Modifications

- Restrict the softmax fast path to softmax scoring and apply the requested output scale after conversion to FP32.
- Route normalized sigmoid through the existing generic NPU fused operation.
- Use the shared native TopK helper for unbiased, ungrouped sigmoid with `renormalize=False`, preserving FP32 weights, int32 IDs, and NPU finalization. The generic NPU operation normalizes sigmoid scores even with `renorm=False`, so changing the fast-path condition alone is insufficient.
