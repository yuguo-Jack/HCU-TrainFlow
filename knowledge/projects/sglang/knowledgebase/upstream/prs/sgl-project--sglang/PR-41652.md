# [Bugfix] Falcon-H1: do not .float() tied LM head embeddings in place

[Upstream PR](https://github.com/sgl-project/sglang/pull/41652) · state: open · merged: False

## Original PR description

## Motivation

Fixes https://github.com/sgl-project/sglang/issues/41463.

When `tie_word_embeddings` is set, `FalconH1ForCausalLM` pointed `lm_head` at the embedding module and called `.float()` on it. That rewrites the shared parameter in place, so the token embedding becomes float32 while the rest of the model stays bfloat16. The first forward then feeds float32 hidden states into fused RMSNorm and dies during server warmup, so nothing is ever served.

## Modifications

- Tied models use `ParallelLMHead.tie_weights` instead of aliasing the embedding module and calling `.float()` on it.
- Embedding weights stay in the model dtype. Logits still run in fp32 through `enable_lm_head_fp32` (matmul upcast, not an in-place cast).
- Untied heads are still stored in fp32.
- A separate checkpoint `lm_head.weight` is skipped when the head is tied.
