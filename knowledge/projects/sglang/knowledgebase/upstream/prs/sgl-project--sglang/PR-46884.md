# [Perf] hicache: Publish prefill read-done when offload copies are fenced on the forward stream

[Upstream PR](https://github.com/sgl-project/sglang/pull/46884) · state: closed · merged: True

## Original PR description

## Motivation

The prefill shared-read-done fastpath lets the schedule stream run ahead of the forward that writes a stashed chunk's KV, instead of falling back to `wait_stream(forward_stream)`. `maybe_publish_prefill_shared_read_done` disabled it whenever hierarchical cache or a storage backend was enabled, because host and storage offload copies used to be ordered only behind the schedule stream and could have read unfinished KV.

That reason no longer holds for the cache controller: it orders its device-to-host copies behind the forward stream through `write_fence_stream`, and its load-back H2D copies through `load_fence_stream`. Keeping the coarse barrier there costs real time. Under overlap scheduling, a synchronous page-index `.cpu()` issued while preparing the next batch inherits the schedule stream's wait on the entire in-flight forward, so the CPU cannot prepare batch `n+1` until forward `n` finishes and the GPU sits idle between batches.

## Modifications

- `scheduler.py`: after the decode offload manager is set up, record on the model runner whether every KV offload copy waits on the forward stream: hierarchical cache with a cache controller and no decode offload manager (which has no such fence).
- `model_runner.py`: add the `kv_offload_fenced_on_forward_stream` flag, default `False`.
- `shared_read_event.py`: keep the coarse whole-forward barrier for LMCache and for unfenced offload; publish read-done when hierarchical cache / storage offload is fenced.

Read-done does not mean KV-ready: HiCache backups still wait on the forward stream on their own copy stream, so a backup of a chunk stashed early still copies the final KV.

## Tests

- `test/registered/unit/model_executor/runner/test_prefill_shared_read_done.py` (CPU): fenced hierarchical cache, with and without a storage backend, publishes read-done; LMCache keeps the coarse barrier even when hierarchical cache is fenced; the existing unfenced cases are unchanged.
- `test/registered/unit/mem_cache/test_hicache_write_back_ordering.py` (1 GPU): a write-through backup of a chunk checkpointed while its forward is still writing the KV (a long device sleep on the fence stream before the writes) copies the final values, not the stale ones.

Both files pass locally on this branch (the GPU test on a single GPU). No serving benchmark was run on this branch.
