# [Feat] [AMD] mori: Add Fabric PD backend for rack-level gfx1250 serving

[Upstream PR](https://github.com/sgl-project/sglang/pull/44283) · state: open · merged: False

## Original PR description

Co-developed with @maning00 
## Summary

Add a Mori Fabric backend for PD on rack-level gfx1250 (prefill and decode in the same vPod). Enable with `SGLANG_MORI_BACKEND=fabric`; RDMA stays the default and is unchanged.

`SGLANG_MORI_FABRIC_STAGING=1` keeps KV/state pools in ordinary device memory and transfers through a few small Fabric-registered staging slots, instead of allocating the whole pool from Fabric memory.

## Other changes

- Shared MLA row pack/unpack: add the scatter kernel `copy_pack_into_mla_rows` and `pack_row_segments` / `unpack_row_segments` in `common/dcp_pack.py`. Backend-neutral; only Mori uses them for now.
- `maybe_init_custom_mem_pool` asks the PD transfer backend first via a resolver table, then falls back to the existing Mooncake selection.
- Fix deferred-release failure paths: drain submitted writes before the abort ACK, and complete terminal chunks on every PP rank.
