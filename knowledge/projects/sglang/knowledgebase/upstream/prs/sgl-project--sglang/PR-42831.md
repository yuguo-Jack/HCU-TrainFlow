# [Fix] [Intel] mamba: Enable hybrid attention+Mamba models on XPU

[Upstream PR](https://github.com/sgl-project/sglang/pull/42831) · state: closed · merged: False

## Original PR description

## Motivation

Hybrid attention+Mamba/GDN models (e.g. Qwen3.8) were hard-blocked from using the `extra_buffer` Mamba radix-cache strategy on Intel XPU -- `supports_mamba_cache_extra_buffer` had an unconditional `if get_platform().is_xpu: return False`. Without `extra_buffer`, hybrid models fall back to `no_buffer`, which asserts `page_size == 1` and disables overlap scheduling, so any hybrid model configured with `--page-size > 1` (needed e.g. for LMCache KV offloading) failed at startup on XPU.

Enabling `extra_buffer` on XPU surfaced two further crashes once a hybrid model actually reached the decode step on real XPU hardware; both are fixed here too.

## Modifications

1. `arg_groups/overrides.py`: remove the XPU early return from `supports_mamba_cache_extra_buffer`, letting XPU fall through to the same allow-list/registry check every other platform uses.
2. `kernels/ops/attention/fla/fused_recurrent.py`:
   `fused_recurrent_gated_delta_rule_packed_decode`'s `use_small_value_tile` heuristic (SM100-only) called `torch.cuda.get_device_capability()` unconditionally, which raises `AssertionError: Torch not compiled with CUDA enabled` on a non-CUDA torch build. Guarded with `is_cuda()`, the same pattern used at every other CUDA-capability call site in this codebase.
3. `srt/layers/attention/xpu_backend.py`: `flash_attn_with_kvcache` always passed `bidirectional_block_ids`, a kwarg sgl-kernel-xpu's build doesn't accept. Only passed when a caller (Gemma-3 image batches) actually sets it.

## Accuracy Tests

N/A -- none of these changes alter model math; they remove a platform gate and fix two crashes that happen before any numerical output is produced.

## Speed Tests and Profiling

Not benchmarked in this PR. Verified functionally working end to end on Intel XPU with Qwen/Qwen3.8-27B-FP8, SGLang TP4, `--page-size 64`: the server starts, and hybrid attention+Mamba requests are served correctly, including with LMCache KV offloading enabled (companion LMCache change, multi-group engine-driven transfer).
