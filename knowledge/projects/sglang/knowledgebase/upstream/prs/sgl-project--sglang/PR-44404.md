# [Fix] [AMD] mooncake: Bump Mooncake to v0.3.14-rc1 for cross-node KV transfer

[Upstream PR](https://github.com/sgl-project/sglang/pull/44404) · state: closed · merged: True

## Original PR description

## What
Bump Mooncake in `docker/rocm.Dockerfile` from `01d1eb2a` to v0.3.14-rc1 (`78566d45`).

## Why
With `01d1eb2a`, cross-node requests are sent through Mooncake's single-node GPU-IPC transport, so KV transfer between prefill and decode nodes fails (`hipIpcOpenMemHandle failed (201)`, then "remote mooncake session is not alive"). The fix has been in Mooncake since `45b84d36`. This replaces #30051, and no ROCm runtime change was needed on ROCm 10.

## Validation
Rebuilt the ROCm 10 image (`v0.5.21-rocm10-mi35x-20261013`) with this commit and ran DeepSeek-V4-Flash FP4, 1 prefill + 1 decode node, on two MI355X nodes: GSM8K 0.926, concurrency 1 to 256 completed, no transfer errors. The unmodified image fails on the first request.
