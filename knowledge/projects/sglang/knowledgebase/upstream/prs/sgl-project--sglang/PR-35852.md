# fix: handle list token-id logprob results

[Upstream PR](https://github.com/sgl-project/sglang/pull/35852) · state: open · merged: False

## Original PR description

## Motivation

In mixed batches, `next_token_token_ids_logprobs_val` can contain both:

- tensors for requests that ask for token-ID logprobs;
- list placeholders for requests that do not ask for token-ID logprobs.

The current prefill and decode normalization paths call `.tolist()` on every entry. When an entry is already a list, this raises:

```text
AttributeError: 'list' object has no attribute 'tolist'
```

Fixes #35705.

## Modifications

- Use `torch.is_tensor()` to check each token-ID logprob result before calling `.tolist()`.
- Preserve values that are already lists.
- Apply the fix to both prefill and decode normalization paths.
- Add focused CPU regression tests covering mixed list and tensor results in both paths.

## Accuracy Tests

- Deployment validation against the reported failure scenario passed.
- Added regression coverage for both prefill and decode result normalization.
- This change does not modify model forward computation or numerical results.

## Speed Tests and Profiling

Not applicable.

The change only adds a lightweight `torch.is_tensor()` check while normalizing token-ID logprob results. This path runs only when token-ID logprobs are requested, and no measurable performance impact is expected.

- 0xFFFFail · comment · 2026-10-14T13:01:53Z · [source](https://github.com/sgl-project/sglang/pull/35852#issuecomment-6168960099)

Another reproduction, hit in production use. This PR's fix resolves it.

**Environment**
- SGLang source build at commit `4ccff141` (reports `0.0.0.dev0`), with unrelated local patches. The crash sites are byte-identical to current `main`.
- Model: Qwen3.8-27B (BF16), with MTP / NEXTN speculative decoding (`num_steps 2`, `topk 1`, `draft_tokens 3`) and `--max-running-requests 16`.
- Hardware: 1× RTX PRO 6000 Blackwell (driver 595.80), torch 2.13.0+cu130.

**Workload.** Long thinking generations run concurrently. Each one is followed by short scoring requests (`max_new_tokens=1`, `return_logprob=True`, `token_ids_logprob=[...]`) that land in the same running batches.

**Failure.** A single isolated scoring request works. After about 8 minutes of mixed traffic, the scheduler dies:

```
File ".../scheduler_components/batch_result_processor.py", line 825, in process_batch_result_decode
    next_token_ids, next_token_logprobs = self._normalize_decode_outputs(
File ".../scheduler_components/batch_result_processor.py", line 952, in _normalize_decode_outputs
    v.tolist() for v in logits_output.next_token_token_ids_logprobs_val
AttributeError: 'list' object has no attribute 'tolist'
```

**Workaround.** We applied the same `torch.is_tensor()` guard as this PR at all six sites: the `top_logprobs_val`, `top_logprobs_idx` and `token_ids_logprobs_val` normalisation, in both `move_logprobs_to_cpu` and `_normalize_decode_outputs`.

**After the guard.** The same server and workload are running with 0 scheduler exceptions so far. The guard only changes the container type; values are passed through unchanged.

**Note.** #34075 was approved but closed unmerged (2026-09-28), and #34719 reports the bug still present on v0.5.20. This PR covers both the prefill and decode paths, so it would be great to get it reviewed. cc @Qiaolin-Yu, who approved #34075.


- 0xFFFFail · comment · 2026-10-14T15:03:22Z · [source](https://github.com/sgl-project/sglang/pull/35852#issuecomment-6171426129)

Follow-up with the numbers from the same patched server: the `is_tensor` guard at all six sites, on the build described above.

**Full mixed-traffic gate run.** The gate was 14 long thinking requests, with traces up to 18,033 tokens. Each was followed by its `token_ids_logprob` scoring requests, sharing batches throughout.
- 0 scheduler exceptions, 0 request errors, 0 retractions.

**Readout parity.** The scoring requests were re-run on a separate server without speculative decoding, on a sample of 4 requests (8 scoring slots, including the longest trace). Comparing the probabilities over the candidate token ids:

| Comparison | Max abs difference |
|---|---|
| no-spec vs spec rescore | 2.6e-4 |
| no-spec vs in-run (mixed batch) | 3.0e-4 |
| spec rescore vs in-run | 2.6e-4 |

The argmax was identical on all 8 slots.

So the guard fixes the crash without changing the scores. The remaining differences are at the scale of ordinary batch-shape numerics (cf. #43956).
