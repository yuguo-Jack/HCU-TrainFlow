# [Fix] anthropic: Keep K3 token counts consistent with Messages usage

[Upstream PR](https://github.com/sgl-project/sglang/pull/46549) · state: open · merged: False

## Original PR description

## Motivation

K3 Messages token counts disagree with generation usage. `/v1/messages/count_tokens` returns the full rendered prompt length, while Chat generation already excludes the assistant generation stub through `_reported_prompt_tokens`. The count endpoint is therefore three tokens higher for the same input.

When cache usage is measured, compare this endpoint’s public total with the full Messages `input_tokens + cache_read_input_tokens + cache_creation_input_tokens` partition, rather than uncached `input_tokens` alone; unknown creation remains unclassified.

This focused fix is also included in the combined usage feature #46091. Keeping this PR open preserves the smaller review path; the combined PR's validation does not replace evidence for this head.

## Modifications

Reuse the existing reporting helper after tokenizing either an ID-list prompt or a string prompt. This keeps model-specific accounting and the zero lower bound in one place. Other models retain their original counts.

The regression covers both prompt forms, K3 and non-K3 accounting, a changed stub length, short prompts, cancellation, and tokenization errors. It uses the real reporting helper.

## Accuracy Tests

Based on main `52a6f7049f99`.

- The new test class fails against the original count handler and passes with this change in a focused CPU fixture. The fixture executes the production conversion/count/error methods and reporting helper with the actual protocol models; it isolates Torch/CUDA startup imports. It is not a full-package test run.
- Ruff, formatting, isort, codespell, and the registered-test checks pass for the changed files.
- An internal K3 GPU run exposed the original mismatch: count `1506`, generation input `1503`. A later internal build with this fix returned `1498` from both paths on another synthetic prompt. These are different inputs and internal serving builds, not a GPU A/B of this upstream commit.

The normal package entry still needs CI:

```bash
PYTHONPATH=python python -m pytest -q \
  test/registered/unit/entrypoints/anthropic/test_serving.py \
  -k TestAnthropicCountTokens
```
