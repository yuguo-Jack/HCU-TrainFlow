# [AMD][DI][CI] 10/N Add DSV4 HiSparse+HiCache 1P1D nightly recipes (FP4/FP8) x (PRO/FLASH)

[Upstream PR](https://github.com/sgl-project/sglang/pull/37200) · state: open · merged: False

## Original PR description

## What
Nightly tests for DSV4 HiSparse + HiCache in 1P1D over MoRI, for Pro and Flash, FP4 and FP8: HiCache on prefill, HiSparse on decode. Added to `nightly-configs.yaml`.

Launcher: a `disable_radix_cache: false` knob (HiCache needs the radix cache on), and a recipe's `*_extra_env` is now applied after the DSV4 env so it can override it.

Recipe notes:
- Decode uses `--disable-overlap-schedule`: the overlap scheduler intermittently desyncs the decode TP request broadcast.
- Prefill is capped at 262144 tokens and 9217 context, decode at 1M tokens. Without the prefill cap, prefill runs out of GPU memory on the first real batch. Without the decode cap, the HiSparse host pool is too large for transparent hugepages.

## Depends on
#45494, #29168, #32368, merged in that order. This one merges last.

## Validation
MI355X, 2 nodes, ROCm 10 image `v0.5.22-rocm10-mi35x-20261018` with those PRs applied: all four recipes complete concurrency 1 to 256 with no errors. GSM8K: Flash FP4 0.965, Pro FP4 0.975, Flash FP8 0.950, Pro FP8 0.985. Flash FP4 also passes 64k-context needle retrieval (40/40). To re-run after the dependencies land in main.

The stack under test was #29168 → #32368 plus a host-pointer fix. We also built #32368 + #35233 on its own, with a rebuilt gfx950 `sgl_kernel` and no #36966 in the tree, and pro-fp4 scored 0.970 there — so #35233 covers what these recipes need, and #36966 can be closed.

What the recipes now carry, measured rather than guessed:

- **decode host pool on 2MiB pages.** One ionic pd holds about 1M 4K page-table entries, roughly 4 GiB. The pool is larger, so `ibv_reg_mr` fails with `errno:22` partway through and the decode scheduler aborts. On 2MiB pages the same pool registers clean: 100 GiB on one pd against 3.75 GiB on 4K.
- **Flash decode capped at the Pro token budget.** The host pool is the budget over four, and Flash budgets 26.2M against Pro's 12.3M, so an uncapped decode wants 174 GB per rank, 1.4 TB over eight.
- **Flash prefill at `--hicache-ratio 1.2`.** At 2 the c4 indexer pool is left 3.67 GB and prefill dies. `--hicache-size` is not a way out; the DSV4 path rejects it.
- **Flash prefill at `mem_fraction_static 0.78`.** At 0.85 it is left about 0.5 GiB of VRAM and the first lazily loaded Triton kernel has no room. `hipModuleLoadData` then reports `hipErrorNoBinaryForGpu`, which is about space, not the arch.

The recipes are the run command — full flags and env for both roles — at `scripts/ci/slurm/recipes/mi355x-{fp4,fp8}/dsv4{pro,flash}/1k1k/1p1d-hisparse-hicache.yaml` in [this PR](https://github.com/sgl-project/sglang/pull/37200/files).
