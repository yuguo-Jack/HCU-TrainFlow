# [Fix] kv-events: Retry replay batches under backpressure

[Upstream PR](https://github.com/sgl-project/sglang/pull/48114) · state: open · merged: False

## Original PR description

## Motivation

Prevent the KV-event replay publisher from silently dropping retained batches and the completion marker when a slow reader fills its outgoing queue. ZeroMQ ROUTER sockets otherwise silently discard sends to peers at their high-water mark.

This rebases #38945 onto current `main` (`8d4e1ce4c7d66ab7e940484e4626fa56b1508e96`), preserving the original commit's authorship. Conflict resolution retains main's topic-bearing replay frames and empty-topic completion marker, and updates the regression expectations and publisher test setup accordingly.

## Modifications

- Enable `ROUTER_MANDATORY` and nonblocking replay sends; retry the next unsent batch or completion marker on `EAGAIN`.
- Resume pending replays on later publisher iterations with a shared 256-send budget and rotation between clients so live publication continues.
- Pin each accepted request's retained history while the live replay buffer rotates. Limit pending snapshots to 16, remove disconnected clients, and expire replays after 30 seconds without progress without sending a completion marker.
- Retain seven CPU regression tests covering queue saturation/history rotation, completion-marker retry, independent readers, live publication, send budget/nonzero starting sequence, admission/expiry, and disconnect cleanup. Replay assertions include a nonempty topic to cover the current wire format.
