# [PD] Add UniFlow as a native KV transfer backend

[Upstream PR](https://github.com/sgl-project/sglang/pull/43437) · state: open · merged: False

## Original PR description

## Motivation

[UniFlow](https://github.com/meta-pytorch/torchcomms/tree/main/comms/uniflow) is an open-source, host-initiated point-to-point transfer library developed at Meta. It exposes one interface over NVLink, RDMA (InfiniBand/RoCE, EFA) and TCP, and over GPU, CPU and NVMe memory. It picks the best transport automatically from topology and provides zero-copy put/get for KV cache transfer in LLM inference. To enable vendor-neutral PD (Prefill-Decode) disaggregation on both NVIDIA and AMD hardware, we add UniFlow as a transport layer for SGLang's KV transfer.

## Modifications

### Architecture Overview

The implementation follows the Mooncake, NIXL, and MORI pattern: the classes in `python/sglang/srt/disaggregation/uniflow/conn.py` subclass the common connector in `python/sglang/srt/disaggregation/common/conn.py` and reuse its bootstrap server, heartbeat, timeouts, and deferred decode KV release. Prefill writes KV, aux, and state directly into decode memory with UniFlow one-sided puts; control messages use the common ZMQ side channel. `python/sglang/srt/disaggregation/uniflow/DESIGN.md` documents the wire protocol, ordering, and failure semantics.

#### 1. **UniflowKVManager** - Core Transfer Management

- **Initialization**:
  - Creates a `UniflowAgent` on the rank's GPU
  - Registers KV and state buffers (GPU memory) and aux buffers (host memory)
  - Spawns the accept and control-message threads, plus a transfer worker on prefill and the heartbeat checker on decode

- **Configuration Options** (via environment variables):
  - `SGLANG_DISAGGREGATION_UNIFLOW_TRANSFER_TIMEOUT_MS`: Completion deadline for each put batch (default: 30000)

#### 2. **UniflowKVSender** (Prefill Side)

- **Workflow**:
  1. Waits for the decode rank's registration and request metadata
  2. Connects to the decode agent and imports its segments on first use
  3. Puts each chunk's KV as one batch, and aux and state with the last chunk
  4. Sends the terminal status; with deferred release, acks a decode ABORT only after earlier puts return

#### 3. **UniflowKVReceiver** (Decode Side)

- **Workflow**:
  1. Registers its agent and segments with each prefill rank it targets
  2. Sends per-request metadata: KV page, aux, and state indices
  3. Polls for the terminal status from prefill
  4. On abort or timeout, sends ABORT; with deferred release, keeps the request's pages until prefill acks or the release timeout expires (#41402, #41404)

#### 4. **Registration, Docs, and Tests**
Adds the `uniflow` choice for `--disaggregation-transfer-backend`, a UniFlow section in the PD disaggregation docs, CPU unit tests with a fake binding, and two AMD GPU tests on the real binding.

### Usage

**Installation**: 
Follow this [README](https://github.com/meta-pytorch/torchcomms/blob/main/comms/uniflow/python/README.md)

**SGLang PD Disaggregation with UniFlow**: Use `--disaggregation-transfer-backend uniflow` on both the prefill and decode servers. UniFlow picks the transport per transfer: GPU peer copies within a node where supported, otherwise RDMA, then TCP on builds with TCP enabled. Aux data is in host memory and always uses RDMA or TCP, so even a single-node deployment needs an RDMA NIC or TCP with a routable address. See `docs/docs/advanced_features/pd_disaggregation.mdx` for a single-node example.

### Known Limitation
- In this very first PR of adding Uniflow, only one-to-one prefill/decode rank routing (equal attention TP, or MLA with a larger prefill TP) is throughly tested, for paged KV, aux, and mamba/SWA/DSA state; other configurations fail at startup or fail the request.

## Benchmarking and Profiling

### End-to-End PD Disaggregation
**Hardware Configuration:**
- **GPUs**: 8x AMD Instinct MI350X per node
- **CPUs**: 2x AMD EPYC 9655 (96 cores each) per node
- **Network**: 8x Broadcom 400 Gb/s RoCE NICs (bnxt_re) per node
- **Model**: Qwen3-30B-A3B
- **Setup**: 2-node configuration (node 1: prefill + router + benchmark client; node 2: decode)
- **Software**: PyTorch 2.12.0 (ROCm 7.2 build), HIP 7.2

**Benchmark Command:**

Prefill instance (node 1):
```bash
python -m sglang.launch_server \
  --model-path Qwen/Qwen3-30B-A3B \
  --disaggregation-mode prefill \
  --host :: --port 31000 \
  --tp-size 8 \
  --page-size 1 --chunked-prefill-size 16384 \
  --attention-backend triton \
  --cuda-graph-backend-prefill disabled --cuda-graph-backend-decode disabled \
  --disable-radix-cache --disable-overlap-schedule \
  --disaggregation-transfer-backend uniflow \
  --trust-remote-code
```

Decode instance (node 2):
```bash
python -m sglang.launch_server \
  --model-path Qwen/Qwen3-30B-A3B \
  --disaggregation-mode decode \
  --host :: --port 31000 \
  --tp-size 8 \
  --page-size 1 --chunked-prefill-size 16384 \
  --attention-backend triton \
  --cuda-graph-backend-prefill disabled --cuda-graph-backend-decode disabled \
  --disable-radix-cache --disable-overlap-schedule \
  --disaggregation-transfer-backend uniflow \
  --trust-remote-code
```

The MORI column uses the same two commands with `--disaggregation-transfer-backend mori`. STANDALONE is one server on node 1 with the same flags, `--port 30000`, and no `--disaggregation-*` flags.

The NIXL column uses the same two commands with `--disaggregation-transfer-backend nixl` and SGLang's NIXL code unchanged, on NIXL 1.3.2 with its UCX backend (UCX 1.20.1 built with ROCm and verbs), `UCX_TLS=rc_verbs,ud_verbs,self,rocm_copy` and `UCX_IB_GID_INDEX=3` (the default GID index did not connect on these NICs).

Router (node 1):
```bash
python -m sglang_router.launch_router \
  --pd-disaggregation --mini-lb \
  --prefill http://<node1>:31000 8998 \
  --decode http://<node2>:31000 \
  --host :: --port 30000
```

Benchmark client (node 1):
```bash
python -m sglang.benchmark.serving \
  --backend sglang \
  --base-url http://[::1]:30000 \
  --model Qwen/Qwen3-30B-A3B \

```

Tests (single node):
```bash
python -m pytest test/registered/unit/disaggregation/test_uniflow_backend.py
```

**GSM8K Accuracy (PD vs STANDALONE):**

One node, Qwen3-30B-A3B, same server flags as above. STANDALONE is one TP=4 server on GPUs 0-3. PD is a TP=4 prefill server on GPUs 0-3 and a TP=4 decode server on GPUs 4-7 (`--base-gpu-id 4`) behind the router, with `--disaggregation-transfer-backend uniflow` and UniFlow restricted to RDMA by a test override. This is a quality check, not the two-node TP=8 setup above.

```bash
python -m sglang.test.few_shot_gsm8k --num-shots 5 --num-questions 1319 \
  --max-new-tokens 512 --parallel 128 --temperature 0 --host ::1 --port 30000
```

| Setup | Correct | Accuracy | Invalid |
|---|---|---|---|
| STANDALONE (TP=4) | 1200/1319 | 0.910 | 0.001 |
| UNIFLOW PD (RDMA, TP=4 + TP=4) | 1208/1319 | 0.916 | 0.000 |
| MORI PD (RDMA, TP=4 + TP=4) | 1205/1319 | 0.914 | 0.000 |
| NIXL PD (RDMA, TP=4 + TP=4) | 1204/1319 | 0.913 | 0.000 |

PD over UniFlow matches STANDALONE accuracy within noise.


UniFlow moved KV correctly over RDMA at TP=8; and UniFlow leverages RDMA effectively, with near-identical performance profiles, validating UniFlow as a production-ready alternative for AMD hardware.
