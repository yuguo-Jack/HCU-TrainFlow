# [Fix] hicache: Fix rank ownership of recurrent file checkpoints

[Upstream PR](https://github.com/sgl-project/sglang/pull/41692) · state: open · merged: False

## Original PR description

## Motivation

A hybrid model can share MLA KV across TP ranks while its recurrent state remains rank-local. File storage gives those state shards the same key, so a fresh reader can silently restore another rank's state at DCP1.

This work grew out of experiments with Kimi-K3 serving configurations.

This fix is independent. Follow-up DCP storage PRs #41693, #41694 and #41695 are temporarily drafts while being rebased against upstream.

## Modifications

- Qualify recurrent files by TP rank/size and tensor schema, excluding cache capacity.
- Let each rank write and evict its own state while the MLA KV owner manages shared KV. Lock registration and preserve pending write reservations during rescans.
- Compact long filenames without losing the suffix used for ownership and metadata scans.

Legacy rank-less recurrent files and compacted long namespaces intentionally cold-miss. Ordinary KV filenames stay compatible. The file size cap applies per rank, including its owned state. Old state files from a previous TP topology require manual cleanup. DCP > 1 remains gated in this PR.

**[suggestion]** For an MLA rank with eviction configured, `__init__` still logs that this rank "skips LRU bookkeeping and will not create new files" and `is_storage_owner` stays False. `HiCacheFile.register_mem_host_pool_v2` then calls `add_owned_suffix`, after which that same rank does create and evict recurrent files. The log and the property now describe the pre-registration KV-only world, not the ownership model this PR implements.

**Suggestion:** Treat ownership as `_owned_suffixes` only. Do not log the skip until it is known no side-pool suffix will be added, or log again from `add_owned_suffix` when eviction is armed; make `is_storage_owner` reflect `bool(self._owned_suffixes)` (or drop the property if tests are the only callers).

- ch-wan · comment · 2026-10-15T12:21:19Z · [source](https://github.com/sgl-project/sglang/pull/41692#discussion_r4282875271)

File: `python/sglang/srt/mem_cache/storage/file/lru_file_evictor.py` · line None

**[suggestion]** `_scan_existing_files` now does `self._lru.clear()` / `_total_bytes = 0` without `_lock` and without touching `_pending_writes`. That rebuild is required for `add_owned_suffix`, whose docstring says it runs "before storage workers start", but `HybridCacheController.attach_storage_backend` starts storage threads in the parent and only then registers host pools (including Mamba). A concurrent `reserve`/`touch` would race the OrderedDict, and an in-flight reservation would vanish from `_lru` while remaining in `_pending_writes`, so byte accounting undercounts until the next touch.

**Suggestion:** Rebuild the index under `_lock`, and either merge still-pending keys back into `_lru` or fail `add_owned_suffix` if `_pending_writes` is non-empty. Update the docstring to match the real attach order.
