# [Superseded] Add opt-in MXFP8 output for DeepSeek WO-A

[Upstream PR](https://github.com/sgl-project/sglang/pull/45677) · state: closed · merged: False

## Original PR description

Superseded by #45632 (`aa10927271f0302fc7f2394a66b5568d394f2c88`), which is present in the clean remeasurement baseline `779adb4b82243e7743be60a305dc62ca3bee3a3a`.

Current main already writes Mega WO-A output as an FP8/packed-scale pair and prepares the DeepGEMM-packed WO-B consumer under the default FlashInfer configuration. The actual DeepSeek-V4.1-Flash TP4/EP4 DSPARK deployment selects FlashMLA Mega attention and FlashInfer CuTe-DSL. Reintroducing the overlapping helper and opt-in environment variable adds maintenance surface without establishing a new serving benefit.

A post-timing 12-step trace of the pinned current-main deployment on four GB300 GPUs confirms 300 FP8-output WO-A kernels per rank (280 in verify and 20 in extend); both baseline and the Engram-only candidate use that same path. Some other shapes still use BF16 output, so this is not a claim that every WO-A path is fused.

The previous measurements used `ed89693` before #45632: they remain historical evidence for that implementation, not incremental gains over current main. The remaining regular/group128 path and stricter tiny-value scale-floor contract are distinct features; neither has fresh default-deployment throughput evidence supporting this PR. The optional floor API proposed in [DeepGEMM #111](https://github.com/sgl-project/DeepGEMM/pull/111) was also closed on 2026-10-23: the current main path does not depend on it, and no remaining concrete consumer or independent serving benefit has been established in this optimization work.

Closing this draft rather than shipping the duplicate implementation, new environment flag and 195-line standalone integration test. The branch and earlier validation artifacts are retained; no independent performance gain over current main is claimed.
