# [Feat] router: Support abort_request endpoint

[Upstream PR](https://github.com/sgl-project/sglang/pull/45296) · state: closed · merged: False

## Original PR description

## Motivation

The router does not expose the engine's `/abort_request` endpoint, so clients cannot cancel an in-flight request through the router.

Fixes #6531.

## Modifications

- Add `POST /abort_request` to the HTTP router.
- Forward the complete abort JSON payload and caller `Authorization` header.
- Fan the request out to every registered worker. The router has no persistent request-id-to-worker mapping, and a PD request can occupy both prefill and decode workers; non-owning workers safely treat the abort as a no-op.
- Return an empty `200 OK` when all workers acknowledge the abort (or the fleet is empty), and a per-worker `502 BAD_GATEWAY` breakdown on partial failure.
- Bound fan-out concurrency to 32 requests.
- Add unit coverage for mixed worker modes, payload preservation, authorization forwarding, partial failure, and an empty registry.
- Document the new endpoint and API-key behavior.
