# [Feat] attention: Block-bidirectional (prefix-LM) attention for decision models via bidir_prefix_len

[Upstream PR](https://github.com/sgl-project/sglang/pull/45776) · state: open · merged: False

## Original PR description

<!-- PR title: [Feat] attention: Block-bidirectional (prefix-LM) attention for decision models via bidir_prefix_len -->

## Motivation

- Base Labs' [elephant-1](https://huggingface.co/baselabs/elephant-1) and [mammoth-1](https://huggingface.co/baselabs/mammoth-1) (Qwen3.5 hybrid GDN decision models) are trained with a two-block mask in their full-attention layers: the state attends to itself in both directions and never sees the question; the question sees the state and itself in both directions; GDN layers stay causal.
- SGLang today runs them causally (median answer-probability error 0.045 vs their engine, 101/120 argmax) or, with `noncausal_full_attention`, makes the whole prompt bidirectional and gives up the radix cache. Neither matches the checkpoint, and the second cannot share one state across many questions.

## Modifications

- `bidir_prefix_len` on `/generate`: tokens before it are the state block, tokens at or after it the question block; `None`/`-1` is causal. Plumbed `GenerateReqInput` → `Req` → `ForwardBatch.bidir_prefix_lens`; rejected on non-Triton backends and for prompts above `--chunked-prefill-size`.
- Triton extend kernel takes a per-sequence boundary (`USE_BLOCK_MASK`) and widens the causal predicate to `causal | key < P | query >= P`, skipping fully masked tiles; CUDA graphs stay on and causal sequences are untouched.
- Radix cache: block-bidirectional requests live under `extra_key="|bidir{P}"`, and a hit is accepted only when the whole state block matched; a shorter match is a miss and its copy-on-write Mamba state is dropped (previously a stale GDN state leaked into the forward).
- `PrefillAdder` never splits a block-bidirectional prompt across chunks; the whole prompt must fit in `--chunked-prefill-size`.
- Kernel unit test (per-sequence output vs an eager masked-softmax reference: causal `-1` rows, boundary at 0, inside the cached prefix, inside the extend, Qwen3.5 head shape at 1k-3k), docs rows in `sampling_params.mdx` and `decision_models.mdx`.

## Accuracy Tests

Against Base Labs' own OneJev engine on identical prompts: 120 questions (6 seeds × {1k, 3k}-token state × 10 question types), one GPU, radix cache and CUDA graphs on. `max|Δp|` is the largest difference across a question's answer-label probabilities.

| Model | GPU | Quant | p50 max\|Δp\| | worst | same top option |
|---|---|---|---|---|---|
| elephant-1 | B200 | BF16 | 0.0019 | 0.014 | 120/120 |
| elephant-1 | H200 | BF16 | 0.0016 | 0.021 | 119/120 |
| mammoth-1 | B200 | BF16 | 0.0021 | 0.023 | 120/120 |
| mammoth-1 | H200 | BF16 | 0.0024 | 0.026 | 120/120 |
| elephant-1 | B200 | FP8 | 0.0078 | 0.064 | 115/120 |
| mammoth-1 | B200 | FP8 | 0.0122 | 0.091 | 120/120 |
| elephant-1, causal (today's behaviour) | B200 | BF16 | 0.0447 | 0.211 | 101/120 |

On a B200 at the current head (rebased onto `main` @ 9eec211b9a; 14 files, +210 / -1): the new kernel test and `test_prefill_adder.py` / `test_scheduler_held_row_admission.py` (56 passed). The accuracy and speed numbers in this PR were measured on the previous head; the kernel, cache and scheduler code are unchanged by the rebase.

## Speed Tests and Profiling

- One B200, 32 clients, 3k-token state × 1 question: 54.7k prompt tok/s BF16 vs 59.7k causal same boot (the block mask costs 8%), 67.0k FP8; elephant-1. mammoth-1: 18.0k BF16, 20.9k FP8. H200: 33.6k / 44.6k (elephant), 10.5k / 15.4k (mammoth).
- 10 questions per 3k state: radix hits 0% → 76%, 136k prompt tok/s (elephant BF16, B200); the second question on a state whose boundary is not on the 64-token Mamba checkpoint grid still recomputes it once.
- Requests without `bidir_prefix_len` are unaffected (`USE_BLOCK_MASK=False` specialisation).
