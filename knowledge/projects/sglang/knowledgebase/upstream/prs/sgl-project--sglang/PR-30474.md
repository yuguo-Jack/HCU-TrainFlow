# [sglang-miles] Allocate DSA cuda-graph page_table and flashmla_metadata in TMS cuda_graph region

[Upstream PR](https://github.com/sgl-project/sglang/pull/30474) · state: open · merged: False

## Original PR description

## Problem

`SGLANG_MEMORY_SAVER_CUDA_GRAPH` only routes the **graph pool** (capture-time intermediates) through torch_memory_saver. The static buffers pre-allocated in `init_cuda_graph_state` are untagged and survive `release_memory_occupation([\"cuda_graph\"])`.

For DSA models the dominant static buffer is `page_table`: `max_num_tokens x max_context_len x int32`. On GLM-5.2 744B (context_len 1M, EAGLE num-draft-tokens 6, cuda-graph bs<=256) that is **6.4 GB** for the target runner plus **4x1.07 GB** for the multi-step draft backends = **~10.7 GB per GPU** that a colocate RL trainer cannot reclaim while the engine is paused.

## Fix

Allocate `page_table` and `flashmla_metadata` inside `region(tag=GPU_MEMORY_TYPE_CUDA_GRAPH)` (gated on `enable_memory_saver` + the same env var). Both are fully rewritten by the replay metadata path before every replay, so their contents need not survive pause/resume.

The init-once buffers (`cache_seqlens`=ones, `cu_seqlens_q`=arange, `cu_seqlens_k`) deliberately stay **outside** the region: resume hands back zero pages, which would silently corrupt them. They are KB-sized, so excluding them costs nothing.

## Validation (GLM-5.2 744B fp8, GB300)

- Single-node TP4 probe, per-tag release with per-PID NVML: releasing `cuda_graph` frees an extra **9.9 GB/GPU** with this change.
- temperature=0 generate before pause vs after resume: token ids identical, max logprob diff 0.0.
- 16-node colocate RL run: engine residual during training drops 10.01 GB/GPU (update-phase engine footprint 134.55 -> 124.54 GB); `train_rollout_logprob_abs_diff` unchanged (0.0577 vs 0.048-0.061 band); full RL step passes.
