# [Test] cp: Add a diagnostic for the CP8 TP-decode logprob gap (do not merge)

[Upstream PR](https://github.com/sgl-project/sglang/pull/47980) · state: open · merged: False

## Original PR description

## Motivation

`test/registered/e2e/cp/test_cp_decode_attn_tp_server.py` (added in #46857) fails on every run in its VERIFY versus teacher-forced CP prefill check (`atol=0.02`): 19/32 positions off with max 0.507 on the first runs, 25/32 with max 0.895 on [Nov 2](https://github.com/sgl-project/sglang/actions/runs/41434200175/job/125240292690), always with identical greedy tokens. Position 0, which both requests compute in a prefill, went from 0.057 to 0.54 apart.

Nothing measures what this gap is without CP, so we can't tell whether it is FP8 noise (the bound is wrong) or error introduced by the CP prefill / CP decode path (the code is wrong). #47970 loosens the bound and is on hold until this is answered.

## Modifications

Adds `test/registered/e2e/cp/test_cp_decode_attn_tp_logprob_gap_diag.py`, registered on `8-gpu-b300` but `disabled=`, so no scheduled suite runs it; it is for `/rerun-test` only. It never asserts on the gaps; it prints them.

It launches GLM-5.3 twice with the failing test's settings (EAGLE, decode graphs 1–8, `sgl-kernel` DSA top-k, fusion disabled):

1. **Plain TP8** (no CP flags)
2. **CP8** (`--attn-cp-size 8 --enable-prefill-cp --cp-strategy interleave --enable-cp-decode-attn-tp`)

For prompts of 1, 257 and 8193 tokens and a batch of 4 (257–281 tokens), it generates 32 greedy tokens, rescores prompt + output with a teacher-forced prefill, and reports per position (plus pos0, mean, median, max):

- `tp8_verify_vs_prefill`: the noise floor without CP
- `cp8_verify_vs_prefill`: what the failing test checks
- `cp8_prefill_vs_tp8_prefill_same_tokens`: CP8 prefill of the exact token sequence TP8 produced, against TP8's prefill. This isolates CP prefill from decode.
- `tokens_equal_tp_vs_cp`

Output lines start with `[gap]`, and the full report is one `CP_DECODE_ATTN_TP_GAP_REPORT {json}` line.

Checked locally with stubbed server responses (all cases run, report prints); not yet run on GPUs. `ruff format` and the repo's ruff lint selection pass.

## How to read it

- `tp8_verify_vs_prefill` about the same as `cp8_verify_vs_prefill`: FP8 noise; set the server test's bound from the TP8 numbers (#47970).
- `cp8_verify_vs_prefill` well above TP8 and `cp8_prefill_vs_tp8_prefill_same_tokens` large: CP prefill is off.
- CP8 VERIFY gap well above TP8 but CP prefill close to TP8: the CP decode path is off.

This PR is not meant to merge.

- em-dreyer · comment · 2026-11-02T22:46:44Z · [source](https://github.com/sgl-project/sglang/pull/47980#issuecomment-6590420271)

Results from the three diagnostic runs on `8-gpu-b300`:

1. [Run 1](https://github.com/sgl-project/sglang/actions/runs/41525986425/job/125553939201): VERIFY vs teacher-forced prefill on the same server is ≤ 0.11 for 257/8193-token and batched prompts on both TP8 and CP8. The 1-token case is the outlier (TP8 max 0.44, CP8 max 0.89). Its 33-token rescore runs as CP prefill.
2. [Prefix sweep](https://github.com/sgl-project/sglang/actions/runs/41532349161/job/125575733451): prefill-only logprobs for prefixes of one 2100-token sequence differ between CP8 and TP8 at every length (8–2100), mean 0.10–0.30, isolated spikes up to 8.4 nats.
3. [Attention-DP control](https://github.com/sgl-project/sglang/actions/runs/41535250316/job/125585543365): TP8 with `--attn-dp-size 8` (no CP) differs from plain TP8 just as much: mean 0.10–0.21, spikes up to 9.5.

Conclusion: the CP-vs-TP gap is the normal spread between valid layouts of this FP8 MoE model, not a CP prefill bug; `test_cp_decode_attn_tp_server.py`'s 0.02 cross-path bound can't hold. #47970 re-enables the test with bounds set from these numbers. This diagnostic PR is not meant to merge.
