# [Fix] kda: Honor state and replay dtype

[Upstream PR](https://github.com/sgl-project/sglang/pull/46594) · state: closed · merged: False

## Original PR description

Make KDA replay buffers and state writes honor `--mamba-ssm-dtype`, with matching memory accounting, while preserving the independent BF16 convolution default and `SGLANG_MAMBA_CONV_DTYPE` override.

Validated dtype configuration and memory accounting (5 tests, 16 subtests), buffer allocation, and replay against an independent FP64 reference on B300. All 54 added convolution regression cases passed on B300, covering prefill, decode, chain/tree verification, and FP32/BF16/FP16 states. The tree fix also supports explicit mixed-dtype convolution configurations; it does not enable ReplaySSM with topk > 1.

Kimi-K3 AIME26 via sgl-eval on final commit `47c218356f` (BF16 convolution, FP32 SSM/replay; 4 × 30 questions, concurrency 8, temperature 1.0, top_p 0.95, max_tokens 32768): main 102/120 (85.0%), PR 104/120 (86.67%); 4 vs. 5 truncated outputs. This DSpark chain-verification evaluation showed no score decrease, but does not establish an accuracy improvement or cover tree verification.
