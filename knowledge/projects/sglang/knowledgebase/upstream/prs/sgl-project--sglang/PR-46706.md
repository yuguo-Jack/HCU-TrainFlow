# [Fix] dsv4: Render null contents, trailing tool-call turns and numeric string efforts with deepseek-recipe

[Upstream PR](https://github.com/sgl-project/sglang/pull/46706) · state: closed · merged: True

## Original PR description

Fixes requests that rendered before deepseek-recipe (#45315) and now return 400 on DeepSeek-V4 / V4.1:

- A null message content renders as `""`, as `_process_messages` renders it for every model (a `tool` result, a `system` message, an assistant turn without tool calls).
- A trailing assistant turn's tool calls are discarded before it becomes a user turn or is continued, as `_handle_last_assistant_message` discards them; a null content there is `""` too.
- A numeric string `chat_template_kwargs.reasoning_effort` (`"30"`, `"0.3"`) is the number it spells: a budget on V4.1, a 400 on V4 as an integer is. `SGLANG_DSV41_REASONING_EFFORT` parses the same way.
- `sglang-processor` renders the same, and its DeepSeek tool dump now uses the shared `function_dump`, so `strict: null` renders as Python's `Function` (since #46133) does.
- Tests: the two DeepSeek parity fixtures are regenerated (the five cases above now render; `kwargs_budget_float_string` and V4's `kwargs_budget_string` added; `tool_results` no longer mixes strict and non-strict tools, which recipe rejects), and `test_serving_deepseek_recipe.py` covers the three fixes.

Behavior change: a request with `tools` (and `tool_choice` other than `"none"`) under `continue_final_message` keeps recipe's 400 ("Function call should not be used with prefix"), as DeepSeek's API rejects it; #45315 did not list it.
