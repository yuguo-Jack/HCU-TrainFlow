## Motivation

<!-- Describe the purpose and goals of this pull request. -->
With plain data parallelism, `attn_dp_rank` is zero on every replica. The sender currently uses this value to validate `follow_bootstrap_room` routing and register each request's prefill DP rank. As a result, a request handled by replica 1 can be rejected or registered as belonging to replica 0, causing the decode side to contact the wrong prefill worker.

Use the rank of the active DP dimension for these operations: `system_dp_rank` when `system_dp_size > 1`, otherwise `attn_dp_rank`. This matches the bootstrap server's existing topology indexing.

Revisits the fix proposed in [#29730](https://github.com/sgl-project/sglang/pull/29730), associated with [#29725](https://github.com/sgl-project/sglang/issues/29725). That PR was closed automatically after 91 days without updates and was not merged. This change revalidates the issue against the current working branch and adapts the existing regression test.

## Modifications

<!-- Detail the changes made in this pull request. -->
- Add `CommonKVManager.effective_dp_rank` as a property so both sender paths use the same selection rule. Keep the original system-DP and attention-DP topology fields intact.
- Use the effective rank in the `follow_bootstrap_room` conflict check and its error message. Correctly routed plain-DP requests are accepted, while genuine routing conflicts remain rejected.
- Use the effective rank in the `/register_dp_rank` payload so decode workers resolve the actual prefill replica.
- Update the sender registration test to represent both plain DP and DP attention. The previous fixture assigned `attn_dp_rank=dp_rank`, masking the plain-DP case where replica 1 has `system_dp_rank=1` but `attn_dp_rank=0`. The updated fixture exercises the real manager property and sender code, covering round-robin routing, bootstrap-room routing, forced queries, and explicit prefill-rank hints.
