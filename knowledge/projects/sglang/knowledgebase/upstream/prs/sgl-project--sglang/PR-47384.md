# [Doc] deployment: Add a Slurm Apptainer serving example

[Upstream PR](https://github.com/sgl-project/sglang/pull/47384) · state: open · merged: False

## Original PR description

## Motivation

Contributes to #3244. Slurm users running Apptainer need an example that preserves the allocated GPU selection and keeps model files and compilation caches outside the read-only container image.

This adds the container workflow alongside the existing deployment guide. It complements the general Slurm examples in #36116. The earlier Apptainer proposal in #29991, now closed, provided useful context for this focused example.

## Modifications

- Add a single-node, single-NVIDIA-GPU recipe for `Qwen/Qwen3-0.6B`, including image preparation and model download before job submission.
- Bind persistent Hugging Face and SGLang caches, enable offline model loading, and forward the task's `CUDA_VISIBLE_DEVICES` through Apptainer's `--cleanenv` boundary.
- Document submission, logs, foreground job lifetime, bounded HTTP readiness retries, a chat request, and container troubleshooting.

## Validation

- `mint validate`: build passed; six warnings in unchanged pages (Kimi-K2.5, speculative decoding, cache_dit, and models_with_ar).
- `mint broken-links --check-anchors --check-redirects`: passed, no broken links.

- Local Bash mock execution checked task-side GPU selection (including a GPU UUID), paths containing spaces, missing configuration, container failure exit-code propagation, Slurm's parsable cluster suffix, and the health/chat request arguments.

The shell checks use stub commands. I did not run a Slurm cluster, an Apptainer GPU container, model inference, or multi-node networking. Cluster resource requests and driver/container compatibility still need site-specific validation.
