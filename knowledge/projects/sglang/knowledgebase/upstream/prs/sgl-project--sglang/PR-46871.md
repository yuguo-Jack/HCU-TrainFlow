# [Fix] diffusion: keep tied vocab tables on device under layerwise offload

[Upstream PR](https://github.com/sgl-project/sglang/pull/46871) · state: closed · merged: True

## Original PR description

## Motivation

Fixes #47297

With default flags, LingBot-Video-MoE (`robbyant/lingbot-video-moe-30b-a3b`) crashes in text encoding on a single H100:

```
[LingBotVideoTextEncodingStage] Error during execution: Expected all tensors to be on the same device,
but got mat2 is on cpu, different from other tensors on cuda:0 (when checking argument in method wrapper_CUDA_mm)
```

The auto memory policy puts the text encoder on layerwise offload, which parks the declared host-resident vocab table (`Qwen3VLTextModel.embed_tokens`) in host memory. This checkpoint has `tie_word_embeddings=True`, so `Qwen3VLForConditionalGeneration.lm_head.weight` is the same Parameter. The head's matmul then gets a CPU weight.

## Modifications

- `_host_resident_tables` skips a declared table whose weight is also owned by another module (a tied output head). Untied tables are handled as before.
- One regression case in the existing `test_host_resident_vocab_table.py`.

## Accuracy Tests

Real checkpoint, 1x H100 80GB, `sglang generate --height 480 --width 480 --num-frames 81 --num-inference-steps 40 --seed 0` with the cookbook JSON prompt, default flags.

| | main | this PR |
|---|---|---|
| e2e generate | crashes (above) | video generated |
| vs known-good placement (`--layerwise-offload-components vae --text-encoder-cpu-offload true`) | n/a | bitwise identical, 81/81 frames, max pixel diff 0 |
| `test_a_table_tied_to_an_output_head_is_left_alone` | fails (`[Embedding(4096, 64)] == []`) | passes |

Unit tests (`test_host_resident_vocab_table.py`, `test_gemma4_unified_layerwise_offload.py`): CPU main 11 passed / 1 skipped, this PR 12 passed / 1 skipped; on H100 13 passed (includes the CUDA-only case).

## Speed Tests and Profiling

No speed change intended. Tied tables now stay on device (the gather on host is skipped only for them).
