# [DCP] Validate DCP nesting at launch; reject non-bf16/fp16 KV under NPU DCP

[Upstream PR](https://github.com/sgl-project/sglang/pull/43141) · state: open · merged: False

## Original PR description

## Motivation

Two decode-context-parallel (DCP) configurations that nothing rejects at launch: one is invalid on every
platform, the other runs an unvalidated path on Ascend.

1. **A DCP group that does not fit inside one attention-TP group.** `tp_size % dcp_size == 0` is checked
   only inside `initialize_model_parallel`, after torch.distributed is up. Nothing checks the case that
   matters with DP attention, DWDP or attention CP. For example, with `--tp-size 4 --attn-dp-size 2
   --dcp-size 4`, `4 % 4 == 0` passes, but attention TP is 2. So one 4-rank DCP group spans two DP replicas
   that decode different batches. No launch check catches it.
2. **FP8 KV cache under DCP.** The non-DCP branch routes an FP8 KV cache to
   `npu_kv_quant_sparse_flash_attention`. The DCP branch has no equivalent and passes the cache unchanged
   to `sgl_sparse_flash_attention`, which has not been validated with FP8 KV.

## Modifications

- `parallel_hook.py` (`handle_context_parallelism`): when `dcp_size > 1`, reject an attention-TP size
  (`derive_attn_tp_size`) that `dcp_size` does not divide. This covers the ragged `tp_size % dcp_size`
  case too, because attention TP divides `tp_size`. The check sits in `handle_context_parallelism`
  because the DP and CP widths are final only there. DWDP declares `attn_dp_size` earlier, and the
  prefill-CP model overrides declare `attn_cp_size` in `handle_model_specific_adjustments`, which runs
  after the DCP flags are read. The check runs on every platform, not only Ascend. On CUDA, DSA or MLA
  with `--enable-prefill-cp` and `--dcp-size > 1` now fails at launch, because that override sets
  attention TP to 1 by default. That combination was not tested on CUDA; if it works today, the check is
  too strict there.
- `ascend_backend.py`: the DCP branch of the DSA forward raises `NotImplementedError` for any KV cache
  dtype other than bf16 or fp16, such as FP8. It uses an allow-list instead of listing FP8 variants, so
  `fp8_e5m2` is caught too. Only bf16 has run under DCP; fp16 is allowed as the other half-precision
  model dtype.

No change at `--dcp-size 1`, or for layouts where DCP nests inside attention TP with a bf16 or fp16 KV
cache.

## Accuracy Tests

The code only adds argument checks at launch and a KV-dtype error on the first DCP forward. The working DCP
path is unchanged.

Box run: GLM-5.2 W4A8, Ascend A3, tp16 dcp16, chunked prefill 4096 (at -1, an ~11k-token prefill runs
out of memory in the existing `cp_lse_ag_out_rs_mla_npu` merge). It ran on an earlier revision of this
branch. The changes since then only touch startup and dtype checks, which tp16 dcp16 with bf16 KV passes.

GSM8K, 64 questions, eager: 0.953, paired against a tp16 run without DCP on an earlier development
build, not this branch (0.938 on the same questions). 60 right in both, 3 wrong in both, 1 right only
with DCP. Too few questions to prove parity, but nothing broke.

Launch checks. Both are rejected during argument resolution, before any device work. These messages
come from a CPU run of `handle_context_parallelism`:

```
--tp-size 16 --dcp-size 3
ValueError: Decode context parallelism must nest inside one attention-TP group: the attention TP size must be evenly divisible by --dcp-size / --decode-context-parallel-size, but got attn_tp_size=16 and dcp_size=3 (tp_size=16, attn_dp_size=1, attn_cp_size=1).

--tp-size 16 --attn-dp-size 2 --dcp-size 16
ValueError: Decode context parallelism must nest inside one attention-TP group: the attention TP size must be evenly divisible by --dcp-size / --decode-context-parallel-size, but got attn_tp_size=8 and dcp_size=16 (tp_size=16, attn_dp_size=2, attn_cp_size=1).
```

## Tests

- `test/registered/unit/server_args/test_server_args.py::TestDcpGroupGeometryValidation` (CPU, 4 cases):
  ragged split, DCP wider than attention TP under DP attention, CP width declared by a model override,
  and DCP nested in each DP replica accepted. The three rejection cases fail without this change.
- The KV-dtype guard in `ascend_backend.py` has no unit test, because exercising it needs torch_npu and
  the Ascend backend.
