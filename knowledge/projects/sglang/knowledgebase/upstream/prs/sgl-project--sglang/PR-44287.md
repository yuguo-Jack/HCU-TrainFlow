# [Feat] simulator: Support closed-loop agentic workloads

[Upstream PR](https://github.com/sgl-project/sglang/pull/44287) · state: open · merged: False

## Original PR description

## Motivation

Request completion and tool waits determine subsequent arrivals in closed-loop workloads. Fixed traces lose this feedback when inference latency changes. This PR adds optional coordination with external drivers, independent of dataset or harness. Implements the server side of #44221.

## Modifications

Add optional coordination to `OFFLINE`, without introducing a new execution mode or a dependency on a workload harness.

- `Coordinator` maintains transport-independent protocol state.
- `CoordinatedScheduler` connects it to existing request-receive, batch-result and idle hooks.
- External drivers own datasets, dependencies, timers and benchmark phases.
- An opt-in JSONL ledger records native visible output-token increments, preserving earlier committed output and excluding discarded cancellation tails. It does not change scheduling or batch costs.
- Native prefill/decode cadence decisions retain their original return values and countdown. A cadence-only pass with pending native work defers the coordinator idle boundary until the next scheduling pass, without advancing virtual time or granting a tool timer prematurely.

Native scheduling, batching, KV-cache behavior and latency prediction remain responsible for request execution.

### Execution flow

This example shows an independent tool timer releasing B while A is still running. Times are illustrative.

```mermaid
sequenceDiagram
    participant D as Workload driver
    participant H as HTTP frontend
    participant S as Scheduler + coordinator

    Note over D,S: OFFLINE with coordinator#59; A completes in one batch

    D->>H: HTTP request A
    D->>S: Ready 0: Submit A#59; next timer = 5 ms
    H->>S: Tokenized payload A
    S->>S: Input barrier satisfied#59; batch ends at 10 ms

    S-->>D: Grant 0: now = 5 ms#59; no terminals
    D->>D: Independent tool timer fires
    D->>H: HTTP request B
    D->>S: Ready 1: Submit B
    H->>S: Tokenized payload B
    Note over S: Queue B#59; current batch is not preempted

    S->>S: Advance to 10 ms#59; commit A
    S->>H: A result
    par Independent delivery
        S-->>D: Grant 1: now = 10 ms#59; A completed
    and
        H-->>D: HTTP response A
    end

    D->>D: Pair A's result and terminal by request ID
    D->>D: Process completion callbacks
    D->>S: Ready 2
    S->>S: Schedule pending work, including B
```

HTTP submissions and `Ready` proceed concurrently; their arrival order does not affect virtual time. The input barrier waits for request payloads, not responses. A timer-only grant requires no HTTP result, and the driver does not wait for every pending request before sending its next `Ready`.

Coordinated responses include virtual timestamps and native token/cache counts. Drivers manage warmup exclusion and measurement windows. Shutdown completes only after requests and native cleanup drain.

Existing clients can use `BLOCKING` without an adapter. This PR also paces visible cache-load latency before delivering `BLOCKING` responses.

Initial scope is one local driver and scheduler, text requests, ordinary radix cache, and completion- or timer-driven workflows. See the [driver contract](https://github.com/Jeff010101/sglang/blob/1e3e9dee8f99c5ae14b22ac75afbbf5b4401e6d2/tools/sglang-simulator/README.md#driver-contract) for configuration restrictions and adapter requirements.
