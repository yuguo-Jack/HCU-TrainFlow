# [Test] dsv4: Fix Hopper indexer replay test after DeepSelect decode (#41561)

[Upstream PR](https://github.com/sgl-project/sglang/pull/44193) · state: closed · merged: True

## Original PR description

[by Claude Code]

## Motivation

Fixes #44183.

`test/registered/kernels/ops/attention/test_fp4_indexer.py::test_hopper_indexer_backends_replay[1]` and `[2]` fail on every Hopper runner since #41561 landed. This breaks `call-jit-kernel-tests / jit-kernel-unit-test-1-gpu-large (0)` in `PR Test Base` for every PR based on current `main` (for example #36652, #43448, and #43826):

```
AttributeError: 'types.SimpleNamespace' object has no attribute 'page_table'
  python/sglang/srt/layers/attention/dsv4/v41_indexer/full_topk.py:149 (_torch_decode)
```

#41561 made `FullTopKIndexer` use DeepSelect for decode when `is_deep_select_supported()`. That path reads `paged_metadata.page_table` and `paged_metadata.compressed_page_size`, but this test mocks `paged_metadata` with only `max_compressed_seq_len`.

## Modifications

The test now sets `full.use_deep_select_decode = False`, so this CUDA-graph replay test keeps exercising the paged `select_decode` path it was written for. DeepSelect itself is covered by `test_deep_select.py`.

Adding a `page_table` mock instead would not be enough. The test also checks that output padding (row `batch`, and the columns past `topk`) is `-1`, and that the page indices come out in sorted order. The DeepSelect branch writes only `out_page_indices[:bs, :topk]`, with `sorted_index=False`. @yuyu5333, could you check whether production callers rely on `select_decode` resetting those padding entries? If they do, the DeepSelect branch may need the same reset. I haven't verified this.
