## Motivation

<!-- Describe the purpose and goals of this pull request. -->

`FlashAttentionBackend.__init__` selects a FlashAttention build (FA3, generic FA4, or the SM12x FA4 entry points added in #32991) and binds it to `self.flash_attn_varlen_func` / `self.flash_attn_with_kvcache`. Only one call site uses that binding: the `fa_skip_kv_cache` varlen call (#33007). The other 14 call sites go through the module-level wrapper `sglang.kernels.ops.attention.flash_attention`, passing `ver=self.fa_impl_ver`. That wrapper has no SM12x branch, which causes two problems:

- On SM12x with FA4, the entry points `__init__` selects run on one path, and the generic FA4 entry points run everywhere else. One consequence: the static `max_seqlen_k` that the SM12x runtime policy sets for CUDA-graph decode is dropped before it reaches the paged-decode fast path.
- A subclass that needs a different FA build, such as a vendor backend, has to replace both the `__init__` binding and every module-level call. There is no single seam.

What a single dispatch buys:

- **What `__init__` selects is what runs.** The kernel choice lives in one assignment, so a build-specific feature (the SM12x entry points, their runtime policy, any future build) reaches every call site, not only the one that happens to read `self.*`.
- **One override point for other FA builds.** #45946 (SAIL FA3 / FlashMLA) is a live example. To swap the FA build today, it extracts the binding into `_init_flash_attention_functions` and overrides it, and it also adds `_call_flash_attn_with_kvcache` / `_call_flash_attn_varlen_func` methods and rewrites every call site to go through them, because those call sites ignore the binding. On top of this PR, overriding the binding is enough: the `_call_*` methods and the call-site rewrites can go, along with the function-local import they run on every CUDA call. The FA part of that PR's base-class diff shrinks to the method extraction.
- **No `ver=` to thread through each call**, and the new guard test keeps the backend from drifting back to two paths, which is how it got here (see below).

### History

The backend used to have a single dispatch. #22028 bound `self.flash_attn_*` in `__init__` and aliased them at the top of each forward. Four days later, #20796 replaced those aliases with the module-level wrapper plus `ver=`, so it could route FA3 through the kernels-community loader. That left the `__init__` binding unused. #32991 added the SM12x choice to that binding, and #33007 reconnected one call site. #33426 unified the dispatch again, but it was reverted in #39405 for process reasons (merged before review and CI completed) and never resubmitted.

## Modifications

<!-- Detail the changes made in this pull request. -->

- Every FA call in `flashattention_backend.py` goes through `self.flash_attn_*`. The per-call `ver=` and the module-level wrapper import are removed.
- For FA3, `__init__` now binds `sglang.kernels.ops.attention.flash_attention_v3`, which is the build the wrapper already dispatched to for `ver=3`. `fa_skip_kv_cache` on FA3 used to call `sgl_kernel.flash_attn` directly; it now follows `SGLANG_USE_SGL_FA3_KERNEL` like every other path. The default (`1`) still loads the `sgl_kernel` build. `get_scheduler_metadata` still comes from `sgl_kernel`.
- `flash_attention_v4_sm120.flash_attn_varlen_func` / `flash_attn_with_kvcache` accept and forward `mask_mod`. Previously their `**_` swallowed it, which would drop FA4 image masks on SM12x now that those paths route there. A call with `mask_mod` skips the cached paged-decode fast path.
- New `test_flashattention_kernel_dispatch.py`, a CPU test: it fails if any FA call in the backend uses a name other than `self.flash_attn_*`. Verified to fail on `main` and pass here.

Behavior by configuration:

| Configuration | Before | After |
|---|---|---|
| FA3 | wrapper(`ver=3`) -> `flash_attention_v3`; `fa_skip` -> `sgl_kernel.flash_attn` | `flash_attention_v3` everywhere (same kernel by default) |
| FA4, not SM12x | wrapper(`ver=4`) -> `flash_attention_v4`; `fa_skip` -> `flash_attention_v4` | `flash_attention_v4` everywhere; kwargs the wrapper filtered out land in its `**_` |
| FA4, SM12x | 14 sites -> generic `flash_attention_v4`; `fa_skip` -> `flash_attention_v4_sm120` | `flash_attention_v4_sm120` everywhere, with `max_seqlen_k` and `mask_mod` reaching it |

Out of scope: `dots_hybrid_backend.py` and `minicpm/attention_adapter.py` still call the module-level wrapper with their FA backend's `fa_impl_ver`.
