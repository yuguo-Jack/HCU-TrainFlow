# fix: recover templated path for FastAPI >=0.137 included routers in the Prometheus middleware

[Upstream PR](https://github.com/sgl-project/sglang/pull/28890) · state: closed · merged: False

## Original PR description

## Motivation

FastAPI 0.137 ([fastapi#15745](https://github.com/fastapi/fastapi/pull/15745)) changed `include_router()`: child routes are no longer flattened into `app.routes`; they become `_IncludedRouter` wrapper objects that can match a request but expose no `.path`. The Prometheus HTTP middleware's `_get_fastapi_request_path()` iterates `app.routes` and unconditionally reads `route.path` on a full match, so any request to an included route raises `AttributeError: '_IncludedRouter' object has no attribute 'path'`, which Starlette surfaces as **HTTP 500**. SGLang registers its endpoints via `include_router`, so every API endpoint fails under FastAPI >=0.137. Fixes #28887.

## Modifications

- `_get_fastapi_request_path()` now guards the `.path` access and, when the matching route is an included-router wrapper (no `.path`), descends into the wrapped router's routes (`original_router.routes`, or a generic `.routes`) to recover the templated path. It still falls back to the raw URL path when nothing resolves, so it never raises.
- Added a unit test in `test/registered/unit/utils/test_common.py` covering the included-router path and the unmatched-path fallback.

## Accuracy Tests

No model/output change -- this only fixes route-path resolution for the metric label. Verified against FastAPI 0.138 / Starlette 1.3: pre-fix the FULL-matching route is an `_IncludedRouter` and `route.path` raises; post-fix the templated path (`/v1/chat/completions`) is recovered, a normal route (`/docs`) is unchanged, and an unmatched path falls back to the raw URL.
