# [Fix] Unpack KDA prefill output regardless of state tracking

[Upstream PR](https://github.com/sgl-project/sglang/pull/41122) · state: closed · merged: False

## Original PR description

## Motivation

Untracked KDA prefill forwards `(output, h)` from FlashKDA or CuTe DSL to callers expecting a tensor, causing failures such as `AttributeError: 'tuple' object has no attribute 'shape'` in gated normalization.

Related: #39925, #39926, #40124. The existing FlashKDA PRs fix the producer return contract; this alternative normalizes both supported return forms at the shared caller and also covers CuTe DSL.

## Modifications

Unpack tuple results immediately after dispatcher.extend(), regardless of state tracking. For a bare tensor, set h=None. Continue consuming h only on the existing tracking path.

## Accuracy Tests

- Isolated execution of the actual forward_extend caller tail: five cases covering bare output, tuples with None or intermediate states, and tracking on/off. Confirmed the original untracked tuple leak, corrected tensor output, and unchanged forwarding of intermediate states to tracking.
- Repository pre-commit checks and `git diff --check` passed. The branch-name guard was excluded.
- No PyTorch, Triton, or GPU is available in this checkout, so full kernel/model tests were not run here. Isolated checks are not committed CI tests.
- Reporter-provided combined validation with this and the separate safe-gate dispatch fix (#41121): Kimi-K3 with FlashKDA prefill and FlashInfer decode, 356-token health-check prefill HTTP 200, 120-token generation completed, zero tracebacks. This is functional validation, not an accuracy benchmark.
