# [Perf] diffusion: Validate breakable CUDA graphs for LTX-2.5 two-stage serving

[Upstream PR](https://github.com/sgl-project/sglang/pull/46239) · state: closed · merged: True

## Original PR description

## Motivation

LTX-2.5's default (distilled) path is unguided, so its stage-1 forward over 8,160 video tokens per step is short and launch-bound. On 4xB300 at 1920x1088 with Ulysses 2, a stage-1 step took 0.244 s of wall time against ~0.15 s of GPU kernel time (torch.profiler, ~8,000 kernels per step). Breakable CUDA graphs remove that host time. `LTX2TwoStagePipeline` already turns them on by default for LTX-2 and LTX-2.3 (#45977), but LTX-2.5 was not on the validated list, so it ran eager unless `--enable-breakable-cuda-graph true` was passed, and then with a "not validated" warning.

## Modifications

- `server_args.py`: `Lightricks/LTX-2.5-Diffusers` joins `BREAKABLE_CUDA_GRAPH_SUPPORTED_MODEL_IDS`. The existing default gates are unchanged: `LTX2TwoStagePipeline`, server warmup, >= 130 GiB cards, resident DiTs, no compile, LoRA, batching or offload.

- `docs/cookbook/diffusion/LTX/LTX2.5.mdx`: the default and the warmup flags for the served shape.

Tests:
- `test_server_args.py`, `test_ltx25_distilled_two_stage_serving_turns_bcg_on` (with the existing `TestBreakableCudaGraphDefault` cases: 6 passed).

## Accuracy Tests

4xB300, LTX-2.5 two-stage at 1920x1088, 121 frames, `--num-gpus 2 --ulysses-degree 2 --warmup-resolutions 1920x1088 --warmup-num-frames 121`. Warmup captures 289 segments per stage shape, and the four requests' MP4s are byte-identical to eager (same md5 for every prompt and seed).

## Speed Tests and Profiling

Same setup, synchronized stage timers:

| | eager | BCG |
|---|---|---|
| stage 1 (8 steps) | 1.95 s (0.244 s/step) | 1.26 s (0.151 s/step) |
| stage 2 step | 0.674 s | 0.630 s |
| request (client) | 7.07-8.05 s | 6.39-6.51 s |

As for LTX-2/2.3, graphs are captured per shape at warmup, so serving another shape needs `--warmup-resolutions` / `--warmup-num-frames` for it; the LTX-2.5 cookbook now says so.
