# [Perf] diffusion: Patchify Wan latents straight into tokens

[Upstream PR](https://github.com/sgl-project/sglang/pull/46148) · state: closed · merged: True

## Original PR description

Branch: mick/wan-patch-embed-tokens (on main efd2ce8a9d), commit 949d3c9cd6

## Motivation

Wan's `PatchEmbed` is built with `flatten=False`. Its 5D fast path computes the patchify GEMM token-major (`[B, T'H'W', C]`), then writes it out channel-first (`.permute(0, 4, 1, 2, 3).contiguous()`), and `WanTransformer3DModel.forward` immediately transposes it back with `.flatten(2).transpose(1, 2).contiguous()`. At 720p (75600 tokens x 5120) that is two 774 MB copies per forward on every rank, 1.5-2.5 ms each on B300 (`aten::contiguous` on `[1, 5120, 21, 45, 80]` and on `[1, 75600, 5120]` in the profile): 3.3-5 ms per denoising step.

## Modifications

- `layers/visual_embedding.py`: `PatchEmbed.forward(x, tokens=False)`; `tokens=True` returns `[B, T'H'W', C]` whatever `flatten` says (the Conv3d fallback for indivisible grids flattens as before).
- `models/dits/wanvideo.py`: the forward asks for tokens. Subclasses that read the 5D output (Wan-Animate, LingBot) are untouched.

The values are the same, so the output is bit-identical.

## Accuracy Tests

`test_patch_embed_tokens.py`: `tokens=True` equals the flattened channel-first output bitwise for a divisible grid (patchify GEMM) and an indivisible one (Conv3d fallback). The transformer sees the same tensor, minus two copies.

## Speed Tests and Profiling

Wan2.2 T2V A14B 720p, 4xB300: the two copies leave the step profile (3.3-5 ms per step). Measured together with "Run the Wan VAE fast path under spatial-parallel decode" (two interleaved rounds, fresh servers, 3 requests each): 91.27 -> 91.03 s median; the decode change alone accounts for ~0.27 s of decode time, so this one is within noise e2e at this resolution.
