# [Fix] unified_cache: Agree on external LOAD construction outcomes across ranks

[Upstream PR](https://github.com/sgl-project/sglang/pull/47044) · state: open · merged: False

## Original PR description

## Motivation

`UnifiedCacheLinkerWrapper.load_back` builds destination transfers locally before queueing a load. If one rank receives `None` or raises during construction, it can leave the construction path while peers queue the load and prepare their buffers. An exception can also leak transfers already built for earlier components.

This is **SG04** in #47031: a focused construction/rollback fix on upstream `c6c7533957ab0abac373dd772c085289ca282200`, independent of page-wise loading, PP hit-boundary policy, prefetch and new Mooncake APIs.

## Modifications

- Collect each rank's construction outcome and MIN-reduce it through the existing attention-cache groups before queueing or PREPARE.
- If any rank cannot construct the full component set, ABORT locally built transfers on all participating ranks. Preserve the originating construction exception after rollback; healthy peers follow the existing zero-loaded fallback.
- Roll back local transfers when the verdict collective itself fails.
- Add real two-process Gloo regressions for one-rank `None`, `RuntimeError`, and `KeyboardInterrupt`, plus successful construction, local collective failure, and rollback-error precedence.

Adapted from our downstream commit `b2fffa638a` (lihenga); the scope here is LOAD construction only.
