# [Perf] diffusion/qwen-image-2.1: Keep an image prefix's K/V in the packed buffer across steps

[Upstream PR](https://github.com/sgl-project/sglang/pull/46101) · state: closed · merged: True

## Original PR description

## Motivation

Qwen-Image-2.1 computes the prompt prefix (text, and for edits the reference image tokens) once per request and caches its per-layer K/V. Every cached denoising step still rebuilds the attention input from scratch: the packed projection allocates a fresh `[P+S, 3C]` QKV buffer per layer, and the fused Q/K RMSNorm + RoPE + pack kernel copies the cached prefix K/V into its first `P` rows before attention.

For text-to-image the prefix is a few dozen rows and the copy is free. For an edit the reference image makes the prefix about as long as the target (1248x864 reference: 4212 image rows plus text, against 4096 target rows), so the copy doubles the kernel's memory traffic in every layer of every step. On 1xH200 the kernel takes 164 us per call in an edit request against 95 us in a text-to-image request (grid capped at 65535 instead of 32984 blocks): about 88 ms per 40-step request across 32 layers.

## Modifications

`models/dits/qwen_image21.py`, `QwenImage21Attention`:
- After an image-conditioned prefill on the packed path, the request's per-layer cache keeps the packed buffer (`cache["qkv"]`), and its `key`/`value` become views of that buffer's prefix rows, so the separate prefix tensors are freed.
- Cached steps project into the kept buffer (the GEMM writes rows `[P:]` exactly as before) and call the same CUDA kernel with an empty prefix on the target rows, so it normalizes and rotates Q and the target K in place and copies nothing. Attention reads the full buffer.
- Text-only prefixes keep today's compact copy. The kept path needs the packed projection and a verified CUDA pack kernel, single sample, no SP, and no BCG prefix padding; anything else runs as before.

The attention inputs are the same values in the same layout, so outputs are bitwise unchanged. Memory: an edit request holds `[P+S, 3C]` bf16 per layer instead of the `[P, 2C]` prefix plus one transient buffer, about 3.1 GB more at the 1024x1024 edit shape.

Tests (`test_qwen_image21_cuda.py`, CUDA):
- `test_cached_steps_copy_the_prefix_only_for_text`: records every pack-kernel call over a prefill and two cached steps. For an image prefix the cached steps pass an empty prefix and write into the buffer kept by the prefill; for a text prefix they copy the prefix as before.
- `test_cuda_qk_rope_pack_matches_eager_prefill_and_cached_steps`: still bitwise against the eager chain on prefill and cached steps and under BCG replay; its storage check now expects an image prefix to live in the kept buffer and a text prefix to stay compact.
