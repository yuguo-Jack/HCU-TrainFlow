# [Fix] diffusion/realtime: Reserve generation slots after initialization

[Upstream PR](https://github.com/sgl-project/sglang/pull/46252) · state: closed · merged: True

## Original PR description

## Motivation

Opening a realtime WebSocket currently reserves the only active generation slot before the client sends `init`. An idle connection, or one that keeps sending invalid initialization messages, can block valid clients indefinitely.

## Modifications

- Reserve the slot only after initialization succeeds. Keep the existing one-session limit, one-second wait, and busy error/close code `1008`.
- Send scheduler cleanup only for sessions that started a generation task. Always dispose local session state and temporary inputs.
- Add a WebSocket-route regression for idle and invalid-init peers, busy rejection, and release ownership. Document the admission behavior.

The production change stays in one existing file. No new setting, queue, or multi-session generation support.

## Validation

- Remote realtime suite: **154 passed**. Both new regression cases fail on the pre-fix code (**2 failed, 152 passed**).
- Paired **1x H200, SANA-WM Stage1** runs: 256x256, four denoising steps, seed 42, two chunks. An idle/invalid-init peer blocks generation before the fix and no longer blocks it afterward. A genuinely active peer is still rejected with `1008`; generation succeeds again after a disconnect.
- Successful requests produce identical raw-frame payload SHA256 hashes to the baseline. All five generated sessions on the fixed version are released; idle/rejected connections send no release RPC, and no input temporary directories remain.

This is a lifecycle regression check, not a throughput benchmark, full-pipeline quality evaluation, or long-duration HA certification. Initialization still stages inputs before admission; connection quotas and initialization deadlines are outside this change.
