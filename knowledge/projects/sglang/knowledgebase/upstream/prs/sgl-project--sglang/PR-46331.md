# [Fix] mla: Preserve request boundaries in ragged draft extend

[Upstream PR](https://github.com/sgl-project/sglang/pull/46331) · state: open · merged: False

## Original PR description

Fix request boundaries in `trtllm_mla` and `cutedsl_mla` draft extend. A ragged batch such as `[1, 3]` was incorrectly reshaped to `[2, 2]`, assigning queries to the wrong request and causal window.

Use cached length aggregates to detect uniform batches in constant time; otherwise pad/unpad using cached metadata. Keep reusable query-buffer views contiguous after graph setup, and preserve the actual captured query width during ordinary and DCP replay, including multilayer EAGLE front tokens.

### Validation

- Prior GPU validation: **22 GB300 comparisons passed** against float32 causal attention across both backends, prefill, ragged/uniform drafts, and graph replay/buffer reuse. For `[1, 3]`, maximum absolute error fell from **2.545** (or **3.299** after graph setup) to **0.00764**.
- CPU regressions cover six layouts with/without reusable buffers and widened ordinary/DCP graph windows: **2 tests and 14 subtests**, rerun after consolidating query-shape setup and refreshing upstream.
- GPU results used FlashInfer 0.7.2, CuTe DSL 4.8, and PyTorch 2.11/CUDA 13.2. Full-model accuracy and throughput were not measured.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Avoid rescanning requests in every MLA layer**

When `DRAFT_EXTEND_V2` runs eagerly (for example with CUDA graphs disabled or after missing a captured shape), `forward_extend` is called once per MLA layer, and the common uniform-length case makes this generator traverse the entire host list every time. At the backend's supported 8,192-request limit, a deep model therefore performs hundreds of thousands of redundant Python comparisons per speculative iteration even though `init_forward_metadata` already processes these lengths once per batch; cache the uniformity decision in the metadata (or derive it from cached aggregates) to avoid regressing eager draft latency.

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Preserve uniform widened CUDA-graph draft windows**

When the boundary-KV fix widens a multi-layer EAGLE draft window, the capture runner sets `captured_req_width = speculative_num_draft_tokens + num_front_tokens` (`multi_layer_eagle_draft_extend_cuda_graph_runner.py:196-204`), but `_init_cuda_graph_metadata` still records `sum_seq_lens_q`, `max_seq_len_q`, and the indptr using only `self.num_draft_tokens` (`trtllm_mla_backend.py:562-575`). This equality therefore rejects an actually uniform captured batch and enters the ragged path with too-short metadata; requests after the first read query rows at the wrong packed offsets and the widened front rows are omitted or left stale, silently corrupting multi-layer hybrid speculative output whenever its draft-extend CUDA graph uses this backend. Build the graph metadata from the captured `num_tokens // bs` width, or otherwise retain the direct-view path for widened uniform captures.
