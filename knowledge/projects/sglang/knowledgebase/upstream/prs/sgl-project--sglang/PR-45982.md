# [Feat] benchmark: Add --input-len-list to bench_one_batch_server for per-request input lengths

[Upstream PR](https://github.com/sgl-project/sglang/pull/45982) · state: closed · merged: True

## Original PR description

## Motivation

`bench_one_batch_server` gives every request in a batch the same `--input-len`, so a decode step can only be measured over uniform contexts. Serving traffic is rarely uniform: a decode batch mixes short and long contexts, and the attention cost of that step is not the cost of the same token total spread evenly across the batch. There is currently no way to build such a ragged batch from the random datasets.

## Modifications

- New `--input-len-list` flag: a comma-separated list of positive per-request input lengths for the `random` and `random-ids` datasets. Request `i` of a batch gets entry `i` modulo the list length, so `--input-len-list 128,4096 --batch-size 4` builds a batch with 128, 4096, 128 and 4096 input tokens.
- In `run_one_case`, the generated prompt token lists are cycled to the requested per-request length, and the reported `input_len` becomes the batch's mean.
- `should_skip_due_to_token_capacity` sums the per-request lengths when the list is set instead of multiplying one length by the batch size; the skip message prints the resident token total. The new parameter is positional-last with an empty-string default, so existing callers and the default path are unchanged.
- The flag is validated before any request is sent: entries must be positive integers, and it requires a single `--input-len` value, no `--fixed-prompt-file` and the `random` / `random-ids` dataset. Without the flag, behaviour is identical to today.

## Tests

- `pre-commit` passes on the changed file (isort, ruff, ruff-format, codespell, ast).
- A throwaway check of the new helpers passes: `"128, 4096,  32"` parses to `[128, 4096, 32]`; empty, zero, negative, non-numeric and float entries raise `ValueError`; `--input-len-list 128,4096` cycled over a batch of 5 gives `[128, 4096, 128, 4096, 128]`; the capacity skip still triggers at `batch_size * (input_len + output_len)` without the list and at `sum(per-request lengths) + batch_size * output_len` with it; the prompt-cycling expression turns `[1, 2, 3]` into `[1, 2, 3, 1, 2]` for a requested length of 5.

Not run here: a GPU end-to-end pass. To verify against any served model, with the default single `--input-len`:

```bash
python -m sglang.benchmark.one_batch_server --base-url http://127.0.0.1:30000 \
    --model-path <served model> --dataset-name random \
    --batch-size 4 --output-len 32 --input-len-list 128,4096
```

The 4-request case should report `input_len=2112` (the batch mean of 128, 4096, 128, 4096), and the same command without `--input-len-list` should behave exactly as before.
