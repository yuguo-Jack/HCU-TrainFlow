# [Perf] [NPU] dsv4: Reuse CPU query lengths for prefill metadata

[Upstream PR](https://github.com/sgl-project/sglang/pull/47663) · state: open · merged: False

## Original PR description

## Motivation

DeepSeek-V4 prefill builds `actual_seq_lengths_q_pa_cpu` from the current batch's host query lengths. The NPU compression metadata path then reads the same cumulative lengths back with `cu.cpu().tolist()`, adding a redundant device-to-host copy and stream wait.

## Changes

Read the existing CPU mirror in `_build_npu_compress_metadata_prefill` and update the comments. The mirror is rebuilt before this call on each prefill initialization. Decode and speculative metadata paths are unchanged.

## Validation

CPU and Ascend NPU: 168 prefill cases match before/after, plus four non-prefill mode controls. The harness runs the actual initialization and prefill methods with scaffolding for the parent metadata and unrelated kernels. Compressed positions are also checked against an independent oracle.

On NPU, counted `Tensor.cpu()` device-to-host calls within the tested methods drop from 168 to 0. No model-level latency or throughput claim.

Formatting and lint checks passed. Two hooks using `python3` could not start on Windows; both scripts passed when run with the available Python executable.

[Reproduction script, frozen sources and raw results](https://github.com/AkiYangDev/sglang/tree/c14954c62ff4633c44d8495b6b4d31b2a07ed9f9) are on a separate evidence branch. No test files are added to this PR.
