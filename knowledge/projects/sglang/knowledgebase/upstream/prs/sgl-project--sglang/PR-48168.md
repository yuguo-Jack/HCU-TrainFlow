## Original PR description

# [Test] [NPU] rl: Add sleep/wake scheduler unit and 1-NPU smoke tests

Per the RL Test Consolidation RFC (#47624), this PR lands the first feature area (sleep/wake) of the NPU-side test consolidation: file ownership, coverage docstrings, and CI integration for Ascend.

**Precision scope: BF16 only.** Per the RFC's BF16 precision target, all cases in this PR plan and assert BF16 only (other dtypes — FP16/FP32/INT8/W8A8 — are explicitly out of scope for this round). The 1-NPU smoke launches the server with an explicit `--dtype bfloat16` (never dtype-inferred) and asserts the effective dtype via `/server_info` (`dtype == "bfloat16"` + the flag pinned in `launch_command`) before any scenario assertion, so all bitwise determinism anchors validate the BF16 numerics path specifically. The unit tier is dtype-agnostic (mocked devices) and inherits the contract from its smoke sibling.

## What's here

**1. `test/registered/unit/managers/test_scheduler_memory_release.py`** (new, CPU tier)

Pins the `release_memory_occupation` / `resume_memory_occupation` state-machine contracts (`SchedulerWeightUpdaterManager`):

- release asserts a fully idle engine; an `engine_paused` release passes with `ignore_waiting=True`
- default tags pause all memory types in the fixed order `kv_cache -> weights -> cuda_graph`; the request-side tag order is normalized
- the device is synchronized during release (a strict synchronize-BEFORE-first-pause ordering assertion is included commented-out, to be enabled together with the pending Ascend SDMA-race fix)
- `kv_cache` release flushes the cache exactly once; weights release does not
- release is idempotent; unknown tags are silently tracked today (pinned deliberately — the RFC proposes strict rejection)
- resume is not idempotent: unknown tag raises `KeyError`; weights resume without the release-time stash raises `AttributeError`; the happy path imports the stash and clears it

**2. `test/registered/npu/rl/test_npu_release_resume_memory.py`** (new, 1-NPU tier)

- **S0 BF16 precision contract**: both instances launch with `--dtype bfloat16`; `/server_info` must echo `dtype == "bfloat16"` with the flag pinned in `launch_command` (weights + KV cache follow the model dtype on the ascend attention backend)
- KV-only sleep roundtrip keeps greedy outputs bit-identical (under BF16)
- full cycle with device-memory evidence logging (on current CANN/TMS the TMS pause does not return pages to the device-level pool, so the watermark is informational, not an assertion) + the RL standard chain `release(all) -> resume(all) -> update_weights_from_disk -> /health_generate`
- level-1 equivalence: with `--enable-weights-cpu-backup`, `release(all) -> resume(all)` without any update restores outputs bitwise (regression probe for the sleep-pollution class of bugs)
- `cuda_graph` tag contract: accepted, documented as a release no-op on NPU today

Both files carry coverage docstrings (behaviors, APIs, NPU-specific risks, sibling CUDA tests) per the RFC.

## CI registration

- unit file: `register_cpu_ci(est_time=8, suite="base-a-test-cpu")`
- NPU file: `register_npu_ci(est_time=1800, suite="nightly-npu-a3-merged", nightly=True)`

## Validation

Validated on Ascend 910 (openEuler 22.03, CANN 9.1.0, torch 2.10 + torch_npu, Qwen3-0.6B, TP=1, `--dtype bfloat16`):
- unit: 11 passed
- 1-NPU smoke: 2 passed (BF16 contract asserted on both instances; KV-only roundtrip clean; level-1 cpu-backup restore bitwise-identical; full RL chain serves after update)

Environment knobs: `RL_FEAT_MODEL_PATH` (model override, defaults to `LLAMA_3_2_1B_INSTRUCT_WEIGHTS_PATH`) and `RL_FEAT_NPU_ID` (die selection, default "0").

Related: #47624 (tracks the remaining feature areas: pause/resume, weight update + metrics, weight checker, routed experts, response schema, CPU lifecycle-state, weight telemetry)
