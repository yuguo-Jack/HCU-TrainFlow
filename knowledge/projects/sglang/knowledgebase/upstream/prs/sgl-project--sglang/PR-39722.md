## Motivation
Adds Qwen2MoeSparseMoeBlock.forward_cp for callers that hold a row-sharded hidden state: gate and top-k run on the local rows, then the rows and their top-k ids/weights are all-gathered together so the TP-sharded experts still see every token, and the partial sum is reduce-scattered back to the local rows. Same bytes on the wire as the all-reduce of the TP path, plus 80 B per token for the top-k payload.

The two collectives are injected as callables, so this carries no dependency on any particular CP layout.

Routing uses the fused topk_softmax + build_precomputed_topk_output rather than a second TopK module: the Triton router costs ~0.2 ms of host time per layer, which is +10 ms on a 4K forward. That yields the STANDARD top-k format, so the FlashInfer TRT-LLM runner picks its routed kernels from the top-k format instead of asserting BYPASSED -- switching the model to flashinfer_trtllm_routed instead would also change the TP path's routing numerics.

Measured per MoE layer on 4x B200: gate GEMM 70 -> 11 us, routing 51 -> 17 us (~4.5 ms per 32K forward), all-gather launch count unchanged.
