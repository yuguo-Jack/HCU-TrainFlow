# [Fix] imports: Bind FlashInfer lazily at four import sites so the server starts without it

[Upstream PR](https://github.com/sgl-project/sglang/pull/44430) · state: closed · merged: True

## Original PR description

## Motivation

Four modules import FlashInfer at module level behind `is_cuda()` alone: `layers/sampler.py`, `speculative/dflash_utils.py`, `layers/quantization/fp8_utils.py` and `layers/attention/vision.py`. Importing `sglang.srt.entrypoints.http_server` reaches all four, so a CUDA environment without FlashInfer fails at import time before any backend is chosen:

```
File ".../sglang/srt/layers/quantization/fp8_utils.py", line 255, in <module>
    from flashinfer import bmm_fp8 as _raw_bmm_fp8_batched
ModuleNotFoundError: No module named 'flashinfer'
```

Every other FlashInfer-dependent path is already selected at runtime (attention backend, sampling backend, the per-tensor fp8 helper guarded by `is_flashinfer_available()`); these four were the remaining hard import-time dependencies.

## Modifications

- Replace the four eager imports with `LazyImport` from `sglang.utils`, which resolves the attribute on first call. With FlashInfer installed the bound names resolve to the same objects (checked with `is` for all six names), so behaviour is unchanged. Without it the server imports and starts, the sampling backend defaults to `pytorch` as it already does when FlashInfer is absent, and a path that really needs FlashInfer still raises `ModuleNotFoundError` at the call instead of at import.
- Add `test/registered/unit/test_import_without_flashinfer.py` (base-b, 1-gpu-small): imports the HTTP entrypoint in a subprocess with `flashinfer` blocked in `sys.modules`. It fails on current main at the `fp8_utils` import and passes with this change.

## Accuracy Tests

Not applicable: no numerics change. The lazily bound names are the same FlashInfer functions once resolved.

## Speed Tests and Profiling

Not applicable: `LazyImport.__call__` adds one attribute lookup per call after the first resolution; the four names are called from already Python-dispatched paths.
