# [CI] python: Move the remaining CUDA build paths off Python 3.10

[Upstream PR](https://github.com/sgl-project/sglang/pull/44393) · state: open · merged: False

## Original PR description

## Motivation

#43021 raised sglang to Python >=3.11 but left the CUDA `sglang-kernel` wheel (`cp310-abi3`) and several CI and release jobs on 3.10. This PR moves the remaining CUDA and hardware-neutral paths off 3.10. Other hardware platforms are out of scope.

## Modifications

- **`sglang-kernel` (CUDA):** `requires-python >=3.11` and `wheel.py-api = "cp311"`, so the wheel is `cp311-abi3`. The PR build, release build and build Dockerfile use Python 3.11. The artifact `wheel-python3.10-cuda*` is renamed `wheel-python3.11-cuda*` in every consumer, and `ci_install_dependency.sh` matches `cp311-abi3`.
- **ROCm kernel wheels stay `cp310-abi3`:** `build_rocm.sh` builds from the CUDA `pyproject.toml`, so it now sets `>=3.10` / `cp310` back before building (the result is byte-identical to main), then runs `pip install --dry-run` on the image's Python so an uninstallable wheel fails the job.
- **cuda-tile:** the `==1.6.0rc5` pin from #34321 (rc6 lacked cp310 wheels) is dropped. rc5 is a stub sdist that downloads its wheel at install time; 1.6.0 ships real wheels for cp310–cp314, and `flashinfer-python==0.7.1` now resolves to it.
- **DeepEP:** release matrix and `build_sgl_deepep.sh` drop 3.10.
- **Workflows on 3.12:** coverage, multimodal-gen, diffusion GT gen, release-pypi index steps, bot-bump, runner utilization, slash commands, est-time update. The bot-bump jobs no longer install `tomli`; the release scripts import `tomllib` directly.

**Unchanged:** ROCm, MUSA, NPU, XPU and MLU, `pyproject_other.toml`, and the shared runtime's 3.10 compatibility code, since those platforms still install sglang on 3.10.

**Notes:** the first kernel build starts with a cold buildx cache (the cache tag includes the Python tag). `diffusion-ci-gt-gen`'s `kernel_wheel_run_id` only accepts runs made after this change.

## Verification

- scikit-build-core 1.1.1: `py-api cp311` gives `cp311-abi3` on 3.11/3.12 and silently falls back to `cp310-cp310` on 3.10, which the CI install's `cp311-abi3` match catches.
- The `pip --dry-run` check rejects both bad ROCm wheels on 3.10 and accepts `cp310-abi3` on 3.10 and 3.12.
- pre-commit, `bash -n`, YAML load, and `scripts/release/test_utils.py` (14 passed) all pass.
- Not run: a full CUDA or ROCm kernel build. Run `release-whl-kernel.yml` with `target: rocm720` for ROCm; this PR's CI covers CUDA.

No model forward or kernel source changes.
