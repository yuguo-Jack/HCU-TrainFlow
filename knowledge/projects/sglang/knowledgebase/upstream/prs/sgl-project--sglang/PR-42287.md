# [Refactor][TCPCG] Retire backend selection and configuration (3/9)

[Upstream PR](https://github.com/sgl-project/sglang/pull/42287) · state: closed · merged: True

## Original PR description

This is **step 3/9**, split from [the original TCPCG removal PR #41634](https://github.com/sgl-project/sglang/pull/41634).

**Steps 1/9 (#42285) and 2/9 (#42286) are merged.** This branch includes upstream main through `1638c5d699` via a normal merge. The Files changed tab now shows only step 3; the merged scoped forward-batch API and argument-free BCG replay are preserved.

Retire TCPCG as a selectable graph backend while retaining the internal context and compatibility needed by BCG callers that later steps will migrate. Explicit `tc_piecewise` and `tc_compiler` configuration now raises an error instead of selecting the legacy backend. CUDA keeps BCG as its default prefill graph backend; other platforms default to disabled prefill graphs rather than TCPCG.

## Series

1. Relocate shared graph tensor and DSA head-gate helpers — #42285.
2. Add scoped forward-batch access and bare eager decorators — #42286 (merged).
3. **Retire TCPCG backend selection, configuration, documentation, and tests — this PR.**
4. Consolidate Radix attention eager regions and isolate Inkling-specific behavior, including the dependent MLA wrapper migration.
5. Migrate DSA and DeepSeek eager regions to explicit methods.
6. Migrate MoE and Mamba eager regions.
7. Migrate diffusion eager wrappers and standardize their names. This step depends only on step 2.
8. Remove obsolete runtime contexts, layer registries, split-op plumbing, and temporary compatibility after caller migration.
9. Simplify quantization paths separately because of their torch.compile implications.

All nine steps have been submitted (#42285–#42293); later steps still need synchronization with the merged predecessors. The disputed relocation of inactive compiler/reference files is excluded pending a separate decision.

## Changes

- Remove TCPCG from selectable backends, convenience configuration, backend dispatch, and automatic fallback selection.
- Reject the removed backend/compiler settings and update supported-backend/default tests.
- Remove the HIP TCPCG eager-fallback wrapper and update failure hints.
- Delete the TCPCG documentation page and navigation entries; update relevant examples and platform documentation.
- Remove TCPCG-specific tests and adjust server-argument expectations.

The legacy `Backend.TC_PIECEWISE` constant and internal `PhaseConfig.tc_compiler` field temporarily remain for references in unmigrated code, but parsers no longer accept these settings. Existing runtime context and layer registries remain until the caller migrations are complete. This step preserves the torch.compile framework.

## Validation

- Pre-commit passed on the changed files.
- Seven CPU configuration tests passed through the CI-style script entry point (`-f`), using the macOS import shim.
- CI collection with sanity checking passed for all 2,237 registered test files (2,728 registrations).
- Resolved conflicts with current platform/configuration changes; removed the now-obsolete, already-disabled TCPCG-only XPU test. Kept the temporary `PhaseConfig` field order compatible.
- Full main CI, accelerator execution, and end-to-end model correctness at this intermediate step remain to be validated. The local checks do not establish those results.
