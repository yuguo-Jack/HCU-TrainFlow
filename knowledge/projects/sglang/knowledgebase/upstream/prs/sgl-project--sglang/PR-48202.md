# [Refactor] dwdp: Route DWDP through a device-neutral VMM backend

[Upstream PR](https://github.com/sgl-project/sglang/pull/48202) · state: open · merged: False

## Original PR description

## Motivation

DWDP calls `cuda.bindings` and `torch.cuda` directly, so only CUDA can run it. This puts the driver calls behind one VMM backend interface, with no CUDA behavior change. Split out of #40763; the Intel XPU backend follows in a separate PR on top of this one.

## Modifications

- `utils/vmm_backend.py`: `VmmBackend` + `CudaVmmBackend`. `get_vmm_backend()` takes the class from `DeviceMixin.get_vmm_backend_class()` (default `None`, CUDA returns `CudaVmmBackend`), so a platform adds DWDP support by returning its own.
- `layers/moe/dwdp/*`: use the backend and device-neutral streams/events. A backend that cannot alias pages gets a remap path with one extra slot; CUDA keeps two slots and no remap.
- Startup peer-access check; peer-import failure is agreed across ranks, so one failing rank cannot hang the others.
- `utils/common.py`: `Reservation`, `align_up/down`, `all_ranks_ok`, fd exchange move out of `cuda_vmm_utils` (re-imported there, callers unchanged).
- `parallel_hook.py`: DWDP turns shared-expert fusion off and rejects `--enforce-shared-experts-fusion`.
- Tests: `test_vmm_backend.py` (2 GPU), `test_dwdp_weight_prefetch.py` (2/4 GPU, also with aliasing off), CPU tests for layout and backend dispatch.
