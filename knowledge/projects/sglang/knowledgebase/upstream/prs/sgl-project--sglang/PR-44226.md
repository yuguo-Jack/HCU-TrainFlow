# [Fix] bench_serving: count input tokens in summary metrics for multi-turn runs

[Upstream PR](https://github.com/sgl-project/sglang/pull/44226) · state: open · merged: False

## Original PR description

## Motivation

In multi-turn benchmarks (`--dataset-name agentic-trace`, or any dataset whose `prompt` is a list of turns), each turn is sent as a separate request, so `calculate_metrics` is called with `input_requests=None`. Input tokens are only added up inside `if input_requests is not None`, so these runs print:

- `Total input tokens: 0` and `Total input text tokens: 0`
- `Input token throughput: 0`
- a `Total token throughput` that leaves out input tokens

The JSONL output has the same zeros in `total_input_tokens`, `input_throughput` and `total_throughput`.

This is the input-token counting part of #30304, submitted on its own. #30304 was closed without being merged. #29215 added the `agentic-trace` loader but did not change this code. #39889 stores the server-reported prompt length in `RequestFuncOutput.prompt_len` (used by `--cache-report` and the JSON `input_lens`), but the summary totals still read `input_requests[i].prompt_len`. So the per-turn prompt length is already available on each output; it just is not added to the total.

`input_lens` in `--output-file --output-details` needs no change: on current main it is `[output.prompt_len for output in outputs]`, which #39889 already fills from `usage.prompt_tokens` / `meta_info.prompt_tokens`.

## Modifications

Only `calculate_metrics` in `python/sglang/benchmark/serving.py` changes. When `input_requests is None`, the `prompt_len` of each successful output is added to `total_input` and `total_input_text`. Vision tokens stay 0. Single-turn runs still use the dataset row, so their numbers do not change. No new flags.

A CPU-only unit test is added at `test/registered/unit/bench/test_bench_serving_multiturn_input_metrics.py` (registered in the `base-a-test-cpu` suite). It calls `calculate_metrics` directly and covers: multi-turn with server usage, failed requests not counted, single-turn totals unchanged, and the fallback when the server returns no usage.

## Limitations

- If the server returns no usage (for example `stream_options.include_usage=false`), each round's `prompt_len` stays at the dataset row value, so the multi-turn total is an estimate, not an exact count. This fallback already exists on main (`--cache-report` sums the same field); this PR does not change it. The unit test documents this behaviour.
- Multi-turn prompts are assumed to be text. If a round contains images, image tokens are counted in `total_input_text` and `total_input_vision` stays 0. `total_input` is still correct.

## Accuracy Tests

Not applicable. This only changes benchmark reporting; no model or kernel code is touched.

## How to test

Run the command below against the same server twice: once on current main and once with this change. `BASE_URL` is an OpenAI-compatible SGLang endpoint, `MODEL` is the served model name, `TOKENIZER` is a local tokenizer or model directory, and `agentic_sample.json` is an agentic-trace file.

```bash
python3 -m sglang.benchmark.serving \
  --backend sglang-oai-chat \
  --base-url "$BASE_URL" \
  --model "$MODEL" \
  --tokenizer "$TOKENIZER" \
  --dataset-name agentic-trace \
  --dataset-path agentic_sample.json \
  --num-prompts 4 \
  --sharegpt-output-len 8 \
  --max-concurrency 1 \
  --request-rate inf \
  --warmup-requests 0 \
  --output-file multi.jsonl
```

On main, `Total input tokens` and `Input token throughput` are 0. With this change, `Total input tokens` equals the sum of `prompt_len` over all successful turns (the server's `usage.prompt_tokens` when it is returned). Output tokens are unchanged. Single-turn runs are also unchanged: a random-dataset run of 10 requests x 128 input tokens reported 1280 both before and after.

## Speed Tests and Profiling

Inference speed is not affected. For multi-turn runs, the reported input and total throughput go up because input tokens are now counted.

Results of the command above on a GLM-5 deployment (4 conversations x 4 turns; it was run through the older `python3 -m sglang.bench_serving` entry point, which forwards to `sglang.benchmark.serving`):

| | before | after |
|---|---:|---:|
| completed requests | 16 | 16 |
| output tokens | 128 | 128 |
| Total input tokens | 0 | 4692 |
| input throughput (tok/s) | 0 | 64.25 |
| total throughput (tok/s) | 1.60 | 66.01 |

As a cross-check, summing `usage.prompt_tokens` from non-streaming requests for the same 16 turns gave 4694. The 2-token difference comes from how the chat template is counted in streaming and non-streaming mode; no turn is missing.
