# [Perf] radix-cache: Preserve long device prefixes during partial eviction

[Upstream PR](https://github.com/sgl-project/sglang/pull/48096) · state: open · merged: False

## Original PR description

## Motivation

A decode allocation sometimes needs only a few pages but evicts a much longer FULL radix leaf. Keeping the reusable prefix can reduce KV eviction on the next turn.

## Modifications

Add the opt-in `SGLANG_PYTHON_RADIX_EVICT_TAIL_CHUNK_SIZE` to the Python unified radix tree. The default is zero. On an eligible device-only FULL leaf, split a page-aligned suffix sufficient for the allocator’s shortfall, preserve prefix recency, and let the normal eviction walk reclaim the suffix. The option is documented in the environment reference.

## Speed Tests and Profiling

On two 910B4 hosts, a full allocator with a 32,768-token leaf and a 1,280-token shortfall freed **32,768 → 4,096** tokens with the option set to 4,096, retaining **28,672** tokens for the next turn. At an 8,192-token shortfall it freed 8,192, and at a 32,768-token shortfall it freed the whole leaf. [Allocator reproducer and byte checks](https://github.com/INBreezefall/sglang/tree/682f1c33931c4b8c0ab11df9d0236d00ff06fcfb/benchmark/ascend_a2_pd_evidence).

In the full replay the two controls evicted **6,367,104 / 6,282,112** D tokens and the two PR runs evicted **4,525,824 / 5,311,232**, a mean reduction of **22.2%**. Mean TTFT was **15.5% lower**. Both P95 TTFTs were higher, both output rates were lower, and both native D decode rates fell inside the control range.

GLM-5.2 W4A8C8 ran on four hosts with eight Ascend 910B4-1 NPUs each, CANN 9.1.0 and torch-npu 2.10.0.post6. P and D each used TP16 and attention DP8. Every arm used SGLang `40a64e1b5ba0` with the same A2 C8 / Mooncake compatibility fixes. Each row contains all 72 responses from the same 24 sessions × three closed-loop turns, after 24 warm-ups. Temperature was 0, output was capped at 256 tokens, and retries were disabled.

Client decode averages valid semantic streaming spans. The PD relay can buffer output. D decode is the inverse of token-weighted server ITL, covering every post-first token interval. Output TPS counts actual output tokens over the formal wall window. The complete comparison allowed 1,200 s for the first token and 300 s between subsequent events. A separate original 300 s control completed 38 of 50 attempted requests before its stop policy withheld 22. [Protocol and anonymized per-request results](https://github.com/INBreezefall/sglang/tree/26bc7bdac9a4158319a7d3d8e3cd10218072bb05/benchmark/ascend_a2_pd_evidence/c24).
