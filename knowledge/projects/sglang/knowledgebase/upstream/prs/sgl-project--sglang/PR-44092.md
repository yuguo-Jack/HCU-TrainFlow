# docs(glm5_next): fix inaccurate NextN WeightsMapper comment

[Upstream PR](https://github.com/sgl-project/sglang/pull/44092) · state: closed · merged: False

## Original PR description

## Motivation

A comment in the GLM-5-Next NextN weight mapper is inaccurate and misleads
readers. `get_hf_to_sglang_mapper` ends with:

```python
# target rules still normalize the non-draft layers and vision tower in `exclude`
return Glm5NextForConditionalGeneration.hf_to_sglang_mapper | WeightsMapper(
    orig_to_new_substr=draft_rules,
)
```

`WeightsMapper` has no `exclude` field — it only has `orig_to_new_substr`,
`orig_to_new_prefix`, and `orig_to_new_suffix`
(`python/sglang/srt/models/utils.py`). There is no "exclude" mechanism involved.

## Modifications

Comment-only change in `python/sglang/srt/models/glm5_next_nextn.py`. Replace the
comment with an accurate description of what the reused target mapper
(`Glm5NextForConditionalGeneration.hf_to_sglang_mapper`) actually does
(`model.language_model.` -> `model.`, `model.visual` -> `visual`,
`.attn.qkv` -> `.attn.qkv_proj`) and that the draft rules are merged on top. No
code behavior change.

Not applicable — comment-only change, no model output or forward-path change.
