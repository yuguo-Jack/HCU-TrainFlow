# [Fix] hicache: Register the whole host-pool allocation with Mooncake

[Upstream PR](https://github.com/sgl-project/sglang/pull/48163) · state: open · merged: False

## Original PR description

## Motivation

Host pools hand out views of a single allocation: MHAHostKVCache exposes k_buffer/v_buffer as kv_buffer[0]/kv_buffer[1], two halves of one mmap. Registration was sized to each view, so the interior view started at a non-hugepage-aligned offset and the first view ended at a length that is not a hugepage multiple. The transfer engine madvise()s the registered range for ibv_reg_mr, and the kernel refuses to split a hugetlb VMA inside a huge page, so registration failed with EINVAL (surfaced to Python as -600).

## Modifications

Register the backing storage's own extent instead of the view: use untyped_storage()'s data_ptr()/nbytes(), the same rule mooncake_direct_linker already follows.

Collapse views of one allocation into a single registration, so a split allocation is registered once rather than per view.

Take the page-rounded mapping length from the allocator via mapped_size_for(), so an alloc_mmap() pool under SGLANG_HUGEPAGE_SIZE is registered whole as well.

alloc_mmap_ex() exposes that mapped length; alloc_mmap() stays as a thin wrapper over it.
