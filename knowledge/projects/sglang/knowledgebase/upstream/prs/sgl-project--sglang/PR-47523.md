# [Perf] RL: Keep the routed-expert host cache only on the output rank

[Upstream PR](https://github.com/sgl-project/sglang/pull/47523) · state: closed · merged: False

## Original PR description

## Why?

With `--enable-return-routed-experts`, every rank keeps a pinned host copy of the routed experts, but only one rank per DP group, the one that talks to the detokenizer, ever sends them out. This is bad for CPU RAM constrained case like GB300.

```text
Before (TP8, no DP attention)                      After (TP8, no DP attention)
rank 0: capture → D2H → host cache → output        rank 0: capture → D2H → host cache → output
rank 1: capture → D2H → host cache   (never sent)  rank 1: capture
  ...                                                ...
rank 7: capture → D2H → host cache   (never sent)  rank 7: capture

Nemotron 3 Ultra, 11.4M-token KV pool, pinned host memory:
        8 × 101 GiB = 808 GiB                      1 × 101 GiB = 101 GiB
```

With DP attention, each DP group has its own output rank, so one cache per group stays:

```text
TP8, --attn-dp-size 2 (attention TP 4 per group), DeepEP

               Before                                         After
group 0  r0:   capture → AG → D2H → host cache → output       capture → AG → D2H → host cache → output
         r1-3: capture → AG → D2H → host cache (never sent)   capture → AG
group 1  r4:   capture → AG → D2H → host cache → output       capture → AG → D2H → host cache → output
         r5-7: capture → AG → D2H → host cache (never sent)   capture → AG

AG = attention-TP all-gather of DeepEP's scattered tokens; r1-3 and r5-7 still join it.
Pinned host caches: 8 → 2, one per DP group.
```
## What?

- Only the output rank of each DP group (`pp_rank == attn_tp_rank == attn_cp_rank == 0`, the scheduler's `is_rank_zero`) allocates the host cache.
- Other ranks still capture on the device (the all-gather needs them) but skip the copy and the readback.

## Verification?

8×H200, `lmsysorg/sglang:dev` (sglang `302b78c`, 2026-10-29) as the base, then the same image plus this PR. Qwen3-30B-A3B-Instruct-2507, 8 prompts with `return_routed_experts` (**observed**):

```text
                                      pinned host caches                     routed experts + text
--tp 8                       before   8 × 7.25 GB = 58 GB  (every rank)
                             after    1 × 7.25 GB          (TP0)             identical, 8/8 prompts
--tp 8 --attn-dp-size 2      before   8 × 7.00 GB = 56 GB  (every rank)
--moe-a2a-backend deepep     after    2 × 7.00 GB = 14 GB  (DP0 TP0, DP1 TP4) identical, 8/8 prompts
```

- The DeepEP run uses the FP8 checkpoint with `--deepep-mode normal`: on this image, BF16 DeepEP supports only low-latency mode, which needs IBGDA that our container lacks.
- The 101 GiB per rank for Nemotron 3 Ultra was **observed** on our internal sglang fork.
