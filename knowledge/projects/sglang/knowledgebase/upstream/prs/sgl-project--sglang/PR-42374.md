# test(multiplex): add CPU unit tests for pdmux context and scheduling mixin

[Upstream PR](https://github.com/sgl-project/sglang/pull/42374) · state: closed · merged: False

## Original PR description

## Motivation

multiplex 模块（单卡 PD 复用调度，#41800 落地）目前没有任何单元测试。本 PR
为其中的纯逻辑补充 CPU 可运行的测试覆盖；CUDA green-context 流的创建本身
仍由集成测试覆盖，不在本 PR 范围内。

## Modifications

- `test_pdmux_context.py`：
  - YAML 配置加载与校验（缺失 / 越界的 `sm_group_num`、`manual_divisions`
    的长度契约、可选字段默认值）
  - 各架构的 SM 分区约束表（`get_arch_constraints`）
  - `divide_sm` 黄金值用例：H100 132 SM 的步长采样、A100 108 SM 的
    stride 选取、候选数不足时全量返回、decode 下限（16 SM）导致的
    无解报错，以及分区不变量（和恒等、prefill≥decode、倍数约束、降序）
  - stream 索引簿记：直接替换模块级全局变量，不创建任何 CUDA 流
- `test_multiplexing_mixin.py`：
  - `adjust_stream_groups` 的选档逻辑：公式路径、`manual_divisions`
    的"取最后匹配档"语义、仅 decode 与全空闲的回退路径
  - `update_split_prefill_batch` 的短路返回与创建路径（含
    `ForwardMode.SPLIT_PREFILL` 标记）

需要向维护者报告的一个行为：`manual_divisions` 路径下，若 `decode_bs`
不匹配任何阈值，`stream_idx` 从未被赋值，函数将抛出
`UnboundLocalError`。测试只钉住有匹配时的"最后匹配档"语义；如果维护者
认为这是缺陷，我可以跟进一个修复（在循环前默认 `stream_idx = 1`）。

## Accuracy Tests

- 共 22 + 7 = 29 个 CPU 测试用例，通过
  `register_cpu_ci(est_time=6, suite="base-a-test-cpu")` 注册，
  无需 GPU。
