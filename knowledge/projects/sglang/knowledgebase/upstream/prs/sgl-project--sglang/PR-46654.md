# [Fix] scheduler: Skip --prefill-decode-interval when nothing is decoding

[Upstream PR](https://github.com/sgl-project/sglang/pull/46654) · state: closed · merged: True

## Original PR description

[by Claude Code]

## Motivation

`--prefill-decode-interval N` holds back the next prefill for N scheduler rounds after each prefill batch, so requests that are already decoding get N decode steps in a row and keep a steady inter-token latency. The counter counts scheduler loop iterations, not decode steps. When no request is decoding, an iteration has nothing to run: it polls for new requests, does idle housekeeping, and goes round again. Chunked prefill splits a long prompt into chunks (8,192 tokens with `--chunked-prefill-size 8192`), and the scheduler treats each chunk as a prefill batch. So a long prompt that reaches an idle server waits through about N empty iterations after every chunk before its next chunk is scheduled, and the GPUs sit idle the whole time. There is no decode to protect, so the wait only delays the prompt.

This PR skips the interval when the running batch is empty or prefill-only (requests that generate no tokens), so the next chunk is scheduled at once. With DP attention the interval is unchanged, because its cadence is synchronized across DP ranks and a peer rank may still be decoding. Whenever a request is decoding, the scheduler behaves exactly as before. What each forward computes does not change in any case; only the time at which the next chunk is admitted moves.

The interval is off by default, but deployments do turn it on: SGLang sets 22 for Qwen3-VL on large Hopper GPUs, and the DeepSeek-V4.1 cookbook's agentic deployments set it as high as 192. At low concurrency, a session's next long prompt often arrives with nothing else decoding. This follows #44001, which added `--prefill-decode-interval-min-bs` to apply the interval only at or above a running-batch size. Setting that flag to 1 avoids this case without DP attention, but it is opt-in and also changes DP behavior. With this PR the idle case is handled at the default `min_bs = 0`, and the flag keeps controlling the small-batch policy.

**Impact**

- **Performance (measured):** DeepSeek-V4.1-Flash, TP4 on 4x B200, `--prefill-decode-interval 96`, `--chunked-prefill-size 8192`. A 122,880-token prompt (15 chunks) with nothing cached on an otherwise idle server: TTFT **2.546 s → 1.187 s (−53%)**, 6 runs per arm (ranges 2.516-2.577 s and 1.182-1.205 s). That is 170 → 79 ms per chunk. Before, a GPU trace shows 14 idle gaps of 97-107 ms between the chunks on every TP rank; after, no gap over 10 ms on any rank.
- **The wait scales with N:** at `--prefill-decode-interval 192` the same prompt takes 3.858 s on main (3 runs, 3.831-3.895 s), with 14 gaps of 196-211 ms. With this PR the interval is not consulted while nothing decodes, so N should not matter here (expected ~1.19 s; this PR was measured at 96 only).
- **Decode always running (concurrency 16):** no difference beyond run-to-run noise. Pooled over 5 runs per arm: output throughput +0.6%, median ITL +0.1%. In every run the server logged the same number of prefill batches in both arms, and only the run's first batch (and the benchmark's warm-up request) was admitted with nothing decoding.
- **Accuracy:** unchanged by construction: the change only decides when the next prefill batch is admitted. Unit tests below.

## Modifications

**+7 / −1 runtime code (1 file), +48 / −6 tests (1 file), +2 / −2 flag help text (1 file) and +2 / −2 docs (1 file).** No kernel changes.

- `Scheduler._should_defer_prefill` (`python/sglang/srt/managers/scheduler.py`): also clears the interval when the running batch is empty or prefill-only, unless `require_mlp_sync` is set (DP attention). The existing `--prefill-decode-interval-min-bs` check is unchanged.
- Help text for `--prefill-decode-interval` and `--prefill-decode-interval-min-bs` (`python/sglang/srt/arg_groups/fields/schedule.py`, `docs/docs/advanced_features/server_arguments.mdx`): says the interval is skipped while nothing decodes without DP attention. `min-bs 0` now reads "at any batch size" instead of "always".
- Tests (`test/registered/unit/managers/test_scheduler_prefill_decode_interval.py`): the fake running batch gains `is_empty` and `is_prefill_only`, and four cases are added (next section).

## Speed Tests and Profiling

**Where on the curve, and why a static workload.** The change only acts while nothing is decoding, which happens at the low-concurrency end of the curve (and between bursts at any concurrency): a session's next long prompt arrives at an idle server and is prefilled chunk by chunk. A single long prompt on an idle server isolates exactly that wait. Whether the interval applies depends only on whether a decode batch exists, not on the request mix, so an AgentX replay is not needed; the concurrency-16 control covers the case where decode is always running.

**Setup.** One node with 4x B200. Image `lmsysorg/sglang:nightly-dev-20261024-5994c559`, whose interval code is identical to current main. "main" is the image as shipped. "This PR" is the same image with this PR's `scheduler.py` change applied. Blocks ran in the order main, PR, PR, main, with a fresh server per block. Server flags are those of the public InferenceX B200 TP4 recipe for this model, with two changes: `--prefill-decode-interval 96` instead of 192, and real rather than simulated speculative acceptance.

**Prompt with nothing cached on an idle server.** After a warm-up (three short prompts, one 16K and one 120K prompt), three prompts of 122,880 random token ids are sent one at a time, with `/flush_cache` before each. Every response reported `cached_tokens == 0`. Client wall time with `max_new_tokens=1` is the TTFT:

```python
import random, time, requests

URL = "http://127.0.0.1:30000"

def cold_ttft(seed, n=122880):
    rng = random.Random(seed)
    ids = [rng.randrange(1000, 100000) for _ in range(n)]
    requests.post(f"{URL}/flush_cache").raise_for_status()
    time.sleep(2)
    t = time.perf_counter()
    r = requests.post(f"{URL}/generate", json={"input_ids": ids, "sampling_params": {"max_new_tokens": 1, "temperature": 0}})
    dt = time.perf_counter() - t
    assert r.json()["meta_info"]["cached_tokens"] == 0
    return dt

print([round(cold_ttft(seed), 4) for seed in (1, 2, 3)])
```
