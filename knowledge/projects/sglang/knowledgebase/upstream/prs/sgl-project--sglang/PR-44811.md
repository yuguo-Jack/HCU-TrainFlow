# [Feat] logging: Add flag to redact request tokens from logs

[Upstream PR](https://github.com/sgl-project/sglang/pull/44811) · state: open · merged: False

## Original PR description

## Motivation

In some production scenarios, especially under zero-data-retention requirements, prompt and output data should never reach logs. `Req.__repr__` prints the token ids, the sampling params and the grammar. A couple of places format a `Req` into a log line or error message, including the scheduler watchdog dump and an assertion in the grammar manager.

## Modifications

When `SGLANG_REDACT_REQUEST_DATA=1` is set, `Req.__repr__` prints only the rid and the input and output lengths, and the server refuses to start with `--log-requests`, `--crash-dump-folder` or `--log-level debug`. The default is unchanged. Putting the flag in the repr covers every call site with one small change. The PR also adds unit tests and a docs entry.

If you would prefer this on by default whenever `--log-requests` is off, happy to switch it.
