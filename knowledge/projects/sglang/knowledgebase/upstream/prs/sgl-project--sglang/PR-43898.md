# [Refactor] scheduler: Remove PD multiplexing

[Upstream PR](https://github.com/sgl-project/sglang/pull/43898) · state: closed · merged: True

## Original PR description


> [!NOTE]
> PD multiplexing has few users and no CI coverage, so this PR deprecates it for now by removing it. It can be redesigned and added back later on top of the reworked scheduler.

Remove PD multiplexing (`--enable-pdmux`). No CI test enables it, and it has had no feature work since its docs landed.

- Scheduler: the `multiplex/` package (`SchedulerMultiplexMixin`, `event_loop_pdmux`, the pdmux context), `enable_pdmux` and its init.
- Server args: `--enable-pdmux`, `--pdmux-config-path` and `--sm-group-num` (read only by pdmux), and every validation hook term that read them. `ServerArgs` positional slots after them move back by three; the positional-order test is updated.
- Distributed: the duplicate prefill TP group and the `duplicate_tp_group` parameter of `initialize_model_parallel`.
- Model executor: per-stream decode CUDA graphs and attention backends (`decode_attn_backend_group`, `stream_idx` in graph keys, capture and replay, `ShapeKey.stream_idx`), the eager runner's per-stream backend, the `enable_pdmux` flags in the base and speculative graph runners, and the pdmux terms in `kv_cache_configurator`, cutedsl fusion, metrics and the forward observer.
- Split prefill, which only pdmux created: `ForwardMode.SPLIT_PREFILL`, `ScheduleBatch.prepare_for_split_prefill`, `forward_batch_split_prefill`, `ModelRunner.forward_split_prefill`, the split-only `ForwardBatch` fields, the split branches in `run_batch` and the step counters, and `forward_split_prefill` in 18 model files.
- The green-context stream kernel in the AOT kernel package (`spatial` extension), which only pdmux used.
- Tests and docs: pdmux and split-prefill tests and table cases removed; the PD-Multiplexing sections of the server-argument and Ascend feature docs removed.

No behavior change for servers that do not pass `--enable-pdmux`; passing it, `--pdmux-config-path` or `--sm-group-num` is now an unknown-argument error.
