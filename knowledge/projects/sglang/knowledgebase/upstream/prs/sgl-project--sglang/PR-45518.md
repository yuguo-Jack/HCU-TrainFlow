# [Fix] dspark: clamp FlashInfer softmax output to <= 1.0 for spec accept

[Upstream PR](https://github.com/sgl-project/sglang/pull/45518) · state: open · merged: False

## Original PR description

Fixes #45517

## Motivation
FlashInfer softmax can return q slightly > 1.0 (max 1.0000068) on near-one-hot
rows. The accept kernel unconditionally rejects q outside (0, 1], so the DSpark
accept length collapses at certain temperatures (e.g. 1.75 at T=0.3).

## Modifications
In `softmax_temp_flashinfer`, clamp the output to `max=1.0` (in-place on the
fresh FlashInfer tensor; upper bound only).

## Verification
- Switching only SoftmaxTemp to triton (same effect as clamping) restores accept
  length: T=0.05~1.2 all 7.5~7.6; business benchmark 1.75 -> 6.08.
- Distribution change is at most ~7e-6 per element.
