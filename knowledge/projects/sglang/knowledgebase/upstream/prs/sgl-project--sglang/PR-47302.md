# Fix LFM2 tool-call parser buffering entire arguments during streaming

[Upstream PR](https://github.com/sgl-project/sglang/pull/47302) · state: open · merged: False

## Original PR description

LFM2 buffers Pythonic tool calls until `<|tool_call_end|>`, so long string arguments do not stream as they are generated.

Serve `LiquidAI/LFM2.5-24B-A2B` on port 30000 with `--tool-call-parser lfm2`, then run:

```bash
curl -N http://localhost:30000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  --data-binary @- <<'JSON'
{
  "model": "LiquidAI/LFM2.5-24B-A2B",
  "stream": true,
  "temperature": 0,
  "max_tokens": 4096,
  "messages": [
    {
      "role": "system",
      "content": "Use the provided write_file tool. Supply complete file contents, never placeholders."
    },
    {
      "role": "user",
      "content": "Call write_file to create examples.py containing exactly 35 separate Python functions named example_01 through example_35. Each function takes x and returns x plus its number. Put a one-line docstring in each function describing the addition. Include every function in the content argument of one tool call. Do not run the file."
    }
  ],
  "tools": [{
    "type": "function",
    "function": {
      "name": "write_file",
      "description": "Write the full content to a file.",
      "parameters": {
        "type": "object",
        "properties": {
          "path": {"type": "string"},
          "content": {"type": "string"}
        },
        "required": ["path", "content"]
      }
    }
  }]
}
JSON
```

Before the fix, `delta.tool_calls[].function.arguments` arrives only when the call ends. With the fix, fragments arrive while `content` is being generated; concatenating them produces valid JSON.

The parser temporarily completes incomplete Pythonic expressions for AST parsing, excludes synthetic endings from output, and emits only new argument bytes. Non-streaming parsing is unchanged.

Validated with live SSE on an H100: 2,254 generated tokens and 702 deltas after `content` starts. Test files are unchanged; two existing assertions still expect the old buffering behavior.
