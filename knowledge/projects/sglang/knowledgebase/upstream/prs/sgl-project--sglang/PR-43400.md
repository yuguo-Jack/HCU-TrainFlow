# [rust-processor] Keep parity fixtures on Hugging Face

[Upstream PR](https://github.com/sgl-project/sglang/pull/43400) · state: open · merged: False

## Original PR description

Follows up on [this review comment](https://github.com/sgl-project/sglang/pull/43000#discussion_r4231294007) on #43000: the parity fixtures are large JSON, so they move out of git to a Hugging Face dataset. Stacked on #43233.

## What changes
- All of `rust/sglang-processor/tests/fixtures/` (about 600 KB: `parity/`, `openai_parity/`, `reasoning_parity/`, `tool_parity/`) moves to the [`sgl-project/sglang-processor-parity`](https://huggingface.co/datasets/sgl-project/sglang-processor-parity) dataset, and the directory is gitignored.
- `tests/scripts/fetch_fixtures.sh` downloads the fixtures at the revision it pins. The processor CI job runs it before `cargo test`.
- Tests and generators still read and write `tests/fixtures/`. A missing directory fails with `run tests/scripts/fetch_fixtures.sh`.
- The README and the `processor-model-parity` skill describe the workflow: regenerate, upload with the command in the script, then pin the new commit in the same PR.

## Before merge
- [ ] Create the dataset and upload the fixtures (from `rust/sglang-processor`):
  `hf upload --repo-type dataset --exclude '.cache/*' --delete '*.json' sgl-project/sglang-processor-parity tests/fixtures .`
- [ ] Pin `REVISION` in `fetch_fixtures.sh` to `hf datasets info sgl-project/sglang-processor-parity --expand sha` (it is `main` until the upload).

## Test
- `cargo test -p sglang-processor --all-features` passes with the fixtures in `tests/fixtures/`. With the directory removed, the tests fail with the fetch hint.
