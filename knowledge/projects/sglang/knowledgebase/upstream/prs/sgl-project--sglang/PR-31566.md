# [2/N] [spec] preserve verify capture mode on idle DP ranks

[Upstream PR](https://github.com/sgl-project/sglang/pull/31566) · state: closed · merged: False

## Original PR description

## Motivation

Sibling of #31537; prerequisite of #30877 (enable STANDALONE + DP attention).

Current idle DP ranks hardcode the target-verify capture mode to `FULL`, but STANDALONE's verify graph is captured with `NULL` (draft model is independent). So an idle rank falls back to eager while the active ranks run the graph. Ranks diverging on graph-vs-eager cause a **collective deadlock**. This PR makes `forward_batch` the source of truth and sets idle `spec_info` capture mode to`NULL`, so it never escalates beyond what `forward_batch` actually requests.

## Modifications

- `EagleVerifyInput.create_idle_input()`: make `capture_hidden_mode` a required arg instead of hardcoding `FULL` so every idle call site states its mode explicitly.
- `build_eagle_verify_input()`: on the idle path, pass `NULL` so `requested = max(fb, spec_info)` collapses back to `fb`, matching active path.
- `_build_trivial_verify_input()` (behavior is **unchanged**): on the idle path, pass `FULL` to align with active path.

**NOTE:** `_build_trivial_verify_input()` is touched only to satisfy the required argument; both its idle and active paths use `FULL` and already agree. If STANDALONE ever supports `steps == 0`, both sides should move to the algorithm-derived mode together in a follow-up.

## Unit Tests

Runtime path (STANDALONE + DP attention) is gated on main, so coverage is a CPU unit test asserting the idle path of `build_eagle_verify_input()` returns the enum floor `NULL` regardless of algorithm; so it never raises capture mode above what `forward_batch` decides.
