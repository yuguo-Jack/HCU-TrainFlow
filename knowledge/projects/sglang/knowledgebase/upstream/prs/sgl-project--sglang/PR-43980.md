# fix(qwen_vl): neutralize the legacy "<image>" sentinel in chat message text

[Upstream PR](https://github.com/sgl-project/sglang/pull/43980) · state: open · merged: False

## Original PR description

## Motivation

Fixes #43979.

For models served by `QwenVLImageProcessor` (Qwen2-VL / Qwen2.5-VL / Qwen3-VL / Qwen3.5 / Qwen4-Exp / …), a **literal `<image>` string in ordinary message text** is counted as an image placeholder. `qwen_vl.py` registers the legacy `/generate` sentinel as an alternative inside `image_token_regex`, and the multimodal processor reuses that regex to split and count the rendered prompt. When the same request also carries a real image, the placeholder count exceeds the number of image payloads and the request aborts:

```text
Mismatch: More 'IMAGE' tokens found than corresponding data provided.
Error in request: An exception occurred while loading multimodal data:
...
RuntimeError: An exception occurred while loading multimodal data:
INFO: ... "POST /v1/chat/completions HTTP/1.1" 500 Internal Server Error
```

This is easy to hit in agent workloads: GitHub issue/PR pages render user-uploaded screenshots as the literal text `<image>`, and the fetched page content is replayed as a tool message. Once such a message is in the history, **every** subsequent request to that model fails identically while any image is present — the conversation is permanently wedged (we observed 20+ consecutive 500s from a single agent session, which also tripped the gateway's circuit breaker).

The chat template only ever emits the native `<|vision_start|><|image_pad|><|vision_end|>` placeholder, so in the chat path any bare `<image>` in the rendered prompt is user text.

## Modifications

- `python/sglang/srt/entrypoints/openai/serving_chat.py`
  - Add `neutralize_qwen_vl_image_sentinel*` helpers, mirroring the existing Kimi K3 `neutralize_kimi_k3_image_placeholder*`.
  - Add `self.is_qwen_vl` (model-type gate, same idiom as the existing `is_gpt_oss` / `is_gemma4`).
  - In `_apply_jinja_template()`, neutralize the bare `<image>` sentinel in message text before the chat template is rendered, for the Qwen-VL family only.
  - Only *text* is rewritten: string content, `text` / `input_text` parts, and `reasoning_content` / `reasoning`. Structured `image_url` parts are untouched, so real media still renders as the template's native placeholder and media pairing is unaffected.
  - Raw `/generate` prompts are not touched, so the legacy sentinel keeps working there.
- `test/registered/unit/entrypoints/openai/test_serving_chat.py`
  - `TestNeutralizeQwenVlImageSentinel` covers: text replacement; native placeholder untouched; string content neutralized without mutating the input; text parts neutralized while media parts are preserved; `reasoning_content`; the nested value walker; and gate membership.

Gate list (`QWEN_VL_MODEL_TYPES`) is the set of model types handled by `QwenVLImageProcessor`: `qwen2_vl`, `qwen2_5_vl`, `qwen3_vl`, `qwen3_vl_moe`, `qwen3_5`, `qwen3_5_moe`, `qwen4_exp`, `qwen3_omni_moe`, `intern_s2_preview`, `interns2_mobius`, `cosmos3`.

### Alternatives considered

- **Drop `<image>` from `image_token_regex` / `get_combined_regex()`**: breaks the legacy `/generate` path, where the bare sentinel is the legitimate placeholder written by the caller.
- **Neutralize globally (all models)**: unsafe — LLaVA / DeepSeek-VL2 / InternVL / … legitimately use `<image>` as a *client-written* placeholder in message text, so the gate is required.
- **Degrade the mismatch to a warning in the processor**: masks genuine pairing bugs (e.g. a client that drops image data), so it needs a flag and a separate discussion.

### Related

#37579 reports the same failure mode for the GLM-V (`glm4v`) processor with `<|image|>` / `<|video|>`. This PR only covers the Qwen-VL family; the two share the underlying "prompt split cannot distinguish template placeholders from ordinary text" issue.

## Reproduction (pre-fix)

One real image plus one message whose text contains the literal sentinel:

```python
import requests

PNG = "iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="


def call(text):
    return requests.post(
        "http://127.0.0.1:30000/v1/chat/completions",
        json={
            "model": "<any Qwen-VL-family model>",
            "messages": [
                {
                    "role": "user",
                    "content": [
                        {"type": "text", "text": "what is this?"},
                        {"type": "image_url", "image_url": {"url": f"data:image/png;base64,{PNG}"}},
                    ],
                },
                {"role": "tool", "tool_call_id": "c1", "content": text},
                {"role": "user", "content": "go on"},
            ],
            "max_tokens": 8,
        },
    ).status_code


print(call("plain text, no markers"))  # 200
print(call("<image>"))                 # 500 before this change
```
