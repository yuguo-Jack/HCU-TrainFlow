# [Feat] cache: Expose external-linker page generations

[Upstream PR](https://github.com/sgl-project/sglang/pull/45548) · state: open · merged: False

## Original PR description

## Motivation

External-linker transfers carry reusable physical page indices. A late
completion cannot distinguish an earlier allocation of page N from a newer
allocation of page N using request, tree-node or process metadata alone.

Closes #45493. A search for open PRs by issue number and by
`page generation external linker allocator` found no matching implementation.

## Modifications

- Add opt-in allocator-issued Full/SWA page generations for token, paged and
  NPU allocation paths. Default serving allocates no ledger.
- Carry one generation per complete page in linker load/offload descriptors;
  default Rust tree-core offloads are enriched by the Python allocator owner.
- Use asynchronous device `index_fill_`/`index_select` and attach a CUDA
  readiness event for another stream. Generation equality is explicitly not a
  physical transfer-termination receipt.
- Preserve legacy positional `PoolTransfer` construction, make the new fields
  keyword-only, reject Mamba/non-CPU-CUDA generation profiles, and keep
  overflow/resize failure-safe.

## Accuracy Tests

No model forward or output semantics change. Source/CPU contract controls:

- allocator/linker/assembler: `91 passed`, `12 subtests passed`
- matching prebuilt SGLang 0.5.22 Rust-extension adapter gate: `1 passed`
- canonical changed-file pre-commit: passed

The local source build of `torch-sys 0.24.0` is blocked before candidate code by
its existing Torch 2.13/C++20 `module(...)` identifier conflict; the prebuilt
0.5.22 extension was used to validate the unchanged six-tuple Rust boundary and
candidate adapter enrichment.

## Speed Tests and Profiling

An H20 / Torch 2.14.1 / CUDA 13 component gate on GPU UUID
`GPU-14c5531e-c52e-712b-8b90-fe7fdad8c172` observed after warm-up:

- `index_fill_` host return: 0.041 ms while a preceding CUDA sleep remained pending
- `index_select` + recorded readiness event: 0.171 ms while the sleep remained pending
- old advanced assignment control: 101 ms and waited for the sleep
- 1,000 enabled generation submissions: 6.31 ms device time
- cross-stream event consumption, generation reuse/stale rejection, and compute
  oracle passed; GPU returned to 0 MiB

This is allocator-primitive evidence, not installed SGLang serving or physical
DMA/RDMA termination qualification.
