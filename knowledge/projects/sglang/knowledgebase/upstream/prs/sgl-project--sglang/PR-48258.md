# [Perf] flashinfer: release the shared workspace when no backend uses it

[Upstream PR](https://github.com/sgl-project/sglang/pull/48258) · state: open · merged: False

## Original PR description

## Motivation

`FlashInferAttnBackend.__init__` fetches the process-wide `flashinfer_workspace` buffer through `get_buffer`: 384 MiB by default, 2 GiB with `--enable-deterministic-inference`. Hybrid QSA models (Qwen3.8-Flash-Next / `qwen4_exp`) build the full-attention backend from `--attention-backend`, which defaults to `flashinfer` on SM120 and other non-SM90/SM100 GPUs. The model-level wrapper (`attn_backend_wrapper`) then replaces it with `QwenSparseAttnBackend`. The discarded backend is collected, but the workspace stays cached in the runtime context for the life of the process, unused. That is 384 MiB of device memory doing nothing by default, and 2 GiB with `--enable-deterministic-inference`.

## Modifications

- `layers/attention/flashinfer_backend.py`:
  - `FlashInferAttnBackend` instances that use the shared workspace register in a `WeakSet`;
  - `release_unused_global_workspace()` collects garbage (the replaced backend can sit in a reference cycle) and, when no registered backend is alive, drops the `flashinfer_workspace` buffer.
- `runtime_context.py`: `pop_buffer(name)`, the counterpart of `get_buffer`.
- `model_runner_components/attention_backend_setup.py`: after the attention backends are built, when FlashInfer is one of the resolved backends, call the release. This happens before CUDA-graph capture, so no graph references the buffer.

A live FlashInfer backend keeps the workspace (nothing changes for models that use FlashInfer). A FlashInfer backend built after the release calls `get_buffer` and re-creates the shared workspace. That includes backends built with `init_new_workspace=True` (some speculative draft workers), which use a buffer of their own and leave the re-created one unused, so configurations that build such a backend after the release do not keep the saving.

- Test: `test/registered/unit/layers/attention/test_flashinfer_workspace_release.py` (CPU) covers three cases: a live backend keeps the workspace, a replaced one releases it and a later backend re-allocates, and nothing happens when there is nothing to release.

## Accuracy Tests

No kernel or model code changes.

- `Qwen/Qwen2.5-0.5B-Instruct` (FlashInfer backend stays alive, so nothing is released), `--enable-deterministic-inference`, same RTX PRO 6000. Greedy outputs of 7 prompts (single, repeated twice, and batched) are **token-identical** to main, and main is repeat-identical in this config.
- `nvidia/Qwen3.8-Flash-Next-NVFP4` (workspace released): main itself is not repeat-deterministic on this GPU (even prefill logprobs differ between two passes on one server, and `--enable-deterministic-inference` is unsupported for its QSA top-k), so it has no strict gate on this GPU. The long prompt's greedy output is identical to main, and short prompts diverge within main's own run-to-run range.
- `Qwen/Qwen3.8-Flash-Next-FP8` on 8x H100 (workspace released): `--tp 8 --ep-size 8 --enable-deterministic-inference --attention-backend flashinfer --speculative-algorithm NEXTN --speculative-num-steps 3 --speculative-eagle-topk 1 --speculative-num-draft-tokens 4`. Every rank logs `Released the unused FlashInfer workspace (2.000 GiB)`, and main logs nothing. 8 chats (3 short texts, one of about 6,000 words, 4 with images), each sent twice: all **16/16 outputs are token-identical** to main, both arms are repeat-identical, and the KV pool is 2,838,592 tokens in both.

## Speed Tests and Profiling

`nvidia/Qwen3.8-Flash-Next-NVFP4`, TP=1, `--ple-offload-embedding --json-model-override-args '{"text_config": {"ple_embedding_dtype": "float8_e4m3fn"}}' --moe-runner-backend flashinfer_cutlass --mem-fraction-static 0.85 --cuda-graph-max-bs-prefill 2048 --disable-radix-cache`, default attention backend (resolves to `flashinfer`), RTX PRO 6000 Blackwell Max-Q (300 W), same GPU:

| | main `8d4e1ce4c7` | this PR |
|---|---|---|
| Log | – | `Released the unused FlashInfer workspace (0.375 GiB).` |
| GPU memory used after startup | 86,694 MiB | 86,310 MiB (**−384 MiB**) |
| Free device memory after CUDA-graph capture | 11.20 GB | 11.58 GB |
| KV cache tokens | 140,928 | 140,928 |

The release happens after the KV pool is sized, so the freed memory is runtime headroom (activations, graphs), not KV capacity. With `--enable-deterministic-inference` the discarded workspace would be 2 GiB, but that mode is unavailable for this model on SM120. With Qwen2.5-0.5B (FlashInfer in use), memory is identical to main: 87,716 MiB used, 9.42 GB free after capture.
