## Motivation

<!-- Describe the purpose and goals of this pull request. -->
Sleep mode releases weights/kv_cache/cuda_graph but keeps every
GroupCoordinator's device process group (HCCL communicators) alive, so a
sleeping NPU engine still holds hundreds of MB per rank. This adds a
platform-gated `comm` tag that releases those communication domains and
rebuilds them on wake without restarting the server.

## Modifications

<!-- Detail the changes made in this pull request. -->
- Add the `comm` memory-occupation tag. It is not part of `GPU_MEMORY_ALL_TYPES`; only platforms that register a comm backend accept it, so non-NPU paths are unchanged.
- New `sglang/srt/utils/sleep_comm`: tag schema + `SleepCommBackend` (`release`/`resume`, `handles_cuda_graph`, `resume_requires`) + a process-local registry. NPU registers `NPUSleepCommBackend` from `init_npu_backend()`, so `SRTPlatform` is untouched.
- `GroupCoordinator`: snapshot the final group parameters as `_DeviceGroupSnapshot`; expose generic `destroy_device_group()` / `rebuild_device_group()`, which replays the full `group_ranks` in order on every rank.
- Sleep: drop target/draft/ViT graphs, invalidate the DeepEP buffer, destroy device groups; keep `cpu_group` for barriers. Wake: rebuild groups, invalidate the buffer, recapture graphs, then AND-vote across ranks so a partial recapture failure falls back to eager everywhere.
- `weight_updater`: client errors are returned in the output (HTTP 400) instead of killing the scheduler; repeated release is idempotent; legacy triple resume auto-includes `comm`; `comm` resume requires weights/kv in the same request.
- Fix caches that held a raw `device_group` (Sampler, PrefillDelayer, DeepEP dispatcher, NemotronH) and dedupe spec-worker capture hooks on recapture.
- Gates: `comm` returns 400 for MindSpore and `pp_size > 1` (world-group collectives are unreachable from the PP request path); tag-less release filters it out.

## Function Tests

19 cases in 4 NPU test suites (`test/registered/npu/`, 2×/4× A3, nightly). Every case also checks that greedy output is identical before and after wake.

| Suite | Server config | What it tests |
| --- | --- | --- |
| `test_sleep_comm_cleanup.py` (9) | Qwen3-0.6B, tp=2, graphs on; plus a no-graph class | comm-only and full sleep/wake, 400 on resuming a never-released tag, 400 on comm resume missing `kv_cache`, legacy `[weights, kv_cache, cuda_graph]` resume auto-including comm, double release idempotent, 3x full cycles back to baseline (no HCCL/graph leak), `cuda_graph` not left in offload state after comm resume |
| `test_sleep_comm_cleanup_topology.py` (6) | tp=2×pp=2, and dp=2+tp=2 with dp-attention | full-group replay on disjoint tp/pp and attn_tp/attn_dp subgroups plus sampler sync group; PP rejects explicit `comm` with 400 (before any tag is released) and drops it from tag-less requests |
| `test_sleep_comm_cleanup_eagle.py` (2) | Qwen3-8B + EAGLE3 draft, tp=2 | draft-side graphs dropped on sleep and recaptured on the rebuilt comms; greedy spec-decoded text identical for full and comm-only cycles |
| `test_sleep_comm_cleanup_vit.py` (2) | Qwen3-VL-4B, tp=2, `SGLANG_VIT_ENABLE_CUDA_GRAPH=1` | model-external ViT graphs and their class-level pool released, lazily recaptured on the next image request; image QA answer unchanged after both cycle types |

Memory is measured device-wide via `torch.npu.mem_get_info()`: comm-only sleep must free >100 MB (HCCL buffers only, isolated by the no-graph class), full sleep >500 MB, and wake must return within 400 MB of the pre-sleep baseline.
