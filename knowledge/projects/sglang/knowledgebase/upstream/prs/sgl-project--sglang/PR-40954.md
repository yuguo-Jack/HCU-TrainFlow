# [PD] Decouple prefill session affinity from decode workload routing

[Upstream PR](https://github.com/sgl-project/sglang/pull/40954) · state: closed · merged: False

## Original PR description

## Motivation

Prefill benefits from stable session/cache affinity, but forwarding the same rank hint to decode can prevent the existing token-load scheduler from balancing decode work. The two routing decisions should be independently selectable.

## Modifications

- Add default-off `--disaggregation-decode-workload-balancing`, requiring DP attention and `--load-balance-method total_tokens`.
- Reuse `DPBudget.dispatch` with eligible ranks; override only decode rank hints and preserve explicit prefill rank/bootstrap identity. Preserve fake-PD warmup routing.
- Reject incompatible decode prefix-cache and elastic-EP configurations.
- Add canonical registered prefill-URL targeting in the gateway and optional `SGLANG_ROUTER_REQUIRE_CTX_URL_TARGET=1` enforcement.
- Add an optional single-owner session admission edge: new sessions choose least in-flight request-body-byte pressure, existing sessions retain their prefill URL. Inventory changes, unavailable owners and capacity exhaustion fail closed. Streaming/error/disconnect semantics are preserved without retries.

This is **not a new load-prediction algorithm**: decode reuses the existing total-token budget; admission byte pressure is not a KV index or compute-cost estimate. Decode balancing is within one replica, not across replicas. The admission edge requires a trusted ingress and one owner per session namespace; state is not replicated.

This PR is independent of the draft-probability and decode-bootstrap changes.
