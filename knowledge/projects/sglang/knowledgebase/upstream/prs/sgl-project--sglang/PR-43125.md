## AITER prerequisites

- [ROCm/aiter#6437](https://github.com/ROCm/aiter/pull/6437) — `gemm_a8w8_bpreshuffle_out`, the caller-owned BF16 output. Without that symbol the adapter copies.
- [ROCm/aiter#6410](https://github.com/ROCm/aiter/pull/6410) — gfx950 tuned rows for the Kimi-K3 A8W8 bpreshuffle shapes.
- [ROCm/aiter#6456](https://github.com/ROCm/aiter/pull/6456) — zero-pads the activation when the preshuffled weight K is padded.

`gemm_a8w8_bpreshuffle` and `per_token_quant_hip` are on AITER main.

## Motivation

With per-channel FP8 attention weights, every decode linear first quantizes its BF16 input per token. The producer of that input (residual-add norm, KDA gated norm, MLA q_a norm, MLA output gate) already reads and writes the same tensor, so a separate quant launch is wasted.

## Modifications

**`1be2e97c1e` take producer-quantized per-token FP8 inputs on ROCm and add a PTPC GEMM adapter**
- Let Quark W8A8 FP8 take a per-token (fp8, scale) tuple from any AITER producer, not only Qwen3.5's small-M ones.
- Add QuarkW8A8Fp8.takes_per_token_fp8_input so producers can tell whether a linear takes that tuple.
- Add a PTPC FP8 adapter over AITER's preshuffled a8w8 GEMM that also packs prequantized per-channel weights.
- Write into a caller buffer through gemm_a8w8_bpreshuffle_out when AITER has it (ROCm/aiter#6437), else copy.
- Register the adapter in the gemm kernel inventory and add numerical, prequantized-input and graph-replay tests.

**`da7f3a6558` fold the decode activation quant into its producers for PTPC FP8 on ROCm**
- Read the decode attention input as (fp8, per-token scale) when the in-projection takes it.
- Let an attention-residual bank read fuse its norm with that quantization where the aggregation can skip the norm.
- Run the Quark per-channel FP8 KDA in-projection as one PTPC GEMM that reuses the checkpoint's channel scales.
- Fuse the KDA gated output norm and the MLA q_a norm with the per-token FP8 quant their consumers take.
- Gate everything behind SGLANG_OPT_HIP_K3_PTPC_FP8 and its decode token window, off by default.
- Add bank quantized-read tests and document the switches.

**`dae7581e1e` extend PTPC FP8 to the ROCm MLA output gate and the latent MoE up-projection**
- Fuse the MLA output gate with o_proj's per-token FP8 quant in one JIT kernel on ROCm.
- Run the latent MoE up-projection as a PTPC FP8 GEMM inside the decode window.
- Add SGLANG_OPT_HIP_K3_PTPC_FP8_PREFILL_MIN_TOKENS to also use it for large prefill chunks, off by default.
- Register the gate kernel in the attention kernel inventory and document the switch.

Switch: `SGLANG_OPT_HIP_K3_PTPC_FP8`. Everything is ROCm only; CUDA and other checkpoints keep the existing path.
