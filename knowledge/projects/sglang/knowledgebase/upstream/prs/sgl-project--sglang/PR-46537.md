## Motivation

Part 4/5 of the DeepSeek-V4.1 CP>1 support series, split from the original combined PR [#45954](https://github.com/sgl-project/sglang/pull/45954). Based on the CP replay core in part 3. This PR connects CP>1 Prefill to CP1 Decode using Mooncake P/D and static DSpark.

KV transfer alone is insufficient: Decode also depends on compatible target/draft SWA state and pending DSpark state. The receiver must understand the CP owner/fan-in contract, and Prefill must verify that the required logical window history exists before publishing final metadata.

For example, with transfer start 0, end 257, and a 128-token window, required history is `[129, 257)`. If any CP peer lacks a committed row in this interval, publishing success would let Decode consume incomplete state. Every peer therefore votes on window validity, and any failed vote rejects the handoff. Page-aligned rows before 129 are not required logical history. This example illustrates the validation rule, not a new GPU transfer test.

## Modifications

- Advertise `cp_encoder_replay_version=1` from replay-enabled CP>1 Prefill and validate it during bootstrap. Preserve legacy layout behavior and reject unknown versions or incompatible DSpark layouts.
- Derive all-owner fan-in from the negotiated layout on both sides, using the existing KV/state transfer machinery.
- Validate committed request-window tags on every CP rank before final metadata publication, then combine validity with a MIN vote.
- Route a failed vote through existing room-failure handling without publishing success metadata.
- Admit Mooncake P/D with static DSpark. Decode remains CP1 with encoder replay disabled; draft block size and KV/state layouts must match.

Both roles must implement the versioned contract. This PR reuses existing payloads rather than defining a new hidden-state format. CP1 and encoder-off paths retain their existing transfer policy.

## Accuracy Tests

Archived replay/wire CPU validation for this split head: **96 passed, 0 skipped**. Coverage includes version negotiation, fan-in, state indices, no-page final-send decisions, missing window history, and a failed collective vote followed by a healthy vote. Lint passed during split preparation.

These checks do not establish real RDMA transfer, GPU state integrity, or complete cleanup/recovery of the same failed transport manager. Historical combined H20 results are not a fresh standalone run.
