# [Fix] dsv4: Capture the V4.1 prefill graph tail without two-level candidates

[Upstream PR](https://github.com/sgl-project/sglang/pull/45912) · state: closed · merged: False

## Original PR description

- Without two-level candidates (SM90), the DeepSeek-V4.1 ratio-1/2 sources run as one eager break in the prefill CUDA graph. Inside the late-layer tail that break sees the tail's live rows, but rebuilt their request rows from `forward_batch`, which still describes the whole extend, so capturing the 1,792-token bucket failed in `repeat_interleave` (`output_size` 128 against 1,792). The break now takes the leading rows of the tail metadata's bucket-sized request and position rows.
- `write_tail_source_kv` ran its eager compressor directly in a captured segment, so it was captured with the capture batch's shape and did not mark the source layer at replay. It now runs through an eager break under the same condition as the sources, `_low_ratio_sources_break`.
- Add `TestTailSourceRows`.

No behavior change where the ratio-1/2 sources run inside the graph (SM100 with two-level candidates) or outside a prefill graph.
