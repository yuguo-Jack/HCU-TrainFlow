## Modifications

- Register the explicit NCCL EP/Triton adapter, mask inactive slots and feed block-128 expert GEMMs while keeping routing IDs and weights under NCCL combine ownership.
- Preserve the FP8 scale and capability guards on the #41353 dispatcher interface. Reject rank-major layout with this Triton path.
- Keep scratch/requantization and the LL wire format explicit. This prerequisite adds no overlap scheduling or fixed experimental GEMM parameters.

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Include NCCL EP in TP-spanning EP resolution**

When `tp_size > 1` and the user leaves the documented `ep_size=1` default, `_a2a_ep_size()` does not adjust it because `_A2A_EP_SPANNING_BACKENDS` omits `nccl_ep`, even though this dispatcher unconditionally communicates over the TP group. Consequently `FusedMoE` lays out all experts as local for an EP group of size 1 while `NcclEpDispatcher` creates a multi-rank TP communication group, producing an inconsistent expert layout and invalid multi-GPU execution. Add `nccl_ep` to the TP-spanning backend resolution before parallel groups and weights are initialized.

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Bound prefill batches before entering the LL dispatcher**

For an eager prefill chunk containing more than 1024 tokens, this always raises: the NCCL EP budget defaults to 1024 and is capped at 1024, while the normal server defaults select `chunked_prefill_size` values from 2048 through 16384. Since the new backend routes prefill through LL too, ordinary long prompts fail despite the message suggesting a budget increase that validation forbids. Clamp NCCL EP prefill chunks to the LL capacity or provide a separate high-throughput/fallback path.

**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Keep Triton fallback on a supported A2A backend**

When `nccl.ep` is unavailable but `deep_ep` is installed, a launch using the newly supported explicit `--moe-runner-backend triton` is silently changed to `deepep` without changing the runner. Triton registers the new fused conversion only for `nccl_ep` (and its existing permutation path only accepts the standard format), so it cannot consume the `deepep_ll`/`deepep_normal` dispatch output and the first MoE request fails in runner selection. Select `none` for this combination or resolve a DeepEP-compatible runner along with the A2A fallback.
