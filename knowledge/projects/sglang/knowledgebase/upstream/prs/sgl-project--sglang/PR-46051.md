# [Doc] ascend-npus: Point the NPU test guide at a suite CI dispatches

[Upstream PR](https://github.com/sgl-project/sglang/pull/46051) · state: open · merged: False

## Original PR description

The registration snippet in the Ascend NPU contribution guide uses a suite name that does not exist:

```python
register_npu_ci(est_time=400, suite="stage-b-test-1-npu-a3", nightly=False)
register_npu_ci(est_time=400, suite="nightly-1-npu-a3", nightly=True)
```

`stage-b-test-1-npu-a3` appears exactly once in the whole repository: on this line. It is not in `PER_COMMIT_SUITES[HWBackend.NPU]` in `test/run_suite.py`, which lists `base-a-test-npu`, `base-b-test-{1,2,4,8,16}-npu-a3` and the `base-c-*` suites, and no workflow passes it to `run_suite.py`.

Two things make this silent rather than loud:

- `validate_all_suites()` in `test/run_suite.py` skips `HWBackend.NPU` (`_SUITE_CHECKED_BACKENDS` covers only CUDA/CPU/MUSA/XPU/MLX/MPS/PPU), so an unknown NPU suite is never rejected.
- `filter_tests()` selects by exact suite name, so the test is simply not collected.

The nightly line (`nightly-1-npu-a3`) is valid and is left alone. The net effect for a contributor who copies the snippet is that they keep nightly coverage but silently lose per-commit coverage.

The page points at `test_npu_sampling_backend.py` as "a complete example" two lines earlier, and that file already registers to the correct `base-b-test-1-npu-a3`, so the guide contradicts its own reference.

One line changed; docs-only.
