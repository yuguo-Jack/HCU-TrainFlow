# [Fix] qwen3-coder: Recover unescaped inner quotes in JSON parameters

[Upstream PR](https://github.com/sgl-project/sglang/pull/42448) · state: open · merged: False

## Original PR description

Reopened from #39809. GitHub closed that PR on 2 October when the fork it came from was deleted; its review history is still there.

## Motivation

Hebrew abbreviations write gershayim as an ASCII double quote (סה"כ, ש"ח). When a model writes them verbatim inside a JSON string in an object typed parameter, `json.loads` fails, the detector degrades the value to a string, the tool side rejects the type, and the model keeps retrying the same call. I hit this on a Qwen3.5 family model with an extended Hebrew vocabulary: 703 of 703 failed `save_record` calls in an office task suite had exactly this shape (the base model writes U+05F4 and never hits it). Any language that uses an inner ASCII quote (Hebrew, some Dutch and Swiss German abbreviations, inch marks like 5"x7") can trigger it.

## Modifications

After JSON parsing fails for an object or array parameter, retry three bounded repairs: remove backslashes when every quote was pre-escaped, escape an inner quote between word characters, and combine both. Pre-escaped arrays of objects are included. Valid JSON takes the original path, and failed repairs retain the existing `literal_eval` fallback.

The pre-escaped regression uses a raw string so the test input contains actual backslashes. Its negative control fails with the old array-prefix guard.
