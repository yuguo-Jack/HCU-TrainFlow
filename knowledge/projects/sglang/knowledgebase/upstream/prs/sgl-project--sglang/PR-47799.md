# [Fix] models: Phi-3-4k ignores its 2047-token sliding window (output breaks past 2k tokens)

[Upstream PR](https://github.com/sgl-project/sglang/pull/47799) · state: open · merged: False

## Original PR description

## Motivation

phi-3-mini-4k and phi-3-medium-4k ignore their 2047-token sliding window in sglang (they attend to everything), so output falls apart once a prompt passes ~2k tokens. it's been like this since #1299 (v0.3.0): the phi3 and mistral classes subclass `llama.py`, which never passes `sliding_window`.

## Modifications

following `gemma2.py`, `olmo2.py`, and `exaone4.py`, pass `config.sliding_window - 1` to `RadixAttention` and return it from `get_attention_sliding_window_size()` on `Phi3ForCausalLM` and `MistralForCausalLM`. windows >= `max_position_embeddings` return `None` (phi-3.5, phi-4-mini, and 128k set 262144 >= 131072 to mean no window). the mistral part is separable: it aligns mistral-7b-v0.1 (window 4096) with transformers past 4096 tokens (NLL 1.601 -> 1.610 vs HF 1.610), while phi-3-4k is the one that breaks.

## Accuracy Tests

microsoft/Phi-3-mini-4k-instruct on H100 (bf16) vs transformers 5.19 (sdpa), 8 wikitext-2 windows of 3,500 tokens and passkey at ~2,750 tokens (n=40); below 2047 tokens nothing changes (1.726 either way vs HF 1.727; phi-3.5 and phi-4-mini are 28,000/28,000 bit-identical):

|Metric|HF|main (FA3/Triton)|patched (FA3/Triton)|
|---|---|---|---|
|wikitext-2 NLL, tokens 2048..3499|1.644|6.686 / 6.691|1.644 / 1.644|
|passkey at ~2,750 tokens (n=40)|-|0/40 / 0/40|30/40 / 30/40|

repro: https://gist.github.com/EvanZhuang/d2433c0b917178fefa1870bf44a34132 (`python3 repro.py`, and `--attention-backend triton`).
tests: `pytest test/registered/unit/models/test_llama_sliding_window.py` (1 passed, 6 subtests; 5 fail on main) and 7 existing unit test files (100 passed, 12 skipped).

## Speed Tests and Profiling

no kernel change; windowless models keep -1, and windowed layers skip keys past `sliding_window`.
