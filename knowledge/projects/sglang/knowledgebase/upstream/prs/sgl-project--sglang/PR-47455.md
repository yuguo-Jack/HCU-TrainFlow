## Motivation

HiSparse currently reserves index-K memory for every DSA layer, including layers that reuse another layer’s top-k selection. This PR removes the redundant allocation, freeing GPU memory to support more concurrent decode requests.

For GLM-5.2, **index-K storage layers decrease from 78 → 21. Consider a 8 RTX PRO 6000 D, total index-K memory across eight GPUs decreases from 160.88 → 43.31 GiB (−73.1%); MLA KV is unchanged.** Removing redundant index-K allocations raises the theoretical capacity for 256K-token resident contexts to the CPU KV budget limit of 145 requests, as shown below.

## Modifications


- Skip index-K allocation for shared-top-k layers under non-speculative HiSparse, and match capacity estimation to the reduced allocation.
- Preserve per-layer MLA KV and dense index-K allocation for HiSparse speculative targets and draft workers.
- Include a prerequisite DSA + HiSparse PP fix: translate global layer IDs to PP-local buffer indices during KV swap-in, leaving DSv4/M3 entry paths unchanged.

The PP indexing fix overlaps with [#36331](https://github.com/sgl-project/sglang/pull/36331); this patch does not enable PP prefetch or add PP+MTP support.
## Accuracy Tests

Finite OFF/ON regression with matched inputs and P-cache conditions, using the **torch top-k reference backend**.

| Check | Result |
|---|---|
| Exact generated-token agreement | 20/20 request pairs |
| Retrieval correctness | 12/12 in each arm |

Four AgentX histories (128 output tokens/request) and six retrieval cases, each tested twice. This is not a broad accuracy benchmark; the original `sgl-kernel` backend has unresolved repeatability differences in both dense and shared modes.

## Speed Tests and Profiling

GLM-5.2 NVFP4, RTX PRO 6000, P=PP8 + HiCache, D=PP8 + HiSparse R32/B4096; no MTP/DCP; 900-second windows.
