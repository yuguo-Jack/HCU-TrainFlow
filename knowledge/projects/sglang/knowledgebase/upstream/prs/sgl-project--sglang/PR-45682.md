# [Perf] spec: Let DSPARK prefill publish read-done by placing its draft KV inject before the target forward

[Upstream PR](https://github.com/sgl-project/sglang/pull/45682) · state: closed · merged: True

## Original PR description

- DSPARK prefill can now publish prefill read-done: `supports_prefill_shared_read_done` returns True for DSPARK as well as DFLASH. Its one later shared reader, the draft KV inject after the target prefill, no longer reads scheduler-shared tables after the target forward.
- `TargetHiddenKvInjector.place_prefill` computes where a prefill's target hidden lands in the draft pool (`PrefillPlacement`: the draft write ids from the batch's own plan, positions, the SWA ring's slot and final position, and the SWA rows). `DSparkWorkerV2._forward_prefill` calls it before the target forward, whose read-done event is recorded before replay, and after the forward calls `inject_prefill`, which only selects the kept tokens and writes. The position and ring code moves from the worker unchanged; the SWA rows come from `_mla_swa_loc`, moved out of `_inject_mla` unchanged, for both the per-request ring and the paged full-to-SWA mapping. `inject_target_hidden`, used by verify, is unchanged.
- The pinned allowlist test now includes DSPARK.

Behavior change: DSPARK target prefill publishes read-done when the attention backend declares a pre-replay read end, so the next batch's scheduler-stream work waits only for the target's metadata reads instead of the whole forward. Validation on GB300, DEP4 DeepSeek V4.1 Flash with DSPARK, GSM8K (sgl-eval, 200 examples), with a debug build that also computed the placement after the forward and compared: with encoder SWA bounded replay (SWA ring) 98.00% and 134/134 prefill injects identical; without it (paged SWA mapping) 97.50% and 137/137 identical; read-done active on every DP rank in both. Rerun the same way on the placement-into-injector commit: 97.00% with 137/137 identical (ring) and 98.50% with 144/144 identical (paged mapping), read-done active on every DP rank.
