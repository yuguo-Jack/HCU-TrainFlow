# [Refactor] scheduler: Move deferred responses into an object and rename the PD prefill inflight queue to the transfer queue

[Upstream PR](https://github.com/sgl-project/sglang/pull/43902) · state: closed · merged: True

## Original PR description

Deferred responses were loose state on `Scheduler`; they become an object that owns their state and behavior, so later changes can ask it for the requests it holds. The PD prefill inflight queue is renamed to the transfer queue, matching PD decode.

- `DeferredResponses` (`scheduler_components/deferred_responses.py`) holds the finished responses a plugin defers, with the methods that used to be on `Scheduler`: `defer`, `stream_released`, `has_pending`, `abort`, and `held_reqs` for the weight-version inventory. The bodies moved unchanged apart from the renames. `Scheduler.defer_response(req, completion)` stays as the plugin entry point and delegates to it. The dict is created with the object instead of on the first deferral.
- `Scheduler.disagg_prefill_inflight_queue` becomes `disagg_prefill_transfer_queue`, so PD prefill has a bootstrap queue and a transfer queue as PD decode has a prealloc queue and a transfer queue. `process_disagg_prefill_inflight_queue` becomes `process_disagg_prefill_transfer_queue`, and the load inquirer's getter is renamed to match. The metric names and the `#inflight-req` log field are unchanged.

It also fixes three unit tests main currently fails, each broken by two PRs that merged without seeing each other:
- `test_decode_queue_cleanup.py` passed `tree_cache=` twice, so the file did not parse.
- The paused cache-flush test in `test_scheduler_pause_generation.py` had no `request_receiver`, which `flush_cache` now reads.
- The quark shuffle-import tests in `test_quark_config.py` reload the scheme with `is_hip` patched on, and the scheme queries the CUDA device at import; the reload now stubs that query.

No behavior change.
