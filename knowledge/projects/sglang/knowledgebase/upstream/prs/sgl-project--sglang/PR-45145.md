## Motivation

An out-of-tree (OOT) platform that runs the built-in `EAGLEWorkerV2` with device graph capture cannot capture the EAGLE draft graphs:

- `EagleDraftWorker._capture_cuda_graphs` looks the draft decode and draft extend runners up in maps keyed by in-tree device names (`cuda`, `npu`, `xpu`, `musa`), which raises `KeyError` for an OOT device.
- Adaptive speculation (`--speculative-adaptive`) hardcodes `NPUGraphRunner if _is_npu else DecodeCudaGraphRunner` for its per-configuration target verify graphs, so an OOT platform gets the CUDA runner, while its startup target verify graph comes from `get_graph_runner_cls()`.

This is part of generic OOT speculative-decoding support, for platforms that use the built-in worker (the previous PR covers platforms that bring their own worker).

## Modifications

- `SRTPlatform.get_speculative_graph_runner_cls(algorithm, phase)` (default `None`) with `phase` in `"draft_decode"` / `"draft_extend"`. The class is constructed like the built-in runner for that phase. `None` runs the phase eagerly, and the hook is not consulted when `capabilities.graph_capture` is False.
- `_select_spec_graph_runner_cls` picks the runner in one place: built-in platforms keep today's device-keyed selection (including the draft extend backend conditions); on an OOT platform only the platform answers, so the device maps are never indexed.
- Adaptive target verify runners on an OOT platform come from `get_graph_runner_cls()`, the same class as the startup target verify graph, so one run never mixes runner classes across step configurations. The keyword arguments it must accept (`attn_backend`, `speculative_num_steps`, `speculative_num_draft_tokens`) are documented on the hook.
- Docs: the plugin guide lists the new hook and the adaptive requirement on `get_graph_runner_cls()`.

## Tests

Added to `test/registered/unit/spec/test_oot_eagle_hooks.py` (CPU):

- `_capture_cuda_graphs` on an OOT device takes the draft decode and draft extend runners from the platform and constructs them with the worker (fails with `KeyError: 'custom'` before this change);
- nothing is consulted or captured without `capabilities.graph_capture`;
