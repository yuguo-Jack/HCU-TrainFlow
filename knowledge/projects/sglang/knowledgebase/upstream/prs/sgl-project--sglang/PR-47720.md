# [Perf] [NPU] Bound DeepSeek-V4 prefill query intermediates

[Upstream PR](https://github.com/sgl-project/sglang/pull/47720) · state: open · merged: False

## Original PR description

## Motivation

Long DeepSeek-V4 NPU prefills materialize full-size Q and attention outputs before the output projection. These intermediates grow with the local prefill length even though the final WO_A output is much smaller.

## Modifications

Add opt-in query tiling with `SGLANG_DSV4_NPU_PREFILL_CHUNK_SIZE=4096` (default: 0). KV writes, compression and index selection still run once for the full request. Each tile runs Q projection, normalization, RoPE, attention and WO_A; WO_B runs once after the tiles.

Reuse scheduling metadata across layers within one eager batch, while reading each layer's current top-k indices. Release Q before WO_A so its scratch can reuse that storage.

The initial path covers pre-A5 DeepSeek-V4, attention TP1, 64 heads, BF16 WO_A and a single-request eager prefill without CP. Other configurations keep the existing path.

## Accuracy Tests

On Ascend 910C, torch/torch_npu 2.10 and CANN 9.1:

- Nine target-attention comparisons across SWA, C4 and C128 match bitwise, including cached prefixes and uneven tiles.
- Extracted production methods pass a 16K BF16 pipeline comparison and four dynamic W8A8 Q_B/WO_B comparisons. The W8A8 tests call the production INT8 linear method.
- Eighteen dispatch cases and metadata cache/current-top-k/new-batch/exception-restoration checks pass.
- Ruff, isort, Python compilation and `git diff --check` pass.

Projection results are not bitwise identical. The final BF16 comparison has max absolute error 0.0009765625; the harness uses rtol=0.02 and atol=0.002.

These tests use synthetic weights and cache/index fixtures, with an identity Q_A. Real compressor/indexer integration and full-model generation accuracy remain untested. This PR is draft pending that validation.

## Speed Tests and Profiling

Isolated production-method pipeline through WO_B, synthetic BF16 weights, 16K query tokens, prefix 256, C4 top-k 512, tile size 4096:

| | Full queries | Tiled queries |
| --- | ---: | ---: |
| Incremental peak allocated memory | 3328 MiB | 864 MiB |
| Warm median latency | 38.89 ms | 39.28 ms |

Peak allocation falls by **2.41 GiB (74%)**, with **1.01% higher latency** in this test. Timing uses ABBA order with 16 samples per arm. Warm timings exclude first-use scheduling; the peak sample includes tile metadata allocations. These are not total HBM or end-to-end serving measurements.
