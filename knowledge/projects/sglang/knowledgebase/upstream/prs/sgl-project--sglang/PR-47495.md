# [Fix] lang: Normalize stop in RuntimeEndpoint._handle_dtype_to_regex

[Upstream PR](https://github.com/sgl-project/sglang/pull/47495) · state: open · merged: False

## Original PR description

## Motivation

In `sglang.lang.backend.runtime_endpoint.RuntimeEndpoint._handle_dtype_to_regex`, `sampling_params.stop` is only converted to a list when it equals the default empty tuple `()`:
```python
if sampling_params.stop == ():
    sampling_params.stop = []

dtype_regex = None
if sampling_params.dtype in ["int", int]:
    dtype_regex = REGEX_INT
    sampling_params.stop.extend([" ", "\n"])
elif sampling_params.dtype in ["float", float]:
    dtype_regex = REGEX_FLOAT
    sampling_params.stop.extend([" ", "\n"])
```

However, `sgl.gen(..., stop=...)` accepts `Optional[Union[str, List[str]]]` (as well as tuples), and `StreamExecutor._resolve_sampling_params` copies `stop` as-is onto `SglSamplingParams`. Consequently:
1. Calling `sgl.gen("val", dtype=int, stop="\n")` or `sgl.gen("val", dtype=float, stop=("\n", ";"))` raises `AttributeError: 'str' object has no attribute 'extend'` (or `'tuple' object has no attribute 'extend'`) inside the stream worker thread.
2. Passing a `list` `stop` mutates the caller's list in place via `.extend([" ", "\n"])`.

## Modifications

- Normalize `sampling_params.stop` in `RuntimeEndpoint._handle_dtype_to_regex` (`[]` when falsy, `[sampling_params.stop]` when `isinstance(..., str)`, and `list(sampling_params.stop)` otherwise) before extending stop tokens for `int` and `float` dtypes.
- Add CPU unit tests in `test/registered/unit/lang/test_runtime_endpoint_dtype.py`.
