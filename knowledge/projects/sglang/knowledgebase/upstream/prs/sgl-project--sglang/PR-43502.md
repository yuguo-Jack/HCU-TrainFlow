# [DSv4.1] Size the encoder-replay SWA pool by the DSpark draft's stages, and keep more prefix tails

[Upstream PR](https://github.com/sgl-project/sglang/pull/43502) · state: open · merged: False

## Original PR description

## Motivation

```bash
python3 -m sglang.launch_server --model-path deepseek-ai/DeepSeek-V4.1-Flash --trust-remote-code \
  --tp 4 --ep-size 4 --mem-fraction-static 0.8 --max-running-requests 64 --chunked-prefill-size 8192 \
  --speculative-algorithm DSPARK --speculative-dspark-block-size 5 \
  --enable-encoder-swa-bounded-replay --enable-decoder-swa-bounded-replay
# startup, TP0: DSV4 SWA sizing: ... prefix_tails=256 / DSV4 memory calculation: ... swa_fixed=4.55 GB ... full_token=60815360
```

**The pool is priced at the wrong layer count.**
- Under encoder SWA bounded replay the target keeps its window per request, so the paged SWA pool holds only the DSpark draft's KV.
- `DSV4PoolConfigurator` prices that pool at `paged_draft_layers` = `dflash_draft_num_layers`, the draft config's `num_hidden_layers`. The DSpark head bundled with DeepSeek-V4.1 inherits the target's 40.
- `DeepseekV4DSpark` builds `len(dspark_target_layer_ids)` = 3 stages. The configurator therefore reserves about 13× the bytes the draft allocates and takes them out of the full KV pool: 3.8 GB per GPU at the default, 33.5 GB at `--swa-prefix-tails 4096`. That memory stays free after graph capture.

**256 prefix tails are too few for multi-turn agentic traffic.**
- A cached prefix is reusable only while its last window still has paged SWA slots (the radix match stops at a tombstoned window).
- On a one-hour agentic-coding replay at 16 concurrent sessions, conversations idle for 3–5 minutes lose their tail while their full KV is still on the GPU. They re-prefill 130K–755K tokens, which blocks everything queued behind them for 2–13 s.
- 3.5% of requests wait more than 1 s. One request with a 104,704-token cached prefix and 311 new tokens waited 11.6 s.

## Modifications

- Record the DSpark stage count (`SpecAuxHiddenStateConfig.dspark_num_stages`) and price the encoder-replay paged SWA by it, falling back to `dflash_draft_num_layers`.
- Under encoder replay with DSpark, default `--swa-prefix-tails` to `4 × max_running_requests × (num_layers_total // paged_draft_layers)`.
  - This keeps the byte budget of the non-replay default, which prices all target layers, and spends it on cheaper tails: 3,328 tails, ≈2.3 GB per GPU, at 64 running requests.
  - An explicit flag still wins.
- Tests in `test_pool_configurator.py`:
  - pricing at 256 and 4096 tails against the startup values (SWA cap 189,440 / 1,664,000; `swa_fixed` = request window + cap × 3 stages × 584 B);
  - the default rule and its override;
  - the DSpark budget test now uses a 40-layer draft config with 3 stages.

## Speed Tests and Profiling

Same node, 4×GB300, launch command above; each arm uses its default prefix tails.

| startup (TP0) | main `3831e7e0918` | this PR `c5130ca00ba` |
|---|---:|---:|
| default prefix tails | 256 | 3,328 |
| `swa_fixed` | 4.55 GB | 2.66 GB |
| full KV pool tokens | 60,815,360 | 62,058,752 |

Static prefix reuse: N distinct 16K-token prefixes at concurrency 16, one output token. Pass 1 caches them; pass 2 revisits them in reverse order with 256 new tokens. All prefixes fit in the full KV pool in both arms.

| pass 2 | main | this PR |
|---|---:|---:|
| N=100: prefix hits | 21/100 | 100/100 |
| N=100: uncached prompt tokens | 1,319,936 | 25,600 |
| N=100: TTFT p50 (ms) | 7,728 | 3,982 |
| N=200: prefix hits | 21/200 | 153/200 |
| N=200: uncached prompt tokens | 2,983,936 | 821,248 (−72%) |
| N=200: TTFT p50 (ms) | 7,944 | 4,028 |

At N=200, `--swa-prefix-tails 8192` reaches 200/200. The remaining misses at the default come from finished requests keeping their whole last chunk of SWA (~8.7K slots per 16K prefix) instead of one window; that retention is a separate issue and is not changed here.
