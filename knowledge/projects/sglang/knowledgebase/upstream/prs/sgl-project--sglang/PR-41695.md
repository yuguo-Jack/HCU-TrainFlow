# [DCP] [HiCache] Support role-local DCP storage in prefill/decode serving

[Upstream PR](https://github.com/sgl-project/sglang/pull/41695) · state: open · merged: False

## Original PR description

**Stack 4/4.** Depends on #41694. Targets `main`, so the full diff is cumulative. [Incremental diff](https://github.com/Venkat2811/sglang/compare/39e4d07b341dd50551e77214122e899b895a021a...ed850058f8397ebd371856562dd9ed052110642d). Refreshed onto `4cca7fcd3e` on 16 October; remains draft. The reviewed recurrent-file dependency was replayed locally; #41692 itself was not changed.

## Motivation

Decode must honor the prefix it promised to prefill without replacing the live recurrent state received through P-to-D transfer. Enable role-local DCP L3 reuse while preserving that contract.

This work grew out of experiments with Kimi-K3 prefill/decode serving configurations.

## Modifications

- Restore canonical cached state separately from live request state; reuse main's capacity and lock ownership paths.
- Reserve outstanding checkpoint slots and advertise only admitted prefetch coverage.
- Require effective `wait_complete` on DCP decode and reject decode KV offload with DCP storage. Runtime attachment forwards the selected policy through both controller layers.

Live-state preservation and admission fixes also affect DCP1. Roles can have different layouts, but each reads compatible role-local objects. Persisted cross-layout conversion is unsupported. Losing promised data fails the request safely; it does not turn an incomplete restore into a hit. Broader timeout/liveness redesigns are outside this PR.

## Accuracy Tests

Before = hybrid stage `39e4d07b34`, which rejects DCP P/D storage. Final stage = `ed850058f8`. Kimi-Linear uses TP4/DCP1 prefill and TP4/DCP4 decode on one eight-GPU B300 node, with live RDMA transfer and separate role-local namespaces.

| Scenario | Before | After |
| --- | --- | --- |
| File L3, live P/D | Rejected | 22 requests pass: main cache-off control, role-local reuse, three concurrent restores, cancellation during I/O, lost promised state and recovery |
| Mooncake DRAM L3, live P/D | Rejected | 16 requests pass, including main control, fresh readers and missing-state fallback; both roles attach through the real HTTP API |
| Start with default timeout, attach using wait_complete | Rejected incorrectly by this draft's old controller check | Real controller regression is red before the fix and green after; HTTP attachment and inference pass |
| HiCache SSD offload via file L3 | Rejected | Physical pressure verified on the hybrid parent; not repeated as live P/D in this refresh |
| Mooncake SSD offload | Rejected | Disk-only readback verified on the hybrid parent; not repeated as live P/D in this refresh |

File P/D ran before the final attach-policy fix; that fix changes runtime attachment, not its startup configuration. Mooncake P/D uses the final runtime code. Compared output IDs match the relevant control. The largest concurrent/retry logprob delta is 0.01291 (threshold 0.2); fresh-reader deltas against the matching warm control are zero. A fresh process can acquire a 64-token shared device prefix during successive requests, so P/D cache counters are not represented as universally zero L1.

25 CPU files plus two scheduler-attach tests pass with CUDA hidden. Four Python/Rust GPU restore tests pass, including preserving live state. Reservation and effective-policy regressions have failing-before/passing-after evidence. Pre-commit and docs checks pass. Hosted CI, B200, Kimi-K3, cross-node P/D, speculative L3 and live P/D SSD pressure were not rerun.
