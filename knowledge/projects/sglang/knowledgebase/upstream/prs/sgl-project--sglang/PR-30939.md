# Fix HashTopK empty output shapes

[Upstream PR](https://github.com/sgl-project/sglang/pull/30939) · state: closed · merged: False

## Original PR description

## Summary

- preserve `HashTopK.topk` as the empty `topk_ids` and `topk_weights` width, including fused shared-expert columns
- size the empty `router_logits` placeholder by `num_experts`, matching normal forward
- remove the per-rank-only empty-column workaround now that both shared-slot policies use the same output contract
- compare empty-helper output with the real zero-token torch forward in both per-rank and non-per-rank regression cases

This keeps the existing DeepEP waterfill behavior intact: waterfill construction first reduces `self.topk` to routed width, then its balancer expands the shared column exactly once.

The separate fused JIT hash-topk zero-token kernel launch failure described in the issue is outside this change.

## Code Review

This pull request simplifies the empty_topk_output method in HashTopK by directly using self.topk and ensuring router_logits is sized based on self.num_experts. It also removes redundant tensor replacement logic for per-rank fused shared slots. The unit tests are updated and parameterized to verify that the empty top-k output matches the zero-token forward pass output shape. The reviewer suggested adding a return type annotation -> StandardTopKOutput to empty_topk_output for better type safety and consistency.
