# [Test] [NPU] HiCache: Add NPU e2e test for --hicache-host-memory-fraction

[Upstream PR](https://github.com/sgl-project/sglang/pull/46795) · state: open · merged: False

## Original PR description

## Motivation

`--hicache-host-memory-fraction` bounds the HiCache L2 host (CPU RAM) pool budget. Its sizing path (psutil + cgroup) is device-agnostic, but the knob still needs coverage on the Ascend NPU backend to prove both ends of it work end-to-end: fraction-only keeps L2 auto-sizing on, while an explicit `--hicache-size` turns it off. Either way, L2 prefix reuse must keep working on NPU (second identical prompt hits `cached_tokens > 0`).

## Modifications

- Add `test/registered/npu/basic_function/HiCache/test_npu_hicache_host_memory_fraction.py`, an NPU HiCache e2e test that:
  - launches the server with `--hicache-host-memory-fraction 0.3` and asserts the "HiCache auto-sizing" / "fraction 0.30" markers plus L2 reuse;
  - launches again with an explicit `--hicache-size` and asserts auto-sizing is disabled while L2 reuse still holds.
- The server is launched with `ASCEND_USE_FIA=1` so `NPUMHATokenToKVPool` exposes per-layer KV buffers, letting the unified HiCache host pool enumerate device strides (avoids `RuntimeError: Boolean value of Tensor with more than one value is ambiguous`).
- Registered to the `full-1-npu-a3` nightly suite via `register_npu_ci`.

Numeric budget-scaling (fraction -> per-rank bytes) is already covered by the device-agnostic CPU unit test `test_hicache_auto_size.py`, so this e2e test does not assert exact byte budgets.
