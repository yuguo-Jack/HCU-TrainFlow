# [Fix] wan2.2-s2v: Take the last wav2vec2 layer from last_hidden_state

[Upstream PR](https://github.com/sgl-project/sglang/pull/44755) · state: open · merged: False

## Original PR description

Fixes broken Wan2.2-S2V lip sync on transformers ≥ 5.17. **Correctness only — no performance change, and it is not XPU-specific.**

## The bug
The S2V audio encoder took its last layer as `result.hidden_states[-1]`. The checkpoint uses `do_stable_layer_norm`, so the encoder's final LayerNorm belongs to the **last layer's output** — and transformers 5.17 returns `hidden_states[-1]` *before* that norm, where 5.12 returned it after. The audio features were therefore un-normalised, and lip sync degraded with no error anywhere.

`last_hidden_state` is post-norm in **both** versions, so it is used as the last layer:

```python
hidden_states = (*result.hidden_states[:-1], result.last_hidden_state)
feat = torch.cat(hidden_states) if return_all_layers else hidden_states[-1]
```

This is version-robust rather than pinning a transformers release. Verified against 5.17 and 5.19.

The call also narrows from `self.model(...)` to `self.model.wav2vec2(...)`: feature extraction does not use the LM head, and calling the bare encoder avoids computing and discarding it.

1 file, +6/−6.

## Base
⚠️ **Stacked on #43279** (the S2V port), included here as the first commit — S2V does not exist on `main` yet.
