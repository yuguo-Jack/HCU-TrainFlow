# [Fix] hicache: Report a deadline-cut storage prefetch separately and keep its storage beliefs

[Upstream PR](https://github.com/sgl-project/sglang/pull/44338) · state: closed · merged: False

## Original PR description

## Motivation

A storage prefetch that the stop policy ends before the read completes is not a storage shortfall: the span is still in the store, and the hit count the query agreed on may be a MIN over lookups that were skipped rather than a verdict about what is stored. A partial hybrid transfer is nevertheless resolved as `storage_transfer`, which heals the storage-existence beliefs beyond the completed span, so the next insert re-writes pages the store already holds and lookups skip them until it does.

## Modifications

- `PrefetchOperation.deadline_expired` marks an operation whose read was ended by the stop policy. `_handle_prefetch_result` then reports the unfulfilled tokens under a new `deadline` reason and leaves the KV and auxiliary-pool beliefs untouched; `_invalidate_absent_from_hit_query` skips such a cut query. The flag is set by a cache or controller implementation that cancels an in-flight read under its stop policy; the in-tree `timeout` check in `check_prefetch_progress` keeps its current handling in this PR.
- `storage_prefetch_unfulfilled_tokens` gains the `deadline` reason label, pre-registered like the others.
- `PrefillAdder` finishes storage-prefetch admission for a retracted request (with `reason=None`, so nothing is logged) after discarding its accounting, so a cache implementation that keeps per-request admission state sees the same lifecycle end as every other admitted request. In the base cache this call is a no-op for that request because its accounting was already discarded. `test_prefill_adder.py` asserts the call.
- The buffer-mode hit-drain fixture in `test_storage_prefetch_lifecycle.py` gains `deadline_expired=False`, since the drain now reads it.
