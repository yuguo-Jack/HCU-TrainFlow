# [Chore] environ: Remove retired unified radix tree environment variable

[Upstream PR](https://github.com/sgl-project/sglang/pull/45090) · state: open · merged: False

## Original PR description

## Motivation

`SGLANG_ENABLE_UNIFIED_RADIX_TREE` no longer controls cache selection: the unified radix tree is already the default. Its remaining references are a warning-only deprecation entry and obsolete assignments in cookbook commands and AgentX configuration data.

## Modifications

Remove all remaining references to this retired variable:

- The warning-only entry in `environ.py`.
- Three DeepSeek-V4 cookbook command assignments.
- Seven DeepSeek-V4 and three GLM-5.2 AgentX configuration entries.

Cache selection is unchanged. Setting the old variable externally now has no effect and no longer emits its deprecation warning. Other deprecated variables and Qwen3.8 documentation are unchanged.

The two AgentX files are generated snapshots. Their sync scripts are external to this repository; future regeneration should also omit the retired key. Historical images and external deployments were not revalidated; this cleanup targets the current repository/runtime.

## Accuracy Tests

- Full tracked-repository search for `ENABLE_UNIFIED_RADIX_TREE`: zero remaining matches, including canonical and legacy prefixes.
- Inspected the cache factory and environment definitions: no functional consumer remains.
- Both AgentX modules parse in Node. Recursive before/after comparison confirms their only semantic changes are the removal of the seven and three environment keys respectively.
- Loaded the actual `environ.py` with the old variable set to `0` and `1`: no descriptor, deprecation entry, or warning remains.
- `bash -n` passed for all three modified launch commands.
- Pre-commit and `git diff --check` passed.
- Full Mintlify validation/link checks remain unverified: earlier attempts could not complete npm dependency installation (registry stalls / FETCH_ERROR).
