# [Fix] sampling: Fix penaltylib release/merge edge cases and None tokenizer handling

[Upstream PR](https://github.com/sgl-project/sglang/pull/47024) · state: open · merged: False

## Original PR description

## Motivation

Self-discovered while auditing `python/sglang/srt/sampling/penaltylib/`:

1. **`BatchedPenalizerOrchestrator.release()` breaks `orch.batch` and `orch.reqs()`:**
   - The `batch` property setter (`@batch.setter`, line 36) sets `self._batch_ref = lambda: None` when `value is None` because `@property def batch` invokes `return self._batch_ref()`.
   - However, `release()` (invoked by `__exit__()`) directly sets `self._batch_ref = None`, causing any subsequent `orch.batch` or `orch.reqs()` call to raise `TypeError: 'NoneType' object is not callable`.
   - Similarly, `orch.reqs()` accesses `self.batch.reqs` without guarding `self.batch is None`.

2. **`BatchedPenalizerOrchestrator.filter()` with empty `keep_indices` breaks subsequent `merge()` and `filter()`:**
   - When `filter(keep_indices)` runs with `len(keep_indices) == 0`, calling `self.release()` clears `self.penalizers` and sets `self.batch = None`.
   - If another orchestrator with active penalties is subsequently merged via `self.merge(their)` on the live `running_batch`, either `self.penalizers[penalizer]` raises `KeyError` or the next non-empty `filter()` sees `self.reqs() == []` (because `_batch_ref` was cleared) and silently tears down all merged penalizers.

3. **`BatchedMinNewTokensPenalizer._prepare()` crashes when `req.tokenizer is None` or `reqs` is empty:**
   - With `--skip-tokenizer-init`, the scheduler sets `self.tokenizer = None` and copies it to `req.tokenizer`. While `Req.check_finished` (`schedule_batch.py:1825`) guards `if self.tokenizer is not None:` before reading `eos_token_id` and `additional_stop_token_ids`, `BatchedMinNewTokensPenalizer._prepare()` unconditionally accesses `req.tokenizer.additional_stop_token_ids` and `req.tokenizer.eos_token_id`, raising `AttributeError` when `req.tokenizer is None` and `min_new_tokens > 0`.
   - When `reqs` is empty during `merge()` preparation, `torch.nn.utils.rnn.pad_sequence([], ...)` raises `RuntimeError: received an empty list of sequences`.

## Modifications

- Assign `self.batch = None` in `BatchedPenalizerOrchestrator.release()` and return `batch.reqs if batch is not None else []` in `reqs()`.
- In `BatchedPenalizerOrchestrator.filter()`, when `len(keep_indices) == 0`, tear down the penalizers and set `self.is_required = False` without calling `self.release()`, preserving `_batch_ref` and `self.penalizers` across `filter([]) -> merge() -> filter(non_empty)`.
- Extract `_stop_token_ids(req)` guarding `req.tokenizer is not None` and handle empty `reqs` in `BatchedMinNewTokensPenalizer._prepare()`.
- Add unit tests in `test/registered/unit/sampling/test_penaltylib.py` covering `release()`, `filter([]) -> merge() -> filter([0])`, and `BatchedMinNewTokensPenalizer` with `req.tokenizer = None`.

The `req.tokenizer is None` guard fixes a real crash. With `--skip-tokenizer-init` the scheduler sets `self.tokenizer = None` and copies it to `req.tokenizer`, so any request with `min_new_tokens > 0` raises `AttributeError` in `_prepare()`. The orchestrator changes are defensive (see my reply on @paolo-perrone's thread). As written they swap a loud `TypeError` for silently dropping penalties on the next `filter()`. I'd either keep the batch ref on the empty-`filter()` path or split the orchestrator part out so the tokenizer fix can land on its own.

This re-creates the penalizers, but `release()` already set `self.batch = None` and nothing rebinds it, so `reqs()` returns `[]` for the rest of the orchestrator's life. The merge itself works, and that's all `test_merge_after_empty_filter_recreates_penalizers` checks. It breaks on the next non-empty `filter()`. Each `penalizer.is_required()` loops over `self.orchestrator.reqs()`, gets False and calls `teardown()`, so the merged requests silently lose their frequency, presence, repetition and min-new-tokens penalties. Before this PR that path raised a `TypeError`. Now it fails quietly. It isn't reachable from `ScheduleBatch.filter_batch` today, since that returns early on empty, but it's the path this PR and its test set out to fix. I'd have the empty branch in `filter()` tear the penalizers down and set `is_required = False` without calling `release()`, so the batch ref survives.

File: `python/sglang/srt/sampling/penaltylib/orchestrator.py` · line None

+1, I reproduced this reading through the code. After `filter([])` calls `release()`, `_batch_ref` stays `lambda: None`, so every later `penalizer.is_required()` sees `[]`. The first non-empty `filter()` after the merge tears down all four penalizers for the merged requests, and nothing raises.

A smaller fix that also makes the `KeyError` guard in `merge()` unnecessary is to keep the penalizer instances and the batch weakref on the empty path:

```python
if len(keep_indices) == 0:
    for penalizer in self.penalizers.values():
        penalizer.teardown()
    self.is_required = False
    return
```

The next `merge()` then prepares the torn-down penalizers against the (now empty) `batch.reqs`, which the new empty-`reqs` branch in `BatchedMinNewTokensPenalizer._prepare()` already handles, and `reqs()` keeps following `batch.reqs` after the scheduler extends it. `release()` can keep clearing everything for `__exit__`.

For context, this path isn't reachable from the scheduler today. `ScheduleBatch.filter_batch` returns before touching the orchestrator when nothing is kept, and `scheduler.py` replaces an empty `running_batch` rather than merging into it (the `running_batch.is_empty()` checks before `merge_batch`). So the orchestrator half of this PR is defensive. The `req.tokenizer is None` fix is the one that matters in production.

This matches `Req.check_finished`, and EOS is still masked through `req.eos_token_ids` (populated from the model config's `hf_eos_token_id`), so the semantics with `--skip-tokenizer-init` look right.

Nit: the `req.tokenizer is not None` check now appears twice inside the nested comprehension. A small helper is easier to read:

```python
def _stop_token_ids(req) -> set:
    ids = (req.sampling_params.stop_token_ids or set()) | (req.eos_token_ids or set())
    tok = req.tokenizer
    if tok is not None:
        ids |= tok.additional_stop_token_ids or set()
        if tok.eos_token_id is not None:
            ids.add(tok.eos_token_id)
    return ids
```
