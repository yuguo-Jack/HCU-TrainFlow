# [Fix] multimodal: Return the selected processor from LlavaMultimodalProcessor

[Upstream PR](https://github.com/sgl-project/sglang/pull/45868) · state: open · merged: False

## Original PR description

Pixtral, Mistral-3 and HF-format LLaVA servers answer HTTP 500 to `/flush_cache` and to every
weight update, because their multimodal processor is a wrapper without the base processor's state;
this makes `LlavaMultimodalProcessor` return the processor it selects.

## Motivation

`LlavaMultimodalProcessor` (used for `LlavaForConditionalGeneration` and
`Mistral3ForConditionalGeneration` checkpoints in the HF layout) builds the processor of the vision
encoder as `self.inner` and forwards only `process_mm_data_async` to it. It never runs
`BaseMultimodalProcessor.__init__`, so anything else the server calls on it raises
`AttributeError`. Since #34398 that includes `clear_preprocess_cache()`, which the tokenizer
manager calls after every successful flush and weight update:

- `/flush_cache` and `/update_weights_from_disk`, `_tensor`, `_distributed`, `_ipc` (with the
  default `flush_cache=True`) return HTTP 500 after the scheduler has already flushed or loaded
  the weights, and the requested `weight_version` is never set. RL trainers see every update fail.
- `Engine.flush_cache()`, `Engine.update_weights_from_tensor()` and `Engine.shutdown()` raise.
- With `SGLANG_MM_PRECOMPUTE_HASH=1` every multimodal request fails (`hash_executor`), so the
  server fails its own warm-up and does not start.
- `/v1/decisions` with an image is rejected (`images require a processor exposing image markers`),
  although `PixtralProcessor` has them.

## Modifications

- `LlavaMultimodalProcessor.__new__` builds and returns the selected processor
  (`PixtralProcessor`, `LlavaImageProcessor`) instead of wrapping it, so the server holds a fully
  initialized processor; `_get_sgl_processor_cls` becomes a static method, and the forwarding
  `process_mm_data_async` goes away. Registration and `get_mm_processor_cls` are unchanged.
- `test/registered/unit/models/test_llava.py`: one CPU case that builds the processor for a
  `LlavaConfig` with the real base `__init__`, clears its preprocess cache and shuts it down.

## Accuracy Tests

No model, kernel or forward code changes.

```bash
python3 test/registered/unit/models/test_llava.py -v
```

Without the change the new case errors, in the test and in its `shutdown` cleanup:
`'LlavaMultimodalProcessor' object has no attribute 'mm_preprocess_cache'`. With it all four
cases pass.
`pytest` on `test_llava.py`, `test_mistral3_vision_feature.py`, `unit/multimodal` and
`unit/managers` (GPUs hidden): 3 failed, 1180 passed, 2 errors without the change; 3 failed, 1181
passed, 2 errors with it. The failures and errors are the same on both and come from the test
machine: two `test_mm_process_config.py` cases stop on `parallel topology is inconsistent`, one
ViT graph test needs a GPU, and two files fail to collect without a GPU or without `cargo`.
`pre-commit run --files` passes.

End to end on one H200 each, upstream `cc811ff0c3` with and without this change, default server
arguments plus `SGLANG_VLM_CACHE_SIZE_MB=0` (the embedding cache is not cleared by a flush on main,
#36468). On each server: a 448x448 image, `/flush_cache`, `/update_weights_from_disk` to a copy of
the checkpoint with `multi_modal_projector.linear_2.weight` set to zero (`weight_version` v2), two
images compared with a fresh server started on that copy, then `/update_weights_from_tensor`
restoring the tensor (v3):

| Model | | `/flush_cache` | disk update | version | answers vs fresh server | tensor update | version |
|---|---|---|---|---|---|---|---|
| `mistral-community/pixtral-12b` (now `mistral-experimental/pixtral-12b`) | main | 500 | 500 | default | identical | 500 | default |
| | this PR | 200 | 200 | v2 | identical | 200 | v3 |
| `unsloth/Mistral-Small-3.1-24B-Instruct-2503` (with #45656) | main | 500 | 500 | default | identical | 500 | default |
| | this PR | 200 | 200 | v2 | identical | 200 | v3 |

"Identical" means the same tokens with the same log probabilities. On main the weights are updated
too; only the status and the version are wrong.

On Pixtral-12B, main / this PR: `SGLANG_MM_PRECOMPUTE_HASH=1` server does not start / serves;
`/v1/decisions` with an image 400 / 200; a disk update with 16 image requests in flight 500 / 200
(all 16 requests 200 on both); `--tokenizer-worker-num 2` flush and update 500 / 200. `sgl.Engine`
on Pixtral-12B and on Ministral-3-3B (with #45656): `flush_cache`, `update_weights_from_tensor`
and `shutdown` raise on main and succeed with this PR, with no processes left behind.

Not covered: `update_weights_from_distributed` (NCCL failed on the test machine on both trees)
and `update_weights_from_ipc`; they reach the same `clear_preprocess_cache()` call. Mistral-3
checkpoints need #45656 to start on current main; FP8 ones (Ministral-3, Devstral-Small-2) then
stop at `/update_weights_from_disk` on both trees for an unrelated reason (a weight in checkpoint
layout loaded into a parameter in kernel layout). HF LLaVA checkpoints with a CLIP or SigLIP vision
tower do not start on main for other reasons.
