# Enable FlashInfer decode attention access for NVFP4 KV cache and fix Gemma4 text config

[Upstream PR](https://github.com/sgl-project/sglang/pull/43247) · state: open · merged: False

## Original PR description

## Motivation

This pull request provides complete, production-grade Blackwell (SM120 / RTX 5090) integration for NVFP4 KV cache and Gemma 4 model execution with FlashInfer:

1. **FlashInfer NVFP4 Decode Attention Access**:
   - When running models with `--kv-cache-dtype nvfp4` and `--decode-attention-backend flashinfer`, `fp4_kv_cache_quant_method.py` previously omitted `flashinfer` from decode access registration, raising `ValueError: KV cache method 'nvfp4' does not support decode with flashinfer attention backend`.
   - SGLang already implements the underlying dequant workspace in `memory_pool.py` (`get_flashinfer_decode_dequant_workspace_kv_buffer`).
   - This PR registers `flashinfer` into `_NVFP4_DQ_KV_DECODE_BACKENDS` and `KV4_ATTENTION_MHA_BACKEND_CHOICES`.

2. **Gemma 4 Configuration & Heterogeneous Architecture Fixes**:
   - In `_apply_gemma4_attention_overrides`, `text_config.is_heterogeneous` was accessed directly, raising an `AttributeError` on standard HuggingFace `Gemma4TextConfig` objects where `is_heterogeneous` is absent. Guarding this with `getattr(text_config, 'is_heterogeneous', False)` enables seamless config parsing.
   - Fixed RoPE embedding device alignment in `Gemma4RotaryEmbedding` (casting `inv_freq` to fp32 and target device before concatenation).
   - Added support for `--language-model-only` execution with heterogeneous head dimensions.

3. **Memory Pool & Stride Geometry Protection**:
   - Routed memory pool zeroing through uint8 tensor views to preserve 3D/4D tensor geometry and prevent stride corruption during FlashInfer decode operations.
   - Excluded shared dequant workspace buffers from per-layer cell size calculations to avoid memory pool over-allocation.

- **Model Compatibility**:
  - `RedHatAI/gemma-4-26B-A4B-it-NVFP4` (64k context, zero CPU offload, pure GPU speed): verified end-to-end token generation.
  - `RedHatAI/gemma-4-31B-it-NVFP4` (32k–256k context with host RAM offload): verified parsing and KV allocation.
  - `nvidia/Gemma-4-31B-IT-NVFP4`: verified config parsing and speculative draft layers.
