# ROCm: add Triton fallback for DSV4 indexer query

[Upstream PR](https://github.com/sgl-project/sglang/pull/32439) · state: closed · merged: False

## Original PR description

  ## Motivation
  The native DSV4 indexer-Q ROCm operator is unavailable on MI250X/gfx90a, causing the indexer path to fail.
  ## Changes
  - Add a portable Triton implementation of the fused indexer-Q operation:
    - RoPE
    - normalized 128-point Walsh–Hadamard transform
    - dynamic FP8 quantization
    - weight-scale adjustment
  - Automatically use Triton on ROCm when the native operator is unavailable.
  - Preserve the existing native path when the operator is present.
  - Add correctness and dispatch tests against an independent PyTorch reference.
  ## Results
  - Tested on AMD MI250X (`gfx90a`)
  - 3 tests passed
  - Exact FP8 output parity with the reference
  - Approximately 10x faster than the unfused PyTorch reference in local microbenchmarks
  ## Test plan

## Speed Tests and Profiling
 ## Performance
  Microbenchmark on AMD MI250X (`gfx90a`) with 64 indexer heads, comparing the fused Triton kernel against the
  unfused PyTorch reference:
  | Tokens | Speedup |
  |-------:|--------:|
  | 1      | 10.2×   |
  | 8      | 10.5×   |
  | 128    | 10.1×   |
  | 512    | 6.0×    |
  
  
  The Triton implementation fuses RoPE, the 128-point Hadamard transform, FP8 quantization, and weight scaling into
  one GPU launch, avoiding intermediate tensors and multiple kernel launches.
  The native ROCm operator was unavailable on this MI250X build, so these results do not compare Triton against the
  native implementation.
