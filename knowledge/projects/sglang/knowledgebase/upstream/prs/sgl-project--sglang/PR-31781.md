# feat(flexkv): support hybrid cache with shared restore lifecycle

[Upstream PR](https://github.com/sgl-project/sglang/pull/31781) · state: open · merged: False

## Original PR description

## Summary

Extend FlexKV to DeepSeek V4's split C4/C128/SWA pools while preserving SGLang's admission and cache-ownership contracts. Ordinary models use the FlexKV radix adapter; hybrid models wrap UnifiedRadixCache for FULL/SWA bookkeeping. The connector and transfer implementation remain in the external FlexKV package.

- Share request identity, restore leases, reset reclamation, and prefetch lifecycle between both adapters.
- Keep asynchronous H2D destinations request-owned until normal cache commit; retain Store sources until transfer completion. Cross-rank polling stays in the synchronized scheduler hook.
- Support optional chunked storage prefetch and ordinary-cache duplicate-restore deferral. Deferred Store mapping is retained for supported ordinary-cache topologies; hybrid SWA keeps synchronous mapping.
- Include physical SWA eviction accounting from `a144fb1d23`, and merge upstream main `77983865d8`.

## Review fixes and scope cleanup

- Fix abort releasing staged/launched Store source locks before DMA completion.
- Preserve LoRA/extra-key and cache-salt identity through lookup, delayed Store and ordinary/chunked prefetch using a shared JSON namespace. Enable scoped host reuse only when the connector explicitly advertises support; older connectors continue to skip all FlexKV I/O for scoped requests. Paired FlexKV changes: taco-project/FlexKV#304 and taco-project/FlexKV#291. Deployments that previously published unscoped KV for namespaced requests must use a fresh host/remote cache pool.
- Make explicit `--radix-cache-backend=flexkv` load the factory, honor configuration, poll completions, and retry admission just like `--enable-flexkv`.
- Reject incompatible streaming-session and built-in HiCache combinations before connector initialization.
- Reject EAGLE-style bigram cache keys before importing or initializing the connector. This covers both selection flags and ordinary/hybrid adapters; EAGLE, EAGLE3, and FROZEN_KV_MTP currently use these keys. The token-only connector cannot preserve their extra boundary token.
- Remove duplicated lifecycle methods, unreachable hybrid async-mapping queues, the redundant MP/IP lookup wrapper, and the unused load stream. Remove unrelated process-wide SIGINT/watchdog changes.
- Replace stale setup/performance claims in the integration README with current contracts and validation boundaries.

If `swa_indices` becomes empty after slicing (i.e., when all indices are unmapped), returning an empty tensor of shape `(0,)` might cause issues downstream. It is safer to return `None` when no SWA slots are mapped, consistent with the earlier check `if not bool(mapped.any()): return None`.

```suggestion
        unmapped = (~mapped).nonzero(as_tuple=False)
        if unmapped.numel() > 0:
            swa_indices = swa_indices[int(unmapped[-1].item()) + 1 :]
        if swa_indices.numel() == 0:
            return None
        if not bool((swa_indices > 0).all()):
            raise RuntimeError("SWA slot mapping contains the reserved slot 0")
        return swa_indices
```

Delegating all attribute lookups via `__getattr__` can cause unexpected issues or infinite recursion during copying, deepcopying, or pickling when Python's internal magic methods (e.g., `__setstate__`, `__getstate__`, `__deepcopy__`) are queried. It is a best practice to explicitly raise `AttributeError` for any attribute names starting with `__`.

```suggestion
    def __getattr__(self, name: str) -> Any:
        if name.startswith("__"):
            raise AttributeError(name)
        inner = self.__dict__.get("_inner_cache")
        if inner is None:
            raise AttributeError(name)
        return getattr(inner, name)
```
