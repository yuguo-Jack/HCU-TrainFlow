# [MoE] [minimax-m3] Add a memory-efficient contiguous DeepGEMM path for pure TP

[Upstream PR](https://github.com/sgl-project/sglang/pull/32524) · state: closed · merged: False

## Motivation

Under pure TP, every rank owns all 129 MiniMax-M3 experts. The masked DeepGEMM path allocates token capacity for every expert, while each token is only routed to 5 experts. Its allocation overhead therefore approaches `129 / 5 = 25.8x`, rather than approaching 1 as the batch grows. At 16384 prefill tokens, these temporary MoE buffers can use about 25 GB.

The contiguous layout packs the routed rows together. It still has alignment padding between experts, but the overhead approaches 1 at large batch sizes. The primary goal of this PR is to reduce additional memory usage while simultaneously lowering decoding latency.

## Modifications

- Added an optional contiguous DeepGEMM path for the standard dispatcher in pure TP mode, enabled via the environment variable `SGLANG_ENABLE_DEEPGEMM_PURE_TP_CONTIGUOUS_MOE=1`; the original masked path remains the default.
- Implemented GPU-side expert counting, padding, and offset calculations, as well as Scatter and Gather operations.
- Utilized host-side (CPU) upper-bound values ​​for allocation to avoid introducing GPU-to-CPU synchronization during the preparation phase.
- Added a standalone benchmark and correctness tests comparing the new path against the masked path.

## Accuracy Tests

`test/registered/moe/test_deep_gemm_contiguous.py` compares contiguous and masked outputs on SM100/MXFP8.

We verified the correctness of the change on MiniMax-M3, achieving an accuracy of 0.9672 on the GSM8K dataset, compared to the original 0.9695.

Align32 is much better for decode, but becomes much worse once prefill grows beyond 1024 tokens. I did not include this setting in the PR because `set_mk_alignment_for_contiguous_layout` changes the alignment globally for contiguous DeepGEMM calls. SGLang currently cannot select align32 for decode and align128 for prefill on each call. A per-call DeepGEMM option would make that policy possible.
