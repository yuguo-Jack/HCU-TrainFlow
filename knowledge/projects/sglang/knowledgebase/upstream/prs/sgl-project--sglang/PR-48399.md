# [Refactor] env: Dispatch on the GPU architecture instead of env vars that restate it

[Upstream PR](https://github.com/sgl-project/sglang/pull/48399) · state: open · merged: False

## Original PR description

## Motivation

SGLang declares about 910 environment variables (819 in `srt/environ.py`, 91 in `multimodal_gen/envs.py`) and reads about 115 more raw. Many of them only restate the hardware: a path that is valid on one GPU and must be switched on by hand there, or a kill switch for a path that is already gated by architecture. This PR deletes those and decides at the read site from the GPU itself (`sglang.kernels.arch.current_arch()` / the platform helpers).

Rules used for every variable:

- **Selector that restates the hardware**: deleted; the read site checks the architecture.
- **Kill switch of a default-on, architecture-gated path**: deleted; the path keeps its existing gate. Kept when a doc tells users to set it, or a CI test uses it as the A/B control (listed below).
- **Default-off fast path for one architecture**: only the five with the strongest evidence are turned on: the cookbook already sets them on exactly that hardware, and GSM8K was checked wherever a checkpoint was available. The rest stay opt-in.

Wrong architecture gates and env bugs found during the audit are fixed here too.

**41 variables deleted** (33 declared, 8 read raw); 4 are now declared or read under their documented name.

## Behavior changes (please review these first)

| Area | Before | After |
|---|---|---|
| DeepSeek-V4 on gfx950 | `SGLANG_OPT_USE_AITER_BATCHED_GEMM`, `SGLANG_OPT_FP8_WO_A_FUSED_INVROPE`, `SGLANG_HIP_DSV4_C4_INDEXER_ROWGROUP` (and `SGLANG_OPT_HIP_FLYDSL_MXFP8` for V4.1) had to be set; every MI355X cookbook cell set them | On by default on gfx95 / gfx950 when the kernel is available. `FUSED_INVROPE` stays an opt-in on CUDA |
| DSA `flashmla_sparse_q8` (SM90) | Per-row top-k length behind `SGLANG_ENABLE_DSA_Q8KV8_TOPK_LENGTH` | Always on (bit-exact by construction: skipped blocks hold only `-1` pads) |
| MiniMax-H3 VAE | The fused residual-add + RMSNorm ran at every quality level, including `exact`, though it is not bit-exact | Runs only at `lossless` / `high`; `exact` output now equals the unfused path byte for byte |
| `SGLANG_FLASHINFER_USE_TENSOR_CORE` | Compared to `"true"`, so `=1` turned tensor cores **off** | Parsed as a boolean; unset keeps the heuristic |
| `SGLANG_FORCE_SHUTDOWN`, `SGLANG_SYNC_TOKEN_IDS_ACROSS_TP` | Documented under these names, read as `SGL_FORCE_SHUTDOWN` / `SYNC_TOKEN_IDS_ACROSS_TP`, so the documented name did nothing | Read through `envs`; the old names still work as deprecated aliases |
| `SGLANG_USE_DEEPGEMM_BMM` | `not DEEPGEMM_BLACKWELL` let SM120/121 into DeepGEMM's SM90 masked/einsum kernels; dots3 had no gate | Requires SM90 (MUSA keeps its path) |
| MiniMax-M3 NVFP4 native stack | `is_blackwell` (majors 10-12) selected MSA-v1 kernels that build for SM10x only | SM10x only |
| DeepSeek-V4.1 indexer | `major >= 10` sent SM120 into the DeepGEMM `fp8_fp4` path, which raised at build time | SM100 family only; SM120 gets the torch / Triton paths |
| DSA backend | TRT-LLM workspace allocated on SM120, where the kernel raises "Unsupported architecture" | Allocated on SM10x only |
| DeepSeek-V4 model hooks | The ROCm block overwrote 9 variables unconditionally; `SGLANG_OPT_USE_TOPK_V2` on SM120 and `SGLANG_OPT_FLASHMLA_SPARSE_PREFILL` on ROCm overwrote user values | Values the user set are kept; sets equal to the default, or for variables nothing reads on that platform, are removed |
| MegaMoE on ROCm | `--moe-a2a-backend megamoe` without `SGLANG_AMD_USE_FLYDSL_MEGA_MOE=1` ran DeepGEMM, which has no ROCm kernels | megamoe on ROCm is aiter MegaMoEv2 |
| DSpark on NPU | Needed `SGLANG_DSPARK_FAST_KERNEL=0` | Chosen by platform |
| smallm router, smallm FP8 block-scale GEMM | Admitted any `gfx95*` | `gfx950` exactly, like the other smallm kernels |
| gfx1250 MXFP4 MoE | Every recipe and test had to set `AITER_FORCE_A8W4=1` | SGLang's own decisions key on gfx1250, and startup sets the variable for aiter on gfx1250 when unset |
| DGX Spark DeepSeek-V4 recipe | Selected the `b12x` FlashMLA backend, which main does not have | Removed from the recipe |

**Diffusion:** `MINIMAX_H3_VAE_DECODER_FUSED_NORM` (now the quality gate).

## Kept on purpose

- Documented escape hatches / CI A/B controls: `SGLANG_DISABLE_MSA`, `SGLANG_K3_SP_COLLECTIVE`, `SGLANG_DISABLE_FUSED_AR_QUANT`, `SGLANG_AITER_GFX942_BLOCKSCALE_USE_CK`, `SGLANG_DISABLE_GFX1250_FP8_GEMM`, `SGLANG_ROCM_SMALLM_MOE`, `SGLANG_ROCM_DISABLE_AITER_TOPK_GATING`, `SGLANG_ROCM_SMALLM_FP8_BS` (now also gated on gfx950).
- `SGLANG_AITER_CAPTURE_COPY_IN` stays off. #43077 moved it from on to off on purpose and scoped it to the DeepSeek-V4.1 MI355X DP-attention recipe. It is now declared, and its comment no longer says the opposite of the default. On Qwen3-30B-A3B TP4 / DP4 DP-attention on MI350X, turning it on costs about 2.7% output throughput with the same GSM8K.
- The other default-off candidates stay opt-in. The closest to ready are `SGLANG_OPT_SM120_MTP_ROUTER_TOP22` (bit-exact, needs a re-benchmark) and `SGLANG_ENABLE_FP8_BLOCK_GEMV` (needs an H200 accuracy run).

## For the owners (not changed here)

- The DGX Spark DeepSeek-V4 cells are still `verified: true`, but they use the preview image and `--moe-runner-backend b12x`, which main does not have.
- MiniMax-M3 NVFP4 still keys on `is_blackwell` in `model_overrides/minimax_m3.py` and `quantization/minimax_m3_nvfp4.py`, so SM12x end to end is unsupported. This PR only stops SM12x from selecting MSA-v1.
- `single_batch_overlap.py` uses `not is_blackwell()` for the Hopper paths; switching to `is_sm(9)` would change HIP / MUSA with SBO, so it is left alone.
- The gfx950 V4.1 multi-stream branch from #41308 has never run in a server: the ROCm hook already turned `SGLANG_OPT_USE_MULTI_STREAM_OVERLAP` off. It stays off by default, and setting it to 1 now works.
- DeepGEMM `fp8_fp4_mqa_logits` also runs on SM120; the V4.1 prefill indexer could re-admit SM120 there.
- With `SGLANG_FA4_TMEM_LOAD_RED_MAX` gone there is no runtime switch back to FMNMX. Two benchmark rounds on GB300 showed `ld.red` about 5-7% slower on d64 ViT shapes and 3-10% faster on d72 / d80.

## Validation

Every changed read site was tested on base (`27aedf7f93`) and on this branch, on the hardware it runs on.

**Full sweep.** All 1,561 files under `test/registered/unit` and `multimodal_gen/test/unit`, plus the kernel tests this PR touches. Each file ran in its own process on both trees, and every failure seen only on the branch was rerun serially on both.

| Hardware | Failing only on the branch | Import / collect |
|---|---|---|
| H200 (sm_90) | 0 | identical |
| GB300 (sm_103) | 0 (3 port-in-use failures in the parallel run pass serially) | identical (+2 tests) |
| RTX 5090 (sm_120) | 0 | identical |
| MI350X (gfx950, ROCm 7.2) | 0 (13 port-in-use failures in the parallel run pass serially) | identical |

**Accuracy** (sgl-eval 0.1.3, GSM8K). DeepSeek-V4-Flash TP4, 200 questions, temperature 0.6, top-p 0.95, max tokens 8192. Base runs the recipe with the deleted variables set; the branch runs it without them:

| Setup | Base | Branch | New default path seen |
|---|---|---|---|
| GB300, cookbook FP4 low-latency | 98.0% | 97.5% | same command |
| MI350X, MI355X FP4 low-latency | 97.5% | 97.0% | `aiter::inverse_rope_group_quant_kernel` in the trace |
| MI350X, plus `--enable-deepseek-v4-fp4-indexer` | 97.0% | 98.0% | row-group FP4 MQA logits kernel logged on every rank |
| MI350X, `SGLANG_OPT_FP8_WO_A_GEMM=false` (the CI setting) | 98.0% | 98.5% | `_batched_gemm_bf16_kernel` in the trace |

Qwen3-30B-A3B-Instruct-2507 on MI350X (TP4, DP4 DP-attention, TP MoE; all 1,319 questions, temperature 0.7): 0.9598 / 0.9545 with `SGLANG_USE_ROCM700A=0` and 0.9591 / 0.9598 with the image default (base / branch). Output throughput is within 1%.

**Targeted checks**
- MiniMax-H3 VAE on H200 with real weights: `exact` is now byte-identical to the unfused path (base differed by up to 1.36e-2), and `lossless` / `high` are byte-identical to base.
- FA4 on sm_103: `test_flash_attention_4_sm103.py` still checks FMNMX against `ld.red` bit-exactly (62 passed).
- FlyDSL MXFP8 GEMM on gfx950, now the default on the V4.1 route: matches an fp32 reference within bf16 rounding for M = 2048-8192. No V4.1 checkpoint was available for an end-to-end run.
- Probes: `SGLANG_FORCE_SHUTDOWN=1`, `SGLANG_SYNC_TOKEN_IDS_ACROSS_TP=true` and `SGLANG_FLASHINFER_USE_TENSOR_CORE=1` take effect only on the branch, and the old names still work. The changed arch gates were probed on H200, GB300, 5090 and MI350X, and mocked as gfx942 / gfx1151 / gfx1250 / gfx115x.
- `cargo clippy -p sglang-server -- -D warnings` passes on Linux; the Rust changes are doc comments only.

After merging main (`77c3bcbe`), the DSA metadata tests and main's new `test_dsa_kernel_metadata_hook.py` were rerun on H200 and pass.

**Not run on hardware:** H20 (the 78-SM rule), gfx1250 / gfx1151 / gfx115x (arch-mocked unit tests only), MegaMoE EP8 on ROCm, DGX Spark, MuseSpark finalize-AR, and MiniMax-M3 NVFP4 end to end.
