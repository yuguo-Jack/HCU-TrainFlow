# [Fix] kernel: Fix int32 overflow in MoE topk and concat_mla indexing

[Upstream PR](https://github.com/sgl-project/sglang/pull/30104) · state: open · merged: False

## Original PR description

## Motivation

Fix #29605, #29606. Row offsets and output indices in `topk_sigmoid` / `topk_softmax` (fused and fallback paths) and `concat_mla` are computed in 32-bit `int` and overflow once `num_tokens * num_experts > INT_MAX`.

## Modifications

Widen the index arithmetic to `int64_t` in both the AOT (`kernels/aot`) and JIT (`kernels/jit`) copies, plus the workspace size.

## Accuracy Tests

Added a `num_tokens * num_experts > INT_MAX` case to the existing topk sigmoid/softmax tests, skipped when GPU memory is insufficient.

## Speed Tests and Profiling

N/A: index casts only.

While widening `thread_row * ELTS_PER_ROW` to 64-bit here is correct, there are other locations in this file that still suffer from 32-bit integer overflow when `num_tokens * num_experts > INT_MAX`:

1. **Fallback Kernels**: In `moeSigmoid` (line 80) and `moeTopK` (line 123), the row offsets are computed using 32-bit signed integers:
   ```cpp
   const int thread_row_offset = blockIdx.x * num_cols;
   const int thread_read_offset = blockIdx.x * num_experts;
   ```
   These will overflow when `blockIdx.x * num_experts > INT_MAX`. They should be widened to `int64_t` (e.g., `static_cast<int64_t>(blockIdx.x) * num_cols`).

2. **Workspace Allocation**: In `topk_sigmoid` (line 531), the workspace size calculation performs a 32-bit integer multiplication before assigning to `int64_t`:
   ```cpp
   const int64_t workspace_size = needs_workspace ? num_tokens * num_experts : 0;
   ```
   This will overflow and wrap around to a negative value when `num_tokens * num_experts > INT_MAX` and `needs_workspace` is true, leading to a crash in `torch::empty`. It should be:
   ```cpp
   const int64_t workspace_size = needs_workspace ? static_cast<int64_t>(num_tokens) * num_experts : 0;
   ```
