# multimodal: keep the images of a chat request sent as token IDs, and locate them by placeholder ID

[Upstream PR](https://github.com/sgl-project/sglang/pull/44133) · state: open · merged: False

## Original PR description

**Problem.** For RL, the client sends the prompt as token IDs so the engine runs exactly what the trainer will score. Two bugs break this for requests with images.

1. On the chat endpoint, a request sent as token IDs loses its images. The model answers a prompt whose image placeholders stand for nothing.
2. To find the images, the server turns the IDs back into text and searches for placeholder strings. Text that only spells a placeholder (for example `<image>` in HTML the model wrote) counts as one more image, and the request fails with HTTP 500. In our RL runs that cost 3 episodes in the first hour.

Example 1. Both bugs on one request, before and after, Qwen3.8-27B-VL.

```text
bug 1, token IDs: 21 IDs with 1 placeholder, plus 1 image (1024x576 = 576 image tokens)
    now:   images dropped -> the engine runs 21 IDs, text only
    fixed: the engine runs 20 + 576 = 596 IDs, ID for ID
bug 2, prompt: 1 screenshot + an earlier reply with "<div><image></div>"
    now:   2 placeholders found, 1 image given -> HTTP 500
    fixed: 1 placeholder ID = 1 image; "<image>" stays text -> HTTP 200
```

**Change.**

- Bug 1. When a multimodal model gets a request with token IDs, the chat endpoint collects the images, videos and audio from the messages, as the template path does, and passes them with the IDs. Text-only models and requests without IDs are unchanged.
- Bug 2. The fix skips the decode-and-search step for ID prompts. It finds images by counting the placeholder ID, which already sits in the list. That's simpler, and it can't be fooled by text, because typed text never produces the placeholder ID. Each image is one placeholder ID, or one run of them if the client already expanded it; any other count is a 400. The engine then runs the client's IDs as sent, with each placeholder expanded to its image's tokens by the existing exact-token code ([sglang#26555](https://github.com/sgl-project/sglang/pull/26555)). If expansion fails, the request fails instead of quietly re-tokenizing. Requests sent as text, requests with video, audio or precomputed features, and requests with `SGLANG_MM_AVOID_RETOKENIZE` off keep the old path.

Example 2. Bug 2 on one request with 1 screenshot, before and after. Qwen3.8-27B-VL; the placeholder `<|image_pad|>` is ID 248056, and the text `<div><image></div>` tokenizes to `[2539, 1721, 1742, 1419, 596, 29]`.

```text
BEFORE
  IDs: [... 20 text IDs ..., 248056, ..., 2539, 1721, 1742, 1419, 596, 29, ...]  + 1 image
    │
    ├─ decode IDs to text ──► "...<|vision_start|><|image_pad|><|vision_end|> ... <div><image></div> ..."
    ├─ regex split on  <|vision_start|><|image_pad|>+<|vision_end|>  or  <image>
    └─ 2 markers found, 1 image attached ──► "More 'IMAGE' tokens found" ──► HTTP 500

AFTER
  IDs: same  + 1 image
    │
    ├─ count ID 248056 in the IDs ──► 1      ("<image>" is the text IDs 1742, 1419, 596, never 248056)
    ├─ 1 placeholder, 1 image ──► match
    └─ keep the IDs; expand 248056 to the image's 576 tokens ──► engine runs the IDs as sent ──► HTTP 200
```

Chat endpoint with token IDs (unit, and end to end on Qwen2.5-VL-3B-Instruct):

- A request with token IDs on a multimodal model keeps its images; on a text-only model it carries none.
- "D" + "escribe" + one placeholder + one 64x64 image through `/v1/chat/completions` runs as `len(input_ids) - 1 + N` prompt tokens, the same count as `/generate` for the same IDs and image.
- The same text without the image keeps `len(input_ids)` prompt tokens.

Loaders on an ID prompt:

- One ID per image is read first; a run of placeholder IDs counts as one image.
- Both loaders run an ID prompt with a tokenizer whose `decode()` raises, so the decoded text is never produced.
- 2 placeholders with 1 image is a client error (`ValueError`), not a 500.
- With `SGLANG_MM_AVOID_RETOKENIZE` off, an ID prompt keeps the text path.
- Text prompts, video, audio and precomputed features keep the text path.
