# [Fix] [AMD] deterministic: Run FP8 MoE experts through the Triton runner on ROCm

[Upstream PR](https://github.com/sgl-project/sglang/pull/47414) · state: open · merged: False

## Original PR description

## Motivation

With `--enable-deterministic-inference` on ROCm, FP8 MoE experts still run through AITER's fused MoE when `--moe-runner-backend` is `auto`. Its configuration depends on the token count, so a token's result depends on the other tokens in its batch: Qwen3-30B-A3B-FP8 in deterministic mode on MI350X gives 19-21 different outputs for 50 identical requests. SGLang's Triton MoE runner uses one fixed configuration in deterministic mode.

**Which models this affects.** FP8 MoE checkpoints on ROCm in deterministic mode (Qwen3-30B-A3B-FP8 tested; other FP8 MoE models take the same runner selection, untested). MXFP4 and MXFP8 experts (gpt-oss, MiniMax-M3) and INT4 weights are unchanged.

## Modifications

- `layers/quantization/fp8.py`: `Fp8MoEMethod._deterministic_fp8_experts_on_triton()`; when the runner backend is `auto`, deterministic mode keeps FP8 experts off the AITER runner (the Triton runner is used). MXFP4 / MXFP8 experts, INT4 weights, an explicit `--moe-runner-backend` and normal mode are unchanged.
- New test `test/registered/unit/layers/quantization/test_fp8_moe_deterministic_runner.py`: the runner choice for deterministic and normal mode, FP4 / MXFP8 / INT4 experts and an explicit backend.

## Accuracy Tests

MI350X (gfx950), ROCm 7.2.4, `rocm/sgl-dev:v0.5.22-rocm724-mi35x-20261021`, deterministic mode (`--enable-deterministic-inference`) together with the other open MI350X deterministic-mode changes (the same in every run). Checks: `python3 -m sglang.test.test_deterministic` (`single`, `prefix`, `prefix --return-logprob`, `radix_cache`, 50 trials) plus a bitwise batch-size check (the same prompt in batches of 1 to 50, 1,275 responses, token IDs and logprobs compared exactly with the batch-size-1 response). GSM8K through sgl-eval, 1,319 questions, temperature 0.

- Qwen3-30B-A3B-FP8 TP1 with this change alone: every check passes (9 / 9 `Unique samples: 1`, logprobs identical, bitwise 1,275 / 1,275); before: single 19-21 outputs.
- With the block-FP8 linear change too, no flags: every check passes at TP1 (2 / 2 fresh servers), TP2 (2 / 2) and TP4 (1 / 1). GSM8K 95.38% (TP1), 94.92% (TP2).
- The unit test passes on MI350X (1 passed, 5 subtests).

## Speed Tests and Profiling

Qwen3-30B-A3B-FP8, deterministic mode with both FP8 changes, output throughput 1k in / 1k out: TP2 6,792 tok/s (before, not deterministic: 8,035; normal mode 13,775); TP4 10,537 tok/s (normal 20,683). This is the cost of correct results; normal mode is unchanged.
