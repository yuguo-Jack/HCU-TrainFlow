# [Doc] server-args: Sync the --quantization and --kv-cache-dtype choices with the parser

[Upstream PR](https://github.com/sgl-project/sglang/pull/44562) · state: open · merged: False

## Original PR description

## Motivation

Two rows in the server arguments docs list choices that no longer match the parser.

The `--quantization` row lists `marlin` as a choice, but the parser rejects it:

```
error: argument --quantization: invalid choice: 'marlin'
```

`--quantization` takes its choices from `QUANTIZATION_CHOICES` in `python/sglang/srt/arg_groups/choices.py`, which has no `marlin` entry. The row was also missing three choices the parser accepts: `auto-round-int8`, `mxfp_w4a8` and `humming`.

The `--kv-cache-dtype` row in the same table is missing `mxfp8`, which the parser accepts (`python/sglang/srt/arg_groups/fields/model.py`), and its description is missing the help text's sentence about it.

## Modifications

- `--quantization`: the choices now match `QUANTIZATION_CHOICES` exactly, in the same order. `marlin` is removed; `auto-round-int8`, `mxfp_w4a8` and `humming` are added.
- `--kv-cache-dtype`: `mxfp8` is added to the choices, and the description now matches the flag's help text (`"mxfp8" is supported by the FA4 backend.` and "MX-style block-size-16").

Checked by extracting the `<code>` values and the description from each row and comparing them to the lists and help string in the source (`--quantization`: 31 entries, identical; `--kv-cache-dtype`: 8 entries and the help text, identical). `test/registered/unit/server_args/test_server_args_docs_coverage.py` passes; it checks flag names, not choice lists.
