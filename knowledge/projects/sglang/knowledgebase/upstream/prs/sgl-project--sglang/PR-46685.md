# [CI] [AMD] monokernels: Bump the sgl-amd-mono pin daily

[Upstream PR](https://github.com/sgl-project/sglang/pull/46685) · state: closed · merged: True

## Original PR description

## Motivation

SGLang picks up an sgl-amd-mono change only after someone bumps the pin by hand. #46662 needs sgl-amd-mono#60, which neither `main` (`05e0bb02`) nor the open bump #45045 (`e952b221`) contains. This adds a bot that opens the bump daily.

## Modifications

- `.github/workflows/bot-bump-sgl-amd-mono-version.yml`: runs daily at 08:00 UTC, or by hand with an optional `ref`. It has the same steps as `bot-bump-kernel-version-to-sglang.yml`.
- `scripts/release/bump_sgl_amd_mono_version.py`: rewrites the pin in `python/pyproject_other.toml` and reports `needs_bump`.
- `scripts/release/commit_and_pr_sgl_amd_mono.sh`: opens a PR from `bot/bump-sgl-amd-mono-<sha8>` that lists the sgl-amd-mono commits, and closes the bump PR it supersedes.
- `.github/scripts/pr-title.test.cjs` and `scripts/release/README.md`: the title check and the docs.

How the bot behaves:

- A commit that already has a PR, open or closed, is skipped, so closing a bump PR without merging rejects that commit.
- The PAT closes a superseded PR, which triggers `cancel-pr-workflows-on-close.yml` to cancel its CI.
- Pushes use `GITHUB_TOKEN`, because `GH_PAT_FOR_PULL_REQUEST` cannot push (#25926). `gh` uses the PAT, so bump PRs get CI runs.
- It adds no `run-ci` label (#13486). Comment `/tag-and-rerun-ci` on a bump PR to run its CI.
- CI on a bump PR shows that the pin installs. It does not run the monokernel: no GPU test enables it, and plugin load errors are only logged.
