# [Fix] unified-memory: Refuse an MXFP8 KV cache at boot

[Upstream PR](https://github.com/sgl-project/sglang/pull/46374) · state: open · merged: False

## Original PR description

## Motivation

`--kv-cache-dtype mxfp8` (SM100 and newer) stores the KV cache as fp8 rows plus a scale factor per 32-element block. The default pool keeps both in `MHATokenToKVPoolMXFP8`, and the FA4 MXFP8 attention path reads the scales from the pool. The unified memory pool (`--enable-unified-memory`) builds only the fp8 rows: `MHAView` leaves `k_scale_buffer` and `v_scale_buffer` as `None`. So the combination passes the boot checks and has no scale buffers for the kernel to read.

The FP4 KV cache already refuses `--enable-unified-memory` at boot for the same reason (`handle_kv4_compatibility`).

## Modifications

- `handle_mxfp8_kv_cache_compatibility` (`arg_groups/kv_cache_hook.py`) now raises a `ValueError` when `--kv-cache-dtype mxfp8` is combined with `--enable-unified-memory`, after its existing SM100 check. The message names the flag and the reason. MXFP8 without unified memory is unchanged.

Test (CPU), `test/registered/unit/server_args/test_server_args.py`: `TestMXFP8KVCacheCompatibility::test_mxfp8_rejects_unified_memory` overrides the platform to SM100 and checks that mxfp8 alone resolves and that mxfp8 with `--enable-unified-memory` raises. It fails on main and passes with this PR.
