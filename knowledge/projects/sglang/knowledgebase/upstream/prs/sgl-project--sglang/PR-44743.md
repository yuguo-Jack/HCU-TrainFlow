# Validate stop_token_ids against vocab_size in SamplingParams.verify

[Upstream PR](https://github.com/sgl-project/sglang/pull/44743) · state: closed · merged: False

## Original PR description

## Motivation

A `stop_token_ids` entry outside `[0, vocab_size)` crashes the server whenever
any request in the batch sets `min_new_tokens > 0`: `SamplingParams.verify()`
checked `logit_bias` keys against `vocab_size` but not `stop_token_ids`, so the
bad id reached `BatchedMinNewTokensPenalizer._prepare`
(`penaltylib/min_new_tokens.py:65`), where `scatter_add_` into a
`[batch, vocab_size + 1]` CUDA tensor trips a device-side assert and takes down
all in-flight requests (not just the offending one).

Fixes #44535 (item 2 of #31597, whose fix PR #31561 was auto-closed before
review).

## Modifications

- `python/sglang/srt/sampling/sampling_params.py`: `SamplingParams.verify()`
  now rejects `stop_token_ids` outside `[0, vocab_size)` with a `ValueError`,
  mirroring the existing `logit_bias` check. The check runs at admission time
  in `TokenizerManager` before any GPU work, so `http_server` maps it to
  HTTP 400 — the same behavior the issue asked for. This single point covers
  `/generate`, `/v1/chat/completions`, and `/v1/completions`, since all three
  funnel through `verify()`.
- `test/registered/unit/sampling/test_sampling_params.py`: added four
  `TestSamplingParamsVerify` cases — out-of-vocab id raises, negative id
  raises, `[0, vocab_size - 1]` boundaries accepted, and unset
  `stop_token_ids` skips the check.

## Tests

- Exercised the actual `verify()` method (extracted verbatim from the repo
  source via AST, run with a stub `self` and a stub for
  `get_request_reasoning_end_token_ids`): in-range set passes, `None` passes,
  `1000000` / `-1` / `32000` with `vocab_size=32000` raise with message
  `"stop_token_ids must be in [0, 31999], got <id>"`, including the issue's
  exact repro combination (`min_new_tokens=1`, `stop_token_ids=[1000000]`).
- New unit tests in `test_sampling_params.py` assert the same behavior.
- Not verifiable here: a live server end-to-end run (no GPU on this machine),
  and the full registered CPU suite (the `sglang` package needs heavy
  third-party deps not installed in this environment).
- `ruff check --select F401,F821,F823,UP037`: pass. `ruff format --check`:
  pass. `py_compile`: pass. `git diff --check`: clean, no added line over
  88 columns.
