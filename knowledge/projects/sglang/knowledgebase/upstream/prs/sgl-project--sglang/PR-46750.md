# [CI] [AMD] miles-nightly: Split the 8-GPU suite into two jobs

[Upstream PR](https://github.com/sgl-project/sglang/pull/46750) · state: closed · merged: True

## Original PR description

## Motivation

radixark/miles#4325 added six tests to the miles `nightly-stage-c-8-gpu-mi350` suite, raising its estimated time from 16600s to 23600s. Since then the single 8-GPU job in both miles nightlies runs into the step timeout:

- MI35X: `The action 'Run miles CI suite nightly-stage-c-8-gpu-mi350' has timed out after 180 minutes` on 10-25 and 10-26 ([10-26 run](https://github.com/sgl-project/sglang/actions/runs/40370401626)). Before the new tests landed it passed in ~150 min.
- MI30X: timed out after 300 minutes on 10-25 and 10-26 ([10-26 run](https://github.com/sgl-project/sglang/actions/runs/40401635417)).

## Modifications

Split the 8-GPU suite into two jobs with `run_suite.py --auto-partition-id/--auto-partition-size`, the same way the MI35X 4-GPU suite is already split. Applied to both `nightly-test-amd-miles-rocm10.yml` (MI35X) and `nightly-test-amd-miles-rocm10-mi30x.yml` (MI30X).

The MI30X job also gets the same `name:` template as the MI35X one, so the parts show up as `part 1/2` / `part 2/2` instead of a list of every matrix value.

With the estimates in miles main, the split is 11700s / 11900s. No single test hangs: on 10-26 the MI35X job finished 18 of 25 tests normally and was killed partway through the 19th. With the per-test times from that run (and 10-24 for the last seven), the two halves come to about 129 and 97 min of test time on MI35X, against the 180-min timeout.
