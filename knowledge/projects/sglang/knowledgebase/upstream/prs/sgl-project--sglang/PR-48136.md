# [Refactor] memory-pool: Report device pool roles in buffer info

[Upstream PR](https://github.com/sgl-project/sglang/pull/48136) · state: open · merged: False

## Original PR description

## Motivation

Followup of #47928. Draft sidecar dispatch still named DeepSeek-V4 by type, and fused draft admission read a `DraftMHAView`'s private sub-pool name and arena. Device pool infos could not answer either question because every view reported itself as KV, and `SWAKVPool` had no description at all. This PR makes pools report their roles so both decisions read infos.

## Modifications

- `MHAView`, `MLAView` and `DraftMHAView` take the host pool their sub-pool mirrors and report it, so a window view is described as SWA.
- `SWAKVPool.get_device_pool_infos` reports the full side and the window side as SWA, in model layer IDs, with `indices_from_pool=KV` when the window uses full indices.
- `build_hicache_draft_sidecars` picks the SWA builder when the draft describes window KV, the full builder when it describes KV or wraps a hybrid child, and rejects anything else with the existing error.
- `validate_fused_hicache_draft` admits a single full KV description and checks that the draft and the target share one allocation.

## Accuracy

HiCache multi-turn KL with forced host hits on MHA, MLA, MLA with a separate draft, SWA with a separate draft, unified SWA and Mamba hybrid, against #47928. Every model passes, and the assembly plan, the H2D copies and the host transfers are identical. A byte level host probe over every HiCache host builder (444 cases across layouts and IO backends) matches #47928 exactly.
