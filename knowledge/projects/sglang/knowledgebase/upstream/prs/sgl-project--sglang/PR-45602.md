# [Doc] [NPU] deepseek-v4: Add A3/950 single-node cookbook recipes

[Upstream PR](https://github.com/sgl-project/sglang/pull/45602) · state: closed · merged: True

## Original PR description

## Motivation

The DeepSeek-V4 cookbook deploy matrix covered CUDA and ROCm only; there was no Ascend path, so the docs could not emit a runnable NPU command for this model.

Add the Ascend single-node recipes that were validated locally, with the quantization row resolved per chip: the A3 Series serves the ModelSlim W8A8 checkpoint, the 950PR/DT Series (`a5`) serves the FP8 checkpoint.

## Modifications

Only `docs/src/snippets/configs/deepseek-ai/deepseek-v4.jsx` changes.

- `supportedHardware`: add `a3` and `a5`. Labels, VRAM and `npuDevices` come from the shared `HARDWARE_CATALOG`, so the engine already renders the docker `--device` block (16 davinci cores on A3, 8 on 950PR/DT).
- Add an `isNpuHw` predicate on `config` (Mintlify strips module-level statements, so shared predicates live on the exported object, same as `kimi-k3`).
- Gate the quantization row per platform:
  - A3: `Modelslim (W8A8)` only.
  - A5 (950PR/DT): `FP8` only.
  - CUDA / ROCm: unchanged (`FP8`, `FP4`, `NVFP4`).
  - Hidden picks are re-seated on the next visible option, so switching hardware never leaves a value the new chip cannot run.
- `modelNames`: A3 resolves to `Eco-Tech/DeepSeek-V4-Flash-0731-w8a8`; A5 resolves to `deepseek-ai/DeepSeek-V4-Flash-0731`.
- Add two `in-progress` single-node cells:
  - A3 `flash-official / modelslim / balanced / single`: TP16 + DP attention, DSpark (block size 5, 6 draft tokens), static ragged verify, `SGLANG_DSV4_FP4_EXPERTS=False` for the W8A8 checkpoint.
  - A5 `flash-official / fp8 / balanced / single`: TP4 + DP attention, DSpark, mixed FP8 + FP4 routed experts, env set transcribed from the local run.
- Disable (with a reason) the FlashInfer and Marlin MoE runner options on NPU instead of hiding them, so the constraint stays visible in the UI.

Both cells are `verified: false` / `verificationStatus: "in-progress"` and will stay that way until they are re-run on a release build.

Not in this PR: NPU docker image tags (`dockerImages` still has a TODO for `a3:` / `a5:`, so the docker tab falls back to `lmsysorg/sglang:dev`), and the DeepSeek-V4-Flash tutorial page.
