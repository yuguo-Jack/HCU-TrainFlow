# [Fix] DSpark: Make the simulated-acceptance sampling skip opt-in

[Upstream PR](https://github.com/sgl-project/sglang/pull/46864) · state: closed · merged: False

## Original PR description

## Motivation

Since #45421, the DSpark eager accept path skips the sampling accept (draft/target softmax + rejection) whenever `SGLANG_SIMULATE_ACC_LEN` is set, on CUDA as well as HIP, with no way to turn it off. Simulated-acceptance benchmarks should keep the real sampling-accept cost by default, so their numbers are not lower-bounded by skipped work.

## Modifications

- Add `SGLANG_ENABLE_DSPARK_SIMULATE_SKIP_SAMPLING = EnvBool(False)` in `environ.py`, next to the other DSpark simulation knobs.
- In `TargetVerifyExecutor.accept_and_finalize`, skip the sampling accept only when simulated acceptance is active **and** this flag is set. Default behavior now runs the sampling accept and then applies the simulated `correct_len`, as before #45421 on CUDA.
- `SGLANG_SIMULATE_ACC_GREEDY` and `SGLANG_DSPARK_SIMULATE_FOLD` already default to `False`; unchanged.

## Accuracy Tests

No change to model outputs: with simulated acceptance, `correct_len` is overwritten by the simulation either way; without simulated acceptance, this code path is unchanged.

## Speed Tests and Profiling

Default simulated-acceptance runs regain the sampling-accept cost that #45421 removed; runs that want the old behavior set `SGLANG_ENABLE_DSPARK_SIMULATE_SKIP_SAMPLING=1`.

[by Claude Code] **Severity: functional | Confidence: Medium**

**Issue**

The new flag only works in `accept_and_finalize`. With `SGLANG_OPT_DSV41_SAMPLING_ACCEPT_GRAPH=1`, all-sampled static steps use `DsparkSamplingAcceptGraph` instead, and its `sampling_accept_commit_lens` always runs the sampling accept (softmax + rejection) under `SGLANG_SIMULATE_ACC_LEN`. The `environ.py` comment does not mention this limit.

**Example**

The DeepSeek-V4.1-Flash AgentX recipe sets `SGLANG_OPT_DSV41_SAMPLING_ACCEPT_GRAPH=1`. A simulated run with temperature > 0 and this flag set still pays the sampling-accept cost on those steps.

**Fix**

Read the flag once at init, like `simulate_fold`, and pass `sampling_info=None` to `accept_draft_tokens` in `sampling_accept_commit_lens` when it is set; that region already takes the bonus from `epilogue.sim_bonus`. Or say in the `environ.py` comment that the flag covers only the eager accept.
