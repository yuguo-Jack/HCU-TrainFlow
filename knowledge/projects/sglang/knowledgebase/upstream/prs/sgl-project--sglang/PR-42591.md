# [Fix] llama3.2: Fix quadratic brace scan in the tool-call parser

[Upstream PR](https://github.com/sgl-project/sglang/pull/42591) · state: open · merged: False

## Original PR description

## Motivation

When an object in `Llama32Detector.detect_and_parse` (`llama3`) fails to decode as JSON, the Python-dict fallback looks for the matching `}` with a character-by-character Python loop starting from the failed start. If the braces never balance, every `{"name":` start rescans to the end of the text:

| Input (one non-streaming parse) | Before | After |
|---|---|---|
| 126 KB of repeated `<|python_tag|>{"name":"` | 38 – 59 s | 0.08 s |
| 120 KB of `{"name": {` | 93 – 108 s | 0.16 s |

Tool-call parsing runs synchronously on the tokenizer manager's event loop, so one such response stalls every in-flight request. Found with an Atheris fuzzing harness that records per-input parse time.

## Modifications

- `_make_brace_matcher`: on the first failed decode, index every brace position and the running brace level once. "The first `}` at or after `idx` that brings the count started at `idx` back to 0" is then "the first `}` at or after `idx` whose global level equals the level just before `idx`", which is a bisect lookup instead of a scan. It returns exactly the position the loop produced (including "no match", which falls back to `idx` as before).
- Regression test `test_unbalanced_braces_parse_in_linear_time` in `test_llama32_detector.py` (fails on `main`, passes here).

Residual: `raw_decode(action_text[idx:])` still slices the remaining text on every failed attempt, a much smaller super-linear term (0.25 s at 120 KB, 0.67 s at 240 KB). Passing `idx` to `raw_decode` instead was slower, because each `JSONDecodeError` counts line numbers from position 0, so this PR leaves it.

## Accuracy Tests

- Brace matcher vs the old loop on 300k random strings, at every start index: identical.
- Differential test of `main` vs patched detector (20k random + 20k mutated well-formed JSON / Python-dict inputs, streaming under random re-chunking and non-streaming): **0 mismatches** (9.5k produced parsed calls).
- `test/registered/unit/function_call/`: 630 passed.
