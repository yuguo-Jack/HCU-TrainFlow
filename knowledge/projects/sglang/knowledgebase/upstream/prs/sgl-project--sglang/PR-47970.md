# [Test] cp: Re-enable the CP8 TP-decode server test with measured logprob bounds

[Upstream PR](https://github.com/sgl-project/sglang/pull/47970) · state: open · merged: False

## Original PR description

## Motivation

`test/registered/e2e/cp/test_cp_decode_attn_tp_server.py` (added in #46857) failed every run on its VERIFY versus teacher-forced CP prefill check (`atol=0.02`) with identical greedy tokens, and #47894 has since disabled it on main.

The diagnostic in #47980 measured the logprob gaps on B300 instead of guessing a bound ([run 1](https://github.com/sgl-project/sglang/actions/runs/41525986425/job/125553939201), [prefix sweep](https://github.com/sgl-project/sglang/actions/runs/41532349161/job/125575733451), [attention-DP control](https://github.com/sgl-project/sglang/actions/runs/41535250316/job/125585543365)):

| Comparison (prefill only, prefixes of 8–2100 tokens) | Mean gap | Largest single position |
|---|---|---|
| CP8 vs plain TP8 | 0.10–0.30 | 8.4 |
| **TP8 with attention DP (no CP) vs plain TP8** | 0.10–0.21 | 9.5 |
| CP8 vs attention DP | 0.10–0.31 | 7.3 |

| VERIFY vs teacher-forced prefill, same server | Max gap |
|---|---|
| plain TP8, 1-token prompt | 0.44 |
| CP8, 1-token prompt | 0.89 |
| CP8, 257/8193-token and batched prompts | ≤ 0.11 |

Valid layouts of this FP8 MoE model differ as much as CP does, so the gap is not a CP prefill bug; the test's 0.02 cross-path assumption is what fails. (The 1-token case's comment also said it stays below the CP threshold; its 33-token rescore actually runs as CP.)

## Modifications

- Re-enable the test (drop the `disabled=` added in #47894).
- VERIFY versus teacher-forced prefill (same server): per-position `atol` 1.0 (`rescore_logprob_atol`), above the measured 0.89.
- Fused versus fallback parity (two server layouts, where isolated multi-nat spikes are normal): mean absolute difference ≤ 0.4 (`fusion_parity_mean_atol`) instead of a per-position bound.
- Exact greedy-token equality is unchanged everywhere; an omitted or doubled boundary reduction changes greedy tokens. Repeated graph replay on the same server keeps `logprob_atol = 0.02`.
- Correct the 1-token case comment.

`ruff format` and the repo's ruff lint selection pass.

## Validation

Needs `/rerun-test test/registered/e2e/cp/test_cp_decode_attn_tp_server.py` on B300 before it is marked ready. The fused arm and the later cases have never run in this test (it stopped at the first case), so this is the first full run.
