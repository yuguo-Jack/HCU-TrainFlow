# [HiCache] Retry failed storage backup batches and expose terminal failures

[Upstream PR](https://github.com/sgl-project/sglang/pull/39701) · state: open · merged: False

## Original PR description

## Motivation

A failed HiCache backup batch can leave only part of a prefix in storage. Retry transient write errors so later batches can complete, and record terminal failures before releasing host resources.

Found while investigating #39444.

## Modifications

- Retry failed primary-KV and HybridCache auxiliary-pool writes through `_retry_storage_write()`, with three attempts and short backoff delays. Handle both false returns and exceptions.
- On terminal failure, set `StorageOperation.backup_failed`, log requested/completed tokens, and increment `sglang:hicache_backup_failed_tokens_total`.
- Acknowledge terminal failures to release host resources.
- Add regressions for retry success/exhaustion, acknowledgement order, shutdown during backoff, auxiliary-pool writes, and host-lock release after partial backup.

## Accuracy Tests

- `test/registered/unit/mem_cache/test_hicache_storage_backup_failure.py`: **12 passed**.
- `test/registered/unit/mem_cache/test_hicache_staged_write_back_dispatch.py`: **16 passed, 1 skipped**.
- Mooncake fault injection, Qwen3-4B, H20-3e, TP1:
  - A failed 128-page batch succeeds on retry and later batches continue.
  - Three failed attempts mark the operation failed and record 8,192 failed tokens.
  - After removing the fault, a fresh 16,011-token request restores a 16,010-token prefix.

The separate host-capacity truncation in #39444 remains.

## Speed Tests and Profiling

Not benchmarked. Failed writes can incur up to two backoff delays.
