# [Perf] diffusion: Blend VAE tile seams in one pass

[Upstream PR](https://github.com/sgl-project/sglang/pull/46240) · state: closed · merged: True

## Original PR description

## Motivation

`ParallelTiledVAE.blend_v` / `blend_h` / `blend_t` cross-fade two tiles one row (or column, or frame) at a time in a Python loop. With 512-pixel tiles on a 448 stride, each seam is 64 iterations of a slice multiply, a second multiply, an add and a copy. LTX-2.5's 1920x1088 decode has 22 seams, so the blend alone is ~5,600 small launches per rank, all host time (the GPU work is ~10 ms).

## Modifications

- `models/vaes/common.py`: the three blends call one `_blend(a, b, extent, dim)` that writes the whole seam at once. It reproduces the loop bit for bit: the loop multiplied by the Python floats `1 - i / extent` and `i / extent`, which run in the op-math dtype, so the weights are the same doubles (computed in float64 on the device) rounded to fp32 (fp64 for fp64 tensors). Each product is rounded to the tile's dtype before the add, as the loop's tensor-times-scalar ops were.

Tests:
- `test_vae_tiled_decode_groups.py::test_blend_matches_per_slice_loop`: bf16, fp16 and fp32, the three blend dims, extents 1, 7, 64 and 100 (clipped to the tile): `torch.equal` against the per-slice loop on CUDA (36 cases).

## Accuracy Tests

The output is bitwise unchanged (unit test above; on 4xB300 the LTX-2.5 MP4s keep their md5).

## Speed Tests and Profiling

4xB300, LTX-2.5 two-stage 1920x1088 x 121 frames, 2 GPUs, on top of "Split LTX tiled VAE decode across the decode-parallel ranks" and breakable CUDA graphs, synchronized stage timers, five requests after warmup each:

| | without | with |
|---|---|---|
| `LTX2AVDecodingStage` | 1.753 s | 1.705 s |
| request (client) | 5.261-5.308 s | 5.219-5.281 s |

The five MP4s are byte-identical between the two builds.
