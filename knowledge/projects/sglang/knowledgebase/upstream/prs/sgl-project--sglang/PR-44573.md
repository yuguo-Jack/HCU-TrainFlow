# [Fix] sampling: Validate stop_token_ids against vocabulary bounds in verify()

[Upstream PR](https://github.com/sgl-project/sglang/pull/44573) · state: open · merged: False

## Original PR description

## Motivation

Fixes #44535.

When `stop_token_ids` contains token IDs outside `[0, vocab_size)` (e.g. negative numbers or IDs >= `vocab_size`), `BatchedMinNewTokensPenalizer._prepare` in `penaltylib/min_new_tokens.py` executes `scatter_add_` on a `[batch, vocab_size + 1]` CUDA tensor. An out-of-range token ID triggers an out-of-bounds assert in PyTorch CUDA kernels (`idx_dim >= 0 && idx_dim < index_size`), crashing the server and terminating all in-flight requests.

While `SamplingParams.verify()` validates `logit_bias` keys against `vocab_size`, `stop_token_ids` was previously unchecked.

## Modifications

- Added bounds verification in `SamplingParams.verify()` (`python/sglang/srt/sampling/sampling_params.py`) to validate that every entry in `self.stop_token_ids` satisfies `0 <= token_id < vocab_size`, raising `ValueError` (HTTP 400) early if violated.
- Added comprehensive unit tests in `test/registered/unit/sampling/test_sampling_params.py` covering out-of-vocab token IDs, negative token IDs, and valid tokens within range.
