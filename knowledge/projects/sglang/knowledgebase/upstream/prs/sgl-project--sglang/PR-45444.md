# [Refactor] radix-tree: Make each cache action a typed CacheAction implementation

[Upstream PR](https://github.com/sgl-project/sglang/pull/45444) · state: closed · merged: True

## Original PR description

Stacked on #45439 (`oss-sync-f2543fd394`): this pull request is based on that branch and its own diff is only its top commit. Please read it after #45439; once that lands this branch is rebased onto `main`.

## Motivation

The Rust tree core hands cache actions back to the Python cache as tagged tuples. They were modelled as one `CacheAction` enum, and each concern about an action lived in its own match over every variant: the tag in `cache_action_tag`, the Python encoding in `cache_action_to_py`, and the insertion-barrier rule in the insert loop. Adding an action meant extending the enum and three switches, and the Rust tests matched enum variants to inspect payloads.

## Modifications

Each cache action becomes its own struct implementing a `CacheAction` trait (`rust/sglang-radix-tree/src/cache_action.rs`), so its payload, tag, Python encoding and insertion-barrier behaviour sit together:

- `CacheAction` has `tag()`, `requires_insert_barrier()` (default `true`; the device-free and split-bookkeeping actions opt out, as before) and, under the `python-extension` feature, `into_py_tagged()`. `CacheActions = Vec<Box<dyn CacheAction>>` replaces `Vec<CacheAction>` in the component trait and tree-core signatures.
- The ten existing actions (`FreeDeviceKV`, `FreeDeviceKVFullOnly`, `BackupKV`, `UpdatePendingBackupOnNodeSplit`, `MambaEvictExcessPathStates`, `FreeComponentDeviceSlot`, `FreeComponentHostSlot`, `RebuildFullToSwaMapping`, `RecoverSwaWithLockedFull`, `SwaRebuild`) keep their payloads and tags; a small `impl_cache_action!` macro wires each one to the trait.
- The Python encodings move from the central switch in `python_bindings.rs` to `python_bindings/cache_action.rs`, one `into_py_tagged` per action. The tuples the binding returns are unchanged, as are the emitted actions and their order, so `UnifiedRadixCache` needs no change.
- Rust tests downcast through a test-only `as_any()` instead of matching enum variants; the shared test helper `expect_action::<T>()` does the downcast and `action_kinds` reports tags.
