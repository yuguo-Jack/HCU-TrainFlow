# [Perf] [NVIDIA] quantization: Add tuned W8A8 block-FP8 GEMM configs for RTX 4090

[Upstream PR](https://github.com/sgl-project/sglang/pull/48381) · state: open · merged: False

## Original PR description

## Motivation

`get_w8a8_block_fp8_configs()` resolves a per-shape tuning file keyed by
`(N, K, device_name, dtype, block_shape)`. There is no `NVIDIA_GeForce_RTX_4090` file, so every
block-FP8 linear on Ada falls back to the built-in default tile:

```python
{"BLOCK_SIZE_M": 64, "BLOCK_SIZE_N": 128, "BLOCK_SIZE_K": 128,
 "GROUP_SIZE_M": 32, "num_warps": 4, "num_stages": 3}
```

At decode sizes that default is the wrong shape. `offs_am = (pid_m * BLOCK_SIZE_M +
tl.arange(0, BLOCK_SIZE_M)) % M` (`python/sglang/kernels/ops/gemm/fp8_kernel.py:102`) wraps the row
index, so a batch of 8 still computes 64 rows per tile, and the wasted rows are paid for in weight
traffic that a 27B model on a single 4090 has no spare bandwidth to absorb. Dropping
`BLOCK_SIZE_M` to 8 and shrinking `BLOCK_SIZE_N` recovers 1.3-1.7x on the o-proj and down-proj
shapes at batch 5-22.

The `configs/` directory already ships `dtype=fp8_w8a8, block_shape=[128, 128]` files for L40, the
other Ada part, so this looks like nobody tuned the 4090 rather than a deliberate exclusion.

## Modifications

Six config files for `device_name=NVIDIA_GeForce_RTX_4090`, `dtype=fp8_w8a8`,
`block_shape=[128, 128]`, covering the dense linears of a 27B hybrid model with hidden 5120
(Qwen3.8-27B): `N=34816` QKV, `N=16384` gate/up, `N=14336` MLP, `K=17408` down, `K=6144` o-proj,
and the vocab-parallel head `N=248320`.

Two deliberate constraints:

- **No `SWAP_AB` / `SPLIT_K`.** The same search found larger wins that need them, including +6-8%
  at `M=8192`, but those keys are `tl.constexpr` parameters of `_w8a8_block_fp8_matmul_hopper` and
  `hopper_tuned` (`fp8_kernel.py:824`) requires `get_platform().is_sm90`. On Ada they would be inert
  at best and handed to a kernel that does not declare them at worst, so they are left out. Lifting
  that gate to sm_89 is a separate change; we have the measurements if it is of interest.
- **`M=96` and `M=8192` are pinned to the default tile above.** The lookup takes the nearest M, so
  without an anchor an unmeasured mid-size batch inherits a `BLOCK_SIZE_M=8` entry and reads the
  whole weight once per 8 rows. We hit exactly that with a `chunked_prefill_size` of 4096 and it
  cost 3.6 s of TTFT. Both anchor entries are byte-identical to the previous default, so prefill and
  any larger batch keep stock behaviour and cannot regress.

## Accuracy Tests

Not affected. `BLOCK_SIZE_K` is 128 in every entry, so each output element accumulates over K in the
same order and with the same kernel as the default config; only `BLOCK_SIZE_M`, `BLOCK_SIZE_N`,
`GROUP_SIZE_M`, `num_warps` and `num_stages` change. Each candidate was additionally checked against
the default tile's output during the search (see below) before it was allowed to win.

## Speed Tests and Profiling

Each candidate ran beside the default tile in one process on the same tensors: it had to match the
default tile's output and beat it by more than the run-to-run noise floor, otherwise it was
discarded. Entries that came out under 1.02x are not in these files. 50 points survived,
measured on a card that reports `NVIDIA GeForce RTX 4090` with 49140 MiB and a max SM clock of
3105 MHz.

The decode-side wins are bandwidth-bound and should hold at stock clocks. The two shapes under 1.05x
(`N=16384` and the `N=248320` head) are worth re-checking on a stock card before trusting them, and
we would rather say that than imply a wider validation than we have.
