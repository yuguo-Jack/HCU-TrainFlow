# Fix issue #46476: DSpark draft query width on FA3/FA4

[Upstream PR](https://github.com/sgl-project/sglang/pull/46491) · state: open · merged: False

## Original PR description

## Summary

Fix incorrect draft query width in the FlashAttention backend when using DSpark speculative decoding with `sample_from_anchor=False`.

## Root Cause

The FlashAttention backend called `resolve_num_tokens_per_req()` directly to compute the speculative verify width. This did not account for DSpark's `sample_from_anchor=False` case, where each request produces **gamma+1 rows** (one extra anchor row) instead of gamma rows. The resulting width mismatch caused incorrect draft query dimensions in FlashAttention v3/v4 backends.

## Fix

Replace the direct `resolve_num_tokens_per_req()` call with `model_runner.decode_num_tokens_per_req()`, which is the single source of truth for decode-time token counts and correctly handles all speculative algorithms including DSpark.

**File changed:** `python/sglang/srt/layers/attention/flashattention_backend.py`

## Testing

- Verified that DSpark speculative decoding with FA3/FA4 backends produces correct output with `sample_from_anchor=False`.
- Standard speculative decoding paths (non-DSpark) remain unaffected since `decode_num_tokens_per_req()` returns the same value as before for those cases.

Closes #46476
