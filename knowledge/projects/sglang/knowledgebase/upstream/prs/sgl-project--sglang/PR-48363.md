# [Fix] [Intel] int8: Use backend-agnostic rounding in per_token_quant_int8

[Upstream PR](https://github.com/sgl-project/sglang/pull/48363) · state: closed · merged: False

## Original PR description

## Motivation
`per_token_quant_int8` uses `tl.extra.cuda.libdevice.round` (`__nv_roundf`) on every non-HIP backend. XPU Triton cannot link it (`ZE_RESULT_ERROR_INVALID_MODULE_UNLINKED`), so W8A8 int8 models (e.g. auto-round int8) fail on XPU.

## Modifications
- `int8_kernel.py`: use the CUDA libdevice round only on CUDA, and the backend-agnostic `libdevice.round` elsewhere (already the ROCm path). No change on CUDA or ROCm.
- New kernel test `test_per_token_quant_int8.py` (CUDA + XPU CI): quantized values, scales and sums against a torch reference for fp16/bf16/fp32, plus round-half-away-from-zero.

## Accuracy Tests
New test passes on Arc Pro B60 (2 tests, 9 subtests); without the fix it fails with `ZE_RESULT_ERROR_INVALID_MODULE_UNLINKED`. Same rounding semantics as before on CUDA.

## Speed Tests and Profiling
N/A. Same kernel; only the round intrinsic changes, off CUDA.
