# [Fix] modelopt: Preserve explicitly quantized NextN drafts

[Upstream PR](https://github.com/sgl-project/sglang/pull/44760) · state: open · merged: False

## Original PR description

## Codex notes

### Motivation

`DeepseekModelNextN` unconditionally discards `modelopt_fp4` quantization. This is correct for legacy checkpoints with bundled BF16 MTP weights, but makes a separately serialized NVFP4 MTP draft allocate unpacked weights instead of packed weights and scales.

### Modifications

- Preserve the NextN quantizer only when the checkpoint explicitly sets `quantized_mtp: true`. Checkpoints without this flag retain the BF16 fallback.
- Exclude packed MTP drafts from the legacy BF16-to-FP8 helper. Both decoder construction and expert weight conversion use this helper, so the environment flag cannot select FP8 buffers or convert packed NVFP4 weights. Legacy BF16 drafts remain eligible with the flag and DeepGEMM backend enabled.
- Read `use_per_token_activation` from checkpoint metadata so the draft can select its activation-scaling mode without a process-wide environment override that also affects the target. An explicit value takes precedence over the environment; an absent value retains the current behavior.
- Reject per-token activation metadata outside serialized W4A4 NVFP4 and reject `quantized_mtp` for non-serialized weights.

For example, the draft's `config.json` can contain:

```json
{
  "quantization_config": {
    "quant_method": "modelopt",
    "quant_algo": "NVFP4",
    "group_size": 16,
    "quantized_mtp": true,
    "use_per_token_activation": true
  }
}
```

These fields describe the exported weights; they do not convert BF16 weights. Existing exclusion metadata still controls which modules are quantized.

Related: https://github.com/sgl-project/sglang/pull/37322 addresses the same NextN loading problem through broader exclusion-mapping changes. This PR provides a smaller explicit opt-in and preserves the legacy fallback. https://github.com/sgl-project/sglang/pull/44032 covers Qwen auxiliary modules; this change is limited to the DeepSeek NextN path and ModelOpt FP4 metadata.

### Validation

The ModelOpt NVFP4 and NextN quantization CPU suites pass: **12 tests, 13 subtests**. The three added tests cover metadata precedence, legacy/default versus explicit MTP selection, and invalid format combinations. They fail against unpatched upstream `2c2986be2b05`, confirming that they exercise the new behavior. The NextN regression covers the flag on/off with DeepGEMM and FlashInfer TRT-LLM, checking both legacy and packed drafts. It fails on the packed-draft/flag-on/DeepGEMM combination before the shared-helper guard and passes after it.

```bash
PYTHONPATH=python python -m pytest \
  test/registered/unit/layers/quantization/test_modelopt_nvfp4.py \
  test/registered/unit/models/test_deepseek_nextn_quant_config.py -q
```

No full checkpoint load, model-output accuracy evaluation, or GPU benchmark was run on this upstream branch. This PR makes no throughput claim.

## Review follow-ups

- Nested `hf_quant_config.json` (`{"quantization": {...}}`) now supplies `quantized_mtp` and `use_per_token_activation` from the inner block, matching where `quant_algo` is read.
- A separately packed draft builds `eh_proj` as `ReplicatedLinear` with the preserved config so its FP4 weight loads; the quant method still honors the checkpoint's `ignore` list, so an excluded `eh_proj` stays unquantized.
- Checkpoint metadata that turns on per-token activation repeats the MoE hook's `flashinfer_cutedsl` + `deepep` rejection, which previously only saw the environment switch.
- `SGLANG_NVFP4_CKPT_FP8_NEXTN_MOE` no longer applies the BF16-to-FP8 MoE override to a packed draft.

Unit coverage: nested-block read, DeepEP rejection, FP8-override skip (`test_modelopt_nvfp4.py`, `test_deepseek_nextn_quant_config.py`); 14 CPU tests pass.
