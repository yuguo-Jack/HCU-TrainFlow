# [Fix] modelopt: Preserve explicitly quantized NextN drafts

[Upstream PR](https://github.com/sgl-project/sglang/pull/44760) · state: open · merged: False

## Original PR description

Preserve ModelOpt NVFP4 quantization for NextN drafts whose checkpoint explicitly sets `quantized_mtp: true`. Without this opt-in, legacy BF16 MTP behavior remains unchanged. This fixes packed-weight loading failures such as a **4096 vs. 2048 shape mismatch**.

Honor checkpoint exclusions for the selected NextN layer and auxiliary projections, preserve GLM Quark mapping, and prevent packed drafts from taking BF16-to-FP8 conversion paths. Read `use_per_token_activation` from checkpoint metadata, including nested `hf_quant_config.json`, with precedence over the environment; reject unsupported format/backend combinations. These fields describe exported weights, not an online conversion.

### Validation

- Focused CPU suites cover checkpoint metadata precedence, mapped exclusions, and legacy versus packed NextN behavior. Flat and nested metadata cases share one test.
- At `0dc65d5d97`, loaded and postprocessed a real [GLM-5.3-Flash-NVFP4 NextN layer](https://huggingface.co/LibertAIDAI/GLM-5.3-Flash-NVFP4/tree/caca4e6a4ebbd66f159d3d2fc256683fd6e27177) on GB300 through the production loader. Original tensor names and exclusions were retained; only the opt-in was added. Removing it reproduces the shape mismatch.
- The load used CuTeDSL W4A16 MoE with shared-expert fusion disabled and a local runtime version override. Full-target loading, generation accuracy, and throughput remain unvalidated.
