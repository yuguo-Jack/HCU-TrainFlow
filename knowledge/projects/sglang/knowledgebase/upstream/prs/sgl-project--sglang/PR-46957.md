# [diffusion] Add encode-only disagg serving with POST /encode

[Upstream PR](https://github.com/sgl-project/sglang/pull/46957) · state: closed · merged: False

## Original PR description

## Motivation

Training jobs (for example diffusion SFT in miles-diffusion) need the text-encoder outputs and VAE latents that serving computes, without running the DiT or the decoder. Disaggregated serving already runs the encoders as independent pools; this lets those pools back an encode-only deployment.

## Modifications

- `--disagg-encode-only` (head and encoder roles): the last encoder role on a request's path (`encoder`, `prompt_encoder` for text-only requests, or `image_encoder`) sends its request extras to the head instead of staging them for a denoiser. The head answers the client from that result and needs no `--denoiser-urls` or `--decoder-urls`.
- Head: `_handle_decoder_result` becomes `_handle_final_result(role)`; an encoder result restores its extras into the new `OutputBatch.encoded`. `ENCODER_RUNNING` and `IMAGE_ENCODER_RUNNING` may transition to `DONE`.
- `POST /encode` (mounted only on encode-only servers): `prompt`, optional `image_path`, `width`, `height`, `extra_sampling_params`; returns msgpack `{request_id, encoded}` with the `/rollout/generate` tensor serialization. Clients key caches with the existing `/model_info` and `/server_info`.
- Docs (`disaggregation.mdx`, `cli.mdx`) and a head protocol test for the combined and split encoder topologies.

## Tests

- `test/unit/test_disagg_orchestration.py`: 46 passed (2 new encode-only cases).
- `test/unit/test_server_args.py`, `test/unit/test_disagg_roles.py`: 287 passed.
- E2E with FLUX.3 Image and a miles-diffusion SFT run: in progress.
