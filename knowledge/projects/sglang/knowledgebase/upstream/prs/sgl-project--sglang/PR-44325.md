# [Feat] diffusion: Add support for the MOSS-Image family

[Upstream PR](https://github.com/sgl-project/sglang/pull/44325) · state: closed · merged: True

## Original PR description

## Motivation

Add native text-to-image inference for `OpenMOSS-Team/MOSS-Image-Base`, including the latest DiT weights and small FLUX.2 decoder. Load its Diffusers component export through SGLang's standard component loaders and run the model through the native diffusion runtime.

## Modifications

- Register `OpenMOSS-Team/MOSS-Image-Base` and `OpenMOSS-Team/MOSS-Image-SFT` identifiers. End-to-end checkpoint evidence below covers Base only; SFT is name registration only until its weights are updated and validated.
- Expose `uncond_skip_layers` and `slg_*` through model-owned sampling fields and the existing Images API whitelist. DiT `skip_layers` is an internal forward argument.
- Register the pipeline, DiT, Qwen3.5 text encoder, training V2 nearest-grid Euler scheduler and sampling configuration. Keep flow shift 5, BF16 DiT/text encoder and FP32 VAE.
- Support ordinary CFG, two-pass skipped-unconditional guidance and three-pass additional skipped-conditional guidance. Defaults: CFG 3, layer 22 unconditional skipping, window 0.01–1.0. Ordinary CFG uses `uncond_skip_layers=[]`; three-pass uses CFG 5, `slg_layers=[22]`, `slg_scale=3`.
- Sampling defaults intentionally retain the recommended recipe used here: `slg_start=0.01` leaves the first denoising step at full CFG, and selecting three-pass SLG without an explicit `uncond_skip_layers` uses a complete unconditional branch so the extra skipped-conditional term is evaluated independently. The official pipeline at the tested revision defaults to `slg_start=0.0` and keeps unconditional skipping enabled even with three-pass SLG. Set `slg_start=0.0, uncond_skip_layers=[22]` explicitly to request that official behavior.
- Add exact DiT activation/normalization/RoPE fusion with numerical gates and eager fallback; precompute step-invariant conditioning and reuse the framework text-conditioning cache.
- Declare component residency and support DiT/text-encoder layerwise offload through existing managers. Reuse shared FLUX.2 VAE decoding helpers; LLaDA-Image only changes its helper import. The existing native VAE already accepts decoder channels 96/192/384/384 from the updated checkpoint.

## Accuracy Tests

**Numerical parity: with cuDNN SDPA disabled in both processes, the official reference and SGLang Torch SDPA produce identical float RGB (maximum absolute error 0) for all three guidance recipes.** An independent repeat also confirms that each reference policy is reproducible across two fresh processes. This validates the tested Base diet-guide workload; default FA comparisons are reported separately below.

On the final commit, 171 tests passed across `python/sglang/multimodal_gen/test/unit/test_moss_image.py` and `python/sglang/multimodal_gen/test/unit/test_qwen3_5_encoder.py`. Pre-commit passes. Images API checks cover all three guidance recipes and a default request after three-pass; returned pixels match native offline output. The reproduction commands below were also run for all three recipes with both native default component backends and native Torch SDPA (six HTTP requests); all six outputs match the corresponding measured images. The new reference script reproduces all three controlled float-RGB outputs exactly. The displayed images, timing, offload and profile results were collected on an earlier revision with equivalent inference computation; the unit tests and API checks were rerun on the final commit. Component, DiT-only, text-encoder-only and combined layerwise offload preserve the resident float RGB output with `quality=exact`.

The reference is the unmodified `pipeline_moss_image.py` bundled at Base revision 355120bd6b44ff67b8df18f57e40b928fc886cd3, using Diffusers 0.38.0 for its small decoder. Native SGLang uses Diffusers 0.37.0 for configuration utilities and its own model/VAE implementation. PyTorch 2.14.1+cu130 and Transformers 5.19.0 are shared. All guidance arguments are explicit: the comparison uses slg_start=0.01, and three-pass reference calls set uncond_skip_layers=[] to keep the unconditional branch complete. These override the new reference's start=0 and unconditional-skip defaults.

Main images show the reference's original SDPA policy (cuDNN allowed), native Torch SDPA (framework cuDNN policy disabled), and native default FA. The main table therefore reports actual backend differences. A separate controlled lane disables cuDNN SDPA in the reference; all three guidance outputs are float-RGB identical to native SDPA, with matching branch order and layer 22 execution counts. SSIM uses float RGB in [0,1], a 7×7 local window, sample covariance and channel averaging; PSNR uses data_range=1. This single-prompt/seed agreement check is not a semantic-quality or GenEval benchmark. `quality=exact` does not imply equality across attention backends. Over 50 denoising steps, small floating-point differences between attention kernels can accumulate into composition changes; three-pass guidance can amplify them further. The matched-SDPA result isolates port correctness from those backend differences. The default request quality is `lossless`; these measurements explicitly use `exact`. MOSS-Image DiT fusions use bit-exact gates at either level, but the shared FLUX.2 VAE has additional quality-gated fast paths enabled at `lossless`, so the two end-to-end paths must not be treated as identical. No default-lossless pixel-parity result is claimed here.

### Reproduction

Use this PR's checkout with its diffusion dependencies installed. Native validation used PyTorch 2.14.1+cu130, Transformers 5.19.0 and Diffusers 0.37.0. Run on one otherwise idle H200; the resident configuration needs approximately 33 GiB of GPU memory.

```bash
sglang serve --model-path OpenMOSS-Team/MOSS-Image-Base \
  --revision 355120bd6b44ff67b8df18f57e40b928fc886cd3 \
  --backend sglang --num-gpus 1 \
  --disable-autocast true --warmup-mode off --performance-mode manual \
  --component-residency all=resident \
  --served-model-name OpenMOSS-Team/MOSS-Image-Base \
  --host 127.0.0.1 --port 30000
```

Leave `--attention-backend` unset for the displayed default-attention results: on the tested H200 this selects `text_encoder: torch_sdpa` and `transformer: fa`. Setting it globally to `fa` also changes the text encoder and does not reproduce these images. Confirm these component choices in the startup log. For the matched-SDPA accuracy lane, restart with `--attention-backend torch_sdpa`; both components should then log `torch_sdpa`. Keep `quality=exact` and use the cuDNN-disabled reference below.

<summary>Reference pipeline: reproduce all three recipes</summary>

Use a separate environment with Diffusers **0.38.0**, PyTorch **2.14.1+cu130** and Transformers **5.19.0**, plus `huggingface_hub`, NumPy and Pillow. The tested reference uses Transformers' PyTorch fallbacks for causal convolution and gated delta attention (`causal_conv1d` and `flash-linear-attention` are not installed). Installing either package may change the reference's numerics; use the same dependency versions and keep both packages absent when reproducing the bit-exact result. Run from the directory containing the three request JSON files above. Save this as `moss_reference.py`; it loads the pinned checkpoint's own pipeline code and does not import SGLang.

```python
import argparse
import importlib.util
import json
from pathlib import Path
import sys

import numpy as np
import torch
from diffusers import AutoencoderKLFlux2
from huggingface_hub import snapshot_download
from PIL import Image
from transformers import AutoModel, AutoTokenizer

parser = argparse.ArgumentParser()
parser.add_argument("--cudnn", choices=("enabled", "disabled"), default="disabled")
parser.add_argument("--output", type=Path, default=Path("reference-sdpa"))
args = parser.parse_args()
args.output.mkdir(parents=True, exist_ok=False)
# Run in a separate process that has not imported SGLang.
torch.backends.cuda.enable_cudnn_sdp(args.cudnn == "enabled")
model = Path(snapshot_download(
    "OpenMOSS-Team/MOSS-Image-Base",
    revision="355120bd6b44ff67b8df18f57e40b928fc886cd3",
))
spec = importlib.util.spec_from_file_location(
    "reference_moss_image", model / "pipeline_moss_image.py"
)
module = importlib.util.module_from_spec(spec)
sys.modules[spec.name] = module
spec.loader.exec_module(module)
transformer = module.MOSSImageTransformer.from_pretrained(
    str(model / "transformer"), torch_dtype=torch.bfloat16
).eval()
encoder = AutoModel.from_pretrained(
    str(model / "text_encoder"), dtype=torch.bfloat16, attn_implementation="sdpa"
).eval()
tokenizer = AutoTokenizer.from_pretrained(str(model / "tokenizer"))
vae = AutoencoderKLFlux2.from_pretrained(
    str(model / "vae"), torch_dtype=torch.float32
).eval()
scheduler = module.MOSSImageScheduler.from_config(
    json.loads((model / "scheduler/scheduler_config.json").read_text(encoding="utf-8")),
    shift=5.0,
)
pipe = module.MOSSImagePipeline(transformer, scheduler, encoder, tokenizer, vae).to("cuda")
for name in ("recommended", "ordinary", "three_pass"):
    req = json.loads(Path(f"{name}.json").read_text(encoding="utf-8"))
    width, height = map(int, req["size"].split("x"))
    guidance = {key: req[key] for key in (
        "guidance_scale", "uncond_skip_layers", "slg_layers", "slg_scale",
        "slg_start", "slg_stop",
    ) if key in req}
    rgb = pipe(
        req["prompt"], width=width, height=height,
        negative_prompt=req["negative_prompt"],
        num_inference_steps=req["num_inference_steps"],
        generator=torch.Generator("cuda").manual_seed(req["seed"]),
        output_type="np", **guidance,
    ).images
    np.save(args.output / f"{name}.npy", rgb)
    # Match the Images API's uint8 truncation when comparing downloaded PNGs.
    Image.fromarray(np.clip(rgb[0] * 255, 0, 255).astype(np.uint8)).save(
        args.output / f"{name}.png"
    )
    print(name, "saved", flush=True)

```

## Speed Tests and Profiling

One H200, batch 1, eager execution, quality=exact, autocast disabled, BF16 DiT/text encoder and FP32 VAE. Every displayed result uses the 1024×1024 diet-guide prompt, seed 0, 50 steps, empty negative prompt and flow shift 5. The timed recipe is CFG 3 with zero-indexed unconditional layer 22 skipped for 0.01 ≤ step_index / num_steps < 1.0. Each arm runs in a fresh process, one warmup followed by three measured calls; the table shows arithmetic means and sample standard deviations. CUDA-synchronized timing covers the complete pipeline through CPU float RGB, excluding load, PNG encoding/saving, HTTP and profiling. The cached arm reuses the exact same positive/negative prompt; it is not cold-prompt latency. The speed baseline uses the reference's default PyTorch SDPA policy with cuDNN enabled, its faster configuration on this GPU.
