# perf: fuse FA3 query quantization with RoPE

[Upstream PR](https://github.com/sgl-project/sglang/pull/35142) · state: closed · merged: False

## Original PR description

**Incremental review:** [Files changed](https://github.com/sgl-project/sglang/pull/35142/files) against `main`.

## Summary

- centralize the FA3 FP8 query dtype requirement behind an attention-backend capability and stamp it onto each `RadixAttention` layer before graph capture
- make query quantization an explicit model-layer operation, while retaining a generic `RadixAttention` fallback for models that do not opt into earlier fusion
- fuse full-dimension RoPE and Q-to-FP8 conversion for Qwen2/Qwen3 decode:
  - under `torch.compile`, the output cast is folded into the compiled RoPE graph
  - in eager CUDA mode, a Triton kernel rotates Q/K and writes Q directly to FP8
- preserve FA4, MXFP8, partial/unsupported RoPE, MRoPE, DualChunk, non-CUDA, and deterministic fallbacks

This addresses the Q-centralization part of #30815. K/V cache-write fusion is separate work (see #31652).

## Performance

H200 NVL, CUDA 13, `Qwen/Qwen3-0.6B`, FA3, `--kv-cache-dtype fp8_e4m3`, `--enable-torch-compile`, CUDA graphs enabled, radix cache disabled, fixed 256-token input and 256-token output, three runs per point:

| Max concurrency | Baseline output tok/s | This PR output tok/s | Delta | Baseline mean TPOT | This PR mean TPOT |
|---:|---:|---:|---:|---:|---:|
| 1 | 711.79 | 732.28 | **+2.88%** | 1.36 ms | 1.32 ms |
| 8 | 4,368.42 | 4,469.63 | **+2.32%** | 1.713 ms | 1.673 ms |
| 32 | 13,215.11 | 13,510.03 | **+2.23%** | 2.183 ms | 2.123 ms |

An 80-step decode profile at concurrency 8 shows:

- CUDA kernels: 39,437 -> 37,253 (**-2,184 launches**)
- aggregate CUDA-kernel time: 124.565 ms -> 121.795 ms (**-2.22%**)
- the removed 2,184 launches are exactly the standalone Q cast: 28 layers x 78 profiled decode steps

For eager execution, standalone H200 measurements on representative Qwen2.5 and Qwen3 attention shapes (batch 1/8/32) show the fused RoPE + Q quantization operation is 27-39% faster than launching RoPE and Q cast separately.
