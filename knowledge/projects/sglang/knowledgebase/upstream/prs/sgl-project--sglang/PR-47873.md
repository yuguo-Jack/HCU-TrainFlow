# [Fix] engram: create the shared host table without os.memfd_create

[Upstream PR](https://github.com/sgl-project/sglang/pull/47873) · state: open · merged: False

## Original PR description

## Motivation

With `--engram-config '{"placement":"cpu","replication":"per_node"}'` the engram
host table is backed by a memfd. `os.memfd_create` only exists when CPython was
built against a libc that declares the wrapper; interpreters from conda and from
python-build-standalone before 20260718 do not, and model construction then dies
with:

    File "sglang/srt/layers/engram.py", line 751, in _open_shared_fd
      fd = os.memfd_create(name, 0)
    AttributeError: module 'os' has no attribute 'memfd_create'

`mem_cache/storage/mmap/mmap_allocator.py`, `layerwise_offload.py` and
`multimodal_gen/.../utils.py` already guard the same gap; the engram host table
is the remaining call site without a fallback.

## Modifications

`_memfd_create()` uses `os.memfd_create` when the interpreter has it and issues
the same syscall through `libc` otherwise. A `/dev/shm` file is not usable here:
these tables are tens of GiB and the container tmpfs is far smaller.

## Not a duplicate

No open issue or PR changes this call site. #43021 records that uv-managed
python-build-standalone builds lacked `os.memfd_create`; #44521 (closed) used a
libc shim only inside its benchmark harness; #42920 rewrites the engram row-read
path and does not touch memfd creation.
