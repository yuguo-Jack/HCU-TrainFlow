# [sglang-miles] Extract reasoning-request normalization into standalone helpers

[Upstream PR](https://github.com/sgl-project/sglang/pull/32428) · state: open · merged: False

## Original PR description

## Motivation

External OpenAI-compatible frontends that pre-render `input_ids` (e.g. token-in-token-out routers like Miles' session server) must interpret the accepted reasoning spellings (`reasoning` object, top-level `reasoning_effort`, `chat_template_kwargs.reasoning_effort`, thinking toggles) exactly as the server does. Today that logic is split between a pydantic validator bound to `ChatCompletionRequest` and `serving_chat._convert_to_internal_request`, so external callers must mirror it and drift silently when it changes.

## Modifications

Add `python/sglang/srt/entrypoints/openai/reasoning_request.py` holding the logic as unbound functions; the existing call sites delegate, so serving behavior is byte-identical:

- `normalize_reasoning_inputs(values)`: the `ChatCompletionRequest.normalize_reasoning_inputs` validator body, moved verbatim; the validator now delegates.
- `pop_reasoning_effort_kwarg(chat_template_kwargs)`: the kwargs-spelling promotion pop; `serving_chat._convert_to_internal_request` delegates.
- `normalize_reasoning_request(values)`: both steps composed in the server's order, for callers outside the request lifecycle.
- `resolve_v4_reasoning_effort(effort)` / `V4_ENCODER_REASONING_EFFORTS`: the dsv4 encoder effort filter; the dsv4 encoding path delegates.
