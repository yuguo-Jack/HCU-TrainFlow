## Motivation

<!-- Describe the purpose and goals of this pull request. -->
Under prefill context parallelism, each QSA layer runs two all-gathers: one for the index keys and one for the layer's K/V. The following changes reduce synchronization overhead and overlap communication with computation.

### 1. Remove Host–Device Synchronizations

The first change removes four host–device synchronizations per layer on this path, or five when using a cached prefix:

- The `positions.max().item()` call in the indexer's RoPE.
- The `.tolist()` conversion of sequence lengths.
- The prefix's request-index `.tolist()` conversion, when using a cached prefix.
- The per-layer `torch.tensor` copy that builds the sparse-attention kernel's K offsets.
- The sparse-attention kernel's `max_q.item()` call.

Three of these synchronizations, or four with a cached prefix, occurred immediately after an all-gather. As a result, every rank's CPU waited for the slowest rank on each layer, and the GPU then sat idle while the CPU relaunched work. Removing these synchronizations lets the CPU run ahead.

This saves:

- CP4: approximately 8 ms at both 8K and 32K, reducing latency by 27.5% and 11.7%, respectively.
- CP8: approximately 3–8.5 ms at 8K and 32K, reducing latency by 12.1% and 19.4%, respectively.

There is no numeric change.

### 2. Overlap the K/V All-Gather with the Indexer

The second change overlaps the K/V all-gather with the indexer. A hook fires immediately after the indexer issues its own key gather and starts the K/V gather on a side stream.

The K/V gather then runs during:

- Compression.
- MQA scoring.
- Top-k selection.

Attention waits for the gather only when it needs the result.

The index-key gather stays inline: it is short, and its long waits come from load imbalance, which overlap cannot hide.

This provides additional latency reductions:

- At 32K: 1.5 ms on CP4 and 1.85 ms on CP8, or 2.5% and 5.3%, respectively.
- At 128K: approximately 7 ms.
- At the 8K first chunk: neutral overall, because the layer is limited by kernel launch speed.
