# [Fix] spec: Select positive-weight final tokens in reject sampling

[Upstream PR](https://github.com/sgl-project/sglang/pull/47998) · state: closed · merged: False

## Original PR description

## Motivation

With rejection sampling on B200, a request can get an out-of-vocabulary or zero-weight final token.

This affects EAGLE, EAGLE3, and NEXTN servers with `--speculative-use-rejection-sampling` or block verification (both off by default) at temperature above 0. Sampled DSpark on CUDA and EAGLE on ROCm can reach this kernel with no flag. I did not test ROCm, MUSA, DSpark, DFlash, or UNO.

It is rare: with ordinary `torch.rand` coins on synthetic inputs, `main` returned 94 bad tokens in 138 million draws at vocabulary 32,000, and 4 in 138 million after a top-50 filter. Each request makes one draw per verify step.

The real-output rate is unknown. A Qwen3.5-9B server returned no bad token in 56,052 draws on `main`, too few to show it. Coins forced near 1 in those runs gave 6 zero-weight tokens on `main` and none with this change. With ordinary coins, out-of-vocabulary tokens came only from vocabularies of 32 or less. I found no issue that reports this bug.

On B200, `tl.cumsum` over a tile is not monotonic, so a zero-weight or out-of-vocabulary lane can cross the cutoff. This fix comes from closed #44116 and slows large batches.

No other open PR changes this scan, but #47807 copies it into a small-batch split path that this change does not cover.

All table counts are for `main`.

## Modifications

Only positive-weight lanes can match the cutoff. If none matches, the scan uses the last positive-weight token, or `VOCAB_SIZE - 1` for an empty residual. An accepted row with a positive token, a NaN, then zeros now returns that token.

## Accuracy Tests

Results cover the kernel in b91e0c89ba against `main` 582168dd7c on B200.

In a separate paired run of 2.86 billion ordinary-coin draws, only final tokens differed (258, each a bad token from `main`, none from this change). New regression tests fail only on `main`.

GLM-5.3-Flash FP8 (TP4, EAGLE 5/1/6, rejection sampling on) scored 97.5% on `main` and 98.0% with this change, one run each, as a no-regression check.

```bash
# sgl-eval 0.1.3
sgl-eval run gsm8k --num-examples 200 --num-threads 64 --max-tokens 32768 --temperature 1.0 --top-p 0.95 --thinking
```
