# [Fix] multimodal: Reject malformed offsets before scheduler execution

[Upstream PR](https://github.com/sgl-project/sglang/pull/47224) · state: open · merged: False

## Original PR description

## Summary

Reject malformed multimodal items with missing token offsets at the processor-output boundary, and convert the validation failure into a request-scoped error instead of allowing it to crash the scheduler.

## Motivation

In #47218, a DeepSeek-V4.1 deployment hit `TypeError: 'NoneType' object is not iterable` in `mm_schedule._count_mm_tokens_in_extend`. The exception propagated out of the scheduler and restarted the serving container. The host-side offsets fast path and downstream MM embedding assembly both require offsets, so treating missing offsets as empty could silently corrupt embeddings.

This change enforces the invariant where `MultimodalProcessorOutput` becomes scheduler-owned `MultimodalInputs`. Both generate and embedding request paths translate `ValueError` into a request failure, so malformed input cannot reach a TP/EP collective.

## Test

- Added a regression test for a valid-modality MM item with missing offsets.
- Ran in an isolated container using the affected `lmsysorg/sglang:dev-dsv41` image: `9 passed`.

## Scope

This protects the scheduler boundary; it intentionally does not coerce missing offsets to an empty list, because correct MM embedding construction cannot be guaranteed without offsets.
