# [Fix] sampling: Apply additive penalties before repetition scaling

[Upstream PR](https://github.com/sgl-project/sglang/pull/47947) · state: open · merged: False

## Original PR description

## Motivation

Non-overlap sampling applies additive and repetition penalties in a set-derived order. Those operations do not commute, while the existing overlap and speculative-repeat paths already apply additive penalties before repetition scaling.

This can change the greedy token for supported parameters. With token 5 at logit 4, count 2, frequency 1, presence 0.5 and repetition 2, the established order gives `(4 - 2 - 0.5) / 2 = 0.75`. A natural constructor order on the base produces -0.5 instead; an unseen token at 0.6 is then chosen instead of token 5.

## Modifications

Use the existing additive-accumulation path first, then apply prepared multiplicative penalizers. The repeat path and public signatures are unchanged. The regression checks both class orders, repetition below/above 1, positive/negative logits, greedy selection and repeat parity.

## Accuracy Tests

The base fails two regression subcases; the patched penalty suite passes 42 tests plus 4 subtests. Separate consumer checks match the independent scalar formula in 192/192 supported cases across all 24 class orders, versus 128 mismatches on base. Independent review also passed 132 mixed-batch cases / 660 count-transition steps through non-overlap, overlap and repeat consumer methods; 120 additive-only base comparisons are bitwise identical.

These are real CPU penaltylib/common/Torch operations. The local bridge bypasses unrelated top-level package bootstrap and executes unchanged consumer methods from source. Host Torch 2.10 / Transformers 5.1 differs from the pinned 2.14.1 / 5.19 environment. Pinned-runtime initialization, serving, GPU execution and model-level accuracy were not tested locally.

## Speed Tests and Profiling

Not run. The non-overlap Python path gains an iteration; no throughput or arbitrary-input bitwise parity claim is made.
