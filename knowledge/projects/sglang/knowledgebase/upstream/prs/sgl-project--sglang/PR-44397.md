# [Fix] scheduler: Reject priority requests safely with a zero queue limit

[Upstream PR](https://github.com/sgl-project/sglang/pull/44397) · state: open · merged: False

## Original PR description

## Motivation

With priority scheduling enabled and `max_queued_requests=0`, the first incoming request reaches the full-queue path while the waiting queue is empty. Selecting an eviction candidate with `max()` raises `ValueError` before the scheduler can send its normal queue-full rejection.

## Modifications

Only consider priority eviction when a waiting request exists. Otherwise, preserve the existing incoming-request rejection with status 503. Nonempty queues retain the same priority comparison and eviction behavior.

Open PR searches for `max_queued_requests`, `priority max queued`, `zero queue`, and `empty waiting queue priority` found no overlapping fix. #37260 changes retraction admission and #37661 adds runtime scheduler controls; neither handles empty priority eviction.

The fixed cases check the emitted rejection's request ID and status, and that the waiting queue stays empty. The existing suites also cover nonempty priority eviction and request cleanup.
