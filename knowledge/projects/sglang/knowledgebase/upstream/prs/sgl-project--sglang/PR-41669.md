# [AMD] Add a GLM-5.3 MI35x nightly perf step

[Upstream PR](https://github.com/sgl-project/sglang/pull/41669) · state: open · merged: False

## Original PR description

## Motivation

#41602 retired `nightly-8-gpu-mi35x-glm52-fp8` in favour of GLM-5.3. That job's perf step was the only GLM throughput benchmark on MI35x, so the MI35x nightly lost that coverage. The GLM-5.3 cookbook also ships its MI355X FP8 cells as `verified: false` with no AMD benchmark numbers, so nothing measures GLM-5.3 throughput on AMD yet.

## Modifications

- **New test** `test/registered/amd/perf/mi35x/test_glm53_perf_mi35x.py`, suite `nightly-perf-8-gpu-mi35x-glm53`:
  - `NightlyBenchmarkRunner` against `zai-org/GLM-5.3` (FP8), with the cookbook's MI355X / FP8 / low-latency / single-node cell. These are the same server args as the GLM-5.3 accuracy test: `--tp 8 --dsa-prefill-backend tilelang --dsa-decode-backend tilelang --chunked-prefill-size 131072 --mem-fraction-static 0.80 --watchdog-timeout 1200`, plus the `glm45` / `glm47` parsers and multithreaded weight loading.
  - It runs 8K input / 1K output at batch 1, 8, 16 and 64. Batch 1, 16 and 64 are concurrency points on the cookbook's benchmark card, and 8 keeps the range the GLM-5.2-FP8 benchmark covered. The first batch-1 run is a warmup that the report drops.
  - It mirrors `test_glm52_fp8_perf_mi35x.py`, which stays in the tree.
- **New step** `Performance Test MI35x ROCm (8-GPU GLM-5.3 FP8)` in the existing `nightly-8-gpu-mi35x-glm53` job, after the accuracy step:
  - It uses the same layout as the retired GLM-5.2-FP8 job: 120-minute step timeout, 5400 s per-file cap, and `continue-on-error: true`, so a perf problem doesn't fail the job.
  - Running in the same job means accuracy gates perf, the ~700 GB checkpoint is already cached, and it takes no extra 8-GPU MI35x slot.
  - No new job, dropdown option or `check-all-jobs.needs` entry is needed. The section comments now read "MI30x accuracy, MI35x accuracy + performance".
- There is no `run_suite.py` change. AMD suites aren't validated against `NIGHTLY_SUITES`, and the existing `nightly-perf-8-gpu-mi35x-*` suites aren't listed there either.
- **Cleanup:** the GLM-5.3 accuracy steps for MI30x and MI35x get their backslash line continuations back. In #41602 they had collapsed into one long line padded with spaces. There is no functional change.

## Validation

Dispatched `nightly-8-gpu-mi35x-glm53` on this branch with `continue_on_error=false` on rocm10 only ([run 36551834936](https://github.com/sgl-project/sglang/actions/runs/36551834936), [job 109351606539](https://github.com/sgl-project/sglang/actions/runs/36551834936/job/109351606539)). Both steps passed against the warm cache:

- **Accuracy:** GSM8K 0.9757 (threshold 0.92), 1080 s
- **Perf:** the sweep finished in 293 s (300 s wall clock including server launch)

| batch size | input len | latency (s) | input throughput (tok/s) | output throughput (tok/s) | ITL (ms) |
|---|---|---|---|---|---|
| 1 | 8192 | 12.55 | 14769.58 | 85.35 | 11.72 |
| 8 | 8192 | 21.30 | 14366.18 | 489.57 | 16.34 |
| 16 | 8192 | 28.17 | 15640.60 | 827.72 | 19.33 |
| 64 | 8192 | 61.41 | 15604.54 | 2356.19 | 27.16 |

The perf step adds no new model or image dependency beyond the accuracy step, which #41602 already validated on rocm10, rocm724 and rocm720.
