## Motivation

Nemotron-H’s ModelOpt mixed-precision override rejects flashinfer_cutedsl for checkpoints containing W4A16_NVFP4 experts, even when the existing W4A16 opt-in is enabled.
Allow this supported explicit configuration, following the Qwen precedent in #39126 and using the implementation already introduced in #35120. Preserve the automatic Marlin selection established by #33543.

## Modifications

- Allow --moe-runner-backend flashinfer_cutedsl when SGLANG_FLASHINFER_CUTEDSL_NVFP4_W4A16=1 on SM100-family GPUs.
- Preserve auto → marlin, explicit Marlin support, and Nemotron’s existing --moe-a2a-backend none requirement.
- Update the validation error and add regression coverage for backend selection, the environment flag, unsupported hardware, and A2A restrictions.

## Accuracy Tests

GSM8K, 200 questions, thinking enabled, using the existing Nemotron CI evaluator.
B200, TP1, SGLang 0.5.21 / FlashInfer 0.6.18, Nemotron-3.5-Lightning-30B-A3B-NVFP4;
temperature 0, seed 42, concurrency 32, 16,384-token cap, speculation disabled.
Results from the confirmation run:

| Backend | Correct | Accuracy |
|---|---:|---:|
| Marlin | 188/200 | 94.0% |
| CuTe DSL W4A16 | 190/200 | 95.0% |

No degradation observed in this run. The small difference is consistent with noise.


## Speed Tests and Profiling

### End-to-end serving

B200, TP1, SGLang 0.5.21 / FlashInfer 0.6.18, same NVFP4 checkpoint, concurrency
32, static 57,600 shared-prefix + 6,400 new input tokens and 400 output tokens,
8 warmup + 160 measured requests, AIPerf 0.12.0.

| MoE backend | Output tokens/s | Speedup |
|---|---:|---:|
| Marlin | 1,576.63 | 1.00× |
| CuTe DSL W4A16 |  2,199.04 | 1.40× (+39.9%) |

Both measurements completed all 160 requests with zero errors and 64,000 output 
tokens.

### Isolated grouped-GEMM microbenchmarks

A separate B200 study invoking kernels directly (FlashInfer 0.7.0.post1).
Replayed nine expert-assignment patterns captured from Nemotron-3.5-Lightning,
using its checkpoint's NVFP4 expert weights and BF16 activations. These exercise
Nemotron's actual MoE workloads and help explain the serving speedup above.
Logical up K→N: 2688→1856; down: 1856→2688.

Selected cases below. Times are median milliseconds per grouped-GEMM invocation,
covering all assigned experts for one projection, without activation or final
combine. 
T is the number of input tokens before routing, and each case replays its full
captured per-expert assignment vector. These measurements help illustrate 
the kernel-level gains behind the serving speedup.

| Case | T | Projection | Marlin (ms) | CuTe DSL (ms) | Speedup |
|---|---:|---|---:|---:|---:|
| A | 32 | Up | 0.0439 | 0.0242 | 1.81× |
| A | 32 | Down | 0.0430 | 0.0231 | 1.86× |
| F | 16 | Up | 0.0675 | 0.0431 | 1.57× |
| F | 16 | Down | 0.0665 | 0.0448 | 1.48× |
| G | 2,129 | Up | 0.8267 | 0.1986 | 4.16× |
| G | 2,129 | Down | 0.7558 | 0.1988 | 3.80× |
| H | 14,896 | Up | 4.1495 | 0.8799 | 4.72× |
| H | 14,896 | Down | 3.4406 | 0.8886 | 3.87× |
| I | 15,436 | Up | 4.2833 | 0.9067 | 4.72× |
| I | 15,436 | Down | 3.5455 | 0.9163 | 3.87× |

CuTe DSL was faster in every tested case: **1.44–4.72×** for pure up/down GEMMs
and **1.67–5.10×** for up+ReLU² (fused CuTe DSL versus Marlin plus standalone
activation), across all nine measured patterns.
