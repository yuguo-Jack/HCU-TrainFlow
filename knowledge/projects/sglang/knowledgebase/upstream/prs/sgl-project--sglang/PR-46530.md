# [Refactor] dsv41: Write engram hash ids and embeddings into caller-allocated prefill graph outputs

[Upstream PR](https://github.com/sgl-project/sglang/pull/46530) · state: closed · merged: True

## Original PR description

- The two engram breaks in the breakable prefill graph, the hash-id break in the DeepSeek V4 model and the embedding lookup break in `Engram`, write into an output the caller allocates right before the break and return nothing; the captured segment after each break reads that output. Before, each break returned a fresh tensor on every replay and the graph wrapper copied it into the one it had captured.
- The caller sizes each output from the inputs it already has: `EngramHasher.new_hash_ids(input_ids)` and `EngramEmbedding.new_rows(hash_ids)` (the existing `_empty`, renamed now that a caller outside the class uses it). Every path through the hasher and the embedding returns that shape and dtype, so the break copies its result in as is.
- The idle DP path of the hasher allocates through the same helper.
- No behavior change intended. The changed path runs only for DeepSeek V4 models with engram layers under the breakable prefill graph.
