# [Fix] deepseek-v3.2/v4/v4.1: Fix quadratic regex scans in the tool-call parser

[Upstream PR](https://github.com/sgl-project/sglang/pull/42576) · state: open · merged: False

## Original PR description

## Motivation

`DeepSeekV32Detector` (`deepseekv32`, and its `deepseekv4` / `deepseekv41` subclasses) scans model output with two lazy `open(.*?)close` patterns that go quadratic when the closing tag never arrives:

1. `detect_and_parse` runs `re.findall(<｜DSML｜function_calls>(.*?)</｜DSML｜function_calls>)`. With many opening tags and no closing one, each opening tag rescans to the end of the text.
2. `_parse_parameters_from_xml` runs `re.finditer` with `<｜DSML｜parameter ...>(.*?)</｜DSML｜parameter>` over the invoke body. A closed invoke holding many unclosed parameter tags rescans the body from each one, both in `detect_and_parse` and in a single `parse_streaming_increment` call.

| Input | Before | After |
|---|---|---|
| 184 KB of unclosed `<｜DSML｜function_calls>`, non-stream | 23.7 s | 0.3 ms |
| closed invoke with 8000 unclosed parameter tags (352 KB), non-stream | 48 s | 33 ms |
| same, **one streaming call** | 49 s | 21 ms |

Tool-call parsing runs synchronously on the tokenizer manager's event loop, so one such response stalls every in-flight request. Found with an Atheris fuzzing harness that records per-input parse time.

## Modifications

Both scans are bounded with `endpos` = the end of the last closing tag. No match can end past it. Every opening tag before it still finds its closer (and the match consumes everything up to that closer), while opening tags after it never could match. So the matches are unchanged and the total scan is linear.

Regression test `test_unclosed_tags_parse_in_linear_time` in `test_deepseekv4_detector.py`: 41.3 s on `main`, fast here.

## Accuracy Tests

- Differential test of `main` vs patched detectors for all three variants, comparing `detect_and_parse` and every streaming result under random re-chunking: **0 mismatches** over 60k random plus 60k mutated well-formed inputs (about 12.5k per variant produced parsed calls).
- `test/registered/unit/function_call/`: 630 passed.

## Speed Tests and Profiling

See the table above. A scaling probe (each token literal and each pair, repeated 2k/4k/8k times) finds no remaining super-linear input.

Related: #42573, #42574, #42575 (same issue class in other tool-call parsers).
