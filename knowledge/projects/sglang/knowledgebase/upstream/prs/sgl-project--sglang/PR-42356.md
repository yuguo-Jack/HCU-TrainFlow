# [Fix] Reject non-positive server stream intervals

[Upstream PR](https://github.com/sgl-project/sglang/pull/42356) · state: closed · merged: False

## Original PR description

## Motivation

`--stream-interval 0` currently passes server argument validation. An unfinished streaming request that uses the server default then reaches `len(req.output_ids) % stream_interval` in `_GenerationStreamAccumulator.accept` and raises `ZeroDivisionError`.

Reject non-positive server intervals during startup, before a request reaches the scheduler. Per-request `SamplingParams.stream_interval=0` still means inherit the server default.

## Modifications

- Add `validate_stream_interval` before model-source resolution and the dummy/absent-model early return, following the existing model-independent validation order and hook registry.
- Extend the existing registered CPU server-args test through actual `resolve_once()` calls on constructor and CLI arguments, covering `dummy` and `none` model paths. Reject `0`, `-1`, and `-50`; preserve `1`, `3`, and `50`.
- Leave request-level overrides and output streaming logic unchanged.

## Accuracy Tests

No model, kernel, or forward-pass changes. CPU validation used the real `ServerArgs` resolution pipeline with the test file's existing device mock.

- New regression on unchanged production code: 12 expected failing subtests (`ValueError` was not raised); 12 positive controls pass.

- Separate real `Req` + `_GenerationStreamAccumulator` CPU check: confirms the unvalidated zero-default exception, valid-default inheritance for request-level `None` and `0`, and explicit positive request overrides.
- Broader server-args directory run: **375 passed, 4 failed, 199 subtests passed**. A pristine-main control has **374 passed, the same 4 failures, 175 subtests passed**.
