> **Uses ROCm/aiter#6270** for the fused AR+RMSNorm (`hip_fused_ar_rmsnorm`). Without it that path falls back to plain all-reduce. See [AITER dependency](#aiter-dependency).

## Motivation

This PR connects the kernels from the previous PRs to the Kimi-K3 model on ROCm, and adds the all-reduce fusions and FP8 decode projections that use them.

## Modifications

- Call the MLA, KDA and MoE fused kernels from new `kimi_k3_rocm_*.py` modules. Each path has its own env switch and falls back to the existing code when the shape or hardware does not match.
- `kimi_k3.py` only gains short `_is_hip` hooks. The CUDA paths do not change.
- ROCm decode reads the attention input already quantized for the in-projection. The decoder asks the stage boundary for `quant_format="fp8"` or `"fp8_per_token"`, the existing boundary option, so the input norm runs fused with the FP8 quant in upstream's own kernels.
- `AttnBankState` (shared) gains quantized attention reads: the bank aggregates without the out-norm, then runs that format's norm+quant kernel. Where the aggregation cannot skip the norm, or the read is gathered afterwards, it reads plainly. `AttnResidual.aggregates_unnormed` reports which applies.
- Add `hip_fused_ar_rmsnorm` on AITER custom all-reduce, with a token cap from measurements.
- Split the MoE `[latent | shared]` all-reduce into two when it is larger than the quick-reduce buffer.
- Add PTPC FP8 decode projections, online FP8 loading and shared-expert weight caches.
- Use all-zero positions for the Triton MLA identity-RoPE fallback, so it never reads past the one-row cos/sin tables.
- Keep the MORI combine `output` when the zero-copy MoE buffer is published (`moe_runner/aiter.py`).
- Add an opt-in SGLang BF16 GEMM tuning profile for M=16384. It is set while the Kimi-K3 model is built, before AITER loads its BF16 GEMM table, so it also applies to single-process tools such as `bench_one_batch`.
- Let `AttnResidual.forward` take `out_norm=None`.
- Turn off symmetric memory under graph capture from an argument hook that only runs on HIP.
- Rename `SGLANG_AITER_K3_OPT` to `SGLANG_ROCM_K3_AITER_OPT`; the old name still works with a deprecation warning.
- Add runtime tests, all-reduce benchmarks and entries in the env variable reference.

### Changes since the last revision

- Rebased the stack onto `main` after the stage-boundary refactor of Kimi-K3 (#42894, #42898, #42936). The decoder-layer hooks no longer exist upstream, so the ROCm FP8 attention-input fusion now goes through the boundary's `quant_format` instead (see above), and its K3-local copies of the norm+quant kernels are gone.
- Removed `hip_ar_residual` (`SGLANG_ROCM_AR_RESIDUAL`). K3 already folds the residual add into `attn_res_hip`, so the fused AR+add was 0.7% to 1.1% slower in TPOT at c1/c2 and neutral at c4/c8, and its call site is gone upstream.
- Removed the direct write of Quark MXFP4 shared-expert GEMMs into the collective buffer. AITER's `gemm_afp4wfp4_pre_quant` reduces with atomic adds and only zeroes `y` it allocates itself, so writing into a `new_empty` buffer corrupted the shared-expert output: GSM8K fell from 0.929 to 0.90. Running the linears normally and copying is also 0.3% to 1.2% faster than zeroing the buffer first.
- The shared-experts densify hook moved to #44049 with the rest of that feature, and is no longer called here.
- The KDA o_norm FP8 fusion passes `use_sigmoid=True`, the keyword in AITER after ROCm/aiter#5392.

## AITER dependency

`hip_fused_ar_rmsnorm` calls `custom_fused_ar_rms(..., residual_out=, out=, num_norm_rows=, skip_residual=)`, which ROCm/aiter#6270 adds. Without it the module returns `None` and the model uses plain all-reduce; nothing fails, so check the AITER version when you measure that path.

It does not use `--enable-aiter-allreduce-fusion`. That flag fuses all-reduce + residual add + RMSNorm at the shared layer boundary. Kimi-K3's MoE all-reduce is AR + RMSNorm on the latent rows only, with no residual, which the flag's kernel cannot do until ROCm/aiter#6270.

| Kimi-K3 all-reduce | Module in this PR | Covered by the flag? |
|---|---|---|
| Attention-residual prefix: AR + residual add, **no norm** | `hip_ar_residual.py` | No. The flag always applies RMSNorm after the add. |
| MoE `[latent \| shared]`: AR + RMSNorm on **the latent rows only**, **no residual** | `hip_fused_ar_rmsnorm.py` | No. `fused_allreduce_rmsnorm` has no `num_norm_rows` / `skip_residual`. |
| MoE pair larger than the quick-reduce buffer: split into two all-reduces | `hip_k3_moe_pair_ar.py` | No. This isn't a fusion. |

The flag also works only at the shared layer boundary (`fused_attn_input` / `forward_with_allreduce_fusion`). K3's attention-residual layers never reach that code, so turning it on changes nothing for K3.

The AITER options K3 needs are in ROCm/aiter#6270. I added that dependency to the description.

You're right that `hip_fused_ar_rmsnorm._aiter_fused_ar_rms` duplicates the dispatch in `GroupCoordinator.fused_allreduce_rmsnorm`. Once ROCm/aiter#6270 lands, I'd like to add `num_norm_rows`, `skip_residual` and `out` to `GroupCoordinator.fused_allreduce_rmsnorm`. Then the K3 module could call it instead of copying the dispatch.
