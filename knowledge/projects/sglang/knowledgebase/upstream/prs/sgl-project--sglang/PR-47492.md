# [Fix] speculative: Unpad prefill hidden states before draft extend

[Upstream PR](https://github.com/sgl-project/sglang/pull/47492) · state: closed · merged: False

## Original PR description

## Motivation

Fixes #47490. During chunked prefill with a cached prefix, the target can pad FULL hidden states to a larger DP prefill-graph bucket than the draft uses. The extend post-forward path currently slices by `seq_lens_sum`, which includes cached-prefix tokens and can leave target padding in the output. Passing those rows into the smaller draft bucket raises a negative-dimension error.

## Modifications

Trim ordinary extend outputs using `_original_num_tokens`, already recorded before input padding, and preserve the previous behavior when that count is unavailable. The existing auxiliary hidden-state trimming follows the corrected row count. Graph bucket selection and speculative decoding branches are unchanged.

Add regressions for target/draft buckets 64→32, 80→32 and 64→48, cached/no-prefix inputs, unpadded inputs, FULL/LAST/NULL-shaped hidden outputs, and auxiliary hidden rows.

### Related work

Further review found that #37587 already contains the same core unpadding correction in commit `cf384e9b9fbbf445a392796f7cb36991dd3426bf` (October 21), including a cached-prefix regression. That PR has not been merged into main. Credit to HanHan009527 for the earlier fix. This narrower PR adds the target-to-smaller-draft-bucket failure chain, auxiliary-row tests, a compatibility fallback, and independent validation for #47490; the core correction is overlapping work.
