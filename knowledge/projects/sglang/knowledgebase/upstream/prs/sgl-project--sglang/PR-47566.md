# [Perf] minimax-h3: Skip attention for the packing's alignment rows in the Ulysses pipeline

[Upstream PR](https://github.com/sgl-project/sglang/pull/47566) · state: closed · merged: True

## Original PR description

## Motivation

H3 pads its packed sequence to a multiple of 64 per Ulysses rank, so a 1280x704 request attends `cu_seqlens [0, 33002, 33024]`. cuDNN SDPA's varlen runs each segment as its own call, so every pipelined head group ran the real rows, a copy into the output, a cuDNN call for the 22 alignment rows and a second copy. With 7 groups per layer that is 28 extra launches and their host work per block.

## Modifications

- The alignment rows only ever reach their own rows (attention keeps them in their own segment, everything else is row-wise), so group attention now attends the real rows only, writes them straight into the output when the backend can (FA4), and zeroes the alignment rows. The real rows run the same call as before.
- Test added to `test_minimax_h3_dit_contract.py`.

## Accuracy Tests

Bit-identical output: MP4 md5 identical to main in every arm (4/4 on FA4, 4/4 forced-cuDNN).

## Speed Tests and Profiling

4x B300 (stand-in for B200), same protocol as the three-waves PR; measured on top of it:

| | 1280x704 | 1344x768 |
|---|---|---|
| three-waves | 26.55 s | 31.78 s |
| + this PR | 26.46 s (-0.10) | 31.63 s (-0.14) |

Together with three-waves, the 20-prompt 720p median goes 26.793 -> 26.517 s (-1.03%).

Note: this touches the same H3 pipelined-Ulysses block in `minimax_h3.py` as the ROCm Ulysses-pipeline PR; whichever lands second needs a small rebase.
