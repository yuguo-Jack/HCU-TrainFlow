# [diffusion] Don't report video jobs completed after their outputs are deleted

[Upstream PR](https://github.com/sgl-project/sglang/pull/43084) · state: closed · merged: True

## Original PR description

When neither the request nor the server sets output_path, /v1/videos writes outputs to a temp dir that is removed once the job finishes. Only the first output was uploaded to cloud storage, so with cloud storage disabled or failing (or for any variant beyond the first) the job was marked completed with no retrievable URL or path.

- Upload every output, not just the first, and expose per-variant URLs via a new `urls` field.
- Fail the job when outputs live in a temp dir and any of them was not uploaded, instead of reporting success for media that is gone.
- With a persistent output_path, report `file_paths` only for outputs still on disk (uploaded ones are removed locally), and make /content check the cloud URL of the requested variant.

Fixes sgl-project/sglang#43080

  2. `protocol.py` and `video_api.py` reverted to the PR parent `0f5bc4a` (main), with the PR's test file kept, to check that the new tests actually catch the bug

**Results**

| Code | Result |
|---|---|
| PR head | 6 passed |
| main + new tests | 4 failed, 2 passed |

On main, the 4 new tests fail and the 2 existing lifecycle tests still pass:
- `test_temp_output_without_cloud_upload_fails_job`: main reports `completed` with no URL and no path, even though the temp dir is deleted.
- `test_temp_output_with_partial_cloud_upload_fails_job`: main uploads only variant 0 and still reports `completed`.
- `test_temp_output_uploads_every_variant`: main has no `urls` field, and variant 1 is never uploaded.
- `test_persistent_output_reports_only_local_files`: main lists `file_paths` for outputs that were already uploaded and removed locally.

With the PR all four pass, so the behavior matches the description:
- Every output gets uploaded, and each variant's URL shows up in `urls`.
- When outputs live in a temp dir and any upload is missing, the job is marked `failed` with an error message, not `completed`.
- With a persistent `output_path`, `file_paths` only lists outputs still on disk, and `/content?variant=N` returns the cloud URL for that specific variant.

I did not run GPU end-to-end server tests here. Leaving those to CI.
