# [Fix] [Apple] mlx: Return an error for online weight updates

[Upstream PR](https://github.com/sgl-project/sglang/pull/46849) · state: closed · merged: False

## Original PR description

## Motivation

On the MLX backend, one call to `/update_weights_from_disk` stops the server.

`MlxModelRunnerStub` keeps the base Torch `WeightUpdater`, whose `get_model` returns the stub's `_DummyModel`. The first thing `update_weights_from_disk` does is walk `model.modules()`:

```
AttributeError: '_DummyModel' object has no attribute 'modules'
```

This is raised inside the scheduler's request dispatch, which doesn't catch it, so the scheduler process exits. The other update paths (`update_weights_from_tensor`, `begin_weight_update`, distributed, IPC) also go through the Torch model. Even if they didn't crash, they would update Torch weights that don't exist, while the served weights live in the MLX model.

## Modifications

- The stub overrides `init_weight_updater` with a small `_MlxWeightUpdater`. Every update entry point returns `(False, "Online weight updates are not supported on the MLX backend")`. `begin_weight_update`/`end_weight_update` are no-ops, so a tensor or distributed session fails at the load step with that message.
- Add a regression test to `test_mlx_runner_pool_contract.py`, next to the other stub-override checks.

Actually reloading weights through the MLX runner would be a separate feature.

## Accuracy Tests
