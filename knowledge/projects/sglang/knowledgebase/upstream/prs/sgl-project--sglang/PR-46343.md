# [Fix] spec: Keep routing captures aligned with accepted tokens

[Upstream PR](https://github.com/sgl-project/sglang/pull/46343) · state: open · merged: False

## Original PR description

## Motivation

With EAGLE tree drafting (`topk > 1`), accepted tokens' KV moves to the front of each request's block, but the routing and indexer captures stay in tree order. RL replay can then read valid-looking routes for the wrong tokens. NGRAM also drops the capture handles before the scheduler publishes them.

This continues my earlier #37949, which was closed by the idle-PR bot. It is rebased onto current main and preserves the original implementation and authorship. The related backend-capture, buffer-sizing, and retraction PRs address different failure modes.

## Modifications

Compact pending captures with the accepted KV and pass NGRAM's capture handles through to the scheduler. Single-stage verification defers publication until after that compaction, including when overlap scheduling is disabled.

The refresh adapts the pipeline-parallel caller and regression fixture to the current relay method, and updates the existing KV-move test to pass an explicit empty capture set. It does not add pipeline-parallel capture support.

## Accuracy Tests

All five cases in `test_accepted_path_state_capture.py` pass in an isolated source-loading CPU harness on the refreshed branch. They exercise the actual compaction, capture holder, model-runner forward, and PP relay method definitions. The fixture accepts non-front tree nodes and checks readback from nonzero KV slots. The harness excludes GPU/runtime imports, so this is not a full registered-suite run.

The two-GPU regression in `test_spec_routed_experts.py` compares routing against a cold-prefill reference for NGRAM and EAGLE topk 4, with overlap on and off. It has not run locally and still needs CI. That comparison covers routed experts; indexer captures use the same compaction mechanism.

Changed-file pre-commit checks and `git diff --check` pass.

## Speed Tests and Profiling

Not run. The added capture gather needs GPU correctness and performance validation before merge.
