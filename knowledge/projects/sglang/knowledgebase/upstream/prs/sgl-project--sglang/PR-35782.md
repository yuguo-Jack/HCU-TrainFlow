# [Feat] sgl-router: Add authenticated abort-request fan-out

[Upstream PR](https://github.com/sgl-project/sglang/pull/35782) · state: open · merged: False

## Original PR description

## Summary

Add an `/abort_request` endpoint to the SGLang router.

The router does not currently track which worker owns a particular request ID. To ensure that an abort reaches the correct worker, the endpoint forwards the original request body to every registered worker. Workers that do not own the request can safely treat it as a no-op.

## Changes

- Add `POST /abort_request` to the router.
- Forward the original JSON request body to all registered workers.
- Preserve the `application/json` content type and caller `Authorization` header when forwarding requests; do not copy unrelated caller headers.
- Limit concurrent worker requests to avoid unbounded fan-out.
- Handle plain, prefill, and decode workers consistently.
- Return a per-worker success and failure breakdown.
- Return `502 Bad Gateway` when one or more workers cannot process the request.
- Keep the route under `sgl-router/` after the upstream directory move.
- Add coverage for successful fan-out, partial failures, unreachable workers, trailing-slash URLs, empty registries, mixed worker modes, request-body forwarding, authenticated fan-out, rejected missing/invalid keys, and unrelated-header isolation.
