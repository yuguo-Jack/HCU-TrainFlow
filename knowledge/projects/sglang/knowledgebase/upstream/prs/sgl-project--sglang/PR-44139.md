# [Fix] offloader: Preserve cached weights during CPU offload

[Upstream PR](https://github.com/sgl-project/sglang/pull/44139) · state: open · merged: False

## Original PR description

## Summary

Fix CPU-offload loading and cached-weight aliasing without changing graph or quantization defaults:

- Centralize GemmaRMSNorm's `weight + 1` refresh in `refresh_gemma_weight()`. Copy CPU parameter data directly into the existing device buffer and add in place, preserving its storage and avoiding a temporary device tensor. Both checkpoint loading and presharded rebinding use it.
- Match cached ordinary tensor attributes against parameter storage by `(device, untyped_storage().data_ptr())`, across the owner and its children. Apply this residency protection in OffloaderV1 and OffloaderV2, including V2 aliases held outside the selected submodule. Preserve the existing MLA protection.
- Share convolution-view rebuilding through `RadixLinearAttention.refresh_conv_weights()` in the presharded and IPC loaders.
- Move accelerator regressions to `test/registered/model_loading/test_cpu_offloader.py`, use `CustomTestCase`, and retain CUDA/XPU CI registration. Exercise real `ColumnParallelLinear`/`MergedColumnParallelLinear` layouts, renamed aliases, Gemma checkpoint/rebind paths, V2 whitelist selection, and both loaders' view rebuilding.

## Problem

CPU offload moves parameters to host memory while buffers can remain on the accelerator. GemmaRMSNorm's loader and reload helper currently add the CPU parameter directly into the accelerator `gemma_weight` buffer, causing a device mismatch during loading.

Separately, Qwen3.5 GDN constructs `attn.conv_weights` as an ordinary tensor view of `conv1d.weight`. `functional_call` substitutes registered parameters and buffers, but does not substitute that ordinary attribute. Offloading the parameter can therefore leave attention reading stale accelerator storage after checkpoint loading. The existing protection recognizes KDA's `qkv_conv1d` spelling but misses GDN's `conv1d`.

This can silently produce incorrect speech even when serving returns HTTP 200. In a small accelerator reproducer, GDN returned `[0, 0]` after weight updates when the expected forward output was `[6, 6]`. KDA's already-protected equivalent returned the expected result. After this fix, both pass and ordinary projection parameters still reside on CPU.

The shared loader/offloader fixes preserve CPU offload, quantization, and graph defaults.
