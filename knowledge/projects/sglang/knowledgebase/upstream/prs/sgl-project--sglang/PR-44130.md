# feat: integrate KVPress as optional KV-cache compression backend (prototype)

[Upstream PR](https://github.com/sgl-project/sglang/pull/44130) · state: closed · merged: False

## Original PR description

## Summary

Closes #10585.

Add a thin adapter layer that bridges SGLang's prefill KV write path with the NVIDIA [kvpress](https://github.com/NVIDIA/kvpress) library, which provides a pluggable family of KV-cache compression heuristics (SnapKV, AdaKV, ChunkKV, random baselines, etc.).

This PR is a **focused prototype** — intentionally small, well-documented, and designed so reviewers can extend it without reworking the adapter layer.

## What was added

1. **New file: `sglang/srt/layers/kvpress_adapter.py`** (~400 LOC)
   - Optional-dependency-safe (`try: import kvpress`). SGLang boots without it.
   - Translates between SGLang's flat KV layout (`[total_tokens, num_heads, head_dim]`) and KVPress's per-request stacked format (`(batch, num_kv_heads, seq_len, head_dim)`).
   - Lazily mirrors `kvpress.presses` into a name → class registry so new methods added upstream are picked up automatically.
   - Exposes a single public entry point `maybe_compress_prefill_kv(k, v, layer, forward_batch)` that attention backends can call before writing KV to the paged cache.
   - Zero-masks the lowest-scoring KV entries (keeps cache layout valid, memory footprint unchanged — see scope/limitations below).
   - `_FakeTransformersAttnModule` shim adapts SGLang's `RadixAttention` attributes (`tp_q_head_num`, `tp_k_head_num`, `head_dim`, `qk_head_dim`) to the `transformers` attention-module interface that KVPress presses expect.

2. **New envs on `sglang.srt.environ.Envs`**:
   - `SGLANG_ENABLE_KVPRESS` (bool, default `False`) — master switch.
   - `SGLANG_KVPRESS_METHOD` (str, default `"random"`) — press name, looked up in the registry.
   - `SGLANG_KVPRESS_COMPRESSION_RATIO` (float, default `0.5`) — fraction of KV entries to drop, passed to `ScorerPress` subclasses.

3. **Hook into `torch_native_backend.forward_extend`**: before `token_to_kv_pool.set_kv_buffer`, call `maybe_compress_prefill_kv`. The hook is imported lazily at module load so the hot-path cost is paid only when `SGLANG_ENABLE_KVPRESS=1`.

## Scope (intentional prototype)

| Area | Status | Follow-up |
|------|--------|-----------|
| Prefill-phase compression (ScorerPress family) | ✅ Zero-masking hook in | Page-table compaction for memory savings |
| Decode-phase masking (`kvpress.attention_patch`) | ❌ Not wired | Post-prefill hook + mask propagation |
| FlashInfer / Triton / DeepSeek-V4 backends | ❌ Only `torch_native_backend` | Copy the hook into each backend's KV write path |
| TP / PP / DP awareness | ❌ Each rank compresses independently | Coordinated cross-rank compression |
| CUDA graph recording | ❌ Short-circuits under `torch.compiler.is_compiling()` | Graph-friendly mask kernels |
| Generic `BasePress` subclasses | ❌ Only `ScorerPress` children have a `score()` we can call | Adapter for the generic `compress()` return path |

## How to try it

```bash
pip install kvpress                # brings transformers too
export SGLANG_ENABLE_KVPRESS=1
export SGLANG_KVPRESS_METHOD=random  # or snapkv, knorm, tokcope, adakv, ...
export SGLANG_KVPRESS_COMPRESSION_RATIO=0.5
python -m sglang.launch_server --model ... --attention-backend torch_native ...
```

On first prefill the adapter logs one info line:
`KVPress enabled: method=random compression_ratio=0.5 press=RandomPress(compression_ratio=0.5, seed=None)`
