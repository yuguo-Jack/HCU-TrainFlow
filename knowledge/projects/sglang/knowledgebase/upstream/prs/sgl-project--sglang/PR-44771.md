# [CI] lora: Use the canonical Llama model ID in eviction tests

[Upstream PR](https://github.com/sgl-project/sglang/pull/44771) · state: closed · merged: True

## Original PR description

## Motivation

`test_lora_eviction.py` fails during model loading on the 5090 runner in [this extra-a CI job](https://github.com/sgl-project/sglang/actions/runs/38833170655/job/116756528883?pr=43387), before any eviction assertions run:

```text
RuntimeError: Cannot find any model weights with `meta-llama/Meta-Llama-3.1-8B-Instruct`
```

The test still uses the legacy repository ID. Hugging Face redirects its model API to `meta-llama/Llama-3.1-8B-Instruct`, which is already used by the other Llama 3.1 LoRA tests. Repository IDs also determine local Hugging Face cache paths, so the legacy name does not directly reuse a cache populated under the canonical ID. The job log does not establish why the legacy snapshot had no usable weights.

## Modifications

Use `meta-llama/Llama-3.1-8B-Instruct` as the eviction test's base model ID, avoiding the legacy alias and aligning its cache lookup with the other tests. The model, adapters, eviction sequences, and output comparisons are unchanged.

## Accuracy Tests

- Confirmed the legacy Hugging Face model API redirects to the canonical ID and the canonical metadata lists four safetensors shards.
- Python AST parsing, Ruff lint/format, isort, and `git diff --check` passed.
- GPU eviction tests were not run locally: this workspace is macOS without a CUDA GPU. The registered `extra-a` test still needs CI validation.

## Speed Tests and Profiling

Not applicable; test model identifier only.
