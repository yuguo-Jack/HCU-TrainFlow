# [rust-server] bound and fail fast rust warmup

[Upstream PR](https://github.com/sgl-project/sglang/pull/43223) · state: open · merged: False

## Original PR description

Follow-up to #43004 addressing its review.

- **Bound the warmup inside `warm_up`** ([review](https://github.com/sgl-project/sglang/pull/43004#discussion_r4213344109)). `warm_up` now takes a `timeout` that covers admission and the whole response stream, like `probe_health(timeout)`. On expiry, the dropped call aborts the request, so a stream that never ends cannot hang it ([review](https://github.com/sgl-project/sglang/pull/43004#discussion_r4213317417)). The caller still resolves `SGLANG_WARMUP_TIMEOUT` (default 600 s, 1800 s for PD). The request is built in `warm_up_request`.
- **Fail fast when the warmup fails or times out**, matching Python's `kill_process_tree` ([review](https://github.com/sgl-project/sglang/pull/43004#discussion_r4213351351)). Previously the listener logged an error and returned 503 forever while the process stayed up. It now sends SIGQUIT to its parent, the same path a scheduler exception takes, so the launcher tears down the process tree.
- **Ignore EOS in the PD warmup**, to ensure consistent warmup, and avoid stopping generation after less than 8 tokens in case of an early EOS.
