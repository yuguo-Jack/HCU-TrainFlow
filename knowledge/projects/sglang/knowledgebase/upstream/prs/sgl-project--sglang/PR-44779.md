# [Perf] [NVIDIA] diffusion: Support per-token shift/scale in the fused norm_scale_shift kernel

[Upstream PR](https://github.com/sgl-project/sglang/pull/44779) · state: open · merged: False

## Original PR description

## Motivation

FLUX.3 modulates every token separately, so its blocks pass per-token shift/scale tensors to `fused_norm_scale_shift`. The fused CUDA kernel (`kda_kernels/norm_scale_shift`) only handled one shift/scale row per batch, so on Blackwell every FLUX.3 block fell back to the slower CuTe-DSL kernel. This PR adds a per-token variant of the fused kernel and routes those calls to it.

## Modifications

- `norm_scale_shift.cuh`: a `kPerTokenMod` template parameter that offsets the shift/scale loads by the token row, and a `NormScaleShiftPerTokenKernel` BF16 entry point (non-residual path).
- `norm_scale_shift_jit.py`: `try_fused_norm_scale_shift` keeps the per-batch row path and additionally dispatches contiguous per-token shift/scale (`[1, S, D]` or `[S, D]`, matching `x`) to the new entry point. Other inputs still fall back to CuTe-DSL as before.
- `test_norm.py`:
  - The per-token path matches the CuTe-DSL reference for FLUX.3 token counts (text stream and 1024x1024 joint stream) and both modulation ranks, and the public `fused_norm_scale_shift` op returns the same output.
  - Strided (non-contiguous) per-token modulation is rejected and falls back.

## Accuracy Tests

Kernel-level: the per-token kernel matches the CuTe-DSL reference (`test_norm.py`, atol/rtol 5e-2). Against an FP32 reference on B200, both kernels have the same max abs error (~0.03) at every token count in the table below.

## Speed Tests and Profiling

Kernel, B200, per-token shift/scale, hidden 3072, cold L2 (`marker.do_bench`):

| Tokens | Fused (this PR) | CuTe-DSL fallback | Speedup |
|---|---|---|---|
| 1,024 | 5.2 us | 6.5 us | 1.25x |
| 4,608 | 17.7 us | 22.0 us | 1.24x |
| 9,216 | 33.9 us | 41.6 us | 1.23x |
| 18,432 | 65.3 us | 80.9 us | 1.24x |

At 9k tokens the fused kernel reaches ~84% of B200 HBM bandwidth (CuTe-DSL: ~68%).
