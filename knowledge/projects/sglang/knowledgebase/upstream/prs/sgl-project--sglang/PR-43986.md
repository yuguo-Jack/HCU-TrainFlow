# [Perf] Avoid copying row-padded FlashInfer PAGED top-k logits

[Upstream PR](https://github.com/sgl-project/sglang/pull/43986) · state: open · merged: False

## Original PR description

## Motivation

FlashInfer PAGED top-k accepts a physical row stride, but SGLang materializes a contiguous copy of row-padded producer logits before calling it. That copy adds prefill latency for long contexts.

## Modifications

Pass logits directly to the kernel — producers emit row-padded layouts (columns contiguous, row stride >= logical width) that FlashInfer PAGED top-k accepts natively, so the contiguous copy is never needed. Verified against real serving layouts (e.g. decode width=163904 with pitch=164096). RAGGED behavior is unchanged.

## Tests

- Changed-file pre-commit.
- Upstream-tree serving validation on a public DSA model (release v0.5.21 + this change; the touched file is byte-identical between release and this PR's base): DeepSeek-V3.2-Exp, TP8 on 8x B300, `--dsa-topk-backend flashinfer`, GSM8K full 1319 at temp 1.0 / top_p 0.95 — score 95.75% and 95.98% across two seeds, stop-rate 100.00%, truncated 0%, error 0%.

## Performance

Top-2048 transform latency on B300 (fp32 logits, pitch = width + 2048), old (copy + kernel) vs new (direct):

| Shape (rows x width) | Old | New | Saved |
|---|---|---|---|
| 64 x 65536 (16.8MB) | 40.6us | 31.6us | 22.0% |
| 256 x 131072 (134MB) | 180.0us | 105.0us | 41.7% |
| 2048 x 65536 (537MB) | 809.4us | 455.3us | 43.7% |
| 8192 x 131072 (4.3GB) | 4890.5us | 2820.0us | 42.3% |

Long-context prefill chunk (8192 x 131072) saves ~2.1ms per top-k transform; decode at 256 x 131072 saves ~75us per step.
