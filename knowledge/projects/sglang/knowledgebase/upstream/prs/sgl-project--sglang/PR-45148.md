## Motivation

`DraftBackendFactory` builds EAGLE draft attention backends only from a closed in-tree map. An attention backend that an out-of-tree (OOT) platform or plugin registers with `register_attention_backend` therefore cannot serve the draft of EAGLE-family speculative decoding (including NEXTN / MTP) on the built-in worker; the factory raises `EAGLE is not supported in attention backend ...`.

This is part of generic OOT speculative-decoding support: a platform that runs the built-in EAGLE worker with its own attention kernels needs a way to provide the draft backends, and plugins that patch the factory today can drop that patch. A name-keyed registry matches how OOT platforms already contribute their main attention backends.

## Modifications

- `attention_registry.register_draft_attention_backend(name)` / `DRAFT_ATTENTION_BACKENDS`, mirroring `register_attention_backend` / `ATTENTION_BACKENDS`. The factory is called as `fn(runner=, topk=, speculative_num_steps=)` and returns a multi-step container exposing `attn_backends`.
- `DraftBackendFactory._create_backend`: built-in names are looked up first, unchanged. A name with a registered draft factory is built from it for draft decode and from the regular `ATTENTION_BACKENDS` factory of the same name for draft extend, stamped with that name. Registering the draft factory is the opt-in: a backend without one keeps the existing error.
- Docs: the plugin guide shows how to register a draft backend.
