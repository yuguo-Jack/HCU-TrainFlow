# [Perf] [AMD] Kimi-K3: emit AITER's MoE sort from the radix-4 router launch

[Upstream PR](https://github.com/sgl-project/sglang/pull/43126) · state: open · merged: False

## Original PR description

## Motivation

- Kimi-K3 serving on MI355X is decode-bound: AgentX interactivity is set by per-step latency at small batch sizes (M <= 64 tokens per MoE call).
- At that size each MoE layer runs three launches before the expert GEMMs: the radix-4 router, AITER `moe_sorting`, and the zeroing of the MoE output.
- The sort and the zeroing are short, latency-bound launches. K3 has 92 MoE layers, so they add 184 launches to every decode/verify step.
- The router launch already produces every route: its last CTA to finish can sort them, and each CTA can zero its own output row, so neither needs a separate launch.
- Goal: remove those 184 launches per step without changing routing or MoE output.

## Modifications

- `route_radix4_with_sort`: one launch routes, writes AITER's BM=16 MoE sort, and zeroes the MoE output.
- `srt/layers/moe/aiter_presort.py`: hands the sort to the next `fused_moe` via `register_presorted_moe` (ROCm/aiter#6484); AITER then skips `moe_sorting` and the zeroing.
- Scope and fallbacks:

| Condition | Path |
|---|---|
| 1 <= M <= 64, AITER has `register_presorted_moe` | fused route + sort |
| M > 64, or AITER without [#6484](https://github.com/ROCm/aiter/pull/6484) | unfused router, as before |
| `SGLANG_SIMULATE_*_EXPERTS` set | unfused router |
| Tuned kernel for M is not BM=16 (Kimi-K3 table: M=3 only) | AITER logs once and sorts again |
| `expert_mask` set (EP) | AITER rejects the presort and sorts again |

- CUDA-graph padding rows are routed to expert 0 with weight 0, matching the HIP mask in `select_experts`.
- The host side checks sorted-row capacity and `reverse_sorted` length; the kernel writes them unchecked.
- No dependency on other SGLang PRs.

| New env var | Default | Effect |
|---|---|---|
| `SGLANG_OPT_HIP_K3_RADIX4_FUSE_SORT` | on | `0` keeps the radix-4 router unfused |

## Accuracy Tests

Model eval: `sgl-eval 0.1.3 run gsm8k --load-preset-from-model-id moonshotai/Kimi-K3 --num-threads 32` (full 1319, temperature 1.0, top_p 0.95, thinking on, reasoning_effort max).

| Fused sort | GSM8K | Truncated | Errors |
|---|---:|---:|---:|
| on | 97.19% | 0 | 0 |
| off | 97.50% | 0 | 1 |

- The gap is 4 questions, within sampling noise (single-run stderr ~0.47 pp at temperature 1.0).
- Setup: 8x MI355X, `Kimi-K3-Quark-MXFP4-AttnFP8`, AgentX c16 recipe (cookbook MI35x TP8/DCP8 AITER + HiCache, DSpark block 4, decode graphs bs 1-32). Simulated acceptance (`SGLANG_SIMULATE_ACC_LEN`) is off so outputs are real. Only `SGLANG_OPT_HIP_K3_RADIX4_FUSE_SORT` differs.
- ROCm/aiter stack including [#6484](https://github.com/ROCm/aiter/pull/6484).

Kernel tests (`test/registered/kernels/ops/moe/test_moe_route_radix4.py`, 69 passed on MI355X):

- Fused launch returns the same ids and weights as `route_radix4`, bit for bit.
- Sort checked entry by entry against the routes for M = 1 to 128, with padding rows, and across CUDA-graph replay.
- AITER's `match_presorted_moe` accepts the aux for M = 1, 12, 64.
