# [Perf] deepseek-v4.1: Check request-window SWA history without per-layer host syncs

[Upstream PR](https://github.com/sgl-project/sglang/pull/45223) · state: closed · merged: True

## Original PR description

- With encoder SWA bounded replay on, `RequestWindow.buffer` checked each SWA layer's history before use with boolean-mask indexing and `torch.equal`: three host syncs per SWA layer per extend step, so the scheduler could not run ahead of the GPU.
- The check now goes through the sync-free invariants API (`utils/invariants.py`): `expect` on a `dsv41.swa_history_present` invariant (`FATAL_CONTAINABLE`), so `SGLANG_INVARIANT_CHECK` decides it: off in production (no detection), a throttled count and log at WARN, a device-side assert at STRICT.
- Behavior change: with `SGLANG_INVARIANT_CHECK` off (the default), servers no longer check SWA history; CI runs at STRICT and still fails on a missing history.
- Verification: DeepSeek-V4.1-Flash on GB300, DP2 attention + MegaMoE (EP2), encoder and decoder replay on, a multi-turn agentic prefill trace at concurrency 512, 900 s per run, same-node pairs.
  - Before: py-spy put 75% of the scheduler main thread's samples in `RequestWindow.buffer`.
  - Removing the per-layer check: +4.5% to +6.7% tok/s/GPU on three nodes; the step interval went from ~405 to ~375 ms at the same step shape.
  - The deferred-flag version of this check (an earlier revision of this PR) ran within -1.3% to +0.7% of removing the check on three nodes, with no false raise; the invariants version adds only the comparison kernels.
  - `test_dsv41_request_window_copy.py` passes. A one-off GPU script confirmed: matching history passes at STRICT; missing history passes at OFF and trips `invariant-check FAILED [dsv41.swa_history_present]` at STRICT.
