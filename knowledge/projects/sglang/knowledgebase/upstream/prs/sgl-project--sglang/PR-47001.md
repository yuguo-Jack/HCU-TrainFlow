# [Perf] [XPU] qwen3: Fuse q/k RMSNorm and RoPE on XPU

[Upstream PR](https://github.com/sgl-project/sglang/pull/47001) · state: open · merged: False

## Original PR description

## Motivation

On XPU, every Qwen3 dense layer runs the q RMSNorm, the k RMSNorm and RoPE as three kernel launches. Qwen3-MoE already replaces them with one in-place launch, sgl-kernel-xpu's `fused_inplace_qknorm_rope`, under `--enable-fused-qk-norm-rope`, which is on by default on XPU. Qwen3 dense (`Qwen3Attention`) never took that path.

## Modifications

- `models/qwen3.py`: new `use_fused_qk_norm_rope_xpu`, decided once in `Qwen3Attention.__init__`. When it is set, `forward_prepare_native` calls `fused_inplace_qknorm_rope` on the strided q/k views of `qkv`, normalizing and rotating them in place. This is the same call Qwen3-MoE makes.
- The fused path is used only when all of these hold; otherwise the unfused path runs unchanged:
  - the device is XPU,
  - `--enable-fused-qk-norm-rope` is set,
  - RL on-policy mode is off (it needs the FP32 norm),
  - the rotary embedding is not mrope,
  - the head dim is 64, 128 or 256,
  - q_norm and k_norm use the same eps,
  - the dtype is bf16.
- `test/registered/xpu/test_fused_inplace_qknorm_rope_xpu.py`: the existing test checks the fused call against the model's unfused path. It now also covers the per-rank head counts of Qwen3-32B at TP4 (16 q / 2 kv heads), in addition to Qwen3-30B-A3B's (8 / 1).

## Accuracy Tests

- `test_fused_inplace_qknorm_rope_xpu.py`: 32 passed on Arc Pro B70, with sgl-kernel-xpu 0.4.0 and 0.5.0. The cases include YaRN scaling, partial rotary, neox and non-neox, and 1 and 257 tokens.
- GSM8K on Qwen3-32B, TP4: 94.31% before, 94.77% after. Same within sampling noise. Settings: sgl-eval, full 1319 questions, temperature 0.7, top-p 0.8, thinking off, max 2048 tokens, seed 0.

## Speed Tests and Profiling

**Setup:**
- 4x Arc Pro B70, TP4, torch 2.14.0+xpu, compute-runtime 26.31.
- Server flags: cookbook BMG flags plus `--attention-backend intel_xpu --page-size 64 --cuda-graph-backend-decode full --cuda-graph-backend-prefill breakable`.

Qwen3-32B, `bench_serving` random 512 in / 256 out, TPOT in ms, ABBA order. A is `--no-enable-fused-qk-norm-rope`, B is this PR's default.

| | c=1 | c=4 | c=16 |
|---|---|---|---|
| A | 31.60, 31.58 | 32.56, 32.54 | 34.94, 34.95 |
| B | 31.38, 31.38 (-0.7%) | 32.29, 32.23 (-0.9%) | 34.91, 34.82 (noise) |

TTFT is about 1% lower. The gain is small because Qwen3-32B decode is bound by weight bandwidth. The PR mostly brings dense Qwen3 onto the path Qwen3-MoE already takes.
