# [Refactor] radix-cache: Route pending-backup split bookkeeping through one component action

[Upstream PR](https://github.com/sgl-project/sglang/pull/45242) · state: closed · merged: True

## Original PR description

Stacked on #45238 (`oss-sync-3cc5dd45b8`): this pull request is based on that branch and its own diff is only its top commit. Please read it after #45238; once that lands this branch is rebased onto `main`.

## Motivation

A node split used to produce `ReplaceWriteThroughOnNodeSplit` only when the split node carried a write-through ack, and `UnifiedRadixCache` applied it by itself: it retargeted its ongoing write-through publish list and the linker's pending offload entry, and nothing else heard about the split. A FULL component that tracks its own per-node buffer-write dependencies therefore could not follow a split, and in host-memory buffer-only mode, where writes are tracked by the cache rather than by a node ack, no action was emitted at all.

## Modifications

`ReplaceWriteThroughOnNodeSplit` becomes `UpdatePendingBackupOnNodeSplit`, a `ComponentAction` routed to FULL with an optional `ack_id`, on both tree cores:

- The tree core emits it on every split of a node with a pending write-through ack, and on every split while the core is in host-memory buffer-only mode (then with `ack_id=None`). The new prefix node still inherits the ack when there is one.
- `UnifiedRadixCache._apply_cache_action` applies it in one place and in order: when `ack_id` is present it first retargets the ongoing write-through publish list and the linker's pending offload node, then hands the same action to the FULL component. `FullComponent` accepts it as a no-op; a FULL component that tracks buffer-write dependencies handles it in its own `apply_component_action`.
- The SWA component's fresh-leaf window cap (`_maybe_split_leaf_for_swa_lock` / `maybe_split_leaf_for_swa_lock_`) forwards the split action it receives into the batch instead of asserting that none was produced; the assertion now only rejects a split that carries an ack. The SWA boundary split in the Rust core does the same.
- The Rust binding tag becomes `update_pending_backup_on_node_split` and the ack travels as `Option<usize>`; the Python adapter decodes it into the new action.

Behaviour is unchanged for caches that are not in buffer-only mode and use the in-tree `FullComponent`: the same two retargeting calls happen in the same order, followed by a no-op.
