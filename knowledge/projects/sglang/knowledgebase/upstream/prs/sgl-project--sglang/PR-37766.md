# [Intra-node PD][DSV4] Layer batching and status polling optimization

## Motivation

1. When deploying intra-node pd disaggregation and nvlink is set for kv transfer, transfer worker will submit each layer as a batch to mooncake engine, which greatly slows down the intra-node pd performance. In contrast, when taken rdma, transfer worker will patch all layers and submit all of them as one batch to mooncake.
3. In poll_and_all_reduce_attn_cp_tp_group where we check the kv transfer status, the real kv transfer may be in progress because send_kv_chunk is only for enqueueing and right after send_kv_chunk we do poll. Therefore, polling might miss and the kv transfer latency and TTFT will include the launch duration of next batch.

## Modifications

1. ~~When INTRA_NODE_NVLINK is set for transfer, pack all the layers as 1 batch, just like rdma.~~ Layer batching is implemented in PR #38984.
2. Add a user-defined timeout_s and wait until kv transfer is really completed or timeout, so that can reduce the TTFT. It can also greatly reduce the kv_transfer_latency_ms metrics and let the metric be less misleading.

## Speed Tests and Profiling

### Metrics
After applying **polling optimization**, average kv_transfer_latency_ms decreases from **119ms to 21ms**, indicating that in intra-node case, the polling miss contributes to the most of kv_transfer_latency metric.
