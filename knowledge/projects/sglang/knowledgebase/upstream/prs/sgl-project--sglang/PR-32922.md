# [AMD] Fix silent greedy fallback in speculative decoding verify on ROCm

[Upstream PR](https://github.com/sgl-project/sglang/pull/32922) · state: closed · merged: False

## Original PR description

## Summary

* On ROCm, `eagle_sample` gates the verifier on `if sampling_info.is_all_greedy or _is_cpu or _is_npu or _is_hip or _is_xpu:`, so **every** HIP request takes the `torch.argmax` greedy path regardless of `temperature` / `top_p` / `top_k`. Speculative decoding is supposed to be distribution-preserving; on ROCm it silently is not, and enabling a speculator effectively forces `temperature=0`.
* The `_is_hip` entry exists because the distribution-preserving path needs kernels the ROCm sgl-kernel build does not compile: `csrc/speculative/speculative_sampling.cu` (`tree_speculative_sampling_target_only`) and flashinfer's `renorm.cu` (`top_k_renorm_prob`, `top_p_renorm_prob`) are absent from `setup_rocm.py`. Rather than erroring, the code degraded to greedy.
* The Triton `chain_speculative_sampling_triton` verifier behind `--speculative-use-rejection-sampling` is platform-independent and already in the tree, so a correct verifier does exist on ROCm — it was simply unreachable. Remove the `_is_hip` shortcut, supply torch equivalents of the two missing renorm ops, and raise instead of silently downgrading when no distribution-preserving verifier is available.
* This is a correctness bug, not a missing feature, and it is invisible to the usual accuracy suites because those run greedily (`temperature=0` sets `is_all_greedy`, so both paths agree). It surfaced on GLM-5.2-FP8 + EAGLE MTP on MI300X: a long-horizon reasoning eval at `temperature=1, top_p=0.95, n=8` dropped from 75% to 0% pass rate, with generated length inflating from ~30k to ~123k tokens as the forced-greedy model fell into repetition loops and never emitted a stop token.

## Changes

| File | Change |
| --- | --- |
| eagle_utils.py | Drop `_is_hip` from the greedy-verify gate, so non-greedy requests on ROCm reach the Triton chain verifier instead of `argmax`. Supply torch fallbacks for the two renorm ops missing from the ROCm build, raise `NotImplementedError` if no distribution-preserving verifier is available, and import the CUDA-only tree kernel lazily. |
| test_spec_verify_distribution.py | New test: the chain verifier preserves the target distribution, the greedy verifier collapses to argmax, and the renorm fallbacks match the kernels they replace. |

## Scope

* ROCm (`_is_hip`) speculative decoding with non-greedy sampling. Previously unreachable, now routed through the Triton chain verifier.
* No CUDA behavior change: `_get_spec_renorm_fns()` returns the same `sgl_kernel` ops that were imported before, the gate condition is otherwise unchanged, and greedy requests short-circuit on `is_all_greedy` before any platform check on every platform.

## Test plan

**Accuracy (long-horizon math reasoning, `n=8`, `temperature=1`, `top_p=0.95`, `max_tokens=131072`, GLM-5.2-FP8, MI300X / ROCm 7.2.0, EAGLE MTP `--speculative-num-steps 5 --speculative-eagle-topk 1 --speculative-num-draft-tokens 6`):**

| Configuration | Pass rate | Generated tokens (min / mean / max) | Hit 131k cap | Mean accepted length |
| --- | --- | --- | --- | --- |
| No speculator (reference) | 6/8 (75%) | 25.7k / 29.8k / 33.6k | 0/8 | n/a |
| EAGLE MTP, before | 0/8 (0%) | 65.1k / 122.8k / 131.1k | 7/8 | 5.59 / 6 |
| EAGLE MTP, after (`--speculative-use-rejection-sampling`) | 6/8 (75%) | 24.8k / 29.9k / 38.0k | 0/8 | 4.56 / 6 |

The speculator now matches the no-speculator reference. Accepted length drops from 5.59 to 4.56 because the pre-PR number came from a greedy draft agreeing with a greedy target; it was not a real acceptance rate.

**Kernel-level (one identical target distribution fed to both verifiers, total-variation distance of the emitted token distribution from the intended one):**

| Verifier | TV distance from target |
| --- | --- |
| Greedy (`verify_tree_greedy`, pre-PR ROCm path) | 0.65 |
| `chain_speculative_sampling_triton` (post-PR ROCm path) | 0.0023 |

**Performance:** greedy traffic is unaffected by construction — `is_all_greedy` short-circuits the gate before any platform check, so greedy requests execute the same verify path before and after on every platform. Measured on GLM-5.2-FP8 / MI300X (`sglang.benchmark.serving`, ISL 8192 / OSL 1024, concurrency 16), decode speed on the greedy path is unchanged (10.59 vs 10.63 ms median ITL) and the newly reachable non-greedy path costs ~2% (10.84 ms). Accepted length on the real reasoning workload above goes from 5.59/6 to 4.56/6, so a modest decode cost is expected on real non-greedy traffic; the pre-PR 5.59 was not a genuine acceptance rate.

**Unit test** (`test/registered/kernels/ops/speculative/test_spec_verify_distribution.py`, registered for both CUDA and AMD CI):

* `test_chain_sampler_preserves_target_distribution` — feeds one shared target distribution across all draft positions with the draft proposing a different one, and asserts the aggregate emitted distribution stays within 0.02 total variation of the target.
* `test_greedy_verify_collapses_to_argmax` — asserts the greedy verifier emits the target argmax and nothing else, i.e. it is not a valid substitute for a non-greedy request.
* `TestSpecRenormFallbacks` — checks the torch renorm fallbacks against `sgl_kernel`'s `top_k_renorm_prob` / `top_p_renorm_prob`, skipping where those ops are unregistered. Compared as distributions rather than element-wise, since the two implementations locate the cutoff differently (sort-and-scan vs pivot search) and may disagree on a probability sitting exactly at the boundary.

Run on MI300X / ROCm 7.2.0: the two verifier tests pass, and `TestSpecRenormFallbacks` skips with `sgl_kernel renorm ops are unavailable: '_OpNamespace' 'sgl_kernel' object has no attribute 'top_k_renorm_probs'` — which is the build gap this PR works around. The renorm comparison itself needs CUDA hardware and is left to CI; `_top_k_normalize_probs_torch` was checked against a value-threshold reference implementation on ROCm and agrees to ~1e-7.
