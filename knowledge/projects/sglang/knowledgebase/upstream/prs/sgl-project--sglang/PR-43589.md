## Motivation

Image-to-3D in ComfyUI currently needs the fragile per-package Hunyuan3D installs. The SGLang Diffusion server already serves Hunyuan3D through `POST /v1/meshes`, so a server-mode node can give ComfyUI users image-to-3D with no extra installs, and the result plugs into ComfyUI's built-in 3D preview.

## Modifications

- `SGLDiffusionGenerateMesh` node (server mode). Inputs: the server client, an image, and optional `output_format` (glb or obj), `seed`, `steps` and `guidance_scale` (-1 / 0 keep the server defaults). Outputs: ComfyUI's `FILE_3D` type (accepted by `Preview 3D` and `Preview 3D (Advanced)`) and the saved file path. The mesh is saved under the ComfyUI output directory in `mesh/`.
- `SGLDiffusionServerAPI.generate_mesh` uploads the image as multipart, then polls the job. `fetch_mesh` puts the file in place: it copies it when the server shares the filesystem, downloads it from the cloud URL when the server stored it in cloud storage (the API key is not sent to that host), and otherwise downloads it from `/v1/meshes/{id}/content`.
- Example workflow `sgld_image_to_3d.json` and README entries.
- No paint (texturing) toggle. Texturing is chosen when the server is launched (the Hunyuan3D `paint_enable` setting), and `MeshGenerationsRequest` has no field for it, so a node option would do nothing. A per-request option would need a server-side change.

## Accuracy Tests

Against a real server on a GPU (L40S): `sglang serve --model-path tencent/Hunyuan3D-2` (the launch used by the repo's pinned CI case; there is no Hunyuan3D cookbook page) with the CI test image.
- GLB: job completed, 23.9 MB, valid `glTF` header, 536,896 vertices and 705,768 faces. The first request took 270 s on a cold server.
- Remote download path: byte-identical to the server's own file.
- OBJ: real vertices and faces.
- The node, run with a real ComfyUI checkout: returns a genuine `File3D` (format `glb`) and saves the file.

CPU unit tests (`test_comfyui_mesh.py`) run the client against a local HTTP server that speaks the job protocol, covering the multipart upload fields, polling, failure messages, the three file sources, and unset options not being sent: 6 pass without ComfyUI, 7 with it. The related ComfyUI tests pass (69 passed). The lint hooks pass at the repo's pinned versions, and the example workflow validates against ComfyUI's node definitions.

Not covered: a textured mesh (depends on the server's paint setting), a server behind cloud storage, and AMD (the repo skips Hunyuan3D on ROCm).
