## Motivation

<!-- Describe the purpose and goals of this pull request. -->

While auditing the NPU test registrations we found that several tests request far more cards than they actually use. For example, `test_npu_pd_disaggregation` only occupies 4 cards (prefill tp2 on cards 0-1, decode tp2 on cards 2-3) but is registered to the 16-card suite, which wastes runner capacity and adds queueing time to the nightly pipeline.

This is a temporary CI-only PR used to verify that the four audited tests can actually run on runners sized to the cards they use. In the first validation run all four passed on 4-, 2- and 8-card runners, so `test_npu_load_balance_method_pd_disaggregation` was additionally adjusted to fit 4 cards. It is not intended to be merged as-is; the temporary registrations and jobs will be reverted once the validation is done.

## Modifications

<!-- Detail the changes made in this pull request. -->

- Add temporary `register_npu_ci(..., suite="tmp-...", nightly=True)` registrations, sized by the cards each test actually uses (all marked with `TEMP` comments):
  - `test_npu_pd_disaggregation.py` -> `tmp-nightly-4-npu-a3`: prefill `--tp-size 2` (cards 0-1) + decode `--tp-size 2` (cards 2-3) = 4 cards.
  - `test_npu_load_balance_method_pd_disaggregation.py` -> `tmp-nightly-4-npu-a3`: 4 cards in total. Its prefill `--base-gpu-id` was changed from 4 to 0, because prefill tp2 on cards 4-5 plus decode tp2 on cards 2-3 required at least 6 visible cards.
  - `test_npu_qwen3_6_27b_2p_in64k_out1k_prefix90_50ms.py` and `test_npu_qwen3_6_27b_w8a8_1p_in64k_out1k_50ms.py` -> `tmp-nightly-perf-2-npu-a3`: both use `--tp-size 2`, i.e. 2 cards.
- `nightly-test-npu.yml`: add the two matching jobs (`tmp-nightly-4-npu-a3`, `tmp-nightly-perf-2-npu-a3`) and set every other job, including `check-all-jobs`, to `if: false`, so a run only exercises the temporary jobs. `set-image-config` stays enabled because the new jobs depend on it.
- No changes to `test/run_suite.py`: NPU is not in `_SUITE_CHECKED_BACKENDS`, so the temporary suite names are collected by name and only trigger the existing "unknown suite" warning.
