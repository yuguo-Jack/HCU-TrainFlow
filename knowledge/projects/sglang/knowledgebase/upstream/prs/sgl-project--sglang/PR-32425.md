# [Feat] gemma4: Make multimodal loading opt-in

[Upstream PR](https://github.com/sgl-project/sglang/pull/32425) · state: open · merged: False

## Motivation

Gemma 4 multimodal models currently build their vision and audio components and load their weights even for text-only serving. This increases memory usage and model load time. It also causes SGLang to treat the model as multimodal and disable the prefill CUDA graph because breakable CUDA graphs are incompatible with multimodal models.

This PR makes Gemma 4 multimodal loading opt-in with `--enable-multimodal`, matching Llama 4 and Gemma 3.

> On a DGX Spark with TP1, text-only mode increased the default static memory fraction from `0.8115` to `0.8880` and reduced memory used by model weights. Together, these changes increased the KV cache capacity from 265,062 to 326,684 tokens, an increase of 61,622 tokens or 23.2%.

## Modifications

- Default `gemma4_mm` and `gemma4_unified` to text-only mode.
- Build and load vision and audio components only when `--enable-multimodal` is set.
- Update Gemma 4 deployment documentation with the new default and flag.
- Enable multimodal mode explicitly in the existing Gemma 4 MMMU eval configurations.

## Accuracy Tests

Not applicable. This PR does not change model computation. 
The registered Gemma 4 MMMU eval configurations now pass `--enable-multimodal` explicitly and keep their existing thresholds.

## Speed Tests and Profiling

Not applicable. This PR only skips multimodal component construction and weight loading during text-only serving. The inference path is unchanged when multimodal mode is enabled.

Replaced `get_server_args().enable_multimodal` with `get_mm().enable_multimodal`, the accessor mllama4 and inkling also moved to in #33013.

The vision/audio checkpoint name fragments are now a class attribute and moved the skip to `_should_skip_multimodal_weight()`, mirroring mllama4's `_should_skip_weight()`. Fragments cover every published Gemma 4 checkpoint: E2B / E4B carry vision + audio, 26B-A4B / 31B vision only, and the encoder-free 12B carries vision + audio under its own module names.

12B is the only size on the unified architecture, which overrides the tuple with its own names in `gemma4_unified.py`. End-to-end 12B serving is separately broken on a regression from #22498 as `lm_head_is_tied` is unset on the unified class. Fix is up as #35809.
