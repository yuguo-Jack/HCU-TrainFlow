# [Fix] qwen3_coder: Close streamed arguments when the model omits </function>

[Upstream PR](https://github.com/sgl-project/sglang/pull/46218) · state: open · merged: False

## Original PR description

## Motivation

Fixes #43150.

The streaming `Qwen3CoderDetector` closes a call's arguments object only on `</function>`. When the model ends the call with `</tool_call>` but omits `</function>`, the streamed `arguments` stop mid-object; when `</parameter>` is missing too, the parameter is never emitted. `detect_and_parse` returns `{"days": 0}` for both, so the same output succeeds or fails depending only on `stream`. Current main, character-by-character:

```
...<parameter=days>\n0\n</parameter>\n</tool_call>   streamed: '{"days": 0'
...<parameter=days>\n0\n</tool_call>                 streamed: ''
```

## Modifications

- At `</tool_call>`, if a function is still open, emit the closing `}` (and the opening `{` for a call without parameters).
- Override `finish()`, which runs once when the stream ends. No `</parameter>` can arrive any more, so a parameter that is still open ends at `</tool_call>`, which is how `detect_and_parse` reads it.
- `</tool_call>` ends a parameter only at stream end. This differs from the diff suggested in the issue and from the closed #43467, which make it an unconditional terminator. Mid-stream, `</tool_call>` can be literal text in a value that a later `</parameter>` closes, for example a coding agent writing parser code. Main streams that case correctly today; with the unconditional terminator it becomes invalid JSON plus leaked content:

  ```
  <parameter=content>\nprint("</tool_call>")\n</parameter>\n</function>\n</tool_call>
  main:                     {"content": "print(\"</tool_call>\")"}
  unconditional terminator: {"content": "print(\""}}   and content text ")\n</parameter>\n\n"
  ```

  A second test pins this down.

Related, not changed here:

- #45244 (open) makes a stray `</function>` after a closed call inert. It changes the `</function>` branch, this PR changes the `</tool_call>` branch and the parameter scan, so the two compose.
- The shape from the issue thread where the model omits both `</function>` and `</tool_call>` and opens the next call directly is not covered: `detect_and_parse` merges those two calls as well, so it needs a one-shot change too.

## Accuracy Tests

Parser-only change; no model-forward or kernel code is touched.

- `test_function_call_parser.py -k Qwen3Coder`: 19 passed.
- `test_streaming_closes_arguments_when_function_end_omitted` covers the two shapes from the issue and a call with no parameters; all three subcases fail on main and pass here. `test_streaming_keeps_tool_call_end_inside_parameter_value` passes on main and here, and fails when `</tool_call>` is made an unconditional terminator.
