## Original PR description

# [Diffusion][AMD] Add gfx1250 detection and stop silent CPU fallback for diffusion


## Motivation

#32754 enables gfx1250 for the SRT path. `multimodal_gen` has its own
platform-resolution and aiter-gating modules, so it needs the equivalent plumbing before
diffusion models can be brought up on gfx1250.

## Changes

**1. `srt/utils/common.py` — add `is_gfx1250_supported()`**

Alongside the existing `is_gfx95_supported()` / `is_gfx942_supported()`, same pattern and
`lru_cache`. Note #32754 introduces an identical helper; whichever lands second should drop
its copy. Kept here so this PR is self-contained if it lands first.

**2. `multimodal_gen/runtime/platforms/aiter.py` — expose `USE_AITER_GFX1250`**

So diffusion code can gate arch-specific aiter paths the way it already does for gfx942 and
gfx95x (`USE_AITER_GFX942`, `USE_AITER_GFX95`).

**3. `multimodal_gen/runtime/platforms/__init__.py` — don't silently fall back to CPU**

This is the substantive fix. `rocm_platform_plugin()` decided ROCm-vs-CPU solely on whether
`import amdsmi` and `amdsmi_get_processor_handles()` succeeded:

```python
    except Exception as e:
        logger.debug("ROCm platform is unavailable: %s", e)
```

`amdsmi` is an optional dependency and is absent from several ROCm container images. When it
is missing, the exception is swallowed into a `logger.debug` and platform resolution falls
through to `CpuPlatform`.

- ROCm: 7.2.4
- PyTorch: 2.9.1+rocm7.2.4
- `torch.cuda.is_available()`: `True`
- `torch.version.hip`: available

With the current main branch, automatic diffusion platform detection returns:

```text
sglang.multimodal_gen.runtime.platforms.cpu.CpuPlatform
```

When setting:

```
SGLANG_DIFFUSION_PLATFORM_OVERRIDE=rocm
```
it correctly returns:

```
sglang.multimodal_gen.runtime.platforms.rocm.RocmPlatform
```
Would it make sense to generalize this PR beyond gfx1250 to cover ROCm/HIP containers without amdsmi, including gfx1151?
