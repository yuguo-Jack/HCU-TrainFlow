# [Refactor] scheduler: Name the condition that blocks flush_cache / attach / detach

[Upstream PR](https://github.com/sgl-project/sglang/pull/36869) · state: open · merged: False

## Original PR description

## Motivation

`flush_cache`, `attach_hicache_storage` and `detach_hicache_storage` are all gated on `Scheduler.is_fully_idle()`, which checks about twenty conditions — six of them HiCache-specific (`ongoing_write_through`, `ongoing_load_back`, `ongoing_prefetch`, `ongoing_backup`, the buffer pipeline). All three rejection messages print only the waiting queue and the running batch, so the reader is sent to inspect queues that are not the blocker:

```
Cache not flushed because there are pending requests. #queue-req: 16, #running-req: 0
```

## Modifications

- Extract `Scheduler.not_idle_reasons()`, returning what is unsatisfied. `is_fully_idle()` becomes `not not_idle_reasons()` — same predicates, same order, no new logic. Countable reasons carry their count; the rest report by name.
- The three rejection messages and the deferred-flush timeout now report `blocked-by: ...`.
- `SchedulerFlushWrapper` takes `not_idle_reasons` instead of `is_fully_idle`, so it needs one injected callable instead of two.

## Tests

Mechanical refactor, so the guard is the existing suite: `test/registered/unit/managers/` plus `test_decode_queue_cleanup.py` give **595 passed**, matching the pre-change count exactly.

E2E on H200 (Qwen3-4B + hierarchical cache + file storage), all three endpoints under load:

```
Reject attach: scheduler is not idle. blocked-by: running_batch=4, last_batch=4, result_queue=1, waiting_queue=21
blocked-by: last_batch=4, result_queue=1, waiting_queue=17, hicache_write_through=1, hicache_backup=3
```

Idle behaviour is unchanged: flush/detach/attach succeed as before, with zero `blocked-by` lines when idle.
