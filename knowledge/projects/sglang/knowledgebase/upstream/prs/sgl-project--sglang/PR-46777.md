# [Fix] dsv4: Refuse the draft metadata glue when the backend needs host lengths

[Upstream PR](https://github.com/sgl-project/sglang/pull/46777) · state: closed · merged: True

## Original PR description

- `DeepseekV4AttnBackend.glue_draft_metadata` refuses the draft metadata glue graph when the backend needs host sequence lengths, as `glue_target_verify_metadata` already does. Under DSpark `needs_cpu_seq_lens` is always False today, so this guards future configurations.
- `init_forward_metadata_out_graph` drops its unused `seq_lens_sum`, including the `seq_lens.sum().item()` sync when capturing decode CUDA graphs.
- The host-read fix this PR first carried landed in #46891 and #46897.

No behavior change, except one fewer device-to-host sync while capturing decode CUDA graphs.
