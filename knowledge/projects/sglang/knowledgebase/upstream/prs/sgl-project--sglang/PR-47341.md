# [Fix] sampling: Validate n before parallel request expansion

[Upstream PR](https://github.com/sgl-project/sglang/pull/47341) · state: open · merged: False

## Original PR description

## Motivation

Native generation reads `sampling_params["n"]` before constructing `SamplingParams`. Explicit `null` therefore raises a `TypeError` during request normalization even though `SamplingParams` treats it as the default of 1. Zero, negative, boolean and non-integer values can also reach request expansion without a consistent validation error.

Related prior work: #28858 (closed by its author, not merged). This PR independently focuses only on sample-count normalization and validation; it does not change stop-string or regex handling.

## Modifications

- Share a small `normalize_sample_count` helper between `SamplingParams` construction and native request normalization.
- Treat omitted/null `n` as 1 and reject other values unless they are positive integers, before request expansion and beam-search fan-out handling.
- Cover single/batched inputs, dict/list sampling parameters, invalid counts, and valid beam requests without fan-out. Existing valid parallel-sampling tests remain unchanged.
