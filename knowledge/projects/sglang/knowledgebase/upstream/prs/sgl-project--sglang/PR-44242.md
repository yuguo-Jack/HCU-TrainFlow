# [Fix] Require admin API key for HiCache clear and remote weight export

[Upstream PR](https://github.com/sgl-project/sglang/pull/44242) · state: open · merged: False

## Original PR description

## Summary

HiCache storage clear and remote weight export endpoints were decorated with `AuthLevel.ADMIN_OPTIONAL`, but unlike HiCache attach/detach they did not reject requests when the server was started without `--admin-api-key`. With only `--api-key` set, a caller holding the user API key could clear hierarchical cache storage or drive remote weight transfer.

This change matches the existing `_backend_status()` / attach-detach pattern: if `admin_api_key` is unset, return the same missing-admin-key response; otherwise keep requiring an admin token via the decorator.

Also extends `ADMIN_PATHS` in `test_http_server_auth_levels.py` and asserts that a user API key is rejected on those paths.

## Changes

- `python/sglang/srt/entrypoints/http_server.py`: add admin-key-missing checks to
  - `/hicache/storage-backend/clear`
  - `/init_weights_send_group_for_remote_instance`
  - `/send_weights_to_remote_instance`
- `test/registered/unit/entrypoints/test_http_server_auth_levels.py`: cover the three paths + reject user token

## How to verify

1. Start server with `--api-key` only (no `--admin-api-key`); calling the three endpoints with the user key should get 400 (admin key required).
2. Start with both `--api-key` and `--admin-api-key`; user key rejected, admin key allowed.
3. `python -m pytest test/registered/unit/entrypoints/test_http_server_auth_levels.py -q`
