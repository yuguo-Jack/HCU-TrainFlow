# [diffusion] perf: layerwise offload for the LTX-2.5 Gemma-4 text encoder

[Upstream PR](https://github.com/sgl-project/sglang/pull/43683) · state: closed · merged: True

## Original PR description

## Motivation

LTX-2.5's text encoder is Gemma-4-Unified: 23.9 GB in bf16. Its 48 decoder layers are 21.8 GB and its vocab table is 2.0 GB. It has no SGLang port and loads through `transformers.AutoModel`, so it lacks `LayerwiseOffloadableModuleMixin`. As a result, `--layerwise-offload-components text_encoder` raises:

```
ComponentResidencyError: Components selected for layerwise-offload do not support it: ['text_encoder']
```

On a 32 GB card the only remaining placement is component offload. Every request moves the whole text encoder, the 6 GB connectors and the VAE onto the GPU and back: roughly 60 GB of PCIe traffic and a 31.2 GB peak.



## Modifications

Three commits:

1. **Layerwise-offload adapter for Gemma-4-Unified**, in the new file `runtime/models/encoders/gemma_4_unified.py`.
   - After the native load, the module's class is swapped for a subclass that also carries the mixin, with `layer_names=["language_model.layers"]`. Weights, forward, signature and class name are unchanged.
   - The 2.0 GB vocab table is declared host-resident (`host_resident_table_names`).
   - Gemma's embedding multiplies by a 0-dim `embed_scale` buffer, which follows the module to the device. A host-side gather cannot use it there, so the embedding forward moves the scale to the gather's device. The result is bit-exact.
   - Adapters are registered by transformers class name in `NATIVE_LAYERWISE_ADAPTERS`.
2. **Apply native layerwise adapters in `TextEncoderLoader.load_native`** (+21 lines). The loader looks up the adapter by class name, so only `Gemma4UnifiedModel` changes; every other encoder loads as before.
3. **Docs:** LTX-2.5 cookbook presets for 1x and 2x 32 GB GPUs.

New unit test `test_gemma4_unified_layerwise_offload.py` checks that outputs are identical after the class swap and with the host-resident embedding table.

## Accuracy Tests

- **Text encoder:** all 49 hidden states are identical (max-abs 0) between the resident and layerwise encoder, on a 1024-token prompt.
- **1 GPU, end to end** (960x544x121f, 8 steps, seed 42): the output mp4 is **byte-identical** to before.
- **2 GPUs:** the same placement with tiled decode is pixel-identical to before. With the untiled parallel decode used in the 2-GPU preset (`--vae-tiling false --vae-sp false`), it is 34.1 dB PSNR against the tiled output. That difference comes from tile blending; the frames look the same and show no seams.

## Speed Tests and Profiling

Setup: RTX 5090 32 GB (SM120, PCIe, no P2P), LTX-2.5 distilled one-stage T2V, 960x544x121f, 8 steps, conv VAE. Client wall-clock median of 3 runs after 1 warmup run.

| Config | Before | After |
|---|---:|---:|
| 1 GPU, `--dit-layerwise-offload true --layerwise-offload-components dit text_encoder` (connectors and VAEs resident) | 17.0 s (component offload), peak 31.2 GB | **15.2 s**, peak **17.1 GB** |
| 2 GPUs Ulysses2, same + `--vae-tiling false --vae-sp false` | 21.8 s | **18.2 s** |
| 2 GPUs, + `--dit-layerwise-resident-layers 12` | – | **17.1 s**, peak 25.9 GB |

1-GPU stage times:
- text encoding: 1.03 → 0.84 s
- connectors: 1.08 → 0.04 s, now resident
- a 0.2 s timestep-preparation stall is gone


## Notes

- **Host memory:** on 2 GPUs, each rank now pins about 55 GB of host memory (DiT 35 + TE 20), up from about 35 GB. Sharing one host copy across ranks is not part of this PR.
- **The LTX2 VAE overrides `decode()`**, so it does not take the generic parallel tiled decode. Its own height-split parallel decode needs tiling off; the 2-GPU preset documents the flags.
