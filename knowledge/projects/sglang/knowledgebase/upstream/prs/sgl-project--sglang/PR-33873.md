# [Perf] [AMD] kimi-k2.5: Fuse MLA value projection with MXFP4 output quantization

## Motivation

This PR complements #32935, which separately fuses the absorbed MLA key projection, RoPE, and KV-cache write. The two optimizations are independent; this branch is based directly on `main` and contains only the value-projection fusion.

During Kimi-K2.5 MXFP4 decode on ROCm gfx95, the absorbed value projection still runs as a batched A16W4 GEMM that materializes a BF16 tensor. `o_proj` immediately reads that tensor and quantizes it back to MXFP4. Folding the quantization into the GEMM epilogue avoids this intermediate HBM round trip and removes one launch from the decode path.

## Modifications

- Add `batched_gemm_a16wfp4_flatten_mxfp4_quant`, a Triton kernel that fuses the absorbed value-projection GEMM with flattened MXFP4 output quantization.
- Preserve the split path's BF16 rounding boundary so the fused output and scales match bit-for-bit.
- Route eligible AITER decode calls through the fused kernel when `w_vc` and `o_proj` use MXFP4.
- Add `SGLANG_ROCM_FUSE_MLA_VALUE_MXFP4_QUANT`, enabled by default.
- Probe shape, dtype, and AITER configuration support before dispatch; unsupported configurations fall back to the split GEMM plus `fused_flatten_mxfp4_quant`.
- Keep DSA, optimized LoRA execution, and active `kv_b_proj` LoRAs on the existing split path.
- Support eager execution, `torch.compile`, and HIP graph capture.
- Add AMD parity coverage, CPU gate coverage, a focused microbenchmark, and environment-variable documentation.
