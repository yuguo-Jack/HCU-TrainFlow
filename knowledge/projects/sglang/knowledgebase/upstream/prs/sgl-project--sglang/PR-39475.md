## Motivation

<!-- Describe the purpose and goals of this pull request. -->
Added model implementation for Cosmos Dreams and Cosmos Multiview.
For cosmos dreams action, a realtime session supported is also added. User could feed action as video generation goes, which could steer generation on the fly.

## Modifications

<!-- Detail the changes made in this pull request. -->
**Cosmos Dreams** model generates videos in causal fashion. The model checkpoint is 8B autoregressive, self-forcing DMD-distilled, e.g. nvidia/Cosmos3-Nano-Sim-Bimanual. Given image anchor with action/control, each chunk is denoised and generates 4 latent frames (This denoising process is the same as existing cosmos pipeline). Then generated frames will be committed to clean kv history, which will be used as history for the future chunks of attention calculation. (The pipeline is located at multimodal_gen/runtime/pipelines/cosmos_dreams_pipeline.py for action input and multimodal_gen/runtime/pipelines/cosmos_dreams_transfer_pipeline.py for control input)

As for realtime generation for action, the model logic is the same. The realtime session keeps track of clean KV for generated chunks. The pipeline can be found at multimodal_gen/runtime/pipelines/cosmos_dreams_realtime_pipeline.py


For **Cosmos Multiview**, one request produces all cameras (and optionally a LiDAR range-image stream) in a single denoising pass, with the checkpoint's visibility rules enforced by one block-sparse attention mask. The captions live in a separate UND sequence, one caption per camera.

Sequence looks like this:
GEN stream, camera-major per item (every frame of view 0, then view 1, ...):

 [ WSM control: cam0 f0..fT | cam1 f0..fT | ... | cam10 ]
 [ RGB target : cam0 f0..fT | cam1 f0..fT | ... | cam10 ]
 [ HD-map ctrl: sweep 0..S ]          (joint requests)
 [ LiDAR target: sweep 0..S ]         (joint requests)

UND stream (keys only): one caption per camera, packed back to back.

Each GEN token carries (sample, frame, view, control|sensor, timestamp); a learned
rig-view embedding (12 ids: 11 MADS cameras + LiDAR) is added per view block.

Attention mask:
1. A sensor query (RGB or LiDAR target) sees sensor keys of its own view at every frame, and sensor keys of every other view captured at the same instant or up to 0.4 s before it (past-only; this is what registers 10 Hz LiDAR sweeps against 7.5 Hz camera latents).
2. A sensor query sees control keys of its own view only.
3. A control query sees control keys of its own view, plus sensor keys of its own view (control_attends_sensor).
4. Every camera token sees its own camera's caption; LiDAR-view tokens (HD-map control and LiDAR target) see every caption.


The pipeline can be found at multimodal_gen/runtime/pipelines/cosmos3_multiview_pipeline.py. The attention implementation is located at python/sglang/multimodal_gen/runtime/models/dits/cosmos3_multiview_attention.py and  python/sglang/multimodal_gen/runtime/models/dits/cosmos3_multiview_fa4.py.
