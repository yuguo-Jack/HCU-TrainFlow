## Motivation

<!-- Describe the purpose and goals of this pull request. -->
The Cosmos3 Nano simulation family consists of four NVIDIA world models for robotics and
autonomous driving. They share the Cosmos3 Omni weights, Wan VAE and tokenizer with the
already-supported `Cosmos3Pipeline`, but each needs a rollout the single-pass bidirectional
pipeline cannot express:

- **Cosmos3-Nano-Sim-Bimanual**: image + prompt + per-frame robot or camera actions to video,
  generated causally in chunks by a distilled 4-step SDE student, with clean K/V committed as
  history. Long rollouts need a bounded history (deploy-time window and sinks, camera-frustum
  K/V retrieval) and realtime tick sessions driven by actions as they arrive.
- **Cosmos3-Nano-Sim-Transfer**: the same causal recipe conditioned on a control video
  (depth, segmentation, edge, blur) instead of actions, with the newer direct-resize
  preprocessing its latest checkpoint was trained on.
- **Cosmos3-Nano-Transfer-Auto** (already in main): the 11-camera driving rig, per-camera WSM
  control clips and captions, optional joint LiDAR, one bidirectional pass with masked
  cross-camera attention.
- **Cosmos3-Nano-Sim-Auto**: the causal, distilled version of Transfer-Auto, generating 0.4 s
  chunks against a two-slot KV ring with a fixed 4-step schedule, so that cost per chunk and
  history size stay constant over long clips.

This PR adds the three causal pipelines (Bimanual with its realtime variant, Transfer,
Sim-Auto) so the whole family is served through the same video API and request shapes,
with each rollout matching the imaginaire4 reference.

## Modifications

<!-- Detail the changes made in this pull request. -->

All model-specific; `Cosmos3Pipeline` and the multiview pipeline are untouched beyond small
shared hooks (video API LiDAR artifact download, realtime adapter registry, Hub-id component
file resolution, transformer class override in the loader).

**Sim-Bimanual** (`CosmosDreams*`, pipelines `Cosmos3NanoSimBimanualPipeline` and
`CosmosDreamsRealtimePipeline`)
- Artifact manifest for the `cosmos3_nano_sim_bimanual` contract (unified 59-D action schema,
  per-domain normalizer, chunk size, sampler schedule, K/V window) with strict validation.
- `CosmosDreamsTransformer`: GEN forward over `[text K/V | committed history K/V | current chunk]`
  with per-frame action tokens interleaved with vision patches; returns the chunk's K/V.
- Stages: canvas fitting of the conditioning image, action loading and normalization
  (sidecars, per-row domains), chunked rollout with the reference's seeded fixed-step SDE and
  per-frame clean commits, sliding-window history with pinned sinks, camera-frustum K/V
  retrieval (`frustum_geometry` request field), VAE decode overlapped with the rollout.
- Deploy-time `kv_cache_inference_size` / `attention_sink_size` in the pipeline config, in the
  training config's units.
- Realtime pipeline and adapter: one block of latent frames per tick from the actions received
  since the last tick, session state kept between ticks.

**Sim-Transfer** (`Cosmos3NanoSimTransferPipeline`)
- Control-video stage on the same causal rollout: direct-resize bucket selection over the five
  480p canvases with a 3 % distortion limit, per-modality interpolation, float32-first
  normalization, and `transfer_output_size` to restore the source size; legacy center-crop
  mode kept for older checkpoints. Registered under both Hub names (`Sim-Transfer`, `Sim-Depth`).

**Sim-Auto** (`Cosmos3NanoSimAutoPipeline`)
- Strict parser for the schema-1 `cosmos3_nano_sim_auto` artifact, from which the Multiview-AV
  stage contract is derived so the existing multiview input, tokenization, latent and decoding
  stages are reused unchanged.
- Host-side layout: chunk schedule, camera-major packed items, per-token metadata, caption
  documents, ring slots; replay visibility evaluated on metadata runs and projected onto a
  FlexAttention block mask over `[current chunk | KV ring | per-camera captions]`, following the
  maskless replay semantics the student trained with.
- `Cosmos3SimAutoTransformer` (one masked GQA attention per layer at absolute mRoPE positions,
  clean forwards without time embedding) and the rollout stage (four seeded SDE forwards per
  chunk, then one clean forward whose K/V is published to the ring).
- Request contract: the multiview shape plus fixed guidance, step count and shift; one anchor
  frame per camera; one measured LiDAR sweep.

Tests: `test_cosmos_dreams.py`, `test_cosmos_dreams_frustum.py`, `test_cosmos_dreams_realtime.py`,
`test_cosmos3_sim_auto.py`


For **Cosmos Multiview**, one request produces all cameras (and optionally a LiDAR range-image stream) in a single denoising pass, with the checkpoint's visibility rules enforced by one block-sparse attention mask. The captions live in a separate UND sequence, one caption per camera.

Sequence looks like this:
GEN stream, camera-major per item (every frame of view 0, then view 1, ...):

 [ WSM control: cam0 f0..fT | cam1 f0..fT | ... | cam10 ]
 [ RGB target : cam0 f0..fT | cam1 f0..fT | ... | cam10 ]
 [ HD-map ctrl: sweep 0..S ]          (joint requests)
 [ LiDAR target: sweep 0..S ]         (joint requests)

UND stream (keys only): one caption per camera, packed back to back.

Each GEN token carries (sample, frame, view, control|sensor, timestamp); a learned
rig-view embedding (12 ids: 11 MADS cameras + LiDAR) is added per view block.

Attention mask:
1. A sensor query (RGB or LiDAR target) sees sensor keys of its own view at every frame, and sensor keys of every other view captured at the same instant or up to 0.4 s before it (past-only; this is what registers 10 Hz LiDAR sweeps against 7.5 Hz camera latents).
2. A sensor query sees control keys of its own view only.
3. A control query sees control keys of its own view, plus sensor keys of its own view (control_attends_sensor).
4. Every camera token sees its own camera's caption; LiDAR-view tokens (HD-map control and LiDAR target) see every caption.


The pipeline can be found at multimodal_gen/runtime/pipelines/cosmos3_simulation.py. The attention implementation is located at python/sglang/multimodal_gen/runtime/models/dits/cosmos3_simulation/multiview_attention.py and  python/sglang/multimodal_gen/runtime/models/dits/cosmos3_simulation/multiview_fa4.py.
