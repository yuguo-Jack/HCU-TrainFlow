# [Refactor] engine: Make the follower-rank SIGTERM handler an overridable classmethod

[Upstream PR](https://github.com/sgl-project/sglang/pull/47158) · state: closed · merged: True

## Original PR description

## Motivation

In a multi-node engine, only node rank 0 owns the tokenizer manager and can drain in-flight requests and broadcast `ShutdownReq` to every scheduler. Non-zero node ranks therefore install a SIGTERM handler that only logs a warning and waits for that broadcast. Today that handler is a closure defined inline in `Engine._launch_subprocesses`, so an `Engine` subclass that wants a different follower behaviour on SIGTERM (for example, notifying rank 0 so it starts its normal drain instead of letting the orchestrator's kill timeout tear the whole engine down) has no way to change it without copying the entire `_launch_subprocesses` body.

## Modifications

- `python/sglang/srt/entrypoints/engine.py`: move the inline `sigterm_handler` closure to a classmethod, `Engine._handle_follower_sigterm(cls, signum, frame)`, and register `cls._handle_follower_sigterm` as the SIGTERM handler at the same point, under the same main-thread guard. The handler body is unchanged (same warning text), so the base `Engine` behaves exactly as before; only subclasses gain an override point.

No behaviour change, no new flags, no new dependencies.
