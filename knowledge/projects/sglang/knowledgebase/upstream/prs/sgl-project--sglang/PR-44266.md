# [Fix] [AMD] qwen3: Fix KV cache write in the fused QK-norm + mRoPE decode path

[Upstream PR](https://github.com/sgl-project/sglang/pull/44266) · state: closed · merged: True

## Original PR description

## Motivation

On ROCm with `SGLANG_USE_AITER=1` (the default in the ROCm images), dense Qwen3-VL decode goes through `Qwen3Attention.forward_prepare_aiter_fused_mrope`, which calls aiter's `fused_qk_norm_mrope_3d_cache_pts_quant_shuffle` to run QK-norm + 3D mRoPE + the KV cache write in one kernel. That path currently produces garbage:

| `Qwen3-VL-8B-Instruct`, default server args | `main` | This PR |
|---|---|---|
| GSM8K (1319 questions, chat API, greedy) | **0.005** | **0.942** |
| "What is the capital of France? Answer in one sentence." | `The capital of France's capital of France is Paris of France is Paris is Paris is …` | `The capital of France is Paris.` |
| Image with the text "MI355X 2026", a red circle and a blue square | `BasedThe text: The text: The text: The text: …` | `… The text written at the top of the image is: M1355X 2026 … Left Shape: A solid red circle. Right Shape: A solid blue square.` |

**Root cause.** Since ROCm/aiter#4531 (in the AITER pin since #37784), the kernel reads `k_cache` / `v_cache` strides as `(block, token, head, head_dim)`: dim 1 is the per-token stride and dim 2 the per-head stride. `Qwen3Attention` passes the NHD pool buffers `(slots, num_kv_heads, head_dim)`, whose dim-1 / dim-2 strides are `head_dim` / `1`, so the K/V of slot `s`, head `h` is written at element offset `s * head_dim + h` instead of `(s * num_kv_heads + h) * head_dim`. The decode token's own slot is not written by it, and other slots — including the prompt KV of running requests — are overwritten. Nothing faults and throughput is unchanged, so performance runs do not notice. Prefill uses the unfused path, which is why the first token is still sensible.

Affected: dense Qwen3-VL (`Qwen3VLForConditionalGeneration`) on ROCm with the default aiter attention backend. Qwen3-VL-MoE uses `Qwen3MoeAttention` and does not take this path; the AMD VLM accuracy test runs `Qwen3-VL-30B-A3B-Instruct`, which is why CI did not catch it.

The same path also cast `cos_sin_cache` to the activation dtype on every layer of every decode step. On HIP that cache is kept in fp32, and for Qwen3-VL-8B (`max_position_embeddings = 262144`) it is 128 MiB, so each step moved about 6.75 GiB (36 layers × 128 MiB read + 64 MiB write) just to recreate the same bf16 table.

## Modifications

- `aiter_fused_qk_norm_rope_set_kv` (new, `models/qwen3.py`) holds the kernel call and passes the NHD buffers as one-slot blocks, `k_cache.unsqueeze(1)` → `(slots, 1, num_kv_heads, head_dim)` with `block_size = 0`, which gives the kernel the token stride `num_kv_heads * head_dim` and the head stride `head_dim`.
- `Qwen3Attention.forward` takes the fused path only when the pool buffer is that 3D NHD layout in the activation dtype. The kernel's quantized write uses a fixed per-tensor scale of 1.0 rather than the layer's `k_scale` / `v_scale`, and the HND and `vectorized_5d` layouts are not NHD; those configurations use the unfused path.
- `RotaryEmbedding.cos_sin_cache_as(dtype)` returns `cos_sin_cache` in `dtype` and reuses the cast copy until `cos_sin_cache` is replaced (`_ensure_cos_sin_cache_length`, device moves). The first call happens in the eager warmup before CUDA graph capture, so the captured graphs contain no cast.
- `test/registered/amd/test_qwen3_aiter_fused_qk_norm_rope.py` calls the helper with NHD buffers and checks q and the K/V written at `out_cache_loc` against `RMSNorm.forward_native` + `MRotaryEmbedding.forward_native`, that no other slot is written, and the `cos_sin_cache_as` reuse/invalidation. With the 3D buffers passed as before, 98% of the written K elements mismatch; with this PR it passes.

## Accuracy Tests

MI355X (gfx950), ROCm 7.2.0, torch 2.9.1, Triton 3.7.0, transformers 5.19.0, `SGLANG_USE_AITER=1`, default server args (attention backend resolves to `aiter`, decode CUDA graphs on). The pinned AITER `e7d2453f` has the same stride handling in both fused kernels.

**Unit test.** `test/registered/amd/test_qwen3_aiter_fused_qk_norm_rope.py`: 2 passed, 8 subtests passed.

**`Qwen3-VL-8B-Instruct`, end to end:** see the table above. GSM8K via `python -m sglang.test.run_eval --eval-name gsm8k --num-examples 1319 --max-tokens 2048`; the text and image prompts are single chat requests at temperature 0.

Dense Qwen3 (plain RoPE) does not take this path and is unchanged.

## Speed Tests and Profiling

`Qwen3-VL-8B-Instruct`, `python -m sglang.bench_serving --backend sglang --dataset-name random-ids --random-input-len 1024 --random-output-len 512 --random-range-ratio 1.0`, `--num-prompts = max(16, 4 × concurrency)`, prefix cache flushed before each run, one benchmark at a time. Both servers generate the same number of tokens per request, so the comparison holds even though the `main` output is wrong.

| Concurrency | Median TPOT `main` (ms) | Median TPOT this PR (ms) | Delta | Output throughput |
|---|---|---|---|---|
| 1 | 5.960 | 4.818 | **−19.2%** | +14.5% |
| 8 | 6.782 | 5.462 | **−19.5%** | +22.5% |
| 32 | 8.797 | 7.490 | **−14.9%** | +15.9% |
| 64 | 12.359 | 11.190 | −9.5% | +9.2% |

The saving is a roughly constant 1.1–1.3 ms per step across concurrencies, the order expected for the ~6.75 GiB per-step `cos_sin_cache` cast that is no longer launched.

Hi, @jiaqiang-dot-liu 

Reassigning `use_aiter_fused` after the cache lookup makes the same flag mean two different things. It might read more clearly to use a cheap `can_try_aiter_fused` check to decide whether to fetch the cache, and set `use_aiter_fused` once from the layout and dtype.

Just for ref,
```py
can_try_aiter_fused = (
    self.use_fused_qk_norm_mrope
    and forward_batch.forward_mode.is_decode()
    and get_exec().deterministic.rl_on_policy_target is None
)
if can_try_aiter_fused:
    k_cache, v_cache = get_token_to_kv_pool().get_kv_buffer(self.attn.layer_id)
    # NHD in the activation dtype. This path passes scale 1 and does not
    # quantize, so a quantized or other-layout store stays on the normal write.
    use_aiter_fused = (
        k_cache.dim() == 3
        and k_cache.dtype == hidden_states.dtype
    )
```
