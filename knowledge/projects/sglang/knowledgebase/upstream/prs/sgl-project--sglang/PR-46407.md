# [Fix] environ: restore the env var when an override block raises

[Upstream PR](https://github.com/sgl-project/sglang/pull/46407) · state: open · merged: False

## Original PR description

## Motivation

`EnvField.override` does not restore the environment variable when the `with` body raises. It snapshots the previous presence, value and `_set_to_none` state, then restores them after the `yield`, so an exception propagating out of the block skips the restore entirely and the override leaks into the rest of the process.

That is the opposite of the documented contract. `.claude/skills/env-var-conventions/SKILL.md` tells callers to prefer `override` over touching `os.environ` precisely because it "restores the original cleanly, including the explicit-None state, even if the block raises", and lists it as the supported way to scope a value in tests and to seed a `subprocess.Popen`. The sibling context manager `ParallelContext.override` in `runtime_context.py` already restores in a `finally`.

Reproduction, CPU only, on `dba22e9b68`:

```python
import os
from sglang.srt.environ import envs

name = envs.SGLANG_IS_IN_CI.name
os.environ.pop(name, None)

try:
    with envs.SGLANG_IS_IN_CI.override(True):
        raise RuntimeError("boom")
except RuntimeError:
    pass

print(name in os.environ, envs.SGLANG_IS_IN_CI.get())
# main:     True True
# expected: False False
```

Two places this bites:

Tests. 82 files under `test/registered/unit/` alone scope an env var with `envs.*.override(...)`. When a test fails inside one of those blocks, the override survives into every later test in the same process, so one real failure turns into a run of unrelated ones and the root cause is no longer the first red test. `ExitStack` composition, which the conventions doc recommends for multiple overrides, inherits the same hole.

Runtime. `dflash_worker_v2.py:836` wraps a sampling-peak measurement in `with envs.SGLANG_ENABLE_GRAPH_POOL_BORROW.override(False):`, and line 843 reads `graph_pool_borrow_enabled()` immediately after. If the measurement raises, graph-pool borrowing stays disabled for the remaining lifetime of the process.

## Modifications

`python/sglang/srt/environ.py`: wrap the `yield` in `try`/`finally`. The restore block is unchanged and the clean-exit path behaves exactly as before.

`test/registered/unit/test_environ.py`: one case added to `TestEnvField`, beside the existing `test_override_restores_previous_state`, which only covered the clean exit. It walks the three prior states the restore branches on: key absent, key set to a value, and key explicitly set to `None`.
