# [sgl-router] Policy reorg 7/N: BucketResolver, ordered buckets and the pick loop

[Upstream PR](https://github.com/sgl-project/sglang/pull/40090) · state: closed · merged: False

## Original PR description

Stacked on the 6/N config PR. Last piece built beside the current path; the next PR wires it behind `--selection-engine reorg`.

## Modifications

- `policy_reorg/buckets.rs`: `BucketResolver::from_config` builds one policy instance per configured bucket (`policy` override or the model/decode default). `ordered_groups` emits the affinity group first when the model policy keeps affinity across buckets (cache-aware, sticky, session-aware in a global mode): the whole stage pool filtered by each engine's own `max_context_tokens` and `slo_first` TTFT rule, extend ranges not applied, mode `HitRequired`. Then the compatible size buckets by SLO preference (`slo_first` matching first, `best_effort` matching last), rank and id. No bucket config, or no decode buckets for decode, yields one implicit group.
- `pick` / `pick_from`: one ordered pass. `NoCandidates` advances; `NoAdmissibleEngine` / `AdmissionRejected` advance (and under `global-preserve` disable session lookup and binding in later groups); `InvalidSignal` and an out-of-set pick are errors. The winner's reason is recorded on the existing `policy_decision` metric.
- `SessionAwarePolicy` in `HitRequired` mode reports a binding whose engine is not a candidate as `AdmissionRejected(NotACandidate)` so the resolver can tell it from a miss.
- Ordering predicates are copies of `policies/buckets.rs`; the old file is deleted with the legacy path.
