# [Perf] [NVIDIA] dflash: Use FA4 on SM100 and SM110

[Upstream PR](https://github.com/sgl-project/sglang/pull/43694) · state: open · merged: False

## Original PR description

## Motivation

DFLASH falls back to FlashInfer when the target attention backend is unsupported by the draft, including DSA targets. FA4 is faster for this draft path on B200.

## Modifications

Use FA4 as the fallback on SM100 and SM110. Other CUDA GPUs keep FlashInfer; ROCm and XPU keep Triton. An explicitly selected draft backend still takes precedence.

## Accuracy Tests

CPU backend-selection regressions and scoped formatting pass on the updated branch. The fallback regression failed before the fix.

The draft attention kernel changes. Earlier B200 backport runs had similar accepted tokens per verify step with either backend, but do not establish numerical equivalence. This branch has not been run end to end on SM100; SM110 execution remains unverified.

Run the unit suites with `python -m pytest` and scoped formatting with `pre-commit run --files <changed-files>`.

## Speed Tests and Profiling

These measurements came from a v0.5.20 backport with GLM-5.3-Flash FP8, TP8 B200, an 8-layer DFLASH drafter, cached 60K-token prompts and EAGLE decoding. Time per verify step:

| Draft attention backend | 1 request | 4 requests | 16 requests |
| --- | ---: | ---: | ---: |
| FlashInfer | 9.05 ms | 11.32 ms | 16.03 ms |
| FA4 | 7.14 ms | 9.45 ms | 14.20 ms |

The speed results have not been repeated on this branch.
