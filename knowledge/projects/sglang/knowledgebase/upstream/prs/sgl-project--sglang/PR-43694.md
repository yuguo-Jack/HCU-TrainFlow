# [Perf] [NVIDIA] dflash: Use FA4 on SM100 and SM110

[Upstream PR](https://github.com/sgl-project/sglang/pull/43694) · state: closed · merged: False

## Original PR description

## Motivation

DFLASH falls back to FlashInfer for targets outside the draft choices (such as `trtllm_mla`, `dsa`) and on SM110. FA4 is faster for GQA drafts on B200. The SM100 `trtllm_mha` fallback already uses FA4 and does not change.

## Modifications

On SM100 and SM110, the fallback returns FA4 for GQA drafts. MLA drafts keep FlashInfer, because FA4 fails at warmup unless `kv_lora_rank` is 512. Other GPUs, ROCm, XPU and explicit backends do not change.

- Fallback on SM100 and SM110 reads the draft config, and all resolver reads honor `--decrypted-draft-config-file`.
- FP8 targets whose draft moves to FA4 get a BF16 pool, even with explicit draft `fp8_e4m3`.
- Llama-3.1-8B does not move on B200, but pinned drafts on its FP8 FlashInfer target (page 64) give 1,015,680 target tokens on FlashInfer and 894,784 on FA4.
- The Kimi-K3 recipe now resolves to an unmeasured FA4 draft. With FP8, a reduced 6-layer dummy config at TP4 drops from 1,696,064 to 981,952 tokens (not representative).

Deliberate limits:

- A `head_dim` 256 GQA draft fails at warmup on FA4, where main uses FlashInfer. No public draft I checked uses 256.

These limits are deliberate. Do not add code for them without a real input that reaches the case.

## Accuracy Tests

Server runs used this head on B200.

Llama-3.1-8B on a FlashInfer target ran sgl-eval gsm8k (page 64, 200 examples, temperature 0, max tokens 1024, seed 0). FA4 drafts scored 81.50% and 82.00%, FlashInfer drafts 81.50%, 82.50% and 83.00%.

DFLASH unit tests on CPU and B200 fail only where main fails.

Not validated: SM90, SM110, B300, GB300, real Kimi-K3 or MLA drafts, Kimi-K3 with DCP, GLM-5.3-Flash serving on this head.

## Speed Tests and Profiling

GLM-5.3-Flash FP8 at TP4 with cached 60K-token prompts ran on nightly `7224fce1` with this fallback, not this head.
