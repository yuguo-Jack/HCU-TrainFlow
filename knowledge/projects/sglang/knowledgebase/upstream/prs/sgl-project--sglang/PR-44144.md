# [DSV4.1] Derive the late-layer DP geometry from the captured shape under the breakable prefill graph

[Upstream PR](https://github.com/sgl-project/sglang/pull/44144) · state: closed · merged: True

## Original PR description

## Changes

Follow-up to #43812 and #43736. Together they admit decoder SWA bounded replay with DP attention under the breakable prefill CUDA graph, but the DP-geometry swap from #43812 skipped itself while the stream was capturing and graph replays never re-run the late-layer loop, so inside the graph the late-layer MoE gather kept the full-shape counts while the hidden states were the tail block (only consistent when the shape fits within `max_running_requests x 128`).

- `late_layer_dp_counts` takes `in_graph`: prefill graphs pad every DP rank to one shape, so the tail block is rank-uniform and the counts come from the captured shape with no collective. The capture bakes the geometry in; replays inherit it.
- `enter_late_layer_dp` uses device ops only (`full_like` for the count tensor, `clamp` on the runner's static non-padded scalar) so it is capture-safe and rebounds per replay.
- The model loop decides `tail_in_graph` before computing the counts.

## Accuracy

DeepSeek-V4.1-Flash on 2xGB300, TP2/DP2/EP2, MegaMoE, DSpark, breakable prefill graph, bounded replay on, evaluated with the GB300 CI test's evaluators (`max_running_requests` 32 per rank, so the in-graph tail block of 4096 rows is smaller than the captured 4096-8192 shapes).

| Eval | Score | CI threshold |
|---|---:|---:|
| GSM8K (zero-shot chat, 200) | 0.980 | 0.95 |
| MMLU (500) | 0.926 | 0.90 |

DSpark accept length 3.4-4.3. A 10-shot completion GSM8K smoke check on the same box gave 0.925 with the graph vs 0.910 eager, both with replay and DP2.
