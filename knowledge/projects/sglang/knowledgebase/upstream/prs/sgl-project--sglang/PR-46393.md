# [Fix] [Intel] diffusion/wan: Guard the CuTe DSL q/k norm RoPE imports on XPU

[Upstream PR](https://github.com/sgl-project/sglang/pull/46393) · state: closed · merged: True

## Original PR description

## Motivation

#46228 added `can_use_fused_rmsnorm_interleaved_rope` / `fused_rmsnorm_interleaved_rope_` to the module-level imports of `wanvideo.py`. The lazy `__getattr__` in `sglang.kernels.ops.diffusion` resolves them from `rope/rmsnorm_interleaved_rope_cutedsl.py`, which imports `cutlass` / `cuda.bindings` / `flashinfer` unconditionally. On XPU, which has no CuTe DSL, importing `wanvideo.py` now fails:

```
ModuleNotFoundError: No module named 'cutlass'
ValueError: Model architectures ['WanTransformer3DModel'] failed to be inspected.
Error while loading customized transformer, falling back to native version
```

Wan then runs on the native fallback transformer, and the XPU multimodal job fails its perf check on `wan2_1_t2v_1.3b` (E2E 122149 ms vs 76292 ms baseline, 106809 ms limit) on all 7 attempts, e.g. https://github.com/sgl-project/sglang/actions/runs/40161807926.

## Modifications

On XPU, skip the import of the two fused-kernel symbols in `wanvideo.py` and fall back to `can_use_fused_rmsnorm_interleaved_rope = lambda ...: False`. `_qkv_rope` then takes the existing unfused q/k RMSNorm path (the pre-#46228 behaviour).

The guard is caller-side because the kernel module applies `@cute.jit` / `@cute.kernel` at import time, so guarding only its imports would not be enough.

- CUDA: unchanged.
- XPU: Wan loads the sglang transformer again, unfused norm path.
- Other platforms (ROCm, etc.): unchanged, left to their owners.

#46247 then added two more symbols from the same CuTe DSL module (`fused_rmsnorm_interleaved_rope_into_blocks`, `rmsnorm_interleaved_rope_block_cols`); they are moved into the same XPU guard. Their only call site is behind `_fuses_qk_norm_rope`, which is False on XPU.

#46247 also added `torch.cuda.is_current_stream_capturing()` to the guard in `WanTransformer3DModel._text_kvs`. On XPU torch it raises on every denoising step:

```
RuntimeError: Tried to instantiate dummy base class _cuda_isCurrentStreamCapturing
```

It now uses `is_device_stream_capturing(context.device)` from `sglang.srt.utils`, which checks the device actually in use.
