# [Perf] [AMD] GLM5.3: Add opt-in PTPC FP8 KDA projections on gfx950

[Upstream PR](https://github.com/sgl-project/sglang/pull/38764) · state: open · merged: False

## Original PR description

## Motivation

GLM-5.3-Flash keeps its KDA qkv, low-rank f/g, beta, and output projections in BF16. The PTPC path repacks selected weights to per-channel FP8 and quantizes activations per token, but `o_proj` previously required a separate BF16 gated RMSNorm output followed by a standalone quantization kernel.

This change adds an opt-in no-copy packed PTPC prefill path while preserving the upstream fused BF16 projection modules for decode. Prefill uses one FP8 `[qkv | f_a | g_a]` GEMM plus BF16 beta and passes qkv/beta/fg directly to their consumers without reconstructing the fused output; decode remains one fused GEMM.

## Modifications

- Preserve the default-off `SGLANG_OPT_GLM53_KDA_PTPC_MODULES` selector and reject it unless AITER is active on gfx950.
- Move GLM-specific repacking and FP8/BF16 dispatch into dedicated subclasses; leave `UnquantizedLinearMethod` tensor-in/tensor-out for every other model and backend.
- Preserve upstream `fused_qkvbfg_a_proj` and `fused_bfg_a_proj` construction instead of unfusing projections when PTPC is selected.
- Repack `[qkv | f_a | g_a]` into one FP8 weight, quantize `hidden_states` once, and return qkv/beta/fg views directly without a full-width output concatenation.
- Keep fused BF16 decode and fallback. Enable no-copy packed PTPC only for measured prefill windows: TP4 `M=4096-16384`, TP8 `M=8192-16384`.
- Reject unsupported fused qkv layouts with a named `ValueError` instead of a bare lookup failure.
- Add a gfx950 Triton bridge that performs independent 128-wide RMSNorm, applies the sigmoid gate, and emits FP8 directly for PTPC `o_proj`.
- Register the gfx950 kernel suites on the MI35X runner.

Enable with:

```bash
SGLANG_OPT_GLM53_KDA_PTPC_MODULES=qkv_proj,f_a_proj,g_a_proj,o_proj
```
