# [chat] pass mm_token_type_ids to generate for mrope models

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10927) · state: open · merged: False

## Original PR description

# What does this PR do?

Fixes wrong image/video positions in the HF chat engine (`llamafactory-cli chat`, `api`, web UI chat) for M-RoPE models on transformers >= 5.3.0. There's no separate issue for it; the repro is below.

Since transformers 5.3.0, Qwen2-VL, Qwen2.5-VL, Qwen3-VL, Qwen3.5, GLM-4V (and a few others) only compute 3D M-RoPE positions in `generate()` when `mm_token_type_ids` is passed. Otherwise `_prepare_position_ids_for_generation` quietly falls back to 1D text positions. `HuggingfaceEngine._process_args` never passes it (`Qwen2VLPlugin` / `Qwen3VLPlugin.get_mm_inputs` don't emit it), so every image patch is positioned as if it were the next word. Nothing raises; answers just degrade.

The training collator already builds these ids (`collator.py:178`). This PR does the same in `_process_args`, only when:
- the plugin didn't already supply `mm_token_type_ids` (Gemma4 / GLM-5-Next keep theirs),
- the inputs contain `image_grid_thw` or `video_grid_thw`, and
- the model's `forward` accepts `mm_token_type_ids` (so transformers < 5.3 and omni models are unchanged).

This is separate from #10907 (prediction collator with `model=None`) and #10818 (KTO), which fix other paths.

## Repro (CPU, tiny random Qwen3-VL, transformers 5.8.0)

Positions of the first image tokens at prefill:

```
expected (M-RoPE)  t=[4, 4, 4, 4, 4, 4]  h=[4, 4, 4, 4, 4, 4]  w=[4, 5, 6, 7, 8, 9]
before this PR     t=[4, 5, 6, 7, 8, 9]  h=[4, 5, 6, 7, 8, 9]  w=[4, 5, 6, 7, 8, 9]
after this PR      t=[4, 4, 4, 4, 4, 4]  h=[4, 4, 4, 4, 4, 4]  w=[4, 5, 6, 7, 8, 9]
```

## Tests

New `tests/e2e/test_hf_engine_mrope.py` runs `_process_args` + `generate()` on a tiny random Qwen3-VL (processor from `Qwen/Qwen3-VL-30B-A3B-Instruct`, as in `test_mm_plugin.py`) and checks the prefill positions equal `get_rope_index`. It fails on `main` and passes with this change.

```
WANDB_DISABLED=true pytest -q --import-mode=importlib tests/e2e/test_hf_engine_mrope.py tests/e2e/test_chat.py tests/data/test_mm_plugin.py -k "mrope or chat or qwen"
7 passed
```

Ruff 0.15.5 check/format and `check_license.py` pass. Run on macOS (CPU), Python 3.12, torch 2.15, transformers 5.8.0. Not tested: GPU, real pretrained weights, other M-RoPE families beyond Qwen3-VL.
