# [train] Fix hinge and IPO objectives with TRL 0.20+

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10889) · state: open · merged: False

## Original PR description

With the supported TRL 0.20–0.24 releases, `pref_loss: hinge` and `pref_loss: ipo` silently compute sigmoid loss: `dpo_loss` now selects the objective from a `loss_type` argument, while LlamaFactory only sets the instance attribute. Forward the configured loss on the new interface and retain the existing call for TRL 0.18–0.19.

The regression initializes `CustomDPOTrainer` with local tiny GPT-2 policy/reference models, then checks `compute_loss` and every parameter gradient against independent token-log-probability formulas for sigmoid, hinge and IPO. It includes unequal response lengths and needs no model or dataset download. This was found through source review and reproduced on CPU, not observed in a production training run.

Validation (Python 3.13, PyTorch 2.9.1, Transformers 4.57.6):
- TRL 0.18.0 and 0.19.1: all 3 regression cases pass with the patch; old-interface behavior is retained.
- TRL 0.20.0 and 0.24.0: unchanged upstream fails hinge/IPO and passes sigmoid; the patch passes all 3 cases.
- Command: `python -m pytest tests/train/test_dpo_trainer.py -q --import-mode=importlib`.
- Repository-pinned pre-commit hooks (including Ruff 0.15.5), changed-file license checks, and `git diff --check` passed.

The existing `kto_pair` choice is not implemented by these supported TRL releases. Explicit forwarding restores TRL's unsupported-loss error on newer versions, consistent with 0.18–0.19, instead of silently running sigmoid. No new objective is implemented.

The validation covers actual Trainer initialization and loss forward/backward calls. Full training loops, GPU/distributed runs, and the full repository suite were not run. AI assistance was used for investigation, implementation, tests, independent review and this description.
