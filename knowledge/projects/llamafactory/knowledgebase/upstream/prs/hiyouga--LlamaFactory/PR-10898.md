## Original PR description

# What does this PR do?

Fixes #10897.

`OpenAIDatasetConverter` raises `KeyError: 'content'` when aligning a raw `IterableDataset` whose assistant message has nonempty `tool_calls` and omits `content`. [OpenAI's assistant-message schema](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) permits that shape.

Process the existing tool-call branch before looking up content. Other messages retain their content-field requirement. Tests exercise the real streaming `align_dataset` path, all four content states (missing, null, empty and text), and missing-content errors for ordinary messages.

The affected path is raw streaming message alignment. Standard Hugging Face JSON loading fills missing nested content with `None` and already works.

Related #10455 handles `tool_calls: null`; this fixes the separate case where nonempty `tool_calls` are present and the content key is omitted.

Validation on CPU, Python 3.11.0, datasets 4.0.0:

- `pytest -q tests/data/test_converter.py`: original converter 1 failed / 9 passed; patched converter 10 passed. The patched suite also passed with `--import-mode=importlib`.
- Ruff 0.15.5 lint, format (312 files), license checks and `git diff --check` passed.
- Changed-file pre-commit passed. All 11 hooks passed in a temporary worktree after normalizing the Windows `CLAUDE.md` symlink placeholder; that placeholder change is excluded from the PR.

Tests used `WANDB_DISABLED=true`, `CUDA_VISIBLE_DEVICES=-1` and `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`. The full model-dependent suite and training were not run.
