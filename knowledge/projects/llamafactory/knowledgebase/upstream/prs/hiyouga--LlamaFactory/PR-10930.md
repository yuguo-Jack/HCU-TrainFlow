# [data] preserve literal placeholders in formatter content

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10930) · state: open · merged: False

## Original PR description

# What does this PR do?

Fixes #10929.

User text such as `Use {{idx}} literally` is currently changed to `Use 0 literally` during template encoding because `StringFormatter.apply` searches each previous replacement result. Inserted text can also consume a placeholder intended for the template itself.

Collect each provided key's first occurrence from the original slot, then replace those ranges from right to left. This preserves literal content, the existing first-occurrence rule, unknown placeholders, type validation and special-token slots.

### Validation

- Added seven focused regression/control cases: the original implementation fails two and passes five; the fix passes the complete formatter module (57 tests).
- A real offline `PreTrainedTokenizerFast` with the registered `empty` template confirms two training turns preserve `{{idx}}` after the fix.
- Changed-file Ruff lint/format, applicable pre-commit hooks, actual commit hooks and full license check pass.
- Whole-repository quality checks encounter existing EOF/format issues in `CLAUDE.md`, `template.py`, `tool_utils.py`, `patcher.py` and `supa_rms_norm.py`; their unrelated autofixes are excluded. The affected paths were clean before the checks.
- An offline CPU attempt of the full suite with `--maxfail=1` stops at `test_feedback_data` because `llamafactory/tiny-random-Llama-3` is not cached. The focused formatter module and public encoding checks above pass.
- Model training and GPU tests were not run; the complete repository suite did not pass locally.

AI assistance was used for investigation, implementation and test review.
