# feat: adopt HyperParallel unified model setup

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10877) · state: open · merged: False

## Original PR description

# What does this PR do?

This PR updates the optional HyperParallel backend to HyperParallel's unified model-construction path while preserving LlamaFactory's Trainer, dataset pipeline, and Accelerate launch entry.

When `use_hyper_parallel: true`, LlamaFactory now:

1. builds the Transformers model on `meta`;
2. applies the LlamaFactory model patches and model-specific CP/EP plan;
3. lets HyperParallel construct FSDP2/CP/EP layouts;
4. loads pretrained weights directly into the sharded model;
5. continues training with `HyperParallelTrainer`, using AdamW by default or Hyper Muon when requested.

The Torch-native loading and training paths are unchanged.

## Supported scope

| Item | Support |
| --- | --- |
| Training stage | PT and SFT |
| Fine-tuning type | Full fine-tuning |
| FSDP2 | Yes |
| Context Parallel | Qwen3-MoE and Qwen3-VL-MoE dedicated plans |
| Expert Parallel | Qwen3-MoE and Qwen3-VL-MoE dedicated plans |
| Optimizer | Existing AdamW path; optional Hyper Muon |
| Quantized model loading | Not supported by the Hyper meta-init path yet |

The model-specific registrations are kept in LlamaFactory. Users do not need to write or edit a HyperParallel parallel-plan JSON for Qwen3-MoE or Qwen3-VL-MoE.

## How to use it

Install a HyperParallel build containing [mindspore-ai/hyper-parallel#1045](https://github.com/mindspore-ai/hyper-parallel/pull/1045), then add the required options to an existing LlamaFactory PT/SFT full-fine-tuning YAML.

### Hyper FSDP2

```yaml
use_hyper_parallel: true
```

### Add Context Parallel

```yaml
use_hyper_parallel: true
hyper_parallel_cp_size: 2
```

### Add Expert Parallel

```yaml
use_hyper_parallel: true
hyper_parallel_ep_size: 8
```

### Use Hyper Muon

```yaml
use_hyper_parallel: true
use_muon: true
```

Launch training through the existing Accelerate entry. No new launcher is introduced:

```bash
accelerate launch \
  --config_file examples/accelerate/fsdp2_config.yaml \
  src/train.py path/to/train.yaml
```

`hyper_parallel_args` remains available for advanced HyperParallel settings supplied through a JSON file. Direct LlamaFactory fields override the corresponding values from that file.

### Performance

Each result is the mean of three 100-step runs after excluding the first 10 warm-up steps. Relative changes compare the same AdamW configuration against Torch FSDP2; Muon is reported independently because it is a different optimizer.

| Model | Method | Mean step | Step-time change | Samples/s | Throughput change | Peak HBM / rank |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| `Qwen/Qwen3-30B-A3B` | Torch FSDP2 + AdamW | 3.3412 ± 0.0210 s | baseline | 19.1556 ± 0.1201 | baseline | 43,856 MiB |
| `Qwen/Qwen3-30B-A3B` | Hyper FSDP2 + AdamW | 2.6174 ± 0.0062 s | **-21.7%** | 24.4518 ± 0.0577 | **+27.6%** | 48,462 MiB |
| `Qwen/Qwen3-30B-A3B` | Hyper FSDP2 + Hyper Muon | 2.6493 ± 0.0047 s | — | 24.1571 ± 0.0429 | — | 47,975 MiB |
| `Qwen/Qwen3-VL-30B-A3B-Instruct` | Torch FSDP2 + AdamW | 3.6004 ± 0.0578 s | baseline | 8.8901 ± 0.1423 | baseline | 43,245 MiB |
| `Qwen/Qwen3-VL-30B-A3B-Instruct` | Hyper FSDP2 + AdamW | 2.8500 ± 0.0043 s | **-20.8%** | 11.2282 ± 0.0170 | **+26.3%** | 48,512 MiB |

For the 32K packed-sequence capacity test, Hyper FSDP2 ran out of memory during backward, while Hyper FSDP2 + CP2 completed 100 steps at 3.1902 s/step, 164,345 effective tokens/s, and 52,400 MiB peak HBM per rank.

The complete experiment configuration and results are available in the [experiment report](https://gist.github.com/Cui-yshoho/c06ff30fa2ea5f52f699ae40ff427cce).
