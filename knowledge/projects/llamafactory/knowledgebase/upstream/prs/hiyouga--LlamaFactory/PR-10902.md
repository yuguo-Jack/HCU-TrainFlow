# [model] fix numeric automatic target matching

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10902) · state: open · merged: False

## Original PR description

# What does this PR do?

While looking into #9664, I found that automatic target discovery can shorten a numeric linear leaf such as `visual.merger.mlp.0` to `0`. The VLM filter then treats it as a substring and can select containers that PEFT cannot wrap.

This change keeps the full path for numeric leaves and uses exact matching for those automatically discovered paths. Explicit targets and ordinary suffix matching keep their existing behavior. It also carries the paths through Llama-Pro and automatic GaLore/APOLLO target selection.

The targeted tests passed locally (40 passed, 1 skipped), along with the changed-file pre-commit checks. I also checked adapter save/reload, merge/export, and a second LoRA pass using real PEFT, then ran the same lifecycle and a multimodal backward step with Qwen2.5-VL-3B on a 16 GB GPU.

The numeric-path failure is reproduced by a small VLM test topology. The current Qwen model under Transformers 5.8 has no numeric linear leaves, so that run checks compatibility rather than reproducing the reporter's original setup. The full `make test` suite was not completed locally because of missing fixtures and a CPU loss test that did not finish.

Refs #9664. I'd appreciate feedback on whether this preserves the intended target-matching behavior.
