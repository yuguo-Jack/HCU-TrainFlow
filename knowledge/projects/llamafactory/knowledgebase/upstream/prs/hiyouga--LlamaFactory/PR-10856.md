# [docs] add Windows install steps for AMD GPUs with ROCm

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10856) · state: open · merged: False

## Original PR description

# What does this PR do?

The Windows section of the README only covers NVIDIA. LlamaFactory itself needs no changes to run on AMD GPUs under Windows: the ROCm build of PyTorch exposes the same `torch.cuda` API, and `bitsandbytes` has shipped Windows ROCm builds in its official releases since `0.50.2`. What was missing is how to install it.

This adds ROCm steps for AMD users to the Install PyTorch part of the Windows guide in `README.md` and `README_zh.md`. PyTorch comes from AMD's TheRock index using the documented `[device-gfxNNNN]` extras, which pull in the per-GPU kernel packages. Installing plain `torch` from that index gives a build that detects the GPU but fails at runtime with `hipErrorInvalidImage`. It also notes which GPUs need `TORCH_ROCM_AOTRITON_ENABLE_EXPERIMENTAL=1` for the AOTriton flash and memory-efficient SDPA backends, since without it they fall back to the math backend, and that `bitsandbytes` covers AMD on Windows too.

Tested on Windows 11 with an RX 9060 XT (`gfx1200`), `torch 2.13.0+rocm10.0.0` and `bitsandbytes 0.50.2`: `llamafactory-cli env`, LoRA SFT and 4-bit QLoRA SFT on `Qwen2.5-0.5B-Instruct`, and inference through `ChatModel` with the trained adapter. A 30-step LoRA run took about 29 s.
