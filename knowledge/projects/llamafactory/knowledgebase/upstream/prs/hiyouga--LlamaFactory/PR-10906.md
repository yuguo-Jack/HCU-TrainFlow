## Original PR description

## Security fix: SSRF: check_ssrf_url bypass via HTTP redirect and DNS rebinding on the multimodal media fetch

**Severity**: HIGH (CVSS 8.7)
**CWE**: CWE-918
**File**: `src/llamafactory/api/common.py`

### What this fixes

The image/video/audio URL guard validates only the initial URL, but the subsequent requests.get follows 3xx redirects and re-resolves DNS without re-validation, so an attacker URL on a public host reaches cloud-metadata or loopback services.

Preconditions: API reachable and API_KEY unset (verify_api_key is a no-op when the env var is empty). Attacker controls a public host that can return a 302 or authoritative DNS with a short TTL.

### The change

Changed check_ssrf_url to iterate over every address returned by socket.getaddrinfo and validate each one with ipaddress.ip_address(...).is_global, instead of only checking the first resolved address. This prevents DNS rebinding / round-robin attacks where getaddrinfo returns a mix of public and private/loopback addresses and the original code only inspected index [0]. The redirect-following fix belongs in api/chat.py (allow_redirects=False + re-validation of each Location), which is out of scop

### Impact if unpatched

An unauthenticated caller can make the model server issue requests to cloud metadata, loopback or internal HTTP services, exposing IAM credentials or internal endpoints.
