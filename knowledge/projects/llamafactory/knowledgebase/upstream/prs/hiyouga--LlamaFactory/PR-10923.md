# feat(webui): support private Hub export repositories

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10923) · state: open · merged: False

## Original PR description

# What does this PR do?

Add a "Create private repository" checkbox to the WebUI export tab and the `export_hub_private` export argument. When enabled, model, tokenizer, and processor uploads all request a private Hugging Face repository. The default passes `private=None`, preserving the Hub's existing default visibility behavior. This option controls repository creation; existing repositories retain their visibility.

Fixes #5345.

Related: the closed, unmerged #8842 proposed the CLI argument. This change includes the WebUI wiring, all five UI locales, and export regression tests.

Validation on Windows CPU, Python 3.12.13:

- New export and WebUI tests: 14 passed with Transformers 5.8.0 and 14 passed with 4.57.6. The unchanged implementation gives 10 failed / 4 passed. Coverage includes omitted/false/true settings, model/tokenizer/processor uploads, local-only export, and real tiny-model/tokenizer serialization and reload. Hub calls are mocked.
- Actual Gradio event processing forwards both checkbox values; locale updates work for all five languages.
- Offline integration with actual LlamaFactory model/tokenizer loaders, export, and reload passes for both values on Transformers 4 and 5. Upload methods are intercepted; no live Hub repository was created.
- Full `pytest --import-mode=importlib tests/ tests_v1/ -q`: 356 passed, 24 skipped, 4 xfailed, 3 xpassed, 1 failed. The failure is `test_fsdp2_save_pretrained_uses_original_model_class` because this Windows Torch 2.7.1 CPU build lacks `torch.distributed.HashStore`; the same failure reproduces on unchanged `9997aa07`.
- All applicable pre-commit hooks, license check, changed-file Ruff lint/format, and wheel build pass. Whole-repository Ruff also reports existing whitespace/formatting problems in untouched files.
