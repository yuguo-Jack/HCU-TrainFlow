# [data] fix: use continuous position ids for plain SFT packing

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10920) · state: open · merged: False

## Original PR description

# What does this PR do?

With `packing: true` and `neat_packing: false`, `supervised.py` restarts each packed example's `position_ids` at `0` (since `c3c0efba`), while the attention mask still covers the whole pack. On SDPA/eager, and on FA2 with more than one pack per batch, later examples attend to earlier ones while their positions reset to `0`. This causes the high SFT packing loss in #8277.

`Qwen/Qwen2.5-0.5B-Instruct` (`flash_attn: auto`, 120 GSM8K examples in 13 packs of 2,048 tokens, 12,877 label tokens after the first example per pack):

| setting | position restarts | later examples' mean NLL |
|---|---|---|
| alone / `neat_packing: true` | 0 | 0.694 |
| unpatched `main` (`packing: true`) | 107 | 3.480 |
| this PR (`packing: true`) | 0 | 0.430 |

With consistent positions, earlier GSM8K examples in the pack act as in-context examples.

This PR emits `0..L-1` over the pack when `neat_packing` is false (`neat_packing: true` is unchanged) and adds `test_supervised_packing_position_ids`.

Notes:
- On FA2 with `per_device_train_batch_size: 1`, `transformers` inferred varlen boundaries from the reset positions; plain packing now attends across the pack on all backends as documented (use `neat_packing: true` for isolated packing).
- Existing `datasets` caches are not invalidated automatically; re-run with `overwrite_cache: true`.

Fixes #8277
