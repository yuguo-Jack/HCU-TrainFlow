# fix: make unsloth gradient checkpointing and device fallback device-agnostic

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10828) · state: open · merged: False

## Original PR description

# What does this PR do?

Makes the unsloth gradient-checkpointing custom autograd function and the reward-model device fallback **device-agnostic**, so LLaMA-Factory works on non-CUDA accelerators (Ascend NPU, Intel XPU, MPS, etc.).

## Problem

### 1. `get_unsloth_gradient_checkpointing_func()` — crash on NPU
When `use_unsloth_gc=True`, the custom function uses CUDA-specific APIs:

```python
@torch.cuda.amp.custom_fwd
def forward(...):
    ...
@torch.cuda.amp.custom_bwd
def backward(...):
    hidden_states = hidden_states.to("cuda", non_blocking=True).detach()
```

On an Ascend NPU environment (torch_npu, where `torch.cuda` is **not** compiled in), `hidden_states.to("cuda")` raises:
```
RuntimeError: Torch not compiled with CUDA enabled
```
So gradient checkpointing is broken on NPU.

### 2. `hf_engine.py` device fallback hardcodes `"cuda"`
```python
device = getattr(model.pretrained_model, "device", "cuda")
```
On NPU `torch.cuda.is_available()` is `False`, so a missing device attribute would incorrectly fall back to CUDA.

## Fix

- Use `torch.amp.custom_fwd/bwd(device_type=...)` with the device type resolved from `torch.accelerator.current_accelerator()` (falls back to `"cuda"` for torch < 2.4 / no accelerator module).
- Save the compute device as `ctx._device` in `forward`, and move the saved `hidden_states` back to it in `backward` instead of hardcoding `"cuda"`.
- Change the `hf_engine.py` fallback default to `torch.device("cpu")`.

## Verification

Verified on **Ascend NPU (torch 2.14, torch_npu, 910B)**:
- Full forward+backward through `UnslothGradientCheckpointing` runs correctly (`hidden_states` round-trips to NPU, gradients propagate).
- The old `.to("cuda")` pattern reproduces `RuntimeError: Torch not compiled with CUDA enabled` on the same setup, confirming the fix addresses a real NPU break.
- `torch.amp.custom_fwd(device_type="npu")` is confirmed valid on this environment.

Device-agnostic: on CUDA, `torch.accelerator.current_accelerator()` returns `"cuda"`, preserving existing behavior.
