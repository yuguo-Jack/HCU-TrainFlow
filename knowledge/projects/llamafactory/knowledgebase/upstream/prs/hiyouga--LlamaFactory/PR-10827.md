# fix(data): mask historical EOS labels with mask_history

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10827) · state: open · merged: False

## Original PR description

# What does this PR do?

`mask_history=True` should train only on the final assistant turn. With an
`efficient_eos` template, the SFT processor masks historical response tokens
but still inserts supervised EOS labels into historical source spans.

For a three-turn conversation using `bailing` or `hy_dense_7b`, one historical
EOS remains in the labels consumed by shifted causal-LM loss. The final
response is therefore not the only training target. This affects ordinary
and packed SFT preprocessing.

Skip the historical EOS insertion when `mask_history` is enabled. The final
EOS remains supervised. Training on every turn and templates without
`efficient_eos` keep their existing behavior.

Add offline regression cases using the real registered templates and a local
byte-level tokenizer. The expected targets come from encoding individual
assistant responses, and the assertion checks labels after the causal shift
so an ignored label at position zero cannot produce a false positive.
