# fix(webui): gate trust_remote_code behind server-side opt-in (prevent unauthenticated RCE)

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10903) · state: open · merged: False

## Original PR description

## Summary

Removes the hardcoded `trust_remote_code=True` used by the WebUI when loading models/tokenizers. Remote-code execution is now an explicit **server-side opt-in** (`LLAMAFACTORY_WEBUI_TRUST_REMOTE_CODE`, default **off**) and is never derived from the user-supplied model path.

## PoC summary

The WebUI launches with no authentication and the model path is a free-text field. An unauthenticated HTTP POST to the Gradio queue join endpoint for the Load-model handler with `model_path` pointing at an attacker-controlled HF-style repo causes `transformers` to import and execute the repo's `configuration_evil.py` **inside the server process** (marker file written on the host). Code executes during config import — before tokenizer/weight loading fails — so no valid model weights are required:

```
POST /gradio_api/queue/join  ->  Load-model handler  ->  model_path=<attacker repo>
                                     |
                                     +-> transformers imports configuration_evil.py
                                         => arbitrary Python execution as the WebUI user
```

## Fix explanation

- Replace each hardcoded `trust_remote_code=True` with `is_env_enabled("LLAMAFACTORY_WEBUI_TRUST_REMOTE_CODE")` (default `0`/off), reusing the existing `is_env_enabled` helper.
- The opt-in lives on the **server** (env var), so a network client can no longer turn remote-code execution on by choosing a model path.
- Result: remote code is never executed for a user-supplied path unless the operator explicitly opted in.

Files changed:
- `src/llamafactory/webui/chatter.py`
- `src/llamafactory/webui/runner.py` (train + eval)
- `src/llamafactory/webui/components/export.py`

## Notes for maintainers

Operators who intentionally rely on remote code (e.g. custom `auto_map` models) can restore the previous behaviour by exporting `LLAMAFACTORY_WEBUI_TRUST_REMOTE_CODE=1`. Consider additionally defaulting the Gradio bind to `127.0.0.1` and adding `launch(auth=...)` for defence in depth.
