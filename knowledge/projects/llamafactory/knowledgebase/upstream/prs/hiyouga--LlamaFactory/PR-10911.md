## Original PR description

# What does this PR do?

Fixes #10910.

Use fsspec's path-only `ls(..., detail=False)` for cloud JSON directories instead of assuming every detailed entry has an S3-specific `Key`. Standard listings use `name`, so the old code raises `KeyError` before reading any files.

Keep the existing JSON/JSONL filter, concatenation, and single-file behavior. Tests use a real fsspec in-memory filesystem through the existing filesystem-creation boundary, covering S3/GS/GCS path forms, mixed JSON/JSONL directories, unrelated files, and the intended no-JSON error.

- Original code: 4 regression failures / 6 passing controls.

- Changed-file Ruff lint/format, license checks, and diff checks pass; source distribution and wheel build successfully.
- Repository-wide `make quality` stops on an existing W293 whitespace issue in the unchanged model patcher. That unrelated file is not changed here; full model/training suites and real cloud-provider integration were not run.
