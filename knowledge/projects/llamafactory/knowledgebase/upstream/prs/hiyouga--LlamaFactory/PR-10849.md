# [data] guard Qwen2-VL media tokens against SFT truncation

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10849) · state: open · merged: False

## Original PR description

# What does this PR do?

Refs #6699. Prevent Qwen2-VL supervised preprocessing from emitting image or video features whose expanded tokens were truncated. The original report's `get_rope_index` shape mismatch is reproducible when only part of an image token span remains.

The guard compares the original and retained Qwen2-VL vision boundaries and image/video token counts. It keeps a sample when truncation only removes text, and conservatively drops a truncated sample if its media-token mapping cannot be verified. Prefix tokens and an added EOS do not mask truncation. This applies to the `Qwen2VLPlugin` layout; other multimodal plugins retain their existing behavior.

Both ordinary and packed SFT preprocessing return consistent output keys for empty batches. This lets `datasets.map` continue when one batch contains only dropped examples. Warnings do not include the prompt content.

- Disabling the guard makes the real image, video and EOS regressions fail. Forcing the guard to drop every truncated sample makes the text-only truncation tests fail. Returning an empty mapping for an all-dropped batch reproduces the Arrow schema failure in ordinary and neat packing.

The repository's Ruff checks pass after its CI-style formatting step in a disposable checkout, and the license check plus source and wheel builds pass.
