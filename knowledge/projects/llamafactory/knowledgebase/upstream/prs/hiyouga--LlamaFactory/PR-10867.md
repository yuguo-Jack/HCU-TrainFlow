# [fix] preserve v0 torchrun argument boundaries

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10867) · state: open · merged: False

## Original PR description

# What does this PR do?

The v0 torchrun launcher joins and splits arguments again, turning an already-quoted path such as `"experiments/my run.yaml"` into two arguments and dropping empty values. Build argument lists directly in both static and elastic paths to preserve `__file__` and `sys.argv[1:]`, keeping the existing options, environment, and exit/error behavior.

Add CPU regression tests through `cli.main()` for static, elastic, and elastic node-range launches. They cover spaced paths/values, literal quotes/backslashes, empty arguments, and the existing environment/error behavior, with subprocess execution mocked.

Related to #5604 ([filename-space follow-up comment](https://github.com/hiyouga/LlamaFactory/issues/5604#issuecomment-2712179069)). That comment is historical context; the original issue was already closed for a different reported cause.

- Existing converter, formatter, and processor utility tests: **55 passed**.
- Ruff 0.15.5 lint and format checks across `scripts src tests tests_v1`: passed.
- Repository license check and sdist/wheel build: passed.
- Pre-commit on the two changed files: all applicable hooks passed. The all-files run passed every hook except `end-of-file-fixer`, which added a newline to the existing `CLAUDE.md` symlink placeholder on Windows (`core.symlinks=false`); that unrelated change was reverted.

A separate real torchrun smoke attempt was blocked before worker startup by this Windows PyTorch build's libuv rendezvous error. Full repository pytest, multi-platform CI, and distributed/model training have not been run locally.
