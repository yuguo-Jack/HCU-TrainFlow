# [model] fix gpt-oss kernel loading with transformers v5

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10900) · state: open · merged: False

## Original PR description

# What does this PR do?

Fixes #10256

Loading gpt-oss with transformers 5.x fails in `configure_attn_implementation` with:

```
ImportError: cannot import name 'load_and_register_kernel' from 'transformers.integrations.hub_kernels'
```

transformers v5 renamed `load_and_register_kernel` to `load_and_register_attn_kernel` (huggingface/transformers#41477). The first positional argument is still the attention implementation string, so the call site doesn't change. This PR imports the new name first and falls back to the old one for transformers 4.56/4.57.

Also adds a regression test that runs `configure_attn_implementation` on a `gpt_oss` config with the kernel loader mocked out (no GPU or hub download needed). It checks that the kernel is registered and the config/model args get updated.

Tested locally (CPU, macOS) with `WANDB_DISABLED=true pytest --import-mode=importlib tests/model/model_utils/test_attention.py -k gpt_oss`:
- transformers 5.2.0: fails before the fix with the ImportError above, passes after
- transformers 5.8.0, 4.57.1, 4.56.0: pass
- transformers 4.55.0: skipped (no hub kernel loader in that version)

`ruff check` / `ruff format --check` are clean on the touched files.
