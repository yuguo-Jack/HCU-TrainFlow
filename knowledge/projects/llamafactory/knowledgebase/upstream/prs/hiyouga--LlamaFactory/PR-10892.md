# [train] Left-pad generation during scheduled SFT evaluation

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10892) · state: open · merged: False

## Original PR description

# What does this PR do?

Fixes #10611.

`run_sft` switches the tokenizer to left padding only after `trainer.train()` returns. With `predict_with_generate=True` and scheduled evaluation, unequal-length prompts are therefore right-padded during training but left-padded for final evaluation. Decoder-only generation reads the padded last position, so the shorter prompt can produce a different completion.

Temporarily use left padding throughout `evaluate()` and `predict()` when generating, then restore the previous padding side, including when generation raises. Training batches retain their original padding.

The starting point was the user report in #10611. The regression was reproduced with constructed local data and randomly initialized tiny models; this does not reproduce the reporter's exact model or F1 scores.

Validation:
- Offline tiny-Llama regression tests exercise real training and generation, compare batched completions with individual unpadded generation, and cover persistent workers, multiple evaluation datasets, generation errors, and loss-only evaluation. On Transformers 4.57.6 and 5.8.0: upstream has 5 failures / 5 passes; the patch passes all 10 tests.
- An offline `get_train_args` → `run_sft` check with a locally saved tiny GPT2 and JSON dataset completes two training steps, scheduled evaluation, final evaluation, and prediction. Scheduled generation changes from 8/8 right-padded rows to 8/8 left-padded rows; final generation stays left-padded. Saved model weights are byte-identical before and after the patch.
- Repository pre-commit hooks, changed-file license checks, and `git diff --check` pass. Tests ran on CPU; GPU/distributed training and the full repository suite were not run.

AI assistance was used for investigation, implementation, tests, independent review, and this description.
