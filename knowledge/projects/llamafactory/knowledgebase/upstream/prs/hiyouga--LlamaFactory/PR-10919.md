# [data] fix default tool extractor for non-alphanumeric names

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10919) · state: open · merged: False

## Original PR description

## Motivation

`DefaultToolUtils` is the fallback tool format of every template that does not register its own
`tool_format` (the ReAct-style `Action: <name>` / `Action Input: <json>` format), and it is what
`Template.extract_tool` uses to turn a model response into `list[FunctionCall]`.

Two call sites depend on it:

- `src/llamafactory/api/chat.py` — the OpenAI-compatible API server, which only returns `tool_calls`
  when the extractor succeeds.
- `src/llamafactory/webui/chatter.py` — the WebUI chat, which renders the parsed tool calls.

The extractor could not parse two very common shapes of a tool call. In both cases it silently fell
back to returning the raw assistant text, so the tool call was lost and the caller saw a plain
string instead of a tool call.

1. **Tool names that are not made of word characters.** OpenAI allows `-` and `.` in function names
   (e.g. `get-weather`, `browser.search`), and `DefaultToolUtils.function_formatter` writes them out
   verbatim as `Action: get-weather`. The extractor only accepted `[A-Za-z0-9_]+`, so such a call was
   not matched at all:

   ```python
   >>> DefaultToolUtils.tool_extractor('Action: get-weather\nAction Input: {"location": "SF"}')
   'Action: get-weather\nAction Input: {"location": "SF"}'   # not parsed
   ```

2. **Argument values that contain the literal text `Action:`.** The arguments were cut at the next
   `Action:` occurrence, even when that occurrence was inside a JSON string. The arguments were
   therefore truncated and could not be parsed:

   ```python
   >>> DefaultToolUtils.tool_extractor('Action: test_tool\nAction Input: {"instruction": "Action: run"}')
   'Action: test_tool\nAction Input: {"instruction": "Action: run"}'   # not parsed
   ```

## Changes

`src/llamafactory/data/tool_utils.py`

- accept any non-space character in the tool name, so that names such as `get-weather` or
  `browser.search` are extracted;
- only split the arguments at a following `Action: ...` when that marker is followed by its
  `Action Input:`, so that an `Action:` inside the argument values no longer truncates them.

The behaviour for well-formed calls is unchanged: a single call, several calls, a call whose
arguments are not valid JSON (the raw content is returned) and a response without any call (the
raw content is returned).
