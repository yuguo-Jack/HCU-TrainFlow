# fix: handle a single validation sample after CLI parsing

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10922) · state: open · merged: False

## Original PR description

## Summary

- Treat `val_size == 1` as an absolute sample count, consistently with larger integer counts and the documented `[0, 1)` fractional range.
- Add eight regression cases covering CLI `1`/`1.0`, larger counts, fractional splits, and streaming/non-streaming integer and float inputs.

`DataArguments.val_size` is typed as `float`, so `HfArgumentParser` converts `--val_size 1` to `1.0`. The existing `> 1` conversion leaves that boundary as a float, which `Dataset.train_test_split()` rejects. Changing the boundary to `>= 1` reserves one validation sample instead. This also preserves the existing streaming behavior. The older fix referenced by #474 handled values greater than one; this fixes the remaining equality boundary rather than reopening that report.
