# fix(longlora): extend device type check to include Ascend NPU

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10829) · state: closed · merged: True

## Original PR description

### Problem

In `llama_sdpa_attention_forward` (LongRoPE / long-context path), the "avoid pytorch bug" contiguous workaround only applied on CUDA:

```python
if query_states.device.type == "cuda" and causal_mask is not None:  # avoid pytorch bug
    query_states = query_states.contiguous()
    ...
```

On Ascend NPU, `query_states.device.type` is `"npu"`, so this workaround is skipped. The same `scaled_dot_product_attention` path that motivated the contiguous fix on CUDA can produce incorrect results with non-contiguous shifted query/key/value states on NPU too.

### Fix

Extend the device type check to include `"npu"`:

```python
if query_states.device.type in ("cuda", "npu") and causal_mask is not None:  # avoid pytorch bug
```

Keeps the workaround device-agnostic and consistent with LLaMA-Factory's existing NPU support.

### Verification (Ascend 910B NPU, torch 2.14.0a0 + torch_npu)

- Before: workaround skipped (`device.type == 'npu'`, check was `== 'cuda'`)
- After: workaround applied, and `scaled_dot_product_attention` runs correctly on NPU (output shape `(2,3,4,8)`, device `npu`)

Changes: 1 line in `src/llamafactory/model/model_utils/longlora.py`.
