# [Fix] Honor return_outputs during ASFT evaluation

[Upstream PR](https://github.com/hiyouga/LlamaFactory/pull/10845) · state: closed · merged: False

## Original PR description

# What does this PR do?

Fixes ASFT evaluation failing with `TypeError: iteration over a 0-d tensor` when `predict_with_generate=False`.

## Motivation

ASFT training can complete its first optimizer step, then crash at the first scheduled evaluation. Hugging Face's `Trainer.prediction_step()` calls `compute_loss(..., return_outputs=True)` and unpacks `(loss, outputs)`. The ASFT override ignores that argument and always returns a scalar loss. This also breaks loss-only evaluation, since the unpack happens before the `prediction_loss_only` check.

Returning a scalar is correct for the ordinary training call, which explains why training without evaluation can run. The override needs to support both forms of the Trainer contract. The existing ASFT examples leave their evaluation settings commented out.

The fix explicitly handles `return_outputs`, returning the ASFT loss with the policy model outputs when requested, and forwarding the argument to the parent implementation for other SFT losses. The ASFT objective and its normalization are unchanged.

## Validation

- Added offline CPU tests using a tiny, randomly initialized Llama: ASFT scalar/tuple returns, backward propagation with a frozen reference, both prediction modes, the full `evaluate()` loop, and ordinary SFT delegation.
- Before the fix: 4 evaluation-related failures and 1 passing training-loss test, all failures reporting `iteration over a 0-d tensor`.
- After the fix: all 7 tests pass on both Transformers **5.8.0** and **4.55.0**, using Python 3.12 and PyTorch 2.10.0.
- Real CLI reproduction on an RTX 5090 with **Qwen3-0.6B**, full ASFT, BF16, SDPA, and `eval_steps: 1`: the baseline crashes during evaluation after step 1. The fix completes 2 training steps, both scheduled evaluations, and final evaluation (`eval_loss=0.06441557`). This is a smoke test, not a training-quality benchmark.
- `make commit`, `make style`, `make quality`, `make license`, and `make build` pass.
- Full `make test` was attempted, but stopped while the first existing test waited for a Hugging Face model: this machine cannot connect to `huggingface.co:443`. The full suite is **not** claimed to pass locally; the new regression tests require no network or downloaded weights.
