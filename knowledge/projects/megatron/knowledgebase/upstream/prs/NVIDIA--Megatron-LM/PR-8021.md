# Require dp in the refit source collection instead of filling it

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8021) · state: open · merged: False

## Original PR description

**Why.** `_unwrap_model_cores`, used by `prepare_swap_model_weights`, `swap_model_weights` and `reshard_model_weights`, fills a missing `dp` on the source model's `pg_collection` from `parallel_state` and stores it in the model's own collection. When the model is not on the global grid, that is another grid's data-parallel group: the reshard plan routes over the wrong ranks, and every later reader of `model.pg_collection.dp` sees a group the caller never set.

**What.**
- A source model without `refit_modules` whose collection does not set `dp` (or sets it to `None`) now raises `ValueError`, and the collection is never modified.
- `refit.py` no longer imports `parallel_state`, and the README's requirement table drops the auto-fill note.

**Tests.**
- New: a missing or `None` `dp` raises and leaves the collection unchanged (on main, the collection gains the global group), and a collection that sets `dp` reads no global group.
- The provider test now patches `parallel_state` itself, so it covers reads from any module.
- A `tests/unit_tests/resharding/` subset passes on 4 GPUs, as on main: metadata, plan cache, planner, MIMO swap, and GPT and router-bias refit over NCCL.

**Compatibility.** Megatron-LM's training loop, the RL refit path and the refit benchmark build the source model with a full collection, so they are unaffected. External callers that relied on the auto-fill must set `pg_collection.dp`.

For the refit owners: the fill was kept on purpose as a legacy single-model fallback. If it must stay, the alternative is to resolve it into a local variable passed to plan building, without writing into the model's collection. That keeps one global read.
