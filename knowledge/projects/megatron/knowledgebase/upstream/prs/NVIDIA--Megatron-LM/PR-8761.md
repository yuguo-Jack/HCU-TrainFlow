# Use the model's process groups in ModelOpt, multimodal and MIMO examples

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8761) · state: closed · merged: False

## Original PR description

Depends on #6303 (which contains #6293), #8733, #8753 (which contains #8017, #8023, #8044 and #8049) and #8757. Please review the diff from their merge: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/610d56d002...yx/pstate-f3-examples).
- #8753 gives `InternViTRMSNorm` the `tp_group` and checkpoint groups that this PR builds on.
- The example fallbacks use #8049's helpers. This PR rewrites `use_mpu_process_groups()` fallbacks that #6293 and #6303 add to the examples.
- The tests use #8017's `forbid_global_process_groups`. The dataloader-restore and packed-stats tests call #8733's `enable_strict_process_group_fallbacks()`.
- `test_full_dataset_probe_builds_the_loader_on_the_run_collection` calls the full-dataset probe with the run's collection. #8741 adds that argument, and #8757 passes it to the provider. Without #8757 the test fails with a `TypeError`.
- The merges of #8753 and #8757 regenerate the process-group allowlist, whose total conflicted. The merge of #8757 keeps all three names in the `process_groups_config` import of `initialize.py`, which #8733 and #8757 both extend.

Land this after #8759. Dataset providers receive the run's collection only from #8759's `build_train_valid_test_datasets`. Until then, stock multimodal, ModelOpt-finetune and MIMO training warn once per dataset provider. The changes of the two PRs do not overlap.

**Why.** The ModelOpt, multimodal and single-grid MIMO examples build their models with the run's process-group collection, then read the global `parallel_state` grid anyway. They read it for:
- pipeline-stage checks;
- the ranks that read data;
- batch broadcasts, some through `broadcast_data` with no group;
- loss reductions;
- data sharding.

On a grid other than the global one these reads select the wrong ranks.

**What.** One commit per example family, then a multimodal follow-up for the dataloader restore and the packed-sequence stats.
- ModelOpt:
  - the scripts take their groups from `unwrap_model(model)[0].pg_collection`;
  - `forward_step` passes the model's collection to `get_batch`, which broadcasts over its TP group, shards over its CP group and finds the stage from its PP group;
  - the SFT dataset provider takes `pg_collection`;
  - `offline_feature_extract.py` imports the `parse_and_validate_args` it called, so it no longer fails at startup.
  - That makes its per-sample WORLD barrier reachable. The ranks handle different numbers of samples whenever the split is not a multiple of the expert data-parallel size, so the first rank to finish exited while the others waited in barriers it never entered. `extract_feature` now runs one barrier after its loop, which every rank enters once per split.
- Multimodal:
  - `forward_step` passes the model's collection to `get_batch` and `loss_func`. `get_batch` broadcasts over `tp`, or over `tp_cp` when the dataloader is deduplicated across CP, and needs `tp_cp` only then.
  - The dataloader provider, its rank helpers and the text-generation helpers take `pg_collection`. Like `build_pretraining_data_loader`, the provider shards over `dp_gtp_remat`, or over `dp` for a collection without the GTP fields.
  - InternViT builds `linear_qkv` and its Q/K norms on the attention's TP group. The new `InternViTTransformerLayer` rebuilds the input and pre-MLP norms on the layer's TP group, so checkpointing stock InternViT does not warn.
  - The `get_model` wrappers in `run_text_generation.py` and `vision_model_tester.py` accept the `config` and `pg_collection` that `get_model` passes. They raised `TypeError` before.
  - The dataloader-state restore (`--load` with `--dataloader-save`) passes `get_checkpoint_name()` what the writer, `maybe_save_dataloader_state()`, uses: the PP flag from the model's `pp` group, then TP 0, PP 0, no EP and EP rank 0. It used to leave `pipeline_parallel`, `tensor_rank` and `expert_rank` unset, so it read them from the global grid. #8758 makes that read warn, so without this change every resume would warn once #8758 lands, and strict mode would stop it. LLaVA trains on the global grid, so its restore does not change.
  - `get_batch()` passes its model collection to `update_packed_sequence_stats()` for `--log-packed-sequence-stats`. Without one, the helper warned once per process and raised under `--strict-process-group-fallbacks`. `get_batch()` requires `cp` when the flag is set, because the helper counts a batch only at CP rank 0.
  - Neither of the last two changes adds or moves a collective. Both helpers only read ranks and sizes, and the training loop still gathers the packed stats over all ranks.
- MIMO:
  - `forward_step` uses the language model's collection for `get_batch` and `loss_func`;
  - `broadcast_nested_data_batch` takes the TP group;
  - the dataset providers take `pg_collection`;
  - the model providers pass their collection to every module spec and attach it to the MIMO model.
- Every new `pg_collection` or `tp_group` argument defaults to the global groups with a `ProcessGroupFallbackWarning` (deprecated in 0.21, removed in 0.23). The model providers, which fell back silently, warn too.

**Tests.**
- New `tests/unit_tests/post_training/test_modelopt_example_process_groups.py`, `tests/unit_tests/data/test_multimodal_example_process_groups.py` and `tests/unit_tests/models/mimo/test_mimo_example_process_groups.py`. They use stand-in groups, or a TP=2 test grid built without the global one, with global-grid reads forbidden. Several also run with `ProcessGroupFallbackWarning` as an error. The InternViT, MIMO-broadcast and fallback cases need 4 GPUs.
- `test_multimodal_dataloader_provider.py` passes stand-in collections instead of patching the accessors by name. It also runs the full-dataset probe end to end and checks that it does not warn.
- `test_restore_reads_the_state_file_the_checkpoint_writes[1|2]` saves with `maybe_save_dataloader_state()` as data ranks 0 and 3, then restores through the provider. It uses the real `get_checkpoint_name()` at PP 1 and 2.
- `test_get_batch_counts_packed_sequence_stats_on_the_model_groups[0|1]` checks that the stats helper gets the model collection and counts the batch on CP rank 0 only. `test_get_batch_requires_the_cp_group_for_packed_sequence_stats` checks the new requirement.
- The restore and stats-counting tests run under `enable_strict_process_group_fallbacks()` with every global-grid accessor raising.
- `test_mimo_model_quantization.py` passes the grid's collection to the mock MIMO provider.

On 4 GPUs against its base, no test fails or is skipped on either side:
- `test_multimodal_dataloader_provider.py`: 23 passed here vs 15 on the base. The 8 new tests pass.
- `test_multimodal_example_process_groups.py`, `test_mimo_example_process_groups.py` and `test_modelopt_example_process_groups.py` are new: 13, 7 and 7 passed.
- `test_mimo_model_quantization.py` and the existing `test_checkpoint_helper_group_fallbacks.py`: 2 and 19 passed, as on the base.
- The 36 passes of the two multimodal test files include the new restore and packed-stats tests and the 3 CUDA-only tests: `test_provider_without_collection_warns_and_uses_the_global_grid` and the two InternViT tests.

In the integration run (main 77391e71cc with all 93 #6307 PRs and 6 gap fixes merged), this PR's five test files show no regressions against main and give the same counts as above.

On an earlier version of these commits, with the missing packages stubbed, the new tests passed on CPU (49 passed; the GPU-only cases skipped, and one existing GPU test failed for lack of NCCL), and 40 of them failed on the base.

Before the sync with main, the branch ran on 4 CPU ranks with Gloo:
- With the multimodal task encoders and the Energon loaders stubbed, the two multimodal test files give 33 passed and 3 skipped. The 3 skips are the existing CUDA-only tests. The 5 new CPU tests and the full-dataset probe test pass.
- With the restore and packed-stats code changes reverted, the 5 new tests fail. The restore reads `get_pipeline_model_parallel_world_size()` from the global grid, the stats helper gets `None`, and the missing `cp` is not rejected.
- Without the stubs, the five test files give the same results per test as the stacked version of this PR, which lacked the dataloader-restore and packed-stats commit. The exceptions are the 3 new `get_batch` tests, which error there. That run covers little of the example code, because the multimodal tests cannot import PIL there.
- The process-group checker reports 154 grandfathered reads, 7 of them guarded, on the base and on this branch.

**Compatibility.**
- Signatures only gain keyword arguments. Their defaults keep the earlier behavior, which now warns. On the standard grid the groups are the ones the accessors returned, and dataloader checkpoint names are unchanged.
- `InternViTTransformerLayer` builds the two norms twice: `TransformerLayer` builds them without a group, and the subclass rebuilds them. Module order, parameter names, state-dict keys and RNG state are unchanged.
- With `--log-packed-sequence-stats` set, multimodal `get_batch()` now raises `ValueError` for a hand-built collection without `cp`. Before, it ran and the stats fell back to the global grid. `forward_step()` passes the model's full collection, which has `cp`.
- Left on the global grid on purpose:
  - the bootstrap reads in `convert_model.get_model` and `avlm_inference.main`;
  - `examples/mimo/training/distributed.py`, which reads the globals to assert that they were never initialized.
- Already broken before this PR and not fixed here:
  - `run_text_generation.py` imports the removed `megatron.inference.text_generation`;
  - the MIMO `train.py` `model_provider` raises for `mock` and `video_llava_vlm`;
  - `--dataset-provider llava_avlm` raises `TypeError` on `max_seq_length`.
- Needs `determinism-exempt` only while the PRs below this one are unlanded. CI diffs against main, and #8753 changes registered kernel files such as `transformer_engine.py`. This PR's own diff passes the coverage check.

On 2026-11-01 the branch was synced with main 77391e71cc by a merge commit that lists each conflict and its resolution, so existing commits and review links stay valid.

A later commit moves that barrier out of the per-sample loop. On 4 GPUs against the head before it, `test_modelopt_example_process_groups.py` passes 7 of 7 on both, and the feature-extraction test now checks for one barrier per call on a split that gives the expert data-parallel ranks different sample counts. The PRs that contain this one pick the commit up at their next sync.
