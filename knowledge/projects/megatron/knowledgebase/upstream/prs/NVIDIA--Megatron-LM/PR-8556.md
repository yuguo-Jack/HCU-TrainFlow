# What does this PR do?

Align non-distributed-optimizer gradient-buffer parameter starts to 16 bytes when NVFP4 and fused weight-gradient accumulation are enabled. On the tested SM120 stack, an unaligned `main_grad` causes the TE/cuBLAS NVFP4 weight-gradient GEMM to fail with `CUBLAS_STATUS_NOT_SUPPORTED`; [cuBLAS requires 16-byte alignment for block-scaled FP4 matrices](https://docs.nvidia.com/cuda/cublas/index.html#using-the-cublaslt-api). Existing distributed-optimizer layouts are already aligned; other configurations retain their existing layout.

The failure was observed in GPU training of an eight-layer GDN2 test model with synthetic tokens, TP2+SP and offloading disabled. It is independent of GDN activation offloading. [TE 2.20.2 documents NVFP4 training support for SM100 and SM103](https://docs.nvidia.com/deeplearning/transformer-engine/features/low_precision_training/nvfp4/nvfp4.html#supported-devices). Reproduction in a supported training environment is still needed.

## Validation

The cases cover FP32/BF16 gradient buffers, repeated backward passes and cross-rank gradient equality. The control uses parent `9dd63d992a5925dba7f9bfd1aec9dbfb1f54b837` with the identical regression test and unchanged production code; both cases fail on both ranks with `CUBLAS_STATUS_NOT_SUPPORTED`. RHT and stochastic rounding are disabled for exact comparisons.

[Commands, source revisions, original rank logs and audit](https://github.com/WEIXILIN0307/Megatron-LM/tree/5af996df67ef2483242ea25be876b996d745449c/nvfp4-current-20261103).

The [earlier evidence](https://github.com/WEIXILIN0307/Megatron-LM/tree/02890e97b1273d9a8695f76aaa208730054fe415/gdn-open-issues-20261027) retains layout tests at this head and native GDN2 training controls at their recorded prototype/integration revisions. These results are on SM120; testing on a documented NVFP4 training device remains pending. Upstream GPU CI has not run.

The change addresses the fused weight-gradient output buffer only. A current offload-disabled Qwen TP2+SP baseline also fails in a separate NVFP4 dgrad GEMM; an isolated TE Linear reproduces its width-4112 failure. That is a different failure and is not addressed by this PR.

Black, isort, Ruff, Pylint and the determinism coverage checker passed on the changed files; production code is unchanged in this recheck.
