# Extract build_process_group_collection from initialize_model_parallel

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8039) · state: closed · merged: False

## Original PR description

Depends on #6259. Please review the diff from #6259's head: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/7a951c3dfd...yx/pstate-p2-standard-grid-builder).

#6259 adds the Gloo fields `intra_dp_cp_gloo` and `intra_expt_dp_gloo` to `ProcessGroupCollection`. The builder already creates both Gloo groups, and the commit "Fill the Gloo fields in build_process_group_collection" passes them to the collection it returns. Without it, the field-set checks in `test_build_process_group_collection.py` fail once both PRs are merged. With the merge and this commit, the file passes all 21 tests on 4 CPU ranks with Gloo (run before the 2026-11-01 sync).

**Why.** `initialize_model_parallel()` creates the process groups of the standard grid and writes them into about 50 `parallel_state` globals. `ProcessGroupCollection.use_mpu_process_groups()` copies them back out, and code that needs the standard grid without the globals (inference sub-grids, Megatron-Bridge) rebuilds it with its own code. This PR adds one builder that later migration steps can use.

**What.**
- `build_process_group_collection(*, ...)` creates the groups and returns `(ProcessGroupCollection, StandardGridExtras)` without setting any `parallel_state` global. It takes the keyword arguments of `initialize_model_parallel()` except the virtual-pipeline size and the deprecated `hybrid_context_parallel`. Every collection field is set, to `None` where this rank is not a member or the group is not built; the dynamic CP maps `dynamic_cp` and `dynamic_tp_cp` are empty without dynamic CP. `StandardGridExtras` holds what the collection has no field for: the TP x DP group, GTP-inclusive partial DP groups, the dense weight-replica rank lists and global rank lists. It also holds all five Gloo groups; the collection has fields for two of them, `intra_dp_cp_gloo` and `intra_expt_dp_gloo`.
- The body is the previous one with locals instead of globals: same groups, order, `group_desc`, `pg_options`, backend and timeout.
- `initialize_model_parallel()` keeps its signature, registers the result in the existing globals and returns the collection.

**Tests.**
- New `test_build_process_group_collection.py` (fails on main): the returned collection holds the objects `use_mpu_process_groups()` returns; with every accessor patched to raise and another grid registered, the builder reproduces the registered grid's ranks and changes no global; rank-offset windows; dynamic CP with TP1 and TP2.
- A parity harness on 8- and 16-rank CPU worlds, run before the sync: every `new_group` call, barrier, global, accessor and shim field matches main.
- On 4 GPUs, in the integration run (all #6307 PRs merged onto main) against main: `test_build_process_group_collection.py` passes all 21 tests. `test_parallel_state.py` passes 74 tests vs 68 on main; the 6 extra are tests #6259 adds. The same 9 `test_parallel_state.py` tests (`test_different_initialize_order_consistency` and `test_pipeline_parallel_initializations` cases) fail on both sides because they need 8 ranks. In the integration run, this PR's test files show no regressions against main.

**Compatibility.** The signature is unchanged; the return value is new. If building fails nothing is registered, and a rank outside a group no longer keeps that group's rank list from an earlier initialization.

**Landing order.** #8026 conflicts at the end of `initialize_model_parallel()`; resolve by keeping this side. The API shape (tuple return, `StandardGridExtras`) is open for discussion.
