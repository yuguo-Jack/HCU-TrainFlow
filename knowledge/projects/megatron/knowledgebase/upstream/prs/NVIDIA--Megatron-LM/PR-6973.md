# MFSDP v2: overlap the DP-outer gradient reduction on its own stream

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/6973) · state: closed · merged: True

## Original PR description

## Summary

Overlaps the last-microbatch DP-outer gradient reduction with the DP-inner
reductions in the experimental Megatron-FSDP (v2) path, behind an opt-in
`overlap_outer_communication` flag. Continues #6714 (sub-issue of #5616).

Today the DP-outer finalize (HSDP all-reduce / HFSDP reduce-scatter) runs on the
reduce-scatter stream, serialized behind the DP-inner reductions. This routes it
to its own stream so a parameter group's DP-outer reduction can overlap the next
group's DP-inner reduction.

## Design

The opt-in `overlap_outer_communication` flag gives the last-microbatch
DP-outer reduction a dedicated stream. It is exposed through
`--overlap-outer-communication`. With the flag off, outer reductions share
`inner_reduction_stream`; enabling it creates a dedicated `outer_reduction_stream`.

`overlap_allgather_reduction=True` replaces `unify_communication_stream=False`
in `RuntimePolicy`, preserving the default of separate all-gather and reduction
streams. Setting it to false shares those streams. The two overlap options are
independent: all four combinations are supported. Outer all-gather separation
is future work; this PR implements outer reduction overlap.

Split gradient reduction into `reduce_inner_gradients()` and
`reduce_outer_gradients()`. The module orders the outer stream after each
group's inner reduction, allowing subsequent groups to pack and reduce their
gradients while outer communication runs. Both paths reuse the existing
persistent `main_grad` buffer and its optimizer-layout
`pre_optimizer_main_grad` view; no extra gradient buffer is introduced.

The rebased implementation uses `context.py` and joins both reduction streams
in `finish_grad_sync()`, covering automatic and caller-managed synchronization.
The adapter and both shared training context factories propagate the option through
`RuntimePolicy`.

## Testing

Rebased onto `origin/main` at `2d7ea246f`, preserving main's recorded-prefetch order and
SchedulePolicy changes. Both shared training-context factories still
propagate outer overlap through `RuntimePolicy`. The reduction-scheduling method, parameter-group implementation,
and runtime-policy definitions are unchanged from the reviewed head.

On two RTX A6000 GPUs with NGC 26.08, **142 passed, 6 skipped per rank** across
context, fully-shard, overlap, memory, MCore CUDA graphs, gradient multiplicity,
dense/MoE adapter, and parameter tests. This covers serial/overlapped HSDP and
HFSDP training with both shard layouts, both `zero_grad` modes, and 1/3
microbatches, plus all four stream-option combinations.

Black, isort, Ruff, Pylint (10/10), and `git diff --check` passed in the
repository's formatter scope; the modified training entry points also compile.
Skipped cases require four ranks or Blackwell hardware. The local hybrid mesh
is 2x1; nontrivial communication on both mesh axes and multi-node performance
were not revalidated. Local tests used NGC 26.08; canonical CI uses NGC 26.09.
GitHub CI is pending on the rebased head.

## Measurement

This overlap pays off when DP-outer and DP-inner map to different communication
channels (e.g. RDMA vs NVLink). On single-node hardware both axes are NVLink; a
collective-overlap microbenchmark there recovers ~1/3 of the combined DP-inner +
DP-outer collective time. The impact on a realistic multi-channel setting is best
measured on larger hardware.
