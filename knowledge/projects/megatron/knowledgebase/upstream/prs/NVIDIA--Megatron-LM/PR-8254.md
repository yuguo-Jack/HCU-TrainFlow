# fix(inference): AUT-2539 hold back unstable reasoning in streamed chat deltas

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8254) · state: closed · merged: False

## Original PR description

## Background

A review of recent inference changes on `main` found that `StreamingChatParser`, which drives OpenAI-compatible streaming in the dynamic text-gen server, commits reasoning deltas as soon as the reasoning parser returns them. A later chunk can still move that text, and text that was already streamed cannot be taken back.

## What changed

- `openai_streaming.py`: while reasoning is still open, hold back a trailing partial end marker (for example `</thi`, or a partial implicit marker such as `<tool_call>`) instead of streaming it as reasoning. This adds `_partial_marker_start` (now also used by `_safe_content_prefix`) and `_safe_reasoning_prefix`.
- `StreamingChatParser` takes two new arguments, `reasoning_markers` and `force_content`. Some parsers return reasoning as content until a non-empty answer follows, then move it back to reasoning. NemotronV3 does this with `enable_thinking=False` or `force_nonempty_content=True`. For those parsers no deltas are sent until the split is stable. The parser is either named explicitly or detected by a one-time probe of `parse`. The final parse flushes everything.
- Logprobs of tokens whose text the parser holds back are no longer dropped. They are buffered per choice (`pending_logprobs`) and attached to the next chunk that carries text, including the final flush.
- New unit tests in `tests/unit_tests/inference/test_openai_streaming.py`, including `test_openai_stream_keeps_logprobs_of_parser_held_back_text`. It covers a final flush with and without additional tokens.

## Details

The callers are `endpoints/chat_completions.py` and `endpoints/completions.py`. There are no dependency or lock changes.

### [P2] Retain OpenAI logprobs while forced-content deltas are buffered

**Failure:** The new [early return](https://github.com/NVIDIA/Megatron-LM/blob/436475833c5ede86b11dafbe73ab90e981f99451/megatron/core/inference/text_generation_server/dynamic_text_gen_server/openai_streaming.py#L235-L239) drops the standard OpenAI logprobs for buffered tokens. For example, use `NemotronV3ReasoningParser` with `enable_thinking=False`, stream two partial frames generating `a` and `b` with logprobs, then send a final frame containing the same two tokens. Both partial parses return `[]`. At finalization, `openai_stream` finds no new tokens, sets `logprobs=None`, and emits the buffered `{"content":"ab"}` without its logprobs. The terminal `generation_log_probs` extension does not restore the missing OpenAI `choices[].logprobs.content` entries. This follows directly from the [per-frame attachment logic](https://github.com/NVIDIA/Megatron-LM/blob/436475833c5ede86b11dafbe73ab90e981f99451/megatron/core/inference/text_generation_server/dynamic_text_gen_server/openai_streaming.py#L468-L510).

**Correction:** Keep the reasoning/content holdback, but retain unattached logprob records in each choice's `openai_stream` state. Consume them once when the parser next emits a textual delta, including a final-only flush. The invariant is that delaying text must not discard its logprob records.

Suggested implementation in [the state initialization](https://github.com/NVIDIA/Megatron-LM/blob/436475833c5ede86b11dafbe73ab90e981f99451/megatron/core/inference/text_generation_server/dynamic_text_gen_server/openai_streaming.py#L359-L373) and parser branch, preserving the existing policy of attaching records to the first textual delta:

```python
# Add to each per-choice states entry:
pending_parser_logprobs=None,
```

Replace the parser branch's logprob selection through the assignment to `parsed_logprobs`; retain its existing `yield sse(...)` below:

```python
if parser is not None:
    if logprobs is not None:
        pending = state["pending_parser_logprobs"]
        if pending is None:
            state["pending_parser_logprobs"] = logprobs
        else:
            for key, entries in logprobs.items():
                pending[key].extend(entries)

    parsed_deltas = parser.parse(state["detokenizer"].text, finished=is_final)
    for parsed_delta in parsed_deltas:
        parsed_logprobs = None
        if (
            state["pending_parser_logprobs"] is not None
            and (
                parsed_delta.get("content") is not None
                or parsed_delta.get("reasoning_content") is not None
            )
        ):
            parsed_logprobs = state["pending_parser_logprobs"]
            state["pending_parser_logprobs"] = None
        # Keep the existing yield sse(...) here.
```

- Add an async regression alongside [the existing parser/logprob test](https://github.com/NVIDIA/Megatron-LM/blob/436475833c5ede86b11dafbe73ab90e981f99451/tests/unit_tests/inference/test_openai_streaming.py#L241-L288): partial tokens `[1]`, then `[2]`, followed by final tokens `[1, 2]`, using the existing test tokenizer and forced Nemotron parser. Expect no early text, final content `ab`, and standard logprob entries for both `a` and `b`, in order and exactly once. Include `-inf` and top-logprobs to verify their existing finite-floor conversion survives buffering. Also test a final frame adding token `3`: expect `abc` with all three entries exactly once.
