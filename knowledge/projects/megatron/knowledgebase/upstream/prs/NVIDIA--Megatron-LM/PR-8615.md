# fix: clean up CUDA graph runners in delete_cuda_graphs after capture (#8537)

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8615) · state: open · merged: False

## Original PR description

## Description
Fixes #8537.

### Problem
`delete_cuda_graphs()` relies on `_CudagraphGlobalRecord.cudagraph_record` to locate and reset active `_CudaGraphRunner` instances (`runner.cudagraph_created = False`, `runner.fwd_graph = None`, `runner.bwd_graph = None`, `runner.mempool = None`). However, `_CudagraphGlobalRecord.create_cudagraphs()` clears `cls.cudagraph_record = []` upon completing graph capture. Consequently, calls to `delete_cuda_graphs()` after graph capture encounter an empty `cudagraph_record` and fail to reset the runners, retaining graph and mempool references and leading to process termination hangs (e.g., in Megatron-Bridge recipes, see https://github.com/NVIDIA-NeMo/Megatron-Bridge/issues/6639 and WAR PR https://github.com/NVIDIA-NeMo/Megatron-Bridge/pull/6681).

### Solution
1. In `_CudagraphGlobalRecord.create_cudagraphs`, retain captured runners in `_CudagraphGlobalRecord.cudagraph_created_runners` before resetting `cudagraph_record`.
2. In `delete_cuda_graphs()`, aggregate runners from `cudagraph_created_runners` along with any un-captured and inference runners, resetting their state, graph handles, and mempool references.
3. Added unit tests in `tests/unit_tests/transformer/test_cuda_graphs.py` (`TestDeleteCudaGraphsRunners`) to verify that `delete_cuda_graphs()` properly resets runners and clears global tracking state after capture.

### Testing
- Verified `test_delete_cuda_graphs_resets_captured_runners` passes and confirms that `runner.fwd_graph is None`, `runner.bwd_graph is None`, `runner.mempool is None`, and `runner.cudagraph_created is False`.
