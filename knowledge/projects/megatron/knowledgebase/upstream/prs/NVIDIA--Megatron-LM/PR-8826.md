## Implementation details

- vLLM's `env_override.py` runs `os.environ.setdefault("TRITON_CACHE_AUTOTUNING", "1")` when it is imported, and ModelOpt imports it while loading its plugin during collection. `apply_determinism_env` then rejects the run because `TRITON_CACHE_DIR` is unset, so every module under `tests/unit_tests/determinism/kernels` fails to collect.
- `tests.unit_tests` is imported before the root conftest, so setting Triton's own default there first makes vLLM's `setdefault` a no-op. An explicit `TRITON_CACHE_AUTOTUNING` from the environment still wins.

## Testing

H20 with vLLM installed, `tests/unit_tests/determinism/kernels`, 2 ranks:

- `main`: 20 collection errors (`TRITON_CACHE_AUTOTUNING=1 under --deterministic-mode requires TRITON_CACHE_DIR`).
- this branch: 703 passed, 73 skipped, 1 failed. The failure, `test_mla_device_placement.py::test_mla_split_device_first_prefill`, also fails on `main` once collection works there (with `TRITON_CACHE_AUTOTUNING=0` set explicitly), so it is unrelated.
