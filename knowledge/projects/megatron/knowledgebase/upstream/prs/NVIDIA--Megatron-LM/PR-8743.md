# Run cached-logits distillation on the model's process groups

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8743) · state: closed · merged: False

## Original PR description

**Why.** Offline logits distillation (`megatron/training/distillation/`) reads its TP, CP and DP ranks and groups from the global `parallel_state`: the logits saver, the cached-logits KD loss, the KD-loss TP all-reduce and the remote shard-listing broadcast over TP×DP×CP. If the model's collection is laid out differently from the global grid, shards are named and resharded by the wrong DP ranks. The vocab-parallel top-K and KL reductions also combine ranks that do not hold the other vocabulary shards.

**What.**
- `LogitsSaverHooks` and `CachedLogitsKDLoss` take `pg_collection` and use its `tp`, `cp`, `dp_gtp_remat` and `tp_dp_cp` groups. A collection that does not set one of them raises `ValueError`.
- Training passes the collection of the chunk the saver hooks attach to. `LossFuncCallable` builds the KD loss on the collection of the model it receives and all-reduces over that collection's TP group.
- The remote listing helpers, `make_teacher_tar_dataset` and the teacher datasets take `tp_dp_cp_group`.
- Omitting the collection or the group keeps the global groups.

**Tests.** New `tests/unit_tests/training/distillation/test_distillation_process_groups.py` builds a grid unlike the global one and makes every global accessor raise. On that grid it checks:
- the saver's top-K and its remote listing;
- the KD loss value;
- the loader's DP and CP inputs;
- the remote listing and metadata broadcast of the v1 and v2 loaders.

It also checks that omitting the collection selects the global groups. The three `__init__` tests in `test_logits_saver_cu_seqlens.py` now pass a collection. On 4 GPUs against main: `test_distillation_process_groups.py` passes all 17 of its tests, which are new, and `test_logits_saver_cu_seqlens.py` passes 10 tests here vs 10 on main, with no regressions. Before the sync, this branch ran both files on 4 CPU ranks with Gloo: 15 passed and 1 skipped, and the 2 tests that compute on the model's TP group need CUDA. In the integration run, this PR's test files show no regressions against main. Known nits, not changed: that file's module docstring still says `__init__` needs an initialized `parallel_state`, and each new test that builds the strided grid creates about 2W+2 subgroups on W ranks without destroying them.

**Compatibility.** The new arguments default to the global groups, so direct callers keep working. On the standard grid every group is the same object as before. With distillation on, a custom collection without `tp`, `cp`, `dp_gtp_remat` or `tp_dp_cp` now raises `ValueError` instead of quietly using the global groups. `LossFuncCallable` needs the model to expose `pg_collection` through its wrappers, which every `LanguageModule` does.

Not covered here: the `mpu.is_pipeline_last_stage()` checks in `setup_model_and_optimizer` that decide where `LogitsSaverHooks` and `StudentLogitsCapture` attach still read the global grid. #8741 moves them onto the collection, and #8757 builds the saver on the same collection as that check.
