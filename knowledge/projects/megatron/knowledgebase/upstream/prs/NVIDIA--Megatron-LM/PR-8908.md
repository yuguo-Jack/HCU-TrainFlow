# Warn on global process-group fallbacks in core helpers and config logging

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8908) · state: open · merged: False

## Original PR description

This unit stops several Megatron Core helpers from silently filling an omitted process group from the global `parallel_state` grid. Each such fallback now goes through `resolve_process_groups` and emits a `ProcessGroupFallbackWarning`. The config logger gets the optimizers' and Megatron-FSDP wrappers' collections, so `--config-logger-dir` does not warn in stock training. Callers that run a model on its own grid, such as MIMO modules, RL inference models or a second model in the job, are affected. So are maintainers of the logging, RoPE, multimodal, MoE, FP8/FP4, CUDA-graph, optimizer and Megatron-FSDP code. The unit consolidates 2 draft PRs unchanged, one commit per member, so review it commit by commit. A final commit regenerates `tools/process_group_usage_allowlist.json`. It builds on #6303, #8890 (core process-group APIs: #8017, #8049), #8893 (FP8/FP4 amax group, CUDA graphs, 1F1B: #8032, #8035), #8899 (MoE plumbing: #8053), #8889 (optimizer plumbing: #8042, #8045), #8895 (training loop and strict mode: #8047) and #8903 (optimizer warnings: #8752). It lands after #8897 and #8898, which give MLA, DSA, CSA and GDN their collection for the Transformer Engine linears (#8748) and the combined 1F1B delayed-FP8 context its collection (#8739); without them, stock training would warn.

## Members

- #8755: Warn on silent global process-group fallbacks in core helpers. `log_on_each_pipeline_stage`, `check_param_hashes_across_dp_replicas`, packed-sequence `apply_rotary_pos_emb`, the multimodal CP gather, MIMO `PartitionConfig.from_mp_config`, batch-invariant `unpermute`, `get_fp8_context`, `get_fp4_context`, the TE per-module recipe autocast, `CudaGraphManager`, `TECudaGraphHelper` and `log_config_to_disk` warn when a group is omitted and still select the same groups on the standard grid; `GPTModel`, `BertModel`, `HybridModel`, LLaVA, `T5LMHead`, the vision encoders and `DistributedDataParallel` pass their collection to `log_config_to_disk`.
- #8763: Pass the optimizers' process groups to the config logger. `MixedPrecisionOptimizer`, `FP32Optimizer`, `DistributedOptimizer` and `FullyShardedOptimizer` take an optional keyword-only `pg_collection`, `get_megatron_optimizer` passes it, and both Megatron-FSDP wrappers pass theirs to `log_config_to_disk`.

## Behavior changes for callers

- On the standard grid the groups and ranks are unchanged, so numerics, checkpoints and config-dump names do not change.
- Without a global grid, packed-sequence RoPE, the multimodal gather, MIMO `from_mp_config` and `unpermute` (with `torch.distributed` initialized) raise a `ValueError` that names the argument. Before, they asserted or continued with a `None` group.
- FP8/FP4 contexts without an amax group still let Transformer Engine reduce over WORLD, now with a warning.
- Unpacked RoPE no longer needs a global grid.
- The log filter and `unpermute` read the groups, so `set_tensor_model_parallel_rank`, `set_data_parallel_rank` and `set_expert_model_parallel_world_size` no longer affect them. Callers that set the EP size through the override pass `ep_size` instead.
- `log_config_to_disk` takes a keyword-only `pg_collection` and falls back with a warning when the collection lacks one of its six groups.
- The private `_get_fp8_autocast_for_quant_recipe` and `_get_fp8_autocast_for_quant_params` require a keyword-only `owner`. Out-of-tree callers get a `TypeError`.
- Needs `determinism-exempt`: in the registered kernel files `fp8_utils.py`, `fp4_utils.py`, `batch_invariant.py`, `optimizer/__init__.py` and `optimizer/optimizer.py`, only the source of the groups and of `ep_size` changes.
