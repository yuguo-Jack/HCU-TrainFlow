# Enforce process-group checks in CI, functional tests and review rules

## Original PR description

Depends on #7991, #8730, #8768 and #8772. Please review the diff from their merge: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/9cd6192092...yx/pstate-h1-checks).
- #8772 moves the last two unwarned core reads behind their warnings, so the new tree-wide test passes with an empty `UNWARNED_READS`. Through #8772, this branch contains #8770, which adds the warned and unwarned classification and the guard extensions this PR builds on, and #8766, #8765, #8767, #8747, #8762, #8031, #8049 and #8055.
- #7991 writes the deprecation guide, `docs/developer/parallel-state-deprecation.md`, that this PR edits.
- The stricter guard accepts the silenced bootstrap block in `megatron/training/initialize.py` only in the form #8768 gives it. Without #8768, the guard's in-tree test fails.
- The docs and the review rules cite `test_global_memory_buffer_imports.py` from #8730.
- The converter test calls `parallel_state.get_registered_process_groups()` from #8747 and `model_parallel_cuda_manual_seed(pg_collection=...)` from #8031, and fails at run time without them.
- The merge of #8768 keeps #7991's deprecation paragraph in the Gloo accessor docstrings of `parallel_state.py`. The other merges are clean.

This PR takes over #8774, which ran the checkpoint-converter functional test on its registered groups, and #8776, which aligned the agent and review rules with these checks.

**Why.**
- Nothing that blocks a merge caught a new unwarned read of the global grid in Megatron Core. The ratchet step is report-only until #6307 decides on new fallbacks, `TestAllowlist` checks only the allowlist file, and calls from Megatron Core never emit `ParallelStateDeprecationWarning`, so strict mode stays silent too.
- The checker resolved only calls made through imports. An assigned module alias (`grid = parallel_state`), `getattr()` with a constant name, a reference that is not called, a module looked up through `importlib` or `sys.modules`, and any use of `parallel_state`'s private globals all passed it.
- The guard for code outside Megatron Core accepted any `catch_warnings()` block that ignores `ParallelStateDeprecationWarning` as bootstrap code, so a read wrapped that way passed silently. It never looked at private attributes, which bypass the deprecation warning altogether. It skipped all of `tests/`, functional tests included.
- The checker tests, the guard and the removal-version test read the source as text. Testmon never maps a source change to them, so a selective unit-test run skips them.
- The functional checkpoint-converter test (`tests/functional_tests/test_cases/common/ckpt_converter`) read the global grid through 11 deprecated `parallel_state` calls. It also called `get_model`, `get_forward_backward_func`, the pipeline schedule, the RNG seeding and the tensor-parallel gather without process groups, so each of them fell back to the global grid. Since #7516 its save fails with a `TypeError`, on main too, because it passes `num_floating_point_operations_so_far=None`. The recipe runs the test only in its broken scopes, so nothing noticed.
- The process-group section of `AGENTS.md` (which `CLAUDE.md` links to) predates the deprecation of the `parallel_state` accessors. It allows "migration fallbacks with an explicit comment" and says not to apply the rules to `megatron/training`. The pr-review rubric carries its own copy of that text, and `docs/developer/contribute.md` calls the process-group job report-only. An agent or reviewer following them would add or pass a commented, silent read of the global grid, skip the training code and functional tests that the guard covers, accept a silent `catch_warnings()` block or a private write that CI rejects, and assume that nothing blocks an unwarned core read.

**What.** The first six commits tighten the checker and the guard.
- The checker (`tools/check_process_group_usage.py`) counts every reference to a counted function, called or not. It follows:
  - assigned aliases within its scoped bindings, including names declared `global` or `nonlocal`, walrus targets in comprehensions, either side of a conditional expression and the operands of `and` and `or`;
  - `self`, `cls` and class-attribute aliases, as the guard does;
  - `getattr()`, `setattr()` and `delattr()` with a constant name;
  - `importlib.import_module()` with a positional or keyword name, and relative names with their package;
  - `sys.modules` lookups and star imports, `megatron.core`'s included.
- A new `private` kind counts reads, writes and deletions of `parallel_state`'s private attributes. They are never warned. The deprecated `_set_global_memory_buffer()` stays a deprecated function. Each alias binding is resolved once per pass, so long reassignment chains cannot stall CI.
- The tree has none of the new forms. The per-line results over `megatron/core` are identical to the previous checker's, and the allowlist does not change.
- The guard (`tests/unit_tests/test_parallel_state_accessor_uses.py`) flags every use of a private `parallel_state` attribute, including through `setattr()` and `delattr()`, and follows the same new alias and lookup forms.
- The guard accepts a silenced block only after the code has warned on its own: a statement that is only a call of `warnings.warn(..., ParallelStateDeprecationWarning)` or `warn_global_process_group_fallback()`, before the `with`, in the block that holds it or in a block that contains that block. Only a spelling of `warnings.warn` that the file's imports bind counts, and the category name must match exactly, so `logger.warn()` does not. The lazy initialization in `megatron/training/initialize.py` is the only such block in the tree.
- New `TestTree` in `test_check_process_group_usage.py` runs the checker's classification over `megatron/core`. It fails on a counted read that is neither warned nor guarded, apart from the reads in `UNWARNED_READS` (none now), and on any private use. It also reports stale `UNWARNED_READS` entries, including those of a moved or deleted file. It runs in the blocking "Test the process-group usage checker" step and in the unit-test bucket.
- `tests/unit_tests/testmon_mandatory_tests.yaml` maps the folders these three tests scan, and each top-level script, to the three test files, for the H100 buckets. A new test in `tests/test_utils/test_unit_testmon_mandatory.py` checks that the mapping covers every scanned folder and top-level script.
- The guide, `docs/api-backwards-compatibility-check.md` and the workflow comments describe the new failures, the private reads, and the exact bootstrap rule. The guide's guard paragraph is the reference statement of that rule: which filter forms the guard accepts (`simplefilter` or `filterwarnings` with `"ignore"` and the category, in the block's body), which it flags (`catch_warnings(action=..., category=...)`, a blanket ignore, an ignore of `FutureWarning`), and that a function or lambda defined in the block gets no cover. The docs also say that `test_global_memory_buffer_imports.py` rejects memory-buffer aliases from `parallel_state`, fallback or not.

The next four commits move the checkpoint-converter functional test onto its registered groups.
- One commit saves with `num_floating_point_operations_so_far=0`, the count a run starts from. It is independent of the rest and applies to main on its own. Would maintainers rather take it as a separate PR?
- Each pipeline keeps the collection that `initialize_model_parallel()` registers for its grid, read with `parallel_state.get_registered_process_groups()`, and passes it or its groups to every call that needs them:
  - ranks and stages from `pg.tp`, `pg.pp`, `is_pp_first_stage()` and `is_pp_last_stage()`, and the first rank of `pg.tp` as the broadcast source;
  - `get_model(pg_collection=...)` and `model_parallel_cuda_manual_seed(123, pg_collection=...)`;
  - `get_forward_backward_func(pp_size=pg.pp.size(), vp_size=None)`, and the schedule with `pg_collection` and a `P2PCommunicator` on `pg.pp`;
  - the embedding all-reduce over `pg.embd`, and `gather_from_tensor_model_parallel_region(group=pg.tp)`.

  The ranks, stage checks, broadcast source, RNG seeds and the order of the collectives stay the same. The helpers that read the groups become instance methods.
- The guard also scans `tests/functional_tests`. Functional tests run Megatron end to end like the entry points the guard already covers, and only the unit tests use the global grid on purpose. The comment above `SCANNED_FOLDERS` names every folder the guard skips and why. `tests/functional_tests` joins the Testmon mandatory mapping, so a change there selects the `parallel_state` source checks in a selective unit run.
- The guide lists `tests/functional_tests/` among the guarded folders. The guard docstring and `docs/api-backwards-compatibility-check.md` say that the unit tests, not all tests, are skipped.

The last four commits align the agent and review rules. They change docs and agent guidance only.
- `AGENTS.md` states the current rules:
  - Code takes its groups from the owning model's collection or an explicit group from its caller. New code requires its groups.
  - What is deprecated, in which releases, and what is not: bootstrap, teardown and the registry stay.
  - Compatibility fallbacks go only through the warned helpers, dated 0.21 and 0.23 by default. A comment does not make a read a fallback.
  - What the checker counts and allows in `megatron/core`, and that its tests fail CI on a read that is neither warned nor guarded.
  - What the guard covers outside `megatron/core` (the rest of `megatron/`, `examples/`, `tools/`, `tasks/`, `scripts/`, `docs/`, `tests/functional_tests/` and the top-level scripts) and what it allows.
  - What the pytest filters turn into errors, how to find fallbacks with strict mode, and what reviewers flag.
- `skills/pr-review/references/light.md` and `strict.md` state the same rules. The strict rubric gives 0.21 and 0.23 as defaults: a fallback that first warns in a later release passes its own dates and is not a finding for them.
- The guide's "Reviewing?" paragraph no longer lists bootstrap code and warned fallbacks as allowed in `megatron/core`, and covers the code outside it.
- `docs/developer/contribute.md` says which reads in `megatron/core` fail the process-group job. Only its allowlist ratchet is report-only now.
- Every text states the rules the same way and points to the guide's guard paragraph for the details:
  - the bootstrap rule: a statement that is only a call of `warnings.warn(..., ParallelStateDeprecationWarning)` or `warn_global_process_group_fallback()` comes before the `with`, in the block that holds it or in a block that contains that block;
  - the filter the guard accepts: a body call of `warnings.simplefilter("ignore", ParallelStateDeprecationWarning)` or the matching `filterwarnings()`;
  - private `parallel_state` attributes are never allowed. The memory buffer comes from `megatron.core.utils`, since `test_global_memory_buffer_imports.py` rejects its aliases from `parallel_state` even in a fallback;
  - only the unit tests may use the global grid.
