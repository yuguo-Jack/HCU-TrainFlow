# [Inference][SSM] Apply the per-channel D skip term in Mamba decode when D_has_hdim

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8569) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Fixes Mamba decode, which applied the wrong `D` skip term when the mixer is built with `D_has_hdim=True`.

**Bug.** With `D_has_hdim=True`, `MambaMixer.D` has one coefficient per channel, shape `(nheads * headdim,)`. Training, prefill and the batch-invariant decoder reshape it to `(nheads, headdim)`. `ssm_decode` instead built `D = repeat(self.D, "h -> h p", p=headdim)`. For a per-channel `D`, that gives a `(nheads * headdim, headdim)` view with strides `(1, 0)`. `selective_state_update` reads `D` only through its strides, so every channel of head `h` got `D[h]` instead of `D[h * headdim + p]`.

No error is raised. Prefill is correct and the SSM states are correct, but every decode step returns a wrong output. On H100 the max abs error against a per-channel reference was 2.53. All non-batch-invariant decode is affected: dynamic, static and speculative verification. The default all-ones `D` hides the bug, so it only shows up once `D` is trained or loaded from a checkpoint. No in-tree config sets `D_has_hdim`; it is reached through a custom layer spec's `params`.

**Fix.**
- New `MambaMixer.get_ssm_D(D, per_channel=False)` puts `D` in the layout the SSM kernels take:
  - `(nheads, headdim)` when `D_has_hdim`;
  - otherwise `(nheads,)`, or a stride-0 `(nheads, headdim)` broadcast when `per_channel=True`.
- Every `D` site now uses it: training, static and dynamic prefill, the Triton decode step, the native-PyTorch decode fallback and `MambaBatchInvariantDecode`. Decode can no longer drift from prefill.
  - The Triton decode step therefore now passes the per-channel `D`. The per-head case is unchanged.
  - The fallback is unreachable today, because the in-tree `selective_state_update` is always imported. It used to raise a shape error for `D_has_hdim`.
  - The batch-invariant decoder was already correct.
- `selective_state_update` now asserts that `D` has shape `(nheads, dim)`, so a mis-shaped `D` fails loudly instead of being read through its strides. This is a host-side shape check.
- No allocations, host syncs or kernel launches are added, and decode stays CUDA-graph safe.

**Tests.**
- `tests/unit_tests/ssm/test_mamba_mixer.py::TestMambaMixerDecode::test_decode_matches_reference` builds a real `MambaMixer` (TP=1, fp32, `rmsnorm=False`) and checks `ssm_decode` against a float64 Mamba-2 recurrence at `atol=rtol=1e-4`. It checks the outputs, the whole conv/SSM state pool and, when speculative, the per-token state snapshots.
  - The `D` cases are `per_head_D` (control), `per_channel_uniform_D` (control: `D_has_hdim` with a constant `D`, where every indexing agrees) and `per_channel_D` (random per-channel `D`).
  - Each runs in three decode modes:
    - `batch_order`: one token, no slot map, as static batching calls it;
    - `slot_map`: one token through `batch_indices`, as dynamic batching does;
    - `speculative`: 3 tokens per request through `batch_indices`, with intermediate states, as speculative verification does.
  - The `per_channel_D` cases fail on `main` and pass with this PR.
- `tests/unit_tests/ssm/ops/mamba2/test_selective_state_update.py::TestSelectiveStateUpdateShapeChecks` is CPU-only. It checks that a broadcast per-head `D` and a flat per-channel `D` are both rejected.
- `tests/unit_tests/ssm/ops/mamba2/test_batch_invariant_decode.py::TestBatchInvariantDecodeBufferedScan::test_mixer_adapter_per_channel_D_matches_full_scan` checks that `MambaBatchInvariantDecode` decodes a per-channel `D` bitwise like the full chunk scan.
- `tests/unit_tests/determinism/kernels/test_ssm_kernels.py::test_selective_state_update_replays` also replays the kernel with a contiguous per-channel `D`, at a small batch.

**H100 results** (CI image, first commit):
- The new decode test passes with this PR: 5/5 regression cases, i.e. 3 mixer cases plus 2 replay cases. On `main`, only `test_decode_matches_reference[per_channel_D]` fails.
- Neighbor tests pass:
  - `TestMambaMixer`: 10 passed;
  - `test_dynamic_engine.py::TestDynamicInferenceEngine::test_speculative_decoding_mamba_hybrid`: 3 passed;
  - `test_dynamic_engine.py::TestDynamicInferenceEngine::test_mamba_chunked_prefill`: 2 passed.

On H100 in the CI image (rerun at this PR's head), the regression tests pass (14/14) and 6 fail on `main`. The neighbor tests pass.
