## What does this PR do?

Mixed-precision modules can have BF16 weights ready for both phases while MXFP8 weights are ready only for forward. Track readiness in each `FsdpParameterGroup`, alongside its buffers, so each group reuses its existing events independently. This removes the module's readiness-set intersection and the return value from `unshard_parameters()`.

BF16 and replicated weights share one event for forward and backward. Sharded MXFP8 records independent events for newly gathered rowwise and columnwise planes. Releasing storage invalidates the corresponding event. The module retains ownership of stream scheduling, compute waits, and prefetch.

For sharded compute weights, the original forward gathers its weights and releases them afterward. The remaining lifecycle is:

| Checkpointing | BF16 | MXFP8 |
| --- | --- | --- |
| None | Gather for backward; release afterward | Gather columnwise for backward; release afterward |
| Reentrant | Gather for recomputation; keep through backward | Gather rowwise for recomputation; release rowwise; gather columnwise for backward |
| Non-reentrant | Gather for backward; reuse during recomputation | Gather columnwise for backward; add rowwise for recomputation; release only rowwise afterward |

Prefetch may gather columnwise before recomputation even in reentrant mode. Recomputed post-forward releases gathered MXFP8 rowwise planes while preserving columnwise readiness and keeping BF16 weights. The module waits once for compute before releasing selected groups; an empty selection adds no wait.

`_unsharded_model_weight` aliases persistent `model_weight` for replicated weights and owns temporary gathered storage for sharded weights. Installation always uses this field. Replicated weights skip gathering and storage release, while full reshard clears readiness so the next unshard refreshes Parameter data and padded MXFP8 scales.

The preparation methods have separate responsibilities: `unshard_parameters()` chooses the work and records readiness; `_allgather_model_weight()` allocates and gathers; `_install_unsharded_parameters()` updates `FsdpParameter.unsharded`; `_switch_to_unsharded_parameters()` installs those Parameter objects on their owning modules.

## Validation

- Existing two-rank parameter, training, checkpointing, CUDA-graph, quantization, and quantized-buffer test selection: **47 passed, 32 skipped**. Skips require four ranks or Blackwell hardware.
- Temporary two-GPU lifecycle probe: **28 cases passed**, covering BF16, MXFP8, mixed groups, both recomputation orders, prefetch, both-phase requests, event reuse, storage release, and replicated MXFP8 scale refresh. Uses real CUDA buffers and collectives, without MXFP8 quantization or GEMMs.
- With TE imports disabled: **six cases passed** (replicated/sharded BF16 × no/reentrant/non-reentrant checkpointing), with exact loss, gradient, and final-weight agreement across checkpoint modes. Covers the `QuantizedDBuffer = DBuffer` fallback.
- Required `tools/autoformat.sh` check passed. Its non-blocking mypy step reports the existing `FsdpModule.register_load_state_dict_pre_hook` typing error.

Additional stream scopes and per-group events/waits add control-path overhead. A two-rank A6000 microbenchmark of gather + backward reuse + release, with 64x64 BF16 weights and no model compute, measured median times of 122.5 us before / 150.2 us after for one group and 178.9 us before / 229.0 us after for two groups (seven batches of 200 cycles). These are not end-to-end training measurements. Blackwell numerical and model-scale performance validation remain outstanding.

Existing tests are unchanged; temporary probes and benchmarks are not added to the repository.

[P2] Exclude the no-TE DBuffer alias from this predicate

**Failure:** Without Transformer Engine, the [import fallback](https://github.com/NVIDIA/Megatron-LM/blob/dcb296a813c27a24c34499c5fa6da0bdb267eb45/megatron/core/distributed/fsdp/src/megatron_fsdp/experimental/parameter_group.py#L38-L45) aliases `QuantizedDBuffer = DBuffer`. Consequently, `isinstance(buffer, QuantizedDBuffer)` is true for ordinary weights, and this line accesses the nonexistent `DBuffer.is_rowwise_allocated` attribute. A minimal trigger is a CUDA BF16 `nn.Linear(4, 4, bias=False)`, wrapped with `Placements([0], [Replicate()], [Shard(0)], [Shard(0)])`, called through reentrant activation checkpointing with an input requiring gradients. The recomputed [post-forward cleanup](https://github.com/NVIDIA/Megatron-LM/blob/dcb296a813c27a24c34499c5fa6da0bdb267eb45/megatron/core/distributed/fsdp/src/megatron_fsdp/experimental/module.py#L367-L374) raises `AttributeError` instead of completing backward. The [base predicate](https://github.com/NVIDIA/Megatron-LM/blob/9ef1a71d6e8a089afff1988fb7f87fe9a675722f/megatron/core/distributed/fsdp/src/megatron_fsdp/experimental/parameter_group.py#L450-L455) short-circuited for these replicated weights.

**Correction:** Gate the check with the existing `HAVE_TE` flag so ordinary buffers never qualify for rowwise-only release. Suggested replacement, to verify before adopting:

```suggestion
        return HAVE_TE and isinstance(buffer, QuantizedDBuffer) and buffer.is_rowwise_allocated
```

**Preservation:** The predicate must remain false for ordinary BF16 buffers, true for sharded MXFP8 with gathered rowwise planes, and false for columnwise-only sharded MXFP8 and replicated MXFP8 whose transient gather buffer stays released. BF16 and persistent replicated compute weights must remain available through recomputation/backward.

**Acceptance — proposed, not run:** In a TE-free environment, run the replicated BF16 checkpoint example above; backward must complete, exposed parameters must return to DTensors, and this predicate must be false. Also check the ordinary sharded BF16 predicate. Retain the exact loss, gradient, and final-weight equality assertions for both checkpoint modes and all placements in the [MXFP8 recomputation test](https://github.com/NVIDIA/Megatron-LM/blob/dcb296a813c27a24c34499c5fa6da0bdb267eb45/tests/unit_tests/distributed/mfsdp_v2/test_quantization.py#L273-L331), plus the forward `(True, False)`, backward `(False, True)`, and final `(False, False)` allocation checks in the [plane-lifecycle test](https://github.com/NVIDIA/Megatron-LM/blob/dcb296a813c27a24c34499c5fa6da0bdb267eb45/tests/unit_tests/distributed/mfsdp_v2/test_quantization.py#L208-L270).
