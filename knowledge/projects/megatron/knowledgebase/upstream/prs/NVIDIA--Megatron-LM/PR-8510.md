## Phase 3 — CI fix commit `b24bdac31`

All nine non-exempt failures from the first CI cycle are addressed by one rolling fix
commit on top of the immutable merge commit `a1be423e3` (2-commit policy preserved).

### Merge accidents — dev-only hardening restored

Main never removed these lines; the merge dropped them because main happened to own
nearby lines. Restored verbatim from `origin/dev`.

| File | What was dropped | Detected by |
|---|---|---|
| `pretrain_gpt.py`, `pretrain_hybrid.py` | Dev's narrowed ModelOpt import guard. The merge took main's bare `except ImportError:`, which silently disables ModelOpt when an **internal** `megatron.post_training` import fails. Dev inspects `error.name` and re-raises anything that is not `modelopt`/`modelopt.*`. | `post_training/test_modelopt_import_guard.py::test_modelopt_import_guards_only_suppress_missing_modelopt` (`assert None == 'error'`) |

`megatron/elastification/pretrain_hybrid_flex.py` was checked for the same pattern: it
carries the bare `except ImportError:` on **both** dev and main, so it is not an accident
and was left alone.

### Duplicate test-recipe entry

`tests/test_utils/recipes/gb200/unit-tests.yaml` contained the
`ssm/test_gated_delta_net.py` product block twice. The GB200 dispatcher therefore emitted
two jobs for one bucket — the second resolving to `0 workloads` — and the duplication also
violated the one-bucket-per-file scope contract. Removing the duplicate fixes three
failures at once:

- `Unit tests (GB200) / tests/unit_tests/ssm/test_gated_delta_net.py` (both instances)
- `Unit tests (H100) / tests/unit_tests/**/*.py` →
  `test_unit_test_scope_contracts.py::test_every_unit_file_has_exactly_one_platform_bucket[gb200]`

An audit across every recipe YAML found this as the only duplicate.

### Cross-side API reconciliation

**`megatron/core/transformer/transformer_config.py` — DSv4 + dynamic CP.**
Main added an unconditional `raise ValueError("DSv4 dynamic context parallelism is not
supported yet.")`. Dev has since implemented that combination for the balanced zigzag
indexer: dev's own `dsa_cp_balance_indexer` precondition, a few hundred lines above in the
same merged file, explicitly accepts `dynamic_context_parallel=True` as a valid CP
activation. The merged tree ended up carrying two contradictory tests:

- `test_dsv4_hybrid_attention.py::test_config_rejects_dynamic_context_parallel` (main-only) — expects the raise
- `test_cp_balanced_indexer_layout.py::test_balanced_config_accepts_dynamic_context_parallelism` (dev-only) — expects acceptance

The guard is now scoped with `and not self.dsa_cp_balance_indexer`. Since
`dsa_cp_balance_indexer` defaults to `False` and main's test does not set it, main's
rejection still fires for the configurations it was written for, while dev's balanced path
is preserved. Both tests pass. Dev's test file was authored by the dev commits
`6e8ff3ecd` ("Preserve dev DSv4 execution and Muon split-QKV semantics") and `bd23668a4`
("fix: reconcile sync runtime and unit-test integration") — i.e. dev's position here was
established deliberately to survive main syncs.

**`megatron/core/utils.py` — `cp_group is None` fallback.**
Dev's `get_batch_on_this_cp_rank` resolves a missing `cp_group` from `parallel_state`;
main has no fallback and lets `None` reach `torch.distributed.get_world_size(None)` (the
default group). Keeping dev's fallback made main's new
`data/test_batch_api_compat.py` assert, because it calls the helper with no `cp_group` and
no CP initialization. The fallback now probes with `check_initialized=False`, which keeps
it useful once CP is initialized and matches main's behaviour when it is not. All 8
production callers pass `cp_group` explicitly, so this path is only reached by the
compat API.

or filing DCO remediation attestations on their behalf, which this bot will not do.
