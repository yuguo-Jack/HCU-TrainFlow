# fix(parallel_state): destroy created process groups and invalidate communicator caches on teardown

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7029) · state: open · merged: False

## Original PR description

`destroy_model_parallel()` cleared Megatron's globals but left every process group it had created registered in c10d, so each initialize/destroy cycle in one process leaked NCCL communicators and their device memory. This PR releases the resources owned by the ending lifetime, destroys the groups it created, and invalidates caches that could otherwise reuse destroyed groups. Continuation of #6902; closes #6897.

### Leak evidence and cost

Measured before the 2026-11-01 sync with main, on an internal GB200 node (4 GPUs, torch 2.13.0a0, TE 2.17). Each cycle runs `initialize_model_parallel(tensor_model_parallel_size=2, pipeline_model_parallel_size=2)`, one all-reduce on every created group with more than one rank, and `destroy_model_parallel()`. Ten cycles per build:

| After each `destroy_model_parallel()` | main | this PR |
|---|---|---|
| Process groups left in c10d (beyond WORLD) | +20 per cycle, 200 after 10 cycles | 0 |
| Device memory in use, relative to before the first cycle | +10,684 MiB per cycle, 104.4 GiB after 10 cycles | +20 MiB, flat |

| Time per cycle | main | this PR |
|---|---|---|
| `initialize_model_parallel()` | 7.3–8.0 s | 7.4–7.9 s |
| First collective on each group | 4.3–4.5 s | 4.3–4.5 s |
| `destroy_model_parallel()` | ≤ 0.02 s | 4.8–6.0 s |

Teardown now destroys the communicators it created, which takes several seconds for this 20-group layout. The probe creates no CUDA graphs or EP buffers, so this time is group destruction. Nothing runs per training iteration, so steady-state training is unaffected. The cost is paid once per `destroy_model_parallel()` call.

### A2A overlap tests share model parallelism

Teardown now releases the fused A2A buffers together with their process groups. Tests that initialize and destroy model parallelism around every case would therefore build a new HybridEP buffer for every HybridEP case. (On main, the first buffer outlived teardown and was reused on a leaked group.) `tests/unit_tests/a2a_overlap/conftest.py` adds a `shared_model_parallel` fixture. Consecutive tests that request the same layout share one model-parallel state. The fixture destroys that state when a test requests a different layout, after a test fails on any rank, and at the end of each module. Between tests, it still releases the NCCL EP context.

Run times, measured before the 2026-11-01 sync with main:

| `tests/unit_tests/a2a_overlap/` | main | this PR without the fixture | this PR |
|---|---|---|---|
| 4 GPUs, one node | 712 s | 2588 s | 524 s |
| 8 GPUs, two nodes | 741 s | not run | 573 s |

This PR is faster than main, because main also creates new communicators for every test and destroys all the leaked ones at exit. The A2A overlap CI bucket stays a single job.

### The ssm unit tests get a second H100 bucket

The H100 `tests/unit_tests/ssm/**/*.py` bucket already takes about 57 of its 60 minutes on main. Destroying the communicators a test used costs 0.1–0.5 s per communicator, about 1 s per test, so the bucket hit the job timeout with every test passing. Shutting the communicators down concurrently or aborting them doesn't make teardown meaningfully faster (0.5–0.8 s per test, measured on 4 GPUs).

`tests/unit_tests/ssm/test_kda.py`, about 20 minutes of that bucket, now runs in its own bucket. The change is in `tests/test_utils/recipes/h100/unit-tests.yaml`, so this PR also needs `@NVIDIA/ci`. No other bucket comes near its limit. `models/**/*.py` grows the most, from 22 to 29 minutes.

### Behavior changes for callers

- **Teardown is effectively collective.** Every member of each created group must call `destroy_model_parallel()` after its communication has finished. Graceful destruction of an NCCL group waits for its peers. It adds no WORLD rendezvous.
- **Raises inside an open Transformer Engine autocast**, before releasing anything, because the context's exit would reduce FP8 state over a destroyed group. A negative depth is accepted. It occurs when an in-process restart resets TE before the interrupted autocast unwinds.
- **Raises when a release fails.** If a registered release fails (for example, NCCL EP finalize), the remaining releases still run, because some of them rendezvous with peer ranks. The first error is then raised before any group is destroyed or module state is cleared. A resource that failed to release may still use its communicator, and graceful destruction could then wait forever. Previously, a failed NCCL EP finalize was ignored.
- **Objects from the ended lifetime become unusable.** This covers process groups and anything that holds them: `ProcessGroupCollection`s, models, and DTensor device meshes. The Kitchen SDPA tests built their groups at import time and now build them per test. The upcycling tests take a fresh collection.
- **`delete_cuda_graphs()` behaves as on main.** Since #8358 on main, it deletes the graphs of recorded runners (inference graphs and pending captures) and of every runner that started a capture since the last call, including the training graphs that `create_cudagraphs()` created. The inference engine's `suspend()`, which RL calls after each rollout, therefore also releases training graphs kept with `--rl-training-cuda-graphs`. Teardown uses the new `release_all_cuda_graphs()`, which also releases live runners that are neither recorded nor tracked as captured. A captured graph keeps the communicators of its collectives alive, and destroying such a communicator waits for the graph.
- **No abort mode.** `destroy_model_parallel()` still takes no arguments. A failure handler with outstanding collectives must abort its communicators before calling it, as nvrx's in-process restart does.
- **In-process restart.** `megatron/training/inprocess_restart.py` now re-raises an exception from `destroy_state()`. nvrx's `ThreadedFinalize` runs it on its own thread and ignores exceptions raised there, so the wrapper would otherwise restart on partially destroyed state. With the re-raise, nvrx terminates the rank.
- **HybridEP buffer rebuilds on a group change.** The HybridEP buffer is rebuilt when a dispatch passes a different group than the one it was built for. A model that alternates between two EP groups would rebuild it on every call.

### Design

- **Teardown registry.** `parallel_state` no longer imports or probes Transformer Engine, MoE, or CUDA-graph modules. The modules that cache group-bound resources register callbacks with `register_model_parallel_teardown(stage, callback)` when they are imported. `destroy_model_parallel()` runs the stages in this order:
  1. `VALIDATE`: the TE autocast check. It modifies nothing.
  2. `RELEASE_COMMUNICATION`: GTP registered memory pools, NCCL EP symm buffers, NCCL EP finalize, DeepEP/HybridEP buffers.
  3. `RELEASE_CUDA_GRAPHS`: layer runners, full-iteration graphs, optimizer graphs.
  4. `RESET_STATE`: GTP pending gradients, cached parameters/tickets and streams; TE FP8 global state.

  After the stages, it clears the DTensor caches and the module state, and destroys the groups last. Within a stage, callbacks run in reverse registration order, so a module releases its resources before the modules it imports release theirs. Callbacks are cheap and idempotent when there is nothing to release.
- **GTP resources.** Registered memory pools are released before their groups are destroyed. A pool whose group no longer exists is dropped without deregistration. That happens in in-process restart, where nvrx aborts and destroys every process group before Megatron's finalize runs. Pending gradient accumulation is discarded without launching collectives, and the ended lifetime's parameter registry, weight cache, streams and graph-pool references are cleared. This prevents a subsequent non-GTP model's gradient fence from trying to reduce an old GTP gradient over a destroyed group.
- **Groups.** It uses the existing `create_group()` registry, which records every group this rank is a member of, including `ranks=None`, and leaves WORLD alone. Groups are destroyed in reverse creation order. If one fails, the rest are still attempted, and the first error is raised.
- **DTensor.** DTensor's sharding cache compares meshes by layout, not by process-group identity, so a later lifetime with the same layout would reuse specs that name destroyed groups. The cache is cleared at teardown and again at initialization, because it is thread-local and nvrx's finalize runs on a different thread. From torch 2.10, the native dispatch cache is cleared as well.
- **Version checks.** API differences are selected with `is_torch_min_version` / `is_te_min_version` rather than attribute probing. The TE autocast depth lives in a different field before TE 2.9, from 2.9, and from 2.15.

- Connor-XY · comment · 2026-09-09T16:33:57Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/7029#discussion_r3970810243)

File: `megatron/core/distributed/fsdp/src/megatron_fsdp/uneven_dtensor.py` · line None

The file should not change at all, and I'm dropping it from the PR.

The `Could not resolve the process group registered under the name N` failure is not a checkpoint carrying an old mesh. The state dict being preprocessed is generated in the new lifetime from the destination model, yet its DTensors end up on the previous lifetime's DeviceMesh object. The source is DTensor's sharding-propagation cache. It memoizes the output spec of every op keyed by the input DTensorSpecs, and `DeviceMesh.__eq__`/`__hash__` compare rank layout, device type and dim names, not process-group names. Once `destroy_model_parallel` really destroys the groups, the next lifetime's mesh over the same ranks is a cache hit, and `param.detach()` inside `Module.state_dict()` returns a DTensor whose mesh still names the dead groups. On main this was invisible because the dead groups were leaked and still resolved.

Fix: clear that cache in `destroy_model_parallel` while the groups are still alive, next to the other cache resets in this commit. On this torch (2.12, C++ dispatch fast path) the Python `LocalLRUCache` is bypassed, so it also needs `torch._C._clear_DTensor_sharding_propagator_cache()`; clearing only the Python cache leaves the same 5 failures. With the reset and `uneven_dtensor.py` back at main, `test_gpt_hybrid_interop.py` is 39/39 (5 failed / 34 passed without it). The per-rank mesh rebuild from #6902 and my store-based rewrite both go away.
