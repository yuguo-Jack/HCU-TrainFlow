# What does this PR do?

Main counterpart of #6910.

Keep ordinary DSA sparse-attention backward shapes static when top-k contains
empty query rows, removing its dynamic `nonzero`/compact/gather/scatter path.

The generic path replaces each empty row with a safe one-tile cuDNN invocation:
its first index is zero, its effective top-k length is one, and its `dO`/`LSE`
are zeroed before backward. The returned `dQ` is explicitly zeroed for those
rows, so the safe tile contributes neither query nor KV gradients. A conservative
host-side certificate retains the existing allocation-free fast path when all
rows are provably nonempty.

This covers both the combined fused path and the split path used by IndexShare
and MTP sharing. It does not change CSA, THD/CP layout, MTP sharing semantics,
configuration, or the full-iteration CUDA Graph validator.

### Update (2026-10-26)

- Rebased onto current `main` (`e3f528380c`). The original commit is unchanged: its patch-id is the same as before the rebase.
- Added a second commit, `fix(dsa): do not certify non-empty top-k rows for KPool without tail selection`. This is the dev fix #8536 applied to this PR.
  - Why: `main` now has KPool selection (#7522). KPool without `dsa_indexer_kpool_always_select_tail` leaves the rows before a query's first complete pool with no key. The host-side certificate added here cannot see that, so it would skip the empty-row handling for exactly those rows.
  - The layer now certifies nothing in that mode.
  - A new CPU test (`test_dsa_topk_nonempty_certificate.py`) covers both tail settings. Its `no-tail` case fails without the fix.
- CPU, after the rebase: `test_dsa_native_parity.py` gives 67 passed, and `test_attention_variant_dsa.py` 53 passed. The remaining failures and errors (3 and 34) are identical on unmodified `main` and come from the CPU environment.
- `CHECK_ONLY=true BASE_REF=main tools/autoformat.sh` passes.
- The GPU results above predate the rebase and have not been re-run on it.
