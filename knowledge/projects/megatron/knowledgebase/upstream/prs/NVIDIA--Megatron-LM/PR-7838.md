# What does this PR do?

Skip an empty KV pull when decode reuses every prompt KV block, while still starting the independent SSM import.

:warning: For major changes (either in lines of code or in its impact), please make sure to first share a design doc with the team. If you're unsure what's the best way to do so, contact @NVIDIA/mcore-oncall.

`_try_start_kv_handoff_import()` currently submits `begin_pull_blocks()` even when the uncached KV suffix is empty. For the PP-metadata path reported in #7837, this can fail before `_start_ssm_handoff_import()` runs. Guarding the KV submission with `imported_blocks` leaves its handle as `None`; existing pending-handle collection already filters `None`, and SSM transfer startup is unchanged.

The regression covers no/partial/full prefix hits, with and without SSM, and flat/PP metadata. It checks continuation-block ownership and that nonempty suffix transfers still happen.
