# perf(moe): add opt-in torch grouped weight gradients for BF16 experts

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8118) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Add an opt-in SM90 BF16 grouped-linear path that uses PyTorch grouped matmul for MoE expert weight gradients while retaining TE grouped GEMM for forward and input gradients. The default remains the original TE implementation.

## Motivation

On the legacy, separately stored BF16 expert-weight path, grouped dW can launch one cuBLASLt GEMM per expert across internal streams. With 64 local experts, eager submission and gaps between these launches are material at short token counts. Computing the ragged-K weight gradients in a grouped operation reduces that overhead.

## Implementation

- Add `moe_use_torch_grouped_wgrad` to `TransformerConfig`; the standard argument factory exposes `--moe-use-torch-grouped-wgrad`.
- Keep the existing TE-owned parameters, expert-parallel attributes, state-dict keys and load hooks. There is no installed-TE patch or process-wide TE monkeypatch.
- Reuse packed activations and build int32 cumulative expert offsets in forward via pinned memory and a nonblocking H2D copy. Each autograd context owns its inputs and offsets.
- Call TE `general_grouped_gemm` for forward/dgrad and `torch.nn.functional.grouped_mm` (or `torch._grouped_mm` on PyTorch 2.9) for dW. Return per-expert views of the new gradient storage, without concatenating expert inputs or copying dW back to another allocation.
- Preserve the original TE path for unsupported dtype, layout, precision, offload, accumulation, distributed-weight and graph configurations.
- Add focused module tests, bit-exact replay tests, determinism-manifest coverage, a standalone benchmark, captured routing-shape fixtures, and documentation.

Enable through MCore:

```python
moe_grouped_gemm=True,
moe_use_torch_grouped_wgrad=True,
params_dtype=torch.bfloat16,
bf16=True,
add_bias_linear=False,
gradient_accumulation_fusion=False,
```

## Single-module performance

One SM90 GPU (132 SMs, approximately 80 GiB), BF16, 64 local experts, `CUDA_DEVICE_MAX_CONNECTIONS=1`, and `NVTE_USE_CUTLASS_GROUPED_GEMM=1` in both arms. FC1 weights are [64, 1024, 2048], FC2 weights are [64, 2048, 512].

The checked-in 80 shapes use actual expert-token counts captured at rank 0 / microbatch 0 from a Qwen3.5-35B-A3B text workload at TP1/PP2/CP4/EP4. Tensor values and weights are newly generated BF16 random values. **The 8K/32K labels describe the source global sequence length; these are isolated module measurements, not distributed training timings.**

Each shape uses five warmup calls per arm followed by ABBA/BAAB ordering, six samples per arm/metric and five calls per sample. The table is the median of per-shape medians over 20 routing distributions. CUDA-event intervals include eager submission gaps, rather than summing kernel active time.

| Global sequence | FC | Metric | TE (ms) | Torch dW (ms) | Speedup |
|---:|---|---|---:|---:|---:|
| 8,192 | FC1 | dW | 0.638 | 0.210 | 3.041x |
| 8,192 | FC1 | Module F+B | 2.346 | 1.534 | 1.529x |
| 8,192 | FC2 | dW | 0.638 | 0.124 | 5.144x |
| 8,192 | FC2 | Module F+B | 2.336 | 1.519 | 1.538x |
| 32,768 | FC1 | dW | 0.666 | 0.502 | 1.327x |
| 32,768 | FC1 | Module F+B | 2.339 | 1.645 | 1.422x |
| 32,768 | FC2 | dW | 0.649 | 0.303 | 2.144x |
| 32,768 | FC2 | Module F+B | 2.348 | 1.547 | 1.518x |

- **dW:** packed X/dY and offsets already exist; both paths allocate new BF16 output.
- **Module F+B:** one GroupedLinear forward, dgrad, dW and common gradient clearing; includes the candidate's forward metadata transfer. No SwiGLU, routing, communication, activation recomputation or optimizer update.
- The supported path bypasses the generic quantized TE autograd wrapper, so module-level gains include wrapper overhead as well as dW dispatch. They must not be attributed solely to a faster GEMM kernel.

Benchmark reproduction (no model checkpoint required):

```bash
PYTHONPATH=. CUDA_DEVICE_MAX_CONNECTIONS=1 NVTE_USE_CUTLASS_GROUPED_GEMM=1 \
  torchrun --standalone --nproc-per-node=1 tools/benchmark_torch_grouped_wgrad.py \
  --shapes tests/unit_tests/transformer/moe/data/torch_grouped_wgrad_shapes.jsonl \
  --output /tmp/torch-grouped-wgrad-benchmark
```

See `docs/developer/torch_grouped_wgrad.md` and the adjacent CSV for the scope and results.

## Limitations

- Eager SM90 BF16, separately stored expert parameters, expert TP/GTP size one, and ordinary autograd gradient accumulation.
- Bias, FP8/FP4, quantization recipes, FP16 autocast, TE debugging, fused main-grad accumulation, delayed wgrad, CPU/activation offload, FSDP, grouped parameters and CUDA graphs retain the original TE path.
- The native TE GroupedTensor/op-fuser path is an alternative and was not benchmarked here; this proposal targets the legacy BF16 expert path.
- No new distributed communication or DeepGEMM integration. No full-model throughput, optimizer-update or convergence claim.
