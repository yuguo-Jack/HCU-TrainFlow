# Fix PP CUDA graph capture and grouped hybrid paged-stash discovery

## What does this PR do?

Stacked on #4944. Review this PR against that parent.

Fixes pipeline-parallel full-iteration CUDA graph capture and paged-stash discovery for grouped HybridModel layers:

- Skip `torch.cuda.synchronize()` during batched P2P CUDA graph capture while retaining the communication request waits. The normal non-capture synchronization behavior is unchanged.
- Reject tensor/non-tensor input transitions, including `None` to tensor and tensor to `None`, with an actionable error. A captured graph cannot consume a newly introduced optional tensor; valid updates retain the original static tensor storage.
- Descend through grouped `HybridStack` layers when collecting paged-stash MoE layers, for both decoder and MTP paths.

Grouped HybridStack EP-overlap CUDA graphs remain unsupported: the schedule-plan guard from #4942 is retained. Grouped paged-stash discovery also applies with CUDA graphs disabled. This PR does not enable grouped EP-overlap graph capture.
