# (feat) add cpu-init support for MoE layers

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7011) · state: open · merged: False

## Original PR description

This PR makes CPU initialization of MoE experts independent of the expert-parallel layout. Currently, EP=4 with eight experts produces only two distinct initial expert weights because each EP rank draws from the same CPU RNG stream.

The change introduces per-global-expert CPU RNG streams, preserves distinct draws for FC1 and FC2, and prevents expert initialization from advancing the shared RNG differently across layouts. TE grouped and duplicated linear layers initialize full logical weights before applying ETP/GTP sharding.

Validation:

- 51 targeted tests passed on four GB300 GPUs using PyTorch 26.07 and TE 2.19.
- Coverage includes grouped/sequential experts, EP/ETP/GTP layout invariance, BF16/MXFP8 initialization, and RNG restoration.
- Reproduced duplicate experts on latest main in both expert implementations.
- Formatting and Ruff checks passed.

CPU initialization with moe_single_grouped_weight=True remains explicitly unsupported. Full CI validation with the current container remains pending.

### [P2] Preserve gate/up pairing when CPU-sharding grouped FC1

The new [grouped CPU initializer](https://github.com/NVIDIA/Megatron-LM/blob/5f438f645bdf1d89e49335d912566b1a4f5e8d7a/megatron/core/extensions/transformer_engine.py#L2882-L2906) always uses `stride=1`. With `gated_linear_unit=True`, no GLU interleaving, and ETP=2, this gives rank 0 the first contiguous half of FC1—only gate rows—and rank 1 only up rows. Each rank nevertheless [splits its local activation into gate/up halves](https://github.com/NVIDIA/Megatron-LM/blob/5f438f645bdf1d89e49335d912566b1a4f5e8d7a/megatron/core/transformer/moe/experts.py#L1172-L1179). Consequently, the same seed initializes a different logical expert at ETP=1 versus ETP=2. For a logical FC1 `[G0,G1,U0,U1]`, the expected local weights are `[G0,U0]` and `[G1,U1]`, not `[G0,G1]` and `[U0,U1]`.

**Correction:** In `TEGroupedLinear.__init__`, select stride 2 only for non-interleaved gated column weights, and keep the CPU parameter's partition metadata consistent. Suggested patch for that new initialization block:

```diff
-                with expert_cpu_init_scope():
+                cpu_init_stride = (
+                    2
+                    if original_parallel_mode == "column"
+                    and config.gated_linear_unit
+                    and config.moe_mlp_glu_interleave_size is None
+                    else 1
+                )
+                with expert_cpu_init_scope():
                     for local_expert_idx in range(num_gemms):
                         weight = getattr(self, f"weight{local_expert_idx}")
+                        weight.partition_stride = cpu_init_stride
@@
-                                stride=1,
+                                stride=cpu_init_stride,
```

**Preservation:** Nongated FC1 must retain contiguous output-row partitions; FC2 must retain contiguous input-column partitions even when GLU is enabled. Explicitly interleaved GLU weights must also retain contiguous partitions—the [interleaving resolver](https://github.com/NVIDIA/Megatron-LM/blob/5f438f645bdf1d89e49335d912566b1a4f5e8d7a/megatron/core/transformer/moe/experts.py#L988-L994) expects paired interleaved blocks, not two global halves. Keep GPU initialization, per-global-expert streams, full logical RNG draws, and subsequent GTP slicing unchanged.

**Acceptance — proposed checks:** Extend the [layout regression](https://github.com/NVIDIA/Megatron-LM/blob/5f438f645bdf1d89e49335d912566b1a4f5e8d7a/tests/unit_tests/transformer/moe/test_expert_cpu_init.py#L180-L204), which currently leaves GLU disabled. Using eight experts, hidden size 128, FFN size 256, and gated SiLU, compare ETP=2 against ETP=1: each local FC1 must equal the concatenation of that rank's slice of the reference gate half and its slice of the up half; FC2 must equal the corresponding reference input-column slice. Repeat with nongated FC1 and with interleave size 32, expecting contiguous FC1 slices instead. Retain the existing nongated layout comparisons and the [distinct successive draws/shared-RNG-tail assertions](https://github.com/NVIDIA/Megatron-LM/blob/5f438f645bdf1d89e49335d912566b1a4f5e8d7a/tests/unit_tests/tensor_parallel/test_expert_cpu_rng.py#L30-L44). Verify the suggested patch before adoption.

### [P3] Include the new MXFP8 regression cases in GB200 CI selection

The added [duplicated-linear tests](https://github.com/NVIDIA/Megatron-LM/blob/5f438f645bdf1d89e49335d912566b1a4f5e8d7a/tests/unit_tests/generalized_tensor_parallel/test_gtp_cpu_init.py#L288-L295) include MXFP8 cases, but this file has no `launch_on_gb200` marker. H100 skips those cases through `_requires_mxfp8`; meanwhile, the [GB200 file selector](https://github.com/NVIDIA/Megatron-LM/blob/5f438f645bdf1d89e49335d912566b1a4f5e8d7a/tests/unit_tests/find_test_cases.py#L89-L98) excludes unmarked files, and its [pytest invocation also selects that marker](https://github.com/NVIDIA/Megatron-LM/blob/5f438f645bdf1d89e49335d912566b1a4f5e8d7a/tests/unit_tests/run_ci_test.sh#L114-L117). Thus the new quantized initialization regression is not exercised by either hardware lane.

**Correction:** Add this module-level declaration after the imports in the GTP CPU-init test file:

```python
pytestmark = pytest.mark.launch_on_gb200
```

This retains H100 BF16 coverage, existing hardware/version skips, and all parameter combinations; the GB200 marker is additive on H100.

**Acceptance — proposed checks:** On a GTP-capable environment, collecting this file with `pytest --collect-only -m launch_on_gb200` should include all 11 cases, including both new `fp8_param=True` duplicated-linear cases. The GB200 file selector must no longer emit an ignore entry for this file. Execute those MXFP8 cases on Blackwell and retain their exact equality assertion against GTP=1.
