# Finish moving the training loop onto its process-group collection

#8895 adds a name to the same `process_groups_config` import in `initialize.py` (originally #8733). The consolidated commit keeps both names.

#8904 builds on this PR (originally #8758 and #8759).

**Why.** `pretrain()` builds one `ProcessGroupCollection` and passes it to the model, the optimizer and the training loop. When a caller omits it, the loop and its helpers still read the global parallel state without a word. The loop also picked its data-parallel group in six places by two different rules. With GTP weight remat on and `dp_cp_gtp_remat` unset, one rule reduced over the replicate group only, a fraction of the ranks that read distinct data. The `--train-full-dataset` length probe called the dataset provider without the run's groups at all.

**What.**
- `_get_data_parallel_group()` picks the group for all six reductions: the full-dataset sum, samples-seen, the full-validation length, QK clipping, and the train and eval losses. It returns `dp_cp_gtp_remat` (`dp_gtp_remat` without CP), the group `get_data_parallel_group()` returns by default. When the collection does not set it:
  - `gtp_remat=None` or a one-rank `gtp_remat`: `dp_cp`/`dp`, silently;
  - no `gtp_remat` field: `dp_cp`/`dp`, with a warning;
  - an active `gtp_remat`, or neither group set: `ValueError`.
- `setup_model_and_optimizer()` without a collection builds one, with a warning, and gives the same object to the model and the optimizer. Before, `get_model()` and `get_megatron_optimizer()` each built their own, and only the first had the `--create-all-gather-group` communicators.
- The full-dataset probe, `_get_train_full_dataset_sample_count`, passes `pg_collection` to a provider whose signature declares it, the check training already does for `vp_stage`. Other providers are called as before.
- The cached-logits saver runs on the collection whose pipeline group decides that the rank is the last stage.
- Omitted groups now emit `ProcessGroupFallbackWarning` (deprecated in 0.21, removed in 0.23) and keep the old groups in:
  - `training.py`: `get_model`, `wrap_model_chunks_with_ddp`, `train_step`, `evaluate`, `evaluate_and_print_results`, `training_log`, `dummy_train_step`, the full-dataset probe, the data-loader builder, the batch accounting and the weight-hash check;
  - `utils/common_utils.py`: `calc_params_l2_norm`, the loss and stat reductions, and `report_memory`;
  - `initialize.py`: the RNG seeding and the JIT warmup, which now takes the TP size from the run's collection;
  - the packed-sequence stats, the cached-logits distillation helpers, the GPU sniff test and `default_layer_spec`.
- The loop passes its groups to all of these. When the grid was initialized before `initialize_megatron()`, the seeds come from that grid's collection.

`is_first_or_last_pipeline_stage()` stays silent here. #8904 makes it warn (originally #8759), together with the dataset providers that start passing a pipeline group.

**Tests.**
- New `tests/unit_tests/training/test_training_data_parallel_group.py`. On CPU it covers each rule of the helper. On 4 GPUs it sums over a grid unlike the global one, with global reads forbidden.
- New `tests/unit_tests/training/test_training_fallback_warnings.py`: each fallback warns with its owner before it reads the global grid, and the collection paths stay silent.
- `test_training.py` checks that an omitted collection is built once and reaches both the model and the optimizer.
- `test_full_dataset_length.py` checks that the probe passes the collection to a provider that takes one.
- The QK-clip, full-dataset, weight-hash and GPT-builder tests cover the new warnings and groups. The logger, profiling, inference-init and RL-config tests drive the loop with stubs that now pass a collection.

**Compatibility.**
- On the standard grid the collection holds the global groups, so every reduction and seed uses the same ranks as before. Stock training emits no warning.
- Omitted groups still work and warn. `--strict-process-group-fallbacks` turns the warnings into errors.
- New `ValueError`s where main kept running, for collections that no in-repo code builds:
  - `gtp_remat` with more than one rank but no GTP-inclusive group. Main reduced the train and eval losses over `dp_cp` and clipped QK over the global group.
  - Neither the GTP-inclusive nor the replicate group. Main's `evaluate` passed `None`, which reduces over WORLD.
- The samples-seen count and the full-dataset sum raised for a collection without the GTP-inclusive group since #8895 (originally #8741). If the collection does not set `gtp_remat`, they now use `dp`/`dp_cp` with a warning.
- Known gap: when a collection does not set `gtp_remat`, the helper does not check the global GTP layout. With `--gtp-weight-remat-size` > 1 and a hand-built collection without the GTP fields, QK clipping and the samples-seen sum run over `dp_cp` only. The warning there says the call falls back to the global process groups, but it returns the collection's replicate group.
- A MIMO run passes no single-grid collection to `dummy_train_step`, the full-dataset probe and the full-validation reduction, so those options now warn there. The sniff test does not reach its warning there, because #8895 rejects `--gpu-sniff-test-interval` for a multi-module run.
- Callers outside `megatron/training` that omit groups now warn too: examples, tools, `tasks/` and the ModelOpt inference entry points. Later PRs in #6307 pass their groups.
- Needs `determinism-exempt`: `utils/common_utils.py` is a registered kernel file. Numerics are unchanged.
