# fix: refresh relocated parameters after all-gather

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7448) · state: closed · merged: True

## Original PR description

Inference packing can redirect parameter storage while distributed optimizer shards still refer to the original DDP buffer. Copy completed gathered parameters into relocated plain storage without changing serving addresses or CUDA graph inputs.

- [x] I, the PR author, have personally reviewed every line of this PR.

## Notes

this is a replacement for PR #6931. see that PR for background and history. 

this is a simpler fix that refreshes the expert weights after every update if the data pointer has diverged from what it was originally set to. this avoids a lot of the complexity that was inherent in PR #6931.
 
the charts below show the fix in action:
<img width="5056" height="2656" alt="W B Chart 9_17_2026, 12_34_48 PM" src="https://github.com/user-attachments/assets/8751d496-7cf7-42d5-ac91-f53221909ad6" />

the curves show KL divergence between the reference policy and the current generation policy. in this case, lower divergence (orange curve) doesn't really mean healthier training. it is just a side effect of the expert weights in the generation policy getting stale. the green curve shows the KL metric after the fix.

- tdene · comment · 2026-09-27T15:22:43Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/7448#discussion_r4115887809)

File: `megatron/rl/rl_utils.py` · line 3034

RL with `--use-distributed-optimizer` and `--fp8-recipe mxfp8` and `--reuse-grad-buf-for-mxfp8-param-ag`, but without `--overlap-param-gather` has a problem.

Currently, this sync will zero all MXFP8 weights during inference.

`param_and_grad_buffer.py`, on L391, does a `bucket.param_data.zero_()`.

This should get caught, but `prepare_model_params_for_param_sync` inside `distrib_optimizer.py` gates on `self.config.reuse_grad_buf_for_mxfp8_param_ag and self.config.overlap_param_gather`. So without  `--overlap-param-gather`, we never enter that if-statement.

The solution is to change the if-statement on `distrib_optimizer.py` L2908 to just `if not self.config.reuse_grad_buf_for_mxfp8_param_ag`, and the if-statement on `optimizer.py` L1702-1705 to just `if not self.config.reuse_grad_buf_for_mxfp8_param_ag`.

I do not see any reason why that check was not like this in the first place. I see nothing that can break.
