# refactor: require independent FSDP configuration

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8698) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

## What does this PR do?

Separate Megatron-FSDP configuration from DDP throughout model construction and runtime consumers. `FullyShardedDataParallel`, `FullyShardedDataParallelV1`, and `FullyShardedDataParallelV2` require `fsdp_config: FullyShardedDataParallelConfig` as their sole data-parallel config argument.

This is an alternative to #8697, targeting `main` independently.

```python
fsdp_config = FullyShardedDataParallelConfig(
    version=2,
    data_parallel_sharding_strategy="optim_grads_params",
    main_grads_dtype=torch.float32,
)
model = FullyShardedDataParallel(
    config=transformer_config,
    fsdp_config=fsdp_config,
    module=model,
    pg_collection=pg_collection,
)
```

### Scope

- Independent DDP and FSDP config classes; FSDP fields use names such as `version`, `main_grads_dtype`, and `double_buffer`.
- Migrate the v1 engine and buffers, v2 adapter, optimizers, gradient finalization, pipeline scheduling, process-group selection, direct callers, tests, and examples to native FSDP config access.
- Rename the standalone package's config to `FullyShardedDataParallelConfig`, preserving operation without Megatron Core.
- Model builders accept `data_parallel_config=`; native training containers accept `data_parallel=`. Existing CLI and serialized training inputs are converted at the training boundary.
- Validation is side-effect-free; adapters resolve defaults on a copy. The v1 adapter and engine share that effective config so runtime buffer/overlap adjustments stay consistent.

### API migration

This intentionally changes the direct FSDP Python API:

- Replace `ddp_config=` with `fsdp_config=`. Passing a DDP config positionally is also rejected.
- Replace `model.ddp_config` and FSDP-specific prefixed fields with `model.fsdp_config` and the native field names.
- Where an old config still needs conversion, call `FullyShardedDataParallelConfig.from_ddp_config(old_config)` before constructing FSDP.

There is no legacy config proxy and no automatic conversion inside FSDP constructors. Legacy fields remain in `DistributedDataParallelConfig` for loading/converting existing training configs; removing that serialized schema is a separate migration. Downstream direct callers must migrate.

Compared with #8697, this removes the constructor compatibility machinery and migrates the callers instead. The wider diff is **53 files, +1,339/−604**, including the standalone config rename and mechanical field-access changes.
