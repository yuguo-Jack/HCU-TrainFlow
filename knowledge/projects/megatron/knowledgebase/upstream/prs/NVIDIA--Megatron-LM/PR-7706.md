# Fix batch indexing and KL gradient in deterministic CSA indexer backward

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7706) · state: closed · merged: False

## Original PR description

[Scoped diff of this PR's own changes](https://github.com/NVIDIA/Megatron-LM/compare/bb1283725a6be98841fc09cb3566791c0cf79bb4...bfc22f1466f02f0c8e140693f5470c914ea91330). The full diff also shows #7441's commits until it merges.

Depends on #7441 by @HaochenYuan; please review and merge #7441 first. This branch carries #7441's two commits, rebased onto current `dev`, so that it merges cleanly.

SBHD Top-K IDs are local to each sample, but the deterministic sparse-indexer dK/dW replacement in #7441 treats them as flattened batch-wide IDs. With batch size greater than one, it reads and updates another sample's keys. Validate IDs against the per-sample key count, then add row-derived batch offsets before flattened gather/accumulation. Chunk boundaries may cross samples; packed THD's synthetic batch size one is unchanged.

It also makes the replacement follow cuDNN's clipped-log KL gradient. cuDNN's sparse-indexer backward uses the per-slot score gradient `predict * sum(kept_target) - kept_target`, where `kept_target` is the target raised to exp(-100) on valid slots whose predicted probability is at least exp(-100). The replacement used `predict - target`, which is equal only when the selected targets sum to one. The CSA indexer target is normalized by an attention LSE that also covers the sink and the local keys, so the selected targets sum to less than one: deterministic mode changed the dK (and SM90 dW) math, not only the reduction order, and dK no longer matched the dQ that cuDNN still computes.

The underlying deterministic implementation is by @HaochenYuan in #7441; this PR contains the batch-addressing and KL-gradient repairs and their regressions. Three small hunks only reformat #7441 lines that exceed the line-length limit; they can be dropped if #7441 reformats them. Like #7441, this targets `dev`.

`dev` conflict: #7441 conflicts with `dev` in one hunk. `dev` added `_align_topk_width` (#7343) at the position where #7441 inserts its deterministic helper block. This branch is rebased onto current `dev` with both kept: `dev`'s function unchanged, followed by #7441's block unchanged. #7441's two commits are otherwise replayed as is. This PR's own commits do not touch that hunk and replay unchanged. When #7441 is rebased or merged, this PR will be restacked onto it so that only its own commits remain (or they can be folded into #7441).

The 32 reference cases (now including a target row that sums to 0.75) cover B1/B2, FP32/BF16, optional dW, padding, full/cross-sample chunks, an independent per-sample autograd reference, and byte-exact replay, each with Torch deterministic algorithms on (`index_add_` accumulation) and off (stable sort plus prefix sums). An SM100 test compares dK and dW against the cuDNN kernel on rows whose targets sum to one half and slots with zero or underflowing predictions.

Validation: on four GB300 ranks with the normal repository conftest, all 33 cases pass on this head, which is rebased onto current `dev`. With only the batch-offset repair, all 33 fail (the cuDNN comparison is off by 0.38 relative L2 in dK). With #7441's original helper, all B2 cases also fail. On this head, `test_csa_fused_sparse_attention.py` passes 130 of 131 cases. The failure is `TestThdWrapperDispatchAndValidation::test_indexer_topk_thd_compact_dispatch`, which also fails on #7441's own head: under `deterministic=True`, #7441 recomputes the compact softmax that the test expects to pass through. All 131 pass on `dev`, so that test needs an update in #7441. Black, isort, Ruff, Pylint and the copyright check pass.

The dependency branch predates main's kernel-determinism registry/checker. This is a focused correctness fix, not a universal DSV4 determinism or CI certification claim.
