# Fix MFSDP v2 backward completion with EP overlap

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7582) · state: open · merged: False

## Original PR description

Fix tied-weight and MTP backward completion when using M-FSDP v2 with EP overlap. The fine-grained schedule splits backward across multiple autograd GraphTasks, so completion should follow the schedule rather than depend on a configurable gradient-callback count.

## Changes

- Let the schedule reshard parameters and reduce gradients after each FSDP unit's last backward use, including delayed wgrad.
- Configure hooks from the outer model chunk so wrapper-owned parameters are included. Finish shared and nested units once, and finish remaining root-owned parameters after pre-process backward.
- Refresh externally supplied tied embedding weights in the demand-gather hook, and reshard evaluation forwards.
- Remove `grad_accumulation_count` from the FSDP API and keep EP-overlap regression tests under `pipeline_parallel`.

## Validation

Eight H100s, BF16, EP2, and 200 training steps on a fixed real-Pile subset. Each configuration was tested with normal and delayed wgrad, with no NaNs or skipped iterations. Initial weights and input fingerprints match across all eight ranks in each comparison.

| Configuration | Final validation LM loss: M-FSDP v2 | DistOpt |
| --- | ---: | ---: |
| PP1, tied embeddings, MTP1 | 6.8805 | 6.8776 |
| PP2/VPP2, tied embeddings, no MTP | 6.8268 | 6.7883 |
| PP2/VPP2, untied weights, MTP1 | 6.7232 | 6.7491 |

Normal and delayed-wgrad loss/norm curves match exactly in all three configurations. The PP1 and PP2/VPP2 loss/norm curves also match their pre-refactor M-FSDP baselines exactly. DistOpt shows comparable loss convergence; its gradient and parameter norms differ.

All 14 focused distributed regression cases pass on every rank. The broader M-FSDP v2 suite was also exercised; an assertion was updated for main's parameter-group readiness tracking and verified in the focused rerun. Four Muon `palm` reference cases are incompatible with the container's `emerging_optimizers`; the same failures reproduce on the unchanged baseline and were excluded from the rebased suite run.

PP/VPP MTP coverage uses untied weights. The existing restriction on tied embeddings with MTP across pipeline stages remains.
