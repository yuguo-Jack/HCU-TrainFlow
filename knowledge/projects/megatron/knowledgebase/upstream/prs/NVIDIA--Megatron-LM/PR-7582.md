# Declare gradient multiplicity for shared weights in combined 1F1B

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7582) · state: open · merged: False

## Original PR description

## Summary

Fix failures when using tied weights or MTP with Combined 1F1B and M-FSDP v2.

Tied weights and MTP can cause a parameter to receive multiple gradient contributions within a single forward/backward pass. Combined 1F1B needs to account for these contributions to trigger gradient reduction at the correct time. Tied weights also require explicit unsharding when consumed by the output head.

This PR addresses both issues and builds on #7581, which has merged into main.

## Implementation

1. Compute the expected number of gradient accumulation callbacks for the embedding weight from the weight-tying and MTP configuration, ensuring reduction starts only after all expected contributions have accumulated.
2. Explicitly unshard the tied weight before the post-process schedule node’s forward and backward computations in model_chunk_schedule_plan.py.

## Testing and Validation

Validated on H100 GPUs with BF16 and Transformer Engine 2.16:

- Passed the reproduction script from #8179.
- Passed 31 focused unit tests on each of four ranks.
- Passed six-step training runs with validation every two steps for PP1, PP1 with MTP, and PP2 with VPP2. Gradient accumulation completed correctly, and parameters were resharded after validation.
- Compared the new schedule-node unsharding against the previous hook implementation: all 576 gradient and updated-weight tensor pairs were exactly equal in a four-step PP1 + MTP run.
- Confirmed that PP1 runs with and without MTP performed the same number of parameter materializations as the previous implementation.
- Verified that unsharding also works when the parameter owner is an outer FSDP wrapper with no nested FSDP units.

Validation covers short GPT training runs; HybridModel and the full CI suite have not been tested.
