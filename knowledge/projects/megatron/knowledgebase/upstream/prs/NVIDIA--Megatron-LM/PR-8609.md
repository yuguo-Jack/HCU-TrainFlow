# Support MFSDP-wrapped stages in MIMO optimizer setup

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8609) · state: open · merged: False

## Original PR description

## What does this PR do?

Support MIMO optimizer construction when language uses MFSDP v2 and vision uses DDP. The language wrapper may enclose the whole local `MimoModel` stage, so selecting only `mimo_model.language_model` loses the wrapper needed to construct `FullyShardedOptimizer`.

- Add optional `module_overrides` to `get_mimo_optimizer()` so callers can supply the wrapped language stage. Existing callers can omit it.
- Derive `use_distributed_optimizer` and MXFP8 gradient-buffer reuse from each module's distributed configuration. Vision can retain distributed Adam while MFSDP language disables it. Preserve the existing layer-wise optimizer selection.
- Set each MFSDP optimizer's gradient-statistics group to its complete module grid. The generic factory defaults to `WORLD`, which includes unrelated vision ranks in a non-colocated MIMO run. An optimizer-instance subgroup can omit language shards. DDP optimizer groups retain their existing behavior.

This extracts the optimizer portion of the NT4 MIMO integration. The diff changes one production file and extends its existing setup tests. Bridge/worker enablement and pretrained checkpoint loading are separate changes.

## Validation

Based on upstream `main` at `364eef70a30aacdc622e75f6f437b50c2ef18278`.

On two RTX A6000 GPUs, the MIMO overlap/setup, nested optimizer-chain, and optimizer-consensus suites passed **13 tests per rank**, with no skips or failures. The extended setup tests check selection of the supplied wrapper, per-module optimizer configuration, full-grid MFSDP norm-group selection, and preservation of the non-MFSDP norm group. These setup checks use a mocked optimizer factory; they are not a full MFSDP training comparison.

Black, isort, Pylint, and Ruff pass through `tools/autoformat.sh`. The advisory Mypy step reports two existing diagnostics: an unannotated `optimizers` list and the unresolved `MimoModel` forward reference.

The previous 72-GPU NT4 experiment used the corresponding local integration patch, but this upstream revision has not been rerun on that workload. No new latency or full-model numerical-equivalence result is claimed.
