# Fix a paged-stash hang, shared-expert checkpoint metadata and the quickstart optimizer

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8906) · state: open · merged: False

## Original PR description

This PR fixes three bugs on main that the #6307 work found. A paged-stash overflow step can deadlock when a pipeline stage has only dense layers. `SharedExpertMLP.sharded_state_dict(metadata=None)` raises `TypeError` when the shared-expert gate is on. The quickstart example never updates its weights. It consolidates three draft PRs from #6307, one commit per member, so please review commit by commit. The fixes depend on no other unit, and no unit depends on them. The branch sits on top of the earlier units in the chain, including #8896 (inference plumbing and standalone tools), which contains #8746. #8746 edits the same example loop, so the #8819 commit applies the resolution that #8819's description gives: `get_optimizer()` and `train_step()` take `pg_collection`, and the new test passes it. The other two members are unchanged. None of the members adds a `parallel_state` read, so the allowlist does not change.

## Review

This unit's own commits: https://github.com/Connor-XY/Megatron-LM/compare/0e8c3da8d54713b98a8f5c6b009eadc9f81463e1...78a4fd484dde040bb9c10120d70642d3ec707abe

The branch is a linear chain on main. The full PR diff also shows the PRs and units below this one until they merge.

## Members

- #8821: Enter the paged-stash capacity reduction on every rank. After the WORLD vote reports an over-budget rank, `PagedStashRunner.check_moe_overflow` has every rank enter the MAX `all_reduce` of the required receive capacity, with 0 from ranks without a reporting MoE layer, so a dense-only PP stage no longer skips it and hangs the MoE stages.
- #8818: Fill SharedExpertMLP checkpoint metadata when the caller passes none. `SharedExpertMLP.sharded_state_dict` fills `dp_cp_group` with `ensure_metadata_has_dp_cp_group` before it calls `MLP.sharded_state_dict`, so `gate_weight` gets the same replica id as `linear_fc1` and `linear_fc2` instead of raising `TypeError`; `FusedSharedExpertMLP` inherits the fix.
- #8819: Fix the quickstart example's optimizer so training updates weights. `examples/run_simple_mcore_train_loop.py` builds its optimizer with `get_megatron_optimizer()`, which steps on `main_grad`, and a new `train_step()` zeroes the grad buffer before backward and calls `finalize_model_grads()` before `optim.step()`, the order `training.py` uses.

## Behavior changes for callers

- On an over-budget paged-stash step, every rank issues one more `all_reduce` of 2 int64 values. Steps within budget are unchanged (#8821).
- `SharedExpertMLP.sharded_state_dict(metadata=None)` returns a state dict instead of raising `TypeError`. Callers that pass a dict see no change (#8818).
- The quickstart example now changes its weights every iteration, so its checkpoint holds trained weights. Over 5 iterations on 2 GPUs on this chain, its loss goes from 4.61 to 4.55. On main it stays near 4.61 (#8819).
