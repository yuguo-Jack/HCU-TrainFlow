# Avoid unused output weights on tied MTP stages

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8330) · state: open · merged: False

## Original PR description

When an MTP stage owns a tied output head but is not the input stage (`pre_process=False`, `post_process=True`, `mtp_process=True`), GPTModel and HybridModel allocate `output_layer.weight` even though their postprocessing passes the embedding weight explicitly to that head. The registered output weight is therefore unused and never receives a gradient.

Include `mtp_process` in the existing `skip_weight_param_allocation` condition so the tied MTP head uses its canonical embedding without allocating an unused trainable parameter. Untied heads keep their own weight. The production change is one line in each model; no MFSDP scheduler or callback-count changes are included.

### Reproducer

The `test_mtp_output_weight_receives_gradient` cases in the existing `test_gpt_model.py::TestGPTModel` and `test_hybrid_model.py::TestHybridModel` classes construct real GPT and Hybrid models with one MTP layer, `pre_process=False`, `post_process=True`, vocabulary 128, and hidden size 12. They isolate the projection path used by model postprocessing:

```python
weight = model.shared_embedding_or_output_weight()
logits, _ = model.output_layer(hidden_states, weight=weight)
logits.square().mean().backward()

assert weight is model.embedding.word_embeddings.weight
assert weight.grad is not None
```

With the original allocation condition, `model.output_layer.weight` is a distinct, trainable parameter and its `.grad` is `None`. The regression fails with:

```text
AssertionError: Output projection owns unused trainable parameters: ['weight']
```

With the fix, `model.output_layer.weight is None` and the embedding receives the gradient. The untied controls retain their output weight and receive its gradient. This demonstrates the allocation bug without MFSDP or a pipeline training schedule; it does not claim to run the complete decoder/MTP forward path.

Run the four cases with:

```bash
uv run python -m torch.distributed.run --standalone --nproc-per-node 8 \
  -m pytest -q \
  tests/unit_tests/models/test_gpt_model.py::TestGPTModel::test_mtp_output_weight_receives_gradient \
  tests/unit_tests/models/test_hybrid_model.py::TestHybridModel::test_mtp_output_weight_receives_gradient
```

To reproduce on the original code, copy the new test methods and required import into the existing model test files on main (baseline `ce852bfb93f364f64a556602fc71a5d9ed2c377e`), or revert just the two production-line changes while keeping the test.

### Validation

Executed both versions on eight H100 ranks using the mirrored CI image `mcore-ci-dev_b1cac88379bb` (PyTorch 2.12.0a0 / CUDA 13.2):

| Code | GPT tied | Hybrid tied | GPT untied | Hybrid untied |
| --- | --- | --- | --- | --- |
| Main + regression tests | Fails: unused output weight | Fails: unused output weight | Pass | Pass |
| Main + two allocation fixes + regression tests | Pass | Pass | Pass | Pass |

Each rank reported `2 failed, 2 passed` before the fix and `4 passed` after it. The runner verified the specific unused-weight assertion in every failing rank, rather than accepting any nonzero exit. Both versions were also verified after moving the cases into the existing model test classes, using their setup and teardown. No #7582 scheduler code was applied in either run.

isort, Black 26, Ruff, and `git diff --check` also passed.

Extracted from #7582 so the model allocation fix can be reviewed independently. The missing-gradient error previously observed during #7582's tied PP2/MTP MFSDP training motivated this reproducer; this PR's before/after test checks the underlying allocation issue independently.
