# Remove a redundant device-to-host sync from the ragged dispatch path

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7528) · state: open · merged: False

## Original PR description

**Incremental review:** [Files changed](https://github.com/NVIDIA/Megatron-LM/pull/7528/files) against `main`.

`NCCLAllGatherDispatcher.update_metadata()` (ragged / non-CG path) host-syncs the per-rank
token counts, then re-reads the device tensor for a total it already has on the host.

```python
cls._local_tokens_per_rank = local_tokens_per_rank.tolist()   # D2H sync #1
total = local_tokens_per_rank.sum()
_valid_tokens_tensor.copy_(total)
_host_valid_tokens_estimate = int(total.item())               # D2H sync #2, same data
```

`.item()` synchronises to read a value that `.tolist()` just copied to the host, and
`local_tokens` (the caller's Python int) is on the host too. The fix sums the host list
directly and writes the total with `.fill_`, which is the same write the original performed
via `copy_` after the reduction:

```python
cls._local_tokens_per_rank = local_tokens_per_rank.tolist()
total_tokens = sum(cls._local_tokens_per_rank)                # no sync
_valid_tokens_tensor.fill_(total_tokens)
_host_valid_tokens_estimate = total_tokens
```

## Measured effect

Deterministic, not a timing claim. `benchmarks/moe/ragged_sync_probe` counts the tensor
methods that force a device->host synchronisation by wrapping them, so base and patched are
compared on a number that does not depend on GPU contention. Configuration: EP=2,
local tokens `[2048, 128]`, 10 measured steps, exact-round-trip oracle enabled.

| tree | rank | syncs/step | `.tolist()` | `.item()` | round trip | total |
|---|---|---|---|---|---|---|
| base | 0 / 1 | **2.00** | 10 | 10 | exact | 2176 |
| patched | 0 / 1 | **1.00** | 10 | 0 | exact | 2176 |

`total` is the value the removed `.item()` used to produce: the probe asserts that the
valid-tokens tensor and the host estimate both equal the global token count
(`tensor=2176 host=2176 want=2176`), so the replacement writes exactly what the original did.
The exact round trip (`hidden * ep_size`) is unchanged.

## What this does NOT claim

**No wall-clock improvement.** Paired A/B (`-A-P-P-A-` style, same probe) on a shared node gave
**+43.5% / -0.3%** for this path across two run pairs -- opposite signs, i.e. below the noise
floor. The verifiable statement is one fewer device->host sync per ragged step; the time
saving on this hardware was not resolvable and is not asserted.

This is a draft: it removes a clearly redundant synchronisation, and whether that is worth
taking should be weighed against the fact that its runtime benefit could not be demonstrated.

## Regression

- `tests/unit_tests/inference/test_nccl_ragged_and_empty_rank.py`: 5 passed
- A3 token-count tests on a tree carrying both this change and the A3 fix: 11 passed, 3 skipped
  (identical to the A3 fix alone)

- summed the int32 per-rank counts on the device;
- `copy_`'d the result into the int32 `_valid_tokens_tensor`;

New code:
- sums the host list that `.tolist()` already produced;
- writes it with `fill_`;
- stores the same Python int as `_host_valid_tokens_estimate`.

I traced the cases that matter:
- **Ragged EP>1:** same total.
- **A rank with 0 tokens:** `sum` gives the same value, and `max(tokens_per_rank)` is unaffected.
- **Stream ordering:** `fill_` and `copy_` are both enqueued on the current stream.
- **CUDA graphs:** the ragged branch is never captured.
- **CG path:** the `else` branch is unchanged.
- **`_local_tokens_per_rank` consumers:** `token_dispatch` and `token_combine` see no change.

This removes one device-to-host sync per ragged step without changing any value.
