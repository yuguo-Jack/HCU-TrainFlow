# What does this PR do?
Right now, the dtype of the logits tensor pinned in inference does not always match the dtype of the logits emitted by the forward pass. Sampling and logprobs still convert the logits from whatever dtype they're in to FP32. But in addition to that, there is an undocumented conversion, where the dtype of the logits emitted by the forward pass is converted to some the params' dtype (which could be completely different) when it goes into the logits tensor. The first commit fixes this.

The second commit forces inference to use FP32 as the dtype of the logits tensor when this is possible.    
This has been discussed over the last year by the inference team; the consensus is that this is optimal, because sampling and logprobs need to convert the logits to FP32 anyway, so this saves both memory and latency.
