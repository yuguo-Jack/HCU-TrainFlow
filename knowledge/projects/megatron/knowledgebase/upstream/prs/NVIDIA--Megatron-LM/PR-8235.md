# MInf: Make logits dtype match the forward output dtype

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8235) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?
Right now, the dtype of the logits tensor pinned in inference does not always match the dtype of the logits emitted by the forward pass. Sampling and logprobs still convert the logits from whatever dtype they're in to FP32. But in addition to that, there is an undocumented conversion, where the dtype of the logits emitted by the forward pass is converted to some the params' dtype (which could be completely different) when it goes into the logits tensor. The first commit fixes this.

The second commit forces inference to use FP32 as the dtype of the logits tensor when this is possible.    
This has been discussed over the last year by the inference team; the consensus is that this is optimal, because sampling and logprobs need to convert the logits to FP32 anyway, so this saves both memory and latency.

with batch-invariant BF16 execution and MuP output scaling, casting before `_scale_logits` changes rounding relative to training, so generation and training can return different scores. please move the cast after scaling in `GPTModel`, `HybridModel`, and `compute_mtp_single_step`.

an example flow:

- enable batch-invariant mode with `use_mup=True` and `mup_output_mult=0.1`.
- let the output layer produce a BF16 score of `1.0`.
- training scales in BF16 and then casts, giving `0.10009765625`, while the new inference order gives about `0.10000000149`.
- scaling before the cast preserves the same rounded score in both paths.

suggested fix:

```python
# After the existing output_layer call in GPTModel and HybridModel:
logits = self._scale_logits(logits)
if in_inference_mode:
    logits = logits.float()

# After the existing output_layer call in compute_mtp_single_step:
logits = self._scale_logits(logits).float()
```
