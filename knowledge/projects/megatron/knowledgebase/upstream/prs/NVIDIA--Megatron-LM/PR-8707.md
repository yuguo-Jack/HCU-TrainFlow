# [Inference][Hybrid] Map hybrid MLA layers to KV-cache planes in dynamic inference

## Original PR description

# What does this PR do?

Lets a `HybridModel` with MLA layers (`+`) run dynamic inference, and sizes every hybrid model's KV cache by its attention layers. Before this PR, building the `DynamicInferenceContext` for a hybrid model with Mamba and MLA layers failed with:

```
NotImplementedError: Using `DynamicInferenceContext` with no attention is not supported.
```

**Bug.** For a hybrid model with Mamba or GDN layers, `DynamicInferenceContext.__init__` built its KV layer map from the per-symbol attention (`*`) and DSA (`D`) maps of `get_layer_maps_from_layer_type_list`. MLA layers were left out:
- A hybrid model whose only attention is MLA (for example pattern `M+-` with `cache_mla_latents=True`) got `num_attention_layers == 0`, and the context raised the error above.
- With a DSA layer also present, the context would build, but the MLA layer's `append_key_value_cache` would raise `KeyError`.

`MTPContextMixin.should_enable_mtp_kv_cache` already counted MLA as attention, so only the main map was wrong: the two places kept their own copies of the symbol sets, and the copies had drifted apart. An inference-vs-training configuration matrix on H100 hit this on its hybrid Mamba + MLA row (`M+-`, TP=1). The GPT MLA rows and the hybrid GQA rows passed.

Each per-symbol map is numbered from 0, so adding an MLA map the same way would give a DSA layer and an MLA layer the same KV plane. Dynamic MLA requires `cache_mla_latents`, and #8570 rejects DSA cores with cached latents, so once #8570 lands a hybrid with both `D` and `+` cannot run dynamic inference and this case is latent. The single numbering below keeps it correct anyway.

A related sizing problem: the context got the layer types only from `MambaInferenceStateConfig`, which exists only when the model has Mamba or GDN layers. Any other hybrid model took the GPT path and got one KV plane per layer, MLP and MoE layers included. `+E+E` (MLA + MoE) allocated 4 KV planes and used 2, which halves the KV blocks the buffer holds.

**Fix.**
- The context numbers every KV-cache layer type (attention, DSA, MLA) in one map, in layer order, the same way it numbers Mamba and GDN layers. The KV buffer keeps one layout: MLA latents with `cache_mla_latents`, per-head keys and values otherwise. That layout fits every KV-cache layer, because the hybrid pattern parser already rejects standard attention next to MLA-family layers ("Not supported to have both Attention and MLA/DSA/CSA/HCA/Window in one model").
- `Symbols.KV_CACHE_LAYERS` and `Symbols.RECURRENT_STATE_LAYERS` define the two sets once. The context, the MTP draft-KV gate and `MambaInferenceStateConfig.from_model` all use them.
- New `InferenceConfig.layer_type_list` carries the main decoder's layer types for every hybrid model. `layer_types_from_model` fills it in `InferenceSetupConfig.to_inference_config` and in the static engine. When it is unset, the context falls back to the list in `mamba_inference_state_config`, so existing callers keep working. The context builds its KV map from the layer types whenever it has them, so `+E+E` gets 2 KV planes.

The other users of the plane count are unchanged: the MTP draft plane is still appended after the attention planes, prefix caching and CUDA graphs address blocks and the whole buffer, and the disaggregated KV handoff gathers each pipeline stage's plane count. As before for Mamba hybrids, a hybrid pipeline stage must hold at least one KV-cache layer.

**Tests.**
- `tests/unit_tests/inference/contexts/test_dynamic_context.py::TestDynamicContext::test_hybrid_mla_layers_get_their_own_latent_kv_planes` builds a Mamba hybrid context with cached MLA latents for two patterns. It checks the layer map, the plane counts, the latent buffer shape, and that each KV-cache layer's latents round-trip through its own plane:
  - `M+-M+-`: map `{0: 0, 1: 0, 3: 1, 4: 1}`. On `main` it fails at context construction with the error above.
  - `MD+-`: map `{0: 0, 1: 0, 2: 1}`. Numbering each symbol separately would put the DSA and MLA layers on plane 0, so this case fails for that design.
- `test_hybrid_without_recurrent_layers_gets_kv_planes_for_attention_layers_only`: `+E+E` gets the map `{0: 0, 2: 1}` and two planes, and the latents round-trip.
- `tests/unit_tests/inference/contexts/test_dynamic_context_mtp_kv_cache.py::TestMtpKvCacheGating::test_draft_kv_plane_follows_the_hybrid_attention_planes`: for `*E*E` with an MTP head, the draft plane is plane 2 of 3.
- `tests/unit_tests/inference/test_inference_config.py::TestInferenceConfig::test_inference_setup_config_maps_hybrid_layer_types`: the setup builder passes a non-recurrent hybrid's layer types to the context.

None of these tests launches FlashMLA.

On H100 in the CI image, the first version of the regression test (`M+-M+-`) fails on `main` with the `NotImplementedError` above (1 case) and passes with this PR. The neighbor tests `test_mamba_states_cache` (2 cases), `TestMtpKvCacheGating` (8) and `test_dynamic_engine.py::TestDynamicInferenceEngine::test_mamba_chunked_prefill` (2) pass with no skips. The configuration-matrix row that found the bug (hybrid Mamba + MLA, `M+-`, TP=1, FlashMLA decode) passes end to end with this PR applied. With the review-fix commit (dfw 21004395), all 5 regression cases pass with this PR and fail on `main`; the neighbors pass. The 57-task inference-vs-training matrix passes on integration trees of current `main` with every open fix (dfw 21004395, 21007036).
