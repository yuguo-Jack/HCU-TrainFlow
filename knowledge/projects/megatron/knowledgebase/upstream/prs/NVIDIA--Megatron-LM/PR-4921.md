# What does this PR do ?
Adds an opt-in MCore flag to skip checkpointing the final full-recompute unit in each pipeline stage, retaining its forward activations because backward consumes them first.

## Issue tracking

Linked issue: Fixes #4546

## Scope

This PR intentionally scopes the optimization to `recompute_granularity='full'`. `skip_final_recompute` now raises a config error when used without full activation recomputation, so the flag cannot silently no-op for selective recompute.

- chengcuiping · comment · 2026-07-28T04:05:52Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/4921#issuecomment-5099812012)

Thanks for working on this. I can help validate the change on 4×A100, but I think the intended meaning of “final instance” in #4546 should be clarified first.

The current patch interprets it spatially on every forward invocation:

* `uniform`: bypass checkpointing for the final recompute group;
* `block`: bypass checkpointing for the final recomputed layer.

For example, with 6 layers and `recompute_num_layers=2`, the uniform path retains the full final two-layer group. Is that the intended unit, or should only the final module/layer be retained? Also, does “final instance” mean the final layer/unit, or the final outstanding forward/microbatch instance before backward?

The current 5-layer / group-size-2 unit test leaves a one-layer final group, so it does not distinguish these interpretations.

If the intended contract is confirmed, I can help provide:

* output, input-gradient, and parameter-gradient parity;
* uniform tests with a multi-layer final group;
* multiple-microbatch PP/VPP coverage;
* FP8/TE coverage;
* iteration-time and `max_memory_allocated` measurements across several microbatch counts.

This would help quantify the recompute saving versus the additional retained-activation memory.
