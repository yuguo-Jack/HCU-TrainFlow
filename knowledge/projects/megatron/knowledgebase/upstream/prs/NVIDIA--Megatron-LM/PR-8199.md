# fix(moe): keep per-token aux-loss scaling capturable in CUDA graphs

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8199) · state: closed · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?
With calculate_per_token_loss=True and a Python-int token count, TopKRouter.attach_and_log_load_balancing_loss builds the aux-loss token count with torch.tensor(num_local_tokens, device=...). That copies from pageable host memory, which CUDA graph capture forbids, so per-layer CUDA graphs that include moe_router stop at capture with seq_aux_loss and global_aux_loss (a regression from #7046). Fill the count on the device with torch.full instead; the value, dtype and shape are unchanged.

Add TestPerTokenAuxLossCudaGraph, which captures and replays the router with per-token loss for both load-balancing types.

The old code was `torch.tensor(num_local_tokens, device=...)`. It builds a CPU scalar and then does a blocking host-to-device copy from pageable memory, which CUDA graph stream capture rejects. The result is the same as before: a 0-d `int64` tensor. `torch.distributed.all_reduce` at [L802-L803](https://github.com/NVIDIA/Megatron-LM/blob/4cda138c49a84c400e1af305c551f8e243ff2664/megatron/core/transformer/moe/router.py#L802-L803) and the product `aux_loss * aux_loss_scale_num_tokens` at [L804-L806](https://github.com/NVIDIA/Megatron-LM/blob/4cda138c49a84c400e1af305c551f8e243ff2664/megatron/core/transformer/moe/router.py#L804-L806) therefore see the same value, dtype and type promotion.
