# Fix AbsorbedMLA to respect explicit config.softmax_scale override

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8649) · state: open · merged: False

## Original PR description

## Summary

`AbsorbedMLASelfAttention` is documented as mathematically equivalent to `MultiLatentAttention`, but its `__init__` computed `softmax_scale` as always `mscale * mscale * (1 / sqrt(q_head_dim))`, ignoring an explicit `config.softmax_scale` override. `MultiLatentAttention` itself checks for the override and uses it when present (e.g. the value `TransformerConfig.__post_init__` derives for muP training).

With muP enabled, this silently produces a different (and substantially larger, ~11x in the case checked) softmax scale on `AbsorbedMLA` than on standard `MLA`, despite the "equivalent" claim in the docstring.

## Fix

Mirror `MultiLatentAttention`'s exact expression in `AbsorbedMLASelfAttention.__init__`:

```python
self.softmax_scale = (
    mscale
    * mscale
    * (
        (1 / math.sqrt(self.q_head_dim))
        if self.config.softmax_scale is None
        else self.config.softmax_scale
    )
)
```

## Test plan

Added `test_softmax_scale_respects_explicit_config_override` in `tests/unit_tests/transformer/experimental_attention_variant/test_absorbed_mla.py`, which builds both `AbsorbedMLASelfAttention` and `MLASelfAttention` from the same config with an explicit `softmax_scale` override and asserts the two match.
