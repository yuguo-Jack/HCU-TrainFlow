# Name FSDP-DTensor experts by the model's expert-parallel layout

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8045) · state: open · merged: False

## Original PR description

**Why.** The FSDP-DTensor checkpoint helpers turn local expert indices into global ones with the global expert-parallel rank and size. A model with its own EP layout then saves and loads optimizer state under other experts' names. The distributed optimizer's parameter names and the param-group dump have the same problem.

**What.**
- `get_ep_layer_offset`, `handle_experts_in_state_dict`, `expert_param_local_key` and `get_global_unique_param_name` take keyword-only integer `ep_rank` and `ep_size`. Integers keep offline tools without process groups working. Passing only one raises `ValueError`; passing neither keeps the global fallback.
- `get_ep_rank_and_size(pg_collection)` reads them from a collection. An unset `ep` keeps the fallback, and `ep=None` means expert parallelism is off.
- `DistributedOptimizer`'s parameter names, the `get_megatron_optimizer` param-group dump, `handle_swiglu_in_state_dict` and the training loop's FSDP-DTensor preprocessing pass their model's layout.

**Tests.** New tests check expert offsets, state-dict keys and parameter names on an EP grid that differs from the global one, for the helpers, the distributed optimizer and the param-group dump. They fail on main and pass here on 4 GPUs. `test_fsdp_dtensor_checkpoint.py` matches main.

**Compatibility.** Names on the standard grid do not change. MoE models must carry a `pg_collection` at some wrapper level for these paths, as all Megatron models do.
