# Pass the pipeline rank to the ModelOpt GPT spec

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8726) · state: closed · merged: False

## Original PR description

**Why.** `get_gpt_modelopt_spec` keeps only one pipeline stage's layers. It called `get_num_layers_to_build` and `get_transformer_layer_offset` without a pipeline rank or virtual stage, so both read the global pipeline rank. A model built on its own pipeline grid (a distillation teacher, an RL inference model, any builder given a `ProcessGroupCollection`) got the global stage's layers, while `TransformerBlock` numbered them by its collection's rank. With a PP=2 collection over a global PP=1 grid and three layers split 1 + 2, stage 1 built one layer instead of two. With a virtual pipeline, slicing the MoE layer specs asserted because `vp_stage` was missing.

**What.**
- `get_gpt_modelopt_spec` takes `vp_stage` and `pp_rank` and forwards them to both helpers, as `get_gpt_decoder_block_spec` does.
- `GPTModelBuilder` (through `default_layer_spec`, which also forwards `vp_stage`), `modelopt_gpt_hybrid_builder` and the distillation teacher pass their collection's pipeline rank.

**Tests.**
- New `tests/unit_tests/post_training/test_modelopt_spec_pipeline_stage.py`:
  - spec-level checks for uneven and virtual pipelines, with the global pipeline rank patched to raise;
  - a check that omitting the arguments still uses the global rank;
  - the three builders on a PP=2 grid over a global PP=1 grid.
- Updated the interface and dispatch tests.

Before the 2026-11-01 sync, on 4 GPUs against main, in three test groups (one of them merged with #8048): no regressions, 27 results fail on main and pass here, and 6 fail on both. In the integration run (main 77391e71cc with all #6307 PRs and the gap fixes merged), on 4 GPUs, the new file passes 13 tests, `test_gpt_builder.py` passes 66 (64 on main) and `test_modelopt_module_spec.py` passes 16 (15 on main). The extra tests in those two files come from other PRs in the run. In the integration run, this PR's test files show no regressions against main.

**Compatibility.**
- Both parameters default to `None`, so existing callers keep the global rank. The training loop's collection comes from the global grid, so its rank is unchanged.
- Forwarding `vp_stage` also fixes VPP with `account_for_embedding_in_pipeline_split` or `account_for_loss_in_pipeline_split` and the dense ModelOpt spec. On main the first or last virtual chunk got one extra layer spec.
- A custom `pipeline_model_parallel_layout` still uses the global rank until #8033 lands.
- The builder edits are byte-identical to the overlapping lines in #8048, so the two merge cleanly in either order and the second one shrinks on rebase. Until #8048 lands, only the ModelOpt branch of `default_layer_spec` forwards `pp_rank`, although the docstring copied from #8048 describes every block spec. In the merged tree the distillation teacher sets `pg_collection` twice, which is harmless. Would you rather keep this PR to core and tests and move the caller edits into #8048?
- #8741 adds `pg_collection` to `default_layer_spec`, so the two conflict in `megatron/training/models/gpt.py` and `test_gpt_builder.py`. Whichever lands second keeps both: `default_layer_spec(config, vp_stage, pp_rank=None, pg_collection=None)`.

The branch was synced with main 77391e71cc on 2026-11-01 by a merge commit, not a rebase. The merge had no conflicts, so existing commits and review links stay valid.
