# [MFSDP v2] Reuse local gradients across reduce-scatter windows

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8329) · state: open · merged: False

## Original PR description

## Design

Add opt-in `SchedulePolicy(reduce_scatter_interval=k)` to MFSDP v2. A module reuses one full local-gradient buffer per trainable parameter group, accumulates in main-gradient precision, and reduces every `k` completed backwards. The last microbatch flushes a shorter window; the default remains one reduction per backward.

## Why

Weight caching saves all-gathers but not reduce-scatters. Local gradient accumulation reduces the inner RS count from `m` to `ceil(m/k)` at the cost of retaining full gradients for selected modules. It is independent of weight-cache/trace-replay changes and preserves the configured communication dtype and final HSDP/HFSDP outer reduction.

## Validation

- Three focused tests cover gradient/update parity, delayed wgrad, and collective counts plus full-iteration CUDA-graph replay.
- NSC-LHR, 4 x GB300, job 274754: **14 passed per rank**, SLURM completed with exit code 0. The profiler verifies five microbatches use two reduce-scatters; full-iteration CUDA-graph replay matches the reference. No end-to-end speedup claim yet.
- Black 26.3, isort, pylint, and Ruff checks pass. Host mypy is limited by missing Torch/TE dependencies.

Scope: low-level experimental API only; no training CLI flag or baseline changes. Callers must mark each module's final backward before consuming gradients; partial-microbatch graph replay is not supported for advancing the interval.
