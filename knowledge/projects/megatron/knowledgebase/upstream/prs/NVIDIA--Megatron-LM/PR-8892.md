# Use the owning module's process groups in attention, layers and models

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8892) · state: open · merged: False

## Original PR description

Attention, layer and model code in `megatron/core` now uses the process groups of the module that owns it, not the global grid. This matters to callers that build a model on its own grid, such as MIMO, a vision encoder next to an LLM, or the checkpoint tools. On the standard grid the groups are the same as before. This PR consolidates 8 draft PRs unchanged. Each member is one commit, followed by a commit that regenerates `tools/process_group_usage_allowlist.json`, so review commit by commit. #8729 builds on #6293, so this PR depends on #6293. It lands after #6303, the core process-group API unit #8890 and the training I/O unit #8891, which edit some of the same files, such as `attention.py`, `utils.py` and the checkpoint loader. Part of #6307.

## Members

- #8817: Drop the WORLD barriers from RealQuant's per-layer verbose report. Removes two ungrouped `barrier()` calls per layer, which could hang uneven pipelines or a model that does not span every rank, and logs the report through `log_single_rank`.
- #8022: Use the model's process groups in BERT and in GPT's padding-mask scatter. `BertModel` passes its collection to every submodule and picks the first stage from its own PP group; `Pooler` takes an optional `tp_group`; GPT scatters the MoE padding mask over `pg_collection.tp`.
- #8023: Use MLA's own TP group for its collectives and checkpoint shards. The three MLA classes pass `self.tp_group` to their 10 mapping calls, `linear_q_proj` is built on `pg_collection.tp`, and `FusedMLASelfAttention.sharded_state_dict` uses the module's TP and DP x CP groups.
- #8025: Scatter LLaVA's language-model input over the model's TP group. The sequence-parallel scatter in `_process_embedding_token_parallel` uses `pg_collection.tp`, the group the language model is built on.
- #8033: Honor the caller's pipeline rank in custom layouts and the checkpoint converter. `get_transformer_layer_offset()` and `get_num_layers_to_build()` pass `pp_rank` to the layout, and the converter sets the rank of its fake pipeline group, which fixes PP > 1 conversions that built every stage as stage 0.
- #8044: Compute checkpoint replica ids over the module's own DP x CP group. `sharded_state_dict()` without metadata fills `dp_cp_group` from the module's collection, and the sharded-tensor helpers reject a `tp_group` without a `dp_cp_group`.
- #8722: Pass the owner's TP group to duplicated-mode linears. Duplicated `TELinear` accepts `tp_group`, every in-repo owner passes it, and `MoELayer` no longer patches `_tp_group` after construction.
- #8729: Use the module's groups in SelfAttention consistency check. The test-mode Q/K layernorm check compares over `dp_gtp_remat` and the module's TP group, which restores coverage of GTP-remat peers that #6293 dropped.

## Behavior changes for callers

- The ModelOpt duplicated `Linear` at TP > 1 records replica id `(0, tp_rank, dp_rank)` instead of `(0, 0, dp_rank)`, on the standard grid too. Post-training owners need to approve this checkpoint change (#8722).
- The DSA, simplified DSA and CSA indexers and the CSA compressor pass `tp_group=` to the spec's duplicated linear class. A custom class without that argument raises `TypeError` (#8722).
- `make_sharded_tensors_for_checkpoint`, `make_tp_sharded_tensor_for_checkpoint` and `make_sharded_tensor_for_checkpoint` raise `ValueError` for a `tp_group` without a `dp_cp_group`. No in-repo caller is affected (#8044).
- Under `test_mode` with `qk_layernorm`, an explicit collection without `dp_gtp_remat` or `tp` raises `ValueError` where main used the global DP group. `MultiTokenPredictionBlock` built without a collection hits this too (#8729).
- With `verbose`, the RealQuant report no longer synchronizes ranks and logs on the ranks `set_default_log_ranks` names (#8817).
- The checkpoint loader initializes a single-process gloo group, as the saver does, and sizes TP layers from its fake groups (#8033).

#8023, #8722 and #8729 touch registered kernel files but change only process-group plumbing, so this PR needs the `determinism-exempt` label.
