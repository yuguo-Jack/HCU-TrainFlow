# Integrate five inference pairwise campaigns and prefix-cache prompt scores

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8426) · state: closed · merged: True

## Original PR description

## What does this PR do?

Combines 34 active split PRs from five inference pairwise-testing campaigns with NVIDIA #7063 on one branch based on main. It brings together fixes and regression coverage for chunked prefill, MTP, DP coordination, batch invariance, disaggregated prefill, and cached prompt scores. It also adapts the combined tests to CI's H100 image and current main, so every affected CI bucket passes.

## Example failure scenario(s)

These examples illustrate the integrated behavior; the linked split PRs document each individual defect and regression.

**Scenario 1 (Cached prompt scores)**
- Request A computes a prompt and caches its KV blocks and prompt scores.
- Request B reuses that prefix and asks for prompt scores.
- Cached and newly computed scores must be returned in the correct order, including across prompt chunks.

**Scenario 2 (MTP stop boundaries)**
- A speculative decoding step accepts 4 tokens for request A, and a stop sequence ends at the second token.
- The engine trims the step at that boundary, so tokens, scores and events stay aligned.
- An EOS that completes a stripped stop sequence is stripped, exactly as in one-token steps.
- Proposal metrics count only the draft positions before the boundary.

**Scenario 3 (DP worker failure)**
- A worker owns requests A and B when it disconnects.
- The coordinator reports those owned requests as failed and removes their stale ownership.
- The coordinator stays available for replacement workers even if no worker can currently accept new requests.

**Scenario 4 (Batch-dependent low-precision scaling)**
- A caller enables batch invariance with a scaling mode that depends on the surrounding batch.
- Changing neighboring requests can change the arithmetic used for the same input.
- Configuration checks reject the incompatible scaling modes instead of promising invariant results.

**Scenario 5 (Disaggregated Mamba state lifetime)**
- A prefill worker detaches a request's Mamba state for transfer.
- Other requests arrive while the handoff still owns that state.
- The detached slot stays reserved until the handoff releases it, preventing premature reuse.

## How was this bug discovered?

The source campaigns compare ordinary and stressed execution using token/log-probability parity, exact ownership and lifecycle invariants, and runtime evidence that the intended interactions executed. Focused source audits also identified edge cases that received targeted regressions. Each linked split PR records its discovery and validation evidence.

Integrating with main exposed one behavior difference. Fork/74 kept an EOS that also ended a stripped stop sequence, but only inside multi-token MTP steps. Main's request-finalization test showed that the same tokens decoded one per step still strip it, so MTP and non-MTP output differed. This PR drops that tie rule.
