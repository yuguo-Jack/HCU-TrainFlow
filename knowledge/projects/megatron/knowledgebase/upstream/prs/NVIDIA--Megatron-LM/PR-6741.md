# [Dev] Add absolute row alignment for MTP sequence rolls

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/6741) · state: open · merged: False

## Original PR description

## Summary

- Add a layout-neutral sequence-roll context that aligns MTP fields from immutable source tensors using absolute offsets.
- Reuse the context across MTP forward inputs, learned positions, padding masks, SFT/RL cross-entropy, and E2E-TV targets in GPT, HybridModel, and CUDA Graph call paths.
- Preserve the existing cumulative-roll implementation as an atomic fallback for valid layouts that cannot use absolute addressing.

## Design

- Move sequence-roll infrastructure into `mtp_sequence_roll.py`, with layout-specific implementations for local CP1, contiguous packed CP, and scheduler-certified one-hop zigzag/dynamic CP.
- Validate each consumer's complete field group before communication. `prepare_fields()` returns an immutable sibling context, allowing geometry reuse and late-bound CE/TV payloads without mutating the original context.
- Materialized consumers obtain all required offsets together. E2E-TV instead passes source, halo, row indices, and valid-row metadata directly to the fused TV path, avoiding materialized full-vocabulary target rolls.
- Propagate a scheduler certificate for zigzag packed batches so the optimized path is selected only when the requested offsets fit within supported one-hop geometry. Missing certificates and unsupported multi-hop layouts retain the established fallback.

## Coverage added

- Unpacked and packed CP1, packed boundaries, implicit tails, padding, source immutability, and absolute offsets at multiple MTP depths.
- Contiguous packed CP, grouped mixed-field P2P, atomic fallback, geometry reuse, stale-field detection, and distributed global-sequence parity.
- Certified zigzag CP2 and dynamic/interleaved CP4, effective CP-group resolution, invalid metadata, and unsupported multi-hop fallback.
- Repeated and non-repeated MTP, learned positions, padding-mask scattering, SFT/RL objectives, native and fused-linear CE, and E2E-TV direct target rows.
- GPTModel, HybridModel, fine-grained callables, CUDA Graph argument matching, capture/replay, and full-iteration graph integration.

The design holds up well:
- Each consumer's field group is validated before any P2P.
- An unsupported layout falls back to the cumulative-roll path for that consumer's whole field group, so prepared and rolled fields are never mixed.
- Geometry reuse is guarded by source identity and version.
- The zigzag certificate is conservative: zero or unknown falls back, runtime `_assert_async` checks contradict an overstated certificate, and the certificate is disabled under `full_iteration` graphs.
- Distributed oracle tests cover CP2 and CP4.

### Most impactful findings
1. **[CRITICAL Correctness]** In [fine_grained_callables.py L778](https://github.com/NVIDIA/Megatron-LM/blob/a833ab16ed149160ac6ef576cc02a7b4f7be4b0f/megatron/core/models/gpt/fine_grained_callables.py#L778), the mHC attention-CUDA-graph replay branch overwrites the `padding_mask` kwarg with `node.chunk_state.padding_mask`.
   - The new prepared MTP path deliberately leaves that field as the unrolled decoder mask, so every MTP depth's graphed MoE routing (z-loss, dropless gating, aux-loss-free load counters) uses a mask that is misaligned by `d` positions.
   - The eager path routes with the correct mask. Before this PR the legacy path mutated `chunk_state.padding_mask`, so this line was correct then.
   - The fix is one line.
2. **[IMPORTANT Compatibility]** [`ZigzagPackedCPRollContext`](https://github.com/NVIDIA/Megatron-LM/blob/a833ab16ed149160ac6ef576cc02a7b4f7be4b0f/megatron/core/transformer/mtp_sequence_roll.py#L1073) inherits the base `prefetch_halos`, which raises `NotImplementedError`.
   - `prepare_mtp_sequence_roll_context` now returns this context for certified zigzag batches, where the merge base returned `None`.
   - Callers that still use the documented merge-base pattern `ctx.prefetch_halos(...)` therefore crash on the first certified microbatch.
   - The PR already adds the equivalent no-op shim for `LocalRollContext`; zigzag needs the same one.
