# build: install cuBLAS 13.8.1 in the dev CI image

## What does this PR do?

Install cuBLAS 13.8.1 (package version `13.8.1.7`) in the dev CI image to pick up the fix for:
A standalone CUDA C++ reproducer on two GB200 GPUs shows cublasLtMatmul intermittently leaving output elements unchanged during concurrent NCCL communication, despite beta=0. One process uses one host thread per GPU, with no PyTorch or Transformer Engine dependency. Routing to cuBLASLt for investigation; attribution among cuBLAS, NCCL, the driver, and hardware remains unresolved.

The Docker build selects the official CUDA 13 archive for x86_64 or Arm SBSA and replaces the toolkit's cuBLAS/cuBLASLt libraries and headers before compiling native dependencies. Installing into the existing toolkit paths ensures PyTorch uses the updated libraries. `CUBLAS_VERSION` is a build argument.

Sources: [13.8.1 download archive](https://developer.nvidia.com/cublas-13-8-1-download-archive), [version metadata](https://developer.download.nvidia.com/compute/cublas/redist/redistrib_13.8.1.json).

## Validation

- Dockerfile build checks passed against the cached NGC PyTorch 26.06 image.
- Built the added installation layer on Arm64 with NGC PyTorch 26.06. Both cuBLAS and cuBLASLt report 13.8.1, headers report 13.8.1.7, and the PyTorch process maps both updated `.so.13.8.1.7` files.
- Built the same installation layer on x86_64 with Ubuntu 24.04. Both runtime libraries report 13.8.1, headers report 13.8.1.7, and the unversioned/SONAME symlinks resolve to the updated files.
- Shell syntax, `git diff --check`, and `CHECK_ONLY=true bash tools/autoformat.sh` passed; no Python files changed.

The initial local PyTorch loading check used cached NGC PyTorch 26.06 because resolving the then-configured 26.08 image returned an authorization error. After rebasing onto main, Dockerfile build checks also passed against NGC PyTorch 26.09. Earlier [GPU CI run `36493748270`](https://github.com/NVIDIA/Megatron-LM/actions/runs/36493748270) predates checksum removal and the rebase onto PyTorch 26.09. A full dev image build and GPU validation have not been rerun locally for the current revision.
