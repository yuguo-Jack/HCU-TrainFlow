# Require an explicit process-group collection in LanguageModule

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/6303) · state: open · merged: False

## Original PR description

[Scoped diff of this PR's own changes](https://github.com/Connor-XY/Megatron-LM/compare/8d10a53d52...yx/pstate-d1-require-pg-collection). The full diff also shows #6293's commits until it merges.

**Depends on #6293 and #7487.** Until they merge, please review the scoped diff linked above. It compares this branch with #6293's head, so it shows only this PR's changes. NVIDIA-NeMo/Megatron-Bridge#6151 updates Bridge's providers to pass collections; with the deprecation below it is a follow-up rather than a prerequisite. Callers that pass a collection are subject to the behavior changes below.

**Why.** `LanguageModule` (the base of `GPTModel`, `BertModel`, `T5Model`, `HybridModel` and `MambaModel`) falls back to the global parallel grid when its caller omits or only partly supplies `pg_collection`, so a language model built on its own grid silently uses another model's groups (#6307).

**What.**
- All in-repo constructors pass a collection: model builders and providers, keyword-expanded ModelOpt calls, MIMO ModuleSpecs, examples and tests (176 direct constructor calls, 7 keyword-expanded calls and 9 ModuleSpecs audited). Three HybridModel constructions in tests added upstream after this audit (`test_wide_residual_mtp_mimo.py`, `test_wide_residual_tp_sync.py`) still use the deprecated fallback. The five GPTModel constructions in `tests/unit_tests/rl/test_rl_utils.py` also use it; this PR does not touch that file. The GPTModel and HybridModel constructions that main added in five other test files (`coordinator_pairwise_utils.py`, `batch_invariant_test_utils.py`, `test_batch_invariant_models.py`, `test_pos_embedding_cuda_graph.py`, `test_hybrid_mhc.py`) pass `ProcessGroupCollection.use_mpu_process_groups()`. Compatibility providers keep caller-owned collections.
- Only a caller's collection is validated: it must define `tp`, `cp` and `pp`; a missing `embd` warns and counts as `None`; once distributed is initialized, `tp`/`cp`/`pp` must be participating groups (including singleton dimensions); a non-participating embedding stage uses `embd=None`; PyTorch's `NON_GROUP_MEMBER` sentinel is rejected. Violations raise `ValueError`. Offline construction may use explicit `None` fields.
- T5 keeps only its tied-pipeline embedding check and runs it after `LanguageModule`; the shared checks live in `LanguageModule`.
- Copyright headers added to three touched files that lacked one.

**Behavior changes for callers that pass a collection.**
- A missing `tp`, `cp` or `pp` field raises `ValueError`. On main, a missing field read as `None`.
- With `torch.distributed` initialized, `tp`, `cp` and `pp` must be participating groups, and `None` raises `ValueError`. On main, `tp=None` fell back to the global tensor-parallel group with a `DeprecationWarning` once `parallel_state` was initialized, and `cp=None` or `pp=None` was kept.
- `NON_GROUP_MEMBER` in `tp`, `cp`, `pp` or `embd` raises `ValueError`. On main it was accepted. A non-participating embedding stage passes `embd=None`.
- A collection without an `embd` field emits a `FutureWarning` and is treated as `embd=None` for every language model. It becomes an error in Megatron Core 0.23. On main it read as `None` without a warning.
- `T5Model` checks tied pipeline stages after `LanguageModule`. With tied embeddings and pipeline parallelism, a first or last stage whose `embd` is missing or `None` raises `ValueError`.

**Deprecations.** Omitting `pg_collection` from a `LanguageModule` subclass still works during the deprecation period: the global collection is used, as today, and is not validated. It goes through the same helper as #6293, so a `FutureWarning`, once per class and attributed to the first caller outside Megatron Core and torch, says the fallback is deprecated since Megatron Core 0.21 and will be removed in 0.23.

**Tests.** `tests/unit_tests/models/test_language_module.py` covers the validation rules, the missing-`embd` warning and the deprecated fallback (now expecting the `FutureWarning` and checking that the fallback collection is not validated); T5 covers both paths. Constructor-only change: no performance impact, no checkpoint format change.
