# Require an explicit process-group collection in LanguageModule

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/6303) · state: open · merged: False

## Original PR description

[Scoped diff of this PR's own changes](https://github.com/NVIDIA/Megatron-LM/compare/Connor-XY:yx/pstate-p34-rebased...Connor-XY:yx/pstate-d1-require-pg-collection). The full diff also shows #6293's commits until it merges.

**Depends on #6293 and #7487.** Until they merge, please review the scoped diff linked above. It compares this branch with #6293's branch, so it shows only this PR's changes. NVIDIA-NeMo/Megatron-Bridge#6151 updates Bridge's providers to pass collections; with the deprecation below it is a follow-up rather than a prerequisite.

**Why.** `LanguageModule` (the base of `GPTModel`, `BertModel`, `T5Model`, `HybridModel` and `MambaModel`) falls back to the global parallel grid when its caller omits or only partly supplies `pg_collection`, so a language model built on its own grid silently uses another model's groups (#6307).

**What.**
- All in-repo constructors pass a collection: model builders and providers, keyword-expanded ModelOpt calls, MIMO ModuleSpecs, examples and tests (176 direct constructor calls, 7 keyword-expanded calls and 9 ModuleSpecs audited). Three HybridModel constructions in tests added upstream after this audit (`test_wide_residual_mtp_mimo.py`, `test_wide_residual_tp_sync.py`) still use the deprecated fallback. Compatibility providers keep caller-owned collections.
- A supplied collection is validated: it must define `tp`, `cp`, `pp` and `embd`; once distributed is initialized, `tp`/`cp`/`pp` must be participating groups (including singleton dimensions); a non-participating embedding stage uses `embd=None`; PyTorch's `NON_GROUP_MEMBER` sentinel is rejected. Violations raise `ValueError`. Offline construction may use explicit `None` fields.
- T5 keeps only its tied-pipeline embedding check; the shared checks live in `LanguageModule`.
- Copyright headers added to three touched files that lacked one.

**Deprecations.** Omitting `pg_collection` from a `LanguageModule` subclass still works during the deprecation period: the global collection is used, as today. It goes through the same helper as #6293, so a `FutureWarning`, once per class and attributed to the first caller outside Megatron Core and torch, says the fallback is deprecated since Megatron Core 0.20 and will be removed in 0.22.

**Tests.** `tests/unit_tests/models/test_language_module.py` covers the validation rules and the deprecated fallback (now expecting the `FutureWarning`); T5 covers both paths. Constructor-only change: no performance impact, no checkpoint format change.

**Rebased onto main `a07014bbd`** (2026-10-08), restacked on #6293's review follow-up. #7591's RNGConfig migration rewrote the `global_vars` import in `examples/bert/pretrain_bert.py`. Its `get_run_config` import is kept, inside this PR's sorted import block. This PR's `examples/t5/pretrain_t5.py` hunk is now empty, because #6293 already passes the caller's collection through in the same form. One new commit, "Expect FutureWarning from the LanguageModule fallback", follows #6293's switch to `FutureWarning`. On the new head, 4 GPUs: the language-module, fallback, T5, Bert, GPT, LLaVA, heterogeneous-GPT, hybrid-MoE and fused-MLA pre-MLP-norm tests give 144 passed / 1 skipped / 7 failed. All 7 also fail on main because they need 8 ranks, and all 7 pass on 8 GPUs (2×4). An entry-point smoke test passes: the T5 and BERT providers keep a caller-supplied collection (main fails both checks).

**Merged #6293's branch** (2026-10-09), which merged main `c4129afff`. New commit: "Give the checkpoint converter a context-parallel group".
- The checkpoint saver starts a one-process `torch.distributed` world and builds its models without a collection, so `LanguageModule` falls back to the global groups the converter fakes.
- The converter faked no context-parallel group, so the fallback collection had `cp=None`, which `LanguageModule` rejects once `torch.distributed` is initialized.
- The converter now installs a size-one fake context-parallel group, and a new test checks that the collection built from the fake groups passes `LanguageModule`'s checks.

**Counts.** With #6293: 182 global process-group reads in `megatron/core` (210 on main); about 160 once the deprecated fallbacks are removed. The last commit refreshes #6258's allowlist (183 → 182, removal only).

Landing order: #7487 → #6293 → #6303. Part of #6307.
