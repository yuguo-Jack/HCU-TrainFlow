Scope is GLM-5.3-Flash text training on `dev`. The released text architecture
has 45 attention/FFN blocks (34 KDA and 11 NoPE sparse MLA/DSA), KPool size 4,
four mHC residual streams, 288 routed experts and one MTP depth. The hybrid
stack builds these as 90 separate attention and FFN modules. Training uses a
frozen KPool selector; trainable pool-aware indexer pretraining is not specified
upstream and is not covered. Inference, multimodal training and speculative
decoding are out of scope.

  causes:
  - `ClampReplay` decides clamps with the installed torch's boundary rule.
    PyTorch 2.14 gives zero `clamp` gradient to a value exactly on the bound
    ([pytorch#184572](https://github.com/pytorch/pytorch/issues/184572)), so the
    rule is `>=`/`<=` there and `>`/`<` before. A probe picks the rule, not a
    version check, because the change landed within the 2.14 series.
  - The single-stream MTP case also replays its MTP expert clamp decisions, as
    the real-HybridModel MTP case already did.
  - The near-tie band is per row: `max(0.125, 6 * d_i * ||W_j||)`. `W_j` is the
    reference's FC1 weight row of the element's output column. `d_i` is the
    RMS, over the element's row (gate and up, flipped elements excluded), of
    the FC1 difference divided by each column's weight norm. The fixture draws
    weight rows independently of the input, so this is the element's expected
    rounding-level spread, measured per token. The old band multiplied one
    call-level relative difference by a column RMS over only the ~15 rows
    routed to an expert.

    replay were first measured in a diagnostic GPU run on this image (MTP
    incoming hidden gradient 0.99997); the amendment was recorded before the
    confirmation run.

## Changes

- Ports of two main PRs (merged into main on 2026-10-28, not yet on `dev`),
  each pinned to the head named in its commit message:
  - [#7054](https://github.com/NVIDIA/Megatron-LM/pull/7054): GLM-style two-stage
    low-rank KDA gates, `kda_disable_fp8` for the KDA projections,
    `HybridModel.output_processor` and the shared GDN-family `"gdn"` whole-layer
    recompute. Dev builds its CLI from `TransformerConfig`, so the PR's
    `KDALayerConfig` fields become `TransformerConfig` fields and CLI flags.
  - [#7521](https://github.com/NVIDIA/Megatron-LM/pull/7521): opt-in
    `mhc_norm_eps_inside_sqrt` and `mhc_keep_mappings_in_fp32`,
    `mhc_learned_output_contract` (FP32-accumulated mean contraction when False)
    in the HybridStack post-process and the MTP layer, an FP32 projection/RMS,
    viewless mHC full-recompute boundaries, forward autocast replay in
    `tensor_parallel.checkpoint`, and the Sinkhorn input detach.
- Local fixes:
  - `kda_disable_fp8` also covers dev's GPT KDA spec, and dev's zigzag chunkwise
    KDA CP cases are kept as a separate test.
  - The caller-owned mHC H-aggregate (dev's attention CUDA-graph split) reduces
    mixed FP32/BF16 inputs in FP32, rounds once and passes detached inputs to its
    compiled forward; hybrid-stack mHC contraction and MTP tests are added.
  - `--no-mla-proj-use-quantization` (alias
    `--disable-mla-proj-use-quantization`) exposes
    `MLATransformerConfig.mla_proj_use_quantization`; GLM-5.3 keeps the MLA
    projections in BF16, as the HF reference does.
  - KPool: a rank with zero query rows returns a fixed-width empty selection
    instead of crashing, and the sparse-attention nonempty-row certificate is
    refused for KPool without the tail.
  - A clamped SwiGLU (`activation_func_clamp_value`) is allowed in dense MLPs, as
    the GLM-5.3 dense FFN needs. `TEFusedMLP` rejects the clamp, because its TE
    activation ops do not clamp.
  - The training FLOPs estimate counts KPool sparse-attention and pooled-indexer
    pairs, hybrid DSA layers and two-stage KDA gates.
- GLM-5.3 integration (numerical oracle
  `huggingface/transformers@93c8b7b485963a10800c91f55304db6be211c2bd`). These
  default-off options are intended to reproduce the HF GLM5Next arithmetic, and
  existing models keep their paths:
  - GLM5Next RMSNorm rounding before gamma, with an exact bounded VJP;
  - KDA HF beta and convolution precision, plus an opt-in FP32 recurrent core
    (`kda_core_in_fp32`; FP32 tensors, but FLA's Triton dot products run in TF32
    by default) that supports CP1 only and fails closed otherwise;
  - mHC normalize-before-projection and pre-coefficient precision, single-stream
    MTP, and opt-in activation-dtype residual rounding
    (`mhc_preserve_activation_dtype_rounding`);
  - KPool HF scoring and compression arithmetic, with the chunked selection
    under `no_grad`;
  - KPool explicit-mask pool origin (not behind an option): with an explicit
    mask and no packing, KPool starts pooling at each sample's first valid key,
    as in HF GLM5Next. A zero offset is an exact identity, so no-mask, varlen,
    packed and pool-aligned explicit masks keep their selections bit for bit;
  - opt-in post-FC2 router-probability weighting for `TEGroupedMLP`
    (`moe_apply_probs_after_fc2`; non-quantized BF16/FP32 only and rejected for
    every quantized path);
  - the GLM hybrid layer specification and config/CLI wiring.
- Tests: composite hybrid-block and MTP parity tests against an independent,
  source-pinned native reference (reduced depth, production width), an opt-in
  mutation diagnostic (`GLM53_COMPOSITE_DIAG=1`), and blockwise FP8 tests for
  grouped-MoE parameter gather and the GLM-5.3 precision profile.
