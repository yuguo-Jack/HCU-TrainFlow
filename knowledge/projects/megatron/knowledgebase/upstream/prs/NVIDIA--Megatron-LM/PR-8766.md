# Count core calls of every deprecated parallel_state function

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8766) · state: closed · merged: False

## Original PR description

Depends on #8022, #8054, #8058, #8751 (which contains #8017, #8029 and #8049) and #8765. Please review the diff from their merge: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/3e1bc2b801...yx/pstate-m1-checker-functions).
- The checker counts the functions that #8765 decorates. The last commit rewrites the coverage note that #8765 adds to `docs/api-backwards-compatibility-check.md` and `parallel_state.py`. #8767 stacks on this PR and edits the text that commit writes.
- On this base the new scan adds exactly three allowlist entries. #8022 removes a fourth call, `is_pipeline_first_stage` in `BertModel.forward`, and #8751 routes three more in `megatron/core/inference/communication_utils.py` through one warned helper.
- Comment-only edits touch tests from #8017, #8054 and #8058.
- The merge of #8058 takes the pipeline group from the wrapper (#8054) and the data-parallel group from the collection resolved for the model (#8058) in `text_generation_controller.py`. The merges regenerate the process-group allowlist where it conflicted.

**Why.** Megatron Core's own calls of deprecated `parallel_state` functions do not emit `ParallelStateDeprecationWarning`. `tools/check_process_group_usage.py` counted only the group, rank and size accessors. A new core call of a stage predicate, a virtual-pipeline getter or setter, `get_all_ranks()`, a rank or size override, a dynamic context-parallel group map or a memory-buffer alias went unreported. `save_modelopt_state` was one: it silently set the global virtual-pipeline rank for each model chunk.

**What.**
- `save_modelopt_state` no longer sets the global virtual-pipeline rank. Megatron Core passes `vp_stage` explicitly, and no code in `megatron/`, `examples/`, `tools/` or `tasks/` outside `parallel_state` reads that rank. Neither does `mto.modelopt_state()` in nvidia-modelopt 0.45, the call the rank was set for. The write also left the rank at the last chunk's index after every save.
- The checker counts Megatron Core calls of every function that `_deprecated_accessor` decorates. Those that are not group, rank or size accessors get a new entry kind, `function`, ratcheted like the accessors. They get a kind of their own because the test helpers that forbid the global grid stub exactly the accessors, and expect `get_all_ranks`, the virtual-pipeline getters and `get_global_memory_buffer` to keep working. That set does not change.
- The allowlist records the three existing calls. All three sit in fallbacks that warn for a caller that omitted its groups or sizes: `get_all_ranks` in `log_config_to_disk`, and the virtual-pipeline size in `get_forward_backward_func` and `mtp_on_this_rank`. It goes from 136 to 139 entries: 105 accessor, 3 function, 16 shim, 15 guarded. `--update` refuses new entries by design, so the entries were written with its writer after checking that the scan adds only these.
- A new `function` use fails with a line that points to the function's own replacement, which its decorator names: the model chunk's `vp_stage`, the configuration's virtual-pipeline size, the stage helpers of `megatron.core.pipeline_parallel.utils`, or `megatron.core.utils` for the memory buffer. The output and the allowlist comment now say "uses of global parallel_state", since setter calls count too.
- `docs/api-backwards-compatibility-check.md` and the comment in `parallel_state.py` state the new coverage and name the two files the checker exempts.

**Tests.**
- New checker tests: a call of every decorated function in `parallel_state` is counted, other deprecated functions are flagged, a call right after a fallback warning is not counted as guarded, and a new `function` use gets the replacement hint while a new group read does not.
- New `test_multiple_models_leave_the_global_virtual_pipeline_rank_alone` in `test_modelopt_checkpointing.py`. The existing test of the indexed keys no longer mocks `mpu`.
- Test comments that said the checker does not count the stage predicates now say how it counts them.

On this branch the checker prints "OK: no new uses of global parallel_state (139 grandfathered, 15 of them guarded)". `test_check_process_group_usage.py` passes 39 tests, against 35 on the base. Before the sync with main, the 6 edited test files ran on 4 CPU ranks with Gloo, with the same results per test as on the stacked version, apart from tests that come from PRs this base does not contain. The 4 new checker tests pass. The ModelOpt test skips on CPU, where ModelOpt is not installed.

On 4 GPUs against its base: `test_check_process_group_usage.py`: 39 passed here vs 35 on the base, and the 4 new tests pass. `test_modelopt_checkpointing.py`: 14 passed vs 13, and the new test passes. `test_inference_process_group_fallbacks.py` (11), `test_inference_process_groups.py` (11) and `test_process_group_test_helpers.py` (18) pass the same tests on both sides, and `test_utilities.py` passes on both sides. Six related test files (RL utilities, dataset providers, initialization lifecycle, the inference API, `parallel_state` accessor uses and the deprecation tests) also pass the same number of tests on both sides. No test fails on either side. In the integration run, this PR's test files show no regressions against main.

**Compatibility.**
- No API change. `save_modelopt_state` produces the same state dict.
- Code that read `get_virtual_pipeline_model_parallel_rank()` after a ModelOpt save no longer sees the last chunk's index. No in-repo code does.
- Before merging, check that the nvidia-modelopt in the CI container (`pyproject.toml` requires 0.47 or later) does not read the global virtual-pipeline rank either: `grep -rn 'get_virtual_pipeline_model_parallel_rank\|_VIRTUAL_PIPELINE_MODEL_PARALLEL_RANK'` over the installed package. The evidence so far is from 0.45.
- The allowlist grows once, by three existing warned calls, because the checker covers more functions. It records no new read.
- The checker's `--stats` output gains a `function` line, and its first line, OK line and error header use the new wording. Nothing in the repository parses them, and the CI step is report-only.
- `_is_deprecated_accessor`, which the forbid-the-grid test helpers use, returns the same values as before.
- `determinism-exempt` is needed only while the PRs below this one are unlanded. CI diffs against main, and the base contains registered kernel files. This PR's own diff passes the coverage check.
