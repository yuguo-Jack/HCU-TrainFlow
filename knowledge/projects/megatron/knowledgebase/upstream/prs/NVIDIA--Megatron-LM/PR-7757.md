## What does this PR do?

Fix `Invalid FSDP module phase transition: Phase.BACKWARD -> Phase.BACKWARD` when `mtp_use_repeated_layer=True` reuses the same FSDP-wrapped block across MTP depths:

```python
h1 = block(fuse(h0, shifted_embeddings_1))
h2 = block(fuse(h1, shifted_embeddings_2))
(loss1(h1) + loss2(h2)).backward()
```

One backward visits both invocations, entering depth 2 and then depth 1. Each shared parameter's post-accumulate hook fires once after both uses contribute, so the second module entry sees `BACKWARD` while the weights are already gathered.

Make `pre_backward()` return when backward is already active. This avoids duplicate setup and leaves the existing gradient-ready callback responsible for reduction, resharding, and resetting the phase.
