# feat(transformer): add shared-prefix forest attention

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8156) · state: open · merged: False

## Original PR description

# feat(transformer): add shared-prefix forest attention

## What this PR does

Adds exact attention over a shared-prefix layout, in which each prompt is
stored once and followed by its completions:

- a prompt token attends the prompt causally;
- a completion token attends the whole prompt and its own completion
  causally, never a sibling completion or another prompt.

A star is one prompt followed by its completions. A forest is several stars
stored back to back in one packed sequence.

RoPE positions restart at the prompt length for each completion. Nothing calls
this attention unless a caller passes the new keyword-only
`shared_prefix_forest` argument, so existing attention behavior is unchanged.

## Changes

- `megatron/core/shared_prefix_layout.py`: the layout descriptor.
  - `SharedPrefixLayout` describes one star `[prompt, c_1, ..., c_G]`, and
    `SharedPrefixForestLayout` describes several.
  - They provide dense-row indices, positions, CP zigzag ownership and per-row
    token multiplicities, and their `forest` tuples are what the attention
    consumes.
  - CP zigzag ownership (`cp_local_indices`) returns main's
    `build_zigzag_cp_local_positions` from
    `megatron/core/transformer/experimental_attention_variant/dsa_layout.py`.
  - They also carry logical (unpadded) completion lengths and the MTP
    loss-group partition, which the HybridModel integration (#7914) uses and
    tests.
  - The module sits next to `packed_seq_params.py` because the SSM and model
    code (#8157, #7914) import it.
- `megatron/core/ops/attention/shared_prefix.py`: the forest kernel.
  - `flash_composed_forest_attention` runs a whole forest in at most two
    FlashAttention 2 varlen passes and merges them by log-sum-exp: a causal
    self pass and a non-causal completion-to-prompt pass.
  - Its backward is exact and accumulates every completion's contribution into
    the shared prompt keys and values in FP32. Under
    `torch.use_deterministic_algorithms(True)`, which `--deterministic-mode`
    enables, it uses FlashAttention's deterministic backward and a
    deterministic `index_add_`, so the accumulation order is fixed.
  - `flash_composed_forest_attention_cp` runs the same computation on zigzag
    CP shards through sequence-to-head all-to-alls, including replicated GQA
    KV heads. It restores token order with the CP load-balancing helpers in
    `megatron/core/ssm/mamba_context_parallel.py`, as the Gated DeltaNet and
    Gated Delta Product context-parallel code does. With a CP group of size 1 it calls
    `flash_composed_forest_attention`.
  - `require_shared_prefix_flash_attn` checks and binds flash-attn once
    through `megatron.core.ops._backends.require`:
    `flash_attn.flash_attn_interface` with `flash_attn_varlen_func`, the
    private `_flash_attn_varlen_backward` and `min_version="2.7.0"`. A missing
    or older flash-attn raises `ImportError`. The forward and backward call
    the bound module and do not import flash-attn themselves.
  - The pass plan, including the varlen offsets and maximum lengths, is built
    on the host for every forest. The kernel therefore cannot be captured in a
    CUDA graph.
- `megatron/core/transformer/shared_prefix_attention.py`: the caller-side
  validation. It stays outside `megatron/core/ops` because it inspects
  `SelfAttention` and its core attention.
  - `validate_shared_prefix_attention(attention, *, tp_size, cp_size)` reads
    `attention.config`. A caller runs it on every attention layer before any
    layer executes. It rejects:
    - any module that is not a `SelfAttention`, and a `SelfAttention` whose
      core attention is not `DotProductAttention` or `TEDotProductAttention`;
    - selective core-attention recompute, QK-clip statistics, sliding
      windows, non-vanilla softmax, attention dropout, logit softcapping and
      batch-invariant mode;
    - FP8 attention (`fp8_dot_product_attention`, `fp8_multi_head_attention`),
      because the forest always runs FlashAttention 2 in fp16/bf16;
    - CUDA graphs (any `cuda_graph_impl` other than `"none"`);
    - TP or CP group sizes that differ from the caller's, and uneven CP head
      splits.
  - Its last step calls `require_shared_prefix_flash_attn`. A caller that
    validates every layer first therefore fails before any layer runs when
    flash-attn is missing or older than 2.7.
- `Attention.forward_pre_attn_and_core_attn`, and through it
  `Attention.forward`, take a keyword-only `shared_prefix_forest` (a
  `SharedPrefixForestLayout`, `None` by default), following
  `packed_sequence_cp_metadata`. When a caller passes it to a `SelfAttention`,
  `flash_composed_forest_attention_cp` on the layer's CP group replaces
  `core_attention`.
  - The branch rejects packed-sequence parameters, external masks or biases,
    non-fp16/bf16 inputs, inference contexts that reach core attention, and
    CUDA stream capture.
  - It does not check the module settings above itself; callers run
    `validate_shared_prefix_attention` first.
- `TransformerLayer._forward_attention`, and through it
  `TransformerLayer.forward`, take the same keyword and pass it to
  `self_attention` only when it is set. Without a forest, attention modules
  whose `forward` does not take the keyword, such as multi-latent attention,
  never receive it.

The kernel is registered in the determinism manifest and listed in the op
catalog and in the `megatron/core/ops` README.

## Notes for reviewers

- On prompt-heavy stars, forward-plus-backward peak memory is dominated by
  FlashAttention 2's grouped-query dK/dV expansion of the gathered prompt keys
  and values. That term grows roughly linearly with the number of completions.
- The forest travels as a call argument, not inside `PackedSeqParams`.
  Several consumers, such as `get_rotary_seq_len` and the `split_qkv` choice
  in `Attention`, treat any non-None `packed_seq_params` as THD packing. As an
  argument, the forest is part of every call, including a checkpointed
  callable that replays the layer.
- Supporting CUDA graphs would need fixed-capacity forest metadata on the
  device. This PR does not attempt it.
- #8157 (Mamba state fork) and #7914 (HybridModel integration) build on the
  layout. #7914 runs `validate_shared_prefix_attention` on every
  self-attention layer and then passes `shared_prefix_forest` with each
  attention layer call.
