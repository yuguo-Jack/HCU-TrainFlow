# feat(transformer): add shared-prefix forest attention

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8156) · state: open · merged: False

## Original PR description

# feat(transformer): add shared-prefix forest attention

## What this PR does

Adds exact attention over a shared-prefix layout, in which each prompt is
stored once and followed by its completions:

- a prompt token attends the prompt causally;
- a completion token attends the whole prompt and its own completion
  causally, never a sibling completion or another prompt.

RoPE positions restart at the prompt length for each completion. Nothing calls
this attention unless a caller sets the new per-call slot, so existing
attention behavior is unchanged.

## Changes

- `megatron/core/shared_prefix_layout.py`: the layout descriptor.
  - `SharedPrefixLayout` describes one star `[prompt, c_1, ..., c_G]`, and
    `SharedPrefixForestLayout` describes several.
  - They provide dense-row indices, positions, CP zigzag ownership and per-row
    token multiplicities, and their `forest` tuples are what the attention
    consumes.
  - They also carry logical (unpadded) completion lengths and the MTP
    loss-group partition, which the HybridModel integration (P6) uses and
    tests.
  - The module sits next to `packed_seq_params.py` because the SSM and model
    code (P5, P6) import it.
- `megatron/core/transformer/shared_prefix_attention.py`:
  - `flash_composed_forest_attention` runs a whole forest in at most two
    FlashAttention varlen passes and merges them by log-sum-exp: a causal
    self pass and a non-causal completion-to-prompt pass.
  - Its backward is exact and accumulates every completion's contribution into
    the shared prompt keys and values in FP32. Under
    `torch.use_deterministic_algorithms(True)`, which `--deterministic-mode`
    enables, it uses FlashAttention's deterministic backward and a
    deterministic `index_add_`, so the accumulation order is fixed.
  - `flash_composed_forest_attention_cp` runs the same computation on zigzag
    CP shards through sequence-to-head all-to-alls, including replicated GQA
    KV heads.
  - Validation for callers, to run before any layer:
    - `validate_shared_prefix_attention` rejects any module that is not a
      `SelfAttention`, and a `SelfAttention` the forest kernel cannot run: selective core-attention recompute, QK-clip statistics, sliding
      windows, non-vanilla softmax, attention dropout, logit softcapping, TP or
      CP group sizes that differ from the caller's, and uneven CP head splits;
    - `require_shared_prefix_flash_attn` rejects a missing flash-attn or one
      older than 2.7.
- `Attention._shared_prefix_forest`: a class-level per-call slot, `None` by
  default. When a caller sets it on a `SelfAttention`, the forest kernel
  replaces `core_attention`. Attention subclasses that override `forward`, such
  as multi-latent attention, never read it.
  - The branch rejects packed-sequence parameters, external masks or biases,
    non-fp16/bf16 inputs, and inference contexts that reach core attention.
  - It does not check the module settings above itself; callers run
    `validate_shared_prefix_attention` first.

The kernel is registered in the determinism manifest and listed in the op
catalog.

- four GPUs: 351 passed on every rank, including CP1/2/4.

This branch alone on top of main also ran the surrounding regression suites (routers, attention, MTP, Mamba, training, RL) on one and four GPUs. Every failure in those runs also occurs on main in the same container: tests that need more ranks than the run had, and missing APEX extensions.

## Notes for reviewers

- On prompt-heavy stars, forward-plus-backward peak memory is dominated by
  FlashAttention 2's grouped-query dK/dV expansion of the gathered prompt keys
  and values. That term grows roughly linearly with the number of completions.
- P5 (Mamba) and P6 (HybridModel) build on the layout.

## Shared-prefix stack

This PR is one of seven that #7914 was split into; #7914 itself is now P6, the
HybridModel integration. Each one needs fewer CODEOWNERS groups and can be
reviewed on its own. Shared-prefix
execution stores a prompt once per star (by default up to 16 completions of the
same group)
and runs those completions against it, instead of repeating the prompt in every
packed row.

| PR | Branch | Reviewer groups | Depends on |
|---|---|---|---|
| P1 #8152 RL packing library | `shared-prefix/p1-rl-packing` | reinforcement-learning | — |
| P2 #8153 MoE multiplicities and recompute context | `shared-prefix/p2-moe-multiplicities` | core, mixture-of-experts | — |
| P3 #8155 MTP loss groups | `shared-prefix/p3-mtp-loss-groups` | core, transformer | — |
| P4 #8156 forest attention and layout | `shared-prefix/p4-forest-attention` | core, transformer | — |
| P5 #8157 Mamba state fork | `shared-prefix/p5-mamba-state-fork` | core, hybrid-model | P4 |
| P6 #7914 HybridModel integration | `shared-prefix/hybrid-kernels-20261006` | core, hybrid-model | P1, P2, P3, P5 |
| P7 #8158 RL packaging | `shared-prefix/p7-rl-packaging` | ci, training | P1 |

P1 to P4 can merge in any order. A dependent branch carries its dependencies'
commits until they merge; review only its last commit.

Without a caller, P2 to P5 do not change existing numerics. Two P2 changes do
apply to every caller, and both keep results unchanged:

- recomputation through `tensor_parallel.checkpoint` and
  `CheckpointWithoutOutput` restores the forward pass's `contextvars` context
  (`te_checkpoint` is unchanged);
- the router GEMM backward skips gradients nobody requested.

P1 changes `megatron.rl` import-time behavior (lazy request types, lazy log
file). P6 is the first PR that wires the feature into a model.

File: `megatron/core/transformer/shared_prefix_attention.py` · line 238

Can we keep the head-dimension padding for backward too? With kv_channels=100, flash_attn_varlen_func pads Q/K/V to 104 internally and slices the output back to 100, but this call passes the original 100-wide tensors to the private backward, which requires a multiple of 8. That lets forward succeed and then fails on the first backward. We need to pad the backward inputs and gradient buffers consistently and slice the gradients back, or reject these head sizes before forward.

- jalbericiola · comment · 2026-10-17T12:47:08Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/8156#discussion_r4302704565)

File: `megatron/core/transformer/shared_prefix_attention.py` · line 238

Good catch, thanks. Fixed in 577d54a by padding, not by rejecting those head sizes. The backward now zero-pads Q, K, V, the merged output and dout to the next multiple of 8, the same way flash_attn_varlen_func’s own backward does, and slices dq/dk/dv back. Zero columns change neither the scores nor rowsum(dout * out), so the gradients stay exact. test_composed_attention_matches_independent_reference now also runs with head dim 100 against the fp64 reference. Without the fix, all 20 head-dim-100 cases fail on the first backward with head_size should be a multiple of 8.
