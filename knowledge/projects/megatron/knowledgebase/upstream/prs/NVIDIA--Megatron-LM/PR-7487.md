# Preserve T5 process-group collections during initialization

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7487) · state: open · merged: False

## Original PR description

**Why.** `T5Model` accepts a caller-provided `ProcessGroupCollection` but does not pass it to `LanguageModule`, the embedding or the output layer, so those parts read the context-parallel, pipeline and embedding groups from the global parallel grid. A T5 built on its own grid silently uses the wrong groups.

**What.**
- Forward the supplied collection to the `LanguageModule` base, the embedding and the output layer, so their process-group and GTP-rematerialization lookups use the caller's grid.
- An explicit collection should define `embd` (it may be `None` where no embedding synchronization is needed). A collection without an `embd` field emits a `FutureWarning` and is treated as `embd=None`. The warning states that this becomes an error in Megatron Core 0.23. With pipeline parallelism and tied embedding/output weights, the embedding and output stages need a usable `embd` group; without one, initialization would zero the output weight and skip its synchronization. These stages raise `ValueError` when `embd` is missing, `None` or `NON_GROUP_MEMBER`.
- Omitting the collection keeps today's behavior. The one in-repo explicit caller is updated.

**Behavior change for callers that pass an explicit collection.** On main, `T5Model` ignores the collection's `embd` and uses the global embedding group. With this PR it uses the collection's `embd`. A collection built with `use_mpu_process_groups(required_pgs=['tp', 'cp', 'pp'])` has no `embd` field. It now triggers the `FutureWarning`, and it raises `ValueError` on tied pipeline embedding/output stages. `LanguageModule`'s `hasattr(pg_collection, 'embd')` assert does not catch a missing field, because `ProcessGroupCollection.__getattr__` returns `None` for unset declared fields.

**Tests.** New regressions cover supplied and default collections, omitted and `None` embedding groups, and identical non-zero embedding/output weights on a real two-stage pipeline; the explicit-collection tests forbid global-grid lookups and fail on main. The omitted-`embd` cases assert the `FutureWarning`. Before the 2026-11-01 sync, this branch on the main of that time passed the T5 model tests on 8 GPUs (two nodes) and the T5 checkpoint, inference-wrapper and encoder-decoder controller tests on 4 GPUs. In the integration run, which predates the `FutureWarning` change, this PR's test files show no regressions against main: `test_t5_model.py` passes 31 tests on 8 GPUs (two nodes) vs 13 on main. This PR adds 14 of the 18 new tests; other campaign PRs that change the same file add the other 4. Constructor-only change: no performance impact, no checkpoint format change.
