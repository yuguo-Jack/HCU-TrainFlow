# [SSM] Copy GDP's conv input when the projection width breaks causal_conv1d's stride rule

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8706) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Lets `GatedDeltaProductMixer` run in BF16 at head counts and TP sizes where its input projection is not 8-element aligned. Before this PR, every forward of such a model failed with:

```
RuntimeError: causal_conv1d with channel last layout requires strides (x.stride(0) and x.stride(2)) to be multiples of 8
```

**Bug.** #6553 removed the copy before the causal conv in `_prepare_qkv`. Since then the conv reads the channels-last transpose of the VKQ slice in place, as a view into the fused `zVKQba` in_proj output. The view's token stride is the full local projection width:

`d_inner_local + conv_dim + nheads_local_cp * (num_householder + 1)`

The channel-last `causal_conv1d` kernel loads 8-element vectors along the channels. Its batch and token strides must be multiples of 8 elements, and so must the slice's start. The first two terms are multiples of 8 for the usual head and state sizes. The last term is not whenever `nheads_local_cp * (num_householder + 1)` is not, for example:
- two Householder reflections with 4 local heads: 8 heads at TP=2, or 32 heads at TP=8;
- the default three reflections with an odd local head count.

Affected paths: the training forward, static-batching prefill (it seeds the conv state through the same code), and both CP modes (head-wise CP feeds the conv its all-to-all output, a narrower projection with the same layout; chunkwise CP's `causal_conv1d_cp` transposes the same view). Dynamic batching and static decode use other conv kernels and are not affected.

Under FP8 and FP4 these widths still fail, earlier: TE's quantized in_proj GEMM has its own alignment requirement on the projection width, which they also break. This PR unblocks BF16 runs.

An inference-vs-training configuration matrix on H100 hit this on both GDP rows at TP=2 (8 heads, head_dim 32, 8 groups, state 64, two reflections; local width 1164). The training forward raised the error above. The same model at TP=1 (width 2328) passed.

**Fix.**
- `megatron/core/ssm/causal_conv1d.py` now holds the kernel's layout rule in one place: `CHANNEL_LAST_ALIGNMENT = 8` and `ensure_channel_last_alignment(x)`. The helper returns a `[B, L, D]` input unchanged when its start and its batch and token strides are multiples of 8, and copies it otherwise. Without causal-conv1d it always returns the input unchanged, since the `F.conv1d` fallback has no such rule.
- `_in_proj_preprocess` passes VKQ through the helper. The copy, when one is needed, is therefore made inside the `gdp_in_proj` recompute checkpoint, which discards it with the rest of the projection after the forward pass.
- `_preprocess` already copies the projection to make it batch-first when the micro-batch size is above 1. That copy's rows are now padded to a multiple of 8, so VKQ is aligned inside it and needs no second copy. A copy of VKQ is therefore needed only when there is no batch-first copy (batch size 1, or a single token), or when VKQ starts off an 8-element boundary. The dynamic-inference callers of `_preprocess` never copy, so they are unchanged.
- The helper copies with `clone(memory_format=torch.contiguous_format)`, not `contiguous()`. When batch and length are both 1, as in a one-token static-batching prefill at batch size 1, `contiguous()` returns the misaligned view unchanged: torch ignores the strides of size-1 dimensions, and the kernel's check does not.
- Aligned widths keep the zero-copy path of #6553. The checks read host-side tensor metadata only: no syncs, nothing data-dependent, and CUDA-graph safe.

**Cost.** Misaligned widths at micro-batch 1 pay one VKQ-sized copy per forward, and one more per `gdp_in_proj` recompute. That copy replaces the full projection as the tensor the conv saves for backward, so it never keeps more memory alive than an aligned width does. `gdp_in_proj` frees it until the backward pass, and `gdp_qkv` saves it instead of the projection view. Micro-batch above 1 pays no extra copy, only up to 7 elements of padding per token row.

**Tests.**
- `tests/unit_tests/ssm/test_gated_delta_product.py` uses a 4-head mixer at TP=1. Two Householder reflections give in_proj width 1548, or 774 after head-wise CP's all-to-all; neither is a multiple of 8. Three reflections give 2064 and 1032, the aligned controls. Each case checks that the output and every gradient (or, for prefill, the output and both caches) match, bit for bit, a mixer with the same weights whose conv always reads a dense copy. It also records the storage of the projection, of VKQ as `_in_proj_preprocess` returns it, and of the conv kernel's input. It checks that the conv reads that VKQ itself, and that VKQ is a copy exactly when the width is misaligned and the micro-batch size is 1.
  - `test_conv_reads_vkq_at_any_projection_width`: training forward and backward at CP=1 (micro-batch 1 and 2), chunkwise CP=2 (micro-batch 1), and head-wise CP=2 (micro-batch 1 and 2). The CP=2 cases need 2 GPUs.
  - `test_recompute_at_misaligned_projection_width`: `gdp_qkv`, `gdp_in_proj`, and both, at micro-batch 1 and 2. Under `gdp_in_proj` it also checks that VKQ's storage is freed after the forward pass. 1 GPU.
  - `test_static_prefill_at_any_projection_width`: static-batching prefill of a 1-token prompt at batch size 1 and of an 8-token prompt at batch size 2. It compares the output, the seeded conv state and the SSM state. 1 GPU.
- `tests/unit_tests/ssm/test_causal_conv1d.py::test_ensure_channel_last_alignment` runs on CPU. It checks which strided slices the helper copies, including the single-token case that `contiguous()` would miss, and that the `F.conv1d` fallback never copies.
- Every case that fits on 1-2 GPUs is covered. The TP=2 and TP=8 configurations from the bug report are not needed: the width alone triggers the bug, and 4 heads at TP=1 reproduce it.
- On H100 in the CI image, the first version of `test_conv_reads_vkq_at_any_projection_width` (CP=1 and chunkwise CP=2, micro-batch 1) failed on `main` in its two two-reflection cases with the error above, and passed all 4 cases with this PR. Neighbor tests `test_in_proj_recompute_parity`, `test_in_proj_recompute_preserves_norm_gate_view` and `tests/unit_tests/ssm/test_gdp_packed_seq.py` passed. Their only skips were MXFP8 on SM90, the CuTeDSL CP backend not being installed, and CP=4 needing 4 ranks.
- The second commit (review feedback) adds the cases above and moves the copy. In the rerun (dfw 21004395), all cases pass with this PR (14 on 1 GPU, 10 on 2 GPUs) and every misaligned case fails on `main` (12 and 5; the aligned controls pass); the neighbors pass. On CPU, an emulated conv that applies the kernel's host checks and 16-byte alignment ran `_in_proj_preprocess` and `_prepare_qkv` on both conv paths. With this PR, outputs, conv-state seeding and gradients match a dense copy bitwise, including under the `gdp_in_proj` checkpoint. The same checks fail if the copy goes back into `_prepare_qkv`, if `contiguous()` replaces `clone()`, or if the row padding is removed.

**Determinism gate.** `causal_conv1d.py` and `gated_delta_product.py` are registered kernel-dispatch entries, so this PR needs the `determinism-exempt` label. The kernels and their numerics are unchanged: aligned configurations pass the same tensors as before, and misaligned ones run the same kernels on an exact copy or a padded-row view of the same values.

**Not changed.** The channel-last kernel also needs the conv channel count (`conv_dim`) to be a multiple of 8. That holds whenever `head_dim` and `d_state` are, and is unchanged here.
