# Allow native fused cross entropy in deterministic mode

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8380) · state: open · merged: False

## Original PR description

`--deterministic-mode --cross-entropy-loss-fusion` currently rejects both CE backends. Permit the native `torch.compile` path under strict deterministic algorithms, while continuing to reject the separate TE implementation. Keep the existing native computation and collectives; no new reduction kernel is introduced. Update the operation catalog and user guide to distinguish the backends.

Expand native CE replay coverage to TP1/TP2 × bf16/fp32 × strict/default modes with rank-distinct vocabulary shards and four replays under side-stream contention. Strict-mode cells are required to pass. Default-mode cells remain non-strict xfails because cold compiler autotuning can select different reduction configurations. Parameter tests verify that the admission check does not mutate the selected backend, and restore the global deterministic flags and fill setting.

Validation:

- **2×H100 SXM 80 GB, NV18:** native fused and unfused CE were each stable within their own TP1/TP2 strict-mode process series (three independent launches per setting). This is not a claim that fused and unfused outputs are bit-identical.
- **Two GH200 hosts, one GPU each, NET/IB/GDRDMA:** three cold-cache launches of the expanded eight-cell matrix passed on both ranks, with four contention replays per cell. All eight strict-mode case/rank groups retained identical input/output/gradient digests across processes. Six of eight default-mode groups changed output or gradient digests between processes. In a separate TP1 series the default reduction changed `R0_BLOCK` from 32768 to 16384.
- **True TP2 reference check:** bf16/fp32 native fused and unfused loss and gradients passed fixed tolerances against full-vocabulary `F.cross_entropy` on both ranks. Maximum loss error was 9.54e-7; maximum bf16 gradient error was 6.66e-4. These reference timings are not performance claims.
- **Updated admission and required cells on GH200:** 34 parameter tests passed. Normal pytest execution produced 2 strict TP1 passes, 2 default XPASS and 4 TP2 skips on the single-GPU invocation; the TP2 numerical body is unchanged from the two-host matrix above. Three additional cold processes ran actual bf16 GPT forward/backward/SGD with native fusion admitted through `apply_determinism_to_args`; all four-step losses, initial/final parameters and gradients matched exactly.
- **Performance with Megatron's `fill_uninitialized_memory=False`:** three independent processes per mode, eight warmup plus 50 measured iterations, rotated mode order. For the 2048-token × 32768-vocabulary single-GPU probe, paired strict/default geometric-mean median-step ratios were **1.337 for bf16** (95% interval 0.930–1.921) and **1.539 for fp32** (1.236–1.917). Intervals use Student-t on paired log ratios, n=3, df=2. Samples are small/noisy; no negligible-overhead or full-model throughput claim is made. Raw values and a separate uninitialized-fill-on control are retained.
- Nsight det/nondet captures, NVTX ranges and stats extraction both completed using the clean-exit fix in #8382. The original wrapper failure remains recorded.
- Black, isort, ruff and `git diff --check` passed. The repository autoformat pylint check passed for the changed test files; the separate training-module check reported its pre-existing `bad-builtin` warning at line 183. The optional mypy step was unavailable locally. No full CI result is claimed.

GH200: aarch64, driver 595.58.03, PyTorch 2.14.1+cu130, CUDA runtime 13.0, Triton 3.8.0, NCCL 2.30.7, TE 2.20.2+44f31bbe. H100: NGC PyTorch 26.09, PyTorch 2.14.0a0+b2c75dd062.nv26.09, CUDA 13.4, Triton 3.8.0, NCCL 2.31.2+cuda13.4, TE 2.19.0+5e52befd. This qualifies the measured native bf16/fp32 paths, not TE CE, batch invariance, arbitrary compiler options, older compiler versions or model convergence.
