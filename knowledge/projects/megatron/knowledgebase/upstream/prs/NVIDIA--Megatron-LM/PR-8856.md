# perf(fsdp): stage gradient reduction inputs on the compute stream

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8856) · state: open · merged: False

## Original PR description

## Summary

Move partial-gradient lifetime management from the communication stream to the compute stream, removing the need for `current_stream.wait_stream(inner_reduction_stream)` solely to keep partial-gradient buffers alive. This avoids potential performance degradation caused by unnecessary compute-stream synchronization.

```
Schematic timeline (not to scale)                         time -->

Before: packing the next group waits for the previous reduction

compute : [pack g0][ wait  ][pack g1][next compute ...]
reduce  :          [reduce0]         [reduce1]


After: compute overlaps reduction; inputs retire during forward

compute : [pack g0][pack g1][ F0 ][ F1 ] R [ F2 ... ]
reduce  :          [reduce0][reduce1]--E
inputs  : [=========== held ==============]--> reusable
                                         ^
                                         R

- E: completion event after reduction/local accumulation consumes the inputs.
- R: allocation_stream.wait_event(E), then release input references.
- Record: observe completed inputs and record their retirement occurrence.
- Replay: apply those retirement actions, including during CUDA Graph capture, without querying events.
```

## Implementation

- Add `_pending_grad_buffers` to the FSDP context to explicitly retain partial-gradient buffers while asynchronous gradient reduction is in flight.
- Manage these buffers’ lifetimes from the compute stream rather than relying on synchronization with the communication stream.
- Remove the lifetime-related `current_stream.wait_stream(inner_reduction_stream)` call, decoupling buffer lifetime management from compute-stream synchronization.
- Record forward retirement points during the first execution trace and replay their completion waits, allowing earlier storage reuse during CUDA Graph capture.

Validation: 80 tests passed on each of four GB200 GPUs, including eager/CUDA Graph lifetime checks, MXFP8 gradient communication, and HSDP/HFSDP reductions.
