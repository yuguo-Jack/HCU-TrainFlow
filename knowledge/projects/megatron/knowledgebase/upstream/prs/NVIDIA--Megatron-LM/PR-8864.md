# [Inference] Apply FlashInfer fused RoPE only where the model built its cos/sin cache

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8864) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

With FlashInfer fused RoPE on, dynamic inference applies each model's own RoPE again: YaRN models use the fused kernel, and layers in `no_rope_freq` are not rotated. Multimodal RoPE, which dynamic inference cannot run at all, is rejected when the context is built.

**Stacked on #8863 (`fix/hybrid-flash-decode-rope`)**, which is itself stacked on #8862 (`fix/flashinfer-fused-rope-shapes`). This PR extends #8863's shared RoPE-input helper. It routes YaRN models onto FlashInfer's kernel, which faults on some head dims (e.g. 72) and silently mis-rotates others (e.g. 80) until #8862 lands. Review this PR's commits: `3345e7089` (the fix) and `ba22d8ed5` (review follow-up). `51ae3098b` merges the base. Retarget to `main` once both bases are merged.

## Bug

`use_flashinfer_fused_rope=True`, or `None` with FlashInfer installed (the CI image has it), makes the dynamic context apply RoPE with `flashinfer.rope.apply_rope_with_cos_sin_cache` from a cos/sin cache that the model passes as `rotary_pos_cos_sin`. Attention keyed this on the context flag, not on the cache:
- `Attention.forward` dropped `rotary_pos_emb` whenever the context enabled fused RoPE.
- `_adjust_key_value_for_inference` applied the fused rotation whenever a cache came in.

On `main` only `GPTModel` with `position_embedding_type='rope'` built the cache. So, silently, with no error:
- **GPT YaRN** (GPT-OSS style) ran every dynamic prefill and decode step with no RoPE. Attention dropped `rotary_pos_emb` and got no cache.
- **HybridModel RoPE and YaRN** did the same, because hybrids never built the cache. #8863 fixes hybrid RoPE; hybrid YaRN still had none.
- **`no_rope_freq` layers** (e.g. Llama-4-style models) cleared only `rotary_pos_emb`, so they still got the fused rotation from the cache.

Affected: dynamic inference (`DynamicInferenceEngine`, and `StaticInferenceEngine`, which runs it underneath) with fused RoPE on. The flag is off by default in `InferenceConfig`.

Multimodal RoPE (`position_embedding_type='mrope'`) is a different case: it does not run in dynamic inference at all, whatever the flag. The context passes `[1, n]` position ids, and `MultimodalRotaryEmbedding` needs `[3, batch, seq]`, so the first forward raises `IndexError`. Even with three-row ids, the unfused path looks up its per-token embedding by absolute position (`token_to_pos_ids`), which is wrong across requests and out of range at decode.

## Fix

- **Attention keys fused RoPE on the cache.** `_adjust_key_value_for_inference` applies FlashInfer's fused RoPE exactly when `rotary_pos_cos_sin` is passed, and then drops `rotary_pos_emb`, so a caller passing both cannot rotate twice. `Attention.forward` no longer drops `rotary_pos_emb` because of the context flag; it still does under `flash_decode`. A model that passes only `rotary_pos_emb` therefore gets the unfused RoPE path with fused RoPE on.
- **No-RoPE layers take no RoPE input at all.** A `no_rope_freq` layer clears `rotary_pos_emb`, `rotary_pos_cos`, `rotary_pos_sin` and `rotary_pos_cos_sin`. The flash-decode tables are cleared too. `TransformerConfig` already refuses `flash_decode` with `no_rope_freq` when the config is built; clearing them also covers a runtime toggle.
- **The model builds the cache only for RoPE the kernel applies exactly.** The shared helper `LanguageModule._rotary_pos_emb_inputs` (from #8863) builds it for RoPE and YaRN.
  - **RoPE**: `RotaryEmbedding.get_cos_sin`, as before.
  - **YaRN**: the new `YarnRotaryEmbedding.get_cos_sin` returns the cosines and sines of YaRN's interpolated frequencies, scaled by its concentration factor (`mscale`). The unfused path rotates with `cos(freqs) * mscale` and `sin(freqs) * mscale` (`_apply_rotary_pos_emb_bshd`, with attention's `_yarn_concentration_factor`, computed from the same config attributes). FlashInfer computes `x * cos - y * sin` from the cache, which is linear in it, so the rotation is the same up to rounding. The review measured a max abs difference of 1.7e-7 in fp32. YaRN is NeoX-only and rotates the whole head. Before, `YarnRotaryEmbedding.get_cos_sin` was the base class's and returned plain-RoPE frequencies without `mscale`.
  - **MLA** layers apply their own RoPE and never take the cache, as before.
- **GPT models with MTP take the unfused RoPE.** FlashInfer's fused RoPE has not been validated with MTP. `GPTModel` used to assert at its first dynamic step when it built the cache with MTP layers. It now passes `allow_fused_rope=not self.mtp_process`, so RoPE and YaRN models with MTP run the unfused path instead.
- **HybridModel honours `rotary_interleaved`.** It passes the flag to its RoPE and YaRN embeddings, as `GPTModel` does. Before, a hybrid with `rotary_interleaved=True` applied a NeoX-layout embedding with the interleaved `_rotate_half`, which is not a rotation, while the fused path applied a GPT-J rotation. RoPE now rotates GPT-J style on every path, which FlashInfer's kernel implements (`is_neox=False`). YaRN does not implement the interleaved layout, so `YarnRotaryEmbedding` rejects it when the model is built, as for GPT.
- **Multimodal RoPE is rejected when the dynamic context is built**, whatever `use_flashinfer_fused_rope` is. The error is `ValueError("Multimodal RoPE (mrope_section is set) is not supported by dynamic inference: ...")`. The check uses `mrope_section` because `position_embedding_type` is a model argument, not a config field; `rope_utils` already treats `mrope_section` as the multimodal-RoPE marker. The helper still never builds a cache for multimodal RoPE, which static inference and training keep running unfused.

No new host syncs or per-step allocations: the cache is built once per maximum sequence length and cached in `rotary_pos_emb_cache`, as for RoPE.

## Tests

- `tests/unit_tests/inference/test_flashinfer_fused_rope_models.py` (1 GPU, TE, flash-attn, FlashInfer; bf16, head dim 64). Each case runs a prefill of two requests (12 and 7 tokens) and one decode step with fused RoPE off and on. It compares the queries and keys every attention layer hands to the attention kernel, within 2%: bf16 rounding of the two RoPE paths differs by about 0.3%, a missing or extra rotation by tens of percent, and YaRN without its `mscale` by 17%. It also counts the fused RoPE calls: once per RoPE layer and step.
  - `TestGPTModelFusedRope::test_fused_rope_matches_unfused[yarn]` (scaling factor 8, so YaRN's frequencies and its `mscale` of 1.21 differ clearly from RoPE's): fails on `main` (no fused RoPE call; no RoPE at all).
  - `[no-rope-layer]` (`no_rope_freq=[1, 0]`): fails on `main`, where the no-RoPE layer is rotated too (4 fused calls instead of 2).
  - `[rope]`: control, passes on `main`.
  - `TestGPTModelFusedRope::test_mtp_model_takes_unfused_rope`: a YaRN model with one MTP layer runs with no fused RoPE call and matches the unfused path. Before the follow-up it raised "MTP not tested with flashinfer_fused_rope".
  - `TestHybridModelFusedRope::test_fused_rope_matches_unfused[rope|rope-interleaved|yarn]`: all fail on `main`. `rope` passes on #8863 alone; `rope-interleaved` and `yarn` need this PR.
  - `TestHybridModelFusedRope::test_yarn_rejects_interleaved_layout`: building a YaRN hybrid with `rotary_interleaved` raises.
- `tests/unit_tests/transformer/test_attention_no_rope.py::test_static_flash_decode_prefill_skips_rope_tables[1-True|4-False]` (1 GPU, TE): a static flash-decode prefill given cos/sin tables applies RoPE on a RoPE layer and not on a `no_rope_freq` layer. The no-RoPE case fails on `main`.
- `tests/unit_tests/inference/contexts/test_dynamic_context.py::test_multimodal_rope_is_rejected[False|None|True]` (CPU): building the context with `mrope_section` raises the `ValueError` for every flag value. On `main` it fails only on an unrelated setup error (see the results below).
- Determinism: `tests/unit_tests/determinism/kernels/test_runtime_cp_attention.py::test_dynamic_fused_rope_dispatch_replays[rope-layer|no-rope-layer]` (1 GPU, TE, FA2, FlashInfer) runs a `SelfAttention` dynamic prefill with `rotary_pos_cos_sin`. It replays bit-exactly under side-stream contention, and is compared with the same prefill without the cache: a RoPE layer differs, a `no_rope_freq` layer matches bit for bit. Passing `rotary_pos_emb` as well changes nothing. On `main` the `no-rope-layer` case fails. The `rope-layer` case passes there, because `main` drops `rotary_pos_emb` on the context flag; its last check guards this PR's own change and failed on its first commit, which applied `rotary_pos_emb` to the KV-cache view. The test sits under the existing `attention_kernels_and_dispatch` manifest entry, so `tools/check_kernel_determinism_coverage.py --base-ref origin/main` passes. No kernel is added: the change selects between FlashInfer's fused RoPE and the unfused RoPE path, both elementwise.

On H100 in the CI image (`mcore_ci_dev:main`, 2026-11-02), the regression tests pass (15 cases). On this PR's base, #8863, 11 of the 15 fail and the 4 controls pass (GPT and hybrid `[rope]`, the RoPE-layer flash-decode prefill, the `rope-layer` replay):
- GPT and hybrid `[yarn]` make no fused RoPE call; GPT `[no-rope-layer]` makes 4 instead of 2.
- Hybrid `[rope-interleaved]` and `test_mtp_model_takes_unfused_rope` differ from the unfused path. `test_yarn_rejects_interleaved_layout` does not raise.
- The no-RoPE flash-decode prefill and the `no-rope-layer` replay rotate the no-RoPE layer.
- `test_multimodal_rope_is_rejected` fails only on an unrelated setup error: with nothing rejecting multimodal RoPE first, the context constructor stops on "expert model parallel group is not initialized". So the missing rejection is not shown on GPU; P4-N1 has no step 3 GPU repro.

The neighbor tests (`test_attention_no_rope.py`, `test_rope.py`, and the `flashinfer-fused-rope` case of `test_dynamic_engine_async_sched.py::TestAsyncSchedulePairwise`) pass (18 cases).

## Notes for reviewers

- **Behaviour changes.**
  - Models that pass `rotary_pos_emb` (YaRN, hybrid YaRN, any other model built on `Attention`) now get RoPE with fused RoPE on, where they got none. Their generations change, to match `use_flashinfer_fused_rope=False`.
  - GPT models with MTP run unfused RoPE instead of asserting.
  - Hybrids with `rotary_interleaved=True` now rotate GPT-J style on every path, including training. YaRN hybrids with that flag are refused.
  - Multimodal-RoPE models are refused by the dynamic context instead of crashing at their first forward.
  - GPT and hybrid plain RoPE are unchanged.
- `flash_decode` with YaRN is still rejected, as before. The tables `YarnRotaryEmbedding.get_cos_sin` now returns would carry YaRN there too, but that path is not tested here.

## Interaction with other open PRs

Three PRs fix FlashInfer fused RoPE in dynamic inference, each at a different layer:
- **#8862 (`fix/flashinfer-fused-rope-shapes`)**, the context: whatever cos/sin cache a model passes, `apply_fused_qk_rotary_emb` rotates every head shape exactly. Shapes FlashInfer mis-rotates or faults on are rotated in fp32.
- **#8863 (`fix/hybrid-flash-decode-rope`, stacked on #8862)**, the models: one helper owns RoPE inputs for GPT and hybrids, and RoPE hybrids build the cache and pass it through `HybridStack`.
- **#8864 (this PR, `fix/fused-rope-model-embedding`, stacked on #8863)**, attention: fused RoPE runs only with the model's cache; YaRN gets a cache; no-RoPE layers are not rotated.

Together, every model with fused RoPE on gets its own RoPE, rotated exactly for every head shape. The merge order is #8862, then #8863, then this PR, and stacking enforces it. Retarget this PR to `main` once both bases are merged. After that, its `dynamic_context.py` change, a constructor check with no numerics, is flagged by the coverage gate against #8862's manifest entry for that file. It needs the `determinism-exempt` label.

Several open PRs change `attention.py` (n2, n12, n13, s8, #8878, the MLA zero-padding and Blackwell decode fixes) or append to `test_runtime_cp_attention.py`. This PR merges cleanly with all of them and with every open fix branch that merges with `main`.
