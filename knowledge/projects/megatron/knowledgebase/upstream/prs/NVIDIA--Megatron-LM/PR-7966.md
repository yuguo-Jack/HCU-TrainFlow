# Reuse GlobalLayout in owner planning

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7966) · state: closed · merged: True

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

Owner planning duplicates tensor shapes and shard geometry in `ParameterLayout`. This PR removes that duplicate representation and derives owner assignments and packed communication ranges from the group's existing `DBuffer.layout`, using the range APIs introduced in #7963.

- `GroupOwnerLayout` stores the device mesh, shared `GlobalLayout`, and owner assignments keyed by the original tensor indices. Owners and communication peers use global process ranks.
- `assign_owner_work` collects each tensor's nonempty shard holders, orders single-candidate work first and remaining work by descending cost, then assigns each tensor to its least-loaded holder. Ties follow buffer order, including for reordered and multidimensional meshes.
- `OwnerGatherPlan` and `OwnerScatterPlan` derive packing ranges from the shared layout. Receive sizes and offsets are computed together, and gather reconstructs tensors in buffer order.
- Cost callbacks receive full tensor shapes. The Newton–Schulz cost docstring explains the matrix update and the relative work estimate.

Tests use real device meshes, construct parameter groups through the public `fully_shard` API, and exchange packed buffers with distributed P2P. Coverage includes eligibility, single-candidate priority regardless of input order, noncontiguous and reordered global ranks, 2D meshes, padding, empty plans, and gather/scatter round trips.

Validation:

- All 93 cases across owner-planning, layout, and DBuffer tests passed on eight GB300 GPUs on nsc-lhr (job 137895, exit 0). Ranks outside each test's submesh skipped its cases. NCCL emitted shutdown warnings after the passing pytest summaries.
- Black, isort, pylint, Ruff, and `git diff --check` passed.

#7963 has merged. #7432 builds on this PR via `pull-request/7966`; retarget that dependent PR to `main` before merging this one.

Refactors owner-planning code originally authored by @janEbert. Related to #5533.
