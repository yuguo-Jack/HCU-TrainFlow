# Handle an empty local expert assignment in fused permute and unpermute

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8804) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Fixes #8690.

In dropless top-k routing, an expert-parallel rank can get no tokens for a microbatch when none of them picked its experts. The allgather dispatcher then calls `permute()` with `num_out_tokens == 0`. With `moe_permute_fusion`, Transformer Engine's mask-map permute asserts `num_out_tokens > 0`. The flex dispatcher makes the same call when a rank receives no tokens.

`permute()` now takes the unfused path for an empty assignment, and `unpermute()` does the same when it gets zero permuted rows. The unfused path returns zero rows and a zero output, and both stay in the autograd graph. That matters: if the empty rank dropped out of the graph, it would also skip the backward collectives behind its inputs (the reduce-scatter that backs the token and probs all-gather) while the other ranks run them.

The expert computation itself needs no change. With this fix, both SequentialMLP and TE grouped-MLP experts run a zero-row forward and backward without problems (see below).

## Testing

2 × B300, EP = 2, allgather dispatcher, `moe_permute_fusion=True`. Every token picks experts 0 and 1, which live on expert-parallel rank 0, so rank 1's local assignment is empty:

| Path | main | this PR |
|---|---|---|
| Dispatcher round trip (permute, all-gather, unpermute, reduce-scatter, backward) | rank 1: `AssertionError: moe_permute (mask map) requires num_out_tokens > 0, got 0.` | both ranks pass; rank 1 has 0 local tokens, the round trip is exact, input and probs gradients arrive |
| `MoELayer` forward and backward, SequentialMLP experts | same assertion | both ranks pass |
| `MoELayer` forward and backward, TE grouped-MLP experts | same assertion | both ranks pass |

New tests in `tests/unit_tests/transformer/moe/test_token_dispatcher.py`:
- `test_permute_unpermute_empty_assignment`: single GPU, fused and unfused, with and without probs. Checks the zero-row output, the all-zero restore, and that gradients reach the tokens and probs.
- `TestAllgatherDispatcher::test_expert_ranks_without_tokens`: needs at least two ranks and uses EP = world size. Runs the round trip above, then the whole MoE layer with the router replaced by the same assignment.

With this PR all 6 new cases pass on 2 × B300. With only the new tests on main, the two fused cases of `test_permute_unpermute_empty_assignment` fail with the TE assertion. `test_expert_ranks_without_tokens[True]` fails on rank 1 the same way, and rank 0 then waits in a collective until the run is killed.

The whole `test_token_dispatcher.py` on 2 × B300 has the same 14 failures on main and with this PR. All 14 are cases sized for 8 ranks (`world_size (2) is not divisible by 8`). Passing cases go from 29 to 35, which are the six new tests.

The flex dispatcher goes through the same `permute()` / `unpermute()` change, but I could not run it here (no DeepEP install).

black 26.3.0 and isort 5.13.2 report no changes; pylint and ruff were not run.
