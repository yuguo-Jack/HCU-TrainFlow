# What does this PR do?

Add an opt-in EP MoE return path that combines expert outputs directly into tokens. Its single-round path overlaps NCCL all-to-all with output initialization; the default native path is unchanged.

## Validation

On 8×RTX 5090 hardware, EP2 with Transformer Engine grouped experts, BF16, two GPT layers, 16 experts, top-k 4, H1024 and 4096 tokens, the median of the slower rank over 20 complete optimizer steps after five warmups was:

| Launch order | Native | Candidate | Speedup | Native / candidate peak allocated |
|---|---:|---:|---:|---:|
| Candidate → native | 63.26 ms | 59.88 ms | 1.056× | 2296.59 / 2323.10 MiB |
| Native → candidate | 62.16 ms | 60.87 ms | 1.021× | 2296.55 / 2323.03 MiB |

A second H512/8192-token shape was mixed across two reversed-order pairs (1.015× and 0.988×). This change improves speed on the H1024 shape but does not reduce complete-step allocated peak. A separate fixed-route deterministic 20-step comparison matched native initial weights, routes, every loss, first gradients, and final parameters exactly on both ranks. Isolated EP2/EP4 forward and backward cases passed for FP64, FP32, and BF16, including tails and empty peers. The branch passed `ruff check`, Python compilation, and `git diff --check`. Full measurements and limitations are in `A2_RESULTS.md`.
