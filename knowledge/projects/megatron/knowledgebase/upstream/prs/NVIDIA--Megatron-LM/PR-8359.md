# [Fix] Atomically write dataset index caches and commit markers

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8359) · state: open · merged: False

## Original PR description

## Problem

In `megatron/core/datasets/`, the blended dataset index caches are written non-atomically and re-validated unsoundly:

- Rank 0 writes `.npy` index caches using plain `numpy.save` directly into the final path. If rank 0 crashes or is preempted mid-write (due to OOM, hardware fault, or timeout), a truncated `.npy` file is left on shared storage.
- `description.txt` was written **before** the `.npy` payloads, so it could not serve as a commit completion marker.
- On subsequent runs or job restarts, `cache_hit` checks `all(map(os.path.isfile, ...))`, which accepts the torn files as valid cache hits. Dataloader workers then crash at `numpy.load(..., mmap_mode='r')` with `ValueError: mmap length is greater than file size`.

## Solution

1. **Atomic Array Saving**:
   - Added `atomic_save(path, array)` in `megatron/core/datasets/utils.py`.
   - Writes to a temporary file in the same directory (`tempfile.NamedTemporaryFile(dir=dir_name, suffix=".tmp")`) and replaces the target path via `os.replace` only when write and flush are complete.
2. **Atomic Text Writing**:
   - Added `atomic_write_text(path, content)` in `megatron/core/datasets/utils.py`.
3. **Commit Marker Ordering**:
   - In `GPTDataset`, `BlendedDataset`, and `MaskedWordPieceDataset`, save all index array payloads first atomically, and write `description.txt` **last** as the commit completion marker.
4. **Unit Tests**:
   - Added `tests/unit_tests/data/test_dataset_cache_atomic.py` testing successful atomic save, atomic text write, and ensuring simulated failures leave no corrupted files at the target path.

Fixes #8189
