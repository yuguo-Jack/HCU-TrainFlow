# Fix sequence-packing scheduler crash on middle pipeline stages

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8378) · state: closed · merged: True

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

## What does this PR do?

Fixes an `AssertionError` on the first training step when the sequence-packing scheduler runs on packed data with three or more pipeline stages and no virtual pipeline parallelism (VPP). This affects `--use-varlen-dataset` in THD mode, which enables the `dp_balanced` scheduler automatically, and `--sft --sequence-packing-scheduler dp_balanced`, in both `pretrain_gpt.py` and `pretrain_hybrid.py`.

## Root cause

Two assumptions about middle pipeline stages conflict:

- For packed data, `is_dataset_built_on_rank` builds the dataset on TP rank 0 of **every** pipeline stage, because in the regular path middle stages read `cu_seqlens` from their own data iterator (#4103).
- The sequence-packing scheduler (#6684) packs on the first and last stages, sends the packing metadata to the middle stages through `broadcast_to_pp_group`, and asserts in `DpBalancedScheduler.run()` that no other rank holds a data iterator.

#6742 enabled the scheduler for the varlen THD dataset, which put both in the same run. Without VPP, nothing removes the middle-stage iterator before `wrap_data_iterator`, so TP rank 0 on each middle stage fails with:

```
AssertionError: Only TP rank 0 and PP stage 0 or -1 should have data_iterator
```

With VPP, `run()` replaces middle-stage iterators with `None`, so it doesn't crash, but TP rank 0 on every stage still builds one dataloader per virtual stage, and the scheduler uses at most one of them.

## Fix

When `--sequence-packing-scheduler` is set, `is_dataset_built_on_rank` builds the dataset only on TP rank 0 of the first and last pipeline stages (`is_first_or_last_pipeline_stage(vp_stage)`), in both entry points. Behavior without the scheduler is unchanged. The resulting iterator layout is the one `test_wrap_dataloader` in `tests/unit_tests/test_sequence_packing.py` already builds by hand.

The MTP shortcut is skipped under the scheduler. MTP layers on a middle stage aren't supported by the scheduler path regardless: `broadcast_to_pp_group` carries only packing metadata, while `get_batch_on_this_rank_for_sequence_packing` expects `tokens` on MTP ranks.

## Testing

- Added `test_packed_sequence_dataset_built_on_rank` to `tests/unit_tests/data/test_get_batch.py`. It covers TP=2 and PP=4, with and without VPP and the scheduler, for both entry points.
- Not run on GPUs yet; relying on CI for the unit test. On CPU, I ran the real `is_dataset_built_on_rank`, `is_first_or_last_pipeline_stage`, and `parallel_state` stage helpers for all 8 simulated ranks. The fixed code matches the test's expectations everywhere. The code on `main` fails on 8 rank/stage combinations: the two crashing middle-stage ranks without VPP, and six unused dataloaders with VPP.
- Also on CPU, the real `wrap_data_iterator` raises the assertion above for a simulated middle-stage rank without VPP (fake process groups).
- `tools/autoformat.sh` passes in check mode.
