# refactor(training): add the data section (Megatron Core's GPTDatasetConfig, DataloaderConfig) to PretrainConfigContainer

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8341) · state: closed · merged: True

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Adds the `data` section to `PretrainConfigContainer`: `cfg.data.dataset` is **the** dataset config, Megatron Core's `GPTDatasetConfig` itself, built from the arguments, serialized into `run_config.yaml`, and handed to `BlendedMegatronDatasetBuilder` as is; `cfg.data.dataloader` holds the loader settings and `cfg.data.dataset_type` the dataset class the builder instantiates. The GPT dataset providers (`pretrain_gpt.py`, `pretrain_hybrid.py`, `pretrain_hybrid_flex.py`, `tools/prepare_cache.py`) build from it instead of re-reading the argparse namespace. In Megatron Core, the dataset configs move the assertions of their `__post_init__` to `validate()` (the checks that need no tokenizer in `validate_without_tokenizer()`, which `validate()` runs first and the container's `validate()` runs on its own) and have no `__post_init__` anymore, so the object can be constructed before its tokenizer exists (`BlendedMegatronDatasetBuilder` validates the config it is given); the derived values (`mock`, `split_matrix`, `token_dtype_code`) become read-only properties, and the FIM dataset moves from `megatron/training/datasets` to `megatron/core/datasets`. First PR of the DatasetConfig series (follow-ups: TokenizerConfig authoritative, dataloader and batch consumers, `seq_length` ownership).

## Issue tracking

Part of #3554 (args namespace to config container). Converges on the shape Megatron-Bridge uses for its dataset config.

## Design

- **One object, Core's.** `cfg.data.dataset` is `megatron.core.datasets.gpt_dataset.GPTDatasetConfig` (or its FIM subclass); there is no training-side subclass. Core's class no longer asserts in `__post_init__` what needs the tokenizer: those assertions are `validate()`, run once the config is complete (the tokenizer bound), and `validate()` asserts only. The derived values are read-only properties: `mock` and `split_matrix` of the sources and `split`, `token_dtype_code` of the bound tokenizer; nothing is derived into the object at any step. `BlendedMegatronDatasetConfig.validate_without_tokenizer()` holds the blend and split assertions, `validate()` runs it and then what needs the tokenizer, and nothing runs at construction (the base `__post_init__` is gone; the two Core subclasses that chained to it keep their own checks); `DataConfig.validate()` runs `validate_without_tokenizer()` (the GPT and FIM tokenizer-free checks included) for the container path, and `BlendedMegatronDatasetBuilder.__init__` calls `config.validate()`, so every caller that hands the builder a complete config is covered without an explicit call. `DataConfig.bind_tokenizer(tokenizer)` binds the run's tokenizer and runs Core's `validate()`; `initialize_runtime_services` does this right after the tokenizer is built, and `builder_inputs()` refuses an unbound config. The builder receives `cfg.data.dataset` itself: `builder.config is cfg.data.dataset`.
- **Fields other sections own.** Six Core fields are owned by other sections (the four parallel sizes by the model layout and the world size, the two validation flags by `validation`; `CONTAINER_WRITTEN_FIELDS`). The factory leaves them unset. `validate()` checks, with one explicit comparison per field, that a value given on the dataset config agrees with its owner, the way Megatron-Bridge checks `model.seq_length` against its dataset config; `finalize()` does the same for `data_parallel_size`, which needs the world size (`get_data_parallel_size(safe_get_world_size())` uses `GTPParallelLayout` with the configured context-parallel size, the quotient `validate_args` computes), then writes them, one assignment each (seven names since #7047: `dynamic_context_parallel` and its deprecated alias `hybrid_context_parallel`, which the container folds into the canonical field and clears). A layout field at Core's default (1, 0, False) carries no explicit value and is written over; without a model config (`pretrain_hybrid_flex.py`) the layout fields have no owner and keep what they hold; none of them is serialized with the section: what is saved reproduces the run. Standalone callers (`tools/prepare_cache.py`, the legacy `core_gpt_dataset_config_from_args` wrappers) fill them from `args`. `random_seed` is not a mirror: it is the data section's own setting, filled from `--seed` by the factory and saved with the section, independent of `rng.seed` after construction (Megatron-Bridge's semantics). Every command line behaves as on `main`; a `--dataset-seed` flag can follow when CLI control is wanted.
- **Only Core inputs on the object.** The data-path flags are resolved into `blend` / `blend_per_split` / `split` by the factory, `--per-dataset-sequences-path` is loaded into `sequences_per_dataset`, the five `--fim-*-token` flags fold into `fim_extra_tokens`. Megatron Core's `GPTFIMDatasetConfig` (the FIM dataset now lives in `megatron/core/datasets/gpt_fim_dataset.py`; `megatron.training.datasets.fim_dataset` re-exports both classes) carries the six FIM fields `GPTFIMDataset` reads and checks them in its own `validate()`. `--phase-transition-iterations` stays a training argument.
- **The dataset class is the selector.** `cfg.data.dataset_type` is the class (`GPTDataset`, `MockGPTDataset`, `GPTFIMDataset`, `SFTDataset`, `MockSFTDataset`, `VarlenDataset`, `MockVarlenDataset`), serialized as a `_target_` with `_call_: false`. On the CLI it follows the existing `--sft`, `--use-varlen-dataset`, `--mock-data` and `--fim-data` flags with the providers' precedence; no new flag. With no data source and no `--mock-data`, the mock class is selected where the entry point has one (with a warning), as Megatron-Bridge does. `resolve_dataset_class()` checks class and config agree (a mock class takes no source, a real class needs one, `GPTFIMDataset` goes with `GPTFIMDatasetConfig`).
- **One factory for the four entry points.** `gpt_data_config_from_args(args)` builds the same section for `pretrain_gpt.py`, `pretrain_hybrid.py`, `pretrain_hybrid_flex.py` and `tools/prepare_cache.py`; the differences between their legacy factories (fields never forwarded, requests silently downgraded to plain GPT) are not carried into the config. What a script cannot build it rejects itself: `pretrain_hybrid_flex.py` rejects `--use-varlen-dataset` (its batch path has no varlen support), the cache tool keeps rejecting `--mock-data`, `--sft` and `--fim-data` and pins the class to `GPTDataset`. No provider copies or edits the object.
- **Loader-only default.** Every other caller of `pretrain_cfg_container_from_args` (T5, BERT, VLM, the multimodal example, MiMo, RL, the ModelOpt fine-tuning example) gets `cfg.data` with the loader settings only (`dataset is None`): nothing dataset-related is validated, read or bound for them.
- **Providers unchanged in shape.** `training.py` is untouched: the GPT providers keep the legacy signature `(train_val_test_num_samples, vp_stage=None)` and the shared body reads `cfg.data` from the registered run config, as every provider reads `get_args()` today; `build_gpt_datasets` takes `data_config` explicitly for tests and direct callers.
- **One provider body.** `megatron/training/datasets/providers.py` holds `build_gpt_datasets` (the body of the GPT dataset provider: `cfg.data` in, `BlendedMegatronDatasetBuilder` fed with the config as is) and the GPT / hybrid rank predicate (`dataset_built_on_rank`, the rule from explicit inputs, and `is_dataset_built_on_rank`, the rule over the registered arguments, which it reads at call time from `megatron.training.global_vars` and `megatron.training.arguments`, where `tests/unit_tests/data/test_get_batch.py` patches them); `pretrain_gpt.py`, `pretrain_hybrid.py` and `pretrain_hybrid_flex.py` keep `train_valid_test_datasets_provider` as a wrapper of the legacy shape that calls it, hybrid-flex with its own predicate.

## Compatibility

- The parser is identical to `main`: no flag is added, moved or re-typed (snapshot test against the data arguments of `main`).
- `run_config.yaml` gains the `data` section; a file saved before it loads with the loader-only default.
- `core_gpt_dataset_config_from_args(args)`, the legacy call shape, is one helper in `argument_utils.py` (a standalone config built from the arguments, every data argument forwarded, the layout and validation fields and the seed from `args`, validated, bound to the tokenizer); `pretrain_gpt` and `pretrain_hybrid` re-export it and build their own tokenizer from `args` as before, `pretrain_hybrid_flex` wraps it with the global tokenizer as before, the cache tool wraps it with the class pinned to `GPTDataset`. The script-level names stay importable (`tests/unit_tests/distributed/mfsdp_v1` imports `pretrain_gpt.train_valid_test_datasets_provider`).
- `set_global_variables(args, cfg)` finalizes the container before the runtime services bind the tokenizer; since #8149 on `main` it finalizes every `PretrainConfigContainer`, and this PR changes nothing there anymore.
- Providers keep the positional contract `(train_val_test_num_samples, vp_stage=None)`; `training.py` is unchanged.
- Megatron Core: `GPTDatasetConfig(...)` constructs as before (same constructor fields and required arguments) and runs no check at construction anymore: the blend / split assertions and the tokenizer-dependent ones (the tokenizer, the `reset_*` / `eod_mask_loss` booleans, the SBHD / hybrid-CP exclusion, the `sequences_per_dataset` dtype requirement) are `validate()`'s, which `BlendedMegatronDatasetBuilder` runs (those that need no tokenizer are `validate_without_tokenizer()`'s, which `validate()` runs first); mock data uses the arbitrarily even split whatever `split` says, as before, with `split` left as given; the deprecated `hybrid_context_parallel` alias of #7047 is warned about and rejected next to `dynamic_context_parallel` by `validate_without_tokenizer()` but not rewritten there (`validate_args` and the training container normalize it; a Core-only caller sets `dynamic_context_parallel` itself); `MaskedWordPieceDatasetConfig` (BERT, T5) and `MultimodalDatasetConfig` keep their own `__post_init__` checks without chaining to a base method. `mock`, `split_matrix` and `token_dtype_code` are read-only properties instead of `init=False` fields: readers are unchanged, they cannot be assigned, `token_dtype_code` follows the tokenizer as soon as it is bound, and a mock config's `split` stays as given, `None` on the CLI without `--split` (the even split is `split_matrix`, whatever `split` says, as before); `sanitize_dataclass_config` drops the three names from older `run_config.yaml` files that carry them. A caller that wants the assertions before building calls `validate()`. `GPTFIMDatasetConfig.validate()` requires the two FIM rates and the five extra tokens to be given; a rate of `0.0` is a value, as before (`validate_args` keeps its own check for `--fim-data`).
- Megatron-Bridge: its `GPTDatasetConfig.finalize()` calls `super(MCoreGPTDatasetConfig, self).__post_init__()` explicitly (`training/config.py:332`), a method this PR removes, so Bridge's bump PR replaces that line with `super(MCoreGPTDatasetConfig, self).validate()` or `self.validate_without_tokenizer()` (the same checks); until then its data and training-config unit tests against this branch show 28 differing ids against `main` (210 failed on the branch, 182 on `main`), all failing inside `GPTDatasetConfig.finalize()` on the removed base `__post_init__`; with that one line applied to Bridge `d86a5c09b`, the same suites against this branch are identical to `main` again (0 differing ids of 1535). Agreed with the Megatron-Bridge PIC: Bridge adapts when it bumps its Megatron-LM pin. Everything else keeps working as is: its provider reads `mock` (a property), it binds the tokenizer in `setup()` before any build (so the builder's `validate()` passes, with the `reset_*` flags its `finalize()` asserts; its hand-written `token_dtype_code` assignment runs only when the value is `None`, which it no longer is once the tokenizer is bound), and its container calls `validate()` only on its SFT / HF / Energon configs. Two further bump items: the `token_dtype_code` block in `setup.py` is dead code, and the CLI translator's `dataset.mock=true` override for `--mock-data` names a read-only property. Bridge imports other sections of `megatron.training.config`, not the dataset one.

Documented behaviour differences, all intentional:

1. A request with no data source and no `--mock-data` selects the mock dataset class where the family has one (gpt, sft, varlen; fim has none and fails at validation), with a warning; the legacy providers keyed on `--mock-data` and paired a mock runtime config with the real dataset class, which failed to build.
2. `--mock-data` next to `--data-args-path` or `--per-split-data-args-path` (accepted by `validate_args`, which does not count file-backed sources) is rejected by the factory with the single-source message; the legacy providers paired `MockGPTDataset` with a config resolved from the file, which `MockGPTDataset` refuses, so the combination never trained.
3. `pretrain_hybrid.py` and `pretrain_hybrid_flex.py` build the requested dataset family, as `pretrain_gpt.py` does: `--fim-data` builds `GPTFIMDataset` where the legacy providers silently built plain GPT data, and `--sft --mock-data` builds `MockSFTDataset` where they selected the real `SFTDataset` around a mock config and failed inside the builder (`SFTLowLevelDataset(None)` raises `EmptyDatasetError`). On `pretrain_hybrid_flex.py` an SFT build, mock or real, still fails in `SFTDataset`'s padding divisor because the script builds its container without a model config (no layout), exactly as `--sft` fails there on `main`. A missing data source on `tools/prepare_cache.py` is rejected at validation instead of inside the builder.
4. `--sft --fim-data` and `--use-varlen-dataset --fim-data` keep their dataset class and every shared field, but the config is a plain `GPTDatasetConfig` instead of the FIM wrapper `pretrain_gpt` built around an SFT / varlen dataset (the packed datasets read no FIM field; AST check and identical mock samples under both configs in the tests).
5. The GPT providers use the run's tokenizer, bound once, instead of building a second tokenizer from `args` inside the provider; `pretrain(build_tokenizer=False)` with the stock GPT provider stops in the provider with a message naming `bind_tokenizer()` (no in-tree caller does this; `examples/mimo` passes `build_tokenizer=False` with its own provider).
6. The FIM flags without `--fim-data` are parsed as before but not stored: a plain `GPTDatasetConfig` has no FIM field, so `run_config.yaml` no longer records them.
7. The data-args and sequences files are read when the container is built, on every rank, instead of inside the provider; `pretrain_gpt` already ran its provider on every rank. `run_config.yaml` records the resolved blend.
8. `pretrain_hybrid_flex.py` forwards every data argument: `--multiple-validation-sets`, `--allow-ambiguous-pad-tokens`, `--dataloader-fast-cache-load`, `--dataloader-defer-npy-index-mmap` and `--per-dataset-sequences-path` take effect where its legacy factory ignored them (its only CI case, `hybrid_flextron_nightly_tp2_pp1_ep2_dgx_h100_1N8G`, passes `--data-path` alone); `--use-varlen-dataset` is rejected with an error where it silently built plain GPT data (its batch path has no varlen support). The layout mirrors still take Megatron Core's defaults there, as before, because the script builds its container without a model config.
9. `tools/prepare_cache.py` forwards the four fields its legacy factory left out (`inter_document_masking`, the two mock-dataset JSONs, `varlen_sbhd_validation`); none affects the cache it writes. `pretrain_hybrid.py` forwards `sft_mock_dataset_config_json`, read only by the mock SFT dataset it can now build.

Scope boundary: dataset construction is migrated; the data loaders and batch functions still read `args` (`pin_memory`, `persistent_workers` and `drop_last` are accepted in YAML / Python but the existing loaders keep their built-in values until the consumer migration, next PR), and `args.seq_length` keeps its readers (`cfg.data.dataset.sequence_length` is the sample length; the container checks that `model.seq_length`, the position-embedding capacity, covers it).
