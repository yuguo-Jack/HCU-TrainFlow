# What does this PR do?
<!-- Add a one line overview of what this PR aims to accomplish. -->

MFSDP v2 all-gathered both rowwise and columnwise MXFP8 weight
  planes (data and scales) at every unshard, although forward GEMMs read only rowwise
  planes and backward data-gradient GEMMs read only columnwise planes. This PR enables that unshard
  gathers only the planes its compute phase reads, roughly halving MXFP8 weight
  all-gather bytes.

## Issue tracking

Closes #7584 
| Requirement from #7584 | Status |
  |---|---|
  | Forward gathers rowwise data and scales | Done |
  | Backward gathers columnwise data and scales | Done |
  | Activation recomputation gets the forward representation again | Done: rowwise planes are gathered on demand during recomputation |
  | Correctness across resharding and optimizer updates | Done: covered by bit-exact recomputation and training tests |
  | Numerical parity with existing MXFP8 tests | Done: existing MXFP8 training tests pass unchanged |

## Design

  - `FsdpModule.unshard(compute_phase, prefetch)` takes a dtype-agnostic `ComputePhase`
    (`FORWARD`/`BACKWARD`); prefetch follows that phase's module order. `unshard()` with
    no arguments still unshards every phase, so external schedulers are unchanged.
  - `FsdpParameterGroup` translates the phase into the data to unshard and tracks what is
    already installed. MXFP8 groups gather rowwise planes for forward and columnwise planes
    for backward; regular groups and already-unsharded compute weights install everything
    at once.
  - Activation recomputation gathers rowwise planes on demand, since backward prefetch
    cannot tell whether a module recomputes (same strategy as MFSDP v1).
  - Compute tensors carry only installed planes, with a quantizer advertising the same
    usages. TE saves the weight Parameter itself for backward, and reassigning `.data`
    updates it in place, so backward reads columnwise planes gathered after forward.
  - `QuantizedDBuffer.redistribute` accept `rowwise=`/`columnwise=`.

  ## Tests

  - Forward unshards only rowwise planes and backward only columnwise planes.
  - Reentrant and non-reentrant recomputation match no recomputation bit-exactly
    (losses, gradients, updated weights), with shapes needing padded scales.
  - Partial-plane redistribution and compute tensors, including rowwise-only (TN) and
    columnwise-only (NN) GEMMs against TE references.

- XiaodaNV · comment · 2026-10-18T13:03:41Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/7907#issuecomment-6250248314)

@wujingyue  I added after rebasing onto main: `_release_symmetric_memory_pools()` in `tests/unit_tests/distributed/mfsdp_v2/conftest.py` (commit 6700971).

  **Symptom.** After the rebase, running the whole mfsdp_v2 suite (as GB200 CI does) deterministically hung in `test_symmetric_memory.py::test_fully_shard_symmetric_memory_matches_default_and_profiles_nccl`. Each test file run on its own passed.

  **Root cause.** `symm_mem.get_mem_pool()` caches one pool per device for the whole process, and rendezvous is cached per allocation. Pool state left by earlier tests diverged across ranks, so ranks 0/2 reused segments already rendezvoused by `test_cuda_graph` and returned from the cache, while ranks 1/3 got fresh segments and blocked in the registration collective. The rebase only changed the allocation history enough to expose this; the same hazard exists on main.

  **Fix (tests only).** In `distributed_setup` teardown, after the barrier and before subgroups are destroyed, drop the cached symmetric-memory pools (`gc.collect()`, `synchronize()`, `_symm_mem_pools.clear()`, `gc.collect()`), so every test starts from an empty pool. With this, the full suite passed twice in a single process.
