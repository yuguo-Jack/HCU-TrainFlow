# [Inference][MLA][MTP] Let latent-caching MLA layers run MTP draft steps without an inference context

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8703) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Fixes MTP speculative decoding in the dynamic engine for every MLA model. On `main` it crashes for heads with one layer per depth and is rejected for repeated heads. The MTP draft step now runs the MLA layer with the unabsorbed attention that training uses, for both kinds of head.

**Stacked on [#8702](https://github.com/NVIDIA/Megatron-LM/pull/8702) (n6)**: "[Inference][MLA] Cache whole MLA latents on each TP rank with sequence parallelism". This branch merges n6's branch, so its diff includes n6's commits until n6 merges. This PR's own changes are the commits "Let latent-caching MLA layers run MTP draft steps without an inference context" and "Address review feedback: MLA draft up-projection, repeated MLA heads, engine test".

## The bug

Dynamic-batching MLA requires `cache_mla_latents=True`. With MTP (`num_speculative_tokens > 0`), the engine fails with:

```
AssertionError: Caching MLA latents only works with dynamic backend inference
  multi_latent_attention.py  MLASelfAttention.get_query_key_value_tensors
  <- MultiTokenPredictionLayer.forward_single_position
  <- LanguageModule.compute_mtp_single_step
  <- MTPControllerMixin._compute_serial_mtp_and_sample_impl
```

The crash happens at the first draft step. With CUDA graphs it happens earlier, while the engine captures the MTP graph (`DynamicInferenceEngine.create_cuda_graphs`). We found it with a configuration matrix on H100: GPT + MLA + MoE, `mtp_num_layers=2`, `num_speculative_tokens=2`, with eager and CUDA-graph rows and both the legacy and async schedules. The GQA rows with the same MTP setup pass.

The draft step passes the MTP layer an inference context only when the context has reserved an MTP draft KV plane. `MTPContextMixin.should_enable_mtp_kv_cache` reserves one only for a repeated head (`mtp_use_repeated_layer=True`), and `TextGenerationController` then rejected that plane for MLA ("MTP KV caching does not support MLA's rotary position embeddings"). On `main`, an MLA model with a repeated head therefore fails at engine construction. A head with one layer per depth always drafts without a context. DeepSeek-V3-style checkpoints are built this way (`mtp_num_layers=1`, no repeated layer). Without a context, `get_query_key_value_tensors` still took the cached-latent branch and asserted. The absorbed V up-projection after the core attention would also have called `inference_context.is_decode_only()` on `None`.

## Root cause and fix

`MLASelfAttention` treated `cache_mla_latents` as "every inference forward has a dynamic context". A forward with no context has no latent cache to read from or write to.

- `get_query_key_value_tensors` takes the cached-latent branch only when a context is given. A static context still asserts. Without a context, the forward runs the unabsorbed q/k/v path, `qkv_up_proj_and_rope_apply`, which is the attention training uses.
- That path up-projects cached-mode latents with n6's `up_project_whole_latents`.
  - In cached-latent mode every TP rank holds the whole latents; n6 gathers them along the sequence under sequence parallelism. Every cached-latent forward also runs `prepare_for_absorption` first, which replaces `linear_kv_up_proj` (a fused KV norm becomes `kv_layernorm`).
  - `up_project_whole_latents` is a local GEMM on this rank's column shard of the KV up-projection weight. It never runs `linear_kv_up_proj_linear`. Under sequence parallelism that module all-gathers its input along the sequence, whatever it is: the `TEColumnParallelLinear` split from the fused module, or the `InferenceColumnParallelLinear` that #8570 keeps. Gathering whole latents again would give `[TP * s]` keys against `[s]` RoPE keys.
  - As in the cache up-projection of prefill and in absorbed decode, the GEMM runs in high precision (quantized weight storage is dequantized).
- The absorbed V up-projection after the core attention now also requires a context.
- `should_enable_mtp_kv_cache` declines the draft KV plane for MLA. The plane assumes keys without RoPE, and MLA always applies RoPE to the keys' positional part. A repeated MLA head therefore drafts without a context, as a per-depth head does, applying its one layer at every depth. The controller's MLA rejection is removed, since no MLA head gets a plane any more. The controller still rejects a plane for models with positional embeddings, as before.

Forwards that have a context are unchanged. There are no new host syncs. The MTP CUDA graph captures the same path, because absorption happens in the eager warmup run that precedes capture.

### Why not the other options

- **A draft KV plane for MLA heads, or one for each MTP layer.** The plane assumes keys without RoPE, so it cannot hold MLA keys as it stands. A plane for each layer is also a design question. In training, the history of MTP layer k pairs layer k-1's outputs with tokens k+1 positions ahead. For k >= 2, that history depends on tokens that are still drafts. This is feature work, not a fix.
- **Reject MLA + MTP at config time.** That would remove MTP speculative decoding for every MLA model, although the draft step can run MLA. Reject only what cannot be supported.

## Drafts across requests: fixed by n13

Without a context, the draft step lays the active requests out as one sequence, `[N, 1, H]`. On `main` the MTP layer's causal attention then lets request j's draft attend to the MTP inputs of requests 0..j-1. This affects every attention type on this path (MLA after this PR, GQA, the attention layers of hybrid heads) and the Mamba layers of hybrid heads. It changes drafts and acceptance, not verified outputs.

n13 ([#8710](https://github.com/NVIDIA/Megatron-LM/pull/8710)) fixes it: "[Inference][MTP] Draft each request on its own when the MTP head has no draft KV plane". It runs each request of the context-free forward as its own single-token sequence (THD `PackedSeqParams`). The two PRs touch different files and compose. With both, MLA's context-free forward squeezes to `[t, ...]`, applies THD RoPE with `max_seqlen=1`, and runs the core attention on the single-token pack as sbhd `[1, t]`, with no V padding. On CPU, with both fixes (n13 before its review rework), cached and uncached MLA drafts were bit-identical at both depths, and perturbing request 0 left the drafts of requests 1-3 bit-identical. n13's isolation test has `mla` and `mla_cached_latents` cases; the cached one skips until this PR is present. The MLA+MTP matrix rows pass on H100 with both fixes.

Test coverage of MLA on n13's path: n13's `TestMTPDraftStepRequestIsolation` gains an `mla` case that skips until this PR is present. Whichever of the two PRs lands second removes that skip.

  - `test_forward_matches_layer_without_cached_latents[rope|yarn]`: an `MLASelfAttention` with cached latents runs twice without a context, once absorbing and once already absorbed. Each output must match the same weights without cached latents.

  - Both compare in FP32 at `rtol = atol = 1e-3`. The cached path's GEMM runs in torch's FP32, while Transformer Engine runs FP32 GEMMs in TF32.

A forward without a context must keep every token's whole latent, identical on both ranks. - `TestMtpKvCacheGating::test_unsupported_config_has_no_draft_kv_plane[mla|hybrid-mla]` in `tests/unit_tests/inference/contexts/test_dynamic_context_mtp_kv_cache.py` (1 GPU): a repeated MLA head, GPT or hybrid, gets no draft KV plane. The controller's MLA rejection test is removed.
- `TestMLAMTPCudaGraphInference::test_greedy_generation_with_mtp_cuda_graphs[per-depth|repeated]` in `tests/unit_tests/inference/test_mtp_cuda_graph_inference.py` (2 GPUs).
  - Setup: an inference-optimized GPT MLA model (FlashMLA's decode shape), TP=2 with sequence parallelism, and `num_speculative_tokens=2`. The dynamic engine captures decoder and MTP CUDA graphs.
  - Four greedy requests must complete with all their tokens, drafts must be proposed, and the MTP graphs must be recorded.
  - The test clears the NVTE attention variables before building the model and leaves the attention backend on `auto`, so dynamic prefill runs the newest FlashAttention installed.
  - Requirements: FlashAttention-4 or -3 (FlashAttention-2's varlen kernel needs equal q/k and v head dims, which MLA prefill does not have), and FlashMLA with decode kernels for the GPU. The test probes FlashMLA in a subprocess and skips without either. The CI image's FlashMLA has no SM90 kernels, so this test skips on H100 there until the CI image builds them.
