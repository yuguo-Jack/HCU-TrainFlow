# What does this PR do?

Adds `tests/unit_tests/inference/oracles/`: shared helpers and conventions for testing inference kernels against **independent oracles**, i.e. references that do not share the kernel's algorithm. Kernel-family test packages will be added on top of it in follow-up PRs. No production code changes.

## Why

Most inference kernels are tested against references that mirror the kernel step by step, by determinism replay, or end to end only. An independent oracle needs the same pieces every time: an fp64 reference, a tolerance that is not a hand-tuned `atol`, inputs at the kernel's tile and chunk boundaries, out-of-bounds checks, hardware gating that cannot pass silently, and statistics for samplers. This PR writes them once, with tests.

## What is in it

- **`oracle_utils.py`**
  - **fp64 references**: `fp64_reference(fn, *inputs)` runs a plain-PyTorch reference on exact fp64 copies of the kernel's rounded inputs, and rejects a reference that rounds. `dyadic_tensor` makes inputs whose sums and dot products are exact in fp32 in any order, so a reduction can be checked exactly.
  - **Tolerance policy, with no hand-picked `atol`**: `assert_close_to_reference(actual, reference_fp64, trusted)`. The kernel's max-abs and rms errors against the fp64 reference must each be at most `factor` (default 2) times the error of a trusted implementation in the same dtype (e.g. torch's bf16 op), measured in the same test. A floor of one ulp at one element covers exact-zero cases. Optional per-slice bounds (`dim=-1`) handle rows of different scale. The failure message reports the kernel's and the trusted errors, the bound and the worst element. NaN/inf must match the reference.
  - **Exact assertions**:
    - `assert_exact` (integers by value, floats bitwise) with the first mismatches listed;
    - `assert_is_permutation`;
    - `assert_rows_equal_unordered` for outputs whose order inside a group is unspecified;
    - `assert_quantized_bit_exact`, which reports codes and scales separately and splits code mismatches into those under a wrong scale and those under a correct one.
  - **Structure-derived sizes**:
    - `boundary_sizes` / `size_params`: B−1/B/B+1 and multiples around tile, chunk and window sizes, 0/1 and production sizes; the params carry ids that say why each size is there;
    - `int32_overflow_rows` / `int32_overflow_params`: row counts whose element offsets straddle 2³¹, marked `large`;
    - `pairwise_cases` to combine factors.
  - **Memory safety**:
    - `guarded_empty` / `guarded_like` / `check_guards`: a buffer with guard bands before and after it in the same allocation. The guards are filled with NaN sentinels with an unusual payload, so an out-of-bounds write changes their bits and an out-of-bounds read turns an output into NaN. The check reports the offsets.
    - `poison_` / `poisoned_empty` / `assert_poisoned`: NaN (or out-of-range integer) poison for outputs, padding and rows past the live count.
  - **Hardware**: `requires_sm(HOPPER | BLACKWELL)`.
    - Off-target, a test skips with a reason.
    - It fails instead when the run targets that hardware but the device differs. A run targets hardware through `-m launch_on_gb200`, as in GB200 CI, or through `MCORE_ORACLE_TARGET_SM` set by a runner. A misplaced runner cannot pass by skipping.
    - A Blackwell test must carry `@pytest.mark.launch_on_gb200` literally in its file. GB200 CI launches only such files (`find_test_cases.py`), and the conftest fails a Blackwell test without it, so none is silently never run.
  - **Sampler statistics**, each with a stated false-failure rate (`alpha`, default 1e-6) and a fixed seed:
    - `assert_matches_distribution`: chi-square goodness of fit per row, small bins pooled, Bonferroni over rows; a sample on a zero-probability token fails exactly.
    - `assert_counts_within_binomial_bounds`: exact per-category binomial bounds.
    - `samples_to_detect` sizes a test.
- **Upstream bugs** (`xfail_upstream`): the one allowed xfail, for a confirmed bug in an upstream package that no Megatron change can fix. It is strict, and applies only while the installed package is at most `fixed_after`, the release the CI image pins (`uv.lock`). A newer release runs the test normally, and an XPASS fails until the mark is removed. The reason names the finding and its drafted upstream patch. A Megatron bug keeps a plain failing test until its fix PR lands. `drain_cuda_launch_error`: after a test raises, the conftest clears a pending CUDA launch error, so a kernel that failed to launch cannot fail the next test.
- **CI**:
  - This directory is its own unit-test bucket on H100 and GB200, apart from the broad inference bucket (`tests/test_utils/recipes/{h100,gb200}/unit-tests.yaml`, dev image). A file that takes more than about 5 minutes on H100 gets its own entry.
  - The H100 recipe exports `MCORE_ORACLE_TARGET_SM=9`, so a dependency missing from the image fails the oracles instead of letting them skip. GB200's `-m launch_on_gb200` already targets sm_10x.
  - `use_local_rank_device` gives each rank its own GPU, since CI runs every bucket on all GPUs and every rank runs every test.
  - README "CI" explains the wiring.
- **`conftest.py`** registers the `requires_sm`, `sanitizer` and `large` markers for this directory. `large` tests are skipped unless the `-m` expression names `large`. `sanitizer` marks small cases for a `compute-sanitizer` pass.
- **`README.md`**: the conventions. One module per kernel, with a contract docstring, an fp64 reference, structure-derived inputs, a tolerance class per output and memory checks. It also explains how a family package plugs in and gives an example module.

### Choice of the default factor

Measured on CPU (torch 2.14), kernel error divided by the error of torch's op:

| Case | max-abs | rms | default policy |
|---|---|---|---|
| bf16 GEMM, fp32 accumulation in 64-wide tiles (correct), K = 256 / 1024 / 8192 | 1.00 | 1.00 | pass |
| bf16 log-softmax, RMSNorm, SiLU (correct, fp32 compute) | 0.86–1.00 | 0.97–1.00 | pass |
| bf16 GEMM with a bf16 accumulator, K = 1024 / 8192 | 3.2 / 9.5 | 3.0 / 7.9 | fail |
| bf16 GEMM dropping the last 32 of K | 31–201 | 37–214 | fail |
| one output element with its sign flipped | 12–90 | 1.4–5.4 | fail |
| fp32-output GEMM, fp32 tiles of 64 summed in sequence vs. a blocked CPU GEMM, K = 8192 (correct) | 3.07 | 1.80 | fail |

With bf16 outputs, the final rounding dominates and correct implementations agree to within a few percent. With fp32 outputs of long reductions, the summation order dominates (last row). There, the trusted implementation should come from the same device (cuBLAS for a GPU GEMM), or the test raises `factor` and says why; the docstring states this.

## Tests

`tests/unit_tests/inference/oracles/test_oracle_utils.py` tests each helper both ways: it passes on correct data, and it fails, with a useful message, on the bug class it targets. The cases include:
- the tolerance policy fails a kernel that is worse than the trusted implementation by more than the factor (2.5× and 4×), and passes 1.5× and 1.9×;
- it fails a kernel with a bf16 accumulator;
- its one-ulp floor admits one element off by an ulp, but not an ulp everywhere;
- per-row bounds catch a 10% error in a row 10⁶ times smaller than the others;
- guard bands catch a write one row past the end and one element before the start;
- `int32_overflow_rows` straddles 2³¹;
- `pairwise_cases` covers every pair;
- `binomial_bounds` matches exact enumeration;
- a correct sampler fails at the stated rate over 400 seeds, a biased one fails, and a sample outside the support fails;
- `hardware_decision` covers run, skip and fail for H100, GB200 and no GPU.

Two marker tests check the gating end to end, one per architecture: each asserts the device's compute capability and runs only on its own hardware.

- **On CPU** (no CUDA device): 57 cases, 55 passed. The 2 hardware-gated cases skip with their reason.
- **With a CUDA device**: 4 more guard-band cases run on it.
- **On H100**: the Hopper case runs and the Blackwell case skips. In GB200 CI, only the Blackwell case runs: it is the only test in the file marked `launch_on_gb200`.

## Notes for reviewers

- **Markers.** They are registered in this directory's `conftest.py`, not in `pyproject.toml`, so the PR touches only the new directory. `launch_on_gb200` is the existing marker. `PLATFORM_MARKERS` and `file_has_marker` are imported from `tests/unit_tests/find_test_cases.py`, so the gating follows CI's own selection rule.
- **The `large` opt-in** reads the `-m` expression. Neither CI job names `large`, so int32-overflow sizes never run in CI; they run on a runner that selects `-m large`.
- **Determinism.** No kernel or dispatch changes, so there is no determinism test or manifest entry.
