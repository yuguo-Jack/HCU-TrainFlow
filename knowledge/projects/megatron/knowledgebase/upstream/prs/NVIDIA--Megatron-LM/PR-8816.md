# Use Megatron-FSDP's own groups for UBR barriers and DCP key gather

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8816) · state: closed · merged: False

## Original PR description

**Why.** Three Megatron-FSDP collectives run on the default (WORLD) group, although only the ranks of one model need to agree.
- `ParamAndGradBuffer.__init__` with `nccl_ub` runs a WORLD barrier after the barriers on its user-buffer groups.
- `manual_buffer_registration()` starts with a WORLD barrier for every buffer. Megatron-LM training calls it once per model chunk when `--nccl-ub` is set, since `--fsdp-manual-registration` is then on by default.
- The `state_dict()` hook that `fully_shard_optimizer(..., preproc_state_dict_for_dcp_ckpt=True)` installs all-gathers the optimizer state keys over WORLD.

Every rank of the job has to enter each of these, the same number of times. Two cases break that.
- Models on disjoint DeviceMeshes in one job, such as an actor and a reference model, or module-per-grid MIMO. When only one model saves or builds a buffer, its ranks wait on ranks that never arrive. Otherwise the collective pairs ranks of different models.
- Ranks that own different numbers of FSDP buffers.

The key gather also merges the keys of unrelated optimizers. A rank of an Adam model with an empty shard would mock a `momentum_buffer` entry from an SGD model elsewhere in the job.

**What.**
- `param_and_grad_buffer.py`: drop the WORLD barrier in the constructor. The memory pool is registered only on `self.ubr_groups`, and the loop just before it already runs a barrier on each of them. The default group is never registered.
- `param_and_grad_buffer.py`: `manual_buffer_registration()` runs a barrier on each group in `self.ubr_groups`, the groups it registers the pool on next.
- `fully_shard.py`: the DCP hook gathers the keys over `dist_index.get_dp_group()`, the hybrid group under HSDP. When the index has an expert DP group, it gathers over that group too.
- The DP group's ranks together hold every DP shard of each non-expert parameter. At least one of them has optimizer state, so the union is the optimizer's key set. That matches what the WORLD gather returns when one model spans the job.

Who enters each collective:
- Every rank of a Megatron-FSDP model builds its buffers and calls `manual_buffer_registration()` on them in the same order.
- Each group in `ubr_groups` (FSDP, expert FSDP, the two all-gather groups, outer FSDP) and each DP group holds ranks of that model only. None spans pipeline stages.
- Every member walks the same role-ordered group list. Each barrier is entered by exactly its group's ranks, the same number of times.
- `state_dict()` was already collective over the model's mesh, because the chunk-metadata sync after the key gather runs on the DTensor mesh groups. Whether the expert gather runs depends only on the `FSDPDistributedIndex` arguments, which match on every rank of the model.

**Tests.**
- New `tests/unit_tests/distributed/mfsdp_v1/test_mfsdp_submesh_collectives.py`, 6 cases. It splits the world into two models on a `(model, dp_shard)` DeviceMesh, with and without an EP=2 expert mesh. The second model issues one more call than the first. Any `barrier` or `all_gather_object` on the default group raises, so main fails instead of hanging.
  - Buffer construction with `nccl_ub=True` and a stub NCCL allocator. It asserts the barriers run on the FSDP group, then the expert FSDP group.
  - `manual_buffer_registration()` on 1 or 2 buffers. It asserts the barriers and the pool registrations run on the same groups.
  - `fully_shard_optimizer()` on a `Shard(0)` DTensor parameter whose last DP rank holds 0 rows. Model 0 uses Adam and model 1 SGD with momentum. It asserts the key gather groups, that the empty rank mocks exactly its own optimizer's keys, and the chunk offsets on the other ranks.
- On 4 CPU ranks with Gloo: 6 passed on this branch, 6 failed on main with only the new file added. Each failure on main is the assertion at one of the three WORLD calls. The 6 cases also pass on 8 Gloo ranks, and skip on 2.
- Neighbouring files on 4 CPU ranks give the same results on both trees. `test_mfsdp_mixed_precision_policy.py` has 3 passed and `test_mfsdp_parameter_grouping.py` 5 passed. `test_mfsdp_hybrid_sharding.py` has 11 failed and 10 skipped on both, since it calls `torch.cuda.set_device`.
- GPU runs:
  - `test_mfsdp_submesh_collectives.py`: all 6 cases pass on 4 GPUs with NCCL.
  - `test_mcore_fully_sharded_data_parallel.py::TestFullyShardedDataParallel::test_fsdp_user_buffer_registration`: `[8-True-True-False-False]`, `[8-True-True-True-True]` and `[8-False-True-False-True]` pass on 8 GPUs (two nodes) with this change merged into the rest of #6307, as they do on main. These build real NCCL memory pools and cover both the constructor and manual registration.
  - `test_mfsdp_fully_shard.py::TestMegatronFsdpFullyShard::test_dcp_checkpoint_save_and_load` on 8 GPUs (two nodes, with the test's shared temp directory on shared storage): 30 passed, 12 skipped and 6 expected failures on this branch, the same as on main. It covers the key gather over the FSDP group and over the hybrid group.
- No GPU test fully shards a real model on a sub-mesh with `nccl_ub`. The CPU test covers the group choice, not NCCL registration.
- `tools/check_process_group_usage.py` reports the same 3 pre-existing entries before and after.
- `tools/check_kernel_determinism_coverage.py` passes for the 3 changed files.

**Compatibility.**
- Without `nccl_ub` and without `preproc_state_dict_for_dcp_ckpt`, nothing changes.
- With `nccl_ub`, buffer setup and manual registration no longer synchronize ranks outside the buffer's groups. When one model spans the job, the only difference is one fewer barrier at construction, and smaller barrier groups at manual registration.
- When one model spans the job, the DCP key set is the same as before. Under EP there is one extra small gather over the expert DP group.
