# Record and replay runtime prefetch order for MFSDP v2

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7998) · state: open · merged: False

## Original PR description

## Summary

Record actual MFSDP v2 parameter demands over a complete iteration, preserving repeated module calls and mixed forward/backward phases. This builds on the merged ExecutionOrder change (#8207) and brings the iteration-scope implementation from #8284 into this PR.

## Changes

- Keep ExecutionOrder generic: callers store weak module references or `(weakref(module), phase)` pairs. Traversal uses `advance()` and an explicit reset, without module lookup or `_unique_index`.
- Add `iteration(context, key=..., rerecord=...)`. The first successful scope records every demand; subsequent scopes validate replay and prefetch through a separate monotonic cursor. Failed or divergent iterations invalidate their cached order.
- Preserve static forward/backward prefetch without a recording scope. Root hooks reset the static cursors at the first root; active iteration scopes own their cursor lifecycle.
- Scope the VPP and combined 1F1B entry points, and issue phase-aware demands from the combined hooks.
- Retain `--megatron-fsdp-record-prefetch-order` for other eager training schedules. Training and validation share the same scope wrapper, with separate cache keys for their schedule configurations.
- Record repeated backward invocations while opening a shared module's backward phase and NVTX range once, preserving the current gradient-completion lifecycle.

## Usage and limits

For ordinary eager training, enable `--use-megatron-fsdp --megatron-fsdp-version 2 --megatron-fsdp-record-prefetch-order --cuda-graph-impl none`. Static forward/backward prefetch continues to work without this flag. Eager VPP and combined 1F1B enter the scope at their schedule boundaries.

Recorded schedules must be repeatable and collective-compatible across peers. Explicit scope keys or `rerecord=True` handle changed execution patterns. CUDA graph recording/replay is outside this change.

**Work in progress:** an earlier combined VPP experiment stalled during replay, including in its eager reference. That issue has not been resolved or revalidated on this revision; the presence of iteration scopes does not establish combined VPP correctness.

## Validation

- Import sorting, Black 26.3.0 (core/tests), Ruff, syntax parsing, and whitespace checks passed.
- Preserved the distributed shared-projection regression comparing outputs, gradients, and SGD updates across recording and replay. Added iteration/checkpoint coverage and retained existing context regressions.
