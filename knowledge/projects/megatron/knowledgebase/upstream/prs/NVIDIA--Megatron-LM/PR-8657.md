# Unify residual connection dispatch for eager and checkpointed execution

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8657) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

## What does this PR do?

Route eager and checkpointed residual operations through `ResidualConnection.forward`, and migrate the existing wide residual (WR) Transformer and Mamba callers to that interface.

Previously, eager calls entered the residual module normally, while `checkpoint_residual_read` and `checkpoint_residual_write` called its checkpoint methods directly. A forward override or module hook could therefore affect eager execution while being bypassed when recomputation was enabled. 

## Changes

- Add `recompute_context` to the module call. `None` selects `_eager_read` or `_eager_write`; a context selects the corresponding checkpoint implementation. Rename the private `_read` and `_write` methods to `_eager_read` and `_eager_write`.
- Add a separate `execution_context` for algorithm-specific dependencies supplied by the caller, such as the existing parameter-owning module in the mHC implementation. This keeps execution policy separate from parameter ownership.
- Remove `checkpoint_residual_read` and `checkpoint_residual_write`, and migrate WR callers to direct module calls. Preserve the existing terminal-write decisions and gradient scopes.
- Share WR arithmetic through `_compute_read` and `_compute_write`. Keep carried-state construction and FP32 residual promotion outside read replay, and preserve write casting, bias, dropout, controller, and retention behavior.
- Share Transformer residual reader/writer lookup using the existing registered attribute names. Add invocation methods with an explicit attention/MLP stage, so adapters can specialize each call while reusing the existing norm, gradient-scope, and offload schedule.
- Let the residual reader own the carried state and reject tuple-returning norms when a reader is active. Preserve input retention and selected residual aliases for ordinary tuple-returning norms.

Each connection still chooses which computations can be replayed and which state must remain live. Hooks and forward overrides must not modify checkpoint-owned output storage in place, because replay reconstructs the original values.

## Issue tracking and follow up

General proposal: #7888.

**mHC follow-up: [#8669 — Use shared residual dispatch for mHC](https://github.com/NVIDIA/Megatron-LM/pull/8669) (draft, depends on this PR).**

#8669 adds parameterless mHC read/write adapters and reuses the shared Transformer schedule introduced here. It preserves the registered parameter owners, selected residual aliases, computed maps, and existing replay boundaries.

Together, these PRs give WR and mHC a common module-call contract and Transformer schedule while retaining their own arithmetic and state handling. The follow-up keeps the existing mHC manager entry point; manager/context unification is deferred to the subsequent layer PR. Adoption by the existing Hybrid wrapper and MFSDP parameter capture/integration remain separate follow-up work.

### 1. **[SUGGESTION Simplification] Mark the deferred stage argument as a migration hook**

**Failure:** Both production invocation methods accept `is_mlp` but never read it: [Transformer reader/writer invocation methods](https://github.com/NVIDIA/Megatron-LM/blob/ac5dd916646b8000eddb77fe5ddfb57e7905cc33/megatron/core/transformer/transformer_layer.py#L949-L981). Calling either implementation with `True` rather than `False` changes no behavior. The [test override](https://github.com/NVIDIA/Megatron-LM/blob/ac5dd916646b8000eddb77fe5ddfb57e7905cc33/tests/unit_tests/transformer/test_transformer_residual_dispatch.py#L91-L101) records it, but the production consumer is deferred to A2. This is not a numerical defect; the missing piece is the explicit TODO and migration note required for intentionally deferred arguments.

**Correction:** Retain the override interface and add the following note immediately before the module call in both `_read_residual_connection` and `_write_residual_connection`:

```python
# Temporary migration hook: the default WR invocation ignores is_mlp.
# TODO: A2's mHC overrides will use it to select the stage-specific owner.
```

**Preservation and acceptance:** Do not remove the stage flag or add artificial stage-dependent arithmetic. Retain the [dispatch test](https://github.com/NVIDIA/Megatron-LM/blob/ac5dd916646b8000eddb77fe5ddfb57e7905cc33/tests/unit_tests/transformer/test_transformer_residual_dispatch.py#L159-L215) assertions that attention events receive `False`, MLP events receive `True`, reader-selected state identity is preserved, and terminal/nonterminal writes retain their recompute contexts and gradient scopes. Static acceptance is an explicit migration note in both methods with unchanged calls and scheduling.

### 2. **[SUGGESTION Simplification] Document WR's intentionally unused execution context**

**Failure:** The dispatcher forwards the new `execution_context`, but every production WR implementation discards it: [eager read/write](https://github.com/NVIDIA/Megatron-LM/blob/ac5dd916646b8000eddb77fe5ddfb57e7905cc33/megatron/core/transformer/wide_residual.py#L231-L273) and [checkpoint read/write](https://github.com/NVIDIA/Megatron-LM/blob/ac5dd916646b8000eddb77fe5ddfb57e7905cc33/megatron/core/transformer/wide_residual.py#L315-L368). Supplying an object therefore has no effect for the current concrete connection. The [public contract](https://github.com/NVIDIA/Megatron-LM/blob/ac5dd916646b8000eddb77fe5ddfb57e7905cc33/megatron/core/transformer/residual_connection.py#L124-L134) describes its intended dependency role, but the source does not mark the current no-op and deferred mHC consumer as migration scaffolding.

**Correction:** Extend the [WR connection class docstring](https://github.com/NVIDIA/Megatron-LM/blob/ac5dd916646b8000eddb77fe5ddfb57e7905cc33/megatron/core/transformer/wide_residual.py#L187-L193) with:

```text
WR accepts but ignores execution_context to implement the shared signature.
TODO: A2's mHC adapter will consume it for its existing parameter owner;
WR continues to use its own registered maps and retention parameters.
```

**Preservation and acceptance:** Keep forwarding the exact object through the base dispatcher in eager and checkpoint modes; retain the [protocol test's identity assertion](https://github.com/NVIDIA/Megatron-LM/blob/ac5dd916646b8000eddb77fe5ddfb57e7905cc33/tests/unit_tests/transformer/test_residual_connection.py#L349-L406). WR must remain context-independent without registering supplied modules or changing state-dict ownership. A proposed regression check is to pass `execution_context=object()` to matched WR eager/checkpoint calls with dropout disabled and require unchanged outputs, carried state, and parameter names. Static acceptance is the explicit current-behavior/TODO note, with arithmetic and replay boundaries unchanged.

Both suggested documentation additions require author verification before adoption.
