# What does this PR do?

Adds `tests/unit_tests/inference/oracles/moe_activations/test_glu_options.py`. It tests the GLU options and the gated squared ReLU that #8566 adds to the inference MoE GLU kernels: `padded_swiglu`, `bounded_silu_mul`, `swiglu_with_probs` and `weighted_silu_mul_bounded`. The options are clamp, linear offset and interleaved FC1 layout. No production code changes.

**Stacked on #8566 (`fix/d2-moe-glu-options`) and on the MoE activation oracle PR #8968 (`test/inference-oracles-o2`)**, through the branch `test/inference-oracles-o2-glu-base`, which merges the two. Review only the last commit. Retarget to `main` once both land.

## The oracles

The contract is training's GLU: `TEGroupedMLP`'s unfused `glu`, and the fused `clamped_weighted_swiglu` for batch-invariant mode.
- **SwiGLU with options.** The reference is `silu(min(g, c)) * (clamp(u, -c, c) + offset)`, in fp64, with the clamp and offset as fp32 values. Each output must be the single bf16 rounding of an fp32 evaluation, and the harness policy holds per row against torch's fp32 ops. The clamp must keep NaN NaN.
- **Interleaved layouts** (block sizes 1, 32 and 64) must give bitwise the output of the same values laid out as halves.
- **Batch-invariant kernels.** With a clamp, the output must be bitwise training's `clamped_weighted_swiglu`. Without weights (probabilities applied to the expert input), it must be bitwise `weighted_swiglu(y, 1)`.
- **Gated squared ReLU.** The output must be bitwise training's bf16 GLU with the live compiled `squared_relu`, times the fp32 probability where the kernel applies one. This holds for NaN and infinities too.

The clamp values are 7.0 (as in GPT-OSS) and 7.3. bf16 cannot represent 7.3, so it separates an fp32 clamp bound from a bf16-rounded one.
