# Use slot-indexed in-place kernels for GDN decode

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7896) · state: closed · merged: True

## Original PR description


- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?
Speeds up Gated DeltaNet (GDN) decode in the dynamic inference engine. It removes the
gather/scatter of recurrent state, and CUDA-graph padding rows no longer cost any compute.

Previously, GDN decode ([#6499](https://github.com/NVIDIA/Megatron-LM/pull/6499)) clamped
padding rows (`batch_indices == -1`) to slot 0. It then gathered the conv and SSM state of
every row, ran the pip FLA kernels, and scattered the results back with a mask. Each decode
step moved the whole SSM state through a gather and a scatter, and ran the full recurrence
on every padding row.

## Performance (GB200, Qwen3-Next GDN dims, CUDA graphs)

Per-layer decode, measured as bucket / active rows:

| Bucket / active | bf16 state | fp32 state |
|---|---|---|
| 128 / 32 | 229.3 → 82.0 µs (2.80×) | 253.7 → 84.1 µs (3.02×) |
| 512 / 128 | 798.1 → 272.7 µs (2.93×) | 889.9 → 276.2 µs (3.22×) |
| 512 / 512 | 944.3 → 485.2 µs (1.95×) | 1146.4 → 493.5 µs (2.32×) |

- Kernels per step drop from 16 to 9.
- With no padding, the gain comes from removing the state gather and the masked scatter.
  At 512 / 512, bf16, those took 184 µs and 256 µs.
- With padding, the early exit also halves the recurrent kernel's time (442 → 210 µs at
  512 / 128).
- Outputs and conv/SSM caches are bitwise identical to the previous implementation on
  active rows.

End-to-end decode with a hybrid model (12 GDN, 4 attention and 16 MLP layers) on
`DynamicInferenceEngine`, using the median decode step:

| Requests |  100 | 128 | 512 |
|---|---|---|---|
| Speedup | 1.31× | 1.36× | 1.62× |

## Testing

- **FLA parity test:** now also covers the in-kernel gate.
- **Determinism replay test:** extended to the gated path.
- **GDN CUDA-graph test:** now replays a partly padded batch from non-zero state and compares
  the caches exactly.
- **Results on GB200:**
  - `tests/unit_tests/ssm`: the same results as `main` (1 pre-existing GDN2 failure on both).
  - GDN/GDP dynamic-engine tests: pass.

**Known issue, not caused by this PR:** with CUDA graphs on non-decode steps,
GDN prefill can hit an intermittent `illegal memory access`. FLA caches prefill chunk
metadata tensors and later frees them, while captured graphs still hold their addresses.
Clean `main` has the same freed metadata pointers. I will file an issue to track.

EDIT: filed issue #8151 to track the memory access issue in the base code.
