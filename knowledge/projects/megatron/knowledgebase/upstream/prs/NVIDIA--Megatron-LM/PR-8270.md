# test: cover eager MFSDP v2 HybridEP cuBLAS corruption

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8270) · state: open · merged: False

## Original PR description

Add a 100-step eager BF16 MFSDP v2 + HybridEP regression for #7400 after the cuBLAS upgrade in #7685. The old library can corrupt gradients while training still exits successfully; the resulting loss divergence fails the existing golden-value comparison.

Preserve the reproducer's GEMM dimensions, EP=2, four optimizer instances, dense/expert outer optimizer sharding, and two accumulation microbatches on eight GPUs. Explicitly select cuBLAS grouped GEMM and NCCL implicit launch ordering. Register one case in the internal GB200 merge-request and nightly suites, using the recipe's default of five repetitions.

Validate all 100 loss samples through the standard CI comparator, using its existing 5% tolerance and allowance for one outlier. The golden file contains only `lm loss`, recorded at full TensorBoard precision.

Validation uses saved NSC LHR training runs on eight GB300 GPUs with the published 26.09-based `mcore_ci_dev` image. Replayed the standard CI pytest comparison after selecting loss-only golden data:

- Shipped cuBLAS 13.8.1.7: all three independent 100-step runs pass, with zero samples outside tolerance and at most 0.55% loss deviation (training job 220207).
- Same image/source/training arguments with only old cuBLAS 13.8.0.4 preloaded: the loss comparison fails on 83 of 100 steps, starting at step 18 (training job 220220). The largest relative difference is 133.26% at step 47: 0.0580261 versus 0.0248759. Final loss is 43.47% higher.
- Four-GPU graph probes, including the existing graph case adapted to mock data, passed on both libraries and did not establish regression detection (jobs 220471 and 220549). The eager reproducer supplies the coverage here.
- Regenerated the selected loss metric from the onboarding TensorBoard events and verified that all 100 values and metadata match the original baseline exactly. Golden-file validation, configuration checks, and `git diff --check` pass. GB200 execution remains for internal CI.
