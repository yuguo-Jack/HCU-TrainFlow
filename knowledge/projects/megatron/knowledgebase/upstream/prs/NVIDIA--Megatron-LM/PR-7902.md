# What does this PR do?

Separate MFSDP v2 weight release from gradient reduction. For shared layers and delayed weight gradients, the parameter-gradient callback can arrive after module backward has finished consuming the weights. This change lets module completion release full weight storage while gradient reduction still waits for all contributions.

Diffbase: #8113 (`pull-request/8113`, rebased onto `431f1fb89`). The final-autograd callback and frozen-module completion fix are provided by that PR.

Changes on top of the diffbase:

- Register `post_backward()` for module completion and `post_accumulate_grad()` for parameter-gradient completion. The former releases weight storage and ends the backward phase; the latter packs and reduces gradients through the existing parameter countdown or TE completion hooks. Neither callback waits for the other.
- Retain full-shaped parameter bindings after releasing weight storage, allowing delayed `backward_dw()` to assign `.grad`. `finish_grad_sync()` restores sharded bindings after all backward work. Name binding and storage operations explicitly, and annotate storage release with its own NVTX range.
- Update combined 1F1B to register its trainable-unit callback through `register_post_accumulate_grad_hook()`, preserving its explicit resharding. Reject delayed wgrad without caller-managed synchronization during hook registration.
- Add a shared-layer storage regression using a raw PyTorch observer, extend the existing delayed-wgrad adapter test with a storage assertion, and simplify the synchronization rejection test.

Full backward hooks observe positional tensor inputs only. Modules receiving grad-requiring inputs solely through keywords use the final callback for weight release, which can increase peak memory. Gradient reduction may also precede weight release; the callbacks do not enforce an ordering.

## Functional performance comparison (NSC-LHR)

The existing GB300 comparison used baseline `dddd756` and PR revision `90cf910`, before the later storage-lifetime changes. These measurements have not been rerun against the current diffbase or head.

Seven existing 8-GPU configurations and one 4-GPU MXFP8 configuration completed **22 training runs of 50 steps**, including repeat comparisons. Every paired logged loss and peak-allocation value matched. Training and optimizer CUDA graph capture completed in the graph recipe.

The runs used `MockGPTDataset` and `NullTokenizer` (50257 tokens), preserving model, batch, and iteration settings. Both benchmark snapshots required the same `caller_managed_grad_sync=True` setup correction in `megatron/training/models/dist_utils.py`. These are paired performance measurements with mock data, not CI corpus/golden-value results.

Step time is the median over iterations 11–50. Memory is the maximum TensorBoard allocation on the CI logging rank, not the maximum across ranks. Each pair ran sequentially in the same allocation and container.
