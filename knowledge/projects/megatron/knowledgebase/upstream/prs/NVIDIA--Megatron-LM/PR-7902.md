# Separate MFSDP v2 weight release from gradient reduction

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7902) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

## Why

Separate MFSDP v2 weight release from gradient reduction. Shared layers and delayed weight gradients can finish consuming full weights before parameter-gradient callbacks arrive. Releasing storage at module backward completion avoids retaining those weights while gradient reduction waits for all contributions.

**Depends on #8523.** The diffbase is `pull-request/8523` at `6215df2bd`; its positional layer-input contract and CUDA graph caller changes are inherited. This PR contains the MFSDP lifecycle changes and their regressions. #8113 is already merged.

## Changes

- Register `post_backward()` for module completion and `post_accumulate_grad()` for parameter-gradient completion. Release full weight storage independently of packing and reducing gradients; neither callback waits for the other.
- Keep full-shaped parameter bindings after storage release so delayed `backward_dw()` can assign `.grad`. At final synchronization, `reshard()` restores bindings, releases any remaining storage, and clears unused backward-prefetch events. The frozen-first-layer regression exercises this cleanup across two iterations.
- Update combined 1F1B to use the parameter-gradient completion hook while retaining its explicit resharding. Reject delayed wgrad without caller-managed synchronization.
- Check shared-layer storage lifetime, delayed-wgrad storage release, and TransformerBlock weight release from an input-gradient hook before final autograd cleanup.

Custom modules receiving differentiable inputs only through keywords still use conservative final-callback cleanup, because PyTorch full-backward hooks do not track keyword input gradients. #8523 enforces positional activations for TransformerLayer and MambaLayer.

## Validation

After stacking on #8523, the annotation, context, fully-shard, dense-adapter, and memory suites passed on two RTX A6000 GPUs with NGC 26.08: **73 passed, 10 skipped per rank**. Skips require four or more ranks or Blackwell hardware. Black, Ruff, and `git diff --check` passed.

The two MFSDP production commits replayed without conflicts and have unchanged patches. The existing TransformerBlock storage regression is retained; the older positional-input changes are supplied by #8523.

Can we track completion for keyword inputs too? TransformerBlock normally calls each layer with hidden_states as a keyword argument, so this defers every layer's weight release until the whole backward finishes. That keeps the full weights for all decoder layers on the stage in memory at once and can make a ZeRO-3 run run out of memory even if it fit before.

- guihong-nv · comment · 2026-10-26T19:20:42Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/7902#discussion_r4381485431)

File: `megatron/core/distributed/fsdp/src/megatron_fsdp/experimental/context.py` · line None

Can we keep the parameter binding and _unshard_event in sync here? With a frozen first layer and inputs that don't require gradients, the following trainable layer's backward prefetches the frozen layer, but the frozen layer never runs backward to clear its event. This loop then binds its sharded parameters while leaving _unshard_event set, so the next forward skips unsharding and fails with mixed Tensor/DTensor inputs. Running the existing frozen-first-layer test for a second iteration should cover this.
