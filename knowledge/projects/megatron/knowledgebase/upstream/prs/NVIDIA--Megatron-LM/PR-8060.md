# Warn when tensor-parallel helpers fall back to the global TP group

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8060) · state: open · merged: False

## Original PR description

Depends on #8049 (and #6293). Please review the diff from #8049's head: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/64aea4dcb...yx/pstate-b11-tp-helper-fallbacks).

**Why.** `get_tensor_model_parallel_group_if_none` backs 34 call sites: TP and TE linears, TP mappings, MLP, embeddings and the 1-D split helpers. When `tp_group` is omitted it silently uses the global TP group; its only signal is a rank-0 `DeprecationWarning`, which Python hides. `vocab_parallel_cross_entropy` has the same silent fallback.

**What.**
- Both fallbacks emit `ProcessGroupFallbackWarning` (deprecated in 0.21, removed in 0.23). The helper's warning names the function that called it, once per function.
- Training-path callers pass their group: `RowParallelLinear.forward` (unused there, so numerics do not change) and `tensor_parallel.checkpoint(..., tp_group=)` for `distribute_saved_activations`, from block recompute and MTP.
- `_initialize_affine_weight_cpu` requires `rank` and `world_size`; every caller passes them. Two global reads go away.

**Tests.** New unit tests cover one warning per owner and argument, no warning or global read with explicit groups, strict mode, and the callers passing their group. They fail on #8049's head and pass on 4 GPUs. Stock `pretrain_gpt.py`/`pretrain_hybrid.py` runs (dense, PP, CP, local spec, recompute, MTP, FP8, MoE, hybrid) pass with fallbacks turned into errors, and match #8049's head value for value in deterministic mode.

**Compatibility.** Warnings only. `CheckpointFunction.forward` takes `tp_group` as its third argument; `checkpoint()` callers are unaffected. MLA, DSA/CSA and MoE latent projections still warn through duplicated `TELinear`, which cannot take a group yet; that follows separately.

Part of #6307.
