# Warn when tensor-parallel helpers fall back to the global TP group

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8060) · state: closed · merged: False

## Original PR description

Depends on #8049 (and #6293). Please review the diff from #8049's head: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/d89eccea46...yx/pstate-b11-tp-helper-fallbacks).

**Why.** `get_tensor_model_parallel_group_if_none` backs 34 call sites: TP and TE linears, TP mappings, MLP, embeddings and the 1-D split helpers. When `tp_group` is omitted it silently uses the global TP group; its only signal is a rank-0 `DeprecationWarning`, which Python hides. `vocab_parallel_cross_entropy` has the same silent fallback.

**What.**
- Both fallbacks emit `ProcessGroupFallbackWarning` (deprecated in 0.21, removed in 0.23). The helper's warning names the function that called it, once per function.
- Training-path callers pass their group: `RowParallelLinear.forward` (unused there, so numerics do not change) and `tensor_parallel.checkpoint(..., tp_group=)` for `distribute_saved_activations`. `precision_aware_checkpoint` passes it the group that block recompute and MTP already give it. The gated delta net and KDA `tensor_parallel.checkpoint` calls from main pass `self.pg_collection.tp`, the group their `te_checkpoint` branch uses.
- `_initialize_affine_weight_cpu` requires `rank` and `world_size`; every caller passes them. Two global reads go away.

**Tests.** New unit tests cover one warning per owner and argument, no warning or global read with explicit groups, strict mode, and the callers passing their group. They fail on #8049's head. The fakes of `tensor_parallel.checkpoint` in the `precision_aware_checkpoint` and MTP recompute tests take `tp_group` and check that the caller's group arrives. On 4 GPUs against its base, the 13 new tests in `test_tp_group_fallbacks.py` pass. `test_random.py` passes 13 tests on both sides, and `test_tensor_observation.py` passes 44 on both sides. `test_model_parallel_cuda_manual_seed` fails on both sides because it needs 8 ranks; the integration run passes it on 8 GPUs (two nodes). In the integration run (all #6307 PRs merged onto main, against main), this PR's test files show no regressions: `test_multi_token_prediction.py` (225 passed), `test_hybrid_hash_routing.py` (33) and `transformer/test_utils.py` (24) match main, and `test_tp_group_fallbacks.py` passes its 13 tests. End-to-end training smokes with the other process-group changes from #6307 applied (22 configurations on 4 GPUs) give bit-identical losses to main and record no process-group fallback warning.

**Compatibility.** Warnings only. `CheckpointFunction.forward` takes `tp_group` as its third argument; `checkpoint()` callers are unaffected. Without #8722, this PR makes MLA, DSA/CSA and MoE latent projections warn, because duplicated `TELinear` cannot take a group. #8722 passes it the owner's TP group, so please land that PR first.
