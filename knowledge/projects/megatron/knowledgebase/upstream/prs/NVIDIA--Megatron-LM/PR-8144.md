# Quantize MLA key and value in TE's fused key/value RoPE kernel

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8144) · state: closed · merged: True

## Original PR description

With MXFP8 attention, fused_apply_mla_rope_for_kv writes the key and value in BF16 and attention reads them back to quantize them. Add use_fused_mla_kv_rope_quant to MLATransformerConfig. With it, in training, when Transformer Engine provides fused_mla_kv_rope_mxfp8 and an MXFP8 recipe with FP8 attention is active, MLA takes the MXFP8 key and value from that kernel, quantizes the RoPE'd query as attention would (or keeps the already quantized query of the fused Q up-projection), and passes the pre-quantized query, key and value to attention through the path the fused Q up-projection uses. The backward is the key/value split RoPE backward. Output and gradients are bitwise identical to the path without the option.

At DeepSeek-V3's shape on VR200 this replaces 60.8 + 75.6 us of key/value split and quantization per layer and microbatch with a 100.1 us kernel.

when `use_fused_mla_kv_rope_quant=True` runs with FP16 inputs, this condition selects a kernel that rejects them with `kv must be BF16`. please require BF16 inputs before selecting the fused path and add an FP16 fallback test.

an example flow:

- train with FP16 inputs, 256 tokens, 16 heads, and the supported head dimensions on Blackwell.
- enable MXFP8 attention and the new option with a Transformer Engine build containing the kernel.
- the first forward pass reaches the BF16-only kernel and fails instead of using the existing path.

suggested fix is to add these two lines to the condition:

```python
use_fused_kv_rope_quant = (
    ...
    and kv.dtype == torch.bfloat16
    and k_pos_emb.dtype == torch.bfloat16
)
```

File: `megatron/core/transformer/multi_latent_attention.py` · line 194

with `NVTE_FP8_DPA_BWD=0` and `use_fused_mla_q_uproj=False`, this helper still enables fusion, so attention reconstructs rounded `Q/K/V` for backward instead of retaining the original BF16 values. please keep the unfused path in this mode and add a fallback comparison, since the new path no longer preserves the inputs used to compute gradients.

an example flow:

- train BF16 MLA with MXFP8 attention and `use_fused_mla_q_uproj=False`.
- set `NVTE_FP8_DPA_BWD=0` to request high-precision attention backward.
- enable the new option and attention receives only already-rounded compact inputs.
- backward uses reconstructed values in place of the originals, which can change gradients.

suggested fix is to insert this 2-line guard:

```python
import os

def _is_mxfp8_attention_active() -> bool:
    if not FP8GlobalStateManager.is_fp8_enabled():
        return False
    # ... >>> insert these lines
    if int(os.getenv("NVTE_FP8_DPA_BWD", "1")) == 0:
        return False
    # ... <<<
    recipe = FP8GlobalStateManager.get_fp8_recipe()
    return recipe.mxfp8() and recipe.fp8_dpa
```
