# fix(inference): allow hybrid pipeline stages without attention layers

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8366) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Dynamic inference with pipeline parallelism now works for hybrid models where a pipeline stage holds no attention layer. Before, initialization hung: that stage raised, and the other stages waited for it in a collective.

## Problem

`DynamicInferenceContext.__init__` counts the attention layers of the local stage. When there are none it raises `NotImplementedError("Using DynamicInferenceContext with no attention is not supported.")` (`megatron/core/inference/contexts/dynamic_context.py:548-551` at ebab8e2e2, after `_mtp_initialize_kv_cache`). For a hybrid model, `MambaInferenceStateConfig.from_model` takes `layer_type_list` from the pipeline-local decoder. So with PP > 1 the check runs per stage, and any stage holding only Mamba / GDN and MLP / MoE layers raises.

The other stages do not raise. They go on to the PP MIN all-reduce of the block count a few lines later, and wait there for the stage that already raised. Reproduced on `main` (ebab8e2e2), PP=2, layer types `M*` | `M-`:
- stage 1 (attention-free): `NotImplementedError: Using DynamicInferenceContext with no attention is not supported.`
- stage 0: hangs in `torch.distributed.all_reduce(block_count_tensor, op=MIN, group=pipeline_parallel_group)`. A faulthandler dump after 200 s shows `dynamic_context.py:718`.

Which models hit it: hybrid models with long recurrent runs, when a PP stage boundary leaves a stage with no attention layer. Examples are Nemotron-H and Nemotron 3 layouts (Mamba + MoE/MLP with sparse attention) at higher PP, and pure-Mamba models, where no stage has attention.

## The change

When the local stage of a hybrid model holds no attention layer:

- Its KV blocks are sized as if it held one attention layer (`kv_block_layer_count = max(num_attention_layers, 1)` in `block_size_bytes`). The block count and the existing PP MIN all-reduce then run as on every other stage. The stage still needs the block tables, because every stage admits requests and assigns blocks alike.
- `num_attention_layers` stays 0, so `_allocate_memory_buffer` allocates a KV buffer with zero layers. The stand-in blocks use no memory.

The error is kept for non-hybrid contexts with zero layers. Stages that hold attention are unchanged. MTP's reserved KV plane counts as an attention layer, as before.

## Tests

- `tests/unit_tests/inference/contexts/test_dynamic_context.py` (2 GPUs, PP=2, layer types `M*` | `M-`):
  - `test_pipeline_stage_without_attention_layers_allocates_no_kv_memory`: the attention-free stage initializes, `num_attention_layers == 0`, and `memory_buffer.numel() == 0`. The other stage's buffer has one layer. Pool size and paused limit are the same on both stages.
  - `test_pipeline_stage_without_attention_layers_mirrors_block_tables`: three requests (1, 2 and 3 blocks) get the same block ids, block counts and free-pool count on both stages.
  - On `main`, these tests hang as described above.
- `tests/unit_tests/inference/engines/test_dynamic_engine_parallel_and_chunked_prefill.py::test_hybrid_pipeline_stage_without_attention_matches_pp1`, parametrized over `M*-|M-` (last stage attention-free), `M-|M*-` (first stage attention-free), `M-|M-` (no attention anywhere) and the control `M*-|M*-`:
  - A PP=1 model generates 8 greedy tokens for 4 requests, with log probs.
  - A PP=2 model is loaded with the same weights (layer indices shifted by the stage offset) and generates again.
  - Every request must complete. The prefill step (first token and its log prob) must match PP=1 bitwise. Decode log probs must match within 2e-2, up to the first token where the runs diverge. If the runs never diverge, they must have the same length; a request also ends early when it samples the termination id.
  - The tolerance is there because decode at PP=2 differs from PP=1 by a few bf16 ulps even in the control `M*-|M*-`, which runs on `main` today. That can flip a greedy near-tie later in the run, which happened once in `M-|M-`. This PR does not change that path. The PP=1 run of `M-|M-` (`M-M-`) also covers a hybrid model with no attention layer at PP=1.
- `DynamicEngineTestConfig.hybrid_layer_pattern` (new, optional) sets the hybrid pattern. The default pattern is unchanged.

Run on GB200, 2 GPUs (1 GPU for the PP=1-only file):
- `test_dynamic_context.py`: 141 passed, 2 skipped.
- The new engine test: 4 passed on each of 3 runs in a row.
- `test_dynamic_engine.py -k "hybrid or mamba"`: 21 passed. This checks the test-config refactor at PP=1.
- `test_parallel_inference` and `test_speculative_decoding_pipeline_parallel`: the hybrid PP=2 cases pass. Two GPT cases, `local-gpt-2-1-1-True-*`, fail here with `sequence parallel not supported by torch LayerNorm`. This PR does not touch that GPT-only path; the failure comes from the environment.
- `test_gdn_pipeline_parallel` fails with `State dimensions must match` in the GDN prefill. Unmodified `main` fails the same way in this environment.

## Limitations

- On an attention-free stage, the block count comes from one stand-in attention layer plus that stage's Mamba state memory. This is conservative: it is never larger than what the stage could hold, and the PP MIN keeps every stage's count equal. If the attention-free stage holds the most Mamba layers, it can be the one that sets the MIN.
- `inference_state_handoff` (disaggregated prefill/decode) reads `num_attention_layers` for KV transfer. An attention-free stage has nothing to transfer, but that path is not exercised here.
