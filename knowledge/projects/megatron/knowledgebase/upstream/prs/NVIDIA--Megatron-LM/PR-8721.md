## What does this PR do?

Builds on merged #8478; rebased onto `main` at `88312648a`.

Use one weakly held list of `ExecutionEvent(module, phase)` values and one cursor. Registration mode fills the list during construction; recorded mode fills it from execution. Both use the same validation, lookahead, and argument-free `advance()`, which wraps automatically.

Registration mode requires a complete forward/backward sequence matching its preset; reordered or repeated execution needs recorded mode. Lookahead follows successive execution events and gathers parameters for each event's phase. Phase changes do not stop prefetch; the existing prefetch budgets still apply.

This PR changes three production files and two test files. Schedule completion, PP/VPP and EP-overlap integration, and evaluation handling are in the separate follow-up #8778.
