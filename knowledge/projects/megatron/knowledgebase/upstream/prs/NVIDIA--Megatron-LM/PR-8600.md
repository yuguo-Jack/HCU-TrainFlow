# fix(inference): count every prompt in completion usage

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8600) · state: open · merged: False

## Original PR description

## What does this PR do?

`/v1/completions` accepts several prompts in one request, but its usage record reported only the largest prompt's token count, and likewise for cached tokens. The `prompt_tokens` and `total_tokens` values therefore undercounted multi-prompt requests. This happened in both the streaming and non-streaming responses.

This PR sums prompt and cached tokens across the prompts of a completion request. Chat requests keep using the maximum, because their choices all share one prompt.

## Example failure scenario(s)

**Scenario (two-prompt completion)**

- Client A sends a completion with two prompts of 3 and 2 tokens.
- The engine generates 4 tokens in total.
- Before this fix, usage reported `prompt_tokens: 3` and `total_tokens: 7`.
- With this fix, usage reports `prompt_tokens: 5` and `total_tokens: 9`.

## How was this bug discovered?

The completion response-format test sends prompts of different lengths and expects summed usage. The streaming fan-out test sends three requests and expects summed prompt and cached counts for completions, and the maximum for chat. On `main` both tests report only the largest prompt.

## Dependency and scope

This PR is independent and based on `main`. It changes the usage totals in `completions.py` (non-streaming) and in `openai_streaming.py` (streaming, completions only). Two existing tests change only their expected completion prompt-token counts, because those expectations encoded the undercount: `test_completions_response_format` and `test_streaming_fans_out_and_reports_usage_on_request`. A new test, `test_streaming_usage_counts_cached_tokens_per_prompt`, checks the cached-token totals.
