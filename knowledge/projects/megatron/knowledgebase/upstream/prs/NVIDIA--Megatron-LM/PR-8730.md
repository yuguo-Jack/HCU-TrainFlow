# Take the global memory buffer from megatron.core.utils

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8730) · state: closed · merged: False

## Original PR description

Depends on #8026. Please review the diff from the merge of #8026 into main: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/dffb310a5d...yx/pstate-g15-memory-buffer-imports).

**Why.** With #8026 the global memory buffer lives in `megatron/core/utils.py` and is created on first use; `parallel_state` only re-exports it. In-tree callers still reach it through `parallel_state`: the local `DotProductAttention` (looked up on the module in every forward), the tensor-parallel linears and mappings, the dynamic engine's CUDA-graph pre-sizing, training teardown and the MIMO example. They depend on the global-grid module for scratch memory that uses no process group. The MIMO example also wraps the get in a `try/except AssertionError` that can no longer trigger.

**What.**
- Every in-tree caller imports `get_global_memory_buffer` and `destroy_global_memory_buffer` from `megatron.core.utils`.
- The MIMO example no longer creates the buffer at startup. Its first user does.
- `parallel_state` keeps `get_global_memory_buffer` and `destroy_global_memory_buffer` as re-exports of the same functions, and `_set_global_memory_buffer`, which still only creates the buffer if it is missing.

**Tests.**
- `tests/unit_tests/test_global_memory_buffer.py`: the sequence-parallel linear, buffer all-gather and local-attention tests run with the `parallel_state` aliases patched to raise, and check that the shared buffer was used. Only local attention can tell the import paths apart at runtime. The linears and mappings import the function by name, so the scan below covers them.
- New stdlib-only `tests/unit_tests/test_global_memory_buffer_imports.py` scans `megatron/`, `examples/`, `tools/` and the top-level scripts for buffer functions taken from `parallel_state`. It finds 8 sites on #8026's head and none here.

Before the 2026-11-01 sync, on 4 GPUs against #8026's head: no regressions, and the import scan fails there and passes here. On 4 CPU gloo ranks, also before the sync, the import scan passes, and the same 4 buffer tests fail for lack of CUDA here and on #8026's head. In the integration run (main 77391e71cc with all #6307 PRs merged, against main, on 4 GPUs), `test_global_memory_buffer.py` passes 7 tests and `test_global_memory_buffer_imports.py` passes 3. Main has neither file, so all 10 are new tests there. In the integration run, this PR's test files show no regressions against main.

**Compatibility.** No behavior change. `megatron.core.transformer.dot_product_attention` no longer imports `parallel_state`, so the module attribute `dot_product_attention.parallel_state` is gone. Code that patched `parallel_state.get_global_memory_buffer` to intercept attention's buffer no longer intercepts it. The linears and mappings already behaved this way. Megatron-Bridge's `mpu.get_global_memory_buffer` calls keep working through the re-export. Not changed here: the stale memory-buffer remark in the comment above `DEPRECATED_PREFIXES` in `tools/check_process_group_usage.py`, and Bridge's test that patches `mpu._GLOBAL_MEMORY_BUFFER`. Needs `determinism-exempt`: `layers.py`, `mappings.py` and `dot_product_attention.py` are registered kernel files, and their edits only change where the buffer function comes from.

Synced with main 77391e71cc on 2026-11-01 by a merge commit (through the updated #8026), so existing commits and review links stay valid. The merge had no conflicts. Through #8026, the process-group allowlist records the reads main added since this PR was written.
