# MInf: bound the FlashInfer MoE expert kernels by token count

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8367) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?
This makes the FlashInfer MoE kernels only do work proportional to the live tokens on a step, instead of proportional to the overall buffer. This in the same spirit of changes started by #4258.

As a result, my testing shows that a decode step on Nano 3.5 drops from 25ms to 9ms with a 65,536-row buffer (EP4), and from 76ms to 12ms with a 262,144-row buffer (EP16), with no change at all in outputs.

## Problem

The FlashInfer MoE kernels currently assume that the token count can be provided as a host-side parameter. This is false. The host only provides this parameter at CUDA graph record, and it has no way of knowing what the token count will ever be, because the token count is only known after the all-to-all expert collectives run on every layer.

A secondary problem is that the FlashInfer MoE kernels currently downcast their accumulated results from FP32 to BF16 and only return BF16, forcing the user (Megatron Inference) to manually upcast the BF16 out back to FP32. This is a loss of precision and slowdown with no benefit.

## Solution

Monkey-patch the FlashInfer kernels until they are fixed at a future date.

## Perf numbers

One GB300 node, Nemotron 3.5 Nano, TP 2 EP 2 DP 2, 256 requests of 128-token prompts, 1,024 greedy tokens, three
trials per run averaged out:

| decode step timing | 65,536 rows | 131,072 rows | 262,144 rows |
| --- | --- | --- | --- |
| bf16, `main` with FlashInfer | 23.6ms | 38.0ms | 67.9ms |
| bf16, this PR with current FlashInfer | 9.8ms | 10.8ms | 13.3ms |
| bf16, this PR with a future, fixed, FlashInfer | 9.3ms | 10.3ms | 11.9ms |

| decode step timing | 65,536 rows | 131,072 rows | 262,144 rows |
| --- | --- | --- | --- |
| MXFP8, `main` with FlashInfer | 25.3ms | 42.5ms | 76.2ms |
| MXFP8, this PR with current FlashInfer | 9.2ms | 10.6ms | 12.1ms |
| MXFP8, this PR with a future, fixed, FlashInfer | 8.9ms | 9.8ms | 11.8ms |

Please see the Slack thread for a wide list of perf numbers. More are available upon request.
