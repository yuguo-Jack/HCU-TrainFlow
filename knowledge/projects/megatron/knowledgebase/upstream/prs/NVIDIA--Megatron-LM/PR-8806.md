# Skip the KPool FP8 Hadamard reference test without fast_hadamard_transform

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8806) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

`test_kpool_causal_tail.py` has an autouse fixture that replaces `hadamard_transform` with a plain scale when `fast_hadamard_transform` is not installed, so the other KPool tests can still run. `test_kpool_fp8_input_matches_hadamard_matrix_reference` compares `_kpool_fp8_input` with a real Hadamard matrix. Under the mock it therefore fails with large mismatches (greatest relative difference 87 to 481) instead of reporting that the package is missing. This PR skips that test when `fast_hadamard_transform` is unavailable.

## Testing

`test_kpool_causal_tail.py` without `fast_hadamard_transform`, on B300:
- main: 3 failed, 111 passed. The `input_scale=0.0` case passes trivially, since all-zero input stays zero under the mock.
- this PR: 4 skipped, 110 passed.

The same three failures showed up on an L40S environment without the package. With the package installed nothing changes, since the decorator only reads `HAVE_HADAMARD`; I did not run that configuration.

black 26.3.0 reports no changes.
