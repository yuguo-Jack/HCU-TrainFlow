# Normalize moe_router_padding_for_fp8 before config checks read it

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7694) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Make `TransformerConfig` validate `moe_router_padding_for_fp8` and its canonical replacement `moe_router_padding_for_quantization` identically, by folding the alias in before any check reads it.

`moe_router_padding_for_fp8` is documented as a compatibility alias that "will also enable `moe_router_padding_for_quantization`", but `__post_init__` only folds it in near the end, and one check still reads the alias itself. So the same setting is accepted or rejected depending on which name is used:

| Check | `moe_router_padding_for_quantization=True` | `moe_router_padding_for_fp8=True` |
|---|---|---|
| `transformer_impl="inference_optimized"` rejects padded routing | `ValueError` ✅ | constructs, and `moe_router_padding_for_quantization` is then set to `True` ❌ |
| `moe_preprocess` CUDA graph rejects padded routing with `alltoall` | constructs ❌ | `AssertionError` ✅ |

The first check runs about 1,180 lines before the alias is folded in. The second is the only remaining reader of `moe_router_padding_for_fp8` in the tree (every other consumer reads the canonical flag), so the documented flag is the one that skips it.

Reproduction on current `main` (CPU, `TransformerConfig` only):

```python
base = dict(num_layers=2, hidden_size=128, num_attention_heads=8, num_moe_experts=8,
            moe_router_dtype="fp32", fp4="e2m1", moe_token_dispatcher_type="alltoall")

# constructs, although the equivalent moe_router_padding_for_quantization=True raises ValueError
TransformerConfig(**base, moe_router_padding_for_fp8=True, transformer_impl="inference_optimized",
                  gated_linear_unit=False, normalization="RMSNorm", add_bias_linear=False,
                  moe_router_score_function="sigmoid")

# constructs, although the equivalent moe_router_padding_for_fp8=True raises AssertionError
TransformerConfig(**base, moe_router_padding_for_quantization=True, cuda_graph_impl="local",
                  cuda_graph_modules=["moe_router", "moe_preprocess"])
```

**Change:** move the existing fold-in block (unchanged, including its deprecation warning) up next to the other up-front alias resolution (`experimental_attention_variant`), and have the `moe_preprocess` CUDA graph check read `moe_router_padding_for_quantization`. No other behaviour changes.
