# [Inference][FP8] Reduce FP8-padded row-parallel outputs once under sequence parallelism

# What does this PR do?

Fixes the FP8 inference padding wrapper so that a row-parallel TE linear under sequence parallelism reduces its output once instead of twice. The wrapper now pads each rank's chunk of the sequence and leaves all communication to the module.

**Bug.** `prepare_model_for_fp8_inference` wraps every TE linear of a model served with `fp8` set (any `transformer_impl` except `inference_optimized`) with `_wrap_te_linear_for_padding`. With TP > 1 and `sequence_parallel=True`, each wrapped `TERowParallelLinear` (attention `linear_proj`, MLP `linear_fc2`) returns `TP x` the correct output on every FP8 forward, for padded and unpadded sequences alike.

**Root cause.** With sequence parallelism, the wrapper:
1. cleared `module.sequence_parallel`;
2. padded the whole sequence and ran the TE forward;
3. reduce-scattered the row-parallel output itself.

TE's `Linear` reads `sequence_parallel` on every call. Its row-parallel branch is "reduce-scatter if `sequence_parallel`, else all-reduce if `tp_size > 1`" (`transformer_engine/pytorch/module/linear.py`). With the flag cleared, TE all-reduced the partial products, and the wrapper's reduce-scatter then summed the already reduced tensor across the ranks again. Column-parallel modules were not affected, because there the wrapper's own all-gather replaced TE's.

**Fix** (`megatron/core/fp8_utils.py`). With sequence parallelism, a column-parallel module all-gathers its input and a row-parallel module reduce-scatters its output along the sequence, in one chunk per TP rank. The wrapper now pads and unpads each chunk separately (`Fp8Padding`/`Fp8Unpadding` with one split per chunk):

| Module (TE `parallel_mode`) | Pads | Module communication | Unpads |
|---|---|---|---|
| `"column"` | the local chunk | all-gather of `TP` padded chunks | `TP` chunks |
| `"row"` | `TP` chunks of the full sequence | reduce-scatter, one padded chunk per rank | the local chunk |

- Padding per chunk keeps the chunk boundaries aligned with the ranks, so the module's own single all-gather or reduce-scatter gives each rank exactly its rows.
- Each local chunk also meets TE's FP8 shape check, which TE applies to the local input before its all-gather.
- The chunk layout follows the module's TE `parallel_mode`, since that is what selects TE's collective. This covers `TEColumnParallelLinear`, `TELayerNormColumnParallelLinear`, `TERowParallelLinear`, and any `TELinear` built with a row or column mode.
- A row-parallel input whose sequence length is not divisible by TP now fails with a clear assertion.
- The wrapper no longer toggles `module.sequence_parallel`, so an exception in the forward can no longer leave it cleared. It also no longer issues its own collectives.
- Without sequence parallelism, the behavior is unchanged.

Hot path: the per-call cost is unchanged (Python list arithmetic and an integer check), with no host syncs and no new allocations beyond the existing padding buffer.

Performance trade-offs, not benchmarked:
- Padding per chunk can add up to `TP x (alignment - 1)` zero rows to the GEMM, instead of `alignment - 1`. For example, with TP=8 and MXFP8, 8 tokens per rank are padded to 32 per rank, a 256-row GEMM instead of 64.
- Under sequence parallelism, column-parallel modules now use TE's own sequence-parallel all-gather (of the quantized input) instead of the wrapper's bf16 all-gather. For current-scaling recipes, TE also all-reduces the input amax across the TP group, as it does for any sequence-parallel column-parallel linear.

**Tests** (`tests/unit_tests/test_fp8_utils.py`):
- `TestFP8PaddingSequenceParallel` (2 GPUs, FP8 tensorwise) covers `TERowParallelLinear`, `TEColumnParallelLinear` and `TELayerNormColumnParallelLinear`:
  - `test_wrapped_output_matches_unwrapped`: for 32 tokens (already aligned) and 40 tokens, the wrapped FP8 output equals the unwrapped FP8 output (relative error < 0.05). The unwrapped output is within FP8 tolerance of an fp64 reference, and `sequence_parallel` is untouched. The test runs with the recipe's padding alignment and with the 32-row MXFP8 alignment. MXFP8 itself needs Blackwell, so the 32-row alignment is forced on the tensorwise recipe. When padding is expected, the test also checks that the wrapper actually padded.
  - `test_wrapper_is_noop_outside_fp8`: outside an FP8 context, the wrapped output equals the unwrapped one and the reference.
- CPU tests with a single emulated rank (the last of 4) and pure-torch padding:
  - `test_fp8_padding_pads_each_sequence_parallel_chunk[row|column|None]`: the wrapper pads per chunk as the TE `parallel_mode` splits the sequence, and returns exactly that rank's rows.
  - `test_fp8_padding_rejects_sequence_not_divisible_by_tp`: checks the divisibility assertion.

**Results.** On H100 in the CI image (TE 2.20.2), at the first commit of this PR:
- Of the original test's 6 GPU cases, the 2 row-parallel cases fail on main (relative error 1.0: the output is scaled by TP). All 6 pass with this PR.
- The neighbor tests `TestFP8Padding` and `test_dynamic_engine.py::TestDynamicInferenceEngine::test_fp8_inference` pass.

On H100 in the CI image (rerun at this PR's head), the regression tests pass (4/4 on 1 GPU, 15/15 on 2 GPUs) and 7 fail on `main`. The neighbor tests pass, including the TP=4 sequence-parallel FP8 engine test. On CPU, the layout tests pass with this PR and fail with both main and the first commit of this PR, which chose the chunk layout from the module class.
