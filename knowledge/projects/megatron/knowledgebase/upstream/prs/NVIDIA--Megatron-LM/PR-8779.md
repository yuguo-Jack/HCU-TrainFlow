# What does this PR do?
Fix a `TypeError` in `HuggingFaceTokenizer.__init__` when `additional_special_tokens=None` is passed.

`additional_special_tokens` is typed `Optional[List]`, and the constructor already guards against `None` when building the special tokens dict and when storing the requested list. However, the loop that collects tokens missing from the vocabulary iterated over it directly, so passing `None` raised `TypeError: 'NoneType' object is not iterable`.

This PR guards that loop the same way as the surrounding code (`additional_special_tokens or []`). Behavior for the default (`[]`) and for explicit lists is unchanged.

Reproducer on current `main`:

```python
from megatron.core.tokenizers import MegatronTokenizer

MegatronTokenizer.from_pretrained(
    "<any local HF tokenizer dir>",
    metadata_path={"library": "huggingface"},
    additional_special_tokens=None,
)
# File ".../huggingface_tokenizer.py", line 195, in __init__
#     for token in additional_special_tokens:
# TypeError: 'NoneType' object is not iterable
```

The training path (`build_tokenizer`) already converts an unset `--special-tokens` into `[]`, so the training CLI is unaffected. The crash affects users calling `MegatronTokenizer.from_pretrained` / `HuggingFaceTokenizer` directly with `None`.
