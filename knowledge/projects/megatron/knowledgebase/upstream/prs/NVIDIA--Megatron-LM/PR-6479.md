# [dev] Share CUDA graph slots across dynamic CP variants

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/6479) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Lets dynamic context parallelism (DCP) use layer-wise Transformer Engine CUDA graphs. Each CP size gets its own graph bank, and all banks share one TE memory pool. The PR also adds packed Gated DeltaNet attention capture (Qwen3.5) and moves DSv4/MLA backward metadata into saved tensors, which is the only state that graph slot memory protects.

**Dependencies**
- NVIDIA/TransformerEngine#3353 adds `make_graphed_callables(_graph_memory_slots=...)`. Without it, `TECudaGraphHelper` raises at construction when DCP is enabled.
- Packed GDN attention capture also needs `fla.ops.cp.graph` from an FLA fork (xiaoyao0115/flash-linear-attention@01d1c029). Released FLA 0.5.1 does not have it. Without it, GDN layers raise at construction when attention capture is configured, and the dependent tests skip. Upstream FLA already builds the graph metadata on device for KDA (fla-org/flash-linear-attention#1212); a planned upstream FLA PR will add the same path for GDN.

## Design

DCP chooses a CP size for each microbatch. CP communicators are capture-time constants, so every CP size needs its own graph executables, and capturing them in separate pools multiplies graph memory by the number of CP sizes.

- **Banks.** `TECudaGraphHelper` captures every power-of-two CP size from `--min-dynamic-context-parallel-size` to DP×CP, using the real process group of each size. At replay, a layer uses `PackedSeqParams.local_cp_size` to select its bank (graphs, process group and static inputs). This also covers the mHC attention split and the hybrid wrapper.
- **Shared slots.**
  - The physical slot ring is sized from the liveness union of every PP/VPP schedule that the dynamic-CP scheduler can produce.
  - Saved-tensor and returned-gradient arenas are colored so that frames live at the same time never share storage. The plan reaches TE as seven-field `_graph_memory_slots` tuples.
  - Variants of one slot share arena addresses, so storage is sized by the largest variant rather than the sum.
- **Capture state.**
  - THD capture seeds a bounded RoPE table and `cu_seqlens` per bank. Under DCP, eager RoPE uses the same bound.
  - During training, the packed microbatch count is checked against the captured range. The DCP scheduler now honors `thd_max_packed_sequences` (leaving room for the dummy tail sequence), so a pack never exceeds the captured `cu_seqlens` capacity.
  - Capture can be retried, and capture-only state is released on failure and on delete.
- **DSv4 and MLA RoPE.** Only tensors saved for backward survive another bank's replay. CSA sparse attention, the cuDNN sparse attention functions, the fused DSA indexer loss and fused MLA RoPE therefore save their metadata with `save_for_backward` instead of keeping it in `ctx` attributes.
- **GDN.** Packed GDN inputs are validated on the host before replay. Capture uses fixed-shape layout conversion and fixed-capacity, device-side FLA metadata (chunk indices, chunk offsets and the CP context), which the graph recomputes from the live `cu_seqlens` on every replay. Both chunkwise (contiguous) and headwise (zigzag) CP are supported. With deterministic TE algorithms, the graph-safe GDN path matches the eager path bitwise, forward and backward.
  - **Why not stock FLA metadata.** Stock varlen GDN builds this metadata from `cu_seqlens` with a host sync and caches it by tensor identity. A capture therefore either fails at the sync or, when warm-up has already cached the metadata for the static `cu_seqlens` buffer, freezes the capture-time pack layout into the graph; replays with other sequence boundaries then run without error but are wrong. Fixed-length packs, where every pack matches the capture sample, do not exercise this. In a single-H100 check (one 1024-token varlen GDN call, forward and backward captured), replaying the captured pack was bit-exact, but two packs with other boundaries gave output errors of 0.27 (|o| max ≈ 0.1) and `dbeta` errors of 3e38 and inf; with the cache disabled, capture failed. The `fla.ops.cp.graph` path matched eager bitwise on every pack, forward and backward.

Runs without DCP keep dev behavior: capture bounds are unchanged, and fixed-CP THD capture uses the full token capacity for RoPE, so eager RoPE and fused THD RoPE selection are unaffected.

The branch is three commits: core dynamic-CP graph sharing; DSv4/MLA saved-tensor fixes; packed GDN support.

## Results

### Qwen3.5 proxy on 16×GB200

**Setup**
- **Model:** a proxy with 4 layers (3 headwise GDN and 1 softmax attention) plus MTP1. It has 64 experts with EP4 and HybridEP (expert-rank capacity 1.25).
- **Parallelism and capture:** dynamic CP 1–16 with the zigzag layout, capture scope `attn moe_router moe_preprocess`.
- **Software:** this PR at 5075ae0f7, TE main 53e241c5 with NVIDIA/TransformerEngine#3353, the FLA fork, and the torch 2.11 container. 5075ae0f7 matches the head except for how `_get_sample_arguments` handles layers outside packed THD.
- **Method:** each working point runs all arms in one allocation, with identical inputs and schedules (checked on every rank and step). Times are the slowest rank per step, averaged over steps 6–20.

| Working point | eager DCP | eager, graph-safe math¹ | DCP + partial CG | CG vs eager |
| --- | ---: | ---: | ---: | ---: |
| approved: 16K tokens/rank, GBS512 | 75.25 s | 73.49 s | 73.01 s | 1.031×, 15/15 steps faster |
| Haochen's point: 64K-token sequences, 4K tokens/rank, GBS4 | 1.119 s | 1.073 s | 0.907 s | 1.234×, 15/15 |
| scaled: approved ÷ 4, GBS64 | 3.199 s | 3.159 s | 2.673 s | 1.197×, 15/15 |

¹ Eager execution with the same fixed-capacity GDN path that the graphs capture. It separates kernel and layout effects from graph replay.

- **Speedup:** at the approved working point the step is GPU-bound. In earlier nsys profiles the GPU idles about 6.5% of an eager DCP step, against 24% at Haochen's point. Graphs therefore save little there: 0.7% over the graph-safe-math control. At the two smaller points the same code is 20–23% faster than eager DCP.
- **Numerics:**
  - At the approved and scaled points (both with variable sequence lengths), partial CG matches the graph-safe-math control exactly (loss and grad norm, all 20 steps). At the scaled point every arm also matches eager DCP exactly.
  - At the approved point, eager DCP itself drifts from both graph-safe arms after step 10, by up to 8.5e-5 relative.
  - At Haochen's point the CG arm ran first, with empty JIT caches, and FLA autotuning in its first step shifted the step-1 gradients slightly. Its loss differs from eager by 5e-6 at step 2 and by 1.5e-3 at step 20, by which point the loss has fallen to 1e-3. The arms that ran later, with warm caches, match eager exactly.
- **Memory** (peak physical per GPU, eager → CG): approved 88.6 → 95.3 GiB, scaled 62.2 → 65.0 GiB. At the scaled point, TE's native per-variant pool (a single-PP-stage diagnostic arm) is 0.5% faster than the slot pool (median) but uses 1.8 GiB more.
- **Comparison with our earlier runs:** these runs use TE main instead of TE 2.19. They also exclude two changes that our earlier benchmark tree carried: the MTP roll rewrite (NVIDIA/Megatron-LM#5258) and the HybridEP padding mask (NVIDIA/Megatron-LM#8285). Absolute times therefore differ from those runs; for example, approved-point eager DCP took 71.0 s/step there.

Memory, measured on an earlier revision of this PR (before the dev rebase), as whole-device peak:

| Model, GPUs, CP sizes | fixed CP + CG | DCP + CG | eager DCP |
| --- | ---: | ---: | ---: |
| Qwen3-30B proxy, 8×H100, CP1/2 | 75037 MiB | 76105 MiB | 74251 MiB |
| Qwen3-235B, 128×H100, CP1/2/4 | 67497 MiB | 69667 MiB | 66023 MiB |
| DeepSeek-V4-Flash, 128×GB200, CP1/2/4/8 | 107465 MiB | 110781 MiB | 105951 MiB |

DCP + CG costs 1.4–3.2% more than fixed CP + CG, and 2.5–5.5% more than eager DCP. Graph and eager DCP losses match exactly for the Qwen3 runs. For DSv4 the largest relative difference over 50 steps is 0.15%.

## Limitations

- Dynamic CP sizes are powers of two, and DP×CP must be a power of two.
- Dynamic-CP graphs do not support delayed wgrad, EP overlap, `moe_paged_stash` or mamba scopes.
- Some packed GDN paths stay out of attention capture:
  - selective recompute of `gdn` or `gdn_norm_out`;
  - the hybrid mHC wrapper;
  - `gdn_conv_pad_alignment`.
- CI (FLA 0.5.1, TE without #3353) skips the TE-slot and FLA-fork tests until those dependencies land.
