# [Hybrid] Fix per-layer residual replay with FSDP

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8422) · state: open · merged: False

## Original PR description

Fix residual replay running before FSDP gathers weights (#7777). With `residual_stream_recompute_num_layers=1`, finalize inside the owning layer; Shortcut-MoE pairs stay together.

Validation: 51 tests passed per rank on two GPUs, including a real MFSDP regression that reproduces the failure on the base revision. Eight four-GPU cases were not run. Formatting checks pass; Mypy diagnostics match the base.

On 72 GPUs, `num_layers=1`:

- **Versus replay disabled:** saves **10.31 GiB (7.82%)** of peak decoder memory per GPU for **2.18% more policy time**, measured over 100-update runs.
- **Versus `num_layers=4`:** uses **2.83 GiB more memory** for **8.3% less policy time**, from an earlier 64-update comparison that also coarsened FSDP boundaries.

[Evaluation details](http://nv/m7J).

- kwangjunahn · comment · 2026-11-02T19:45:24Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/8422#issuecomment-6586803557)

Thanks, @wujingyue, for the fix! Moving finalization inside the owning layer makes sense for `residual_stream_recompute_num_layers=1`, so the owner gathers its parameters before replay starts.

For memory-constrained workloads, we also want larger replay regions to retain fewer wide activation boundaries. As discussed in [my reply on #7777](https://github.com/NVIDIA/Megatron-LM/issues/7777#issuecomment-6368323687), we plan to address replay across multiple FSDP owners in follow-up PRs in the WR/mHC unification series tracked in [#7888](https://github.com/NVIDIA/Megatron-LM/issues/7888). The planned approach uses differentiable snapshots of the small WR controller and normalization parameters needed for replay, with correctness and memory/runtime validation under MFSDP.

Thanks also for pointing out the limitations of existing tests. I see the gap. The test over-specifies the internal call order without exercising backward or verifying the intended memory savings. We’ll address this in a separate test-only PR, replacing those brittle assertions with eager/replay backward parity and checks that intermediate activations are actually discarded and restored. Your change to execute the real Mamba forward already improves that coverage.
