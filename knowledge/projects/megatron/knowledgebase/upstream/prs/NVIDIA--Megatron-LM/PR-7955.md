# fix(inference): honor request-local FlashInfer sampling seeds

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7955) · state: closed · merged: False

## Original PR description

Explicit request seeds currently require Torch sampling; FlashInfer uses a shared generator whose stream changes with scheduling. This adds request-local FlashInfer draws using explicit `seed`/`offset`, preserves saved async token positions, and allows the backend through engine admission. Seeded requests do not advance the unseeded generator, and speculative seeded decoding remains rejected.

Stacked on #7828 (`pull-request/7828`). Includes parent review fixes `5b01e917d`; the synthetic base branch may lag that head until CI synchronizes it. Retarget this PR to `main` before merging the parent. Keep this PR draft pending the target container's FlashInfer bump and the performance decision below; dependency pins and NeMo-RL's backend selection are not changed here.

FlashInfer's per-row seed fix [#5745](https://github.com/flashinfer-ai/flashinfer/pull/5745) still incorporates the output row into the RNG subsequence. Its [sampling documentation](https://docs.flashinfer.ai/generated/flashinfer.sampling.sampling_from_logits.html) explicitly describes this batch-position dependence. Seeded requests therefore use one-row launches and select their own filter kernel. Hashing the request seed and absolute token position selects a separate stream with offset zero; adjacent offsets would risk overlapping draws in rejection sampling. Unseeded requests remain batched.

This is a correctness fix, not yet a general speedup over batched Torch. Local GB200 microbenchmark, vocabulary 131072, 5 warmups and 20 synchronized draws, median milliseconds including host dispatch:

| Batch | Filter | Torch | FlashInfer |
| --- | --- | ---: | ---: |
| 1 | none | 0.351 | 0.206 |
| 1 | top-p 0.9 | 0.535 | 0.321 |
| 1 | top-k 50 | 0.473 | 0.375 |
| 16 | none | 0.427 | 1.001 |
| 16 | top-p 0.9 | 0.884 | 2.469 |
| 16 | top-k 50 | 0.564 | 2.374 |

A fully batched seeded path needs upstream request-local subsequence semantics, beyond honoring per-row seed/offset arrays. Do not re-enable FlashInfer globally in RL on the strength of these microbenchmarks.

Validation: **284 tests passed** on local GPUs with FlashInfer 0.6.8.post1 (seed sampling plus kernel-manifest checks). GPU replay tests cover all four filter dispatches, batch reorder/singleton equivalence, mixed-filter neighbors, shared-generator isolation, saved async positions, output/gather buffers, and inactive metadata in speculative batches. The new tests are registered in the kernel determinism manifest. Formatting, isort, pylint, and Ruff pass; the repository's advisory mypy step reports missing stubs and existing engine typing errors in the lint environment.
