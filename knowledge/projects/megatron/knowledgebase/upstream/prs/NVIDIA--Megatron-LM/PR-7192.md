# Support GPT checkpoint loading into grouped HybridModel

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7192) · state: open · merged: False

## Original PR description

**Depends on #4942** — merge #4942 first. [Scoped diff of this PR's own changes](https://github.com/NVIDIA/Megatron-LM/compare/Connor-XY:pr4798-2-hybrid-stack-grouped...Connor-XY:codex/pr4942-grouped-gpt-checkpoint-load). The full diff also shows #4942's commits until it merges.

## What does this PR do?

Loading a GPT checkpoint into a HybridModel whose pattern has bracketed groups, such as `[M*-][M*-]`, fails today: the GPT layer maps reject the brackets, and the `fsdp_dtensor` parameter names of group members carry an extra `layers.<member>.` level. With this change, a grouped pattern loads a GPT checkpoint the same way as the pattern without brackets, and Mamba layers keep their fresh initialization.

- `torch_dist`: #4942 stores every grouped layer under the checkpoint key it has without brackets, so sharded entries retarget unchanged. Only the layer maps needed to parse brackets.
- `fsdp_dtensor`: a member's module path, `decoder.layers.<i>.layers.<member>.`, resolves to its global layer index.
- GPT checkpoints with indexed layer keys also load. TransformerBlock writes these with `non_homogeneous_layers=True` and in several other configurations. The loader checks the checkpoint's tensor keys and, when they are indexed, keeps the GPT layer index in each key instead of adding a layer axis. Model and optimizer state are handled the same way.

The migration guide now covers grouped patterns and both GPT key formats.

## Scope and dependency

Depends on #4942's bracket parser and checkpoint keys. Rebased onto #4942 at `980af2d63`, which includes main through `5052ce8c4`. That commit made grouped layers keep their ungrouped checkpoint keys, as requested in the #4942 review, so this PR no longer resolves logical group keys for sharded entries; only the FSDP module-path lookup remains. This follow-up contains only:

- `megatron/core/dist_checkpointing/gpt_checkpoint_interop.py`
- `megatron/training/checkpointing.py`
- `tests/unit_tests/dist_checkpointing/models/test_gpt_hybrid_interop.py`

Original grouped HybridStack work is by @Wohox, @Connor-XY, and @guihong-nv in #4798/#4942. The checkpoint implementation was extracted from #4942's review-fix commit `e8db9ddcb`.

Review requires core-adlr, core-nemo, dist-checkpointing, training-adlr, and training-nemo. Merge this follow-up after #4942.
