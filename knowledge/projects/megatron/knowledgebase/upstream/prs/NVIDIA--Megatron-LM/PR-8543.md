# Allow TE FP8/NVFP4 with BF16 GDN recurrence offloading

# What does this PR do?

Allow `gdn_core_attn` activation offloading when Transformer Engine projections and MLPs use FP8 or NVFP4. The FLA recurrence and offloaded tensors remain BF16/FP32. Existing TE precision contexts and recipes are reused; the Qwen validation tool adds a precision option and keeps BF16 as its default.

TE graph capture now honors `disable_parameter_transpose_cache`, matching the existing linear wrappers. NVFP4 graph offloading requires `TransformerConfig.disable_parameter_transpose_cache=True` through programmatic configuration. An earlier offload-disabled Qwen graph baseline with caching enabled failed on this SM120 stack; this PR does not fix that failure, and its behavior on documented NVFP4 training devices is not yet established. Disabling the cache requantizes weights on each microbatch.

Recurrence kernels, the offload manager and transfer scheduling are unchanged.

## Known limitations

- With the ordinary optimizer and fused weight-gradient accumulation, some parameter layouts can produce a misaligned gradient-buffer address. #8556 proposes a separate fix. Its current SM120 GPU control fails in TE NVFP4 GEMM on the old layout and passes with the fix for FP32/BF16 gradient buffers; reproduction on a documented NVFP4 training device remains pending.
- Complete Qwen TP2+SP NVFP4 training with offload disabled still fails on this SM120 stack, including with RHT and stochastic rounding enabled and unfused weight gradients. The failure is in TE's dgrad GEMM. The NVFP4 operands have shapes `[4112, 1024]` and `[128, 4112]`, giving a reduction dimension of 4112. A separate real TE Linear reproduces the failure at output width 4112, while 4096 and 4128 controls pass. This failure is independent of activation offloading; it is not counted as a passing training path.

Earlier FP8/NVFP4 and multi-rank results remain tied to the revisions in the [original evidence](https://github.com/WEIXILIN0307/Megatron-LM/tree/02890e97b1273d9a8695f76aaa208730054fe415/gdn-open-issues-20261027). The [earlier complete-Qwen FP8 graph comparison](https://github.com/WEIXILIN0307/Megatron-LM/tree/63e7434cb9cd53f84c49015566d4eb437abcaa7e/gdn-conflict-20261030) ran at `a04f1e65627ec7a5323bdd56d165a746b59f1c6e` and has not been rerun at this head.
