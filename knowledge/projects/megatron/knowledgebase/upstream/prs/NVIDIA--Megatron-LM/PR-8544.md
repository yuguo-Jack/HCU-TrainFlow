# Support multiple DistOpt instances with GTP

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8544) · state: open · merged: False

## Original PR description

This PR was prompted by a larger effort to improve support for multi-site training (https://github.com/NVIDIA/Megatron-LM/issues/8482), but is relevant to single-site training as well.

### Problem statement

The current implementation of generalized tensor parallelism (GTP) does not support multiple DistOpt instances. This is currently protected by assertion.

### How this PR fixes it

This PR scales down and replicates the existing intra-instance `GTP_remat` process groups appropriately.

### Details

As discussed in https://github.com/NVIDIA/Megatron-LM/pull/8519, Megatron currently requires multiple DistOpt instances to inter-instance groups between expert and non-expert parameters.
* In the absence of GTP, the correctness of the current construction of these groups requires that the number of DistOpt instances divides both `DP * CP` and `EDP`, and that the (default) `tp-cp-ep-dp-pp` or (non-default) `tp-cp-ep-pp-dp` rank order is used. 
* In the presence of GTP, we must strengthen the first divisibility condition: the number of DistOpt instances must divide `DP`, not just `DP * CP`. This PR adds this condition.

Regardless of GTP, current Megatron does not validate the rank ordering; this is the content of https://github.com/NVIDIA/Megatron-LM/pull/8519. I decided to leave this PR independent of that one (vs. stacking).

(I reiterate my "side comment" https://github.com/NVIDIA/Megatron-LM/pull/8519, that separate expert and non-expert inter-instance groups would allow us to relax some of these constraints.)

I tested this with various GTP/EGTP settings, with and without GTP sequence sharding. There weren't any major surprises, besides the aforementioned one related to divisibility conditions.
