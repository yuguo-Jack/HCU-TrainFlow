# Log only the configured MoE load balancing losses

# What does this PR do?

Stops `training_log` from reporting a spurious `load_balancing_loss: 0` when the MoE router uses `seq_aux_loss` or `global_aux_loss`.

`validate_args` stores a single `--moe-router-load-balancing-type` as a plain string. `training_log` then checks `"aux_loss" in args.moe_router_load_balancing_type`, which is a substring test and is also true for `seq_aux_loss` and `global_aux_loss`. As a result `load_balancing_loss` is added to `track_names`, even though the router never records it for those types. `MoEMetricsTracker.report(force_initialize=True)` pre-creates the missing entry as zeros, and `load_balancing_loss: 0` shows up in the console log line, TensorBoard and W&B next to the real `seq_load_balancing_loss` or `global_load_balancing_loss`.

The fix normalizes the type to a list before the membership checks. Behavior for `aux_loss`, list values, `sinkhorn`, `none` and `quantile_balancing` is unchanged.

With the real tracker (gloo, world size 1, router recording only `seq_load_balancing_loss`), `--moe-router-load-balancing-type seq_aux_loss` currently produces:

```
{'load_balancing_loss': tensor(0.), 'seq_load_balancing_loss': tensor(0.5000)}
```

After this change only `seq_load_balancing_loss` is tracked.
