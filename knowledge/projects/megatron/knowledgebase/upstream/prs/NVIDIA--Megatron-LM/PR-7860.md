# MFSDP v2: write TE fused wgrads directly into the reduce-scatter buffer

## Original PR description

# What does this PR do?

Lets Transformer Engine modules built with `fuse_wgrad_accumulation=True` write their weight gradients directly into the experimental Megatron-FSDP (v2) reduce-scatter buffer through TE's `weight.main_grad`, removing the per-micro-batch gradient copy.

Linked issue: Fixes #6942

## Summary

Today, after each module's backward, `copy_gradients_to_partial_buffer` copies every parameter's unsharded gradient into the reduce-scatter buffer. On H200 that copy is 1.2–3.9% of step time for a 4.54B-parameter Llama-shaped model (numbers in #6942). With this PR, TE writes the weight gradients of fused modules straight into the buffer.

## Design

As agreed in #6942:

- **Detection:** a parameter group treats a 2-D weight as fused when its owning module has `fuse_wgrad_accumulation=True`. MFSDP follows the TE module's own setting; there is no new `fully_shard` argument.
- **Buffer:** when a module's own backward starts, its group allocates and zeroes the reduce-scatter buffer on the compute stream and sets `weight.main_grad` to each fused weight's view. TE accumulates into it and returns no gradient to autograd. Post-backward adds the remaining autograd gradients (biases, LayerNorm, unfused weights) into their views, removes `main_grad`, and hands the buffer to the reduce-scatter stream as before.
- **Recompute:** a checkpointed region is recomputed before its modules' backward. No buffer is prepared during recompute, so each one is allocated only when its own module's backward starts.
- **Lifetime:** the buffer is allocated on the compute stream, so it is released only after the compute stream's next wait on the reduce-scatter stream (the next group's reduction or the end of backward). Allocation and release stay on one stream without `record_stream`, and at most two fused buffers are alive at once. With `delay_wgrad_compute=True`, a buffer lives until `backward_dw()` has run and the next reduction has waited for it.
- **TE contract:** only the documented `main_grad` attribute is used, not `__fsdp_param__` or `is_distributed_weight`.
- **MXFP8:** parameters with fusion raise a `ValueError` at `fully_shard` for now.

`runtime_schedule.md` gains a "Fused Weight Gradients" section describing this.

## Scope and follow-ups

- The MCore adapter still rejects `gradient_accumulation_fusion` for v2 (`mcore_fsdp_adapter.py`), so this PR applies to `fully_shard` used directly with TE modules. Allowing it in the adapter, including the combined-1F1B path, is the next PR.
- `overwrite_main_grad` to skip the zeroing for weights with a single contribution per step.
- MXFP8 support.
- Requires PyTorch 2.8 or newer: the post-accumulate-grad hook must fire when TE returns no gradient, and 2.7's `AccumulateGrad` returns early on an undefined gradient.

## Question for reviewers

Detection reads TE's `fuse_wgrad_accumulation` module attribute, a documented constructor argument that MCore also reads. The alternative is an explicit `fully_shard` argument. Happy to switch if you prefer that.

## Testing

New tests in `tests/unit_tests/distributed/mfsdp_v2/`:

- `test_fused_wgrad_losses_match_unfused`: `te.LayerNormLinear` + `te.Linear`, fused against the copy path; losses and weights match over 5 steps. Variants: one unit per layer, one unit mixing fused and unfused weights, activation checkpointing (reentrant and non-reentrant), and HSDP; 1 and 3 micro-batches; `set_to_none` True and False; fp32 and bf16.
- `test_fused_wgrad_main_grad_only_exists_during_backward`, `test_fused_wgrad_releases_buffers`, `test_fused_wgrad_recompute_prepares_each_buffer_at_its_backward` and `test_fused_wgrad_with_delayed_weight_gradient`, plus unit tests for detection and the buffer.
- `test_fused_wgrad_rejects_mxfp8_parameters` (Blackwell only).

Results on H200 (NGC PyTorch 26.08, TE 2.18):

- 2 GPUs, `test_fully_shard.py -k fused`: 40 passed, 8 skipped (the HSDP variants need 4 ranks).
- 1 GPU, the whole `mfsdp_v2` directory: no new failures. 7 tests fail on one rank, and the same 7 fail on main.
- Each test commit fails without the commit that follows it, and the recompute test fails if buffers are prepared during recompute.
- Not run here: the HSDP variants (4 GPUs) and the MXFP8 test (Blackwell).

## Measurement
