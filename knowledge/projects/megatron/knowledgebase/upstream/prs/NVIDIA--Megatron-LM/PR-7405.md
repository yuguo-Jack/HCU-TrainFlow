# dist_ckpt: inference-only streaming checkpoint dequantization for --fp8-param-gather / --fp4-param-gather loads

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7405) · state: closed · merged: True

## Original PR description

# What does this PR do?

Brings back the streaming checkpoint dequantization of #4451 (reverted in #6275) as an **inference-only** load path, `--stream-ckpt-dequant`, so that models with quantized params (`--fp8-param-gather` / `--fp4-param-gather`) can be loaded without materializing a BF16 replica of the whole model.

## Problem

`dist_checkpointing.load()` starts with `force_all_tensors_to_non_fp8`, which replaces every quantized destination of the sharded state dict with a fresh BF16 copy before a single byte is read. That is a full high-precision replica of the local model on top of the quantized params, alive until `load_state_dict` finishes, and it OOMs large models at inference load time.

## Why #4451 was reverted, and why this version is inference-only

#4451 returned the re-quantized parameters themselves in the loaded state dict. Exactly one training path reads those values in high precision: `optimizer.reload_model_params(state_dict=...)` under `--load-main-params-from-ckpt`, i.e. weights-only loads that re-initialize the optimizer (MLPerf DeepSeek-V3 turns that flag on automatically with `fp8_param_gather`, and Megatron-Bridge has the same branch). The FP32 main params were built from `dequantize(quantize(bf16))`, so SFT / post-training runs started from FP8-precision master weights. Loading *with* optimizer state never consumed the loaded values in high precision, which is why pretraining resumes were unaffected.

This version cannot be reached from training:

- `load_checkpoint` raises if it is called with an optimizer (every training entry point does).
- `validate_args` requires `--no-load-optim` and rejects `--finetune`, `--load-main-params-from-ckpt`, `--fp8-recipe delayed` and any `--ckpt-fully-parallel-load-exchange-algo` other than `broadcast`.
- The flag defaults to off and is passed explicitly on the inference command line (as the functional tests below do).

## Design

- **Per-destination quantization.** `MCoreLoadPlanner` hands DCP a view of a per-destination BF16 scratch and quantizes the whole destination once, after its last read item (`finish_plan` counts read items per destination). #4451 quantized per read item, which corrupted data-derived scales and silently dropped bytes on resharding loads (TE quantized tensors do not support being narrowed).
- **Delayed scaling is not supported.** Its scale is only restored by `load_state_dict`, so it cannot be quantized during the load; supported recipes are tensorwise, mxfp8, blockwise and nvfp4.
- **`ShardedTensorFactory` views (SwiGLU `linear_fc1`).** Streamed only when the factory's views alias the param's codes *and* scales and share no per-tensor scale (MXFP8 with 128-row aligned halves); the merge then returns a view of the param. Otherwise (tensorwise, NVFP4, blockwise, misaligned MXFP8) that tensor takes the upfront path: per-tensor-scaled views share one scale and cannot be quantized independently.
- **Fully parallel load (`broadcast` only).** The loading rank packs the raw quantized storage (codes and scales) into one byte buffer and broadcasts it; receivers unpack it straight into their own params. Nothing is dequantized or re-quantized, so every rank holds the loading rank's encoding bit for bit, at half the bytes of a BF16 exchange. Sizes are gathered once with an `all_gather_object` so that ranks that do not need a tensor can take part in its broadcast.
- **Streamed loads return aliasing views**, never the param object itself: TE's generic quantized `copy_` (blockwise) cannot copy a tensor onto itself, and `load_state_dict` copies the loaded tensor into the param.
- `_unwrap_pyt_sharded_tensor` strips prepended singleton axes with `view` instead of `ten[0]`, which dequantizes MXFP8 tensors.

## Functional tests

- `gpt_static_inference_tp1_pp1_583m_fp8_cudagraphs` (H100, tensorwise + `--fp8-param-gather`): `--stream-ckpt-dequant` enabled; params are bit-identical, so the golden values should not change.
- New `gpt_dynamic_inference_tp1_pp1_dp4_583m_mxfp8_param_gather_logitsmatch` (GB200): the BF16 minitron checkpoint loaded straight into MXFP8 params over DP=4 with `--ckpt-fully-parallel-load`, covering the streamed load and the quantized broadcast. **Its golden values need to be generated by the first CI run.**

## Known limitations / follow-ups

- `linear_fc1` of tensorwise / NVFP4 / blockwise models still takes the upfront path (about 40% of a dense model's params), because TE's `split` either shares the per-tensor scale between the views or returns dequantized copies. Fixing it fully needs the factory's parent to become the streaming unit (lazily materialized sub-tensors) and, for blockwise, a storage-aliasing `split` in TE.
- Megatron-Bridge builds its own load strategy and does not read this field.
- Related: #4451, #6275, #6666.
