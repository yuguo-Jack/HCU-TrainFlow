# [Dev] Restore non-fused NCCL-EP grouped tensors

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8925) · state: open · merged: False

## Original PR description

MCore dev rejects BF16 NCCL-EP grouped tensors when TE op-fuser is disabled, so six unchanged Megatron-Bridge Nemotron recipe tests fail during config finalization. Main already removed this rejection in #7195 (`7613fd7a9508833d5895dd35d2847a1b8571fd0d`); dev still contains it at `7b66fcc088e6e60b87c350e0e185721e0373d0ab` after #8813.

Port the matching validation removal to dev and restore the existing NCCL-EP output/gradient parity and padding tests. Add a small BF16 config regression test. Eager grouped-tensor execution is already present; this changes no kernel implementation. Static-capacity and quantized-communication restrictions remain intact.

This unblocks the dev validation stage of NVIDIA-NeMo/Megatron-Bridge#6759. Classification: **Megatron-LM bug**. #8813 identifies the inspected dev snapshot; it is not claimed to have originally introduced the rejection.

Validation:
- Bridge recipe-finalization selection: **35 passed** with this correction, versus **29 passed / 6 failed** on unmodified dev.
- Focused MCore NCCL-EP/config checks: **10 passed**.
- Restored numerical tests were attempted on two RTX 6000 Ada GPUs. They cannot run there: TE requires SM90+, while Ada is SM89. Numerical correctness remains for supported H100/GB200 CI; no passing numerical result is claimed.
- Black, isort, pylint, ruff and diff checks passed. The formatter's advisory mypy step reports existing typing errors.
- Independent review completed; no remaining code blockers found.

Source: the existing in-repository main fix #7195. No external repository code was copied. Existing license notices are preserved.
