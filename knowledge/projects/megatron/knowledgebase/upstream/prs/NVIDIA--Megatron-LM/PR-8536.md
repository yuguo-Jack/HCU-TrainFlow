# [Dev] fix(dsa): keep KPool safe on empty and tail-less query rows

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8536) · state: open · merged: False

## Original PR description

## Summary

A DSA layer that computes top-k can prove from its layout that every query row selects at least one key (`dsa_masking.can_prove_all_topk_rows_nonempty`). When it can, it skips the empty-row masking around sparse attention added in #7434.

KPool selection (#8287, `dsa_indexer_kpool > 1`) without `dsa_indexer_kpool_always_select_tail` leaves the rows before a query's first complete pool with no selected key (all `-1`). The layout check cannot see this, so such a layer claimed the certificate for rows that are in fact empty, and the masking was skipped for them.

This change stops certifying when the layer runs KPool selection without its tail. Layers without KPool, and KPool with tail selection (the default), are unchanged.

The second commit fixes a crash on the same KPool path. `fused_qk_topk_kpool` flattens the selected pools with `pool_topk.reshape(rows, -1)`. When a rank has no query rows (a packed context-parallel split can leave one empty), `rows` is 0 and the reshape raises `cannot reshape tensor of 0 elements into shape [0, -1]`. The helpers on the same path (`_compute_index_scores`, `_kpool_topk_from_score_chunks`) already handle zero rows. The function now returns early with fixed-width empty outputs whose dtypes and widths match the non-empty case. `main` has the same unguarded reshape.

## Test plan

- [x] New CPU test `test_dsa_topk_nonempty_certificate.py`: builds a one-layer DSA layer from a local config, turns on KPool selection, and runs it on a plain causal layout with and without tail selection.
  - Without the tail, the selection has empty rows and the certificate is now `False`. On `dev` it is `True`, so the `no-tail` case fails there.
  - With the tail, every row selects a key and the certificate stays `True`.
- [x] CPU: `test_attention_variant_dsa.py` gives the same result on this branch and on `dev` (207 passed, 61 skipped; the 105 errors are identical on both and come from the CPU environment).
- [x] New CPU test `test_kpool_empty_query_keeps_fixed_width` in `test_kpool_causal_tail.py`, for both `return_index_scores` settings.
- [x] New `test_kpool_contract.py`: selector-contract validation, a frozen selector without auxiliary loss, per-segment compression against an independent torch reference, score-free selection without an autograd graph, and finite zero gradients for empty absorbed rows.
- [x] The KPool tests also pass in a larger stack on top of this change: on H100 with the dev CI image, and on GB300 (`test_kpool_causal_tail.py` 164 passed, `test_kpool_contract.py` 140 passed).
