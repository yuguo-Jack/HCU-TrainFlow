# Support multiple distributed optimizer instances for LayerWise optimizers

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8466) · state: open · merged: False

## Original PR description

This PR was prompted by a larger effort to improve support for multi-site training (https://github.com/NVIDIA/Megatron-LM/issues/8482), but is relevant to single-site training as well.

### What this PR does

This PR adds support for multiple LayerWise DistributedOptimizer instances. This closes a functionality gap with the standard DistributedOptimizer, which already supports multiple instances.

While making this change, I noticed that the current LayerWise DistributedOptimizer does not seem to support expert "fallbacks" (e.g., expert biases, admittedly uncommon). The current implementation appears to group such parameters with non-expert fallbacks, then later rejects them. (The standard DistributedOptimizer has no such issues.) This PR adds support for expert fallbacks, treating them separately from the non-expert fallbacks to account for the fact that these two parameter classes generally have different data-parallel domains.

### Additional details

It is technically possible to refactor the second change into a separate PR, but there is some overlap in the logic so it felt cleaner to address these two concerns together.

I validated these changes with CPU multiprocess numerical tests and GPU cluster tests covering Muon updates, dense and MoE models, `torch_dist` checkpoint round-trips, and changes in optimizer-instance count.
