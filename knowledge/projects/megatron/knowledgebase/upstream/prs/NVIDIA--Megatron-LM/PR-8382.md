# Let torchrun exit cleanly between determinism profiles

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8382) · state: open · merged: False

## Original PR description

`run_nsys_breakdown.sh` stops after its first profile when `cudaProfilerStop()` shuts down the Nsight session and terminates the torchrun launcher. The launcher exits with a signal error, so `set -e` prevents the nondeterministic profile and comparison from running.

Use `--capture-range-end=stop` to stop collection while allowing the target application to finish its cleanup and exit normally. The entry point is still responsible for having a finite run; the profiling window remains bounded by the CUDA profiler API.

Validation on a single GH200 (aarch64), Nsight Systems 2025.6.3.541, PyTorch 2.14.1+cu130, NVIDIA driver 595.58.03:

- Before: a finite fused/unfused CE forward/backward probe wrote its deterministic results, then torchrun reported signal 15. The wrapper exited 1 after producing only `nsys-det.nsys-rep`; no nondeterministic report was produced.
- After: the same probe, with only this wrapper option changed, completed both modes and the leaderboard with exit 0. Both `.nsys-rep` files and NVTX CSVs were produced; independent `cuda_gpu_kern_sum` and `nvtx_gpu_proj_sum` exports also exited 0. No foreign GPU process was observed during either run.
- `bash -n` and `git diff --check` passed.

The probe warms up before calling `cudaProfilerStart()`, then performs 20 measured forward/backward iterations for each of fused/unfused CE and bf16/fp32, calls `cudaProfilerStop()`, and destroys its process group. This validates the wrapper lifecycle; it is not a model performance claim.
