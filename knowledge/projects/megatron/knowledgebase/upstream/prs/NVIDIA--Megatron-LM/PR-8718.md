# What does this PR do?

Add a decoder-width, bias-free FastGELU vision projector recipe to the Nemotron MIMO provider, with descriptive recipe names and compatible aliases.

The new two-linear projection maps encoder output width -> decoder hidden width -> decoder hidden width. Its intermediate width follows the decoder rather than expanding to four times the encoder output width. It uses unfused FastGELU for variable-length image embeddings, with no GLU or added normalization layer, and supports both existing projector placements.

| Provider choice | Intermediate width | Activation |
| --- | --- | --- |
| `affine` (unchanged default) | Single linear layer | None |
| `mlp_squared_relu_4x_encoder_output_width` / `mlp` | 4x encoder output width, including pixel shuffle | Squared ReLU |
| `mlp_fast_gelu_1x_decoder_hidden_width` / `mlp2` | Decoder hidden width | Unfused FastGELU |

Resolve aliases inside the existing factories without rewriting parsed or restored argument strings. Preserve the existing affine/MLP configurations, backend classes, parameter names and generic Core projector types. Matching aliases select the same architecture; switching between different recipes is not a checkpoint conversion.

Share the existing public inference FastGELU expression through Core activations while retaining its old inference import name. Existing compiled activations and inference configuration/defaults remain unchanged; this PR does not add automatic inference recipe detection.

- Black, isort, pylint, Ruff and the kernel determinism coverage gate pass. Mypy passes for the changed Core/test files in a CPU PyTorch environment.
- Compatibility audit confirms existing compiled activation functions, inference configuration functions, non-projector provider functions and the generic projector are unchanged. The moved eager activation matches its prior outputs and input gradients exactly in six CPU cases.
- Added tests cover all accepted recipe spellings, both projection placements, pixel shuffle, default/invalid direct callers, explicit projector forward/gradient math, strict serialized checkpoint loading between aliases in both directions, and bit-exact activation replay.
- Single-GPU execution of the native provider, projector and checkpoint-inference test files: **92 passed, 1 skipped** (the existing multi-rank GTP case requires at least two ranks). This includes strict alias-to-canonical and canonical-to-alias state restoration for both MLP recipes, explicit TE forward/input/weight-gradient comparison at two token lengths, and unchanged inference configuration checks.
- The two new variable-length activation replay cases pass on GPU, checking bit-exact output and gradient replay. Total: **94 passed, 1 skipped**. Tests ran through `torch.distributed.run` using actual source, without the suite-wide conftest to avoid an unrelated automatic dataset download; no production module was mocked. Runtime package/source fingerprints match before and after.
