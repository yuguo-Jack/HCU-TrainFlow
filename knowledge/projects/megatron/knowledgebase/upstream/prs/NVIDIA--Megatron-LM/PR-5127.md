# What does this PR do ?
Right now, router replay is closely intertwined with the rest of the inference context, making it very difficult to make incremental modifications to the inference context code. This PR factors it all router replay logic into separate classes and files so that targeted modifications can be made more easily.

could we describe `MoERoutingReplayCache` as saving expert choices, rather than guaranteeing the same choices when a request resumes? the resumed computation still uses `RouterReplayAction.RECORD`, so it records choices again instead of replaying the saved ones.

an example flow:

- request A processes a token using experts 2 and 5, and the cache saves that choice.
- after a pause, request A recomputes that token and records the choices made this time.
- the cache does not force that computation to use experts 2 and 5 again.
