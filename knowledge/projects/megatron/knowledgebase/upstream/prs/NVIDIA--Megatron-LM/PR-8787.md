# What does this PR do?
With `hfsdp_param_gather_overlap`, a DP-Outer bucket larger than the remaining prefetch size could end the DP-Inner prefetch window partway through the next FSDP unit. The rest of that unit was then gathered only at its own pre-forward hook, on the critical path. The window now finishes the FSDP unit it ends inside, which exceeds the size by at most one unit and never walks further.

### Complete holes inside the frontier FSDP unit

The new [completion helper](https://github.com/NVIDIA/Megatron-LM/blob/5e9f02611a020c650402455f678cb18803027a0e/megatron/core/distributed/fsdp/src/megatron_fsdp/param_and_grad_buffer.py#L4700-L4720) assumes that reaching the maximum/minimum selected bucket means all intervening buckets were selected. That is not guaranteed: [parameter groups distinguish dtype](https://github.com/NVIDIA/Megatron-LM/blob/5e9f02611a020c650402455f678cb18803027a0e/megatron/core/distributed/fsdp/src/megatron_fsdp/param_and_grad_buffer.py#L1848-L1884), whereas [collective groups combine buckets by unit and expert status](https://github.com/NVIDIA/Megatron-LM/blob/5e9f02611a020c650402455f678cb18803027a0e/megatron/core/distributed/fsdp/src/megatron_fsdp/param_and_grad_buffer.py#L1999-L2025). A unit registering dense FP32, expert FP32, then dense FP16 parameters can therefore have an interleaved dense collective group.

**Failure:** Use `unit_ids=[0,1,1,1,2]`, sizes `[6,20,6,6,6]`, and bucket groups `{0:[0],1:[1,3],2:[2],3:[1,3],4:[4]}`. With overlap, prefetch, and DP-Outer gathering enabled, requesting bucket 0 with budget 10 makes size extension return `[0,1,3]`. The new helper starts after bucket 3 and stops at unit 2, leaving bucket 2 ungathered. DP-Inner therefore still gathers that part of unit 1 at its own hook instead of prefetching the whole unit. Backward traversal from bucket 4 similarly leaves `[1,3,4]` incomplete.

**Correction:** Fill missing buckets of the frontier unit inside the selected interval, as well as completing its directional tail. Preserve atomic bucket-group inclusion without adding another unit. A small proposed insertion after the existing `while` loop and before its final return is:

```python
        for bucket_id in range(min(result), max(result) + 1):
            if (
                bucket_id not in result
                and parameter_groups[bucket_id].fsdp_unit_id == fsdp_unit_id
            ):
                result.update(self.buffer.bucket_to_bucket_group[bucket_id])
```

The existing `None`-frontier early return should remain. Skipping already-selected buckets is important: otherwise a fine-grained request containing only bucket 3 could unnecessarily expand its existing collective group to bucket 1. This patch is based on source reasoning and must be verified before adoption.

**Acceptance and preservation:** Add proposed forward/backward pipeline regressions with the mapping above. Expect DP-Inner `[0,1,2,3]` forward and `[1,2,3,4]` backward; DP-Outer should include all five buckets in both cases. Also assert that helper-only partial requests `[3]` forward and `[1]` backward remain unchanged. Retain the [existing regression cases](https://github.com/NVIDIA/Megatron-LM/blob/5e9f02611a020c650402455f678cb18803027a0e/tests/unit_tests/distributed/mfsdp_v1/test_mfsdp_fully_shard.py#L275-L431): contiguous forward/backward completion, unchanged non-unit frontiers, zero-size `inner=[0]`/`outer=[0,1,2]`, double-buffered `inner=[0,1,2]`/`outer=[0,1,2,3,4]`, overlap-disabled `inner=[0,1]` with no outer launch, and outer-gather-disabled `inner=[0,1,2,3,4,5]` with no outer launch.
