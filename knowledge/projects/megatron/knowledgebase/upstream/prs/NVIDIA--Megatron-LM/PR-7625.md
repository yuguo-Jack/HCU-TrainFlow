# [DEV] Add opt-in aligned HCA backward

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7625) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

Add `--hca-aligned-backward` (default off) using NVIDIA/cudnn-frontend#1198. Supports GB300/Rubin, contiguous CP4/8/16, and 8K–128K tokens with 128-token-aligned local chunks. Requires BF16, H128/D512, window/compression 128, and one padded sequence per pack. Other eager layouts use stock backward; cuDNN's capability query controls eligibility.

Preserves existing forward, output RoPE and KV reconstruction. CUDA graph replay requires fixed pack boundaries and eager backward warmup. The configuration comment reflects the broader support.

Validation: Hecate/Rubin job **637018** passed 66 MCore and 55 frontend tests, 56 shape/rank cases, and three memchecks. Saved 15-layer, 30-step comparisons: **637939**, 32K/CP8, **0.23%** step-time reduction; **637940**, 64K/CP16, **1.78%**. All ten arms were finite; loss/gradient-norm agreement passed. The generalized 64K result remained near parity with the previous implementation. CP4 and other sequence lengths have attention-level coverage; earlier GB300 validation is recorded in job **3144587**.

Review follow-ups: prepare eager packing once per microbatch, skip no-grad HCA selection, require explicit CP size, and drop unused saved index metadata. Backend checks precede capture guards. Reconciled with current `dev`.

Latest validation (Hecate/Rubin): **894182**, **136 correctness + 332 determinism/registry checks passed**; **894212**, bit-exact outputs/gradients and attention backward within **0.3%** of the previous PR at 32K/CP8 and 64K/CP16.

**[IMPORTANT Performance]** HCA selection also runs in forward passes that can never reach backward. In the TE-graph eval path this adds back one device→host sync per HCA layer.

**How it happens**
- **Setup:** `hca_aligned_backward=True`, `cuda_graph_impl="transformer_engine"`, `cuda_graph_modules` empty or containing `attn`, an eligible layout, and periodic evaluation (`model.eval()` under `torch.no_grad()`).
- **No preparation:** [`prepare_packed_seq_params`](https://github.com/NVIDIA/Megatron-LM/blob/036041092fb0eebbee741d6b5e2fa845e7a06036/megatron/training/utils/packed_seq_utils.py#L32) skips the HCA preparation whenever `cuda_graph_captures_attention(config)` is true, so `_aligned_hca_sequence` is never set.
- **Eval runs eagerly:** TE graphs require `self.training` ([module.py L812-L822](https://github.com/NVIDIA/Megatron-LM/blob/036041092fb0eebbee741d6b5e2fa845e7a06036/megatron/core/transformer/module.py#L812-L822)), so this branch runs outside the graph.
- **Per-layer sync:** `aligned_hca_cp_rank` → [`_is_single_sequence`](https://github.com/NVIDIA/Megatron-LM/blob/036041092fb0eebbee741d6b5e2fa845e7a06036/megatron/core/transformer/experimental_attention_variant/csa_utils/aligned_hca.py#L61) has no prepared verdict, so it calls `.item()` on the CUDA `cu_seqlens`. That is one device→host sync per HCA layer per eval microbatch, and the selected rank is thrown away because backward never runs.
- **Same waste elsewhere:** the no-grad first pass of full activation recompute also runs the selection, and so does any frontend that never calls `prepare_packed_seq_params`.

**Expected:** only select the HCA backward when a backward can follow.

**Fix** (gate the selection on autograd being enabled):
```suggestion
            if self.config.hca_aligned_backward and indexer is None and torch.is_grad_enabled():
```
`training_with_grad` (L3493) would also work, but it additionally sends eval-mode-with-grad forwards to the stock path. `torch.is_grad_enabled()` is the smallest condition that keeps the invariant.

**Must keep working**
- Training forwards with grad, both eager and during TE/local graph capture, still select HCA and still record the `_assert_async` boundary guard.
- The recompute forward inside backward runs with grad enabled, so full and selective recompute still use the HCA backward.
- The forward output is unchanged: FlashMLA forward is the same on both branches.
- `test_aligned_hca.py` and `test_dev_aligned_hca_backward_replays` call `aligned_hca_cp_rank`/`csa_sparse_attn` directly, so they are unaffected.

**Acceptance**
- Proposed test (not run): patch `csa.aligned_hca_cp_rank` with a `Mock` and run the THD-CP forward on an eligible layout.
  - Under `torch.no_grad()`: the mock is not called and `csa_sparse_attn` receives `hca_cp_rank=None`.
  - With grad enabled: the mock is called exactly once and its return value is passed through.
- Static invariant: the `aligned_hca_cp_rank` call is reachable only when `torch.is_grad_enabled()` is true.
