# Seed the RNG from the grid that initialize_megatron builds

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8737) · state: closed · merged: False

## Original PR description

Depends on #8031, #8037 and #8039 (which contains #6259). Please review the diff from the merge of their heads: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/82d482bb48...yx/pstate-g13-rng-from-builder).
- The end-to-end seeding test builds `pretrain()`'s collection with `training._build_pg_collection_from_parallel_state`, which #8037 adds.

**Why.** Stock `pretrain()` passes no collection to `initialize_megatron`, so RNG seeding reads the pipeline, data-parallel, tensor, expert and GTP-remat ranks from the global parallel state. `initialize_model_parallel()` has just returned the collection of that grid, but nothing uses it. Seeding is one of the last global reads in stock setup.

**What.**
- `_initialize_distributed` returns the collection that `initialize_model_parallel()` built, or `None` when it builds no grid: model-parallel setup skipped, a grid already initialized, or no CUDA device.
- `initialize_megatron` seeds from `seed_pg_collection` when the caller passes one, and otherwise from that collection. It falls back to the global state only when no grid was built.
- The log lines that report the grid sizes read the same collection, so initialization reads no global group, rank or size once the grid exists.

**Tests.**
- `test_rng_ownership.py`:
  - On 4 GPUs (TP2 PP2, TP2 EP2 ETP1, TP2 with GTP remat 2; each with and without `--data-parallel-random-init`), `initialize_megatron` runs with every global accessor raising once the grid exists. The CPU, CUDA, tracker and Python RNG states equal those of the global path, and the collection `pretrain()` builds afterwards holds the same group objects.
  - The seeding precedence (model collection, built grid, globals), eager and lazy.
- `test_initialization_lifecycle.py`: `_initialize_distributed` returns the built collection and logs sizes from it, with the global size accessors patched to raise.

On 4 GPUs against its base: `test_rng_ownership.py` has 86 passed here vs 74 on the base, and its 12 new tests pass; `test_initialization_lifecycle.py` has 112 passed on both sides. No test fails on either side, and there are no regressions. The 12 new tests do not exist on the base, so the run does not show them failing without this change. Before the sync with main, the branch also ran on 4 CPU gloo ranks with no regressions; the 6 precedence cases pass there, and the 6 end-to-end cases need CUDA. In the integration run, which merges all #6307 PRs onto main, this PR's test files show no regressions against main: `test_rng_ownership.py` has 86 passed vs 63 on main, and `test_initialization_lifecycle.py` has 112 passed on both.

**Compatibility.**
- No signature change. Seeds are unchanged for every non-lazy initialization.
- Behavior change that needs maintainer sign-off: with `lazy_mpu_init`, the tensor-parallel RNG seed now uses the TP group rank instead of the global rank. `initialize_megatron` sets a provisional TP rank equal to the global rank before the grid exists, and that value used to replace the group rank in the seed. The new seed matches non-lazy runs and Megatron-Bridge's own initialization. No in-repo code uses `lazy_mpu_init`; `pretrain` ignores the returned finish function. Is the new lazy-mode seed acceptable, or should lazy mode keep the old one through a special case?
- `_initialize_distributed` is private, but its return value changes from `None` to a collection. A wrapper that patches `parallel_state.initialize_model_parallel` and returns `None` would now fail on the size log lines. I found no such wrapper in this repository, Megatron-Bridge or NeMo-RL.
- `pretrain` still builds its own collection after `initialize_megatron`, with #8037's `_build_pg_collection_from_parallel_state`, which calls `use_mpu_process_groups()`. It holds the same group objects, as the end-to-end test checks. #8767 and #8768 change that path later.
- Needs `determinism-exempt` only because #8039 brings #6259's change to `megatron/core/optimizer/__init__.py`. This PR touches no kernel file.
