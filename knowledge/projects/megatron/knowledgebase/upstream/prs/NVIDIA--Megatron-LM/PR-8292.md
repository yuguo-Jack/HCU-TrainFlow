# Fix duplicate parameter all-gathers across MoE distributed optimizers

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8292) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Restrict each `DistributedOptimizer` to synchronizing the bucket groups it owns, avoiding duplicate parameter all-gathers when the dense and expert optimizers of an MoE model share the same DDP model chunk.

The fix targets the synchronous parameter-gather path with `overlap_param_gather=False` and does not change the Adam update rule.

## Problem

The dense and expert child optimizers manage different parameter buffers but can hold the same `model_chunks`. Currently, `start_param_sync_for_bucket_group_subset()` excludes LayerWise-managed groups without checking ownership by the current optimizer. Consequently, each child optimizer gathers both dense and expert groups after its update, and every parameter bucket is gathered twice per step.

```text
Before:
  dense optimizer update  -> gather dense + expert groups
  expert optimizer update -> gather dense + expert groups

After:
  dense optimizer update  -> gather dense groups
  expert optimizer update -> gather expert groups
```

Simply skipping synchronization for the second optimizer is not correct: the expert parameters have not yet been updated when the first gather occurs. Each owner must still synchronize its parameters after updating them.

## Fix

- Select groups owned by the current optimizer using the identities of the buckets in `self.buffers`.
- Skip groups with no owned buckets, and assert that every bucket in a selected group belongs to the current optimizer to reject mixed ownership.
- Preserve the existing exclusions for empty and LayerWise-managed groups, and do not initiate synchronization for stub optimizers.
- Keep each group intact and continue to call `DDP._start_bucket_group_param_sync()`, preserving the existing parameter-publication and quantization post-processing entry point.

The production change is confined to one method, with no new configuration option. The implementation and dispatch regression tests are in this PR's [Files changed](https://github.com/NVIDIA/Megatron-LM/pull/8292/files) tab.

## Reproduction and profiling results

The reproduction uses the pinned official baseline [7a0024e2ca8317740af2e2e3ac245ba3cfe34bc1](https://github.com/NVIDIA/Megatron-LM/commit/7a0024e2ca8317740af2e2e3ac245ba3cfe34bc1) on a single node with 4 x H20 GPUs: a two-layer BF16 GPT MoE, hidden size 128, four experts, and top-k 2; TP=PP=CP=ETP=1, EP=2, dense DP=4, and expert DP=2. Parameter-gather overlap is disabled. The reproduction runs the real DDP, optimizer updates, and NCCL collectives; the counters track only gathers for parameter buckets.

| Per rank, per step | Before | After |
| --- | ---: | ---: |
| Parameter AG calls per dense or expert bucket | 2 | 1 |
| Parameter AG GPU kernels inside `optimizer_step` | 4 | 2 |

All four ranks show the same reduction: each child optimizer goes from two parameter AG kernels to one. The screenshots compare the same rank and configuration before and after the fix. Two unrelated all-gathers remain unchanged, so the full-step total drops from six to four. The profile confirms removal of redundant communication; end-to-end performance is measured separately below.

## Correctness validation

The GPU experiments below were executed on the pinned official baseline [`7a0024e2`](https://github.com/NVIDIA/Megatron-LM/commit/7a0024e2ca8317740af2e2e3ac245ba3cfe34bc1) and its patched candidate.

- **Four-GPU training comparison:** From the same initial state, five consecutive training steps produce bit-exact loss, post-ReduceScatter gradient shards, BF16 model parameters, FP32 master parameters, and Adam state on all four ranks. The maximum absolute difference is zero.
- **Sixteen-GPU fixed-gradient optimizer regression:** On 2 nodes x 8 H20 GPUs, with EP=4, expert DP=4, and dense DP=16, a small BF16 MoE exercises FusedAdam, ChainedOptimizer, and NCCL using identical initial parameters, gradients, and Adam state. Both cold-start and nonzero-history cases run for five consecutive updates. A/A, B/B, and A/B comparisons are bit-exact across 54,064 tensor comparisons (A: baseline; B: patched candidate).

**Synchronization is checked without repairing the model:** No extra model-parameter gather is performed before comparison. After each update, DP/expert-DP parameter replicas match a reference independently reconstructed from the owners’ updated FP32 master shards. Validation collectives operate only on detached snapshots and never write back to the model.

The PR is based on [`3888b348`](https://github.com/NVIDIA/Megatron-LM/commit/3888b34882eb85aecf6ec9ecc3f4020b7608b497). The optimizer file is byte-identical between the validation baseline and the PR base, both before and after applying the fix. These experiments are not a full CI rerun on the PR base.

## Scope

Runtime correctness validation covers BF16 with synchronous parameter gathers. The overlap scheduling and existing deferred-synchronization gates are unchanged. Retaining the DDP post-processing entry point is not a claim of runtime FP8/MXFP8 coverage.

## Additional performance results

A randomly initialized synthetic training workload using the Qwen3-30B-A3B architecture was measured on two nodes with 16 x H20 GPUs: BF16, sequence length 2048, EP=4, EDP=4, dense DP=16, global batch size 16, and both parameter- and gradient-communication overlap disabled.

Eight paired A/B runs on the same GPUs show a median step-time reduction of **8.43%** and a median throughput increase of **9.21%**. Each run uses 200 warmup steps followed by 1,000 measured steps. A Student-t 95% interval over the eight paired log time ratios, transformed to step-time reduction, is **7.93%-9.80%**; this is not a confidence interval for the median.

These results characterize performance under the stated synthetic workload. The performance runs were not used to establish end-to-end numerical equivalence; optimizer-update and parameter-synchronization correctness was validated separately by the bit-exact fixed-gradient regression.
