## What does this PR do?

This PR adds selective, ordered replay for the streamwise wide-residual connections introduced
by #6716. It reduces saved wide-boundary activations without recomputing the expensive attention,
Mamba, MLP, or MoE branch computations.

The PR is intentionally limited to replay:

- #6716 owns HybridStack/Mamba construction, training CLI, and checkpoint restoration.
- #7600 owns eager FP32 residual execution and fused branch casts.
- This PR owns replay planning, checkpoint boundaries, offload ownership, and preservation of the
  branch dtype during replay.

## Design

### Ordered replay blocks

Local layers are partitioned into replay blocks. Every layer in one block receives a `ResidualStreamRecomputeContext` containing:

- one `CheckpointWithoutOutputManager` shared by the block; and
- whether the current layer is the block end.

During forward, the manager records only the cheap operations that form wide residual boundaries:

1. residual reads;
2. connected branch norms; and
3. non-terminal residual writes.

The branch output remains in the ordinary autograd graph. At the block end, `finalize()` places one hook on the live residual boundary and discards registered intermediate outputs. During backward, the existing manager replays those operations in forward order and restores their storage before ordinary autograd continues.

```text
wide state X_l
    |
    +-- checkpoint(read + norm) --> ordinary-width branch --> branch update
    |                                                        |
    +---------------- checkpoint(write) <--------------------+
    |
wide state X_{l+1}

...repeat within one ordered replay block...

live block-end state -> one backward hook -> replay reads/norms/writes in order
```

### Memory model

If one ordinary residual activation costs `X`, a `K`-stream residual costs approximately `K*X` per retained boundary. With replay blocks of `M` local layers, the retained wide-boundary term is amortized to approximately:

```text
K * X / M per layer
```

This estimate applies only to residual-boundary activations. Branch, optimizer, and communication memory are unchanged by this mechanism.

### FP32 residual streams

With `fp32_residual_connection=True`, the carried stream remains FP32 while branches execute in `params_dtype`. Replay captures the requested branch-input dtype in its read closure, so backward reconstruction selects the same fused read and returns the same branch dtype as eager forward.

### Fine-grained activation offloading

For a connected branch, replay owns its residual read, immediately connected norm, and residual write. Those norms are therefore not also offloaded. Independent nested groups such as QKV or expert activations remain eligible for offloading.

## Configuration

```text
--recompute-granularity selective
--recompute-modules residual_stream
--residual-stream-recompute-num-layers 4
```

Omitting `--residual-stream-recompute-num-layers` places all local layers in one replay block.

Validation rejects replay without wide residuals, replay outside selective recomputation, non-positive block sizes, CUDA graph capture, and intermediate-layer extraction that could bypass the block-end restoration hook.

## Validation

- Eager versus replay forward, input-gradient, and parameter-gradient equivalence.
- Native and FP32 residual streams across Transformer, Mamba, and mixed HybridStack paths.
- Ordered storage discard/restoration and block partitioning.
- Connected-norm ownership with nested fine-grained QKV offloading.
- Dedicated distributed and surrounding regression coverage.
