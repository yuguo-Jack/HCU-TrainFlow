# What does this PR do?

Upgrade the development dependency from `multi-storage-client~=0.50` to `~=1.1`, allowing compatible 1.x releases while excluding 2.x. Regenerate `uv.lock` with CI's pinned uv 0.7.2, upgrading MSC from 0.51.0 to 1.1.0 without changing other package versions.

Add `sys_platform != 'win32'` to MSC's direct development requirement. Energon's requirement is unchanged; its transitive MSC dependency can still cause MSC to be installed on Windows.

Megatron's MSC integration does not use the APIs removed in the [1.0.0](https://github.com/NVIDIA/multi-storage-client/releases/tag/1.0.0) and [1.1.0](https://github.com/NVIDIA/multi-storage-client/releases/tag/1.1.0) releases, so no production code changes are needed.

## Validation

- `uv lock --check` passed in a Python 3.12 Linux container with uv 0.7.2.
- MSC's direct requirement marker excludes Windows and includes Linux/macOS for Python 3.12–3.14. Verified that Energon's requirement and transitive MSC dependency are unchanged.
- Five existing MSC fallback test functions passed in an isolated CPU harness.
- Temporary smoke checks passed with MSC 1.1.0 and PyTorch 2.14.1+cpu: file I/O, path checks, glob, download, Megatron's ranged bin reader, torch save/load, and a one-rank Gloo distributed checkpoint round trip using Megatron's MSC reader/writer factories. Production definitions were loaded independently of GPU-only module imports.
- `git diff --check` passed. The repository autoformatter check passed with no changed Python files.
- The full GPU unit/functional suites were not run locally; the Megatron CI container was unavailable.
