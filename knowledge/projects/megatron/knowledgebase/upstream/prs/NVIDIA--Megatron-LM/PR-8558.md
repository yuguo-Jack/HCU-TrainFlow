# refactor(training): migrate CheckpointConfig

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8558) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Makes `cfg.checkpoint` the only source of checkpoint policy for training and inference. `CheckpointConfig` already existed and both containers already carried it; this PR moves its checks and derivations onto the class, builds it through one factory, and switches the consumers (`checkpointing.py`, the training loop, the async worker, initialization, fault tolerance, autoresume, the RL rollout bank, the ModelOpt loader and builder, the inference loader, the legacy finetune loop) from `args` to the section. The call sites that used to rewrite checkpoint arguments around a single load or save (checkpoint conversion, the RL reference-weights load, the distillation teacher, the legacy finetune tasks, the inference entry points forcing `exit_on_missing_checkpoint`) pass the values that differ as arguments of that load or save, or set the inference flag on the section, and write nothing to `args`. A checkpoint records the policy that produced it, and a resume reads that record.

No flag is added, renamed or re-typed; no default changes; the parser is identical to `main`.

## Issue tracking

Part of #3554 (args namespace to config container). Same shape as #7591, #7778, #8149 and #8211; converges on the shape Megatron-Bridge uses for its checkpoint config.

## Design

- **Schema.** The three flags that configured checkpointing without being fields (`--dist-ckpt-workers`, `--override-ckpt-iteration`, `--ckpt-drop-redundant-extra-state`) become fields with the same dests and defaults. `use_dist_ckpt` is a read-only property (`ckpt_format != "torch"`); `args.use_dist_ckpt` keeps being maintained for readers outside this PR. A parser snapshot test pins the checkpointing group to `main` (dests, defaults, `nargs`, choices, actions).
- **Validation on the class.** `CheckpointConfig.validate()` holds the own-section checkpoint rules: the three checks that ran at construction (the `__post_init__` is gone, so constructing the class runs no check) and the checks `validate_args` applied to checkpoint arguments alone; it raises only. It is the one set of checkpoint rules for both frameworks: Megatron-Bridge's subclass runs it from its `finalize()` (see Compatibility). `validate_args` calls `checkpoint_config_from_args(args).validate()` after the entry-point `args_defaults` are applied, so the CLI keeps rejecting the same inputs with the same messages (the call site moved: the migrated rules now run together, right after the defaults loop). The cross-section checks follow the convention of #8796: the containers check them from their own sections (`_validate_checkpoint()` on both; the inference container checks the `torch_dcp` / FSDP2 pairing, the one rule its sections can express), and `validate_args` keeps `main`'s inline checks at `main`'s positions, so every CLI entry point is covered whatever container it builds and the Gloo rule runs after `use_distributed_optimizer` is rewritten, as on `main`.
- **Derivations at finalize.** The four flips `validate_args` applies (`exit_on_missing_checkpoint` for a conversion, `async_save` without a persistent worker under a distributed format, `replication_jump` without replication, `load_optim` under `--skip-train`) run inline in the containers' `_finalize()` (the first three through `_derive_checkpoint_policy()`, shared by both containers; the `skip_train` rule in the training container), with the legacy conditions and a warning only when a value changes; `validate_args` keeps its flips, so a CLI run finalizes silently. `set_global_variables` finalizes inference containers too (the checkpoint converters never reach `initialize_megatron`), and `pretrain()` finalizes the registered container before fault-tolerance setup, which captures the save directory and the async mode.
- **One factory.** `checkpoint_config_from_args(args)` replaces the two inline copies; it folds the `--no-*` aliases and the `ckpt_fully_parallel_*` dests and accepts a sparse or Python-built namespace. `project_checkpoint_policy(args, checkpoint, **overrides)` is its inverse for every spelling of the aliased fields (round-trip tested) and builds the arguments a checkpoint persists, with the values of a conversion save in place of the section's.
- **Consumers read the owner; a load or save names what it changes.** `load_checkpoint` takes `load_dir`, `finetune`, `load_optim`, `load_rng` and `ckpt_format` as keyword arguments and `save_checkpoint` takes `save`, `ckpt_format` and `verify_integrity`; omitted means the run's section. The values are resolved into locals and each helper receives the value it reads next to the run-wide section (the base loaders, `generate_state_dict`, the sharded-metadata builder, the GPT-to-hybrid optimizer decision, the argument check, the save's finalize functions); no copy of the section is composed and nothing writes it. `load_dir=None` clears the directory so the pretrained-checkpoint fallback runs (RL's reference weights rely on that classification, which with `--allow-llm-only-checkpoint` adds the LLM-only load metadata); a string names another directory (the distillation teacher). The two derivations `load_checkpoint` applied to `args` in place (the pretrained fallback's `finetune`, `--freeze-all-layers`' `finetune` and `override_ckpt_iteration`) stay local to the load; the primary load records its outcome on the train state (`TrainState.effective_finetune`, not checkpointed, written only by the load `setup_model_and_optimizer` performs through `record_finetune=True`), and the multimodal dataloader resume reads it, with the checkpoint section, instead of `args.finetune`, `args.pretrained_checkpoint` and `args.load`.
- **MSC.** `enable_msc` is a field; the saver reads it from the section. One helper, `setup_multi_storage_client(enable_msc)`, applies the policy to the process-wide flag (enable; disable so a process does not inherit it from an earlier run; fail early when requested without the package; warn once), called by `parse_args` as before and by `initialize_runtime_services` from the section for every entry point, before the tokenizer or any checkpoint path is read, so a native container gets the same early setup as a CLI run. The `--enable-msc` flag keeps its argparse group next to the deprecated `--disable-msc`.
- **Startup, before any container.** Two readers run before a run config exists and build their policy from the arguments: `load_args_from_checkpoint` (`--use-checkpoint-args`) and the ModelOpt auto-detection (`maybe_enable_modelopt`, which decides the model config class the entry point builds; its run-time fallback callers pass the registered section).
- **Persisted policy.** `state_dict['args']` is a copy of the arguments whose checkpoint names are projected from the effective section (byte-identical to the former saved arguments for a CLI run, conversion included), and the saved run config's `checkpoint` section is the effective one. On load, the saved checkpoint section is read right after the rank-0 pass and decides what the checkpoint holds (optimizer state, for the load template and the GLU guard alike; RNG state; the legacy optimizer sharding); the saved arguments remain the fallback for checkpoints written before the run config was saved with them, and for the `args`-less checkpoints Megatron-Bridge writes the section is the only source.
- **Inference.** The same factory, consumers and checks; `InferenceConfigContainer` gets a `_finalize()`; `get_model_for_inference`, the text generation server, the VLM dynamic server and the checkpoint converters set `exit_on_missing_checkpoint` on the section before their load (their policy decision; nothing else in the inference container's twenty-odd other users changes).

## Compatibility

- The parser is identical to `main` (snapshot test over the 64 actions of the checkpointing group).
- `run_config.yaml` gains the three promoted keys under `checkpoint`; a file saved before them loads with their defaults. A checkpoint written by a conversion now records the format and the directory it was written in (`main` recorded the source run's).
- `state_dict['args']` is unchanged for a CLI run, with one documented case: after a pretrained-checkpoint fallback or a `--freeze-all-layers` load, the persisted `finetune` and `override_ckpt_iteration` carry the run's policy (the projection follows the registered section), where `main` persisted the values the load had derived; nothing reads them back from a checkpoint. `load_checkpoint` no longer writes `args.finetune` or `args.override_ckpt_iteration`: the one in-tree reader that needed the effective value after the load, `examples/multimodal/dataloader_resume.py`, reads `TrainState.effective_finetune`; an out-of-tree reader of `args.finetune` after a load sees the run's flag.
- `CheckpointConfig(...)` constructs without checks; code that relied on the constructor to reject `async_strategy`, the nvrx requirement or `verify_integrity` calls `validate()`.
- A save directory without a periodic interval is accepted: `--save` with no `--save-interval` (or `--save-interval 0`) saves at the end of training and on the exit paths only, which is how Megatron-Bridge already reads it. `main` rejected it only because the end-of-training save computed `iteration % save_interval` unguarded; every other save site already treated a falsy interval as "no periodic saves". A negative interval is rejected; `save_retain_interval` requires a positive interval and may not be combined with `most_recent_k` (Bridge's rule, adopted). The retention and `load_main_params_from_ckpt` messages take Bridge's wording, so the shared rule has one message.
- `checkpointing.py` helpers take the value they read, keyword-only where a positional existed: `_load_base_checkpoint(..., *, checkpoint=None, finetune=None)` (the section for the parse-time load), `_load_non_persistent_base_checkpoint` and `_load_global_dist_base_checkpoint` (`checkpoint=`), `_build_sharded_state_dict_metadata(dp_cp_group=None, *, ckpt_format=None)` (no namespace: the optimizer flags come from `cfg.optimizer`, the checkpoint settings from the section), `generate_state_dict(..., *, ckpt_format=None, save=None, verify_integrity=None)`, `check_checkpoint_args(..., ckpt_format=None)`, `_maybe_setup_gpt_to_hybrid_load(..., *, load_optim, saved_save_optim)`; `load_checkpoint(..., *, restore_training_state=False, record_finetune=False, load_dir=_UNSET, finetune=None, load_optim=None, load_rng=None, ckpt_format=None)` and `save_checkpoint(..., *, save=None, ckpt_format=None, verify_integrity=None)`; `get_load_checkpoint_path_by_args` is replaced by `_get_load_checkpoint_path(load_dir, checkpoint)`; `has_modelopt_state(path, *, checkpoint)` and `maybe_enable_modelopt(args, checkpoint=None)`; `TrainState.effective_finetune` (not serialized); `megatron.training.utils.setup_multi_storage_client`. Megatron-Bridge imports `save_tokenizer_assets` only, whose signature is unchanged.
- The two legacy `torch` branches of the ModelOpt loader called `_load_base_checkpoint` without `args` and unpacked three of its four results; they are repaired in passing.
- Megatron-Bridge: its `CheckpointConfig(MTrainCheckpointConfig)` keeps working; the removed `__post_init__` means the three construction checks stop running for Bridge's subclass until its bump PR ends its `finalize()` with `super().validate()`, after the Bridge-only checks. With the save-interval rule above settled on Bridge's reading, the inherited `validate()` accepts everything Bridge accepts; Bridge drops its own copies of the retention and `load_main_params_from_ckpt` rules and its retention tests expect the inherited assertions (the change is prepared on a Bridge branch and verified below).
