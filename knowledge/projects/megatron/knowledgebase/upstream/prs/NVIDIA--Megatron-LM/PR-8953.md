# [Inference] Stop TE attention from reading a strided query or KV-cache slice as dense

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8953) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

`TEDotProductAttention` now passes Transformer Engine (TE) every q, k and v in the layout TE reads it with: only dense tensors and the packed views TE reads correctly go through as they are. Static-batching attention used to hand TE a strided query, or strided KV-cache slices. On TE's fused (cuDNN) backend, the default on Hopper and Blackwell, these were silently read with the wrong strides.

Commits: `0c5e1fc1a` (the fix) and `7736dcebe` (review follow-up: the helper mirrors TE's packed-layout detection exactly; the CPU rule tests move to their own file so the GPU tests run on `main`).

## Bug

TE's `get_qkv_layout` decides how cuDNN reads q, k and v. A q, k or v that is not a view of one packed buffer gets labelled dense in its format (`sbhd_sbhd_sbhd`) without its strides being checked. The only checks are that k and v have proportional strides and that the storage offsets fit. FusedAttention then builds the cuDNN graph with dense strides, not with the tensors' own. This holds in TE 2.20.2 (the CI image), in 2.21.0 and on TE main as of 2026-11-03.

Static batching (the legacy static engine, the VLM and T5 wrappers) reaches this in two ways:
- **Strided query.** This needs no RoPE or q_layernorm, and MHA or MQA per rank. `get_query_key_value_tensors` leaves the query as a strided view of the fused QKV projection, at storage offset 0. `_adjust_key_value_for_inference` then replaces k and v with slices of the separate static KV cache. Both prefill and decode are affected. On H100 (dfw 21202692) the static prefill is off by rel 0.108 with TE's default backend and 0.102 with cuDNN pinned, against bf16 noise of 2e-3. A bare `te.pytorch.DotProductAttention` call with a strided query is off by rel 0.242. With `NVTE_FUSED_ATTN=0`, or a contiguous query, results are correct.
- **Batch smaller than the context's `max_batch_size`.** This affects every model, RoPE or not. k and v are `cache[:seq_end, 0:b]`, strided slices at offset 0, and TE reads them as dense too. The legacy static engine runs at the request count unless CUDA graphs are on. It is reached through `--use-legacy-static-engine` (`examples/inference/advanced/gpt_static_inference.py`), through `StaticInferenceEngine`'s fallback when the dynamic context cannot be built, or by code that drives a `StaticInferenceContext` directly. `tools/run_text_generation_server.py` runs the dynamic engine, and the VLM wrapper sizes its context to the batch, so neither reaches it. On H100 the static prefill of a GQA model at half the context's batch is off by rel 0.756 (0.754 with cuDNN pinned), and an attention-level case reads unwritten (NaN) cache rows. When the batch starts at a non-zero offset, TE cannot classify the layout and copies, so that case is correct.

The same TE rule misreads shared-storage inputs that land in a dense layout. No current Megatron caller reaches these at realistic shapes:
- gated attention (`attention_output_gate`) without RoPE or qk-norm at s · b · groups == 2, where k sits at offset numel(q), so TE takes q for dense and k/v for a packed KV buffer (`sbhd_sb2hd`);
- `key is value` as one strided cache slice;
- a batch-sliced or transposed fused QKV or KV buffer, which TE still takes for `sbh3d`/`sbhd_sbh2d` and reads as dense.

Not affected:
- GQA with 1 < groups < heads (the query reshape copies), RoPE or q_layernorm models at full batch, and training: q, k and v are dense, views of the fused QKV buffer that TE reads as `sbh3d`, or views TE cannot classify and copies itself.
- MLA, which makes q, k and v contiguous before core attention, and dynamic batching, which does not use TE attention.

## Fix

`_dense_unpacked_qkv` in `megatron/core/extensions/transformer_engine.py` runs at the top of `TEDotProductAttention._forward`, so it covers every caller: `Attention`, MLA, cross-attention, prefill and decode, `sbhd`, `bshd` and `thd`.
- It passes through tensors that are already dense.
- It mirrors TE's packed-layout detection (`get_qkv_layout`, `44f31bbe`, unchanged on TE main). q, k and v are taken for one packed buffer when they share a storage, have equal shapes and strides, and sit at offsets 0, h·d, 2·h·d (`sb3hd`) or 0, d, 2·d (`sbh3d`), tried in that order. k and v are taken for one when they share a storage, have equal leading shapes and proportional strides, and sit at h·d or d apart, starting at 0, or at numel(q) when q shares the storage too (`sbhd_sb2hd`, `sbhd_sbh2d`). A detected group is passed through only when every view has the strides of that dense packed buffer (size-1 dims ignored, since cuDNN never steps along them), i.e. when TE's read is correct. Training's fused QKV (MHA) and cross-attention's fused KV pass this way with no copy.
- Every other strided input is made contiguous, the layout TE then reads it with: a tensor outside a packed buffer, including the query beside packed k/v, is read with the dense strides of its own shape.
- Quantized q/k/v are left to TE, which detects their layout from their data, not from the wrappers.
- The check reads strides and data pointers on the host: no sync, no `.item()`. `.contiguous()` is capturable, so the fix is CUDA-graph safe. It adds no flag and does not depend on the TE version.

**Cost.** Copies happen only where TE used to read the wrong data:
- Static inference with a strided query (no RoPE or q_layernorm, MHA or MQA per rank) copies the query: `sq · b · np · hn` elements per layer and step. Decode at hidden 4096, TP 1 and batch 8 copies 64 KiB in bf16 per layer and step. A prefill copies a tensor the size of the query, as a RoPE model's rotation already does there.
- Static inference with a batch below `max_batch_size` copies k and v: `2 · seq_end · b · ng · hn` elements per layer and step. For example, 32 MiB in bf16 at 8 KV groups of 128, b = 4 and 2048 tokens. That is the copy TE already makes when the batch starts at a non-zero offset.
- The cases listed under the bug above copy what they misread (at most q, k and v once).
- Nothing else copies more than before. Training's fused QKV views (MHA, THD), cross-attention's fused KV views and dense inputs pass through. The views TE could not classify and copied in its own fallback (the MQA, GQA and gated splits of training, RoPE's v) are now copied here instead: the same tensors, once. A CPU model of TE 2.20.2's `get_qkv_layout` and the strides cuDNN reads with confirms this over 216 training splits (sbhd and bshd, gated or not): no extra copy anywhere `main` read correctly, and no misread left.
- On FlashAttention, the pre-Hopper default, TE already transposes `sbhd` inputs into new tensors. There the strided query costs one extra copy of its size.

## Tests

Two files next to the attention tests:
- `tests/unit_tests/transformer/test_te_attention_qkv_layout_rule.py` runs on CPU and tests the rule (32 cases):
  - dense inputs, MHA fused QKV views and fused KV views beside a dense query come back as the same objects, not copies (`sbhd`, `bshd`, `thd`);
  - these come back as contiguous copies with equal values, and only the strided tensors among them: MQA/GQA fused splits, a strided query beside separate or fused-KV k/v, strided separate k/v, cache batch slices, q/k sharing a buffer without v, `key is value` as a strided cache slice, gated splits at s · b · groups == 2, and batch-sliced or transposed fused QKV/KV buffers.
- `tests/unit_tests/transformer/test_te_attention_qkv_layout.py` imports only public API, so its GPU cases also run on `main`, where they fail by assertion. `TestStaticTEAttentionStridedInputs` needs 1 GPU and TE. It builds a TE-spec `SelfAttention` (8 heads of 32, bf16, causal, no positional embedding) and runs a static prefill of 2×16 tokens and one decode step. It compares each step with an fp32 attention over the q/k/v Megatron hands its TE wrapper. The bound is rel 1e-2, five times the measured bf16 error. It resets TE's cached backend selection, and failure messages name the backend TE picked. The `cudnn` cases skip if TE has no backend for them (TE raises `ValueError`).
  - `test_strided_query_matches_reference[{default,cudnn}-{mha,mqa}]` checks that the query reaches the wrapper strided (strides `(1536, 768, 96, 1)` and `(640, 320, 32, 1)`). `cudnn` pins `NVTE_FLASH_ATTN=0 NVTE_UNFUSED_ATTN=0`.
  - `test_batch_below_max_batch_size_matches_reference[default|cudnn]` uses GQA, so the query is dense, with a cache built for twice the batch.
  - `test_te_wrapper_strided_query_matches_reference[default|cudnn]` is the repro's standalone case, through Megatron's wrapper.
  - The repro's controls are kept: `test_control_contiguous_query_prefill_matches_reference`, `test_control_strided_query_without_fused_attention` (`NVTE_FUSED_ATTN=0`) and `test_control_te_wrapper_contiguous_query_matches_reference`.
- Determinism: `tests/unit_tests/determinism/kernels/test_te_wrappers.py::TestTEWrappers::test_te_dot_product_attention_strided_query_replays[fused|flash]`. `TEDotProductAttention` with a strided query (a view of `[s, b, h, 2d]`) beside separate k/v replays bit-exactly, forward and backward, under side-stream contention. It must also equal the call with the dense query bit for bit. The test sits under the existing `transformer_engine_wrappers` manifest entry.

GPU results (H100, CI image `mcore_ci_dev:main`, TE 2.20.2):
- With this branch: the 45 GPU and rule cases pass (pdx 7847830); `test_attention_packed_seq.py` passes at 8 GPUs (16/16, pdx 7848637), `test_attention.py` and the TE wrapper replays pass.
- On `main` (pdx 7848637), the same GPU tests fail by assertion: the strided-query prefill by rel 0.107 (MHA) and 0.102 (MQA) with TE's default backend and 0.105 / 0.138 with cuDNN pinned; the batch-below-`max_batch_size` prefill by rel 0.756 / 0.754; the wrapper case; and the `fused` replay's dense-query comparison. The three controls and the `flash` replay pass, and the CPU rule file fails at import (`_dense_unpacked_qkv` is new).

## Notes for reviewers

- **Behaviour change.** Affected static-batching generations change to the correct result, matching `NVTE_FUSED_ATTN=0` or a contiguous query. So would the rare shared-storage cases above. Nothing else changes numerically.
- **Determinism gate.** `transformer_engine.py` is listed in three manifest entries. The new replay covers `transformer_engine_wrappers` and `te_fused_cross_entropy`. The third, `paged_stash_marker_propagation` (test `test_fused_activations.py`), is code this PR does not touch. So the PR needs the `determinism-exempt` label. `tools/check_kernel_determinism_coverage.py --base-ref origin/main --labels determinism-exempt` passes.
- **TE upstream.** The root cause is in TE. The proposed TE fix requires dense strides for q in the `*hd_*2hd`, `*hd_*h2d` and `*hd_*hd_*hd` branches and for k and v in `*hd_*hd_*hd`, falling through to TE's own contiguous fallback otherwise. It is not filed yet. It is not a full replacement for this PR: for a strided query beside packed k/v it falls back to copying all three, where this PR copies only the query, and it still reads a batch-sliced or transposed packed buffer as dense. A complete TE fix would check every tensor's strides against the layout it picks, which is what this PR's rule does on Megatron's side. Either way, the copies here make TE's fallback a no-op, so nothing is copied twice. This wrapper rule can be dropped once Megatron's minimum TE has a complete fix.
