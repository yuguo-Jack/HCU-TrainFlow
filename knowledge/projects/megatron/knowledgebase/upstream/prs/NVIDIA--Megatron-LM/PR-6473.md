# What does this PR do?

Add Bebop's end-to-end total-variation objective as an alternative MTP training loss.

Set `mtp_loss_type=e2e_tv` with `mtp_detach_heads=True` to enable it. The implementation projects the detached target distribution once, computes TP-aware full-vocabulary TV distance for each draft step, applies the analytical draft-only backward, masks incomplete packed-sequence prediction chains, and accounts for the additional target projection in model FLOPs. The existing cross-entropy objective remains the default.

This is an online MTP objective and is distinct from the offline cached-logits KD workflow proposed in #6023.

- claude · comment · 2026-08-30T14:21:40Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/6473#issuecomment-5469231065)

Light review — read the full diff plus the testing and linting skills. The kernels, TP collectives, and the analytical backward all look correct to me, and the test coverage is unusually thorough (independent oracles for both Eq. 10 and Eq. 13, TP-sharded vocab, THD boundaries, contiguous CP2, CUDA-graph safety, dispatch fallbacks). One gap worth closing:

**`calculate_per_token_loss=True` is untested for the new objective**

`_process_mtp_e2e_tv_loss` has a per-token normalization branch (`megatron/core/transformer/multi_token_prediction.py:1809-1815`) that no test exercises — every test in `test_mtp_tv_loss.py` leaves `calculate_per_token_loss` at its default `False`. That branch is genuinely different code, not a cosmetic variation: it multiplies by `original_num_tokens / num_tokens` instead of dividing by `num_tokens`, and it also flips what `save_loss_to_tracker` accumulates (raw sums plus token counts vs. pre-normalized values). The cross-entropy path documents that `finalize_model_grads` later divides by the main loss’s `total_num_tokens`, so an error in this factor would silently mis-scale MTP gradients relative to the main loss rather than fail loudly.

Suggest parametrizing the existing alignment test, which already builds a full native reference to compare against:

```python
@pytest.mark.parametrize("calculate_per_token_loss", [False, True])
def test_process_mtp_e2e_tv_matches_native_alignment_and_gradient(calculate_per_token_loss):
    config = _make_tv_config(mtp_num_layers, hidden_size)
    config.calculate_per_token_loss = calculate_per_token_loss
    ...
    if calculate_per_token_loss:
        (reference_loss * chain_mask * (loss_mask.sum() / chain_mask.sum())).sum().backward()
    else:
        (reference_loss * chain_mask).sum().div(chain_mask.sum()).backward()
```

I also left one advisory inline comment about a newly added direct `parallel_state.get_data_parallel_group()` read, per the repo guidance on Megatron Core process groups. Neither item blocks the PR.
