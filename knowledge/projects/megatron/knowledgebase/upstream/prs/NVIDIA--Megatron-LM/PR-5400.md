# fix(optimizer): route GDN in_proj to Adam under Muon

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/5400) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

## Summary

Routes the shared GatedDeltaNet/GatedDeltaNet2 `in_proj` weight to the scalar optimizer instead of Muon by setting the existing `param.use_muon = False` marker.

## Why

`in_proj` is a heterogeneous fused matrix containing q, k, v, convolution, gate, and beta projections. Orthogonalizing the whole matrix as one 2D block is not meaningful. `out_proj` remains on Muon.

This addresses the open routing question in #2885 without adding another optimizer-group mechanism. Current `main` already consumes `use_muon=False` in `_is_muon_excluded`, so the original generic `skip_orthogonalization` change is no longer needed; this PR now only tags the GDN parameter at its source.

## Change

- Set `self.in_proj.weight.use_muon = False` in `_GDNBase`, covering both GDN and GDN2.
- Extend the existing parameterized constructor test to assert that the fused input projection is excluded from Muon.
