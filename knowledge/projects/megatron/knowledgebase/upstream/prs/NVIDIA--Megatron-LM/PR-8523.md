# Require positional layer inputs for PyTorch full-backward hooks

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8523) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

## Why

PyTorch's `register_full_backward_hook` includes only positional inputs in `grad_input`; keyword inputs are ignored. Calling a layer with `hidden_states=...` therefore prevents the hook from tracking that activation's input gradient, even when the tensor requires gradients. See the [PyTorch hook documentation](https://docs.pytorch.org/docs/2.14/generated/torch.nn.Module.html#torch.nn.Module.register_full_backward_hook).

This PR require `hidden_states` to be positional in TransformerLayer (including MoETransformerLayer) and MambaLayer so MFSDP (#7902) can use standard PyTorch full-backward hooks to detect when the backward is complete. 

## Changes

- Enforce `layer(hidden_states, ...)` and update layer calls in TransformerBlock, HybridStack, full recomputation, MTP, hybrid wrappers, shortcut layers, and fine-grained execution. TransformerBlock's public calling convention remains unchanged.
- Update CUDA graph argument handling for positional layer activations and remove obsolete layer-specific keyword fallbacks. The shared graph manager retains keyword support for block/model callers.
- Add tests asserting non-null activation gradients in layer backward hooks for eager, uniform-recompute, and block-recompute execution, plus tests rejecting keyword activations.

Downstream callers of TransformerLayer and MambaLayer must pass `hidden_states` positionally.

### [P1] Migrate local inference CUDA-graph consumers to positional activations

**Failure:** With `cuda_graph_impl="local"`, active inference, and block-scoped graphs, the updated [GPT decoder call](https://github.com/NVIDIA/Megatron-LM/blob/e9caeb460cf4456f41276103f8e1254526482605/megatron/core/models/gpt/gpt_model.py#L679-L690) passes the activation in `args[0]`, but [TransformerBlock.__call__](https://github.com/NVIDIA/Megatron-LM/blob/e9caeb460cf4456f41276103f8e1254526482605/megatron/core/transformer/transformer_block.py#L513-L530) still reads `kwargs['hidden_states']`. A graph-enabled forward therefore raises `KeyError: 'hidden_states'` instead of capturing/replaying the block. This affects ordinary tensors as well as `WrappedTensor` inputs.

The independently changed [per-layer call](https://github.com/NVIDIA/Megatron-LM/blob/e9caeb460cf4456f41276103f8e1254526482605/megatron/core/transformer/transformer_block.py#L751-L766) also reaches keyword-only assumptions in [CudaGraphManager.__call__](https://github.com/NVIDIA/Megatron-LM/blob/e9caeb460cf4456f41276103f8e1254526482605/megatron/core/transformer/cuda_graphs.py#L2099-L2158): static inference fails while constructing its cache key, and multi-layer dynamic inference fails while comparing/reusing the preceding graph's activation buffer. Thus fixing only the block's first lookup leaves layer-scoped inference broken.

**Correction:** Keep activations positional through module execution. Update the block's unwrap branch and the manager's cache-key, recorded-input comparison, and buffer-replacement logic together. Suggested targeted replacements, to verify before adopting:

```python
# TransformerBlock.__call__: replace the hidden_states keyword assignment.
if isinstance(args[0], WrappedTensor):
    args = (args[0].unwrap(), *args[1:])
return super().__call__(*args, **kwargs)[0]
```

```python
# CudaGraphManager.__call__: immediately after computing is_inference_mode.
if is_inference_mode:
    hidden_states = args[0] if args else kwargs["hidden_states"]

# Static cache-key branch: replace the keyword activation lookup.
batch_size = hidden_states.shape[0]

# Previous-runner predicate: replace its two activation metadata lookups.
and ArgMetadata(r[2][0] if r[2] else r[3]["hidden_states"])
== ArgMetadata(hidden_states)

# Previous-buffer replacement: replace the unconditional local_kwargs update.
if args:
    local_args = (previous_runner[0].fwd_graph_outputs[0], *args[1:])
else:
    local_kwargs = dict(kwargs)
    local_kwargs["hidden_states"] = previous_runner[0].fwd_graph_outputs[0]
```

The invariant is that graph bookkeeping reads and replaces the same activation argument that module execution receives, without supplying it twice. Preserve keyword-input support in the shared manager: [HybridStack's eager layer calls](https://github.com/NVIDIA/Megatron-LM/blob/e9caeb460cf4456f41276103f8e1254526482605/megatron/core/models/hybrid/hybrid_block.py#L753-L799) still use keywords. Also retain `WrappedTensor.unwrap()`, trailing positional arguments, the block's output-tuple unwrapping, and preceding-layer buffer reuse.

**Acceptance (proposed):** Exercise static decode and two-layer dynamic capture/replay with both block and layer scopes; each must return the expected output shape without argument errors. For block scope, check raw and wrapped activations. Retain both scope cases of [test_padding_logits_are_zero_after_cuda_graph_replay](https://github.com/NVIDIA/Megatron-LM/blob/e9caeb460cf4456f41276103f8e1254526482605/tests/unit_tests/models/test_gpt_model.py#L676-L787), including its assertion that every padding-logit row is zero. Check that keyword-driven HybridStack inference still captures/replays and that dynamic layer graphs continue reusing the preceding graph's output buffer.

### [P2] Make the new regression detect missing activation-gradient hooks

**Failure:** The new [weight-release test](https://github.com/NVIDIA/Megatron-LM/blob/e9caeb460cf4456f41276103f8e1254526482605/tests/unit_tests/distributed/mfsdp_v2/test_mcore_dense.py#L653-L696) leaves every layer parameter trainable. In this standalone tree, [register_post_backward_hook](https://github.com/NVIDIA/Megatron-LM/blob/e9caeb460cf4456f41276103f8e1254526482605/megatron/core/distributed/fsdp/src/megatron_fsdp/experimental/module.py#L181-L229) selects parameter post-accumulation callbacks for those layers, not the activation full-backward completion hook. Those callbacks already call [post_backward, which releases the weights](https://github.com/NVIDIA/Megatron-LM/blob/e9caeb460cf4456f41276103f8e1254526482605/megatron/core/distributed/fsdp/src/megatron_fsdp/experimental/module.py#L470-L475). Consequently, the allocation check does not establish that reverting the positional layer calls is detected. The independently changed full-recompute path has no equivalent hook-contract assertion either.

**Correction:** Keep the existing trainable-layer MFSDP allocation test, and add a small hook-contract test using the same two-layer configuration and a differentiable input. Parameterize it over eager execution and full recompute (`block` and `uniform`, with `recompute_num_layers=1`). The essential instrumentation on the ordinary, unwrapped block is:

```python
seen = []

def check_input_gradient(_module, grad_input, _grad_output):
    assert grad_input and grad_input[0] is not None
    seen.append(True)

for layer in block.layers:
    layer.register_full_backward_hook(check_input_gradient)

block(x, attention_mask=None).float().square().mean().backward()
assert seen == [True] * config.num_layers
```

Keep `x.requires_grad=True`. This separately enforces the intended positional-input invariant without changing MFSDP's lifecycle implementation or replacing the existing allocation check.

**Acceptance (proposed):** All three execution modes must observe two non-null layer input gradients. Restoring only the old eager keyword call must fail the eager hook assertion; restoring only the shared-recompute keyword call must fail the recompute assertions. The existing MFSDP test must retain its pre-final-cleanup `is_allocated` checks and `released == [True]` assertion.

This affects both CP-layout parameterizations. The [base helper](https://github.com/NVIDIA/Megatron-LM/blob/e3f528380c197e8811fb68064d9ef3acf59fd3c6/megatron/core/recompute.py#L115-L156) supplied that activation by keyword.

**Correction:** Keep the positional production call. In the linked test's `record_layer_residuals`, replace the accumulator assignment with:

accumulator = (args[0] if args else kwargs["hidden_states"]).detach().clone()

The invariant is that the observer snapshots the actual layer input under either convention. Do not switch the hook unconditionally to `args[0]`: [HybridStack's non-recompute branch](https://github.com/NVIDIA/Megatron-LM/blob/e9caeb460cf4456f41276103f8e1254526482605/megatron/core/models/hybrid/hybrid_block.py#L753-L799) still passes it by keyword. > I'm not super stoked to make things more error-prone across the board to benefit just MFSDP.

The positional-input convention also benefits other backward-hook consumers. [`DataGradLogger`](https://github.com/NVIDIA/Megatron-LM/blob/a0ef64615cc3d2574ffbaac70f324ee365f5ed34/megatron/training/dgrad\_logging.py\#L91) is another example in Megatron: it misses input gradients when activations are passed by keyword. The call sites already pass activations positionally to the modules it hooks.

PyTorch [explicitly documents that `register_full_backward_hook` ignores keyword arguments](https://docs.pytorch.org/docs/2.15/generated/torch.nn.Module.html\#torch.nn.Module.register\_full\_backward\_hook). I don't think there's a fundamental reason that it can't take kwargs -- more like [Hyrum’s Law](https://www.hyrumslaw.com/) to me. I'm happy to send a PR to PyTorch to add a with_kwargs knob. 

> How much complexity would that add?

I haven’t prototyped it yet, but it might be manageable. Torch FSDP2 provides a reference: it wraps gradient-requiring tensors from both positional and keyword arguments in a custom autograd function, whose backward calls `post_backward()`. The entry point is [here](https://github.com/pytorch/pytorch/blob/main/torch/distributed/fsdp/\_fully\_shard/\_fsdp\_param\_group.py\#L1164-L1180).
