# Sum the GatedDeltaNet out_norm gradient across TP without sequence parallelism

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8319) · state: closed · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?
Sum the gradient of the GatedDeltaNet output norm weight across tensor-parallel ranks when sequence parallelism is off, so every TP rank gets the same, full-head gradient for this replicated weight.

## Issue tracking

Linked issue: Fixes #8317

Companion issue in Megatron-Bridge: https://github.com/NVIDIA-NeMo/Megatron-Bridge/issues/6533

### Cause

`self.out_norm` in `_GDNBase.__init__` (`megatron/core/ssm/gated_delta_net/common.py`) has `hidden_size=value_head_dim` and is replicated on every TP rank, while the value heads it scales are split across TP ranks. Each rank's backward therefore only accumulates the gradient contribution of its own heads. `_allreduce_non_tensor_model_parallel_grads` sums a replicated weight across TP only when it is marked `sequence_parallel` (and SP is on) or is a `q_layernorm`/`k_layernorm` by name. With SP off the GDN `out_norm` matches neither, so each TP rank applies a different partial gradient and the replicated copies drift apart. The loss and the global grad norm do not show it.

### Fix

- `common.py`: when `tp_size > 1` and sequence parallelism is off, mark the `out_norm` parameters with `sum_gradients_across_tp_domain = True` (the sum counterpart of the existing `average_gradients_across_tp_domain`).
- `finalize_model_grads.py`: `_allreduce_non_tensor_model_parallel_grads` also SUM-reduces params carrying that marker, in the same branch as the sequence-parallel and qk_layernorm cases.

`GatedDeltaNet` and `GatedDeltaNet2` both build `out_norm` in the shared base class, so both are covered. `GatedDeltaProduct`'s gated norm is built over the local `d_inner` slice and marked `tensor_model_parallel`, so it does not have this problem. With SP on nothing changes (the param was already summed through the `sequence_parallel` path, and it is not marked). The reduction runs at the same point and on the same `main_grad` buffers as the existing SP layernorm reduction, so the distributed-optimizer, overlapped grad reduce and Megatron-FSDP branches are handled the same way they already are for SP layernorms.

### Test

New `test_gdn_out_norm_grad_is_summed_across_tp` in `tests/unit_tests/ssm/test_gated_delta_net_parallel.py`, parametrized over variant (`gated_delta_net`, `gdn2`), TP 2/4 and SP off/on. It builds one GDN layer from the module spec, wraps it in megatron-core DDP, runs forward/backward on the same input on every rank, records each rank's partial `out_norm` `main_grad`, calls `finalize_model_grads`, and asserts that the result is bitwise identical across TP ranks and equal to the sum of the partials over the TP group (averaged over DP).

Run with `torchrun --nproc_per_node 8 -m pytest` on 8x B200 (torch 2.14.1, Transformer Engine 2.18.0, flash-linear-attention 0.4.2; the GDN2 cases skip because this FLA version has no GDN2 support):
