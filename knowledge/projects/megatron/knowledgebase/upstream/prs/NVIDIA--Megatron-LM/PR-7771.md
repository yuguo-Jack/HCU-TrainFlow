# fix(moe): disable HybridEP custom allgather to avoid silent routing corruption

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7771) · state: closed · merged: True

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Makes HybridEP exchange routing information through NCCL instead of its own custom kernel. The custom kernel silently corrupts MoE token routing whenever one GPU is more than about 20 seconds late.

## The problem

In an MoE layer, each GPU decides which experts each of its tokens goes to (the "routing map"). Before HybridEP can send tokens to the GPUs that own those experts, **every GPU needs every other GPU's routing map**. HybridEP collects them with an allgather.

By default, when all GPUs of the expert-parallel group sit in one NVLink domain (e.g. a GB200/GB300 NVL72 rack), HybridEP uses its own allgather kernel instead of NCCL. The kernel works like this:

1. Each GPU writes its routing map into a shared buffer on every other GPU.
2. Each GPU then waits until all the others have signalled "done writing".
3. Each GPU reads the buffer and decides where tokens go.

Step 2 has a time limit. If one GPU has not arrived after about 20 seconds, the others print a warning and **carry on anyway**:

```
HYBRID-EP ALLGATHER TIMEOUT:SM 19 [0]:expecting 416 got 415
```

(`got 415` of `416` means one GPU had not arrived.) At that point the buffer still holds the late GPU's routing map from the **previous** MoE layer. The other GPUs read it as if it were current, so they send and receive the wrong tokens. Nothing fails, and training continues with wrong numbers.

Any one-off stall of more than about 20 seconds on a single GPU is enough to trigger it (real cases below).

With `enable_custom_allgather=False`, HybridEP uses NCCL's allgather instead. NCCL waits for the late GPU however long it takes, so the data is always current.

## How it showed up

DeepSeek-V3 training on 256 GB300 GPUs: runs that should have been bit-identical occasionally diverged at one step. In each of those runs the log contains this timeout warning (60 lines) at exactly the step that diverged. Runs without the warning never diverged.

A normal training step here takes about 11 s. The timeout hit in the two situations below, which are ordinary in large jobs:

| Case | When | What the log shows |
|---|---|---|
| First step | step 1 | Step 1 took 543 s. The timeout lines appear while the GPUs are compiling kernels on first use (each GPU compiles its own fused MoE GEMM kernels, so they finish at different times). |
| Degraded run | step 17 | Every step took 99–260 s instead of ~11 s (slow job, cause not diagnosed). The timeout fired at step 17 of 50. |

All GPUs in the expert-parallel group must reach the same dispatch within ~20 s of each other. NCCL collectives tolerate a late GPU for the full watchdog timeout, typically 10–60 minutes. Anything that delays one GPU by 20 s to several minutes is therefore harmless with NCCL but silently corrupts data with the custom kernel. Examples are first-step compilation, CUDA graph capture, checkpoint saving, a filesystem stall, or a slow node.

## Reproducing it (one node, 4 GPUs, about a minute)

The script below runs two MoE "layers" through HybridEP on 4 GPUs. It records the correct result for layer 1, then runs layer 0 and layer 1 again, but this time GPU 1 waits 30 seconds before layer 1. Each GPU compares what it got to the correct result.

```python
# torchrun --nproc_per_node=4 hybridep_allgather_timeout_repro.py --custom-allgather 1   # HybridEP's own kernel
# torchrun --nproc_per_node=4 hybridep_allgather_timeout_repro.py --custom-allgather 0   # NCCL (this PR)
import argparse, os, time

import deep_ep
import torch
import torch.distributed as dist

p = argparse.ArgumentParser()
p.add_argument("--custom-allgather", type=int, default=1)
p.add_argument("--stall-s", type=float, default=30)
a = p.parse_args()

rank, local = int(os.environ["RANK"]), int(os.environ["LOCAL_RANK"])
torch.cuda.set_device(local)
dist.init_process_group("nccl", device_id=torch.device("cuda", local))
world = dist.get_world_size()
tokens, hidden, local_experts, topk = 1024, 1024, 8, 8
buf = deep_ep.HybridEPBuffer(
    group=dist.new_group(list(range(world))), hidden_dim=hidden, max_num_of_tokens_per_rank=tokens,
    num_local_experts=local_experts, use_fp8=False, enable_custom_allgather=bool(a.custom_allgather),
)


def layer(seed):  # one MoE layer: random tokens, each routed to `topk` random experts
    g = torch.Generator(device="cuda").manual_seed(seed * 1000 + rank)
    x = torch.randn(tokens, hidden, generator=g, device="cuda", dtype=torch.bfloat16)
    idx = torch.rand(tokens, local_experts * world, generator=g, device="cuda").topk(topk, dim=1).indices
    return x, torch.zeros(tokens, local_experts * world, dtype=torch.bool, device="cuda").scatter_(1, idx, True)


def tokens_per_expert(x, routing_map):  # how many tokens this GPU's experts receive
    return buf.dispatch_with_permute(hidden=x, routing_map=routing_map, pad_multiple=32)[3].tolist()


layer0, layer1 = layer(0), layer(1)
expected = tokens_per_expert(*layer1)  # correct answer for layer 1 (all GPUs on time)
tokens_per_expert(*layer0)             # run layer 0 ...
if rank == 1:
    time.sleep(a.stall_s)              # ... then GPU 1 is 30 s late for layer 1
got = tokens_per_expert(*layer1)
print(f"rank {rank}: custom_allgather={a.custom_allgather} -> {'CORRUPTED' if got != expected else 'ok'}", flush=True)
dist.destroy_process_group()
```

Result on GB300 (DeepEP 1.2.1+17cfb81):

```
--custom-allgather 1   (HybridEP's own kernel, the current default)
  HYBRID-EP ALLGATHER TIMEOUT ... expecting 12 got 11      <- printed by GPUs 0, 2, 3
  rank 0: CORRUPTED
  rank 1: ok                                               <- the late GPU itself
  rank 2: CORRUPTED
  rank 3: CORRUPTED

--custom-allgather 0   (NCCL, this PR)
  rank 0-3: ok
```

With a 5 s delay instead of 30 s, both settings give `ok`: the problem only appears once the delay exceeds the kernel's time limit. Two nodes over multi-node NVLink with production-sized tensors behave the same way.

## The change

`init_hybrid_ep_buffer` now passes `enable_custom_allgather=False` (only when the installed DeepEP accepts that argument). HybridEP then takes the path it already uses for multi-node groups (`executor.cu`: `if (config.num_of_nodes > 1 || !enable_custom_allgather)` → `torch.distributed.all_gather_into_tensor`).

### Performance

Only the routing-map gather moves to NCCL: one boolean `[tokens, num_experts]` tensor per rank per dispatch. Token data still goes through HybridEP's own dispatch and combine kernels. According to DeepEP's docs, the custom kernel exists to avoid "copying from NCCL's internal buffer to PyTorch tensors".

In end-to-end DeepSeek-V3 runs (256 GB300, MXFP8, 50 steps), the fastest steady-state step was the same with the custom allgather on and off:

| custom allgather | runs | fastest step (ms) |
|---|---|---|
| on (current default) | 3 | 10875 / 10877 / 10881 |
| off (this PR) | 2 | 10868 / 10869 |

These were not dedicated A/B benchmarks. The cluster was noisy (median steps varied widely between runs), and the "off" runs also carried an unrelated debugging patch. The result shows no visible cost at this scale, not a precise number.

## Where the real fix belongs

This PR is a mitigation. The bug itself is in DeepEP:

```
where the bug lives                         fix layer
─────────────────────────────────────────   ────────────────────────────
DeepEP  csrc/hybrid_ep/extension/
        allgather.cu:83-86
          if (clock64()-s > 2*TIMEOUT) {
            printf("...TIMEOUT...");
            break;          ← ROOT CAUSE      ★ fundamental fix (DeepEP)
          }                                     fail loudly, never continue
            │
            ▼ stale routing rows used silently
MCore   fused_a2a.py  init_hybrid_ep_buffer   ◇ mitigation (this PR)
          enable_custom_allgather=False          avoid the path; revert later
            │
            ▼
Megatron-Bridge / users                       nothing needed
```

The DeepEP kernel should stop with an error (e.g. `__trap()`) instead of `break`. A late GPU would then crash the job, the same way a NCCL watchdog timeout does, instead of silently corrupting it. Once a DeepEP release with that behaviour is the minimum supported version, this change can be reverted to get the custom kernel back.
