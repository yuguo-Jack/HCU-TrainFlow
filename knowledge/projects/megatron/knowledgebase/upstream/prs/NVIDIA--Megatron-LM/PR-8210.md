# Add Mixture-of-Kittens MoE backend on main

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8210) · state: open · merged: False

## Original PR description

## What does this PR do?

Enable `moe_megakernel_backend=mok` on main. MCore supplies routing and owns the expert parameters, optimizer state, and checkpoints; MoK executes dispatch, routed/shared experts, and combine.

Ports #6572 and #7289, building on the earlier main adaptation in #7695. Related to #5795 and #7756. Uses the MoK revision already installed by #7696.

- Support BF16 and native MXFP8 routed weights, with BF16 shared experts and existing grouped-weight layouts.
- Preserve parameter aliases and their MCore/TE attributes; refresh derived views after device/dtype conversion and checkpoint loading.
- Forward packed-sequence metadata and hash-routing inputs, and use main's precision-aware whole-MoE recomputation.
- Keep optional imports lazy and reject unsupported configurations. Initial support is TP=1/ETP=1 with fused shared experts. A native shared-expert fallback for TP>1 and the shared-output gate from #7391 are follow-ups; the pinned MoK API has neither a routed-only mode nor the gate argument.

File: `megatron/core/transformer/moe/megakernel/mok/backend.py` · line 60

The GEMM accumulator is FP32 in both cases. With FP32 `main_grad`, it stays FP32 through the reduction-store. With BF16 `main_grad`, each contribution is rounded to BF16 before the BF16 reduction-store, so persistent accumulation is BF16. The shared weight dtype does not select this; `main_grad.dtype` does. The pinned API also requires shared/routed main-grad buffers to have the same dtype. Documented this from the [kernel epilogue](https://github.com/QiZhangNV/mixture-of-kittens/blob/a2ad2d0ce2366c1817d15498cdbaf8ead5966117/csrc/megakernel/grouped_gemm.cuh#L446).

The cache includes converted MXFP8 scale buffers. Payloads still alias TE storage; after an optimizer update/parameter sync, the scale values change, so their MOK layout must be refreshed on the first microbatch. This happens in place to preserve descriptor addresses, and later microbatches reuse it. It does not requantize or copy the FP8 weight payload. Added this explanation in the method.
