# [feat] Support multi-layer MTP with EP overlap

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7954) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

## What does this PR do?

Allow multiple independent MTP depths to use the existing combined 1F1B expert-parallel overlap schedule. Each intermediate depth output feeds both its prediction head and the following depth; store a detached head branch and merge its gradient at the owning schedule node so the final-norm graph is traversed once. Without this boundary, a two-depth backward attempts to traverse an already-freed graph.

For HybridModel, expand each depth's nested HybridStack into its logical schedule units. Apply embedding/projection at the first unit and final normalization at the last unit, including depths with multiple groups and dense tails. Restore the original token IDs and masks before model loss postprocessing, and honor mtp_detach_heads at the backbone boundary. Prediction heads remain in postprocessing and the existing forward/backward interleaving loop is unchanged.

The ordinary overlap restrictions remain. Hidden State Mixing and shared-layer reuse across multiple depths require different schedules and remain explicitly rejected; a single repeated depth remains accepted.

## Validation

Validated on NVIDIA GB200 with PyTorch `2.14.0a0+4fdf77b940.nv26.08`, CUDA 13.4 and Transformer Engine `2.20.2+6ea2a74a`.

- **Passed on every rank of four GPUs:** 68 hybrid/configuration/gradient cases, including depths 1/2/4, grouped and ungrouped depths, dense tails, padding/conditioning masks, shared embedding/output gradients and precision-context checks.
- **Passed on every rank of four GPUs:** 12 existing GPT chunk-overlap cases in BF16/all-to-all, covering depths 0/1/2/4 and unequal forward/backward chunk sizes.
- **Passed:** PP=2, VPP=2, EP=2 training with two MTP depths. Both overlap-on and overlap-off runs completed; an ABBA comparison ran 20 iterations per run, 80 total. Losses and gradients remained finite and the trajectories agreed closely.
- **Passed:** the 12 float64 branch-gradient regressions with real PyTorch. Reverting the intermediate-depth detach reproduces a second-backward error at depth 2.
- **Passed:** required Black/isort/Pylint/Ruff checks, Python parsing, whitespace checks and the kernel determinism coverage gate. Mypy remains advisory and reports optional-dependency/type findings in the lightweight lint environment.

GPU testing caught an obsolete parser rejection of groups inside MTP patterns; this PR removes it and adds physical-layer-count and invalid-group regression coverage. The shared BF16 weight is checked with both a relative L2 bound and an elementwise bound accounting for accumulation rounding. The main and auxiliary objectives have comparable scales in the GPU comparison.

## Performance experiments

These are synthetic proxies, not production-throughput claims. Model forward/backward and EP communication were timed with BF16 parameters and FP32 gradient accumulation; optimizer and DP reduction time are excluded from these microbenchmarks. Each configuration was checked against eager losses and parameter gradients before timing. Two rounds reverse mode order; the table reports pooled sample medians.

| Configuration | MTP depths | Eager (ms) | 1F1B overlap (ms) |
| --- | ---: | ---: | ---: |
| 4 GPUs, all-to-all, H=1024, S=1024, 8 microbatches | 2 | 348.3 | 404.2 |
| Same, four MTP depths | 4 | 489.4 | 552.3 |
| 8 GPUs / 2 nodes, all-to-all, H=2048, S=2048, 4 microbatches | 2 | 168.4 | 194.8 |
| Same, four MTP depths | 4 | 242.8 | 271.1 |
| 4 GPUs, NCCL EP flex dispatcher, H=1024, S=1024, 8 microbatches | 2 | 296.3 | 338.4 |
| 4 GPUs, Mamba+attention+MoE groups, all-to-all, H=1024, S=1024, 8 microbatches | 2 | 603.7 | 674.8 |

All models have four backbone groups, 16 experts, top-k 2, vocab size 8192 and microbatch size 1. Attention/MoE proxies use `[*E]`; the mixed proxy uses `[M*E]` in both backbone and MTP. Both main and auxiliary losses and every parameter gradient were checked; maximum relative per-parameter gradient L2 error across these successful configurations was below 0.9%.

Changing the dispatcher to NCCL EP reduced the two-depth overlap path by about 16%, but eager NCCL EP remained faster. High-priority communication, delayed weight gradients and fused permutation did not yield a consistent net overlap win in these configurations. Delayed-gradient comparisons use Megatron DDP's FP32 accumulation buffers; standalone `.grad` accumulation was not a valid setup for that option and its exploratory timings are excluded.

The full PP=2/VPP=2 training ABBA comparison was effectively flat after dropping the first five iterations of each run: 333.55 ms median without overlap and 333.60 ms with overlap. A diagnostic trace showed many small collectives and substantial host/launch overhead; profiling was kept separate from the final timings. Process-level memory readings are not reported because repeated DDP model construction retained hook state, making those readings unsuitable as per-model memory estimates.

This PR enables multi-depth overlap but does not claim a general speedup. No performance defaults are changed. FP8, CUDA graphs and FSDP were not covered by this validation.
