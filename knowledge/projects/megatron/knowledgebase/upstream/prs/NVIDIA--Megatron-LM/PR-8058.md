# Resolve inference process groups at one warned boundary

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8058) · state: open · merged: False

## Original PR description

Depends on #8049 (and #6293). Please review the diff from #8049's head: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/64aea4dcb...yx/pstate-c-inference-warnings).

**Why.** Inference reaches the global process groups in several places, all silently:

- `InferenceConfig.resolve_pg_collection` ignores the groups the model was built with.
- `DynamicInferenceContext`, `TextGenerationController` and the context that `StaticInferenceEngine` builds each derive their own groups or sizes from global state.
- The pipeline helpers in `communication_utils` use the global pipeline group when `pp_group` is `None`.

A model on its own grid can therefore run inference on another model's groups, and nothing tells the caller.

**What.**
- `resolve_pg_collection(model=None)` returns the configured collection, else the model's when it sets every group inference reads (`tp`, `pp`, `dp`, `mp`, `ep`), else warns once with `ProcessGroupFallbackWarning` (deprecated in 0.21, removed in 0.23) and builds only those groups through `resolve_process_groups`.
- The dynamic context, wrapper, controller and both engines share that collection.
- Each pipeline helper warns once when called without `pp_group`; the fallback itself is unchanged.
- Global reads: 183 → 178.

**Tests.** A new test file covers one warning per fallback, explicit groups under a patch that makes every global read raise, and a TP=2 model on a TP=1 global grid through the static engine. 9 of its 10 tests fail on #8049's head; all pass on 4 GPUs. Existing inference suites match #8049's head.

**Compatibility.** Standard-grid groups are unchanged. Callers that pass no groups get one warning per fallback.

Part of #6307.
