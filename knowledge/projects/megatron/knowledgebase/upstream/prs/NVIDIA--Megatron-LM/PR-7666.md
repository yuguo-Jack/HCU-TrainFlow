# What does this PR do?

Improve GDP decode inference on GB200 by reducing redundant recurrent-path work and avoiding repeated transposed-weight copies in the batch-invariant Triton TE GEMM.

## Changes

- Compute GDP decay only for the first Householder update.
- Zero padding outputs inside the recurrent kernel, removing a separate masked_fill operation.
- Prefetch recurrent inputs for multi-token speculative decode.
- Handle noncontiguous speculative decode outputs and projection padding.
- Pass transposed weights directly to the stride-aware Triton GEMM without copying them on every forward.
- Add bit-exact, CUDA-graph, and strided-weight tests, plus a reproducible GDP kernel benchmark.

## Performance

Measurements use one GB200, batch size 32, BF16 inputs, and FP32 recurrent state.

### GB200 GDP decode performance

The isolated recurrent-kernel benchmark compares the original main (80e5f8a98) with this PR (bb8ee6044). It uses FP32 recurrent state and 12 paired CUDA-graph runs per case.

| Case | Baseline p50 | Optimized p50 | Speedup |
| --- | --- | --- | --- |
| B=32, S=1 | 23.721 µs | 19.467 µs |  1.219× | 
| B=32, S=4 | 81.576 µs | 67.462 µs | 1.209× |

For the complete GDP mixer and decode step, unmodified main fails before timing in the global batch-invariant configuration. Their baseline is original main with only the runtime fixes needed to handle padded projection rows and non-contiguous speculative-decode output. The candidate is the full PR. Measurements use a fixed three-layer model, one GB200 per paired experiment, CUDA graphs, and FP32 recurrent state.

| Case | Measurement | Baseline p50 | Optimized p50 | Speedup |
| --- | --- | --- | --- | --- |
| B=32, S=1 | Decode step | 1628.433 µs | 1496.369 µs |  1.088× | 
| B=32, S=1 | GDP mixer | 260.206 µs | 104.170 µs | 2.498× |
| B=32, S=4 | Decode step | 4794.273 µs | 4126.704 µs | 1.162× |
| B=32, S=4 | GDP mixer | 301.662 µs | 151.673 µs | 1.989× |

The mixer results use four paired runs per case. The complete-step results use 24 paired runs for S=1 and eight for S=4; generated-token hashes matched across the paired complete-step runs.

The mixer and complete-step results measure the combined effect of the PR changes beyond the two runtime fixes. They should not be attributed solely to removal of the Triton TE weight copy. These measurements exercise the global batch-invariant Triton path; they do not measure the default te_native path.
