# What does this PR do?

Fixes refit load balancing when all source replicas of a parameter share one DP group, which is the case for training with TP=1 and PP=1.

`select_src_metadata_balanced()` picks the source replica for each destination rank by round-robin over source DP groups and then over the replicas in the chosen group (`_round_robin_dp`). A fast path returned `src_meta_list[0]` whenever every candidate belonged to a single DP group, on the assumption that no balancing was needed. With TP=1 and PP=1 every replica of a parameter has the same DP group, so the fast path made every destination rank read every parameter from the first replica, and refit traffic concentrated on one source rank instead of being spread across the DP replicas.

The fix removes the fast path. With one group the general code reduces to `src_meta_list[dst_rank % len(src_meta_list)]`. Selection stays a pure function of the gathered metadata and the destination rank, so sender and receiver still derive the same plan without coordination. Selection is unchanged when candidates span several DP groups (TP or PP > 1), and the local-copy preference for collocated refits is unchanged.

Behavior change to note: with TP=1 sources, destinations now read from different replicas, so `nccl_m2n` creates one communicator per distinct (source mesh, destination mesh) pair it now uses, instead of all pairs sharing replica 0 as the source.
