# What does this PR do?
@humansand

Enable the existing FP32-output indexer projection with ordinary cuDNN DSA. Preserve FP32 forward scores and indexer KL values while retaining native BF16 indexer backward as an explicit gradient approximation.

- **Existing interface:** reuse `--dsa-indexer-weights-proj-output-dtype fp32` with `--no-dsa-indexer-weights-proj-use-quantization`. Projection inputs and stored parameters remain BF16; the existing GEMM produces FP32 per-token/per-head weights. Q/K remain BF16, and index scores remain FP32. BF16 defaults and projection implementation are unchanged.
- **Forward:** remove the cuDNN-only config rejection, remove the split-loss hook's pre-forward downcast, and keep the FP32-output requirement to disable projection quantization. Existing SBHD/BSHD, chunked and packed paths preserve the FP32 weight tensor; no forward downcast, new buffer or new selector is introduced.
- **Backward contract:** merged [cuDNN FE#1311](https://github.com/NVIDIA/cudnn-frontend/pull/1311) admits FP32 W in forward scoring, but native indexer backward still requires BF16 W. Convert only in the existing backward head-padding helper: >=64 heads cast FP32 W once; smaller head counts cast while copying into the already-required BF16 padded allocation. BF16 >=64 inputs retain tensor identity, and disabled indexer loss never enters this helper.
- **Numerics:** sparse and dense indexer KL consume the saved original FP32 forward logits; no indexer-score recomputation API is involved. Backward uses BF16-rounded W for dQ/dK and native BF16 dW, so this is not full FP32 indexer-gradient support. Autograd promotes dW to the FP32 projection-output dtype without recovering precision; no redundant explicit gradient upcast is added. Full FP32 backward remains separate work in [zianglih/cudnn-frontend#2](https://github.com/zianglih/cudnn-frontend/pull/2).
- **Performance/scope:** no new GPU operation for BF16 defaults, no host/device synchronization or transfer, no per-forward version checks, and no new fallback implementation. FP32 backward incurs the conversion described above; no timing benefit or RL numerical result is claimed. CP communication, tie policy, CSA/DSv4, quantization recipes and checkpoint parameter dtype are unchanged. Independent of [top-k integration #7813](https://github.com/NVIDIA/Megatron-LM/pull/7813).
- **Dependency / draft gate:** [cuDNN Frontend 1.31.0](https://github.com/NVIDIA/cudnn-frontend/releases/tag/v1.31.0) is the first stable release containing [FE#1311](https://github.com/NVIDIA/cudnn-frontend/pull/1311). Target `dev` at `ff20ed54650dd47ba21989767dfc0068d8c6f73e` pins FE **1.29.0** in both `pyproject.toml` and `uv.lock`. **Keep draft until Megatron advances its consuming dependency to a release containing this API.** The C3 image already contains FE 1.31.0; that validates this patch but does not satisfy the upstream dependency gate. No version checks, compatibility fallback, or dependency-pin change is added.

--no-dsa-indexer-weights-proj-use-quantization
--dsa-indexer-weights-proj-output-dtype fp32
