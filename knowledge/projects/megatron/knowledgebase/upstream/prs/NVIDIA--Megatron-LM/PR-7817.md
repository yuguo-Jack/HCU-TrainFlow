# What does this PR do?
@humansand

Enable the existing FP32-output indexer projection with ordinary cuDNN DSA. Preserve FP32 forward scores and indexer KL values while retaining native BF16 indexer backward as an explicit gradient approximation.

- **Existing interface:** reuse `--dsa-indexer-weights-proj-output-dtype fp32` with `--no-dsa-indexer-weights-proj-use-quantization`. Projection inputs and stored parameters remain BF16; the existing GEMM produces FP32 per-token/per-head weights. Q/K remain BF16, and index scores remain FP32. BF16 defaults and projection implementation are unchanged.
- **Forward:** remove the cuDNN-only config rejection, keeping the FP32-output requirement to disable projection quantization. Existing SBHD/BSHD, chunked and packed paths preserve the FP32 weight tensor; no forward downcast, new buffer or new selector is introduced.
- **Backward contract:** merged [cuDNN FE#1311](https://github.com/NVIDIA/cudnn-frontend/pull/1311) admits FP32 W in forward scoring, but native indexer backward still requires BF16 W. Convert only in the existing backward head-padding helper: >=64 heads cast FP32 W once; smaller head counts cast while copying into the already-required BF16 padded allocation. BF16 >=64 inputs retain tensor identity, and disabled indexer loss never enters this helper.
- **Numerics:** sparse and dense indexer KL consume the saved original FP32 forward logits; no indexer-score recomputation API is involved. Backward uses BF16-rounded W for dQ/dK and native BF16 dW, so this is not full FP32 indexer-gradient support. Autograd promotes dW to the FP32 projection-output dtype without recovering precision; no redundant explicit gradient upcast is added. Full FP32 backward remains separate work in [zianglih/cudnn-frontend#2](https://github.com/zianglih/cudnn-frontend/pull/2).
- **Performance/scope:** no new GPU operation for BF16 defaults, no host/device synchronization or transfer, no per-forward version checks, and no new fallback implementation. FP32 backward incurs the conversion described above; no timing benefit or RL numerical result is claimed. CP communication, tie policy, CSA/DSv4, quantization recipes and checkpoint parameter dtype are unchanged. Independent of [top-k integration #7813](https://github.com/NVIDIA/Megatron-LM/pull/7813).
- **Dependency / draft gate:** [cuDNN FE 1.31.0](https://github.com/NVIDIA/cudnn-frontend/releases/tag/v1.31.0), released October 8, is the first stable release containing merged [FE#1311](https://github.com/NVIDIA/cudnn-frontend/pull/1311) (`b56af9d558e10bb20ecff3cf6e5879ba18134f04`). Current Megatron `dev` still resolves FE `b15181d82170c172f2023521638367cc4c01047b` (1.28.0) in `uv.lock`; the `develop` source declaration in `pyproject.toml` does not advance that locked revision. **Keep this PR draft until Megatron bumps its cuDNN FE dependency to a release or revision containing #1311.** A newer local FE installation does not satisfy this prerequisite. The dependency bump is separate; this patch adds no package pin, runtime version gate or compatibility fallback.

- **New features**: a linked issue is **required**. Please open a [feature request](https://github.com/NVIDIA/Megatron-LM/issues/new?template=feature_request.md) and reference it here before submitting the PR.
- **Small updates (bug fixes, minor improvements)**: a linked issue is **recommended** and will accelerate the PR review process.

Linked issue: Fixes #7816.

## Contribution process

### Pre-checks

- [x] I have added relevant unit tests
- [ ] I have added relevant functional tests
- [x] I have added proper typing to my code [Typing guidelines](https://docs.python.org/3/library/typing.html)
- [x] I have added relevant documentation
- [x] I have run the [autoformatter.sh](https://github.com/NVIDIA/Megatron-LM/blob/main/tools/autoformat.sh) on my PR

### Code review

Feel free to message or comment @NVIDIA/mcore-oncall to help accelerate your merge into main. The less complex your PR is, the faster it will be approved and merged!

All PRs start as **draft**. If you open a non-draft PR, it will be automatically converted to draft.

#### Step 1: Mark PR as "Ready for Review"

1. When your PR is ready, click **Ready for Review**.
2. An oncall reviewer is auto-assigned and expert reviewers are notified based on your changes.
   - Some PRs may jump straight to step 2. This is determined by `.github/CODEOWNERS`.

:warning: Only mark as ready once merge-conflicts are resolved and the CI is passing.
Final Review might get declined if these requirements are not fulfilled.

#### Step 2: Final Review

For PRs that change `megatron/core`, once all expert reviewers have approved, the `Final Review` label is applied **automatically** and final reviewers are assigned.

For PRs outside `megatron/core`, this step is skipped.

#### Step 3: Approved

Once all required reviewers have approved, the `Approved` label is applied **automatically**.

### Merge

Any member of [mcore-engineers](https://github.com/orgs/NVIDIA/teams/mcore-engineers) will be able to merge your PR.
