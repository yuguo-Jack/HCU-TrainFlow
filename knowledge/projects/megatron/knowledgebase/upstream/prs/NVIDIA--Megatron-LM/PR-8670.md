# What does this PR do?

Reduces redundant NCCL communicator allocations by reusing eligible process groups with identical membership and creation settings.

Megatron creates separate groups for several parallelism roles even when they span the same ranks. With eager NCCL2 initialization, each duplicate allocates device memory immediately. In the configurations reported in #8668, this causes previously passing H100 training runs to exhaust device memory at iteration 2–3.

This patch:

- Caches plain NCCL groups by sorted ranks, timeout, backend, and `NCCL_COLLNET_ENABLE`. An omitted backend is resolved from the default process group.
- Excludes groups with custom `pg_options`, non-NCCL backends, local synchronization, or unspecified ranks.
- Preserves independent dense and expert all-gather communicators through `reuse_existing=False`, so those groups remain separate from their reduce-scatter counterparts.
- Provides `MEGATRON_DISABLE_PROCESS_GROUP_REUSE=1` for comparison and fallback. All ranks must use the same setting.
- Caches nonmember results as well, keeping group-creation decisions consistent across ranks. Clears the cache on model-parallel initialization and teardown, and retains the first group's description when reusing it.
- Adds focused regression coverage for reuse, exclusions, rank consistency, all-gather separation, and repeated initialization with a real collective.

## Evidence and review considerations

The experiment documented in [#8668](https://github.com/NVIDIA/Megatron-LM/issues/8668) on MCore revision `a0f793dfa4e776d99a8aa63bed74e0fafc91b0db`. With the model settings and recorded dependencies held fixed:

| Workload | Reuse disabled | Reuse enabled | Group-creation calls |
|---|---|---|---|
| Llama3-8B, 8 × H100 | OOM at iteration 2 | Completed 30 iterations | 121 → 12 |
| Nemotron3-Nano, 16 × H100 | OOM at iteration 3 | Completed 30 iterations | 191 → 37 |

Counts are rank-0 `create_group()` calls, including groups that rank 0 does not join; they are not resident communicator counts per GPU. The issue contains the reproduction commands, environment details, and limitations of the historical comparison.

The 30-step results do not establish correctness or performance of this revision, long-run convergence, or all TP/PP/CP and communication-overlap configurations.

**Sharing a communicator changes stream and collective-ordering behavior**. Review should confirm which additional roles need distinct communicators even when their memberships match. The explicit all-gather exclusions cover the known AG/RS separation requirement; broader overlap behavior still needs GPU evaluation. Selective lazy initialization, as discussed in #8668, remains an alternative that preserves communicator identity.

- Connor-XY · COMMENTED · 2026-10-29T17:11:12Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/8670#pullrequestreview-5701916403)

I replayed `initialize_model_parallel()` on CPU with `new_group` mocked and grouped the parallel_state globals by object identity. With reuse off, the Llama layout joins 20 NCCL groups per rank: 14 single-rank groups and 6 that span all 8 ranks. This PR brings that to 2, which matches your numbers, so the saving is real.

My main concern is that keying on membership alone also merges groups that are meant to overlap. Details are inline. What I'd suggest instead is an explicit list of roles allowed to share a group, built per grid, plus `lazy_init` for the groups that stay separate.

On lazy init by itself: it won't recover enough here. `dp_cp` and the dist-opt grad-norm group communicate every step, so they'd still allocate. One catch when combining the two: the PR skips the cache for any group with `pg_options`, so passing `lazy_init` through `pg_options` would quietly turn reuse off for those groups.

Membership alone also merges groups that are meant to overlap. When expert DP is 1 (EP8 on one node, TP2 CP2 EP4, or PP×EP with EP equal to the per-stage DP), `EXPERT_MODEL_PARALLEL_GROUP` and `DATA_PARALLEL_GROUP_WITH_CP` become the same object. A `ProcessGroupNCCL` runs all of its collectives on one NCCL stream. The Megatron-FSDP docs have a probe showing that an RS and an AG on one group run back to back even when issued from different user streams (`megatron/core/distributed/fsdp/src/docs/runtime_schedule.md`). With overlap-grad-reduce, the alltoall dispatcher's A2A then waits behind in-flight grad RS buckets, and the overlapped param AG runs ahead of the forward A2A. CP at DP=1 has the same issue: `CONTEXT_PARALLEL_GROUP` merges with `DATA_PARALLEL_GROUP_WITH_CP`. Neither repro would show this. Llama has no EP, and the Nemotron layout has expert DP = 2.

I'd replace this with an explicit list of roles that may share a group:

- `dp`/`dp_cp` and `tp_dp`/`tp_dp_cp` when CP is 1
- the GTP-remat variants at size 1
- `expt_dp`/`dp_cp` when EP is 1 and ETP equals TP
- the dist-opt grad-norm group with any world-sized group
- one single-rank group per rank

Keep `ep`, `tp_ep`, `cp`, the hierarchical and dynamic CP groups, `pp`, and the AG groups separate. Main already aliases this way in one place (`_INTRA_PARTIAL_DATA_PARALLEL_GROUP_WITH_CP = _DATA_PARALLEL_GROUP_WITH_CP`).
