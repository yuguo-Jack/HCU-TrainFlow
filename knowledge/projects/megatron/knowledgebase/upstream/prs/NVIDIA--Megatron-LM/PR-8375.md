## Original PR description

# Add bit-exact replay coverage for NCCL-EP MoE dispatch

The MoE determinism suite exercises the DeepEP flex dispatcher but has no NCCL-EP replay cell. Add an EP=2 NCCL-EP parameter to the existing full MoELayer test so it compares outputs, input gradients, and parameter gradients across three replays with competing CUDA streams.

The new cell uses the existing TE NCCL-EP API capability check and world-size guard. Teardown finalizes the borrowed NCCL communicator before model-parallel process groups are destroyed, including on replay failure. Update the kernel manifest to include NCCL-EP; HybridEP remains uncovered.

Validation on 2×H100 SXM 80 GB, NV18 topology:

- The new pytest cell passed on both ranks, including setup and teardown.
- NGC PyTorch 26.09 container: torch 2.14.0a0+b2c75dd062.nv26.09, CUDA 13.4, Triton 3.8.0, Transformer Engine 2.19.0+5e52befd, NCCL 2.31.2+cuda13.4.
- Repository `tools/autoformat.sh` check passed (Black, isort, pylint and Ruff). Its non-blocking mypy stage reports missing local torch/pytest stubs; it is not a type-check pass. `git diff --check` passed.
- The two-host GH200 replay also passed on both ranks. Each host has one GPU; NCCL logs confirm `NET/IB/0/GDRDMA` communication. The existing assertion compares outputs, input gradients and parameter gradients across three contention replays.
- GH200 runtime: PyTorch 2.14.1+cu130, CUDA runtime 13.0, Triton 3.8.0, Transformer Engine 2.20.2+44f31bbe, NCCL 2.30.7, NVIDIA driver 595.58.03. This run used the submitted source head `67413f611ffb1e7d7d29cd2a61f520cffe79d995` plus an unrelated CE test-only overlay; the MoE test file matched the submitted file byte for byte. Broader CI remains separate.
- The first cross-host launch failed because Gloo resolved the hostname to a loopback address. That failure is retained. Binding `GLOO_SOCKET_IFNAME` to the actual inter-host interface resolved startup; the corrected run exited successfully on both ranks with no foreign GPU process detected.
- The repository's automatic data fixture emitted an extraction race warning on one rank; this synthetic-input cell does not consume that dataset. Original logs preserve the warning.

Command:

```bash
python -m torch.distributed.run --standalone --nproc_per_node=2 -m pytest -q \
  'tests/unit_tests/determinism/kernels/test_moe_kernels.py::TestMoEModules::test_moe_layer_replays[flex-ncclep-ep2]'
```

The GPU test ran on frozen main `13a9d46d958ca72582682ae93fa742e94d550d25` plus this test patch. The submitted branch is rebased onto `fce1e2051`; the intervening upstream changes do not alter the tested MoE layer/dispatcher. No production kernel or performance behavior is changed. The GH200 run validates this fixed two-host topology; it is not evidence for arbitrary allocations or different GPU counts.

For the two-host run, launch one worker per host with the same `MASTER_ADDR`/port and `--nnodes=2 --node-rank=0` or `1`. Set `NCCL_ALGO=Ring`, `NCCL_EP_HT_EM_AG_SCAN_MODE=1`, `NCCL_SOCKET_IFNAME` and `GLOO_SOCKET_IFNAME` to the correct interface on each host, and `NCCL_IB_HCA=mlx5_0`. The environment pins are part of the recorded validation.

The [public reproduction record](https://github.com/0z5a/Megatron-LM/tree/hopper-validation-evidence/validation/hopper-20261020) contains the bounded protocols, cold-process digest records and audit summaries. Private hostnames are replaced with rank labels; raw execution archives retain the original failures and topology logs.
