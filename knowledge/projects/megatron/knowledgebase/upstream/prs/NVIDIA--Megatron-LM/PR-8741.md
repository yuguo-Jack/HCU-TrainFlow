# Run the training loop's remaining reads on its process-group collection

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8741) · state: closed · merged: False

## Original PR description

**Why.** `pretrain()` accepts a `ProcessGroupCollection` and builds the model on it, but the loop itself still read the global grid in these places:
- the packed-sequence FLOPs deduplication;
- the stage checks that attach the logits saver and the logits capture;
- the batch-size check and the batch accounting;
- the skipped-iteration batch reads in `dummy_train_step`;
- the samples-seen reduction;
- the full-validation TP rank and the full-dataset length probe;
- the GPU sniff test;
- the ModelOpt GPT spec's context-parallel size.

With `pretrain(pg_collection=...)` on a grid laid out differently from the global one, these steps used other ranks than the ones the model trains on. With PP=2 and TP=2 over a global TP=PP=1 grid, the samples-seen sum and the batch accounting ran over the whole world, and the FLOPs were deduplicated by 1 instead of 4.

**What.**
- `train()` and `pretrain()` pass the run's single-grid collection to these steps. `train_step`, `evaluate`, `evaluate_and_print_results` and the logits hooks use the model's collection, then the run's, and read the global grid only when given neither.
- The two tensor-metric observer calls that main added to `train_step` use the same collection, so they reduce over the same groups as the loss and grad-norm reductions.
- `consume_seqlen_stats_in_iteration`, `dummy_train_step`, `post_training_step_callbacks` and `update_packed_sequence_stats` take an optional `pg_collection`.
- `default_layer_spec(config, vp_stage, pg_collection=None)` reads the ModelOpt CP size from `pg_collection`, and `GPTModelBuilder` passes its collection.
- Sample counts and batch accounting use `dp_gtp_remat`, the group that `get_data_parallel_group()` returns by default.
- The batch-size check raises `ValueError` and reports the batch-parallel size that the microbatch calculator divides by.
- `train()` rejects `--gpu-sniff-test-interval` for a `MultiModuleProcessGroupCollection` with a `ValueError`, before any sniff-test collective.

`update_packed_sequence_stats` only gains the parameter here. Its one production caller, `examples/multimodal/train.py`, does not pass a collection yet, so that path still reads the global grid. #8757 makes that fallback warn, and #8761 passes the model's collection there.

The last commit makes multi-module runs reject the sniff test instead of running it on the global grid:
- Without it, `train()` gives the sniff test no collection on a multi-module run, and `run_gpu_sniff_test()` builds one from the global grid. Heterogeneous MiMo (`examples/mimo/pretrain_mimo.py`) never builds that grid, so the flag fails with `data parallel group is not initialized`. Main fails the same way, because its sniff test always reads the global grid.
- Passing each rank's module collection instead is not safe. The sniff test all-gathers every metric over WORLD. A rank reports 0 or 2 reduce-scatter metrics and 0 or 2 all-to-all metrics, depending on whether its TP and EP groups have more than one rank. It adds 2 send/recv metrics per stride of its DP group. The MiMo encoder always has EP=1, and the language model takes `--mimo-llm-ep`. Ranks of different modules would issue different numbers of WORLD all-gathers, and the surplus would pair with the closing WORLD barrier or hang.
- The check adds no collective. Every rank of a multi-module run gets a multi-module collection and the same flag value, so all ranks raise at the same point.

**Tests.** New `tests/unit_tests/training/test_training_loop_pg_collection.py` makes the global accessors raise. Most of its cases also build a collection laid out unlike the global grid. Full validation, the full-dataset probe's model-parallel group, collection precedence, the tensor-metric observers, the sniff test and the missing-group check rely on the raising accessors alone. `test_sniff_test_rejects_a_multi_module_collection` checks the new helper, and `test_train_rejects_the_sniff_test_for_a_multi_module_collection` checks that `train()` raises before it runs the sniff test. `test_train_step_observes_tensor_metrics_on_the_run_collection` checks that the tensor-metric observers and the samples-seen count receive the run's collection. `test_full_dataset_length.py` and `test_gpt_builder.py` are updated, including a check that the ModelOpt spec takes its CP size from the collection.

On 4 GPUs against main, with no regressions: `test_training_loop_pg_collection.py` has 14 passed, all new; `test_gpt_builder.py` has 66 passed here vs 64 on main, and its 2 new tests pass; `test_full_dataset_length.py` has 10 passed on both sides. No test fails on either side. In the integration run, this PR's test files show no regressions against main. With the other process-group changes from #6307 applied, end-to-end training smokes give losses bit-identical to main's at every iteration.

Before the 2026-11-01 sync, this branch ran the three test files on 4 CPU ranks with Gloo, with no regressions: 81 passed and 6 failed.
- 10 of the 15 new tests pass there, and the other 5 need CUDA.
- The sixth failure is an existing test in `test_full_dataset_length.py` whose device all-reduce the CPU environment does not support.
- With the sniff-test check removed, its 2 new tests fail. One fails on the missing helper. In the other, `train()` runs past the collection choice.
- `tools/check_process_group_usage.py` gives the same output on this branch as on main.

**Compatibility.** New parameters are keyword arguments that default to the old behavior, so callers that pass no collection keep the global grid. On the standard grid every step selects the same groups and ranks as before. No `megatron/core` file changes, and the process-group allowlist is unchanged. Differences:
- On main, `pretrain()` has a run collection only when its caller passes one. Stock runs therefore keep the global grid in the run-level steps until #8037 makes `pretrain()` build a collection for every run. The per-model steps use the collection `get_model()` built the model on.
- The batch-size check is a `ValueError` instead of an `assert`, so it also runs under `python -O`. Its message reports `get_batch_parallel_size(args)`, the size the microbatch calculator uses. That equals the old data-parallel world size unless GTP weight-remat ranks split sequences.
- The samples-seen count raises `ValueError` when the model's collection has no `dp_gtp_remat`, where main summed over the global DP group. It raises on the last pipeline stage only, so the other stages wait until the job is torn down. Collections from `pretrain()` and `use_mpu_process_groups()` always set the field.
- The full-dataset probe raises `ValueError` when the collection lacks the group it sums over: `dp_gtp_remat`, or `dp_cp_gtp_remat` when the loader deduplicates across context parallelism. A collection without `mp` still falls back to the global model-parallel group inside `reduce_max_stat_across_model_parallel_group`.
- A multi-module (MIMO) run keeps its run-level steps on the global grid. Its samples-seen sum moves to the language model's DP group.
- With `--gpu-sniff-test-interval` set, a multi-module run now stops at the start of `train()` with a `ValueError`, where it used to fail inside the sniff test. Single-grid runs and runs without a collection are unchanged. Is rejecting the flag acceptable here, rather than a sniff test per module?

Not covered here:
- The fallbacks for callers without a collection stay silent. #8757 makes them warn.
- The data-loader reads in `training.py` move in #8742.

Landing:
- #8037 adds its own helpers and docstrings next to this PR's in `training.py`, and the two conflict there. Whichever lands second keeps both pairs of helpers and both `train_step` docstring additions. `train()`'s docstring keeps #8037's text, plus this PR's multi-module sentence and `Raises` section.
- #8048 and #8726 add `pp_rank` to `default_layer_spec`, and this PR adds `pg_collection`. They conflict in `megatron/training/models/gpt.py` and `test_gpt_builder.py`. Whichever lands second takes `default_layer_spec(config, vp_stage, pp_rank=None, pg_collection=None)`, and the builder passes both.
- #8742 adds a second DP×CP helper to `training.py` that falls back to `dp_cp`. This PR's `_reduce_sum_across_data_parallel_group` requires the GTP-inclusive group instead. #8757 replaces both with one helper.
- #8743 builds `LogitsSaverHooks` on the last chunk's `pg_collection`, while the stage check here uses the model's collection or the run's. #8757 puts both on the same collection.
