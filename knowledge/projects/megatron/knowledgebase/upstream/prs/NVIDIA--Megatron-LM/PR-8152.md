## Original PR description

# feat(rl): add the shared-prefix packing library

## What this PR does

GRPO samples several completions per prompt, and a packed forward normally
repeats the prompt in every row. This PR adds the planning side of
shared-prefix execution to `megatron.rl`. Rows with the same group ID and
exact prompt tokens are packed into stars. A star stores the prompt once,
followed by up to `MAX_SHARED_PREFIX_BRANCHES` (16) completions. Several
stars can share one packed forward.

Terms:

- **Star**: one prompt followed by its completions, `[prompt, c_1, ..., c_G]`.
- **Forest**: several stars packed into one forward.
- **Dense rows**: the separate sequences `[prompt, c_g]` that a star replaces.

## Changes

- `tree_layout.py`: the parent-linked tree descriptor of a packed unit.
- `shared_prefix_packing.py`: planner rows, exact-prompt matching, star and
  forest layouts, even group subdivision and forest packing.
- `shared_prefix_metadata.py`: group-coherent data-parallel sharding and equal
  real-row execution slots.
- `shared_prefix_tensors.py`: token, position and scatter maps, TP/CP padding
  and zigzag sharding.
- `shared_prefix_alignment.py`: brings every data-parallel replica to a forward
  count the caller has agreed on. It splits execution units at real-row
  boundaries and never adds dummy rows.
- `shared_prefix_dense_bins.py`, `shared_prefix_execution.py`,
  `shared_prefix_cost.py`: dense-bin reconstruction, execution plans and the
  work model.
- `megatron/rl/shared_prefix.md` documents the API and the integration
  contract.

The packing modules depend only on torch and the standard library. They never
import `megatron.core`. NeMo RL (NVIDIA-NeMo/RL#4537) is the first consumer.

## Changes to existing `megatron.rl` behavior

`import megatron.rl` becomes lighter:

- The Pydantic request types move from `megatron/rl/__init__.py` to
  `generation_api.py`. The package exports load lazily, and `agent/` and
  `inference/` import the types from the new module. Newly pickled request
  objects therefore name `megatron.rl.generation_api` as their module.
- `logging.py` prints its log directory and opens (truncates) its log file on
  the first `log()` call instead of at import.

## Tests

CPU-only, with no distributed fixtures:

```bash
python -m pytest --noconftest \
    tests/unit_tests/rl/test_shared_prefix*.py tests/unit_tests/rl/test_tree_layout.py
```

Result on one GB200 node (torch 2.11, Transformer Engine 2.15, mamba-ssm 2.3.2.post1, causal-conv1d 1.6.2.post1, flash-attn 2.8.1): 206 passed (12 subtests). This branch alone on top of main also ran the surrounding regression suites (routers, attention, MTP, Mamba, training, RL) on one and four GPUs. Every failure in those runs also occurs on main in the same container: tests that need more ranks than the run had, and missing APEX extensions.

- The tensor property tests run a toy model on planned and materialized
  layouts and check every predicted position against a dense per-row forward.
  The planning property tests push seeded random batches through sharding,
  slot planning, layout planning and alignment, end to end.
- `tests/unit_tests/rl/shared_prefix_oracles.py` holds a quadratic reference
  attention mask built from the tree descriptor, plus a plan-and-materialize
  helper.
- `test_shared_prefix_api_contract.py` pins the symbols and keywords NeMo RL
  calls and checks that the packing modules import without undeclared
  dependencies.

## Notes for reviewers

- Nothing in Megatron-LM calls this library yet. P8 adds a test that checks
  this planner's padding quantum and CP ownership against core execution (P6).
  Wheel packaging of these modules is P7.
- `megatron/rl/shared_prefix.md` describes the contract with core shared-prefix
  execution, which P4 to P6 add.
- Planned follow-up: remove the slot planner once the dense-bin planner packs
  siblings together. In the documented NeMo RL configuration, workers plan
  execution only with the dense-bin planner, but the driver still calls
  `plan_fixed_execution_slots` for shard metadata, so removing the slot planner
  also needs a NeMo RL change.

## Shared-prefix stack

This PR is one of eight that #7914 was split into; #7914 itself becomes P6, the
HybridModel integration. Each one needs fewer CODEOWNERS groups and can be
reviewed on its own. Shared-prefix
execution stores a prompt once per star (by default up to 16 completions of the
same group)
and runs those completions against it, instead of repeating the prompt in every
packed row.
