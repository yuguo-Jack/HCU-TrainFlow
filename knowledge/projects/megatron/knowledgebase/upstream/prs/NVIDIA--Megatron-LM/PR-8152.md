## Original PR description

# feat(rl): add the shared-prefix packing library

## What this PR does

GRPO samples several completions per prompt, and a packed forward normally
repeats the prompt in every row. This PR adds the planning side of
shared-prefix execution to `megatron.rl`. Rows with the same group ID and
exact prompt tokens are packed into stars. A star stores the prompt once,
followed by up to `MAX_SHARED_PREFIX_BRANCHES` (16) completions. Several
stars can share one packed forward.

Each data-parallel replica plans only its own rows. The caller agrees on one
forward count across replicas. The alignment helpers then split units at
real-row boundaries to reach that count.

Terms:

- **Star**: one prompt followed by its completions, `[prompt, c_1, ..., c_G]`.
- **Forest**: several stars packed into one forward.
- **Dense rows**: the separate sequences `[prompt, c_g]` that a star replaces.
- **Slot**: a set of rows that the execution planner plans together. A slot
  holds up to `max_completions_per_bin` (default 16) rows of one prompt group
  that fit the token budget, or one row without a group ID. The planner turns
  a slot into a star when the slot's rows share one exact prompt.

## Changes

- `tree_layout.py`: the parent-linked tree descriptor of a packed unit.
  `PackedTreeLayout.iter_star_roots()` returns a tuple. It rejects deeper
  trees, interleaved star storage and padded prompt roots when it is called.
- `shared_prefix_packing.py`: planner rows, exact-prompt matching, star and
  forest layouts, even group subdivision and forest packing. A group larger
  than the branch limit becomes the fewest stars the limit allows, with sizes
  that differ by at most one: 17 rows become 9 and 8, and 241 rows become one
  star of 16 and fifteen of 15. Star and forest layouts expose
  `dense_length`, their conventional length with one prompt copy per row.
- `shared_prefix_metadata.py`: group-coherent data-parallel sharding.
- `shared_prefix_tensors.py`: token, position and scatter maps, TP/CP
  (tensor-/context-parallel) padding and zigzag sharding.
  `shard_shared_prefix_tensor_bin_for_context_parallel` requires `tp_size` and
  `padding_multiple`. Passing `padding_multiple=None` still selects the
  topology quantum. `materialize_shared_prefix_token_aligned_tensor` rejects
  a source, such as an MTP (multi-token prediction) loss mask, that is narrower
  than the longest real row.
- `shared_prefix_execution.py`: execution plans. Each replica splits every
  local prompt group into slots, first-fit decreasing on padded full row
  lengths. Evaluation packing splits a group on the physical budget instead.
  A slot whose rows share one exact prompt runs as one star. Each row
  without a group ID gets its own slot. `pack_groups` allows several forwards
  per slot and coalesces stars into forests. With `pack_groups`, a slot whose
  rows do not all share keeps its stars and runs only the other rows dense.
  This description calls such a star a partial star. Without `pack_groups`,
  each slot is exactly one forward. Flag combinations
  are checked before any row is read. `largest_first` orders every unit by
  nonincreasing physical length.
- `shared_prefix_alignment.py`: brings every data-parallel replica to a forward
  count the caller has agreed on. It splits execution units at real-row
  boundaries and never adds dummy rows.
- `shared_prefix_dense_bins.py`: dense-bin reconstruction. A dense bin that
  holds a row without a group ID, prompt or completion stays dense.
- `shared_prefix_cost.py`: the work model, with one prompt copy per group.
- `megatron/rl/shared_prefix.md` documents the API and the integration
  contract. It also covers planning errors that occur on one replica only, and
  the difference between deterministic planning and batch invariance.

Every packing module except `shared_prefix_tensors` needs only the Python
standard library. `shared_prefix_tensors` also needs torch. No packing module
imports `megatron.core`. NeMo RL (NVIDIA-NeMo/RL#4537) is the first consumer.

## Notes for reviewers

- Nothing in Megatron-LM calls this library yet. The branch
  `shared-prefix/p8-rl-parity` (RL planner parity test, no PR number yet) adds
  a test that checks this planner's padding quantum and CP ownership against
  the core execution in #7914. Wheel packaging of these modules is #8158.
- `megatron/rl/shared_prefix.md` describes the contract with core shared-prefix
  execution, which #8156, #8157 and #7914 add.
- The driver is the RL controller that shards a batch across data-parallel
  replicas. This PR no longer has a slot planner for the driver.
  `FixedExecutionSlotPlan`, `plan_fixed_execution_slots` and
  `get_prescribed_shared_prefix_slots` are removed.
  `plan_shared_prefix_execution_units` no longer takes `row_slots` or
  `repack_groups`. `estimate_shared_prefix_row_work` no longer takes
  `row_slot_ids`. `align_physical_units` no longer takes a `rebuild`
  callable, which no caller passed. Each replica now splits its own groups, as the former
  `repack_groups` path did. Forward counts can therefore differ between
  replicas, and a distributed caller must align them.
- NeMo RL #4537 changes in the same round. Its driver no longer plans
  execution slots. It keeps group-coherent sharding and checks that every row
  fits one forward after padding. At data-parallel size above
  1, its shared modes require `pack_groups` and data-parallel alignment.
  `test_shared_prefix_api_contract.py` pins the keywords that #4537 passes, so
  the two PRs move together.
- A check on the rows can fail on one replica only, for example when a row is
  longer than the token budget after padding. The caller must carry that error
  in the collective that agrees on the forward count, so that every rank
  raises together. NeMo RL #4537 does this.
- The even split changes plans only for some groups larger than the branch
  limit. For example, 49 rows used to become 13+13+13+10, and 241 rows used to
  become fifteen stars of 16 plus one unshared row.
- Partial stars apply only to `plan_shared_prefix_execution_units` with
  `pack_groups`. `share_prefixes_in_dense_training_bins` keeps the
  all-or-nothing rule for a dense bin that holds a row without a group ID,
  prompt or completion. That bin is already one agreed forward, so it cannot
  be split. A forest root needs a group ID, a nonempty prompt and a nonempty
  completion. The core forest layout in #8156 enforces the last two. The
  function's docstring states this rule, and the planning example
  `dense-bins-placeholder-keeps-bin-dense` pins it.
