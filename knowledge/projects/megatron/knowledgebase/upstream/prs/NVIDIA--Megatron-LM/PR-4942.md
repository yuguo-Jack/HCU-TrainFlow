# [feat] HybridStack grouped syntax and EP-overlap (2/4 of #4798)

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/4942) · state: open · merged: False

## Original PR description

## What does this PR do?

Adds bracketed HybridStack groups and EP communication overlap to HybridModel. Patterns such as `[*-]` and `[*E]` make several physical layers one logical layer for scheduling. Groups do not change checkpoint storage: every layer keeps the distributed-checkpoint key it has in the pattern without brackets, so grouped and ungrouped models load each other's checkpoints. Groups reject nesting and nonterminal MoE layers. This is part 2 of the original #4798 split by @Wohox, @Connor-XY, and @guihong-nv; the common scheduler prerequisite #4941 has merged.

Grouping is what makes EP overlap possible for hybrid models. The overlap scheduler overlaps one microbatch's MoE all-to-all with another microbatch's compute at logical-layer granularity, so an attention (or Mamba/GDN) layer and the MoE layer after it must form one logical layer, e.g. `[*E]`.

The overlap callables support attention, MLA, Mamba, GDN, and MoE layers, with per-microbatch norm-offload state and correct delayed-weight-gradient hook ownership. Hybrid MTP is not supported with EP overlap: as on main, `HybridModel` raises for an MTP pattern with `overlap_moe_expert_parallel_comm`. Hybrid checkpoint names and direct-stack offsets are unchanged, for grouped and ungrouped patterns alike. `HybridModel.sharded_state_dict` omits the output layer's (empty) TE extra state, as `GPTModel` does. GPT checkpoint import into grouped models is isolated in #7192.

**Change to the common MTP callable (affects GPTModel).** `build_mtp_layer_callables` in `models/common/fine_grained_callables.py` now detaches the per-depth hidden-state chunks it stores for the MTP post-process slot (`node.detach`), and the schedule node merges their gradients. Before, the post-process slot backpropagated through the pre-dispatch slot's graph, so the final norm's backward graph was traversed twice whenever the pre-dispatch slot applies the final norm. The code path runs for GPTModel with `mtp_num_layers >= 1` and `overlap_moe_expert_parallel_comm=True`. The existing GPT chunk-level 1F1B tests with MTP (`tests/unit_tests/a2a_overlap/test_schedule_chunk_1f1b.py`) pass unchanged.

## Current-main integration and boundaries

Rebased on `5052ce8c48d999a9422ad5ef02954089639db832` (no new conflicts; this refresh only lets the stacked #6958 merge cleanly). The one conflict, from the earlier rebase onto `4729b9c6c`, was with the Shortcut-MoE wide-residual work (#7440): `HybridStack.mamba_state_shapes_per_request` iterates `physical_layers()` and still descends into bracketed groups, which never coexist with Shortcut-MoE blocks. The refresh preserves eager hash routing, sequence-parallel token alignment, precomputed MTP embeddings, CP layout inputs, inference caches, and tensor observation hooks. Group parsing accounts for the current CSA/HCA/window attention symbols. MTP metrics retain main's explicit depth mapping. Ungrouped shortcut checkpoints keep physical storage indices, and static inference accepts caller-provided embeddings without token IDs.

The EP-overlap MoE slot passes the batch-first padding mask to `MoELayer.route` and `MoELayer.preprocess` unchanged, as `MoELayer.forward` and the GPT overlap callables do (#6615), so dropless HybridEP drops padded rows on both paths. The slot used to transpose the mask before `route`, which transposes it again, so with a micro-batch size above 1 the router excluded the wrong tokens from the aux loss.

With EP overlap, `HybridModel` rejects CUDA graphs, mixed CP-layout conversion, chunkwise linear CP, mHC, and MoE shortcuts at construction; `TransformerConfig` already rejects hash-routed MoE and wide residuals with overlap. These features require dedicated schedule integration before they can be enabled together.
