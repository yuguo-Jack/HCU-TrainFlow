# [feat] HybridStack grouped syntax and EP-overlap (2/4 of #4798)

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/4942) · state: open · merged: False

## Original PR description

## What does this PR do?

Adds bracketed HybridStack groups and EP communication overlap to HybridModel. Patterns such as `[*-]` and `[*E]` make several physical layers one logical layer for scheduling. Groups do not change checkpoint storage: every layer keeps the distributed-checkpoint key it has in the pattern without brackets, so grouped and ungrouped models load each other's checkpoints. Groups reject nesting and nonterminal MoE layers. This is part 2 of the original #4798 split by @Wohox, @Connor-XY, and @guihong-nv; the common scheduler prerequisite #4941 has merged.

Grouping is what makes EP overlap possible for hybrid models. The overlap scheduler overlaps one microbatch's MoE all-to-all with another microbatch's compute at logical-layer granularity, so an attention (or Mamba/GDN/KDA) layer and the MoE layer after it must form one logical layer, e.g. `[*E]`.

The overlap callables support attention, MLA, Mamba, GDN, KDA, and MoE layers, with per-microbatch norm-offload state and correct delayed-weight-gradient hook ownership. Hybrid MTP is not supported with EP overlap: as on main, `HybridModel` raises when the model has MTP depths (from a `/` pattern or an `MTPSplit` config list) and `overlap_moe_expert_parallel_comm` is set on the model config or on any layer config. Hybrid checkpoint names and direct-stack offsets are unchanged, for grouped and ungrouped patterns alike. `HybridModel.sharded_state_dict` omits the output layer's (empty) TE extra state, as `GPTModel` does. GPT checkpoint import into grouped models is isolated in #7192.

**Change to the common MTP callable (affects GPTModel).** `build_mtp_layer_callables` in `models/common/fine_grained_callables.py` now detaches the per-depth hidden-state chunks it stores for the MTP post-process slot (`node.detach`), and the schedule node merges their gradients. Before, the post-process slot backpropagated through the pre-dispatch slot's graph, so the final norm's backward graph was traversed twice whenever the pre-dispatch slot applies the final norm. The code path runs for GPTModel with `mtp_num_layers >= 1` and `overlap_moe_expert_parallel_comm=True`. The existing GPT chunk-level 1F1B tests with MTP (`tests/unit_tests/a2a_overlap/test_schedule_chunk_1f1b.py`) are unchanged. In the ord run below, their only failures are FP8 and 8-rank cases that fail on main too.

## Current-main integration and boundaries

Rebased on `631e14632`. The PR split `HybridModel.forward` into `_preprocess` / `forward` / `_postprocess`; main's later edits to the old `forward` now sit in the matching piece: the SP scatter before `zero_padding_tokens` (#8274), per-layout padding masks from `cp_batch` (#7047), and the MTP padding mask (#7611). `forward` takes main's `output_processor` / `output_processor_context` arguments (#7054) and passes them to `_postprocess`. `_postprocess` calls the hook where main's `forward` does, after the MTP block and before last-token logits slicing. Bracketed groups receive `padding_mask_by_layout` on both the eager and the checkpointed path. The hybrid MoE slot passes `packed_seq_params` to `route` (#7046) and `preprocess` (#8458) and treats `deepepv2` like `deepep` (#5153), as the GPTModel callables do. The EP-overlap pre-dispatch slot runs #7054's KDA (`K`) layers through `_forward_attention` and registers their delayed weight gradients through the layer's `backward_dw_wrapper`, as it does for GDN. Main's config-list path (#7555, `hybrid_layer_config_list`) builds one layer per config: brackets are pattern syntax, and config lists reject group entries. `HybridModel` does not reject EP overlap for config lists; the schedule runs each layer as its own logical layer, as for an ungrouped pattern. The hash-MoE threshold and placement checks flatten groups and also match `MoELayerConfig` entries. As in main's `forward`, `_preprocess` builds rotary embeddings only when the model has a rotary module, and `forward` and `_postprocess` drop them for a config-list decoder or MTP block that uses MLA. Main's ScheduleNode activation-ownership refactor (#8302) needed no change here: `node.detach`, which the hybrid MoE slots and the MTP chunk fix use, now keeps only each tensor's producer gradient edge, and hybrid slots that free their input use main's storage-free input wrapper. Main's DSA indexer FLOPs count (#7043) counts the flattened pattern, so brackets don't shift it. The one conflict in the rebase onto `4729b9c6c` was with the Shortcut-MoE wide-residual work (#7440): `HybridStack.mamba_state_shapes_per_request` iterates `physical_layers()` and still descends into bracketed groups, which never coexist with Shortcut-MoE blocks. The refresh preserves eager hash routing, sequence-parallel token alignment, precomputed MTP embeddings, CP layout inputs, inference caches, and tensor observation hooks. Group parsing accounts for the CSA/HCA/window attention and KDA symbols. MTP metrics retain main's explicit depth mapping. Ungrouped shortcut checkpoints keep physical storage indices, and static inference accepts caller-provided embeddings without token IDs.

The EP-overlap MoE slot passes the batch-first padding mask to `MoELayer.route` and `MoELayer.preprocess` unchanged, as `MoELayer.forward` and the GPT overlap callables do (#6615), so the flex dispatcher's dropless HybridEP and (since #8458) NCCL EP backends exclude padded rows on both paths. The slot used to transpose the mask before `route`, which transposes it again, so with a micro-batch size above 1 the router excluded the wrong tokens from the aux loss.

With EP overlap, `HybridModel` rejects CUDA graphs, full recompute, mixed CP-layout conversion, chunkwise linear CP in Mamba layers, mHC, and MoE shortcuts at construction; `TransformerConfig` already rejects hash-routed MoE and wide residuals with overlap. These features require dedicated schedule integration before they can be enabled together.

`PagedStashRunner` now finds MoE layers inside bracketed groups. Without that, `--moe-expert-rank-capacity-factor` or `--moe-paged-stash` with a grouped pattern tracked no MoE layer and silently missed over-budget token drops. This fix moved here from #6958.

The EP-overlap MoE slot unflattens packed micro-batches (`tokens_per_sample`) before routing, as the eager path does, so the sequence-level aux loss is per sample.
