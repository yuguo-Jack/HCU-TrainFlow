# What does this PR do?
Add an optional max_cp_size for dynamic context parallelism, independently of the static context_parallel_size.

### Motivation

Pure A2A requires TP-local Q/K/V head counts to be divisible by the effective CP group size. With a small number of KV heads, DCP candidate groups can exceed the head-sharding limit.

For example, Q=32, KV=4 and TP=2 produces local Q/K/V heads of 16/2/2, limiting the maximum compatible power-of-two A2A group size to CP2.

### Changes

- Add an optional, user-specified power-of-two max_cp_size.
- Validate explicit caps against the supported DP×CP sizes and minimum CP size.
- Validate head-sharding compatibility during configuration or construction for supported attention implementations.
- Bound scheduler candidate selection and reject oversized initial placement.
- Preserve static context_parallel_size and the user's communication choices.
- Without DCP, record max_cp_size=context_parallel_size without applying the new validation or scheduling behavior.

### Scope

Existing rank-filling, group-expansion and VPP-alignment behavior is unchanged.
Those paths may still produce groups above the candidate limit. This PR does not establish an end-to-end hard cap or resolve those separate expansion issues.

This PR does not add support for DCP with a2a+p2p.

### Validation

Tested commit: df18365d4b9415bd1b544ab66f88268f98aa4b52

- Selected unit suite: 280 cases passed on each of eight workers.
- Fixed-CP versus DCP numerical comparison: passed for two steps using the same ordered packed samples.
- Full-model Qwen3-30B training: completed 90 iterations training, with no observed OOM or A2A failure.
- Tested Invalid cap8 configuration: successfully rejected during initialization with the expected TP-local head-divisibility error. This configuration also exceeded the physical DP×CP size of four.

The 150-step training run did not complete. GDN GPU-kernel training was not tested.
