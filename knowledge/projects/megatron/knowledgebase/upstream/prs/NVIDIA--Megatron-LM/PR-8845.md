# Handle unequal inference token counts in the allgather MoE dispatcher

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8845) · state: open · merged: False

## Original PR description

## What does this PR do?

In dynamic inference with expert parallelism, the default `allgather` MoE token
dispatcher (used with `transformer_impl` `local` or `transformer_engine`) hangs
every EP rank whenever the ranks hold different token counts in an eager,
non-CUDA-graph step. `MoEAllGatherTokenDispatcher` gathers the routing map,
probabilities and hidden states, and later reduce-scatters the output, with
equal-size collectives across TP×EP. Inference EP ranks do not hold equal
counts:
- Each EP rank batches its own requests, so busy ranks can hold 2 and 3
  requests.
- An idle rank runs a minimal dummy forward: one request, or one token for an
  MTP draft.
- The engine equalizes EP token counts only when it matches a CUDA graph.

The inference-optimized NCCL/NVLS dispatchers and the all-to-all dispatcher
already exchange per-rank sizes; the allgather dispatcher does not.

This PR lets the allgather dispatcher handle unequal counts during inference.
While the engine is active (`InferenceMode.is_active()`) and the stream is not
capturing a CUDA graph, each rank shares its token count before dispatch. When
the counts differ, they become the split sizes of the three gathers and of the
combine reduce-scatter. Equal-count steps, training, and CUDA-graph capture keep
the existing path. The affected inference runs now complete instead of hanging.

## Example failure scenario(s)

**Scenario 1 (MTP draft with an idle EP rank)**
- With EP=2 and an MoE MTP draft head, rank 0 holds requests A and B and rank 1
  holds none.
- Rank 0's eager MTP draft forward dispatches 2 tokens, while rank 1's dummy
  MTP forward dispatches 1.
- The equal-size all-gather cannot match these sizes, so both ranks block in
  the expert dispatch forever.
- With only request A on rank 0, both ranks dispatch 1 token and the run
  completes.

**Scenario 2 (two busy EP ranks)**
- With EP=2 and an MoE MTP draft head, rank 0 holds requests A and B and rank 1
  holds requests C, D and E.
- The two ranks' MTP draft forwards dispatch 2 and 3 tokens.
- Both ranks block in the expert dispatch, although neither rank is idle.

**Scenario 3 (MoE decoder without MTP)**
- With EP=2 and a GPT model with MoE layers, rank 0 holds requests A and B and
  rank 1 holds none.
- Rank 0's first prefill dispatches 8 padded tokens, while rank 1's dummy
  decode forward dispatches 4.
- Both ranks block before the first step finishes.

## How was this bug discovered?

An engine test with an MoE MTP draft head, EP=2 and one idle rank hung with two
requests on the other rank and passed with one. To find where, a test wrapper
all-gathered each rank's token count before every allgather dispatch. It showed
counts of `[2, 1]` at an MTP draft dispatch. Stack dumps after a timeout showed
the busy rank blocked at the first host sync after the gathers
(`tokens_per_expert` in `dispatch_postprocess`). The idle rank waited in the run
loop's next EP all-reduce.

The oracle was the same scenario with the all-to-all dispatcher, which exchanges
split sizes: it completes. The engine also documents that its non-graph path
handles variable token counts. Widening the search showed the same hang with 2
and 3 requests on two busy ranks, with legacy scheduling, and with an MoE
decoder and no MTP. One request per rank, or the all-to-all dispatcher,
completed every time.

## Scope

- Production: `megatron/core/transformer/moe/token_dispatcher.py`,
  `MoEAllGatherTokenDispatcher` only (+37/−4). The unequal splits reuse the
  existing `output_split_sizes` and `input_split_sizes` support of
  `gather_from_sequence_parallel_region` and
  `reduce_scatter_to_sequence_parallel_region`.
- Cost: during eager inference, one `int64` all-gather and one host sync per
  MoE layer per forward. The allgather path already host-syncs per layer for
  `tokens_per_expert`.
- Behavior is unchanged for:
  - training, because the engine clears the flag when it suspends, so RL
    training between inference phases is unaffected;
  - CUDA-graph capture and replay, because graphed steps are already padded to
    EP-synced sizes;
  - equal-count eager steps, which only pay the count exchange;
  - the all-to-all, Flex, NCCL and NVLS dispatchers.
- Engine regression: `test_dynamic_engine_parallel_and_chunked_prefill.py`
  (+87), `test_allgather_moe_with_an_idle_ep_rank`, with an MoE MTP draft head
  and an MoE decoder. Two requests run on one EP rank while its peer stays idle
  and runs dummy forwards, as the engine's run loop does.
  - It records every allgather dispatch's per-rank token counts and requires at
    least one unequal dispatch.
  - It requires both requests to complete with exactly their requested output
    lengths.
  - Without the fix, both cases block in the dispatch rather than raise.
- Determinism: `tests/unit_tests/determinism/kernels/test_moe_kernels.py` (+41),
  `TestMoEModules::test_allgather_moe_layer_replays_with_unequal_inference_token_counts`.
  - Two EP ranks hold 1 and 38 tokens under `InferenceMode`.
  - The allgather MoE layer must dispatch with split sizes `[1, 38]`.
  - It must replay bit-exactly three times under stream contention.
  - The `moe_token_dispatchers` manifest note now lists this case (+1).
