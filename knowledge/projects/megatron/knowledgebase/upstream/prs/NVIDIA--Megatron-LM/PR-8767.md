# Deprecate use_mpu_process_groups outside core and close its silent paths

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8767) · state: closed · merged: False

## Original PR description

Depends on #8766, which stacks on #8765 and contains #8747, #8761, #6293, #8037 and #8049. This branch also merges #8728. Please review the diff from the merge of #8766 and #8728: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/ad85e66a85...yx/pstate-a2-mpu-shim).
- The shim's deprecation reuses #8765's warning machinery. Its note in `docs/api-backwards-compatibility-check.md` edits the text that #8766's last commit writes.
- #8728 binds `args` to the ModelOpt builder in the same `get_model()` calls that this PR gives the registered collection. The merge keeps #8728's comment and calls `get_model(partial(modelopt_gpt_hybrid_builder, args), wrap_with_ddp=False, pg_collection=pg_collection)` in `megatron/inference/utils.py` and `tools/run_text_generation_server.py`. The commit after the merge makes the entry-point test's ModelOpt fixture call the bound builder the way `get_model()` does. If this PR lands before #8728, the merge and that commit move to #8728.
- Draft #8694 changes lines next to this PR's change in `tools/run_inference_performance_test.py`. Whichever lands second keeps both.

#8768 stacks on this PR.

**Why.** `ProcessGroupCollection.use_mpu_process_groups()` rebuilds a collection from the global `parallel_state` grid. It did not warn: the accessors it calls are called from a Megatron Core file, which is exempt from `ParallelStateDeprecationWarning`. Some in-repo paths reached the grid through it without any warning:
- the BERT and T5 model providers;
- the detoxify sampling provider, which also failed under `get_model()`;
- `get_model_for_inference(pg_collection=None)`, whose default every in-repo inference entry point relied on.

Many inference entry points, the ModelOpt example scripts, the vision converter check and the refit benchmark also built their models with `get_model()` and no groups. They warned on every run and raised under `--strict-process-group-fallbacks`. Callers of the shim got no signal and no removal date.

**What.**
- The BERT, T5 and detoxify model providers and `get_model_for_inference()` fall back inside `global_process_group_fallback()`, deprecated in 0.21 and removed in 0.23. The detoxify provider now takes the `config` and `pg_collection` that `get_model()` passes.
- These callers pass the registered collection, `parallel_state.get_registered_process_groups()`, so a stock run takes no fallback:
  - `tools/run_inference_performance_test.py`, `tools/run_text_generation_server.py` (both branches), `tools/run_dynamic_text_generation_server.py` and `tools/run_vlm_text_generation.py`;
  - `examples/inference/offline_inference.py`, `examples/inference/launch_inference_server.py`, the four scripts in `examples/inference/advanced/`, and `examples/multimodal/run_text_generation.py`;
  - the Dynamo engine service;
  - the ModelOpt example scripts (`export`, `generate`, `mmlu`, `offline_feature_extract`, `prune`, `quantize`, `validate`), `examples/multimodal/model_converter/vision_model_tester.py` and the detoxify sampler;
  - the source model of `examples/rl/benchmark_refit.py`, whose provider now also forwards the collection to the GPT builder.
- `get_dynamic_inference_engine()` takes an optional `pg_collection` for the model it builds when `model` is omitted. Before, it read the registered collection, which a framework may have registered with fields unset.
- The ModelOpt path of `get_model_for_inference()` accepts the registered collection.
- The BERT and T5 `forward_step`s pass the model's groups: `get_batch()` broadcasts over its TP group, and the BERT loss averages over its `dp_gtp_remat` group, the group the fallback used. Stock runs no longer fall back on every micro-batch.
- Bootstrap sites that rebuilt a grid's collection through the shim take that grid's collection instead. The simple training loop and the two TRT-LLM export examples use `initialize_model_parallel()`'s return value. AVLM inference, ModelOpt `convert_model` and the text generation server use the registered collection.
- `_initialize_distributed()` and `_build_pg_collection_from_parallel_state()` keep the shim, in a block that ignores its deprecation warning. A framework may have registered a partial collection, and the second one adds groups to the collection it returns. #8768 moves both to the registry.
- Called from outside Megatron Core, `use_mpu_process_groups()` emits `ParallelStateDeprecationWarning` once per call site, attributed to the caller. It is deprecated in 0.21 and removed in 0.23. The message names the replacements: pass a `ProcessGroupCollection`, or use `get_registered_process_groups()`.
  - It keeps the accessors' exemptions: callers in Megatron Core, calls in a fallback block, and code that `torch.compile` traces. Core fallbacks still emit exactly one `ProcessGroupFallbackWarning`.
  - The 22 warned fallbacks outside Megatron Core that called the shim now call it in `global_process_group_fallback()` blocks. Checkpointing drops `_warn_global_grid_fallback()`, which has no caller left.
  - `test_parallel_state_accessor_uses.py` flags a shim call outside a fallback or bootstrap block.
- `docs/api-backwards-compatibility-check.md` lists the shim and its replacement. It says to set fields on a `copy.copy()` of the registered collection, and names the `megatron.core.utils` replacements of the memory-buffer aliases. The docstring example of `create_all_gather_groups()` copies the collection before it sets the all-gather groups, and the datasets readme points legacy entry points at the registered collection.

**Tests.**
- New `tests/unit_tests/inference/test_inference_entry_point_groups.py` and `tests/unit_tests/test_example_process_groups.py`:
  - the entry points and providers build on the given or registered groups, and warn without them;
  - the example-provider test stubs `get_run_config()` as well as `get_args()`, since main's #8391 makes the BERT provider read the run config first;
  - `get_dynamic_inference_engine()` without groups falls back to the grid, not to a partially registered collection;
  - the refit benchmark builds its source model and GPT builder on the registered collection in both modes;
  - static checks that every in-tree call of `get_model_for_inference()` and `get_dynamic_inference_engine()`, and every call of `megatron.training`'s `get_model()` outside the tests, passes groups. The `get_model()` check resolves imports and aliases, relative ones included, and does not count a literal `pg_collection=None`.
- 8 new tests in `test_parallel_state_deprecation.py`. The shim warns outside core before it reads the grid, once per call site, and raises under an error filter. It stays silent in a fallback block and from core, stays a warning under strict mode, and returns the same collection as before. Stock bootstrap stays silent under strict mode.
- Self-tests for the extended guard. The detoxify sampler test checks that `main()` passes the registered object itself.

**Compatibility.**
- Downstream callers of the shim, such as Megatron-Bridge and NeMo-RL, get `ParallelStateDeprecationWarning`, a `FutureWarning`, once per call site. Test suites that turn `FutureWarning` into errors fail until they migrate or filter `megatron.core.parallel_state.ParallelStateDeprecationWarning`.
- To migrate, pass the model's collection or `parallel_state.get_registered_process_groups()`. That returns the registered object itself, with only the fields its registrant set. Set fields such as `dp_cp_ag` on a `copy.copy()` of it: `copy.deepcopy()` returns the same object, and `dataclasses.replace()` returns one without groups.
- New `ProcessGroupFallbackWarning`s, which raise under strict mode, for callers that omit their groups:
  - `get_model_for_inference()`;
  - `get_dynamic_inference_engine()` with neither `model` nor `pg_collection`. It builds the same full collection from the grid as before;
  - the BERT, T5 and detoxify `model_provider`s.
- Stock BERT and T5 training no longer emit the per-micro-batch `get_batch` and BERT loss fallback warnings. Called without groups, `get_batch()` and `loss_func()` keep their warned fallback.
- The scripts that now pass the registered collection build their model right after `initialize_megatron()` and do not wrap it in DDP. On the grid that `initialize_megatron()` builds, that collection holds the same groups as `get_model()`'s fallback. The fallback also adds the all-gather groups of `--create-all-gather-group`, which only the Megatron-FSDP wrap uses.
- The ModelOpt path of `get_model_for_inference()` still rejects any collection other than the registered one.
- No signature breaks. Every new parameter is optional and keyword-compatible. `get_dynamic_inference_engine`'s `pg_collection` comes after `engine_class`.
- The detoxify sampler, `tools/run_vlm_text_generation.py` and `examples/multimodal/run_text_generation.py` still import the removed `megatron.inference.text_generation`, so they cannot be imported. Their changes are checked statically. This PR does not fix the import.
- `examples/rl/benchmark_refit.py` needs review from the `examples/rl` code owners.
- `determinism-exempt` is needed only while the PRs below this one are unlanded. CI diffs against main, and the base contains registered kernel files. This PR's own diff passes the coverage check.
