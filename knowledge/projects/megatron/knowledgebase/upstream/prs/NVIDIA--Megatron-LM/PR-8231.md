# [Dev] Release MoE dispatcher routing tensors after combine

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8231) · state: closed · merged: True

## Original PR description

# What does this PR do ?

Releases the routing tensors the all-to-all dispatcher caches for `combine_postprocess` as soon as combine has read them.

`MoEAlltoAllTokenDispatcher.dispatch_preprocess` stores `probs`, `routing_map` and the permutation mappings on the dispatcher, and they stayed there until the layer's next forward. `probs` carries the router's autograd graph back to the layer input, so under full activation recompute every MoE layer kept its checkpointed input and that input's gradient alive for the rest of the step.

`combine_postprocess` now drops them through `_release_routing_tensors()`, which `reset_transient_forward_state()` (#5869) also uses; that reset only runs in the EP A2A-overlap schedule. Shapes stay, because CUDA graph replay of the preprocess restores only tensor attributes.

The Flex dispatcher had the same leak: its comm managers (DeepEP, DeepEP v2, HybridEP, NCCL EP) kept `token_probs` after combine. Its `combine_postprocess` now calls the manager's existing `reset_transient_forward_state()`, whose attributes are documented as reassigned on the next forward and unread by backward.

## Memory

One H200, a `TransformerBlock` of MoE layers (alltoall dispatcher, TE spec), seq 4096, hidden 4096, 8 experts, top-2, forward + backward, on `dev` at c3010d6:

| | peak, `dev` → this PR | held by dispatchers after backward | step time |
|---|---|---|---|
| 8 layers, full recompute | 3875 → **3458 MiB** (−10.8%) | 481 → 0 MiB | 102.3 / 103.7 ms |
| 16 layers, full recompute | 7461 → **6531 MiB** (−12.5%) | 995 → 0 MiB | 170.4 / 172.5 ms |
| 8 / 16 layers, no recompute | unchanged | 1–2.5 → 0 MiB | within noise |

Flex dispatcher with the DeepEP backend, EP = 8 on 8×H200, 8 layers, full recompute (per rank): peak 2253 → **1836 MiB** (−18.5%), held by the comm manager after backward 482 → 0 MiB. Flex step time is unchanged. Measured in one process, alternating steps with the reset enabled and disabled (ABBA, 20 steps each): 107.6 vs 106.6 ms median with full recompute, 74.9 vs 77.0 ms without. Separate back-to-back runs on this box varied from 117 to 411 ms for the same configuration, so they cannot resolve the difference.

About 62 MiB per layer here, which matches the layer input plus its gradient (2 × 4096 × 4096 × 2 bytes); the saving scales with tokens per rank × hidden size × MoE layers. Not exercised: alltoall with EP > 1, the HybridEP / NCCL EP backends (not installed on the test box), CUDA graphs, the EP A2A-overlap schedule.

## Strict review: [Dev] Release MoE dispatcher routing tensors after combine

**Findings: 1 CRITICAL, 1 IMPORTANT, 1 SUGGESTION.**

The single-stream change is sound. Releasing the tensors after `unpermute` is safe for the A2A dispatcher under plain or full recompute. It is also safe under partial CUDA-graph replay, because every released A2A attribute is in `cudagraph_attrs` and the shapes are kept. Two paths the PR says it did not exercise regress:

1. **CRITICAL Correctness** (inline, [token_dispatcher.py#L960](https://github.com/NVIDIA/Megatron-LM/blob/d458f553539a829e6a1a9d77b1149172c9f8b0e2/megatron/core/transformer/moe/token_dispatcher.py#L960)). Affects the alltoall dispatcher with `overlap_moe_expert_parallel_comm` and full recompute. The permutation mapping is allocated on the compute stream and read by `unpermute` on the communication stream. The new release then drops its last reference without `record_stream`. That is a cross-stream use-after-free, overlapped by design with `attn` backward on the compute stream.
2. **IMPORTANT Correctness** (inline, [token_dispatcher.py#L2344](https://github.com/NVIDIA/Megatron-LM/blob/d458f553539a829e6a1a9d77b1149172c9f8b0e2/megatron/core/transformer/moe/token_dispatcher.py#L2344)). Affects HybridEP drop-and-pad with a `moe_preprocess` partial CUDA graph. The per-forward manager reset clears the static `tokens_per_expert`. Only `setup_metadata` writes it, and graph replay skips `setup_metadata`. From the second replayed forward on, the experts get `None`. This configuration is covered by the existing `test_moe_partial_cudagraph`.
3. **SUGGESTION** (below). There is no regression test for the new release-after-combine contract.

**Overall risk: high** for alltoall runs using EP A2A overlap with full recompute: silent corruption of the MoE output and gradients, or device-side asserts. **Moderate** for HybridEP drop-and-pad with partial CUDA graphs: a deterministic failure. Everything else looks correct.

### Checked and not flagged
- **A2A readers.** `combine_preprocess` reads `self.probs.dtype` and `routed_experts_compute` reads `token_dispatcher.routing_map`, both before `combine_postprocess`. `hidden_shape` is read after the release but is not cleared.
- **A2A partial-CUDA-graph replay.** `probs`, `routing_map`, `reversed_local_input_permutation_mapping` and the batch-invariant map are all in `cudagraph_attrs`, so replay restores them every forward.
- **DeepEP / DeepEP v2 / NCCL EP.** `dispatch()` always reassigns `tokens_per_expert`. `combine_preprocess` reads `reversed_mapping_for_combine`, `dispatched_routing_map` and `pad_offsets` before the reset. NCCL EP's `num_local_tokens` is not in the reset list.
- **Flex under EP overlap.** Each tensor released on the comm stream is either allocated on the comm stream, or last read on the compute stream before the `mlp` node's event wait. Nothing is read cross-stream after it is freed, unlike the A2A mapping.
- **Inference dispatchers** subclass `MoEAllGatherTokenDispatcher` and are unaffected.

**Correction.** In `MoEAlltoAllTokenDispatcher.combine_postprocess`, record the current stream on every tensor handed to `unpermute` before releasing them. Replace this line with:
```python
        current_stream = torch.cuda.current_stream()
        for routing_tensor in (
            self.reversed_local_input_permutation_mapping,
            self.routing_map,
            self.batch_invariant_inverse_permutation_mapping,
        ):
            # Allocated on the compute stream by dispatch_preprocess; under EP A2A overlap the
            # unpermute above reads them on the communication stream.
            if isinstance(routing_tensor, torch.Tensor) and routing_tensor.is_cuda:
```
