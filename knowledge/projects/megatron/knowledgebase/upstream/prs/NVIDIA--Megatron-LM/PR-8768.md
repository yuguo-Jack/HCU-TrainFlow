# Read the bootstrap process groups from the registry

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8768) · state: closed · merged: False

## Original PR description

Depends on #8767, which contains #8766, #8765, #8747, #8728, #8037 and #8049. Please review the diff from the merge of #8767: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/f3bb71f061...yx/pstate-d4-bootstrap-registry).
- #8767 deprecates `use_mpu_process_groups()` outside Megatron Core and keeps the two bootstrap reads of it that this PR replaces.
- #8747 adds the registry. #8037 adds `_build_pg_collection_from_parallel_state()` and the all-gather `ValueError` that this PR drops. #8765 deprecates the tensor-parallel setters that `--lazy-mpu-init` calls.

#8775 stacks on this PR and builds the finetuning and BERT embedding models on the run's process groups.

**Why.**
- `pretrain()` and `initialize_megatron()` built their collection with `use_mpu_process_groups()` in a block that ignored its deprecation warning. That kept stock runs quiet, but the shim and the accessors it reads are removed in 0.23, so this path would break then with no notice beforehand.
- `--create-all-gather-group` read the global grid: the dense groups from the weight layout, and the expert groups from a `RankGenerator` in the default rank order, without the rank offset and with an expert data-parallel size that includes expert GTP. With another rank order, `pretrain()` rejected the groups with a `ValueError`. With expert GTP they named ranks outside the world, and `new_group()` raised.
- `--lazy-mpu-init` set the tensor-parallel overrides in a block that ignored their deprecation warning, so its users had no notice that the overrides go away in 0.23.
- `--distributed-timeout-seconds-after-init` raised `TypeError` on runs whose groups a framework built, such as a multi-module run on `HyperCommGrid` groups. Those runs never call `create_group()`, so its record stayed `None`.

**What.**
- `pretrain()` and `initialize_megatron()` take the groups of the registered collection, `parallel_state.get_registered_process_groups()`. `_registered_pg_collection()` copies them into a new collection field by field, the way the shim built it: an unset field is `None`, `dynamic_cp` and `dynamic_tp_cp` are new dictionaries, and `dp_cp_ag` and `expt_dp_ag` are `None`.
  - A grid set up without registering a collection is still read with the shim, in a `global_process_group_fallback()` block that warns once (deprecated in 0.21, removed in 0.23). No in-repo path does this: `initialize_model_parallel()` and `register_process_groups()` are the only writers of the grid.
  - `initialize_megatron()` reads a grid set up before it only when it seeds from that grid, not when `seed_pg_collection` is passed or seeding is skipped.
- `create_all_gather_groups(pg_collection=...)` mirrors the collection's `dp_cp` and `expt_dp` groups in any rank order.
  - Each rank all-gathers only the lowest rank of each of its two groups, so startup moves O(world size) data. Every rank rebuilds the groups from those ranks and creates them in the same sorted order, with the timeout, NCCL options and group descriptions used before.
  - `pretrain()` passes its collection and drops the default-order `ValueError`, which this construction makes unreachable.
  - Called without a collection, the function builds the groups it built before and emits a `ProcessGroupFallbackWarning` (deprecated in 0.21, removed in 0.23).
- With `--lazy-mpu-init`, `initialize_megatron()` emits one `ParallelStateDeprecationWarning` (deprecated in 0.21, removed in 0.23) for both setters, attributed to its caller. It names the replacement: build the model after the returned function has built and registered the grid, on `get_registered_process_groups()`. The setters set the same values. Strict mode leaves the warning a warning, as for the other deprecated functions.
- `update_pg_timeout(pg_collection=...)` also updates each group of the collection that `create_group()` did not record, once. An empty record means the default group alone. `train()` passes the run's collection, so a stock run updates the same groups as before.
- The docstrings of `create_group()` and `update_pg_timeout()`, and the deprecation notes, say that these functions manage the lifetime of the groups `parallel_state` creates, read no grid, and are not deprecated.

**Tests.** New `tests/unit_tests/training/test_bootstrap_process_groups.py`:
- the new collection equals the shim's on ten grid layouts and on collections that a framework registers, and it refuses what the shim refused;
- an unregistered grid falls back with one warning and raises under strict mode, and `initialize_megatron()` reads a grid set up before it only to seed from it;
- the all-gather groups mirror the collection on the default order, on the tp-cp-ep-pp-dp order with pipeline and expert data parallelism (8 ranks, where `pretrain()` raised before) and with expert GTP (4 ranks, where the groups could not be built). Each rank exchanges one rank per group, and the fake backend works;
- `--lazy-mpu-init` warns once;
- the timeout update reaches the collection's groups, also on a grid that a framework built.

Tests that set the global groups without registering them now register a collection. Tests that call `create_all_gather_groups()` without one expect its warning.

Before the sync, the branch ran 6 test files on 4 CPU ranks with Gloo: 234 passed, the same per test as on the stacked version. The 26 new tests passed, and 3 base tests that this PR replaces are gone. 23 failed, as on the stacked version: 8-rank layouts run at 4 ranks, CUDA-only tests and rank-order checks. The 8-rank cases (`-k tp2_pp2_ep2`) need 8 GPUs. The process-group checker was unchanged at 139 entries, 15 of them guarded.

**Compatibility.**
- Stock runs build the same groups and emit no new warnings.
- Only new optional keyword arguments; nothing is removed. `_initialize_distributed()` gains `read_initialized_grid`, which defaults to `True`.
- A registered collection without a data-parallel group that the shim's accessors asserted on, or without `tp` under dynamic context parallelism, raises `ValueError` instead of `AssertionError`. It does so only when bootstrap reads the collection.
- `create_all_gather_groups(pg_collection=...)` requires the groups to partition the ranks that have them, as a parallel grid's groups do. It does not check this, because any check breaks `--fake-process-group`. Groups that do not partition the ranks hang or fail in NCCL instead of raising a clear error. Both docstrings state the requirement.
- `pretrain()` does not support `--lazy-mpu-init`, before or after this change: it discards the returned function and then needs the grid.
- `megatron/training/training.py` imports the private `_registered_pg_collection` from `initialize.py`.
- `determinism-exempt` is needed only while the PRs below this one are unlanded. CI diffs against main, and the base contains registered kernel files. This PR's own diff passes the coverage check.
