# [dev][kimi-k3] Fix: Fall back to legacy_soap when Emerging-Optimizers has no soap module

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8946) · state: open · merged: False

## Original PR description

The main-to-dev sync (#7960) pins Emerging-Optimizers v0.3.0 and imports ``emerging_optimizers.soap`` unconditionally inside the single try/except that guards every optimizer import. Emerging-Optimizers >= 0.5.0a0 (a44d1f83, the revision in the Kimi-K3 container) moved SOAP to ``emerging_optimizers.legacy_soap`` with the registry name unchanged, so on that package the import fails, ``HAVE_EMERGING_OPTIMIZERS`` becomes False and ``--optimizer muon`` is rejected at startup.

Import SOAP from ``legacy_soap`` when ``emerging_optimizers.soap`` is missing, in the optimizer module and in its unit test, so both the v0.3.0 and the 0.5.x layouts work.
