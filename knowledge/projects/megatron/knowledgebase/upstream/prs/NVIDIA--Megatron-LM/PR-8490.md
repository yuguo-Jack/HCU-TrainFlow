# test(inference): add sampling output coverage foundation

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8490) · state: open · merged: False

## Original PR description

## What does this PR do?

This PR adds a unit-test foundation for sampling and output correctness in dynamic inference. It checks scores against an independent float32 calculation, and it runs a mixed set of requests through the real engine under both schedulers. It changes no production code, and every test passes on unmodified `main`.

The foundation adds:

- `test_sampling_oracle.py`: an independent float32 temperature/top-k/top-p and score oracle for known logits, an analytic check of stochastic top-p sampling, and a contract test for exact ties;
- `test_sampling_output_matrix.py`: an end-to-end engine case with three requests that use different score settings and stop rules, run under the legacy and async schedulers with both sampling backends, plus a case for a reordered request-metadata schema;
- a stronger MTP rejection test in `test_dynamic_engine.py`, which now runs the real model forward and MTP head, counts real KV rewinds, and checks that every generated token's top-N entry matches its log probability;
- prompt-score and top-N checks added to the existing FP8 offload lifecycle case, finish-reason checks in the recompute lifecycle test, and per-request seeds in one async metadata case; and
- two small test-harness fixes needed by these tests (see Scope).

## How was the test matrix determined?

An audit of the existing sampling tests found three gaps:

1. Most score checks compared one backend or scheduler with another, so a shared mistake would pass.
2. No test finished a middle request while requests on either side kept generating with different score settings, which is when per-request metadata is compacted on the GPU.
3. The MTP rejection test mocked both the model forward and the MTP head.

The matrix therefore has three layers:

1. **Oracle layer.** Probabilities are checked against an independent float32 calculation, so a backend cannot agree with itself and still be wrong.
2. **Engine layer.** One workload forces stop-word stops, stop-token stops, a length finish, mixed score requests and middle-request compaction. It runs under both schedulers with both sampling backends.
3. **Targeted strengthening.** The existing MTP and lifecycle tests now check real scores.

This is differential coverage, not every combination of sampling flags. Cases that need either sampling/output fix are excluded here and live with their fixes.

## What combinations are tested?

### Independent oracle (6 cases)

| Case | Backend | Logit dtype | Checked against |
| --- | --- | --- | --- |
| Known logits, filters and scores | Torch | FP32 | Float32 temperature/top-k/top-p oracle |
| Known logits, filters and scores | FlashInfer | FP32 | Same oracle |
| Known logits, filters and scores | FlashInfer | BF16 | Same oracle |
| Stochastic top-p | Torch | FP32 | Analytic top-p distribution |
| Stochastic top-p | FlashInfer | FP32 | Analytic top-p distribution |
| Exact ties | Torch and FlashInfer | FP32 | Documented tie contract, with no claim of identical choices across backends |

### Engine matrix (3 cases)

Each case runs the same three requests under the legacy scheduler and the async scheduler, then compares them.

| Request | Sampling settings | Expected result |
| --- | --- | --- |
| A | top-k 1, log probs on, top-3, stop words `"12 13"` and `"11 12 13"` | Stops on a stop word, with no generated tokens |
| B | top-k 1, log probs on, top-1, stop tokens 22 and 55 | Generates tokens 21 and 22, then stops on token 22 |
| C | top-k 2, log probs off, no top-N | Generates 4 tokens and finishes by length |

| Case | Sampling backend | Request metadata schema |
| --- | --- | --- |
| `test_heterogeneous_scores_stops_and_middle_compaction[torch]` | Torch | Default |
| `test_heterogeneous_scores_stops_and_middle_compaction[flashinfer]` | FlashInfer | Default |
| `test_custom_metadata_schema_survives_gpu_compaction` | Torch | Built-in fields in a different order |

### Strengthened existing tests

| Test | What is added |
| --- | --- |
| MTP rejection scores (`test_dynamic_engine.py`) | Real forward and MTP head, a count of real rewinds, and top-2 entries that match each generated token's log probability |
| FP8 offload lifecycle case | Prompt log probabilities and top-3 entries with one row per prompt token after the first |
| Recompute lifecycle | Every request finishes by length |
| Async metadata case | Distinct per-request seeds |

## How are results checked?

The oracle tests compute raw log probabilities from the unfiltered logits and processed probabilities from a separate float32 implementation. They check finite support, normalization, selected-token membership, the difference between raw and processed scores, and the top-p distribution against its analytic value.

The engine cases check:

- the exact generated tokens and finish reason for each request;
- that each request's token events match its generated tokens;
- that the middle request finishes while the other two continue, and that the scores and metadata of those two remain correct afterwards; and
- that legacy and async runs agree on tokens, finish reasons, prompt and generated scores (to 1e-4) and top-N rows.

Under top-k 1, unselected alternatives all score negative infinity, so top-N rows are compared by size and score values rather than by token identity.

## Scope

This PR is test-only. It changes 9 files under `tests/unit_tests/` (+621/−24) and makes no production, functional-test, configuration or golden change. The whole sampling/output series adds 616 net unit-test lines.

One harness change is needed by existing tests: `test_gpt_model_batch_invariant.py` now imports `megatron.rl` lazily. The existing Mamba prefix-caching test imports helpers from this module and should not require the RL extras. This PR no longer changes `test_utilities.py`: main (NVIDIA/Megatron-LM#7575) now restores the frozen PyTorch backend flags there.

The BF16/FP16 temperature regressions belong to lmcafee-nvidia/Megatron-LM#107, and the KV-cache initialization regression belongs to lmcafee-nvidia/Megatron-LM#120. No test needs both fixes, so this series has no separate tests PR.
