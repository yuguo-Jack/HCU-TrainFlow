## Original PR description

The TP8 `TestRouterAuxLoss.test_force_balanced_aux_loss[8-1-1]` case repeatedly hits a 30-minute Gloo group-creation timeout, leaving the MoE CI bucket cancelled after about an hour. Mark only this parameterization `flaky_in_dev` so dev PR and merge-queue validation exclude it while the initialization fix in #8164 is validated.

The four other parameterizations and LTS eligibility are preserved. The test body, fixtures, parameter values, and node IDs are unchanged. Both full execution and Testmon selection/execution use the existing dev marker filter.

Tracking: #7745. This is temporary containment; keep that issue open and re-enable the case after the process-group fix passes repeated eight-rank H100 validation.

Evidence:
- [#7685: repeated Gloo timeout and one-hour cancellation](https://github.com/NVIDIA/Megatron-LM/actions/runs/38393730937/job/115284619673).
- [#7709: same case and timeout](https://github.com/NVIDIA/Megatron-LM/actions/runs/38465606155/job/115534040422).

Validation:
- Whole-file AST comparison confirms the parameter marker is the only semantic change; `git diff --check` passed.
- Actual pytest collection verifies five unchanged node IDs, four selected under the dev filter, and all five eligible under the LTS filter. This was collection only in the cached CI container, using an import-time architecture-query shim with CUDA unavailable; no GPU fixtures or test bodies ran.
- Repository Black, isort, pylint, and Ruff checks passed. The autoformat script's optional mypy command was unavailable in the cached image.
