# Add page-contiguous copy and MXFP8 activation storage to the MoE page…

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8589) · state: open · merged: False

## Original PR description

…d stash

Two opt-in TransformerConfig options for the paged activation stash:

- moe_paged_stash_page_copy: copy/pop kernels that move whole pages in contiguous 16 KiB chunks instead of one row per iteration. Results are bit-identical to the row kernels; narrow rows copy faster (FP32 router probs 2.6x, 1024-byte rows 1.7x), wide rows about the same.
- moe_paged_stash_mxfp8_activations: stash BF16 activations (power-of-two row size) as MXFP8 rows (E4M3 values + one E8M0 scale per 32 elements) and decode to BF16 on reload. Lossy; halves the stash buffer of the expert SwiGLU input in FP8/FP4 models.

Also moves the columnwise-scale token-count division into the kernels and drops the per-stash zeroing of page_record/spilled_to_host (the copy kernels write both, including on the overflow path), saving three small launches per stashed tensor.
