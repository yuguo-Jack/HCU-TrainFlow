# What does this PR do?

Move runtime-service initialization into `initialize_megatron()`, after run-config validation and before distributed/RNG setup.

- Training entrypoints construct/register the config and call `pretrain()`; inference entrypoints call `initialize_megatron()` without separately constructing runtime services.
- Resolve tokenizer-derived vocabulary centrally after tokenizer construction, before writers and other services consume it. Preserve explicit and checkpoint-restored vocabulary.
- Forward `build_tokenizer=False` for heterogeneous MiMo, which supplies its own tokenization.
- Keep the lightweight checkpoint-converter bootstrap, validating its config before creating services.

Most entrypoint changes remove the old explicit runtime/vocabulary calls and their imports. This does not change config ownership, training/inference selection, or distributed/RNG behavior.

This is the separate startup-order follow-up discussed in #7778; #7778 does not depend on it. Pending #7778 and #8149 changes will need to be merged here once they land.

There are a couple config in the inference container that are environment-dependent: `--inference-kv-cache-management-mode` and `--inference-static-kv-memory-pointers`. They both require `torch_memory_saver` to be installed under some of the argument values.

This validation check leads to an odd case, where a checkpoint that was RL-trained on a machine that has `torch_memory_saver` can fail validation if the checkpoint is loaded on a machine without `torch_memory_saver`.

I think that before this PR, most codepaths already did validation and would encounter this issue. But I see that `tools/checkpoint/convert.py` specifically did not validate before this, and this is new behavior.

I don't think this is a problem. But I'm noting it down here, because it's a strange interaction.
