# What does this PR do?

Adds first-class layer-config lists to the Core `HybridModel` API while preserving string-defined architectures.

This is PR 2 of the split of #7153, based directly on `main` after #7370 merged. The original PR and branch are unchanged.

## Scope

- Accept `hybrid_layer_config_list`, mutually exclusive with pattern/deprecated architecture inputs; export `PipelineSplit` and `MTPSplit` sentinels.
- Parse config objects directly, validate decoder counts and repeated MTP template identity, infer MTP depth, and select explicit PP/VPP segments without generating pattern strings.
- Clone physical layer configs while preserving caller-owned configs, heterogeneous fields, and explicit initializer callables.
- Normalize hybrid MTP patterns to config lists immediately and use an explicit hybrid-MTP discriminator throughout. Preserve repeated-layer and BF16 MTP behavior.
- Include the necessary pipeline auxiliary-loss scaling, MTP router indexing, CUDA-graph rotary selection, and FSDP MTP naming adaptations.
- Carry the existing tiny Puzzle-like forward/backward unit test and MTP/FSDP test fixture updates with the core implementation.

Training/configuration-builder integration, FLOP reporting, training checkpoint family/resume handling, the Puzzle example, and functional-test recipes are deliberately excluded. No optimizer or dependency changes.

File: `megatron/core/models/hybrid/hybrid_model.py` · line 485

Can we use each attention layer's kv_channels when building RoPE, or reject different head widths for now? The config-list path accepts different widths, but this still builds one rotary embedding from the root config. With 64 on the root and 32 on a layer, the rotary multiply fails on the first forward pass. If the layer is wider than the root, only part of the head gets rotated.

- guihong-nv · comment · 2026-10-08T18:22:53Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/7555#discussion_r4222651355)

File: `megatron/core/models/hybrid/hybrid_model.py` · line 338

Can we also detect DSA layers here and set up their auxiliary-loss scaling? A DSALayerConfig can enable indexer loss while experimental_attention_variant is unset on the root config. The scheduler then skips DSAIndexerLossAutoScaler, leaving its default scale at 1. With CP=1, eight microbatches, no extra gradient scaling and per-token loss disabled, that makes the indexer gradients eight times too large.
