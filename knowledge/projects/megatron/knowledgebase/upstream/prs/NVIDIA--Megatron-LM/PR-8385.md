# fix(inference): bound batch-invariant MoE work by live rows, not worst-case buffers

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8385) · state: closed · merged: True

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Batch-invariant (BI) inference with MXFP8 routed experts does work proportional to `max_tokens` on every decode step, whatever the number of live tokens. This PR bounds that work by the live rows, which the kernels already read on device. CUDA graphs keep their static shapes, and the quantized and reduced rows are bitwise unchanged.

It also removes an illegal memory access. The MXFP8 quantize kernel indexes rows in int32, so a worst-case buffer of 2^31 elements or more faults (see Problem).

## Problem (file:line on main, fce1e2051)

The fused-MoE buffers are sized `max_tokens x EP x topk` rows for CUDA graphs. Under BI, several steps then walk all of them:
- `fused_moe.py:268`: the fc2 input (activation output) is quantized with `MXFP8Tensor.from_bf16` over every row. BI turns off the fused activation+quantize (`fused_moe.py:169`).
- `permute.py:774-781`: `permute_and_quantize_mxfp8(zero_padding=True)` memsets the whole fp8 buffer (`torch.zeros`) only to zero the alignment padding.
- `batch_invariant.py:468`: `unpermute_tokens_in_expert_order` launches one CTA per worst-case token.
- `batch_invariant.py:88,139`, `permute.py:286,327,645`: grid-stride loops run to `max_rows`/`max_pairs` and skip the dead rows inside the loop.
- `mxfp8_quantize.py`: `row = tl.program_id(0)` is int32, so `row * K` overflows once rows x K reaches 2^31. Example: max_tokens 73728 x EP4 x topk 6 = 1.77M rows x 1856.

Profile (eager, EP4, 8 live rows, max_tokens 73728, the tree before #7660): `_mxfp8_quant_swizzle_kernel` took 80.7 ms per decode step over 46 calls. Next were BI unpermute 10.7 ms, zero padding 4.0 ms, permute 4.4 ms and BI relu^2 4.1 ms.

## The change

- `mxfp8_quantize_rows(x, n_rows)`: a persistent kernel with a fixed grid that quantizes rows `[0, n_rows)`, with `n_rows` read on device. It indexes rows in int64. The per-row code is factored out of `_mxfp8_quant_swizzle_kernel` (`_mxfp8_quant_swizzle_row`), so both paths emit the same bits. `fused_moe` uses it in BI mode for the unfused quantizations.
- `permute_and_quantize_mxfp8(zero_padding=True)`: `torch.empty` plus zeroing of only the padding rows below `n_used`, after the permute (`_zero_permutation_padding_kernel` on the byte view).
- `unpermute_tokens_in_expert_order`: a persistent grid over the valid tokens, with the same fp64 accumulation in expert order.
- BI activation, zero-padding and permute loops are bounded by the device counts they already checked.

## Results

Setup: Nemotron-3.5-Nano shapes (52 layers, 128 experts, topk 6, hidden 2688), random weights. MXFP8 routed experts, inference_optimized, NVLS dispatcher, EP4 on 4x GB200, local CUDA graphs, async scheduling, `batch_invariant_collective=ordered`. The engine settings follow an RLVR recipe that showed the slowdown: buffer 20 GB, block 256, max_tokens 73728, 40 requests. Numbers are decode ms per step, median of 60 steps.

| rows : context | main | this PR | main, BI off |
|---|---|---|---|
| 1 : 1k | crashes (illegal memory access) | 9.5 | 17.9 |
| 40 : 1k | crashes | 12.5 | 21.5 |
| 1 : 32k | crashes | 11.2 | – |
| 40 : 16k | crashes | 13.3 | – |
| 40 : 32k | crashes | 14.2 | 23.2 |

At max_tokens 8192, where main runs, main vs this PR: 16.6 -> 7.9 ms (1 row), 19.4 -> 10.8 ms (40 rows), 19.9 -> 11.3 ms (40 rows at 8k context).

The same change on the older tree the recipe pins (before #7660) took the BI decode step from 111-117 ms to 9.6-15.7 ms at max_tokens 73728.

## Bitwise evidence

- Kernel level: `mxfp8_quantize_rows` vs `mxfp8_quantize` has equal data and scale bytes on the live rows. This held for K 1856/2688/4096, n_rows 0..M, and under CUDA-graph replay with the device count changed between replays. The unpermute output matches the fp64 expert-order reference, and rows past the valid count stay untouched.
- Model level, EP4 BI, graphs on, greedy, 48 tokens from 4 prompts (500 to 33k tokens): generated tokens and log-probs are bitwise equal before vs after. That covers the older tree at max_tokens 73728 and main at max_tokens 8192.
- `tests/unit_tests/inference/test_mxfp8_utils.py` (including the BI fused/unfused equality tests) and the new `tests/unit_tests/inference/test_batch_invariant_live_rows.py`: 162 passed on GB200.

## Limitations

- Training is unaffected: `InferenceGroupedMLP.forward` uses the TE path outside `InferenceMode`.
- Rows at or past `n_used` in the quantized buffers are no longer initialized. Nothing reads them: the grouped GEMMs stop at the expert offsets and the activation is bounded.
- #8357 (contiguous inputs in `mxfp8_quantize_into`) touches the same file but does not conflict functionally. The fused-MoE callers here pass contiguous buffers.
- Not changed: the remaining full-size scale `torch.zeros` and inverse-map fill (MBs, not GBs).
