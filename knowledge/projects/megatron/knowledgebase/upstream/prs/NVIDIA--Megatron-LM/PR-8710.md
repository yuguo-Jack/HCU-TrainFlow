# [Inference][MTP] Draft each request on its own when the MTP head has no draft KV plane

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8710) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Stops MTP speculative decoding from mixing requests in the draft step when the MTP head has no draft KV plane. Each request's draft now sees only its own position, as a sequence of one token. Attention layers hand core attention those sequences as an ordinary sbhd batch, and recurrent layers take one step per sequence from a zero state, so no backend needs varlen support or host syncs for them.

## The bug

Without a draft KV plane, the dynamic engine drafts through `LanguageModule.compute_mtp_single_step` -> `MultiTokenPredictionLayer.forward_single_position` with no inference context. The controller lays the N active requests along the sequence dimension: token ids `[1, N]`, hidden states `[N, 1, H]` (split across TP ranks under sequence parallelism). The MTP layer saw one N-token sequence:

- Its causal attention let request j attend to requests 0..j-1.
- A recurrent layer in a hybrid head (Mamba, Gated Delta Product, KDA, GDN2) ran its convolution and scan across requests.

On `main`, replacing every other request moves the last request's draft logits already at the first draft depth, where the regression test stops (H100 results below). Greedy outputs are unaffected because drafts are verified. The acceptance rate drops, and it depends on which requests share the batch.

This path runs whenever the draft KV plane is off. `MTPContextMixin.should_enable_mtp_kv_cache` reserves the plane only for a repeated head (`mtp_use_repeated_layer=True`), and for a hybrid head only with exactly one attention layer and otherwise only MLP and MoE layers. MLA heads never get one. Heads with one layer per depth, as in DeepSeek-V3 checkpoints, always draft this way.

## Root cause and fix

Without a context, the draft step has no history to attend over. Training's MTP attends within each sequence, and the draft KV plane gives every request its own attention metadata. The context-free step had no sequence boundaries at all.

`forward_single_position` now passes the MTP layer `PackedSeqParams.single_token_sequences(N)` when it has no context: THD params with `cu_seqlens = [0, 1, ..., N]`, `max_seqlen = 1` and a precomputed `seq_idx`, one sequence per row. The token layout does not change, so sequence parallelism, MoE and expert-parallel padding rows, and the hidden-state chain across depths keep working. Forwards with a context are unchanged: the draft KV plane, the commit pass, and the EP dummy forward.

`PackedSeqParams.has_single_token_sequences()` names the case. Two contracts run it, one for each kind of sequence mixer:

- **Attention** (`Attention._runs_tokens_as_batch`, used by `Attention` and `MultiLatentAttention`). Only core attention needs the boundaries, so that each query sees its own key alone. The projections, norms and rotary embeddings work per token, so they run the tokens `[t, 1, ...]` as one unpacked sequence, as for any input; RoPE rotates a query and its only key by the same angle, which leaves their product unchanged. Core attention then gets the sbhd batch `[1, t, ...]` of length-1 sequences and no pack, so TE, local, Kitchen or any other core attention runs it without THD support. DSA keeps the pack, because its indexer reads the layer input, which sequence parallelism splits along the tokens.
- **Recurrent mixers** (`megatron.core.ssm.ssm_inference.steps_from_zero_state`). In inference, every token starts a recurrence of its own: the short conv sees the token alone and the recurrence takes one step from a zero state, which it neither reads nor stores. Each mixer runs that step on all tokens at once with its own projection, conv and gate code, through kernels that need no varlen metadata and keep no state per sequence. The step kernels of GDP, KDA and GDN2 have no backward, hence inference only.

| Mixer (hybrid symbol) | How a single-token pack runs |
|---|---|
| GQA/MHA attention (`*`), any core attention | Unpacked projections, then core attention on the sbhd batch `[1, t]` |
| MLA (`+`) | Same. RoPE runs on the unpacked sequence, as on `main`, instead of the vectorized THD RoPE; V is not padded |
| DSA over GQA (`*` with the DSA-GQA spec) | Same; its indexer gets the layer input as the same batch (DSA over GQA rules out sequence parallelism) |
| DSA over MLA (`D`) | Keeps the pack and takes DSA's packed path. The indexer now passes `max_seqlen` to its packed RoPE, which removes the path's only host sync |
| DSv4 CSA / HCA / window (`C`, `H`, `W`) | DSv4 runs at TP 1, so nothing splits its tokens: the whole layer runs on the batch `[1, t, h]`. Its packed path needs the cuDNN backend |
| Mamba (`M`) | The conv runs over each token as a row `[t, d, 1]`, with pip `causal_conv1d` or the `F.conv1d` fallback; the chunked scan runs on `[1, t]` and restarts at every token through `seq_idx`, keeping `ceil(t / chunk_size)` chunk states as on `main` |
| Gated Delta Product (`M`, GDP spec) | `ssm_decode` without state caches: the training path's conv (pip `causal_conv1d_fn` or its fallback) over each token, then the in-tree fused recurrence from a zero state. The decode CUDA graphs run the forked `causal_conv1d_update` instead |
| KDA (`K`) | KDA's own projection code (`_input_projections`), its conv and gate code on the batch of length-1 sequences (FLA conv or the fallback; the packed-input conv padding is not needed), then one step of FLA's `fused_recurrent_kda` |
| GDN2 (`G` with `gdn2`) | GDN2's own conv and gate code on the batch, then one step of FLA's `fused_recurrent_gdn2`, or the torch backend's kernel when `gdn_kernel_backend="torch"` |
| GDN (`G`) | Unchanged: GDN rejects inference without a context before it reads the pack |
| MLP (`-`), MoE (`E`) | Per token; MoE reads only the pack's CP fields, which it leaves unset |

Mamba's unfused (non-memory-efficient) path still rejects packed training input, as on `main`: it takes packed input only as sequences of one token each in inference, at CP 1. Packed training keeps running the memory-efficient path, which also lays packed sequences out for context parallelism.

Hot-path cost per draft depth, eager: one `arange` of N+1 int32 for the pack. Attention and MLA run the projections and RoPE `main` ran. Mamba copies its conv input once, as `main` did. GDP, KDA and GDN2 launch fewer kernels than their chunked scans.

### Why not the other options

- **Requests along the batch dimension** (`[1, N, H]`). Sequence parallelism splits the sequence dimension across TP ranks, and every SP linear gathers and scatters along it. A length-1 sequence cannot be split, so the rows stay on the sequence dimension, and attention swaps them onto the batch dimension only after the projections have gathered them.
- **Each mixer's general THD path.** It is correct, but GDP, KDA and GDN2 then host-sync (FLA's varlen chunk indices) and keep a chunk state per sequence, MLA pads V and runs the THD RoPE, and DSA over GQA and DSv4 (without cuDNN) reject packing.
- **A draft KV plane for every head.** That is a design question, not a fix. Each MTP depth after the first would need history built from tokens that are still drafts.

## Follow-ups: KDA MTP heads, FLA's `g` reads, the draft-plane predicate

Review findings on KDA and GDN2 heads, fixed in two commits (26cdb2776 and the one after it). H100 results are at the end of this section.

- **A head with KDA and one attention layer crashed at the first step.** `should_enable_mtp_kv_cache` counted only Mamba and GDN as recurrent, so a repeated head such as `K*` (pattern `M*/K*` or `*-/K*`) got the draft KV plane. The controller then handed the dynamic context to the head's KDA layer, which asserts static batching. Such a head now drafts without a context, on this PR's single-token path.
- **The predicate is an allowlist now.** It listed the mixers that must not get the plane, so the next one missed would fail as KDA did. A hybrid head gets the plane only with exactly one attention layer that can use it (`*`, `D` or `+`) and otherwise only MLP and MoE layers. Every other mixer drafts without a context: Mamba, GDN, KDA, and DSv4 attention (`C`, `H`, `W`), which rejects every inference context. A head such as `*C` used to get the plane and then fail DSv4's assertion; it now drafts on the single-token path, which DSv4 supports.
- **KDA in the main decoder is rejected when the engine is built.** `KimiDeltaAttention` rejects every inference context, so a decoder with KDA layers used to fail at its first forward. `MambaInferenceStateConfig.from_model` now raises `NotImplementedError` for it, as it already does for GDN2. An MTP head may still hold KDA layers, since it drafts without a context.
- **FLA's recurrent KDA and GDN2 kernels read past `g` when the key head dim is not a power of two.** FLA 0.5.1 loads each (token, head) row of `g` in `fused_recurrent_kda` and `fused_recurrent_gdn2` `next_power_of_2(K)` wide without a mask (`fla/ops/kda/fused_recurrent.py:158`, `fla/ops/gdn2/fused_recurrent.py:177`). For K = 96, 160, 192, ..., the last row reads BK − K elements past the end of `g`, and a NaN there makes that head's draft NaN. This PR reaches both kernels. FLA 0.6.0 masks both loads, so this PR is now stacked on the FLA bump (#8861, `fix/fla-core-g-overrun`) instead of padding around the library bug. The `g` pad of 26cdb2776, which covered KDA only and copied `g` at every draft depth, is gone.

Tests (1 GPU each, except where noted):

- `TestMtpKvCacheGating` in `test_dynamic_context_mtp_kv_cache.py`: `K*`, `*K` and `*C` heads get no draft KV plane, and `*-` and `E*` heads do. Before 26cdb2776, `K*` and `*K` get one; before the allowlist, `*C` does.
- `test_kda_single_token_sequences_read_only_g` in `test_kda.py` (one- and two-stage gates) and `test_gdn2_single_token_sequences_read_only_g` in `test_gated_delta_net2.py`, both at a key head dim of 96. Each runs a single-token pack with `g` handed on as a view at the start of a NaN-filled buffer. Every output must be finite and match the token's run alone. They pass with any fix of the read and fail on FLA 0.5.1, where the last (token, head) row is NaN. Both also pass under compute-sanitizer memcheck with `PYTORCH_NO_CUDA_MEMORY_CACHING=1`, with no memcheck errors.
- `test_mamba_inference_state_config_rejects_kda_in_decoder` in `test_inference_config.py` (CPU): decoders with KDA layers raise when the engine is built. Before this commit, they don't. Checked on CPU.

On H100 in the CI image (`mcore_ci_dev:main`, 2026-11-02), at this head, with #8861's `uv.lock` change applied in the container (FLA 0.6.0, for this PR and its base):
- The regression tests pass: 45 cases on 1 GPU, including the three tests above, and 20 on 2 GPUs (`TestMTPDraftStepRequestIsolation`, with the same 3 skips).

The 1-GPU tests only fail at import there: `test_kda.py` and `test_gated_delta_net2.py` import `followed_by_nan`, a test helper this PR adds, and that collection error stops the 1-GPU run before any case. The step 3 GPU repros did, on `main` on H100: R01-F2 (4 of 4 cases: the context reserves the draft KV plane for a `K*` or `*K` head and hands the dynamic context to KDA, which raises) and R01-F3 (8 of 8 kernel cases: FLA 0.5.1's `fused_recurrent_kda` puts NaN in the output at K = 96 and 192 with NaN after `g`).
- The neighbors pass: `TestMTPCudaGraphInference` (28 cases, 2 GPUs), `test_mamba_mixer.py` (22, at 8 GPUs) and `test_kda_packed_matches_unpacked_cp1` (2).
- Under compute-sanitizer memcheck there are no memcheck errors, and 34 cases on 1 GPU and 13 on 2 GPUs pass. 18 cases that capture a CUDA graph fail at capture: with the caching allocator off, as this memcheck run sets it, the capture calls `cuMemAlloc`, which a capturing stream does not permit. So those graphed cases have not run under memcheck.
