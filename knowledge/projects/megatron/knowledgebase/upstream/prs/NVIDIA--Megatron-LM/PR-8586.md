# [MFSDP] Group context-level options in RuntimePolicy

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8586) · state: closed · merged: True

- [x] I, the PR author, have personally reviewed every line of this PR.

## What does this PR do?

Group the three context-wide runtime flags into a frozen `RuntimePolicy`, exported from the experimental MFSDP API:

```python
with fully_shard_context(
    device=device,
    runtime_policy=RuntimePolicy(
        use_symmetric_memory=True,
        unify_communication_stream=True,
        caller_managed_grad_sync=True,
    ),
) as context:
    fully_shard(model, mesh=mesh, placements=placements)
```

All three flags retain their default of `False`. `device` and the construction-only `parameter_to_owner` map remain explicit context arguments. Callers using the former top-level flag keywords must pass them through `runtime_policy`.

Migrate the MCore adapter, both training wrappers, and tests; update the construction guidance and design documentation. Extend existing context tests to cover default versus explicit stream sharing and automatic versus caller-managed gradient synchronization. Field documentation is consolidated in the policy's `Attributes` section.

Related to #8585; this PR is independently based on main and does not include the SchedulePolicy changes.

### Document each `RuntimePolicy` field at its declaration

The three new public configuration fields in [runtime_policy.py](https://github.com/NVIDIA/Megatron-LM/blob/57d6c2a0cbdf52afc4b0b82fbc3f1ff06f30da8a/megatron/core/distributed/fsdp/src/megatron_fsdp/experimental/runtime_policy.py#L20-L37) are documented only in the class-level `Attributes` section. The repository’s [configuration-documentation rule](https://github.com/NVIDIA/Megatron-LM/blob/f368e94627ac2cfca4a450a3169128384278a12e/style-guide.md#L17-L19) explicitly requires a MyST docstring immediately after each public configuration field. This is a source-convention issue, not a demonstrated runtime failure.

**Correction:** Replace the class definition at the linked location with the following, moving the existing descriptions beside their fields:

```python
@dataclass(frozen=True)
class RuntimePolicy:
    """Configure communication and gradient synchronization for an FSDP context."""

    use_symmetric_memory: bool = False
    """Allocate communication staging buffers from PyTorch's NCCL symmetric-memory pool."""

    unify_communication_stream: bool = False
    """Share one stream for all-gathers and reduce-scatters to reduce peak transient memory."""

    caller_managed_grad_sync: bool = False
    """Leave gradient synchronization to the caller while retaining automatic weight cleanup.

    The caller must call ``finish_grad_sync()`` after all backward work, including
    delayed weight gradients, and before reading or modifying gradients.
    """
```

**Preservation and acceptance:** Static inspection should confirm an immediately following docstring for every field, with the frozen decorator, field names, boolean annotations, and three `False` defaults unchanged. Retain the existing [stream-sharing assertions](https://github.com/NVIDIA/Megatron-LM/blob/57d6c2a0cbdf52afc4b0b82fbc3f1ff06f30da8a/tests/unit_tests/distributed/mfsdp_v2/test_context.py#L88-L100): omitted or false sharing creates separate streams; true sharing reuses the all-gather stream. Also retain the [gradient-sync assertions](https://github.com/NVIDIA/Megatron-LM/blob/57d6c2a0cbdf52afc4b0b82fbc3f1ff06f30da8a/tests/unit_tests/distributed/mfsdp_v2/test_context.py#L191-L219): automatic mode waits once after the last microbatch, while caller-managed mode performs no automatic wait before explicit synchronization.

The suggested replacement changes documentation only; please verify it before adopting. No functional regression was identified in the changed context, adapter, training-wrapper, or test paths. Review was static; distributed/CUDA tests were not executed.
