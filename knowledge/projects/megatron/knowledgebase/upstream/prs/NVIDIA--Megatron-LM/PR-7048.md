## What does this PR do?

This is **DCP V2 4/4**. It carries each packed microbatch's runtime CP topology through HybridStack layout conversion, Mamba, GDP, GDN/GDN2, MTP, MLA/absorbed MLA, and DSA/indexer consumers. Models can be constructed with CP1 and consume successive CP1/CP2/CP4 microbatches without mutating build-time geometry.

`PackedSeqParams` retains real singleton runtime groups and the matching TP×CP group under sequence parallelism. MCore-only group metadata is filtered at the Transformer Engine API boundary. Headwise mixers validate every scheduler-enabled CP size at construction; chunkwise GDP retains all TP-local heads.

Original change authored by @zhongbozhu in [879f596](https://github.com/zhongbozhu/Megatron-LM/commit/879f5968f26f1cce5d71ccc55b17d2aaf1e5ec4d). This PR follows merged #7045, #7046, and #7047. Source lineage also includes #4226 and #6387.

## Behavior changes, including static CP

- Per-token MTP backward now SUM-reduces main/MTP valid-token counts over the effective CP group before computing the ratio. This fixes partition-dependent gradients for **static CP>1 as well as dynamic CP** when valid-token counts differ across ranks. Empty ranks participate; counts are clamped only after reduction. There is one two-element all-reduce per MTP depth per microbatch, including evaluation.
- Under per-token loss, logged `mtp_N loss` becomes a global token-weighted mean instead of a mean of microbatch means, including under static CP. Packed/masked runs may log different values even when CP1 training gradients are unchanged. Legacy normalized logging retains its existing definition.
- Indexer metrics weight each contribution by its runtime CP size when it represents a partial token sum, then reduce over fixed PP/DP×CP/rematerialization groups. The metric remains a mean per logical sample, independent of microbatch order or build-time CP. Logging uses the scheduled microbatch count. CP1 external callers may continue supplying only PP/DP; real CP additionally requires the caller's fixed `dp_cp` group.
- MTP metric mode can change after a cleaned logging window; mixing `calculate_per_token_loss` modes within a nonempty window is rejected.

Dynamic CP requires per-token loss and variable-length packing. Deterministic mode, CUDA graphs, router z-loss, CSA, DSA-GQA, and DeepSeek-V4 are outside the supported combinations. Mamba does not support chunkwise CP; inference remains CP1. See [the dynamic CP guide](https://github.com/xiaoyao0115/Megatron-LM/blob/dcp-v2-hybrid-model-runtime-cp/docs/user-guide/features/context_parallel.md#dynamic-context-parallelism).
