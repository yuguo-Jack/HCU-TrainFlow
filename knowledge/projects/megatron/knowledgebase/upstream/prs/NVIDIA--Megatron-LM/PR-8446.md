# What does this PR do?

Exempt PRs authored by `tdene` from `@NVIDIA/reinforcement-learning` approval while preserving every other applicable owner's approval requirement.

Replace the external approval action with a repository-owned checker. The author-exemption mapping and helper live in `check_codeowners_approval.py`, and review-label automation imports that helper. Determine eligibility from the actual PR author, and stop label evaluation on GitHub API failures instead of treating failed requests as empty results. Preserve active core-team change requests even when the exemption removes every required team approval, keeping those PRs in Final Review.

### Preserve final-team blockers after removing the RL requirement

**Failure:** Using the added [RL-only `tdene` fixture](https://github.com/NVIDIA/Megatron-LM/blob/53f3dcbbdec463a95afaa3008da34843247fc605/tests/test_utils/python_scripts/test_codeowners_approval.py#L29-L44), supply latest reviews `{"nemo-reviewer": "CHANGES_REQUESTED"}` with no existing review-stage labels. This subtraction empties both required-team sets. The reviewer is correctly retained in `pending_final`, but [the stage decision](https://github.com/NVIDIA/Megatron-LM/blob/53f3dcbbdec463a95afaa3008da34843247fc605/tests/test_utils/python_scripts/swap_pr_labels.py#L232-L255) sets `needs_final_review=False` because no final team owns the changed files. Consequently, [the expert-stage handler](https://github.com/NVIDIA/Megatron-LM/blob/53f3dcbbdec463a95afaa3008da34843247fc605/tests/test_utils/python_scripts/swap_pr_labels.py#L313-L331) adds `Approved` despite the active blocker. Before the exemption, the outstanding RL approval prevented this advancement.

**Correction:** In `swap_labels`, replace the assignment at line 247 with:

```python
needs_final_review = bool(final_required or final_non_approvers)
```

This lets the existing handler retain final-review blockers even when no final team owns these paths. The invariant is that exempting a team's mandatory approval must not exempt an individual's active change request. This is a source-traced suggestion, not an executed patch; verify it before adopting.

**Acceptance and preservation — proposed checks, not run:**
- Extend `TestReviewLabels` using its default fixture and the review above; repeat with `adlr-reviewer`. Each case should add only `Final Review`, never `Approved`. Changing that review to `APPROVED` should permit `Approved`.
- Retain the existing RL-only/no-review assertion: add `Approved` once without looking up RL membership. Retain the RL-member change-request assertion: no label changes.
- Retain the other-author and mixed-training assertions: no advancement without their required approvals; mixed RL/core changes must still add `Final Review` while core approvals are missing.
- With an existing `Approved` label, a core-team change request must remove it and return to `Final Review`; with an existing `Final Review` label, the blocker must prevent advancement.
