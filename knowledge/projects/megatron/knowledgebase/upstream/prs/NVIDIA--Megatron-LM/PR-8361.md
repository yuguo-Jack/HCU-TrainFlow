# Support TE attention CUDA graphs with THD sequence packing

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8361) · state: closed · merged: True

## Original PR description

## What does this PR do?

Enable Transformer Engine attention CUDA graph capture/replay for THD batches produced by main's `dp_balanced` sequence-packing scheduler. Preserve changing document boundaries and valid/padded offsets while keeping token and metadata buffers fixed in shape.

This PR **replaces #5783** as the main port of the remaining THD attention-graph functionality from these merged dev PRs:

| Dev PR | Feature completed on main by this port |
|---|---|
| #4359 | THD partial attention graph capture/replay with bounded packed metadata and changing packed microbatch counts. |
| #5724 | Consistent packed-token padding and sequence metadata between eager and graph execution. |

Credits to the original implementations in #4359 and #5724. Related to #5795.

## Scope

- Reuse main's packing scheduler and graph-buffer lifetime management, retaining the dev configuration names.
- Preserve all four logical/physical Q/KV offset tensors. Padding contributes zero real tokens and is excluded from loss and routing.
- Support fixed source batch size, MBS1, static CP, and PP/VPP attention capture. Reject microbatch overflow before reusing a live graph.
- Build directly on main, with no dependency on #7703. mHC/Hybrid wrapper graph integration (#7337) and mHC attention split/recompute (#7385 and related work) remain separate recipe dependencies.

## Validation

- Four GB200 ranks: PP2/CP2 and PP2/VPP2/CP2 with real MCore DDP, changing microbatch counts 4 → 2 → 4; outputs, input gradients, and every layer's main gradients passed with unchanged tolerances.
- Real fused CSA ratio-4 with sparse indexer loss and HCA ratio-128 at CP2: all 288 output/gradient comparisons passed, including changing packed boundaries and zero-real-token padding tails.
- Focused CPU padding/scheduler tests, CLI parsing, formatting/lint, and kernel determinism coverage checks passed.

This qualifies the THD attention-graph foundation, not the full 64K Pro performance recipe. Full-recipe FP8 and PP4/VPP4/CP16 performance validation remains separate.

- HaochenYuan · comment · 2026-10-21T13:48:48Z · [source](https://github.com/NVIDIA/Megatron-LM/pull/8361#issuecomment-6317709999)

**[P2] Preserve TP divisibility when padding sequence-parallel inputs**

[model_parallel_config.py:571–577](https://github.com/NVIDIA/Megatron-LM/blob/4637d21dfce3133629eabddd1887e98527ff6cf1/megatron/core/model_parallel_config.py#L571-L577). The new validation checks zigzag CP alignment but does not preserve sequence-parallel TP divisibility. For example, TP=4, CP=1, `sequence_parallel=True`, `pad_packed_seq_alignment="max"`, and `max_seqlen_per_dp_cp_rank=18` pass this validation. A valid 16-token batch is then padded to 18 tokens, causing the [embedding split](https://github.com/NVIDIA/Megatron-LM/blob/4637d21dfce3133629eabddd1887e98527ff6cf1/megatron/core/tensor_parallel/mappings.py#L76-L79) to fail with `First dimension of the tensor should be divisible by tensor parallel size`. Please ensure the resulting padded local length remains divisible by TP when sequence parallelism is enabled, and add coverage with TP > 1.

**Integration gap: preserve logical offsets before invoking the new padding helper**

[data_schedule.py:947–957](https://github.com/NVIDIA/Megatron-LM/blob/4637d21dfce3133629eabddd1887e98527ff6cf1/megatron/core/datasets/data_schedule.py#L947-L957). The new helper receives metadata after the [existing constructor](https://github.com/NVIDIA/Megatron-LM/blob/4637d21dfce3133629eabddd1887e98527ff6cf1/megatron/core/datasets/data_schedule.py#L927-L934) has replaced both logical Q/KV offsets with `cu_seqlens_padded`. For input logical offsets `[0, 3, 8]`, physical offsets `[0, 4, 12]`, token capacity 16, and metadata capacity 4, this path returns logical offsets `[0, 4, 12, 12, 12]`. The metadata therefore reports 12 valid tokens while the padding mask identifies only eight.

This assignment predates the PR, so this is not a newly introduced regression. However, it leaves the advertised logical/physical-offset preservation incomplete for scheduler-produced batches and affects CSA indexer auxiliary-loss masking. Please preserve the original logical offsets on this path and add a loader-level test. Tests that construct `PackedSeqParams` directly do not exercise this conversion.

This PR supports static CP with `dp_balanced` packing only. `cuda_graph_dynamic_microbatches` handles changing packed microbatch counts, not changing CP groups.

Dynamic CP selects communicators per microbatch, while captured graphs retain their communicators. Main already rejects dynamic CP with CUDA graphs; this PR keeps that restriction. The recent CLI fix only scopes the new static-packing checks to `dp_balanced`, so dynamic CP reaches its existing validation.

The existing eager GPT dynamic-CP path is unchanged. HybridModel's builder still rejects dynamic CP, even without graphs. Supporting dynamic CP here would require separate graph/communicator handling, beyond this port's scope.

I've synced with @yuzhongw-nvidia , and we will provide a separate plan for dynamic CP.
