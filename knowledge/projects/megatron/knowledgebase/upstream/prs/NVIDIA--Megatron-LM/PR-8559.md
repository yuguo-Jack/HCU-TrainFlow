# perf(moe): fused Triton kernel for the batch-invariant MoE unpermute

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8559) · state: closed · merged: True

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Runs the batch-invariant MoE unpermute (training-side AllToAll combine) as one Triton kernel instead of a Python loop, with outputs and gradients bitwise equal to the loop.

## Details

Under `batch_invariant_mode`, `moe_utils.unpermute` calls `moe/batch_invariant.py::unpermute`, which evaluates the engine's combine tree in software: for each EP rank in order, an fp64 sum of the token's top-k rows that belong to that rank, rounded to fp32, then the rank partials chained in fp32 (`ordered`) or accumulated in fp64 and rounded once (`multimem`). The loop ran over EP ranks x top-k slots on `[tokens, hidden]` fp64 temporaries, and autograd recorded every step for the backward. It ran in every MoE layer of every training and log-prob forward and backward.

For `probs=None` (the path used when the routing probabilities are applied before FC2, e.g. `use_fused_weighted_squared_relu`), the tree now runs as one kernel per (token, hidden block). It loads the same rows and adds them in the same order and precision for both cross-rank variants. The backward is a gather: each permuted row belongs to exactly one (token, slot), and adding `+0.0` reproduces the loop's sign of zero. The loop is kept for the `probs` path and for non-CUDA tensors.

`--moe-ep-invariant-combine` (#8261) already has its own Triton combine (`tree_combine`); this PR targets only the default batch-invariant unpermute and leaves that path untouched.

## Performance

GB200, Nemotron-3-Nano MoE shapes (hidden 2688, 128 experts, top-6, EP 8), BF16, milliseconds per call, median of 20:

| collective | tokens | fused fwd | fused fwd+bwd | loop fwd | loop fwd+bwd | non-BI unpermute fwd | non-BI fwd+bwd |
|---|---|---|---|---|---|---|---|
| ordered | 4096 | 0.22 | 0.80 | 7.51 | 22.06 | 0.08 | 0.23 |
| ordered | 16384 | 0.70 | 2.26 | 25.46 | 77.51 | 0.22 | 0.67 |
| multimem | 4096 | 0.25 | 0.81 | 8.20 | 22.82 | 0.08 | 0.23 |
| multimem | 16384 | 0.76 | 2.33 | 27.49 | 80.64 | 0.22 | 0.67 |

In a 1-node Megatron A/B (Nemotron-3-Nano architecture, TP2, EP4, MXFP8, sequence length 8192, eight micro-batches per rank, full recompute), a batch-invariant training iteration takes 7.77 s with this kernel versus 10.27 s with the loop (8.02 s without batch-invariant mode). In a NeMo-RL GRPO run of Nemotron-3-Nano with batch-invariant mode (TP2, EP8), training took 23.0 s per step versus 17.5 s without it, a gap of the same relative size.

```python
@pytest.mark.parametrize("collective", ["ordered", "multimem"])
@pytest.mark.parametrize("dtype", [torch.bfloat16, torch.float32])
def test_batch_invariant_unpermute_replays(monkeypatch, collective, dtype):
    from megatron.core.transformer.moe import batch_invariant

    if not batch_invariant.HAVE_TRITON:
        pytest.skip("requires Triton")
    seeded()
    monkeypatch.setattr(
        batch_invariant, "get_batch_invariant_collective", lambda: collective
    )
    monkeypatch.setattr(
        parallel_state, "get_expert_model_parallel_world_size", lambda: 2
    )
    rows = torch.randn(
        8192, 520, device="cuda", dtype=dtype, requires_grad=True
    )
    inverse_map = torch.stack((
        torch.arange(8192, device="cuda").view(2, 4096).T,
        torch.tensor([0, 1], device="cuda").expand(4096, 2),
    ))
    grad = torch.randn(4096, 520, device="cuda", dtype=dtype)
    grad.view(-1)[::7] = -0.0

    def combine(x):
        return batch_invariant.unpermute(
            x, torch.Size((4096, 520)), probs=None,
            num_experts=2, inverse_map=inverse_map,
        )

    assert_replays_bit_exact(
        combine, (rows,), replays=3, contention=True,
        grad_outputs={"out": grad}, what="batch-invariant unpermute",
    )
```

### Keep the fused backward CUDA-graph capturable

**Failure:** With CUDA rows requiring gradients and `probs=None`, capturing forward/backward in `torch.cuda.graph(...)` reaches this boolean selection and `inverse_rows[valid]` below. CUDA boolean indexing produces a data-dependent-sized result through `nonzero`, requiring host synchronization that capture cannot perform—even when every entry is valid. The [previous loop](https://github.com/NVIDIA/Megatron-LM/blob/9dd63d992a5925dba7f9bfd1aec9dbfb1f54b837/megatron/core/transformer/moe/batch_invariant.py#L96-L107) used fixed-shape selection/masking. This breaks the [fixed-shape inverse-map contract](https://github.com/NVIDIA/Megatron-LM/blob/e00f052d95a6bb1a0b83c93e79474bad666affa0/megatron/core/transformer/moe/moe_utils.py#L559-L561), and the normal [AllToAll combine caller](https://github.com/NVIDIA/Megatron-LM/blob/e00f052d95a6bb1a0b83c93e79474bad666affa0/megatron/core/transformer/moe/token_dispatcher.py#L904-L913) selects this `probs=None` path.

**Correction:** Replace both boolean selections in `_RankTreeUnpermute.backward` with fixed-shape work—for example, a masked backward kernel over `(token, slot, hidden block)` that writes each valid slot's gradient to its uniquely owned row. Allocation/launch shapes must depend only on tensor shapes, not `valid` contents. Keep the zero initialization for unused rows; do not redirect invalid writes into row zero. The exact replacement kernel still needs verification of signed-zero and upstream-stride handling, so an unchecked implementation is not prescribed here.

**Preserve:** Retain byte-identical gradients for `ordered`/`multimem` and BF16/FP32, including `-0.0` becoming `+0.0`. Invalid slots must contribute nothing, unused rows must remain zero, and noncontiguous upstream gradients must work. Leave CPU and probability-weighted fallbacks unchanged.

**Acceptance (proposed, not run):** Set EP size 1; use `rows=torch.ones((1, 4), device='cuda', requires_grad=True)` and inverse map `[[[0]], [[0]]]`. Warm up on a side stream, clear gradients, then capture forward plus backward with a fixed upstream gradient and replay. Capture must succeed, and output/gradient bytes must match `_unpermute_loop`. Repeat with negative-zero and noncontiguous upstream gradients, plus an inverse map containing an invalid slot and an unused input row; the unused row's gradient must remain zero. Retain the existing collective/dtype parity assertions. The [existing graph test](https://github.com/NVIDIA/Megatron-LM/blob/e00f052d95a6bb1a0b83c93e79474bad666affa0/tests/unit_tests/rl/test_rl_batch_invariant.py#L65-L111) uses `probs` under `no_grad`, so it does not exercise this new backward.
