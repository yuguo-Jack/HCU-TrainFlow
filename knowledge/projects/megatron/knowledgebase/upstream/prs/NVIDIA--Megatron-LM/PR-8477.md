# What does this PR do?

Keeps the vocab-parallel cross entropy loss and target gradient accurate for confident tokens: once the target leads the other logits by more than ~16.6 they used to round to exactly 0, while the other classes kept their gradients.

No copied code. The method follows [A Fix for Softmax and Cross-Entropy](https://arxiv.org/abs/2610.31642) (arXiv:2610.31642).

## Problem

After subtracting `logits_max`, the target contributes `exp(0) = 1` to `sum_exp_logits`, and the other terms (`~exp(-margin)`) are added to that 1. Below 2^-24 they round away, so:

- `loss = log(sum_exp_logits) - predicted_logits` becomes exactly 0,
- the target gradient `softmax - 1` becomes exactly 0,
- every other class keeps `softmax[j] = exp(z_j - max) / sum`, computed without the 1,

and the row gradient sums to `+exp(-margin)` instead of 0. On main, logits `[20, 0, 0]` with target 0 give loss `0.0` and gradient `[0, 2.06e-9, 2.06e-9]`; the exact values are `4.12e-9` and `[-4.12e-9, 2.06e-9, 2.06e-9]`.

## Change

`megatron/core/tensor_parallel/cross_entropy.py` and `megatron/core/fusions/fused_cross_entropy.py`:

- **One row reduction for both sums:** the new `VocabParallelCrossEntropy.sum_exp_logits_excluding_target` zeroes the target entries of `exp_logits`, reduces, restores them (`x - x` and `0 + x` are exact) and adds the target back as a scalar. It allocates only `[s * b]` tensors, never a logits-sized one, and runs eagerly like the existing gather and scatter.
- **Loss:** `softplus(log(sum_exp_others) - predicted_logits)`, the same value as `log(sum_exp_logits) - predicted_logits` without forming `1 + others`.
- **Target gradient:** `-sum_exp_others / sum_exp_logits`, always in `[-1, 0]`, written in place of `softmax - 1` on the rank that owns the target (`set_target_gradients`). With label smoothing it is `target_grad + smoothing`.
- **No extra collectives:** the unfused path all-reduces `sum_exp_logits` and `sum_exp_others` stacked in one call; the fused path adds `sum_exp_others` to its existing concatenated all-reduce.
- **API:** existing helpers keep their signatures and default behaviour; `calculate_cross_entropy_loss` and `calculate_gradients` take an optional extra argument. The unfused forward now calls the staged helpers (`gather_predicted_logits`, `exp_logits_inplace`, then the new sum), the same way the fused path already does, instead of `calculate_predicted_logits`. Note for downstream projects that monkeypatch `VocabParallelCrossEntropy.calculate_predicted_logits` (MindSpeed does): the unfused forward no longer goes through it.

## Not covered

- **Functional goldens:** the loss is now computed as `softplus(log(sum_exp_others) - x)` instead of `log(sum_exp) - x`, so per-token values can differ in the last bits. Exact golden checks, if any cover these paths, may need a refresh; please run the functional suite.

- **TE path:** `cross_entropy_fusion_impl='te'` calls Transformer Engine's parallel cross entropy, which has the same pattern in its Triton kernel; that needs a separate TE change.
- **Impact:** this is a numerical correctness fix. On pretrained Qwen2.5 0.5B to 3B checkpoints, no token reached the cutoff on web text or code (max margin 14.8); after 10 epochs of SFT on 64 sequences, 1.3% of training tokens did, carrying about 5e-8 of the loss. The paper's training-dynamics effects come from regimes where nearly all tokens cross it (e.g. grokking).
- **8-GPU CI and other GPUs** were not run.
