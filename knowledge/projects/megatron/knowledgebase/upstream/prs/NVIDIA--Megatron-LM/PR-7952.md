# [Refactor] Select wide-residual operation at construction

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7952) · state: closed · merged: True

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

## What does this PR do?

Wide-residual connections currently reuse one module for both reading and writing. Under MFSDP, those repeated invocations trigger redundant parameter prefetches, adding communication overhead and increasing peak memory.

This PR separates reads and writes into distinct module instances, with the operation fixed at construction, while preserving computation and validation.

Select `StreamwiseSigmoidWideResidualConnection`'s operation at construction with required `operation="read"` or `operation="write"`. The reader owns `read_map`; the writer owns `write_map` and optional retention. `forward` no longer takes `operation`. Transformer, Mamba, residual replay, and existing test callers use separate reader/writer instances of the same class.

This is a numerical no-op: the residual maps, read/write math, and Triton operators are unchanged.

Residual parameter paths change from `residual_connection*` to `residual_read*` / `residual_write*`. Ordinary `load_state_dict` accepts the original model keys. Migration of existing distributed checkpoints and optimizer state is not validated.

Standalone refactor targeting `main`. The MFSDP integration is tracked separately in #7930. Related: #7777.
