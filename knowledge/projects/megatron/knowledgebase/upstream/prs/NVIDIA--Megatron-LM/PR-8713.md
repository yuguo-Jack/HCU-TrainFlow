# [Inference][SSM] Keep Mamba's A one-dimensional in dynamic prefill when a rank holds one head

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8713) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Fixes a crash on every dynamic-batching prefill step of a Mamba model whose ranks each hold one Mamba head.

**Bug.** `MambaMixer.ssm_prefill` drops the batch dim of the projected `x`, `dt`, `B`, `C` and `z` with `squeeze(0)` before the varlen chunk scan, and squeezes `A` along with them. `A = -exp(A_log)` is per head, shape `(nheads_local_tpcp,)`, and has no batch dim. With several heads per rank the squeeze does nothing. With one head per rank it turns `A` into a 0-d tensor, and `_mamba_chunk_scan_combined_fwd` fails its `A.shape == (nheads,)` assertion (`ops/mamba2/ssd_combined.py:53`).

The trigger is one Mamba head per rank (`nheads_local_tp == 1`). The head count can come from `mamba_num_heads` or from `d_inner // headdim`. Examples: 2 heads at TP=2, or hidden size 64 with expand 2 and head dim 128 on one GPU. Every dynamic-batching prefill step fails, including chunked prefill. Static batching and training were not affected. The squeeze was added with the varlen prefill path in #3225.

The bug was found by `test_text_generation_controller.py::test_inference_optimized_steps_barrier_once_per_forward[hybrid]` (2 Mamba heads at TP=2). That test is added by n12 ([#8709](https://github.com/NVIDIA/Megatron-LM/pull/8709)), which marks the hybrid case `skip` because of this bug. Whichever of the two PRs lands second should remove that skip.

**Fix.** Stop squeezing `A`. I checked the other paths that use the per-head tensors (`A`, `D`, `dt_bias`) for the same mistake, and none needs a change:
- Decode uses the cached `(nheads, headdim, dstate)` view of `A`.
- The PyTorch decode fallback, static-batching prefill, training and the batch-invariant decoder pass `A`, `D` and `dt_bias` without squeezing them.
- The context-parallel getters slice these tensors and keep them 1-D.

**Tests.** `tests/unit_tests/ssm/ops/mamba2/test_ssm_kernel.py` calls the real `MambaMixer.ssm_prefill` and `ssm_decode` on a stub mixer. The head count is now a class attribute. `TestMambaDynamicInferenceSingleHead` gives a one-head stub the parameters of head 0 of an 8-head stub, and runs three checks:
- It reruns the existing prefill test with one head.
- `test_ssm_prefill_matches_head0_of_multi_head`: two requests, one of them spanning two chunks, start from nonzero states. The one-head prefill output, conv state and SSM state must match head 0's.
- `test_ssm_decode_matches_head0_of_multi_head`: the same comparison for one decode token, and for a 3-token speculative step including its per-token state snapshots.

The comparison allows rounding error relative to each tensor's scale, because the GPU kernels may tile one head and several heads differently. A head that reads another head's `A_log` is off by up to 18x relative and fails the check.

**Results.**
- On H100 in the CI image (dfw 21012189), with the original version of the test: on `main` the single-head case fails and the 8-head case passes; with this PR both pass.
- The neighbor tests pass on H100:
  - `test_mamba_mixer.py::TestMambaMixer`: 10 passed.
  - `test_hybrid_prefix_caching_e2e.py::TestMambaPrefixCachingE2E::test_mamba_prefix_caching_e2e`: 2 passed.
  - `determinism/kernels/test_ssm_kernels.py`: 54 passed and 3 xpassed.
- At this head (dfw 21013289), all 4 single-head tests pass on H100 with this PR; on `main` the two prefill tests fail (shape assertion) and the two decode tests pass, since decode was never affected. The neighbors pass (10, 2 and 57 cases).

`mamba_mixer.py` is registered with the kernel-determinism gate, but this PR changes no kernel or dispatch. For more than one head, the removed squeeze was a no-op, so numerics do not change. This PR needs the `determinism-exempt` label.
