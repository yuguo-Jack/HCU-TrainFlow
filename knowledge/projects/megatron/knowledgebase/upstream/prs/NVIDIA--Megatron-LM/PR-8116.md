# Add unpadded shards for MFSDP v2 RowAtomic/BlockAtomic layouts

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8116) · state: closed · merged: True

## Original PR description


- [x] I, the PR author, have personally reviewed every line of this PR.

Add an opt-in unpadded layout for MFSDP v2 RowAtomic/BlockAtomic parameter groups.
  Tensors are packed back to back and rank boundaries snap to the nearest row
  (32-row block for MXFP8) boundary, so shards are generally unequal but carry zero
  padding. The default padded layout is unchanged.

  Motivation: the padded layout rounds every group up to `dp_size * LCM(row sizes)`
  (`* 32` for MXFP8). For groups mixing many row widths this is large; the
  DeepSeek-V3-shaped dense group measured for #7585 pads 13% at DP=4 and over 80% at
  DP=16.

  Changes:
  - `layout_builder.build_for_row_atomic_unpadding`: padding-free builder; shards
    differ by at most one row/block and may be empty. Shape validation and per-tensor
    alignment are shared with the padded builder.
  - `GlobalLayout.validate_for_row_atomic` only checks that no rank boundary splits a
    row/block, instead of requiring equal segments; padded layouts still pass.
  - `DBuffer`: the list-based `all_gather` / `reduce_scatter` paths slice per-peer chunks
    via `get_rank_range`, so uneven layouts work on multi-axis (HSDP/HFSDP) meshes.
  - `QuantizedDBuffer`: scale planes derive from the unpadded data layout.
  - Knob: `ShardLayout.PADDED | UNPADDED` enum, `fully_shard(shard_layout=...)`;
    `DistributedDataParallelConfig.megatron_fsdp_padded_shards` (default True) and
    `--no-megatron-fsdp-padded-shards` for MCore. Incompatible with `nccl_ub`
    (symmetric memory needs equal shards).

  Uneven NCCL collectives are somewhat slower than the even `*_into_tensor` paths; the
  NCCL team is optimizing them. Only users opting into `UNPADDED` are affected.

  Tests: existing DBuffer, QuantizedDBuffer, SGD/HSDP/HFSDP parity, and MXFP8 training
  tests are parametrized over `ShardLayout`; layout builder tests added; adapter flag
  covered. `tests/unit_tests/distributed/mfsdp_v2` passes on 4xGB200.

  ## Issue tracking

  Linked issue: Related to #7585, #6587

### Make the padded-storage comparison NaN-safe

The new comparison in [test_2d_mesh_shards_across_all_ranks](https://github.com/NVIDIA/Megatron-LM/blob/c68b1cdc59f102067bd5634b8b0d6e8eecc74927/tests/unit_tests/distributed/mfsdp_v2/test_dbuffer.py#L667-L673) compares entire buffers, including uninitialized padding. If that padding contains NaNs, gathering copies them correctly but `assert_close` rejects the matching NaNs. Padding is explicitly unspecified by [DBuffer.copy_from](https://github.com/NVIDIA/Megatron-LM/blob/c68b1cdc59f102067bd5634b8b0d6e8eecc74927/megatron/core/distributed/fsdp/src/megatron_fsdp/experimental/dbuffer.py#L353-L357); the neighboring [replicate-view test](https://github.com/NVIDIA/Megatron-LM/blob/c68b1cdc59f102067bd5634b8b0d6e8eecc74927/tests/unit_tests/distributed/mfsdp_v2/test_dbuffer.py#L401-L409) already handles this case.

Replace the comparison at lines 671–673 with:

```python
torch.testing.assert_close(
    inner_view.view([RowAtomic(), RowAtomic()]).local_buffer,
    fully_sharded_buffer.local_buffer,
    equal_nan=True,
)
```

This must retain the preceding per-logical-tensor comparison, which checks actual data independently of padding. Proposed regression check: in the padded parameterization, fill local storage with NaNs and restore each input tensor through `copy_from` before gathering. The round trip must pass; changing a finite logical element must still fail. Retain the unpadded round trip and the existing padded/unpadded logical-value assertions. Suggested code requires author verification.

### Keep this test valid on two ranks

With `ShardLayout.UNPADDED` and two ranks, these shapes contain 12,288 elements and the midpoint, 6,144, is already a valid 32-row-block boundary inside the first tensor. Both shards therefore contain 6,144 elements, so this assertion fails before either all-gather runs. Three ranks also produce equal shards. Unpadded layouts may legitimately be equal; only padding, not equality, is disabled.

To retain this test's intended uneven/empty-shard coverage rather than removing the assertion, change its shapes and matching size assertion in [this test](https://github.com/NVIDIA/Megatron-LM/blob/c68b1cdc59f102067bd5634b8b0d6e8eecc74927/tests/unit_tests/distributed/mfsdp_v2/test_quantized_dbuffer.py#L205-L234):

```diff
-    shapes = [(128, 64), (32, 128)]
+    shapes = [(96, 64), (32, 128)]
@@
-        assert data_layout.size == 128 * 64 + 32 * 128
+        assert data_layout.size == 96 * 64 + 32 * 128
```

Both dimensions remain MXFP8-compatible. The replacement yields unpadded shard sizes `[4096, 6144]` on two ranks, unequal shards on four ranks, and empty ranks on eight; the padded variant still has equal shards. Keep the per-plane rank-value assertions and `result is destination` check.

Acceptance (proposed, not executed): run this test with 2, 4, and 8 ranks for both layouts and both `use_out` values. Every case should reach and pass the plane-content checks, with the shard properties above. Verify the suggested patch before adopting it.
