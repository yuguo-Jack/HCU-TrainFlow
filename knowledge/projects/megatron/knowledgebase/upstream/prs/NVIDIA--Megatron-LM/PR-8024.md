# Use the shared expert's TP group in the fused SwiGLU path

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8024) · state: closed · merged: False

## Original PR description

**Why.** `FusedSharedExpertMLP` ran its four tensor-parallel collectives without a group, so they used the global TP group. The unfused and overlapped paths of the same module use `self.tp_group` from its `pg_collection`. For a model on its own grid, the fused shared expert reduced over ranks its weights are not sharded over, and returned wrong values without an error.

**What.** Pass `self.tp_group` to the sequence-parallel all-gather and reduce-scatter, and to the copy/all-reduce pair used without sequence parallelism.

**Tests.** The new `test_fused_shared_expert_uses_module_tp_group` covers SP on and off. The module gets its own TP=2 communicator while the global grid has TP=1, and the global TP accessors raise while the fused path runs. The grouped TE kernel is replaced by the same math on the local shard. Outputs and gradients match the unfused path. Before the sync, on 4 GPUs, the test failed on main and passed here, and the rest of `test_shared_experts.py` gave the same results as on main. In the integration run on 8 GPUs (two nodes), `test_shared_experts.py` gives 28 passed vs 25 on main; the difference is new tests, 2 of them from this PR. In the integration run, this PR's test files show no regressions against main.

**Compatibility.** No change on the standard grid, where `self.tp_group` is the global TP group.
