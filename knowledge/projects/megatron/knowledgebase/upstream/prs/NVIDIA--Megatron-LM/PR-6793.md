# Fix DSA index-share holder isolation during activation recompute

# What does this PR do?

Fix DSA index-share holder leakage across non-packed activation-checkpointed forwards.

When DSA index sharing is enabled, source-layer top-k indices and optional lengths are stored on a holder for reuse by subsequent layers. In the non-packed path, the fallback holder was attached to `attention_mask` or the transformer config, both of which can outlive a single model forward.

With multiple outstanding checkpointed forwards, a later forward could overwrite the holder before an earlier forward was recomputed. The earlier recompute could therefore consume top-k support from the wrong forward.

This change:

- creates one private holder carrier per `checkpointed_forward` invocation;
- enables it only for non-packed DSA with `dsa_indexer_topk_freq > 1`;
- captures the carrier in each activation-checkpoint closure;
- preserves `PackedSeqParams` as the preferred holder for packed training;
- keeps the existing source-layer top-k recomputation and layer ordering unchanged;
- adds a regression test covering F1 -> F2 -> B1 -> B2 holder isolation.
