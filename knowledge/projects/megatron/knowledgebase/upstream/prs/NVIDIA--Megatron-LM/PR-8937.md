# fix(optimizer): keep Muon's lr live under the optimizer CUDA graph

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8937) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Fixes `--optimizer-cuda-graph` with Muon: the captured optimizer step kept Muon's lr from the capture step, so warmup and decay stopped there for the matrix params. Settings the captured step cannot follow are now rejected before training.

## Problem

`OptimizerCudaGraphWrapper` captures `optimizer.step()` once, after `--cuda-graph-warmup-steps`, and replays it from then on. `OptimizerParamScheduler` updates a tensor `param_group['lr']` in place but rebinds a float one.

- TE FusedAdam keeps `lr` in a tensor (`capturable=True`), so Adam follows the schedule.
- Muon reads `lr` as a Python float (`p.add_(update, alpha=-lr)`), so the replayed graph keeps the capture-time value. The logged lr still follows the schedule, so the bug only shows in the loss.

## Changes

- **Capturable Muon.** `TensorParallelMuon` and `LayerShardedMuon` take `capturable`, which is set from `optimizer_cuda_graph`.
  - With it, each param group's `lr` is a 0-dim fp32 CUDA tensor, as in TE FusedAdam. It is kept as a tensor across `load_state_dict`.
  - The update and the decoupled/palm weight decay are applied with `addcmul_`. This rounds `lr * update` before the add, so it matches the eager step up to fp32 rounding.
  - Without `capturable`, the step is unchanged.
- **Checks before training.**
  - `OptimizerConfig.validate()` allows `optimizer_cuda_graph` only with `adam` or `muon`, and with Muon only when `muon_scalar_optimizer='adam'`. The other optimizers read lr as a float.
  - `train()` calls `check_weight_decay_constant_for_optimizer_cuda_graph` before wrapping `optimizer.step`. It rejects a weight decay that changes during training, including per-group `start_wd`/`end_wd` overrides, because weight decay stays a float in both TE FusedAdam and Muon.

## Results

End-to-end runs on a Qwen3-MoE proxy, all with the same config and seed:

- Model: 16 layers, hidden 1024, 32 experts top-4, EP8, seq 4096, global batch 8.
- Optimizer: Muon on the distributed optimizer, so the layer-wise path, with Adam for the scalar params.
- Schedule: 300 iters, lr warmup 50 iters to 3e-4 then cosine decay to 3e-5. The graph is captured at iter 3.

|lm loss| diff is measured against eager Muon with this fix.

| Run | \|lm loss\| diff, mean / max | lm loss, avg of last 20 iters | TFLOP/s/GPU |
|---|---|---|---|
| Eager, this PR (reference) | - | 5.984 | 65.7 |
| Eager, this PR, rerun (run-to-run noise) | 0.004 / 0.038 | 5.984 | 65.7 |
| `--optimizer-cuda-graph`, before (main) | 0.418 / 0.696 | 6.379 | 76.7 |
| `--optimizer-cuda-graph`, this PR | 0.006 / 0.061 | 5.988 | 76.1 |

With the fix, the graphed run stays within run-to-run noise of eager. Throughput is unchanged by the fix, and the optimizer graph's speedup over eager is kept.

## Tests

`tests/unit_tests/optimizer/test_optimizer_cuda_graph_schedule.py` adds:

- **Graph vs eager under an lr warmup + cosine schedule.** Covers Adam, Muon `duplicated` and Muon `layer_sharded`, with params compared after every step. Before the fix, Muon fails from the first replay.
- **Tensor lr across `load_state_dict`.** Capturable Muon keeps a tensor lr after loading.
- **Config and weight-decay checks.** Covers the `OptimizerConfig` rejections and the constant-weight-decay check, including a per-group override.
