# What does this PR do?

Upgrade Dockerfiles and some documentation to avoid CA weakness issues and thus MITM attacks. Fixes mostly include:
- Upgrade Ubuntu's `ca-certificates` (NGC PyTorch's base OS)
- Install most-recent `uv` version (and according Dockerfile changes)
- Upgrade `certifi` version in `uv.lock` (`uv lock --upgrade-package certifi`)

Note that `python3-certifi` OS packages on Ubuntu don't need an update because they map to the OS certificates, unlike venv `certifi`s, which use bundled certificates.

More info:
- https://emudhra.we-have-a-problem.com/
- https://discuss.python.org/t/information-for-python-users-regarding-emudhra-emsign-ca-certificate-security-incident/109576
- https://ubuntu.com/blog/emudhra-ca-compromise-fixes-available (NGC PyTorch builds on top of Ubuntu)

File: `examples/multimodal/Dockerfile` · line 14

**Ensure subsequent commands use the newly installed uv.**

The installer defaults to `/root/.local/bin`, but this Dockerfile never adds that directory to `PATH`. The [base image already provides uv](https://github.com/NVIDIA/Megatron-LM/blob/d109e55a2ed32b25394e58b9924a389a837cb6a5/examples/multimodal/Dockerfile#L1-L3), so the bare [uv invocations](https://github.com/NVIDIA/Megatron-LM/blob/d109e55a2ed32b25394e58b9924a389a837cb6a5/examples/multimodal/Dockerfile#L15-L62) continue selecting the base-image executable rather than this new installation. Building the documented multimodal image therefore does not apply the intended uv certificate fix.

Install into `/usr/local/bin`, using the [existing repository convention](https://github.com/NVIDIA/Megatron-LM/blob/d109e55a2ed32b25394e58b9924a389a837cb6a5/.github/actions/action.yml#L123-L130):

```suggestion
RUN curl -LsSf https://astral.sh/uv/${UV_VERSION}/install.sh | UV_INSTALL_DIR=/usr/local/bin sh
```

The invariant is that every subsequent bare `uv` resolves to the requested version. Preserve the installer’s architecture selection, the existing `--system`/`--break-system-packages` installation behavior, and the base Python/PyTorch/CUDA stack; do not install a separate Python environment as a workaround.

**Proposed acceptance checks (not executed):** immediately after this layer and in the finished image, `command -v uv` should return `/usr/local/bin/uv` and `uv --version` should report `0.13.5`. Build using the documented command, verify the existing dependency-install layers still complete, and confirm `python -c 'import torch; print(torch.__version__)'` retains the base-image PyTorch version. Verify the suggested replacement before adopting it.
