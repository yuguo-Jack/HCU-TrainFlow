# What does this PR do?

Unfused `TEGroupedMLP` can create large FP32 temporaries when it weights low-precision activations with FP32 router probabilities.

This change chunks large products and recomputes supported, parameter-free GLU activations during backward while preserving activation rounding and the forward CUDA autocast context.

### Downsides

The chunked path supports first-order gradients only and adds Python chunk iteration and activation recomputation. CUDA router gradients can differ from the native expression by FP32 reduction roundoff; repeated chunked executions remain bit-exact.

**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Preserve autocast during activation recomputation**

When `enable_autocast=True` and a large gated activation uses an op whose CUDA autocast policy changes precision, the forward callback runs inside the autocast scope established in `megatron/core/pipeline_parallel/schedules.py:510-516`, but backward normally runs after that scope has exited and this recomputation restores only grad mode. For example, gated `squared_relu` runs its `torch.pow` in FP32 during the forward but recomputes it from the saved BF16 input here, so the FC1 and router gradients correspond to a different activation (and may also encounter a grad-output dtype mismatch). Preserve the forward autocast enabled state and dtype around the recomputation, such as by pairing AMP `custom_fwd`/`custom_bwd` decorators.
