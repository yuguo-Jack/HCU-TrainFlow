# What does this PR do?

Preserve native Torch Adam counters through `DistributedOptimizer` checkpoint restore.

Two restore paths corrupt the counter:

- `load_state_dict` shares one step tensor across parameter states. After restoring step 12, the next update advances it to 14 with two parameters or 16 with four, changing Adam bias correction.
- DP-reshardable checkpoints retain a local, nonpersistent step from the load template. Loading parameter states overwrites the saved common step 12 with the template's step 1, so the next update uses step 2.

Clone the restored scalar per parameter and keep the common step when copying native Adam's sharded parameter states.

## Validation

Linux / PyTorch 2.11.0+cu130 with normal Core imports:

- 12 CPU tests pass: six common-metadata restores and six actual DP-reshardable DCP save/load round trips, covering 1/2/4 parameters and both single-tensor and foreach Adam updates. Restored counters, parameters, and moments match a separate reference, including the next update at step 13.
- On the previous PR head `a9497453b`, the same test file passes the original six cases and fails all six DCP cases with the counter restored to 1.
- The earlier main-base control passes the two single-parameter cases and fails the four multiple-parameter cases, reproducing the shared-counter bug.

On clean final head `3c08784b5`, the two-process CPU/Gloo DCP run also passes all six round trips on each rank. Both ranks retain step 12 after restore and match the reference parameters and moments after step 13. Source hashes and normal Core import paths were verified, and CUDA remains uninitialized.

The CPU fixtures use preallocated Adam state and synthetic bucket metadata with real Core checkpoint methods and torch_dist disk I/O. They do not construct CUDA/DDP buffers or run a full training loop. The isolated runs exclude the repository-wide conftest.

`tools/autoformat.sh` passes Black, isort, pylint, and Ruff. Its non-blocking mypy stage reports missing dependencies and existing diagnostics; type checking is not clean.
