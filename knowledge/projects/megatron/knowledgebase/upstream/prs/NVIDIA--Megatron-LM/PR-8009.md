# What does this PR do?

`--fp16` causes `Float16OptimizerWithFloat16Params` to sync its fp32 master params with the model params. It does so via a custom kernel, inside `_multi_tensor_copy_this_to_that`, instead of looping through multiple `_copy` calls.

TE quantized parameters are not actual tensors, they just act like them. For example, their `_copy` method is overwritten.  The custom kernel can't copy them, because their data acts differently.

Currently, this is a problem under a set of arguments like `--fp16 --fp4-format e2m1 --fp4-param-gather`.

An alternate solution can be seen with the `--fp8-param-gather` path: just assert that `--use-distributed-optimizer` must always be used with `--fp4-param-gather`. This would also solve the issue.
