# Support NoPE shapes and unaligned top-k in TileLang sparse MLA

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7617) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Allow `fused_sparse_mla_absorbed` to use TileLang for 512-channel NoPE inputs and top-k slot counts that are not multiples of 64. These inputs currently return `None` from the adapter, selecting the fallback path even though padding can make them compatible with the existing kernel.

The adapter zero-pads 512-channel Q/K to the kernel's 576-channel layout and pads top-k slots with the existing `-1` invalid-index sentinel. It keeps the caller's softmax scale, selected keys, output shape, and autograd connection to the original inputs. Existing 576-channel inputs with aligned top-k take the same path as before.

## Issue tracking

Related to #7522: KPool/NoPE can produce these shapes. This adapter fix is independently testable against `main`; it adds no model configuration or indexer behavior and does not depend on that PR being merged.

## Validation

Tests cover Q/K widths 512 and 576, top-k counts 64/65/127, and 8/16/32 query heads. They check input preservation, sentinel/zero padding, explicit scale forwarding, and output/Q/K-gradient agreement with an independent FP32 sparse-attention reference, including an all-invalid query row.

Forward bit-exact replay tests run with stream contention and are registered in the kernel manifest. The existing DSA backward exemption remains: backward uses atomic accumulation, so its tests check numerical agreement rather than bit-exact replay.

On one H200, **276 passed, 0 failed, 0 skipped**: 18 adapter tests, 18 real CUDA output/gradient tests, 4 forward replay tests, and 236 manifest tests. Replacing only the adapter with the unmodified upstream implementation gives 15 expected failures and 3 passes in the adapter tests.

Environment: current dev NGC base `nvcr.io/nvidia/pytorch:26.08-py3`, PyTorch `2.14.0a0+4fdf77b940.nv26.08` (CUDA 13.4), TileLang `0.1.12`, TVM FFI `0.1.11`, Z3 `4.15.4.0`, and isolated test dependencies. This was targeted validation on the NGC base; the full CI image and end-to-end training were not run. No performance benchmark is claimed.
