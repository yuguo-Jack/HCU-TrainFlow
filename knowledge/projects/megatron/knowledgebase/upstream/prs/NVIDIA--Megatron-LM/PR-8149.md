# refactor(training): migrate TrainingConfig and ValidationConfig

# What does this PR do?

Migrate TrainingConfig and ValidationConfig together, making `cfg.train` and `cfg.validation` authoritative in the shared training loop while preserving existing CLI behavior.

- Read training/evaluation batch sizes, horizons, stopping policies, validation controls, and runtime housekeeping from the run config. Resolve batch-size defaults centrally before constructing training services.
- Keep derived training/evaluation iteration counts on the config; leave runtime progress on its existing owner.
- Update scheduler, dataloader, checkpoint-resume, RL batching, warmup, and dataset-construction consumers. Keep `test_mode` only in TransformerConfig while retaining `--test-mode`.
- Keep inference independent of TrainingConfig: correct pure inference/export startup calls and select compatibility-bootstrap services by container type. Checkpoint conversion can still restore sample metadata without creating a training config.

This targets `main` and does not depend on the distributed-config migration (#7778). No copyright-year changes, unrelated formatting cleanup, or new config-specific test file.
