# Support routing replay with asynchronous scheduling

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7310) · state: closed · merged: True

## Original PR description

## Summary

Enable MoE routing replay on the dynamic-inference asynchronous scheduling path without serializing the successor forward. Routing output remains associated with the forward that produced it, even when requests finish, rows compact, or prefix-cached blocks are reused.

## Architecture

- Track routing output alongside the pending asynchronous forward rather than treating logits as the only pending output.
- Snapshot each forward's routing indices and immutable token-to-block layout before later request bookkeeping can reorder the context.
- Transfer routing data through a dedicated CUDA stream and two reusable pinned CPU buffers, allowing publication of the consumed forward's routing while the successor forward remains in flight.
- Compact routing rows together with pending forward outputs when requests finish.
- For MTP, retain only accepted routing rows before rejected KV-cache blocks are released.
- Store routing against the captured block layout so ordinary, chunked-prefill, and prefix-cached requests reconstruct the correct routing history.
- Preserve the existing synchronous routing behavior on the legacy scheduling path.

## Coverage

Adds focused unit coverage and end-to-end routing-replay functional cases for asynchronous scheduling, including prefix caching with CUDA graphs.
