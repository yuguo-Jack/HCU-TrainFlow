# perf(ci): reuse workers for both Testmon selection phases

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7997) · state: closed · merged: False

## Original PR description

## What does this PR do?

Testmon selection currently launches separate `torchrun` worker groups for production and experimental tests, repeating Python startup and module imports. Run both collection phases in one worker group, with a fresh pytest session and separate private Testmon database for each phase.

The selector validates both baselines before collection and propagates failures from either session. Per-rank selection unions, mandatory test mappings, full-suite fallback, baseline generation, and actual test execution retain their existing behavior.

## Performance

A synthetic CPU benchmark using four workers, real PyTorch imports, and pytest-testmon 2.2.0 measured the following wall times after one warmup per variant:

| Trial | Separate launches | Combined launch |
| --- | ---: | ---: |
| 1 | 8.843 s | 5.023 s |
| 2 | 8.994 s | 4.722 s |
| 3 | 9.194 s | 5.023 s |
| Median | 8.994 s | 5.023 s |

Median selection time decreased by **44.2%**. All four ranks selected identical node IDs (24 production and 12 experimental), baseline database contents and modification times remained unchanged, and test-module imports fell from eight to four. This measures startup and collection overhead on CPU; GB200 CI performance remains to be measured.

## Validation

- All 13 added regression cases passed, covering equivalence to separate selections, phase-specific pytest options, empty selections, new tests, immutable baselines, and failures during either collection phase.
- The broader four-file Testmon tooling run produced 196 passes and eight failures; the additional second-session failure regression passed separately. The same eight `test_pr_label_gate` failures reproduce on untouched `main` at `441a987409b8fdd2b90b463f7999bac970109a43` because the existing test environment omits `UNIT_TESTMON_REQUESTED`.
- Black, `uv run isort`, Ruff, Pylint, Python 3.12 syntax checks, `bash -n`, and `git diff --check` passed. Mypy passed with `MYPYPATH=tests/unit_tests` to resolve the script-local cache module.
- Validation used the `nvcr.io/nvidia/pytorch:26.08-py3` container with pytest 9.1.1 and pytest-testmon 2.2.0.

The existing cache compatibility digest includes both changed runner files, so deployment requires a refreshed Testmon baseline before enforced selection can use the new code.
