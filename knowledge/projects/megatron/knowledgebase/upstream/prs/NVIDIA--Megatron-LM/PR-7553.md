# Qwen3.8-Flash-Next: gated-residual mHC, Qwen Sparse Attention, hashed n-gram memory, and mHC pipeline support

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7553) · state: open · merged: False

## Original PR description

## Summary

Adds support for training **Qwen3.8-Flash-Next** on Megatron-Core. The model is a 48-layer hybrid of
Gated DeltaNet and Qwen Sparse Attention over a 512-expert MoE. Around that it has:
- a gated-residual hyper-connection stack with 4 residual streams;
- a hashed n-gram memory (PLE) on one decoder layer;
- one MTP depth.

The vision tower of the released checkpoint is not modelled.

This version is rebased onto current `main` (`9dd63d992`) and is one commit per feature. Fixes found in
testing are folded into the commit they belong to. Two pieces of the previous version have since landed on
`main` and are no longer here: the mHC pipeline p2p sizing and the MoE metric-slot fix. **Draft**: it is
large and stacked on two open PRs (see below).

## What this branch supports

**Model components**
- **Gated DeltaNet (GDN)**
  - `--gdn-output-gate-activation`: this model gates the GDN output with sigmoid. Qwen3-Next used SiLU.
  - Three kernel backends via `--gdn-kernel-backend`: `fla` (default), `cudnn` (cuDNN Frontend's GDN) and
    `internal` (in-tree SM10x CuTe DSL forward/backward).
  - **Chunkwise context parallelism**, needed for 1M-token context. Every rank keeps all of its heads and
    holds a contiguous sequence shard, and the recurrent state is passed across CP ranks. It is built on
    `main`'s linear-attention CP framework (`linear_cp_layout`, packed-sequence CP metadata) instead of
    porting `dev`'s own layout code. The fused pre-GDR path exchanges causal-conv boundaries over the CP group.
- **Qwen Sparse Attention (QSA, hybrid symbol `Q`)**
  - Block-sparse GQA. A detached MQA indexer scores mean-pooled 4-token key blocks and picks `budget/4`
    blocks per query with a deterministic top-k. The main GQA attention (output gate, partial RoPE, qk norm)
    runs over the selected blocks only.
  - Attention backends: `cute` (in-tree CuTe DSL sparse fwd/bwd), `cudnn` (cuDNN Frontend QSA kernels) and
    `dense` (reference mask path).
  - Supports packed THD and all-gather context parallelism on the sparse path.
  - Sparse-KL indexer distillation, with a fused single-pass CuTe DSL implementation.
  - Hybrid FLOPs accounting next to `main`'s DSA terms.
- **Engram / PLE hashed n-gram memory**
  - Trainable, deterministic hashed n-gram memory on selected layers, with a `deepseek` variant and a
    `qwen` (PLE) variant.
  - **The embedding tables are row-sharded over expert parallelism (EP)**, with an all-to-all lookup, so
    table memory scales down with EP.
  - The dense part runs as fused Triton kernels: bitwise repeatable and graph-capturable.
  - `--engram-freeze-embedding` keeps the tables fixed, e.g. for post-training that must not update
    them. The tables still serve the EP lookup but get no gradient buffer and no optimizer state, and
    the lookup's backward all-to-all is skipped. The dense part still trains.
  - Works with packed-document boundaries, recompute and context parallelism. Includes an HF converter.
- **Gated-residual hyper-connections** (`--mhc-connection-variant gated_residual`, hybrid only)
  - The Qwen4-Exp 4-stream residual mechanism: a low-rank read gate over group-RMS-normalized streams, a
    per-stream write gate and an identity residual.
  - Reuses `main`'s mHC plumbing: config names, hybrid wrapper, MTP interop, selective recompute and SP.
  - The gates run as fused Triton kernels.
  - Works with full activation recompute (hybrid `checkpointed_forward` already runs the wrapper).
- **MoK (Mixture-of-Kittens) MoE megakernel**: `--moe-megakernel-backend mok`. Dispatch, routed and shared
  experts, and combine run in one kernel. Carried from #8210.

**Training infrastructure**
- **Static packed-THD CUDA graphs**
  - TE per-layer graphs over attention on packed (THD) data. Microbatches are padded to a fixed token
    and `cu_seqlens` capacity (`--thd-max-packed-sequences`, `pad_sequence_for_thd`).
  - Works on the hybrid `--sft` path, which this model uses because Engram rejects the
    sequence-packing schedulers.
  - Builds on #8361 (carried) with the `dev`-vs-`main` delta.
- **Partial (per-layer) CUDA graphs on hybrid layers**
  - Per-layer capture eligibility, so one uncapturable layer no longer forces a whole scope eager.
  - TE scopes `attn`, `moe_router`, `moe_preprocess`.
  - The **MoK router prefix** is captured (router + route compaction), and the megakernel runs eagerly on
    its outputs.
  - **Engram host capture**: the Engram lookup runs eagerly in front of its layer's graph, and the rest
    of that layer is captured.
  - A graphable hybrid mHC wrapper, written the way `dev` does it (separate commit, see "How to review").
- **Muon + distributed optimizer with EP parameters**: expert-parallel parameters that Muon does not own
  (the Engram tables) get their own DistributedOptimizer on the expert-DP group. Previously the only way
  was to drop `--use-distributed-optimizer` entirely.
- **NVTX ranges** per hybrid layer and per module, for profiling.

## Single-node proxy

`examples/qwen4exp/train_proxy_1node.sh` keeps every per-layer, per-expert and PLE dimension of the 48-layer
model and shrinks only what sets the total size.

**Shape**
- 8 layers instead of 48. Pattern `GEGEGEQEGEGEGEQE/QE` with one MTP depth.
- Hidden 2560.
- 32 experts at EP4 instead of 512 at EP64, so 8 local experts per rank either way. Top-10 routing with a
  shared expert.
- PLE on layer 3, with a 1M n-gram base instead of 20M.
- Gated residual with 4 streams.

**Training setup**: BF16, Muon on the layer-wise distributed optimizer, mock data. It has two layouts:

| Layout | Configuration |
|---|---|
| `thd32k` (default) | packed THD, one 32K-token document per rank; vocab 40832 (scaled with the layers); **partial CUDA graphs**: TE `attn` + `moe_router` with Engram host capture; **MoK** megakernel with fused router; GDN `cudnn` with the fused pre-GDR; QSA `cute` sparse attention with the fused indexer loss |
| `bshd4k` | unpacked BSHD at seq 4096, real 248320 vocab, stock kernels (`fla` GDN, native MoE, no CUDA graphs) |

**Results on this branch** (4 GPUs, 30 iterations, global batch 16):

| Layout | Peak allocated | Iteration-30 lm loss |
|---|---|---|
| `thd32k` | 123.0 GiB | 3.1470e-2 (`dev` reference 3.1468e-2) |
| `bshd4k` | 59.5 GiB | 2.7565e-2 |

Losses track the `dev`-based reference branch, and `thd32k` throughput is within ~1.5 % of it.

## Testing

**Unit tests** cover the touched test directories, run as parallel shards on one 8-GPU node. All pass except:
- **Pre-existing or environment failures, not from this PR:**
  - mamba-ssm is not installed in the image (mamba cases in `test_cuda_graphs` / `test_hybrid_moe_model`).
  - DeepEP is built without NVSHMEM (`test_moe_kernels` flex-deepep).
  - `test_hybrid_block` and `test_sequence_packing` fail the same cases on base `main`.
- **Deferred to a follow-up validation pass:**
  - `test_gated_delta_net.py` needs world size % 4 == 0 and has not yet run at 4 GPUs on this branch.
    The same paths are covered by `test_gated_delta_net_parallel` (8 GPUs), `test_gated_delta_net_chunkwise_cp`
    and `test_internal_gdn_backend_e2e`, which all pass.
  - Two numerical-tolerance tests each failed once and then passed:
    - `test_gated_residual_distributed::test_sp_grad_allreduce_matches_full_sequence`
    - `test_internal_gdn_backend_e2e[non_cp-ragged]`

**Proxy and HF parity**
- Proxy: both layouts above, plus the same flags with full activation recompute (no CUDA graphs) in BF16
  and MXFP8.
- HF parity: `examples/qwen4exp/parity/run_parity.sh` checks forward, gradients and a 20-step trajectory
  against Hugging Face `qwen4_exp` on one GPU. Results are recorded in
  `examples/qwen4exp/docs/validation/parity_and_acceptance.md`; it has not been re-run on this rebase yet.

## Known limitations

- **Full activation recompute and CUDA graphs** are mutually exclusive on this model. `main` rejects per-layer
  graphs with full recompute, and Engram / gated residual reject `full_iteration` graphs.
- **Context parallelism + packed THD + CUDA graphs** is not supported yet. The static-THD path supports a single
  CP layout, and chunkwise GDN layers run eagerly.
- **Static THD** rejects middle pipeline stages.
- **MoK** requires TP = 1 and ETP = 1.
- **QSA context parallelism** works only with `cute` + `all_gather`.
- **Under THD attention capture**, GDN `internal` falls back to `fla`.
- **FSDP** is blocked by Engram, MoK and Muon.
- **VPP + `--overlap-param-gather`** fails in the distributed optimizer.
- **Performance:** a full-recompute, no-CUDA-graph configuration is ~5–6 % slower per step than the `dev`
  reference at identical losses. This is being profiled.
