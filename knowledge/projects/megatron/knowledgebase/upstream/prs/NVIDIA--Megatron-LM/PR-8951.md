# [dev] Add chunked MCore master-weight offload with optional triple buffering

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8951) · state: open · merged: False

## Original PR description

## Summary

Extend the chunked optimizer offload introduced in #6244 to stage MCore-owned FP32 master parameters together with optimizer state.

Previously, selected MCore masters were restored to CUDA as a full window, limiting peak-memory savings. This change updates whole parameter matrices in bounded chunks and copies updated BF16 weights back before offloading each chunk.

- Create selected FP32 masters directly in pinned CPU memory to avoid the full CUDA master allocation during initialization.
- Use CUDA gradient proxies for gradient statistics and clipping.
- Add optional three-buffer staging with slot-local completion events, allowing previous-chunk D2H, current-chunk compute, and next-chunk H2D to overlap.
- Keep the existing two-buffer mode as the default.

The new joint master/state mode currently supports BF16 LayerWise Muon. FP8 parameter/gather paths are excluded.

## Usage

    --chunked-optimizer-state-offload
    --chunked-optimizer-main-params
    --optimizer-state-offload-chunk-size-mb 256
    --optimizer-state-offload-num-buffers 3

The chunk target includes selected master weights and optimizer state. Matrices remain atomic, so an oversized matrix may exceed the target. Three buffering windows consume more staging memory than two.

## Results on my test workload

Single-node, 8-GPU training. The following results are specific to my test configuration and are not a general performance guarantee.

Rank 0 memory statistics reported after the first iteration:

| Metric | Before (MB) | After (MB) | Reduction |
|---|---:|---:|---:|
| Allocated | 23,278.95 | 20,875.70 | 2,403.25 |
| Max allocated | 32,878.95 | 30,838.83 | 2,040.12 |
| Reserved | 38,080.00 | 35,920.00 | 2,160.00 |
| Max reserved | 38,080.00 | 35,920.00 | 2,160.00 |

Measured throughput increased from **220 to 222 TFLOP/s/GPU**, approximately **0.9%**. The main observed benefit in this workload is reduced memory usage, with a modest throughput improvement.

## Limitations

- GPU staging remains bounded by atomic parameter bundles rather than a strict byte cap.
- External full-master restore paths and distributed-checkpoint transport temporaries are outside the staging-memory bound.
- Throughput gains depend on matrix sizes, transfer bandwidth, and available computation to hide transfers.

## Code provenance
