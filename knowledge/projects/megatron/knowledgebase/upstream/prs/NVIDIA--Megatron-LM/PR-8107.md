# Reuse the index file handle when creating its memory map

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8107) · state: open · merged: False

## Original PR description

When `_IndexReader` reads metadata from an index header, it opens the `.idx` file once to read the header and again inside `numpy.memmap`. At large distributed-training scale, the extra open can add unnecessary metadata RPCs on distributed filesystems.

Create the memory map from the already-open file object inside the same context manager. The Python file object is closed after mapping, while the mapping keeps its existing lifetime and cleanup. The pre-supplied metadata path still opens the index only once.

Validation:
- Local CPU smoke check using the actual `DType` and `_IndexReader` class definitions extracted with AST, real NumPy mappings, and Python audit hooks: header-reading opens decrease from 2 to 1; pre-supplied metadata opens remain at 1.
- Checked both text and multimodal indices, lengths/pointers/document indices/modes, indexed access, mapping cleanup, and invalid header/version rejection.
- `git diff --check` passed.
- Full GPU unit tests were not run (no CUDA/container environment on this macOS host). `tools/autoformat.sh` was attempted but stopped because `black` is not installed.
- No distributed-filesystem performance benchmark was run; the measured improvement is the removed file open.
