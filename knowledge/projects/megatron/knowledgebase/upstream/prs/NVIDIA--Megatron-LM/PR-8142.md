# Accumulate the embedding weight gradient into main_grad

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8142) · state: closed · merged: True

## Original PR description

With gradient_accumulation_fusion, VocabParallelEmbedding's backward now adds its weight gradient into main_grad itself, as the linear layers do, and hands autograd a ZeroTensor, so the DDP hook still runs but adds nothing. PyTorch's embedding backward builds a dense [vocab, hidden] gradient that the hook then adds whole, about 1 ms per embedding use for a 129280 x 7168 vocabulary on VR200.

For 3073 to 8192 tokens, Triton kernels add only the rows of the tokens that occur, with the arithmetic of PyTorch's sort-based embedding backward followed by main_grad.add_, so main_grad is bit-identical. Otherwise the backward adds PyTorch's dense gradient into main_grad.

The MXFP8 LM head sets zero_tensor_dummy_wgrad on its weight: with MTP the main and MTP heads use it in one backward pass, and Transformer Engine versions that read the attribute return ZeroTensor dummy weight gradients, whose sum is free.

File: `megatron/core/fusions/fused_embedding_wgrad.py` · line None

flattening with `ids.reshape(-1)` can retain a non-unit stride, but the sorting kernel reads consecutive memory locations, so valid sliced inputs update the wrong word-table rows. please make the flattened IDs contiguous and add sliced and expanded input cases against `embedding_dense_backward`.

an example flow:

- use one tensor-parallel rank, an untied word table, and gradient accumulation fusion.
- pass `torch.arange(8192, device="cuda").view(1, 8192)[:, ::2]` as the 4,096 token IDs.
- the forward pass reads rows 0, 2, 4 through 8,190, while the fused backward updates rows 0 through 4,095.
- making the flattened IDs contiguous preserves the correct token destinations.

suggested fix:

```python
_sort_tokens_kernel[(1,)](
    ids.reshape(-1).contiguous(),
    sorted_ids,
    positions,
    run_start,
    run_end,
    long_runs,
    num_tokens,
    POS_BITS=_position_bits(num_tokens),
    NROWS=_NROWS,
    BLOCK=triton.next_power_of_2(num_tokens),
    num_warps=16,
)
```
