# Warn when tensor-parallel seeding and filters use the global grid

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8750) · state: closed · merged: False

## Original PR description

Depends on #8734 (which builds on #8049 and #8042), #8060, #7029, #8017, #8031 and #8730 (which builds on #8026). Please review the diff from their merge: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/56e57bda3...yx/pstate-c3-tensor-parallel-fallbacks). The merges regenerate the process-group allowlist where it conflicted. Land this after #8737: until training seeds from the grid that `initialize_megatron` builds, stock `pretrain()` calls `model_parallel_cuda_manual_seed` without groups and would warn once per process.

**Why.** `model_parallel_cuda_manual_seed` and `gtp_replica_rank` read the ranks they need from the global `parallel_state` grid when the caller omits its groups, with no warning. The duplicate filters `param_is_not_tensor_parallel_duplicate` and `param_is_not_gtp_duplicate` warn (#8734), but then call the global rank accessors directly. A caller on its own grid got the global ranks with no signal, so these fallbacks could not be removed on a published schedule.

**What.**
- `model_parallel_cuda_manual_seed` without a collection:
  - Omitted TP, EP and expert-TP ranks come from `resolve_process_groups`, which emits a `ProcessGroupFallbackWarning` (deprecated in 0.21, removed in 0.23).
  - Omitted GTP-remat ranks and sizes warn and come from `resolve_gtp_remat_group(None)`, as the layers resolve them without a collection. Those axes stay off when there is no global grid.
  - The global TP, EP and expert-TP groups are resolved only when one of those ranks is missing. A builder that passes them before any global grid exists, like Megatron-Bridge's MIMO builder, keeps seeding.
- The duplicate filters keep #8734's warning, owner and argument names. The TP filter resolves the group through `resolve_process_groups`, and the GTP filter through `resolve_gtp_remat_group`, instead of calling rank accessors. Without a global grid the GTP filter still keeps every parameter.
- `gtp_replica_rank` resolves `dp_cp`, or `expt_dp` for a routed-expert weight, through `resolve_process_groups` when `parallel_state` is initialized. It returns 0 in a single-process save, and raises `RuntimeError` when there is no group to elect a writer over, as before.
- `VocabParallelEmbedding`, `ColumnParallelLinear` and `RowParallelLinear` read the replica group of their GTP shards from the collection field instead of `getattr` with a default. An unset field still stamps no group, and checkpointing then takes the warned fallback.
- The checker goes from 171 reads to 162. Twelve accessor reads go away. Six become 3 guarded `resolve_process_groups` calls. The other 6 are GTP-remat reads that now go through `resolve_gtp_remat_group` in `process_groups_config.py`, which the checker exempts, so it no longer counts them.

The optimizers that `get_megatron_optimizer` builds and the training parameter statistics already pass their groups and do not warn.

**Tests.**
- New `tests/unit_tests/tensor_parallel/test_tensor_parallel_group_fallbacks.py`, on 4 ranks:
  - helpers given their groups read no global group and do not warn;
  - each fallback warns once and gives the same RNG states and ranks as the global accessors;
  - the seed's GTP-remat axes are off without a global grid;
  - `gtp_replica_rank` without a grid raises;
  - the layers stamp the replica group of their collection.
- #8734's duplicate-filter tests in `test_optimizer_fallback_warnings.py` now patch the groups the filters resolve, not the rank accessors they no longer call. `test_grad_norm_gtp_invariance.py` stops patching names that `layers.py` no longer imports.

On 4 GPUs, an earlier version of these commits on a base without #8734 and #8730 showed no regressions once the `test_grad_norm_gtp_invariance.py` fix above was in. With the other process-group changes from #6307 applied, the full unit test suite shows no regressions against main on 4 GPUs, and end-to-end training smokes match main's loss at every iteration. This branch itself ran only on 4 CPU gloo ranks: no regressions, 16 of the new tests pass, and the 5 seed test cases need CUDA. All 6 duplicate-filter mock tests pass.

**Compatibility.**
- On the standard grid, the seeds, the duplicate filtering and the checkpoint writers use the same groups and ranks.
- The fallbacks read group ranks. A rank forced with `set_tensor_model_parallel_rank` or the expert rank setters no longer replaces the group rank there. With `lazy_mpu_init`, which sets a provisional TP rank, the seed then uses the TP group rank. #8737 makes the same change for training and asks for sign-off on it. Checkpoint tools set rank overrides but neither seed nor call these filters.
- About 700 test calls of `model_parallel_cuda_manual_seed(123)` without a collection now warn once per process. They are not converted here. The snippet in `megatron/core/QuickStart.md` makes the same call.
- Without groups, the duplicate filters build a collection for every parameter, which is slower than one accessor call. In-repo optimizers pass their groups, so only hand-built optimizers and direct callers pay for it.
- `gtp_replica_rank`'s warning names the `explicit_group` argument, which the checkpoint path never passes. What is actually missing is `dp_cp` or `expt_dp` in the layer's collection. The `RuntimeError` text says so.
- #8764 stacks on this PR. With it, `resolve_gtp_remat_group` warns on its own and takes an `owner` argument, and `param_is_not_gtp_duplicate` and `model_parallel_cuda_manual_seed` pass `owner=None`, because they have already warned.
- Landing: this PR replaces #8734's duplicate-filter bodies with resolver-based ones and retargets its three mock tests. The warning text is unchanged.
- Needs `determinism-exempt`: `tensor_parallel/layers.py` is a registered kernel file. The changes there only plumb groups.
