# Reuse full-iteration graph storage for optimizer gradient conversion

# What does this PR do?
Full-iteration CUDA graphs with an eager optimizer currently allocate FP32 gradient-conversion buffers outside the forward/backward graph pool. Capture that conversion in the same pool so it can reuse completed forward/backward scratch. This conversion graph is disabled with `--optimizer-cuda-graph`, which captures the optimizer
step itself.

Retain and rebind gradient storage across `zero_grad()`, reject changed input storage, and rebuild conversion state after a training-graph reset. Enable this for the distributed and layer-wise mixed-precision optimizers. Optimizer CUDA graphs, precision-aware zero-copy conversion, CPU offload, and FSDP retain their existing paths.

The conversion graph roughly saves the memory for one full set of FP32 optimizer-gradient shards per GPU. For example, the device max memory decrease ~16GB for NT4 model in 256 GPUs w/ Adam without throughput regression. 



Configuration       |            Device max memory
--| ---
   Full CG without grad-copy CG        |      241.10 GiB
   Full CG with grad-copy CG              |      225.02 GiB
   Change                             |    −16.08 GiB
