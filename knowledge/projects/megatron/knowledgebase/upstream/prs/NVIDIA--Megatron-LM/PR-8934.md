# ci: skip empty unit buckets on CPU and reselect on GPUs

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8934) · state: closed · merged: True

## Original PR description

Restore CPU planning from before #8716 so empty H100/GB200 unit-test buckets do not allocate GPU runners. For eligible PRs targeting main, every dispatched bucket—including CPU planner full-fallback decisions—uses native Testmon on the existing GPU runner and container to select individual tests and apply mandatory mappings. Missing or incompatible GPU baselines, incomplete PR-file information, and native selection failures retain the existing full-bucket fallback.

Merge-group runs, explicit full-suite requests, unsupported target branches, and the existing always-full precision/disaggregation buckets remain full. CPU-empty buckets are still skipped without GPU verification; this retains the custom planner's existing dependency limitations. CPU planner job failures continue to block GPU dispatch.

### Restore the full-bucket fallback when selection cleanup fails

In [run_enforced_tests](https://github.com/NVIDIA/Megatron-LM/blob/d3baa05c9e685f7e8d8573a297760c7ca8dab4a6/tests/unit_tests/run_ci_test.sh#L337-L362), cleanup now runs outside the guarded selection chain. With `UNIT_TESTMON_MODE=enforce`, any nonzero `rm -rf` result exits the script under `set -e`, without running selection or the full bucket. The base implementation fell back to full execution for this failure, and the deleted [native-selection regression](https://github.com/NVIDIA/Megatron-LM/blob/e14be57fe1855cc61ef8af92e779239d0f5a5637/tests/test_utils/test_unit_testmon.py#L433-L510) explicitly covered it by making `rm` return 7.

**Correction:** Replace lines 350–351 in the runner with the following guarded cleanup, retaining the remaining selection chain and fallback body:

```diff
-        rm -rf -- "$UNIT_TESTMON_CACHE_DIR/.testmon-work"
-        if ! run_testmon_phase select prod \
+        if ! rm -rf -- "$UNIT_TESTMON_CACHE_DIR/.testmon-work" \
+            || ! run_testmon_phase select prod \
```

This restores the invariant that preparation or collection failures run the full bucket. It leaves the separate `preselected` validation branch unchanged and keeps selected-test failures outside the fallback guard.

**Proposed acceptance checks:** Restore the removed native orchestration regression. When cleanup returns 7, assert one full-bucket execution, no collection or selected-test execution, and success if the full bucket succeeds. Retain its collection, merge, and mandatory-mapping failure cases and its successful-path assertion that both phases execute for every repeat. Preserve the invalid-plan failure in [test_cpu_plan_execution](https://github.com/NVIDIA/Megatron-LM/blob/d3baa05c9e685f7e8d8573a297760c7ca8dab4a6/tests/test_utils/test_unit_testmon.py#L616-L677), and retain [test_selected_test_failure_does_not_run_full_bucket](https://github.com/NVIDIA/Megatron-LM/blob/d3baa05c9e685f7e8d8573a297760c7ca8dab4a6/tests/test_utils/test_unit_testmon.py#L381-L406)'s exit-1 and no-full-rerun assertions.

I inspected all changed files and their directly affected paths. The workflow child's written report was unavailable, so I completed its dispatch and coverage inspection directly. I didn't execute tests; verify the suggested patch before adopting it.
