# What does this PR do?

Migrate rerun and straggler runtime consumers to `cfg.rerun_state_machine` and `cfg.straggler`, keeping the existing config classes separate.

- Use config values for rerun initialization, loss checks, and straggler setup/reporting.
- Resolve tracker-file skipped iterations and FP16/fake-process-group normalization centrally in once-only container finalization. Keep section validation pure and repeatable.
- Preserve the shared CLI loss/gradient-check flag while allowing independent native loss and gradient settings.
- Use `report_determinism_stats` as the canonical config value; retain `--rerun-mode report_stats` as a CLI alias.
- Preserve Core's rerun checkpoint restore precedence, replay behavior, straggler cadence, and detector placement. Fault tolerance/autoresume is out of scope.

Compatibility note: existing `--rerun-mode report_stats` commands remain supported and now map to Core's canonical mode, fixing their previous initialization failure. Native configs use `cfg.rerun_state_machine.rerun_mode = "report_determinism_stats"`; `report_stats` is a CLI-only alias.

Based on pinned main; no dependency on the pending model, optimizer, DDP, or checkpoint migrations.
