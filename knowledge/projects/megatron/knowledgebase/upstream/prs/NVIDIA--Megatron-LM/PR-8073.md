# Warn on MoE process-group fallbacks and validate MoELayer collections

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8073) · state: closed · merged: False

## Original PR description

Depends on #8049 (and #6293). Please review the diff from #8049's head: [scoped diff](https://github.com/Connor-XY/Megatron-LM/compare/d89eccea46...yx/pstate-b7-moe-defaults).

**Why.** Without a `pg_collection`, `MoELayer` silently builds its groups from `parallel_state`, and `MoEMetricsTracker.report` and `get_updated_expert_bias` silently use global groups. A collection that omits a field the layer, router or token dispatchers read yields `None`: a size-1 group, a crash in forward, or a collective over the default group.

**What.**
- `get_default_pg_collection(owner=...)` goes through `resolve_process_groups`, warns once per owner (deprecated in 0.21, removed in 0.23), and builds the same nine fields with the same accessor flags, so the default groups are unchanged. If `parallel_state` was never initialized it raises, as the accessors did.
- `MoELayer` validates `ep`, `tp`, `cp`, `expt_tp`, `tp_ep`, `tp_cp` and `tp_dp_cp` with `require_process_groups`. GTP-inclusive groups stay optional.
- The metrics tracker (no collection, or no `dp_cp_gtp_remat`) and `get_updated_expert_bias` (no group) warn and keep their groups.
- Four tests that built MoE layers from partial collections now set those fields. One of them, `test_full_recompute_real_moe_matches_forward_backward`, came from main (#7521) and now requests `tp_cp` and `tp_dp_cp` like its sibling `test_real_moe_raw_branch_forward_backward`.
- Process-group reads: 174 → 166, one of them guarded.

**Tests.** New `test_moe_process_groups.py`: identity with the global groups on five grids (including GTP and EGTP), one warning per owner, an explicit collection with every global accessor patched to raise, missing fields, and the logging and expert-bias fallbacks. Before the sync, 21 of its 23 tests failed on #8049's head. On the pre-sync branch, the MoE layer, router, dispatcher, aux-loss, expert and hybrid suites matched #8049's head on 4 GPUs. In the integration run (main 77391e71cc with all #6307 PRs merged), this PR's test files show no regressions against main. On 4 GPUs, `test_hybrid_mhc.py` passes 43 tests, `test_hybrid_block.py` 67 and `test_latent_moe_layer.py` 15, the same counts as main. `test_moe_process_groups.py` passes all 23 tests there; the file is new, so main has no results for it.

**Compatibility.** Omitting the collection warns. A collection without a layer field raises; Megatron Bridge's builders set all seven.

The branch was synced with main 77391e71cc on 2026-11-01 by a merge commit that brings in #8049 after its own update to main and lists each conflict and its resolution, so existing commits and review links stay valid.

Part of #6307.
