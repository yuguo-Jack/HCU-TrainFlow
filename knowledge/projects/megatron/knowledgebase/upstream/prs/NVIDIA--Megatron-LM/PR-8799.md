# What does this PR do?

This PR lets `overlap_moe_expert_parallel_comm` (the combined-1F1B EP A2A overlap) work with two or more MTP layers. Until now it allowed at most one (`mtp_num_layers <= 1`).

**Root cause.** Each MTP depth's `mtp_post_process` appended its output, without detaching it, to `chunk_state.mtp_hidden_states`, and the last depth concatenated the list with `torch.cat`. With two or more depths, the last depth's node backward ran through the earlier depths' `mtp_post_process` graphs and freed them (`keep_graph=False`). Each earlier depth's own node backward then failed. With TE norms the error is `ctx must have .tensor_objects to restore saved tensors`; plain PyTorch reports "Trying to backward through the graph a second time".

**Fix** (`megatron/core/models/common/fine_grained_callables.py`). Each depth except the last now hands the concatenation a copy made with `node.detach(...)`. `TransformerLayerNode.backward_impl` then adds the gradient that the loss leaves on that copy back into the depth's own backward. The copy shares storage with the original. That stays safe because neither the next depth's `pre_dispatch_computation` nor `mtp_post_process` frees its input.

**Guards** (`TransformerConfig`). With `mtp_num_layers > 1` under EP overlap, the config now rejects the features the overlap schedule doesn't yet handle per depth:
- `mtp_use_repeated_layer`: the schedule plan builds one layer plan per MTP layer module, so a shared layer would run only one depth.
- `mtp_hsm`: the hidden-state mixing runs in `MultiTokenPredictionBlock.forward`, which the overlap schedule doesn't call.
- `enable_mhc_connections`: the overlap schedule feeds each depth the previous depth's contracted, normalized output instead of its multi-stream output.
- Full recompute: each MTP depth is its own recompute segment, so replaying a later depth would reuse the earlier depths' no-grad outputs and lose their loss gradients.

A negative `mtp_num_layers` is still rejected.

**Scope.** This is shared combined-1F1B code, so today it applies to GPTModel. On main, HybridModel still rejects MTP with EP overlap until #4798 lands. After that, HybridModel MTP (for example, Nemotron 3 Ultra's two MTP layers) uses this same path.
