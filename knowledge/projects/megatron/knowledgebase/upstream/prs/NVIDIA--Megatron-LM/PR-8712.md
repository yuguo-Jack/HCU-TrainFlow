# [Inference] Keep fused TP communication on the norm weights after the model is moved or cast

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8712) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Makes the fused reduce-scatter + add + rms-norm + all-gather of `inference_fuse_tp_communication` read the next layer's norm weights and epsilon from that layer at every forward, instead of a tensor taken from the weights at construction. Before, the fused kernel crashed on models built on the CPU or on the meta device and moved to the GPU, and silently used wrong norm weights when the parameters were cast or moved into DDP's buffer after construction.

**Bug.** `TransformerBlock.__init__` calls `_setup_fused_tp_communication`, which gives each `InferenceRowParallelLinear` (every `linear_proj` and `linear_fc2`) the weights of the norm that its fused kernel applies: the same layer's `linear_fc1` norm, or the next layer's `linear_qkv` norm. `TransformerLayer.get_mlp_layer_norm_weights()` and `get_qkv_layer_norm_weights()` returned `layer_norm_weight.data`, a separate tensor bound to the parameter's storage at that moment, and the last layer's `linear_fc2` got a `torch.empty_like()` placeholder. Anything after construction that rebinds a parameter's storage or replaces the Parameter leaves the kernel reading the old tensor, while the unfused path reads the live parameter. Every case needs TP > 1 with NVLS, where the kernel runs:

| After construction | Who does it | Effect on main | With this PR |
|---|---|---|---|
| `.cuda()` after `use_cpu_initialization=True` | `get_model` with `--use-cpu-initialization` (training, RL's separate inference model, `run_text_generation_server.py`, ModelOpt examples), unit tests | Host pointers reach the kernel. Triton types a small address as i32 and the compile fails (`'tt.int_to_ptr' op operand #0 must be 64-bit ... but got 'i32'`, fused_collectives.py:195); a large one compiles and the GPU dereferences a host address | Fixed |
| FP32 parameters cast to BF16 | `Float16Module` / `.bfloat16()` on a model built with the default `params_dtype` | Silent: the kernel reads the stale FP32 bytes as BF16 norm weights | Fixed |
| Parameters moved into a contiguous buffer | DDP wrapping (`get_model(wrap_with_ddp=True)`), i.e. inference on the training model, as in RL without a separate inference model | Silent: the kernel keeps the initial norm weights (ones); the checkpoint load and optimizer steps that follow update only the buffer | Fixed |
| Meta-device materialization, which installs new Parameter objects | `--init-model-with-meta-device` (`to_empty_if_meta_device`); Megatron-FSDP's meta init, where TE `reset_parameters` replaces the Parameters again | The kernel gets a null pointer from the stale meta tensor | Fixed |
| Any move or cast under `torch.__future__.set_overwrite_module_params_on_conversion(True)`, which installs new Parameter objects | Processes that set the flag | Same as the move or cast above, on the old Parameter | Fixed |

In-place updates reach the old storage, so they were not affected: `load_state_dict`, distributed checkpoint loads, RL refit (`copy_` into the parameters), torch_memory_saver and UVM offload (same addresses), and DDP's `offload_to_cpu` (storage resize). That is why the usual inference path, `get_model_for_inference` (built on the GPU in BF16, no DDP, checkpoint loaded in place), and the fused-TP functional test work on main. Models without `inference_fuse_tp_communication`, or at TP=1, never run the fused kernel.

## Fix

- Each `InferenceRowParallelLinear` holds the column-parallel layer whose input norm its fused kernel applies, `next_layer_norm_linear`, and reads that layer's `layer_norm_weight` and `eps` on every forward. Module objects outlive every transform above, and the layer resolves its current Parameter. `next_layer_norm_weights` remains as a read-only property over it. `_set_next_layer_norm_linear` stores the layer with `object.__setattr__`: a plain assignment would register it as a submodule of the row-parallel layer and duplicate its parameters and state-dict keys.
- `TransformerLayer.get_mlp_layer_norm_linear()` and `get_qkv_layer_norm_linear()` replace the weight getters, and `TransformerBlock` passes the next layer's QKV linear to `configure_fused_tp_inference(fc2_next_layer_norm_linear=...)`.
- The last layer's `linear_fc2` has no next norm but still runs the fused kernel for its residual add, and nothing reads its normalized output. It now takes its own layer's `linear_fc1` instead of an `empty_like` placeholder allocated at construction, which stayed on the construction device.

The per-forward cost is two attribute lookups; no allocation or host sync is added. Under CUDA graphs, the address read at capture is replayed, as for every other weight: in-place updates such as checkpoint loads and refit reach it, and rebinding parameters after capture requires capturing again.

## Tests

`tests/unit_tests/transformer/test_fused_tp_norm_weights.py`, for each row of the table: `.cuda()` after CPU initialization, `.bfloat16()` from FP32, a DDP-style storage move (`param.data = param.detach().clone()`), a block built under `torch.device("meta")` with `init_model_with_meta_device` and materialized on the GPU with `to_empty_if_meta_device`, and `.bfloat16()` under overwrite-on-conversion.

- `test_row_parallel_layers_hold_the_norm_parameters` (1 GPU, TP=1): every `linear_proj` and `linear_fc2` reads the current device, dtype and storage of the norm parameter it fuses (the last `linear_fc2`, if it holds one, its layer's device and dtype), and the fused block has the same state-dict keys, parameter names and module names as the unfused one.
- `test_fused_matches_unfused` (TP=2 with NVLS multicast; skips on all ranks without it): after the same weights are loaded in place into both blocks, with norm gains drawn from [0.5, 1.5], the fused block's output matches the unfused block's, and the fused kernel ran.

H100, CI image (dfw 21012189), first commit: the six cases of the first three rows fail on main and pass with the fix. Neighbor `test_dynamic_engine_parallel_and_chunked_prefill.py::TestDynamicInferenceEngineParallel::test_mtp_kv_cache_inference_optimized_sequence_parallel` passes. At this head (dfw 21013289), all 10 cases pass with this PR and all 10 fail on `main`: `.cuda()` after CPU init, FP32 to BF16, a DDP-style storage move, meta-device materialization and overwrite-on-conversion, each for the stored-reference check and the TP=2 fused-vs-unfused output check. The neighbors pass: `test_transformer_layer.py` (45 cases) and `test_transformer_block.py` (56) on 8 GPUs, and the engine test.

The kernel determinism gate passes without a label (`inference_layers.py` is registered with an exemption; no kernel or dispatch change).

**Related PRs.**
- #8561 (fused-TP residual on fallback) and #8704 (MLA fused TP, stacked on #8561) rewrite the same wiring. Both conflict with this PR in adjacent lines of `inference_layers.py` (`InferenceRowParallelLinear.__init__`), `transformer_block.py` (the `configure_fused_tp_inference` call) and `transformer_layer.py` (`configure_fused_tp_inference` and its helpers). Resolution: keep both sides. That means #8561's `qkv_fused_tp_handoff` argument and handoff lines, `residual` and `fused_tp_handoff` attributes, `get_fc2_fused_tp_handoff` and `_using_fused_tp_inference`, together with this PR's `next_layer_norm_linear`, `fc2_next_layer_norm_linear` and `_set_*_next_layer_norm_linear`. #8561's `_matmul_reduce_scatter` merges cleanly: its `next_layer_norm_weights is None` check goes through the property. #8561's `_FakeLayer` in `test_inference_layers.py` merges without a textual conflict, but must rename `get_qkv_layer_norm_weights` to `get_qkv_layer_norm_linear` and `fc2_next_layer_norm_weights` to `fc2_next_layer_norm_linear`.
- With #8704 also:
  - `get_qkv_layer_norm_linear()` returns #8704's `_get_fusable_linear_qkv()` (None for MLA).
  - `_set_fc2_next_layer_norm_linear` drops the placeholder and passes None through, so #8561 reduce-scatters and adds the residual.
  - The setter docstring keeps #8704's "None when no next layer takes its input from the fused all-gather".
  - #8704's `test_block_wiring` checks `layer.get_qkv_layer_norm_linear() is qkv` / `is None` instead of the weight getter. Its `next_layer_norm_weights` checks work unchanged.
  - Both resolutions were checked in trial merges: the modules import, the tests collect, and #8561's fake-layer wiring test passes on CPU.
  - The new tests need no change on top of either: the last-`linear_fc2` check allows None, and the fused-call count allows the last layer not to fuse.
- #8709 (inference all-gather barriers) merges cleanly. Its `test_text_generation_controller.py::TestTextGenerationController::test_inference_optimized_steps_barrier_once_per_forward[gpt_fused_tp]` case is skipped, citing this bug. Whichever of the two PRs lands second removes that skip.
