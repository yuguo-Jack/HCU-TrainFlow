# Integrate MFSDP v2 Muon in the emerging optimizer factory

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8398) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

## What does this PR do?

Enable MCore Muon+Adam training with MFSDP v2. Eligible matrices use the standalone `FsdpMuon`; embeddings, output projections, non-matrix parameters, and explicit exclusions use Adam by default. Dense and expert Muon parameters use separate optimizers on their respective DP meshes.

This is an alternative implementation to #8394 for comparison. Both PRs target `main`; only one should be merged.

## Construction and responsibilities

- Construct `FsdpMuon` directly in the emerging-optimizer branch, then wrap it in `FullyShardedOptimizer` using the original MCore config.
- Construct Adam through the existing standard factory. That factory has no Muon dispatch, no Muon exception to its empty-shard filtering, and no Muon-specific state initialization.
- Keep `FullyShardedOptimizer` as the shared MCore wrapper for gradient statistics, checkpoint conversion, and stepping. Keep Adam's existing gradient casting and model-weight refresh. The wrapper also retains its refresh after `FsdpMuon.step()`, accepting the redundant refresh for now.
- Keep Muon momentum and Adam moments in their underlying optimizers. `ChainedOptimizer` coordinates joint clipping and exposes a combined FQN-keyed checkpoint, including fused-parameter transforms for Muon momentum.

Muon construction is also partitioned by the actual FSDP mesh. With EP=1, dense and expert parameters can both have `allreduce=True` while belonging to different meshes; grouping only by the expert flag would incorrectly combine them. The tests cover models containing both dense FFNs and MoE layers.

Requires `--optimizer muon --use-megatron-fsdp --megatron-fsdp-version 2 --data-parallel-sharding-strategy optim_grads_params --muon-no-split-qkv --ckpt-format fsdp_dtensor`. Supports FP32/BF16 and one-dimensional DP meshes, including expert parallelism. Tensor parallelism, hybrid DP meshes, split-QKV updates, and precision-aware Adam remain unsupported.

## Validation

The initial integration passed 12 tests per rank on two RTX A6000 GPUs with Emerging Optimizers 0.3.0:

- FP32/BF16 Muon+Adam loss and joint-norm comparisons against unsharded training, with exact SwiGLU checkpoint continuation.
- Expert-parallel Muon and Adam training, including separate dense/expert mesh assignments.
- Existing Adam training and checkpoint tests, SGD gradient casting, and both FSDP clipping modes.

The mesh-grouping update passed an additional focused run with 9 tests passed and 2 skipped per rank on two RTX A6000 GPUs. This covers dense+MoE training and joint clipping, plus exact BF16 SwiGLU checkpoint continuation at EP=1 and EP=2; the EP=4 cases require more GPUs and were skipped. A separate two-GPU `pretrain_gpt.py` run saved at update 2, resumed, and completed update 4 with dense and MoE layers, BF16, EP=2, and Muon+Adam.

`tools/autoformat.sh` completed in check mode: Black, isort, Pylint, and Ruff passed. The script's non-blocking mypy check reported 62 errors across five files, including missing dependency typing and optimizer factory/type-union errors. The determinism coverage check passed.
