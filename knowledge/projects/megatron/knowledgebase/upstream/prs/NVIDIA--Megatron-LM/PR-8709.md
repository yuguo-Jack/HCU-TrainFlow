# [Inference][MLA][KDA] Barrier every symmetric-buffer all-gather unless its order proves the barrier redundant

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8709) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Makes every inference-optimized all-gather into a symmetric buffer barrier before it writes, unless the module that knows the order of operations on the buffer declares, statically, that no peer can still be reading it. This fixes the MLA and Kimi Delta Attention (KDA) races below, and makes the next missed case cost a barrier instead of a silent race.

**The buffer.** Inference-optimized column-parallel linears (`InferenceColumnParallelLinear`, `InferenceLayerNormColumnParallelLinear`) all-gather their sequence-parallel input with multicast stores into one shared buffer, `SymmetricMemoryManager.get_buffer("tp")`, and their GEMMs read the gathered input there. `InferenceRowParallelLinear` writes its GEMM output there and reduce-scatters it, and so does the vocab-parallel embedding in inference mode. `multimem_all_gather` ends with a barrier; `barrier_before` adds one at the start. `multimem_reduce_scatter` barriers on entry only.

**The old contract was an opt-in, and its rule was wrong.** All-gathers skipped the entry barrier by default, and a caller had to request it by hand (`set_barrier_before_all_gather`) after another all-gather. MTP did so at three sites, and the RADIO ViT embedder was restructured for the same reason (#7665). MLA and KDA missed it:

- MLA without latent caching (static batching, or an eval or MTP-draft forward without an inference context) runs the query projection's all-gather (`linear_q_up_proj`, or `linear_q_proj` without `q_lora_rank`) and then `linear_kv_up_proj`'s, back to back. A fast rank multicasts its KV latents into a peer's buffer while the peer's query GEMM still reads it. Affects `MLASelfAttention` (GPT inference spec, hybrid `mla_layer`) and `FusedMLASelfAttention` (hybrid `mla_fused_down_proj_layer`) when the up-projections are inference linears.
- KDA runs `in_proj`, `beta_proj` and, with two-stage gates, `f_b_proj` and `g_b_proj` all-gathers back to back. With two-stage gates, a rank overwrites a peer's buffer while the peer's `beta_proj` (or `f_b_proj`) GEMM reads it. KDA rejects inference contexts, so this hits eval forwards of inference-optimized hybrid KDA models, such as RL's train-versus-inference check.

Both need TP > 1 with NVLS multicast, and corrupt data silently, depending on timing. The documented rule, "an all-gather after a reduce-scatter is safe", was also incomplete: the reduce-scatter has no exit barrier, so peers may still be reducing their own segments of every rank's buffer. An all-gather that writes the same per-rank segments is safe; one of any other size overwrites a peer's segment. MLA's query projection (`q_lora_rank` wide) was safe only because an NCCL gather happens to run before it.

## Fix

**Barrier by default.** `multimem_all_gather`, `multimem_all_gather_fused` (which gains `barrier_before`), the inference column-parallel linears, `inference_all_gather_from_tensor_model_parallel_region` and `ColumnParallelLinear`'s inference output gather all barrier unless told otherwise. The opt-in setter and the hand-placed calls in MTP, MLA and KDA are gone.

**Two rules drop the barrier, in one place**, a new module `megatron/core/inference/tp_buffer_order.py`:

- `skip_all_gather_barrier_after_reduce_scatter(reduce_scatter, ag)`: the caller states that `ag`'s all-gather is the next operation on the buffer after the reduce-scatter that ends `reduce_scatter`'s forward, on the same tokens. `reduce_scatter` is an inference row-parallel linear or a vocab-parallel embedding. The rule then checks what makes it safe: both are on the same TP group, `ag`'s input width equals the reduce-scatter's output width, and there is no FP32 residual stream (which would double the all-gather's bytes).
- `skip_all_gather_barrier_after_synchronizing_collective(ag)`: the caller states that a collective synchronizing the TP group, such as an NCCL all-gather, runs between the buffer's last operation and `ag`'s all-gather.

**Declarations follow the module tree.** A module declares its order of operations on the buffer in a method `declare_tp_buffer_order(preceding_reduce_scatter)`: it applies the rules to its all-gathering linears and returns the module whose reduce-scatter is its last operation. Containers pass their submodules through `chain_tp_buffer_order` in forward order. `SelfAttention`, `MLP`, the GDN/GDN2/KDA base, `MambaMixer` and `GatedDeltaProductMixer` declare their input projection first and output projection last. `MLASelfAttention` declares its query projection after the NCCL gather of the RoPE key or latent, which inference linears always run since they require sequence parallelism at TP > 1; its KV up-projection keeps the barrier. `MoELayer` passes the order through its shared experts (routed tokens never touch the "tp" buffer). `TransformerLayer` chains its sublayers at construction; `TransformerBlock` and `HybridStack` chain their layers. A module that declares nothing keeps its barriers, and so does the first all-gather after it. Declarations are static, so CUDA graph capture and replay make the same decisions, and a host-side record of the last operation, which goes stale across graph replays, is not needed.

**MTP with hyper connections.** `h_proj`'s all-gather runs right after the NCCL gather of `e_proj`'s output, so it skips the barrier. `e_proj`'s all-gather is the first operation on the buffer after the embedding's reduce-scatter, on the same tokens, normalized; `HybridModel`, which owns both and passes its embedding to every MTP forward, declares it. Given precomputed embeddings, `MultiTokenPredictionBlock` rolls them with an NCCL all-gather over the TP group before each layer, which also synchronizes it.

**Output layer.** With sequence parallelism, `ColumnParallelLinear.forward` all-gathers its input with NCCL just before the logits all-gather, which synchronizes the group, so it skips the barrier. GPT and hybrid models pass `inference_tp_ag_barrier=False` when they did that gather themselves (last-token logits in dynamic batching). `TELMHeadColumnParallelLinear` accepts the argument; it gathers through NCCL.

**KDA `beta_proj`.** `beta_proj` all-gathered the same input that `in_proj` had just gathered. In inference, KDA now gathers it once with `InferenceColumnParallelLinear.all_gather_input` and calls both projections with `input_is_gathered=True`. Both still run through their module calls, so forward hooks fire as before (for example, the DDP pre-hook that waits for a weight's parameter all-gather). KDA's input projections live in one method, `_input_projections`. KDA runs one all-gather fewer per layer.

**Barriers, compared with main.** Decode in the GPT layers is unchanged except at the first layer of a forward.

| All-gather | main | this PR |
|---|---|---|
| First all-gather of every layer after the first in a block, and every sublayer after attention (`linear_qkv`, `linear_fc1`, shared-expert `linear_fc1`, Mamba/GDP/GDN/GDN2/KDA `in_proj`) | no barrier | no barrier (follows a same-size reduce-scatter) |
| First all-gather of a `TransformerBlock`/`HybridStack`: decoder layer 0, once per forward and pipeline stage; with fused TP, layer 0's `linear_qkv` | no barrier | **barrier** |
| MTP inner stack's first all-gather, `eh_proj`, MTP output gather | barrier | barrier |
| MTP with hyper connections: `e_proj`, `h_proj` | no barrier | no barrier (follow the embedding's same-size reduce-scatter, and an NCCL gather) |
| MLA query projection (`linear_q_up_proj` / `linear_q_proj`), including the latent-cache decode path | no barrier | no barrier (follows an NCCL gather) |
| MLA `linear_kv_up_proj` (no latent cache) | no barrier (race) | **barrier** |
| KDA `beta_proj` | all-gather, no barrier (race) | **no all-gather** |
| KDA `f_b_proj`, `g_b_proj` (two-stage gates) | no barrier (race) | **barrier** |
| Logits all-gather | no barrier | no barrier (follows an NCCL gather) |
| `ColumnParallelLinear` output gather without sequence parallelism (such as the RADIO embedder) | no barrier | **barrier** |

The decoder's first all-gather keeps a barrier because a block cannot prove what ran before it. In a plain forward that is the embedding's same-size reduce-scatter, but a model given `decoder_input` (multimodal) or running a later pipeline stage has no such guarantee, and a flag that depended on the call would not stay consistent across CUDA graph replays. The cost is one in-kernel barrier per forward step, right after the embedding's reduce-scatter has already synchronized the ranks.

No host syncs or allocations are added. Numerics are unchanged: barriers order writes, and KDA's `beta_proj` reads the same gathered bytes.

## Tests

- `tests/unit_tests/inference/test_inference_all_gather_barriers.py` (2 GPUs; GPU cases skip on all ranks without NVLS multicast). Each eval case runs a forward without an inference context at TP=2 with sequence parallelism and bf16, on the full MPU process groups. It records the operations on the buffer and the NCCL collectives that synchronize the group, checks that no all-gather writes a buffer that a peer may still read, under the corrected rule (same-size segments after a reduce-scatter, or a synchronizing collective), and that no reduce-scatter input is written while a previous reduce-scatter may still be read. It also pins which all-gathers barrier. Cases:
  - two-layer GPT `TransformerBlock`s: dense, MoE with shared experts, MLA, and MLA without `q_lora_rank`;
  - `HybridStack`s: attention+MLP, MoE, Mamba, GDP, GDN, GDN2, KDA, KDA with two-stage gates, `mla_layer`, `mla_fused_down_proj_layer`;
  - `dsa_layer`, checked on the built layers: its projections are Transformer Engine linears (NCCL), so its only buffer operation is `linear_proj`'s reduce-scatter, and the next layer's all-gather follows it without a barrier;
  - MTP with hyper connections, in inference mode: the embedding's reduce-scatter, then `e_proj`'s and `h_proj`'s all-gathers, both without a barrier and race-free;
  - CPU: every layer spec of the hybrid inference stack specs has a case (the one spec checked elsewhere, `mtp_block_spec`, names its test, and the check verifies that the test exists), and the race check counts a collective only for buffers whose group it contains.
- `tests/unit_tests/inference/text_generation_controllers/test_text_generation_controller.py::TestTextGenerationController::test_inference_optimized_steps_barrier_once_per_forward` (2 GPUs): dynamic-batching prefill and decode steps through the controller at TP=2 with sequence parallelism, on the full MPU groups, for GPT and GPT MoE with shared experts. No buffer write races, and each forward barriers once, at its decoder's first all-gather. Its cases for GPT with fused TP communication and for a Mamba/attention/MLP hybrid are skipped: they hit two bugs on main, independent of this PR and fixed separately. Fused TP communication keeps the norm weights captured at construction (`TransformerLayer.get_*_layer_norm_weights` return `.data`), so a model built on the CPU and moved with `.cuda()` hands the fused kernel host pointers: fixed in [#8712](https://github.com/NVIDIA/Megatron-LM/pull/8712). `MambaMixer.ssm_prefill` squeezes `A` to a scalar when a rank holds one Mamba head: fixed in [#8713](https://github.com/NVIDIA/Megatron-LM/pull/8713). Whichever of this PR and #8712 lands second removes the `gpt_fused_tp` skip, and whichever of this PR and #8713 lands second removes the `hybrid` skip.
- `test_text_generation_controller.py::TestTextGenerationController::test_mtp_inference_optimized_hybrid_no_unbarriered_consecutive_all_gathers` (hybrid MTP) uses the shared recorder.
- `tests/unit_tests/inference/test_tp_buffer_order.py` (CPU): the declaration rules on stand-in linears and embeddings, and the walker.
- `tests/unit_tests/inference/symmetric_buffer_test_utils.py`: the shared recorder and race check, which replaces the copies in the MLA test, the invariant test and `test_text_generation_controller.py`. It records all four multimem kernels, including the fused ones, through every module's reference to them, and the process group of each buffer and collective.
- `tests/unit_tests/tensor_parallel/test_layers.py`: the output gather barriers by default, except after the layer's own sequence-parallel input gather.
- `tests/unit_tests/inference/engines/test_dynamic_engine_parallel_and_chunked_prefill.py::TestDynamicInferenceEngineParallel::test_mtp_kv_cache_inference_optimized_sequence_parallel` gains a CUDA-graph case, like its TP=1 sibling: inference-optimized hybrid MTP at TP=2 with sequence parallelism, with the new barriers inside graphed decode and draft steps.

On H100 in the CI image, with this PR merged into main (dfw 21007036), all 10 single-GPU regression cases and 19 of the 24 two-GPU cases pass. The other five were the three MoE cases, whose config used GELU, which the inference-optimized grouped experts do not implement, and the two dynamic-batching cases now skipped for the main bugs above. At this head (dfw 21011495), with the MoE cases on squared ReLU, all 10 single-GPU cases and 22 of the 24 two-GPU cases pass, with the two skips; on `main`, 16 two-GPU cases fail and the single-GPU file fails to import. All neighbor tests pass: `TestSequenceParallelMLAAttention`, `TestFusedMLASelfAttention`, `tests/unit_tests/ssm/test_kda.py` (on 4 GPUs), `test_kda_gate_precision.py`, the engine test's eager and new CUDA-graph cases, the hybrid MTP controller test, `TestSymmCollectiveOrdering` and the `test_layers.py` dispatch test. The 57-task configuration matrix passes on an integration tree with this PR and the other open fixes (dfw 21004430, 21007037).

On main (same run), six eval cases record a race: GPT `mla` and `mla_q_proj` and hybrid `mla` and `mla_fused_down_proj` (`linear_kv_up_proj` all-gathers right after the query projection), and hybrid `kda` and `kda_two_stage` (`beta_proj`, and with two-stage gates `f_b_proj` and `g_b_proj`, all-gather right after another all-gather). The eval cases GPT `dense` and hybrid `attention_mlp`, `mamba`, `gdp`, `gdn` and `gdn2`, and the GPT dynamic-batching case, record no race: they fail only because they pin the barrier this PR adds at the decoder's first all-gather. The DSA and MTP hyper-connection cases and the CPU race-check test pass on main, and `test_tp_buffer_order.py` fails to import there (its module is new).

**Related PRs.** Merges cleanly with main and with the open fix branches, including #8561 (fused-TP residual), #8569 (Mamba `D_has_hdim`), #8570 (DSA / latent-cache absorption), #8571 (MLA sink), and the MLA latent-cache sequence-parallel (#8702), MLA MTP-draft (#8703) and MLA fused-TP (#8704) fixes; the MTP draft-isolation fix conflicts in `kda.py` (below).
- With the latent-cache sequence-parallel fix (#8702), the cache up-projection is a local GEMM, so it runs no all-gather; with #8570 alone, the reused `linear_kv_up_proj` all-gathers, now with the default barrier.
- The MLA MTP-draft fix (#8703) runs the unabsorbed up-projections without an inference context; their all-gathers follow the same declarations.
- The MLA fused-TP fix's test (#8704) forces the up-projections to NCCL to avoid the MLA race; it no longer needs to.
- With fused TP communication, the fused kernel also all-gathers the next layer's normalized input, which that layer reads without an all-gather. When it falls back (#8561), a plain reduce-scatter precedes that layer's own all-gather, as declared.
- The MTP draft-isolation fix adds a single-token KDA path for context-free draft steps that calls KDA's own `_input_projections`, so with both PRs that path gathers `in_proj`'s and `beta_proj`'s input once, as here. The two conflict in `kda.py` (imports, and the `_input_projections` definition, which each adds) and in `gated_delta_product.py` imports. Whichever lands second keeps both imports and this PR's `_input_projections`. The resolved tree passes this PR's tests, the draft-isolation tests and the 57-task matrix (dfw 21007036, 21007037).

**Follow-ups, not in this PR.** Gathering MLA's query and KV latents in one two-tensor all-gather into disjoint offsets would drop the KV barrier and a launch; it needs MLA to gather both latents itself and feed both GEMMs, so it does not fall out of this change. Fusing the embedding's reduce-scatter with the first layer's norm and all-gather, as fused TP does between layers, would remove the first layer's all-gather and its barrier.
