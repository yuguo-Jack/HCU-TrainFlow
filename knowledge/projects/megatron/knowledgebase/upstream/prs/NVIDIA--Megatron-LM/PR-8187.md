# What does this PR do?

Add an opt-in mLite checkpoint primitive that redistributes materialized expert deployment tensors between different EP layouts without gathering the full expert set first. For example, EP2 to EP4 requires selecting one source replica and reaching destinations outside a single two-rank source EP group. The caller provides the exchange group; training ownership and existing export defaults are unchanged.

Fixes #8186. Related context: #7050.

## Changes

- `ExpertLayoutPlan` maps global expert IDs to source holders and all required destination replicas using an explicit ordered process group.
- `exchange_expert_layout_tensors` coordinates bounded collective rounds, including empty or exhausted senders, and exchanges opaque tensor bytes with `all_to_all_single`. It preserves parameter names, shapes and dtypes, including FP8 values and scalar scales.
- Validate source ownership, duplicate names, matching plans/budgets and group order before the corresponding tensor exchange. Copy received byte ranges into aligned storage before reconstructing mixed dtypes.
- Add usage and limitations documentation plus real multi-process CPU/Gloo tests for split/merge layouts, replicas, noncontiguous global ranks, unequal stream lengths and invalid inputs.

The PP broadcast and matching-EP local export implementations discussed in #7050 are outside this PR. This change isolates layout mapping and collective transport from model-specific quantization, ordinary-parameter export and rollout loading; it does not enable a new production path by default.

## Boundaries

- Final-head GPU/NCCL testing and a complete optimizer-update → export → vLLM-reload check are still required before production enablement. This PR claims no end-to-end RL speedup.
- TP/ETP tensor slices must be materialized or handled by the caller. Source replicas must contain identical deployment values.
- Every exchange-group member must fully consume the iterator. The helper cannot repair an incomplete process group or a caller that stops participating.
- The byte budget bounds source bytes before replica fan-out; a single oversized tensor may travel alone. It is not a hard send/receive memory cap.
