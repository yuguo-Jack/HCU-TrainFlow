# What does this PR do?

PR unit-test selection currently allocates GPU runners before discovering that a bucket has no affected tests. Run selection on `ubuntu-latest` and launch H100/GB200 runners only for a nonempty selection or a full-bucket decision. GPU jobs execute the CPU decision without running Testmon selection again.

- Keep `testmon_selector.py` as the CLI entry point, with `testmon_plan.py` implementing CPU selection and saved-plan preparation.
- Read existing rank-0 v1 databases, select affected test files from recorded dependencies, include new/changed test files and mandatory mappings, and preserve recipe exclusions and platform markers. Selected files run with the existing production/experimental filters.
- Keep existing cache-content and PR-file validation. An unusable baseline or PR-file artifact produces a full-run decision on CPU. Setup and plan-transfer failures fail the check instead of moving selection to GPU.
- Do not reject CPU selection because Python sources or recipes changed, the baseline commit is unavailable locally, an explicit-file bucket has a different commit, or the image/interpreter differs. Remove the image-identity artifact and its build/workflow plumbing.
- Restore the existing gzip baselines on hosted CPU runners by disabling the cache action's zstd probe only during restore. Cache keys, schema and producers remain unchanged.
- Preserve full-run overrides, scheduled/merge-group execution, AWS/GCP H100 routing and GB200 labels. Missing coverage is accepted only when every expected bucket has a validated empty selection.

Baseline recording stays on rank zero, the cache stays at v1, and `testmon_cache.py` is unchanged. No new baseline inventory or recording hooks are added. The legacy distributed selector remains available, but PR workflow GPU jobs receive only `preselected` or `full`.

The CPU planner reads runtime fingerprints without importing the GPU suite or running the CI container. This has two limitations: changes used only by an unrecorded collection-time import can generate new parametrized cases that are not selected, and current container package versions are not compared against the baseline. New/changed test files and changes to recorded runtime dependencies are handled, but this is not identical to pytest collection in the target container. For example, changing only an imported parameter list can be missed if that import has no runtime fingerprint.
