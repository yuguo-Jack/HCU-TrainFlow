# What does this PR do?

Selective unit CI currently allocates GPU runners before discovering that a bucket has no affected tests. Move Testmon dependency selection to `ubuntu-latest` and launch H100/GB200 test jobs only when a validated selection or full-suite fallback requires them.

- Read executed test IDs and dependency fingerprints from the existing rank-0 Testmon databases without importing the GPU test suite. Pass affected test files to GPU execution in both production and experimental phases.
- Compare test/helper sources and the active recipe with the cached baseline commit, fetching that commit when the checkout is shallow. Changed sources or recipes require full GPU execution.
- Preserve configured AWS/GCP H100 runner groups, cloud-specific images, and GB200 runner labels through the reusable workflow.
- Preserve mandatory tests mapped to changed source directories, using the existing validated PR-files artifact, recipe exclusions, and GB200 markers.
- Check baseline image and Python interpreter compatibility during CPU selection, then verify the actual pulled image and plan identity before GPU execution. Missing or incompatible evidence falls back to full execution. Explicit-file buckets also run fully when the source SHA differs from the baseline.
- Handle absent coverage only when every expected bucket has a verified empty selection.

The cache stays at v1, and baseline recording stays unchanged on rank zero. No collection snapshot, additional recording hooks, or cache migration is required. In `tests/unit_tests/`, only the new `testmon_plan.py` and the runner's `preselected` execution path differ from main; `testmon_selector.py` and `testmon_cache.py` remain unchanged. The repository variable and label controls for selective testing remain in place.
