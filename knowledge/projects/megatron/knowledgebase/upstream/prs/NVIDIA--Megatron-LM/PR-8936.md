# Keep MTP draft-KV prefix reuse from cascading across turns

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8936) · state: open · merged: False

## Original PR description

## What

Stop the MTP draft-KV prefix-match trim from turning one declined cached block into a permanent prefix-cache miss for the rest of a multi-turn session.

With MTP speculative decoding and its draft-KV plane enabled, `_mtp_trim_prefix_match` declines a matched block when its final draft slot can't be inherited. That slot consumes one token past the block, so it isn't determined by the block's hash.

After a decline the request marks the rest of its prompt private (unregistered). The trimmed match also replaces `matched_block_ids` for the **main** model, and the Mamba match is searched only within it. So MTP lowers main-model and Mamba prefix reuse, not just draft-plane reuse.

The decline itself is usually one block. The problem is what follows it:

- **A turn that declines the previous turn's last block could never register its own copy.** The previous turn's block keeps the hash, so this turn's later blocks stay unregistered. Every later turn of the session declines the same block again and re-prefills everything after it. This happens when the prompt is block-aligned, the successor slot is unwritten, or the successor differs.
  - **Fix:** when the declined block is an unreferenced cached leaf (`ref_count == 0`, no cached children, LRU policy, last block of the match), evict it. The decliner then registers its recomputed copy and the rest of its prompt. A decline now costs one block instead of the rest of the session.
- **A continuation chunk holding the MTP boundary carry gave up its whole match.**
  - **Fix:** it now keeps the per-block successor check and inherits matched blocks that extend its leading run of inherited blocks. It still takes no prefill skip, so the carry is consumed at `finished - 1`. A match after a gap is still dropped whole.

3. **Invariant tests for same-pass admissions** (see below).

## Prefix-forest invariant

`_find_kv_match_count` relies on every cached block having all of its ancestors cached. Hashes are parent-chained, and a block registered after its parent's hash is gone silently becomes a root. The replacement keeps this:

- **It only removes a leaf.** It requires `ref_count == 0` and `block_child_count == 0`, and it deregisters through the same `_deregister_blocks` path as LRU leaf-peel eviction. That path updates the parent's child count and fires the deregistration observers, including the Mamba prefix cache's.
- **Re-registration chains correctly.** The recomputed copy's parent is the request's last kept matched block, which is registered and pinned. The rest of the prompt registers in order through the normal path.
- **No stale match can reach allocation.** The engine admits requests one at a time, and `add_request` recomputes the match and pins it before any replacement or allocation.

The new test admits two continuations of a block-aligned prompt in one scheduling pass. It covers engine order and availability checks taken before either admission, same and different continuations, and tails shorter and longer than a block. After every admission it checks that:

- every registered block's parent is registered;
- child counts match;
- every request's hash chain is prefix-closed;
- in-flight block tables reference only live blocks;
- each block's ref count equals the number of tables holding it.

**Mutation check:** dropping the `ref_count == 0` guard makes exactly the childless-in-use cases fail ("block …: ref count 1, held by 2 rows").

## Measured

Setup:

- **Model:** Hybrid Mamba/attention MoE; one repeated `*E` MTP depth, so it has a draft-KV plane.
- **Serving:** DP4 + ETP4/EP1, prefix caching with LRU, FlashInfer sampling, 3 draft tokens.
- **Workload:** real SWE-bench Pro multi-turn trace replay at concurrency 32, ~50 min per arm.
- **Code:** measured on the MTP draft-metadata branch (#8542) plus this change. The code this change touches is identical on main.

**Paired on the 14,646 (session, turn) requests common to all arms:**

- Cached share: 97.70% / 93.13% / 97.69%.
- Requests with under 50% cached: 88 / 454 / 96.

**Back-off counts:**

- Before: 1,468 mismatch declines and 171,760 prompt blocks left unregistered behind a decline.
- After: 70 declines, 69 replaced, 3 unregistered.

**Remaining limitations:**

- A decline still cascades when the declined block is in use or has registered children; this happened once in the run.
- Attention-only (non-hybrid) MTP models still take no skip on carry-holding continuation chunks, as before.
