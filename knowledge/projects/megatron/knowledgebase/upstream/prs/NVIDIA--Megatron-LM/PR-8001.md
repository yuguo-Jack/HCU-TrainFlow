# ci: Narrow Testmon cache compatibility inputs

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8001) · state: closed · merged: True

## Original PR description

## What does this PR do?

Reduce unnecessary full unit-test runs by narrowing Testmon compatibility inputs and selecting conftests per bucket. For example, adding `tests/unit_tests/tuning/conftest.py` no longer invalidates an unrelated pipeline or model bucket's baseline.

Selective PR runs prioritize fast feedback and may miss failures caused by recipe or native-build changes. This PR deliberately accepts that limitation to avoid repeated full runs during PR iteration. Merge-group validation is the final testing gate: it runs the configured unit-test suites in `full` mode with Testmon selection disabled, using the merged recipe and built image. Failures missed during PR selection may therefore first appear in the merge queue. Existing workflow tests cover merge-group exclusion with selective testing requested through either the repository default or the enable label.

Keep `COMPATIBILITY_FILES` as a set containing only `tests/test_utils/python_scripts/download_unit_tests_dataset.py`. This script prepares the datasets and tokenizers embedded in the test container, so changes can alter test inputs without changing `conftest.py` or tracked package versions. Remove the other CI/build, package, README, runner/helper inputs (including `testmon_mandatory.py`), `.dockerignore`, and the `docker/**/*` glob, including recipe hashing through the platform registry. Keep `COMPATIBILITY_GLOBS` as an empty tuple and retain its expansion logic for future compatibility inputs.

Hash ancestor conftests for each bucket. Directory and glob buckets also include descendant conftests; explicit-file buckets include only ancestors. Glob handling conservatively includes descendants below the literal directory prefix, so catch-all buckets still track all unit-test conftests even when markers or ignore rules exclude tests. The selected path-to-hash map detects additions, edits, and deletions. Runtime-version checks, platform/bucket isolation, and database-integrity validation remain in place.

Adjust existing tests in `tests/test_utils/test_unit_testmon_cache.py` for the reduced compatibility inputs and recipe behavior. Extend the existing isolation test to verify root/nested fixture scope and cache reuse after an unrelated tuning conftest is added. No test functions or parameter cases are added.

Existing baseline manifests will mismatch once because their input maps contain the removed paths. Jobs continue to fall back to full buckets until the main baseline producer publishes refreshed generations.
