## Original PR description

# feat(ssm): add shared-prefix Mamba state forking

## What this PR does

Runs a `MambaLayer` on a shared-prefix layout:

- Each prompt is scanned once, up to its last scan-chunk boundary.
- The convolution and SSM state there are forked, differentiably, into one
  branch per completion.
- Each branch replays the remaining prompt tail (fewer than `chunk_size`
  tokens) and the convolution halo.

The layer runs through its ordinary module calls. A keyword-only
`shared_prefix_call` argument carries the request to the mixer.

Nothing calls this path unless a caller opts in.

Depends on #8156 for `megatron/core/shared_prefix_layout.py`.

## Changes

- `mamba_shared_prefix.py`:
  - `forward_mamba_layer_shared_prefix(layer, hidden_states, layout)` runs one
    layer at TP1 or TP>1 with sequence parallelism, and at CP1 or CP>1
    through sequence-to-head collectives.
    - For every backend except the forward-only `packed_fused` oracle, it
      builds one `MambaSharedPrefixCall` per call. The request holds the
      layout and the selected backend.
    - It calls `layer(hidden_states=..., attention_mask=None,
      shared_prefix_call=call)`. No module attribute is set.
    - The request goes through `MambaLayer.__call__` and
      `MambaMixer.__call__`, so module hooks fire as on the dense path. Those
      hooks include Megatron FSDP's unshard, prefetch and reshard hooks and its
      per-module parameter gathers.
    - The mixer marks the request as consumed. If the layer returns without
      that mark, the call raises `RuntimeError` instead of silently running
      dense Mamba.
  - `forward_mamba_mixer_shared_prefix` is the mixer half: input projection,
    shared-prefix scan, gated norm and output projection.
  - `NRL_SP_MAMBA_IMPL` selects the backend:
    - `ragged_state_fork` (default) pads each branch only to its own chunk
      boundary, so scan work follows the real completion lengths.
    - `state_fork` uses only the public mamba-ssm API and pads every branch to
      its longest sibling.
    - `replay_prefix` rescans the prefix per branch as a parity baseline;
      `packed_recurrence` and `packed_fused` are diagnostic oracles.
      `packed_fused` is a forward-only diagnostic: its backward has never
      been validated, so it is rejected when grad is enabled.
    - The `*_training` variants use the named backend in training and
      `state_fork` in evaluation.
  - `validate_mamba_layer_shared_prefix` is meant to run for every Mamba layer
    before any layer executes. #7914 wires that in. It rejects:
    - non-`MambaMixer` mixers and missing gated RMSNorm;
    - a mixer whose TP or CP size differs from the caller's (the error names
      both sizes);
    - the contiguous linear CP layout at CP>1;
    - batch-invariant mode, for every backend: the shared paths apply the gate
      to the rounded scan output, while dense fused training and
      batch-invariant prefill and decode apply it inside the scan;
    - for the default backend: a non-power-of-two `chunk_size`, a non-default
      SSM state dtype, and missing private kernels. In those cases the error
      names `NRL_SP_MAMBA_IMPL=state_fork` as the manual workaround.
- `mamba_layer.py`: `MambaLayer.forward` takes a keyword-only
  `shared_prefix_call` argument. It passes the argument to the mixer only when
  it is set, as it already does for `packed_sequence_cp_metadata`. Dense calls
  reach the mixer with the same arguments as before. The layer still applies
  the pre-norm, residual and bias-dropout-add on the shared-prefix path.
- `mamba_mixer.py`: `MambaMixer.forward` takes the same keyword-only argument.
  - When it is set, the mixer runs `forward_mamba_mixer_shared_prefix` in place
    of its dense path.
  - With the argument set, an inference context or `packed_seq_params` raises
    `NotImplementedError`.
  - On the shared-prefix path, a mixer subclass whose forward lacks the
    argument fails with `TypeError`.
- `mamba_ragged.py`, `mamba_ragged_scan.py`: the ragged forest scan.
  - `mamba_ragged_scan.py` adapts mamba-ssm's `ssd_combined` and
    `ssd_state_passing` kernels (Apache-2.0, covered by the repository
    LICENSE). Only the inter-chunk forest state passing is new.
  - The new ragged gather sums sibling gradients in a fixed FP32 order,
    without atomics.
  - `NRL_SP_MAMBA_SAVE_INTERMEDIATES=1` keeps the FP32 scan intermediates for
    backward instead of recomputing them. It defaults to 0 and is checked at
    the first scan.
- `mamba_forest_replay.py` and `mamba_sequence_packing.py` hold the
  `packed_recurrence` backend; `mamba_branch_layout.py` holds the branch
  packing helpers that `state_fork` and `replay_prefix` use.
- The new modules import causal-conv1d, mamba-ssm and einops under guards, so
  each module imports without those packages. Validation or the backend entry
  point reports a missing causal-conv1d or mamba-ssm.
- Every shared path passes channel-last input to `causal_conv1d`, whose
  channel-first backward is wrong at some lengths.
- `MambaContextParallel.pre_conv_ssm(..., include_gate=True)`: with
  `include_gate=False` the gate stays TP-local. The default is unchanged.

The new kernels are registered in the determinism manifest.

## Tests

All results are from head 10744db4c on one GB200 node, in container
rl-gym.63635108 (torch 2.11.0+cu130, Transformer Engine 2.15.0, mamba-ssm
2.3.2.post1, causal-conv1d 1.6.2.post1, flash-attn 2.8.1).

```bash
    tests/unit_tests/ssm/test_mamba_layer.py
```

Result: 298 passed, 7 skipped.
The 7 skipped tests are #8156's attention CP2 cases, which skip at an odd
world size.
The attention tests are included because this branch carries #8156's commits.

Two GPUs:

```bash
torchrun --nproc-per-node 2 -m pytest \
    tests/unit_tests/determinism/kernels/test_shared_prefix_mamba_kernels.py \
    tests/unit_tests/shared_prefix/ssm
```

Result: 168 passed.

The five shared-prefix Mamba test files check the following; the first four
make up `tests/unit_tests/shared_prefix/ssm`.

- `tests/unit_tests/shared_prefix/ssm/test_shared_prefix_mamba_numerics.py`:
  the four differentiable backends (`ragged_state_fork`, `state_fork`,
  `replay_prefix`, `packed_recurrence`) against dense rows.
  - Branch lengths are chosen so that the `state_fork` and `replay_prefix`
    convolutions fall in the defective `causal_conv1d` length classes. The
    ragged and packed paths pad every segment to the scan chunk, so they run
    the same parity check without reaching those classes.
  - In FP32 the difference is only summation order, bounded at 5e-5 relative
    L2.
  - In BF16, shared must stay within 1.5 times the dense error against an
    FP32 reference.
  - Evaluation and training forwards must match bit for bit.
  - The `packed_fused` oracle is not tested.
- `tests/unit_tests/shared_prefix/ssm/test_shared_prefix_mamba_backends.py`:
  - backend selection and layer validation on CPU, including the
    batch-invariant rejection;
  - int32 and int64 offsets bitwise;
  - the gather backward against `index_add_`;
  - compile reuse across lengths.
- `tests/unit_tests/shared_prefix/ssm/test_shared_prefix_mamba_module_call.py`:
  - on CPU, with a stubbed mixer half, the layer and mixer module calls run in
    hook order, and both calls receive the same `shared_prefix_call`;
  - `MambaLayer.forward` passes `shared_prefix_call` to the mixer only when it
    is set;
  - a mixer forward that ignores the request raises `RuntimeError`, and one
    without the argument raises `TypeError`;
  - the mixer rejects `packed_seq_params` and an inference context together
    with a request;
  - on GPU, each differentiable backend runs a real layer through its
    submodule calls and produces a gradient for every parameter.
- `tests/unit_tests/shared_prefix/ssm/test_mamba_branch_layout.py`: branch
  pack/merge gradients against a slice reference (CPU, FP64, bitwise) and
  `gradcheck`.
- `tests/unit_tests/determinism/kernels/test_shared_prefix_mamba_kernels.py`:
  - bit-exact replay of the ragged gather and the forest scan, kernel by
    kernel;
  - replay of the ragged and packed scans with a real `MambaMixer`'s
    parameters;
  - a negative control without `MAMBA_DETERMINISTIC=1`.

  Bit-exact replay needs `MAMBA_DETERMINISTIC=1` for the SSD kernels and
  `CAUSAL_CONV1D_DETERMINISTIC=1` (causal-conv1d >= 1.6.0) for the
  convolution.

These tests run at TP1/CP1. The TP>1, sequence-parallel and CP>1 paths,
including `include_gate=False`, are covered by #7914's model-parity tests at
TP2/SP/CP2 and TP1/CP4.

On the dense Mamba path, `MambaLayer.forward` now collects the mixer's
optional keyword arguments in one dictionary.
`MambaMixer.forward` and `MambaContextParallel.pre_conv_ssm` behave as before
when the new arguments keep their defaults.
`tests/unit_tests/ssm/test_mamba_layer.py` passed in the one-GPU run above.
`test_mamba_mixer.py`, `test_mamba_context_parallel.py` and
`determinism/correctness/test_ssm_conv1d.py` were not rerun in this round,
because with `shared_prefix_call` unset and `include_gate=True` the mixer and
`pre_conv_ssm` run the same dense code as before this change.

## Notes for reviewers

- The shared-prefix request is a keyword-only call argument, as main does for
  `packed_sequence_cp_metadata`. Earlier revisions of this PR set a
  `MambaMixer` attribute around the layer call instead.
- The `consumed` flag on the request still catches a forward that accepts
  `**kwargs` and runs dense Mamba.
- The default backend calls private mamba-ssm SSD kernels, validated on
  2.3.2.post1 only.
- Planned follow-up:
  - keep `ragged_state_fork` (default) and `state_fork` (the public-API
    workaround above);
  - remove the other backends;
  - replace `NRL_SP_MAMBA_IMPL` and `NRL_SP_MAMBA_SAVE_INTERMEDIATES` with
    configuration.
