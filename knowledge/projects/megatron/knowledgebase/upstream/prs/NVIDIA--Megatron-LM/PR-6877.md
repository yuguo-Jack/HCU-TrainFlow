# What does this PR do?
<!-- Add a one line overview of what this PR aims to accomplish. -->

- Add low-rank F-decay and output-gate projections to KDA while preserving the legacy fused projection path.
- Use fused LayerNorm column-parallel projections for MLA Q/KV up-projections in hybrid specs.
- Add per-layer NOPE support to MLA, including forward-path coverage.
- Keep the small beta projection replicated so MXFP8 sees the globally aligned output dimension instead of an unaligned TP shard.
- Support selective input LayerNorm recomputation for GDN/KDA with FP8/FP4, fixing the missing hook during TransformerLayer construction.

`tp_comm_buffer_name="fc1"` looks wrong for the two up-projections (`f_b_proj` here, `g_b_proj` at L210).

`"fc1"` is one of the four names TE recognizes (`transformer_engine.py:806`), so TP-comm-overlap stays **enabled** for these layers and `ub_name="fc1"` is forwarded to TE. But the fc1 user buffer is allocated from `initialize_ub(shape=[s*b/cp, hidden_size], ...)`, while these GEMMs take an input of width `kda_f_lora_rank` / `kda_gate_lora_rank`, not `hidden_size`. That's a UB shape mismatch under `--tp-comm-overlap`.

MLA's analogous up-projections deliberately use non-recognized names (`tp_comm_buffer_name='q_up_proj'` / `'kv_up_proj'`, `multi_latent_attention.py:683,730`) so the name check trips and overlap is disabled for that layer — the same trick `beta_proj` already uses here with `"beta_proj"`.
