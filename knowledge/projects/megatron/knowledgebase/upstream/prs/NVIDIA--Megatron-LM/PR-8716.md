# ci: restore native Testmon selection per GPU bucket

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8716) · state: closed · merged: True

## Original PR description

Restore native pytest/Testmon selection and execution inside each H100/GB200 unit-test bucket's existing GPU job, following the behavior before #8019. Each bucket uses its existing runner, container, and recipe rank count, restores the compatible main baseline, collects production and experimental selections, merges rank results, applies mandatory mappings, and executes the selected tests.

Remove the custom database-based CPU planner, shared selection coordinator, saved-plan handoff, selection-only worker override, and comparison controls. Buckets dispatch directly through the GPU matrix instead of waiting for all buckets to finish selection in a shared job.

Preserve main-only enforcement, baseline/runtime and complete PR-file validation, full-run overrides, precision/disaggregation full buckets, and full-bucket fallback when native selection fails. Selected-test failures remain failures. Baseline recording/publication remains unchanged. Empty selections still produce a coverage database; missing coverage artifacts fail the coverage job.

Validation: 228 targeted CPU regression tests passed across workflow scheduling, native selection/execution, cache integrity, mandatory mappings, recipe topology, empty selections, cleanup/selection failures, and missing rank outputs. Black, isort, Ruff, pylint, targeted selector/regression typing, Bash syntax, and whitespace checks passed. The reusable unit-test workflow passes Actionlint; the main workflow retains its two existing missing-required-script diagnostics in unrelated integration calls. GPU execution validation is pending CI.
