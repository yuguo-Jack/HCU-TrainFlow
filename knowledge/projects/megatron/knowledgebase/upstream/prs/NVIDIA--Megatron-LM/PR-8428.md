# [GTP] Record all asynchronous gather completion events at issuance

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8428) · state: closed · merged: True

## Original PR description

## Description

<img width="1400" height="1100" alt="image" src="https://github.com/user-attachments/assets/d193953b-5806-4c03-9f0a-3c371a3747d1" />


Follow up on #8345 by applying issue-time completion recording to all asynchronous GTP weight gathers, including dense and activation-recompute gathers.

Previously, grouped-expert FC1/FC2 gathers recorded completion at issuance, while other gathers recorded it at consumption. This required a `completion_recorded` flag to distinguish the two paths.

This change uses one consistent policy:

```python
with torch.cuda.stream(ag_stream):
    # Issue asynchronous gather.
    ...
    if handle is not None:
        handle.wait()
    event.record()
    handle = None
```

The underlying communication wait establishes the NCCL → AG-stream dependency **before** recording the event. Consumers still wait on that event before using the weights. Recording at issuance prevents unrelated later AG-stream work from extending the consumer’s dependency.

## Changes

- Apply issue-time completion recording to all asynchronous weight gathers.
- Remove `completion_recorded`, consume-side event recording, and the unused AG-stream cache.
- Preserve host tracking, CUDA-graph handoff handling, and consumer event waits.
- Leave synchronous on-demand gathers and reduce-scatter behavior unchanged.

## Validation

GPU validation on four GB300 GPUs: **101 tests passed per rank**:

- 15 completion-ordering and grouped CUDA-graph tests.
- 80 basic GTP tests.
- 3 recomputation tests.
- 3 graph-gradient tests.
