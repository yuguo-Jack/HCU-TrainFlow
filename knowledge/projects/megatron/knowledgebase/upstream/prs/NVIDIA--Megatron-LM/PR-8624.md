# test: Ensure vocabulary-parallel workers exit cleanly

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8624) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Reap vocabulary-parallel test workers after fixture failures and require clean worker exits on success.

## Motivation

A worker error or queue timeout raises before `vp_tp2_results` reaches its joins. The peer process can remain blocked, leaving live children after the fixture has failed. Those children can delay pytest shutdown and obscure the original failure.

The success path also ignores children that remain alive or exit unsuccessfully after a timed join.

## Change

Put cleanup in a `finally` block, reap every started child, and close the queue. Require clean worker exits after successful result collection. Cleanup terminates children that remain alive and kills them if needed.

The change is confined to `vp_tp2_results` in `test_rl_utils.py`.

## Results

A matched fault-injection probe waited for the peer to enter its blocking path before injecting the same worker error:

| Observation at fixture exit | Before | After |
| --- | --- | --- |
| Live fixture children before outer safety cleanup | Two were alive, including the blocked peer. | None were alive. |
| Reported error | The original worker `AssertionError`. | The same worker `AssertionError` was preserved. |

This demonstrates cleanup after failure. A separate injection into the real fixture, with the real test module and spawned children on a B200 node, gave the same result: the base left two live children, this change left none, and both reported the injected worker error.

The parity test took 68 seconds in one base run and a median of 67 seconds across five runs with this change, so the cleanup adds no visible cost on the normal path. Historical CI failure-rate improvements have not been measured.

## Validation

The matched before/after process-lifecycle probe used a fork override. Additional probes used real spawned children with the fixture body isolated from GPU imports. Partial startup, queue timeout, and nonzero child exit preserved the relevant failure, closed the queue, and left no live children.

The existing `TestRLUtils::test_vocab_parallel_selective_log_softmax` numerical parity cases passed through `torch.distributed.run --nproc-per-node 1 -m pytest`. The fixture started its two CPU/Gloo workers using spawn. Canonical Black, isort, Pylint, and Ruff checks passed. Optional mypy was unavailable.

An independent lifecycle check also ran the extracted base and PR fixtures with real spawned children. The same injected worker error left children alive on the base and none alive on the PR. Success, timeout, partial startup, and nonzero-exit cases preserved the relevant outcome and left no live children. These checks isolate process lifecycle behavior from the GPU-dependent test module.

The RL unit-test directory also ran on eight ranks on an eight-GPU B200 node, with this branch merged into main, and it reported no failures. That environment used PyTorch 2.13.0+cu130 and the pinned Transformer Engine revision. It was not the CI image. The H100 CI bucket remains for maintainer validation.
