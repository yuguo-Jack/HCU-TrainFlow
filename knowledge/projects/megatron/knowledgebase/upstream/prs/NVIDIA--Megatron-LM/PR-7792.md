# refactor(inference): separate runtime setup from training state

# What does this PR do?

Make training runtime setup and checkpoint-state restoration explicit opt-ins, ahead of the `cfg.train` / `cfg.validation` migration.

- Share tokenizer, W&B, telemetry and runtime-flag setup through `initialize_runtime_services(args, training=False)`. Training workloads pass `training=True`; the initializer then calls `initialize_training_runtime_services(args)` for the microbatch calculator, training state, TensorBoard, timers, energy monitoring, autoresume and training signal handlers. Scripts make one runtime-initialization call; there is no duplicate inference initializer.
- Default `initialize_megatron(training=False)` to shared distributed/RNG initialization without training rerun state, checkpoint workers, or dataset compilation. Training workloads explicitly pass `training=True`.
- Keep one `load_checkpoint()` API, defaulting `restore_training_state=False`. Training callers explicitly opt into restoring optimizer, scheduler, rerun, consumed-sample state and training iteration overrides. Existing RNG-loading controls remain independent. The legacy converter also opts in because it preserves training-progress metadata. Direct downstream callers that resume training must now pass `restore_training_state=True`.
- Move microbatch-calculator synchronization out of checkpoint loading into training-side callers after progress restoration, before setup batch validation or evaluation. Cover normal resume, iteration overrides, RL reloads, upcycling and legacy fine-tuning.
- Keep existing inference loader calls unchanged. No inference checkpoint wrapper, inference-package inclusion, or inference README changes are needed. Training and legacy training-service consumers retain their existing initialization; no `cfg.train` is added to the inference container.

**Inference-owner review:** this PR explicitly rejects the training `--tp-comm-overlap` option on the inference path until an inference-specific user-buffer sizing contract is validated. Inference-specific communication optimizations are unchanged. The common CLI parser still accepts legacy training batch-size flags; removing those parsing dependencies is outside this PR.

Independent full-diff review completed before opening the PR. This PR is independent of #7778.

The wheel builds and installs successfully; Core, the dynamic inference server, and the shared checkpoint loader import from the installed wheel outside the source tree, without packaging `megatron.inference`.

Coverage includes default and explicit non-training checkpoint loads, explicit training resume, unchanged RNG-loading policy, optimizer/scheduler restoration only when requested, synchronization before evaluation-only setup validates batch sizes, and real tiny-GPT `torch` / `torch_dist` checkpoint loads without a microbatch calculator. Existing logging, lifecycle, checkpointing, JIT, config-save, static-generation and MIMO checkpoint tests are included, along with GPT-to-Hybrid optimizer-state resume and finetuning cases.

The academic generation example has startup-routing regression coverage for both prompt modes and checkpoint/no-checkpoint paths, with its preexisting missing generation-module dependency mocked. This is not end-to-end generation validation.

Not validated: full HTTP/coordinator serving, `torch_dcp` / `fsdp_dtensor` inference loads, all distributed-checkpoint topology combinations, or production-model performance.
