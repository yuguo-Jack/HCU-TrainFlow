# Add option to scale embedding norms to threshold after optimizer step

# What does this PR do?

Adds `--embedding-min-norm`, which rescales input word-embedding rows whose L2 norm falls below a threshold to twice that threshold after each optimizer update. Exact-zero rows are left alone, since they have no direction to scale along. Off by default.

- The rescale runs on the FP32 master shard owned by each data-parallel rank, between the inner optimizer step and the copy back to model parameters. Per-row squared norms are all-reduced over the data-parallel group, so every rank sees full-row norms.
- `LanguageModelEmbedding` marks its word-embedding weight with `is_word_embedding_parameter`, which separates the input table from an untied output layer. `copy_optimizer_param_metadata` carries the marker onto optimizer copies.
- It requires the distributed optimizer and FP32 master parameters. The config rejects a non-finite or non-positive threshold, and rejects use with `optimizer_cuda_graph` or Megatron FSDP.
- Interval statistics (rows rescaled, fraction rescaled, RMS norm change, exact-zero rows) are aggregated across ranks and logged to the console, TensorBoard and W&B every `log_interval` iterations.

## Notes on the port

### 1. Preserve tied embedding/output weights across pipeline stages

With PP=2, tied embeddings, no MTP, threshold 1, and a shared row `[0.25, 0]`, a zero-gradient, zero-weight-decay step projects the input row to `[2, 0]` but leaves the output-stage copy at `[0.25, 0]`. Only the input constructor receives the [new marker](https://github.com/NVIDIA/Megatron-LM/blob/5198c9f5cc5ef402c01db565aeab334f0820f3d1/megatron/core/models/common/embeddings/language_model_embedding.py#L68-L70). The [shared-weight lifecycle](https://github.com/NVIDIA/Megatron-LM/blob/5198c9f5cc5ef402c01db565aeab334f0820f3d1/megatron/core/models/common/language_module/language_module.py#L194-L258) synchronizes initial values, while [gradient finalization](https://github.com/NVIDIA/Megatron-LM/blob/5198c9f5cc5ef402c01db565aeab334f0820f3d1/megatron/core/distributed/finalize_model_grads.py#L283-L302) synchronizes gradients—not weights after this projection. The new transform therefore breaks weight tying.

**Correction:** In `LanguageModule.setup_embeddings_and_output_layer`, immediately after the duplicated-weight branch's [shared-embedding assignment](https://github.com/NVIDIA/Megatron-LM/blob/5198c9f5cc5ef402c01db565aeab334f0820f3d1/megatron/core/models/common/language_module/language_module.py#L222-L237), add:

```python
weight.is_word_embedding_parameter = True
```

That branch selects a tied output copy or an MTP input replica, not an ordinary untied output head. Retain the constructor marker and metadata propagation. As a dependent change, prevent newly selected tied replicas from inflating logical row-event counts: replace the [statistics-only gate](https://github.com/NVIDIA/Megatron-LM/blob/5198c9f5cc5ef402c01db565aeab334f0820f3d1/megatron/core/optimizer/distrib_optimizer.py#L1042-L1053) with:

```python
if (
    self.data_parallel_group.rank() == 0
    and self.distributed_optimizer_instance_id == 0
    and not getattr(model_param, "shared", False)
):
```

Do **not** exclude shared copies from projection itself. The invariant is that every tied copy receives the same transform, while statistics count the logical input table once.

**Proposed acceptance:** The PP=2 example must leave both FP32 masters and staged model rows at `[2, 0]`; a subsequent ordinary update must keep them equal. For a one-row table, record one rescale event, not two. Retain PP=1 tying, MTP input replicas, unchanged zero/at-threshold rows, and an untied output head whose `[0.25, 0]` row remains unchanged. These snippets were traced against the inspected branches but must be verified before adoption.

### 2. Reject CPU offload until its authoritative master is projected

The [new compatibility check](https://github.com/NVIDIA/Megatron-LM/blob/5198c9f5cc5ef402c01db565aeab334f0820f3d1/megatron/core/optimizer/distrib_optimizer.py#L894-L898) permits positive CPU-offload fractions when precision-aware optimization is disabled. However, `HybridDeviceOptimizer` maintains [persistent CPU parameter copies](https://github.com/NVIDIA/Megatron-LM/blob/5198c9f5cc5ef402c01db565aeab334f0820f3d1/megatron/core/optimizer/cpu_offloading/hybrid_optimizer.py#L253-L303), updates them, and [copies them back after each step](https://github.com/NVIDIA/Megatron-LM/blob/5198c9f5cc5ef402c01db565aeab334f0820f3d1/megatron/core/optimizer/cpu_offloading/hybrid_optimizer.py#L119-L181). Projecting only the GPU shard leaves the next update starting from an unprojected CPU master.

For example, offload the entire embedding, start at `[0.25, 0]`, use threshold 1, Adam `betas=(0, 0)`, LR 0.1 and no weight decay. A zero-gradient first step projects the GPU master to `[2, 0]` but leaves the CPU master at `[0.25, 0]`. A second gradient `[-1, 0]` updates approximately `[0.35, 0]` and projects back to `[2, 0]`, instead of updating the projected master to approximately `[2.1, 0]`.

**Smallest safe correction:** Add this guard in [OptimizerConfig.__post_init__](https://github.com/NVIDIA/Megatron-LM/blob/5198c9f5cc5ef402c01db565aeab334f0820f3d1/megatron/core/optimizer/optimizer_config.py#L435-L458), until projection also updates authoritative offloaded masters:

```python
if (
    self.embedding_min_norm is not None
    and self.optimizer_cpu_offload
    and self.optimizer_offload_fraction > 0.0
):
    raise ValueError("embedding_min_norm is not supported with optimizer CPU offload")
```

**Preservation and proposed acceptance:** Positive-fraction CPU offload plus the floor must raise that explicit error. CPU offload with the floor disabled, GPU-only projection, and zero-fraction offload must retain their existing behavior. If implementing support instead of rejection, the two-step example must finish near `[2.1, 0]` in both authoritative CPU and GPU masters. This proposed guard has not been executed.
