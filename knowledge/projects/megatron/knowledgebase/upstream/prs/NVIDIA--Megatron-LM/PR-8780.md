# What does this PR do?
Make `tools/preprocess_data.py --split-sentences` work again: on current `main` it either hangs forever or exits without writing a dataset.

There are two independent bugs (one commit each):

**1. Hang on NLTK >= 3.9 (including the pinned `nltk==3.10.3`)**

The sentence splitter is loaded with `nltk.load("tokenizers/punkt/<lang>.pickle")`. Since NLTK 3.9 (CVE-2024-39705), the pickled Punkt models are no longer supported and unpickling them raises (`UnpicklingError: global 'copy_reg._reconstructor' is forbidden`). This happens inside the `multiprocessing.Pool` initializer, so the pool keeps respawning failing workers and the script hangs indefinitely instead of exiting.

The fix uses `nltk.tokenize.punkt.PunktTokenizer`, which loads the `punkt_tab` model, and downloads `punkt_tab` instead of `punkt`. NLTK versions without `PunktTokenizer` keep the existing pickle-based path.

| NLTK | legacy `punkt` pickle (current code) | `PunktTokenizer` / `punkt_tab` (this PR) |
|---|---|---|
| 3.8.1 | works | not available, so the legacy path is kept |
| 3.9.1 / 3.9.2 / 3.9.3 / 3.10.0 / 3.10.3 | fails, script hangs | works |

**2. First run produces no `.bin`/`.idx` with `--partitions 1` (the default)**

After writing the intermediate `*_ss.json`, `main()` hits `if args.partitions == 1: continue`, which skips encoding. The run exits successfully with no dataset; only a second run (which finds the existing `*_ss` file) tokenizes it. With `--partitions > 1` the same run already splits and encodes. This PR removes the early `continue`.

This was reported in #1052 (converted to discussion #1075, which has no maintainer answer). The same one-line change was proposed in #7715, which was closed without review as part of a batch of PRs from that author. This PR additionally fixes the NLTK hang above, which would still block `--split-sentences` with only that change.

Reproducer on current `main` (any tokenizer; nltk 3.10.3 from `uv.lock`):

```bash
python tools/preprocess_data.py --input data.json --output-prefix out \
    --tokenizer-type HuggingFaceTokenizer --tokenizer-model <tokenizer dir> \
    --workers 2 --split-sentences
# hangs; workers keep failing with UnpicklingError. With the NLTK part fixed but not
# part 2, the first run exits 0 with only data_ss.json and no out_text_sentence.{bin,idx}
```

Verified with the real CLI and the real `punkt_tab` model, single invocation each:
- `--split-sentences` (6 docs, 18 sentences written)
- `--split-sentences --keep-newlines`
- `--split-sentences --partitions 2 --keep-sequential-samples`
- no `--split-sentences` (unchanged)
- `--split-sentences` on nltk 3.8.1 (legacy pickle fallback)

Out of scope: any exception in the pool initializer (e.g. a missing `punkt_tab` when offline) still makes `multiprocessing.Pool` respawn workers forever rather than fail fast. Happy to follow up separately if useful.
