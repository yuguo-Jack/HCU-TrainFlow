# [Test][Inference] Independent oracles for NVLS collectives

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8973) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Adds independent oracle tests for the NVLS (NVLink multicast) symmetric-memory collectives in `megatron/core/inference/communication/torch_symm_triton/`, in `tests/unit_tests/inference/oracles/nvls/`:
- `_multimem_reduce_scatter_residual_add_kernel`, the fused reduce-scatter + residual add + RMSNorm + all-gather of `--inference-fuse-tp-communication`;
- the all-gather and reduce-scatter of the inference-optimized linears and the embedding;
- `symm_mem_sync`, the barrier all of them use;
- the NVLS MoE dispatcher's three-tensor all-gather-v and its reduce-scatter-v combine, multimem and the batch-invariant rank-ordered one.

No production code changes.

**Stacked on the oracle harness PR #8966 (`test/inference-oracle-harness`)**, which adds the shared helpers. Retarget to `main` once it merges.

## Why

- The fused kernel has no unit test. Its only check is the functional golden tokens of two 583M models with H = 1152, and those goldens were regenerated in the PR that added the kernel. The H > 8192 path, where a masking bug was fixed in ecd9d1bde, has never run in a test.
- The existing tests of the other collectives can miss most errors:
  - every rank contributes the same data or a constant fill, so a wrong peer, shard or element order passes;
  - each launches one block, so the grid-stride loops never run;
  - the buffers already hold the expected data from warm-up, so a missing barrier reads correct stale data;
  - the all-gather → all-gather barrier test writes identical data twice, so it cannot see the race it guards;
  - nothing compares any of them with NCCL.

## The oracles

Each module's docstring holds the contract. It was written from the call sites and the launchers' documented API before the kernel bodies were read. The tests run on subgroups of 2, 4 and 8 ranks of the 8-GPU job (2 and 4 on a 4-GPU GB200 node). Each subgroup has its own `SymmetricMemoryBuffer`s, and every subgroup runs the same case at the same time with its own data.

References use NCCL on the same group. An exact `all_gather_into_tensor` of every rank's inputs feeds the fp64 reference and the expected copies. NCCL's fp32 reduce-scatter or all-reduce, rounded to the output dtype, is the trusted implementation of the bounded checks. Tolerances follow the harness: exact where the operation is a copy or the inputs make it exact, otherwise at most 2× the trusted error against fp64 plus one ulp. There are no hand-picked tolerances.

- **Fused kernel (high risk).**
  - The residual output is checked bit for bit on data whose in-switch sums are exact in bf16 under any order and rounding, so addressing is checked exactly on every architecture. On N(0, 1) data it is bounded per row against fp64, with NCCL's fp32 reduce-scatter followed by torch's bf16 add as the trusted path.
  - The normalized output is bounded per row against fp64 RMSNorm of the kernel's own residual output, with torch's `rms_norm` as trusted. It must be bit-identical on every rank. Doubling the weights must double it bit for bit, and zero inputs must give zero.
  - Shapes cover both launch geometries: main's shard-sized blocks and #8880's per-token blocks. They include H around the per-token block's powers of two and the 1024-lane window (8184/8192/8200, 12288, 16384, 16392), 127/128/129 tokens per rank at the 128-block grid, the production H = 1152 and 4096, and rows narrower than a warp.
  - Every third token has outliers at lane and window edges. They dominate the row's sum of squares, so a lane left out of it or counted twice is visible. N(0, 1) cases also have near-eps rows and an all-zero row.
  - Back to back on one buffer: fused → all-gather (barrier) → reduce-scatter → equal-size all-gather (no barrier). The token counts and data change every step.
  - CUDA graphs: one graph per token count, replayed in a changing order.
- **All-gather:** exact against NCCL on random bit patterns (NaN payloads, −0). It covers 2/4/8/16 elements per thread, both `barrier_before` values, 1 to 262145 chunks per rank (one block, the 128-block grid and a second grid sweep), byte offsets 0/16/1 MiB, and back-to-back all-gathers with the barrier.
- **Reduce-scatter:** exact on exactly summable data; on N(0, 1) data bounded for bf16 (trusted: NCCL's fp32 reduce-scatter rounded once) and, for fp32, within the recursive-summation bound γ_(ws−1)·Σ|x|, because the switch picks its own add order. It also runs the non-fused TP order, reduce-scatter → equal-size all-gather without a barrier, eagerly and as CUDA graphs per token count.
- **How the switch rounds a bf16 sum:** designed sums (ties, quarter and three-quarter ulps, sticky bits, carries, signs, binades, and fp32 versus bf16 accumulation) must come out as the exact sum rounded once to nearest even, which is what `.acc::f32` promises. On a failure the message counts, per case class, which rounding rule the results follow.
- **Barrier:** two probe kernels in the test file pass per-round tokens between ranks through the barrier, as the collectives use it:
  - P2P stores, then the acq_rel barrier, then local reads;
  - a token written by an earlier kernel, then the relaxed entry barrier, P2P reads and the acq_rel exit barrier.

  Each runs 40 rounds at grids 1/2/127/128, eagerly and from a CUDA graph. Afterwards every signal slot must be back to 0. The first probe also runs with every block of every rank delaying itself by its own random time (up to 20 µs) before it publishes. Block `b` must then still wait for block `b` of each peer, not for whichever peer block signals first.
- **Reduce-scatter-v combine** (tests on Blackwell only where noted):
  - exact on exactly summable data, and bounded (bf16) or within the summation bound (fp32) on N(0, 1) data;
  - what batch-invariant mode with collective `"multimem"` needs from the fp32 in-switch sum: probe tokens keep their bits across calls while their row positions, the co-batched tokens, the per-rank counts and the timing change. This runs on Blackwell, where Megatron allows the collective;
  - on Hopper, the contract Megatron will enforce instead: a batch-invariant config with `"multimem"` is refused (`test_hopper_refuses_batch_invariant_multimem`; it needs the config rejection added by s4f-multimem-rounding-doc and fails on `main`);
  - the batch-invariant ordered combine, bitwise against a rank-order fp32 sum.

  Cases span uneven, full, one-rank and all-zero per-rank counts, 1-300 tokens per rank, fp32 H up to 7168 (two windows) and bf16 H up to 8200.
- **Three-tensor all-gather-v:** exact for the 128- and 64-bit paths (top-k 8, 6, 22 and narrow rows), bf16 H up to 16384, and separate or packed buffers. Rows past the total must keep their poison. It also runs the dispatcher's step order: metadata update → all-gather-v → copy out → poison → experts write the combine buffer → combine. The per-rank counts change every step, eagerly and as one CUDA graph per local count.

Memory checks:
- inputs and outputs have NaN guard bands;
- outputs and unread rows are NaN-poisoned;
- 64 KiB sentinels sit before and after every region of the symmetric buffers;
- read-only inputs and the device metadata scalars must be unchanged.

Every result is checked after its loop, with no NCCL call inside. One random rank is delayed before each collective, so a missing barrier shows up as stale or overwritten data. One small case per module carries the `sanitizer` marker; the fused kernel's is a dedicated test, `test_sanitizer_small_case`, so a compute-sanitizer (memcheck) run can select it alone at any world size.

A check that fails on one rank fails the test on every rank (`nvls_oracle_utils.agree`). This keeps the job in step instead of leaving ranks waiting in a later collective. A world barrier follows every test, because the reduce-scatter kernels end without one.

## Expected failures on `main`

- `test_rows_narrower_than_a_warp[ws*-H{8,64,128}-tpr1]`: when the whole per-rank shard is at most 16 lanes, the fused launcher passes `num_warps = 0`, which Triton rejects. #8880 fixes this; the cases pass with it.
- `test_launcher_refuses_inputs_outside_the_contract`: the fused launcher checks only dtypes and `numel % 8`. It launches on T % ws ≠ 0 (the last rank then writes past T·H·2 into every rank's buffer and past its residual rows), on H % 8 ≠ 0 (misaligned rows), on fp32 or wrong-length norm weights (silently misdecoded), and on residuals of the wrong size. These are findings O5-N1 and O5-N2; the fix PR s4f-nvls-launcher-checks adds the checks. The CPU test shows them with a launch recorder. No production caller is known to pass such inputs: dynamic inference pads T to a multiple of TP.

- `test_hopper_refuses_batch_invariant_multimem` (H100): batch-invariant mode accepts `batch_invariant_collective="multimem"` on Hopper. The fix PR s4f-multimem-rounding-doc rejects it at config time; the test passes with it.

## Findings from the first GPU run

- **O5-N3 (H100):** the fp32 in-switch sum is not correctly rounded on H100, and its add order differs between GPU sets (the two 4-GPU groups of a node gave different bits for the same data). GB200 matched. The dispatcher's comment (`token_dispatcher_inference.py:667-671`) claims correct rounding for the batch-invariant `"multimem"` combine. That mode only needs a token's sum to depend on its partials alone. On one H100 system it did not: a token's sum changed bits with its row position and the co-batched tokens. It held on another H100 system and on GB200. This matches the Hopper NVLS multicast-history driver issue (NVIDIA/nccl#2360), for which deterministic training already rejects NVLS on every Hopper GPU. So s4f-multimem-rounding-doc rejects batch-invariant `"multimem"` on Hopper at config time, and corrects the comment. This PR tests batch invariance on Blackwell and the rejection on Hopper; no H100 case depends on the driver.
- **O5-N4 (GB200):** the bf16 in-switch sum does not round to nearest even. Results differ by one ulp in about 10-17% of elements even for two terms, deterministically. H100 matches.
  - This is the hardware, and s4f-multimem-rounding-doc documents it in `multimem_asm.ld_128`: fp32 accumulation, rounded by the switch, mostly toward zero, within one bf16 ulp.
  - `test_bf16_in_switch_sum_rounding` asserts that contract on Blackwell: each result is exactly one of the two bf16 values adjacent to the exact fp32 sum, a faithful rounding. It still rejects bf16 accumulation.
  - Every measured GB200 result meets it. Hopper keeps the nearest-even check.
  - No xfail is involved.

## Tests

- 367 test ids at 8 ranks (302 at 4): 352 multi-rank GPU cases and 15 CPU launcher cases. Later commits add the 2 batch-invariant config tests and the fused kernel's sanitizer case (370 ids at 8 ranks, 305 at 4).
- Mutation testing (H100) found that the barrier probes missed a barrier whose slots ignore the block id. The blocks of one rank publish together, so any peer block's signal came late enough. The per-block delays added in the third commit expose it. The probe compiles to cubin for sm_90 and sm_100 with Triton's ptxas; it has not run on a GPU yet.
- First GPU run (before the follow-up commit): H100 337 passed and 7 failed; GB200 230 passed and 55 failed. Each failure is explained in the packet. The changes: exactly summable data for the exact checks, a derived bound for fp32 sums, the batch-invariance test in place of the correctly-rounded one, the designed rounding test, and the dispatcher's metadata barrier at the start of every dispatch step (a step without tokens has no other barrier).
- Local checks only, since there is no multi-GPU machine here:
  - collection at both world sizes;
  - the CPU launcher cases: 10 pass and the 5 O5-N1/N2 cases fail, on `main` and on the trees of #8880, #8709, #8879 and #8868;
  - a thread-per-rank emulation that runs every eager GPU test unchanged at 2 and 4 ranks (249 cases), with torch models of each kernel and a fake NCCL. All pass, and injected kernel mutants fail the tests wherever they change an output;
  - the barrier probe kernels compiled, ran and replayed from a graph on a single SM89 GPU (smoke only).
- The H100 and GB200 runs are next. Runtime is unmeasured; Triton compiles a variant per rank, group size and hidden size, so expect 10-15 minutes on a cold cache.

## Interaction with other open PRs

- **#8880 (t3-r09f2)** launches the fused kernel with one block per token. Every case here is geometry-agnostic and must pass with it. The narrow-row cases above need it.
- **#8709 (n12)** makes `barrier_before=True` the default of `multimem_all_gather`. Every call here passes it explicitly. The reduce-scatter → equal-size all-gather without a barrier is the one rule it keeps.
- **#8879 (t3-r09f1)** runs the batch-invariant NVLS MoE test at EP = world size and asserts the same correctly-rounded fp32 combine. This PR checks that claim on the kernel directly.
- **#8868 (t3-r04f3)** masks the barrier's peer loads for padded world sizes and makes the ordered combine's adds `add_rn_f32`. The barrier probes and `test_ordered_sum_is_rank_ordered` are the cases it must pass. If LLVM reorders main's plain adds on the target compiler, the ordered test fails on main.
