# fix(dsa): warn once when a selected fused hook falls back

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8160) · state: open · merged: False

## Original PR description

## What
When the configured fused DSA backend declines a hook (`run_fused_qk_topk`, `run_fused_qk_topk_with_loss`, `run_fused_absorbed_sparse_attention`, `run_fused_dsa_attention`), the caller falls back to the PyTorch reference path. That path is far slower and materializes much larger tensors; the naive top-k builds the full `[sq, b, h, sk]` fp32 score tensor.

`_log_declined_hook` logged this at DEBUG on every call, so a run could sit on the reference path with nothing in the logs. This changes it to a WARNING emitted once per (backend, hook, reason).

## Why once
Declines happen on every forward, so a per-call warning would flood the logs. The key keeps distinct reasons visible.

## Testing
- **Unit test:** `test_dsa_kernel_hooks_log_declined_backend` now asserts the message is visible at WARNING level and that a repeat decline doesn't log again. It and `test_dsa_kernel_hooks_dispatch_to_backend` pass on this branch (GB300).
- **Downstream check:** on a downstream fork, a healthy GLM-family DSA run (cuDNN backend, 262k and packed 8x32k) emits no declined warnings, so this doesn't add noise to normal runs.
