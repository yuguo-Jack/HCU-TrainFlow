# test: Define the NVFP4 attribute in the clamped ReLU2 stub

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8912) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?
Fix the BF16 cases of `test_flashinfer_clamped_relu2_replays`, which fail on SM10x GPUs before they reach replay.

## Motivation

`InferenceGroupedMLP._flashinfer_forward` reads `_nvfp4_weights` on every call that does not use MXFP8 weights. The stub module in this test does not define that attribute, so both BF16 cases fail with this error:

```
AttributeError: 'types.SimpleNamespace' object has no attribute '_nvfp4_weights'
```

The MXFP8 cases return before that read. Other GPU generations skip the test, so H100 jobs do not reach the failure.

## Change

Set `_nvfp4_weights=None` on the stub, which is the value that `InferenceGroupedMLP` starts with.

## Validation

On an eight-GPU B200 node, both BF16 cases failed with that error before this change. With this change, the BF16 and MXFP8 cases ran on one rank and on eight ranks with no failures. `tools/autoformat.sh` in check mode and the kernel determinism coverage check also reported no problems. These runs used PyTorch 2.13.0+cu130 and the pinned Transformer Engine revision, not the CI image. The test skips on H100, so H100 CI will not exercise this change.

The first run of the BF16 cases with a cold kernel cache did not finish on eight ranks within 40 minutes, because FlashInfer was compiling kernels. The results above used a warm cache.

To reproduce on an SM10x GPU:

```sh
uv run python -m torch.distributed.run --nproc-per-node 1 -m pytest \
  "tests/unit_tests/determinism/kernels/test_inference_kernels.py::test_flashinfer_clamped_relu2_replays" -k bf16
```
