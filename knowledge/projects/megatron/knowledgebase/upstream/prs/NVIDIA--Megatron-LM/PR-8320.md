# What does this PR do?

Improve ordinary-mode MoE inference performance through tuned expert GEMM launches, parallel token alignment, and tiled routing-weighted reduction

This extracts the expert-compute optimizations from [#8114](https://github.com/NVIDIA/Megatron-LM/pull/8114) into a separate PR.

:warning: For major changes (either in lines of code or in its impact), please make sure to first share a design doc with the team. If you're unsure what's the best way to do so, contact @NVIDIA/mcore-oncall.

## Changes

### Expert FC1/FC2 GEMM configuration

Add offline-tuned BF16 launch configurations keyed by GPU capability and expert tensor geometry. FC1 and FC2 can use different configurations while sharing the token-alignment block size. The tables cover the Nano, Super and Ultra expert shapes on SM 10.3 at EP4 and EP8; other shapes and devices keep the existing defaults. Every tuned configuration reproduces the default configuration's output bitwise. On the rebased code, the Nano EP4 table's first row measured about 1% slower than the default configuration at 1–2 tokens, so that table now has separately tuned rows for 1 and 2 tokens

### Parallel token alignment

Add an atomics-free parallel kernel to construct the sorted token indices, expert block IDs, and padded-token count. The existing alignment implementation remains the fallback for larger workloads

### Tiled routing-weighted reduction

Add a tiled `_moe_sum` kernel that processes multiple tokens and columns per CTA. It preserves each element's accumulation order and skips non-local expert slots

These optimizations apply to ordinary execution. BI execution retains its existing GEMM configurations, alignment implementation, and FP64 reduction

Production changes are confined to `megatron/core/inference/moe/vllm_fused_moe.py`

## Performance

End-to-end batch generation speedup against main `a0ef64615`, with the 95% interval in brackets. The measured candidate is the PR before its last table change; the head (`7db9028b3`) adds only the Nano EP4 rows for 1–2 tokens, which these EP8 runs do not use, and the matching test hints.

| Model | BS16 speedup | BS32 speedup |
|---|---:|---:|
| Nano | 1.041x [1.023, 1.060] | 1.046x [1.030, 1.063] |
| Super | 1.019x [1.011, 1.028] | 1.042x [1.014, 1.070] |
| Ultra | 1.017x [1.014, 1.020] | 1.023x [1.018, 1.028] |

All six cells are measured speedups (95% interval above 1). Super and Ultra now use their own tuned tables; in the previous revision of this PR, with the default configurations, they measured 1.008x / 1.011x and 1.012x / 1.015x against main `db3a6cd8a`.

Measurement setup:

- Two nodes, 8 NVIDIA GB300 GPUs, TP8 / EP8 / ETP1; official BF16 checkpoints converted to Megatron Core, FP32 router, FA4, decode CUDA Graphs, NVLS dispatcher; batch-invariant mode and prefix caching disabled; shared-expert overlap off
- 16 or 32 requests with 32–33 prompt tokens and exactly 128 greedy output tokens each
- Three independent allocations per model. Each runs four fresh processes per batch size (baseline → candidate → candidate → baseline at BS16, reversed at BS32) with five timed generations per process
- Speedup = baseline / candidate latency, using the mean of the two per-process medians; the table shows the geometric mean of the three allocation ratios and a 95% t interval on the log ratios. All samples are retained
- Triton autotune selection is pinned for both versions (`--triton-autotune-mode pinned`), so fresh processes generate comparable tokens. Greedy output tokens were identical between main and this PR in all 18 model / batch / allocation comparisons
- Timing starts after request enqueue and ends when all requests finish (prefill and decode). Model loading, warmup and tokenization are excluded

Tuned-table A/B (whole `vllm_fused_moe` call, default configs vs the tuned table, one GB300, 8 layers in a CUDA graph, 6 alternating rounds, 26 token counts from 1 to 8192 on and between table rows; outputs bitwise equal at every point; Nano EP4 is the median of 4 runs on 2 GPUs):

| Table | 1–32 tokens | 48–1024 tokens | 1536–8192 tokens |
|---|---:|---:|---:|
| Nano EP4 | 1.01–1.11x | 1.12–1.24x | 1.07–1.12x |
| Nano EP8 | 1.01–1.06x | 1.06–1.38x | 1.06–1.13x |
| Super EP4 | 1.03–1.08x | 1.01–1.13x | 1.04–1.13x |
| Super EP8 | 1.01–1.10x | 1.00–1.19x | 1.02–1.16x |
| Ultra EP4 | 1.00x | 1.04–1.10x | 1.06–1.22x |
| Ultra EP8 | 1.00–1.04x | 1.01–1.13x | 1.07–1.24x |
