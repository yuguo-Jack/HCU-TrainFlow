# What does this PR do?
MXFP8 NCCL EP Dispatch is currently not functional due to Dispatch Op outputting MXFP8 GroupedTensor. GroupedTensor does not have functionality of untyped_storage.resize_(0). It also doesnt make sense to implement such functionality for custom tensor with no unified backing storage.

Aims at solving 2 main problems
1. Gets rid of self.inputs member variable of ScheduleNode. inputs doesnt need to be saved in ScheduleNode. Only reason it is there, is because grads need to be propogated by autograd. This can be done by wrapping the inputs in a ScheduleNodeWrapper which lets the grad flow to the wrapper without having to save the inputs in the Schedulenode object. Even the outputs doesnt need to be saved and rather the autograph graph's output edge needs to be saved to start the node.backward.
   -  As shown in results below. This is better than manually using free_inputs in only some of the nodes based on should_free_input method. Since garbage collection based clearance gives better control freeing tensors not needed in the workflow, in comparison to, storing all tensors and freeing them manually.

2. Rearranges the code for dispatch/grouped_mlp/combine so that the permuted_local_hidden_states gets garbage collected early by pytorch instead of us having to manually release memory using untyped_storage.resize_(0)(which is anyway missing in GroupedTensor). Although the manual release is removed/no longer needed at the ScheduleNode Boundary. CPU offloading still force releases the tensors in the saved tensor hook after offloading the tensors. That force releasing is still kept intact for ordinary tensors(as a measure of caution). For GroupedTensor(used with MXFP8 Dispatch) we dont do that anymore and rely on garbage collection. As shown through results it is not necessary as well.

Has been verified on DSV3 4n Proxy Config. And there is in fact advantage in the memory savings.
