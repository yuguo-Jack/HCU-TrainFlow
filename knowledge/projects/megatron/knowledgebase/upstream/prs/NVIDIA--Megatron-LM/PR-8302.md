# What does this PR do?
**Motivation**

MXFP8 NCCL EP Dispatch is currently not functional because the Dispatch Op outputs an MXFP8
`GroupedTensor`. `GroupedTensor` does not support `untyped_storage().resize_(0)`, and implementing
that operation does not make sense for a custom tensor with no single backing storage.

**Aims at solving 2 main problems**
1. Refactors `ScheduleNode` activation ownership so releasable inputs no longer require
`untyped_storage().resize_(0)`.
   - `self.inputs` is retained because the node still needs a source from which to retrieve input
     gradients.
   - Only inputs selected by the existing `should_free_input` policy are represented by a
     storage-free `ScheduleNodeInputWrapper`. The real detached tensor is moved into the node's
     forward graph and is released through normal Python/autograd lifetime management.
   - Inputs that are needed in backward remain ordinary detached tensor leaves, preserving the
     pre-PR behavior and avoiding wrapper/unwrap overhead on those boundaries.
   - Outputs are represented by autograd `GradientEdge`s instead of retaining output tensors.
     Transformer-layer side outputs similarly use ordinary detached leaves and producer edges.

2. Rearranges dispatch/grouped-MLP/combine ownership so `permuted_local_hidden_states` can be
garbage-collected instead of being manually released with `untyped_storage().resize_(0)`.
Fine-grained CPU offloading still force-releases ordinary tensors after offload as a precaution.
For `GroupedTensor`, it relies on garbage collection because there is no unified storage to resize.

This has been verified on the DeepSeek-V3 4-node proxy configuration with combined 1F1B overlap,
MXFP8 NCCL EP, paged stashing with TE main.

MXFP8 Dispatch is not functional on plain main, so the baseline is current main plus
[PR #7992](https://github.com/NVIDIA/Megatron-LM/pull/7992), which has explicit `GroupedTensor`
release handling.

Steady-state performance (iterations 50-100) is equivalent: 1473.49 ms/iteration for PR #7992 and
1473.40 ms/iteration for this PR (-0.007%).
