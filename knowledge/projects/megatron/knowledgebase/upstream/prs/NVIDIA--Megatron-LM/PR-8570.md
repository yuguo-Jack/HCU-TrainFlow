# [Inference][MLA] Reject DSA with dynamic-batching MLA and fix latent-cache absorption crash

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8570) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Fixes the dynamic-inference crash that MLA hits when `linear_kv_up_proj` is a plain linear (as in DSA layers, QK norm disabled, or a standalone `kv_layernorm`). DSA with dynamic batching is now rejected when the config or layer is built, so it can no longer run dense attention without a warning.

## The bug

DeepSeek sparse attention (DSA) layers from the inference spec (`MLASelfAttention` with a `DSAttention` core, e.g. `hybrid_inference_stack_spec.dsa_layer`) fail in two ways under dynamic batching:

1. **Crash.** `MLASelfAttention.prepare_for_absorption` runs on every forward with `cache_mla_latents` and always calls `split_te_layernorm_column_parallel_linear(self.linear_kv_up_proj, ...)`. That helper only accepts a fused `TELayerNormColumnParallelLinear`. DSA needs a standalone KV norm and a plain `linear_kv_up_proj` (`QKNormConfigResolver`), so the forward raises `AttributeError: 'TEColumnParallelLinear' object has no attribute 'eps'` before any attention runs. Plain MLA layers whose KV norm is not fused crash the same way: `qk_layernorm=False`, or a standalone `kv_layernorm` in the spec.
2. **Dense attention with no warning.** Even past the crash, the dynamic MLA branch of `MultiLatentAttention.forward` calls `flash_decode_and_prefill` (dense FlashAttention / FlashMLA) directly and never the core attention module. A DSA layer would therefore skip its indexer and top-k selection and attend to every key. Once a context is longer than `dsa_indexer_topk`, the result differs from what the model was trained with.

Reproduced on H100 (TE 2.20): the end-to-end dynamic DSA forward raises the `AttributeError`. With that step patched out, the DSA core and its indexer are called 0 times and `flash_decode_and_prefill` is called once.

## Root cause and fix

- **Absorption** (`multi_latent_attention.py`): `prepare_for_absorption` assumed the KV norm is always fused into `linear_kv_up_proj`. It now splits only a fused `TELayerNormColumnParallelLinear`. Otherwise it keeps the existing `kv_layernorm` (a standalone norm or an identity) and uses `linear_kv_up_proj` itself to uncompress the latent cache. The fused path is unchanged.
- **DSA in dynamic batching**: making DSA work here would need a paged per-layer cache of the indexer keys (the indexer scores past tokens from their hidden states, which decode no longer has), plus paged top-k and sparse attention kernels over the latent cache. None of these exist, so this is new-feature work, not a fix. Dynamic-batching MLA already requires `cache_mla_latents` (the forward asserts it), and `cache_mla_latents` only works with the dynamic backend. The combination is therefore rejected in two places, each with a `ValueError`:
  - `MultiLatentAttention.__init__`: when the layer's core attention is DSA (`requires_dsa_inputs`), because that is the core the cached-latent path bypasses. This also covers DSA layers whose config does not name the DSA variant, such as a `'D'` layer of a hybrid model built through the API.
  - `MLATransformerConfig.__post_init__`: for `experimental_attention_variant='dsa'`, so the usual path fails before the model is built.

  The other sparse-attention variants (`AbsorbedMLASelfAttention`, DSv4 hybrid) already refuse inference outright. The user guide's Known Limitations now lists DSA.

No hot-path change: the absorption setup runs once per layer, and the new checks run only at construction.

## Tests

- `tests/unit_tests/transformer/test_transformer_config.py`: `test_cache_mla_latents_rejects_dsa` checks the config rejection. `test_cache_mla_latents_accepts_mla` is the control. Both run on CPU.
- `tests/unit_tests/transformer/test_multi_latent_attention.py::TestMLADynamicInferenceLatentCache` (1 GPU, TE) uses a real `DynamicInferenceContext` with only the attention kernel stubbed. It covers three KV-norm placements: fused, standalone (the DSA structure) and disabled.
  - `test_cached_latents_prefill_and_decode`, prefill: the K/V handed to the kernel must match the layer's own up-projection.
  - The same test, decode step: the absorbed query must score the cached latents as the plain query scores those keys, and the absorbed V up-projection must map a cached latent to that token's value.
  - `test_dsa_core_rejects_cache_mla_latents` builds the DSA layer with cached latents and the DSA variant unset, and expects the new `__init__` rejection.
  - Two controls are kept from the repro: the DSA layer runs its core and indexer outside inference, and a dynamic-batching forward without `cache_mla_latents` fails.
- On H100 in the CI image (TE 2.20.2), for the first commit of this PR:
  - With the PR, the regression tests pass (81/81).
  - On main, 3 cases fail as expected: the prefill test's `standalone` and `disabled` cases with the `eps` AttributeError, and `test_cache_mla_latents_rejects_dsa` with "DID NOT RAISE".
  - Neighbor tests `TestParallelMLAAttention`, `TestMLAClipQK` and `TestDSAIndexer` (DSA) pass.
On H100 in the CI image (rerun at this PR's head), the regression tests pass (82/82) and 4 fail on `main`. The neighbor tests pass.
- No GPU kernel or kernel dispatch changes. `tools/check_kernel_determinism_coverage.py` flags `multi_latent_attention.py` only because the whole file is registered under the `mla_rope_dispatch` entry; the RoPE path is untouched, so this PR should carry the `determinism-exempt` label.

## Follow-up (not in this PR)

`DynamicInferenceContext` numbers `attention_layer_map` and `dsa_layer_map` both from 0, so `'*'` and `'D'` layers in one hybrid pattern would share KV-cache slots. This cannot be reached today, because DSA cannot run under dynamic batching. Fix it together with any future DSA dynamic-inference support.
