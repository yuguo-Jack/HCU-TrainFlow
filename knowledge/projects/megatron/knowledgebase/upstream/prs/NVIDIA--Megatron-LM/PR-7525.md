# Fix fused mHC scalar-grads tile size for non-power-of-two token counts

# What does this PR do?

Fixes the fused mHC cuTile backward for micro-batches whose token count M is below 128 and not a power of two: `_cutile_fused_compute_h_proj_rms_bwd` launched `_ct_scalar_grads_partials_kernel` with `tile_m_scalar = min(128, M)`, which cuTile rejects at compile time (`TypeCheckingError: Invalid argument "shape" of load(): Dimension #0 of shape (112, 32) is not a power of two`). The tile is now `min(128, _next_power_of_2(M))`; the loads already use `PAD_ZERO` and the kernel reduces over the tile, so the padded rows contribute nothing.

```text

PASSED [256-4-4096]  PASSED [64-2-512]  PASSED [128-4-2048]
FAILED [112-4-2048]   TypeCheckingError: Dimension #0 of shape (112, 32) is not a power of two

12 passed  (incl. [112-4-2048], [21-2-512])
```

Motivating failure: DeepSeek-V4 SFT with `use_fused_mhc=True`, unpacked SBHD, MBS 1 on 8 × GB200 died after 7 iterations on a 112-token micro-batch; with the fix the tile for that batch is 128 with one M block.
