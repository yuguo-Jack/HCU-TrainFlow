# What does this PR do?

Fill `FullyShardedOptimizer.sharded_state_dict` and `load_state_dict` (previously `NotImplementedError`) so a Megatron-FSDP v2 optimizer saves and loads its state as a PyTorch Distributed Checkpoint in the `fsdp_dtensor` format.

The layout mirrors `DistributedOptimizer.sharded_param_state_fsdp_dtensor`, so v1 and v2 write the same on-disk format:

```python
{"state": {fqn: {"exp_avg": DTensor, "exp_avg_sq": DTensor}},
 "param_to_group_meta": {fqn: {...group hyperparameters...}}}
```

That is also why the parameter names come from MCore's `get_global_unique_param_name` rather than from torch's `get_optimizer_state_dict`, whose names are the plain `named_parameters` ones rather than MCore's PP/EP-unique checkpoint names. The base optimizer (TE FusedAdam) tracks `step` per param group rather than per parameter, so `step` round-trips inside `param_to_group_meta`.

**Empty-local shards are the interesting part.** Megatron-FSDP v2 filters parameters whose *local* shard is empty out of the base optimizer, per rank (a TE FusedAdam workaround, [TransformerEngine#3207](https://github.com/NVIDIA/TransformerEngine/issues/3207)), so the surviving state and param groups differ across ranks. Meanwhile `preprocess_state_dict_for_uneven_dtensor` runs one `all_gather_object` *per DTensor* in sorted key order, so a rank-dependent DTensor keyspace deadlocks. `sharded_state_dict` therefore emits every trainable parameter: real state where the optimizer holds it, and empty-local `zeros_like` placeholders otherwise. A placeholder has the parameter's global shape and dtype but no local rows, so it contributes no data — the rank that owns a non-empty shard covers the tensor fully — and only keeps the keyspace identical everywhere. One `all_gather_object` over the sharded mesh dimensions distributes the per-parameter state keys so each placeholder carries exactly the owning rank's key set.

`param_to_group_meta` stays rank-local on purpose: it covers exactly the parameters this rank's optimizer owns, which is what both ends need. On save DCP unions the non-tensor entries written by all ranks, and on load each rank reads back the entries for the parameters it owns — including after a reshard, where a rank asks for parameters another rank saved.

`state_dict()` keeps raising: Megatron-FSDP always runs with `--ckpt-format fsdp_dtensor` (enforced in `validate_args`), so the plain accessor is unreachable, and forwarding the wrapped optimizer's state would only produce a checkpoint that silently drops the cross-rank resharding metadata.

Materializing the optimizer state before a load reuses `init_optimizer_state` from #6024 rather than carrying a second implementation, so that helper becomes public.

## Testing

New `tests/unit_tests/distributed/mfsdp_v2/test_optimizer_checkpoint.py` trains a source model, checkpoints the model and the optimizer the way the training loop does (`state_dict_for_save_checkpoint` + `sharded_state_dict` + the uneven-DTensor preprocessing), and loads into a zero-initialized model that has been trained a *different* number of steps, so a dropped or mis-serialized `step` — and the stale momentum that comes with it — fails the comparison instead of matching by construction. The optimizer state, the param groups (including `step`), and the model weights are all asserted bit-exact, at zero tolerance, including each DTensor's global shape, placements and device mesh rather than only this rank's local shard.

The test runs on a single rank too, where it degenerates to a single-shard sanity check. With two or more ranks it additionally asserts that some rank really had an empty-local shard, so the placeholder path is not covered vacuously.

Verified on 2× RTX 6000 Ada: passes on 2 ranks and on 1 rank, together with #6024's `test_checkpoint.py` and the neighbouring `test_mcore_adapter.py` / `test_optimizer.py` / `test_dbuffer.py` buckets.
