# [Test][Inference] Independent oracles for the dynamic context, MTP and sampling-noise kernels

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8974) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Adds oracle tests for the inference kernels of the dynamic context, MTP speculative decoding and request-seeded sampling, under `tests/unit_tests/inference/oracles/context/`. Each kernel is checked against a reference written from what the kernel must compute, not from its code. No production code changes.

**Stacked on the oracle harness PR #8966 (`test/inference-oracle-harness`)**, which adds the shared helpers in `tests/unit_tests/inference/oracles/`. Review this PR's commit only; retarget to `main` once the harness is merged.

## Why

The two high-risk kernels here had no independent check:
- `_prepare_next_forward_pass_kernel` was compared only with `mtp_utils_pytorch.prepare_next_forward_pass`, a per-program transliteration written in the same PR. That test used identity required-row indices, so a kernel writing the index instead of gathering through it passed. It used S in {2, 4} only, so no masked lane ever ran.
- `_request_seed_noise_kernel` had property tests and one coarse statistical test: 3 tokens, one position, a 6-sigma band. Nothing tested the stream a user sees across steps, or independence between the server's adjacent seeds.

## What is in it

- **`speculative_steps.py`**: builds one speculative step from a request layout: decode requests with their acceptance, then prefill chunks, the last possibly a chunked-prefill request. It produces the inputs the controller hands the MTP kernels, for eager, CUDA-graph-padded, async-scheduled and async-plus-graph forwards. `reference` gives the bookkeeping the next forward relies on, from the input and sampled tokens and the required rows alone:
  - for each decode request, the longest draft prefix that equals the model's own samples;
  - the accepted drafts and their count;
  - the token sampled after the last accepted one, and its token row.
- **`test_prepare_next_forward_pass.py`**: `_prepare_next_forward_pass_kernel`, fed by the verify kernel and, separately, by the reference's mask.
  - The test asserts the reference recovers the acceptance the builder made, so the oracle is not vacuous.
  - Factors: S in 1..9 (every lane width, masked lanes at 3, 5, 6, 7, 9); decode and prefill counts around Triton's `== 1` and `% 16` specializations, plus 512 decode requests; every acceptance pattern, including a match after a mismatch and a rejection that equals its sample mod 2^32; token ids up to 2^62; int32 and int64 required rows; contiguous and strided output rows. Pairwise, 83 cases.
  - Five steps on persistent buffers while requests finish, are evicted, pause, resume and are admitted, padded to fixed captured dimensions. Every active row must be rewritten, so a prefill row never keeps another request's drafts. Every other row must keep its value.
  - verify + prepare captured in a CUDA graph and replayed with new data.
- **`test_request_seed_noise.py`**: `_request_seed_noise_kernel`.
  - **Bit level**: a numpy Philox4x32-10, checked against the Random123 known-answer vectors, with Triton's documented uniform map. The noise is compared with `-ln u` in fp64, bounded by torch's fp32 `log` on the same device.
  - **Seeded determinism, bit for bit**: a request's noise does not depend on its row, the batch, the launch path, the vocabulary size or earlier launches. Unseeded rows and the shared generators are untouched.
  - **Statistics**, with the harness's chi-square and exact binomial bounds:
    - the marginal is Exp(1);
    - the sampler's race draws an 8-token distribution across 2^17 requests and across 2^17 steps of one request;
    - the joint draw of adjacent seeds (the server's `n > 1` seeds), seeds 2^32 apart, consecutive positions, positions 2^32 apart and adjacent vocabulary entries is the product of the marginals.
  - Vocabulary sizes around the 1024-entry tile and production vocabularies.
  - Scalar seeds and positions in every Triton integer type.
  - Searched coordinates where the uniform is 0 (the `FLT_MIN` clamp) or its maximum.
- Three neighbours that share the MTP and padding structure:
  - **`test_verify_speculative_tokens.py`**: `_verify_speculative_tokens_kernel` (mask, last indices), with the same builder.
  - **`test_mamba_state_selective_copy.py`**: `_mamba_state_selective_copy_kernel`. Multi-chunk production conv and SSM states, which no earlier test ran; bit patterns in fp32, bf16 and fp16; strided slots; a chained verify -> prepare -> copy step.
  - **`test_zero_padding_rows.py`**: `_zero_padding_rows_kernel`. Rows over several column tiles (every production hidden size), SP shards, the non-contiguous fallback, and CUDA-graph replay with the real token count changing on every replay.
- Every module: guard bands and poison on outputs, read-only input checks, a `sanitizer` case, and `large` cases with offsets past 2^31 where the kernel has them.

Tolerance: exact for every integer and copy output. The noise is the only floating-point output: its uniforms are exact, and its log is bounded by torch's. The statistical assertions have a false-failure rate of 1e-6 each, on fixed inputs.

## Tests

509 tests: 1 CPU test (Philox known answers) and 508 H100 tests (`requires_sm(HOPPER)`), 6 of them `large` (opt-in).

- **Not run on a GPU yet.**
- **On CPU** (Triton 3.8 interpreter): every non-`large`, non-graph test passes (499). The seed-noise run used smaller statistical samples and a correctly rounded interpreter `log`. The interpreter maps `tl.log` to numpy's fp32 log, about 3 ulp off; on the GPU the kernel calls libdevice `__nv_logf` (checked in its sm_90 PTX).
- **Mutation self-check** on CPU:
  - prepare: 13 mutants, all killed. They include writing the index instead of the gathered row, prefill rows 0 or unwritten, an ignored output stride, int32 tokens, and an off-by-one lane mask.
  - seed noise: 11 mutants, all killed. They include dropping the seed's or the position's high word, swapping counter words, the wrong Philox word, 7 rounds, a missing clamp, and a store mask one past V.
- **On main**: every test should pass. No open PR changes these kernels:
  - #8565 drops the controller's per-step buffer reset; the across-steps test checks the kernel behaviour it relies on.
  - #8710, #8876, #8872 and #8642 touch the MTP context, the controller or the dynamic context, not these kernels or their buffers.

## Notes for reviewers

- The Philox key and counter layout is the one part of the seed-noise oracle taken from the kernel. Pinning it keeps seeded generations reproducible across releases. The statistical and determinism tests check the contract without it.
- `_prepare_next_forward_pass_kernel` takes its counts as host ints, so a captured prepare cannot change them across replays. The graph test replays with new data. Changing counts are covered by the padded steps, whose actual counts change under fixed captured dimensions.
- Not covered here: the SSM prefill split/merge/masked-update kernels and the KV append. They share no structure with these kernels.
