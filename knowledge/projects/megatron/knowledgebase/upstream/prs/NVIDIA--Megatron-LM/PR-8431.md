# What does this PR do?

Add opt-in `--log-dcp-stats` to report estimated attention-work balance and logical-sample CP-size fractions for the **final packed schedule, after VPP alignment**.

The flag defaults to off, with no statistics computed when disabled. It uses the existing log interval and stdout/TensorBoard/W&B writers. Packing and scheduling decisions are unchanged.

## Metrics

For microbatch `m`, `L_i` is sample `i`'s **padded** sequence length, `c[m,i]` is the number of ranks containing its ID, and `R` is the DP×CP rank count, excluding TP/PP replicas:

```text
W[m,r] = sum(L_i² / c[m,i] for each sample i assigned to rank r)
balance = sum_m sum_r W[m,r] / (R × sum_m max_r W[m,r])
```

- `dcp/estimated_attention_balance_efficiency`: closer to 1 means more balanced estimated work. `[8,8,4,4]` gives 0.75. Per-microbatch maxima preserve alternating rank hotspots.
- `dcp/cp_size_<c>_sample_fraction`: each logical ID counts once per microbatch, regardless of CP replication. Equal-length samples with different IDs remain distinct.

Windows accumulate numerators, denominators and counts before division. Empty/zero-work windows omit undefined balance. Packed samples contribute individual squared lengths.

This is a scheduler attention-work estimate, excluding communication, MLP work, pipeline bubbles and some later THD padding. It does not measure GPU utilization.

## Implementation

- A pure CPU helper retains the complete microbatch-by-rank work matrix. The optional `schedule_stats` output preserves the scheduler's four-element return interface.
- TP rank 0 computes statistics after alignment; float64 summaries reuse the existing TP scalar metadata broadcast. No DP/CP collectives are added.
- Pending statistics commit once after a successful update. Reruns reuse the summary; skipped/aborted steps and evaluation do not contribute. TP/PP replicas are not accumulated together.

The [data-loading guide](https://github.com/WEIXILIN0307/Megatron-LM/blob/915ffdb5a4d89a3b3f9491ee4d93038cf0985ba2/docs/user-guide/data-loading.md#observing-packed-schedules-and-dynamic-context-parallelism) includes formulas, example logs, limitations and reproduction commands.

All four ranks receive the same global summary, without multiplying counts by rank count. Per-microbatch work conservation, window reset and evaluation exclusion pass. TensorBoard emits exactly once at iterations 3/6/9. The existing first-resumed-iteration stdout report at iteration 2 leaves the window intact; the final partial window at iteration 10 is not emitted. W&B routing has mock-based unit coverage; its external service was not exercised.

The actual `run_train_loop_without_updates` path also passed three iterations on two GPUs with metrics enabled and `--no-load-optim`: the data hook ran each iteration, train_step/statistics never ran, parameters were unchanged, and stdout/TensorBoard had no DCP metrics.

DCP V2 rejects `--deterministic-mode`, so these revalidations omit it while retaining seed 1234, `NVTE_ALLOW_NONDETERMINISTIC_ALGO=0` and `CUBLAS_WORKSPACE_CONFIG=:4096:8`. Observed bitwise equality is not a general determinism guarantee.

### Current-source performance and observation cost

Two A6000 GPUs, TP1/PP1/DP1/CP2, same checkpoint/data/seed and **2,560 effective tokens per update**. Three rotated repetitions per arm, each with 100 updates and the first ten excluded. Timing uses the existing interval timer with stdout/TensorBoard enabled at log interval 1, W&B off, fixed process CPU affinity, no tensor hashing or CPU profiling. Raw GPU telemetry is retained; this is a shared host without locked GPU clocks.

| Arm | Mean step ± between-run std (ms) | Mean effective tokens/s |
|---|---:|---:|
| Fixed CP2 | 142.42 ± 0.40 | 17,975 |
| DCP, metrics off | 117.61 ± 5.39 | 21,796 |
| DCP, metrics on | 116.66 ± 2.25 | 21,949 |

On/off mean step-time difference: **−0.81%**; paired differences **+1.20%, −3.79%, +0.39%**. The variation prevents resolving small overhead. These results do not establish zero overhead or a speedup from enabling metrics. Fixed CP versus DCP compares the existing schedulers on this small workload; this PR does not change their decisions.

Separate CPU diagnostics exclude ten warmups from 40 updates per arm: statistics **40.14–41.43 µs/step**, accumulator update **12.62–13.30 µs/step**. Disabled diagnostic runs make neither call. Emitting-rank logging averages 1.619 ms off / 1.535 ms on, including existing logging/synchronization and host variation. These diagnostic runs are excluded from primary timing aggregates.
