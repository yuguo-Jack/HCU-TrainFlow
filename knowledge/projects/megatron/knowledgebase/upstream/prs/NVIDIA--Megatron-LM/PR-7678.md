# Add general cross-layer tensor state for checkpointing, CUDA graphs, CP and PP

## Original PR description

# What does this PR do?

Adds general cross-layer tensor state: a producer publishes named tensors that later layers consume, with gradients preserved across checkpointing, CUDA graphs, CP/SP redistribution and the existing ordinary/interleaved 1F1B schedules. It contains no model-specific attention, compression or routing rules. The schema and typed transport are adapted from #7224 by Hongxiao Bai (@hxbai).

- **Schema** — `TensorField`/`TensorSchema` declare key, shape, dtype, CP layout (`contiguous`, `zigzag`, `replicated`, `local`, `strided`), gradient eligibility and presence. Absent fields and empty tensors keep distinct meanings.
- **Recompute and graphs** — `StatefulModule.run(..., recompute=True)` checkpoints explicit state, preserving Megatron's model-parallel RNG; quantized regions pass an FP8-aware `checkpoint_fn` (e.g. `te_checkpoint`), and the default checkpoint is rejected under FP8 autocast. `StatefulGraphs` captures independent slots (Torch or TE backend) for outstanding microbatches, preserves `main_grad`/DDP state and registered buffers through capture, supports MCore DDP parameter-gather pre-hooks, and checks input profiles and every captured module's training mode on replay.
- **Context parallelism** — `redistribute_state` and `gather_state` take explicit TP/SP/CP groups. Gathers use one all-gather plus a reorder without host synchronization, so they also run inside graph capture; backward reduce-scatters, with `tp_replicated=True` for TP-replicated consumers.
- **Pipeline parallelism** — a stage opts in with `pipeline_payload_factory = TensorStatePayload`. Every boundary message is described ahead of time by a per-microbatch `PipelinePayloadSpec` (shapes may vary between microbatches, e.g. packed sequences), so blocking, batched and VPP-overlapped P2P post all receives without shape discovery and peers exchange only tensor data. Gradient eligibility is static per microbatch: a differentiable field must receive a gradient (an unused branch is declared non-differentiable in that microbatch's plan rather than silently zero-filled). All differentiable outputs of a stage share one autograd traversal and are released after the send is posted.

## Changes in this revision

Follow-up to a strict review, with a goal of a smaller, more general prerequisite:

- Removed the dynamic JSON header protocol, the mandatory Gloo control group (`create_pipeline_control_group` / the model's `pipeline_control_group`) and the runtime gradient-activity bitmap. PP=2 uses WORLD for one physical direction, like the tensor-only communicator.
- Merged `PipelineTensorSpec` into `TensorField` and the `PipelinePayload` base into `TensorStatePayload` (`eq=False`, no frozen-dataclass mutation); every differentiable root, not only hidden, is now owned and released after send.
- Fixed: zigzag `gather_state` host sync (not capture-safe), silent graph replay after `model.eval()`, unguarded FP8 recompute, and TP-replicated gradient overcounting under SP.
- Moved the generic `StatefulGraphs` fixes from #7224 here (input-gradient copies, buffer restore, singleton-stride signatures, DDP parameter-gather hooks).
- Production code added vs. main: 2,031 → 1,475 lines (`typed_p2p_communication.py` 820 → 391, `pipeline_payload.py` 405 → 231); tests 2,361 → 1,948 lines.

## Integration boundary

This PR owns the model-independent contract, replay boundaries, typed transport and their tests. #8226 consumes these APIs for V4.1; CSA2, single-pass mHC, Engram and model-specific state codecs remain in #8223–#8226.

The API changes require a small downstream update (+17/−33 lines): #8226 (`deepseek_v41/model.py`, `deepseek_v41/state.py`, `test_v41_state_integration.py`) drops the control group, reads `payload.spec.boundary_id`/`.metadata`, and builds specs from `TensorField`s; #8227 (`training/models/deepseek_v41.py`) no longer creates the control group. #7224's `stateful_module.py` additions are now part of this PR.

## Limitations and deferred work

- Consumers wire the APIs explicitly; integration into `TransformerBlock` / layer specs is not part of this PR.
- Graph slots use separate memory pools; FP4 capture, dynamic parameter-storage replacement (including FSDP) and full recomputation inside capture are unsupported. Every differentiable captured output must participate in one backward.
- Packed CP layout conversion remains model-owned; the CP helpers' `thd_plans` argument is preliminary.
- Plans are compared once per schedule invocation (one small all-gather over the PP group).
- Warmup/flush P2P prefetch, the combined MoE schedule, ring exchange, multi-module pipelines and custom P2P communicator subclasses are rejected for typed stages.
