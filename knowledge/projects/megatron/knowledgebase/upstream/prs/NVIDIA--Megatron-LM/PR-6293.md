# Remove global process-group reads from Megatron Core

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/6293) · state: open · merged: False

## Original PR description

[Scoped diff of this PR's own changes](https://github.com/Connor-XY/Megatron-LM/compare/dcccf3e468c548f1a75fa45be706f90b3bb066aa...86a03c02ed92ba23fc43af2f9c3ff7d831461dfa). The full diff also shows #7487's commits until it merges.

**Depends on #7487** (its two commits come first here). Please review from "Use already-plumbed process groups instead of global accessors" onward; this PR rebases cleanly once #7487 merges.

**Why.** Attention, transformer, model and inference code in `megatron/core` reads the global parallel grid whenever a caller omits process groups. For a model on its own grid (vision encoder + LLM, MIMO, GTP), those reads silently select another model's groups (#6307).

**What.**
- In-repo callers now pass their collection or group explicitly to `SelfAttention`/`CrossAttention`, `DotProductAttention`, the MLA attention classes, `DSAIndexer`, `TEGroupedLinear`, `MultiTokenPredictionBlock`, `LLaVAModel`, `T5Model`, the rotary embeddings (`cp_group`), the multimodal context-parallel helpers (`cp_group`), `mtp_on_this_rank` (`pp_group`, now also from `pretrain_gpt.py`, `pretrain_hybrid.py` and `pretrain_hybrid_flex.py`) and the hybrid-CP scheduler (`pg_collection`; it balances samples over `dp_cp_gtp_remat` when the collection carries it, the GTP-remat-inclusive group the default data loader uses).
- Groups already in scope are threaded through instead of re-read globally: heterogeneous linear replacements (the layer's `pg_collection` and its `tp_group`), the attention consistency check (`dp`), MTP recompute (`tp`).
- Inference resolves its groups once in `InferenceConfig.resolve_pg_collection()`, and the TRT-LLM export converter once in its constructor; these are the two remaining compatibility boundaries.
- A collection that is passed but lacks a needed group raises `ValueError`.

**Deprecations.** Omitting the collection or group from any of the classes and functions listed above, or from `TEDotProductAttention` and `DSAttention`, still works during the deprecation period: the previous global-grid lookup is used, including the hierarchical CP groups for `cp_comm_type="a2a+p2p"`. A `FutureWarning`, once per class or function, says the fallback is deprecated since Megatron Core 0.20 and will be removed in 0.22 (N+2, per `docs/api-backwards-compatibility-check.md`). It is attributed to the first caller outside Megatron Core and torch, so it shows under Python's default filters and points at the code to change. This covers the rotary embeddings too, where an omitted `cp_group` keeps meaning "the global context-parallel group". The context-parallel helpers keep their previous positional order, with `cp_group` as a trailing optional argument. No behavior changes until the fallbacks are removed.

**Tests.** New `tests/unit_tests/test_process_group_fallback.py` covers the warning (once per owner, its attribution and the removal release) and, with groups of size 2, the global fallback for the rotary embeddings, `DotProductAttention`, `SelfAttention` (including hierarchical CP and `test_mode`), `mtp_on_this_rank` and the context-parallel split and gather, plus `TEDotProductAttention` requiring `hcp` only for hierarchical CP; T5 covers both the explicit and the deprecated paths; LLaVA covers the static, dynamic and temporal vision-CP paths on a separate CP communicator with every global CP accessor forbidden. Constructor and plumbing changes only: no performance impact, no checkpoint format change; the `dot_product_attention.py` change only touches group resolution, hence `determinism-exempt`.

**Review follow-up.** The fixes for the first review are in the last five commits, from "Pass the caller's process groups in the T5 example and to mtp_on_this_rank" onward.

**Rebased onto main `a07014bbd`** (2026-10-08). One upstream change conflicted: #7591's RNGConfig migration rewrote the `global_vars` import in `examples/t5/pretrain_t5.py`. Its `get_run_config` import is kept, inside this PR's sorted import block. Apart from that hunk's context, the patches, the allowlist and the read inventory (210 → 183) are unchanged. On the new head, 4 GPUs: the fallback, LLaVA training/model, multimodal-CP, hybrid-CP scheduler, T5, heterogeneous-GPT, attention, custom-process-group block, DSA, runtime-CP attention and the new fused-MLA pre-MLP-norm tests give 397 passed / 21 skipped / 12 failed. All 12 also fail on main because they need 8 ranks, and all 12 pass on 8 GPUs (2×4). An entry-point smoke test passes on the new head: the T5 provider keeps a caller-supplied collection that carries `mp`/`pp`/`dp_cp` (main fails this check), and a small T5 command line takes the dataset seed from the run config (`cfg.rng.seed`).

**Merged main `c4129afff`** (2026-10-09). This is a merge rather than a rebase, so the commits referenced in the review replies stay valid. The only conflict was an import in `tests/unit_tests/transformer/test_multi_latent_attention.py`; both imports are kept. Three follow-up commits:
- The `tests/unit_tests/data` bucket failed in `test_sequence_packing_batch_uses_context_parallel_batch_interface`. That test mocks `get_batch`'s dependencies without initializing model parallelism, but `get_batch` now evaluates `mpu.get_pipeline_model_parallel_group()` to pass it to `mtp_on_this_rank`. The test now patches the accessor and checks that `get_batch` forwards the group.
- The TRT-LLM distributed converter raises when the tensor- or pipeline-parallel group is missing. Before, an uninitialized grid silently exported a TP1/PP1 mapping, because `get_pg_size(None)` is 1.
- `TestMLAUpProjectionInput`, added on main, passes its collection explicitly.

**How to review.** Core: 23 files (+354/−175); tests (+767/−79) and examples are mechanical caller updates. Read `process_groups_config.py` (the deprecation helper), then `transformer/attention.py`, `dot_product_attention.py`, `multi_latent_attention.py`, `multi_token_prediction.py`, `models/common/embeddings/rotary_pos_embedding.py`; then plumbing (`models/multimodal/context_parallel.py`, `llava_model.py`, `heterogeneous/linear_replacements.py`, `pipeline_parallel/hybrid_cp_schedule.py`, `inference/config.py`); tests last.

**Counts.** Global process-group reads in `megatron/core`: 210 → 183. 27 reads are removed outright; the remaining fallback reads are the deprecated paths above (same functions as on main) and go away when the deprecation ends. The commit "Refresh the process-group read allowlist for this series" (just before the review follow-up) refreshes #6258's allowlist (210 → 183): 30 stale entries are dropped, and the two boundaries plus the hybrid-CP fallback are added as reviewed entries, each replacing reads already allowlisted in the same function.

Landing order: #7487 → #6293 → #6303. Part of #6307.
