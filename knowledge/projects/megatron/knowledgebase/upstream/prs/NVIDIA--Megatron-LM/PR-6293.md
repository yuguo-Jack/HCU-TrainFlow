# Remove global process-group reads from Megatron Core

[Scoped diff of this PR's own changes](https://github.com/Connor-XY/Megatron-LM/compare/670445fa5e..yx/pstate-p34-rebased) against #7487's current head, which includes the same main. Against main as of the last merge below, this PR's diff is 57 files, +1444/−261, and includes #7487 (2 files, +194/−3). The full diff also shows #7487's commits until it merges.

**Depends on #7487** (its first two commits come first here; its later missing-`embd` warning commit is merged in at the tip). Please review from "Use already-plumbed process groups instead of global accessors" onward; this PR rebases cleanly once #7487 merges.

**Why.** Attention, transformer, model and inference code in `megatron/core` reads the global parallel grid whenever a caller omits process groups. For a model on its own grid (vision encoder + LLM, MIMO, GTP), those reads silently select another model's groups (#6307).

**What.**
- In-repo callers now pass their collection or group explicitly to `SelfAttention`/`CrossAttention`, `DotProductAttention`, the MLA attention classes, `DSAIndexer`, `TEGroupedLinear`, `MultiTokenPredictionBlock`, `LLaVAModel`, `T5Model`, the rotary embeddings (`cp_group`), the multimodal context-parallel helpers (`cp_group`) and `mtp_on_this_rank` (`pp_group`, now also from `pretrain_gpt.py`, `pretrain_hybrid.py` and `megatron/elastification/pretrain_hybrid_flex.py`). This PR also passes `pp_group` to `mtp_on_this_rank` from `is_dataset_built_on_rank_explicit`, main's shared dataset predicate in `megatron/training/datasets/providers.py`, so middle pipeline stages do not hit the fallback warning.
- Groups already in scope are threaded through instead of re-read globally: heterogeneous linear replacements (the layer's `pg_collection` and its `tp_group`), the attention consistency check (`dp`), MTP recompute (`tp`).
- Inference resolves its groups once in `InferenceConfig.resolve_pg_collection()`, and the TRT-LLM export converter once in its constructor; these are the two remaining compatibility boundaries.
- A collection that is passed but lacks a needed group raises `ValueError`.

**Deprecations.** Omitting the collection or group from any of the classes and functions listed above, or from `TEDotProductAttention` and `DSAttention`, still works during the deprecation period: the previous global-grid lookup is used, including the hierarchical CP groups for `cp_comm_type="a2a+p2p"`. A `FutureWarning`, once per class or function, says the fallback is deprecated since Megatron Core 0.21, the first release that emits it, and will be removed in 0.23 (N+2, per `docs/api-backwards-compatibility-check.md`). It is attributed to the first caller outside Megatron Core and torch, so it shows under Python's default filters and points at the code to change. This covers the rotary embeddings too, where an omitted `cp_group` keeps meaning "the global context-parallel group". The context-parallel helpers keep their previous positional order, with `cp_group` as a trailing optional argument.

**Behavior changes.** Besides the warnings above, callers can notice these changes:
- A collection that is passed but lacks a needed group raises `ValueError` in `Attention`, `DotProductAttention`, `MultiTokenPredictionBlock` and `T5Model`. Before, `MultiTokenPredictionBlock` raised `AssertionError` for a missing `tp`, `cp` or `pp`. The `hasattr` asserts in `Attention`, `DotProductAttention` and the MTP HSM `dp` check never fired, because `ProcessGroupCollection` returns `None` for any declared field that was not set. `SelfAttention`'s test-mode consistency check now takes its rank and group from `pg_collection.dp` and raises `ValueError` without it; before, it read the global data-parallel group.
- `TEDotProductAttention` with `cp_comm_type="a2a+p2p"` takes the hierarchical CP groups from `pg_collection.hcp`. Before, it always read the global hierarchical groups, even when a collection was passed. A passed collection without `hcp`, or with `hcp=None`, now raises `ValueError`.
- The TRT-LLM distributed converter raises `RuntimeError` when the tensor- or pipeline-parallel group is missing. Before, `parallel_state` raised `AssertionError`. Sizes and ranks now come from the groups, so the `parallel_state` world-size and rank overrides no longer apply to the converter.
- From #7487: `T5Model` given a collection without an `embd` field emits a `FutureWarning`, treats it as `embd=None`, and says a missing `embd` becomes an error in Megatron Core 0.23. Tied pipeline embedding and output stages raise `ValueError` when `embd` is missing, `None` or `NON_GROUP_MEMBER`, since they would otherwise skip the weight sync.

**Tests.** New `tests/unit_tests/test_process_group_fallback.py` covers the warning (once per owner, its attribution and the removal release) and, with groups of size 2, the global fallback for the rotary embeddings, `DotProductAttention`, `SelfAttention` (including hierarchical CP and `test_mode`), `mtp_on_this_rank` and the context-parallel split and gather, plus `TEDotProductAttention` requiring `hcp` only for hierarchical CP. It also runs the fallbacks of `TEDotProductAttention` at TP=2/CP=2, `MultiTokenPredictionBlock` at CP=2 and the dynamic-resolution CP split and gather at CP=2. T5 covers both the explicit and the deprecated paths and the missing-`embd` warning; LLaVA covers the static, dynamic and temporal vision-CP paths on a separate CP communicator with every global CP accessor forbidden. The mHC inference-wrapper test's fake config gains `resolve_pg_collection()`, which the wrapper now calls. Constructor and plumbing changes only: no performance impact, no checkpoint format change; the `dot_product_attention.py` change only touches group resolution, hence `determinism-exempt`.
