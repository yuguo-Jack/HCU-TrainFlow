# refactor(transformer): deduplicate FP8/FP4-aware activation checkpointing

# What does this PR do?

Moves the FP8/FP4-aware activation-checkpoint dispatch, which six recompute call sites each re-implemented, into one helper: `precision_aware_checkpoint` in `megatron/core/transformer/utils.py`. No behavior change.

Every recompute site picked `te_checkpoint` under FP8/FP4 (FP4 is implemented with TE's `fp8_autocast`, so it needs TE's checkpoint too) and `tensor_parallel.checkpoint` otherwise, and spelled out both calls because the two functions take different arguments. The helper takes the function, the config, the tensor-parallel group, the function's arguments, and `distribute_saved_activations`. On the `tensor_parallel.checkpoint` path it binds keyword arguments with `functools.partial`, as the call sites did.

Call sites switched to the helper:

- `MoELayer.shared_experts_compute` (shared-expert recompute), `moe_layer.py`
- `MoELayer.forward` (MoE layer recompute), `moe_layer.py`
- `TransformerLayer._run_mlp` (MLP recompute), `transformer_layer.py`
- `MoETransformerLayer._forward_mlp` (MoE layer recompute on the partial CUDA graph path), `transformer_layer.py`
- `checkpointed_forward` (full-layer recompute for `TransformerBlock` and `HybridStack`), `recompute.py`
- `MultiTokenPredictionLayer._checkpointed_forward` (MTP recompute), `multi_token_prediction.py`

Each site passes the same function, arguments, tensor-parallel group, and `distribute_saved_activations` value as before. The MTP site still passes `parallel_state.get_tensor_model_parallel_group()`; switching it to a `pg_collection` group is left for a separate change. Imports that only served the removed branches are dropped.

## Testing

- New CPU-only unit tests in `tests/unit_tests/transformer/test_utils.py` cover the FP8, FP4, and default paths, including positional and keyword argument forwarding. They pass locally on CPU (macOS, with unrelated Triton-importing modules stubbed out because Triton has no macOS wheels).
- `tools/autoformat.sh` passes in check mode.
- The refactored GPU paths are exercised by existing unit tests, for example the MoE layer recompute tests in `tests/unit_tests/transformer/moe/test_moe_layer.py` (FP8 and BF16). These were not run locally (no GPU).
- `tools/check_kernel_determinism_coverage.py` flags `moe_layer.py` and `transformer/utils.py` because they are registered kernel files. This change cannot affect numerics, so the PR carries the `determinism-exempt` label.
