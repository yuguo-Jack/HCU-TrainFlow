# What does this PR do?
The NanoV3 GB200 EP4 benchmark completes successfully but repeatedly exceeds the +20% throughput improvement ceiling at batch 128. Refresh its stale performance reference from the complete median-throughput row of three fresh GB200 sweeps and restore the recipe's original `mr` scope, which was quarantined in #7916.

Batch-128 throughput changes from **11,512.760738** to **14,234.332897 tokens/sec**. Update its throughput, average/p50/p99 latency, and TPOT together using the original full-precision result. Retain the existing 10% regression tolerance, 20% throughput improvement ceiling, other batch references, and benchmark metadata. Restoring `scope: [mr]` returns the pre-quarantine GitLab selection.

### Validation

Three independent server launches on two GB200 nodes reproduced the same isolated high-side failure against the original reference. Each sweep ran batch sizes 1, 8, 32, and 128 with five warmups and ten timed iterations per batch.

| Sweep | Batch-128 throughput (tok/s) | Change vs old baseline | Average latency (ms) | p99 latency (ms) |
| --- | ---: | ---: | ---: | ---: |
| 1 | 14,218.683365 | +23.50% | 1,137.180562 | 1,209.695876 |
| 2 | 14,248.113662 | +23.76% | 1,134.807123 | 1,193.082603 |
| 3 — selected median throughput | 14,234.332897 | +23.64% | 1,136.289481 | 1,236.761791 |

The selected baseline is the complete batch-128 row from sweep 3, not a mixture of independently selected metric values. The sample throughput coefficient of variation is 0.103%.

Runtime provenance: source `d7157825675a65c2503a061ffd1fffa7886df9b7`; CI image tag `main_73361945` (PyTorch 26.09); ARM64 manifest `sha256:5f37d7e0464e5abab9ec8b22f808d11a81bb23a859f9dfd99a1e4e2d49b98f71`. The runs used four GB200 GPUs, TP=1/PP=1/EP=4, FlashAttention 2, legacy scheduling, NVLS dispatch, GSM8K prompts, and 128 output tokens. W&B upload was disabled. Runtime arguments confirm the same checkpoint and principal model configuration as the historical run.

- The original reference fails exactly one of 20 comparisons in each fresh sweep: batch-128 throughput.
- Replaying the official comparator with the refreshed reference passes **all 60 metric comparisons** across the three fresh sweeps.
- Four archived runs with isolated high-throughput failures also pass after refresh. The two archived runs with p99 latency outliers continue to fail.
- Verified finite measurements, matching batch-128 metadata, exact provenance of the adopted full-precision row, and preserved values in other batch rows.
- JSON/YAML validation and `git diff --check` pass. Ran `BASE_REF=main CHECK_ONLY=true SKIP_DOCS=false bash tools/autoformat.sh`; it found no changed Python files to format.

This is direct GPU benchmark execution followed by comparator replay. Full CI on the PR head is pending. The separate historical p99 outliers remain unresolved, and three sweeps do not establish a fleet-wide flake rate. The source/dependency change responsible for the underlying speedup has not been bisected.
