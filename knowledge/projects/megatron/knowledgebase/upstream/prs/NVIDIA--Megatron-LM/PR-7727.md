# Support multi-axis all-gathers in QuantizedDBuffer

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7727) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

## What does this PR do?

Allow `QuantizedDBuffer.allgather` to accept multiple mesh axes and forward them to every data/scale plane. Materialize an axis iterator once so all four planes receive the same axes. Existing output-buffer reuse is preserved.

Use separate 1D and 2D plane-gather tests, each gathering into output that shares storage with the source. Both tests check every byte in all four planes without invoking MXFP8 arithmetic.

The DBuffer support from #7633 is now merged in `main`. This PR contains only the quantized wrapper and its tests; it is independent of the MCore adapter change (#7728).

## Validation

- Rebased onto `1b3e04143` after #7633 merged. `git range-diff` confirms all feature patches are unchanged; syntax and whitespace checks passed. GPU tests were not rerun for this rebase.
- The 1D and 2D tests passed on two local GPUs after removing the mesh/output parameterization. Their exact functions were extracted to bypass the module-level GB200 gate; no MXFP8 kernels were exercised.
- Before the test split, all four byte-plane communication cases passed on eight H100s without #7662 (EOS jobs 6125814 and 6129095). The test function was extracted unchanged to bypass the module-level GB200/MXFP8 gate; this validates communication of all four planes, not MXFP8 kernels.
- Black, isort, Ruff, and `git diff --check` passed. Repository checks retain the existing Pylint configuration error and missing Transformer Engine module/stub diagnostics.

File: `tests/unit_tests/distributed/mfsdp_v2/test_quantized_dbuffer.py` · line None

The `is_mxfp8_available()` gate at top of the file makes H100 skip the whole file. So these tests only run on GB200 where 4 GPUs give a square (2, 2) mesh. which can't catch a bug that mixes up the two axis sizes, H100's 8 GPUs would give a (2, 4) mesh. Only two tests actually do MXFP8 arithmetic, `test_quantized_dbuffer_quantization_matches_te` and `test_quantized_dbuffer_get_tensor_supports_gemm`. The other four (redistribute, view, and both all-gathers) only move raw bytes and run on my local Ada GPUs. Suggested change is to move the gate to test level:
```python
requires_mxfp8 = pytest.mark.skipif(
    not is_mxfp8_available(), reason="MXFP8 quantization is not available."
)

@requires_mxfp8
def test_quantized_dbuffer_quantization_matches_te(...): ...

@requires_mxfp8
def test_quantized_dbuffer_get_tensor_supports_gemm(...): ...
```
