# Fix MLA request-arrival consistency in batch-invariant inference

## Original PR description

# What does this PR do?

With batch-invariant inference and MLA latent caching enabled, a new request entering prefill can change the generated log-probabilities of requests already decoding. Decode-only batches use absorbed MLA, while mixed batches use unabsorbed attention; switching between them changes floating-point evaluation order.

Use unabsorbed attention for both paths when `batch_invariant_mode=True`, as required by the [batch-invariant inference guarantee](https://github.com/NVIDIA/Megatron-LM/blob/ce852bfb93f364f64a556602fc71a5d9ed2c377e/docs/mcore-inference-user-guide.md#L133). Ordinary inference keeps its absorbed decode path. With pretrained Moonlight-16B-A3B, solo and mixed runs now produce identical tokens and log-probabilities in both tested arrival orders.

In the BF16 TP1 test with a 2 GiB latent cache and 64 generated tokens, median elapsed time increased 6.8%–7.6%.

## Issue tracking

Related: #4919 and #4920 discuss the numerical difference and a broader FlashInfer rewrite. This change keeps the existing attention implementation and makes the fallback specific to batch-invariant mode.

## Validation

The regression starts three requests and adds a fourth at step 2 through `DynamicInferenceEngine.add_request()`. It compares each request with its solo result, then reverses the arrival order. It needs no downloaded weights and takes about 10 seconds.

### Pretrained model

The [reproduction archive](https://github.com/Sunt-ing/Megatron-LM/raw/06ee2bba41a6d7122c51c07369eaa85f18132293/external-reproduction.zip) contains the runnable model script, setup/run instructions, raw JSON results and logs. These are supplemental evidence; the repository regression above does not require the model or Megatron Bridge.

The model is `moonshotai/Moonlight-16B-A3B` at `476b36a473d4467f94469414bef6cee75c9c8172`, loaded in BF16 without quantization. Settings: TP1, PP1, no sequence parallelism, TE native batch-invariant kernels, FA4, latent caching, eager execution, greedy sampling, four fixed prompts and a 2 GiB KV cache. The script checks loaded checkpoint tensors and records the actual tokens and log-probabilities.

Measured software: Python 3.12.3, PyTorch `2.11.0a0+eb65b36914.nv26.02`, CUDA 13.1, TE 2.18.0, FA4 4.0.0b35, Transformers 5.19.0; exact Bridge and FlashMLA source revisions are in the reproduction instructions.

In the 64-token comparison, each baseline arrival order had 189 differing generated log-probabilities; the largest absolute difference was `0.028387248516082764`. Generated tokens and prompt log-probabilities were unchanged. All six patched arrival runs matched their solo references exactly.

A final 8-token causal check used candidate `9367dd0f7d58ca27860df4c38b39028fbec04b2b` on the stated base, then restored only the two production attention files. The candidate matched in 6/6 cases; restoring the original implementation made all six cases differ again, with 126 differing generated log-probabilities in total and maximum difference `0.0060443878173828125`, matching the original baseline failure.

Timing includes request submission and generation, with CUDA synchronization around each run, after four solo runs. Each arrival order was repeated three times. Baseline/candidate elapsed seconds were:

| Arrival order | Baseline | Patched |
| --- | --- | --- |
| 1, 2, 3, then 4 | 9.1741, 9.1353, 9.1357 | 9.9701, 9.8345, 9.8017 |
| 4, 3, 2, then 1 | 9.2128, 9.1438, 9.1329 | 9.8609, 9.7657, 9.7165 |

Maximum full-run allocation was 37,148,235,264 bytes for both implementations; decode-only temporary memory was not measured separately. Expanding the latent cache costs more as cache capacity and model dimensions grow. These measurements used baseline `b607c1b7f564f47dbb9f1b962e9c91f40abd8c59`; the subsequent base commit changes training initialization, with the relevant attention and dynamic-context files unchanged.

### Other checks

- A small-model local CUDA graph control passed the same arrival comparison with 112 graph replays.
- With batch-invariant mode disabled, baseline and patched tokens/log-probabilities matched. That control used prompt lengths 257, 513, 1025 and 2049; the shorter 31-token shape hit the baseline FA4 SM90 `SplitKV not supported` assertion.
- The final repository regression passed on the stated base. The native autoformatter and kernel determinism coverage gate passed. The native nonblocking mypy step reports the same 40 existing errors as baseline, with no added errors.

The measurements cover BF16 TP1 on H200 at the stated cache size. Pretrained whole-model CUDA graphs, other topologies and training/inference parity were not tested. Production trigger frequency is unknown.
