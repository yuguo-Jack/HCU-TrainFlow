# Compare HybridEP virtual experts on logical MoE workloads

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8388) · state: open · merged: False

## Original PR description

This adds a finite comparison of the existing HybridEP MoELayer path and the virtual-expert path merged in #7450. Both use TE grouped experts, identical logical parameters, source inputs and the W workload routes from #7488. RouterReplay preserves the real differentiable router scores, and the adapter checks the routes actually executed.

Depends on #7488. The [incremental adapter diff](https://github.com/0z5a/Megatron-LM/compare/benchmark/moe-token-imbalance...hybridep-workload-adapter) isolates this follow-up. The upstream `pull-request/7488` mirror is not available, so this Draft currently targets main and includes the parent benchmark changes. It can be retargeted when the parent mirror or merged base is available. This uses the current MoELayer interface and makes no assumption about a future MoEScheduler API.

The driver reports all-rank and worst-rank step times, logical expert/rank loads, virtual runtime loads, input/route/value hashes, and numerical errors for outputs, input/probability/parameter gradients and optional local SGD updates without a DDP wrapper. Seven W workloads run six steps each, including hotspot rotation and burst recovery. BF16 tolerances are fixed at relative L2 <= 0.01 and peak-normalized error <= 0.05; zero references must match exactly. Failed gates return nonzero while preserving records. Timings exclude evidence copies and reductions.

Validation:
- 267 CPU workload, trace and adapter-boundary tests passed; Black, isort and Ruff checks passed.
- Two NV18-connected H100 SXM 80 GB GPUs: all 336 rank records passed across seven workloads, six steps, two backends, two ranks and two modes (forward/backward and SGD update). The independent reader verified 50 original files and every route/input pairing. [Raw records, numerical errors and descriptive worst-rank timings](https://github.com/0z5a/Megatron-LM/tree/hopper-validation-evidence/validation/hopper-20261020/hybridep).
- Runtime: NGC PyTorch 26.09, Torch 2.14.0a0+b2c75dd062.nv26.09, CUDA 13.4, Triton 3.8.0, TE 2.19.0+5e52befd, NCCL 2.31.2. HybridEP source 10d4dd7377d5bce900fbb4b80cce863764892b95, sm90 intranode build. An older added NVSHMEM wheel was removed after its Torch ABI conflict; the original NGC runtime was retained. The initial cleanup import failure and its partial records were preserved before the complete corrected run.

Scope: one NVLink EP group, BF16, TP=ETP=1, fixed per-rank source tokens and K. Recompute, CUDA graphs, zero source rows, other precisions, full-model convergence and bit-exact qualification are outside this change. Fixed-order single-run timing is descriptive and is not a speedup qualification.
