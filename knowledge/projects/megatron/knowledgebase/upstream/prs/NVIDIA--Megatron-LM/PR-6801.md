# [dev] Support arbitrary-size dynamic context parallelism

## Original PR description

## Self-contained runtime and timing models (2026-10-12)

- Include the a55 lightweight CPU planner, physical-capacity/rank-row validation, full CP/EP forward/backward timeline, frozen attention prediction kernels and paired GDN/non-attention/FA-remainder parameters in `megatron/core/datasets/dcp_runtime_scheduler`. The stock runtime no longer requires the external `dcp-scheduler` package. Custom factory hooks remain optional.
- Provide in-tree `calibrated_attention` and `qwen35_gb200` model names. Preserve the standalone GPU-hidden worker and one-batch lookahead. Keep calibration/transfer limitations explicit; these are provisional timing predictions, not native/eager accuracy guarantees. No offline search or benchmark scripts are vendored.

Every rank passed **189 tests** (137 scheduler/model, 39 automatic selection, 13 dispatch compatibility).
- **56 frozen-core cases** (GB200/GB300, two attention geometries, CP1/2/3/5/7/16/32) reproduce both phase timings exactly; seven mixed-model program checks and two full schedule/prediction comparisons also match. A real arm64 wheel builds and contains all 31 parameter/provenance JSON files.

- Kineto still confirms genuine CPU/GPU compute overlap (230/250 compute kernels intersect two CPU solves); this is positive-overlap evidence, not a claim that the entire solve is hidden. This short integration gate is **not** fixed-CP versus DCP 100-step Qwen acceptance or a new throughput study. TE #3420 and existing Qwen/GDN campaigns are unchanged.

## What

- Allow the dynamic-CP scheduler to select arbitrary CP sizes instead of rounding every request to a power of two.
- Add lightweight logical CP descriptors backed by one existing DPxCP parent communicator.
- Order each logical ring so a rank sees at most four peers across all CP sizes and contiguous tail intervals are representable.
- Automatically route supported default GPT/TE full-attention DCP, MoE auxiliary reductions and MTP through native transport; no additional transport CLI flag.
- All ranks agree on model and parent-communicator capability before constructing dynamic CP groups. Unknown/unsupported models or old TE builds retain the legacy ProcessGroup path, with the reason logged; there is no per-rank fallback after native initialization.

## Async runtime scheduler (2026-10-11)

- Add one-batch lookahead at the data-iterator boundary, retaining the existing sampler, metadata collectives and rerun behavior.
- Solve only on the DPxCP leader in a persistent, GPU-hidden CPU executable; CUDA/NCCL and metadata collection stay on the training thread.
- Inject the frozen a55 planner through `plan_padded(..., logical_lengths=..., incumbent_rows=...)`, with explicit factory/options. Its 0.8-second budget is cooperative, not a hard timeout.
- Provide same-planner synchronous comparison (`--no-dynamic-cp-runtime-async`), powers-only baseline and per-rank input/row/timing/worker-state telemetry.
- Keep this optional path restricted to PP1/no VPP, sequence-parallel size one and matching dataset padding; support both classic zigzag and explicitly configured contiguous layouts.
- Release formatting/lint checks passed with no new diagnostics. Four-GB200 scheduler contract regression passed 124 tests per rank.
- Prior exact-a55 eight-GB200 small standard-attention GPT/MoE validation passed: same-solver sync/async input rows and logged LM/aux/grad norm matched, actual CP5+CP3 forward/backward ran, workers reported CUDA/distributed uninitialized, and Kineto confirmed simultaneous training compute kernels and CPU solving.
- These are short integration/overlap checks, not Qwen3.5/GDN acceptance or a new 100-step Qwen performance study. TE #3420 is unchanged.

## Prior transport and scheduler validation

- Formatting, import sorting, Ruff, and Pylint passed.
- Eight scheduler tests cover CP1-16 and CP5 followed by a CP3 tail starting at rank 5.
- Six logical-group/bounded-ring tests passed, including the maximum peer-degree invariant.
- Exact-source Qwen3-30B-A3B training on LongAlign-10k completed 100 fixed-CP16 steps and 100 native arbitrary-DCP steps on 32 H100 GPUs. The runs started from identical sampled parameters and consumed identical real batches at every step.
