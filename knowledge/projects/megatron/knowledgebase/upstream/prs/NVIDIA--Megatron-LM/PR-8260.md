# Refresh MFSDP v2 compute weights on optimizer checkpoint loads; add EP ckpt-resume test

## What does this PR do?

Follow-up to #8230, which refreshes MFSDP v2's BF16 compute weights in `FullyShardedDataParallelV2.load_state_dict` after a checkpoint load. Not every load goes through that method. The GPT→Hybrid `fsdp_dtensor` load (`gpt_fsdp_model_loaded_in_place` in `megatron/training/checkpointing.py`) writes the main weights in place and then only calls `FullyShardedOptimizer.load_state_dict`, or `optimizer.reload_model_params()` under `--no-load-optim`. Neither refreshed the compute weights, so the first resumed step ran on the pre-load weights.

This PR:
- Refreshes compute weights from `FullyShardedOptimizer.load_state_dict` and from a new `reload_model_params` override. Both iterate the model chunks' parameters rather than `get_parameters()`, because frozen parameter groups also keep separate compute weights and the load writes their main weights too. On a normal resume the refresh now runs twice (adapter and optimizer); the cost is one local cast of each group's main weight per load.
- Adds two EP=2 cases to `test_ep_fsdp_checkpoint_roundtrip`, each with a frozen word embedding, that skip the wrapper's `load_state_dict` the way the GPT→Hybrid load does:
  - `ep2_optimizer_only` loads the optimizer and compares all five resumed losses exactly;
  - `ep2_reload_model_params` loads no optimizer state, calls `reload_model_params()`, and compares the first loss, which depends only on the loaded weights.
- Adds `deepseek_proxy_mfsdp_v2_ep2_resume`, an mr-scope `ckpt-resume` twin of `deepseek_proxy_mfsdp_v2_ep2`. It saves at iteration 25 and resumes, so iterations 26–50 must match. Every other v2 functional test is `TEST_TYPE: regular`, so until now nothing in CI saved a v2 model and read it back through `load_checkpoint`. At 8 GPUs, EP=2 gives expert-DP 4, so expert shards are really split across ranks. Memory metrics are not compared, since a resumed process allocates differently.

## Validation

All on 2× RTX 6000 Ada, NGC PyTorch 26.08 (torch 2.14, TE 2.19).

- `test_checkpoint.py` + `test_optimizer_checkpoint.py`: **15 passed, 1 skipped** per rank (EP=4 needs 4 GPUs).
- Negative controls for the two new cases:
  - On #8230 without this change, both fail: `ep2_optimizer_only` on 5/5 losses (max abs diff 0.214), `ep2_reload_model_params` on the first loss (0.200).
  - Refreshing only `get_parameters()` also fails both (0.197), because the frozen embedding stays stale.
- The functional test was not run locally (it needs 8×H100 and the CI datasets). Its golden values (`golden_values_dev_dgx_h100.json` and `_2nd.json`) still need to come from a CI run.
- black 26.3.0, isort 5.13.2, ruff 0.9 and pylint 3.2.6 (10.00/10) pass on the changed Python files.
