# perf(moe): skip the combine communication when re-running a checkpointed MoE layer (incl. latent MoE)

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8347) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

With selective MoE recompute (`recompute_granularity="selective"`, `"moe"` in `recompute_modules`), the backward pass re-runs the MoE layer forward to rebuild the autograd graph. That re-run includes the combine exchange. This PR skips the combine's forward communication during the re-run and keeps its backward communication.
- Without latent projections, nothing reads the re-run's combined values.
- With latent MoE, the re-run reuses the combined latent tensor kept by the forward pass.

Outputs and gradients are bitwise unchanged. Still a draft.

Three commits:
1. Skip the re-run's combine communication (non-latent MoE).
2. Extend the skip to latent MoE.
3. Fix a pre-existing mismatch: the checkpointed forward and its recompute sorted the top-k differently, so they routed slightly differently. Commit 2's bitwise guarantee relies on this fix.

## Problem

- `MoELayer.forward` checkpoints `custom_forward` (`moe_layer.py:788` on main). `custom_forward` calls `self.combine(output)` (`moe_layer.py:771`).
- `CheckpointFunction.backward` re-runs the function (`random.py:740`) and then calls `torch.autograd.backward(outputs, args)` (`random.py:749`). The backward starts from the incoming output gradient.
- Without latent projections, the re-run's combined values only pass through:
  - the unpermutation (`unpermute` without probs; probs are applied in the experts),
  - the shared-expert add,
  - the reshape, and
  - the layer output.
- All of these are linear in the combined values, and none saves them for backward. So the re-run's combine communication is wasted:
  - alltoall dispatcher: the EP all-to-all (`token_dispatcher.py:879`) and, with expert TP, the reduce-scatter in `combine_preprocess` (`:844`);
  - allgather dispatcher: the TP x EP reduce-scatter (`:380`).
- Measured on main: one MoE layer's backward pass issues one more collective per combine exchange than with this PR. For example, 6 vs 5 `all_to_all_single` calls with alltoall at EP 2 and EP 4.

## The change

### Commit 1: skip the re-run's combine communication

- `tensor_parallel/mappings.py`: `all_to_all(..., skip_forward=False)` and `reduce_scatter_to_sequence_parallel_region(..., skip_forward=False)`.
  - With `skip_forward=True`, the forward returns zeros of the output shape without communicating.
  - The backward is the usual communication: the subclasses `_AllToAllSkipForward` and `_ReduceScatterToSequenceParallelRegionSkipForward` inherit it.
- Token dispatchers declare `supports_skip_combine_forward_comm`. It is true for alltoall and allgather. The inference all-gather dispatchers and flex keep the communicating re-run.
- `skip_combine_forward_comm` is the flag the supporting dispatchers pass to their combine collectives.
- `MoELayer._skip_combine_comm_on_recompute` wraps the checkpointed function and sets the flag on every call after the first.
  - It counts calls instead of checking grad mode, so it works with both `tensor_parallel.checkpoint` and TE's checkpoint.
  - Every rank re-runs the layer, so all ranks of a combine group skip together.
- Zeros rather than uninitialized memory: the cost is one memset, and the recomputed tensors stay finite for hooks and NaN checks.
- No config flag.

### Commit 2: latent MoE

- With latent MoE, `fc2_norm` and `fc2_latent_proj` read the combined values. So the forward pass keeps the unpermuted combined latent tensor, shape `[tokens, moe_latent_size]`.
- In the re-run, the combine is skipped as above. A small autograd function then substitutes the kept tensor for the skipped combine's output: it returns the kept values in the forward and passes the gradient straight through in the backward. The combine's backward still communicates.
- `fc2_norm` and `fc2_latent_proj` are recomputed from the same values the forward used.
- **Cost:** `tokens x moe_latent_size x 2 bytes` (bf16) per MoE layer per in-flight micro-batch, held from the forward to the backward pass. This is the same whether or not `moe_use_norm_before_up_proj` is set. The re-run still recomputes `fc2_norm` and the `fc2_latent_proj` GEMM (about `2 * tokens * latent * hidden` FLOPs).
- **Alternative considered:** checkpoint only route + dispatch + experts, and run combine + postprocess outside the checkpoint as normal saved activations. That avoids recomputing the `fc2_latent_proj` GEMM. But it saves `fc2_latent_proj`'s input plus `fc2_norm`'s input, which is twice the memory with the norm on. It would also move the checkpoint boundary through the partial-CUDA-graph / `intermediate_tensors` paths. The approach in this PR keeps one checkpoint and one code path.

### Commit 3: route the checkpointed forward like its recompute

- `topk_routing_with_score_function` sorted the top-k only when grad is enabled; sorting is turned off for inference (`moe_utils.py:913`).
- A checkpointed forward runs without grad and its recompute with grad. So the two picked the same experts in a different order.
- That order sets the order of the probability normalization and of the expert-output sums. So the recomputed values could differ slightly from the forward's, and the backward differentiated a slightly different function than the forward ran.
- Measured on a 512-expert, top-22 layer at EP 4, on one of four ranks: 1 of 1M router probabilities, 766 of 185M expert-output elements and 299 of 8.4M combined latent elements differed.
- The fix also sorts while `is_checkpointing()`. After it, all ranks reproduce the forward bitwise.
- **Limitation:** TE's checkpoint (fp8/fp4) does not set `is_checkpointing()`, so this fix does not apply there. Under fp8/fp4, the latent path differentiates through the forward's combined values rather than recomputed ones.

## Tests

`tests/unit_tests/transformer/moe/test_moe_layer.py::TestMoELayerRecomputeSkipsCombineComm`:
- Dispatchers: allgather and alltoall. (TP, EP) in {(1,1), (1,2), (1,4), (2,2), (2,4), (1,8)}, depending on the GPU count.
- Variants: shared-expert overlap (alltoall), and latent MoE (`moe_latent_size=32`, TE spec, shared experts) with `fc2_norm` off and on.
- Checks:
  - layer output, input gradient and every parameter gradient are `torch.equal` with the skip and without it (the re-run communicates);
  - the backward issues exactly one all-to-all / reduce-scatter fewer per combine exchange;
  - no state is left behind.
- On 4x GB200, together with `test_latent_moe_layer.py`, the existing recompute test at (1,1), and `test_routers.py`: all new and existing MoE-layer tests pass, and the 8-GPU cases skip.
- Two existing tests fail identically on unmodified main: `test_router_gating_linear[bf16]` and `test_router_gating_linear_bias[bf16]`.

`tests/unit_tests/transformer/moe/test_routers.py::test_checkpointed_forward_routes_like_its_recompute`:
- 4096 x 128 logits, top-22.
- Under `_set_checkpointing()` + `no_grad`, the selected indices and probabilities equal the grad-mode ones bitwise.
- It fails without commit 3.

## Layer benchmark

Setup: 4x GB200, one NVLink node, bf16, TE grouped GEMM.
- Deterministic mode (`deterministic_mode` + `torch.use_deterministic_algorithms`): outputs and all gradients are bitwise equal with and without the skip on all ranks. Configs:
  - E128, top-6, H2688 (non-latent), alltoall EP 4;
  - Super-like latent layer (H4096, latent 1024, E512, top-22, FFN 2688, shared 5376): alltoall EP 4 with `fc2_norm` off and on, allgather EP 4, alltoall TP2 x EP2.
- Without deterministic mode, the reference also differs from itself between runs (atomics), so bitwise comparisons need deterministic mode.

| config | fwd+bwd ref -> skip (median of 6 alternating rounds x 30 iters) | note |
|---|---|---|
| non-latent alltoall EP4, 32768 tokens/rank | 38.73 -> 37.08 ms | 1.60-1.69 ms saved in every round (about 4.3%) |
| non-latent alltoall EP4, 8192 tokens/rank | 13.74 -> 13.67 ms | within noise |
| non-latent alltoall TP2 x EP2 / allgather EP4 | within noise | reference spread larger than the difference |
| Super-like latent, alltoall EP4 / allgather EP4 / TP2 x EP2, 8192 tokens/rank | within noise | per-round differences of a few ms either way |

Latent memory:
- The tensor held from forward to backward grows by +16.2 MiB at EP 4, which equals 8192 x 1024 x 2 B. It grows by +8 MiB at TP2 x EP2 (half the tokens per rank with sequence parallelism).
- Peak memory over fwd+bwd is unchanged within 2.5 MiB.

The saving is one combine exchange per recomputed MoE layer and micro-batch. It should grow with the combine payload (tokens x top-k x hidden or latent) and with slower EP links, such as inter-node EP over IB. On one NVLink node it only rose above noise at 32k tokens per rank. For context, in NeMo-RL a similar skip on a custom device-side dispatcher (Nemotron-3-Nano, EP 4) saved 78 ms of about 1.58 s of fwd+bwd. That number is not from this code path.

## Limitations

- Only applies to the layer-level selective `"moe"` recompute. Full recompute (`recompute_granularity="full"`) is unchanged, because there the MoE output feeds later layers inside the same recomputed region.
- The flex dispatcher (DeepEP / HybridEP / NCCL-EP) is unchanged. #7416 (against `dev`) proposes an opt-in skip of the DeepEP combine and the expert fc2 GEMM in the re-run. This PR covers the alltoall / allgather dispatchers and does not overlap with it.
- The MoE-overlap path (`overlap_moe_expert_parallel_comm`, fine-grained callables) does not use `MoELayer.forward`'s checkpoint and is unchanged.
- fp8/fp4 (TE checkpoint): see the limitation under commit 3.
