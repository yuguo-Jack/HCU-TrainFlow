# Share Mamba branch execution through local residual state

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8344) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

## What does this PR do?

The shared Mamba forward currently carries both an ordinary residual tensor
and optional WR connection state, although each implementation uses only one.

This refactor introduces `ResidualBranchInput(branch_input, write_state)`:
the shared forward executes the branch and passes its saved state unchanged
to the implementation-specific residual-update hook.

- Ordinary Mamba saves its residual tensor.
- Current WR saves `(wide_residual,)`.
- Each implementation controls preparation, normalization, precision, and writeback.
- A packaging hook preserves the existing two-stage interfaces used by ShortcutMoE.

Residual mathematics, parameter ownership, and replay policy are preserved.

## Refactoring Plan

Stage 2A of #7888, following the replay-planning refactor in #7923.

This establishes a small common contract through ordinary and WR Mamba.
Future token-dependent WR variants or mHC adapters can save additional
coefficients needed at writeback while reusing the branch forward.
Their integration and cross-layer state transport remain subsequent work.

**Light review: Mamba branch execution now goes through `ResidualBranchInput`**

The refactor keeps behavior the same on every path I traced. I found no correctness, test-coverage, or documentation problems. There is one small style-guide nit, posted inline. It is annotation-only and does not block the PR.

What I checked against base:
- **WR two-stage tuple:** [`WideResidualMambaLayer._pack_two_stage_output`](https://github.com/NVIDIA/Megatron-LM/blob/f5de30a9324ce876172dbe7446c1399fb3468807/megatron/core/ssm/wide_residual_mamba_layer.py#L151-L156) returns `write_state[0]`. Base returned `self.residual_read.residual_stream(connection_state)` instead. These give the same tensor: [`ResidualConnection.residual_stream`](https://github.com/NVIDIA/Megatron-LM/blob/f5de30a9324ce876172dbe7446c1399fb3468807/megatron/core/transformer/residual_connection.py#L231-L238) is a staticmethod that validates the state and returns `state[0]`, and `StreamwiseSigmoidWideResidualConnection` does not override it. The validation call still runs before normalization, so a hook-modified read is still rejected at the same point.
- **ShortcutMoE:** [`ShortcutMoEBlock.forward`](https://github.com/NVIDIA/Megatron-LM/blob/f5de30a9324ce876172dbe7446c1399fb3468807/megatron/core/models/hybrid/shortcut_block.py#L519-L564) still unpacks `*paired_state` into `forward_post_core_attn`. The tuples are unchanged: `(ssm_output, residual)` for ordinary Mamba and `(ssm_output, residual, connection_state)` for WR. WR's `forward_post_core_attn` now passes only `connection_state` to `_apply_mixer_update`. Base never used `residual` there anyway.
- **Replay policy:** unchanged. Ordinary Mamba returns `None` for the context. WR still checkpoints the read and a non-`IdentityOp` norm, and checkpoints the write only when it is not the block end.
- **Python version:** a generic `NamedTuple` needs Python 3.11 or later, and `pyproject.toml` requires `>=3.12`, so `ResidualBranchInput[ResidualConnectionState]` in the WR return annotation is safe.
- **Old private signatures:** I looked for callers of the old 4-tuple `_prepare_mixer_state` and the old `_apply_mixer_update(residual, connection_state)` in `test_residual_recompute.py`, `test_shortcut_block.py`, `test_hybrid_block.py` and `test_wide_shortcut_parallel.py`. None remain, and [`test_mamba_layer.py`](https://github.com/NVIDIA/Megatron-LM/blob/f5de30a9324ce876172dbe7446c1399fb3468807/tests/unit_tests/ssm/test_mamba_layer.py#L75-L189) was updated to the new binding.
- **New tests:** [`test_mamba_residual_state.py`](https://github.com/NVIDIA/Megatron-LM/blob/f5de30a9324ce876172dbe7446c1399fb3468807/tests/unit_tests/ssm/test_mamba_residual_state.py) compares the new forward against the old eager schedule. It checks outputs, gradients, the operator trace, the RNG state and hooks, and also covers two-stage parity, replay selection and legacy state-dict loading. The CPU path it relies on exists (`streamwise_residual_ops` has a pure-PyTorch fallback), and the `SimpleNamespace` config has every field the WR connection constructors read. I reasoned through these tests but did not run them.
