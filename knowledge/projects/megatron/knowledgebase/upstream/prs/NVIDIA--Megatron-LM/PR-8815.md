# Scope DDP's NCCL user-buffer warmup barriers to the DP group

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8815) · state: closed · merged: False

## Original PR description

**Why.** With `nccl_ub=True`, `_ParamAndGradBuffer.__init__` calls `torch.distributed.barrier()` with no group before and after its warmup `all_reduce` on the buffer's data-parallel group. It does this once per buffer. A rank builds one buffer per (param dtype, grad dtype, expert-parallel) key of its own model chunk, so its WORLD barrier count depends on its own parameters.
- In an MoE or hybrid model with a dense-only pipeline stage, that stage has no expert buffer. Each expert buffer adds 2 WORLD barriers on the MoE stages that the dense stage never enters.
- MIMO modules each wrap their own DDP on their own grid, so their ranks enter different counts too.
- The extra barriers wait on ranks that never reach them, or pair with a later default-group collective. Setup hangs, or later collectives cross-pair.
- The WORLD communicator is not one the memory pool registers on, so the WORLD barrier warms nothing that registration uses.

**What.**
- Pass `group=self.data_parallel_group` to both barriers in `megatron/core/distributed/param_and_grad_buffer.py`. That is the group of the warmup `all_reduce` and of the NCCL memory-pool registration.
- Every rank of that group is a data-parallel replica of the same model chunk. It builds the same buffers in the same order.
- Those ranks already enter the warmup `all_reduce` on this group at this point. The barriers sit on the same path, so exactly the group's ranks enter them, once per buffer.
- Dense buffers keep the intra DP x CP group and expert buffers the intra expert-DP group.

**Tests.**
- New `test_nccl_ub_warmup_syncs_only_the_data_parallel_group[gloo|nccl]` in `tests/unit_tests/distributed/test_param_and_grad_buffer.py`. It makes each half of the world its own data-parallel group. The first half builds 2 buffers with `nccl_ub=True` and the second half builds 1. The NCCL allocator is mocked. Collectives on the rank's own group run for real, and any collective on another group is recorded and skipped, so main fails instead of hanging.
- On 4 CPU ranks with Gloo, the `[gloo]` case passes on this branch and on 2 ranks. On main with only the new test added, it fails on every rank: ranks 0 and 1 report 4 group-less barriers, ranks 2 and 3 report 2.
- On 4 GPUs with NCCL, the whole file gives 99 passed and 4 skipped on this branch, and 97 passed and 4 skipped on main. The 2 extra passes are the new `[gloo]` and `[nccl]` cases.
- The whole file on 4 CPU ranks gives 81 passed, 17 failed, 5 skipped on this branch. Main with the new test gives 80 passed, 18 failed, 5 skipped. The extra failure on main is the new test. The other 17 fail on CPU with "Torch not compiled with CUDA" and are the same set on both.
- No DDP run with `--use-nccl-ub` and real NCCL memory pools was done on GPUs. No unit or functional test covers that path today.
- `tools/check_process_group_usage.py` reports the same 3 pre-existing entries before and after.
- `tools/check_kernel_determinism_coverage.py` flags the file under `ddp_grad_buffer_reductions`, hence `determinism-exempt`. The change only scopes two barriers and does not touch any reduction.

**Compatibility.**
- Without `nccl_ub`, nothing changes.
- With `nccl_ub`, the warmup no longer synchronizes ranks outside the buffer's data-parallel group. When every rank owns the same buffers, the only difference is that the barriers are on smaller groups.
