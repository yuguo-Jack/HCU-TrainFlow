# Pass the CP size and last stage to the combined 1F1B loss step

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8028) · state: open · merged: False

## Original PR description

**Why.** The EP-overlap (combined 1F1B) schedules call `forward_step_calc_loss` without `cp_group_size` and `is_last_stage`. It therefore reads `parallel_state.get_context_parallel_world_size()` and `parallel_state.is_pipeline_last_stage()` even when the schedule has an explicit `pg_collection`. If the schedule's grid differs from the global one, the loss and the MoE auxiliary and indexer loss scales use the wrong CP size, and a stage that is not last can compute the loss. Without a global grid, the call fails.

**What.**
- Without pipelining, pass the collection's CP size; every microbatch is on the last stage, as `forward_step` already assumes.
- With interleaving, pass the CP size and the pipeline group. A forward chunk is last when `is_vp_last_stage(...) and is_pp_last_stage(pp_group)`, as on the non-overlapped path.
- Every caller now passes both values, so `forward_step_calc_loss` requires them and its global fallback is removed.

**Tests.** The new `tests/unit_tests/a2a_overlap/test_combined_1f1b_process_groups.py` runs on 4 GPUs. An EP-overlap step without pipelining (EP=4) and an interleaved one (PP=2, VPP=2, EP=2) both match the non-overlapped step and make no global CP-size or last-stage query. Both fail on main. Existing combined-1F1B and schedule tests are unchanged.

**Compatibility.** Same values on the standard grid. `forward_step_calc_loss` and the combined-1F1B helpers take the new arguments as required parameters; no callers outside Megatron-LM were found.
