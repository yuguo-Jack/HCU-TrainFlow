# What does this PR do?

Prevent ranks from rewriting the VMM allocator's C++ source while another rank compiles it. PyTorch's `load_inline()` publishes `main.cpp` before taking its build lock; on a cold cache, competing writers can truncate the source while the compiler is reading it, potentially producing a shared library without the expected Python module initializer.

Move the existing C++ into `megatron/core/allocator/csrc/vmm_symm_allocator.cpp` and build it with `cpp_extension.load()`. Include the source in wheels and source distributions. Preserve the allocator's behavior, extension name, build directory, and success/failure caches. Add regression coverage for packaged-source loading and failure caching, and include the C++ path in the allocator's existing determinism exemption.

## Validation

- Two allocator unit tests passed through `torch.distributed.run` with the normal repository conftest.
- Four simultaneous processes completed a cold build/load of the real extension; output showed one compiler/linker invocation and successful loads on all four ranks.
- Built a source distribution and a wheel from it; both contain the exact C++ source.
- C++ token comparison against the former inline source passed, excluding the explicit `<cstdlib>` include.
- Black, isort, Ruff, Pylint, the determinism coverage gate, and `git diff --check` passed.

Local validation used the existing `megatron-lm:local` development image (PyTorch `2.13.0a0+8145d630e8.nv26.06`) and its bundled CUDA compatibility libraries. Current main's CI image pin is 26.08, so this is not exact CI-image parity. No GPU memory allocation or NCCL collective was exercised. The unit-test fixture attempted an unavailable dataset download; these two tests do not use that dataset.
