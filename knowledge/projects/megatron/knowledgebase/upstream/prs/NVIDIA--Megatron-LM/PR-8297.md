# Release router probs in the all-to-all dispatcher after combine

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8297) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

The all-to-all MoE token dispatcher now drops its reference to the router probabilities at the end of `combine_postprocess`, so under full activation recompute every MoE layer's recomputed autograd graph is no longer kept alive for the rest of the backward pass.

## Why it happens

`MoEAlltoAllTokenDispatcher.dispatch_preprocess` stores the router output on `self.probs`. That tensor carries the router's `grad_fn`. Only `combine_preprocess` reads it, later in the same forward, and only for its dtype. Nothing clears it afterwards, so the reference lasts until the next forward through that layer overwrites it, and it keeps that forward's autograd graph reachable the whole time.

Without recompute this costs almost nothing: the next microbatch's forward overwrites the reference. With `recompute_granularity=full`, the forward re-runs inside each layer's backward. Each recomputed MoE layer stores a new `self.probs` whose graph reaches back to the checkpoint's detached input and that input's `.grad`. No later forward overwrites it, so every MoE layer keeps its recomputed graph for the rest of the backward pass. Memory therefore grows with the number of MoE layers and with sequence length.

This applies to any MoE model that uses the all-to-all dispatcher with full recompute. Nothing in it is model-specific.

## The fix

At the end of `MoEAlltoAllTokenDispatcher.combine_postprocess`, set `self.probs = None`. Every MoE forward goes through this step: the plain `MoELayer.forward` and the fine-grained overlap callables (`fine_grained_callables.py`, `shortcut_block.py`) all reach it through `MoELayer.postprocess`. Nothing reads `self.probs` after `combine_preprocess`. The other `.probs` reads in megatron-core are on `cudagraph_tensor_store`, which is a separate object. The partial-CUDA-graph attribute plumbing (`cudagraph_attrs` / `_get_token_dispatcher_attrs`) reads `probs` right after preprocess, while it is still set, so it is unaffected.

## Alternatives considered

- **Clear it in `MoELayer.postprocess`.** SkyRL does this as a monkeypatch, because SkyRL also replaces dispatcher methods with its own and wanted the release to survive those patches. In megatron-core the dispatcher sets the attribute, so the dispatcher should also clear it. `MoEAlltoAllTokenDispatcher` is the only dispatcher that sets `self.probs`, so both placements behave the same.
- **Clear it right after the last read in `combine_preprocess`.** This releases it slightly earlier within the same forward. The leak is about the reference outliving the forward, so that difference does not matter. `combine_postprocess` is the last step of the dispatcher's forward.
- **Store `probs.detach()`, or only `probs.dtype`.** Either one also breaks the graph pin. But `probs` is listed in `cudagraph_attrs`, which the `moe_preprocess` partial CUDA graph returns and restores. Changing what the attribute holds would touch that surface, while clearing it after use does not.

## Scope and limitations

- When `MoELayer.postprocess` runs inside a captured partial CUDA graph (`_forward_mlp_postprocess`), the Python assignment runs only during capture, not on replay. This PR does not change that path.
- `MoEAllGatherTokenDispatcher.local_probs` and the flex dispatcher managers (`token_probs`, `dispatched_probs`) store probs the same way, for the same forward. This PR does not touch them because the measurements below cover only the all-to-all dispatcher. They could get the same treatment in a follow-up.

## Test plan

- New CPU unit test `test_alltoall_combine_postprocess_releases_router_probs` in `tests/unit_tests/transformer/moe/test_token_dispatcher.py`. It builds the dispatcher's combine state directly and stores a non-leaf `probs` (softmax of a leaf that requires grad). It then checks that `combine_postprocess` returns the expected unpermuted output, leaves `self.probs` as `None`, and that a `weakref` to the probs tensor is dead afterwards, meaning nothing else holds the graph.
  - With this change: passes. Without the change in `token_dispatcher.py`: fails on `assert dispatcher.probs is None`.
  - The rest of `test_token_dispatcher.py` on a CPU-only host: 16 passed, 72 skipped (CUDA not available).
- The existing GPU dispatcher tests (`test_a2a_token_dispatcher.py`, `test_token_dispatcher.py`) exercise forward/backward through `combine_postprocess` and should pass unchanged in CI. I did not run them on GPU for this PR.

## Validation (SkyRL)

The same release has run in SkyRL as a monkeypatch on `MoELayer.postprocess` since [NovaSky-AI/SkyRL#2433](https://github.com/NovaSky-AI/SkyRL/pull/2433). It is applied to every Megatron model build there.

- GLM-5.3-Flash (42 MoE layers, TP8) with full recompute: about 21 GiB per GPU at 64k tokens and about 42 GiB per GPU at 256k tokens were held by these references and are freed by the release.
- End-to-end parity test on B200, 4-layer GLM-5.3-Flash slice, full recompute vs. none with the release applied ([NovaSky-AI/SkyRL#2411](https://github.com/NovaSky-AI/SkyRL/pull/2411)):
  - Grad relative error 0.0219, against run-to-run noise of 0.0234 / 0.0227.
  - Activation peak 15.7 -> 8.8 GB. This number compares recompute against no recompute, so it does not isolate this change alone.
