# What does this PR do?
Two fixes for serving distributed checkpoints of wide-residual MoE models:

- Wide-residual parameters moved from residual_connection* modules to residual_read*/residual_write* modules in #7952. load_residual_state maps the legacy keys for load_state_dict only, so torch_dist checkpoints saved before the split loaded without their residual read/write/retention maps (dropped silently under log_unexpected strictness). load_checkpoint now retargets each wide-residual sharded key that the checkpoint lacks to its legacy key when that one is present (retarget_legacy_residual_keys), for model and optimizer state.

- The MIMO checkpoint loader enabled moe_router_enable_expert_bias whenever the checkpoint carries router.expert_bias. With global-batch quantile balancing the router registers and loads expert_bias itself, and the config rejects combining it with the DeepSeek-style update, so such checkpoints could not be served. Skip the override there.
