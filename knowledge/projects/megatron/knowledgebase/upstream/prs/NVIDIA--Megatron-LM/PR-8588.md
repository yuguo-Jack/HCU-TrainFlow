# Optionally overlap unpaired layers' EP comm with the post-process

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8588) · state: open · merged: False

## Original PR description

Add ep_overlap_unpaired_layer_post_process (default off). When the forward and backward chunks of a combined 1F1B step have different layer counts, the extra layers run unpaired and their EP dispatch/combine is exposed. With the flag, the other microbatch's post-process (output layer + loss) fills the first unpaired layer's comm window: the backward output-layer backward runs during the dispatch of the first unpaired forward layer (unpaired forward layers now run first), or the forward output-layer forward runs during the combine backward of the first unpaired backward layer. TransformerLayerSchedulePlan.run gains an optional fill_comm_window callback for unpaired layers. Only the order changes.

Adds a parity test for [2,1], [3,1], [1,2], [1,3] and [1,1] chunks with and without MTP.
