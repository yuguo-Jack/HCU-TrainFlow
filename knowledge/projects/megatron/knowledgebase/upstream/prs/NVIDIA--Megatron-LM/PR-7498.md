# Fix MTP loss normalization across context parallel ranks

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7498) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

## What does this PR do?

Fix MTP loss normalization across context-parallel ranks. A rank with no original LM targets can receive a shifted MTP target and discard its gradient because per-token normalization multiplies by its zero local count. Even an all-ones mask gives different weights after CP partitioning.

Reduce original and effective shifted token counts over the explicit CP group, compensate CP averaging in legacy mode, and apply consistent weighting to logged MTP loss. This works with current main's contiguous/zigzag layouts and early/deferred backward paths. CP=1 behavior and the existing DP/microbatch objective are preserved. There are no parameter, checkpoint-format, or public-signature changes; CP>1 adds one two-scalar collective per MTP depth.

Related to NVIDIA-NeMo/Megatron-Bridge#6103 and NVIDIA-NeMo/Megatron-Bridge#6105. The Bridge change forwards the mask; this companion fixes normalization once the mask reaches the model.

## Tests

- A two-GPU functional test uses a complete GPT+MTP model, training schedule, Megatron DDP, and `finalize_model_grads`. It compares every parameter's gradient across CP1/CP2 for seven masks, depths 1/3, both normalization modes, early/deferred backward, and two accumulated microbatches. Empty masks must produce exactly zero gradients. The H100 recipe participates in both default and full PR functional scopes.
- Focused distributed unit tests compare token, hidden-state, and shared-head gradients, plus logged loss. They cover zigzag/contiguous layouts, packed/unpacked sequences, all single-target positions, empty masks, and depth-3 cumulative conditioning masks. Conditioning tests independently calculate expected token gradients and effective denominators.
- On two H100s against main `d5cc5e6d`, all **81 unit cases passed per rank with normal pytest fixtures**. The old helper reproduced the CI `runtime_gather_output` TypeError; the updated helper uses the current MTP API.
- All 12 focused upstream MTP loss tests and nine SOAP optimizer tests pass per GPU. The previous general-bucket cancellation followed a rank-3 SOAP stall; that stall did not reproduce in the focused run.
- Against unmodified current main, the real BF16 functional test fails **38/56** comparisons. With this fix it passes **56/56** comparisons. Maximum per-parameter relative gradient difference: **0.904%**, below the existing **2.5%** tolerance.
- Native CPU/Gloo checks pass all 80 gradient/conditioning cases with both two ranks and four ranks forming independent CP groups with different data. Unmodified current main fails all 32 gradient matrix cases in both topologies.

Reproduce the functional test:

```bash
CUDA_DEVICE_MAX_CONNECTIONS=1 uv run python -m torch.distributed.run \
  --standalone --nproc-per-node=2 \
  -m tests.functional_tests.test_cases.gpt.gpt_mtp_cp_gradients.test_gradients
```
