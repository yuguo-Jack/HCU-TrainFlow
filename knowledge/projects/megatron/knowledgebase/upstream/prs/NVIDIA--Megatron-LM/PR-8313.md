# MFSDP v2: add Muon with sharded momentum

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8313) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

Muon needs full matrices for orthogonalization while MFSDP v2 keeps parameters and gradients sharded. Add `experimental.muon.FsdpMuon` to keep momentum sharded, gather each matrix to its assigned owner for orthogonalization, scatter the update, apply local weight updates, and refresh model weights. Buffers complete this sequence serially on the caller's CUDA stream.

Owners are assigned jointly across the fixed set of buffers during initialization and reused across steps. Parameters sharing an FSDP buffer can belong to different optimizer groups with different hyperparameters.

The design considers three ways to reuse Emerging Optimizers (EO):

1. **Inheritance (chosen):** subclass EO's `Muon`, reusing its configuration, public orthogonalization method, and update hooks. One optimizer owns state, parameter groups, and checkpointing.
2. **Composition:** contain an EO `Muon` instance. The main difficulty is optimizer state ownership across the wrapper and inner optimizer: updates and checkpoint save/load must consistently use the same state and parameter groups.
3. **Direct EO kernels:** call Newton–Schulz and scaling functions from a standalone optimizer. The main drawback is duplicating EO's configuration, defaults, and validation code.

Inheritance is the current choice. Revisit it as the [inheritance tax](https://media.pragprog.com/titles/tpp20/inheritance-tax.pdf) grows, for example if adapting to EO changes requires more overrides or workarounds. Momentum initialization stays local, and the implementation uses public EO methods.

This version supports 2D parameters on a one-dimensional, non-quantized, all-`RowAtomic` DP mesh without tensor parallelism. Non-2D parameters are skipped and need another optimizer; explicitly exclude 2D parameters that should use another optimizer, such as embeddings and output projections. Weight decay defaults to zero, and nonzero values are rejected.

```python
from megatron_fsdp.experimental.muon import FsdpMuon

optimizer = FsdpMuon(matrix_params, dp_mesh=mesh, lr=0.05, momentum=0.95, nesterov=True)
```

Adds the optional `megatron-fsdp[emerging-optimizers]` dependency. Weight decay, stream overlap, higher-dimensional parameter contraction, and MCore optimizer-factory integration remain follow-up work.

Original work by @janEbert in #7519. This is the first standalone optimizer slice of that prototype. Related to #5533.

Validation:

- All four numerical reference cases passed on both ranks of a two-GPU/NCCL run. Weights, momentum, and forward outputs match unsharded EO Muon bit-for-bit over multiple steps. Coverage includes FP32/BF16 model weights, momentum/Nesterov, nondefault orthogonalization settings, multiple optimizer groups, split/fully local matrices, excluded parameters, non-2D parameters, skipped gradients for individual tensors and whole buffers, cached owner assignment, and optimizer-state reload.
- Black, isort, pylint, Ruff, kernel determinism coverage, and `git diff --check` passed.
- The nonblocking mypy check reports only three `import-untyped` diagnostics because EO does not ship typing metadata.
