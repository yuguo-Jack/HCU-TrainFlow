# Fix MFSDPv1 meta-device init overwriting router buffers

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8952) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?
Megatron-FSDP v1 with `init_model_with_meta_device=True` replaces tensors that a module already created on a device with uninitialized memory when it materializes the module. This includes the MoE router's `expert_bias` and `local_tokens_per_expert` buffers. This PR materializes only the meta tensors and leaves the others unchanged.

## Problem
  Under `torch.device("meta")`, a module can still create tensors on a device by passing `device=` explicitly. `TopKRouter.__init__` does this for its zero-initialized buffers (`expert_bias`, `local_tokens_per_expert`, and others such as `global_tokens_per_expert` and `qb_bin_bounds`).

  v1 materialized each meta-initialized module with `Module.to_empty(device, recurse=False)`, then called `reset_parameters()`. `to_empty()` replaces **every** parameter and buffer of the module with uninitialized memory, not only the meta ones. `reset_parameters()` then re-initializes the router weight but never zeroes these buffers again, so they hold whatever data was previously in that memory.

## Fix
  In `ParamAndGradBuffer`, replace `m.to_empty(device=self.device, recurse=False)` with `m._apply(...)`. It allocates `torch.empty_like(t, device=device)` only for tensors where `t.is_meta`, and returns the other tensors unchanged.

 ## Test
  `TestMegatronFsdpMetaDeviceInitRouterBuffers` in `test_mcore_fully_sharded_data_parallel.py`:
  1. Builds a GPT MoE model with aux-loss-free routing (`moe_router_enable_expert_bias=True`) under `torch.device("meta")`.
  2. Writes sentinel values into each router's `expert_bias` and `local_tokens_per_expert`. Uninitialized memory would not reproduce these values.
  3. Wraps the model with `FullyShardedDataParallel` (`init_model_with_meta_device=True`) and checks that both buffers are unchanged.

The test is parametrized over `optim`, `optim_grads`, and `optim_grads_params`.
  - Before the fix: all 3 cases fail (`expert_bias` differs by up to 4.03).
  - After the fix: all 3 pass.
