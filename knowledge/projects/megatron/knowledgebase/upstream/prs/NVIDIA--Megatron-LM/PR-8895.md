# Run the training loop on its process-group collection and add a strict mode

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8895) · state: open · merged: False

## Original PR description

This PR moves the rest of the training loop onto the run's `ProcessGroupCollection`: RNG seeding, the parameter-hash check, the loop's remaining global reads and cached-logits distillation. It also adds `--strict-process-group-fallbacks`, which turns every process-group fallback into an error. Training-loop maintainers and frameworks that call `pretrain()` with their own collection are affected. On the standard grid every step uses the same groups as before, and seeds change only under `lazy_mpu_init`. The PR consolidates six draft PRs unchanged, one commit per draft, so please review commit by commit. It builds on #8890 (core process-group APIs, #8039 and #8049) and #8891 (training I/O, #8037), and lands after both. Part of #6307.

## Members

- #8031: Seed the RNG from the model's process-group collection. `model_parallel_cuda_manual_seed` takes a keyword-only `pg_collection` and reads the TP, EP, expert-TP and GTP-remat ranks from it, and `pretrain` passes its collection through `initialize_megatron(seed_pg_collection=)`.
- #8047: Check parameter hashes across the model's own data-parallel groups. `check_param_hashes_across_dp_replicas` takes `dp_group` and `expt_dp_group`, and the training loop passes the model's groups, so a model on its own grid no longer compares hashes with unrelated ranks.
- #8741: Run the training loop's remaining reads on its process-group collection. Batch accounting, the samples-seen sum, packed-sequence FLOPs, full validation, the full-dataset probe, the GPU sniff test and the ModelOpt CP size now use the model's or the run's collection.
- #8743: Run cached-logits distillation on the model's process groups. `LogitsSaverHooks`, `CachedLogitsKDLoss` and the teacher dataset helpers take the collection or `tp_dp_cp_group` instead of reading the global groups.
- #8733: Add a strict mode that turns process-group fallbacks into errors. `enable_strict_process_group_fallbacks()` and the `--strict-process-group-fallbacks` flag (off by default) make every fallback raise on the rank that reaches it, and the rank-0 log suppression no longer hides fallback warnings on other ranks.
- #8737: Seed the RNG from the grid that `initialize_megatron` builds. `_initialize_distributed` returns the collection that `initialize_model_parallel()` built, and seeding and the grid-size log lines read it instead of the global state.

## Behavior changes for callers

- A collection passed to `pretrain` must set `tp`, `ep`, `expt_tp`, `gtp_remat` and `expt_gtp_remat` (`None` when an axis is off), plus `dp_gtp_remat` with `--data-parallel-random-init`. An unset field raises `ValueError`.
- The batch-size check raises `ValueError` instead of failing an `assert`, so it also runs under `python -O`.
- The samples-seen sum and the full-dataset probe raise `ValueError` when the collection lacks `dp_gtp_remat` (or `dp_cp_gtp_remat`).
- With distillation on, a custom collection without `tp`, `cp`, `dp_gtp_remat` or `tp_dp_cp` raises `ValueError`.
- A multi-module (MIMO) run with `--gpu-sniff-test-interval` raises `ValueError` at the start of `train()`. On main it failed inside the sniff test.
- The rank-0 suppression appends its warning filters. An earlier `error` filter for these categories now raises on every rank, and `ProcessGroupFallbackWarning` shows on every rank.
- With `lazy_mpu_init`, the tensor-parallel RNG seed uses the TP group rank instead of the global rank. This matches non-lazy runs.
