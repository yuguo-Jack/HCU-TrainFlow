# fix: restore activation checkpointing state after exceptions and nested calls

## What does this PR do?

Restore the enclosing `is_checkpointing()` state when activation checkpoint
forward/backward returns or raises.

Currently, an exception in `run_function` or autograd skips the unconditional
unset and leaves `IS_CHECKPOINTING` true. Conversely, an inner checkpoint unsets
the flag while the outer checkpoint is still running. A small context manager
saves the previous state and restores it in `finally` around both paths.
This keeps the existing process-global flag; it does not add thread safety or
change the checkpoint computation/RNG protocol.

Tests cover forward/recompute/backward exceptions, subsequent healthy use,
nested checkpoint output and gradients, and normal CPU/CUDA RNG preservation.
