# Bind args to the ModelOpt builder in the inference entry points

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8728) · state: closed · merged: False

## Original PR description

**Why.** With `--modelopt-enabled`, `get_model_for_inference()` in `megatron/inference/utils.py` and `tools/run_text_generation_server.py` pass `modelopt_gpt_hybrid_builder` straight to `get_model()`. The builder takes `args` as its first positional parameter, but `get_model()` calls its provider with keyword arguments only. Every ModelOpt run through these entry points fails with `TypeError: modelopt_gpt_hybrid_builder() missing 1 required positional argument: 'args'`. That includes `tools/run_dynamic_text_generation_server.py`, which reaches `get_model_for_inference()` through `get_dynamic_inference_engine()`. The regression came with #5169, which replaced `partial(model_provider, builder)` with the bare builder.

**What.**
- Bind `args` with `functools.partial` at both call sites. That is what `model_provider()` did for this builder, and what `examples/post_training/modelopt` still do.
- Drop the claim in the call-site comments that `get_model()` runs the ModelOpt checkpoint auto-detection. Both entry points take this branch only when `--modelopt-enabled` is already set, and `maybe_enable_modelopt()` returns at once in that case.

**Tests.** New `tests/unit_tests/post_training/test_modelopt_inference_builder.py` drives both entry points with a stand-in builder that has the real builder's signature and a stand-in `get_model()` that, like the real one, calls the provider with keyword arguments only and replaces a `None` collection with its own groups. The builder must receive the same `args` object and exactly the groups `get_model()` built with. A third test compares the stand-in's signature with the real builder where ModelOpt is installed. In a CPU run before the 2026-11-01 sync, the two binding tests fail on main with the `TypeError` above and pass here. The rest of `tests/unit_tests/post_training` gives the same results on both. The signature test skipped in that CPU run because ModelOpt is not installed there. In the integration run on 4 GPUs (main 77391e71cc with all #6307 PRs merged), all 3 tests in the new file pass and none skip; main has no such file. In the integration run, this PR's test files show no regressions against main. No end-to-end run with `--modelopt-enabled` was done.

On main after #8391, the first commit's test fails without the third commit, so please squash on merge.

**Compatibility.** No API change and no new warnings. Not fixed here: since #5169 these entry points no longer pick the ModelOpt builder on their own for a ModelOpt checkpoint served without `--modelopt-enabled`. That behavior change needs its own PR.

Synced with main 77391e71cc on 2026-11-01 by a merge commit with no conflicts, so existing commits and review links stay valid.
