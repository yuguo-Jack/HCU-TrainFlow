# Preserve empty FusedAdam group steps on distributed optimizer restore

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7707) · state: open · merged: False

## Original PR description

Distributed optimizer checkpoints align the step of every parameter group for resharding. On load, that aligned step is copied into every local group, including groups that hold no parameters on this rank. Whether that matches an uninterrupted run depends on the FusedAdam in use:

- Apex FusedAdam, and TE FusedAdam before 2.19, skip empty groups entirely, so an uninterrupted run never gives an empty group a step. Loading the aligned step there adds metadata that a fresh run does not have.
- TE 2.19 and later advance `step` in empty groups too (TransformerEngine#3318), so an uninterrupted run carries the aligned step everywhere and the current restore is already right.

For FusedAdam versions that skip empty groups, this keeps the live step of an empty local group (or its absence) on restore. Populated groups still restore the checkpoint step. TE 2.19+ behaves exactly as on main. Serialization is unchanged, so existing checkpoints load as before. Empty groups update no parameters or moments, so this is not a fix for numerical divergence. It removes a difference in raw `param_groups` and the inner optimizer's `state_dict()` that breaks exact fresh-versus-resume state comparisons.

Tests (`tests/unit_tests/optimizer/test_distrib_optimizer_empty_groups.py`, real FusedAdam on tiny CUDA tensors):
- `FUSED_ADAM_SKIPS_EMPTY_GROUPS` matches what the installed FusedAdam does after a real step, so a TE version without the expected behavior fails loudly.
- After a restore, every group carries the same step metadata as an uninterrupted run, with fresh and preallocated optimizer state.
- Absent, zero and nonzero empty-group steps, reordered groups, populated-group restore, and an unmodified checkpoint after loading.

Validation on GB300, four ranks, normal repository conftest:
- TE 2.17: all 9 cases pass. With `distrib_optimizer.py` from main, the uninterrupted-run comparison fails.
- TE 2.17 patched with TransformerEngine#3318 and reporting 2.19: all 9 cases pass. Main passes the uninterrupted-run comparison and the first revision of this PR fails it. That revision's own test also failed here, because it assumed a FusedAdam step leaves an empty group without a step. CI runs TE 2.20.
- `tests/unit_tests/optimizer`, `test_optimizer.py` and `test_optimizer_cpu_offloading.py` on the CI-style merge with main: 214 passed, 52 skipped on stock TE.
- Black and isort pass.

Performance: this runs once per checkpoint load and does not touch the training step.

Related: #7288 describes the same empty-group metadata difference while fixing a separate optimizer restore-allocation problem.
