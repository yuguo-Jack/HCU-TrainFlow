# Fix --ckpt-step checkpoint selection bugs

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8115) · state: open · merged: False

## Original PR description

## Summary

Fixes three related bugs in `--ckpt-step` handling that cause the wrong checkpoint to be loaded:

1. **`--ckpt-step 0` silently ignored** — `getattr(args, 'ckpt_step', None)` is used as a truthiness check, so step 0 (falsy) falls through and loads the latest checkpoint instead.

2. **`release=True` not cleared** — When the tracker file records a release checkpoint but the user requests a specific numeric step, the `release` flag remains `True`, causing `get_checkpoint_name` to resolve to the `release/` directory instead of `iter_NNNNNNN/`.

3. **Non-persistent checkpoint silently overrides explicit step** — In `_load_base_checkpoint`, a non-persistent checkpoint at step >= the requested step takes precedence, even when the user explicitly requested a specific persistent checkpoint via `--ckpt-step`.

## Changes

- `get_load_checkpoint_path_by_args`: truthiness → `is not None`, set `release = False`
- `_load_base_checkpoint`: same truthiness fix, same `release = False`, skip non-persistent override when `--ckpt-step` is explicitly set

## Test plan

- [ ] `--ckpt-step 0` now loads step-0 checkpoint instead of latest
- [ ] `--ckpt-step N` with release tracker loads `iter_000000N/` not `release/`
- [ ] `--ckpt-step N` ignores non-persistent checkpoints at step >= N

Fixes #8110
