# [dev] enable parallel PP prewarm

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/6850) · state: open · merged: False

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?
Run a synthetic local forward/backward pass on every pipeline stage before the first scheduled training iteration. This initializes lazy kernels concurrently across PP stages without pipeline P2P dependencies.This prewarm does not capture or replay CUDA Graphs. Normal graph capture still happens later in the training schedule.   

## Performance

  On a full-scale DSV4-Flash run using 64 GB200 GPUs (`TP=1`, `PP=4`, `VPP=4`, `CP=16`, `EP=16`, 64K sequence length), startup time through the completion of the first training iteration decreased from **866.0s to 370.8s**, a **2.34x speedup**.

File: `megatron/core/pipeline_parallel/parallel_prewarm.py` · line 291

**[IMPORTANT Correctness]** `layer.forward(*args, **kwargs)` bypasses `nn.Module.__call__`, so none of the layer's forward pre/post hooks fire.

Megatron-FSDP registers its parameter-unshard forward pre-hook on the FSDP unit modules (`TransformerLayer`, `MoETransformerLayer`, `MambaLayer` by default in `mcore_fsdp_adapter.py`), and torch FSDP2 does the same. Under either wrapper this direct `.forward` runs on sharded parameters and will fail or compute garbage, and nothing in the PR rejects the FSDP configurations.

Note that `_should_call_te_cudagraph` is False at this point (no `is_graph_capturing()`, empty `cuda_graphs`), so `layer(...)` would still execute eagerly for the TE impl; only `cuda_graph_impl == "local"` would re-route through `cudagraph_manager`.

**Suggestion:** call `layer(*args, **kwargs)` so hooks run (guarding the local-cudagraph case explicitly), or assert up front that `use_megatron_fsdp` / `use_torch_fsdp2` are disabled and add a comment explaining why `.forward` is used.

**[IMPORTANT Performance]** With `for_pipeline_prewarm=True`, `attention_is_executed` is always True, so the SBHD branch below always builds the synthetic `attention_mask`: a `(seq_length/cp) x seq_length` fp32 tensor created on CPU, moved to GPU, then tiled by micro-batch size.

`create_attention_mask_in_dataloader` defaults to True, so this is the common case. At the 64K sequence lengths the prewarm targets that is ~16 GB of host fp32 plus ~4 GB of device bool per microbatch, before the first iteration runs. The CUDA-graph capture path had the same code, but the prewarm now reaches it for every long-sequence PP run that is not using a packing scheduler.

**Suggestion:** build the mask directly on device as bool, e.g.
```python
~torch.tril(torch.ones((slen_per_cp, seq_length), dtype=torch.bool, device=device))
```
and skip it entirely when `attn_mask_type` is causal and the attention backend ignores the explicit mask.

**Prewarm THD metadata should alias Q/K the way real batches do (interaction with `dev`)**

With `for_pipeline_prewarm=True`, the four assignments right after this block (L1278-1281, just outside the diff, so no `suggestion` block) give `cu_seqlens_kv`, `cu_seqlens_q_padded` and `cu_seqlens_kv_padded` each their own `clone()`. Real self-attention batches share one tensor between Q and KV, and one between the two `*_padded` fields:

- `megatron/core/datasets/data_schedule.py:840-845` at `dev`, and likewise `get_thd_batch_on_this_cp_rank` (`megatron/core/utils.py:2881-2886` at `dev`).
- `packed_seq_params.py:695-701` at `dev` keeps that alias on purpose when it transforms the metadata.

**Why it matters.** Since #6206, the cuDNN DSA indexer uses its general packed-THD scorer only when it can prove, without a device sync, that the Q and K boundaries match. For CUDA tensors that means the same tensor or the same view (`_packed_thd_kernel_applicable`, `experimental_attention_variant/dsa_cudnn_kernels.py:849-867` at `dev`; `_get_packed_thd_metadata`, `:189-212`, supplies `cu_seqlens_q_padded` and `cu_seqlens_kv_padded` to it). With the clones, the multi-entry synthetic pack (`[0, max_T, max_T, ...]`) resolves to `UNFUSED_BOUNDS` ("packed THD without compatible cu_seqlens metadata", `dsa_scoring_plan.py:155-163` at `dev`) instead of `PACKED_THD_GENERAL`:

- **Prewarm warms a different kernel.** It runs the unfused per-head fallback scorer, while real batches, which alias, use the cuDNN general packed-THD indexer. That kernel's first call, and any one-time setup it does, moves into the first training step. Avoiding that is the point of prewarm. We haven't measured how much it costs.
- **A misleading warning.** `report_unfused_scoring_once` (`dsa_scoring_plan.py:184-206` at `dev`) logs "DSA indexer scoring falls back to the unfused per-head loop ..." on every rank by design, but no training step takes that path. It also uses up the once-per-reason slot, so a later real fallback with the same reason would not be reported.

In our runs with this PR, every rank logs that warning exactly once, during prewarm, and the training steps take the fused path. I also checked the gate on CPU with this PR merged onto `dev`: the current prewarm inputs resolve to `UNFUSED_BOUNDS`, and the inputs from the change below resolve to `PACKED_THD_GENERAL`. A single-sequence synthetic pack (`thd_max_packed_sequences` unset or 1) usually takes the single-sequence segment scorer, which does not use this metadata.

**Numerics:** no change. Prewarm throws its results away: grads are zeroed, and buffers, FP8 state, RNG, the DSA tracker and the loss scales are restored (`parallel_prewarm.py:257` and `:287-307`). The change only affects which tensors the synthetic sample shares; CUDA Graph capture inputs stay as they are.

**Suggestion:** replace L1278-1281 so that only prewarm aliases, and capture keeps four independent buffers:

```python
                static_inputs["cu_seqlens_q"] = cu_seqlens
                if for_pipeline_prewarm:
                    # Match real self-attention batches, which share one tensor between Q and KV
                    # (and one padded tensor between both *_padded). Fused DSA scoring relies on
                    # that aliasing to recognize self-attention without a device sync.
                    padded_cu_seqlens = cu_seqlens.clone()
                    static_inputs["cu_seqlens_kv"] = cu_seqlens
                    static_inputs["cu_seqlens_q_padded"] = padded_cu_seqlens
                    static_inputs["cu_seqlens_kv_padded"] = padded_cu_seqlens
                else:
                    # CUDA Graph capture keeps independent static buffers.
                    static_inputs["cu_seqlens_kv"] = cu_seqlens.clone()
                    static_inputs["cu_seqlens_q_padded"] = cu_seqlens.clone()
                    static_inputs["cu_seqlens_kv_padded"] = cu_seqlens.clone()
```

After the rebase, `dev`'s `_uses_graph_dynamic_dsa_route()` block stays right after this.

```python
from types import SimpleNamespace

import torch

from megatron.core.transformer.enums import AttnMaskType
from megatron.core.transformer.transformer_layer import TransformerLayer


def _make_thd_transformer_layer(*, cuda_graph_impl):
    layer = object.__new__(TransformerLayer)
    torch.nn.Module.__init__(layer)
    layer.config = SimpleNamespace(
        bf16=True,
        context_parallel_size=1,
        create_attention_mask_in_dataloader=False,
        cuda_graph_impl=cuda_graph_impl,
        cuda_graph_modules=[],
        fp16=False,
        hidden_size=4,
        max_seqlen_per_dp_cp_rank=4,
        sequence_packing_scheduler=object(),
        sequence_parallel=False,
        tensor_model_parallel_size=1,
        thd_max_packed_sequences=2,
    )
    layer.self_attention = SimpleNamespace(attn_mask_type=AttnMaskType.causal)
    layer.is_moe_layer = False
    return layer


def test_pipeline_prewarm_aliases_thd_qk_metadata_only_for_prewarm(monkeypatch):
    monkeypatch.setattr(torch.cuda, 'current_device', lambda: torch.device('cpu'))

    prewarm_inputs = _make_thd_transformer_layer(cuda_graph_impl='none').get_layer_static_inputs(
        4, 1, for_pipeline_prewarm=True
    )
    assert prewarm_inputs['cu_seqlens_q'] is prewarm_inputs['cu_seqlens_kv']
    assert prewarm_inputs['cu_seqlens_q_padded'] is prewarm_inputs['cu_seqlens_kv_padded']
    assert prewarm_inputs['cu_seqlens_q'] is not prewarm_inputs['cu_seqlens_q_padded']

    graph_inputs = _make_thd_transformer_layer(cuda_graph_impl='local').get_layer_static_inputs(
        4, 1, for_pipeline_prewarm=False
    )
    qk_metadata = [
        graph_inputs['cu_seqlens_q'],
        graph_inputs['cu_seqlens_kv'],
        graph_inputs['cu_seqlens_q_padded'],
        graph_inputs['cu_seqlens_kv_padded'],
    ]
    assert len({tensor.data_ptr() for tensor in qk_metadata}) == 4
```
