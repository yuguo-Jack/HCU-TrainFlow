# perf(moe): batch-invariant sigmoid routing with the Triton top-k kernel

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8602) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Batch-invariant mode now routes sigmoid MoE layers with the Triton sigmoid top-k kernel from #8296, in both training and inference. The trainer and the engine call the same kernel, so their routing stays bitwise identical, and BI decode is 0.57 to 0.62 ms per step faster on Nemotron-3-Nano.

**Depends on #8296.** This branch is main plus #8296's three commits plus one commit. Only the last commit, "perf(moe): batch-invariant sigmoid routing with the Triton top-k kernel", belongs to this PR.

## Details

Before this change, `batch_invariant_mode` routed with the uncompiled reference: sigmoid, a sorted aten `topk`, a gather and a normalize. It did this in the training router and in `InferenceTopKRouter`, so the two sides agreed. #8296 added a faster fused kernel for inference, but kept it disabled under BI. Its probabilities differ from the reference in the last bits, so using it in the engine alone would break trainer/engine parity.

The kernel computes every row independently. With a launch configuration that does not depend on the number of tokens, it is batch invariant. This PR uses it on both sides:

- `topk_routing_with_score_function` (`moe_utils.py`):
  - Under `batch_invariant_mode`, it runs the kernel when the configuration is supported: sigmoid scores, an expert bias, fp32 logits, no group-limited routing, router replay, precomputed indices, quantile balancing or TE fused router, and a supported shape.
  - The training router (`TopKRouter.routing`) and the BI inference path (`InferenceTopKRouter._forward`) already call this function. They now reach the same kernel through one code path, with no flag or environment variable.
  - Unsupported configurations keep the reference path on both sides.
- `_BatchInvariantSigmoidTopK` (autograd function):
  - The forward returns the kernel's probabilities.
  - The backward differentiates the reference formula `s_j / (sum_i s_i + 1e-20) * scaling_factor` (with `s = sigmoid(logits)`) at the kernel's indices.
  - The expert bias only selects experts and gets no gradient, as in the reference.
  - Without autograd (inference, log-prob passes under `no_grad`), the kernel is called directly.
- `sigmoid_topk_routing(..., batch_invariant=True)`: keeps four warps for top-k of eight or more. That is the only case where the default launch changed with the token count (one warp from 1024 tokens up). For top-k below eight the launch is unchanged, so the BI and non-BI arms run the same kernel launch.
- The opt-in `inference_moe_triton_router` path in `InferenceTopKRouter` is unchanged and still not taken under BI. The docstrings now describe the BI behavior.
- The determinism manifest registers `sigmoid_topk.py` as its own entry, since it is now on the training path under BI.

## Results

GB200, Nemotron-3-Nano 30B-A3B (128 experts, top-6, sigmoid with expert bias, fp32 router). The end-to-end and decode numbers were measured with this change on a tree that also carries #8559, #8306, #8320 and a BI decode-graph fix. The comparison arms differ only in this change.

**Trainer/engine parity, end to end.** Setup: Megatron's native RL loop, GRPO on GSM8K, trainer TP2/SP + EP8, separate `inference_optimized` engine at TP2 + EP8, NCCL refit after every step, BI mode, three iterations.
- With this change: all 501,240 generated tokens have the same log-prob in the engine and in the trainer, bitwise. Max |difference| and KL are both 0.
- Negative control: a scratch run that uses the kernel only inside the engine, with the trainer kept on the reference router. In that run 444,511 of 477,703 tokens (93.1%) differ, by up to 1.59 nats (KL 5e-4 to 7e-4).

**Engine batch invariance (EP4, MXFP8).** Batch 1 vs batch 24: 0 of 2,796 prompt and 0 of 529 generated log-probs differ. Decode vs prefill: 0 of 1,024 differ.

**Decode step time.** EP4 on one node: TP2/SP x DP2, MXFP8, FA4, CUDA graphs, torch grouped GEMM, `--batch-invariant-collective ordered`. Each value is the median ms per steady decode step, averaged over two repeats; all arms ran in the same job:

| batch | context | BI, reference router | BI, this PR | non-BI (`--inference-moe-triton-router`) |
|---|---|---|---|---|
| 32 | 1k | 8.56 | 7.97 | 7.26 |
| 8 | 1k | 7.44 | 6.86 | 5.93 |
| 1 | 1k | 6.49 | 5.89 | 4.68 |
| 8 | 8k | 7.77 | 7.15 | 5.95 |
| 1 | 8k | 6.83 | 6.25 | 4.70 |

The BI overhead over non-BI drops from 1.30 / 1.51 / 1.80 ms to 0.71 / 0.93 / 1.20 ms at batch 32 / 8 / 1 (1k context). BI and non-BI now share the router kernel, so the router adds no BI cost.

**Training-side router cost.** Measured with a standalone prototype of the same autograd function, per call, N = 4,096 to 16,384 tokens:
- Forward: 0.11 to 0.15 ms, vs 0.25 to 0.31 ms for the reference.
- Forward + backward: 0.62 to 0.72 ms, vs 0.57 to 0.68 ms for the reference.

## Tests

- New `tests/unit_tests/transformer/moe/test_moe_batch_invariant_router.py`, for Nano (128 experts, top-6) and a 512-expert top-22 configuration:
  - Each row's probabilities and indices are bitwise the same alone and inside batches of up to 4096 tokens. This covers the top-k of eight or more launch change.
  - Under BI, `topk_routing_with_score_function` returns the kernel's values, in both the dense and the `[tokens, experts]` map formats.
  - The differentiable training path returns the same bits as the inference path.
  - Gradients match autograd through the reference formula (rtol 1e-5).
  - Unsupported configurations (bf16 logits, no expert bias, group-limited routing, top-1) and non-BI mode keep the reference routing.
  - `TopKRouter` in training and `InferenceTopKRouter` under `InferenceMode` with shared weights produce bitwise identical routing, and the training router backpropagates.
- `tests/unit_tests/inference/test_sigmoid_topk.py`: the BI test now checks that the inference router under BI returns the batch-invariant kernel's output, and not the opt-in or compiled path.

### Keep global-batch quantile balancing on one BI routing implementation

**Failure.** With BI enabled, global-batch quantile balancing, sigmoid scores, fp32 logits, 128 experts/top-6 and fusion disabled, the original checkpoint forward now uses Triton while recomputation uses the reference router. [TopKRouter.quantile_balancing](https://github.com/NVIDIA/Megatron-LM/blob/309e345ee10da72d55ea32d74569f11a4f72f3ec/megatron/core/transformer/moe/router.py#L457-L473) supplies histogram arguments only during unfrozen, gradient-enabled training. Consequently, `use_quantile_balancing` is false during the no-grad forward and the [new fast-path guard](https://github.com/NVIDIA/Megatron-LM/blob/309e345ee10da72d55ea32d74569f11a4f72f3ec/megatron/core/transformer/moe/moe_utils.py#L987-L1004) admits it. Recomputation supplies the histogram and bypasses Triton. [BI inference](https://github.com/NVIDIA/Megatron-LM/blob/309e345ee10da72d55ea32d74569f11a4f72f3ec/megatron/core/transformer/moe/router.py#L1498-L1529) also supplies no histogram, creating the same split between training and inference.

These are different numerical implementations: the [kernel](https://github.com/NVIDIA/Megatron-LM/blob/309e345ee10da72d55ea32d74569f11a4f72f3ec/megatron/core/inference/moe/sigmoid_topk.py#L78-L141) uses its own sigmoid and normalization order, whereas [QB routing](https://github.com/NVIDIA/Megatron-LM/blob/309e345ee10da72d55ea32d74569f11a4f72f3ec/megatron/core/transformer/moe/moe_utils.py#L1072-L1106) selects sorted top-(k+1) and normalizes eagerly. They are not bitwise interchangeable. Changing histogram accumulation must not change the probability implementation between forward/recomputation or trainer/engine. The base used the reference implementation throughout these BI cases.

**Correction.** Separate kernel eligibility from histogram accumulation. Exclude global-batch QB in both router callers, without supplying histogram buffers during passes that must not update them. The following proposed patch appends a defaulted eligibility argument, preserving existing positional callers, including the compiled-reference tests. Targets: [shared helper](https://github.com/NVIDIA/Megatron-LM/blob/309e345ee10da72d55ea32d74569f11a4f72f3ec/megatron/core/transformer/moe/moe_utils.py#L852-L1004), [global-QB caller](https://github.com/NVIDIA/Megatron-LM/blob/309e345ee10da72d55ea32d74569f11a4f72f3ec/megatron/core/transformer/moe/router.py#L463-L473), [compiled wrapper](https://github.com/NVIDIA/Megatron-LM/blob/309e345ee10da72d55ea32d74569f11a4f72f3ec/megatron/core/transformer/moe/router.py#L1417-L1446), and [inference caller](https://github.com/NVIDIA/Megatron-LM/blob/309e345ee10da72d55ea32d74569f11a4f72f3ec/megatron/core/transformer/moe/router.py#L1516-L1529).
