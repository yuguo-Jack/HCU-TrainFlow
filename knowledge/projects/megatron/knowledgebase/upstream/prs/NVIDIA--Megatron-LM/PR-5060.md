# use param_group_name as the canonical identifier for param groups

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/5060) · state: open · merged: False

## Original PR description

 # What does this PR do ?

  Make optimizer param-group identity stable under µP — where multiple
  groups intentionally share `wd_mult` / `lr_mult` but have different
  LR schedules.

  ## Why

  Group identity used to be the tuple `(wd_mult, lr_mult, is_expert_parallel, is_decoupled_lr)`.

  Under µP, per-region LR differences are expressed via `max_lr` / `min_lr` /
  `init_lr` (the schedule), not via `lr_mult` — and `wd` is typically held
  the same across regions. So semantically distinct groups (e.g. embedding /
  hidden / output / layernorm) all collapse to the same identifier:

  | group | wd_mult | lr_mult | is_ep | is_decoupled_lr | max_lr |
  |---|---|---|---|---|---|
  | hidden | 1.0 | 1.0 | F | F | 3e-4 |
  | embedding | 1.0 | 1.0 | F | F | 6e-4 |
  | output | 1.0 | 1.0 | F | F | 1e-4 |

  → identifier tuple collides → checkpoint reload matches the wrong group
  (or fails).

  ## What

  Switch identity to a stable **name** computed from the matched
  `ParamKey`s, not from override values:

  - New `ParamKey.canonical_name()` — derived from `name` / `attr` /
    `predicate` / `with_name_predicate`, independent of any numeric
    override.
  - `_get_param_groups` records the matched `ParamKey.canonical_name()`s
    per group, all-gathers across ranks (PP/EP shards each see only a
    subset of params), and writes `param_group_name` on the group.
  - `param_group_identifier_keys = ('param_group_name', 'is_expert_parallel')`.

  Groups remain distinguishable regardless of how identical their numeric
  overrides happen to be.
