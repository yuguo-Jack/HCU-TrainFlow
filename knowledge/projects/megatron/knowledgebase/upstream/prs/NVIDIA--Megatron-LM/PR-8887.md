# What does this PR do?

Connect ordinary native Energon loaders to heterogeneous MIMO pretraining through
an opt-in `--dataset-provider energon` route. The existing mock default and
conventional supervised entrypoints remain unchanged.

An application supplies a fresh TaskEncoder factory and a stateless encoder-batch
merger through `--energon-data-config MODULE:FUNCTION`. The bridge owns explicit
sample-lane placement, native loader construction, language-authoritative state,
ordered encoder fanout and cleanup. The application owns cooking, tokenization,
packing policy, supervision and modality-specific layouts. No data-format or
vision-encoder implementation is added.

Language batches retain their labels, loss masks and optional packed/model
metadata. Encoder replicas consume the corresponding consecutive language lanes;
the application merger assembles their modality inputs without guessing tensor
concatenation axes. Normal pretrain tokenizer setup is reused.

## Dependency and scope

`pyproject.toml` and `uv.lock` are unchanged. This uses the existing locked
Energon 7.4.1 API, with no native source patches, additional package requirements
or dependency on an unmerged feature stack. This draft supersedes #8859 with a
bridge-only implementation based directly on main.

Initial support is training-only, disjoint single-encoder TP/PP/CP1 and no GTP
rematerialization. Microbatch sizes above one and divisible unequal encoder/
language DP are supported; language-only mode is also supported. Unequal DP
requires positive workers because the native zero-worker seed cache is shared
between in-process lane replicas. Encoder prefetch and encoder DDP overlap are
rejected. The generic application interface is independent of these topology
qualification limits.

Resume restores native rank-local state before iteration and validates the
fixed loader/application configuration. Encoder replicas restore matching
language files and save no competing cursor. No rescaling or edited-recipe
migration is added. The pinned native version predates a public loader close
API, so cleanup includes a small persistent-worker compatibility fallback.

## Validation

21 focused CPU tests passed on Linux/Python 3.12 with the unmodified locked
Energon 7.4.1 wheel. The suite uses the real native loaders, including persistent
workers and serialized fresh-process continuation, without model initialization
or GPU fixtures. Protected runtime package versions and representative binaries
were unchanged. CPU pin-memory and native fork warnings were reported.

The checkpoint cases compose the actual external-dataloader save hook with
the heterogeneous data entrypoint, using instrumented process-group selection
and barriers. They check canonical per-lane files, encoder non-writing
behavior, model-resolved iteration and initial-weight versus resume handling.

Changed-file Black/isort/Ruff, Python syntax and whitespace checks pass. Existing
mock defaults and eight mock-data definitions are preserved, and the conventional
data provider, batch-transfer and loss paths are unchanged. The repository-wide
GPU/distributed suite and full autoformatter CI have not been run.

The focused tests use tiny generated datasets through real native loaders.
They cover two task representations, within-document masking, arbitrary modality
names/layouts, empty modalities, unequal lanes, one/two-worker randomized
processing, serialized fresh-process replay of language and encoder continuation,
failure cleanup, and configuration rejection. They do not qualify distributed
model training or broader TP/PP/CP/worker-resize configurations.

## Code provenance

New application-integration code uses the public Megatron-LM MIMO interfaces and
native Energon APIs. No external implementation is copied. Existing copyright
notices are retained.
