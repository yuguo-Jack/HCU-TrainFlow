# What does this PR do?

Routes packed micro-batches per sample in the GPTModel EP-overlap MoE slots, the same way the eager path does.

With packed sequences, `micro_batch_size > 1` and `--overlap-moe-expert-parallel-comm`, `pretrain_gpt.py` sets `PackedSeqParams.tokens_per_sample` and the hidden states arrive flattened to `[mbs*s, 1, h]`. Eager `TransformerLayer._forward_mlp` calls `_maybe_unflatten_for_moe` after the pre-MLP norm to get `[s, mbs, h]` back, and `_maybe_reflatten_from_moe` after the MLP. The overlap callables in `megatron/core/models/gpt/fine_grained_callables.py` skipped both. Shared experts, `route` and `preprocess` saw the flat tensor, so with `seq_aux_loss` the router treated the whole micro-batch as one sequence and the gradients behind the aux loss stopped matching eager.

Changes:

- `submodule_pre_dispatch_forward` unflattens the pre-MLP norm output and the padding mask before shared experts, `route` and `preprocess`. The micro-batch size goes into `node.layer_state`, since another microbatch can run between the two slots.
- `submodule_combine_forward` flattens the output back after `postprocess`, before the residual add.
- When the batch was unflattened, the combine slot skips the fused shared-expert + residual add. That kernel needs all three tensors in one shape, and the residual is still flat. The shared expert is added in `[s, mbs, h]` inside `postprocess` and the sum is flattened back, which is what eager does. Unpacked batches still take the fused kernel.
- The TE CUDA graph replay branch is unchanged. The graphed router routes the flat tensor, and eager TE graph capture does the same: `_te_cuda_graph_capture` calls `_forward_mlp` without `packed_seq_params`. A graphed attention asserts `packed_seq_params is None`. Overlap and eager already agree there; the gap is in graph capture itself and is out of scope.

This is the GPT counterpart of the HybridModel fix in #4942, which @janEbert raised in review there. It was kept out of #4942 because it touches GPT code on main.

## Known limitation (pre-existing, unchanged)

`_maybe_unflatten_for_moe` infers `mbs` from the rank-local token count, while `tokens_per_sample` is the global sequence length. Under sequence parallelism or CP the local count is divided by TP or CP, so the inferred `mbs` is wrong. Eager has the same behavior. This PR keeps the overlap path identical to eager instead of changing both.

## Tests

- `tests/unit_tests/models/test_gpt_fine_grained_callables.py` (new, CPU): drives the GPT MoE slot callables with a stub layer. It checks that shared experts, `route` and `preprocess` get `[s, mbs, h]` and the `[mbs, s]` padding mask, that the shared expert joins before the reflatten, and that the output comes back flat.
- `tests/unit_tests/a2a_overlap/test_schedule_layer_1f1b.py::TestA2AOverlap::test_transformer_layer_overlap_packed_moe_routes_per_sample` (new, GPU, EP=4): an MoE-only GPT layer with a shared expert, `seq_aux_loss`, `moe_aux_loss_coeff=1.0` and mbs=2 × 512 tokens, with and without a padding mask. It compares overlap against eager bit for bit on outputs and every parameter gradient, router weight included, over two microbatches.
  - The layer has no attention (`_NoAttention`, an `IdentityOp` with a no-op `backward_dw`), because the unfused test attention rejects `packed_seq_params`. The bug sits entirely in the MoE slots.
  - The two capture helpers take optional `packed_seq_params` and `padding_mask`. Existing callers are unchanged.

Ran on draco against main at a29652351 in the `fw-final-x86` pipe.50600619 image, 4 GPUs:

- main plus the new tests:
  - Both GPU cases fail. Forward outputs still match bit for bit. The first gradient that differs is `pre_mlp_layernorm.weight`, upstream of the router aux loss.
  - The CPU test fails because shared experts get `[6, 1, 4]` instead of `[3, 2, 4]`.
- This branch: all three new cases pass.
- The rest of `test_schedule_layer_1f1b.py` and `TestA2AOverlapPaddingMask` (TP 1/2/4) give the same results on main and on this branch. The four fp8 cases fail on both because these GPUs are below sm89. TP=8 did not run, since it needs 8 GPUs.
