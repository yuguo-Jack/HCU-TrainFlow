# What does this PR do?
Reduce sigmoid MoE inference routing overhead for Nemotron Nano, Super, and Ultra while preserving bit-exact expert indices and FP32 probabilities relative to the original compiled router.

:warning: For major changes (either in lines of code or in its impact), please make sure to first share a design doc with the team. If you're unsure what's the best way to do so, contact @NVIDIA/mcore-oncall.

## Implementation

- For small top-k, including Nano's 128 experts / top-6 configuration, fuse sigmoid, expert selection, normalization, and scaling into one kernel
- For larger top-k, including Super/Ultra's 512 experts / top-22 configuration, use parallel expert selection while retaining the original compiled sigmoid and probability computation
- Tune launch configurations for small decode batches and larger prefill batches
- Preserve existing fallback behavior for unsupported configurations and environments

For larger top-k, a scoped runtime dispatch mode replaces only aten.topk. The original compiled graph, cache lookup, and normalization kernels remain unchanged. This preserves the reference reduction order, including when reusing an existing compiler cache

The optimization requires Triton tl.topk and PyTorch's private TorchDispatchMode.ignore_compile_internals hook for the large-top-k path. When these capabilities are unavailable, routing retains the original compiled implementation.

## Performance

End-to-end batch generation speedup against main `db3a6cd8a` (candidate `3014eea22`):

| Model | BS16 speedup | BS32 speedup |
|---|---:|---:|
| Nemotron Nano | 1.053x | 1.030x |
| Nemotron Super | 1.031x | 1.016x |
| Nemotron Ultra | 1.015x | 1.012x |

Measurement setup:

- Two nodes, 8 NVIDIA GB300 GPUs, TP8 / EP8 / ETP1; official BF16 checkpoints converted to Megatron Core, FP32 router, FA4, decode CUDA Graphs, NVLS dispatcher; batch-invariant mode and prefix caching disabled
- 16 or 32 requests with 32–33 prompt tokens and exactly 128 greedy output tokens each
- Three independent allocations per model. Each runs four fresh processes per batch size (baseline → candidate → candidate → baseline at BS16, reversed at BS32) with five timed generations per process
- Speedup = baseline / candidate latency, using the mean of the two per-process medians; the table shows the geometric mean of the three allocation ratios and a 95% t interval on the log ratios. All samples are retained
- Triton autotune selection is pinned for both versions (`--triton-autotune-mode pinned`), so fresh processes generate comparable tokens. Generated tokens were identical between baseline and candidate in every allocation
- Timing starts after request enqueue and ends when all requests finish (prefill and decode). Model loading, warmup and tokenization are excluded

## Validation

All tested routing comparisons require identical expert indices and identical FP32 probability bits. No numerical tolerances were relaxed

- 87 targeted tests passed on each of 8 ranks
- 120 TP8 router cases passed, covering Nano, Super, and Ultra dimensions with 2, 32, 256, 512, and 8192 tokens per rank
- 292 production-path comparisons passed with both reused and fresh compiler caches, including 36 CUDA Graph replay checks with updated inputs
- 3,552 candidate router comparisons using real checkpoint weights and activations passed bit-exact comparison
- Generated tokens matched across all ranks, runs, and versions for all three models

Tests also cover tied scores, strided expert bias, fallback configurations, gradient-enabled execution, and preservation of the batch-invariant path.

Bit-exact replay tests were added or updated, and the kernel module is registered in the determinism manifest.

After rebasing onto main `db3a6cd8a`, the router, determinism replay and manifest tests (362 per rank) pass on each of 4 GB300 ranks, and the end-to-end runs below generated the same tokens as main in every allocation.

Validation used PyTorch 2.12.1+cu130 and Triton 3.7.1 on GB300. Checkpoint comparisons validate the original and optimized Megatron Core paths; full Hugging Face-versus-Megatron forward parity was not tested.
