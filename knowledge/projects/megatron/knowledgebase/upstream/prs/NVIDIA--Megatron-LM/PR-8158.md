## Original PR description

# build(rl): ship the megatron.rl packing modules in the wheel

## What this PR does

NeMo RL imports the shared-prefix packing modules from `megatron.rl` (added in
P1). This PR ships them in built wheels and makes non-RL training stop
importing the RL runtime.

Depends on P1.

## Changes

- `pyproject.toml` `py-modules`: built wheels include the `shared_prefix_*`
  modules and `tree_layout` (torch and the standard library only), the lazy
  package `__init__`, and `generation_api`.
  - `generation_api` backs the lazy `megatron.rl.Request` exports. It needs
    pydantic, which is not a declared dependency.
  - The rest of the RL runtime (`rl_utils`, agents, inference, server) needs
    undeclared dependencies and stays out of the wheel.
- Editable installs now map the whole `megatron/rl` directory. Before, an
  editable install did not map `megatron.rl`; it was importable only from the
  repository root. Because of that, `megatron/training/training.py` now
  imports the `megatron.rl` training hooks only for RL runs.
- `.github/workflows/install-test.yml`: the pip job installs a built wheel. A
  new step then imports every shipped packing module (every `py-module` except
  `generation_api`) from the installed package, outside the checkout, and
  checks that `megatron.rl.rl_utils` is not installed. It uses
  `$GITHUB_WORKSPACE` and `$RUNNER_TEMP` because the job runs in a container.
- `docker/Dockerfile.ci.dev`, `docker/Dockerfile.ci.lts` and the image build
  inputs (`.github/workflows/_build_ci_container.yml`,
  `populate-build-cache.yml`): the CI images install an editable skeleton of
  the repository, and setuptools refuses a listed `py-module` whose package
  directory is missing (`package directory 'megatron/rl' does not exist`).
  The skeleton now includes `megatron/rl/__init__.py`. This also affected
  #7914 before the split.
- `.pre-commit-config.yaml`, `tools/autoformat.sh`: black, isort, pylint and
  ruff (through `tools/autoformat.sh`) now cover the `shared_prefix_*` and
  `tree_layout` modules. `generation_api.py` and `__init__.py` stay outside
  these globs.

## Tests

```bash
python -m pytest tests/unit_tests/test_megatron_rl_wheel.py tests/unit_tests/test_training.py
```

- `tests/unit_tests/test_megatron_rl_wheel.py` checks that `py-modules` lists
  exactly the packing modules plus `generation_api`. P1's API-contract test
  imports every packing module with undeclared dependencies blocked.
- `tests/unit_tests/test_training.py::test_megatron_rl_is_imported_only_for_rl_runs`
  checks that importing the training loop does not load the RL runtime.

Result on one GB200 node (torch 2.11, Transformer Engine 2.15, mamba-ssm 2.3.2.post1, causal-conv1d 1.6.2.post1, flash-attn 2.8.1): 16 passed (`test_megatron_rl_wheel.py`, `test_training.py`). A wheel built from this branch contains exactly `megatron/rl/__init__.py`, `generation_api.py`, the seven `shared_prefix_*` modules and `tree_layout.py`; the new CI step imports the eight packing modules from it outside the checkout, and fails with `ModuleNotFoundError` when a shipped module imports an unshipped one (checked by injecting `import megatron.rl.logging`). The CI image's editable skeleton install was reproduced: it fails without `megatron/rl/__init__.py` and succeeds with it. This branch alone on top of main also ran the surrounding regression suites (routers, attention, MTP, Mamba, training, RL) on one and four GPUs. Every failure in those runs also occurs on main in the same container: tests that need more ranks than the run had, and missing APEX extensions.

## Shared-prefix stack

This PR is one of seven that #7914 was split into; #7914 itself is now P6, the
HybridModel integration. Each one needs fewer CODEOWNERS groups and can be
reviewed on its own. Shared-prefix
execution stores a prompt once per star (by default up to 16 completions of the
same group)
and runs those completions against it, instead of repeating the prompt in every
packed row.

| PR | Branch | Reviewer groups | Depends on |
|---|---|---|---|
| P1 #8152 RL packing library | `shared-prefix/p1-rl-packing` | reinforcement-learning | — |
| P2 #8153 MoE multiplicities and recompute context | `shared-prefix/p2-moe-multiplicities` | core, mixture-of-experts | — |
| P3 #8155 MTP loss groups | `shared-prefix/p3-mtp-loss-groups` | core, transformer | — |
| P4 #8156 forest attention and layout | `shared-prefix/p4-forest-attention` | core, transformer | — |
| P5 #8157 Mamba state fork | `shared-prefix/p5-mamba-state-fork` | core, hybrid-model | P4 |
| P6 #7914 HybridModel integration | `shared-prefix/hybrid-kernels-20261006` | core, hybrid-model | P1, P2, P3, P5 |
| P7 #8158 RL packaging | `shared-prefix/p7-rl-packaging` | ci, training | P1 |

P1 to P4 can merge in any order. A dependent branch carries its dependencies'
commits until they merge; review only its last commit.

Without a caller, P2 to P5 do not change existing numerics. Two P2 changes do
apply to every caller, and both keep results unchanged:

- recomputation through `tensor_parallel.checkpoint` and
  `CheckpointWithoutOutput` restores the forward pass's `contextvars` context
  (`te_checkpoint` is unchanged);
- the router GEMM backward skips gradients nobody requested.

P1 changes `megatron.rl` import-time behavior (lazy request types, lazy log
file). P6 is the first PR that wires the feature into a model.
