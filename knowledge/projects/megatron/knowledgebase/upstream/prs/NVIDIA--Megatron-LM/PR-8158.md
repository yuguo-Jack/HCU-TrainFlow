## Original PR description

# build(rl): ship the megatron.rl packing modules in the wheel

## What this PR does

NeMo RL imports the shared-prefix packing modules from `megatron.rl` (added in
#8152). This PR ships them in built wheels. It does not change
`megatron/training/training.py`. Main #4264 already removed that file's
`megatron.rl` import. A new test keeps non-RL training from loading the RL
runtime (`rl_utils`, agents, inference, server).

Depends on #8152. This branch carries the current #8152 commits by merge.
`git diff shared-prefix/p1-rl-packing shared-prefix/p7-rl-packaging` shows
only this PR's changes.

## Changes

- `pyproject.toml` `py-modules`: built wheels include the `shared_prefix_*`
  modules and `tree_layout` (torch and the standard library only), the lazy
  package `__init__`, and `generation_api`.
  - `generation_api` backs the lazy `megatron.rl.Request` exports. It needs
    pydantic, which is not a declared dependency.
  - The rest of the RL runtime (`rl_utils`, agents, inference, server) needs
    undeclared dependencies and stays out of the wheel.
- Editable installs now map the whole `megatron/rl` directory. Before, an
  editable install did not map `megatron.rl`; it was importable only from the
  repository root. Non-RL training is unaffected because
  `megatron/training/training.py` no longer imports `megatron.rl` (main
  #4264). The RL entry point, `train_rl.py`, imports the RL hooks and
  registers them as callbacks.
- `.github/workflows/install-test.yml`: the pip job installs a built wheel. A
  new step then imports every shipped packing module (every `py-module` except
  `generation_api`) from the installed package, outside the checkout, and
  checks that `megatron.rl.rl_utils` is not installed. It uses
  `$GITHUB_WORKSPACE` and `$RUNNER_TEMP` because the job runs in a container.
- `docker/Dockerfile.ci.dev`, `docker/Dockerfile.ci.lts` and the image build
  inputs (`.github/workflows/_build_ci_container.yml`,
  `populate-build-cache.yml`): the CI images install an editable skeleton of
  the repository, and setuptools refuses a listed `py-module` whose package
  directory is missing (`package directory 'megatron/rl' does not exist`).
  The skeleton now includes `megatron/rl/__init__.py`. This also affected
  #7914 before the split.
- `.pre-commit-config.yaml`, `tools/autoformat.sh`: black, isort, pylint and
  ruff (through `tools/autoformat.sh`) now cover the `shared_prefix_*` and
  `tree_layout` modules. `generation_api.py` and `__init__.py` stay outside
  these globs.

## Tests

```bash
python -m pytest tests/unit_tests/test_training.py tests/unit_tests/test_megatron_rl_wheel.py tests/unit_tests/rl/shared_prefix
```

- `tests/unit_tests/test_megatron_rl_wheel.py` checks that `py-modules` lists
  exactly the packing modules plus `generation_api`.
- `tests/unit_tests/rl/shared_prefix` holds #8152's packing tests. Its
  API-contract test imports every packing module with undeclared dependencies
  blocked.
- `tests/unit_tests/test_training.py::test_training_import_does_not_load_megatron_rl`
  imports `megatron.training.training` in a fresh interpreter. It checks that
  `megatron.rl.rl_utils`, `megatron.rl.inference` and
  `megatron.rl.training_setup` are not loaded. It fails if a future
  `megatron.rl` import in `training.py` pulls the RL runtime into non-RL runs.

Result on one GB200 node (container with torch 2.11.0+cu130, Transformer Engine 2.15.0, mamba-ssm 2.3.2.post1, causal-conv1d 1.6.2.post1, flash-attn 2.8.1), for the command above with plain pytest (one process): 276 passed, with no failures or errors.

A wheel built from this branch must contain exactly `megatron/rl/__init__.py`, `generation_api.py`, the seven `shared_prefix_*` modules and `tree_layout.py`. The new CI step must import the eight packing modules from it outside the checkout. To check both, build and list the wheel, install it, and run the script of the `Check imports for the shipped megatron.rl packing modules` step from `/tmp`:

```bash
pip wheel --no-deps --no-build-isolation -w /tmp/mlm-wheel .
python -m zipfile -l /tmp/mlm-wheel/megatron_core-*.whl | grep 'megatron/rl/'
pip install --no-deps --force-reinstall /tmp/mlm-wheel/megatron_core-*.whl
```

The wheel build was not rerun in this round: the round changed neither `pyproject.toml` nor the CI step, and the eight packing modules still import only each other.

Two checks come from the previous round and were not rerun in this one, for the same reason. The CI step failed with `ModuleNotFoundError` when a shipped module imported an unshipped one (checked by injecting `import megatron.rl.logging`). The CI image's editable skeleton install failed without `megatron/rl/__init__.py` and succeeded with it.

The router, attention, MTP and Mamba suites and the rest of `tests/unit_tests/rl` were not rerun on this branch in this round, because apart from its two tests this PR changes only packaging, CI and lint configuration.

## Shared-prefix stack

#7914 was split into the eight branches below, so that each one needs fewer
CODEOWNERS groups and can be reviewed on its own. #7914 itself keeps the
HybridModel integration. Shared-prefix execution stores a prompt once per star
(by default up to 16 completions of the same group) and runs those completions
against it, instead of repeating the prompt in every packed row.

| PR | Branch | Reviewer groups | Depends on |
|---|---|---|---|
| #8152 RL packing library | `shared-prefix/p1-rl-packing` | reinforcement-learning | — |
| #8153 MoE multiplicities and recompute context | `shared-prefix/p2-moe-multiplicities` | core, mixture-of-experts, transformer | — |
| #8155 MTP loss groups | `shared-prefix/p3-mtp-loss-groups` | core, transformer | — |
| #8156 forest attention and layout | `shared-prefix/p4-forest-attention` | core, transformer | — |
| #8157 Mamba state fork | `shared-prefix/p5-mamba-state-fork` | core, hybrid-model | #8156 |
| #7914 HybridModel integration | `shared-prefix/hybrid-kernels-20261006` | core, hybrid-model | #8153, #8155, #8157 |
| #8158 RL packaging | `shared-prefix/p7-rl-packaging` | ci | #8152 |
| RL planner parity test (no PR number yet) | `shared-prefix/p8-rl-parity` | none required | #8152, #7914 |

#8152, #8153, #8155 and #8156 can merge in any order. A dependent branch
carries its dependencies' commits until they merge; review only its own
commits.

Without a caller, #8153, #8155, #8156 and #8157 do not change existing
numerics. Two #8153 changes do apply to every caller, and both keep results
unchanged:

- recomputation through `tensor_parallel.checkpoint` and
  `CheckpointWithoutOutput` restores the forward pass's `contextvars` context
  (`te_checkpoint` is unchanged);
- the router GEMM backward skips gradients nobody requested.

#8152 changes `megatron.rl` import-time behavior (lazy request types, lazy log
file). #7914 is the first PR that wires the feature into a model.
