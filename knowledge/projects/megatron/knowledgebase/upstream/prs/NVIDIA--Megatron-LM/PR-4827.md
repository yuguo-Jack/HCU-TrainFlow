# Avoid GPU0 CUDA context growth from checkpoint common-step broadcast

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/4827) · state: open · merged: False

## Original PR description

# What does this PR do ?

Avoid persistent GPU0 CUDA context growth during distributed checkpoint save by keeping the shared optimizer `common_step` value on CPU before it is inserted into checkpoint common state.

`common_step` is a scalar shared by optimizer parameter states. In some optimizer paths it may be a CUDA scalar tensor. Distributed checkpoint code can treat common checkpoint state as Python object state and broadcast it with `torch.distributed.broadcast_object_list` for validation/coordination. If rank 0's common object contains a CUDA tensor, peer ranks can deserialize that object onto the serialized device, commonly `cuda:0`, which may initialize persistent CUDA contexts on GPU0 for processes whose real local training device is not GPU0.

This change avoids putting a CUDA tensor into the common object state. Tensor steps are detached, cloned, and moved to CPU; non-tensor steps keep the previous deep-copy behavior. The runtime optimizer state remains unchanged, and the checkpoint schema still contains the same `common_step` field.

This is a small bug fix with a narrow impact: it reduces checkpoint-induced GPU0 memory side effects without changing training behavior.
