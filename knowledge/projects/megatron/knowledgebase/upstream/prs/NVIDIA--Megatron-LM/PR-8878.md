# [Inference] Apply the sliding window and output gate in static flash_decode steps

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8878) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Makes the decode steps of static `flash_decode` compute the same attention as every other path: the layer's sliding window now reaches the kernel, and the output gate (and everything else after core attention) runs.

**Bug.** In the decode phase of static flash decoding, `Attention.forward_pre_attn_and_core_attn` called `flash_decode` (FA2 `flash_attn_with_kvcache`) and returned straight away.
- **Sliding window.** `flash_decode` passed no `window_size`, and flash-attn's default is no window. A layer with `window_size=(W, 0)` attended to the whole KV cache in every decode step once the context passed W+1 tokens. Prefill, the dynamic engine (`flash_decode_and_prefill`) and `flash_decode=False` all apply the window.
- **Output gate.** The early return came before `attention_output_gate` is applied, so gated layers decoded ungated while prefill was gated. It also skipped any core-attention variant: DSA over GQA decoded with dense attention.

Both are silent. On H100 the decode output missed windowed attention by rel 0.70 and matched attention over the whole cache within 0.002; with a gate it missed the gated value by rel 1.0 and matched the ungated one within 0.002.

Affected: models with `window_size` (e.g. gpt-oss) or `attention_output_gate` decoded with `flash_decode=True` on the static engine. That is the legacy static engine (`legacy=True`, `--use-legacy-static-engine`), and the fallback `StaticInferenceEngine` takes when the dynamic engine cannot be built, which is where GPT with `flash_decode` and local CUDA graphs ends up. Static CUDA graphs require `flash_decode`.

**Fix.** The flash-decode kernel becomes a core-attention choice instead of an early exit:
- In the decode phase it replaces only what it does itself: the KV-cache update (it appends this step's key and value) and the core-attention kernel. RoPE is applied by the kernel as before. Every step after core attention, including the output gate, is shared with the other paths.
- The window comes from one helper, `_flash_attn_window_size()`, which the dynamic path now uses too: `config.window_size` on a sliding-window layer, otherwise `(-1, -1)`. Like the softcap kwarg next to it, `flash_decode` passes `window_size` to `flash_attn_with_kvcache` only on sliding-window layers (asserting flash-attn >= 2.3.0 there), so full-attention layers keep their call signature on older flash-attn builds.
- DSA over GQA (`experimental_attention_variant='dsa'` with the simplified indexer and no MLA) cannot run on this kernel, which computes dense attention over the whole cache. `TransformerConfig` now rejects it together with `flash_decode` with a `ValueError` when the config is built, instead of the model decoding with dense attention. Static DSA-GQA decode without `flash_decode` already raises (its indexer has no decode cache). For any other core-attention variant that needs extra inputs, the decode step keeps an internal assert naming the class.

No new host syncs or allocations: the decode step stays CUDA-graph safe. The `adjust_key_value` NVTX range, which the early return left open, is now closed.

**Tests.**
- `tests/unit_tests/inference/test_flash_decode.py::TestStaticFlashDecodeStep` (1 GPU, TE, flash-attn 2): one decode step through `forward_pre_attn_and_core_attn` over a seeded 12-token cache, GQA 4/2, against fp32 attention over the keys the window allows, times `sigmoid(gate)`, on the layer's own q/k/v/gate. Four cases: full or window `(4, 0)`, ungated or gated. The error bound is stated in the test: flash-attention rounds the probabilities and output to bf16 and the gated product is rounded again, at most 2⁻⁹ relative each, about 1e-2 over 13 keys (2e-3 measured on H100); the tolerance is 2e-2. On `main` the window and gate cases fail (rel 0.75 to 1.03 on H100), the full ungated case passes.
- `TestStaticFlashDecodeStep::test_windowed_gated_decode_step_with_rope_matches_reference[eager|cuda_graph]`: the windowed, gated step with RoPE, which the kernel applies to the step's query and key (the reference rotates them with the same bf16 tables). The `cuda_graph` case captures the step in a CUDA graph after an eager run and checks the replayed output, since the static engine's CUDA graphs require `flash_decode`. This is layer-level: the static engine itself is not run.
- `tests/unit_tests/transformer/test_attention_variant_dsa_gqa.py::test_transformer_config_rejects_flash_decode_with_dsa_over_gqa` (CPU): building a DSA-over-GQA config with `flash_decode=True` raises the `ValueError`. It fails without the check.
- `TestFlashDecodeSoftcapPlumbing::test_window_is_passed_only_on_window_layers` (CPU): `flash_decode` passes `window_size` on a window layer and omits it otherwise.
- None of these tests runs TE attention: the decode cases run the flash-decode kernel, and there is no prefill control. The step-3 repro's gated-prefill control is not carried over. Its miss (rel 0.0535; the tolerance was 0.02, about ten times this harness's bf16 error) was not a tolerance artifact: it is traced to a separate suspected Transformer Engine bug, P4-N2. TE 2.20.2 classifies a strided query (a view of the fused QKV output, as MHA without RoPE produces) with a separate static KV cache as `sbhd_sbhd_sbhd`, and cuDNN then reads q with dense strides. That repro's prefill control now builds GQA, whose query is contiguous, so it no longer depends on P4-N2. P4-N2 is confirmed on H100 (rel 0.10 to 0.24), open, and not fixed here.
- Determinism: `tests/unit_tests/determinism/kernels/test_runtime_cp_attention.py::test_static_flash_decode_dispatch_replays` replays the static step (window and gate) bit-exactly under side-stream contention, then checks that dropping the window changes the output, so the window reaches the kernel. It fails on `main`. It sits under the existing `attention_kernels_and_dispatch` manifest entry; `tools/check_kernel_determinism_coverage.py` passes.
- `TestFlashMLASoftcapRejected` stubs `self` with a `Mock`, so its stub now answers `_flash_attn_window_size()`.

On H100 in the CI image (`mcore_ci_dev:main`, 2026-11-02), the regression tests pass (11 cases, including the RoPE and CUDA-graph cases) and fail on `main` (8 of 11 cases). On `main`, the five window or gate decode cases miss the reference by rel 0.75 to 1.03, the replay test fails, the DSA-over-GQA config does not raise, and `flash_decode` passes no `window_size`. The full ungated case and the two softcap cases pass there. The neighbor tests (`test_attention.py`, `test_static_engine.py::TestStaticInferenceEngine`, `test_runtime_cp_attention.py::test_flash_decode_dispatch_config_softmax_scale_replays`) pass (139 cases; 2 fused-RoPE cases skip, since fused QKV RoPE does not support gated attention).
