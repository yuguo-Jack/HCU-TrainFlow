# What does this PR do?
Gives MInf the ability to snapshot the engine's live state at a token-level granularity, and also to load such a snapshot on a restart.

This feature is used for resiliency with RL setups, so that if inference has to be interrupted while there are still live requests in the engine, the engine state can be saved and restored.

For the snapshot side, `DynamicInferenceEngine.snapshot_live_requests()` returns a `LiveRequestSnapshot` dataclass. This can be called by any user of MInf.

For the resume side, the `RequestPromptPreparer` can now provide an encoded `ResumedGeneration`, which the engine reads and honors.

As a side-effect, part of the engine logic had to be refactored to avoid code duplication; `_admit_request` now handles both new requests and resumed requests.

saved image-request epoch boundaries already count the expanded image tokens, so rebasing them from the compact prompt shifts them a second time and mislabels which model version produced each token. please carry the saved prompt length through `ResumedGeneration` and test a real snapshot-and-resume round trip.

an example flow:

- an image prompt has three compact tokens and expands to five model-input tokens.
- after three generated tokens, its saved model-version boundaries are `[(0, 3), (6, 4)]`.
- resuming shifts position `6` to `8`, although the prompt still has five model-input tokens.
- switching to model version `9` appends boundary `(7, 9)`, leaving the positions out of order.

suggested fix:

```python
# Add beside the required ResumedGeneration fields:
saved_prompt_length: int
# Include this field in to_wire/from_wire.
# Set it when constructing a resume from a snapshot:
saved_prompt_length = len(snapshot.payload.prompt_token_ids)

# Replace the rebase call in build_resumed_record:
resumed = resumed.with_expanded_prompt(
    resumed.saved_prompt_length, len(first.prompt_tokens)
)
```

finished replay returns immediately, but `ResumedGeneration` cannot carry the saved expert-routing choices that training consumes. please preserve `routing_indices` through replay and collect them before snapshotting a stopped live request, while its cache blocks still exist.

an example flow:

- a request records which model experts processed each token and stops on `END`.
- the service snapshots it before normal completion has copied those choices from its cache blocks.
- after restart, the saved `finished=True` request returns without another model pass.
- the answer has its tokens but no routing choices for training.

suggested fix:

```python
# Add to ResumedGeneration:
routing_indices: Optional[np.ndarray] = None
# Encode/decode in to_wire/from_wire with the ndarray helpers.
# Before snapshotting a stopped live request, reconstruct its
# routing from its still-owned KV blocks and copy it to the payload.
# Populate the resume field from payload.routing_indices.
# Replace the finished branch in build_resumed_record:
if resumed.finished:
    first.routing_indices = resumed.routing_indices
    first.status = Status.COMPLETED
    return record
# Continuing requests still reconstruct routing after prefill.
```

snapshots and `ResumedGeneration` drop the per-token alternative scores requested by `top_n_logprobs`, so a continued response can attach new scores to old tokens. please save and restore both top-N score fields and reject missing or misaligned generated scores when they are requested.

an example flow:

- a caller requests two alternative scores per token, skips prompt scores, and receives scores inline.
- the service saves generated tokens `[7, 8]`, then resumes and generates token `9`.
- the merged answer contains `[7, 8, 9]`, but its alternative-score list contains only the entry for `9`.
- the chat response indexes that list from the start and attaches the entry for `9` to token `7`.

suggested fix:

```python
# Add to OffloadedRequestPayload and ResumedGeneration:
generated_top_n_logprobs: Optional[List[Dict[str, float]]] = None
prompt_top_n_logprobs: Optional[List[Dict[str, float]]] = None
# Copy both from the request; include both in to_wire/from_wire.
# In build_resumed_record before checkpointing:
if first.sampling_params.top_n_logprobs > 0:
    if (resumed.generated_top_n_logprobs is None
            or len(resumed.generated_top_n_logprobs) != len(tokens)):
        refuse("has missing or misaligned top-N log probs")
first.generated_top_n_logprobs = resumed.generated_top_n_logprobs
first.prompt_top_n_logprobs = resumed.prompt_top_n_logprobs
```
