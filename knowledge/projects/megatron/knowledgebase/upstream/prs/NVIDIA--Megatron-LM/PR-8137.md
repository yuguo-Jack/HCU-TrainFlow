# MInf: Add support for token-level snapshotting

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8137) · state: closed · merged: True

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?
Gives MInf the ability to snapshot the engine's live state at a token-level granularity, and also to load such a snapshot on a restart.

This feature is used for resiliency with RL setups, so that if inference has to be interrupted while there are still live requests in the engine, the engine state can be saved and restored.

For the snapshot side, `DynamicInferenceEngine.snapshot_live_requests()` returns a `LiveRequestSnapshot` dataclass. This can be called by any user of MInf.

For the resume side, the `RequestPromptPreparer` can now provide an encoded `ResumedGeneration`, which the engine reads and honors.

As a side-effect, part of the engine logic had to be refactored to avoid code duplication; `_admit_request` now handles both new requests and resumed requests.

saved image-request epoch boundaries already count the expanded image tokens, so rebasing them from the compact prompt shifts them a second time and mislabels which model version produced each token. please carry the saved prompt length through `ResumedGeneration` and test a real snapshot-and-resume round trip.

- an image prompt has three compact tokens and expands to five model-input tokens.
- after three generated tokens, its saved model-version boundaries are `[(0, 3), (6, 4)]`.

snapshots and `ResumedGeneration` drop the per-token alternative scores requested by `top_n_logprobs`, so a continued response can attach new scores to old tokens. please save and restore both top-N score fields and reject missing or misaligned generated scores when they are requested.
