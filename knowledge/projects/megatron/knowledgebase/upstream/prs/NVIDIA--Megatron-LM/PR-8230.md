# Fix MFSDP v2 checkpointing for expert-parallel MoE models

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8230) · state: closed · merged: True

## Original PR description

- [x] I, the PR author, have personally reviewed every line of this PR.

## What does this PR do?

Fix MFSDP v2 checkpoint save and restart for expert-parallel MoE models. After #6215, a BF16 EP=2 run trains two steps but fails at its first checkpoint with `NotImplementedError: MFSDP v2 optimizer checkpointing does not support expert parallelism yet`.

Serialize optimizer state directly under MCore's global parameter names on TE >= 2.18. For TE < 2.18, preserve the empty-shard workaround and gather missing optimizer-state keys within each parameter's own dense or expert-DP mesh. Shard filtering, placeholder reconstruction and removal, and the gradient-clearing fallback run only under explicit TE version guards. This removes the single-mesh restriction that rejected EP checkpointing while preserving older-TE compatibility.

After loading model state, refresh BF16 compute weights from the restored FP32 main weights before the first resumed forward.

Use MCore's existing global expert names and optimizer checkpoint format. The standalone `experimental/checkpoint.py` loader now always refreshes compute weights after restoring state; remove its unused `sync_model_weights` option.

EP checkpoint coverage lives in `test_checkpoint.py`, with model setup local to the test and forward/backward delegated to `mcore_training_utils.run_forward_backward_on_microbatches`. It compares five resumed losses exactly against uninterrupted training. It covers EP=1/2/4 with the precision-aware optimizer enabled and BF16 optimizer state. GPU initialization uses the normal expert-parallel RNG stream to initialize distinct experts across EP ranks. This replaces the old test expecting EP checkpointing to be rejected. The existing optimizer test helper also waits for gradient synchronization before stepping.

The script requires fresh outputs, rejects missing resume checkpoints, and checks the first process ran steps 1–2 and the resumed process loaded iteration 2 and ran only steps 3–4. Logged losses match the uninterrupted four-step run, and **all 84 model/Adam tensors and optimizer/scheduler metadata match exactly** (459 entries at step 4).
