# Preserve unsharded cyclic samples across DP changes

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/7649) · state: open · merged: False

## Original PR description

## Problem

With `cyclic` dataloading and data sharding disabled, the sampler derives its epoch length from the current DP size. When the dataset tail is not aligned to the new DP layout, resuming can repeat and skip samples.

## Fix

Use a DP-independent permutation epoch and form each global batch from a continuous permutation stream. A global batch may cross the dropped tail into the next epoch, so the resume position remains a sample offset in the same stream after a DP change. The existing sharded path is unchanged.

## Compatibility note

A pre-fix unsharded cyclic checkpoint can repeat or skip samples once when it is first resumed with this fix if `total_samples % (micro_batch_size * data_parallel_size) != 0`, even when the data-parallel size is unchanged. This is the one-time transition from the old DP-dependent stream to the new DP-independent stream; checkpoints created with this implementation resume consistently.

### Carry sample epochs into DataLoader workers

**Failure:** The new epoch-boundary seed handling works only when samples are fetched in the sampler's process. With `RandomSeedDataset(_RandomValueDataset(), seed=1234)`, 10 samples, microbatch size 2, DP size 1, global batch size 6, and `DataLoader(num_workers=1, persistent_workers=True)`, the first iterator emits 12 samples. The last two belong to permutation epoch 1, but the worker seeds them with `index + 1234`, rather than `index + 1235`.

The sampler's [`set_epoch()` call](https://github.com/NVIDIA/Megatron-LM/blob/7dfbbbcc0c354a81f488f4079df220f4e8e1a3f5/megatron/training/datasets/data_samplers.py#L447-L456) mutates the parent dataset; it does not update the worker's copy. [`RandomSeedDataset.__getitem__()`](https://github.com/NVIDIA/Megatron-LM/blob/7dfbbbcc0c354a81f488f4079df220f4e8e1a3f5/megatron/training/datasets/data_samplers.py#L331-L336) reads that copy's `curr_seed`, and the [production loader enables persistent workers](https://github.com/NVIDIA/Megatron-LM/blob/7dfbbbcc0c354a81f488f4079df220f4e8e1a3f5/megatron/training/datasets/data_samplers.py#L129-L135). The [new seed regression](https://github.com/NVIDIA/Megatron-LM/blob/7dfbbbcc0c354a81f488f4079df220f4e8e1a3f5/tests/unit_tests/data/test_data_samplers.py#L134-L164) fetches directly from the parent dataset, so it misses this path.

**Correction:** Make the permutation epoch part of each queued index for `RandomSeedDataset`, and resolve it inside the worker. The invariant is that augmentation seeds depend on the sample's permutation epoch, not when or where the sampler changes mutable state. A small suggested correction is:

At [`RandomSeedDataset.__getitem__()`](https://github.com/NVIDIA/Megatron-LM/blob/7dfbbbcc0c354a81f488f4079df220f4e8e1a3f5/megatron/training/datasets/data_samplers.py#L331-L336), replace the seed calculation, retaining the existing RNG initialization and underlying dataset access:

```python
if isinstance(idx, tuple):
    epoch, idx = idx
    seed = idx + self.base_seed + epoch
else:
    seed = idx + self.curr_seed
```

At the [final unsharded yield](https://github.com/NVIDIA/Megatron-LM/blob/7dfbbbcc0c354a81f488f4079df220f4e8e1a3f5/megatron/training/datasets/data_samplers.py#L455-L456), replace only the yield statement:

```python
if isinstance(self.dataset, RandomSeedDataset):
    yield micro_batch
else:
    yield [index for _, index in micro_batch]
```

Keep the parent `set_epoch()` calls for existing synchronous behavior and `curr_seed` observability. This suggested code was traced statically, not executed; verify it before adopting it.

**Preservation:** Ordinary datasets must still receive integer indices. The unchanged sharded branch must retain integer indices and its existing `curr_seed` behavior. The synchronous seed test must retain its exact returned index order, random values, and final `curr_seed == base_seed + 1`. Retain the [DP-change Counter comparisons](https://github.com/NVIDIA/Megatron-LM/blob/7dfbbbcc0c354a81f488f4079df220f4e8e1a3f5/tests/unit_tests/data/test_data_samplers.py#L97-L131) and the [effective batch-size assertion of 16 rather than 18](https://github.com/NVIDIA/Megatron-LM/blob/7dfbbbcc0c354a81f488f4079df220f4e8e1a3f5/tests/unit_tests/data/test_data_samplers.py#L167-L206).

**Acceptance — proposed regressions:** Fetch through a real DataLoader with the setup above and worker counts 0, 1, and 2, using persistent workers when nonzero. Assert the first 12 indices equal `randperm(10, seed=0)` followed by the first two indices of `randperm(10, seed=1)`; assert each random value matches a generator seeded with `index + 1234 + epoch`. Also recreate the loader at `consumed_samples=12`: its first six samples must equal epoch-1 permutation positions `[2:8]`, with epoch-1 seeds. For DP size 2, microbatch size 2, global batch size 4, and offset 8, rank 0 must fetch epoch-0 positions `[8:10]` and rank 1 epoch-1 positions `[0:2]`, each with the corresponding seeds.
