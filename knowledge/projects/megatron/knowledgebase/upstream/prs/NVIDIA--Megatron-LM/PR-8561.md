# [Inference] Keep the residual connection when fused TP communication falls back

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8561) · state: open · merged: False

## Original PR description

- [ ] I, the PR author, have personally reviewed every line of this PR.

# What does this PR do?

Fixes `inference_fuse_tp_communication`, which silently dropped the residual connection of every attention and MLP block whenever the fused NVLS kernel did not run. The flag-on output now equals the flag-off output on every path.

## The bug

With `inference_fuse_tp_communication=True`, `TransformerLayer` hands the residual to `InferenceRowParallelLinear` (`linear_proj`, `linear_fc2`) and skips its own bias-dropout-add whenever `InferenceMode` is active. The row-parallel layer added the residual only inside the fused NVLS reduce-scatter + add + rms-norm + all-gather kernel. Its other paths returned the bare projection:

- the `tp_size == 1` short-circuit;
- the NCCL reduce-scatter, taken when `inference_disable_triton_nvls_kernels=True`, activations are not bf16, the tensor is not NVLS-eligible, symmetric memory is missing or too small, or batch-invariant mode is on;
- the TE training path, taken in training mode while `InferenceMode` is still active.

On these paths, each block's output lost the residual stream. The NCCL fallback had a second problem: the next `InferenceLayerNormColumnParallelLinear` decided it was "fused" from a static flag and the buffer handle only. It therefore consumed the symmetric-memory buffer that no kernel had written that step, so the output depended on stale buffer contents.

Config validation accepts all of these combinations. Reproduced on H100: TP=1, TP=2 with NVLS disabled, and TP=2 in batch-invariant mode all differ from flag-off by about the norm of the residual. With NVLS disabled, pre-filling the buffer with 1.0 instead of 0.0 changes the output by up to 0.57. A configuration matrix also showed 1.6–1.9 nats of log-prob error on the TP=1 and batch-invariant rows. The fused NVLS path itself was correct.

## Root cause and fix

Three components each decided on their own whether the fused kernel would run: the row-parallel layer, the layer's skipped residual add and the next column-parallel layer.

- **One condition for handing over the residual add** (`transformer_layer.py`). The five places that hand over or skip the add now use one predicate, `_using_fused_tp_inference()`: the flag is on, `InferenceMode` is active and the layer is in eval mode. In training mode the inference linears run their TE training path, so the layer keeps its own bias-dropout-add, dropout included. `_forward_mlp` hands the residual to `linear_fc2` on every MLP branch, including `recompute_mlp`.
- **The row-parallel layer owns the residual add on every path** (`inference_layers.py`). `InferenceRowParallelLinear.forward` consumes the residual handed to it through `_set_residual`. It runs the fused kernel only when it has a residual, the next layer's norm weights and an NVLS-capable buffer. Otherwise it adds the residual to its fresh output in place, which is exactly the eval-mode bias-dropout-add the layer skipped. This also covers layers that `TransformerBlock` never configures, such as the MTP inner layer. The residual is consumed in every mode, so none is left behind for a later forward, and a residual handed over in training mode is rejected.
- **One recorded fact for the next layer's input** (`inference_layers.py`, `transformer_layer.py`, `transformer_block.py`). A small `FusedTPHandoff` object is owned by each row-parallel layer and set on every forward to say whether the fused kernel ran. `configure_fused_tp_inference` and `TransformerBlock._setup_fused_tp_communication` give it to the column-parallel layer the row-parallel layer feeds: `linear_proj` → `linear_fc1`, and layer *i* `linear_fc2` → layer *i+1* `linear_qkv`. The column-parallel layer reads symmetric memory only when the handoff says the kernel ran. Otherwise it applies its own norm and all-gather. This replaces the static `skip_norm_and_all_gather` attribute. `configure_fused_tp_inference` now takes `qkv_fused_tp_handoff` instead of `skip_qkv_norm_and_all_gather`.
- **CUDA graphs.** The handoff is Python state that is written only when the row-parallel layer's Python runs. A CUDA graph bakes in the decisions made at capture, so the record is valid while producer and consumer are replayed together or run eagerly together.
  - Within a layer this always holds: inference CUDA graphs capture whole layers or the whole block, and TE's sub-layer graphs run only in training mode.
  - Across layers, the block links layer *i*'s `linear_fc2` to layer *i+1*'s `linear_qkv` only when both layers are graphed alike (both have a `cudagraph_manager` or neither does). Otherwise that boundary uses the unfused path.
- The `inference_fuse_tp_communication` docstring states the fallback.

The fused NVLS path performs the same kernels as before. The fallback adds no allocation, host sync or per-step setup: it is an in-place add plus Python attribute writes, so it is CUDA-graph safe. No configuration is newly rejected.

## Tests

`tests/unit_tests/tensor_parallel/test_inference_layers.py` (2 GPUs; the TP=1 cases also run on 1 GPU) builds 2-layer inference-optimized GPT blocks with the flag on and off and identical weights. Each test compares outputs first (atol/rtol 2e-2, where a dropped residual gives a relative error near 1) and then checks kernel call counts:

- `test_fused_matches_unfused[tp1|tp2_nccl|tp2_batch_invariant|tp2_nvls]`: the flag-on output matches flag-off on every path. On the fallback paths the fused kernel is not called and every column-parallel layer applies its own norm. On the NVLS path the fused kernel runs in all 4 row-parallel layers, and only layer 0's `linear_qkv` applies a norm, so the fusion is still used.
- `test_output_independent_of_stale_symm_buffer[unfused|fused]`: with NVLS disabled, filling the buffer with 0.0 or 1.0 before the forward gives the same output.
- `test_fusion_is_decided_every_forward` (NVLS): a fully fused step is followed by a step where `linear_proj` fuses but `linear_fc2` falls back. The second step must match flag-off. This pins the per-forward handoff reset.
- `test_recompute_mlp_keeps_residual[tp1|tp2_nvls]`, `test_unconfigured_layer_keeps_residual[tp1|tp2_nccl|tp2_nvls]` (a layer built the way the MTP layer builds its inner layer) and `test_training_mode_keeps_bias_dropout_add[tp1|tp2_nccl]`: the flag-on output matches flag-off on these paths too, and no residual is left stored.
- `test_unfused_inference_matches_training_path[tp1|tp2_nccl]` (control): the flag-off reference equals the TE training forward and keeps the residual.
- `test_block_links_fused_tp_handoff_only_between_layers_graphed_alike` (CPU): the block's CUDA-graph link rule.

On H100 in the CI image (torch 2.14, TE 2.20.2), the 8 tests of the first commit pass with this PR, including `tp2_nvls`, which ran with NVLS multicast. On main, the 4 expected cases fail (`tp1`, `tp2_nccl`, `tp2_batch_invariant` and the stale-buffer `fused` case), and the 4 controls pass. Neighbor tests pass:
- `tests/unit_tests/transformer/test_transformer_block.py::TestParallelTransformerBlock`: 11 tests.
- `tests/unit_tests/inference/engines/test_dynamic_engine_parallel_and_chunked_prefill.py::TestDynamicInferenceEngineParallel::test_parallel_inference`: 24 pass and 104 skip on 2 GPUs.
- `tests/unit_tests/tensor_parallel/test_layers.py`: 28 tests. Its 8-GPU case `test_LinearWithFrozenWeight[8-True]` was launched with one process and needs 8.

On H100 in the CI image (rerun at this PR's head), the new tests pass (17/17 on 2 GPUs, 44/44 on 1 GPU); on `main` the new test file does not collect, since it imports `FusedTPHandoff`. The neighbor tests pass, including `tests/unit_tests/tensor_parallel/test_layers.py` on 8 GPUs.

No GPU kernel was added or changed. `tools/check_kernel_determinism_coverage.py` passes: `inference_layers.py` is registered as an exempt dispatch entry.
