# Add an optional TensorAtomic placement for MCore MFSDP v2 dense parameters

[Upstream PR](https://github.com/NVIDIA/Megatron-LM/pull/8914) · state: open · merged: False

## Original PR description

## What does this PR do?

Muon needs each weight matrix whole on one rank to run Newton-Schulz. MFSDP v2 shards the matrices, so today the optimizer step gathers each matrix's pieces to an owner rank and scatters the update back. This PR adds an optional alternative: with `MFSDP_TENSOR_ATOMIC=1`, every dense parameter stays whole on one owner rank (the `TensorAtomic` placement), so the Muon step needs no gather or scatter. Owners are chosen greedily to balance the Newton-Schulz cost. The plan depends only on parameter shapes, so every rank computes the same one. Experts keep their own mesh. It is off by default.

Stacked on the Muon step-latency PR (#8782) and on #8684, #8548 and #8547: until they land, the diff also shows their commits, and only the top commit is new.

## Implementation

- `FullyShardedDataParallelV2` builds `TensorAtomic` placements for the dense parameters when `MFSDP_TENSOR_ATOMIC=1` and passes the owner map from `_plan_tensor_owners` to `fully_shard`. A matrix that Muon updates costs `numel * (5 * min(rows, cols) + 1)`, as in `assign_owner_work`; other parameters cost their `numel`.
- `build_for_tensor_atomic` takes an optional `alignment`. `MFSDP_TENSOR_ATOMIC_ALIGN` uses it to start every tensor and every rank segment at a multiple of that many elements, so vectorized kernels see aligned addresses.
- TensorAtomic needs a 1-D data-parallel mesh and raises `NotImplementedError` when there is an outer DP axis. Expert parameters are not affected.

## Dependencies and attribution

Stacked on #8782, #8684, #8548 and #8547. Related to #6161 and #5533. Original Muon changes by @wujingyue in #8398.
