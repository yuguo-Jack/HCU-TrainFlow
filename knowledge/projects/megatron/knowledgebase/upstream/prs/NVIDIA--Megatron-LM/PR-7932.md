This makes all checkpoints saved between the time #7516 and the time this #7932 lands unreadable, right?

#7516 made it so that `train_state.pt` / `latest_train_state.pt` files are written with each checkpoint. But those lack the `release` key that's being added in this PR. So we get a `KeyError` here.

And then there's a further complication. To fix this, my reaction was to default `release` to something like `False`. But any checkpoints made between #7516 and #7932 have incorrect `train_state` info being saved, correct? They count from step 0, and do not account for the fact that checkpoints are usually resumed from a prior non-0 step. Meanwhile, this PR does that correctly in the codeblock at L3198-3217.

So I think the real fix is, to go inside `read_train_state`, and make it so that if we run `latest_ckpt_state = read_train_state(latest_state_filename)` and see that there is no `release` field, we avoid actually reading the train state. We instead just take the `else` branch here, something like:
```
        latest_ckpt_state = None
        if file_exists(latest_state_filename):
            latest_ckpt_state = read_train_state(latest_state_filename)
        if latest_ckpt_state is not None:
            iteration = latest_ckpt_state.iteration
            release = latest_ckpt_state.release
        else:
            tracker_filename = get_checkpoint_tracker_filename(load_dir)
            if maybe_msc.os.path.isfile(tracker_filename):
                iteration, release = read_metadata(tracker_filename)
```
where `read_train_state` returns `None` if there is no `release` field.

I'm confused by this line. This restores everything into the current train state.

The way I understand it, the train state is made of 3 separate buckets:
 * State that should carry across run (like the 3 counters that were restores in `main`)
 * State that this `load_checkpoint` itself is deriving (like iteration, flops)
 * Per-run state (`do_train, `do_test`, etc)

Only the first bucket should be restored. As this logic reads, the 3rd bucket is always going to have issues (you can no longer change the `do_*` values). For the 2nd bucket, `current_train_state.iteration = iteration` happens on L3202, and this overrides it.

There's also a problem with runs do `load_checkpoint` multiple times, but that's a bigger issue to discuss in the other thread.

On this line, I think we should stick with the logic in `main` and only restore those 3 specific counters.

`state_dict.get()` is the wrong way to fix this. Current checkpoints lack the `release` key in `state_dict`. But they are also broken in other ways see this thread: https://github.com/NVIDIA/Megatron-LM/pull/7932#discussion_r4248369199

The right fix is to catch this one level up and ignore the training state altogether, instead of just patching over the missing field. Inside `read_train_state`, in `megatron/training/utils/checkpoint_utils.py`. Something like:
```
    try:
        if MultiStorageClientFeature.is_enabled():
            msc = MultiStorageClientFeature.import_package()
            state_dict = msc.torch.load(train_state_filename, map_location="cpu", weights_only=True)
        else:
            state_dict = torch.load(train_state_filename, map_location="cpu", weights_only=True)
        if "release" not in state_dict:
            logger.warning(f"Ignoring stale train state file {train_state_filename}")
            state_obj[0] = None
        else:
            ts = TrainState()
            ts.load_state_dict(state_dict)
            state_obj[0] = ts
```
compared to the current
```
        if MultiStorageClientFeature.is_enabled():
            msc = MultiStorageClientFeature.import_package()
            state_dict = msc.torch.load(train_state_filename, map_location="cpu", weights_only=True)
        else:
            state_dict = torch.load(train_state_filename, map_location="cpu", weights_only=True)
        ts = TrainState()
        ts.load_state_dict(state_dict)
        state_obj[0] = ts
```

This combines with my suggestion from the other thread, to handle the `None`.
The point is just that old checkpoints have a `train_state`, that is redundant (the information exists elsewhere) and wrong (the train state disagrees with the correct source of truth).
